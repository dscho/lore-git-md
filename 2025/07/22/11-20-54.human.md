This is a refactoring patch in Patrick Steinhardt's reftable backend migration effort, specifically addressing a type inconsistency in identity parsing.

The patch changes the length parameter of `split_ident_line()` from `int` to `size_t`, which better matches how the function is actually used. The commit message notes that callers typically pass string lengths from `strlen()`, `strbuf::len`, or pointer differences - all of which naturally produce unsigned values. The current signed parameter is described as "somewhat confusing" since negative lengths wouldn't make sense in this context.

The change is mechanical and straightforward, touching only the function declaration in ident.h and its definition in ident.c. While small, this cleanup appears well-justified and aligns with good type hygiene practices. It's part of the larger reftable migration series but stands on its own as a sensible improvement to Git's identity parsing infrastructure.

The patch doesn't introduce any new functionality or behavior changes - it simply makes the interface more accurately reflect its actual usage patterns. This kind of cleanup is particularly valuable when working with code that handles string parsing, where type correctness helps prevent subtle bugs.
