This is a follow-up in the `git imap-send` documentation thread, where Aditya Garg responds to Junio C Hamano's suggestion that the IMAP folder listing output should be made more user-friendly in code rather than just better documented. The key technical point is that `git imap-send --list` outputs raw IMAP protocol messages showing folder attributes (like `\HasNoChildren`) and server-side paths (e.g. Gmail's "[Gmail]/Spam" format).

Garg pushes back on implementing a friendlier output format, citing two challenges: the difficulty of regex parsing in C, and variability in output formats across different email servers. They argue the current verbose output provides necessary details for locating subfolders and tags, implying the documentation approach (explaining how to interpret the raw output) is more maintainable than trying to normalize the output format in code.

The exchange reveals a design tension - whether to treat the IMAP protocol details as an implementation detail that should be hidden from users (Junio's position) or as necessary technical information that power users need (Garg's position). The thread remains unresolved on whether to accept the doc-only solution or push for code changes to improve the user experience.
