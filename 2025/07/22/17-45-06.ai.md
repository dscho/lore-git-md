Build system and git-gui modernization patch series from Johannes Sixt, syncing git-gui with Git 2.50.1 and updating version requirements. This is a major cleanup of git-gui's build and runtime dependencies, removing legacy code paths and modernizing the Tcl/Tk implementation.

The key changes include:
- Raising minimum requirements to Tcl/Tk 8.6 (allowing 8.7) and Git 2.36
- Removing decades-old compatibility code for Git versions < 1.5.3 and Tk 8.4
- Adding SHA-256 repository support (Takashi Iwai)
- Bulgarian translation update (Alexander Shopov)
- Fix for redundant trailing empty lines in commit messages
- Major refactoring of process execution and redirection handling (Mark Levedahl)
- Elimination of deprecated `null_sha1` in favor of `nullid`

The patch series builds on Johannes Sixt's earlier fix for the TCL file deletion issue during NO_TCLTK builds (referenced in the base commit). The changes touch nearly all git-gui components, with particularly heavy modifications to `git-gui.sh` (877 lines changed) and the Bulgarian translation file (3608 lines changed). The modernization removes many workarounds for ancient Git versions and Tcl/Tk features, while introducing more robust process handling and Windows compatibility fixes.

This appears to be a well-considered modernization effort that removes substantial technical debt while maintaining functionality. The changes are spread across 60 commits from 4 contributors, with Mark Levedahl contributing the majority (35 commits) of the modernization work. The patch series is ready for integration, having already been synchronized with Git 2.50.1.
