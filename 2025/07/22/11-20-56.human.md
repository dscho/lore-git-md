This is a refactoring patch in Patrick Steinhardt's reftable migration series, focusing on reflog handling behavior. It addresses how the `REF_HAVE_OLD` flag is managed during reflog updates.

The patch stops unconditionally clearing the `REF_HAVE_OLD` flag for log-only updates (like reflog writes), which was previously done to avoid unnecessary old-oid verification. While this made sense for avoiding race condition checks during reflog writes, it had the unintended side effect of losing the signal that a caller provided an old object ID. This caused problems during reflog migration where entries would incorrectly get zeroed object IDs.

The change preserves the flag while still skipping verification for log-only updates, allowing the backend to properly use caller-provided old object IDs when available. The implementation touches both files and reftable backends consistently, with careful attention to the interaction between `REF_HAVE_OLD` and `REF_LOG_ONLY` flags.

This appears to be a well-justified change that fixes a real migration issue while maintaining the original safety properties. The patch is part of the larger reftable migration effort and builds logically on previous preparatory work in the series. The changes are focused and the commit message clearly explains both the problem and solution.
