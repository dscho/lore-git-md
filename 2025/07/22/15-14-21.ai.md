This is a platform compatibility discussion in the ongoing Rust/xdiff RFC thread, focusing on Gentoo's Rust support limitations across various architectures.

Eli Schwartz provides a detailed breakdown of Gentoo's Rust compiler support constraints, responding to Patrick Steinhardt's suggestion to survey distribution impacts before committing to Rust adoption. The response enumerates specific architecture limitations: no Rust support for HPPA/Alpha/m68k, partial support for s390 (only s390x), and various 32-bit architecture issues affecting musl, i486, sparc32, and riscv32. Schwartz notes macOS and Solaris Prefix users also lack Rust support despite Rust's official macOS compatibility.

The email highlights two key technical barriers: (1) Rust's dependence on LLVM prevents support on architectures where LLVM isn't available (like Alpha/HPPA), and (2) 32-bit architectures face more limitations than 64-bit counterparts. Schwartz mentions GCC-rs as a potential solution since it could leverage existing GCC backends for unsupported architectures. The attached Gentoo repository reference shows how the distribution currently handles Rust-dependent features through its wd40 feature set that disables Rust requirements.

This contribution adds concrete distribution packaging data to the thread's platform support discussion, particularly emphasizing the 32-vs-64-bit divide and LLVM dependency as systemic constraints. The tone suggests these are factual limitations rather than opposition to Rust in principle, with an implied question about whether Git wants to effectively drop support for these architectures if Rust becomes mandatory. The response doesn't propose solutions but provides important ecosystem data that wasn't previously quantified in the thread.
