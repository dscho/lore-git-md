Bugfix patch implementing consistent path expansion for `gpg.program` configuration.

This is the first patch in a v2 series addressing the GPG path expansion issue. It modifies `gpg-interface.c` to use `git_config_pathname()` for the `gpg.program` setting, enabling tilde expansion for paths like `~/.local/bin/mygpg`. The change is updated in both the implementation and documentation, with the doc now explicitly calling this a "pathname" rather than just a "program" to clarify the expected input format.

The technical change is minimal - just switching from `git_config_string()` to `git_config_pathname()` in the config callback - but has important implications for users who want to store their GPG program under their home directory. The documentation update makes the pathname semantics clear while maintaining the existing note about command-line interface requirements.

This builds on previous discussion where the inconsistency with other path-based Git configs was identified, and follows the approach of handling path expansion while still treating the entire value as a single path (not parsing arguments). The patch appears straightforward and well-contained, with no obvious edge cases or complications in the implementation.
