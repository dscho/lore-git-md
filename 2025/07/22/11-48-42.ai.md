Documentation update for `git imap-send`. This is version 2 of a patch that adds a new section to the `git-imap-send` man page explaining how to use the `--list` option to discover IMAP folder names. The patch follows up on the initial version with a minor wording fix (changing "need to be" to "need not be" when describing client vs server folder names).

The new documentation section addresses a common point of confusion by showing how to interpret the verbose IMAP LIST output, with a concrete example from Gmail that maps client-visible names ("Junk", "Trash") to their server-side equivalents ("[Gmail]/Spam", "[Gmail]/Trash"). The example output shows the full folder listing a user might see, with annotations explaining how to extract the relevant folder names for use with `git imap-send`.

The patch is narrowly focused on improving documentation clarity around an existing feature, with no code changes. The example uses Gmail's specific folder naming scheme but notes the same approach works for other providers. The v2 revision corrects a small but important wording error from v1 that could have misled readers about the relationship between client and server folder names.
