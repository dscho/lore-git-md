This is a refactoring patch in Patrick Steinhardt's reftable backend migration series, specifically preparing for the introduction of a new reflog write subcommand in patch 4. The change exports the previously internal `ref_transaction_update_reflog()` function from refs.c to refs.h, making it available for use by other parts of the codebase.

The patch makes two key changes: first, it removes the `flags` parameter since all current callers use the same set of flags (REF_HAVE_OLD|REF_HAVE_NEW|REF_LOG_ONLY|REF_FORCE_CREATE_REFLOG|REF_NO_DEREF), hardcoding these instead. Second, it moves the function declaration to refs.h while preserving its documentation comment.

This is a straightforward preparatory change that follows the series' pattern of restructuring code before adding new functionality. The modification to `migrate_one_reflog_entry()` shows the simplified calling pattern that will be used by the upcoming `git reflog write` command. The patch maintains all existing behavior while cleaning up the interface in anticipation of new uses.
