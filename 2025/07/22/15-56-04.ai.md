This is a policy discussion about Rust adoption strategy in Git, specifically addressing the context of the xdiff optimization series. Junio Hamano responds to Patrick Steinhardt's position that Git should fully commit to Rust rather than maintaining parallel implementations. Hamano notes the current lack of clearly bounded subsystems in Git's architecture would complicate any partial Rust adoption strategy, making it difficult to selectively implement some components in Rust while keeping others in C. This reinforces the binary choice facing the project: either fully embrace Rust (with all its platform compatibility tradeoffs documented in the thread) or avoid it entirely for now.

The exchange highlights the architectural challenge that makes incremental Rust adoption problematic - Git's current codebase doesn't have clean enough component boundaries to support mixing languages at subsystem level. This comes after extensive technical discussion in the thread about performance gains (5-19% from Rust xdiff optimizations), platform support limitations (particularly for niche architectures), and build system integration challenges. Hamano's response focuses on the maintainability implications rather than revisiting the performance or compatibility questions already raised by others.
