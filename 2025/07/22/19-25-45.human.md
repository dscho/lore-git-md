This is a discussion about the implementation details of the new `git repo info` subcommand, specifically focusing on the field callback system in patch 2/8 of the series. Justin Tobler raises some thoughtful questions about the design.

The email examines the current implementation where each field (like `references.format`) has a dedicated callback function to retrieve its value. Justin notes this works well for simple cases but questions whether it might become inflexible for future use cases where a single operation could generate multiple fields of data - particularly relevant for a potential future `git repo stats` subcommand that would report aggregated metrics.

He also points out that the current behavior silently does nothing when no keys are specified, suggesting this might not be the most intuitive default. Two alternatives are proposed: either erroring out or treating an empty request as asking for all available fields.

The discussion shows good technical engagement with the patch's architecture while maintaining a constructive tone. It doesn't propose specific changes but raises important considerations about future extensibility and user experience that the authors may want to address either now or when expanding the command's functionality later. The questions are well-framed and show Justin is considering both immediate needs and long-term maintainability.
