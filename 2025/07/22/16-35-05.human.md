Documentation follow-up discussing IMAP folder listing usability. Aditya Garg responds to Junio Hamano's suggestion that the `git imap-send --list` output's unfriendliness might warrant a code change rather than just documentation improvements. The author argues that making the output more user-friendly would be difficult due to variations in IMAP server responses and the challenges of regex parsing in C, while noting the current output's verbosity provides necessary details for locating subfolders and tags.

This continues the discussion about whether to accept the documentation patch explaining Gmail's folder naming scheme or push for deeper implementation changes. The exchange highlights a tension between documentation-as-workaround versus fixing underlying UX issues, with the author leaning toward keeping the detailed IMAP protocol output for its technical completeness despite the learning curve.
