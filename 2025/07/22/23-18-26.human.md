This is a bugfix patch addressing a memory leak in the reflog expiry code. Jacob Keller (with co-development from Jeff King) fixes a case where `find_cfg_ent()` allocates `reflog_expire_entry_option` structs that were never freed during reflog expiration operations.

The patch adds a new `reflog_clear_expire_config()` function to properly clean up these allocations, calling it from both `cmd_reflog_expire()` and `reflog_expire_condition()`. The fix is demonstrated with a new test case that also verifies the existing per-ref reflog expiry configuration functionality that had been untested since its introduction in 2008.

This is the fourth iteration of the patch, with changes focused on fixing the cleanup calls and adding test coverage. The commit message clearly shows the leak via ASAN output and explains the solution. The changes look straightforward and well-tested, addressing a real resource leak that affects both direct reflog operations and garbage collection.
