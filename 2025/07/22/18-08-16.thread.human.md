This thread began as a proposal to remove the "THIS COMMAND IS EXPERIMENTAL" markers from `git-switch` and `git-restore`, which were introduced in 2019 but have remained unchanged for six years despite widespread adoption. The discussion split into two tracks: one about the straightforward documentation updates (now reaching consensus) and another about more contentious interface design questions around short flags and shared option handling.

Junio Hamano has approved moving forward with the documentation changes while acknowledging this represents a "failed experiment" in UI improvements rather than celebrating stability. The latest patch (2/2) simply removes the experimental warnings from both commands' man pages with minimal wording changes, referencing the original 2019 commit. Justin Tobler and others have agreed to the refined phrasing that avoids overstating the commands' maturity.

The interface design discussion around parameterizing `add_common_options()` and the `-m` short flag remains unresolved but is now effectively separated from these documentation updates. While that larger design question may resurface later, this uncontested portion appears ready for inclusion as it has achieved clear consensus among the participants. The thread demonstrates how Git's development process can decouple and advance non-controversial changes even when related design questions remain open.
