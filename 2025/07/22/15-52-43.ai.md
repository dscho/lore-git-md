Performance test patch in the `git last-modified` series.

This email from Toon Claes responds to Taylor Blau's feedback on the performance test script for the new `git last-modified` command. The test script (`t/perf/p8020-last-modified.sh`) measures execution time for three scenarios: top-level checks, recursive checks, and subdirectory checks. Taylor suggests improving the subdirectory test by using `git ls-tree -d` to avoid piping Git output through grep and cut, which Toon agrees to incorporate in the next version.

The exchange shows the performance test infrastructure being refined as part of the final polishing of the `last-modified` feature. The test cases themselves are straightforward benchmarks of the command's core operations, with the subdirectory test being the most complex as it needs to dynamically identify a directory path to test against. The discussion reflects the careful attention to shell scripting best practices that characterizes Git's test suite.
