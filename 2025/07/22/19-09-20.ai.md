This is a bugfix patch series addressing path expansion in Git's GPG configuration. The two-patch series follows up on the ongoing discussion about `gpg.program` behavior, specifically implementing tilde expansion for the configuration value while maintaining the current limitation of not parsing command-line parameters.

The first patch (unchanged from v1) modifies `gpg-interface.c` to use `git_config_pathname()` for `gpg.program`, ensuring consistent tilde expansion with other Git path settings. It also updates the documentation to clarify this is a pathname parameter. The second patch (new in v2) adds test cases verifying the expansion works for non-absolute paths, including a home-directory case that required some test harness workarounds.

Key technical details:
- Changes `gpg-interface.c` to expand paths via `git_config_pathname()`
- Updates `gpg.adoc` documentation to specify pathname semantics
- Adds tests covering relative paths and home-directory expansion
- Test workaround uses `HOME` variable override for tilde expansion
- Maintains current behavior of treating entire value as single path (no argument parsing)

The patch appears well-scoped to address the immediate path expansion issue while leaving the larger command-line argument handling question for future work. The test additions in v2 provide coverage for the new behavior, though the author notes some awkwardness in testing home-directory expansion. This series represents a focused solution to one aspect of the broader GPG configuration discussion.
