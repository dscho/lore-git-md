Bugfix for file descriptor leak in `git archive` command. This is the second patch in a four-part series addressing resource leaks found during code review.

The patch fixes a case in `builtin/archive.c` where the file descriptor returned by `xopen()` could leak if `dup2()` fails. The change adds a `close(output_fd)` call on the error path before calling `die_errno()`. The fix follows Git's standard pattern for resource cleanup, ensuring the descriptor is closed whether `dup2()` succeeds or fails.

Key technical details:
- Function affected: `create_output_file()` in `builtin/archive.c`
- Leak scenario: When `dup2(output_fd, 1)` fails
- Fix: Adds single `close(output_fd)` call before error handling
- Impact: Prevents potential file descriptor exhaustion in error cases

The change is minimal (one line added) and uncontroversial, matching the pattern seen in the other patches of this series. Like the test-truncate fix in patch 1, this addresses a clear resource leak found through code review rather than a user-reported issue. The patch stands alone but fits into the series' broader theme of thorough resource cleanup.
