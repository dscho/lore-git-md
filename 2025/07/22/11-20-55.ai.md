Bugfix in the reftable migration series, addressing incorrect identity handling during reflog format conversion. This patch fixes a specific issue where the committer identity was being incorrectly passed to `fmt_ident()` during reflog migration between storage formats.

The core problem occurs when migrating reflog entries - the code was passing the full committer identity (name + email) as just the email parameter to `fmt_ident()`, resulting in malformed output like `pks <Patrick Steinhardt ps@pks.im>`. The fix properly splits the identity line first using `split_ident_line()` (building on patch 5's type safety improvements) to extract name and email components separately before passing them to `fmt_ident()`.

Key technical changes:
- Adds `name` and `mail` strbuf fields to both `migration_data` and `reflog_migration_data` structs
- Uses `split_ident_line()` to parse committer info into components
- Updates `fmt_ident()` calls to use the properly separated name/email
- Ensures proper cleanup of new strbufs in `repo_migrate_ref_storage_format()`

The patch is part of Patrick Steinhardt's ongoing reftable migration series (now at v1, patch 6/8). While it fixes a clear bug, testing is deferred to a later patch that will add stricter verification in t1450. This appears to be a well-contained fix that properly leverages the infrastructure built in earlier patches, particularly the `split_ident_line()` improvements from patch 5. The change is focused and maintains the series' careful attention to detail in handling reflog migration edge cases.
