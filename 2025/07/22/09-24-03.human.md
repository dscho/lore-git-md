This is a follow-up discussion about the treeless clone bugfix, focusing on submodule behavior. Jeff King explores whether submodule fetches should be handled differently in tree-less repositories, where parent trees may be missing.

The core issue is that when doing submodule diffs in a tree-less clone, Git currently tries to recursively fetch missing submodule trees, which may be pointless if we don't have the parent trees that reference them. King proposes a theoretical fix that would temporarily disable lazy fetching during submodule path calculation, but notes this doesn't work in practice because the underlying diff machinery isn't prepared to handle missing trees gracefully.

The email suggests two key insights: first, that there may be a need for a "permissive mode" in the submodule diff code to quietly skip missing trees, and second, that this submodule behavior discussion is somewhat separate from the main race condition fix proposed earlier in the thread. The tone is exploratory rather than proposing a concrete solution, indicating this is an open design challenge that may need more discussion.
