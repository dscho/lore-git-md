This is a policy discussion email in the ongoing Rust integration thread, where Patrick Steinhardt voices support for making Rust a hard dependency in Git. The email responds to earlier messages from Taylor Blau and brian m. carlson about the benefits of Rust adoption.

Steinhardt aligns with the view that Rust is becoming the de facto systems programming language and argues for a full transition rather than maintaining parallel C and Rust implementations. He suggests that as Git continues to reduce global state usage (like the `the_repository` removal effort), subsystems could be cleanly replaced with Rust implementations - specifically mentioning the reftable library as a candidate.

The email reinforces previous arguments about the downsides of optional Rust support, agreeing that maintaining two implementations would be unmaintainable. Steinhardt's perspective comes from his experience with Git's internals and his past proposals for Rust integration. This continues the thread's central debate about whether Git should commit fully to Rust or pursue more incremental adoption strategies.
