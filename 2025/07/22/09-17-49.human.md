Bugfix investigation for partial clone race condition. Jeff King analyzes a reported issue where treeless/blobless clones fail on first pull after a delay, succeeding on second attempt. He reproduces the problem with a minimal test case showing that submodule fetches trigger endless tree fetches in filtered clones, eventually hitting a race where maintenance repacks make objects temporarily unavailable.

The root cause appears to be in `fetch-pack.c` where commit graph lookups don't properly recheck packed objects when they appear missing. King proposes a one-line fix adding `HAS_OBJECT_RECHECK_PACKED` to the object existence check, though he notes this might have performance implications and wants feedback from Jonathan Tan (cc'd) who worked on related commit graph code.

The analysis suggests this isn't strictly a filtered clone issue - any situation with rapid fetches racing against repacks could trigger it. King also considers (but doesn't propose) changes to submodule fetching behavior in tree-less repos as a separate improvement. The proposed fix is minimal and targeted at the immediate race condition.
