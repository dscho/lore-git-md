This is the third patch in a series implementing the new `git repo info` subcommand, adding support for detecting bare repositories. The patch introduces a new `layout.bare` field that returns "true" or "false" based on whether the repository is bare, using the existing `is_bare_repository()` function from the environment API.

The implementation follows the established pattern from previous patches, adding a new callback function `get_layout_bare()` that returns a string value. The field is integrated into the sorted field array with proper documentation and test coverage. The tests verify both bare and non-bare repository cases.

Key technical details:
- Uses `is_bare_repository()` from environment.h (requiring `USE_THE_REPOSITORY_VARIABLE`)
- Returns static strings "true"/"false" rather than allocating
- Maintains lexicographical field ordering in the array
- Adds test cases in t1900-repo.sh for both bare and non-bare scenarios
- Updates documentation in git-repo.adoc with the new field under the "layout" category

The patch continues the series' pattern of simple, focused field implementations while maintaining the architectural decisions established earlier (direct printing, string-returning callbacks, etc.). It demonstrates the extensibility of the field system for different types of repository metadata.
