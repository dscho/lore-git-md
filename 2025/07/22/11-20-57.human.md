This is the final patch in Patrick Steinhardt's 8-part series fixing reflog migration issues between Git's storage backends, specifically addressing invalid old object IDs that appear during format conversion.

The patch fixes a critical bug where migrated reflog entries were incorrectly showing all-zero old object IDs instead of preserving the original values. The root cause was that the migration process was trying to resolve old OIDs from references that didn't yet exist in the target storage. The solution introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells backends to use the caller-provided OIDs directly rather than attempting resolution.

The change is implemented consistently across both files and reftable backends, with proper validation to ensure required flags are set. Test coverage is improved by modifying t1460-refs-migrate.sh to use a test helper that shows both old and new OIDs, closing a previous testing gap. The patch also provides additional test coverage for the identity handling fixes from the previous commit in the series.

This completes the technical implementation for robust reflog migration, a key requirement for Git's planned transition to making reftable the default backend. The series as a whole shows careful attention to edge cases in storage format conversion while maintaining backward compatibility.
