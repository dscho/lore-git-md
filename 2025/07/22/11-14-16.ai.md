Feature implementation for `git send-email` adding IMAP sent-folder archiving. This v3 patch from Aditya Garg finalizes the naming debate by adopting "imap-sent-folder" terminology while maintaining the core functionality to archive SMTP-sent messages via IMAP. The implementation spans `git-send-email.perl` (message collection and piping) and `imap-send.c` (header parsing adjustments).

Key technical changes from v2:
- Renamed all occurrences of "imapfolder" to "imap-sent-folder" in config, CLI options, and variables
- Simplified an error message by removing redundant details
- Kept the dual-mode header parsing in `imap-send.c` that distinguishes between regular messages and `git-send-email` copies

The patch addresses iCloud Mail's SMTP limitation by providing a configurable IMAP folder destination (`sendemail.imapSentFolder` or `--imap-sent-folder`). Messages are archived after successful SMTP transmission via `git imap-send`, with Bcc headers preserved for the archive copy. Documentation covers both the feature and its `imap-send` dependency.

This version resolves the naming debate by accepting Junio's preference for "sent-folder" terminology while maintaining the ability to archive to any folder. The implementation appears solid, with clear documentation and error handling. The remaining architectural question about supporting a pure-IMAP transport mode (B2) appears deferred, focusing instead on the archiving use case that motivated the patch.
