Bugfix for a file descriptor leak in `git archive`. This is the second patch in a series addressing resource leaks found during code review.

The patch fixes a case in `builtin/archive.c` where a file descriptor would remain open if `dup2()` failed during output file creation. The change is minimal - just adding a single `close(output_fd)` call on the error path. The fix follows Git's standard pattern for resource cleanup.

This appears to be a straightforward correctness improvement with no behavioral changes beyond proper resource management. Like the other patches in the series, it addresses a potential (though likely rare) resource leak scenario rather than a user-reported bug. The change is small and focused that it's unlikely to be controversial.
