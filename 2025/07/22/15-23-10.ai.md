Bugfix patch addressing multiple edge cases in merge-ort's handling of rename-to-self scenarios during directory renames. This is patch 5/6 in the series fixing complex rename detection issues in merge-ort.

The patch fixes three specific bugs that were either masked by optimizations or revealed through expanded test coverage:
1. Silent file deletion in testcase 12i2 (when a file is renamed to itself with modifications)
2. Silent file retention in testcase 12n2 (when a file should be deleted but isn't)
3. Incorrect index entry count in testcase 12n

Key technical changes:
- Adds explicit check in process_renames() to skip rename-to-self cases (oldpath == newpath)
- Modifies testcase 12i to use a multi-line file (prep for new testcase)
- Adds new testcase 12i2 demonstrating silent deletion bug
- Converts testcases 12n and 12n2 from expect_failure to expect_success
- Verifies correct file states via test_path_is_* and git ls-files checks

The fix builds on prior work in the series, particularly the test infrastructure improvements from earlier patches. The core issue involves directory renames interacting with the "relevant renames" optimization in merge-ort, where certain edge cases were being incorrectly handled. The patch adds robust test coverage while fixing the underlying logic.
