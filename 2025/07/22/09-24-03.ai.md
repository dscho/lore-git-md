This is a follow-up discussion about submodule behavior in tree-less clones, building on the earlier bug report and proposed fix for fetch race conditions.

Jeff King explores whether submodule fetches should be handled differently in tree-less repositories, where parent trees may be missing. He suggests that attempting to fetch submodules when their parent trees are unavailable may be pointless, and proposes temporarily disabling lazy fetching during submodule path calculation. However, he notes this approach currently fails because the underlying diff machinery isn't prepared to handle missing trees gracefully.

The key technical points are:
- Current submodule fetch behavior may unnecessarily trigger cascading fetches in tree-less clones
- A proposed solution would disable `fetch_if_missing` during `calculate_changed_submodule_paths()`
- This fails because diff operations expect trees to be present
- The diff machinery would need new "permissive mode" handling for missing trees

This discussion extends the original bugfix conversation into design considerations for how submodules should work in filtered clones. While the initial race condition fix addresses the immediate corruption issue, this email surfaces deeper questions about the interaction between submodule operations and partial clone functionality. The technical hurdle identified (diff machinery assumptions about tree availability) would require non-trivial changes to make the proposed solution work.
