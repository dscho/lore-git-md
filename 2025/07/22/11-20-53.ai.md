This is patch 4/8 in Patrick Steinhardt's series introducing a new `git reflog write` subcommand, part of broader reftable backend migration improvements. The patch adds the core implementation of the new subcommand that allows manually writing reflog entries, which becomes particularly useful with the binary reftable format where manual editing isn't feasible.

The new `git reflog write <ref> <old-oid> <new-oid> <message>` command provides basic functionality to append single entries while enforcing strict validation: it requires all parameters, verifies object IDs exist (unless null), and checks refname formatting. The implementation builds on the refactored `ref_transaction_update_reflog()` interface from patch 3, using it within a transaction to safely append entries.

The patch includes comprehensive tests in t1421-reflog-write.sh covering:
- Argument validation (wrong count, invalid refnames)
- Object existence checking
- Basic write functionality verification
The test suite uses a new helper `test_reflog_matches` to verify reflog contents.

Key technical details:
- Adds BUILTIN_REFLOG_WRITE_USAGE definition
- Implements cmd_reflog_write() with strict parameter checking
- Uses git_committer_info() for signature generation
- Validates objects via odb_has_object()
- Maintains existing behavior for null OIDs
- Adds new test-tool integration for verification

The implementation is intentionally minimal, explicitly noting several unimplemented features that could be added later (batch writes, arbitrary insertion, custom timestamps, nonexistent objects). This positions the command as a testing/debugging tool for the reftable transition rather than a general-purpose feature. The thorough test coverage suggests this will be reliable infrastructure for the migration fixes coming in later patches.
