Feature addition for reftable compatibility, part of Patrick Steinhardt's series fixing reflog migration issues. This patch introduces a new `git reflog write` subcommand to manually append reflog entries, primarily motivated by the reftable backend's binary format making manual edits impractical.

The new command provides basic functionality to append a single entry with given old/new object IDs and a message, with strict validation: it requires all parameters, verifies refname format, checks object existence, and uses the current committer info for the timestamp. The implementation builds on the refactored `ref_transaction_update_reflog()` from patch 3.

The patch includes thorough tests (t1421-reflog-write.sh) covering error cases (invalid args, bad refnames, missing objects) and basic success scenarios. The author notes this is intentionally minimal - it doesn't support batch writes, custom timestamps, or references to nonexistent objects, though these could be added later if needed.

This appears well-constructed with clear motivation (reftable compatibility), careful validation, and good test coverage. It's part of a larger effort to ensure smooth reflog handling during Git's transition to reftable as the default backend.
