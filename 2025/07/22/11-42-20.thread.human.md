This thread explores a performance optimization for `git blame` that would reduce unnecessary commit parsing by skipping full commit details when only basic author information is needed. The original proposal modifies two call sites in `builtin/blame.c` to use a lighter-weight parsing mode, building on a 2006 optimization that wasn't fully utilized.

Patrick Steinhardt, reviewing the patch, requested two key improvements: concrete performance measurements showing the speedup impact (especially for large repositories), and clear documentation explaining why these specific call sites don't need full commit details. Junio Hamano has now weighed in, agreeing these are reasonable requests while raising an interesting alternative perspective. He suggests that if the optimization doesn't demonstrate measurable benefits, the project might be better off removing the partial-parse capability entirely rather than maintaining underutilized code paths.

The discussion highlights Git's performance-sensitive culture, where even small optimizations require empirical validation. While the technical approach appears sound, the thread remains open pending benchmark data and clearer documentation from the original author. The next step will likely be a v2 submission addressing these points, which should help determine whether to proceed with the optimization or reconsider the underlying partial-parse mechanism.
