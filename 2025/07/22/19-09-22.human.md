This is the second patch in a bugfix series addressing path expansion in Git's GPG configuration. It adds test coverage for the `gpg.program` path handling changes introduced in the first patch.

The test suite now verifies two key scenarios: when `gpg.program` is set to a home-relative path (using `~/fake-gpg`) and when it's a program name that should be found in `$PATH`. Both cases use test harness tricks - overriding `HOME` and `PATH` respectively - to ensure the expansion works as expected without affecting the system.

This completes the v2 series that fixes inconsistent tilde expansion behavior in `gpg.program` while maintaining the existing limitation that the value is treated as a single path (not parsing command-line arguments). The tests are straightforward and well-constructed, providing clear verification of the new behavior. With both the implementation change and test coverage now in place, this appears ready for final review.
