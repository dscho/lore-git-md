This is a bugfix series targeting the reftable backend migration, with additional functionality for reflog handling. The patches address two specific issues discovered while implementing reftable support in libgit2, where reflog entries were being migrated incorrectly between storage formats.

The key problems fixed are: (1) incorrect identity information being written to migrated reflog entries, and (2) old commit IDs being erroneously set to all-zeroes during migration. The series also introduces a new `git reflog write` subcommand to help with testing reflog scenarios, though this appears primarily as a debugging aid rather than a user-facing feature.

The changes span several components: refs backend code (both files and reftable implementations), identity handling, and the reflog command interface. Test coverage is expanded with new cases in t1421-reflog-write.sh and updates to t1460-refs-migrate.sh. The series appears well-structured, with preparatory refactoring (patches 1-3) before the core fixes (patches 6-8) and the new subcommand (patch 4) positioned where it can be used by later tests.

This work is particularly relevant given the upcoming reftable default in Git 3.0, as it ensures proper compatibility when repositories migrate between storage backends. The discovery via libgit2 testing suggests these issues could affect other implementations working with migrated repositories.
