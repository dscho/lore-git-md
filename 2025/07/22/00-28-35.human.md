Feature implementation for the new `git repo info` command. This patch adds the `--format` flag to control output formatting, completing the core functionality of the command.

The patch introduces two output formats: `keyvalue` (default) with human-readable `key=value` pairs, and `null` for machine parsing with NUL-delimited output. The implementation follows Git conventions seen in commands like `git config`, with the format selection handled through a new enum and switch statement. The test suite is expanded to verify both formats work correctly.

This is the final patch in the v5 series, which has now implemented three repository metadata fields (`references.format`, `layout.bare`, and `layout.shallow`) along with this formatting control. The implementation is clean separation of concerns - the field callbacks remain simple string producers while the formatting logic is centralized in the printing function.

The patch maintains the series' high quality with thorough tests (now covering both formats) and clear documentation updates. With this addition, the command now has the core functionality needed for both human and programmatic use, addressing one of the key requirements identified in earlier discussion. The implementation choices align well with Git's existing output format patterns.
