This is a refactoring and bugfix patch in Patrick Steinhardt's reftable migration series, specifically addressing how reflog updates handle the REF_HAVE_OLD flag. The change affects both files and reftable backends.

The patch stops unsetting REF_HAVE_OLD for log-only updates, which was previously causing issues during reflog migration by losing the signal that a caller had provided an old object ID. This led to reflog entries incorrectly getting zeroed object IDs. The change preserves this signal while still skipping old-OID verification for log-only updates through careful flag checking.

Key technical changes include:
- Removing the REF_HAVE_OLD unsetting in ref_transaction_update_reflog()
- Modifying ref_update_expects_existing_old_ref() to consider REF_LOG_ONLY
- Updating both files-backend and reftable-backend to properly handle the combined flags
- Fixing a whitespace issue in reftable-backend.c's error message

The patch builds on the series' earlier refactoring work and directly enables proper handling of old object IDs during reflog migration, which will be implemented in the subsequent commit. The changes are consistently applied across both storage backends, maintaining behavior parity while fixing the migration issue.
