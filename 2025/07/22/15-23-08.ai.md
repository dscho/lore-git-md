Test documentation patch in the merge-ort rename detection bugfix series. This is patch 3/6, adding detailed test case descriptions and assertions for two edge cases involving directory renames that result in files being renamed to themselves.

The patch documents and expands test coverage for two scenarios where directory renames interact with file operations in non-obvious ways. First, it enhances testcase 12n (originally added in commit 98a1a00d5301) with proper English documentation and index state checks, revealing that the current code fails to handle a rename-to-self case properly when merge.directoryRenames=false. The test expects a conflict but the file should actually be deleted since there's no content conflict.

Second, it introduces a new testcase 12n2 that's nearly identical but with merge.directoryRenames=true, showing another bug where the file incorrectly remains when it should be deleted. Both testcases are marked as expecting failure, with the issues to be fixed in subsequent patches. The test assertions carefully check the number of index entries and conflict messages, providing clear specification of the expected behavior.

Key technical details:
- Tests directory rename interactions where a file becomes renamed to itself (world -> tools/world -> world)
- Documents expected behavior for both directoryRenames=false (path conflict) and =true (should delete) cases
- Adds index state verification via `git ls-files -s` assertions
- Follows existing test pattern in t6423-merge-rename-directories.sh
- Builds on earlier test reorganization (moving from t6036/t6043 to t6416/t6423)
