Documentation update for `git imap-send`. This is version 2 of a patch that improves the man page by adding a concrete example of how to interpret the output of `git imap-send --list` when discovering IMAP folders.

The patch adds a new section explaining that client-visible folder names (like "Junk" or "Trash") often differ from the server-side names needed for IMAP operations. It provides a clear Gmail example showing the mapping between common folder labels and their actual IMAP names (e.g., "Junk" -> "[Gmail]/Spam"). The v2 revision fixes a minor wording issue from v1 ("need to be" -> "need not be") while keeping the helpful example output.

This is a straightforward documentation improvement that addresses a real pain point for users trying to send patches to specific IMAP folders. The example is well-chosen (Gmail being a common provider with non-obvious folder naming) and the explanation is clear. The patch integrates cleanly into the existing man page structure.
