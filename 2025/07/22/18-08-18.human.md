This is the second patch in a 2-part series removing the experimental status markers from `git-switch` and `git-restore`. The patch follows up on the first one (which removed the `-m` short flag from `git-switch`) by actually stripping the "EXPERIMENTAL" warnings from both commands' documentation.

The commit message makes a strong case for stabilization, noting that six years have passed since the commands were introduced (in 2019) without significant interface changes. It acknowledges but dismisses concerns about the `-c` flag (for branch creation), arguing this common operation deserves to keep its short flag. The author references prior discussion and a year-old attempt to remove the experimental markers, suggesting this change has been well-vetted.

The implementation is straightforward - just removing the warning lines from two documentation files. This appears to be a well-justified cleanup that formalizes what has effectively been true for years: these commands are stable parts of Git's interface. The patch seems uncontroversial and ready for inclusion.
