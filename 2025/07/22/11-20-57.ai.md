This is the final patch in Patrick Steinhardt's 8-part series fixing reflog migration issues between storage formats, specifically addressing invalid old object IDs during conversion.

The patch fixes a critical bug where migrated reflog entries were incorrectly getting all-zero old object IDs. The root cause was that during migration, the code was trying to resolve the old OID from the target storage (where the ref didn't exist yet) rather than using the provided old OID from the source reflog. The solution introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells backends to use the caller-supplied OIDs directly.

Key technical changes:
- Adds `REF_LOG_USE_PROVIDED_OIDS` flag to refs.h with proper documentation
- Modifies both files and reftable backends to honor the new flag
- Updates `ref_transaction_update_reflog()` to set the flag by default
- Enhances t1460-refs-migrate.sh tests with new `print_all_reflog_entries` helper that verifies both old and new OIDs
- Includes validation that required flags (HAVE_OLD, HAVE_NEW, LOG_ONLY) are set when using the new behavior

The patch completes the series' goal of ensuring accurate reflog migration between storage formats. It builds on previous patches that standardized identity handling and flag management. The test changes not only verify this specific fix but also provide coverage for the identity handling fixes from earlier in the series.

The implementation shows careful attention to cross-backend consistency and includes appropriate error checking. The test improvements address the previous lack of validation for old OIDs in migrated reflogs. This appears to be a well-considered final piece of the migration puzzle.
