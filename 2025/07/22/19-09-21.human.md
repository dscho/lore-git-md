This is a bugfix patch addressing inconsistent path expansion behavior in Git's GPG configuration. It's part of a v2 series that improves how `gpg.program` handles paths, particularly home directory expansion (using `~`).

The patch makes two simple but important changes: it updates the documentation to clarify that `gpg.program` expects a pathname (rather than just any program name), and modifies the code to use `git_config_pathname()` instead of `git_config_string()`. This ensures tilde expansion works consistently with other Git path configurations.

The change is well-motivated by the thread discussion, which identified that the current behavior fails to properly handle paths under a user's home directory. The implementation is straightforward and focused, touching only the necessary files. The documentation update helpfully clarifies the expected input format.

This is the first of two patches in the series, with the second patch adding test coverage for the changes. Together they resolve the immediate path expansion issue while maintaining the existing limitation that the setting doesn't support command-line arguments (a separate concern that may be addressed in future work).
