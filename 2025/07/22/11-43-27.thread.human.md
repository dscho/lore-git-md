This thread documents an improvement to `git imap-send`'s `--list` option, which helps users discover IMAP folders for patch submission. The original patch by Aditya Garg added documentation showing how to interpret verbose IMAP LIST output, with a concrete Gmail example demonstrating the mapping between client labels (like Junk) and server-side folder names (like [Gmail]/Spam). A follow-up version fixed a minor but important wording issue in the docs.

Junio C Hamano has now weighed in, agreeing the current situation is confusing but questioning whether better documentation is the right solution. He suggests the core issue is that exposing raw IMAP protocol details to end users is inherently unfriendly, and that a code change to present the information more cleanly might be preferable. The thread remains open on whether to accept the documentation improvement as a stopgap or hold out for a more fundamental fix to the user experience. While focused on Gmail's specific naming scheme, the discussion acknowledges the underlying principles apply to other IMAP providers as well.
