This thread discusses improvements to the `git imap-send` documentation, specifically around the `--list` option for discovering IMAP folders. The original patch by Aditya Garg added documentation section explaining how to interpret the raw IMAP protocol output, using Gmail's folder naming scheme (like "[Gmail]/Spam") as a concrete example. A follow-up version fixed minor wording in the docs.

Junio Hamano, while agreeing the current documentation is lacking, suggested the deeper issue might be the unfriendly nature of exposing raw IMAP protocol details (including attributes like `\HasNoChildren`) to end users. He floated the idea of modifying the code to present cleaner output rather than just documenting the current verbose format.

In the latest response, Garg defends the documentation-only approach, arguing that parsing and normalizing IMAP output in C would be challenging due to variability across email servers. He maintains that power users need access to the raw details for locating subfolders and tags, making documentation the more practical solution.

The discussion now centers on a design philosophy question: should Git hide IMAP protocol details as an implementation concern (Junio's view) or expose them as necessary technical information (Garg's position)? No resolution has been reached yet on whether to accept the documentation patch as-is or pursue code changes to improve the user experience.
