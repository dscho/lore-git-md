This is the first patch in a 2-part series to remove experimental status markers from `git-switch` and `git-restore`. The patch specifically removes the `-m` short flag for the `--merge` option in both commands, while keeping the long form.

The change is motivated by a desire to free up the short flag for potential future use (possibly for a `--move`-like feature similar to `git-branch`), since `-m` is currently used for an uncommon operation. The patch removes the short flag documentation and reorganizes the option handling in builtin/checkout.c to make the `--conflict` option explicitly accompany `--merge` in each command's implementation.

Key technical changes:
- Removes `-m` documentation from git-restore.adoc and git-switch.adoc
- Restructures builtin/checkout.c to move the `--merge` and `--conflict` options from common options to command-specific sections
- Maintains all existing functionality, only removing the short flag binding

This appears to be a well-considered change that aligns with the series' goal of finalizing these commands' interfaces. The patch follows up on previous discussion about flag usage and prepares for potential future extensions while being minimally disruptive to current users (who can continue using `--merge`). The implementation is clean and maintains all existing behavior while improving the code organization.
