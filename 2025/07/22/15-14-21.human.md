This is a platform compatibility discussion in the ongoing Rust integration thread, specifically addressing distribution-level challenges.

Eli Schwartz from Gentoo provides a comprehensive breakdown of Rust's limitations across various architectures and platforms in their distribution. The response builds on earlier concerns about niche architectures (HPPA/Alpha/m68k) by detailing additional problem areas: macOS/Solaris Prefix installations, musl libc compatibility issues, 32-bit architectures (i486, sparc32, riscv32), and s390/s390x disparities. A key theme is that 32-bit support is particularly problematic across multiple platforms.

The email highlights the compounding challenge that porting Rust to new architectures requires both LLVM and Rust compiler support, making GCC-rs an attractive alternative for broader compatibility. Schwartz includes practical commands for examining Gentoo's current Rust feature disablements, suggesting this data could inform Git's Rust adoption decision-making.

This contribution adds concrete distribution-level data to the thread's ongoing tension between performance improvements and platform support tradeoffs. While not proposing specific solutions, it strengthens the case for considering optional Rust support or fallback C implementations to maintain compatibility across Gentoo's diverse ecosystem. The detailed architecture-by-architecture breakdown provides valuable context for future discussions about Rust's feasibility as a hard dependency.
