This is a Windows compatibility patch that's part of an ongoing effort to improve Git daemon's signal handling and child process tracking. It's the first of two patches in v4 of this series.

The patch modifies Windows-specific code to support `sigaction(SIGCHLD)` with BSD-style semantics by adding SA_NOCLDSTOP flag support. The changes ensure Windows behaves consistently with the pipe-based child process tracking approach being developed, while maintaining backward compatibility with existing behavior where `signal()` returns SIG_ERR without setting errno.

Key technical changes include:
- Adding the SA_NOCLDSTOP flag definition (copied from Cygwin)
- Modifying the `sigaction()` implementation to handle SIGCHLD specially
- Preserving the existing error behavior for SIGCHLD signals

This continues the thread's focus on making the pipe-based tracking work across platforms while addressing Windows-specific concerns. The patch appears well-contained and focused on its specific compatibility task, though the broader discussion about Windows signal handling behavior (POSIX vs backward compatibility) remains ongoing in the thread.
