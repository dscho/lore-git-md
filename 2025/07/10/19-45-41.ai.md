This is a v4 patch series addressing signal handling in git-daemon, specifically focusing on Windows compatibility and OpenBSD cleanup behavior. The series represents Carlo Marcelo Arenas Belón's continued refinement of the pipe-based child process tracking approach while maintaining the thread's consensus on eliminating SA_RESTART manipulation.

The two patches in this version:
1. Modify Windows compatibility code to allow `sigaction(SIGCHLD)` with BSD-style semantics, adding SA_NOCLDSTOP flag support
2. Replace `signal()` with `sigaction()` in daemon.c while explicitly avoiding SA_RESTART to maintain expected EINTR behavior

Key technical changes from previous versions:
- Drops earlier SA_RESTART fallback patches per Phillip Wood's suggestion
- Focuses on making Windows signal handling consistent with the pipe-based approach
- Preserves the existing behavior where child process completion interrupts poll()
- Adds proper SA_NOCLDSTOP flag support from Cygwin

The series continues the thread's technical debate around Windows signal handling behavior, with Carlo advocating for maintaining current Windows behavior (no errno setting) rather than enforcing strict POSIX consistency. The changes appear to be a compromise position that enables the pipe-based tracking while still addressing OpenBSD's zombie process cleanup requirements.

The implementation touches Windows-specific compatibility code (mingw-posix.h and mingw.c) and the core daemon signal handling logic. The changeset is now more narrowly focused than previous iterations, having dropped several earlier patches from the series.
