Junio Hamano has proposed a significant change to Git's release model, moving from version-tagged releases to a time-based monthly tagging system (e.g., "Git 2.50.202508" for August 2025). The motivation comes from observing that distribution maintainers often struggle with backporting security fixes, clinging to outdated major versions long after Git's official maintenance period ends (currently supporting 8 parallel versions). 

Hamano suggests that making releases more frequent and less ceremonious might help break distros' habit of version lock-in, noting that Git maintains strong backward compatibility at the user level. The proposal is framed as an RFC to gauge community interest, particularly from distribution maintainers who would be most affected. No implementation details are provided yet - this is purely a conceptual discussion about whether such a model would actually help distributors and their users stay current with security updates.

The core question is whether psychological factors around version numbering are contributing to the maintenance burden, and if making releases more like rolling updates would improve the situation. Hamano is explicitly seeking feedback on whether this approach would address the real pain points distributors face.
