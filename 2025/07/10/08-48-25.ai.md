Performance optimization series for Git's pathspec bloom filters, v5. This iteration continues the work to optimize revision traversal with multiple pathspec elements by introducing a `struct bloom_keyvec` abstraction that replaces direct `struct bloom_key *` usage in `rev_info`.

Key changes in v5:
- Merged `bloom_keyvec_fill_key()` into `bloom_keyvec_new()` so keys are filled during creation
- Changed function parameter order for `bloom_key_fill()` to take the key struct first
- Added comprehensive documentation for the new keyvec API
- Maintained the single-pathspec fast path while extending to multiple pathspecs
- Includes performance measurements showing significant speedups (0.24s vs 2.36s on LLVM repo)

The series builds on the v4 discussion where:
- Derrick Stolee clarified the evaluation semantics should require ALL pathspecs to match (not ANY)
- Memory management was refined using `CALLOC_ARRAY()`
- Test/production API boundaries were cleaned up
- Case sensitivity behavior was documented (filters are case-sensitive regardless of `core.ignorecase`)

Changes touch bloom.c/h, revision.c/h, blame.c, line-log.c with test updates. The implementation now:
1. Creates a keyvec per pathspec item containing keys for each path component
2. Checks ALL keys in ALL keyvecs must match to skip tree traversal
3. Maintains the fast path for single pathspec cases
4. Adds cleanup helpers for the keyvec arrays

Performance impact is substantial for multi-pathspec cases while maintaining the existing optimization for single pathspecs. The series appears ready with only minor organizational suggestions remaining from reviewers.
