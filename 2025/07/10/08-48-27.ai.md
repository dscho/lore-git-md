This is a refactoring patch in the bloom filter optimization series, specifically addressing code style consistency for functions operating on `struct bloom_key`. The patch renames two key functions to follow Git's naming convention where functions operating on a struct S should be named S_verb. The changes are mechanical but touch multiple files that use these bloom filter utilities.

The main changes are:
1. `fill_bloom_key()` becomes `bloom_key_fill()`
2. `clear_bloom_key()` becomes `bloom_key_clear()`

The patch updates all callers across bloom.c/h, blame.c, line-log.c, revision.c, and the test helper. The function parameter order is also adjusted in `bloom_key_fill()` to put the `struct bloom_key` first, which is more idiomatic for this style of function.

This is part of a larger performance optimization series for pathspec bloom filters, but stands alone as a pure refactoring that improves code consistency without changing behavior. The changes are straightforward and unlikely to be controversial, though they do require coordinated updates across several files. The patch follows the established pattern seen elsewhere in Git's codebase for similar utility functions.
