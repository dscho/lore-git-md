This is a bugfix patch in the ongoing Git daemon signal handling series, specifically addressing Windows compatibility. It's the second of two patches in v4 of the RFC series that aims to improve child process tracking in `git-daemon`.

The patch replaces the old `signal()` call with `sigaction()` in `daemon.c` while carefully avoiding the `SA_RESTART` flag. This maintains the existing behavior where system calls should be interrupted when child processes complete, which is important for the daemon's operation. The change also removes the need to rearm the signal handler manually (previously required for SysV systems) by using BSD signal semantics consistently.

The implementation is straightforward - it sets up a `sigaction` structure with `SA_NOCLDSTOP` (added in the previous patch) and an empty handler function. This matches the thread's technical direction of moving away from `SA_RESTART` dependence while maintaining the daemon's expected interrupt behavior. The patch appears well-focused and builds on the Windows compatibility work from patch 1/2 in this series.

This continues the thread's gradual refinement of the pipe-based tracking approach, with the broader discussion still weighing POSIX consistency against backward compatibility, particularly on Windows. The change looks like a solid technical improvement that doesn't appear controversial, though it depends on the Windows-specific groundwork laid in the first patch of the series.
