This is a v4 patch series addressing Windows compatibility in Git daemon signal handling, with Junio Hamano's final review and typo fixes before queuing. The series now consists of two patches (down from three in previous versions) that complete the transition from `signal()` to `sigaction()` while maintaining Windows compatibility.

The first patch fixes typos in the Windows `sigaction(SIGCHLD)` implementation, correcting "Cygwinr" to "Cygwin" and "sigacgtion" to "sigaction". This maintains the Windows behavior where the function returns SIG_ERR without setting errno, while adding the SA_NOCLDSTOP flag from Cygwin (though it remains unused in the implementation).

The second patch (unchanged from previous versions) completes the transition to `sigaction()` in daemon.c for child process tracking. Junio explicitly notes this leaves the self-pipe wake mechanism for future work, which aligns with the thread's consensus to handle signal handling changes separately from the pipe-based tracking approach.

Key technical points confirmed in this final review:
- The Windows-specific `sigaction()` behavior (returning SIG_ERR without errno) is preserved
- Cygwin's SA_NOCLDSTOP flag is properly referenced
- The changes maintain compatibility while cleaning up the signal handling code
- The separation between signal handling changes and future pipe-based tracking is intentional
