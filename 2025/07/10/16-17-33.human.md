This is a final cleanup patch in the performance optimization series for Git's pathspec bloom filters. Junio Hamano points out two now-unused variables in `prepare_to_use_bloom_filter()` that can be removed since the logic they supported has been moved to helper functions in earlier patches. The `bloom_keyvec` variable is no longer needed because keyvecs are now handled directly via the helper's return value, and `p` became obsolete when path processing logic was relocated.

This minor cleanup follows the major refactoring work that introduced the `bloom_keyvec` abstraction to optimize multiple literal pathspec queries. The patch doesn't change any functionality - it just removes dead code left over from the architectural changes in the series. Given the thorough review history of the bloom filter optimization work and Junio's attention to detail, this cleanup looks like a straightforward final polish before merging.
