Refactoring patch in a series moving MIDX tracking to per-source storage.

This is reviewing patch 2/8 in Patrick Steinhardt's series restructuring MIDX handling to attach to individual `struct odb_source` instances rather than tracking globally. The patch refactors `prepare_packed_git_one()` to work directly with sources rather than object directories, eliminating the need to search for matching MIDX files since they're now directly accessible via the source's `multi_pack_index` field.

Key technical changes:
- Changes `prepare_packed_git_one()` signature to take `struct odb_source*` instead of `struct repository*` and object directory path
- Directly uses source's pre-loaded MIDX (`source->multi_pack_index`) rather than searching the global MIDX list
- Simplifies the function by removing MIDX matching logic and consolidating initialization into a struct declaration
- Updates callers to pass the source directly
- Maintains the same core functionality while reducing indirection

The review from Justin Tobler is positive, noting the simplification enabled by having MIDX, objdir, and repository information readily available in the source structure. The changes align with the series' goal of moving MIDX tracking to be source-specific while maintaining existing behavior. This patch builds on the foundation laid in patch 1 (introducing per-source MIDX storage) and will be followed by further conversions of MIDX-related functions in subsequent patches.
