This is a bugfix patch addressing an issue with locale handling in HTTP requests. Brian M. Carlson noticed that some users include "C" or "POSIX" in their Accept-Language headers when making Git requests, which are valid locales but not valid language codes. While he's only observed "C" in practice, the patch proactively filters out both since they serve the same purpose.

The change is straightforward - it modifies the HTTP client code to strip these values from the Accept-Language header before sending requests. The patch includes tests verifying this behavior in the HTTP push test suite. The motivation comes from real-world observations (including a GitLab issue reference) where these invalid language codes appear in debugging traces.

This appears to be a clean, well-justified fix for a minor but real issue. The patch is small, focused, and comes with test coverage, making it likely to be uncontroversial. While the impact is limited to HTTP interactions, it helps maintain protocol correctness when clients have unusual locale settings.
