A bug report describes unexpected behavior with `git commit --verbose` when using VS Code as the editor. The reporter found that when configured with `core.editor = code --wait` and `commit.verbose = true`, VS Code includes all text below Git's scissor-line marker (`# ------------------------ >8 ------------------------`) in the final commit message, rather than stripping it as expected. 

The issue was reproduced on Git 2.50.1 running on macOS (ARM64). The reporter provided clear steps to reproduce the problem, which appears to stem from an interaction between Git's verbose commit message generation and VS Code's handling of the temporary commit message. This could impact developers using VS Code-based Git workflows with verbose commits enabled. No solutions or workarounds have been proposed yet in the thread.
