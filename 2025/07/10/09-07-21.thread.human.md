This thread reports a bug where `git commit --verbose` fails to properly strip text below the scissor-line marker when VS Code is configured as the editor. The original reporter observed this on Git 2.50.1 on macOS ARM64, where the diff content below `# ------------------------ >8 ------------------------` was incorrectly included in the final commit message.

Junio C Hamano has since attempted to reproduce the issue using a different editor (not VS Code) and confirmed that Git's scissor-line handling works as expected in that case. His test methodology involved creating a detached HEAD state and verifying three aspects of the scissor-line behavior, all of which functioned correctly with his editor. While Junio couldn't test with VS Code directly, his results suggest the issue may lie in how VS Code interacts with Git's temporary commit message file rather than being a core Git bug. The investigation now points toward VS Code's specific behavior in this workflow.
