This is patch 5/8 in a refactoring series moving MIDX tracking from global state to per-source storage. The patch converts `get_multi_pack_index()` to operate on individual `struct odb_source` instances rather than returning a global linked list. This requires callers to explicitly prepare alternates before iteration and handle each source's MIDX separately.

Key technical changes:
- Renames and repurposes `get_multi_pack_index()` to take a source parameter
- Updates all callers to iterate sources and call the function per-source
- Adds explicit `odb_prepare_alternates()` calls where needed
- Simplifies `lookup_multi_pack_index()` by using the new source-based lookup
- Removes the now-unused `get_local_multi_pack_index()` function
- Touches MIDX handling in pack-objects, repack, object-name resolution, and bitmap code

The changes follow the series' pattern of moving MIDX tracking to be source-local while maintaining functionality. Justin Tobler's review confirms the technical approach makes sense, though he previously questioned whether an earlier patch's optimization flag was necessary. The patch intersects with Junio Hamano's note about a conflict with commit 5ee86c27's use of `get_local_multi_pack_index()`, which this patch removes.
