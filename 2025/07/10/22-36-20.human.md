This is a discussion about Git's release schedule, specifically responding to Junio Hamano's RFC proposing a shift to time-based monthly releases to encourage distros to stay current. Brian m. carlson expresses skepticism that this change would actually help distribution maintainers, arguing that distros generally avoid non-security updates regardless of release cadence.

The response highlights several concerns: Git does occasionally make incompatible changes (like default behavior modifications) that distros wouldn't want to introduce mid-cycle. The example of Chromium and Firefox's frequent releases shows that even security-update-only models don't make distros happy about frequent updates. Brian suggests that while more frequent releases might benefit users directly, they're unlikely to change distro maintainers' conservative update policies.

The email provides concrete examples of problematic changes (case-insensitive filesystem bugs, the `init.defaultBranch` advice message) that would frustrate users if introduced via unattended security updates. The overall assessment is that while the problem of outdated distro packages is real (as seen in Git LFS experience), changing release cadence probably isn't the solution. The tone is constructive but firmly skeptical about the proposal's effectiveness for its stated goal.
