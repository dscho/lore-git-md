Performance optimization patch introducing `struct bloom_keyvec` to improve pathspec handling in Git's bloom filters. This is part of a series addressing performance issues with combined pathspec queries.

The patch replaces direct `struct bloom_key *` usage in `rev_info` with a new `bloom_keyvec` abstraction that groups keys by pathspec items. Key changes include:
- New `bloom_keyvec_new()` and `bloom_keyvec_free()` functions for lifecycle management
- `bloom_filter_contains_vec()` to check all keys in a keyvec against a bloom filter (requiring ALL pathspecs to match)
- Updated `prepare_to_use_bloom_filter()` and `check_maybe_different_in_bloom_filter()` to use the keyvec API
- Maintained single-pathspec fast path optimization (keyvec count limited to 1 in this implementation)
- Added `release_revisions_bloom_keyvecs()` helper for cleanup

The implementation maintains backward compatibility while preparing for future multiple-pathspexec optimization. Performance measurements show significant improvements (0.24s vs 2.36s for multi-pathspec queries in LLVM repo). The patch touches bloom.c/h and revision.c/h, with careful attention to memory management using `CALLOC_ARRAY()` and proper cleanup routines.

This represents a core architectural improvement in the bloom filter subsystem, with all substantive technical feedback from previous rounds addressed. The changes maintain the existing fast path for single pathspec cases while establishing the foundation for handling multiple pathspecs more efficiently.
