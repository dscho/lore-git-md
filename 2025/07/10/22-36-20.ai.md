This is a response in the ongoing discussion about changing Git's versioning scheme to encourage distribution maintainers to update more frequently. Brian m. carlson expresses skepticism that the proposed time-based monthly tags would actually solve the problem of distros sticking to outdated versions.

The response argues that even with more frequent releases, distributions are unlikely to adopt them for non-security updates due to several factors: occasional backward-incompatible changes (like default behavior changes), unexpected user-visible changes (like advice messages), and the potential for new bugs. The email cites real-world examples where frequent updates caused problems, including a case-insensitive filesystem cloning bug and the disruptive `init.defaultBranch` advice message.

Carlson draws parallels to other projects (Chromium, Firefox) where frequent updates are already a pain point for distros, and shares experience from maintaining Git LFS where outdated distro packages persisted despite upstream fixes. While sympathetic to the goal, the response concludes there may not be a good technical solution to the underlying distro maintainer psychology. The core concern remains that production environments using automated security updates could be broken by non-critical Git updates.
