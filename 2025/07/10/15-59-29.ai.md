This is a follow-up in the gitk Tcl/Tk error thread, confirming the diagnosis of a distribution packaging issue rather than an upstream Git problem. Junio Hamano initially misread the report as potentially indicating a backport error in Git's own maintenance releases, but confirms after checking that Git 2.43.7 and newer versions are unaffected. The issue appears to be specific to downstream distributions that backported security fixes to older Git versions (pre-2.43.7) incorrectly, as previously identified by Johannes Sixt. The email serves to clarify that the root cause lies with distribution maintainers rather than the Git project itself, while acknowledging Johannes' quick response in identifying the packaging issue. No new technical details are added beyond what was already established in the thread - the focus is on confirming the scope of the problem and ruling out upstream responsibility.
