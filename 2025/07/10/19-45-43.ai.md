This is the second patch in a v4 series addressing Git daemon signal handling and child process tracking, specifically focusing on Windows compatibility. The patch replaces the use of `signal()` with `sigaction()` in `daemon.c` while carefully avoiding the SA_RESTART flag to maintain the existing behavior where system calls should be interrupted upon child process completion.

Key technical changes include:
- Removal of the signal handler rearming call (previously needed for SysV systems)
- Addition of SA_NOCLDSTOP flag to prevent SIGCHLD signals for stopped children
- Preservation of the existing poll() behavior when children complete
- Maintenance of BSD-style signal semantics

The change builds on the Windows compatibility work from patch 1/2 (adding SA_NOCLDSTOP support) while implementing the core signal handling approach that works across platforms. The empty handler remains but now relies on proper sigaction() behavior rather than manual rearming. This aligns with the thread's technical consensus to eliminate SA_RESTART dependence while maintaining current Windows behavior.

The patch appears well-focused and maintains backward compatibility requirements established in the thread discussion. It represents a key piece of the pipe-based tracking approach being evaluated, though the broader debate about POSIX consistency vs. backward compatibility remains open. The implementation looks technically sound for its stated purpose of transitioning from signal() to sigaction() while preserving existing behavior.
