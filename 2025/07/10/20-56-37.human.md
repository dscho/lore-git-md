Refactoring patch moving MIDX tracking from global to per-source storage, part of a larger series preparing for pluggable ODB backends.

This first patch in an 8-part series begins restructuring how Git tracks multi-pack indices (MIDX) by moving them from a global linked list in `struct object_database` to individual `struct odb_source` instances. The change better matches the on-disk organization where each object source (like an alternate) has its own MIDX if present, and prepares for future where some backends may not use MIDX at all.

The patch modifies `prepare_multi_pack_index_one()` to work with a specific source rather than searching the global list, storing the MIDX pointer directly in the source. It maintains temporary compatibility by still inserting into the global list, which will be removed in later patches. The changes touch core MIDX and packfile handling code across 4 files, with careful attention to cleanup paths.

Justin Tobler's reply confirms the approach makes sense, noting the temporary awkwardness of maintaining both storage methods will be resolved as the series progresses. The careful, well-explained changes follow established refactoring patterns for the ongoing object database abstraction work.
