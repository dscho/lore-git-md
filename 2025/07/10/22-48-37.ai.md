Refactoring patch completing the MIDX tracking migration from global to per-source storage.

This is the final patch in Patrick Steinhardt's series to move MIDX tracking from a global linked list in the object database to per-source storage in `struct odb_source`. The patch removes the now-unused global MIDX infrastructure that was kept for compatibility during the migration, including:

1. The `multi_pack_index` field from `struct object_database`
2. The `next` pointer from `struct multi_pack_index`
3. All remaining global MIDX list maintenance code in `prepare_multi_pack_index_one()`
4. Global MIDX cleanup paths in `clear_midx_file()` and `close_object_store()`

The changes are straightforward deletions of now-dead code, with patches 1-7 having migrated all MIDX operations to use the per-source storage. Justin Tobler notes the simplicity of the final cleanup, observing we no longer need to maintain the MIDX list in the object database since each source manages its own MIDX state independently.

This completes the technical goal of the series - MIDX files are now properly associated with their corresponding object sources rather than being tracked globally. The change better matches MIDX's on-disk organization and supports future pluggable backends. With this patch, all MIDX-related code has been converted to the new model and the transitional compatibility code can be removed.
