This thread discusses improving Git's HTTP protocol compliance by filtering invalid locale values ("C", "POSIX", and variants) from Accept-Language headers, as these system locales don't meet IANA language tag requirements. The patch modifies `http.c` with test coverage in `t/t5541-http-push-smart.sh`.

Junio Hamano initially questioned whether this addresses actual breakage or is preventative standards compliance, with Brian Carlson clarifying it's primarily a hygiene improvement rather than a fix for observed problems. Collin Funk then raised a more fundamental question about whether Git should attempt to map system locales to proper BCP 47 language tags rather than just filtering, though acknowledged the practical limitations of requiring a comprehensive language tag database.

In the latest response, Han Young reinforces the practical challenges with locale conversion, noting issues with incomplete locale support across different Linux systems (particularly musl) and ambiguities in language matching. Young suggests that while hardcoding locale names might be possible, the simpler filtering approach may be more practical given cross-platform variability.

The discussion has clarified that this is a standards compliance improvement rather than a bugfix, with the technical implementation remaining focused on filtering "C" and "POSIX" locales. The thread shows consensus forming around keeping the solution simple due to the complexity of comprehensive locale conversion, though the patch will need a v2 to incorporate documentation corrections (fixing "LANGUAGE header" to "LANGUAGE environment variable" in the description). The test coverage in t5541 remains valid for verifying the behavior.
