This thread discusses improving Git's HTTP protocol compliance by filtering invalid locale values ("C", "POSIX" and variants) from Accept-Language headers, as these system locales violate IANA language tag requirements. The patch modifies `http.c` with test coverage in `t/t5541-http-push-smart.sh`.

The discussion began with Junio Hamano questioning whether this addresses actual breakage or is purely preventative standards compliance. Brian Carlson clarified it's primarily a hygiene improvement, though it could theoretically prevent issues where users expect localized responses. Collin Funk and Han Young raised deeper questions about whether Git should attempt to map system locales to proper language tags, but acknowledged the practical challenges of such an approach.

In the latest update, Justin Tobler provided a technical review noting the patch aligns with existing behavior when NO_GETTEXT is defined. He examined the implementation and test cases, suggesting (but not strongly advocating for) a potential alternative approach using length-based validation. The test coverage is confirmed as adequate for verifying the filtering behavior.

Key open questions remain about whether this qualifies as a bugfix versus refactoring (affecting merge timing), and whether selective filtering is preferable to more comprehensive solutions given platform variability. The thread appears to be converging on the current selective filtering approach, awaiting either further feedback or Brian Carlson's promised v2 submission.
