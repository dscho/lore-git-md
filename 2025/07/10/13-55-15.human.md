Performance optimization completing the bloom filter pathspec series. This final patch in the series enables bloom filter optimization for multiple literal pathspecs by removing the previous restriction that blocked the optimization when more than one pathspec was present. The key changes are:

1. Modifying `forbid_bloom_filters()` to only reject pathspecs containing wildcards or non-literal magic bits, regardless of how many pathspecs are present
2. Updating `prepare_to_use_bloom_filter()` to process all pathspec items in a loop rather than just the first one
3. Adding comprehensive test cases to verify the optimization works correctly with multiple pathspecs while still properly rejecting cases with actual wildcards

Performance improvements are substantial, particularly in large repositories - the LLVM project sees a 7.5x speedup (262ms vs 1.97s) when using multiple pathspecs with bloom filters enabled. The Git repository itself shows a more modest but still meaningful 1.33x improvement. The patch maintains all existing behavior for non-literal pathspec cases while unlocking significant optimizations for the common case of multiple exact path matches.

This builds on the earlier infrastructure changes in the series (the `bloom_keyvec` abstraction and related API improvements) and has been through multiple review rounds with Junio Hamano, Patrick Steinhardt, and Derrick Stolee. The implementation appears solid with thorough test coverage and clear performance measurements demonstrating the value of the optimization.
