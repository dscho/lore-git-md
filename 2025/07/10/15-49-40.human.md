Performance optimization for bloom filters with multiple pathspecs. This is the final patch in a series that speeds up revision traversal when using multiple literal pathspecs with bloom filters. The key change is allowing bloom filter optimization when all pathspec items are literal (previously disabled for multiple pathspecs), while still rejecting wildcards and non-literal magic bits. 

The patch shows impressive speedups: 1.33x faster in the Git repository (55.1ms vs 73.1ms) and 7.5x faster in the LLVM repository (263ms vs 1.974s) for multi-pathspec queries. Test coverage verifies consistent results between optimized and non-optimized paths, and proper handling of wildcard cases.

The implementation builds on earlier refactoring that introduced `struct bloom_keyvec` to manage multiple bloom keys. This final version incorporates Derrick Stolee's suggested hyperfine benchmark results and test improvements. The series has undergone thorough review and appears ready for merging, having addressed all technical concerns while significantly improving performance for a common use pattern.
