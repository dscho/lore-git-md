This is a proposal to change Git's release model to better support downstream distributors. Junio Hamano suggests moving from the current numbered release system to a time-based tagging approach, where the tip of 'master' would be tagged monthly (e.g., Git 2.50.202508 for August 2025). The motivation comes from observing that some distros struggle with backporting security fixes to their outdated Git versions, often maintaining older releases longer than the Git project officially supports.

The proposal aims to make version distinctions less significant, potentially encouraging distros to update more frequently. Hamano notes that since Git maintains backward compatibility at the user level, distros' insistence on sticking to old versions for "stability" may be counterproductive. The idea is to make releases so routine that distros might naturally adopt newer versions rather than backporting fixes to ancient ones.

This appears to be an early-stage RFC rather than a concrete plan, seeking feedback on whether this model would actually help downstream packagers. The proposal doesn't address potential challenges like how this would interact with Git's existing maintenance track system or how version pinning in scripts/tools might be affected. Given the source (the Git maintainer), this is clearly a serious proposal worth considering, though its ultimate viability will depend on community and distributor feedback.
