Performance optimization patch for Git's pathspec bloom filters, finalizing the series that enables optimization for multiple literal pathspecs. This patch modifies `forbid_bloom_filters()` to allow bloom filter usage when all pathspec items are literal, regardless of count, while still rejecting wildcards and non-literal magic bits. The implementation adds loops to initialize and check each pathspec item's bloom_keyvec when optimization is possible.

Key changes include:
- Removing the pathspec count check in `forbid_bloom_filters()`
- Converting single-pathspec initialization to loop over all items
- Updating tests to verify bloom filter usage with multiple literal pathspecs
- Adding explicit tests for escaped wildcard pathspecs that should not use bloom filters

Performance benchmarks show significant improvements:
- 1.33x speedup in Git repository (55.1ms vs 73.1ms)
- 7.5x speedup in LLVM repository (263ms vs 1.974s)

The patch builds on Derrick Stolee's earlier refactoring and incorporates his suggested hyperfine benchmark output format. Lidong Yan indicates this will be included in the v6 series commit message. The changes maintain backward compatibility while optimizing the common case of multiple literal pathspec queries, with all substantive technical concerns from earlier reviews now addressed.
