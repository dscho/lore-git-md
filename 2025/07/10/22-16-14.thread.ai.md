Git release schedule RFC: Junio Hamano proposes shifting from version-tagged releases to time-based monthly tags (e.g. "Git 2.50.202508" for August 2025) to address distribution maintainers' tendency to cling to outdated versions. Current model supports 8 parallel versions, which may be excessive given Git's strong backward compatibility. The RFC questions whether making releases more frequent and less ceremonious would psychologically encourage distros to stay current, reducing the maintenance burden on both distros and the Git project. No implementation details yet - seeking community feedback on whether this approach would actually help distributors. Core concern is that distros maintaining ancient versions causes harm to their users and the ecosystem.
