Git release schedule RFC: Junio Hamano proposes shifting from version-tagged releases to time-based monthly tags (e.g. "Git 2.50.202508" for August 2025) to address distribution maintainers' tendency to cling to outdated versions. Current model supports 8 parallel versions, which may be excessive given Git's strong backward compatibility. The RFC questions whether making releases more frequent and less ceremonious would psychologically encourage distros to stay current.

brian m. carlson expresses skepticism that time-based tags would solve the distro update problem, citing real-world examples where frequent updates caused issues: case-insensitive filesystem cloning bugs, disruptive `init.defaultBranch` advice messages, and occasional backward-incompatible changes. Argues distros are unlikely to adopt non-security updates due to frequency-induced risks, drawing parallels to Chromium/Firefox update pains. Shares experience from Git LFS where outdated distro packages persisted despite upstream fixes. Concludes the core issue is distro maintainer psychology and production environment risk tolerance, with no clear technical solution yet identified. The discussion remains open on whether the proposed change would meaningfully improve version adoption.
