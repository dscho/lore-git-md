Git commit verbose scissor-line bug report with VS Code editor.

Bug report describes unexpected behavior in `git commit --verbose` when VS Code is configured as editor (`core.editor = code --wait`). Reporter observes text below the scissor-line marker (`# ------------------------ >8 ------------------------`) is incorrectly included in the final commit message rather than being stripped as expected. Reproduction case uses Git 2.50.1 on macOS ARM64 with `commit.verbose = true` and `git ci -a` alias.

Junio C Hamano attempted reproduction using a different editor (not VS Code) with test methodology: `git checkout --detach HEAD` and `git reset --soft HEAD~23` to create test state. Verified three aspects: (1) scissor-line marker presence, (2) proper commit creation when editing above marker, (3) `git show` and `git cat-file` output correctness (with/without diff respectively). Confirmed expected behavior with non-VS Code editor, suggesting issue is specific to VS Code's handling of temporary commit message file. Root cause remains unconfirmed as Junio does not use VS Code for direct verification.

Current status: Core Git functionality confirmed working as expected with standard editors. Investigation points toward VS Code-specific behavior in processing the temporary commit message file during verbose commit workflow. No proposed fix yet. May affect VS Code users relying on verbose commits.
