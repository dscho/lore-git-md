Performance optimization patch completing the bloom filter pathspec series. This final patch enables bloom filter optimization for multiple literal pathspecs by:

1. Modifying `forbid_bloom_filters()` to only reject pathspecs containing wildcards or non-literal magic bits, allowing multiple literal pathspecs to use bloom optimization
2. Updating `prepare_to_use_bloom_filter()` to process all pathspec items in a loop using the new `convert_pathspec_to_filter()` helper
3. Adding comprehensive test cases verifying:
   - Bloom filter usage with multiple literal pathspecs
   - Correct behavior with wildcards in pathspecs
   - Case sensitivity handling
   - Backward compatibility with single pathspec cases

The patch shows significant performance gains in benchmarks:
- 1.33x speedup in Git repository tests (55.1ms vs 73.1ms)
- 7.5x speedup in large repos like LLVM (263ms vs 1.974s)

Key technical changes:
- Removes the pathspec count check in `forbid_bloom_filters()`
- Adds loop to process all `revs->pruning.pathspec.items`
- Maintains existing wildcard and magic bit rejection logic
- Updates tests to verify both optimization and fallback cases
- Uses `convert_pathspec_to_filter()` helper introduced earlier in series

The implementation builds on prior review feedback, with Derrick Stolee providing final benchmarks and test verification. The changes complete the series' goal of optimizing multiple-pathspexec cases while maintaining correct behavior for all edge cases.
