Performance optimization series for Git's pathspec bloom filters, version 5. This patch series builds on previous iterations to enable bloom filter optimization for multiple pathspec elements during revision traversal, addressing a performance issue reported by Kai Koponen.

The key changes in v5 include:
- Restructuring the bloom key API to pass `struct bloom_key *` as first parameter
- Merging `bloom_keyvec_fill_key()` and `bloom_keyvec_new()` into a single function
- Maintaining the single-pathspec fast path while adding support for multiple pathspecs

Performance impact is significant - benchmarks show `git log` time dropping from 2.365s to 0.240s on the LLVM repository when querying two files. The implementation introduces `struct bloom_keyvec` to manage multiple bloom keys, replacing direct `struct bloom_key *` usage in `rev_info`.

The series has undergone thorough review from Derrick Stolee, Junio Hamano, and others, with all substantive technical feedback addressed. Remaining suggestions focus on presentation (performance measurements, code organization) rather than core functionality. The changes maintain backward compatibility while improving multiple-pathspec performance through the new keyvec abstraction.
