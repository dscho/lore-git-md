Performance optimization for Git's pathspec bloom filters, final patch in a series addressing multiple-pathspexec performance. This patch enables bloom filter optimization for multiple literal pathspecs while maintaining the fast path for single pathspecs.

The key change modifies `forbid_bloom_filters()` to allow bloom filter usage when all pathspec items are literal, regardless of their count. The implementation now checks each pathspec item individually for non-literal magic bits. The patch also updates test cases to verify the optimization works correctly with multiple literal pathspecs while still rejecting cases with actual wildcards.

Performance measurements from earlier in the series show significant improvements - from 2.36s to 0.24s for multi-pathspec queries in the LLVM repository. The changes maintain backward compatibility and don't affect the existing fast path for single pathspec cases.

The patch includes comprehensive test updates in t4216-log-bloom.sh that verify:
- Consistent results between optimized and non-optimized paths
- Bloom filters are correctly avoided when any pathspec contains wildcards
- Proper handling of escaped wildcard characters

This concludes the series that has undergone multiple review rounds with Junio Hamano, Patrick Steinhardt, and Derrick Stolee. The implementation appears solid, with thorough test coverage and clear performance benefits for a common revision traversal case.
