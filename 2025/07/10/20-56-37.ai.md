This is the first patch in an 8-part refactoring series moving MIDX tracking from global object database state to per-source storage. The change prepares for pluggable backends by better aligning MIDX organization with their actual on-disk layout (one per source rather than global).

The patch introduces a `multi_pack_index` field in `struct odb_source` and modifies `prepare_multi_pack_index_one()` to work with individual sources rather than searching a global linked list. While maintaining temporary backward compatibility by still inserting MIDX entries into the global list, it now also stores them in their corresponding source. The changes touch core MIDX/packfile handling in `midx.c`, `packfile.c`, and related headers.

Key technical changes include:
- New `multi_pack_index` field in `struct odb_source`
- Modified `prepare_multi_pack_index_one()` signature and implementation
- Updates to cleanup paths in `clear_midx_file()` and `close_object_store()`
- Header file adjustments for new dependencies and field ordering

The patch follows the series' pattern of incremental changes - it introduces the per-source storage while keeping the global list temporarily. Justin Tobler's review notes the temporary awkwardness of maintaining both storage methods but recognizes this will be resolved in later patches. The changes appear carefully implemented with proper cleanup handling and maintain existing functionality during the transition.
