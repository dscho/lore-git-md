This is a documentation patch continuing the discussion about clarifying the empty template behavior in `git init`. Todd Zullinger provides additional historical context, pointing to the original 2008 commit (d65d2b2fb4) that introduced the behavior where `--template=` skips template copying to prevent dangerous filesystem operations. He notes this has been stable behavior for 17 years across Git versions, strengthening the case for documentation.

The email suggests expanding the TEMPLATE DIRECTORY section in git-init(1) to explicitly document this behavior, and recommends verifying whether empty values for `init.templatedir` and `GIT_TEMPLATE_DIR` exhibit the same behavior for completeness. The proposed documentation approach would cover all three configuration methods (CLI option, config, and environment variable) with a single statement about empty values if they behave consistently.

This builds on prior confirmations from Han Young and Boris Kolpackov about real-world usage of this feature by package managers. The thread shows clear consensus that documenting this long-standing implementation detail is worthwhile, with no objections raised. The patch would affect only documentation (git-init.adoc) without changing any behavior in the template handling code (builtin/init-db.c).
