Documentation patch clarifying the long-standing behavior of `git init --template=` to skip template copying. 

This email from Han Young confirms and expands on the thread's original observation that passing an empty path to `--template` has intentionally skipped template copying since Git 1.5.6.4 (2008). The behavior is particularly useful for tools like package managers that create temporary repositories just for fetching remote data, where template files would add unnecessary overhead. 

Young notes this is already in wide use by some package managers via `git clone` (which internally uses `init --template`), making it effectively a de facto standard behavior despite lacking documentation. The patch would formalize this understanding by explicitly documenting the empty-string case in git-init(1)'s TEMPLATE DIRECTORY section.

The exchange shows consensus that this is a straightforward documentation improvement of existing behavior rather than a behavior change. The thread has no objections so far, suggesting this is likely to proceed smoothly. The clarification would help users understand current practices while giving future tooling explicit permission to rely on this behavior.
