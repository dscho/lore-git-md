Performance optimization patch completing the bloom filter pathspec series. This final patch in Lidong Yan's v4 series enables bloom filter optimization for multiple literal pathspec items in revision traversal, while maintaining the existing fast path for single pathspecs.

The key changes:
1. Modifies `forbid_bloom_filters()` to allow multiple pathspec items if they're all literal (removing the `spec->nr > 1` check)
2. Extends `prepare_to_use_bloom_filter()` to handle multiple pathspecs by creating a bloom keyvec for each one
3. Adds `release_revisions_bloom_keyvecs()` helper to clean up all bloom keyvecs in `rev_info`
4. Updates tests in t4216-log-bloom.sh to verify:
   - Multiple literal pathspecs now use bloom filters
   - Wildcard pathspecs still bypass bloom filters
   - Results match non-bloom-filtered output

The implementation carefully maintains all existing behavior for non-literal pathspecs while adding support for the multiple literal pathspec case. The test changes demonstrate the optimization works correctly by comparing bloom-filtered and non-bloom-filtered outputs.

This completes the series' goal of optimizing combined pathspec queries through the new `bloom_keyvec` abstraction. All substantive technical feedback from Junio Hamano and Patrick Steinhardt has been addressed in previous iterations, with this final version focusing on the multiple-pathspexec optimization itself. The changes touch revision.c bloom filter handling and test verification, with no changes to the core bloom filter data structures.
