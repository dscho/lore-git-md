This is a cover letter for the third version of Patrick Steinhardt's patch series to establish reftable as Git 3.0's default ref storage backend, now focusing on the rollout strategy and ecosystem coordination. The series builds on prior technical consensus about implementation location in setup.c while introducing new user-facing elements. 

The cover letter clarifies the dual rollout approach: announcing the breaking change for Git 3.0 while enabling immediate opt-in via `feature.experimental`. This experimental flag serves as a testing ramp while ecosystem support (JGit/libgit2/Gitoxide) is confirmed. The v3 changes refine documentation by adding compression benefits to the reftable advantages list and polishing commit messages.

Key technical elements carried forward include the `REF_STORAGE_FORMAT_DEFAULT` define and build-options reporting, while new test coverage in t0001-init.sh verifies the experimental flag behavior. The implementation remains guarded by `WITH_BREAKING_CHANGES` for conditional compilation. Documentation updates in BreakingChanges.adoc now comprehensively list reftable benefits: case-sensitivity resolution, Unicode handling, performance gains, and space efficiency via prefix compression.

The series explicitly avoids expanding scope to REPOSITORY_FORMAT_INIT unification despite identifying it as future technical debt. Current changes maintain focus on the versioned default transition path while preserving all existing compatibility mechanisms. Documentation wording refinements from prior review rounds appear addressed, with the compression benefit addition being the most notable v3 change.
