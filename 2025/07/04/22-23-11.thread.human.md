This thread addresses a build failure on FreeBSD caused by recent changes to sysinfo() detection that conflicted with FreeBSD's preferred sysctl() approach. The proposed solution, from Ramsay Jones, reorders build system checks to prioritize BSD's native sysctl() over sysinfo compatibility, modifying both configure.ac and meson.build files.

Eric Sunshine reviewed the patch, noting that while it's a simple and effective fix, an alternative approach modifying preprocessor conditionals in builtin/gc.c might have provided a more comprehensive solution. However, he acknowledges the current approach is adequate and well-documented. The change has already been verified by Renato Botelho on FreeBSD systems.

The discussion appears to be converging on this solution, with no major objections remaining. The patch maintains existing behavior on non-BSD systems while cleanly resolving the FreeBSD-specific build issue. This seems to be a straightforward platform compatibility fix that's ready to be merged.
