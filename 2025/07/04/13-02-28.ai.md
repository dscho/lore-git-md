This is a feature patch series adding pagination capability to `git for-each-ref` via a new `--skip-until` option. The v2 series refines the interface and behavior based on feedback from the initial submission.

Key technical changes in v2:
- Replaces the `set_prefix` boolean parameter in `ref_iterator_seek()` with a `flags` field using `REF_ITERATOR_SEEK_SET_PREFIX` for clearer intent
- Ensures prefix state is properly reset when seeking without setting prefix
- Adds validation to prevent `--skip-until` being used with `--sort` since seeking happens before sorting
- Includes various style fixes and documentation improvements

The implementation works across all ref backends (files, packed, reftable) with O(log N) performance by leveraging sorted reference lists. The files backend requires more complex handling due to its ref-cache structure, while packed and reftable backends benefit from their inherently sorted nature.

Notable behavioral characteristics:
- The skipped reference (if it exists) is included in the current page output
- Subsequent pages correctly exclude the marker ref even if deleted between requests
- New refs inserted before the skip marker in sort order are properly excluded
- The implementation maintains expected cursor-based pagination semantics

The thread context shows this builds on prior discussion about race conditions and interface design, with Patrick Steinhardt raising concerns about state management in the seek operation. The v2 changes address some of these by making prefix handling more explicit through the flags field.

The series consists of 4 patches:
1. Exposes `ref_iterator` in refs.h for external use
2. Removes unused `find_ref_entry()` from ref-cache
3. Implements selective prefix setting in seek functions
4. Adds the `--skip-until` option to `for-each-ref`
