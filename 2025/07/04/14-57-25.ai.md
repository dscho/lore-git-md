This is a follow-up in the thread about documenting empty template directory behavior in `git init`. Kristoffer Haugsbakk points out that there's an existing `--no-templates` flag that also prevents template copying, though it works differently from the empty path approach being discussed.

The email notes that when using both `--template` with a path and `--no-templates`, the template directory contents (including a custom `description` file) are not copied, demonstrating that `--no-templates` overrides the template path specification. This suggests there are two distinct mechanisms to skip template copying: the undocumented empty path behavior (which the thread has been discussing) and the documented `--no-templates` flag.

This new information adds complexity to the documentation effort, as the man page would need to explain both methods and their interaction. The thread had previously focused only on the empty path behavior, which has been in place since 2008, while `--no-templates` appears to be a more recent addition (introduced in 2.38.0 per code history). The patch will now need to address both approaches and clarify whether they are alternatives or have different use cases.
