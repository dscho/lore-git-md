Aditya Garg raised a question about how Git would convert SHA-1 hashes to SHA-256 during the planned transition, suggesting (incorrectly) that the system could simply re-hash the SHA-1 strings themselves. brian m. carlson, who leads the SHA-256 transition effort, provided a detailed technical response explaining why this approach wouldn't work - it would still be vulnerable to SHA-1 collisions and break Git's content-addressable storage model.

The correct approach involves hashing blob contents directly with SHA-256, while rewriting object references in trees, commits and tags to SHA-256 format before hashing. brian pointed to existing implementation work in `object-file-convert.c` and design documentation, noting that SHA-256-only repositories can already be created with `git init --object-format=sha256`. He also mentioned upcoming protocol extensions for interoperability and plans to discuss progress at Git Merge.

This exchange highlights both the technical complexity of the SHA-256 transition and the need for clear communication about the process. While the conversion mechanism is well understood by the core team working on it, newcomers may need help understanding why simple approaches like string re-hashing won't work. The thread serves as a useful reference point for others with similar questions about the transition.
