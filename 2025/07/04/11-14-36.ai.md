Performance optimization patch introducing `struct bloom_keyvec` to support multiple pathspec items in Git's bloom filter implementation. This is part 3/4 of a series addressing performance issues with combined pathspec queries.

The patch replaces direct `struct bloom_key *` usage in `rev_info` with a new `struct bloom_keyvec` abstraction that can store multiple bloom keys per pathspec item. Key changes include:
- New `bloom_keyvec_new()` and `bloom_keyvec_free()` functions for lifecycle management
- `bloom_filter_contains_vec()` to check all keys in a keyvec against a bloom filter
- Updated `prepare_to_use_bloom_filter()` and `check_maybe_different_in_bloom_filter()` to use the new keyvec API
- Maintains the single-pathspec fast path (keyvec count limited to 1 in this patch)

The implementation touches bloom.c/h and revision.c/h, with careful handling of memory allocation and cleanup. The changes follow Git's struct-verb naming conventions (`bloom_keyvec_*` prefix) and maintain backward compatibility while laying groundwork for future multiple-pathspec optimizations.
