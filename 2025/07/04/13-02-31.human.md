This is the third patch in a 4-part series implementing `--skip-until` pagination for `git for-each-ref`. The patch refines the ref iterator interface by adding a `flags` parameter to `ref_iterator_seek()`, allowing callers to distinguish between seeking to a specific reference (clearing any previous prefix) versus setting a new iteration prefix.

The key change replaces the previous boolean `set_prefix` approach with a proper flags field containing `REF_ITERATOR_SEEK_SET_PREFIX`. This makes the interface more explicit about its dual-purpose nature - the same function can now either seek to a position while clearing prefixes (default behavior) or set a new prefix for subsequent iteration (when the flag is set).

The implementation requires backend-specific adjustments, with the files backend needing the most work due to its ref-cache structure. The patch splits the files backend's seek logic into separate functions for prefix-setting versus pure seeking. The packed and reftable backends require simpler changes since they naturally work with sorted references.
