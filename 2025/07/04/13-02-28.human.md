This is a feature patch series adding pagination capability to `git for-each-ref` via a new `--skip-until` option. The series has already gone through significant discussion and refinement, with this being version 2 incorporating feedback.

The core functionality allows efficient iteration through large repositories by starting from a specified reference rather than always beginning from the start. The implementation builds on the existing `ref_iterator` infrastructure, with key changes to the seek functionality across all ref backends (files, packed, reftable).

Version 2 makes several improvements:
- Replaces the `set_prefix` boolean parameter with a proper flags field (adding `REF_ITERATOR_SEEK_SET_PREFIX`)
- Ensures prefix state is properly cleared when not setting a new prefix
- Disallows combining `--skip-until` with sorting options since seeking happens before sorting
- Includes various style fixes and documentation updates

The implementation handles edge cases well - the skipped reference is included in output, and subsequent pages correctly handle cases where the marker ref is deleted or new refs are inserted. Performance remains O(log N) due to the name-based seeking approach.

This appears to be a well-considered addition with thorough test coverage (188 new test lines). The interface changes are clean and the implementation handles all ref backends consistently. The discussion thread shows the design has been vetted for race conditions and edge cases.
