This is the third patch in a 4-part series implementing `--skip-until` pagination for `git for-each-ref`. The patch refactors the ref iterator interface to clarify the behavior of `ref_iterator_seek()` by introducing a flags-based approach.

The key changes:
- Replaces the ambiguous `prefix` parameter in `ref_iterator_seek()` with a clearer `seek` string and `flags` parameter
- Introduces `REF_ITERATOR_SEEK_SET_PREFIX` flag to explicitly control whether the seek string should also set the iteration prefix
- Implements backend-specific handling:
  - Packed and reftable backends get simplified logic since they use sorted lists
  - Files backend requires more complex changes due to its ref-cache structure
- Maintains backward compatibility by defaulting to prefix-setting behavior when the new flag is used

The patch addresses previous review feedback about interface clarity while maintaining all existing functionality. It cleanly separates the concepts of seeking to a position versus setting a filter prefix, which were previously conflated in the API. The changes span all ref backends (files, packed, reftable) with corresponding test updates.

This continues the series' focus on providing efficient O(log N) pagination while improving the internal API design. The implementation handles edge cases like concurrent ref modifications through position tracking rather than name-based offsets.
