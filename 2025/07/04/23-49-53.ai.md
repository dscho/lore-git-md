This is a platform compatibility fix for FreeBSD build issues. The email is part of an ongoing thread about build failures on FreeBSD caused by recent sysinfo() detection changes conflicting with FreeBSD's preferred sysctl() approach. Eric Sunshine is reviewing Ramsay Jones's proposed solution, which reorders build system checks to prioritize BSD's native sysctl() over sysinfo compatibility.

The patch modifies both configure.ac and meson.build to only enable HAVE_SYSINFO if HAVE_BSD_SYSCTL is not set. Sunshine notes that while the solution is simple and effective, an alternative approach of modifying the preprocessor conditionals in builtin/gc.c would have provided a more comprehensive fix that would work even if both macros were manually defined. However, he acknowledges the current solution is adequate and well-described in the commit message.

The change has already been tested and verified by Renato Botelho on FreeBSD. Sunshine's review confirms the patch is technically sound and the commit message provides sufficient context, though he notes he wasn't closely following the earlier discussion. The thread appears to be reaching consensus on this solution, with no major objections or outstanding questions remaining about the approach.
