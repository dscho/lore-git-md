Feature patch (part 2/2 of v3 series) implementing experimental opt-in for reftable as default ref storage format. This follows the first patch's documentation and infrastructure setup by adding runtime behavior where `feature.experimental=true` will cause new repositories to use reftable format, unless overridden by explicit `init.defaultRefFormat` or `GIT_DEFAULT_REF_FORMAT` environment variable.

The implementation adds a new config handler in setup.c that checks `feature.experimental` when no ref format is specified, defaulting to reftable when enabled. Three new test cases verify the precedence rules: experimental flag alone enables reftable; explicit init.defaultRefFormat overrides experimental; environment variable overrides both. The documentation update in feature.adoc explains the new behavior and summarizes reftable's advantages (case-sensitivity handling, compression, performance).

This continues the versioned default transition strategy from the SHA-256 migration, using experimental flag testing as an intermediate step before full rollout in Git 3.0. The patch maintains all prior technical decisions from the series while expanding test coverage of the new opt-in path. No ecosystem coordination blockers remain as the implementation preserves backward compatibility through the existing override mechanisms.
