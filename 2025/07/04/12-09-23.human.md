Performance optimization follow-up regarding case sensitivity in pathspec bloom filters.

Lidong Yan responds to Junio Hamano's question about how bloom filters handle case sensitivity, confirming through code analysis and practical testing that the current implementation is case-sensitive regardless of the filesystem's `core.ignorecase` setting. The investigation shows bloom filters are built without checking case sensitivity configuration, and benchmark results from an llvm-project repository on macOS system (where case insensitivity is default) demonstrate significantly slower performance for case-insensitive pathspec queries compared to exact matches.

This email provides important clarification about current behavior but doesn't propose any code changes - it's purely investigative. The findings confirm that case sensitivity optimizations (mentioned in the thread summary as deferred work) would indeed need to consider `core.ignorecase` to be effective. The clear performance difference (0.089s vs 0.458s for exact vs case-varied matches) helps quantify the potential benefit of future case-insensitive optimizations.
