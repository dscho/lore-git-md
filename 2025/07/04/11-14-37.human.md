Performance optimization for Git's pathspec bloom filters in revision traversal. This is the final patch in a series addressing performance issues with multiple pathspec queries.

The patch enables bloom filter optimization for multiple literal pathspec items by:
1. Modifying `forbid_bloom_filters()` to allow multiple pathspecs if all are literal
2. Adding per-pathspec bloom keyvec initialization in `prepare_to_use_bloom_filter()`
3. Introducing `release_revisions_bloom_keyvecs()` for cleanup
4. Updating tests to verify correct behavior with multiple pathspecs

The changes maintain the existing optimization for single pathspecs while extending it to handle multiple literal pathspecs efficiently. Test cases confirm the optimization works as expected and doesn't trigger for non-literal pathspecs. This builds on the `bloom_keyvec` abstraction introduced earlier in the series.

The implementation looks thorough, with careful handling of edge cases and proper memory management. The test coverage appears comprehensive, verifying both the optimization's correctness and its boundaries. This completes the core functionality of the series while leaving some optimizations (like case sensitivity handling) for future work.
