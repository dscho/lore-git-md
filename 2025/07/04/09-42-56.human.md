This is a key patch in Patrick Steinhardt's series to make reftable the default ref storage backend in Git 3.0. The patch formally announces the planned change in BreakingChanges.adoc and implements the technical wiring to make reftable the default when compiled with WITH_BREAKING_CHANGES.

The documentation update provides a comprehensive list of reftable's advantages over the current files backend, including case-sensitivity fixes, Unicode handling, atomic writes, performance improvements, and new details about space savings from prefix compression. The implementation maintains backward compatibility by keeping files as the default unless WITH_BREAKING_CHANGES is set, while adding infrastructure to detect the default format via git version --build-options.

This appears well-considered, with clear attention to ecosystem readiness (calling out JGit/libgit2/Gitoxide support as a prerequisite) and a measured transition path. The patch builds on prior technical consensus while adding new test coverage and documentation. As part of a versioned default change following the SHA-256 transition pattern, this looks like a carefully executed step toward the reftable future.
