This is a performance optimization patch series for Git's pathspec bloom filters, addressing a reported slowdown when using combined pathspec queries. The series is now in its fourth iteration, with refinements based on review feedback.

The core change enables bloom filter optimizations to work with multiple pathspec elements during revision traversal. The implementation introduces a new `struct bloom_keyvec` to manage multiple bloom keys (patch 3) and modifies the revision machinery to handle these keyvecs while preserving the fast path for single pathspecs (patch 4). The changes touch bloom.c/h and revision.c/h, with corresponding test updates.

Version 4 focuses on code organization and naming conventions, renaming functions to follow Git's subsystem patterns (moving from `*_bloom_key*` to `bloom_key_*` and `bloom_keyvec_*`). It also adds a new test helper for murmur3 hash calculation (patch 1) to clean up the bloom filter API by moving test-specific functionality out of the main code.

The series has undergone thorough review rounds with Junio Hamano and Patrick Steinhardt, addressing edge cases and API consistency. Some potential optimizations around case sensitivity handling (for PATHSPEC_ICASE) have been deferred to future work to keep this series manageable. The implementation looks well-considered, with clear attention to maintaining existing performance characteristics while adding the new functionality.
