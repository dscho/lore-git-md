Performance optimization patch introducing a new `bloom_keyvec` abstraction for pathspec bloom filters. This is part 3/4 of a series addressing performance issues with combined pathspec queries.

The patch replaces the direct `bloom_key *` usage in `rev_info` with a new `struct bloom_keyvec` that can store multiple bloom keys per pathspec item. While currently limited to single pathspec optimization (maintaining backward compatibility), the new structure paves the way for future multi-pathspec optimizations. Key changes include:

1. New `bloom_keyvec` struct and related API functions (`bloom_keyvec_new`, `bloom_keyvec_free`, `bloom_keyvec_fill_key`)
2. Updated bloom filter checking logic with new `bloom_filter_contains_vec()`
3. Conversion of revision.c to use the new keyvec API while preserving existing behavior

The implementation appears clean and well-contained, touching bloom.c/h and revision.c/h with straightforward test updates. This continues the series' trend of careful API design while addressing previous reviewer feedback about naming consistency and test organization. The patch maintains the single-pathspec fast path while setting up infrastructure for future optimizations.
