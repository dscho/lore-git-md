Platform compatibility fix for FreeBSD build issues with sysinfo library.

This patch addresses a build failure on FreeBSD systems that occurs when the optional sysinfo compatibility library is installed. The issue stems from recent changes that added sysinfo() checks to the build system (commits 50dec7c566 and 187ce0222f). The FreeBSD sysinfo library causes linking failures because it requires `-lsysinfo` but the build system doesn't include it.

Ramsay Jones evaluates three potential solutions and opts for the cleanest approach: prioritizing the BSD sysctl() detection over sysinfo() when on BSD systems. This avoids unnecessary library linking (since sysinfo is likely just a sysctl wrapper on BSD anyway) and only requires changes to the autoconf and meson build configurations. The Makefile build already handles this correctly.

The patch moves the sysinfo check after BSD sysctl detection in both configure.ac and meson.build, and only enables HAVE_SYSINFO if HAVE_BSD_SYSCTL isn't set. This maintains existing behavior on non-BSD systems while fixing the FreeBSD build. The change has been tested by Renato Botelho on FreeBSD.

This appears to be a well-considered solution to a specific platform compatibility issue, with clear analysis of the alternatives and minimal impact on other systems. The change is focused and unlikely to introduce new problems elsewhere.
