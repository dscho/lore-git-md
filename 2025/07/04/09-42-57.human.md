This is the second patch in Patrick Steinhardt's v3 series to make reftable the default ref storage backend in Git 3.0. While the first patch established the technical foundation, this one focuses on expanding real-world testing by automatically enabling reftable format when `feature.experimental` is turned on.

The patch adds a new configuration option that makes `git init` use reftable format when experimental features are enabled, unless overridden by explicit `init.defaultRefFormat` or `GIT_DEFAULT_REF_FORMAT` settings. This provides a gradual rollout path - early adopters who opt into experimental features will automatically test the new format, while others continue using the traditional files backend.

The implementation is straightforward, adding the new behavior to setup.c while maintaining all existing override mechanisms. Three new test cases verify the interaction between experimental flag, config settings, and environment variables. Documentation is updated to explain the new option alongside other experimental features.

This appears to be a well-considered incremental step in the reftable rollout strategy. The patch maintains backward compatibility while expanding testing coverage, and the test coverage is thorough. The approach follows Git's established patterns for experimental feature testing.
