This is a feature patch series (v3) from Patrick Steinhardt that moves Git toward making the reftable format the default reference storage backend. The series has two main parts: announcing the planned breaking change for Git 3.0, and enabling reftable as the default when experimental features are turned on.

The first patch updates the BreakingChanges document to explain the upcoming switch to reftable, highlighting benefits like better performance (especially for many refs), case-sensitivity handling, and space efficiency through compression. The change is framed as dependent on ecosystem support from tools like JGit and libgit2. The second patch makes reftable the default when `feature.experimental` is enabled, giving power users early access to help test the format before the full Git 3.0 rollout.

This version includes minor refinements from previous iterations, like improved commit messages and additional details about reftable's compression benefits. The approach remains focused and incremental - while there are opportunities to improve initialization code more broadly (like making REPOSITORY_FORMAT_INIT more consistent), those are explicitly deferred to keep this change manageable. The series appears well-considered, with thorough documentation and test coverage, though wider ecosystem adoption remains a prerequisite for the full rollout.
