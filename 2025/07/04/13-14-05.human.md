This is a review ack for Patrick Steinhardt's v3 patch series to make reftable the default ref storage backend in Git 3.0. Karthik Nayak confirms the changes look good as expected, signaling continued approval of the technical approach.

The series establishes reftable as the default when `feature.experimental` is enabled, serving as a transitional step before the full Git 3.0 rollout. Version 3 includes minor refinements to commit messages and documentation, adding compression benefits to the listed advantages of reftable over the traditional files backend.

The review maintains the technical consensus from previous rounds, with no new concerns raised about the implementation strategy that combines build-time guards (`WITH_BREAKING_CHANGES`) with runtime opt-in via experimental flag. The thread shows steady progress toward the goal, with ecosystem coordination (JGit/libgit2/Gitoxide support) noted as the remaining consideration rather than any technical blockers.
