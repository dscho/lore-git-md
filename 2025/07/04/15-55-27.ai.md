This is a naming discussion in the ongoing `git for-each-ref` pagination feature thread. Andreas Schwab responds to Karthik Nayak's clarification about the seeking behavior, arguing that the current `--skip-until` name is misleading because the operation is not pattern matching but rather positional seeking in a sorted list.

The key points in this email are:
1. Andreas maintains that `--start-with` better describes the actual behavior of dividing the sorted ref list at a position where the given name would appear, rather than matching patterns
2. He emphasizes this is fundamentally a sorting/positioning operation, not a set operation
3. The argument builds on Karthik's earlier explanation that the feature seeks to insertion points (where a ref would be if it existed) rather than doing exact matches

This continues the naming debate that has seen multiple proposals (`--skip-to`, `--start-after`, `--seek`, etc.), with Andreas advocating for `--start-with` as the clearest option given the actual implementation behavior. The technical implementation itself is not in question - the discussion remains focused on finding the most accurate name for the positional seeking functionality.
