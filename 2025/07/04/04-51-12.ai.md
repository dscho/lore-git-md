This is a discussion about backward compatibility concerns regarding the proposed ban on forward slashes in remote names. Junio Hamano responds to Per Cederqvist's bug report about refname ambiguity when remote names contain slashes.

Hamano acknowledges the potential confusion but notes the problem only arises when mixing single-level (e.g. "origin") and multi-level (e.g. "origin/chat") remote names in the same repository. He points out that consistently using two-level naming would avoid ambiguity entirely. The key concern raised is that retroactively banning slashes would break existing repositories, which is particularly significant given Git's large user base.

The response suggests this isn't a simple fix - while the ambiguity is real, the solution needs to consider real-world usage patterns and backward compatibility. This moves the discussion toward weighing the tradeoffs between preventing future confusion and maintaining compatibility with existing setups. The thread appears to be shifting from technical problem identification to solution design considerations.
