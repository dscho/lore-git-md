This is a bugfix patch that resolves a regression in `git log --diff-filter` behavior. The patch addresses an issue where lowercase exclusion filters (like `d" to exclude deletions) weren't working with default output formats, causing Git to incorrectly show no commits at all.

The problem stemmed from a 2022 change that split negative filter bits into a separate `filter_not` field without updating the revision walk setup code. Jeff King's solution is straightforward - modify `setup_revisions()` to check both `filter` and `filter_not` fields when determining if diffs are needed. The fix is minimal (just one line in `revision.c`) but effectively restores the expected behavior where exclusion filters work regardless of output format.

The patch includes a new test case in `t/t4202-log.sh` that verifies the corrected behavior. Karthik Nayak has reviewed and approved the fix, noting it addresses the issue cleanly while maintaining the original design intent.
