This is a naming discussion for the `git for-each-ref` pagination feature, now in its third iteration. Junio C Hamano weighs in on the ongoing debate about what to call the new `--skip-until` option (currently implemented in patch 4 of the series). He highlights a key semantic point: the option should clearly indicate that the specified reference point itself won't appear in the output, even if it exists in the ref list.

Hamano provides concrete examples showing why names like `--start-at` or `--start-from` could mislead users into thinking the specified ref would be included. He suggests the option name should explicitly convey the "skip everything before and including this ref" behavior that pagination use cases actually need. This reinforces Andreas Schwab's earlier argument for `--start-with` as a better descriptor, though Hamano doesn't explicitly endorse any particular alternative here.

The technical implementation (with its O(log N) performance across all ref backends) remains settled - this discussion purely concerns UX clarity in the command-line interface. The thread shows maintainers carefully considering how the option name will guide user expectations about the seeking behavior's exact semantics.
