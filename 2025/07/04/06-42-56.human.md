Follow-up in thread about remote naming ambiguity with slashes. Per Cederqvist responds to Junio Hamano's concerns about backward compatibility, suggesting several incremental approaches to address the issue without breaking existing setups. The proposals include: making slash-containing names opt-in via config setting, enforcing consistent slash levels across all remotes in a repo, or a deprecation path with eventual removal. Cederqvist notes that while the problem exists, immediate breaking changes would be too harsh, and estimates that few users actually use slashes in remote names today. The discussion continues to explore ways to prevent future ambiguity while preserving compatibility.
