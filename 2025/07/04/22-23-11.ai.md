Platform compatibility fix for FreeBSD build system interaction.

This patch addresses a build failure on FreeBSD systems where an optional sysinfo compatibility library is installed. The issue stems from recent changes that added sysinfo() detection to the build system (commits 50dec7c566 and 187ce0222f), which conflicts with FreeBSD's preferred sysctl() approach for system information queries.

The solution prioritizes BSD's native sysctl() over the sysinfo compatibility layer by:
1. Moving the sysinfo() check after HAVE_BSD_SYSCTL detection in configure.ac
2. Only enabling HAVE_SYSINFO if HAVE_BSD_SYSCTL is not set
3. Applying the same logic to meson.build

The patch considers and rejects alternative approaches like adding explicit linking checks or reordering conditionals in the code, opting instead for the most maintainable solution that respects FreeBSD's conventions. The change is tested and verified by a FreeBSD user (Renato Botelho).

Key technical details:
- Affects configure.ac and meson.build
- Introduces conditional logic around HAVE_SYSINFO definition
- Preserves existing behavior on non-BSD systems
- Maintains compatibility with both autoconf and meson builds

The fix is straightforward and unlikely to be controversial, as it resolves a clear platform-specific build issue while maintaining the intended functionality across all systems. The patch demonstrates good attention to cross-platform compatibility concerns in the build system.
