Platform compatibility fix for FreeBSD build system interaction. This email confirms the solution to a FreeBSD build issue where recent sysinfo() detection changes conflicted with FreeBSD's preferred sysctl() approach. Eric Sunshine reviews Ramsay Jones's patch that reorders build system checks to prioritize BSD's native sysctl() over sysinfo compatibility, noting it's a simple and effective solution.

The patch modifies both configure.ac and meson.build to only enable HAVE_SYSINFO if HAVE_BSD_SYSCTL is not set, which Eric agrees is likely sufficient despite a theoretical edge case where both might be defined. The change has already been tested and verified working on FreeBSD by Renato Botelho.

This appears to be a straightforward, uncontroversial fix that preserves existing behavior on non-BSD systems while resolving the platform-specific build issue. The commit message is clear and well-explained, making the technical tradeoffs understandable even to those who didn't follow the full discussion. No further action seems needed beyond applying the patch.
