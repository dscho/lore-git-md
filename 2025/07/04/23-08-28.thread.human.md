This thread addresses a resource leak in Git's SSH signing functionality. The issue occurs when signing commits or tags with SSH keys - temporary key files weren't being properly cleaned up due to how filenames were handled in the tempfile management code.

The fix, proposed in a single-line patch, changes how the temporary key filename is copied in `gpg-interface.c`, switching from `strbuf_detach()` to `xstrdup()`. The original implementation inadvertently prevented proper cleanup mechanism from working, causing temporary SSH key files to accumulate rather than being removed after use.

The change is small but important, fixing a real resource management issue in the SSH signing path (`sign_buffer_ssh()`). While the impact isn't severe (the leak only occurs during signing operations), it's still a hygiene issue worth fixing. The patch maintains all existing functionality while ensuring proper cleanup of temporary files.
