This thread addressed a memory leak in Git's SSH signing subsystem, specifically in how temporary key files were handled during commit signing operations. The original issue was a leak in `sign_buffer_ssh()` where `strbuf_detach()` was incorrectly used for the temporary key file path. The fix replaces this with `xstrdup()` to properly manage memory.

Through three iterations, the patch incorporated feedback from multiple reviewers. Patrick Steinhardt suggested using subshell isolation with exported TMPDIR to prevent environment variable leakage between tests, while Phillip Wood recommended merging the test case with existing SSH-agent tests and using `test_must_be_empty` for verification. The final version implements all these improvements while maintaining symmetry between key handling paths.

Junio C Hamano has reviewed the v3 patch and confirmed it looks good to merge, marking the technical solution as complete. The changes modify `gpg-interface.c` and update the test file `t/t7528-signed-commit-ssh.sh`. A separate discussion about policy documentation updates regarding contributor identity continues independently, but this memory management fix is now ready for integration.
