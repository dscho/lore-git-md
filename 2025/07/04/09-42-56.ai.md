This is the first patch in Patrick Steinhardt's v3 series to make reftable the default ref storage backend in Git 3.0, focused on documentation and infrastructure setup. The patch adds comprehensive documentation of reftable's advantages over the files backend in BreakingChanges.adoc, including new details about prefix compression benefits. It establishes the technical foundation by defining REF_STORAGE_FORMAT_DEFAULT as reftable when WITH_BREAKING_CHANGES is set, while maintaining files as the default for compatibility. The change is exposed in `git version --build-options` output and tested via t0001-init.sh.

Key technical elements include the conditional compilation guard (WITH_BREAKING_CHANGES) protecting the default change, the new ref format reporting in help.c, and the setup.c logic that respects both explicit config and the new default. The documentation now lists seven specific advantages of reftable: case-sensitivity handling, Unicode support, efficient deletion via tombstones, geometric compaction, atomic multi-ref writes, performance gains, and space savings from prefix compression.

The patch maintains the series' ecosystem readiness requirement, explicitly calling out JGit/libgit2/Gitoxide support as a prerequisite. Test coverage verifies the default format behavior matches the build-time setting. This builds on the SHA-256 versioned defaults pattern while keeping REPOSITORY_FORMAT_INIT unification as future work. The implementation appears thorough, with clear documentation and testing of the versioned default transition mechanism.
