Performance optimization series for bloom filters in revision traversal, addressing multiple pathspec handling. This v4 iteration focuses on API naming consistency and test helper reorganization while maintaining the core functionality from previous versions.

The series introduces a new test helper for murmur3 hash calculation (patch 1) to clean up the public API by moving test-specific functionality out of bloom.h. This addresses Junio Hamano's concern about API naming inconsistencies. Patch 2 renames bloom key functions to follow Git's subsystem naming pattern (`bloom_key_*` prefix). Patch 3 replaces direct `bloom_key*` usage with the new `bloom_keyvec` structure for managing multiple pathspec keys. Patch 4 implements the actual optimization for multiple pathspec traversal while preserving the single-pathspec fast path.

Key technical changes include comprehensive pathspec magic bit checking, per-pathspec bloom key initialization, and updates to the bloom filter checking logic. The implementation now properly handles all pathspec types (FROMTOP, MAXDEPTH, LITERAL, GLOB, ICASE, EXCLUDE, ATTR) while deferring case sensitivity optimizations for future work. The series touches bloom.c/h, revision.c/h, and updates tests in t4216-log-bloom.sh, with test coverage expanded to verify the new multiple-pathspexec behavior.

The v4 changes specifically address review feedback by:
1. Renaming functions to follow Git's subsystem naming conventions
2. Moving test-specific murmur3 functionality into a helper
3. Fixing parameter alignment issues
4. Documenting the new bloom_keyvec structure
5. Maintaining the single-pathspec optimization path

Open questions from previous rounds about case sensitivity handling (PATHSPEC_ICASE) and nowildcard_len optimizations remain deferred to future work, as the core functionality is now considered stable after multiple review iterations with Junio Hamano and Patrick Steinhardt.
