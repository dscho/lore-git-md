This is a bugfix patch addressing a resource leak in the SSH signing code. The issue occurs when signing commits/tags with SSH keys, where temporary key files weren't being properly cleaned up due to how the filename string was being handled.

The patch changes how the temporary key filename is copied in `gpg-interface.c`, switching from `strbuf_detach()` to `xstrdup()`. The original implementation detached the filename from the tempfile structure, which prevented `delete_tempfile()` from working correctly. This meant temporary SSH key files would accumulate rather than being removed after use.

The fix is straightforward - just one line changed - but addresses a real resource management issue. The commit message clearly explains the problem and solution, though it might benefit from mentioning the impact (how often this occurs in practice) or any observable symptoms users might notice from the leak. The change appears correct and maintains the same functionality while fixing the cleanup path.

Key technical details for future reference: the bug was in the SSH signing path (`sign_buffer_ssh()`), specifically around handling of `key_file->filename`, and involved interaction with the tempfile API's cleanup mechanisms. The fix preserves all existing behavior while ensuring proper resource management.
