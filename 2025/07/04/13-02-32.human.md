Feature addition to `git for-each-ref` for efficient pagination. This is the final patch in a 4-part series introducing a `--skip-until` option that enables O(log N) seeking in reference iteration across all ref backends (files, packed, reftable).

The patch adds the user-facing `--skip-until=<ref>` option to `git for-each-ref`, building on the ref iterator seek functionality introduced in earlier patches. When provided, iteration starts from the first reference matching or following the given pattern, enabling efficient pagination workflows like:

```
git for-each-ref --count=100
git for-each-ref --count=100 --skip-until=refs/heads/branch-100
```

The implementation:
- Adds validation to prevent incompatible combinations (custom sorting or pattern matching with `--skip-until`)
- Handles edge cases like partial matches, directory prefixes, and non-existent markers
- Includes extensive test coverage verifying behavior across different ref types and edge conditions

The series has undergone thorough review, with v3 addressing interface clarity through explicit flags. This final patch completes the user-facing functionality while maintaining the architectural decisions validated earlier - sorted reference seeking for performance, clear documentation of race condition limitations, and consistent behavior across ref backends.
