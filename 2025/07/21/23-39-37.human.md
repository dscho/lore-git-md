This is a bugfix patch addressing a memory leak in the reflog expiration code. The leak occurs when `find_cfg_ent()` allocates a `reflog_expire_entry_option` struct during reflog configuration parsing, but these allocations are never freed. The leak affects both `cmd_reflog_expire` and the reflog expiration part of garbage collection.

The patch introduces a new reflog_clear_expire_config()` function to properly clean up these allocations, calling it at appropriate exit points in both the reflog command and GC code. This is the third version of the patch, with previous iterations having been reviewed and improved - notably removing an incorrect cleanup call and adding proper cleanup in `reflog_expire_condition()`.

The fix is straightforward and well-justified, with clear ASAN output showing the leak. The patch appears technically sound, touching only the necessary files to add the cleanup logic while maintaining the existing behavior. This is the kind of small but important fix that should be uncontroversial to merge.
