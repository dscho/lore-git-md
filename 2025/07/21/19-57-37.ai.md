This is a documentation bug report pointing out a contradiction in `git help rebase` output. Rodney Bates identifies that while the textual description states that `git rebase master topic` would modify the `master` branch (by resetting to it and reapplying commits), the accompanying example diagram shows the opposite behavior - with `topic` being modified while `master` remains unchanged.

The issue lies in the mismatch between the command's described behavior and its illustrated behavior in the same help text. The email doesn't propose a fix but clearly demonstrates the inconsistency by quoting and annotating the relevant sections from the manual page. This appears to be a genuine documentation error that could confuse users about which branch gets modified during a rebase operation.

Key technical details:
- The contradiction appears in the SYNOPSIS and EXAMPLES sections of `git help rebase`
- The command in question is `git rebase master topic` (upstream=master, branch=topic)
- Text claims current branch becomes master and gets modified
- Diagram shows topic branch being rewritten while master stays unchanged
- No proposed solution, just clear demonstration of the inconsistency

This would be relevant to anyone working on Git documentation or teaching Git concepts, as the rebase command is fundamental yet often confusing to users. The bug report is well-structured and clearly demonstrates the problem without editorializing.
