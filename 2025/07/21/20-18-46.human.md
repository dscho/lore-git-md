This is the final patch in a 5-part series extending the promisor-remote protocol to support configurable validation of remote attributes. The patch focuses on code hygiene by introducing string constants for the mandatory "name" and "url" fields, completing the standardization effort for all promisor-remote fields.

The change replaces hardcoded string literals with `promisor_field_name` and `promisor_field_url` constants, matching the approach already taken for optional fields like `partialCloneFilter` and `token`. This makes the code more maintainable and consistent, though it doesn't change any behavior. The patch has already been reviewed and approved by multiple contributors, with Junio Hamano calling it a "nice" cleanup.

The series as a whole is now technically complete, with all implementation work done, tests passing, and documentation polished. The only remaining discussion point is whether to rename the configuration options from `promisor.sendFields`/`checkFields` to use "configuration variable" terminology instead of "field" terminology - a debate that doesn't affect this particular patch's changes.
