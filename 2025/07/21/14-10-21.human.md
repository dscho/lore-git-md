This is the third patch in a v6 series extending the promisor-remote protocol to support configurable validation of remote attributes. The series is in its final documentation refinement phase before potential merge.

The patch refactors how advertised promisor-remote fields are parsed from the server, introducing a new `parse_one_advertised_remote()` function that populates a `struct promisor_info` with the parsed name and URL. This prepares for future addition of more fields (like filter and token) in subsequent commits. The changes include:

1. Moving field parsing into a dedicated function for better modularity
2. Passing the complete `promisor_info` struct to `should_accept_remote()` rather than individual fields
3. Adding proper cleanup via `promisor_info_free()`

The refactoring maintains all existing functionality while making the code more maintainable for the planned extensions. The changes are well-contained to promisor-remote.c and follow the type-safety improvements established earlier in the series. With the series already having addressed all reviewer feedback and passing CI tests, this patch appears ready for inclusion as part of the final polished series.
