This is a documentation patch refining a NEEDSWORK comment in `builtin/rev-list.c` as part of an ongoing refactoring effort to move `struct rev_list_info`. The patch comes from Junio Hamano and represents the final tweak in a thread that previously discussed both the struct relocation and the phrasing of this comment.

The comment warns about broken option parsing logic in rev-list that fails to properly handle arguments for options. The new version is more explicit about the core issue: the loop can't distinguish between option names and their arguments, leading to incorrect behavior with chained options like `--grep --exclude-promisor-objects`. The comment maintains the call for a better mechanism in `setup_revisions()` to validate option sets per command.

This appears to be the conclusion of a minor debate about comment phrasing, where Jeff King had initially questioned whether the original "broken options" wording was more accurate than Junio's edit. The final version strikes a balance, clearly blaming the parsing logic rather than the options themselves while keeping the technical warning intact. The change is purely documentation - no functional impact - and comes with Junio's sign-off, suggesting it's ready to be applied.
