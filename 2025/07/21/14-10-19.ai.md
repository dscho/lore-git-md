This is the first patch in a 5-part series extending the promisor-remote protocol to support configurable validation of remote attributes. The patch performs a refactoring to prepare for handling additional remote fields beyond just name and URL.

The key change replaces the existing `struct strvec` approach (which used separate vectors for names and URLs) with a new `struct promisor_info` that encapsulates all information about a promisor remote. Each instance contains explicit `name` and `url` members, stored in a `string_list` where the item's string is the name and util pointer points to the full info struct. This provides better type safety and clearer field documentation while making it easier to add new fields in future patches.

The implementation includes:
- New `struct promisor_info` definition with name/url members
- `promisor_config_info_list()` to populate the list from config
- `promisor_info_list_clear()` cleanup helper
- Updated `promisor_remote_info()` and `should_accept_remote()` to use the new structure
- Removal of the now-unused `remote_nick_find()` helper

The changes maintain all existing functionality while providing a more extensible foundation. The commit message clearly explains the motivation (preparing for additional fields) and design choices (explicit struct members for type safety). This appears to be a well-considered refactoring that cleanly separates the mechanical changes from the functional additions coming in later patches.
