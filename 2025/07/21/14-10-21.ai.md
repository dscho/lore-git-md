This is a refactoring patch in the promisor-remote protocol extension effort, specifically part 3 of a 5-part series that's now in its 6th iteration. The patch focuses on restructuring how advertised remote information is parsed from the server-side "promisor-remote" capability.

The key changes introduce a new `parse_one_advertised_remote()` function that centralizes parsing of remote attributes (currently name and URL) into a `struct promisor_info`. This replaces the previous ad-hoc parsing scattered through the code. The patch also modifies `should_accept_remote()` to take the full `promisor_info` struct rather than individual name/URL strings, and adds a `promisor_info_free()` helper for consistent cleanup.

These changes serve as preparation for upcoming patches that will parse additional fields (filter and token) from the server advertisement. The refactoring improves code organization by:
1) Consolidating field parsing logic in one place
2) Making the data flow more explicit via the structured `promisor_info`
3) Simplifying memory management with the new free function

The patch maintains all existing functionality while making the code more maintainable for the planned extensions. It's a clean, focused refactoring that follows the series' established patterns and has already passed CI testing. The changes align with the overall goal of making promisor remote attributes more configurable while preserving backward compatibility.
