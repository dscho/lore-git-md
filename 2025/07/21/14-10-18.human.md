This is the final version (v6) of a 5-patch series enhancing the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now in its final documentation refinement phase before merging.

The core change allows servers to advertise additional fields (currently just `partialCloneFilter` and `token`) alongside the existing name/URL information, and lets clients verify these fields match their local configuration before accepting promisor remotes. This provides better control over remote validation while maintaining backward compatibility.

Key improvements in v6 include:
- Removal of a redundant NULL check in the validation logic
- Documentation refinements (standardized formatting, reduced "will" usage, clearer field/field-name terminology)
- Protocol specification tightening (BNF syntax improvements, field ordering rules)
- Confirmed passing CI tests

The series is part of Git's "Large Object Promisors" (LOP) effort and builds on existing promisor-remote infrastructure. All reviewer feedback has been addressed, with final documentation polish being coordinated between Christian Couder and Jean-Noël Avila. The implementation appears solid with thorough test coverage and careful attention to protocol design details.
