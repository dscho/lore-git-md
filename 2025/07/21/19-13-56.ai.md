This is a naming critique of the IMAP folder archiving feature for `git send-email`. Junio C Hamano raises concerns about the current naming scheme (`sendemail.imapfolder` and `--imap-folder`) being too generic for its specific purpose of archiving sent messages. He suggests more specific terms like "sent" or "fcc" (for "file carbon copy") would better reflect the feature's current use case while leaving room for future IMAP-related enhancements to `send-email`.

The feedback focuses entirely on naming semantics rather than technical implementation, noting the current names could constrain future development if other IMAP integrations are added. Hamano explicitly states he has no objections to the feature itself and found no implementation flaws, positioning this as a pre-merge naming polish request rather than a blocking concern.

- The feature currently pipes sent messages to `git imap-send` for storage
- Implementation spans `git-send-email.perl` and `imap-send.c`
- Special header handling preserves Bcc" and other metadata
- Configuration uses `sendemail.imapfolder` with CLI `--imap-folder` alias
