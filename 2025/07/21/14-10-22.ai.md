This is the 4/5 patch in a series extending promisor-remote protocol support, implementing client-side validation of advertised remote fields. The patch introduces a `promisor.checkFields` configuration that lets clients verify server-advertised fields (currently `partialCloneFilter` and `token`) against local configuration before accepting a promisor remote.

The implementation adds a new `fields_checked()` function mirroring the existing `fields_sent()` from patch 2, plus validation logic in `should_accept_remote()` that enforces three conditions for each checked field: local config must be set, server must advertise the field, and values must match exactly. Field names are compared case-insensitively while values are case-sensitive. The validation integrates with existing `promisor.acceptFromServer` policies and only activates when not set to "None".

Key technical changes include:
- New `match_field_against_config()` helper for field-specific comparisons
- `all_fields_match()` function implementing the three validation conditions
- Modified `should_accept_remote()` to incorporate field checks while maintaining existing name/URL validation
- Lazy loading of config info only when needed
- Comprehensive test case verifying filter validation behavior

The documentation update precisely specifies the validation semantics and interaction with other promisor-remote configurations. The test demonstrates successful rejection of mismatched filter specifications while maintaining the expected promisor remote acceptance flow.

This completes the client-side counterpart to the server field advertisement added in patch 2, providing end-to-end validation capability for the series' core functionality.
