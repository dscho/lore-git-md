This is part 2 of a 5-patch series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is currently in its final documentation refinement phase before merging.

The patch enables servers to advertise additional fields about promisor remotes beyond just name and URL. It introduces a new `promisor.sendFields` config variable that lets servers specify which additional fields to send (currently supporting "partialCloneFilter" and "token"). The fields are looked up in the remote's config and included in the protocol capability.

Key aspects:
- Maintains backward compatibility while adding extensibility
- Documents the protocol changes thoroughly in both config and protocol-v2 docs
- Includes comprehensive tests verifying field transmission
- Follows Git's security practices by urlencoding values and validating fields
- The implementation is clean and well-tested, with clear separation between mandatory and optional fields
- Documentation improvements standardize terminology and formatting
- Builds on existing promisor-remote infrastructure while enabling future extensions

This is a mature patch that has gone through multiple review iterations, with all feedback addressed. It solves a real need for more granular promisor remote validation while maintaining protocol stability. The changes are well-considered and ready for inclusion.
