This is a documentation clarification regarding `git rebase` behavior. Nico Williams responds to Rodney Bates' report about an apparent contradiction in the `git help rebase` output, arguing that there is no actual contradiction - just a misunderstanding of terminology.

Nico explains that when the documentation states "the current branch is reset to <upstream>", it means the branch pointer is moved to match the upstream commit (a standard Git "reset" operation), not that the working branch is being changed to the upstream branch. This maintains the correct behavior where the topic branch gets rewritten while master remains unchanged, as shown in the diagram.

The response highlights how the technical term "reset" can be confusing to users who might interpret it more literally. While this doesn't propose any documentation changes, it clarifies that the existing documentation is technically accurate if read with proper understanding of Git terminology. The exchange suggests the documentation might benefit from either rephrasing to avoid "reset" or adding a brief explanation of what "reset" means in this context.
