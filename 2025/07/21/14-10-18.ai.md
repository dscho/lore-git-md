This is the cover letter for v6 of a 5-patch series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is in its final documentation refinement phase before potential merge.

The core change allows servers to advertise additional remote fields (currently just `partialCloneFilter` and `token`) via a new `promisor.sendFields` config, while clients can validate these against their local config using `promisor.checkFields`. This enables more informed client decisions about which promisor remotes to accept while maintaining backward compatibility.

Key technical aspects include:
- Replacement of `struct strvec` with `struct promisor_info` and `struct string_list`
- Strict BNF protocol definitions for field handling
- Mandatory name/url field ordering
- Validation rules (unique field names per remote)
- Documentation standardization (description-list format, backtick consistency)

The v6 changes focus on documentation polish:
- Removed redundant NULL check in patch 1 per Junio's feedback
- Clarified terminology around "field names" vs "fields"
- Tightened BNF syntax and validation rules
- Standardized placeholder syntax (`<field-name>`)
- Reduced "will" usage for clarity
- Adjusted protocol documentation underlines to match headings

CI tests are passing, and all major reviewer feedback has been addressed. The series is part of Git's "Large Object Promisors" (LOP) effort and aligns with broader protocol-v2 patterns. Documentation refinements match ongoing project-wide man page standardization.
