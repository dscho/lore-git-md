This is the second patch in a 5->v6 revision of a series extending the promisor-remote protocol to support configurable validation of remote attributes. The patch implements server-side advertisement of additional remote fields beyond just name/url, specifically `partialCloneFilter` and `token`, controlled by a new `promisor.sendFields` config.

Key technical changes:
- Introduces `known_fields` array defining allowed field names (`partialCloneFilter` and `token`)
- Adds `fields_sent()` to parse `promisor.sendFields` config into a string list
- Extends `struct promisor_info` to store filter/token values
- Modifies `promisor_config_info_list()` to populate these fields from remote configs
- Updates protocol documentation with precise BNF and field semantics
- Adds comprehensive test case verifying field transmission

The implementation maintains strict compatibility while allowing servers to advertise filter specs and auth tokens that clients can later use for validation (handled in subsequent patches). Documentation carefully distinguishes between "field names" (config keys) and "fields" (name/value pairs in protocol).

This version incorporates all prior feedback with polished documentation formatting and backtick consistency. The changes are well-contained to promisor-remote.c and its tests, with thorough coverage of the new functionality.
