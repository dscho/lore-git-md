This is the 4th patch in a v6 series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is in its final documentation refinement phase before merging.

The patch introduces client-side validation of additional promisor remote fields (currently "partialCloneFilter" and "token") through a new `promisor.checkFields` config variable. When set, the client will verify that any advertised fields match its local configuration before accepting the remote. This provides security and consistency guarantees - for example ensuring authentication tokens match expected values or that partial clone filters align between client and server.

The implementation adds:
- Configuration parsing for `promisor.checkFields`
- Field matching logic that verifies both presence and exact value equality
- Integration with the remote acceptance logic
- Comprehensive tests demonstrating the validation behavior

The patch builds on the refactoring and server-side advertisement capabilities added in earlier patches of the series. It maintains backward compatibility while adding the new validation layer. Documentation clearly explains the validation rules and interaction with existing `promisor.acceptFromServer` settings.
