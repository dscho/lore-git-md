Performance investigation in the xdiff Rust optimization thread.

Phillip Wood presents benchmark results comparing the performance impact of hash algorithm changes versus language implementation (Rust vs C) in the xdiff optimization series. His two experimental patches (available in the xdiff-hashing-experiments branch) isolate the performance factors:

1. The first patch refactors `xdl_hash_record()` to inline the whitespace flag check, allowing the compiler to hoist it out of the loop in `xdl_prepare_ctx()`. This yields an 8% speedup in `git log --oneline --shortstat` benchmarks.

2. The second patch replaces Git's existing hash function with XXH3_64bits from libxxhash, showing a further 6% improvement. Notably, this matches the performance of the Rust implementation in the main series, suggesting the hash algorithm change accounts for most of the Rust version's gains.

Wood's measurements show the combined changes provide a 15% speedup, with roughly half coming from the whitespace optimization and half from the hash function change. He notes the Rust implementation appears to be a direct port of the C xxhash code using SIMD intrinsics, and raises an open question about performance on platforms without optimized implementations.

The email includes detailed benchmark results and cleanly separated patches with performance measurements for each change. This provides concrete data to inform the ongoing discussion about whether the performance gains justify adding Rust as a hard dependency, particularly since similar gains appear achievable through C optimizations. The analysis helps address Junio Hamano's earlier question about separating hash algorithm effects from language implementation effects.
