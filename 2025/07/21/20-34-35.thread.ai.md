Bug report for Git for Windows (not upstream Git) regarding file permission issues on Windows 11 Pro (10.0.22631). James Gao reports that Git 2.50.1 fails basic operations (git init, git add, git pull) with "Permission denied" errors when writing to .git/objects and index files, even as Administrator. The issue affects repository metadata and working tree files, persists across operations, and occurs on a fresh system with latest Git for Windows x64 build. No known workarounds; reporter considering downgrade.

Brian m. carlson responds, unable to reproduce on Linux, suggesting Windows-specific factors. Provides troubleshooting steps: checking CIFS/SMB shares, avoiding special folders (Documents, OneDrive), using regular NTFS disks. Directs to Git for Windows issue tracker with specific diagnostic needs (storage location, filesystem type). Maintains this is likely environment-specific rather than universal regression, contrasting with reporter's complete breakdown. Notes known Windows system folder handling peculiarities and sync service incompatibilities.

Johannes Schindelin (Git for Windows maintainer) follows up, probing questions about the full error message, how clone succeeded despite errors, and whether repository is on network drive. Suggests trying latest snapshot build before downgrading and links to possible duplicate GitHub issue. Schindelin takes active diagnostic role while questioning whether permissions error is the true root cause. The thread remains focused on Windows-specific troubleshooting with no upstream Git implications identified yet. Key open questions: exact error context, filesystem details, and whether issue reproduces in latest snapshot build.
