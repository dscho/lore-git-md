This thread began with Rodney Bates reporting a documentation inconsistency in `git rebase`'s man page. The help text for `git rebase master topic` appeared to contradict itself: while the diagram correctly showed the topic branch being rewritten, the accompanying text suggested the master branch would be modified. 

Nico Williams clarified that the confusion stems from Git's specific use of the term "reset" - it refers to moving the branch pointer (changing history) rather than switching the working tree. This means the current documentation is technically accurate, if read with precise Git terminology in mind. The example's behavior is correct (topic branch gets rewritten while master stays unchanged), though the wording could potentially be clearer for newcomers.

The discussion highlights how Git's specialized terminology can create confusion, particularly around fundamental operations like rebase. While no documentation changes have been proposed yet, the thread remains open for further discussion about whether the text should be made more explicit about this behavior to prevent similar misunderstandings.
