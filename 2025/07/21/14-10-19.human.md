This is the first patch in a 5-part series extending the promisor-remote protocol to support configurable validation of remote attributes. The series is in its final refinement phase before merging.

The patch refactors the promisor-remote internals to replace `struct strvec` usage with a new `struct promisor_info` that stores remote name and URL as explicit fields. This prepares for future protocol extensions where more fields may need to be handled. The change improves type safety and makes the code more maintainable when adding new fields later.

Key changes include:
- Introducing `struct promisor_info` to store name/URL pairs
- Using a `string_list` to manage promisor remote instances
- Updating all related functions to use the new structure
- Adding proper cleanup with `promisor_info_list_clear()`

The patch has already gone through multiple rounds of review, with feedback incorporated. It's part of a well-tested series that's ready for merging, with all CI tests passing and documentation polished. The change is purely internal - no user-visible behavior is modified.
