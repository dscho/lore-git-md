This is a build system patch addressing a macOS-specific character encoding issue. It's part of an ongoing thread about unreliable ISO-2022-JP to UTF-8 conversion in macOS's built-in iconv implementation, which causes test failures in t3900.

René Scharfe's patch adds support for using Homebrew's libiconv as a workaround for the broken macOS system iconv. The change searches for Homebrew's libiconv in default locations (/opt/homebrew for Apple Silicon and /usr/local for Intel), with Apple Silicon taking precedence. It respects any existing ICONVDIR setting while adding a new HOMEBREW_ICONVDIR variable to make the Homebrew path discoverable.

The patch builds on previous discussion in the thread about package manager support on macOS, specifically implementing the agreed-upon approach for Homebrew while maintaining compatibility with other configurations. The changes are minimal but targeted - just 10 lines added across Makefile and config.mak.uname to handle the iconv path detection.

This appears to be a well-considered solution to a specific platform compatibility issue, following the thread's established direction. The patch maintains backward compatibility while adding the new Homebrew support cleanly. It's part of a larger effort to handle macOS's problematic iconv implementation, with this being the second patch in a two-part series.
