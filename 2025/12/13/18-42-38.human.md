This is a build system patch adding Homebrew support control to Git's Makefile, part of the ongoing macOS iconv conversion issue thread.

René Scharfe introduces a new `NO_HOMEBREW` flag that allows users to disable Homebrew library linking, similar to existing controls for MacPorts and Fink. The change helps packagers and others who want explicit control over dependencies. The patch restructures Homebrew path handling to use new variables (`HOMEBREW_PREFIX`, `HOMEBREW_GETTEXT_PREFIX`, `HOMEBREW_MSGFMT`) that can be overridden, while maintaining support for both Intel (/usr/local) and Apple Silicon (/opt/homebrew) Homebrew installations.

The change appears well-considered, building on previous discussion in the thread about macOS package manager paths. It follows the pattern established for other package managers while adding more flexible configuration. The implementation handles both architecture variants cleanly and preserves backward compatibility needed for the iconv workaround discussed earlier in the thread.

This is the first of two patches in a series addressing the broader macOS build system issues, with the cover letter likely providing more context about how these changes fit into the iconv conversion problem. The patch itself is focused and mechanical, touching only the Makefile infrastructure without changing any core functionality.
