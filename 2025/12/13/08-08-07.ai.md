Refactoring patch in the submodule gitdir path encoding series, updating `submodule--helper` to use the centralized path resolution function.

This is the first patch in a 10-part series implementing runtime configuration for submodule gitdir paths. It modifies `add_submodule()` in `builtin/submodule--helper.c` to use the existing `submodule_name_to_gitdir()` helper instead of hardcoding the path format. The change ensures consistent path handling across all submodule operations and fixes test failures that occurred with the new path encoding system.

Key technical details:
- Replaces direct path construction (`xstrfmt(".git/modules/%s", name)`) with the centralized helper
- Converts path storage from heap-allocated string to `strbuf` for better memory management
- Maintains identical error handling and user messaging flows
- Narrowed scope of `submod_gitdir_path` variable to where it's actually used
- Part of the larger effort to standardize submodule gitdir path handling through configuration
- Follows the architectural principle of centralizing path resolution logic
- Prepares for the new path encoding system while fixing immediate test failures
- No behavior change for existing repositories without the new extension enabled

The change is straightforward and aligns with the series' goal of consistent path handling. It demonstrates good practice by using existing infrastructure rather than duplicating path construction logic.
