This is a build system patch addressing the macOS iconv regression, part of the ongoing thread about character encoding issues on macOS. The patch specifically implements Homebrew-based workaround paths for the broken system iconv implementation.

The patch adds detection and configuration for Homebrew-installed libiconv as a workaround for macOS's broken ISO-2022-JP to UTF-8 conversion in t3900 tests (cases 17, 25, 38). It introduces a new `HOMEBREW_ICONVDIR` variable that automatically detects Homebrew's libiconv in standard locations (/opt/homebrew for Apple Silicon, /usr/local for Intel), with Apple Silicon taking precedence. The variable is then used to set `ICONVDIR` if not already defined by the user.

Key technical details include:
- The change maintains backward compatibility by only setting ICONVDIR if not already defined
- Detection uses simple directory existence checks for libiconv under Homebrew paths
- The patch builds on previous work establishing Homebrew`-specific variables in the build system
- Follows the established pattern of Homebrew path handling seen with other dependencies like gettext

This represents the concrete implementation of one of the three proposed solution paths (using Homebrew's libiconv) from the thread. The patch is narrowly focused on the build system changes needed to support this workaround, while the broader discussion continues about package manager support scope and other potential solutions. The implementation appears straightforward and aligns with the maintainer-endorsed direction from earlier in the thread.
