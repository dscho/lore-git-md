This is part 2 of a 3-patch documentation series improving the `git replay` man page, specifically on clarifying the `--contained` option's behavior. The patch updates both the documentation and corresponding help text in the implementation to use clearer language about what the option does.

The key change is replacing the vague "advance all branches contained in revision-range" phrasing with the more precise "update all branches that point at commits in <revision-range>". This follows discussion in the v1 review where contributors found the original wording unclear. The patch also adds an important clarification that `--contained` requires the `--onto` option to be specified, which was previously undocumented.

The changes affect:
- `Documentation/git-replay.adoc`: Adds new `--contained` section with the updated description and `--onto` requirement
- `builtin/replay.c`: Updates the help text to match the new documentation

The patch carries forward consensus from v1 review, with attribution to Phillip Wood and Junio Hamano for their input on the terminology change from "advance" to "update". This continues the series' goal of making `git replay` documentation more precise while maintaining consistency between docs and implementation. No functional changes are made to the command itself.
