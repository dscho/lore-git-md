Core infrastructure patch addressing macOS platform compatibility, specifically around iconv handling. This is a follow-up to René Scharfe's earlier workaround for macOS's broken ISO-2022 string handling in iconv, which proposed using Homebrew's iconv instead.

The new version adds a NO_HOMEBREW option, giving users/builders the choice to avoid Homebrew's iconv even on macOS systems where it's available. This responds to the original patch being queued for 'next' by requesting a delay until the new version can be considered.

The change appears straightforward - a build-time configuration option for the macOS workaround - but shows careful attention to giving users control over their build environment. The patch maintains the original purpose of working around macOS's problematic ISO-2022 handling while adding flexibility for those who prefer not to use Homebrew packages.
