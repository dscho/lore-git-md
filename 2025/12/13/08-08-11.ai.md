Feature patch implementing runtime configuration for the submodule path encoding extension. This is part 5/10 of the submodule gitdir path encoding series, adding the ability to enable the `extensions.submodulePathConfig` via global runtime configuration while maintaining local repository precedence.

The patch introduces a new `submodule_path_config_enabled` global variable that allows the extension to be turned on without requiring per-repository configuration. The implementation includes updates to `submodule--helper` and `submodule.c` to check both the repository flag and this new global variable when determining whether to enforce the new path configuration requirements. Documentation is updated to explain the runtime configuration option, and new tests verify both new repository creation and existing repository migration scenarios when the global config is enabled.

Key technical details include the new global variable declaration in `submodule.h`, the modified path resolution logic in `submodule_name_to_gitdir()`, and the config reading added to `module_add()`. The test cases demonstrate the expected behavior when toggling the global config, showing that new submodules get proper gitdir config entries while existing ones remain unmodified until explicitly migrated. This maintains the series' principle of requiring explicit configuration while providing a convenient way to opt-in across multiple repositories.

The change aligns with the series' architectural consensus by keeping the strict config requirements while adding flexibility in how the extension is enabled. It implements one of the suggested improvements from Patrick Steinhardt and Junio Hamano to support runtime configuration. The patch follows the established pattern of centralizing path resolution through `submodule_name_to_gitdir()` while extending its behavior to respect the new global setting.
