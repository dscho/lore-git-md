This is part of the ongoing submodule gitdir path encoding series, specifically implementing a migration command for the new path configuration system.

Patch 6/10 introduces a new `git submodule--helper migrate-gitdir-configs` command that automates the process of adding gitdir configurations for existing submodules when the `extensions.submodulePathConfig` extension is enabled. The command scans the `.git/modules/` directory and creates appropriate `submodule.<name>.gitdir` entries for each valid submodule, which is required for repositories using the new path encoding system.

The implementation includes safety checks to ensure the repository format version and extension are properly configured before proceeding. It also handles edge cases like dotfiles and non-submodule directories in the modules folder. The patch comes with thorough test coverage verifying the migration works as expected.

This addresses a practical usability concern raised earlier in the thread - manually configuring gitdir paths for each submodule would be tedious for repositories with many submodules. The command follows the series' architectural principle of requiring explicit configuration while making adoption easier. The implementation builds on the centralized path validation infrastructure added in earlier patches.
