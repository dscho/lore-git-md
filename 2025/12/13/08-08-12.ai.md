This is part 6/10 of the submodule gitdir path encoding series, implementing a migration command for the new `extensions.submodulePathConfig` system. The patch adds a `git submodule--helper migrate-gitdir-configs` command that automatically creates the required `submodule.<name>.gitdir` configurations for all existing submodules when enabling the extension.

The command enforces that both `core.repositoryformatversion=1` and `extensions.submodulePathConfig=true` are set before proceeding, then iterates through all submodules in `.git/modules/` to:
1. Skip any that already have gitdir configs
2. Validate paths via `create_default_gitdir_config()`
3. Add the standard `.git/modules/<name>` configuration for each

The implementation includes comprehensive tests verifying that:
- The command properly requires the extension to be enabled
- It correctly migrates legacy submodules
- It skips already-configured submodules
- The resulting configurations match expected paths

This addresses Junio Hamano's concern about impractical manual configuration by providing an atomic migration path, while maintaining the series' strict validation requirements. The command integrates with the centralized `submodule_name_to_gitdir()` validation system introduced earlier in the series.

Key technical details for future reference:
- New `module_migrate()` function in `builtin/submodule--helper.c`
- Uses `repo_config_set_gently()` for prerequisite checks
- Iterates `.git/modules/` directory with `opendir()/readdir()`
- Skips is_dot_or_dotdot() and non-git directories
- Calls `create_default_gitdir_config()` for validation
- Test cases in `t7425-submodule-gitdir-path-extension.sh`
- Documentation updates in `extensions.adoc`

The patch maintains the series' architectural principle that extension-enabled repositories must have complete submodule.gitdir configuration while providing a practical migration path. It represents the final piece of core infrastructure before the actual encoding functionality in later patches.
