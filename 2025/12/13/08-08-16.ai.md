This is the final patch in the v6 series implementing submodule gitdir path encoding, adding a hashed fallback path resolution strategy. The patch introduces a "last resort" mechanism that generates a hash of the submodule name when all other path resolution attempts (plain text, URL encoding, digit appending) fail to find a non-conflicting path.

The implementation adds hashing logic to `create_default_gitdir_config()` using Git's standard hash object format (blob header + content). When triggered, it produces a hex-encoded hash path under `.git/modules/`. The accompanying test case demonstrates this by forcing the hashing path through a series of 20+ conflicting submodule names (including case variants and URL-encoded versions) before adding "Foo" which must use the hashed path.

Key technical details for future reference:
- Uses `the_hash_algo` infrastructure for consistent hashing
- Follows Git object format (blob header with size + NUL + content)
- Maintains the existing validation flow through `validate_and_set_submodule_gitdir()`
- Comprehensive test coverage in t7425 with explicit hash verification
- Only activates after exhausting all other resolution strategies (case 2.4 in the series' phased approach)

This completes the series' conflict resolution ladder while maintaining the requirement that all paths must be explicitly configured when `extensions.submodulePathConfig` is enabled. The hashing approach preserves uniqueness guarantees while sacrificing human readability - an acceptable tradeoff given its position as the final fallback.
