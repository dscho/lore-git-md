This is a feature patch in the submodule gitdir path encoding series, specifically addressing case-folding filesystem collisions. It's part of the v6 series implementing runtime configuration for submodule paths via `extensions.submodulePathConfig`.

The patch introduces case-folding collision detection and handling for submodule gitdirs on case-insensitive filesystems. When enabled, it uses a stricter RFC3986 URL encoding variant that forces uppercase letters to be percent-encoded, preventing collisions between paths that differ only in case (e.g., "Foo" and "foo"). The encoding is only applied when needed, preserving the original path on case-sensitive filesystems.

Key technical changes include:
- New `is_casefolding_rfc3986_unreserved()` helper in url.[ch] that treats uppercase as reserved
- Case-folding collision detection via `check_casefolding_conflict()`
- Three-stage fallback in `create_default_gitdir_config()`: standard encoding -> case-folding encoding -> digit-appended variants
- Comprehensive test cases in t7425 verifying handling of mixed-case, encoded, and digit-suffixed paths

The implementation maintains the series' architectural approach while solving a specific edge case, with careful attention to filesystem behavior and backward compatibility. The test coverage is thorough, including multiple collision scenarios and verification of the resulting encoded paths.

This patch represents the final refinement of the path encoding functionality before the series' concluding patch, addressing one of the last identified edge cases in the implementation.
