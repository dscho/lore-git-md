This is a build system patch adding Homebrew support control, part of the ongoing macOS iconv conversion issue thread. The patch introduces a `NO_HOMEBREW` flag to disable Homebrew library linking, similar to existing controls for MacPorts and Fink. It restructures the Homebrew path handling in `config.mak.uname` to use new `HOMEBREW_PREFIX`, `HOMEBREW_GETTEXT_PREFIX`, and `HOMEBREW_MSGFMT` variables that are only activated when `NO_HOMEBREW` is undefined.

The changes accommodate both Intel (`/usr/local`) and Apple Silicon (`/opt/homebrew`) Homebrew installations while maintaining backward compatibility. The patch moves path logic from direct compiler/linker flags to variable assignments, making the build system more maintainable. This follows the thread's established pattern of handling macOS package managers, though focuses specifically on Homebrew rather than the broader package manager ecosystem discussed earlier.

Key technical points for future reference: The Makefile now checks `NO_HOMEBREW` before applying Homebrew paths, with separate handling for general Homebrew libraries (`HOMEBREW_PREFIX`) and gettext-specific paths (`HOMEBREW_GETTEXT_PREFIX`). The msgfmt` binary path is now configurable via `HOMEBREW_MSGFMT`. The changes preserve existing behavior while adding the disable option requested in earlier thread discussion.
