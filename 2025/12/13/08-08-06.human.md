This is a feature patch series implementing the submodulePathConfig extension, representing the culmination of a long design discussion about handling submodule gitdir paths. The v6 series from Adrian Ratiu finalizes the approach as a pure runtime configuration solution after definitively rejecting build-time options.

The series is split into two logical parts: patches 1-6 establish the core extension infrastructure, while patches 7-10 add path encoding capabilities to prevent filesystem conflicts. Key changes in v6 include renaming the extension (from submoduleEncoding), decoupling the extension from encoding logic, simplifying validation, and adding a migration command.

The implementation now follows a three-phase approach separating core infrastructure, encoding logic, and migration functionality. The design ensures repositories with the extension enabled must have complete submodule.gitdir configuration, with new submodules automatically recording non-conflicting paths. Case-folding filesystems are handled through RFC3986-based encoding, with hashed names as a last resort.

The series appears well-tested with comprehensive coverage in t7425, including edge cases around parallel clones and case-folding collisions. The architectural direction has reached consensus, with all major design questions resolved and build-time configuration options conclusively rejected. This represents the final iteration before potential merging, pending real-world migration testing.
