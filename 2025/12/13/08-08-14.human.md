This is part 8 of a 10-patch series implementing URL-encoded paths for submodule gitdirs when the new `extensions.submodulePathConfig` is enabled. The series has reached architectural consensus after several rounds of review.

The patch addresses filesystem collisions in nested submodule directories by introducing URL encoding for gitdir paths. When the path config extension is active, submodule names containing problematic characters (like slashes) are now encoded using RFC3986 rules before being used in filesystem paths. This prevents directory nesting issues while maintaining backward compatibility with existing submodules.

Key technical changes:
- Adds URL encoding fallback path in `create_default_gitdir_config()`
- Introduces new validation logic for encoded paths
- Splits validation into legacy and encoded variants
- Adds comprehensive tests for nested submodule scenarios
- Handles parallel cloning cases
- Verifies the extension can be toggled on/off

The implementation follows the agreed design where encoding is only applied when needed for new submodules, avoiding disruption to existing repositories. The tests demonstrate successful handling of tricky cases like submodules named "hippo/hooks" that would previously cause filesystem conflicts.

This is a well-tested piece of the larger submodule path configuration effort, showing careful attention to edge cases and clean integration with the existing codebase. The patch moves the series closer to completion while maintaining the strict config requirements established earlier in the thread.
