This is a follow-up in the MEMZERO_ARRAY/Coccinelle series, with Junio Hamano providing feedback on the build system changes and showing additional conversions found by the new rules.

The email contains two main pieces of information:

1. A small but important fix to the Makefile change from patch 2/2, where the `grep` command was incorrectly using `-q` which made CI failures impossible to diagnose. The fix removes the `-q` flag so error output will be visible.

2. A demonstration of the Coccinelle rules in action, showing additional conversions found in Junio's 'seen' branch. These affect:
   - diffcore-delta.c (spanhash rehashing and initialization)
   - linear-assignment.c (array zeroing for small column counts)
   - shallow.c (bitmap clearing in shallow commit handling)

Junio notes these may contain false positives that would require marking the rules as "pending" rather than active checks, or they may represent real improvements to adopt. The conversions appear technically sound, following the same pattern as earlier approved changes - replacing memset() of array-sized memory blocks with the new type-safe MEMZERO_ARRAY() macro.

This continues the thread's technical discussion while showing the practical impact of the proposed changes. The build system question from Patrick Steinhardt remains open, but the core macro implementation and Coccinelle rules appear to be working as intended in real code. The additional conversions touch core Git functionality (diff, shallow clone, linear assignment) demonstrating the broad applicability of the change.
