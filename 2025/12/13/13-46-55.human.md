This is a documentation patch series (v2) improving the `git replay` man page, building on previous discussion about clarifying behavior and terminology. Kristoffer Haugsbakk addresses three aspects: conflict output, the `--contained` option, and internal linking.

The key change in v2 is a significant rewrite of the `--contained` documentation. Based on feedback from Phillip Wood and Junio Hamano, the patch now clarifies that the option "updates all branches that point at commits in <revision-range>" rather than the more obscure "advances branches contained in revision-range". The new version also explicitly states that `--contained` requires `--onto`.

The series maintains the original patch documenting `git replay`'s silent conflict resolution behavior (which some users might find surprising compared to other Git commands) and adds proper Asciidoc markup for internal section linking. The changes are well-motivated by real user confusion and have already benefited from thorough review discussion in v1.

This appears ready for inclusion - the terminology debate has reached consensus, and the changes directly improve user understanding of `git replay`'s behavior. The interdiff shows careful attention to reviewer feedback while keeping the scope focused on documentation improvements.
