This is the second patch in a two-part refactoring series converting memset() calls to MEMZERO_ARRAY() for Coccinelle compliance. The patch mechanically replaces manual memset() calls with MEMZERO_ARRAY() in three core components: diffcore-delta.c (diff algorithm internals), linear-assignment.c (optimization code), and shallow.c (shallow clone handling).

The changes are straightforward array zeroing operations where MEMZERO_ARRAY() provides a more maintainable and Coccinelle-friendly alternative to memset(). Key technical details include:
- Array types being zeroed: struct spanhash (diffcore), int arrays (linear assignment), uint32_t bitmaps (shallow)
- Size calculations preserved exactly (including bit-shifted allocations in diffcore)
- All changes maintain identical runtime behavior
- Touches stable, performance-sensitive code paths but changes are low-risk

This continues the established pattern of MEMZERO_ARRAY() adoption seen in the codebase, triggered by new Coccinelle checks flagging these older memset() patterns. The patch follows the same style as previous conversions in the series, with no functional changes beyond the macro substitution. As with part 1, this appears to be an uncontroversial mechanical change that improves code consistency.
