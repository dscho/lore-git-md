This patch introduces the core infrastructure for the `extensions.submodulePathConfig` feature, which is part of a larger series to standardize submodule gitdir path handling. The extension makes `submodule.<name>.gitdir` the single source of truth for submodule paths when enabled, requiring explicit configuration for all submodules.

Key technical components:
- New `repository_format_submodule_path_cfg` flag in `struct repository`
- Extension handling in `setup.c` for `extensions.submodulePathConfig`
- Automatic config creation for new submodules via `create_default_gitdir_config()`
- Strict validation in `submodule_name_to_gitdir()` that enforces config existence when extension is active
- New test file `t7425-submodule-gitdir-path-extension.sh` verifying behavior
- Helper function `validate_and_set_submodule_gitdir()` for config validation/setting

The implementation enforces that repositories with the extension enabled must have complete `submodule.<name>.gitdir` configuration, throwing errors for missing entries. New submodules automatically get their config set, while existing ones require manual migration (shown in the error message). The tests demonstrate both legacy and extension-enabled workflows, including clone behavior and path validation.

This patch represents the foundational layer of the three-phase approach agreed upon in the thread, providing the config infrastructure before the actual encoding logic (coming in later patches). It directly implements Junio Hamano's requirement for complete config coverage when the extension is active.
