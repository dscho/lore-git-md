This is part 4/10 of a series implementing the `extensions.submodulePathConfig` feature, which standardizes submodule gitdir paths through configuration. The patch introduces the core extension infrastructure that makes `submodule.<name>.gitdir` the single source of truth for submodule paths when enabled.

When the extension is active, Git will:
- Require explicit `submodule.<name>.gitdir` configuration for all submodules
- Automatically set this config for new submodules
- Error out if the config is missing for existing submodules (with migration instructions)
- Validate configured paths to prevent conflicts

The implementation adds the extension flag handling, config documentation, and validation logic while maintaining backward compatibility. New tests verify the behavior with both legacy and extension-enabled repositories. This is a key piece of the series' goal to provide reliable, configurable submodule paths without filesystem conflicts.

The patch appears well-structured with thorough test coverage. It follows the architectural direction established in earlier discussion, particularly Junio Hamano's requirement that extension-enabled repositories must have complete gitdir configuration. The validation safeguards help prevent misconfiguration while the clear error messages guide users through migration.
