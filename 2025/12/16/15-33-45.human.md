Windows symlink support: Fix `getcwd()` symlink resolution

This is the first of five patches preparing for proper Windows symlink support, fixing a bug where `git rev-parse --is-inside-work-tree` fails when the current directory path contains symlinks. The issue stems from Git's Windows-specific `mingw_getcwd()` implementation not resolving symlinks as POSIX `getcwd()` would.

The patch simplifies the Windows directory resolution logic by directly using `GetFinalPathByHandleW()` (which resolves symlinks) rather than first trying `GetLongPathNameW()`. This change is now safe since Git no longer supports Windows XP, where the symlink-resolving API was unavailable. The implementation remains careful about error handling and path length limits.

The change appears straightforward and well-justified, coming from the Git for Windows maintainer with clear motivation from a real user-reported bug. It's part of a coordinated effort to improve symlink handling on Windows, with subsequent patches in the series addressing related prerequisites.
