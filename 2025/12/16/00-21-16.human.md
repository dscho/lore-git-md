This is a feature/bugfix patch for the experimental `git replay` command, now in its second version with all technical feedback addressed. The change makes `git replay` drop commits that become empty during replay (when their changes already exist in the target branch), matching the behavior of `git rebase --reapply-cherry-picks --empty=drop` and `git cherry-pick --empty=drop`. Originally-empty commits are preserved.

The implementation compares tree OIDs to detect empty commits and updates branch pointers when tip commits are dropped. Test coverage in t3650 demonstrates the behavior, showing how topic1 updates to point to the rebased C when F is dropped. The patch includes documentation updates to clarify the new behavior.
