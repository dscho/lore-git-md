Feature implementation in the submodule gitdir path encoding series. This is patch 4/10 in the v6 series, focusing on introducing the `extensions.submodulePathConfig` extension and its core infrastructure.

Patrick Steinhardt reviews Adrian Ratiu's implementation of the submodule path configuration extension. The patch adds documentation for the new `extensions.submodulePathConfig` option and implements the core logic that makes submodule gitdir paths configurable when the extension is enabled. The main components are:

1. Documentation updates explaining that when enabled, `submodule.<name>.gitdir` becomes the single source of truth for submodule paths, with Git enforcing its presence for all submodules.

2. A new `validate_and_set_submodule_gitdir()` helper that checks path validity and sets the config if missing.

3. The `submodule_name_to_gitdir()` function is updated to first check the extension status, then either use the plain path (if disabled) or require and validate the config-specified path (if enabled).

Patrick suggests minor improvements: rewording the config documentation for clarity, fixing a whitespace nit, and restructuring the control flow in `submodule_name_to_gitdir()` to reduce early returns. He also recommends adding a hint about the extension in error messages to help users understand why the config is required.

The review is positive, with Patrick agreeing the core approach makes sense. This patch establishes the foundation for the subsequent patches that will add path encoding strategies and migration tooling. The implementation cleanly separates the extension's enablement from the path resolution logic while maintaining strict validation.
