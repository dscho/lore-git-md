This is a feature patch series addressing submodule gitdir path encoding, now in its final review stages. Junio Hamano provides feedback on the documentation aspect, suggesting the need for clearer examples to help users understand when to enable the new `extensions.submodulePathConfig` feature.

The series has already established technical consensus around its three-phase implementation (core infrastructure, path encoding functionality, and hashed fallback strategy). While the technical solution is sound, Junio notes the user-facing documentation could better explain the practical scenarios where this feature helps - particularly for the less obvious case of needing non-standard gitdir paths.

He suggests including concrete examples showing problematic submodule layouts that would benefit from custom gitdir locations, similar to how the case-insensitive filesystem case is already explained. The goal is to help users self-diagnose when they need this feature rather than requiring them to ask developers.

This appears to be one of the final pieces of feedback before the series can be merged, focusing on polishing the user experience rather than making any architectural changes. The implementation itself seems ready, having addressed all major technical concerns through six iterations and gained approval from key maintainers.
