Build system refactoring with platform-specific configuration relocation.

This is a follow-up to Torsten Bögershausen's patch that moved Darwin/macOS build settings from the main Makefile to config.mak.uname. René Scharfe points out a technical issue with the approach - while the relocation works for command-line variable settings, it won't properly handle variables set in config.mak since config.mak.uname is included first in the build process. This means any Darwin-specific overrides in config.mak would be ignored.

The original patch moved several macOS-specific configurations including Fink (/sw) and MacPorts (/opt/local) paths, Apple Common Crypto vs OpenSSL selection, Pthread handling, and CoreServices framework linkage. While mechanically sound, René's observation reveals an important ordering constraint in how these configuration files interact.

This appears to be a genuine issue that would need addressing before the series can proceed, as it affects users who customize their builds via config.mak. The thread is now at a point where either the inclusion order needs adjustment or the patch needs to find another way to preserve config.mak overrides while still achieving the goal of consolidating platform-specific settings.
