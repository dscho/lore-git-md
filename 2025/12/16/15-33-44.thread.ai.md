This thread concerns a 5-patch series preparing for Windows symlink support, co-authored by Johannes Scharfe and Karsten Blees with Johannes Schindelin (Git for Windows maintainer) contributing fixes. The series addresses technical prerequisites across mingw compatibility, config parsing, strbuf utilities, and path handling, with a net reduction of 22 lines across 6 files.

The first patch (now improved) fixed `git rev-parse --is-inside-work-tree` failures in symlink-containing paths by modifying `mingw_getcwd()` to resolve symlinks via `GetFinalPathNameByHandleW`, with Patrick Steinhardt noting its enhanced fallback behavior: when `CreateFileW()` fails, it now attempts `GetFileAttributesW()` before giving up, returning at least the unresolved path when full resolution isn't possible. The second patch, now validated by Patrick Steinhardt, ensures early parsing of `core.*` config settings (including `core.symlinks`) before template copying during `git init` by switching from `platform_core_config` to `git_default_core_config` in setup.c - a safe change since the latter already includes the former's functionality, while maintaining the full config re-parse after template copying. The third optimized `strbuf_readlink()` to avoid redundant system calls by allocating hint+1 bytes. The fourth removed PATH_MAX limitations in `strbuf_readlink()` for long symlink targets. The final patch makes `trim_last_path_component()` in lockfile.c handle both forward and backward slashes via `is_dir_sep()`, crucial for Windows symlink targets.

All changes maintain general utility while removing Windows-specific restrictions, with each building on prior work. Johannes Schindelin's sign-offs confirm Windows relevance throughout. The series solves path resolution (now with improved fallback behavior), initialization ordering (validated as technically sound by Patrick Steinhardt), performance issues, path length limits, and cross-platform separator handling - key prerequisites for upcoming symlink support.
