This thread concerns a 5-patch series preparing for Windows symlink support, co-authored by Johannes Scharfe and Karsten Blees with Johannes Schindelin (Git for Windows maintainer) contributing fixes. The series addresses technical prerequisites across mingw compatibility, config parsing, strbuf utilities, and path handling, with a net reduction of 22 lines across 6 files.

The first patch fixed `git rev-parse --is-inside-work-tree` failures in symlink-containing directories by modifying `mingw_getcwd()`. The second ensured early parsing of `core.*` config settings before template copying during `git init`, specifically for `core.symlinks` on Windows. The third optimized `strbuf_readlink()` to avoid redundant system calls by allocating hint+1 bytes. The fourth removed PATH_MAX limitations in `strbuf_readlink()` for long symlink targets. The final patch (new) makes `trim_last_path_component()` in lockfile.c handle both forward and backward slashes via `is_dir_sep()`, crucial for Windows symlink targets.

All changes maintain general utility while removing Windows-specific restrictions, with each building on prior work. Johannes Schindelin's sign-offs confirm Windows relevance throughout. The series solves path resolution, initialization ordering, performance issues, path length limits, and now cross-platform separator handling - key prerequisites for upcoming symlink support.
