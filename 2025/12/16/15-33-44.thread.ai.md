This thread concerns a 5-patch series preparing for Windows symlink support, co-authored by Johannes Scharfe and Karsten Blees with Johannes Schindelin (Git for Windows maintainer) contributing fixes. The series addresses technical prerequisites across mingw compatibility, config parsing, strbuf utilities, and path handling, with a net reduction of 22 lines across 6 files.

The first patch fixed `git rev-parse --is-inside-work-tree` failures in symlink-containing paths by modifying `mingw_getcwd()` to resolve symlinks via `GetFinalPathNameByHandleW`, with enhanced fallback behavior when full resolution isn't possible. The second patch ensures early parsing of `core.*` config settings before template copying during `git init`. The third optimized `strbuf_readlink()` to avoid redundant system calls. The fourth removed PATH_MAX limitations in `strbuf_readlink()` for long symlink targets, which Patrick Steinhardt now questions regarding potential undefined behavior with unbounded growth and probes whether Windows imposes natural size limits that could provide safe bounds. The final patch makes `trim_last_path_component()` handle both forward and backward slashes.

He suggests exploring if Windows-specific limits might provide safe bounds, maintaining the series' focus on robust cross-platform symlink support while addressing safety considerations. Johannes Schindelin's sign-offs confirm Windows relevance throughout the series, which has completed its preparatory work with these focused improvements to core functionality.
