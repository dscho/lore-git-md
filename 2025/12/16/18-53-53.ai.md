This is the second patch in a v3 series addressing macOS iconv(3) issues, specifically focusing on Homebrew integration for libiconv. The patch builds on the foundational Homebrew configuration changes from patch 1/2 to provide a workaround for macOS's broken ISO-2022-JP to UTF-8 conversion in t3900 tests (17, 25, 38).

The technical solution adds explicit support for Homebrew-installed libiconv through a new USE_HOMEBREW_LIBICONV flag, following the same pattern as the gettext integration. It searches Homebrew's default locations (/opt/homebrew for Apple Silicon, /usr/local for Intel) and sets ICONVDIR accordingly if the libiconv directory exists. The change maintains backward compatibility by respecting any existing ICONVDIR setting.

The patch modifies both the main Makefile (adding documentation and detection logic) and config.mak.uname (enabling the feature by default on Darwin). This completes the Homebrew-specific portion of the iconv workaround strategy, alongside the previously discussed platform-specific detection and state reset approaches.
