This is part 3/7 of Justin Tobler's series to add object size reporting to `git repo structure`, focusing on human-readable formatting of large counts.

The patch introduces a new `humanise_count()` function in strbuf.[ch] that converts large numbers into scaled values with SI prefixes (k for thousands, M for millions, G for billions). For example, 1005 becomes "1.01 k". The table output format in `git repo structure` is updated to display these humanized counts with proper alignment and unit suffixes, while keeping raw numbers for the keyvalue and nul formats.

The changes include:
- Adding a new `unit_col_width` to track display width of unit suffixes
- Extending table formatting logic to handle the value/unit separation
- Comprehensive test updates showing the new humanized output
- Careful handling of translation strings for the unit prefixes

This is a well-executed refactoring that builds on previous preparatory work in the series. The implementation maintains clean separation of concerns by putting the number formatting logic in strbuf.c while keeping the display specifics in builtin/repo.c. The test changes demonstrate the new behavior clearly, showing both small counts (displayed normally) and large counts (with appropriate scaling).
