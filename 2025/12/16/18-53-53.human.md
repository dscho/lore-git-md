This is a macOS-specific build system patch that adds Homebrew's libiconv as a workaround for broken system iconv functionality on recent macOS versions. It's the second part of a v3 series addressing character encoding conversion issues in t3900 tests.

The patch introduces a new `USE_HOMEBREW_LIBICONV` flag that, when enabled, will make Git use Homebrew's libiconv installation (found in standard Homebrew paths) instead of the system version. This specifically addresses test failures in t3900 (tests 17, 25, and 38) where macOS 15.7.2 and later versions fail to properly convert ISO-2022-JP to UTF-8 in multiple steps.

The implementation respects any existing `ICONVDIR` setting while defaulting to Homebrew's standard locations (/opt/homebrew for Apple Silicon, /usr/local for Intel). The change is cleanly integrated with the existing Homebrew support in the build system, maintaining the pattern established for other Homebrew components like gettext.

This appears to be a well-justified, focused change that builds on the series' earlier work to improve macOS compatibility. The commit message clearly explains the problem and solution, and the implementation follows established patterns for Homebrew integration in Git's build system.
