This is a documentation follow-up in the submodule gitdir path encoding series. Junio Hamano responds to Adrian Ratiu's explanation of when users would need the new `extensions.submodulePathConfig` feature, suggesting the documentation could be improved with concrete examples.

Junio notes that while case (1) about filesystem conflicts (particularly on case-insensitive systems) is reasonably clear, case (2) about non-standard gitdir paths lacks motivating examples. He proposes adding specific scenarios like branch-dependent submodule layouts where path collisions could occur, explaining both the problem and how this feature would help. 

The response emphasizes that good documentation would prevent repeated explanations and help users understand when to enable the extension. This comes after the technical implementation has reached consensus in the thread, with the remaining open question being how to best document the practical use cases for end users. The suggestion aligns with Ben Knoble's earlier request for clearer user-facing motivation in the documentation.
