Bugfix for HTTP authentication in remote-curl, now with testing confirmation. This follows up on Aaron Plattner's patch that fixed authentication failures during filtered clones (`--filter=blob:none`) where blob requests would fail with 401 errors due to missing auth headers in probe_rpc() calls. 

The original issue occurred when initial authentication succeeded for commit history downloads but subsequent blob requests failed because probe_rpc() wasn't properly including credentials. Plattner's solution added `http_append_auth_header()` to ensure credentials are included in these requests.

Lucas De Marchi has now tested and confirmed the fix works, adding a Tested-by tag. The patch remains focused on the immediate Bearer token flow issue while leaving broader HTTP_REAUTH cases for future work. The confirmation from testing suggests this is a solid fix for the specific authentication failure scenario described.

This appears to be a straightforward and well-tested solution to a real-world problem affecting filtered clones with certain authentication setups. The minimal 2-line change follows existing patterns in Git's HTTP transport code.
