Windows compatibility fix for symlink handling in `open()`. This is patch 3/10 in Johannes Schindelen's series preparing Git's test suite for Windows symlink support, particularly for MSYS2's planned default enablement of symlinks.

The patch addresses a Windows-specific behavior where `_wopen()` would incorrectly create a file when given a symlink with `O_CREAT|O_EXCL` flags, while POSIX (and Git expects) this to fail with `EEXIST`. The fix adds explicit checks in `mingw.c` to detect this case and return the expected error code.

This change is specifically needed to make test t4115.8 pass on Windows when symlink support is enabled. The test verifies that `--reject` properly handles existing `.rej` symlinks. The implementation follows POSIX standards and matches Linux's handling of this edge case.

The patch is well-contained, adding just 14 lines with clear comments explaining the Windows vs POSIX behavior mismatch. As part of an already-approved series that's queued for integration, this appears to be a final refinement addressing a specific test case that would otherwise fail with Windows symlinks enabled.
