Performance improvement for Windows symlink support, part of the ongoing preparatory work. This patch removes an artificial PATH_MAX limitation in `strbuf_readlink()` that was preventing Git from handling long symlink targets on platforms like Windows that support paths longer than PATH_MAX. The change replaces a while-loop bounded by STRBUF_MAXLINK (2*PATH_MAX) with an unbounded for-loop, similar to how `strbuf_getcwd()` already handles long paths.

The modification is small (4 lines changed) but significant for Windows compatibility, where long paths are common. The patch builds on previous work in this series that improved symlink handling performance and initialization. Johannes Schindelin's sign-off confirms the Windows-specific relevance, though the change is technically platform-agnostic.

This appears to be a straightforward and well-justified change, removing an unnecessary restriction while maintaining the existing growth strategy (starting with a hint of 32 bytes and doubling as needed). The patch follows the series' pattern of addressing technical prerequisites for better Windows symlink support, though it could theoretically benefit other platforms where PATH_MAX is similarly restrictive.
