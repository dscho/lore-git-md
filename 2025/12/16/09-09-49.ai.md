This is a review response in the submodule gitdir path encoding series, focusing on the runtime configuration implementation in patch 5/10. Patrick Steinhardt raises concerns about the current approach to enabling the `extensions.submodulePathConfig` feature via runtime configuration.

Patrick identifies two key issues with Adrian Ratiu's implementation:
1. The current design would default-enable the extension globally across all repositories, which could cause compatibility problems with other Git implementations that don't understand this configuration.
2. Enabling the extension without proper migration would break existing repositories that lack the required `submodule.<name>.gitdir` configuration.

He suggests an alternative approach where the global configuration would only affect *new* repositories (via `git-init` and `git-clone`), requiring explicit migration for existing repositories. This maintains compatibility while still providing convenience for new work.

The discussion reflects ongoing refinement of the series' configuration strategy, with Patrick advocating for a more conservative approach that better handles the transition period and cross-implementation compatibility. This feedback will likely lead to revisions in how the runtime configuration is implemented, particularly around the scope and timing of extension activation.

The exchange shows the careful consideration being given to backward compatibility and cross-implementation concerns in this significant submodule infrastructure change. Patrick's position aligns with the series' overall goal of maintaining strict config requirements while providing migration paths.
