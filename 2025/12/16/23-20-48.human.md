This is a bug report in the ongoing submodule gitdir path encoding series. Josh Steadmon reports test failures when trying to trigger the new encoding behavior for submodule gitdir path conflicts.

The issue occurs when attempting to add a submodule whose name would conflict with an existing gitdir (like "nested%2fsub"). Instead of using the new path encoding system as expected, the `extensions.submodulePathConfig` is enabled, Git fails with an error about finding a local git directory. This happens even with the global configuration set, suggesting the conflict detection isn't working as intended.

Josh provides detailed reproduction steps using a test setup with nested submodules and specially named repositories. The error comes from `builtin/submodule--helper.c` line 3389, indicating the system is detecting the conflict but not properly handling it through the new encoding path.

This appears to be a regression or gap in the implementation of the new submodule path handling system that was meant to resolve exactly these kinds of filesystem conflicts. The report will likely prompt investigation from the series author (Adrian Ratiu) and other submodule experts to determine why the conflict resolution isn't triggering as designed.
