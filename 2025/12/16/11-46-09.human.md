This is a bugfix patch in a series preparing Git's test suite for Windows symlink support. It corrects an unintended behavior change in `git apply` where a fix for executable file warnings was incorrectly applied to symbolic links and directories as well.

The patch narrows the scope of a special code path in `apply.c` to only affect regular files, not symlinks. This fixes test case t4115.5 (which checks symlink behavior when creating new files) on Windows systems with symlink support enabled in MSYS2.

The change is minimal - just a one-line condition adjustment - but important for correct behavior. This is part of a larger, maintainer-approved effort to improve Windows compatibility, particularly around symlink handling. The patch follows up on a regression introduced in commit 0482c32c334b and has already been reviewed in previous iterations of the series.
