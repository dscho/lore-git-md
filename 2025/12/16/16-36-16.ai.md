This is a bugfix and behavior alignment patch for the experimental `git replay` command, now at v3 with all technical feedback addressed. The patch makes `git replay` drop commits that become empty during replay (when changes already exist in target branch), matching the behavior of `git rebase --reapply-cherry-picks --empty=drop` and `git cherry-pick --empty=drop`. Originally-empty commits are preserved.

The implementation in `replay.c` uses tree OID comparison via `oideq()` to detect empty commits, with branch pointers automatically updated when tip commits are dropped. Test coverage in t3650 demonstrates the behavior, showing how branch `topic1` updates when commit `F` is dropped. The changes are justified by `git replay`'s experimental status allowing behavior improvements.
