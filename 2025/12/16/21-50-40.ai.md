This is a bugfix for HTTP authentication in remote-curl, specifically addressing an issue with probe_rpc() requests during filtered clones. The patch adds authentication headers to probe_rpc() calls, fixing a scenario where initial authentication succeeds for commit history but subsequent blob requests fail with 401 errors due to missing auth headers.

The problem manifests clearly in filtered clones (`--filter=blob:none`) when using git-credential-msal, where the initial authentication works but blob requests fail partway through. The original patch from Aaron Plattner demonstrated this with detailed trace logs showing the authentication failure sequence. The fix is minimal (a 2-line addition of `http_append_auth_header()` to probe_rpc() in remote-curl.c) and follows existing auth handling patterns in the HTTP transport code. While it specifically helps the Bearer token flow, the solution isn't limited to that authentication method.

Lucas De Marchi has tested and confirmed the fix works, adding a Tested-by tag. The solution handles the immediate issue of token reuse in probe_rpc() while explicitly noting that HTTP_REAUTH cases remain for future work. The change is focused and well-contained, addressing a clear pain point in filtered clone operations with authenticated servers.
