Feature patch extending the `git repo structure` command's table output format with inflated object size metrics. This is patch 5/7 in Justin Tobler's series, building on the infrastructure established in previous patches to now display human-readable size information alongside object counts.

The patch introduces a new `stats_table_size_addf()` helper that formats byte sizes with appropriate unit prefixes (KiB, MiB) using the existing `humanise_bytes()` function, now enhanced with a `HUMANISE_COMPACT` flag for abbreviated "B" units. The table output gains a parallel structure under "Reachable objects" showing both counts and sizes for each object type (commits, trees, blobs, tags), with totals for each category.

Key technical details include:
- New `inflated_sizes` field in `object_stats` populated via `odb_read_object_info_extended()`
- Size values formatted with `humanise_bytes()` using compact "B" units
- Table columns dynamically adjust width for aligned output
- Test updates verify empty repo output and realistic size measurements
- SHA1-specific test case demonstrates scaled values (KiB/MiB) and per-type breakdown

The implementation maintains separation between keyvalue/nul formats (unchanged) and the enhanced table format, following the series' incremental approach. Test coverage includes both empty repository and populated scenarios, with size measurements integrated into the existing test framework. The patch appears well-integrated with the series' evolving metrics infrastructure while keeping display formatting concerns localized.
