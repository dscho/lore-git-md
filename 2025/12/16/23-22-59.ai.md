This is a bug report in the submodule gitdir path encoding series, specifically addressing patch 4/10 which introduces the `extensions.submodulePathConfig` feature. Josh Steadmon reports a discrepancy between the documented behavior and actual implementation regarding automatic configuration of `submodule.<name>.gitdir` paths during submodule cloning.

The issue occurs when cloning with `--recurse-submodules` while having the extension enabled globally - the resulting repository's config lacks the expected gitdir entries for submodules, yet no error is raised as the documentation claims should happen. This suggests either a gap in the automatic configuration logic during clone operations or an incorrect assumption about when the validation occurs.

The report directly challenges Adrian Ratiu's claim that "the submodule.<name>.gitdir config is added automatically for all new submodules when this extension is enabled" and that Git will error on missing configs. This appears to be a concrete implementation bug in the path encoding system's validation layer, which was meant to enforce config existence as a core requirement of the extension.

This follows Josh's earlier observation about potential issues with the fallback mechanism when encountering pre-existing encoded paths, indicating there may be multiple edge cases not fully handled by the current validation logic in `submodule_name_to_gitdir()`. The report doesn't specify whether this occurs with new submodule additions, existing submodule clones, or both, but clearly demonstrates the automatic config creation isn't functioning as described during recursive clone operations.

The finding is significant because it touches on a core promise of the extension - that gitdir paths would be fully config-driven when enabled. The silent failure to create configs during clone could lead to repositories being in an inconsistent state where the extension is enabled but required configs are missing, which the validation layer was specifically designed to prevent. This may require revisiting both the clone-time configuration logic and the error reporting paths in the submodule initialization code.
