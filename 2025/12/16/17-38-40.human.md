This is patch 5/7 in Justin Tobler's series adding object size reporting to `git repo structure`. The patch extends the table output format to display inflated object sizes by type (commits, trees, blobs, tags) alongside the existing count metrics. The implementation builds on the infrastructure introduced in earlier patches, now showing human-readable size units (KiB, MiB) for the compressed object data.

The changes include a new `stats_table_size_addf()` helper that formats size values using the existing `humanise_bytes()` function (now enhanced with a `HUMANISE_COMPACT` flag for shorter unit names). The table output now shows both object counts and their total inflated sizes, with proper alignment and i18n support. Test cases are updated to verify the new size reporting works correctly, including edge cases for empty repositories and proper scaling of large values.

The patch appears well-integrated with the series' existing architecture, maintaining separation between data collection and presentation. It follows the incremental development pattern seen in previous patches, focusing cleanly on adding size metrics to the table format while leaving other output formats unchanged. The test coverage is thorough, checking both empty and populated repository scenarios.
