Feature implementation in the submodule gitdir path encoding series (v6 patch 5/10). This patch originally proposed runtime configuration for enabling the `extensions.submodulePathConfig` extension globally, but Patrick Steinhardt points out this would cause compatibility issues with other Git implementations and break existing repositories lacking the required gitdir config.

The key issue is that the current implementation would enable the extension for all repositories by default through runtime config, which Patrick argues is unsafe. Instead, he suggests restricting the automatic enabling to only new repositories created via `git-init` and `git-clone`, requiring explicit migration for existing repositories. This maintains compatibility while still providing convenience for future repositories.

Adrian Ratiu acknowledges the misunderstanding and commits to revising the patch to implement Patrick's suggested approach. The change will involve modifying the configuration handling to only affect new repositories rather than applying globally. This addresses both the cross-implementation compatibility concern and the risk of breaking existing repositories that haven't been properly migrated.

The patch is part of the larger effort to implement path encoding for submodule gitdirs through the new `extensions.submodulePathConfig` extension. This specific change relates to how the extension gets enabled, with the series having already established consensus on requiring explicit gitdir configuration when the extension is active. The revision will align with the project's preference for safe, incremental adoption of the new feature rather than wholesale runtime enablement.
