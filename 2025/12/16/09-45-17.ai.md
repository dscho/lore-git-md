This is part 4/10 of the submodule gitdir path encoding series, focusing on the core extension infrastructure. The patch introduces the `extensions.submodulePathConfig` extension and implements the `submodule.<name>.gitdir` configuration mechanism.

The key changes in this patch:
- Adds documentation for the new `submodule.<name>.gitdir` config option that only works when the extension is enabled
- Modifies `submodule_name_to_gitdir()` to first check for the extension flag, then either:
  - Uses the legacy path format if extension is disabled (with validation)
  - Requires and validates a configured gitdir path if extension is enabled
- Includes strict validation of paths in both modes to prevent conflicts
- Patrick Steinhardt suggested improvements to:
  - Documentation phrasing for the config option
  - Code flow in `submodule_name_to_gitdir()` to reduce early returns
  - Error messages to better explain the extension requirement
- Adrian Ratiu has acknowledged these suggestions and will implement them in the next revision

The patch maintains the series' strict requirements around configuration while implementing the core path resolution logic that will be built upon in later patches. It's part of the first phase (core infrastructure) of the three-phase approach, establishing the foundation for the path encoding functionality that follows.
