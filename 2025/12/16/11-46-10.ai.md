This is a bugfix patch in the ongoing series preparing Git's test suite for Windows symlink support, specifically addressing behavior in MSYS2 environments. The patch modifies Windows-specific code in `compat/mingw.c` to make `open()` with `O_CREAT|O_EXCL` flags behave like POSIX when encountering symlinks.

The core issue is that Windows' `_wopen()` would incorrectly create files through dangling symlinks when given these flags, while POSIX (and Git's expectations) require an `EEXIST` error in this case. The fix adds explicit checks for reparse points (Windows' equivalent of symlinks) before attempting the open operation.

This change enables test t4115.8 ("--reject removes .rej symlink if it exists") to pass when MSYS2's symlink support is enabled. The implementation follows POSIX standards precisely, with added documentation explaining the divergence from native Windows behavior. The patch is part of a well-polished v3 series that's already been approved by the maintainer, with this being one of the final refinements.
