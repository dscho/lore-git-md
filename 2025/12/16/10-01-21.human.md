This is a patch in the submodule gitdir path encoding series, specifically addressing runtime configuration of the new `extensions.submodulePathConfig` feature. The patch (v6 05/10) originally proposed enabling the extension globally, but Patrick Steinhardt points out this would cause compatibility issues with other Git implementations and break existing repositories lacking the required gitdir config.

Adrian Ratiu acknowledges the feedback and will revise the approach to only enable the extension automatically for new repositories via `git-init` and `git-clone`, requiring explicit migration for existing repositories. This matches the architectural consensus that emerged in earlier discussion, where runtime configuration was accepted but with careful consideration for backward compatibility.

The change represents an important refinement in the series' rollout strategy, ensuring the new submodule path handling won't silently break existing setups. The patch is part of a well-developed effort that has addressed multiple rounds of review feedback, with this being one of the final technical adjustments needed before the series can be merged.
