Documentation patch clarifying `git rev-list --filter` behavior with explicitly provided objects. This is a follow-up to Justin Tobler's patch that added documentation about how objects given directly to `git rev-list` bypass filter restrictions by default. Junio C Hamano acknowledges the documentation accurately reflects the current behavior but expresses mild dissatisfaction with the design, noting it's "unfortunate that we need an extra option to do this." The patch itself is minimal and non-controversial, just documenting existing behavior that was previously only implied in the code. The change adds clarity for users who might be surprised when explicitly provided objects appear in filtered output. While the patch is being accepted, Junio's comment suggests there might be room for reconsidering this behavior in the future.
