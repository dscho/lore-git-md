Build system patch refining Homebrew integration on macOS, part of the ongoing character encoding conversion issue thread. This is the first of two patches in René Scharfe's v3 series implementing Junio C Hamano's requested changes for explicit component flags and unified Homebrew handling.

The patch makes Homebrew usage configurable through several new variables: NO_HOMEBREW to disable entirely, HOMEBREW_PREFIX for custom locations, and individual USE_HOMEBREW_* flags for gettext and msgfmt components. It replaces hardcoded paths in config.mak.uname with architecture-aware defaults (/opt/homebrew for ARM, /usr/local for Intel) while maintaining the same functionality. The gettext linking is now precisely targeted to the "keg" (opt/gettext subdirectory) rather than broader Homebrew paths.

Key technical changes include moving Homebrew-specific logic from config.mak.uname to the main Makefile with proper conditionals, adding documentation for the new variables, and implementing path existence checks before usage. The patch maintains backward compatibility while providing more control over Homebrew integration, addressing concerns raised in earlier thread discussion about implicit behavior and platform-specific handling.

This represents a significant step toward the thread's goal of a more maintainable build system architecture for macOS, though questions remain about whether to support other package managers like MacPorts in parallel. The explicit flags and documentation improvements should help users understand and customize their Homebrew-based builds while reducing the "magic" in the current implementation.
