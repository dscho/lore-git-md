This is a review response in the submodule gitdir path encoding series, focusing on the runtime configuration aspect of the new `extensions.submodulePathConfig` feature.

Patrick Steinhardt raises concerns about patch 5/10's implementation of runtime enabling for the submodule path configuration extension. He argues that the current approach of default-enabling the extension globally could cause compatibility issues with other Git implementations and break existing repositories lacking the required gitdir config. 

The key objection is that the patch's behavior differs from what was previously discussed with Junio Hamano - instead of automatically setting the extension for new repositories via git-init/clone, it makes the extension active everywhere by default. Patrick maintains this could lead to problems when repositories without proper configuration are accessed by Git clients that don't understand the extension.

He suggests a more conservative approach: using global config to automatically enable the extension only for newly created repositories (via init/clone), while requiring explicit migration for existing ones. This would prevent breakage while still providing convenience for future repositories. The response indicates the series may need revision to align with this more gradual deployment strategy for the new extension.

This exchange shows the careful balancing act required when introducing repository extensions that affect compatibility. While the overall architectural direction of the series has consensus, this specific implementation detail around enabling the extension needs refinement to avoid potential ecosystem-wide issues.
