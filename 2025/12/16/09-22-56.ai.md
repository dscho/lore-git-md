This is part 10 of the ongoing hook subsystem refactoring series, converting receive-pack's update hook to the new `hook.h` API while maintaining sideband output functionality.

Adrian Ratiu responds to Patrick Steinhardt's minor style note about NULL checking the output parameter in the `hook_output_to_sideband()` callback. While agreeing that NULL output should theoretically never occur, Adrian acknowledges the defensive check is still worthwhile and suggests upgrading it to a BUG() assertion if a reroll is needed for other reasons. The current implementation safely handles NULL by doing nothing, which Patrick considers acceptable as a non-blocking issue.

The exchange confirms this is the last remaining minor point in the otherwise complete receive-pack hook conversion, which successfully preserves sideband protocol support (including keepalive packet handling) through the new callback-based output capture system. The discussion shows both maintainers consider this ready to proceed, with any potential NULL check hardening being a trivial follow-up if needed.
