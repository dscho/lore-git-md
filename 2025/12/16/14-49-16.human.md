This is a follow-up discussion in the documentation patch thread about `git rev-list --filter` behavior. Patrick Steinhardt, the original implementer of `--filter-provided-objects`, responds to Justin Tobler's question about whether there are legitimate use cases for the current default behavior where explicitly provided objects bypass filters.

Steinhardt acknowledges the current behavior is surprising but explains it was preserved for backward compatibility with partial clone implementations, where the consequences of changing it weren't fully understood. He doesn't know of any positive use cases for the current behavior but cautions that lack of awareness doesn't mean they don't exist - the behavior was kept to avoid potentially breaking unknown edge cases in partial clones.

The exchange highlights that while the documentation patch accurately describes the status quo, there's an underlying design question about whether the default behavior should be changed. Steinhardt suggests this would require research into partial clone usage patterns before considering any modification. The thread remains open-ended on this larger question while the straightforward documentation improvement moves forward.
