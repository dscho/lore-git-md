Platform compatibility patch focusing on Windows symlink support initialization. This is the second in a 5-part series preparing for proper symlink handling on Windows.

The patch modifies Git's initialization sequence to parse all core.* config settings early, specifically before copying template files during `git init`. This is particularly important for Windows where `core.symlinks` defaults to false, but needs to be respected if explicitly set to true. The change moves the config parsing from a platform-specific callback (`platform_core_config`) to the more comprehensive `git_default_core_config`, while making that function non-static so it can be called from setup.c.

The immediate motivation is fixing a Git for Windows issue (#3414) where template symlinks weren't properly handled during init when `core.symlinks=true` was set. The change has broader implications though - it ensures all core.* settings are processed early in init, which could affect other initialization behaviors beyond just symlinks. The diff is minimal (5 lines added, 3 removed across 3 files) but touches sensitive areas of config parsing and repository setup.

This builds on the series' goal of robust symlink support by addressing initialization ordering, with Johannes Schindelin's involvement as Git for Windows maintainer lending credibility to the Windows-specific considerations. The patch appears straightforward but modifies core initialization flow, so may warrant close review from those familiar with Git startup sequence.
