Documentation patch clarifying edge case in `git rev-list --filter` behavior. This is a maintainer response to Justin Tobler's patch that explicitly documents how `git rev-list` handles explicitly provided objects when filtering. The patch adds a note to the man page explaining that objects given directly to the command bypass filter restrictions by default, only respecting filters when `--filter-provided-objects` is specified.

Junio Hamano confirms the documentation accurately reflects the current behavior and queues the patch, though expresses mild dissatisfaction with the design requiring a separate option to filter provided objects. The change is minimal (3 line additions, 1 deletion) and non-controversial, simply documenting existing behavior that was previously only implied. The thread reference suggests this clarification was prompted by prior discussion, though the specific context isn't included in this email.

Key technical details for future reference: the behavior affects the interaction between `--filter` and explicitly provided object IDs in `git rev-list`, with the `--filter-provided-objects` option being the toggle for whether filters apply to direct inputs. The documentation update targets the `object:type` filter section specifically, though the behavior likely applies to other filter types as well.
