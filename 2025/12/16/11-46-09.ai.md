Bugfix in the Windows symlink preparation series. This patch corrects an unintended side effect of commit 0482c32c334b ("apply: ignore working tree filemode when !core.filemode") where the change to executable bit handling accidentally affected symbolic links and directories in addition to regular files.

The fix narrows the special `!trust_executable_git` code path in `apply.c` to only apply to regular files by adding a `!S_ISREG(st->st_mode)` condition. This ensures the original behavior is preserved for symlinks and directories while still fixing the executable bit warning issue for regular files.

The change is specifically needed to make test t4115.5 ("symlink escape when creating new files") pass on Windows when MSYS2's symbolic link support is enabled. The patch is part of Johannes Schindelen's v3 series preparing Git's test suite for Windows symlink support, which has already been approved by the maintainer with this version containing final refinements.

Key technical details:
- Modifies `apply.c`'s `check_preimage()` function
- Preserves behavior for symlinks/directories while fixing regular file handling
- Connects to earlier commit 0482c32c334b
- Enables t4115.5 test case to pass with Windows symlinks
- Part of broader effort to support MSYS2's upcoming default symlink enablement
