This is a technical clarification in the ongoing refactoring series for packfile storage in Git's object database (ODB) abstraction effort. Patrick Steinhardt responds to Justin Tobler's question about how alternate ODB sources are handled in the current transitional state of the code.

The discussion centers around patch 1/10, which introduced packfile stores being created via their owning ODB source rather than directly via the ODB. Justin had noted some awkwardness in how alternate sources are being prepared through the same packfile store despite the architectural shift to per-source stores. Patrick confirms this is indeed a temporary inconsistency in the transitional state of the code, acknowledging it as flawed but necessary for incremental refactoring.

Key technical points clarified:
- Alternate sources are currently prepared through the same packfile store during this intermediate phase
- This represents an intentional but imperfect transitional state in the series
- The awkwardness will be resolved later in the series (though Patrick notes he couldn't find a cleaner incremental approach)
- The current state maintains the architectural direction of tracking packs per source rather than per ODB

This exchange highlights the careful balance required in large-scale refactoring between incremental progress and architectural purity, with both parties demonstrating awareness of the tradeoffs. The response provides important context for reviewers about intentional transitional states in the series.
