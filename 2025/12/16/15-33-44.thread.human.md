This thread centers on a 5-patch series preparing Git for better Windows symlink support, co-authored by Johannes Scharfe and Karsten Blees with input from Git for Windows maintainer Johannes Schindelin. The series makes focused improvements across mingw compatibility, config parsing, and path handling, with an overall reduction of 22 lines across 6 files.

The series addresses several technical prerequisites: fixing `git rev-parse` failures in symlink-containing paths, ensuring early config setup during `git init`, optimizing symlink reading, and improving path component trimming. The most substantive discussion revolved around patch 4/5, which removes PATH_MAX limitations in `strbuf_readlink()` to handle long symlink targets. Patrick Steinhardt initially raised concerns about potential undefined behavior with unbounded growth, but the authors and Johannes Schindelin have since signed off on the approach, with Junio Hamano confirming the safety of the ERANGE-based retry mechanism.

With this latest patch receiving positive reviews from both the Windows maintainer and the Git maintainer, the technical discussion appears resolved. The series now seems ready for integration, having addressed all identified concerns while maintaining its focus on robust cross-platform symlink support. The changes are minimal but important, particularly for Windows compatibility, and represent the culmination of careful review from key platform experts.
