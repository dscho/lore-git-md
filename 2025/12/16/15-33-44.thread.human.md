This thread covers a 5-patch series preparing Git for better Windows symlink support, co-authored by Johannes Scharfe and Karsten Blees with input from Git for Windows maintainer Johannes Schindelin. The series makes several incremental improvements: fixing `rev-parse` failures in symlink-containing paths, ensuring proper config parsing during `git init`, optimizing symlink reading, removing PATH_MAX limitations, and improving path separator handling.

Patrick Steinhardt has been actively, previously validating the config parsing changes and noting improvements to the symlink resolution fallback behavior. His latest feedback raises concerns about potential undefined behavior in the now-unbounded `strbuf_readlink()` implementation from patch 4/5. While the removal of PATH_MAX constraints was intentional, Patrick questions whether there should be platform-specific upper bounds, particularly for Windows, to prevent issues with extremely large symlink targets. This technical discussion represents the final open question in an otherwise complete series that has addressed path resolution, initialization ordering, performance, and cross-platform compatibility - all key prerequisites for upcoming Windows symlink support.
