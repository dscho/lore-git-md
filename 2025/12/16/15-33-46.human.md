This is a Windows-specific bugfix and preparatory patch for symlink support, part of a 5-patch series. The change ensures all `core.*` config settings are parsed early during `git init`, which is particularly important on Windows where `core.symlinks` needs to be known before copying template files that might contain symlinks.

The patch makes `git_default_core_config()` non-static and calls it directly during initialization, rather than the more limited `platform_core_config`. This fixes a concrete issue where template symlinks weren't being handled correctly on Windows (Git-for-Windows issue #3414), while also being generally useful for ensuring all core settings are respected during init.

The change is small (5 lines net) but impactful, touching config parsing in environment.c/h and init behavior in setup.c. As part of the broader symlink support effort led by Windows Git experts, this patch shows careful attention to initialization order and config handling edge cases. The fix is straightforward and maintains existing patterns while solving a real user-facing problem.
