Performance optimization in the Windows symlink support series.

This third patch in the 5-part series addresses an inefficiency in `strbuf_readlink()` where the function could make redundant `readlink()` system calls in edge cases. The issue occurs when the caller provides a size hint that exactly matches the link target size (such as from `stat.st_size`), requiring a second call to confirm the buffer wasn't too small. The fix is straightforward: always allocate one extra byte (using `hint + 1`) to ensure unambiguous detection of buffer adequacy in a single call.

The change affects the strbuf utility's link-reading logic, modifying the growth size and comparison checks while maintaining the same overall behavior. This optimization is particularly relevant for Windows symlink handling where such operations may be more frequent. The patch is small (3-line diff) and focused, with Johannes Schindelin's sign-off indicating Windows-specific validation. It builds on the series' theme of improving symlink-related infrastructure, though unlike the previous config parsing changes, this is a general performance tweak not specific to Windows.
