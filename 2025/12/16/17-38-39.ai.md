This is patch 4/7 in Justin Tobler's series adding object size reporting to `git repo structure`, focusing on adding inflated object size metrics to the keyvalue output format.

The patch extends the repository structure reporting to include the total inflated size of objects by type (commits, trees, blobs, tags) in the keyvalue and nul output formats. It introduces a new `inflated_sizes` field in the `object_stats` struct to track these metrics alongside the existing object type counts. The implementation uses `odb_read_object_info_extended()` to get the inflated size of each object during traversal, accumulating the totals per type.

Key technical changes include:
- New `inflated_sizes` field in `object_stats` mirroring the structure of `type_counts`
- Modified `count_objects()` callback to measure and accumulate sizes using ODB APIs
- Updated keyvalue output format to include `objects.<type>.inflated_size` entries
- Test updates to verify the new size reporting in SHA1 contexts
- Documentation update mentioning the new size metrics

The patch maintains the series' pattern of cleanly separating data collection from presentation, with the table format support deferred to a subsequent commit. The test changes focus on SHA1 compatibility, suggesting follow-up work may address SHA-256. The implementation handles error cases gracefully by skipping objects that can't be measured.

This continues the series' progression from basic counting to comprehensive repository metrics, with the infrastructure now in place for both counts and sizes. The changes are well-contained, touching only the keyvalue/nul formats as promised, with clear intent to extend to the table format later.
