This is a performance optimization patch in the Windows symlink support series. It addresses a subtle inefficiency in `strbuf_readlink()` where the function could make an unnecessary second system call to `readlink()` in certain cases.

The issue occurs when the caller provides a size hint (like from `stat.st_size`) that exactly matches the link target's length. Currently, the function can't distinguish between this case and the buffer being too small, so it makes a second call with a larger buffer. The patch avoids this by always allocating one extra byte, ensuring the first call can definitively determine if the buffer was large enough.

The change is small (3 lines modified in `strbuf.c`) but meaningful, especially for Windows where system calls may be more expensive. Johannes Schindelin's sign-off suggests this has been vetted for Windows compatibility. This is one of several preparatory fixes needed before full symlink support can be implemented on Windows.
