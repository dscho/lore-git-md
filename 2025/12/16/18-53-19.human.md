Build system refactoring for macOS configuration. This is part 2/3 of a series reorganizing platform-specific build settings, with this patch moving Darwin/macOS-specific logic from the main Makefile to config.mak.uname where it belongs alongside other platform configurations.

The change is purely mechanical - it preserves all existing macOS build behaviors exactly, including Fink (/sw) and MacPorts (/opt/local) path handling, Apple Common Crypto vs OpenSSL selection, Pthread configuration, and CoreServices framework linkage. The patch follows the same pattern used for other platforms in config.mak.uname.

René Scharfe points out a potential issue with the implementation - while the refactoring works when variables are set on the command line, it won't properly handle settings in config.mak since config.mak.uname is included first. This suggests the series may need adjustment to maintain all existing configuration mechanisms.

The change appears well-scoped and follows established patterns, though the thread indicates there may be some build configuration edge cases to address. The series seems to be improving build system organization by properly isolating platform-specific logic, with the full motivation likely becoming clear in part 3.
