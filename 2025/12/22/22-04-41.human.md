This is a bugfix patch series for the experimental `git replay` command, addressing confusing error messages when invalid commit references are provided.

The main patch improves error reporting when users provide an invalid commit-ish argument to `--onto` or `--advance`. Currently, the command fails with an obscure message about replaying to the root commit when it can't resolve the input. The change makes it fail immediately with a clearer message about the invalid commit reference.

A second patch adds regression tests covering various failure modes, including invalid commit-ish inputs. The test additions appear thorough, exercising both `--onto` and `--advance` modes.

The author notes some confusion about the `determine_replay_mode` function's logic, particularly the final `else` case that seems unreachable given the mandatory nature of `--onto` or `--advance` options. While this observation isn't part of the actual changes, it suggests potential area for future code clarification.

The changes are focused and well-motivated, with clear explanations of both the problem and solution. The test additions provide good coverage for the error cases being addressed. This appears to be a straightforward quality-of-life improvement for users of the experimental replay command.
