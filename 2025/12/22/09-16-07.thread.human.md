This thread started with a bug report from Zhelyo Zhelev about what appeared to be a typo in `git restore`'s error message when using `-source` (with a single dash). Brian M. Carlson clarified that this was actually correct behavior - Git was parsing `-source` as `-s ource` and correctly reporting it couldn't resolve "ource" as a revision, though the unquoted output could confuse users.

Junio C Hamano has now pointed out that while the behavior is correct, the error message formatting doesn't follow Git's style guidelines, which recommend quoting unresolved names. The current implementation in `builtin/checkout.c` shows the revision name without quotes, while the convention is to use single quotes (like `unable to open 'file'`). This would be a simple one-line change to make the output clearer while maintaining the same underlying behavior. The thread is effectively closed, but this minor style improvement could be made in a follow-up patch.
