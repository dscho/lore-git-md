Bugfix for `git replay` error messaging, part of Elijah Newren's series addressing confusing error handling. This first patch focuses on improving feedback when invalid commit-ish arguments are provided to `--onto` or `--advance` options.

The patch modifies `peel_committish()` in `builtin/replay.c` to fail immediately with a descriptive error when commit resolution fails, rather than propagating NULL and eventually showing the misleading "root commit" message. The change affects both stuck (`--onto=<name>`) and unstuck (`--onto name`) option forms, catching cases where arguments might be unintentionally passed to the option when meant as positional arguments.

Test coverage is added in `t/t3650-replay-basics.sh` with two new test cases verifying the improved error messages for invalid commit-ishes with both `--onto` and `--advance` options. The tests use `refs/not-valid` as the invalid reference and verify the exact error message format.

The change is narrowly scoped to error reporting without altering the underlying commit resolution logic. The commit message provides clear technical background on the error propagation chain and demonstrates the improved user experience with a concrete example showing the new error message format.
