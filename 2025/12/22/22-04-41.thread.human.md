This thread documents a bugfix and test coverage series for `git replay` error handling when invalid commit-ish inputs are provided. Originally identified by Elijah Newren, Kristoffer Haugsbakk has led the effort through three iterations, incorporating feedback from Junio Hamano, Phillip Wood, and Elijah himself.

The six-patch v3 series makes several architectural improvements: removing dead code (including an unimplemented "guess mode"), restructuring validation to check ref existence before commit peeling, adding caller-specific error messages, and adopting `parse_object_or_die()` for more robust object handling. The final patch adds comprehensive test coverage for various failure conditions, including mandatory option requirements, root commit handling, option incompatibilities, and current limitations around merge commits.

All reviewers' feedback has been addressed across the series. Junio suggested the final function naming (`set_up_replay_mode`) and the switch to `parse_object_or_die()`. Phillip Wood helped refine the test approach, while Elijah Newren confirmed all outstanding issues were resolved in v3. The changes are focused in `builtin/replay.c` and `t/t3650-replay-basics.sh`, with the series now appearing merge-ready with its combination of clean architectural improvements and thorough test coverage.
