This is a bugfix patch series for the `git replay` command, addressing error messaging and adding test coverage. The main patch improves error reporting when an invalid commit-ish is provided to `--onto` or `--advance` options, replacing a confusing "root commit" message with an immediate failure when the commit lookup fails. The second patch adds regression tests for various failure conditions.

The author notes that the current error message about replaying to root commit is misleading when users simply mistype an argument, making it seem like a fundamental limitation rather than an input error. The fix moves the error reporting to the point where the commit lookup fails, providing more direct feedback.

The series also includes an observation about potentially dead code in `determine_replay_mode()` where an else clause appears unreachable given the mandatory nature of `--onto` and `--advance` options, though the author acknowledges this might just be their misunderstanding. The code in question was introduced in commit 22d99f01 which made these options mandatory.

Key technical details for future reference:

- Adds 43 lines of test coverage in `t/t3650-replay-basics.sh`
- Focuses on error cases for commit resolution

- Questions (but doesn't change) the `determine_replay_mode` logic structure
