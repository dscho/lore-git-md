This is a discussion about a reported bug in `git restore`'s error messaging. The original reporter, Zhelyo Zhelev, noted that when using `-source` (single dash) instead of `--source`, the error message shows "could not resolve ource" - missing the 's' from "source". They reproduced this on multiple platforms with Git 2.52.0.

Brian m. carlson responds that this isn't actually a bug in Git's messaging, but rather expected behavior due to how command-line arguments are parsed. The single-dash form `-source` gets interpreted as `-s ource` (equivalent to `--source=ource`), so Git is correctly reporting it couldn't resolve "ource". The code in `builtin/checkout.c` shows the message is working as designed - it concatenates "could not resolve" with whatever revision name was provided.

This appears to be a case of user error rather than a Git bug, though the behavior could perhaps be made more user-friendly. The discussion clarifies Git's argument parsing behavior and shows the current implementation matches the intended design. No code changes are proposed - just an explanation of why the reported behavior occurs.
