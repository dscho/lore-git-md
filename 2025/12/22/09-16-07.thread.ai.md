Thread summary:

Bug report from Zhelyo Zhelev regarding `git restore` error messaging when given an invalid `-source` argument (single dash). Initial confusion stemmed from interpreting "could not resolve ource" as a typo. Brian M. Carlson clarified the correct parsing behavior (as `-s ource`) and identified an opportunity to improve error message formatting to match Git's CodingGuidelines, which recommend quoting unresolved names.

Brian has now submitted a one-line patch modifying `builtin/checkout.c` to wrap the unresolved treeish in single quotes, changing "could not resolve ource" to "could not resolve 'ource'". This strictly improves clarity while maintaining the same underlying behavior. The patch includes a Reported-by tag crediting Zhelyo Zhelev and confirms the original issue was a syntax misunderstanding rather than a bug. The change aligns with Git's convention for similar error messages (e.g., "unable to open '%s'") and requires no functional modifications beyond the message formatting. The thread demonstrates how user reports can surface small but meaningful improvements to error messaging, even when the reported behavior was technically correct.
