Thread summary:

Bug report from Zhelyo Zhelev regarding `git restore` error messaging when given an invalid `-source` argument (single dash). Initial report interpreted "could not resolve ource" as a typo. Brian M. Carlson clarified this is correct behavior: single-dash syntax parses as `-s ource`, with the error showing the failed revision resolution. Thread concluded this was a syntax misunderstanding, not a bug.

Junio C Hamano notes the error message formatting in `builtin/checkout.c` doesn't follow Git's CodingGuidelines for unresolved names, which specify quoting the unresolved item. Current implementation shows `die(_("could not resolve %s"), opts->from_treeish)` without quotes, while guidelines recommend patterns like `unable to open '%s'`. A simple change would wrap the revision name in single quotes (e.g., "could not resolve 'ource'") to clarify the unresolved portion, aligning with convention. This would be a one-line change in `builtin/checkout.c` without affecting the underlying behavior. The thread remains closed regarding the original issue, but this observation identifies a small style improvement opportunity.
