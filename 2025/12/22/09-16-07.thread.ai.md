Thread summary:

Bug report from Zhelyo Zhelev regarding `git restore` error messaging when given an invalid `-source` argument (single dash). Brian M. Carlson analyzed the issue, confirming the parser correctly interpreting `-s ource` but identifying an opportunity to improve error message formatting per Git's CodingGuidelines by quoting unresolved names. Brian submitted a one-line patch modifying `builtin/checkout.c` to wrap the unresolved treeish in single quotes, changing "could not resolve ource" to "could not resolve 'ource'".

Junio C Hamano has now approved the change ("Obviously the right thing to do"), confirming the patch aligns with Git's error message conventions (e.g., "unable to open '%s'") and improves clarity without functional changes. The minimal change addresses the original user confusion where the unquoted message appeared to contain a typo. With maintainer approval, this is likely to be merged into the next integration cycle. The thread demonstrates how user reports can surface small but meaningful improvements to error messaging, even for technically correct behavior.
