This is a minor code style fix in response to a closed bug report thread about `git restore` error messaging. The thread had established that the "could not resolve ource" message (from `-source` being parsed as `-s ource`) was technically correct behavior, just potentially confusing to users.

Junio C Hamano points out that while the behavior is correct, the error message formatting in `builtin/checkout.c` doesn't follow Git's CodingGuidelines for error messages, which specify that unresolved names should be quoted. The current implementation shows `die(_("could not resolve %s"), opts->from_treeish)` without quotes around `%s`, while guidelines recommend the pattern `die(_("unable to open '%s'"), path)`.

This would be a simple change to wrap the revision name in single quotes in the error message, making it clearer that "ource" is the unresolved revision rather than part of a typo. The fix would be localized to one line in `builtin/checkout.c` and would align with established error message conventions, though it wouldn't change the underlying behavior that was the original subject of the thread.
