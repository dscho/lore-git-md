Bugfix improving error messages in `git replay` when invalid commit references are provided. This is the first patch in a two-part series addressing confusing error handling in the `--onto` and `--advance` options.

Currently, when users provide an invalid commit reference (like a typo or malformed ref), `git replay` fails with the misleading message "Replaying down to root commit is not supported yet!" Kristoffer Haugsbakk's patch makes the error reporting more direct by failing immediately with a clear message like "'refs/not-valid' is not a valid commit-ish" when the commit resolution fails.

The change moves the error reporting into the `peel_committish` function where the commit resolution actually fails, rather than letting the error bubble up through the call stack. The patch includes tests verifying the new behavior for both `--onto` and `--advance` options. The author notes this also helps catch cases where users might accidentally pass arguments to `--onto` when they meant to use positional arguments.

This appears to be a straightforward improvement to user experience with minimal code changes (just 1 line modified in the core logic plus test coverage). The patch follows the thread's focus on making `git replay` error handling more precise, though it doesn't address the potentially dead code in `determine_replay_mode()` mentioned in the thread summary.
