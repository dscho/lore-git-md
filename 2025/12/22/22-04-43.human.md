Test coverage expansion for `git replay` error conditions. This is the second patch in a series addressing error handling in `git replay`, adding three new test cases to `t/t3650-replay-basics.sh` that verify proper error messages for: (1) when neither `--onto` nor `--advance` is specified (making the mandatory option requirement explicit), (2) invalid base ref cases that would trigger root commit replay (currently unsupported), and (3) conflicting usage of `--advance` and `--contained` options.

The tests follow the same pattern as existing cases in the file, capturing and comparing exact error message output. While simple, these additions systematically cover basic usage constraints that weren't previously tested. The commit message notes these are intentionally straightforward tests that could be removed if the underlying behavior changes. This complements Elijah Newren's earlier error message improvements by ensuring the expected behaviors remain stable.
