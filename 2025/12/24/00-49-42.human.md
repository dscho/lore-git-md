This is a discussion about the ongoing feature enhancement to show default branch comparisons in `git status` output. Yee Cheng Chin responds to Junio C Hamano's concerns about the hardcoded use of "upstream" and "origin" for branch comparisons, particularly in complex workflows.

Chin explains that not all users configure separate push/pull remotes for branches, especially in feature branch scenarios where collaborators need to pull from the same feature branch. They argue that even without explicit push/pull remote configuration, users may still want to see divergence from the original upstream main branch.

The response highlights real-world complexity through the example of MacVim's fork maintenance, where "upstream" can mean different things depending on context (personal fork vs. project fork vs. original Vim repository). Chin speculates that users might eventually want to compare against multiple upstream branches simultaneously, suggesting the current implementation may be too limited for complex forking scenarios.

This continues the thread's evolution from implementation details toward broader design considerations about configurability, particularly for non-standard workflows and multi-remote repositories. The discussion remains focused on finding flexible solutions that accommodate diverse use cases while maintaining the feature's utility.
