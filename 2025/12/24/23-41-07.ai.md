Feature enhancement adding default branch comparison to `git status` output, now in its final v6 iteration. This patch introduces core functionality showing divergence from the configured goal branch (now using `status.compareBranch` config key) alongside existing tracking branch status.

The implementation adds a new `format_goal_branch_comparison()` function (renamed from `format_default_branch_comparison`) in remote.c that determines the upstream's default branch through symbolic ref resolution (checking `upstream/HEAD` then `origin/HEAD`). The comparison appears on a separate line when different from tracking status, using the same ahead/behind/diverged format as existing tracking info.

Key technical aspects:
- Symbolic ref fallback chain (upstream/HEAD -> origin/HEAD)
- Single ref resolution point in `format_tracking_info()`
- Comparison only shown when different from tracking status
- Graceful handling of missing symbolic refs
- Comprehensive test coverage in t6040-tracking-info.sh
- Consolidated memory management for ref handling

The patch demonstrates thorough test coverage of various workflow scenarios:
- Branches ahead/behind/diverged from both tracking and default branches
- Preference for upstream remote when available
- Edge cases like up-to-date tracking but diverged from default
- Proper handling of different default branch names

This represents the foundational patch in the series, introducing the core comparison functionality while later patches will add configuration interface and warning systems. The implementation builds carefully on existing tracking infrastructure while adding the parallel comparison capability.
