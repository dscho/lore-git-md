Bugfix discussion regarding regression in push error reporting. Junio C Hamano confirms that the loss of specific error messages when pushing non-commit objects (reported by Elijah Newren) is indeed a regression, not an intentional change. The issue stems from commit 9d2962a7c44 which introduced batched reference updates for performance reasons, but inadvertently affected error message propagation. 

Hamano clarifies that since the change was meant to be purely a performance optimization, any behavioral changes (including the missing "trying to write non-commit object" diagnostic) should be considered bugs. This provides clear direction that the regression should be fixed rather than being treated as an intentional change in behavior.

 

The confirmation from the Git maintainer settles the open question about whether this was intentional, moving the discussion toward how to restore the original error reporting behavior while maintaining the performance benefits of batched updates. The thread now shifts from diagnosis to solution phase, with the regression clearly identified and acknowledged.
