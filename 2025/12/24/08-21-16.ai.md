Bugfix proposal expanding scope of ref transaction error reporting regression. Jeff King follows up on his earlier analysis to note the regression in error reporting for non-commit objects affects more commands than just push - it also impacts fetch and update-ref when using batched updates. The root cause traces back to the original batch reference update implementation (23fc8e4f61) rather than the later receive-pack optimization (9d2962a7c44) identified in the bisect.

Key new findings:
- Fetch operations now silently succeed in the status output while failing to update refs, only showing a generic error
- The `update-ref --batch-updates` command lacks detailed error messages for ALLOW_FAILURE cases
- The regression affects all commands using batched updates with ALLOW_FAILURE, not just push

Technical implications:
- The fix will need to address multiple command interfaces (push, fetch, update-ref)
- Machine-readable output formats may need enhancement to carry detailed errors
- Backward compatibility considerations extend beyond just the push use case

The email suggests this is a good opportunity to improve error reporting consistency across all batched update operations, though the core issue remains restoring the lost "non-commit object" diagnostic. This expands the scope of the original regression report while maintaining focus on the error message degradation.
