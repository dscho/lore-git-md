This is a bugfix patch series addressing an issue with shallow clones when the ref-in-want protocol feature is enabled. The problem has existed since ref-in-want was introduced in 2018, causing shallow clones to fail with a protocol error when uploadpack.allowRefInWant is set.

The root cause is that the server sends protocol v2 sections in the wrong order - it sends wanted-refs before shallow-info, violating both the documented protocol specification and client expectations. The fix is straightforward, just swapping two lines in upload-pack.c to correct the section ordering.

The series includes both the core fix and a new regression test that verifies shallow fetches work properly with ref-in-want enabled. The changes are minimal (just 10 lines total) and well-contained, touching only upload-pack.c and adding a new test file. The commit message clearly explains the problem and solution, and the test case should prevent future regressions. This appears to be a solid fix for a long-standing protocol compliance issue.
