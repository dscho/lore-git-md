Performance optimization patch in the `git status` goal branch comparison series (v5 2/5). This refactoring simplifies the branch comparison logic by:

1. Eliminating the `is_default_remote_branch()` helper function entirely, moving its core comparison logic inline where needed
2. Performing ref resolution just once at the start of `format_tracking_info()` rather than potentially multiple times
3. Consolidating memory management of the goal branch refs to a single pair of allocations/frees
4. Moving the goal branch comparison output to a single conditional at the end of the function rather than repeating it after each status case
5. Maintaining all existing behavior while reducing overhead

The changes focus on the internals of `remote.c`, particularly around the `format_tracking_info()` and `format_default_branch_comparison()` functions. Key technical points:

- The comparison now uses pre-resolved `default_full` and `default_short` ref names passed directly to `format_default_branch_comparison()`
- Memory management is simplified with paired allocations/frees at function entry/exit
- The comparison output is now gated by a single condition checking `upstream_is_gone`, `sti`, and `abf` states
- All test coverage from previous versions continues to pass with these internal changes

This patch represents a straightforward optimization of the v4 implementation, following through on performance opportunities identified during earlier review while keeping the user-visible behavior identical.
