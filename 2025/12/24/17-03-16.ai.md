Refactoring patch converting midx-write.c to use the new `commit_stack` infrastructure, part of the larger series standardizing dynamic commit pointer arrays.

This third patch in the 14-part series focuses on the multi-pack index bitmap writing code. It replaces manual commit array management in `midx-write.c` with the centralized `commit_stack` API, demonstrating the pattern in a more complex callback-driven scenario. The changes affect the bitmap commit collection logic, where commits are gathered during a revision walk via the `bitmap_show_commit` callback.

Key technical changes include:
- Replaces the `commits`/`commits_nr`/`commits_alloc` trio in `bitmap_commit_cb` with a single `commit_stack` pointer
- Modifies `find_commits_for_midx_bitmap()` to take a `commit_stack` parameter instead of returning an allocated array
- Updates all call sites to use stack operations (`push`, `clear`) rather than direct array management
- Maintains the same functionality while reducing code by 11 lines (23 deletions vs 12 additions)

The patch shows the series' approach working well in callback contexts, with the stack being passed through multiple layers of the midx bitmap generation code. Like previous patches, it maintains identical behavior while simplifying memory management. The changes touch the core bitmap writing path but don't affect the bitmap format or on-disk structure.

This continues the series' pattern of mechanical but impactful conversions, with René Scharfe now contributing to the effort after the initial foundation was laid. The midx subsystem conversion demonstrates the API's flexibility across different Git components.
