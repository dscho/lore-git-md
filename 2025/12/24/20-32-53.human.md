This is a documentation/UX improvement patch addressing error message formatting in `git restore`/`git checkout`. 

Brian M. Carlson follows up on a thread where a user reported confusing output when accidentally using `-source` (single dash) instead of `--source`. While the original behavior was correct (it parsed as `-s ource`), the unquoted error message "could not resolve ource" made it appear like a typo rather than showing the actual failed revision resolution.

The patch makes a simple one-line change to wrap the unresolved revision in single quotes per Git's CodingGuidelines, matching patterns like "unable to open '%s'" seen elsewhere. This produces clearer output like "could not resolve 'ource'" when similar syntax errors occur. 

The change is minimal (just adding quote marks in `builtin/checkout.c`) but improves user experience by making the error's origin more obvious. It maintains all existing functionality while better aligning with Git's message formatting conventions. The patch series context shows this was prompted by a real user report, and the solution follows established project norms.
