Feature enhancement adding configurable default branch comparison to `git status` output, now in its v4 iteration. This patch introduces core functionality for showing divergence from a project's default branch alongside the existing tracking branch status.

The implementation adds a new `get_default_remote_ref()` helper in remote.c that resolves the default branch through symbolic refs (preferring upstream/HEAD, falling back to origin/HEAD). The comparison uses existing ahead/behind tracking infrastructure but adds a new `format_default_branch_comparison()` function to display results in the same style as regular tracking info. Key technical aspects include:

- Symbolic ref resolution chain (upstream/HEAD -> origin/HEAD)
- New output format showing divergence from default branch
- Integration with existing status` output structure
- Comprehensive test coverage in t6040-tracking-info.sh for various workflow states
- The comparison appears only when different from the tracking branch
- Output examples show both tracking status and default branch divergence
- Preserves all status output formats while adding new information
- Handles edge cases like missing symbolic refs gracefully

The patch demonstrates careful attention to performance with single ref resolution at operation start and consolidated memory management. Test coverage is thorough, validating behavior in scenarios like:
- Ahead of tracking but diverged from default
- Behind tracking but ahead of default
- Up-to-date with tracking but diverged from default
- Different remote preferences (upstream vs origin)
- Various divergence states (ahead, behind, both)

This represents the core functionality that subsequent patches in the series will make configurable via `repo.settings.statusGoalBranch`. The implementation quality is high, with clear commit message explaining the workflow motivation and comprehensive test coverage validating the behavior.
