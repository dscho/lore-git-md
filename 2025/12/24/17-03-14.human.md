**Refactoring patch introducing shared commit_stack infrastructure**

This is the first patch in a 14-part series by René Scharfe that standardizes Git's handling of dynamic commit pointer arrays. The patch extracts the `commit_stack` implementation from revision.c (where it was previously a private implementation detail) and promotes it to a public API in commit.h.

The new API provides three core operations: `commit_stack_push()` to add commits, `commit_stack_pop()` to remove them, and `commit_stack_clear()` to free resources. The implementation follows Git's standard ALLOC_GROW pattern for dynamic arrays. This change alone removes 23 lines from revision.c while adding 27 lines to commit.c and commit.h - a net reduction that will compound as subsequent patches convert other subsystems to use this shared infrastructure.

The patch appears mechanically sound and well-contained, focusing solely on the API extraction without yet converting any callers. Given René Scharfe's track record with similar refactoring work and the clear motivation (eliminating widespread code duplication), this foundational change seems likely to be uncontroversial. The series as a whole promises significant codebase simplification by replacing at least 10 ad-hoc implementations with this standardized version.
