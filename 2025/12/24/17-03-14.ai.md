This is the foundational patch in a refactoring series that standardizes Git's handling of dynamic commit pointer arrays by introducing shared `commit_stack` infrastructure. The patch moves the `commit_stack` implementation from being a private helper in revision.c to a public API in commit.h/commit.c, making it available for use across Git's codebase.

The changes consist of:
1. Moving the `struct commit_stack` definition and its three core operations (`push`, `pop`, `clear`) from revision.c to commit.c
2. Adding corresponding declarations to commit.h with a new `COMMIT_STACK_INIT` macro
3. Removing the now-redundant static implementation from revision.c

The implementation remains functionally identical - it's a straightforward growable array of commit pointers using Git's standard `ALLOC_GROW` pattern. The key difference is that this common pattern will now be available to all subsystems rather than being duplicated in each place that needs commit pointer management.

This initial patch establishes the basic infrastructure that subsequent patches in the series will use to replace various ad-hoc commit array implementations throughout the codebase. The changes are mechanical and focused purely on code organization, with no behavior modifications. The patch follows Git's established patterns for similar container types and includes all three fundamental operations (push/pop/clear) needed for complete stack functionality.
