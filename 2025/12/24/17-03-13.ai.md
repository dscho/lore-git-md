This is a refactoring patch series aimed at reducing code duplication in Git's handling of dynamic arrays of commit pointers. The series standardizes on a single implementation (`commit_stack`) that was previously internal to revision.c, exporting it for wider use and adding initialization and growth helper functions.

The series touches a wide range of Git components including revision walking, logging, midx generation, name-rev, remote operations, bitmap writing, commit-graph, and test infrastructure. The changes are mechanical replacements of various local array implementations with the new shared `commit_stack` type, demonstrating significant code reduction (184 insertions vs 247 deletions across 13 files).

Key technical points for future reference:
- Introduces `commit_stack_init()` and `commit_stack_grow()` helper functions
- Replaces at least 10 different ad-hoc commit array implementations
- Affects core data structures in revision.c, commit.c, and commit.h
- Modifies performance-sensitive areas like pack-bitmap-write and commit-graph
- Includes test updates in test-reach.c to use the new infrastructure

The changes appear well-scoped and focused purely on code deduplication without altering functionality. The series follows Git's typical refactoring pattern of first exporting the shared infrastructure, then incrementally converting callers. The broad impact across multiple subsystems suggests this could be a foundational change for future maintenance.
