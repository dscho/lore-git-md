Part of the ongoing refactoring series to standardize Git's dynamic commit pointer arrays with the new `commit_stack` infrastructure.

This fifth patch in the 14-part series converts `remote.c` to use the shared `commit_stack` API for managing local commit collections during reflog traversals. The changes replace a custom `reflog_commit_array` implementation with the standardized stack operations, demonstrating the API's applicability to reflog processing workflows.

Key technical changes include:
- Removal of the entire `reflog_commit_array` struct and its helper functions (`append_commit`, `free_commit_array`)
- Conversion of `check_and_collect_until_cb_data` to store a `commit_stack*` instead of `reflog_commit_array*`
- Replacement of manual array growth with `commit_stack_push`
- Update of batch processing loop to use `arr.items` instead of `arr.item`
- Use of `commit_stack_clear` for cleanup

The patch maintains identical functionality while reducing code by 27 lines (33 deletions vs 6 additions), continuing the series' pattern of significant code simplification. This conversion shows the `commit_stack` API working effectively in the reflog context, further validating its design for commit collection scenarios beyond the initial revision.c use case. The changes touch performance-sensitive reflog traversal logic but preserve all existing behavior, including the MERGE_BASES_BATCH_SIZE optimization.
