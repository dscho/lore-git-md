Bugfix proposal expanding scope of regression in batched ref updates. Jeff King follows up on his earlier analysis of the push error reporting regression, noting the issue is more widespread than initially thought. The problem affects not just `git push` but also `git fetch` and `git update-ref --batch-updates` when they use the ALLOW_FAILURE flag with batched reference updates.

The email demonstrates how fetch operations now silently drop the specific "non-commit object" diagnostic that was present in Git 2.50.0, showing only a generic error in 2.51.0. Worse, fetch's status output no longer marks failed refs at all. The `update-ref --batch-updates` command also lacks detailed error reporting, though this isn't technically a regression since the feature is new.

King notes the root cause predates the commit found via bisect, tracing back to the original batched reference update implementation (23fc8e4f61). The email reinforces the need for a comprehensive fix that addresses all these cases while maintaining the performance benefits of batched updates. The proposed solution would need to work across push, fetch, and update-ref operations while considering both human-readable and machine-readable output formats.
