This is a bug report about a regression in error messaging when pushing non-commit objects to branch refs. Elijah Newren notes that Git versions before 2.51.0 would show a clear diagnostic message ("trying to write non-commit object...") when attempting to push a non-commit (like a tag) to a branch ref, but this helpful message disappeared after commit 9d2962a7c44 in version 2.51.0.

The error message still exists in the codebase (found in both files-backend.c and reftable-backend.c), but is no longer being displayed to users. Instead, they now see a more generic "invalid new value provided" message. Newren bisected the change to a commit that introduced batched reference updates in receive-pack, and questions whether the loss of the specific error message was intentional or an oversight.

The patch appears well-researched, with clear reproduction steps and bisect results. The change affects both ref backends (files and reftable) and the regression seems unintentional based on the commit message Newren quotes. This would be worth investigating for anyone working on the refs or receive-pack code.
