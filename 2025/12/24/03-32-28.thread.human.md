This thread addresses a regression in Git 2.51.0 where batched reference updates (used in push, fetch, and update-ref) lost detailed error messages about non-commit objects, replacing them with generic errors. The issue was first reported by Elijah Newren and confirmed by Junio C Hamano as unintentional.

Jeff King proposed a technical solution to restore detailed error messages while maintaining performance, which Karthik Nayak (the original author of the batched updates feature) has agreed to implement after the New Year's break. The fix involves modifying the ref transaction API to pass through detailed error messages consistently across both files and reftable backends.

In the latest development, Jeff King has identified a formatting issue where human-readable error messages become redundant when included in machine-readable output, as the refname gets included at multiple levels. While suggesting this could be cleaned up with careful audit of callers, he pragmatically proposes first restoring the old behavior of sending detailed errors to stderr, deferring machine-readable format improvements for later. This would quickly fix the regression while allowing more time to design a cleaner solution.

The discussion remains focused on technical tradeoffs between human-readable and machine-readable error reporting, with implementation work expected to proceed after the holiday break. Karthik Nayak remains assigned to implement the fix, with Jeff King providing detailed technical guidance on the approach.
