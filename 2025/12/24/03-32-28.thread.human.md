Elijah Newren has reported a regression in Git's error reporting when attempting to push non-commit objects to branch references. The issue affects both the traditional files backend and the newer reftable backend, where Git 2.51.0 and later show only a generic "invalid new value provided" error instead of the more specific "trying to write non-commit object" message that was present in Git 2.50.1.

The change appears to have been unintentionally introduced in commit 9d2962a7c44 ("receive-pack: use batched reference updates") from May 2025, which modified error handling for batched reference updates but didn't mention any intention to drop specific error messages. The diagnostic text still exists in both backend implementations but is no longer being surfaced to users.

This affects users who rely on the detailed error messages to diagnose push failures. The reporter is seeking clarification on whether this was an intentional change or a regression that should be fixed. The issue is particularly relevant for the reftable backend work being led by Patrick Steinhardt and Karthik Nayak, though the regression stems from changes to receive-pack's batched update handling rather than the backends themselves.
