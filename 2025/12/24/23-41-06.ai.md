Feature enhancement for `git status` showing branch divergence, now in v6 with config key rename. This series adds configurable comparison output in `git status` to show how the current branch differs from a configured "goal" branch (typically mainline). The v6 iteration renames the configuration key from `statusGoalBranch` to `status.compareBranch` based on feedback, while maintaining all functionality from v5.

The implementation builds on existing branch tracking infrastructure, adding a new comparison line when the configured goal branch differs from the tracking branch. Key technical aspects include:
- New `status.compareBranch` configuration (previously `statusGoalBranch`)
- Symbolic ref resolution fallback chain (upstream/HEAD -> origin/HEAD)
- Optimized memory management with single ref resolution point
- Comprehensive test coverage in t6040-tracking-info.sh
- Warning system for malformed configurations
- Graceful fallback for missing/misconfigured branches

The series has evolved through previous rounds addressing maintainer feedback about triangular workflows and branch naming. The v5 version was already production-ready with performance optimizations and thorough testing. This final change aligns the configuration key name with Git's conventional dotted notation while preserving all other functionality.

The feature provides a complete solution for monitoring divergence from important branches, particularly useful for workflows where developers track feature branches against a mainline. The implementation handles edge cases gracefully while maintaining efficiency through consolidated ref handling and optimized output paths.
