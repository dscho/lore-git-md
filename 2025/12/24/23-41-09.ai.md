Feature enhancement for `git status` default branch comparison configuration, part 3/6 in v6 series. This patch replaces the hardcoded upstream/origin preference chain with a configurable `repo.settings.statusGoalBranch` setting, making the comparison branch fully user-definable while maintaining graceful fallback behavior when unset.

The implementation in remote.c's `get_default_remote_ref()` now checks for the new config value first, parsing it as a remote/branch pair (e.g. "origin/main"). The function returns early if the config is unset or malformed, skipping comparison entirely in those cases. The parsing enforces a strict slash-separated format and validates the resulting ref exists before using it.

Test coverage in t6040-tracking-info.sh expands significantly to verify:
- Basic functionality with the config set to various remote/branch combinations
- Silent fallback when config is unset
- Proper handling of malformed or nonexistent branch specifications
- Integration with existing tracking info display
- Edge cases where tracking and goal branch states differ

Key technical points:
- New config key: `repo.settings.statusGoalBranch` (slash-separated remote/branch)
- Strict validation of config format (must contain exactly one slash)
- Complete fallback to traditional behavior when unset/invalid
- Maintains all prior optimization work from earlier series patches
- Adds 7 new test scenarios covering config variations

This patch represents the configuration interface finalization for the feature, following Junio's earlier guidance to use existing branch config patterns. The implementation cleanly separates the config parsing from the comparison logic while preserving the performance characteristics established in part 2/6 of the series.
