This is a performance optimization patch in the v4 series adding configurable branch comparison to `git status`. It simplifies the default branch comparison logic while maintaining the same functionality.

The key changes in this patch:
- Eliminates the `is_default_remote_branch()` helper function entirely
- Moves the default branch ref resolution to happen once at the start of `format_tracking_info()`
- Passes the resolved refs directly to `format_default_branch_comparison()`
- Consolidates all memory management for default branch refs
- Reduces ref resolution calls from multiple to one per status operation
- Maintains identical output while reducing overhead

The patch demonstrates careful attention to performance by:
- Removing redundant ref lookups
- Eliminating duplicate memory allocations/frees
- Keeping the comparison logic centralized
- Preserving all existing behavior while being more efficient

This builds on the thread's established approach of using symbolic refs (upstream/HEAD -> origin/HEAD) for default branch determination, now with optimized resolution. The changes align with Junio C Hamano's guidance about using existing branch configuration mechanisms while improving efficiency.

- Memory management consolidation
- Single-point ref resolution
- Preserved output structure
- Maintained test coverage from previous patches
- No behavior changes despite internal restructuring
