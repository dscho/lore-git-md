Bugfix targeting the reftable backend and push error reporting. This email reports a regression where Git no longer shows the specific "trying to write non-commit object" diagnostic message when attempting to push non-commit objects to refs/heads/* references. The change appears to have been introduced in commit 9d2962a7c44 ("receive-pack: use batched reference updates") from May 2025.

The reporter, Elijah Newren, provides clear reproduction steps showing the difference in behavior between Git 2.50.1 (which showed the detailed error) and 2.51.0 (which shows only a generic "invalid new value provided" message). The diagnostic message still exists in the codebase (found in both files-backend.c and reftable-backend.c) but is no longer being displayed to users.

The email suggests this might be unintentional based on the commit message of 9d2962a7c44, which mentioned changes to error handling being necessary for batched reference updates but didn't indicate any intention to drop specific error messages. The reporter is asking whether this was an intentional change or a regression should be fixed.

Key technical details include the specific error message text that's missing, the commit that introduced the change (9d2962a7c44), and the affected versions (behavior changed between 2.50.1 and 2.51.0). The issue appears to affect both files and reftable backends, though the regression was introduced through changes to receive-pack's batched reference update handling.
