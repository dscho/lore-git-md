This is a small bugfix improving error message clarity in `git restore`. The patch wraps an unresolved treeish in single quotes when reporting errors, changing output like "could not resolve ource" to "could not resolve 'ource'".

The change comes from a user report where someone mistakenly used `-source` (single dash) instead of `--source`, causing Git to parse it as `-s ource`. While the original behavior was technically correct, the unquoted error message made it appear like a typo in Git's code rather than a user syntax error.

Junio Hamano has reviewed and approved the one-line change to `builtin/checkout.c`, calling it "obviously the right thing to do". The patch maintains the same underlying behavior while better following Git's CodingGuidelines for error message formatting. It's a straightforward improvement that makes the error output more immediately understandable when users make this particular mistake.

The fix is minimal and low-risk, touching only the message formatting without any functional changes. It demonstrates how user reports can lead to small but meaningful quality-of-life improvements in Git's interface.
