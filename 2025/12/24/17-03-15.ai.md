Refactoring patch converting `builtin/log.c` to use the new `commit_stack` infrastructure for managing commit arrays.

This is the second patch in a 14-part series standardizing Git's handling of dynamic commit pointer arrays. It modifies the format-patch command to use the shared `commit_stack` API instead of its previous manual array management with `REALLOC_ARRAY`. The changes are mechanical but demonstrate the benefits of the new approach - simpler push/pop operations replace explicit index calculations, and memory management is handled automatically via `commit_stack_clear()`.

Key technical changes:
- Replaces `struct commit **list` with `struct commit_stack list = COMMIT_STACK_INIT`
- Swaps `REALLOC_ARRAY`/manual counting for `commit_stack_push()`
- Converts reverse iteration to use `commit_stack_pop()` instead of manual index calculation
- Updates all array access sites to use `list.items[]` instead of raw pointer
- Maintains identical functionality while reducing LOC (15 insertions vs 16 deletions)

The patch affects format-patch's core commit processing logic but doesn't change user-visible behavior. It demonstrates the series' value by simplifying a complex area of the codebase while maintaining the same performance characteristics. The conversion appears thorough and correctly handles all edge cases in the command's commit processing pipeline.
