This is a follow-up review of the whitespace check patch series, specifically addressing the implementation of the `tab-between-non-ws` feature. Junio Hamano points out that while the core detection logic and test coverage are solid, the patch is incomplete in two key areas:

1. The colored diff output doesn't properly highlight the detected tab-between-non-ws violations (needs BG_RED highlighting via `diff_colors[]` and likely a new helper function)
2. The whitespace fixing functionality (`git apply --whitespace=fix`) doesn't yet handle converting these tabs to spaces

The review also clarifies the intended behavior around edge cases:
- Confirms that tabs at end-of-line should not be flagged by this check (those are handled by trailing-whitespace)
- Suggests improving the commit message to better explain the false positive avoidance (tabs that expand to multiple spaces)

The implementation currently in `ws.c` correctly detects tabs between non-whitespace when they would expand to a single space (at columns 7, 15, etc. for 8-space tabs), with comprehensive test coverage. This appears to be the final round of review before the feature can be considered complete, pending these two additional implementation pieces.
