This is a feature patch adding PID file support for debugging stale locks in Git. It's the third version of a series that has seen significant discussion about implementation details like naming conventions and Windows compatibility.

The patch introduces an optional feature that creates companion PID files alongside lock files (e.g. `index~pid.lock` next to `index.lock`) containing the process ID of the lock holder. The tilde separator was chosen to avoid refname collisions while remaining Windows-compatible. When lock conflicts occur, Git can now provide more helpful error messages indicating whether the holding process is still running or if the lock is stale.

The feature is controlled via a new `core.lockfilePid` config that follows the same pattern as `core.fsync`, allowing per-component control (index, config, refs, etc.). The implementation includes thorough test coverage and handles edge cases like abnormal termination via tempfile registration.

Key changes in v3:
- Switched from hyphen to tilde separator in PID filenames to guarantee no namespace collisions
- Maintained opt-in behavior with default `core.lockfilePid=none`
- Added comprehensive tests covering various config scenarios

The patch appears well-constructed with careful attention to cross-platform compatibility and edge cases. It addresses a real pain point in debugging lock issues while being minimally invasive through its opt-in design. The extensive test suite and documentation additions suggest this is production-ready.
