Refactoring patch converting Git's remote tag synchronization to use the new `commit_stack` API, part 7/14 in the standardization series.

This patch continues the mechanical conversion of commit pointer array management to the shared `commit_stack` infrastructure, this time targeting the tag synchronization logic in `remote.c`. The changes replace a manually managed array in `add_missing_tags()` with stack operations, following the same conversion pattern seen in previous patches. Key technical points include:

- Replaces `ALLOC_ARRAY`/`ALLOC_GROW` pattern with `COMMIT_STACK_INIT` and `commit_stack_push`
- Updates `get_reachable_subset()` call to use stack's `items` and `nr` fields
- Converts cleanup from direct `free()` to `commit_stack_clear()`
- Maintains existing reachability marking behavior via `clear_commit_marks_many`

The conversion demonstrates the API's suitability for networking code paths, with the expected reduction in manual memory management code (7 insertions vs 8 deletions). As with previous patches, this maintains all existing functionality while eliminating custom array growth logic.
