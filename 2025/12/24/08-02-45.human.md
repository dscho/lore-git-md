This is part of the ongoing macOS character encoding conversion fix series, specifically the Homebrew configuration portion. The patch simplifies how Git finds and uses Homebrew-installed gettext tools on macOS, making the behavior more configurable while reducing potential side effects.

René Scharfe's patch introduces two new Makefile variables: NO_HOMEBREW to disable Homebrew integration entirely, and HOMEBREW_PREFIX to specify non-standard installation locations. The key improvement is switching from directly including Homebrew's prefix (which could pull in unwanted libraries) to specifically targeting just the gettext installation via Homebrew's standard opt/gettext symlink.

The changes maintain compatibility with both Intel (/usr/local) and ARM (/opt/homebrew) Macs while removing some now-unnecessary workarounds. The patch represents the consensus from prior discussion, implementing Carlo Marcelo Arenas Belón and Torsten Bögershausen's suggestions for cleaner Homebrew integration. This is a well-considered change that should make macOS builds more reliable while giving users clearer control over Homebrew usage.
