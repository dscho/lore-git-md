This is the final patch in a v3 series adding configurable default branch comparison to `git status`. The feature allows users to specify which remote branch to compare against via a new `repo.settings.statusGoalBranch` config option, replacing the previous hardcoded preference for upstream/origin.

The patch makes the default branch comparison fully configurable, with the comparison being skipped entirely when the config is unset. The implementation:
- Modifies `get_default_remote_ref()` to read from `repo.settings.statusGoalBranch` instead of hardcoded remote names
- Validates the config value contains a valid remote/branch format
- Falls back gracefully when the config is unset or invalid
- Adds comprehensive test coverage for various config states (unset, valid, invalid, non-existent branch)

Key technical details:
- Config format must be "remote/branch" (e.g. "origin/main")
- Invalid or missing config silently disables the feature
- The comparison uses the same ahead/behind infrastructure as regular tracking info
- Tests verify behavior with config unset, set to valid branches, and set to non-existent branches

The patch builds on previous optimizations in the series while making the feature more flexible. It addresses earlier concerns about hardcoded assumptions by making the comparison target fully configurable. The implementation maintains all performance improvements from previous versions while adding this configurability.

The extensive test coverage demonstrates all edge cases, including:
- Config unset (no comparison shown)
- Config set to valid remote/branch
- Config set to non-existent branch (silently ignored)
- Different remote/branch combinations

This completes the feature's evolution from initial proposal to a configurable, optimized implementation that respects Git's existing configuration mechanisms.
