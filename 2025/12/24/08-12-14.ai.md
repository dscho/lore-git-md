Bugfix proposal for restoring detailed error messages in batched reference updates, addressing the regression in push error reporting for non-commit objects.

Jeff King analyzes the regression where specific error messages (like "trying to write non-commit object") are no longer shown during batched reference updates, despite still being generated internally. The issue stems from commit 9d2962a7c44 which introduced batched updates but didn't properly propagate the detailed error strings through the new error handling path.

The proposed changes involve modifying the ref transaction API to:
1. Pass detailed error messages through `ref_transaction_maybe_set_rejected()` by adding a `details` parameter
2. Store these details in the `ref_update` struct via a new `rejection_details` field
3. Extend `ref_transaction_for_each_rejected_update_fn` callback to receive the details string
4. Update all backend implementations (files, packed, reftable) to pass through error messages

The patch demonstrates this with receive-pack outputting details via `rp_error()`, but notes several limitations:
- Memory management issues (leaking detail strings)
- Incomplete coverage of all error cases
- Questions about whether to include details in machine-readable output

Key technical points for future discussion:
- The changes touch core refs infrastructure across multiple files
- New string handling in `ref_update` struct needs proper memory management
- Tradeoffs between human-readable sideband output vs machine-readable ref status
- Backward compatibility considerations for existing callers of the ref transaction interfaces

The patch serves as a starting point, with Jeff King suggesting Karthik Nayak (original author of the batched updates) should likely take over the final implementation.
