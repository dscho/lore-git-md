Refactoring patch adding a growth helper function to the `commit_stack` API series.

This twelfth patch in the 14-part series introduces `commit_stack_grow()` as a new public API function, allowing callers to pre-allocate capacity when they know how many commits they'll need to store. The change factors out the growth logic from `commit_stack_push()` into this new function, then makes push use it with a count of 1. The implementation remains based on the existing `ALLOC_GROW` macro but provides more direct control over capacity planning.

The patch follows the series' pattern of incrementally building out the `commit_stack` interface while maintaining behavioral consistency. This addition is particularly useful for cases where the caller can predict the required capacity in advance, potentially reducing reallocations. The change is minimal (7 lines net) and touches only the core commit infrastructure files (`commit.c` and `commit.h`), with no test modifications needed since it doesn't alter behavior.
