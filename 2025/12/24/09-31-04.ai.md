Performance optimization patch in the configurable branch comparison series for `git status`. This is the second of three patches in v3, focusing on streamlining the default branch comparison logic while maintaining the same functionality.

The patch simplifies the implementation by:
- Moving ref resolution for the default branch to a single call at the start of `format_tracking_info()`
- Eliminating redundant memory allocations and frees that were previously done in helper functions
- Consolidating the default branch comparison check into the main flow rather than separate functions
- Maintaining all existing output formats and conditions while reducing overhead

Key technical changes include:
- Removal of `is_default_remote_branch()` helper function
- Modification of `format_default_branch_comparison()` to take pre-resolved refs as parameters
- Single resolution of default_full/default_short at start of format_tracking_info()
- More efficient conditional logic for when to show the default branch comparison
- Preserved test coverage from previous versions

The optimization reduces the number of ref resolution calls from multiple to one per status operation and eliminates several memory allocation/free cycles. The patch maintains all functionality from v2 while being more efficient, addressing performance concerns raised earlier in the thread. The changes follow the established pattern of using existing branch configuration rather than making assumptions about remote names.
