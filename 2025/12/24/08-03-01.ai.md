This is a platform compatibility patch addressing macOS-specific character encoding issues, part of René Scharfe's v4 series to work around Apple's problematic iconv implementation. The patch implements the Homebrew-based solution path that was previously discussed in the thread, specifically:

1. Introduces `USE_HOMEBREW_LIBICONV` flag to explicitly opt into using Homebrew's libiconv when needed (for macOS 24+)
2. Automatically detects Homebrew's default locations (/opt/homebrew for ARM64, /usr/local for Intel)
3. Maintains user override capability via existing `ICONVDIR` while adding new path resolution logic
4. Adds version detection to activate the workaround only on affected macOS versions (24+)
5. Updates documentation to reflect the new build variables and their purpose

The changes are focused on the Makefile and config.mak.uname, with careful attention to:
- Backward compatibility (preserving existing `ICONVDIR` behavior)
- Architecture awareness (different default paths for ARM64 vs Intel)
- Version specificity (only enabling workaround for affected macOS versions)
- Documentation clarity (explaining new variables and their relationships)
