Feature enhancement for configurable branch comparison in `git status`, part 3/4 of the series. This patch introduces the `repo.settings.statusGoalBranch` configuration option to replace the hardcoded upstream/origin preference for default branch comparison in status output. When unset, the feature is disabled entirely.

The implementation modifies `get_default_remote_ref()` to read the new config value instead of using a static list of remotes. The config expects a "remote/branch" format (like "origin/main") and validates this strictly - invalid formats or non-existent branches silently disable the feature. The patch includes comprehensive test coverage showing various valid and invalid configurations, including cases where the goal branch exists or doesn't exist, different remote/branch combinations, and the unset state.

Key technical details: The config lookup happens once at function start, with proper memory management via `strbuf`. The ref resolution follows the same pattern as before but uses the configured target. Invalid configurations (missing slash, empty values) return NULL to skip the comparison. Test cases demonstrate the config's effect on status output in various workflow states - ahead/behind tracking but diverged from goal branch, up-to-date with tracking but diverged from goal, and cases where the goal branch doesn't exist.

This builds on the v4 series' optimizations by maintaining the single ref resolution point while adding configurability. The implementation respects earlier maintainer feedback about using existing branch configuration mechanisms rather than making assumptions about remote names. Test coverage remains thorough, now including config behavior scenarios.
