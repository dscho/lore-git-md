Performance optimization patch in the `git status` branch comparison feature series. This is part 2/6 of v6, which finalizes the configuration interface for showing divergence from a configured goal branch (now using `status.compareBranch` as the config key).

The patch simplifies the default branch comparison logic in `remote.c` by:
1. Moving ref resolution for the default branch to a single point in `format_tracking_info()` rather than doing it repeatedly
2. Eliminating redundant memory allocations and frees by passing the resolved refs to `format_default_branch_comparison()`
3. Consolidating the comparison output to happen once at the end of `format_tracking_info()` rather than at multiple points
4. Maintaining all existing functionality while reducing ref lookups and memory operations

Key technical changes:
- Removes `is_default_remote_branch()` helper function
- Modifies `format_default_branch_comparison()` to take pre-resolved refs as parameters
- Restructures `format_tracking_info()` to handle default branch resolution once
- Preserves all existing output formats and warning behaviors
- The optimization builds on the series' earlier work to show parallel comparison between tracking branch and configured goal branch
- Changes are purely internal - no user-visible behavior differences
- Maintains all test coverage from previous versions
- Follows Junio C Hamano's guidance on using existing branch config infrastructure

This represents a clean-up pass on the core comparison logic after establishing the feature's behavior in earlier patches. The changes demonstrate good attention to performance in the feature's hot path while keeping the functionality intact.
