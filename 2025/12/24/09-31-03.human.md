Feature enhancement adding default branch comparison to `git status` output, part of a v3 series introducing configurable target branch comparison. This first patch implements the core functionality to show how the current branch compares to the project's default branch (typically main/master) in addition to the existing tracking branch comparison.

The patch adds a new `get_default_remote_ref()` function in remote.c that determines the default branch by checking symbolic refs in this order: first `upstream/HEAD`, then falling back to `origin/HEAD`. The comparison uses the same ahead/behind/diverged format as the existing tracking branch status, appearing on a new line when applicable. For example, a feature branch might show both "Ahead of 'origin/feature' by 2 commits" and "Ahead of 'origin/main' by 5 commits".

The implementation is thorough, handling various workflow cases through extensive new test coverage in t6040-tracking-info.sh. Tests verify behavior for branches that are: ahead of tracking but diverged from main, behind tracking but ahead of main, up-to-date with tracking but diverged from main, and other combinations. The tests also confirm the upstream/HEAD fallback behavior.

This appears to be a well-considered implementation that addresses the original use case of monitoring drift from a project's mainline while maintaining all existing functionality. The code follows Git's established patterns and includes comprehensive tests. The v3 iteration has incorporated feedback from earlier rounds about remote handling and configuration.
