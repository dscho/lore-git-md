This is a bugfix patch addressing a protocol violation in Git's upload-pack when the ref-in-want feature is enabled. The patch corrects the section ordering in protocol v2 responses to match the documented specification.

The core issue stems from an incorrect ordering of protocol sections in upload-pack.c when both shallow cloning and ref-in-want are active. Since 2018, the server has been sending wanted-refs before shallow-info, contrary to the protocol specification in gitprotocol-v2.adoc. This causes fetch-pack to fail with an error about unexpected section ordering.

The fix is minimal - just swapping two lines in upload-pack.c to call send_shallow_info() before send_wanted_ref_info(). This aligns with both the documented protocol and client expectations. The change affects the interaction between upload-pack and fetch-pack when uploadpack.allowRefInWant is enabled during shallow operations.

Key technical details for future reference:
- Bug manifests when both shallow clone/fetch AND uploadpack.allowRefInWant=true
- Protocol violation in upload-pack.c section ordering (wanted-refs before shallow-info)
- Client (fetch-pack.c) expects shallow-info first per gitprotocol-v2.adoc
- Fix: swap two lines in upload-pack.c to correct section order
