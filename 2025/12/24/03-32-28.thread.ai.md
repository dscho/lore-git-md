Thread identity: Bug report about regression in error reporting for non-commit objects when using batched reference updates, affecting push, fetch, and update-ref commands across both files and reftable backends. Originated from Elijah Newren.

Core problem: Git 2.51.0 silently regressed detailed error reporting ("trying to write non-commit object") in favor of generic messages ("invalid new value provided") when pushing non-commit objects to refs/heads/*. The issue extends to fetch and update-ref --batch-updates with ALLOW_FAILURE, where operations can silently fail in status output. Root cause traces to the original batch reference update implementation (23fc8e4f61).

Current status: Regression confirmed by Junio C Hamano as unintentional. Jeff King proposed a fix modifying the ref transaction API to restore detailed error messages while maintaining batched update performance. Karthik Nayak has agreed to implement this after New Year's break. New discussion reveals redundancy issues in error message formatting when propagating through ref transaction layers.

Key technical details: The regression stems from batched reference updates losing error context. The agreed approach involves:
- Adding `details` parameter to `ref_transaction_maybe_set_rejected()`
- Storing details in `ref_update` via new `rejection_details` field
- Extending callback to receive details string
- Updating all backends (files, packed, reftable) to pass through error messages
Jeff King now identifies redundant refname information in error message construction, particularly between write_ref_to_lockfile() and lock_ref_for_update(). For immediate regression fix, he suggests initially restoring old stderr behavior for detailed errors while deferring machine-readable format cleanup.

Open questions: 
- Final implementation details for memory management of error strings
- How to handle redundant refnames in error message construction
- Whether to initially defer machine-readable output changes
- Scope of changes needed for fetch and update-ref interfaces
Implementation now assigned to Karthik Nayak (original batched updates author), with work planned after New Year's break.
