Thread identity: Bug report about regression in push error reporting for non-commit objects when using batched reference updates, affecting both files and reftable backends. Originated from Elijah Newren.

Core problem: Git 2.51.0 no longer shows the specific "trying to write non-commit object" diagnostic when pushing non-commit objects to refs/heads/* references, instead showing a generic "invalid new value provided" message. This appears to be a regression from 2.50.1 behavior.

Current status: Regression identified between Git 2.50.1 (working) and 2.51.0 (broken). The diagnostic message still exists in both files-backend.c and reftable-backend.c but is not being displayed to users. The change was introduced in commit 9d2962a7c44 ("receive-pack: use batched reference updates") from May 2025.

Key technical details: The missing error message is specifically about rejecting non-commit objects being pushed to refs/heads/* references. The regression affects the error reporting path in receive-pack's batched reference update handling, though the underlying validation still occurs in both backend implementations.

Open questions: Whether this change was intentional (not indicated in commit 9d2962a7c44's message) or a regression that should be fixed. The reporter suggests it may be unintentional based on the commit's stated purpose.

Participant positions: Elijah Newren reported the regression with clear reproduction steps and analysis suggesting it may be unintentional. No other participants yet.
