Thread identity: Bug report about regression in push error reporting for non-commit objects when using batched reference updates, affecting both files and reftable backends. Originated from Elijah Newren.

Core problem: Git 2.51.0 no longer shows the specific "trying to write non-commit object" diagnostic when pushing non-commit objects to refs/heads/* references, instead showing a generic "invalid new value provided" message. This is confirmed to be an unintentional regression from 2.50.1 behavior, as the change was meant to be purely a performance optimization.

Current status: Regression confirmed by Junio C Hamano as unintentional. Jeff King has proposed a fix that modifies the ref transaction API to restore detailed error messages while maintaining batched update performance. The proposal needs refinement around memory management and error case coverage.

Key technical details: The regression was introduced in commit 9d2962a7c44 ("receive-pack: use batched reference updates"). Jeff King's proposal involves:
- Adding a `details` parameter to `ref_transaction_maybe_set_rejected()`
- Storing details in `ref_update` via new `rejection_details` field
- Extending callback to receive details string
- Updating all backends (files, packed, reftable) to pass through error messages
Current limitations include memory management of detail strings and incomplete error case coverage.

Open questions: 
- How to properly manage memory for error detail strings
- Whether to include details in machine-readable output
- Tradeoffs between human-readable sideband vs machine-readable ref status
- Backward compatibility for existing ref transaction interface users
Jeff King suggests Karthik Nayak (original batched updates author) should likely finalize the implementation.

Participant positions: Elijah Newren reported the regression. Junio C Hamano confirmed it was unintentional. Jeff King has proposed a technical solution but notes it needs refinement, suggesting Karthik Nayak take over the final implementation. No other participants have weighed in yet.

Related work: The regression stems from performance optimizations in batched reference updates (9d2962a7c44) which affected error reporting paths. The fix will need to work consistently across both files and reftable backends.
