Performance optimization patch in the configurable branch comparison series for `git status`. This is the second of four patches in v4 of the series, which adds the ability to show how a branch compares to a project's default branch (configurable via `repo.settings.statusGoalBranch`).

The patch simplifies the default branch comparison logic by:
- Eliminating the redundant `is_default_remote_branch()` helper function
- Moving ref resolution to a single call at the start of `format_tracking_info()`
- Passing the resolved refs directly to `format_default_branch_comparison()`
- Consolidating memory management for default branch refs
- Only performing the comparison once at the end rather than at multiple points

The changes maintain all existing functionality while reducing overhead - a key consideration since `git status` runs frequently. The implementation now resolves the default branch reference just once per status operation rather than potentially multiple times, and eliminates several memory allocations/frees that were happening in the comparison path.

This continues the series' trend of performance-conscious implementation while keeping the configurable comparison feature flexible. The changes are straightforward refactoring with no behavior changes, building on the core functionality established in earlier patches.
