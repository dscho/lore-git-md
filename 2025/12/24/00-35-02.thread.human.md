The thread discusses a bug in Git's upload-pack that causes shallow clones to fail when the ref-in-want protocol feature is enabled. This issue has existed since ref-in-want was introduced in 2018. The problem occurs because upload-pack sends protocol sections in the wrong order (wanted-refs before shallow-info), violating the documented protocol specification and causing clients to fail with a "fatal: expected 'packfile', received 'shallow-info'" error.

Matthew Dodd originally reported the issue, and Patrick Steinhardt has confirmed the bug and proposed a solution. The fix is minimal - just swapping two lines in upload-pack.c to correct the section ordering. A regression test has also been provided that verifies the fix by creating a shallow clone with ref-in-want enabled and checking the remote ref points to the correct commit.

Patrick suggests combining the fix and test into a single patch since the test directly verifies the fix's correctness. The solution appears straightforward and well-justified, addressing a long-standing protocol violation that affects a specific but valid combination of features (shallow clone + ref-in-want). No objections or additional concerns have been raised so far.
