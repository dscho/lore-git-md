This is part 3/5 of a feature series adding configurable branch comparison to `git status` output. The patch implements the core configuration mechanism via `repo.settings.statusGoalBranch`, replacing the previous hardcoded preference for upstream/origin branches.

The main change is in `get_default_remote_ref()` (which will be renamed in a later patch), where it now checks the config value first. If unset or invalid, it skips the default branch comparison entirely. The config expects a "remote/branch" format and validates this strictly. The patch includes extensive set of test cases showing the behavior with:
- Config unset (shows only tracking branch status)
- Valid remote/branch configurations
- Non-existent branch targets (silently falls back)
- Different remote preferences overriding origin/upstream

This builds on previous discussion that established the configurable approach is preferable to hardcoded behavior. The implementation is clean separation of concerns - the config handling is self-contained and the comparison logic remains unchanged. Test coverage is thorough, verifying both the happy path and edge cases.

For users who want to monitor divergence from important branches (like mainline), this provides flexible configuration while maintaining clean output when the feature isn't configured. The silent fallback for invalid configs keeps the status output reliable even with misconfiguration.
