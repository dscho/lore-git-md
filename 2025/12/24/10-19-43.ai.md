This is the v4 iteration of a feature enhancement to `git status` that shows configurable branch comparisons, now with a naming refinement. The series has evolved through previous rounds addressing performance, configurability, and workflow concerns, and this version focuses on final terminology cleanup.

The patch series introduces a new `repo.settings.statusGoalBranch` configuration to specify which branch `git status` should compare against when showing divergence information. The implementation reuses Git's existing ahead/behind tracking infrastructure while adding flexibility through configurable comparison targets. The v4 changes rename internal variables from "default_remote" to "goal_branch" to better reflect the configurable nature of the feature.

Key technical aspects carried forward from v3 include optimized ref resolution (now done once per status operation), comprehensive test coverage in t6040-tracking-info.sh, and graceful handling of various workflow states. The implementation preserves backward compatibility while allowing users to track divergence from any specified remote/branch combination.

The new naming in v4 better aligns with the feature's configurable nature, where the comparison target is no longer assumed to be a default remote branch but rather any user-specified goal branch. This change doesn't affect functionality but improves code clarity. The series maintains all previous optimizations that reduced overhead for frequent status operations.
