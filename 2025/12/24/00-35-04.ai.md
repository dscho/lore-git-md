Test patch adding coverage for shallow fetch with ref-in-want protocol feature. This is the second patch in a two-part series fixing a protocol violation where upload-pack sent sections in the wrong order when both shallow clone and ref-in-want were enabled.

The test verifies that a shallow clone (--depth=1) succeeds when the server has uploadpack.allowRefInWant enabled, which previously failed with "fatal: expected 'packfile', received 'shallow-info'" due to incorrect section ordering. The test creates a shallow clone and verifies the remote ref points to the expected commit.

The test case is minimal but sufficient - it exercises the problematic combination of features without additional complexity. It follows the pattern of existing tests in t5703-upload-pack-ref-in-want.sh, adding the new case at the end of the file. The test setup uses standard Git test infrastructure (test_expect_success, test_cmp) and cleans up after itself with test_when_finished.

This patch complements the one-line fix in upload-pack.c from the first patch, providing regression protection for the combination of shallow clones and ref-in-want that was previously untested. The commit message clearly explains what failure it guards against and references the protocol violation fixed in the series.
