This is patch 11/14 in the ongoing `commit_stack` refactoring series, converting the shallow.c subsystem to use the new shared infrastructure for managing commit pointer arrays. The patch follows the established pattern of replacing manual array management with the standardized API, demonstrating its applicability to yet another core Git component.

The changes focus on the shallow clone functionality, where commit arrays are used for tracking reachability during shallow operations. The patch eliminates the custom `commit_array` struct and its manual `ALLOC_GROW` usage, replacing them with `commit_stack` operations. Key technical changes include initializing the stack in `prepare_shallow_info`, using `commit_stack_push` in the `add_ref` callback, and updating reachability checks to use the stack's `items` and `nr` fields. The `delayed_reachability_test` path is simplified by storing the stack directly in the `shallow_info` struct rather than managing separate commit pointer and count fields.

This conversion maintains the exact same behavior while reducing code complexity, removing 29 lines while adding 19 (net -10). The changes touch both shallow.c and shallow.h, with the latter gaining a new `commit.h` include to access the `commit_stack` type. As with previous patches in the series, no test modifications are needed since the behavior remains identical. The work continues the trend of demonstrating the API's versatility across different subsystems while consistently reducing code duplication.
