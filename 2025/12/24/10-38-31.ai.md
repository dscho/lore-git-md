Feature enhancement adding default branch comparison to `git status` output, now at v5. This is the core implementation patch in a series that helps developers monitor divergence from important branches.

The patch introduces a new comparison line in `git status` output that shows how the current branch differs from the project's default branch (typically main/master), in addition to the existing tracking branch comparison. The default branch is determined via symbolic refs (first checking upstream/HEAD, then origin/HEAD). The comparison uses the same ahead/behind/diverged format as the tracking branch status.

Key technical components in this patch:
- New `get_default_remote_ref()` helper in remote.c resolves the default branch via symbolic refs
- `is_default_remote_branch()` checks if current tracking branch is already the default
- `format_default_branch_comparison()` generates the new status line when needed
- Integration with existing `format_tracking_info()` ensures the comparison only appears when different from tracking status
- Comprehensive test coverage in t6040-tracking-info.sh verifies various workflow scenarios:
  - Ahead of both tracking branch and default branch
  - Diverged from default while tracking another branch
  - Up-to-date with tracking branch but diverged from default
  - Preference for upstream/HEAD over origin/HEAD when available

The implementation builds on existing branch tracking infrastructure and maintains performance by:
- Reusing ahead/behind calculation logic
- Only performing default branch lookups when needed
- Consolidating memory management for ref lookups

This represents the core functionality that subsequent patches in the series will build upon with configuration options and warning systems. The approach follows maintainer guidance to work within Git's existing branch configuration system rather than introducing new concepts.
