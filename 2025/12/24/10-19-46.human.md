Feature enhancement for `git status` output, part 4/4 of a series adding configurable branch comparison. This patch introduces the `repo.settings.statusGoalBranch` configuration option to specify which branch should be used for the "diverged from" comparison in status output, replacing the previous hardcoded preference for upstream/origin.

The implementation validates the config format (requiring "remote/branch" syntax) and silently skips the comparison if the config is unset or invalid. The patch includes extensive test coverage showing the config's effect in various workflow states - when the branch exists, when it doesn't, and when the config is unset. The tests demonstrate that the feature gracefully handles edge cases while maintaining the expected status output structure.

This represents the final piece of the configurable branch comparison feature, following earlier discussion about triangular workflows and remote naming conventions. The implementation addresses previous concerns by making the comparison target fully configurable rather than making assumptions about remote names. The tests verify that the feature works as expected when configured, and quietly disappears when not configured, maintaining backward compatibility.
