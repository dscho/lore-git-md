This is part of the ongoing macOS character encoding conversion fix series, specifically addressing Homebrew configuration. The patch simplifies and makes configurable the use of Homebrew-installed gettext tools on macOS, implementing changes discussed in the thread.

The changes focus on two main aspects: First, it introduces new Makefile variables `NO_HOMEBREW` and `HOMEBREW_PREFIX` to control Homebrew installations, replacing previous hardcoded paths. Second, it consolidates the Homebrew path handling to use `/opt/homebrew` for ARM64 and `/usr/local` for Intel by default, while still allowing overrides. The patch removes several now-unnecessary flags and conditions while maintaining the same functionality.

Key technical details include the simplified path resolution through `HOMEBREW_PREFIX/opt/gettext` for includes and libraries, with checks for directory and executable existence. The changes reflect the consensus from the thread discussion, particularly implementing Torsten Bögershausen's suggestion to simplify flags and Carlo Marcelo Arenas Belón's focus on Homebrew integration.

The patch maintains backward compatibility while providing more flexibility in Homebrew usage. It's part of the broader solution to macOS's iconv issues, though this specific change focuses on the build system configuration rather than the core encoding problem. The implementation appears clean and aligns with the thread's direction, with the remaining open questions about non-Homebrew package managers being addressed separately.
