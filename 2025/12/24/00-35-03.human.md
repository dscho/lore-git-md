Bugfix addressing a long-standing protocol violation in Git's shallow clone functionality when the ref-in-want feature is enabled. This is the first patch in a two-part series.

The patch corrects the order in which upload-pack sends protocol v2 sections during a fetch operation. Since 2018, when ref-in-want was introduced, the server has incorrectly sent wanted-refs before shallow-info, violating the documented protocol specification. This causes shallow clones to fail with a protocol error when ref-in-want is enabled on the server.

The fix is straightforward - swapping two lines in upload-pack.c to send sections in the correct order (shallow-info first, then wanted-refs). The commit message clearly explains the change with reference to both the protocol documentation and the actual client error that occurs. The patch appears well-researched, with a clear connection made between the specification violation and the observable failure case.

This is a minimal change (just two lines modified) that fixes a real bug affecting users who enable ref-in-want. The patch series includes a follow-up test case to prevent regression. Given the clear specification violation and straightforward fix, this seems likely to be accepted with minimal discussion.
