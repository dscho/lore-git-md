This is part 5/6 of the feature series adding configurable branch comparison to `git status`. The patch focuses on user feedback and test improvements for the `repo.settings.statusGoalBranch` configuration.

The main change adds a warning when the `statusGoalBranch` config has invalid format (not containing exactly one slash), causing the goal branch comparison to be skipped. This improves user experience by making configuration errors visible rather than silently failing.

The patch also updates the test suite to verify full `git status` output rather than grepping for specific lines. This provides more thorough verification of the output format and ensures the "nothing to commit" line is properly included in all cases. The test changes show the complete status output for various scenarios including:
- Divergence from both tracked and goal branches
- Different combinations of ahead/behind states
- Handling of nonexistent goal branches
- Cases where goal branch matches tracking branch

The tests now explicitly verify the full output format including the working tree status line, which was previously being stripped by `head` commands. This provides stronger guarantees about the output formatting and ensures no regressions in the complete status display.

This patch builds on the v6 series' optimizations while adding user-facing improvements, maintaining the thread's focus on both performance and usability. The warning system complements the earlier strict format validation added for the `statusGoalBranch` configuration.
