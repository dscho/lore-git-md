This is a refactoring patch series aimed at reducing code duplication in Git's handling of dynamic arrays of commit pointers. René Scharfe identifies over ten different implementations of this pattern across the codebase and proposes consolidating them under a single `commit_stack` implementation.

The 14-part series first exports an existing `commit_stack` implementation from the revision subsystem, then systematically replaces various ad-hoc commit array implementations throughout the codebase with this common version. The series adds initialization and growth helper functions (`commit_stack_init()` and `commit_stack_grow()`) to make the interface more complete and ergonomic.

The changes touch a wide range of subsystems including log handling, commit graphs, midx, remote operations, and test infrastructure. The diffstat shows significant net reduction in code (-247 lines) despite adding new helper functions, suggesting successful deduplication. The changes appear mechanical and focused on internal implementation rather than user-visible behavior.

This looks like a well-scoped cleanup that follows Git's established patterns for such refactorings. The commit messages could benefit from more detailed motivation about why unifying these implementations is valuable (beyond just reducing duplication), but the technical approach seems sound and the changes are appropriately focused.
