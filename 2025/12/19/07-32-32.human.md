This is a follow-up discussion in the test suite maintenance series addressing curl 8.18.0 compatibility issues. 

Jeff King confirms Matthew John Cheetham's analysis that the t5563 test was incorrectly named and actually intended to test mixed continuation characters (spaces vs tabs) in HTTP headers rather than line endings. The test was producing malformed HTTP responses by omitting the final CRLF, which curl 8.18.0 enforces more strictly. 

This exchange validates the approach taken in patch 2/3 of the series, which added the missing CRLFs and renamed the test to better reflect its purpose. The discussion shows good technical alignment between the contributors on diagnosing and fixing the test case, with no outstanding issues remaining about this particular patch. The thread context indicates this fix remains necessary regardless of other curl behavior changes being discussed in the series.
