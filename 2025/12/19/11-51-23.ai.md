This is a follow-up discussion in the Windows symlink support series, specifically addressing the PATH_MAX handling in `strbuf_readlink()`. Patrick Steinhardt had previously expressed concerns about unbounded buffer growth in the patch that removed PATH_MAX limitations. Johannes Schindelin now proposes a Windows-specific practical upper bound of 32,768 characters for symlink paths, citing Microsoft documentation while acknowledging edge cases with relative paths. 

The key technical point is that while Windows theoretically allows longer paths through relative path components, 32,768 provides a reasonable safety limit against memory exhaustion attacks while accommodating real-world use cases. Patrick accepts this solution, resolving the last open question in the series. This exchange finalizes the approach to symlink path length handling on Windows, complementing Junio Hamano's earlier approval of the unbounded approach with ERANGE checks for other platforms.
