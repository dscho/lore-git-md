This thread documents a small but important clarification to `git worktree`'s terminology around expired worktrees. The original author noticed that the documentation inconsistently used "unused" and "missing" to describe worktrees whose working directories no longer exist, which could confuse users about when the `--expire` option applies.

The first version of the patch standardized on "missing" terminology and clarified that `--expire` only applies when the working directory path is actually absent from disk. Eric Sunshine reviewed this and suggested an additional refinement - changing "expire" to "prune" in the documentation to better match the actual command name (`git worktree prune`).

The second version of the patch series maintains the approved changes from v1 while implementing Eric's suggestion. The first patch keeps the "missing" terminology standardization, and the new second patch updates just two lines - in both the man page and command help text - to use "prune" instead of "expire" when describing the removal action. The changes are purely documentation improvements that don't affect any functionality.

With both patches now submitted and the v1 feedback fully incorporated, the series appears ready for final review. The changes are small but meaningful, making the documentation more precise and consistent for users trying to understand worktree expiration behavior.
