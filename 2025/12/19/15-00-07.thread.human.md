This thread documents the evolution of a documentation patch series clarifying the terminology and behavior around `git worktree prune`. The original discussion identified inconsistencies between the documentation and help text regarding "prune" vs "expire" terminology, particularly for missing worktrees. 

Sam Bostock's v2 patches standardized the language to consistently use "prune" for missing worktrees and clarified that `--expire` only affects worktrees whose working directory no longer exists. Eric Sunshine reviewed and approved these changes, while Junio C Hamano suggested combining some patches and checked on the status. The latest v3 iteration incorporates all feedback, including Junio's suggestion to expand the `prune` subcommand description to better distinguish it from `worktree remove` and `worktree repair`. 

The changes are now mechanical documentation improvements with no behavior modifications, touching both the man page and builtin help text. Both Eric and Junio have reviewed the latest version, which appears ready for merging. This represents the conclusion of a focused discussion that progressed from terminology debates to final, uncontroversial documentation updates.
