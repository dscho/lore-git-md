This is the first patch in a v2 documentation series clarifying the `--expire` option behavior in `git worktree` commands. The patch standardizes terminology around worktrees with missing working directories, changing inconsistent "unused" references to "missing" in both the man page and command help text.

The changes affect two files: Documentation/git-worktree.adoc and builtin/worktree.c. The key modification is making it explicit that `--expire` only applies when the working directory path no longer exists on disk. The patch maintains the same core clarification from v1 while incorporating Eric Sunshine's feedback to use "prune" terminology in specific contexts (which appears in patch 2/2).

The documentation updates are straightforward mechanical changes to strings describing the `--expire` option's behavior for both `git worktree prune` and `git worktree list`. The commit message clearly explains the motivation for the inconsistency being fixed. This appears to be a well-scoped, uncontroversial documentation improvement that has already received positive feedback in the v1 review cycle.
