Maintainer feedback on maintenance config file proposal. Junio C Hamano provides detailed technical review of Matthew Hughes' RFC patch to add `maintenance.configFile` support.

The review identifies several issues with the current proposal:
1. The commit message lacks clear explanation of the problem and solution, making readers work too hard to understand the change. Junio reconstructs the intended behavior where `maintenance.configFile` would control where `maintenance.repo` entries are written, while other config operations remain unaffected.

2. Questions whether maintenance-specific config handling is the right approach, suggesting a more general solution for read-only base configs with writable overlays might better serve the author's stated use case of version-controlled global configs.

3. Points out multiple code style violations in the implementation:
   - NULL checks should use `if (!var)` syntax
   - Single-statement blocks should omit braces
   - Long function calls should be wrapped for 72-column display

4. Identifies potential portability issues in the test script:
   - `pwd` output may vary on Windows
   - Test assertions could be more precise about verifying config isolation
   - `>>` operator may mislead about test intent

5. Suggests alternative test approaches that would better verify the core requirement - that the base config remains untouched while maintenance operations write to the alternate file.

The review maintains the thread's technical focus while providing concrete guidance for improvement. It doesn't reject the proposal outright but questions whether the maintenance-specific approach is optimal solution for the underlying versioned-config use case. The feedback is thorough yet constructive, typical of Junio's maintainer style.
