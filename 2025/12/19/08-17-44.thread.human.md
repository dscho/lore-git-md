This thread discusses Harald Nordgren's proposal to add a `--no-indicators` option to `git diff` that would replace the '+', '-', and ' ' indicators with spaces while preserving colors, aiming to make diff output easier to copy-paste. The initial implementation touches `diff.c` and the test suite.

Several experienced contributors have expressed skepticism about the feature's necessity. Collin Funk suggested `sed` could achieve similar post-processing, while Phillip Wood raised technical concerns about space handling and newline markers. Maintainer Junio Hamano questioned the value, noting terminal workarounds exist and other diff tools don't offer this functionality. Ben Knoble and Phillip Wood both highlighted that `git restore -p` provides a better native solution for version recovery than copying from diffs.

The latest contribution from Chris Torek reinforces this skepticism by sharing his personal workflow using `git show` to extract file versions into temporary files for comparison in Vim, avoiding diff output issues entirely. This practical example from an experienced user further demonstrates how existing Git tools can address the underlying need without modifying diff output.

The discussion now shows a clear consensus among multiple contributors that the proposed feature may not provide enough unique value given the robust alternatives already available in Git (`git restore -p`, `git show`) and terminal capabilities. Unless proponents can demonstrate compelling advantages over these existing methods, the feature faces significant barriers to adoption.
