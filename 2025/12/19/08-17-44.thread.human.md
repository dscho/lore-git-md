This thread discusses a proposal to add a `--no-indicators` flag to `git diff` and `git show` that would replace the '+', '-', and ' ' indicators with spaces while preserving colors. The original motivation came from Harald Nordgren's workflow of copying React/TypeScript code blocks from their own commits, where the indicators were problematic.

Several experienced contributors have raised concerns and alternatives. Phillip Wood noted technical issues around space handling and newline markers, while Junio Hamano questioned the feature's necessity given that terminal emulators can already select text without indicators. Multiple alternatives have been suggested: Ben Knoble proposed using `git restore`, Chris Torek demonstrated a script using `git show` with temporary files, and others pointed to terminal column selection.

Harald continues to advocate for the feature, most recently arguing that built-in commands are more convincing for team adoption than scripts. However, they haven't addressed the technical concerns or explained why existing solutions don't work for their case. The discussion remains at a standstill, with maintainer skepticism and no clear path forward unless stronger justification emerges for why this feature is needed when multiple alternatives exist. The core question remains whether this solves a problem that isn't already addressed by Git's current capabilities.
