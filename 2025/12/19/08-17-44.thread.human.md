This thread discusses a proposal to add a `--no-indicators` option to `git diff` that would replace the '+', '-', and ' ' margin indicators with spaces while preserving colors. The original author, Harald Nordgren, argues this would make diff output cleaner for copy-pasting purposes.

Several contributors have raised concerns about the proposal. Collin Funk questioned whether the feature was necessary, suggesting `sed` could achieve similar results. Phillip Wood noted technical issues around handling leading spaces and newline markers, while pointing out that existing `--output-indicator-*` options can partially address the need. Harald responded to some of these points but hasn't yet addressed all the edge cases.

The discussion took a significant turn when maintainer Junio Hamano weighed in with skepticism. He pointed out that terminal emulators with column selection can already bypass the indicator issue, and that users would still need to strip leading spaces when copying multi-line diffs. Junio also questioned whether other diff tools offer similar functionality, suggesting this might not be a widely needed feature.

The core debate now centers on whether this feature provides enough unique value to justify adding it to Git's codebase, given existing alternatives like terminal features, external filtering tools, and partial solutions through current indicator customization options. The proposal's future likely depends on whether proponents can demonstrate concrete advantages that these alternatives can't provide.
