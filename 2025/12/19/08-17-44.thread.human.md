This thread discusses Harald Nordgren's proposal to add a `--no-indicators` flag to `git diff` and `git show` that would replace the '+', '-', and ' ' indicators with spaces while preserving colors. The motivation is to make it easier to copy React/TypeScript code blocks from diffs without the indicator characters.

Several experienced contributors have raised concerns and proposed alternative solutions. Junio Hamano (the maintainer) questions whether this feature is necessary, noting that terminal emulators can already select text without indicators and that traditional diff tools haven't needed this capability. Others have suggested existing Git features that could solve the use case: `git restore -p` for selective recovery, `git show` with temporary files for comparison (Chris Torek's approach), and now Johannes Sixt's suggestion to use `git difftool` with graphical diff tools like meld or WinMerge.

The discussion has reached an impasse. While Harald continues to advocate for the feature based on workflow preferences, they haven't addressed key technical concerns about edge cases (like newline markers and space handling) or demonstrated why the existing alternatives are insufficient. The thread now features four different ways to accomplish the same task without modifying Git, making it unclear what unique value the proposed flag would add. Unless proponents can show compelling advantages over these established methods, the proposal seems unlikely to gain traction.
