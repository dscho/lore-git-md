This thread continues to explore Harald Nordgren's proposal for a `--no-indicators` flag in `git diff` and `git show` that would replace the '+', '-', and ' ' indicators with spaces while preserving colors. The original motivation was to make it easier to copy-paste React/TypeScript code blocks from commit diffs.

Several experienced contributors have raised concerns about the necessity of this feature, suggesting alternative approaches. Collin Funk questioned whether `sed` post-processing would suffice, while Phillip Wood pointed out technical edge cases around space handling and newline markers. Junio Hamano expressed skepticism about the feature's value, noting terminal emulators can already handle column selection. Ben Knoble and Phillip Wood both suggested `git restore -p` as a better native solution for version recovery.

Harald has maintained that these alternatives don't meet their specific workflow needs for quickly recovering discarded code blocks, though they haven't addressed the technical concerns raised. Chris Torek has now provided a concrete script example showing how to extract both old and new versions of a file using `git show` with revision syntax (`${rev}^:$path` for the parent version and `${rev}:$path` for the current version), demonstrating that existing Git functionality can solve the use case without new features.

The discussion remains at an impasse, with the original proposer continuing to advocate for their specific workflow need while multiple contributors have shown how existing Git tools can address the same requirement. The maintainer's skepticism and the demonstrated alternatives present significant barriers to the feature's adoption unless stronger justification can be provided for why current solutions are insufficient.
