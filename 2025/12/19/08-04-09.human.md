This is a technical discussion about HTTP header parsing behavior between curl and Git's test suite, continuing from the test compatibility series for curl 8.18.0.

Jeff King responds to Daniel Stenberg's proposed curl fix for header unfolding behavior, noting it only partially resolves the test failures. While the fix correctly handles spaces in folded headers, it still preserves tabs when unfolding, which may violate HTTP standards. King provides a more thorough solution that would always insert a space during unfolding, regardless of the original whitespace character (space or tab).

The exchange reveals deeper considerations about HTTP standards compliance versus real-world behavior. King acknowledges that while the current curl behavior might work in practice (since most HTTP parsers accept tabs as whitespace), strictly following RFC 7230 would require converting all whitespace to spaces during unfolding. His proposed patch demonstrates how curl could implement this while working around the constraint of a const input buffer.

This discussion highlights the careful balance between maintaining backward compatibility, adhering to standards, and writing robust tests that don't make implementation-specific assumptions. The thread shows productive collaboration between Git and curl maintainers to find solutions that work for both projects.
