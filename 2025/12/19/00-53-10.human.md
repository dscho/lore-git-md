Platform compatibility fix for the build system, addressing a Rust compilation issue on non-GNU platforms. This is a follow-up to D. Ben Knoble's patch that fixes a build failure when compiling Git with Rust support on macOS/BSD systems.

The core issue stems from using GNU sed's `-s` extension in `src/cargo-meson.sh`, which isn't portable to BSD sed implementations. The script determines the library naming convention (`gitcore.lib` for Windows vs others) by parsing cargo's host platform information. Knoble's solution replaces the non-portable `sed -s` with standard `sed -n` plus pattern printing, making the build work across all Unix-like systems.

The change is minimal (a one-character modification) but crucial for cross-platform compatibility in Git's Rust build infrastructure. The patch has already received positive reviews from Eric Sunshine and Patrick Steinhardt, suggesting it's technically sound.

This fix is part of Git's ongoing Rustification effort and meson build system modernization. The issue likely went unnoticed initially because most developer machines and CI systems use GNU sed, where the original command worked fine. The patch demonstrates good attention to platform compatibility details in the relatively new Rust components of Git's build system.
