This is a documentation patch series (v2) clarifying the behavior of `--expire` in `git worktree` commands. The changes standardize terminology around "missing" worktrees (those whose working directories no longer exist on disk) and improve consistency between documentation and help text.

The series addresses feedback from Eric Sunshine on v1, specifically adopting the term "prune" instead of "expire" when describing the option's effect, since this better matches the actual behavior. The first patch remains unchanged from v1, while the new second patch updates the help text in `builtin/worktree.c` to use "prune" terminology.

The changes are straightforward and uncontroversial, touching only documentation strings in the man page and command-line help. The v1 review already approved the core concept, and this revision incorporates the suggested wording improvements. The patch series appears ready for merging pending final review.
