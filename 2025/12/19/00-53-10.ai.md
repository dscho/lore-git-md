Platform compatibility fix for the Rust build system, addressing a BSD/macOS compilation issue. This is a follow-up to D. Ben Knoble's patch that fixes the use of GNU sed's `-s` extension in `src/cargo-meson.sh`, which was causing build failures on BSD-derived systems like macOS when compiling with Rust support enabled.

The patch makes a minimal but crucial change, replacing the non-portable `sed -s` with standard `sed -n` plus pattern printing (`p` flag) to correctly extract cargo's host information. This maintains the same functionality while working across all Unix-like systems. The issue had gone unnoticed on GNU systems where the sed behavior happened to work by accident.

Eric Sunshine confirms the change looks good in this reply, marking the second positive review after Patrick Steinhardt's earlier approval. The fix targets a clear compatibility issue in Git's relatively new Rust build infrastructure, which is part of the broader Rustification effort. The technical solution is straightforward and well-justified, with the impact limited to build system behavior rather than runtime functionality.

Key technical details for future reference: the script determines library naming (`gitcore.lib` for Windows vs other platforms) by parsing cargo's host platform string. The original GNU sed usage would have failed on BSD systems when trying to extract this information, while the new version uses portable sed syntax to achieve the same result. The change affects only the build-time platform detection logic in `src/cargo-meson.sh`.
