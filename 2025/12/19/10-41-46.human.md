Initial feedback on the `--snapshot` feature proposal. Phillip Wood raises several important points about the proposal to add a `--snapshot` option to `git commit` that would create timestamped copies of staged files before committing.

The key concern is the lack of clear motivation for why this feature is needed, given that commits already serve as snapshots of the working tree. Phillip notes that while the code comments explain what the feature does, they don't establish why it would be useful to maintain additional copies of staged files outside the Git object database. He also observes that the author admits the code hasn't been tested, raising questions about how they determined the feature's usefulness.

This appears to be the first substantive feedback on the proposal, focusing on fundamental questions about the feature's purpose rather than implementation details. The response doesn't address technical concerns from the initial proposal (like the use of `system()` calls or security implications) because those become secondary if the core concept isn't justified. The ball is now in the original author's court to either articulate the use cases that motivate this feature or reconsider the proposal.
