This is a technical discussion about conflict resolution strategy in Patrick Steinhardt's `git-history` RFC series, specifically addressing how to handle branch updates during history editing operations. The email comes from Elijah Newren, who strongly disagrees with Steinhardt's proposed "HEAD-to-commit walk" approach for determining which branches to rewrite.

Newren makes several key technical arguments against the current proposal. He disputes Steinhardt's scaling concerns about walking all branches, noting that Jujutsu (jj) handles this case efficiently despite its focus on large repositories. More fundamentally, he argues the HEAD-to-commit walk creates a "principle of least astonishment" violation by potentially leaving some dependent branches unmodified while others are rewritten. He provides three alternative approaches that would avoid this: (1) rewrite all dependent branches (with existing implementation being shorter than current code), (2) walk all branches to detect and warn about multiple affected branches, or (3) require explicit user specification via mutually exclusive flags.

The discussion reveals a core philosophical difference - Steinhardt prioritizes UI simplicity (single-commit focus) while Newren prioritizes behavior consistency (avoiding disconnected histories). Newren's position suggests the current compromise may not satisfy either camp, as it neither fully embraces Jujutsu's automatic behavior nor provides clear user control. The email raises important implementation questions about how Git's existing infrastructure could support the more comprehensive branch walking Newren advocates, particularly around performance characteristics and warning/error presentation.
