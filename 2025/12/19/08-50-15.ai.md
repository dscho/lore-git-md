This is a follow-up discussion in the Windows symlink support series, specifically addressing the PATH_MAX removal in `strbuf_readlink()`. Johannes Schindelin (Git for Windows maintainer) responds to Patrick Steinhardt's concerns about unbounded growth in the symlink buffer by proposing a practical upper bound of 32,768 characters based on Windows path limitations. While acknowledging that technically valid paths could exceed this through relative path components, he argues this provides a reasonable compromise between safety and practicality - high enough for legitimate use but preventing memory exhaustion attacks. This builds on the prior resolution where Junio Hamano had approved the unbounded approach with ERANGE safety checks, now adding Windows-specific considerations to the solution. The exchange demonstrates the series' attention to cross-platform robustness as it finalizes technical details before integration.
