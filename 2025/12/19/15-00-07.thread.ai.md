Thread identity: Documentation patch clarifying the `--expire` option behavior in `git worktree` commands, focusing on consistent terminology for worktrees with missing working directories.

Core problem: The documentation and help text for `git worktree` commands inconsistently used "unused" and "missing" to describe worktrees whose working directories no longer exist, causing confusion about when the `--expire` option applies.

Current status: Patch version 1 under review, proposing to standardize on "missing" terminology. Eric Sunshine has reviewed and agrees with the core change while suggesting refinements to the wording.

Key technical details: Changes affect documentation strings in the man page and in-command help text for `git worktree list` and `git worktree prune`. Clarifies that `--expire` only applies when the working directory path is actually missing from disk. Review feedback proposes changing "expire" to "prune" in both the man page and `prune` command's help text to better match actual behavior, while keeping the `list` command's help text modification as proposed.

Participant positions: Original author proposed standardizing on "missing" terminology. Eric Sunshine reviewed and approved the core concept while suggesting more precise phrasing - changing "expire" to "prune" in the man page and `prune` command's help text to better reflect command behavior, with the suggested wording "prune missing worktrees older than <time>". The review explicitly endorsed the unchanged wording for the `list` command's help text modification.

Open questions: Whether the author will incorporate the suggested wording changes in a v2 patch. The review did not raise any objections to the core approach, only suggesting refinements to improve clarity.
