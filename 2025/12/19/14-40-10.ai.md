This is a discussion email in the ongoing thread about the proposed `--no-indicators` option for `git diff`. Chris Torek weighs in with an alternative workflow suggestion, reinforcing the skepticism about the feature's necessity.

Chris shares his personal approach for working with file versions, preferring to use `git show` to extract specific versions of files into separate temporary files (`file.oldver` and `file.newver`), then using Vim to manually compare and paste between them. He notes this avoids mouse-based selection issues and provides more control than trying to copy from diff output. While acknowledging that `git restore -p is good for small changes, his method handles larger-scale version comparisons better.

This contribution strengthens the emerging consensus in the thread that existing Git tools (`git show`, `git restore -p`) already provide robust alternatives to the proposed indicator suppression feature. Chris's workflow suggestion comes from practical experience with text editing scenarios similar to those motivating the original patch, yet demonstrates how current capabilities can address the need without new diff output modifications. The email doesn't introduce new technical considerations but provides another concrete example of how experienced users work around the limitations the patch attempts to address.
