This is a follow-up in the curl 8.18.0 compatibility thread, specifically addressing whitespace handling in HTTP header unfolding. Daniel Stenberg (curl maintainer) responds to Jeff King's observation about incomplete handling of tab characters in header folding, acknowledging the oversight in curl's initial fix.

The discussion centers on curl's implementation of RFC 7230 header unfolding behavior, where the initial fix only handled spaces but not tabs in folded headers. Stenberg confirms this was an oversight and commits to fixing it in curl by ensuring any leading whitespace character (space or tab) in folded headers gets replaced with a single space during unfolding.

This email represents the ongoing collaboration between Git and curl maintainers to align HTTP protocol handling while maintaining backward compatibility. The solution being discussed would make curl's behavior more standards-compliant (RFC 7230) while fixing the test failures Git encountered with curl 8.18.0 release candidates. The fix would complement the earlier test suite changes (cookie path handling and CRLF enforcement) that were already agreed upon in this thread.
