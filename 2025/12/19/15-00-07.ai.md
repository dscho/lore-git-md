This is a documentation patch that clarifies the behavior of the `--expire` option in `git worktree` commands. The patch standardizes the terminology used to describe worktrees whose working directories no longer exist, changing from inconsistent usage of "unused" and "missing" to consistently use "missing" throughout.

The changes affect both the man page documentation and the in-command help text for `git worktree list` and `git worktree prune`. The key clarification is that `--expire` only applies to worktrees where the working directory path is actually missing from disk, not just unused worktrees in general.

The patch appears straightforward and well-scoped, touching only documentation strings in two files. The commit message clearly explains the motivation for the change (to fix inconsistent terminology) and the specific changes made. This seems like a low-risk improvement to user-facing documentation that makes the behavior more clear.
