Documentation patch clarifying `git worktree` terminology for expired worktrees. This is the first of two patches in v2 of a series addressing inconsistent language around worktrees with missing directories.

The patch standardizes on "missing worktrees" terminology in both the man page and command help text to make clear that the `--expire` option only affects worktrees where the working directory path no longer exists. The changes are straightforward text updates in Documentation/git-worktree.adoc and builtin/worktree.c, replacing previous inconsistent uses of "unused" and other phrasing.

This version maintains the core clarification from v1 while incorporating feedback to improve consistency. The changes are minimal but meaningful, affecting how users understand when the expiration feature applies. The patch appears well-scoped and properly motivated, with clear commit message explaining both the problem and solution.

As part of an already-reviewed series where the core concept was approved in v1, this iteration seems likely to progress smoothly unless new concerns emerge about the specific wording choices. The second patch in the series handles the separate "expire"->"prune" terminology refinement suggested during v1 review.
