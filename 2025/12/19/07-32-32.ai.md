This is a follow-up discussion in the curl 8.18.0 compatibility test fixes thread. Jeff King confirms Matthew John Cheetham's analysis that the t5563 test was incorrectly named and actually intended to test mixed continuation characters (spaces vs tabs) in HTTP headers rather than line endings. The test was producing malformed HTTP responses by omitting the final CRLF, which curl 8.18.0 enforces more strictly.

The exchange clarifies the original intent and validates the approach taken in patch 2/3 of the series, which added the missing CRLFs and renamed the test to better reflect its purpose. This confirmation from both parties helps solidify the technical justification for the change while maintaining backward compatibility with older curl versions. The discussion doesn't introduce new changes but provides important context about the test's original design that wasn't fully captured in the commit message.
