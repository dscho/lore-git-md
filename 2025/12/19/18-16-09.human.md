This is the second patch in a documentation series clarifying terminology around `git worktree`'s `--expire` option. It implements a reviewer-suggested change from the v1 discussion to use "prune" rather than "expire" when describing the action taken on missing worktrees.

The patch makes two straightforward changes: updating the man page and command help text to say "prune" instead of "expire" when describing what happens to worktrees that are both missing and older than the specified time. This follows naturally from the first patch's clarification that `--expire` only affects worktrees whose working directories are actually missing from disk.

The changes are minimal and focused - just two lines modified in total - and appear to cleanly implement the suggestion from Eric Sunshine's v1 review. The patch maintains the same technical meaning while using more precise terminology. Since the first patch in the series was already approved in principle, this follow-up seems likely to be accepted as well, completing the documentation improvements around this feature.
