This is a technical discussion about HTTP header whitespace handling in curl, continuing the test suite maintenance series for curl 8.18.0 compatibility.

Jeff King responds to Daniel Stenberg's proposed curl fix for header unfolding behavior, noting it only partially resolves the test failures. While the fix correctly handles spaces in folded headers, it still preserves tabs when unfolding, which may violate HTTP standards (RFC 7230) that specify spaces should be used. King provides a more comprehensive patch suggestion for curl's http.c that would always insert a space during unfolding, regardless of the original whitespace character (space or tab).

The discussion reveals deeper considerations about HTTP standards compliance versus real-world behavior. King acknowledges that while the tab preservation might work in practice (since most HTTP grammars accept any whitespace), strictly following the standard would be cleaner. His proposed solution avoids modifying the const input buffer by explicitly adding a space during unfolding operations.

This exchange highlights the tension between maintaining backward compatibility, adhering to standards, and writing robust tests. The Git test suite's expectations of specific whitespace patterns in HTTP headers are proving to be a point of friction as curl evolves toward stricter standards compliance. The thread shows active collaboration between Git and curl maintainers to find solutions that work for both projects.
