This is the first patch in a v2 series improving the `git reset` documentation, specifically reordering the command forms to prioritize the most commonly used `[<mode>]` variant. The change is motivated by user feedback indicating this is the primary form used in practice, and it better aligns with the command's introductory description about resetting HEAD.

The patch moves the `git reset [--soft|--mixed|--hard|--merge|--keep]` form to the top of the SYNOPSIS section, followed by the path-specific and interactive forms. This reordering is accompanied by corresponding adjustments to the DESCRIPTION section to maintain logical flow. The change preserves all technical content while making the documentation more intuitive for typical usage patterns.

Key technical details include:
- The `[<mode>]` form is now first in SYNOPSIS
- DESCRIPTION section reorganized to match the new order
- All existing content and cross-references preserved
- Justification based on user feedback and alignment with `git reset`'s core functionality
