This is a feature proposal for `git diff` that continues an ongoing discussion about adding a `--no-indicators` option. Junio Hamano, Git's maintainer, weighs in with skepticism about the usefulness of the proposed feature.

Hamano questions whether replacing the +/- indicators with spaces actually solves the copy-paste problem as claimed, since users would still need to remove the leading space column when pasting. He notes terminal emulators like `screen` already allow column-based selection, making the indicator characters irrelevant for copy-paste workflows. 

The maintainer raises the bar for new features by asking whether other diff implementations (GNU/BSD) offer similar functionality, suggesting this would need stronger justification to be considered for inclusion. This continues the thread's theme of questioning whether the feature provides enough unique value over existing alternatives (either built-in options or external tools).

The exchange remains technical and constructive, but Hamano's involvement as maintainer signals this proposal faces significant hurdles unless the author can provide more compelling use cases or demonstrate broader demand for the feature. The core question remains whether this solves a problem important enough to justify adding to Git's core.
