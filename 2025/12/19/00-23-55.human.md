This is the third patch of a four-part documentation series improving the `git reset` man page, focusing on clarifying the behavior of different reset modes. The patch addresses several user-reported confusions by restructuring the mode descriptions to be more intuitive.

The changes standardize terminology (using "index" consistently instead of mixing "index" and "index file"), reorder modes to put the default `--mixed` first, and improve explanations of each mode's effects. Notably, it now leads with working directory changes (what users most want to avoid losing) before discussing index updates. The `--soft` mode gets a concrete example showing how to squash commits, while `--merge` is clarified as being mainly for resolving unmerged states from operations like `git am -3`.

This continues the series' goal of making the documentation both technically precise and pedagogically clear, building on Julia Evans' initial work and Junio Hamano's technical refinements. The patch appears well-considered, with clear commit message explanations for each change and careful attention to user pain points.
