This is a follow-up discussion in the Windows symlink support series, specifically addressing the buffer size limits for symlink targets. The thread had previously resolved most technical questions, with Johannes Schindelin (Git for Windows maintainer) now proposing a practical upper bound of 32,768 characters for symlink paths on Windows. This addresses Patrick Steinhardt's earlier concern about unbounded memory growth while still accommodating realistic path lengths.

Schindelin acknowledges that while Windows documentation suggests this limit, some relative paths could technically exceed it. However, he argues this strikes a reasonable balance between safety and functionality. Patrick Steinhardt confirms this solution works for him, marking the final resolution of this technical point in the series.

The discussion shows careful consideration of platform-specific constraints while maintaining Git's general approach to PATH_MAX issues. With this last question settled, the preparatory work for Windows symlink support appears complete and well-vetted by both general Git developers and Windows specialists.
