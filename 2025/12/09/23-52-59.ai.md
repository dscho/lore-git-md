This is a follow-up review of the memory leak fix in the HTTP 429 retry series. Taylor Blau suggests an alternative approach to addressing the strbuf leak in `show_http_message()` that would avoid copying the message buffer while still preventing leaks.

The proposed alternative would:
1. Rename the function to `show_http_message_fatal` to better reflect its behavior
2. Make it handle buffer cleanup directly before calling die()
3. Take the die() format string and arguments as parameters
4. Release all buffers (type, charset, and msg) before dying

This approach would eliminate the need for the `msgbuf` copy introduced in the original patch while still properly cleaning up resources. The change would affect all HTTP error paths (HTTP_MISSING_TARGET, HTTP_NOAUTH etc.) that use this helper function.

The review focuses on code organization and resource management rather than the core functionality, continuing Taylor's pattern from the earlier review of Patch 1. The suggestion maintains the same error handling behavior while potentially being more efficient (avoiding the buffer copy) and making the fatal nature of the function more explicit in its name.

This is part of the ongoing refinement of the rate limiting series, specifically addressing a pre-existing memory leak that became more visible during retry testing. The discussion remains focused on implementation details rather than the series' overall approach.
