This is a follow-up to the ongoing macOS iconv compatibility discussion, focusing on build system configuration. Yee Cheng Chin points out an edge case in René Scharfe's proposed Homebrew libiconv detection patch - it could incorrectly select the x86-64 Homebrew installation (under `/usr/local/`) when running on Apple Silicon Macs via Rosetta 2. While this is a niche scenario, it could lead to suboptimal performance or compatibility issues.

The note serves as a useful technical refinement to the build-system approach being considered for the macOS iconv regression. It doesn't fundamentally change the solution space but highlights an additional consideration for the final implementation. The discussion continues to balance between comprehensive platform coverage and handling of edge cases in the iconv workaround strategies.
