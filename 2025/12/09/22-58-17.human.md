This is the third patch in a series extending Git's `repo structure` command with object size reporting capabilities. It adds inflated (content) size information to the keyvalue and nul output formats for each object type (commits, trees, blobs, tags).

The patch introduces a new `inflated_sizes` field in the `object_stats` struct to track sizes alongside the existing type counts. It modifies the object counting callback to calculate and accumulate the inflated size of each object using `odb_read_object_info_extended()`. The sizes are then included in the keyvalue output with new keys like `objects.commits.inflated`.

The implementation looks solid, with proper error handling for object reading and clear separation from the table formatting changes that will be added in a later patch. Test coverage is added to verify the new size fields appear correctly in keyvalue output. The patch builds logically on the previous infrastructure refactoring while keeping the scope focused on just the keyvalue/nul format changes.

This continues the series' pattern of well-structured, incremental changes to enhance repository structure reporting. The next patches will presumably add the same size information to the table format and possibly introduce on-disk size reporting as hinted in the thread summary.
