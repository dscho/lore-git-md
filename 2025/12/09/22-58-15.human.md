This is the first patch in a series adding object size reporting to Git's `repo structure` command. It's a refactoring patch that prepares for the new functionality by restructuring how object counts are stored.

The patch introduces a new `object_values` struct to group the per-type object counts (tags, commits, trees, blobs) that were previously stored directly in `object_stats`. This nesting makes the code more maintainable and provides a clear place to add the upcoming size measurements in later patches. The changes are mechanical - moving fields, updating accessors, and adjusting all the call sites to use the new structure.

The implementation looks clean and focused, touching only the necessary parts of the code to enable the planned extensions. As the first step in a series, it does exactly what's needed without introducing any new functionality. The commit message clearly explains the purpose and ties it to the broader series goal.
