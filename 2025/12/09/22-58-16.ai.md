This is the second patch in a 6-part series enhancing Git's `repo structure` output formatting, specifically focusing on human-readable number display.

The patch introduces human-friendly scaling of large numbers in the table output format of `git repo structure`, while keeping machine-readable formats (keyvalue and nul) unchanged. When counts exceed certain thresholds (1k, 1M, 1G), values are now displayed with appropriate unit prefixes (k, M, G) and decimal places for better readability. The implementation:

1. Adds unit handling to the table formatting infrastructure, including a new `unit_col_width` field in `stats_table` and `unit` field in `stats_table_entry`
2. Implements scaling logic that:
   - Rounds numbers to 2 decimal places (e.g., 1005 becomes "1.01k")
   - Handles three scaling tiers (k=1000, M=1000000, G=1000000000)
3. Updates the table output to properly align both values and their units
4. Modifies tests to verify the new formatting, including a test case with 1005 commits that should show as "1.01k"

The changes affect `builtin/repo.c` (61 lines added/modified) and its tests (62 lines modified), with careful attention to maintaining alignment in the table output. This builds on the refactoring from patch 1 by using the restructured object counting infrastructure to display the improved output.

Key technical details for future reference:
- New constants: unit_k, unit_M, unit_G
- Modified structs:
  - `stats_table` gains `unit_col_width`
  - `stats_table_entry` gains `unit` field
- Scaling thresholds: 1000, 1000000, 1000000000
- Test verification: checks output formatting for both small (0) and large (1005 -> 1.01k) counts
