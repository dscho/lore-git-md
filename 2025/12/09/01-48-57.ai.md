Performance optimization extending the `PARSE_OBJECT_SKIP_HASH_CHECK` behavior to promisor object initialization. This is the second patch in a v3 series improving partial clone workflows, specifically targeting the performance of `--exclude-promisor-objects`.

The change modifies `add_promisor_object()` in `packfile.c` to use `parse_object_with_flags()` with `PARSE_OBJECT_SKIP_HASH_CHECK` when initializing the promisor object set. The key insight is that this initialization only needs to track object presence, not validate contents, making full hash verification unnecessary. The patch demonstrates dramatic speedups - from 76 minutes to 2 minutes in a real-world 176GB promisor pack scenario - by avoiding decompression and hash verification of blob objects during this phase.

The change is minimal (3 lines modified) and focused, building on the series' earlier work to optimize object parsing. It maintains all existing behavior guarantees while improving performance in the common case where promisor objects are being enumerated but their contents aren't needed. The commit message provides clear before/after benchmarks and explains the safety of skipping hash verification in this specific context.

Technical focus remains on the interaction between `parse_object_with_flags()` behavior and promisor object handling, specifically the `PARSE_OBJECT_SKIP_HASH_CHECK` optimization path. The change complements the first patch's work with `OBJ_NONE` handling by applying similar optimizations to the promisor object initialization phase. Both patches together form a coherent optimization of the promisor object processing pipeline.
