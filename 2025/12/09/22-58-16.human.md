This is the second patch in a series improving Git's `repo structure` command output, focusing on human-readable formatting. It follows the preparatory refactoring in patch 1 and precedes the planned object size reporting features.

The patch modifies the table output format to display large counts (1000+) with scaled units (k/M/G) while keeping raw numbers for smaller values. For example, 1005 commits will show as "1.01 k" rather than "1005". The key-value and nul output formats remain unchanged for machine consumption. The implementation adds unit handling to the table formatting logic and updates tests to verify the new humanized output.

The changes are thorough, touching both the core formatting logic in `builtin/repo.c` and updating all test expectations in `t/t1901-repo-structure.sh`. The patch maintains the existing alignment and structure of the table while adding the new unit display. This appears to be a well-executed quality-of-life improvement that makes the command more user-friendly without breaking existing machine parsing use cases.
