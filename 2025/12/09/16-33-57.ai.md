This is a follow-up in the macOS iconv thread, proposing an alternative workaround for the stateful encoding conversion issue in `reencode_string_iconv()`. Torsten Bögershausen responds to René Scharfe's original patch with a modified version that takes a different approach to handling buffer growth during iconv conversions.

The key differences in Torsten's proposal are:
1. It tracks the original input size (`originsz`) rather than recalculating it from the current position
2. It makes the workaround Apple-specific (`#ifdef __APPLE__`) rather than using a configurable `ICONV_BREAKS` flag
3. It omits the explicit `iconv(conv, NULL, NULL, NULL, NULL)` state reset that was in René's version

The patch maintains the same core solution approach - when the buffer growth case is hit, it restores the original conversion state and retries the entire conversion with the larger buffer. However, it differs in implementation details and platform targeting. The change appears to be a direct response to René's uncertainty about the state-resetting iconv call in the original patch.
