This is a bugfix patch series addressing an issue with relative-depth fetching in shallow repositories. The series comes from Samo Pogačnik via GitGitGadget and consists of 2 patches targeting the shallow clone/fetch functionality.

The core issue occurs when fetching with relative depth (`--deepen`) in a repository with merged branches - some shallow commits may incorrectly remain behind reachable ones, while absolute-depth fetches handle this case correctly. The solution unifies the handling of absolute and relative deepening by introducing a new `get_shallows_depth()` function that calculates equivalent depths for existing shallow commits, allowing relative deepening to work similarly to absolute deepening.

The first patch is a preparatory cleanup, freeing local `object_array` allocations in the shallow code. The second patch implements the main fix by:
1. Removing the now-redundant `get_reachable_list()` function
2. Adding `get_shallows_depth()` to properly calculate relative depths
3. Modifying the deepening logic to handle both absolute and relative cases consistently

The changes affect `shallow.c`, `upload-pack.c`, and include a new test case in `t5500-fetch-pack.sh` that demonstrates the fixed behavior. The approach appears well-reasoned, with the commit message clearly explaining both the problem and solution. The patch touches core shallow clone functionality, so reviewers will likely want to carefully verify the depth calculation logic and edge cases.
