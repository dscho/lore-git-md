Feature patch adding on-disk size metrics to Git's `repo structure` command, part 5/6 in the series enhancing object size reporting.

This patch extends the keyvalue and nul output formats to include disk size information for repository objects, completing the parallel reporting structure alongside the existing inflated size metrics. The implementation adds a new `disk_sizes` field to the `object_stats` struct and collects sizes via `oi.disk_sizep` during object iteration. Platform variance in disk sizes is explicitly acknowledged by excluding these values from test assertions - the tests only verify presence of the disk size fields in output, not their numeric values.

Key technical elements:
- New `disk_sizes` field in `object_stats` struct (parallel to `inflated_sizes`)
- Size collection via `oi.disk_sizep` in `count_objects()`
- Keyvalue output format extended with `objects.*.disk` entries
- Test strategy focuses on field presence rather than value validation
- Maintains SHA1-specific test patterns (consistent with series)

The patch follows the series' incremental approach, building on the refactored counting infrastructure from earlier patches. It completes the machine-readable output formats (keyvalue/nul) for disk sizes, leaving the human-readable table format presumably for the final patch. The implementation maintains clean separation between different size metrics while sharing the underlying collection mechanism.
