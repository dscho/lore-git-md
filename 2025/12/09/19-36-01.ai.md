This is a feature patch series introducing `--keys` flag support for `git repo info`, now including format compatibility in v2.

The series adds a `--keys` option to list available repository information keys without values, addressing Junio Hamano's earlier suggestion. The main change in v2 is implementing format support (`-z`/`--format`) for the key listing output, where v1 had deferred this decision. The implementation now handles both default newline-separated and NUL-terminated output formats while rejecting invalid combinations with `--all` or specific key requests.

Key technical changes include:
- New `FORMAT_DEFAULT` enum value for the output format type system
- Updated `print_keys()` function that respects the requested format (newline or NUL separator)
- Strict validation preventing `--keys` from being combined with value-requesting options
- Test cases verifying format handling and invalid combination rejection

The implementation builds on commit bdc5341ff6 (`lo/repo-struct-z`) and maintains the core approach of iterating `repo_info_fields` while adding the new format handling layer. Documentation updates clarify the supported formats for key listing.

This version appears to resolve the open question from v1 by implementing format support rather than rejecting format options, while maintaining clean separation from value-printing functionality. The test coverage is thorough, including format verification and error case testing. The changes align with Git's direction toward better programmatic interfaces while keeping the implementation focused and well-contained within the existing `repo-info` command structure.
