Memory management fix in shallow clone handling.

This is the first of two patches fixing issues with relative-depth fetching in shallow repositories. The patch addresses a memory leak in the `get_shallow_commits()` function where dynamically allocated elements in a local `object_array` weren't being freed before function return. The fix is straightforward - adding a call to `object_array_clear()` to clean up the allocations.

While this appears to be a preparatory cleanup rather than the main bugfix, it's a good hygiene change that prevents memory leaks in the shallow commit processing code. The change is minimal (just one line added) and clearly correct, touching only shallow.c. This sets the stage for the more substantial changes in patch 2 that will address the core relative-depth fetching issue mentioned in the thread summary.
