Performance optimization for promisor object handling in partial clones. This is the second patch in a v3 series that improves the efficiency of `--exclude-promisor-objects` by skipping unnecessary hash verification when building the set of promisor objects.

The patch modifies `add_promisor_object()` in `packfile.c` to use `parse_object_with_flags()` with `PARSE_OBJECT_SKIP_HASH_CHECK` instead of `parse_object()`. This avoids decompressing and verifying the hash of each object when initializing the promisor object set, which is particularly beneficial for repositories with large pack files. The commit message includes compelling benchmarks showing a dramatic speedup - from 76 minutes down to just over 2 minutes for a real-world case with a 176GB promisor pack.

This change builds on the first patch in the series (which extended skip-hash optimization to `OBJ_NONE` objects) by applying the optimization to the promisor object initialization path. The implementation is minimal (just 3 lines changed) and focused, maintaining all existing behavior while optimizing the common case where promisor objects are accessed but their contents aren't needed. The patch appears well-constructed with clear motivation and measurable impact.
