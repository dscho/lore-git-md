This is a discussion about backward compatibility in Taylor Blau's MIDX compaction series, specifically regarding pack ordering requirements in multi-pack indexes.

The thread centers on patch 09/17 which relaxes the lexicographic ordering requirement for packs in MIDX files. Patrick Steinhardt had previously raised concerns about how this change might break other Git implementations like libgit2 that assume strict ordering. Taylor now agrees this warrants a MIDX format version bump to maintain compatibility.

In this follow-up, Taylor considers and rejects an alternative approach using a new MIDX chunk to specify custom ordering, recognizing it would still cause problems for bitmap handling in clients that support MIDX bitmaps. The discussion shows careful consideration of ecosystem impact beyond core Git, with Taylor explicitly prioritizing avoiding breakage in bitmap-capable clients regardless of libgit2's current capabilities.

This exchange solidifies the decision to increment the MIDX version number as the proper solution, demonstrating the project's attention to maintaining compatibility while evolving core functionality. The technical depth and consideration of edge cases reflects well on both the patch author and reviewer.
