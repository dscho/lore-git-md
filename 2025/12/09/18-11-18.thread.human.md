This thread covers Samo Pogačnik's two-patch series (now at v3) improving shallow repository handling in Git. The first patch fixes a memory leak in `get_shallow_commits()` that was caught by leak-checking tests, while the second implements correct relative-depth fetching (`--deepen`) when working with merged branches. 

The series has seen thorough review from both Patrick Steinhardt (focusing on technical correctness) and Junio C Hamano (who suggested documentation improvements). The v3 iteration unifies depth calculation logic, properly handles graft points, and includes comprehensive test coverage in t5500-fetch-pack.sh. A key addition is the new `get_shallows_depth()` function that tracks minimum depths of existing shallow commits using a `commit_depth` slab.

After multiple rounds of review addressing both implementation details and documentation formatting, the patches appear ready for integration. The changes are well-contained within shallow.c and upload-pack.c, with the test suite confirming the fixes work as intended. The memory leak fix is particularly valuable as it addresses a real issue caught by CI, while the relative-depth implementation improves functionality for users working with shallow clones.
