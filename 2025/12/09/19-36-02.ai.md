This is a preparatory refactoring patch for the `git repo info --keys` feature series. It introduces a `FORMAT_DEFAULT` enum value to cleanly handle the default output format case, which will be used by subsequent patches in the series.

The patch makes three main changes to `builtin/repo.c`:
1. Adds `FORMAT_DEFAULT` as the first enum value in `output_format`
2. Initializes the format variable to `FORMAT_DEFAULT` rather than hardcoding `FORMAT_KEYVALUE`
3. Adds parsing for a "default" format string (though this isn't yet exposed to users)

The implementation maintains backward compatibility by silently converting `FORMAT_DEFAULT` to `FORMAT_KEYVALUE` during execution, which matches the previous hardcoded behavior. This sets up the infrastructure needed for the later `--keys` flag implementation to properly handle format options.

The changes are straightforward and well-contained, with the commit message clearly stating this is groundwork for future patches. The diff shows careful attention to maintaining existing behavior while adding the new enum value in a logical position (first in the list, making it the 0-value default). This appears to be a clean, incremental improvement to support the larger feature work.
