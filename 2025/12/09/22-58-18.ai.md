This is patch 4/6 in a series enhancing Git's `repo structure` command with object size reporting. It adds human-readable inflated size metrics to the table output format, completing functionality started in earlier patches.

The patch introduces a new `stats_table_size_addf()` function that formats size quantities with appropriate scaling (B/KiB/MiB/GiB) and decimal precision. The implementation handles unit conversion with careful rounding (adding small offsets before division to get proper rounding behavior) and maintains the existing table formatting style. Inflated sizes are now shown both in aggregate and per-object-type (commits, trees, blobs, tags) under the "Reachable objects" section.

Key technical elements:
- New constants: `unit_B`, `unit_KiB`, `unit_MiB`, `unit_GiB` for unit suffixes
- Size formatting logic in `stats_table_size_addf()` with thresholds at 1KiB, 1MiB, 1GiB
- Integration with existing `stats_table` infrastructure via new calls in `stats_table_setup_structure()`
- Test updates showing both empty repository output and a populated case with SHA1-specific size expectations

The implementation maintains consistency with previous patches by keeping keyvalue/nul formats unchanged while only modifying table output. The test demonstrates expected formatting for both small (0 B) and large (16.03 MiB) values, though the populated test case remains SHA1-specific like earlier tests in the series. This appears to be building toward comprehensive size reporting that will likely be completed in the remaining patches (5-6).
