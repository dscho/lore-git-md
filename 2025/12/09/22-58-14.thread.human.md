This thread introduces a 6-part patch series enhancing Git's `repo structure` command with detailed object size reporting, covering both inflated content sizes and on-disk storage sizes. The series progresses methodically, with each patch building on the last to refactor infrastructure, add new capabilities, and improve output formatting.

The implementation introduces several technical elements: new structs like `object_values` and `object_stats` (now tracking both inflated and disk sizes), size collection via `odb_read_object_info_extended()` and `oi.disk_sizep`, and careful formatting with human-readable units (k/M/G for counts, KiB/MiB/GiB for sizes). The final patch completes the work by adding disk size metrics to the human-readable table output, mirroring the structure used for inflated sizes. Tests verify the output structure while gracefully handling platform variance in disk sizes.

The series maintains a clean separation between machine-readable (keyvalue/nul) and human-readable (table) output formats while sharing collection infrastructure. It focuses solely on `repo structure` enhancements without modifying core object storage behavior.
