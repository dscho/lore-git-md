This thread covers Justin Tobler's patch series enhancing Git's `repo structure` command with comprehensive object size reporting, including both inflated content sizes and on-disk storage sizes. The series has been merged by Junio Hamano after incorporating feedback from reviewers like Patrick Steinhardt and resolving conflicts with Lucas Seiki Oshiro's work on format handling.

The implementation introduces new infrastructure for tracking and displaying object statistics, with careful attention to output formatting (supporting both machine-readable and human-readable formats), internationalization, and test coverage. Key technical elements include new structs for storing size information, precise unit handling (using decimal SI units for counts and binary IEC units for sizes), and robust verification methods including cross-checking with `git rev-list --disk-usage`.

In the latest exchange, Justin responds to Junio's suggestion about reusing the existing `strbuf_humanise_bytes()` helper for count formatting. While acknowledging the value of code reuse, Justin explains that the current implementation's table alignment requirements necessitated a different approach. He indicates plans to refactor in a way that can share some underlying logic while maintaining the precise output formatting needed for the command's human-readable table display. This continues the thread's pattern of carefully considering both implementation quality and user-facing presentation.
