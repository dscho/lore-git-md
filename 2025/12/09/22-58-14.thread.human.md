This thread introduces a 6-part patch series extending Git's `repo structure` command with new reporting capabilities. The series begins with infrastructure refactoring in patch 1, then adds human-friendly number formatting in patch 2, and now introduces inflated object size reporting in patch 3.

Patch 3 adds the ability to report the total content size (inflated size) of objects by type (commits, trees, blobs, tags) in the machine-readable keyvalue and nul output formats. The implementation carefully tracks sizes during object traversal using `odb_read_object_info_extended()` and stores them in a new `inflated_sizes` field that parallels the existing type counts. Tests verify the basic functionality, though they're currently SHA1-specific.

The series is progressing logically from counting objects to enhancing output formats to now adding size metrics. The changes remain well-contained to the `repo structure` subcommand without modifying core object handling. No reviews or feedback from other contributors have been shared yet, but the patches appear carefully structured with clear commit separation. The next patches in the series will presumably build on this foundation, possibly adding on-disk size reporting and human-readable table formatting for the new size metrics.
