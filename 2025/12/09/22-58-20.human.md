This is the final patch in a 6-part series enhancing Git's `repo structure` command with detailed object size reporting. The patch adds disk size metrics to the human-readable table output, completing the functionality introduced in previous patches.

The change mirrors the existing inflated size reporting but shows the on-disk storage usage for each object type (commits, trees, blobs, tags). Since disk sizes can vary across platforms, the tests only verify that the size fields appear in the output rather than checking specific values. A new test helper `strip_object_disk_usage()` filters out these platform-dependent values when comparing output.

The implementation builds on the series' existing infrastructure, adding disk size totals and per-type breakdowns to the structured table output. This maintains consistency with the earlier inflated size reporting while acknowledging platform differences in the test suite. The patch follows the series' pattern of careful separation between output formats and shared collection logic.

With this patch, the series now provides both inflated content sizes and on-disk storage metrics in all output formats (table, keyvalue, and nul), giving users comprehensive visibility into repository object storage characteristics. The implementation appears clean and well-tested, with appropriate handling of platform-specific variations.
