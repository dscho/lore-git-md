This is a follow-up in the ongoing thread about macOS's broken iconv implementation affecting character encoding conversion in Git. Torsten Bögershausen responds to René Scharfe's earlier report of test failures in t3900 when converting ISO-2022-JP to UTF-8 on macOS.

Torsten proposes an alternative fix to René's ICONV_BREAKS workaround, specifically targeting macOS systems via `#ifdef __APPLE__` rather than a configurable make variable. The key differences are:
1. It removes the explicit `iconv(NULL...)` state reset that René included
2. It tracks the original input size separately rather than recomputing it
3. It applies automatically on macOS rather than requiring manual configuration

The patch maintains the same core approach of restarting the conversion from scratch when the buffer needs to grow, but with a simpler implementation focused specifically on the known-broken platform. This appears to be a refinement rather than a fundamentally different solution, though the thread context suggests the broader discussion has already established that this is a platform bug rather than a Git issue needing a complex fix.
