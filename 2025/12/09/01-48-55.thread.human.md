This thread focuses on performance optimizations for partial clone workflows, specifically improving how Git handles promisor objects with `--exclude-promisor-objects`. The series, now at v3, comes from a contributor targeting two key bottlenecks in promisor object processing.

The core optimization extends Git's existing `PARSE_OBJECT_SKIP_HASH_CHECK` behavior - which previously worked only for known blob and tree objects - to also handle cases where the type is initially unknown (`OBJ_NONE`). This change, implemented in `object.c`, skips expensive hash verification when we only need to track object presence rather than contents. A second patch applies the same optimization to `add_promisor_object()` in `packfile.c`, dramatically speeding up promisor pack initialization (from 76 minutes down to 2 minutes in one real-world 176GB pack case).

The changes are minimal (4 and 3 lines respectively) but impactful, maintaining all existing behavior while optimizing the common case where promisor objects are accessed but their contents aren't needed. The series builds cleanly on prior work (commit 8db2dad7a045) and appears ready for merging, with v3 indicating previous feedback has been addressed. The commit messages clearly explain both the current limitations and the optimization opportunities, with concrete benchmarks showing the real-world benefits.
