This is the second patch in a series fixing issues with shallow repository fetching. It addresses a bug where relative-depth fetches (`--deepen`) in repositories with merged branches could leave some shallow commits incorrectly positioned behind reachable ones. The patch unifies the handling of absolute and relative deepening by introducing a new `get_shallows_depth()` function that calculates equivalent depths for existing shallow commits.

The key change replaces the previous `get_reachable_list()` approach with a more direct depth calculation that works for both absolute and relative cases. The new function examines the current shallow commits to determine their depth in the remote repository, then uses this to properly position new shallow commits during relative-depth fetches. The patch includes a new test case that demonstrates the fixed behavior when fetching beyond a merged branch.

The changes are focused in upload-pack.c, with significant restructuring of the deepening logic. While the patch is somewhat complex due to the nature of shallow clone internals, it appears well-motivated by the test case showing incorrect behavior, and the solution follows the pattern of Git's existing absolute-depth handling. This is the more substantial half of the series, following the preparatory memory leak fix in patch 1.
