This is a platform compatibility patch addressing the macOS iconv regression discussed in the ongoing thread. René Scharfe proposes a workaround that uses Homebrew's libiconv instead of the system's broken iconv implementation on macOS 15+ systems.

The patch modifies `config.mak.uname` to detect Homebrew's libiconv installation in either `/opt/homebrew/opt/libiconv/` or `/usr/local/opt/libiconv/`, setting `ICONVDIR` accordingly. This builds on the thread's established context about macOS 15+ having a broken iconv implementation for stateful encodings like ISO-2022-JP, which causes test failures in t3900.

This approach differs from the two previously discussed code-based workarounds (ICONV_BREAKS flag vs platform-specific state reset) by avoiding the problematic system iconv entirely when a known-good alternative is available. The patch is minimal and focused, though it doesn't address cases where Homebrew isn't installed. It represents a third potential solution path in the ongoing discussion about handling macOS's iconv regression.
