This is a technical follow-up in the macOS iconv(3) regression thread, focusing on implementation details of the workaround. René Scharfe responds to Torsten Bögershausen's alternative patch proposal, pointing out two critical omissions that cause test failures: the lack of state reset for the iconv converter and incorrect outsz handling. The discussion remains focused on the platform-specific workaround for macOS 15's broken stateful encoding conversion during buffer growth in `reencode_string_iconv()`.

Key technical points in this exchange:
- René confirms the purpose of `iconv(conv, NULL, NULL, NULL, NULL)` is to reset converter state between buffer growth operations, which is essential for stateful encodings like ISO-2022-JP
- Torsten's alternative approach using `__APPLE__` instead of `ICONV_BREAKS` and tracking original input size (`originsz`) is found to be incomplete
- The missing state reset in Torsten's version causes t0028-working-tree-encoding.sh to enter an infinite loop, demonstrating the practical consequences
- Both proposals still share the core approach of retrying full-string conversion after buffer growth, differing mainly in platform detection method and state management

The thread continues narrowing the solution space, with René's response providing concrete feedback on implementation requirements. The core issue remains Apple's platform regression in iconv(3) state handling during buffer growth operations, with Git needing a workaround specifically for macOS 15+.
