This is a platform compatibility patch addressing the macOS iconv regression discussed in the ongoing thread. René Scharfe proposes a workaround for the broken ISO-2022-JP to UTF-8 conversion in macOS 15+ by detecting and using Homebrew's libiconv when available.

The patch modifies `config.mak.uname` to check for Homebrew's libiconv installation in two standard locations (`/opt/homebrew/opt/libiconv/` and `/usr/local/opt/libiconv/`), setting `ICONVDIR` if found. This provides an alternative to the problematic system iconv implementation that was causing test failures in t3900.

The approach is straightforward and builds on the thread's established understanding that this is a macOS platform issue rather than a Git bug. It offers a practical solution for developers who use Homebrew, though it doesn't address the underlying system iconv problem or provide a solution for non-Homebrew users. The patch is cleanly implemented with clear conditional checks and maintains existing build system conventions.
