Feature enhancement to Git's `repo structure` command, adding inflated object size reporting. This is patch 3/6 in a series extending repository structure analysis capabilities.

The patch introduces size tracking for objects in their inflated (content) form, adding this information to the keyvalue and nul output formats of `git repo structure`. It builds on the object counting infrastructure from earlier patches by adding a parallel `inflated_sizes` field to the `object_stats` struct that tracks cumulative sizes per object type (commit, tree, blob, tag).

Key technical elements:
- New `inflated_sizes` field in `object_stats` mirroring the existing type counts
- Size collection via `odb_read_object_info_extended()` during object traversal
- Output fields like `objects.commits.inflated` added to keyvalue format
- Test updates verifying size output (SHA1-specific for now)
- Documentation update noting the new size reporting capability

The implementation handles the object database interaction carefully, using proper error handling when reading objects. The test demonstrates the expected output format and verifies basic functionality, though it's currently SHA1-specific (a potential portability consideration for future work). The patch maintains the series' clean separation between machine-readable (keyvalue/nul) and human-readable (table) output formats, with table support planned for a subsequent patch.

This continues the series' logical progression from counting objects (patch 1) to enhancing output (patch 2) to now adding size metrics. The changes are well-contained to the `repo structure` subcommand without affecting core object handling.
