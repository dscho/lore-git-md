This is a bugfix patch series addressing an issue with shallow repository fetches when using relative depth specifications. The problem occurs when deepening a shallow clone beyond the start of a merged branch, which can leave some shallow commits incorrectly marked as unreachable.

The first patch is a minor memory leak fix, freeing local allocations in the shallow code. The second and main patch reworks how relative depth calculations are handled during fetch. It introduces a new `get_shallows_depth()` function to properly compute depths for existing shallow commits, unifying the handling of absolute and relative depth specifications. The change ensures consistent behavior between the two depth specification methods.

The series includes a new test case that demonstrates the original issue and verifies the fix. The approach appears well-reasoned, with the author noting that absolute depth fetches already worked correctly, and adapting that logic to handle relative depth cases. The patch touches core shallow clone functionality in `upload-pack.c` and adds test coverage in `t5500-fetch-pack.sh`.

This looks like a solid contribution addressing a real edge case in shallow clone behavior. The explanation is clear and the solution appears to maintain consistency with existing behavior while fixing the problematic case.
