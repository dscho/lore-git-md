Platform compatibility issue with macOS 15+ iconv implementation affecting character encoding conversion. This is a follow-up to René Scharfe's report of test failures in t3900 when converting ISO-2022-JP to UTF-8 on macOS 26.1. Koji Nakamaru confirms the problem occurs on macOS 15.7.2 but not 14.8.2, suggesting a regression in newer macOS versions. The issue appears when `reencode_string_iconv()` needs to grow its buffer during conversion, causing the macOS iconv implementation to lose state for the stateful ISO-2022-JP encoding.

Nakamaru verifies that René's proposed workaround (the ICONV_BREAKS patch) resolves the issue, as does using Homebrew's libiconv instead of the system version. The findings help confirm this is specifically a macOS 15+ regression rather than a general Git bug, and suggest viable workarounds for affected systems. The thread continues to explore platform-specific solutions while maintaining correct behavior across all systems.
