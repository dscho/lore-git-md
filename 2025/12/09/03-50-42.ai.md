This is a follow-up in the macOS iconv encoding conversion thread, adding context about Apple's iconv implementation changes. Yee Cheng Chin notes their surprise that the t3900 tests pass on macOS 14.8.2 with the native iconv, given that Apple replaced GNU iconv with a custom version in macOS 14 which caused other breakages. They suggest this indicates the stateful encoding issue is specifically a new regression in macOS 15 rather than a general problem with Apple's custom iconv. The email reinforces that using Homebrew's libiconv via ICONVDIR remains a viable workaround, while adding the observation that Apple's iconv changes in macOS 14 didn't trigger this particular test failure, helping further narrow the regression window to macOS 15 specifically. The technical context remains focused on `reencode_string_iconv()`'s handling of stateful encodings during buffer growth operations.
