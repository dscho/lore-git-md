This is a follow-up in the macOS iconv encoding conversion thread, adding historical context about Apple's iconv changes. Yee Cheng Chin notes they're surprised the tests pass on macOS 14.8.2, since Apple replaced GNU iconv with their own implementation in that version, which caused other third-party software breakages. They suggest the current test failures might indicate a new regression specifically in macOS 15's iconv rather than being inherent to Apple's replacement.

The email confirms the Homebrew libiconv workaround (via ICONVDIR) as a viable solution, while providing useful context about the broader ecosystem impact of Apple's iconv changes. This helps reinforce the thread's consensus that this is a platform regression rather than a Git bug, though it raises the interesting point that the breakage might be more recent (macOS 15-specific) than initially thought.
