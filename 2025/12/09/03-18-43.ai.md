This is a platform compatibility issue affecting character encoding conversion on macOS. The thread continues investigating the ISO-2022-JP to UTF-8 conversion failures in t3900 tests, where macOS's iconv implementation loses state between buffer growth operations in `reencode_string_iconv()`.

Koji Nakamaru provides additional test results showing the problem appears in macOS 15.7.2 but not in 14.8.2, confirming René Scharfe's findings about the platform-specific nature of the issue. The tests pass either with René's ICONV_BREAKS workaround (which forces full-string reconversion when buffer growth is needed) or when using Homebrew's libiconv instead of the system version.

The email reinforces that this is a macOS regression rather than a Git bug, with the problematic behavior appearing in macOS 15+. The workaround options now include both a compile-time flag (ICONV_BREAKS) and runtime configuration (ICONVDIR pointing to Homebrew's libiconv). This helps establish the scope of affected systems and validates the proposed solutions.
