This is the second patch in a 2-patch series fixing issues in shallow repository fetching, specifically addressing relative-depth fetching (`--deepen`) in repos with merged branches. The patch unifies the handling of absolute and relative deepening by introducing a new `get_shallows_depth()` function that calculates equivalent depths for existing shallow commits, making `get_reachable_list()` redundant.

The core change replaces the previous dual-path logic (which treated absolute and relative deepening separately) with a unified approach where relative deepening first calculates the equivalent depth of existing shallow commits via `get_shallows_depth()`, then uses the same `get_shallow_commits()` path as absolute deepening. The new function implements depth calculation by walking commit parents while tracking minimum depths, storing the result in `data->deepen_relative`.

Key technical details include: a new `commit_depth` slab for tracking depths during the walk, careful handling of graft points in shallow history, and removal of the now-unused `get_reachable_list()` function. The patch adds a test case that demonstrates the fixed behavior when fetching beyond merged branches, verifying that no shallow commits remain behind reachable ones.

The changes affect upload-pack.c (major logic restructuring) and add a test in t5500-fetch-pack.sh. The solution appears well-motivated by the test case showing incorrect behavior with merged branches, and the implementation carefully preserves the shallow/non-shallow boundary calculations while eliminating redundant code paths. Reviewers will want to verify the depth calculation logic in `get_shallows_depth()`, particularly around edge cases of graft points and multiple parent handling.
