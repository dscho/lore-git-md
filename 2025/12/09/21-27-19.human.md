This is a follow-up in the ongoing macOS iconv encoding issue thread, addressing platform-specific build system considerations.

René Scharfe responds to Yee Cheng Chin's concern about Rosetta 2 compatibility in the Homebrew libiconv detection approach. The current patch already handles the architecture priority correctly by preferring native ARM64 Homebrew installations (in /opt/homebrew) over x86-64 ones (in /usr/local) when both are present. For users who only have the x86-64 version installed under Rosetta, the patch will use that as a fallback, following the same pattern Git already uses for gettext.

The response also clarifies that users can still want to use the system's broken iconv implementation can explicitly override the detection by manually setting ICONVDIR to point to the system headers. This maintains flexibility while defaulting to the more reliable Homebrew version when available.

The exchange shows the solution is maturing with attention to edge cases, though the core approach remains using Homebrew's libiconv as a workaround for macOS 15's encoding conversion bugs when possible. The thread continues to show careful consideration of real-world deployment scenarios across different Mac architectures and installation methods.
