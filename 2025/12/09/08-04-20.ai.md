This is a discussion follow-up in Patrick Steinhardt's refactoring series for Git's object database alternates handling, specifically addressing feedback on patch 2/8.

Patrick clarifies his intent to move alternate ODB source handling into the ODB source abstraction generally, not just the primary source, since alternates are recursive by nature. The key motivation is to support non-filesystem-based ODB sources that may need alternate handling without assuming filesystem access.

In response to Justin Tobler's naming suggestion, Patrick agrees that `odb_add_alternate_source()` would be more precise than the originally proposed `odb_add_source()`, since the function specifically handles alternate sources. This resolves one of the open questions from the thread summary about naming conventions.

The exchange confirms the technical direction while refining the implementation details, showing constructive collaboration on this refactoring effort. No new technical concerns are raised - the discussion remains focused on naming clarity for the new abstraction being introduced. This moves the thread forward with consensus on how to proceed with the alternate source handling implementation.
