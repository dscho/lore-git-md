This is a technical discussion about backward compatibility in Taylor Blau's MIDX compaction series, specifically patch 09/17 which relaxes lexicographic pack ordering requirements.

The exchange focuses on whether the change requires bumping the MIDX format version number. Patrick Steinhardt raised concerns that other Git implementations (like libgit2) currently assume sorted pack lists and would break with the relaxed ordering. Taylor initially wanted to avoid version bumps for what seemed like a minor change, but now agrees the compatibility risk warrants a version increment.

The discussion reveals important context about how MIDX format changes affect not just Git itself but also alternative implementations. Taylor confirms the technical impossibility of MIDX packs changing order after creation, addressing Patrick's secondary question about runtime modifications. This thread shows the careful consideration being given to cross-ecosystem impacts in the MIDX compaction work.
