Feature enhancement for `git status` showing divergence from push target branch, now using existing tracking mechanisms. This is the final patch in a 10-iteration series that has evolved significantly based on maintainer feedback.

The patch removes the previously proposed `status.goalBranch` configuration in favor of using Git's existing branch tracking infrastructure. It now shows divergence from the push target (determined by `branch.<name>.pushRemote` or the tracking branch) when that differs from the regular upstream branch. The implementation reuses much of the existing tracking info machinery while adding the new comparison logic.

Key technical changes:
- Replaces `get_goal_branch_ref()` with `get_remote_push_branch()`
- Renames `format_goal_branch_comparison()` to `format_push_branch_comparison()`
- Updates all related test cases to verify the new behavior
- Maintains the same output format but with push branch instead of configured goal

The test suite has been significantly streamlined (296 lines removed) while maintaining coverage of all scenarios. Tests now verify behavior with:
- Push remotes vs tracking branches
- Diverged states between local, tracking, and push branches
- Various branch configurations (ahead, behind, diverged)
- Edge cases like unset/malformed branches

This represents the culmination of the series' evolution, having addressed Junio Hamano's concerns about adding new configuration by instead leveraging Git's existing branch tracking mechanisms. The implementation appears clean and well-tested, with the test suite providing thorough verification of the new behavior.
