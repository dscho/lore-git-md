This is part 4 of a 5-patch bugfix series improving `git replay`'s error handling when given invalid commit-ish inputs. The series, now in its second version, addresses confusing error messages and validation issues in the `--onto` and `--advance` options.

This specific patch switches from `parse_object()` to `parse_object_or_die()` in the `peel_committish()` function, ensuring immediate failure with a descriptive error message when an invalid object is encountered. The change was suggested by Junio Hamano and follows the series' architectural direction of moving error handling to callers for better specificity.

The change is straightforward - a one-line modification that replaces the silent NULL return with an explicit die() call when object parsing fails. This eliminates the need for NULL checks at call sites while maintaining the same validation behavior. The patch builds on earlier work in the series that restructured validation flows and improved error messages.

As with the rest of the series, this change appears well-considered and properly motivated, with clear attribution to the reviewer who suggested the approach. The implementation is cleanly integrated with the surrounding code and maintains the series' focus on robust error handling.
