Jon Forrest asked how `git log --reverse` implements oldest-to-newest commit ordering, given that Git's commit parent pointers naturally support newest-to-oldest traversal. He wondered whether commit list data structures were involved in reversing the order, noting the lack of explanatory comments in the code.

Junio C Hamano provided the key insight: `--reverse` works in two phases. First, it collects commits in forward order (newest-to-oldest) using the standard traversal mechanism in `get_revision_internal()`, storing them in a queue. Only after completing this forward traversal does it output the commits in reverse order from the queue. This explains how parent pointer-based traversal can produce oldest-to-newest output - by buffering commits during initial traversal rather than walking the graph in reverse directly. The `.commits` list serves as the key data structure enabling this behavior. Junio's response confirms Jon's suspicion about commit lists being involved and provides the architectural understanding Jon was seeking.
