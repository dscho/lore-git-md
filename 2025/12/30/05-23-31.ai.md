Junio Hamano identifies a subtle inaccuracy in the description of `git reset -p` behavior. The current wording suggests chosen changes are always "added" to the index, but the actual behavior depends on whether the operation targets HEAD or another commit. Against HEAD, it unstages changes (removing from index), while against other commits it stages changes toward that commit (adding to index). The proposed fix would describe the operation more neutrally as "modifying the index using the chosen hunks" rather than specifying direction. This matches the command's actual behavior where the prompt wording changes contextually between "unstage" and "apply" based on the target.
