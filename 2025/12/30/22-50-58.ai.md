Refactoring patch in the `git replay` error handling series. This is patch 1/5 in v2 of the series, focusing on dead code removal and function reorganization in `builtin/replay.c`. The patch removes legacy code paths from when `--onto` and `--advance` options were optional (now mandatory) and renames the function from `determine_replay_mode` to `populate_for_onto_or_advance_mode` to better reflect its current behavior. 

Key technical changes:
- Eliminates dead code branch that handled implicit mode determination
- Combines conditional logic since `advance_name` is never set in this function
- Adds a BUG() assertion for invalid state that should be impossible
- Preserves all functional behavior while simplifying the control flow

Elijah Newren suggests the new function name might be too verbose and proposes `setup_replay_mode()` as an alternative, while approving the technical changes. The patch maintains the series' direction of cleaning up error handling architecture while removing obsolete code paths from earlier iterations of the command. This foundational cleanup enables subsequent patches to focus on validation and error message improvements.
