This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than scanning the working directory.

The patch addresses feedback from two previous PR attempts (#1352 and #1667), fixing issues like GPLv3 code concerns, memory leaks, unsafe hashmap iteration, and portability problems. Key technical details include using inotify with recursive directory monitoring, special handling for directory renames via IN_MOVED_FROM/TO event cookies, maintaining bidirectional watch descriptor <-> path mappings using hashmap, and detecting/rejecting remote filesystems (NFS/SMB) via statfs() unless explicitly allowed.

The implementation shows thorough attention to edge cases and includes fixes for a newly discovered memory leak during daemon initialization that was caught by LeakSanitizer in test case t7527. Documentation covers inotify watch limits and expands fsmonitor.socketDir support to Linux. The patch requires pthreads and Unix domain socket support, enabled via FSMONITOR_DAEMON_BACKEND=linux and FSMONITOR_OS_SETTINGS=linux build configurations.

This appears to be a well-crafted and complete implementation that has undergone significant review iteration. The commit message provides detailed technical explanations of design decisions and review feedback incorporation. The only remaining open issue appears to be the newly identified memory leak, which has been precisely located but not yet fixed in this version.
