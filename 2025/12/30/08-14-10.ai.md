This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify. The implementation brings Linux to parity with existing Windows and macOS fsmonitor backends, enabling faster status operations by watching filesystem events rather than scanning the working directory.

The key technical aspects include:
- Uses inotify to monitor directories recursively, with special handling for directory renames via IN_MOVED_FROM/TO event cookies
- Maintains bidirectional mappings between watch descriptors and paths using hashmap
- Detects remote filesystems (NFS, SMB etc) via statfs() and rejects them unless explicitly allowed
- Falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is on a remote filesystem
- Adds build configuration via FSMONITOR_DAEMON_BACKEND=linux and FSMONITOR_OS_SETTINGS=linux
- Requires pthreads and Unix domain socket support (NO_PTHREADS/NO_UNIX_SOCKETS unset)

The patch addresses feedback from two previous PR attempts (#1352 and #1667), fixing issues around GPLv3 code, memory leaks, unsafe hashmap iteration, null checks, and portability concerns. It adds documentation about inotify watch limits and expands fsmonitor.socketDir support to Linux.

The implementation appears thorough, with careful attention to edge cases like directory renames and remote filesystems. Test coverage includes the fsmonitor test suite and manual verification of behavior on local and remote filesystems. The commit message provides detailed technical explanations of the design decisions and changes made in response to prior reviews.
