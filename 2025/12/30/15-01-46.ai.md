This is a bugfix and test coverage series for `git replay`'s handling of invalid commit-ish arguments. The v2 series from Kristoffer Haugsbakk builds on previous discussion to improve error messages and remove dead code while adding more test coverage.

Key technical changes in v2:
- Removes dead code in `determine_replay_mode()` that was a remnant from when options weren't mandatory
- Restructures error handling to provide more specific messages by moving validation to callers
-onto` and `--advance` paths
- Uses `parse_object_or_die()` for more robust object handling
- Adds several new test cases covering mandatory options, root commits, option conflicts, and merge commits
- Fixes a test case that was losing exit status due to piping through `head`

The series now has 5 patches:
1. Removes dead code and reorganizes `determine_replay_mode()` into `populate_for_onto_or_advance_mode()`
2. Moves `--advance` reference validation before commit peeling
3. Improves error messages when invalid commit-ish is given
4. Uses `parse_object_or_die()` for object parsing
5. Adds comprehensive test coverage for failure conditions

The changes address previous feedback from Junio Hamano and Phillip Wood about error handling architecture and test robustness. The series appears well-tested with thorough commit messages explaining each change. The dead code removal and validation restructuring clean up technical debt while the expanded test coverage helps prevent regressions.
