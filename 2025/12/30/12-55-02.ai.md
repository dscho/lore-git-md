This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The patch represents the third iteration of this work, addressing feedback from PRs #1352 and #1667 while fixing newly discovered issues.

The implementation uses inotify to monitor filesystem events, with special handling for directory renames via IN_MOVED_FROM/TO event cookies. It maintains bidirectional watch descriptor <-> path mappings using hashmap and detects remote filesystems (NFS/SMB) via statfs(). The daemon falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is remote.

Key technical details include:
- Uses inotify_init1(O_NONBLOCK) for non-blocking monitoring
- Handles directory creation/deletion/renames dynamically
- Adds build configuration via FSMONITOR_DAEMON_BACKEND=linux and FSMONITOR_OS_SETTINGS=linux
- Requires pthreads and Unix domain socket support
- Documents inotify watch limits and expands fsmonitor.socketDir support to Linux

The patch fixes several issues identified in previous versions, including memory leaks, unsafe hashmap iteration, missing null checks, and portability concerns. It also addresses a newly discovered 512-byte leak in hashmap initialization during daemon startup. Test coverage includes the fsmonitor test suite plus manual verification on local/remote filesystems.

The implementation shows thorough attention to edge cases and appears ready for inclusion aside from the final memory leak issue. The commit message provides detailed technical explanations of design decisions and review feedback incorporation.
