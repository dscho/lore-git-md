This is the final patch (5/5) in a bugfix and test coverage series for `git replay` error handling. The patch adds several new regression tests to validate failure conditions that weren't previously covered.

The new tests verify:
- Mandatory requirement of either `--onto` or `--advance` options
- Error when attempting to replay down to root commit
- Incompatibility between `--advance` and `--contained` options
- Ill-defined ordering when advancing with multiple sources
- Current limitation on replaying merge commits

The test improvements address feedback from Phillip Wood about properly capturing return values and normalizing test output formatting. The test cases are designed to be simple and removable if the underlying behavior changes. The patch builds on earlier architectural changes in the series that restructured error handling and validation.

Key technical details:
- Tests use `test_must_fail` to properly check error conditions
- Error messages are captured in `expect` files for precise matching
- New test setup includes merge commits to validate the merge commit limitation
- Tests cover both option parsing and semantic validation cases

This completes the series' goal of robust error handling with comprehensive test coverage, addressing all feedback from earlier reviews. The tests validate the new error paths introduced in previous patches while adding new edge cases.
