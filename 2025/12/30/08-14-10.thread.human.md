This thread covers the implementation of Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The feature enables faster status operations by watching filesystem events rather than scanning the working directory.

The implementation has gone through four iterations, addressing feedback about GPL concerns, memory leaks, and portability issues. The current version includes recursive directory watching via inotify, special handling for directory renames, remote filesystem detection, and support for the meson build system. Paul Tarjan, the primary author, reports the code has been stable in production use for two months across a large deployment, providing real-world validation beyond the test suite.

Two small memory leaks remain (512 bytes during daemon startup and 40 bytes in IPC handling), but Junio Hamano has indicated these may not block merging if addressed in follow-up patches. The meson build support, contributed by Patrick Steinhardt, may be split out as a separate patch since Paul isn't familiar with meson and the CI failures appear unrelated to the core changes. With extensive testing and production validation, this long-running effort appears ready to merge after addressing the final minor issues.
