This thread introduces Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

The series has gone through seven iterations, with Patrick Steinhardt providing detailed technical review that helped address race conditions, memory leaks, and edge cases around directory watch registration and cleanup. The current version (v7) is stable in Junio's 'seen' branch, with Paul Tarjan reporting production stability in large deployments. Key technical improvements include proper handling of directory renames via inotify event cookies, remote filesystem detection, and a new timeout mechanism to prevent hangs on container filesystems.

The final patch focuses on process management reliability, particularly for CI/test environments. It introduces a `close_fd_above_stderr` flag to prevent inherited file descriptor issues in long-running daemons, and ensures proper process group handling via `setsid()` to avoid shell job control hangs. These changes complete the implementation by addressing the last edge cases for production readiness. The series now includes comprehensive test coverage, including new stress tests for concurrent operations and event delivery verification.

With all review feedback addressed and the implementation stable across platforms, this work is ready for merging. The Linux fsmonitor backend represents a significant performance improvement for status operations on Linux systems while maintaining consistency with the behavior of existing platforms.
