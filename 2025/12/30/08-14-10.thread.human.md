This thread introduces Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS implementations. The feature enables faster status operations by watching filesystem events rather than performing full directory scans.

The implementation has gone through five iterations, with Paul Tarjan and Patrick Steinhardt collaborating to address technical feedback. The current version includes recursive directory watching via inotify, proper handling of directory renames, and safeguards against remote filesystems. After initial concerns about splitting meson build support into a separate patch, the team now agrees it works better integrated.

While the implementation has been stable in production for two months, a new CI failure has emerged unrelated to the core functionality. The team considers this a minor issue to resolve, as the only remaining known problems are two small memory leaks (512 bytes at startup and 40 bytes during IPC handling) that are non-critical. Patrick Steinhardt has completed his review of v5 and confirms all major technical concerns have been addressed.

The patch appears ready for merging pending resolution of the CI issue and final approval from Junio Hamano. This would complete cross-platform fsmonitor support after extensive review across five versions, building on prior work by Eric DeCosta and Marziyeh Esipreh.
