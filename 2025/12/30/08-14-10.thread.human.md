This thread covers the ongoing work to add Linux inotify support for Git's filesystem monitoring (fsmonitor), bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

The technical implementation is now stable in Junio's 'seen' branch after seven iterations, with Paul Tarjan and Patrick Steinhardt being the primary contributors. The current version addresses race conditions, memory leaks, and portability issues while adding comprehensive test coverage. Key improvements include a new timeout mechanism for inotify cookie waits, Windows pthread compatibility fixes, and consolidation of Unix domain socket handling between macOS and Linux.

Patrick Steinhardt's latest review focuses on process management in the fsmonitor daemon, specifically around file descriptor inheritance and process groups. Paul's patch introduces a `close_fd_above_stderr` flag to prevent unwanted descriptor inheritance and calls `setsid()` when daemonizing. Patrick suggests reusing existing `daemonize()` functionality and questions whether some changes should be split into separate commits for clarity.

Several open questions remain regarding memory management in the cookie hashmap, Windows pthread implementation details, test reliability, and commit organization. While the technical work appears complete, Patrick's thorough review continues to surface opportunities for refinement in code structure and documentation. The patch series is nearing readiness for final submission, with only minor cleanup and justification of design choices remaining.
