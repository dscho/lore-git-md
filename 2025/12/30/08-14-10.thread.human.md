This thread covers the implementation of Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing it to parity with existing Windows and macOS backends. The technical work is largely complete, with the implementation now stable in Junio's 'seen' branch. Key aspects include recursive directory watching via inotify, proper handling of directory renames, remote filesystem detection, and cross-platform process management. The latest patches have addressed memory leaks, test reliability, and added comprehensive pthread compatibility for Windows.

Paul Tarjan, who has been testing the implementation in production, recently explained the rationale behind the 1-second timeout for inotify cookie waits. This timeout acts as a safety mechanism - normal operations complete in milliseconds, but the delay provides a graceful fallback to full scans if event delivery fails (as can happen with problematic filesystems like overlayfs). While this maintains correctness, Patrick Steinhardt has raised questions about whether the duration is optimal and whether test strategies might mask real issues. These appear to be the final open questions before the series can be submitted for merging. The implementation already includes significant improvements to test coverage and process management, with particular attention given to Windows compatibility through proper pthread_cond_timedwait() emulation.
