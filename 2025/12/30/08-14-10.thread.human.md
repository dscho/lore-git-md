This thread introduces Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux up to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than performing full directory scans.

The series is now in its eighth iteration, with the latest patch (6/12) renaming `fsm-settings-darwin.c` to `fsm-settings-unix.c` to reflect that the settings logic is shared across Unix platforms. This follows an earlier consolidation of the IPC implementation under the same naming scheme. The change updates build configurations to use the new `FSMONITOR_OS_SETTINGS` variable consistently.

Key technical work includes inotify integration with recursive directory watching, event synchronization with timeout handling, remote filesystem detection, and Unix domain socket support. The implementation maintains bidirectional watch descriptor mappings and includes comprehensive test coverage for event delivery and race conditions. Patrick Steinhardt's thorough reviews have helped address several technical concerns around race conditions, memory management, and test reliability.

The series is currently in Junio's 'seen' branch with all major technical issues resolved. Paul Tarjan has contributed Windows compatibility patches and reported production stability. Remaining open questions focus on refining Windows pthread error handling and validating the 1-second timeout duration for inotify cookie waits. The architectural work to unify Unix platform support while allowing for platform-specific components appears complete, with this patch finalizing the settings consolidation.
