This thread introduces Linux support for Git's filesystem monitoring (fsmonitor) using inotify, completing the platform coverage alongside existing Windows and macOS implementations. The feature enables faster status operations by watching filesystem events rather than scanning the working directory.

The implementation has undergone multiple iterations, with this third version addressing all previous feedback including GPLv3 concerns, memory leaks, and portability issues. Key technical aspects include recursive directory monitoring with inotify, special handling for directory renames, remote filesystem detection, and fallback IPC socket locations when .git is on a network mount. The patch adds Linux-specific build configuration options and requires pthreads and Unix domain socket support.

A newly discovered 512-byte memory leak during daemon initialization was identified by Junio Hamano during leak sanitizer testing. While this remains the sole outstanding issue, the implementation otherwise appears robust with thorough test coverage including the fsmonitor test suite and manual verification across different filesystem types. The commit message documents all design decisions and review feedback incorporation, showing the patch has matured through its three iterations.
