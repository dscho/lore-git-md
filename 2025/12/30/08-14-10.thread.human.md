This thread has reached a practical resolution regarding the interaction between Git's split-index feature and the index.skipHash setting (a Scalar default). The core issue stems from a fundamental incompatibility: split-index requires hash calculations while index.skipHash explicitly avoids them. 

Paul Tarjan proposed a test-focused solution - unsetting GIT_TEST_SPLIT_INDEX in affected scalar clone tests - which maintains existing fsmonitor and index behavior while avoiding the problematic feature combination in specific test cases. Johannes Schindelin had earlier raised design concerns about this feature clash, but the pragmatic test adjustment bypasses deeper architectural questions.

Junio Hamano, the Git maintainer, has now weighed in to confirm this approach. He concisely summarized the technical incompatibility and explicitly endorsed the test workaround, effectively settling the debate. The fsmonitor implementation itself remains unchanged and production-stable. This resolution represents a compromise between Johannes's preference for clear feature boundaries and Paul's focus on solving immediate test failures with minimal disruption.

The thread concludes with maintainer-approved consensus to handle this as a test suite limitation rather than modifying core behavior, leaving broader questions about Git's feature interaction design patterns for future discussion. The Linux filesystem monitoring implementation (fsmonitor) at the heart of the original discussion remains unaffected, with its production-validated v12 core including Linux inotify support, Windows compatibility layers, and container/overlayfs fixes all intact.
