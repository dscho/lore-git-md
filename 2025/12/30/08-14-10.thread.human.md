This thread introduces Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS implementations. The feature enables faster status operations by watching filesystem events rather than performing full directory scans.

The implementation, now in its fifth iteration, uses inotify with recursive directory watching and special handling for directory renames. It includes careful management of watch descriptors, remote filesystem detection, and fallback mechanisms when .git directory is on a remote filesystem. The patch has undergone extensive review across multiple versions, with all major technical concerns addressed. Paul Tarjan reports the implementation has been stable in production for two months across a large deployment.

Two small memory leaks remain (512-byte during startup and 40-byte in IPC handling) but are considered non-blocking. The latest version includes meson build system integration and fixes for crashes during rapid nested directory creation. While Junio Hamano initially suggested splitting the meson support into a separate patch, both Paul Tarjan and Patrick Steinhardt now recommend keeping it integrated as it's working correctly in its current form.

The series appears ready for merging once Patrick Steinhardt completes his review of v5. The implementation is currently in Junio's 'seen' branch and has proven stable under various stress tests including parallel operations and sustained load. This represents the final step before potential inclusion in a future Git release.
