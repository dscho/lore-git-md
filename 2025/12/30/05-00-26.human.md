Junio Hamano proposes a simpler alternative to the symlink buffer size discussion in this thread. While the previous solution involved dynamic buffer growth with ERANGE checks, Hamano suggests a fixed 32KB limit (matching Windows' documented maximum path length) as a more straightforward approach that avoids potential platform-specific issues with unbounded growth.

The key observation is that some platforms set PATH_MAX artificially low compared to their actual capabilities, making the original PATH_MAX-based limit problematic. Hamano's patch replaces this with a hardcoded 32KB value, citing Microsoft's documentation as a reference point while acknowledging this is a pragmatic rather than theoretically perfect solution.
