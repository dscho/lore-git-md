This thread addresses a memory leak in Git's fsmonitor daemon client handling code, specifically in `do_handle_client()` in `builtin/fsmonitor--daemon.c`. The issue involves improper cleanup of a khash table used for pathname deduplication, leaking 40 bytes per client request due to using `kh_release_str()` instead of `kh_destroy_str()`.

The discussion progressed through two patch versions, with v2 narrowing the focus to just the memory leak fix after v1 proposed three changes. The fix is minimal (5 lines) and well-contained, switching to `kh_destroy_str()` for proper cleanup. René Scharfe reviewed and confirmed the technical correctness of this approach.

Junio C Hamano noted this fix is already included in v4 of a larger fsmonitor-linux series, but author Paul Tarjan submitted it separately as it addresses an existing bug that may warrant quicker merging. The thread has reached consensus on the technical solution with no outstanding objections.
