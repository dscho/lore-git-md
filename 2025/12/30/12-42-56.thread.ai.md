This thread addresses a memory leak in Git's fsmonitor daemon client handling code, specifically in `do_handle_client()` in `builtin/fsmonitor--daemon.c`, where improper cleanup of a khash table used for pathname deduplication was leaking 40 bytes per client request. The fix switches from `kh_release_str()` to `kh_destroy_str()` for proper cleanup - a minimal 5-line change that has been technically validated by René Scharfe.

The discussion progressed through two patch versions, with v2 narrowing the focus to just the memory leak fix after v1 proposed three changes. While Junio C Hamano noted this fix is already included in v4 of a larger fsmonitor-linux series, author Paul Tarjan submitted it separately as it addresses an existing bug that may warrant quicker merging. The thread has reached consensus on both the technical solution and the rationale for separate submission, with Junio's "Thanks" signaling acceptance of this approach.
