This is the final test patch in a 5-patch series improving `git replay` error handling. Kristoffer Haugsbakk adds several regression tests to cover failure conditions that weren't previously tested.

The patch adds five new test cases that verify:
1. The requirement for either `--onto` or `--advance` options
2. Error when attempting to replay down to a root commit
3. Incompatibility between `--advance` and `--contained` options
4. Error when advancing with multiple sources (undefined ordering)
5. Current limitation on replaying merge commits

The tests follow Phillip Wood's suggestion to avoid pipes that lose return values and use simpler `echo`/`printf` for expected output. The test setup is also expanded with additional commits (N, O) and a merge commit (P) to support the new test cases.

This completes the series' goal of robust error handling by ensuring all the new validation paths have test coverage. The tests are straightforward and focused on failure modes, making them easy to maintain. The patch maintains the series' high quality with clear commit messages and thorough test coverage.
