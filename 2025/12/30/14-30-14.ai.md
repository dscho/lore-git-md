This is a follow-up in the `git replay` error handling thread, specifically addressing the placement of error messages for invalid commit-ish arguments. Kristoffer Haugsbakk acknowledges Phillip Wood's observation that moving error handling to callers would be better, particularly since there are only two callers (`--onto` and `--advance` paths) in `determine_replay_mode()`. 

The key point here is that `--advance` already has its own reference validation ("must be a reference") through `repo_dwim_ref()`, making the error handling in `peel_committish()` redundant for that case. Kristoffer confirms that their initial patch would have provided a worse error message for `--advance` by duplicating validation, and mentions they've incorporated Junio's suggestion in v2 of the patch to move error handling to the callers.

This email reinforces the architectural direction suggested earlier in the thread - moving toward caller-specific error messages while maintaining `--advance`'s stricter validation requirements. The discussion remains focused on the two call paths in `builtin/replay.c` and the interplay between `peel_committish()` and `repo_dwim_ref()` validation. No new test cases or code changes are proposed here - this is primarily an acknowledgment of the suggested improvements and confirmation they're being addressed in the next version.
