Feature enhancement for `git status` showing divergence from push branch, final implementation patch. This is the third and concluding patch in the v10 series that pivots from using a custom `status.goalBranch` config to leveraging Git's existing branch tracking mechanisms.

The patch completely removes the `status.goalBranch` configuration approach from v1-v9, replacing it with logic that uses `branch.<name>.pushRemote` when available, falling back to the tracking branch if unset. The core functionality remains the same - showing divergence information in status output - but now integrates with Git's standard remote tracking system rather than introducing new configuration.

Key technical changes:
- Renames `get_goal_branch_ref()` to `get_remote_push_branch()`
- Replaces config lookup with `pushremote_for_branch()`
- Updates `format_goal_branch_comparison()` to `format_push_branch_comparison()`
- Maintains all v6-v9 optimizations (single ref resolution, memory management)
- Significantly refactors tests (296 lines changed) to focus on push branch behavior

The test suite has been completely overhauled to verify the new pushRemote-based approach while maintaining coverage of all scenarios:
- Ahead/behind/diverged states
- Different remote configurations (origin vs upstream)
- Edge cases and error handling
- Integration with existing tracking info
- Output format verification

This represents the final implementation after addressing Junio Hamano's objections to the original config-based design and incorporating Ben Knoble's suggestion to use existing mechanisms. The series has evolved through 10 iterations to reach this solution that preserves the feature's utility while aligning with Git's standard patterns.
