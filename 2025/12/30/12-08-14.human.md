This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than scanning the working directory.

The patch is version 2 of the series, addressing feedback from two previous PR attempts and fixing a newly discovered memory leak during `SANITIZE=leak` testing. The implementation shows thorough attention to edge cases like directory renames and remote filesystem handling, with detailed technical explanations of design decisions in the commit message.

Key technical aspects include using inotify with recursive directory monitoring, special handling for directory renames via IN_MOVED_FROM/TO event cookies, maintaining bidirectional watch descriptor <-> path mappings using hashmap, and detecting/rejecting remote filesystems (NFS/SMB) via statfs() unless explicitly allowed. The patch also adds build configuration via FSMONITOR_DAEMON_BACKEND=linux and FSMONITOR_OS_SETTINGS=linux, requiring pthreads and Unix domain socket support.

The patch appears well-crafted with comprehensive test coverage (including the fsmonitor test suite plus manual verification) and addresses all previously identified issues. The only remaining known issue is a 512-byte memory leak during daemon initialization that was identified but not yet fixed in this version. The implementation looks production-ready aside from this minor leak.
