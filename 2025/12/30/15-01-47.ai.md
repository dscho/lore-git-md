This is a refactoring patch that removes dead code from `git replay`'s option handling logic, part of a larger bugfix and test coverage series for `git replay` error handling.

The patch focuses on cleaning up `determine_replay_mode()` in `builtin/replay.c`, which contained legacy code from when `--onto` and `--advance` options were optional rather than mandatory. The function is renamed to `populate_for_onto_or_advance_mode()` to better reflect its actual behavior, which is to populate data structures rather than determine mode. The dead code removal eliminates an entire else-branch that could never be reached since one of the options is now mandatory.

Key technical details include:
- Removal of the "guess mode" logic that was dead on arrival in git.git
- Consolidation of the `onto_name` and `advance_name` handling paths
- Addition of a BUG() assertion to enforce the mandatory option requirement
- Preservation of the core functionality for both `--onto` and `--advance` modes
- The change is part of internal cleanup with no user-facing behavior changes
- The patch builds on historical context from Elijah Newren's original work and incorporates feedback from the mailing list discussion

The patch appears well-justified and cleanly implemented, with the commit message providing clear historical context about why the code was dead. This sets up the subsequent patches in the series to build on this cleaner foundation for error handling improvements.
