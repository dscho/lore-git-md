Bugfix patch in the `git replay` error handling series. This is patch 2/5 in v2 of Kristoffer Haugsbakk's series addressing error message clarity and validation order in the `--advance` option.

The patch reorders operations in `populate_for_onto_or_advance_mode()` to first verify that the `--advance` argument is a valid reference before attempting to peel it as a commit-ish. This ensures users get the most specific error message possible - first learning if their input isn't a reference at all, before any commit-ish validation occurs. The change was suggested by Junio Hamano to prevent less descriptive error messages from shadowing the reference validation.

A new regression test confirms the error message order remains correct when passing a raw object ID (which is a valid commit-ish but not a reference) to `--advance`. The test expects the "must be a reference" error rather than any commit-related failure.

This continues the series' architectural improvements by separating validation concerns and making error paths more precise. The change is straightforward and well-tested, with clear motivation explained in both the commit message and series notes. It builds on the dead code removal from patch 1 while setting up for later patches that will further improve error handling and test coverage.
