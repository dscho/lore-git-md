Bugfix for a memory leak in the fsmonitor daemon's client handling code. The patch addresses two related issues in `do_handle_client()` where a khash table used for pathname deduplication wasn't being properly freed. First, it was using `kh_release_str()` which only freed internal arrays but not the struct itself, leaking 40 bytes per request. Second, the cleanup was happening mid-function rather than in the cleanup section, making it vulnerable to leaks if the thread was interrupted during shutdown.

The fix makes three key changes: initializing the hash table pointer to NULL at declaration, switching to `kh_destroy_str()` which properly handles NULL and frees all memory, and moving the cleanup to the unified cleanup section. The changes are minimal (5 lines modified) and focused on the fsmonitor daemon's client handling code in `builtin/fsmonitor--daemon.c`.

This appears to be a straightforward and well-motivated fix for a real memory leak.
