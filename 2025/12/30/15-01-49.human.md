This is the third patch in a 5-part bugfix and test coverage series for `git replay` error handling, focusing on invalid commit-ish inputs. Kristoffer Haugsbakk continues the work started by Elijah Newren to improve error messages and validation in the `replay` command.

The patch fixes a confusing error message when an invalid commit-ish is given to `--onto`. Previously this would fail with an unhelpful "Replaying down to root commit is not supported yet!" message. Now it properly reports when the input isn't a valid commit-ish, making it clearer what went wrong. The change also catches cases where users might accidentally pass an argument to `--onto` when they meant to pass a positional argument.

The implementation modifies `peel_committish()` to accept a `mode` parameter (either `--onto` or `--advance`) so it can generate context-aware error messages. A new test case verifies the improved error reporting. The patch also removes some dead code related to the old error handling path.

This is part of a well-structured series that has incorporated feedback from Junio Hamano and Phillip Wood. The changes are focused and clearly explained, with good test coverage. The patch moves the code toward more robust error handling while maintaining clean separation between the validation paths for `--onto` and `--advance`.
