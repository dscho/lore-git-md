This is a bugfix and test coverage series for `git replay` error handling when invalid commit-ish arguments are given. Kristoffer Haugsbakk builds on previous discussion to improve error messages and remove dead code.

The series addresses confusing error messages when users provide invalid commit references to `--onto` or `--advance` options. Previously, these would produce misleading "root commit not supported" errors. The new version provides immediate, descriptive failures when commit resolution fails.

Key changes in v2:
- Removes dead code from when `--onto` and `--advance` weren't mandatory
- Improves error messages to specify which option (`--onto` or `--advance`) had the invalid argument
- Adds more regression tests covering various failure conditions
- Uses `parse_object_or_die()` for more robust object parsing
- Restructures validation to maintain `--advance`'s stricter reference requirements

The patch series shows good responsiveness to review feedback, with clear explanations of changes and rationale. Test coverage appears thorough, addressing edge cases like merge commits and option conflicts. The changes align with the thread's consensus on moving error handling to callers while preserving `--advance`'s special validation requirements.
