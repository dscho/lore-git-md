This is the second patch in a 5-part bugfix and test coverage series for `git replay` error handling, focusing on validation order for the `--advance` option. The patch addresses a specific edge case where error messages would become less descriptive after planned changes to make `peel_committish()` die on invalid input.

The key change reorders operations in `populate_for_onto_or_advance_mode()` to first validate that the `--advance` argument is a valid reference (via `repo_dwim_ref()`) before attempting to peel it as a commit-ish. This ensures users see the more specific "must be a reference" error rather than a generic commit-ish parsing failure. The patch includes a new test case that explicitly checks this error message when passing a raw OID to `--advance`.

Technical implementation notes:
- Moves `peel_committish()` call after reference validation
- Adds regression test in `t/t3650-replay-basics.sh`
- Maintains the same error flow for multiple source cases
- Follows Junio Hamano's suggestion from thread discussion

This change is part of the larger architectural restructuring in v2 that separates validation steps and moves error handling to callers. The patch cleanly integrates with the series' goal of improving error reporting while maintaining `--advance`'s stricter validation requirements. The test addition helps lock in the desired behavior for future modifications.
