This is patch 2/5 in a bugfix and test coverage series for `git replay` error handling. The patch focuses on improving error message ordering when an invalid commit-ish is provided to `--advance`.

The key change reorders operations in `populate_for_onto_or_advance_mode()` to first check if the argument is a valid reference (via `repo_dwim_ref()`) before attempting to peel it as a commit-ish. This ensures users get the more specific "must be a reference" error rather than a generic commit-ish failure when the input isn't a ref. The patch includes a regression test verifying this error message behavior.

Elijah Newren provides minor feedback suggesting to rephrase "error-order" in the commit message for clarity, but otherwise approves the change. The patch implements Junio Hamano's earlier suggestion about error message ordering and is part of the series' broader effort to make error handling more robust and user-friendly.

Technical details for future reference:
- Changes validation flow in `builtin/replay.c` to check ref existence before commit peeling
- Adds test case in `t/t3650-replay-basics.sh` for `--advance` reference validation
- Maintains same error conditions but improves their ordering
- Follows series pattern of moving error handling to callers and using more specific messages
