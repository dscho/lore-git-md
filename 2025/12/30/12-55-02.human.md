This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The patch represents the third iteration of this work, addressing feedback from two previous PR attempts and fixing a recently discovered memory leak.

The implementation uses inotify to monitor filesystem events, with special handling for directory renames via IN_MOVED_FROM/TO event cookies. It maintains bidirectional watch descriptor <-> path mappings using a hashmap and detects/rejects remote filesystems (NFS/SMB) via statfs() unless explicitly allowed. The daemon falls back to $HOME/.git-fsmonitor-* for IPC sockets when .git is remote.

The patch includes thorough documentation updates covering inotify watch limits and expands fsmonitor.socketDir support to Linux. Testing shows all t7527-builtin-fsmonitor.sh tests pass on local filesystems, with proper rejection of network mounts. The implementation appears robust, with attention to edge cases like directory renames and remote filesystem handling.

Key changes since v2 include fixing a khash memory leak in do_handle_client and removing 9p (Plan 9) from the remote filesystem list since inotify works correctly on 9p filesystems. The patch has undergone multiple iterations to address all raised concerns except for one final memory leak issue identified during SANITIZE=leak testing.
