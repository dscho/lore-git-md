This is a bugfix patch in the `git replay` error handling series, specifically addressing error message ordering for the `--advance` option. The patch (v2 2/5) reorders validation in `builtin/replay.c` to first check if the `--advance` argument is a valid reference before attempting to peel it as a commit-ish. This ensures users get the most specific error message possible when providing invalid input - first being told if their argument isn't a reference at all, before any commit validation occurs.

The change comes with a new regression test that verifies the error message when passing a commit OID directly to `--advance` (which should fail with "must be a reference" rather than a commit validation error). Elijah Newren provides a minor suggestion about clarifying the commit message wording around "error-order" phrasing.

This continues the series' focus on improving error handling robustness, following Junio Hamano's earlier suggestion about error message ordering. The change is small but meaningful for user experience, ensuring the most relevant error surfaces first when validation fails.
