Bugfix for merge-ort's handling of submodule/directory conflicts in optimization paths. This addresses a complex corner case where merge-ort's tree-level optimization incorrectly handles cases where one side of history treats a path as a directory while another treats it as a submodule, particularly when multiple merge bases are involved.

The core issue occurs in `resolve_trivial_directory_merge()`, which was originally written assuming both sides would be directories. The fix involves:
- Proper clearing of dirmask/filemask bits when resolving type mismatches
- Careful marking of merge cleanliness to avoid premature optimization
- Clearing df_conflict bits after resolution
- The test case demonstrates the failure scenario through a carefully constructed repository state with multiple merge bases and enough files under the directory to trigger the optimization path where the bug occurs.

Key technical details for future reference:
- The bug manifests when merge-ort attempts to optimize directory merges without recursing into trees
- The fix specifically handles cases where one side is a submodule rather than a directory
- The test case in t6422 exercises the optimization path by creating a scenario with:
  - Branch A treating "folder" as a directory
  - Branch B treating "folder" as a submodule
  - Multiple merge bases requiring virtual merge base creation
  - Enough files under "folder" to trigger the optimization threshold

The patch includes extensive documentation of both the failure scenario and the solution rationale, which will be valuable for future maintenance of this complex merge optimization logic.
