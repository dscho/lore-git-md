This is part 4 of a 5-patch bugfix and test coverage series for `git replay` error handling, focusing on object parsing robustness. The patch replaces `parse_object()` with `parse_object_or_die()` in the `peel_committish()` helper function, ensuring immediate failure with a descriptive error when invalid objects are encountered rather than propagating NULL values.

The change follows Junio Hamano's suggestion to use the `*_or_die` pattern for cleaner error handling, removing the need for NULL checks at call sites. The modification affects the core object parsing path used by both `--onto` and `--advance` options in `builtin/replay.c`, though the actual error messages remain mode-specific through the existing `mode` parameter infrastructure established earlier in the series.

This patch represents a straightforward technical improvement that builds on the series' architectural direction of making validation failures fatal with context-specific errors. It doesn't introduce new test cases since the existing test coverage from previous patches already exercises these error paths, now benefiting from more robust failure behavior. The change is small (a single line modification) but meaningful for code reliability, eliminating a potential NULL dereference while maintaining the same user-facing behavior through the `*_or_die` wrapper's built-in error reporting.
