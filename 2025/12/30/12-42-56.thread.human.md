This thread addresses a memory leak in Git's fsmonitor daemon client handling code, where each client request was leaking 40 bytes due to improper cleanup of a khash table used for pathname deduplication. The fix, now in its second iteration, properly uses `kh_destroy_str()` instead of `kh_release_str()` in `do_handle_client()`.

René Scharfe reviewed and confirmed the technical correctness of the solution, which is minimal (just 5 lines) and well-contained. While Junio C Hamano noted this fix is already included in a larger fsmonitor-linux series (v4), the author Paul Tarjan submitted it separately as it fixes an active bug that might benefit from quicker merging. The thread has reached clear consensus with no outstanding objections, making this a straightforward fix for a maintenance release.
