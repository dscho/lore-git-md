This thread addressed a memory leak in Git's fsmonitor daemon client handling code, where a khash table used for pathname deduplication wasn't being properly cleaned up. The issue was identified as using `kh_release_str()` instead of `kh_destroy_str()`, causing a 40-byte leak per client request.

The patch went through two iterations, with René Scharfe providing review feedback that helped refine the approach. The final version focused narrowly on fixing the core memory leak issue by using the correct khash API function. Junio Hamano has now noted that this fix is already included in a larger fsmonitor-linux patch series (v4), so this standalone fix likely won't need separate merging.

The technical solution is straightforward and uncontested - using `kh_destroy_str()` in the cleanup section of `do_handle_client()` in `builtin/fsmonitor--daemon.c`. With the maintainer's confirmation that the fix is already accounted for in ongoing work, this thread appears to be resolved.
