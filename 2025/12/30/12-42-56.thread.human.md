This thread addressed a memory leak in Git's fsmonitor daemon client handling code, where each client request was leaking 40 bytes due to improper cleanup of a pathname deduplication hash table. Paul Tarjan identified the issue in `do_handle_client()` and submitted a minimal fix switching from `kh_release_str()` to `kh_destroy_str()` for proper cleanup.

The fix went through two versions, with v2 narrowing the scope to just the memory leak after v1 included additional changes. René Scharfe reviewed and confirmed the technical correctness of the approach. While Junio Hamano noted this fix was already included in v4 of a larger fsmonitor-linux series, Paul explained submitting it separately to address the existing bug more quickly. The thread reached consensus with no outstanding objections, and Junio's acknowledgment indicates the fix will be merged - either independently or as part of the larger series. This straightforward fix for a clear memory leak is now ready for integration.
