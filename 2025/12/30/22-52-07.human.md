Bugfix patch improving error messages in `git replay` when invalid commit-ish arguments are given. This is patch 3/5 in Kristoffer Haugsbakk's v2 series addressing error handling in the replay command.

The patch modifies `peel_committish()` to immediately die with a descriptive error when an invalid commit-ish is provided to either `--onto` or `--advance` options, rather than returning NULL and failing later with a less helpful message. The new error clearly indicates which option received the invalid input (e.g. "'^main' is not a valid commit-ish for --onto").

Elijah Newren provides review feedback suggesting the patch could include a corrected FIXME comment about future handling of root commits, though this is out of scope for the current series. The patch includes a test case verifying the new error message format for invalid `--onto` inputs.

This continues the series' pattern of moving error handling closer to the point of failure with more context-specific messages. The changes appear well-considered, building on previous feedback from Junio Hamano about error message placement and Elijah's earlier suggestions about the code structure.
