This is a bugfix patch addressing memory leaks in the fsmonitor daemon's client handling code. The patch fixes two related problems in the `do_handle_client()` function where a khash table used for pathname deduplication wasn't being properly freed.

The first issue was using `kh_release_str()` which only freed internal arrays but not the struct itself, causing a 40-byte leak per client request. The second issue was freeing the hash mid-function rather than in the cleanup section, meaning leaks could occur if the daemon shut down before reaching that point.

The solution cleanly addresses both problems by:
1. Initializing the hash pointer to NULL upfront
2. Using `kh_destroy_str()` which properly handles NULL and frees everything
3. Moving the cleanup to the proper cleanup section that runs on all exit paths

The patch is small (5 lines changed) and focused, with a clear commit message explaining both the problems and solution. This appears to be a straightforward improvement to the fsmonitor daemon's resource management.
