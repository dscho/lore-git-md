This is patch 3/5 in the bugfix and test coverage series for `git replay` error handling. Elijah Newren provides feedback on Kristoffer Haugsbakk's changes to improve error messages when invalid commit-ish arguments are given to `--onto` and `--advance` options.

The patch modifies `peel_committish()` to die immediately with a descriptive error when an invalid commit-ish is provided, rather than returning NULL. This produces clearer messages like "fatal: '^main' is not a valid commit-ish for --onto". The changes also remove now-unnecessary NULL checks since the function will die on invalid input.

Elijah suggests two potential follow-up improvements: (1) updating the FIXME comment about root commit handling to clarify the desired future behavior, and (2) considering whether "replaying from root commit" would be more accurate wording than "replaying down to root commit". These are noted as out of scope for the current series but worth considering for future work.

The technical changes include:
- Adding a `mode` parameter to `peel_committish()` to provide context for error messages
- Removing dead code paths that handled NULL returns
- Adding a test case for invalid `--onto` input
- Maintaining the parallel validation flows for `--onto` vs `--advance`

This continues the series' pattern of moving error handling to callers with specific messages, following Junio Hamano's earlier suggestion. The changes are focused and well-contained, building on the structural improvements from earlier patches in the series.
