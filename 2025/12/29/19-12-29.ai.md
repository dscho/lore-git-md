This is a bugfix patch addressing a race condition in `git fsck` when run on live repositories. The issue occurs when refs are modified (via commits or other operations) while `fsck` is running, causing it to report false positives about missing commits and invalid reflog entries.

The patch introduces a snapshot mechanism that captures ref states at the start of `fsck` operation. Key changes include:
- Adding a `ref_snapshot` struct to store ref names and OIDs
- Implementing `snapshot_refs()` callback to populate the snapshot
- Modifying `get_default_heads()` to use either snapshot or live refs
- Adding timestamp-based filtering for reflog entries
- Freeing snapshot memory when done

The solution is demonstrated with a test case showing concurrent commit operations while `fsck` runs. The patch handles both refs and reflogs, and makes snapshotting the default behavior when no specific refs are provided on the command line. The changes primarily affect `builtin/fsck.c`, adding about 70 lines while removing 4.

This appears to be a well-motivated change with clear problem demonstration and solution. The patch includes co-authorship from Elijah Newren who helped adapt it for upstream, including handling reflogs and making snapshotting the default. The change should particularly benefit forge operators and automated maintenance jobs where repository modifications during `fsck` are more likely.
