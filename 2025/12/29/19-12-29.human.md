This is a bugfix patch for `git fsck` that addresses a race condition when checking live repositories. The issue occurs when new commits are written while `fsck` is running - since `fsck` reads refs at the start and end of its operation, it can incorrectly flag new refs/reflogs as invalid when they reference commits that were added mid-operation.

The patch solves this by taking a snapshot of refs at the start of the operation and using that consistent view throughout. It also ignores reflog entries created after the snapshot time to prevent false positives. The commit includes a clear reproduction case showing the problem and demonstrates the fixed behavior.

The change is particularly relevant for forge operators and automated maintenance jobs, but benefits any user who might run `fsck` while continuing to work in the same repository. The implementation adds a new `ref_snapshot` struct to store the ref state and modifies the ref handling logic to use this snapshot when no specific refs are provided on the command line.

The patch appears well-constructed with thorough testing demonstrated in the commit message. It handles edge cases like memory management for the snapshot and accounts for reflog timestamp comparisons. The change builds on existing `fsck` infrastructure while cleanly solving a real-world race condition.
