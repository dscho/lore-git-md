Thread identity: bugfix patch addressing a race condition in `git fsck` when run on live repositories, where concurrent ref modifications cause false positives about missing commits and invalid reflog entries.

Core problem: `git fsck` currently operates on live refs, making it vulnerable to race conditions when repositories are modified. This is particularly problematic for automated maintenance jobs and forge operators where concurrent operations are common.

Current status: initial patch version proposing a solution via ref snapshots. The patch:
- Introduces `ref_snapshot` struct to store ref names and OIDs
- Implements `snapshot_refs()` callback
- Modifies `get_default_heads()` to use snapshots
- Adds timestamp-based reflog filtering
- Makes snapshotting default behavior when no specific refs are given

Key technical details:
- Changes primarily in `builtin/fsck.c` (+70/-4 lines)
- Handles both refs and reflogs
- Includes test case demonstrating concurrent operations
