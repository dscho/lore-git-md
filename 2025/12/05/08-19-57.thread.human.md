Patrick Steinhardt's bugfix series addressing memory management issues in Git's maintenance operations has reached consensus and is ready for merging. The series fixes two distinct problems: a memory leak during commit-graph writing and a submodule ODB cleanup issue.

The commit-graph fix in `builtin/gc.c` replaces `commit_list_append()` with `commit_list_insert()` to properly handle memory during depth-first search, while also correcting SEEN flag handling to prevent double-counting. Justin Tobler contributed test coverage for merge commit scenarios, and Toon Claes has now confirmed the technical correctness of this approach, noting that the change in list ordering doesn't affect the counting operation.

The second fix addresses a 192-byte leak per submodule access during `git-grep` operations by reordering cleanup operations in `odb.c`. This minimal but important change comes with clear reproduction steps and proper test coverage.

Both patches have been thoroughly reviewed, with all technical concerns addressed. The series maintains a tight focus on its original scope - fixing memory management issues without introducing new complexity. With Toon's approval joining Justin's earlier feedback, the path is clear for Junio to pick up these well-validated fixes for the next release. The more complex geometric repack/promisor pack interaction issues mentioned earlier remain deferred for future work.
