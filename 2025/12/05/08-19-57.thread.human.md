Patrick Steinhardt has submitted a two-patch series fixing memory management issues in Git's maintenance operations. The first patch addresses problems in commit-graph auto-generation, fixing both a memory leak and incorrect object counting when processing merge commits. The changes in `builtin/gc.c` replace `commit_list_append()` with `commit_list_insert()` to properly maintain the traversal stack and add SEEN flag handling to prevent double-counting of tip objects. A new test case in `t/t7900-maintenance.sh` verifies the fixes work correctly with merge commits.

The second patch fixes a 192-byte memory leak per submodule access during `git-grep` operations by correcting the cleanup sequence in the object database handling. Both patches have gone through multiple review iterations with Justin Tobler, Karthik Nayak, and Toon Claes providing thorough feedback. All technical concerns have been addressed, and the patches have received final review acks. The series is now considered merge-ready, with only a non-blocking suggestion from Karthik for additional test coverage as potential future work. These are focused, well-contained fixes that improve Git's memory management without introducing new complexity.
