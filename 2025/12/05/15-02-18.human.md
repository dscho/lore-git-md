This is a Windows compatibility patch in a series preparing Git's test suite for upcoming MSYS2 symlink support. Patch 3/10 addresses a specific behavior mismatch where Windows' `_wopen()` would incorrectly create files through dangling symlinks when given `O_CREAT|O_EXCL` flags, while Linux would return `EEXIST`.

The change modifies `mingw.c` to explicitly check for this case and emulate Linux's behavior, which is needed to make test t4115.8 pass when MSYS2 enables symlink support by default. The implementation adds a check for the Windows-specific `FILE_ATTRIBUTE_REPARSE_POINT` attribute when those flags are present, returning `EEXIST` if the path is a symlink.

This appears to be a straightforward and well-motivated change that cleanly handles a platform-specific divergence. The commit message clearly explains both the problem and solution, and the change is narrowly scoped to just this one behavior mismatch. As part of the larger symlink support effort that has already been reviewed in v1, this refinement seems uncontroversial.
