Performance optimization follow-up for promisor object handling, addressing an edge case in the type-checking logic.

Aaron Plattner confirms Jeff King's analysis that `OBJ_NONE` objects should be included alongside `OBJ_BLOB` in the type check within `parse_object_with_flags()`, as both represent unparsed objects that could be blobs. The change yields a modest performance improvement (2min to 1:58 in Plattner's tests). Plattner traces the `OBJ_NONE` objects back to `mark_uninteresting()` calls during promisor pack processing, where dummy struct objects are created without type information.

The discussion reveals environmental differences that may explain performance variations - notably commit-graph availability. Plattner observes their test repository (a Scalar clone with worktree) sometimes hits pathological cases during pulls, suggesting commit-graph usage might normally prevent these slowdowns. Both agree King's flag-based approach with `PARSE_OBJECT_SKIP_HASH_CHECK` remains the cleanest solution, now with the `OBJ_NONE` edge case addressed.

Key technical points:
- Confirmed need to handle `OBJ_NONE` in `parse_object_with_flags()` type check
- Performance impact smaller than initial optimizations but still worthwhile
- `OBJ_NONE` objects originate from `create_object()` calls in promisor pack processing
- Commit-graph presence may significantly affect real-world performance
- Scalar clone behavior suggests this optimization helps edge cases even when commit-graph normally prevents them

The email indicates Plattner will submit a v2 patch incorporating both the type-check fix and King's flag-based approach, closing this edge case in the optimization path. The discussion highlights how environmental factors like commit-graph usage can mask performance issues that still need addressing for edge cases.
