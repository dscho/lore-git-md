Bugfix for object database (odb) resource cleanup. This is the third patch in Patrick Steinhardt's series addressing odb-related issues.

The patch fixes a memory leak that occurs when reading from submodule repositories, specifically during git-grep operations. The root cause is an incorrect cleanup sequence in `odb_free()` where sources were being freed before being closed, causing resources to leak. The leak manifests when packfiles and multi-pack-indexes are loaded from submodule repositories.

The fix is straightforward - swapping the order of `odb_close()` and `odb_free_sources()` calls in `odb_free()` to ensure proper cleanup. The patch includes a detailed stack trace showing the 192-byte leak and explains the problematic sequence of operations that leads to it. This builds on recent quarantine directory handling work (ac65c70663) mentioned in the series.

The change is minimal (a 2-line swap in odb.c) but addresses a real resource management issue that would become more prominent with upcoming changes to packfile store organization. The patch doesn't include new tests as it fixes a cleanup path that's difficult to observe directly, but the explanation clearly demonstrates the problem scenario.
