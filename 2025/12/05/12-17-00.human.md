This is a technical discussion about the submodule gitdir path encoding implementation, specifically around race condition validation.

Patrick Steinhardt is reviewing Adrian Ratiu's patch that removes some validation checks in the submodule code. The patch is part of the larger submodule path encoding series (v5.7) that introduces a unified way to handle submodule gitdir paths to prevent filesystem conflicts.

Steinhardt raises two concerns about the removal of validation checks:
1. In the first diff, he questions why a TOCTOU (Time of Check to Time of Use) race condition check is being removed, since the new unified API doesn't appear to protect against concurrent modifications between initial validation and actual use.
2. In the second diff, while he agrees the validation makes sense when using the new `submodule_name_to_gitdir()` API, he notes there's still a code path that retrieves the path directly without this protection.

The discussion appears to be about ensuring the safety of the new path encoding system, particularly around edge cases where multiple processes might be manipulating submodule directories concurrently. This is part of the final refinements to the series before it gets merged.
