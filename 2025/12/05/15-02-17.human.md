Bugfix for `git apply`'s executable bit handling on Windows symlinks. This is part of Johannes Schindelen's v2 series preparing Git's test suite for Windows symlink support, specifically addressing a regression introduced in commit 0482c32c334b.

The patch fixes an unintended side effect where changes to executable bit handling were incorrectly applied to symbolic links and directories, not just regular files. The original change was meant to stop `git apply` from warning about executable files when `core.filemode` is disabled, but it broke test case t4115.5 which checks symlink behavior when creating new files.

The solution is straightforward - the special `!trust_executable_git` code path now only applies to regular files (`S_ISREG`). This maintains the intended behavior for regular files while properly handling symlinks and directories. The change is minimal (just a one-line condition modification in apply.c) but important for correct symlink behavior on Windows, particularly with MSYS2's upcoming default symlink support.

This appears to be a well-justified fix for a clear regression, with a focused change and good commit message explaining both the problem and solution. It's part of a larger, maintainer-approved effort to improve Windows symlink support in Git's test suite.
