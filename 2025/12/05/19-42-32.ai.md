This is a discussion about build-time configuration options for the submodule path encoding feature, part of the ongoing submodule gitdir path encoding series.

The email responds to Patrick Steinhardt's suggestion to make submodule encoding configurable via runtime gitconfig rather than build-time options. Adrian Ratiu explains the build-time approach was chosen based on feedback from Junio Hamano, Aaron, and Josh to minimize user intervention during migration. The goal is to automate the transition without requiring manual config changes or command-line parameters.

Adrian maintains a neutral stance, noting they could potentially add a runtime gitconfig option alongside the existing build and repo config options if desired. This reflects the ongoing tension in the series between strict configuration requirements (favored by Patrick) and practical migration needs (emphasized by Junio and others).

The discussion touches on key technical points:
- Current implementation uses `--enable-submodule-encoding` (autoconf) and `submodule-encoding` (meson) build options
- Alternative proposal would introduce a new gitconfig key for runtime control
- Underlying motivation remains enabling the feature with minimal user friction

This exchange represents one of the few remaining open questions in the otherwise largely finalized series - how to handle default enablement of the feature across different deployment scenarios. The thread shows Adrian balancing architectural feedback from Patrick with the practical migration concerns raised by other contributors.
