This is a build system patch in the ongoing submodule gitdir path encoding series, responding to discussion about how to enable the new encoding feature.

Junio Hamano questions the need for a build-time configuration option (`--enable-submodule-encoding`) that was proposed in the series. He argues that runtime configuration (via `/etc/gitconfig` or similar) should be sufficient for enabling the submodule path encoding feature, since managed environments can already distribute config changes centrally. The build-time approach seems unnecessary given Git's existing configuration mechanisms.

The email continues the thread's discussion about the best way to roll out the new submodule path handling without requiring manual migration. While previous emails had settled on making the submodule.gitdir config entries mandatory when the feature is enabled, this exchange focuses specifically on the activation mechanism. Junio's position suggests the build-time flag may be an overcomplication compared to using standard Git config channels.

This appears to be one of the final open questions before the series can be finalized, with Junio providing architectural guidance that may lead to simplifications in the next version. The exchange highlights the project's preference for runtime configuration over build-time knobs where possible.
