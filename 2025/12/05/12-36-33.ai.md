Performance optimization for promisor object handling, with additional memory efficiency suggestion.

Patrick Steinhardt responds to Aaron Plattner's patch that optimized promisor object initialization by skipping full parsing of blobs. While agreeing the original change is an obvious improvement (reducing runtime from 76 to 2 minutes for large packs), Patrick suggests a further optimization: freeing commit buffers after processing them, similar to how tree buffers are already freed. He provides a complete patch demonstrating this change, which restructures the code to pass repository context through a new `add_promisor_object_data` struct and adds `free_commit_buffer()` calls.

The technical changes include:
- Introducing a callback data structure to carry both the repository` pointer and `oidset`
- Maintaining all existing functionality while adding commit buffer cleanup
- Keeping the same promisor object tracking logic but with explicit repository context
- Preserving the static initialization pattern for the promisor objects set

This builds on the thread's core insight that promisor object initialization can be made more efficient by avoiding unnecessary work, now extending it from CPU cycles to memory usage. The suggestion appears technically sound but would need testing in large-repository scenarios to verify actual memory savings. The change touches the same `packfile.c` area as the original patch but with broader structural modifications to support the new memory management approach.
