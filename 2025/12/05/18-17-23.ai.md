Adrian Ratiu responds to Patrick Steinhardt's review of patch 3/7 in the v5 series, agreeing that two validation checks were incorrectly removed. The second discussion point concerns submodule_move_head() validation paths. Adrian explains the !submodule_uses_gitfile case was already relying on validation within absorb_git_dir_into_superproject(), though this wasn't immediately obvious from the diff. He offers to either make this clearer through refactoring or restore explicit validation in the move-head path.

Key technical points for future reference:
- TOCTOU protection needed in clone path despite centralized API
- Validation coverage in move-head path currently depends on absorb_git_dir_into_superproject() internals
- submodule_name_to_gitdir() now handles primary validation but supplementary checks may still be needed
- All validation can safely be run multiple times without side effects
