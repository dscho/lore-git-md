This is a conceptual proposal about integrating Git with structured databases. Cedric Sodhi raises an interesting question about why Git, which excels at versioning filesystems, can't be extended to handle structured data like databases. They describe encountering real-world cases where having version-controlled structured data would be valuable, without having to sacrifice either the database structure or versioning capabilities.

The email presents two potential approaches: using FUSE to map databases into a filesystem that Git could then version (with expected performance issues), or modifying Git's backend to work directly with databases (which might require significant changes to handle mixed data types). The author is seeking feedback on which approach seems more promising to the Git community.

The proposal is thoughtful but raises complex technical questions about Git's architecture and scope. It's not a concrete patch but rather an invitation to discuss whether and how Git might expand beyond its filesystem roots. The performance and implementation challenges mentioned suggest this would be a non-trivial undertaking if pursued.
