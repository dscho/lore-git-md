This thread explores adapting Git's version control capabilities to work with structured data (like databases) rather than just filesystems. Cedric Sodhi proposes the idea by framing Git's working directory as already being a filesystem-based database, then questions why the model couldn't extend to other database types with schemas. 

The proposal identifies a real gap where users currently must choose between structured data and version control. Two potential approaches are outlined: using FUSE to map databases into a filesystem (with expected performance overhead) or modifying Git's backend to directly handle database types (which would require substantial changes to support mixed data). The discussion is just beginning, with the author seeking feedback on which direction might be more viable for the Git community to pursue. Key challenges mentioned include performance implications and handling schema-aware data.
