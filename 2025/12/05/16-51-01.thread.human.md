This thread explores whether Git could be extended to version control structured data like database contents, rather than just files. Cedric Sodhi's initial proposal suggested two approaches: a FUSE-based filesystem mapping (keeping Git unchanged but with performance overhead) or modifying Git's backend to directly handle database records (requiring architectural changes). The key challenge is handling mixed data types - both traditional files and database records - in a single repository.

René Scharfe has now pointed to two existing solutions that may address this need without modifying Git: Data Version Control (DVC) and Dolt, which position themselves as "Git for data." While René hasn't personally evaluated these tools, their existence shifts the discussion toward whether the problem might be better solved by specialized tools rather than Git modifications. The thread now faces an open question: do these existing tools adequately meet the requirements around performance and mixed-data handling that Cedric's original proposal identified, or does Git itself still need adaptation for this use case?
