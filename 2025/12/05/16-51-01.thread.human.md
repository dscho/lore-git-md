This thread explores how to version structured data that doesn't fit Git's line-oriented model. Cedric Sodhi initiated the discussion by considering Git modifications, leading to evaluations of specialized tools like DVC (for binary data), Dolt (Git-like with SQL), and Fossil (SQLite-backed). The core tension is between adapting Git versus using existing solutions, with no clear winner yet.

Simon Richter's new contribution shifts perspective by proposing database-native versioning using temporal columns - tracking when data was valid/current directly in the database schema. His KiCad example shows how 3D CAD data's multi-axis changes create diff complexities that even text-serialized formats struggle with in Git. While not dismissing filesystem-based approaches, Richter argues some structured data might be better served by database techniques with built-in versioning semantics.

The thread now spans three architectural approaches: modifying Git (still theoretical), specialized VCS (Dolt/Fossil), and database-native versioning. All agree semantic-aware tooling is essential, but differ on where that intelligence should live. The KiCad example provides concrete grounding, showing how even text-like data can defy Git's assumptions when structure matters more than line changes. No consensus yet, but the discussion is richer for considering database techniques alongside version control systems.
