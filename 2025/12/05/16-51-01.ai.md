This is a feature proposal exploring how Git could be adapted to handle version control for structured data (databases) rather than just filesystems. The author, Cedric Sodhi, frames Git working directory as already being a type of database (albeit a filesystem-based one) and questions why Git couldn't version control other database types with schemas.

The email identifies a real-world need where users want both structured data and version control, but currently must choose between them. It presents two potential approaches: (1) using FUSE to map databases into a filesystem that Git can then version (with expected performance issues), or (2) modifying Git's backend to directly read from databases (which would require significant changes to handle mixed data types).

Key technical points for future reference: the proposal centers on Git's data model limitations with structured data, mentions FUSE as one possible integration path, and raises performance and mixed-data concerns as central challenges. The thread appears to be starting a discussion rather than proposing a specific implementation, with the author seeking feedback on which approach might be more promising for the community.
