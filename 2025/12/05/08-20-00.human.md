Bugfix for object database cleanup order. This is the third patch in Patrick Steinhardt's series addressing odb-related issues.

The patch fixes a memory leak that occurs when reading from submodule repositories, specifically when `git grep` accesses submodule content. The root cause is an incorrect cleanup sequence in `odb_free()` where sources were being freed before being properly closed, causing resources to leak. The fix simply reorders the operations to close sources before freeing them.

The commit message provides a clear walkthrough of the problematic sequence and includes a detailed stack trace showing the leak's origin. The change itself is minimal - just swapping two lines in `odb.c` - but addresses a real issue that would become more prominent with upcoming changes to the packfile store architecture.

This appears to be a straightforward technical fix with no obvious downsides. It completes the series of odb improvements that started with geometric repacking fixes and commit-graph maintenance corrections. The patch maintains the series' pattern of focused changes with clear explanations.
