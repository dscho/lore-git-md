This is a bugfix patch in a series preparing Git's test suite for Windows symlink support, specifically addressing a regression in `git apply` behavior. The patch corrects an oversight from commit 0482c32c334b where changes meant to handle executable bits on regular files accidentally affected symbolic links and directories too.

The core issue is that `git apply` was applying the "trust executable bit" logic (which handles platform-specific filemode behavior) to all file types, when it should only apply to regular files. This caused test t4115.5 (which verifies symlink behavior) to fail on Windows when symlink support is enabled. The fix narrows the special-case handling to only regular files by adding a `!S_ISREG(st->st_mode)` check.

Key technical details:
- Modifies `apply.c` to properly scope the `trust_executable_bit` logic
- Fixes a regression introduced in 0482c32c334b
- Enables t4115.5 to pass when MSYS2 enables symlink support
- Maintains the same approach as v1 but with this specific refinement
- Part of broader Windows symlink support preparation (patch 2/10 in series)

The change is minimal (one-line diff) and clearly motivated by both the regression and the Windows symlink support context. The commit message provides clear before/after context and connects the fix to the larger test suite preparation effort.
