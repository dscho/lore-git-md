This is a performance optimization refinement in the ongoing discussion about promisor object handling. Jeff King builds on his earlier suggestion to use `parse_object_with_flags()` with `PARSE_OBJECT_SKIP_HASH_CHECK` instead of the current approach that checks object types separately. He provides concrete timing data showing this drops the linux.git test case from 2 minutes (with Aaron Plattner's original optimization) to 49 seconds when commit-graph is available.

The key technical points are:
- The flag-based approach avoids blob loading entirely without needing type-specific checks
- It also leverages commit-graph optimizations for commit objects
- Hash computation skipping provides additional (though likely smaller) gains
- Users may need to explicitly generate commit-graphs to see full benefit

This follows naturally from the thread's progression, where Jeff previously suggested this approach theoretically and now provides concrete implementation and measurements. The email reinforces that this is strictly better than the current optimization path, handling both blobs and commits more efficiently while being more maintainable by using existing parse_object infrastructure. The only open question appears to be whether to keep the original type-check optimization as a fallback when commit-graph isn't available.
