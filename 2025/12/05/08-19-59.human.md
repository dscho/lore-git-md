Bugfix for commit graph auto-generation in git maintenance. This is the second patch in Patrick Steinhardt's series fixing object database-related issues.

The patch addresses two bugs in the logic that determines when to automatically write commit graphs during maintenance. First, it fixes a memory leak that occurred when processing merge commits, where `commit_list_append()` was being misused and causing parent commits to be discarded. Second, it corrects a counting error where objects at reference tips weren't being marked as "seen", potentially causing them to be double-counted.

The fix replaces `commit_list_append()` with `commit_list_insert()` and properly marks seen commits. A new test case in t7900-maintenance.sh verifies the fix works with merge commits, checking the boundary conditions for when commit graph generation should trigger.
