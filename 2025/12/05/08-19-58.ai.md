Bugfix for geometric repacking with promisor remotes. This is the first patch in Patrick Steinhardt's series of object database fixes.

The patch addresses an incompatibility between two `git repack` options: `--exclude-promisor-objects` (used in partial clones to avoid packing objects not yet fetched from promisor remotes) and `--stdin-packs` (used by geometric repacking to identify packs to merge). Currently, geometric repacks in partial clones fail because they incorrectly try to use both options together.

The fix moves the `--exclude-promisor-objects` check outside the geometric repack logic, since geometric repacks don't need this protection - they only merge existing packs or pack loose objects, neither of which can contain promisor objects. The change is small (5 lines moved in builtin/repack.c) but comes with thorough test coverage in t7703 that verifies promisor packs remain untouched while geometric repacking still works.

This appears to be a straightforward technical fix with clear motivation and testing. The patch builds on recent work around quarantine directory handling (ac65c70663) and fits with the series' theme of object database improvements. The test case demonstrates the fix works by creating a partial clone scenario and verifying promisor pack behavior before/after geometric repacking.
