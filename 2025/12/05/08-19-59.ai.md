This is the second patch in Patrick Steinhardt's bugfix series for object database-related issues. It addresses two problems in the commit graph auto-generation logic within `builtin/gc.c`:

1. A memory leak in the depth-first search used to count commits not covered by commit graphs, caused by incorrect use of `commit_list_append()` that was dropping parent commits from the traversal stack. The fix switches to `commit_list_insert()` which properly maintains the stack.

2. A miscounting issue where objects at reference tips weren't marked as SEEN, potentially causing double-counting when reachable via multiple references. The patch adds proper SEEN flag handling.

The changes are accompanied by a new test case in `t/t7900-maintenance.sh` that verifies correct behavior with merge commits, specifically testing the boundary condition where maintenance should trigger. The test creates a repository with merge commits and verifies the auto-generation threshold works as expected.

This appears to be a straightforward technical fix for a memory leak and logic error in commit graph maintenance. The patch is well-explained with clear commit message analysis of both issues and their solutions. The test case provides good coverage for the merge commit scenario that exposed the problems. As part of the odb-related fixes series, this continues the theme of addressing subtle bugs in core object database operations.
