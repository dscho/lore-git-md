Refactoring patch in the submodule gitdir path encoding series.

Patrick Steinhardt provides a quick review of Adrian Ratiu's patch that moves the `is_rfc3986_unreserved()` function from credential-store.c to url.[ch]. This is part of the larger submodule path encoding effort, where the function will be needed for URL-encoding submodule names to avoid filesystem conflicts.

The patch itself is straightforward - it relocates the RFC3986 unreserved character check function to be publicly available via url.h, since it will now be needed by submodule.c. Steinhardt notes two minor issues: the commit message contains an outdated statement about the function's future use, and suggests the function documentation would be better placed in the header file rather than the implementation.

This appears to be a clean, uncontroversial change that's part of the well-architected submodule encoding series. The review is light, focusing only on documentation placement and commit message accuracy, suggesting the technical implementation is sound. The change helps centralize URL-related functionality while supporting the broader submodule encoding feature.
