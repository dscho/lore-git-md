This is a follow-up in the ongoing discussion about improving the clar test framework integration with Git's test suite.

Jeff King (Peff) responds to Patrick Steinhardt's updates about clar framework fixes, acknowledging progress on the TAP output format issue but raising deeper concerns about test output handling in CI environments. The core problem is that while clar's TAP output format has been fixed (changing `---` to `...` to avoid parser issues), Git's test infrastructure still doesn't properly capture or relay this output during CI runs.

Peff explores potential solutions:
1. Modifying the unit test wrapper to handle verbose logging, though this would require duplicating output streams and understanding test directory variables
2. Running the unit tests through Git's main test suite, which already handles output capture via `tee`
3. Reviving or adapting the old `test_external` mechanism that was removed in 2022

The email highlights an interesting tension between wanting tight integration with Git's test infrastructure while maintaining the independence of the unit test framework. Peff's analysis suggests the current solutions are either too invasive (modifying clar internals) or too limiting (wrapping in `test_expect_success`).

This continues the thread's theme of improving test infrastructure while maintaining developer experience, with Peff focusing on practical CI integration concerns that weren't fully addressed by the recent clar framework fixes.
