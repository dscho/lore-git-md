This is a technical discussion about follow-up cleanups to the recently completed `mktemp(3)` removal series, specifically focusing on the Windows compatibility layer's `gitmkdtemp()` wrapper.

René Scharfe responds to Jeff King's suggestions for simplifying the build system integration of the new `git_mkdtemp()` function. While agreeing with the general direction, Scharfe notes several practical complications: the CMake build being broken on macOS, limited ability to test NO_MKDTEMP configurations across all build systems, and the need to carefully coordinate changes across Makefile, meson, and CMake build systems. He suggests these cleanups should be done in a separate patch due to their complexity.

The discussion reveals two potential paths forward: 1) An immediate cleanup to remove the redundant `gitmkdtemp()` wrapper while keeping the NO_MKDTEMP knob (requiring careful build system updates), or 2) A more comprehensive solution that would eliminate NO_MKDTEMP entirely by always using `git_mkdtemp()`, which would require updates to configure.ac and other build files. Scharfe leans toward the latter approach but suggests it should be handled in a future series.

Key technical points include:
- The need to maintain the function_checks dictionary entry for NO_MKDTEMP even when removing the implementation file
- Required parallel changes to contrib/buildsystems/CMakeLists.txt
- The eventual possibility of banning mkdtemp(3) entirely rather than just redirecting to the secure wrapper

The exchange demonstrates the careful consideration given to build system maintenance in Git, particularly when making security-related changes that touch multiple platforms and build configurations. Both participants show awareness of the tradeoffs between immediate cleanup and more comprehensive architectural improvements.
