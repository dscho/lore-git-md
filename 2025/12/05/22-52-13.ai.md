Junio Hamano's response to the build-time configuration discussion in the submodule path encoding series. This is part of the ongoing architectural refinement of the feature that aims to prevent filesystem conflicts in submodule gitdirs through config-based path resolution.

Junio questions the need for build-time configuration (via meson/Makefile) for enabling submodule path encoding, arguing that runtime configuration (through gitconfig) should suffice. He points out that managed environments can already distribute config changes via system-wide gitconfig files, making build-time enablement seem unnecessary. This pushes back against Adrian Ratiu's position that build-time options provide convenience for users who find config distribution difficult.

The email reinforces Junio's previously stated principle of minimizing user intervention, but clarifies that this should be achievable through runtime mechanisms rather than compile-time choices. This suggests a preference for keeping the configuration layer unified at runtime rather than splitting it between build and runtime settings. The response implies that the build-time enablement option may be an overcomplication of the design.

Key technical points referenced:
- The `extensions.submoduleEncoding` config option
- System-wide configuration via `/etc/gitconfig`
- The series' goal of automated transition without manual migration

This email represents the final architectural guidance before Adrian's planned v6 revision, effectively vetoing the build-time configuration approach in favor of a purely runtime solution. The response maintains the series' core principle of config authority while simplifying the implementation by removing the build-time dimension.
