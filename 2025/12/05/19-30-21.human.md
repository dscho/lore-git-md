This is a technical refinement in the submodule path encoding series, focusing on the naming and behavior of the new configuration mechanism. Adrian Ratiu responds to Patrick Steinhardt's feedback about renaming the `extensions.submoduleEncoding` option to better reflect its role as the source of truth for submodule gitdir paths (suggesting `submodulePathConfig` instead). The discussion also addresses error message formatting and memory management nitpicks.

The key debate centers on whether to enforce strict config-based behavior when the extension is enabled. Patrick suggests erroring out if the gitdir config is missing, while Adrian explains the current design intentionally allows fallback behavior to avoid manual migration steps, as requested by Junio Hamano and others. Adrian seeks clarification on how to distinguish between cases where a submodule path should already exist versus when it's being computed for the first time.

This represents the final polishing phase of the series, with architectural agreement on the core approach but ongoing discussion about the exact semantics when the extension is enabled. The changes are straightforward to implement once the behavioral questions are resolved.
