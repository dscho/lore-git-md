This is a technical discussion in the security-focused thread about eliminating insecure `mktemp(3)` usage. René Scharfe responds to Jeff King's suggestions for further cleanup of the temporary directory creation code.

The exchange focuses on simplifying the build system integration now that the new `git_mkdtemp()` wrapper provides a portable implementation. Jeff had proposed two approaches: (1) an immediate cleanup removing the redundant `gitmkdtemp()` wrapper while keeping the NO_MKDTEMP knob, or (2) a more aggressive approach eliminating the knob entirely since `git_mkdtemp()` handles all cases.

René notes practical complications with the first approach across multiple build systems (Makefile, meson, CMake), particularly given CMake's broken state and his limited ability to test NO_MKDTEMP scenarios. He suggests this cleanup deserves its own patch due to the non-trivial build system changes required.

The discussion reveals an interesting tension - while removing the NO_MKDTEMP knob entirely would be cleaner long-term, it would mean automatically redirecting `mkdtemp()` calls rather than banning the insecure function outright. Both developers seem to prefer eventually banning `mkdtemp(3)` completely, but recognize this requires careful build system coordination.

This email shows the meticulous attention to detail in Git's security-related changes, where even after the core functionality is secured, the team carefully considers the cleanest way to remove legacy infrastructure without introducing new build complications.
