This is a Windows-specific bugfix in the ongoing series preparing Git's test suite for MSYS2's symlink support. The patch addresses a behavioral mismatch where Windows' `_wopen()` would incorrectly create files through dangling symlinks when given `O_CREAT|O_EXCL` flags, while Linux (and Git's expectations) would return `EEXIST`.

The change modifies `mingw.c` to explicitly check for this case: when opening with create/exclusive flags, it first checks if the path exists and is a symlink (reparse point), returning `EEXIST` if so. This makes Windows behavior match Linux for test t4115.8, which expects `--reject` to fail when encountering an existing symlink rather than overwriting it.

Key technical details:
- Adds `WIN32_FILE_ATTRIBUTE_DATA` check before the open operation
- Uses `GetFileAttributesExW` to detect symlinks via `FILE_ATTRIBUTE_REPARSE_POINT`
- Maintains the existing `mingw_open()` function signature and fallback paths
- Specifically enables t4115.8 (reject symlink handling) to pass under MSYS2 symlinks

This is a focused change that cleanly handles one edge case in Windows symlink emulation while preserving the broader approach approved in v1. The commit message clearly explains the Linux/Windows behavioral difference and which test case this enables.
