This is a technical refinement in the submodule path encoding series, specifically addressing naming and validation concerns. Adrian Ratiu responds to Patrick Steinhardt's feedback on the implementation details of the submodule gitdir path encoding mechanism.

Key technical points in this response:
- Agrees to rename the extension from `extensions.submoduleEncoding` to `submodulePathConfig` to better reflect its role in establishing config-as-source-of-truth
- Acknowledges and will fix several minor issues: typo ("gitidir"), unnecessary `FREE_AND_NULL` usage, and error message capitalization
- Explains the current design rationale for fallback behavior when gitdir config is missing (following Junio Hamano's guidance to avoid manual migration)
- Seeks clarification on Patrick's suggestion to split path computation into two distinct cases (deriving vs computing paths), noting the current unified usage pattern and deployment constraints

The discussion reveals an architectural tension between:
1. The desire for strict config-based behavior when the extension is enabled
2. The practical need to support gradual migration without manual intervention
3. The challenge of distinguishing between "should exist" and "new creation" cases in the current implementation

Adrian maintains the position that the centralized `submodule_name_to_gitdir()` API should handle both cases while being open to making the validation paths more explicit. The exchange highlights ongoing refinement of the validation strategy, particularly around when to enforce strict config requirements versus allowing computed fallbacks.
