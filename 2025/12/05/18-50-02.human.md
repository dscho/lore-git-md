This is a follow-up in the performance optimization thread for promisor object handling in packfiles. Aaron Plattner responds to Jeff King's suggestion to use `PARSE_OBJECT_SKIP_HASH_CHECK` to avoid loading blobs entirely when processing promisor objects.

Aaron confirms the flag doesn't improve performance in his case because `parse_object_with_flags()` hits a case where objects with `OBJ_NONE` type still get inflated. He identifies this relates to commit 8db2dad7a04's logic and proposes modifying the type check to include `OBJ_NONE` objects. With this change combined with Jeff's flag suggestion, he achieves a significant speedup (from 76 minutes originally to under 2 minutes).

The email shows good technical engagement with the proposed solution while identifying an edge case that wasn't fully addressed. Aaron's measured approach and reference to prior commits demonstrates careful consideration of the change. This moves the discussion forward by validating Jeff's approach while identifying needed adjustments to handle all object states properly.
