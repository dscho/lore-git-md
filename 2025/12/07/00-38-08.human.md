Maintainer decision on short-option completion patch. Junio C Hamano has officially closed the discussion on adding bash completion for Git's short options (-C, -P, etc.), siding with SZEDER Gábor's earlier critique that such completion provides limited value without accompanying help text. 

This marks the end of Wiktor Mis's patch series (now at v2) that aimed to enable `git -<TAB>` completion. The fundamental objection wasn't about the code quality - which had previously been accepted with minor tweaks - but rather about the philosophical stance that shell completion should be meaningfully helpful, not just technically possible. 

Junio references a 2007 discussion that established this principle, noting that without the ability to display explanatory text (like "-p (enable pager)"), short-option completion offers little practical benefit to users. The thread demonstrates Git's longstanding emphasis on discoverability in its completion system, where showing context is prioritized over raw efficiency gains.

The patch is now formally discarded, with Junio thanking Wiktor for the contribution while making clear this direction doesn't align with the project's completion philosophy. This decision leaves Git's bash completion behavior unchanged - short options remain uncompleted when pressing Tab.
