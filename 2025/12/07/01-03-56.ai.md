Documentation patch clarifying the behavior of Git's bash completion script regarding short options and arguments.

This patch updates the header comment in `git-completion.bash` to be more precise about what types of completions are supported. The original text from 2007 stated that the script completes "common --long-options", which implicitly excluded uncommon long options and all short (single-letter) options. The new text makes this exclusion explicit by stating "but not single-letter options" while also adding that arguments to both long and short options are completed (like `-c` followed by configuration variables).

The change is straightforward and well-motivated by the historical context provided in the commit message. The patch maintains consistency with the actual behavior of the completion script while making that behavior more transparent to readers of the file. The diff shows the exact wording changes to the comment block, which now better reflects the script's capabilities.
