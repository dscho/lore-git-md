This is a discussion about index extension compatibility in the context of Scalar's configuration cleanup.

Junio Hamano responds to Patrick Steinhardt's analysis of the index.threads/index.recordOffsetTable interaction, which traces back to a 2018 compatibility decision (commit 2a9dedef2e). While Patrick suggests reconsidering the default behavior since the original compatibility concerns may now be outdated, Junio provides important technical context about Git's index extension handling.

Key technical points clarified:
- Any Git version complains about mandatory extensions it doesn't understand
- All versions (even current) note when ignoring optional extensions
- The "ignoring" message only appears when downgrading Git versions
- Index files being local makes this scenario relatively rare
- The notification is actually useful when users downgrade versions
- The age of the compatibility decision (7 years) isn't the key factor
- The design should be evaluated based on whether suppressing the message is actually desirable

Junio argues that even if this were made recently, suppressing the "ignoring" message for optional extensions may not be the right approach, as it hides potentially useful information when users downgrade versions. This provides important context for evaluating whether to change Scalar's current behavior regarding index.recordOffsetTable defaults.

The discussion doesn't block the current Scalar config series but provides deeper insight into index extension handling that could inform future decisions about both Scalar's configuration and core Git behavior. It surfaces that the original motivation for the suppression may have been misguided rather than just outdated.
