Feature discussion about structured data versioning, with a new perspective from Simon Richter focusing on relational database approaches.

Simon Richter contributes to the ongoing thread about versioning structured data by proposing an alternative approach using relational databases with temporal columns, rather than modifying Git or using specialized version control systems. He suggests using valid-time columns with range constraints to track both when data was valid and when it was current in the database, which could serve as a built-in versioning mechanism.

The email provides concrete examples from KiCad's file format challenges, illustrating how Git's line-oriented diff struggles with three-dimensional data where object positions may change across multiple axes. Richter notes that while Git could theoretically store such data, it would require custom diff/merge tools that understand the data's semantics - similar to how Git handles move detection but more complex.

This contrasts with the thread's previous focus on evaluating existing version control systems (DVC/Dolt/Fossil) or modifying Git's internals. Richter's approach suggests that some structured data might be better served by database-native versioning rather than filesystem-based version control, though he acknowledges this may not apply to all data structures.

Key technical points include: temporal database techniques using range types and constraints; the specific challenge of diffing 3D CAD data where object positions may appear as deletions/creations; and the general observation that any solution requires semantic-aware tooling whether built into Git or external. The email doesn't directly address previous tools discussed (Dolt/Fossil) but provides a different architectural perspective.

This moves the discussion into considering database-native approaches alongside filesystem-based version control, though it doesn't resolve the original question of whether/how Git should be modified for structured data. The KiCad example provides a concrete use case where even text-serialized structured data poses significant diff/merge challenges with Git's current model.
