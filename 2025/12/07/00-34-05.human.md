This is a discussion about index extension compatibility in the context of Scalar's configuration cleanup.

Junio Hamano responds to Patrick Steinhardt's suggestion about reconsidering the default behavior of `index.recordOffsetTable` (which is tied to `index.threads`). The behavior dates back to a 2018 change for backwards compatibility, where enabling threads would write the offset table extension, but avoiding it by default to prevent warnings from older Git versions seeing unknown extensions.

Junio clarifies that the concern isn't just about older versions - any Git version will complain about mandatory extensions it doesn't understand, and will note when ignoring optional ones. He argues that the 7-year timeframe isn't the key factor, since the warning only appears when downgrading Git versions, which is rare. He suggests that if the only reason for the current behavior is to avoid these non-critical warnings, the design should be reconsidered regardless of how old the decision is.

This discussion surfaces an interesting architectural consideration about how Git handles index extensions, though it's noted this doesn't block the current Scalar config cleanup series. The exchange provides useful context about how long-standing compatibility decisions might be reevaluated as assumptions change.
