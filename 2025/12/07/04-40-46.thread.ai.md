Thread identity: Bugfix patch addressing memory leak in Git push protocol when pushing to multiple remotes configured as a group.

Core problem: Memory leak occurs in `process_capabilities()` in `connect.c` where server capabilities_v1` string is overwritten without freeing previous allocation when pushing to multiple remotes in a group.

Current status: Patch v1 proposed with fix and test coverage. Not yet merged. Fix adds `free()` call before overwriting capabilities string.

Key technical details:
- Leak location: `process_capabilities()` in `connect.c`
- Each connection allocates new string via `xstrdup()`
- Test case `t5565-push-multiple.sh` added to exercise push-to-group functionality
- Test creates 3 dummy repos configured as pushurls for single remote "them"
- Verifies identical ref states across all destinations after push

Open questions: None raised yet - appears to be straightforward fix. Author notes some difficulty reproducing with both leak+address sanitizers but confirms reliable detection with leak sanitizer alone.

Participant positions: Junio provided detailed context explaining this fixes one specific issue while broader static variable problems remain (but are out of scope for this fix).

Related work: Part of ongoing effort to improve memory management in Git's remote connection handling.
