Thread identity: Bugfix patch addressing memory leak in Git push protocol when pushing to multiple remotes configured as a group.

Core problem: Memory leak occurs in `process_capabilities()` in `connect.c` where `server_capabilities_v1` string is overwritten without freeing previous allocation when pushing to multiple remotes in a group.

Current status: Patch v1 proposed with fix and test coverage. Not yet merged. Fix adds `free()` call before overwriting capabilities string. Patrick Steinhardt reviewed and approved the technical approach while suggesting optional test reorganization.

Key technical details:
- Leak location: `process_capabilities()` in `connect.c`
- Each connection allocates new string via `xstrdup()`
- Test case `t5565-push-multiple.sh` added to exercise push-to-group functionality (Patrick notes related tests exist in `t5505` but considers this a minor organizational point)
- Test creates 3 dummy repos configured as pushurls for single remote "them"
- Verifies identical ref states across all destinations after push

Open questions: None raised - appears to be straightforward fix. Author notes some difficulty reproducing with both leak+address sanitizers but confirms reliable detection with leak sanitizer alone.

Participant positions:
- Junio provided detailed context explaining this fixes one specific issue while broader static variable problems remain (but are out of scope)
- Patrick Steinhardt reviewed and approved the technical approach, suggesting optional test reorganization (moving to `t5505`) as a minor improvement

Related work: Part of ongoing effort to improve memory management in Git's remote connection handling.
