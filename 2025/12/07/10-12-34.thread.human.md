The thread discusses the potential deprecation of `git whatchanged`, a command that duplicates `git log --raw` functionality but remains in use due to its simplicity. While the command currently shows a deprecation warning suggesting migration to `git log`, no final decision has been made about its removal.

Kristoffer Haugsbakk weighed in, acknowledging that while `git log --raw` can be verbose, different workflows have merit. He proposed a concrete migration path by suggesting users could set up an alias (`git config set --global alias.whatchanged 'log --raw --no-merges'`) to preserve the familiar command if removal proceeds. This practical suggestion addresses concerns about complex option memorization while still moving toward the eventual goal of reducing redundant command maintenance.

The discussion remains balanced between technical debt and user experience considerations, with this latest contribution focusing on making any transition smoother rather than taking a firm position for or against deprecation. The alias proposal may influence how the project structures future deprecation messages if the maintainers decide to proceed with removing the command.
