This is a user feedback email regarding the potential deprecation of `git whatchanged`.

Lee Smith writes in to say they still regularly use `git whatchanged` despite being a Git user who learned after `git log` was introduced. They find it useful as a simpler alternative to remembering all of `git log`'s various options. While understanding the maintenance burden might justify removing it, they suggest that if the command is deprecated, the warning message should recommend creating an alias as an alternative.

The email provides a data point from an actual `git whatchanged` user, showing there is still some utility in the command's simpler interface compared to `git log`. The suggestion about improving deprecation messaging is practical and user-focused. The tone is constructive and acknowledges the maintainers' perspective while advocating for user experience considerations.
