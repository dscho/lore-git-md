This is a bugfix patch addressing a memory leak in the Git push protocol handling. The issue occurs when pushing to multiple remotes configured as a group - the server capabilities from each connection overwrite a static variable `server_capabilities_v1` without freeing the previous allocation, causing memory leak.

The patch adds a `free()` call before overwriting the capabilities string in `connect.c`. Junio provides a detailed explanation of the context - while there are broader issues with static variables preventing parallel connections (which this patch doesn't address), this specific leak is straightforward to fix. The commit includes a new test case `t5565-push-multiple.sh` that exercises the push-to-group functionality and would fail under leak detection without the fix.

Key technical details:
- The leak occurs in `process_capabilities()` in connect.c
- Each connection allocates a new string for capabilities via `xstrdup()`
- The test creates 3 dummy repositories and configures them as pushurls for a single remote "them"
- The test verifies identical ref states across all destinations after push

The patch is small and focused, with clear justification and test coverage. The author notes some difficulty reproducing the leak with both leak+address sanitizers, but confirms it's reliably detected with leak sanitizer alone. This appears to be a straightforward correctness fix for a clear memory management issue.
