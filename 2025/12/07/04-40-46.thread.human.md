This thread addresses a memory leak in Git's push protocol when pushing to multiple remotes configured as a group. The core issue occurs in `process_capabilities()` where `server_capabilities_v1` gets overwritten without being freed between connections. The initial patch (v1) provides a straightforward fix by adding the missing `free()` call and includes a test case in `t5565-push-multiple.sh` that verifies push behavior across multiple destinations.

Patrick Steinhardt reviewed and approved the technical approach, though he noted the test might better belong in `t5505` which contains related remote configuration tests. Junio Hamano later clarified that `t5505` focuses more on configuration management while `t5565` is the more appropriate home for testing operational push behavior, so the test will remain where initially placed.

The discussion participants agree this is a clean fix for a specific issue, while acknowledging broader static variable concerns remain (but are out of scope for this patch). With both technical approval from Patrick and test placement confirmation from Junio, the patch appears ready for merging with no outstanding objections.
