This thread addresses a memory leak in Git's push protocol that occurs when pushing to multiple remotes configured as a group. The issue was found in `process_capabilities()` in `connect.c`, where the `server_capabilities_v1` string was being overwritten without freeing the previous allocation. The original patch (v1) from Junio Hamano proposes adding a `free()` call before overwriting the string and includes a new test case in `t5565-push-multiple.sh` to verify the fix.

Patrick Steinhardt has reviewed the patch and agrees the fix is correct. He suggests the test might better belong in `t5505` alongside other push group tests, but notes this is a minor organizational point and doesn't block the patch. The discussion confirms this is a straightforward fix for a specific issue, while acknowledging there are broader static variable problems in remote connection handling that remain to be addressed separately. With no substantive objections raised and the fix receiving positive review, this appears ready to be picked up for merging.
