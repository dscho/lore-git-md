This thread addresses a memory leak in Git's push protocol when pushing to multiple remotes configured as a group. The leak occurs in `process_capabilities()` where the `server_capabilities_v1` string was being overwritten without freeing the previous allocation. The initial patch (v1) from the author fixes this with a simple `free()` call and adds test coverage in `t5565-push-multiple.sh` to verify the behavior.

Junio Hamano and Patrick Steinhardt both reviewed the patch, with Patrick suggesting the test might belong in `t5505` (which focuses on remote configuration) while Junio argued it fits better in `t5565` (which tests operational push behavior). The technical approach was approved, with Junio noting this fixes one specific issue while broader static variable problems remain out of scope.

Jeff King (Peff) later chimed in with a tangential observation about the misleading variable name `server_capabilities_v1` - it actually refers to v0 protocol capabilities, with v1 being an unused variant. While agreeing the memory leak fix is correct, he noted this historical oddity in the naming, mentioning he'd cleaned up similar cases in the test suite but didn't consider this instance worth changing independently. The core fix remains uncontroversial and appears headed for merging.
