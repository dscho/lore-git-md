This is a technical discussion contribution about versioning structured data, adding relational database perspectives to the ongoing thread comparing Git modifications versus specialized tools like Dolt and Fossil.

Simon Richter responds to Cedric Sodhi's original question about structured data versioning by proposing an alternative approach using temporal database techniques. He suggests using valid-time columns in relational databases to track historical states, which avoids some of the diff/merge challenges Git faces with structured data. Richter draws from experience with KiCad's 3D design files, illustrating how Git's line-oriented diffs struggle with multidimensional data where object positions in serialized files don't correspond to their logical relationships.

The email makes two key points: (1) relational databases can natively model versioning through temporal tables and constraints, and (2) Git's diff algorithms fundamentally assume one-dimensional text changes, making them poorly suited for multidimensional structured data without custom tooling logic. Richter concludes that while Git could store such data, the effort required to build appropriate diff/merge plugins may not be justified when databases already offer versioning capabilities.

This contribution shifts the discussion's focus from comparing existing version control systems to considering database-native versioning techniques, while reinforcing the thread's core observation that Git's text-file assumptions create fundamental mismatches with structured data. The technical depth and concrete examples (KiCad file formats, temporal database constraints) make this a substantive addition to the conversation.
