This is the first patch in a documentation series improving the `git replay` man page. It addresses a subtle but important behavioral difference between `git replay` and other Git commands when handling conflicts.

The patch explicitly documents that `git replay` produces no stderr output when conflicts occur, unlike many other Git commands which typically notify users about conflicts. The change adds this clarification right before the EXIT STATUS section and properly links to that section using Asciidoc markup.

The commit message is straightforward and the change appears well-targeted - it solves a specific documentation gap that could confuse users expecting conflict notifications. The patch is part of a larger effort to improve `git replay` documentation, with two more patches coming that will document the `--contained` option and improve internal linking.

This seems like a useful clarification for a relatively new to Git (added in 2.43) and still-evolving command. The change is small but meaningful for users who might otherwise be surprised by the silent conflict behavior.
