Documentation patch clarifying Bash completion behavior. Junio Hamano updates the header comment in `git-completion.bash` to better document what types of completions are supported. The original text from 2007 only mentioned completion of "common --long-options", which left the status of short options and their arguments ambiguous.

The patch makes two clarifications: first, it explicitly states that single-letter options (like -c) are not completed, though this was already implied by the original text. More importantly, it documents that arguments to options *are* completed, even for single-letter options - for example, tab completion after `git -c` will suggest configuration variables.

This is a straightforward documentation improvement that better reflects the actual behavior of the script. The change is minimal (just two lines modified) but helps set clearer expectations for users and future maintainers of the completion script.
