Lucas Seiki Oshiro's patch series to add a `--keys` flag to `git repo info` has progressed to its second version, now with format support included. The feature, originally suggested by Junio Hamano, allows listing available repository information keys programmatically without their values - a useful capability for scripting and test maintenance.

The v2 series addresses the key open question from the initial review by implementing full format support, including NUL-terminated output via `-z`, rather than rejecting format options outright. The implementation carefully maintains separation between key listing and value printing, with strict validation to prevent invalid usage like combining `--keys` with `--all` or specific key requests. Test coverage has been expanded to verify the new format handling.

Junio and Patrick Steinhardt have both engaged with the series, with Patrick providing wording suggestions in the initial review. The changes build cleanly on the existing `repo-info` infrastructure while aligning with Git's broader direction toward better programmatic interfaces. With format support now implemented and thorough test coverage, the series appears ready for final review and potential merging.
