Lucas Seiki Oshiro has sent a revised version of the `git repo info --keys` patch series, addressing Junio Hamano's review feedback on the initial submission. The feature adds a flag to list available keys without values, making it easier to programmatically discover what information can be requested.

The revision makes the behavior more robust by explicitly rejecting invalid combinations - the command will now error out if `--keys` is used with either `--all` or specific key arguments. The author considered but decided against adding `-z` support for NUL-terminated output in this version, as it would complicate the format handling. Instead, they're leaning toward keeping the implementation simple by rejecting format-related options when using `--keys`.

Junio had originally suggested this feature and approved the general approach, while requesting specific fixes around error handling and documentation. Patrick Steinhardt also contributed a minor wording improvement to the commit message. With these changes addressing the review feedback, the patch appears ready for merging once the final design decision about format handling is settled. The implementation builds cleanly on the recent `lo/repo-struct-z` changes in the codebase.
