This thread centers on adding a `--keys` flag to `git repo info`, implementing Junio Hamano's suggestion to enable programmatic discovery of available repository information fields. Lucas Seiki Oshiro drove the implementation through three versions, with key input from Junio and Patrick Steinhardt.

The initial proposal introduced the basic `--keys` functionality, which was later expanded in v3 to fully support output formats (`-z`/`--format`). The final implementation includes strict validation to prevent mixing `--keys` with `--all` or specific key requests, comprehensive test coverage, and clear documentation. The technical work builds on commit bdc5341ff6 and introduces a `FORMAT_DEFAULT` enum to cleanly handle output formatting.

Junio originally suggested this feature to reduce test maintenance burden by replacing hardcoded key lists with dynamic verification. The discussion converged cleanly, with v3 resolving all open questions about format handling. The patch is now in good shape, with no outstanding issues, and aligns well with Git's direction toward better programmatic interfaces.
