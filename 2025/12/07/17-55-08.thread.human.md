This thread documents improvements to the `git replay` man page, addressing some gaps in its documentation. The author has sent a 3-part series that clarifies `git replay`'s silent conflict resolution behavior (unlike other Git commands that typically show conflict output) and adds documentation for the previously undocumented `--contained` option. The changes also include proper Asciidoc markup for internal section links.

The first patch in the series specifically documents the silent conflict behavior, adding a note in the main documentation section with a cross-reference to the EXIT STATUS section. The author explains this change was motivated by their own confusion when using the command. The patches are limited to `Documentation/git-replay.adoc` and follow standard documentation conventions.

As this is the initial submission, there hasn't been any review feedback yet. The changes document existing behavior rather than introducing new functionality, so they're unlikely to be controversial, though reviewers might suggest wording refinements. The work fits into the broader effort to improve documentation quality, though it's separate from the larger synopsis-style conversion project.
