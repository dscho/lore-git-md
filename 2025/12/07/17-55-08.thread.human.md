This thread documents the evolution of improvements to the `git replay` man page, now merged to the 'next' integration branch. Kristoffer Haugsbakk's three-part series clarified two key aspects of the command: how it silently resolves conflicts (documenting the existing behavior) and precisely defining what the `--contained` option does (updating branches pointing to commits in the revision range). The changes standardized documentation links and ensured the help text matched the man page.

After the series was merged, Junio Hamano reflected on how one commit message could have been clearer. While the changes were purely documentation improvements, the original wording might have suggested behavioral modifications. He proposed an alternative structure that would make the intent unmistakable: quoting the original text, identifying the clarity issue, then explaining the improved phrasing. Kristoffer acknowledged this as valuable guidance for future documentation patches. Phillip Wood had earlier confirmed the technical accuracy of all changes.

The discussion now serves as a case study in writing commit messages that stand alone - particularly important for documentation changes where the diff alone might not reveal the full context. While no further changes are needed (the series is already merged with all substantive feedback addressed), the exchange reinforces the project's standards for commit message clarity. Toon Claes' earlier note about potential future changes to conflict behavior remains the only forward-looking consideration from this thread.
