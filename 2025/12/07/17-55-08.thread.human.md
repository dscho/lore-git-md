This thread documents improvements to the `git replay` man page, focusing on clarifying the behavior of the `--contained` option. The original patch series from Kristoffer Haugsbakk added documentation for previously undocumented features while standardizing the Asciidoc markup. 

Key participants have converged on keeping the original "contained in <revision-range>" phrasing that matches the implementation, though alternatives like "tip of the branch" (suggested by Junio) and now "tip commit" (proposed by Phillip Wood) were considered to make the description more intuitive. Testing confirmed that the command fails when branches span revision ranges but works for simple cases. 

While the core behavior is now well-documented, some open questions remain about whether to include an example and whether the silent conflict resolution behavior might need changes in the future. The discussion remains focused on wording clarity rather than functionality, with Junio having already approved the series. Phillip's latest input continues the terminology debate but doesn't introduce new technical considerations - it primarily suggests including "commit" in the description to make the operation's target more explicit.
