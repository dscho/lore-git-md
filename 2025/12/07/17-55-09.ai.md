Documentation patch for `git replay` clarifying its silent conflict behavior.

This is the first of a 3-part series improving the `git replay` man page. The patch explicitly documents that `git replay` produces no stderr output when conflicts occur, unlike many other Git commands. The change adds a brief note about this behavior in the main documentation section, with a cross-reference to the EXIT STATUS section (which is also properly marked with an Asciidoc anchor in this patch).

The modification is straightforward and clearly motivated by the author's personal experience with the command. The patch follows standard documentation conventions by using proper Asciidoc markup for internal links. Since this documents existing behavior rather than changing functionality, it's unlikely to be controversial, though reviewers might suggest tweaks to the exact wording.

Key technical details for future reference:
- Adds documentation about silent conflict behavior
- Introduces `<<exit-status>>` anchor for cross-referencing
- Modifies only `Documentation/git-replay.adoc`
- Part of broader effort to document `git replay`'s unique characteristics

The patch appears well-formed and focused, addressing a clear gap for users who might expect conflict output similar to other Git commands like `rebase` or `merge`.
