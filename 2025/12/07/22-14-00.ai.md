This is a review response to the `git repo info --keys` feature patch from Junio Hamano, the Git maintainer. The patch itself adds a `--keys` flag to list available repository information keys without values, implementing a suggestion Junio had made earlier.

Junio generally approves of the patch's concept and commit message clarity, but identifies several technical issues with the current implementation. The main problems are that the flag doesn't properly handle combinations with other options: it silently ignores `--all` and key arguments when `--keys` is given, and doesn't respect the `-z` format flag for NUL-terminated output. 

He suggests modifying the code to explicitly error out when `--keys` is combined with `--all` or key arguments, and to properly support NUL-terminated output by passing the format to `print_keys()`. The changes would make the behavior more consistent with Git's usual command-line interface patterns.

The review maintains the positive trajectory of this feature addition while pointing out specific areas needing refinement. Junio's feedback focuses on making the implementation more complete and robust rather than questioning the feature's value, suggesting this is likely to proceed once these technical details are addressed.
