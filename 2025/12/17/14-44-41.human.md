This is a follow-up discussion on the second patch in the Windows symlink preparation series, focusing on early config parsing during `git init`. Patrick Steinhardt confirms the technical soundness of the change from `platform_core_config` to `git_default_core_config` in `setup.c`.

The patch ensures core settings (including `core.symlinks` on Windows) are parsed before template copying during repository initialization, addressing a timing issue where template-based configs would otherwise override these settings. Steinhardt notes this doesn't introduce duplicate parsing - `git_default_core_config` already includes `platform_core_config`'s, and the later full config parse after template copying remains necessary.

The analysis validates the change as a safe optimization that maintains existing behavior while fixing the initialization order, an important prerequisite for reliable symlink support. This continues the series' pattern of focused, well-justified technical improvements.
