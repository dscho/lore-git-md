This is a bugfix response in the ongoing submodule gitdir path encoding series. Adrian Ratiu acknowledges Josh Steadmon's report of unexpected behavior when testing the submodule path encoding functionality, specifically that the collision detection/encoding isn't triggering as expected during submodule operations.

The issue occurs when trying to add a submodule with a path that would conflict with an existing encoded path (nested%2fsub). Instead of encoding the path as intended, the operation fails with an error about finding an existing git directory. Adrian confirms this is a valid test case that will be added to the test suite in v7.

Key technical details:
- The problem appears related to global config handling of `extensions.submodulepathconfig`
- Existing submodules won't automatically get their `submodule.<name>.gitdir` configs created
- Two ways to create these configs are provided: manual per-submodule config setting or using the new `git submodule--helper migrate-gitdir-configs` command
- The migration command both creates the extension config and sets up all submodule gitdir configs atomically

Adrian indicates v7 will fix the global config issue and invites further questions. This response helps clarify the expected workflow for existing repositories while confirming a real bug that will be addressed in the next version of the patch series.
