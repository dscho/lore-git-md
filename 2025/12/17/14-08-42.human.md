This is part 5 of a major platform compatibility series introducing symbolic link support for Windows. The patch focuses on improving directory entry handling for symlinks.

The change moves symlink detection logic into a central helper function (`file_attr_to_st_mode`) and adds proper symlink type reporting (`DT_LNK`) in directory listings. This cleans up the code by removing duplicate symlink checks from `mingw_lstat()` while maintaining the same functionality. The implementation now properly identifies symlinks both when stat'ing files directly and when scanning directories.

This continues the series' pattern of methodically building POSIX-compatible symlink support by handling one subsystem at a time. The changes are focused and well-contained, touching only the MinGW compatibility layer. The patch carries signatures from both Karsten Blees and Johannes Schindelin, indicating it incorporates lessons from Git for Windows' long-running symlink support development.

The technical changes are straightforward but important for proper filesystem behavior - directory listings will now correctly identify symlinks alongside regular files and directories. This brings Windows behavior closer to Unix systems where symlinks are first-class citizens in directory operations.
