Thread identity: Major platform compatibility patch series introducing symbolic link support for Windows (18 patches, now at v1 with contributions from Bill Zissimopoulos, Johannes Schindelin (Dscho), and Karsten Blees). Builds on Git for Windows' symlink implementation that has been maturing since 2015.

Core problem/goal: Upstream comprehensive Windows symlink support by implementing POSIX-like symlink operations in the MinGW compatibility layer, including creation, reading, stat'ing, directory handling, and now renaming. Key technical components include proper `stat()`/`lstat()` implementation, `readlink()` functionality, directory symlink handling in `unlink()`/`chdir()`, symlink-specific error codes, and robust rename operations. Now includes default behavior configuration with `core.symlinks=false` on Windows.

Current status: Eleven patches submitted (v1). Patch 6 introduces accurate symlink size reporting in `mingw_lstat()`. Patch 7 refactors retry logic for file operations. Patch 8 changes default `core.symlinks` to false on Windows. Patch 9 adds Windows-to-POSIX error code mappings. Patch 10 addresses directory symlink deletion behavior. New patch 11 fixes symlink renaming by replacing problematic CRT `_wrename()` with direct `MoveFileEx()` calls. Series builds on long-running Git for Windows development. Not yet in any integration branch.

Key technical details: Touches primarily `compat/mingw*` and `dirent.c` files. Patch 1 eliminates redundant `GetFileAttributes()` call. Patch 2 implements symlink resolution in `mingw_stat()`. Patch 3 refactors `do_lstat()`. Patch 4 improves reparse point detection. Patch 5 moves symlink mode detection into `file_attr_to_st_mode()`. Patch 6 introduces `read_reparse_point()` for proper symlink target length handling. Patch 7 factors out retry logic into `retry_ask_yes_no()`. Patch 8 modifies Windows environment setup. Patch 9 adds error code translations. Patch 10 handles directory symlink deletion. Patch 11 restructures `mingw_rename()` to use `MoveFileEx(MOVEFILE_REPLACE_EXISTING|MOVEFILE_COPY_ALLOWED)` instead of `_wrename()`, maintaining the series' pattern of replacing CRT functions with direct Win32 API calls. Each patch demonstrates ongoing code simplification alongside functional improvements, with patch 11 specifically addressing silent failure cases in symlink renaming operations.
