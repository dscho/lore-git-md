This is a security-related patch in the ongoing series addressing ANSI escape sequence injection vulnerabilities (CVE-2024-32002, CVE-2024-52005). The patch modifies the default behavior of `sideband.allowControlCharacters` to permit ANSI color sequences while still blocking other potentially dangerous control characters.

The key changes include:
- Restructuring the configuration option into an enum with three states: `default` (allowing colors), `false` (blocking all non-whitelist controls), and `true` (full passthrough)
- Adding specific handling for ANSI SGR (Select Graphic Rendition) sequences via new `handle_ansi_color_sequence()` function
- Updating tests to verify color sequence passthrough while still blocking other control characters like BEL (`\a`)

The patch responds to Brian Carlson's real-world use case where `pre-receive` hooks rely on color output, arguing that color sequences pose minimal security risk compared to other control characters. The implementation maintains security for other sequences while accommodating this common workflow.

Technical details of note:
- New `ALLOW_ANSI_COLOR_SEQUENCES` flag (1<<0) in the control character policy enum
- SGR sequence validation follows the pattern `ESC [ [<n> [; <n>]*] m`
- Test cases now verify both color preservation and non-color control character blocking
- Warning emitted for unrecognized config values

This represents a compromise position in the ongoing security philosophy debate, allowing colors by default while maintaining protections against more dangerous sequences. The patch builds on previous work in the series while addressing specific user needs raised in the thread.
