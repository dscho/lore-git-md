This is part 4/7 of Justin Tobler's series adding object size reporting to `git repo structure`, focusing on adding inflated object size metrics to the keyvalue and nul output formats.

The patch extends the existing object statistics infrastructure to track and report the total inflated size of objects by type (commits, trees, blobs, tags) in the keyvalue and nul formats. It introduces a new `inflated_sizes` field in the `object_stats` struct to store these metrics alongside the existing type counts. The implementation uses `odb_read_object_info_extended()` to get the inflated size of each object during traversal.

Key technical changes include:
- Added `inflated_sizes` to `object_stats` mirroring the `type_counts` structure
- Modified `count_objects()` callback to accumulate sizes per object type
- Updated `structure_keyvalue_print()` to output new size metrics with `inflated_size` suffix
- Added test assertions for the new size fields in the keyvalue format
- Maintained backward compatibility with existing output formats

The patch builds on the series' established `object_values` architecture and follows the pattern of incremental metric additions. It handles the object database interaction carefully with proper error checking. The test updates verify the new functionality while keeping the existing SHA-1 specific test cases.

This is a straightforward extension of the reporting capabilities that maintains the series' focus on structured, machine-parsable output formats before tackling the more complex table formatting in subsequent patches. The implementation looks solid and well-integrated with the existing codebase.
