This is patch 15/18 in the major Windows symlink support series, focusing on directory symlink creation. It builds on the previous file symlink implementation (patch 14) to handle the Windows-specific requirement that symlinks must declare whether they point to files or directories.

The patch introduces a clever workaround for Windows' strict symlink typing: when creating a symlink to a target that doesn't yet exist (or whose type is unknown), it first creates a tentative file symlink, then checks the target type later when the destination appears. A background tracking system ("phantom symlinks") handles deferred type resolution, particularly when directories are created via `mingw_mkdir()`. The implementation includes thread-safe handling via critical sections and comprehensive error checking.

This represents a key milestone in the series, completing the symlink creation story after the earlier read-side support. The solution is necessarily complex due to Windows API constraints, but the patch shows careful attention to edge cases like cross-process directory creation and type changes. As with previous patches in the series, it maintains the pattern of direct Win32 API usage and builds on the established infrastructure for path handling and error reporting.
