This is patch 3/10 in a series preparing Git's test suite for Windows symlink support, specifically addressing MSYS2's planned default enablement of symlinks. The patch focuses on fixing Windows-specific behavior in `mingw.c` when opening files with `O_CREAT|O_EXCL` flags on symlinks.

The core issue is that Windows' `_wopen()` would incorrectly create files when given these flags on a symlink pointing to a non-existent file, while POSIX (and Git) expects an `EEXIST` error in this case. The fix adds explicit handling to check for symlinks via `GetFileAttributesExW()` and returns the expected error when detected.

This change enables test t4115.8 ("--reject removes .rej symlink if it exists") to pass on Windows with symlink support. The patch builds on previous work in the series and maintains the pattern of making Windows behave more POSIX-like for symlink operations. The implementation is straightforward - checking file attributes before the open operation and returning the expected error code when the path is a symlink.

The patch appears well-contained and motivated, with a clear connection to the series' overall goal of Windows symlink compatibility. It follows the established approach of the series by adding Windows-specific handling while maintaining expected POSIX behavior.
