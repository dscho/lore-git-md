This is a bugfix follow-up in the submodule gitdir path encoding series. Adrian Ratiu acknowledges Josh Steadmon's report that the automatic configuration of `submodule.<name>.gitdir` paths fails silently during `--recurse-submodules` clone operations when the `extensions.submodulePathConfig` extension is enabled globally. This violates the extension's core requirement that all submodule gitdir paths must be explicitly configured.

Adrian confirms this is a real issue stemming from a misunderstanding of how global config should work, and commits to fixing it in v7 of the series. The fix will include proper error handling when required configs are missing, plus additional test coverage for various clone scenarios (with/without `--recurse-submodules` and global config on/off). This addresses one of the two critical issues Josh identified in the current implementation.

The response shows good engagement with the bug report - Adrian quickly recognizes the problem, relates it to prior feedback from Patrick Steinhardt, and outlines concrete steps to resolve it. This keeps the series moving forward after reaching architectural consensus in v6, now focusing on implementation correctness. The fix will be important for ensuring the extension's validation layer works as designed.
