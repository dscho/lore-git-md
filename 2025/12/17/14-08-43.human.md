This is patch 6/18 in a major Windows platform compatibility series introducing proper symbolic link support. The patch focuses on correctly calculating symlink sizes in `mingw_lstat()` to match POSIX behavior.

The patch fixes a long-standing issue where Git for Windows would hardcode symlink sizes to MAX_PATH (260 characters) rather than reading the actual target length. While Git generally doesn't trust symlink sizes, some operations (like `diff_populate_filespec()`) do use them, leading to problems when repositories were accessed by both Git for Windows and other implementations (Cygwin/WSL). The inconsistency caused unnecessary index updates when symlinks hadn't actually changed.

The solution involves properly reading the reparse point data to determine the true symlink length. The implementation handles both symlinks and mount points (junctions), falling back to MAX_PATH for unknown reparse point types. The changes are contained to `compat/mingw.c` and build on Windows-specific APIs like `REPARSE_DATA_BUFFER` and `FSCTL_GET_REPARSE_POINT`.

This appears to be a well-justified fix with clear motivation and thorough implementation. The patch has sign-offs from both Bill Zissimopoulos and Johannes Schindelin, indicating it incorporates prior Git for Windows work. It's part of a larger effort to bring comprehensive symlink support to Windows that's been in development for nearly a decade.
