This is patch 12/18 in the Windows symlink support series, focusing on directory change behavior. The patch modifies `mingw_chdir()` to properly resolve symlinks when changing directories, aligning with POSIX expectations. This is particularly important because Git's `real_path()` function relies on this symlink-resolving behavior of `chdir()`.

The implementation uses Windows API calls (`CreateFileW` with `FILE_FLAG_BACKUP_SEMANTICS` and `GetFinalPathNameByHandleW`) to properly resolve symlinks before changing directories. The patch maintains the existing error handling pattern seen throughout the series, converting Windows error codes to POSIX equivalents. A notable limitation mentioned is that Windows' MAX_PATH (260 character) restriction may cause issues when combining symlinks with long paths.

This continues the series' pattern of replacing CRT functions with direct Win32 API calls for better symlink handling. The change is particularly relevant for operations that depend on path resolution, like `real_path()`, and represents another step toward full POSIX-compatible symlink behavior on Windows. The patch carries signed-off-by from both Karsten Blees and Johannes Schindelin, indicating it builds on their prior Git for Windows work.
