Platform compatibility patch adding Windows symlink error handling. This is patch 9/18 in the series introducing comprehensive symbolic link support for Windows.

The patch adds proper error code translation for Windows-specific symlink-related errors in Git's MinGW compatibility layer. When Windows API calls fail with symlink-specific errors (like invalid reparse data or tag mismatches), they'll now be translated to standard POSIX `EINVAL` errors that Git can handle. This builds on the series' goal of making Windows symlink behavior match POSIX expectations.

The changes are straightforward, mapping five new Windows error codes to `EINVAL`. The patch is small and focused, just adding the new mappings to the existing error translation function in `compat/mingw.c`. Like previous patches in the series, it carries sign-offs from both Karsten Blees and Johannes Schindelin, indicating it incorporates their combined Windows expertise.

This appears to be a necessary plumbing piece before implementing the actual symlink operations in later patches. The error handling will help Git properly report issues when dealing with Windows symlinks, whether they're malformed or encountered in unexpected contexts. The patch maintains the series' careful approach to Windows-POSIX compatibility.
