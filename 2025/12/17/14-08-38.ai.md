Performance optimization patch in the Windows symlink support series. This is the first of 18 patches introducing comprehensive symbolic link support for Windows.

The patch eliminates a redundant `GetFileAttributes()` system call in the Windows stat/lstat implementation. Currently, when handling paths with trailing slashes (which Windows APIs can't process), the code makes an initial failing call before stripping slashes and retrying. The change modifies the path buffer in-place after conversion to wide characters, avoiding the need for the first doomed attempt.

Key technical details: Modifies `compat/mingw.c` to handle path normalization during the initial UTF-8 to wide char conversion. Removes the `do_stat_internal()` wrapper function that previously managed the retry logic, simplifying the call chain to just `do_lstat()`. The wide character buffer modification is safe as it occurs before any system calls.

This appears to be a straightforward optimization building on the series' wider character handling changes. The patch carries signed-off-by tags from both Karsten Blees and Johannes Schindelin, indicating it incorporates prior Git for Windows work. The change reduces code size by removing 36 lines while adding 12, with no apparent behavior change beyond the performance improvement.
