Platform compatibility refactoring in the Windows symlink support series. This patch (7/18) consolidates retry logic for file operations that may fail due to transient Windows file locking issues.

The change factors out duplicated retry-with-delay-and-prompt logic from `mingw_unlink()` and `mingw_rmdir()` into a new `retry_ask_yes_no()` helper function. The helper handles the retry pattern consistently: attempting the operation multiple times with increasing delays (0ms, 1ms, 10ms, 20ms, 40ms), then prompting the user if all retries fail while preserving the original `errno`. The implementation also fixes some edge cases in the original code where `errno` wasn't properly restored after user prompts.

Key technical details:
- Moves the delay array into the new helper function
- Changes `ask_yes_no_if_possible()` to take a `va_list` for consistency
- Updates three operations to use the helper: file deletion (`mingw_unlink`), directory removal (`mingw_rmdir`), and file renaming (in the `repeat` block at the end)
- Maintains special error handling for directory emptiness checks in `mingw_rmdir()`

The patch continues the series' pattern of centralizing and simplifying Windows-specific code while maintaining the same behavior. It touches only `compat/mingw.c`, modifying the retry logic while keeping the same retry timing and user interaction flow. The changes are particularly relevant for operations that might conflict with other processes holding file handles (e.g., editors locking files).
