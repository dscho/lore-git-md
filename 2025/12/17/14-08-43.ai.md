This is patch 6/18 in the Windows symlink support series, focusing on accurate symlink size reporting in `mingw_lstat()`. The patch addresses a long-standing issue where Git for Windows incorrectly reported symlink sizes as MAX_PATH, causing unnecessary index updates when repositories were accessed across different Windows Git variants (Cygwin, WSL).

The key technical change is the introduction of `read_reparse_point()`, which properly extracts symlink target lengths from Windows reparse point data. This replaces the previous shortcut that hardcoded sizes to MAX_PATH. The new implementation handles both symlinks and mount points (junctions), with proper error handling for unknown reparse tags. The patch modifies `mingw.c` to use this new function during `lstat()`, ensuring POSIX-compliant size reporting while maintaining compatibility with existing Windows filesystem behavior.

This builds on the series' progression by addressing a specific interoperability pain point between different Git-on-Windows implementations. The change is particularly notable because it fixes a class of spurious index updates that could occur during cross-toolchain repository access. The implementation shows careful attention to Windows API details while maintaining the POSIX semantics Git expects.
