This is a follow-up discussion on the second patch in the Windows symlink preparation series, focusing on the early parsing of core.* config values during `git init`. Patrick Steinhardt confirms the technical soundness of Johannes Schindelin's change from `platform_core_config` to `git_default_core_config` in setup.c.

The key insight is that while the patch moves config parsing earlier in the initialization sequence, it doesn't actually parse more configuration - it just ensures core settings (including the critical `core.symlinks` for Windows) are available before template copying occurs. Patrick notes this is safe because `git_default_core_config` already includes `platform_core_config` functionality, and the full config will still be re-parsed after templates are copied to catch any template-provided settings.

This discussion validates the patch's approach to solving the initialization ordering problem while maintaining all existing functionality. The change is particularly relevant for Windows where `core.symlinks` needs to be known early, but the solution remains general-purpose by leveraging Git's existing config parsing hierarchy.
