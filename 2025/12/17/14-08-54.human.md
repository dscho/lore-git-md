This is patch 17/18 in a major Windows compatibility series introducing comprehensive symbolic link support. The patch focuses on improving `stat()` emulation for directories with restricted permissions.

The change makes Git's Windows port handle permission-denied directories more like POSIX systems would. Currently, when Git tries to create directories and encounters an existing but unreadable one, the Windows implementation fails completely. The patch modifies `mingw_stat()` to fall back to `mingw_lstat()` in these cases, allowing it to still gather basic directory information even without full access - unless the path is a symlink, where access is still required.

This fixes a specific GitHub issue (#2531) where Git would fail unnecessarily when encountering directories it couldn't fully access. The change is narrowly scoped to the permission-denied case and maintains proper behavior for symlinks. As part of the larger symlink series, it helps provide more POSIX-compatible filesystem behavior on Windows.

The patch appears well-considered, with clear explanation of both the problem and solution. It maintains the careful attention to edge cases (like symlinks) seen throughout this series. Being the 17th of 18 patches, it's part of a mature effort that's clearly approaching completion.
