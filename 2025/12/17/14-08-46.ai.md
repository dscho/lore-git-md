Platform compatibility patch adding Windows symlink error code mappings. This is patch 9/18 in the series introducing comprehensive symlink support for Windows.

The patch focuses on error handling by adding translations for Windows-specific symlink-related error codes to their POSIX equivalents in Git's MinGW compatibility layer. It maps several Windows API error codes (ERROR_INVALID_REPARSE_DATA, ERROR_NOT_A_REPARSE_POINT, ERROR_REPARSE_ATTRIBUTE_CONFLICT, ERROR_REPARSE_TAG_INVALID, ERROR_REPARSE_TAG_MISMATCH) to standard EINVAL errno values. These mappings will be needed for the upcoming symlink operations in later patches.

The changes are straightforward additions to the existing error code translation table in compat/mingw.c, maintaining the pattern already established for other Windows-to-POSIX error mappings. The patch continues the series' careful attention to Windows-POSIX compatibility details, with all changes focused on the MinGW compatibility layer. Like previous patches, it carries sign-offs from both Karsten Blees and Johannes Schindelin, indicating it builds on prior Git for Windows work.

This is a foundational piece for the symlink functionality being added, ensuring proper error reporting when symlink operations fail on Windows. The patch doesn't introduce any new behavior changes itself, but enables proper error handling for the symlink operations that will be introduced in subsequent patches.
