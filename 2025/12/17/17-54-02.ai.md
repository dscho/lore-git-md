This is part 5/7 of Justin Tobler's series adding object size reporting to `git repo structure`, focusing on adding inflated size metrics to the table output format.

The patch introduces human-readable inflated size reporting for objects in the repository structure table output. It adds a new `stats_table_size_addf()` function that formats size metrics using the existing `humanise_bytes()` infrastructure, now enhanced with a new `HUMANISE_COMPACT` flag for abbreviated unit display ("B" instead of "byte/bytes"). The table output shows both total inflated size and per-type breakdowns (commits, trees, blobs, tags).

Key technical changes include:
- New `inflated_sizes` tracking in `object_stats`
- Integration with `humanise_bytes()` via new `HUMANISE_COMPACT` flag
- Updated test expectations to verify the new size reporting
- Maintained backward compatibility with keyvalue/nul formats

The implementation follows the series' established pattern of methodical architectural evolution, building on the preparatory refactoring from earlier patches. Test coverage remains comprehensive, verifying both empty and populated repository scenarios. The changes are localized to the table output formatting while preserving the existing machine-readable formats.

This continues the series' progression toward complete object metric reporting, now covering both raw counts and inflated sizes in human-readable form. The patch appears well-integrated with the existing codebase and maintains the series' high standard of test coverage.
