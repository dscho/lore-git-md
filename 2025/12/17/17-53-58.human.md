Refactoring patch that lays groundwork for object size reporting in `git repo structure`. This is the first of seven patches in a series that has already gone through several rounds of review and is now in its final polishing phase (v5).

The patch introduces a new `object_values` struct to group the per-type counts (tags, commits, trees, blobs) that were previously direct fields in `object_stats`. This structural change enables the subsequent patches to add new per-type measurements (inflated and disk sizes) in a clean way. The commit includes all the mechanical updates needed to use the new nested structure throughout the codebase, including renaming `get_total_object_count()` to `get_total_object_values()` to better reflect its new role.

This is a well-contained preparatory change that follows good refactoring practice - it doesn't introduce new functionality but makes the codebase ready for the size reporting features that follow in the series. The patch has already been reviewed and refined through multiple iterations, with the thread summary indicating the series as a whole is now ready for merging.
