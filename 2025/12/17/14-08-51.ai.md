Platform compatibility patch implementing file symlink creation on Windows, part of the ongoing symlink support series (14/18). This patch replaces the stub `symlink()` function in the MinGW compatibility layer with a working implementation that creates file symlinks (not directory symlinks yet) using Windows' `CreateSymbolicLinkW()` API.

The implementation handles path conversion between UTF-8 and Windows' WCHAR format, normalizes path separators, and respects the `core.symlinks=false` configuration by returning ENOSYS when symlinks are disabled. Error cases are properly mapped from Windows error codes to POSIX equivalents. The patch follows the series' pattern of direct Win32 API usage rather than relying on CRT functions.

This builds on the previous patches in the series that established symlink detection and handling infrastructure. The implementation is limited to file symlinks for now, with directory symlinks promised in a follow-up patch. The code maintains consistency with the series' approach to UTF-8/WCHAR conversion and error handling while completing another key POSIX API that was previously unimplemented on Windows.
