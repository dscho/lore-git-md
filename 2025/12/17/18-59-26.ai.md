This is a feature patch introducing PID file support for Git lockfiles to aid in debugging stale locks. The patch creates companion `.pid.lock` files alongside lockfiles (e.g. `index.pid.lock` next to `index.lock`) containing the PID of the process holding the lock. 

Key aspects:
- Controlled via new `core.lockfilePid` config with component-level granularity (index, config, refs etc.)
- Uses key-value format (`pid <value>`) for extensibility
- Automatically cleaned up with lockfiles via tempfile mechanism
- Provides enhanced error messages showing holding process status (running/stale)
- Always reads existing PID files for diagnostics even when disabled
- Includes comprehensive test coverage and Windows compatibility fixes

The implementation follows the `core.fsync` pattern for component configuration. This is v2 of the patch, addressing feedback by:
- Changing file format from `.lock.pid` to `.pid.lock` to avoid ref validation issues
- Switching from environment variable to config-based control
- Adding per-component configuration
- Improving Windows PID handling
- Adding more test cases

The patch touches multiple lockfile call sites across Git to add component specifications. It represents a significant debugging aid for lock contention issues while maintaining backward compatibility.
