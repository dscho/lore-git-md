Performance optimization in the Windows symlink support series. This first patch in an 18-part series eliminates a redundant `GetFileAttributes()` call in the Windows stat/lstat implementation when handling trailing slashes. The change leverages existing wide character conversion to modify paths in-place rather than making a second system call after path adjustment. 

The patch simplifies the code significantly by removing the `do_stat_internal()` wrapper function entirely, folding its trailing slash handling directly into `do_lstat()`. This appears to be a straightforward optimization building on prior work - the commit notes this becomes possible after the conversion to wide Unicode handling. 

As the opening patch in a major platform compatibility effort, this change sets the stage for more substantial symlink handling improvements to follow. The clean diff and focused scope suggest this is a well-considered optimization, though small, helps streamline the codebase for the larger changes coming in subsequent patches. The dual sign-off from both Karsten Blees and Johannes Schindelin indicates this has already gotten review from key Windows compatibility maintainers.
