This is a refactoring patch in Justin Tobler's series adding object size metrics to `git repo structure`. It splits the byte-formatting logic from `strbuf_humanise()` into a new `humanise_bytes()` function that returns the numeric value and unit string separately, enabling better column alignment in the upcoming table output.

The patch introduces a new `humanise_bytes()` function in strbuf.[ch] that decomposes the formatting into two parts: a numeric value string (like "12.34") and a unit string (like "MiB"). This separation allows callers to handle alignment independently. The existing `strbuf_humanise()` is refactored to use this new function while maintaining identical output behavior.

Key technical changes:
- New `humanise_bytes()` function with `value` and `unit` out parameters
- New `HUMANISE_RATE` flag in `enum humanise_flags` to distinguish between bytes and bytes/second units
- Updated translation strings with proper plural forms
- Special handling in test-simple-ipc.c to avoid translation conflicts
- Maintains all existing behavior through the refactoring

The change is part of preparing the codebase for displaying object sizes in aligned columns in the `git repo structure` output. The patch demonstrates careful attention to translation concerns and backward compatibility while introducing the new infrastructure.
