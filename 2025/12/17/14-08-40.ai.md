Refactoring patch in the Windows symlink support series, simplifying the lstat implementation.

This third patch in the 18-part series continues the Windows symlink work by cleaning up redundant `do_lstat()` function. The previous patch's new `mingw_stat()` implementation made `do_lstat()` only ever called from `mingw_lstat()` with `follow=0`, so the patch removes the now-unused `follow=1` path and inlines the remaining logic directly into `mingw_lstat()`. The change eliminates 20 lines while maintaining the same behavior for symlink detection and attribute reporting.

Key technical details: The patch removes the conditional symlink target reading code (the `follow` branch) that was previously used by the old `mingw_stat()` implementation, since the new implementation handles symlink following differently. It keeps the core symlink identification logic (`IO_REPARSE_TAG_SYMLINK` check) and permission bit setting. The change touches only `compat/mingw.c`, specifically the symlink handling path within the stat implementation.

This appears to be a straightforward cleanup following the architectural changes in patch 2, with no functional changes. The dual sign-off from Karsten Blees and Johannes Schindelin suggests this builds on their prior collaborative work on Windows symlink support in Git for Windows. The patch follows the series' pattern of incrementally improving the Windows POSIX emulation layer while simplifying the codebase.
