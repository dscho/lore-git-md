Platform compatibility patch (final in series) addressing a Windows symlink index corruption edge case. This is the 18th and concluding patch in a long-running effort to properly support symbolic links on Windows, building on Git for Windows' implementation.

The patch fixes a specific interaction where symlinks that were previously recorded with incorrect size information (4096 bytes, due to a now-fixed bug) would show up as modified in `git status` but not in `git diff`. Rather than forcing users to manually `git add` these files, the patch detects these "known bad" sizes and triggers a re-check of the symlink as if it were freshly checked out. The solution is narrowly scoped to Windows (`GIT_WINDOWS_NATIVE`) and only affects symlinks with exactly MAX_PATH (4096) size in the index.

This appears to be a thoughtful conclusion to the symlink work, addressing a real-world migration issue for users upgrading from affected Git for Windows versions. The patch maintains the series' careful attention to backward compatibility while cleanly solving the specific pain point. With this, the comprehensive Windows symlink support series appears complete.
