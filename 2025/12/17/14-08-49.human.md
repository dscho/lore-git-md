Platform compatibility patch (12/18 in series) improving Windows symlink support by making `chdir()` properly resolve symlinks when enabled. This brings Windows behavior in line with POSIX requirements, which is important because Git's `real_path()` function relies on this property of `chdir()`.

The patch modifies `mingw_chdir()` to use Windows API calls (`CreateFileW` and `GetFinalPathNameByHandleW`) to resolve symlinks when `has_symlinks` is true, falling back to the simple path change if symlinks are disabled. The implementation handles error cases by translating Windows error codes to POSIX equivalents.

A notable limitation is that Windows' current directory is still subject to the MAX_PATH (260 character) limit, which may cause issues when combining symlinks with long paths. The commit message clearly calls out this known constraint.

This continues the series' pattern of replacing CRT functions with direct Win32 API calls for better symlink handling. The patch has sign-offs from both Karsten Blees and Johannes Schindelin, indicating it builds on their prior Git for Windows work. As with other patches in this series, the change is focused and well-explained, though real-world testing may be needed to verify edge cases with complex symlink structures.
