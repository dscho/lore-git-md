This is a documentation patch finalizing Git's policy on sign-off automation, specifically addressing a minor editorial suggestion in the FAQ text. 

The email shows maintainer Junio C Hamano accepting Johannes Sixt's suggestion to simplify the phrasing in the documentation about why Git won't add more automatic sign-off options beyond the existing `format.signoff`. The original text used "pile on more mistakes" while the suggestion proposes "pile more mistakes" for better clarity. Junio agrees with the change, noting that "add more mistakes" would be even clearer for all readers.

This represents the final tweak to documentation that has already been through extensive review regarding Git's sign-off policy. The core technical/legal decisions about sign-off automation were settled earlier in the thread, with this being purely about polishing the wording. The FAQ text being modified is one of two locations (along with signoff-option.adoc) that document Git's position that automatic sign-offs beyond `format.signoff` violate the intentionality requirement of the Developer Certificate of Origin.

Key technical context for future reference:

- Final phrasing will use "add more mistakes" rather than "pile on"
