This is the final version (v5) of Justin Tobler's series adding object size reporting to `git repo structure`. The feature is now complete with all technical requirements addressed, including comprehensive metrics (counts, inflated sizes, disk sizes) across all output formats (table, keyvalue, nul) and robust test coverage.

The series has evolved through five versions with:
- Core infrastructure for tracking per-type object metrics
- Human-friendly formatting for table output (with SI prefixes)
- Careful handling of i18n concerns (unit strings vs prefixes)
- Special handling for tag size display quirks
- Support for partial clones by skipping unmeasurable objects

The v5 changes are minor polish: comment/log message improvements and spacing adjustments in `count_objects()`. The series has received positive reviews from Patrick Steinhardt and Junio Hamano, with the latter providing key documentation clarifications about unit string display in i18n contexts.

This appears ready for merging, providing users with valuable repository size insights while maintaining clean separation between data collection and presentation. The implementation is thorough, addressing edge cases and maintaining backward compatibility.
