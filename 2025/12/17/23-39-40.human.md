Junio Hamano's review of a Windows symlink support patch. This is part of a 5-patch series preparing Git for better Windows symlink handling, with this specific patch (4/5) removing PATH_MAX limitations in `strbuf_readlink()` to support longer symlink targets.

The patch removes an artificial 2*PATH_MAX limit on symlink target sizes, particularly important for Windows which supports longer paths. Junio notes this is a welcome change given past issues with platforms setting PATH_MAX too low. He briefly considered but dismissed concerns about infinite loops on broken platforms, since the code only retries on ERANGE errors.

The change is straightforward - removing a constant and replacing a while-loop with an infinite for-loop that grows the buffer as needed. Both Karsten Blees and Johannes Schindelin (Git for Windows maintainer) have signed off, indicating Windows-specific relevance. This appears to be a well-justified, low-risk change that completes the series' work on core symlink handling improvements.
