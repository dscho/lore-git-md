Platform compatibility patch in the Windows symlink support series (10/18). This patch specifically addresses directory symlink deletion behavior in the MinGW compatibility layer.

The change modifies `mingw_unlink()` to properly handle symlinks pointing to directories on Windows. The core issue is that Windows' `_wunlink()` and `DeleteFileW()` APIs fail with ERROR_ACCESS_DENIED when attempting to delete directory symlinks. The patch adds a fallback to `_wrmdir()` when this error occurs, which can successfully remove the symlink while maintaining the same error behavior for genuine access denial cases.

Key technical details:
- Modifies the retry loop in `compat/mingw.c` to attempt `_wrmdir()` when ERROR_ACCESS_DENIED is encountered
- Preserves existing in-use file handling logic by checking `is_file_in_use_error()` first
- Maintains the same retry behavior for actual access errors via the `handle_in_use_error` parameter
- Builds on the retry infrastructure introduced in patch 7/18 (`retry_ask_yes_no()`)

This continues the series' pattern of carefully handling Windows filesystem quirks while maintaining POSIX-compatible behavior. The change is narrowly focused on directory symlink deletion, suggesting it's part of the incremental approach to comprehensive symlink support.
