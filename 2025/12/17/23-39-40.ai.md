This is a performance and platform compatibility patch in the Windows symlink support series. It removes the PATH_MAX limitation in `strbuf_readlink()`, allowing Git to handle longer symlink targets on platforms like Windows that support them. The change follows the pattern previously established in `strbuf_getcwd()` and addresses known issues with artificially low PATH_MAX values on some systems.

The patch simplifies the link reading logic by eliminating the STRBUF_MAXLINK constant and its associated size doubling loop, replacing it with an unbounded growth approach that relies on the existing ERANGE retry mechanism. Junio Hamano notes this is safe since the loop only continues on ERANGE errors, not other failures, preventing infinite loops on broken platforms.

This change directly supports the series' goal of robust symlink handling across platforms, particularly important for Windows compatibility. While earlier in the thread Patrick Steinhardt raised concerns about potential undefined behavior with unbounded growth, this patch appears to have consensus with sign-offs from both Karsten Blees and Johannes Schindelin (Git for Windows maintainer), suggesting the approach is considered sound for the target platforms.

The modification is minimal (4 lines changed) and focused, removing a limitation rather than introducing new complexity. Junio's review confirms the change aligns with Git's historical approach to PATH_MAX issues and maintains safe error handling. This appears to be the final piece in the technical discussion around this patch before the series can proceed.
