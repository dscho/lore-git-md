This is part 3/10 in a series preparing Git's test suite for Windows symlink support, specifically addressing a POSIX-compliance issue in `mingw_open()`. The patch fixes how Windows handles `O_CREAT|O_EXCL` flags when opening symbolic links - currently Windows will create the target file even if the symlink exists, while POSIX requires an `EEXIST` error in this case. The change makes Git's behavior match POSIX expectations, allowing test t4115.8 ("--reject removes .rej symlink") to pass correctly when MSYS2 enables symlink support by default.

The implementation adds a check for existing symlinks before attempting to create files, returning `EEXIST` when appropriate. This is a focused, well-explained change that clearly addresses a specific compatibility gap between Windows and POSIX behavior. As part of an already-accepted series, it demonstrates careful attention to cross-platform behavior in the test suite.
