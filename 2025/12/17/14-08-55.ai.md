Platform compatibility patch (final in series) addressing a Windows-specific index corruption edge case with symbolic links. This is the 18th and concluding patch in the symlink support series for Windows, building on the comprehensive POSIX-like symlink implementation work.

The patch fixes a subtle interaction between the index and symlink handling where Git for Windows v2.27.0 incorrectly recorded symlink target sizes as 4096 (MAX_PATH) instead of their actual lengths. While this was fixed in later versions, it left users with tracked symlinks seeing false "modified" status in `git status` (though not in `git diff`). The solution detects these bad size recordings (specifically MAX_PATH values) and forces re-checking of affected symlinks, avoiding the need for manual `git add` to resolve the discrepancy.

The change is narrowly scoped to `read-cache.c`, adding a Windows-specific condition in `ie_modified()` that excludes symlinks with MAX_PATH sizes from the DATA_CHANGED check. The implementation maintains the existing behavior for all other file types and correctly handles the rare case where a symlink might legitimately have a MAX_PATH-sized target. The patch includes clear documentation of both the bug and solution rationale in the code comments.

This completes the symlink series by addressing a real-world migration issue stemming from the earlier bug fix, demonstrating attention to practical upgrade paths. The solution is minimally invasive while solving the specific problem, and the patch follows the series' pattern of careful Windows-POSIX compatibility work. With this addition, the symlink support appears functionally complete, though future testing may reveal additional edge cases.
