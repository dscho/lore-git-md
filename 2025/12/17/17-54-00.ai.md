This is part 3 of Justin Tobler's series adding object size metrics to `git repo structure`, focusing on human-readable formatting of large counts. The patch introduces a new `humanise_count()` function in strbuf.c that converts large numbers into scaled values with SI unit prefixes (k, M, G) for better readability. The table output format now displays counts like "3.02 k" instead of raw numbers when values exceed certain thresholds.

Key technical changes:
- Adds `humanise_count()` utility function with rounding logic and i18n support
- Introduces separate `unit` field in `stats_table_entry` struct
- Updates table formatting to properly align values and units
- Modifies tests to expect the new humanized output
- Preserves exact numeric output for keyvalue and nul formats

The implementation follows the series' pattern of careful architectural evolution, building on the previously established `object_values` infrastructure. The patch maintains backward compatibility while improving user experience for repositories with large object counts. Test coverage is thorough, including both empty and populated repository cases.

This change is a preparatory step toward the series' goal of adding comprehensive size metrics, with the human-readable formatting being particularly important for the default table output format. The separation of numeric values from their units enables better column alignment while preserving the i18n work done in earlier iterations.
