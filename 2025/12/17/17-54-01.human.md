This is part 4/7 in Justin Tobler's series adding object size reporting to `git repo structure`. The patch focuses on adding inflated object size metrics to the keyvalue and nul output formats.

The change extends the existing object statistics reporting to track and display the inflated size of objects by type (commits, trees, blobs, tags). The implementation adds a new `inflated_sizes` field to the `object_stats` struct and updates the counting logic to accumulate sizes during object traversal. The keyvalue format now includes new fields like `objects.commits.inflated_size` alongside the existing count metrics.

The patch maintains the series' careful approach - it's well-structured with clear additions to both the core counting logic and output formatting. Test coverage is updated to verify the new size fields, though the test is currently SHA1-specific (marked with the SHA1 prereq). This appears to be a straightforward extension of the existing functionality, building on the foundation established in earlier patches.

The commit message could be slightly more detailed about why inflated sizes (rather than packed sizes) are being reported, but the technical implementation looks solid. This continues the series' pattern of methodical, incremental improvements to the repository structure reporting feature.
