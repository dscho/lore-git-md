This is a feature patch adding PID file support for debugging stale locks in Git. The patch introduces a new `core.lockfilePid` config option that creates companion PID files alongside lock files to help identify processes holding locks.

The key aspects are:

1. For each lock file (e.g. `index.lock`), a PID file (e.g. `index.pid.lock`) is created containing the process ID of the lock holder.

2. When lock conflicts occur, Git checks if the PID from the PID file is still running and provides more informative error messages indicating whether the lock is held by a live process or is stale.

3. The feature is configurable per component (index, config, refs, etc.) via `core.lockfilePid` with syntax similar to `core.fsync`. It's disabled by default.

4. The implementation handles cleanup via tempfile mechanisms and works across platforms including Windows.

5. Comprehensive tests verify the behavior including stale lock detection, running process detection, config options, and cleanup.

The patch appears well-constructed with thorough documentation, cross-platform support, and extensive test coverage. It addresses a real debugging pain point while being opt-in to avoid overhead for normal operations. The implementation follows Git's existing lockfile patterns and adds the new functionality in a maintainable way.
