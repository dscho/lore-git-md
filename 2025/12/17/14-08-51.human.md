Windows platform compatibility patch implementing basic `symlink()` functionality for file symlinks, part of a larger series bringing comprehensive symlink support to Windows (now patch 14/18). This builds on the team's previous work implementing other POSIX symlink operations in the MinGW layer.

The patch removes the stub `symlink()` implementation and provides a real one that creates file symlinks (not directory symlinks yet) using Windows' `CreateSymbolicLinkW()`. It handles path conversion between UTF-8 and Windows' wide characters, normalizes path separators, and respects the `core.symlinks` configuration by failing with `ENOSYS` when symlinks are disabled. Error cases convert Windows error codes to POSIX equivalents.

This is a focused, well-contained addition to the symlink series, following the established pattern of using direct Win32 API calls rather than CRT functions. The implementation looks solid, with proper error handling and the same attention to UTF-8/WCHAR conversions seen in earlier patches. Directory symlink support is explicitly noted as coming in a follow-up patch.
