This is a bugfix response in the submodule gitdir path encoding series, specifically addressing patch 4/10's implementation of the `extensions.submodulePathConfig` feature. Adrian Ratiu acknowledges Josh Steadmon's report that the automatic configuration creation during `--recurse-submodules` clone operations is not working as intended - the required `submodule.<name>.gitdir` config entries are missing despite the extension being enabled, yet no error is raised.

Adrian confirms this stems from a misunderstanding of how global configuration should work, which Patrick Steinhardt had previously identified. He commits to fixing this in v7 of the patch series by ensuring proper error throwing when configs are missing, and adding comprehensive test coverage for four clone scenarios (with/without `--recurse-submodules` and with extension enabled/disabled globally).

The response indicates this is part of the broader effort to make submodule gitdir paths config-driven through the new extension, where the `submodule.<name>.gitdir` config must be the single source of truth when the extension is active. The bug affects core functionality by allowing repositories to enter an inconsistent state where the extension is enabled but required configs are missing. Adrian's planned fixes will address both the immediate issue and add missing test coverage to prevent regression.
