Platform compatibility patch (17/18 in Windows symlink series) focusing on `stat()` emulation edge cases. This patch addresses a specific scenario where `stat()` fails on Windows due to permission issues when checking existing directories, diverging from POSIX expectations.

The change modifies `mingw_stat()` to fall back to `mingw_lstat()` when encountering `ERROR_ACCESS_DENIED`, but only for non-symlink cases. This maintains POSIX semantics where `stat()` should still provide information even when file handle creation fails due to permissions, while correctly failing for symlinks which would need handle resolution. The fix specifically targets `safe_create_leading_directories()` scenarios where existing directories might be unreadable.

Key technical details include:
- New fallback path in `mingw_stat()` when `CreateFile()` fails with `ERROR_ACCESS_DENIED`
- Careful symlink exclusion via `S_ISLNK(buf->st_mode)` check
- Maintains existing error code translation via `err_win_to_posix()`
- Preserves all other error conditions unchanged
- Fixes Git for Windows issue #2531

This builds on previous symlink infrastructure in the series, particularly the `mingw_lstat()` implementation from earlier patches. The change is narrowly scoped to permission-denied cases while maintaining all other existing behavior, including proper symlink handling. The patch demonstrates careful attention to both POSIX compliance and Windows-specific constraints.
