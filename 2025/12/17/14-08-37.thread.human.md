This thread has finalized comprehensive Windows symlink support in Git, culminating in a 22-patch series (v5) that's now ready for integration. The work builds on years of Git for Windows development, with contributions from Bill Zissimopoulos, Johannes Schindelin (Dscho), Karsten Blees, Johannes Sixt, and Ben Knoble. The series implements POSIX-like symlink operations in Git's MinGW compatibility layer, handling creation, reading, stat'ing, and edge cases like directory handling and index corruption.

The latest addition is a mechanical but important patch that translates Windows-specific symlink error codes to POSIX equivalents, ensuring consistent error handling across platforms. This foundational piece maps reparse point failures to standard EINVAL errors that Git can process uniformly. Both Karsten Blees and Dscho have signed off on this patch, confirming it's been thoroughly reviewed by Windows platform experts.

The series now includes all planned refinements: performance optimizations eliminating redundant system calls, architectural cleanup removing obsolete helper functions, robust error handling, dirent symlink detection refactoring, correct size calculation, retry logic consolidation, and Windows-default symlink behavior adjustment for security compliance. Maintainer Junio Hamano has approved the complete series for integration, marking the conclusion of this long-running effort to bring comprehensive symlink support to Windows.
