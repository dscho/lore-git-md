This thread represents the culmination of a decade-long effort to bring comprehensive symbolic link support to Git on Windows, now reaching completion with the 18-patch v5 series. The work, primarily authored by Karsten Blees with contributions from Johannes Schindelin (Dscho) and Johannes Sixt (Hannes), builds on Git for Windows' symlink implementation that has been maturing since 2015.

The series implements POSIX-like symlink operations in the MinGW compatibility layer, covering creation, reading, stat'ing, directory handling, and renaming - including fixes for edge cases like index corruption. The latest patch addressed a specific issue where symlink target sizes were incorrectly recorded as MAX_PATH (4096), which could cause false "modified" status reports. The implementation maintains Windows compatibility while providing proper `stat()`/`lstat()` behavior and includes configuration via `core.symlinks=false` on Windows.

Johannes Sixt recently reviewed patch 11/18, which improves symlink renaming behavior by using `MoveFileEx()` with `MOVEFILE_COPY_ALLOWED` instead of the problematic `_wrename()`. While expressing some concerns about code complexity, Sixt acknowledged the implementation's proven track record from its long testing history in Git for Windows. The series has now been maintainer-approved by Junio Hamano for integration, marking a significant milestone in Windows-POSIX compatibility for Git.
