This thread covers a major effort to bring comprehensive symbolic link support to Git, specifically addressing Windows compatibility issues. The 18-patch series, now in its fifth iteration, builds on years of development work in Git for Windows to implement POSIX-like symlink operations in the MinGW layer. Key contributors include Karsten Blees (primary author) and Johannes Schindelin (Dscho), with all patches carrying Dscho's sign-off.

The series methodically implements all aspects of symlink handling: creation (including non-elevated operations), reading, stat'ing, directory handling, renaming, and error reporting. The latest patches address edge cases - first fixing stat() emulation when encountering permission-denied directories, and now resolving a subtle index corruption issue from Git for Windows v2.27.0 where symlink target sizes were incorrectly recorded as MAX_PATH (4096). This final patch ensures affected symlinks are properly re-checked rather than showing false modifications in git status.

While the core functionality appears complete, some edge cases around target type changes and cross-process operations may need future attention. The series represents a significant step forward in Windows-POSIX compatibility, with careful attention to both technical implementation and practical upgrade paths for users. All patches remain in the author's tree and haven't yet been picked up by the maintainer.
