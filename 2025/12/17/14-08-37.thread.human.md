This thread documents the completion of a major effort to implement comprehensive Windows symlink support in Git, culminating in a 29-patch series (v5) that has now received final approval. The work builds on Git for Windows' symlink implementation that has been maturing since 2015, with contributions from Bill Zissimopoulos, Johannes Schindelin (Dscho), Karsten Blees, Johannes Sixt, and Ben Knoble.

The series implements POSIX-like symlink operations in Git's MinGW compatibility layer, covering all aspects of symlink handling including creation, reading, stat'ing, directory operations, and error handling. The most recent additions refined the implementation with performance optimizations, architectural cleanup, and now a fix for a Windows-specific edge case where symbolic links' target path sizes were incorrectly recorded as 4096 (MAX_PATH) in Git for Windows v2.27.0. This final patch modifies `read-cache.c` to detect and handle this corruption pattern, ensuring consistent behavior between `git status` and `git diff` for affected symlinks.

All technical issues have been resolved, with sign-offs from key Windows experts Dscho and Karsten Blees, and maintainer approval from Junio Hamano. The series is now complete and ready for integration, marking a significant milestone in Git's Windows compatibility that has been years in the making.
