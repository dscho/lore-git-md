This thread marks the completion of a major effort to bring comprehensive symbolic link support to Git on Windows, culminating in an 18-patch series (v5) that has now received maintainer approval. The work, primarily by Karsten Blees with contributions from Johannes Schindelin (Dscho) and Bill Zissimopoulos, builds on Git for Windows' long-running symlink implementation and addresses everything from basic operations to edge cases like index corruption.

The series implements POSIX-like symlink behavior in Git's MinGW compatibility layer, covering creation, reading, stat'ing, directory handling, and renaming - including support for non-elevated symlink creation on modern Windows. The final patch fixes an index corruption edge case from Git for Windows v2.27.0 where symlink target sizes were incorrectly recorded. Junio Hamano has reviewed the non-Windows-specific portions of the changes and found them sound, praising the implementation quality. The extensive changes touch 19 files, with the bulk in `compat/mingw.c` and include test updates across multiple scripts.

With the maintainer's approval, this decade-long effort to achieve full symlink support on Windows is now ready for integration, representing a significant step forward in Windows-POSIX compatibility for Git. The series will likely land in a future Git release, providing Windows users with robust symlink functionality that matches the behavior on Unix-like systems.
