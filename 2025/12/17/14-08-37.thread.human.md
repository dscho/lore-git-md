This thread introduces a major effort to bring comprehensive symbolic link support to Windows, building on nearly a decade of development in Git for Windows. The 18-patch series from Karsten Blees, with contributions from Bill Zissimopoulos and Johannes Schindelin (Dscho), aims to upstream POSIX-like symlink operations including creation, reading, and directory handling through the MinGW compatibility layer.

The first patch in the series, now under discussion, optimizes the Windows stat/lstat implementation by eliminating a redundant system call when handling paths with trailing slashes. The change modifies the path buffer during UTF-8 to wide character conversion, avoiding an initial doomed `GetFileAttributes()` attempt. Both Karsten and Dscho have signed off on this optimization, which reduces code size while maintaining behavior. The series as a whole represents a significant step forward in Windows-POSIX compatibility for core Git operations, though the default `core.symlinks=false` setting suggests the feature may need further real-world validation before being enabled by default.
