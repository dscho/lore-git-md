This thread introduces a major series of 18 patches to improve symbolic link support on Windows, building on nearly a decade of development in Git for Windows. The initial five patches, submitted by Karsten Blees with contributions from Johannes Schindelin (Dscho) and Bill Zissimopoulos, refactor symlink handling in the MinGW compatibility layer to provide more POSIX-like behavior. The changes touch core filesystem operations like `stat()`, `lstat()`, and directory handling, while defaulting to `core.symlinks=false` on Windows for safety.

The newly arrived patch (6/18) addresses a specific interoperability issue where symlink sizes were incorrectly reported as MAX_PATH, causing unnecessary index updates when repositories were accessed across different Windows Git variants (Cygwin, WSL). It introduces proper size reporting through a new `read_reparse_point()` function that accurately extracts target lengths from Windows reparse point data. This fixes a long-standing pain point while maintaining POSIX compatibility.

The series represents a significant step forward in Windows-POSIX compatibility for Git, with each patch carefully refining the implementation. All submitted patches so far carry signed-off-by lines from both Karsten Blees and Johannes Schindelin, indicating they incorporate mature Git for Windows work.
