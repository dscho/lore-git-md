This thread continues the long-running effort to upstream comprehensive symbolic link support for Windows, building on Git for Windows' existing implementation. The series, now at v3 with 18 patches, is primarily authored by Karsten Blees with contributions from Johannes Schindelin (Dscho) and Bill Zissimopoulos. It aims to implement POSIX-like symlink operations in Git's MinGW compatibility layer, covering creation, reading, stat'ing, and now renaming operations.

The latest patch (16/18) adds an important usability improvement: support for non-elevated symlink creation on modern Windows versions (10 and later) when Developer Mode is enabled. This eliminates the need for administrator privileges in common development scenarios by leveraging Windows 10's `SYMBOLIC_LINK_FLAG_ALLOW_UNPRIVILEGED_CREATE` flag. The implementation carefully checks the Windows build number and gracefully falls back for older versions. This builds on the series' existing infrastructure while adding new flag handling for both file and directory symlinks.

The series now has only two patches remaining to complete the comprehensive symlink support. Previous patches have established core functionality including file and directory symlink creation, symlink detection, error handling, rename behavior, and `readlink()` support. The work demonstrates careful attention to Windows version compatibility and edge cases while methodically implementing previously stubbed POSIX APIs. While there are still some minor loose ends around edge cases and test coverage across Windows versions, the series appears to be approaching completion with its established approach and consistent contributor engagement.
