This thread covers a major effort to bring comprehensive symbolic link support to Git on Windows, building on nearly a decade of development in Git for Windows. The 18-part patchset, now at version 1, aims to implement POSIX-like symlink operations in Git's MinGW compatibility layer, addressing creation, reading, stat'ing, and directory handling.

Karsten Blees and Johannes Schindelin (Dscho) are leading the effort, with contributions from Bill Zissimopoulos. The series touches core Windows compatibility code in `compat/mingw*` and `dirent.c`, with each patch carefully refining the implementation. The latest addition (patch 11) improves symlink renaming behavior by replacing problematic CRT functions with direct Win32 API calls, building on earlier work to standardize error handling and retry logic.

Key technical achievements so far include proper symlink size reporting, refactored retry mechanisms, Windows-to-POSIX error code mapping, and directory symlink handling. The series defaults to `core.symlinks=false` on Windows for safety, requiring explicit opt-in via MSYS2 environment variables. While the patches show careful attention to edge cases and cross-toolchain compatibility, real-world testing will be needed before enabling by default. The work represents a significant step forward in Windows and POSIX interoperability for Git.
