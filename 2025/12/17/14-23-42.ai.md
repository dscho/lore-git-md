This is the final patch in a security-focused series addressing ANSI escape sequence injection (CVE-2024-32002, CVE-2024-52005). The patch expands the `sideband.allowControlCharacters` configuration to support granular control over cursor movement and character-erasure sequences, which were previously blocked by default due to their potential for abuse in attack scenarios.

The implementation introduces two new bitmask flags (`ALLOW_ANSI_CURSOR_MOVEMENTS` and `ALLOW_ANSI_ERASE`) alongside the existing color sequence handling. The configuration now accepts comma-separated values (e.g., `cursor,erase`) and maintains backward compatibility with the previous boolean/string values. The core sanitization logic in `handle_ansi_sequence()` is enhanced to validate specific cursor movement (CUU, CUD, etc.) and erase (ED, EL, etc.) sequences against the configured policy.

Test coverage demonstrates the default blocking behavior while verifying that explicitly allowed sequences pass through correctly. The test harness includes a CSI decoder to validate sequence handling, with assertions checking for both preservation of allowed sequences and blocking of others. Documentation updates clarify the new options and their security implications, noting that these additional sequences remain disabled by default due to their potential for abuse.

This completes the series' goal of providing controlled passthrough for legitimate ANSI sequence use cases (particularly in `pre-receive` hooks) while maintaining protection against malicious sequences. The implementation retains the layered defense approach from earlier patches, with the expanded configuration offering finer-grained control for users who need these specific sequence types.
