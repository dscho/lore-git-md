Platform compatibility patch implementing proper `stat()` behavior for symlinks on Windows, part of the larger symlink support series.

This second patch in the 18-part series focuses on making `mingw_stat()` correctly follow symlinks, unlike the current implementation which behaves nearly identically to `mingw_lstat()`. The new version properly resolves symlinks by opening the file handle with minimal permissions and using `GetFileInformationByHandle()`, letting Windows handle the symlink resolution. When symlinks are disabled via `core.symlinks=false`, it falls back to the existing `mingw_lstat()` behavior but now correctly fails with `ELOOP` when encountering symlinks that would need resolution.

The implementation uses Windows API calls (`CreateFileW` with `FILE_FLAG_BACKUP_SEMANTICS`) to get proper file information after symlink resolution, with appropriate error handling that converts Windows error codes to POSIX equivalents. The patch touches only `compat/mingw.c`, adding 18 lines while removing 1. It carries signed-off lines from both Karsten Blees and Johannes Schindelin, indicating it builds on prior Git for Windows work.

This change is a foundational piece for the larger symlink support effort, establishing proper POSIX-like stat() behavior that distinguishes between symlinks and their targets. The implementation appears carefully crafted to maintain compatibility with existing behavior when symlinks are disabled while adding proper resolution when they're enabled. The error handling and permission requests follow security-conscious patterns seen elsewhere in Git's Windows compatibility layer.
