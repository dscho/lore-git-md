This is patch 5/18 in the Windows symlink support series, focusing on directory entry handling for symlinks. The patch centralizes symlink detection logic by moving S_IFLNK mode bit setting into the shared `file_attr_to_st_mode()` function, and adds DT_LNK support in the Windows dirent implementation.

The key changes are:
1. Moves symlink mode detection from mingw.c's `mingw_lstat()` into `file_attr_to_st_mode()`, which now takes an additional reparse tag parameter
2. Updates `file_attr_to_st_mode()` to handle symlinks first before directories/files
3. Adds DT_LNK detection in dirent.c's `finddata2dirent()` when processing directory entries
4. Simplifies `mingw_lstat()` by removing its inline symlink handling code
5. Maintains the same symlink permission bits logic (read-only flag handling)

This continues the series' pattern of consolidating symlink handling logic while maintaining POSIX compatibility. The changes touch core filesystem interaction points (`mingw.c`, `dirent.c`) and affect how Git interprets directory listings and file modes on Windows. The patch carries signed-off-by from both Karsten Blees and Johannes Schindelin, indicating it builds on prior Git for Windows work.
