This is part 10 of the ongoing Windows symlink support series, focusing on directory symlink deletion behavior. The patch addresses a Windows-specific quirk where `_wunlink()` fails with `ERROR_ACCESS_DENIED` when attempting to delete symlinks pointing to directories. The solution is straightforward: when this error occurs, the code now falls back to trying `_wrmdir()`, which can properly handle directory symlinks.

The change is small but important for consistent behavior - it ensures Git's unlink operation works uniformly regardless of whether a symlink points to a file or directory. The patch builds on the retry logic introduced earlier in the series (patch 7) while maintaining the same error handling patterns. As with other patches in this series, it carries sign-offs from both Karsten Blees and Johannes Schindelin, indicating it incorporates well-tested Git for Windows improvements.

This continues the series' pattern of methodically addressing Windows symlink edge cases while maintaining POSIX-compatible behavior. The implementation is clean and focused, with a clear commit message explaining both the Windows behavior and the solution.
