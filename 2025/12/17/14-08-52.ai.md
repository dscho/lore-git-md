This is patch 15/18 in the Windows symlink support series, focusing on directory symlinks - a key remaining piece of the platform compatibility effort. It builds on the file symlink implementation from patch 14, adding the ability to create and handle symlinks that point to directories on Windows.

The core challenge addressed is Windows' strict distinction between file and directory symlinks at the API level. The patch implements a sophisticated detection mechanism that:
1. Initially creates tentative file symlinks
2. Verifies the target type by attempting to open the symlink with backup semantics
3. Converts to a directory symlink if the target is a directory
4. Maintains a thread-safe list of "phantom" symlinks for cases where targets don't yet exist, processing them when new directories are created

Key technical components include:
- New `process_phantom_symlink()` function that handles the type detection and conversion
- Thread-safe `phantom_symlinks` list management with critical sections
- Integration with `mingw_mkdir()` to process pending symlinks when directories are created
- Path normalization and relative path handling utilities

The implementation acknowledges some edge case limitations (target type changes after creation, cross-process directory creation) but provides robust handling for Git's typical use cases. This completes another major piece of the Windows symlink puzzle, following the established pattern of direct Win32 API usage seen throughout the series.

With this patch, the series' core symlink operations are nearly complete - only directory symlink creation remains as outstanding work in the final three patches. The careful attention to thread safety and edge cases continues the series' high standard of Windows-POSIX compatibility work.
