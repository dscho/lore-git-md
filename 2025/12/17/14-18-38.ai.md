Bugfix targeting Windows symlink behavior in `git apply`. This is the second patch in a 10-part series preparing Git's test suite for Windows symlink support, particularly for MSYS2's planned default enablement of symlink support.

The patch fixes a regression introduced by commit 0482c32c334b ("apply: ignore working tree filemode") which inadvertently changed executable bit handling for symbolic links and directories when core.filemode is disabled. The fix narrows the special `!trust_executable_git` code path to apply only to regular files, restoring the previous behavior for symlinks and directories.

This change is specifically needed to make test t4115.5 ("symlink escape when creating new files") pass on Windows when symbolic link support is enabled in MSYS2. The patch modifies just one line in apply.c, changing the condition for when to use the stat-based mode versus the index mode for file permissions.

The change is part of a larger effort to make Git's test suite work correctly with Windows symlinks, with this particular fix addressing a subtle interaction between executable bit handling and symlink support. The patch maintains the series' focus on Windows-specific behavior while fixing a regression that affected multiple file types.
