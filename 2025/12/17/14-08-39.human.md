This is the second patch in a major platform compatibility series introducing symbolic link support for Windows. It specifically implements proper `stat()` behavior for symlinks in the MinGW compatibility layer.

The patch changes how Git on Windows handles `stat()` calls when encountering symlinks. Previously, `mingw_stat()` behaved almost identically to `lstat()`, returning information about the symlink itself rather than its target. The new implementation properly resolves symlinks by opening the file handle with minimal permissions and using Windows' native file system layer to follow the symlink chain. When symlinks are disabled via `core.symlinks=false`, it falls back to the old behavior but now correctly fails with `ELOOP` when symlink resolution would be required.

The implementation uses Windows API calls like `CreateFileW` with `FILE_FLAG_BACKUP_SEMANTICS` and `get_file_info_by_handle` to properly emulate POSIX behavior. This is a foundational change in the larger effort to bring comprehensive symlink support to Windows, building on years of development work in Git for Windows. The patch carries sign-offs from both Karsten Blees and Johannes Schindelin, indicating it incorporates well-vetted changes from the Git for Windows project.
