Simon Richter started a thread asking about better workflows for rebasing branches after automatic code reformatting (e.g., with clang-format). The core problem is that reformatting creates widespread whitespace changes that cause merge conflicts during rebases. His current solution involves using `git filter-branch` to normalize formatting history, but this is tedious and error-prone, especially across multiple branches.

Kristoffer Haugsbakk has now suggested an alternative approach using `git-test` from the git-branchless suite. This tool can apply formatters across entire commit stacks using a worktree strategy, potentially avoiding merge conflicts by transforming trees per snapshot rather than through three-way merges. While Kristoffer notes the tool seemed promising for this use case, he ultimately uninstalled it due to concerns about complexity (it creates many refs and hooks) and lack of clear understanding of its overall purpose. His suggestion comes with the caveat that he hasn't actually tried this specific solution himself.

The thread remains open for other suggestions or experiences with alternative tools that could streamline the reformatting/rebasing workflow, particularly for multi-branch scenarios. The core challenge of maintaining consistent formatting while rebasing against upstream changes remains unresolved, with git-filter-branch being the only proven (if cumbersome) solution so far.
