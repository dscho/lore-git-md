Platform compatibility patch adding Windows symlink rename support. This is patch 11/18 in the series introducing comprehensive symbolic link handling for Windows.

The patch addresses a limitation in older MSVCRT implementations where `_wrename()` fails silently when attempting to rename symlinks over existing files. The solution replaces this with a direct call to `MoveFileEx()` using both `MOVEFILE_REPLACE_EXISTING` and `MOVEFILE_COPY_ALLOWED` flags, which should work reliably across Windows versions. The change maintains proper error handling and attribute management while simplifying the code path.

This continues the series' pattern of replacing CRT functions with direct Win32 API calls for more reliable symlink operations. The implementation shows careful attention to edge cases, including proper attribute restoration on failure and integration with the existing retry mechanism. As with earlier patches in the series, this carries sign-offs from both Karsten Blees and Johannes Schindelin, indicating it builds on established Git for Windows work.

The change is narrowly focused on the rename operation while fitting into the larger goal of POSIX-compatible symlink support on Windows. It touches only `compat/mingw.c`, modifying the `mingw_rename()` function with a net reduction of 6 lines despite adding new functionality.
