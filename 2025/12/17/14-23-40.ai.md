Security feature introducing configurable control character handling in sideband messages. This is the second patch in Johannes Schindelin's v2 series addressing ANSI escape sequence vulnerabilities (CVE-2024-32002, CVE-2024-52005). It builds on the core sanitization from patch 1 by adding a `sideband.allowControlCharacters` configuration option that lets users bypass the new protections when needed.

The implementation adds a global `allow_control_characters` flag set via config, which when true makes `strbuf_add_sanitized()` skip its control character filtering. Documentation is added in a new `config/sideband.txt` explaining the security tradeoffs. The test suite is extended to verify both the default protected behavior and the opt-in bypass case, checking for color sequences in remote hook output.

Key technical details:
- Config option name: `sideband.allowControlCharacters` (note camelCase)
- Default behavior remains protected (false)
- When enabled, passes through all control characters unmodified
- Test verifies both default blocking and opt-in allowing of color sequences
- Follows Brian Carlson's suggestion for an escape hatch while maintaining secure defaults

This patch represents the policy/UX layer of the security solution, complementing the core sanitization mechanics from the first patch. It acknowledges legitimate uses like server-side coloring while keeping protections active by default. The test demonstrates the intended workflow where users who understand the risks can explicitly enable control sequences.
