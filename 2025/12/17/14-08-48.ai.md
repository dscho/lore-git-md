Platform compatibility patch (part of Windows symlink support series) addressing symlink renaming behavior. This is the 11th in an 18-part series introducing comprehensive symlink support for Windows.

The patch modifies `mingw_rename()` to properly handle symlink renaming by avoiding the problematic `_CRT` `_wrename()` function, which fails silently when attempting to rename symlinks over existing files. Instead, it directly calls `MoveFileEx()` with both `MOVEFILE_REPLACE_EXISTING` and `MOVEFILE_COPY_ALLOWED` flags, which provides more reliable behavior across different Windows CRT versions.

Key technical changes include:
- Removing the initial `_wrename()` attempt that was causing silent failures
- Adding proper error handling through `MoveFileEx()` with combined flags
- Restructuring the attribute handling logic to be more robust
- Reusing the existing retry mechanism from patch 7 via `retry_ask_yes_no()`
- Maintaining the same error translation infrastructure established in patch 9

The change affects only `compat/mingw.c`, simplifying the rename logic while making it more reliable for symlink operations. This builds on the series' pattern of replacing CRT functions with direct Win32 API calls for better control over symlink behavior. The patch carries signed-off-by from both Karsten Blees and Johannes Schindelin, indicating it incorporates prior Git for Windows work.
