This is patch 4/8 in Patrick Steinhardt's v3 series refactoring Git's object database alternates handling. The series is part of the broader ODB abstraction effort to support alternative object database backends.

The patch fixes a subtle behavioral mismatch in `odb_add_to_alternates_file()`. Currently, when adding an alternate, it uses `link_alt_odb_entries()` which processes newline-separated paths, even though all callers only ever pass single directories. The patch changes this to directly call `odb_add_alternate_recursively()` instead, which better matches the actual usage pattern.

The change is small (just one line modified) but meaningful - it removes an undocumented and unused capability while making the same-path behavior explicit. This continues the series' theme of cleaning up alternates handling by making the code match its actual use cases more precisely. The patch maintains all existing functionality while removing a potential source of confusion.

This appears to be a straightforward improvement that follows naturally from the architectural changes in earlier patches. The series as a whole is making steady progress toward its goal of abstracting alternates handling to support non-filesystem ODB backends.
