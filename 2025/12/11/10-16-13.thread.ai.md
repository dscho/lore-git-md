Junio C Hamano's thread proposes modernizing Git's flexible array member (FAM) syntax to require C99 standard `[]` notation, eliminating legacy pre-C99 workarounds. The discussion has evolved from whether to document this as a Git 3.0 breaking change (initial proposal) to Junio's current "weather balloon" approach - removing all compatibility layers to test real-world compiler support.

Technical changes remove 31 lines of platform-specific FAM workarounds from git-compat-util.h while adding 2 lines of unconditional C99 syntax. This enables future adoption of Linux kernel-style fortified memcpy features. The implementation is minimal (affecting FLEX_ARRAY macro usage) with zero behavioral impact on compliant compilers.

Process discussion centers on adoption strategy. Patrick Steinhardt questioned classifying this as a Git 3.0 breaking change, noting prior C99 adoptions didn't require such documentation. Junio's revised approach bypasses that debate by forcing immediate testing of full C99 compliance, treating any platform issues as revert-worthy rather than pre-documenting incompatibility. The technical direction (C99 syntax) remains uncontested, but the project now leans toward aggressive testing over gradual documentation. Open question remains whether any platforms will require legacy support reinstatement.
