This is the third version of Patrick Steinhardt's series refactoring Git's alternates handling as part of the ODB abstraction effort. The series restructures how alternate object directories are managed by introducing a source-based interface, which will enable future support for non-filesystem-based object database backends.

The v3 series addresses the build failure identified in v2 by SZEDER Gábor, where patch 4/8 referenced a non-existent `odb_add_source()` function. The key changes in this revision are:
1. Renaming the function to `odb_add_alternate_recursively()` throughout
2. Fixing commit messages that still referenced the old function name
3. Maintaining the same architectural approach while ensuring buildability

The series progresses through 8 patches that systematically restructure alternates handling:
1. Makes alternates parsing self-contained
2. Handles relative path resolution during parsing
3. Moves normalized path computation
4. Simplifies alternates file addition (the fixed patch)
5. Removes mutual recursion in parsing
6. Cleans up forward declarations
7. Implements source-based reading of alternates
8. Completes the transition with source-based writing

The changes are focused on the `odb.c` file with significant line count changes (158 insertions, 149 deletions) but maintain the same overall structure and goals as previous versions. The series remains part of the broader effort to abstract object database operations, with alternates handling being the final piece. Once this build issue is resolved, the technical approach appears sound and ready for review.
