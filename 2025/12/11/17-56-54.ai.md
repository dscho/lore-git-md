Bugfix for `git replay` segfault when using non-existent `--onto` target. This patch addresses the crash reported in the thread by moving a NULL check for the `onto` pointer before its first use in the code. The regression was introduced in commit 15cd4ef1f4 which added atomic ref updates as default behavior for `git replay`.

The fix is straightforward - it simply reorders the code to perform the NULL check before the pointer is dereferenced. The patch maintains the existing behavior of erroring out when attempting to replay down to a root commit (which remains unsupported), but now does so safely. The change touches only 6 lines in builtin/replay.c, swapping the position of the NULL check with some reflog message construction code that was previously dereferencing the pointer first.

The patch appears well-scoped and correctly addresses the immediate crash. It doesn't attempt to solve the larger issue of root commit replay support (noted by the FIXME comment), focusing instead on the safety fix. The change is minimal and clearly motivated by the reported segfault, with a proper attribution to the original reporter.
