Bugfix for a segmentation fault in `git replay` when using a non-existent target with `--onto`.

Kristoffer Haugsbakk reports a segmentation fault that occurs when running `git replay --onto` with a non-existent branch name. The fault was bisected to commit 15cd4ef1 ("replay: make atomic ref updates the default behavior") from November 2025, meaning this regression is present in both `master` and `next` branches.

The minimal reproduction case shows the fault occurs with any invalid target passed to `--onto`, while valid targets (even if they result in other errors) don't trigger the segfault. The bisect script helpfully includes the exact test case and shows the fault results in exit code 139 (SIGSEGV).

This appears to be a straightforward null pointer dereference that should be caught with proper error handling. The patch doesn't propose a fix yet - it's just reporting the bug with clear reproduction steps and bisect information. Given the clear impact (crash on invalid input) and straightforward reproduction, this seems likely to get quick attention from maintainers.
