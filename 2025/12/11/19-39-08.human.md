This is a technical clarification in the ongoing discussion about `git pull --rebase` behavior with multiple push URLs. Phillip Wood corrects his previous explanation of how fork-point calculation works - it actually looks for the most recent reflog entry that is an *ancestor* (not descendant) of the local branch. He points to the official documentation which includes a helpful diagram of this behavior.

The email doesn't introduce new solutions but serves to ensure all participants have an accurate understanding of the fork-point mechanism's current implementation. This precision matters because the thread is evaluating whether and how to modify this behavior to prevent data loss scenarios when repositories have different push and pull URLs. The reference to the documentation suggests any changes will need to maintain or clearly justify deviations from the current specified behavior.
