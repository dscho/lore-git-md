This is part of the ongoing ODB alternates refactoring series, specifically patch 4/8 in v3. The patch addresses a subtle behavioral mismatch in how alternates are added to the object database.

The change focuses on `odb_add_to_alternates_file()`, which currently uses `link_alt_odb_entries()` to handle multiple newline-separated alternates, despite all callers only ever passing single directories. This creates an undocumented and potentially problematic behavior where the function could process multiple entries when only one was intended. The patch simplifies this by directly calling `odb_add_alternate_recursively()` instead, which better matches the single-entry expectation.

The technical change is minimal (just 2 lines modified in `odb.c`), but it's an important cleanup that makes the code's behavior match its actual usage patterns. This continues the series' theme of making alternates handling more precise and better abstracted. The change maintains all existing functionality while removing an unnecessary layer of indirection that could cause confusion or bugs if the function were ever called with multiple entries.

This patch follows naturally from the previous ones in the series (particularly patch 3/8 which renamed and clarified the alternate addition functions) and helps set up for the later patches that will complete the transition to source-based alternates handling. The fix appears straightforward and well-justified, with no obvious downsides to the change.
