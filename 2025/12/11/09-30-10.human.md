Refactoring patch in the ODB alternates handling series (1/8). This is the first patch in Patrick Steinhardt's v3 series to restructure how Git handles object database alternates as part of the broader ODB abstraction effort. The patch focuses on making alternates parsing self-contained by separating it from the linking logic.

The key change moves alternates parsing into a new `parse_alternates()` function that processes the entire input at once into a string vector, rather than the previous incremental parsing approach. This eliminates the need to pass around parsing state and prepares for later patches that will address the mutual recursion between parsing and linking alternates. The patch is a refactoring with no intended behavior change - it just reorganizes the code to be more maintainable.

This appears to be a clean, focused change that does what it claims - the diff shows the parsing logic being cleanly extracted while maintaining all the same functionality (handling comments, quoted paths, etc). As the first step in an 8-part series, it lays groundwork for more substantial changes to come in subsequent patches. The v3 version has already addressed a build issue found in v2, so this iteration should be technically sound.
