This thread addresses a regression in `git replay` that caused a segfault when users specified a non-existent `--onto` target. The bug was introduced in November 2025's commit 15cd4ef1f4, which made atomic ref updates the default behavior. Kristoffer Haugsbakk originally reported the issue, providing a reproduction case and bisecting it to the problematic commit.

René Scharfe proposed a fix that moves a NULL check for the `onto` pointer before its first use in the code, preventing the segfault while maintaining the existing behavior for unsupported cases like root commit replay. The change is minimal (just 6 lines) and well-scoped to the immediate issue.

Phillip Wood, a core contributor familiar with this area of the code, has reviewed and approved the fix. He notes there's a separate preexisting issue where invalid and missing `--onto` arguments are treated identically, but agrees this is out of scope for the current fix. With both the original reporter's sign-off and Phillip's approval, the patch appears ready for integration in the next development cycle. The larger limitation around root commit replay remains as future work, as noted in the existing FIXME comment.
