This thread reports and fixes a segfault in the relatively new `git replay` command when given a non-existent `--onto` target. The regression was introduced in November 2025's commit 15cd4ef1 ("replay: make atomic ref updates the default behavior") and affects master and next branches. The original reporter provided a reliable reproduction case and bisected the issue.

A fix has now been proposed that addresses the crash by reordering code in builtin/replay.c to perform a NULL check before dereferencing the `onto` pointer. The patch is minimal (6 lines changed) and specifically targets the segfault while maintaining the existing behavior of erroring out for unsupported root commit replays. The larger question of root commit replay support (noted by a FIXME comment) remains open, but this change makes the immediate crash safe. The fix properly attributes the original reporter and appears ready for maintainer consideration.
