This is patch 5/8 in Patrick Steinhardt's v3 series refactoring Git's object database alternates handling as part of the ODB abstraction effort. The patch focuses on removing mutual recursion between alternates parsing and addition functions.

The key change restructures how alternates are processed to eliminate the circular dependency between `link_alt_odb_entries()` and `parse_alternates()`. Previously, these functions called each other recursively, making the control flow harder to follow. The new version makes `parse_alternates()` unaware of the recursive behavior, moving all recursion handling into `odb_add_alternate_recursively()`.

Technical changes include:
- Removing `link_alt_odb_entries()` entirely
- Modifying `read_info_alternates()` to output parsed alternates via a `strvec` rather than processing them directly
- Updating `odb_prepare_alternates()` to use the new non-recursive parsing approach
- Maintaining the same depth checking for alternates nesting (still capped at 5 levels)

The patch is a clean refactoring that doesn't change observable behavior but makes the code more maintainable. It prepares for future work where alternates parsing will move into object database sources. The changes are focused in `odb.c` (60 lines modified) and follow naturally from the function renaming done in patch 3/8.

This continues the series' pattern of separating concerns while preserving functionality, with the architectural goal of eventually supporting non-filesystem alternates. The change appears well-contained and builds on the previous patches' foundation.
