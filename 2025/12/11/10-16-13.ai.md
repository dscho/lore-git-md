This is a platform compatibility patch that removes support for pre-C99 flexible array member syntax in Git's codebase. The change is part of Git's ongoing effort to require more modern C language features.

The patch makes two key modifications:
1. Updates `BreakingChanges.adoc` to document that support for the `FLEX_ARRAY` macro (used for pre-C99 compilers) will be removed
2. Modifies `git-compat-util.h` to make C99 flexible array member syntax (`[]`) mandatory when `WITH_BREAKING_CHANGES` is defined, while keeping the legacy support for now

The commit explains the historical context - before C99 standardized the `[]` syntax for flexible array members, compilers used either GNU's `[0]` extension or the workaround of `[1]`. The change aligns with Git's trend of requiring more modern C features, though the legacy support remains available unless explicitly opting into breaking changes.

The patch is straightforward and well-motivated, coming from the project maintainer. It follows Git's typical pattern for deprecating legacy features by first documenting the change while maintaining backward compatibility through a build-time flag. The change primarily affects developers working on Git itself rather than end users.
