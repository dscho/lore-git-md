This is patch 3/8 in Patrick Steinhardt's v3 series refactoring Git's object database alternates handling as part of the ODB abstraction effort. The patch focuses on cleaning up the path normalization logic in alternates checking.

The key change moves the computation of the normalized object directory path from the caller (`odb_add_alternate_recursively()`) into the callee (renamed from `alt_odb_usable()` to `odb_is_source_usable()`). This eliminates redundant path normalization since the function already receives the object database and can compute the normalized path itself. The patch also updates the function name to better reflect modern terminology around ODB sources.

Technically, this:
- Introduces a `strbuf` for path normalization inside `odb_is_source_usable()`
- Changes return type from `int` to `bool`
- Removes the `normalized_objdir` parameter and its computation from callers
- Updates all call sites to use the new function name
- Maintains the same error checking and duplicate detection logic

The changes are mechanical but meaningful - they reduce redundancy in path handling and better encapsulate the normalization logic. This continues the series' pattern of separating concerns between parsing, path resolution, and ODB operations. The diff shows 15 insertions and 12 deletions in `odb.c`, with the main complexity being the moved path normalization logic.

This patch builds on the architectural changes from patches 1-2 while keeping the same overall approach. It doesn't introduce new functionality but cleans up the implementation in preparation for later patches that will complete the source-based alternates handling.
