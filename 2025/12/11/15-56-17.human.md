Bugfix discussion for `git pull --rebase` with multiple push URLs. Phillip Wood responds to Junio Hamano's suggestion about how to handle the fork-point calculation issue that can cause data loss when pushing and pulling from different servers.

The core problem remains that fork-point calculation examines reflog entries from pushes to different servers than the pull operation, leading to incorrect commit exclusion during rebase. Phillip notes that if they disable fork-point calculation when pushurl is set (as previously suggested), they'll also need to provide users a way to explicitly skip fork-point usage during pulls, since currently there's no such option.

This continues the technical discussion about solution approaches, now focusing on the user interface implications of potential fixes. The exchange suggests the team is weighing tradeoffs between automatic behavior changes (disabling fork-point) versus user education (via advise messages) versus giving users more control (adding a skip option). The thread has established technical consensus on the root cause but is now grappling with how to implement a fix that maintains flexibility while preventing data loss.
