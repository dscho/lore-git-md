This is a bugfix patch for the commit-graph writing logic in `builtin/gc.c`, part of Patrick Steinhardt's v2 series addressing odb-related issues. The patch fixes two distinct but related problems in the commit-graph auto-maintenance condition checking.

The primary issue is a memory leak occurring during depth-first search of commit references when determining whether to write commit graphs. The leak stems from incorrect use of `commit_list_append()` which was discarding parent commits during traversal of merge commits. The fix replaces this with `commit_list_insert()` to properly maintain the commit stack.

A second bug is fixed where commit tips weren't being marked with the SEEN flag, potentially causing double-counting of commits reachable via multiple references. The patch adds proper SEEN flag handling when first encountering commits.

The commit includes a new test case in `t/t7900-maintenance.sh` that specifically verifies the fix works with merge commits, exercising the scenario where multiple parent paths need to be traversed. This test was added in response to Justin Tobler's feedback on the v1 series.

The changes are well-contained, touching only the commit-graph writing logic in `builtin/gc.c` and adding targeted test coverage. The memory leak fix is straightforward, and the SEEN flag handling aligns with standard graph traversal patterns in Git. The test case provides clear validation of the merge commit scenario that exposed both issues.

This appears ready for merging as part of the v2 series, with the geometric repack issues having been deferred to future work as noted in the thread context. The patch addresses its stated problems without introducing new complexity or side effects.
