Thread summary:

Feature request for enhanced color differentiation in `git log --graph --all` ref decorations. Skybuck Flying proposes coloring remote names (e.g., `origin`, `Repository`) differently from branch paths when displaying remote refs, to address visual ambiguity between true remotes and branch names that structurally resemble remote paths. Currently both components appear in the same red color. The author suggests using pink for remote names while keeping branch paths red, motivated by their own workflow with multiple remotes (GitHub `origin`, local `Repository` mirror, and `upstream`). D. Ben Knoble points out existing configuration options (`color.decorate.branch` and `color.decorate.remoteBranch`) that might provide similar functionality, though it remains unclear whether these can fully separate remote names from branch paths in the display. Key open questions include: whether current color options suffice, backward compatibility impact, configurability needs, and handling of edge cases like nested remotes or non-standard ref formats. The proposal remains under discussion with no clear consensus yet on whether new coloring logic is needed or if existing configuration meets the use case.
