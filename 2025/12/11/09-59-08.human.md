This is a follow-up discussion in the ongoing thread about macOS iconv(3) issues affecting Git's character encoding tests. Maintainer Junio C Hamano raises broader questions about Git's testability on vanilla macOS installations.

The email questions whether Apple's own builds (which don't use Homebrew) can realistically pass Git's test suite on a stock macOS system. Junio suggests three potential paths forward: fixing macOS bugs like the iconv issue, marking some tests as macOS-incompatible if unfixable, or establishing CI to maintain compatibility. He's essentially asking whether Apple or macOS users are engaged enough to help improve Git's macOS support baseline.

The discussion builds on the previously agreed solution (using Homebrew's libiconv as a workaround) but shifts focus to the larger ecosystem question of how Git should handle platform limitations when vendors don't fix underlying system issues. This isn't proposing new code changes - it's a call for community input about macOS compatibility standards.
