This thread discusses Junio Hamano's proposal to remove pre-C99 flexible array member syntax from Git's codebase, documenting it as a breaking change for Git 3.0 while maintaining backward compatibility via build flags. The change primarily affects contributors rather than end users.

Patrick Steinhardt has raised thoughtful questions about the approach, suggesting this might not warrant being tied to Git 3.0 as a breaking change. He notes the change is technically sound but questions whether it's meaningfully different from previous C99 feature adoptions that didn't require such documentation. Steinhardt proposes alternative implementation strategies and points out that problematic platforms this might affect could still be discovered, making the Git 3.0 tie-in potentially premature.

The discussion has shifted from the technical merits (which appear uncontested) to the process question of how to phase out this legacy construct while following Git's established patterns for introducing modern C features. The thread remains focused on maintainer workflow considerations rather than end-user impact.
