This thread discusses modernizing Git's codebase to require C99 flexible array member (FAM) syntax, eliminating legacy pre-C99 workarounds. Junio Hamano initially proposed documenting this as a breaking change for Git 3.0, maintaining backward compatibility via a compile-time flag. Patrick Steinhardt questioned whether this change truly needed Git 3.0 classification, suggesting it could follow Git's previous pattern of incremental C99 adoption.

Junio has now shifted approach with a new patch that completely removes the legacy FLEX_ARRAY compatibility layer rather than just documenting it. This "weather balloon" change tests whether any platforms still need pre-C99 support by unconditionally requiring standard C99 [] syntax. The technical impact is small (31 lines removed) and should not affect compliant compilers, but it serves as a test case for broader C99 adoption. Junio mentions this is also preparation for adopting Linux kernel-style fortified memcpy features that require C99 support.

The core question remains whether to treat this as a breaking change (original proposal) or follow Git's historical approach of testing C feature adoption through implementation (current patch). While the technical direction (moving to C99 syntax) is uncontested, the process for getting there - either via documentation or immediate testing - is still being discussed. The thread shows Junio leaning toward the more aggressive testing approach, with the understanding that problematic platforms could prompt a revert.
