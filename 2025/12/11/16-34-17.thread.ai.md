Thread summary:

Bug report and fix for `git replay` segfault when given non-existent `--onto` target. The regression was introduced in commit 15cd4ef1f4 ("replay: make atomic ref updates the default behavior") from November 2025, currently present in master/next branches. Reproduction case: `git replay --onto="$doesntexist" "$commit^!"` triggers segfault (exit code 139) instead of proper error handling. The reporter bisected the issue to the atomic ref updates change.

The fix moves a NULL check for the `onto` pointer before its first use in builtin/replay.c, addressing the immediate crash. The 6-line change swaps the position of the NULL check with reflog message construction code that was previously dereferencing the pointer first. The patch maintains existing behavior of erroring out for root commit replay attempts (still unsupported per FIXME comment) but now does so safely. The change is minimal and well-scoped to the reported issue, with proper attribution to the original reporter. The core problem (segfault on invalid --onto target) is resolved, while the larger limitation around root commit replay remains as future work.
