Thread summary:

Bug report and fix for `git replay` segfault when given non-existent `--onto` target, with reviewer approval. The regression was introduced in commit 15cd4ef1f4 ("replay: make atomic ref updates the default behavior") from November 2025, currently present in master/next branches. Reproduction case: `git replay --onto="$doesntexist" "$commit^!"` triggers segfault (exit code 139) instead of proper error handling. The reporter (Kristoffer Haugsbakk) bisected the issue to the atomic ref updates change.

René Scharfe's fix moves a NULL check for the `onto` pointer before its first use in builtin/replay.c, addressing the immediate crash. The 6-line change swaps the position of the NULL check with reflog message construction code that was previously dereferencing the pointer first. Phillip Wood has reviewed and approved the fix, confirming it properly resolves the regression while maintaining existing behavior for unsupported root commit replay attempts (still FIXME). Phillip notes a separate preexisting issue where invalid `--onto` arguments are treated identically to missing arguments, but considers this out of scope for the current fix.

The patch has been signed off by both the original reporter (Kristoffer Haugsbakk) and reviewer Phillip Wood, indicating readiness for integration. The core segfault issue is resolved while the larger limitation around root commit replay remains as future work. The change is minimal and well-scoped to the reported crash scenario, with proper attribution to all involved contributors.
