Thread summary:

Bug report and fix for `git replay` segfault when given non-existent `--onto` target, with ongoing error handling improvements. The regression was introduced in commit 15cd4ef1f4 ("replay: make atomic ref updates the default behavior") from November 2025, currently present in master/next branches. Original reporter Kristoffer Haugsbakk bisected the issue to the atomic ref updates change.

René Scharfe's initial fix (merged) moved a NULL check for the `onto` pointer before its first use in builtin/replay.c, resolving the immediate segfault. Phillip Wood reviewed and approved this 6-line change, noting it properly fixed the crash while maintaining existing behavior for unsupported root commit replay attempts (still marked FIXME). The patch carried Signed-off-by from both Kristoffer and Phillip.

Kristoffer now proposes follow-up work to improve error handling for invalid commit-ish arguments to both `--onto` and `--advance`. The WIP patch modifies `peel_committish()` to call `die()` with descriptive errors when commits cannot be found, rather than silently returning NULL. This would distinguish between missing arguments (current "root commit not supported" message) and invalid arguments. The proposal is untested and raises questions about memory leak handling during errors.

- Maintains distinction from unresolved root commit support limitation
