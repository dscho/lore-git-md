Feature request for improved remote branch coloring in `git log --graph --all`.

Skybuck Flying proposes enhancing the visual distinction between remote names and branch names in `git log` output. Currently, full remote branch references like `origin/feature` and `Repository/feature` are shown entirely in red, making it hard to quickly parse the remote vs. branch components. The suggestion is to use different colors (e.g., pink for the remote part, keeping red for the branch part) to clarify this distinction.

The motivation comes from practical workflow issues: it's possible to accidentally create branches whose names collide with remote names, and the current monochromatic display doesn't help users spot such cases. The author provides concrete examples from their setup where `origin` points to GitHub and `Repository` points to a local mirror, both currently rendered identically.

This appears to be a well-articulated usability improvement that wouldn't break existing behavior. The change would affect the color rendering in `git log --graph` output, specifically how remote branch names are displayed. No implementation details or patches are provided yet - this is purely a feature request to gauge interest from the community.
