This is a retraction of a bugfix patch for geometric repacking with promisor remotes. Patrick Steinhardt had originally proposed a fix (as part of a 3-patch series) that would prevent passing `--stdin-packs` and `--exclude-promisor-objects` simultaneously during geometric repacks in partial clones. The patch claimed these options were incompatible and that geometric repacks didn't need promisor object exclusion anyway.

After Justin Tobler questioned this assumption, Patrick investigated further and discovered his original analysis was incorrect. The current reality is worse than initially thought: Git's geometric repacking doesn't properly handle promisor packs at all. The pack-objects operation fails immediately when encountering them, and even if it didn't, the code lacks the capability to merge promisor packs properly.

Patrick is now withdrawing this patch entirely, acknowledging the problem requires a more fundamental solution. This leaves the original issue (geometric repacks failing with promisor remotes) unresolved, with the deeper problem now recognized as needing proper promisor pack handling support in the repacking machinery. The thread context shows this was the first of three patches, with the other two (memory leak fixes in commit-graph writing and submodule odb handling) still valid and under discussion.
