This is patch 3/8 in Patrick Steinhardt's v3 series refactoring Git's object database alternates handling as part of the ODB abstraction effort. The patch focuses on cleaning up the alternates usability checking logic.

The key change moves the computation of the normalized object directory path into the `alt_odb_usable()` function (renamed to `odb_is_source_usable()`) rather than having it passed in as a parameter. This makes the function more self-contained since it already receives the object database from which this path can be derived. The change simplifies callers by removing their need to compute and pass this redundant information.

The patch also modernizes the terminology by renaming the function to better reflect its role in the new ODB abstraction model. The actual behavior remains unchanged - it still checks whether a path is valid as an alternate object store by verifying directory existence, preventing cycles, and avoiding duplicates.

This appears to be a straightforward refactoring that improves code organization while maintaining existing functionality. It continues the series' theme of separating concerns and reducing redundancy in the alternates handling code. The changes are mechanical but meaningful, touching about 30 lines in odb.c with a clear net reduction in complexity.
