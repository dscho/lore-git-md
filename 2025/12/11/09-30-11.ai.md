This is patch 2/8 in Patrick Steinhardt's v3 series refactoring Git's alternates handling as part of the ODB abstraction effort. The patch moves relative path resolution for alternates into the parsing phase rather than handling it during linking.

The key change relocates path normalization logic from `link_alt_odb_entry()` (renamed to `odb_add_alternate_recursively()`) into `parse_alternates()`. This creates a cleaner separation between parsing alternates (which now handles relative path resolution) and linking them into the object database. The patch maintains existing behavior where unresolvable paths are silently ignored, as the later `alt_odb_usable()` check will still catch invalid paths.

Technical changes involve:
- Adding a `relative_base` parameter to `parse_alternates()`
- Moving path resolution code including `strbuf_realpath()` calls into the parser
- Simplifying the renamed `odb_add_alternate_recursively()` to focus solely on linking
- Updating all callers to pass the new parameter
- Maintaining error handling semantics while changing their location

The patch continues the series' architectural goal of making alternates handling self-contained in preparation for moving it into the `struct odb_source` abstraction. This intermediate step helps separate concerns before the later patches implement the source-based reading/writing. The changes are mechanical but important for the overall design, with 32 lines added and 32 removed in `odb.c`.
