This is a bugfix patch addressing two issues in Git's commit-graph auto-maintenance logic. It's part of Patrick Steinhardt's v2 series that has been refined based on Justin Tobler's earlier feedback.

The patch fixes two distinct but related problems in `builtin/gc.c`:
1. A memory leak occurring when counting merge commits during commit-graph maintenance, caused by incorrect use of `commit_list_append()` that was dropping parent commits from the traversal.
2. A miscount issue where commit tips weren't properly marked as SEEN, potentially causing double-counting when commits were reachable via multiple references.

The fix replaces `commit_list_append()` with `commit_list_insert()` to properly maintain the commit stack during traversal, while also ensuring SEEN flag handling correctly accounts for all commit tips. The patch includes a new test case that specifically exercises the merge commit scenario, building on the existing test coverage that was enhanced in this version of the series.

The changes are well-contained and the commit message provides clear technical details about both the problems and solutions. With the test improvements from v1 now incorporated, this appears to be a solid fix ready for inclusion.
