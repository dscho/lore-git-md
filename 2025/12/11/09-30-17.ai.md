This is the final patch in Patrick Steinhardt's v3 series refactoring Git's object database alternates handling as part of the ODB abstraction effort. The patch completes the transition to source-based alternates handling by implementing writing alternates through the source interface.

The key change refactors `odb_add_to_alternates_file()` to use a new `odb_source_write_alternate()` helper that operates on a `struct odb_source` rather than direct filesystem paths. The new helper:
1. Takes the alternate path as a parameter rather than hardcoding "objects/info/alternates"
2. Returns error codes instead of dying on failures
3. Maintains the same core logic for checking/updating alternates files
4. Is called unconditionally from the wrapper function which then handles the recursive addition

The patch builds on all previous architectural changes in the series, particularly the source-based reading implemented in patch 7/8. It represents the final step in decoupling alternates handling from direct filesystem operations, though as noted in the thread summary, some architectural questions about alternates representation remain open.

The changes are relatively straightforward (35 insertions, 16 deletions) and maintain existing behavior while providing the foundation for future backend-specific alternates handling. With this patch, the series appears technically complete, having addressed the v2 build failure and systematically restructured alternates handling through all 8 patches.
