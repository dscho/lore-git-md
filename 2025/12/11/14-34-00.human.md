Bugfix and platform compatibility discussion regarding macOS iconv issues and package manager assumptions.

René Scharfe provides concrete evidence about Apple's Git builds in response to Junio C Hamano's question about "vanilla" macOS installations. The analysis shows Apple maintains their own Git fork (closely tracking v2.50.1) with several modifications, notably including NO_GETTEXT, NO_FINK and NO_DARWIN_PORTS build flags. This confirms Apple's builds would indeed fail the t3900 tests due to their iconv implementation, regardless of third-party package manager workarounds.

The email advances the thread by moving from theoretical discussion to actual Apple Git implementation details, showing their build configuration choices. This supports the ongoing discussion about whether core Git should accommodate macOS limitations or expect users to rely on package managers like Homebrew. The minimal diff between Apple's fork and upstream suggests they've made only selective modifications, though the specific changes (like additions to config.c and http.c) aren't analyzed in detail here.

This contributes important real-world data to the strategic questions about macOS compatibility, particularly regarding Apple's own Git distribution practices and how they handle the known iconv limitations. The information helps ground the discussion about whether and how to modify Git test expectations for macOS environments.
