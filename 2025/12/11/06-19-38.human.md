This is a follow-up discussion about the Coccinelle build system patch from the MEMZERO_ARRAY series. Patrick Steinhardt questions why explicit include paths are needed for spatch when the compiler doesn't require them, particularly regarding the ewah/ewok.h case that motivated the change.

The core issue stems from Coccinelle's type analysis failing to recognize the `eword_t` type in builtin/last-modified.c, even though the file correctly includes "ewah/ewok.h". Toon Claes' patch adds explicit include paths to help spatch resolve these types, but Patrick finds this solution suspicious since the compiler works fine without these paths.

The exchange highlights an interesting discrepancy between how the compiler and Coccinelle handle include paths. Patrick's skepticism suggests the root cause might lie elsewhere, perhaps in how Coccinelle processes relative includes versus the compiler. This discussion could lead to either refining the include path solution or discovering a different approach to make Coccinelle's type analysis more robust.

The thread remains active with this technical question unresolved, awaiting either clarification from Toon or input from other Coccinelle experts. The outcome may affect how future static analysis tools are integrated into Git's build system.
