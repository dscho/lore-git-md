This thread documents a series of mechanical updates to Git's man pages to accurately reflect the default hash algorithm when Git is compiled with `WITH_BREAKING_CHANGES` enabled (where SHA-256 becomes the default instead of SHA-1). The series, which prepares for Git 3.0's SHA-256 transition, consists of four patches updating documentation for `git`, `git-index-pack`, `git-init`, and `git-show-index`.

The first two patches updated the main `git` and `git-index-pack` man pages to show SHA-256 as the conditional default when breaking changes are enabled, while maintaining the existing SHA-1 documentation path for normal builds. The third patch follows the same pattern for `git-init`, updating its `--object-format` option documentation with conditional asciidoc directives to show the appropriate default based on build configuration. 

All changes are purely presentational - they ensure the documentation matches existing code behavior without altering any functionality. The patches maintain backward compatibility and preserve full sentences for localization purposes. The series appears uncontroversial, with reviewers mainly needing to verify the exact phrasing of the conditional text blocks. One patch remains to update the `git-show-index` man page, completing this documentation alignment effort.
