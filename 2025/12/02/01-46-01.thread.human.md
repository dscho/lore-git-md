This thread documents updates to Git's man pages to reflect that SHA-256 becomes the default hash algorithm when Git is compiled with WITH_BREAKING_CHANGES enabled, rather than SHA-1. The original patch series mechanically updated individual man pages (`git`, `git-init`, `git-index-pack`, and `git-show-index`) using conditional AsciiDoc blocks to show the different defaults.

Junio C Hamano has now proposed a refactoring that would centralize this documentation by defining a `defaulthash` attribute in the build system and documentation configuration, rather than repeating conditional blocks in each man page. This approach would make the documentation more maintainable while preserving the same conditional behavior. The change would affect the Makefile, asciidoc.conf.in, and git.adoc, but Junio notes it needs verification with Asciidoctor and presents it as a discussion point.

The series remains focused on documentation accuracy and maintainability, not changing any actual Git behavior. The patches so far have been uncontroversial, with the main discussion now being whether to proceed with the original per-file conditional approach or adopt Junio's proposed centralized attribute solution. The next steps will likely involve testing the macro approach and gathering feedback from other documentation experts on the list.
