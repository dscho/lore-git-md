This thread is about updating Git's documentation to accurately reflect the default hash algorithm (SHA-1 or SHA-256) when Git is compiled with the WITH_BREAKING_CHANGES option enabled for the upcoming Git 3.0 release. The initial patches from Brian Carlson took a straightforward approach, adding conditional blocks in multiple man pages to show SHA-256 as the default when breaking changes are enabled while keeping SHA-1 documentation for normal builds.

Junio Hamano then proposed a more maintainable solution - using AsciiDoc attributes to centralize the hash algorithm default text rather than duplicating conditional blocks across files. Patrick Steinhardt has now built on this idea with a more focused suggestion, introducing a specific `default-hash-algo` attribute that could be defined once in asciidoc.conf.in and referenced throughout the documentation.

The key open question remains toolchain compatibility - whether this attribute-based approach will work consistently with both Asciidoc and Asciidoctor. The discussion is converging toward a solution that reduces duplication while maintaining accurate documentation for both hash algorithm scenarios, with no actual behavior changes to Git itself. The next steps will likely involve testing the attribute approach across documentation toolchains before finalizing the implementation.
