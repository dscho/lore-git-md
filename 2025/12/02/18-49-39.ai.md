This is the final patch in Patrick Steinhardt's v6 series implementing the `git history` command, focusing on the `split` subcommand. The patch responds to Elijah Newren's review feedback on the initial implementation.

Key technical aspects of the split subcommand:
- Currently splits commits into exactly two parts (like Jujutsu's implementation)
- Uses interactive hunk selection via `run_add_p_index()`
- Preserves authorship but will now ask for messages for both resulting commits
- Retains original commit's tree structure
- Restricts operation to commits reachable from HEAD for initial simplicity
- Notable changes from review feedback:
  - Will preserve extended commit headers (fixing an oversight)
  - Disallows hunk editing for now to avoid worktree/index complications
  - Clarifies test descriptions about hook execution
  - Maintains restrictive validation (ancestor-of-HEAD requirement) for now

The patch includes extensive test coverage (432 lines) verifying:
- Pathspec filtering
- Validation of non-empty splits
- Branch reachability requirements
- Worktree/index state preservation
- Hook execution behavior
- Message handling

Open questions remain about:
- Future support for multi-way splits
- Whether to relax the ancestor-of-HEAD requirement
- Potential integration with replay infrastructure's revision walking
- Long-term handling of hunk editing

This completes the core functionality for the series, though some interface decisions may evolve based on user feedback. The implementation balances initial simplicity against future extensibility, with clear markers for where enhancements could be added later.
