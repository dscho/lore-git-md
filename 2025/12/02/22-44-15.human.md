This is a user testimonial about the proposed `git-history` command's utility, specifically praising the `drop` and `reorder` subcommands that were part of earlier versions of Patrick Steinhardt's series.

D. Ben Knoble shares two real-world scenarios where these subcommands proved valuable: 

1. **Drop use case**: Needed to move changes to a new branch without using stashes, finding `drop @` more convenient than the standard workflow of committing, cherry-picking, and switching branches.

2. **Reorder use case**: While working on uncommitted changes, found `reorder @ --before-commit=@~` helpful for rearranging WIP commits to maintain logical ordering before finalizing changes.

The email serves as positive feedback about the practical benefits of these history-editing operations, though it's worth noting these particular subcommands aren't in the current v6 series. The testimonial suggests there may be user demand for expanding the command's subcommands beyond the currently implemented `reword` and `split` functionality.
