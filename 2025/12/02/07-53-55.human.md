This is a documentation follow-up in the Scalar config settings series, addressing final questions about GC behavior. Patrick Steinhardt confirms that `gc.auto=0` completely disables automatic garbage collection in Scalar-managed repos, explaining the historical context behind this setting. He notes that while this made sense when maintenance strategies didn't apply to normal maintenance, recent Git versions (2.52+) have changed this behavior while maintaining backwards compatibility.

The email suggests an opportunity for future improvement - introducing an "incremental-v2" strategy that could properly handle both scheduled and normal maintenance, potentially allowing Scalar to re-enable auto maintenance. This would address the performance concern that scheduled maintenance alone (running hourly) might not be frequent enough for highly active repositories.

The discussion builds on Matthew Hughes' earlier question about the interaction between `gc.auto=0` and maintenance strategies, providing both technical clarification and forward-looking suggestions. While not blocking the current series, this exchange surfaces an area for potential future optimization in Scalar's maintenance approach.
