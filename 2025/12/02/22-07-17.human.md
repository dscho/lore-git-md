Performance optimization follow-up for diff-tree copy detection. This is a continuation of René Scharfe's work to optimize copy detection across Git's diff commands. While the initial work showed clear speedups for `diff-index`, this follow-up explores applying similar optimizations to `diff-tree` with mixed results.

The patch introduces a new `diff_same()` function (now renamed to `diff_keep()` in the callback API) to handle unchanged file pairs more efficiently during copy detection. It modifies several core diff components to support this, including the diff options struct and tree-diff machinery. The changes touch key files like `diff.c`, `diff.h`, and `tree-diff.c`.

Benchmarks show inconsistent performance impact on `diff-tree`: memory usage improves slightly (about 2% reduction in peak footprint), but runtime performance varies from 1% slower to 5% faster depending on the repository and commit range being compared. The author expresses some disappointment with these results compared to the clearer wins seen with `diff-index`.

This appears to be a technically sound extension of the earlier optimization work, though the performance benefits for `diff-tree` specifically seem less compelling. The patch maintains good code quality and includes thorough benchmarking, but the marginal gains may warrant discussion about whether the complexity is justified for this particular command.
