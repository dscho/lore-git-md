This is a feature addition to the `git replay` command, introducing a `--revert` mode for server-side commit reversal. The patch series is now in its second version, addressing feedback from the mailing list discussion.

The implementation follows the architectural pattern established by `--onto` and `--advance` modes, making `--revert` a standalone operation mode that takes a target branch argument. The core mechanism swaps merge base and pickme trees to reverse commit changes, similar to how `sequencer.c` handles reverts. Key technical aspects include:

1. Extracted revert message formatting into `sequencer_format_revert_header()` helper function (patch 1)
2. Added `--revert <branch>` mode with proper branch handling and validation (patch 2)
3. Implemented commit-by-commit reversal preserving individual messages
4. Added comprehensive tests covering basic reverts, reapply behavior, conflicts, and edge cases

The series has evolved significantly from v1 based on maintainer feedback:
- Split into two logical patches
- Changed from a modifier flag to standalone mode
- Improved message generation using `commit_subject_length()`
- Added atomic ref update handling
- Enhanced tests with `test_commit_message()` verification
- Notable changes in v2:
  - Restructured operation mode selection
  - Fixed subject extraction bugs
  - Made `--revert` mutually exclusive with other modes
  - Improved documentation and examples
  - Addressed memory safety in merge_opt cleanup

The implementation appears well-considered, with thorough test coverage and clear documentation updates. The changes align with GitLab's use case for server-side operations in Gitaly while maintaining consistency with existing `replay` command behavior. The patch series seems ready for final review, with the main technical questions around operation modes and revision parsing having been resolved in previous discussion.
