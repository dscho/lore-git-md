This is a discussion about the behavior of `git-last-modified`'s depth handling, part of an ongoing series documenting previously undocumented features. The author Toon Claes responds to Patrick Steinhardt's question about whether the command should automatically handle nested paths (like "sub/file") by default.

Toon explains that GitHub's internal `git-blame-tree` implementation defaults to recursive behavior, which would show modifications for specific files when given paths. However, the upstream `git-last-modified` currently doesn't default to recursive mode because the `--max-depth` option wasn't available initially. Toon suggests that without depth limiting, always-on recursion could be annoying, but now that since the command is still marked EXPERIMENTAL, they could consider changing the default behavior.

The exchange highlights a design decision point - whether to make the command more intuitive by defaulting to recursive behavior (like GitHub's version) or maintain the current more conservative approach. This may require implementation changes beyond just documentation updates, potentially affecting the readiness of the patch series.
