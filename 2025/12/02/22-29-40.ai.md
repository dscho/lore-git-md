This is a discussion follow-up in the lockfile PID feature thread. D. Ben Knoble raises several thoughtful points about the proposed debugging feature for Git's lock files. The core suggestion is to consider making the PID tracking configurable via Git config in addition to the current environment variable opt-in, since environment variables may be impractical to set reactively when lock issues occur. Knoble questions whether the feature needs to remain opt-in at all, suggesting it might be useful enough to enable by default, though notes the potential for PID reuse creating false positives in the lock holder identification. The email doesn't propose specific implementation changes but invites discussion about the feature's activation mechanism and default behavior, hinting at real-world debugging scenarios where this would be valuable. The thread context shows this builds on Paulo Casaretto's initial patch which implemented PID tracking via environment variable only, with comprehensive tempfile cleanup and process-alive checking.
