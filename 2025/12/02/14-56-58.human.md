Security debate continuation on ANSI escape sequence handling in Git's sideband channel. Johannes Schindelin responds to Phillip Wood's suggestions about allowing additional control sequences (`\e[K` for line erasure and `\e[G` for cursor positioning) in the sideband sanitization mechanism.

Schindelin strongly opposes expanding the whitelist, arguing these sequences could be abused to hide information from users - a key attack vector. He provides a prototype patch showing how such a whitelist might work (with configurable flags for different sequence types) but expresses reservations about the complexity and necessity, noting Git for Windows' existing color-only whitelist hasn't generated complaints.

The email escalates the security debate by:
- Challenging the terminal-emulator-focused security model, citing terminal query sequences that must insert characters into input buffers
- Questioning the legitimacy of non-color control sequences from remote processes
- Suggesting the original security concerns may have been overstated given lack of real-world issues
- Implying the community outreach request may not have been made in good faith

This continues the fundamental architectural disagreement about whether Git should sanitize control sequences (Schindelin's position) or rely on terminal emulators' security (opponents' view). The technical solution appears polished but the philosophical divide remains unresolved, with Schindelin now providing concrete examples of potentially dangerous sequences beyond those originally discussed.
