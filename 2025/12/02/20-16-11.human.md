This is a feature addition to the `git replay` command, introducing a `--revert` mode as part of a series primarily targeting GitLab's Gitaly service. The patch implements server-side commit reversal functionality for bare repositories, completing the trio of history rewriting operations alongside existing `--onto` (rebase) and `--advance` (cherry-pick) modes.

The implementation follows Git's standard revert semantics, creating new commits that undo changes from the specified range while preserving commit-by-commit history. The revert commits use conventional "Revert" message formatting (switching to "Reapply" when reverting a revert) and attribute authorship to the current user rather than the original committer. The core mechanism swaps merge base and pickme trees to reverse the diff direction while reusing the existing merge infrastructure.

The patch includes thorough documentation updates explaining the new mode's behavior and several test cases covering basic functionality, conflict scenarios, message formatting, and option compatibility. The implementation appears well-considered, building on established patterns from `sequencer.c` while maintaining consistency with `git replay`'s existing design.

This is the second patch in a v2 series that has already undergone significant review, with consensus reached on key design points like making `--revert` a distinct operation mode rather than a combinable flag. The changes are focused and well-contained, touching primarily the command implementation, documentation, and test files.
