This is a refactoring patch that extracts revert message formatting logic into a shared function, part of the ongoing `git replay --revert` feature series.

The patch moves the logic for formatting revert commit messages from `do_pick_commit()` into a new `sequencer_format_revert_header()` function in sequencer.c. This handles both regular reverts ("Revert <subject>") and revert-of-revert cases ("Reapply <subject>"), while preserving the special handling for `commit_use_reference`. The extracted function will be reused by the upcoming `git replay --revert` implementation.

The change is cleanly separated into two logical parts - the function extraction itself and the caller updates - making it easy to review. The commit message clearly explains the motivation (avoiding code duplication) and the behavior being preserved. The implementation looks solid, with proper documentation added to sequencer.h and careful handling of edge cases like nested reverts.

This is the first of two patches in v2 of the series, focusing on the preparatory refactoring before introducing the actual `--revert` functionality. The changes are well-contained to sequencer.{c,h} and maintain backward compatibility with existing behavior.
