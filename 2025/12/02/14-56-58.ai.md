[Security] Ongoing debate about ANSI escape sequence handling in sideband channel, with Johannes Schindelin providing additional technical arguments against allowing certain control sequences.

Schindelin responds to Phillip Wood's suggestion to allow '\e[K' (erase to end of line) and '\e[G' (move to column 1) sequences by arguing these could be used maliciously to hide information from users. He provides a prototype patch that would make these sequences configurable via a more granular `sideband.allowControlCharacters` setting (accepting CSV values like "color,erase-in-line"), though expresses doubts about whether this complexity is justified given lack of complaints from Git for Windows users about their stricter default.

Key technical points raised:
- Demonstrates how terminal query sequences (like window size queries) must insert characters into input buffers by design
- Argues terminal emulators have full rights to implement new control sequences without application approval
- Notes his Windows implementation already blocks non-color sequences without reported issues
- Questions whether community outreach was genuine given limited additional sequence requests

The email intensifies the architectural debate about security boundaries should lie, with Schindelin firmly maintaining that applications (not terminals) must sanitize untrusted input. He provides concrete examples of dangerous sequences (`OSC P 1 0 ; ? ST`) and argues terminal-focused security models are fundamentally flawed. The discussion remains polarized between those wanting to preserve existing terminal capabilities and those prioritizing defense against malicious servers.
