This is a documentation patch in the ongoing thread about hash algorithm defaults in Git's documentation when compiled with WITH_BREAKING_CHANGES.

Brian Carlson responds to Patrick Steinhardt's suggestion about using Asciidoc attributes to handle the conditional hash algorithm defaults in documentation. The thread has been exploring two approaches: the original patch series used repeated conditional blocks (ifdef::with-breaking-changes[]), while Patrick proposed a more centralized approach using attributes.

Brian acknowledges Patrick's alternative approach but suggests it might be easier to implement this through the build system (Makefile and Meson config) rather than Asciidoc attributes. They indicate they'll experiment with this approach and potentially send a v2 of the patch series.

The exchange shows the technical discussion is moving from the documentation specifics to the implementation strategy for handling these conditional defaults. Brian's response suggests a preference for build-system integration while remaining open to exploring the attribute approach. This keeps the focus on maintainability and accuracy of the documentation as Git prepares for SHA-256 becoming the default in breaking-changes mode.
