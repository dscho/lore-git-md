This is a feature patch adding debugging support for lock files in Git. The patch introduces an optional mechanism to track which process holds a lock by creating companion `.lock.pid` files alongside lock files. The feature is enabled via the `GIT_LOCK_PID_INFO=1` environment variable and provides more informative error messages when lock conflicts occur.

The implementation creates PID files when locks are acquired (if enabled) and automatically cleans them up during normal operations via the existing tempfile infrastructure. When a lock conflict happens, Git checks if the PID from the `.lock.pid` file is still running using `kill(pid, 0)`, allowing it to distinguish between active locks and stale ones from crashed processes. The error messages are enhanced to show either "Lock is held by process X" (if the process is still running) or "Lock was held by process X (no longer running)" (if stale).

The patch includes comprehensive tests in `t/t0031-lockfile-pid.sh` covering various scenarios: stale lock detection, running process detection, cleanup behavior, and the opt-in nature of the feature. The implementation touches core lockfile handling code in `lockfile.c` and adds documentation for the new environment variable in `Documentation/git.adoc`.

Key technical details:
- New `LOCK_PID_SUFFIX` (".pid") and `GIT_LOCK_PID_INFO_ENVIRONMENT` ("GIT_LOCK_PID_INFO") constants
- `lock_pid_info_enabled()` checks the environment variable
- `create_lock_pid_file()` writes the PID file
- `read_lock_pid()` reads and validates PID files
- Enhanced `unable_to_lock_message()` shows PID-aware errors
- New `pid_tempfile` field in `struct lock_file`
- Modified `rollback_lock_file()` to clean up PID files
- Tests verify behavior with both active and stale PIDs

The patch appears well-structured with thorough test coverage and clear documentation. The opt-in nature via environment variable makes it a safe addition that won't affect existing behavior unless explicitly enabled. The implementation leverages Git's existing tempfile infrastructure for proper cleanup.
