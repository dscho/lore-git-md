This is a bugfix patch for gitk, addressing two related window layout issues in the history view. The patch modifies the Tcl/Tk code that handles pane resizing in gitk's graphical interface.

The first issue fixes sash positions not being preserved when the gitk window is vertically resized. The patch adds a new binding to track sash movements and save their positions in a global `oldsash` variable. This ensures user-adjusted pane sizes persist across window resizing.

The second issue addresses tiny, barely visible panes that occur when moving gitk between screens of different sizes. The patch implements minimum width constraints (30 pixels for author pane, 300 pixels between sashes) and adds logic to scale pane positions proportionally when the window is resized.

The patch includes extensive debug logging (marked for removal after review) that reveals the resizing logic flow. Key changes involve:
- New `oldsash` global variable tracking
- Minimum/maximum size constraints for panes
- Proportional scaling calculations based on window width
- Special handling for very narrow windows (<60 pixels)

The changes affect the `resizeclistpanes` procedure and add a new `<Configure>` event handler in `makewindow`. The patch appears thorough in addressing the reported issues, though the debug output may need cleanup before final merging.
