Documentation patch proposing a refactoring of hash algorithm default documentation. This is part of the ongoing thread about updating man pages to reflect SHA-256 as the default when Git is compiled with WITH_BREAKING_CHANGES.

Junio C Hamano suggests centralizing the hash algorithm default text using AsciiDoc attributes/macros rather than repeating conditional blocks (`ifdef::with-breaking-changes[]`) in each man page. The proposal adds a `defaulthash` attribute set in both the Makefile and asciidoc.conf.in, then demonstrates using it in git.adoc with `{defaulthash}`. 

The change would affect three files: Makefile gets new ASCIIDOC_EXTRA definitions, asciidoc.conf.in gets conditional attribute settings, and git.adoc shows the simplified usage. The approach maintains the same conditional behavior but reduces duplication. Junio notes the idea is untested with Asciidoctor and presents it as a concept for discussion rather than a final solution.

This builds on the previous patches in the series that added conditional documentation blocks, potentially offering a more maintainable approach. The change is purely about documentation presentation and doesn't affect actual Git behavior. Reviewers will need to verify the Asciidoctor compatibility and whether this macro approach works consistently across all documentation toolchains Git supports.
