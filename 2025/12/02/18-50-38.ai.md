Implementation refinement for the `git-history reword` subcommand in Patrick Steinhardt's v6 series. This patch addresses feedback from Phillip Wood on the technical implementation details while maintaining the core functionality of the in-memory commit message rewriting capability.

Key technical changes discussed:
- Defends use of `strvec` for commit collection due to lack of equivalent array utilities
- Explains the `revisions.nr != 1` check as validating argument consumption in revision walking
- Agrees to avoid HEAD updates on `replay_create_commit()` failure
- Considers but keeps current reflog message format for rewritten commits
- Will add abort-via-empty-message documentation to the editor hint
- Acknowledges need to backfill status-related config handling
- Removes misleading `-m` option suggestion from editor failure case
- Fixes potential shell injection in test scripts by using environment variables
- Prefers isolated test repos over reset-based approach for clarity
- Adopts `test_commit_message()` helper where applicable

The patch maintains the subcommand's experimental nature while tightening edge cases and test robustness. Phillip's review has identified several quality-of-life improvements that don't fundamentally change the approach but address potential gotchas in the implementation. The extensive test suite (237 lines) provides coverage for core scenarios while leaving room for future hook integration.
