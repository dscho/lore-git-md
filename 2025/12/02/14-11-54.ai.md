# Security debate on terminal control sequence handling

This email from Johannes Schindelin continues the security discussion about ANSI escape sequence handling in Git's sideband channel. The message provides a detailed technical counterpoint to Brian Carlson's position that terminal emulators should handle security rather than Git.

Schindelin makes several key arguments:
1. Demonstrates concrete dangerous terminal control sequences like `OSC P 1 0 ; ? ST` that can query terminal state, citing XFree86 documentation
2. Argues terminal programs (not emulators) are responsible for sanitization, pointing to examples like `tar` and cURL that implement this
3. Explains how screen-clearing sequences enable attacks by hiding evidence of compromise
4. Notes Git already handles terminal capabilities properly (unlike pre-receive hooks)
5. Describes advanced terminal capabilities (Sixel graphics, video playback) that could be abused
6. Shares independent security researcher validation that this is a real (though moderate severity) vulnerability

The email strongly advocates for Git maintaining its security boundary by sanitizing remote content before terminal display, framing this as standard practice for terminal applications. Schindelin challenges the terminal-emulator-focused security model while acknowledging some terminal emulators have disabled certain features due to buggy applications.

This contributes significantly to the architectural debate by:
- Providing concrete exploit scenarios
- Citing precedent from other tools
- Addressing Carlson's terminal-emulator arguments directly
- Sharing external security validation
- Suggesting Google's security team might provide additional perspective

The core disagreement remains unresolved - whether Git should sanitize or trust terminal emulators - but this email substantially raises the technical stakes of that debate with specific examples and professional security opinions.
