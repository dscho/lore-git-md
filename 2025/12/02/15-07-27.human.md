This is a feature patch adding debugging support for Git's lockfiles. It introduces an optional mechanism to track which process holds a lock by creating companion `.lock.pid` files alongside lockfiles when enabled via the `GIT_LOCK_PID_INFO=1` environment variable.

The patch adds PID tracking to help diagnose stale locks - a common issue when processes crash or are killed. When enabled, Git will create a `.lock.pid` file containing the process ID when acquiring a lock, and provide more informative error messages when lock conflicts occur. The messages can distinguish between an active lock (showing the running PID) and a stale lock (showing the PID is no longer running). The PID files are automatically cleaned up during normal operation via Git's existing tempfile infrastructure.

The implementation touches core lockfile handling code and adds a new test script with scenarios covering stale lock detection, running process detection, and the opt-in nature of the feature. The changes look thorough, with careful handling of edge cases and proper integration with Git's existing tempfile cleanup mechanisms. This appears to be a well-considered quality-of-life improvement for debugging locking issues.
