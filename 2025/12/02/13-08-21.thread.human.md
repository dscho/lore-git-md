This thread discusses a bugfix series for gitk's window layout, specifically addressing issues with sash position preservation and pane sizing during window resizing. The initial patch from Tobias Boesch introduced changes to track sash movements and enforce minimum pane widths (30px for the author pane, 300px between sashes) in the Tcl/Tk GUI code, focusing on the `resizeclistpanes` procedure and new event handlers. While the patch successfully addressed some edge cases, it included debug logging marked for future removal.

Johannes Sixt, the gitk maintainer, has now provided detailed testing feedback that reveals the problem is more complex than initially thought. He found that the bug actually affects horizontal resizing (not vertical as originally stated) and impacts both upper and lower panes. His testing uncovered a specific sequence with maximize/restore operations that causes worse pane proportion scrambling than the original bug. Johannes raised several technical concerns about the current implementation, questioning the choice of event binding, the cascading enforcement of minimum widths, and whether the solution truly fixes the underlying proportional resizing issue rather than just masking symptoms.

The thread now faces open questions about the fundamental approach: whether to use panedwindow's native events, how to properly handle proportional resizing, and how to balance minimum width enforcement with preserving user preferences. Johannes's feedback suggests the patch needs significant refinement before it can be accepted, though no specific code changes have been proposed yet. The debug logging remains in place while these design questions are resolved.
