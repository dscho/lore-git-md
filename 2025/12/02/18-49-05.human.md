This is a refactoring patch in Patrick Steinhardt's ongoing `git-history` series, specifically addressing the add-patch/add-interactive separation needed for in-memory index operations. The patch introduces `run_add_p_index()` to support patching an in-memory index, which is a key requirement for the `git-history` command's planned functionality.

The email is a response to Elijah Newren's concern about potential code duplication between the new `run_add_p_index()` and the existing `run_add_p()` functions. Patrick explains that while there is some overlap (~20 lines out of 90), most of the logic is distinct to warrant keeping them separate. He notes that factoring out the shared code wouldn't provide significant benefits given the complexity differences.

This exchange highlights the careful balancing act in this series between clean code organization and practical implementation needs. The discussion remains technical and constructive, with Patrick providing a reasoned justification for the current approach while acknowledging the validity of the concern about potential future drift between the two functions.
