This is a documentation patch discussion about how to best handle hash algorithm defaults in Git's documentation when compiled with WITH_BREAKING_CHANGES.

Brian m. carlson responds to Patrick Steinhardt's suggestion about using Asciidoc attributes to centralize the hash algorithm default documentation. The thread has previously explored two approaches: direct conditional blocks in each man page (original patches 1-3) versus a centralized attribute approach (proposed by both Junio Hamano and Patrick). 

Brian acknowledges Patrick's suggestion but proposes investigating an alternative implementation that would set the default hash algorithm in the build system (Makefile/Meson) rather than in Asciidoc configuration files. This indicates a potential third technical approach to solving the same documentation consistency issue. The key technical consideration remains maintaining accurate SHA-1 vs SHA-256 default documentation across different build configurations.

The response suggests Brian will experiment with this build-system-based approach and potentially sending a v2 series. This keeps open the question of which implementation strategy (direct conditionals, Asciidoc attributes, or build system variables) will ultimately be adopted for documenting hash algorithm defaults in the Git 3.0 transition context. All approaches aim to solve the same core problem while maintaining compatibility with both regular and WITH_BREAKING_CHANGES builds.
