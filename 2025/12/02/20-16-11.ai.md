This is the second patch in a v2 series adding `--revert` capability to `git replay`, primarily targeting GitLab's Gitaly service. The patch implements the core functionality for reverting commits on bare repositories, following the same architecture as the existing `--onto` and `--advance` modes.

The implementation treats reverts as a distinct operation mode (mutually exclusive with other modes) that creates new commits undoing changes from the specified range. It handles the merge operation by swapping the base and pickme trees compared to cherry-picking, effectively reversing the diff direction. Commit messages follow `git revert` conventions with "Revert" prefix and original SHA, or "Reapply" when reverting a revert. The current user becomes author of revert commits, matching `git revert` behavior.

Key technical aspects:
- New `REPLAY_REVERT` mode enum and `--revert <branch>` CLI option
- Reuses existing merge infrastructure with swapped tree arguments
- Extracts message generation into shared `sequencer_format_revert_header()`
- Adds comprehensive tests covering basic reverts, reflogs, conflicts, and mode exclusivity
- Documents behavior and provides usage examples
- Maintains atomic ref updates and transaction support

The patch builds on prior discussion consensus about keeping revert as a distinct mode and preserving commit-by-commit reversal. It addresses all technical points from the thread, including proper handling of revision ranges and integration with existing replay infrastructure. The implementation appears thorough with good test coverage and clear commit messages.
