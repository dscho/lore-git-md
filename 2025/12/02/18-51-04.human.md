This is the final patch in Patrick Steinhardt's v6 series introducing the `git-history` command, focusing on implementing the "split" subcommand. The patch enables splitting a single commit into two commits by interactively selecting which changes should go into each new commit.

The implementation builds on the replay infrastructure and shares some code with the previously implemented "reword" subcommand. Phillip Wood's review feedback led to several improvements: the commit now prompts for both commit messages (not just the split-out one), shares more code with the reword implementation, and uses a more consistent approach to commit validation.

The split operation works by:
1. Creating a temporary index with the parent commit's tree
2. Using interactive add-patch to let the user select changes for the first commit
3. Committing those changes with a new message
4. Creating a second commit with the remaining changes, preserving the original commit's message

The patch maintains the series' experimental approach while addressing technical feedback. It includes thorough test coverage (432 lines) and handles edge cases like commit validation and message editing. While some code sharing opportunities were identified (particularly around commit creation and message handling), the core split functionality appears solid.

This completes the core functionality of the `git-history` command, which now has both "reword" and "split" subcommands implemented. The series remains marked as experimental, allowing for future refinements based on user feedback.
