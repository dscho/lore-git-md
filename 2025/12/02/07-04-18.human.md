This is a documentation improvement suggestion in the ongoing thread about hash algorithm defaults when Git is compiled with breaking changes enabled.

Junio C Hamano proposes a more maintainable approach to documenting the conditional hash algorithm defaults (SHA-1 vs SHA-256) by introducing a centralized `defaulthash` attribute in the current ad-hoc `ifdef` blocks. The suggestion would define the default hash algorithm once in the build system and documentation configuration, then reference it via `{defaulthash}` throughout the man pages.

The proposal includes three changes:
1. Adding build-time configuration of `defaulthash` in Documentation/Makefile
2. Defining the attribute in asciidoc.conf.in with the same conditional logic
3. Updating git.adoc to use the new attribute reference

While the implementation appears sound, Junio notes this was drafted experimentally and hasn't been tested with Asciidoctor. The change would simplify maintenance of the documentation series by centralizing the conditional logic rather than repeating it in each man page. This follows the existing pattern seen with other shared attributes like `litdd` (for double-dash formatting).

The suggestion builds on the previous patches in this series that updated individual man pages, offering a more scalable solution as more commands need to document their hash algorithm defaults. Reviewers would need to verify the Asciidoctor compatibility and consider whether this approach should be adopted for the remaining documentation updates in the series.
