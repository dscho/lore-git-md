This thread has been developing a mechanism to track which processes hold Git locks, using companion PID files to help diagnose stale locks. Paulo Casaretto has led the implementation through three versions, with significant input from Jeff King (Peff), Patrick Steinhardt, Taylor Blau, and Junio Hamano.

The current solution uses `~pid.lock` files (e.g., `index~pid.lock`) to avoid refname collisions, with a simple boolean`core.lockfilePid` configuration after earlier discussions about more granular control. The implementation includes Windows support via `mingw_kill()` updates, automatic PID file cleanup, and a 139-line test suite in t0031. Each PID file contains a single `pid <value>` line in Git header style.

After Junio's review identified needed refinements in documentation and error handling, this latest version addresses those concerns. The solution now provides production-ready PID tracking with safe namespace separation, cross-platform support, and backward compatibility. With the documentation accuracy issues resolved, this appears ready for merging unless any last-minute concerns surface. The thread has progressed from technical implementation debates to final polish, with consensus forming around the simplified configuration approach.
