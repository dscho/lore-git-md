This is a documentation patch in the ongoing thread about hash algorithm defaults when Git is compiled with WITH_BREAKING_CHANGES. Patrick Steinhardt responds to Brian Carlson's patch series that conditionally documents SHA-256 as the default hash algorithm in this mode, suggesting an alternative approach using Asciidoc attributes.

Patrick agrees with the series but proposes centralizing the hash algorithm default text using an attribute (`default-hash-algo`) defined in asciidoc.conf.in, which would then be referenced in the documentation files. His example shows how this would work for git-index-pack.adoc, replacing the conditional blocks with a single attribute reference. The approach would need to work with both Asciidoc and Asciidoctor.

The suggestion builds on Junio Hamano's earlier proposal in the thread for reducing duplication in the documentation. Patrick presents this as an optional alternative rather than a criticism, noting he's fine with either approach. The patch demonstrates the technical implementation but remains untested with Asciidoctor, leaving that as an open question for discussion.

This continues the thread's focus on accurately documenting the conditional hash algorithm defaults while improving maintainability, with no behavior changes to Git itself. The discussion now has two competing approaches to achieve the same goal - direct conditional blocks versus centralized attributes.
