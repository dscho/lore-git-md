This is a feature patch in Patrick Steinhardt's ongoing `git-history` series, specifically addressing the "reword" subcommand implementation. The email is a response to feedback from SZEDER Gábor about usability concerns with the current approach.

The key discussion points revolve around the reword subcommand's behavior of not checking out the commit being modified (unlike interactive rebase). Patrick acknowledges this is a tradeoff - it makes the operation faster and works with existing working tree changes, but loses the context of seeing the full commit state during message editing. SZEDER Gábor notes this significant behavioral difference isn't well documented or tested in the current implementation.

Patrick also addresses interface concerns about requiring users to specify the commit upfront rather than selecting from a rebase-style instruction sheet. While he personally prefers the direct specification approach, he acknowledges this is subjective.

The patch itself (part of the v6 series) adds substantial implementation (331 lines) and test coverage (237 lines) for the reword subcommand.
