This is a follow-up discussion in the Scalar configuration documentation series, focusing on the interaction between `index.threads` and `index.recordOffsetTable` settings. Patrick Steinhardt confirms Matthew Hughes' understanding that `index.recordOffsetTable` defaults to true when `index.threads` is explicitly enabled, false otherwise. He traces this behavior back to commit 2a9dedef2e from 2018, which implemented this logic for backwards compatibility - avoiding warnings from older Git versions encountering unknown index extensions.

Patrick notes this compatibility concern may now be outdated after 7 years, suggesting it might be time to reconsider the default behavior. The current approach means repositories only benefit from the faster multi-threaded index reading when the offset table is explicitly enabled, while removing this legacy protection could provide performance benefits by default. This discussion surfaces an interesting historical context about index extension handling that wasn't fully captured in the main documentation patches, though it doesn't block the current series' integration.
