This is a documentation patch in the ongoing thread about hash algorithm defaults in Git's documentation when compiled with WITH_BREAKING_CHANGES. Patrick Steinhardt responds to Brian Carlson's patch series that conditionally documents SHA-256 as the default hash algorithm in this mode, suggesting an alternative approach using Asciidoc attributes.

Patrick agrees with the series but proposes centralizing the hash algorithm default text using an attribute (`default-hash-algo`) defined in asciidoc.conf.in, which would then be referenced in documentation files like git-index-pack.adoc. His example shows replacing the hardcoded default with `{default-hash-algo}`. He notes this would need implementation for Asciidoctor as well and presents it as an optional alternative to the current approach of duplicating conditional blocks.

The suggestion builds on Junio Hamano's earlier proposal for attribute-based documentation but focuses specifically on the hash algorithm default rather than broader documentation macros. The key technical elements are the new `default-hash-algo` attribute definition in asciidoc.conf.in and its usage in man pages. This maintains the same conditional behavior (SHA-1 vs SHA-256) while reducing duplication, though it requires verification across both Asciidoc and Asciidoctor toolchains. The patch demonstrates the concept but doesn't claim to be a complete solution.
