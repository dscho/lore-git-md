This is a build system patch addressing cross-compilation issues in the Meson setup, specifically around ICONV_OMITS_BOM detection. It's the second patch in a series originally started by D. Ben Knoble, now being picked up by Toon Claes with the same technical focus.

The change modifies the Meson build configuration to properly handle iconv behavior detection during cross-compilation scenarios. The key technical change is wrapping the ICONV_OMITS_BOM test with `meson.can_run_host_binaries()` check, preventing attempts to execute cross-compiled test binaries on the build host. This affects how Git detects whether the iconv implementation omits byte-order marks.

The patch is narrowly focused on a specific cross-compilation edge case, particularly relevant for s390x architecture but applicable to other cross-compile scenarios. It follows the same pattern as the first patch in the series - addressing a clear technical limitation in the Meson build configuration. The change is minimal (1 line modified) and appears to be a straightforward fix for a known build system quirk.

This continues the series' theme of making the Meson build system more robustly handle cross-compilation scenarios. The change doesn't affect runtime behavior when not cross-compiling, and maintains the same iconv detection logic for native builds. No new configuration options or user-facing changes are introduced.
