This is a documentation patch series addressing an inconsistency in Git's documentation when built with `WITH_BREAKING_CHANGES`. 

Brian Carlson points out that while the `WITH_BREAKING_CHANGES` build option changes the default hash algorithm from SHA-1 to SHA-256, several documentation files still incorrectly state SHA-1 as the default. The 4-patch series updates four documentation files (`git-index-pack`, `git-init`, `git-show-index`, and the main `git.adoc`) to conditionally describe the correct default algorithm based on whether breaking changes are enabled.

The changes are straightforward documentation updates that make the text match the actual behavior when compiled with `WITH_BREAKING_CHANGES`. The patches appear well-scoped, each focusing on a specific command's documentation. The series serves both to correct current inaccuracies and to prevent similar oversights when Git eventually transitions to SHA-256 by default in the future (referred to as "Git 3.0" in the cover letter). 

This is a clean, focused documentation improvement that should be uncontroversial to merge. The changes are clearly motivated and address a real inconsistency in the project's documentation.
