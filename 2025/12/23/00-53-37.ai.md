Feature enhancement for `git status` output. This patch adds a new status line showing how the current branch compares to the project's default branch (origin/main or upstream/main) when tracking a non-default branch. The comparison appears as an additional line after the normal tracking branch status, with three possible states: ahead, behind, or diverged from the default branch.

The implementation adds a new `get_default_remote_ref()` function to remote.c that checks refs/remotes/upstream/HEAD first, falling back to refs/remotes/origin/HEAD. The comparison logic reuses the existing ahead/behind tracking infrastructure but applies it to the default branch rather than the tracking branch. The feature is automatically enabled when already tracking the default branch to avoid redundant output.

The patch includes extensive test coverage in t6040-tracking-info.sh, verifying various scenarios: branches ahead of both their tracking branch and main, diverged from main while synced with tracking, and edge cases around remote preference and different default branch names. The tests confirm the output format matches expectations and properly handles singular/plural commit counts via the existing Q_() pluralization system.

This appears to be a well-considered change with clear motivation (helping developers track drift from mainline) and thorough test coverage. The implementation is focused and doesn't introduce new user-facing configuration, instead using existing remote HEAD ref conventions. The only potential concern is whether the additional output might clutter status for users who don't want this information, though the patch maintains the current behavior when tracking the default branch.
