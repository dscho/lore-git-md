This is part 7/9 of the promisor remote enhancement series, implementing core infrastructure for the `--filter=auto` feature. The patch adds two key functions to `list-objects-filter-options.[ch]`:

1. `list_objects_filter_combine()` takes a list of filter specs and combines them into a single "combine:" filter string, handling URL encoding of sub-filters when needed. It returns a single filter unchanged or NULL for empty input.

2. `list_objects_filter_resolve_auto()` processes auto filters by replacing them with a concrete filter specification, releasing the old filter and parsing the new one. This will be used when resolving filters from multiple promisor remotes.

The implementation includes comprehensive unit tests verifying:
- Basic combination cases (empty, single, multiple filters)
- Proper URL encoding of complex filter strings
- Handling of nested combine filters
- Edge cases around filter syntax

The changes build on existing filter handling infrastructure while adding the dynamic combination behavior needed for the promisor workflow. This is a well-contained plumbing change that maintains backward compatibility and follows the established patterns in the filter options code. The test coverage is thorough, particularly for the URL encoding cases that are security-sensitive.
