This is a documentation patch adding a new whitespace check to detect tabs between non-whitespace characters in documentation files. The change was suggested by Junio Hamano to catch cases where a space was likely intended instead of a tab.

The patch introduces a new `tab-between-non-ws` whitespace rule that specifically looks for tabs appearing between non-whitespace characters when the tab would expand to a single space (i.e., when it appears at a column one less than a tab stop). This avoids false positives for cases like "a\tb" where the tab is being used for alignment.

The new check is enabled by default for all `.adoc` files in the Documentation directory, where these types of whitespace issues have been observed. The implementation includes comprehensive tests covering various edge cases - tabs at tab stops vs between them, multiple tabs in a line, and tabs at line boundaries.

The change appears well-considered with thorough test coverage and a clear explanation of the motivation. It's a focused improvement to Git's whitespace checking that should help maintain consistency in documentation formatting.
