Feature patch for promisor remotes, part 2/9 in the LOP series. This introduces a new `promisor.storeFields` config option that allows clients to automatically store certain fields (currently "partialCloneFilter" and "token") from server-advertised promisor remotes into their local config.

The patch enables secure rotation of authentication tokens and filter specs by having clients automatically update their config when servers advertise new values. Key security constraints: 1) The remote must already be configured locally, 2) No new remotes or URLs are created, 3) Filters are validated before storage, 4) Tokens are checked for control characters. Changes trigger config reload and emit user notifications.

Implementation adds new helper functions in `promisor-remote.c` for field validation and storage, plus extensive tests in `t5710`. Documentation updates cover both config and protocol aspects. The change builds on previous field-checking infrastructure while adding persistent storage capability, maintaining backward compatibility with existing promisor workflows.

This appears well-considered with thorough test coverage and clear security boundaries. The use case for dynamic token rotation is particularly compelling for large-scale deployments. The patch follows the series' incremental approach, with this being the first to introduce persistent state changes after the preparatory refactors in patch 1.
