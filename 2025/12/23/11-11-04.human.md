This is a feature series introducing two related enhancements for Git's promisor/partial clone functionality. The series comes with thorough documentation and test coverage, clearly building on prior work in the "Large Object Promisors" (LOP) effort.

The first part (patches 1-2) adds a `promisor.storeFields` config option that allows clients to store certain fields (like authentication tokens) received from promisor remotes during fetches. This enables workflows where servers can securely rotate credentials that clients need for subsequent lazy fetches.

The second part (patches 3-9) introduces a `--filter=auto` mode for clone/fetch operations. When used, this mode dynamically selects the optimal object filter based on the server's recommendations rather than using a fixed filter specification. This maintains backward compatibility while allowing servers to guide clients toward more efficient filtering strategies.

The implementation appears well-structured, with preparatory cleanups (patches 3-4), documentation updates (patch 5), core filter logic (patches 6-7), promisor integration (patch 8), and final wiring (patch 9). The series includes both shell and unit tests, and CI reports show all tests passing.

This looks like a substantial but carefully planned enhancement to Git's partial clone capabilities, particularly useful in environments where servers need to manage client access policies dynamically. The changes are focused and well-explained, making this a promising contribution to the ongoing LOP effort.
