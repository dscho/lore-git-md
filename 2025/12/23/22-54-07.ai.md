Feature enhancement adding default branch comparison to `git status`, part of v2 patch series addressing triangular workflows. This first patch introduces the core functionality to show divergence from the upstream's default branch (determined via `refs/remotes/upstream/HEAD` or `refs/remotes/origin/HEAD`) alongside the existing tracking branch status.

The implementation adds a new `get_default_remote_ref()` function in remote.c that resolves symbolic refs to find the default branch, with fallback from upstream to origin. The comparison uses the same ahead/behind/diverged format as existing tracking info, appearing on a new line when the tracking branch differs from the default. Extensive test coverage in t6040-tracking-info.sh (246 new lines) verifies behavior across various scenarios: ahead of both branches, diverged from default while tracking a feature branch, and up-to-date with tracking but diverged from default.

Key technical details:
- Default branch determination follows symbolic refs with upstream preference
- New `format_default_branch_comparison()` handles the additional status line
- Comparison suppressed when tracking branch is already the default
- Tests cover remote preference (upstream vs origin), various divergence states, and output formatting
- Maintains existing status output structure while adding the new information

The patch builds on prior discussion about triangular workflows and branch naming, now with concrete implementation addressing the maintainer's request for commit message restructuring. It leaves open questions about push/pull configuration divergence and `branch.<name>.pushRemote` behavior that were raised in the thread, focusing here on the status reporting enhancement.
