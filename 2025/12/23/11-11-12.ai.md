Feature implementation for promisor remotes and filter combination, part 8/9 in the LOP series. This patch adds infrastructure to persist server-advertised filters in memory during a session, enabling the upcoming `--filter=auto` functionality without requiring persistent configuration.

The key changes are:
1. Adds an `advertised_filter` field to `struct promisor_remote` to store filters from server advertisements
2. Modifies `filter_promisor_remote()` to capture and apply these filters to accepted remotes, marking them with a new `accepted` flag
3. Introduces `promisor_remote_construct_filter()` which combines filters from all accepted remotes using the `list_objects_filter_combine()` function from earlier in the series

The patch carefully handles memory management of the captured filters and ensures the accepted state persists through configuration reloads. This enables subsequent operations (like the planned `--filter=auto`) to access the combined filters without requiring them to be stored in config via `promisor.storeFields`.

The changes are tightly scoped to the promisor remote subsystem, modifying only `promisor-remote.[ch]` while building on previous filter combination infrastructure. The implementation maintains the series' thorough approach to state management and prepares for the final `--filter=auto` feature in patch 9/9.
