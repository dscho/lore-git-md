Harald Nordgren's 2-patch series (v25) enhancing `git status` to show divergence from both upstream and push tracking branches was merged into Git after extensive review. The implementation introduced:

1. Core refactoring with `format_branch_comparison()` helper centralizing formatting logic while maintaining existing behavior including quick mode (AHEAD_BEHIND_QUICK) and all output formats.

2. Push tracking implementation with `get_remote_push_branch()` helper and extended `format_tracking_info()` handling both upstream/push, including 285-line test coverage in t6040-tracking-info.sh. The feature shows divergence info for both upstream and push when they differ, with output on new lines and preserved quick mode behavior.

Post-merge, Jeff King (Peff) raised a workflow concern: in triangular workflows (working on 'jch' branch with remote as mirror), the push branch status creates noise. While globally disableable via `status.aheadbehind`, this also removes desired upstream branch info. Peff notes `git checkout` shows this without suppression options.

This reveals a gap in configuration granularity - the thoroughly tested feature lacks per-component display control. The discussion may lead to new configuration knobs for selective push status suppression while preserving upstream info. Key participants in the thread include Harald Nordgren (implementor), Phillip Wood (push.default feedback), Junio C Hamano (merger), and now Jeff King surfacing real-world workflow considerations post-release.

The series remains robust technically but this feedback highlights how merged features continue evolving based on usage patterns. Potential follow-ups could include additional configuration options or conditional display logic for push status in specific workflow contexts. All prior technical requirements and edge cases remain addressed; this is a new user experience consideration emerging from production use.
