This is the final patch in a 9-part series implementing auto-filter functionality for promisor remotes. The patch wires up the `--filter=auto` option in clone/fetch commands and implements the server-side filter combination logic.

Key changes:
- Enables `allow_auto_filter` flag in clone.c, fetch.c, and transport.c to accept "auto" filter specifications
- Modifies fetch-pack.c to handle auto filters by combining server-advertised filters from accepted promisor remotes using the new `promisor_remote_construct_filter()` function
- Persists the "auto" filter setting in config so subsequent fetches maintain the dynamic filtering behavior
- Adds comprehensive tests in t5710 verifying auto-filter behavior, including filter updates from the server and config persistence
- Updates documentation in fetch-options.adoc, git-clone.adoc, and gitprotocol-v2.adoc to explain the new auto-filter behavior

The implementation builds on the series' earlier infrastructure for storing and combining promisor filters, completing the end-to-end functionality. The patch maintains backward compatibility while adding the dynamic filter selection feature, with thorough test coverage of the new behavior. Documentation clearly explains how auto-filtering works with promisor remotes and how it differs from static filter specifications.
