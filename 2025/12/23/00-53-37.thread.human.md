Harald Nordgren's long-running effort to make `git status` branch comparisons configurable via `status.compareBranches` has now been merged to 'next' after thorough review. The feature allows users to specify multiple branch comparisons (like both @{upstream} and @{push}) while maintaining the default @{upstream} behavior when unconfigured. The implementation went through 31 iterations over two months (building on work since 2016) with careful attention to edge cases like remapped refspecs and triangular workflows.

Junio Hamano has now merged a final documentation and test polish patch that explicitly clarifies three key behaviors that were already correctly implemented: branch comparisons are shown in config order, duplicate entries resolving to the same ref are suppressed, and when @{upstream} and @{push} resolve to the same branch, only one comparison appears. The test suite demonstrates this more clearly with renamed test branches, expanded deduplication cases, and consistent use of `git -C` instead of subshells.

Jeff King brokered the final technical approach, while Kristoffer Haugsbakk provided administrative clarifications. The feature now has comprehensive test coverage (354 lines in t6040-tracking-info.sh) and complete documentation, serving as a model for persistent contribution through Git's mailing list workflow. With all social protocols followed and technical concerns resolved, this marks the successful conclusion of a multi-year effort to make branch tracking more flexible while maintaining backward compatibility.
