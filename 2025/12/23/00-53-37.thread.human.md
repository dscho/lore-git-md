Harald Nordgren's long-running effort to make `git status` branch comparisons configurable has reached completion, with the feature now approved for merging. The implementation adds a `status.compareBranches` configuration option that lets users specify which branches to compare against (like `@{upstream}` and `@{push}`), while maintaining the default upstream-only behavior for backward compatibility.

After 31 iterations spanning multiple years, the final version addresses all technical feedback from reviewers. Junio Hamano requested and received several test improvements in this last round - fixing inconsistent test styles, adding explicit tests for single-branch cases, and better documenting the deduplication behavior when the same branch appears multiple times. The implementation now has comprehensive test coverage (354 new test lines) handling edge cases like triangular workflows, remapped refspecs, and various output modes.

The feature represents a persistent contribution success story, with Harald Nordgren patiently incorporating feedback over many revisions, and Jeff King helping broker the final technical approach. With maintainer approval secured and all outstanding issues resolved, the change is now queued for merging to 'next' and should appear in an upcoming release. This concludes a multi-year effort to give users more flexibility in tracking branch relationships while preserving Git's traditional behavior.
