Harald Nordgren's configurable branch comparison feature in `git status` has completed its main development cycle with v26 queued by Junio Hamano, but a small cleanup patch has surfaced. The feature allows configuring which branches `git status` compares against (typically `@{upstream}` and/or `@{push}`) via the `status.compareBranches` setting. After extensive review across 26 versions—including memory leak fixes from Jeff King—the implementation is technically sound.

A final edge case emerged where identical upstream and push branches (like both pointing to `origin/main`) caused redundant divergence reporting. Harald promptly addressed this with a de-duplication fix that maintains backward compatibility. The patch is undergoing final CI testing and will likely be applied to the queued series without further discussion, as it resolves a clear oversight rather than introducing new complexity. This concludes a multi-year effort to make branch comparison flexible while preserving existing behavior, with only minor documentation polish remaining before the feature ships.
