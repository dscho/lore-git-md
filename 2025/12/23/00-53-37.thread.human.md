This thread documents the evolution of a feature enhancing `git status` to show divergence from both upstream and push tracking branches, originally implemented by Harald Nordgren and now merged. The discussion has progressed through several phases, from initial technical implementation to broader workflow considerations, and now in configuration design.

The core implementation introduced helper functions and thorough test coverage, while Jeff King provided detailed analysis of `@{push}` advantages in mirror workflows. Junio Hamano then shifted the focus by proposing a configurable approach via `status.compareBranches`, maintaining upstream-only as the default for backward compatibility while allowing future extensions.

In the latest exchange, Jeff King - who originally implemented the `@{push}` syntax - humorously notes this while reaffirming his stance that push tracking should be configurable to avoid output noise for users who don't need it. He suggests defaulting to "off", though acknowledges this is based on anecdotal experience rather than systematic data. The discussion highlights the tension between feature discoverability (Harald's preference for default-on) and interface cleanliness (Jeff's concerns).

All participants agree on the technical merits of using `@{push}` and anticipate Junio's configuration proposal will resolve the remaining questions about default behavior. The thread has evolved from implementation specifics to UI philosophy, with the merged code serving as a reference point while the community converges on the right balance between functionality and user experience.
