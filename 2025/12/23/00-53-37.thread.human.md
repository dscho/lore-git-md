Harald Nordgren's work on configurable branch comparison in `git status` continues to progress, with the core functionality now implemented and thoroughly tested. The feature introduces a `status.compareBranches` configuration that allows users to specify which branches to compare (upstream and/or push targets) when checking divergence status. The implementation handles various workflow scenarios and maintains backward compatibility.

Jeff King recently identified a subtle memory management issue - a potential double-free in the branch tracking code - that represents the last technical blocker. This builds on earlier debugging work by Harald to address memory leaks in the feature. Jeff has offered to help untangle some legacy memory management in the remote tracking code to properly fix both this issue and related leaks.

The thread shows strong consensus around the feature's design, with Junio Hamano having originally proposed the configuration framework now implemented. Phillip Wood continues to advocate for simplified binary-state output (just showing whether branches differ rather than exact counts), while Jeff has noted the practical value of supporting `push.default=current` workflows. Documentation needs and default settings remain open questions, but the implementation appears structurally sound pending resolution of the memory management issues.
