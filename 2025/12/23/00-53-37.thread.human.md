Harald Nordgren's 27-iteration effort to make `git status` branch comparisons configurable is now complete and queued for the next release. The feature introduces `status.compareBranches` to let users specify multiple branches (including `@{upstream}` and `@{push}`) for comparison, with intelligent de-duplication when these resolve to the same ref - a common scenario in simple workflows. The implementation handles triangular workflows where upstream and push branches differ, while maintaining backward compatibility by defaulting to comparing both.

The series received thorough review from Jeff King (who confirmed memory issue resolutions) and Junio Hamano (who verified the de-duplication behavior). Phillip Wood maintained his preference for binary state information throughout, though this didn't block merging. With comprehensive test coverage (15 new cases in t6040-tracking-info.sh) and all technical concerns addressed, the only remaining item is finalizing the documentation wording. This concludes a significant enhancement to `git status`'s branch comparison capabilities after extensive community review.
