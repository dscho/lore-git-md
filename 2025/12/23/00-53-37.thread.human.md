This thread explores adding configurable branch comparison to `git status` output, originally proposed by Harald Nordgren to help track drift from mainline branches. The v2 patch series introduced performance optimizations and improved default branch detection, but raised concerns about hardcoded remote names ("upstream"/"origin") from reviewers including Yee Cheng Chin and brian m. carlson, who highlighted edge cases in multi-remote setups and specialized workflows.

Junio C Hamano has now clarified the design direction, firmly stating that no new configuration is needed for remote naming. He emphasizes that existing branch configuration (`branch.<name>.remote`) already provides the necessary mechanism to determine pull/push destinations, making pushRemote considerations irrelevant for this feature. This simplifies the implementation by removing the need for new configuration knobs and focusing instead on proper integration with Git's core configuration system.

The discussion continues to balance workflow flexibility with implementation complexity, now with clearer technical guidance about leveraging existing configuration rather than introducing new assumptions. Key open questions remain about handling special cases like gh-pages branches and detached HEAD states, but the path forward appears more focused on adapting the current implementation to better utilize Git's established configuration mechanisms.
