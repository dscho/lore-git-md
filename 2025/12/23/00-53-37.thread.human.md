This thread centers on configuring how `git status` displays branch divergence information, building on Harald Nordgren's merged series that added push-tracking comparisons alongside the existing upstream tracking. The core technical implementation is settled, with `format_branch_comparison()` now handling both upstream and push branch relationships, tested in t6040-tracking-info.sh.

Junio Hamano's latest response refines the ongoing discussion about configuration design. He separates the problem into two dimensions: which branches to compare (upstream, push, or potentially others) and how detailed the comparison output should be (ranging from simple binary "needs push/needs rebase" indicators to detailed commit counts). While Phillip Wood had advocated for simpler output tailored to triangular workflows, Junio suggests keeping the design flexible enough to accommodate both detailed and simplified views through configuration.

The thread has revealed three main perspectives: Harald Nordgren's original vision of showing both push and upstream relationships, Jeff King and D. Ben Knoble's emphasis on configurability (with differing views on defaults), and Phillip Wood's practical focus on triangular workflow needs. Junio is steering toward a solution that preserves the merged functionality while allowing users to customize the output to their workflow - whether they need the full commit counts or just action-oriented indicators. The discussion remains open on exactly how to structure these configuration options to balance simplicity with future extensibility.
