Harald Nordgren's long-running effort to make `git status` branch comparisons configurable is nearing completion after multiple iterations over several years. The feature, controlled via the new `status.compareBranches` configuration option, allows users to specify which tracking branches (like `@{upstream}` and `@{push}`) should be compared when running `git status`. The default behavior remains unchanged (comparing only against `@{upstream}`), but users can now configure additional comparisons.

Maintainer Junio Hamano has conducted a final review of the test suite and found the coverage thorough, verifying various workflow scenarios including different remote configurations, ahead/behind states, and edge cases. He raised two minor points for clarification: how duplicate branch specifications should be handled (the implementation currently deduplicates them) and whether to document that the comparison order follows the configuration order. These are considered documentation polish rather than blocking issues.

The 2-patch series (a refactoring followed by the feature implementation) has already addressed all technical feedback from reviewers like Jeff King, including style fixes and test organization. With Junio's final test review complete, the feature is expected to move to the 'next' integration branch shortly, likely appearing in an upcoming release. This marks the successful conclusion of Harald's persistent contribution effort that began back in 2016.
