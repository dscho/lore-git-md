Harald Nordgren's configurable branch comparison feature for `git status` has been successfully merged after extensive review, but a post-merge discussion has surfaced about its long-term design direction. The feature currently allows comparing against remote-tracking branches through the `status.compareBranches` configuration, with robust implementation and test coverage.

Junio Hamano has raised concerns that the current hardcoded `refs/remotes/` prefixing for branch resolution could create future compatibility issues if the feature is later expanded to support Git's full DWIM (Do What I Mean) rules for refname resolution. He argues that either the standard resolution rules (which handle local branches, tags, and other ref types with proper precedence) should be implemented now, or the project should explicitly commit to never supporting non-remote comparisons through this interface. This would prevent future behavior changes that users might perceive as regressions.

While the current remote-tracking branch functionality remains production-ready and fully tested, this discussion suggests the merged code may need follow-up work to properly align with Git's standard ref resolution behavior. Harald Nordgren, the feature's implementer, had previously agreed with the DWIM expansion path, but the maintainer now sees this as more urgent than originally thought. The exchange highlights the careful balance between feature focus and long-term interface design in Git's evolution.
