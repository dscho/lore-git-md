This thread discusses Harald Nordgren's recently merged enhancement to `git status` that shows divergence from both upstream and push tracking branches. The implementation is technically solid, with thorough refactoring and test coverage, but has sparked discussion about workflow ergonomics post-merge.

Jeff King (Peff) raised concerns that in triangular workflows - where developers work on a branch but push to a mirror repository - the push branch status creates unnecessary noise. While the feature can be globally disabled via `status.aheadbehind`, this also hides useful upstream branch information. Harald responded by questioning whether the mirror-based workflow itself might be suboptimal, suggesting more frequent pushes to a non-mirror destination would provide better visibility.

The exchange highlights differing perspectives on workflow design, with Peff valuing the mirror pattern's simplicity and Harald advocating for more direct pushing. While no concrete changes to the feature are proposed yet, this discussion may lead to future configuration options for selectively suppressing push status while preserving upstream information. The thread demonstrates how even well-tested features continue evolving based on real-world usage patterns and workflow preferences.
