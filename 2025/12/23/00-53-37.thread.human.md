This thread documents the successful conclusion of Harald Nordgren's multi-year effort to make branch comparisons in `git status` configurable. The feature, now merged to the 'next' integration branch, introduces a `status.compareBranches` option that lets users specify which branch comparisons to show (defaulting to `@{upstream}` for backward compatibility). The implementation cleanly separates the formatting logic from the comparison logic and handles various edge cases including deduplication of identical branches and proper ordering of output.

The 2-patch series went through 31 iterations over two months (building on earlier work from 2016-2018) before satisfying all technical requirements. Key reviewers Junio Hamano and Jeff King provided thorough feedback that led to improved test coverage (now 354 lines in t6040-tracking-info.sh) and documentation. The final version addresses all remaining concerns about test organization, edge case handling, and configuration behavior. This serves as a model example of a persistent contribution navigating Git's mailing list workflow to completion.
