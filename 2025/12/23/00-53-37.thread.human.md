Harald Nordgren's configurable branch comparison feature for `git status` has been merged with the current implementation focused on remote-tracking branch resolution, but the thread has evolved into a deeper discussion about making the branch name resolution more flexible and consistent with Git's standard DWIM (Do What I Mean) behavior. Jeff King has taken the lead in proposing technical solutions, identifying two specific edge cases in Git's ref resolution machinery that would need to be addressed for proper DWIM behavior.

The first issue involves `repo_dwim_ref()` not properly handling missing upstream refs - currently it fails silently when a configured upstream branch is missing, while the tracking-info code needs to be able to report this case. King proposes modifying this to return the ref name (with a null OID) in such cases. The second issue stems from how branch names get shortened during expansion, which could lose information needed by the tracking code. King suggests adding an option to preserve the full refname when needed.

King has provided concrete patches for both issues that allow the test suite to pass, though he notes some concern about the complexity being introduced. These changes would support his proposed DWIM-based approach using pattern expansion ("%s@{upstream}") rather than the current hardcoded remote-tracking branch resolution. Junio Hamano has expressed strong preference for this more standard Git behavior approach, though the increased complexity remains a consideration. The discussion has reached a point where the technical path forward is clear, but a final call needs to be made between implementing this more sophisticated resolution or keeping the current restricted approach.
