This thread has evolved a feature enhancement for `git status` that shows divergence from both the upstream tracking branch and the push remote's tracking branch. The original proposal by Harald Nordgren went through several iterations, initially using a custom configuration approach before pivoting to leverage Git's existing branch tracking mechanisms after feedback from Junio Hamano and Ben Knoble. The current v11 patch uses `branch.<name>.pushRemote` when available, falling back to the tracking branch if unset, with optimized ref resolution and memory management.

The implementation has received broad technical approval, with Junio Hamano endorsing the direction and all major feedback addressed. Phillip Wood's recent review focuses on final polishing - he notes the patch is conceptually sound but suggests making the output wording more consistent with Git's existing tracking messages, handling custom refspecs properly, and sharing formatting logic between upstream and push comparisons. The test suite already provides comprehensive coverage of all scenarios.

The only remaining discussion points are about commit organization philosophy (mailing-list style progression vs GitHub-style squashing) and these final implementation refinements. With Harald responsive to feedback and the technical approach settled, this feature appears to graduate to inclusion once these last details are addressed. Key participants have included Harald as implementer, Junio as maintainer, Ben Knoble for design direction, and now Phillip Wood for final code quality review.
