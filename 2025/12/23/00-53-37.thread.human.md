Harald Nordgren's long-running effort to make `git status` branch comparisons configurable has reached its final stages. The feature, which lets users specify whether to compare against @{upstream}, @{push}, or both via a new `status.compareBranches` config option, has gone through 28 iterations over two months (and multiple years of prior work). The implementation consists of two cleanly separated patches - a refactoring foundation followed by the feature itself - with comprehensive test coverage for various workflow scenarios.

Junio Hamano has approved the merge pending final test suite review, with all technical concerns addressed. Kristoffer Haugsbakk recently clarified that Junio's terse "Will replace" comment simply referred to updating the topic branch with this final version, not indicating any further changes needed. The thread demonstrates both the rigor of Git's review process and the persistence required from contributors - Harald first proposed this in 2016-2018 before successfully reviving it this year. The feature is now cleared for merging into 'next' with no outstanding objections, marking the conclusion of this multi-year contribution journey.
