The series introduces a new status output line showing how the current branch compares to the upstream's default branch (determined via refs/remotes/upstream/HEAD or refs/remotes/origin/HEAD), in addition to the existing tracking branch comparison. The implementation adds logic in remote.c to identify the default branch and reuse existing ahead/behind tracking infrastructure. Patch 1 contains the core functionality while patch 2 simplifies the comparison logic.

Key technical changes include:
- New `get_default_remote_ref()` function in remote.c to identify the upstream default branch
- Memory management fixes for the default branch reference strings
- Extended test coverage in t6040-tracking-info.sh (246 new lines)
- Output format matching existing tracking info ("Ahead of 'origin/main' by N commits" etc.)

The commit message has been restructured per maintainer feedback to better follow Git conventions, with clearer explanation of the motivation (helping developers track divergence from mainline when working on feature branches). The implementation now handles both trunk-based and maintenance workflows by dynamically determining the default branch via symbolic refs rather than hardcoding assumptions about branch names.
