This is a discussion about the design of a proposed feature to show default branch comparisons in `git status` output. Junio C Hamano responds to Harald Nordgren's earlier message about terminology and workflow considerations.

The exchange focuses on whether using `remotes/*/HEAD` as the reference point for comparison is appropriate in all workflows. Hamano points out a key scenario where this approach falls short: in projects that maintain both development (`main`) and maintenance (`maint`) branches, contributors working on fixes may want to compare against the maintenance branch rather than the default HEAD. 

Hamano notes the current implementation already provides comparison against the tracked branch (e.g., `fix` vs remote's `fix`), but suggests the additional comparison should be against the maintenance branch in this case, not necessarily the default HEAD. This highlights a limitation in the current proposal's assumption that the remote's HEAD always represents the most relevant comparison point.

The discussion continues to refine the feature's design to handle more complex workflow scenarios beyond simple GitHub-style repositories. The core challenge remains determining the most meaningful reference point for comparison in diverse development environments.
