This is a follow-up in the ongoing discussion about enhancing `git status` to show comparisons with a configurable default branch. Harald Nordgren responds to Chris Torek's suggestion about using `branch.<name>.pushRemote` to handle triangular workflows (where push and pull remotes differ).

Nordgren reports that in his testing with a typical fork-and-upstream setup (his personal GitHub fork and the main project's origin), the `pushRemote` configuration doesn't get automatically set, even though this is exactly the kind of scenario where it might be useful. He provides concrete output showing his remote configuration where both fetch and push point to the same locations for both his fork and the upstream repo.

The email highlights a practical challenge in implementing the proposed status enhancement - the existing configuration mechanisms don't always capture the workflow relationships that users might want to compare against. Nordgren remains open to guidance on how to better utilize these settings, suggesting the discussion around configuration approaches needs more real-world testing data.

This continues the thread's technical refinement phase, now focusing on how remote configuration actually behaves in common forking scenarios versus how it's theoretically supposed to work. The exchange surfaces important implementation considerations for the proposed default branch comparison feature.
