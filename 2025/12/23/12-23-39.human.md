This is a technical discussion about the ongoing feature enhancement to show default branch comparisons in `git status` output. Chris Torek responds to Harald Nordgren's observation that the current branch tracking infrastructure loses the default branch reference (upstream/HEAD) when using `git push --set-upstream`.

The key point is that Git's configuration is more complex than just the basic tracking setup - there are multiple configuration items (remote.pushdefault, branch.<name>.pushRemote, remote.<remote>.push) that can affect where pushes go independently of the pull/status tracking configuration. Chris suggests that `git status` might need to check these additional configurations to properly handle cases where push and pull destinations differ.

This highlights a deeper challenge in the proposed feature: the original approach of simply reusing the existing tracking infrastructure may not be sufficient, as Git's branch setup workflow has multiple moving parts that can affect where branches actually point. The discussion continues to refine how to robustly determine and maintain the default branch reference across different workflow scenarios.
