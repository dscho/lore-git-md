This is a follow-up in the ongoing discussion about enhancing `git status` with configurable branch comparison features. Harald Nordgren responds to Chris Torek's suggestion about using `branch.<name>.pushRemote` to handle triangular workflows, reporting that in his testing this configuration doesn't seem to be automatically set even in typical fork+upstream scenarios. 

Nordgren provides concrete evidence from his Homebrew fork setup where both remotes have identical push/fetch URLs, suggesting the pushRemote mechanism may not address the core issue as hoped. The email highlights a gap between the theoretical solution and practical workflow realities, reinforcing the need for a more direct configuration approach like the previously proposed `repo.settings.defaultBranch`.

The exchange continues to probe edge cases in remote configuration behavior, with Nordgren maintaining focus on real-world usability while acknowledging his own configuration expertise limits. This keeps the thread moving toward a solution that works across different workflow patterns while avoiding the complexities of push/pull divergence.
