Junio C Hamano provides feedback on Harald Nordgren's patch to show default branch comparisons in `git status`. This is a design review focusing on improving the patch's explanation and considering alternative approaches.

The review notes that the commit message doesn't follow Git project conventions - it should first describe current behavior, then the problem, then the solution. Hamano provides sample text showing how to properly structure this. He also questions the concept of "default branch" being the right comparison point, suggesting instead that in triangular workflows, users might want to compare against both their pull source and push destination branches, regardless of naming conventions.

While supportive of addressing the underlying need (tracking divergence from main development lines), Hamano expresses uncertainty about the proposed implementation's design. He hints that the remote configuration system already has the necessary machinery to identify appropriate comparison points without relying on assumptions about branch naming.

The review maintains a constructive tone while identifying several areas needing clarification or reconsideration: commit message structure, terminology ("default branch"), and the fundamental design approach for identifying comparison branches.
