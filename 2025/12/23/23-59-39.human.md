Harald Nordgren responds to concerns about the default branch comparison feature in `git status`, acknowledging that the current upstream/origin assumptions may not fit all workflows. This is part of the ongoing discussion about making branch tracking more configurable.

Nordgren shares their personal workflow context (working against clear origin/master and origin/develop branches) but agrees the feature should likely be off by default. They suggest making it configurable through a repository-wide setting (proposing names like 'repo.settings.defaultBranch' or 'statusGoalBranch') while still allowing per-branch overrides for special cases like 'gh-pages'.

The response indicates openness to making the feature more flexible while maintaining the core value of showing default branch comparisons. The discussion continues to focus on finding the right balance between useful defaults and configurability for diverse workflows.
