Feature implementation in the LOP (Large Object Promisors) series, patch 8/9. This patch adds infrastructure to store server-advertised filters in memory for the current session, enabling the upcoming `--filter=auto` functionality. 

The key changes are:
1. Adding an `advertised_filter` field to `struct promisor_remote` to persist filters during the session
2. Modifying `filter_promisor_remote()` to capture and apply these filters to accepted remotes
3. Introducing `promisor_remote_construct_filter()` to combine filters from accepted remotes using the combination infrastructure from earlier patches

The patch builds on previous work in the series while maintaining the security model where clients must explicitly accept promisor remotes. The implementation handles filter persistence carefully, ensuring filters remain available even if configuration is reloaded. This is part of the larger effort to improve promisor remote functionality, particularly for large-scale deployments needing dynamic filter behavior. The changes are well-contained and follow the established pattern of the series.
