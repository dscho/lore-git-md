This thread introduces a new whitespace rule `tab-between-non-ws` to detect tabs between non-whitespace characters in AsciiDoc documentation files, addressing a documentation quality issue where tabs are sometimes mistakenly used instead of spaces in running text. The feature was suggested by Junio Hamano and implemented with careful attention to avoiding false positives - it only flags tabs that would expand to a single space, not those at tab stops.

The implementation adds a `WS_TAB_BETWEEN_NON_WS` flag to the whitespace checking system in `ws.c`, with comprehensive test coverage in `t/t4015-diff-whitespace.sh` verifying edge cases. The check is specifically enabled for `*.adoc` files via `.gitattributes`. After initial review, Junio identified two remaining tasks: proper colored output highlighting for violations and support for automatic whitespace fixing.

Adrian Ratiu has now confirmed he's implemented these remaining components - adding BG_RED highlighting for violations in diff output and whitespace fixing support in `ws_fix_copy()`. He plans to send a v2 patch series shortly with these additions. With the core detection logic already well-tested and these final presentation and automation pieces being addressed, the feature appears ready for merging once the updated patches are reviewed.
