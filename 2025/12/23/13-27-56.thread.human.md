This thread introduces a new whitespace check for documentation files to catch cases where tabs are mistakenly used between words when spaces were intended. The patch adds a `tab-between-non-ws` rule that specifically flags tabs appearing between non-whitespace characters when they would expand to a single space (at columns one less than a tab stop). This helps catch documentation typos while avoiding false positives for intentionally aligned tabs.

The implementation by the contributor adds a new `WS_TAB_BETWEEN_NON_WS` flag to Git's whitespace checking system, with focused changes to `ws.c` for the new logic. The check is enabled specifically for AsciiDoc files in the Documentation directory via `.gitattributes`. The patch includes thorough test coverage in `t/t4015-diff-whitespace.sh` that verifies edge cases like tabs at tab stops versus between them, multiple tabs, and line boundary conditions.

The implementation carefully distinguishes between intentional alignment tabs and likely typos by only flagging tabs that would collapse to a single space when rendered.
