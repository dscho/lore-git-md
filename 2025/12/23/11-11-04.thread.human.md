This thread covers two closely related patch series that enhance Git's promisor remote functionality, both now in their final iterations and ready to merge. The first series (LOP) implements secure storage of remote fields and dynamic filter combinations, while Christian Couder's series adds URL-based auto-configuration with strict security constraints.

Christian's v4 series, now at patch 5/8, introduces the core `promisor.acceptFromServerUrl` configuration that allows promisor remotes to be automatically configured based on URL patterns. The latest patch adds validation for URL patterns and remote name prefixes, building on the new `url_normalize_pattern()` helper from earlier in the series. The implementation includes thorough error checking and maintains the security boundaries established in previous versions.

Both series have completed their technical review cycles with approvals from key contributors including Patrick Steinhardt and Jeff King. The remaining patches focus on final documentation refinements and code hygiene improvements, with all substantive feedback already addressed. The combined work represents production-ready enhancements to Git's promisor remote capabilities, with particular attention to security and configuration flexibility.
