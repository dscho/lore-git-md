This thread covers a 9-patch v3 series that completes Git's LOP (Large Object Promisors) effort, enhancing promisor remote functionality with two major features: secure storage of remote fields via `promisor.storeFields` config and full implementation of `--filter=auto` mode for dynamic filter combination.

The series has seen thorough review from Patrick Steinhardt (technical implementation), Jean-Noël Avila (documentation), and Christian Couder (both). The latest email discusses patch 4/9, which refactors `builtin/fetch.c` to make `filter_options` local to `cmd_fetch()` rather than file-scoped static - a mechanical change that improves code organization and prepares for later functionality. This follows a similar refactoring in `builtin/clone.c` (patch 3/9).

The series has evolved through three versions with all reviewer feedback addressed, including new test coverage, API cleanup, and implementation simplifications. Junio C Hamano has weighed in on naming choices ("accepted_filters"), and the patches appear ready for merging. The changes enable more dynamic promisor workflows while maintaining security and backward compatibility, representing a significant enhancement to partial clone capabilities.
