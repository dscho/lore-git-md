This thread documents the completion of the LOP (Large Object Promisors) effort, a significant enhancement to Git's partial clone capabilities. The 9-patch v3 series, primarily authored by Christian Couder with substantial input from Patrick Steinhardt, introduces two major features: secure storage of remote fields via `promisor.storeFields` config and full implementation of `--filter=auto` mode for dynamic filter combination.

The series went through three iterations of review, with Patrick Steinhardt providing technical oversight across all patches. Key improvements in v3 include API refinements (notably optimizing `promisor_remote_reply()` to avoid unnecessary string allocations), expanded test coverage for clone operations, and documentation updates (with Jean-Noël Avila's input). Junio Hamano also weighed in on naming choices, resulting in the change from `captured_filters` to `accepted_filters`.

The implementation touches core areas including promisor remote handling, fetch/clone operations, and transport layer integration, with changes to `promisor-remote.[ch]`, `fetch-pack.c`, and related files. The design maintains backward compatibility while adding security-conscious validation of filters and tokens.

With Patrick Steinhardt's final approval confirming all review feedback has been addressed, the series is now merge-ready. This completes a multi-version effort that significantly enhances Git's ability to handle large objects and dynamic filtering, paving the way for future work like configurable remote fallback ordering (a planned GSoC 2026 project).
