The thread covers two complementary improvements to Git's promisor remote functionality that are now ready for merging. The first is a 9-patch series implementing "Large Object Promisors" (LOP) with secure storage of remote fields and dynamic filter combination via `--filter=auto`. The second, by Christian Couder, adds URL-based auto-configuration for promisor remotes, allowing servers to advertise remotes that are automatically configured when their URLs match allowlist patterns.

The URL-based configuration series has gone through three iterations, with the latest patch (v3 7/8) completing the feature by adding automatic remote creation when matching allowlisted URLs. It handles name collisions by appending numbers (-1, -2) and stores both the generated name and original advertised name. The implementation includes thorough documentation of security considerations and extensive test coverage.

Both series have received detailed review from key contributors - Patrick Steinhardt, Toon Claes, and Junio C Hamano - with all technical feedback addressed. The LOP series was approved in its fourth iteration, while the URL-based series has now reached technical completion in its third version. Together they provide a robust foundation for promisor remote management, with future work planned around fetch ordering optimizations. The code touches core promisor-remote handling and URL matching infrastructure while maintaining backward compatibility.
