This thread covers two major improvements to Git's promisor remote functionality. The first is a 9-patch series implementing secure storage of remote fields and dynamic filter combination, which has received final approval and is ready for merging. The second is Christian Couder's 8-part series adding URL-based auto-configuration for promisor remotes, now in its third version.

The URL-based configuration work has progressed through careful review, with Patrick Steinhardt and Junio providing overall approval while Toon Claes offered detailed technical feedback on the security implementation. The latest discussion addresses three specific points: removing an unnecessary pathname matching flag (now done in v3), documenting the intentional exclusion of user/password comparison in URL matching, and explaining the test strategy for server initialization. Christian has incorporated all feedback while maintaining the feature's security properties.

Both series are now rebased and marked as ready in Junio's integration branches, representing significant progress in promisor remote functionality. The only remaining open question concerns configuration precedence when `promisor.acceptFromServer` is set to "all", which may need clarification in either documentation or implementation. The work sets the stage for a planned GSoC 2026 project on promisor remote fetch ordering.
