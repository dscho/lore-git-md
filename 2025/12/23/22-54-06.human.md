Feature enhancement for `git status` to show default branch comparison alongside tracking branch status. This is version 2 of a patch series that would add a second line of output showing how the current branch compares to the project's default branch (typically main/master), even when tracking a different branch.

The key changes in this revision:
- Rewritten commit message to better explain the workflow motivation (tracking feature branches while monitoring drift from mainline)
- Added memory cleanup for allocated strings
- Split the implementation into two patches, separating core functionality from later simplifications

The patch detects the default branch by checking symbolic refs (upstream/HEAD then origin/HEAD) and reuses Git's existing ahead/behind tracking infrastructure. Example output would show both the feature branch status and main branch comparison:

```
On branch feature
Your branch is ahead of 'origin/feature' by 2 commits.
Ahead of 'origin/main' by 5 commits.
```

The thread discussion reveals this addresses real workflow pain points, particularly in fork-based development where engineers want to monitor drift from upstream while working on feature branches. However, there are open questions about triangular workflows and how this interacts with push/pull configurations that may diverge. The implementation looks thorough with 246 lines of new tests covering edge cases.
