This is a feature patch series introducing new configuration and filtering capabilities for Git's promisor remote functionality, part of the ongoing LOP (Large Object Promisors) effort.

The series has two main components. First, it adds a `promisor.storeFields` config option that allows clients to store certain fields (like authentication tokens and filter specs) received from promisor remotes in their local config. This enables workflows where servers can rotate tokens and clients can automatically update them by fetching, while maintaining security by requiring pre-configured remote names/URLs.

The second major feature is a new `--filter=auto` mode for clone/fetch operations. Currently, partial clone filters are fixed at clone time and ignore server suggestions. The new mode dynamically combines filter specs from accepted promisor remotes using Git's existing filter combination mechanism, while still preserving the "auto" setting in local config for future fetches.

The series is well-structured with preparatory refactors (patches 1-4), documentation updates (patch 5), core implementation (patches 6-8), and final wiring (patch 9). It includes comprehensive tests and documentation updates across multiple files. The changes touch promisor-remote handling, filter options processing, and fetch-pack logic, with new unit tests for the filter options code.

Key technical points for future reference:
- New config: `promisor.storeFields` (values: "token", "partialCloneFilter")
- New CLI option: `--filter=auto` for clone/fetch
- Modified files: `promisor-remote.[ch]`, `list-objects-filter-options.[ch]`, `fetch-pack.c`
- New test: `t5710-promisor-remote-capability.sh`
- Related docs: updates to promisor.adoc, protocol-v2.adoc, and command docs

The implementation appears thorough with consideration for backward compatibility and security constraints. The series builds on existing filter combination infrastructure while adding new dynamic behavior for promisor workflows.
