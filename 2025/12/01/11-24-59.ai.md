Feature implementation for reference backend selection via environment variable.

This patch introduces `GIT_REF_URI` as the second part of a v3 series enabling reference backend selection through URI syntax. The environment variable follows the format `<backend>://<URI-for-resource>`, allowing users to specify both the reference storage backend (files or reftable) and its location without modifying repository structure. This mirrors the existing `GIT_OBJECT_DIRECTORY` functionality for objects.

Key technical aspects:
- Implementation centers around `get_ref_store_from_uri()` which parses and validates the URI format
- Strict validation requires `://` separator and non-empty path components
- Lazy initialization in `get_main_ref_store()` ensures hash algorithm availability for reftable
- Comprehensive test coverage in new t1423-ref-backend.sh verifies:
  * URI format validation (missing/empty/malformed cases)
  * Backend compatibility (files<->reftable migrations)
  * Read/write operations across backends
- Documentation added to git.adoc explaining the variable's purpose and syntax

The patch builds on prior refactoring work to make `get_ref_store_for_dir()` URI-aware while maintaining backend-agnostic design. It represents the operational core of the series' goal to enable zero-downtime reference backend migrations, with the environment variable approach having achieved consensus in earlier discussion rounds.

Implementation appears robust with thorough error handling and test coverage. The remaining architectural discussion (per thread context) focuses on filesystem path handling details rather than this environment variable mechanism itself.
