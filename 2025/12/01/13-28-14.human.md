This is a design proposal in the ongoing ref backend selection thread, suggesting an alternative approach to the recently implemented `GIT_REF_URI` environment variable solution.

Patrick Steinhardt proposes extending the existing `extensions.refStorage` config option to support URI-style syntax (`<backend>://<location>`), which would provide a more unified approach for specifying reference backends. The key advantages would be: (1) greater flexibility for moving reference backends, (2) preparation for future backends needing input data, and (3) consistent behavior between config and environment variables (with the latter acting as an override).

The proposal acknowledges some implementation challenges, particularly around worktree reference handling, and suggests refactoring `ref_store_init()` to better accommodate this approach. This comes after the thread had seemingly reached consensus on the environment variable approach, so it represents a significant new direction in the discussion.

The suggestion appears technically sound and aligns with Git's existing patterns, though it would require more substantial refactoring than the current solution. Given Steinhardt's involvement in related ODB URI work, the proposal likely has architectural merit, but its adoption would delay finalizing the series while the changes are implemented.
