This is a bugfix patch in the Scalar configuration series, correcting an inverted performance-related config setting.

The patch fixes `index.skipHash` being incorrectly set to `false` in Scalar repositories when it should be `true` for performance benefits. The incorrect value was introduced in commit 4933152cbb but went unnoticed until now. The change improves performance by avoiding hash computation for index entries.

A test failure was discovered when `GIT_TEST_SPLIT_INDEX` is enabled, so the patch temporarily works around this by unsetting that variable in the affected test. The author notes this split index interaction should be properly addressed in a future dedicated series.

The change is straightforward - flipping the boolean value in scalar.c and adding the test workaround. This is part of a larger effort to audit and document Scalar's configuration settings, with this particular fix addressing a clear performance regression that was unintentionally introduced. The patch maintains the split index issue as a known limitation to be resolved separately.
