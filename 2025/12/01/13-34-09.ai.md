This is a follow-up discussion in the completed 10-part series improving Windows symlink test compatibility, specifically addressing patch 7/10 which modified t1006 to handle MSYS2 symlink normalization.

Patrick Steinhardt seeks clarification on whether the test changes in patch 7/10 indicate a bug in `git cat-file`'s symlink handling on Windows. Johannes Schindelin explains that the issue stems from how MSYS2's `winsymlinks:nativestrict` mode creates symlinks differently than Git's test suite expects, not from any failure in `cat-file` functionality. The test changes reflect this platform difference rather than indicating a bug to fix.

The exchange confirms the technical approach taken in the series - the test modifications properly account for Windows-specific symlink behavior while maintaining test coverage. This aligns with the series' goal of making tests work with MSYS2's upcoming symlink support without requiring changes to core Git behavior. The discussion provides additional validation that the patch correctly handles a platform difference rather than working around a Git limitation.
