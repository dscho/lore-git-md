This is a platform compatibility patch in Johannes Schindelin's series improving Windows symlink handling for MSYS2 compatibility. The patch specifically addresses how Windows' `_wopen()` behaves differently from POSIX when creating files with `O_CREAT|O_EXCL` flags on dangling symlinks.

The core issue is that Windows' `_wopen()` would create a file at the symlink target location when given these flags, while Git expects the operation to fail with `EEXIST` (matching Linux behavior). The patch adds a workaround in `compat/mingw.c` to check for symlinks before opening and return `EEXIST` when appropriate, fixing test t4115.8 which expects POSIX-like behavior.

A minor debate emerges in the commit message discussion about whether to frame this as matching "Linux" or "POSIX" behavior. Schindelin argues for the Linux framing, noting Git's coding guidelines prioritize practical behavior over strict POSIX compliance. Junio Hamano suggests the POSIX reference would be more accurate, though acknowledges the compat layer's role is precisely to emulate desired behavior regardless of underlying platform differences.

The technical implementation adds a `GetFileAttributesExW()` check for symlinks (reparse points) before the open operation, preserving existing behavior on non-Windows platforms. This is part of the broader effort to make Git's test suite pass when MSYS2 enables symlink support by default.
