This is a follow-up in the interactive patch UI improvement thread, addressing feedback on the hunk selection state indicators. Abraham Samuel Adekunle responds to Junio Hamano's review of their initial patch that added `[selected]`/`[deselected]` markers to hunk prompts in `add-patch.c`.

The key developments in this reply are:
1. Acknowledgment that the issue affects all interactive commands using the shared prompt machinery (`git reset -p` etc.), not just `git add -p`
2. Recognition that the problem exists for all prompt types (mode changes, deletions, additions), not just hunks
3. Agreement that the current indicator placement breaks the input-flow convention of having choices immediately before the question mark
4. Willingness to explore more explicit phrasing like "previous decision: stage/skip" instead of "selected/deselected"
5. Indication they'll work on a revised solution that addresses these broader concerns while being mindful of display width constraints

The response shows the author is incorporating the feedback about the patch's limited scope and terminology issues, though the specific implementation approach for the expanded solution remains to be determined. The core challenge remains how to provide consistent, clear feedback across all interactive commands without disrupting the established UI flow.
