This is a bug report concerning a submodule-related race condition. Jeff King has identified a test failure in `t7450-bad-git-dotfiles.sh` that appears when stress-testing the `ar/submodule-gitdir-tweak` topic branch. The failure occurs in a test case added by commit 9cf8547320 which verifies proper handling of nested submodules during parallel checkout.

The race condition seems to be introduced or exacerbated by commit 099fe37397 from the series, which moves validation of gitdir paths into `submodule_name_to_gitdir`. While the original intent of the series was to prevent path collisions by encoding submodule names, this change appears to create a timing window where parallel operations can interfere with each other. Jeff notes this might have security implications given the original test's purpose of preventing malicious gitdir clashing.

The report is particularly concerning because the race is reliably reproducible under stress testing (failing within ~10 iterations) but doesn't manifest without the topic branch. This suggests the validation changes in 099fe37397 are interacting poorly with parallel operations, though Jeff acknowledges the possibility the race existed previously in a harder-to-trigger form.

This will likely require attention from both the original author (Adrian Ratiu) and the submodule/parallel checkout maintainers to determine whether the issue lies in the validation logic itself or its interaction with parallel operations. The security implications mentioned make this particularly urgent to address before the topic progresses further in the integration pipeline.
