This thread introduces a refactoring patch (1/2) to prepare the refs subsystem for supporting alternate reference directories outside the main repository. The patch extracts the core ref_store creation logic from `get_main_ref_store()` into a new, more flexible helper function `get_ref_store_for_dir()`. This structural change doesn't modify behavior but enables future work where the refs subsystem will need to create stores for reference directories in arbitrary locations.

The implementation is clean and minimal - just 10 lines added and 3 removed in refs.c - while maintaining all existing functionality including debug wrapper support. The commit message clearly explains this is preparatory work for upcoming changes to support alternate reference directories, though the follow-up patch hasn't arrived yet. This appears to be a well-justified first step in a larger refactoring effort.
