This is a Windows compatibility patch in Johannes Schindelin's series improving symlink handling for MSYS2. The patch specifically fixes how `_wopen()` handles dangling symlinks with `O_CREAT|O_EXCL` flags on Windows would incorrectly create files at the symlink target, while POSIX (and Git's expectations) require failing with `EEXIST`.

The email shows a minor philosophical debate between Schindelin and Junio Hamano about whether to describe the desired behavior as "Linux-like" or "POSIX-compliant" in the commit message. Schindelin argues for keeping the Linux-specific reference since Git's coding guidelines don't mandate strict POSIX compliance, while Hamano suggests the more general POSIX framing. The technical content itself is uncontroversial - the patch clearly fixes a real issue affecting test t4115.8 when MSYS2 enables symlink support.

The patch adds a check in `mingw.c` to detect symlinks via `GetFileAttributesExW()` and return `EEXIST` when appropriate, matching the behavior Git expects. This is part of Schindelin's broader effort to make Git's test suite work correctly with Windows symlinks in preparation for MSYS2's planned symlink support enablement.
