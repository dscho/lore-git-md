This is a feature patch series introducing reference backend selection via URI syntax, now in its third iteration. The series builds on prior consensus around using an environment variable (`GIT_REF_URI`) for temporary backend overrides, with the current focus refining the implementation details.

The core functionality allows specifying reference backends and paths in URI format (`<backend>://<path>`), addressing GitLab's production need for zero-downtime migrations between files and reftable backends. The v3 changes focus on cleanup and localization: removing stale code, translating error messages, and eliminating unnecessary defensive checks. The implementation now properly validates URI syntax (requiring `://` separator) and paths while maintaining the backend-agnostic design established in earlier versions.

Key technical components include the refactored `get_ref_store_for_dir()` helper for URI-aware ref_store initialization and expanded test coverage in t1423-ref-backend.sh. The series remains functionally complete but continues the architectural discussion around URI format (`://` vs `:`) and filesystem path handling from previous iterations. The changes since v2 show responsive refinement based on prior feedback, particularly around error handling and test structure.
