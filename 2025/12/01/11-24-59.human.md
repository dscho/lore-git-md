This is the second patch in a v3 series introducing reference backend selection via URI syntax, focused on implementing the `GIT_REF_URI` environment variable. The patch adds a reference backend counterpart to Git's existing `GIT_OBJECT_DIRECTORY` capability, allowing users to specify both the backend type (files/reftable) and storage location through a URI format (`<backend>://<path>`).

The implementation lazily initializes the reference store when first needed, since repository hash algorithm information required by some backends isn't available during early repo setup. The patch includes thorough validation of URI syntax (now strictly requiring `://`) and comprehensive tests covering:
- Various invalid URI formats
- Cross-backend compatibility between files and reftable
- Read/write operations through the environment variable

The changes touch core refs infrastructure, adding the new environment variable handling while maintaining the existing default behavior. Documentation is updated to explain the new variable, and tests are added in a new t1423-ref-backend.sh file.

This iteration shows responsive refinement from previous feedback, with strengthened URI validation and improved error messages. The patch appears well-constructed with clear commit message, thorough test coverage, and careful handling of edge cases. It represents a key piece of the series' goal to enable zero-downtime reference backend migrations.
