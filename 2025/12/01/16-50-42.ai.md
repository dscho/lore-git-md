This is a cover letter for a documentation and maintenance patch series targeting Scalar's configuration settings. The series builds on a September discussion about improving Scalar's config documentation and implements several key improvements:

1. Adds "# set by scalar" annotations to all config settings to help users understand their origin
2. Corrects a performance regression by properly setting `index.skipHash=true`
3. Removes five stale config values with detailed justifications
4. Reorganizes config handling alphabetically while relaxing enforcement for most settings
5. Documents all remaining config settings with rationales in scalar.adoc

The v2 updates include simplified config-setting code, use of `sane_unset` in tests, and improved documentation clarity. The series has received positive reviews from Junio Hamano and Patrick Steinhardt, with Derrick Stolee addressing all feedback. One notable cross-platform consideration is `core.fscache` which exists only in Git for Windows and will need separate handling there.

Key technical changes affect scalar.c (config handling), t9210-scalar.sh (test adjustments), and Documentation/scalar.adoc (new config documentation). The series represents a comprehensive audit of Scalar's configuration approach while maintaining backward compatibility where needed. The documentation patch in particular provides valuable context for each config setting, including performance tradeoffs and upgrade considerations for settings like commitGraph.generationVersion.
