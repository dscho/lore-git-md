This is a Windows compatibility fix for the test suite, part of Dscho's ongoing series to prepare Git's tests for MSYS2's upcoming symlink support.

The patch addresses a test in t0301-credential-cache.sh that uses `mkdir -m 700`, which doesn't work properly on Windows due to differences in permission systems. The fix splits this into two steps: first creating the directory with `mkdir -p`, then setting permissions with `chmod 700`. This follows the same pattern as a previous 2021 fix (0fdcfa2f9f5).

While Junio questions why Windows' more powerful permission system can't emulate the simpler Unix model, Dscho pragmatically notes this is beyond the scope of the current series. The patch represents a straightforward solution to an issue that has surfaced twice now over four years, suggesting it might be worth adding a test linter rule to catch similar cases in the future.

The change is currently hidden behind a SYMLINK prerequisite but would become problematic when Windows gains broader symlink support. The fix is minimal and focused, touching just one test file with a simple two-line modification.
