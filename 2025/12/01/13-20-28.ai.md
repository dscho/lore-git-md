This is part 4/10 of Johannes Schindelin's series improving Windows symlink test compatibility, specifically addressing test failures in t0001-init.sh when `git diff --no-index` is used for test comparisons. The patch originally proposed skipping the symlink comparison entirely on Windows when `GIT_TEST_CMP` uses `--no-index`, since that mode doesn't resolve symlinks as the test expects.

Junio Hamano suggested an alternative approach - using direct `cmp` instead of `test_cmp` when `--no-index` is detected, which Johannes agrees to implement despite reservations about its value. The test verifies correct handling of gitdir symlinks during re-initialization, and the change ensures it passes on Windows while maintaining the check on other platforms. This represents a pragmatic solution to the immediate test failure while leaving open the broader question of whether `test_cmp`'s symlink handling should be made more consistent across platforms.

Key technical details:
- Modifies t0001-init.sh's 're-init to move gitdir symlink' test
- Adds platform-specific handling when `GIT_TEST_CMP` contains `--no-index`
- Preserves original behavior on non-Windows platforms
- Follows Junio's suggestion to use `cmp` directly rather than skipping the check
- Maintains test coverage for symlink functionality while working around Windows path handling differences
