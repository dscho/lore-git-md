This is part 6/7 of Justin Tobler's series extending Git's `repo structure` command with detailed object size reporting. The patch adds disk size information to the machine-readable keyvalue and nul output formats, complementing the existing inflated size reporting added in earlier patches.

The changes introduce a new `disk_sizes` field in the `object_stats` struct to track on-disk storage sizes by object type, collected via the `oi.disk_sizep` field from `odb_read_object_info_extended()`. The patch updates both the documentation and test suite to verify the new disk size reporting, using `git cat-file --batch-check` to validate the numbers.

This continues the series' pattern of carefully maintaining both human-readable and machine-readable output formats while adding new metrics. The implementation follows the same approach used for inflated sizes, keeping the code consistent and predictable. Test coverage is thorough, with a new helper function to calculate expected disk sizes and updated SHA1-specific test expectations.

The patch appears well-integrated with the rest of the series, showing the same attention to detail in both implementation and testing as previous parts. It completes the machine-readable output formats by providing both size metrics (inflated content and on-disk storage) for programmatic consumption.
