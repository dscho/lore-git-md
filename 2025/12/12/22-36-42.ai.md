This is part 5/7 of Justin Tobler's v2 series enhancing Git's `repo structure` command with object size reporting. The patch focuses on adding inflated object size information to the human-readable table output format.

The key technical changes include:
- Introduces a new `stats_table_size_addf()` helper function in `builtin/repo.c` that formats size values using `strbuf_humanise_bytes_value()` with the new `STRBUF_HUMANISE_COMPACT` flag
- Extends the `stats_table_setup_structure()` function to display both count and inflated size information for each object type (commits, trees, blobs, tags)
- Adds a new `STRBUF_HUMANISE_COMPACT` flag to control whether to use compact unit strings ("B" vs "bytes")
- Updates tests in `t/t1901-repo-structure.sh` to verify the new size reporting, including SHA1-specific expected values for a non-empty repository

The implementation maintains the series' careful separation between machine-readable (keyvalue/nul) and human-readable (table) output formats, with size information only being added to the table format. The test updates demonstrate the new output format showing both counts (in decimal k/M units) and sizes (in binary KiB/MiB units).

This builds on the infrastructure from earlier patches in the series while keeping the output formatting changes focused on human readability. The patch follows the established pattern of the series with thorough test coverage and attention to internationalization (gettext markings for all new strings).
