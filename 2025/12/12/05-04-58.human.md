This is a follow-up discussion about build system changes for Coccinelle rules in the MEMZERO_ARRAY patch series. Junio Hamano responds to Patrick Steinhardt's questioning of whether explicit include paths are needed for spatch analysis.

The core issue revolves around whether Coccinelle requires explicit `-I` include paths (compat, ewah, refs, etc.) to properly analyze Git's codebase. Patrick argues these paths shouldn't be necessary since Git's code already includes headers relative to the root directory, and regular compilation works fine without them.

Junio acknowledges Patrick's point that the current approach seems puzzling, suggesting he may be reconsidering the build system changes proposed in patch 2/2. The discussion remains unresolved, with no clear technical justification yet provided for why Coccinelle would need these paths when the compiler doesn't.

This exchange highlights an important design question about how Coccinelle should interface with Git's build system. The outcome could affect how future static analysis rules are implemented, though it doesn't impact the core MEMZERO_ARRAY functionality from patch 1/2. The thread awaits input from build system or Coccinelle experts to resolve the technical question.
