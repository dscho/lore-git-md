This is a technical clarification in the ongoing macOS iconv conversion thread. René Scharfe corrects his earlier statement about compiling Git with NO_ICONV on macOS, noting that it's not actually feasible due to `compat/precompose_utf8.c`'s hard dependency on `reencode_string_iconv()`. The PRECOMPOSE_UNICODE functionality cannot be easily disabled, making NO_ICONV unusable on macOS without source modifications.

The email reveals that René had previously used ICONVDIR for builds but forgot about this configuration, leading to initial confusion when working with fresh builds. This serves as an important implementation detail for the build system discussion, confirming that macOS builds must either use the system iconv (with its known ISO-2022-JP conversion issues) or properly configured alternative iconv installations via ICONVDIR.

Key technical points:
- NO_ICONV is non-viable on macOS due to precompose_utf8.c requirements
- PRECOMPOSE_UNICODE has a hard dependency on iconv functionality
- ICONVDIR remains the proper configuration mechanism for alternative iconv installations
- The clarification helps narrow the solution space for the macOS build issues

This reinforces that any final solution must account for macOS's mandatory iconv usage, either through the workarounds previously discussed (state reset, package manager paths) or by accepting the system iconv's limitations with appropriate test accommodations.
