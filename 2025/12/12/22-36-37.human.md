This is a feature patch series extending Git's `repo` command functionality, specifically enhancing the "structure" subcommand with object size reporting. The series adds both inflated content sizes and on-disk storage sizes for objects, along with improved human-readable output formatting.

Justin Tobler's 7-part series builds on previous work to provide more detailed repository analysis. The key additions are:
1. Refactoring object type counting infrastructure
2. Adding human-readable scaling for counts with translatable units
3. Tracking inflated object sizes
4. Displaying disk size metrics in both machine-readable (keyvalue/nul) and human-readable formats

The v2 changes address feedback from the previous round, including:
- Reusing existing strbuf humanization logic while maintaining table alignment
- Handling missing objects gracefully for partial clones
- Renaming keyvalue fields to be more explicit (disk_size/inflated_size)
- Marking unit prefixes for translation
- Improving test coverage with real value checks

The implementation carefully separates output formats while sharing collection infrastructure. The series shows attention to internationalization, documentation, and test robustness, with coordination between multiple contributors to resolve test conflicts. The changes provide useful repository insights while maintaining backward compatibility with existing formats.
