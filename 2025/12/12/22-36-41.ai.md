Feature enhancement in Justin Tobler's ongoing `repo structure` series (part 4/7), adding inflated object size reporting to keyvalue/nul output formats.

This patch extends the machine-readable output formats (`--format=keyvalue` and `--format=nul`) to include the total inflated size of objects by type (commits, trees, blobs, tags). The implementation uses `odb_read_object_info_extended()` to collect size data during object traversal, storing results in a new `inflated_sizes` field within the `object_stats` struct. Each object type gets its own size counter, parallel to the existing count tracking.

Key technical details:
- New `object_values inflated_sizes` struct field tracks cumulative sizes per type
- Size collection happens during existing object traversal via `count_objects()`
- Output format adds new keys like `objects.commits.inflated_size` with raw byte counts
- SHA1-specific test patterns verify expected sizes against known test repo contents
- Documentation updated to mention size reporting alongside existing count features

The patch maintains the series' separation of concerns - this change focuses solely on the keyvalue/nul formats, with table format support coming in a subsequent patch. Test coverage includes verification of the exact expected sizes, though the SHA1-specific patterns may need future updates for hash algorithm transitions. The implementation builds on established infrastructure from earlier patches while cleanly extending the data collection and output systems.
