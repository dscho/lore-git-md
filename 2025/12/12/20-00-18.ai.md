This is a platform compatibility issue affecting the Rust build system on macOS. The problem stems from commit e509b5b8be which introduced a `sed` command using the GNU-specific `-s` flag to parse `cargo -vV` output, when the library naming convention differs between Windows (`gitcore.lib`) and other platforms (`libgitcore.a`). The author, D. Ben Knoble, notes this works on Gentoo (which uses GNU sed) but fails on macOS (which uses BSD sed). They suggest the `-s` flag may be unnecessary here and propose using `-n` with a `p` flag instead, though they're unsure why the GNU-specific behavior was needed in the first place. The email includes sample `cargo -vV` output showing the host platform detection format being parsed. This appears to be a straightforward build system bug that would prevent Rust-enabled builds from working on macOS systems without GNU sed installed.
