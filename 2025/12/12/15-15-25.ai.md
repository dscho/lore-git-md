This is a bugfix patch in the ongoing Scalar configuration documentation and maintenance series (v3 2/5). It corrects an incorrect `index.skipHash` setting that was unintentionally disabling a performance optimization in Scalar repositories.

The patch changes `index.skipHash` from false to true, which was the intended behavior according to the referenced commit 4933152cbb. This provides a performance benefit by skipping hash computation for index entries. The commit message notes this was an unintentional regression that's being fixed before adding full documentation for Scalar's config settings.

A test failure was discovered when `index.skipHash=true` interacts with `GIT_TEST_SPLIT_INDEX` during `test_commit`. The patch works around this by unsetting `GIT_TEST_SPLIT_INDEX` in the affected test, though the split index interaction is noted as something that should be addressed in a future series focused on that feature.

Key technical details:
- Changes `index.skipHash` from false to true in Scalar's recommended config
- Documents this was an unintentional regression since commit 4933152cbb
- Includes test workaround for split index interaction
- Part of broader effort to document and maintain Scalar's configuration settings
- Follows earlier discussion about performance-oriented defaults
- Maintains backward compatibility patterns from 2018 (commit 2a9dedef2e)

The patch is straightforward but reveals an interesting edge case with split index testing that may need follow-up. It demonstrates the value of the ongoing config audit in catching unintended behavior changes.
