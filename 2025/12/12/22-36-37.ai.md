This is a cover letter for a 7-part patch series extending Git's `repo structure` command with object size reporting capabilities. The series builds on previous work that was already merged, now adding both inflated content sizes and on-disk storage sizes for objects, along with improved human-readable output formatting.

The key technical changes include:
- Refactoring object type counting infrastructure into a struct
- Splitting out byte/count humanization logic from strbuf for reuse
- Adding inflated size tracking via `odb_read_object_info_extended()`
- Implementing disk size metrics using `oi.disk_sizep`
- Supporting both machine-readable (keyvalue/nul) and human-readable table output formats
- Using decimal (1000-based) SI units for counts and binary (1024-based) IEC units for sizes
- Adding platform-aware test verification using `git cat-file --batch-check`

Notable improvements in v2:
- Reused `strbuf_humanise()` logic while maintaining table alignment needs
- Changed error handling to ignore missing objects (supporting partial clones)
- Renamed keys to `disk_size`/`inflated_size` for consistency
- Marked unit prefixes for translation
- Added real value verification for keyvalue output tests)

The series touches core components including `builtin/repo.c`, `strbuf.[ch]`, and adds extensive test coverage in `t/t1901-repo-structure.sh`. It maintains careful separation between output formats while sharing collection infrastructure, with particular attention to internationalization, documentation, and test robustness. The implementation follows Git's established patterns for size reporting while introducing new capabilities for repository analysis.
