This is a bugfix patch in the ongoing Scalar configuration documentation series, correcting an inverted performance setting for `index.skipHash`.

The patch fixes a mistake where Scalar was unintentionally setting `index.skipHash=false` when it should have been `true`, missing out on a performance optimization. The incorrect setting dates back to May 2025 and was caught during the current documentation audit. The change is straightforward - flipping the boolean value in the config list.

A test failure was discovered when enabling the correct setting under `GIT_TEST_SPLIT_INDEX`, so the patch temporarily works around this by unsetting that test variable. The author notes this split index interaction should be properly fixed in a future series focused on that area.

This is part of a larger v3 series improving Scalar's config documentation and maintenance. The change aligns with the series' goal of ensuring Scalar's performance optimizations are properly enabled and documented. While simple, it demonstrates the value of the config audit in catching unintended behaviors.
