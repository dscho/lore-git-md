This is a refactoring patch in the `git repo-structure` series that improves human-readable byte size formatting. The patch splits the existing `strbuf_humanise()` function into two parts to better support column alignment in the repo-structure command's table format.

The key change introduces `strbuf_humanise_bytes_value()` which writes just the numeric portion of a human-readable size to the buffer and returns the unit string (like "KiB" or "MiB") separately. This allows callers to control spacing and alignment when combining the numeric value with its unit. The existing `strbuf_humanise_bytes()` and `strbuf_humanise_rate()` functions are rewritten to use this new helper while maintaining their current behavior.

The implementation handles both regular byte counts and rate measurements (with "/s" suffix) via a new `STRBUF_HUMANISE_RATE` flag. All unit strings are marked for translation, continuing the internationalization work from earlier in the series. The patch maintains the same IEC binary unit scaling (1024-based) and rounding behavior as before, just with the formatting components now separable.

This change supports the repo-structure command's need for precisely aligned columns in its human-readable output table, where numeric values and units may need different alignment handling. The patch is a clean refactoring with no behavior change to existing callers, just exposing the formatting components separately for new use cases.
