Refactoring patch in the `repo structure` object size reporting series.

This is the first patch in v2 of Justin Tobler's series to enhance Git's `repo structure` command with detailed object size reporting. It performs a straightforward structural change - grouping the per-type object counts (tags, commits, trees, blobs) into a new `object_values` struct that is then embedded in `object_stats`. This prepares for future patches that will add size measurements (both inflated content sizes and on-disk storage sizes)

The change is mechanical but well-executed, updating all references to the counts to use the new nested struct. The patch maintains all existing functionality while making the codebase more extensible. This is clearly groundwork for the more substantive size reporting features that follow in the series.

As part of an already-reviewed series (v1 was merged), this change is unlikely to be controversial. The diff shows careful attention to updating all affected code paths, including both the human-readable table output and machine-readable keyvalue format. The commit message is concise but adequately explains the motivation.
