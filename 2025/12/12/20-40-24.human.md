This is a follow-up discussion in the ongoing thread about enhancing Git's `repo structure` command with disk size reporting. Justin Tobler responds to Patrick Steinhardt's suggestion about using `git rev-list --disk-usage` for verifying disk sizes in tests.

Justin points out a limitation in `git rev-list`'s filtering behavior - user-specified objects (like HEAD) are always included in the output regardless of the object type filter, which would inflate the reported disk usage. He suggests this might be an undocumented behavior in `git rev-list`'s filtering logic.

As a workaround for testing, Justin proposes using `git cat-file --batch-check` with object type filters to sum disk sizes, though this approach doesn't help verify human-readable formatted output. He indicates he may continue omitting disk size verification from tests, as done in the current implementation.

The discussion reveals a subtle edge case in Git's object filtering behavior that affects testing strategies for the new disk size reporting feature. This technical exchange shows the careful consideration going into ensuring accurate test coverage for the new functionality.
