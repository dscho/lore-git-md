This is a discussion about macOS package manager paths in the context of the ongoing iconv conversion issue.

Carlo Marcelo Arenas Belón responds to René Scharfe and Junio Hamano's conversation about Homebrew paths in the Git build system. He clarifies that Homebrew installations can actually be located anywhere, not just in the standard `/opt/homebrew` (Apple Silicon) or `/usr/local` (Intel) paths, especially in constrained environments like remote macOS instances without root access.

The email notes that the current path settings in the Makefile are outdated (predating the config.mak.uname split) and too macOS-specific. Carlo points out that while user package managers exist on other Unix systems, they're less common outside macOS, mentioning declining usage on AIX and Solaris.

This discussion highlights the tension between supporting flexible package manager locations while maintaining build system simplicity. The exchange suggests the current Homebrew-focused approach may need to account for more edge cases, though Carlo seems to favor keeping the solution pragmatic rather than over-engineering for all possible scenarios.
