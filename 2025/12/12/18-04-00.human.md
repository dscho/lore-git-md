This is a bug report about inconsistent rename detection between `git diff` and `git merge`. Luca Balsanelli demonstrates a case where `git diff --find-renames` correctly identifies a file move with 71% similarity (moving `aaa` to `dir/aaa` while also modifying its content), but `git merge` fails to recognize this as a rename and instead reports a modify/delete conflict.

The key observation is that both commands are using the same 50% similarity threshold (the default value), yet produce different outcomes. The reporter notes they've verified this isn't due to threshold differences, as adjusting the values doesn't resolve the discrepancy. The commit message suggests this contradicts the assumption that rename detection works consistently across Git commands, and that the documentation doesn't explain this divergence.

This appears to be a genuine inconsistency in Git's behavior that could affect users relying on rename detection during merges. The report is well-structured with a clear reproduction recipe and demonstrates the reporter has done basic troubleshooting by checking thresholds. The next steps would likely involve Git maintainers investigating whether this is an intentional difference (with undocumented rationale) or a bug in the rename detection logic during merges.
