This is a technical discussion about modernizing Git's C code requirements, specifically around flexible array member syntax. Junio C Hamano responds to Patrick Steinhardt's questions about why this change was tied to Git 3.0's breaking changes documentation.

The core proposal is straightforward: remove all the legacy compatibility code for pre-C99 flexible array syntax from git-compat-util.h and require the standard C99 syntax (`flexible_array[]`). Junio explains this isn't a typical "weather balloon" test (where Git gradually adopts new features) because we already know some platforms historically needed workarounds (`flexible_array[0]` or `flexible_array[1]`). The patch serves as a test - if any platforms still need the old syntax, they'll fail to compile and can be addressed.

Junio acknowledges Patrick's suggestion to make the change unconditionally rather than tying it to Git 3.0, and provides a revised patch that does exactly that. The implementation is minimal - just 2 lines replacing 31 lines of compatibility code. Junio also hints at longer-term motivations, mentioning this change would help enable importing Linux kernel memory safety features that rely on modern compiler capabilities.

The discussion remains technical and collegial, with both parties focused on finding the right approach rather than debating whether to modernize. The key open question is about process (how to phase in the change) rather than technical direction (everyone agrees C99 syntax is preferable).
