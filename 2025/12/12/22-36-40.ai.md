This is part of a performance/feature series enhancing Git's repository structure reporting capabilities. The patch focuses on improving human-readable output formatting for large object counts.

The patch introduces human-friendly scaling of count values in the table output format of `git repo structure`, using decimal (1000-based) SI units (k/M/G) for better readability of large numbers. Key technical changes include:

- Adds a new `unit_col_width` field to `stats_table` to track unit string widths separately from values
- Introduces `strbuf_humanise_count_value()` helper in strbuf.c to format counts with appropriate scaling and rounding
- Updates table formatting logic to properly align both values and their units in separate fields
- Maintains existing behavior for keyvalue/nul formats while only modifying table output
- Includes test updates showing the new formatting with scaled values (e.g., "3.02 k" instead of "3020")

The implementation handles:
- Proper rounding of values (adding 5/5000/5000000 before division)
- Translation support for unit strings via gettext
- Clean separation between value formatting and unit generation
- Backward-compatible output for unchanged formats

This builds on previous work in the series that established the basic repository structure reporting infrastructure, now focusing specifically on improving human-readable output presentation. The changes touch `builtin/repo.c`, `strbuf.[ch]`, and test files, with careful attention to maintaining alignment and readability in the tabular output format.
