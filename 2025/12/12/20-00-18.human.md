This is a platform compatibility issue affecting Rust-enabled builds on macOS. The problem stems from commit e509b5b8be which introduced a build script using GNU sed's `-s` flag, which isn't available on macOS's BSD sed. The script attempts to parse `cargo -vV` output to determine the library naming convention (`.lib` vs `.a`), but the GNU-specific flag causes the build to fail on non-GNU systems.

D. Ben Knoble notes the script appears to work on Gentoo (which uses GNU sed) but fails on macOS, and questions whether `-n` with a `p` flag might have been the intended approach. The email includes sample `cargo -vV` output showing the host platform detection format the script is trying to parse.

The issue appears to be a straightforward compatibility oversight in the build system, though the author notes they haven't yet reproduced the failure on their own macOS system. The fix would likely involve either using portable sed syntax or adding a platform check to handle BSD sed's different flag conventions.
