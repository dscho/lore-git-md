This is part 3 of a 7-patch series improving Git's `repo structure` command with better object size reporting and output formatting. The series builds on previously merged work that added object size metrics (both inflated content sizes and on-disk storage sizes) to the command's output.

This particular change focuses on making the human-readable table output more readable for large repositories by scaling count values with appropriate unit prefixes (k for thousands, M for millions, G for billions). The patch introduces a new `strbuf_humanise_count_value()` helper that formats numbers like "1.01 k" instead of raw counts, while keeping the machine-readable formats unchanged.

The implementation carefully handles table alignment and adds a new column for units, maintaining clean output formatting. The changes affect `builtin/repo.c`, `strbuf.[ch]`, and test updates in `t1901-repo-structure.sh`. The patch appears well-constructed with thorough test coverage demonstrating both small and large repository cases.

This continues the series' theme of improving repository analysis capabilities while maintaining good output presentation. The changes are focused and build logically on the previous work, with attention to detail in the formatting and internationalization aspects (units are marked for translation).
