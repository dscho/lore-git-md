Bug report about `--pretty=reference` output formatting.

Dirk Gouders reports an issue with the `--pretty=reference` format when displaying a commit with a multi-line message. The format appears to truncate the output after the first line of the commit message, unlike other commits which display correctly. The example shows a commit with a detailed message about fixing a comment and function call in the `lsp_line_t` code, where the `--pretty=reference` output only includes the first line ("line.normalized: fix a comment...") rather than the full subject line.

The commit itself appears legitimate - it's fixing a comment and updating a string copy function call (`lsp_mdup2str()` to `lsp_mdup()`) after a previous change that added null-termination to the `.normalized` field. The commit references the earlier change (ee7b96f) that introduced this behavior.

This looks like a genuine formatting bug in Git's pretty-printing logic, where `--pretty=reference` isn't properly handling multi-line commit subjects. The report is clear and includes both the problematic output and a correct example for comparison, making it would be easy to reproduce. No patch is included - this appears to be just an initial bug report.
