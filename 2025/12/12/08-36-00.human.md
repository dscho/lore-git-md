This is a follow-up discussion about the ongoing platform compatibility effort to require C99 flexible array syntax in Git's codebase. Patrick Steinhardt questions Junio Hamano's approach of tying this change to the Git 3.0 breaking changes document.

Steinhardt suggests this change might not warrant being treated as a major version-breaking change, since Git already uses other C99 features. He proposes two alternative approaches: either converting one FLEX_ARRAY usage site unconditionally as a test case, or keeping the change minimal by just adapting the FLEX_ARRAY macro definitions. He notes the actual code changes would be small either way.

The email maintains a constructive tone while challenging the maintainer's proposed approach. Steinhardt leaves the door open for reconsidering the 3.0 tie-in if compatibility issues emerge, suggesting this might be handled more incrementally like other C99 feature adoptions. The discussion appears to be about process rather than technical substance, focusing on how best to phase in this modernization.
