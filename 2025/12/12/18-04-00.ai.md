Bug report about inconsistent rename detection behavior in `git diff` vs `git merge`.

Luca Balsanelli reports a case where `git diff` and `git merge` handle file renames differently despite using the same similarity threshold (50%). The test case involves moving a file to a subdirectory while modifying its content, where `git diff` correctly detects the rename (showing 71% similarity) but `git merge` fails to recognize it, resulting in a modify/delete conflict instead.

The key observation is that both commands are using the same rename detection threshold (50% similarity) and the same underlying config (`merge.renames=true`), yet produce different outcomes. The commit message notes that the documentation doesn't explain this discrepancy, suggesting it may be unexpected behavior rather than a documented difference in implementation.

This appears to be a genuine inconsistency in Git's rename detection logic between the diff and merge machinery, potentially affecting users who expect consistent behavior across Git commands. The report is well-structured with a clear reproduction recipe and demonstrates understanding of Git's rename detection mechanics. The next step would likely be for Git maintainers to investigate whether this is an intentional design difference or a bug in the merge machinery's rename detection implementation.
