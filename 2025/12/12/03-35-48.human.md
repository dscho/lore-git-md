This is a follow-up in the ongoing macOS iconv conversion issue thread, specifically addressing build system considerations for Homebrew installations.

Junio Hamano and René Scharfe are discussing Apple's own Git distribution to understand how vanilla installations handle the iconv issue. René investigates Apple's modified Git source (based on v2.50.1) and finds they explicitly disable certain features (NO_GETTEXT, NO_FINK, NO_DARWIN_PORTS) in their Makefile. This suggests Apple's builds wouldn't be affected by the current Homebrew/MacPorts path detection discussions since they use their own configuration.

The exchange reveals Apple maintains a modified Git version with about 15 file changes, including some functional modifications beyond just build flags. This provides important context for the broader discussion about what constitutes "vanilla" macOS Git behavior and whether core Git should accommodate unfixable macOS limitations.

The thread continues to balance practical solutions (like Homebrew path detection) with understanding the wider macOS ecosystem. Junio's original question about Apple's shipping version remains relevant - their custom builds appear to sidestep the iconv issues by avoiding certain dependencies altogether, though this doesn't help third-party Git builds on macOS.
