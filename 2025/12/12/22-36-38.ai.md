This is a refactoring patch that is part of the ongoing `repo structure` command enhancement series. It introduces a new `object_values` struct to group per-type object counts (tags, commits, trees, blobs) that were previously directly part of the `object_stats` struct. The change enables better code organization as the series will later add more per-type measurements beyond just counts.

The patch makes mechanical changes throughout `builtin/repo.c` to use the new nested struct:
- Renames `get_total_object_count()` to `get_total_object_values()`
- Updates all references to object counts to go through `type_counts` member
- Maintains identical output formatting in both table and keyvalue modes
- Preserves all existing functionality while preparing for future additions

This foundational change doesn't modify behavior but establishes the structure needed for subsequent patches in the series to add size measurements (both inflated content sizes and on-disk storage sizes) in a clean way. The patch follows Git's established patterns for object type handling while making the code more maintainable for the planned extensions.

Key technical points for future reference:
- New struct `object_values` contains the four object type counts
- `object_stats` now contains `type_counts` as a member
- All counting logic and output formatting updated to use new structure
- Function signatures changed to take `object_values` where appropriate
- Progress reporting and total counting now use the nested structure
