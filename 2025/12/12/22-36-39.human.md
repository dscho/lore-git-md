This is a refactoring patch that splits out byte-formatting logic from `strbuf.c` to support better alignment in the `git-repo structure` command's output. It's part of a larger series (v2 2/7) improving object size reporting.

The patch extracts the core byte-formatting logic from `strbuf_humanise()` into a new `strbuf_humanise_bytes_value()` function that returns the unit string separately from the numeric value. This allows callers to handle the numeric and unit components independently, which is needed for proper column alignment in the repo structure command's table output. The existing `strbuf_humanise_bytes()` and `strbuf_humanise_rate()` functions are rewritten to use this new helper.

The change maintains all existing functionality while making the formatting more flexible. The patch includes careful handling of translation strings (gettext markings) and preserves the distinction between regular byte counts and rate measurements. The implementation continues to use binary (IEC) units (KiB/MiB/GiB) for byte sizes, matching Git's conventions.

This appears to be a well-considered refactoring that cleanly separates concerns while maintaining backward compatibility. The change is motivated by a specific use case in the repo structure command but improves the strbuf API more generally. The patch follows the project's style and includes appropriate documentation updates.
