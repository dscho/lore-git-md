This is a platform compatibility discussion about macOS package manager paths for the ongoing iconv workaround effort.

Carlo Marcelo Arenas Belón responds to René Scharfe and Junio C Hamano's discussion about Homebrew path detection in the macOS iconv workaround patch. He notes that Homebrew installations can technically be located anywhere, not just the standard `/opt/homebrew` (Apple Silicon) and `/usr/local` (Intel) paths, especially in constrained environments like remote macOS instances without root access. 

The email highlights that the current Makefile settings predate the config.mak.uname split and may be too macOS-specific for that location. Carlo also observes that while user package managers exist on other Unix systems (mentioning AIX and Solaris specifically), they are less prevalent than on macOS and generally declining in usage, with the exception of NONSTOP which Git supports directly.

This contributes to the thread's ongoing tension between comprehensive package manager support versus pragmatic focus on the most common Homebrew cases. Carlo's technical note about Homebrew's install location variability adds complexity to the path detection logic under discussion, while his historical context about other Unix systems helps frame why macOS presents unique challenges in this area.
