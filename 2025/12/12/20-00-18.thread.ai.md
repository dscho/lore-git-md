Thread identity: Build system issue affecting Rust compilation on macOS due to GNU/BSD sed incompatibility in commit e509b5b8be, reported by D. Ben Knoble.

Core problem: The build system uses GNU sed's `-s` flag when parsing `cargo -vV` output to determine library naming conventions (gitcore.lib vs libgitcore.a), which fails on macOS's BSD sed. The flag may be unnecessary for this specific parsing task.

Current status: The issue is newly reported with no resolution yet. The problematic code was introduced in e509b5b8be (part of the Rustification effort) and currently breaks Rust-enabled builds on macOS.

Key technical details: The sed command processes cargo's verbose version output to extract platform-specific naming patterns. The GNU-specific `-s` flag appears in the command `sed -E -s '...'` where BSD sed would require different syntax. The output being parsed follows the format `host: x86_64-apple-darwin` (macOS) or similar.

Open questions: Whether the `-s` flag is actually needed for the parsing task, or if it can be replaced with portable `-n` and `p` flags. The original reason for using GNU-specific behavior is unclear.

Participant positions: D. Ben Knoble identified the issue and proposed investigating alternative portable sed syntax, though hasn't submitted a patch yet.

Related work: Part of the broader Rustification effort (Ezekiel Newren). Build system changes often involve D. Ben Knoble (Meson/CMake expert) and Patrick Steinhardt (Rust infrastructure).
