This is part 6/7 of Justin Tobler's series extending Git's `repo structure` command with comprehensive size reporting. The patch adds disk size information to the machine-readable keyvalue and nul output formats, complementing the existing inflated size reporting added in earlier patches.

The changes introduce a new `disk_sizes` field in the `object_stats` struct to track per-type disk usage, collected via `oi.disk_sizep` during object iteration. The patch updates the keyvalue output to include new `objects.<type>.disk_size` entries and modifies the test suite to verify these values by comparing against `git cat-file --batch-check` output. Documentation is updated to mention the new size reporting capability.

Key technical elements:
- New `disk_sizes` field in `object_stats` struct alongside existing `inflated_sizes`
- Disk sizes collected via `oi.disk_sizep` in `count_objects()`
- New test helper `object_type_disk_usage()` using `git cat-file --batch-check`
- Updated test patterns to verify disk sizes match expected values
- Documentation update listing disk size reporting as a supported feature

The implementation maintains consistency with the series' approach to size reporting, using the same object type categorization (commits, trees, blobs, tags) and output format structure as the existing inflated size reporting. Test coverage is extended to verify the new disk size values while maintaining the existing test patterns for other output fields.

This patch builds on the infrastructure established in earlier parts of the series, particularly part 4/7 which added inflated size reporting to the same output formats. The changes are focused and well-contained, following the established patterns for size collection and output formatting in this command.
