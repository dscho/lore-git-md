This is a technical discussion about Git's handling of directory permissions, specifically the SGID bit, in container workflows.

Hadmut Danisch responds to Michal Suchánek's suggestion about using standard group permissions, clarifying that the core issue is Git's removal of the SGID bit (mode 2770) which provides automatic group inheritance for new directories. This behavior breaks container workflows where maintaining consistent group permissions across nested directories is essential.

The email reinforces the key technical distinction that SGID provides automatic propagation of group ownership to new subdirectories - a feature that standard group permissions and ACLs cannot replicate. Danisch emphasizes this is basic Unix administration functionality that Git currently disrupts.

This exchange continues the thread's narrowing focus on SGID's unique propagation behavior as the critical requirement for container use cases.
