This is a technical follow-up in the ongoing discussion about Git's handling of directory permissions, specifically the SGID bit (mode 2770). The email directly responds to Michal Suchánek's suggestion about using standard group permissions, clarifying why that approach doesn't solve the core issue in container workflows.

Hadmut Danisch emphasizes that the SGID bit's key functionality - automatic group inheritance for new directories - is precisely what gets broken when Git clears this bit during operations. This reinforces the thread's central technical point that existing mechanisms like basic group permissions or ACLs (previously discussed) cannot fully replace SGID's automatic propagation behavior in container environments.

The exchange highlights a fundamental gap between Git's current directory creation behavior and Unix filesystem semantics, particularly for use cases requiring strict permission inheritance. No new solutions are proposed in this email, but it serves to sharpen the technical distinction between the proposed alternatives and the SGID behavior that container workflows appear to require.

Key technical points for future reference:
- SGID's automatic group inheritance remains the unresolved requirement
- Git's clearing of this bit breaks container permission workflows
- Simple group membership solutions don't address the propagation need
