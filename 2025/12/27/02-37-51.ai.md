This is a bug report about Git modifying directory permissions unexpectedly, specifically regarding the SGID bit. The reporter, Hadmut Danisch, describes a scenario where they need a Git repository directory to be accessible by a system user running a rootless Podman container. They've configured the directory with specific group ownership and the SGID bit (mode 2770), but Git clone operations overwrite these permissions.

The core issue is that Git currently doesn't preserve the SGID bit when creating or modifying repository directories, despite this being a legitimate use case for shared access. The reporter mentions `core.fileMode` but notes it's documented as being for filesystem compatibility rather than permission preservation. As a workaround, they're using a post-pull hook to reset permissions.

The reporter suggests adding a configuration option that would let users specify permission bits Git shouldn't modify. This touches on filesystem permission handling in Git's repository management code, particularly around directory creation and maintenance operations. The issue appears to be a genuine oversight in Git's permission preservation logic rather than a deliberate design choice.

Key technical details: the problem occurs with directory mode 2770 (group writeable with SGID bit set), affects Git 2.43.0 on Ubuntu 24.04.3, and involves interaction with rootless Podman containers. The reporter is specifically concerned about SGID preservation but the underlying issue might extend to other special permission bits.
