This thread addresses a bugfix for a crash in `receive-pack` when handling symbolic refs that cross namespace boundaries. The original patch from Troels Thomsen fixed a NULL dereference by properly handling fully-qualified ref names during symref updates, with a test case verifying the fix. While Junio Hamano acknowledged the crash fix, he raised concerns about whether allowing such cross-namespace symref updates violates namespace isolation principles, suggesting the behavior might need to be more restrictive.

In the latest response, Troels argues for maintaining the current permissive behavior, noting that symrefs require explicit creation on the receiving side, implying intentionality in cross-namespace links. He suggests that update hooks could enforce stricter policies if needed, preserving flexibility for legitimate use cases. Troels also points out that the bug's longevity (since 2016) indicates such namespace/symref combinations are rare in practice. While he considers making the behavior configurable, he questions whether the use case justifies it. The discussion remains unresolved, weighing namespace isolation guarantees against symref flexibility without proposing immediate code changes.
