Here's a human-readable summary of the thread:

This thread reports a bug where Git unexpectedly modifies directory permissions, specifically the SGID bit, during clone operations. Hadmut Danisch describes a real-world scenario where they need a repository directory (mode 2770) to remain accessible to a system user running rootless Podman containers, but Git overwrites these carefully configured permissions.

The core issue is that Git's current behavior doesn't preserve special permission bits like SGID when creating or modifying repository directories, despite this being a legitimate system administration need. While `core.fileMode` exists for filesystem compatibility, it's not designed for this permission preservation use. As a temporary solution, the reporter uses a post-pull hook to manually reset permissions.

The discussion suggests this appears to be an oversight in Git's permission handling rather than intentional design. The reporter proposes adding a configuration option to specify which permission bits Git should preserve during operations. The bug affects Git 2.43.0 on Ubuntu 24.04.3 and specifically impacts workflows involving rootless containers where precise permission control is crucial.
