This is a small refactoring patch that simplifies some integer parsing logic in the config subsystem. René Scharfe proposes changing `git_config_get_expiry_in_days()` to use `git_parse_int()` instead of `git_parse_signed()`, since the latter was effectively being used with the maximum value of `int` anyway. The change makes the code slightly shorter and clearer.

The patch adjusts the types of some variables to maintain the same behavior: `days` is changed from `intmax_t` to `int` to match `git_parse_int()`, while `scale` is promoted to `intmax_t` to preserve the same multiplication behavior. This appears to be a straightforward improvement with no functional changes - just cleaner code that does the same thing in a more direct way.

The change is small (6 lines modified) and well-contained, touching only config.c. The commit message clearly explains the motivation and the type adjustments needed to maintain identical behavior. This seems like a low-risk cleanup that follows Git's ongoing efforts to simplify and clarify its codebase.
