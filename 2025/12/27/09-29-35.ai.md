This is a refactoring patch that simplifies integer parsing in the config_get_expiry_in_days() function. René Scharfe replaces git_parse_signed() with git_parse_int() since the function was effectively already using int-range values (by passing maximum_signed_value_of_type(int) as the max parameter). 

The change involves two related adjustments: demoting the "days" variable from intmax_t to int to match git_parse_int()'s signature, while promoting the "scale" constant to intmax_t to maintain the same arithmetic behavior when multiplying with days. The patch is small (3-line diff) and focused, touching only config.c.

The commit message clearly explains the motivation - using the simpler git_parse_int() makes the code shorter and clearer, since it was already effectively operating within int bounds. The change appears straightforward with no obvious behavioral impact, though reviewers might want to verify the arithmetic safety of the type changes (particularly ensuring the int can't overflow when multiplied by the scale).
