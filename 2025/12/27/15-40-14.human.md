Bugfix for a receive-pack crash when handling symrefs that point outside their namespace. 

Troels Thomsen fixes a segmentation fault that occurs in `receive-pack` when processing a push that updates both a symbolic reference and its target, where the symref is in a namespace but points to a ref outside that namespace. The crash happened because the code was stripping namespace prefixes before checking for aliased updates, causing a NULL dereference when the target ref wasn't in the same namespace.

The solution changes the approach by building a list of fully qualified ref names (including namespaces) rather than stripping namespaces first. This preserves the existing consistency checks while preventing the crash. The patch includes a new test case that verifies the fix works for symrefs pointing outside their namespace.

The change is relatively straightforward - it modifies the ref list construction in `check_aliased_updates()` to include namespaces and removes the problematic `strip_namespace()` call. The fix appears well-contained and comes with appropriate test coverage, addressing a clear edge case in the namespace handling logic.
