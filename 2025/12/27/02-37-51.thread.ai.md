Bug report from Hadmut Danisch about Git unexpectedly modifying directory permissions, specifically the SGID bit (mode 2770). The issue occurs when cloning into directories configured for shared access by a system user running rootless Podman containers. Git currently overwrites the SGID bit during repository operations despite this being a legitimate use case for shared group access.

Core problem: Git's directory creation and maintenance code does not preserve special permission bits like SGID, which breaks workflows requiring fixed directory permissions. The existing `core.fileMode` option is documented as being for filesystem compatibility rather than permission preservation. Current workaround involves using a post-pull hook to manually reset permissions.

Technical context: affects Git 2.43.0 on Ubuntu 24.04.3, specifically with directory mode 2770 (group writeable with SGID). The issue likely extends to other special permission bits beyond SGID. Reporter suggests adding a configuration option to specify which permission bits Git should preserve during directory operations.

This touches Git's low-level filesystem interaction code, particularly around repository directory creation and maintenance. The behavior appears to be an oversight in permission handling rather than an explicit design choice. No maintainer response or proposed solution yet.
