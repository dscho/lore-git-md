Bugfix discussion about error message formatting in batched reference updates. Jeff King responds to Karthik Nayak's agreement on attaching detailed error messages to specific ref updates in machine-readable output, pointing out potential redundancy issues in the current error message construction.

The core issue is that the human-readable error strings (like "cannot update ref 'foo': trying to write non-commit object...") contain redundant refname information when propagated through multiple layers of the ref transaction code. When these verbose messages get attached to machine-readable output, they become unwieldy due to duplicate refname mentions.

King identifies that write_ref_to_lockfile() includes the refname in its error message, while its caller lock_ref_for_update() also prepends the refname, creating unnecessary verbosity. He suggests this could be cleaned up by auditing callers to ensure consistent refname handling, but cautions that such refactoring should be done carefully.

For the immediate regression fix, King proposes a pragmatic approach: initially restoring the old behavior of sending detailed errors to stderr rather than machine-readable output, with potential cleanup of the machine-readable format to follow later. This would quickly address the regression while allowing more time to design a clean solution for machine-readable output.
