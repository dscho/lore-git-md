This is a bug report about Git's handling of directory permissions, specifically the SGID bit. The reporter describes a real-world use case where they need a Git repository directory to maintain special group permissions (2770 mode with SGID set) to allow access by a system user running a container. However, Git currently strips these permissions during operations like `clone`.

The issue appears legitimate - Git shouldn't unnecessarily modify directory permissions that serve a functional purpose beyond basic access control. The reporter has found a workaround using hooks but suggests a more elegant solution could be adding configuration to preserve certain permission bits.

This seems like a reasonable feature request that could benefit others with similar multi-user or containerized workflows. The report is clear and well-motivated, though it might need input from Git maintainers about whether there are security implications to preserving these bits by default. The proposed solution of a bitmask configuration is interesting but would need technical review.
