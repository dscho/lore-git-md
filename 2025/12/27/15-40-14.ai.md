This is a bugfix for receive-pack that addresses a crash when handling symbolic refs that point outside their namespace. The patch comes with a new test case demonstrating the fixed scenario.

The issue occurs in `check_aliased_update_internal()` when processing symbolic ref updates. The function was stripping namespace prefixes from ref names to detect when a symref and its target are being updated in the same push, but this could return NULL for out-of-namespace symrefs, leading to a segfault. The fix changes the approach to work with fully-qualified ref names (including namespaces) throughout the check, which both prevents the crash and maintains the intended consistency checking behavior from previous commits.

The patch modifies `builtin/receive-pack.c` to build a list of fully-qualified ref names using `get_git_namespace()`, and adds a new test in `t/t5509-fetch-push-namespaces.sh` that verifies pushing to a symref pointing outside its namespace works correctly. The changes appear well-contained and focused, with the test providing clear validation of the fix. The commit message references two prior commits (ded8393610 and da3efdb17b) that relate to this functionality, showing awareness of the historical context.
