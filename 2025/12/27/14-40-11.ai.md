This is a continuation of the thread about Git's handling of directory permissions, specifically the SGID bit. Hadmut Danisch responds to Randall Becker's suggestion about using ACLs, firmly rejecting it as a solution to the core problem.

The key technical point in this response is that ACLs don't propagate to new subdirectories, unlike the SGID bit which automatically applies the parent directory's group to new items. Hadmut maintains that this makes ACLs unsuitable for their container workflow needs where consistent group permissions are required throughout the directory tree.

The tone is somewhat frustrated, emphasizing that proposed solutions need to actually address the specific behavior of SGID propagation that the original use case depends on. This keeps the focus on whether the Git project should modify its directory creation behavior to preserve special permission bits, rather than relying on external mechanisms.

No new technical solutions are proposed in this email - it primarily serves to reject one alternative approach while keeping the original issue open. The thread remains in a state where the fundamental question persists: should Git change its behavior for special permission bits like SGID, or are the use cases better handled outside Git?
