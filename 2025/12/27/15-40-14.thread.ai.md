Bugfix for receive-pack crash when handling symbolic refs pointing beyond their namespace, with ongoing discussion about namespace isolation implications. Original patch from Troels Thomsen modified `check_aliased_update_internal()` in `builtin/receive-pack.c` to work with fully-qualified ref names (including namespaces) rather than prematurely stripped namespaces, preventing NULL dereferences when checking symref updates. Added test case in `t/t5509-fetch-push-namespaces.sh` verifies push to symref with out-of-namespace target succeeds without crashing.

Junio Hamano acknowledges the crash fix but questions whether allowing updates to symrefs pointing outside their namespace violates namespace isolation principles, suggesting explicit denial of cross-namespace symref updates. Troels Thomsen responds with design considerations: symrefs require explicit creation on the receiving side, implying intentional cross-namespace links; update hooks could enforce stricter policies if needed; the long-standing bug (since 2016) suggests namespace/symref combinations are rare; and while making behavior configurable is possible, the use case may not justify it. Troels leans toward preserving the current permissive post-fix behavior while acknowledging hooks could enforce stricter policies.

Junio Hamano continues the discussion, emphasizing security concerns: accidental cross-namespace symrefs could lead to unintended access violations, framing this as a tradeoff between flexibility (allowing intentional cross-namespace links) and safety (preventing misconfigurations that might bypass namespace protections). The exchange crystallizes two perspectives: Troels views the permissive behavior as reasonable given symrefs' explicit nature, while Hamano suggests stricter validation might be warranted to prevent security issues. The discussion remains at policy level without new implementation proposals.
