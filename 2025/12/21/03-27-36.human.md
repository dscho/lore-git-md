This is a minor style nit in the submodule gitdir path encoding series. Junio Hamano points out a tab character used where a space should be in an error message from patch 4/11 of Adrian Ratiu's series. While the series itself (which introduces runtime configuration for submodule paths) has already been acked for merging, Junio notes this as a general whitespace formatting issue that could be caught by a new lint rule.

The observation is that the error message contains a tab between "errors like" and the backtick-quoted text, when it should use a regular space. Junio suggests this could be detected by a whitespace checker looking for tabs in the middle of sentences (specifically tabs not at standard tab stops). He references a previous discussion about similar whitespace issues, though notes his column-counting may be off by one in this case.

This is purely a code style comment that doesn't affect the functionality of the submodule path encoding feature. The main series remains approved, with this being a small polish item that could be addressed separately.
