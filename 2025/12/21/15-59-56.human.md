This is a feature patch introducing a new configuration option `checkout.remoteBranchTemplate` to customize how Git resolves remote branch names during DWIM (Do What I Mean) operations like checkout and push with auto-setup.

The patch by Pasteley Absurda adds a printf-style template system where `%s` represents the branch name, allowing users to define patterns like "feature/%s" or "user/%s". When checking out "foo" with this template set, Git will look for "origin/feature/foo" rather than just "origin/foo". The same template applies when pushing with `push.autoSetupRemote` enabled.

The implementation touches several commands (`checkout`, `worktree`, `push`) and includes comprehensive tests covering template expansion, edge cases like literal % characters, and interaction with existing features like `checkout.defaultRemote`. The documentation clearly explains the new config option and its relationship with related features.

The change appears well-considered with thorough test coverage (162 new lines in t2024-checkout-dwim.sh alone) and clear documentation updates. This could be particularly useful for teams using prefix-based branch naming conventions on remotes while preferring unprefixed names locally.
