This is the v4 cover letter for the hook subsystem refactoring series, completing the conversion of all remaining Git hooks to the new `hook.h` API. The series standardizes hook execution across Git, enabling future work on config-based hooks and parallel execution.

The v4 iteration focuses on code cleanup and readability improvements based on prior review feedback. Key changes include:
- Simplified callback data passing by using `pp_task_cb` directly for hook state
- Added helper functions for parallel process child state checks (GIT_CP_WORKING, etc.)
- Removed stale comments and improved API documentation clarity
- Maintained all prior functionality including stdin feeding and output capture

The series now consists of 11 patches (3 from Adrian Ratiu, 8 from Emily Shaffer) touching core hook execution in `run-command.c`, individual hook conversions in `receive-pack.c`, `transport.c`, and other callers, plus test updates. All technical concerns from v3 reviews have been addressed, with only minor documentation tweaks remaining.

This represents the completion point for hook standardization, with all major hook types (pre-push, post-rewrite, reference-transaction, receive-pack) now using the structured API. The changes preserve backward compatibility while providing the infrastructure needed for future parallel execution support. CI tests confirm the stability of all conversions.
