This is part 8 of an 11-part series refactoring Git's hook subsystem to use a structured API, focusing on output handling for parallel processes. The patch adds a new `consume_output_fn` callback to `struct run_process_parallel_opts`, allowing callers to capture and redirect child process output that would normally go to stderr. This is particularly useful for server-side hooks that need to relay output to clients over a transport layer.

The implementation provides several key features:
- Output is passed to the callback via strbuf, avoiding the need for temporary pipes
- Callbacks receive empty strbufs periodically, enabling keepalive mechanisms
- A BUG() assertion prevents invalid combinations with the existing `ungroup` option
- Test coverage demonstrates output diversion to files

The change maintains backward compatibility by defaulting to the existing stderr behavior when no callback is provided. The patch has already received sign-offs from multiple core contributors (Emily Shaffer, Ævar Arnfjörð Bjarmason) and appears well-integrated with the broader hook refactoring effort. The test case shows the functionality working as expected with no output leakage to stderr.

This continues the series' trend of thoughtful API design with clear use cases in mind, though some readers may want to review the interaction between output capturing and the parallel execution model more closely.
