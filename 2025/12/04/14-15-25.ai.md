This is a refactoring patch that introduces helper functions for parallel process child state management, part of a larger hook subsystem modernization series.

The patch extracts the anonymous struct tracking child process state into a named `parallel_child` type and adds the first helper function `child_is_working()` to check if a child process is active. This replaces repeated direct state comparisons with more readable function calls. The change affects several functions in `run-command.c` that manage parallel processes, including output buffering, cleanup, and scheduling.

The helper function provides a clearer interface for checking the `GIT_CP_WORKING` state, which is used to determine if a child process is still executing and needs management. This is foundational work for the hook API conversions that follow in the series, where parallel execution state tracking becomes more complex with the addition of stdin feeding and output capture capabilities.

The change is mechanical and focused on code organization rather than behavior modification. It follows the pattern suggested by Junio Hamano during earlier review rounds, indicating this is addressing prior feedback. The patch maintains all existing functionality while making the state checks more explicit and easier to maintain.
