Hook subsystem refactoring (part 11/11): Final receive-pack hook conversion

This patch completes the multi-part series standardizing Git's hook subsystem by converting receive-pack's hooks to use the new structured API. The changes follow the established patterns from earlier conversions, with a few receive-pack-specific considerations.

The main change replaces the custom hook-running code with calls to `run_hooks_opt()`, using a new `feed_receive_hook_cb` callback that batches ref updates in groups of 500 lines to maintain performance. The patch also preserves receive-pack's sideband output capability through the `hook_output_to_sideband` callback.

This conversion provides the same benefits as earlier parts of the series: eliminating manual signal handling, removing direct `child_process` management, and preparing for future config-based hook specification. The implementation appears thorough, with proper handling of edge cases like EPIPE errors and careful memory management.

As the final technical conversion in the series, this patch demonstrates the API's ability to handle receive-pack's unique requirements while maintaining backward compatibility. The changes have been reviewed by multiple core contributors and show clean integration with the established patterns from earlier conversions.
