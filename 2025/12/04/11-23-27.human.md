This is a follow-up discussion in the ongoing thread about parsing utilities and test infrastructure improvements. Patrick Steinhardt responds to Jeff King's patch that changes the return type of parsing functions from `int` to `bool` for clearer semantics.

The change makes the functions' success/failure returns more intuitive by using `bool` (true/false) rather than the current `int` (1/0) which is opposite Git's usual convention. Patrick agrees this is a sensible improvement that will help avoid confusion, noting he's personally been tripped up by the current API.

While the patch itself is straightforward (just changing return types in parse.h and parse.c), Patrick suggests adding documentation comments to these functions while making the change. This would help clarify their behavior for future users. The discussion remains collaborative, with both developers focused on improving API clarity and usability.

This is a small but worthwhile refinement to the larger parsing utilities work, showing attention to detail in making the interfaces more intuitive. The suggestion to document the functions while changing them is particularly thoughtful, as it would help prevent the very confusion Patrick experienced.
