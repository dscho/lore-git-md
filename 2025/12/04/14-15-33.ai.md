Hook subsystem refactoring (part 9/11) - output capture capability.

This patch adds the final major piece to the hook API modernization series by exposing output capture functionality through a new `consume_output_fn` callback in `struct run_hooks_opt`. The change allows server-side hooks to redirect output (which would normally go to stderr) for processing elsewhere, such as sending over sideband channels.

The implementation is straightforward, plumbing the existing `consume_output` field from `run-command.c` through the hook API. The hook.h documentation explains the purpose and references test-run-command.c for implementation examples. This completes the parallel execution capabilities started in earlier patches, joining the existing stdin feeding (`feed_pipe_fn`) and process management features.

As with other parts of this series, the change maintains backward compatibility while adding new functionality. The patch has already received sign-offs from key reviewers (Emily Shaffer and Ævar Arnfjörð Bjarmason) and fits cleanly into the established pattern of the hook API conversions. The simple diff (9 lines total) suggests this was a well-planned incremental change rather than a late addition to the series.

Key technical details:
- Adds `consume_output` field to `struct run_hooks_opt`
- Plumbs the callback through to `run_processes_parallel()`
- Documents the feature with reference to test implementation
- Maintains existing behavior when callback is NULL
- Completes the output handling side of the parallel execution API

This appears to be the last functional piece needed before the final polishing patches in the series (parts 10-11). The change addresses the original series goal of supporting server-side hook use cases while maintaining flexibility for other output handling needs.
