This is part 8 of an 11-part series refactoring Git's hook subsystem to use a structured API, focusing on output handling capabilities for parallel processes.

The patch introduces a new `consume_output_fn` callback in `run-command.c` that allows callers to capture and redirect the collated output of parallel processes rather than having it written directly to stderr. This is particularly useful for server-side hooks that need to relay output to clients over a network transport. The callback receives output in a strbuf, eliminating the need for temporary pipes or files.

Key technical changes:
- Adds `consume_output` field to `struct run_process_parallel_opts` with associated callback type
- Modifies `pp_output()`, `pp_buffer_stderr()`, and `pp_collect_finished()` to use the callback when present
- Enforces mutual exclusivity between `ungroup` and `consume_output` modes with a BUG() assertion
- Includes test coverage demonstrating output diversion to a file
- Maintains backward compatibility by falling back to stderr when no callback is provided

The implementation handles edge cases like empty output buffers (allowing for keepalives) and properly manages the output buffer lifecycle. The test case verifies that output can be redirected to a file while leaving stderr empty.

This builds on previous work in the series that established parallel execution infrastructure and stdin handling capabilities, completing another configuration option for the parallel execution API. The changes are well-contained and maintain the established patterns of the hook modernization effort.
