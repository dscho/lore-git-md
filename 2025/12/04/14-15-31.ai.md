This is part 7 of an 11-part series refactoring Git's hook subsystem to use a structured API. The patch focuses on making the parallel execution behavior more flexible by allowing callers to control the `ungroup` option when running hooks.

The change addresses a limitation where `run_hooks_opt()` was hardcoding `ungroup=1`, which prevented sideband reading of collated output from child hooks (as sideband reading requires grouped output). The patch adds a new `ungroup` field to `struct run_hooks_opt` while maintaining the default ungrouped behavior for existing APIs (`run_hooks()` and `hook run` command) via explicit settings in those codepaths.

Key technical changes:
- New `ungroup` bitfield in `struct run_hooks_opt` to control parallel process output grouping
- Maintains backward compatibility by explicitly setting `ungroup=1` in `run_hooks()`, `run_commit_hook()`, and `builtin/hook.c` codepaths
- Adds documentation comments explaining the ungrouping behavior assumptions for each API

The change is relatively straightforward but important for hook output handling flexibility. It follows the series' pattern of making the hook execution more configurable while preserving existing behavior where needed. The patch includes clear documentation and maintains the series' high standard of backward compatibility considerations.
