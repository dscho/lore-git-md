Feature patch in the hook subsystem refactoring series, adding output capture capability for server-side hooks.

This is part 9 of an 11-part series modernizing Git's hook infrastructure. The patch introduces a new `consume_output` callback in the hook API, allowing callers to capture and redirect hook output rather than having it always print to stderr. This is particularly useful for server-side hooks where output needs to be sent over sideband channels.

The change is minimal but important - just exposing the existing `run_parallel_processes()` capability through the hook API. The commit message notes this is specifically for server-side use cases, though the implementation is general. The patch includes clear documentation of the new field in `hook.h` and references test examples.

As with the rest of the series, this appears well-considered and properly integrated. It follows the established pattern of the refactoring by exposing parallel execution capabilities through the new hook API while maintaining backward compatibility.
