This is part 2 of an 11-part series refactoring Git's hook subsystem to use a standardized parallel execution API. The patch introduces stdin handling capabilities to `run_processes_parallel()`, enabling efficient streaming of large inputs to child processes without buffering everything in memory.

The change adds a new `feed_pipe_fn` callback to `struct run_process_parallel_opts` that gets called repeatedly to feed data to child processes' stdin pipes. The implementation handles pipe buffering, error conditions (including EPIPE when children close stdin early), and proper cleanup. New helper functions `child_is_ready_for_cleanup()` and `child_is_receiving_input()` help manage process state transitions.

The patch includes comprehensive test coverage demonstrating the stdin feeding mechanism works correctly across multiple parallel processes. A key aspect is the SIGPIPE handling - the parent ignores SIGPIPE globally while letting individual feed callbacks handle write errors appropriately.

This infrastructure will be used by subsequent patches in the series to convert specific hooks (like pre-push and receive-pack) to the new parallel API while maintaining their existing stdin processing requirements. The implementation appears robust, with clear state management and thorough test coverage of edge cases.
