This is part 10 of an 11-part series modernizing Git's hook subsystem, converting the receive-pack update and post-update hooks to use the new structured hook API. The patch focuses on output handling, particularly for sideband transmission.

The changes replace direct `child_process` management with the new `run_hooks_opt` API, simplifying the code by removing manual hook path lookup and process setup. A key addition is the `hook_output_to_sideband` callback that properly routes hook output to the sideband channel when needed, using the `consume_output_fn` mechanism introduced earlier in the series.

The conversion maintains all existing behavior while removing about 40 lines of boilerplate code. The update hook now takes its arguments via `strvec_pushl`, and both hooks benefit from centralized sideband handling through the new callback. This continues the series' pattern of standardizing hook execution while preserving backward compatibility.

As with previous patches in the series, this appears well-considered and mechanically sound. The changes are focused and clearly explained, with sign-offs from key reviewers. Being the 10th in a mature series, it represents the final stages of a thorough refactoring effort that has already addressed all major design concerns.
