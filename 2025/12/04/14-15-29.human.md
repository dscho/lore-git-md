This is part 5 of an 11-part series refactoring Git's hook subsystem to use a new structured API. The patch converts the pre-push hook implementation in transport.c from direct `run-command` usage to the new `hook.h` API.

The key changes include:
- Replacing the custom child_process` setup with a `run_hooks_opt` structure
- Moving the ref filtering and stdin writing logic into a new `pre_push_hook_feed_stdin` callback
- Simplifying error handling by leveraging the API's built-in EPIPE/SIGPIPE management
- Maintaining all existing behavior while removing manual signal toggling

The conversion follows the pattern established in earlier parts of the series, using the new stdin feeding mechanism via callbacks. The patch handles all pre-push hook cases (various rejection statuses, peer refs) while being more maintainable than the original implementation.

This appears to be a well-executed conversion that builds on the series' prior work. The changes are focused and the commit message clearly explains the motivation. With multiple sign-offs from key contributors and no outstanding review comments, this looks ready for inclusion.
