This is part 3 of an 11-part series refactoring Git's hook subsystem to use a new structured API, with a focus on adding stdin handling capabilities for parallel execution.

The patch introduces a callback mechanism (`feed_pipe_fn`) for incrementally feeding stdin to hooks, as an alternative to the existing `path_to_stdin` file-based approach. The key technical additions are:

1. A new `feed_pipe` callback in `struct run_hooks_opt` that allows streaming data to hooks without filesystem involvement, particularly useful for large inputs like ref lists during pushes. The callback receives context via `feed_pipe_ctx` and maintains state across calls via `feed_pipe_cb_data`.

2. Strict BUG() assertions enforcing mutual exclusivity between the file-based and callback-based stdin approaches to prevent misuse.

3. Plumbing to pass the callback data through the parallel execution infrastructure via `pp_task_cb`, simplifying access for hook implementations.

4. Documentation in hook.h explaining the callback's purpose, memory management responsibilities, and access patterns for the context pointers.

The changes build on part 2's parallel stdin handling infrastructure while maintaining backward compatibility. The implementation shows careful attention to memory safety and clear API contracts, with Ævar Arnfjörð Bjarmason's sign-off indicating review of the callback mechanism. This is a well-motivated change that enables more efficient hook execution for large inputs while keeping the existing file-based approach working unchanged.
