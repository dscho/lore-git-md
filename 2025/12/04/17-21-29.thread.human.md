This thread explores performance optimizations for handling promisor objects in packfiles, particularly for partial clone scenarios where large promisor packs can cause significant overhead. The original issue was that promisor object initialization was unnecessarily parsing all objects (including blobs), leading to major performance bottlenecks.

Aaron Plattner initially proposed skipping full parsing for blob objects, achieving dramatic improvement (76 minutes down to 2 minutes). Patrick Steinhardt then contributed memory efficiency improvements. Jeff King refined the approach further by leveraging commit-graphs with a flag-based solution (PARSE_OBJECT_SKIP_HASH_CHECK), cutting the time to just 49 seconds.

The latest discussion confirms an edge case where OBJ_NONE-typed objects (created during promisor pack processing) were bypassing the optimization path. Plattner and King agree these should be treated like OBJ_BLOB objects in the type check, yielding a small but worthwhile improvement (2 minutes to 1:58 in Plattner's tests). The discussion also revealed that environmental factors like commit-graph availability can significantly affect performance, with Scalar clones sometimes hitting pathological cases that this optimization helps address.

The consensus favors King's flag-based approach with the added OBJ_NONE handling. Plattner plans to submit a v2 patch incorporating these changes, which should provide robust performance improvements while maintaining correctness across all edge cases. The optimization is valuable for partial clone workflows, especially in environments where commit-graphs might not always prevent slowdowns.
