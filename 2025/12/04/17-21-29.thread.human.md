This thread explores performance optimizations for handling promisor objects in partial clone scenarios, where the current implementation unnecessarily parses all objects (including blobs) when building the oidset. Aaron Plattner's initial patch reduced processing time for a linux.git test case from 76 minutes to 2 minutes by skipping full parsing of blob objects. Patrick Steinhardt then extended this with memory efficiency improvements.

Jeff King has now demonstrated a superior approach using `parse_object_with_flags()` with `PARSE_OBJECT_SKIP_HASH_CHECK`, which leverages the commit-graph when available. His implementation further reduces the processing time to just 49 seconds for the same test case while also being more maintainable through reuse of existing infrastructure. This approach handles both blobs and commits more efficiently - avoiding blob loading entirely while benefiting from commit-graph optimizations for commits. Jeff has provided concrete timing data validating the improvements and notes that users may need to generate commit-graphs to see the benefit.

The discussion has evolved from Aaron's initial solution through Patrick's memory management refinements to Jeff's current proposal, which appears strictly better. The only remaining consideration is whether to retain the original type-check optimization as a fallback for environments without commit-graphs. The thread has attracted attention from key contributors in related areas (Patrick Steinhardt on ODB abstraction and Taylor Blau on commit-graph infrastructure), but no objections have been raised to Jeff's approach.
