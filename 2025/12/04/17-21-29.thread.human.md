This thread introduces a performance optimization for handling promisor objects in partial clone scenarios. The patch addresses a significant bottleneck where Git was unnecessarily fully parsing every object (including blobs) when initializing promisor objects from large pack files. The key insight is that blobs don't reference other objects, so their full parsing isn't required to determine promisor status.

The change modifies `add_promisor_object()` in packfile.c to first check the object type using `odb_read_object_info()`, skipping full parsing for blobs while maintaining the existing behavior for trees, commits and tags. The performance impact is dramatic - the example shows a reduction from 76 minutes to under 2 minutes when processing a 176GB promisor pack. This optimization will particularly benefit users working with large partial clones where promisor packs are common. The patch appears well-constructed with clear performance measurements and maintains correctness while eliminating unnecessary work.
