Performance optimization for promisor object handling. This patch addresses a significant performance bottleneck when initializing promisor objects from large pack files. Currently, `add_promisor_object()` fully parses every object (decompressing and hashing it) when building the set of promisor objects, which is unnecessary for blobs since they don't reference other objects.

The change introduces a type check using `odb_read_object_info()` before parsing, allowing blobs to be added to the oidset without full parsing. The performance impact is dramatic - the example shows a reduction from 76 minutes to under 2 minutes for a repository with a 176GB promisor pack. The patch maintains correctness since blobs don't need to be parsed to determine their promisor status, while trees/commits/tags still get fully parsed as before.

Key technical details:
- Modifies `packfile.c`'s `add_promisor_object()` function
- Uses `odb_read_object_info()` for lightweight type detection
- Only skips parsing for `OBJ_BLOB` type objects
- Maintains existing behavior for other object types
- The optimization is particularly important for partial clone scenarios with large promisor packs

The patch appears well-constructed with a clear performance justification and includes before/after timing measurements. The change is focused and doesn't appear to introduce any new edge cases or complexity.
