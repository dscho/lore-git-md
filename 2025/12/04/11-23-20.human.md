This is a follow-up discussion in the ongoing thread about buffer-safe parsing utilities and clar test framework improvements. Patrick Steinhardt responds to Jeff King's patch introducing new parsing functions for non-string buffers.

Patrick suggests unifying the naming convention for parsing functions, proposing that `strtol_i()` could eventually become `parse_<type>()` and `git_parse_int()` could become `parse_<type>_with_units()`. He agrees with Jeff's choice of using boolean return values for error handling rather than the syscall-style convention.

The more substantive feedback questions whether the new parsing functions should preserve `strtol()`'s behavior of skipping leading whitespace, suggesting this may be an undesirable legacy behavior. He also echoes Phillip Wood's earlier suggestion about wrapping `cl_invoke()` calls in a macro to reduce test boilerplate.

This continues the productive technical discussion around both the parsing utilities themselves and the test framework improvements needed to support them. Patrick's feedback is constructive and focused on API design consistency and test ergonomics, without blocking the current series.
