This is a follow-up in the ongoing discussion about making `git replay` drop commits that become empty during replay. The patch author Phillip Wood responds to feedback from Elijah Newren, agreeing to add a paragraph break in the commit message and confirming that using a temporary variable for `result->tree` assignment is indeed the better approach. 

The technical discussion reveals that the test verification could be simplified by directly checking branch states rather than reconstructing them with sed, and Phillip acknowledges this would be cleaner than the current `--ref-action=print` approach used to match existing tests. 

The exchange shows the patch is nearing final form with only minor documentation and test improvements remaining. Both maintainers (Junio C Hamano) and other contributors (Elijah Newren) have endorsed the core behavior change, suggesting this RFC may soon be ready to graduate from experimental status. The remaining open question about potentially adding an option to retain empty commits appears non-blocking at this stage.
