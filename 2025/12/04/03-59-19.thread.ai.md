Bug report about Windows drive-letter remotes in copied repositories, with discussion of multiple Windows-specific solutions. The issue occurs when a Git repo with local path remotes (e.g., `X:\path\to\repo`) is copied to another drive (e.g., `Z:`), causing clones to still reference the original drive letter. Torsten Bögershausen initially proposed UNC paths (\\server\share format) as a solution, with Git internally converting forward slashes to backslashes. Konstantin Khomoutov confirms Git's behavior of preserving exact remote paths is working as designed, and suggests two additional Windows-specific solutions: NTFS junction points (mounting drives at folder paths) and the `mountvol` command. 

The thread now presents three Windows filesystem approaches to avoid the issue: UNC paths, junction points, and mountvol - all without requiring Git changes. The core tension remains between user expectation (wanting remotes to adjust when repositories move) and Git's design principle of faithfully recording exactly what was specified. No Git changes are proposed; the discussion is documenting existing Windows filesystem features that can prevent the problem. The issue remains Windows-specific, affecting users with local path remotes moved between volumes.
