Bug report about Windows drive-letter remotes in copied repositories, with Torsten Bögershausen proposing UNC paths as a solution. The issue occurs when a Git repo with local path remotes (e.g., `X:\path\to\repo`) is copied to another drive (e.g., `Z:`), causing clones to still reference the original drive letter. This can lead to accidental modifications in the wrong location. The reporter provided a verified recovery procedure: adjust remote path, fetch, stash changes, hard-reset to remote branch, and verify history. Torsten Bögershausen confirms that UNC paths (\\server\share format) can be used as an alternative to drive-letter paths (Z:\path) for local remotes on Windows, with Git internally converting forward slashes to backslashes when handling these paths. This workaround doesn't require Git changes but educates about existing functionality that could prevent the issue. The core question remains whether Git should avoid storing absolute drive letters in remotes to prevent this Windows-specific pitfall, with UNC paths now presented as a viable alternative approach. The issue affects Windows users with local path remotes that get moved between volumes.
