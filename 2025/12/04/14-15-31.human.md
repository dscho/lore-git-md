Hook subsystem refactoring (part 7/11): Adding flexibility to output grouping behavior.

This patch in Adrian Ratiu's hook modernization series introduces a new `ungroup` option in the `run_hooks_opt` struct, allowing callers to control whether child hook processes' output should be grouped. Previously this was hardcoded to ungrouped output (ungroup=1), which caused issues when sideband-reading collated output from child hooks since these features are mutually exclusive.

The change maintains backward compatibility by keeping ungroup=1 as the default in existing APIs (`run_hooks()` and the "hook run" command), with comments noting these could be modified if future use cases arise. The patch touches four files - adding the new field in hook.h, propagating it through hook.c, and documenting the current behavior in builtin/hook.c and commit.c.

This appears to be a straightforward addition that addresses a real limitation in the hook API while preserving existing behavior. The patch is well-contained and follows the established pattern of the series, with clear documentation of the new flexibility and thoughtful consideration of backward compatibility.
