This is part 6 of an 11-part hook subsystem refactoring series, focusing on converting the reference-transaction hook to the new structured hook API. The patch replaces direct `run-command` usage with the new hook infrastructure, eliminating manual child process setup and signal handling.

The key technical change introduces a `transaction_hook_feed_stdin` callback that processes one ref update per invocation, writing the hook's stdin in the format `<old-value> <new-value> <refname>`. The callback handles all OID formatting cases (null OIDs, symbolic refs, regular OIDs) while maintaining the existing filtering of `REF_LOG_ONLY` updates. The conversion preserves all existing behavior while removing explicit pipe management and SIGPIPE handling, which are now handled by the hook API infrastructure.

The patch follows the established pattern from earlier conversions in the series, using a `feed_pipe_ctx` to pass the transaction and a task-specific `feed_cb_data` struct to track progress through the ref updates. Memory safety is maintained through proper strbuf initialization and cleanup. The implementation demonstrates the hook API's ability to handle streaming input generation without temporary files, though the commit message notes the current one-ref-per-callback approach could be optimized with batching if needed.

This conversion completes the major hook type migrations in the series, with all prior review feedback on memory safety and API design already addressed in previous iterations. The change is well-contained to `refs.c` and maintains backward compatibility while removing several dozen lines of manual process management code.
