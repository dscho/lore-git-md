Follow-up discussion on the git_mkdtemp() implementation in the security hardening series.

Chris Torek points out a minor but potentially confusing aspect of René Scharfe's patch that introduced `git_mkdtemp()` as part of eliminating insecure `mktemp(3)` usage. The issue centers on the shared implementation between `git_mkstemps_mode()` (which returns a file descriptor) and the new directory-creation path (which returns a success/failure status). While functionally correct, the reuse of the `fd` variable for both cases could mislead future maintainers into thinking the directory creation returns a file descriptor needing closing.

This is a small code clarity observation in an otherwise completed series that has already received Reviewed-by tags and consensus. The thread shows the careful attention to detail typical of Git's security-related changes, even for what Torek calls a "fairly trivial" point. The suggestion to add a clarifying comment would help prevent any future misunderstanding without requiring code changes, maintaining the series' goal of providing secure, maintainable replacements for unsafe tempfile operations.
