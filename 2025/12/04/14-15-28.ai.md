This is part 4 of an 11-part series refactoring Git's hook subsystem to use the new `hook.h` API. The patch converts the post-rewrite hook implementation in sequencer.c from direct `run-command` usage to the structured hook API.

The key technical changes in this specific patch:
- Replaces manual child process setup with `run_hooks_opt()` which handles SIGPIPE toggling automatically
- Introduces a new `pipe_from_strbuf` callback function that writes the old/new OIDs to the hook's stdin via the feed_pipe mechanism
- Maintains the same functionality (passing "amend" as argument and OID pairs via stdin) but with less boilerplate code
- Uses the series' standard pattern of storing stdin data in a strbuf passed via `feed_pipe_ctx`

The conversion follows the pattern established in earlier parts of the series, using the new parallel execution infrastructure while maintaining backward compatibility. The change is straightforward and well-contained, with proper cleanup of the strbuf and no behavior changes beyond the internal implementation details.

This patch has already been reviewed and signed off by multiple contributors (including Emily Shaffer and Ævar Arnfjörð Bjarmason) in previous iterations, suggesting the approach is sound. The v4 version appears to be a straightforward application of the now-well-established hook API conversion pattern from earlier parts of the series.
