This is part 11 of the hook subsystem refactoring series, converting receive-pack's receive hooks to the new structured hook API. The patch focuses on the `run_receive_hook()` function and related helpers, replacing manual process management with the standardized API while maintaining all existing functionality.

Key technical changes:
- Replaces direct `child_process` management with `run_hooks_opt` API calls
- Implements batched stdin feeding via `feed_receive_hook_cb()` callback, processing 500 lines at a time to maintain performance (addressing a degradation seen with single-line callbacks)
- Maintains sideband output capability through `hook_output_to_sideband()` callback
- Preserves all existing environment variable setup (push options, cert info, tmp_objdir)
- Keeps the same skip_broken refs behavior and push certificate handling (now via `prepare_push_cert_sha1()` adapted for hook API)
- Properly manages memory with strbuf` cleanup and explicit freeing of callback data

The conversion follows established patterns from earlier parts of the series while addressing receive-pack's specific needs for batched input processing. The changes demonstrate the API's flexibility in handling both streaming input (via batched callbacks) and specialized output handling (sideband support). This completes the major hook conversions in the series, with all core hook types now using the structured API.
