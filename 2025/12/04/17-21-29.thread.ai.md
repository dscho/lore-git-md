Thread identity: Performance optimization for promisor object handling in packfiles, focusing on partial clone scenarios with large promisor packs.

Core problem: Current promisor object initialization unnecessarily parses all objects (including blobs) when building the oidset, causing significant performance overhead for large packs. Since blobs don't reference other objects, their full parsing is redundant for promisor tracking.

Key technical details:
- Modifies `add_promisor_object()` in `packfile.c` to use `odb_read_object_info()` for type detection
- Skips full parsing for `OBJ_BLOB` objects while maintaining full parsing for trees/commits/tags
- Demonstrates dramatic improvement (76min -> 2min) on a 176GB promisor pack
- Maintains correctness since blob parsing isn't needed for promisor tracking
- Particularly impactful for partial clone workflows

Current status: Initial proposal showing clear performance benefits with no apparent downsides. No reviews or objections yet. The change is focused and well-justified with concrete measurements.
