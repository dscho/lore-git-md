Thread identity: Performance optimization for promisor object handling in packfiles, focusing on partial clone scenarios with large promisor packs.

Core problem: Current promisor object initialization unnecessarily parses all objects (including blobs) when building the oidset, causing significant performance overhead for large packs. Since blobs don't reference other objects, their full parsing is redundant for promisor tracking.

Key technical details:
- Original patch (Aaron Plattner) modified `add_promisor_object()` in `packfile.c` to use `odb_read_object_info()` for type detection, skipping full parsing for `OBJ_BLOB` objects
- Patrick Steinhardt's follow-up introduced `add_promisor_object_data` struct to carry repository context and oidset, enabling commit buffer cleanup via `free_commit_buffer()`
- Jeff King's response suggests using `parse_object_with_flags()` with `PARSE_OBJECT_SKIP_HASH_CHECK` as alternative approach that leverages commit-graph optimizations
- Benchmark improvements: original 76min -> 2min (Aaron's approach), further reduced to 49s (Jeff's approach) when commit-graph available
- Jeff notes test case needs adjustment to properly trigger promisor checks via synthetic OID method
- Maintains all functionality while focusing on the primary CPU optimization
- Preserves static initialization pattern while making repository context explicit
- Particularly impactful for partial clone workflows

Current status: Core performance optimization proven effective across multiple approaches. Jeff King's suggestion provides further refinement by integrating with commit-graph optimizations when available. The changes remain focused on promisor pack handling without broader architectural implications.
