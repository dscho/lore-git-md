Thread identity: Performance optimization for promisor object handling in packfiles, focusing on partial clone scenarios with large promisor packs.

Core problem: Current promisor object initialization unnecessarily parses all objects (including blobs) when building the oidset, causing significant performance overhead for large packs. The discussion has refined multiple optimization approaches to reduce both CPU and memory usage while maintaining correctness, with recent focus on edge cases in the type-checking logic.

Key technical details:
- Original patch (Aaron Plattner) modified `add_promisor_object()` to skip full parsing for `OBJ_BLOB` objects using `odb_read_object_info()` (76min -> 2min improvement)
- Patrick Steinhardt introduced `add_promisor_object_data` struct for repository context and commit buffer cleanup
- Jeff King's refined approach uses `parse_object_with_flags()` with `PARSE_OBJECT_SKIP_HASH_CHECK`, leveraging commit-graph (2min -> 49s improvement)
- Aaron Plattner identified and Jeff King confirmed an issue where `OBJ_NONE`-typed objects bypass optimization path in `parse_object_with_flags()`
- Both agree the type check should include `OBJ_NONE` alongside `OBJ_BLOB` since both represent unparsed objects that could be blobs
- Performance impact of this fix is modest (2min -> 1:58) compared to larger gains from earlier optimizations
- Environmental differences (commit-graph availability) may explain performance variations between test setups
- Maintains all functionality while optimizing both CPU and memory usage
- Preserves static initialization pattern with explicit repository context
- Particularly impactful for partial clone workflows with large promisor packs

Current status: Jeff King's flag-based approach with commit-graph integration remains the most performant solution (49s), with consensus that the `OBJ_NONE` edge case should be addressed in the type checking logic.
