Thread identity: Performance optimization for promisor object handling in packfiles, focusing on partial clone scenarios with large promisor packs.

Core problem: Current promisor object initialization unnecessarily parses all objects (including blobs) when building the oidset, causing significant performance overhead for large packs. Since blobs don't reference other objects, their full parsing is redundant for promisor tracking.

Key technical details:
- Original patch (Aaron Plattner) modified `add_promisor_object()` in `packfile.c` to use `odb_read_object_info()` for type detection, skipping full parsing for `OBJ_BLOB` objects
- Patrick Steinhardt's follow-up introduces `add_promisor_object_data` struct to carry repository context and oidset, enabling commit buffer cleanup via `free_commit_buffer()`
- Maintains all functionality while adding memory efficiency
- Demonstrates dramatic runtime improvement (76min -> 2min) on 176GB promisor pack
- Preserves static initialization pattern while making repository context explicit
- Particularly impactful for partial clone workflows

Current status: Initial performance optimization proven effective, now extended with memory efficiency improvements. Both patches appear technically sound but need verification in large-repository scenarios. The changes remain focused on promisor pack handling without broader architectural implications.

Open questions: None raised yet regarding core approach, though real-world testing needed to verify memory savings. Reviewers may want to check edge cases around buffer management and repository context handling.
