This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. The implementation enables faster status operations by watching filesystem events rather than scanning the working directory.

The patch represents the fourth iteration of this work, addressing feedback from previous PRs while fixing newly discovered issues. Key technical details include using inotify with recursive directory watching, maintaining bidirectional watch descriptor mappings, handling directory renames via event cookies, and detecting remote filesystems. The implementation shows thorough attention to edge cases and includes extensive testing.

Two small memory leaks remain (512-byte during daemon initialization and 40-byte in IPC client handling) that need resolution before merging. The patch has undergone significant stress testing with various filesystem operations and appears stable aside from these known leaks. Documentation is updated to cover Linux-specific considerations like inotify watch limits.

The changes since v3 focus on fixing a crash during rapid nested directory creation and adding more stress testing. This appears to be a well-crafted contribution that has been carefully refined through multiple review cycles, with only minor memory leaks remaining as open issues.
