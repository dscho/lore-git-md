Bugfix for fsmonitor daemon memory leak.

This is a follow-up to Paul Tarjan's patch fixing a memory leak in Git's fsmonitor daemon client handling code. René Scharfe provides a brief review, agreeing with the overall approach but questioning whether an interrupted thread would actually reach the cleanup section. The original patch addressed two issues: using the wrong khash cleanup function (causing a 40-byte leak per request) and performing cleanup mid-function rather than in the dedicated cleanup section.

The changes are minimal (5 lines modified) and well-contained to the fsmonitor daemon's client handling code. While the impact is small (40 bytes per request), the fix properly addresses the leak by using the correct khash cleanup function (`kh_destroy_str`) and moving the cleanup to the unified cleanup section. The thread shows no major objections to the technical solution, though René raises a minor question about thread interruption behavior that doesn't appear to affect the validity of the fix.

The patch appears ready for merging as it cleanly resolves a definite memory leak while maintaining existing functionality. The discussion is wrapping up with only this minor clarification point remaining.
