This is a test fix targeting flaky fsmonitor test case. Paul Tarjan addresses intermittent failures in the fsmonitor event tests (edit/create/delete/rename operations) that were occurring due to timing races between the daemon writing events and the test checking for those events.

The patch introduces a new `retry_grep()` helper function that repeatedly attempts a grep operation with a 5-second timeout, waiting for expected events to appear in the trace file. This replaces the previous approach of using `test-tool fsmonitor-client query` as a delay mechanism. The change is applied consistently across all event-checking tests in t7527-builtin-fsmonitor.sh.

The fix appears well-motivated by actual CI failures and follows a pattern already established in lib-git-p4.sh. The implementation is straightforward and touches only the test file, making it a low-risk change that should improve test reliability.
