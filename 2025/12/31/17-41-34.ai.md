This is a feature patch implementing Linux support for Git's filesystem monitoring (fsmonitor) using inotify, bringing Linux to parity with existing Windows and macOS backends. It's the fourth iteration of this work (v4), addressing feedback from previous PRs and fixing newly discovered issues.

The implementation enables faster status operations by watching filesystem events rather than scanning the working directory. Key technical details include:
- Uses inotify with recursive directory watching via inotify_init1(O_NONBLOCK)
- Special handling for directory renames through IN_MOVED_FROM/TO event cookies
- Maintains bidirectional watch descriptor <-> path mappings using hashmap
- Detects and rejects remote filesystems (NFS/SMB) via statfs() unless explicitly allowed
- Falls back to $HOME/.git-fsmonitor-* for IPC socket when .git is remote

The patch adds build configuration via FSMONITOR_DAEMON_BACKEND=linux and FSMONITOR_OS_SETTINGS=linux, requiring pthreads and Unix domain socket support. It also documents inotify watch limits and expands fsmonitor.socketDir support to Linux.

Changes since v3 include fixes for rapid creation of nested directories where the daemon could crash, along with extensive stress testing. The patch addresses all previously identified issues except for two remaining memory leaks (512-byte during daemon startup and 40-byte in IPC worker thread) that need resolution before merging.

The implementation shows thorough attention to edge cases with comprehensive test coverage, including the fsmonitor test suite plus manual verification on local/remote filesystems. It represents a complete and well-reviewed solution that has undergone multiple iterations to address all raised concerns except for the two remaining leaks.
