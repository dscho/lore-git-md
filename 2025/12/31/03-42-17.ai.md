This is an RFC patch addressing a user experience issue in `git format-patch` when handling merge commits. The patch proposes adding a warning when merge commits are skipped during patch generation, as the current silent behavior can be surprising to users, particularly those using merge-heavy workflows like those encouraged by `jj`.

The change modifies `builtin/log.c` to remove the hardcoded `max_parents=1` limit and instead explicitly checks for merge commits (those with multiple parents) to issue a warning before skipping them. The warning includes the commit hash of the skipped merge. The author acknowledges this might need refinement - suggesting it could be made conditional (perhaps via config) and wonders if including the commit subject would be useful context.

Key technical details for future reference:
- Modifies the revision walking in `cmd_format_patch()`
- Introduces a new `warning()` call when encountering merge commits
- Uses `commit->parents->next` to detect merges (multiple parents)
- Includes the commit OID in the warning via `oid_to_hex()`

The author explicitly marks this as RFC quality, noting it lacks tests and proper configuration options, and invites feedback on the approach before submitting a more complete version. The change is motivated by a report from Julien Moutinho about unexpected behavior when using `jj` workflows.
