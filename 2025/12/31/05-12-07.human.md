Maintainer response on merge commit warnings in `git format-patch`

Junio Hamano responds to Dominique Martinet's RFC about warning users when `git format-patch` skips merge commits. The current behavior silently ignores merges (commits with multiple parents), which can surprise users of merge-heavy workflows like Jujutsu VCS.

Hamano suggests the warning might be appropriate only when *no* commits are formatted from a non-empty range - this would catch cases where users might genuinely unaware of the skipping behavior. However, he cautions against warnings in the common case where users intentionally format a topic branch containing back-merges from trunk, as these warnings would just be noise for an expected workflow.

The response indicates the maintainer sees value in the warning concept but wants to avoid false positives in normal usage. This suggests any final implementation would need careful consideration of when to trigger warnings, possibly with configuration options or heuristics to distinguish "probably unexpected" cases from normal merge-heavy workflows. The thread continues to explore the right balance between visibility and quiet operation.
