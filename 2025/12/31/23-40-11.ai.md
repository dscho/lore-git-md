This is a test fix targeting flaky fsmonitor event tests. The patch addresses race conditions in t7527-builtin-fsmonitor.sh where grep checks for filesystem events could fail because the fsmonitor daemon hadn't finished writing them to the trace file yet.

The solution introduces a new `retry_grep()` helper function that repeatedly attempts a grep with a 5-second timeout, waiting for the expected event to appear. This replaces the previous approach of using `test-tool fsmonitor-client query` as a delay mechanism. The helper is applied consistently across all event-checking tests in the file (edit, create, delete, rename, directory operations).

The changes are mechanical but thorough - 24 lines removed (mostly the query calls) and 27 added (the new helper and its calls). The commit message notes this was prompted by an actual CI failure, suggesting the flakiness was observed in practice rather than being theoretical. The implementation follows a similar pattern to `retry_until_success` from lib-git-p4.sh, indicating it's using established patterns for test reliability.
