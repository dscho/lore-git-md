Bugfix addressing a memory leak in Git's fsmonitor daemon client handling. This is version 2 of a patch that fixes improper cleanup of a khash table used for pathname deduplication in `do_handle_client()`.

The key change is switching from `kh_release_str()` to `kh_destroy_str()` to properly free both the hash table's internal arrays and the struct itself, fixing a 40-byte leak per client request. The patch also moves the cleanup to the unified cleanup block and initializes the pointer to NULL for safety.

Compared to v1, this version simplifies the commit message by dropping an incorrect claim about thread interruption handling, focusing just on the core memory leak fix. The change is small (5 lines) and well-contained to the fsmonitor subsystem. The technical approach appears sound, and the thread discussion indicates the fix is nearly ready for merging, with only minor questions remaining about cleanup section placement.
