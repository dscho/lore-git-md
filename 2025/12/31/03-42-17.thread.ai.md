Updated AI thread summary:

RFC patch proposing to improve `git format-patch` behavior with merge commits by adding warnings when they are skipped. Currently, format-patch silently skips merge commits (those with multiple parents) due to its hardcoded single-parent limitation, which can surprise users of merge-heavy workflows like those used with `jj` (Jujutsu VCS).

The patch modifies `builtin/log.c` to:
1. Remove the implicit `max_parents=1` limitation
2. Explicitly detect merge commits via `commit->parents->next`
3. Issue warnings using `warning()` when skipping merges, including the commit OID via `oid_to_hex()`

Key developments:
- Junio Hamano suggested warnings should be context-sensitive - useful when no commits are formatted (user might expect output) but noisy in workflows intentionally including merge-heavy ranges (like `trunk..mytopic` with back-merges)
- Jeff King (Peff) identified and fixed a segfault risk in the original implementation - root commits (no parents) would crash when dereferencing `commit->parents->next`. His fix adds a null check for `commit->parents` first.

Open questions:
- How to distinguish "empty output" cases (warnings useful) vs "partial output with skipped merges" (warnings annoying)
- Whether to make warnings conditional on empty output or add configuration options
- Should warnings include commit subject in addition to OID
- Needs test coverage for both warning scenarios and root commit handling
- Proper option handling for any new warning controls

Current positions:
- Original goal: make merge-skipping more visible
- Junio's concern: avoid spam in established workflows
- Peff's contribution: ensure technical correctness for all commit types

The solution will need to balance visibility with workflow compatibility while maintaining robust handling of edge cases. The change preserves the fundamental behavior of not generating patches for merge commits, just making the skipping more visible when appropriate.
