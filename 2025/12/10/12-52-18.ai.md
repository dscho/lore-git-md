This is a bugfix patch for MIDX (multi-pack index) handling, specifically around determining the preferred pack when no reverse index exists. It's the first patch in a v2 series focused on MIDX performance optimizations during repacking.

The patch fixes a `BUG()` that occurs when `midx_preferred_pack()` tries to access a non-existent reverse index. The issue stems from incorrect error handling in `load_midx_revindex()` - the function was only checking for negative return values, but needs to check for any non-zero return (including positive error codes indicating no reverse index exists). The fix changes the condition and adds documentation clarifying the return values.

A new test case verifies the behavior when trying to determine the preferred pack without a bitmap (which would mean no reverse index). The test would have triggered the `BUG()` before this fix. The test also confirms proper behavior when a bitmap is present.

This appears to be a straightforward and well-tested fix for a clear edge case in MIDX handling. The patch builds on prior MIDX work and has already incorporated feedback from Taylor Blau in previous iterations. The changes are minimal (2 lines of functional code changes plus documentation and tests) and focused on the error handling issue.
