This is the seventh patch in Patrick Steinhardt's v2 series refactoring Git's object database alternates handling as part of the broader ODB abstraction effort. The patch focuses on adapting alternates reading to work through the ODB source interface rather than direct path operations.

The key change renames `read_info_alternates()` to `odb_source_read_alternates()` and modifies it to accept a `struct odb_source` parameter instead of a raw path string. This better aligns with the series' goal of abstracting alternates handling through source operations. The function now uses `source->path` internally rather than receiving the path as a parameter, and all call sites are updated accordingly.

The patch continues the series' pattern of moving implementation details behind the source abstraction layer, which will eventually support pluggable backends with different alternates storage mechanisms. Changes are mechanical and maintain existing behavior while improving the architectural separation between parsing alternates and operating on paths directly.

This follows positive review of the approach in v1 from Justin Tobler, who had previously suggested naming improvements that were incorporated into v2. The patch builds on the recursion elimination work completed in patch 5/8 and cleanup in 6/8, further simplifying the alternates handling code.
