This thread introduces a new MEMZERO_ARRAY macro to standardize how Git zeroes dynamically allocated arrays, addressing potential uninitialization issues that surfaced in the git-last-modified bug discussion. The initial two-patch series includes both the macro implementation and corresponding Coccinelle rules to automate conversions across the codebase, plus a build system fix for Coccinelle include paths.

Junio Hamano has now reviewed the Coccinelle semantic patch, noting that while the current implementation correctly handles memset() calls with literal 0 or 0x0, it should also catch the common '\0' (null character) notation pattern to be fully comprehensive. This is a focused technical suggestion to improve the automated conversion coverage before the patch series is finalized. The core approach remains sound - this is about making the transition more thorough rather than any fundamental objection.

The series still awaits broader review from Coccinelle experts like René Scharfe, build system maintainers, and subsystem owners for the affected areas (simple-ipc, diff-delta, ewah, hashmap, and pack-revindex). The changes demonstrate conversions in several key files while maintaining compatibility with both Makefile and meson builds, with one noted exception in add-patch.c where pointer arithmetic makes the macro unsuitable.
