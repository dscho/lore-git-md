This thread discusses a two-patch series introducing a new `MEMZERO_ARRAY` macro for type-safe array initialization and updating Coccinelle rules to automate conversions. The series emerged from discussions about uninitialized memory issues in git-last-modified.

The core technical work is progressing well, with consensus forming around the pattern matching approach. Junio Hamano suggested extending the Coccinelle rule to catch `'\0'` patterns, and René Scharfe - a recognized Coccinelle expert - has now confirmed this while also proposing additional improvements: matching `sizeof(ptr[...])` syntax and making the rule more flexible by parenthesizing the size parameter. René noted that `0` already matches `0x0` in current Coccinelle versions, making that explicit pattern redundant.

However, Patrick Steinhardt's earlier concerns about the build system changes in patch 2/2 remain unresolved. He questioned whether the explicit include paths added for spatch analysis are actually needed, since Git's codebase already includes headers relative to the root directory. Junio has acknowledged this concern as valid, but no alternative solution has been proposed yet. The thread now needs input from build system experts to resolve this aspect.

The macro implementation itself hasn't drawn objections, and the demonstrated conversions across multiple files (including last-modified.c, simple-ipc.c, and others) show the utility of the approach. One exception in add-patch.c where pointer arithmetic makes the macro unsuitable has already been noted. With René's input addressing the pattern matching questions, the remaining open items are the build system changes and final reviews from subsystem maintainers for affected areas.
