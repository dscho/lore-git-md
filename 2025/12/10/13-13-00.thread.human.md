This thread introduces a two-patch series aimed at standardizing how Git zeroes dynamically allocated arrays across the codebase. The first patch adds a new `MEMZERO_ARRAY()` macro to `git-compat-util.h` as a type-safe alternative to manual `memset()` calls, complete with overflow protection matching Git's other array utilities. It includes conversions in several subsystems (last-modified, simple-ipc, diff-delta, etc.) and a Coccinelle rule to automate future adoption. The author notes one exception in `add-patch.c` where pointer arithmetic makes the macro unsuitable.

The second patch fixes Coccinelle's include path handling to support the new semantic patch rules, working with both Makefile and meson builds. The series builds on prior memory initialization cleanup efforts and deliberately avoids naming the macro `CLEAR_ARRAY` to prevent confusion with array resizing operations. 

So far the thread has seen only the initial posting from the author, with no reviews yet. The changes appear mechanically sound but would particularly benefit from review by Coccinelle expert René Scharfe and maintainers of the affected subsystems. The standardization effort could help prevent uninitialized memory issues while making the codebase more consistent.
