This thread discusses a two-patch series introducing a new MEMZERO_ARRAY macro for safer array zeroing and updating Coccinelle rules to catch uninitialized memory patterns. The first patch introducing the macro has seen positive feedback, with Junio Hamano suggesting an extension to also match '\0' notation patterns in the Coccinelle rules.

The debate now centers on the second patch's build system changes, which add explicit include paths for Coccinelle analysis. Patrick Steinhardt questioned whether these paths are actually needed, since Git's codebase already includes headers relative to the root directory during normal compilation. Junio has acknowledged Patrick's concerns, implicitly agreeing the justification may be unclear. 

The thread is now at an impasse on this build system question, waiting for either:
1) The original author to defend the include path approach with new technical rationale, or
2) An alternative solution to Coccinelle's type resolution issues that doesn't require modifying the build system.

Key participants so far include the original submitter, Junio (who suggested the '\0' pattern extension), and Patrick (who raised the build system concerns). The series still needs review from Coccinelle experts like René Scharfe and build system maintainers before it can proceed. The core MEMZERO_ARRAY implementation itself appears uncontested.
