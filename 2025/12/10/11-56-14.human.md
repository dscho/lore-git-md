This is a documentation discussion thread about terminology for the `git replay` man page. Junio Hamano responds to Phillip Wood's suggestion about how to describe the `--contained` option's behavior. 

Phillip had proposed using "tip" terminology (like "Update all branches whose tip is replayed") to align with existing Git documentation, while also suggesting the wording should mention "commit" for clarity. Junio agrees with the general approach and offers an alternative phrasing that explicitly mentions commits ("Update all branches that point at commits in the replayed <revision-range>").

The exchange shows the careful consideration being given to making the documentation both technically precise and accessible. This follows earlier discussion where Junio had endorsed the original phrasing, showing the project's iterative approach to documentation wording. The thread remains focused on finding the clearest way to describe branch update behavior without proposing any functional changes to `git replay` itself.
