Bugfix for `git add -p` handling of binary file deletions.

This patch addresses an inconsistency in how `git add -p` processes binary files. While the command already skipped modified binary files (as it can't usefully interact with them), it would incorrectly attempt to process deletions of binary files, leading to an error. The issue occurs because the "deleted file" marker in the diff output was preventing proper detection of the "Binary files" header.

The fix modifies the parsing logic in `add-patch.c` to properly detect binary status even in deletion cases, and then consistently skips all binary files (whether modified or deleted) during the interactive add process. This matches the existing behavior for modified binary files and prevents the confusing error message shown in the reproduction case.

The change is small (6 insertions, 4 deletions) and focused, with a test case demonstrating both the problem and solution. The patch closes a Debian bug report (#1122502) and maintains the expected behavior where `git add -p` will simply report "Only binary files changed" when encountering such cases.

Key technical details for future reference:
- Modifies the `parse_diff()` function in `add-patch.c` to check for "Binary files" header even in deleted file cases
- Updates the binary file skipping logic to ignore all` binary files regardless of hunk count
- Affects the interaction between `file_diff->binary`, `file_diff->deleted`, and `file_diff->hunk_nr` state tracking
- Maintains existing behavior for non-binary files while fixing the binary file edge case
