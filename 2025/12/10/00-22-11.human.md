This is a bugfix patch addressing MIDX (multi-pack index) handling, specifically around determining the preferred pack when a reverse index is missing. The patch corrects error handling in `midx_preferred_pack()` to properly detect cases where the reverse index doesn't exist, which can occur when MIDX doesn't have an associated bitmap.

The issue stems from a mismatch between how `load_midx_revindex()` signals missing reverse indexes (returning a positive error code) and how `midx_preferred_pack()` checks for errors (only looking for negative returns). The fix updates the check to handle any non-zero return value. The patch includes documentation updates clarifying the return value behavior and adds a test case in `t5319-multi-pack-index.sh` to verify the behavior when working without bitmaps.

Taylor Blau confirms the fix makes sense and notes that other callers of `load_midx_revindex()` already handle positive return values correctly. The change is small but important for correct error handling in MIDX functionality, particularly in cases where geometric repacking is used without bitmaps. The patch appears well-considered with appropriate test coverage for the edge case it addresses.
