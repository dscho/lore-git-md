This is a technical follow-up in the ongoing macOS iconv encoding conversion discussion. René Scharfe responds to Torsten Bögershausen's questions about the Homebrew libiconv solution path for the character encoding regression on macOS 15.

Key points confirmed:
- Homebrew's libiconv does support UTF-8-MAC encoding (though with an unusual alias UTF8-MAC)
- The t3910 tests pass with Homebrew's libiconv, except for one known issue with decomposed filenames that was already documented

The email also notes Torsten's observation about existing build switches for MacPorts (`NO_DARWIN_PORTS`) and Fink (`NO_FINK`), with René indicating he'll address Carlo Arenas' related comments about package manager switches in the other thread. This keeps the Homebrew solution path viable while acknowledging the need to consider multiple package manager scenarios in the final implementation.
