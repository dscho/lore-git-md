This is a refactoring and tooling improvement series addressing memory initialization patterns in Git's codebase. The patches stem from a bug found in `git-last-modified` where uninitialized memory caused issues, leading to a discussion about better ways to zero out dynamically allocated arrays.

The first patch introduces a new `MEMZERO_ARRAY()` macro to standardize array zeroing, replacing various ad-hoc `memset()` calls across the codebase. The author chose this name over `CLEAR_ARRAY()` to avoid potential confusion about array resizing. The second patch improves Coccinelle's ability to find and convert these patterns by properly passing include paths to the tool, though notes one tricky case in `add-patch.c` that needs to remain as-is due to pointer arithmetic.

The changes touch several areas of the code including builtins, compat layers, and data structures like ewah bitmaps and hashmap. The series appears well-motivated by a real bug and subsequent discussion, with clean separation between the core change (the new macro) and the tooling improvement (Coccinelle support). The author acknowledges the naming debate but makes a reasonable case for `MEMZERO_ARRAY()`.
