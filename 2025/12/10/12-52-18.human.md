This is a bugfix patch for the MIDX (multi-pack index) subsystem, addressing a `BUG()` that occurs when trying to determine the preferred pack without a reverse index. It's the first of three patches in a series optimizing MIDX handling during repacking.

The patch fixes an issue where `midx_preferred_pack()` would trigger an assertion failure when called on a MIDX without a bitmap (and thus no reverse index). The problem was in the error checking - the code only checked for negative return values from `load_midx_revindex()`, but that function returns a positive error code when the reverse index doesn't exist. The fix changes the condition to check for any non-zero return value.

Patrick Steinhardt includes a test case that verifies the fix by demonstrating the preferred pack cannot be determined without a bitmap, and that the operation fails gracefully rather than hitting the `BUG()`. The patch also improves documentation of `load_midx_revindex()`'s return values.

This appears to be a straightforward and well-tested fix for a clear edge case. The patch builds on prior MIDX optimization work and has already incorporated feedback from Taylor Blau in previous iterations, suggesting it's ready for inclusion.
