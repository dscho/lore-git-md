This is the second patch in Patrick Steinhardt's v2 series refactoring Git's object database alternates handling. The patch moves relative path resolution from the linking phase into the parsing phase of alternates processing.

The key change is relocating the path normalization logic from `link_alt_odb_entry()` (now renamed to `odb_add_alternate_recursively()`) into `parse_alternates()`. This creates a cleaner separation between parsing alternates (which now produces fully-resolved paths) and linking them into the object database. The patch maintains the existing behavior of silently ignoring paths that cannot be resolved, as the later `alt_odb_usable()` check will still catch invalid paths.

The rename to `odb_add_alternate_recursively()` (from Justin Tobler's suggestion in v1 review) better reflects the function's purpose. The changes are mechanical but meaningful - this is part of the larger effort to abstract alternates handling for future object database backends that may not use traditional filesystem paths.

The patch follows logically from the first in the series (which introduced batch parsing of alternates) and sets up for subsequent patches that will further restructure the alternates handling. It's a well-contained change with clear motivation that advances the series' goal of making alternates processing more self-contained and backend-agnostic.
