Refactoring patch from Patrick Steinhardt as part of an 8-part series modernizing Git's alternates handling. This is the first patch in v2 of the series, which restructures how Git parses alternate object database paths without yet solving the deeper architectural issues.

The patch extracts alternates parsing into a new self-contained `parse_alternates()` function that processes entire input strings at once, replacing the previous `parse_alt_odb_entry()` that handled one entry at a time. The new version collects all parsed paths into a `strvec` before processing them, separating the parsing logic from the subsequent linking of alternates into the object database.

While this doesn't yet address the mutual recursion between parsing and linking (which comes later in the series), it's a necessary first step toward cleaner alternates handling. The change is mechanical but important groundwork for the more significant restructuring that follows. The patch maintains all existing functionality while making the code more maintainable.

This v2 version incorporates naming feedback from Justin Tobler received on v1, though the technical changes remain the same. The series as a whole is part of Git's ongoing object database abstraction effort to support pluggable backends.
