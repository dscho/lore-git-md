CI / build system patch fixing Coccinelle include path handling, part of the MEMZERO_ARRAY series.

This second patch in the series addresses a build system issue where Coccinelle semantic patches weren't properly analyzing certain files due to missing include paths. The problem was discovered when the new array.cocci rule from patch 1/2 failed to match a case in builtin/last-modified.c because Coccinelle couldn't resolve types from ewah/ewok.h.

The fix adds explicit include directory flags for both Makefile and meson builds, listing key Git subdirectories (compat, ewah, refs, sha256, trace2, win32, xdiff) where type definitions are commonly found. This ensures spatch can properly analyze struct definitions and type information when applying semantic patches.

The change is straightforward but important for the effectiveness of the Coccinelle rules introduced in the first patch. It maintains consistency between Makefile and meson build systems, and the selected include paths cover the main areas where type definitions are needed for static analysis. The patch doesn't introduce any new functionality - it just fixes the infrastructure to make the semantic patches work as intended.
