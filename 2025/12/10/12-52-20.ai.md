Performance optimization for MIDX handling during geometric repacking. This is the third and final patch in a series that prevents unnecessary MIDX rewrites when the index is already up-to-date, specifically addressing the `--stdin-packs` case used by geometric repacking.

The patch enhances `midx_needs_update()` to properly handle `--stdin-packs` scenarios by comparing the actual pack names rather than just counting packs. Previously, the function would always trigger a rewrite when using `--stdin-packs` even if the resulting MIDX would be identical. The new implementation:
- Creates a string set of basenames for the requested packs (stripping ".pack" suffix)
- Compares against MIDX-tracked pack names (stripping ".idx" suffix)
- Only requires rewrite if the sets differ

The change includes comprehensive tests in t5319 and t7703 that verify MIDX retention behavior with various pack combinations, including edge cases with bitmap indexes. Benchmarking shows this avoids ~3 seconds of unnecessary work during geometric repacks in the Git repository itself.

Key technical details for future reference:
- New `midx_needs_update()` handles three distinct cases: incremental updates, missing MIDX, and pack set comparisons
- Special handling for `.pack` vs `.idx` filename suffixes
- Maintains existing behavior for non-stdin-packs cases
- Adds test helpers `test_midx_is_retained` and `test_midx_is_rewritten`
- Touches midx-write.c primarily, plus test files
- Builds on prior MIDX optimization work by Taylor Blau and Derrick Stolee

The patch appears well-tested and completes the optimization series, with all prior review feedback incorporated. The implementation is careful to maintain existing behavior while adding the new pack comparison logic.
