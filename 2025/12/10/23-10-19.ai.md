This is a brief response in the ongoing thread about macOS iconv issues affecting character encoding conversion in Git tests. Brian M. Carlson supports René Scharfe's proposed solution of using Homebrew's libiconv as a workaround for macOS's broken ISO-2022-JP to UTF-8 conversion in recent versions (15.7.2 and 26.1). The key point is that this approach creates an incentive for Apple to fix their implementation, as their own Git builds (which wouldn't use Homebrew) would continue to fail the t3900 tests. This is a pragmatic endorsement of the Homebrew solution path that's been under discussion, noting how it aligns vendor interests with the need for correct encoding behavior. The email doesn't introduce new technical details but reinforces the strategic value of this approach in the context of Apple's potential response.
