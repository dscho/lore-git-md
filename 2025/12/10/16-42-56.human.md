This is a follow-up in the ongoing macOS iconv conversion issue thread, focusing on build system considerations. Torsten Bögershausen raises several practical questions about René Scharfe's proposed Homebrew-based workaround for macOS's broken iconv implementation.

Torsten asks whether Homebrew's libiconv supports UTF-8-MAC (a macOS-specific Unicode normalization form) and whether it passes the t3910 tests, suggesting these could be important compatibility considerations. He also notes that Git already has build flags for other package managers (NO_DARWIN_PORTS for MacPorts, and another for Fink), and questions whether a similar NO_HOMEBREW flag would be appropriate here.

The email advances the discussion by bringing up real-world deployment concerns that weren't previously addressed - particularly the need to maintain compatibility with existing macOS-specific behaviors and the precedent of similar package manager integration controls. These questions will likely need resolution before the Homebrew approach can be finalized, as they touch on both technical correctness and user flexibility. The thread continues to balance between finding a robust technical solution and maintaining practical compatibility with various macOS development environments.
