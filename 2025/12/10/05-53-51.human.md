This is a follow-up discussion in the ongoing refactoring series for Git's object database alternates handling. Patrick Steinhardt responds to Justin Tobler's architectural concerns about how alternates are represented in `struct object_database`.

The key point here is agreement about a current fragility in the ODB transaction system, where sources get reordered to change write targets. Patrick acknowledges this is "a bit weird" and particularly calls out the transaction reordering behavior as problematic. While he agrees this should be addressed, he notes it's out of scope for the current patch series, suggesting it would be better handled as future work to polish ODB transactions.

This exchange doesn't introduce new code changes but rather confirms an architectural concern that may guide future development. The discussion remains constructive, with both contributors aligned on the existence of the issue but deferring its solution to maintain focus on the current refactoring work.
