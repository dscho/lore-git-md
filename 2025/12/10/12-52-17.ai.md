This is a performance optimization patch series for MIDX (multi-pack index) handling during repacking, building on prior work by Taylor Blau and Derrick Stolee. The series now consists of three patches (expanded from two in v1) to avoid unnecessary MIDX rewrites when the index is already up-to-date.

The first patch (already reviewed and finalized) fixes a `BUG()` when getting the preferred pack from a MIDX without a reverse index, improving error handling in `midx_preferred_pack()`. The key changes involve clearer object position conversion flow and better documentation.

The two new patches refactor MIDX update logic:
1. Extracts a helper function `midx_needs_update()` to centralize the logic for determining when a MIDX rewrite is needed
2. Skips MIDX rewrites with `--stdin-packs` when the existing MIDX already reflects the current pack state, particularly useful for geometric repacking

Notable technical changes in v2:
- Moved skip logic into `write_midx_internal()` to better handle edge cases and leverage existing no-op checks
- Explicitly handles `--stdin-packs` cases by loading MIDX after computing packs
- Drops preferred pack change detection (may be addressed later if deemed important)
- Updates tests to use `git-multi-pack-index` directly

The changes affect midx-write.c, midx.c, pack-revindex.h, and add tests in t5319 and t7703. The series shows technical consensus with Taylor Blau's feedback incorporated, focusing on optimizing repository maintenance operations without introducing new user-facing behavior.
