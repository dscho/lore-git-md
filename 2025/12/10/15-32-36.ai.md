Refactoring patch in Patrick Steinhardt's ODB alternates handling series (v2 3/8). This patch relocates the normalized object directory path computation into the renamed `odb_is_source_usable()` function (previously `alt_odb_usable()`), eliminating redundant parameter passing and aligning with the series' terminology updates.

The key change moves the `strbuf_realpath()` call for computing the normalized object directory path from the caller (`odb_add_alternate_recursively()`) into the callee (`odb_is_source_usable()`). This simplifies the calling code while maintaining the same functionality and error checking. The patch also converts the return type from `int` to `bool` as part of the function rename.

The changes are straightforward mechanical transformations with no behavior modifications:
1. Removes the `normalized_objdir` parameter since it can be derived from the `object_database` parameter
2. Renames function to match the series' "source" terminology
3. Updates all callers to use the new signature
4. Maintains identical error handling and path comparison logic

This continues the series' pattern of separating concerns between parsing/linking phases and modernizing the alternates handling code. The patch builds on the previous two in the series (v2 1/8 introducing `parse_alternates()` and v2 2/8 moving path resolution into parsing) by further cleaning up the alternates usability checking. The changes are consistent with Justin Tobler's positive feedback on the v1 version of this patch series.
