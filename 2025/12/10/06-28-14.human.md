This is a review comment on patch 2/6 of the repo structure enhancement series, focusing on unit formatting in human-readable output. Patrick Steinhardt raises two key points about Justin Tobler's implementation of human-readable count formatting.

First, he suggests the unit strings ("k", "M", "G") should be made translatable, noting they're currently hardcoded constants. This would allow localization of the output for non-English users.

Second, he identifies a potential inconsistency in unit bases - the patch uses decimal (1000-based) units while Git's `parse.c` uses binary (1024-based) units. He notes this is technically incorrect (proper binary units should use "KiB" etc.), but acknowledges it's a common convention. He suggests this might need addressing when disk sizes are added later in the series, where proper binary units would be more important.

The review is constructive and technical, pointing out genuine considerations for the series' implementation. The test change noted at the end appears to be a minor formatting tweak unrelated to the main functionality. This feedback will likely lead to revisions in how units are handled in subsequent versions of the patch series.
