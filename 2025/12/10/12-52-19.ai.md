This is a refactoring patch in the MIDX optimization series, extracting logic to determine when MIDX needs updating into a dedicated function. The change prepares for handling `--stdin-packs` cases in subsequent patches while maintaining the existing optimization that skips MIDX rewrites when packs haven't changed.

The new `midx_needs_update()` function centralizes three key conditions: checking for incremental updates (always requiring rewrite), handling missing MIDX cases (like geometric repacks), and comparing pack counts between current and existing MIDX. The function replaces inline checks in `write_midx_internal()` with equivalent logic, though the commit notes the pack count comparison is currently "somewhat lenient" and will be improved later.

The patch touches only midx-write.c, moving 3 lines of conditionals into a 20-line function with detailed comments explaining each case. This follows the series' pattern of incremental improvements to MIDX handling, building on prior work by Taylor Blau. The change is purely internal - no user-facing behavior modifications - and appears technically sound, with the commit message clearly stating its preparatory nature for the next patch's `--stdin-packs` handling.
