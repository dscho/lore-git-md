This is the final patch in Patrick Steinhardt's v2 series refactoring Git's alternates handling to work through the ODB source abstraction. The patch introduces `odb_source_write_alternate()` to handle writing alternates through the source interface, completing the transition from direct filesystem operations to the new abstraction layer.

The change moves the alternates file handling logic into a new function that operates on an `odb_source` rather than directly on paths. The implementation maintains the same behavior - checking for existing entries, atomic writes via lockfile, and error handling - but now structures it around the source abstraction. The existing `odb_add_to_alternates_file()` becomes a thin wrapper that calls the new function with the primary source.

Key technical points:
- New `odb_source_write_alternate()` takes a source and alternate path
- Handles all file operations (locking, reading existing entries, writing)
- Returns error codes rather than dying on failure
- Preserves existing behavior of skipping duplicates
- Keeps the recursive addition of alternates when the ODB has loaded alternates
- Maintains atomic update semantics via lockfiles

This completes the series' goal of restructuring alternates handling to work through the source abstraction, paving the way for future backend implementations that may handle alternates differently than the traditional filesystem approach. The change is consistent with the series' architectural direction and follows the pattern established in previous patches of moving implementation details behind the source interface.
