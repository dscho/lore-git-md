Refactoring patch in Patrick Steinhardt's ODB alternates handling series (v2 5/8). This patch eliminates mutual recursion between alternates parsing and source addition functions, simplifying the control flow for handling object database alternates.

The key change restructures the recursive alternates processing to remove the mutual recursion between `link_alt_odb_entries()` and `odb_add_source()`. Previously, these functions called each other in a cycle: parsing alternates would trigger source additions, which would then trigger more alternate parsing. The new version makes `odb_add_alternate_recursively()` handle all recursion internally, while `parse_alternates()` becomes a pure parsing function unaware of the recursive context.

Technical changes include:
- Removes `link_alt_odb_entries()` entirely
- Modifies `read_info_alternates()` to output parsed paths via `strvec` rather than processing them directly
- Updates `odb_prepare_alternates()` to use the new non-recursive parsing approach
- Maintains the same depth-checking safety (still limiting to 5 levels of recursion)
- Preserves all existing functionality while making the control flow more linear

This is part of the larger effort to abstract alternates handling through the ODB source interface, preparing for future backend support. The change follows Justin Tobler's positive review of the approach in v1, with Patrick having incorporated naming feedback in v2 (using `odb_add_alternate_recursively()`). The patch keeps the series moving toward its goal of separating parsing from recursive processing, which will be important for the planned source-based backend support.
