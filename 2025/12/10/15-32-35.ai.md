This is the second patch in Patrick Steinhardt's v2 series refactoring Git's alternates handling as part of the ODB abstraction effort. The patch moves relative path resolution from the linking phase into the parsing phase of alternates processing.

The key change relocates path normalization logic from `link_alt_odb_entry()` (renamed to `odb_add_alternate_recursively()`) into `parse_alternates()`. This creates a cleaner separation between parsing alternates (now including path resolution) and linking them into the object database. The patch maintains the same error handling behavior where unresolvable paths are ignored, with validation still occurring in `alt_odb_usable()`.

The renamed `odb_add_alternate_recursively()` function now focuses solely on adding validated alternates to the object database, while `parse_alternates()` handles the input parsing and path resolution. This aligns with the series' goal of making alternates handling more self-contained for eventual integration with the `struct odb_source` abstraction.

The changes appear well-contained and maintain existing functionality while improving code organization. This continues the series' pattern of incremental refactoring steps toward the larger ODB abstraction goal, following positive feedback on the approach from Justin Tobler in v1. The patch builds on the first patch's introduction of `parse_alternates()` while preparing for subsequent changes in the series.
