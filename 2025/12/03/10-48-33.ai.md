Refactoring patch in the `git-history` series, splitting add-patch declarations into their own header.

This is the sixth patch in Patrick Steinhardt's v7 series implementing the `git-history` command. It performs a code organization change by extracting add-patch related declarations from `add-interactive.h` into a new `add-patch.h` header. The motivation is to create clearer subsystem boundaries between the interactive add and patch functionality.

The patch moves:
- The `add_p_opt` struct and its initialization macro
- The `add_p_mode` enum
- The `run_add_p()` function declaration
- Related forward declarations for `struct pathspec` and `struct repository`

This is a straightforward refactoring that doesn't change any behavior, just reorganizes the code to better reflect the actual architecture. The change is minimal and mechanical - declarations are moved verbatim to the new header, and both files are updated to include the new header where needed.

This refactoring supports the larger `git-history` effort by helping prepare the add-patch infrastructure for in-memory operations needed by the history editing commands. The clean separation of concerns will make it easier to modify the patch application logic independently from the interactive selection interface.
