This is a bugfix discussion about `git diff --no-index` showing inappropriate line-ending conversion warnings when used outside a Git repository.

Junio Hamano confirms Kristoffer Haugsbakk's observation that CRLF/LF conversion warnings don't make sense when comparing files outside version control, since these warnings are specifically about Git's working tree behavior. However, he notes that Git's diff machinery still needs to read configuration files (for features like coloring and diff algorithms) even in `--no-index` mode.

The warning originates from `check_global_conv_flags_eol()`, which is called during text conversion. Hamano explores potential fixes but raises several open questions: Should the warning be disabled just for `--no-index`, or more broadly when operating outside a repository? Should it still show when running `--no-index` inside a repository? The discussion suggests this might affect other commands like `git grep --no-index` as well.

The email doesn't propose a specific solution but thoughtfully examines the tradeoffs, indicating this will require careful consideration of Git's behavior both inside and outside repository contexts. The issue touches on how Git's diff functionality balances repository-specific features with its role as a general-purpose diff tool.
