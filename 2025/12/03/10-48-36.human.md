This is a refactoring patch in Patrick Steinhardt's `git-history` series, adding infrastructure support for in-memory index operations in the interactive patch application code. The patch introduces a new `run_add_p_index()` function that allows applying changes to an arbitrary in-memory index rather than always using the repository's main index.

The change is part of the larger effort to enable history editing operations (like `reword` and `split`) that need to work with temporary in-memory indexes. The implementation carefully maintains all existing behavior while adding the new capability, factoring out common logic into `run_add_p_common()` to avoid duplication. The patch includes proper handling of index files, commit parent lookups, and tree diffs needed for the new mode.

This appears to be a well-constructed technical foundation for the history editing features, with clean separation of concerns and no obvious behavioral regressions. The changes are focused and clearly motivated by the needs of the larger series. While not user-visible on its own, this infrastructure will enable more flexible history operations in subsequent patches.
