This is a follow-up discussion on the gitk window layout bugfix series, focusing on sash position preservation during window resizing. Johannes Sixt provides detailed testing feedback on Tobias Boesch's patch, identifying several issues with the current implementation.

The email clarifies that the bug affects both horizontal resizing (not vertical as originally stated) and impacts both upper and lower window panes. Johannes demonstrates a specific problematic sequence with maximize/restore operations that scrambles pane proportions worse than the unpatched behavior. Key technical observations include: the patch enforces minimum widths (30px author pane, 300px between sashes) but may override user preferences, the event handler only binds to one pane, and debug logging reveals questionable proportional scaling logic.

Johannes questions several design choices: why not use panedwindow's native events instead of Configure binding, whether the resize logic should be in a separate procedure, and why minimum widths are only enforced cascadingly. The feedback suggests the current solution may mask rather than fix the underlying proportional resizing bug. No code changes are proposed yet - this is primarily a quality assessment identifying areas needing refinement before the patch can be accepted.
