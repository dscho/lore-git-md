This is a refactoring patch in Patrick Steinhardt's `git-history` series, specifically adding in-memory index patching capabilities to the add-patch infrastructure. The patch introduces a new `run_add_p_index()` function that allows applying changes to an arbitrary in-memory index rather than always operating on the repository's main index. This builds on previous refactoring work that split add-patch declarations into their own header file and introduced new configuration structures.

Key technical changes include:
- New `run_add_p_index()` function that takes explicit `index_state` and `index_file` parameters
- Modified `add_p_state` struct to track both repository and working index state
- Extraction of common logic into `run_add_p_common()` helper function
- Updates to index handling code to use the specified index rather than always using `r->index`
- Special handling when operating on the repository's main index to maintain existing refresh behavior
- New diff-tree based approach for generating patches when working with in-memory indexes

The changes maintain backward compatibility while enabling the new in-memory operation mode needed for the `git-history` command's split functionality. The patch appears well-structured with clear separation of concerns between the new and existing code paths. This continues the series' trend of careful refactoring to support both immediate needs and future extensibility.
