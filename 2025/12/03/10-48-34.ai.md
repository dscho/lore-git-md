Refactoring of the interactive add/patch infrastructure as part of the git-history series.

This patch (7/12 in v7) restructures the configuration handling for interactive commands like `git add -i` and `git add -p`. It introduces a new `struct interactive_options` to hold common configuration parameters that were previously passed via `struct add_p_opt`, and moves color/config handling into a new `struct interactive_config`. The changes affect several builtin commands that use the add-patch machinery (add, checkout, commit, reset, stash).

Key technical changes:
- Splits out `struct interactive_options` from `struct add_p_opt`
- Introduces `struct interactive_config` to centralize color/config handling
- Moves color initialization and config parsing into new `interactive_config_init()`
- Updates all callers to use the new structures
- Maintains backward compatibility with existing command-line options (`--unified`, `--inter-hunk-context`)
- Affects multiple commands: add, checkout, commit, reset, stash

The refactoring is part of the larger effort to share infrastructure between `git-replay` and the new `git-history` command, while also reducing use of `the_repository` global. This particular change focuses on cleaning up the configuration handling before further detangling the interactive add/patch subsystems in subsequent patches.
