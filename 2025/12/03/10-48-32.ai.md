This is the fifth patch in a v7 series introducing the `git-history` command, specifically implementing the "reword" subcommand. The patch adds functionality to rewrite commit messages without checking out the commit, similar to interactive rebase's reword operation but working directly in memory.

The implementation handles several key scenarios:
- Rewriting messages at the tip, middle, or root of a branch
- Preserving working tree and index changes during the operation
- Validating commit reachability and rejecting merges
- Showing proper status information in the editor
- Maintaining original authorship and commit metadata

Technical details include:
- New `cmd_history_reword()` function handling the subcommand
- Uses extracted replay infrastructure (`replay_create_commit()`)
- Implements tree-to-tree diff display via `wt_status_collect_changes_trees()`
- Adds 236 lines of test coverage in t/t3451-history-reword.sh
- Retains original commit author while allowing message editing
- Handles edge cases like empty commit messages

The patch builds on previous infrastructure work in the series while being careful to maintain compatibility with the replay machinery and avoiding `the_repository` usage where possible. The implementation appears thorough with comprehensive test coverage of both happy paths and error cases.
