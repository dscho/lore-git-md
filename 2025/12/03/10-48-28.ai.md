This is an infrastructure patch for the `git-history` command series, adding tree-to-tree diff capabilities to the working tree status machinery. The patch introduces a new function `wt_status_collect_changes_trees()` that compares two arbitrary trees and formats the differences in the same way as working tree changes would be shown. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting code for the upcoming history editing commands.

The implementation wraps existing diff machinery with status formatting callbacks, handling rename detection and other diff options through the existing wt_status configuration. The function will be used by subsequent patches in the series to show changes between commits during history editing operations. This is a foundational piece for the `reword` and `split` subcommands that need to display changes between tree states without involving the working tree or index.

Key technical details:
- New function takes two tree OIDs and a wt_status struct
- Uses same callback mechanism as working tree status collection
- Respects existing rename detection settings from wt_status config
- Maintains consistent formatting with other status output
- Prepares for in-memory index operations in later patches

The change is cleanly scoped and well-motivated as shared infrastructure for the series. The implementation follows existing patterns in the status code while solving a specific need for the history editing functionality.
