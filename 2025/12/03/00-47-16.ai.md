[Security] Ongoing debate about terminal escape sequence vulnerability mitigation in Git's sideband channel.

Brian Carlson responds to Johannes Schindelin's concerns about terminal escape sequence vulnerabilities with a practical demonstration showing the proposed patches don't fully prevent malicious color changes via SSH. His test case uses a fake upload-pack script that successfully changes terminal colors despite the security patches, arguing this demonstrates fundamental limitations in Git's ability to sanitize SSH channel output.

The email highlights several key points of contention: the practical impossibility of fully securing SSH channels while maintaining functionality (particularly for authentication prompts and Windows compatibility), the prevalence of terminal escape sequence usage in real-world systems (including GitHub Actions and pre-receive hooks), and disagreement about whether this constitutes a Git-specific vulnerability versus a broader terminal trust boundary issue.

Carlson pushes back against Schindelin's characterization of prior discussions as "gas-lighting," framing the disagreement as a technical debate rather than personal. He acknowledges the security concerns but maintains that terminal emulators bear primary responsibility for protection, citing legitimate uses of escape sequences like QR code generation and noting many systems already interpret them.

The exchange reveals deeper philosophical divides about security boundaries - whether Git should attempt comprehensive sanitization or rely on terminal emulator hardening - with Carlson's practical demonstration adding concrete evidence that SSH channels may be inherently unsecurable against this class of attacks. The discussion remains technically grounded but exposes tensions about vulnerability assessment and mitigation strategy.
