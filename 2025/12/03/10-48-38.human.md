This is a refactoring patch in Patrick Steinhardt's v7 series introducing the `git-history` command. It modifies the cache-tree infrastructure to support writing arbitrary in-memory indexes as trees, rather than just the repository's main index.

The change is straightforward: the existing `write_in_core_index_as_tree()` function is modified to accept an explicit `index_state` parameter instead of always using `repo->index`. This enables the upcoming `git history split` subcommand to work with temporary in-memory indexes during its operation. The patch updates the single existing caller in `builtin/checkout.c` to pass the repository's index explicitly.

This is a technical change that builds on earlier infrastructure work in the series, particularly the in-memory index patching support added in patch 9/12. The modification is clean and focused, with minimal churn - just 3 files changed with 6 lines added and 4 removed. The commit message clearly explains the purpose and connects it to the larger series' goals.
