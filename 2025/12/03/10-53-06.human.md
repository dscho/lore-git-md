This is the final patch in a security-focused series removing insecure `mktemp(3)` usage from Git. The patch adds `mktemp` to `banned.h`, preventing future use of this deprecated POSIX function that creates predictable temporary filenames vulnerable to race conditions. 

The change follows three preparatory patches that introduced secure alternatives (`git_mkdtemp()`) and removed platform-specific implementations. As noted in the commit message, `mktemp(3)` was removed from POSIX due to security concerns - it checks for filename availability in a way that can be exploited by attackers creating files between the check and actual use.

The series achieves its goal of eliminating all `mktemp` usage while maintaining compatibility, particularly on Windows. This final patch serves as the enforcement mechanism, ensuring no regressions by making `mktemp` calls fail compilation. The change is minimal (3 lines added to `banned.h`) but represents the culmination of a thoughtful security hardening effort that removed 18 lines of code overall while making temporary file handling more robust.
