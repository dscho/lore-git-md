This is an infrastructure patch for the `git-history` command series, adding tree-to-tree diff capabilities to the working tree status machinery.

The patch introduces a new function `wt_status_collect_changes_trees()` that compares two arbitrary trees and formats the changes as if they were staged in the index. While this stretches the working tree status subsystem's original purpose, it avoids duplicating diff formatting logic that will be needed for the upcoming `git-history` command's history editing operations.

The implementation builds on existing diff machinery, reusing the same callback mechanism that `wt-status` uses for working tree changes. It properly handles rename detection and other diff options that may be configured in the status settings. The function signature takes two tree OIDs and a `wt_status` struct to collect the results.

This foundational change enables subsequent patches in the series to show users the changes between commits during history editing operations like `reword` and `split`. The patch itself is straightforward and well-contained, with clear documentation of the new function's purpose. As the first in a 12-part series, it sets up infrastructure without yet implementing any user-facing features.
