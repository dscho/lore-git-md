Performance optimization for `diff-tree` command, completing the series of copy detection improvements across Git's diff commands. This patch extends René Scharfe's earlier work on `diff-index` and `diff-files` to `diff-tree` by introducing a new `keep_fn_t` callback in `struct diff_options` and modifying the tree-diff processing logic.

Key technical changes:
- Adds `keep` callback to `diff_options` (defaulting to new `diff_same()` function)
- Modifies `emit_diff_first_parent_only()` and `emit_path()` in `tree-diff.c` to handle both changed and unchanged file pairs
- Updates callers in `builtin/reset.c` and `diff.c` to use the new callback
- Extends API documentation in `diff.h` and `diffcore.h`

The benchmarks show mixed results - while memory usage drops from ~36MB to ~35MB, the performance impact is neutral (1.00-1.01x speed) in the Linux repo test case. This contrasts with the 1.33x speedup seen in `diff-index`. The patch appears technically sound but the performance benefits may be command-specific or workload-dependent.

This completes the series' goal of optimizing copy detection across all major diff commands, though the `diff-tree` case shows the limitations of the approach when dealing with tree-to-tree comparisons versus index/worktree operations. The implementation maintains consistency with prior patches while handling the additional complexity of `diff-tree`'s callback-heavy architecture.
