This thread documents the completion of a security-focused series that eliminated all insecure `mktemp(3)` usage from Git's codebase, replacing it with a secure `git_mkdtemp()` wrapper. The four-part series, now merged, introduced cross-platform secure directory creation while removing 30 lines of code, including the Windows-specific `mingw_mktemp()` implementation. Jeff King (Peff) provided the final Reviewed-by for the series, which also banned `mktemp(3)` in `banned.h` as part of Git's ongoing security hardening.

The discussion has shifted to follow-up cleanups, particularly around the Windows compatibility layer's `gitmkdtemp()` wrapper. While there's consensus on removing this redundant wrapper, René Scharfe has raised practical concerns about coordinating the changes across Git's multiple build systems (Makefile, meson, CMake). He notes testing limitations and current CMake issues on macOS that complicate immediate removal. Scharfe and Peff are considering two approaches: a minimal cleanup preserving the NO_MKDTEMP configuration knob, or a more comprehensive solution that would eliminate the knob entirely by always using the new `git_mkdtemp()`. The latter would require careful updates to configure.ac and other build files, likely warranting a separate patch series.

Throughout the thread participants have demonstrated Git's characteristic attention to both security and maintainability, with Chris Torek earlier noting a subtle code clarity issue in the implementation. The technical discussion reflects the project's careful approach to build system changes, especially when they impact multiple platforms and security-sensitive code paths.
