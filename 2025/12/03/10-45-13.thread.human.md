This thread documents a security-focused effort to eliminate all usage of the insecure `mktemp(3)` function from Git's codebase, motivated by its POSIX deprecation and known TOCTOU race vulnerabilities. The series introduced a new cross-platform `git_mkdtemp()` wrapper in wrapper.c/h (patch 1/4), then systematically migrated all callers - including the Windows compatibility layer - to use this secure alternative while removing platform-specific implementations (patches 2-3). 

The final patch (4/4) now adds `mktemp` to `banned.h`, preventing any future reintroduction of this deprecated function. The change is minimal (3 lines) but significant as the capstone to this security hardening effort, following Git's pattern of proactively banning unsafe functions like `gets()` even without known exploits. Throughout the series, the implementation carefully preserved Windows compatibility while achieving a net reduction of 18 lines of code. The commit messages clearly explain the security rationale, particularly how predictable temporary filenames could be exploited by concurrent processes. With all callers migrated and the function now banned, this completes the removal of insecure temporary file creation paths from Git's codebase.
