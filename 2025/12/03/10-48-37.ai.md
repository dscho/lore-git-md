This is a refactoring patch in Patrick Steinhardt's `git-history` series, introducing a new `ADD_P_DISALLOW_EDIT` flag to the add-patch infrastructure. The change prepares for the upcoming `git history split` subcommand by allowing callers to disable hunk editing, which would be incompatible with the split operation.

The patch modifies the add-patch subsystem to accept a new flags parameter throughout its call chain, from the public `run_add_p()` and `run_add_p_index()` entry points down to the internal `patch_update_file()` helper. The flag prevents the "edit hunk" option from being shown in the interactive prompt when set. All existing callers are updated to pass `0` to maintain current behavior.

Key technical details:
- New `ADD_P_DISALLOW_EDIT` flag in `add-patch.h`
- Flag propagation through `run_add_p_common()` to `patch_update_file()`
- Conditional suppression of ",e" option in interactive menu
- Updates to all builtin commands using add-patch (add, checkout, reset, stash)
- Maintains backward compatibility with existing callers
- Enables future `git history split` to prevent hunk editing conflicts

The change is part of the broader effort to refactor add-patch for in-memory index operations, building on previous patches that split headers and restructured configuration handling. This continues the series' pattern of incremental infrastructure improvements to support the history editing commands.
