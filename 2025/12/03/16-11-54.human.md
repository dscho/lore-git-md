This is a follow-up discussion in the security-focused series eliminating insecure `mktemp(3)` usage. Jeff King (peff@peff.net) responds to René Scharfe's patch that replaced the Windows-compatibility layer's `gitmkdtemp()` with the new secure `git_mkdtemp()` wrapper.

Jeff agrees with the security improvement but suggests further simplification. He notes that now both `gitmkdtemp()` and `git_mkdtemp()` do the same thing, proposing to eliminate the intermediate wrapper entirely. His first suggestion would remove the compatibility layer's implementation while keeping the build system infrastructure. His more aggressive proposal would completely remove the `NO_MKDTEMP` build knob and always use `git_mkdtemp()`, simplifying the codebase further.

The discussion shows the series is reaching its final polishing stage, with experienced contributors looking for opportunities to streamline the implementation beyond just the security fixes. Jeff's suggestions would remove about 15 more lines of code while maintaining the same security guarantees. This level of scrutiny suggests the changes are being carefully reviewed before the final patch that will ban `mktemp()` entirely.
