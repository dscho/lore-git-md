This is a refactoring patch in Patrick Steinhardt's `git-history` series, specifically focusing on the add-patch subsystem. The patch removes the dependency between `add-patch.c` and the `add-interactive` subsystem by directly managing interactive configuration within `add_p_state` rather than inheriting it from `add_i_state`.

The key technical changes include:
- Replaces the embedded `add_i_state` struct with direct `interactive_config` storage in `add_p_state`
- Updates all color output and configuration references to use the new `cfg` field instead of the old `s` path
- Modifies initialization to call `interactive_config_init()` directly rather than via `init_add_i_state()`
- Maintains identical behavior while simplifying the dependency graph between subsystems

This builds on the previous patch's split of interactive configuration declarations and continues the effort to disentangle the add-patch implementation from add-interactive. The changes are mechanical but thorough, touching nearly all parts of the add-patch implementation that previously relied on the add-interactive infrastructure.

The patch is part of the larger effort to enable in-memory index operations for the history editing commands, with this particular change helping to isolate the add-patch functionality for cleaner integration with the new `git-history` command's requirements.
