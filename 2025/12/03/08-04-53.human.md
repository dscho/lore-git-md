This is a security discussion thread about ANSI escape sequence vulnerabilities in Git's sideband channel, specifically addressing concerns about the scope and effectiveness of the proposed fixes.

Johannes Schindelin responds to Brian Carlson's demonstration showing that the current patches don't prevent escape sequence injection via SSH channels. Schindelin clarifies that the patches specifically target HTTPS scenarios (where malicious servers could pose as trusted ones like github.com), not SSH, arguing that securing one transport is still valuable even if another remains vulnerable. He emphasizes security as a layered approach rather than all-or-nothing.

The exchange reveals a philosophical divide: Carlson questions whether partial HTTPS fixes create a false sense of security given SSH's limitations, while Schindelin maintains that each secured vector reduces overall risk. Schindelin also defends the principle that applications (like Git) should sanitize output rather than relying on terminal emulators to handle malicious input, citing CWE-150 security guidelines.

Notably, Schindelin acknowledges legitimate uses of escape sequences (like QR codes in build outputs) but argues these don't justify delaying security fixes. The tone remains professional despite earlier tensions, with both contributors recognizing each other's technical contributions while disagreeing on implementation philosophy. The thread highlights the complex balance between security hardening and maintaining compatibility with existing workflows.
