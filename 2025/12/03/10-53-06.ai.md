Final patch in security series banning `mktemp(3)` system call. This completes the 4-part effort to eliminate insecure temporary file creation across Git's codebase, following the earlier introduction of `git_mkdtemp()` wrapper and removal of platform-specific implementations. The patch adds `mktemp` to `banned.h`, preventing future reintroduction of this POSIX-deprecated function known for creating predictable filenames vulnerable to TOCTOU races. The commit message clearly explains the security rationale, noting how concurrent processes could exploit the race window between name generation and file creation. 

The change is minimal (3 lines added to `banned.h`) but significant as the capstone to the series' security hardening. It follows Git's pattern of proactively banning unsafe functions even without known exploits, similar to previous bans of `gets()` and `strtok()`. The implementation preserves all existing functionality since the series already migrated all callers to secure alternatives. This represents the final step in removing `mktemp(3)` usage while maintaining cross-platform compatibility through the new wrapper infrastructure introduced earlier in the series.
