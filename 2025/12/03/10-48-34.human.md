This is a refactoring patch in Patrick Steinhardt's v7 series introducing the new `git-history` command. The patch focuses on cleaning up the interactive add/patch infrastructure that will be shared between `git-add` and the new history editing commands.

The main change splits out a new `struct interactive_options` to hold common configuration used by both the interactive add (`git add -i`) and patch (`git add -p`) subsystems. Previously this was handled through a confusing circular dependency where callers passed `struct add_p_opt` which was then used to initialize `struct add_i_state` that was shared by both.

The patch moves color configuration, diff settings, and other interactive options into the new structure while maintaining the same behavior. It's a preparatory step for further detangling of the interactive add/patch code in future patches. The changes are mechanical but improve code organization - over 200 lines are removed from `add-interactive.c` as configuration handling is centralized in the new `interactive_config` functions.

This is part of the larger effort to build shared infrastructure for history editing commands while reducing global state usage. The patch doesn't introduce new functionality but makes the codebase more maintainable for the planned `reword` and `split` subcommands in the series.
