This is a refactoring patch in Patrick Steinhardt's `git-history` series, specifically adding infrastructure support for the upcoming `split` subcommand. The change modifies the interactive add-patch machinery to optionally disable hunk editing, which the new split command needs since editing hunks during a split operation could lead to conflicts.

The patch introduces a new `ADD_P_DISALLOW_EDIT` flag that prevents the "edit hunk" option from being shown in the patch interface. This is a focused change that touches all the add-patch callers (add, checkout, reset, stash) to maintain backward compatibility while adding the new capability. The implementation threads the flag through the call chain while keeping the default behavior unchanged for existing commands.

This appears to be a well-considered change that cleanly extends the add-patch infrastructure without disrupting existing functionality. It's part of the larger effort to build robust history editing tools by properly handling edge cases - in this case, preventing problematic interactions between hunk editing and commit splitting operations. The patch maintains all existing test coverage while enabling the next step in the series.
