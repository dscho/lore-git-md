Bugfix follow-up for gitk's window layout issues. Tobias Boesch provides additional testing instructions for their patch that fixes pane resizing behavior in gitk's history view. The test case involves moving sashes all the way right before closing, then reopening gitk to verify the panes resize properly - simulating a transition from a large to small screen. This builds on their initial patch which addressed two specific problems: sash positions being lost during vertical resizing, and panes becoming unusably small when moving between different-sized displays. The patch itself (sent earlier) adds Tcl/Tk event handling to track sash positions and enforce minimum pane widths. While the code includes debug prints for testing, the author notes these will be removed after review. The changes appear well-motivated by real usability problems, though the thread hasn't yet received review feedback.
