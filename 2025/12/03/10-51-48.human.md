Security patch introducing a secure temporary directory creation function.

This is the first of a 4-part series to replace insecure `mktemp(3)` usage in Git with secure alternatives. René Scharfe introduces `git_mkdtemp()` as a secure replacement for creating temporary directories, building on Git's existing `git_mkstemps_mode()` infrastructure. The new function shares the same secure random generation logic but uses `mkdir(2)` instead of `open(2)`.

The implementation is clean - it refactors the existing temporary file creation code into a shared `git_mkdstemps_mode()` helper that can handle both files and directories, then exposes the new directory-specific variant through the public API. The change is minimal (17 lines net) and maintains the same security properties as the file creation path.

This appears to be a well-considered piece of security hardening, though the commit message could be more explicit about why `mktemp(3)` is problematic (beyond just being deprecated by POSIX). The next patch in the series will presumably start using this new function to replace existing insecure calls.
