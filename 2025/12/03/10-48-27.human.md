This is a feature patch series introducing a new `git-history` command with `reword` and `split` subcommands, building on Git's replay infrastructure. It's the seventh iteration of this proposal, now significantly refined after discussions at the Git Contributor's Summit.

The series adds two key subcommands:
- `reword`: Quickly edit a commit message without checking out the commit (faster than rebase and works with dirty working trees)
- `split`: Split a commit into two parts, with interactive selection of changes to split out

Key improvements in v7 include:
- Shared validation logic between subcommands
- Better commit message handling (now prompts for both messages when splitting)
- Disabled hunk editing in `split` to avoid conflicts (may be re-added later)
- Extensive test coverage (over 400 lines for split alone)
- The implementation uses in-memory index operations for speed
- Current focus is on non-conflicting operations only
- The command is marked as experimental, with clear documentation of limitations

The series appears technically solid with thorough test coverage. While some discussion continues about multi-branch handling, Junio Hamano has suggested merging to 'next' for wider testing. The patch builds on prior work with the replay infrastructure while drawing inspiration from Jujutsu's history editing capabilities.
