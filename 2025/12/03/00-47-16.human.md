This is a security discussion thread about ANSI escape sequence vulnerabilities in Git's sideband channel. Brian Carlson responds to Johannes Schindelin's concerns with a practical demonstration showing that the proposed patches don't fully prevent malicious ANSI sequences from being executed when using SSH. 

Carlson sets up a test with a fake git-upload-pack that sends a color-changing escape sequence, showing it still affects his terminal despite the security patches. He argues that since SSH requires TTY access for authentication prompts and other legitimate uses, completely blocking these sequences isn't practical. He also notes many real-world use cases (like GitHub Actions and pre-receive hooks) rely on some terminal sequences working.

The email highlights a fundamental disagreement about security boundaries - while Schindelin wants Git to sanitize all output, Carlson believes terminal emulators should handle this protection. Carlson pushes back against characterizing the debate as "gaslighting," maintaining it's a technical disagreement while acknowledging Schindelin's contributions.

The exchange shows the security issue remains unresolved, with valid arguments on both sides about where the responsibility for sanitization should lie. Carlson's practical demonstration adds weight to his position that complete protection at the Git level may not be feasible, especially for SSH use cases.
