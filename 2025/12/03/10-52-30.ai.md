This is the second patch in a security-focused series replacing insecure `mktemp(3)` usage. It migrates the Windows-compatibility layer's `gitmkdtemp()` function to use the new `git_mkdtemp()` wrapper introduced in patch 1/4.

The change is straightforward - replacing the old insecure `mktemp()`+`mkdir()` sequence with a single call to the new secure wrapper. The commit message explains the security rationale: the old approach had a TOCTOU race where a file could appear between the `mktemp()` and `mkdir()` calls, while `git_mkdtemp()` handles this safely with retries and avoids the need for an `lstat()` check.

The diff shows a net reduction of 3 lines in `compat/mkdtemp.c` by removing the manual implementation in favor of the shared wrapper. This is part of the series' broader goal to consolidate platform-specific tempfile handling while improving security. The patch maintains the same 0700 permission behavior as the original.

This appears to be a clean mechanical conversion that builds on the infrastructure established in the first patch. The change is focused and well-contained to the Windows compatibility code, with no behavioral changes beyond the security hardening. The series is progressing methodically through the codebase's tempfile usage, and this patch follows that pattern.
