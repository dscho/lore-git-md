Bugfix/feature discussion regarding `git diff --no-index` behavior.

Kristoffer Haugsbakk reports that `git diff --no-index` still shows CRLF-to-LF conversion warnings when comparing files outside a Git repository. The warning appears even though the user is explicitly using Git as a general diff tool without repository context (via `--no-index`), and the files being compared aren't part of any working tree.

The core issue seems to be that the line-ending conversion warning logic isn't properly gated by the `--no-index` flag. When operating outside a repository, these warnings about future Git behavior may be irrelevant since the user isn't working with Git-managed files. The patch suggests this warning should be suppressed or reconsidered in `--no-index` mode.

This appears to be a legitimate usability concern - the warning could confuse users who are just using Git's diff capabilities as a standalone tool. The change would likely involve modifying the diff machinery to respect the `--no-index` flag when deciding whether to show line-ending warnings. No patch is provided yet, but the report clearly explains the unexpected behavior and its context.
