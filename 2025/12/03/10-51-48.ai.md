Security-focused refactoring introducing a secure `git_mkdtemp()` function as part of eliminating insecure `mktemp(3)` usage. This first patch in a 4-part series extends the existing `git_mkstemps_mode()` infrastructure to support directory creation, then exposes it as a new public `git_mkdtemp()` function in wrapper.h. The implementation shares the same secure random suffix generation as the file creation variant but uses `mkdir(2)` instead of `open(2)`. The patch maintains the same permission defaults (0700 for directories) and error handling patterns as the existing tempfile infrastructure. This appears to be a well-contained change that builds logically on existing code, with the actual migration of callers promised in subsequent patches. The diff shows careful handling of the shared code path between file and directory creation cases.
