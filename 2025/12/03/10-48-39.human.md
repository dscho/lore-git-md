This is the final patch in Patrick Steinhardt's v7 series introducing the `git history` command, specifically implementing the "split" subcommand. The patch adds functionality to interactively split a commit into two commits by selecting which changes should move to a new parent commit.

The implementation handles several key scenarios:
- Splitting tip, root, and in-between commits
- Preserving working tree and index state during the operation
- Validating against empty commits (both the split-out and remaining portions)
- Supporting pathspec filtering for partial splits
- Maintaining original authorship information

The command simplifies what would otherwise be a complex rebase-based workflow into a single interactive operation. The patch includes extensive test coverage (452 lines) verifying edge cases like merge commits, empty messages, and hook behavior. It builds on earlier infrastructure patches in the series for in-memory index operations and replay machinery.

This appears to be a well-considered implementation that addresses real workflow pain points while maintaining Git's safety guarantees. The thorough test suite and documentation suggest it's production-ready, though marked as experimental in the docs. As the culmination of a 12-patch series that's received significant review, this looks like a solid contribution to Git's history editing capabilities.
