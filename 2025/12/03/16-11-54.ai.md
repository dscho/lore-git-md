This is a follow-up discussion in the security-focused series eliminating `mktemp(3)` usage, specifically about patch 2/4 which migrated the Windows-compatibility layer's `gitmkdtemp()` to use the new `git_mkdtemp()` wrapper.

Jeff King (Peff) agrees with René Scharfe's security rationale for the change but suggests further simplification. He observes that with `git_mkdtemp()` now always available, we can eliminate the intermediate `gitmkdtemp()` wrapper entirely. He proposes two incremental improvements: first removing the redundant wrapper while keeping the NO_MKDTEMP build knob, then a more aggressive version that removes the knob entirely since `git_mkdtemp()` provides portable implementation.

The changes would remove compat/mkdtemp.c entirely and update various build systems (Makefile, meson, CMake, configure.ac) to reflect the simplified architecture. This continues the series' trend of reducing platform-specific code while maintaining security - the proposed changes would eliminate another 15 lines while keeping the same secure behavior. The discussion shows the maintainers looking for opportunities to further streamline the codebase after the core security work is done.
