This thread addresses a character encoding conversion issue affecting macOS 15 systems, where the system's implementation of iconv fails to properly handle stateful encodings like ISO-2022-JP during buffer growth operations. The problem was first reported by René Scharfe and confirmed by Yee Cheng Chin as specific to macOS 15 (not present in 14.8.2), with Collin Funk providing historical context about Apple's problematic iconv implementation.

The discussion initially focused on two code-based workarounds: René's original approach using an ICONV_BREAKS flag with explicit state resets, and Torsten Bögershausen's alternative using platform detection. Technical analysis showed Torsten's approach was incomplete without state reset handling, as demonstrated by test failures.

René has now proposed a third solution path - using Homebrew's known-good libiconv instead of the system's broken implementation when available. His latest patch modifies the build system to detect and prefer Homebrew's libiconv installation. While this doesn't cover cases without Homebrew, it offers a cleaner solution when the alternative library is present. The thread continues to explore the tradeoffs between these approaches for handling macOS's iconv regression.
