This thread addresses a macOS-specific character encoding issue affecting Git's t3900 tests, where the system's `iconv(3)` implementation fails to properly handle stateful ISO-2022-JP to UTF-8 conversion on macOS 15+. The core technical problem stems from Apple's custom iconv implementation (based on a buggy FreeBSD version) losing state between buffer growth.

After extensive discussion, the maintainer (Junio Hamano) has approved a multi-path solution that prioritizes using Homebrew's libiconv when available (via ICONVDIR), while maintaining fallbacks: René Scharfe's code workaround with state reset, platform-specific detection, and alternative package manager support. The approach is designed to both solve the immediate issue and incentivize Apple to fix their implementation.

The latest email from Junio focuses on documentation cleanup, proposing to update historical references to DarwinPorts (now MacPorts) in the Makefile while preserving backward compatibility. He also raises broader questions about the solution's packaging integration - suggesting expanded documentation to cover MacPorts paths and questioning the practical need for a NO_HOMEBREW flag. This documentation patch represents the final polish on the technical solution that has already reached consensus.
