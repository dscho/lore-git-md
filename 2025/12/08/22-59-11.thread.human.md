This thread addresses a macOS-specific character encoding issue affecting several tests (t3900 tests 17, 25, and 38) due to Apple's problematic iconv(3) implementation for ISO-2022-JP to UTF-8 conversion. The core problem was identified by René Scharfe, with Junio Hamano and Brian M. Carlson confirming the solution path.

The technical solution has converged on three complementary approaches: a code workaround with state reset (René Scharfe), platform-specific detection (Torsten Bögershausen), and package manager integration. The latest patch from René's v4 series implements the Homebrew portion of this solution, introducing version-specific activation (macOS 24+ only) with automatic path detection for both ARM64 (/opt/homebrew) and Intel (/usr/local) architectures while maintaining user override capability via ICONVDIR.

The implementation now includes proper version detection, simplified build variables (USE_HOMEBREW_LIBICONV), and updated documentation. All key technical aspects appear resolved, with the remaining discussion focused on final documentation polish and whether to include MacPorts paths in config.mak.uname. The thread shows clear consensus on the Homebrew approach, with the patch representing the finalized implementation of that component.
