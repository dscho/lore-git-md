This thread addresses a macOS-specific character encoding issue affecting several tests (t3900 tests 17, 25, and 38), where Apple's custom iconv implementation causes problems with ISO-2022-JP to UTF-8 conversion. The discussion has evolved into a broader examination of how Git's build system should handle macOS package managers, particularly Homebrew.

The core technical workaround for the iconv issue remains René Scharfe's state-reset approach, but the conversation has expanded to build system considerations. Junio Hamano has been guiding the architectural decisions, with significant input from René Scharfe, Torsten Bögershausen, and others about how to best support different macOS installation scenarios.

The latest development comes from René, who responds to Junio's clarification about the purpose of HOMEBREW_* variables in the build system. René agrees documentation needs improvement but suggests the current implementation is still somewhat ad-hoc. He proposes a more structured approach using explicit component flags (like USE_HOMEBREW_GETTEXT) rather than the current implicit behavior where setting HOMEBREW_PREFIX affects multiple components. This would provide clearer control for packagers while maintaining backward compatibility.

The discussion continues to balance several concerns: supporting different architectures (ARM vs Intel), accommodating non-standard Homebrew installations, maintaining backward compatibility, and keeping the build system understandable. While the technical solution for the iconv issue is settled, the build system refinements are still being worked out, particularly around how to clearly document and structure the Homebrew-related configuration options.
