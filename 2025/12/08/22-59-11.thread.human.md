This thread addresses a macOS-specific character encoding issue where stateful conversions (particularly ISO-2022-JP to UTF-8) fail during buffer growth operations in Git's `reencode_string_iconv()` function. The problem was first reported by René Scharfe and has been confirmed as a regression in macOS 15's iconv implementation, which stems from Apple's switch to a custom (and historically problematic) iconv variant.

The discussion has produced two validated workarounds: René's original approach using a compile-time `ICONV_BREAKS` flag that forces full-string reconversion during buffer growth, and the alternative of using Homebrew's libiconv. Now Torsten Bögershausen has proposed a modified version of René's patch that makes the workaround Apple-specific and simplifies some implementation details, particularly around state tracking and resetting. While the core issue is clearly a platform regression rather than a Git bug, the thread continues to refine the best way to handle it in Git's code - with Torsten's proposal offering a more targeted approach that might be preferable for maintainability. The technical consensus remains that macOS's iconv implementation is at fault, but the discussion now focuses on choosing between two similar-but-differently-implemented workarounds.
