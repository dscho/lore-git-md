Here's a human-readable thread summary:

The thread discusses a platform-specific issue with character encoding conversion on macOS, where the iconv(3) function fails to properly handle stateful encodings like ISO-2022-JP when growing output buffers. René Scharfe identified the problem through test failures in t3900, which revealed that macOS's iconv implementation loses conversion state between calls when the buffer needs to expand.

The proposed solution introduces a build-time workaround via an ICONV_BREAKS flag that modifies the behavior of `reencode_string_iconv()` in utf8.c. When enabled, this makes the conversion restart completely when growing buffers rather than attempting to continue from the previous state. The patch affects both the build system (adding the new configuration option) and the core conversion logic.

This appears to be a known limitation of macOS's iconv implementation, and the workaround is specifically targeted at this platform quirk. The solution is pragmatic rather than ideal, as it doesn't fix the underlying iconv behavior but provides a reliable way to get correct conversions on affected systems. The thread suggests this issue went unnoticed previously because the author typically compiled Git without iconv support.
