This thread addresses a macOS-specific issue with iconv(3) where stateful encoding conversions (particularly ISO-2022-JP to UTF-8) fail during buffer growth operations in macOS 15, breaking Git's t3900 tests. The problem stems from Apple's switch to a custom iconv implementation based on a buggy FreeBSD version.

René Scharfe originally reported the issue and proposed three solution approaches: a code workaround with state reset, platform-specific detection, or preferring Homebrew's libiconv. Technical analysis confirmed that explicit state reset is essential, and that Torsten Bögershausen's initial alternative approach failed due to missing this reset. The discussion has since expanded to consider architecture-specific Homebrew paths on Apple Silicon systems.

In the latest email, Torsten acknowledges the need for state reset and suggests refinements to René's implementation, including better code organization and raising questions about platform detection scope. While accepting the core technical requirements, he flags some code-level concerns about pointer arithmetic and variable naming. The thread remains focused on finalizing the implementation details, with open questions about whether to combine approaches and how to apply the workaround across different macOS versions.
