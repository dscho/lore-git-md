This thread addresses a macOS-specific character encoding issue in Git's test suite, where macOS 15's system iconv implementation fails to properly handle stateful encodings (like ISO-2022-JP) during buffer growth operations. The problem was first identified by René Scharfe and confirmed as a regression in macOS 15 by Yee Cheng Chin.

Three solution approaches have been under discussion: code-based workarounds (with different platform detection methods), and a build-system approach that prefers Homebrew's libiconv when available. Technical consensus has formed around the need for explicit state resets during conversion and the macOS 15+ specificity of the issue.

The latest contribution from Carlo Marcelo Arenas Belón introduces new considerations about binary compatibility, particularly for universal macOS binaries that might need to use system libraries rather than Homebrew's version. He proposes adding a `NO_HOMEBREW` Makefile flag to give users control over this choice, similar to existing flags for other package managers. This shifts the discussion toward deployment tradeoffs, complementing the existing technical focus on the workarounds themselves.

The thread remains active with multiple viable solutions on the table, now considering both the technical correctness of the fixes and their practical implications for different macOS deployment scenarios. Key participants include René Scharfe (driving the technical solutions), Torsten Bögershausen (providing alternative approaches), and now Carlo Marcelo Arenas Belón (raising packaging concerns). The next steps likely involve weighing these new deployment considerations against the existing technical solutions.
