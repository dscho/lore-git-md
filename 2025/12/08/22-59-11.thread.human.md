The thread discusses a character encoding conversion issue affecting Git's test suite on macOS, specifically when converting between ISO-2022-JP and UTF-8 using iconv(3). René Scharfe originally reported that macOS 15's iconv implementation loses state during buffer growth operations in Git's `reencode_string_iconv()` function. Follow-up testing by Yee Cheng Chin confirmed this is a regression specific to macOS 15, not present in earlier versions, despite Apple having switched from GNU's iconv to their own implementation in macOS 14.

Two workarounds have been identified: a compile-time flag (ICONV_BREAKS) that forces full-string reconversion during buffer growth, and using Homebrew's libiconv instead of the system version. The consensus is that this is a platform regression in macOS 15 not a Git bug.

Collin Funk recently added historical context, sharing that the GNU iconv maintainer has criticized Apple's custom implementation (based on a buggy FreeBSD version with Apple-specific patches). This reinforces that the current test failures are part of a broader pattern of iconv issues on macOS, though the specific regression only appeared in macOS 15. The thread appears to have reached technical consensus, with the remaining question being which workaround to recommend to users.
