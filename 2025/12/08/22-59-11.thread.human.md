This thread addresses a macOS-specific issue with character encoding conversion in Git's test suite, where macOS 15's iconv implementation fails to properly handle stateful encodings like ISO-2022-JP during buffer growth operations. The problem was first reported by René Scharfe and confirmed as a regression in macOS 15 by Yee Cheng Chin, with Collin Funk providing historical context about Apple's problematic iconv implementation.

Three solution approaches have been proposed: René's original compile-time workaround with state reset, Torsten Bögershausen's alternative platform detection method, and a build-system approach that prefers Homebrew's known-good libiconv when available. Technical analysis has established that explicit state reset is essential for correct operation, and Torsten has confirmed this through testing while suggesting refinements to René's implementation.

In the latest exchange, René responds to Torsten's feedback, defending the use of `ICONV_BREAKS` for platform detection (since the issue is macOS 15+ specific) and refining the pointer arithmetic and state reset implementation. While consensus exists on the core technical solution, open questions remain about the cleanest implementation approach and how to handle systems without Homebrew's libiconv. The discussion remains focused and productive, with all participants working toward a robust solution that maintains compatibility across different macOS versions and architectures.
