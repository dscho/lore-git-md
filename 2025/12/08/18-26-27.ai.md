This is a technical review of patch 07/17 in Taylor Blau's MIDX compaction series, focusing on bitmap position handling during MIDX writes. Patrick Steinhardt examines Taylor's change to stop using `pack_perm` when assigning `bitmap_pos` values, which was originally done to handle pack permutations during MIDX writes.

The key technical points are: the patch removes reliance on `ctx->pack_perm` array when setting bitmap positions, instead directly indexing into `ctx->info`. This simplifies the code and avoids potential issues with future compaction work that will wrap `pack_perm` with range-relative indexing. Patrick confirms the current behavior is safe since pack expiration (the only case affecting `pack_perm`) doesn't occur with bitmap-writing operations, though notes this could become fragile if that assumption changes.

The change itself is straightforward - a one-line modification to `midx-write.c` that replaces the permuted index lookup with direct array access. Patrick's review validates the technical rationale while observing the current implementation's safety depends on the invariant that bitmap-writing operations don't expire packs. The patch appears to be a clean preparatory change for the upcoming compaction functionality while making the code more robust against future modifications.
