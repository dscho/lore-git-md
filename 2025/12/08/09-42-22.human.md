This is a follow-up discussion in the submodule path encoding series, specifically addressing build-time configuration options that were previously proposed. Adrian Ratiu responds to Junio Hamano's skepticism about the need for build-time behavior changes, clarifying that the goal is to enable automatic transitions without user intervention.

The email explains that while runtime configuration (via /etc/gitconfig) solves most cases, there remains a need to force-enable `extensions.submoduleEncoding` regardless of local config. Adrian references Josh Steadmon's earlier feedback as motivation for this requirement. For v6 of the series, Adrian plans to implement Patrick Steinhardt's suggestion of a config variable with a build-time default, which would enable automatic migration while maintaining a cleaner implementation.

This discussion represents the final resolution of the build-time configuration debate in this series, with Adrian confirming the approach for v6 that will satisfy both the automation requirements and architectural concerns raised by maintainers. The solution aims to provide a smooth transition path while avoiding manual configuration needs.
