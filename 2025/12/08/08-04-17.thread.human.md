This thread covers Patrick Steinhardt's ongoing work to refactor Git's object database alternates handling as part of the broader ODB abstraction effort. The series aims to modernize how Git processes alternate object stores, moving from direct filesystem operations to a more abstract "source" interface that will eventually support pluggable backends.

The first two patches restructured the alternates parsing logic, introducing `parse_alternates()` to replace the older `parse_alt_odb_entry()` and moving relative path resolution into the parsing phase. The third patch, just posted, continues this cleanup by moving path normalization into the renamed `odb_is_source_usable()` function, eliminating redundant parameter passing and improving encapsulation. 

So far the changes are preparatory refactorings that maintain existing behavior while improving the code structure. The series appears to be following Patrick's established pattern of careful, incremental changes to the object storage layer. No reviews or feedback have been posted yet, but given the technical nature of these changes and Patrick's deep expertise in this area, the patches are likely to be well-received as they move the ODB abstraction effort forward.
