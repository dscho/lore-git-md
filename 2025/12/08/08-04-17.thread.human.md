The series systematically restructures the code, with each patch building on the last: first separating parsing from linking operations, then moving path resolution earlier in the process, eliminating recursive calls, and finally adapting the reading and writing of alternates files to use the new source interface. Justin Tobler has reviewed the approach positively, with some naming suggestions incorporated in v2. The final patch just added introduces `odb_source_write_alternate()` to complete the transition by handling alternates file writing through the source abstraction.

While the technical changes are well-received, there remains an open architectural question about how alternates are represented in the object database structure, particularly regarding write operations and transaction handling. Both Patrick and Justin acknowledge this will need to be addressed in future work, but consider it separable from the current refactoring. The series appears ready for merging, providing cleaner internals that maintain existing behavior while paving the way for more flexible backend implementations.
