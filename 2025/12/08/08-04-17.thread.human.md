Patrick Steinhardt continues his series refactoring Git's object database alternates handling as part of the broader ODB abstraction effort. The eight-patch series systematically replaces direct filesystem operations with a new "source" abstraction layer, paving the way for pluggable backends that may not use traditional filesystem paths. 

The third patch, which moves normalized path computation into the newly renamed `odb_is_source_usable()` function (formerly `alt_odb_usable()`), received positive review from Justin Tobler. He confirmed the relocation of path normalization logic was appropriate since it was only used within that function anyway, and noted a minor documentation typo that could be fixed. This follows Justin's earlier positive review of the first patch and his engagement on naming discussions for the second patch, where he suggested `odb_add_alternate_source()` as a more precise name than the proposed `odb_add_source()`.

The series remains in its first iteration with no substantive technical objections raised so far. The main open question is the naming convention for source-related functions, which Justin has already provided input on. Patrick's systematic approach to restructuring the alternates handling continues the established modernization of Git's object storage layer that both he and Justin have been driving forward.
