Bugfix for `git-last-modified` bitmap initialization, now using a new `MEMZERO_ARRAY` macro. This is version 2 of a patch that fixes incorrect bitmap clearing in the `last-modified` command, where the scratch bitmap wasn't fully zeroed between uses. The original issue was reported by Anders Kaseorg after test failures on s390x (though the bug wasn't endian-specific).

The patch introduces a new `MEMZERO_ARRAY` macro in `git-compat-util.h` that properly calculates the byte count for array zeroing by multiplying the element count by the element size. This replaces a direct `memset()` call in `builtin/last-modified.c` that was passing the wrong size. The macro follows the pattern of existing array helpers like `ALLOC_ARRAY` and `CALLOC_ARRAY`.

Key technical points:
- The fix affects bitmap handling in `process_parent()` where `lm->scratch->words` needs clearing
- Uses `st_mult()` for safe multiplication of element count
- Maintains the same behavior as the original fix but with better encapsulation
- The v2 changes incorporate feedback about the commit message wording and add the new utility macro

The thread history shows this was already reviewed by Jeff King (who suggested potential architectural improvements that weren't taken here) and approved by Junio Hamano for backporting to maint. The new macro approach provides a cleaner solution than the original size-calculation fix while maintaining the same correctness guarantees.
