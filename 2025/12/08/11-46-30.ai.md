This is a follow-up discussion in the submodule gitdir path encoding series, focusing on migration strategy for the new extension.

Patrick Steihardt responds to Adrian Ratiu's plan for v6 implementation, suggesting a phased approach to the migration work. He proposes separating the core extension implementation from the auto-migration functionality, allowing each to be reviewed and discussed. This would let the team first establish consensus on the fundamental extension design before tackling the potentially more contentious migration mechanics.

The suggestion comes after Adrian confirmed that real-world migration should work smoothly and outlined plans to block manual configuration while automatically migrating build-time enabled cases. Patrick's proposal aims to isolate the architectural discussion (which has largely reached consensus) from operational concerns about migration paths.

This email represents a tactical refinement to the series' rollout strategy rather than a technical change to the implementation. It acknowledges the complexity of migration while maintaining the hard-won consensus around runtime-only configuration and config authority. The thread shows the series moving toward finalization with careful attention to real-world deployment considerations.
