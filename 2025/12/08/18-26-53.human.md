This is a review comment on patch 09/17 of Taylor Blau's MIDX compaction series, focusing on pack ordering requirements. Patrick Steinhardt raises two main points about the patch that relaxes the lexicographic ordering requirement for packs in MIDX files.

First, he questions whether the change might cause compatibility issues with other Git implementations, noting that assuming older versions will gracefully handle out-of-order packs seems potentially risky. He asks whether Taylor verified behavior across implementations and whether there was a specific reason not to bump the MIDX version number for this change.

Second, regarding the implementation's use of a lazily-sorted `pack_names_sorted` array, Patrick confirms his understanding that the MIDX cannot be modified after creation (so the sorted array remains valid), though this appears more as a verification than a concern.

The exchange shows careful technical review of a subtle but important aspect of the MIDX compaction work - how pack ordering affects compatibility and performance. Patrick's questions suggest this might be worth deeper discussion before finalizing the approach, though the technical implementation itself seems sound. This patch is part of the broader effort to make MIDX handling more flexible while maintaining backward compatibility.
