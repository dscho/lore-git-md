This is the third patch in Patrick Steinhardt's 8-part series refactoring Git's object database alternates handling. The change focuses on cleaning up the interface for checking alternate object database usability.

The patch simplifies `alt_odb_usable()` (renamed to `odb_is_source_usable()`) by having it compute the normalized object directory path internally rather than receiving it as a parameter. This makes the function more self-contained since it already has access to the object database needed for this computation. The change removes redundant parameter passing and aligns with the series' goal of better separation of concerns.

The implementation moves path normalization into the function using a `strbuf`, with proper cleanup via a new `out` label. The rename to `odb_is_source_usable()` follows the series' terminology updates. The core logic remains the same - it still checks for directory existence, prevents adding the main object directory as an alternate, and avoids duplicate entries.

This appears to be a straightforward refactoring that improves code organization without changing behavior. It builds on the previous patches' work to modernize the alternates handling code in preparation for pluggable object database backends. The change is focused and well-contained, touching only the intended functionality in odb.c.
