Refactoring patch from Patrick Steinhardt, part of an 8-patch series modernizing Git's alternates handling for the object database abstraction effort.

This first patch focuses on making alternates parsing self-contained by separating it from the linking logic. Currently, alternates parsing (for both files and environment variables) is intertwined with `link_alt_odb_entries()`, leading to recursive parsing and mixed responsibilities. The changes:

1. Extracts parsing into a new `parse_alternates()` function that processes all entries at once into a string vector
2. Simplifies `link_alt_odb_entries()` to just handle the linking phase
3. Maintains all existing functionality for quoted paths and comments

The commit message notes this doesn't yet solve the recursion or responsibility issues, but is a necessary preparatory step. The diff shows a clean reorganization of the parsing logic with no behavior changes - just moving code between functions and switching from a strbuf to strvec for intermediate storage.

This appears to be a well-scoped, mechanical refactoring that follows Git's established patterns for such preparatory work. The changes are limited to odb.c and focused on improving code structure in service of the larger ODB abstraction goal.
