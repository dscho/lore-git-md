Bugfix for `git-last-modified` bitmap initialization, now incorporating feedback from the thread discussion. This is version 2 of the patch that fixes a memory initialization issue in the command's scratch bitmap handling, where the original code passed an element count rather than byte count to `memset()`. The bug was more visible on s390x big-endian systems but wasn't endian-specific.

The patch now introduces a new `MEMZERO_ARRAY()` macro in `git-compat-util.h` to properly handle the size calculations, addressing Jeff King's suggestion for better code hygiene. The commit message has been updated with a more accurate title ("uninitialized memory" instead of "inproper initialized") per Junio Hamano's feedback, while keeping the core fix unchanged. The change remains minimal, just updating the memset call to use the new macro and adding the macro definition.

The patch maintains all attribution, keeping the original bug report credit to Anders Kaseorg and Jeff King's "Helped-by" for his review. The v2 changes show responsiveness to the mailing list discussion while keeping the solution focused. This appears ready for inclusion, having been reviewed by multiple contributors and deemed suitable for backporting to maint.
