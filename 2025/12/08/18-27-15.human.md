Performance optimization for MIDX handling in geometric repacking.

This is the second patch in a two-part series that improves MIDX (multi-pack index) handling during repacking operations. The patch focuses on avoiding unnecessary MIDX rewrites when running `git repack --geometric --write-midx` by introducing a new `midx_needs_update()` function that checks several conditions before deciding whether to regenerate the MIDX.

The key insight is that geometric repacking may determine no packs need merging (printing "Nothing new to pack") but still wastefully rewrites the MIDX. The patch adds logic to skip this when:
- No MIDX exists (must create one)
- Bitmap was requested but missing
- Preferred pack changed
- Packfile set changed

Benchmarks show dramatic improvements - from ~3.2s to ~100ms for no-op repacks in the Git repo. The change is particularly valuable for geometric repacking which may frequently hit this case.

The implementation adds thorough test coverage in both t5319 (MIDX-specific) and t7703 (geometric repack) to verify all edge cases. The patch builds on the first in the series (which fixed MIDX reverse index handling) to complete the optimization.

This appears to be a well-considered change with clear performance benefits, particularly for repositories using geometric repacking. The implementation is careful to maintain all existing behavior while only skipping truly redundant work.
