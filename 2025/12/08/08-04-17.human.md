This is a refactoring series targeting Git's handling of alternate object directories, part of the ongoing effort to support pluggable object database backends. Patrick Steinhardt proposes restructuring how alternates are managed to work through object database sources rather than direct filesystem operations.

The key motivation is that future object database backends may not use physical directories, making the current "objects/info/alternates" file approach unsuitable. The 8-patch series cleans up and centralizes the alternates handling code, with changes including:
- Making alternate path parsing self-contained
- Moving path normalization logic
- Removing recursive parsing
- Transitioning to source-based operations

The changes are focused on the odb.c file with significant line count churn (158 insertions, 149 deletions) but appear to be mechanical refactoring rather than behavior changes. The series builds logically from foundational cleanups to the final source-based interface.

This looks like a well-structured preparatory series for the pluggable ODB work, with each commit appearing focused and explained. The changes are internal plumbing that shouldn't affect end users but should make future backend implementations cleaner.
