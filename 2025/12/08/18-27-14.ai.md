This is a bugfix patch addressing MIDX (multi-pack index) handling, specifically around determining the preferred pack when no reverse index exists. It's the first of a two-patch series aimed at optimizing MIDX behavior during repacking.

The patch fixes a `BUG()` that occurs when `midx_preferred_pack()` tries to access a non-existent reverse index. The issue stems from incorrect error checking - the code only looks for negative return values from `load_midx_revindex()`, but that function returns a positive error code when no reverse index exists. The fix changes the condition to check for any non-zero return value.

Key technical details include:
- Modifies the error handling in `midx_preferred_pack()` to properly detect missing reverse indexes
- Updates documentation for `load_midx_revindex()` to clarify its return values
- Adds a new test case in `t5319-multi-pack-index.sh` that verifies the preferred pack cannot be determined without a bitmap (which would create the reverse index)
- Touches core MIDX functionality in `midx.c` and `pack-revindex.h`

The patch appears well-constructed with clear commit message explanation and thorough test coverage. It serves as groundwork for the second patch in the series which will optimize MIDX rewrites during repacking. The changes are narrow in scope, focusing specifically on the error case without introducing new behavior.
