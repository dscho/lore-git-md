Refactoring patch in a series modernizing Git's object database alternates handling.

This is the first of 8 patches from Patrick Steinhardt refactoring how Git handles object database alternates. The immediate change moves alternates parsing logic into a self-contained `parse_alternates()` function that returns results via a `strvec` rather than mixing parsing with the linking of alternate entries into the object database. The patch converts the parsing to process all entries at once rather than one-by-one, though the behavioral changes are minimal at this stage.

Key technical changes:
- Replaces `parse_alt_odb_entry()` with new `parse_alternates()` that processes entire input strings
- Switches from `strbuf` to `strvec` for collecting parsed paths
- Separates parsing phase from linking phase in `link_alt_odb_entries()`
- Maintains same quoting/comment handling behavior
- Touches only odb.c (70 lines changed, net +10)

This appears to be for preparatory work - the commit message notes this doesn't yet resolve the recursive parsing issue but is a necessary step toward that goal. The changes follow established patterns for Git's object storage modernization efforts, with clean separation of concerns being the primary benefit. The patch is focused and well-contained, though as the first in a series, its full impact will only be clear when combined with the subsequent changes.
