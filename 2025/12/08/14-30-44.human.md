Bugfix analysis for `git pull --rebase` fork-point behavior. Phillip Wood confirms Kartik Agaram's bug report about data loss during rebase after a partial push failure, explaining the root cause. When a push partially fails (succeeding on one URL but not another), the successful push updates the remote-tracking branch, causing `git pull --rebase` to miscalculate the fork point and incorrectly drop local commits.

The issue stems from how the fork-point logic interacts with remote-tracking branch updates after partial push failures. Phillip notes this isn't the first time fork-point calculation has caused problems, referencing prior discussions about adding a `--no-fork-point` option to `git pull`. As a workaround, he recommends manually using `git fetch && git rebase --no-fork-point` instead of `git pull --rebase`.

The email references two previous attempts to address similar fork-point issues (linked in footnotes), though one lacked tests. This suggests the current behavior might require more fundamental changes rather than just fixing the immediate edge case.
