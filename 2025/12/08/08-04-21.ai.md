This is the fourth patch in Patrick Steinhardt's series refactoring Git's alternates handling as part of the object database (ODB) abstraction effort. The patch focuses on `odb_add_to_alternates_file()`, which adds new alternates paths to the ODB.

The key change replaces a call to `link_alt_odb_entries()` (which processes multiple newline-separated paths) with `odb_add_source()` (which handles a single path). This better matches the actual usage pattern, as all callers only ever pass single directories to this function. The previous behavior was undocumented and potentially surprising since it could process multiple paths when only one was expected.

The patch is a straightforward one-line change in odb.c that maintains the same functionality for the existing single-path use cases while removing the unexpected multi-path processing capability. This continues the series' trend of improving the separation of concerns in alternates handling, making the code more predictable and better aligned with actual usage patterns.

This change is part of the broader effort to modernize Git's object storage layer by introducing proper abstractions for ODB backends. The patch builds on the previous refactoring work in the series that introduced the `odb_add_source()` function and related infrastructure.
