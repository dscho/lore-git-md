This is a refactoring series targeting Git's object database (odb) alternates handling, part of the ongoing effort to support pluggable object database backends. The series comes from Patrick Steinhardt and consists of 8 patches that restructure how alternates are processed to work through a "source" abstraction rather than direct filesystem operations.

The motivation stems from the need to support object database backends that may not store alternates in the traditional "objects/info/alternates" file format. The changes move the alternates handling to work through a more abstract interface, making it backend-agnostic. Key technical changes include refactoring the alternates parsing logic to be self-contained, resolving relative paths earlier in the process, eliminating recursive parsing, and ultimately routing both reading and writing of alternates through the new source-based interface.

The series appears to be a well-structured, incremental refactoring that touches only odb.c while maintaining the same functionality. Each commit message clearly explains its purpose, and the changes are focused on the stated goal of abstracting alternates handling. The diffstat shows significant churn (307 lines changed) but this is largely code reorganization rather than new logic. This looks like preparatory work for future pluggable odb backends, following established patterns seen in other parts of Git's object storage modernization.
