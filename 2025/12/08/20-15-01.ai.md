Bugfix follow-up with architectural discussion. Jeff King (peff@peff.net) responds to Toon Claes's v2 patch introducing a `MEMZERO_ARRAY` macro for zeroing memory regions with automatic size calculation. While the original bitmap initialization bugfix is already merged to 'next', this email explores whether the new macro would be useful more broadly in the codebase.

King notes the macro looks technically sound but questions its value given the original fix is already in place. He provides a `git grep` showing 5 other potential use sites in the codebase where `memset(..., 0, ... * sizeof(...))` patterns appear (excluding one odd case in add-patch.c). The candidate locations span various subsystems: last-modified, simple-ipc, diff-delta, hashmap, and pack-revindex.

The response maintains a neutral stance on whether to proceed with the macro, noting it could clean up several existing patterns but isn't strictly necessary. This continues the thread's evolution from immediate bugfix to broader code quality discussion, with King providing concrete data to assess the macro's potential impact. The architectural suggestion remains open-ended, with no strong push for or against adoption at this stage.
