This is a review response in Patrick Steinhardt's refactoring series for Git's object database alternates handling. Justin Tobler provides feedback on the first patch, which aims to make alternates parsing more self-contained.

Justin notes that the patch successfully separates the alternates parsing logic from the linking phase by having `parse_alternates()` process all entries at once into a `strvec` rather than handling them one-by-one as the old `parse_alt_odb_entry()` did. He confirms the parsing behavior remains unchanged while the implementation becomes cleaner.

The review highlights that while this improves code organization, it doesn't yet address the mutual recursion issue between parsing and linking (which will be handled in later patches). Justin gives the change a "looks good so far" indication, suggesting the refactoring direction is sound. This appears to be a positive early review of a technical change that's part of a larger effort to modernize Git's object storage layer.
