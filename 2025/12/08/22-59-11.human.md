This is a platform compatibility patch addressing a macOS-specific issue with character encoding conversion. René Scharfe reports that three tests in t3900 fail on macOS 26.1 when converting ISO-2022-JP encoded text to UTF-8. The issue appears when `iconv(3)` handles stateful encodings in chunks - it loses state between buffer resizes, causing corrupted output for the latter part of the string.

The patch introduces a new `ICONV_BREAKS` make variable that, when set, modifies `reencode_string_iconv()` to restart the entire conversion from scratch when needing to resize the buffer, rather than continuing from the partial result. This workaround avoids the state corruption issue while maintaining functionality.

The problem appears specific to macOS's `iconv` implementation, as René notes they previously worked around it by compiling with `NO_ICONV`. The patch provides a more targeted solution that preserves iconv functionality while working around the implementation quirk. The change is minimal (19 lines) and well-explained, with clear rationale in the commit message.
