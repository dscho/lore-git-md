This is a follow-up discussion in the submodule gitdir path encoding series, focusing on migration concerns for the new configuration approach. Adrian Ratiu responds to Junio Hamano's and Patrick Steinhardt's suggestions about how to handle repository migration to the new path encoding scheme.

The key development is Adrian's plan to implement an atomic enablement command in v6 that will both persist submodule gitdirs in config and enable the repository extension in one step. This addresses Junio's concern about operational complexity for repositories with custom path handling. Adrian notes that for most real-world cases, migration should work automatically, but acknowledges some edge cases may need special handling.

The email confirms the series is converging on a solution where:
- Users won't manually enable the extension
- A dedicated command will handle both config persistence and extension enablement
- Build-time configuration will trigger automatic migration for existing repos
- Adrian plans to block direct config setting attempts
- The implementation will include safeguards against improper manual configuration

This moves the series closer to completion by addressing the last major operational concern about migration paths. The v6 implementation will show how these migration scenarios work in practice while maintaining the core principle of config authority that has been agreed upon throughout the thread.
