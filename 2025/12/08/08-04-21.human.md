This is the fourth patch in Patrick Steinhardt's series refactoring Git's alternates handling as part of the object database (ODB) abstraction effort. The patch focuses on improving the behavior of `odb_add_to_alternates_file()`.

The change addresses a subtle mismatch in behavior where the function was calling `link_alt_odb_entries()` (which processes multiple newline-separated paths) when only ever being called with single paths. The patch makes this more precise by calling `odb_add_source()` directly instead, which better matches the actual usage pattern and makes the behavior more predictable.

This is a straightforward refactoring that doesn't change the external behavior but improves the internal consistency of the code. It follows logically from the previous patches in the series that have been restructuring the alternates handling code. The change is small (just one line modified) but meaningful in terms of making the code's behavior match its documented purpose more closely.

The patch is part of a larger effort to modernize Git's object storage layer to support pluggable backends, though this particular change is more about cleaning up existing behavior than enabling new functionality. It continues the series' pattern of careful, incremental improvements to the alternates handling code.
