This is a follow-up discussion in the submodule gitdir path encoding series, specifically addressing how to handle the transition to the new encoding scheme when the configuration is missing.

Adrian Ratiu responds to Patrick Steinhardt and Junio Hamano's discussion about enforcing strict configuration requirements when the submodule encoding extension is enabled. The key points are:

1. Patrick had raised concerns about the fragility of falling back to legacy path resolution when configuration is missing, arguing this undermines the extension's purpose of having config as the single source of truth.

2. Junio clarified his earlier position - while still opposing manual migration of existing directories, he agrees configuration should be required when the extension is enabled, with new submodules getting non-conflicting paths recorded in config.

3. Adrian acknowledges Patrick's point about the edge case where someone manually enables the extension after submodules exist, which would leave them without proper config entries.

4. The consensus is to implement an atomic enablement command in v6 that will both:
   - Persist existing submodule gitdirs in config
   - Enable the repository extension
   - Prevent manual configuration of the extension

This ensures the invariant that config entries exist when the extension is enabled, addressing the bootstrapping problem while maintaining the design principle of config authority. Adrian confirms he will implement this approach in the next version of the series.

The discussion resolves one of the last open questions in the series by providing a clean migration path that preserves the extension's guarantees while avoiding manual directory moves. This aligns with Junio's guidance while addressing Patrick's concerns about implementation robustness.
