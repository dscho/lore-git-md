This is a bugfix patch for MIDX (multi-pack index) handling, specifically addressing an edge case when determining the preferred pack without a reverse index. It's the first of a two-patch series aimed at optimizing MIDX operations during repacking.

The patch fixes a `BUG()` that occurs when `midx_preferred_pack()` tries to access a non-existent reverse index. Currently, the function checks for negative return values from `load_midx_revindex()`, but misses the case where the function returns a positive error code indicating no reverse index exists. The fix changes the condition to catch all non-zero return values, preventing the crash.

The change is well-validated with both code documentation updates (clarifying `load_midx_revindex()`'s return values) and a new test case that verifies the behavior when working with MIDX files that lack bitmaps. The test demonstrates that the function now gracefully fails when no reverse index exists, while still working correctly when bitmaps are present.
