Platform compatibility issue with iconv(3) on macOS affecting character encoding conversion.

René Scharfe reports test failures in t3900 on macOS 26.1 where ISO-2022-JP to UTF-8 conversion is incomplete, leaving some text in the original encoding. The issue occurs in `reencode_string_iconv()` when the function needs to grow its output buffer and make multiple iconv(3) calls - the macOS iconv implementation appears to lose state between calls for this stateful encoding.

The proposed patch adds an `ICONV_BREAKS` make variable that, when defined, works around the issue by restarting the conversion from scratch when growing the buffer rather than continuing from where it left off. This involves resetting the input pointer, adjusting sizes, and clearing the iconv state with a NULL call before retrying.

The changes affect the build system (adding the new ICONV_BREAKS flag) and the utf8.c conversion logic. The issue appears specific to macOS's iconv implementation and wasn't previously noticed because the author typically compiled with NO_ICONV. The patch provides a workaround rather than fixing the underlying iconv behavior, suggesting this may be a known limitation of the macOS implementation.
