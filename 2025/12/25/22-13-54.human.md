Performance issue with `git pack-refs --all` on large repositories.

Martin Fick reports that `git pack-refs --all` takes over 3 minutes to run on a large repository (90M objects, 3M refs) with only 200 loose refs, when it should complete in under 20 seconds. The slowdown is particularly problematic on their Gerrit server as it holds the packed-refs.lock file during this time. 

The issue appears to be related to Git unnecessarily reading objects during the ref packing process, as evidenced by strace showing 200+ object directory accesses interspersed with writes. Interestingly, JGit handles the same operation in the expected timeframe, and pre-repacking the repository speeds up the ref packing to acceptable levels. The repository is stored on NFS, though file writing throughput doesn't seem to be the bottleneck.

This looks like a genuine performance regression in Git's ref packing implementation, particularly affects large repositories with many refs. The fact that repacking first helps suggests the issue may be related to how Git handles object lookups during ref packing. The report provides good diagnostic information including strace output and repository characteristics, making it a solid starting point for investigation.
