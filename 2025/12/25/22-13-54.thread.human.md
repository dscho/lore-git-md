Here's the updated human-readable summary:

This thread investigates why `git pack-refs --all` runs much slower than JGit (5+ minutes vs 20 seconds) on large Gerrit servers with ~3 million refs. The initial analysis found that Git verifies each ref points to a valid object by actually opening object files, which is slow over NFS. Repacking the repository first (reducing pack files) helps significantly.

Jeff King (peff) has now explained that Git also needs to open objects to "peel" tags when writing the packed-refs file - reading object headers to determine their types. While refs under `refs/heads/` should only point to commits (avoiding peeling), Git can't safely assume this for all refs. This explains the observed file accesses and performance gap with JGit, which appears to handle ref packing differently.

The core issue remains: Git's current implementation requires expensive object verification that JGit avoids. While we understand why now (peeling tags and object verification), it's still unclear whether Git can be optimized to match JGit's performance or if this is a fundamental difference in approach. The discussion continues to focus on potential optimizations in the packed-backend implementation.
