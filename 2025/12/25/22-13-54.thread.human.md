Jeff King's analysis and Martin Fick's testing revealed the bottleneck isn't in writing the packed-refs file itself, but in Git's mmap access to packfiles over NFS during the operation. While JGit's speed suggests better NFS handling, Martin notes NFS is non-negotiable for Gerrit's mirroring requirements.

The thread has identified that Git holds the packed-refs.lock for extended periods during this slow operation, impacting Gerrit's atomic updates. Technical discussions continue about whether architectural changes could help, such as pre-reading data before acquiring locks. While a NO_MMAP build might help diagnose further, Martin notes this would be more useful as a runtime option than a compile-time setting. The core tension remains between Git's current implementation and the needs of large-scale deployments, with mmap/NFS interaction now clearly established as the primary performance culprit.
