This thread investigates severe performance issues with `git pack-refs --all` on large repositories (3M refs) stored on NFS, where Git takes 5+ minutes compared to JGit's 20 seconds. The original report from Martin Fick sparked analysis from Jeff King and others, revealing two key bottlenecks: mmap/NFS interaction overhead (confirmed via flame graphs showing 42% time in page faults) and verification of packed-refs file markers.

The latest development is significant: Martin found that adding just the "fully-peeled" marker to packed-refs files (which JGit wasn't writing) reduced runtime from 5 minutes to under 4 seconds - a 75x improvement. This confirms Jeff's earlier hypothesis about marker verification overhead, though it turns out the peeling status was the critical marker rather than the sortedness flag. While JGit does properly sort refs, it wasn't writing either marker, causing Git to perform expensive verification.

The thread now has a clear path forward - JGit should be modified to write proper markers, particularly "fully-peeled". However, Martin notes this still leaves room for Git to optimize its handling of marker-less files. The earlier findings about mmap/NFS overhead remain relevant but are now understood to be secondary to the marker verification issue in this specific case. The discussion has productively narrowed from broad performance investigation to specific, actionable improvements in both JGit's output format and Git's verification strategy.
