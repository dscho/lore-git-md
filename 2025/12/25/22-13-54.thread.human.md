This thread investigates why `git pack-refs --all` runs much slower (5+ minutes) than JGit (20s) on large Gerrit repositories with ~3M refs. The discussion has evolved from initial focus on object verification overhead to deeper analysis of write-path inefficiencies.

Jeff King's latest analysis confirms both Git and JGit perform similar object verification with comparable I/O patterns, ruling out tag peeling as the sole bottleneck. He notes writes to packed-refs are already buffered in 4K chunks, making small writes an unlikely culprit. This challenges Martin Fick's hypothesis about write-path issues being the primary cause.

The core discrepancy remains unexplained - why Git's implementation performs so much worse despite similar operations. While the reftable backend (which caches object info) remains a promising long-term solution, the thread continues to seek optimizations for the current files backend. Jeff's analysis suggests the performance gap may involve more subtle factors than initially thought, keeping the investigation open.
