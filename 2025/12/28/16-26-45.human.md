This is a follow-up discussion in the bugfix thread about namespace isolation with symbolic refs. Troels Thomsen responds to Junio Hamano's concerns about whether allowing cross-namespace symref updates might violate namespace isolation principles.

The exchange reveals a design tension: while the original patch fixed a crash by properly handling symrefs pointing outside their namespace, Junio questioned whether this permissive behavior is actually desirable from a security/isolation perspective. Troels argues that since the symref must be explicitly created on the receiving side, administrators still have control and could implement stricter policies via hooks if needed.

Troels suggests the low frequency of namespace/symref combinations in practice might not justify adding configuration options, though he acknowledges the behavior could theoretically be made configurable. The discussion highlights an underlying question about Git's philosophy regarding namespace boundaries - whether they should be strictly enforced by default or treated as advisory with hooks providing enforcement where needed.

The thread remains unresolved, with both technical and philosophical aspects still open for debate. The core crash fix is uncontroversial, but the broader implications for namespace isolation merit further discussion.
