Bugfix follow-up discussion regarding receive-pack's handling of out-of-namespace symrefs. Junio Hamano acknowledges the crash fix but questions whether allowing updates to symrefs pointing outside their namespace might violate namespace isolation principles. The original patch from Troels Thomsen modified `check_aliased_update_internal()` in `builtin/receive-pack.c` to work with fully-qualified ref names rather than stripped namespaces, preventing NULL dereferences when checking symref updates.

Hamano suggests the fix might unintentionally permit namespace boundary violations through symref updates, proposing an alternative approach where such cross-namespace updates would be explicitly rejected rather than allowed. This raises design questions about whether namespace isolation should be strictly enforced at the symref level, or if the current behavior (after the crash fix) represents an intentional relaxation of those rules.

The discussion centers on `strip_namespace()` behavior and the security implications of namespace boundary crossings, building on prior work from commits ded8393610 (namespace handling) and da3efdb17b (symref update checks). The test case in `t/t5509-fetch-push-namespaces.sh` would need reevaluation if the behavior changes.
