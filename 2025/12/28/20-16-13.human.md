This is a follow-up in the ongoing feature discussion about adding goal branch comparison to `git status`. The author, Harald Nordgren, responds to maintainer Junio Hamano's concerns about introducing a new `status.goalBranch` configuration variable. 

Harald defends the design choice, arguing that using existing branch tracking mechanisms (remote/pushRemote) would make the feature less useful since those settings are branch-specific and often point to personal forks rather than upstream repositories. He notes that most developers don't have pushRemote configured and that branch-specific tracking would require reconfiguration when switching branches, which would "ruin the feature."

The email doesn't propose any code changes but rather seeks to clarify the design rationale. Harald maintains that a dedicated configuration variable is the only practical way to implement persistent goal branch comparison across all branches in a repository. The response suggests the discussion has moved from technical implementation details back to fundamental design questions about how best to specify the comparison branch.

This comes after 9 iterations of the patch series that had previously addressed all technical feedback, with the current sticking point being whether the new configuration approach is justified. The timing (year-end) and tone suggest the thread may pause until after the new year while the design questions are reconsidered.
