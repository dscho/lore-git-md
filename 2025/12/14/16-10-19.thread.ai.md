Thread summary:

Feature proposal to extend commit signing configuration by generalizing the `commit.signOff` option beyond `git format-patch` to cover `commit`, `merge`, `cherry-pick`, and `revert` commands. Currently only `format-patch` has config-based SOB trailer support, while other commands require manual `--signoff` flags. The lazygit project's needs motivate this proposal.

Carlo Marcelo Arenas Belón references prior discussion establishing that Signed-off-by (SOB) trailers carry specific cultural significance in open source contexts, suggesting they should remain explicitly given rather than automatically applied. This reinforces the semantic distinction between SOB trailers in patch submission (where they're standard) versus general commit operations. The response doesn't directly evaluate the proposed command coverage but provides important context about SOB trailer semantics from earlier discussions (lore.kernel.org link).

Key open questions remain: whether different commands warrant different SOB policies, how to balance user convenience against trailer semantics (particularly in closed-source contexts), and whether the lazygit use case justifies configuration support despite the cultural considerations. The discussion continues to explore these tensions without yet reaching consensus on implementation approach or scope.
