This is a build system refinement patch in the ongoing macOS package manager compatibility discussion. Junio C Hamano responds to René Scharfe's proposal for more structured Homebrew dependency handling in the Git build system.

The email continues the thread about improving how Git locates and uses Homebrew-installed dependencies (gettext, msgfmt, libiconv) on macOS. René suggests moving from the current ad-hoc approach to a more principled system with explicit flags (USE_HOMEBREW_GETTEXT, USE_HOMEBREW_MSGFMT, USE_HOMEBREW_LIBICONV) that would allow granular control over which Homebrew components to use.

Junio agrees with the general direction but notes the macOS-specific details are beyond his expertise. René's proposal includes architecture-aware default paths (/opt/homebrew for ARM, /usr/local for Intel) and shows how conditional logic in config.mak.uname and the Makefile could implement this. The approach maintains backward compatibility while adding more control, though René notes the current implementation has some complexities that would need to be addressed.

This discussion represents an important refinement to the build system changes being made to work around macOS's problematic iconv implementation, showing the careful consideration being given to both functionality and maintainability. The thread continues to balance technical solutions with practical concerns about how packagers and users will interact with these build options.
