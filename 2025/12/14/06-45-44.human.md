This is a build system patch that introduces a `NO_HOMEBREW` option for Git's Makefile, allowing users to disable linking against Homebrew-installed libraries on macOS (or Linux). The change follows the pattern already established for other package managers like MacPorts and Fink.

The patch makes two main changes:
1. Adds a `NO_HOMEBREW` flag that, when set, prevents Git from using Homebrew's include paths and libraries
2. Refactors the existing Homebrew path detection to use new variables (`HOMEBREW_PREFIX`, `HOMEBREW_GETTEXT_PREFIX`, `HOMEBREW_MSGFMT`) rather than hardcoding paths directly into compiler flags

Torsten Bögershausen raises a question about where the `HOMEBREW_*` variables come from and suggests adding explanatory comments. The variables appear to be part of Homebrew's environment but aren't well-documented in Git's build system.

This is part of the ongoing work to improve Git's build system handling of macOS package managers, particularly around the iconv/encoding issues that have been discussed in the thread. The change maintains backward compatibility while providing more flexibility for packagers and users who want to control their build environment.
