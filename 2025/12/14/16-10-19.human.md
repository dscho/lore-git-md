This is a proposal discussion about adding a global `commit.signOff` configuration option to automatically add Signed-off-by trailers to commits, similar to the existing `format.signOff` for patches.

Stefan Haller notes that while several Git commands (`commit`, `merge`, `cherry-pick`, `revert`) support `--signoff`, only `format-patch` has a corresponding config option. The question arises from a feature request in the lazygit GUI tool, where users want consistent sign-off behavior across operations.

The core question is whether it makes sense to have a unified sign-off configuration that would cover all operations that create commits, not just patch generation. Stefan acknowledges their limited experience with Signed-off-by in open source contexts, suggesting they're seeking input from maintainers more familiar with the convention's typical usage patterns.

The proposal touches on workflow consistency - whether users who want to sign off on all contributions (a common requirement in some projects) should have to remember the flag for each command type. No implementation is proposed yet; this is purely a discussion starter about the concept's merits and potential scope.
