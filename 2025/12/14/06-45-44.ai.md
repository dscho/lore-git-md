This is a build system patch adding Homebrew-specific configuration options to the Git Makefile, part of the ongoing macOS iconv compatibility work. Torsten Bögershausen responds to René Scharfe's patch that introduces a NO_HOMEBREW flag to control linking against Homebrew-installed libraries, similar to existing flags for MacPorts and Fink.

The core change moves Homebrew path handling from direct compiler/linker flags to intermediate HOMEBREW_* variables (PREFIX, GETTEXT_PREFIX, MSGFMT), making the build system more flexible. Torsten raises a key question about the origin and purpose of these HOMEBREW_* variables, noting they currently only appear in CI scripts. He suggests adding explanatory comments to clarify their role in the build process.

The patch maintains backward compatibility while restructuring the Homebrew detection logic to work across both Intel (/usr/local) and Apple Silicon (/opt/homebrew) architectures. It follows the established pattern of package manager handling seen with MacPorts/Fink, but introduces more granular control through the new NO_HOMEBREW flag.

Implementation details include:
- Centralized Homebrew path detection in config.mak.uname
- Conditional inclusion of Homebrew paths only when NO_HOMEBREW is undefined
- Preservation of existing MSGFMT behavior through the new HOMEBREW_MSGFMT variable
- ARM vs Intel architecture handling through different prefix paths

The discussion highlights an ongoing tension in the thread between comprehensive package manager support and maintainable build system code. This patch represents a middle ground - adding Homebrew-specific controls while keeping the door open for future MacPorts/Fink integration. The missing documentation Torsten notes would help future maintainers understand the variable-based approach being established.
