This is a build system clarification in the ongoing macOS package manager compatibility thread. Junio Hamano responds to Torsten Bögershausen's questions about the purpose and usage of HOMEBREW_* variables in the Git build system.

The email explains that these variables (HOMEBREW_PREFIX, HOMEBREW_GETTEXT_PREFIX, HOMEBREW_MSGFMT) are Git-specific configuration points, not Homebrew environment variables. They allow builders to specify non-standard Homebrew installation locations when compiling Git. The variables get added to BASIC_CFLAGS and BASIC_LDFLAGS unless NO_HOMEBREW is set, with default values coming from config.mak.uname for standard Homebrew installations.

Key technical details:
- The variables control include paths and linker flags for Homebrew-installed dependencies
- HOMEBREW_MSGFMT overrides the default msgfmt path
- The mechanism is conditional on NO_HOMEBREW not being set
- Default paths are automatically handled for standard installations (/opt/homebrew for Apple Silicon, /usr/local for Intel)

This continues the thread's focus on properly documenting and implementing the build system changes needed to handle macOS package managers, with Junio providing authoritative clarification about how these Git-specific variables differ from Homebrew's own environment variables and their role in the build process. The exchange highlights the need for clear documentation about these configuration points, particularly for users with non-standard Homebrew installations.
