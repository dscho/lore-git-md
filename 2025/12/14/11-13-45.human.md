This is a build system patch adding Homebrew package manager support to Git's macOS build options, part of the ongoing work to address iconv conversion issues on macOS.

René Scharfe follows up on Junio Hamano's suggestion to document the HOMEBREW_* variables, agreeing they need clearer explanation but cautioning that the current implementation is still somewhat ad-hoc. The patch adds NO_HOMEBREW support parallel to existing NO_FINK and NO_DARWIN_PORTS flags, allowing users to opt out of Homebrew library linking.

The discussion reveals the current approach searches for Homebrew components in a piecemeal fashion, while a more principled solution would involve centralizing Homebrew path handling through HOMEBREW_PREFIX and per-component USE_HOMEBREW_* flags. René sketches what this might look like in config.mak.uname and Makefile, noting the current code has additional complexity that would need to be preserved or rationalized.

This continues the thread's theme of improving macOS package manager integration while maintaining backward compatibility. The patch itself is straightforward, but the surrounding discussion highlights deeper architectural questions about how Git should handle alternative package manager installations on macOS. The solution appears headed toward a more systematic approach, though not fully realized in this iteration.
