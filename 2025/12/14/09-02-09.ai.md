This is a build system patch continuing the macOS package manager integration work, specifically addressing the NO_HOMEBREW flag implementation. Torsten Bögershausen seeks clarification on the purpose and usage of the HOMEBREW_* variables introduced in René Scharfe's patch.

The discussion focuses on documenting the relationship between Git's build variables and Homebrew's environment. Junio Hamano explains that HOMEBREW_PREFIX and related variables are Git-specific configuration points, not Homebrew environment variables, allowing users to specify non-standard Homebrew installation locations. The default paths (/opt/homebrew for Apple Silicon, /usr/local for Intel) are handled automatically in config.mak.uname.

Key technical points under discussion:
- The distinction between Git's build variables (HOMEBREW_PREFIX) and Homebrew's own environment variables
- Need for clear documentation about variable usage patterns
- How non-standard Homebrew installations should be accommodated
- Whether additional comments should explain the variables' purpose in the build system

The thread shows consensus on the technical approach but highlights an ongoing need to clarify the documentation around these build variables, particularly for users who may be unfamiliar with Homebrew's conventions or who have customized installations. This follows the broader effort to properly handle macOS package managers while maintaining backward compatibility and clear user control.
