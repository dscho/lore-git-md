This thread addresses a long-standing bug in Git's diff machinery that affects copy detection when comparing the working tree to the index, particularly for reverse diffs showing deletions. The issue dates back to 2008 and manifests when using `--find-copies-harder` with index preloading. The core fix, from René Scharfe, modifies `run_diff_files()` to properly handle up-to-date and skip-worktree entries during copy detection, using the more efficient `diff_same()` function.

A follow-up note from SZEDER Gábor points out that the fix depends on an earlier commit (38f88051da) that introduced `diff_same()`, and the patches must be applied in the correct order to avoid a build error. While the core logic of the fix remains sound, maintainers need to be aware of this dependency when applying the changes. The thread includes test cases that validate the fix works for both regular and preloaded index scenarios.
