This thread addresses a bug in Git's diff machinery that affects copy detection in `diff-files` when comparing the working tree to the index, particularly for reverse diffs showing deletions from the index. The regression dates back to 2008 and manifests when using `--find-copies-harder` with index preloading (which happens automatically for large repositories). The core issue is that up-to-date and skip-worktree entries were incorrectly skipped, missing potential copy sources.

René Scharfe proposed a fix that modifies `run_diff_files()` in `diff-lib.c` to properly queue these entries using `diff_same()` when copy detection is enabled. SZEDER Gábor identified that this fix depends on commit 38f88051da ("diff-index: don't queue unchanged filepairs with diff_change()"), which introduced `diff_same()`. Without this prerequisite, the patch fails to compile. Junio C Hamano has confirmed this dependency and agrees the patch must be applied after its prerequisite commit.

The fix has been validated with test cases in `t/t4007-rename-3.sh` covering both non-preloaded and preloaded index scenarios. The thread has established both the functional fix and the correct application order, resolving a long-standing regression in copy detection behavior.
