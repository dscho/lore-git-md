This is a build system patch adding Homebrew support control to Git's macOS configuration, part of the ongoing character encoding conversion issue thread.

René Scharfe responds to Junio Hamano's clarification about the purpose of HOMEBREW_* variables in the build system. The discussion centers on how to properly document and implement these Git-specific configuration points that allow specifying non-standard Homebrew installation locations. René agrees with Junio's suggestion for clearer documentation but notes the current implementation is still somewhat ad-hoc, particularly around how HOMEBREW_PREFIX should affect searches for gettext and libiconv.

The email proposes a more structured approach where config.mak.uname would define both the default Homebrew prefix paths (architecture-dependent) and separate USE_HOMEBREW_* flags for individual components. This would replace the current implicit behavior where setting HOMEBREW_PREFIX affects multiple components without clear control. René sketches how this might look in the build files, noting the existing implementation has some complexity that would need to be preserved or reworked.

Key technical points include:
- Current architecture-specific paths (/opt/homebrew for ARM, /usr/local for Intel)
- Proposal for explicit component flags (USE_HOMEBREW_GETTEXT, USE_HOMEBREW_MSGFMT, USE_HOMEBREW_LIBICONV)
- ICONVDIR handling for libiconv specifically
- Need to maintain backward compatibility with existing behavior

The discussion highlights the tension between making the build system more configurable while keeping it understandable, particularly for packagers who need precise control over dependencies. This builds on earlier thread work to handle macOS-specific iconv issues while accommodating various package manager scenarios.
