Junio Hamano responds to Torsten Bögershausen's questions about the NO_HOMEBREW patch, clarifying the purpose and usage of the HOMEBREW_* variables in the build system changes. This is part of the ongoing macOS package manager compatibility work addressing iconv issues.

The email explains that HOMEBREW_PREFIX and related variables are Git-specific configurations set in config.mak.uname, with default paths for standard Homebrew installations (/opt/homebrew for Apple Silicon, /usr/local for Intel). Users with non-standard Homebrew locations can override these by setting the variables manually while keeping NO_HOMEBREW unset. Junio suggests adding clarifying comments to document this behavior, proposing specific wording that explains when and how to set HOMEBREW_PREFIX.

This discussion highlights the need for clear documentation around the new Homebrew-related build options, particularly around:
- The relationship between NO_HOMEBREW and HOMEBREW_PREFIX
- Default paths for different macOS architectures
- How users with custom Homebrew installations should configure their builds
- The distinction between Git's internal variables and Homebrew's own environment variables (like HOMEBREW_NO_AUTO_UPDATE)

The exchange shows maintainers working through the final documentation details of the build system changes before finalizing the solution for the macOS iconv conversion issues. The thread continues to refine the balance between automatic detection and explicit user control in the package manager integration.
