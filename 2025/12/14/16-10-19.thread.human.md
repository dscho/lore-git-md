This thread discusses extending Git's commit signing configuration to be more consistent across commands. Currently, only `git format-patch` has a `commit.signOff` config option to automatically add Signed-off-by trailers, while other commands like `commit`, `merge`, `cherry-pick`, and `revert` require manual `--signoff` flags each time.

The proposal originates from a feature request in the lazygit GUI tool, which currently implements its own signoff configuration just for commits. The author questions whether a global config option would be useful, particularly for regular commits where they believe it might be most needed. They also raise open questions about extending this to operations like merge/revert/cherry-pick, and note the different cultural significance of Signed-off-by in open vs. closed source contexts.

As this is an early-stage proposal, the author is primarily seeking community feedback, particularly from those familiar with open source Signed-off-by conventions, as they primarily work in closed-source environments. The discussion touches on both UX consistency (why some commands have configs while others don't) and the semantic meaning of Signed-off-by in different contexts. The lazygit use case suggests there may be real user demand for more consistent signoff configuration across Git commands.
