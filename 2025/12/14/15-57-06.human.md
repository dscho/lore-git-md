Bugfix for copy detection in `diff-files` when comparing working tree to index.

René Scharfe fixes a long-standing issue where copy detection wasn't working properly in `git diff-files` when comparing the working tree to the index, particularly in reverse diffs (-R flag). The bug was introduced in 2008's d1f2d7e8ca and went unnoticed because it only manifests with index preloading (which requires large repos) and is timing-dependent.

The patch makes two key changes: it properly handles up-to-date and skip-worktree entries for copy detection, and optimizes memory usage by using `diff_same()` for unchanged files. The fix comes with two new tests - one reliable test for basic functionality and another that stresses the preloading scenario which would reliably catch the bug under --stress testing.

The changes are focused and well-explained, touching only diff-lib.c and adding targeted test coverage. The commit message provides clear historical context about how this slipped through testing until now. This appears to be a solid fix for a subtle but real issue in diff machinery.
