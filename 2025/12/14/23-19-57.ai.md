Build system refinement for macOS package manager support.

Junio C Hamano responds to René Scharfe's proposal for more structured Homebrew integration in the build system. The discussion focuses on moving from ad-hoc path detection to a more principled approach using explicit component flags (USE_HOMEBREW_*) and a unified HOMEBREW_PREFIX variable.

Key technical elements under consideration:
- Architecture-specific default paths (/opt/homebrew for ARM, /usr/local for Intel)
- Three new component flags: USE_HOMEBREW_GETTEXT, USE_HOMEBREW_MSGFMT, USE_HOMEBREW_LIBICONV
- Conditional logic in Makefile that would check these flags when HOMEBREW_PREFIX is defined
- Special handling for libiconv via ICONVDIR when USE_HOMEBREW_LIBICONV is set
- Preservation of existing NO_HOMEBREW flag behavior

The proposal represents a significant shift from the current implicit detection to explicit component selection, addressing concerns about ad-hoc behavior while maintaining backward compatibility. The implementation would need to carefully handle:
- Path existence checks (like the test for $(HOMEBREW_PREFIX)/opt/libiconv)
- Interaction between the new USE_HOMEBREW_* flags and existing variables
- Documentation of the more complex but more flexible configuration system

This email moves the discussion toward a more maintainable solution while acknowledging the complexity of the current implementation. The thread continues to balance macOS-specific needs with general build system principles.
