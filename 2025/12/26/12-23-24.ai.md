This is the first patch in the v6 series refactoring Git's hook subsystem, introducing foundational parallel process infrastructure. It creates a named `parallel_child` struct to encapsulate process state and adds a `child_is_working()` helper function to check if a child process is active, replacing direct state comparisons throughout `run-command.c`.

The change extracts the anonymous struct tracking child processes into a properly named `parallel_child` type, with the key fields being the process state`, `child_process` instance, error buffer, and opaque data pointer. The new `child_is_working()` helper provides a more readable way to check the `GIT_CP_WORKING` state, used in several process management functions like `kill_children()`, `pp_buffer_stderr()`, and `pp_output()`.

This appears to be a straightforward preparatory refactoring that improves code organization without changing behavior, setting up for subsequent parallel execution features in the hook system. The patch follows the pattern of the larger series by introducing small, focused changes with clear boundaries. Junio Hamano suggested the approach, and the implementation looks clean with all state checks properly updated to use the new helper.
