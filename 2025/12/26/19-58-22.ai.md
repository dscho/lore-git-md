This is a bug report regarding a regression in `git subtree` functionality. The reporter describes a breakage when pushing subtree changes that worked correctly in Git 2.51.1 but fails in 2.52.0 with a non-fast-forward error. The issue appears related to commit 83f9dad7d6 ("subtree: fix split after annotated tag was squashed merged", 2025-11-15).

The key symptoms are:
1. When pushing to a subtree remote that was originally added with `--squash`, Git 2.52.0 produces a disconnected history with fewer commits compared to 2.51.1
2. The `git-subtree-split:` marker in squash commit bodies seems to be ignored in the newer version
3. The reporter provides a concrete reproduction case using the Athena Framework monorepo and its clock subcomponent

The regression appears to affect the history reconstruction during subtree operations, particularly when dealing with squashed commits. The reporter has done some initial investigation showing the behavioral difference between versions, noting that 2.51.1 properly maintains commit connections while 2.52.0 creates a new root commit history.

The bug report includes detailed system information showing the exact Git version and build environment where the issue occurs. The reporter also references a specific commit that may be related to the regression, suggesting this could be an unintended side effect of that change.
