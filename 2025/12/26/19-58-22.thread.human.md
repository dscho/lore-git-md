This thread reports a regression in `git subtree` functionality that appeared in Git 2.52.0. The issue occurs when pushing subtree changes that were originally added with `--squash` - the newer version creates a broken history with fewer commits and fails with a non-fast-forward error, whereas Git 2.51.1 handled this case correctly. The reporter suspects commit 83f9dad7d6 ("subtree: fix split after annotated tag was squashed merged") may be the cause, as it modified subtree behavior around squashed commits.

The bug manifests when working with the Athena Framework monorepo's clock subcomponent, where 2.52.0 ignores the `git-subtree-split:` markers in squash commit bodies that previously allowed proper history reconstruction. The reporter has documented the behavioral difference between versions, showing how 2.51.1 maintained commit connections while 2.52.0 creates a disconnected history with a new root commit. The report includes detailed reproduction steps and environment information to help diagnose the issue.
