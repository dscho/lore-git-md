This thread documents a regression in `git subtree` functionality that appeared in Git 2.52.0, breaking operations involving squashed subtree commits. The issue was first reported with a detailed analysis showing it affected the Athena Framework monorepo, with Colin Stagner later creating a minimal reproduction case. The root cause was traced to commit 83f9dad7d6, which changed how subtree split commits are detected during history reconstruction.

Colin has proposed a solution that completely removes the problematic "ignore other splits" optimization in `should_ignore_subtree_split_commit()`, as analysis showed this heuristic was both incorrect and a performance bottleneck. The new approach not only fixes the regression but also provides significant performance improvement - testing shows the fixed version runs 3x faster than the original working version (10.8s vs 33.0s) and nearly 2x faster than the broken version. The patch also addresses a separate "recursion depth exceeded" issue on Debian/Ubuntu systems.

George Dietrich is currently reviewing the implementation to verify it preserves history correctly across all normal split operations in their workflow. While the technical consensus is strong, the solution may need additional test coverage to prevent regression recurrence. The thread has progressed methodically from initial bug report through technical analysis to this promising implementation that resolves both functional and performance issues.
