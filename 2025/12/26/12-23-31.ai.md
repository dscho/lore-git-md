This is part 8 of the hook subsystem refactoring series, focusing on output capture functionality for parallel hook execution. The patch introduces a new `consume_output_fn` callback in `run-command.c` that allows callers to intercept and process hook output rather than having it written directly to stderr. This is particularly useful for server-side hooks that need to relay output to clients.

Key technical aspects:
- Adds `consume_output` field to `struct run_process_parallel_opts` with a callback that receives output in a strbuf
- Modifies parallel process handling to use the callback when present, falling back to stderr otherwise
- Explicitly forbids combining `ungroup` and `consume_output` modes with a BUG() assertion
- Includes test coverage demonstrating output redirection to a file
- Maintains backward compatibility by defaulting to stderr output when no callback is provided

The implementation handles both buffered output (from `pp->buffered_output`) and per-child output streams, ensuring all hook output can be captured. The callback is called even with empty output to support keepalive mechanisms. This builds on the parallel execution infrastructure introduced earlier in the series while addressing the specific need for output control in server-side hook scenarios.

The patch has already been reviewed and signed off by key contributors (Emily Shaffer and Ævar Arnfjörð Bjarmason) and fits cleanly with the established hook API patterns from earlier parts of the series. The changes are focused and well-contained, touching only the parallel execution output handling while leaving other behaviors unchanged.
