This is part 2 of the hook subsystem refactoring series, introducing parallel execution infrastructure. The patch adds stdin handling capabilities to the parallel process API in `run-command.c`, enabling efficient streaming of large inputs to child processes without buffering everything in memory.

The key technical addition is a new `feed_pipe_fn` callback in `struct run_process_parallel_opts` that allows callers to incrementally feed data to child processes' stdin pipes. The implementation handles SIGPIPE gracefully and provides helper functions (`child_is_ready_for_cleanup`, `child_is_receiving_input`) to manage pipe state. The patch includes comprehensive test coverage demonstrating both the basic functionality and edge cases like EPIPE handling when children close stdin early.

This infrastructure is specifically designed to support the hook conversion work in later patches, where hooks like `pre-push` need to process potentially large inputs. The implementation follows the established pattern of the parallel API, adding stdin handling while maintaining the existing output capture and error handling capabilities. The test additions verify both the core functionality and integration with the existing test harness.

The patch has already undergone significant review iteration, with sign-offs from key reviewers (Ævar Arnfjörð Bjarmason and Emily Shaffer) and addresses all technical concerns raised in earlier versions. It provides the foundation for the hook conversions that follow in the series while being generally useful for any parallel process execution needing stdin streaming.
