This is part 7 of the hook subsystem refactoring series, focusing on parallel execution control. The patch introduces a new `ungroup` flag in `struct run_hooks_opt` to override the default ungrouped output behavior when running hooks in parallel. This is needed because sideband reading (used in receive-pack) requires grouped output, conflicting with the current hardcoded ungroup behavior.

Key technical changes:
- Adds `ungroup:1` bitfield to `struct run_hooks_opt` in hook.h
- Makes `run_hooks_opt()` respect the caller's ungroup setting instead of hardcoding to 1
- Maintains backward compatibility by explicitly setting `ungroup=1` in `run_hooks()` and `builtin/hook.c` entry points
- Adds comments noting these could be made configurable if future use cases require

The change enables proper sideband output handling in receive-pack hooks while preserving the existing ungrouped behavior for other hook types. This addresses a specific technical limitation in the parallel execution infrastructure introduced earlier in the series, completing the sideband support functionality mentioned in the thread summary.

The implementation is straightforward and maintains the series' careful attention to backward compatibility. The patch follows the established pattern of the series by adding just enough configurability to solve the immediate need while documenting potential future extension points.
