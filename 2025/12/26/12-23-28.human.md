This is part 5 of an 11-part series refactoring Git's hook subsystem to use the new `hook.h` API. The patch converts the pre-push hook implementation in `transport.c` from direct `run-command` usage to the standardized hook API.

The changes eliminate manual child process management and signal handling, replacing them with the series' new callback-based approach. The pre-push hook now uses a `feed_pipe` callback (`pre_push_hook_feed_stdin`) to stream reference updates to the hook's stdin, with the same filtering logic as before (skipping non-fast-forward and up-to-date refs). The conversion maintains all existing behavior while removing about 40 lines of boilerplate process management code.

This patch follows the pattern established earlier in the series, using the `run_hooks_opt` infrastructure for argument passing and stdin feeding. It's a straightforward conversion that benefits from the groundwork laid in earlier patches, particularly the stdin callback mechanism introduced in part 3. The implementation looks clean and maintains all the hook's existing functionality while being more maintainable.

With sign-offs from both Emily Shaffer (the original author) and Ævar Arnfjörð Bjarmason (a key reviewer of the hook conversions), this appears ready for inclusion as part of the larger series. The changes align well with the thread's overall goal of standardizing hook handling across Git.
