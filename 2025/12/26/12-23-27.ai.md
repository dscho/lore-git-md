This is part 4 of the hook subsystem refactoring series, converting the post-rewrite hook implementation in sequencer.c to use the new hook API. The patch replaces manual child process management and SIGPIPE handling with the standardized `hook_run_opt()` interface. Key technical changes include:

- Introduces a new `pipe_from_strbuf()` callback function that handles stdin feeding for the hook, using the `feed_pipe_ctx` and `feed_pipe` fields of `struct run_hooks_opt`
- Removes direct `find_hook()` calls and manual SIGPIPE toggling, which are now handled internally by the hook API
- Maintains identical functionality while reducing boilerplate code (42 lines changed, net -17 lines)
- Preserves the "amend" argument passing and stdin format (oldoid + newoid pairs)
- Uses the same strbuf-based stdin preparation but now feeds it through the hook API's streaming mechanism

The implementation follows the pattern established in earlier parts of the series, using the structured stdin handling capabilities introduced in part 3. The change is straightforward and well-contained, focusing only on the post-rewrite hook conversion while leaving surrounding sequencer logic unchanged. With sign-offs from both Emily Shaffer and Ævar Arnfjörð Bjarmason, this appears to be a non-controversial piece of the larger hook standardization effort.
