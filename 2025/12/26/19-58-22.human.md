This is a bug report about a regression in `git subtree` functionality. The reporter, dev@dietrich.pub, describes how `git subtree push` stopped working correctly after upgrading from Git 2.51.1 to 2.52.0. 

The issue occurs when pushing subtree changes to a component repository in a monorepo setup. While the operation worked fine in 2.51.1, the newer version rejects the push with a non-fast-forward error. The reporter suspects this relates to commit 83f9dad7d6 ("subtree: fix split after annotated tag was squashed merged") and notes that components originally added with `--squash` seem particularly affected.

A key symptom is that subtree splits now produce fewer commits (8 vs 92 in the working version) with disconnected history, suggesting the `git-subtree-split:` markers in squash commits aren't being properly honored. The reporter has done some initial investigation but hasn't identified the exact cause.

This appears to be a genuine regression affecting real-world monorepo workflows, though the impact seems limited to cases where subtrees were originally added with `--squash`. The report is well-documented with clear reproduction steps and version comparisons, making it a solid candidate for investigation by subtree maintainers.
