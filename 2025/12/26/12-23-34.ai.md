This is the final patch in the hook subsystem refactoring series, converting receive-pack's hooks to the new `hook.h` API. The patch focuses on the receive hooks, which handle push operations, and introduces batched stdin processing to maintain performance while using the new callback-based API.

Key technical changes:
- Replaces direct `child_process` management with `run_hooks_opt` API calls
- Implements `feed_receive_hook_cb` callback that processes ref updates in batches of 500 lines to avoid performance degradation from per-line polling
- Maintains push certificate handling by moving certificate SHA1 preparation into the hook options
- Preserves sideband output routing through the `hook_output_to_sideband` callback
- Keeps push option environment variable generation but moves it into the hook options setup
- The conversion maintains all existing functionality including:
  - Broken ref skipping
  - Push option passing
  - Sideband output
  - Push certificate metadata
  - Temporary object directory environment

The patch addresses a performance concern identified during conversion - processing ref updates one line at a time through the new callback system caused noticeable slowdowns. The solution batches 500 lines per callback invocation, matching the throughput of the previous direct pipe implementation.

This completes the series' goal of all major Git hooks to the new API, with receive-pack being the last subsystem converted. The implementation has been reviewed and signed off by key contributors including Ævar Arnfjörð Bjarmason, with all technical concerns addressed across the series' six iterations.
