This is a performance analysis follow-up in the ongoing investigation of `git pack-refs --all` slowness on large repositories. Jeff King (Peff) responds to Brian Carlson's earlier analysis of the `should_pack_ref` check, explaining why Git needs to open object files during ref packing.

Peff clarifies that the object access occurs during tag-peeling operations when writing the packed-refs file, not just during the initial existence check. The `peel_object()` function must read object headers to determine types, which explains the observed file operations. He notes this is particularly relevant for tags, though refs in `refs/heads/` should theoretically not need peeling since they should point to commits.

The response suggests this is an inherent aspect of Git's current ref-packing design rather than an optimization oversight, though Peff leaves open whether assumptions about branch refs could be leveraged to reduce work. This adds important technical context to the thread's core question about why Git's behavior differs from JGit's faster approach.
