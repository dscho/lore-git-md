This is a bugfix patch addressing a regression in error reporting for batched reference updates. Karthik Nayak responds to Jeff King's proposed solution for restoring detailed error messages (like "trying to write non-commit object") that were lost during batched reference updates in Git 2.51.0.

The regression affects multiple commands (push, fetch, update-ref) across both files and reftable backends. Jeff's solution involves modifying the ref transaction API to store and propagate detailed error messages per reference update, rather than just error codes. Karthik agrees with the technical approach and notes he'll implement it with proper memory management and integration across all affected commands.

Karthik plans to polish Jeff's prototype (which currently has memory leaks) and send a proper patch series in early 2026, though he notes he's currently on break. The fix will need to handle both human-readable output and machine-readable formats consistently across all reference backends while maintaining the performance benefits of batched updates.
