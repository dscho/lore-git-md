This is part 5/11 of the hook subsystem refactoring series, specifically converting the pre-push hook to use the new standardized hook API. The patch replaces the custom `child_process` handling and manual SIGPIPE management with the structured `run_hooks_opt` interface.

Key technical changes:
- Introduces `feed_pre_push_hook_data` struct to manage state for streaming ref data to the hook's stdin
- Implements `pre_push_hook_feed_stdin` callback that selectively streams ref updates (skipping non-pushed refs) using the new `feed_pipe` mechanism
- Maintains identical ref filtering logic (REJECT_* and UPTODATE cases) but moves it into the stdin callback
- Preserves all existing hook arguments (remote name/URL) via `strvec_push`
- Removes direct `find_hook()` calls and manual signal handling in favor of `run_hooks_opt`

The conversion follows the pattern established in earlier parts of the series, using the stdin feeding mechanism first introduced in part 3. This maintains backward compatibility while providing a more robust foundation for future enhancements. The patch has already been reviewed and signed off by key contributors (Emily Shaffer and Ævar Arnfjörð Bjarmason), indicating it meets the project's technical standards.

This is a mature patch in a well-reviewed series that's now in its 6th iteration, with all major technical concerns addressed. The changes are focused and mechanical, converting existing functionality to the new API without altering behavior.
