This is part 10/11 of the hook subsystem refactoring series, converting receive-pack's update and post-update hooks to use the new hook API. The patch focuses on the receive-pack side of the hook execution, specifically handling the sideband output mechanism that's critical for server-side operations.

The key technical changes in this patch:
- Replaces direct `child_process` usage with the new `run_hooks_opt` API for both update and post-update hooks
- Introduces `hook_output_to_sideband()` callback function that properly routes hook output through the sideband channel when enabled
- Maintains existing behavior where hook output is sent to stderr when sideband is disabled
- Preserves all existing hook argument passing (ref names, old/new OIDs) but through the new API's `strvec_push` interface
- Keeps the same filtering logic for post-update hooks (skipping failed/nonexistent refs)

The conversion follows the pattern established in earlier parts of the series, removing manual hook plumbing in favor of the standardized API while maintaining all existing functionality. The sideband output handling is particularly important for receive-pack as it ensures hook output gets properly multiplexed with the protocol stream.

This patch builds on the parallel execution infrastructure and output capture capabilities introduced in earlier parts of the series, though it still runs hooks sequentially (as indicated by the `processes=1` note in the commit message). The implementation has been reviewed and signed off by key contributors including Emily Shaffer and Ævar Arnfjörð Bjarmason, with all major technical concerns addressed in previous iterations.
