This is a technical discussion about performance optimization in `git pack-refs` for repositories with high ref counts, continuing the investigation into why `pack-refs --all` is significantly slower than JGit's implementation.

Jeff King (peff) responds to Brian Carlson's analysis of the `should_pack_ref` check by pointing out that `pack-refs` also needs to open objects for peeling tags when writing the packed-refs file. The peeling operation requires reading object headers to determine their types, which explains the observed file accesses. Peff notes that while refs under `refs/heads/` should theoretically not need peeling (as they should only point to commits), enforcing this assumption might not be safe or helpful for all cases, particularly when dealing with refs outside that namespace.

The discussion continues to explore the fundamental differences between Git and JGit's approaches to ref packing, with Git's current implementation requiring more expensive object verification. This exchange provides important technical details about the ref packing internals that future discussion will likely reference, particularly around the peeling behavior and potential optimization opportunities in the packed-backend.c implementation.
