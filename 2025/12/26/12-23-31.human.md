This is part 8 of an 11-part series refactoring Git's execution infrastructure to support structured hook handling. The patch adds output capture capability to the parallel process runner, allowing callers to intercept and process hook output rather than having it always go to stderr.

The change introduces a new `consume_output_fn` callback in `run-command.h` that receives hook output in a strbuf. This is particularly useful for server-side hooks that need to relay output to clients. The implementation maintains the existing behavior when no callback is provided, falling back to writing to stderr. A BUG() assertion prevents invalid combinations with the ungrouped output mode.

The patch includes tests demonstrating the new functionality, showing how output can be diverted to a file. This builds on the parallel execution infrastructure introduced earlier in the series while maintaining backward compatibility. The change has already been reviewed and signed off by key contributors including Emily Shaffer and Ævar Arnfjörð Bjarmason.

This appears to be a well-considered addition to the hook refactoring effort, with clear motivation, thorough testing, and attention to edge cases. As part of the now-mature v6 series, it represents one of the final pieces needed to complete the hook subsystem modernization.
