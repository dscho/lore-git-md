This is part 2 of a 13-part series refactoring Git's hook subsystem to use a new parallel execution API. The series has undergone extensive review and is now in its final iteration (v6) with all major technical concerns addressed.

The patch introduces a stdin callback mechanism for `run_processes_parallel()`, allowing efficient streaming of large inputs to child processes without buffering everything in memory. This solves a practical problem where hook input (like the pre-push hook's ref updates) could exceed pipe buffer sizes. The implementation:
- Adds a `feed_pipe_fn` callback type that streams data incrementally
- Handles SIGPIPE gracefully when children close their stdin early
- Includes comprehensive tests demonstrating parallel stdin feeding
- Maintains backward compatibility with existing hook behavior
- The change is foundational for converting remaining hooks to use the new parallel API in subsequent patches

This is a well-constructed patch with clear motivation, thorough test coverage, and careful attention to edge cases like signal handling. It represents a key building block in the larger hook refactoring effort that has been under development for years.
