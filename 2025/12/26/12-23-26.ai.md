This is part 3 of the hook subsystem refactoring series, focusing on adding a callback mechanism for feeding stdin to hooks. The patch introduces a new `feed_pipe_fn` callback in `struct run_hooks_opt` as an alternative to the existing file-based stdin approach (`path_to_stdin`), with strict BUG() assertions to prevent misuse of both mechanisms simultaneously.

Key technical changes include:
- New `feed_pipe` callback field in `run_hooks_opt` for streaming stdin without filesystem overhead
- Parallel execution support via integration with the `run-command` infrastructure from patch 1
- Two new opaque data pointers (`feed_pipe_ctx` and `feed_pipe_cb_data`) for callback state management
- Clear documentation of the callback mechanism in `hook.h` including memory ownership
- Assertions ensuring mutual exclusivity between file-based and callback stdin approaches

The implementation shows careful attention to thread safety and memory management, with explicit documentation of callback responsibilities. This builds on the parallel execution foundation from earlier in the series while maintaining the strict backward compatibility goals. The patch has already received sign-off from key reviewers (Emily Shaffer and Ævar Arnfjörð Bjarmason) and addresses all technical concerns raised in previous iterations.
