Hook subsystem refactoring: Adding ungroup option control. This patch is part of the v6 series standardizing Git's hook infrastructure, specifically addressing output grouping behavior in parallel hook execution.

The change introduces a new `ungroup` flag in `struct run_hooks_opt` to allow callers to control whether child process output should be grouped. Previously this was hardcoded to ungrouped mode (ungroup=1), which conflicts with sideband output reading in some hook contexts. The patch maintains the default ungrouped behavior for existing APIs (`run_hooks()` and `hook run` command) while making the behavior configurable via the new flag.

The implementation touches four files, adding the flag definition in hook.h and setting the default in builtin/hook.c, commit.c, and hook.c. Each location includes a note explaining why ungrouped output remains the default for that case. The change is straightforward and well-contained, with clear documentation of the new field's purpose.

This appears to be a minor but important refinement to the hook infrastructure, addressing a specific edge case (sideband output handling) while maintaining backward compatibility. As part of the extensively reviewed v6 series, it follows the established patterns from earlier patches and has already received sign-off from key reviewers.
