This is patch 4/11 in a series implementing the `extensions.submodulePathConfig` feature, which provides a solution for submodule gitdir path conflicts. The patch introduces the core extension infrastructure that makes `submodule.<name>.gitdir` the single source of truth for submodule paths when enabled.

Key technical elements:
- Adds new `repository_format_submodule_path_cfg` flag and extension handling
- Implements automatic config creation for new submodules via `create_default_gitdir_config()`
- Requires manual migration for existing submodules by setting `submodule.<name>.gitdir`
- Includes comprehensive tests in new `t7425-submodule-gitdir-path-extension.sh`
- Documents the extension and new config option in config documentation
- Modifies `submodule_name_to_gitdir()` to use the config when extension is enabled
- Adds validation that ensures gitdir paths are unique
- Updates error messages to guide users toward enabling the extension

The implementation enforces that the extension can only be enabled for new repositories during clone/init, as established in earlier thread discussion. The patch builds on prior consensus that this should be a pure runtime configuration without build-time options.

Test coverage verifies:
- Mixed environments with both legacy and new-style submodules
- Clone behavior with and without the extension enabled
- Path validation and error messaging
- Submodule operations after migration

The changes touch core submodule handling in `submodule.c`, repository initialization in `setup.c`, and add a new test library `t/lib-verify-submodule-gitdir-path.sh`. This is a well-structured patch that implements the agreed-upon approach from earlier thread discussion while maintaining backward compatibility.
