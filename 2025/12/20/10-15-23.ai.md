This is a feature patch in the submodule gitdir path encoding series, adding a migration command to automate configuration of existing submodules for the new path extension system.

The patch introduces `git submodule--helper migrate-gitdir-configs` to automatically create `submodule.<name>.gitdir` configurations for all existing submodules, which is required when enabling the `extensions.submodulePathConfig` extension. This addresses the practical concern that manual configuration would be tedious for repositories with many submodules. The command validates paths via `create_default_gitdir_config()` before writing configurations and ensures the repository format version and extension are properly enabled.

Key technical details:
- Scans `.git/modules/` directory to find existing submodules
- Skips submodules that already have gitdir configurations
- Uses `create_default_gitdir_config()` for validation and config creation
- Enforces repository format version 1 and extension enablement
- Adds comprehensive tests covering migration and post-migration clone behavior
- Documents the new command in extensions.adoc

The implementation builds on prior work in the series by:
- Leveraging the centralized path validation from earlier patches
- Maintaining the series' strict validation requirements
- Following the established pattern of atomic operations
- Adding test coverage that complements existing scenarios

This appears to be a well-integrated addition to the series, providing the missing piece for practical adoption of the path encoding extension while maintaining all the safety guarantees established in previous patches. The tests cover both the happy path and edge cases like recursive clones with mixed extension states.
