This is part 5/11 of the submodule gitdir path encoding series, implementing a feature to allow runtime enabling of the `extensions.submodulePathConfig` extension through a config option.

The patch adds `init.autoSetupSubmodulePathConfig` which, when set globally, will automatically enable the submodule path extension for new repositories created via `git init` or `git clone`. This provides a convenient way to opt into the new submodule path handling system without manual configuration for each new repository. Importantly, this only affects new repositories - existing ones still require explicit migration.

The implementation modifies `setup.c` to check for this config during repository initialization and conditionally enable the extension. It includes comprehensive test coverage in `t7425-submodule-gitdir-path-extension.sh` verifying behavior for both `init` and `clone` operations, with and without submodule recursion, and ensures the extension isn't enabled by default.

Key technical details:
- New config option `init.autoSetupSubmodulePathConfig` documented in config/init.adoc
- Extension documentation updated in config/extensions.adoc
- Modifies `init_db()` in setup.c to check the config and set extension
- Adds 5 new test scenarios covering init/clone behavior
- Maintains strict separation between new and existing repositories
- Follows the series' architectural principle of requiring explicit opt-in

This builds on the core extension infrastructure from earlier patches while maintaining the series' safety guarantees around existing repositories. The tests demonstrate the expected behavior when the config is set globally, including proper handling of recursive submodule operations.
