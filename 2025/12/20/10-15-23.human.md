This is part 6 of an 11-patch series implementing submodule gitdir path encoding via a new repository extension. The series has reached architectural consensus in its 7th iteration, with all major design questions resolved.

Adrian Ratiu introduces a new `git submodule--helper migrate-gitdir-configs` command to automate the migration of existing submodules to the new path configuration system. The command scans `.git/modules/`, validates each submodule's path, and creates the required `submodule.<name>.gitdir` configurations. It also enables the `extensions.submodulePathConfig` extension automatically after successful migration.

The patch includes comprehensive tests showing:
1. Successful migration of legacy submodules
2. Proper handling of recursive clones both with and without the extension enabled
3. Verification that the extension gets enabled after migration

This addresses a practical usability concern raised earlier in the thread - manually configuring gitdir paths for each submodule would be tedious. The implementation builds on previous work from Patrick Steinhardt and incorporates feedback from Junio Hamano. Test coverage appears thorough, exercising both the happy path and edge cases around recursive cloning.

The patch touches documentation, the submodule helper implementation, and test files. It's a key piece of the series' migration story, providing the bridge between legacy submodules and the new path encoding system.
