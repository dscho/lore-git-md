This is patch 4/11 in a series implementing the `extensions.submodulePathConfig` feature, which provides a new way to handle submodule gitdir paths to avoid filesystem conflicts and enable custom layouts. The patch introduces the core extension infrastructure.

The extension makes `submodule.<name>.gitdir` the single source of truth for submodule paths when enabled. New submodules automatically get this config set, while existing ones must be manually migrated. The patch adds documentation explaining the use cases (filesystem conflicts and custom layouts) and implements strict validation to ensure configs are properly set.

Key technical changes:
- Adds `repository_format_submodule_path_cfg` flag
- Implements extension handling in `setup.c`
- Adds comprehensive tests in `t7425-submodule-gitdir-path-extension.sh`
- Documents the extension and new config options
- Maintains backward compatibility while enforcing new rules when enabled
