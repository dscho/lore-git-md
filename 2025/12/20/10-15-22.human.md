This is part 5 of an 11-patch series implementing runtime configuration for submodule gitdir paths via a new `extensions.submodulePathConfig` extension. The series aims to prevent filesystem conflicts in submodule gitdirs and enable custom layouts.

Patch 5 adds a new `init.autoSetupSubmodulePathConfig` config option that allows automatically enabling the submodule path extension for new repositories created via `git init` or `git clone`. The implementation is conservative - it only affects new repositories and doesn't retroactively modify existing ones, which would require explicit migration. The patch includes thorough test coverage verifying the default behavior (extension disabled) and the new auto-enable behavior when configured.

The changes are well-contained, touching documentation, the repository setup code, and adding comprehensive tests. The commit message clearly explains the scope and limitations (no global enablement, migration still required for existing repos). This appears to be a straightforward addition that builds on the architectural consensus established earlier in the series.
