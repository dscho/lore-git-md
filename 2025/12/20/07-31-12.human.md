Maintainer discussion refining `git worktree prune` documentation. This is part of an ongoing documentation improvement series that started with clarifying terminology around "missing" worktrees and the `--expire` option, but has expanded to address fundamental documentation issues.

Junio and Eric Sunshine are working through the precise wording for explaining `git worktree prune`'s core purpose. They've identified that the current documentation has misleading phrasing about not touching the working tree (which is already missing in prune scenarios). The discussion has shifted from just terminology to properly documenting the three distinct worktree removal scenarios.

The latest proposal from Junio suggests clearer language that:
1. Explicitly states prune only affects worktrees with missing working directories
2. Recommends using `git worktree remove` for normal cleanup
3. Mentions `git worktree repair` for moved worktrees

Eric had pointed out logical inconsistencies in earlier phrasing, and they're now converging on more accurate documentation. This is part of broader documentation quality improvements that build on Julia Evans' prior work on clear explanations. The discussion remains focused on getting the technical details precisely right while maintaining good documentation practices.
