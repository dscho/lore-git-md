This is a documentation patch in an ongoing thread about clarifying `git worktree` terminology and behavior. The discussion has progressed to refining the exact wording for the `prune` subcommand's help text.

Eric Sunshine and Junio Hamano are collaborating on the final phrasing, having already resolved earlier issues about terminology standardization and redundant explanations. The current focus is on precisely describing when `prune` should be used versus `remove` or `repair`.

Junio initially proposed text that included a redundant "without touching the working tree" phrase, which Eric pointed out was misleading since `prune` only applies when the working tree is already missing. Junio then revised the text to clearly distinguish three scenarios: using `remove` for intentional deletion, `prune` for missing worktrees, and `repair` for moved worktrees.

The exchange shows the maintainers paying close attention to both technical accuracy and user guidance, ensuring the documentation helps users choose the right command for their situation. This level of detail in the help text will likely prevent common user mistakes when managing worktrees.
