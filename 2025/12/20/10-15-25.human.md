This is part 8 of an 11-patch series implementing submodule gitdir path encoding to prevent filesystem collisions. The series introduces a new `extensions.submodulePathConfig` extension that enables URL-encoding of submodule gitdir paths when needed.

This specific patch focuses on fixing filesystem collisions by implementing URL-encoding for submodule gitdir paths when the new extension is enabled. The encoding uses RFC3986 rules (via a helper function moved from credential-store to url.[ch]) to safely encode problematic characters in submodule names that could otherwise create nested gitdir paths.

The patch adds three key components:
1. URL-encoding support in `create_default_gitdir_config()` that tries plain names first, then falls back to encoded versions
2. A new validation function `validate_submodule_encoded_git_dir()` that enforces path safety rules when the new extension is active
3. Comprehensive tests verifying the encoding works for nested submodule cases, including parallel cloning scenarios

The implementation maintains backward compatibility - existing submodules continue working without encoding, while new problematic cases get automatically encoded. The tests demonstrate this handles tricky cases like submodules named "hippo/hooks" that would previously create nested gitdirs.
