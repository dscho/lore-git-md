This is part 8/11 of a feature series implementing submodule gitdir path encoding to prevent filesystem collisions. The patch focuses on URL-encoding gitdir paths when the `extensions.submodulePathConfig` extension is enabled, specifically addressing nested submodule directory conflicts.

The key technical changes:
- Adds RFC3986 URL encoding for submodule gitdir paths when the path config extension is active, using the newly shared `is_rfc3986_unreserved()` helper
- Implements a new `validate_submodule_encoded_git_dir()` that enforces path encoding rules while the legacy validation remains for non-extension cases
- Modifies `create_default_gitdir_config()` to try plain names first, then fall back to URL-encoded versions
- Adds comprehensive tests for nested submodule scenarios, including parallel cloning cases

The implementation maintains backward compatibility while solving the nested gitdir problem through encoding. The tests verify both the encoding behavior and proper interaction with parallel submodule operations. This builds on the series' earlier work to centralize path resolution while adding the critical collision-avoidance mechanism.

The patch touches core submodule handling in `submodule.c` and `builtin/submodule--helper.c`, expanding the test suite with new nested submodule scenarios. It depends on the URL encoding helper moved in an earlier patch and integrates with the centralized path resolution established in previous patches.
