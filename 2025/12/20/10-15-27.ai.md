Feature patch in the submodule gitdir path encoding series, implementing a final fallback mechanism for path conflicts.

This patch adds a last-resort conflict resolution strategy for submodule gitdir paths by hashing the submodule name when all other attempts (plain name, encoded name, and numbered variants) fail to find a conflict-free path. The hash-based approach loses human readability but ensures a unique path can always be found. The implementation uses Git's standard hashing infrastructure to generate the path name.

The change is part of the larger effort to handle submodule gitdir paths safely on case-insensitive filesystems and allow custom path layouts. This particular patch addresses the edge case where even the previous fallback mechanisms (including case-aware encoding and numbered variants) would fail to find a conflict-free path. The test case demonstrates this by creating multiple conflicting variants of "foo" submodules until the hashing fallback is triggered for an uppercase "Foo" variant.

- Uses standard Git hash-object style formatting (blob header + content)
- Comprehensive test in t7425 that forces the hashing fallback by exhausting all other options
- Maintains the existing validation flow through `validate_and_set_submodule_gitdir()`

The patch represents the final piece of the conflict resolution strategy in this series, completing the four-tier fallback system (plain -> encoded -> numbered -> hashed).
