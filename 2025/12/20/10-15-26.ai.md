This is a feature patch in the submodule gitdir path encoding series, specifically addressing case-folding filesystem collisions when the submodulePathConfig extension is enabled. The patch adds a new case-folding check and encoding mechanism to prevent directory conflicts on case-insensitive filesystems.

The key technical changes include:
- A new `is_casefolding_rfc3986_unreserved()` helper in url.[ch] that treats uppercase letters as reserved characters requiring encoding
- Enhanced `validate_submodule_encoded_git_dir()` that checks for case-folding conflicts using a new `check_casefolding_conflict()` function
- A multi-stage fallback in `create_default_gitdir_config()` that first tries plain encoding, then case-folding-aware encoding, and finally appends digits if conflicts remain
- Comprehensive test cases in t7425 that verify behavior with mixed-case submodule names on case-insensitive filesystems

The patch maintains backward compatibility while adding protection against filesystem collisions, particularly important for Windows and macOS users. It's part of the broader effort to enable custom submodule gitdir paths through runtime configuration rather than build-time options. The implementation follows the series' established pattern of centralized validation in `submodule_name_to_gitdir()` while adding new test coverage for edge cases.
