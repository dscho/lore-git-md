The patch adds detection and prevention of case-folding collisions when `extensions.submodulePathConfig` is enabled. It introduces a new RFC3986-based encoding variant that percent-encodes uppercase characters only when necessary (on case-insensitive filesystems), preserving the original paths where possible. The implementation includes:

1. A new `check_casefolding_conflict()` function that scans for existing directories that would collide due to case-folding
2. Enhanced validation in `validate_submodule_encoded_git_dir()` to trigger the stricter encoding when needed
3. A fallback mechanism that appends digits if conflicts persist
4. Comprehensive test cases demonstrating the handling of various collision scenarios

The changes maintain backward compatibility while solving a real problem - submodules with names differing only in case would previously collide on case-insensitive filesystems. The solution is well-integrated with the existing path encoding infrastructure and includes thorough test coverage.
