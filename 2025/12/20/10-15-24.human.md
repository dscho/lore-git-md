This is a refactoring patch in the submodule gitdir path encoding series, moving a URL encoding helper function to a more widely accessible location.

The patch relocates `is_rfc3986_unreserved()` from `builtin/credential-store.c` to `url.[ch]` where it can be shared by multiple subsystems. This function checks if a character is safe to use in URLs without encoding. The move is motivated by the need to use this same encoding logic when constructing gitdir paths for submodules to avoid filesystem conflicts.

The change is straightforward - the function implementation is moved to `url.c` with its declaration added to `url.h`, and the credential-store code is updated to include the header. The commit message explains the rationale well, noting this was previously made static function when it was only used by credential-store, but now needs to be shared with the submodule system.

This appears to be a clean, well-justified refactoring that enables code reuse between subsystems. The patch is part of a larger series implementing submodule path encoding, with this change providing a shared building block for the URL encoding functionality needed in subsequent patches.
