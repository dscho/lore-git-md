This is a technical critique in the ongoing discussion about the `git-history` command's branch selection strategy. Elijah Newren pushes back strongly against Patrick Steinhardt's proposed HEAD-to-commit walk approach for determining which branches to rewrite during history editing operations.

Newren makes several key arguments:
1) The performance concerns about walking all local branches are overstated, especially with commit-graphs enabled, and cites Jujutsu's successful implementation of this approach at scale.
2) The current proposal creates a "principle of least astonishment" violation by potentially disconnecting branches with shared history.
3) He clarifies that only refs/heads/* (local branches) should be considered for rewriting, excluding remotes and tags which should remain immutable.

The email serves as a substantive technical challenge to the current direction, suggesting the simpler comprehensive branch walking approach would both be more consistent and potentially easier to implement. Newren emphasizes that any performance costs would be justified by avoiding user confusion from inconsistent branch states. This continues the thread's central debate about how to balance performance, implementation complexity, and user expectations in multi-branch history editing.
