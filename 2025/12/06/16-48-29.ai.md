This is a follow-up discussion in the submodule gitdir path encoding series, specifically addressing build-time configuration considerations that were previously debated. Junio Hamano reaffirms his position against build-time configuration options, emphasizing that runtime configuration via `/etc/gitconfig` should be the sole mechanism for enabling submodule path encoding. The exchange with Patrick Steinhardt confirms mutual agreement that even a hypothetical build-time-influenced default (like tying it to `WITH_BREAKING_CHANGES`) would add unnecessary complexity without clear benefit.

The discussion solidifies the architectural decision to keep the feature purely runtime-configurable, which aligns with the series' principle of maintaining config authority. This email serves as final confirmation that the build-time configuration approach explored in patch 7/7 of v5 will not be pursued, closing that avenue of discussion. The thread context shows this was the last major design question before the series' finalization, with only implementation of the atomic enablement command and transition documentation remaining for v6.
