This is a bugfix targeting the histogram diff algorithm in xdiff. The patch addresses a rare but visually confusing case where shifted change groups in the compaction phase can create redundant diff output that includes matching lines from both files. The author provides both synthetic and real-world examples showing how the current histogram diff can incorrectly include unchanged lines in its output.

The fix detects when shifting has created new matching groups and re-diffs those sections using Myer's algorithm to remove redundant unchanged lines. The change is specific to histogram diff since other algorithms (Myer's and patience) either already produce minimal diffs or use anchors that prevent this issue. The patch includes thorough test coverage with multiple scenarios demonstrating the problem and verifying the fix works correctly.

Key technical details:
- Adds logic in xdl_change_compact() to detect shifted groups that may need re-diffing
- Only triggers for histogram diff (XDF_HISTOGRAM_DIFF)
- Uses existing xdl_fall_back_diff() infrastructure with original diff flags
- Preserves all diff flags during re-diff (shown in --ignore-all-space test)
- Includes new test file t4073-diff-shifted-matched-group.sh with 3 test cases

The commit message provides clear motivation with both abstract and concrete examples, and the implementation appears well-considered with attention to edge cases. The author notes this affects <1% of diffs in surveyed repositories, but fixes a clearly undesirable output when it does happen.
