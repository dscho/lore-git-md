Performance feature completing Taylor Blau's MIDX compaction series, enabling bitmap support during multi-pack index compaction. This final patch (17/17) allows combining reachability bitmaps from compacted MIDX layers while preserving pseudo-pack ordering, a key requirement for bitmap validity. The implementation treats all objects as non-preferred during compaction to maintain object ordering, with future potential for more sophisticated bitmap combination strategies.

The patch adds a `--bitmap` option to `git multi-pack-index compact` and includes extensive test coverage in t5335, verifying: bitmap preservation across compactions, pack object selection integrity, and handling of non-trivial commit graphs. The tests demonstrate compaction with both lex-ordered and unordered pack names, plus complex scenarios with multiple branches and merges.

This builds on the series' earlier work (patches 1-16) that refactored MIDX internals to support compaction, particularly the pseudo-pack ordering scheme established in previous commits. The implementation is careful to maintain backward compatibility while removing lexicographic pack ordering requirements. The test additions follow the pattern of earlier patches in the series, providing thorough coverage of the new bitmap handling during compaction.

Key technical aspects include: the `MIDX_WRITE_BITMAP` flag handling in builtin/multi-pack-index.c, the `midx_pack_order()` modification in midx-write.c to force non-preferred status during compaction, and the new test cases verifying bitmap behavior. The documentation update reflects the new `--bitmap` option availability for the compact subcommand.
