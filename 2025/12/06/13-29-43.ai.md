Security patch banning insecure `mktemp(3)` function as part of the ongoing secure tempfile creation series. This is the fourth patch in a 5-part series (now expanded to 6 patches in v2) that systematically eliminates insecure temporary file/directory creation patterns across Git's codebase.

The patch adds `mktemp(3)` to `banned.h`, preventing its future use in the codebase. The commit message explains the security rationale: older versions generate predictable filenames and suffer from TOCTOU races where another process could create the file between the name generation and actual creation. The function was removed from POSIX standard due to these security concerns.

This change builds on the series' earlier work that introduced secure alternatives (`git_mkstemps_mode()` and `git_mkdtemp()`). The patch is straightforward, adding just 3 lines to `banned.h` to mark `mktemp` as forbidden. The implementation follows the established pattern in this file, using the `BANNED` macro that will cause compilation to fail if the function is used.

The patch appears well-motivated and uncontroversial, as the thread context shows consensus around removing insecure tempfile functions. It completes the logical next step after the previous patches migrated all callers to secure alternatives. The change is part of Git's proactive security hardening efforts, eliminating vulnerable patterns before they can be exploited.
