This is a technical discussion about Windows symlink handling in patch 3/10 of Johannes Schindelin's series preparing Git for MSYS2's symlink support. The patch addresses how Windows' _wopen() behaves differently from POSIX when creating files with O_CREAT|O_EXCL on symlinks.

Junio Hamano pushes back on the commit message's framing, arguing the fix should be described as making Windows behave like POSIX rather than specifically like Linux. He emphasizes this isn't just pedantry - future maintainers reading the commit message should understand the code's intent is POSIX compliance, not Linux emulation. The technical solution itself isn't in dispute, but the documentation approach is being refined to better capture the project's cross-platform philosophy.

This continues the pattern from earlier in the thread where the technical solutions are settled but commit message clarity is being polished. The exchange shows the maintainer's attention to how changes will be understood years later, not just whether they work today.
