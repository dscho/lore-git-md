Performance optimization for promisor pack handling. This patch speeds up operations involving promisor objects (used in partial clone) by avoiding unnecessary blob decompression and hash verification when initializing the promisor object set.

The current implementation fully parses every object when first building the set of promisor objects, which can be extremely slow for large repositories - the example shows a 176GB pack taking over 76 minutes. The key insight is that while commits, trees need full parsing (since they reference other objects), blobs can be handled just by their OIDs since they don't reference anything else.

The patch modifies `parse_object_with_flags()` to properly handle objects marked as `OBJ_NONE` (which happens during `mark_uninteresting()`) and then updates `add_promisor_object()` to use `PARSE_OBJECT_SKIP_HASH_CHECK` for blobs. The results are dramatic - the same operation drops from 76 minutes to under 2 minutes in the test case.

The changes are minimal (4 lines modified across 2 files) and well-explained, with clear before/after performance measurements. This appears to be a straightforward optimization that should be uncontroversial, though reviewers may want to verify the safety of skipping hash checks in this context. The v2 revision addresses handling of UNINTERESTING objects, showing responsive iteration on feedback.
