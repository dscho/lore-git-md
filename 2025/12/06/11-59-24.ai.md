This is a discussion about the submodule gitdir path encoding series, specifically addressing how to handle repositories where the extension is manually enabled after submodules exist.

Patrick Steinhardt responds to Junio Hamano's clarification about configuration authority in the submodule path encoding system. The key concern is how to handle repositories where someone manually enables the extension after submodules are already initialized - in these cases, the gitdir paths wouldn't exist in gitconfig yet. Patrick argues that falling back to alternate path resolution methods in this case would undermine the extension's purpose of having the config be the single source of truth.

He proposes a solution where users would never manually enable the extension, but instead use a dedicated command that would both persist existing submodule gitdirs to config and enable the extension atomically. This would ensure the config always contains the necessary gitdir paths when the extension is active. If the config is missing required entries, Git would error out with a helpful message rather than falling back to legacy behavior.

The discussion continues the thread's focus on maintaining strict configuration authority while ensuring practical usability. Patrick's suggestion aims to close a potential loophole where the extension's guarantees could be violated through manual configuration changes. This would affect the implementation of the path resolution fallback system and error handling in the submodule initialization paths.
