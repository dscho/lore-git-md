This thread addresses a bugfix for the histogram diff algorithm (XDF_HISTOGRAM_DIFF) in xdiff, where shifted change groups during compaction could produce redundant diff output showing matching lines from both files. The issue was identified in two specific edge cases, one where no further shifting was needed but previous shifts had occurred, and another where slide-up shifting remained.

Yee Cheng Chin submitted the initial patch, which was reviewed by Phillip Wood and Junio Hamano. Phillip confirmed the need to handle both cases and suggested improving code comments, while Junio indicated flexibility on implementation details while emphasizing future readability. The solution involves detecting when shifting creates new matching groups and re-diffing those sections using Myer's algorithm while preserving all original diff flags.

The v2 patch has now been submitted with several refinements: simplified entry condition checking, removal of redundant tracking, use of assignment instead of memcpy(), improved comments and test case naming, and an additional test case. The comprehensive test coverage in t/t4074-diff-shifted-matched-group.sh demonstrates both triggering scenarios and verifies proper handling of diff flags.

All technical concerns have been resolved with consensus on the approach, and the patch is now ready for merging. The commit message provides clear motivation with examples showing this affects less than 1% of diffs but fixes clearly undesirable output when it occurs. The thread has progressed efficiently from problem identification through review to a technically sound solution now awaiting final merge.
