This thread addresses a bug in the histogram diff algorithm (XDF_HISTOGRAM_DIFF) where shifted change groups during compaction can produce redundant diff output containing matching lines from both files. The proposed fix detects these cases occur and re-diffs the affected sections using Myer's algorithm while preserving all original diff flags.

Phillip Wood has been actively reviewing the implementation, raising concerns about memory safety (preferring direct assignment over memcpy) and questioning whether checking both file groups is necessary. Junio C Hamano suggested extracting the new logic into a helper function for clarity. In the latest exchange, Phillip explains why completely disabling group shifting - as Junio wondered about - would be worse, as it would prevent useful coalescing of changed lines and interfere with the indent heuristic. He notes this may point to a deeper characteristic of histogram diff producing harder-to-read output compared to patience diff in some cases.

The discussion continues to focus on refining the implementation details while maintaining the core approach. Test coverage exists in t4073-diff-shifted-matched-group.sh with three cases verifying the fix. While the technical solution is considered sound, the conversation remains active around Phillip's review comments regarding code safety and maintainability.
