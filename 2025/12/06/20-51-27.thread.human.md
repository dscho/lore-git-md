This thread focuses on fixing an edge case in Git's histogram diff algorithm (XDF_HISTOGRAM_DIFF) where shifted change groups during compaction could incorrectly include matching lines from both files in the diff output. The issue is specific to histogram diff, as other algorithms like Myer's and patience diff either naturally avoid this problem or use anchors to prevent it.

The proposed solution detects when shifting creates new matching groups and re-diffs those sections using Myer's algorithm while preserving all original diff flags (including space-ignoring options). The patch includes test coverage in t4073-diff-shifted-matched-group.sh with three test cases demonstrating the fix.

Junio C Hamano and Phillip Wood have been actively reviewing the implementation. Phillip raised two specific concerns: whether checking both file groups is necessary (since they should move in sync), and whether memory handling could be made safer by using direct assignment rather than memcpy. He also questioned if a full re-diff is always needed versus just marking common prefixes/suffixes, though acknowledged complex cases likely require the full diff approach. These discussions build on Junio's earlier suggestion to extract the new logic into a helper function for better code organization.

While this edge case affects fewer than 1% of diffs, the fix addresses clearly undesirable output when it occurs. The thread shows the core approach - using Myer's algorithm to correct histogram diff's suboptimal output in this specific scenario - remains sound, with the discussion now focused on refining implementation details for robustness and maintainability.
