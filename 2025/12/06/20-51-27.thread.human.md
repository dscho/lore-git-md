This thread addresses a bug in the histogram diff algorithm (XDF_HISTOGRAM_DIFF) where shifted change groups during compaction could produce redundant diff output containing matching lines from both files. The issue is specific to histogram diff, as Myer's and patience algorithms either naturally produce minimal diffs or use anchors that prevent this problem.

The proposed fix adds logic in xdl_change_compact() to detect when shifting creates new matching groups, then re-diffs those sections using Myer's algorithm via xdl_fall_back_diff() while preserving all original diff flags. The implementation has evolved through review - initially checking both file groups during compaction, then being refined to check just one group with safer memory handling. Junio C Hamano suggested extracting the new logic into a helper function for clarity, which has been implemented.

Phillip Wood provided key technical insights, confirming that completely disabling group shifting would be worse as it prevents useful coalescing of changed lines and interferes with the indent heuristic. He also observed that histogram diff sometimes produces harder-to-read diffs than patience diff as an inherent characteristic, though this patch doesn't address that broader issue.

The commit message clearly explains the motivation with examples, noting this affects fewer than 1% of diffs but fixes clearly undesirable output when it occurs. Test coverage in t4073-diff-shifted-matched-group.sh verifies the fix across scenarios. With all substantive technical concerns resolved and only minor refinements remaining, the patch appears ready for merging.
