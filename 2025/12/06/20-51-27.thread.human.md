This thread addresses a bug in Git's histogram diff algorithm where shifted change groups during compaction could incorrectly include unchanged lines in the diff output, creating redundant and confusing output. The patch author has identified a specific edge case where the histogram diff's compaction phase can produce non-minimal diffs by including matching lines from both files.

The fix introduces logic to detect when shifting has created new matching groups that should be re-diffed using Myer's algorithm to maintain minimal output. The change is carefully scoped to only affect the histogram diff algorithm (XDF_HISTOGRAM_DIFF) since other diff strategies either already produce minimal output or use different anchoring that prevents this issue. The implementation builds on existing fallback diff infrastructure while preserving all diff flags during re-diffing.

The patch includes comprehensive test coverage with a new test file (t4073) containing multiple scenarios that demonstrate both the problem and the effectiveness of the fix. The author provides clear examples showing this affects a small fraction of diffs (<1% in surveyed repositories), but fixes a clearly undesirable output when it does occur. The implementation appears well-considered with attention to edge cases and flag preservation.
