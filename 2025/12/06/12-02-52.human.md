This is a discussion about build-time vs runtime configuration for the submodule path encoding feature, part of the ongoing submodule gitdir path encoding series.

Patrick Steinhardt responds to Junio Hamano's skepticism about build-time configuration options for enabling submodule encoding. While acknowledging Junio's preference for pure runtime configuration via `/etc/gitconfig` in managed environments, Patrick suggests a potential middle ground: making the feature runtime-configurable but allowing its default to be set at build time (e.g., tied to a `WITH_BREAKING_CHANGES` flag). However, he expresses personal doubt about whether this build-time default would actually be valuable.

The exchange highlights the series' ongoing tension between making the feature easily adoptable while maintaining clean configuration semantics. Junio maintains his position that runtime configuration is sufficient, especially for corporate environments with centralized config management. This discussion appears to be closing out the build-time configuration question in favor of the runtime approach, with Patrick's message serving as a thoughtful but ultimately conceding response to Junio's concerns.
