Submodule gitdir path encoding discussion - follow-up on configuration strictness

Patrick Steinhardt responds to Junio Hamano's guidance about making submodule gitdir paths strictly configuration-based when the extension is enabled. The thread had previously settled on requiring complete `submodule.<name>.gitdir` configuration entries when the path encoding extension is active, rejecting any fallback path derivation.

Patrick identifies one remaining edge case: repositories where someone manually enables the extension after submodules are already initialized, leaving the config incomplete. He argues that allowing fallback behavior in this case would undermine the extension's purpose of providing a single source of truth. Instead, he proposes introducing a dedicated command that would both record existing submodule paths in config and enable the extension atomically.

This appears to be the last architectural question before the series can be finalized. The discussion shows careful attention to maintaining consistency while avoiding migration pain - a balance the thread has been working through across multiple iterations. Patrick's suggestion would close the loop on configuration strictness while providing users a clear migration path.
