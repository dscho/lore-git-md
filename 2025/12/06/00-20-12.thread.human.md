This thread focuses on optimizing how Git handles promisor packs (lazy-fetching partial clones) by reducing unnecessary object decompression and hash verification. The original patch from Aaron Plattner showed dramatic improvements - reducing processing time for 176GB promisor packs from 76 minutes to under 2 minutes by skipping hash checks for blobs. 

Jeff King (Peff) reviewed the approach, agreeing with the technical implementation but suggesting the fix for `OBJ_NONE` handling (from `mark_uninteresting()`) be split into a separate bugfix patch, and that the commit message better document why skipping hash checks is safe. In his latest response, Aaron agrees to split out the `OBJ_NONE` fix but now questions whether skipping hash verification for all object types (not just blobs) might risk missing on-disk corruption, since trees and commits are actually used for their contents. He proposes three options: creating a blob-specific flag, reverting to the original approach, or keeping the current version if the risk is acceptable.

The core optimization remains technically sound with consensus, but the discussion has shifted to weighing the safety tradeoffs of hash verification skipping, particularly for non-blob objects. Aaron will proceed with splitting out the `OBJ_NONE` fix while the broader question about hash verification safety is resolved. The thread references prior work in commit c868d8e91f regarding object parsing optimizations.
