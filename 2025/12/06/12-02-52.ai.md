This is a discussion about build-time vs runtime configuration for the submodule path encoding feature, part of the ongoing submodule gitdir path encoding series.

Patrick Steinhardt responds to Junio Hamano's skepticism about build-time configuration options for enabling submodule encoding. While acknowledging Junio's preference for pure runtime configuration via `/etc/gitconfig` in managed environments, Patrick suggests a potential middle ground where runtime configuration could have defaults set at build time, perhaps tied to the existing `WITH_BREAKING_CHANGES` flag. However, he expresses personal doubt about whether this build-time aspect is actually necessary.

The exchange highlights the architectural tension between making the feature easily adoptable (which might suggest build-time defaults) versus maintaining clean runtime configuration (Junio's position). This comes after earlier consensus that the extension should require explicit configuration when enabled, with Patrick having previously identified edge cases around post-initialization enablement.

Key technical points mentioned:
- Runtime `extensions.submoduleEncoding` config option
- System-wide `/etc/gitconfig` as preferred enablement path
- Potential build-time influence on runtime defaults via `WITH_BREAKING_CHANGES`
- Maintained principle of config authority when extension is active

The discussion represents final fine-tuning of the configuration approach before the series' expected v6, which will incorporate Patrick's atomic enablement command proposal while adhering to Junio's strict config requirements. The build-time question appears to be settling toward Junio's runtime-only position, with Patrick's comment serving as a final consideration of alternatives.
