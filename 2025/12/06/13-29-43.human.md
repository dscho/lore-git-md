Security patch banning insecure `mktemp(3)` function.

This is the fourth patch in a security-focused series eliminating insecure temporary file handling in Git. It adds `mktemp(3)` to the `banned.h` list of prohibited functions, preventing any new uses from being introduced. The commit message explains that `mktemp(3)` creates easily guessable filenames and has race conditions that make it unreliable - problems serious enough that POSIX removed the function entirely.

The change is straightforward, adding just 3 lines to `banned.h`. This comes after earlier patches in the series migrated all existing callers to safer alternatives. René Scharfe has been leading this effort, with previous patches introducing secure replacements and removing compatibility wrappers. The series has seen thorough review from Jeff King and Junio Hamano, with consensus that removing these insecure functions is worthwhile proactive hardening.

This patch represents a key milestone in the series - once merged, Git codebase will be permanently protected against reintroduction of this problematic API. The implementation is clean and minimal, building on the foundation established by earlier patches that handled the migration work. There's clear security value in banning the function rather than just migrating existing callers, as it prevents future regressions.
