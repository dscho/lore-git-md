This is a feature discussion about version control for structured data, continuing the thread evaluating existing alternatives to modifying Git.

Cedric Sodhi responds to René Scharfe's suggestion of DVC and Dolt as potential "Git for data" solutions. He clarifies that his original proposal specifically concerned versioning structured but text-like data (analogous to source code) rather than binary blobs. Sodhi analyzes both tools: DVC appears focused on large binary data management (similar to Git LFS) and thus doesn't match his use case, while Dolt - though functionally aligned - introduces new architectural concerns by being a standalone system that bundles both Git-like interfaces and its own SQL server.

The response maintains the original thread's technical focus while narrowing the evaluation criteria. Sodhi's analysis suggests neither tool fully satisfies his requirements: DVC solves the wrong problem (binary vs structured data), while Dolt introduces new dependencies and architectural constraints. This keeps open the original question of whether Git modifications might still be preferable, though no new technical details about such modifications are proposed in this response.

Key technical points carried forward: the distinction between binary/opaque data (DVC's domain) versus structured/text-like data (Sodhi's focus), and the architectural tradeoffs of Dolt's bundled SQL server. The thread remains in an evaluative phase regarding external solutions versus Git modifications.
