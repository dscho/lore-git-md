This is the core implementation patch (16/17) in Taylor Blau's series adding MIDX compaction functionality. The patch introduces a new `git multi-pack-index compact` command that combines adjacent MIDX layers into a single layer while preserving the MIDX chain and bitmap validity.

Key technical components:
- New `fill_packs_from_midx_range()` function walks backwards through the compaction range to gather packs while preserving pseudo-pack order (preferred packs first)
- `compute_sorted_entries()` adjusts pack_int_id mappings to maintain original pack references
- MIDX chain file updates replace the compacted range with the new single layer
- New test script `t5335-compact-multi-pack-index.sh` verifies compaction works with both lexicographically ordered and unordered pack names
- Compaction preserves object uniqueness across all layers in the chain

The implementation handles several tricky aspects:
- Maintaining bitmap validity by preserving pack ordering
- Correctly mapping original pack_int_id values through the compaction
- Properly updating the MIDX chain file to replace the compacted range
- Supporting both incremental and standalone compaction modes

The patch builds on previous refactoring in the series (particularly the pack permutation helpers from patch 9/17) and introduces the core compaction algorithm that will be used in the final geometric repacking strategy. Tests demonstrate the functionality works regardless of pack naming order, a key requirement for the geometric repacking use case.
