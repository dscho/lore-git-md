This is a performance optimization patch targeting the promisor pack handling code. The change focuses on `add_promisor_object()` which currently decompresses and hashes all objects when initializing the promisor object set, even though blobs don't need this processing since they don't reference other objects.

The patch makes two key changes: First, it updates `parse_object_with_flags()` to properly handle objects marked as `OBJ_NONE` (which come from `mark_uninteresting()`), allowing them to skip unnecessary processing. Second, it modifies `add_promisor_object()` to use `PARSE_OBJECT_SKIP_HASH_CHECK` for blobs. The results are dramatic - the example shows a reduction from 76 minutes to under 2 minutes for processing a 176GB promisor pack.

The technical changes are minimal (4 lines modified across 2 files) but impactful. The patch touches core object handling code in `object.c` and promisor pack processing in `packfile.c`. Key functions involved are `parse_object_with_flags()` and `add_promisor_object()`, with the `PARSE_OBJECT_SKIP_HASH_CHECK` flag playing a central role. The optimization specifically benefits repositories with large promisor packs, and the commit includes clear before/after benchmarks showing the improvement.
