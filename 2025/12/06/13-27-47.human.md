This is part 2 of a security-focused series replacing insecure `mktemp(3)` usage with safer alternatives. The patch migrates the Windows compatibility layer to use the new `git_mkdtemp()` function introduced in the series' foundation patch.

René Scharfe simplifies the Windows-specific `gitmkdtemp()` implementation by replacing its manual `mktemp()+mkdir()` sequence with a direct call to the new secure `git_mkdtemp()` wrapper. The change eliminates a potential security race where a file could appear between the temporary name generation and directory creation steps. The new version is both safer and simpler, removing 3 lines of manual error handling code.

This is a straightforward migration that follows the series' established pattern of replacing insecure temp file/directory creation with the new unified secure infrastructure. The patch appears well-contained, touching only the Windows compatibility code, and builds on the consensus already established in the thread about removing redundant layers.

The change is part of a larger effort to harden Git against potential security issues by proactively eliminating unsafe functions before exploits emerge. Reviewers including Jeff King and Junio Hamano have already approved the general approach in earlier discussion.
