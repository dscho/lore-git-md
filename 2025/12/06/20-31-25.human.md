This is a performance optimization patch in Taylor Blau's MIDX compaction series, specifically addressing a constraint that was making incremental repacking difficult. The patch removes the requirement that packs in a multi-pack index (MIDX) be stored in lexicographic order, which was previously needed for efficient pack lookup via binary search. The change enables more flexible MIDX layer compaction by allowing packs to be arranged in pseudo-pack order (with the preferred pack first) rather than alphabetically.

The key insight is that while lexicographic ordering was convenient for implementing `midx_contains_pack()` efficiently, it's not fundamentally necessary. The patch maintains the O(log n) lookup performance by lazily building a sorted index of pack names when needed for searching, stored in a new `pack_names_sorted` array. This allows the actual pack ordering to follow the pseudo-pack order needed for bitmap compatibility during compaction.

The change makes MIDX files produced by new Git versions potentially incompatible with older versions that enforced strict ordering, though the patch notes existing Git versions will gracefully handle such MIDX files. Test changes remove now-unneeded ordering checks. This is a well-motivated change that removes an artificial constraint while maintaining performance characteristics, advancing the series' goal of efficient MIDX compaction.
