This is part 2 of an 11-part series refactoring Git's hook subsystem to use a new parallel execution API. The patch introduces stdin handling capabilities to `run_processes_parallel()` through a new `feed_pipe_fn` callback mechanism.

The key technical addition is a streaming stdin interface that allows incremental feeding of large inputs to child processes without buffering everything in memory. The implementation:
- Adds `feed_pipe_fn` callback type and field in `run_process_parallel_opts`
- Introduces new helper functions `child_is_ready_for_cleanup()` and `child_is_receiving_input()` for state management
- Implements `pp_buffer_stdin()` to handle the feeding logic with proper error handling
- Adds SIGPIPE handling since child processes may close their stdin pipes early
- Includes comprehensive tests demonstrating the functionality via a new `run-command-stdin` test mode

The changes maintain backward compatibility while enabling the hook conversion work in subsequent patches. The stdin handling is designed to work with both grouped and ungrouped parallel execution modes, with careful attention to avoiding deadlocks when processes block on input.

This foundational work enables later patches to convert hooks that need to stream large amounts of data (like reference updates) to child processes. The implementation follows the established pattern of the parallel execution API while solving the specific problem of incremental stdin feeding that was previously handled in an ad-hoc manner (as noted in the transport.c example).
