This is part 5 of an 8-part series improving object info reading in Git's object database layer, specifically focusing on refactoring the `packed_object_info()` function's return value handling.

The patch simplifies the return value semantics of `packed_object_info()` to just indicate success (0) or failure (negative error code), rather than mixing in object type information. This change is possible because the last caller that relied on the old return value was removed in a previous patch. The simplification enables a small optimization by allowing the function to skip reading object types in some cases.

The changes touch core packfile handling code, modifying both the implementation in packfile.c and updating the documentation in packfile.h. The patch appears to be a clean, focused improvement that maintains backward compatibility while making the code's behavior more straightforward. This continues the series' pattern of incremental infrastructure improvements to support future work on object database functionality.
