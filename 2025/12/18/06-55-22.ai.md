Refactoring patch in Patrick Steinhardt's series moving packfile handling to ODB sources. This patch (3/10) focuses on the kept-pack cache, which tracks packfiles marked as kept either via ".kept" files or in-memory flags.

The change reorients the kept-pack cache to operate on packfile stores rather than repositories, preparing for the series' goal of per-source packfile stores. Key technical changes include:
- Renaming `kept_pack_cache()` to `packfile_store_get_kept_pack_cache()`
- Replacing `ON_DISK_KEEP_PACKS`/`IN_CORE_KEEP_PACKS` flags with explicit `enum kept_pack_type` (KEPT_PACK_ON_DISK/KEPT_PACK_IN_CORE)
- Updating cache invalidation logic to work with packfile stores
- Modifying callers in pack-objects.c, reachable.c, and revision.c to use new names and flags

The patch maintains existing behavior while shifting the architectural foundation. Justin Tobler previously reviewed this patch in v1, suggesting documentation improvements which Patrick implemented. The changes are mechanical but important for the series' goal of moving packfile operations to source level, with transitional edge cases noted for future resolution.
