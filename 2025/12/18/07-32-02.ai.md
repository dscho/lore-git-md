This is a bugfix discussion in the ongoing object info reading improvements series, specifically addressing patch 4/8 which ensures pack-specific info is always populated. Junio Hamano points out a latent issue with the `blank_oi` static variable usage in `packfile_store_read_object_info()`.

The core concern is that the current approach modifies the supposedly blank `blank_oi` when checking for empty requests via pointer comparison, which could affect subsequent calls. Junio notes this violates the blankness guarantee and suggests fixing the fundamental issue with `blank_oi` before proceeding with the patch's changes. The problematic code would populate pack-specific fields in the static `blank_oi` when checking for empty requests, potentially leaking that state to future calls.

This discussion follows an earlier patch in the series that introduced `object_info_is_blank_request()` to replace pointer comparison with content checking, which would resolve this issue. The exchange highlights the need for careful handling of static state in core object database operations, particularly around the transition to more robust object info flag handling being introduced in this series.
