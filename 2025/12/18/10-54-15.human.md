This is part 3 of a 7-patch series improving object info reading in Git's object database layer, focusing on interface cleanup and performance. The series aligns with Patrick Steinhardt's broader odb refactoring efforts.

The current patch extends the `is_delta` field in `struct object_info` from a simple boolean to a 4-state enum that can represent unknown, full, offset delta, and reference delta object types. This prepares for a future change where we'll need to represent "unknown" delta state when skipping object parsing for size-only requests. The change is mechanical but important groundwork - it replaces boolean checks with enum comparisons while maintaining the same behavior for now.

The modification touches `odb.h` (adding the new enum) and `packfile.c` (updating the delta type handling). While not yet using the "unknown" state, this sets up the infrastructure cleanly for the next patch in the series. The change is well-contained and follows the series' theme of simplifying the object info interface while maintaining functionality.

This continues the careful interface evolution seen in the series so far, with maintainer-approved changes that remove implementation details while preparing for future improvements. The patch will enable proper handling of size-only requests while keeping delta information accurate.
