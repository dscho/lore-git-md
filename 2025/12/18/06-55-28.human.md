This is patch 9/10 in Patrick Steinhardt's series refactoring Git's packfile storage to track packs per object database (ODB) source rather than per ODB. The patch focuses on `find_pack_entry()`, a key function for locating objects in packfiles.

The change makes `find_pack_entry()` operate on a specific packfile store rather than the entire repository, better aligning with the series' goal of source-level packfile management. The patch updates three callers to handle this change: `packfile_store_freshen_object()` and `packfile_store_read_object_info()` (which already work with stores) are straightforward updates, while `has_object_pack()` is modified to explicitly iterate through sources when needed.

The diff shows the function being simplified to work on a single store, removing the source iteration that's now handled by callers. This continues the series' pattern of making packfile operations more direct and explicit about their ODB source dependencies. The changes are mechanical but important for the architectural shift toward source-level packfile management.

This patch follows the established direction of the series, with previous patches having set up the necessary infrastructure. It's a focused change that moves another key piece of functionality to the new model while maintaining the same behavior. The remaining patch (10/10) will finalize the transition by moving MIDX tracking to `struct packfile_store`.
