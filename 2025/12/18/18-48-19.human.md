Feature proposal for maintenance command configuration. This is the implementation patch following up on Matthew Hughes's RFC for adding a `maintenance.configFile` option to specify an alternate config file for maintenance operations.

The patch adds support for reading a config file path from `maintenance.configFile` when none is specified via command line. This allows users to split maintenance configuration out from their main gitconfig, which the author notes is particularly useful when tracking the global config in version control. The implementation modifies both the register and unregister subcommands in builtin/gc.c and includes a test case demonstrating the functionality.

The change is small and focused - just 8 lines of implementation code plus a 13-line test. The author provides a clear example in the commit message showing how this would be used in practice with an include directive in the main config pointing to a separate maintenance-specific file. The motivation is practical (keeping repo-specific maintenance config separate from version-controlled global config) though the use case may be somewhat niche.

This appears to be a well-constructed patch that does what it sets out to do, though as an RFC it's explicitly seeking feedback on whether this functionality is worth adding to Git proper. The thread context indicates this is the first implementation following a conceptual RFC, so the discussion will likely focus on whether the feature is generally useful enough to include.
