This is the final patch in Patrick Steinhardt's series improving object info handling, completing the cleanup by removing a redundant repository parameter from `packed_object_info()`. The patch follows logically from the earlier optimizations and interface simplifications in the series.

The change removes the `repository` parameter from `packed_object_info()` since the same information is already available via the `packed_git` struct's `repo` field. This affects several call sites across the codebase that need to be updated to match the new signature. The modifications span multiple files including `cat-file.c`, `pack-objects.c`, `commit-graph.c`, and the packfile implementation itself.

Key technical points:
- All callers now rely on `pack->repo` rather than passing a separate repository parameter
- The change maintains consistency with the series' goal of simplifying object info interfaces
- Internal packfile operations like `cache_or_unpack_entry()` and `packed_to_object_type()` still use the repository from the pack struct
- The `packfile_store_read_object_info()` wrapper is updated to match the new signature

This patch represents the final step in the interface cleanup portion of the series, following the performance optimizations introduced in patch 6/7. It demonstrates good attention to detail by catching and updating all call sites, including some less obvious ones like the bitmap and commit-graph code paths.
