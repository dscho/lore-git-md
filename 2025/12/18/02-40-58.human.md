This is a bugfix patch addressing a memory leak in the macOS filesystem monitoring code. The patch adds proper cleanup of CoreFoundation paths in the fsmonitor daemon's error and shutdown paths.

The changes add `CFRelease()` calls for three CoreFoundation objects (`cfar_paths_to_watch`, `cfsr_gitdir_path`, and `cfsr_worktree_path`) in both the constructor's error path and the destructor. The patch also adds the missing `CFTypeRef` typedef and `CFRelease` function declaration to the Darwin compatibility header.

The fix is straightforward and clearly motivated - these resources were being freed but weren't. The patch appears technically sound, touching only the Darwin-specific fsmonitor implementation. While small, it's an important fix for proper resource management on macOS systems using the filesystem monitor.
