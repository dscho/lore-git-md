Platform compatibility patch in the Windows symlink support series, specifically addressing symlink renaming behavior.

This is patch 11/18 in the now-complete v5 series that brings POSIX-like symlink support to Windows. Johannes Sixt is reviewing Karsten Blees' patch that fixes how Git handles renaming symlinks on Windows, particularly addressing an issue where older MSVCRT implementations would silently fail when trying to rename symlinks over existing files.

The patch replaces the problematic `_wrename()` call with direct use of `MoveFileEx()` with proper flags (`MOVEFILE_REPLACE_EXISTING | MOVEFILE_COPY_ALLOWED`), which provides more reliable behavior across Windows versions. The changes include careful error recovery and attribute handling, though Johannes Sixt notes the logic is quite complex - particularly around the `attrs` variable management and error paths. He ultimately trusts the implementation based on its long testing history in Git for Windows.

This is one of several foundational changes needed for comprehensive symlink support, with the series now maintainer-approved for merging. The review highlights both the technical complexity of Windows filesystem emulation and the value of real-world testing - even intricate code can be trusted when it has proven itself over years of use.
