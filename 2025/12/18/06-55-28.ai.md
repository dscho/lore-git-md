This is patch 9/10 in Patrick Steinhardt's series refactoring packfile storage to track packs per object database (ODB) source rather than per ODB. The patch focuses on `find_pack_entry()`, a key function for locating objects in packfiles.

The patch changes `find_pack_entry()` to operate on a specific `packfile_store` rather than the entire repository. This aligns with the series' goal of making packfile operations explicitly source-aware. The function now checks MIDX and regular packs within a single store, with callers responsible for iterating through multiple sources when needed. The main changes include removing the source iteration loop from `find_pack_entry()` itself and updating its callers to handle the new contract.

Three callers are affected: `packfile_store_freshen_object()` and `packfile_store_read_object_info()` already knew to iterate through sources, so only needed minimal updates to pass the store directly. The third caller, `has_object_pack()`, required more substantial changes to explicitly iterate through sources and their packfile stores.

The diff shows the mechanical transformation - the function signature changes to take a packfile_store, the source iteration moves to callers, and the packfile/MIDX lookup logic remains similar but now on a per-store basis. This continues the series' pattern of making packfile operations more direct and source-aware while maintaining existing behavior. The change is part of the broader architectural shift where each ODB source manages its own packfiles independently.
