This is a follow-up discussion on patch 2/8 in the object info reading series, specifically addressing the removal of the OI_DBCACHED flag distinction. The patch proposes simplifying the interface by always reporting OI_PACKED for objects read from packfiles, since the delta base cache status can already be determined via the `is_delta` enum and no callers actually use the OI_DBCACHED distinction.

Junio Hamano raised a cautious note about potential breakage for code paths that might check OI_PACKED status, despite the current audit showing only one usage (the one being removed). Patrick Steinhardt acknowledges this concern and agrees to update the commit message to better document the investigation into potential impacts.

The exchange highlights the careful approach being taken with these core object database changes, where even seemingly safe simplifications undergo thorough vetting for hidden dependencies. This discussion occurs in the context of broader refactoring work that includes performance improvements (9% speedup for size-only requests) and alignment with the `the_repository` removal effort.

Key technical points for future reference:
- The change removes OI_DBCACHED entirely from odb.h
- All packfile reads will now report OI_PACKED regardless of delta cache status
- Delta state remains available via the `is_delta` enum (recently converted from boolean)
- Only one existing reference to OI_DBCACHED exists (in packed_object_info())
- Potential but unconfirmed risk for code checking OI_PACKED specifically

The thread shows maintainers proceeding cautiously with interface simplifications in core functionality, even when audits suggest low risk. This patch remains under discussion pending improved commit message justification.
