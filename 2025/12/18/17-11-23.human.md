This is part 9 of an 11-part series refactoring Git's hook subsystem to use a new standardized API. The patch adds output capture capability to hooks, which is particularly important for server-side hooks that need to relay output to clients via sideband rather than printing directly to stderr.

The change exposes a `consume_output` callback in the `run_hooks_opt` struct that gets passed through to the parallel process runner. This allows hook callers to intercept and process hook output programmatically. The commit message notes this is specifically for server-side use cases, and points to test code for implementation examples.

This is a straightforward addition to the hook API that builds on the parallel execution infrastructure introduced earlier in the series. It has already received sign-offs from both co-author Emily Shaffer and Ævar Arnfjörð Bjarmason, indicating it fits well with the series direction. The implementation is minimal - just plumbing the callback through the existing hook execution path - and maintains backward compatibility since the callback is optional.

As part of the larger hook standardization effort, this patch provides an important capability for server-side operations while keeping the core change focused and well-contained. The series appears to be in good shape, with all prior feedback addressed and CI passing through previous versions.
