Refactoring patch in the packfile storage series, focusing on memory management cleanup. This is patch 4/10 in Patrick Steinhardt's ongoing work to reorganize packfile handling around object database sources rather than the ODB itself.

The patch simplifies the `unuse_one_window()` function which manages packfile memory mapping limits. The function previously took a `packed_git` parameter that was misleading - while it appeared optional, the code actually always required it after a 2019 change. The patch makes this explicit by changing the parameter to take the object database directly, removing confusing NULL checks and clarifying the function's actual behavior.

The change is mechanical but improves code clarity by matching the function's signature to its real requirements. It's part of the broader architectural shift to properly separate packfile storage concerns from the ODB layer. The patch maintains all existing functionality while making the code more straightforward - a good example of incidental complexity being cleaned up during a larger refactoring effort.
