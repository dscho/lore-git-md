This is patch 5/7 in Patrick Steinhardt's series improving object info reading in Git's object database layer, focusing on interface cleanup and performance optimization. The patch simplifies the return value semantics of `packed_object_info()` from an ambiguous `enum object_type` that could represent either an actual type or delta status, to a straightforward success/error integer return.

The key change makes `packed_object_info()` return 0 on success and negative on error, removing its previous dual-purpose return value that mixed object types with error signaling. This change is safe because the preceding patch removed the last caller that relied on the old return value behavior. The modification enables a small optimization by allowing callers to skip reading the object type when not needed.

The patch updates all error paths in `packed_object_info()` to use the new return convention and adjusts the sole caller in `packfile_store_read_object_info()` to check for errors via the new scheme. The packfile.h header comment is also updated to document the clarified return value contract.

This change is part of the broader effort to clean up the object info reading interface in preparation for future `odb_for_each_object()` functionality. It follows the series' theme of simplifying distinctions while maintaining stability, with this patch specifically removing an ambiguous interface that could cause confusion between object types and delta states. The modification is low-risk since it builds on the previous patch's removal of the last dependent caller.
