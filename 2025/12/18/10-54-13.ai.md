This is a bugfix patch in Patrick Steinhardt's series improving object info reading in Git's object database layer. It addresses an inconsistency in how the `OI_LOOSE` flag is set when reading loose object information.

The patch fixes `odb_source_loose_read_object_info()` to consistently set the `whence` field to `OI_LOOSE` in all successful return paths, including early exits. Currently, some quick-return paths (like when using `OBJECT_INFO_QUICK` flag or just checking disk size) fail to set this flag, making it impossible for callers to determine the object's format in these cases.

While no current callers appear to rely on this information, the commit message notes this is "a bug waiting to happen" as future code might depend on accurate `whence` values. The changes touch only `object-file.c`, modifying the early return logic to ensure `oi->whence` is properly set in all cases where we successfully determine we're dealing with a loose object.

This is the first of seven patches in v2 of the series, which overall aims to clean up and standardize object info reading interfaces in preparation for future `odb_for_each_object()` functionality. The changes are surgical and focused, with clear justification for the modification despite no immediate breakage.
