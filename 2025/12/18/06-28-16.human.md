Performance optimization in the object database layer, part of a series improving object info reading. This patch specifically skips unpacking object headers when only the disk size is requested, since that information is available without full header parsing. The change shows a measurable speedup of about 9% in a `git rev-list --disk-usage` benchmark.

The patch builds on earlier work in the series that introduced an "unknown" state for object types (via the `OBJ_NONE` enum value) and refactored `packed_object_info()`'s. The change is focused and well-measured, touching only the packfile.c logic for header unpacking while maintaining all existing behavior for other object info requests. The benchmark results are convincing for this specific case where only disk size is needed.

This continues the series' pattern of careful, incremental improvements to the object info infrastructure, with each patch addressing a distinct optimization or cleanup opportunity. The change appears straightforward and low-risk, though reviewers may want to verify the benchmark methodology and ensure no edge cases are missed in the header-skipping logic.
