This is the first patch in a 2-part series implementing HTTP 429 (rate limiting) retry support for Git's HTTP client. The patch adds core functionality for handling rate-limited responses, including:

Key technical components:
- Three new config options: `http.maxRetries` (default 0), `http.retryAfter` (fallback delay), and `http.maxRetryTime` (300s ceiling)
- RFC-compliant parsing of both delay-seconds and HTTP-date Retry-After header formats
- New `HTTP_RATE_LIMITED` (7) status code in http.h
- Slot-specific retry timing via new `retry_delay_seconds` and `retry_delay_start` fields in `struct active_request_slot`
- Extracted rate limit handling into `handle_rate_limit_retry()` function
- Renamed `http_request_reauth()` to `http_request_recoverable()` to reflect expanded role
- Added comprehensive test coverage in t5584-http-429-retry.sh (286 lines)

The implementation follows a fail-fast approach - if any delay exceeds maxRetryTime, Git fails immediately with a clear error rather than capping the delay. The patch includes extensive test coverage for various scenarios including different Retry-After formats, configuration combinations, maxRetryTime limits, and edge cases.

This builds on feedback from Taylor Blau on v1 of the series, with significant refactoring to improve maintainability and test organization. The implementation appears thorough and well-tested, with no obvious technical concerns remaining. The patch touches multiple HTTP-related files (http.c, http.h, remote-curl.c, etc.) and adds new test infrastructure (http-429.sh helper).
