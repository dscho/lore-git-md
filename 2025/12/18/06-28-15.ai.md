This is part 5 of an 8-part series improving object info reading in Git's object database layer, specifically focusing on refactoring the `packed_object_info()` function's return value handling.

The patch simplifies the return value semantics of `packed_object_info()` to use a simple success/error code rather than overloading the return type to sometimes indicate object types and sometimes indicate delta status. Since the previous patch removed the last caller that relied on the overloaded return value, this change is now possible. The new behavior returns 0 on success and negative error codes otherwise, which enables future optimizations by allowing the object type to be skipped in some cases.

The changes touch both packfile.c (where the function implementation is updated to use the new return convention) and packfile.h (where the documentation is updated to reflect the simpler contract). The diff shows careful attention to error handling, converting all cases that previously returned OBJ_BAD to now return -1 consistently. The change appears to be a straightforward cleanup that improves the function's interface while maintaining all existing functionality through the object_info struct parameters. This continues the series' pattern of focused, incremental improvements to the object info reading infrastructure.
