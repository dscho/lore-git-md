Performance regression fix addressing a severe slowdown in promisor pack handling.

Junio Hamano proposes a solution to the performance regression reported by Aaron Plattner, where `packfile_store_read_object_info()` was incorrectly comparing object_info structs. The root cause was comparing against a static `blank_oi` variable rather than properly handling NULL cases. The patch removes all uses of the static `blank_oi` pattern throughout the object info subsystem, instead making each function explicitly handle NULL `oi` parameters.

The changes span three files:
- `object-file.c` adds NULL checks for `oi` before accessing its fields
- `odb.c` completely removes the static `blank_oi` and restructures the cached object handling to work with NULL `oi`
- `packfile.c` simplifies its early return check to just test for NULL

This appears to be a direct fix for the 1500x slowdown Plattner observed, addressing the core issue of unnecessary processing when comparing against the wrong blank struct. The changes follow Git's typical pattern of defensive programming by making NULL handling explicit rather than relying on a shared static variable. The patch maintains all existing functionality while eliminating the problematic comparison that caused the regression.

The solution aligns with Plattner's diagnosis while taking a more comprehensive approach by removing the `blank_oi` pattern entirely rather than just fixing the comparison. This should prevent similar issues in other parts of the object info subsystem. The changeset is relatively small (18 insertions, 22 deletions) and focused specifically on the regression path.
