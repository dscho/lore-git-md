This is the final patch in a major hook subsystem refactoring series, converting receive-pack's receive hooks to the new `hook.h` API. The patch completes the standardization of all major Git hooks onto the new callback-based infrastructure.

The conversion follows the established pattern of the series, replacing manual `child_process` management and direct `find_hook()` calls with the new API's structured approach. Key changes include batching hook input in 500-line chunks to maintain performance (addressing a regression noticed during testing), preserving sideband output capabilities, and maintaining all existing environment variable handling for push certificates and options.

The patch has already received sign-offs from co-author Emily Shaffer and Ævar Arnfjörð Bjarmason, indicating technical consensus. With this conversion, the series now provides a unified hook execution framework across all major Git operations while maintaining backward compatibility. The implementation looks thorough, with careful attention to edge cases like EPIPE handling and memory management.

This concludes a significant architectural improvement to Git's hook subsystem that has been under review through multiple iterations, with all CI tests passing in previous versions.
