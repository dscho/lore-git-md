This is a patch series (8 parts) focused on improving object info reading in Git's object database layer, with both loose and packed object handling enhancements. The changes appear to be preparatory work for a future `odb_for_each_object()` function, though that larger change isn't included here.

The series makes several technical improvements to how object info is handled:
- Consistently sets OI_LOOSE/OI_PACKED flags when reading objects
- Extends delta detection to include an "unknown" state
- Ensures pack-specific info is always populated
- Cleans up return value handling in `packed_object_info()`
- Optimizes by skipping header unpacking for size-only requests
- Fixes edge cases with empty requests
- Removes repository parameter from `packed_object_info()` as part of `the_repository` removal effort

The changes touch core object database code across multiple files (object-file.c, packfile.c, etc.) and include test updates. There's a minor conflict with another ongoing series (ps/packfile-store-in-odb-source) that the author proposes to resolve via an "evil merge" if acceptable.

The series also incidentally fixes an issue reported in a previous thread (reference given but not summarized here).
