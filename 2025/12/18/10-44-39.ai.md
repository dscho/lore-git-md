Platform compatibility patch (Windows symlink support) in a completed series (v5). This is a review comment on patch 2/18 from Johannes Sixt, who identifies a minor documentation issue in Karsten Blees' implementation of `mingw_stat()` for Windows symlink support.

The patch itself implements proper symlink resolution in `mingw_stat()` by using `CreateFileW()` and `GetFileInformationByHandle()` to follow symlinks, rather than treating them like `mingw_lstat()`. Johannes Sixt notes that the patch's final paragraph about `ELOOP` error codes appears disconnected from the actual implementation - it may be a leftover from earlier iterations when symlink support was optional. He confirms the technical implementation itself looks correct.

This is a small documentation clarification in an otherwise mature patch series that has already received maintainer approval. The series as a whole represents the culmination of Windows symlink support development spanning nearly a decade, with this particular patch establishing core filesystem behavior for following symlinks when `stat()` is called. The `ELOOP` comment doesn't affect functionality but could be cleaned up for accuracy.
