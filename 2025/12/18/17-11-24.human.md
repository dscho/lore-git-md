Hook subsystem refactoring (part 10/11). This patch converts receive-pack's update and post-update hooks to use the new hook API introduced earlier in the series. The changes eliminate manual child_process setup in favor of the standardized run_hooks_opt interface while preserving sideband output functionality.

The patch replaces direct find_hook() calls and custom child_process structs with the new hook-running infrastructure. For the update hook, it passes ref updates through the standard argument vector, while the post-update hook collects all successful ref updates before execution. Both hooks maintain their sideband output capability via the new consume_output callback when use_sideband is enabled.

This continues the series' pattern of converting existing hooks to the new API while maintaining backward compatibility. The changes are straightforward mechanical conversions that follow the patterns established in earlier parts of the series, with sign-offs from both co-authors and reviewers indicating consensus on the approach. The patch reduces custom hook plumbing by about 60 lines while preserving all existing functionality.

As with previous conversions in the series, execution remains sequential (processes=1) at this stage, though the new API prepares for future parallel execution capabilities. The changes demonstrate how the new hook API can simplify server-side hook implementations while maintaining critical features like sideband communication.
