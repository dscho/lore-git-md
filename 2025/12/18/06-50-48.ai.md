This is a refactoring patch in Patrick Steinhardt's ongoing series to move packfile handling from object database (ODB) level to ODB source level, part of the broader ODB abstraction effort. The patch relocates packfile store ownership from `struct object_database` to `struct odb_source`, updating callers to use the new location.

Key technical details:
- Changes affect packfile operations in `fast-import.c`, `index-pack.c`, `pack-objects.c`, and `http.c`
- Maintains current behavior where new packs are written only to primary source while reads consider all sources
- `packfile_store_load_pack()` now operates on source-specific stores
- `want_cruft_object_mtime()` in `pack-objects.c` now iterates through all sources' kept-pack caches
- Transitional cases still use primary source only (marked in code)

Justin Tobler's review identified several edge cases needing future resolution:
- `fast-import.c` only uses primary source's packfile store (intentional for writes)
- `index-pack.c` only loads primary store for fsck (intentional for new pack activation)
- `http.c` always adds packs to primary store (will need interface changes for pluggable ODBs)
- Behavior with duplicate OIDs across sources remains unchanged from pre-refactor logic

The patch maintains existing functionality while advancing the architectural shift to source-level packfile handling, with some transitional limitations acknowledged for future work. Justin's review confirms the correctness of the changes while noting areas that will need attention in later stages of the ODB abstraction effort.
