This is a refactoring patch in Patrick Steinhardt's series improving object info reading in Git's object database layer. It's patch 5/7 in the v2 series, which focuses on standardizing interfaces and improving performance.

The patch simplifies the return value semantics of `packed_object_info()`, changing it from returning an ambiguous `enum object_type` (which could represent either an actual object type or delta status) to a straightforward success/error code (0/-1). This change is possible because the last caller relying on the old return value behavior was removed in the previous patch.

The key changes include:
1. Converting all error paths to return -1 consistently
2. Adding a clear success case that returns 0
3. Updating the packfile.h header comment to document the new behavior
4. Adjusting the sole caller (`packfile_store_read_object_info()`) to handle the new return value

This is part of a larger effort to clean up the object info reading interface in preparation for future `odb_for_each_object()` functionality. The change enables a small optimization (skipping object type reads in some cases) while making the code's behavior more predictable and maintainable. The patch appears well-contained and builds on the series' previous work.
