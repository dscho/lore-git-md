Feature proposal for a commit snapshot mechanism.

Abdullah proposes a new `--snapshot` flag for `git commit` that would create timestamped copies of all staged files before committing. The implementation creates a new `.git/snapshots` directory (configurable via `snapshot.folder`) containing folders named with timestamps and sanitized commit messages (e.g. `2025-12-17_14-30-00_Initial_commit/`).

The patch adds:
1. A new `--snapshot` option to `git commit`
2. Core functionality in new files `snapshot.[ch]` that:
   - Checks if snapshots are enabled via config
   - Creates timestamped directories
   - Copies staged files using `git diff --name-only --cached`
3. Two new config options: `snapshot.enable` and `snapshot.folder`

The author notes this is untested code submitted for initial feedback. The implementation raises several potential concerns:
- Uses `system()` to shell out for file copying
- Simple space-to-underscore message sanitization
- No handling of edge cases like empty commit messages
- No tests included

This appears to be a first-time contribution attempting to add a new feature that could help with recovery from accidental commits. The concept may warrant discussion about whether this belongs in core Git versus an external tool.
