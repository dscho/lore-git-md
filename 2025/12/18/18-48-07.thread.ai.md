RFC proposal and implementation for maintenance config file option. Author: Matthew Hughes. Thread type: feature proposal.

Core proposal: add ability to specify alternate config file for git-maintenance operations via new `maintenance.configFile` setting, similar to -c/GIT_CONFIG for general git config but specific to maintenance subsystem. Implementation in builtin/gc.c with test in t/t7900-maintenance.sh.

Technical details: new config option `maintenance.configFile` would point to maintenance-specific config. Implementation modifies `builtin/gc.c` to check for this config when no explicit `--config-file` is provided to `register`/`unregister` subcommands, following same pattern as existing config file handling. Test case demonstrates functionality by setting config option globally and verifying maintenance paths are written to specified file.

Author motivation: separate maintenance configuration from version-controlled global config, allowing repo-specific maintenance settings without polluting tracked config. Implementation appears straightforward and consistent with existing behavior.

Status: initial RFC with implementation patch now available. Open questions remain about whether this functionality is needed and what specific problems it would solve. No reviews or discussion yet on the implementation details. Key unresolved question is whether the feature provides sufficient value to justify adding to maintenance subsystem.

Implementation specifics:
- New config key: `maintenance.configFile`
- Affected commands: `git maintenance register/unregister`
- Implementation files: `builtin/gc.c` (main logic), `t/t7900-maintenance.sh` (test)
- Behavior: When no `--config-file` is passed, falls back to `maintenance.configFile` if set
