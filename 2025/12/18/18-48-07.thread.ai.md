RFC proposal and implementation for maintenance config file option. Author: Matthew Hughes. Thread type: feature proposal.

Core proposal: add ability to specify alternate config file for git-maintenance operations via new `maintenance.configFile` setting, similar to -c/GIT_CONFIG for general git config but specific to maintenance subsystem. Implementation in builtin/gc.c with test in t/t7900-maintenance.sh.

Technical details: new config option `maintenance.configFile` would point to maintenance-specific config. Implementation modifies `builtin/gc.c` to check for this config when no explicit `--config-file` is provided to `register`/`unregister` subcommands, following same pattern as existing config file handling. Test case demonstrates functionality by setting config option globally and verifying maintenance paths are written to specified file.

Patrick Steinhardt provided technical feedback identifying several considerations:
1. Questions whether users should need to manually include the maintenance config file, suggesting git-maintenance should handle this automatically
2. Points out minor code style deviation (single-line if statements without braces)
3. Identifies a gap in the current implementation: scheduled maintenance via `git for-each-repo` doesn't support reading from alternate config files
4. Proposes an extension to `git for-each-repo` with a new `--file` option to read config from specified files
5. Includes an untested implementation patch for this extension
6. Raises two important follow-up questions about service file updates and config migration

Implementation specifics:
- New config key: `maintenance.configFile`
- Affected commands: `git maintenance register/unregister`
- Implementation files: `builtin/gc.c` (main logic), `t/t7900-maintenance.sh` (test)
- Behavior: When no `--config-file` is passed, falls back to `maintenance.configFile` if set
- Proposed extension: `--file` option for `git for-each-repo` to support scheduled maintenance

Open questions and loose ends:
1. Should git-maintenance automatically handle config file inclusion?
2. How to handle service file updates when config file location changes?
3. What should be the migration path for existing maintenance configs?
4. Need to verify and test the proposed `for-each-repo` extension
5. Code style cleanup needed (single-line if statements)

Participant positions:
- Matthew Hughes: original author proposing the feature
- Patrick Steinhardt: provided detailed technical feedback and proposed complementary changes to `for-each-repo`

Related work: The proposal builds on existing config file handling patterns in Git and would need to work with the scheduled maintenance infrastructure via `git for-each-repo`.
