This thread addresses a severe performance regression in Git's object handling code, where a `git commit` operation slowed from 0.38 seconds to over 25 minutes. The regression was introduced by the recently merged ps/object-read-stream topic and was reported by Aaron Plattner.

Junio Hamano has proposed a minimal fix that removes problematic static "blank" object_info structs and adds explicit NULL checks, restoring the original performance. Patrick Steinhardt is preparing a more comprehensive series that would address additional edge cases and optimizations, though this hasn't been sent yet. Aaron Plattner has verified that Junio's fix works (adding Tested-by and Reviewed-by tags).

A recent discussion emerged about commit message conventions, with Kristoffer Haugsbakk clarifying that "Fixes:" tags aren't standard Git practice except in special cases like "Best-viewed-with" documentation. Instead, related commits should be referenced in the message body using Git's standard 8-character hash format with subject and date. This procedural point doesn't affect the technical solutions under consideration.

The thread now waits on Patrick Steinhardt's alternative series to evaluate whether to proceed with Junio's minimal fix or adopt a more comprehensive solution. The core performance issue is resolved in both approaches, leaving the decision between minimal versus thorough as the remaining open question.
