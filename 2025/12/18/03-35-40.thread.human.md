This thread addresses a severe performance regression in Git's object handling code that was introduced in the recently merged `ps/object-read-stream` topic, causing `git commit` times to balloon from 0.38s to 1508s. Aaron Plattner reported the issue, and Junio Hamano quickly provided a minimal fix that removes problematic static "blank" object_info structs and adds explicit NULL checks, restoring original performance. Patrick Steinhardt confirmed the fix works and will rebase his more comprehensive series addressing related object handling issues on top of it.

The discussion has now turned to commit message conventions, with Kristoffer Haugsbakk and Carlo Marcelo Arenas Belón clarifying that Git doesn't typically use "Fixes:" tags for bugs in unreleased versions (unlike the Linux kernel's backport-focused workflow). This is settled as a point of contributor education rather than a technical debate, as the core fix has already been verified and accepted. The path forward is clear: Junio's minimal fix will go in first, followed by Patrick's expanded work on object handling improvements.
