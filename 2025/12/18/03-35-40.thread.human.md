This thread addresses a severe performance regression in object handling code (from 0.38s to 1508s for `git commit`) that was introduced in the recently merged ps/object-read-stream topic. Junio Hamano has provided a minimal fix that removes problematic static "blank" object_info structs and adds explicit NULL checks, restoring original performance. The fix has been verified by both the original reporter (Aaron Plattner) and Patrick Steinhardt, who will rebase his more comprehensive series on top of this change.

While the technical solution is settled, the discussion emerged about commit message conventions - specifically whether to use "Fixes:" tags for unreleased versions. Kristoffer Haugsbakk and Carlo Marcelo Arenas Belón clarified that unlike Linux kernel practice, Git typically doesn't use these tags for in-development fixes. Junio reinforced this position, noting he prefers fixes to prove themselves in the wild before being labeled as such. This attention to documentation standards persists even as the urgent performance issue is being resolved, showing the project's commitment to maintaining consistent practices and high-quality commit messages alongside technical fixes.
