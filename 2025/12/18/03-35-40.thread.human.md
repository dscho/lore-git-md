This thread addresses a severe performance regression in Git's object handling code, where a simple `git commit` operation slowed from 0.38 seconds to over 25 minutes. The regression was introduced by the recently merged ps/object-read-stream topic (commit 385e188) and reported by Aaron Plattner.

Junio Hamano proposed a minimal fix that removes problematic static "blank" object_info structs and adds explicit NULL checks throughout the object-info call chain, particularly in packfile.c where the performance bottleneck occurred. Patrick Steinhardt, who had been working on a more comprehensive series to address related object handling issues, reviewed Junio's patch and confirmed it properly fixes the regression (reducing the 1508s runtime back to 0.38s). Both solutions restore performance, but the consensus is to proceed with Junio's immediate fix as the base solution.

The thread has reached agreement on the minimal fix path, with Patrick planning to rebase his larger series - which includes additional object info API improvements and optimizations - as follow-up work. Aaron Plattner has verified the fix works in practice, adding his Tested-by and Reviewed-by tags. This keeps the focus on quickly addressing the regression while leaving room for future enhancements to the object handling code.
