This thread addresses a performance regression in Git's object handling code that was recently introduced by the ps/object-read-stream topic merged to master. The bug caused `git commit` operations to slow from 0.38 seconds to over 1500 seconds in Aaron Plattner's testing. The regression stemmed from incorrect assumptions about static "blank" object_info structs being used as NULL substitutes across object-file.c, odb.c, and packfile.c.

Junio Hamano proposed a fix that removes these problematic static variables in favor of explicit NULL checks while maintaining all existing functionality. Aaron Plattner has now confirmed the fix works as intended, restoring performance to the expected sub-second range. He's added both Tested-by and Reviewed-by tags to the patch, suggesting it could also include a "Fixes:" line referencing the commit that introduced the regression (385e18810f10).

With the original reporter verifying the solution and providing positive feedback, this appears to be a straightforward bugfix that's ready for merging. The thread shows consensus forming around Junio's approach, with no outstanding technical concerns remaining.
