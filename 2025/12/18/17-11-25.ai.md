This is the final patch in the hook subsystem refactoring series, converting receive-pack's receive hooks to the new `hook.h` API. The patch completes the standardization of all major Git hooks onto the new callback-based infrastructure.

The conversion follows the established pattern of the series, replacing direct `child_process` management with the structured API while maintaining existing behavior. Key changes include:

- Replaces manual hook execution with `run_hooks_opt()` calls
- Implements batched stdin feeding (500 lines per callback) to maintain performance with large inputs
- Preserves sideband output capability via the `consume_output` callback
- Maintains push certificate and push option environment variable handling
- Removes direct `find_hook()` calls and manual SIGPIPE toggling

The patch introduces a `feed_receive_hook_cb()` callback that processes ref updates in batches rather than line-by-line, addressing a performance regression observed in earlier versions. The callback maintains all existing ref update filtering and reporting logic while integrating with the new API's streaming model.

Environment variable handling for push certificates and options is moved to operate on the `run_hooks_opt` struct rather than `child_process`. The sideband output relay remains functional through the `hook_output_to_sideband()` helper introduced in earlier patches.

With this conversion, all major Git hooks now use the new API, completing the series' goal of standardizing hook execution while maintaining backward compatibility. The implementation has received sign-offs from both co-authors (Emily Shaffer and Ævar Arnfjörð Bjarmason) and addresses all prior feedback from maintainers.
