Bugfix addressing a performance regression in object info handling. Junio Hamano responds to Aaron Plattner's analysis of a severe slowdown in repositories with large promisor packs, tracing it to incorrect comparison of `object_info` structs in the recently merged object streaming code.

The issue stems from `do_oid_object_info_extended()` using a static `blank_oi` as a stand-in when callers pass NULL, while `packfile_store_read_object_info()` compares against its own local blank struct. Junio proposes eliminating the blank struct pattern entirely, instead explicitly handling NULL cases throughout the object info chain. The patch modifies `object-file.c`, `odb.c`, and `packfile.c` to make all functions properly handle NULL `oi` pointers directly.

This appears to be a clean, focused fix that removes a problematic pattern while maintaining the same functionality. The changes are limited to the object info plumbing and don't affect higher-level behavior. Given Junio's role as maintainer and the clear explanation of both the problem and solution, this fix is likely to be accepted quickly to address the reported regression.
