This is part of the performance optimization series for object info reading in Git's ODB layer. Patch 6/8 focuses on optimizing disk size requests for packed objects by avoiding unnecessary header unpacking.

The change modifies `packed_object_info()` in packfile.c to skip unpacking object headers when only the disk size is requested, since this information can be obtained without parsing the full header. The patch introduces a new case in the switch statement to properly handle the `OBJ_NONE` case that results from this optimization.

The commit includes benchmark results showing a ~9% speedup for `git rev-list --disk-usage` operations. The implementation is careful to maintain existing behavior for all other request types (content, type, delta base) while optimizing the size-only path. This builds on earlier patches in the series that refactored the object info handling infrastructure, particularly the enum-based type system introduced in patch 3.

The change is narrowly scoped to packed object handling and doesn't affect loose objects. It demonstrates good attention to performance-sensitive paths in Git's object storage layer while maintaining correctness through the new `OBJ_NONE` handling case. The patch fits cleanly into the series' broader goal of improving object info reading efficiency.
