Feature proposal for maintenance config file option, building on the RFC cover letter. This is the implementation patch that would allow specifying an alternate config file for git-maintenance operations via a new `maintenance.configFile` setting.

The patch modifies `builtin/gc.c` to check for this config option when no explicit `--config-file` is provided to `register`/`unregister` subcommands. The implementation follows the same pattern as the existing config file handling, just moving the lookup earlier in the process. A test case demonstrates the functionality by setting the config option globally and verifying maintenance repo paths are written to the specified file.

The author's stated motivation is to separate maintenance configuration from their version-controlled global config, allowing repo-specific maintenance settings without polluting their tracked config. The implementation appears straightforward and maintains consistency with existing behavior, though as noted in the RFC thread, the broader need for this functionality hasn't been established yet.

Key technical details:
- New config key: `maintenance.configFile`
- Affected commands: `git maintenance register/unregister`
- Implementation files: `builtin/gc.c` (main logic), `t/t7900-maintenance.sh` (test)
- Behavior: When no `--config-file` is passed, falls back to `maintenance.configFile` if set

The patch is functionally complete but remains in RFC status pending discussion of whether this feature is worth adding to Git's maintenance subsystem.
