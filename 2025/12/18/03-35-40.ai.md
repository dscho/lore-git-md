This is a bugfix addressing a performance regression in object handling code. The patch removes the use of a static "blank" object_info struct as a substitute for NULL pointers in several object-info related functions, instead explicitly checking for NULL inputs.

The issue stemmed from the ps/object-read-stream topic recently merged to master, where a bug assumed identical static variable names in different functions referred to the same memory location. This caused severe performance degradation in some cases (from 0.38s to 1508s for `git commit`), as reported by Aaron Plattner.

The fix modifies three files (object-file.c, odb.c, packfile.c) to:
1. Remove the static blank_oi variables
2. Add explicit NULL checks before accessing oi fields
3. Only process object_info fields when oi is non-NULL

The change not only fixes the performance regression but also improves safety by eliminating potential issues where the blank_oi could be accidentally modified between calls. The patch demonstrates careful consideration of edge cases and maintains all existing functionality while being more robust.
