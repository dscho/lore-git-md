This is a refactoring patch in the object database infrastructure series, specifically addressing the `OI_DBCACHED` flag in object info handling. Junio Hamano is reviewing Patrick Steinhardt's patch that proposes removing the `OI_DBCACHED` distinction entirely from the `object_info` struct, since callers don't appear to care about the difference between objects stored in packfiles versus those in the delta base cache.

The key technical change is the elimination of the `OI_DBCACHED` enum value and simplification of the `packed_object_info()` function to always report `OI_PACKED`. The patch argues this is an implementation detail that can be inferred from other fields (`is_delta`), and notes there are no callers checking this distinction (confirmed via `git grep`).

Junio raises a cautious note about potential breakage for any code paths that might check for `OI_PACKED` specifically, though the audit suggests this is unlikely. The changes are minimal - just 3 lines across two files (odb.h and packfile.c) - but touch core object database infrastructure. This continues the series' theme of simplifying object info handling while maintaining all existing functionality through other means.
