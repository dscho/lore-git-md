This is a refactoring patch in an 8-part series improving Git's object info reading infrastructure. The patch simplifies the interface by removing the OI_DBCACHED enum value from `struct object_info`, which was an implementation detail distinguishing between objects stored in packfiles versus those in the delta base cache. The author argues this distinction isn't useful to callers, who can already determine delta status via the `is_delta` field.

Junio Hamano notes the change appears safe since `git grep` shows no other uses of OI_DBCACHED, though he cautions that a more thorough audit would be needed to confirm no code paths rely on checking for OI_PACKED specifically. The change is mechanically simple, removing one enum value and updating the single assignment site to always use OI_PACKED.

This appears to be a straightforward cleanup that reduces interface complexity without affecting functionality, though as Junio notes, the impact on any hidden assumptions in the codebase about the OI_PACKED value would need consideration. The patch fits into the larger series' goal of improving object info handling consistency.
