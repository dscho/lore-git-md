This is part 3 of the ongoing hook subsystem refactoring series, introducing a callback mechanism for feeding stdin to hooks without filesystem overhead. The patch adds a `feed_pipe_fn` callback to `struct run_hooks_opt` that enables streaming large amounts of data directly to hook processes, building on the parallel stdin handling infrastructure from part 2.

Key technical changes include:
- New `feed_pipe` field in `run_hooks_opt` that takes a callback function pointer
- Two associated context pointers (`feed_pipe_ctx` and `feed_pipe_cb_data`) for passing initialization state and maintaining per-hook state across callback invocations
- BUG() assertions enforcing mutual exclusivity between the new callback and existing `path_to_stdin` file-based approach
- Plumbing to pass the callback through to `run_processes_parallel()` via the `feed_pipe` field in `struct parallel_processes`
- Documentation of the callback mechanism in `hook.h` explaining use cases for large data streams

The implementation maintains backward compatibility while providing a more efficient path for hooks processing substantial input. The patch follows the series' established pattern of using `pp_task_cb` for per-hook state management. This change is foundational for later conversions of hooks like reference-transaction and receive-pack that need to stream reference updates rather than using temporary files.

Review context shows this builds on consensus from earlier parts, with signed-off-by from key contributors. The implementation appears clean and well-documented, with clear separation of concerns between the hook API and underlying parallel process machinery. This continues the series' steady progress toward complete hook modernization.
