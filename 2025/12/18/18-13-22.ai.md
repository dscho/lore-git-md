This is a platform compatibility patch implementing `readlink()` for Windows as part of the larger symlink support series. Johannes Sixt points out that the commit message's claim about failing with `ENOSYS` when symlinks are disabled appears incorrect, as the implementation doesn't actually check `core.symlinks` configuration.

The patch moves `readlink()` from being a stub in `mingw-posix.h` to a full implementation in `mingw.c`, using the existing `read_reparse_point()` infrastructure introduced earlier in the series. The implementation handles both symlinks and directory junctions, converting paths from UTF-16 to UTF-8 and carefully managing buffer sizes to match POSIX `readlink()` semantics where the caller's buffer size limits the copied data without being treated as an error condition.

This is patch 13/18 in the now-complete v5 series that upstreams comprehensive Windows symlink support. The implementation follows the series' pattern of building POSIX-compatible APIs on Windows filesystem primitives, here using the reparse point reading infrastructure established in earlier patches. Johannes Sixt's observation about the `ENOSYS` comment appears to be a minor documentation nit rather than a functional concern, as the implementation itself looks correct and aligns with the series' technical approach.
