Refactoring patch in the object info reading series, specifically targeting the packed object info interface.

This second patch in the 8-part series simplifies the object info interface by removing the OI_DBCACHED enum value and always reporting packed objects as OI_PACKED, regardless of whether they're in the delta base cache. The change affects both odb.h (removing the enum value) and packfile.c (removing the conditional check).

The rationale is that callers don't need to distinguish between objects in the pack versus those in the delta base cache, as this is an implementation detail. The `is_delta` field already provides sufficient information about delta status when needed. This simplification makes the interface cleaner without losing any meaningful functionality.

The change is relatively straightforward, touching only two files with minimal modifications. It aligns with the series' broader goal of improving and simplifying the object info reading infrastructure. The patch appears technically sound and well-motivated, though we might expect some discussion about whether any existing code might have been relying on the OI_DBCACHED distinction (the author asserts there are such callers).
