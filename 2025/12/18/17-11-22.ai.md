This is part 8 of the hook subsystem refactoring series, introducing output capture capabilities for parallel processes. The patch adds a `consume_output_fn` callback to `struct run_process_parallel_opts`, allowing callers to intercept and process child process output that would normally go to stderr. The implementation maintains the existing behavior when no callback is provided while adding the new capture capability.

Key technical details include:
- New `consume_output_fn` typedef and field in `run_process_parallel_opts` for output handling
- Modified `pp_output()`, `pp_buffer_stderr()`, and `pp_collect_finished()` to use the callback when present
- BUG() assertion preventing `ungroup` and `consume_output` from being used simultaneously
- Test case demonstrating output redirection to a file via the new callback
- Maintains existing parallel execution behavior when no callback is specified

The change is particularly useful for server-side hooks needing to relay output to clients, as noted in the commit message. The implementation avoids temporary files/pipes by working directly with strbufs. The test case verifies output can be diverted while keeping stderr clean. This builds on previous parallel execution infrastructure from earlier in the series while maintaining the established pattern of optional callbacks for customization.
