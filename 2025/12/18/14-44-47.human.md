Feature patch adding HTTP 429 (rate limiting) retry support to Git's HTTP client. This is the first of two patches in the series, implementing the core functionality.

The patch adds automatic retry logic when Git receives an HTTP 429 (Too Many Requests) response from a server. It supports RFC-compliant Retry-After headers in both delay-seconds (integer) and HTTP-date formats. Three new config options control the behavior: `http.maxRetries` (default 0, opt-in), `http.retryAfter` (fallback delay when no header is provided), and `http.maxRetryTime` (300s delay cap).

Key implementation details include:
- Renames `http_request_reauth()` to `http_request_recoverable()` to reflect its expanded role
- Adds new `HTTP_RATE_LIMITED` status code 7
- Implements non-blocking retry delays using slot-specific timers
- Extracts rate limit handling into `handle_rate_limit_retry()` function
- Includes comprehensive test coverage in t5584-http-429-retry.sh (286 lines)

The patch appears well-constructed with thorough test coverage and clear documentation. It follows up on feedback from Taylor Blau on the v1 submission, with significant refactoring to improve maintainability. The implementation maintains backward compatibility by defaulting to no retries (`maxRetries=0`).
