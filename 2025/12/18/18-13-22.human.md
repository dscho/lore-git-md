This is a platform compatibility patch implementing `readlink()` for Windows as part of the larger symlink support series. Johannes Sixt points out that the commit message's claim about failing with ENOSYS when symlinks are disabled doesn't match the actual implementation, which appears to always attempt to read reparse points regardless of symlink configuration.

The patch removes the stub `readlink()` from mingw-posix.h and implements a proper version in mingw.c that uses the previously introduced `read_reparse_point()` function. The implementation handles Windows path conversion and carefully follows POSIX readlink semantics around buffer sizing, including the quirk that it doesn't fail if the buffer is too small - it just truncates the result.

This appears to be a well-constructed piece of the larger Windows symlink puzzle, though Johannes Sixt's observation suggests the commit message may need minor clarification. The implementation looks thorough, handling both file symlinks and directory junctions while maintaining POSIX-compatible behavior.
