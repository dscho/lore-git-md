This is the first patch in a refactoring series for the parallel process execution infrastructure, introducing helper functions to improve code readability around child process state management.

The patch extracts the anonymous struct representing a parallel child process into a named `parallel_child` type and adds the first state-checking helper function `child_is_working()`. This replaces direct state comparisons with a more readable function call at several call sites in `run-command.c`. The change is purely structural - no behavior is modified.

Key technical details:
- Introduces `struct parallel_child` containing the existing fields (state enum, child_process, strbuf err, void* data)
- Adds `child_is_working()` helper that checks for `GIT_CP_WORKING` state
- Updates all existing state checks to use the new helper
- Maintains identical behavior while improving code organization

This is a foundational change for the larger hook subsystem refactoring series, establishing the pattern of named types and helper functions that subsequent patches will build upon. The patch follows Junio Hamano's suggestion to make the state checks more readable. As the first in the series, it sets up infrastructure without yet implementing any of the parallel execution or input/output handling features that come later.
