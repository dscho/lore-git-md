This is a feature patch series adding HTTP 429 (rate limiting) retry support to Git's HTTP client. The v2 series incorporates feedback from Taylor Blau on the initial submission, with significant refactoring of the retry logic and test improvements.

Key changes in v2:
- Renamed `http_request_reauth()` to `http_request_recoverable()` to better reflect its expanded role
- Implemented non-blocking retry delays using slot-specific timers, allowing concurrent requests during delays
- Moved rate limit handling into a separate `handle_rate_limit_retry()` function
- Added slot-specific `retry_delay_seconds` and `retry_delay_start` fields
- Improved test infrastructure with a new `http-429.sh` test helper
- Marked error messages for translation
- Simplified commit messages by referencing git-config(1) for new options
- Fixed a leak in `strbuf_reencode()` by adjusting allocation size

The series maintains the three config options from v1:
- `http.maxRetries` (default 0, opt-in)
- `http.retryAfter` (fallback delay without Retry-After header)
- `http.maxRetryTime` (300s delay ceiling)

Patch 1 contains the core retry logic while Patch 2 adds trace2 instrumentation for monitoring retry operations. The implementation handles both delay-seconds and HTTP-date Retry-After formats per RFC 7231, with extensive test coverage in t5584-http-429-retry.sh (286 lines).

The changes address all review feedback while keeping the core functionality intact. The non-blocking retry implementation is a notable improvement over v1's blocking sleep approach. Test coverage remains comprehensive with new helper scripts reducing duplication.
