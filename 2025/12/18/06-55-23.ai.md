This is a refactoring patch in Patrick Steinhardt's ongoing series to move packfile handling to the object database source level. The change focuses on `unuse_one_window()`, a function that manages packfile memory mapping limits.

The patch removes misleading logic where `unuse_one_window()` took a `packed_git` parameter that was never NULL (despite old code suggesting it could be) and used it primarily to access the repository's object database. The function now directly takes the object database (`odb`) as input, making its purpose clearer. The change also removes redundant scanning of the current packfile since the subsequent loop already checks all packfiles.

Key technical points:
- Removes historical artifact from when `release_pack_memory()` could pass NULL (removed in 2019)
- Eliminates misleading conditional that appeared to handle NULL packfiles
- Simplifies control flow by removing redundant `scan_windows()` call
- Updates callers to pass `p->repo->objects` directly
- Maintains identical behavior since the removed code path was effectively dead

This is a straightforward cleanup that improves code clarity while maintaining the existing memory management behavior. The change fits naturally into the larger series' goal of making packfile handling more explicit about its object database dependencies.
