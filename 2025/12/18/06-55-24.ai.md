This is part 5/10 of Patrick Steinhardt's series refactoring Git's packfile storage to track packs per object database (ODB) source rather than per ODB, a foundational change for pluggable ODBs. The patch moves the packfile store from `struct object_database` to `struct odb_source`, completing the logical transition where each source maintains its own packfile store.

Key technical changes include:
- Adding `packfiles` member to `struct odb_source` and removing it from `struct object_database`
- Initializing packfile stores when creating new ODB sources in `odb_source_new()`
- Updating packfile operations in fast-import, grep, index-pack, pack-objects, http, midx, and odb subsystems to work with source-level stores
- Modifying `repo_for_each_pack()` iterator to traverse all sources' pack stores
- Preserving existing behavior while making the packfile ownership more logically consistent

The patch touches core object storage across 11 files, with mechanical but widespread changes to call sites. While most high-level operations continue working unchanged (via `repo_for_each_pack()`), direct packfile access now properly reflects the source-level ownership. The changes maintain backward compatibility while enabling future abstraction of packfile storage behind ODB source interfaces.

This continues the systematic restructuring from previous patches, with Justin Tobler having reviewed earlier parts. The series is building toward full pluggable ODB support by ensuring all object access routes through owning sources.
