This is patch 3/7 in a performance-focused series improving Git's object info reading interface, preparing for future `odb_for_each_object()` functionality. The patch extends the delta type tracking from a boolean to a 4-state enum (unknown/full/ref-delta/ofs_delta) in `struct object_info`.

The change anticipates a fix coming in the next patch where `packfile_store_read_object_info()` will properly skip parsing objects when only metadata is requested. Currently this case is broken, masking the need for an "unknown" state. The enum replaces the `is_delta` boolean with explicit type tracking, though the "unknown" state isn't yet used in this patch.

Key technical changes:
- New `packed_object_type` enum in odb.h with four states
- Conversion of `is_delta` boolean checks to enum comparisons in packfile.c
- Delta type now explicitly tracked for both REF_DELTA and OFS_DELTA cases
- Stream reading now checks both delta types explicitly

The patch affects two main code paths:
1. `packfile_store_read_object_info()` now precisely records delta types
2. `packfile_store_read_object_stream()` gains more accurate delta filtering

This is part of a coordinated effort with Patrick Steinhardt's parallel odb refactoring work, where interface cleanup precedes performance optimizations. The change maintains backward compatibility while enabling future optimizations around partial object reading.
