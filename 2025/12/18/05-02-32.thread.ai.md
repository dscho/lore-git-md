Thread identity: Proposal for a new `--snapshot` option in `git commit` to create timestamped copies of staged files before committing, with configurable storage location (default `.git/snapshots`).

Core problem/goal: Enable users to create timestamped snapshots of their staged changes before committing, providing an additional safety net and history trail. The implementation would store copies of staged files in a dedicated directory structure that includes both timestamp and sanitized commit message in its name.

Current status: Initial proposal (v1) with untested implementation seeking feedback on concept viability before further refinement. No reviews or acks yet.

Key technical details:
- New files: `snapshot.c` and `snapshot.h` for core functionality
- Modifies `builtin/commit.c` to add `--snapshot` option
- Uses `git diff --name-only --cached` to identify staged files
- Creates directories with `mkdir()` and handles basic error cases
- Sanitizes commit messages (spaces -> underscores) for directory names
- Configurable via `snapshot.enable` (boolean) and `snapshot.folder` (path)
- Currently uses `system()` for shell command execution
- No test coverage yet implemented

- Security implications of arbitrary path configuration
