This is a patch series focused on improving object info reading in Git's object database layer. Patrick Steinhardt presents 8 small but technical improvements to how Git handles reading information about both loose and packed objects. The changes touch core object-handling code across multiple files, with most modifications concentrated in packfile.c.

The series emerges from work on a larger effort to introduce a new `odb_for_each_object()` function, though these preparatory changes stand on their own. A minor conflict exists with another ongoing series (ps/packfile-store-in-odb-source), but the author suggests handling it via an "evil merge" if reviewers agree, as the changes are independent.

Key technical improvements include:
- More consistent handling of object info flags (OI_LOOSE/OI_PACKED)
- Better delta object type tracking
- Optimization for disk size requests
- Cleaner return value handling in packed_object_info()
- Removal of an unnecessary repository parameter

The changes appear focused and well-contained, with each commit addressing a specific technical debt item in the object reading code. The series also incidentally fixes an issue reported by another contributor (though the specific problem isn't detailed in the cover letter). This looks like solid plumbing work that should improve the codebase's consistency and maintainability.
