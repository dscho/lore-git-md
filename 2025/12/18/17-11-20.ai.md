This is part 6 of the hook subsystem refactoring series, converting the reference-transaction hook to use the new `hook.h` API. The patch replaces manual `child_process` setup with the structured `run_hooks_opt` interface, including its stdin feeding mechanism.

The key technical change is the introduction of `transaction_hook_feed_stdin()` as a `feed_pipe` callback that processes one ref update per invocation, streaming the update data through the hook's stdin. The callback handles all the same ref update formatting cases as before (null OIDs, symbolic refs, etc.) but now does so through the standardized hook infrastructure. The implementation maintains the same filtering of `REF_LOG_ONLY` updates and EPIPE handling as the original.

This follows the pattern established in earlier parts of the series, using `feed_pipe_ctx` to pass the transaction and `feed_pipe_cb_data` for per-invocation state (here tracking the current ref index and a reusable strbuf`). The conversion eliminates direct `find_hook()` calls and manual SIGPIPE toggling, which are now handled by the hook API.

The patch has received sign-offs from both Emily Shaffer (who co-authored the series) and Ævar Arnfjörð Bjarmason, suggesting it aligns with the established direction of the refactoring. The commit message notes the potential for future batching optimizations but confirms no performance degradation was observed with the current per-update callback approach.
