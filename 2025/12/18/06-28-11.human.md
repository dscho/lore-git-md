This is a bugfix patch that's part of a larger series improving object info reading in Git's object database. The patch fixes an inconsistency in `odb_source_loose_read_object_info()` where early return paths weren't properly setting the `whence` field to indicate the object came from a loose object store. While no current callers rely on this field in these cases, the author notes this could cause problems in the future.

The change is straightforward - it ensures `OI_LOOSE` is always set on successful returns from the function, including the quick-path case where we don't need to fully open the object. The diff shows careful handling of the status checks and field assignments. This appears to be a clean, focused improvement to the object info infrastructure that prevents potential bugs without introducing new complexity.

As the first patch in an 8-part series, this sets the tone for what looks like a well-considered set of incremental improvements to Git's object handling code. The change is small but meaningful, addressing a subtle issue before it can cause problems.
