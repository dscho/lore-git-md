This is a refactoring patch in an ongoing series improving Git's object database handling, specifically addressing how packed object info is reported. The patch proposes removing the distinction between `OI_PACKED` and `OI_DBCACHED` object types since callers don't actually use this differentiation, and the delta state is already available via the `is_delta` field.

Junio Hamano raises a cautious note in review - while a grep shows no direct uses of `OI_DBCACHED`, there could theoretically be code paths that check for `OI_PACKED` specifically. The author acknowledges this concern and will update the commit message to better document the investigation into potential impacts.

The change simplifies the interface by removing what appears to be an unnecessary implementation detail, continuing the series' trend of cleaning up object info handling. The discussion shows careful consideration of backward compatibility even for seemingly unused features, which is particularly important given this touches core object database code. The patch appears well-motivated and the author is responsive to review feedback.
