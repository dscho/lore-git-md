This is patch 5/10 in Patrick Steinhardt's series refactoring packfile storage to track packs per ODB source rather than per ODB. The patch moves the packfile store from `struct object_database` to `struct odb_source`, completing the architectural shift where each source (main repo or alternate) manages its own packfiles independently.

Justin Tobler's review confirms the change's correctness while raising several implementation questions:
1. Notes that `fast-import.c` only uses the primary source's packfile store, asking if this is intentional
2. Observes that some operations now iterate through all sources' packfile stores (like OID lookups in `fast-import.c` and `pack-objects.c`)
3. Asks whether `packfile_store_load_pack()` handles all sources
4. Questions potential behavior changes if the same OID exists in multiple sources
5. Points out that `http.c` still adds packs only to the primary source's store

The patch affects core object storage across 11 files, with mechanical changes to update packfile store access patterns. Key technical details:
- `struct odb_source` gains new `packfiles` member
- Packfile operations now traverse source lists where needed
- Some transitional cases still use primary source only (marked with comments)
- Functions like `packfile_store_load_pack()` and `packfile_store_add_pack()` now operate on source-specific stores

This continues the series' systematic restructuring toward pluggable ODBs while maintaining current behavior. Justin's review suggests the changes are conceptually sound but flags several edge cases that may need follow-up attention as the series progresses.
