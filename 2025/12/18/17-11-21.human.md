Hook subsystem refactoring (part 7/11): Adding ungroup override capability

This patch in Adrian Ratiu's hook refactoring series addresses a limitation in the parallel execution API where the `ungroup` option was previously hardcoded to true. The change allows callers to control whether child process output should be grouped, which is particularly important for sideband reading scenarios where ungrouping would interfere with output processing.

The patch maintains backward compatibility by keeping the default ungroup behavior for existing APIs (`run_hooks()` and the `hook run` command), while adding explicit comments noting these could be made configurable if future needs arise. The implementation touches four files, adding the new field to `struct run_hooks_opt` and updating the relevant call sites.

This appears to be a straightforward but important addition to the hook infrastructure, enabling more flexible output handling while preserving existing behavior. The change is well-contained and follows the established pattern of the series, with clear documentation of the new field's purpose.
