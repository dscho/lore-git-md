This is the first patch in a 7-part series improving object info reading in Git's object database layer. The patch fixes an inconsistency where early returns in `odb_source_loose_read_object_info()` weren't properly setting the `OI_LOOSE` flag in the object info struct, even though the object being examined was indeed loose. 

While no current callers rely on this distinction, Patrick notes this is a bug waiting to happen. The change ensures the `whence` field is always set to `OI_LOOSE` for loose objects, regardless of which code path is taken. The diff shows careful attention to all possible early return cases, adding the flag setting consistently.

This appears to be a straightforward and well-justified cleanup patch that improves interface consistency. It's part of a larger effort to refactor object database handling and prepare for future `odb_for_each_object()` functionality. The patch modifies only `object-file.c` and focuses narrowly on fixing this specific inconsistency.
