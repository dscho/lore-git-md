This is part 4 of the ongoing hook subsystem refactoring series, converting the post-rewrite hook in sequencer.c to use the new hook API. The patch introduces a `pipe_from_strbuf` callback function that streams hook input directly from memory rather than using temporary files, while maintaining the same functionality.

The key technical change is replacing the manual `child_process` setup with `hook_run_opt()`, which handles SIGPIPE toggling automatically. The new implementation uses the `feed_pipe_ctx` mechanism (introduced in part 3) to pass the commit OIDs as stdin to the hook via a strbuf, with a BUG() assertion ensuring the context is properly set. The hook's "amend" argument is now passed through the `opt.args` strvec.

This conversion follows the series' pattern of simplifying hook execution while maintaining backward compatibility. The change reduces boilerplate by eliminating explicit find_hook() calls and manual process management. The patch has already received sign-offs from both Emily Shaffer (who authored the original hook API work) and Ævar Arnfjörð Bjarmason, indicating technical consensus on the approach.

The implementation demonstrates the series' focus on structured stdin handling - the `pipe_from_strbuf` callback will be reused in later parts of the series for other hooks. The BUG() check for NULL feed_pipe_ctx enforces the API contract established in earlier patches. This is a straightforward conversion that builds on the infrastructure introduced in previous parts while maintaining the hook's existing behavior.
