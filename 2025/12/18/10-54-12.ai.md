This is a v2 patch series (7 parts) improving object info reading in Git's object database layer, continuing the thread about OI_DBCACHED removal and other odb improvements. The series is part of Patrick Steinhardt's ongoing work toward introducing `odb_for_each_object()` functionality.

The key changes in this version:
- Rebased on master with Junio's object-read-stream-fix merged
- Improved commit message for patch 2/7 (OI_DBCACHED removal) to better document the investigation showing only one existing reference (being removed) and no callers needing the distinction
- Dropped the now-redundant empty request fix patch that overlapped with Junio's fix

Technical changes across the series:
1. Always setting OI_LOOSE flag for loose objects
2. Removing OI_DBCACHED distinction (now always OI_PACKED)
3. Extending `is_delta` to a 4-state enum (adding "unknown")
4. Ensuring consistent pack-specific info population
5. Cleaning up `packed_object_info()` return values
6. Optimizing size-only requests (~9% speedup)
7. Removing repository parameter from `packed_object_info()`

The thread shows careful maintainer review of these core ODB changes, particularly around the OI_DBCACHED removal where Junio raised concerns about potential breakage. Patrick has addressed these by documenting the limited impact and showing the change actually provides more consistent information to callers.

The series touches odb.h, object-file.c, packfile.c and related files, with changes focused on making the object info interface more consistent and performant while removing unnecessary distinctions. The work aligns with both the `the_repository` removal effort and Patrick's parallel packfile-store-in-odb-source work, with coordination ongoing about integration points.
