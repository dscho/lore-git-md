This is part 2 of a larger series refactoring Git's hook subsystem to use a new parallel execution API. The patch adds stdin handling capabilities to `run_processes_parallel()`, allowing callers to stream large inputs to child processes without buffering everything in memory.

The change introduces a new `feed_pipe_fn` callback that gets called repeatedly to write data to each child's stdin pipe. This enables incremental feeding of stdin, which is important for hooks that may process large inputs (like the pre-push hook). The implementation includes proper pipe management, SIGPIPE handling, and new state tracking helpers (`child_is_ready_for_cleanup`, `child_is_receiving_input`).

The patch comes with thorough test coverage, including a new test case that verifies stdin handling works correctly with parallel processes. It's a well-motivated change that solves a real limitation in the parallel execution API while maintaining backward compatibility. The implementation looks solid, with clear documentation of the callback contract and careful attention to edge cases like pipe closure and error handling.

This is a foundational piece of the larger hook refactoring effort, enabling subsequent patches to convert existing hooks to use the new parallel API while properly handling their stdin requirements.
