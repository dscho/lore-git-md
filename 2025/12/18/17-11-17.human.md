This is part 3 of a major hook subsystem refactoring series, introducing a callback mechanism for feeding stdin to hooks without filesystem overhead. The patch adds a `feed_pipe` callback to `struct run_hooks_opt` that enables streaming large amounts of data directly to hook processes, building on the parallel stdin handling added in part 2.

The implementation carefully maintains backward compatibility with the existing `path_to_stdin` file-based approach while adding BUG() assertions to prevent misuse of both mechanisms simultaneously. The callback design includes context pointers for both initialization state (`feed_pipe_ctx`) and per-hook internal state (`feed_pipe_cb_data`), with clear documentation about memory management responsibilities.

This change is well-integrated with the series' broader goals of standardizing hook execution while enabling performance optimizations. The patch has already received sign-offs from key contributors (Emily Shaffer and Ævar Arnfjörð Bjarmason) and appears ready for inclusion, with thorough documentation and safety checks in place. The series as a whole is nearing completion, with this patch representing one of the core technical pieces enabling efficient hook execution.
