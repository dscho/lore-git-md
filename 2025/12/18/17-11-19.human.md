This is part 5 of an 11-part series refactoring Git's hook subsystem to use the new `hook.h` API. The patch converts the pre-push hook from manual `child_process` handling to the standardized hook API.

The conversion maintains the same behavior as the original implementation, carefully preserving the ref status filtering logic that was previously discussed and agreed upon by maintainers. The new version uses a `feed_pre_push_hook_data` struct to manage the ref iteration state and a `pre_push_hook_feed_stdin` callback to stream ref updates to the hook process. 

Key improvements in this version include:
- Automatic SIGPIPE handling through the hook API
- Cleaner separation of concerns between transport logic and hook execution
- Removal of manual child process management
- Better error handling through the standardized API

The patch has already been reviewed by multiple contributors, with Ævar Arnfjörð Bjarmason and Emily Shaffer providing signed-off-by tags. The implementation aligns with the series' goal of unifying hook handling while maintaining backward compatibility. This particular conversion was previously discussed in the thread, with consensus reached about keeping the original status filtering behavior.
