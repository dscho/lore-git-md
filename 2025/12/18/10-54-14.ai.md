This is part 2/7 of a performance and interface cleanup series for Git's object database layer, specifically focusing on simplifying the `object_info` interface by removing the `OI_DBCACHED` distinction.

The patch eliminates the `OI_DBCACHED` enum value from `object_info`, making all packfile objects report as `OI_PACKED` regardless of whether they're in the delta base cache. The change is motivated by three key observations: (1) callers don't actually care about the delta base cache distinction, (2) the information can already be derived from the `is_delta` field, and (3) the current behavior could incorrectly report objects as not being in promisor packs when they're cached.

The modification affects three callers that check the `whence` field: `packfile_store_read_object_info()` now provides more complete information for deltified objects, while `repack_local_links()` and `is_not_in_promisor_pack_obj()` will now correctly identify promisor pack objects that happen to be in the delta cache. The change removes an implementation detail from the interface while maintaining all necessary functionality.

The patch follows maintainer feedback from Junio Hamano confirming no callers rely on the `OI_DBCACHED`/`OI_PACKED` distinction. It's a straightforward removal of the enum value from `odb.h` and simplification of the condition in `packfile.c`. This change aligns with the series' broader goals of interface simplification and preparation for future `odb_for_each_object()` functionality.
