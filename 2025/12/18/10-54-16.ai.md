This is patch 4/7 in a performance and refactoring series improving object info handling in Git's packfile subsystem. The patch standardizes how pack-specific object metadata is populated across different code paths.

The change ensures `packed_object_info()` consistently fills in all pack-related fields (offset, pack pointer, and delta type) in the `object_info` struct, eliminating a discrepancy where this information was previously only set by `packfile_store_read_object_info()`. The patch moves the field population logic into `packed_object_info()` and removes the redundant code from `packfile_store_read_object_info()`.

Key technical details:
- Always sets `u.packed.offset` and `u.packed.pack` for packed objects
- Maintains the delta type classification (REF_DELTA/OFS_DELTA/FULL) introduced in patch 3/7
- Affects callers that rely on complete pack metadata, particularly those using the new enum-based delta tracking
- Simplifies the code by removing duplicate logic between the two functions

This change is part of the broader effort to standardize object info handling and prepare for future optimizations, particularly around delta handling. The patch appears straightforward and well-contained, with no obvious edge cases or compatibility concerns based on the diff.
