Refactoring patch in a series improving object info handling, specifically ensuring pack-specific info is always set.

This is the fourth patch in an 8-part series that improves how Git reads object information from the object database. The patch fixes two cases where pack-specific information wasn't being properly populated when reading object info: when calling `packed_object_info()` directly, and when handling empty requests (though the latter case is noted as currently unused, to be addressed in the next patch).

The changes ensure consistent behavior by moving the pack info population logic into `packed_object_info()` itself rather than having it to the caller (`packfile_store_read_object_info()`). This makes the interface more robust by guaranteeing the pack info will always be set when reading from a packfile. The diff shows the straightforward movement of this initialization code, with careful handling of the different object types (full objects vs. delta types).

As part of the larger series preparing for future `odb_for_each_object()` functionality, this change helps establish more reliable invariants in the object info handling code. The patch appears focused and well-contained, touching only packfile.c with clear mechanical changes that don't introduce new behavior.
