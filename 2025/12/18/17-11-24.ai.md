This is part 10 of the hook subsystem refactoring series, converting receive-pack's update and post-update hooks to the new `hook.h` API. The patch builds on the parallel execution and output capture capabilities introduced earlier in the series, specifically using the `consume_output` callback to maintain sideband support for server-side hook output.

The key changes replace direct `child_process` management with the structured `run_hooks_opt` API, eliminating manual hook path lookup and process setup. The update hook now streams ref updates through the new API while preserving the existing sideband behavior via the `hook_output_to_sideband` callback. Similarly, the post-update hook conversion batches ref names into the hook arguments while maintaining output handling consistency.

Technical details include:
- New `hook_output_to_sideband()` helper function that safely relays hook output to clients when sideband is enabled
- Removal of direct `find_hook()` calls and manual `child_process` setup in favor of `run_hooks_opt`
- Preservation of the `use_sideband` flag behavior through the `consume_output` callback mechanism
- Maintenance of existing ref filtering logic (skipping failed updates) in the post-update hook conversion

The patch follows the established pattern of the series by providing a drop-in replacement for the old hook implementation while enabling future enhancements like parallel execution. It has already received sign-offs from both co-authors (Emily Shaffer and Ævar Arnfjörð Bjarmason) and addresses the maintainer feedback from earlier iterations. The changes are focused on receive-pack.c, touching both the update and post-update hook implementations while keeping their external behavior identical.
