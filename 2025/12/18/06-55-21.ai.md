This is patch 2/10 in Patrick Steinhardt's series refactoring packfile storage to track packs per object database source rather than per ODB. The patch simplifies `prepare_pack()` to take an ODB source directly rather than passing individual components through a `prepare_pack_data` struct.

The key changes are:
- Removes `repository`, `local`, and `multi_pack_index` fields from `prepare_pack_data`, replacing them with a single `source` pointer
- Updates `prepare_pack()` to check `source->midx` directly rather than the removed `m` field
- Modifies `packfile_store_load_pack()` call to use `source->odb->packfiles` and `source->local`
- Simplifies `prepare_packed_git_one()` initialization by passing the source directly

This is a mechanical refactoring that maintains existing behavior while reducing indirection in the code. As noted in the thread summary, Justin Tobler has already reviewed and approved this simplification, confirming it properly advances the series' goal of moving packfile operations to work with ODB sources rather than ODBs directly. The change is part of the broader architectural shift to support pluggable ODBs.
