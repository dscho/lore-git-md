Performance optimization in the object database layer, part 6/7 of Patrick Steinhardt's series improving object info handling. This patch specifically optimizes disk size requests by skipping unnecessary header unpacking when only the disk size is needed.

The change modifies `packed_object_info()` in packfile.c to avoid unpacking object headers when the caller only requests disk size information. This provides a measurable 9% speedup in `git rev-list --disk-usage` operations, as shown in the included benchmark. The implementation introduces a new `OBJ_NONE` case to handle these size-only requests while maintaining all other functionality.

Key technical details:
- Adds conditional check for `oi->sizep || oi->typep || oi->delta_base_oid` before unpacking headers
- Introduces `OBJ_NONE` type case in the switch statement to handle size-only requests
- Maintains all existing behavior for requests needing type/delta information
- Benchmarks show consistent ~9% improvement in disk-usage operations

This builds on the series' earlier work standardizing return values and object info handling, while providing a concrete performance benefit. The change is narrowly scoped to size-only requests and doesn't affect other object info use cases.
