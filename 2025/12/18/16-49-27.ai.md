This is a follow-up in the curl 8.18.0 test compatibility thread. Daniel Stenberg, the curl maintainer, reports he has implemented a fix in curl to restore the previous whitespace behavior for header unfolding that was changed in the 8.18.0 release candidates. This addresses the issue that prompted patch 3/3 in the series, which had modified Git's test expectations to handle the new behavior.

The commit referenced would make curl's header unfolding output match its pre-8.18.0 behavior, meaning Git's tests could potentially revert to their original form rather than needing the `--relax-whitespace` workaround added in the patch series. Daniel requests verification that this curl change resolves the test failures that motivated the Git test modifications.

This suggests the third patch in the series may no longer be strictly necessary if curl's behavior is being reverted, though the changes would still provide compatibility during the transition period where both old and new curl versions are in use. The thread had previously noted this unfolding code could eventually be removed once curl 8.18.0 becomes the minimum supported version.
