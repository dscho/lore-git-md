This is part 3 of an 8-part series improving object info reading in Git's object database layer, focusing on packed object handling. The patch extends the `is_delta` boolean field in `struct object_info` to an enum that can represent not just delta vs non-delta states, but also an "unknown" state for cases where we don't parse the object header (like when only position/size is requested).

The change is preparatory - it doesn't yet use the new "unknown" state, but sets up the infrastructure for a follow-up patch that will fix handling of empty requests. The enum cleanly distinguishes between ref deltas, ofs deltas, and full objects, replacing the previous boolean that only tracked "is delta" vs "not delta". 

This appears to be a well-motivated change that improves the precision of packed object type tracking while maintaining backward compatibility. The patch is focused and touches only the necessary parts of odb.h and packfile.c. As part of a larger series cleaning up object info handling, it demonstrates careful attention to edge cases and future needs.
