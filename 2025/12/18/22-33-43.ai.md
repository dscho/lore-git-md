This is a bugfix patch for the bundle-uri subsystem, addressing a segfault that occurs when bundle entries lack a proper URI field. The patch adds validation to catch two error cases: when the URI field is completely missing, and when it's misspelled as "url" instead of "uri".

The core changes add checks in two places: during config parsing (where it scans all bundles and verifies each has a URI) and during fetch operations (where it prevents NULL dereference). The validation produces clear error messages identifying which bundle is problematic. The patch includes new test cases that verify both error conditions are caught.

Key technical details for future reference:
- Adds validation in `bundle_uri_parse_config_format()` that iterates through bundles using `hashmap_for_each_entry`
- Adds a NULL check in `fetch_bundle_uri_internal()` before using the URI
- Tests cover both missing URI and "url" typo cases via `test-tool bundle-uri parse-config`
- Error messages include the bundle ID when available, falling back to "<unknown>"
