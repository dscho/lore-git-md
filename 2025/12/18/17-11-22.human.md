This is part 8 of a 12-part series refactoring Git's hook subsystem to use a new standardized API. The patch introduces output capture capability for parallel processes, allowing callers to intercept and process hook output rather than having it written directly to stderr.

The change adds a `consume_output_fn` callback to `struct run_process_parallel_opts`, which receives hook output in a strbuf. This is particularly useful for server-side hooks that need to relay output to clients. The callback is called even when there's no output, enabling keepalive mechanisms. The patch includes a BUG() assertion to prevent incompatible combinations with the existing `ungroup` option.

The implementation maintains backward compatibility by defaulting to the original stderr behavior when no callback is provided. Test coverage demonstrates the new functionality by diverting output to a file. The patch has already received sign-offs from both co-authors (Emily Shaffer and Ævar Arnfjörð Bjarmason) and fits cleanly into the larger hook refactoring effort.
