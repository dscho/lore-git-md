This is a bugfix patch for the packfile object info reading code, part of the ongoing 8-part series improving object database handling.

The patch addresses a faulty optimization in `packfile_store_read_object_info()` where empty object info requests were meant to short-circuit early by comparing against a static `blank_oi` variable. The comparison was broken because it checked pointer equality rather than content, introduced during code reorganization in commit d9f517d051. The fix introduces a new `object_info_is_blank_request()` helper in odb.h that properly checks if any request fields are populated, replacing the pointer comparison.

The change is small but important - it fixes a performance optimization that wasn't actually working while maintaining the same early-return behavior for empty requests. The patch adds proper blank request detection that works regardless of whether the caller passes their own blank struct or relies on the default initialization. The fix was reported by Aaron Plattner and includes input from Junio Hamano.

This continues the series' theme of improving object info handling reliability, specifically addressing an edge case in packed object reading path. The change is localized to packfile.c and odb.h, adding the new helper function while simplifying the packed object info reading logic. The patch maintains backward compatibility while fixing the broken optimization.
