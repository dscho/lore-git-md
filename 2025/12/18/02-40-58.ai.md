This is a bugfix patch addressing a memory leak in the macOS fsmonitor implementation. The patch adds proper cleanup of CoreFoundation paths that were previously not being freed in both error and normal shutdown paths.

The changes focus on the Darwin-specific fsmonitor listener code, adding CFRelease() calls for three CoreFoundation objects: `cfar_paths_to_watch`, `cfsr_gitdir_path`, and `cfsr_worktree_path`. These are freed in both the constructor's error path (`fsm_listen__ctor`) and the destructor (`fsm_listen__dtor`).

The patch also adds a missing type definition for `CFTypeRef` in the Darwin GCC compatibility header, which is needed for the CFRelease() function prototype. The changes are straightforward and appear to follow CoreFoundation memory management conventions correctly.

The commit message is quite brief, stating only that the paths "are not freed even though they should be." While the fix itself looks correct, the lack of detail about the impact or how the leak was discovered might make reviewers want to ask for more context. The changes are limited to macOS-specific code and don't affect other platforms.
