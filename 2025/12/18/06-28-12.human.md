Refactoring patch in a series improving object info handling. This is the second of eight patches preparing for a future `odb_for_each_object()` function while cleaning up current object database infrastructure.

The patch simplifies the `object_info` interface by removing the `OI_DBCACHED` enum value, which previously distinguished between objects stored normally in packfiles versus those in the delta base cache. The author argues this distinction is an implementation detail that callers don't need to care about, especially since the `is_delta` field already provides similar information. The change removes some complexity while maintaining all necessary functionality.

Changes are minimal - just removing the enum definition and updating one conditional in `packfile.c` to always report `OI_PACKED`. This appears to be a straightforward cleanup with no expected behavior change for callers, continuing the series' theme of making object info handling more consistent. The patch follows logically from the first patch's work on `OI_LOOSE` consistency.
