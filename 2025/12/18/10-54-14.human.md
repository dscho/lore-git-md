This is part 2 of a 7-patch series improving Git's object database interface, specifically focusing on simplifying the object info` reporting for packfile objects. The patch removes the `OI_DBCACHED` enum value that distinguished objects in the delta base cache from other packed objects, now always reporting them as `OI_PACKED`.

The change simplifies the interface while providing more consistent information to callers. The commit message thoroughly analyzes the three existing uses of the `whence` field, showing that none actually need the `OI_DBCACHED` distinction and that treating all packed objects uniformly is actually more correct for promisor pack checks. The patch is small (just 3 lines changed) but meaningful, removing what turns out to be an unnecessary implementation detail from the public interface.

This continues the series' theme of interface cleanup in preparation for future odb functionality. The change has already been vetted in the thread, with Junio Hamano's concerns addressed by Patrick's investigation showing no callers rely on the distinction being removed. The patch appears well-justified and low-risk, removing complexity without affecting functionality.
