This is a bugfix patch addressing memory leaks in the macOS fsmonitor implementation. It's version 2 of a patch that was previously submitted with an author name correction.

The patch fixes CoreFoundation memory leaks in the Darwin-specific fsmonitor code by properly releasing paths (`cfar_paths_to_watch`, `cfsr_gitdir_path`, `cfsr_worktree_path`) in both error handling and normal shutdown paths. The changes add `CFRelease()` calls in `fsm_listen__ctor`'s error path and `fsm_listen__dtor`, and also add a missing `CFTypeRef` type definition in the Darwin GCC compatibility header.

The changes are limited to two files: `compat/fsmonitor/fsm-listen-darwin.c` and `compat/macos/gcc-compat.h`. The patch follows CoreFoundation memory management conventions but provides minimal explanation in the commit message beyond stating "They are not freed even though they should be."
