This is part 4 of Justin Tobler's series extending Git's `repo structure` command with object size reporting. The patch specifically adds inflated object size information to the keyvalue and nul output formats.

The patch introduces a new `inflated_sizes` field in the `object_stats` struct to track size totals per object type (commits, trees, blobs, tags). It collects these sizes using `odb_read_object_info_extended()` with `SKIP_FETCH_OBJECT|INFO_QUICK` flags to get the inflated content sizes efficiently. The sizes are then included in the keyvalue/nul format output with new keys like `objects.commits.inflated_size`.

Key technical details:
- Adds `inflated_sizes` to `object_stats` alongside existing `type_counts`
- Uses `odb_read_object_info_extended()` to get sizes during object counting
- Updates test expectations with SHA1-specific size values (9225 for commits, 28554 for trees etc.)
- Maintains the same output format but extends it with new size fields
- Prepares for subsequent table format support (mentioned as coming in follow-up)

The implementation follows the series' established pattern of careful memory management and test coverage, though this patch focuses only on the machine-readable output modes. The changes are localized to `builtin/repo.c` with corresponding documentation and test updates. The patch builds on the thread's prior work around object info flags and size collection while keeping the human-readable table formatting for a later commit.
