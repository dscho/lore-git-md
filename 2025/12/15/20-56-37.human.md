Feature enhancement for `git repo structure` command, part of a series adding object size reporting.

This patch (v3 5/7) extends the human-readable table output of `git repo structure` to show inflated object sizes by type, alongside the existing object counts. The sizes are formatted with appropriate unit prefixes (KiB/MiB) for readability. The implementation:

1. Adds a new `stats_table_size_addf()` helper that formats size values using the existing `humanise_bytes()` function with a new `HUMANISE_COMPACT` flag for abbreviated unit display ("B" instead of "bytes").

2. Updates the table structure to show both total inflated size and per-type sizes (commits, trees, blobs, tags) under a new "Inflated size" section.

3. Includes test updates showing the new output format, with example values for both empty and populated repositories. The test demonstrates proper scaling (e.g., showing "16.03 MiB" for total size and "217.92 KiB" for commits).

The changes build on prior work in the series that established the table formatting infrastructure and object counting. This completes the human-readable output side of the size reporting feature, while machine-readable formats (keyvalue/nul) remain unchanged as noted in the commit message.

The implementation appears thorough, with careful attention to:
- Maintaining i18n support via gettext wrappers
- Clean separation of formatting logic
- Comprehensive test coverage including SHA1-specific expectations
- Clear commit message explaining the scope of changes

This is a well-executed addition to the series that provides useful visibility into repository object storage characteristics.
