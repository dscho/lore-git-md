Feature patch in the `git repo structure` series, adding inflated object size reporting to keyvalue/nul output formats.

This is the fourth patch in Justin Tobler's v3 series enhancing Git's repository structure reporting. The patch extends the machine-readable keyvalue and nul formats to include the total inflated size of objects by type (commits, trees, blobs, tags). The implementation uses `odb_read_object_info_extended()` with `SKIP_FETCH_OBJECT|INFO_QUICK` flags to efficiently collect size data without inflating objects unnecessarily. The patch maintains the series' careful approach to performance and correctness, adding corresponding test assertions that verify the size calculations against known SHA1 hashes.

The changes introduce a new `inflated_sizes` field in the `object_stats` struct to track sizes alongside counts, with straightforward additions to the keyvalue output formatting logic. Test coverage is updated to check the new size fields while maintaining existing count validations. This represents a logical step in the series' progression toward comprehensive size reporting, following the earlier count-only implementation and preceding the planned human-readable table formatting (mentioned as coming in a subsequent commit).

The implementation looks solid, with clear additions to both core logic and documentation. The test changes follow the series' established pattern of SHA1-specific assertions, though this may need future adjustment for SHA-256 repositories. As with previous patches in the series, the changes are well-contained and focused on the specific enhancement while fitting cleanly with the overall design.
