This is part 5 of Justin Tobler's v3 series extending Git's `repo structure` command with object size reporting. The patch focuses on adding inflated object size information to the human-readable table output format.

The key technical changes include:
- Introduces a new `stats_table_size_addf()` function that handles size formatting using the existing `humanise_bytes()` utility with the new `HUMANISE_COMPACT` flag
- Adds inflated size reporting for each object type (commits, trees, blobs, tags) and a total, displayed with appropriate binary unit prefixes (KiB/MiB)
- Updates the table output tests to verify the new size columns, including specific SHA1 expectations for commit (217.92 KiB), tree (15.81 MiB), blob (11.68 KiB) and tag (132 B) sizes
- Modifies `humanise_bytes()` to support compact "B" unit display via the new `HUMANISE_COMPACT` flag while maintaining full i18n support

The patch cleanly integrates with the series' existing table formatting infrastructure, maintaining proper column alignment and spacing. It builds on prior work that established the `object_stats` struct with `inflated_sizes` field and the human-readable output framework. The test updates demonstrate the expected formatting for both empty and populated repositories, with size values matching the SHA1-specific patterns established earlier in the series.

This completes the human-readable output portion of the size reporting feature, complementing the machine-readable formats addressed in other patches of the series. The implementation shows careful attention to i18n requirements and maintains consistency with the series' decimal (1000-based) unit formatting for counts versus binary (1024-based) for sizes.
