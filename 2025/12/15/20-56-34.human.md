This is a refactoring patch in Justin Tobler's series enhancing Git's `repo structure` command with improved size reporting. The patch splits out the byte-formatting logic from `strbuf_humanise()` into a new `humanise_bytes()` function that separates the numeric value from its unit string. This change enables better column alignment in the upcoming table output for the `repo structure` command.

The refactoring maintains all existing functionality while making the formatting more flexible. The new function handles both regular byte counts and rate-based units (like "MiB/s") through a `HUMANISE_RATE` flag, and preserves the existing IEC unit formatting (KiB/MiB/GiB) and i18n support. The patch includes thorough updates to the string handling while keeping the same rounding behavior and translation markers.

This appears to be a well-considered change that cleanly separates concerns in preparation for the table output feature. The implementation is careful to maintain backward compatibility with existing callers of `strbuf_humanise_bytes()` and `strbuf_humanise_rate()`. The patch follows the series' pattern of methodical improvements to the size reporting infrastructure.
