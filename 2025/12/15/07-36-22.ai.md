Refactoring patch in the ODB source abstraction series, focusing on packfile kept-pack cache.

This third patch in Patrick Steinhardt's 10-part series refactors the kept-pack cache mechanism to work with packfile stores rather than directly with repositories. The kept-pack cache tracks packfiles marked as kept (either via ".kept" files or in-memory flags) to avoid repacking them. The changes:

1. Moves the cache from repository-level to packfile-store level, introducing new `packfile_store_get_kept_pack_cache()` API that takes a packfile store and flags
2. Renames and consolidates the keep flags (`ON_DISK_KEEP_PACKS` -> `KEPT_PACK_ON_DISK`, `IN_CORE_KEEP_PACKS` -> `KEPT_PACK_IN_CORE`)
3. Updates all callers (pack-objects, reachable, revision) to use the new interface
4. Maintains the same caching behavior but now invalidates caches per-store rather than per-repository

The patch touches core packfile handling paths across 5 files, with mechanical changes to call sites. It continues the series' pattern of moving packfile-related functionality to the ODB source level while maintaining existing behavior. The changes appear straightforward and well-contained, following the architectural direction established in earlier patches.
