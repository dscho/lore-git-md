This is a refactoring patch in Justin Tobler's series enhancing Git's `repo structure` command with improved size reporting. The patch splits out byte-formatting logic from `strbuf_humanise()` into a new `humanise_bytes()` function that separates numeric values from their unit strings, enabling better column alignment in the command's table output.

The key technical changes:
- Extracts the core byte-formatting logic into `humanise_bytes()` which returns value and unit strings separately via output parameters
- Maintains all existing IEC unit handling (KiB/MiB/GiB) and i18n support
- Introduces a new `humanise_flags` enum with `HUMANISE_RATE` for rate-based units
- Updates callers (`strbuf_humanise_bytes()` and `strbuf_humanise_rate()`) to use the new interface
- Preserves all rounding behavior and translation markers from the original implementation

The refactoring enables subsequent patches to use the separated value/unit strings for properly aligned table columns in the `repo structure` output. The changes are purely structural - no behavior changes in the formatting itself. The patch follows the series' pattern of careful i18n support and maintains all existing functionality while making the code more flexible for the table display use case.
