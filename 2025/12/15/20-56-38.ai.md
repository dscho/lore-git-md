This is part 6/7 of Justin Tobler's patch series extending Git's `repo structure` command with comprehensive size reporting. The patch focuses on machine-readable output formats (keyvalue and nul), adding disk size information alongside the existing inflated size reporting.

The key technical additions are:
- A new `disk_sizes` field in the `object_stats` struct to track per-type disk usage
- Extension of the `count_objects()` function to collect disk sizes via `oi.disk_sizep` alongside inflated sizes
- Updates to `structure_keyvalue_print()` to output disk size fields in the format `objects.<type>.disk_size`
- Test updates using `git rev-list --disk-usage --filter-provided-objects` to verify the disk size calculations

The implementation maintains consistency with the series' approach to size reporting, using the same object type categorization (commits, trees, blobs, tags) for disk sizes as was already done for counts and inflated sizes. The test changes follow the established pattern of the series, adding verification for the new disk size fields while preserving existing test coverage.

This patch builds on the infrastructure established in earlier parts of the series, particularly the object type counting and size collection mechanisms. It represents the machine-readable counterpart to the human-readable table formatting work done in previous patches, completing the dual-format reporting for both size types.
