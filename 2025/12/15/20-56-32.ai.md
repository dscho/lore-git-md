This is a feature patch series (v3) extending Git's `repo structure` command with object size reporting. The series builds on previous work that added basic object counting, now adding both inflated content sizes and on-disk storage sizes with improved human-readable formatting.

Key technical elements in v3:
- Renames `strbuf_humanise_{bytes,count}_value()` to `humanise_{bytes,count}()` with a new interface that separates numeric values from unit strings
- Makes all size/unit formatting strings translatable for i18n support
- Replaces `OBJECT_INFO_FOR_PREFETCH` with explicit `SKIP_FETCH_OBJECT|INFO_QUICK` flags
- Updates tests to use `git rev-list --disk-usage` for verification
- Introduces `HUMANISE_COMPACT` flag for abbreviated unit display
- Maintains careful separation between machine-readable (keyvalue/nul) and human-readable table output formats

The series shows ongoing refinement from previous rounds, particularly around internationalization concerns raised by Junio Hamano and test improvements suggested by Patrick Steinhardt. The v3 changes focus on making the size formatting more flexible for translation while optimizing memory management by eliminating allocations for unit strings.

Implementation spans `builtin/repo.c`, `strbuf.[ch]`, and test scripts, with the human-readable output now showing both raw counts and scaled values with appropriate units (decimal SI for counts, binary IEC for sizes). The tests verify behavior against both `git cat-file` and `git rev-list` calculations.

This represents the culmination of the size reporting feature, with all major technical concerns from previous rounds addressed. The only remaining gap noted is documentation around `--filter-provided-objects` behavior, which appears to be handled in a separate thread.
