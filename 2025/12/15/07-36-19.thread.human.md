This thread covers Patrick Steinhardt's 10-patch series refactoring Git's packfile storage to track packs per object database (ODB) source rather than per ODB, a key step in the larger ODB abstraction effort. The changes systematically move packfile handling to the source level (main repo/alternates) to prepare for pluggable ODB backends.

Justin Tobler has been providing thorough reviews of the latest being for patch 5/10, which moves the packfile store from `struct object_database` to `struct odb_source`. While confirming the architectural approach is sound, Justin identified several edge cases needing attention: how `fast-import.c` and `http.c` interact with the new structure, whether OID lookups properly handle multiple sources, and if the same OID existing in multiple sources is handled correctly. These are important considerations as the series progresses.

Earlier patches (1-3) have already been reviewed with positive feedback, with Patrick incorporating Justin's documentation suggestions. The changes touch core object storage across many files but maintain existing behavior while laying groundwork for future ODB flexibility. The systematic nature of the refactoring - moving packfile functionality to source level while preserving behavior - has been validated by Justin's reviews, though some transitional cases remain to be addressed.
