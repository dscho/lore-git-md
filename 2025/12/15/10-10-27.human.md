Bugfix for `git replay` segfault regression. This is a follow-up to the recently reported issue where `git replay --onto` would segfault when given a non-existent target commit. The fix, which has already been reviewed and acknowledged as correct by Phillip Wood, moves a NULL check earlier in the function to prevent dereferencing the `onto` pointer before verifying it exists.

The regression was introduced in November 2025 when atomic ref updates became the default behavior for `git replay`. The immediate crash is now properly handled, though Phillip notes there's still a pre-existing issue where invalid `--onto` arguments get the same error message as missing arguments - something that could be improved separately.

The change is minimal (6 lines) and well-scoped, just swapping the order of operations in `builtin/replay.c` to do the NULL check before attempting to use the pointer. The patch maintains the existing limitation that replaying down to a root commit remains unsupported (as noted by the FIXME comment), but now fails safely rather than crashing.

This appears to be a straightforward and correct fix for the reported issue, with the original reporter properly credited. The discussion suggests this will likely be merged without further controversy, while leaving room for future improvements to the error messaging around invalid `--onto` targets.
