Bugfix for `git replay` segfault regression, with reviewer ack.

This is a follow-up to the recently reported `git replay` segfault when using a non-existent `--onto` target. Phillip Wood confirms René Scharfe's fix properly addresses the regression introduced in commit 15cd4ef1f4, moving the NULL check for the `onto` pointer before its first use in `builtin/replay.c`. The change prevents the segmentation fault while maintaining the existing behavior of erroring out for unsupported root commit replay attempts.

Phillip notes there remains a separate preexisting issue where invalid `--onto` arguments are treated identically to missing arguments, but considers this out of scope for the current fix. The patch has already been signed off by the original reporter (Kristoffer Haugsbakk) and now receives explicit approval from Phillip Wood, indicating it's likely to proceed to integration.

The technical change is minimal (6 lines) and well-contained, swapping the position of the NULL check with reflog message construction code that was previously dereferencing the pointer first. The fix maintains the FIXME comment about root commit replay support being a future enhancement. With this ack from a core contributor, the patch appears ready for inclusion in the next cycle.
