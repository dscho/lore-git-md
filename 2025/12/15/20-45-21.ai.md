Platform compatibility patch addressing iconv issues on macOS 14/15 (Sonoma/Sequoia). This is the first in a 3-part series proposing a workaround for broken ISO-2022-JP conversions in macOS's system iconv implementation.

The patch documents test failures where `git show` partially converts ISO-2022-JP commit messages to UTF-8, leaving escape sequences in the output. The root cause appears to be macOS's iconv losing state during piecemeal conversions when the output buffer needs resizing. The commit proposes two solutions: linking against third-party iconv (already supported via Fink/MacPorts) or modifying Git's buffer handling.

The technical solution in this commit adds an optional `ICONV_RESTART_RESET` mode that, when enabled, resets the conversion state and restarts from scratch when expanding the output buffer. The change is guarded by a preprocessor flag, with build system integration coming in a follow-up patch. The approach was suggested by René Scharfe and includes references to similar issues encountered in other projects.

Key technical details:
- Modifies `reencode_string_iconv()` in utf8.c
- Adds state reset via `iconv(conv, NULL, NULL, NULL, NULL)`
- Restores original buffer positions when retrying
- Requires explicit opt-in via `ICONV_RESTART_RESET` define
- Follow-up will add Makefile knob for activation

The patch appears well-motivated by concrete test failures and offers a conservative solution that maintains backward compatibility while addressing the macOS-specific issue. The commit message thoroughly documents the problem and solution approach.
