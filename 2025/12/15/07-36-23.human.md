This is a refactoring patch in Patrick Steinhardt's ongoing series to restructure Git's packfile storage. The patch cleans up some misleading code in `unuse_one_window()`, which handles memory management for packfile windows.

The function takes a `packed_git` parameter that appears optional but has actually been required since 2019. The current implementation confusingly checks for NULL but then dereferences the pointer anyway. The patch simplifies this by having callers pass the object database directly, making the interface more straightforward.

The change is mechanical and doesn't affect behavior - it just removes some historical baggage from when the function had different callers. The patch continues the series' trend of moving packfile operations toward the object database level rather than repository level, though this particular change is more about code clarity than architectural shifts.

The commit message provides thorough historical context about how this code evolved to its current state, showing this is a well-considered cleanup rather than an arbitrary change. The diff is small (11 lines changed) and focused, touching only packfile.c.
