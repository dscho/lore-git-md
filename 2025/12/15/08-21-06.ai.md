This is a refactoring patch in Justin Tobler's series to improve Git's object size reporting, specifically addressing internationalization concerns in the human-readable output formatting.

Junio Hamano points out that the refactored `strbuf_humanise_bytes_value()` function introduces several localization regressions compared to the previous implementation. The new version enforces three constraints that may not hold across all languages: (1) decimal points must be periods, (2) numbers must precede units, and (3) exactly one space must separate numbers from units. These requirements could cause problems for languages with different formatting conventions.

The patch shows the refactored code that splits the humanization logic into two parts - `strbuf_humanise_bytes_value()` (which handles the numeric formatting) and `strbuf_humanise_bytes()` (which combines the number with its unit). While the first point about decimal separators could be fixed relatively easily, Junio notes that addressing the other two constraints would require more involved changes to maintain proper internationalization support.

This feedback comes as part of the ongoing refinement of the series' output formatting capabilities, following earlier optimizations to the test infrastructure and size reporting mechanisms. The issue highlights the tension between code refactoring for maintainability and preserving existing localization behavior, particularly around numeric formatting conventions that vary by language.
