Milos Markovic has proposed a new "rebaser-flow" workflow that prioritizes production branches over QA and development branches, flipping the typical developer-centric model. The proposal is currently conceptual rather than a patch submission, with a reference implementation available on GitHub. While the author reports successful production use, there are no concrete metrics provided.

This would cause the implementation to fail in non-Bash environments. The response focuses on this specific technical limitation rather than engaging with the broader workflow philosophy.

The discussion remains in early stages, with no clear path yet for Git core integration. Key open points include the need for more portable scripting if the workflow is to gain wider adoption, along with the original questions about implementation requirements and how this model differs from existing Git branching approaches.
