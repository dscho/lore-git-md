Thread summary:

Build system refactoring series targeting Darwin/macOS platform configuration, currently at part 2/3. The series reorganizes platform-specific build settings by moving Darwin/macOS configurations from the main Makefile to config.mak.uname, following patterns used for other platforms. The patch relocates Fink (/sw) and MacPorts (/opt/local) paths, Apple Common Crypto vs OpenSSL selection, Pthread handling, and CoreServices framework linkage - preserving functionality while improving maintainability.

René Scharfe identified a technical issue with the approach: since config.mak.uname is included before config.mak in the build process, any Darwin-specific overrides in config.mak would be ignored. This creates a regression for users who customize builds via config.mak. The issue must be resolved before the series can proceed - either by adjusting the inclusion order or finding an alternative approach that preserves config.mak overrides while still consolidating platform settings.

The patch remains a mechanical refactoring with no intended functional changes, but the discovered ordering constraint affects real-world use cases. The original author Torsten Bögershausen will need to address this feedback in a v2, likely by either reordering the includes or documenting the limitation if changing the order isn't feasible. The thread awaits his response on how to proceed.
