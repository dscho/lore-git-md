This thread concerns a build system refactoring series that reorganizes platform-specific configuration, currently focusing on Darwin/macOS settings. The initial patch (part 2/3) moved these settings from the main Makefile to config.mak.uname, keeping all functionality intact but improving maintainability. The changes included handling of Fink/MacPorts paths, crypto library selection, and framework linkages.

René Scharfe has identified a significant technical issue: the relocation breaks the expected override precedence, as config.mak.uname is included before config.mak in the build process. This means any user customizations in config.mak would be silently ignored for these Darwin-specific settings. The mechanical correctness of the patch is not in question, but the change in behavior for customized builds needs resolution before the series can proceed. The discussion now turns to whether to adjust the inclusion order or find another way to preserve the override capability while still achieving the consolidation goal.
