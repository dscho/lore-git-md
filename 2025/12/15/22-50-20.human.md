Documentation review feedback on style and organization. Kristoffer Haugsbakk responds to Jean-Noël Avila's documentation cleanup patch series, suggesting the changes could be better organized into separate commits. The original patch mixed several types of doc fixes: imperative mood standardization, wording improvements, markup corrections, and parameter additions. Haugsbakk notes that while all valuable, these would be easier to review and bisect if split into logical groupings - one commit for prose/style changes and another for technical/markup fixes. He provides specific examples where the current combined approach makes it harder to quickly assess the nature of changes when searching history. The feedback is constructive, focusing on commit organization rather than the content of the changes themselves, which appear correct and improve the documentation. This continues the thread's theme of refining documentation quality through both substantive improvements and better patch hygiene.
