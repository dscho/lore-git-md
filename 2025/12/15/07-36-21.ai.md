This is the second patch in Patrick Steinhardt's series refactoring packfile storage to be tracked per object database source. The change focuses on the `prepare_pack()` function, which handles packfile initialization.

The patch simplifies the `prepare_pack_data` struct by removing redundant fields (`r`, `local`, `m`) that can be accessed through the `odb_source` instead. Now the struct only needs to track the source and garbage collection list. The key changes are:
- Replacing direct repository/flag/MIDX references with access through `data->source`
- Updating `packfile_store_load_pack()` to use the source's ODB packfiles and local flag
- Simplifying the call site in `prepare_packed_git_one()`

This is a straightforward refactoring that reduces parameter passing and better aligns with the series' goal of moving packfile handling to the ODB source level. The changes are mechanical and maintain existing behavior while cleaning up the interface. As with the rest of the series, this appears to be uncontroversial groundwork for the larger ODB abstraction effort.
