This is part 3/7 of a feature series enhancing Git's `repo structure` command with human-readable output formatting. The patch focuses on improving the display of large count values in the table output format.

Justin Tobler's patch introduces human-friendly formatting for repository statistics like reference and object counts. When values exceed certain thresholds (1,000, 1,000,000, or 1,000,000,000), they are now displayed with appropriate unit prefixes (k, M, G) and decimal places for better readability. The implementation adds a new `humanise_count()` function to `strbuf.[ch]` that separates the numeric value from its unit string, allowing for proper column alignment in the output table.

The changes maintain backward compatibility with the machine-readable keyvalue and nul formats, which continue to output raw numbers. The patch includes updated tests showing the new formatting in action, including a test case with over 1,000 commits where the counts now display as "1.01 k" rather than the raw number.

This is a well-executed refinement to the series, building on previous work to make repository statistics more accessible while preserving precision. The implementation is thorough, with proper i18n support and clean separation of concerns between the formatting logic and table presentation.
