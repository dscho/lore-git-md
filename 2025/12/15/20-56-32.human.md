This is the v3 version of Justin Tobler's feature series extending Git's `repo structure` command with object size reporting. The series now includes both inflated content sizes and on-disk storage sizes, with improved output formatting and internationalization support.

The key changes in v3 focus on making the size display more localization-friendly:
- Number formatting is now properly marked for translation
- The humanize functions now separate numeric values from unit strings to allow flexible translation
- Unit strings are now constants rather than allocations
- The humanize flags have been moved to a proper enum

The series builds on previous feedback from Patrick Steinhardt (test improvements) and Junio Hamano (i18n concerns). It maintains careful separation between machine-readable (keyvalue/nul) and human-readable output formats, with the latter now properly handling:
- Decimal (1000-based) SI units for counts
- Binary (1024-based) IEC units for sizes
- Compact "B" units vs full "byte/bytes" strings
- Proper rounding and formatting

The implementation touches `builtin/repo.c`, `strbuf.[ch]`, and test scripts, with thorough test coverage that now uses `git rev-list --disk-usage` for verification. The changes appear well-considered and address all previous review feedback while maintaining the series' original goal of providing better repository size insights.
