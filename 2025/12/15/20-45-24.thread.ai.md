Platform compatibility patch series (v0) addressing macOS-specific iconv behavior, focusing on Sonoma (14+) and upcoming macOS 15+. Third patch in series (3/3) modifies `config.mak.uname` to handle system iconv library quirks when Git is built against macOS's built-in iconv rather than third-party versions (Homebrew, MacPorts, Fink). Introduces `HAS_GOOD_ICONV` variable to track presence of known-good third-party iconv installations (/usr/local/opt/libiconv, /opt/homebrew/opt/libiconv, /sw/lib, /opt/local/lib). When using system iconv on affected versions (detected via `uname_R` parsing for version 20+), defines `ICONV_RESTART_RESET` to ensure correct behavior with utf8.c. Workaround is precisely scoped to only activate when no known-good iconv is detected. Implementation checks multiple common installation paths and gates behavior behind version checks. Patch appears technically sound but lacks description of specific symptoms being addressed by the workaround.
