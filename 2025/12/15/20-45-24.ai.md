This is a platform compatibility patch addressing macOS-specific iconv behavior. It's the third in a series (v0 3/3) but no cover letter context is provided.

The patch modifies `config.mak.uname` to handle macOS's built-in iconv library in versions 14+ (Sonoma) and 15+. When Git is built against the system iconv (rather than third-party versions from Homebrew, MacPorts, or Fink), it needs `ICONV_RESTART_RESET` defined to work correctly with utf8.c. The change introduces a new `HAS_GOOD_ICONV` variable that tracks whether a known-good third-party iconv is present, and only applies the workaround when using the system version on affected macOS releases (detected via `uname_R` parsing for version 20+).

The implementation checks multiple common installation paths for third-party iconv libraries (/usr/local/opt/libiconv, /opt/homebrew/opt/libiconv, /sw/lib, /opt/local/lib) and sets `HAS_GOOD_ICONV` if found. The workaround is cleanly gated behind version checks and only activates when no known-good iconv is detected. This appears to be a well-scoped solution to a specific platform quirk, though the commit message could benefit from mentioning any observable symptoms the workaround fixes.
