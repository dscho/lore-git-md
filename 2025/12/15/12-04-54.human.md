This is a follow-up to the recently approved bugfix for a `git replay` segfault when using a non-existent `--onto` target. Kristoffer Haugsbakk is proposing an additional improvement to the error handling in `builtin/replay.c`.

The patch changes the behavior when invalid commit-ish arguments are provided to `--onto` or `--advance`. Currently, the code silently returns NULL for invalid commit-ishes, which then triggers a generic "root commit not supported" error. The new version would instead immediately die with a specific error message identifying the invalid commit-ish argument.

The change appears straightforward - modifying the `peel_committish` helper to call `die()` rather than return NULL when the commit cannot be found. Kristoffer notes this should provide better error messages, though they haven't yet verified whether there might be memory leak implications from this change in error handling path.

This builds on the just-fixed segfault issue but addresses a separate preexisting behavior that Phillip Wood had noted in the previous review. The patch is still in-progress ("cooking locally") and not yet ready for full review, but shows promising direction for improving user feedback when invalid arguments are provided.
