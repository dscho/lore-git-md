Refactoring patch in the ongoing packfile store migration series, specifically addressing the kept-pack cache interface.

This is the third patch in Patrick Steinhardt's 10-part series restructuring Git's packfile handling to operate at the ODB source level rather than repository level. Justin Tobler reviews the changes to the kept-pack cache mechanism, which tracks packfiles marked as kept (either via .kept files or in-memory flags).

The patch makes several coordinated changes:
- Renames and reorganizes the kept-pack type flags into an explicit `enum kept_pack_type`
- Updates the cache accessor from `kept_pack_cache()` (repository-based) to `packfile_store_get_kept_pack_cache()` (store-based)
- Adjusts related documentation and call sites to match the new interface

Justin notes the changes are correct and align with the series' goals, but suggests two minor improvements to the commit message: explicitly mentioning the flag reorganization and updating outdated comments in packfile.h. The review confirms this continues the mechanical but important groundwork for the larger ODB abstraction effort, with all changes being straightforward adaptations to the new packfile store model.
