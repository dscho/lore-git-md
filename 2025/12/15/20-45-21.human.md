This is a bugfix targeting character encoding issues on macOS, specifically addressing problems with the system's `iconv` implementation in macOS 14/15. The patch provides a workaround for incorrect conversion of ISO-2022-JP text to UTF-8, which causes test failures in Git's test suite.

The issue manifests when `iconv` performs piecemeal conversions of stateful encodings like ISO-2022-JP - the macOS version appears to lose state between buffer resizes. The patch introduces a new approach where, when the output buffer needs expansion, the conversion restarts from scratch with the new buffer size while preserving the converter state.

The change is gated behind an `ICONV_RESTART_RESET` compile-time flag, with a follow-up patch promised to add a Makefile knob for controlling it. The commit message is thorough, citing specific test failures, explaining the technical background, and mentioning alternative solutions (like linking against third-party `iconv` implementations from Fink/MacPorts).

This appears to be a well-motivated change addressing a real-world compatibility issue, with clear test evidence and a focused implementation. The patch is part of a 3-part series, with this being the core technical change.
