This is the first patch in a 10-part refactoring series moving packfile storage tracking from the object database (ODB) level to individual ODB sources (main repo, alternates etc.), as part of the ongoing ODB abstraction effort.

The patch modifies `packfile_store_new()` to be initialized via an ODB source rather than directly via the ODB itself, though the store remains owned by the ODB at this intermediate stage. This prepares for future transition to source-owned stores while maintaining current behavior. Key changes include:
- The store creation signature and implementation in packfile.c
- Store initialization in odb.c to use the primary source
- All packfile store operations to now access the repo via `store->source->odb->repo` instead of `store->odb->repo`
- Updated struct packfile_store to track its source rather than the ODB directly

The patch touches core packfile handling paths but is a mechanical refactoring with no intended behavior change. It introduces a temporary architectural inconsistency (stores created by sources but still ODB-owned) that will be resolved in later patches. This foundational work continues the established direction of ODB abstraction with changes to 3 files (odb.c, packfile.c, packfile.h) affecting packfile store initialization and access patterns.
