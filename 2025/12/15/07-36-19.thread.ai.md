Patrick Steinhardt's 10-patch series refactoring Git's packfile storage to track packs per object database (ODB) source rather than per ODB is now complete with patch 10/10. The series enables pluggable ODBs by ensuring all object access routes through owning sources (main repo/alternates), with the final patch moving MIDX (multi-pack index) tracking from `struct odb_source` to `struct packfile_store`.

Key architectural changes in the completed series:
- All packfile-related data (regular packs, kept packs, MIDX) now managed by packfile stores
- `find_pack_entry()` and other core functions made source-aware
- MIDX handling updated to flow through packfile store operations
- Callers now explicitly prepare stores when needed
- Maintains identical object lookup behavior while making ownership explicit

Technical implementation details:
- 30+ files modified across the series
- Packfile operations now properly reflect source-level ownership
- MIDX and pack preparation simplified to operate on individual stores
- Direct packfile access updated in fast-import, grep, pack-objects, etc.
- Final patch touches 5 files with mechanical changes to MIDX handling:
  - `midx.c` updates all MIDX access paths
  - `odb.c` removes redundant MIDX cleanup
  - `odb.h` removes `midx` field from `struct odb_source`
  - `packfile.c` updates MIDX checks and cleanup
  - `packfile.h` adds `midx` field to `struct packfile_store`
