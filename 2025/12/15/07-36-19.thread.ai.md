Patrick Steinhardt's 10-patch series continues refactoring Git's packfile storage to track packs per object database (ODB) source rather than per ODB, advancing the ODB abstraction effort. The changes systematically move packfile handling from ODB to source level (main repo/alternates), completing groundwork for pluggable ODBs by ensuring all object access routes through owning sources.

Justin Tobler has reviewed seven patches in the series:
- Patch 1/10: Confirmed architectural shift where packfile stores now reference ODB sources rather than ODBs directly, while noting transitional awkwardness with alternate source preparation.
- Patch 2/10: Approved simplification of `prepare_pack()` to take ODB source directly.
- Patch 3/10: Verified kept-pack cache interface changes, suggesting documentation updates which Patrick implemented.
- Patch 5/10: Confirmed correctness of moving packfile store to `struct odb_source` while raising implementation questions about edge cases in `fast-import.c`, `pack-objects.c`, and `http.c`.
- Patch 6/10: Approved simplification of `packfile_store_get_packs()` to only prepare MIDX for the specific packfile store being operated on, noting callers either work with single stores or already iterate through sources.
- Patch 8/10: Approved inlining of `find_kept_pack_entry()` into `has_object_kept_pack()`, catching a minor typo ("allow" -> "allows") while confirming the change simplifies the kept-pack lookup path without functional impact.

Technical details from reviews and discussion:
- Packfile store struct stores `source` pointer instead of `odb`
- `struct odb_source` gains `packfiles` member
- ODB still accessible via `source->odb` when needed
- Current transitional state prepares alternate sources through same packfile store
- `packfile_store_new()` and `prepare_pack()` now take source parameter
- Kept-pack cache accessor renamed to `packfile_store_get_kept_pack_cache()`
- Kept-pack type flags reorganized into explicit `enum kept_pack_type`
- Packfile operations now traverse source lists where needed
- Some transitional cases still use primary source only (marked with comments)
- Functions like `packfile_store_load_pack()` and `packfile_store_add_pack()` now operate on source-specific stores
- Updates to `packfile_store_load_pack()`, `packfile_store_prepare()`, and related documentation
- Removal of intermediate `prepare_pack_data` struct
- `packfile_store_get_packs()` simplified to only prepare MIDX for current store
- Callers either work with single stores or explicitly loop through sources
- `find_kept_pack_entry()` inlined into `has_object_kept_pack()`, eliminating indirection
- Combined function made file-local by removing packfile.h declaration
