Patrick Steinhardt's 10-patch series refactors Git's packfile storage to track packs per object database (ODB) source rather than per ODB, completing foundational work for pluggable ODBs by ensuring all object access routes through owning sources (main repo/alternates). The changes systematically move packfile handling from ODB to source level, with key technical changes including packfile store struct storing `source` pointer instead of `odb`, `struct odb_source` gaining `packfiles` member, and functions like `packfile_store_load_pack()` and `prepare_pack()` now taking source parameters.

Justin Tobler has reviewed nine patches in the series:
- Patch 1/10: Confirmed architectural shift where packfile stores now reference ODB sources rather than ODBs directly, while noting transitional awkwardness with alternate source preparation.
- Patch 2/10: Approved simplification of `prepare_pack()` to take ODB source directly.
- Patch 3/10: Verified kept-pack cache interface changes, suggesting documentation updates which Patrick implemented.
- Patch 4/10: Reviewed relocation of packfile store ownership from `struct object_database` to `struct odb_source`, identifying edge cases in `fast-import.c`, `index-pack.c`, `pack-objects.c`, and `http.c` that will need future resolution.
- Patch 5/10: Confirmed correctness of moving packfile store to `struct odb_source` while raising implementation questions about edge cases.
- Patch 6/10: Approved simplification of `packfile_store_get_packs()` to only prepare MIDX for the specific packfile store being operated on, noting callers either work with single stores or already iterate through sources.
- Patch 8/10: Approved inlining of `find_kept_pack_entry()` into `has_object_kept_pack()`, catching a minor typo ("allow" -> "allows") which Patrick acknowledged. The change makes the combined function file-local by removing its packfile.h declaration.
