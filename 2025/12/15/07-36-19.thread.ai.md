Patrick Steinhardt's 10-patch series (v3) refactors Git's packfile storage to support pluggable object database (ODB) backends by moving packfile store ownership from the ODB layer to individual ODB sources. The series builds on prior work to make object lookup source-aware while maintaining identical behavior, with 40+ files modified across core packfile operations.

Key technical changes across patches 1-5:
- Packfile stores now initialized per-source (`struct odb_source`) rather than per-ODB (`struct object_database`)
- `prepare_pack()` simplified to take ODB source directly by reducing `prepare_pack_data` struct
- Kept-pack cache functionality moved to operate on packfile stores with renamed functions
- `unuse_one_window()` and `close_one_pack()` updated to scan all sources, removing obsolete parameters
- Packfile operations (fast-import, grep, pack-objects) adapted to explicitly prepare stores
- Core functions like `find_pack_entry()` made source-aware while maintaining behavior
- MIDX (multi-pack index) tracking will move from `struct odb_source` to `struct packfile_store` in later patches

Series progression:
1. Initial packfile store initialization changes
2. Simplified `prepare_pack()` to take ODB source directly
3. Kept-pack cache refactored to use packfile stores
4. `unuse_one_window()` cleanup
5. Packfile store ownership moved to ODB sources (this patch)
6. Refactored kept-pack cache (reviewed by Justin Tobler and Toon Claes)
7-10. MIDX and final architectural completion

Review process:
- Justin Tobler reviewed patches 1-3
- Toon Claes provided detailed feedback on patches 3-5 and 7, initially misunderstanding patch 7's simplification before recognizing its correctness
- Kristoffer Haugsbakk noted and Patrick fixed a typo in patch 8 (`has_oject_kept_pack` -> `has_object_kept_pack`)
- Patrick addressed all feedback and provided historical context
- Series builds on two other recently merged topics

The v3 iteration incorporates all prior feedback. While the abstractions remain "leaky" (per Patrick), this represents the last major step before introducing pluggable ODB backends. Patch 5 specifically moves packfile store ownership to ODB sources, affecting 11 files but maintaining identical behavior through high-level iteration functions. All open questions from review have been resolved and the series is ready for inclusion.
