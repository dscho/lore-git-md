Patrick Steinhardt's 10-patch series (v3) completes the refactoring of Git's packfile storage to track packs per object database (ODB) source rather than per ODB, establishing the architectural foundation for pluggable ODB backends. The series moves all packfile-related data (regular packs, kept packs, MIDX) to be managed by packfile stores owned by individual ODB sources, with 30+ files modified to make object lookup source-aware while maintaining identical behavior.

Key technical changes:
- Packfile stores now track MIDX (multi-pack index) data instead of ODB sources
- Core functions like `find_pack_entry()` updated to be source-aware
- MIDX and pack preparation simplified to operate on individual stores
- Callers (fast-import, grep, pack-objects) updated to explicitly prepare stores
- Final patch moves MIDX tracking from `struct odb_source` to `struct packfile_store` in 5 files (`midx.c`, `odb.c`, `odb.h`, `packfile.c`, `packfile.h`)

Series progression highlights:
1. Initial packfile store initialization changes
2. Simplified `prepare_pack()` to take ODB source directly
3. Refactored kept-pack cache (reviewed by Justin Tobler and Toon Claes) - Moved to packfile store ownership with updated accessors
4. Packfile store ownership cleanup (reviewed by Toon Claes) - Removed legacy NULL packfile handling
5. Completed packfile store relocation (reviewed by Toon Claes) - Toon noted minor grep.c documentation nit
6-10. MIDX and final architectural completion

Review process:
- Justin Tobler reviewed patches 1-3
- Toon Claes provided detailed feedback on patches 3-5 and 7, initially misunderstanding patch 7's simplification of `packfile_store_prepare()` before recognizing its correctness in limiting preparation to single stores
- Kristoffer Haugsbakk noted a typo in patch 8's commit message (`has_oject_kept_pack` -> `has_object_kept_pack`), which Patrick fixed in v3
- Patrick addressed all feedback and provided historical context for changes
- Series builds on two other recently merged topics

The v3 iteration incorporates all prior feedback, including the typo fix and improved commit messages. While the abstractions remain "leaky" (per Patrick) and will need further refinement, this represents the last major step before introducing pluggable ODB backends. The changes are mechanical but wide-ranging, affecting packfile handling across commands like fast-import, grep, and pack-objects. All open questions from review have been resolved and the series is ready for inclusion.
