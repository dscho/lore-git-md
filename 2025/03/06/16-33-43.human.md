Junio Hamano responds to Johannes Schindelin's patch about Windows/Meson compatibility with concerns about build system readiness. This is part of an ongoing discussion about Git's Windows build infrastructure during the Meson transition.

Hamano acknowledges the technical correctness of Schindelin's patch to make `ident.c` work with GCC 14.2.0/MSVCRT by changing a pointer type, and states he will apply it. However, he expresses deeper reservations about the broader Meson support on Windows, calling it "untested and unproven" given the late discovery of fundamental toolchain differences between CI environments and Git for Windows' needs.

The response suggests Hamano would be uncomfortable using Meson-built artifacts on Windows in their current state, proposing instead that Windows Meson support might need to be temporarily disabled until properly vetted. This contrasts with Schindelin's position that the Meson transition must proceed despite these issues. The exchange highlights growing tensions between maintaining multiple build systems and ensuring production-ready Windows builds.
