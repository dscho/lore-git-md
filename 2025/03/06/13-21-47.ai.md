Performance optimization series for refs subsystem (patch 2/16). This is a foundational change enabling subsequent optimizations in the refname availability checking workflow.

The patch introduces a new flag `GET_OID_SKIP_AMBIGUITY_CHECK` to bypass the reference ambiguity check in `get_oid_basic()` and related functions. The check normally warns when an object ID string could also be interpreted as a reference name, but this adds runtime overhead that isn't always needed. The flag will be used by later patches in the series to optimize refname verification.

Karthik Nayak provides a minor style nit about macro alignment in the review comment, noting it's not worth a re-roll. The change itself is straightforward - adding the new macro definition in hash.h and modifying the condition in object-name.c to respect the flag while maintaining all existing warning behavior when the flag isn't set.

This is part of a larger effort to optimize refname availability checks across Git's storage backends (files, packed, reftable). The series shows measured performance improvements of 1.19-1.27x for files backend and 2.32-7.56x for reftable in later patches. This particular change enables those optimizations by allowing callers to skip the ambiguity check when they know it's unnecessary.
