Follow-up bugfix for merge-ort backend addressing directory rename crash.

This is Elijah Newren's response to Dmitry Goncharov's reported merge-ort crash during cherry-picks involving conflicting directory renames. The thread had previously identified that Goncharov's initial fix approach (ignoring self-move renames) would produce misleading conflict messages, so Newren is providing an alternative solution.

Newren has prepared a two-patch series that: (1) incorporates Goncharov's test case into the existing merge test suite (t6423 rather than a new t3515), and (2) implements a proper fix that handles the directory rename conflict in merge-ort without crashing. The changes focus on the rename collection logic and conflict detection paths in merge-ort.c. Notably, the recursive backend's incorrect behavior with this case is being left as-is since that backend is slated for removal.

The patches are now available via GitGitGadget at the provided link. This represents the authoritative fix from the merge machinery maintainer, properly addressing the edge case by surfacing the conflict to users rather than crashing, while maintaining merge-ort's robustness. The solution avoids the problematic aspects of the initial approach while still resolving the core issue.
