This is patch 7/12 in Patrick Steinhardt's series to remove `the_repository` usage from object APIs, specifically targeting the pack-bitmap-write subsystem. The patch converts bitmap writing operations to use explicit repository contexts stored in the `bitmap_writer` struct rather than relying on the implicit global state.

Key technical changes:
- Adds `repo` field to `struct bitmap_writer` to store repository context
- Removes `USE_THE_REPOSITORY_VARIABLE` define from pack-bitmap-write.c
- Updates all trace2 calls to use writer->repo instead of the_repository
- Converts tree lookups, progress reporting, and hash operations to use writer->repo
- Modifies bitmap header writing to use repository-specific hash algorithms
- Updates permission adjustment and file handling to use repository context

The changes follow the established pattern seen in earlier patches of the series, systematically replacing implicit global state with explicit repository parameters. The patch touches core bitmap writing functionality including commit selection, tree traversal, and final bitmap file generation, ensuring all operations use the correct per-repository context.

This continues the series' methodical approach to removing global state while maintaining existing behavior. The changes are focused and mechanical, similar to previous patches in the series, with no apparent behavior changes beyond the explicit repository parameterization. Reviewers will likely focus on ensuring the bitmap writing logic remains correct when operating with different repository contexts.
