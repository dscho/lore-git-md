Feature addition to `git describe` implementing `--no-optional-locks` option.

This first patch in a two-part series adds the `--no-optional-locks` option to `git describe`, following the same pattern already established for `git status`. The change addresses a specific pain point in scripting scenarios where concurrent Git operations can cause lockfile conflicts when `--dirty` triggers background index updates.

The implementation is clean and focused, wrapping the index update logic in a `use_optional_locks()` check. Documentation updates clearly explain the background refresh behavior and when to use this option. A new test case verifies the option prevents index from being updated, matching the test approach used for `git status`.

This appears to be a well-considered change that solves a real problem encountered in automated environments (the author mentions build systems specifically). The patch follows Git's established patterns and includes thorough documentation and testing. The second patch in the series will apply this same option to `git diff`.
