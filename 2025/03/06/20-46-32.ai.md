Maintainer commentary on remote naming conventions. Junio Hamano reflects on the historical design decisions around remote names containing slashes, noting they were never intended as a primary use case despite being technically permitted. He observes that slashed remote names break the useful globbing pattern `refs/remotes/*/master` and suggests this might warrant reconsideration at a major version boundary (Git 3.0), though acknowledges such a change would be non-trivial.

The email provides important historical context about the remote namespace design from 2005, explaining how the current behavior emerged from filesystem-based URL detection logic. While not blocking the immediate completion fixes (which the thread summary shows have already been resolved), it raises a larger architectural question about whether to formally restrict remote naming conventions in a future Git version. This maintains compatibility with existing thread resolution while surfacing a potential long-term direction for the project.
