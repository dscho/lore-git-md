Performance optimization for refs subsystem (v5, 16 patches) completing the batched refname availability checks series. This is the final version of Patrick Steinhardt's work addressing inefficiencies in refname verification across all Git ref backends (files, packed, reftable), particularly for operations involving many references.

The series implements three key optimizations:
1. Skips redundant object ID ambiguity checks in `git-update-ref` (patches 1-4)
2. Introduces batched verification of refname prefixes using a `strset` to avoid re-checking common paths (patches 5-9)
3. Implements iterator reseek capability across all ref backends to reuse state when checking nested refs (patches 10-16)

Performance improvements are substantial, especially for reftable:
- Files backend: 1.19-1.27x speedup in edge cases, 1.23x in realistic scenarios
- Reftable backend: 2.32-7.56x speedup in edge cases, nearly 5x (15x vs files) in realistic cases

The v5 iteration includes minor commit message improvements and flag value alignment in `GET_OID_*` constants. Karthik Nayak's prior review confirmed technical soundness with only documentation nits remaining. The series now demonstrates reftable outperforming files backend in realistic workloads while maintaining backward compatibility.

Key technical changes include new iterator seek APIs, batched verification infrastructure in `refs.c`, and backend-specific implementations. The optimizations particularly benefit operations like mass ref updates and repository cloning. While originally motivated by reftable tombstone inefficiencies, the improvements generalize to all ref operations.
