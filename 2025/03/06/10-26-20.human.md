Build system patch completing a CMake fix series for unit test linking.

This is the third and final patch in Johannes Schindelin's series addressing build system issues during Git's Meson transition. It fixes a CMake build failure that occurred when the `sk/unit-test-oid` changes landed in v2.49.0, causing unresolved symbol errors during Windows builds. The issue stems from hard-coded test object lists in CMake that weren't properly tracking Makefile changes.

The patch generalizes the handling of `CLAR_TEST_OBJS` in CMakeLists.txt, mirroring an earlier solution for `UNIT_TEST_OBJS`. Instead of maintaining a duplicate list, it now parses the canonical list from the Makefile. This prevents future whack-a-mole updates when test infrastructure changes. The changes are mechanical but important for keeping the CMake build in sync, particularly affecting Windows developers using Visual Studio.

The patch appears well-justified and builds on established patterns, having already solved a similar problem for related test objects. It completes the series' goal of smoothing build system transitions while maintaining compatibility with Git for Windows' development environment.
