Performance optimization for the files backend's initial ref transactions. This is patch 7/16 in a series addressing refname availability checks across Git's ref backends.

The patch refactors how the files backend handles refname availability checks during initial transactions (like those during clone or format migration). Instead of verifying each refname individually in a loop, it now collects all refnames first and performs a single batched verification. While this doesn't yet show performance improvements (those come in later patches), it lays the groundwork by restructuring the code to use the new batched verification API introduced earlier in the series.

The changes are mechanical but important - they maintain all existing behavior (including error handling and conflict detection) while preparing for future optimizations. The commit message notes this will particularly help performance when cloning repositories with many refs or migrating between ref storage formats. The implementation follows the same pattern already applied to the reftable backend in patch 5/16, showing consistent architectural approach across backends.
