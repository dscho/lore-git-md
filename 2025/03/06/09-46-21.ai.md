This is a refactoring patch in Karthik Nayak's partial reference transaction series, specifically addressing the centralization of duplicate refname checking in the refs infrastructure.

The patch moves refname tracking from individual backends (files, reftable) into the generic `ref_transaction` layer, adding a `refnames` string_list field to track all references in a transaction. This eliminates 146 lines of duplicate code across backends while maintaining the same functionality. The reftable backend is adjusted to perform its duplicate check before rather than after adding updates to avoid false positives.

Junio Hamano approves the core approach, noting the transaction object is the logical place for this tracking. He raises an interesting future direction - whether symref handling (like HEAD updates) could also be moved to the generic layer, which would further simplify backend implementations. Karthik acknowledges this as a good potential future improvement but notes it wasn't part of the current scope.

The change demonstrates good incremental progress in the series - centralizing common functionality while leaving room for future generalization. Junio's conceptual approval and Karthik's responsiveness to the feedback suggest this is a solid step in the refactoring effort. The patch maintains all existing behavior while making the codebase more maintainable by reducing duplication.
