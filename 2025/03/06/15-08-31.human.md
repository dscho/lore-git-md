Cover letter for a performance optimization series targeting refname availability checks across Git's ref backends. This v5 series from Patrick Steinhardt builds on earlier work to address inefficiencies in how Git verifies refname availability, particularly in the reftable backend.

The series implements three key optimizations:
1. Skips unnecessary ambiguity checks in `git-update-ref` when parsing object IDs (patches 1-4)
2. Introduces batched refname availability checks to avoid redundant prefix verifications (patches 5-9)
3. Implements iterator reuse infrastructure to avoid recreating iterators for nested ref checks (patches 10-16)

Performance improvements are substantial, especially for the reftable backend which sees up to 7.56x speedup in the original benchmark case (deleting and recreating refs) and nearly 5x improvement in more realistic scenarios with many preexisting refs. The files backend also benefits with 1.23-1.27x speedups.

The series has undergone thorough review iterations, with v5 incorporating minor commit message improvements and flag value alignment. Karthik Nayak's final review of v4 confirmed technical soundness with only minor documentation nits remaining. The optimizations maintain backward compatibility while delivering measurable performance gains, particularly for repositories with many references.
