Test case exposing a crash in merge-ort's directory rename detection.

This patch adds a test case that triggers an assertion failure in `merge-ort.c`'s `process_renames()` function when handling a specific directory rename scenario. The test demonstrates a case where:
1. One branch renames directory A/ to B/
2. Another branch adds new files to A/
3. Directory rename detection tries to move these new files to B/
4. If the file originally came from B/, this creates a circular rename back to itself

The test is modeled after similar cases in t6423 and follows the same style. It shows that merge-ort currently crashes with an assertion failure when encountering this edge case, though the commit message suggests the expected behavior should be to detect a conflict and emit an appropriate message (which the test verifies via grep).

The test is marked with `test_expect_failure` since it currently exposes a bug. The patch includes setup code to create the specific merge scenario and verifies the expected error output. This appears to be a well-constructed test case that isolates a real issue in the merge machinery, though the commit message could be more explicit about whether this represents a regression or long-standing bug.
