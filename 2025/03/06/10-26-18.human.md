Platform compatibility fix for Git for Windows' Meson build.

This patch fixes a long-standing but previously unnoticed issue in `ident.c` where the code incorrectly assumed the `gw_gecos` field was writable. The problem surfaces specifically when building with GCC 14.2.0 targeting MSVCRT in Git for Windows' development environment, though it doesn't appear in CI due to different compiler versions and flags there.

The change itself is simple - making a loop variable `const char *` instead of `char *` - but Johannes provides extensive background on why this is surfacing now during the Meson transition. He notes this reveals a mismatch between Git for Windows' actual development environment and what the CI tests, suggesting the `win+Meson` job may not be fully representative.

While technically a correctness fix, the timing (during Meson transition) and specific circumstances (only failing in a particular development setup) make this a somewhat unusual case. The patch appears well-justified and narrowly scoped, though some might question whether it needs to be rushed in versus waiting for the next cycle.
