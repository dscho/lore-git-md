Platform compatibility fix addressing a long-standing assumption in Git for Windows' development environment.

This patch modifies `ident.c` to use `const char *` for the `gw_gecos` buffer loop variable, fixing a 2011-era assumption that the field would be writable. The issue specifically manifests when building with GCC 14.2.0 targeting MSVCRT in Git for Windows' development setup, though it doesn't appear in CI environments which use different compiler versions and targets. The change is minimal (1-line modification) but addresses a correctness issue that surfaced during Git's Meson build system transition.

The commit provides detailed investigation showing this is a Git-for-Windows-specific development environment issue, not affecting CI builds. It also notes the context of ongoing Meson adoption pressures that make this fix timely despite the issue's long dormancy. The technical change itself is straightforward - changing a variable type to properly reflect the const nature of the source data.

Key technical details for future reference:
- File modified: `ident.c`
- Function changed: `copy_gecos()`
- Old behavior: Used non-const `char *src` to iterate `gw_gecos`
- New behavior: Uses `const char *src`
- Trigger conditions: GCC 14.2.0 + MSVCRT target + specific Meson build flags
