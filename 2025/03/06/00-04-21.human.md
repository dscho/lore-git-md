This is a follow-up in the ongoing discussion about language-specific `.gitignore` support in `git init`. Oleg Taranenko responds to Junio Hamano's clarification about the template system's boundaries by arguing for persistent ignore patterns across multiple repositories. 

Taranenko acknowledges Hamano's point about `.git/info/excludes` being the proper scope for template usage, but suggests this mechanism falls short for developers who frequently create many small repositories (like for learning exercises) where they'd want consistent ignore patterns. The email implies that the current template approach would require manual copying of excludes files for each new repo, which may be cumbersome in these workflows.

The response doesn't propose a concrete solution but seems to be pushing back against the maintainer's strict interpretation by highlighting a real-world use case where the current template mechanism creates friction. This continues the thread's tension between Git's design philosophy and practical developer needs, though Taranenko hasn't yet addressed Hamano's core concern about keeping language-specific features out of core Git.
