Structural refactoring in the ongoing `the_repository` removal effort.

This is patch 10/12 in Patrick Steinhardt's series to eliminate global `the_repository` usage in object APIs. The patch moves all hash algorithm implementation code from `object-file.c` to a new `hash.c` file, separating concerns between object file handling and hash computation. The change is purely organizational - no behavior modifications are made.

Key technical details:
- Creates new `hash.c` with all hash-related functions and data structures:
  - SHA-1 and SHA-256 implementations (init`, `update`, `final` operations)
  - Empty tree/blob OID constants for both algorithms
  - Hash algorithm lookup functions (`hash_algo_by_name`, `hash_algo_by_id`)
  - `unsafe_hash_algo` optimization infrastructure
- Removes equivalent code from `object-file.c`
- Updates build systems (Makefile, meson.build) to include new file
- Maintains all existing functionality including:
  - Support for both SHA-1 and SHA-256
  - "Unsafe" fast-path variants
  - Algorithm detection by name/ID/length

The change follows the series' pattern of methodical, incremental refactoring while maintaining behavior. This prepares for future patches that will make the hash algorithm repository-specific rather than global. Review focus should be on verifying the code movement preserves all functionality and doesn't introduce new implicit dependencies on global state.
