This is a bugfix patch series addressing a crash in merge-ort's rename handling. The issue involves a specific edge case where a file is transitively renamed to itself during a merge, triggering an assertion failure in process_renames().

The series consists of two patches: First, Dmitry Goncharov contributes a test case that reproduces the assertion failure, demonstrating the problematic scenario. Then Elijah Newren provides the actual fix, modifying the assertion in merge-ort.c to properly handle this edge case. The test case involves complex directory renames where a file ends up being renamed to itself through multiple steps.

The bug appears to be long-standing rather than a recent regression, so it's not marked as urgent for the upcoming release. The fix is relatively small (3 lines changed in merge-ort.c) but comes with thorough test coverage (41 lines of new test code). The patch references prior discussion from Dmitry's original bug report, showing this is a well-investigated issue.

Key technical details for future reference: The problematic scenario involves the interaction between directory renames and transitive file renames in merge-ort.c's process_renames() function.
