This is a refactoring patch in Patrick Steinhardt's performance optimization series for the refs subsystem (patch 9/16). It decouples iterator lifecycle management from iteration itself to enable future iterator reuse and simplify calling patterns.

The patch changes how ref iterators are managed by:
1. Removing automatic cleanup when iteration completes, requiring explicit `ref_iterator_free()` calls
2. Replacing `ref_iterator_abort()` with a simpler `ref_iterator_release()` that doesn't return status
3. Updating all iterator implementations (files, packed, reftable backends) to match
4. Adding proper cleanup in all call sites that previously relied on auto-cleanup

The key motivation is to enable potential future iterator reuse (like re-seeking to different prefixes) while making the API more consistent with Git's typical resource management patterns. The changes are mechanical but touch many files since the iterator interface is widely used.

This builds on earlier patches in the series that introduced batched refname verification and prefix optimizations. The changes maintain all existing behavior while cleaning up some awkward patterns where callers had to carefully time `abort` calls. Performance impact appears neutral - this is infrastructure work enabling future optimizations rather than an optimization itself.

The patch has been reviewed in previous iterations with only minor nits noted, and fits cleanly into the larger series that shows measurable speedups for ref-heavy operations.
