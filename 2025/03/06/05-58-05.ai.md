This is the second patch in a series adding `--no-optional-locks` support, extending it to `git diff` after the first patch covered `git describe`. The change allows scripts to prevent background index updates during diff operations, matching the behavior already implemented for `git status`.

The patch modifies `builtin/diff.c` to check `use_optional_locks()` before refreshing the index, updates documentation in both the main Git manpage and diff-specific config docs, and adds a new test file `t4070-diff-auto-refresh-index.sh`. The tests verify that:
1. The index updates when `diff.autoRefreshIndex` is true (default)
2. The index doesn't update when `diff.autoRefreshIndex` is false
3. `--no-optional-locks` overrides `autoRefreshIndex=true`

The implementation follows the same pattern as the existing `git status` behavior, using the established `test_is_magic_mtime` pattern for lockfile testing. The changes are focused and well-scoped, addressing a specific automation pain point where concurrent Git operations could cause lock contention. The test coverage appears thorough, verifying both the config and command-line flag behaviors.

This completes the series' goal of bringing consistent `--no-optional-locks` behavior to commands that perform background index updates. The changes are conservative and maintain backward compatibility while solving a real-world issue encountered in build system scenarios.
