This is the second patch in a series adding `--no-optional-locks` support to commands that perform background index updates. It extends the option to `git diff`, completing the work started with `git describe` in the first patch.

The change prevents `git diff` from updating the index in the background when `--no-optional-locks` is specified, which is useful for scripting scenarios where concurrent Git operations might cause lock contention. The implementation follows the same pattern as `git status`'s existing behavior, wrapping the index update logic in `use_optional_locks()` checks.

The patch updates documentation in both the main Git manpage and diff-specific config docs to reflect the new behavior. It also adds a new test file `t4070-diff-auto-refresh-index.sh` that verifies the functionality using Git's established magic mtime verification pattern. The tests confirm that the index updates as expected by default, but respects both the config setting and command-line override.

This appears to be a well-scoped change that addresses a real pain point in automation scenarios while maintaining backward compatibility. The implementation is consistent with existing patterns in the codebase and includes thorough test coverage. The patch series as a whole provides a clean solution to lockfile conflicts in scripting environments.
