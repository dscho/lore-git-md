This is the foundational first patch in a 16-part performance optimization series for Git's refs subsystem. The patch introduces `repo_get_oid_with_flags()`, a new function that extends `repo_get_oid()` by accepting flags to modify its behavior. This small but important API change enables subsequent optimizations in the series, particularly around refname availability checks.

The change is straightforward - it factors out the existing `repo_get_oid()` implementation to call through to the new function with a default flags value of 0, while exposing the new function for callers that need flag control. The patch includes both the implementation and header declaration, plus documentation clarifying this is for handling object ID expressions like "xyz^".

As the first in a series that has already gone through multiple iterations (now at v5), this patch represents well-scoped preparatory work. It's a clean, focused change that establishes the API groundwork needed for the more substantial optimizations that follow in the series. The commit message could perhaps explain more about which flags will be used later, but the minimal approach is reasonable for a foundational patch.
