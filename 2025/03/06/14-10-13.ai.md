Performance optimization patch for the refs/files backend, part of a larger series improving refname availability checks across Git's ref backends. This is patch 7/16 in v4 of the series, focusing on batching refname checks during initial transactions in the files backend.

The patch modifies `files_transaction_finish_initial()` to collect refnames into a string list first, then verify them in a single batch using the new `refs_verify_refnames_available()` API introduced in patch 4/16. While this doesn't yet improve performance (the underlying verification still happens in a loop), it sets up the infrastructure for future optimizations that will benefit cloning and ref migration operations. The patch includes a minor documentation issue where a sentence appears incomplete ("This doesn't yet have an effect on performance as the underlying logic simply calls").

Key technical changes:
- Adds `refnames_to_check` string list to collect refnames
- Moves verification after packed refs locking but before transaction commit
- Maintains same error handling flow (TRANSACTION_NAME_CONFLICT/GENERIC_ERROR)
- Cleans up both string lists (affected_refnames and refnames_to_check)

The change is part of a coordinated effort to optimize ref operations across all backends (files, packed, reftable), with this patch specifically addressing the files backend's initial transaction case. The series has shown significant performance gains (1.19-1.27x for files backend in other patches), though this particular patch is primarily preparatory work for those optimizations.
