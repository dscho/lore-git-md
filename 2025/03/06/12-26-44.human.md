This is a follow-up in the ongoing discussion about Windows build system compatibility during Git's Meson transition. Johannes Schindelin responds to Patrick Steinhardt's suggestion to standardize Windows CI environments using Meson's `--vsenv` flag.

Schindelin strongly opposes further investment in Visual Studio support via Meson, calling the developer experience "too weak" compared to CMake. He reveals plans to drop Visual Studio build support entirely after Git 2.49.0, including removing CMake definitions and Meson-specific configurations from Git for Windows. The message conveys frustration with the maintenance burden, stating the effort "was not worth the time invested."

This represents a significant policy shift that would affect Windows contributors, effectively deprecating Visual Studio as a supported development environment for Git. The tone suggests this is a firm decision rather than a proposal for discussion, though it may spark debate about Windows build system strategy. The message doesn't address how this would impact CI systems currently using MSVC (like GitLab's Windows runners mentioned earlier in the thread).
