This is a feature patch series adding `--no-optional-locks` support to `git describe` and `git diff`. The change addresses a real-world issue where background index updates by these commands can cause stale lockfile problems in build scripts.

The series comes from a practical need - the author's team has encountered sporadic lockfile issues when using `git describe` in build scripts. They currently work around this by using libgit2, but want native Git CLI support. The implementation follows the pattern already established by `git status`'s `--no-optional-locks` option.

The patches look well-constructed, with thorough test coverage (including new test files) and documentation updates. The changes are focused - just adding the new option behavior while maintaining existing functionality. This appears to be a straightforward quality-of-life improvement for script authors who need to avoid background index operations.
