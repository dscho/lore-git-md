Performance optimization patch introducing batched refname verification as part of the refs subsystem optimization series.

This patch 4/16 in the v5 series introduces `refs_verify_refnames_available()`, a new API that checks reference name availability for multiple refs at once. The function performs the same validation as the existing single-ref `refs_verify_refname_available()` (which is now reimplemented as a wrapper), but processes a list of refnames in a single operation. The initial implementation maintains identical behavior to the single-ref version, with the actual batching optimizations coming in later patches.

Key technical details:
- New function signature takes a `string_list` of refnames instead of single `refname`
- Maintains all existing validation logic (prefix/suffix conflicts, extras/skip lists)
- Current implementation simply loops through refnames (optimizations follow in later patches)
- Modifies `refs.c` (169 lines changed) and adds declaration to `refs.h`
- Preserves all error messages and edge case handling
- Part of broader effort to optimize ref operations across files/packed/reftable backends

The patch follows the series' pattern of first establishing new APIs before optimizing them, with this being the foundational change enabling batched verification. It touches core refs infrastructure but maintains backward compatibility. The diff is best viewed with `--ignore-space-change` due to the indentation changes from wrapping the existing logic in a loop.
