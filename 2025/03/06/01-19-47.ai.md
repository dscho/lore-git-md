This is a cover letter for a two-patch bugfix series addressing issues with the `--exclude` feature in Git's ref iteration. The series aims to unify behavior between different ref backends and handle edge cases more consistently.

The first patch fixes an issue where empty `--exclude` patterns were being processed incorrectly, while the second patch aligns the behavior of `--exclude` between the files and packed backends. The second fix was prompted by a user report (linked in the cover letter), and during investigation the author discovered the first issue as well.

The changes touch core refs.c functionality and include corresponding test updates in t1419-exclude-refs.sh. The patches appear focused and well-motivated, with clear references to the reported issue and additional improvements the author noticed during development. The series builds on commit 6a64ac7b014f from the main Git development history.
