Bugfix series addressing `--exclude` pattern matching inconsistencies in Git's ref iteration. This is a v2 reroll of a two-patch series that fixes edge cases in how ref exclusions are handled across different ref backends.

The series makes two key changes to `--exclude` behavior:
1. Removes empty exclude patterns before they reach backend-specific code
2. Stops matching non-directory prefixes in exclude patterns, requiring exact matches or proper directory boundaries

The v2 changes are minor refinements based on previous review feedback:
- Reworded the second patch's subject line to better reflect its behavior change
- Split the test cases to properly distinguish between non-directory exclusions and true hierarchical overlaps
- Added new test coverage for actual hierarchical ref exclusion cases

The implementation modifies core refs.c logic used by commands like `for-each-ref` and `upload-pack`, building on prior ref backend optimization work (commits 6a64ac7b014f and 59c35fac54). The changes preserve all existing non-empty pattern functionality while fixing the edge cases.

Reviewers have already approved the technical approach, with this version addressing test case organization feedback from Patrick Steinhardt. The test suite now properly validates both the empty pattern removal and the stricter prefix matching behavior, including performance assertions for the jump list behavior.
