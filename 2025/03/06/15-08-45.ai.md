Performance optimization patch implementing iterator seeking for packed-ref backend, completing the series' iterator reseek capability across all ref backends (files, reftable, and now packed-refs). This patch follows the same pattern as previous iterator implementations (patches 12-13/16) but handles packed-refs' specific characteristics.

Key technical changes:
1. Adds `prefix` field to `packed_ref_iterator` struct (heap-allocated like other backends)
2. Implements new `packed_ref_iterator_seek()` function using `find_reference_location()`
3. Modifies `advance()` to handle prefix matching directly rather than using `prefix_ref_iterator`
4. Removes empty iterator optimization to support reseeking
5. Maintains iterator state (position, EOF marker) during seeks
6. Updates iterator lifecycle to free the prefix

The implementation differs from other backends by open-coding prefix matching in `advance()` rather than using the prefix iterator wrapper, as the latter would prevent reseeking between empty and non-empty prefixes. The change localizes all packed-ref iterator logic to `refs/packed-backend.c` while maintaining the series' consistent approach to iterator reseeking.

This completes the series' goal of implementing reseekable iterators across all ref backends, with packed-refs being the final backend to receive this optimization. The patch follows the established pattern of heap-allocated prefixes and explicit seek methods while handling backend-specific requirements.
