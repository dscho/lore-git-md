Performance optimization patch in the refs subsystem series, specifically targeting `git-update-ref`'s object ID parsing. This patch (3/16 in v5) builds on the foundation from patch 2/16 by applying the new `GET_OID_SKIP_AMBIGUITY_CHECK` flag to `git-update-ref`, eliminating expensive reference ambiguity checks during object ID parsing.

The change modifies `builtin/update-ref.c` to use `repo_get_oid_with_flags()` with the new flag in five key locations where object IDs are parsed. The rationale is threefold: (1) update-ref is plumbing where unambiguous object IDs are expected, (2) the warning about ambiguity is rarely seen in non-interactive use, and (3) the check creates significant overhead in batch operations. This follows the precedent set by `git-cat-file`'s similar optimization in commit 25fba78d36b.

Benchmarks show substantial speedups: 1.19x faster for files backend (394.1ms vs 467.3ms) and 2.32x for reftable (63.2ms vs 146.9ms) when creating 10,000 refs against 100,000 existing refs. The larger relative improvement in reftable comes from its faster baseline performance. The patch maintains all existing behavior except suppressing the ambiguity warning, which the commit argues is appropriate for this plumbing command.

This is part of the larger refs optimization series that has received positive reviews, with only minor documentation nits remaining. The change is technically sound and consistent with the series' goal of optimizing ref operations across all backends.
