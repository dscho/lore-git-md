Performance optimization for merged ref iterators in refs subsystem (patch 11/16). This patch implements seeking capability for merged reference iterators, a key piece of the larger series optimizing refname availability checks across Git's ref backends.

The change modifies the merged iterator implementation to support the new `ref_iterator_seek()` operation introduced in patch 10/16. The main technical challenge addressed is preserving the underlying iterators even after exhaustion, since they may need to be reused for subsequent seeks. The patch splits the iterator pointers into owned and working copies to maintain this state.

Implementation is straightforward, with the pattern:
1. Resets iterator state on seek
2. Forwards seek operation to both underlying iterators
3. Maintains existing merge logic for advancement
4. Properly cleans up owned iterators on release

This builds on the iterator reseek capability foundation from patch 10/16, completing the implementation for merged iterator case. The change is part of the performance optimization series that has already shown significant speedups (1.19-1.27x for files backend, 2.32-7.56x for reftable). With Karthik Nayak's positive review of the technical approach and only minor documentation nits remaining, this appears ready for inclusion.
