Performance optimization for the files ref backend in a ref transaction series. This is patch 7/16 in Patrick Steinhardt's v4 series improving refname availability checks across Git's ref backends.

The patch refactors the initial transaction handling in the files backend to use batched refname availability checks, though the performance impact isn't yet realized in this commit. The author notes this will help future optimizations for operations like cloning repositories with many refs or migrating refs to the files format. The change moves from individual refname checks to collecting refnames in a string list and verifying them in a batch.

Karthik Nayak points out a minor issue with an incomplete sentence in the commit message that needs fixing. The actual code changes show the transition from per-ref verification to batched verification using the new `refs_verify_refnames_available()` API introduced earlier in the series. The patch maintains the same verification logic but reorganizes it to prepare for future performance improvements.

This continues the series' pattern of making consistent changes across all ref backends (files, packed, reftable) to support batched operations. While not yet showing speedups itself, it's a necessary step toward the series' demonstrated performance gains of 1.19-1.27x for the files backend in later patches.
