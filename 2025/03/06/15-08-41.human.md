Performance optimization in refs subsystem (patch 10/16) introducing iterator reseek capability. This patch adds infrastructure to allow ref iterators to be reused by seeking to new prefixes without requiring full reinitialization, a key optimization for the reftable backend.

Patrick Steinhardt builds on the iterator lifecycle refactoring from patch 9/16 by adding a new `.seek` vtable function that enables reusing iterators with different prefixes. The change maintains identical behavior to creating fresh iterators but allows backends to optimize by preserving internal state. Currently implemented for debug and prefix iterators, with other backend implementations to follow in subsequent patches.

The patch is part of a larger series optimizing refname availability checks that has already shown significant performance gains (1.19-1.27x for files backend, 2.32-7.56x for reftable). This particular change enables future optimizations in the reftable backend where iterator reuse can avoid expensive reinitialization costs. The implementation is clean and focused, with clear documentation of the new API's behavior.
