Refactoring of ref iterator lifecycle management in the refs optimization series.

This patch (9/16) decouples iterator lifecycle from iteration completion in Git's refs subsystem. Currently, iterators are automatically freed when exhausted, which is unusual in Git's codebase and causes two problems: 1) callers must carefully time `ref_iterator_abort()` calls to avoid use-after-free, and 2) prevents iterator reuse for reseeking. 

The changes introduce explicit `ref_iterator_free()` and `dir_iterator_free()` functions that callers must use to clean up iterators, while removing the automatic freeing behavior. This makes the lifecycle more conventional and enables potential future optimizations like iterator reuse. The patch also removes the return value from `ref_iterator_abort()` since it wasn't meaningfully used, and consolidates cleanup in `ref_iterator_free()` rather than having backends call `base_ref_iterator_free()`.

Key technical changes:
- Adds `release` vtable function replacing `abort`
- Introduces `ref_iterator_free()` API
- Modifies all iterator implementations (files, packed, reftable backends)
- Updates callers to explicitly free iterators
- Preserves special handling for `dir_iterator` which doesn't implement `ref_iterator`
- Updates test helper to demonstrate new usage pattern

The change is part of Patrick Steinhardt's performance optimization series for ref operations, building toward iterator reseek capabilities in later patches. It follows established patterns from earlier patches in the series while maintaining backward compatibility. The explicit lifecycle management will enable future optimizations while making the code more maintainable.
