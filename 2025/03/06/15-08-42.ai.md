This is a performance optimization patch in the refs subsystem series, implementing iterator reseek capability for merged iterators. It's patch 11/16 in the v5 series focused on optimizing refname availability checks across Git's ref backends.

The patch modifies the merged iterator implementation to support seeking by:
1. Adding separate `iter0_owned` and `iter1_owned` fields to track the underlying iterators even after they're exhausted
2. Implementing a new `merge_ref_iterator_seek()` function that resets both underlying iterators and propagates the seek operation to them
3. Updating the release logic to free the owned iterators rather than the active ones
4. Preserving the existing merge selection behavior while allowing iterator reuse

Key technical details:
- The implementation avoids deallocating exhausted iterators (previously done in `advance()`) to enable reseeking
- Seeks reset the merged iterator state and propagate the prefix to both underlying iterators
- The vtable gains a new `seek` operation while maintaining all existing functionality
- Changes are localized to `refs/iterator.c` with no interface changes

This builds on patch 10/16's introduction of the seek API and prepares for subsequent optimizations in the series. The change is part of enabling iterator reuse across ref operations, particularly benefiting batched verification scenarios. The implementation follows the pattern established earlier in the series while handling the merged iterator's special case of combining two input streams.
