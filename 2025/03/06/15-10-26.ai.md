This is part 2/12 of Patrick Steinhardt's series to reduce `the_repository` usage in object APIs, continuing the systematic elimination of global state dependencies. The patch converts several key object-related functions in `object.c` to take explicit repository parameters:

1. Core changes:
- Converts `get_max_object_index()`, `get_indexed_object()`, `parse_object_or_die()`, and `clear_object_flags()` to take `struct repository*` parameters
- Removes `USE_THE_REPOSITORY_VARIABLE` from object.c
- Updates all callers (15 files) to pass `the_repository` where needed

2. Key technical impacts:
- Object hash table access now requires explicit repository context
- Maintains identical behavior while removing implicit global state
- Follows established pattern from patch 1/12 (csum-file.c conversion)
- Touches core object lookup and flag management infrastructure

3. Review context:
- Builds on v1 feedback by maintaining consistent parameter ordering
- Avoids controversial renames from v1 (per Karthik Nayak's review)
- Part of broader effort enabling pluggable ODB work

The changes are mechanical but wide-ranging, affecting object lookup paths across multiple commands (fsck, grep, pack-objects, etc.). The patch demonstrates careful attention to maintaining existing behavior while advancing the series' architectural goals.
