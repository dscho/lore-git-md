Performance optimization completing the refs subsystem iterator reuse series. This final patch (16/16) implements iterator reuse for refname availability checks across all backends, building on the iterator reseek capability introduced in earlier patches. The change modifies `refs_verify_refnames_available()` to reuse iterators when checking for nested references rather than recreating them for each check, with significant performance gains in the reftable backend (1.25x faster in benchmarks) though minimal impact on the files backend due to its inherent filesystem overhead.

Key technical changes include:
- Conditional iterator creation only when none exists
- Safe iterator reseeking via new `ref_iterator_seek()` call
- Maintained error handling through existing cleanup path
- Preserved skip-list functionality for excluded refs
- Backend-agnostic implementation building on vtable changes from patches 12-15

The patch completes the series' goal of eliminating redundant iterator allocations during ref operations, particularly benefiting reftable where iterator state reuse provides substantial savings. Benchmarks confirm the reftable backend now consistently outperforms files backend in realistic workloads, validating the optimization approach.
