This is patch 2/16 in a performance optimization series for the refs subsystem, specifically introducing a new flag to skip ambiguity checks in object ID lookups.

The patch adds a `GET_OID_SKIP_AMBIGUITY_CHECK` flag to disable reference ambiguity validation during object ID parsing. Currently, Git checks whether a given hex string could refer to both an object ID and a reference name (like a branch or tag), which adds runtime overhead. The new flag allows callers to bypass this check when they know it's unnecessary, improving performance in specific cases.

The implementation modifies `hash.h` to define the new flag (with octal value 040000) and updates `object-name.c` to respect it in `get_oid_basic()`. The flag joins existing `GET_OID_*` flags that control various aspects of object lookup behavior. The change maintains backward compatibility - when the flag isn't set, the existing ambiguity checking behavior remains unchanged.

This is a foundational change for the larger optimization series, with the commit message noting the flag will be used in subsequent patches. The series as a whole aims to improve refname availability checks across Git's storage backends (files, packed, and reftable), particularly around tombstone reference handling. Patch 2/16 provides a building block for these optimizations by allowing selective bypass of an expensive check when safe to do so.

Key technical details for future reference:
- New flag `GET_OID_SKIP_AMBIGUITY_CHECK` (040000) added to `hash.h`
- Modifies `get_oid_basic()` in `object-name.c` to conditionally skip ambiguity checks
- Maintains existing behavior when flag not set
- Part of broader refs performance optimization work
- Follows pattern from similar optimizations like those in `git-cat-file`
