This is patch 4/12 in Patrick Steinhardt's series to reduce `the_repository` usage, specifically targeting the `core.bigFileThreshold` configuration. The patch moves this global configuration value into `struct repo_settings`, continuing the series' pattern of eliminating implicit repository state.

The change converts the global `big_file_threshold` variable to be stored per-repository, with new accessors `repo_settings_get_big_file_threshold()` and `repo_settings_set_big_file_threshold()`. This affects 15 files that previously accessed the global directly, including archive handling, pack operations, diff machinery, and object streaming. The implementation lazily loads the value from config when first accessed.

A test in t1050-large.sh needed adjustment since it was verifying config parsing behavior for invalid values - the test now uses `git hash-object` instead to ensure the config is actually read. The patch maintains the same default threshold value (512MB) when not configured.

This conversion follows the established pattern from earlier patches in the series, though it touches more call sites than some previous conversions. The change is straightforward but widespread, affecting core object handling paths. Reviewers should pay particular attention to the pack-related changes (pack-objects, index-pack, etc.) where the threshold affects streaming behavior for large blobs.
