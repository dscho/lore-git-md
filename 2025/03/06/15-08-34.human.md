Performance optimization patch in the refs subsystem series, specifically targeting `git-update-ref`'s skipping unnecessary ambiguity checks when parsing object IDs. This is part of a larger effort to optimize refname availability checks across Git's storage backends.

The patch modifies `git-update-ref` to skip expensive ambiguity checks when parsing object IDs, following the precedent set by a similar optimization in `git-cat-file`. The change is justified by three factors: (1) the command's plumbing nature makes ambiguity warnings less useful, (2) its manpage focuses on object IDs rather than refnames, and (3) users should be using fully-qualified refnames anyway when using plumbing commands.

Benchmarks show significant speedups - 1.19x faster for the files backend and 2.32x for reftable when creating 10,000 refs against a repository with 100,000 existing refs. The relative improvement is more pronounced for reftable since its baseline performance is already better. The patch builds on the new `repo_get_oid_with_flags()` API introduced earlier in the series, using the `GET_OID_SKIP_AMBIGUITY_CHECK` flag to bypass the checks.

This appears to be a well-justified optimization that maintains backward compatibility while providing measurable performance benefits, particularly for batch operations. The change is consistent with the series' overall goal of optimizing ref operations across all backends.
