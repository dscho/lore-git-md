This is the first patch in a two-part bugfix series addressing inconsistencies in Git's ref iteration with `--exclude` patterns. The patch specifically fixes incorrect handling of empty `--exclude` patterns that was causing packed refs to be incorrectly filtered out.

The core issue stems from how the packed-refs backend processes exclude patterns by creating "jump lists" to skip unwanted sections. When given an empty pattern, it was incorrectly interpreting this as matching the entire packed-refs file, causing all packed refs to be excluded. The patch modifies `refs.c` to filter out empty patterns before they reach the backend, ensuring empty patterns don't affect output.

The change is well-motivated with clear examples showing the bug's impact (2229 refs vs 480 refs output) and includes a new test case in t1419-exclude-refs.sh. The implementation adds a strvec-based filtering step in refs_ref_iterator_begin() while maintaining the existing exclude functionality for non-empty patterns.

Key technical details:
- Adds pattern normalization in refs.c that filters empty strings
- Preserves all other exclude pattern behavior
- Includes test verifying empty patterns don't affect output
- Sets up infrastructure for follow-up fix in patch 2/2
- Affects core ref iteration path used by commands like for-each-ref

The patch appears well-constructed with proper test coverage and builds on prior work around ref backend optimization (commit 59c35fac54). It addresses a real inconsistency while being careful not to disrupt legitimate exclude pattern functionality.
