This is a performance optimization patch in the refs subsystem, specifically targeting the reftable backend. It's part 5 of a 16-patch series focused on improving refname availability checks across different ref backends.

The patch refactors the reftable backend to batch refname availability checks during transaction preparation, though the actual performance benefits will come in later patches. Currently, it collects all refnames that need verification into a `string_list` and performs a single batched check using the new `refs_verify_refnames_available()` API introduced in patch 4/16, rather than checking each refname individually as before. The changes are mechanical - replacing individual checks with batched collection, sorting the refnames, and performing one consolidated verification before transaction commit.

Key technical details include:
- Introduces a new `refnames_to_check` string_list to accumulate refnames
- Moves the verification to after all refnames are collected
- Maintains the same error handling and cleanup patterns
- Still uses the same underlying verification logic (to be optimized later)
- Preserves all existing behavior flags (like REF_TRANSACTION_FLAG_INITIAL)

The patch is part of a larger effort to optimize ref operations, particularly benefits the reftable backend, and builds on the batched verification infrastructure established in the series. While this specific patch doesn't yet show performance improvements (as noted in the commit message), it's a necessary step enabling the optimizations that follow. The changes are straightforward and maintain existing behavior while setting up for future performance gains.
