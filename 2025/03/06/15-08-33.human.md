Performance optimization series patch adding a flag to skip refname ambiguity checks. This is patch 2/16 in Patrick Steinhardt's series optimizing refname availability checks across Git's ref backends.

The patch introduces a new `GET_OID_SKIP_AMBIGUITY_CHECK` flag that allows callers to bypass the check for ambiguous refnames when looking up object IDs. The check normally warns when a hex object ID could also be a refname, but this adds overhead in cases where the check isn't needed. The change modifies both the flag definitions in hash.h and the lookup logic in object-name.c.

This is a foundational change for the larger optimization series, enabling subsequent patches to skip these checks in performance-critical paths. The commit message notes this will be used by a follow-up commit, though it doesn't specify which one. The change is straightforward and maintains backward compatibility since the check remains enabled by default.

The patch follows cleanly from patch 1/16's API groundwork and enables the batched verification optimizations that come later in the series. Karthik Nayak has already confirmed the series' technical soundness in review, with only minor documentation nits remaining.
