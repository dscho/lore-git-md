Build system patch addressing CMake test object handling. This is the third patch in a series primarily focused on platform compatibility and build system fixes during Git's Meson transition.

The patch generalizes CMake's handling of the `CLAR_TEST_OBJS` list to avoid manual synchronization with the Makefile, mirroring a similar change made for `UNIT_TEST_OBJS` in September 8afda42fce60. The immediate motivation is a build failure in the `win+VS build` job caused by the `sk/unit-test-oid` series adding new test objects that weren't properly reflected in CMake's hardcoded list. The error manifested as unresolved external symbol errors during linking.

Key technical changes:
- Introduces `parse_makefile_for_sources()` for `CLAR_TEST_OBJS` similar to existing `UNIT_TEST_OBJS` handling
- Creates a new `clar-test-lib` static library target
- Restructures test executable linking to use both unit-test and clar-test libraries
- Moves clar.c from unit-tests-lib to clar-test-lib
- Updates include directories accordingly

The change follows the same pattern as the earlier `UNIT_TEST_OBJS` generalization, suggesting this is part of an ongoing effort to make CMake's test infrastructure more maintainable by reducing duplication with the Makefile. The patch appears straightforward with no obvious technical concerns, though it would benefit from verification that all test cases still build and run correctly in both Windows and non-Windows environments.
