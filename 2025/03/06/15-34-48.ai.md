This is a bugfix patch in a series addressing ref iteration behavior with `--exclude` patterns. It specifically handles the edge case of empty string patterns being passed to ref iteration commands like `for-each-ref`.

The patch fixes an inconsistency where empty `--exclude` patterns were causing the packed-refs backend to skip all packed references, even though an empty pattern shouldn't match any refs. The issue stems from how jump lists optimization in the packed backend was interpreting empty patterns as matching everything. The fix filters out empty patterns at the refs.c level before they reach any backend, ensuring consistent behavior across all ref storage types (files, packed, reftable).

Key technical details:
- Adds pattern filtering in `refs_ref_iterator_begin()` that skips empty strings
- Uses a temporary `strvec` to store non-empty patterns
- Includes test case verifying empty patterns don't affect output
- Maintains existing jump list optimizations for non-empty patterns
- Follows up on prior work (59c35fac54) that introduced packed-refs jump lists

The patch is well-constructed with clear commit message explaining the problem and solution, and includes a test case demonstrating the fixed behavior. It's the first in a two-patch series that has already received positive review feedback and appears ready for merging.
