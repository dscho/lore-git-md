This is the second patch in a bugfix series addressing inconsistencies in Git's ref exclusion patterns across different backends. The patch tightens the rules for how `--exclude` patterns match refnames, requiring them to either be exact matches or proper directory boundaries (ending with a slash).

The core issue is that the packed-refs backend was too lenient in matching exclusion patterns - a pattern like "refs/heads/ba" would exclude "refs/heads/bar" and "refs/heads/baz", while the files backend (which doesn't implement exclusions itself) would show these refs. This led to inconsistent behavior in commands like `for-each-ref` and `upload-pack` depending on whether refs were packed or loose.

The fix normalizes all exclusion patterns to end with a trailing slash in the common refs.c entry point, ensuring consistent behavior across all backends (files, packed, and reftable). This is a behavior change - patterns without slashes will no longer match partial refnames - but the commit argues this is the correct behavior that should have been implemented originally.

The patch includes test updates to verify the new behavior, splitting an existing test that was actually testing the buggy behavior into two separate tests - one for non-directory exclusions and one for proper hierarchical exclusions. The changes are minimal (just 6 lines in refs.c) but have wide impact across all ref backends.
