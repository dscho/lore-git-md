This is a refactoring patch in Karthik Nayak's series implementing partial reference transactions. The patch moves duplicate refname checking from individual ref backends into the generic layer in `refs.c`, centralizing what was previously handled separately by each backend.

The key change adds a `refnames` string_list field to the `ref_transaction` struct to track all references in a transaction. This eliminates 146 lines of duplicate code across backends. Junio Hamano approves the change, noting the transaction object is the logical place for this tracking. He also raises an interesting point about potentially moving symref handling (like HEAD updates) to the generic layer in the future - Karthik acknowledges this would be a good future direction but isn't addressed in this series.

The reftable backend is adjusted to perform its duplicate check before rather than after adding updates, since the new centralized tracking would make post-addition checks always return true. The change maintains safety while simplifying the code, with Junio confirming the approach makes sense after reviewing the context.

This patch represents a clean-up and consolidation step in the larger effort to support partial reference transactions. It doesn't introduce new functionality but makes the codebase more maintainable by reducing duplication and centralizing logic. The changes are well-considered and have received positive feedback from the maintainer.
