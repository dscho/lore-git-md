Bugfix for `--exclude` pattern handling in ref iteration. This is the first patch in a two-part series addressing inconsistencies in how Git handles empty patterns when excluding refs.

The patch fixes a surprising behavior where `--exclude=''` (an empty pattern) would incorrectly filter out all packed refs while keeping loose refs. The root cause is that the packed backend treats an empty pattern as matching everything, while the empty string doesn't actually match any refs. The fix filters out empty patterns at the refs.c layer before they reach the backend implementations.

The change is well-motivated with clear before/after examples showing the bug's impact (2229 refs normally vs 480 with `--exclude=''`). The patch includes a new test case verifying the fixed behavior and maintains performance by avoiding unnecessary pattern processing. This appears to be a solid fix for an edge case that could confuse users, though it's worth noting the files backend still doesn't implement the full jump list optimization that the packed backend does.
