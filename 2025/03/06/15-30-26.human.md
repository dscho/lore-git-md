This is a test case addition that exposes a bug in the merge-ort directory rename detection logic. The patch adds a scenario where a file gets transitively renamed back to its original location, triggering an assertion failure in `process_renames()`.

The test demonstrates a specific edge case: when one branch renames a directory (A/ → B/) while another branch adds new files to A/, and those new files originally came from B/. This creates a situation where directory rename detection would try to rename a file back to itself, causing merge-ort to crash with an assertion failure.

The test is carefully placed in t6423 alongside similar directory rename tests, following the existing style. It's marked as `test_expect_failure` since it documents a known bug rather than fixing it. The commit message clearly describes the triggering condition and includes the exact assertion failure message for debugging purposes.
