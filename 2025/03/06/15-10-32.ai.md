This is patch 8/12 in Patrick Steinhardt's series to remove `the_repository` usage from object APIs, focusing on `object-file-convert.c`. The patch eliminates implicit repository dependencies in object file conversion functions, which handle hash algorithm translations for commits, trees, and tags.

The key change adds a `struct repository*` parameter to `convert_object_file()` and propagates it through all internal conversion functions (`convert_tree_object`, `convert_tag_object`, `convert_commit_object`). This removes the need for these functions to access `the_repository` or `the_hash_algo` globals. The patch updates all callers (in builtin/tag.c, commit.c, and object-file.c) to pass `the_repository` explicitly where needed.

Technical changes include:
- Removing the `USE_THE_REPOSITORY_VARIABLE` define from object-file-convert.c
- Modifying the function signature in object-file-convert.h to include the repository parameter
- Updating all internal object conversion functions to take and use the repository parameter
- Adjusting call sites to pass the repository context through

The conversion maintains existing behavior while making the repository dependency explicit. This continues the series' pattern of methodically removing global state from object handling code, with particular attention to hash algorithm conversions. The changes are straightforward mechanical conversions following the established pattern from earlier patches in the series.
