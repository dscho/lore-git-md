This is a bugfix patch addressing inconsistent behavior with empty `--exclude` patterns in Git's ref iteration. It's the first of two patches in a v2 series that has already received positive feedback and is ready for merging.

The patch fixes a counterintuitive case where `--exclude=''` (an empty pattern) was incorrectly filtering out all packed refs while leaving loose refs untouched. The empty pattern shouldn't match any refs at all, so the command should behave identically to running without any exclusion. The fix filters out empty patterns at the refs.c level before they reach the packed or reftable backends, ensuring consistent behavior across all ref storage types.

The change is well-motivated with clear before/after examples showing the bug's impact (2229 refs normally vs 480 with the empty exclude pattern). The implementation adds a strvec filter in `refs_ref_iterator_begin()` to skip empty patterns, with a new test case verifying the corrected behavior. The commit message also notes this change sets up for a related fix in the next patch regarding prefix matching.

This appears to be a solid, focused fix with good test coverage. Since it's part of an already-reviewed series that addresses ref backend consistency, it's likely to be merged soon.
