This is a bugfix for the merge-ort backend addressing a crash during complex directory rename scenarios. Elijah Newren (the merge machinery maintainer) is following up on Dmitry Goncharov's reported issue where cherry-picks involving conflicting directory moves would trigger an assertion failure. 

The fix comes as a two-patch series: the first incorporates Goncharov's test case into the existing merge test suite (t6423), while the second implements Newren's solution. Unlike Goncharov's initial approach that tried to ignore self-move renames, Newren's fix properly handles the directory rename conflict case that was crashing merge-ort, ensuring users see appropriate conflict messages rather than an abort.

Notably, this only addresses the ort backend's behavior - the recursive backend's incorrect handling of this case remains unchanged since that backend is slated for removal anyway. The changes touch core rename processing logic in merge-ort.c, with Newren's involvement signaling this will be a robust solution. The patches are now available via GitGitGadget for review.
