This is patch 4/12 in Patrick Steinhardt's series to remove `the_repository` global variable usage from object-related APIs. The patch moves the "core.bigFileThreshold" configuration from a global variable to `struct repo_settings`, continuing the series' systematic elimination of implicit repository state.

The change addresses two key issues: potential incorrect behavior when working with multiple repositories that have different big-file thresholds, and the broader goal of making Git more library-friendly by removing global state. The implementation adds new getter/setter functions in repo-settings.[ch] and updates all 15 call sites that previously accessed the global variable directly.

A test in t1050 had to be modified since the original test command didn't actually exercise the big-file threshold code path - it now uses `git hash-object` which does read the setting. The patch follows the established pattern from earlier conversions in the series, with mechanical but widespread changes across multiple subsystems that handle large files (archive, diff, pack operations, etc.).

This is part of the ongoing foundational work to enable pluggable object databases and improve Git's internal architecture. The change is straightforward and maintains existing behavior while making it properly repository-specific.
