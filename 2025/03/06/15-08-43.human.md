Performance optimization for reftable backend in the refs subsystem series. This is patch 12/16 in v5 of Patrick Steinhardt's series addressing refname availability checks.

The patch implements seeking capability for reftable reference iterators, building on the iterator reseek foundation established in earlier patches. The implementation is straightforward since the low-level reftable iterators already support seeking. Two notable design decisions are made: reflog iterators explicitly don't support seeking (as there's no clear use case yet), and the patch adds error checking for `reftable_stack_init_ref_iterator()` that was previously missing.

The changes involve adding a seek operation to the iterator vtable, properly handling prefix strings (now allocated dynamically), and ensuring proper cleanup. The reflog iterator explicitly BUGs out if seek is attempted, making the limitation clear. This is a technical piece of the larger performance optimization series that's already received positive reviews, with only minor documentation nits remaining.
