Performance optimization in the refs subsystem, part of a series addressing refname availability checks. This patch (8/16) eliminates redundant verification of common refname prefixes during batched reference updates by introducing a `strset` to track already-checked prefixes.

The change provides significant speedups, particularly for the reftable backend where creating 10,000 refs against 100,000 existing refs shows a 1.58x improvement (63.1ms → 40.0ms). The files backend sees a more modest 1.03x gain. Migration operations between backends also benefit, with 1.09-1.10x speedups when moving 1 million refs.

The implementation adds a `strset dirnames` to `refs_verify_refnames_available()`, skipping re-verification of previously seen directory prefixes like "refs/heads/". This avoids redundant checks while maintaining all existing validation logic. The patch follows the series' pattern of optimizing batched operations, building on earlier infrastructure changes while preparing for subsequent iterator improvements. Benchmarks confirm the reftable backend now consistently outperforms the files backend in these scenarios.
