Bugfix for merge-ort's handling of directory renames that cause files to be renamed back to themselves.

This patch fixes an overly strict assertion in merge-ort's rename processing logic. The assertion assumed that a renamed file would always end up at a different path than where it started, which is generally true except in the special case of directory rename detection. When directory renames cause a file to be renamed back to its original path (through transitive directory rename operations), the assertion would incorrectly trigger.

The fix is straightforward - the assertion is modified to also allow cases where the source and destination paths are identical. The patch includes a test case that was previously marked as failing but now passes, demonstrating the scenario where a file is transitively renamed back to itself through directory renames. The change is minimal (just adding one condition to the assertion) but important for handling this edge case correctly.

The rest of the rename processing code already handled this case properly; this was purely about relaxing an overly strict sanity check. The patch comes from Elijah Newren, the primary author of merge-ort, suggesting it's a well-considered fix for a subtle edge case in the merge machinery.
