Performance optimization patch implementing iterator functionality for the files backend, completing the series' iterator reseek capability across all ref backends.

This patch adds seek support to the files backend's ref iterator by implementing the `seek` vtable function. The implementation is straightforward since it delegates to the underlying ref-cache iterator (`iter0`). Like with the reftable backend, reflog iterators explicitly do not support seeking (triggering a BUG if attempted), maintaining consistency across backends.

The changes are minimal and focused:
1. Adds `files_ref_iterator_seek()` that forwards to the wrapped ref-cache iterator
2. Updates the iterator vtable to include the new seek operation
3. Explicitly prohibits seeking on reflog iterators via `files_reflog_iterator_seek()`

This completes the iterator reseek functionality for all three backend types (reftable, packed-refs, and now files) in the performance optimization series. The implementation follows the established pattern seen in previous patches while respecting backend-specific constraints - in this case leveraging the existing ref-cache iterator infrastructure rather than requiring new low-level seeking logic. The patch maintains the series' architectural consistency while handling the files backend's particular structure where ref iteration is built atop the ref-cache layer.
