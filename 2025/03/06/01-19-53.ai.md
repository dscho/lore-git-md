This is the second patch in a bugfix series addressing inconsistencies in Git's ref iteration `--exclude` behavior across different backends. The patch specifically unifies how the files, packed, and reftable backends handle exclude patterns by ensuring they all treat patterns without trailing slashes as exact matches rather than prefix matches.

The core issue stems from a behavioral difference where the packed backend would incorrectly consider "refs/heads/ba" as matching references like "refs/heads/bar", while the files backend would not. The fix normalizes all exclude patterns by adding a trailing slash if one isn't present, making the behavior consistent across all backends. This change affects the common entry point in `refs_ref_iterator_begin()` rather than modifying each backend individually.

The patch includes test updates to reflect the corrected behavior, acknowledging that some existing tests were actually verifying the buggy behavior. The solution builds on prior ref backend work and was prompted by a user report. Jeff King provided assistance in developing the fix.

This change has implications for commands using ref iteration with exclude patterns (like `for-each-ref` and `upload-pack`), potentially affecting reference visibility in edge cases. The fix is technically a behavior change but corrects what was clearly unintended functionality, as evidenced by the test updates and cross-backend inconsistency.
