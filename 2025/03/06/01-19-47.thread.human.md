This thread addresses inconsistencies in how Git handles `--exclude` patterns during ref iteration across different backends. The two-patch series fixes two distinct issues: first, incorrect handling of empty exclude patterns, and second, inconsistent matching behavior between backends when patterns lack trailing slashes.

The first patch ensures empty patterns are properly filtered out before reaching any backend, while the second (just posted) normalizes pattern matching by making all backends treat patterns without trailing slashes as exact matches. This fixes cases where the packed backend would incorrectly match "refs/heads/ba" against "refs/heads/bar" while the files backend wouldn't. The changes centralize the pattern handling in `refs_ref_iterator_begin()` rather than modifying each backend individually.

Jeff King helped develop the solution, which affects commands like `for-each-ref` and `upload-pack`. The patches include test updates that reveal some existing tests were actually verifying the buggy behavior. While technically a behavior change, this corrects clearly unintended functionality and brings consistency across the files, packed, and reftable backends. The series builds on prior ref backend optimization work and awaits broader review from the community.
