Performance optimization series patch (02/16) introducing a skip-ambiguity-check flag for OID lookups.

This patch from Patrick Steinhardt (with a minor style nit from Karthik Nayak) adds a new `GET_OID_SKIP_AMBIGUITY_CHECK` flag to bypass reference ambiguity validation during object ID lookups. The change is part of a larger 16-patch series optimizing refname availability checks across Git's storage backends.

The modification allows callers to skip the warning when an object ID string matches both a refname and a hex object ID, which can provide performance benefits in cases where this check is unnecessary overhead. The implementation maintains all existing behavior by default, only skipping the check when explicitly requested via the new flag.

This foundational change enables subsequent optimizations in the series, particularly around batched refname verification. The patch itself is straightforward - adding one flag definition and modifying a single conditional check in `get_oid_basic()`. Karthik notes a minor style inconsistency in the flag alignment that doesn't affect functionality.

As part of the performance optimization series, this change shows careful attention to maintaining backward compatibility while providing new optimization pathways. The series as a whole has already demonstrated significant speedups (1.19-7.56x depending on backend) in testing.
