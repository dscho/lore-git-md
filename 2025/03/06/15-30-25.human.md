This is a bugfix patch series addressing a crash in merge-ort when handling a specific type of rename conflict. The issue was originally reported by Dmitry Goncharov, who provided a test case demonstrating the problem where both merge-ort and merge-recursive fail to properly handle a file that gets transitively renamed to itself during a merge.

The series consists of two patches: first, Dmitry's test case that triggers the assertion failure in `process_renames()`, followed by Elijah Newren's fix that adjusts an overzealous assertion in merge-ort.c. The maintainer notes this isn't a recent regression and doesn't need to be rushed into v2.49.0.

The fix appears well-contained, touching just 3 lines in merge-ort.c while adding a thorough 41-line test case. The problem description references prior discussion, and the solution comes from one of Git's most experienced merge strategy developers. This looks like a solid fix for a corner case that could cause crashes during complex rename scenarios.
