Performance optimization in the refs subsystem, part of a larger series to improve refname availability checks. This patch (8/16) eliminates redundant verification of common refname prefixes during batch operations.

The change introduces a `strset` to track already-checked refname prefixes (like "refs/heads/"), avoiding repeated verification of the same paths. This provides significant speedup for the reftable backend (1.58x faster when creating 10,000 refs) and modest gains for the files backend (1.03x). It also improves reference migration between backends by about 10%.

The implementation is straightforward - adding a string set to cache checked prefixes while maintaining all existing validation logic. Benchmarks show the optimization is most impactful when dealing with many refs sharing common prefixes, particularly with reftable where the overhead was more pronounced. This builds on earlier patches in the series that introduced batched refname verification.
