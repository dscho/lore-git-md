Bugfix for reftable error handling, part of GSoC work.

This patch improves error reporting in the reftable subsystem by replacing generic -1 return codes with specific error codes from the REFTABLE_*_ERROR family. The main change is in block_writer_add() and related functions, where several cases that previously returned -1 now return REFTABLE_ENTRY_TOO_BIG_ERROR when an entry exceeds block size limits. The changes affect three files: block.c (core block writing logic), record.c (key encoding), and writer.c (high-level writer interface).

The patch appears well-scoped and correctly implemented, with consistent error code usage across the call chain. The commit message clearly explains the motivation (avoiding assumptions about error types) and the TODO comment removal in writer.c shows this addresses a known limitation. The changes are mechanical but meaningful for debugging and error handling robustness in the reftable backend.

Key technical details for future reference: the patch standardizes on REFTABLE_ENTRY_TOO_BIG_ERROR for size-related failures, modifies error propagation in reftable_record_key() and reftable_record_encode(), and removes a now-unnecessary error code conversion in writer_add_record(). The changes maintain backward compatibility since callers already handle negative error codes.
