This is a bugfix patch for the reftable backend, part of a GSoC (Google Summer of Code) contribution. The patch improves error handling by replacing generic -1 return codes with specific error codes in several reftable functions, particularly in `block_writer_add()` and related functions.

The change makes error handling more precise by using the existing `REFTABLE_ENTRY_TOO_BIG_ERROR` and `REFTABLE_API_ERROR` codes where appropriate, rather than returning -1. This helps callers better understand what went wrong when operations fail. The patch also removes some now-unnecessary error code guessing in `writer_add_record()` since the underlying functions now return proper error codes directly.

The changes are focused and well-contained, touching only three files in the reftable implementation. The commit message clearly explains the motivation (avoiding assumptions about error types) and the solution. This appears to be a straightforward quality-of-life improvement for the reftable codebase.
