Feature addition extending `--no-optional-locks` to `git describe`.

This first patch in a 2-part series adds `--no-optional-locks` support to `git describe --dirty`, following the same pattern established for `git status`. The change prevents background index updates that could cause lockfile conflicts in scripting scenarios where multiple Git operations run concurrently. 

The implementation wraps the index update logic in a `use_optional_locks()` check, matching the behavior of `git status`. Documentation updates explain the background refresh behavior and recommend the new option for script usage. A new test case verifies the option prevents index from being updated, using the same magic mtime technique seen in other lock-related tests.

Key technical details:
- Modifies `builtin/describe.c` to conditionally skip index updates
- Updates both `git-describe` and main `git` manpages
- Adds test in `t6120-describe.sh` using `test_is_magic_mtime`
- Follows existing patterns from `git status` implementation

The change is well-scoped and maintains consistency with Git's existing locking behavior. The test coverage appears thorough for the new functionality. This addresses a real pain point in automated environments while maintaining backward compatibility.
