This thread explores adding a `--no-optional-locks` option to porcelain commands like `git describe` and `git diff` to address lock contention in scripting scenarios, while maintaining Git's core design principles. The initial patch series (v1) implements the feature following the pattern established by `git status --no-optional-locks`, modifying both commands to make index updates optional when requested.

Junio Hamano provided crucial context about Git's porcelain/plumbing distinction, emphasizing that porcelain commands refresh indexes for correctness (not just performance) and that making refreshes optional should remain an exception rather than the default. Jeff King (peff) expanded on this discussion, explaining how `git status` currently handles optional locks (updating internally without writing) and why he had previously considered `git diff` for this feature. He outlined the practical tradeoffs script authors face when avoiding porcelain commands - either accepting potentially incorrect results from plumbing, using secondary index files with overhead, or using in-memory updates.

The technical implementation includes changes to `builtin/describe.c` and `builtin/diff.c`, documentation updates, and new tests in `t4070-diff-auto-refresh-index.sh` and `t6120-describe.sh`. While the patches address real-world lock contention issues, the discussion continues to weigh Git's design philosophy against practical scripting needs, particularly around when porcelain commands should make exceptions to their normal behavior. The thread remains focused on finding the right balance, with Junio's position suggesting the feature may proceed if clearly documented as a special case.
