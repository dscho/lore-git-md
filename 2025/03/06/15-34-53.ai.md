Ref backend bugfix addressing inconsistent `--exclude` pattern matching behavior. This is the second patch in a v2 series that has already incorporated review feedback and is ready for merging.

The patch fixes a subtle inconsistency in how ref backends handle `--exclude` patterns, where the packed and reftable backends would incorrectly match partial prefixes (like `refs/heads/ba` excluding `refs/heads/bar`), while the files backend would not. The solution normalizes all exclude patterns to require trailing slashes for directory boundaries, implemented at the common `refs_ref_iterator_begin()` entry point to cover all backends.

Key technical changes:
- Modified `refs.c` to append trailing slashes to exclude patterns that don't already have them
- Split and reorganized test cases in `t1419-exclude-refs.sh` to:
  - Separate non-directory exclusion cases (now properly failing to match partial prefixes)
  - Add new test for true hierarchical exclusion scenarios
- Preserves the packed-refs jump list optimization from commit 59c35fac54
- Maintains performance characteristics (asserted via jump count checks)

The patch builds on prior ref backend work and has been reviewed by Patrick Steinhardt, with test organization improvements suggested by Taylor Blau. It addresses a bug report from SURA and includes help from Jeff King during development. The v2 iteration has addressed all feedback and is considered ready for integration.
