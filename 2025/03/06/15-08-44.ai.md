This is patch 13/16 in a performance optimization series for the refs subsystem, implementing iterator seeking capability for the ref-cache backend. The patch builds on previous iterator improvements by adding a dedicated `seek` method to the ref-cache iterator vtable, splitting out seeking logic from the initialization code.

Key technical changes include:
- Moves seeking logic from `cache_ref_iterator_begin()` into new `cache_ref_iterator_seek()`
- Makes the iterator's `prefix` field heap-allocated to support reseeking
- Adds proper cleanup of the prefix in `reftable_ref_iterator_release`
- Removes the optimization of returning an empty iterator when no refs exist, since this prevents reseeking to different prefixes
- Maintains the same prefix matching behavior (textual matching without path component boundaries)
- Adds early bailout in `advance()` when no more directories remain to search

The change is localized to `refs/ref-cache.c` and follows the pattern established in earlier patches for iterator improvements. This completes the ref-cache portion of the iterator reseek capability, complementing the reftable iterator changes from patch 12/16. The implementation shows careful consideration of edge cases like empty directories while maintaining the series' focus on performance optimization through reduced redundant operations.
