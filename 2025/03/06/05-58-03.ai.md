This is a feature patch series introducing `--no-optional-locks` support for `git describe` and `git diff`. The changes address a specific use case where background index updates by these commands can cause lockfile conflicts in scripting scenarios.

The cover letter explains the motivation clearly: the author's build system encountered sporadic stale lockfile issues when using `git describe`, currently mitigated by switching to libgit2. The patches would allow staying with the Git CLI while avoiding the lock contention. The implementation follows the pattern established by other commands that perform background index operations.

Key technical details for future reference:
- Adds `--no-optional-locks` option to both commands' documentation and implementations
- New test file `t4070-diff-auto-refresh-index.sh` verifies the diff behavior
- Existing describe tests extended in `t6120-describe.sh`
- Touches core command manpages and the general `git` manpage's OPTIONS section
- Follows the same pattern as `git status`'s existing `--no-optional-locks`

The changes appear well-scoped and motivated, with thorough test coverage. The implementation approach is conservative, matching existing conventions rather than introducing new paradigms. The lockfile contention scenario described seems plausible for automated build environments where multiple Git operations might run concurrently.
