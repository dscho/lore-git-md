Performance optimization patch introducing iterator reseek capability for ref backends, part of a larger series improving refname availability checks. This patch (10/16 in v5) adds infrastructure to allow reusing ref iterators by seeking them to new prefixes, rather than discarding and creating new iterators. The change enables potential backend optimizations by preserving internal state between seeks.

The core addition is a new `.seek` vtable function that mimics creating a new iterator with a different prefix while allowing reuse of existing iterator state. The implementation currently supports only prefix changes, keeping other parameters (exclude patterns, flags) constant. The patch provides implementations for debug and empty iterators, with other backend implementations to follow in subsequent patches.

Key technical details:
- Adds `ref_iterator_seek()` API function and corresponding vtable entry
- Implements seek for debug wrapper iterator (passing through to underlying iterator)
- Implements seek for empty iterator (no-op)
- Updates `refs-internal.h` documentation with new seek semantics
- Preserves existing behavior where prefix is NULL or empty string (resets to first ref)

This builds on the iterator lifecycle refactoring from patch 9/16 and enables the iterator reuse optimizations that will be implemented in later patches of the series. The change is particularly relevant for reftable backend which already has internal reuse capabilities that can now be exposed. The implementation maintains the same behavior as creating fresh iterators while opening the door for backend-specific optimizations.
