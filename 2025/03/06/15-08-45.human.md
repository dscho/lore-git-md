This is patch 14/16 in Patrick Steinhardt's performance optimization series for the refs subsystem, focusing on implementing iterator seeking for the packed-refs backend. The patch follows the same pattern as previous iterator optimizations in the series, completing the implementation across all major ref backends.

The change modifies the packed-ref iterator to support reseeking by:
1. Adding a heap-allocated `prefix` field to store the current search prefix
2. Moving prefix matching logic directly into `advance()` rather than using a separate prefix iterator
3. Implementing a new `packed_ref_iterator_seek()` function to reposition the iterator
4. Removing the empty iterator optimization to maintain consistency with other backends' reseek behavior

The implementation maintains the same performance characteristics as the original while enabling the iterator to be reused with different prefixes - a key optimization for batched ref operations. As with previous patches in the series, this change is localized to the packed-backend implementation and doesn't affect the public refs API.

This completes the iterator optimization work across all three major ref backends (files, reftable, and now packed), bringing consistent reseek capabilities to the entire refs subsystem. The patch follows the established pattern seen in earlier patches while accounting for packed-refs' specific characteristics, particularly its sorted nature which allows efficient seeking via binary search.
