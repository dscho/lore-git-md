This is a clarification response in the `--no-optional-locks` thread, correcting the motivation for index refreshes in Git commands. Junio C Hamano points out that the original justification ("performance reasons") was incorrect - porcelain commands like `git diff` and `git describe` refresh the index for correctness, while plumbing commands omit refreshes for performance when used in scripts. The key distinction is that porcelain commands must maintain correctness by default, while scripts using plumbing commands are responsible for their own index management.

The response strongly asserts that making index refreshes optional in porcelain commands would be unacceptable as a default behavior, though might be conditionally acceptable as an opt-in feature if no better solutions exist (like using plumbing commands in scripts). This clarifies the fundamental design principle behind Git's command categorization while leaving room for the proposed `--no-optional-locks` feature as a potentially useful exception for scripting scenarios.
