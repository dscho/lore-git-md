This is a test infrastructure patch that extends the `test_lazy_prereq` mechanism as part of the ongoing breaking changes infrastructure work. The patch introduces a way to mark deprecated test prerequisites that should no longer be used, following the pattern established in the thread for handling breaking changes.

The change adds special handling for exit code 125 from lazy prerequisite scripts, which now signals a programming error when a deprecated prerequisite is used. This matches the behavior of git-bisect scripts. The implementation updates both the documentation in t/README (clarifying the different exit code meanings) and the test-lib-functions.sh code (adding the 125 case handling and triggering an error when such prerequisites are used).

Key technical details include:
- New BUG() invocation when a deprecated prerequisite (exiting with 125) is encountered
- Documentation of the three possible exit code outcomes (0 for success, non-125 for unsatisfied, 125 for deprecated)
- Integration with the existing lazy prerequisite evaluation system

This builds on the thread's earlier work around the `WITH_BREAKING_CHANGES` prerequisite by providing a cleaner way to phase out deprecated test requirements. The change is focused on test infrastructure rather than any specific feature deprecation, though it will be used in subsequent patches to handle the `WITHOUT_BREAKING_CHANGES` prerequisite removal.
