This is a follow-up discussion on the breaking changes` infrastructure series, specifically about the removal of the deprecated `--stdin` option from `git name-rev`. Patrick Steinhardt suggests going further with the cleanup by also conditionally compiling the `transform_stdin` variable and its single usage site, rather than just the option definition. This would more accurately reflect the eventual state after full removal of the feature.

The suggestion comes in response to Junio Hamano's patch that already guards the `--stdin` option definition with `#ifndef WITH_BREAKING_CHANGES`. Patrick's proposal would extend this to the supporting variable infrastructure, making the codebase more representative of the post-removal state when `WITH_BREAKING_CHANGES` is enabled. This continues the thread's theme of establishing clean patterns for handling deprecated functionality removal.

The discussion focuses on implementation details of the breaking changes` mechanism in `builtin/name-rev.c`, specifically around how completely to isolate the deprecated `--stdin` functionality. This is part of the larger effort to prepare for Git 3.0 compatibility by properly deprecating and removing old features, with test infrastructure already updated in earlier patches to handle both legacy and new behavior paths.
