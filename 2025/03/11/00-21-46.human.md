This is a performance optimization patch in the ongoing cruft pack series, addressing how pack size limits are handled for cruft packs. 

Taylor Blau modifies `git pack-objects` to allow cruft packs to slightly exceed their specified size limit (by at most one object) when using `--max-pack-size` with `--cruft`. The current behavior strictly enforces the size limit, which can cause inefficient repeated repacking of the same objects. The change lets cruft packs grow just beyond the threshold, reducing future repacking work until a pruning GC occurs.

The patch includes thorough documentation updates in both the config and command manuals explaining this special case for cruft packs. The implementation adds a size check before writing each object and adjusts the limit enforcement logic in `builtin/pack-objects.c`. A new test case verifies the behavior by creating packs with predictable sizes and checking they properly exceed the threshold while containing all expected objects.

This builds on the thread's established consensus about cruft pack freshening and continues the systematic test improvements seen in earlier patches. The change addresses a practical issue Patrick Steinhardt identified with perpetual repacking, though the solution takes a slightly different approach than strict size enforcement. The patch maintains the series' high quality with clear code, good documentation, and comprehensive testing.
