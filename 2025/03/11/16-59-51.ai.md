This is a follow-up discussion in the promisor-remote NULL pointer dereference bugfix thread, where Junio Hamano provides feedback on Christian Couder's v2 patch. The conversation has moved beyond the immediate technical fix to consider broader design philosophy around error handling.

Junio agrees with Christian's approach to focus narrowly on fixing the promisor-remote crash by converting NULL URLs to empty strings, while deferring larger questions about strvec API design. He emphasizes that the root issue is really about configuration validation - a remote without a URL is fundamentally misconfigured, and the discussion about NULL vs empty string is secondary to that core problem.

The exchange confirms consensus on the patch's direction while clarifying the philosophical stance: configuration errors should be caught and reported rather than silently tolerated. Junio endorses Christian's addition of warnings for missing URLs in both client and server configurations, noting this aligns with existing behavior when URLs mismatch.

The thread shows the patch is now considered complete for the immediate bugfix, with all parties agreeing to separate the strvec/xstrdup API design questions for future consideration. This maintains the project's principle of addressing urgent fixes promptly while deferring architectural changes that require more discussion.
