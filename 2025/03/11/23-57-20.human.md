This is a discussion about edge cases in the NUL-delimited output format for `git rev-list`. Jeff King raises two compatibility concerns about the proposed `-z` option:

1. The behavior of `--stdin` with `-z` - whether it should affect input parsing (like most other Git commands) or just output formatting. This is a design gap that should be settled now before the interface becomes set in stone.

2. The fact that `rev-list` already accepts `-z` (inherited from diff options) but doesn't currently do anything meaningful with it. He suggests either fully adopting the diff option's handling (using `revs.diffopt.line_termination`) or cleanly overriding it, but notes the current patch series appears to bypass the diff machinery entirely.

These are practical interface design questions that need resolution before finalizing the feature. While not blocking the core functionality, they touch on Git's consistency and backward compatibility - important considerations for a new output format that may see long-term use. The thread has otherwise reached consensus on the main design, making this a good time to address these edge cases.
