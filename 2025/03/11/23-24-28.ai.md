This is a follow-up discussion in the ongoing feature series adding NUL-delimited output to `git rev-list`. The thread has already established consensus on using a key-value attribute format with single NUL delimiters.

Justin Tobler responds to Junio Hamano's suggestion about handling boundary objects in the new output scheme. He confirms that boundary markers can be naturally incorporated into the unified format as `boundary=yes` attributes, similar to how missing objects are already handled. The implementation would modify `show_commit()` to emit these markers when the `--boundary` option is used with `-z`.

This email solidifies the design by showing how edge cases like boundary commits fit into the key-value format, maintaining consistency across all `rev-list` output modes. The technical approach follows the same pattern established for other special cases in the series, suggesting straightforward implementation in the upcoming v2 patches.
