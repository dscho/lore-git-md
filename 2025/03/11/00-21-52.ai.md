This is the final patch in Taylor Blau's v4 series optimizing cruft pack behavior, focusing on object freshening when multiple cruft packs exist. The patch addresses a limitation where objects in large cruft packs (exceeding the size threshold) couldn't be freshened during repacks, as they were being skipped entirely.

The key changes introduce:
1. A new `ignore_packed_keep_in_core_has_cruft` flag to track when retained cruft packs exist
2. A `want_cruft_object_mtime()` helper to compare mtimes of existing cruft objects against new freshening candidates
3. Modified `want_found_object()` logic that now considers mtimes when deciding whether to pack freshened objects
4. Expanded test coverage in `t7704-repack-cruft.sh` verifying the new freshening behavior

The solution allows freshening objects from retained cruft packs by packing new copies when their mtimes are older than the freshening candidate. This maintains the size threshold behavior while fixing the freshening limitation, though it may result in some duplicate objects temporarily. The implementation builds carefully on the thread's established consensus around object freshening and test infrastructure.
