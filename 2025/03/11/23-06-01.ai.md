Bugfix follow-up discussion regarding promisor-remote URL handling.

Jeff King responds to Christian Couder's v2 patch that fixed a NULL pointer dereference in promisor-remote when URLs are missing from configuration. While agreeing with the general approach, Peff points out that in regular Git remotes, a missing URL defaults to the remote's name (e.g., a remote "foo" with no URL would use "foo" as the URL). He suggests an alternative patch that would make promisor-remote behave similarly by using the remote name when no URL is configured.

The discussion touches on several technical points:
1. The current behavior of `strvec_push()` with NULL values and whether this should be changed at the API level
2. The existence of `xstrdup_or_null()` as an alternative to `xstrdup()`
3. Potential simplification using `git_config_get_string_tmp()` to avoid separate memory management

Peff acknowledges this is a minor edge case and agrees with Christian's approach to focus on fixing the immediate issue in promisor-remote.c rather than broader API changes. The exchange maintains the patch's core safety improvements while exploring alternative implementations that might better match Git's conventional remote URL handling.

Key technical details mentioned:
- Current patch uses empty string as fallback for missing URLs
- Alternative proposal would use remote name as fallback
- `git_config_get_string_tmp()` could simplify memory management
- Discussion of `strvec` API design remains deferred from earlier thread consensus

This continues the thread's pattern of addressing the immediate crash while keeping broader API discussions separate. The exchange suggests potential refinements to the implementation without challenging the fundamental approach or test coverage established in previous iterations.
