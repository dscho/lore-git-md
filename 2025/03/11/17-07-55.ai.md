Maintainer follow-up on breaking changes infrastructure. This email from Junio Hamano responds to Patrick Steinhardt's suggestion about more comprehensive conditional compilation for the deprecated `--stdin` option in `git name-rev`. The thread has been discussing infrastructure for handling breaking changes, particularly around removing the deprecated `--stdin` option in favor of `--annotate-stdin`.

Junio agrees with Patrick's proposal to also wrap the `transform_stdin` variable and its usage site in `builtin/name-rev.c` with `#ifndef WITH_BREAKING_CHANGES` guards, rather than just guarding the option definition as shown in the initial patch. This would more completely isolate the deprecated functionality, making the eventual removal cleaner.

This brief exchange shows the maintainer validating an implementation refinement to the breaking changes infrastructure. The discussion continues to shape how Git will handle deprecated features going forward, with attention to both the option interface and its supporting implementation details. The conditional compilation approach being refined here will serve as a pattern for future breaking changes.
