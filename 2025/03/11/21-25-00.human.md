This is a documentation patch in a series about handling deprecated features and test infrastructure improvements.

Junio Hamano adds documentation for `test_lazy_prereq` in t/README, which was previously undocumented despite being the preferred modern way to define test prerequisites. The patch explains how lazy prerequisites work - they defer evaluation until first use, run in an isolated temporary directory, and set the prerequisite based on the exit status of the provided script. The example shows how SYMLINKS is implemented this way.

This is the first of six patches in v2 of a series that's part of a larger effort to clean up deprecated features (specifically the `--stdin` option in `git name-rev`) while improving test infrastructure. The documentation addition here provides important context for subsequent patches that will use lazy prerequisites in the deprecation process.

The patch is straightforward and well-justified, filling a clear gap in the test documentation. As the first patch in the series, it sets up foundational knowledge that will be expected in later discussion about prerequisite handling for deprecated features.
