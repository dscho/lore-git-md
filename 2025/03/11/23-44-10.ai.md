This is a design refinement discussion in the ongoing `rev-list` NUL-delimited output format thread. Junio Hamano responds to Justin Tobler's agreement with the proposed key-value format for missing objects, suggesting potential optimizations for the attribute names to reduce output size.

The email focuses on a specific implementation detail of the new machine-readable output format - whether to use full attribute names like "missing=yes" or abbreviated forms like "m=yes". This comes after consensus was reached on the overall key-value structure where attributes like path and missing status are represented as NUL-delimited pairs after the object ID.

Junio raises the tradeoff between human readability and output size, noting that since this format is primarily for machine consumption, shorter attribute names could be preferable. The suggestion specifically mentions abbreviating "missing" to "m" and "path" to "p". This builds on the established format where:
- Object IDs come first
- Attributes follow as key-value pairs
- NUL characters delimit all fields
- The format already handles missing objects (via "missing=yes") and paths

The discussion occurs in the implementation phase after the core design was settled, showing attention to optimization details. This refinement would affect the output format documentation in rev-list-options.adoc and the parsing logic in the various output modes (`--objects`, `--missing`, `--boundary`). The thread history shows this is part of a broader effort to create consistent, machine-parseable output across Git commands.
