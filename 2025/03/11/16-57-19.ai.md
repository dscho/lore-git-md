This is a follow-up discussion in the promisor-remote NULL pointer dereference bugfix thread, focusing on broader API design questions around strvec and xstrdup behavior. Junio Hamano responds to Christian Couder's suggestion about potentially modifying strvec_push() and xstrdup() to handle NULL values more gracefully.

The exchange clarifies that while making xstrdup() return NULL or adding a BUG() check might be worth considering, these changes would be inappropriate for the immediate 2.49.0 release and should be discussed separately. Hamano agrees with Couder's assessment that the current promisor-remote fix should proceed independently of these deeper API questions.

Key technical points raised:
- strvec_push() currently uses xstrdup() which crashes on NULL
- strvec_push_nodup() behaves differently by accepting NULL values
- Changing xstrdup() to handle NULLs would require careful consideration of its low-level role
- The argc/argv[] analogy suggests NULLs may not belong in strvec arrays
- These API design questions are explicitly deferred from the current bugfix

The discussion confirms the promisor-remote fix will proceed as-is for 2.49.0, while leaving open the possibility of future strvec API changes. Hamano expresses surprise that the original bug made it into 'seen', indicating the urgency of the fix. The thread maintains its focus on separating immediate bugfixes from broader design discussions.
