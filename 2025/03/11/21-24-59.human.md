This is a cover letter for a patch series preparing infrastructure for breaking changes in Git, specifically targeting the removal of the deprecated `--stdin` option from `git name-rev`. The series builds on previous discussion about establishing patterns for handling breaking changes, with Junio Hamano now taking over the implementation.

The 6-patch series starts with test infrastructure improvements: documenting `test_lazy_prereq`, adding a way to mark deprecated prerequisites, and renaming the problematic `WITHOUT_BREAKING_CHANGES` prerequisite to avoid double negatives. It then modernizes the t6120 test script before finally removing `--stdin` support from `WITH_BREAKING_CHANGES` builds.

The cover letter emphasizes this isn't just about removing one option, but about establishing patterns for future breaking changes in Git 3.0. The implementation now more thoroughly isolates deprecated code with `#ifdef` guards, making it clear what can be removed later. The changes affect test infrastructure, documentation, and the name-rev implementation itself.

This version incorporates feedback from Patrick Steinhardt about more comprehensive conditional compilation and adopts Junio's suggestion to remove the old prerequisite sooner rather than maintaining it through another release cycle. The series shows careful attention to both the technical implementation and the broader goal of creating maintainable patterns for handling breaking changes.
