Refactoring patch in the breaking changes infrastructure series, focusing on test modernization.

This is the fourth patch in a 6-part series that's removing the deprecated `--stdin` option from `git name-rev` and improving test infrastructure for handling breaking changes. The patch fixes a test hygiene issue in t6120-describe.sh where several tests were piping `git` commands together, which can hide exit statuses. 

Junio Hamano updates two test cases to first write the output of `git rev-list` to a file, then use that as input to `git name-rev`, ensuring any failures in the first command would be caught. The changes affect both the modern `--annotate-stdin` test and the deprecated `--stdin` test case. 

This is a straightforward improvement that follows good testing practices, though it's worth noting that the deprecated `--stdin` test will eventually be removed entirely as part of this series' goal to eliminate the old interface. The patch maintains consistency with the series' broader focus on test modernization while making these specific tests more robust.
