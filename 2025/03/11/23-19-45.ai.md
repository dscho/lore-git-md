This is a feature proposal for adding NUL-delimited output to `git rev-list`, now focusing on format design decisions in response to Junio Hamano's feedback. Justin Tobler agrees with Junio's suggestion to simplify the format from double-NUL to single-NUL delimiters and adopt a unified key-value attribute structure. The new format will use `<oid> NUL [<attr>=<value> NUL]...` syntax, where the absence of '=' signals a new record start, eliminating the need for double-NUL terminators. Specific transformations include converting path outputs to `path=<path>` and missing object markers to `missing=yes`. Justin confirms he'll implement this unified approach in the next version, noting its flexibility for future extensions like timestamp support. The discussion has shifted from implementation mechanics to output format philosophy, with consensus forming around the more structured key-value approach despite its slightly larger output size. This positions the v2 series to establish a model for machine-parseable output that could influence other Git commands.
