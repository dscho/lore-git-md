This is a follow-up discussion in the promisor-remote bugfix thread, where Christian Couder responds to Junio Hamano's review questions about the NULL URL handling fix. The email clarifies several design decisions around the strvec behavior and promisor-remote configuration handling. Christian explains that while deeper changes to strvec_push() or xstrdup() could prevent similar issues, those would require separate discussions. For now, the focus remains on the immediate NULL dereference fix for the 2.49.0 release.

Christian provides important context about how the 'names' and 'urls' strvecs are used in promisor remote validation, detailing the behavior differences between 'KnownName' and 'KnownUrl' modes. He defends the approach of pushing empty strings rather than skipping entries, arguing it provides better diagnostics and future flexibility. The response also notes improvements made in v2 of the patch, including additional warnings and test coverage for missing URL cases.

The discussion reveals some remaining philosophical questions about API design (like whether strvec should handle NULLs more gracefully) but confirms the current patch cleanly solves the immediate crash while maintaining backward compatibility. Christian positions these deeper questions as worthwhile but separate from the urgent bugfix needed before the release.
