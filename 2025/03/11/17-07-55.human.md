Maintainer follow-up on breaking changes infrastructure. This email from Junio Hamano responds to Patrick Steinhardt's suggestion about more thoroughly isolating the deprecated `--stdin` functionality in `git name-rev`. The discussion is part of an ongoing series establishing patterns for handling breaking changes in Git.

Patrick had proposed not just conditionally compiling the `--stdin` option definition (as shown in the diff), but also guarding the related `transform_stdin` variable and its usage site with `#ifndef WITH_BREAKING_CHANGES`. Junio agrees this would better reflect the eventual complete removal of the feature, calling it "a great point."

This exchange shows the maintainer validating and accepting a technical refinement to the breaking changes infrastructure. The change would make the codebase more accurately represent the transitional state between the deprecated and new behavior.
