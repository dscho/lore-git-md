This is a compatibility discussion in the ongoing thread about adding NUL-delimited output to `git rev-list`. Jeff King raises two important points about the `-z` flag behavior that need resolution before finalizing the design.

First, he questions whether `--stdin` should also respect the `-z` flag for input parsing, noting this is the convention in other Git commands. This is a forward-looking concern since changing this behavior later would be difficult. Second, he points out that `rev-list` currently accepts `-z` (inherited from diff options) but doesn't meaningfully use it, creating potential backward compatibility questions. He suggests either fully adopting the diff option handling or cleanly separating the new NUL-delimited output behavior.

These questions touch on interface design consistency and backward compatibility - key considerations for a machine-parseable output format that may become a long-term part of Git's interface. The thread has already established consensus on the core output format (single NUL delimiters with key-value attributes), but these edge cases around option handling remain to be addressed in the v2 implementation.
