This is a performance optimization patch in the cruft pack series, addressing how pack size thresholds are handled. It modifies `git pack-objects` to allow cruft packs to grow slightly beyond their specified maximum size limit (by at most one object) to prevent perpetual repacking of small leftover objects.

The key technical changes:
- Modifies `builtin/pack-objects.c` to perform size limit checks before writing each object when generating cruft packs
- Updates documentation in both `pack.adoc` and `git-pack-objects.adoc` to clarify the special size limit behavior for cruft packs
- Adds comprehensive tests in `t5329-pack-objects-cruft.sh` verifying the new threshold handling with randomly generated blobs of specific sizes

The change addresses an issue identified by Patrick Steinhardt where strict adherence to size limits could cause certain cruft packs to be repeatedly repacked. The solution maintains all existing test coverage while adding new verification that:
- Packs properly exceed the threshold by controlled amounts
- All objects are correctly distributed between packs
- The behavior prevents perpetual repacking cycles

This builds on the established cruft pack infrastructure from earlier in the thread, including the recently added test helpers now in `t/lib-cruft.sh`. The patch follows the systematic test organization approach seen in previous parts of the series, with clear documentation updates and thorough test coverage of the new behavior.
