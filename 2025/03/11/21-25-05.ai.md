This is the final patch in a 6-part series removing the deprecated `--stdin` option from `git name-rev` as part of Git 3.0 breaking changes preparation. The patch completes the removal that was started in Git 2.40 when `--stdin` was deprecated in favor of `--annotate-stdin`.

The changes include: (1) documenting the removal in BreakingChanges.adoc with a clear timeline (deprecated in 2.40, removed in 3.0); (2) conditionally compiling out both the `--stdin` option and its supporting `transform_stdin` variable behind `#ifndef WITH_BREAKING_CHANGES`; and (3) updating t6120-describe.sh tests to verify the option is rejected when breaking changes are enabled while maintaining the deprecation warning test for older versions.

The test changes demonstrate the transition pattern - when `WITH_BREAKING_CHANGES` is not set, the deprecated option works but emits a warning; when set, the option is rejected as unknown. The patch maintains the documentation note in `--annotate-stdin`'s help text that it was previously called `--stdin`, preserving historical context for users upgrading from older versions.

This completes the technical work started in earlier patches of the series, fully removing the deprecated interface while maintaining proper documentation of the change and thorough test coverage of both the transition period and final state. The changes affect the name-rev command implementation, breaking changes documentation, and test scripts, following the patterns established earlier in the series for handling breaking changes.
