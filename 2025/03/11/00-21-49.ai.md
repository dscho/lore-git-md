Performance optimization in the cruft pack handling series, specifically simplifying the aggregation logic for small cruft packs.

This patch streamlines how `git repack` combines small cruft packs when the `--max-cruft-size` option is used. The original implementation (from 37dc6d8104) would carefully accumulate packs until their combined size neared the threshold, maintaining a running total. Taylor Blau now proposes a simpler approach: just combine all packs smaller than the threshold in one go, letting `pack-objects` handle any necessary splitting via its existing `--max-pack-size` mechanism.

The key changes are:
1. Removal of the size-sorting comparator (`existing_cruft_pack_cmp`)
2. Elimination of the running total tracking
3. Direct comparison of each pack's size against the threshold
4. Deletion of a now-irrelevant test case that verified the old accumulation behavior

This yields slightly different behavior - packs are now combined more aggressively rather than in careful size order - but the end result is equivalent since `pack-objects` will enforce the size limit anyway. The simplification removes 38 lines of code from `builtin/repack.c` and 42 lines of test code from `t/t7704-repack-cruft.sh`.

This patch builds on the established cruft pack infrastructure from earlier in the series, including the object freshening fixes and test reorganization. It represents a logical optimization now that the core behavior is well-tested and stable. The change is consistent with the thread's trajectory of methodical improvements to cruft pack handling.
