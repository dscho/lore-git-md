This is a test infrastructure patch that extends the `test_lazy_prereq` mechanism as part of the ongoing breaking changes infrastructure work. 

The patch introduces a new way to mark deprecated test prerequisites by having them exit with status code 125 (matching the bisect script convention for programming errors). When such a prerequisite is encountered, Git will now raise a BUG() message rather than silently treating it as unsatisfied. This provides a clearer signal that the prerequisite should not be used anymore.

The change updates both the documentation in t/README (explaining the new 125 exit code behavior) and the implementation in test-lib-functions.sh (adding handling for this case). This builds on the previous work in the series to better handle deprecated features, in this case providing a way to catch and flag when tests try to use prerequisites that have been removed.

The change is cleanly implemented with clear documentation updates, and fits well with the series' goal of establishing patterns for handling breaking changes. As the second patch in a 6-part series, it follows the initial documentation improvements from patch 1 and precedes further test modernization and prerequisite renaming work.
