This is a cover letter for a patch series that continues the work on handling breaking changes in Git, specifically focusing on removing the deprecated `--stdin` option from `git name-rev`. The series builds on previous infrastructure work for managing breaking changes through the `WITH_BREAKING_CHANGES` compilation flag.

The 6-patch series starts with test infrastructure enhancements: documenting `test_lazy_prereq`, adding support for marking deprecated prerequisites, and renaming the problematic `WITHOUT_BREAKING_CHANGES` prerequisite to avoid double negatives. It then modernizes the t6120 test script before finally implementing the removal of `--stdin` support in `git name-rev`, guarded by the breaking changes flag.

Key technical points include: test documentation updates in t/README, prerequisite handling improvements in test-lib.sh, test modernization in t6120 (fixing exit code handling and improving test hygiene), and the actual name-rev change which now more completely isolates the deprecated functionality through conditional compilation (addressing Patrick Steinhardt's earlier suggestion to also guard the supporting `transform_stdin` variable).

The series represents both a specific cleanup (removing the deprecated name-rev option) and a demonstration of the breaking changes infrastructure that may be used for future Git 3.0 preparations. The implementation shows careful attention to test coverage and backward compatibility, with clear demarcation of code that will be removed in the future. The changes affect multiple test scripts (t5323, t5505, t5515, t5516, t6120), test infrastructure files, and the name-rev implementation itself.
