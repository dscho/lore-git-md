This is a discussion about the design of a new NUL-delimited output format for `git rev-list`, part of an ongoing feature series to improve machine parsing of Git's output.

Justin Tobler responds to D. Ben Knoble's feedback on the proposed NUL-delimited format for `git rev-list`. The discussion has evolved from implementation details to the philosophical question of whether the output should use ordered fields (compact but requiring documentation) or key-value pairs (self-documenting but more verbose). 

Tobler highlights the challenge of parsing `rev-list`'s current output, which can vary significantly based on options used, with different line formats even within a single command's results. He suggests that a key-value attribute format (`<oid> NUL [<token>=<value> NUL]...`) might simplify parsing by making the output more consistent and self-describing, even if it increases output size.

The exchange shows the series is moving toward a more general solution that could potentially unify output formats across different `rev-list` modes, while still maintaining the original goal of reliable machine parsing. The discussion remains open-ended, with tradeoffs between verbosity and parseability still being weighed.
