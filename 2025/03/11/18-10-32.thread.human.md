While using `--reapply-cherry-picks` works around the problem, it creates empty commits. The bug appears to be in rebase's commit selection logic when dealing with commits that exist in different forms (original, revert, reapply) across branches. The reporter tested this with Git 2.48.1 on GNU/Linux, and the well-constructed test case makes this a convincing report that would benefit from maintainer attention.
