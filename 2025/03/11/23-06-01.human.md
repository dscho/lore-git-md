Bugfix discussion regarding promisor-remote URL handling. Jeff King responds to Christian Couder's v2 patch that fixed a NULL pointer dereference when promisor remotes lack URLs. While agreeing with the immediate fix, Jeff points out an interesting edge case where Git traditionally defaults missing remote URLs to the remote name itself (e.g., a remote "foo" with no URL can be fetched as "foo"). He suggests an alternative patch that would maintain this behavior for consistency.

The discussion also touches on broader design questions about NULL handling in strvec and xstrdup(), with both agreeing these should be deferred. Jeff notes the current solution could be slightly cleaner using git_config_get_string_tmp() to simplify memory management, though this doesn't affect the core functionality.

This email doesn't introduce new problems but rather explores an alternative approach that might better match Git's existing remote URL conventions. The thread shows healthy technical discussion about edge cases while maintaining consensus on the immediate NULL dereference fix. Jeff's suggestion about URL defaulting appears as a thoughtful refinement rather than a blocking concern.
