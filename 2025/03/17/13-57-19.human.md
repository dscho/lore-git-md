This is the final patch in a series improving Meson build system handling of breaking changes, specifically addressing documentation installation. The patch ensures the `git-pack-redundant(1)` manpage is only installed when breaking changes are enabled, matching Makefile behavior.

Patrick Steinhardt responds to Phillip Wood's review of the third patch, clarifying why an apparent redundancy in the code is actually necessary. The discussion centers around the `configured_manpages` variable, where Wood had suggested removing an explicit addition of `manpages_breaking_changes.keys()` since these keys are already included via the main `manpages` dictionary. Steinhardt explains this is required when breaking changes are enabled, as the manpage check would otherwise fail for pages that need conditional handling.

The exchange shows careful attention to edge cases in the build system logic, with Steinhardt providing a clear technical justification for maintaining the current implementation. This finalizes the series' work to achieve full parity between Meson and Makefile behavior for breaking change scenarios, with all reviewers now aligned on the approach.
