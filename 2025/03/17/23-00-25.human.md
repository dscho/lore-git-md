This is the fourth patch in a series improving cruft pack handling in `git repack`. It changes the behavior of `--max-cruft-size` to act as a cruft-specific override for `--max-pack-size` rather than its previous confusing behavior.

The patch fixes an unintuitive interaction where `--max-cruft-size` would sometimes split cruft packs into multiple smaller packs (e.g. creating 199MB + 1MB packs from two 100MB packs when given a 200MB limit). The new behavior makes `--max-cruft-size` simply pass through to `--max-pack-size` for cruft packs, which provides more predictable results.

The change is implemented by temporarily repurposing the `collapse_small_cruft_packs()` function to behave like the case where no maximum pack size is specified. This sets up for the next patch which will introduce a new `--combine-cruft-below-size` option for the originally intended behavior.

The patch includes test updates to verify the new behavior and marks one existing test as failing since it tested the old behavior. The author acknowledges this is a breaking change but argues it's justified since the old behavior didn't match user expectations. The implementation appears clean and well-tested, continuing the careful approach seen in earlier patches of this series.
