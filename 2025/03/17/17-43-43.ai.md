Technical analysis of path-filtered log behavior with subtree merges, focusing on practical workarounds.

Jeff King responds to Oswald Buddenhagen's report about `git log .` showing primarily merge commits in git-gui's subdirectory. He confirms this is due to path mismatches between the merged git-gui repository (where files live at root) and the main repository (where they're under git-gui/). 

The key technical observation is that path-based filtering fails because the original commits modify paths like "git-gui.sh" while merges update "git-gui/git-gui.sh". King provides a concrete workaround: explicitly listing both path variants (`git log -- git-gui/ git-gui.sh lib/`) to capture history from both locations. He notes this must use "--" to bypass DWIM logic since some paths don't exist in the working tree.

This email doesn't address the deeper architectural issues around rename tracking that were discussed earlier in the thread, but provides immediate practical guidance for users hitting this limitation. The workaround demonstrates how Git's current path-matching behavior requires manual intervention when dealing with subtree-merged histories, reinforcing the need for more sophisticated path-tracking in the revision walking machinery.
