This is the final patch in a build system improvement series addressing unreachable code detection. The patch implements Junio Hamano's systematic solution for handling false positives from the `-Wunreachable-code` compiler warning, replacing Jeff King's earlier platform-specific workaround.

The core of the solution is a new `NOT_A_CONST` macro that prevents compiler optimization of expressions that appear constant but may actually fail at runtime (like `sigfillset()`). The implementation uses a clever trick - an externally defined variable `false_but_the_compiler_does_not_know_it_` that's initialized to 0 but never modified, placed in a separate compilation unit (`fbtcdnki.o`) to prevent cross-unit optimization.

Jeff King provides feedback on the implementation, suggesting minor improvements to naming (preferring `NOT_A_CONSTANT` over `NOT_A_CONST` and a more descriptive filename than `fbtcdnki.o`). He also notes a typo in the comment ("sitfillset") but overall approves of the approach, calling it "much nicer and more descriptive" than the previous errno-based workaround.

The patch demonstrates good technical judgment in evolving from a quick fix to a principled solution, with thorough documentation of the rationale. It completes the series' goal of enabling `-Wunreachable-code` warnings while handling false positives in a maintainable way. The discussion shows healthy collaboration between Jeff King (who initially enabled the warnings) and Junio Hamano (who proposed the architectural solution).
