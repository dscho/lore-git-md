This is a technical clarification in the ongoing Meson build system series about handling breaking changes. Patrick Steinhardt responds to Phillip Wood's review of patch 3/3, explaining why the explicit addition of `manpages_breaking_changes.keys()` to `configured_manpages` is necessary even when breaking changes are enabled. 

The key technical point is that the sanity check for manpages requires all discovered documentation files to be accounted for in `configured_manpages`, regardless of whether they're conditionally included via the breaking changes option. Without this addition, Meson would error out when breaking changes are enabled, as it would detect `git-pack-redundant.adoc` in the source directory but not find it properly wired up in the build configuration. 

This maintains the series' goal of precise alignment between Makefile and Meson build behaviors while ensuring all edge cases in the documentation handling are properly covered.
