This is a follow-up discussion about the build system warning solution series that has already been merged. Taylor Blau raises a historical point about patch ordering in the completed series.

The email questions whether the patches should have been reordered to avoid a temporary build breakage for macOS/Clang users with DEVELOPER=1 enabled. The first patch in the series enabled -Wunreachable-code warnings, while the second patch (this one) provided the errno-based workaround for the sigfillset() issue that those warnings revealed. Taylor notes this is now moot since the series is already in 'next' with the final architectural solution (patch 3) superseding both earlier patches.

The thread context shows this was part of a complete 3-patch series that evolved from warning enablement (patch 1) to platform workaround (patch 2) to final systematic solution (patch 3). The final solution replaced both earlier approaches with a more general NOT_A_CONST macro and new compilation unit. While Taylor's observation about historical breakage is technically correct, the maintainer chose to progress through all stages of the solution rather than reordering patches.
