This is a platform compatibility discussion about removing outdated Cygwin support, specifically focusing on regex handling and test suite implications.

Ramsay Jones responds to Junio Hamano's query about dropping NO_REGEX support for Cygwin 1.7 (released in 2013) by proposing to remove all pre-2.0 Cygwin compatibility code in config.mak.uname. He includes a draft patch that would eliminate version-specific workarounds, noting this would effectively drop support for Cygwin versions older than 2.0 (released April 2015). Ramsay acknowledges he's unsure how many users still build Git from source on these old Cygwin systems, and defers to the Cygwin package maintainer Adam for final judgment.

The discussion also touches on the test anomaly in t7815-grep-binary.sh where Cygwin's FreeBSD-derived regex library matches NUL bytes with '.' patterns, unlike glibc systems. Ramsay notes this behavior likely exists in FreeBSD too but hasn't been reported, and reiterates the three options for handling the test: leave it as-is, disable for Cygwin, or remove entirely. He maintains his preference for removing the test entirely if the behavior is deemed acceptable.

The exchange highlights the careful balancing act between maintaining compatibility with old systems and simplifying the codebase, with Ramsay providing historical context while acknowledging the decision ultimately depends on real-world usage patterns of older Cygwin versions. The technical change itself appears sound, but the discussion remains open pending input from the Cygwin package maintainer about potential user impact.
