This is a design resolution in the protocol v2 fetch behavior architectural improvements series, specifically addressing the final edge case of HEAD updates during fetches.

The email captures Junio Hamano's agreement with Jeff King's analysis of an intermediate case in HEAD update behavior. The discussion centers around `git fetch origin main` currently updating HEAD when it points to "main", which both agree should not happen. Jeff had proposed two options for resolving this: 1) only update HEAD when using configured refspecs (Junio's preference) or 2) allow updates when fetching HEAD's destination ref. 

Junio strongly favors option 1 as more intuitive and consistent with the principle that HEAD updates should only occur when explicitly configured or during full repository fetches. He emphasizes that fetching a specific branch like "main" should not implicitly update HEAD, even when HEAD happens to point to that branch. 

This represents a user-visible behavior change from current Git, but both agree the change is justified given the feature's newness and the current behavior's lack of clear rationale. The resolution aligns with the architectural principle established earlier in the thread that HEAD updates should be strictly limited to configured refspec fetches, excluding both exact-OID fetches and this intermediate case of fetching specific refs by name without configuration.

Key technical details:
- Affects `builtin/fetch.c` behavior
- Finalizes the HEAD update rules for protocol v2
- Overrides current behavior where `git fetch origin main` updates HEAD
- Implements option 1 from the proposal (configured refspecs only)
- Considered a justified behavior change despite being user-visible

The discussion confirms the series is now complete with all edge cases addressed, including this final clarification about HEAD updates. This email represents maintainer approval of the resolution, allowing the series to proceed with the stricter HEAD update behavior.
