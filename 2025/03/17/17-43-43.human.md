This is a technical discussion about path-filtered log behavior with subtree merges, continuing the thread started by Oswald Buddenhagen's observation that `git log .` in the git-gui subdirectory shows mostly merge commits rather than the expected file history.

Jeff King provides a practical workaround for the immediate issue: when viewing history of files that were merged via subtree merges (like git-gui's files), you need to explicitly specify both the current subdirectory path (`git-gui/`) and the original root-level paths (`git-gui.sh`, `lib/`) in the git log command. He explains this is necessary because the individual commits in the source repository modified files at the root level, while the merge commits update them in the subdirectory. The note about using `--` to force path interpretation is particularly helpful detail for users encountering this scenario.

The email doesn't propose any code changes but offers valuable user-facing advice that addresses the symptom while deeper architectural solutions (as discussed in the thread) are being considered. This is a good example of an experienced contributor providing immediate help while the community works on more fundamental fixes.
