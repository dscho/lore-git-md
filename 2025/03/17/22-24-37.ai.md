Refactoring patch in the refspec API cleanup series. This is the second of four patches converting the refspec API from using an enum to boolean flags, following the architectural decisions made in the earlier protocol v2 fetch improvements series.

The patch replaces the single `refspec_init()` function (which took a boolean `fetch` parameter) with two specialized variants: `refspec_init_fetch()` and `refspec_init_push()`. This makes the initialization intent clearer at call sites by encoding the operation type in the function name rather than passing a boolean. The implementation uses new `REFSPEC_INIT_FETCH` and `REFSPEC_INIT_PUSH` constants for initialization.

Changes affect `refspec.[ch]` and update callers in `remote.c` and `transport-helper.c`. The patch follows the pattern established in the first patch of the series (which converted the `fetch` field from enum to boolean) and maintains the same behavior while improving code clarity. This is a mechanical change that builds on the prior architectural work to simplify the refspec API.
