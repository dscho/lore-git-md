This is a design resolution in the protocol v2 fetch behavior series, specifically about HEAD updates during fetches. The discussion clarifies when `git fetch` should update the local HEAD when fetching from a remote.

Jeff King identified an intermediate case where `git fetch origin main` currently updates HEAD if it points to "main", which Junio Hamano agrees should not happen. They consider two approaches:
1. Only update HEAD when using configured refspecs (Junio's preference)
2. Keep the current behavior but with better explanation

The consensus is clearly for option 1, as it's more intuitive and aligns with the principle that HEAD updates should only happen when explicitly configured. This represents a user-visible behavior change from current Git, but both agree it's justified given the feature is relatively new and the current rules are confusing.

This email effectively finalizes the design decision for the series, with Junio as maintainer giving clear approval for the stricter approach. The change will be implemented on top of Jeff's existing patch series, which has already been thoroughly reviewed.
