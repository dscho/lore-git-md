Git maintainer Junio Hamano responds to the `git switch --force` vs `--discard-changes` behavior discussion. This is a clarification of the technical details around branch switching with untracked files.

Hamano confirms the reported behavior where `--discard-changes` fails on untracked files while `--force` proceeds, noting this makes sense conceptually since untracked files aren't technically "changes" from Git's perspective. He provides additional context about the reproduction case, emphasizing it requires a specific setup where the file exists in the target branch but not the current one.

The response suggests this might be a documentation issue rather than a code bug, proposing to clarify that `--discard-changes` is intentionally more conservative than `--force`. Hamano acknowledges both sides of the debate - some might appreciate the finer control while others may find it confusing - but leans toward documenting the distinction rather than changing behavior, as the current implementation appears logically consistent.

The email provides authoritative context from someone familiar with Git's internals, though Hamano notes he doesn't personally use `git switch` and is accustomed to `git checkout -f` behavior. The tone suggests this is a reasonable design choice that just needs better explanation in the docs.
