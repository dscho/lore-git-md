This is the final patch in a series improving cruft pack handling in `git repack`, introducing a new `--combine-cruft-below-size` option to replace the problematic behavior of `--max-cruft-size`.

The patch implements the new combination logic where cruft packs smaller than a specified threshold are combined, while larger ones are left alone. This differs from the old `--max-cruft-size` behavior (now repurposed as a cruft-specific `--max-pack-size` override) by explicitly combining all small packs rather than trying to build up to the threshold size. The change prevents repeated repacking of the same objects and better matches user expectations.

Key changes include:
- New `combine_small_cruft_packs()` function implementing the threshold-based selection
- Updated documentation explaining the new option
- Test updates to verify the behavior, including checking that packs are combined regardless of whether they would exceed the threshold when merged
- The implementation maintains the ability to limit cruft pack size via `--max-cruft-size` when desired
- One test is updated from `test_expect_failure` to `test_expect_success` now that the complete solution is in place

This completes the series' transition to clearer cruft pack handling, with the new option providing more predictable behavior while maintaining flexibility for repository maintenance. The careful staging of changes throughout the series (test improvements first, then behavior changes) demonstrates good patch series hygiene.
