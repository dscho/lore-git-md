This is a refactoring series that cleans up the `refspec` API by treating its `fetch` field as a proper Boolean rather than using enum values `REFSPEC_FETCH` and `REFSPEC_PUSH`. The series emerges from earlier discussions about protocol v2 fetch behavior, where Taylor Blau identified this as a cleanup opportunity.

The 4-patch series simplifies the refspec API by:
1. Converting the `fetch` field to a Boolean
2. Replacing generic initialization functions with fetch/push-specific variants
3. Removing the `refspec_item_init_or_die()` wrapper
4. Updating all callers to use the new API

The changes touch core refspec handling code in `refspec.c` and several callers including fetch, pull, and transport-helper. Taylor notes this is a nice cleanup but not critical - he's open to either merging or dropping the series to avoid bike-shedding. The changes appear mechanically sound and build on the recently-approved protocol v2 improvements.
