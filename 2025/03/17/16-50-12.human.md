This is a documentation bug report highlighting a discrepancy between Git's behavior and its documentation for `git switch` options. David Mandelberg points out that while the docs claim `--force` is an alias for `--discard-changes`, they actually behave differently when dealing with untracked files.

The key observation is that `--discard-changes` refuses to overwrite untracked files (like an untracked Makefile in the example), while `--force` will proceed anyway. This suggests `--force` is more aggressive than its documented alias would imply. The email doesn't propose a fix but raises the question of whether the code or documentation should be changed to align.

The issue appears well-substantiated with a clear reproduction case and references the exact documentation location. Since this involves a potentially surprising behavior difference in a commonly used command, it's likely to get attention from maintainers.
