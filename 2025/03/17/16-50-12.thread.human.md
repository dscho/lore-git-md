This thread examines a subtle but important behavioral difference between `git switch --force` and `--discard-changes` when untracked files are present. Originally reported by David Mandelberg, the issue stems from documentation suggesting these flags are aliases when in practice they handle untracked files differently: `--discard-changes` fails if untracked files would be overwritten (consistent with normal `switch` behavior), while `--force` proceeds regardless.

Junio Hamano has provided technical background, tracing the divergence to specific commits in Git's history. The difference emerged from how two changes interacted: one adding the `--discard-changes` option with its own flag, and another later introducing untracked file protection that keyed off the existing `--force` flag rather than the new one. While this appears to have been an implementation accident rather than intentional design, Hamano notes the behavior may now be effectively frozen due to potential user reliance.

The discussion leans toward documenting the distinction rather than changing behavior, though there's acknowledgment that both approaches have merit - the current behavior provides finer control, but the inconsistency may confuse users expecting parity with `git checkout -f`. No final decision has been made, but documentation clarification seems the likely resolution path if the behavior remains unchanged. The thread remains open to further discussion about whether preserving this subtle distinction is ultimately helpful or just a source of confusion.
