Refactoring of refspec API to simplify boolean handling. This 4-patch series from Taylor Blau proposes converting the `fetch` field in `struct refspec` from an enum (REFSPEC_FETCH/REFSPEC_PUSH) to a simple boolean, arguing this better reflects its actual usage in the codebase.

The changes progress through several API cleanup steps:
1. Direct conversion of the field to boolean
2. Replacement of `refspec_init()` with separate fetch/push variants
3. Removal of `refspec_item_init_or_die()`
4. Replacement of `refspec_item_init()` with fetch/push variants

The series touches multiple files including `refspec.c`, `refspec.h`, and several command implementations (`fetch.c`, `pull.c`, `transport-helper.c`). The author notes this is a quality-of-life improvement rather than a critical fix, and explicitly invites feedback while acknowledging the potential for bike-shedding. The changes appear mechanically sound but would require careful review of all call sites to ensure no subtle behavioral changes in refspec handling.

This builds on the recently concluded protocol v2 refspec discussion where the current enum-based implementation was identified as ripe for cleanup. The patch demonstrates both approaches (boolean conversion and the alternative enum-with-switch proposal) that were previously discussed in the thread. The binary `git-diff-pairs` file included in the diff appears to be accidentally added and would likely need removal before merging.
