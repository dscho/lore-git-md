This is a build system improvement patch introducing a new compiler trick to handle false positives from `-Wunreachable-code` warnings. It's part of a 3-patch series (position 2/3) that evolved from a platform-specific workaround to a general solution.

The patch introduces a `NOT_CONSTANT` macro that prevents compilers from optimizing out expressions they incorrectly deem constant. The implementation uses a global variable `false_but_the_compiler_does_not_know_it_` defined in a separate compilation unit, making it opaque to compiler analysis. This replaces the previous `errno`-based workaround for `sigfillset()` in `run-command.c` with a more general solution that better documents the intent.

Key technical details include:
- New compilation unit `compiler-tricks/not-a-constant.c`
- Macro definition in `git-compat-util.h` that ORs expressions with the opaque global
- Integration into both Makefile and Meson build systems
- Updated `atfork_prepare()` in `run-command.c` using the new macro
- Maintains POSIX compliance while avoiding compiler optimization

The solution addresses a specific case where compilers might incorrectly optimize out error checks for `sigfillset()`, but is designed to be reusable for similar cases. The patch follows Junio Hamano's architectural approach after earlier work by Jeff King, showing the evolution from platform-specific fix to general solution.
