Thread summary:

Performance investigation into `git add .` slowness compared to `git status` in large repositories (~27k dirs, ~78k paths) on MacOS with Git 2.49.0. While `git status` completes in ~300ms (with fsmonitor and untracked cache enabled), `git add .` takes 1.5-2s with nearly all time spent in `read_directo` operations. Author demonstrates workarounds (targeted adds or piping `git status` output to `git add`) that achieve sub-500ms performance, suggesting `git add` could leverage similar optimizations to `git status`. Core question remains why the directory scanning optimizations aren't shared between these operations. No specific code changes proposed yet - primarily a diagnostic understanding of the performance gap between these related operations. Platform/version specifics noted as potentially relevant factors.
