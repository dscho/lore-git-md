This is a follow-up in the thread about integer overflow fixes in xdiff's hunk calculation. René Scharfe provides evidence that the upstream xdiff library (from which Git's xdiff is derived) has been effectively stable since 2008, with the last release being version 0.23 from November 2008. This supports the earlier decision to use a minimal fix (saturating addition) rather than a more invasive change like switching from `long` to `size_t` types, since upstream development appears dormant. The exchange confirms there's little risk of divergence from upstream and thus no need to maintain close compatibility with potential future xdiff changes. This puts to rest Junio Hamano's earlier question about whether upstream activity should influence the implementation approach, reinforcing that the chosen solution is appropriate given xdiff's long-term stability.
