This is a continuation of the platform compatibility discussion around Cygwin regex handling, specifically addressing whether to maintain support for Cygwin 1.7 and how to handle test t7815's NUL byte matching behavior.

Ramsay Jones responds to Junio Hamano's query about dropping NO_REGEX support for Cygwin 1.7 by revealing he already prepared a patch to remove all pre-2.0 Cygwin compatibility code from config.mak.uname, including the NO_REGEX setting. He notes this would effectively drop support for Cygwin versions older than 2.0 (released April 2015), though he's unsure how many users still build Git from source on such old systems. Ramsay defers to Adam (Cygwin's Git package maintainer) for the final decision on this compatibility cutoff.

Regarding the t7815 test case where Cygwin's FreeBSD-derived regex matches NUL bytes with '.' patterns, Ramsay acknowledges this behavior likely exists on FreeBSD too but hasn't been reported. He reiterates the three options for handling this: keep the test as-is, disable it for Cygwin, or remove it entirely. Ramsay's uncertainty about other BSD systems' behavior and potential implementation changes since the FreeBSD code import leaves the test resolution open-ended. The email maintains the thread's careful consideration of platform-specific behaviors while pushing toward modernizing Cygwin support.
