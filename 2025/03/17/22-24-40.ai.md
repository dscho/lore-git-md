Refactoring patch in the refspec API cleanup series. This is the third of four patches converting the refspec API from using an enum to boolean for fetch/push operations, following the architectural decisions made in the protocol v2 fetch improvements thread.

The patch removes `refspec_item_init_or_die()`, a thin wrapper around `refspec_item_init()` that handled error cases by dying. The motivation is to avoid proliferating similar wrappers when introducing fetch/push-specific variants of `refspec_item_init()` in the next patch. The change inlines the error handling at the two call sites (`builtin/pull.c` and `refspec.c`), trading a small code duplication for API simplification.

Key technical points:
- Maintains the same error handling behavior (dying on invalid refspecs)
- Touches the same files as previous patches in the series (`refspec.[ch]`, `builtin/pull.c`)
- Follows the pattern established in patch 2 of replacing general-purpose functions with fetch/push variants
- Leaves the boolean `fetch` parameter in `refspec_item_init()` to be addressed in the next patch

The change is mechanical and low-risk, building on the already-approved direction of the series. The patch maintains test coverage through existing tests that exercise refspec parsing.
