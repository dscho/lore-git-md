This is a follow-up in the ongoing Rust crates publishing discussion, specifically addressing the build system incompatibilities between Git's Makefile-based workflow and Cargo's publishing requirements.

Josh Steadmon reports having preliminary fixes for the crate publishing issues that prevent the Rust interface crates.io publication. The core problem remains that `cargo publish` doesn't include the repository root, breaking the build process that depends on the top-level Makefile and Git sources outside the `contrib/libgit-*` directories. 

The email notes these are currently "pre-RFC-quality" fixes that will need proper splitting, explanation of alternatives considered, and refinement before formal submission. This suggests the solutions are still in early stages but represent concrete technical progress on the publishing blockers. The mention of placeholder crates (previously published to prevent name squatting) indicates this is part of a coordinated strategy to maintain the project's Rust integration momentum while solving the technical challenges.

Key technical points to track in future discussion: the specific build system modifications being proposed, how they reconcile Makefile and Cargo workflows, and whether they maintain compatibility with both local development and crates.io publishing. The email positions this as an interim update with more detailed technical proposals coming soon.
