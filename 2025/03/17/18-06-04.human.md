This is a follow-up discussion on the protocol v2 fetch behavior series, specifically addressing HEAD updates during fetches. Jeff King responds to Junio Hamano's proposed rule that HEAD updates should only occur during fetches using configured fetch refspecs (standard remote-tracking branch updates), not during exact-OID fetches.

Jeff agrees with the core principle but highlights an edge case: fetches with explicit refspecs (like `git fetch origin main`) currently update HEAD if it points to the fetched ref, which is inconsistent with the proposed rule. He presents two possible resolutions:
1. Strictly limit HEAD updates to configured refspec fetches (Junio's preference)
2. Allow HEAD updates for explicit refspec fetches when HEAD points to the fetched ref (current behavior)

Jeff leans toward option 1 as more intuitive and better aligned with how the feature would be designed from scratch, noting the current behavior is both hard to explain and relatively new enough to change. The discussion appears to be converging on establishing clear behavioral rules for HEAD updates as part of the larger protocol v2 improvements.
