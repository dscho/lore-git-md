Refspec API refactoring (part 2/4) - this patch continues Taylor Blau's series to simplify the refspec API by replacing the boolean-based initialization with dedicated fetch/push variants.

The change replaces the single `refspec_init()` function (which took a boolean `fetch` parameter) with two explicit functions: `refspec_init_fetch()` and `refspec_init_push()`. This makes the code's intent clearer at call sites and follows the pattern established in the first patch of converting the enum-based approach to booleans.

The patch updates all existing callers across the codebase (in `remote.c` and `transport-helper.c`) to use the new functions. The implementation uses `memcpy` from static `REFSPEC_INIT_{FETCH,PUSH}` structs rather than direct field assignment, which may help maintain consistency if the struct definition changes in the future.

This is a straightforward mechanical change that builds on the foundation laid in patch 1, continuing the series' goal of making the refspec API more maintainable. The changes are part of a broader effort to clean up the refspec handling code following recent protocol v2 fetch behavior improvements.
