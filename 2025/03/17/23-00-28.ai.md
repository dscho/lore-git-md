This is the final patch in a series improving cruft pack handling in `git repack`, introducing the new `--combine-cruft-below-size` option as a replacement for the problematic `--max-cruft-size` behavior. The patch implements the new combination logic where all cruft packs smaller than a specified threshold are combined, while leaving larger packs untouched.

The key technical changes include:
- Adding the new `--combine-cruft-below-size` option to `git-repack.adoc`
- Replacing `collapse_small_cruft_packs()` with `combine_small_cruft_packs()` in builtin/repack.c, which selectively combines packs below the threshold while retaining larger ones
- Modifying `write_cruft_pack()` to accept the new size parameter
- Updating the test suite to verify the new behavior, including a renamed test case that demonstrates combining packs below 1MB while preserving larger ones

The implementation differs from the old `--max-cruft-size` behavior by aggregating all small packs rather than building up to the threshold incrementally. This means the resulting pack may exceed the threshold size (e.g., combining five 99MB packs with a 100MB threshold), but the goal is to avoid repacking already-large cruft packs rather than strictly limiting size.

The patch resolves the previously failing test from patch 4 by completing the transition to the new semantics. It maintains the series' attention to test coverage and documentation while delivering the promised combination behavior. The change appears well-considered, with clear commit message explanation of the rationale behind the design choice to allow combined packs to exceed the threshold size.
