This is part of the build system improvement series addressing unreachable code detection warnings. The patch introduces a new `NOT_CONSTANT` macro to handle compiler optimizations that might incorrectly mark valid code as unreachable when using `-Wunreachable-code`.

Junio Hamano proposes a general solution to replace the previous platform-specific workaround for `sigfillset()` in `run-command.c`. The new approach uses a clever trick with an external variable (`false_but_the_compiler_does_not_know_it_`) to prevent over-eager compiler optimizations while maintaining POSIX compliance. The macro is designed to be self-documenting and reusable for similar cases that might arise elsewhere in the codebase.

The change affects multiple build systems (Makefile and Meson) and includes a new compilation unit for the helper variable. The implementation is clean and well-explained, with the commit message providing good context about the solution's motivation and potential future compiler behavior. This appears to be a thoughtful architectural improvement over the previous ad-hoc solution.
