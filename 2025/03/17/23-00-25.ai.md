This is the fourth patch in a series improving cruft pack handling in `git repack`, focusing on transitioning the `--max-cruft-size` behavior before introducing a new `--combine-cruft-below-size` option in the next patch.

The patch changes `--max-cruft-size` to act as a cruft-specific override for `--max-pack-size` rather than its previous behavior of trying to combine packs below a threshold. The old behavior was problematic because it would split packs just below the threshold (e.g., creating 199MB + 1MB packs from 200MB input), leading to repeated repacking of the same objects. The new implementation makes `collapse_small_cruft_packs()` simply mark all cruft packs for repacking when `--max-cruft-size` is used, deferring the smarter combination logic to the upcoming new flag.

Key technical details:
- Modifies `builtin/repack.c` to simplify `collapse_small_cruft_packs()`
- Updates documentation to clarify `--max-cruft-size` now inherits `--max-pack-size` behavior
- Adds a new test in t5329 verifying cruft pack splitting with size limits
- Marks an existing test in t7704 as failing since it expected the old behavior
- Explicitly notes this is a breaking change but justified by fixing misleading behavior

The change prepares for patch 5's introduction of `--combine-cruft-below-size` by clearing away the problematic old implementation first. The test changes maintain coverage while aligning with the new semantics, though one test is temporarily marked as failing until the new flag is introduced.
