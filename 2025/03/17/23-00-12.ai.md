This is a cover letter for a series introducing a new `--combine-cruft-below-size` option for `git repack`, part of an ongoing effort to improve cruft pack handling. The series aims to replace the confusing behavior of `--max-cruft-size` with clearer semantics.

The key changes are:
1. `--max-cruft-size` becomes a cruft-specific override of `--max-pack-size`
2. The new `--combine-cruft-below-size` controls when small cruft packs should be combined (with the output pack possibly exceeding this size)

The author acknowledges this breaks backward compatibility but argues the old behavior was sufficiently problematic to justify the change. The series structure is notable - first cleaning up tests (patches 1-3), then modifying `--max-cruft-size` while keeping some old infrastructure (patch 4), before introducing the new behavior cleanly in patch 5.

Technical details include:
- Modifications to `builtin/repack.c` for the new flag logic
- Significant test file reorganization (moving cruft pack tests between t5329 and t7704)
- Documentation updates in `git-repack.adoc`
- Builds on previous work in tb/multi-cruft-pack-refresh-fix

Potential points of discussion:
- The backward compatibility break
- Whether the staged approach (keeping some old code temporarily) is preferable to a more direct implementation
- The exact semantics of when packs should/shouldn't be combined under the new flag
