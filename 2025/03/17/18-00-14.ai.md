This is the final patch in the build system improvement series for unreachable code detection, specifically addressing compiler optimizations that trigger false positives with `-Wunreachable-code`. The patch introduces a systematic solution to prevent over-eager compiler optimizations while maintaining POSIX compliance.

The key technical contribution is the `NOT_A_CONST` macro, which works by referencing an externally-defined variable (`false_but_the_compiler_does_not_know_it_`) to prevent compilers from optimizing away expressions they incorrectly deem constant. The implementation includes a new compilation unit (`fbtcdnki.o`) to house this mechanism, replacing the earlier platform-specific workaround in `run-command.c` that used `errno` checking.

Jeff King provides feedback on the naming (suggesting `NOT_A_CONSTANT` might be clearer) and the compilation unit name (proposing alternatives like `not-constant.c`). He also notes a typo in the comment ("sitfillset") but overall approves of the approach, particularly appreciating how it makes the intent clearer than the previous workaround.

This patch represents the culmination of the build warning solution's evolution - from initial warning enablement through platform-specific fixes to this final architectural approach. The solution is cross-build-system compatible (working with both Makefile and Meson) and generalizes beyond the specific macOS `sigfillset()` case that originally motivated it.
