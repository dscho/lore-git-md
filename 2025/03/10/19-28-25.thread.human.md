This thread has reached consensus on implementing NUL`-delimited output for `git rev-list`, with the design evolving through three versions. Justin Tobler's series, guided by Patrick Steinhardt, adds comprehensive support for machine-readable output using NUL` delimiters across all modes (stdin, objects, missing, and boundary cases). The implementation is technically complete with thorough test coverage.

The final design question - whether to use combined or separate options for controlling input/output delimiters - has been resolved in favor of Junio Hamano's preference for explicit `--nul-delimited-input` and `--nul-delimited-output` flags. Justin agrees this better aligns with Git's plumbing command philosophy of keeping independent features orthogonal. He'll modify the series to make `-z` affect only output (matching `git log`) and defer input handling to a future change.

Jeff King had supported a combined `-z` approach for convenience but isn't strongly opposed to the separate options. Christian Couder identified a minor test assertion issue that needs fixing. The only remaining work is this test fix and the final option syntax adjustment before the series can be merged. Justin also notes an opportunity to standardize Git's delimiter option naming more broadly, though that would be a separate effort.
