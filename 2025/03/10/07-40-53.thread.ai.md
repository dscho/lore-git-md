Thread summary:

Bugfix addressing a NULL pointer dereference in the promisor-remote subsystem when configured without a URL. The issue occurs in `promisor-remote.c` when `git_config_get_string()` returns NULL for a missing URL, which is then unsafely passed to `strvec_push()`. Christian Couder's fix modifies `promisor_info_vecs()` to push an empty string instead of NULL when no URL is found, preserving the strvec's NULL-terminated array invariant while maintaining backward compatibility with existing promisor remote behavior.

The change includes a new test case in `t5710-promisor-remote-capability.sh` that verifies the fix by creating a client clone with a promisor remote configured without a URL ("clone with 'KnownName' and missing URL in the config"). The test confirms object availability checks continue working correctly in this scenario. Technical modifications include updates to URL handling in the info string generation to properly skip empty URLs. This appears to be part of Christian Couder's ongoing "cc/lop-remote" branch work on promisor-remote functionality. The patch is narrowly focused with appropriate test coverage for the specific edge case being addressed.
