Thread summary:

Bugfix addressing a NULL pointer dereference in the promisor-remote subsystem when configured without a URL, originally identified by Christian Couder. The issue occurs in `promisor-remote.c` when handling missing URLs, where `git_config_get_string()` returns NULL that was unsafely passed to `strvec_push()`. Christian's initial fix modified `promisor_info_vecs()` to push empty strings instead of NULL, maintaining strvec invariants while preserving backward compatibility.

Junio Hamano's review has expanded the discussion to consider deeper design implications. He questions whether strvec_push() itself should enforce non-NULL values via BUG(), examines the semantics of empty URLs in the names strvec (whether to skip, error, or filter them earlier), and notes an apparent inconsistency in the patch's dual checking of urls.v[i] existence and content despite the NULL-to-empty conversion. These points suggest the fix may need refinement in either the strvec API contract or promisor-remote URL handling logic.

Technical details include the test case in `t5710-promisor-remote-capability.sh` verifying object availability with missing URLs, and ongoing work in Christian's "cc/lop-remote" branch. Open questions center on proper error handling patterns (fail-fast vs graceful degradation) and whether the solution should live in the strvec layer (adding NULL checks) or the promisor-remote layer (validating configurations earlier). The discussion has shifted from a simple bugfix to considering broader API design principles for the strvec interface and configuration validation.
