Refactoring patch as part of the path-walk delta compression series.

This is the first patch in a 13-part series introducing path-based delta compression. It extracts the delta eligibility checking logic from `prepare_pack()` into a new `should_attempt_deltas()` helper function. The commit message indicates this is preparatory work for future changes in the series, though it doesn't specify exactly how this function will be reused.

The change is purely mechanical - moving existing logic into a standalone function with identical behavior. The extracted function checks several conditions to determine if delta compression should be attempted for a given object: whether it already has a delta, has valid type information, meets minimum size requirements, isn't marked as no-try-delta, and handles some special cases for preferred base objects.

This appears to be a clean refactoring with no functional changes, following good practice by separating concerns before introducing new functionality. The patch touches only `builtin/pack-objects.c`, modifying the delta selection logic that will be central to the path-walk feature. As the first patch in a larger series, it sets up infrastructure that subsequent patches will build upon.
