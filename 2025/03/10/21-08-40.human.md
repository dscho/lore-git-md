This is a design discussion in the ongoing thread about adding NUL-delimited output to `git rev-list`. Junio Hamano responds to the current patch set with a proposal to unify the output format across different `rev-list` modes into a single, more structured format.

The key suggestion is to use an attribute-based format where each record starts with an object ID followed by NUL-delimited key-value pairs. This would naturally handle all current use cases: plain commit lists would just show `<oid> NUL`, boundary objects would add `boundary=yes`, path information would use `path=<path>`, and missing objects would use `missing=yes` instead of the current leading "?" marker.

Junio's proposal aims to make the output both more consistent and more extensible, while maintaining machine-parsability. The format would implicitly signal record boundaries by the appearance of a new hexadecimal object ID. This builds on but significantly evolves the current implementation's approach of having mode-specific output styles.

The email continues the thread's trend of moving toward a more thoughtful, unified design rather than just bolting on NUL support to existing formats. It suggests the series may need another revision to incorporate these design improvements before being ready for inclusion.
