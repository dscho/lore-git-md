This is a refactoring patch that's part of a series preparing for breaking changes in Git. It introduces a new `WITH_BREAKING_CHANGES` test prerequisite to replace the awkwardly named `WITHOUT_BREAKING_CHANGES` that was added in an earlier commit. The change makes test conditions more readable by avoiding double negatives when checking for breaking changes behavior.

The patch updates several test scripts to use the new prerequisite while keeping the old one around temporarily for compatibility with in-flight topics. The changes are mechanical but important for test hygiene - they don't affect runtime behavior but make the test suite more maintainable as Git prepares for potential breaking changes.

This appears to be well-executed groundwork for the kind of infrastructure needed when Git eventually makes backward-incompatible changes. The patch is part of a larger effort that includes removing deprecated functionality like `git name-rev --stdin`, but this particular change is purely about test infrastructure.
