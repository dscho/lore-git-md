This is a feature patch series introducing a new `--path-walk` option to `git pack-objects` and `git repack`, along with related optimizations and configuration options. The series builds on previous work around the path-walk API and name-hash improvements.

The core feature changes how objects are selected for delta compression by grouping them by path rather than name hash, which can lead to better compression ratios particularly in repositories with many hash collisions (like JavaScript projects with long similar filenames). The implementation includes:
- A new `--path-walk` option for both commands
- `pack.usePathWalk` config to enable it by default
- Threading optimizations for the path-based delta phase
- New `edge_aggressive` mode for shallow clone scenarios
- Performance tests showing improvements in both size and speed for certain repository types

Key technical details include:
- Two-phase delta compression (within path groups first, then cross-group)
- Integration with existing `--name-hash-version=2` feature
- New test cases in t5538 for shallow push scenarios
- Performance metrics showing significant improvements for some repos (e.g. 439MB → 142MB for microsoft/fluentui)
- Known limitation with bitmap features/delta islands

The series appears well-motivated with clear performance data and addresses real-world pain points seen in Microsoft's internal monorepo. The implementation builds on established path-walk APIs and incorporates feedback from previous RFCs. The patch organization follows a logical progression from core functionality to optimizations and edge cases.
