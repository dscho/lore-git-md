Bugfix in the signed commits fast-export/import series. This patch addresses a memory safety issue where the code was improperly modifying memory obtained from `get_commit_buffer()`. The original implementation used a helper function `find_encoding()` that would modify a const buffer by inserting null terminators.

The fix replaces this with `find_commit_header()` from commit.h, which properly handles the buffer without modification by returning both the string and its length. This required some restructuring of the commit parsing logic to maintain correctness while improving readability. The changes include introducing a `commit_buffer_cursor` variable to track parsing position and adjusting the encoding handling to work with length-delimited strings.

This is part of Christian Couder's v6 series reviving Luke Shumaker's work on signed commit support. The patch appears well-considered, maintaining all existing functionality while fixing the memory safety issue. It follows the pattern of other fixes in this series that have already been reviewed and approved by multiple core Git developers.
