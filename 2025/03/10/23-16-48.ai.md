This is a cover letter for a patchset that's part of the Git project's ongoing breaking changes preparation. The series has two main goals: (1) removing the deprecated `--stdin` option from `git name-rev` (which was previously replaced by `--annotate-stdin` in Git 2.40), and (2) improving the infrastructure for handling breaking changes through a new `WITH_BREAKING_CHANGES` compilation knob.

The first patch renames the existing `WITHOUT_BREAKING_CHANGES` prerequisite to avoid confusing double negatives in the codebase. The next two patches modernize the t6120 test script, fixing some test hygiene issues like properly checking exit codes. The final patch actually removes the `--stdin` support from `name-rev`, guarded by the new compilation flag.

The author notes this is being sent during a pre-release freeze primarily to avoid duplicate work, with no intention to push the changes before the final release. The series touches several test scripts and the name-rev implementation, with changes that are mostly internal except for the eventual removal of the deprecated `--stdin` option. The breaking changes infrastructure work suggests this may be part of a longer-term effort to prepare for Git 3.0 compatibility changes.
