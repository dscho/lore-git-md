This thread has been working through the removal of the deprecated `--stdin` option from `git name-rev`, which was replaced by `--annotate-stdin` back in Git 2.40. The work establishes patterns for handling breaking changes in preparation for Git 3.0.

The effort has progressed through two patch series. The first set up core infrastructure including a new `WITH_BREAKING_CHANGES` test prerequisite (replacing the confusing double-negative `WITHOUT_BREAKING_CHANGES`), test modernization, and initial removal of `--stdin` guarded by conditional compilation. Patrick Steinhardt and Junio Hamano provided key feedback on implementation details and removal timelines.

The second series expanded this with improved test infrastructure documentation, better handling of deprecated prerequisites, and more comprehensive modernization of affected test scripts. The latest patch completes the work by fully removing `--stdin` support - both the option itself and its supporting code - while maintaining clear documentation of the change timeline (deprecated in 2.40, removed in 3.0) and thorough test coverage.

The changes demonstrate a careful approach to breaking changes: maintaining backward compatibility during transition periods, providing clear warnings, documenting changes thoroughly, and establishing patterns that can be reused for future deprecations. The work affects multiple test scripts and the name-rev implementation while also delivering general improvements to Git's test infrastructure.
