This thread establishes infrastructure for handling breaking changes, starting with the removal of the deprecated `--stdin` option from `git name-rev` (replaced by `--annotate-stdin` in Git 2.40). The series introduces a new `WITH_BREAKING_CHANGES` test prerequisite to replace the problematic `WITHOUT_BREAKING_CHANGES` flag, updates several test scripts to use the new pattern, and modernizes test hygiene in t6120 by fixing piped command patterns and standardizing grep usage.

Junio Hamano and Patrick Steinhardt have been refining the implementation approach. Patrick suggested both a deprecation timeline (originally proposing removal after Git v2.50) and more comprehensive conditional compilation to isolate the deprecated functionality. Junio initially considered immediately removing the unused prerequisite, but has now agreed with Patrick's technical suggestion to wrap not just the option definition but also the supporting `transform_stdin` variable and its usage in conditional compilation guards. This exchange demonstrates the project carefully balancing cleanup urgency with implementation thoroughness, establishing patterns that will guide future breaking changes. The work affects test infrastructure, name-rev implementation, and documentation, serving as groundwork for Git 3.0 compatibility preparations.
