This is a discussion response in the ongoing "rev-list NUL-delimited output" feature thread. D. Ben Knoble weighs in on Justin Tobler's proposal for a structured attribute-based output format for `git rev-list -z`.

The email focuses on the design question of whether to use ordered fields (current implementation) versus self-describing key-value pairs (proposed alternative) for the NUL-delimited output format. Knoble acknowledges the tradeoffs: key-value pairs provide better self-documentation and parsing robustness at the cost of increased output size, while ordered fields are more compact but require external documentation of field positions.

Key technical considerations mentioned include:
- Machine parsing needs versus human readability
- Impact on network transmission efficiency
- Parser implementation and debugging experience
- The tension between structured metadata and minimal output size

Knoble's position appears cautiously supportive of the key-value approach, noting it would aid parser development while recognizing that machines don't strictly need the human-readable labels. The comment suggests this is a philosophical design choice rather than a technical blocker, positioning it as a potential quality-of-life improvement for consumers of the output.

This response doesn't propose concrete changes to the implementation but contributes to the design discussion by articulating the tradeoffs between the two format approaches. It follows Junio Hamano's earlier suggestion for a more structured output format while acknowledging the original series' simpler approach.
