This is the final patch in a series introducing path-based delta compression, specifically addressing shallow clone compatibility.

The patch series has been adding a new `--path-walk` option to improve delta compression by organizing objects by path rather than just by name. This 13th patch removes an artificial restriction that prevented using `--path-walk` with shallow clones (`--shallow`). The author explains that while there was previously a warning about incompatibility, the real issue was in the path-walk API's handling of uninteresting objects during shallow fetches - a problem that has now been fixed with new tests in t5538-push-shallow.sh.

The change is minimal - just removing the warning and adding a flag to enable "edge aggressive" mode for shallow clones. This mode was introduced in a previous patch in the series to better handle the boundary between interesting and uninteresting objects that's particularly important in shallow clones. The patch shows the series is nearing completion, having addressed one of the last remaining special cases (shallow clones) while maintaining all existing functionality.
