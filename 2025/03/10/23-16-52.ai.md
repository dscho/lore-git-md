This is the final patch in a series preparing for breaking changes in Git 3.0, specifically removing the deprecated `--stdin` option from `git name-rev`. The option was previously hidden from documentation in Git 2.40 in favor of `--annotate-stdin`, and this patch completes its removal when compiled with `WITH_BREAKING_CHANGES`.

The patch makes three key modifications: (1) adds an entry to `BreakingChanges.adoc` documenting the removal, (2) guards the `--stdin` option definition with `#ifndef WITH_BREAKING_CHANGES` in the implementation, and (3) updates the t6120 test script to expect either a deprecation warning (without breaking changes) or an unknown option error (with breaking changes). The test changes demonstrate the dual-mode behavior where the same test verifies either legacy or new behavior based on the compilation flag.

This completes the series' work to establish patterns for handling breaking changes, showing both the test infrastructure (via the `WITH_BREAKING_CHANGES` prerequisite) and actual feature removal in action. The changes are straightforward and follow the patterns established in earlier patches of the series, with clear documentation of the backward compatibility break. The test modifications maintain coverage while properly handling both legacy and new behavior paths.
