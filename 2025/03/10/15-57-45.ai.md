This is a bugfix patch in Christian Couder's v6 series implementing signed commit support in git fast-export/import. The patch addresses a memory safety issue where the code was improperly modifying read-only commit buffer memory obtained from get_commit_buffer().

The key changes are:
1. Replaces the custom find_encoding() function (which modified buffer contents) with commit.h's find_commit_header() that properly handles const buffers by returning a string length rather than inserting null terminators
2. Restructures the commit parsing logic to use a commit_buffer_cursor to track position through the buffer
3. Updates encoding handling to work with length-delimited strings rather than null-terminated ones
4. Fixes related string formatting to use the length information when printing encoding values

The patch maintains all existing functionality while making the code memory-safe. It's part of the final polish for the v6 series, which has already received technical approval from multiple reviewers (Jeff King, Junio Hamano, Eric Sunshine). The change originated from Luke Shumaker's initial work in 2021 and was carried forward by Christian Couder through multiple iterations.

This is a straightforward improvement that eliminates a subtle memory safety violation while keeping the same behavior. The patch fits well with the series' overall focus on robust handling of signed commits and follows the established pattern of using const-correct buffer handling throughout the codebase.
