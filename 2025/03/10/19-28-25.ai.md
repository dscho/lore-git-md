This is a feature proposal introducing NUL-delimited output for `git rev-list`, part of an ongoing effort to improve machine parsing of Git's output. The cover letter describes a 4-patch series that:

1. First performs some preparatory refactoring (patches 1-2) to clean up the code before adding new functionality.
2. Then adds a `-z` option (patch 3) that makes `rev-list` output use NUL bytes as delimiters instead of newlines, which is particularly useful when handling paths containing newlines.
3. Finally extends this to the `--missing` option (patch 4) to consistently handle missing object information in the same NUL-delimited format.

The key motivation is to make machine parsing more robust by avoiding issues with newlines and spaces in paths and metadata values. The current implementation handles these cases with various quoting and truncation schemes that can be problematic for parsers. The new NUL-delimited mode outputs paths and values unmodified, using NUL bytes as unambiguous separators.

The series follows up on a suggestion from Junio Hamano and currently limits the `-z` option to work only with `--objects` and `--missing`, leaving room for future expansion to other options. The author also floats an idea (but doesn't implement) about using a more structured `<token>=<value>` format for all output in NUL-delimited mode, which could provide more flexibility.

The changes touch core revision walking code in `builtin/rev-list.c` and add comprehensive tests covering the new NUL-delimited output format. Documentation updates explain the new option and its behavior. The implementation appears thorough, with clean commit messages and good test coverage for the new functionality.
