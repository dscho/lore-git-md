This is a feature patch in the path-walk optimization series, introducing a new 'edge_aggressive' option for shallow clone scenarios. The patch adds configuration to make the path-walk API's boundary exploration more thorough when dealing with UNINTERESTING commits, matching the behavior of `--objects-edge-aggressive` in the revision API.

The change primarily affects the path-walk internals, adding a new flag that gets passed through to the revision walk's edge marking logic. When enabled, this causes trees and blobs reachable from UNINTERESTING tip commits to be marked as UNINTERESTING, which helps avoid sending extra objects during fetches and pushes from shallow clones. The implementation touches the path-walk API documentation, core logic, test helper, and adds a new test case.

- Integration with `mark_edges_uninteresting()` via `edge_hint_aggressive`
