This is a follow-up discussion on the promisor-remote NULL pointer fix. Junio Hamano raises several technical questions about the implementation details of Christian Couder's patch that fixed a segfault when promisor remotes are configured without URLs.

The core discussion revolves around three design-level concerns: First, whether `strvec_push()` itself should have safeguards against NULL values (Hamano suggests it might warrant a BUG assertion). Second, whether empty URLs should be handled earlier in the control flow rather than being passed through the system. Third, Hamano points out an apparent contradiction where the patch ensures URLs won't be NULL but then still checks for NULL in the info string generation code.

These questions suggest the fix might need refinement in its approach to error conditions and API contracts. The exchange indicates this isn't just about fixing a crash, but about establishing clear invariants for how promisor remotes should handle missing or malformed configurations. The thread shows active maintainer engagement with the technical details of the solution, signaling this is being carefully reviewed before potential inclusion.
