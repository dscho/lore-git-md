Refactoring patch in the NUL-delimited rev-list output series.

This is the second patch in Justin Tobler's 4-part series to add NUL-delimited output support to `git rev-list`. It performs preparatory refactoring of the option parsing logic in `builtin/rev-list.c` to clean up how early options like `--missing` and `--exclude-promisor-objects` are handled.

The main change consolidates the previously separate parsing loops for these options into a single pass, making the code more straightforward. It also introduces proper error handling for incompatible option combinations using the existing `die_for_incompatible_opt2()` helper. This refactoring paves the way for cleanly adding the new `-z` option in subsequent patches.

The patch touches only the option parsing logic and doesn't yet introduce any new functionality. It's a focused, mechanical change that follows Git's established patterns for option handling. The diff shows a net reduction in lines while improving the code structure - exactly what you'd want in a preparatory refactoring.

Key technical details:
- Combines two option parsing loops into one
- Uses `parse_missing_action_value()` directly rather than checking its return value
- Adds explicit incompatibility check between `--exclude-promisor-objects` and `--missing`
- Maintains all existing behavior while simplifying the control flow

This change is part of the broader effort to support NUL-delimited output in `rev-list`, but stands alone as a pure refactoring with no behavior changes. The next patch will build on this to add the actual `-z` option support.
