Test modernization patch in the breaking changes infrastructure series.

This is the second patch in a 4-part series (though the thread summary mentions 5 patches, suggesting some reorganization) that's part of the broader effort to establish patterns for handling breaking changes in Git. The patch focuses on improving test hygiene in t6120-describe.sh by fixing instances where Git commands were piped, which hides their exit status.

The changes are straightforward: two tests that previously piped `git rev-list` output directly into `git name-rev` now first write the output to a temporary file, then redirect that file as input. This ensures any failures in `git rev-list` would be caught rather than silently ignored. One test checks the new `--annotate-stdin` behavior, while the other verifies the deprecated `--stdin` option still works (but emits a warning).

The patch is clean and focused, with a clear commit message explaining the motivation. It's a small but important improvement to test reliability, particularly relevant as part of the larger breaking changes infrastructure where robust testing will be crucial. The changes don't affect runtime behavior - they make the tests more thorough about detecting failures.
