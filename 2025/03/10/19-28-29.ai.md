Final patch in a series adding NUL-delimited output support to `git rev-list`, extending the `-z` option to work with `--missing` output. This completes the feature set proposed in the series.

The patch modifies the `--missing={print,print-info}` output format when `-z` is enabled, changing from newline-delimited to NUL-delimited output. Missing objects are printed with a leading "?" followed by the OID, then NUL-separated key-value pairs for path and type information (when using `--missing=print-info`). The implementation handles paths with spaces and special characters by omitting the quoting that would normally be applied in newline-delimited mode.

Key technical changes:
- Adds NUL-delimited output support to `print_missing_object()`
- Uses `print_object_term()` helper from previous patches for consistent termination
- Updates documentation to describe the new output format
- Adds comprehensive test coverage in t6022 including paths with spaces
- Maintains backward compatibility with existing newline-delimited output
- Enforces option compatibility (e.g. still rejects `-z` with `--graph`)

The implementation follows the same pattern established in earlier patches, using double NUL termination for entries and single NULs between components. This matches Git's existing NUL-delimited formats and provides robust parsing for machine consumption. The tests verify correct handling of edge cases like paths containing spaces.

This completes the series' goal of making `rev-list` output reliably parseable by adding NUL-delimited variants for all major output modes. The implementation appears clean and well-tested, building logically on the refactoring done in earlier patches.
