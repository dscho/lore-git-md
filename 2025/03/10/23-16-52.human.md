Feature removal in preparation for Git 3.0, part of the breaking changes infrastructure series.

This final patch in the series removes the deprecated `--stdin` option from `git name-rev`, which was replaced by `--annotate-stdin` back in Git 2.40. The change is guarded by the new `WITH_BREAKING_CHANGES` infrastructure introduced earlier in the series. The patch makes three key changes: documenting the removal in BreakingChanges.adoc, conditionally compiling out the `--stdin` option, and updating the t6120 test to verify the option is rejected when breaking changes are enabled.

The test changes are particularly thorough - they verify both the legacy behavior (where `--stdin` works but warns) and the new behavior (where it fails with an "unknown option" error). The documentation update clearly notes this as a planned change for Git 3.0 while preserving the historical context that `--stdin` was the original name.

As the culmination of the breaking changes infrastructure work, this patch demonstrates the intended workflow: deprecated features are first hidden, then removed behind a flag, with tests that can run in both legacy and new modes. The changes are clean and well-contained, focused specifically on removing this one deprecated option while maintaining all other functionality.
