Feature implementation for `git rev-list` adding NUL-delimited output support. This is patch 3/4 in a series from Justin Tobler and Patrick Steinhardt that builds on earlier refactoring work to make `rev-list` output more robust for machine parsing.

The patch introduces a `-z` option that changes the output format to use NUL bytes as delimiters instead of newlines and spaces. This handles edge cases where paths contain whitespace or newlines, which would otherwise break parsing. The implementation currently works with `--objects` (showing both object hashes and paths) and includes comprehensive tests verifying the new output format.

The change is well-contained, with clear documentation updates and tests that demonstrate both the basic NUL-delimited output and the `--objects` case. The patch explicitly rejects combinations with other options that don't make sense with NUL-delimited output (like graph output or verbose headers), showing thoughtful consideration of edge cases.

This continues the series' clean approach - the earlier refactoring patches laid solid groundwork, and this implementation builds on that with focused, testable changes. The work connects to Git's broader effort to improve machine-readable output formats, following the pattern established by commands like `ls-files -z`.
