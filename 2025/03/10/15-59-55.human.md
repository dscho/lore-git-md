Maintainer follow-up on remote archive segfault investigation.

Junio Hamano responds to Patrick Steinhardt's review of the `git archive --remote=""` segfault fix, agreeing that the current patch may be treating a symptom rather than the root cause. The discussion has shifted from the original simple input validation to deeper architectural questions about error handling in the remote archive code path.

Hamano confirms that if `remote_get()` itself segfaults on empty input, that would be a serious bug needing fixing at that level. More likely, the issue lies in `run_remote_archiver()` which currently doesn't properly handle NULL returns from `remote_get()`. He suggests a more robust architectural solution would be to restructure the code to have `cmd_archive()` handle the remote validation and pass a fully-validated `struct remote` to `run_remote_archiver()`.

This moves the discussion beyond the original simple validation patch toward considering proper error handling throughout the remote archive workflow. The thread now awaits either: (1) confirmation that `remote_get()` itself needs fixing, or (2) a more comprehensive patch restructuring the error handling between these functions.
