This thread addresses a NULL pointer dereference bug in Git's promisor-remote subsystem when configured without a URL, originally identified by Christian Couder. The discussion has progressed through four patch versions (v1-v4), with Jeff King and Junio Hamano providing key review feedback.

The current solution (v4) implements a fix that:
1. Prevents the NULL dereference by falling back to the remote name when no URL is configured, matching standard Git remote behavior
2. Includes comprehensive warnings for URL-related edge cases
3. Adds thorough test coverage
4. Uses safer string handling with `git_config_get_string_tmp()`

Christian Couder has responded to Junio's architectural concerns about whether promisor remotes should follow standard remote conventions. He defends the current approach by describing a valid use case where client, server and promisor remote share a filesystem and could rely on remote names without URLs. The discussion reveals deeper questions about whether promisor remotes might need different behavior than standard remotes, but these are being deferred for future consideration.

Junio has confirmed the core fix is ready for inclusion in Git 2.49.0 while flagging the architectural questions for follow-up. The thread demonstrates how a straightforward bugfix evolved into a thoughtful discussion about API design consistency, with the immediate safety issue resolved but broader design questions noted for future work.
