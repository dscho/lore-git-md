This thread addresses a bug in Git's promisor-remote subsystem where a NULL pointer dereference could occur when a promisor remote is configured without a URL. The issue was discovered when `git_config_get_string()` returned NULL for a missing URL, which was then incorrectly passed to `strvec_push()`.

The fix, contributed by Christian Couder, modifies `promisor-remote.c` to handle missing URL configurations safely by pushing an empty string instead of NULL. This maintains the strvec's NULL-terminated array invariant while preserving the expected behavior. The patch includes a new test case in `t5710-promisor-remote-capability.sh` that verifies the fix by creating a client clone with a promisor remote that has no URL configured, ensuring object availability checks still work correctly.

The change is narrowly scoped to address this specific edge case while maintaining backward compatibility with existing promisor remote behavior. The test coverage appears thorough for the scenario being fixed, and the patch is part of Christian's ongoing work on promisor-remote functionality (referenced as the "cc/lop-remote" branch).
