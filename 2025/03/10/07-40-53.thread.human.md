This thread addresses a NULL pointer dereference bug in the promisor-remote subsystem when configured without a URL, originally reported by Christian Couder. The immediate fix converts NULL URLs to empty strings in `promisor_info_vecs()` while adding configuration warnings, with Christian's v2 patch establishing the core solution. Jeff King (Peff) later noted that regular Git remotes default to using the remote name when no URL is configured, suggesting promisor-remote might benefit from similar behavior.

Junio Hamano has now weighed in, agreeing with Jeff's observation about the remote name fallback pattern while maintaining that the current empty-string approach remains appropriate for the immediate fix. The discussion has cleanly separated the urgent NULL-dereference fix (ready for 2.49.0 with comprehensive test coverage) from broader questions about API design consistency with Git's remote handling.

The thread demonstrates how the project balances immediate stability fixes against longer-term architectural improvements. While all parties recognize the value in making promisor-remote's URL handling more consistent with regular remotes, they've prioritized shipping the safety fix now and deferring behavioral changes for future consideration. Junio's participation confirms the patch's readiness while keeping the door open for follow-up work to align these subsystems.
