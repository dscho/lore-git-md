This thread addresses a NULL pointer dereference bug in Git's promisor-remote subsystem when configured without a URL, originally identified by Christian Couder. The issue occurs when `git_config_get_string()` returns NULL for missing URLs, which was unsafely passed to `strvec_push()`. Christian's v2 patch fixes the crash by converting NULL URLs to empty strings while adding explicit warnings for missing URLs in both client and server configurations.

Junio Hamano has confirmed the patch's direction, emphasizing that the core issue is configuration validation rather than NULL handling semantics. The fix maintains backward compatibility while improving diagnostics, with comprehensive test coverage for edge cases. The discussion cleanly separated the immediate bugfix (ready for 2.49.0) from broader API design questions about strvec handling.

In the latest development, Junio pointed out a test-lint violation in the patch's test script - a minor style issue where `GIT_NO_LAZY_FETCH=0` needed proper `env` wrapping. Christian has addressed this final polish, moving the environment variable into the preferred format. With this last stylistic correction to `t/t5710-promisor-remote-capability.sh`, the patch appears ready for merging, having resolved both the critical NULL dereference and all review feedback.
