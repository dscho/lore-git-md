This thread addresses a NULL pointer dereference in the promisor-remote subsystem when configured without a URL, originally identified by Christian Couder. The issue occurs when `git_config_get_string()` returns NULL that was unsafely passed to `strvec_push()`. Christian's v2 patch converts NULL URLs to empty strings while adding explicit warnings for missing URLs, with comprehensive test coverage for both client and server configurations.

Junio Hamano had previously confirmed the patch's direction, emphasizing that configuration validation is the root concern rather than NULL vs empty string semantics. The patch was considered ready for 2.49.0 after addressing a minor test-lint issue.

Jeff King (Peff) has now contributed additional perspective, noting that regular Git remotes default to using the remote name when no URL is configured. While agreeing with the current approach, he suggests this behavior could be mirrored in promisor-remote for consistency. The discussion explores alternative implementations using `xstrdup_or_null()` and `git_config_get_string_tmp()`, but maintains consensus that broader API changes should remain deferred.

The thread shows clear technical resolution on the immediate crash fix while thoughtfully considering edge cases and consistency with Git's conventions. With Junio's prior approval and Peff's constructive feedback incorporated, the patch appears well-vetted and ready for merging in its current form, maintaining the project's standards for both safety and configuration validation.
