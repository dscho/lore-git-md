This is a follow-up in the build system improvement thread regarding unreachable code detection. The discussion has taken an unexpected turn with platform-specific complications.

Junio C Hamano responds to Jeff King's discovery that the newly enabled `-Wunreachable-code` warning causes OSX CI builds to fail due to `sigfillset()` in `run-command.c`. The compiler can statically determine this POSIX function never fails on OSX, making the error handling code unreachable. 

Hamano expresses frustration with the situation, comparing it to other problematic warnings. He acknowledges Jeff's proposed workaround involving checking `errno` instead of the return value, but finds it overly subtle. The maintainer seems to be leaning toward accepting that some warnings may not be worth the maintenance burden they create, suggesting increased vigilance as an alternative solution.

The email reveals a tension between code quality enforcement through compiler warnings and practical maintenance concerns, particularly when dealing with platform-specific behavior. This builds on earlier discussion about GCC/Clang differences in implementing the warning, now extending to platform-specific system call behavior. The thread remains unresolved how to balance warning cleanliness with POSIX compliance and cross-platform compatibility.
