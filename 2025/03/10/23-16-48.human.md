This is a cover letter for a series preparing to drop deprecated functionality, part of Git's ongoing breaking changes cleanup effort.

Junio Hamano is sending a 4-part series that removes support for the deprecated `--stdin` option in `git name-rev`, which was replaced by `--annotate-stdin` back in Git 2.40. The real motivation appears to be improving the infrastructure for handling breaking changes, particularly by renaming the awkward `WITHOUT_BREAKING_CHANGES` prerequisite to `WITH_BREAKING_CHANGES` and updating test scripts to use it.

The series starts with infrastructure changes (renaming the prerequisite and modernizing tests in t6120) before finally removing the `--stdin` option guarded by the new `WITH_BREAKING_CHANGES` flag. Junio notes this is being sent during the pre-release freeze primarily to avoid duplicate work, with no intention to push it before the final release.

The changes are straightforward - updating tests and removing deprecated code - but the more interesting aspect is the infrastructure work to better handle breaking changes going forward. The patch series looks clean and well-motivated, though it's clearly marked as preparatory work for Git 3.0 rather than something urgent.
