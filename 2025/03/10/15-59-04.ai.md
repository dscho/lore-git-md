This is a follow-up discussion in the signed-commits feature series, clarifying the long-term vision beyond the current implementation. Christian Couder responds to Junio Hamano and Elijah Newren's exchange about the scope of the feature, explaining that while the current series only handles existing signatures (with abort/verbatim/strip modes), the ultimate goal is to enable re-signing commits during import/export operations.

The key technical context is that this v5-v6 series implements memory-safe handling of existing signatures through shared `sign_mode` infrastructure, proper memory management, and comprehensive test coverage - all of which serve as foundation for future work. Christian explicitly adds a "Big picture goal" section to the cover letter to document this roadmap, making clear that the current work is prerequisite for the more ambitious re-signing capability that would allow filter operations to attest to transformed content.

The discussion reveals an important architectural consideration: the current series deliberately avoids the complexity of re-signing (which would involve key management and cryptographic operations) to first establish robust signature preservation mechanics. This positions the work as phase 1 of a multi-phase effort, with all review feedback on the core implementation now addressed and the series ready for inclusion.
