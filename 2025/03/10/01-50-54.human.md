This is part 12/13 of the path-walk optimization series, introducing a new 'edge_aggressive' option for the path-walk API. The patch adds functionality to more thoroughly walk boundary commits when marking uninteresting objects, particularly useful for shallow clone scenarios where we want to minimize transferred objects.

The change adds a new flag that mirrors the existing `--objects-edge-aggressive` behavior from the revision API, ensuring trees and blobs reachable from UNINTERESTING commits are properly marked. This helps avoid sending extra objects during fetches and pushes when both `--shallow` and `--path-walk` options are used together in `git-objects`.

The implementation includes documentation updates, test coverage, and integration with the test helper tool. The test case demonstrates the new behavior by showing how it affects object marking in a simple repository scenario. This appears to be a well-contained addition to the larger path-walk optimization effort, with clear motivation and thorough testing.
