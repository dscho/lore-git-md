This is a status update regarding a bugfix for cruft pack handling. Taylor Blau responds to Junio Hamano's "What's cooking" thread about a pending fix for objects not being properly refreshed in repositories with multiple cruft packs. While the original fix was ready for merging into 'next', Taylor requests a hold because they've discovered an additional issue with how `--max-pack-size` interacts with `--cruft` in `pack-objects`. The new issue appears related enough that it would be cleaner to address it within the existing series rather than as a follow-up patch.

The original fix was already addressing a subtle edge case in Git's garbage collection mechanism where certain objects in multiple cruft packs weren't getting their timestamps refreshed properly. Now Taylor has found another edge case involving size-limited cruft packs that needs to be solved first. This suggests the cruft pack implementation has some non-obvious interactions that need careful handling. The patch appears to be in good hands with Taylor, who is known for their work on Git's packfile and object storage systems.
