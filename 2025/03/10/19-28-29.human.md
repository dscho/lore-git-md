Feature completion for NUL-delimited `rev-list` output. This is the final patch in Justin Tobler's series (4/4) implementing NUL-delimited output support for `git rev-list`, building on Patrick Steinhardt's earlier work. The patch extends the `-z` option to work with `--missing=print` and `--missing=print-info`, providing machine-readable output for missing objects during revision walks.

The implementation handles paths with spaces and special characters cleanly by omitting quoting/escaping in NUL-delimited mode, using double NUL terminators between entries. The patch includes thorough documentation updates and a new test case verifying the behavior with paths containing spaces. This completes the series' goal of making `rev-list` output reliably parseable, particularly for scripts processing repository content with complex filenames.

The changes are well-contained, touching only the expected areas (documentation, core implementation, and tests). The test case follows the established pattern from earlier in the series while exercising the new `--missing` functionality. This appears ready for inclusion, rounding out a cleanly executed feature addition that addresses a real pain point in machine parsing of Git output.
