This is a feature proposal introducing NUL-delimited output for `git rev-list`, part of an ongoing effort to improve machine parsing of Git's object listing. The series adds a `-z` option that replaces LF delimiters with NUL bytes, making output more robust when handling paths or metadata containing newlines.

The cover letter explains that current `rev-list` output can truncate paths containing newlines, and that missing-object metadata uses custom encoding schemes. The proposed `-z` mode uses consistent NUL delimiters (double NUL between objects, single NUL fields) while preserving raw path and metadata content. Initial support focuses on `--objects` and `--missing` options, with other options explicitly rejected for now to allow incremental adoption.

The implementation looks well-structured across four patches: two preparatory refactors, then core NUL-delimited output support, followed by `--missing` option integration. Test coverage appears thorough with new cases in t6000 and t6022. The author floats an unimplmented idea about standardizing on `<key>=<value>` format for all metadata in NUL mode, inviting discussion.

This seems like a thoughtful, incremental improvement to Git's plumbing interface. The change is backward-compatible and clearly motivated by real parsing pain points. The limited initial scope and clean patch division suggest it would be straightforward to review and maintain.
