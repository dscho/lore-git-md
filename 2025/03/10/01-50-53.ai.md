Performance optimization in the path-walk delta compression series. This patch (11/13) adds threading to the path-based compression phase in `git pack-objects`, completing a key optimization promised in the series.

The implementation:
- Adds `regions` to `thread_params` struct for path-based work distribution
- Creates `threaded_find_deltas_by_path()` worker function
- Implements work-stealing between threads for load balancing
- Maintains progress reporting during threaded operation
- Preserves the two-phase compression approach (intra-path then cross-path)

Performance impact is significant:
- Git repo repack time drops from 142.50s to 45.41s (~60% improvement)
- Similar gains seen across test repositories (FluentUI, Node.js, Linux kernel)
- Pack sizes remain identical to unthreaded version
- Makes path-walk more competitive with name-hash-v2 timing while maintaining compression benefits

The patch modifies `builtin/pack-objects.c` with thread management logic while reusing the existing delta finding infrastructure. It includes careful synchronization around progress reporting and work distribution. The implementation shows path-walk can achieve its compression benefits with reasonable runtime overhead when threaded, addressing one of the main remaining performance concerns in the series.
