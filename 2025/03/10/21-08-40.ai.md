This is a design discussion email in the ongoing thread about adding NUL-delimited output to `git rev-list`. Junio Hamano proposes a unified attribute-based format that would cover all three major output modes (basic commit listing, `--objects`, and `--missing`) with a single consistent structure.

The key proposal suggests using `<oid> NUL [<attr>=<value> NUL]...` as a universal format where:
1. Records are implicitly delimited by the next OID
2. Basic commit lists would just show `<oid> NUL`
3. Boundary commits would add `boundary=yes`
4. Object paths would use `path=<path>`
5. Missing objects would use `missing=yes` instead of the current leading "?"

This builds on earlier discussions about simplifying the delimiter handling (moving from double-NUL to single-NUL) while also addressing the format unification that Junio had previously suggested. The proposal maintains machine-parseability while making the output more structured and extensible. The email doesn't include implementation details but focuses on the conceptual design, suggesting this could be a natural evolution from the current patch series' approach.
