Refactoring patch in a series adding NUL-delimited output to `git rev-list`. This is the second of four patches, following preparatory work in patch 1/4.

The change reorganizes how `rev-list` handles early option parsing for `--missing` and `--exclude-promisor-objects`. Instead of scanning the arguments twice (once for each option), it now processes both in a single pass. The patch also introduces a more robust error check for incompatible options using `die_for_incompatible_opt2()`, which provides better error messages when users try to combine these mutually exclusive options.

The refactoring appears clean and focused, with no behavior changes beyond the improved error handling. This groundwork will be used in subsequent patches to support the new `-z` option for NUL-delimited output. The change is small (17 lines modified) and well-contained to `builtin/rev-list.c`.
