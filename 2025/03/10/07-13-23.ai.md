This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` global variable usage, specifically targeting the "core.bigFileThreshold" configuration setting. The patch moves this setting from a static global variable into `struct repo_settings`, making it repository-specific and properly cached.

The change affects 15 files, with most modifications being mechanical replacements of `big_file_threshold` with `repo_settings_get_big_file_threshold(the_repository)`. Key technical points include:
- Removes the global `big_file_threshold` variable from environment.c/h
- Adds new getter/setter functions in repo-settings.c/h
- Implements lazy loading of the config value when first accessed
- Updates all callers to use the repository-specific version
- Modifies t1050 test to use `git hash-object` instead of `rev-parse` since the latter doesn't trigger config parsing

The patch maintains backward compatibility while enabling proper multi-repository operation. It follows the established pattern seen in other parts of this series for migrating global config values to repository-specific storage. The test change demonstrates careful consideration of the new behavior while maintaining coverage of the error case.
