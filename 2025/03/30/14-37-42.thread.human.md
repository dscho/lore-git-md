Here's a human-readable summary of the thread so far:

Alexander Shpilkin raised a limitation in Git's stash functionality that affects build system integration. The core issue is that there's currently no way to create a stash object that includes untracked files without modifying the working tree - a requirement for build systems that need to snapshot state before each build. The existing `git stash create` command excludes untracked files, while `git stash push --include-untracked` modifies the working tree, neither of which works for this use case.

Patrick Steinhardt has confirmed Alexander's technical analysis of the problem in `builtin/stash.c`, where the `do_create_stash()` function either skips untracked files or requires working tree changes. The key obstacle is that the current implementation modifies the repository's index when saving untracked files. Patrick suggests the solution would involve modifying the code to work with an in-memory index instead, which would enable proper support for including untracked files without touching the working tree. While he won't be implementing this himself, he indicates that patches following this approach would likely be accepted. The thread remains open for further discussion or implementation proposals.
