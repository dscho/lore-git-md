This thread discusses extending Git's stash functionality to better support build system integration. Alexander Shpilkin is working on a use case where they need to snapshot the working tree state (including untracked files) before each `make` invocation, without actually modifying the working tree as a regular `git stash push` would.

The core limitation is that while `git stash create` can generate a stash object without touching the working tree, it doesn't support including untracked files. The internal `do_create_stash()` function in `builtin/stash.c` could theoretically handle untracked files, but its current callers either hardcode `include_untracked=0` or would perform a working tree modification. The author has explored the implementation and is seeking suggestions for how to achieve this snapshot capability, either through existing commands or potential modifications to Git's stash implementation.

This appears to be a legitimate gap in Git's functionality for use cases that need to capture working tree state (including untracked files) in a way that preserves build system properties like file modification times. The discussion is currently at the problem-definition stage, with no solutions or patches proposed yet.
