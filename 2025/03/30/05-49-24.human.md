Bugfix for `--left-only`/`--right-only` behavior with unrelated histories.

Matt Hunter fixes an edge case in the revision walker where `--left-only` and `--right-only` options would not work correctly when comparing two unrelated commit histories (those without a common merge base). The issue stems from the code relying on boundary commits being marked UNINTERESTING, which doesn't happen in this scenario.

The patch follows the pattern established by a previous fix for `--cherry-pick` (commit 023756f4eb), explicitly setting `revs->limited = 1` when these options are used. This ensures the limiting behavior works even without boundary commits. The change is small (just two lines in revision.c) but comes with a new test case that verifies the fix by creating two unrelated branches and checking the symmetric difference output.

The patch appears well-constructed - it references prior art, includes a clear explanation of the problem, and adds a test that would have caught the issue. It's currently targeting the maint branch (v2.49.0) but has been verified to apply cleanly to 'seen' as well.
