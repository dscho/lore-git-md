Bugfix follow-up addressing Windows compatibility in test verification. Johannes Sixt points out that the test case added in the previous patch uses Bash process substitution (`<(command)`) which doesn't work on Windows. The suggested fix is to use temporary files instead for cross-platform compatibility. This is a common issue when writing portable Git tests - Windows lacks the `/dev/fd` mechanism that enables process substitution. The comment is brief but clearly identifies the platform-specific problem in an otherwise correct test case. The original bugfix for `--left-only`/`--right-only` behavior remains unaffected; this is purely about making the verification test work across all platforms. The test's core logic of comparing sorted commit lists remains the same, just the implementation needs adjustment to be portable.
