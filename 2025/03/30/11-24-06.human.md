Bugfix for `--left-only`/`--right-only` behavior with unrelated commit histories. This is the second version of a patch that fixes an edge case in the revision walker when comparing branches with no common ancestor.

The core fix mirrors a previous solution for `--cherry-pick` (commit 023756f4eb) by setting `revs->limited = 1` when either `--left-only` or `--right-only` is specified. This ensures proper behavior when comparing unrelated histories where no boundary commit exists to trigger the limiting logic.

1. Using temporary files for sorted output rather than process substitution (better Windows compatibility)
2. Explicitly checking for zero common commits between the outputs using `test_line_count`
3. Following Phillip Wood's earlier suggestion about test methodology
