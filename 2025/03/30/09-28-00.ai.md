Bugfix and test improvement for `git blame` porcelain output. This email from Phillip Wood identifies a potential issue with the final implementation of the porcelain output markers for unblamable/ignored lines in `git blame`. 

The thread context shows this is the final polishing stage of a long discussion about how to properly mark ignored/unblamable lines in blame output while maintaining backward compatibility. The current implementation uses `puts()` to emit metadata lines, which automatically adds a newline. Phillip points out this creates redundant newline in the output since the strings already end with newlines. 

He also suggests improving the regression test to use `test_cmp` rather than counting lines with `grep`, which would better catch formatting issues like this. The current test approach could miss the bug since it only counts matching lines without verifying their exact format.

This is a minor but important final quality check on a feature that has undergone extensive review. The core functionality is already agreed upon and implemented - this is about catching last-mile output formatting issues and improving test robustness. The thread shows all major design decisions are settled, with Junio Hamano and other maintainers having signed off on the approach. Phillip's observations would help ensure the final merged version has polished output and more reliable tests.
