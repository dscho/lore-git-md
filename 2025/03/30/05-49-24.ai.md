Bugfix for `--left-only`/`--right-only` behavior with unrelated histories.

This patch addresses an edge case in the revision walker where `--left-only` and `--right-only` options would not work correctly when comparing two unrelated commit histories (those without a common merge base). The issue stems from the code relying on the presence of UNINTERESTING boundary commits, which don't exist in this scenario. The fix mirrors a similar solution applied to `--cherry-pick` in commit 023756f4eb by explicitly setting `revs->limited = 1` when these options are used.

The change is minimal (just two lines in revision.c) but comes with a new test case that verifies the fix works by creating two unrelated histories through a rebase operation and checking that the symmetric difference filtering behaves as expected. The test confirms that no commits appear in both the left and right filtered lists when comparing the histories.
