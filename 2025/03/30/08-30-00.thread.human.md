This thread discusses secure configuration of git-daemon for public read-only servers following the ownership verification changes introduced after CVE-2022-24765. The original poster described challenges with "dubious ownership" errors when trying to serve repositories, having tried both absolute and relative paths with limited success through per-user .gitconfig workarounds.

Konstantin Ryabitsev has now provided an authoritative solution, recommending system-wide configuration via /etc/gitconfig to mark all repositories under /srv/git/ as safe directories using wildcard patterns. This approach maintains the security protections while eliminating the need for per-user configuration or the potentially risky practice of marking the current directory (.) as safe.

While this addresses the immediate configuration challenge for typical public server setups, some open questions remain about edge cases in path resolution within the daemon context that were hinted at earlier in the discussion. The thread has effectively produced a reference implementation for secure git-daemon configuration that balances access needs with the security requirements introduced by the CVE fix.
