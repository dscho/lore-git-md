Feature inquiry from Alexander Shpilkin regarding stash functionality limitations for build system integration, with technical response from Patrick Steinhardt. The core problem is creating stash objects including untracked files without modifying working tree state, needed for build system snapshots before `make` invocations. Current approaches fail: `git stash create` excludes untracked files while `git stash push --include-untracked` alters working tree. Technical analysis confirms `do_create_stash()` in `builtin/stash.c` either operates with `include_untracked=0` or modifies working tree via `save_untracked_files()`, which currently requires index modifications through `git-update-index`. Steinhardt proposes the solution path would involve modifying `save_untracked_files()` to work with an in-memory index instead, enabling clean `--include-untracked` support in `git stash create` while preserving working tree state and mtimes critical for build correctness. While validating the use case, Steinhardt indicates he won't implement this himself but suggests such patches would likely be accepted. The thread remains focused on technical implementation details within `builtin/stash.c`, with no alternative workarounds yet proposed for the immediate need. Key open question remains whether someone will take up the suggested implementation approach to modify the untracked file handling to use in-memory index operations.
