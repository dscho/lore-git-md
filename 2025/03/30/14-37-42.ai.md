This is a feature inquiry about extending stash functionality. The email comes from Alexander Shpilkin who is trying to create a build system integration that records working tree state before each `make` invocation. The current approach using `git stash create` doesn't handle untracked files, while `git stash push --include-untracked` would modify the working tree in undesirable ways for this use case.

The core problem is that there's no way to create a stash object (without modifying the working tree) that includes untracked files. The author has looked at the stash implementation and found that the internal `do_create_stash()` function is only called in two places - one that hardcodes `include_untracked=0` and another that would modify the working tree.

This appears to be a legitimate gap in Git's stash functionality for use cases that need to snapshot the working tree (including untracked files) without actually performing a stash operation. The email is asking for suggestions on how to achieve this, either through existing commands or potential modifications to Git's stash implementation.

Key technical details: the current workaround uses `git update-ref` with `git stash create`, but this doesn't handle untracked files. The author has identified `builtin/stash.c` as the relevant implementation file, specifically the `do_create_stash()` function and its callers. The concern about mtimes suggests this is for a build system where file timestamps matter for incremental builds.
