This is a bugfix patch for `git blame`'s porcelain output mode, addressing the final issues in a long-running thread about properly marking ignored/unblamable lines. The patch represents version 4 of the solution, incorporating all previous feedback.

The fix adds porcelain output markers ("ignored"/"unblamable") for lines affected by `--ignore-rev` when using `--porcelain` or `--line-porcelain` modes, matching the existing non-porcelain behavior that uses '?' and '*' prefixes. The implementation adds a new `emit_porcelain_per_line_details()` function in `builtin/blame.c` to handle these per-line markers separately from the existing per-commit porcelain output.

Key technical changes in v4:
- Removes duplicate newlines from `puts()` calls (strings already contain newlines)
- Strengthens tests to use `test_cmp` for full output verification rather than line counting
- Updates documentation to clarify porcelain output behavior
- Maintains backward compatibility while extending the format

The thread history shows this has undergone extensive review, with input from multiple contributors (Patrick Steinhardt, Toon Claes, Eric Sunshine, Phillip Wood) and maintainer Junio Hamano. All major design decisions are settled, with this final version addressing the last identified issues around output formatting and test robustness. The changes are focused and well-contained to the porcelain output path, with comprehensive test coverage for both regular and line-porcelain modes.
