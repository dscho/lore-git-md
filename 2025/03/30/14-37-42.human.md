This is a feature inquiry about Git's stash functionality, specifically looking for a way to create stash-like snapshots that include untracked files without modifying the working tree.

Alexander Shpilkin wants to create build system snapshots that preserve both tracked and untracked files, but finds existing stash mechanisms inadequate. The current `git stash create` doesn't support including untracked files, while `git stash push --include-untracked` modifies the working tree in ways that could trigger unnecessary rebuilds.

The email explores the implementation in builtin/stash.c, noting that the internal `do_create_stash()` function could support this use case if exposed differently, but currently its callers either exclude untracked files (in `create_stash()`) or modify the working tree (in `do_push_stash()`). The request appears well-motivated by a concrete workflow need (pre-build state capture) and the analysis shows familiarity with Git's internals.

This seems like a reasonable feature gap that might warrant either a new flag for `git stash create` or perhaps a different command altogether. The email is politely framed as seeking suggestions rather than demanding changes, which should encourage constructive discussion from maintainers.
