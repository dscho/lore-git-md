Refactoring patch in Karthik Nayak's batched reference updates series (v5 4/8). This intermediate step extracts the core reference update preparation logic from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function, which handles all validation and preparation steps for individual reference updates.

The extracted function centralizes:
- Object ID verification (checking for existence and commit type for branches)
- HEAD reference handling (enqueuing log-only updates when HEAD's referent changes)
- Symref processing (including target validation and update splitting)
- Old/new OID validation (matching files backend behavior for compatibility)
- Update queuing logic (skipping no-op updates to avoid unnecessary writes)

The change is purely structural - no behavior modifications are introduced. The refactoring enables future implementation of batched reference updates in the reftable backend by providing a clear boundary for individual update processing. The commit maintains all existing error messages and edge cases (like HEAD/symref handling) while reducing code duplication.

- HEAD update enqueueing logic unchanged
- Object verification checks maintained

- All existing test cases continue passing
