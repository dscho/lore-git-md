Bugfix patch addressing a CodeQL static analysis warning in `cat-file` plumbing. This is the first of four patches in a series fixing potential uninitialized variable warnings found by static analysis.

The change initializes the `size` variable in `cat_one_file()` to 0, where previously it could theoretically remain uninitialized if the object type name was empty. While the author notes this case shouldn't occur in practice (since `do_oid_object_info_extended()` should always populate the type name), the initialization makes the code more obviously correct and easier to reason about. The change is minimal (1 line modified) and defensive in nature, following the pattern seen throughout this series of addressing static analysis warnings even when the problematic paths may not be realistically reachable.

Key technical details for future reference: The patch touches `builtin/cat-file.c`, specifically the `cat_one_file()` function which handles core object inspection plumbing. The variable in question is `unsigned long size` used for object size reporting. The change doesn't affect observable behavior but removes a potential (if unlikely) code path where `size` could be used uninitialized.
