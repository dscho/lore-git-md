This is part 6/8 of Karthik Nayak's v5 series implementing batched reference updates with partial failure support, a feature enhancement for Git's ref subsystem.

The patch introduces core infrastructure for batched reference updates that can tolerate partial failures, addressing a limitation where transactions previously had to be all-or-nothing. The key addition is the `REF_TRANSACTION_ALLOW_FAILURE` flag which, when set, allows individual reference updates to fail (with non-system errors) while letting others proceed. System errors still abort the entire transaction.

The implementation adds tracking for rejected updates via a new `rejection_err` field in `ref_update` and a `ref_transaction_rejections` structure to collect failed updates. It modifies all three ref backends (files, packed, reftable) to handle partial failures appropriately and provides an iterator `ref_transaction_for_each_rejected_update()` for examining failures.

This is a well-structured patch that builds on the previous parts of the series (particularly the strongly-typed error enum introduced earlier). The changes are focused and maintain existing behavior while adding the new capability. The commit message clearly explains both the user-facing benefit (efficient batched updates without all-or-nothing constraints) and the technical implementation.

The patch appears ready for review, with thorough modifications across all relevant backend implementations and clear documentation of the new interfaces. It represents a significant step toward the series' goal of efficient batched reference updates, particularly benefiting the reftable backend where batching provides notable performance advantages.
