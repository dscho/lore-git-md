This is part 6/20 of Patrick Steinhardt's series to eliminate Perl dependencies in Git's test suite. The patch introduces a new `PERL_TEST_HELPERS` prerequisite to distinguish between tests that inherently require Perl (like Gitweb or git-send-email) versus tests that use Perl as a testing aid.

Key technical aspects:
- Creates `PERL_TEST_HELPERS` as distinct from the existing `PERL` prerequisite
- `PERL` indicates Perl-built features are present
- `PERL_TEST_HELPERS` indicates Perl is available for test execution
- Updates 71 test files to use the new prerequisite
- Documents remaining Perl dependencies in commit message (Gitweb, import scripts, git-send-email, Perl bindings, netrc helper)

The change follows the series' pattern of incrementally removing Perl from test infrastructure while maintaining behavior. This patch focuses on properly categorizing tests rather than converting them, setting up future patches to handle the conversions. The commit message clearly explains the distinction between runtime Perl requirements and test-time Perl usage, which will help maintainers understand test dependencies going forward.

This is a well-structured change that fits cleanly into the larger series, with clear motivation and thorough implementation touching all affected test files. The separation of concerns between Perl features and test helpers is particularly thoughtful.
