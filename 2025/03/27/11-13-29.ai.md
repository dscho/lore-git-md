This is a refactoring patch in Karthik Nayak's ongoing series to support batched reference updates with partial failure handling. The patch introduces a strongly-typed `enum ref_transaction_error` to replace preprocessor-defined transaction error codes, improving type safety and making error handling more explicit.

The enum defines seven distinct cases covering common reference transaction failure modes:
- Generic errors
- Name conflicts (A vs A/B)
- Creation of existing refs
- Missing expected refs
- Incorrect old values
- Invalid new values
- Expected symrefs that are regular refs

The change touches all major ref backends (files, packed, reftable) and updates callers like `builtin/fetch.c` to use the new enum. The conversion maintains all existing error messages and edge cases while making the error handling flow more type-safe. 

This refactoring paves the way for the series' main goal of supporting batched reference updates by providing clearer error classification that will be used in subsequent patches to report partial failures. The patch appears thorough, with comprehensive updates across the codebase and no behavior changes beyond the type system improvements.
