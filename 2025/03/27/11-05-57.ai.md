This is the second patch in a two-part bugfix series addressing potential out-of-bounds array accesses found by CodeQL static analysis. The patch focuses on `read-cache.c`'s cache entry name comparison logic.

The change reorders conditions in `ce_write_entry()`'s name comparison loop to perform bounds checking before array access, while explicitly keeping what the author acknowledges is a redundant NUL check. The commit message makes a maintainability argument for retaining the redundant check despite its technical redundancy, stating it reduces cognitive load when reasoning about the code's correctness. This addresses Jeff King's earlier feedback questioning the necessity of the bounds check while maintaining the original CodeQL fix approach.

Key technical details:
- Modifies the loop condition in `ce_write_entry()` to check `common < previous_name->len` before accessing array elements
- Keeps the `ce->name[common]` NUL check despite acknowledging it's redundant with the bounds check
- Argues this pattern (keeping redundant checks) should be followed for similar static analysis findings
- Still addresses the CodeQL `cpp/offset-use-before-range-check` finding
- No test changes as this is considered a defensive improvement

The patch represents an interesting middle ground in the ongoing discussion about how to handle static analysis findings where the original code may be technically safe but could be made more defensive. The author's explicit argument about cognitive load and maintainability provides a concrete rationale beyond just satisfying the static analyzer.
