This is part of Karthik Nayak's v5 series enabling batched reference updates with partial failure support, specifically focusing on refname duplicate detection.

The patch moves duplicate refname checking from individual reference backends (files, packed, reftable) into the generic refs.c layer. It adds a new `refnames` string_list field to the ref_transaction struct to track all references in a transaction, updated automatically via `ref_transaction_add_update()`. This eliminates duplicate tracking code that was previously duplicated across all three backends.

The changes are mechanical but thorough - each backend needed adjustments to work with the centralized tracking:
- Files backend removes its `affected_refnames` handling
- Packed backend drops its custom updates list
- Reftable backend moves its duplicate check before rather than after adding updates

The patch appears well-constructed with clean diffs and maintains all existing functionality while reducing code duplication. It's a clear improvement to the codebase's organization as part of the larger batched updates feature. Since this is v5, the approach has already been vetted through previous rounds of review.
