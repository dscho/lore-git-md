This is a follow-up in the Rust crate packaging series, specifically addressing the Windows symlink compatibility issue in patch 2/5. Josh Steadmon reports that after investigation, Cargo workspaces don't solve the problem of accessing top-level source files from embedded crates. The only recommended approach remains symlinks, which are known to break Windows CI.

The email effectively withdraws the entire series due to this unresolved platform limitation, marking a reversal from earlier discussions where interim solutions were being considered. The thread had previously explored alternatives like source-only builds or separate repositories with leadership showing flexibility, but this final message indicates the technical constraints are currently insurmountable with the chosen approach.

Key technical details referenced include the workspace investigation outcome and the Rust community's recommended symlink pattern for embedded crates (with link to Rust forum discussion). The decision impacts the entire series' viability despite all other aspects (build isolation, parallel compilation, crates.io metadata) being previously resolved. This represents a significant setback for the libgit integration effort via Rust crates.
