This is a follow-up in the Rust crate packaging series, specifically addressing the Windows symlink compatibility issue in patch 2/5. Josh Steadmon reports that after investigating Cargo workspaces as a potential solution (as suggested by Junio Hamano), they don't solve the core problem of accessing top-level source files from embedded crates. The Rust community's recommended approach remains symlinks, which are known to cause Windows CI failures.

With no viable cross-platform solution currently available, Steadmon proposes dropping the entire series for now. This represents a significant pivot from the previous discussion where interim solutions like source-only builds (#1) or separate repositories (#2) were being considered as fallback options. The thread had shown leadership consensus forming around testing the workspace approach first, but these technical limitations appear to block all current paths forward.

The email marks a potential pause in the Rust integration effort, at least for the crate packaging approach, until a Windows-compatible solution emerges. The technical work done in the series (build isolation, parallel compilation, crates.io metadata) remains valid but can't be merged in its current form due to this platform limitation.
