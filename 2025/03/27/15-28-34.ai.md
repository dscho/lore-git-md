This is a follow-up in the reftable library decoupling effort (`ps/reftable-sans-compat-util` series), specifically addressing the Windows-specific memory allocator mismatch issue. The thread context shows this has been a persistent blocker for the series.

The key development is that Johannes Schindelin confirms Patrick Steinhardt's fix for the mimalloc/mscrt.dll allocator mismatch now passes CI testing on Git for Windows. The fix moves mimalloc override declarations from `git-compat-util.h` to `compat/posix.h` to ensure allocator consistency between reftable and Git core. This was the last known technical issue preventing the series from progressing.

Junio Hamano notes this clears the way for a final reroll of the patch series, marking significant progress in the long-term ref backend abstraction work. The successful Windows CI run provides the final verification needed, as the issue only manifested in MinGW builds (not MSVC). This unblocks both the immediate reftable decoupling work and dependent patches like `ps/reftable-windows-unlink-fix`.
