Bugfix addressing a static analysis finding in Git's diff subsystem. This is the first patch in a two-part series (v2) that reorders array bounds checks to satisfy CodeQL's static analyzer, though the maintainer has noted the original code was safe due to sentinel termination.

The change modifies `fill_es_indent_data()` in `diff.c` to check the array bounds before accessing `s[off]` when looking for carriage returns. While the commit message presents this as a general safety improvement, the thread context reveals Junio C Hamano previously argued the original code was safe because strings are NUL-terminated and the specific `off < len - 1` check exists to distinguish CRLF from standalone CRs.

This version maintains the same code change as v1 without addressing the maintainer's feedback about the original safety. The patch appears technically correct but may be solving a non-problem, which could explain why the discussion has focused more on the second patch in the series (which adds explicit justification for a similar change). No tests are included, as this is considered a defensive change.
