This is a refactoring patch that's part of a larger series eliminating comma operator usage in Git's codebase. The change modifies `remote-curl.c` to replace two instances where commas were incorrectly used instead of semicolons in RPC service initialization.

The patch fixes a minor but potentially confusing coding style issue where the comma operator was being used in assignments to `rpc.service_name` for both git-upload-pack and git-receive-pack services. The change makes the code paths more explicit and consistent with standard C practices.

As noted in the thread context, this particular change has already been reviewed and queued by Junio Hamano. The patch is straightforward and uncontroversial, representing one of the simpler changes in a series that has already addressed all technical concerns. The series as a whole aims to improve code clarity by removing potentially confusing comma operator usage across Git's codebase.
