This is the final patch (8/8) in Karthik Nayak's v5 series introducing batched reference updates with partial failure support. The patch adds user-facing functionality to expose the underlying infrastructure built in previous patches.

The patch introduces a new `--batch-updates` flag for `git update-ref --stdin` that allows individual reference updates to fail while still applying the successful ones. This builds on the `REF_TRANSACTION_ALLOW_FAILURE` infrastructure added earlier in the series. Failed updates are reported in a standardized format showing the refname, old/new values, and rejection reason (like "refname conflict" or "incorrect old value"). The flag only works with `--stdin` mode.

Key technical details:
- Adds `print_rejected_refs()` callback to format rejection messages
- Extends `update_refs_stdin()` to handle the new flag
- Updates documentation with the new flag and output format
- Adds extensive test coverage (233 lines) for various failure scenarios:
  - Invalid new OIDs
  - Non-commit OIDs
  - Non-existent refs
  - Dangling symrefs
  - Regular refs vs symref mismatches
  - Incorrect old OIDs
  - Refname conflicts
- Maintains existing behavior for system errors (I/O failures etc) which still abort the entire transaction

The implementation ties together all the infrastructure from earlier patches:
- Uses the `ref_transaction_for_each_rejected_update()` iterator
- Leverages the strongly-typed `enum ref_transaction_error`
- Maintains the centralized refname checking
- Preserves the optimized file/directory conflict detection

This completes the user-facing side of the batched updates feature, providing a way to handle partial failures while maintaining atomicity for critical errors. The comprehensive test suite verifies all the rejection cases work as expected.
