Feature implementation for `git cat-file` batch mode, part of Patrick Steinhardt's series to add object filtering capabilities. This patch introduces the `--filter` option plumbing while deferring actual filter implementation to later patches.

The change wires up the command-line interface for object filtering in `git cat-file`, matching the same `--filter` syntax used by `git rev-list`. Currently all filter types result in an error, as the actual filtering logic will be implemented in subsequent patches. The patch includes documentation updates and comprehensive test coverage for the error cases.

Key technical elements:
- Adds `list_objects_filter_options` to `batch_options` struct
- Implements option parsing via `opt_parse_list_objects_filter`
- Rejects all filter types with appropriate error messages
- Includes memory management for filter cleanup
- Tests cover various filter types (blob:none, blob:limit, object:type, etc.)

The implementation maintains consistency with the broader series' architecture, particularly in its handling of the dual-path execution model (packfile scan vs. bitmap traversal). While this patch doesn't yet deliver performance benefits, it sets up the framework that will enable the significant speedups demonstrated in the series' benchmarks when bitmap support is fully integrated.

This is patch 2/10 in the v2 series, building on the foundation established in the first patch while preparing for the bitmap integration work that follows. The implementation shows careful attention to error handling and documentation, with thorough test coverage for the initial scaffolding phase.
