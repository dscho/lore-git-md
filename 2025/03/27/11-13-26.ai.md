This is part 2/8 in Karthik Nayak's v5 series implementing batched reference updates with partial failure support. The patch moves duplicate refname checking from individual backends (files, packed, reftable) into the generic refs.c layer, centralizing what was previously duplicated logic.

The key changes are:
1. Adds a `refnames` string_list field to `ref_transaction` to track all references in a transaction
2. Automatically populates this list in `ref_transaction_add_update()` (except for REF_LOG_ONLY updates)
3. Removes backend-specific duplicate checking code, having them instead use the centralized list
4. Adjusts the reftable backend to perform its duplicate check *before* adding updates since the generic layer would otherwise make the check always pass
5. Maintains special handling for HEAD and symref updates while using the new centralized mechanism

The change reduces code duplication across backends (114 lines removed vs 51 added) and makes future changes to refname handling easier to implement in one place. This is a clear refactoring improvement that builds on the series' earlier infrastructure work while maintaining all existing behavior. The patch appears well-tested as part of the larger series' comprehensive test coverage.
