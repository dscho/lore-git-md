This is the first patch in a two-part bugfix series addressing potential out-of-bounds array accesses found by CodeQL static analysis. The patch modifies `diff.c`'s `fill_es_indent_data` function to reorder bounds checking before array access when detecting carriage returns in diff output.

The change swaps the order of operations in a condition checking for carriage returns (`\r`), moving the bounds check (`off < len - 1`) before the array access (`s[off]`). While the original code was technically safe due to NUL/LF termination (as noted by Junio Hamano in previous discussion), this makes the defensive programming pattern more explicit.

The patch maintains the same technical approach as v1, without addressing Junio's feedback about the original code's safety. The commit message provides minimal justification, simply stating the general principle of bounds-checking before access rather than engaging with the specific maintainer concerns raised in the thread.

This change is part of a broader discussion about how Git should handle static analysis findings - whether to prioritize strict necessity (removing technically-redundant checks) or maintainability (keeping explicit checks even when invariants exist). The second patch in the series more directly engages with this philosophical question, but this first patch remains unchanged from v1 despite maintainer feedback.
