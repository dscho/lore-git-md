This is a refactoring patch in Karthik Nayak's ongoing series to support batched reference updates with partial failure handling. The patch converts preprocessor-defined transaction error codes into a strongly-typed `enum ref_transaction_error`, improving type safety and making error handling more explicit.

The enum defines seven distinct error cases covering common scenarios like name conflicts, reference existence checks, and value mismatches. The change touches all major ref backends (files, packed, reftable) and updates callers like `builtin/fetch.c` to use the new enum values. While this is primarily a code organization improvement, it also lays groundwork for more comprehensive error handling needed for the upcoming batch update functionality.

The changes appear thorough and mechanically sound, with all existing error cases preserved and only the representation changed.
