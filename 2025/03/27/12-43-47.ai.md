Bugfix patch addressing an uninitialized variable warning in the fsck subsystem, part of a series cleaning up static analysis findings.

This is the second patch in a 4-part series fixing uninitialized variable warnings found by CodeQL static analysis. The change modifies `fsck.c` to initialize the `err` variable to 0 in `fsck_commit()`, where previously it could remain uninitialized when a commit had exactly one author (the variable was only set for 0 or 2+ authors). While the uninitialized path would likely have been harmless in practice (defaulting to 0), the change makes the code's behavior explicitly correct.

The patch follows the series' pattern of defensive initialization for variables flagged by static analysis, though like the other patches, this addresses a theoretical rather than observed issue. The change is minimal (1 line modified) and maintains the existing fsck behavior while making the control flow more obviously correct. The commit message clearly explains both the issue and solution, noting CodeQL as the detection source.
