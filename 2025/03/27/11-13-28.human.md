Refactoring patch for the reftable backend's transaction preparation. This is part of Karthik Nayak's v5 series implementing batched reference updates with partial failure support.

The patch extracts the core logic for individual reference updates from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function. This handles all validation and preparation steps for each reference update, including object ID checks, HEAD reference handling, and symref processing. The change is purely organizational - no behavior is altered - but it improves code maintainability and sets up for future batched update support in the reftable backend.

The refactoring moves 237 lines into the new function while removing 226 lines from the original, making the transaction preparation logic more modular. Key validations preserved include:
- Object existence checks for new ref values
- HEAD/symref update coordination
- Old/new OID verification
- Symref target validation

This continues the series' trend of careful refactoring to support the batched update feature while maintaining existing behavior. The patch appears well-structured and focused, with clear commit message explaining the motivation.
