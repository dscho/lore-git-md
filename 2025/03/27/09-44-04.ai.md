This is a refactoring patch in Patrick Steinhardt's series enhancing `git cat-file` batch mode filtering. It prepares for bitmap integration by consolidating object iteration logic.

The patch extracts common object iteration patterns from `builtin/cat-file.c` into a new `batch_each_object()` helper function. Currently this just wraps two existing calls (`for_each_loose_object` and `for_each_packed_object`), but the commit message notes this is groundwork for upcoming bitmap integration in the next patch. The refactoring:
- Introduces a new `for_each_object_fn` callback type
- Creates a `for_each_object_payload` struct to pass through callback data
- Replaces four specialized functions (`collect_loose_object`, `collect_packed_object`, `batch_unordered_loose`, `batch_unordered_packed`) with two more generic ones (`batch_one_object_loose`, `batch_one_object_packed`)
- Updates two call sites to use the new unified interface

The changes are mechanical and maintain existing behavior while making the codebase more amenable to the bitmap integration coming in the series' next patch. The patch touches only `builtin/cat-file.c` and keeps the same test coverage since it's purely a refactoring with no behavior change.

Key technical elements:
- New `batch_each_object()` helper
- `for_each_object_fn` callback type
- `for_each_object_payload` struct
- Removal of four specialized functions
- Maintains `FOR_EACH_OBJECT_PACK_ORDER` flag handling
- Preserves existing loose/packed object iteration semantics

This appears to be a straightforward preparatory refactoring that follows the series' established pattern of incremental changes to support bitmap filtering. The commit message clearly states the transitional nature of this change, with the real payoff coming in the subsequent commit.
