This is a feature patch introducing batched reference updates with partial failure support, part of Karthik Nayak's v5 series on partially atomic ref updates. The patch builds on previous infrastructure work to enable a new `REF_TRANSACTION_ALLOW_FAILURE` flag that lets reference updates proceed even if some individual operations fail (except for critical system errors).

Key technical components added:
- New `rejection_err` field in `ref_update` to track per-update failure reasons
- `ref_transaction_rejections` struct to efficiently track failed updates
- Backend modifications (files, packed, reftable) to handle partial failures via `ref_transaction_maybe_set_rejected()`
- New iterator `ref_transaction_for_each_rejected_update()` for examining failures
- Preserved behavior for system errors (still abort entire transaction)
- Maintained existing optimization paths while adding failure tracking

The implementation touches all major ref backends with consistent handling, though the reftable backend stands to benefit most from batching efficiency. Error cases are carefully preserved with the same messages as atomic transactions. The patch sets up core infrastructure that will be exposed to users via a new `--batch-updates` flag in a follow-up commit.

This represents a significant behavioral change in ref updates while maintaining backward compatibility. The thorough backend modifications and new iteration capability suggest this will be a stable foundation for the user-facing feature while providing internal APIs for future batched operations.
