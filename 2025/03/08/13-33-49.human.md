Bugfix for reftable error handling, part of a GSoC project to improve error reporting in the reftable subsystem. This is version 2 of a patch that replaces generic -1 error returns in `block_writer_add()` and related functions with specific `REFTABLE_*_ERROR` codes, particularly for block size limit cases.

The patch updates several key reftable components:
- `block.c` now returns `REFTABLE_ENTRY_TOO_BIG_ERROR` when records exceed size limits
- `record.c` propagates error codes through encoding functions rather than converting everything to -1
- Documentation is updated to clarify the error return behavior

The author has addressed previous review feedback by:
- Ensuring callers properly handle the new error codes
- Updating function documentation
- Propagating errors through `->key()` and `->encode()` functions
- Removing an invalid CC from the email list
