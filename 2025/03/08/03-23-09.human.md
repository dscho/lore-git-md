Build system improvement with platform-specific considerations.

Jeff King follows up on his earlier patch to enable `-Wunreachable-code` warnings in developer builds, which had been approved by Junio Hamano. The warning successfully caught an issue in the refs code, but now reveals a new problem in `run-command.c` on macOS CI builds. The compiler detects that `sigfillset()` will never fail on this platform, making the error handling code unreachable.

The core issue stems from POSIX allowing `sigfillset()` to fail, while macOS's implementation appears to be infallible. Jeff proposes two potential fixes: a platform-specific `#ifdef` approach (which he finds ugly) or a more subtle solution checking `errno` directly. Both options have trade-offs between clarity and portability.

This email highlights the challenges of writing portable system-level code while maintaining strict compiler warnings. The discussion shows how Git's quality control process - now enhanced with this new warning - continues to surface subtle platform-specific behaviors that might otherwise go unnoticed. Jeff's thoughtful analysis presents the maintainers with clear choices about how to handle this edge case.
