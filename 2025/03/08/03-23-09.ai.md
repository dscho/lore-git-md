This is a follow-up in the build system improvement discussion regarding enabling `-Wunreachable-code` warnings. Jeff King reports that after fixing the original refs code issue, the OSX CI builds now fail due to the compiler detecting unreachable error handling code in `run-command.c`'s `sigfillset()` check.

The core issue is that on OSX, `sigfillset()` appears to be implemented in a way that the compiler can statically determine will never fail, making the error handling code unreachable. This creates a dilemma - POSIX allows `sigfillset()` to fail, so the check is theoretically correct, but the warning forces either:
1. An ugly platform-specific `#ifdef` to skip the check where unnecessary
2. A subtle workaround checking `errno` directly after the call
3. Disabling the warning for this case

Jeff expresses reservations about all these solutions, particularly the maintenance burden of platform-specific workarounds and the potential for similar surprises with other system calls. The email doesn't propose a specific resolution but lays out the tradeoffs clearly, showing this warning flag may have non-trivial downstream effects beyond its initial motivation of catching the refs transaction issue.
