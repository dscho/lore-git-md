This is a bugfix and feature patch for git-gui that addresses comment handling in commit messages. The change makes git-gui respect the core.commentChar and core.commentString configuration options, which were previously hardcoded to use '#' for comment detection.

The patch modifies two files: git-gui.sh and commit.tcl. In git-gui.sh, it adds configuration handling for comment characters/strings and updates the commit message label to dynamically show which character will be treated as a comment. In commit.tcl, it replaces the hardcoded '#' comment detection with a regex that uses the configured comment string.

Notably, the patch explicitly does not support the "auto" value for commentString, with the author arguing this makes little sense in the GUI context since it wouldn't work with templates or hook output. The implementation follows the label modification approach from a previous commit (b9a43869c9) while avoiding Tcl 8.5 compatibility issues.

The changes appear well-contained and focused, though the author expresses some uncertainty about whether showing the comment character in the UI label is actually helpful versus potentially messy. The patch builds on previous work (1ae85ff6d) that added comment stripping functionality to git-gui.
