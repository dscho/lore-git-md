Documentation patch clarifying the behavior of `core.commentString=auto`. 

The patch improves the documentation of the `core.commentString` configuration option, specifically detailing how the "auto" mode works. The current docs were apparently unclear enough that Oswald Buddenhagen had to read the source code to understand the feature. The new text specifies that "auto" mode selects the first character from a fixed set (#;@!$%^&|:) that doesn't appear at the start of any line in the pre-edit commit message. It also explicitly notes the limitation that this makes it impossible to include comments in either the prepare-commit-msg hook's output or the commit message template.

The author questions in the cover note whether anyone actually uses this feature given its "rather crippling limitations," suggesting they may view it as more of a historical artifact than a useful feature. The patch itself is straightforward documentation improvement with no behavioral changes, touching only the config documentation file. The change is signed off and CC'd to Nguyễn Thái Ngọc Duy, likely the original author or maintainer of this feature.
