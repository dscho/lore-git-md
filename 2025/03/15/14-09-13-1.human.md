Git GUI bugfix: honoring custom comment characters in commit messages

This patch fixes git-gui to properly respect `core.commentChar` and `core.commentString` configurations when processing commit messages. The change builds on a previous commit (1ae85ff6d) that handled comment stripping but didn't account for custom comment markers.

The implementation adds UI feedback by showing which comment character will be discarded (similar to the command line's behavior), though the author expresses some reservations about this being potentially messy. The patch specifically excludes support for the "auto" commentString value, arguing this feature doesn't make sense in the GUI context since it can't handle comments in templates or hook output.

The changes touch both the core git-gui script and commit handling logic, adding configuration handling and updating the comment-stripping regex to use the configured character/string. The author notes they modeled the textfield label behavior after an existing commit (b9a43869c9) while avoiding a Tcl 8.5 compatibility issue.

This appears to be a straightforward improvement that brings git-gui behavior more in line with command-line Git's comment handling capabilities. The implementation looks clean, though the discussion about the UI label addition might warrant some debate about whether it's truly helpful to users.
