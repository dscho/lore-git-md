This thread is about cleaning up obsolete build system compatibility code in Git. The current patch (4/12 in a series) removes the NEEDS_LIBRT build variable and associated linking logic, which was originally needed for older Linux systems where clock_gettime() required linking with librt. The commit message provides thorough historical context, showing this was only needed for glibc versions before 2.17 (released in 2012) and that all major distributions using such old versions have long been end-of-life.

The change removes both the documentation and actual usage of this obsolete variable, including its Linux-specific setting in config.mak.uname. This appears to be a straightforward cleanup with no impact on modern systems. The commit message makes a compelling case for the removal with detailed research including end-of-support dates for various distributions, the oldest being Debian 7 which reached end-of-life in 2018. The series appears to be systematically removing similar obsolete compatibility code, though we haven't seen the cover letter yet to understand the full scope.
