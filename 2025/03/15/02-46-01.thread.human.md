This thread tracks a substantial build system alignment effort (now at v2 with 17 patches) that standardizes behavior between Makefile and meson builds while improving platform compatibility, particularly for Cygwin and Windows. The series originated with cryptographic random number generation (CSPRNG) standardization and has expanded to address various platform-specific quirks.

The latest patch (4/13 in the current grouping) focuses on help format defaults between build systems. Patrick Steinhardt and Ramsay Jones are coordinating to ensure meson builds on Windows default to HTML help output (like Makefile builds) rather than man pages, using meson's host system identification. This follows earlier work that standardized Cygwin's memory reporting, enabled arc4random support, and removed obsolete Linux `NEEDS_LIBRT` requirements.

Key technical accomplishments so far include fixing Cygwin's RAM calculation (handling its unusual `mem_unit` value), expanding `sysinfo()` support, standardizing Linux CSPRNG to `getrandom`, and identifying a meson limitation in handling quoted Windows paths. The series has systematically reduced build system differences while maintaining compatibility across platforms.

One remaining question is how to handle meson's inability to properly escape quotes and backslashes in default editor/pager paths - whether to consider this a blocker or document it as a current limitation. The help format patch continues the pattern of careful platform-specific adjustments while maintaining the series' focus on build system parity.
