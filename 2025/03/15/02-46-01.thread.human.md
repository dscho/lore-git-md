This build system alignment series has evolved into a broader discussion about Cygwin version support policies. The technical work continues to focus on Makefile/meson consistency and platform-specific fixes, but the community is now grappling with how aggressively to prune support for older Cygwin versions.

Junio Hamano has weighed in on the debate between Patrick Steinhardt and Ramsay Jones about dropping pre-v2.x Cygwin support. While acknowledging the maintenance benefits of removing support for untestable older systems, Junio is deferring to Adam Dinwoodie (the Cygwin maintainer) for the final decision. This reflects Git's careful approach to platform support changes - balancing modernization with respect for ecosystem maintainers.

The series itself contains several Cygwin-specific improvements, including better RAM calculation in `git gc`, arc4random enablement, and timing function additions. However, the regex compatibility discussion remains unresolved, particularly around whether to maintain workarounds for Cygwin 1.7 or draw a clean line at v2.x support. Ramsay Jones has prepared a patch for the more aggressive approach, which would simplify several conditional code paths.

Other open questions include meson's path handling limitations and help format targets, but the Cygwin version support question has emerged as the key decision point. The discussion highlights Git's evolving philosophy around platform support - becoming more willing to drop older versions when they create maintenance burdens, but doing so through consensus rather than unilateral action.
