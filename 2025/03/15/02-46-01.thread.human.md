This thread focuses on a build system alignment series (now at v2 with 18 patches) that aims to standardize behavior between Makefile and meson builds while improving platform compatibility, particularly for Cygwin. The core work addresses cryptographic random number generation standardization, platform-specific fixes, and documentation updates.

A recent patch (v2 10/13) from Ramsay Jones and Patrick Steinhardt fixes Cygwin's memory reporting in `git gc` by properly handling the `mem_unit` field difference between platforms (Linux reports in bytes while Cygwin uses 4K pages). The change modifies `total_ram()` to multiply by `mem_unit` when needed, with Patrick suggesting the guard clause might be unnecessary since all systems should properly report this value. This builds on earlier work standardizing Cygwin's `sysinfo()` support and timing functions.

The series has made significant progress on platform-specific issues, including arc4random support for Cygwin, standardizing Linux's CSPRNG to `getrandom`, and addressing meson's path handling limitations. Open questions remain about whether to treat meson's quoted path handling as a blocker, whether to maintain legacy Cygwin 1.7 regex support, and whether to keep 'info'/'pdf' help format targets that were omitted from meson builds due to low usage. The work demonstrates careful attention to cross-platform consistency while thoughtfully evaluating backward compatibility tradeoffs.
