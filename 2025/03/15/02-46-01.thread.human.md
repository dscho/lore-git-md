This thread covers a substantial build system alignment series (now at v3 with 21 patches) focused on standardizing behavior between Makefile and meson builds, particularly around platform-specific configurations. The core work spans cryptographic random number generation (CSPRNG) standardization, Cygwin compatibility improvements, and legacy code removal.

The latest patch finalizes Linux CSPRNG standardization by setting `getrandom` as the preferred method in `config.mak.uname`, completing a cross-platform effort that previously standardized Cygwin to use `arc4random`. Ramsay Jones provided detailed justification for this choice, noting all supported Linux distributions (including RHEL 8) have the necessary glibc support, and Junio Hamano confirmed the technical rationale. This change aligns Makefile behavior with meson's preference for kernel interfaces.

The series has seen significant progress with maintainer alignment - Patrick Steinhardt reviewed v3 favorably and Junio plans to queue the patches. Key accomplishments include Cygwin RAM calculation fixes, timing function standardization, and removal of obsolete NEEDS_LIBRT support. Open questions remain about Cygwin version support boundaries and meson's path handling limitations, but the technical direction is now well-established with successful Linux builds confirmed for both build systems.
