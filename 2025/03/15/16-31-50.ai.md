This is the second patch in a 2-part documentation standardization series, focusing on formatting updates to the git-branch man page. The patch applies new documentation formatting rules to both `Documentation/config/branch.adoc` and `Documentation/git-branch.adoc`.

Key technical changes include:
- Conversion of synopsis to use `[` blocks for automatic formatting
- Standardization of placeholder notation from `<name>` to _<name>_
- Consistent use of backticks for commands, options, and config keys
-d` → ``-d``, `branch.sort` → ``branch.sort``
- Reorganization of option value lists into definition list format
- Normalization of branch naming (`<branchname>` → _<branch-name>_)
- Removal of redundant information while maintaining all technical content
- The changes are purely formatting/rendering improvements with no behavioral impact
- Builds on the completion script fixes from patch 1/2 by ensuring consistent backtick usage
- Affects all branch-related documentation including config options and command usage
- The patch maintains backward compatibility while modernizing the formatting
- Changes are extensive (196 insertions/deletions per file) but focused on presentation
- Follows established documentation standards being applied across Git's manpages

The formatting changes will affect:
- Manpage rendering (italics/formatting of placeholders and commands)
- Potential future documentation parsing (like the completion script in patch 1/2)
- Consistency with other modern Git documentation

No functional changes or compatibility issues are introduced - this is purely a documentation presentation update that complements the technical fix in the first patch of the series.
