Here's a human-readable thread summary:

This thread documents an improvement to Git's configuration documentation, specifically clarifying how `core.commentString=auto` works. The current documentation was apparently unclear enough that Oswald Buddenhagen had to read the source code to understand the feature's behavior. The patch adds precise details about the "auto" mode's operation: it selects the first available comment character from a fixed set (#;@!$%^&|:) that doesn't appear at the start of any line in the pre-edit commit message.

The author notes this feature has "rather crippling limitations" - particularly that it prevents including comments in either the prepare-commit-msg hook's output or the commit message template - and questions whether anyone actually uses it. The change is a straightforward documentation improvement with no code changes, touching only the config documentation file. The patch is signed off and CC'd to Nguyễn Thái Ngọc Duy, likely the original author of this feature.
