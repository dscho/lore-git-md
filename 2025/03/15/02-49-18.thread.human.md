This thread documents platform compatibility considerations for cryptographic random number generation in Git's build system. The discussion focuses on how to configure the preferred CSPRNG method when building with make on Linux systems.

The key point is that while Git supports multiple cryptographically secure pseudorandom number generation backends (with arc4random being the preferred option when available), make builds currently default to /dev/urandom unless manually configured. The patch adds documentation noting that Linux users with glibc 2.36 or newer (found in recent distributions like Debian 12 and Ubuntu 24.04) can explicitly set CSPRNG_METHOD=arc4random in config.mak to use the more secure arc4random_buf() implementation.

This appears to be the final patch in a 12-part series, though the thread lacks the original cover letter context. The change is straightforward - it simply documents an existing configuration option alongside similar notes about other glibc version-dependent features. While the patch might have been more impactful if included in the original CSPRNG implementation series, the documentation addition is uncontroversial and helpful for users building with make on modern Linux systems.
