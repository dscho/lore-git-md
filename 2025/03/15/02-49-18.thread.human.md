This thread examines how Git should configure its cryptographic random number generation across different platforms, focusing on the choice between `arc4random` and `getrandom`. The discussion began with a documentation patch suggesting Linux users use `arc4random`, but technical experts Brian Carlson and Ramsay Jones clarified important platform differences: Cygwin's `arc4random` properly implements ChaCha20 (like OpenBSD), while Linux's version is just a wrapper around `getrandom` with no advantages.

The technical consensus is clear: on Linux, `getrandom` is the better choice since all supported distributions now have glibc 2.25 or newer. The meson build system currently defaults to `arc4random` on Linux, which while not harmful (the performance impact is negligible for Git operations), should be corrected. There's agreement that the Makefile should hardcode `getrandom` as the Linux default.

Looking ahead, participants note that POSIX may standardize `getentropy` in the future, which could become the cross-platform solution. For now, the thread has established authoritative guidance, with Junio C Hamano already incorporating these insights into the documentation. The remaining work involves adjusting the meson build configuration to properly detect and select the appropriate CSPRNG backend.
