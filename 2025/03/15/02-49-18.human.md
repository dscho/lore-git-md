Documentation patch for Linux build configuration regarding CSPRNG methods.

This final patch in a series adds a comment to `config.mak.uname` reminding Linux users to set `CSPRNG_METHOD` in their config if they have glibc 2.36 or newer. The patch explains that while Git defaults to `/dev/urandom` for cryptographic randomness on Linux, newer systems could use the preferred `arc4random` method (available since glibc 2.36) or fall back to `getrandom`/`getentropy` (available since 2.25). 

The change brings the Makefile build system in line with what meson already does automatically - detecting and using the best available CSPRNG method. The note is purely advisory and doesn't change any behavior, just making the option more discoverable for users who might want to override the default. The patch is straightforward and well-explained, though it might have been slightly more helpful to include the exact line users should add to their config.mak rather than just the comment.
