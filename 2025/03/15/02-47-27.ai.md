This is a platform compatibility patch (part 5 of 12) addressing build system behavior for Linux systems with newer glibc versions.

The patch adds a comment to `config.mak.uname` noting that Linux users with glibc 2.38 or newer (like Ubuntu 24.04 and RHEL 10 beta) should override the NO_STRLCPY setting in their config.mak file. This is because these systems now provide the standard strlcpy() function, making Git's compat implementation unnecessary.

The change highlights a divergence between build systems: meson/autoconf will automatically use the system strlcpy() when available, while the make-based build defaults to the compat version unless explicitly configured otherwise. The patch doesn't change any behavior - it just adds documentation to help users make the right choice for their system.

The commit provides historical context about strlcpy() support in Git (added in 2006) and the recent glibc addition (2023). It carefully notes that while some modern distros have the new glibc, others still in support windows don't, so the compat code remains important for those cases.
