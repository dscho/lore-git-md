Documentation patch standardizing git-branch formatting. This is the second patch in a series that began with a fix for shell completion breakage caused by documentation formatting changes.

The patch applies new documentation standards to the git-branch man page, including:
- Converting the synopsis to a proper synopsis block with standardized formatting
- Using _<placeholder>_ syntax for placeholders
- Consistently wrapping commands and options in backticks
- Reformatting configuration option listings with clearer bullet points
- Standardizing branch name references throughout (e.g., <branch-name> instead of mixed forms)

The changes are purely presentational - no content is altered beyond formatting. The patch follows the same style changes made to other documentation that caused the completion script issues fixed in patch 1/2. The formatting brings git-branch in line with current documentation standards while maintaining all existing information.

The changes are extensive (196 lines added/removed across two files) but focused entirely on documentation presentation. The patch appears well-executed and consistent with Git's ongoing documentation standardization efforts.
