This thread continues the discussion of a 12-patch series optimizing Git's meson build configuration to avoid redundant compiler definitions, currently focused on patch 3/12 which handles DEFAULT_* variables (editor, help format, pager). The original approach proposed conditionally including compiler definitions when meson options differ from built-in defaults ('vi', 'man', 'less'), but Patrick Steinhardt raised concerns about hardcoding assumptions. Ramsay Jones defended the approach as aligning with the intent to allow platform-specific overrides while keeping defaults in code, particularly noting implications for Windows' HTML help format and documentation generation.

In the latest exchange, Patrick has proposed alternative solutions that would simplify the configuration while maintaining the same goals. He suggests using empty string defaults in meson_options.txt, allowing the code's defaults to take effect naturally, and offers two approaches for handling the Windows-specific DEFAULT_HELP_FORMAT case. The discussion has revealed subtle differences in how make and meson handle documentation generation, particularly around passing non-default values to asciidoc - a behavior Ramsay notes will be addressed in future patches. Both contributors are exploring ways to reduce redundant definitions while preserving the ability to override defaults, with Patrick's suggestions potentially offering a more maintainable approach by eliminating the need to track defaults in both meson and code. The conversation remains technical and constructive, focused on finding the best way to achieve build system consistency while acknowledging this is part of a larger effort to align meson with make's behavior.
