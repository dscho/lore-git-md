This is a build system patch addressing platform compatibility for cryptographic random number generation on Linux.

The patch adds documentation to `config.mak.uname` about the `CSPRNG_METHOD` setting for Linux systems. The background context is that Git has multiple possible backends for cryptographically secure pseudorandom numbers (added in commit 05cd988dce), with a preference order of arc4random > getrandom/getentropy > /dev/urandom. While meson builds automatically select the best available method, make builds currently default to /dev/urandom unless manually configured.

The note suggests Linux users with glibc ≥ 2.36 (found in recent distros like Debian 12 and Ubuntu 24.04) can override `CSPRNG_METHOD=arc4random` in their config.mak to use the preferred arc4random_buf() implementation. The patch doesn't change any behavior - it just adds this as a documented option alongside similar notes about other glibc version-dependent features like NO_STRLCPY.

This appears to be the final patch in a 12-part series (though no cover letter context is provided). The change is straightforward and well-explained, though it might have been more impactful as part of the original CSPRNG implementation series rather than coming years later. The documentation addition seems uncontroversial and helpful for users building with make on modern Linux systems.
