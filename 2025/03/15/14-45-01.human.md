This is a usability report about `git log` behavior with subtree merges and path restrictions. Oswald Buddenhagen describes encountering confusing output when running `git log .` in the git-gui subdirectory, where the output shows mostly merge commits without the underlying commits being merged. They note this appears related to how Git handles subtree merges, drawing a comparison to the known limitation where `--follow` only works for single files. The report suggests this behavior makes it difficult to trace the history of directories that use subtree merge strategies, particularly for developers trying to understand project history like in git-gui's case. While not proposing a specific solution, the email highlights what appears to be a genuine pain point in Git's history navigation capabilities.
