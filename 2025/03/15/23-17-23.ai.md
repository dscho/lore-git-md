This is a follow-up in the ongoing Windows reftable backend compatibility discussion, where Johannes Schindelin responds to Patrick Steinhardt's v2 patch for handling file-in-use errors during unlink operations on Windows.

The email acknowledges Patrick's solution (using a `MINGW_DONT_HANDLE_IN_USE_ERROR` flag to suppress retry prompts in reftable operations) as pragmatic but expresses concerns about the architectural approach. Schindelin notes this continues Git's pattern of misusing POSIX functions for platform abstraction rather than implementing proper OS-specific interfaces, comparing unfavorably to Subversion's approach. However, he concedes that a proper fix would require extensive refactoring with significant downstream impact for Git for Windows, so he reluctantly accepts the current solution despite its technical debt.

Key technical details referenced include:
- The modified `mingw_unlink()` function signature now takes a `handle_in_use_error` parameter
- The `MINGW_DONT_HANDLE_IN_USE_ERROR` macro being set in reftable's `system.h`
- The three scenarios where unlink prompts were appearing (during compaction, stack reloading, and cleanup)

The response indicates this thread is moving toward resolution, with Schindelin's acceptance suggesting the patch will likely proceed once its prerequisite lands, though it leaves open the larger architectural questions about Git's platform abstraction layer.
