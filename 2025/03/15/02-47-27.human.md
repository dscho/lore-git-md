Platform compatibility patch addressing strlcpy() availability in modern Linux distributions.

This is part 5 of a 12-patch series (no cover letter seen yet). The patch adds a comment to `config.mak.uname` reminding users building Git with `make` that they may want to override `NO_STRLCPY` if they're using a recent glibc version (2.38+) that now includes this function. 

The commit explains that while newer Linux distributions like Ubuntu 24.04 and RHEL 10 beta include strlcpy() in glibc, older supported distributions still need the compatibility version. The meson and autoconf build systems automatically detect this, but the make build defaults to the compat version unless explicitly overridden.

The change itself is minimal - just adding a one-line comment - but serves as useful documentation for maintainers and packagers. The patch appears well-motivated and correctly targeted, though it might be worth considering whether this could be automated like the other build systems rather than requiring manual configuration.
