Git thread summary: Bug report about path-filtered log behavior with subtree merges. Oswald Buddenhagen reports that `git log .` in git-gui subdirectory shows primarily merge commits rather than the expected history of changes being merged, making it difficult to trace actual changes in subtree-merged code. The behavior parallels Git's known limitation where `--follow` only works for single files, suggesting underlying limitations in path-filtering logic. The issue particularly affects git-gui's history and is exacerbated in gitk's display. No proposed solution yet, but the report highlights a significant usability issue for developers working with subtree-merged repositories, indicating this may require non-trivial changes to Git's revision walking logic for path-filtered operations.
