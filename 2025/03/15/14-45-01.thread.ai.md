Git thread summary: Bug report and technical analysis of path-filtered log behavior with subtree merges, originating from Oswald Buddenhagen's observation that `git log .` in git-gui subdirectory shows primarily merge commits rather than the expected history of changes. Johannes Schindelin provided initial detailed analysis of limitations in `tree-diff.c`, particularly `try_to_follow_renames()`'s inability to handle directory-level rename tracking in subtree-merged histories, identifying key technical challenges around multi-path queue access, pathspec matching, and rename-following logic.

Junio Hamano expanded on this analysis, agreeing the current single-path queue access (`q->queue[0]`) is fundamentally limited for merge-heavy histories. He made three critical observations: (1) `--follow-renames` breaks down when paths are renamed differently in parallel histories that later merge, (2) a proper solution requires per-ancestor path tracking during revision walking, and (3) directory-level rename following would emerge naturally from a more general solution for tracking multiple paths. Hamano emphasized these are architectural limitations requiring core revision walking changes.

Jeff King now responds with practical workarounds, confirming the issue stems from path mismatches between the merged git-gui repository (root-level paths) and main repository (git-gui/ prefixed paths). He provides a concrete solution: explicitly listing both path variants (`git log -- git-gui/ git-gui.sh lib/`) to capture history from both locations, noting the need to use "--" to bypass DWIM logic. While not addressing the deeper architectural issues, this workaround demonstrates Git's current path-matching limitations with subtree merges and the manual intervention required.

The discussion now spans both architectural limitations (single-path queue access, rename tracking in merges) and practical implications (path mismatch in subtree merges). Key open questions remain around implementing per-ancestor path tracking in revision walking and restructuring rename-following logic for merge cases. The silent failure mode for directory arguments to `--follow` persists as a known UX issue requiring substantial changes to path-filtering subsystems.
