This is a documentation patch clarifying the behavior of `core.commentString=auto`. 

Oswald Buddenhagen improves the documentation for this configuration option after finding the current description unclear and misleading. The patch makes two key clarifications: it specifies the exact set of characters Git considers for auto-selection (rather than implying any character is possible), and notes an important limitation - that this feature cannot work with comments in the prepare-commit-msg hook's output or commit message template.

The author questions in the cover note whether anyone actually uses this feature given its "rather crippling limitations," suggesting the documentation improvement may be more valuable than the feature itself. The patch is straightforward and uncontroversial, simply making the existing behavior more transparent to users.
