git-branch documentation and completion fix (2-patch series)

This thread addresses shell completion issues arising from recent manpage formatting changes while standardizing git-branch documentation. The series consists of two complementary patches:

1. Fixes completion script to properly handle backtick-wrapped option names in documentation files by modifying `generate-configlist.sh`:
   - Originally proposed using GNU-specific BRE with `\?` for backtick matching
   - Junio C Hamano suggests converting to ERE (`grep -E`) for better portability
   - Recommends consolidating grep+sed pipeline into single sed -E command
   - Maintains requirements for deprecated items, backtick removal, and comma separation
   - Affects all config option completions derived from documentation

2. Reformats git-branch documentation to apply new formatting standards in both `Documentation/config/branch.adoc` and `Documentation/git-branch.adoc`:
   - Converts synopsis to use `[` blocks for automatic formatting
   - Standardizes placeholder notation from `<name>` to _<name>_
   - Ensures consistent backtick usage for commands, options, and config keys
   - Reorganizes option value lists into definition list format
   - Normalizes branch naming (`<branchname>` → _<branch-name>_)
   - Removes redundant information while maintaining technical content

Key technical details:
- Touches `Documentation/git-branch.txt`, `contrib/completion/git-completion.bash`, `generate-configlist.sh`
- Changes are primarily formatting (196-198 insertions/deletions per file) with backtick standardization
- Builds on ongoing man page standardization efforts led by Jean-Noël Avila
- Maintains backward compatibility while fixing completion breakage
- No functional changes or compatibility issues introduced
- Affects manpage rendering and potential future documentation parsing
