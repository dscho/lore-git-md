Supporting proper directory tracking would require fundamental changes to handle multiple paths simultaneously, with implications for Git's revision walking architecture.

Junio Hamano has now weighed in, reinforcing that the issue stems from architectural constraints in how `--follow-renames` handles merge scenarios. A proper solution would need per-ancestor path tracking during revision walks, with directory following emerging as a special case of this more comprehensive approach.

The discussion highlights both the technical complexity involved (requiring changes to core revision walking behavior) and the practical impact on tools like git-gui and gitk.
