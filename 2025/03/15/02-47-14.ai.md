Build system cleanup removing obsolete Linux compatibility code. This is patch 4/12 in a series (no cover letter seen yet).

The patch removes the NEEDS_LIBRT build variable and associated linking logic, which was originally added to support older Linux systems where clock_gettime() required linking with librt. The commit message provides a detailed historical context, noting that this was only needed for glibc versions before 2.17 (released in 2012) and that all major Linux distributions have long since moved to newer versions. The message includes a table showing end-of-support dates for various distributions, with the oldest (Debian 7) having reached end-of-life in 2018.

The change removes both the Makefile documentation of the variable and its actual use in the build process, plus removes the Linux-specific setting in config.mak.uname. This appears to be a straightforward cleanup of obsolete compatibility code with no expected impact on modern systems. The commit message is thorough and well-researched, making a strong case for the removal.
