Build system alignment series (now 22 patches in v3) focusing on Makefile/meson consistency and platform-specific cleanup, with completed cryptographic random number generation (CSPRNG) standardization across all build systems. Core technical work spans: conditional `BASIC_CFLAGS`, platform-specific fixes (Cygwin regex, timing functions, arc4random), documentation updates, and meson path handling limitations. Key developments include:

- Expanded Cygwin support: `sysinfo()` implementation with RAM calculation fix in `git gc` (handling `mem_unit` field via new patch addressing incorrect RAM calculation when `mem_unit > 1`), arc4random enablement (new patch adding `CSPRNG_METHOD = arc4random` to Cygwin's `config.mak.uname` matching autoconf/meson behavior for v2.x+ Cygwin), clock function additions (`clock_gettime` and `clock_monotonic` now handled via standard libc on modern systems via `HAVE_CLOCK_GETTIME`/`HAVE_CLOCK_MONOTONIC` definitions in `config.mak.uname`), and `getdelim` support (via `HAVE_GETDELIM` in `config.mak.uname` to match autoconf/meson behavior)
- Platform standardization: Linux CSPRNG now standardized to `getrandom` (final patch) in Makefile builds, matching meson's preference for kernel-based random number generation while maintaining compatibility with all supported distros (including RHEL 8). This completes the CSPRNG standardization that previously added `arc4random` support for Cygwin. Ramsay Jones' technical rationale confirmed by Junio Hamano: all supported Linux distributions (including RHEL 8 with glibc 2.28) have `getrandom`/`getentropy` (glibc 2.25+), and while `arc4random` exists in newer glibc (2.36+), it offers no performance benefit on Linux since all methods ultimately use the same kernel CSPRNG. Minor typo (`ar4random_buf` instead of `arc4random_buf`) in commit message noted by Junio Hamano but considered trivial enough to handle locally without requiring v4 resend.
- Documentation of meson's path handling limitations for DEFAULT_EDITOR/DEFAULT_PAGER (Ramsay Jones' investigation showing quote/backslash escaping issues, GitHub issue #1564)
- Regex compatibility: NO_REGEX conditional on Cygwin 1.7 with CYGWIN-specific skip for test t7815.12 (NUL character matching failure), aligning Makefile behavior with autoconf/meson builds which already use platform regex library on modern Cygwin (2.0+)
- Legacy cleanup: removal of NEEDS_LIBRT (obsolete since glibc 2.17+ became standard in 2013-2016 across Debian 8+, RHEL 8+, Ubuntu 16.04+), eliminating special linking for `clock_gettime`
- `strlcpy()` handling: added documentation in `config.mak.uname` for Linux users with glibc ≥2.38 to override `NO_STRLCPY` setting, aligning Makefile behavior with meson/autoconf's dynamic detection (no functional change, purely documentation update)
