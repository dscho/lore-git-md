Bugfix addressing edge cases in diffcore-rename when combining break detection (-B) and --follow options. This is a follow-up to the initial patch that adds more robust test coverage and clarifies the commit message.

The patch fixes a BUG() trigger and potential uninitialized memory access that occurs when --follow skips adding rename destinations due to path filtering, violating an assumption in the break detection optimization from commit 9db2ac56168e. The fix adds proper bounds checking for break_idx mapping and handles cases where rename_dst might be NULL.

Key technical details for future reference:
- The issue manifests when using invalid pathspecs with --follow (like directories/globs) combined with -B
- Two distinct failure modes: NULL pointer dereference (BUG()) and uninitialized memory access
- Test cases demonstrate both failure scenarios:
  - t4206-log-follow-harder-copies.sh now includes tests for both the BUG() case and valgrind-catchable uninitialized memory use
  - First test uses invalid directory pathspec with --follow to trigger the original reported bug
  - Second test shows uninitialized memory access when processing file changes

The core fix remains uncontested (proper break_idx handling), but this version expands test coverage and commit message explanation based on prior discussion. The patch maintains the original safety checks while adding more context about the edge cases.
