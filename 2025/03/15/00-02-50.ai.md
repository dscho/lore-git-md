CI infrastructure fix for Meson documentation builds. Junio Hamano responds to Jeff King's report of CI failures in the Meson documentation build job by proposing a direct fix - adding `meson` to the apt-get install list for the Documentation job. The patch is minimal (a one-line change to `ci/install-dependencies.sh`) but addresses the immediate "meson: command not found" errors seen in CI runs. 

Junio questions the underlying assumption that this is the right solution, noting the documentation job runs on ubuntu-latest which should theoretically handle Meson installation through the distro-specific setup. The fix appears to work in practice (Junio provides links to passing/failing CI runs), but the architectural question about proper dependency management between distro and job-specific setups remains open. This ties into the broader Meson integration effort where Patrick Steinhardt's ps/ci-meson-check-build-docs topic introduced the documentation build testing that exposed this CI environment gap.

Key technical details: The change adds `meson` alongside existing doc tooling (asciidoc, xmlto) in the Documentation job's apt-get install list. The thread context shows this is part of ongoing work to modernize Git's build system with Meson, where documentation build verification was recently added but uncovered missing infrastructure dependencies. The simple fix may be a stopgap until a more principled solution for CI dependency management emerges.
