Thread summary:

This thread documents platform-specific build configuration options for cryptographically secure pseudorandom number generation (CSPRNG) in Git's make-based builds. The series adds documentation to `config.mak.uname` about the `CSPRNG_METHOD` setting, particularly for Linux systems with glibc ≥ 2.36 (found in recent distributions like Debian 12 and Ubuntu 24.04). Git supports multiple CSPRNG backends with a preference order: arc4random > getrandom/getentropy > /dev/urandom. While meson builds automatically select the best available method, make builds default to /dev/urandom unless manually configured. The patch suggests Linux users can override `CSPRNG_METHOD=arc4random` to use the preferred arc4random_buf() implementation, similar to other documented glibc version-dependent features like NO_STRLCPY. This is a documentation-only change that doesn't modify behavior, serving as a reference for users building with make on modern Linux systems. The change appears in the final patch of a 12-part series, though no broader context about the series' purpose is provided in this email. The addition is straightforward and uncontroversial, though it might have been more impactful if included with the original CSPRNG implementation (commit 05cd988dce) rather than appearing years later.
