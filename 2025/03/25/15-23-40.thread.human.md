This thread discusses how Git should handle Python version selection for git-p4, Git's only Python-dependent component, as platforms phase out Python2. The discussion began with Randall Becker (NonStop maintainer) raising concerns about Python2 deprecation, and has evolved to consider both technical solutions and philosophical boundaries.

Key participants include Nikolay Shustov, who initially proposed technical solutions for Python environment configuration, and Junio C Hamano, who advocated for keeping Python environment management as a system responsibility. Brian m. carlson confirmed git-p4's compatibility with both Python2 and Python3.

The discussion has now reached consensus: Git should not manage Python environment intricacies beyond basic version selection for git-p4. Systems should handle Python version management through their native methods, with Git only needing to accommodate cases where git-p4 must run with a non-default Python version. This resolution maintains Git's philosophy of minimal intervention in system configuration while still supporting git-p4's needs across different platforms. The thread appears to be concluding with this clarified boundary of responsibility.
