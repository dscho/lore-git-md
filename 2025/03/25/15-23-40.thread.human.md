This thread discusses platform compatibility issues around Python version selection when building Git, specifically for the git-p4 component. The discussion was initiated by Randall Becker, who maintains the NonStop port of Git, as his organization phases out Python2. Brian m. carlson confirmed that git-p4 supports both Python2 and Python3, suggesting that setting PYTHON_PATH to Python3 in config.mak.uname should work, though noted his limited experience with git-p4.

Nikolay Shustov has now added more detailed technical considerations, agreeing that git-p4 is compatible with both Python versions but warning that simply setting PYTHON_PATH may not be sufficient due to system-level complexities. He highlights issues like shebang line interpretation differences between platforms, environment variable coherence, and OS-specific configuration needs. While the core compatibility remains confirmed, Nikolay's input suggests that proper Python3 integration may require additional system-level configuration beyond just the Git build settings. The thread remains focused on git-p4 as Git's only Python-dependent component, with the consensus being that this is primarily a system administration matter rather than requiring changes to Git's codebase.
