This is the architectural improvement component of Justin Tobler's series addressing default branch name advice suppression, now at version 3. The patch introduces proper advice control infrastructure for the "Using 'master' as name for initial branch" message, making it respect standard Git advice mechanisms.

The change adds `ADVICE_DEFAULT_BRANCH_NAME` to the advice system by:
1. Adding the new advice type to `advice.h` and the corresponding string mapping in `advice.c`
2. Modifying `repo_default_branch_name()` in `refs.c` to use `advise_if_enabled()` instead of direct `advise()`
3. Adding test coverage in t0001-init.sh to verify suppression works via both config (`advice.defaultBranchName=false`) and command line (`--no-advice`)

The implementation ensures the advice can be disabled through all standard Git advice control mechanisms while maintaining the existing behavior when enabled. This addresses a long-standing limitation where the advice could previously only be silenced by setting `init.defaultBranch`. The test case specifically verifies the config-based suppression path, complementing the earlier flag-based suppression tests in the series.

This patch represents the architectural half of the solution, working in concert with the earlier clone-specific flag propagation changes. It cleanly separates the advice control mechanism from the specific use cases, following Git's standard patterns for advice handling. The change is minimal and focused, touching only the necessary components to implement proper advice control while maintaining backward compatibility.
