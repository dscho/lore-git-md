Johannes Schindelin proposed a pair of small, purely stylistic patches to clean up unnecessary comma operator usage in Git's code, specifically in `remote-curl.c` and `builtin/rebase.c`. The changes originated from systematic static analysis using GitHub's CodeQL tool, which Schindelin helped develop during his time at GitHub. The patches replace commas with semicolons in cases where expression chaining served no functional purpose, with no impact on the RPC protocol or rebase behavior.

Patrick Steinhardt reviewed the patches positively, confirming their safety based on similar cleanup work in the reftable code. While both noted that compilers don't warn about unintentional comma usage, they agreed these changes improve code clarity. In a follow-up, Schindelin clarified that while Microsoft's Git fork will use CodeQL for static analysis, he doesn't propose enabling it in Git's main CI due to resource constraints. The thread shows clear consensus on these low-risk changes, with no outstanding technical questions. The discussion also revealed an interesting divergence in CI policy between the main project and Microsoft's fork regarding static analysis tooling.
