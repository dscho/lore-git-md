Johannes Schindelin continues leading a systematic refactoring effort to clean up comma operator usage in Git's codebase, now expanded to a 10-patch series. The work has broad consensus among contributors, with Junio Hamano having already queued some of the initial changes.

The latest patch (5/10) focuses on the xdiff subsystem, specifically the Myers diff algorithm implementation in `xdiff/xdiffi.c`. It converts two instances where comma operators were used in boundary condition checks within the `xdl_split()` function - a core routine for finding optimal split points during file comparisons. The changes make the control flow more explicit while maintaining identical behavior, following the series' pattern of improving readability without altering functionality.

This builds on earlier approved changes in `remote-curl.c` (RPC service initialization), `builtin/rebase.c` (rebase options setup), and `kwset.c` (string search algorithms). The series demonstrates Git's careful approach to code hygiene - preserving comma operators in truly performance-critical paths while removing them where they don't serve a clear optimization purpose. Reviewers including Phillip Wood and Jeff King have contributed to establishing clear criteria for when changes are appropriate.

The work combines manual review with automated detection methods (CodeQL and Clang warnings), and has so far avoided any reported false positives. While most changes are straightforward readability improvements, the series maintains special consideration for performance-sensitive areas like diff algorithms, where comma operators sometimes serve legitimate optimization purposes.
