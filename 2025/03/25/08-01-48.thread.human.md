Johannes Schindelin has sent a small refactoring series that cleans up two instances of unnecessary comma operator usage in Git's codebase. The changes are minimal and purely stylistic, replacing commas with semicolons in `remote-curl.c` and `builtin/rebase.c` where the comma operator's behavior (evaluating multiple expressions but only returning the last) wasn't actually needed. 

The patches follow a consistent pattern - in both cases, the first expression's result was being discarded anyway, so using a semicolon makes the intent clearer. Johannes notes that the comma operator is rare in modern C code and often indicates a typo when it appears. While the changes don't fix any specific bugs, they improve code clarity by using the more conventional semicolon separator in these simple statement sequences.

The series touches two different subsystems (remote-curl and rebase) but the changes are so straightforward that they're unlikely to generate much discussion unless someone wants to debate the general principle of avoiding comma operators.
