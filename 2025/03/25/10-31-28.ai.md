Bugfix refinement for `git blame` porcelain output regarding per-line ignored/unblamable status. This email continues the thread about properly marking lines affected by `--ignore-rev` in porcelain mode, now focusing on implementation specifics after Toon Claes demonstrated that status must be tracked per-line rather than per-commit.

Karthik Nayak agrees with Toon's analysis that when ignored revisions cause multiple lines to blame to the same parent commit, their ignored/unblamable status may differ based on original history. The discussion centers on whether to emit status metadata for every affected line in regular `--porcelain` mode (which normally deduplicates commit details) or restrict this to `--line-porcelain`. 

Key technical points:
- Regular porcelain mode groups lines by commit, emitting author/committer metadata once per unique commit
- Status markers (`ignored`/`unblamable`) must appear per-line since they depend on pre-ignore history
- Current proposal would limit these markers to `--line-porcelain` to avoid inconsistent metadata emission
- Alternative approach (emitting status per-line in regular porcelain) would create asymmetry where some lines get extra metadata
- Karthik favors the `--line-porcelain` restriction as more future-proof, though it means porcelain users must opt-in to see these markers

The thread has converged on implementation strategy, with the remaining decision being whether to:
1. Emit status per-line in regular porcelain (odd metadata asymmetry)
2. Restrict to line-porcelain (cleaner but requires user opt-in)

Karthik is leaning toward option 2 as more maintainable long-term, noting the restriction could be lifted later if needed. This represents the final design choice before implementation completion.
