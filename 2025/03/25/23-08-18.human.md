This is a discussion about Windows compatibility issues in the Rust crate packaging series, specifically regarding the symlink approach in patch 2/5. Junio Hamano responds to Josh Steadmon's exploration of alternative solutions for the Windows symlink limitation in the libgit Rust integration.

The thread has established that the current symlink-based solution (which keeps Rust configuration out of the main Git tree) doesn't work well on Windows. Steadmon has proposed investigating Cargo workspaces as a potential solution, with two fallback options if that fails: (1) temporarily limiting to source builds only, or (2) moving crates to separate repositories with Git as a submodule.

Hamano expresses openness to adding root-level Cargo configuration if it's similar to other build configuration files, rather than cluttering the tree. He supports Steadmon's plan to test the workspace approach and agrees that the conservative option #1 (source builds only) is reasonable as an interim solution while the Rust integration gains traction.

The discussion shows the project maintaining a careful balance between technical requirements (Windows compatibility, build system cleanliness) and practical considerations (developer experience, future maintainability). The symlink issue remains the last major blocker for this otherwise complete Rust packaging solution.
