This is the second patch in a Windows platform compatibility series addressing file ownership issues in Git's "safe directory" feature. The patch adds a debugging tool for diagnosing "dubious ownership" problems that can occur when running Git as Administrator on Windows.

The new `test-tool path-utils is_path_owned_by_current_user` subcommand lets developers manually check whether paths are considered owned by the current user according to Git's security model. This is particularly useful for troubleshooting the edge case where Windows assigns ownership to the Administrators group rather than the individual user account when processes run with elevated privileges.

The implementation is straightforward - it exposes the existing `is_path_owned_by_current_user()` function through the test helper, printing ownership status for each provided path along with any error details. While the patch itself is simple (19 lines added), it provides valuable debugging capability for the Windows-specific security issue addressed in the series' first patch.

As noted in the thread context, automated testing of this functionality is challenging due to platform constraints around programmatic process elevation. This manual debugging tool helps compensate for that limitation during development and troubleshooting. The change is focused and well-contained within the test helper infrastructure.
