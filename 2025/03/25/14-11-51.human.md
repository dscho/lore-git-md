Bugfix for gitk's PATH resolution behavior. This patch addresses an issue where gitk incorrectly tries to execute non-executable files named "git" found in PATH directories, rather than properly checking for executable permissions.

Toni Dietze reports that when a non-executable file named 'git' exists in an early PATH directory, gitk fails with a misleading "Cannot find a git repository here" message. The problem occurs because gitk's current implementation checks only for file existence, not executability, when searching PATH for the git binary. This differs from shell behavior (zsh in this case) and the `which` command, which properly skip non-executable files.

The report includes a practical scenario where this occurs: the user maintains a debugging overlay directory in PATH containing non-executable wrapper scripts. While the current behavior isn't strictly wrong (POSIX doesn't require PATH to skip non-executable files), it's clearly unexpected and produces confusing error messages.

The patch appears well-motivated and addresses a real usability issue. The problem is clearly described with reproduction steps, and the suggested fix (checking executability) aligns with common PATH resolution behavior. This seems like a straightforward improvement that shouldn't be controversial.
