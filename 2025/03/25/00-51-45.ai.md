This is a bugfix patch series addressing advice message suppression in Git's clone operation, specifically targeting the default branch name advice that appears unexpectedly during bundle clones. The series represents version 3 of Justin Tobler's solution, incorporating feedback from previous rounds.

The core issue stems from a regression introduced in Git v2.45.0 where bundle clones would display the "hint: Using 'master' as the name for the initial branch" advice message even when suppressed via GIT_ADVICE=0 or --quiet flags. The regression was caused by changes to refdb initialization timing in commit 199f44cb2ead.

The series makes three key improvements: First, it modifies `guess_remote_head()` to accept flags for advice suppression (REMOTE_GUESS_HEAD_QUIET). Second, it updates clone.c to use these flags, now also covering the `--single-branch` case where the message could appear twice. Third, it adds proper advice subsystem support for the default branch name hint via ADVICE_DEFAULT_BRANCH_NAME, allowing suppression through standard mechanisms like --no-advice.

Technical details important for follow-up discussion include: the new REMOTE_GUESS_HEAD_QUIET flag in remote.h, changes to repo_default_branch_name() in refs.c to respect advice settings, test coverage in t5607-clone-bundle.sh that now includes --single-branch verification, and the new advice.defaultBranchName config option. The implementation maintains explicit flags rather than implicit behavior as discussed in the design review.

The patch series appears well-constructed with thorough test coverage and clear commit messages explaining both the immediate fix and architectural improvement. It addresses all known cases where the advice could leak through, including the newly discovered --single-branch interaction. The changes are focused and maintainable, building on prior consensus about the explicit flags approach.
