This is a build system patch addressing an issue with Coccinelle integration in the Meson build. The change prevents Coccinelle from being automatically enabled when building from a tarball, which was causing build failures when `spatch` was installed but the source wasn't a Git checkout.

The patch modifies the Meson configuration to add a new prerequisite: Coccinelle will now be enabled only if both `spatch` is available *and* the source tree contains a `.git` directory/file. This fixes a case where tarball builds would fail if Coccinelle was detected but couldn't run Git commands. The change uses Meson's `opt.require()` to implement this two-factor check, with a clear error message explaining the requirement.

The implementation touches only the `contrib/coccinelle/meson.build` file, adding the Git checkout check while maintaining the existing `spatch` detection. The error handling remains clean - if conditions aren't met, Coccinelle support is either silently skipped (for auto-detection) or fails with a helpful message (when explicitly requested).

This appears to be a well-motivated change that solves a real build issue, particularly relevant for distribution packagers who often build from tarballs. The patch is focused and follows the existing Meson patterns while improving the robustness of the build system.
