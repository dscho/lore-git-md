Refactoring patch in the comma operator cleanup series, targeting the kwset string matching subsystem.

This is patch 3/10 in Johannes Schindelin's v2 series systematically removing unnecessary comma operators from Git's codebase. The changes focus on kwset.c, which implements string matching algorithms used in diff and grep operations. The patch converts comma-separated statements into explicit semicolon-terminated lines, improving code clarity without altering functionality.

Key technical changes:
- Replaces comma operators with semicolons in tree traversal logic (llink/rlink operations in AVL tree balancing)
- Modifies Boyer-Moore string search loop unrolling in bmexec()
- Updates initialization of match state in cwexec()
- Preserves all existing control flow and variable assignments while making sequencing explicit

The changes align with the series' established pattern of removing comma operators that don't serve a clear sequencing purpose, following maintainer-approved criteria. This subsystem was flagged through a combination of manual review and compiler warnings (-Wcomma with DEVELOPER=1). Unlike some performance-sensitive areas where comma operators were preserved (like diff-delta.c), these changes in kwset.c were deemed safe for readability improvements.

The patch follows the same high-quality standard as others in the series, with thorough mechanical conversions and no functional changes. It continues the systematic approach to code hygiene effort that has already seen several patches queued by the maintainer.
