This thread addresses an issue with Coccinelle integration in Git's Meson build system. The original problem caused builds from tarballs to fail when `spatch` was installed but the source wasn't a Git checkout, since Coccinelle rules require access to Git metadata.

The solution modifies the Meson configuration to add a new requirement: Coccinelle will now only be enabled if both `spatch` is available *and* the source tree is a Git checkout (indicated by the presence of a `.git` directory/file. This change prevents false positives where the build system would try to use Coccinelle in environments where it couldn't function properly. The implementation cleanly handles both automatic detection cases (silently skipping when requirements aren't met) and explicit requests (providing clear error messages).

The patch is narrowly focused on the `contrib/coccinelle/meson.build` file and follows existing Meson patterns while making the build system more robust, particularly for distribution packagers who frequently build from release tarballs. The change appears well-considered and solves a concrete problem without introducing new complexity.
