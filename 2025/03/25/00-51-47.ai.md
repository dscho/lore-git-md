Bugfix patch addressing default branch advice suppression in clone operations, particularly for bundle clones. This is part 2/3 of Justin Tobler's series fixing a regression where the "hint: Using 'master'..." advice appears during bundle operations despite suppression flags.

The patch focuses on the clone-specific paths where `guess_remote_head()` is called, adding the `REMOTE_GUESS_HEAD_QUIET` flag to suppress advice messages. This restores pre-regression behavior where the default branch name advice wouldn't appear during clone operations. The regression was introduced by 199f44cb2ead which changed refdb initialization timing, causing the advice to appear in cases where it previously didn't.

Key technical details:
- Modifies two call sites in `builtin/clone.c` to pass the quiet flag
- Adds test coverage in t5607-clone-bundle.sh specifically for the bundle clone case
- Handles both regular and `--single-branch` clone scenarios
- The test uses `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME` to ensure consistent behavior regardless of system configuration

This builds on the architectural changes from part 1/3 which introduced the flag-based control in `guess_remote_head()`. The implementation now comprehensively covers all clone code paths including the `wanted_peer_refs()` path for `--single-branch` clones, addressing a case where the advice could appear twice. The test confirms suppression works for the exact reproduction case that triggered the regression report.
