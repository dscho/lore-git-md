This is a style discussion about enum documentation in the context of the batched reference updates series.

Patrick Steinhardt suggests that enum values should be documented inline (next to each value) rather than in a block comment above the enum, arguing this makes it harder for documentation to become stale. This comes in response to Karthik Nayak's implementation which followed the pattern seen in `enum bisect_error` and `enum scld_error` where documentation is grouped above the enum.

The discussion is part of the now-merged series introducing batched reference updates with partial failure support. While the technical implementation is settled, this touches on a broader code style question that could influence future enum documentation patterns in the codebase. Both participants acknowledge there are existing examples of both styles in the codebase, suggesting this might benefit from a more general style guideline.
