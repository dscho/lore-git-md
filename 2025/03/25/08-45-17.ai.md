This is a technical discussion about the final implementation details of a bugfix for `git blame` porcelain output regarding ignored/unblamable lines. The thread has progressed from design to implementation, with Karthik Nayak's metadata line solution already accepted as the core approach.

Toon Claes provides a concrete example showing how lines blaming to the same commit can have different ignored/unblamable statuses in non-porcelain output, while the current porcelain implementation only shows this status once per commit. The example demonstrates that lines 4-5 in varint.h (function declarations) should be marked as ignored when their original commit is in the ignore-revs file, even though they now blame to the same commit as other lines.

The key technical point is that while commit metadata (author, committer etc.) can be emitted once per commit, the ignored/unblamable status must be per-line since it depends on the line's original blame history. Toon suggests emitting "ignored" metadata lines before each affected line, though notes this creates an odd asymmetry where some lines get extra metadata while others don't.

This discussion represents the final refinement of the implementation, addressing whether the porcelain output needs to emit ignored/unblamable status per-line (like non-porcelain does with '?'/'*' prefixes) rather than per-commit. The solution must maintain porcelain format rules while accurately reflecting line-specific attributes, even when multiple lines share a commit after ignoring revisions.
