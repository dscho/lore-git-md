This is the first patch in a 20-part series refactoring Git's test suite to make Perl optional. The patch focuses on the chain lint mechanism, which verifies proper '&&' chaining in test scripts.

The change automatically disables chain linting when Perl is unavailable (PERL_PATH unset), unless the developer has explicitly requested chain linting (GIT_TEST_CHAIN_LINT=1), in which case it errors out. This makes the test suite more usable in Perl-less environments while preserving the ability to enforce linting when desired.

The patch is straightforward and well-motivated as part of the larger Perl-optional effort. It maintains backward compatibility while removing a friction point for developers working without Perl. The implementation handles all three cases (unset, explicitly disabled, explicitly enabled) cleanly with a case statement.

This is a small but thoughtful change that sets the stage for the more substantial Perl-to-shell/awk conversions that follow in the series. The commit message clearly explains both the immediate change and its context within the broader initiative.
