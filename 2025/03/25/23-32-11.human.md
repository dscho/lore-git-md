Refactoring patch in the systematic comma-operator cleanup series, focusing on wildmatch pattern matching.

This is patch 7/10 in Johannes Schindelin's series to make intentional comma operator usage explicit throughout Git's codebase. The change targets the wildcard matching logic in `wildmatch.c`, specifically the loop that processes character classes in patterns (like `[a-z]`).

The patch adds a `(void)` cast to mark a comma operator as intentional in a loop condition that handles bracket expressions. The comma operator here serves to both save the previous character and advance to the next one in a single expression. The commit message explains why this usage is legitimate - alternatives would require either code duplication or a `goto` due to the presence of a `continue` statement in the loop body.

This follows the established pattern seen in earlier patches of the series: preserving performance-critical comma operator usage while making it explicit via `(void)` casts. The change is purely about code clarity and maintainability, with no functional impact on wildcard behavior. The thorough explanation in the commit message shows careful consideration of alternatives, consistent with the high-quality approach seen throughout this refactoring effort.
