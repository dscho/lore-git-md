Bugfix refinement for `git blame` porcelain output regarding ignored/unblamable lines. This email continues the discussion about how to properly mark lines affected by `--ignore-rev` in porcelain mode, now focusing on implementation details.

Karthik Nayak responds to Toon Claes' concrete example showing that lines blaming to the same commit after ignoring revisions may need different "ignored" status markers, since they could have different original histories. The key insight is that porcelain mode currently groups commit metadata (author info, etc.) when consecutive lines share a commit, but this optimization loses the per-line ignored/unblamable status that exists in non-porcelain output (shown as '?'/'*' prefixes).

The discussion weighs two approaches: either emit "ignored"/"unblamable" metadata per-line while keeping other commit details grouped (creating an asymmetric output), or restrict these markers to `--line-porcelain` mode which already emits per-line details. Karthik leans toward the latter approach as more conceptually clean and future-proof, though it means porcelain mode users won't see these markers. This represents the final design decision needed before implementation can be completed.

The thread has progressed from initial design through several iterations, with all parties now agreeing on the core technical requirements.
