Johannes Schindelin (via GitGitGadget) proposes removing unnecessary comma operator usage in Git's codebase through two small refactoring patches targeting `remote-curl.c` (push_git() function's RPC service initialization) and `builtin/rebase.c` (reset_head_opts setup for detached HEAD checkout). The changes replace commas with semicolons where expression-chaining behavior serves no purpose, being purely stylistic with no functional impact on RPC protocol or rebase behavior. Phillip Wood confirms the second patch fixes what appears to be a clear mistake in `builtin/rebase.c` - a trailing comma that should have been a semicolon in the `reset_head_opts` initialization during detached HEAD checkout (line 1843), calling it "obviously a typo". The patches originated from systematic static analysis using GitHub's CodeQL tool, which Schindelin helped enhance during his GitHub tenure to detect such cases. Patrick Steinhardt has reviewed the patches positively, confirming their harmlessness based on similar cleanup experience in the reftable code, though noting no compiler warnings exist for unintentional comma operator usage. Karthik Nayak now contributes that Clang's `-Wcomma` flag could address this gap by detecting unintentional comma operator usage during compilation, providing a lightweight alternative to the CodeQL analysis that won't be integrated into Git's main CI due to resource constraints. The technical details of the original patches remain unchanged - one-line modifications to `push_git()` in remote-curl.c and detached HEAD setup in builtin/rebase.c, replacing commas with semicolons in isolated code paths where expressions didn't need combining. The thread shows consensus with no objections, the patches appearing complete with maintainer support from Schindelin (Windows expertise), Steinhardt (reftable/ODB work), Wood (sequencer/rebase expertise), and now Nayak (maintenance/refs) contributing tooling insights. No relation to ongoing large-scale efforts like `the_repository` removal, and no tests needed for these syntactic-only changes. The discussion has evolved from specific patches to broader code quality tooling, documenting both the systematic nature of the cleanup via static analysis and divergent CI approaches between upstream Git and Microsoft's fork, now supplemented with compiler flag suggestions for future prevention.
