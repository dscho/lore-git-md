Johannes Schindelin (via GitGitGadget) proposes removing unnecessary comma operator usage in Git's codebase through two small refactoring patches targeting `remote-curl.c` (push_git() function's RPC service initialization) and `builtin/rebase.c` (reset_head_opts setup for detached HEAD checkout). The changes replace commas with semicolons where expression-chaining behavior serves no purpose, being purely stylistic with no functional impact on RPC protocol or rebase behavior. The patches originated from systematic static analysis using GitHub's CodeQL tool, which Schindelin helped enhance during his GitHub tenure to detect such cases. Patrick Steinhardt has reviewed the patches positively, confirming their harmlessness based on similar cleanup experience in the reftable code, though noting no compiler warnings exist for unintentional comma operator usage. The follow-up exchange reveals the CodeQL analysis won't be integrated into Git's main CI due to resource constraints (though Microsoft's fork will use it), establishing a CI policy difference between projects. Technical details remain unchanged - one-line modifications to `push_git()` in remote-curl.c and detached HEAD setup in builtin/rebase.c, replacing commas with semicolons in isolated code paths where expressions didn't need combining. The thread shows consensus with no objections, the patches appearing complete with maintainer support from both Schindelin (Windows expertise) and Steinhardt (reftable/ODB work). No relation to ongoing large-scale efforts like `the_repository` removal, and no tests needed for these syntactic-only changes. The discussion confirms the systematic nature of the cleanup via static analysis tooling rather than ad hoc code review findings, while documenting divergent CI approaches between upstream Git and Microsoft's fork regarding static analysis integration.
