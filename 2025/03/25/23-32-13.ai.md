**Build system change for Clang warning infrastructure**

This patch adds a new compiler warning flag to detect comma operator usage when building with Clang, as part of Johannes Schindelin's ongoing series to systematically address comma operator usage in Git's codebase. The change enables `-Wcomma` for Clang 9+ builds when `DEVELOPER=1` is set, joining other developer-oriented warnings in `config.mak.dev`.

The patch follows established patterns from earlier in the series where comma operator usage was evaluated and either removed (when unnecessary) or preserved with explicit `(void)` casts (in performance-critical sections). This warning infrastructure will help prevent new comma operator usage from being introduced unintentionally, complementing the manual review and CodeQL detection methods mentioned in the thread context.

Key technical details:
- Only activates for Clang 9+ (checked via `COMPILER_FEATURES`)
- Added alongside other developer warnings like `-Wvla` and `-Wwrite-strings`
- Builds on maintainer-approved warning infrastructure patterns
- Follows same conditional structure as existing Clang-specific warnings in the file

The change is straightforward and non-controversial, fitting naturally with the series' goal of improving code hygiene while preserving legitimate comma operator usage in performance-sensitive areas like regex and diff algorithms. This infrastructure piece completes the prevention side of the comma operator cleanup effort after the substantive code changes in earlier patches.
