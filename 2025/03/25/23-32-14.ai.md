Build system patch fixing Clang detection in CUDA environments. This is the final patch in Johannes Schindelin's 12-part series refactoring comma operator usage, though it addresses a separate but related build system issue.

The patch fixes the `detect-compiler` script's handling of Clang installations that also have CUDA toolkits present. Currently, when CUDA is installed, the script incorrectly processes multiple "version" matches in `clang -v` output, leading to misidentification of the compiler family. The change modifies the version detection to only process the first matching line using `sed -n` with an early exit.

This is a straightforward fix that maintains the series' focus on build system improvements while addressing a real-world edge case in compiler detection. The change is minimal (a one-line modification) and follows the established pattern of making the build system more robust. As with earlier patches in the series, this demonstrates careful attention to edge cases in development environments.

Key technical details for future reference:
- Modifies `detect-compiler` script's `get_version_line()` function
- Uses `sed -n '/ pattern /{p;q}'` pattern to only output first match
- Fixes interaction between Clang and CUDA toolkit installations
- Maintains existing behavior for standard Clang installations
- Part of broader build system improvements in the comma-operator refactoring series

The patch appears well-contained and unlikely to be controversial, completing the series' build system enhancements with a focused fix for a specific development environment configuration.
