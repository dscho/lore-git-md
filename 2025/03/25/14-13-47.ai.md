This is a follow-up in the comma operator cleanup thread, confirming the technical approach and CI considerations. Johannes Schindelin responds to Patrick Steinhardt's review of the earlier patches that removed unnecessary comma operators in `remote-curl.c` and `builtin/rebase.c`. (2) Steinhardt confirms the changes are harmless based on similar cleanup experience in the reftable code, though both note the lack of compiler warnings for unintentional comma usage. The technical content remains unchanged from the original patches - these were purely syntactic changes replacing commas with semicolons where expression chaining served no purpose. The thread shows consensus on the changes with no outstanding technical questions, though it surfaces an interesting CI policy difference between the main Git project and Microsoft's fork regarding static analysis tooling.
