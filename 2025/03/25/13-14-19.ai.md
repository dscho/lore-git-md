This is the first patch in a 20-part series refactoring Git's test suite to make Perl optional. The patch focuses on the chain lint mechanism, which verifies proper '&&' chaining in test scripts.

The change automatically disables chain linting when PERL_PATH is unset (indicating Perl is not available), unless the user has explicitly requested chain linting via GIT_TEST_CHAIN_LINT. In that case, it bails out with an error since Perl is required for this feature. This makes the test suite more usable in Perl-less environments while maintaining the ability to enforce chain linting when desired.

Key technical details:
- Modifies t/test-lib.sh to handle PERL_PATH absence
- Introduces logic for GIT_TEST_CHAIN_LINT handling (unset/0/1 cases)
- Maintains backward compatibility with existing chain lint behavior
- Part of broader effort to reduce Perl dependencies in test suite

The patch is straightforward and well-motivated, with clear commit message explaining the rationale. It serves as a foundational change for the larger series by removing a mandatory dependency while preserving optional functionality when Perl is present.
