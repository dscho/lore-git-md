This is a bugfix for `git blame` porcelain output, finalizing the implementation details for showing ignored/unblamable line markers. Junio Hamano responds to Toon Claes' concern about metadata asymmetry in the output format, confirming that the current approach of only showing "ignored" status is correct given the per-line nature of this information.

The email reinforces the thread's consensus to restrict these status markers to `--line-porcelain` mode, as this matches the technical reality that ignored/unblamable status depends on each line's individual blame history. Junio notes that while the current implementation only has one such per-line metadata field ("ignored"), the design properly accommodates future additions of similar per-line information.

This represents the final approval of the maintainer for the chosen approach, which maintains backward compatibility while properly extending the porcelain format. The solution keeps the SHA-1 line format unchanged (as required) and adds new metadata lines only in `--line-porcelain` mode, following Git's porcelain extensibility rules. The implementation in `builtin/blame.c` via `emit_one_suspect_detail()` will proceed with this design, with test updates to follow in `t/t8013-blame-ignore-revs.sh`.
