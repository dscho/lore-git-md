This is a refinement discussion in the ongoing bugfix for `git blame` porcelain output regarding ignored/unblamable lines. Toon Claes provides a concrete example showing that while commit metadata is emitted once per commit in porcelain mode, the "ignored" status can vary per line - even for lines that ultimately blame to the same commit. 

The example demonstrates that in non-porcelain mode, lines 4-5 of varint.h are correctly marked with '?' when ignored, but in porcelain mode this per-line status is lost. Toon suggests emitting "ignored" metadata lines for each affected line, though notes this creates an asymmetry where commit details appear once but status markers repeat.

The discussion represents final polishing of an already-accepted solution that adds metadata lines to preserve ignored/unblamable status in porcelain mode while maintaining backward compatibility. The core question now is whether to optimize metadata emission when multiple lines share a commit (current approach) or emit per-line status at the cost of some redundancy (Toon's suggestion). This is a subtle implementation detail that won't affect most users but matters for precise output formatting.
