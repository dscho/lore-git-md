This is a refactoring patch that's part of a larger series addressing comma operator usage in Git's codebase. It specifically fixes two instances in `remote-curl.c` where commas were incorrectly used instead of semicolons when initializing struct fields in the `fetch_git` and `push_git` functions.

The changes are straightforward replacements of commas with semicolons in the initialization of `rpc.service_name` for both git-upload-pack and git-receive-pack operations. These were clearly unintentional uses of the comma operator, as confirmed by earlier maintainer review, and don't affect functionality.

This patch represents the first of ten in a v2 series that systematically cleans up questionable comma operator usage across Git's codebase. The approach has already gained consensus among key contributors, with Junio Hamano having queued earlier versions of these changes. The series combines manual review with compiler warnings to improve code clarity while preserving legitimate performance-sensitive uses.
