This is a bugfix for the `git p4` bridge, specifically addressing encoding issues in Perforce error messages. The patch builds on previous work to handle non-UTF-8 metadata in Perforce by extending the existing transcoding framework to error messages.

Key technical details for future reference:
- Introduces a `MetadataTranscoder` class to consolidate encoding handling (refactored from `metadata_stream_to_writable_bytes()`)
- Applies same configurable fallback strategy (`git-p4.metadataDecodingStrategy`/`git-p4.metadataFallbackEncoding`) to error messages that was previously only used for metadata
- Adds Python 3-specific test verification (`t9837-git-p4-error-encoding.sh`) with a custom test script that forces Python 3 execution
- Enhances verbose diagnostics in `MetadataDecodingException` to include the underlying error details
- Maintains Python 2/3 compatibility through careful byte handling without new configuration

The author emphasizes this fixes a practical roadblock for companies migrating from Perforce to Git, though the test coverage is limited to Python 3 due to Unicode handling differences. The changes align with the established approach to encoding issues in the git-p4 bridge.
