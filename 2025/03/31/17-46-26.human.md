This is a technical follow-up in the SHA implementation reporting series, where Justin Tobler responds to Patrick Steinhardt's architectural suggestion for handling SHA backend selection.

Justin agrees with Patrick's proposal to have SHA implementations define their own `SHA1_BACKEND` symbol rather than using the current if/elif cascade approach. This would centralize backend selection logic in hash.h while making the implementation more maintainable and less prone to synchronization issues between different parts of the codebase.

The change addresses Junio Hamano's earlier concerns about maintainability and potential misconfigurations when multiple SHA implementations might be defined. By moving to a symbol-based approach, the code will be more robust and clearer about which implementation is actually being used.

Justin indicates he will implement this approach in the next version of the patch series, showing the discussion is converging on a technically sound solution that satisfies both the diagnostic goals and maintainability requirements. The thread demonstrates productive collaboration to refine the implementation strategy.
