This is the resolution of a Windows-specific bugfix thread about lockfile race conditions. The discussion has settled on using the `RtlGetLastNtStatus()` Windows API to precisely detect when a file is pending deletion, which was causing flaky tests when `O_CREAT|O_EXCL` operations returned `EACCESS` incorrectly.

Patrick Steinhardt confirms Johannes Schindelin's acceptance of the NTSTATUS solution after some back-and-forth about alternative approaches (including SQLite-style polling). The fix will go into the core lockfile subsystem rather than being reftable-specific, as the issue could affect any lockfile operations on Windows. Johannes has verified that the implementation won't risk corrupting the NTSTATUS value during initialization.

The patch series is now ready to proceed with this technically correct solution, marking a rare case where Git will use an undocumented Windows API due to the precision requirements of lockfile handling. This represents a pragmatic resolution between Git's reliability needs and Windows platform realities.
