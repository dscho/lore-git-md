Documentation patch addressing Asciidoctor formatting issues in Git manual pages, specifically focusing on triple-dot (`...`) processing in command synopses. This is a follow-up to SZEDER Gábor's report of `{empty}` string rendering problems when building with Asciidoctor 2.0.16.

The patch modifies `asciidoctor-extensions.rb.in` to better handle ellipsis notation in three contexts: main processing, monospaced text, and inline quotes. Key changes include:
- Adding `{empty}` markers around dots in the main processing function
- Special handling for standalone dots in monospaced contexts
- Additional regex patterns to avoid matching dots within brackets or before certain characters

Jean-Noël Avila confirms the patch fixes the immediate `git-diff` rendering issue but notes they cannot reproduce SZEDER's remaining problems with 'diff-generate-patch.adoc' in other manpages (diff-files, diff-index, log) using Asciidoctor 2.0.23. The discussion reveals:
- SZEDER suggests the commit message could better explain the specific problems being addressed
- Jean-Noël acknowledges the regex complexity is growing and mentions work on a parser generator alternative
- Open question about whether format failures have changed with this patch for the remaining issues

The technical changes appear sound but the thread indicates this may be an intermediate step toward a more comprehensive solution, with regex complexity becoming a maintenance concern and some rendering issues persisting in certain environments.
