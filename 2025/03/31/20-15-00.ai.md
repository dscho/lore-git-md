This is a follow-up in the git-daemon security configuration thread, where a user reports issues with wildcard path resolution in `safe.directory` settings. The email from MegaBrutal confirms that while Konstantin Ryabitsev's suggested system-wide `/etc/gitconfig` solution works for explicit paths, two specific problems remain: (1) the wildcard pattern `/srv/git/* fails to match actual repository paths when used with git-daemon, and (2) the daemon still reports ownership errors for the current directory ('.') even when parent paths are marked safe.

The message provides concrete reproduction details using Git 2.43.0 on Ubuntu, suggesting this may be git-daemon-specific behavior rather than a general Git issue. The core technical question revolves around path resolution differences between regular Git operations and the daemon context, particularly regarding wildcard expansion and relative path handling. This appears to be a genuine edge case in the CVE-2022-24765 mitigation implementation, with the reporter demonstrating consistent behavior across system upgrades. The email maintains the thread's focus on practical deployment concerns while surfacing new technical limitations in the proposed solution.
