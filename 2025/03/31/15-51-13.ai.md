This is patch 2/8 in the series removing the legacy merge-recursive implementation in favor of merge-ort. The patch focuses on converting the `builtin/merge-recursive.c` command to use merge-ort's `merge_ort_generic()` instead of `merge_recursive_generic()`.

The key technical changes are:
1. Swapping the include from merge-recursive.h to merge-ort-wrappers.h
2. Replacing the `merge_recursive_generic()` call with `merge_ort_generic()` while maintaining identical parameters
3. Updating several test files to account for behavioral differences between the merge backends

The test changes reflect merge-ort's improved handling of directory/file conflicts and rename/delete conflicts, which now produce two index entries per conflict rather than one. The patch also removes merge-recursive's special "Already up to date" message for toplevel tree matches, as merge-ort handles this case differently by checking tree matches throughout rather than just at toplevel.

The test checking merge-recursive's base tree name reporting is removed entirely since this was merge-recursive-specific behavior. Other tests are adjusted to expect merge-ort's conflict resolution patterns and index state representations.

This is a mechanical conversion that maintains the same interface while switching the backend, part of the systematic elimination of merge-recursive from the codebase. The changes are straightforward given Elijah Newren's deep expertise as the merge-ort architect, though reviewers will want to verify the test adjustments accurately reflect intended behavior.
