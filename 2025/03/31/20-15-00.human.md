Security configuration follow-up for git-daemon's safe directory handling.

MegaBrutal reports that Konstantin Ryabitsev's suggested system-wide `/etc/gitconfig` solution for public git servers isn't fully resolving their issues. While the wildcard pattern `/srv/git/* works for some cases, they're still seeing two specific failure modes: errors when the problematic directory is just "." (current directory), and apparent non-resolution of the wildcard pattern in git-daemon contexts.

The reporter notes they've tested this on Git 2.43.0 after a full system upgrade, suggesting the behavior may be specific to git-daemon rather than general Git operations. The core observation is that git-daemon appears stricter than regular Git commands in its path resolution and wildcard handling, though the exact mechanism isn't clear from the report.

This appears to be a continuation of the thread exploring edge cases in the post-CVE-24765 security model, specifically around daemon-specific path handling scenarios that were flagged as potential outstanding issues in the discussion. The email suggests there may be remaining gaps in how the safe.directory configuration interacts with git-daemon's operational model.
