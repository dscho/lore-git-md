Bugfix for test issues in repository ownership verification. This is a follow-up to the recently merged security improvements that prevent hardlink attacks between repositories owned by different users.

Brian M. Carlson addresses three test issues identified by SZEDER Gábor in the clone-local test suite. The main problem was that the `repo_is_hardlinked` helper was being called with the wrong path (repository top-level instead of .git directory), causing misleading test behavior. The patch makes three specific fixes: correcting the path passed to the helper, properly using `test_grep`'s negation syntax, and removing a stray newline.

The changes are minimal and focused - Carlson considered but declined to implement a more comprehensive solution involving adding negation support to `repo_is_hardlinked`, opting instead for targeted fixes that address the immediate test problems. The patch maintains the existing test coverage while making it more accurate and reliable.

This appears to be a straightforward improvement to test correctness in security-sensitive code, building on the recent work to verify repository ownership during clone operations. The changes are well-explained and limited in scope, suggesting they should be uncontroversial to merge.
