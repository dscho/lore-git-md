This is a refactoring patch in Patrick Steinhardt's reftable API improvement series, focusing on simplifying how restart points are tracked in reftable blocks.

The patch eliminates redundant tracking of block length by recognizing that the restart point offset can be derived from existing data. Instead of maintaining three separate variables (block length, restart count, and restart bytes pointer), it now tracks just the restart offset and count. This makes the code both simpler and more maintainable by reducing the number of variables that need to be kept in sync.

The changes touch the block reading logic in `reftable/block.c`, the block reader structure definition in `reftable/block.h`, and a debug printing function in `reftable/table.c`. The refactoring appears clean and well-justified, with the commit message clearly explaining the motivation and the changes align with the series' goal of improving the reftable API's clarity and maintainability.

This is a straightforward internal improvement that doesn't change functionality but makes the code easier to work with, particularly for external consumers of the reftable library. The patch fits naturally after the earlier structural changes in the series.
