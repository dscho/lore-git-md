This is a technical response to a feature inquiry about stash functionality, specifically the ability to create stash objects including untracked files without modifying the working tree. Patrick Steinhardt confirms Alexander Shpilkin's analysis of the current limitations in `builtin/stash.c`, where `do_create_stash()` either excludes untracked files or requires working tree modifications. 

The key technical obstacle is that `save_untracked_files()` currently operates by modifying the repository's index through `git-update-index`. Steinhardt suggests the solution would require modifying this function to work with an in-memory index instead, which would then enable clean support for a `--include-untracked` flag in `git stash create`. This change would satisfy the build system use case where preserving working tree state (including mtimes) is critical.

While acknowledging the validity of the feature request, Steinhardt notes he won't be implementing it himself but indicates patches implementing this approach would likely be accepted. The response maintains the thread's technical focus on stash internals while providing clear direction for potential implementation, though it doesn't address any alternative workarounds for the immediate need.
