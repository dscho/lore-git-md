Refactoring in Patrick Steinhardt's reftable API series (patch 11/16). This change separates block iterator initialization from seeking operations, making iterators reseekable by storing the block pointer during initialization rather than requiring it on each seek.

The patch modifies the block iterator interface to:
- Add a new `block_iter_init()` that takes the block pointer once
- Make `block_iter_seek_start()` and `block_iter_seek_key()` operate on already-initialized iterators
- Update all callers to the new pattern
- Adjust unit tests to match

The change prepares for exposing a `reftable_iterator` interface for blocks in future work. The implementation is straightforward - storing the block reference in the iterator allows subsequent seeks to reuse it without requiring the caller to pass it again. This continues the series' pattern of cleaning up internal interfaces while maintaining the same functionality.

The patch follows the established quality of the series, with thorough updates to both implementation and tests. It's a mechanical improvement that makes the API more flexible for future needs while keeping the same behavior.
