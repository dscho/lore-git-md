Feature addition for partial clone/fetch operations. This patch introduces a new `--must-filter` option to `git clone` and `git fetch` that makes filter support mandatory rather than optional. Currently, when a server doesn't support filtering, Git silently falls back to an unfiltered operation with just a warning. With this option, the operation will instead fail with an error.

The change adds the new option through several layers of the codebase - from command-line parsing in clone.c and fetch.c, through transport options, down to the fetch-pack implementation where the actual filter negotiation happens. The patch includes test cases demonstrating both the clone and fetch scenarios, though they're currently marked as test_expect_failure (likely because they require server-side changes to properly test).

The motivation appears to come from a StackOverflow question and prior mailing list discussion about making filter support more strict. The implementation is straightforward and touches all the right plumbing layers, though the test situation suggests there may be more work needed to fully validate the behavior.
