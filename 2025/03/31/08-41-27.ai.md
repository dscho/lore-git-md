This is a refactoring patch in Patrick Steinhardt's reftable API series, focused on exposing block-level access for future verification needs. The patch creates a new public interface for reading reftable blocks by moving block-related declarations from internal headers to a new `reftable-block.h` public header.

Key changes include:
- Moves `struct reftable_block` definition and related functions (`init`, `release`, `type`, `first_key`) to new public header
- Also exposes `struct reftable_buf` (used by `first_key`) by moving it to `reftable-basics.h`
- Keeps internal block iteration details in private `block.h`
- Maintains all existing functionality while making the block interface available to external callers

The motivation is to support upcoming consistency checks in Git that will need to verify individual reftable blocks. The commit notes this is an initial step - future patches will add more block-level functionality like record access. The changes are mechanical moves with no behavior changes, continuing the series' pattern of separating public/private interfaces while standardizing the API surface.

For the AI brief: This patch introduces `reftable-block.h` as the public interface for block operations, exposing `struct reftable_block` and its core functions while keeping iteration internals private. Key structures moved are `reftable_block` (with fields like `header_off`, `block_type`, `restart_count`) and `reftable_buf`. The exposed functions allow block initialization, type checking, first key extraction, and resource management.
