Refactoring patch in the reftable API renaming series.

This is patch 2/16 in Patrick Steinhardt's series to improve the reftable library's API and prepare it for standalone use. The change renames `struct reftable_reader` to `struct reftable_table` to better reflect its purpose of handling individual reftable files rather than just reading them. The commit explains that the current name was unclear and didn't match the naming pattern of other structures like `reftable_merged_table` and `reftable_stack`.

The patch makes extensive mechanical changes across the codebase to update all references to the renamed structure, including:
- Renaming the source files from reader.[ch] to table.[ch]
- Updating all function names and signatures (e.g. `reftable_reader_new` -> `reftable_table_new`)
- Modifying test files to use the new names
- Adjusting related data structures and variables to use "table" terminology

The changes are widespread but straightforward, touching 19 files with 467 lines added and 467 removed. The patch maintains all existing functionality while improving naming consistency. This is part of a larger effort to make the reftable library more usable by external projects like libgit2.
