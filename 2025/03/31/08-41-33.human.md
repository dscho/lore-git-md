Refactoring in Patrick Steinhardt's reftable API series, now exposing block type constants publicly. This is patch 15/16 in the v1 series that aims to improve the reftable implementation's standalone usability.

The change moves the block type constants (`BLOCK_TYPE_*`) from an internal header to a new public `reftable-constants.h` file, renaming them with an `REFTABLE_` prefix for consistency. This allows external callers to distinguish between different block types when using the newly exposed block-level APIs from earlier patches. The change is mechanical but important for the API's completeness, updating all internal usage sites to the new names.

The patch follows the series' pattern of carefully exposing implementation details while maintaining clear API boundaries. It's a straightforward change with thorough updates to both implementation and test files, though the diff is large (131 lines added, 117 removed) due to the widespread use of these constants. This prepares for upcoming consistency checking work that will need to inspect block types directly.
