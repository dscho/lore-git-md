Refactoring in Patrick Steinhardt's reftable API series (5/16). This patch continues the effort to clean up the reftable implementation by moving block reading logic entirely into the block reader subsystem.

Currently, block reading responsibilities are split between table and block components, requiring awkward ownership transfers of block data between them. The change makes the block reader fully responsible for reading blocks by having it take a block source and offset rather than a pre-read block. This simplifies ownership semantics and makes the API boundaries clearer.

The patch modifies `block_reader_init()` to handle the block data directly, including decompression for log blocks. It removes the now-unneeded `table_get_block()` helper and updates all callers. The test suite is adjusted to match the new interface, though the test cases themselves remain substantively the same.

This is a logical next step after the previous patch's block length tracking simplification, continuing the pattern of consolidating responsibilities within the block subsystem. The change appears well-contained and maintains existing functionality while making the code easier to reason about.
