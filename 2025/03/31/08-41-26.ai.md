Refactoring patch in Patrick Steinhardt's reftable API series, focusing on zlib type usage standardization. This patch (8/16 in v1) replaces typedef `z_stream` with explicit `struct z_stream_s` throughout the codebase to enable cleaner header dependencies, particularly for the upcoming public exposure of `struct reftable_block`. 

The change affects four files:
1. Updates documentation examples in `recover-corrupted-object-harder.adoc`
2. Modifies zlib-ng compatibility mapping in `zlib-compat.h`
3. Changes the stream type in `git_zstream` struct
4. Updates zstream pointer declarations in reftable's `block.h`

Key technical details:
- Maintains identical functionality while improving header hygiene
- Prepares for public API exposure where internal headers shouldn't be required
- Handles zlib-ng compatibility via `#define z_stream_s zng_stream_s`
- Removes an unnecessary forward declaration of `struct z_stream` that wasn't actually needed

This continues the series' pattern of mechanical groundwork changes that enable later API improvements, with a focus on making the reftable implementation more suitable for external consumption. The change is straightforward but important for the series' goal of better standalone usability.
