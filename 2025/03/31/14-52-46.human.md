This is a technical follow-up in the withdrawn Rust crate packaging series, specifically addressing the Windows symlink limitation that ultimately blocked the effort.

Johannes Schindelin responds to Josh Steadmon's conclusion that symlinks are the only Rust-recommended approach for embedded crates, offering a potential Windows workaround. He suggests using `MSYS=winsymlinks:nativestrict` in CI, similar to how Git for Windows handles symlinks in tests. However, he notes this may still fail if Git itself needs to create symlinks, as those patches haven't been upstreamed yet.

The email reveals two key technical points: 1) partial symlink support exists in Git for Windows (just `readlink()`), and 2) the full test suite doesn't currently pass with strict native symlinks enabled. While the series remains withdrawn, this exchange documents the specific Windows compatibility challenges that would need to be addressed for any future Rust integration attempts requiring symlinks.
