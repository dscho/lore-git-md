This is a technical follow-up in the SHA implementation reporting series, where Justin Tobler responds to Patrick Steinhardt's architectural suggestion about backend-defined symbols.

Justin agrees with Patrick's proposal to have SHA backends define their own `SHA1_BACKEND` symbol, which would centralize backend selection in hash.h rather than scattering it across the codebase. This approach would automatically ensure implementations properly identify themselves while maintaining compile-time safety checks. The change would make the build options output more robust by directly reflecting the actual backend selection rather than duplicating detection logic.

The response indicates Justin will implement this symbol-based approach in the next version of the patch series, moving away from the earlier if/elif cascade that Junio Hamano had critiqued for potential maintenance issues. This represents progress in the technical discussion, converging on an implementation that satisfies both the diagnostic goals and code maintainability concerns raised in the thread.

Key technical points for future reference:
- The new approach will use backend-defined `SHA1_BACKEND` symbols
- Backend selection logic will be centralized in hash.h
- Build options output will directly reflect the selected backend
- This avoids the maintenance concerns of duplicated if/elif cascades
