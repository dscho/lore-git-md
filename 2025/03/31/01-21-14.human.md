This is a bugfix and refactoring patch for git-p4, addressing encoding issues with Perforce error messages. The patch is part of an ongoing thread where Nikolay Shustov is working to fix failures that occur when git-p4 encounters non-UTF-8 error messages from Perforce servers not configured for Unicode.

The key change moves the metadata transcoding logic into a new `MetadataTranscoder` class, which handles error message decoding consistently with the existing fallback strategy (controlled by `git-p4.metadataDecodingStrategy` and `git-p4.metadataFallbackEncoding` configs). The immediate bug being fixed occurs during `git p4 clone` when Perforce returns error messages containing high-bit characters, which previously caused decoding failures at line 901 of git-p4.py.

The patch includes Python 3-specific test coverage through a new test script that verifies Unicode handling. While the technical approach appears sound, Phillip Wood has suggested splitting the refactoring from the bugfix and improving commit message clarity. Nikolay defends the class-based approach as more maintainable than alternatives, noting it avoids duplicating transcoding logic.

This is Nikolay's first contribution to Git, and he's actively seeking review from recent git-p4 contributors since the subsystem lacks active maintainers. The changes build on prior metadata transcoding work and solve a real migration pain point for organizations moving from Perforce to Git.
