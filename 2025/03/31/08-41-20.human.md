This is patch 2/16 in Patrick Steinhardt's reftable API refactoring series. The patch renames the core `reftable_reader` data structure to `reftable_table` to better reflect its purpose - it represents an individual reftable file that has been read from disk. The change aligns the naming of this structure with others in the codebase like `reftable_merged_table` and `reftable_stack`.

The rename causes widespread changes across the codebase (19 files modified, 467 lines added/removed) but is purely mechanical - all functionality remains the same. The commit message explains this change helps prepare the reftable library for standalone use by external projects by making the API naming more consistent and self-documenting.

This is part of a larger effort to improve the reftable implementation's usability both within Git and for other projects like libgit2. The patch appears well-structured and focused, with clear motivation stated in the commit message. As an early patch in the series, it sets up naming conventions that will be used throughout the rest of the refactoring work.
