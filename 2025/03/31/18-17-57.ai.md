Platform compatibility follow-up with static type checking proposal.

This email from SZEDER Gábor builds on the resolved s390x/sparc64 test failures by proposing a compile-time type checking mechanism for parse-options macros. The thread had previously identified and fixed a type mismatch where `OPT_INTEGER()` was incorrectly used with a `size_t` field, causing platform-specific failures on big-endian architectures.

The proposal suggests modifying `OPT_INTEGER_F` to include a compile-time assertion that the target variable matches the expected integer size, using a division-by-zero trick that would trigger a compiler error when types mismatch. The example shows this catching the original `backfill` issue where `ctx.min_batch_size` (size_t) was incorrectly paired with `OPT_INTEGER`.

Key technical aspects:
- Modifies `parse-options.h` to include size validation
- Uses `0/(sizeof(*v) == sizeof(int))` to force compile error on mismatch
- Demonstrates the error message for the backfill case
- Acknowledges limitations: ugly implementation and unclear error messages
- Notes this would need extension to other OPT_* macros

The email positions this as a conceptual proof rather than a polished solution, explicitly stating the approach needs refinement to be production-worthy. It serves as a thought-provoking follow-up to the resolved platform issues, suggesting preventative measures against similar type-safety bugs while recognizing the implementation challenges involved.
