This is a follow-up discussion in the ongoing thread about reporting SHA implementations in Git's build options. Justin Tobler responds to Junio Hamano's feedback on the implementation approach for the patch that would show which cryptographic backends Git was built with.

The key points in this response:
1. Justin agrees with Junio's concern about the if/elif cascade being confusing and hard to maintain, especially since other parts of the code (hash.h and Makefile) have their own precedence orders.
2. He plans to change the implementation to use independent #if blocks rather than the cascading if/elif structure, which will make the code clearer and help catch misconfigurations.
3. There's discussion about how to handle the special case of DC_SHA1 options (collision detection variants), with Justin leaning toward treating them separately from the main SHA1 implementations.
4. Justin also agrees with Junio's suggestion to use the raw symbol names (like SHA1_OPENSSL) rather than creating human-readable names, as this better serves the developer audience for this feature.

This email moves the discussion forward by showing clear agreement on the architectural concerns while identifying one remaining design question (how to handle DC_SHA1 variants). The changes Justin proposes would make the implementation more maintainable while keeping the same functionality. The thread appears to be converging on a solution that addresses both the technical and maintainability aspects of the feature.
