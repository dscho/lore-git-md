This thread has finalized the integration of Git's performance benchmark infrastructure (`t/perf`) with the Meson build system, with Patrick Steinhardt's v3 series now technically complete and approved by maintainers. The key decision was adopting a feature option approach for handling the `time` command, with three states: `auto` (default, silently disables if GNU `time` is missing), `enabled` (errors if GNU `time` is missing), and `disabled`. Junio Hamano explicitly endorsed this approach as balancing developer needs, while Christian Couder suggested a possible future enhancement using placeholders.

Patrick has now clarified that the implementation intentionally requires GNU `time` specifically (excluding shell built-ins) to match the richer output capabilities used by the benchmarks, which aligns with the existing `USR_BIN_TIME` prerequisite in the test infrastructure. While there's potential to refactor this prerequisite for better portability, it's currently low priority since only one test uses it.

All core functionality is operational (47 tests supported, SHA256/reftable working), with only minor items remaining: Karthik Nayak's header listing investigation, documentation updates for the feature option behavior, and resolution of some CI issues (Linux Meson job failures and Windows Python asyncio crashes in Meson PR #14311). With maintainer approval secured and technical questions resolved, the series appears ready for final review pending these last documentation and CI fixes.
