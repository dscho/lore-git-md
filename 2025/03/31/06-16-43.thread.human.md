This thread covers Patrick Steinhardt's work to integrate Git's performance benchmark infrastructure (`t/perf`) with the Meson build system. The series (now at v5) has evolved through several iterations addressing technical requirements like repository format preservation, Perl script portability, and out-of-tree build support. The latest patch completes the implementation by wiring up user-configurable benchmark options that get written to GIT-BUILD-OPTIONS.

The implementation now provides three key configuration knobs through Meson: `benchmark_repo` (standard test repository), `benchmark_large_repo` (for scaling tests), and `benchmark_repeat_count` (test repetitions). These differ slightly from the Makefile build by excluding some legacy options that Meson doesn't use. The patch also ensures proper string quoting when writing to GIT-BUILD-OPTIONS.

With this final piece in place, the series appears complete - it handles all documented functionality including edge cases like non-default repository formats (SHA256/reftable), non-standard Perl installations (NixOS), and alternative build systems (Make/CMake/Meson). Christian Couder has acknowledged the documentation is satisfactory, and there are no outstanding technical objections. While some related work remains (Karthik Nayak's header listing investigation and a pending Meson upstream PR), the core benchmark integration is ready for merging. The implementation maintains compatibility with complex benchmarking scenarios that still require the traditional `t/perf/run` script while providing full Meson support for most use cases.
