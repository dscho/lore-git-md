This is patch 5/8 in Elijah Newren's series to fully remove the legacy merge-recursive implementation in favor of merge-ort. The patch focuses on converting the remaining recursive merge operations to use merge-ort exclusively.

The changes are straightforward but significant:
1. Removes the last conditional merge backend selection in `builtin/merge.c`, always using `merge_ort_recursive()` instead of the old `merge_recursive()`
2. Similarly updates `sequencer.c` to unconditionally use merge-ort for recursive merges, removing 10 lines of conditional logic while preserving the same TODO about potential working tree optimizations
3. Updates test t7615 to remove the explicit GIT_TEST_MERGE_ALGORITHM=recursive setting since merge-ort is now the only option

Key technical details:
- The patch removes the final `#include "merge-recursive.h"` from `builtin/merge.c`
- Updates documentation comments in `sequencer.c` to reference `merge_ort_recursive()` instead of `merge_recursive()`
- Maintains the same return value handling (1 for clean, 0 for unclean) but updates the comment to reflect the ort function name
- The test change reflects that merge-ort is now the only implementation and no longer needs explicit algorithm selection

This continues the mechanical conversion pattern seen in previous patches, with no functional changes intended beyond switching the backend. The changes are consistent with the series' goal of completely removing merge-recursive now that merge-ort has feature parity (including the diff algorithm selection capability added earlier in the series).
