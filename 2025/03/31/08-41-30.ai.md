This is patch 12/16 in Patrick Steinhardt's reftable API refactoring series, introducing a generic iterator interface for reftable records. The patch exposes a new `reftable_block_init_iterator()` function that creates a `reftable_iterator` from a block, implementing the vtable pattern used elsewhere in the reftable code. This enables fine-grained iteration through individual blocks' records, which will be used for implementing consistency checks in the reftable backend.

The implementation wraps the existing `block_iter` functionality in the standard iterator interface, with three key operations: seek, next, and close. The patch includes thorough unit tests that verify:
- Basic iteration through 20 reference records
- Seeking to both existing and non-existent keys
- Proper cleanup of resources
- Type safety checks (rejecting mismatched record types)

The changes touch the block subsystem's public interface (`reftable-block.h`), implementation (`block.c`), and tests. This continues the series' pattern of exposing lower-level operations while maintaining clear boundaries between public and private APIs. The iterator interface matches the style established in earlier patches and prepares for the planned `reftable_iterator` integration mentioned in the commit message.

This is a technical building block that enables the consistency checking functionality mentioned as a series goal, though that higher-level integration isn't shown here. The implementation appears solid with comprehensive test coverage, following the established patterns from previous patches in the series.
