Bugfix investigation for platform-specific backfill test failures, focusing on potential integer type mismatch in batch size handling.

Patrick Steinhardt responds to Todd Zullinger's s390x test artifacts with a concrete hypothesis about the root cause. The key observation is that `--min-batch-size` uses `OPT_INTEGER()` to parse into a `size_t` field (`ctx.min_batch_size`), which could cause problems on big-endian systems. The proposed fix changes this to use `OPT_MAGNITUDE` with an intermediate `unsigned long` variable, which is then assigned to the context struct.

The technical detail shows:
- Current implementation passes `size_t` field directly to `OPT_INTEGER`
- Proposed fix introduces type-safe conversion via `unsigned long`
- Maintains same default value (50000) but with proper type handling
- Preserves all other backfill behavior (sparse checkout handling etc.)
