This is a security configuration follow-up in the ongoing discussion about git-daemon setup post-CVE-2022-24765. Konstantin Ryabitsev responds to a user struggling with "dubious ownership" errors when running a public read-only git server, offering a system-wide configuration solution.

The reply suggests using `/etc/gitconfig` to mark all repositories under `/srv/git/` as safe directories, providing a cleaner alternative to the user's current workaround of using a `.gitconfig` in the service account's home directory. This approach would apply the safe directory setting globally rather than per-user.

The response is brief and technical, directly addressing the configuration challenge while maintaining the security improvements introduced by the CVE fixes. It doesn't engage with the broader concerns about marking "." as safe that were raised in the thread, focusing instead on the immediate path resolution issue. This appears to be a pragmatic solution for system administrators managing public git repositories, though readers following the full thread might want to consider the security implications of wildcard patterns in safe directory declarations.
