Documentation patch addressing Asciidoctor formatting issues in Git manpages. This is a follow-up to SZEDER Gábor's report about problematic `{empty}` strings appearing in rendered output when building with Asciidoctor, particularly affecting command synopses with ellipsis notation (`...`).

The patch modifies `asciidoctor-extensions.rb.in` to better handle triple-dot patterns, with special cases for `git-mv <source>... <dest>` syntax and standalone dots in monospaced/quote contexts. Jean-Noël Avila confirms the fix works for `git-diff` rendering issues, though SZEDER notes the commit message could be more detailed about the specific problems being solved.

A remaining issue surfaces in diff-related manpages (diff-files, diff-index, log) that include content from 'diff-generate-patch.adoc'. Jean-Noël cannot reproduce this with Asciidoctor 2.0.23, suggesting the behavior might be version-dependent. The discussion hints at potential future work to replace the complex regex patterns with a parser generator for better maintainability.

The technical changes appear sound but reveal the ongoing challenge of maintaining documentation toolchain compatibility across different versions. The thread shows active collaboration between the reporter and maintainer to track down edge cases in the formatting rules.
