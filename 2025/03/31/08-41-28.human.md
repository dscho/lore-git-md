Refactoring in Patrick Steinhardt's reftable API work (patch 10/16). This change simplifies the block iterator implementation by storing a direct pointer to the underlying `reftable_block` rather than copying individual fields. 

The patch addresses several issues with the current approach: redundant storage of block data, inconsistent variable naming between structures, and unnecessary bookkeeping. By storing the block pointer directly, the code becomes both simpler and more maintainable. The change also prepares for future work to decouple the iterator's lifetime from seeking operations.

This is a mechanical refactoring with no behavior changes, continuing the series' pattern of cleaning up the reftable implementation. The diff shows straightforward changes to `block.c` and `block.h`, removing copied fields and updating access patterns to use the block pointer directly. The modification maintains the existing functionality while reducing complexity.
