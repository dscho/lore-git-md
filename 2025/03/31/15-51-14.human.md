This is patch 3/8 in Elijah Newren's series to fully replace merge-recursive with merge-ort, marking the final step in the merge-ort migration effort. The patch adds diff-algorithm selection capability to merge-ort, bringing it to feature parity with merge-recursive before the latter is removed.

The change makes merge-ort respect the same diff-algorithm options that merge-recursive did (histogram, patience, minimal, myers), though merge-ort will now default to histogram diff while merge-recursive defaults to myers. The implementation removes merge-ort's hardcoded histogram diff setting and moves the default to init_merge_options(), while updating documentation to show both strategies now support the same options.

This is a key functional change needed before removing merge-recursive, as it ensures users relying on alternative diff algorithms during merges won't lose that capability. The patch technically changes merge-recursive's default diff algorithm too, but since the next patches will remove merge-recursive entirely, this is harmless. Documentation updates clarify the options while removing merge-recursive-specific notes.

The changes are straightforward - one line removals in merge-ort.c and merge-recursive.c plus documentation rewrites. As with the rest of this series, the change is mechanical rather than innovative, focused on achieving behavioral parity before the final switchover.
