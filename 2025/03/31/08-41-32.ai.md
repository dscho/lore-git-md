This is a refactoring patch in Patrick Steinhardt's reftable API series, introducing a new block-level iterator interface for table contents.

The patch adds a `reftable_table_iterator` that allows callers to sequentially access all blocks in a reftable. The iterator provides three main operations: initialization (`reftable_table_init_table_iterator`), iteration (`reftable_table_iterator_next`), and cleanup (`reftable_table_iterator_release`). Each iteration step returns a pointer to a `reftable_block` structure containing the block's type, header offset, and restart count.

The implementation builds on existing table iteration infrastructure but exposes it through a new public interface. A key motivation is supporting upcoming consistency checks for the reftable backend, though it will also be used to reimplement the debugging `reftable_table_print_blocks()` function in a future patch.

The change includes comprehensive unit tests that:
- Verify correct iteration through all blocks in a sample table
- Validate block metadata (type, header offset, restart count)
- Cross-check record counts by using the new iterator with the existing record-level iteration API
- Confirm proper cleanup behavior

The patch follows the series' pattern of carefully exposing implementation details while maintaining clear API boundaries. It depends on the table structure exposure from Patch 13 and prepares for subsequent consistency checking work.
