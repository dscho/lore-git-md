This thread marks the final stages of removing Git's legacy merge-recursive implementation in favor of merge-ort, completing a multi-year architectural transition. Elijah Newren's 8-patch series systematically converts all remaining callers to use merge-ort before deleting merge-recursive.[ch] and its test infrastructure. The current version (v2) shows the technical work is complete, with all functionality now handled by merge-ort including recent additions like diff-algorithm selection.

Junio Hamano, while not objecting to the technical changes, has raised important documentation concerns about how the removal is framed. He notes the current messages describe this as "debugging" work when it's actually eliminating known-buggy code, suggesting the commit messages should explicitly mention which bugs are being fixed by removing merge-recursive. This feedback focuses on ensuring the project's history accurately reflects the motivation and impact of this significant change.

The series has seen light review so far, with Eric Sunshine catching minor typos that were promptly fixed. The lack of substantive objections suggests broad agreement on the technical approach. With Junio's documentation feedback addressed, this series - representing the culmination of years of work to modernize Git's merge machinery - appears ready for merging.
