Elijah Newren continues his series to fully replace Git's legacy merge-recursive implementation with merge-ort, now at version 2 of the 8-patch series. The latest patch (3/8) addresses one of the final functional differences between the two implementations by enabling configurable diff algorithms in merge-ort, matching merge-recursive's capability. 

The change removes merge-ort's hardcoded use of the histogram diff algorithm, making the selection configurable while maintaining histogram as the default for backward compatibility. Documentation has been updated to reflect that both strategies now support the same diff-algorithm options, eliminating what was previously a documented distinction. This brings merge-ort to full feature parity with merge-recursive regarding diff handling.

The series as a whole systematically converts all remaining callers to use merge-ort before removing merge-recursive's code and test infrastructure entirely. Eric Sunshine provided editorial review on version 1 which has been incorporated, and no substantive objections have been raised. With this diff algorithm parity achieved, the series appears technically complete and ready for final review before merging. This represents the culmination of a multi-year effort to modernize Git's merge machinery, with merge-ort set to become the sole merge backend in the codebase.
