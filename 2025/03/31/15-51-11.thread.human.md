Elijah Newren has completed his multi-year effort to replace Git's legacy merge-recursive implementation with the modern merge-ort backend. The final v5 patch series removes all remaining traces of merge-recursive, including its source files, test infrastructure, and the special testing environment variable that previously allowed switching between the two implementations. The changes affect core commands like merge, rebase, and revert, but maintain backward compatibility by treating "recursive" as an alias for "ort."

The series has gone through several iterations, with v5 focusing on the final cleanup: moving shared functions to merge-ort.c, updating documentation to reflect the current state, and removing now-obsolete test scaffolding. The last patch just arrived removes the GIT_TEST_MERGE_ALGORITHM variable from three builtin commands, eliminating the last vestige of the dual-implementation testing infrastructure.

All technical concerns appear resolved, with Junio Hamano having previously approved the direction. The changes represent a significant simplification of Git's codebase, removing about 800 lines of code while maintaining all existing functionality. This marks the successful conclusion of a major architectural improvement that began with merge-ort's introduction in Git 2.33.
