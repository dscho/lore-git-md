Elijah Newren continues his multi-year effort to fully replace Git's legacy merge-recursive implementation with merge-ort. The current v3 series (8 patches) systematically converts the remaining callers - checkout.c and builtin/merge-recursive.c - while maintaining identical interfaces. The latest patch ensures diff algorithm handling parity between the two backends, removing merge-ort's hardcoded histogram diff preference and moving the default to init_merge_options() where both strategies can share it.

Key technical changes include successful conversions of checkout.c to merge_ort_nonrecursive() and builtin/merge-recursive.c to merge_ort_generic(), with test updates that document merge-ort's improved handling of directory/file conflicts, rename/delete cases, and toplevel tree matching. The diff algorithm change maintains backward compatibility while unifying the documentation, though merge-ort still defaults to histogram diff while merge-recursive used myers.

The work represents the final stages of this architectural shift, with all major technical components now aligned between the implementations. Remaining items include verification of edge cases in the sequencer and final review of documentation updates. Junio Hamano has previously approved the technical direction, and the series follows the established pattern of mechanical changes first, followed by removal of the old implementation. This marks the culmination of work begun when merge-ort became the default strategy in Git 2.33.0.
