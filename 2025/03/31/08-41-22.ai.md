This is a refactoring patch in Patrick Steinhardt's reftable API improvement series, specifically focusing on simplifying how restart points are tracked in reftable blocks.

The patch eliminates redundant tracking of block length by recognizing that the restart point offset (`restart_off`) can serve as both the block length and the pointer to restart data. It replaces three variables (`block_len`, `restart_bytes`, and `restart_count`) with just two (`restart_off` and `restart_count`), where `restart_off` now serves dual purpose as both the offset to restart data and the effective block length.

Key technical changes include:
- Replaces `block_len` and `restart_bytes` with single `restart_off` field in `struct block_reader`
- Updates all related calculations to use `restart_off` instead of the removed fields
- Improves documentation by clarifying the purpose of restart point fields
- Maintains identical functionality while reducing bookkeeping overhead

The changes affect several core reftable operations including block reading, iteration, and seeking. The patch follows logically from the earlier structural changes in the series (license standardization and API renaming) and continues the pattern of simplifying the reftable implementation while maintaining its external behavior.
