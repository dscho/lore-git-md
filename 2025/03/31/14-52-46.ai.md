This is a technical follow-up in the withdrawn Rust crate packaging series, specifically addressing the Windows symlink limitation that ultimately blocked the effort.

Johannes Schindelin responds to Josh Steadmon's conclusion that symlinks are the only Rust-recommended approach for embedded crates, which fails on Windows CI. He suggests trying `MSYS=winsymlinks:nativestrict` as used in Git for Windows' test suite, while noting this might still fail if Git itself needs to create symlinks. He mentions partial upstream support exists for `readlink()` functionality but cautions that the full test suite doesn't currently pass under this mode.

The email highlights the specific technical hurdle (Windows symlink handling) that proved insurmountable for the Rust integration approach, while offering potential workarounds that come with their own limitations. This reinforces the thread's conclusion that platform constraints forced withdrawal of an otherwise complete solution. The response maintains focus on the core technical challenge while acknowledging the broader context of incomplete Windows support in this area.
