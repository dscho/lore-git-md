Bugfix for `--reset-author` behavior in post-commit hooks. 

Devste Devste reports that when using `git commit --amend --reset-author` in a post-commit hook, the author date's timezone is not properly reset to UTC (+0000) while the committer date is. The issue only manifests when run through the hook - manually executing the same command or using explicit `--date` formatting works as expected.

The post-commit hook shown attempts to standardize commit timestamps to UTC by setting TZ=UTC0 and skipping recursive hook execution. The bug appears to be specific to the interaction between `--reset-author` and hook execution context, suggesting the environment variable handling may differ between direct CLI usage and hook execution.

This looks like a legitimate edge case in Git's timestamp handling that could affect users who rely on post-commit hooks to normalize commit metadata. The report is clear and includes reproduction steps showing both the broken and working scenarios, making it easy to verify. The impact appears limited to this specific hook+flag combination, but the behavior is clearly inconsistent with manual operation.
