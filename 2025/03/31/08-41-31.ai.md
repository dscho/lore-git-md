This is part 13 of Patrick Steinhardt's reftable API refactoring series, focusing on exposing internal structures to the public interface. The patch moves the `reftable_table` struct definition from private `table.h` to public `reftable-table.h`, making its fields accessible to callers.

The change is motivated by upcoming consistency checking functionality that will need direct access to the table structure. The exposed struct contains metadata about the reftable file including:
- Block source and size information
- Hash function used
- Block size and update index ranges
- Offsets for ref/obj/log sections
- Reference counting

This continues the series' pattern of carefully exposing implementation details to support future API work while maintaining clear boundaries. The patch is purely mechanical - moving the existing struct definition between headers without modifying its contents. It follows logically from the iterator interface standardization in patch 12, as both prepare for the planned consistency checking features.

Key technical points for future reference:
- `struct reftable_table` now public with all fields exposed
- Companion `struct reftable_table_offsets` also made public
- No behavior changes - just visibility modification
- Maintains same header structure and documentation
- Part of enabling future consistency checking functionality

The change is straightforward and aligns with the series' goals of improving API usability while keeping implementation details cleanly separated. It follows the established pattern of mechanical groundwork that enables subsequent functional changes.
