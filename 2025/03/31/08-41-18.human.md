This is a major refactoring of the reftable API, aimed at both improving the library's standalone usability and exposing lower-level block access for upcoming consistency checks in Git. Patrick Steinhardt's 16-part series does three main things:

First, it renames several core data structures to be more intuitive and consistent (`reftable_reader` → `reftable_table`, `reftable_block_reader` → `reftable_block`, etc.), making the API clearer for potential new users like libgit2. The changes are systematic and appear well-considered.

Second, the series exposes previously internal block-level access through new iterator interfaces. This enables Git to implement future reftable consistency checks by examining individual blocks and their records - a capability that wasn't possible before but seems carefully gated behind appropriate abstractions.

Third, it includes various cleanup work like license header fixes and moving test-specific code out of the core library. The changes are wide-ranging (54 files touched) but focused on the reftable subsystem, with extensive test updates showing good attention to maintaining correctness.

The series builds on recent reftable work and appears technically sound, though its size means reviewers will want to examine the block access changes particularly carefully. The clear cover letter and structured approach make this easier to assess than most large refactors.
