Refactoring in Patrick Steinhardt's reftable API series (patch 6/16). This change renames `struct reftable_block` to `struct reftable_block_data` to better reflect its role as a simple data container for reftable blocks, distinguishing it from the upcoming `reftable_block` structure that will handle block access logic.

The patch updates all related function names and call sites to match the new terminology:
- `block_source_return_block()` becomes `block_source_release_data()`
- `block_source_read_block()` becomes `block_source_read_data()`
- Updates vtable method names and implementations
- Modifies 8 files with 54 line changes (adds/removes)

This is a mechanical rename that prepares for the next patch's introduction of the new `reftable_block` structure. The changes are consistent with the series' goal of clarifying API boundaries between data storage and access layers in the reftable implementation. All test cases are updated to use the new naming scheme.
