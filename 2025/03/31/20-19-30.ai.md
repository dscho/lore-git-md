Bugfix targeting commit metadata handling in post-commit hooks.

This email reports an inconsistency in how `--reset-author` handles timezone information when used within a post-commit hook. The author demonstrates that while `--reset-author` correctly sets the committer date to UTC0, it fails to do the same for the author date when executed in a hook context, despite working correctly when run manually.

The issue is well-demonstrated with a reproducible test case showing the discrepancy between author and committer timezones. The reporter provides two working alternatives: manually running the same command outside the hook context, or using explicit `--date` formatting instead of `--reset-author`. This suggests the problem is specific to hook execution rather than a fundamental flaw in the `--reset-author` functionality.

Key technical details include:
- The post-commit hook implementation shown uses environment variable guards (`SKIP_POST_COMMIT`) to prevent recursion
- The test verification uses `git show` with custom formatting to inspect both author and committer metadata
- The workaround using explicit `--date` formatting suggests the issue may lie in how `--reset-author` processes timezone information during hook execution

This appears to be a legitimate bug in Git's hook handling, though the impact is limited to cases where both post-commit hooks and `--reset-author` are used together while requiring UTC0 timezone normalization. The clear reproduction steps and analysis make this a strong bug report worth investigating.
