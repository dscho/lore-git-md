This is a documentation patch reporting formatting issues in the Git man pages when built with Asciidoctor. SZEDER Gábor points out that recent changes to standardize documentation formatting (part of a series by Jean-Noël Avila) are causing unwanted `{empty}` strings to appear in the rendered output of `git-diff` and other man pages that include diff formatting.

The issue appears when using Asciidoctor 2.0.16, while the older AsciiDoc processor renders the pages correctly. The problem manifests in two places: in the `git-diff` synopsis section and in diff header formatting examples that appear in multiple man pages. This suggests the new documentation guidelines may need adjustment to work correctly across different documentation processors.

The report is technical and specific, showing the exact problematic output and the toolchain used to reproduce it. This appears to be a genuine formatting regression that would affect users reading man pages built with modern tooling. The issue is part of a larger documentation standardization effort (patch series v4 1/5), but this email focuses specifically on the rendering problems introduced by those changes.
