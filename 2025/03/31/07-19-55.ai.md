This is a technical discussion about the implementation approach for reporting SHA backends in `git version --build-options`. Patrick Steinhardt responds to Junio C Hamano's concerns about the current if/elif/endif approach in patch 1/2 of Justin Tobler's series.

Patrick proposes an alternative implementation strategy where each SHA backend would define its own `SHA1_BACKEND` symbol, which would be used for reporting. This would:
1. Enforce implementation consistency by requiring the symbol definition
2. Potentially allow marking unsafe implementations via `SHA1_UNSAFE_BACKEND`
3. Avoid the maintenance burden of the if/elif cascade

The suggestion builds on Junio's earlier architectural concerns about the current implementation's fragility and maintainability, particularly around:
- Potential misalignment with hash.h's assumptions
- Difficulty adding new implementations
- Risk of inconsistent behavior if multiple backends are defined

This moves the discussion forward by offering a concrete alternative that addresses Junio's technical concerns while maintaining the original goal of reporting SHA implementations. The proposal would require coordination with the build system and backend implementations, but could provide a more robust foundation than the current approach.
