This is a CI/build system patch that completes the v2 series of build system fixes by ensuring consistent Visual Studio toolchain usage in Windows CI jobs.

The patch addresses an inconsistency where GitHub Workflows builds were unintentionally using GCC instead of the intended Visual Studio toolchain for Meson-based Windows builds. This happened because Meson would auto-select GCC when present in PATH, despite the job's purpose being to test Visual Studio compatibility. The fix explicitly passes `--vsenv` to force Visual Studio toolchain usage in both GitHub and GitLab CI configurations, making the behavior consistent across platforms.

Key technical details:
- Modifies both `.github/workflows/main.yml` and `.gitlab-ci.yml`
- Adds `--vsenv` flag to `meson setup` commands
- Maintains existing Meson configuration flags (`-Dperl=disabled`, `-Dcredential_helpers=wincred`)
- Includes GitLab CI change for consistency despite it not being strictly necessary there
- Fixes a regression from commit 7304bd2bc39 that intended Visual Studio usage but didn't enforce it

The change is well-motivated by a report from Johannes Schindelin and cleanly implements the solution with minimal changes to both CI configurations. As the final patch in a reviewed series, it appears ready for inclusion, completing the cross-platform CI coverage improvements started earlier in the series.
