Documentation patch addressing Asciidoctor formatting issues with triple-dot notation. This is part of Jean-Noël Avila's ongoing series to improve manual page formatting, specifically fixing a problem where triple-dots in command synopses (like `git-mv <source>... <dest>`) were being incorrectly processed.

The patch modifies the Asciidoctor extension to properly handle triple-dots that appear at line boundaries, ensuring they're rendered as literal command syntax rather than being misinterpreted as ellipses. The changes touch the same extension file that was previously identified as causing `{empty}` string artifacts in the rendered output when built with Asciidoctor 2.0.16.

This appears to be a focused technical fix that builds on the earlier discussion about synopsis formatting issues. The changes are surgical - adding specific handling for line-boundary dots while maintaining the existing behavior for other cases.
