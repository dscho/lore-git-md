Refactoring in Patrick Steinhardt's reftable API series (patch 10/16). This change simplifies the block iterator implementation by storing a direct pointer to the underlying `reftable_block` rather than copying individual fields. The patch eliminates redundant storage of `block_len` and `hash_size` in the iterator since these can now be accessed through the block pointer.

Key technical details:
- Removes three fields from `struct block_iter` (`block`, `block_len`, `hash_size`) in favor of a single `reftable_block` pointer
- Updates all iterator operations to access block data through the new pointer
- Maintains the same functionality while reducing memory usage and simplifying the code
- Prepares for future changes to decouple iterator lifetime from seeking operations
- Touches both `reftable/block.c` and `reftable/block.h` with straightforward mechanical changes

This continues the series' pattern of cleaning up the reftable implementation while maintaining the public API surface. The change is purely internal and doesn't affect callers, though it does make the iterator's dependence on the block's lifetime more explicit in the type system.
