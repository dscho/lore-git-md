This is part 9 of Patrick Steinhardt's reftable API refactoring series, focusing on exposing a public interface for block-level access. The patch moves the block reading interface from internal headers to a new public `reftable-block.h`, making it available for external consumers of the reftable library.

The key change is exposing the `reftable_block` struct and related functions that allow direct reading of individual blocks from reftable files. This is motivated by upcoming needs in Git for low-level consistency checking of reftable data, where verifying each block individually will be required. The patch also moves the `reftable_buf` definition to the public basics header since it's needed for the block key reading function.

The implementation looks clean and focused - it's primarily moving existing code to a new location with improved documentation, rather than introducing new functionality. The commit message notes this is just the first step in exposing block-level API, with more functionality to come in later patches. This aligns well with the series' overall goals of improving the reftable library's standalone usability while enabling new internal verification capabilities.
