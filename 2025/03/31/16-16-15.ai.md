This is a feature patch adding a new `--must-filter` option to `git fetch` and `git clone`. The option makes these commands fail with an error when the server doesn't support the requested filter, rather than just warning and continuing without filtering as they do currently.

The patch adds the new option flag through the command line interfaces of both commands, propagates it through the transport layer via a new `must_filter` field in `struct git_transport_options`, and ultimately checks it in `fetch-pack.c` where the server's filter capability is verified. When `--must-filter` is set and the server doesn't support filtering, the operation will now `die()` instead of just warning.

The implementation touches several key areas: command line parsing in `builtin/{clone,fetch}.c`, transport plumbing in `transport.{c,h}`, the fetch-pack protocol handling in `fetch-pack.{c,h}`, and adds new test cases in `t0410-partial-clone.sh`. The test cases are currently marked as `test_expect_failure`, suggesting they may not yet be passing (or perhaps are just placeholders).

The motivation appears to come from a Stack Overflow question and a prior mailing list discussion (linked in the email) about making filter failures more strict. The patch provides a way for users to ensure their partial clone/fetch operations actually get the filtering behavior they requested, rather than silently falling back to unfiltered operations when the server lacks support.
