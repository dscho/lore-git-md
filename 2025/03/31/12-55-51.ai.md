Documentation patch addressing Asciidoctor formatting issue with triple-dot syntax. This is part of an ongoing series to improve manual page formatting, specifically following up on SZEDER Gábor's report about `{empty}` strings appearing in rendered output when using Asciidoctor 2.0.16.

The patch modifies the Asciidoctor extension processing to better handle triple-dot notation (`...`) in command synopses, which was being misinterpreted as an ellipsis. The changes affect three key areas in `asciidoctor-extensions.rb.in`: the main processing function now adds `{empty}` markers around dots, and two additional cases are added to handle standalone dots in monospaced and quoted contexts. The fix specifically mentions the `git-mv <source>... <dest>` case as an example where this was problematic.

The technical change involves regex pattern matching for dot sequences, with careful attention to context (not matching when dots appear within brackets or before certain characters). The patch maintains the existing formatting for other cases while adding the new dot-specific handling. This appears to be a focused fix for the reported issue, though it remains to be seen if it fully resolves the `{empty}` string problem across all documentation builds.
