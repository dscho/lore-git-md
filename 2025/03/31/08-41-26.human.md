This is a refactoring patch in Patrick Steinhardt's reftable API series, focused on zlib compatibility. The patch changes how Git handles zlib's stream structure throughout the codebase, replacing the typedef `z_stream` with the explicit `struct z_stream_s`. 

The change is motivated by upcoming work to expose the reftable block structure publicly - since the public header shouldn't depend on internal implementation details, it needs to work without the typedef that's currently provided via internal headers. The patch also removes an unnecessary forward declaration of `struct z_stream` that wasn't actually needed.

The changes are mechanical but important for the reftable API's future public exposure. The patch updates several files including documentation examples, zlib compatibility layers, and reftable internals. It maintains compatibility with zlib-ng via a define mapping. While not flashy, this is the kind of careful groundwork that makes larger architectural changes possible.
