Windows lockfile race condition fix - final agreement on NtStatus approach.

This email confirms consensus on using `RtlGetLastNtStatus()` to properly handle Windows-specific race conditions where file creation fails with EACCESS due to pending deletion. The discussion had considered three approaches: SQLite-style polling, reftable-specific handling, and the NTSTATUS solution. The latter was chosen for its precision in distinguishing between actual permission errors and pending deletion cases.

Key technical points settled:
- The solution will use Windows NT API to detect `STATUS_DELETE_PENDING`
- Initialization safety concerns were addressed (no risk of overwriting status during setup)
- The fix applies to Git's general lockfile subsystem, not just reftable
- SQLite polling approach (25ms delays, 10 attempts) remains documented as a fallback

The patch series is now ready to proceed with:
1. An uncontroversial Meson build fix for MSVC compatibility
2. The NTSTATUS-based solution for the race condition

This represents a pragmatic resolution balancing Git's reliability needs with Windows platform realities, where an undocumented API is being used due to the precision requirements of lockfile handling. The solution has received approval from Windows experts after thorough review of the technical tradeoffs.
