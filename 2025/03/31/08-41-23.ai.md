This is patch 5/16 in Patrick Steinhardt's reftable API refactoring series, continuing the work to improve the reftable subsystem's API design and internal structure. The patch focuses on cleaning up block reading responsibilities between the table and block subsystems.

The key change moves block reading logic entirely into the block reader subsystem, eliminating awkward ownership transfers of block data between components. Instead of passing around `struct reftable_block` objects, the API now takes a block source` and offset, with the block reader handling all reading operations internally. This clarifies subsystem boundaries and reduces error-prone ownership handoffs.

The patch modifies several key functions:
- `block_reader_init()` now takes a `reftable_block_source` rather than a pre-read block
- New helper `read_block()` centralizes block reading logic
- `block_type` tracking moves into `struct block_reader`
- Table-level block reading functions are removed in favor of direct block reader usage
- Test cases are updated to use the new initialization pattern

The changes affect core block handling in `reftable/block.[ch]` and table operations in `reftable/table.c`, with corresponding test updates. This continues the series' pattern of mechanical groundwork followed by substantive API improvements, here targeting clearer responsibility separation in the block reading pipeline. The patch maintains all existing functionality while simplifying the ownership model.
