This is patch 14/16 in Patrick Steinhardt's reftable API refactoring series, introducing a new block-level iterator for reftable tables. The patch adds a `reftable_table_iterator` that allows callers to examine each block in a reftable file individually, exposing previously internal block details like type, header offsets, and restart counts. This low-level access is needed for upcoming consistency checking functionality in the reftable backend.

The implementation follows the established pattern in this series - it wraps existing internal iteration logic in a clean public API while maintaining the same behavior. The iterator provides three key operations: initialization, block-by-block advancement, and cleanup. A comprehensive unit test verifies the iterator works correctly across different block types (ref, index, obj) with various record counts and restart points.

This change continues the series' progression toward exposing reftable internals in a controlled way.
