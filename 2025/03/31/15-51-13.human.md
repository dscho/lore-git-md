This is the second patch in Elijah Newren's series to fully replace the legacy merge-recursive backend with merge-ort. The patch converts the `builtin/merge-recursive.c` command to use `merge_ort_generic()` instead of `merge_recursive_generic()`, completing the switch for this remaining caller.

The changes are straightforward - swapping header includes and function calls while maintaining the same parameters and options structure. More interesting are the test adjustments that reveal behavioral differences between the backends. The patch updates several test files to account for merge-ort's improved handling of directory/file conflicts (now showing both versions in the index) and removes a test checking merge-recursive's special "Already up to date" message that merge-ort doesn't preserve.

The test changes demonstrate merge-ort's more consistent behavior, particularly around rename/delete conflicts where it properly tracks both sides in the index. Some tests are simplified or removed as they were checking merge-recursive-specific output patterns no longer relevant. The patch maintains all core functionality while cleaning up test expectations to match merge-ort's behavior.

This continues the mechanical but thorough conversion work needed before the final removal of merge-recursive in later patches. The changes are well-explained with references to prior commits that introduced the behavioral differences being accounted for.
