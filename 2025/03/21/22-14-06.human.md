Build system improvements for libgit-sys Rust crate integration. This cover letter introduces version 2 of a patch series that addresses packaging and build issues for the libgit-sys crate, which provides Rust bindings to Git's C API.

The series makes several key improvements: it moves build artifacts outside the source tree (a cleaner approach than the v1 strategy of cleaning after builds), adds parallel build support via Cargo's jobserver, excludes unnecessary files to meet crates.io's size limits, and adds required package metadata. The changes are confined to the contrib/libgit-sys/ directory and related build infrastructure.

Notably, this version abandons the post-build cleanup approach from v1 in favor of building out-of-tree from the start, which Josh Steadmon notes as a simplification. The series also now includes proper licensing and description fields required for crates.io publication, though publishing the dependent libgit-rs crate remains future work.

The changes appear well-considered, with clear explanations of the technical rationale and a logical progression from the previous discussion thread. The patch series seems ready for review, representing a practical solution to the immediate packaging needs while leaving the door open for potential Meson-based approaches in the future.
