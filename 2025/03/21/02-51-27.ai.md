Bugfix and refactoring patch for `git-send-email` SMTP authentication error handling. This is the first of two patches in Zheng Yuting's GSoC project to improve RFC 5321 compliance.

The patch restructures SMTP authentication in `git-send-email.perl` to properly capture all error conditions through several key changes:
1. Wraps the entire auth process (both SASL and basic auth paths) in a single `eval {}` block to catch exceptions
2. Introduces state tracking variables `$error` and `$result` to maintain error context
3. Unifies the previously separate SASL and basic auth code paths
4. Replaces boolean returns with explicit `1`/`0` returns for clarity
5. Adds a placeholder comment indicating future SMTP status code handling (to be implemented in patch 2/2)

The changes are confined to the `smtp_auth_maybe` subroutine, affecting 45 lines with a net +26/-19 diff. The implementation maintains backward compatibility while setting up infrastructure for the status code parsing in the next patch. Error messages now include specific status codes for debugging, addressing previous issues where non-credential errors were misclassified as auth failures.

This represents the structural foundation for the series, with all substantive review feedback from Junio Hamano already addressed in previous iterations. The patch is well-contained and clearly marks its relationship to the status code handling that follows in 2/2.
