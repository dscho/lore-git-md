This thread addressed an inconsistency in `git blame` porcelain output where ignored/unblamable lines weren't properly marked when using `--ignore-rev` or `--ignore-revs-file`. The discussion went through several iterations, starting with a proposal to modify SHA-1 line prefixes (rejected by Junio Hamano for backward compatibility reasons) before settling on a solution that adds new metadata lines while preserving the existing format.

The key participants - Karthik Nayak, Patrick Steinhardt, and Toon Claes - converged on an approach that emits "ignored" and "unblamable" status markers only in `--line-porcelain` mode, as these statuses depend on each line's individual blame history. Junio Hamano confirmed this as the correct design, noting it maintains backward compatibility while properly extending the porcelain format. The implementation in `builtin/blame.c` modifies `emit_one_suspect_detail()` to conditionally include these markers and updates tests in `t/t8013-blame-ignore-revs.sh`.

With the maintainer's approval, this represents the final resolution to the issue. The solution cleanly separates concerns - keeping the standard porcelain output unchanged while providing the new functionality through the existing line-porcelain extension point. This follows Git's porcelain extensibility guidelines and preserves compatibility with existing parsers while adding the requested visibility into ignored/unblamable lines.
