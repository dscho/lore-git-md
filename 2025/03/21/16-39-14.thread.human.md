This thread addresses a bug in `git blame`'s porcelain output where lines ignored via `--ignore-rev` or `--ignore-revs-file` weren't properly marked with the documented '?' (ignored) or '*' (unblamable) indicators. After Junio Hamano rejected an initial approach that would have modified SHA-1 line prefixes (due to backward compatibility concerns), Patrick Steinhardt proposed a cleaner solution using new metadata lines to indicate ignored/unblamable status while preserving the existing porcelain format.

The discussion has now reached consensus on the general approach, with Toon Claes raising a final implementation detail about how the new markers should interact with porcelain output's deduplication behavior. Specifically, he notes that while commit details are typically emitted once per commit in `--porcelain` mode, the ignored/unblamable status can vary per line - suggesting these markers may need special handling. This is a refinement rather than a fundamental objection, indicating the thread is nearing resolution.

The patch appears ready for finalization once this last edge case is addressed, with Patrick's solution satisfying both the functional requirement and Git's strict output format constraints. Junio's earlier involvement established the critical boundary conditions, and the current discussion focuses on ensuring consistent behavior across all porcelain output modes.
