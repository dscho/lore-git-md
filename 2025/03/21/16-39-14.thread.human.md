The thread addresses a bug in `git blame`'s porcelain output where lines ignored via `--ignore-rev` or marked as unblamable weren't showing the documented '?' and '*' markers when the corresponding config options were enabled. The initial patch proposed fixing this by directly adding these markers to the commit hash line in the output.

Junio Hamano has now weighed in with an important design consideration. While agreeing the markers should be visible in porcelain mode, he points out that modifying the hash line format would break existing parsers that rely on the strict 40-character SHA-1 format to detect new records. He explains how porcelain output is typically parsed - scripts look for the hash line as a record delimiter, then collect metadata lines before processing the content.

The discussion has shifted from implementation to interface design. We now need a solution that makes these markers available to porcelain consumers without breaking backward compatibility. Junio suggests exploring alternative approaches, likely involving additional metadata lines rather than changing the fundamental record format. The patch author will need to revise their approach based on this feedback to find a way to expose the markers that maintains compatibility with existing tools.
