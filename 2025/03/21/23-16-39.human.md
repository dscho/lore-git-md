This is the final patch in a v2 series addressing advice message suppression in Git, specifically focusing on the default branch name advice ("hint: Using 'master' as the name for the initial branch"). The patch implements an architectural improvement to make this advice properly respect Git's advice suppression system.

The change adds a new `ADVICE_DEFAULT_BRANCH_NAME` type to the advice system and modifies `repo_default_branch_name()` to use `advise_if_enabled()` instead of the unconditional `advise()`. This means the advice can now be suppressed via `--no-advice` or the config setting `advice.defaultBranchName=false`. The patch includes a test verifying this new behavior.

This completes the three-part solution to the regression where default branch name advice was appearing during bundle operations despite suppression flags. The change is well-contained, touching only the advice system and refs code while maintaining backward compatibility. The test coverage is thorough, checking both the positive case (advice shown) and negative case (advice suppressed).

The patch follows Git conventions and appears ready for review, building on previous discussion that established consensus about making default branch name advice properly suppressible. It represents the architectural half of the fix, complementing the earlier clone-specific changes in the series.
