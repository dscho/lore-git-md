This is the second patch in Zheng Yuting's GSoC project to improve SMTP error handling in `git-send-email`, completing the RFC 5321 compliance work started in the first patch. The implementation now adds proper SMTP status code parsing to distinguish between temporary (4xx) and permanent (5xx) errors, with appropriate retry behavior for each.

The patch modifies the SMTP authentication logic to parse status codes from error messages according to RFC 5321. Temporary errors (4xx codes) will allow retries by returning 1, while permanent errors (5xx codes) and unrecognized codes will return 0 to indicate failure. The changes maintain backward compatibility with existing behavior when no error occurs.

Key technical details include:
- Regex-based status code extraction from error messages
- Three distinct handling paths for temporary/permanent/unknown errors
- Warning messages that include the status code for debugging
- The same boolean return convention (1/0) established in the first patch
- Files touched: `git-send-email.perl` (+24/-3 lines)

This completes the series' goal of proper RFC 5321 compliance for SMTP error handling. The implementation has been through multiple review iterations with Junio Hamano and addresses all substantive feedback, making it ready for inclusion. The only remaining nit is a subject line formatting preference (using "sendemail" vs "send-email") that doesn't affect functionality.
