Bugfix for atomic fetch/prune crash regression. This patch addresses the serious regression introduced in Git v2.49.0-rc1 where `git fetch --atomic` would crash with a BUG message when encountering locked references. The root cause lies in c92abe71df's attempt to fix transaction memory leaks, which inadvertently caused `ref_transaction_abort()` to be called on already-closed transactions.

The fix modifies the error handling path in `builtin/fetch.c` to explicitly free failed transactions rather than relying on abort, preventing the BUG() trigger. Justin Tobler provides a clear reproduction case involving a mirrored repository with manually locked references, and includes a new test case that verifies the atomic fetch fails gracefully (without crashing) when references are locked. The test is marked REFFILES-specific since it relies on filesystem lock files.

Key technical details: The patch changes the transaction cleanup in the error path from implicit abort to explicit free+NULL assignment. This maintains the memory leak fix from c92abe71df while avoiding the closed-transaction assertion. The solution is straightforward and maintains the expected behavior where atomic operations either fully succeed or cleanly fail. The test case serves as both a regression guard and documentation of the expected behavior when atomic operations encounter locked references.
