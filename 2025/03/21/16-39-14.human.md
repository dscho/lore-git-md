Bugfix for `git blame` porcelain output regarding ignored/unblamable lines.

This patch fixes an inconsistency in `git blame` where the porcelain output mode wasn't showing markers for ignored and unblamable lines, despite these markers being available in the regular output mode. The markers ('?' for ignored lines and '*' for unblamable lines) are controlled by the `blame.markIgnoredLines` and `blame.markUnblamableLines` config options, which work with the `--ignore-rev` flags.

The fix is straightforward - it extends the marker output logic to porcelain mode by adding the same character prefixes. The patch includes new tests that verify the behavior matches between regular and porcelain output modes. This appears to be a genuine oversight rather than an intentional design choice, as the documentation doesn't mention any porcelain-mode exclusion.

The changes are cleanly implemented with clear test coverage. This seems like a low-risk quality-of-life improvement for users who rely on porcelain output while using blame's ignore features.
