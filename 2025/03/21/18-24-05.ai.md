Security-focused refinement of remote-object-info format string handling in v12.

This email from Peijian Ju responds to Jeff King's feedback on the remote-object-info security implementation, specifically addressing format string validation vulnerabilities. The discussion focuses on two key security improvements for the batch-command interface:

1. Format string validation is being strengthened with an allow-list approach (option 2 from Jeff's suggestions) that will only permit `%(objectname)` and `%(objectsize)` placeholders. This prevents segfaults from unsupported placeholders while being maintainable - new placeholders won't work until explicitly allowed.

2. The proposal introduces graceful handling of unsupported placeholders by returning "???" for requested but unavailable fields, rather than failing. This maintains backward compatibility while clearly indicating unsupported features. The email also clarifies behavior for three object location scenarios, establishing that remote-object-info should consistently query the remote even when objects exist locally, failing only when objects are purely local.

This represents the final security hardening for the remote object info feature, addressing the last identified vulnerability (format string validation) while maintaining usability. The changes will appear in v12 of the series, completing all security requirements identified through twelve rounds of review.
