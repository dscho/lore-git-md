Bugfix for `git blame` porcelain output regarding ignored/unblamable lines. This patch addresses an inconsistency where the porcelain mode wasn't showing the '?' and '*' markers for ignored and unblamable lines respectively, despite these markers being documented as working with the `--ignore-rev` and `--ignore-revs-file` options.

The fix modifies `builtin/blame.c` to emit these markers in porcelain mode when the corresponding config options (`blame.markIgnoredLines` and `blame.markUnblamableLines`) are enabled. The changes are made in the `emit_porcelain` function, adding marker output both for the initial line and any continuation lines.

The patch includes thorough test coverage in `t/t8013-blame-ignore-revs.sh`, adding new test cases specifically for porcelain output verification. The tests check both unblamable line marking (using '*') and ignored line marking (using '?') in porcelain mode, ensuring the markers appear exactly where expected.

This appears to be a straightforward and well-justified bugfix - the behavior was clearly intended to work in porcelain mode (as evidenced by the documentation) but wasn't implemented. The patch is clean, focused, and comes with appropriate test coverage to prevent regression.
