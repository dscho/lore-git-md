Feature discussion for `git bisect` worktree support, responding to an RFC proposal.

Junio Hamano responds to the proposal for adding worktree support to `git bisect`, suggesting that the existing `--no-checkout` mode already provides the necessary foundation for the desired functionality. He questions why the proposal specifically mentions two worktrees rather than allowing an arbitrary number, and proposes that any worktree management could be built as a wrapper around `git bisect --no-checkout`. This would let users maintain multiple checkouts in whatever configuration they prefer while still using bisect to identify the commit to test.

The response indicates that while the idea has merit, the core functionality may not need new Git commands - the existing tools could support the workflow with some external scripting. Hamano also notes that third-party tools like `rr` could already integrate with the current `--no-checkout` approach. This suggests the proposal might need to demonstrate why new core functionality is needed rather than building on what exists. The discussion remains at the conceptual level, with no implementation yet proposed.
