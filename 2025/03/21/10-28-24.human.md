This is a follow-up in the ongoing discussion about deprecating `core.commentString=auto`. Junio Hamano responds to Phillip Wood's concrete deprecation proposal, agreeing with most of the transition plan while questioning one aspect.

Junio expresses strong support for the proposed deprecation steps: adding advice messages (configurable via `advice.autoCommentStr`), documenting the change in BreakingChanges.adoc, and using conditional compilation with `WITH_BREAKING_CHANGES`. However, he hesitates on Phillip's suggestion to make "auto" an error when breaking changes are enabled, arguing that since commentStr accepts arbitrary strings, treating "auto" as just another string might be sufficient.

The exchange shows the discussion moving from whether to deprecate (now agreed) to precisely how the deprecation should be implemented. Junio's response indicates the project's preference for minimal special-casing in the final implementation, while still supporting the overall deprecation goal. This suggests the thread is nearing consensus on the deprecation path, with only minor implementation details remaining to be resolved.
