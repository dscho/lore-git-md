Bugfix and architectural improvement for advice suppression system, specifically targeting default branch name advice.

This patch (v2 3/3 in the series) completes the architectural solution to make default branch name messages properly respect Git's advice suppression system. It introduces a new `ADVICE_DEFAULT_BRANCH_NAME` advice type and modifies `repo_default_branch_name()` to use `advise_if_enabled()` instead of direct `advise()` calls. The change ensures the "Using 'master' as default branch" advice can be suppressed via both `--no-advice` flag and `advice.defaultBranchName=false` config.

Key technical changes:
- Adds new `ADVICE_DEFAULT_BRANCH_NAME` enum to `advice.h`
- Updates advice string table in `advice.c` with new entry
- Modifies `refs.c` to use config-aware `advise_if_enabled()`
- Adds test case in t0001-init.sh verifying suppression works

The patch builds on the earlier work in the series that addressed the immediate regression (where bundle operations showed advice despite suppression flags) by now making the suppression behavior consistent across all code paths. This represents the architectural component of the three-part solution discussed in the thread, complementing the clone-specific fixes in earlier patches.

The implementation follows Git's established patterns for configurable advice and includes appropriate test coverage. The change is particularly relevant for scripts and automation where advice messages would be undesirable noise. The thread shows consensus that this behavior matches pre-regression expectations and properly handles the bundle clone case that originally surfaced the issue.
