Bugfix for atomic fetch crash when references are locked. This patch addresses a regression introduced in Git v2.49.0-rc1 where `git fetch --atomic` would crash with a BUG" message when encountering locked references, rather than failing gracefully.

Justin Tobler provides a clear analysis of the root cause: commit c92abe71df moved transaction cleanup to a centralized exit path, but this creates a problem because `ref_transaction_commit()` always closes the transaction, while `ref_transaction_abort()` cannot operate on closed transactions. The fix is straightforward - explicitly freeing the transaction when commit fails rather than letting the exit path attempt to abort it.

The patch includes a test case that reproduces the issue by manually creating a lock file, though the author notes this is files-backend specific. The test verifies the command fails properly without triggering the BUG() message. This appears to be a well-constructed fix for a serious regression that could cause crashes in real-world atomic fetch/prune scenarios.
