This is a bugfix patch series addressing advice message suppression during clone operations, with architectural improvements to Git's advice system.

The series builds on previous discussion about a regression where default branch name advice appears during bundle clones despite suppression flags (GIT_ADVICE=0 or --quiet). The root cause was traced to commit 199f44cb2ead which changed clone's remote helper interaction, causing `git_default_branch_name()` to be called later in execution where advice suppression wasn't properly respected.

The solution takes a two-pronged approach: first fixing the immediate clone-specific issue by modifying `guess_remote_head()` to accept suppression flags (converting its existing parameter to a bitmask), then making the default branch name advice globally suppressible via `--no-advice`. The series adds test coverage for both the bundle clone scenario and general advice suppression.

Key technical changes include:
- Conversion of `guess_remote_head()`'s `all` parameter to unsigned flags
- New `GUESS_REMOTE_HEAD_SUPPRESS_ADVICE` flag
- Modified calls in clone/fetch/remote to pass appropriate flags
- Addition of `ADVICE_SUPPRESS_DEFAULT_BRANCH_NAME` to advice system
- New tests in t0001-init.sh and t5607-clone-bundle.sh

The patch set shows careful attention to both the immediate regression and broader architectural consistency in advice handling, with clear commit messages explaining the changes. The v2 iteration incorporates feedback to use flags rather than adding new boolean parameters, following Git conventions. The solution has received positive feedback from other contributors regarding both the technical approach and architectural direction.
