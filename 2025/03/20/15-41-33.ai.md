This is the first patch in a two-part series adding SHA-256 repository support to gitk, reviving a 4-year-old effort originally started by Rostislav Krasny. The patch implements basic SHA-256 hash parsing and display capabilities in gitk's Tcl code, allowing the GUI to work with both SHA-1 and SHA-256 repositories without errors.

The changes are primarily mechanical substitutions replacing hardcoded SHA-1 assumptions (40-character hashes) with a new `hashlength` variable that's set based on the repository's object format (40 for SHA-1, 64 for SHA-256). Key modifications include:

- Adding hash length detection via `git rev-parse --show-object-format` at startup
- Updating regex patterns and string length checks throughout the codebase to use `hashlength` instead of fixed values
- Adjusting UI elements like the commit ID entry field to accommodate longer hashes
- Preserving translation hooks by avoiding changes to generic strings like "Commit ID"

The patch leaves one known limitation unaddressed - the "Auto-select SHA1" preference needs SHA-256 counterpart functionality, which will be handled in the second patch. The changes are confined to gitk's Tcl code and don't affect core Git operations. While the implementation appears straightforward, the author notes it has only been lightly tested so far, suggesting reviewers should pay particular attention to hash parsing edge cases.
