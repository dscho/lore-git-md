This is part 2 of Karthik Nayak's 8-patch series introducing batched reference updates with partial failure support (v4). The patch moves duplicate refname checking from individual backends to the generic refs layer, centralizing what was previously duplicated logic.

The key changes are:
1. Adds a `refnames` string_list to `ref_transaction` to track all references in a transaction
2. Updates this list automatically in `ref_transaction_add_update()`
3. Modifies all backends (files, packed, reftable) to use this centralized list rather than their own duplicate checking
4. Adjusts the reftable backend to perform its duplicate check before rather than after adding updates

The patch is a clean refactoring that eliminates code duplication while maintaining the same behavior. It's part of a larger effort to support batched reference updates that can partially fail, with this change helping ensure consistent behavior across all backends. The implementation looks thorough, touching all three backends and adding comprehensive updates to the core refs infrastructure.
