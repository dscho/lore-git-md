Feature completing a series on batched reference updates with partial failure support.

This is the final patch in Karthik Nayak's 8-part series (now at v4) implementing batched reference updates with partial failure support. The series has built up infrastructure across the refs subsystem to allow individual reference updates to fail while others succeed, with detailed error reporting. This patch exposes that functionality to users through a new `--batch-updates` flag for `git update-ref --stdin`.

When enabled, failed updates are reported in a structured format showing the refname, old/new values, and one of seven specific rejection reasons (like "reference does not exist" or "incorrect old value provided"). The implementation distinguishes between user-input errors (which allow other updates to proceed) and system errors (which abort the entire transaction).

The patch includes thorough documentation of the new flag and extensive test coverage (233 lines across 8 scenarios) exercising various failure modes. The series has undergone significant review, with Jeff King identifying several implementation issues in earlier versions that have since been addressed. This appears to be a well-considered addition that could be particularly useful for scripts performing bulk ref updates where partial failures are acceptable.
