This is the first patch in a 20-part series to make Perl optional for Git's test suite. It's a preparatory change that modifies the chain lint mechanism, which checks test scripts for proper command chaining with '&&'.

The patch automatically disables chain linting when Perl isn't available (PERL_PATH unset), since the linter is implemented in Perl. This makes life easier for developers working without Perl installed, while still allowing explicit chain lint requests (which will now error out if Perl is missing).

The change is straightforward - it adds logic to `t/test-lib.sh` that checks PERL_PATH and adjusts GIT_TEST_CHAIN_LINT behavior accordingly. This is a sensible quality-of-life improvement that fits well with the series' goal of reducing Perl dependencies, though it's worth noting that chain linting will be unavailable for Perl-less test runs unless explicitly requested (and Perl is present).

As the first patch in a large series, this sets up one small piece of infrastructure needed for the broader Perl-optional effort described in the cover letter. The implementation looks clean and focused on its specific task.
