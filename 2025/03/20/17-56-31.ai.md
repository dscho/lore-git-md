This is part 3/14 of Taylor Blau's incremental MIDX bitmap series, which prepares the pack-revindex machinery to handle object lookups across MIDX layers. The patch focuses on adapting reverse index operations to work with the layered structure of incremental MIDX bitmaps.

Key technical changes:
- Introduces `bitmap_num_objects_total()` (renamed from `bitmap_non_extended_bits()` in v5) to properly count objects across MIDX layers
- Modifies `load_midx_revindex()` to use different filename patterns for incremental vs non-incremental MIDX files
- Updates position conversion functions (`pack_pos_to_midx()`, `midx_to_pack_pos()`) to handle global object positions across MIDX layers
- Adjusts `midx_pack_order_cmp()` to account for base layer offsets when comparing positions
- Updates all callers to use the new object counting semantics, particularly in bitmap operations that need to handle extended index positions

The changes maintain backward compatibility while enabling the new incremental bitmap functionality. The patch includes careful handling of object positions across MIDX layers, with explicit bounds checking and BUG() assertions for invalid states. The implementation follows the series' established pattern of treating the MIDX chain as a unified pseudo-pack while preserving layer boundaries where needed (like in pseudo-merge bitmap lookups).

This is a foundational change that enables subsequent patches to build the actual incremental bitmap functionality. The v5 iteration incorporates Jeff King's feedback about clearer naming (`bitmap_num_objects_total`) and maintains the series' high standard of test coverage and documentation.
