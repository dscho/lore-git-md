Build system optimization discussion continuing the meson configuration series. Patrick Steinhardt responds to Ramsay Jones' explanation of the DEFAULT_* variable handling approach in patch 3/12, proposing alternative solutions that would avoid hardcoding assumptions while maintaining the same goals. The key technical points:

1. Patrick suggests using empty string defaults in meson_options.txt instead of duplicating the built-in defaults ('vi', 'man', 'less'), allowing the code's defaults to naturally take effect when no override is provided. This would simplify the build configuration while preserving the same runtime behavior.

2. For DEFAULT_HELP_FORMAT (which has platform-specific behavior on Windows), Patrick proposes either:
   - Adding a 'platform' default choice that resolves to empty string (using code defaults) on most systems and 'html' on Windows
   - Refactoring to move all default logic into code and using an empty choice in meson

3. The discussion reveals this touches documentation generation nuances where make passes git-default-pager/editor to asciidoc only when values differ from standard (Documentation/Makefile lines 239-247), a behavior meson currently doesn't replicate. Ramsay notes this is planned for future patches in the series.

4. Both approaches aim to reduce redundant compiler definitions while maintaining the original intent of allowing platform-specific overrides. Patrick's suggestions would eliminate the need to track default values in both meson and code, potentially making the build system more maintainable.

The exchange shows active exploration of meson best practices for this use case, with Patrick offering concrete alternatives to the current patch's approach while supporting the overall goal of build system optimization and consistency.
