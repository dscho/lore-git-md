This is a review comment on patch 6/8 of Karthik Nayak's batched reference updates series, which has already been merged. Patrick Steinhardt provides two small suggestions for improvement to the implementation.

The first suggestion proposes restructuring the rejection tracking to use a combined `struct ref_update_rejection` that would store both the update index and error together, rather than keeping them separate as in the current implementation. This would make the code more straightforward to understand.

The second is a minor nit about using `strbuf_reset()` instead of `strbuf_setlen(err, 0)` to clear error buffers, which is the more idiomatic way to accomplish this in Git's codebase.

These are small refinements to an already-merged series that implemented batched reference updates with partial failure support. The core functionality is solid, as evidenced by the thorough review and testing the series underwent before merging. Patrick's comments represent the kind of post-merge polish that often happens as maintainers and contributors continue to think about the code.
