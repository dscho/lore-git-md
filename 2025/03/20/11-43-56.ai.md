Refactoring patch in a series about partially-atomic ref updates, focusing on redundant checks in the files backend.

This patch removes a redundant duplicate-check in the refs/files-backend.c code that handles symref updates. The key observation is that the code was performing two checks for duplicate refnames - one before insertion via string_list_has_string() and another after insertion checking item->util. The second check is unnecessary since the first already prevents duplicates.

The changes affect three functions: split_head_update(), split_symref_update(), and files_transaction_prepare(). In each case, the patch simplifies the code by removing the post-insertion validation and direct assignment to item->util, since the string_list_insert()/append() operations alone now guarantee uniqueness. The BUG() checks for unexpected duplicates are also removed as they can no longer trigger.

This appears to be a straightforward cleanup with no behavior change, part of a larger series (v4 1/8) about atomic reference updates. The changes are focused on the internal files backend implementation and don't affect user-facing behavior. The commit message clearly explains the rationale and the specific redundant check being removed.
