SHA-256 support for gitk (part 1/2). This first patch in the series revives Rostislav Krasny's 4-year-old work to make gitk work with SHA-256 repositories, updating it for current Git versions. The changes are focused on Tcl code that handles hash parsing and UI elements, replacing hardcoded SHA-1 assumptions with variable-length hash support. 

The patch modifies gitk functions to use a new `hashlength` variable (40 for SHA-1, 64 for SHA-256) when checking commit IDs, parsing refs, and displaying hash-related UI elements. It preserves translation support and simplifies some regex patterns from the original patch. The author notes one known limitation - the "Auto-select SHA1" preference isn't yet adapted for SHA-256 - but considers this non-critical.

This appears to be a straightforward adaptation of existing logic to handle longer hashes, with changes confined to gitk's Tcl code. The patch builds on prior work but has only been lightly tested so far, particularly around edge cases in hash parsing. As the first step in enabling SHA-256 support, it provides basic foundation without yet implementing all SHA-256-specific features.
