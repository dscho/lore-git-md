Refactoring suggestion for advice suppression patch series.

Patrick Steinhardt responds to Justin Tobler's patch that adds a `quiet` parameter to `guess_remote_head()` to suppress advice messages during clone operations. Rather than adding another boolean parameter, Steinhardt suggests a preparatory refactoring that would convert the existing `all` parameter into a flags field, allowing future additions (like the quiet behavior) to be implemented as bit flags.

This is a style suggestion rather than a technical objection to the functionality. The proposed change would maintain the same behavior but follow Git's common pattern of using flags fields when multiple boolean options might be needed for a function. The suggestion implies the series might benefit from being reworked as a three-patch series: first converting to flags, then adding the quiet flag, then applying it in the clone context.

The response indicates general agreement with the approach but suggests a cleaner implementation path. This kind of refactoring suggestion is common in Git development when extending existing interfaces.
