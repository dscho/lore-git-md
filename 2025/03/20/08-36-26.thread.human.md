The issue specifically affects the interaction between atomic operations and lock file handling in the refs subsystem.

The thread currently shows consensus that this is a serious regression in atomic operation safety that needs to be fixed before the 2.49.0 release. The bug has been narrowed down to a specific commit and the reproduction case simplified, making it easier for maintainers to investigate and fix.
