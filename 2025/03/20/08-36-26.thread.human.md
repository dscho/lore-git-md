A serious regression in Git v2.49.0-rc1 caused `git fetch --prune --atomic` to crash with a BUG message when encountering locked references, stemming from commit c92abe71df's flawed transaction cleanup. The issue was quickly identified through two independent reproduction cases - one involving test.lock files and another from Justin Tobler demonstrating the crash in mirrored repositories with manual locks.

The fix has now been proposed, addressing the root cause where error handling improperly called abort on already-closed transactions. The solution modifies the cleanup path in `builtin/fetch.c` to explicitly free failed transactions rather than relying on abort, maintaining the original memory leak fix while preventing the assertion failure. Justin Tobler contributed both the clear reproduction case and a new test that verifies atomic fetch now handles locked references gracefully (failing cleanly rather than crashing), though the test is currently limited to the REFFILES backend. This straightforward fix resolves the critical safety issue in atomic operations while preserving the intended behavior.
