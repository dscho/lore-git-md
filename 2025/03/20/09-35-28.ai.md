This is the first patch in a 20-part series to make Perl optional for Git's test suite, specifically addressing the chain linter functionality. The patch modifies `t/test-lib.sh` to automatically disable Perl-based chain linting when Perl isn't available (`PERL_PATH` unset), while still allowing explicit chain lint requests to error out if Perl is missing.

The change introduces a new behavior where:
1. If Perl is unavailable and chain linting wasn't explicitly requested, it silently disables linting
2. If Perl is unavailable but someone specifically asked for chain linting (via `GIT_TEST_CHAIN_LINT`), it errors out with a clear message
3. Otherwise maintains existing chain lint behavior when Perl is present

This serves as groundwork for the larger Perl-optional effort by handling one of the test suite's Perl dependencies in a graceful degradation pattern. The patch is narrowly focused on the chain linter interaction with Perl availability, leaving other Perl dependencies to be addressed in subsequent patches. The implementation uses shell case statement logic to handle the various `GIT_TEST_CHAIN_LINT` states while maintaining backward compatibility.
