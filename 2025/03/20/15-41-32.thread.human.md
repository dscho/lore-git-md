This thread introduces a two-patch series updating gitk to properly support SHA-256 repositories, reviving a 4-year-old effort originally started by Rostislav Krasny. The work addresses gitk's current inability to handle SHA-256 hashes, which causes failures despite Git core having supported them for years, particularly impacting openSUSE's SHA-256 workflows.

The first patch laid the foundation with mechanical changes to gitk's Tcl code, introducing hash length detection (40 chars for SHA-1, 64 for SHA-256) via `git rev-parse` and updating regex patterns and UI elements while preserving translation hooks. The second patch, now submitted, completes the work by implementing auto-select length preferences that dynamically adjust between SHA-1 and SHA-256 modes. It adds a new `get_autosellen` proc and stores preferences separately for each algorithm, with the UI now showing appropriate max lengths (40/64 chars) in dialogs.

The changes are confined to gitk's Tcl UI code without affecting core repository operations. While the implementation appears complete, the author notes both patches have only been lightly tested so far, suggesting reviewers should pay particular attention to hash parsing edge cases. No feedback has been provided yet on this revival effort, which represents incremental but important progress in Git's broader SHA-256 ecosystem support.
