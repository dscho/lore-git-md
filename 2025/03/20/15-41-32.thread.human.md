Takashi Iwai has revived and completed a 4-year-old effort to add SHA-256 repository support to gitk, addressing a long-standing gap where gitk couldn't properly handle repositories using SHA-256 hashes. The two-patch series implements basic SHA-256 support and adds hash-algorithm-aware length preferences, maintaining backward compatibility while properly handling both SHA-1 and SHA-256 repositories.

Johannes Sixt, the gitk maintainer, has provided the first technical review of the series. While not objecting to the SHA-256 functionality itself, he pointed out several code quality issues in the first patch - including inconsistent indentation, suboptimal variable usage, and a hardcoded regex that should use the new `$hashlength` variable. These appear to be straightforward cleanup opportunities rather than fundamental problems with the approach.

The series appears functionally complete but would benefit from addressing Johannes's feedback before merging. With gitk being a critical visualization tool for Git repositories, this SHA-256 support will be particularly valuable for users and distributions (like openSUSE) that have adopted SHA-256 repositories.
