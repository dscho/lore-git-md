This is the final patch (8/8) in Karthik Nayak's series introducing batched reference updates with partial failure support. It exposes the new functionality through a `--batch-updates` flag for `git update-ref --stdin`.

The patch adds user-facing documentation and tests for the batched update mode, which allows individual reference updates to fail while still applying the successful ones. Failed updates are reported in a standardized format showing the refname, old/new values, and one of seven possible rejection reasons (like "refname conflict" or "incorrect old value"). The implementation builds on the ref transaction infrastructure added in previous patches.

The 233-line test suite covers various failure scenarios including:
- Invalid new OIDs (non-commits, malformed hashes)
- Nonexistent references
- Dangling symrefs
- Type mismatches (regular ref vs symref)
- Incorrect old OIDs
- Refname conflicts

The implementation distinguishes between user-input errors (isolated failures) and system errors (abort entire transaction). The flag is carefully restricted to stdin mode where the atomicity tradeoffs make sense. Documentation clearly explains the behavior difference from normal atomic updates.

This completes the series' goal of enabling efficient batched updates while maintaining safety - particularly beneficial for the reftable backend. The comprehensive test coverage and clear error reporting should make the feature robust for users.
