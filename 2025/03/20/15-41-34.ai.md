This is the second patch in a two-part feature addition to gitk, completing SHA-256 repository support by implementing auto-select length preferences. The patch builds on the foundational SHA-256 support from part 1 by adding hash-algorithm-aware handling of the commit ID length preference.

The key technical changes introduce a new `get_autosellen` proc that dynamically returns either the SHA-1 (40 chars) or SHA-256 (64 chars) length based on repository settings, replacing hardcoded references to `autosellen`. The preference UI now shows appropriate max lengths (40/64) and saves the SHA-256 preference separately as `autosellensha256` in gitk's config. The default SHA-256 auto-select length is set to 64 characters.

The changes touch several UI interaction points: commit selection, reference copying, and preference dialogs. The implementation maintains backward compatibility while properly handling both hash algorithms, with the preference system dynamically switching based on `hashalgorithm`. The patch appears to complete the SHA-256 support work started in the first patch, though like part 1, it notes only light testing so far.
