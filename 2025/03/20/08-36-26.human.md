Bug report: Git crashes with core dump during atomic fetch --prune when ref lock exists.

李葵 reports a reproducible crash in Git 2.49.0-rc1 when running `git fetch --prune --atomic` while a stale lock file exists. The test case involves:
1. Creating a mirror clone of git/git-merge
2. Manually creating a lock file (`test.lock`) in the refs directory
3. Attempting an atomic fetch operation

Instead of gracefully handling the locked ref, Git hits a BUG() assertion in refs.c and crashes with an IOT (core dumped) error. The error message suggests Git detects the lock file but then aborts on a closed reference transaction.

This appears to be a regression in the atomic fetch/prune interaction when encountering locked refs. The reporter expected Git to either complete successfully or fail gracefully without crashing. The presence of a core dump indicates an unhandled error condition in the ref transaction logic.

The bug report includes complete reproduction steps and system information, making it easy to verify. This looks like a legitimate issue that would need investigation from the refs subsystem maintainers, particularly around atomic operation error handling.
