Platform compatibility fix for Meson build system to properly handle Windows compatibility sources.

This is the first patch in a 2-part series addressing a MinGW-specific race condition in file handling. The patch focuses on correcting how the Meson build system includes compatibility sources when compiling with MSVC versus MinGW. Currently, the build incorrectly includes `mingw.c` for all Windows builds, while `msvc.c` (which wraps `mingw.c` with additional headers) should be used specifically for MSVC toolchains.

The change modifies `meson.build` to:
1. Remove the unconditional inclusion of `mingw.c` for Windows builds
2. Add conditional logic to include `msvc.c` when using MSVC compiler
3. Only include `mingw.c` for non-MinGW Windows compilers

This aligns Meson's behavior with the existing Makefile approach and ensures proper header inclusion for MSVC builds. The change is straightforward (8/+11 lines) and addresses a clear gap in the build system's platform handling. This is a prerequisite for the more complex Windows-specific error handling changes in patch 2 of the series.

Key technical points:
- Affects Windows builds only
- Modifies source file inclusion in `meson.build`
- Maintains existing `compat/` directory structure
- Preserves all other Windows-specific sources
- Follows same pattern as Makefile build
- No functional changes to actual compatibility code

The patch appears well-contained and necessary for proper MSVC support, though its impact is limited to build system correctness rather than runtime behavior. It forms the foundation for the more substantive Windows error handling changes that follow in the series.
