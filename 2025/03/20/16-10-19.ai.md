Bugfix for atomic fetch/prune crash: This email confirms and simplifies reproduction of the previously reported crash in `git fetch --prune --atomic` when lock files exist. Justin Tobler provides a more minimal test case that triggers the same BUG message from refs.c about closed reference transactions. The reproduction steps involve creating a simple repository, mirroring it, adding a test branch, manually creating a lock file, then running the atomic fetch operation. The email notes this behavior was introduced by commit c92abe71df ("builtin/fetch: fix leaking transaction with `--atomic`", 2024-08-22) and CCs its author. The simplified reproduction helps isolate the issue to the interaction between atomic operations and lock file handling in the refs subsystem. This appears to be a regression in error handling where lock conflicts during atomic operations trigger assertion failures rather than proper cleanup.
