Patch review feedback in HTTP keepalive configuration series.

This is a review response in the ongoing HTTP TCP keepalive configuration patch series, specifically addressing patch 2/4 which introduced the `set_long_from_env()` helper function. Patrick Steinhardt provides feedback on the implementation details while generally approving the approach.

The key technical element under discussion is the error handling in `set_long_from_env()`, where Patrick questions the necessity of preserving `errno` (via the `saved_errno` dance) when parsing environment variables into long integers. While noting this minor stylistic concern, he explicitly approves the overall warning-based error handling approach rather than fatal errors.

Patrick also gives blanket approval to the remaining patches in the series, indicating the review cycle for this functionality is nearing completion. The feedback suggests only trivial adjustments might be needed, if any, as the series appears technically sound and aligns with the project's standards. This continues the positive trajectory seen in previous reviews from Elijah Newren and others.

The thread context shows this helper function is part of the infrastructure supporting new HTTP keepalive configuration options (`http.keepaliveidle`, `http.keepaliveinterval`, `http.keepalivecount`) with environment variable overrides. The robust parsing implemented here will be used to handle numeric values for these settings while providing appropriate user feedback when invalid values are encountered.
