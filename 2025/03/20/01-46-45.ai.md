Bugfix patch addressing advice suppression regression in clone operations. This is the first of two patches fixing an issue where the "hint: Using 'master' as the name for the initial branch" message appears during bundle clones despite GIT_ADVICE=0 or --quiet flags being set.

The patch modifies `guess_remote_head()` to accept a new `quiet` parameter that gets passed through to `repo_default_branch_name()`, allowing callers to suppress advice messages. This change affects multiple call sites across clone, fetch, and remote operations, though the immediate regression fix focuses on the clone case. The implementation maintains existing behavior by default (advice shown) while providing the mechanism for suppression when needed.

Key technical details include:
- Function signature change in remote.h adding the `quiet` parameter
- Updates to all callers in builtin/clone.c, builtin/fetch.c, and builtin/remote.c
- The quiet flag being passed through to `repo_default_branch_name()` in remote.c
- Default behavior remains unchanged (quiet=0) for existing callers

This patch lays the groundwork for the second patch which will properly set the quiet flag during clone operations based on suppression settings. The changes are minimal and focused, touching only the necessary plumbing to enable advice suppression while maintaining consistency across related commands.
