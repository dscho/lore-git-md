This is a follow-up in the ongoing discussion about cryptographic random number generation (CSPRNG) backend selection in Git's build systems. Ramsay Jones responds to Patrick Steinhardt's query about incorporating changes into a v2 patch series, but with a revised approach.

The email marks a shift in the technical consensus - while initially considering platform-specific logic for CSPRNG backend selection, Ramsay now advocates for defaulting to `getrandom` on Linux systems in the config.mak.uname file. This change reflects the practical reality that while different platforms have varying optimal orders for CSPRNG backends, `getrandom` is the most universally available option on modern Linux systems while still working acceptably on older ones.

Ramsay notes that Cygwin and *BSD systems should still prefer `arc4random`, but for Linux the performance differences between the three main options (`arc4random`, `getrandom`, `getentropy`) are negligible, making availability the deciding factor. The email suggests this simpler approach will be implemented in the upcoming v2 of the patch series, replacing the more complex platform-siloed logic previously considered.

This represents the final coordination point in the thread's technical discussion, with both build system maintainers now aligned on the Linux default configuration. The exchange demonstrates how initial technical positions evolved through discussion to reach a pragmatic solution that balances correctness with maintainability.
