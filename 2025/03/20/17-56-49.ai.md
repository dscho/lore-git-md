Performance patch in Taylor Blau's incremental MIDX bitmap series (v5 09/14). This small but important change updates the disk-usage calculation code in `pack-bitmap.c` to properly handle incremental MIDX layers by using `nth_midxed_pack()` instead of direct array access to the MIDX's packs. The modification affects two locations where pack objects are looked up during disk-usage computation, ensuring correct behavior when working with layered MIDX bitmaps.

The changes mirror similar updates made in previous patches of the series, maintaining consistency in how packs are accessed across the bitmap codebase. Both modified functions (`get_size_by_pos` and `get_disk_usage_for_type`) are part of Git's object size and disk-usage reporting infrastructure, which needs to account for the possibility of objects being spread across multiple MIDX layers.

This patch is a straightforward mechanical update that follows the established pattern from earlier in the series, with no new test additions since the existing test infrastructure (particularly t5334) already validates this behavior through the comprehensive bitmap testing framework introduced in patch 08/14. The change is small but necessary for correct operation of the MIDX bitmap chain traversal logic.
