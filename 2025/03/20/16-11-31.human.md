This is a refactoring patch in Martin Ågren's series to clean up Git's pretty-format parsing code. It's patch 5/8 in the series, addressing lingering padding state in the pretty-format parser.

The patch fixes an issue where only part of the padding state was being reset after processing padding directives in format strings. Martin adds explicit clearing of the `truncate` and `padding` fields to match the existing `flush_type` reset. Reviewer Patrick Steinhardt suggested consolidating this initialization logic into a helper function, which Martin plans to implement by introducing a `padding_args_clear()` function in the preceding patch.

Martin also notes they currently rely on implicit zero-initialization of the struct, and is considering adding another preparatory patch to make the enum zero-values more explicit. This shows careful attention to maintainability details while working through the refactoring.

The change is part of the series' systematic effort to make the pretty-format code more robust and maintainable, with Patrick providing active review feedback that Martin is incorporating. No behavior changes are introduced - this is purely about making the internal state handling more correct and explicit.
