This is the first patch in a two-part bugfix series addressing a regression where clone operations would show unwanted advice messages despite suppression flags (like `--quiet` or `GIT_ADVICE=0`). The issue specifically affected the "hint: Using 'master' as the name for the initial branch" message when cloning bundle files.

The patch modifies `guess_remote_head()` to accept a new `quiet` parameter that gets passed through to `repo_default_branch_name()`, allowing callers to suppress advice messages. This is a targeted change that affects several call sites in clone, fetch, and remote operations. The diff shows straightforward updates to function signatures and calls, maintaining existing behavior while adding the new suppression capability.

The change is well-motivated by the regression analysis in the thread, which traced the issue to advice messages appearing when they shouldn't during bundle clones. This first patch lays the groundwork for the actual suppression logic that will be implemented in the second patch. The implementation looks clean and focused, touching only the necessary parts of the codebase to enable quiet operation while preserving all existing functionality.
