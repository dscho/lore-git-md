Bugfix targeting advice message suppression during bundle clones, specifically addressing a regression in the `git_default_branch_name()` caching behavior.

Justin Tobler provides a detailed technical analysis of why the "Using 'master' as name for initial branch" hint appears despite suppression flags (GIT_ADVICE=0 and --quiet) when cloning from bundles. The root cause stems from commit 199f44cb2ead which changed when the default branch name is first computed during clone operations. Previously, `create_reference_database()` would compute it with suppressed advice, but now the computation happens later in `guess_remote_head()` which doesn't suppress advice.

The key insight is that `git_default_branch_name()` (now `repo_default_branch_name()`) caches its result after first computation, so where it's first called determines whether advice appears. For bundle clones, the transport can't determine HEAD automatically, so it falls back to `guess_remote_head()` which computes the default branch name without suppression.

Tobler proposes modifying `guess_remote_head()` to support quiet operation by allowing configuration of the underlying `repo_default_branch_name()` call. This would restore the pre-regression behavior where bundle clones properly respect the hint suppression flags. The analysis clearly identifies the exact control flow change that caused the regression and proposes a targeted fix that maintains the intended behavior while preserving the functionality added in 199f44cb2ead.
