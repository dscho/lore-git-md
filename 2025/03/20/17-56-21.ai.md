Feature implementation (incremental MIDX bitmaps) - final refinement before merge.

This is Taylor Blau's v5 cover letter for the incremental MIDX bitmap series, now expanded to 14 patches (from 13 in v4) with minor refinements based on Jeff King and Elijah Newren's reviews. The series implements efficient bitmap operations across multi-pack index (MIDX) layers through structured bitmaps, representing the second of three planned efforts in this area.

Key technical changes in this version include:
- Added new patch 1/14 to remove a "future work" item from MIDX docs that's now being addressed
- Improved documentation wording around object sorting semantics in incremental MIDXs (patch 2/14)
- Renamed `bitmap_non_extended_bits()` to clearer `bitmap_num_objects_total()` (patch 3/14)
- Fixed memory allocation pattern in bitmap test infrastructure (patch 8/14)
- Renamed `ewah_or_iterator_free()` to `ewah_or_iterator_release()` for consistency (patches 10-14)
- Added explicit verification of MIDX layer structure in tests (patch 14/14)

The core architecture remains unchanged from v4, maintaining:
- Layered bitmap design with independent *.bitmap files per MIDX layer
- `ewah_or_iterator` for combining type-level bitmaps across layers
- Pack-reuse optimizations favoring older layers' preferred packs
- Complete test coverage in t5334

Review feedback has been fully addressed, including:
- Jeff King's concerns about array access patterns and naming consistency
- Elijah Newren's editorial improvements to documentation and commit messages
- Performance validation showing negligible impact from `ewah_or_iterator` use

The series is now in final form with all technical concerns resolved, awaiting merge after these last minor refinements. Remaining future work includes layer compaction support and real-world performance monitoring, but this series completes the core incremental bitmap functionality.
