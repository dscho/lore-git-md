Platform compatibility follow-up in CSPRNG configuration thread.

Ramsay Jones responds to Patrick Steinhardt's query about incorporating CSPRNG backend changes into the patch series, but revises his position after reconsidering the platform-specific implications. The email clarifies that while the current priority order works for newer Linux systems, setting 'getrandom' as the explicit Linux default would better accommodate older systems while maintaining correct behavior across platforms.

Key technical points:
- Confirms Linux should default to getrandom despite the general backend priority order
- Notes Cygwin and *BSD systems should still prefer arc4random
- Acknowledges all three Linux options (arc4random, getrandom, getentropy) have similar performance
- Highlights getrandom's broader availability on Linux systems
- Mentions local testing overrides via config.mak remain possible

This represents the final coordination point in the thread's technical discussion, with Ramsay Jones indicating he'll prepare a v2 series with this adjusted approach. The email serves as both implementation confirmation and rationale for the Linux-specific default choice, concluding the platform-specific CSPRNG configuration analysis that began with documentation concerns.
