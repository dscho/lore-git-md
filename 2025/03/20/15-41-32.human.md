This is a feature patch series adding SHA-256 repository support to gitk, the Git repository visualizer. The cover letter explains that gitk currently fails when used with SHA-256 repositories, showing an error about parsing commit hashes.

The series revives a 4-year-old patch that never got merged, with cleanups and corrections. The first patch by Rostislav Krasny adds basic SHA-256 support, while the second patch by Takashi Iwai adds configuration for auto-selecting hash length in the display. The author notes they've done light testing on SHA-256 repositories but doesn't provide extensive validation.

The motivation comes from practical needs - the author encountered this while testing openSUSE's new Git workflow that enforces SHA-256 repositories. The patches appear focused and well-scoped, addressing a clear compatibility gap as Git moves toward broader SHA-256 adoption. The implementation touches about 100 lines in gitk's core file, modifying hash parsing and display logic.
