This is part 5/8 of Karthik Nayak's series introducing batched reference updates with partial failure support, focusing on improving error handling in the refs subsystem.

The patch replaces preprocessor-defined transaction error codes with a strongly-typed `enum ref_transaction_error`, improving type safety and making error handling more explicit. The new enum defines seven distinct error cases covering common scenarios like name conflicts, existence checks, and value mismatches. The change touches all major ref backends (files, packed, reftable) and updates callers like `builtin/fetch.c` to use the new enum values.

The conversion appears thorough and mechanical, maintaining all existing behavior while making the error handling more structured. This is a preparatory step for the batched update functionality coming in later patches, where having well-defined error types will be particularly valuable for partial failure cases. The patch follows the series' pattern of careful refactoring before adding new features.
