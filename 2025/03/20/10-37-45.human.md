This is a revised version of a platform compatibility fix series addressing a MinGW-specific race condition in file handling, now reduced to 2 patches from the original 3. The core issue involves Windows-specific behavior where `_wopen()` with `O_CREAT|O_EXCL` incorrectly returns `EACCESS` instead of `EEXIST` when another process has marked a file for deletion, causing flaky test failures in t0610.

The v2 series makes the error code translation more precise by checking for `STATUS_DELETE_PENDING` to avoid masking genuine permission errors. It also adds a Meson build system fix for MSVC compatibility (a separate issue noticed during debugging) and drops the previously included `O_CLOEXEC` handling patch as non-essential. The changes are focused in `compat/mingw.c` (20 lines added) and `meson.build` (4 lines changed).

The discussion from v1 revealed fundamental Windows API limitations in distinguishing between true permission errors and delete-pending states. While this version attempts to be more surgical in its error translation, the core challenge of cleanly handling Windows file semantics remains. The patch appears well-motivated by test flakiness and shows careful consideration of previous feedback, though Windows experts may still want to verify the approach.
