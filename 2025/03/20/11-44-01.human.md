This is part 6/8 of Karthik Nayak's series implementing batched reference updates with partial failure support, a feature enhancement for Git's ref transaction system.

The patch introduces the core infrastructure for batched updates that can tolerate individual reference update failures while still processing others. The key addition is the `REF_TRANSACTION_ALLOW_FAILURE` flag, which when set allows non-system errors (like name conflicts or incorrect old values) to be recorded as rejections rather than failing the entire transaction. System errors (marked as `REF_TRANSACTION_ERROR_GENERIC`) still abort the whole operation.

The implementation tracks rejected updates through a new `rejection_err` field in `struct ref_update` and a `ref_transaction_rejections` structure for efficient iteration. All three ref backends (files, packed, reftable) are modified to use the new `ref_transaction_maybe_set_rejected()` helper instead of failing outright. A new iterator function `ref_transaction_for_each_rejected_update()` allows callers to inspect which updates failed and why.

This is a well-structured patch that builds on the enum-based error handling introduced in patch 5/8. The changes are systematic across all backends while maintaining consistent behavior. The commit message clearly explains both the user-facing benefit (efficient batched updates for reftable) and the internal mechanisms. The implementation looks thorough, with appropriate BUG() checks for invalid states and careful handling of error conditions.
