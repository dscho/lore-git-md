This is a feature patch series introducing batched reference updates with partial failure support. The 8-part series from Karthik Nayak builds infrastructure to allow reference updates to proceed even when some individual updates fail, while still using the transaction system for optimization.

The series progresses through several preparatory refactorings before implementing the core functionality:
1. Cleanup of redundant checks in the files backend
2. Moving refname checking to the generic layer
3. Reftable backend restructuring
4. Introducing typed transaction errors
5. Core batched update implementation
6. Adding failure support during F/D checks
7. Exposing the feature via `--batch-updates` flag in `git-update-ref`

Key technical points:
- New `REF_TRANSACTION_ALLOW_FAILURE` flag enables the behavior
- Rejected updates are tracked via `ref_transaction_rejections` struct
- Error reporting uses `enum ref_transaction_error` types
- All backends (files, packed, reftable) updated to support partial failures
- Comprehensive test coverage (233 lines across 8 scenarios)
- Particularly beneficial for reftable backend efficiency

The implementation appears thorough, with careful attention to error handling and backward compatibility. The commit messages are detailed and the test coverage looks extensive. The series has evolved through multiple iterations (now at v4) with naming refinements (from "partial transactions" to "batched updates") and error handling improvements based on feedback.

This builds on Patrick Steinhardt's earlier work on batched refname checks and addresses a real need for more flexible reference updates while maintaining transaction optimizations. The changes touch core refs infrastructure but appear well-contained and properly abstracted.
