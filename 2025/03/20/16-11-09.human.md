Bugfix and refactoring in the pretty-format parsing code. This is patch 4/8 in Martin Ågren's series to clean up Git's pretty-format implementation.

The patch fixes edge cases in padding placeholder parsing ("%<" and "%>") by ensuring partially parsed directives don't affect the output. The key change is to only modify the output struct after successful parsing, preventing any half-baked state from leaking through. A test case demonstrates how malformed placeholders like "%<(10,bad)" previously show up verbatim in output.

Patrick Steinhardt suggests in the review that invalid placeholders should ideally cause Git to die rather than silently produce potentially confusing output, though acknowledges this would be a behavior change. Martin agrees this might be a good long-term direction but prefers to keep the current "print verbatim" behavior for now to avoid breaking existing uses.

The patch also includes some naming improvements based on Patrick's feedback, changing an unclear "ans" variable to the more descriptive "result". This continues the productive reviewer-author collaboration seen throughout the series, with Patrick providing constructive feedback that Martin incorporates while maintaining the patch's core technical approach.
