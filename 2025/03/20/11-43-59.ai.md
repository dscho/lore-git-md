This is patch 4/8 in Karthik Nayak's v4 series implementing batched reference updates with partial failure support for the reftable backend. The patch is a refactoring that extracts the core logic for preparing individual reference updates from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function.

The new function handles all validation and preparation steps for each reference update, including:
- Object ID verification
- HEAD reference handling
- Symref processing
- Old/new value validation
- Error condition checking

The refactoring consolidates 226 lines of inline code into a dedicated function while maintaining identical behavior. This improves code organization and sets up the infrastructure needed for the upcoming batched update support in later patches. The commit message notes this is purely a code movement with no functional changes.

Key technical details for future reference:
- New function `prepare_single_update()` takes transaction data, update struct, and various buffers
- Handles all validation cases previously inline (object existence, symref resolution, etc.)
- Maintains same error messages as files backend for compatibility
- Preserves special HEAD update behavior
- Keeps same optimization to skip no-op updates
- Part of larger effort to support `REF_TRANSACTION_ALLOW_FAILURE` flag
- Builds on Patrick Steinhardt's prior work on batched refname checks

The change appears well-contained and mechanically sound, with comprehensive test coverage coming in the full series. This intermediate refactoring step follows good practice by separating mechanical reorganization from behavior changes.
