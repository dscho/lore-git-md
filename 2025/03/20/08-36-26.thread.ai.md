Atomic fetch/prune crash bug report: A bug report demonstrates Git v2.49.0-rc1 crashing with a core dump when running `git fetch --prune --atomic` if a lock file exists in the repository. The reporter provides clear reproduction steps - creating a test.lock file in refs/ then attempting the atomic fetch operation. Instead of proper lock conflict handling, Git aborts with a BUG message from refs.c:2435 about operation on closed reference transaction ("abort called on a closed reference transaction"). The crash occurs on Linux/glibc 2.35 from commit 683c54c999. This reveals a serious flaw in atomic reference transaction handling where lock conflicts trigger assertion failures rather than graceful errors. The report contains all necessary technical details (exact command, error location, system info) for refs subsystem maintainers to investigate this edge case in atomic operation safety.
