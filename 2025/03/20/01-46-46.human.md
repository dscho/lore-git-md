This is the second patch in a bugfix series addressing unwanted advice messages during clone operations. It completes the solution started in patch 1/2 by properly suppressing the "hint: Using 'master' as the name for the initial branch" message when cloning bundle files with GIT_ADVICE=0 or --quiet flags.

The patch makes a minimal but crucial change to `builtin/clone.c`, passing `1` (quiet mode) to `guess_remote_head()` when determining the default branch name. This ensures the advice suppression requested by the user is properly respected throughout the clone operation, fixing a regression introduced in Git 2.45.1.

The change is well-motivated by the thread's technical analysis, which traced the issue to caching behavior in the default branch name computation. While the fix itself is simple (a one-line change), it effectively restores the pre-2.45.1 behavior where clone operations properly honored advice suppression flags. The patch appears ready for review, with clear connection to both the regression analysis and the preparatory changes made in patch 1/2.
