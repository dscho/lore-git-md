This is a feature patch series adding SHA-256 repository support to gitk, part of the ongoing effort to fully support SHA-256 hashes across Git's ecosystem. The cover letter explains that gitk currently fails when encountering SHA-256 repositories with an unhelpful error message, and revives a 4-year-old patch that had been previously proposed but never merged.

The first patch by Rostislav Krasny (revived and cleaned up by Takashi Iwai) adds basic SHA-256 support to gitk, allowing it to parse and display SHA-256 commit hashes. The second patch by Iwai adds configuration support for automatically selecting the appropriate hash length (40 vs 64 characters) based on the repository's hash algorithm, similar to how `git log` behaves. The changes are focused in gitk's Tcl code, modifying hash parsing and display logic.

The series appears well-motivated by real-world needs (openSUSE's SHA-256 workflow) and builds on prior work while cleaning it up. The author notes it's only lightly tested so far, which may warrant review attention to the hash parsing edge cases. This is a currently relevant area of Git development as SHA-256 support matures, though gitk's Tcl codebase may not get as much scrutiny as core C code. The changes are contained to gitk's UI layer and don't affect core repository operations.
