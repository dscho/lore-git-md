This is part 7/8 of Martin Ågren's series refactoring pretty.c's parsing logic, specifically addressing the handling of special formatting characters (like '+' and '-') in commit messages. The patch extracts magic character parsing into a new `parse_magic()` helper function and introduces an `enum magic` to represent the different formatting states.

Key technical details for future reference:
- The enum originally had values like `NO_MAGIC` and `ADD_LF_BEFORE_NON_EMPTY` but will be updated per Patrick Steinhardt's suggestion to use `MAGIC_` prefixes (e.g. `MAGIC_NONE`)
- The parsing logic maintains the same behavior as before, where:
  - Return value >1 causes early exit
  - Return value 0 (`NO_MAGIC`) also causes early exit
  - Only return value 1 proceeds to format/pad the commit
- The commit message will be updated to better explain these edge cases
- The return value "2" remains as a somewhat arbitrary but intentional choice to avoid switching to signed types

The discussion shows consensus on the technical approach, with Patrick having reviewed and approved the changes while suggesting the enum naming improvement. Martin is responsive to feedback and plans to update both the code and commit message accordingly. This continues the series' pattern of careful, incremental refactoring with attention to maintainability.
