This is part 5/8 of Karthik Nayak's v4 series introducing batched reference updates with partial failure support. The patch converts preprocessor-defined transaction error codes into a strongly-typed `enum ref_transaction_error` with seven distinct error cases. 

The change improves type safety and makes error handling more explicit while maintaining all existing error conditions. The new enum covers common scenarios like name conflicts, create-exists cases, nonexistent refs, incorrect old values, invalid new values, and unexpected symref types. The patch updates all ref backend implementations (files, packed, reftable) to use the new enum consistently.

Key technical details include:
- New enum in `refs.h` with clear documentation of each error case
- Updates to function signatures in `refs.h` and `refs-internal.h` to use the enum
- Mechanical conversion of error handling in all three backends
- Preservation of existing error messages and conditions
- No functional changes to actual behavior

The change is a preparatory refactoring that enables more comprehensive error handling for the batched update feature coming in the series. It touches core refs infrastructure but is a straightforward conversion with low risk of introducing new bugs. The patch follows the series' pattern of careful, incremental changes with thorough updates across all affected components.
