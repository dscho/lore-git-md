This is a bugfix patch series addressing the regression in clone operations where advice messages were improperly shown despite suppression flags. The series builds on the thread's technical analysis of the issue, which was narrowed down to commit 199f44cb2ead changing when the default branch name gets cached during clone operations. The key problem occurs when cloning from bundles, as the `guess_remote_head()` function (which now computes the default branch name) doesn't respect advice suppression flags.

The first patch modifies `guess_remote_head()` to accept a `quiet` parameter that gets passed through to `repo_default_branch_name()`, allowing callers to suppress advice messages. The second patch updates `builtin/clone.c` to pass the appropriate quiet flag based on the clone command's suppression settings. The changes are minimal but targeted, touching several files to maintain consistency in the remote HEAD guessing logic across different commands (clone, fetch, remote).

The series appears well-constructed with a clear explanation of both the problem and solution. It maintains the functionality added in the regression-causing commit while restoring proper advice suppression behavior. The patch affects core clone behavior and remote helper interactions, so it may warrant careful review from maintainers familiar with this area of Git's codebase.
