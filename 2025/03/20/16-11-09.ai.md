Refactoring patch in a series improving pretty-format parsing, addressing edge cases in padding placeholder handling. This is the updated version of patch 4/8 in Martin Ågren's series, incorporating Patrick Steinhardt's feedback.

The patch focuses on making the parsing of "%<" and "%>" padding placeholders more robust by only modifying the output struct after successful parsing. This prevents half-parsed directives from affecting the output. The commit message notes this fixes a case where malformed modifiers like "%<(10,bad)" would previously appear verbatim in output.

Patrick suggested two improvements in his review: 1) proposing a stricter mode that would error on malformed placeholders rather than outputting them (though both agree this would be a larger behavioral change to consider separately), and 2) renaming the `ans` variable to `result` for clarity. Martin accepts both suggestions, noting the variable name change while acknowledging the merit of stricter parsing as a potential future enhancement.

The patch maintains the existing "print verbatim on parse failure" behavior while making the implementation safer through the temporary struct approach. Test coverage was added in the original version to verify the fix for malformed cases. This continues the series' pattern of modularizing pretty.c's formatting logic while fixing edge cases.
