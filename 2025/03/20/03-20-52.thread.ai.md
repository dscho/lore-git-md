**Git p4 error message encoding fix** - Patch series by Nikolay Shustov addressing `git p4` failures when processing non-UTF-8 Perforce error messages by extending the metadata transcoding framework. Core implementation introduces a `MetadataTranscoder` class to consolidate encoding handling, refactoring `metadata_stream_to_writable_bytes()` while maintaining Python 2/3 compatibility. Applies existing configurable fallback strategy (`git-p4.metadataDecodingStrategy`/`git-p4.metadataFallbackEncoding`) to error message processing with enhanced verbose diagnostics in `MetadataDecodingException`. Test coverage via Python 3-specific `t9837-git-p4-error-encoding.sh` verifies Unicode handling. Phillip Wood's review acknowledged the practical importance while suggesting structural improvements: splitting refactoring from bugfix commits, clarifying commit messages about high-bit character decoding, and separating Python 2/3 concerns from core logic. Shustov's follow-up defends the class-based approach, identifying the problematic direct `.decode()` call at git-p4.py line 901 as the root cause during `git p4 clone` operations with high-bit characters. Both participants recognize the challenge of finding active git-p4 maintainers, with Shustov committing to contact recent contributors for review while maintaining the current implementation structure. The technical approach remains sound with no unresolved objections, though documentation and patch organization improvements are pending. The series builds on prior metadata transcoding work, solving a practical migration pain point while maintaining backward compatibility without new configuration options. Test coverage remains limited to Python 3 due to fundamental Unicode handling differences between Python versions.
