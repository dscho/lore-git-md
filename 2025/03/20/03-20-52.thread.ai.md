**Git p4 error message encoding fix** - Patch series by Nikolay Shustov addressing `git p4` failures when processing non-UTF-8 Perforce error messages through comprehensive encoding handling improvements. Core implementation introduces a `MetadataTranscoder` class to consolidate encoding logic, refactoring `metadata_stream_to_writable_bytes()` while maintaining Python 2/3 compatibility. The fix specifically targets a crash during `git p4 clone` operations caused by direct `.decode()` calls on high-bit characters at git-p4.py line 901. Shustov's latest response defends the architectural choice, explaining the class-based approach is necessary to avoid logic duplication while maintaining state between calls, not merely cosmetic refactoring. The solution leverages existing configuration (`git-p4.metadataDecodingStrategy`/`git-p4.metadataFallbackEncoding`) with enhanced verbose diagnostics in `MetadataDecodingException`, applying the same fallback strategy to error message processing as previously implemented for metadata. Test coverage via Python 3-specific `t9837-git-p4-error-encoding.sh` verifies Unicode handling, though limited by fundamental Python version differences. Phillip Wood's review feedback remains partially addressed - while technical merits are established (no outstanding objections to the transcoding approach), organizational suggestions (splitting refactoring from bugfix commits, clarifying commit messages about high-bit decoding, separating Python version concerns) await implementation. Shustov has expanded reviewer outreach, CC'ing recent git-p4 contributors Fahad Alrashed, James Touton, and Patrick Steinhardt to compensate for the subsystem's lack of active maintainers. The series builds on prior metadata transcoding work, solving a practical migration pain point while maintaining backward compatibility without new configuration options.
