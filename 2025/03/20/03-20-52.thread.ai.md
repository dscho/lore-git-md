**Git p4 error message encoding fix** - Patch series by Nikolay Shustov addressing `git p4` failures when processing non-UTF-8 Perforce error messages by extending the existing metadata transcoding framework. Core technical implementation introduces a `MetadataTranscoder` class to consolidate encoding handling, refactoring logic from `metadata_stream_to_writable_bytes()` while maintaining Python 2/3 compatibility through careful byte handling. Applies same configurable fallback strategy (`git-p4.metadataDecodingStrategy`/`git-p4.metadataFallbackEncoding`) used for metadata to error message processing, with enhanced verbose diagnostics in `MetadataDecodingException`. Test coverage via Python 3-specific `t9837-git-p4-error-encoding.sh` verifies the fix by forcing Python 3 execution to validate Unicode handling. Phillip Wood's review acknowledges the practical importance of the fix while suggesting structural changes: splitting refactoring from bugfix into separate commits, improving commit message clarity about the high-bit character decoding problem, and separating Python 2/3 compatibility concerns from core encoding logic. Notes the challenge of finding active git-p4 maintainers but confirms the technical approach is sound. Test coverage remains limited to Python 3 due to fundamental Unicode handling differences between Python versions. No outstanding technical issues raised beyond documentation and patch organization improvements needed for maintainer consideration. The series builds on prior metadata transcoding work in the git-p4 bridge, solving a practical migration pain point for Perforce-to-Git transitions while maintaining backward compatibility without new configuration options.
