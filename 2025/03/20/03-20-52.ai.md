Bugfix for `git p4` handling of non-UTF-8 Perforce error messages. This patch addresses a specific failure case where `git p4` would choke on Perforce command errors containing byte sequences with high bits set, failing to properly decode them into UTF-8 strings.

The solution refactors the existing metadata transcoding logic into a new `MetadataTranscoder` class, extending it to handle error message decoding using the same fallback strategy already implemented for other metadata (controlled by `git-p4.metadataDecodingStrategy` and `git-p4.metadataFallbackEncoding` config options). The changes include:

1. Moving transcoding logic from `metadata_stream_to_writable_bytes()` into the new class
2. Adding error message decoding support that respects the same config options
3. Including a new test case (`t9837-git-p4-error-encoding.sh`) that verifies the fix works with Python 3

Key technical details:
- The transcoder now handles both metadata and error messages consistently
- Fallback behavior remains configurable via existing git-p4.* settings
- Python 2/3 compatibility is maintained through careful byte handling
- Error messages now include more detailed diagnostics when verbose mode is enabled

The patch appears well-structured with clear separation of concerns in the refactoring. Test coverage is added specifically for the error decoding scenario, though the test is marked as Python 3 only due to Unicode handling differences. The change is focused and doesn't introduce new config options, instead leveraging existing ones more broadly.
