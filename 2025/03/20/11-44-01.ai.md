This is patch 6/8 in Karthik Nayak's v4 series implementing batched reference updates with partial failure support, building on the typed error handling introduced in patch 5/8. The core change here is the implementation of batched updates that can partially succeed when individual reference updates fail for non-system reasons, enabled by the `REF_TRANSACTION_ALLOW_FAILURE` flag.

The patch introduces several key infrastructure pieces:
- A `rejection_err` field in `struct ref_update` to track why an update failed
- A new `ref_transaction_rejections` struct to track which updates were rejected
- A `ref_transaction_for_each_rejected_update()` iterator for examining failures
- Backend modifications (files, packed, reftable) to handle partial failures

The implementation distinguishes between system errors (which still abort the whole transaction) and user-input errors (which can be isolated). The packed backend changes are particularly notable as they incorporate the new error handling while maintaining the existing packed-refs file update logic.

This builds toward exposing the functionality via a new `--batch-updates` flag in `git update-ref` (coming in a later patch). The reftable backend stands to gain significant efficiency benefits from this change, as noted in the commit message. The patch includes comprehensive changes across all ref backends while maintaining consistent error handling behavior introduced in the previous patch.
