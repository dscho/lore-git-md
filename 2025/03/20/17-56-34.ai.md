This is part of Taylor Blau's incremental MIDX bitmap implementation series (patch 4/14), focusing on the infrastructure to handle layered bitmap indexes. The patch introduces core plumbing to track and traverse bitmap layers across MIDX chains, adding a `base` pointer to link to previous layers' bitmaps and a `base_nr` counter to know the depth of the chain.

Key technical elements:
- Adds `struct bitmap_index` fields `base` (pointer to previous layer's bitmap) and `base_nr` (chain depth counter)
- Modifies `midx_bitmap_filename()` to handle split MIDX filenames when chains are present
- Extends pack preparation and revindex loading to work recursively through MIDX layers
- Ensures proper cleanup by freeing base bitmaps in `free_bitmap_index()`
- Maintains backward compatibility when no base MIDX exists

The changes are primarily infrastructure work to support the layered bitmap operations that will be implemented in later patches. The commit message notes this is mostly boilerplate setup, with the actual bitmap operations coming in subsequent commits. The patch includes thorough handling of edge cases like non-MIDX bitmaps (with a BUG() check) and proper resource cleanup.
