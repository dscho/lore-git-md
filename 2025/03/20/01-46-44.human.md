This is a bugfix patch series addressing an advice message regression in `git clone` operations with bundle files. The issue causes the "hint: Using 'master' as the name for the initial branch" message to appear unexpectedly even when advice suppression flags (GIT_ADVICE=0 or --quiet) are used.

The regression was introduced in Git 2.45.0 by commit 199f44cb2ead, which changed when the default branch name gets computed during clone operations. The key insight is that the computation moved to `guess_remote_head()` which didn't respect the suppression flags, particularly affecting bundle clones where the remote HEAD can't be automatically determined.

Justin Tobler's solution modifies `guess_remote_head()` to properly support quiet operation by configuring the underlying `repo_default_branch_name()` call (formerly `git_default_branch_name()`). The two-patch series makes the necessary plumbing changes to pass through the quiet flag while maintaining the functionality added in the regression-causing commit.

The fix appears well-targeted, addressing the specific interaction between bundle transport and default branch name computation while preserving the remote helper detection capabilities. The commit message provides clear reproduction steps and technical analysis of the root cause, suggesting this is a thoughtful solution to a real regression.
