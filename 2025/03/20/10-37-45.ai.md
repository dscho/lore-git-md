This is a v2 patch series addressing platform compatibility issues in MinGW file handling, specifically targeting a race condition in `O_CREAT|O_EXCL` operations that causes flaky tests on Windows.

The series has been significantly revised from v1, dropping the previously approved `O_CLOEXEC` patch and adding a new Meson build system fix. The core change remains in `compat/mingw.c` where it modifies error code translation from `EACCES` to `EEXIST` when encountering `STATUS_DELETE_PENDING` during file operations, specifically addressing the t0610 test flakiness in reftable lockfile handling.

Key technical changes in v2:
- Added NtStatus code checking (`STATUS_DELETE_PENDING`) to make the error translation more precise
- New Meson build fix ensuring correct compatibility source file inclusion for MSVC builds
- Dropped the uncontroversial `O_CLOEXEC` patch to focus on the core issue
- Total changes: 23 lines modified across `compat/mingw.c` and `meson.build`

The patch series continues to grapple with the fundamental Windows API limitation where `ERROR_ACCESS_DENIED` can indicate either a legitimate permission error or a pending deletion state. The v2 changes attempt to make the workaround more targeted by checking for the specific `STATUS_DELETE_PENDING` condition, potentially addressing Johannes Schindelin's concerns about masking real permission errors.

The Meson build system change appears to be a straightforward correction for MSVC compatibility, while the MinGW change remains the more complex and potentially controversial part of the series. The discussion from v1 suggests this may need further Windows expertise review, particularly around the error handling trade-offs in lockfile scenarios.
