This is patch 7/8 in Karthik Nayak's v4 series implementing batched reference updates with partial failure support. The patch extends the F/D (file/directory) conflict checking infrastructure to work with the new partial failure model.

The key technical changes:
- Modifies `refs_verify_refnames_available()` to call `ref_transaction_maybe_set_rejected()` when conflicts are detected, allowing individual updates to be rejected rather than failing the entire transaction
- Moves `refs_verify_refnames_available()` from refs.h to refs-internal.h since it now requires transaction context
- Updates both files and reftable backends to pass transaction context and update indices through the verification process
- Adds proper memory management for the update index tracking in string lists used for verification

The implementation maintains the existing behavior when not using batched updates while adding the new failure mode when transactions have the `REF_TRANSACTION_ALLOW_FAILURE` flag. This builds on the typed error reporting introduced in patch 5/8 and the core batched update infrastructure from patch 6/8.

The changes are focused on the files and reftable backends, with both receiving similar treatment to maintain consistency. The patch includes updates to handle memory allocation for the new index tracking and ensures proper error propagation through the stack.

This continues the series' progression toward full batched update support while maintaining the safety checks needed for reference updates. The next patch (8/8) is expected to expose this functionality through `git update-ref --batch-updates`.
