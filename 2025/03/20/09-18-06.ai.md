Refactoring patch in the pretty-format parsing series, addressing lingering padding handling state.

Patrick Steinhardt responds to Martin Ågren's patch 5/8 in the pretty.c refactoring series. The patch fixes a subtle issue where padding state (`struct padding_args`) wasn't fully reset after processing padding directive ("%<" or "%>"), potentially leaking partial state between format placeholders. While Martin notes no current bugs are known to exploit this, the behavior was inconsistent and potentially problematic.

The change adds explicit clearing of `truncate` and `padding` fields after processing, matching the initialization pattern established in previous patches. Patrick suggests consolidating this initialization logic into a macro or function to avoid duplication, though this appears as a non-blocking suggestion rather than a required change.

This continues the series' systematic cleanup of pretty.c's formatting logic, with particular attention to edge cases in padding handling. The patch builds on earlier fixes (notably patch 4/8's padding parsing improvements) and includes test coverage. The change maintains behavior while making the code more robust against potential future issues.
