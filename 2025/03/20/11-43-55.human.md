This is a feature patch series introducing batched reference updates with partial failure support, building on previous ref transaction infrastructure work.

Karthik Nayak's 8-patch series adds a new `--batch-updates` flag to `git update-ref` that allows reference updates to proceed even when some individual updates fail. The core change is implemented through a new `REF_TRANSACTION_ALLOW_FAILURE` flag that modifies transaction behavior to continue after non-fatal errors while still aborting for system failures.

The series carefully builds up this functionality through several preparatory steps: consolidating duplicate refname checks, restructuring reftable backend code, introducing typed transaction errors, and implementing the core batch update infrastructure. The final patch exposes this to users through the new flag, with comprehensive test coverage showing how it handles various error cases while allowing successful updates to proceed.

The implementation appears well-considered, with attention to both performance (leveraging existing transaction infrastructure) and safety (maintaining atomic behavior for system errors). The commit messages are detailed and the test coverage thorough. This seems particularly useful functionality for the reftable backend where batching provides significant performance benefits.

The series has evolved through several iterations based on feedback, with v4 notably changing terminology from "partial transactions" to "batched updates" to better reflect the actual behavior. It builds on Patrick Steinhardt's earlier refname optimization work and has already received review attention from Jeff King and Junio Hamano regarding some implementation details.
