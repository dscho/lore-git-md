This is part of Taylor Blau's incremental MIDX bitmap series (v5 12/14), focusing on the performance optimization aspect. The patch extends the bitmap_index structure to track type-level bitmaps (commits, trees, blobs, tags) across all layers of a multi-pack index (MIDX) chain, preparing for efficient cross-layer bitmap operations.

The key change introduces four new arrays (commits_all, trees_all, blobs_all, tags_all) that store each layer's type bitmaps in reverse order (current layer last). A new load_all_type_bitmaps() function populates these arrays by walking the MIDX chain, while maintaining backward compatibility for non-incremental cases. The patch also adds proper cleanup of these arrays in free_bitmap_index().

This is a technical plumbing change that enables the EWAH bitmap iterator optimization introduced in patch 11/14, allowing efficient OR operations across MIDX layers without full decompression. The implementation looks thorough, with careful handling of the bitmap layer counting (including a BUG check for consistency) and proper resource management. As part of the larger series that's now in its fifth iteration, this appears to be a well-considered piece of the incremental MIDX bitmap puzzle.
