This is part 2 of Karthik Nayak's 8-patch series v4 on batched reference updates with partial failure support. The patch moves duplicate refname checking from individual backends (files, packed, reftable) into the generic refs.c layer, centralizing what was previously backend-specific logic.

Key technical changes:
- Adds a `refnames` string_list field to `ref_transaction` to track all references in a transaction
- Updates are automatically added to this list in `ref_transaction_add_update()`
- Backends now use this centralized list rather than maintaining their own
- Special handling for symrefs and HEAD updates to maintain existing behavior
- Reftable backend reorders its duplicate check to happen before adding to transaction
- Removes ~114 lines of duplicate code across the three backends

The change builds on Patrick Steinhardt's earlier work on batched refname checks and is particularly beneficial for the reftable backend's performance. This is a clean refactoring that reduces code duplication while maintaining all existing functionality. The patch appears well-tested as part of the larger series (which includes 233 lines of test coverage across 8 scenarios).
