Refactoring patch in the pretty-format parsing series, addressing lingering padding state issues.

This is patch 5/8 in Martin Ågren's series refactoring Git's pretty-format parsing code. The patch fixes incomplete reset of padding state in `struct padding_args` after processing, explicitly clearing the `truncate` and `padding` fields that were previously left with stale values. Patrick Steinhardt had noted this partial reset was surprising behavior, agreeing it should be fixed.

In this follow-up, Martin acknowledges Patrick's suggestion to consolidate initialization logic into a helper function (`padding_args_clear()`), planning to introduce it in the preceding commit and reuse it here. He also notes the current implicit reliance on enum zero-initialization (where `no_flush` and `trunc_none` happen to be zero) and considers adding a preparatory patch to make these zero-values explicit, potentially auditing other enums in pretty.c for similar cases.

The change maintains the series' pattern of making the pretty-format parsing code more robust while preserving existing behavior. The thread shows active collaboration between Martin and Patrick, with this patch now addressing all identified issues from the initial review.
