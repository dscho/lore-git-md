This thread addresses an encoding issue in the `git p4` bridge where Perforce error messages in non-UTF-8 encodings could cause failures. Nikolay Shustov's patch series extends the existing metadata transcoding framework to handle error messages consistently, applying the same configurable fallback strategy (`git-p4.metadataDecodingStrategy` and `git-p4.metadataFallbackEncoding`) that was used for metadata.

The solution introduces a new `MetadataTranscoder` class that consolidates the encoding handling logic, refactored from `metadata_stream_to_writable_bytes()`. It maintains Python 2/3 compatibility through careful byte handling without requiring new configuration. The patch includes enhanced diagnostics in `MetadataDecodingException` and adds Python 3-specific test coverage via `t9837-git-p4-error-encoding.sh`, though testing is limited to Python 3 due to Unicode handling differences between Python versions.

The changes build on prior work for handling encoding issues in the git-p4 bridge and appear ready for maintainer consideration, with no outstanding technical objections raised in the discussion. This fix is particularly valuable for organizations migrating from Perforce to Git where non-UTF-8 error messages might otherwise block the transition.
