This is a follow-up discussion in the thread about handling slashes in remote names for Git's bash completion. David Mandelberg responds to Junio Hamano's questions about the prevalence and intentionality of slashes in remote names.

Mandelberg notes that while he's not the only one using slashes in remote names (citing a GitHub Desktop issue), he's unsure how common the practice is. He speculates he may have adopted the pattern from seeing slashes used in branch names, though he questions whether that was intentional design or an accident of implementation.

The email highlights an important technical consideration Junio raised - that slashes in remote names can interfere with Git's mechanism for detecting local file:// URLs. Mandelberg acknowledges this as a valid reason to avoid slashes that he hadn't previously considered.

The core question raised is whether to proceed with the completion fixes for slashed remote names (which the patch series addresses) given that remote names with slashes may be discouraged in future Git versions. Mandelberg worries that fixing the behavior might inadvertently endorse the practice, while leaving it broken could serve to discourage it.

This discussion doesn't propose any code changes but rather explores the broader implications of the naming convention issue that underlies the technical fixes in the patch series. It represents a higher-level design consideration about Git's remote naming policies that may influence future Git versions.
