Bugfix for tag-following regression in protocol v2 fetches. This patch addresses a problem introduced by commit 3f763ddf28 where unconditionally adding "HEAD" to ref prefixes broke tag decoration when fetching specific commits. The issue occurs because the tag-following code carefully adds "refs/tags/" only when other prefixes exist, but the unconditional HEAD addition created an incomplete prefix list that prevented tag advertisement.

Taylor Blau and Jeff King propose a conservative fix that makes HEAD prefix addition conditional, similar to the existing tag logic. The patch includes a test demonstrating the fixed behavior when fetching a specific OID with tag following. The authors note this is a "fairly nasty bug" worth considering for the 2.49 release despite being late in the RC cycle.

This appears to be a well-justified fix for a clear regression, with test coverage and coordination between the original reporter, commit author, and other maintainers. The solution follows the pattern already established for tag handling while avoiding more invasive architectural changes that were discussed earlier in the thread.
