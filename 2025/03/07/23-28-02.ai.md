Build system improvement enabling unreachable code detection in Clang.

This is Junio Hamano's response to Jeff King's patch adding `-Wunreachable-code` to developer builds. The patch was motivated by an earlier discussion where Coverity found unreachable code path in Karthik Nayak's ref transaction series that could have been caught earlier with this compiler warning.

Junio agrees with the change, noting it would have helped catch the issue sooner. He finds it amusing that GCC silently accepts the option without implementing it, potentially confusing users. The key technical points confirmed are that Clang properly implements the warning (and already flags the known packed backend issue), while GCC maintains compatibility by accepting the flag without functionality. 

The response highlights the value of layered quality checks in Git's development process - this compiler warning complements existing static analysis and human review. No new technical concerns are raised about the patch itself, which had already passed CI testing. The exchange demonstrates maintainer approval for adding this warning to catch similar issues earlier in development.
