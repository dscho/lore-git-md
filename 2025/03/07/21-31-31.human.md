Bugfix for ref exclusion pattern behavior in Git's ref iteration. This is the second patch in a v2 series that addresses inconsistencies in how `--exclude` patterns are handled across different ref backends (files, packed, reftable). The patch specifically fixes the case where non-directory prefixes (e.g., "refs/heads/ba") were incorrectly matching full refnames (e.g., "refs/heads/bar") in the packed and reftable backends.

The solution normalizes exclude patterns by adding trailing slashes when they don't already have them, ensuring directory boundaries are respected. This change makes all backends behave consistently with the files backend, which already had the correct behavior. The patch includes test updates to verify the new behavior and corrects some tests that were previously codifying the buggy behavior.

Elijah Newren raises a valid concern about whether this change means exact ref matches (without trailing slashes) will no longer be excluded, but notes that this appears acceptable since the exclusion is meant to be a fast filter with the caller responsible for final filtering. He compares this to similar patterns in dir.c but acknowledges the context is simpler here. The patch has already incorporated feedback from several reviewers and appears technically sound, though Newren suggests the commit message could better document this edge case.
