Bugfix for tag-following regression in protocol v2 fetches. This patch addresses a specific interaction between three recent changes that broke tag decoration when fetching specific commits under protocol v2 with depth limits. The core problem stems from commit 3f763ddf28 unconditionally adding "HEAD" to ref_prefixes, which conflicts with the tag-following code's assumption that prefix lists are either complete or empty.

The fix makes HEAD prefix addition conditional on an existing prefix list (mirroring the existing tag-following logic), ensuring tags are properly advertised when needed. The patch includes a new test case verifying tag following works when fetching specific OIDs. Co-authored by Jeff King, this represents a conservative fix that could be backported to the 2.49 release cycle despite being late in the rc phase.

Key technical details:
- Modifies `builtin/fetch.c` to conditionally add HEAD to ref_prefixes
- Adds test case in `t/t5503-tagfollow.sh` for OID-specific fetches
- Preserves the invariant that prefix lists must be complete or empty
- Maintains compatibility with protocol v2's advertisement semantics

The patch follows up on earlier discussion where Jeff King analyzed the architectural tension between optimization and maintainability in protocol v2's prefix handling. While this solution addresses the immediate regression, the underlying design questions about coordinating multiple prefix components remain open for future discussion.
