This is a refactoring patch that's part of the ongoing merge strategy modernization effort, specifically adding infrastructure to help transition from merge-recursive to merge-ort.

The patch introduces a new `merge_ort_generic()` function that provides equivalent functionality to merge-recursive's `merge_recursive_generic()`, completing the set of entry points needed to fully replace merge-recursive. The implementation handles tree and commit references, merge base processing, and index locking, while delegating the actual merge logic to existing merge-ort functions.

The changes span four files in the merge-ort implementation, adding about 90 lines of code. The patch includes some internal adjustments to support this new entry point, like making `make_virtual_commit()` visible to the wrappers and relaxing an assertion to accommodate builtin/am's use case.

As the first in a 3-patch series (with 19 more planned across subsequent series), this is foundational work from an experienced contributor. The changes appear carefully considered and well-tested, with clear documentation of the new function's purpose and behavior matching the recursive counterpart. This is a straightforward but important step in the larger merge-ort adoption effort.
