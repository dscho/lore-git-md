This is the second patch in a two-part bugfix series restoring zlib version reporting functionality in `git version --build-options`. The patch adds support for zlib-ng builds, which use a different header and version macro (`ZLIBNG_VERSION`) than standard zlib (`ZLIB_VERSION`).

The change is straightforward: when compiled with zlib-ng, Git will report "zlib-ng: [version]" instead of looking for the standard zlib version string. The test suite is updated to verify that some zlib version information appears in the output, without being specific about which variant is in use.

This completes the fix started in the first patch, ensuring version reporting works for both standard zlib and zlib-ng builds. The implementation is clean and minimal (just 5 lines changed across two files), with clear fallback behavior. The test change provides basic verification while remaining flexible enough to work with either zlib variant.
