This is the second patch in a bugfix series addressing ref exclusion pattern matching in Git's ref backends. The patch tightens the matching rules for `--exclude` patterns to require either exact matches or proper directory boundaries (e.g., "refs/heads/ba" would no longer incorrectly match "refs/heads/bar").

The discussion with Junio clarifies an important architectural point: while Git's pattern matching subsystems typically allow backends to be permissive (filtering candidates early while letting upper layers do exact matching), the ref exclusion case is different because false positives (incorrectly excluded refs) can't be corrected later since excluded refs are never surfaced to upper layers. The patch fixes this by making the backend matching more precise.

Patrick notes some remaining concerns about test coverage gaps in the files backend due to its split between packed and loose refs, though this doesn't block the current fix. The reftable backend avoids this issue entirely. The patch appears technically sound and addresses all prior feedback, though Junio's comments suggest this area may warrant future architectural review regarding optimization layers.
