This is a bugfix patch series addressing a regression in zlib version reporting. The series consists of two patches that restore functionality where `git-version` should display the zlib version being used, which was broken by a header reorganization in commit 41f1a8435a.

The first commit fixes a regression caused by moving zlib.h includes, ensuring the zlib version gets printed again when using standard zlib. The second commit extends this to properly handle zlib-ng builds by adding explicit version printing for that library variant. Both changes are verified by updates to the bugreport test script.

Key technical details for future reference:
- The regression stemmed from `git-compat-util.h` no longer including zlib.h directly
- The fix adds `#include "git-zlib.h"` to help.c where version info is printed
- For zlib-ng, the patch adds detection of `ZLIB_NG_VERSION` define
- Test t0091-bugreport.sh is updated to verify version string output
- Changes are minimal (5 lines added, 2 removed) and focused on the version reporting feature

The patches appear straightforward and well-motivated, addressing a clear regression in functionality that would be useful for debugging and compatibility checking. The test coverage helps ensure the fix works as intended.
