This thread introduces a patch series that lays groundwork for removing the legacy `merge-recursive` strategy in favor of `merge-ort`, part of Git's ongoing merge machinery modernization. The author, an experienced contributor to this effort, presents three strategic building blocks needed before callers can be converted: a new `merge_ort_generic()` function as a drop-in replacement for `merge_trees()`, rename detection control matching recursive's capabilities, and verbosity level support in merge-ort output.

The changes are relatively small (about 100 net new lines) but carefully targeted, touching merge strategy documentation and key merge-ort implementation files. The author notes this is the first of five planned series totaling 19 patches for the complete transition, and offers to expand the current submission to include the first actual caller conversion (git-am.sh) if reviewers prefer to see the new API in context. The work builds on years of effort to make merge-ort Git's default strategy, with these patches representing the final preparatory steps before recursive can be fully deprecated.
