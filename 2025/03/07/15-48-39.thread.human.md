This thread documents Elijah Newren's multi-part effort to replace Git's `merge-recursive` strategy with the newer `merge-ort` implementation, focusing on converting `git-am` to use the new backend. The series has progressed through API design, test coverage expansion, and now demonstrates full behavioral parity in `git-am` with a 6-patch subset of the larger 19-patch plan.

Key technical work includes the `merge_ort_generic()` wrapper that replaces `merge_recursive_generic()`, with improvements in ancestor labeling, configurable rename detection, and directory rename edge case handling. The `git-am` conversion itself required minimal code changes but revealed `merge-ort`'s stricter conflict detection through test adjustments in t4151 (untracked files), t4255 (submodules), and t6427 (conflict markers).

Jeff King (Peff) recently contributed historical context about why rename detection was temporarily disabled during GitHub's internal migration from shell scripts to libgit2 and later to `merge-tree` - a transitional decision rather than a deliberate design choice. While not requiring changes to the current series, this insight helps explain some real-world deployment considerations that influenced the design.

The thread shows consensus that `merge-ort` is now production-ready for `git-am` use, with all identified test issues either resolved or properly documented as intentional behavior improvements. This marks a significant milestone in the broader `merge-recursive` deprecation effort.
