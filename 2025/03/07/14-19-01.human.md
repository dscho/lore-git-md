This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` usage in object APIs (patch 8/12). The patch focuses on `object-file-convert.c`, which handles hash algorithm conversions for objects.

The change makes `convert_object_file()` take a repository parameter and passes it through to all internal conversion functions (for commits, trees, and tags), removing the need to use `the_repository` or `the_hash_algo` globals. The patch also removes the now-unneeded `USE_THE_REPOSITORY_VARIABLE` define.

The conversion is straightforward - each internal function now takes a `repo` parameter that's passed down from the top-level call. The changes cascade through several callers in `builtin/tag.c`, `commit.c`, and `object-file.c`, all of which now explicitly pass `the_repository` where they previously relied on the global.

This is a clean, mechanical conversion that follows the established pattern in the series. The patch maintains all existing functionality while moving toward the goal of repository independence. The changes are well-contained to the object conversion subsystem and don't introduce any new complexity.
