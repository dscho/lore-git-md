This is a bugfix for the partial reference transaction implementation in the packed refs backend. Jeff King (Peff) identifies an unreachable code path in the error handling logic where a `return` statement makes subsequent code impossible to execute. The issue was caught by Coverity static analysis in the integration branch.

The problematic section attempts to handle nonexistent reference errors in partial transactions by marking them as rejected updates, but the early `return` prevents this from working. Peff suggests the `return` should likely have been an assignment to `ret` instead, though notes the issue might originate in an earlier patch.

This appears to be a straightforward logic error in the packed backend's implementation of partial transaction support. The fix would ensure proper error handling for nonexistent references when partial transactions are enabled, maintaining consistency with the files and reftable backends' behavior. The patch is part of Karthik Nayak's larger series introducing partial transaction support with the `--allow-partial` flag for `git update-ref`.
