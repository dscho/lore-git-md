This is a refactoring patch in Patrick Steinhardt's series to reduce `the_repository` usage in object APIs. It splits out hash algorithm implementation from object-file.c into a new hash.c file.

The patch moves all hash-related functionality - including the hash algorithm table, initialization/clone/update/final functions for SHA-1 and SHA-256, and helper functions like `hash_algo_by_name()` - into a dedicated hash.c file. This separates concerns between object file handling and hash algorithm implementation, making the codebase more modular. The change is purely organizational - no behavior changes, just moving code between files.

Key technical details:
- Creates new hash.c with 283 lines of hash implementation code moved from object-file.c
- Updates Makefile and meson.build to include the new source file
- Maintains all existing hash algorithm support (SHA-1 and SHA-256)
- Preserves all helper functions like `null_oid()` and `empty_tree_oid_hex()`
- Keeps the unsafe hash variants used for performance-sensitive cases

This is patch 10/12 in v3 of the series, continuing the systematic elimination of global state by better organizing the codebase. The separation of hash algorithms into their own file is a preparatory step for further repository independence work.
