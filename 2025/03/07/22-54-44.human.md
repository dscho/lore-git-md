This is a developer infrastructure patch that enables a compiler warning flag to catch unreachable code, prompted by a recent discussion about a bug in the packed refs code.

Jeff King proposes adding `-Wunreachable-code` to the developer compiler flags after discovering that a recent patch series had unreachable code that wasn't caught during review. While this warning is effectively a no-op in GCC (kept only for backward compatibility), it does work in Clang and would have flagged the problematic code earlier. The patch includes background on why this is useful, noting that while Coverity found the issue, compiler warnings could catch similar problems sooner.

The change is minimal - just one line added to `config.mak.dev` - but demonstrates Git's commitment to code quality through layered defenses (human review, static analysis, and now expanded compiler checks). King notes this already catches the known issue in CI testing. The patch is clearly motivated by a concrete problem and provides a straightforward improvement to the development process.
