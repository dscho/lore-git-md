This is a continuation of the discussion about Windows build system compatibility and CI testing during Git's Meson transition. Junio Hamano responds to Patrick Steinhardt's defense of keeping Windows CI jobs that test general builds (as opposed to Git for Windows SDK-specific builds).

The exchange reveals several key tensions:
1. Junio questions the value of testing multiple Windows variants given limited developer resources, suggesting it may create more noise than signal for Windows users
2. He acknowledges the reality that Git for Windows is effectively the dominant Windows port, making specialized CI jobs less critical
3. There's an underlying concern about the lack of broader Windows developer engagement in build system issues
4. Junio hints at resignation about Windows being a "special case" that may need different handling than other platforms

The discussion remains unresolved but shows Junio moving toward accepting that Git for Windows may need to be treated as the primary (if not sole) Windows reference implementation. The technical specifics from earlier in the thread (const-correctness fixes, Meson/CMake adjustments) are now background to this higher-level policy discussion about Windows support strategy.
