This is a bugfix patch restoring zlib version reporting functionality in `git version --build-options`. It addresses a regression caused by commit 41f1a8435a's header changes which inadvertently broke the zlib version display by removing an indirect `zlib.h` include.

The patch simply adds a direct include of `git-zlib.h` to help.c where the version information is printed. This is a minimal one-line change that precisely targets the regression. The commit message clearly explains both the cause (header reorganization) and effect (missing zlib version in build options output).

This is the first of two patches in the series, with the second handling zlib-ng compatibility. The change is straightforward with clear motivation and maintains the existing behavior exactly as it was before the regression. Test coverage in t0091-bugreport.sh verifies the version string functionality works as expected.
