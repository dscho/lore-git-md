Git reflog management enhancement series (2 patches) introducing a 'drop' subcommand to `git reflog` for deleting entire reflogs, with an '--all' flag for repository-wide cleanup. Originating author proposes solving the limitation where users can only expire individual entries but not remove reflogs entirely, addressing accumulation issues even with core.logAllRefUpdates=false.

First patch refactors builtin/reflog.c as part of the `the_repository` removal effort, eliminating all direct and indirect uses of the `the_repository` global variable. The changes are mechanical but thorough, replacing global usage with the repository struct already available to builtin commands. Specifically:
- Removes 14 instances of `the_repository` usage
- Updates 5 command handler functions to use `repo` parameter
- Changes `git_config()` to `repo_config()`
- Affected subsystems: reflog commands (show, list, expire, delete, exists)
- Follows established pattern for removing repository globals

Second patch implements the 'drop' subcommand functionality, touching documentation, reflog builtin, and adding tests. Builds on prior discussion about reflog management, referencing earlier --no-reflog proposal for `git refs migrate`.

Key technical details:
- New subcommand: `git reflog drop <ref>`
- New flag: `--all` for all-ref deletion
- Affected files: builtin/reflog.c, Documentation/git-reflog.txt, t/t1410-reflog.sh
- Removes dependency on global variables in reflog.c (completed in first patch)

Implementation appears complete with tests and docs. The preparatory refactoring in the first patch enables the new functionality to be added without introducing more global state, aligning with Git's ongoing architectural effort. No open questions or objections raised yet in this initial submission.
