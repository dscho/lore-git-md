Git reflog management enhancement (2 patches) introducing a 'drop' subcommand to `git reflog` for deleting entire reflogs, with an '--all' flag for repository-wide cleanup. Originating author Karthik Nayak addresses the limitation where users can only expire individual entries but not remove reflogs entirely, particularly useful for repositories with core.logAllRefUpdates=false.

First patch completed the refactoring of builtin/reflog.c as part of the `the_repository` removal effort, eliminating all 14 instances of the global variable usage and updating 5 command handlers to use explicit repository parameters. This mechanical but thorough change enables the subsequent functionality addition without introducing global state.

Second patch implements the 'drop' subcommand functionality, with Patrick Steinhardt providing substantive review feedback that has now been fully addressed through multiple iterations. Final refinements focus on code style in `cmd_reflog_drop()`:
- Variable initialization moved from separate assignments to direct declaration initialization
- Loop counter `i` scope narrowed by declaring within loop construct
- All changes made in response to Patrick Steinhardt's review suggestions

Implementation maintains:
- Support for single-ref (`git reflog drop <ref>`) and all-ref (`--all`) deletion modes
- Worktree awareness through `get_worktrees()` and `refs_for_each_reflog`
- Comprehensive test coverage in t1410-reflog.sh including error cases

Documentation improvements clarify behavior differences between 'drop', 'expire', and 'delete' subcommands and worktree behavior. All design and implementation questions have been resolved through review exchanges, with the series now addressing all raised points including final stylistic polish.
