Git reflog management enhancement (2 patches) introducing a 'drop' subcommand to `git reflog` for deleting entire reflogs, with '--all' and '--single-worktree' flags. Originating author Karthik Nayak addresses the limitation where users can only expire individual entries but not remove reflogs entirely, particularly useful for repositories with core.logAllRefUpdates=false.

First patch implements the 'drop' subcommand functionality:
- Uses `refs_delete_reflog` after reference resolution via `repo_dwim_log`
- Handles worktrees through `get_worktrees()` and `refs_for_each_reflog`
- Enforces mutual exclusion between --all and explicit references
- Adds `--single-worktree` flag for feature parity with `expire` subcommand
- Provides standardized error messages for invalid references using `usage()`
- Comprehensive test coverage in t1410-reflog.sh for single-ref, multi-ref, --all, --single-worktree cases and error conditions
- Documentation reorganized with "drop" between "delete" and "exists" sections, clearly distinguishing "drop" (reflog structure), "expire" (entries), and "delete" (refs)

Second patch improves error messaging in `git reflog expire` when given invalid references, changing from "points nowhere!" to "reflog could not be found" for non-existent references or reflog entries. Updates both implementation in builtin/reflog.c and test expectations in t/t1410-reflog.sh, covering invalid entries (main@{123}) and non-existent references (does-not-exist). Standalone improvement to existing functionality that fits with the series' focus on reflog management.
