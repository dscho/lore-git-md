Git reflog management enhancement (2 patches) introducing a 'drop' subcommand to `git reflog` for deleting entire reflogs, with an '--all' flag for repository-wide cleanup. Originating author Karthik Nayak addresses the limitation where users can only expire individual entries but not remove reflogs entirely, particularly useful for repositories with core.logAllRefUpdates=false.

First patch (now withdrawn) had completed refactoring of builtin/reflog.c as part of `the_repository` removal effort. Karthik Nayak conceded to Junio Hamano's architectural concerns after demonstrating the help-text behavior remains unchanged (git reflog -h works outside repository while git reflog list -h fails, matching current Git 2.48.1 behavior). Agreed to separate architectural cleanup from new functionality, resolving the immediate discussion while leaving open the broader question of `the_repository` removal boundaries in builtin commands.

Second patch implements the 'drop' subcommand functionality with all review feedback addressed:
- Uses `refs_delete_reflog` after reference resolution via `repo_dwim_log`
- Handles worktrees through `get_worktrees()` and `refs_for_each_reflog`
- Enforces mutual exclusion between --all and explicit references
- Provides standardized error messages for invalid references
- Comprehensive test coverage in t1410-reflog.sh for single-ref, multi-ref, --all cases and error conditions
- Documentation clearly distinguishes "drop" (reflog structure), "expire" (entries), and "delete" (refs)

Patrick Steinhardt's technical review fully incorporated (variable initialization, loop scope, documentation clarity). Junio Hamano's documentation synchronization request implemented. Kristoffer Haugsbakk's real-world validation confirms the feature's utility for workflows needing selective reflog deletion between core.logAllRefUpdates modes (always/true), providing concrete evidence that the functionality solves actual user pain points where neither full retention nor blanket disabling of reflogs suffices.

All implementation and documentation issues are resolved, with only the withdrawn first patch's architectural questions remaining open for future discussion elsewhere in the project. The series now stands ready for merging with its focus narrowed to the user-facing reflog deletion capability, having addressed both technical requirements and demonstrated practical need through user validation. The implementation follows Git's established patterns for subcommand implementation in builtin/reflog.c, adding the new command alongside existing ones with its own usage string and option parsing.
