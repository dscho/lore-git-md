Git reflog management enhancement (2 patches) introducing a 'drop' subcommand to `git reflog` for deleting entire reflogs, with an '--all' flag for repository-wide cleanup. Originating author Karthik Nayak addresses the limitation where users can only expire individual entries but not remove reflogs entirely, particularly useful for repositories with core.logAllRefUpdates=false.

The withdrawn patch (originally first in series) completed refactoring of builtin/reflog.c as part of `the_repository` removal effort. Junio Hamano confirmed the help-text behavior discrepancy (git reflog -h working outside repository while git reflog list -h fails) is pre-existing behavior, not a regression from the patch. This architectural issue requires broader consideration and will be deferred, with Karthik Nayak agreeing to separate it from the immediate feature implementation.

Second patch implements the 'drop' subcommand functionality with all review feedback addressed:
- Uses `refs_delete_reflog` after reference resolution via `repo_dwim_log`
- Handles worktrees through `get_worktrees()` and `refs_for_each_reflog`
- Enforces mutual exclusion between --all and explicit references
- Provides standardized error messages for invalid references
- Comprehensive test coverage in t1410-reflog.sh for single-ref, multi-ref, --all cases and error conditions
- Documentation clearly distinguishes "drop" (reflog structure), "expire" (entries), and "delete" (refs)

Patrick Steinhardt's technical review fully incorporated (variable initialization, loop optimization, documentation clarity). Junio Hamano's documentation synchronization request implemented.
