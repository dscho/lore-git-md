This is a bugfix patch series addressing a regression in version reporting for zlib dependencies.

Toon Claes noticed that `git version` wasn't correctly reporting the zlib version being used, which became important when comparing performance between zlib and zlib-ng. The issue stemmed from a recent change (41f1a8435a) that moved zlib header includes but accidentally broke the version reporting.

The first patch fixes the regression by properly including git-zlib.h where needed. The second patch goes further to ensure the version is reported correctly when building against zlib-ng specifically. Both changes are small and focused, touching just the help.c file and adding test coverage.

The patches look straightforward and well-motivated - this is clearly a real issue affecting users who need to verify their zlib version. The changes are minimal and come with test updates to prevent future regressions. The series should be uncontroversial and likely to be accepted.
