This is a maintainer response to a build system patch that enables a compiler warning. The thread involves two main discussions: Karthik Nayak's partial reference transaction series (where an unreachable code issue was found), and Jeff King's follow-up patch adding `-Wunreachable-code` to developer builds to catch such issues earlier.

Junio Hamano agrees with Jeff King's patch to enable `- Wunreachable-code` in `config.mak.dev`. He acknowledges that while GCC silently accepts this flag without effect (due to historical reasons), Clang does implement it properly and would have flagged the packed backend issue found in Karthik's series. The maintainer appreciates that this adds another layer to Git's quality control system, especially since Clang is already used in CI.

The exchange highlights how the project benefits from its multi-faceted approach to catching issues: human review (which found the dead store in reftable), static analysis (Coverity found the unreachable code), and now compiler warnings (via Clang) will catch similar cases earlier. The tone is positive, with Junio clearly supporting this defensive improvement to the build system.
