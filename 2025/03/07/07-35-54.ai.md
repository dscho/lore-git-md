This is a technical discussion thread about the proposed inline code commenting feature for Git. ZheNing Hu responds to Randall Becker's concerns about implementation challenges, particularly around comment storage and synchronization.

The email focuses on the technical feasibility of storing and tracking line-specific comments through Git's history. Hu acknowledges the complexity of implementing comment system that would need to: 1) store comments in a format like `commit:file:{lines:note}` similar to Git notes, 2) track comments through file history using blame-like functionality, and 3) handle comment merging between users. The discussion reveals significant technical hurdles in making comments persist accurately through code changes while maintaining user control over private vs. shared annotations.

Key technical challenges identified include: the forward-tracing nature of comment tracking (opposite of blame's reverse approach), the need for selective comment sharing between developers, and potential conflicts with proprietary platform features. Hu begins to question whether such a system might be better implemented outside core Git, perhaps as a service-layer feature.

The exchange highlights growing doubts about the practicality of implementing decentralized line comments while maintaining compatibility with Git's core architecture and existing hosting platforms. The technical discussion remains focused on storage formats and change tracking rather than user interface or command design aspects mentioned in earlier messages.
