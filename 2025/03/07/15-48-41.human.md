This is the second patch in a 3-part series preparing for the merge-recursive to merge-ort transition, focusing on feature parity between the two merge strategies. The patch adds support for disabling rename detection in merge-ort, matching functionality that was previously only available in merge-recursive.

The change comes after years of merge-ort development where rename detection was always enabled, as the author initially believed performance was the only reason users might disable it. With merge-ort's optimized rename detection and no reported performance issues, plus a request for behavioral (not performance) control, the patch now honors the `no-renames` option and `merge.renames` config setting.

The implementation is straightforward - adding an early exit in the rename processing logic when detection is disabled. Documentation updates clarify that merge-ort now supports the same rename-related options as merge-recursive, removing it from the list of ignored options. This is a well-justified change from an experienced contributor, completing an important piece of interface compatibility between the old and new merge strategies.
