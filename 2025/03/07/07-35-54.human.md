Feature proposal follow-up on decentralized inline code commenting for Git. ZheNing Hu responds to Randall Becker's technical concerns about implementing line-specific annotations in Git's distributed model.

The discussion focuses on storage mechanics, acknowledging that while the data structure could resemble `git notes`, the real challenge lies in tracking comments through file history changes. Hu notes that `git blame`'s reverse-history approach may not directly translate to forward-tracing needed for comment persistence.

Key concerns raised include:
- The complexity of merging comments from multiple developers while preserving personal annotations
- Potential conflicts with proprietary features from GitHub/GitLab
- Whether this functionality might be better handled outside core Git

The exchange shows the proposal moving from initial enthusiasm to recognizing deeper implementation hurdles, particularly around distributed synchronization and version-tracking of line-specific metadata. While the feature's value remains clear, the technical path forward appears less certain.
