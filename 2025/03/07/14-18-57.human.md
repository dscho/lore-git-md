This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global usage, specifically targeting the "core.bigFileThreshold" configuration setting. The patch moves this threshold value from a global variable into `struct repo_settings`, making it repository-specific and properly cached.

The change affects how Git handles large files across multiple commands including archive, fast-import, pack operations, and diff. The main motivation is to support multi-repository operations where different repositories might need different threshold values, while also advancing Git's libification by removing global state.

A test in t1050 had to be adjusted since the original test command didn't actually use the threshold value - it now uses `git hash-object` which does read the setting. The patch follows the established pattern of this series with careful, mechanical conversions that maintain existing behavior while enabling future improvements.

The changes touch 15 files with 52 insertions and 22 deletions, showing the wide impact of this configuration setting across Git's codebase. This appears to be a well-executed step in the larger `the_repository` removal effort, with appropriate test coverage and clear explanation of the rationale.
