This is a follow-up discussion about remote naming conventions and URL detection in Git, building on the completed patch series for bash completion of slashed remote names.

Junio Hamano confirms that Git's current behavior of checking for local filesystem paths when interpreting remote names is intentional, even for simple names without slashes. He acknowledges that while this can cause confusion (like accidentally pushing to a local directory named "origin" rather than the remote), the issue becomes significantly more problematic with slashed remote names where the ambiguity is harder to spot.

The discussion clarifies that while the completion script fixes are ready for integration, this separate issue about URL detection affects Git's core behavior more broadly. Junio suggests that limiting filesystem references to paths with "../" or "/" prefixes might reduce accidental misuse, though this would be a separate consideration from the completion improvements.

The thread shows that the completion script work remains sound while surfacing a related but distinct architectural question about remote name interpretation that may warrant future discussion.
