This is a follow-up discussion in the bash completion thread regarding remote names containing slashes. David Mandelberg responds to Junio Hamano's historical context about remote naming conventions, providing additional perspective on the practical implications.

The email reveals that while slashed remote names are not officially supported, they do occur in the wild (referencing a GitHub Desktop issue) and some users (including the author) adopted them by analogy with branch naming conventions. Mandelberg acknowledges Junio's point about filesystem URL detection being a technical reason to avoid slashes in remote names, which was previously unknown to him.

The key new consideration raised is whether fixing the completion script for slashed remote names would inadvertently encourage their use, given that they may be deprecated in a future Git 3.0 release. This creates a tension between current usability and future compatibility - fixing the completion would help existing users but might conflict with potential future naming restrictions.

The discussion remains unresolved on whether to proceed with the completion fixes given this broader architectural consideration. Mandelberg seeks guidance on whether to continue with the technical solution (which the thread has largely converged on) or leave the behavior broken to discourage an unofficial usage pattern that may be formally restricted later.
