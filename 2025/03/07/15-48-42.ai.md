This is the third and final patch in a series preparing for the merge-recursive to merge-ort transition, focusing on verbosity control parity. The patch adds support for zero verbosity level in merge-ort's output handling, matching behavior that callers like `git am` and `git checkout` currently rely on in merge-recursive.

The change is minimal (just 2 lines) but strategically important for compatibility - it prevents conflict messages from being printed when verbosity is set to 0, which several existing callers depend on. The implementation adds an early return in `path_msg()` when `opt->verbosity` is 0, placed between existing checks for header messages and inner merge filtering.

This completes the behavioral parity aspects of the series, following the earlier patches that introduced API compatibility wrappers and rename detection control. The change is straightforward and unlikely to be controversial, being a clear case of matching existing behavior during the strategy transition. The patch maintains the series' careful approach of enabling direct drop-in replacement of merge-recursive with merge-ort.
