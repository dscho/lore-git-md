This is part 1/12 of Patrick Steinhardt's series to reduce `the_repository` usage in object APIs, specifically targeting the csum-file subsystem. The patch removes direct and indirect dependencies on the global `the_repository` variable from csum-file.c by making hash algorithm parameters explicit in the API.

The changes modify all hashfile-related functions to accept a `git_hash_algo` parameter, removing their implicit use of `the_hash_algo` (which itself depends on `the_repository`). This affects core checksumming operations across multiple subsystems including pack operations, commit-graph, midx, and bitmap handling. The patch updates 14 files with 56 insertions and 39 deletions, primarily adding hash algorithm parameters to function calls and implementations.

Key technical changes include:
- New `algop` parameter added to `hashfd()`, `hashfd_check()`, `hashfd_throughput()`, and `hashfile_checksum_valid()`
- Removal of `USE_THE_REPOSITORY_VARIABLE` define from csum-file.c
- Updates to all callers to pass either `the_repository->hash_algo` or their context's hash algorithm
- Preservation of existing buffer size optimizations (128KB for normal operation, 8KB when showing progress)

The changes maintain all existing functionality while making the hash algorithm dependency explicit. This is a foundational change for the larger series' goal of repository independence, with csum-file operations being a core primitive used throughout Git's object handling code. The patch follows the series' established pattern of mechanical but careful refactoring, with comprehensive updates to all affected call sites.
