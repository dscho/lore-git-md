This is a discussion about Windows build system compatibility and CI strategy in the ongoing Meson transition.

Patrick Steinhardt responds to Junio Hamano's concerns about Windows Meson build reliability, arguing that while the current CI jobs don't perfectly match Git for Windows' needs, they still provide valuable testing coverage. He clarifies that the existing "win+Meson" jobs serve as additional platform variant testing rather than a direct replacement for Git for Windows builds, similar to how different Linux distributions are tested.

The email reveals a tension between two perspectives: Junio's caution about untested build configurations versus Patrick's view of the CI jobs as useful complementary testing. Patrick offers to quickly address any reported issues and suggests the possibility of adding SDK-specific Meson jobs in the future, though he hasn't seen an immediate need.

This exchange comes after Junio accepted the technical const-correctness fix from the patch series while expressing broader skepticism about Windows Meson readiness. The discussion highlights the challenges of balancing build system modernization with platform-specific reliability concerns, particularly for Windows where toolchain variations create additional complexity.
