This is a cover letter for the first part of a larger series preparing to delete the legacy `merge-recursive` backend in favor of `merge-ort`. The 3-patch subset introduces small new features needed for the eventual transition.

Elijah Newren is working toward removing `merge-recursive.[ch]` entirely, with 19 total patches split into five series. This initial series adds three targeted capabilities to `merge-ort` that will help convert existing callers: 

1. A new `merge_ort_generic()` function that provides a simpler interface for basic merge operations, making it easier to replace `merge-recursive` calls.
2. The ability to disable rename detection in `merge-ort`, matching functionality that exists in `merge-recursive`.
3. Support for setting merge verbosity to 0 (completely silent), another feature parity item with the old backend.

The changes are well-contained, touching only merge-ort files and documentation. The third patch introducing `merge_ort_generic()` might logically belong with its first user (a planned `git-am.sh` conversion), but the author offers to expand this series if reviewers prefer that approach.

This appears to be a thoughtful, incremental step in the long-running effort to sunset `merge-recursive`. The patches look focused and purposeful, each enabling specific functionality needed for the larger transition. Reviewers familiar with the merge backend work will want to check whether these interface additions make sense as standalone changes before the dependent conversions arrive.
