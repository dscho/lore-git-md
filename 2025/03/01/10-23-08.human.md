Performance optimization discussion for bundle-uri reference handling. Scott Chacon responds to Derrick Stolee's concerns about tag handling in the bundle-uri performance improvement patch series.

The key sticking point is how to handle tag references when copying all bundle references into `refs/bundle/` space. Stolee had suggested peeling tags to commits and creating fake branches, but Chacon questions the practicality of this approach, noting it would require special bundle creation scripts or modifications to `git bundle`.

Chacon proposes two alternative solutions:
1. Simply accept tags in `refs/bundle/tags/` (which his testing shows doesn't cause problems)
2. Add a `--bundle-for-uri` option to `git bundle` to handle the reference sanitization

He also suggests a middle ground where tags could be temporarily available in `refs/bundle/tags/` during fetch negotiation but deleted afterward. The email concludes with Chacon stating he'll send an updated patch series with modified tests checking for `refs/bundle/heads/*` instead of `refs/bundle/*` and basic tag unpacking verification.

The discussion highlights the tension between maintaining the significant performance gains (reducing object downloads from 32% to 1% in test cases) and ensuring robust handling of edge cases like tag references. Chacon appears to favor simpler, more direct solutions that don't require complex bundle creation workflows.
