This is a feature patch adding a new `--must-filter` option to `git clone` and `git fetch`. The option makes these commands fail with an error (rather than just a warning) when the server doesn't support the requested filter, which is useful for scripts and automation that need to enforce partial clone/fetch behavior.

The patch appears well-structured, touching all the necessary components to add the new option: command-line parsing in clone.c and fetch.c, transport plumbing, and fetch-pack handling. It includes tests demonstrating both the clone and fetch scenarios, though the tests are currently marked as `test_expect_failure`, suggesting they need server-side support that isn't yet implemented.

The motivation comes from a prior discussion (referenced via a public-inbox link) where the warning-only behavior was noted as potentially problematic for automated use cases. The implementation looks straightforward and maintains backward compatibility by keeping the warning behavior as default.
