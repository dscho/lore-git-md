This thread introduces a new `--must-filter` option for `git fetch` and `git clone` that enforces server-side filtering support. Currently, Git merely warns when a server doesn't support filtering and continues the operation without filtering; this change makes that case fatal when `--must-filter` is specified.

The patch adds the option through several coordinated changes: new command-line flags in both commands, corresponding fields in the transport and fetch-pack argument structs, and modified capability negotiation logic that now errors out rather than warning. The implementation appears cleanly scoped, with new test cases in t0410-partial-clone.sh (though currently marked as expect_failure, indicating some test setup may still need work).

The change seems motivated by partial clone scenarios where filtering isn't just an optimization but a hard requirement - cases where silently falling back to an unfiltered clone would defeat the purpose. The patch references prior discussion with Peff (Jeff King), suggesting this addresses a real-world pain point in ensuring filtered clones actually remain filtered. While the core functionality looks complete, the failing tests suggest there may be some final polishing needed before merging.
