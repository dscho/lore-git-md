This is a bugfix addressing a memory leak in the reftable reader implementation, following up on an earlier report about test infrastructure leaks. The thread has evolved from H Z's initial report about a test-only leak to René Scharfe identifying a more substantial leak in the production reftable_reader_new() function.

The key technical details: when reftable_reader_new() fails during block_source_read_block() or parse_footer(), it leaks the allocated 'name' field of struct reftable_reader. The patch adds cleanup by calling reftable_free(r->name) in the error path. The discussion also notes an inconsistency - reftable/reftable-reader.h documents a non-existent reftable_reader_destroy() function, though this isn't addressed in the current patch.

The original test case mentioned in the thread (test_corrupt_table_empty) no longer exhibits the leak due to previous refactoring, but the production code issue remains. The proposed fix is straightforward - adding a single cleanup line in the error path. The patch maintains the current allocation timing rather than restructuring to allocate 'name' later, which the author notes might complicate matters.
