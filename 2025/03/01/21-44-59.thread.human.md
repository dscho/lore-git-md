This thread introduces a new feature for `git blame` that allows customizing its output format, similar to what `git log` offers. The series, from first-time contributor Aleks Todorov, consists of seven patches now at version 1. The first six patches implemented the core functionality: adding `--format` and `blame.format` configuration options, introducing blame-specific format specifiers (`%F` for filename and `%L` for line number), refactoring the documentation structure, and adding comprehensive tests.

The final patch (7/7) just arrived, completing the feature with user-facing documentation. It adds clear explanations of the new formatting capabilities in three places: the config documentation for `blame.format`, the `git-blame` man page section for the `--format` option, and the shared placeholders documentation (with blame-specific additions properly marked). The documentation follows Git's patterns, with good cross-referencing between related sections.

The series appears technically sound, with a logical progression from implementation to testing to documentation. The documentation work was thoughtfully split - first refactoring the shared infrastructure (patch 6) before adding the blame-specific content (patch 7). There haven't been substantive reviews yet, but the approach aligns with Git's existing patterns for format specifiers and documentation organization. This looks like a well-structured contribution that could be ready for merging once it receives review feedback.
