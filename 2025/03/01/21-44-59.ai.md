This is a feature patch series introducing format specifiers for `git blame` output, based on the existing `git log` formatting system. The series consists of 7 patches that together implement a `--format` option for `git blame`, allowing users to customize the output display.

The key technical components include:
- New `--format`/`-F` command-line option and `blame.format` config option (patches 1-2)
- Two new blame-specific format specifiers `%F` (filename) and `%L` (line number) (patch 3)
- Integration with `pretty.c` for format string processing (patch 4)
- Comprehensive tests (patch 5) and documentation restructuring (patches 6-7)

The motivation comes from the author's debugging workflow, where seeing commit subjects alongside blame output would be helpful. The implementation reuses existing pretty-print infrastructure but notes one limitation: inability to auto-detect minimum column widths for placeholders, which prevents fully replicating the default blame output format.

The series appears well-structured with clear commit separation, test coverage, and documentation updates. The author acknowledges this is their first submission and invites feedback. The changes touch multiple areas: `builtin/blame.c` for the core functionality, `pretty.[ch]` for format specifiers, documentation restructuring, and new test files. The documentation changes are particularly extensive, splitting placeholder documentation into a new file while maintaining backward compatibility.
