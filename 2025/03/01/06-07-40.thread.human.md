This thread documents the discovery and resolution of memory leaks in Git's reftable infrastructure. It began with H Z identifying a test-only leak in the test suite's `test_corrupt_table_empty()` function, which was later found to have already been fixed through prior refactoring. René Scharfe then discovered a more significant production code leak in `reftable_reader_new()`, where allocated memory for the 'name' field could be lost if reader initialization failed partway through.

The proposed fix takes a minimal approach, adding cleanup via `reftable_free(r->name)` in error paths while maintaining the existing allocation timing. The patch appears well-contained and addresses a clear issue in core reftable code. While the immediate memory management problems are being resolved, the discussion has also surfaced a documentation inconsistency regarding `reftable_reader_destroy()` in the header files, which remains as potential future work. The thread demonstrates how test infrastructure hygiene discussions can lead to discoveries of more substantial issues in production code.
