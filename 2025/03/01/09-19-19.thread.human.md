This thread explores ZheNing Hu's proposal to bring GitHub/GitLab-style inline code commenting to Git while preserving its distributed nature. The core idea is to enable line-specific annotations that travel with the repository, filling a gap between centralized platforms' features and Git's current tools like `git blame` and `git notes`.

The discussion has progressed from initial concept to technical feasibility, with key questions emerging about storage format (new metadata needed), line tracking through code changes, and distributed synchronization. Randall Becker's response adds important considerations about implementation challenges, particularly around cross-repository comment transfer (similar to notes exchange) and compatibility with non-core Git implementations like JGit. He also raises the specter of potential conflicts with proprietary features from major hosting platforms.

The proposal continues to identify clear benefits - better documentation capabilities, improved IDE integration, and distributed workflow compatibility - but the technical path forward remains uncertain. Open questions center on storage mechanics, merge/rebase handling, conflict resolution, and where to draw the line between core functionality and extension. The thread reflects healthy skepticism about the non-trivial integration challenges while maintaining interest in the concept's potential value for local development workflows.
