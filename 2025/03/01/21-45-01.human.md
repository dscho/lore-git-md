This is the second patch in a series adding customizable format specifiers to `git blame`, following the pattern of `git log` formatting. The patch introduces a `blame.format` config option that lets users specify a default format string in their Git config, avoiding the need to repeatedly pass `-F`/`--format` on the command line.

The implementation is straightforward, adding just 5 lines to `builtin/blame.c` to handle the new config option using Git's standard `git_config_string()` helper. This matches the pattern seen in other Git commands with format options and cleanly integrates with the existing config parsing infrastructure.

As part of a larger effort to make `git blame` output more flexible, this patch provides the configuration plumbing that will be used by subsequent patches implementing actual format specifiers. The change is well-contained and appears technically sound, though the real test will come when the format expansion is implemented in later patches. The series continues to show promise for improving debugging workflows by allowing custom blame output formats.
