Feature patch adding blame-specific format specifiers to Git's pretty-print system. This is patch 3/7 in Aleks Todorov's series to bring customizable formatting to `git blame` output, modeled after `git log`'s format options.

The patch introduces two new format placeholders that work only in blame context: `%F` for filename and `%L` for line number. The implementation checks a new `is_blame` flag in the pretty-print context before applying these specifiers, ensuring they don't interfere with other formatting contexts. The line number is formatted as a string while the filename is passed through directly from the blame context.

This builds on the infrastructure added in the first two patches (option parsing and config support) by actually implementing some of the promised format specifiers. The changes are focused in `pretty.c` and `pretty.h`, with the new specifiers following the same pattern as existing format placeholders. The implementation appears clean and maintains the separation between blame-specific and general formatting.

The patch keeps the series moving forward with concrete functionality while leaving documentation and more complex formatting cases for later patches. It demonstrates how the blame context will integrate with the existing pretty-print system, which reviewers will likely scrutinize as this touches core formatting code.
