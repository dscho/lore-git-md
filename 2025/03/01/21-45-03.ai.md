Feature patch implementing format string processing for `git blame` output, part 4/7 in the series introducing format specifiers to `git blame`. This patch handles the actual expansion of user-provided format strings when emitting blame output.

The core change refactors `emit_other()` in `builtin/blame.c` to use the new format string processing path when a format is specified (either through `--format` or `blame.format` config). The implementation leverages Git's existing pretty-print infrastructure through `repo_format_commit_message()`, passing a new `pretty_print_context` configured for blame output (including the filename and line number via context fields).

Key technical details:
- Maintains backward compatibility by keeping the original output path when no format is specified
- Uses the same`format` variable populated by earlier patches (1/7 and 2/7) for both CLI and config values
- Demonstrates format string usage with an example that reproduces default blame output
- Handles all existing blame output flags (UNINTERESTING, unblamable, ignored markers) in the legacy path
- Preserves all existing functionality while adding the format expansion capability

The patch shows clean integration with the series' earlier work, completing the core functionality needed for custom blame output formatting. Subsequent patches will add tests and documentation. The implementation appears technically sound, following established pattern of format handling seen in other Git commands while adding blame-specific context through the `is_blame` flag and related fields.
