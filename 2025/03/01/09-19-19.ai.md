This is a feature proposal for adding inline code commenting capabilities to Git, aiming to bring GitHub/GitLab-style annotations into the core tool while maintaining Git's distributed nature. The proposal comes from ZheNing Hu, who identifies a gap in Git's current annotation tools (`git blame` and `git notes`) which don't support line-specific comments that can travel with the repository.

The key motivation is enabling decentralized code annotation that works across different environments without relying on centralized platforms. The proposed solution would allow attaching comments to specific lines or ranges (conceptually similar to `addcomment(file1:[L3~L10], "comment")`), with features to maintain comment positioning through code changes and share annotations between collaborators.

The email thoughtfully outlines both benefits (better documentation, IDE integration, resilience to code changes) and challenges (synchronization, conflict resolution, IDE tooling). The proposal positions this as philosophically aligned with Git's distributed nature while addressing real workflow pain points around code review and knowledge sharing in local/offline scenarios.

For future reference in this thread, the core technical aspects to track would be: the proposed comment storage mechanism (likely needing new metadata handling in Git), line tracking through code changes (similar to blame tracking), and IDE integration points. The discussion may also touch on how this compares to existing solutions like `git notes` and whether the complexity justifies adding to core Git versus building as an extension.
