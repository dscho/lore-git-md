Performance optimization for bundle-uri fetch negotiation, version 2. This is Scott Chacon's follow-up to the ongoing discussion about improving reference handling during fetches from bundle URIs. The patch series demonstrated significant performance benefits but raised concerns about reference naming and tag handling.

The v2 series addresses some of the feedback by updating tests to properly check the new reference locations (`refs/bundle/heads/` rather than direct `refs/bundle/` access) and adding a new test case specifically for tag handling. The core change remains expanding the refspec from just `refs/heads/` to all `refs/` when copying references from bundles, which showed dramatic reductions in downloaded objects (32% to 1% in GitLab's OSS repo).

The series consists of three patches: the main refspec change, test updates for the new reference paths, and a new test for tag handling. This responds to concerns about backward compatibility and reference management safety by ensuring tests verify the new behavior. However, the thread shows deeper questions remain about tag peeling and reference interaction between multiple bundles - those architectural questions aren't fully resolved here, but this version makes progress on the test coverage side.
