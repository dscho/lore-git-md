This is a feature proposal for adding inline code commenting capabilities to Git's core functionality. ZheNing Hu suggests building native support for attaching comments to specific lines or ranges of code, similar to what GitHub/GitLab offer in their web interfaces, but working locally and distributedly like Git's other features.

The proposal identifies a clear gap: while we have tools like `git blame` for historical context and `git notes` for commit-level annotations, there's no way to attach persistent comments directly to code lines that can travel with the repository. The suggested feature would enable developers to maintain contextual notes that survive code changes through intelligent line tracking, while remaining independent of any centralized platform.

Key benefits highlighted include better code understanding through local annotations, decentralized collaboration, and resilience to code changes. The author acknowledges technical challenges around synchronization (keeping comments attached to the right lines as code changes), conflict resolution, and IDE integration.

This appears to be a well-considered proposal that aligns with Git's distributed nature while addressing a real workflow pain point. The author seems to engage in further discussion about implementation details, suggesting this could develop into a serious contribution if the community shows interest. The lack of concrete implementation details at this stage is appropriate for an initial RFC.
