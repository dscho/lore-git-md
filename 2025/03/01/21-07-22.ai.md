This is a feature patch introducing a new `--must-filter` option for `git fetch` and `git clone`. The option makes Git error out when the server doesn't support filtering, rather than just warning and continuing without filtering as it currently does.

The patch adds the new boolean flag across several components:
- New `--must-filter` option in both `builtin/clone.c` and `builtin/fetch.c`
- `must_filter` field added to `struct fetch_pack_args` and `struct git_transport_options`
- Modified behavior in `fetch-pack.c` to die() rather than warn when filtering is unsupported and `must_filter` is set
- New test cases in t0410-partial-clone.sh (currently marked as expect_failure)

The change appears motivated by a prior discussion referenced in the commit message (a message from Peff). The implementation looks straightforward, plumbing the new option through the transport layer to the point where server capability negotiation happens. The tests suggest this is meant for partial clone scenarios where filtering is essential to the operation.

Key technical points for future reference:
- New config/option: `--must-filter`
- Affected commands: `clone`, `fetch`
- Modified structs: `fetch_pack_args`, `git_transport_options`
- Behavior change: switches warning to error when server lacks filter support
- Test files: t0410-partial-clone.sh gets new must-filter scenarios

The patch seems well-contained and addresses a clear use case where users want to ensure filtering actually takes effect rather than silently falling back. The expect_failure tests suggest there may be some unresolved test setup issues to address before finalizing.
