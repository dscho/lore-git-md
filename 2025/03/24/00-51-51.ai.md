Feature addition to the maintenance subsystem, specifically the loose-objects task. This is the second patch in a 2-part series that follows up on progress reporting fixes with a new configuration option.

The patch introduces `maintenance.loose-objects.batchSize` to control how many loose objects are packed at once during maintenance, replacing the hardcoded limit of 50,000 objects. The option accepts:
- Positive integers to set a custom limit (with an off-by-one fix for the comparison)
- 0 to indicate no limit (implemented via INT_MAX)
- Negative values are effectively prohibited to avoid underflow

The implementation includes thorough documentation updates in both config and command manuals, plus a test case that verifies the batch size enforcement works as expected. The test creates 34 commits (102 objects), then verifies the packing happens in expected chunks when batchSize=50.

This builds on the first patch's progress reporting fixes, with the test using --no-quiet to verify progress output. The change appears well-considered, handling edge cases (INT_MAX, negative values) and maintaining backward compatibility while adding flexibility. The test coverage is comprehensive, exercising both the default and custom batch sizes.
