This is a review response on patch 2/8 in Martin Ågren's pretty-format refactoring series, which simplifies color specifier parsing in pretty.c.

Jeff King (Peff) agrees with Martin's changes to reduce code duplication in the handling of "%C(auto,...)" and "%C(always,...)" color specifiers. The patch consolidates the common "auto" case as the default while keeping the special "always" case as an explicit check. Peff notes that while the duplicated code wasn't extremely long, the simplification makes the logic clearer by removing the need to verify identical code blocks. He also approves of Martin's decision not to further golf the code into a single conditional, as that would make future extensions harder and eliminate space for explanatory comments.

The review confirms this is a code organization improvement with no behavior change, aligning with the series' goal of cleaning up pretty.c's parsing logic. Peff's approval adds to the consensus that this patch is ready for inclusion, following Patrick Steinhardt's earlier review. The exchange demonstrates careful consideration of tradeoffs between conciseness and maintainability in the refactoring.
