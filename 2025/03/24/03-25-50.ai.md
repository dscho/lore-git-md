Final security review for git-shell command override feature.

Jeff King provides a detailed technical review of Ayman Bagabas's v3 patch to allow overriding git-shell built-in commands. While acknowledging the usefulness of the feature for administrators needing to intercept shell commands, Peff identifies several implementation concerns that need addressing before the patch can be merged.

Key technical issues raised:
1. The moved `cd_to_homedir()` call changes execution context unexpectedly
2. Memory leak of `full_cmd` if `execv()` fails
3. Inconsistent argument handling between built-in and user-defined commands
4. Missing option-injection protections from `setup_path()` and other security checks
5. Poor documentation of argument passing semantics for override scripts

Peff suggests two alternative approaches that would better maintain consistency with existing behavior:
- Letting the override fall through to `do_generic_cmd()` processing
- Creating a proper hook interface instead of direct command replacement

The review focuses on security implications and behavioral consistency rather than outright rejection, suggesting the core concept remains valid but needs refinement. This represents the final round of technical feedback before potential maintainer approval, with all major architectural concerns from earlier in the thread having been addressed in v3.
