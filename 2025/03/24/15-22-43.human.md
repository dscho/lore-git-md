Feature patch adding `--path-walk` support to `git repack`, part of the path-based delta compression series.

This patch extends the `git repack` command to support the new `--path-walk` option, which passes through to `git pack-objects` for path-based delta compression. The change includes documentation updates, command-line argument handling, and integration with the performance test suite.

Performance data shows mixed results: in collision-heavy repositories like microsoft/fluentui, path-walk provides significant size reductions (142.5M vs 161.7M for name-hash-v2) though with slower execution (81.29s vs 21.51s). For other repositories (Git, Linux kernel, node.js), the size improvements are more modest while runtime costs remain substantial. The patch notes this is partly because the current implementation is single-threaded, with threading optimizations planned for future changes.

The implementation is straightforward, adding the option to both the command-line interface and the internal `pack_objects_args` struct. The performance script is updated to test path-walk alongside the existing name-hash versions, showing direct comparisons between the approaches. The documentation clearly explains the option's purpose and limitations (incompatibility with delta-islands and filter options).

This is patch 7/13 in a series introducing path-based delta compression, building on earlier patches that implemented the core `pack-objects` functionality. The changes here focus specifically on repack integration while maintaining consistency with the series' overall goals.
