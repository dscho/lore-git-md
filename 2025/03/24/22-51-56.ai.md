Bugfix for vimdiff mergetool's buffer handling discrepancy. This email from Fernando Ramos confirms and builds on D. Ben Knoble's earlier analysis of the `@REMOTE` buffer propagation issue in `git mergetool`'s vimdiff backend.

The proposed fix is straightforward - adding an explicit check for `@REMOTE` in the buffer selection logic, mirroring the existing handling of `@LOCAL` and `@BASE`. The current implementation in `mergetools/vimdiff` (lines 298-310) only checks those two cases before defaulting to `MERGED`, which explains why `@REMOTE` changes weren't being saved despite documentation suggesting they should be.

Key technical details carried forward from the thread:
- The bug affects buffer handling in the vimdiff mergetool backend
- Specific variables involved: `LAYOUT` (configuration) and `FINAL_TARGET` (output selection)
- Original implementation dates back to 2022 (commit 0041797449)
- Clear reproduction case exists showing `@LOCAL`/`@MERGED` work while `@BASE`/`@REMOTE` don't

Fernando offers to either test and submit the patch himself or let D. Ben Knoble handle it, indicating this is likely to move forward soon. The fix appears uncontroversial as it aligns the implementation with documented behavior rather than changing either. No discussion yet about potential impacts on existing workflows that might have adapted to the current behavior.
