Bugfix for vimdiff mergetool's buffer handling. Fernando Ramos confirms D. Ben Knoble's analysis of the `@REMOTE` buffer propagation issue in `git mergetool`'s vimdiff backend, agreeing it's a straightforward bug in the script's logic. The current implementation checks for `@LOCAL` and `@BASE` buffers but omits `@REMOTE`, defaulting incorrectly to `@MERGED`.

Ramos proposes a simple fix - adding an `elif` clause to handle `@REMOTE` cases, matching the documented behavior where changes to `@`-prefixed buffers should propagate to the final merge. He offers to submit the patch himself if Knoble doesn't get to it first, showing this is likely to be resolved soon.

This follows up on Knoble's earlier technical analysis that pinpointed the exact location of the bug (lines 298-310 in `mergetools/vimdiff`). The fix appears uncontroversial and aligns with the tool's intended behavior, though it would be good to see test coverage added given the discrepancy between docs and implementation went unnoticed for years.
