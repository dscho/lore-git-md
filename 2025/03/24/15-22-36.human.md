Performance optimization feature introducing path-based delta compression in pack-objects and repack.

This is version 2 of a 13-part series introducing a new `--path-walk` option to `git pack-objects` and `git repack` that improves delta compression by grouping objects by their path rather than by hash. The approach is particularly beneficial for repositories with many hash collisions (like JavaScript projects) and large Scalar-managed repositories, though it shows improvements even in the Linux kernel repo.

Key changes in v2 include:
- Restored a dropped comment about delta reuse
- Added documentation about interaction with `--use-bitmap-index` (which gets silently ignored when path-walk is enabled)
- Reduced global variable usage by making better use of parameters

Performance data shows significant improvements in some cases - for example in the microsoft/fluentui repo, path-walk achieves a 142.5MB pack size (vs 161.7MB with name-hash-v2) while taking slightly longer (28.16s vs 21.51s). The Linux kernel sees more modest gains (2.2GB vs 2.5GB) with minimal time impact.

The implementation uses a two-phase approach: first compressing objects within path groups, then doing a cross-path pass using name-hash to find additional delta opportunities. The series also adds threading support for the path-based phase and introduces an `edge_aggressive` mode for shallow clones.

While the feature shows promise, there are open questions about whether simpler config tuning (like increasing pack.window) could achieve similar benefits with less complexity. The implementation also currently can't work with bitmap indexes or delta islands, though this is now clearly documented.

This looks like a well-considered optimization that could provide real benefits for certain repository types, though the tradeoffs between compression gains and runtime costs may need more evaluation across different real-world use cases.
