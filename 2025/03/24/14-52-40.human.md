Bug report about mergetool.vimdiff.layout behavior not matching documentation.

This is a clear bug report from a first-time contributor about inconsistent behavior in Git's vimdiff merge tool configuration. The user found that while the documentation for `mergetool.vimdiff.layout` states that changes made to buffers marked with `@` should be reflected in the final merged file, this only works correctly for `@LOCAL` and `@MERGED` buffers, not for `@BASE` or `@REMOTE`.

The reporter provides a detailed reproduction case showing they configured `@REMOTE` as the target buffer, made changes there, but those changes weren't saved to the final file. They've helpfully included a video demonstration of the issue and full system information showing they're using Git 2.48.1 on macOS (ARM64).

The report is well-structured with clear separation of expected vs actual behavior, and the documentation quote shows this isn't just a misunderstanding but likely an implementation bug. The issue appears specific to the vimdiff backend's handling of certain buffer types in the merge workflow. This seems like a straightforward bug that would affect anyone trying to use these less-common buffer configurations in vimdiff merges.
