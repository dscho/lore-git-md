This is a follow-up discussion about patch 2/5 in the Rust crate packaging series, focusing on build system compatibility issues.

Junio Hamano notes that the symlink solution introduced in patch 2/5 (which creates a `git-src` symlink pointing to `../..`) is causing test failures on Windows. The symlink was added to allow the Rust crate build process to access the Git repository root while maintaining isolation, but Windows' handling of symbolic links appears to be problematic.

The email questions whether this symlink approach is truly the only viable solution, suggesting some skepticism about the implementation. This comes after Eric Sunshine had previously pointed out minor documentation issues (a typo and missing newline) in the same patch.

The thread context shows this is part of a completed 5-patch series that otherwise successfully addressed Rust crate packaging challenges, including build isolation and crates.io publication requirements. While the series is otherwise production-ready, this Windows-specific issue may require revisiting the symlink approach or finding a Windows-compatible alternative.
