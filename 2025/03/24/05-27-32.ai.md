Maintainer feedback on git-shell command override proposal

Junio Hamano weighs in on Jeff King's suggestion of a more restricted hook interface versus the current flexible command override approach. While acknowledging the usual Git preference for constrained interfaces, Hamano notes that git-shell's limited scope makes wholesale command replacement less risky than it would be in other contexts.

The key observation is that git-shell's inherent limitations (compared to full Git) reduce the danger of allowing command overrides, though Hamano questions whether administrators would find this facility useful enough to prefer over established alternatives like gitolite when needing advanced functionality. This suggests the proposal may be solving a narrow use case between basic git-shell and more full-featured solutions.

The email doesn't address the specific technical issues raised in Jeff King's review, instead focusing on the higher-level design tradeoffs. It represents maintainer perspective on the architectural direction rather than implementation details, indicating the proposal is conceptually acceptable pending resolution of the outstanding technical concerns around path handling, memory management, and argument consistency.
