This is patch 2/13 in a series introducing path-based delta compression to pack-objects. The patch adds the core `--path-walk` option that reorganizes object packing by path rather than name-hash, aiming to improve delta compression especially for repositories with many hash collisions (like JavaScript projects).

The implementation:
- Adds new `add_objects_by_path()` and `get_object_list_path_walk()` functions that use the path-walk API to group objects by path before delta compression
- Maintains UNINTERESTING objects as potential delta bases
- Falls back to name-hash for additional delta opportunities after path-based compression
- Documents incompatibilities with features like bitmaps, delta islands, and shallow packs
- Includes basic tests verifying path-walk works for regular and thin packs

Key technical details:
- Uses new `path-walk.h` API to traverse objects by path
- Performs delta calculations during walk (though not yet threaded)
- Skips delta calculations when window=0 or no objects match path
- Disables incompatible features when path-walk is active
- Adds warnings when path-walk conflicts with other options

The patch builds on the `should_attempt_deltas()` refactoring from patch 1 and will be followed by threading optimizations in later patches. Performance tradeoffs are acknowledged - path-walk can be slower during enumeration but may yield better compression, especially for collision-prone repositories.
