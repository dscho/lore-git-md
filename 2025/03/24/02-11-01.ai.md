Feature addition to the userdiff system, specifically adding Git config syntax highlighting support.

This patch introduces a new builtin userdiff driver for gitconfig files, enabling syntax-aware highlighting in diffs. The driver matches both sections (`[section]`) and subsections (`[section "subsection"]`) as function headers, using a regex that allows alphanumeric characters plus `-` and `.` in section names, while being more permissive with subsection content. The word regex matches any non-whitespace sequence rather than strictly validating variable names/values, trading strict syntax checking for practical diff utility.

The implementation adds the driver definition in `userdiff.c` and includes four new test files covering section/subsection cases with and without indentation. The tests demonstrate the driver's handling of comments (both `#` and `;` styles), key-value pairs, and standalone values. The patch appears well-constructed with clear test coverage and has received feedback from two contributors (Patrick Steinhardt and D. Ben Knoble) in its development. This is version 2 of the patch, which improves the message by referencing documentation rather than quoting it directly and fixes newline issues in test files.

Key technical details for future reference:
- Driver name: `gitconfig`
- Funcname regex: `^\\[[a-zA-Z0-9]+\\]|\\[[a-zA-Z0-9]+[ \t]+\".+\"\\]$`
- Word regex: `[^ \t]+`
- Test files cover indented/non-indented sections/subsections
