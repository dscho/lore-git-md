Security-focused review of git-shell command override implementation

Jeff King provides a detailed technical review of Ayman Bagabas's v3 patch to allow overriding git-shell built-in commands. While acknowledging the usefulness of the feature, he identifies several implementation concerns that need addressing before the patch can be considered ready.

The review focuses on three main issues:
1. An unintended side effect where `cd_to_homedir()` is now called earlier, potentially changing the working directory for built-in commands
2. A memory leak of `full_cmd` if the `execv` call fails
3. More significantly, problems with argument handling where quoted arguments aren't properly processed, missing security protections against option injection, and inconsistencies with how user-defined commands are handled

King suggests two alternative approaches that would better integrate with git-shell's existing command processing: either letting the override run as a regular user-defined command after skipping the built-in, or hooking into `do_generic_cmd()` to properly handle argument processing and security checks. The review maintains a constructive tone while clearly identifying the technical shortcomings that need resolution.
