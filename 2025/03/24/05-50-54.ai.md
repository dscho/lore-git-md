Refactoring of commit mark clearing functions in commit.c. This is a follow-up to René Scharfe's initial patch that restructured the relationship between `clear_commit_marks_many()` and `clear_commit_marks()`. Junio C Hamano provides maintainer feedback, speculating that the original code organization might have anticipated future optimizations for batch processing that never materialized. He endorses the simplification, noting the new version makes the control flow clearer by having `clear_commit_marks_many()` simply iterate over commits while `clear_commit_marks()` handles the actual mark-clearing logic for individual commits. The change remains a pure refactoring with no behavioral impact, touching core commit graph functionality but focused solely on code organization improvements. The maintainer's approval suggests this change is likely to be accepted, though no other reviewers have weighed in yet. The patch continues the thread's focus on maintainability improvements to commit mark handling without introducing new functionality or performance changes.
