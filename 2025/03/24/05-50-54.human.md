Refactoring of commit mark clearing functions. This is a follow-up to René Scharfe's patch that restructured the relationship between `clear_commit_marks_many()` and `clear_commit_marks()` in commit.c. Junio C Hamano provides maintainer feedback, speculating that the original code organization might have anticipated future optimizations for batch processing that never materialized. He agrees the new version makes the control flow clearer by having `clear_commit_marks_many()` simply iterate over commits while `clear_commit_marks()` handles the actual work for a single commit. The change is purely internal - no behavior or performance impact - and improves code readability by making each function's responsibility more obvious. This appears to be a straightforward improvement that's likely to be accepted.
