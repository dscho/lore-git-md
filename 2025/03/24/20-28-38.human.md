This is a discussion about the security implications of the git-shell command override feature.

Jeff King (peff) responds to Junio Hamano's approval of the git-shell command override proposal with some broader security concerns. While acknowledging the technical merits of the implementation, peff expresses reservations about git-shell's security track record, suggesting administrators might be better served by more robust alternatives like gitolite or git-over-http for untrusted environments.

The email highlights an important perspective that wasn't fully addressed in the technical discussion - that git-shell's historical security vulnerabilities and limited usage might make it a poor foundation for building custom features, even with the new override capability. Peff suggests that when administrators need more than basic git-shell functionality, they should consider more mature solutions rather than extending git-shell itself.

This isn't a rejection of the technical approach (which has already been approved), but rather a cautionary note about the real-world security implications of encouraging git-shell customization. The comment serves as useful context for administrators evaluating whether to use this feature when it lands.
