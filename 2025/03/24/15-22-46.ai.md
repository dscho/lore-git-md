This is a refactoring patch in the ongoing path-walk delta compression series. It reorganizes how path-based delta selection works in `pack-objects` to improve progress reporting and prepare for future threading support.

The key change separates the path-walk object grouping from delta computation. Previously, deltas were computed immediately during the path walk, which made progress reporting confusing (long enumeration followed by quick compression). Now, the patch stores path-based object groups in a new `packing_region` structure for later delta processing, allowing proper progress reporting of the "Compressing objects by path" phase.

Technical details include:
- New `find_deltas_by_region()` and `find_deltas_for_region()` functions that process the stored regions
- `packing_region` struct added to track object groups by start index and count
- Progress reporting now shows distinct compression phase
- Removes temporary test workaround since error message ordering is now stable
- Adds test verification of the new progress output
- The change maintains all existing functionality while improving the internal structure
- Threading integration is noted as future work
- Performance impact should be neutral since same work is done, just in different order
- Part of larger effort to optimize delta compression for path-based repositories

The patch fits into the series by:
- Building on previous path-walk infrastructure
- Preparing for future threading optimizations
- Improving user experience with better progress reporting
- Maintaining test coverage while removing temporary workarounds

Key files modified:
- `builtin/pack-objects.c`: Core refactoring of path-walk delta logic
- `pack-objects.h`: Adds new `packing_region` struct
- Test updates verify progress output and remove temporary workaround

The refactoring appears well-contained and maintains the series' goals while improving code structure. The progress reporting improvement is a user-visible benefit, and the structural changes enable future optimizations.
