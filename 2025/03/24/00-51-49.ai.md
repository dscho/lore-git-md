This is a feature patch series introducing configuration options for the loose-objects maintenance task, along with a related progress reporting fix.

The series addresses two distinct but related issues in `git maintenance`'s loose-objects handling. First, it fixes a bug where progress indicators weren't properly propagated to child processes when running non-interactively (patch 1). This is a straightforward fix ensuring the `--[no-]quiet` flag is correctly passed down.

The main feature (patch 2) adds a new `maintenance.loose-objects.batchSize` configuration option, allowing users to override the hard-coded limit for how many loose objects are processed in a single maintenance run. The commit message explains this is useful for users who want to clean all loose objects at once without resorting to `git repack`. The implementation touches documentation (both config and command manuals), the gc.c implementation, and adds new tests.

The changes are well-scoped and follow Git's established patterns for adding new options. The test coverage appears thorough, verifying both the progress reporting fix and the new config option's behavior. This seems like a straightforward quality-of-life improvement for users who need more control over maintenance operations. The series doesn't appear controversial and builds on existing maintenance infrastructure.
