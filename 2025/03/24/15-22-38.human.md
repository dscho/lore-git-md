Feature patch introducing path-based delta compression in pack-objects.

This is patch 2/13 in a series introducing the new `--path-walk` option for `git pack-objects`, which reorganizes object packing to group files by their repository paths rather than using Git's default name-hash algorithm. The key motivation is improving delta compression, particularly for repositories with many hash collisions (like JavaScript projects) and large Scalar-managed repositories.

The patch adds the core `--path-walk` option and its basic implementation, though it currently has some limitations: it's incompatible with object filters, delta islands, shallow packs, and bitmap indexes. The implementation performs delta calculations during the object walk (rather than after), which makes the "Enumerating objects" phase longer and doesn't yet take advantage of threading. The author notes these are temporary tradeoffs that will be addressed in future patches.

The patch includes documentation update explaining the new option and its constraints, plus basic tests verifying the functionality works for both regular and thin packs. Performance testing will come in later patches, but early indications suggest this approach can significantly improve compression for certain repository types, though with some runtime overhead.

This is a well-structured patch that clearly documents both the current capabilities and known limitations, making it easier to evaluate the tradeoffs. The series appears to be building toward a robust solution for path-based delta optimization.
