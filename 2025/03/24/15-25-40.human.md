Patrick Steinhardt responds to Justin Tobler's suggestion about modifying transaction cleanup behavior. The conversation stems from a recent fix where failed atomic fetch operations were causing crashes due to improper transaction handling. While agreeing with Justin's analysis, Patrick raises concerns that requiring explicit abort calls after failed commits might still leave the API feeling awkward, as callers would need to both abort and free transactions.

Patrick suggests an alternative approach - making transaction abortion idempotent so that calling abort on an already-aborted transaction would be harmless. However, he expresses uncertainty about whether this would meaningfully improve the situation compared to Justin's proposal. The email captures the ongoing design debate about how to make the reference transaction API more consistent in its cleanup behavior, with both approaches having tradeoffs that need consideration.
