This is a configuration patch in the ongoing path-walk delta compression series, adding support for enabling the path-walk algorithm via config rather than just command-line flags.

The patch introduces a new `pack.usePathWalk` config option that defaults the path-walk behavior for `git pack-objects` when used with `--revs`. The option is automatically enabled by both `feature.experimental` and `feature.manyFiles` configs, following the pattern of other experimental packing optimizations. The implementation checks repository settings in `pack-objects.c` to determine whether to enable path-walk by default.

Key technical details include:
- New config documentation in both `feature.adoc` and `pack.adoc`
- Repository settings infrastructure updates in `repo-settings.[ch]`
- Logic in `pack-objects.c` that respects the config while maintaining precedence rules (bitmaps/internal-rev-list still disable path-walk)
- The config is specifically designed for client-side use since path-walk disables bitmap walks which are important for server performance

The patch fits into the larger series by making the path-walk functionality more accessible through standard Git configuration rather than requiring explicit command-line flags. This is particularly useful for commands like `git push` and `git repack` that invoke pack-objects internally. The implementation is straightforward and maintains all the tradeoffs documented earlier in the series regarding bitmap incompatibility.
