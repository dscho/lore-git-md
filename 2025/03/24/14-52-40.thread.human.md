This thread documents a bug in Git's vimdiff mergetool backend where changes made to the `@REMOTE` buffer during conflict resolution weren't being saved to the final merged file, contrary to the documented behavior. The issue was initially reported by kawarimidoll with a clear reproduction case, then analyzed by D. Ben Knoble who pinpointed the problem in the buffer selection logic (lines 298-310 of `mergetools/vimdiff`).

Fernando Ramos has now confirmed the analysis and proposed a straightforward fix: adding explicit handling for `@REMOTE` to match the existing logic for `@LOCAL` and `@BASE`. The solution aligns the implementation with the documentation rather than changing either, making it uncontroversial. Fernando has offered to either submit the patch himself or let D. Ben Knoble handle it, suggesting this will likely be resolved soon. The bug affects Git versions 2.48.1 through 2.49, and while the original author and current maintainer were CC'd, they haven't yet weighed in. There's been no discussion yet about whether any workflows might have adapted to the current (incorrect) behavior.
