This thread reports a bug in `git mergetool`'s vimdiff backend where changes made to the `@REMOTE` buffer during conflict resolution aren't being saved to the final merged file, contrary to the documented behavior. The original reporter, kawarimidoll, provided clear reproduction steps and a video demonstration showing that while `@LOCAL` and `@MERGED` buffers work as expected, `@BASE` and `@REMOTE` changes are lost.

D. Ben Knoble has since identified the root cause in the vimdiff mergetool script (lines 298-310), where the code explicitly checks only for `@LOCAL` and `@BASE` before defaulting to `MERGED`. This explains the discrepancy with the documentation, which suggests all `@`-prefixed buffers should propagate changes. Knoble has CC'd both the original author of this code (from commit 0041797449 in 2022) and the current maintainer for further input.

The consensus so far is that this appears to be an implementation bug rather than a documentation issue, as the current behavior doesn't match what's documented. The next steps will likely involve either updating the code to handle all buffer types consistently or revising the documentation if the current limited behavior is intentional. The issue affects at least Git 2.48.1 and 2.49, and while initially reported on Darwin/ARM64, the problem is likely platform-independent given its nature.
