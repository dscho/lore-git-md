This thread reports a discrepancy in `git mergetool`'s vimdiff behavior. The documentation states that changes made to buffers marked with `@` (like `@REMOTE` and `@BASE`) should be reflected in the final merge output, with `@MERGED` as fallback. However, user kawarimidoll found that while `@LOCAL` and `@MERGED` work as documented, changes to `@BASE` and `@REMOTE` are not propagated to the result file. 

The report includes clear reproduction steps and a video demonstration showing the unexpected behavior. This affects users relying on vimdiff for merge conflict resolution, particularly when they expect to edit the remote changes directly. The issue appears to be either a documentation error or an implementation bug in the vimdiff backend. The reporter is new to contributing but has provided all necessary details including their Git version (2.48.1) and platform (Darwin/ARM64). No maintainers or regular contributors have responded yet to confirm whether this is a known issue or to propose a fix.
