Bugfix for progress reporting in maintenance tasks. This is the first patch in a two-part series that also introduces a configurable batch size for loose-object maintenance.

The patch fixes an issue where the `--no-quiet` flag wasn't being properly propagated to child processes during maintenance operations. Currently, child processes would check `isatty(2)` independently, which could suppress progress indicators even when explicitly requested via `--no-quiet`. The change ensures progress reporting works consistently across all maintenance subcommands (commit-graph writing, loose-object packing, and multi-pack-index operations) by explicitly passing `--progress` or `--no-progress` flags to child processes based on the parent's quiet setting.

The changes are straightforward and mechanical, touching only `builtin/gc.c` to add the proper flag passing in several maintenance-related functions. The commit message notes this change will be useful for testing in the subsequent patch that introduces the batch size configuration.

This appears to be a well-contained fix that follows established patterns in the codebase. The change is small (10 lines added) and focused, with clear motivation explained in the commit message. As the first in a series, it sets up infrastructure needed for the more user-visible batch size configuration coming next.
