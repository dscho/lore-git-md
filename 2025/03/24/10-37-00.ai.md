Bugfix follow-up discussion for `git blame` porcelain output markers.

This is a brief response from Toon Claes in the ongoing thread about displaying ignored/unblamable markers in `git blame` porcelain output. The discussion follows Patrick Steinhardt's proposal to use metadata lines rather than modifying SHA-1 prefixes, which was accepted as the correct approach.

Toon agrees with Patrick's solution but raises a subtle implementation question about when the new "unblamable" and "ignored" metadata should be emitted. He notes that in `--porcelain` mode (as opposed to `--line-porcelain`), commit details are typically only printed once per commit, but the ignored/unblamable status might vary per line even for the same commit. This suggests the metadata might need to be emitted more frequently than other commit details in this mode.

The response doesn't propose specific code but flags an important edge case in the implementation that needs consideration - whether the new metadata lines should follow the same deduplication rules as other porcelain output or be treated specially due to their per-line variability. This is a technical refinement to Patrick's already-approved approach rather than a challenge to its core design.

Key technical points for future reference:
- The distinction between `--porcelain` and `--line-porcelain` output modes
- The deduplication behavior in `emit_one_suspect_detail()`
- The per-line nature of ignored/unblamable status vs commit metadata
- The need to maintain consistency with existing porcelain format rules
