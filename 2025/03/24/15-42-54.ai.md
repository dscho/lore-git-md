This is a follow-up discussion in the Rust crate packaging series, specifically addressing patch 2/5 which introduced a symlink for out-of-tree builds. The thread had previously established the series' technical approach and confirmed all crates.io publication requirements were met.

Junio Hamano reports that the symlink solution from patch 2/5 is causing Windows test failures, as evidenced by CI job logs. He questions whether this approach is the only viable solution, implying concerns about platform compatibility. The symlink in question (`contrib/libgit-sys/git-src` pointing to `../..`) was originally added to enable cargo package operations while maintaining access to the full Git repository structure.

This surfaces a previously unaddressed platform limitation in the otherwise complete series. The earlier discussion had focused on build isolation and publication requirements without anticipating Windows-specific issues with the symlink approach. The comment suggests the need to either find an alternative solution or properly handle the Windows case, though no specific alternatives are proposed in this email.

The technical context remains the libgit-sys crate's build infrastructure, where the symlink was introduced to solve the cargo package access problem while maintaining the series' goals of parallel builds and size optimization. The challenge now is preserving those benefits while working around Windows' symlink limitations.
