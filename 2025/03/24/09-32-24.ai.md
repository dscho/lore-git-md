Bugfix and architectural improvement for default branch name advice suppression.

This email contains Phillip Wood's review of Justin Tobler's patch to properly integrate default branch name advice into Git's configurable advice system. The patch is part of a larger series addressing a regression where default branch advice ("hint: Using 'master'...") appeared during bundle operations despite suppression flags. 

The specific patch being reviewed (v2 3/3) makes the default branch name advice respect Git's standard advice suppression mechanisms by:
1. Adding `ADVICE_DEFAULT_BRANCH_NAME` to the advice type enum in `advice.h`
2. Modifying `repo_default_branch_name()` in `refs.c` to use `advise_if_enabled()` instead of direct `advise()`
3. Adding corresponding configuration support in `advice.c`
4. Including test coverage in t0001-init.sh to verify the new behavior

Phillip Wood approves the changes, noting this addresses a long-standing annoyance where the only way to silence the hint was by setting a default branch name rather than using Git's standard advice controls. The review confirms the technical approach is sound, though earlier in the thread Phillip identified one additional call site in `wanted_peer_refs()` that will need similar treatment to fully suppress the advice in all clone scenarios.

Key technical details for future reference:
- New advice type `ADVICE_DEFAULT_BRANCH_NAME` added to core advice system
- `repo_default_branch_name()` now respects both `--no-advice` flag and `advice.defaultBranchName=false` config
- Test verifies suppression works with config setting
-c advice.defaultBranchName=false`
- Part of broader effort to ensure consistent suppression across all code paths
- Builds on earlier work converting boolean parameters to flag bitmasks in related functions

The patch represents the architectural component of a solution that also includes immediate regression fixes for specific clone scenarios. Phillip's positive review suggests this portion is ready for inclusion, pending resolution of the remaining `wanted_peer_refs()` case noted elsewhere in the thread.
