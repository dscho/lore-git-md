Feature addition to the Git maintenance system, specifically for the loose-objects task. This is the second patch in a two-part series (following a progress reporting fix) that adds configurable batch size control for loose object packing during maintenance.

The patch introduces a new `maintenance.loose-objects.batchSize` configuration option that lets users adjust or remove the hardcoded 50,000-object limit when packing loose objects. The implementation handles edge cases carefully - using INT_MAX for "no limit" (configured as 0), avoiding underflow with negative values, and fixing an off-by-one error in the limit comparison. Documentation updates clearly explain the new option and its interaction with other maintenance tasks.

The change comes with thorough test coverage in t7900-maintenance.sh that verifies the batch size behavior works as expected, including progress reporting for partial batches. The implementation appears solid, building on existing maintenance infrastructure while addressing a real configuration gap. This seems like a straightforward quality-of-life improvement for repositories needing to tune their maintenance behavior.
