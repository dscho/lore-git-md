Refactoring patch in the path-walk delta compression series.

This is the first patch in v2 of the "pack-objects/repack: introduce --path-walk" series, extracting delta eligibility logic into a new `should_attempt_deltas()` function in pack-objects.c. The change moves the complex conditional checking whether an object should be considered for delta compression into a dedicated function, making the code more readable and preparing for reuse in subsequent patches that implement path-based delta selection.

The refactoring is straightforward - it takes the existing delta eligibility checks from `prepare_pack()` and moves them into a new helper function with the same logic. Key conditions checked include whether the object already has a delta, has a valid type, meets size thresholds, isn't marked as no-try-delta, and handles preferred_base objects appropriately. The patch maintains all existing behavior while making the code more modular.

This change supports the larger series goal of implementing path-based delta compression by making the delta eligibility logic reusable for both the traditional name-hash and new path-walk approaches. The commit message notes this will be helpful for future changes in the series, though it doesn't specify exactly which ones (likely the path-walk delta selection implementation coming in later patches).
