This is a feature patch series introducing configuration options for Git's maintenance tasks, specifically targeting the loose-objects cleanup operation.

Derrick Stolee proposes two changes to improve the `git maintenance` command's handling of loose objects. The first patch fixes a bug where progress indicators weren't properly passed to child processes when running in non-interactive contexts. The second patch adds a new `maintenance.loose-objects.batchSize` configuration option, allowing users to override the hard-coded limit for how many loose objects are processed in a single maintenance run.

The motivation comes from users who may want to clean up all loose objects at once rather than the default batched approach, without resorting to `git repack`. The changes are well-documented with updates to both config and command documentation, and include thorough test coverage in t7900-maintenance.sh.

The patches appear carefully crafted by an experienced contributor, addressing both an immediate usability issue (the progress indicators) and adding flexible configuration for a maintenance task that previously had hard-coded behavior. The changes are focused and unlikely to be controversial, though reviewers might want to verify the chosen default batch size remains appropriate.
