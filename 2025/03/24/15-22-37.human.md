This is a refactoring patch that extracts delta eligibility logic into a new `should_attempt_deltas()` function in `pack-objects.c`. It's the first patch in a 13-part series introducing path-based delta compression.

The change moves the complex conditional logic that determines whether an object should be considered for delta compression into a standalone function. This prepares for future changes in the series that will need to reuse this logic. The commit message notes this is purely preparatory - the behavior remains exactly the same, just better organized.

The patch is straightforward and mechanical, with no functional changes. It's a clean extraction that:
1. Takes the existing delta eligibility checks from `prepare_pack()`
2. Moves them into the new function
3. Updates the call site to use the new function
4. Maintains all the same error handling and edge cases

As the first patch in a larger series, this establishes a cleaner foundation for the more substantial changes to come. The series as a whole aims to improve delta compression by considering file paths when grouping objects, particularly benefiting repositories with many hash collisions (like JavaScript projects).
