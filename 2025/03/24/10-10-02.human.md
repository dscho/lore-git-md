This is a follow-up discussion in the pretty-format parsing refactoring series, specifically about patch 4/8 which fixes half-parsed padding placeholders.

Patrick Steinhardt agrees with Martin Ågren's approach in the patch to improve padding placeholder parsing by only storing successfully parsed data, but raises a larger question about error handling philosophy. He suggests that malformed placeholders (like "%<(10,bad)") should ideally cause Git to die rather than output the invalid syntax verbatim, as the current behavior can mask real problems. However, both acknowledge this would be a behavior change that might break existing use cases.

The discussion concludes that while stricter error handling would be desirable in principle, it's too risky to include in this refactoring series. Martin indicates this might be worth addressing separately in the future, possibly with configurable strict modes. The immediate patch maintains the current "print verbatim on failure" behavior while making the parsing itself more robust.

This exchange shows the patch is technically sound (having already incorporated Patrick's earlier suggestions) while surfacing an interesting design question about error handling that may warrant future discussion. The thread demonstrates careful consideration of backward compatibility concerns when evolving long-standing behavior.
