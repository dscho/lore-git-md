Bugfix follow-up addressing default branch advice suppression during clone operations. This is part of Justin Tobler's ongoing effort to fix a regression where Git would show unwanted "hint: Using 'master' as the name for the initial branch" advice during clone operations, particularly with bundle clones.

In this email, Justin responds to Phillip Wood's review of v2 patch 2/3, agreeing there's another case where advice suppression is needed. Phillip pointed out that `wanted_peer_refs()` also calls `guess_remote_head()` without suppressing advice, which can trigger the unwanted message when using `--single-branch`. Justin confirms this creates a second path for the advice to appear, and in some cases could even cause the message to print twice.

The email indicates Justin will send an updated version of the patch series that extends the suppression to cover this additional case. The discussion shows good progress toward comprehensively addressing all code paths where the default branch advice might appear during clone operations, with reviewers helping identify edge cases that need coverage. The fix maintains the principle that clone operations should never show this advice, regardless of configuration.
