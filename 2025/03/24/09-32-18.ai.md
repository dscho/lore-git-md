This is a follow-up review comment on a bugfix patch in Justin Tobler's series addressing unexpected default branch advice during clone operations. Phillip Wood notes that while the current patch correctly suppresses advice in the main clone path, there's another call to `guess_remote_head()` in `wanted_peer_refs()` that should also use the new `REMOTE_GUESS_HEAD_QUIET` flag for consistency. The rationale is that users shouldn't see default branch name advice during remote repository cloning operations, regardless of which code path triggers the advice.

The technical context involves the interaction between clone's refdb initialization sequence and default branch name computation, where recent changes caused previously suppressed advice to appear. The patch being reviewed modifies the clone.c caller to use the new quiet behavior flag, but Phillip points out this should likely be applied to all clone-related calls to `guess_remote_head()`. This aligns with the series' goal of comprehensively preventing unwanted advice during clone operations.

Key details for future reference:
- The `wanted_peer_refs()` function in clone.c is another advice-emitting path
- `REMOTE_GUESS_HEAD_QUIET` flag was introduced in this series to control advice
- The advice in question is the "hint: Using 'master' as the name for the initial branch" message
- Test coverage exists in t5607-clone-bundle.sh for the bundle clone case
- Phillip's suggestion implies the fix should be extended to cover all clone scenarios

This review doesn't challenge the core approach but suggests expanding the scope of the quiet behavior to ensure complete suppression of the advice message during clone operations. The comment indicates the series may need one more iteration to address this additional case.
