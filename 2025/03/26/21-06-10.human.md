Bugfix for `git blame` porcelain output, finalizing the implementation to show ignored/unblamable markers in porcelain mode. This patch represents the conclusion of a thread that explored several approaches before settling on adding new metadata lines rather than modifying existing SHA-1 prefixes.

The solution adds "ignored" and "unblamable" metadata lines in both `--porcelain` and `--line-porcelain` modes when the corresponding config options are set. This maintains backward compatibility while fixing what was effectively a documentation bug - the porcelain output didn't match the documented behavior for these special cases.

Key implementation details:
- New `emit_per_line_details()` function handles the conditional output
- Both porcelain modes now show the markers (contrary to earlier discussion about restricting to `--line-porcelain`)
- Documentation updated to clarify line-specific vs commit-specific information
- Tests verify the markers appear the correct number of times

The patch has already gone through significant review, with Junio Hamano and other contributors agreeing on the technical solution. This version incorporates feedback from Patrick Steinhardt and Toon Claes, moving from the rejected v1 approach (which would have broken backward compatibility) to the current metadata-based solution.
