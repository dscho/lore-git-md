Bugfix clarification for interactive rebase "Drop" parsing issue. Phillip Wood responds to Jarno Suni's report about `git rebase --edit-todo` failing on commit messages starting with "Drop", offering a more precise diagnosis than the original workaround.

Wood explains that the core issue isn't the "Drop" prefix itself, but rather that the commit's object ID gets lost when changing the operation from "pick" to "reword". The commit subject line (which happens to start with "Drop") is purely for user reference and isn't how Git identifies commits internally. This suggests the problem may be more about state management during rebase operation changes than about parsing commit messages specifically.

The response doesn't propose a fix but provides important technical context that shifts the understanding of the bug's nature. This moves the discussion from "parser fails on 'Drop' prefix" to "object IDs go missing during rebase operation changes", which may help guide future debugging efforts. The explanation maintains the practical workaround of rewriting commit messages but with better justification for why it works.
