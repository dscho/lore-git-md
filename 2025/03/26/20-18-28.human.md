Feature implementation introducing `git-blame-tree` command.

This patch introduces the core implementation of the new `git-blame-tree` command, which tracks changes to paths within tree objects similarly to how `git-blame` tracks line changes in files. The command walks history backwards to find when each path in a tree was last modified, showing the commit responsible. This is part of a larger series combining Jeff King's infrastructure work with Toon Claes' implementation.

The implementation adds new files `blame-tree.[ch]` for core logic and integrates with Git's diff machinery. Key aspects include:
- Support for recursive/non-recursive operation via `--recursive` flag
- Proper handling of pathspecs and relative paths
- Boundary commit detection (marked with `^`)
- Custom callback system for output formatting

The patch includes comprehensive tests in `t8020-blame-tree.sh` covering:
- Basic blame functionality
- Directory vs recursive behavior
- Subdirectory operation
- Merge scenarios and conflict resolution
- Pathspec handling

The implementation appears solid with careful attention to edge cases and integration with Git's existing revision walking infrastructure. One test (`limit blame traversal by count`) is marked as failing but appears to be a known issue to be addressed later in the series. This looks like a well-constructed addition that could be useful for understanding tree-level changes in a repository history.
