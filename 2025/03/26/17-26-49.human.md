This is a bugfix patchset addressing potential out-of-bounds array accesses in Git's codebase. Johannes Schindelin submits two small but important fixes that move array bounds checks to happen before rather than after array element access.

The first patch fixes a similar issue in the diff.c file, while the second addresses a case in read-cache.c. Both changes follow the same pattern - reordering existing checks to validate array indices before they're used. The commit messages are straightforward and the changes themselves are minimal (just 3 lines total modified).

Schindelin notes there are two more instances of this pattern in the clar test framework (not part of Git core), with fixes already submitted upstream. The changes appear well-justified and low-risk, following a clear defensive programming principle. This seems like a simple but worthwhile hardening of the codebase.
