This is a follow-up in the reftable library decoupling effort (`ps/reftable-sans-compat-util` series), specifically addressing a Windows-specific build issue. The thread had previously identified a MinGW-specific problem where mismatched memory allocators (mscrt.dll vs mimalloc) caused SIGTRAP failures in Windows unit tests. Patrick Steinhardt's solution moved the mimalloc override declarations from `git-compat-util.h` to `compat/posix.h` to ensure allocator consistency across the codebase.

Johannes Schindelin confirms that with this change applied to Git for Windows' `shears/seen` branch, the CI build now passes successfully for the first time in weeks. This resolves the last known technical blocker for the reftable decoupling series, which is a prerequisite for further Windows reftable fixes and part of the long-term ref backend abstraction work. The successful CI run provides the final verification needed to unblock the series' promotion.
