This is the final patch in the `git-blame-tree` series, implementing a performance optimization for tree-level blame operations. The patch introduces dynamic pathspec narrowing during traversal, allowing the revision-walking machinery to prune irrelevant history branches as paths are fully blamed.

Key technical details:
- Adds `pathspec_drop()` and `pathspec_setup()` functions to manipulate pathspecs during traversal
- Implements `pathspec_drop_from_trie()` to efficiently remove matched paths from the trie structure
- Modifies `blame-tree.c` to update pathspecs after each path is processed
- Maintains synchronization between the trie and linear pathspec representations

The optimization shows dramatic speedups (2.35x for git.git, 21.68x for linux.git) by allowing earlier pruning of irrelevant history. The implementation carefully handles edge cases through:
- BUG checks for invalid trie states
- Proper memory management when removing trie nodes
- Synchronization between diffopt and pruning pathspecs

This builds on the series' earlier pathspec trie work while introducing new pathspec manipulation capabilities. The changes are contained to blame-tree-specific code paths, with minimal impact on core pathspec machinery. The patch maintains correctness by accepting that some output may differ (when equally valid blame attributions exist) while guaranteeing accurate results.

The implementation appears production-ready, with thorough benchmarking and clear commit message explaining both the optimization and its limitations. This completes the core functionality of the `git-blame-tree` command, leaving only porcelain formatting and one test case as remaining work items from the original series scope.
