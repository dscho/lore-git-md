**SMTP authentication refactoring for Git send-email (part 1/2)**

This is the first patch in Zheng Yuting's two-part series to improve SMTP authentication error handling in `git-send-email.perl`, part of their GSoC project. The patch refactors the authentication flow to properly distinguish between credential failures and other SMTP errors.

The key change wraps the entire authentication process in a Perl `eval` block to catch all exceptions, where previously the code relied solely on boolean return values. This prevents non-credential errors (like network issues) from being incorrectly reported as authentication failures. The implementation introduces new state variables (`$result` and `$error`) to track outcomes and merges the previously separate SASL and basic auth code paths.

The patch maintains backward compatibility by still returning 1 for success/transient errors and 0 for credential failures. A comment notes that proper SMTP status code handling will come in the second patch. The changes have already gone through multiple review iterations (now at v9) with maintainer feedback incorporated, and the technical approach has been validated.

This appears to be a well-considered change that addresses a real limitation in the current implementation. The remaining work (handled in patch 2) involves integrating proper RFC 5321 status code parsing and resolving test suite expectations.
