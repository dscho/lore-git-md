Performance optimization for tree-diff pathspec matching. This is patch 7/8 in the `git-blame-tree` series, implementing Jeff King's pathspec trie optimization for tree-diff operations. The change makes pathspec matching asymptotically faster (O(log n) vs O(n)) when dealing with large numbers of pathspecs, particularly useful gains when processing 16+ pathspecs (up to 95% faster for 1024 pathspecs).

The patch modifies `tree-diff.c` to use the embedded pathspec trie structure (introduced earlier in the series) during tree traversal. Key changes include:
- New `match_pathspec_trie_entry()` helper that uses the trie for faster lookups
- Modified `skip_uninteresting()` to use the trie when available
- Passing the trie through recursive calls to maintain context during traversal

The included performance benchmarks demonstrate significant speedups for large pathspec sets while showing no regression for small cases. This optimization will particularly benefit use cases like programmatically-generated pathspecs (e.g., finding history for all current files in a directory).

The implementation appears solid with careful handling of edge cases and maintains the series' focus on memory safety. This represents a major performance win for the tree-diff infrastructure that will benefit not just `git-blame-tree` but other tree-oriented operations as well.
