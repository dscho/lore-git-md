Thread identity: Resolved platform-specific test failures in "backfill --min-batch-size" feature (commit 6840fe9ee2) affecting s390x and sparc64 architectures, with root cause identified as type mismatch in option parsing.

Core problem: The `--min-batch-size` option's test failures on big-endian architectures (s390x confirmed, sparc64 expected) were traced to a type mismatch where `OPT_INTEGER()` parsed into a `size_t` field without proper conversion. The issue manifested as missing trace2 data (expected promisor fetch_count=20 absent while unrelated fetch_count=48 appeared) and has now been resolved through type-safe parsing.

Current status: Patrick Steinhardt's fix changing `OPT_INTEGER` to `OPT_MAGNITUDE` has been validated by Todd Zullinger on s390x, with all 10 tests in t5620-backfill.sh now passing, including the previously failing "do partial clone 2, backfill min batch size" test. Fedora build logs confirm the resolution, though architecture coverage is more limited than Debian's.
