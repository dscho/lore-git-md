This is a style discussion in the ongoing refactoring series to eliminate comma operator usage in Git's codebase. Phillip Wood responds to Johannes Schindelin's patch that explicitly marked intentional comma operator use in wildmatch.c with a `(void)` cast.

Phillip proposes an alternative approach that avoids the comma operator entirely by restructuring the control flow. His suggested diff moves the assignments out of the loop condition and into the loop body, using a `goto next` label to handle the `continue` case cleanly. This maintains the same functionality while being more explicit about the control flow.

The discussion comes after technical consensus has been reached on most aspects of the series, with this being one of the final stylistic points under consideration. Phillip's suggestion aligns with Junio Hamano's earlier preference for more explicit control flow over clever use of language features. The patch is part of a broader effort to improve code clarity and maintainability across Git's codebase.
