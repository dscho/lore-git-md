Feature proposal introducing a new `git-blame-tree` command, reviving a long-running effort.

This cover letter proposes a new `git-blame-tree` command that shows the most recent modification to paths in a tree, similar to `git-blame` but operating at the tree level. Toon Claes builds on prior work by Jeff King (2011) and Ævar Arnfjörð Bjarmason (2023), with several key differences in approach.

The series implements this as a standalone builtin rather than a test-tool subcommand, arguing the command-line interface is useful enough to warrant first-class status. It reintroduces the controversial `--max-depth` parameter that was previously removed, and incorporates Jeff King's pathspec trie optimizations from his experimental branch. The implementation shows attention to modern practices by removing `USE_THE_REPOSITORY_VARIABLE` usage and adding memory leak fixes.

The author acknowledges this isn't merge-ready yet - there's a known failing test and missing features like `--porcelain` output. The goal appears to be restarting discussion rather than immediate inclusion. The patch series touches a wide surface area (26 files) including new test infrastructure and performance tests, suggesting this is a substantial but well-instrumented proposal.

This revives a concept that's seen multiple iterations over 12+ years, now updated for current Git practices. The technical depth and historical context in the cover letter suggests serious consideration, though the reintroduction of previously controversial elements may spark debate.
