Bugfix for `git blame` porcelain output, implementing the thread's consensus solution for ignored/unblamable line markers. This v2 patch follows the agreed approach of adding new metadata lines rather than modifying SHA-1 prefixes, addressing the inconsistency where porcelain mode wasn't show the documented '?' and '*' markers with `--ignore-rev`/`--ignore-revs-file`.

The implementation adds per-line "ignored" and "unblamable" metadata lines in both porcelain modes (`--porcelain` and `--line-porcelain`), with the output handled by a new `emit_per_line_details()` function. The patch updates documentation to clarify that line-specific information like these markers won't be grouped with commit-level details, and adds tests verifying the new behavior in both porcelain modes.

Key technical details:
- Maintains backward compatibility by preserving SHA-1 line format
- Adds new metadata lines rather than modifying existing output
- Updates `blame-options.adoc` and `git-blame.adoc` documentation
- Extends `t/t8013-blame-ignore-revs.sh` tests to cover porcelain modes
- Implements per-line status emission via `emit_per_line_details()`
- Follows porcelain format extensibility rules from blame-format.txt

The patch has already received positive feedback in the thread and addresses Junio Hamano's concerns about backward compatibility from earlier iterations. It represents the final implementation of the design discussed in the thread, now ready for merging after documentation and test updates.
