Bugfix clarification for interactive rebase parsing issue. Phillip Wood responds to Jarno Suni's report about the "Drop"-prefix parsing problem in `git rebase --edit-todo`, providing additional technical context about the underlying cause.

The response explains that the error occurs because Git loses track of the commit object ID when changing from "pick" to "reword" operations, not because of the "Drop" prefix itself. Phillip clarifies that commit subjects are purely for user reference in the todo file, as multiple commits could share identical subjects. This suggests the original bug report may have misdiagnosed the root cause, though the "Drop" prefix still appears related to the symptom.

The email doesn't propose a fix but provides authoritative clarification about the rebase machinery's behavior, indicating the issue stems from object ID tracking during operation changes rather than direct parsing of commit message prefixes. This shifts the technical understanding of the problem from being about command parsing to being about state management during interactive rebase operations. The workaround (aborting and restarting the rebase) remains valid, though now with clearer explanation of why it works.
