This is the second patch in Zheng Yuting's GSoC project to improve SMTP error handling in `git-send-email`. The patch implements RFC 5321-compliant status code parsing, distinguishing between temporary (4xx) and permanent (5xx) SMTP errors while maintaining backward compatibility.

The new `handle_smtp_error` subroutine uses regex patterns to extract 3-digit status codes from error messages, then applies RFC-specified behavior: allowing retries for transient errors (4xx) while failing permanently for credential issues (5xx). Unrecognized codes and errors without status codes are treated as transient failures to preserve existing behavior where possible.

The implementation follows through on the architectural foundation laid in patch 1, completing the transition from simple boolean returns to proper SMTP protocol compliance. Error messages now include the specific status codes to aid debugging. The patch has already undergone extensive review (now at v9) with all technical feedback addressed, though test suite updates remain pending.

This represents the final technical implementation of the feature, with the only remaining work being test case adjustments to account for the new RFC-compliant behavior. The changes are focused and well-contained to the SMTP authentication flow in `git-send-email.perl`.
