Interactive rebase parsing bug with "Drop"-prefixed commit messages: Jarno Suni reports that `git rebase --edit-todo` fails when processing commits whose messages begin with "Drop" (case-sensitive), incorrectly interpreting the message text as a malformed rebase command. The error occurs for both 'd' (drop) and 'p' (pick) operations, rejecting the todo file with "could not parse 'Drop'" messages. Technical investigation confirms the parser is failing to properly distinguish between command syntax and commit message content when the message starts with this specific prefix. A workaround exists by first using 'r' (reword) to change the commit message prefix before attempting drop operations. This appears to be a long-standing parsing edge case in the interactive rebase machinery rather than a regression, affecting core functionality for users manipulating commits with "Drop"-prefixed messages. No maintainer response or proposed fix yet; the report stands as an isolated bug demonstration with clear reproduction steps and workaround.
