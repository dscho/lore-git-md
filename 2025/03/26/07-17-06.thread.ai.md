Interactive rebase parsing and state management bug: Jarno Suni initially reported that `git rebase --edit-todo` fails when processing commits with "Drop"-prefixed messages, appearing as a command parsing issue. Phillip Wood's technical clarification reveals the root cause is actually Git losing track of commit object IDs when switching between "pick" and "reword" operations, with the message prefix being coincidentally related to the symptom rather than the cause. The rebase machinery maintains commit references by object ID, not message content, explaining why multiple commits can share identical subjects in the todo file. While the "Drop" prefix still triggers the visible error, the underlying issue involves state management during operation changes in the interactive rebase sequence. The workaround (aborting and restarting the rebase) remains valid, now better understood as resetting the object ID tracking state rather than avoiding a parsing edge case. No proposed fix yet, but the technical understanding has shifted from surface-level command parsing to deeper state management concerns in the rebase implementation.
