Platform compatibility issue: Test failure on s390x and sparc64 architectures after backfill feature addition.

John Paul Adrian Glaubitz reports that commit 6840fe9ee2 ("backfill: add --min-batch-size=<n> option") is causing test failures on s390x and sparc64 architectures. The specific failing test is "do partial clone 2, backfill min batch size" in the test suite.

The original commit by Derrick Stolee added a --min-batch-size option to the backfill command, allowing users to specify minimum batch sizes for more efficient delta compression. While the feature appears well-motivated for general use, it seems to have uncovered platform-specific issues on these less common architectures.

The report includes links to Debian build logs showing the failures, and helpfully CCs the original author. The nature of the test failure isn't specified in detail, but the fact that it's architecture-specific suggests either an endianness issue, word size problem, or other low-level platform quirk affecting the batch processing logic.

This appears to be a legitimate regression that will need investigation from the original author or platform experts. The report is clear and actionable, providing all necessary references to diagnose the issue.
