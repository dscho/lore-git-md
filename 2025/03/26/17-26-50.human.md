Bugfix patch addressing a potential out-of-bounds array access in Git's diff machinery. This is the first of a two-part series fixing similar issues found by static analysis.

The patch modifies `diff.c` to move a bounds check before array access when handling indentation in diff output. The change is minimal (just reordering a condition) but important for safety - it ensures we verify we're within bounds before dereferencing the string array. The issue was caught by CodeQL's static analysis tool.

This appears to be a straightforward correctness fix with no behavior change in normal operation. The author (a known Git contributor) notes this is part of a broader effort to address similar issues, with parallel fixes going into the clar test framework. The change is small and focused, with no obvious controversy or open questions raised yet.

The second patch in the series will address a similar issue in `read-cache.c`. Together they implement a defensive programming pattern of checking array bounds before access rather than after.
