Bug report follow-up about platform-specific test failures in `backfill --min-batch-size`.

Todd Zullinger confirms they previously reported this same test failure during the release candidate period but didn't receive a response. The issue affects the "do partial clone 2, backfill min batch size" test on s390x and sparc64 architectures, though the exact cause remains unclear. 

The original feature by Derrick Stolee added a `--min-batch-size` option to control delta compression during partial clones. While the test passes on other platforms, these two architectures consistently fail. Todd is following up on their earlier report in hopes of getting attention to the issue, noting that the timing may now be better for a response from the feature's author.

This appears to be either a platform-specific bug in the batch size handling or a test assumption that doesn't hold true for these architectures. The thread currently lacks technical analysis of why these particular platforms are affected.
