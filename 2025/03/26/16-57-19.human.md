Platform compatibility fix for the reftable decoupling effort.

This email confirms that Patrick Steinhardt's fix for the MinGW-specific memory allocator mismatch in the reftable library has successfully resolved the Windows CI failures. The issue occurred because the reftable code (using mscrt.dll) and Git core (using mimalloc) were using different allocators, causing SIGTRAP errors during unit tests. The fix moves the mimalloc override declarations to `compat/posix.h` to ensure allocator consistency across the codebase.

Johannes Schindelin reports that with this change, the Git for Windows CI pipeline has passed for the first time in weeks, clearing the last known blocker for the reftable decoupling series (`ps/reftable-sans-compat-util`). This series is part of the long-term effort to make the reftable backend more portable by removing Git-specific dependencies.

The successful resolution of this Windows-specific issue means the series can now proceed toward integration, pending final verification that Schindelin mentions having completed. This is a significant step forward for both the reftable work and the dependent Windows reftable fixes.
