Bugfix for the `within_depth()` function in the `git-blame-tree` series. This patch corrects an edge case in path depth calculation that could theoretically produce incorrect results, though the current callers happen to be unaffected. The function is used to enforce `--max-depth` limits in pathspec matching.

The core issue lies in how `within_depth()` handles empty paths when the base is non-zero. The original implementation would always return true for empty paths regardless of base depth, while the fixed version properly compares the computed depth against the maximum. Jeff King's detailed analysis shows this doesn't currently impact behavior because the only affected caller (`tree_entry_interesting`) is used by `git grep`, which only cares about blobs and benefits from the early termination. However, the inconsistency could matter for future users wanting to show tree entries themselves (like in recursive tree diffs).

The change is minimal (a single-line logic fix in `dir.c`) but demonstrates careful consideration of edge cases in the pathspec subsystem. This patch appears as the second in an 8-part series modernizing tree-level blame functionality, building on prior work while fixing latent issues in the infrastructure. The fix maintains compatibility with existing `git grep` optimization while providing correct behavior for potential future uses.
