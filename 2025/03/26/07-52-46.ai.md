This is the second patch in Zheng Yuting's GSoC project to improve SMTP error handling in `git-send-email.perl`, focusing on RFC 5321 compliance. The patch introduces fine-grained error classification by implementing a new `handle_smtp_error` subroutine that parses SMTP status codes from error messages.

The key technical components are:
1. A regex (`/\b(\d{3})\b/`) extracts 3-digit SMTP status codes from error messages
2. Status codes are classified as transient (4xx), permanent (5xx), or unknown (other codes)
3. Each case produces appropriate warning messages and return values (1 for transient/unknown, 0 for permanent failures)
4. The handler maintains backward compatibility by defaulting to transient error behavior when no status is found

The implementation builds on patch 1's exception handling infrastructure, replacing its simple boolean return with this more sophisticated classification system. This completes the RFC 5321 compliance work while preserving the existing interface contract where 1 indicates success/retry-able conditions and 0 indicates credential failures.

The patch shows careful attention to detail with:
- Clear warning messages distinguishing error types
- Proper handling of edge cases (missing/unknown status codes)
- Preservation of the boolean return contract
- Clean integration with the existing auth flow
