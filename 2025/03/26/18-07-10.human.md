This is a build system patch addressing a platform compatibility issue in the compiler detection script. Eric Sunshine points out a syntax problem with the `sed` command proposed in Johannes Schindelin's earlier fix for detecting Clang in CUDA environments.

The issue specifically affects BSD-lineage `sed` implementations (like macOS's), which misinterpret the closing brace as an argument to the `q` command rather than a statement terminator. Eric demonstrates the failure case and provides the corrected syntax requiring a semicolon after `q`.

This comes as a follow-up to Jeff King's review of the compiler detection changes in the larger comma-operator refactoring series. While the technical approach (using `sed` to parse version strings) had already been approved, this catches a portability issue that would break the build on macOS systems. The fix is straightforward - adding the missing semicolon - and maintains the same functionality while working across all target platforms.

The patch appears well-justified and narrowly focused, addressing a real-world build failure while staying aligned with the series' goals. Since this touches compiler detection logic that's critical for the `-Wcomma` warning implementation, it's likely to be merged quickly given the series is otherwise ready for integration.
