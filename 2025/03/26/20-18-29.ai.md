This is a performance optimization patch introducing a trie data structure for pathspec matching, part of the `git-blame-tree` series. The patch comes from Jeff King (not Toon Claes as the headers might imply - the attribution appears to be a mail client artifact).

The core change adds a `pathspec_trie` structure that provides O(log n) lookups for simple prefix pathspecs (those without wildcards or magic features), improving on the current O(n) linear scan. The trie organizes pathspecs hierarchically by path components, allowing binary search at each level. This particularly benefits operations like tree diffs that repeatedly check paths against the same pathspecs.

Key technical elements:
- New `pathspec_trie` struct in `pathspec.h` with terminal/must_be_dir flags
- Trie construction via `pathspec_trie_build()` and lookup via `pathspec_trie_lookup()`
- Special handling for empty paths (".") and directory markers ("foo/")
- Comprehensive test suite (`t6137-pathspec-trie.sh`) covering:
  - Basic prefix matching
  - Directory vs file distinctions
  - Overlapping pathspecs
  - Root directory matching

The implementation is currently unused in main Git operations but provides infrastructure for future optimizations. The accompanying test helper (`test-pathspec.c`) demonstrates the intended usage pattern, though the commit notes this may be better tested through actual tree-diff operations.

This appears to be a well-considered optimization, building on established pathspec infrastructure while introducing a clear performance win for common cases. The thorough test coverage and careful handling of edge cases (empty paths, directory markers) suggest production-ready quality, though the actual integration with tree-diff operations remains to be completed in later patches.
