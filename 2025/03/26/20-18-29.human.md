This is a performance optimization patch in the `git-blame-tree` series, introducing a trie data structure for faster pathspec matching. Authored by Jeff King (with Toon Claes submitting), it addresses a known O(n²) performance issue when matching many paths against many pathspecs.

The patch adds a `pathspec_trie` structure that organizes plain prefix pathspecs (those without wildcards) into a searchable tree. This enables logarithmic-time lookups by path component, a significant improvement over the current linear scan approach. The trie handles both exact matches and prefix matches, with special consideration for directory markers (trailing slashes).

Implementation includes:
- Core trie construction and lookup functions in `pathspec.[ch]`
- Comprehensive test coverage in new files `t/helper/test-pathspec.c` and `t/t6137-pathspec-trie.sh`
- Careful handling of edge cases like empty paths and overlapping specs

The change is well-motivated with clear performance rationale in the commit message. While currently unused (a follow-up will integrate it), the standalone implementation with tests makes it easy to verify correctness. This appears to be a robust foundation for speeding up tree operations that use pathspecs, particularly relevant for the blame-tree functionality being developed in this series.
