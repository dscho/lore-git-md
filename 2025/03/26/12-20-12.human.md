Windows compatibility fix discussion on reftable lockfile race condition.

This is a technical discussion between Patrick Steinhardt and Windows expert Johannes Schindelin about the v2 patch series addressing a MinGW-specific race condition in file handling. The core issue involves Windows' `CreateFileW()` incorrectly returning `EACCESS` when a file is pending deletion, causing flaky test failures in reftable operations.

Johannes raises concerns about the current solution's use of `RtlGetLastNtStatus()`, an undocumented Windows API function, suggesting it may need removal later. He proposes an approach that would handle `EACCES` the same as `EEXIST` specifically in the reftable library's lockfile handling code (step 4 of the compaction process), rather than making a global change in `mingw_open()`.

The discussion highlights the tension between precise error handling (using NT status codes) and maintaining clean, documented Windows API usage. Johannes references other projects' approaches (PostgreSQL vs SQLite) while acknowledging Patrick's solution does fix the test flakiness. This appears to be a key review point that will determine whether the patch needs another revision before merging.
