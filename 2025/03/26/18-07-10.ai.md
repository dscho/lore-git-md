This is a platform compatibility fix for the compiler detection script in the ongoing comma-operator refactoring series. Eric Sunshine identifies a portability issue with Johannes Schindelin's proposed `sed` command for detecting Clang versions, particularly affecting BSD-derived systems like macOS.

The problem stems from BSD `sed` interpreting the closing brace after `q` as an argument rather than a command terminator. Eric demonstrates the failure case on macOS and provides the corrected syntax requiring a semicolon after `q` (`sed -n '/ version /{p;q;}'`). This maintains the same functionality - printing the first matching version line and quitting - while working across both GNU and BSD `sed` implementations.

This email comes after Jeff King had already reviewed and approved Johannes's original approach, making it a late-stage refinement to ensure cross-platform compatibility. The fix addresses a real issue (confirmed by testing on macOS) while preserving the script's core purpose of reliably detecting Clang versions even in CUDA environments. The change is minimal and clearly explained, with Eric providing both the failure case and working solution.
