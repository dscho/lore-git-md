Feature patch adding tree-diff depth limiting, part of the `git-blame-tree` series.

This patch introduces a `--max-depth` parameter for tree diffs, allowing users to limit recursion depth when comparing trees. The depth is measured from the closest pathspec match, so `--max-depth=1 -- foo` shows `foo/bar` but not `foo/bar/baz`. The implementation carefully handles edge cases like empty pathspecs and ensures the option only works with tree-to-tree comparisons (not worktree/index diffs).

The change touches core diff infrastructure across several files, adding the new parameter to `diff_options` and implementing the depth checking logic in `tree-diff.c`. The patch includes comprehensive tests in `t4071-diff-max-depth.sh` covering various depth and pathspec combinations. While the implementation appears solid, the `--max-depth` concept has been historically debated in Git - some may question whether this belongs in core diff or should be handled by porcelain commands.

This is patch 3/8 in a series modernizing and upstreaming tree-level blame functionality. The depth limiting will be particularly useful for the upcoming `git-blame-tree` command to efficiently analyze changes at specific directory levels.
