This is a performance optimization patch in the `git-blame-tree` series, focusing on the pathspec trie implementation. Authored by Jeff King, it enables automatic trie generation for pathspecs when no wildcards or magic patterns are present, embedding the trie directly within the `struct pathspec` for seamless integration with existing callers.

The patch makes three key changes: First, it adds automatic trie construction during pathspec parsing via `parse_pathspec()` and copying via `copy_pathspec()`. Second, it introduces proper cleanup with `pathspec_trie_clear()` to handle nested trie structures safely. Third, it updates the test helper to use the embedded trie rather than building a separate one.

The implementation embeds the trie directly in the pathspec struct rather than keeping it separate, which minimizes disruption to existing call chains while providing the optimization. The trie will now be automatically available to all pathspec users, though they still need to be modified to actually use it (which future patches will address).

The change is performance-focused, with the trie providing O(log n) lookups for simple prefix pathspecs.
