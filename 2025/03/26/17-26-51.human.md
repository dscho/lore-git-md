Bugfix completing a two-patch series addressing potential out-of-bounds array accesses found by static analysis. This second patch modifies `read-cache.c` to reorder bounds checking in the `ce_write_entry` function, ensuring array indices are validated before being used.

The change follows the same pattern as the first patch in the series (which fixed `diff.c`), swapping the order of conditions in a loop to check array bounds before accessing elements. Here it affects the comparison of cache entry names during index writing. The modification is minimal (just two lines swapped) but prevents possible out-of-bounds reads when comparing file names in the index.

Like the first patch, this was flagged by CodeQL's `cpp/offset-use-before-range-check` rule, suggesting these are part of a systematic code quality effort. The changes appear straightforward and well-justified, following the defensive programming principle of validating inputs before use. With both patches now submitted, this completes the series addressing these static analysis findings.
