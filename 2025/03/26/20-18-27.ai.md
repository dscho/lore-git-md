Feature patch introducing tree-diff depth limiting, part of the `git-blame-tree` series.

This patch from Jeff King (with Toon Claes as submitter) adds a `--max-depth` parameter to tree diffs, allowing controlled recursion into subtrees. The depth is measured from the closest pathspec match, enabling queries like `git log --raw --max-depth=1 a/b/c` to show contents of `a/b/c/` without recursing further. The implementation spans diff infrastructure (adding `max_depth` and `max_depth_valid` fields to `diff_options`), pathspec handling, and tree-diff logic, with careful attention to edge cases like empty paths and wildcards (explicitly prohibited). New test cases in `t4071-diff-max-depth.sh` verify behavior across various depth/path combinations.

Key technical details: The depth calculation uses `within_depth()` from `dir.c` (recently fixed in this series) and handles pathspecs by checking for prefix matches in reverse-sorted order (longest first). The patch maintains existing diff behavior while adding the new constraint, with explicit guards against unsupported use cases (worktree/index diffs, wildcards). The implementation shows thoughtful integration with Git's existing diff machinery, though the `max_depth_valid` flag reveals some awkwardness in the options initialization pattern.
