Feature implementation introducing the `git-blame-tree` command, part of the ongoing tree-level blame functionality series. This patch adds the core subcommand implementation that traces file modifications through tree objects, analogous to `git-blame` but operating at the tree level.

The implementation introduces several key components:
- New `blame-tree.[ch]` files containing core logic for tree traversal and blame attribution
- Integration with Git's diff machinery via callback-based diff processing
- Path tracking through `string_list` with `blame_tree_entry` structs
- Basic porcelain output showing commit hashes and paths
- Initial test suite (`t8020-blame-tree.sh`) covering recursive/non-recursive operation, subdirectory handling, and merge scenarios

The command follows similar patterns to `git-blame` but with some notable behavioral differences:
- Blames any change affecting a path (including renames, mode changes) rather than just content modifications
- Uses tree diffs rather than file content comparison
- Supports recursive operation through subtrees
- Outputs raw commit hashes rather than line-by-line annotations

The patch builds on prior infrastructure work in the series (particularly the diff traversal controls) while introducing the user-facing command. Test coverage appears thorough for basic functionality though one test is marked as failing (depth-limited traversal). The implementation shows careful attention to memory management and integration with Git's existing revision walking infrastructure.
