This is a cover letter for a feature series introducing a new `git-blame-tree` command, building on prior work by Jeff King and Ævar Arnfjörð Bjarmason. The series represents the latest attempt to upstream this functionality that shows the most recent modification to paths in a tree, similar to `git-blame` but operating at the tree level.

The series consists of 8 patches - 7 from Jeff King's earlier work (dating back to 2011) that implement supporting infrastructure like pathspec tries and max-depth parameters for tree diffs, and 1 new patch from Toon Claes that introduces the actual `git-blame-tree` command. The author has made several improvements over previous attempts, including rebasing onto current master, removing `USE_THE_REPOSITORY_VARIABLE`, fixing memory leaks, and moving some code between files as suggested in earlier feedback.

Key technical aspects include:
- New `blame-tree.c` and `blame-tree.h` files implementing the core functionality
- Pathspec trie indexing for performance optimization
- `--max-depth` parameter for controlling traversal (a previously controversial feature the author wants to reconsider)
- New test files (`t/t8020-blame-tree.sh`) and performance tests (`t/perf/p4003-diff-pathspec.sh`)

The author acknowledges this isn't yet merge-ready (with one known test failure and missing features like `--porcelain` output), but aims to gather feedback for further iteration. The series touches multiple subsystems including diff, pathspec, and combine-diff, with significant additions to the codebase (over 1200 lines added across 26 files).

This appears to be a serious, well-researched effort that builds thoughtfully on prior work, though the reintroduction of the controversial `--max-depth` parameter may spark renewed debate. The extensive test coverage and performance benchmarking suggest the author is approaching this with production-quality standards in mind.
