This is a clarification in the ongoing platform compatibility discussion about Python version selection for git-p4.

Todd Zullinger provides technical precision regarding Python-related environment variables, distinguishing between PYTHON_PATH (used by Git's build system to specify the Python interpreter path) and PYTHONPATH (Python's module search path). He confirms that setting PYTHON_PATH to the appropriate Python 3 interpreter path has worked well in Fedora's packaging, suggesting this approach should similarly work for NonStop systems. The email reinforces the thread's consensus that Python environment management is primarily a system-level concern, with Git only needing to know the interpreter path when building git-p4.

Key technical details include:
- Clear differentiation between PYTHON_PATH (build-time interpreter selection) and PYTHONPATH (runtime module search)
- Fedora's successful transition from dual Python 2/3 support to Python 3-only
- Suggestion that any NonStop-specific issues would be Python implementation details rather than Git concerns

The email supports the established thread direction while providing concrete packaging experience to validate the simple PYTHON_PATH approach. It maintains the boundary between Git's limited role in Python configuration and system-level Python environment management.
