This is a bugfix patch in the `git-blame-tree` series, addressing a memory initialization issue in the combine-diff subsystem. The patch fixes a case where `diff_filepair` structs created during combined diffs were allocated but not zero-initialized, potentially exposing random memory values in unused fields. 

The change switches from `xmalloc` to `CALLOC_ARRAY` to ensure all fields start zeroed, matching the behavior of regular diff operations. The author notes that while some fields like `status` could theoretically be set to a new `DIFF_STATUS_COMBINED` value, this remains conservative by keeping them zero until clearer use cases emerge. 

This appears to be a straightforward correctness fix with no behavior change - it plugs a potential source of undefined behavior without introducing new complexity. The patch is small (1-line change) and well-explained, referencing both the original 2011 commit that introduced the issue and the rationale for not yet adding new status flags. As part of the larger blame-tree effort, this helps modernize the diff infrastructure that the new feature will build upon.
