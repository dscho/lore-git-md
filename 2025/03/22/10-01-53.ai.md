Feature proposal for git-shell command override capability.

This RFC patch from Ayman Bagabas proposes allowing git-shell built-in commands to be overridden by placing scripts with matching names in the git-shell-commands directory. The key change moves the `cd_to_homedir()` call earlier in `cmd_main()` to ensure the override directory is checked first, then attempts to execute a matching script if found before falling back to the built-in command.

The implementation adds logic branch that checks for existence of an override script using `make_cmd()` and `access()`, executing it via `execv()` if present. This would enable use cases like access-controlled wrappers around commands like `git-receive-pack`, where the wrapper could perform authorization before invoking the original command.

The patch touches shell.c's command dispatch logic, modifying the execution path for built-in commands. It introduces a new `full_cmd` variable to hold the constructed path and adds conditional execution based on script presence. The change appears to maintain backward compatibility while adding the new capability.

Potential discussion points may include security implications of script execution order, whether this should be configurable rather than automatic, and whether similar functionality could be achieved through existing mechanisms like aliases or wrapper scripts in PATH. The RFC status suggests the author is seeking feedback on both the concept and implementation approach.
