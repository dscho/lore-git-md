Bugfix for `git p4` error message encoding, extending the thread's ongoing work on Perforce metadata handling. This is a follow-up ping from Nikolay Shustov for their previously submitted patch that addresses error message decoding failures when Perforce returns non-UTF-8 byte streams.

The patch refactors the existing metadata transcoding logic into a new `MetadataTranscoder` class, then applies the same configurable fallback strategy (via `git-p4.metadataDecodingStrategy` and `git-p4.metadataFallbackEncoding`) to error message handling. Key technical changes include:

1. Moving transcoding logic from `metadata_stream_to_writable_bytes()` into the new class
2. Enhancing error message decoding to respect the existing config settings
3. Adding Python 3-specific test verification (`t9837-git-p4-error-encoding.sh`)
4. Improving verbose error diagnostics in `MetadataDecodingException`

The implementation maintains Python 2/3 compatibility through careful byte handling and leverages existing configuration options rather than introducing new ones. The test coverage targets the specific failure scenario though is limited to Python 3 due to Unicode handling differences. The changes appear well-contained and consistent with the thread's established approach to encoding issues in the `git p4` bridge.
