This is a feature proposal for git-shell that would allow overriding built-in commands with custom scripts. The RFC patch from Ayman Bagabas would let users place scripts in git-shell-commands/ that have the same names as built-in commands (like `git-receive-pack`), which would then be run instead of the built-ins.

The primary use case presented is for access control - a script could check user permissions before deciding whether to call the original command. The implementation looks straightforward, modifying shell.c to first check for an override script before falling back to the built-in. The patch moves the `cd_to_homedir()` call earlier to ensure script lookup happens in the right directory.

As an RFC, this appears to be an early proposal seeking feedback on the concept. The change is small (12 lines net) and focused, though it does raise some potential questions about security implications and whether this is the best approach versus alternatives like git-shell's existing restricted command mechanism. The commit message could benefit from more detail about why this approach was chosen over alternatives.
