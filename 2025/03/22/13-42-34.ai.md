This is a follow-up in a thread about a `git rebase` issue with worktrees. The thread began with Andy Shevchenko reporting a problem where `git rebase` would fail with "fatal: 'netboot' is already checked out" when trying to rebase a branch that was checked out in another worktree. Jeff King identified the likely culprit as commit b5cabb4a967 which added this check to prevent potential issues with multiple worktree checkouts.

In this email, Andy notes that newer versions (though he doesn't specify which) have resolved the issue for him, and he no longer needs the workaround of splitting the operation into separate checkout and rebase commands. He expresses appreciation for the fix while acknowledging he hasn't tracked down exactly which version introduced the resolution.

Key technical details for future reference:
- Original issue involved `git rebase` failing when target branch was checked out in another worktree
- Fixing commit was b5cabb4a967 (rebase: refuse to switch to branch already checked out elsewhere)
- Workaround involved using `--ignore-other-worktrees` flag with checkout
- Issue appears resolved in recent versions though exact fix version isn't specified

The thread appears to be concluding with this confirmation that the problem has been addressed in newer Git releases.
