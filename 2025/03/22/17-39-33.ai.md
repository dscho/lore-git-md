Security-focused response to git-shell command override RFC.

Elijah Newren raises significant security and compatibility concerns about Ayman Bagabas's proposal to allow overriding git-shell built-in commands via scripts in git-shell-commands. The response argues this approach would introduce multiple risks: creating security vulnerabilities, breaking Git's internal command execution (like `git-stash`), complicating debugging, and potentially disrupting programs relying on plumbing commands. Newren's stance is firmly against the feature in its current form, preferring to avoid these risks entirely.

Key technical objections focus on the cascading effects of command interception, particularly around subprocess execution patterns that Git internals rely on. The response implies these issues may be fundamental to the design rather than easily mitigated, suggesting the RFC may need substantial rethinking or abandonment rather than incremental fixes. This marks a significant challenge to the proposal's core premise, moving the discussion toward whether the feature's benefits outweigh its inherent risks.
