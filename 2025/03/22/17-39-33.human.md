This is a security-focused response to the git-shell command override RFC. Elijah Newren raises strong objections to Ayman Bagabas's proposal to allow overriding built-in git-shell commands via scripts in the git-shell-commands directory.

Newren identifies several potential problems with the approach:
1. Security vulnerabilities could be introduced through the override mechanism
2. Commands that spawn other git subprocesses (like `git-stash`) might break
3. Debugging git issues would become more difficult
4. External programs relying on plumbing commands could be affected

The response is unequivocally negative, stating "I'd rather we didn't" implement this feature. While the original RFC positioned the change as enabling useful access control scenarios, Newren's concerns suggest the security and stability risks outweigh any potential benefits. This appears to be a fundamental objection to the concept rather than just implementation details.
