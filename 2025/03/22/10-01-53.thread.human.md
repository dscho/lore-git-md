Ayman Bagabas proposed allowing git-shell built-in commands to be overridden by placing executable scripts in a git-shell-commands directory, with the implementation modifying shell.c to check for scripts before falling back to built-ins. The RFC sought feedback on both the concept and approach, leaving open questions about security implications and configuration.

Elijah Newren has now raised substantial security and compatibility objections, arguing the proposal would introduce vulnerabilities and break Git's internal command execution patterns. His concerns focus on the cascading effects of command interception, particularly how it might disrupt plumbing commands and subprocess execution that Git internals rely on. Newren's position suggests these issues may be fundamental to the design rather than easily addressed, casting doubt on whether the feature's benefits outweigh its risks. This response moves the discussion toward whether the proposal needs significant rethinking or should be abandoned entirely.
