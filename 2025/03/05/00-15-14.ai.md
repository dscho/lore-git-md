This is the final version of a bugfix series addressing object freshening behavior with multiple cruft packs. The series has been reduced to a single patch after withdrawing an earlier problematic simplification.

The core fix modifies `want_found_object()` in `builtin/pack-objects.c` to properly handle object freshening when multiple cruft packs exist. The implementation:
- Maintains the `ignore_packed_keep_in_core_has_cruft` flag for mtime comparison control
- Preserves objects from non-cruft packs unconditionally
- For cruft pack objects, keeps them only if their mtime is older than the version being packed
- Falls back to pack's mtime when object mtimes are unavailable

The patch includes comprehensive test coverage in `t/t7704-repack-cruft.sh` and requires supporting changes to expose `kept_pack_cache()` in `packfile.c` and `packfile.h`. The commit message has been refined with precise wording about mtime comparisons and clear behavior descriptions.

The withdrawn patch (from v2) would have simplified cruft pack aggregation logic but was found to risk creating pathological repacking cycles when `--max-cruft-size` approaches `--max-pack-size`. Patrick Steinhardt identified this issue, leading to the patch's removal while keeping the original size-tracking approach.

All technical concerns have been addressed, with consensus from reviewers, this version is ready for maintainer consideration. The changes affect core packing behavior but are well-contained with thorough test coverage.
