This is the final version of Karthik Nayak's 8-part series introducing partial reference transaction support to Git's refs subsystem. The series has undergone significant refinement through three iterations, with key design decisions now solidified.

The core feature allows reference updates to partially succeed when the `--allow-partial` flag is used with `git update-ref --stdin`. Individual reference updates can fail (due to user-facing errors like invalid refnames or incorrect old values) while allowing other updates in the same transaction to proceed. System errors (like I/O failures) still abort the entire transaction.

Key technical improvements in v3 include:
- Renamed error enum from `transaction_error` to `ref_transaction_error` for clarity
- Removed `TRANSACTION_OK` in favor of standard `0` success return
- Added optimized rejection tracking via new `ref_transaction_rejections` struct
- Improved error handling logic in `ref_transaction_maybe_set_rejected()`
- Removed NUL-delimited output format for rejected updates
- Added support for partial failures during F/D (filename/directory) conflict checks

The implementation touches all major ref backends (files, packed, reftable) and includes comprehensive tests. The series demonstrates careful attention to performance, maintainability, and backward compatibility while introducing this new capability.

With all major design points resolved through constructive discussion between Karthik, Patrick Steinhardt, and Phillip Wood, this series appears ready for merging to provide a foundation for future integration with fetch/receive-pack operations.
