This is a response to a feature proposal about adding language-specific `.gitignore` templates to `git init`. Brian m. carlson raises several practical concerns about the idea, suggesting it may not be feasible for core Git to implement.

The response acknowledges the appeal of the concept but highlights significant challenges: the vast number of programming languages and environments (citing Neovim's 693 syntax files as an example), platform-specific variations in what should be ignored, and the difficulty of maintaining such a collection. The author notes Git's policy of not favoring external projects like GitHub's templates, and objects to the idea of `git init` making network connections to fetch templates.

As an alternative, the email points to Git's existing `--template` option which can include a `.gitignore` file in an initial commit, though notes this approach has limitations with alternate ref formats and hash algorithms. The tone is constructive but skeptical, suggesting the proposal might be better suited for external tooling rather than core Git functionality. The response doesn't outright reject the idea but sets a high bar for how such a feature would need to be implemented to be acceptable in mainline Git.
