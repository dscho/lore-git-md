This is a refactoring patch in Karthik Nayak's series implementing partial reference transactions. The change moves duplicate refname checking from individual backends into the generic refs layer, centralizing this logic in `ref_transaction_add_update()`.

The patch adds a `refnames` string_list to track all references in a transaction, eliminating 146 lines of duplicate code across backends. Junio Hamano approves the change, noting that the transaction object is the logical place for this tracking. He questions whether symref handling (like updating both HEAD and its target) should also be moved to the generic layer, though this isn't addressed in the current patch.

The reftable backend sees a subtle but important fix - moving the refname check before rather than after adding to the transaction to avoid always getting a positive match. Junio calls this change "perfect" and endorses the overall direction of centralizing transaction logic.

This appears to be a straightforward improvement that simplifies the codebase while maintaining safety. It's part of the larger effort to support partial reference transactions, with this piece specifically cleaning up duplicate functionality before the feature implementation continues.
