This is a follow-up proposal in the ongoing discussion about language-specific `.gitignore` support in `git init`. Oleg Taranenko suggests a middle-ground solution that attempts to address both the maintainer's neutrality concerns and users' desire for language-specific ignore patterns.

The email proposes adding a new `--only-gitignores` flag to `git init --template` that would selectively copy just the `.gitignore` files from a template directory while ignoring other template components. This aims to simplify the user experience compared to full template directories while maintaining Git's neutrality principle by keeping the actual ignore patterns outside core Git.

The proposal includes some practical considerations: it would skip existing `.gitignore` files (with warnings rather than overwrites) and would only process the ignore file structure rather than other template components like hooks. This appears to be an attempt to carve out a minimal, focused solution that might satisfy both sides of the debate.

However, the suggestion still faces the core architectural question raised earlier in the thread: whether any modification to `git init` for this purpose is appropriate, or if the functionality should remain entirely in user-space solutions. The proposal doesn't directly address Junio's expressed concerns about Git becoming responsible" for maintaining language-specific content, even indirectly through template mechanisms.
