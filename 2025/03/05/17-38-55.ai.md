This is the final version (v3) of Karthik Nayak's 8-patch series introducing partial reference transaction support, building on previous discussion and refinements. The series adds a new `--allow-partial` flag to `git update-ref` that enables individual reference updates to fail while allowing others to proceed in a transaction.

Key technical changes in this version include:

1. Renamed the error enum from `transaction_error` to `ref_transaction_error` and removed `TRANSACTION_OK` in favor of using 0 for success (standard Git convention).

2. Added a new `ref_transaction_rejections` struct to track failed updates separately, allowing efficient iteration over only rejected updates rather than scanning all updates.

3. Consolidated error handling logic into `ref_transaction_maybe_set_rejected()` which now handles both the rejection marking and error classification.

4. Added support for partial failures during F/D (file/directory) conflict checks, which were previously treated as fatal.

5. Removed NUL-delimited output format for rejections, keeping only the human-readable format.

The implementation now distinguishes between system errors (which still abort the entire transaction) and user-facing errors (which can be skipped when partial transactions are enabled). The series includes comprehensive tests covering various rejection scenarios and documents the new behavior in git-update-ref.adoc.

This version represents the culmination of design discussions with Patrick Steinhardt and Phillip Wood, addressing performance concerns and interface design points raised in previous iterations. The changes maintain Git's atomic transaction guarantees by default while providing flexibility for tools that need to handle partial failures gracefully.
