This is part 7/8 of Karthik Nayak's series implementing partial reference transaction support, specifically focusing on F/D (file/directory) conflict handling. The patch modifies `refs_verify_refnames_available()` to support partial rejection of updates when F/D conflicts occur, rather than failing the entire transaction.

Key technical changes:
- Moves `refs_verify_refnames_available()` from public `refs.h` to internal header since it now takes a `ref_transaction` parameter
- Adds transaction-aware rejection via `ref_transaction_maybe_set_rejected()` at each F/D conflict check point
- Updates both files and reftable backends to pass update indices through string_list utilities for proper rejection tracking
- Maintains existing atomicity guarantees while allowing individual updates to be skipped
- Includes memory management for the new index tracking in string lists

The changes build on the series' core infrastructure for partial transactions, particularly the F/D conflict handling that was identified as needing revisiting in earlier reviews. This completes the integration of partial transaction support into the refname verification layer, a key component for the overall `--allow-partial` functionality. The patch follows the established pattern of using the transaction's rejection mechanism while maintaining the safety and performance characteristics of batch refname checking.
