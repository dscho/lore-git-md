This is the final patch in Karthik Nayak's series implementing partial reference transactions, adding the user-facing `--allow-partial` flag to `git update-ref`. The flag enables partial transaction support in stdin mode, allowing successful updates to proceed while reporting failures rather than aborting the entire transaction.

The implementation builds on the core infrastructure from earlier patches, with key components including:
- A new `print_rejected_refs()` function that formats error output for failed updates
- Integration with the transaction system's rejection iterator
- Comprehensive tests covering various failure modes (invalid OIDs, nonexistent refs, symref conflicts, etc.)
- Documentation updates explaining the flag's behavior and output format

The patch maintains the series' strong testing approach, adding 233 lines of test coverage across 8 scenarios that verify:
1. Basic partial transaction functionality
2. Handling of malformed new OIDs
3. Non-commit objects as new values
4. Nonexistent references
5. Symref edge cases
6. Invalid old OIDs
7. Refname conflicts
8. New ref creation conflicts

Error reporting follows the established format: `rejected <ref> <old> <new> <reason>`, with clear categorization of failure types through the `enum ref_transaction_error` system. The implementation enforces that `--allow-partial` can only be used with `--stdin`, maintaining the command's existing safety guarantees for direct usage.

This completes the series' goal of enabling partial reference updates while preserving atomicity where needed, providing a foundation for future integration with fetch and receive-pack operations. The extensive test coverage and careful error handling demonstrate the implementation's robustness.
