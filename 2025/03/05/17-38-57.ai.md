This is a refactoring patch that centralizes duplicate refname checking in the Git reference transaction system. It's part of a larger series (v3 2/8) about partially atomic ref updates.

The patch moves the tracking of refnames from individual backend implementations (files, packed, reftable) into the generic refs.c layer. Key changes include:

1. Adds a new `refnames` string_list field to `ref_transaction` to track all references in a transaction
2. Automatically populates this list in `ref_transaction_add_update()`
3. Removes duplicate checking code from all backends in favor of a single check in `ref_transaction_prepare()`
4. Updates backend-specific logic (like symref splitting) to use the centralized list
5. Preserves special handling for HEAD and log-only updates

The changes touch core ref transaction handling in refs.c and modify all three backend implementations (files, packed, reftable). The reftable backend requires special attention to maintain correct ordering of checks since it previously did duplicate detection after adding updates.

This centralization reduces code and makes future changes easier, though it does subtly change some timing of checks (particularly in the reftable backend). The patch appears well-constructed with thorough updates to all affected backends and preservation of existing behavior.
