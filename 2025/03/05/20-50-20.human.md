Bugfix for Git's bash completion handling of remote names with slashes. This is the second patch in a v2 series that addresses completion issues when remote names contain slashes (like "github/dseomn"). The patch builds on the first one's `__git_count_path_components()` helper to properly handle ref completion in these cases.

The main fix replaces hardcoded path stripping with dynamic component counting, ensuring commands like `git push github/dseomn :com<Tab>` correctly complete to `:completion-remote-slash` rather than incorrectly including the remote name portion. The patch includes extensive test coverage (180+ lines) across various completion scenarios, maintaining existing behaviors like case sensitivity and HEAD rules while adding support for slashed remotes.

David notes a small optimization in this follow-up - the initial version sent unnecessary refs to awk, which he'll fix in the next version by limiting the `for-each-ref` to just remote refs. The changes are well-tested and appear to handle all edge cases while maintaining compatibility across different shells and platforms. This looks like a solid improvement to a real pain point for users with slashed remote names.
