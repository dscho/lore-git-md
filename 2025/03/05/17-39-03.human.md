This is the final patch in Karthik Nayak's series implementing partial reference transactions, adding a user-facing `--allow-partial` flag to `git update-ref`. The flag allows reference updates to continue even when some individual updates fail, with failed updates reported in a standardized format.

The patch introduces the new command-line option and implements the user interface for partial transaction handling. When enabled with `--stdin`, the command will now:
- Continue processing updates after non-fatal errors (like invalid refs or incorrect OIDs)
- Report failed updates with clear error message format
- Still abort for system-level failures (I/O errors, memory issues)
- Maintain atomic behavior for F/D conflicts (directory/file reference conflicts)

The implementation includes thorough documentation updates and extensive test coverage (233 lines) verifying behavior across various error scenarios: invalid OIDs, nonexistent refs, symref handling, refname conflicts, and more. The tests demonstrate that successful updates are applied while failed ones are properly reported.

This completes the series' goal of providing controlled partial-update capability while maintaining safety for cases where atomic behavior is required. The design has evolved through several rounds of review, with consensus reached on error handling approaches and output formats.
