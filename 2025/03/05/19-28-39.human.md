This is a discussion thread about the partial reference transactions feature, specifically addressing conceptual concerns about the terminology and approach.

Junio Hamano raises an important philosophical question about the nature of the proposed `--allow-partial` flag for `git update-ref`. He points out that the current implementation frames this as "partial transactions," but questions whether this is conceptually coherent - if transactions are meant to be atomic (all-or-nothing), then allowing partial success seems contradictory. He suggests that "non-transactional batched updates" might be a more accurate description of what's being implemented.

The comment comes after the technical implementation has been thoroughly discussed and largely settled (as seen in the thread summary), indicating this is more about naming and conceptual clarity than technical objections. Hamano isn't rejecting the functionality, but is questioning whether the framing aligns with Git's existing mental models around reference updates.

This is a high-level design discussion that could influence how the feature is documented and presented to users, even if the underlying implementation remains unchanged. The thread shows how even after technical consensus is reached, conceptual clarity remains important in Git's development process.
