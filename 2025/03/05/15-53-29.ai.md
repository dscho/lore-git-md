This is a bugfix patch addressing an inconsistency in the build system's handling of deprecated commands under `WITH_BREAKING_CHANGES`. The patch fixes a mismatch where `git pack-redundant` was correctly excluded from compilation but not properly marked in `EXCLUDED_PROGRAMS`, causing the `check-docs` target to flag it as undocumented despite being intentionally removed.

The change modifies the Makefile to add `git-pack-redundant` to `EXCLUDED_PROGRAMS` when building with breaking changes, mirroring the existing logic that excludes it from `BUILTIN_OBJS`. This maintains consistency between compilation and documentation checking. The commit notes this doesn't yet address the command's presence in the `git help git` output, as that would require changes to `cmd-list.perl`.

This appears to be a straightforward follow-up to the earlier conditional documentation work, ensuring the build system fully implements the deprecation of `git pack-redundant` when configured with breaking changes. The patch is small and focused, coming from the project lead to finalize this aspect of the breaking changes implementation.
