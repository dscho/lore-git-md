This is the core implementation patch (6/8) in Karthik Nayak's series introducing partial reference transaction support to Git. The patch adds the foundational infrastructure for partial transactions, where individual reference updates can fail without aborting the entire transaction when the new `REF_TRANSACTION_ALLOW_PARTIAL` flag is set.

Key technical components introduced:
- New `rejection_err` field in `ref_update` to track per-update failure reasons
- `ref_transaction_rejections` struct to efficiently track and iterate failed updates
- Central `ref_transaction_maybe_set_rejected()` helper to mark updates as failed
- Backend modifications (files, packed, reftable) to handle partial failures
- New iterator `ref_transaction_for_each_rejected_update()` for examining failures

The implementation distinguishes between system errors (which still abort the whole transaction) and user errors (which can be skipped). The patch touches all major ref backends with consistent handling, though the reftable backend sees the most benefit from this change due to its batching characteristics.

This builds on the enum-based error system established in earlier patches and sets up the plumbing needed for the upcoming `--allow-partial` flag in `git update-ref`. The changes are comprehensive but focused, with clear separation between the core transaction logic and backend-specific implementations.
