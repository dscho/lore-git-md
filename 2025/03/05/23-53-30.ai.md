This is a follow-up proposal in the ongoing discussion about language-specific `.gitignore` support in `git init`. Oleg Taranenko suggests a middle-ground approach between the rejected built-in language support and the existing `--template` mechanism.

The email proposes a new `--only-gitignores` flag for `git init --template` that would selectively copy `.gitignore` files from the template directory while ignoring other template components. This would simplify the common use case of language-specific ignores without requiring users to understand the full template mechanism or risk unintended side effects from copying other template files. The proposal includes a safety measure to preserve existing `.gitignore` files with warnings rather than overwriting them.

This suggestion attempts to address the maintainer's neutrality concerns by working within the existing template framework while reducing complexity for the specific `.gitignore` use case. However, it still requires core changes to implement the selective copying behavior, which may face similar philosophical objections about Git maintaining awareness of `.gitignore` files as special cases. The technical implementation would need to handle directory structure preservation and conflict resolution, though these details aren't specified in the brief proposal.
