Maintainer response in the language-specific `.gitignore` templates discussion.

Junio C Hamano weighs in on the ongoing debate about adding language-specific `.gitignore` support to `git init`, responding to brian m. carlson's technical concerns. He agrees with the reservations about modifying core Git for this feature, suggesting the existing `--template` mechanism (despite its limitations) is a more appropriate solution than expanding Git's built-in capabilities. The response reinforces the architectural principle that Git should remain neutral regarding language ecosystems, and hints that any solution involving direct modification of Git's codebase to handle language-specific patterns would likely face resistance. While acknowledging `--template` has technical limitations (particularly around alternate ref formats and hash algorithms), Hamano positions it as the preferred alternative precisely because it keeps language-specific concerns outside Git's core functionality. This maintains the thread's central tension between convenience features and Git's design philosophy, with a maintainer now clearly favoring the latter.
