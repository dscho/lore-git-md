This is part 5/8 of Karthik Nayak's series implementing partial reference transaction support, focusing on refactoring error handling to use an enum-based system.

The patch replaces preprocessor-defined transaction error codes with a strongly-typed `enum ref_transaction_error` that explicitly lists all possible error conditions. The new enum includes cases like name conflicts, create-exists conditions, nonexistent refs, incorrect old values, invalid new values, and unexpected symref types. This change improves type safety and makes error handling more explicit across the codebase.

The implementation touches all major ref backends (files, packed, reftable) to convert their error handling to use the new enum. Key changes include:
- Central definition of error codes in refs.h
- Conversion of return types from `int` to `enum ref_transaction_error` for verification functions
- Consistent error categorization across all backends
- Removal of the old `TRANSACTION_*` macros

This refactoring paves the way for the partial transaction support coming in later patches by establishing a clear error classification system that can distinguish between fatal system errors and skippable user errors. The changes maintain all existing error cases while making the code more maintainable through explicit typing.

The patch follows the series' pattern of progressive refinement, with this change having been discussed and refined across multiple versions (v1-v3) based on feedback from Patrick Steinhardt and Phillip Wood regarding enum naming, scoping, and style.
