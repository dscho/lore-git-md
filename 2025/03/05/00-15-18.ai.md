This is the final version of a bugfix patch addressing object freshening behavior in multi-cruft pack scenarios. The patch modifies `builtin/pack-objects.c` to properly handle freshening objects that exist in cruft packs larger than the size threshold, ensuring we can still update their mtimes even when the original cruft pack is retained.

Key technical changes:
- Introduces `ignore_packed_keep_in_core_has_cruft` flag to track retained cruft packs
- Adds `want_cruft_object_mtime()` helper to compare mtimes of existing cruft objects
- Modifies `want_found_object()` to consider mtimes when freshening objects from retained cruft packs
- Exposes `kept_pack_cache()` in `packfile.[ch]` for the new comparison logic
- Includes comprehensive test coverage in `t/t7704-repack-cruft.sh` with scenarios for both packed and loose object freshening

The solution allows freshening objects from retained cruft packs when the new copy has a strictly greater mtime, while maintaining existing behavior for non-cruft packs. This addresses the limitation where objects in large cruft packs couldn't be freshened at all in previous versions.

The thread has reached consensus with all technical concerns resolved, and this version has been approved by reviewers after addressing earlier issues around perpetual repacking risks. The patch is now ready for integration into the main Git codebase.
