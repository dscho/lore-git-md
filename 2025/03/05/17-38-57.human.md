This is a refactoring patch that centralizes duplicate refname checking in Git's reference transaction system. It's part of a larger series (v3 2/8) working on atomic reference updates.

The patch moves the tracking of refnames from individual backend implementations (files, packed, reftable) into the generic refs.c layer. Previously, each backend maintained its own list of affected refnames to detect duplicates, leading to code duplication. Now, the `ref_transaction` struct includes a `refnames` string_list that's automatically populated when updates are added.

Key changes include:
1. Adding the new `refnames` field to track refnames across all backends
2. Removing duplicate checking code from the files, packed, and reftable backends
3. Adjusting the reftable backend to perform its checks before rather than after adding updates
4. Maintaining special handling for HEAD and symref updates while using the centralized list

The patch appears well-constructed with thorough updates to all affected backends. It simplifies the codebase by eliminating redundant implementations while preserving all existing functionality. This should make future maintenance easier as changes to refname handling can now be made in one place rather than three.
