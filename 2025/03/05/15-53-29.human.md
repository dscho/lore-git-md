This is a bugfix patch addressing an inconsistency in the build system when `WITH_BREAKING_CHANGES` is enabled. Junio Hamano noticed that while `git pack-redundant` was correctly excluded from being built, it wasn't properly listed in `EXCLUDED_PROGRAMS`, causing the `check-docs` target to complain about documentation for a removed command.

The patch fixes this by adding `git-pack-redundant` to `EXCLUDED_PROGRAMS` when `WITH_BREAKING_CHANGES` is defined, mirroring how the command is already excluded from `BUILTIN_OBJS`. This maintains consistency between what gets built and what gets checked in the documentation verification step.

The commit message notes there's still a minor issue where `cmd-list.perl` doesn't know to exclude deprecated commands from the "git help git" output when `WITH_BREAKING_CHANGES` is active, but that appears to be a separate concern not addressed by this patch.

This appears to be a straightforward fix that completes the removal of `pack-redundant` when building with breaking changes enabled. The change is minimal and focused, affecting only the Makefile. While it's a small patch, it's important for maintaining build system correctness when using the breaking changes configuration.
