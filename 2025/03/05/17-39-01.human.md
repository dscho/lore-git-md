This is part 6/8 in a series implementing partial reference transaction support in Git, allowing some updates in a transaction to fail while others succeed. The patch introduces core infrastructure changes across all ref backends (files, packed, reftable) to support this new mode.

The key addition is the `REF_TRANSACTION_ALLOW_PARTIAL` flag, which when set, enables transactions to continue processing updates even if some fail due to non-system errors (like ref conflicts or invalid OIDs). System errors still abort the entire transaction. The implementation tracks rejected updates in a new `ref_transaction_rejections` structure and provides iteration via `ref_transaction_for_each_rejected_update()`.

The changes are comprehensive, touching all ref backends to handle partial transactions consistently. The patch appears well-structured with clear error handling paths and maintains atomicity where needed. This is a foundational change that enables the subsequent user-facing `--allow-partial` flag for `git update-ref` (coming in a later patch).

The implementation follows through on the design discussed in earlier thread iterations, particularly around error classification and handling. It's a significant plumbing change that could affect many ref operations, but the careful backend-by-backend approach and comprehensive changes suggest it's been thoroughly considered.
