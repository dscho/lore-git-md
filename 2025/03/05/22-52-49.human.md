This is a maintainer response in the ongoing discussion about language-specific `.gitignore` templates for `git init`. Junio C Hamano weighs in on brian m. carlson's suggestion to use the existing `--template` mechanism rather than modifying core Git. 

Junio expresses skepticism about extending the `--template` feature beyond its original purpose (hooks and info files), though he acknowledges it as a better alternative than baking language-specific knowledge into Git itself. His comment reinforces the neutrality concerns raised earlier in the thread, suggesting the template approach - while imperfect - aligns better with Git's design principles than the proposed language-specific solutions.

The response doesn't advance new technical arguments but provides important maintainer perspective: core Git should avoid taking on maintenance of language-specific content, and existing mechanisms (even if not ideal) may be preferable to feature creep. This maintains the thread's stalemate between convenience-focused proposals and Git's minimalist philosophy.
