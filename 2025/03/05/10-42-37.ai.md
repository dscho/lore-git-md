This is a documentation patch that follows up on the already-resolved discussion about build-time conditional documentation for deprecated repository layout features. The patch implements the agreed-upon solution for hiding documentation about the deprecated `.git/branches` and `.git/remotes` directories when building with `WITH_BREAKING_CHANGES`.

The key technical change introduces a new AsciiDoc attribute `with-breaking-changes` that controls whether the deprecated feature documentation appears. The patch modifies three files to implement this: `Documentation/Makefile` and `Documentation/meson.build` to set the attribute when configured, and `gitrepository-layout.adoc` to wrap the relevant documentation in conditional blocks. The implementation uses a positive formulation (`ifndef::with-breaking-changes[]`) to avoid the awkward double negative that would result from matching the test prerequisite's current name.

This patch represents the final implementation of the solution discussed in the thread, with Phillip Wood incorporating feedback from Junio Hamano and Patrick Steinhardt to use the positive attribute name. The patch notes that a future series will rename the test prerequisite (`WITHOUT_BREAKING_CHANGES`) to match this new naming scheme. The changes are straightforward and maintain consistency with the existing build system infrastructure while properly handling the documentation of deprecated features.
