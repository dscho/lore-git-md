This is part 5/8 of a series introducing partial reference transaction support in Git, focusing on error handling improvements.

The patch replaces preprocessor-defined transaction error codes with a strongly-typed `enum ref_transaction_error`. This provides better type safety and clearer function signatures while maintaining all existing error cases. The new enum includes specific error types like name conflicts, create-exists conditions, and various validation failures (nonexistent refs, incorrect old values, invalid new values).

The changes touch all major ref backends (files, packed, reftable) to use the new enum consistently. Key improvements include:
- More explicit error handling throughout the ref transaction codebase
- Clearer function signatures showing expected error returns
- Preservation of all existing error semantics while making them more discoverable
- Better documentation of error cases via the enum definition

This refactoring lays groundwork for the partial transaction support coming in the rest of the series, where precise error classification will be important for determining which updates can proceed when others fail. The changes are mechanical but thorough, updating error handling across the entire refs subsystem.
