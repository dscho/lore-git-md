This thread addresses a regression in hash initialization that affects fetch operations when using OpenSSL 3+. The issue stems from commit 0578f1e66a ("global: adapt callers to use generic hash context helpers"), which accidentally removed necessary `->init_fn` calls, causing "invalid index-pack output" errors during fetches.

The fix, submitted by the author of the original regression, adds back the missing initialization of temporary hash contexts in both `index-pack` and `unpack-objects` commands. The changes are minimal and focused, specifically targeting OpenSSL 3+ SHA1 implementations that require proper context initialization. While the patch appears correct and well-tested, it might be worth clarifying whether this affects all OpenSSL 3+ builds or only certain configurations. The fix should restore normal fetch operations for affected users.
