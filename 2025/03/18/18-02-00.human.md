Bugfix for Git's date approximation handling of special time terms like "noon" and "tea". This is the first patch in a two-part series addressing edge cases in how `approxidate` processes date strings that combine fixed day specifications with relative time terms.

The patch fixes an issue where terms like "noon" and "tea" (5pm) would incorrectly adjust the date based on the current time, even when a specific day was provided. For example, "January 5th noon" would behave differently depending on whether it was run before or after noon. The fix modifies the date-time calculation to respect explicitly set day-of-month values when present.

The change is small (just 2 lines modified in date.c) but has clear test coverage - the patch includes a test case that verifies the behavior by artificially setting the test time to before noon. This appears to be a well-scoped fix for a specific edge case, though reviewers may want to verify it doesn't introduce any regressions in other date parsing scenarios.

The patch follows logically from the series' goal of making special date terms respect fixed day specifications, and the test demonstrates the problem being fixed. The change seems straightforward and unlikely to be controversial, though date parsing can sometimes have subtle corner cases.
