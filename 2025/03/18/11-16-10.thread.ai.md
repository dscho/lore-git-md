Bugfix addressing OpenSSL 3+ compatibility regression in hash context initialization, caused by commit 0578f1e66a ("global: adapt callers to use generic hash context helpers"). The change accidentally removed required `->init_fn` calls for temporary hash contexts in packfile operations, leading to "invalid index-pack output" errors during fetches. Jensen Huang's patch restores initialization of `tmp_ctx` in both `builtin/index-pack.c` and `builtin/unpack-objects.c` before context cloning, specifically fixing OpenSSL 3+ SHA1 implementation failures. 

Patrick Steinhardt acknowledges the fix but raises a design consideration about improving the `git_hash_clone()` helper API to potentially handle initialization requirements internally rather than requiring explicit `->init_fn` calls before cloning. This suggests a possible follow-up refactoring to make the hash API more robust against similar initialization issues, though the immediate bug remains resolved by the current patch. The discussion has expanded from a straightforward bugfix to include potential API improvements, with Patrick's suggestion opening consideration for future work on the hash helper infrastructure while maintaining the correctness of the applied fix.
