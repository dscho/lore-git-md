This is the third patch in Christian Couder's v6 promisor-remote bugfix series, focusing on hardening error handling for NULL/empty remote URLs. The patch adds explicit validation in `should_accept_remote()` to prevent potential crashes if a server stops advertising URLs, while maintaining consistent warning messages.

The key changes in this patch:
1. Adds NULL and empty string checks for `remote_url` before comparison
2. Standardizes warning messages to use uppercase "URL" consistently
3. Rejects the remote with a warning when no URL is advertised
4. Maintains the existing behavior of warning when URLs mismatch

The implementation guards against a theoretical case where servers might not advertise URLs, though the commit message notes this isn't currently an issue with existing servers. The warning messages are made more consistent while preserving their diagnostic value. This complements the earlier patches' work on NULL pointer safety and test coverage.

The changes are minimal (7 lines modified) but strategically placed in the critical URL comparison logic. This patch represents the final hardening step in the series' error handling improvements, following the test isolation foundation and core NULL dereference fixes from earlier patches.
