Refspec API cleanup (final patch in series). This is the last of Taylor Blau's refspec API modernization patches, completing the conversion from a generic initialization function with boolean parameters to fetch/push-specific variants. The patch replaces `refspec_item_init()` with `refspec_item_init_fetch()` and `refspec_item_init_push()`, following the same pattern as earlier refactoring of `refspec_init()`.

Key technical changes:
- Makes the original `refspec_item_init()` static since it's now only used internally
- Adds new public API functions with explicit fetch/push semantics
- Updates all callers in `builtin/fetch.c`, `builtin/pull.c`, and `refspec.c`
- Modifies `refspec_append()` to use the new variants based on the refspec's mode
- Maintains all existing behavior while making the API more self-documenting

The changes are mechanical but meaningful, continuing the thread's established direction of making the refspec API more type-safe and intention-revealing. This completes the refspec API modernization that was agreed upon earlier in the thread between Taylor Blau, Jeff King, and Junio Hamano. With this patch, the entire refspec API now uses fetch/push-specific variants rather than boolean parameters, and all related patches in the series have been merged.
