This is a bugfix patch addressing a regression in hash initialization for OpenSSL 3+ compatibility. The change restores missing `->init_fn` calls that were accidentally removed in commit 0578f1e66a ("global: adapt callers to use generic hash context helpers"), which caused fetch operations to fail with "invalid index-pack output" errors.

The patch makes two nearly identical changes - one in `builtin/index-pack.c` and another in `builtin/unpack-objects.c` - both adding back the initialization of a temporary hash context (`tmp_ctx`) before cloning it from another context. The issue specifically affects OpenSSL 3+ SHA1 implementations which require proper initialization of hash contexts.

The fix is straightforward and appears well-targeted, addressing a clear regression from a known commit. The error case (fetch failures) is well-documented in the commit message, though it might benefit from mentioning whether this affects all OpenSSL 3+ builds or only certain configurations. The changes are minimal and focused, touching only the necessary initialization calls in two closely related commands that handle packfile operations.
