Bugfix for date parsing behavior in `approxidate`. This is the second patch in a 2-part series.

The patch fixes an issue where time specifications like "noon today" or "noon yesterday" weren't properly overriding the day component when parsing dates. Currently, these would sometimes use the first previous noon depending on current time rather than strictly using today's or yesterday's noon.

The change modifies the `date_now` and `date_yesterday` functions to explicitly set `tm_mday = -1` before updating the time, ensuring the day component gets properly overwritten. It also adds "today" as an alias for "now" in the special date keywords.

The fix is accompanied by test updates that verify the corrected behavior, particularly around the noon edge cases. The changes are straightforward and focused, with clear test coverage for the specific issue being addressed.

This appears to be a well-justified fix for a subtle but potentially confusing behavior in date parsing, particularly for users relying on precise interpretations of "today" and "yesterday" in their workflows. The patch maintains backward compatibility while making the behavior more intuitive.
