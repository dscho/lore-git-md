This is a CI/build system patch that provides a direct fix for the Meson documentation build failures in Git's CI pipeline. The patch adds `meson` to the package installation list for the Documentation job in `ci/install-dependencies.sh`, resolving the immediate "meson: command not found" errors that were occurring during doc builds.

The change follows from Jeff King's observation of CI failures in Patrick Steinhardt's Meson docs build series, where the CI environment lacked Meson despite the test expectations. Junio Hamano's patch demonstrates this fixes the immediate issue (showing before/after CI run links), but he raises architectural questions about whether this is the right approach given the CI's dual dependency management system (distro-specific vs job-specific installations).

Key technical details:
- Modifies `ci/install-dependencies.sh` to include `meson` in the Documentation job's apt-get install list
- Preserves existing doc toolchain dependencies (asciidoc, xmlto, etc.)
- Maintains the asciidoctor gem installation check

The patch appears effective for the immediate problem but leaves open the broader question of how dependencies should properly be managed between the distro-specific and job-specific sections of the CI setup. Junio explicitly solicits input from more knowledgeable contributors about the CI architecture while providing this working solution.
