This thread addresses edge cases in Git's date approximation logic ("approxidate"), specifically focusing on how special time formats interact with explicit day specifications. The four-patch series, now in its third iteration from Tuomas Ahola, builds on a 2006 bug report from Linus Torvalds about date parsing quirks.

The first and third patches are settled: the test infrastructure improvements (1/4) and the fix for tm_mday handling (3/4) have been accepted. The fourth patch, introducing deferred adjustment for "now"/"yesterday" specials, still awaits Junio's review. The key discussion now centers on patch 2/4 regarding the "today" alias behavior. Junio clarified that the current behavior (treating "today" as equivalent to "now") was accidental rather than intentional, opening the door for Tuomas to propose a more sensible alternative that would align just the day component while preserving the current time.

Junio's latest input frames this as a design decision rather than a bug fix - while Git typically preserves existing behavior, clearly accidental cases can be corrected if the change improves semantics. He cautions that once documented, behaviors become much harder to change, so the choice between keeping the accidental behavior or adopting Tuomas's proposal requires careful consideration of what would be most intuitive for users. The discussion remains open, with the path forward for patch 2/4 now clearer but awaiting a final decision.
