Here is the updated human-mode thread summary:

This three-patch series from Tuomas Ahola fixes long-standing edge cases in Git's fuzzy date parser ("approxidate"), including bugs first reported by Linus Torvalds in 2006. The current version (v2) restructures the fix into three patches rather than two, with the first patch adding test infrastructure. The core problem is that special time keywords like "noon" and "tea" always wrap to the most recent past occurrence, even when an explicit day like "10 May" has been provided -- producing obviously wrong dates.

Patch 2/3 (now posted for review) fixes this problem with a three-line change to `date.c`: in the `date_time()` function, it checks whether `tm_mday` has already been set, and if so, skips the rollback logic. It also adds `"today"` as an alias for `"now"` as a one-line addition. The test cases cover both day-rollover sides (using the `GIT_TEST_DATE_NOW` infrastructure from patch 1/3) and demonstrate the fix working correctly regardless of morning-vs-afternoon. This is a clean, narrow fix that directly addresses the two-decade-old user-facing bug.

Patches 2/3 and 3/3 have not yet received review in this version. Patch 3/3, which fixes `tm_mday` field management for "now" and "yesterday" using a deferred-adjustment approach, answers the design questions Jeff King raised in v1. Whether King or other reviewers find the revised approach acceptable remains open.
