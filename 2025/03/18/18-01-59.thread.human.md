This thread addresses a series of fixes for Git's date approximation logic (approxidate), focusing on edge cases when special time formats like "noon" or "tea" are combined with explicit day specifications. The series has gone through four iterations, with the final patch now awaiting Junio's review.

The core issue stems from longstanding quirks in how Git handles combinations like "May 13 at noon" or "last Friday at tea time". The series establishes that "today" should mean midnight (rather than aliasing to "now"), fixes how explicit days interact with special time formats, and introduces a deferred adjustment mechanism for cases like "tea yesterday" (now correctly meaning "5pm yesterday"). 

Tuomas Ahola has implemented Junio's preferred "today=midnight" semantic and addressed all feedback, with patches 2/4 (test infrastructure) and 3/4 (core fixes) already accepted. The final patch (4/4) introduces the deferred adjustment scheme using negative day markers, which makes these combined time/day specifications work intuitively while maintaining backward compatibility. The changes are well-tested and appear ready for final review.

This work references a 2006 bug report from Linus Torvalds about date parsing quirks, and follows the project's policy that undocumented accidental behaviors (like the original "today=now") can be improved with more sensible defaults.
