This thread addresses long-standing edge cases in Git's date approximation logic ("approxidate"), particularly when special date/time formats are combined with explicit day specifications. The four-patch series, now in its third iteration from Tuomas Ahola, builds on a 2006 bug report from Linus Torvalds about incorrect handling of phrases like "one year ago yesterday at tea-time."

The core technical fixes (patches 3/4 and 4/4) are in good shape, having addressed all feedback from Junio and Jeff King. These changes prevent the system from incorrectly rolling back explicitly specified days when processing time-based specials like "noon" or "tea." The test infrastructure (patch 1/4) has also been thoroughly reviewed.

The sticking point is patch 2/4, which proposes making "today" an alias for "now." Junio has clarified that his concern isn't about implementation details but about the fundamental semantics: treating "today" as equivalent to "now" would make `--since=today` exclude all commits from earlier in the day, which contradicts user expectations. The author initially misunderstood this as an edge case rather than a design question. The patch now requires either a justification for the current behavior or a reimplementation to make "today" mean "since midnight."

While this design discussion continues, the other patches - which address real bugs in date handling - could potentially proceed independently. Jeff King has previously reviewed and approved the core fixes, and Junio has signed off on the test infrastructure changes. The series represents a meaningful improvement to Git's date parsing, with only the "today" alias remaining contentious.
