HTTP TCP keepalive configuration patch series:

This thread introduces new HTTP configuration options for fine-grained control of curl's TCP keepalive behavior through a three-patch series, addressing bandwidth-limited clone failures. The work maintains its original structure: helper function refactoring (patch 1), curl handle preparation cleanup (patch 2), and three new config options implementation (patch 3).

Patch 2/3 has been updated to remove the obsolete `set_curl_keepalive()` helper function, inlining its single remaining line of `curl_easy_setopt()` directly into `get_curl_handle()`. This cleanup is possible because Git no longer supports curl versions older than 7.25.0. The change reduces code complexity without altering functionality, touching only `http.c` (5 lines removed, 1 line added).

Key technical details remain stable:
- Static variables curl_tcp_keepidle/keepintvl/keepcnt (-1 defaults)
- Environment variables GIT_HTTP_KEEPALIVE_* override config
- Clean application in get_curl_handle()

The discussion has evolved from initial architectural approval to implementation refinements, with two main areas of focus:

1. Default value considerations: Both Patrick Steinhardt and Elijah Newren have raised questions about whether Git should use more aggressive default values than curl's defaults to better handle bandwidth-limited scenarios, building on Taylor Blau's original motivation where connection drops occurred during throttled clones. This represents the primary remaining design question.

2. Implementation polish: Patrick noted redundant type casting in config parsing (int→long promotion happens automatically), which remains an open cleanup opportunity.

The core functionality of three config options (keepAliveIdle/Interval/Count) is uncontested, with thorough documentation coverage. The thread shows converging consensus with attention on final polish details rather than fundamental design. The engagement from multiple contributors (Patrick, Elijah, Taylor) on the default values question suggests it may warrant adjustment in the current series or follow-up work. This represents the last substantive discussion point before the series can be finalized.
