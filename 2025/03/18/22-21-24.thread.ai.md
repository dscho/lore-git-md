HTTP TCP keepalive configuration patch series:

This thread introduces new HTTP configuration options for fine-grained control of curl's TCP keepalive behavior. The series consists of preparatory refactoring HTTP infrastructure followed by the feature implementation.

The preparatory work included:
1. Adding helper function `set_long_from_env()` for environment variable parsing into long integers
2. Inlining `set_curl_keepalive()` into `get_curl_handle()` and removing obsolete conditional compilation logic

The final implementation adds three new http.* configuration options in http.c with corresponding environment variables:
- `http.keepAliveIdle`/`GIT_HTTP_KEEPALIVE_IDLE` (time before first keepalive probe)
- `http.keepAliveInterval`/`GIT_HTTP_KEEPALIVE_INTERVAL` (time between probes) 
- `http.keepAliveCount`/`GIT_HTTP_KEEPALIVE_COUNT` (number of probes before closing)

The values are stored in static variables (curl_tcp_keepidle, curl_tcp_keepintvl, curl_tcp_keepcnt) initialized to -1 (use curl defaults) and applied in get_curl_handle(). The implementation maintains the series' clean separation of concerns and uses the previously introduced `set_long_from_env()` helper.

Documentation thoroughly explains each parameter's purpose and relationship to curl's underlying options. The commit message provides clear motivation with a concrete example of bandwidth-limited clones failing due to default keepalive settings. The series demonstrates careful progression from infrastructure improvements to feature implementation while maintaining code hygiene throughout.
