This is a refactoring patch that simplifies the refspec API by treating the 'fetch' field as a pure Boolean value rather than using symbolic constants. It's part of a 4-patch series that modernizes the refspec API, with this being the foundational change.

The patch removes the `REFSPEC_FETCH` and `REFSPEC_PUSH` macros that previously represented fetch/push modes, replacing them with direct Boolean values (1 for fetch, 0 for push). The `fetch` field in `struct refspec` is changed to a single-bit unsigned field to better indicate its Boolean nature. This change affects initialization calls across several files (`builtin/pull.c`, `refspec.c`, `remote.c`, `transport-helper.c`), where the symbolic constants are replaced with literal 1/0 values.

The commit notes this introduces some temporary awkwardness in calls like `refspec_item_init_or_die(&spec, refspec, 1)` where the meaning of "1" isn't immediately clear, but indicates this will be addressed in follow-up patches. The change aligns with prior discussion in the thread where Junio Hamano and Taylor Blau agreed on this Boolean simplification approach.

This is a mechanical change that doesn't alter behavior, just makes the code's intent clearer by removing what were effectively Boolean values masquerading as enums. The patch follows the thread's established direction for refspec API modernization and has already been reviewed with agreement on this approach from key participants.
