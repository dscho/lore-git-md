This is the final patch in Christian Couder's promisor-remote bugfix series, addressing case sensitivity in remote name comparisons. The patch aligns promisor-remote behavior with Git's standard configuration handling where remote nicknames are case-sensitive (unlike other parts of remote configuration).

The implementation uses `strcmp()` for remote name matching, ensuring consistency with how `remote.c` handles remote lookups via `memhash()`. Junio Hamano confirmed this matches Git's existing behavior and prevents potential security issues where case-insensitive matching could lead to confusion between differently-cased remote names.

The patch includes documentation updates to promisor.adoc explicitly stating the case sensitivity requirement. While the commit message doesn't include Junio's detailed explanation about the security implications of case-sensitive matching, Christian indicates willingness to add it if reviewers deem it valuable.

This completes the series' hardening of promisor-remote functionality, following earlier patches that fixed NULL pointer dereferences and improved configuration handling. The change maintains architectural consistency with Git's configuration system while closing a potential edge case in remote name matching.
