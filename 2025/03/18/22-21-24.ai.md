This is a cover letter for a feature patch series introducing new HTTP configuration options for fine-tuning curl's TCP keepalive behavior. The series consists of three patches: two preparatory refactoring changes followed by the main feature implementation.

The core change adds three new http.* configuration options to control curl's TCP keepalive behavior: `http.keepAliveIdle` (time before first keepalive probe), `http.keepAliveInterval` (time between probes), and `http.keepAliveCount` (number of probes before closing). These provide more granular control than the existing binary `http.keepalive` setting.

The first two patches are preparatory cleanups: introducing a helper function `set_long_from_env()` for environment variable parsing and inlining the `set_curl_keepalive()` function. The author notes the main patch currently lacks tests due to difficulty testing the low-level TCP behavior, but invites suggestions for testing approaches.

The changes are focused in http.c with corresponding documentation updates. The implementation appears straightforward, building on existing HTTP infrastructure. The lack of tests is noted as a potential area for improvement, but the changes are otherwise well-contained and motivated by giving users more control over connection behavior.
