This is a follow-up in the thread about changing `git format-patch`'s handling of commit notes. The original patch proposed using raw formatting for notes in email/mbox outputs, but Junio C Hamano identified critical flaws in the approach - it would break existing functionality by losing important metadata and protective indentation that prevents patch boundary detection issues.

Tuomas Ahola acknowledges Hamano's points, particularly about how raw formatting would remove the crucial leading spaces that prevent notes content from being misinterpreted as patch headers. He also notes he should have researched more thoroughly, referencing a similar 2017 proposal.

The exchange shows this particular approach is effectively dead - the maintainer has demonstrated concrete problems that would break existing workflows (especially with the `amlog` notes ref). Any future attempt would need to preserve both the notes source identification and the protective indentation while achieving whatever formatting goals motivated the original change. The thread now appears concluded unless someone proposes a substantially different solution.
