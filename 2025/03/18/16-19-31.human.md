CI infrastructure fix with deeper investigation into root cause.

Karthik Nayak follows up on Junio Hamano's quick fix for Meson documentation build failures by digging into why the CI setup wasn't properly installing Meson in the first place. He identifies that the `$distro` variable in `ci/install-dependencies.sh` isn't being initialized for the Documentation job because the `CI_JOB_IMAGE` environment variable is missing from the GitHub Actions workflow file.

The proposed fix adds `CI_JOB_IMAGE: ubuntu-latest` to the Documentation job's environment, which should properly trigger the distro-specific dependency installation (where Meson would naturally be included). This suggests Junio's direct Meson installation might be unnecessary if the underlying configuration issue is fixed.

The email shows good technical investigation, tracing the problem from symptom (missing Meson) through the CI script logic to its root in the workflow configuration. However, as noted in the thread, there are still open questions about the proper architectural approach to CI dependency management that this doesn't fully resolve. The patch is untested but appears logically sound for the specific issue identified.
