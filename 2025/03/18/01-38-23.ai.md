This is a technical discussion about the incremental MIDX bitmap implementation, specifically focusing on commit bitmap lookup behavior in patch 04/13 of the series.

Jeff King responds to Taylor Blau's changes to `bitmap_for_commit()` that enable recursive lookup across MIDX bitmap layers. While acknowledging the current recursive approach makes sense, he explores an alternative design using a master hash table storing (midx/pack,pos) pairs for the entire MIDX chain. Key technical points raised:
- Questions whether a single global hash table would be more efficient than recursive lookups
- Notes potential tradeoffs with lazy loading - global table would require loading all layers upfront
- Observes that current recursive approach will eventually check all layers on misses anyway
- References the planned lookup table extension that might make this optimization moot
- Characterizes the existing khash-of-commits as a temporary solution awaiting proper lookup tables

The discussion remains exploratory rather than prescriptive, with Jeff King clearly marking his thoughts as speculative ("I dunno") and acknowledging his distance from the current implementation details.
