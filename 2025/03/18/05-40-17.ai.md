This is a follow-up patch in Jeff King's series refining HEAD update behavior in Git fetches, building on the recently settled protocol v2 architecture. The patch implements the "option 1" approach previously discussed with Junio Hamano to make HEAD updates more predictable and efficient.

The key change is limiting `followRemoteHEAD` behavior to only trigger when fetching using a remote's configured refspecs (typically into refs/remotes/). This addresses two issues: efficiency (avoiding unnecessary HEAD queries) and predictability (preventing confusing cases where HEAD might or might not update depending on protocol version or refspec details). The patch removes special-case code from previous optimizations since this new approach covers those cases more cleanly.

Technical changes include:
- Adding a `do_set_head` flag when using configured refspecs
- Removing the `uses_remote_tracking()` helper function
- Updating documentation to clarify the behavior applies only to configured refspec fetches
- Adjusting test t5505 back to its pre-feature behavior
- Adding an explicit test in t5510 for the new refspec behavior

The patch maintains backward compatibility while making the behavior more consistent. It builds logically on the protocol v2 improvements merged earlier, particularly around refspec handling and HEAD update rules. The changes are well-tested and documented, with Jeff noting one test style quirk (use of "cd") that could be cleaned up separately.
