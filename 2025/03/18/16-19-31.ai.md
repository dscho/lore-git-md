CI infrastructure fix addressing Meson documentation build dependencies.

Karthik Nayak identifies the root cause of the CI failures in the Documentation job - the `$distro` variable isn't being set because the `CI_JOB_IMAGE` environment variable is missing from the GitHub Actions workflow configuration. This explains why the distro-specific dependency installation wasn't triggering, forcing Junio Hamano's workaround of adding Meson directly to the job-specific dependencies.

The proposed fix adds `CI_JOB_IMAGE: ubuntu-latest` to the Documentation job's environment in `.github/workflows/main.yml`, which should properly initialize the distro detection and handle dependencies through the standard path. This would make Junio's direct Meson installation in `ci/install-dependencies.sh` unnecessary, though the patch doesn't yet remove that change.

Key technical details:
- Root cause: Missing `CI_JOB_IMAGE` in Documentation job config
- Fix location: `.github/workflows/main.yml`
- Related files: `ci/lib.sh` (distro detection), `ci/install-dependencies.sh` (current workaround)
- Build system: GitHub Actions workflow configuration

This appears to be a genuine configuration oversight rather than an architectural issue. The fix aligns with the existing CI infrastructure design where distro-specific dependencies are handled separately from job-specific ones. The patch doesn't yet address Junio's broader questions about CI dependency management architecture, focusing instead on the immediate technical cause.
