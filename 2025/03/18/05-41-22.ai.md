Performance optimization in the protocol v2 fetch behavior series. This is the second of two follow-up patches from Jeff King refining the HEAD update behavior in fetches, building on the recently settled protocol v2 architecture.

The patch optimizes the case where `followRemoteHEAD=never is configured by avoiding the unnecessary network request for the remote HEAD reference. Previously, the code would still query the remote HEAD before checking the configuration, performing wasted work both in network overhead and local processing. The change moves the configuration check earlier in the process and adds a test verifying the optimization by checking for the absence of HEAD-related protocol traffic.

Key technical details:
- Moves the `followRemoteHEAD=never` check from `set_head()` to the caller in `do_fetch()`
- Removes now-dead code from `set_head()` since the function is only called when HEAD updates are possible
- Adds packet tracing verification in t5510 to confirm HEAD isn't requested when disabled
- Maintains all existing behavior while eliminating unnecessary work

This builds on the previous patch's simplification of HEAD update logic and represents the final refinement in the protocol v2 fetch behavior improvements. The change is straightforward with clear performance benefits and thorough test coverage. Jeff King notes the deliberate choice to remove rather than keep the redundant check in `set_head()` since it's a private function with a single caller.
