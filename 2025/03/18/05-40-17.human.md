This is a refinement to Git's fetch behavior regarding remote HEAD updates, building on recent protocol v2 improvements. Jeff King proposes limiting the `followRemoteHEAD` feature to only trigger when fetching using a remote's configured refspecs (typically into `refs/remotes/`), rather than for every fetch operation.

The change addresses two issues: efficiency (avoiding unnecessary HEAD queries) and predictability (making the behavior more consistent). Previously, fetches using explicit refspecs could sometimes update HEAD depending on protocol version and what refs were advertised, creating confusing edge cases. The patch simplifies this by only considering HEAD updates during full remote fetches.

The implementation removes some special-case code from earlier fixes since this new approach covers those cases more cleanly. It includes documentation updates and test adjustments to verify the new behavior, including a new explicit test case in t5510. The change maintains backward compatibility while making the rules more straightforward - HEAD updates now only happen when fetching a remote's configured refspecs, not during direct ref fetches or exact-OID fetches.
