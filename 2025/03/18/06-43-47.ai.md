Performance optimization patch review in the MIDX bitmap series.

This email contains Elijah Newren's review of patch 11/13 in Taylor Blau's MIDX bitmap series, focusing on the type-level bitmap tracking infrastructure. The patch introduces arrays to store each layer's type bitmaps (commits, trees, blobs, tags) in preparation for combining them via `ewah_or_iterator`. 

Newren identifies a minor documentation issue in the code comments, suggesting two small wording improvements: removing a redundant "either" and an unnecessary comma in the explanation of the bitmap array structure. The feedback is purely editorial - the technical approach of maintaining per-type bitmap arrays for layer combination remains uncontested. 

This continues the pattern of the series receiving only minor nit-level feedback at this stage, with the core architecture and implementation having been thoroughly reviewed in earlier rounds. The changes align with the established design where each MIDX layer maintains its own type-level bitmaps that will be OR'ed together during operations.
