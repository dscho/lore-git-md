This is the final patch in a refactoring series that modernizes Git's refspec API, completing the transition from a generic initialization function to fetch/push-specific variants.

The patch replaces the generic `refspec_item_init()` function with two specialized versions: `refspec_item_init_fetch()` and `refspec_item_init_push()`. This follows the same pattern as earlier changes in the series that split the higher-level `refspec_init()` function. The change updates all callers across `builtin/fetch.c`, `builtin/pull.c`, and `refspec.c` to use the new variants.

The motivation is to make the API more self-documenting by eliminating boolean parameters in favor of clearly named functions. This continues the thread's established direction of simplifying the refspec API after earlier agreement between Taylor Blau, Jeff King, and Junio Hamano. The change is mechanical and maintains all existing behavior while improving code clarity.

This patch represents the conclusion of the refspec API modernization effort that began with boolean simplification and typed initialization variants. With all technical discussions resolved and all patches merged, this series has successfully improved both the clarity and maintainability of Git's refspec handling code.
