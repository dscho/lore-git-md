Core problem: Current approxidate handling has multiple issues when processing special date/time strings with explicit day components:
1. Ignores day-of-month with special date strings (e.g., "last week 15th" dropped "15th")
2. Inconsistent tm_mday field setting for "now"/"yesterday" calculations
3. Incorrect day rollover for time-based specials ("noon", "tea") when combined with explicit days -- the "most recent" rollback fires even when a specific day was explicitly provided, producing a contradictory date (e.g., "10 May at tea" on 2026-05-12 11:00 yields 2026-05-09 instead of 2026-05-10)
4. Month/year rollover edge cases when processing dates near boundaries with time-based specials

- Patch 2/3: in the `date_time()` function, checks whether `tm_mday` has already been set to a non-negative value (meaning a specific day was provided) and if so, skips the "most recent" rollback logic entirely. This is a three-line change to `date.c`. Also adds `"today"` as an alias for `"now"` in the specials table, so that inputs like "today at noon" parse correctly (one-liner via existing alias infrastructure). Test additions: "today at noon", "last Friday at noon" (twice, at offset 0 and at -12 hours to cover morning-vs-afternoon edge case), and "January 5th noon pm" at the -12 offset. These demonstrate the fix works regardless of current time of day.
- Patch 3/3: introduces a deferred-adjustment scheme for the "now" and "yesterday" specials, using negative `tm_mday` values as markers resolved later by `update_tm()`. When "now" or "yesterday" is encountered, `tm_mday` is set to -1 instead of being immediately filled in from the current clock. In `date_time()`, the old rollback logic is replaced by setting `tm_mday = -2`. Crucially, because resolution happens late, if an explicit day-of-month was provided elsewhere in the input string, it overwrites the negative sentinel and the rollback is suppressed entirely. This makes "tea yesterday" work correctly rather than going to the last tea-time and then subtracting another day. Also removes the `now` parameter from `date_time()` and marks corresponding parameters in callers as unused. Three test cases added: "noon today" at an offset crossing a month boundary, "noon yesterday" at -12 hours offset, and "tea last saturday" at both offset 0 and -12 hours. 25 lines changed in date.c, 4 lines in test file.
