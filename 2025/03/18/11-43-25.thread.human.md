This thread has progressed from initial discussions about the limitations of `core.commentString=auto` to concrete planning for its deprecation. The feature, originally added as a workaround for message washing inconsistencies, has proven problematic in several contexts including commit templates, rebase operations, and revert commands.

Key participants Junio Hamano, Phillip Wood, and Oswald Buddenhagen have reached consensus that deprecation is the right path forward. Phillip has proposed a detailed transition plan involving runtime advice messages (configurable via `advice.autoCommentStr`), documentation updates, and conditional compilation with `WITH_BREAKING_CHANGES`. While Junio agrees with most of the proposal, he questions whether treating "auto" as an error when breaking changes are enabled is necessary, suggesting it could instead be interpreted as a literal string value.

The remaining open questions are now quite focused: the exact handling of the "auto" value in the breaking changes mode, and some finer points about message wording and configuration defaults. The technical specifics under discussion involve `builtin/commit.c`, BreakingChanges.adoc, and the proposed new configuration options. With Junio's general approval of the deprecation direction, the thread appears to be moving toward final implementation decisions.
