Bugfix for OpenSSL 3+ compatibility in index-pack and unpack-objects.

This patch restores a missing `->init_fn` call that was accidentally removed in commit 0578f1e66a ("global: adapt callers to use generic hash context helpers"). The omission was causing "invalid index-pack output" errors during fetch operations when using OpenSSL 3+ for SHA1 hashing.

The fix is straightforward - it simply adds the missing initialization call in both `index-pack.c` and `unpack-objects.c` right before cloning the hash contexts. The changes are minimal and focused, touching only two lines total across both files.

The patch appears well-targeted and necessary, addressing a clear regression introduced by earlier refactoring. Since it fixes a functional breakage that affects fetches, it seems like a candidate for quick inclusion in maintenance releases. The commit message could perhaps be more detailed about the exact failure scenario, but the essential information is present.
