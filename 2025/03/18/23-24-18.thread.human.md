This thread documents the ongoing effort to integrate Rust crates for libgit functionality while maintaining compatibility across platforms, particularly addressing Windows-specific challenges. The original 5-patch series established a complete solution for packaging Rust crates with libgit, implementing build isolation, parallel compilation, and crates.io publication requirements. However, the symlink-based approach in patch 2/5 has proven problematic on Windows.

Junio Hamano has engaged with Josh Steadmon's investigation of alternatives, showing openness to a root-level Cargo.toml file if it aligns with existing build configuration practices. The discussion currently centers on testing a Cargo workspace approach as a potential solution that might satisfy both technical requirements and platform constraints. If this proves unworkable, Steadmon has proposed two fallback options: temporarily limiting to source builds (the preferred interim solution) or moving crates to separate repositories with Git as a submodule (following the zlib-sys pattern).

The thread reflects a pragmatic approach to platform limitations while maintaining the project's architectural goals. Hamano's response suggests viewing option #1 source-build limitation as a temporary measure to build momentum for Rust integration effort, leaving open the possibility of more substantial changes if the initiative gains traction. The technical discussion remains focused on finding a solution that preserves both functionality and project cleanliness, with Windows compatibility as the key outstanding challenge.
