This thread explores build system solutions for the libgit-sys Rust crate as part of Git's Rust integration. The discussion began with Josh Steadmon's v1 series proposing a symlink-based approach that required worktree cleanup, then evolved to consider building artifacts in Cargo's working directory to avoid source tree pollution. The core challenge balances four requirements: proper build configuration, source access, parallel compilation support, and crates.io size constraints.

Phillip Wood recently suggested that Meson's native out-of-tree build capabilities could offer a cleaner solution, though this would depend on Git's experimental Meson integration maturing further. The thread shows active technical evolution, with the symlink/cleanup approach being reconsidered in favor of alternatives that minimize workflow disruption while maintaining the series' packaging goals. All proposed changes remain confined to contrib/libgit-sys/, keeping core Git functionality unaffected. The discussion continues to weigh implementation tradeoffs before a v2 submission.
