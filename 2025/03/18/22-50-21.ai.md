This is part of the refspec API refactoring series, specifically converting the boolean-based initialization to typed variants. The patch replaces the generic `refspec_init()` function with two specialized versions - `refspec_init_fetch()` and `refspec_init_push()` - to make the intent clearer at call sites.

The change is mechanical but meaningful, eliminating the need for boolean parameters in favor of self-documenting function names. It updates all callers across `refspec.c`, `remote.c`, and `transport-helper.c` to use the new variants. The implementation uses `REFSPEC_INIT_FETCH` and `REFSPEC_INIT_PUSH` constants to initialize the structs, maintaining the same behavior as before but with clearer semantics.

This follows the earlier foundational patch that converted the `fetch` field from an enum to a simple 1/0 boolean, and represents a logical next step in making the API more type-safe and self-documenting. The changes are straightforward and maintain all existing behavior while improving code clarity.
