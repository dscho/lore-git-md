Performance optimization for bundle-uri reference handling, part of a series addressing fetch negotiation improvements. This patch expands the reference copying from just `refs/heads/` to all `refs/` namespaces while preserving hierarchy, moving bundled references to `refs/bundles/` (e.g., `refs/heads/topic` → `refs/bundles/heads/topic`). The change improves subsequent fetch negotiation by including more references, though the commit message doesn't quantify the expected improvement (the thread context notes prior measurements showed 32% to 1% object download reductions).

The implementation is minimal - just changing the `skip_prefix` check in `bundle-uri.c` from "refs/heads/" to "refs/" - but requires extensive test updates in `t/t5558-clone-bundle-uri.sh` to accommodate the new reference hierarchy. Tests cover path-based and HTTP bundles, bundle lists, failure modes, and non-default hash algorithms, all now verifying the new `refs/bundles/heads/` prefix structure.

Key technical details for future reference:
- Core change: `skip_prefix(refname->string, "refs/", &branch_name)` in bundle-uri.c
- Test updates: 172 line changes in t5558, all adjusting expected ref paths
- Preserved behaviors: HTTP/S handling, bundle lists, failure modes, hash algorithms
- Hierarchy: All original ref namespaces (heads, tags, etc.) maintain structure under refs/bundles/

This is the first of two patches in v3, with the second patch specifically handling tags. The series has already incorporated feedback from prior rounds, including Stolee's suggestions about patch organization, and appears technically sound based on the extensive test coverage.
