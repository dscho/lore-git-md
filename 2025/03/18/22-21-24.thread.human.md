This thread discusses a patch series introducing HTTP configuration options for fine-grained control of curl's TCP keepalive behavior, aimed at addressing connection drops during bandwidth-limited clones. The three-part series has evolved through review, with patch 2 recently simplified by removing an obsolete helper function, and patch 3 now being the focus of final refinements.

The core functionality is uncontested - the series will expose curl's TCP keepalive parameters (keepAliveIdle, keepAliveInterval, keepAliveCount) through Git config, with environment variable overrides. However, an important discussion has emerged about whether Git should use more aggressive default values than curl's defaults to better handle bandwidth-limited scenarios, as originally demonstrated by Taylor Blau's reproduction of connection drops during throttled clones. Both Patrick Steinhardt and Elijah Newren have raised this consideration, suggesting it may need addressing either in this series or a follow-up.

The only other remaining question involves minor implementation cleanups in the config parsing code. With the architectural decisions settled and the documentation thorough, the thread appears to be in its final polishing phase before the series can be considered ready for merging.
