Refactoring patch for HTTP keepalive configuration series.

This is the second patch in a three-part series preparing the HTTP codebase for new TCP keepalive configuration options. It inlines the `set_curl_keepalive()` function into `get_curl_handle()` since the function has become trivial after recent changes. The patch notes that we no longer need the conditional compilation that originally justified having a separate function, as Git now requires curl 7.25.0 or newer (which standardized the `CURLOPT_TCP_KEEPALIVE` option).

The change is straightforward - replacing a one-line function call with its direct implementation. This continues the series' pattern of cleaning up the HTTP code before introducing new functionality. The patch maintains the same behavior while making the curl handle setup more self-contained. 

This appears to be a well-justified refactoring that follows good software engineering practices - simplifying the code before extending it. The commit message provides clear historical context about why the change is safe to make now. The diff is minimal and focused, touching only the intended functionality.
