Review feedback on notes formatting patch.

Brian Carlson responds to Tuomas Ahola's patch proposing to change `git format-patch` to use raw formatting for commit notes in email outputs. While not opposing the change outright, Carlson finds the current justification ("doesn't make a very good fit") too vague to properly evaluate the proposal. 

The reviewer suggests the commit message should clearly explain: (1) what specific problems exist with the current pretty-printed format in email contexts, and (2) concrete benefits the raw format would provide. Carlson speculates the motivation might relate to prefix formatting making notes harder to use as patch explanations, but emphasizes this is just a guess - the patch author should properly document the rationale.

This is constructive criticism rather than rejection, with the reviewer (who notes limited personal experience with the notes subsystem) asking for the kind of technical detail that would help others assess the change. The response maintains a helpful tone while pushing for more rigorous justification of a change affecting core formatting behavior.
