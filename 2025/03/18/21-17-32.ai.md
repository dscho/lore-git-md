This is a discussion about commit note formatting in `git format-patch` output. Junio C Hamano responds to Tuomas Ahola's patch that proposed using raw formatting for notes in email/mbox outputs (CMIT_FMT_EMAIL and CMIT_FMT_MBOXRD). 

Hamano demonstrates concrete problems with the proposed change by showing how it would break existing functionality when using notes containing email metadata (specifically the `amlog` notes ref). The raw formatting causes loss of both the notes source indication ("Notes (amlog):" header) and crucial leading whitespace that prevents false patch detection. This would make the output ambiguous and potentially corrupt patches when notes contain lines that look like patch headers.

The response effectively vetoes the change in its current form, noting it would unconditionally break existing workflows. While not rejecting the original motivation outright, Hamano shows the implementation needs more careful consideration of edge cases, particularly around email metadata preservation and patch boundary detection. The critique suggests any future version would need to address these specific failure modes while maintaining backward compatibility.

Key technical details for future reference: the patch modified log-tree.c to treat email/mbox formats like userformat for note display, but this caused problems with the `amlog` notes ref's Message-Id storage. The raw format strips both the notes source label and protective indentation that prevents false patch header detection.
