This is a bugfix patch addressing date parsing behavior in Git's approxidate functionality. It's the second patch in a two-part series (though we don't have context of the first patch).

The patch fixes how Git handles "now"/"today" and "yesterday" date specifications, ensuring they always refer to the actual current or previous day rather than potentially being influenced by the current time. The key change is setting `tm->tm_mday = -1` in both the `date_now` and `date_yesterday` functions, which forces the date calculation to use the full day rather than partial time calculations. This affects cases like "noon today" which previously could resolve to a different day depending on when the command was run.

The changes include:
1. Modifying the `date_now` and `date_yesterday` functions in date.c to reset tm_mday
2. Adding "today" as an alias for "now" in the special date keywords table
3. Updating the test suite to verify the fixed behavior, particularly around noon calculations
