This is a follow-up discussion about test isolation improvements in Christian Couder's promisor-remote bugfix series (now at v6). The email responds to Junio Hamano's review of test cleanup ordering in the test script, where cleanup commands should be placed before operations that might fail.

Christian agrees with Junio's observation that `test_when_finished` cleanup for clone operations should be placed before the clone attempt, not after, since failed clones wouldn't execute the cleanup. He notes this change has been implemented in v6, along with additional hardening: all tests in the script now arrange cleanup before cloning, and two additional tests gained client directory cleanup to prevent pollution of subsequent tests.

The changes are minor refinements to the already comprehensive test coverage in this series, which addresses NULL pointer dereferences and configuration validation in promisor remotes. The discussion shows careful attention to test robustness, with Christian proactively extending the cleanup pattern beyond just the specific cases Junio noted. These changes don't affect the core functionality fixes but demonstrate the series' attention to detail in test hygiene.
