Feature implementation for HTTP TCP keepalive configuration, completing the preparatory refactoring series.

This final patch in the series introduces three new HTTP configuration options to control TCP keepalive behavior: `http.keepAliveIdle` (time before first probe), `http.keepAliveInterval` (time between probes), and `http.keepAliveCount` (probes before closing). Each has a corresponding environment variable override (GIT_HTTP_KEEPALIVE_*). The changes allow users to fine-tune keepalive behavior when default values cause issues, particularly in low-bandwidth scenarios where connections might be prematurely terminated.

The implementation stores the values in static variables (curl_tcp_keepidle, curl_tcp_keepintvl, curl_tcp_keepcnt) initialized to -1 (use curl defaults), then applies them in get_curl_handle() if set. The patch follows the pattern established in earlier preparatory work, using set_long_from_env() for environment variable parsing and maintaining the series' clean separation of concerns.

Documentation is thorough, explaining each parameter's purpose and relationship to curl's underlying options. The commit message provides clear motivation with a concrete example of bandwidth-limited clones failing due to default keepalive settings. This completes the series' goal of giving users control over TCP keepalive behavior while maintaining the codebase improvements from earlier patches.
