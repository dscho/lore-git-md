This is a refactoring patch that introduces a new compiler utility macro as part of an ongoing effort to handle false positives from the `-Wunreachable-code` warning. 

Junio Hamano proposes adding a `NOT_CONSTANT()` macro to explicitly tell compilers not to optimize out certain expressions that might otherwise be treated as constants. The immediate motivation comes from handling `sigfillset()` calls where compilers might incorrectly assume the function can't fail, potentially optimizing away related error checking code.

The patch demonstrates converting one such case in `run-command.c` from an explicit `errno` check to using the new macro. The change is accompanied by new infrastructure including a source file in a new `compiler-tricks/` directory and updates to both Makefile and meson build systems.

This appears to be a well-considered change that follows Git's pattern of using descriptive macros (like `UNUSED`) to document intentional code patterns to the compiler. The patch is part of a series (position 2/3) exploring how to handle `-are-unreachable` warnings, though the cover letter context isn't provided here. The implementation looks clean with proper build system integration and a focused change to demonstrate usage.
