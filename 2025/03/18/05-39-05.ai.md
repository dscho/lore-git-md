This is a follow-up to the protocol v2 fetch behavior improvements, focusing on refining the `followRemoteHEAD` logic. Jeff King proposes two patches building on the recently merged `jk/fetch-ref-prefix-cleanup` series:

1. The main change limits `followRemoteHEAD` updates to only occur when using the repository's configured refspecs, implementing the simpler "option 1" approach previously discussed with Junio Hamano. This makes the behavior more predictable by avoiding HEAD updates during direct ref fetches or exact-OID fetches.

2. A performance optimization that skips querying the remote HEAD entirely when `followRemoteHEAD` is explicitly set to "never", avoiding unnecessary protocol overhead.

The patches touch documentation, core fetch logic, and add verification tests. Jeff notes an interesting edge case with `git fetch origin HEAD` that currently doesn't update the remote HEAD ref, but leaves this behavior unchanged for now as it's orthogonal to the current changes. The changes appear well-contained, building logically on the recently settled protocol v2 architecture while maintaining backward compatibility where needed.
