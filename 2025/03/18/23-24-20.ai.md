This is the second patch in a series addressing build issues with the libgit-sys Rust crate, specifically focusing on enabling `cargo package` compatibility. The patch introduces a `git-src` symlink in the crate root to point to the Git repository, which gets flattened during packaging. This allows the build script to locate and execute the Makefile from the packaged source. 

A notable side effect is that the build process now requires cleaning the Git worktree after building, as Cargo enforces that build scripts don't modify source files. The patch adds a `PRESERVE_LIBGIT_TARGET` Makefile variable to control this cleanup behavior, though the default remains to clean the worktree. The author acknowledges this is undesirable but currently necessary, and suggests a potential alternative involving temporary copies of the worktree (with tradeoffs around disk space usage and portability).

Technical changes include adding the symlink, modifying the build.rs script to use it, and updating the Makefile to support the new cleanup behavior. The patch affects build configuration files in contrib/libgit-sys/ and the main Makefile. This appears to be a technically sound solution to the packaging problem, though the forced worktree cleanup may be controversial as noted in the cover letter. The changes are confined to build infrastructure and don't impact core Git functionality.
