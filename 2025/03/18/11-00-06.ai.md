Bugfix for promisor-remote NULL pointer dereference when remote URL is missing, part of Christian Couder's v6 series addressing promisor-remote configuration validation. This patch specifically prevents segfaults when pushing NULL or empty URLs into strvecs by skipping such entries entirely, while maintaining consistency with Git's handling of missing/empty URLs elsewhere.

The changes in promisor-remote.c replace git_config_get_string() with git_config_get_string_tmp() for cleaner memory management and add explicit checks for NULL/empty URLs before populating the strvecs. The patch includes three new test cases in t5710 that verify behavior with:
1. Missing URL configurations
2. Unset URLs on the server
3. Empty URLs (treated equivalently to missing)

The implementation aligns with Git's architectural principle of rejecting invalid configurations rather than handling edge cases, as established in earlier thread discussion. Test coverage is expanded to validate these scenarios while maintaining the series' focus on robust error handling. The changes build on Jeff King's earlier input about strvec behavior and complete the NULL-dereference protection started in previous iterations.

- Uses git_config_get_string_tmp() instead of git_config_get_string()
- Skips strvec_push() for NULL/empty URLs
- New test cases cover missing/unset/empty URL scenarios
- Maintains consistency with Git's remote URL handling conventions
