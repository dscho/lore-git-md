This is the final patch in Christian Couder's promisor-remote bugfix series, addressing case sensitivity in remote name comparisons. The patch aligns promisor-remote behavior with Git's standard configuration parsing rules where remote nicknames are case-sensitive (e.g., "Origin" and "origin" are treated as distinct remotes).

The change replaces case-insensitive comparison with `strcmp()` to match how Git's core remote handling works, preventing potential confusion if a promisor remote specifies a differently-cased name than what's locally configured. The promisor.adoc documentation is updated to explicitly state this case sensitivity.

Junio Hamano confirmed the technical rationale, noting that using case-insensitive matching could lead to mismatches between promisor remote names and actual configured remotes. Christian indicates he's happy to incorporate Junio's more detailed explanation into the commit message if others think it would be helpful.

This completes the v6 series which has already addressed NULL pointer dereferences, configuration validation, and now case sensitivity - all with comprehensive test coverage and improved test isolation following earlier review feedback. The series appears ready for inclusion in Git 2.49.0.
