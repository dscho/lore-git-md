Performance optimization for protocol v2 fetch behavior. This is the second of two follow-up patches refining HEAD update behavior in `git fetch`, building on the recently settled protocol v2 architecture.

The patch optimizes the case where `followRemoteHEAD` is set to "never" by avoiding unnecessary network requests for the remote HEAD reference. When this config is active, Git no longer asks the server for its HEAD at all, saving both network bandwidth and client-side processing. The change moves the `followRemoteHEAD` check earlier in the logic flow and adds a packet trace test to verify the optimization works as intended.

Jeff King notes this is a small but clear win - eliminating both the network request and some client-side processing that would otherwise be wasted. The implementation removes now-dead code from `set_head()` since the check is now performed earlier. The accompanying test confirms the optimization by checking the protocol trace for absence of HEAD requests when `followRemoteHEAD=never`.

This change fits logically with the recent series of protocol v2 fetch improvements, particularly the HEAD update refinements that established clearer rules about when remote HEAD should be consulted. The patch maintains all existing behavior while making the "never" case more efficient.
