HTTP infrastructure refactoring (part of TCP keepalive configuration series).

This is the second patch in a three-part series preparing the HTTP code for new TCP keepalive configuration options. It inlines the `set_curl_keepalive()` function into `get_curl_handle()` since the function's conditional compilation logic is no longer needed after Git dropped support for curl versions older than 7.25.0. The change is straightforward - replacing the function call with its single-line implementation that sets `CURLOPT_TCP_KEEPALIVE`.

The patch continues the series' clean-up work by removing now-unnecessary abstraction layers before introducing new keepalive configuration options. The modification is limited to http.c and maintains the existing behavior while making the code more direct. This follows the first patch's pattern of simplifying infrastructure before adding new features.

Key technical details for future reference:
- Removes the `set_curl_keepalive()` wrapper function
- Directly sets `CURLOPT_TCP_KEEPALIVE` in `get_curl_handle()`
- Builds on previous curl version requirement changes (f7c094060c)
- Maintains identical TCP keepalive behavior
- Prepares for upcoming http.* keepalive configuration options

The change is well-justified and follows good refactoring practice by removing obsolete indirection. It demonstrates careful attention to the HTTP subsystem's evolution and sets up cleaner code for the main feature implementation to follow.
