This is the final patch in a series improving cruft pack handling in `git repack`, introducing the new `--combine-cruft-below-size` option. Junio Hamano provides a documentation review, noting that while the new option's behavior is clearly explained, it should explicitly state that the size parameter is measured in bytes (like the related `--max-cruft-size` and `--max-pack-size` options) for consistency.

The patch follows four preparatory patches that reorganized test infrastructure and transitioned away from the problematic `--max-cruft-size` behavior. The new option allows selectively combining small cruft packs while leaving larger ones untouched, addressing repository maintenance scenarios where repeatedly repacking large cruft packs would be inefficient.

The review is minor in nature, focusing on documentation clarity rather than implementation concerns. Since this completes a well-structured series that has already addressed test coverage and backward compatibility in earlier patches, this final tweak appears to be the last step before the changes can be merged. The attention to detail in both the implementation and documentation suggests this will be a robust addition to Git's maintenance tools.
