This is a documentation patch in an ongoing discussion about clarifying the behavior of `core.commentString=auto`. The thread reveals some disagreement about how specific the documentation should be regarding the automatic comment character selection.

Oswald Buddenhagen pushes back against keeping the documentation vague, arguing that the feature is effectively useless without documenting which characters might be selected. He also clarifies that the current implementation makes it literally impossible to include comments from hooks or templates when using "auto" mode, contrary to Junio Hamano's initial interpretation.

The discussion reveals deeper concerns about the feature itself - Buddenhagen considers it a "mis-feature" that was introduced as a workaround for inconsistent message washing behavior between different commit methods. While he suggests the feature should ideally be removed, he pragmatically focuses on improving its documentation to help users recognize its limitations.

The patch appears well-considered but touches on a feature that may have deeper design issues. The discussion shows maintainers have different perspectives on how much implementation flexibility should be preserved in the docs versus providing clear user guidance.
