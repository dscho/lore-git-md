This is a refactoring patch that introduces a new compiler utility macro as part of ongoing work to handle -Wunreachable-code warnings more cleanly. The patch adds a NOT_CONSTANT() macro to explicitly tell compilers not to optimize out certain expressions that might otherwise be treated as constants, particularly in cases like sigfillset() where we want to preserve error checking even when the compiler thinks the call can't fail.

The macro is implemented via a new compiler-tricks/not-a-constant.c file (though there's a note about a naming inconsistency in the 'next' branch where it's called not-constant.o). The main use case shown is replacing an errno check pattern with a more direct NOT_CONSTANT() wrapper around the function call. The change affects several build system components (Makefile, meson.build) and modifies run-command.c to use the new macro.

This appears to be a thoughtful addition to Git's compiler compatibility layer, providing a more maintainable way to handle cases where we need to override compiler optimizations for correctness. The patch is part of a series (position 2/3) and builds on previous discussion about managing -Wunreachable-code warnings. The implementation looks clean with appropriate documentation in the commit message about the motivation and expected usage patterns.
