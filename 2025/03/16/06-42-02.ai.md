This is the final patch in a 3-part series introducing safer alternatives to assert() in Git's codebase. The patch systematically replaces assert() calls with BUG_IF_NOT() in cases where the compiler cannot verify the assertions are side-effect free, as identified by the CI detection infrastructure added in patch 2.

The changes touch several key subsystems:
- Merge machinery (merge-ort.c, merge-recursive.c) - replaces assertions about conflict types and trivial merge conditions
- Object storage (object-file.c) - converts a filter check assertion
- Parallel checkout - updates an eligibility check
- Scalar and sequencer - replaces fsmonitor support and commit option validation assertions

Each change is a straightforward mechanical conversion maintaining the same logical checks but ensuring they execute in production builds. The diff shows 9 total changes across 7 files, all following the same simple pattern of replacing assert() with BUG_IF_NOT() while keeping the exact same condition expressions.

This completes the series' goal of introducing runtime safety for assertions that might have side effects, building on the BUG() infrastructure. The changes are minimal and focused, with the merge and object storage subsystems seeing the most significant updates.
