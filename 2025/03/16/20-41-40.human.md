Documentation update clarifying Linux's arc4random implementation.

Junio C Hamano follows up on the discussion about Linux's arc4random implementation in glibc, agreeing with Brian Carlson's assessment that it's merely a wrapper around getrandom() with no security or performance benefits. The patch proposes two changes:

1. Updates the Makefile comment to explicitly warn that glibc's arc4random is not the "true" BSD-style implementation but rather a getrandom wrapper, suggesting users should prefer getrandom directly on Linux systems.

2. Adds a note in config.mak.uname's Linux section cautioning against using arc4random on glibc systems, though leaves the CSPRNG_METHOD empty rather than hardcoding getrandom as the default.

The patch appears well-considered, building on the technical discussion that revealed Linux's arc4random doesn't provide the fork-safety or performance characteristics of BSD counterpart. This documentation update helps prevent users from making suboptimal configuration choices while avoiding any breaking changes to existing behavior. The changes are focused and clearly motivated by the preceding technical analysis.
