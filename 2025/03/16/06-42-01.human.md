This is the second patch in a 3-part series introducing safer alternatives to assertions in Git's codebase. The patch adds CI infrastructure to detect potentially dangerous assertions that might have side effects.

The core of the patch is a new CI script `check-unsafe-assertions.sh` that uses a clever compiler technique to flag assertions containing function calls. The technique, contributed by Bruno De Fraine and placed in the public domain, redefines `assert()` during static analysis builds to reference an undefined symbol, causing compilation to fail for assertions that might have side effects. The script then provides helpful output showing the problematic assertions and suggesting they be replaced with the new `BUG_IF_NOT()` macro introduced in the first patch.

The patch currently flags 9 assertions across several key subsystems including merge machinery (`merge-ort.c`, `merge-recursive.c`), object storage (`object-file.c`), and parallel checkout. While these assertions appear side-effect-free to human inspection, they involve function calls that make them too complex for the compiler to verify automatically. The implementation has been reviewed by Junio Hamano and brian m. carlson, who confirmed it works reliably across GCC, Clang and MSVC. The patch is part of a well-motivated effort to make Git's assertion handling more robust, with all technical and licensing concerns already addressed in the thread.
