Documentation patch correcting outdated information about `git restore -p`.

This is a straightforward documentation update removing a note that incorrectly stated `git restore -p` couldn't handle pathspecs. Adam Johnson explains that since Git 2.34 (commit 0527ccb1b5), the underlying `add -i` implementation (which powers `restore -p`) has supported pathspecs. He verified this through bisection.

The patch simply removes three lines from git-restore.txt that warned about this limitation. Johannes Schindelin reviews the change, confirming the reasoning is sound and the patch is correct. This appears to be a clean, uncontroversial update to bring the docs in line with actual behavior that's been working for years.

The change is small but useful - it removes potentially confusing documentation that might lead users to avoid a perfectly valid usage pattern. The patch is well-researched (with specific commit references) and has already received positive feedback from a core contributor.
