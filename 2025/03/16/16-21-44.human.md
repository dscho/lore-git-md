This is a bugfix patch in the gitk GUI tool, addressing external diff functionality for renamed files. It's the third version of a series that fixes how gitk handles file paths when showing diffs of renamed files through an external diff tool.

The patch corrects a case where gitk would fail to properly locate renamed files when launching an external diff viewer, regardless of whether the user selected the original or renamed filename in the interface. The solution involves parsing "rename from"/"rename to" markers from the diff output to correctly identify both file versions.

Johannes Sixt has picked up the patch for review but notes it will take some time to examine in detail. He provides feedback on the commit message style, pointing out that it should avoid bullet points, use present tense for current behavior, and imperative mood for changes (the standard Git project style).

The patch appears to be technically sound, having evolved through three versions with improvements based on earlier feedback. It's a focused fix that maintains the existing external diff interface while correcting the path resolution logic for renamed files. The change should benefit users who rely on gitk's external diff functionality when working with renamed files.
