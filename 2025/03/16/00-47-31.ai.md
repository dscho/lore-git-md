Documentation patch correcting outdated information about `git restore -p` behavior.

This is a straightforward documentation update removing a note that incorrectly stated `git restore --patch` couldn't handle pathspecs. The patch explains that since Git 2.35 (commit 0527ccb1b5), the underlying `add -i` implementation (which powers the interactive mode) has supported pathspecs, making the note obsolete. The author verified this through bisection.

The change removes three lines from git-restore.txt that warned users the `--patch` option couldn't accept pathspecs. Johannes Schindelin reviews the patch, confirming the reasoning is sound and the change is correct, indicating it's ready for inclusion. The patch is version 2 of a series, with the revision primarily improving the commit message formatting rather than changing the technical content.

Key technical details for future reference: the change affects only documentation, specifically the `--patch` section of git-restore.txt. The behavior being documented relates to the interaction between `restore -p` and the built-in `add -i` implementation. The original limitation stemmed from the Perl implementation of `add -i`, which was replaced by the current C implementation in 2021.
