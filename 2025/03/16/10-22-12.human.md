This is a follow-up discussion on a git-gui patch that adds support for custom comment characters in commit messages. Johannes Sixt is responding to Oswald Buddenhagen's implementation, which modifies git-gui to respect core.commentChar and core.commentString configurations rather than hardcoding '#' as the comment character.

The key points in this response:
1. Johannes approves of the technical approach, particularly noting the proper handling of both commentChar and commentString configurations and the correct escaping of regex special characters.
2. He questions the UI addition that shows the active comment character in the commit message label, calling it "messy" and proposing to remove that part while applying the patch.
3. The response is generally positive, thanking Oswald for the contribution while suggesting this one refinement.

The discussion continues the thread's focus on making git-gui's comment handling more configurable while maintaining compatibility with existing behavior. Johannes appears to be in a position to apply the patch (mentioning "queuing"), suggesting this may be heading toward acceptance with minor adjustments.
