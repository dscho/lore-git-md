First patch in a series introducing safer assertion infrastructure to replace potentially dangerous `assert()` calls in Git's codebase.

This foundational patch adds a new BUG_IF_NOT() macro to git-compat-util.h that remains active even in production builds (unlike assert() which gets compiled out with NDEBUG). The macro uses Git's existing BUG() infrastructure to ensure assertions with potential side effects will still execute. 

The change is minimal - just a single line addition to the header file - but enables the subsequent patches to safely convert existing assert() calls that the series' CI infrastructure has flagged as potentially problematic. The commit message notes this will be used specifically for assertions that can't be proven side-effect-free through compiler analysis.

As the thread context shows, this is part of a v2 series that has already addressed technical and licensing concerns raised in review, with the approach validated by Junio Hamano and brian m. carlson. The series aims to improve safety in key subsystems like merge machinery and object storage by ensuring important assertions aren't silently removed in production builds.
