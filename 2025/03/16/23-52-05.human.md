This is a technical discussion about cryptographic random number generation (CSPRNG) in Git's build systems, continuing the thread about platform-specific implementations. Brian Carlson responds to Ramsay Jones's analysis of Cygwin's arc4random implementation versus Linux's glibc wrapper.

The email confirms that Cygwin's arc4random_buf() uses OpenBSD-style ChaCha20 encryption, similar to BSD systems, while Linux's glibc implementation is just a thin wrapper around getrandom(). Brian suggests that config.mak should default to getrandom on Linux, as it's the better choice for modern systems, though he's fine with arc4random remaining the meson default for compatibility. He also observes that POSIX 1003.1-2024 standardizes getentropy, which may become more widely available in the future.
