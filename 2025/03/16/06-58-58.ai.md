Refactoring patch in the merge-recursive removal series, specifically fixing a data structure usage mismatch in merge-ort.

This is the fourth patch in Elijah Newren's 5-part series of preparatory cleanups for removing merge-recursive. It corrects a subtle but harmless technical mismatch in merge-ort.c where a strintmap was being iterated using the strset_for_each_entry macro instead of the correct strintmap_for_each_entry. While these macros currently evaluate to the same thing, using the type-correct version is better for maintainability and future-proofing.

The issue originated in commit 7bee6c100431 when relevant_sources was refactored from a strset to a strintmap, but the iteration macro wasn't updated to match. The patch makes no behavior changes - it's purely a code hygiene improvement. The fix is minimal (2-line change) and clearly correct, touching only the merge-ort internals.

This continues the series' theme of small, focused cleanups that improve code clarity and correctness while maintaining existing behavior. As with the rest of the series, this change helps pave the way for the eventual removal of the legacy merge-recursive implementation by ensuring merge-ort's code is as clean and maintainable as possible.
