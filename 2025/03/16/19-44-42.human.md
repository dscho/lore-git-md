Junio Hamano's response in the ongoing discussion about path-filtered logs with subtree merges. This is a technical follow-up to Johannes Schindelin's analysis of the limitations in `tree-diff.c`.

Hamano agrees with Schindelin's technical assessment but broadens the perspective, noting that the current single-path tracking in `--follow-renames` is fundamentally flawed for merge-heavy histories regardless of directory handling. He explains that even following a single path properly would require per-ancestor path tracking when traversing merges, as paths may be renamed differently across branches before being merged back together.

The key insight is that directory-level rename tracking would naturally emerge as a special case of a more general solution that properly handles multiple path tracking through merges. Hamano suggests the current implementation needs to first correctly handle single-path tracking through merges before attempting the more complex directory case. This reinforces the thread's emerging consensus that the issue requires deep architectural change to Git's revision walking and rename tracking subsystems.
