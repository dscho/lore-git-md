This is a technical discussion about CSPRNG backend selection on Linux systems, responding to a documentation patch about `CSPRNG_METHOD` settings. The author argues against using `arc4random` on Linux despite it being the preferred method in Git's hierarchy, explaining that Linux's implementation differs significantly from BSDs.

The response clarifies that while BSDs benefit from `arc4random`'s userspace ChaCha20 implementation (which avoids syscall overhead), Linux's version is just a wrapper around the kernel CSPRNG via `getrandom`. The author contends this makes `getrandom` the better choice on Linux since it's more widely available (supported since glibc 2.25), slightly faster (no extra function call), and avoids the controversy around glibc's implementation that arose during its development.

The email suggests Git might want to `getrandom` by default for Linux builds, noting all supported distros now have sufficiently recent glibc. This challenges the documentation patch's implication that `arc4random` should be preferred when available. The technical rationale is well-articulated but represents a shift from the original patch's guidance, potentially sparking discussion about default behaviors across platforms.
