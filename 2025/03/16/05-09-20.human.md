This is the second patch in Zheng Yuting's GSoC work on improving SMTP authentication error handling in `git-send-email.perl`. Building on the previous patch's unified error capture mechanism, this change implements proper parsing of SMTP status codes (4xx for temporary errors, 5xx for permanent ones) according to RFC 5321.

The patch adds clear differentiation between temporary failures (which allow retries) and permanent failures (which abort the operation), with appropriate warning messages that include the status codes. When no status code is found, it defaults to treating the error as permanent. The implementation is clean and focused, adding 24 lines while removing 3, all within the `smtp_auth_maybe` function.

This appears to be a well-considered improvement that makes the error handling more robust and standards-compliant. The patch follows logically from the first in the series and maintains the same careful attention to detail. With both patches now addressing all prior feedback, this looks ready for final review and potential inclusion.
