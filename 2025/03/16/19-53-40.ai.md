Maintainer commentary on integer overflow fix approach. Junio C Hamano responds to René Scharfe's patch addressing an integer overflow in xdiff's hunk calculation, praising its careful bounds-checking approach over a more invasive `long` to `size_t` conversion. While acknowledging that a type conversion would be valid (especially since counts relate to memory regions), Hamano critiques the broader trend of patches that treat compiler warning suppression as an end goal rather than thoughtfully improving code correctness. The discussion touches on tradeoffs between the minimal fix (saturation arithmetic) versus a more comprehensive type system overhaul, including considerations about diff noise when comparing against upstream xdiff code. Hamano questions whether upstream xdiff development remains active enough for such comparisons to matter, suggesting the code may be effectively stable. The exchange reinforces the maintainer's preference for targeted fixes that solve specific problems without unnecessary churn, while leaving the door open for future refactoring if warranted.
