Bugfix response for a keyboard unresponsiveness issue in Git for Windows.

Johannes Schindelin responds to a bug report about `git add --patch` becoming unresponsive after using the "e" (edit) option on Windows. He suspects this is related to a known issue (git-for-windows/git#4776) that's already fixed and scheduled for release in Git for Windows v2.49.0 coming the following Monday. The reporter experienced complete keyboard lockup requiring terminal restart when trying to edit patches, specifically with Git version 2.42.0.windows.2 on Windows 10.

The response is brief but informative - it acknowledges the issue, links it to an existing fix, and provides a timeline for resolution. While the original report didn't mention editor overrides (a potentially relevant detail), the maintainer is confident enough in the correlation to indicate the upcoming release will address it. This appears to be a Windows-specific terminal handling issue during interactive patch editing.
