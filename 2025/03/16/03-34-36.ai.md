This is a bugfix response regarding keyboard unresponsiveness in Git for Windows when using `git add --patch` with the "e" edit option.

Johannes Schindelin identifies the reported issue (keyboard becoming unresponsive after editing a patch during interactive add) as likely related to a known Git for Windows issue (#4776), though notes the original bug report didn't specify whether an editor override was involved. The fix is already prepared and scheduled for release in Git for Windows v2.49.0, delayed from Friday to Monday following the project's no-Friday-release policy.

The bug manifests when using the "e" edit option during `git add --patch`, causing complete keyboard unresponsiveness that requires terminating the Git Bash process. The reporter (Dan Demp) consistently reproduced this behavior on Windows 10 with Git version 2.42.0.windows.2. While the exact technical connection to issue #4776 isn't detailed here, the response suggests it involves editor interaction during the patch editing workflow. This appears to be a Windows-specific issue given the Git for Windows context and the mention of Git Bash.
