Bugfix discussion for path-filtered log behavior with subtree merges. Johannes Schindelin responds to Oswald Buddenhagen's report about `git log .` in subtree-merged directories showing mostly merge commits rather than the actual changes being merged. 

Schindelin confirms the issue's plausibility and examines the technical challenges in fixing it, focusing on `try_to_follow_renames()` in `tree-diff.c`. He outlines potential code changes needed to handle multiple pathspec items, noting these would require replacing single-path comparisons with loops and `strset`/`strvec` structures. However, he highlights complications like Git's silent acceptance of directory pathspecs with `--follow` (which currently only works for single files) and potential performance degradation from nested loops.

The email suggests this is a deep architectural issue rather than a simple bug, with implications for how Git handles path filtering during revision walking. The technical analysis indicates any fix would need careful consideration of both correctness and performance impacts.
