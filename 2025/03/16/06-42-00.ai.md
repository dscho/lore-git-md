This is the foundational patch in a 3-part series introducing safer assertion mechanisms to Git's codebase. The patch adds a new `BUG_IF_NOT()` macro to git-compat-util.h that serves as an always-active alternative to `assert()`, remaining operational even when NDEBUG is defined (unlike standard assertions which are compiled out in production builds).

The macro is implemented using Git's existing BUG() infrastructure, evaluating its condition and triggering a fatal error if false. The implementation is straightforward - a single-line addition that checks the condition fails and calls BUG() with an appropriate message. This provides runtime safety for assertions that might have side effects, addressing a potential hazard in the codebase where some existing assertions contain function calls that would be silently removed in production builds.

The patch is part of a larger effort to systematically identify and convert risky assertions, as detailed in the thread context. While this initial patch just introduces the infrastructure, subsequent patches will add CI detection for problematic assertions and perform the actual conversions across several subsystems including merge machinery and object storage. The thread indicates this approach has been technically validated by multiple reviewers and has cleared licensing concerns regarding the detection mechanism.
