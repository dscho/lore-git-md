Platform compatibility patch addressing a Cygwin regex test anomaly, part 6/12 in a series modernizing Cygwin workarounds. This follow-up email from Ramsay Jones adds important context about why the original NO_REGEX patch (from 2013) wasn't updated sooner - it reveals a lingering test oddity in t7815-grep-binary.sh where the platform regex library (imported from FreeBSD) matches NUL bytes with '.' patterns, causing a "known breakage" to vanish. The test output shows all cases passing, including the previously-broken case 12, but flags this as an unexpected resolution. 

Ramsay outlines three potential resolutions: leaving it as-is (since it's not causing problems), disabling the test specifically for Cygwin, or removing the test entirely (his preferred option, arguing it doesn't test anything meaningful). The question is framed as seeking Junio Hamano's input on how to handle this test case, which exists outside the main regex compatibility changes but was a blocker for submitting the original update. The email doesn't propose code changes, but rather surfaces a subtle platform-specific behavior that needs consideration as part of the broader Cygwin compatibility updates.
