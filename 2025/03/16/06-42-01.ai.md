This is the second patch in a 3-part series introducing safer assertion handling in Git's codebase. The patch adds CI infrastructure to detect potentially dangerous assertions with side effects, building on the BUG_IF_NOT() macro introduced in the first patch.

The core mechanism redefines assert() during static analysis builds to reference an undefined symbol (not_supposed_to_survive) when assertions contain function calls, causing compilation to fail. This clever technique, contributed by Bruno De Fraine and placed in the public domain, reliably catches assertions that might have side effects across GCC, Clang and MSVC. The CI script (check-unsafe-assertions.sh) parses compiler errors to report problematic assertions with file locations and surrounding code.

The patch flags 9 existing assertions across merge machinery (merge-ort.c, merge-recursive.c), object storage (object-file.c), and parallel checkout that involve function calls like strmap_empty(), starts_with(), and would_convert_to_git_filter_fd(). While these appear side-effect-free to human inspection, they trigger the check due to their complexity. The output guides developers to replace them with BUG_IF_NOT() calls, which will be addressed in patch 3/3.

Key technical details include the Makefile addition of CHECK_ASSERTION_SIDE_EFFECTS flag, the compiler error parsing logic in the shell script, and the assert() redefinition in git-compat-util.h that transforms assertions into (void)(not_supposed_to_survive || (expr)) expressions. The approach has been vetted by Junio Hamano and brian m. carlson, with licensing concerns resolved through direct contact with the technique's author.
