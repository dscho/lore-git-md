Security/performance documentation patch addressing Linux's glibc arc4random implementation.

Junio C Hamano proposes a follow-up to the CSPRNG discussion, incorporating Brian Carlson's technical clarification about glibc's arc4random being merely a getrandom() wrapper on Linux. The patch makes two key documentation improvements:

1. Updates the Makefile comment to explicitly warn against using arc4random on glibc systems, noting it's not the same as BSD's implementation and provides no benefit over direct getrandom() calls.

2. Adds a placeholder comment in config.mak.uname's Linux section to discourage arc4random selection, though doesn't set a default method (the empty CSPRNG_METHOD lets the existing logic choose getrandom when available).

The commit message explains the historical context - glibc briefly included a true arc4random in 2022 but quickly replaced it with a getrandom wrapper after kernel maintainer objections. This makes the Linux implementation functionally equivalent to getrandom but with added call overhead, contrary to BSD's userspace ChaCha20 implementation that provides fork-safety.

This patch cleanly addresses the technical misunderstanding from the original documentation suggestion while maintaining flexibility for future CSPRNG backend changes. The changes are minimal and focused, touching only documentation and leaving the actual selection logic unchanged. The patch appears well-considered, building on established technical consensus about Linux's CSPRNG landscape.
