This thread documents a straightforward documentation correction for `git-diff`'s word-diff formatting. Han Jiang noticed that the online documentation at git-scm.com incorrectly shows `{added}` as the output format for word-diff=plain mode, when in fact Git uses `{+added+}` (and similarly `[-removed-]`) for marking changed words. 

While this is a simple fix, the reporter encountered some friction in the issue reporting process - they initially tried to file this on the git-scm.com GitHub repository but were redirected to the community page instead. The documentation error itself is clear when compared to Git's actual output behavior, though the reporter hasn't yet submitted a formal patch through the normal mailing list channels. This appears to be a case where the documentation simply fell out of sync with the implementation.
