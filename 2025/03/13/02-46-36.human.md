This is part of Elijah Newren's ongoing effort to replace merge-recursive with merge-ort, specifically introducing API compatibility layers. The patch adds a new `merge_ort_generic()` function to match merge-recursive's three entry points, while fixing a long-standing issue with ancestor labeling in conflict markers.

The key improvement is allowing callers to specify their own ancestor labels, which previously incorrect assumptions about the label being a "constructed merge base" that only worked for `git am`. The patch handles three distinct caller cases: `git am` (fake ancestor), `git merge-recursive` (user-specified tree), and `git stash` (stash base commit). The implementation includes a new `get_ref()` helper and makes `make_virtual_commit()` public for wrapper use.

This appears to be a well-considered change that addresses both technical debt (the problematic ancestor labeling) and provides the missing API piece needed for full merge-recursive replacement. The commit message thoroughly explains the motivation and different caller requirements, and the changes are focused on the merge-ort-wrappers layer where this compatibility logic belongs.
