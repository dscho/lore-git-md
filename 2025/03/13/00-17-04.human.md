Feature implementation for `git rev-list` adding NUL-delimited output support. This is patch 4/6 in a series that has already seen significant discussion and refinement (now at v2), with consensus reached on the design approach.

The patch introduces a `-z` option to `git rev-list` that changes the output format to use NUL bytes as delimiters instead of newlines and spaces. This is particularly useful for machine parsing when paths contain special characters. The new format outputs each object's OID followed by NUL, with optional path information in `path=<value>` format when `--objects` is used. The patch also makes `--stdin` input parsing NUL-delimited when `-z` is active.

Key implementation details:
- Adds comprehensive documentation of the new format
- Modifies object printing to use configurable terminators (NUL or newline)
- Rejects incompatible options when `-z` is used
- Includes thorough test coverage for both basic and `--objects` output modes
- Handles NUL-delimited stdin parsing consistently with output
