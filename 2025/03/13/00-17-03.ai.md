Feature implementation for NUL-delimited stdin parsing in `git rev-list`. This patch is part of the ongoing series to add `-z` support for machine-readable output, now addressing stdin handling to maintain consistency with the new NUL-delimited output format.

The change introduces a `nul_delim_stdin` flag in `setup_revision_opt` that makes `setup_revisions()` use NUL bytes instead of newlines when parsing stdin input. This affects both revision arguments and pathspecs read via `--stdin`. The implementation modifies the internal `read_revisions_from_stdin()` and `read_pathspec_from_stdin()` functions to use `strbuf_getdelim_strip_crlf()` with a configurable terminator, while maintaining all existing error checking and dashdash handling.

Key technical details:
- New `nul_delim_stdin` bit in `struct setup_revision_opt`
- Modified stdin parsing to use configurable terminator (NUL or newline)
- Preserved all existing validation and edge case handling
- Maintains compatibility with existing `--stdin` behavior when NUL mode not enabled
- Touches revision.c and revision.h

This builds on the thread's established consensus for NUL-delimited formats and completes the stdin side of the equation to match the output format changes in other patches. The implementation is straightforward and maintains the series' goal of consistent machine parsing while preserving human readability when not using `-z`.
