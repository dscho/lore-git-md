Platform compatibility fix for MinGW file handling, specifically addressing `O_CLOEXEC` flag support in `mingw_open_existing()`.

This is the first patch in a 2-part series fixing Windows-specific file handling issues that were causing flaky test behavior in t0610. The change modifies the MinGW compatibility layer to properly handle the `O_CLOEXEC` flag when opening existing files, though no actual behavior change occurs since Windows already handles file handle inheritance as `O_CLOEXEC` would require. The patch simply adds `O_CLOEXEC` to the accepted flags mask alongside `O_NOINHERIT`, which is functionally equivalent on Windows.

The change is minimal (4 lines modified) and well-justified in the commit message, explaining that while Windows' default behavior already matches `O_CLOEXEC` semantics, accepting the flag explicitly ensures code paths using it will still get proper POSIX file sharing semantics through the MinGW emulation layer. Junio C Hamano has reviewed the patch and found it sensible, though as a non-expert has not verified the Windows-specific behavior claims.

This appears to be a straightforward improvement to flag handling consistency that should help maintain POSIX semantics for code paths using `O_CLOEXEC` on Windows. The change is tightly scoped to the MinGW implementation and doesn't appear to introduce any new risks while resolving a real compatibility gap. The patch stands alone but works in concert with the second patch in the series which addresses a related race condition in file handling.
