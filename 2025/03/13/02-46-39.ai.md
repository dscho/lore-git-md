This is a test case addition that documents a bug in merge-ort's rename caching behavior when directory renames are disabled. The patch adds a failing test that demonstrates an assertion failure that occurs under specific conditions with `merge.directoryRenames=false`.

The test creates a scenario where:
1. A file is moved between directories in one branch
2. The same file is modified in another branch
3. When replayed with directory renames disabled, merge-ort hits an assertion about incomplete rename cache state

Key observations from the commit message:
- The bug only manifests when replaying a sequence of commits, not individual ones
- The same test passes when directory renames are enabled
- The issue appears related to cached rename information persisting incorrectly between commits
- The bug can also be triggered by modifying existing test t6429

The test case carefully constructed shows the failure mode while keeping the reproduction scenario minimal. The test is marked as `test_expect_failure` to document the known issue while allowing CI to continue passing. This appears to be a genuine bug in merge-ort's rename caching logic that only surfaces with directory rename detection disabled, which the test now reliably reproduces.
