Documentation bugfix for `--ancestry-path` graph example.

Han Jiang reports an inaccuracy in the documentation for `git log --ancestry-path`. The current documentation shows an example graph when using `--ancestry-path=H D..M` that omits commit C, which should be included according to the actual behavior. The email includes a detailed reproduction recipe showing the commit graph structure and demonstrating that commit C does appear in the output when running the command as described.

The reproduction steps create a complex branching history with merges, then show both the full graph and the filtered view using `--ancestry-path`. The output demonstrates that commit C (created on branch1 before merging with branch2) is indeed part of the ancestry path between D and M, contrary to what the documentation suggests.

This appears to be a straightforward documentation correction for a subtle but important detail about how `--ancestry-path` works with complex merge histories. The report is well-documented with clear reproduction case and expected vs. actual output. The fix would involve updating the example graph in the man page to include commit C in the ancestry path visualization.
