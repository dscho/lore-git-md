This is a cover letter for a 6-patch series that's part of a larger 19-patch effort to remove merge-recursive in favor of merge-ort. The series introduces new merge-ort features needed for converting existing merge-recursive callers, with a focus on preparing `git am` for the transition.

The first three patches add capabilities to merge-ort that existing callers rely on: a new generic merge function (with improved ancestor labeling), rename detection disablement (with test coverage), and verbosity control (moved to the wrapper layer). Patches 4-5 document and fix a bug with directory rename detection being turned off (important for `git am` compatibility). The final patch converts `git am` itself to use the new merge-ort API.

The v2 changes show thoughtful responses to review feedback: better commit message explanations, style fixes, test additions, and moving verbosity control to a more appropriate layer. The series now includes the actual `git am` conversion to demonstrate the API in use, growing from 3 to 6 patches based on discussion.

This looks like a well-considered step in the ongoing merge-ort migration, with careful attention to maintaining compatibility while cleaning up technical debt.
