This is a feature proposal for NUL-delimited output in `git rev-list`, now at version 2 of the patch series. Justin Tobler builds on earlier work by Patrick Steinhardt to add machine-parseable output formats to `rev-list`, with all major design questions now resolved through mailing list discussion.

The series introduces a `-z` option that formats `rev-list` output using NUL delimiters and a consistent `<token>=<value>` structure, making it easier to parse programmatically. The v2 iteration incorporates several key changes from v1 based on feedback, including:
- Using single NUL delimiters instead of double NULs (Junio's suggestion)
- Supporting NUL-delimited stdin parsing when `-z` is active
- Extending the format to handle `--boundary` and `--missing` options
- Using full attribute names like "missing=yes" for clarity

The implementation now covers all major `rev-list` output modes while maintaining compatibility with existing NUL-delimited formats in Git. The documentation clearly explains the new format and restrictions (like incompatibility with graph output). Test coverage has been expanded to verify the new behavior.

With all technical concerns addressed and consensus reached on the design, this series appears ready for final review. The clean separation of preparatory refactors (patches 1-2) from the actual feature implementation (patches 3-6) makes for an easy-to-follow progression. The changes are well-motivated by the need for reliable machine parsing of revision output, particularly for paths containing special characters.
