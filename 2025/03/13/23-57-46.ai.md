This is part 5/6 of a feature series adding NUL-delimited output support to `git rev-list`. The patch specifically implements `-z` support for the `--boundary` option, completing the machine-readable output format for boundary objects.

The patch modifies boundary object output to use a key-value format (`<OID> NUL boundary=yes NUL`) instead of the human-readable prefix format (`-<OID> LF`). This maintains consistency with the NUL-delimited output format established in earlier patches, where metadata is expressed as key-value pairs rather than special prefixes. The implementation includes:

1. Documentation updates clarifying the new boundary object format alongside existing path metadata
2. Code changes to emit the boundary marker as a key-value pair when in NUL-delimited mode
3. Relaxation of the option compatibility check that previously prevented `-z` from being used with `--boundary`
4. A new test case verifying the boundary object output format

The changes are straightforward and well-contained, building on the infrastructure from previous patches in the series. The test coverage is thorough, checking both the basic boundary case and proper NUL-delimited formatting. This appears to be the final piece needed for comprehensive NUL-delimited output support in `rev-list`, with all technical aspects now addressed through the v3 iteration of the series.
