This is a test case addition that documents a bug in merge-ort's rename caching behavior when directory renames are disabled. The patch is part of Elijah Newren's larger series to replace merge-recursive with merge-ort, specifically addressing edge cases in the transition.

The test demonstrates an assertion failure that occurs when `merge.directoryRenames=false` is set, showing that the rename cache appears to retain incomplete state between commits during replay operations. The failure manifests in a specific sequence: when replaying two commits where the first involves directory renames, but only fails on the second commit's replay. The same test passes when directory renames are enabled, suggesting the cache is being improperly handled in the disabled case.

The test case carefully constructs a scenario with directory moves and subsequent modifications to trigger the issue, marking it as `test_expect_failure` to document the known bug. This follows the pattern of the series by identifying and recording edge cases that need to be addressed in the merge-ort transition. The test will serve both to prevent regression and guide future fixes for the directory rename caching behavior.
