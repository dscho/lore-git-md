This is a security-focused refinement in the ongoing remote object-info implementation. Jeff King responds to Peijian Ju's proposed fix for a format string validation vulnerability in the `remote-object-info` batch command, which was found to segfault when given unsupported placeholders like `%(objecttype)`.

Jeff suggests two alternative approaches to validate format strings more robustly than the current `strstr()` check. The first would check for disallowed placeholders after parsing, while the second would integrate validation into the atom expansion system. He also proposes a third option - gracefully handling missing data by initializing fields to safe defaults and returning empty strings for unsupported queries, which could allow intermixing local and remote object requests.

The discussion shows careful attention to both security and API design considerations, with Jeff providing concrete implementation suggestions while acknowledging tradeoffs. This represents the final polish on a security-hardened feature that has undergone twelve rounds of review, with particular scrutiny from Jeff on the transport layer and validation logic. The exchange demonstrates the project's rigorous approach to hardening new protocol features before merging.
