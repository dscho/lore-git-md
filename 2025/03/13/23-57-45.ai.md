This is patch 4/6 in a series implementing NUL-delimited output for `git rev-list`, now at v3 with refinements from earlier rounds. The patch focuses on core functionality for object output with NUL delimiters, building on preparatory refactoring from earlier patches.

The implementation introduces a `-z` flag that changes `rev-list` output to use NUL bytes as delimiters between objects and their metadata. The format uses `<OID> NUL [path=<path> NUL]` syntax, with OIDs never containing '=' to distinguish them from metadata tokens. This handles paths with special characters (including newlines) that would be problematic in newline-delimited output. The patch also makes `--stdin` arguments NUL-delimited when `- z` is active.

Key technical details include:
- New `line_term` and `info_term` variables control delimiter selection
- Output formatting branches in `show_object()` based on delimiter mode
- Strict validation rejects options incompatible with `-z` (graph output, timestamps, etc.)
- Comprehensive tests verify basic NUL-delimited output and path handling
- Documentation clearly specifies the output format and constraints

The implementation maintains careful backward compatibility while adding the new mode. Test coverage includes both simple object listing and path-inclusive cases, plus verification of stdin handling. The patch follows the series' established pattern of using single NUL delimiters with key-value metadata tokens.

This represents the main functional core of the series, with subsequent patches extending NUL-delimited support to additional `rev-list` options. The implementation appears robust, with clear documentation and thorough testing of edge cases around path handling and special characters.
