This is part 4 of a 6-part series implementing NUL-delimited output for `git rev-list`, now in its third revision. The patch adds core support for the `-z` option, which changes the output format to use NUL bytes as delimiters instead of newlines and spaces. This is particularly useful for machine parsing when paths contain special characters.

The implementation introduces a key-value format for object metadata (like paths) and ensures OIDs are cleanly separated from their attributes. The patch also adds stdin handling for NUL-delimited input when `--stdin` is used with `-z`. Several options that don't make sense with NUL-delimited output (like graph output or verbose headers) are explicitly rejected.

The changes include thorough documentation of the new format and comprehensive tests verifying both basic NUL-delimited output and the stdin handling. The implementation looks solid, with careful attention to edge cases and clear separation of concerns. This is a well-crafted addition that addresses a real need for reliable machine parsing of `rev-list` output.

The series as a whole has evolved through multiple rounds of review, with this version incorporating documentation improvements and minor code style tweaks from earlier feedback. While there's an ongoing discussion about standardizing `-z` behavior across Git commands, that doesn't block this technically complete implementation.
