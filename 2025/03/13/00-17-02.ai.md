This is a refactoring patch in the NUL-delimited output series for `git rev-list`. It prepares for upcoming changes by consolidating early option parsing logic.

The patch refactors how `--missing` and `--exclude-promisor-objects` options are handled in `builtin/rev-list.c`. Instead of having two separate loops to parse these options before `setup_revisions()`, it combines them into a single pass. The key changes are:

1. Moves both option parsers into one loop
2. Uses the new `die_for_incompatible_opt2()` helper to check for incompatible options after parsing
3. Maintains all existing functionality while simplifying the control flow

This is a mechanical change that doesn't modify behavior, but makes the code more maintainable for the subsequent patches in the series that will add more early-parsed options (likely the `-z` flag for NUL-delimited output). The patch follows good practices by keeping the error checking and option validation intact while restructuring the code.

The change touches only `builtin/rev-list.c` and is part of the larger effort to implement machine-parseable output formats in `rev-list`. It builds on the thread's established consensus about the technical approach while preparing for the NUL-delimited output feature to be added in later patches.
