Platform compatibility patch for MinGW file handling, specifically addressing `O_CLOEXEC` flag support. This is the first of a two-patch series aimed at improving Windows compatibility, particularly around file handling race conditions that affect test t0610.

The patch focuses on `mingw_open_existing()` in `compat/mingw.c`, which handles opening existing files in the MinGW compatibility layer. While the function already supported `O_NOINHERIT`, it didn't properly handle `O_CLOEXEC` despite their functional equivalence on Windows (where file handles are non-inheritable by default during exec). The change allows both flags to pass through the validation check, ensuring consistent POSIX semantics across all code paths that use these flags.

Key technical details:
- Modifies flag validation in two locations within `mingw_open_existing()`
- Adds `O_CLOEXEC` to the accepted flags mask alongside `O_NOINHERIT`
- Small change (4 lines modified) with no behavior change for existing callers
- Part of broader effort to maintain POSIX semantics on Windows

The patch appears straightforward and well-justified, noting that Windows already handles the close-on-exec behavior natively.
