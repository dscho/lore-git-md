This is a follow-up discussion in the ongoing thread about adding NUL-delimited I/O support to `git rev-list`. The conversation has moved from technical implementation details to interface design philosophy.

Patrick Steinhardt responds to Junio Hamano's suggestion about using `-z` for both input and output formatting in `rev-list`, rather than introducing separate `-z`/`-Z` flags for input vs. output. He argues for consistency with other Git commands and shares his experience that machine parsing eventually needs NUL termination in both directions, even if it doesn't seem immediately necessary. The discussion references prior experience with `git cat-file` where the split approach caused problems.

This email represents the final design consensus in the thread, with all major technical questions now resolved. The v2 series implements `-z` as affecting both input and output, following the principle that unified behavior is less surprising and more future-proof than separate controls. The thread has reached clear agreement among all participants (Patrick, Justin, Junio, and Jeff King) on this approach.
