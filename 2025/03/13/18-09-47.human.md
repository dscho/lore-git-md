Bugfix for cruft pack freshening when multiple cruft packs exist. This patch addresses an issue where objects in large cruft packs couldn't be freshened during repacking due to size thresholds. The fix introduces a new `ignore_packed_keep_in_core_has_cruft` flag and `want_cruft_object_mtime()` helper to properly handle mtime comparisons when deciding whether to retain existing cruft objects.

The problem occurs when:
1. Multiple cruft packs exist (enabled by `--max-pack-size`)
2. Some cruft packs exceed the size threshold and are retained
3. Objects in those retained packs need freshening (updating their mtime)

Previously, these objects would be skipped entirely. The new logic now:
- Tracks whether any retained packs are cruft packs
- Compares mtimes when deciding whether to keep existing cruft objects
- Allows freshening by packing new copies when needed

The patch includes thorough test coverage demonstrating the fix works for both packed and loose objects that were previously in cruft packs. This was split from a larger series to allow quicker merging of the critical bugfix while policy discussions continue separately.
