This is a refactoring patch in Elijah Newren's ongoing series to replace merge-recursive with merge-ort, specifically addressing verbosity control in the compatibility wrappers.

The patch modifies the merge-ort-wrappers.c file to properly handle verbosity level 0, which callers like `git am` and `git checkout` use to suppress conflict messages. Previously, these wrappers always passed 1 (true) for the display_update_msgs parameter to merge_switch_to_result(). The change introduces a new show_msgs variable that converts the verbosity level to a boolean, allowing callers to control message display through the existing verbosity parameter rather than needing to bypass the wrappers.

The implementation is straightforward - just 6 lines added across two wrapper functions (merge_ort_nonrecursive and merge_ort_recursive) that now check opt->verbosity before deciding whether to show messages. This maintains backward behavior for positive verbosity levels while adding support for the zero case. The change helps simplify caller conversions by letting them use the same verbosity controls they did with merge-recursive.

This appears to be a well-contained change that completes an important piece of API compatibility between merge-ort and merge-recursive. The patch fits logically into the larger series by removing another obstacle to caller migration, in this case for commands that want to suppress merge messages. The implementation is minimal and focused, with the behavioral change clearly motivated by real-world caller needs.
