This is the first patch in a 6-part series to migrate callers from merge-recursive to merge-ort, focusing on API compatibility. It introduces a new `merge_ort_generic()` function that serves as a drop-in replacement for `merge_recursive_generic()`, completing merge-ort's API surface to match merge-recursive's.

The patch addresses a long-standing issue with ancestor labeling in merge conflicts when using diff3 style. The original merge-recursive implementation hardcoded a "constructed merge base" label that was only appropriate for git-am's fake ancestors, causing confusion for other callers like git-stash and direct merge-recursive invocations. The new implementation allows callers to override the ancestor label when there's a single merge base, with special handling for git-am's constructed ancestors.

Key technical changes include:
- New `merge_ort_generic()` in merge-ort-wrappers.[ch] with 64 lines of implementation
- Exposing `make_virtual_commit()` from merge-ort.c to merge-ort-wrappers.c
- Relaxing the ancestor label assertion in merge-ort.c to allow git-am's special case
- Adding documentation for the new function in merge-ort-wrappers.h

The implementation carefully maintains backward behavior while fixing the labeling issue, with direct copying of the `get_ref()` helper from merge-recursive.c (with improved error reporting). This patch sets up the foundation for converting git-am in patch 6/6 of the series, demonstrating the API's flexibility to handle different caller needs while maintaining a clean migration path from merge-recursive.
