This is a feature proposal for a new config option to control submodule recursion behavior during clone operations.

The author suggests adding a config option that would make `git clone` automatically recurse into submodules, similar to passing `--recurse-submodules` on the command line. They note that while similar config options exist for other submodule operations, clone is currently excluded from this behavior. The motivation comes from wanting consistent behavior between CLI and GUI tools (specifically mentioning IDEs that already clone submodules automatically) and a workflow where they always want full recursion during clone but may want different behavior for other operations like checkout.

The proposal suggests two possible config names (`clone.recursive` or `clone.recurse-submodules`) but doesn't provide implementation details. The use case focuses on multi-level submodule hierarchies where the user wants to recursively clone everything in one step. The author explicitly states they don't want to change existing behavior for other commands, just add this as a clone-specific option.

Key points for future discussion would likely focus on:
- The exact config name and location (whether to use existing submodule.* namespace or new clone.*)
- Whether this should interact with or override existing submodule.recurse config
- Potential implementation approach (modifying builtin/clone.c)
- Whether this warrants a new config or if existing mechanisms could be extended

The proposal is clearly motivated by real-world workflow needs but lacks technical implementation details that would be needed for actual review.
