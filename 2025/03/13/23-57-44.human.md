This is the third patch in a series implementing NUL-delimited I/O for `git rev-list`, now in its third revision. The patch focuses on adding NUL-delimited input support when using `--stdin`.

The change introduces a new `nul_delim_stdin` flag in `setup_revision_opt` that, when enabled, makes `rev-list` use NUL bytes instead of newlines to separate input arguments from stdin. The implementation modifies two key functions (`read_pathspec_from_stdin` and `read_revisions_from_stdin`) to use `strbuf_getdelim_strip_crlf` with the appropriate delimiter.

This is a straightforward technical change that builds on the preparatory refactoring in earlier patches. The implementation looks clean and maintains consistency with the rest of the series. The patch follows the established pattern of using NUL delimiters for machine parsing, though as noted in the thread summary, there's an ongoing discussion about whether this behavior should be standardized across all Git commands that accept `-z`.
