This is a bugfix patch in the cruft pack series, now merged by the maintainer. It addresses a limitation in how Git freshens objects that exist in multiple cruft packs when some packs exceed the size threshold.

The core issue is that objects in "frozen" cruft packs (those too large to be rewritten) couldn't be freshened at all before this fix. The patch introduces a new `ignore_packed_keep_in_core_has_cruft` flag and modifies the object selection logic to allow freshening when the existing cruft pack copy is older than the new one being considered. While this means keeping duplicate objects in some cases, it's the only workable solution without modifying existing `.mtimes` files.

The fix comes with extensive test coverage in `t7704-repack-cruft.sh` verifying the new behavior. This was the last critical piece needed in the cruft pack implementation, with only documentation of the size threshold policy remaining before the full series can be merged. The maintainer has accepted the solution as-is, indicating the technical approach is now settled.
