Platform compatibility cleanup for MinGW file handling. This is the second patch in a 2-part series addressing Windows-specific race conditions in file operations, specifically focusing on improving POSIX semantics emulation.

The patch makes `mingw_open_existing()` properly handle the `O_CLOEXEC` flag, which was previously causing some code paths to bypass the MinGW emulation layer. The author notes this is a trivial change since Windows already handles file handle inheritance correctly by default - the flag just needs to be recognized to ensure consistent behavior across all code paths. The change is minimal (4 lines modified) and maintains backward compatibility while improving POSIX compliance.

This appears to be a straightforward cleanup that complements the main fix in patch 1/2 (which addresses a race condition in file creation). The author has clearly considered the Windows-specific behaviors and how they map to POSIX expectations. While not fixing any immediate bugs, this change helps ensure more consistent behavior when `O_CLOEXEC` is used on Windows platforms.
