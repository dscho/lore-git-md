This is part 3 of a 6-part series adding NUL-delimited output support to `git rev-list`, now in its second version. The patch focuses on making `--stdin` mode work with NUL-delimited input when requested.

The change introduces a new `nul_delim_stdin` flag in `setup_revision_opt` that, when set, makes `setup_revisions()` use NUL bytes instead of newlines to separate arguments. This matches the series' overall goal of improving machine parsing of `rev-list` output by using more reliable delimiters. The implementation modifies two key functions (`read_pathspec_from_stdin` and `read_revisions_from_stdin`) to accept a line terminator parameter, with the default remaining newline for backward compatibility.

This patch appears well-integrated with the rest of the series, which has already addressed major design questions and received positive feedback from key contributors. The changes are focused and maintain existing behavior while adding the new capability. The series as a whole seems ready for final review, with this particular patch providing important plumbing for consistent NUL-delimited handling throughout the command.
