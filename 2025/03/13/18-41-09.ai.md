This is a bugfix patch for the cruft pack functionality, specifically addressing an issue with freshening objects that exist in multiple cruft packs. The patch has now been accepted by the maintainer (Junio Hamano) and will be queued for merging.

The core issue fixes a limitation where objects in cruft packs larger than the size threshold couldn't be freshened during repacking. The solution introduces a new `ignore_packed_keep_in_core_has_cruft` flag and modifies the `want_found_object()` logic to properly handle objects in multiple cruft packs. The key change is that objects are now only rejected if they exist in non-cruft packs or in cruft packs with equally/more recent mtimes, allowing freshening when the existing cruft copy is older.

The implementation includes comprehensive test coverage in `t/t7704-repack-cruft.sh` to verify the new behavior works correctly across multiple cruft packs. The changes touch several key files: `builtin/pack-objects.c` (with the main logic changes), `packfile.[ch]` for supporting infrastructure, and the test file.

This patch represents the final technical component of the cruft pack series, with only documentation of the 50% size threshold ratio remaining before the full series can be merged. The maintainer's acceptance indicates this solution meets Git's quality standards and properly addresses the identified issue.
