Bugfix addressing NULL pointer dereference in promisor-remote subsystem, now in its fourth iteration. This patch fixes a segfault that occurs when a promisor remote is configured without a URL by falling back to using the remote name (matching `git fetch` behavior). The solution has evolved through several rounds of review, with Jeff King providing key input on adopting standard Git remote conventions.

The patch now includes comprehensive warnings for various edge cases in the 'KnownUrl' mode, such as when no URL is advertised by the server or when empty URLs are configured. Christian Couder has made two minor changes since v3: removing a redundant comment and replacing `strcmp()` with `strcasecmp()` for URL comparison.

While the core fix is sound and ready for inclusion in Git 2.49.0, Junio Hamano has raised deeper architectural questions about whether promisor remotes should follow standard remote conventions, as remote names may be meaningless to servers in this context. The patch demonstrates thorough test coverage with new test cases verifying the warning behavior and edge cases.

This represents the culmination of a thread that began with a simple NULL dereference fix and has grown to consider broader API design questions for the promisor-remote subsystem.
