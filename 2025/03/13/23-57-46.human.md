This is part 5/6 of a feature series adding NUL-delimited output support to `git rev-list`. The patch specifically implements `-z` support for the `--boundary` option, which marks commits that form the edge of a traversal.

When using `--boundary` with `-z`, boundary commits are now indicated with a `boundary=yes` token rather than the traditional `-` prefix, maintaining consistency with the series' key-value metadata format. The documentation is updated to reflect this new format and clarify compatibility with both `--objects` and `--boundary` options.

The implementation includes:
- Modifying the commit printing logic to output the boundary token when in NUL-delimited mode
- Updating option validation to allow `-z` with `--boundary`
- Adding a test case verifying the new output format

This continues the series' pattern of converting rev-list's output formats to be more machine-parseable while preserving all existing functionality. The changes are straightforward and well-tested, building on the foundation established in earlier patches. With this addition, the NUL-delimited output format now comprehensively handles all of rev-list's major output modes.
