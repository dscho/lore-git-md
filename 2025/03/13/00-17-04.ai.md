This is the fourth patch in a v2 series implementing NUL-delimited I/O for `git rev-list`, focusing on the core output formatting changes. The patch introduces the `-z` option to produce machine-parseable output with NUL delimiters instead of newlines, addressing the longstanding issue of parsing paths containing special characters.

The implementation modifies object printing in `builtin/rev-list.c` to use configurable terminators (NUL or newline) through new `line_term` and `info_term` variables. The output format changes from `OID SP [path] LF` to `OID NUL [path=path NUL]`, with OIDs guaranteed not to contain '=' to enable reliable parsing. The patch enforces compatibility rules, rejecting combinations of `-z` with options like `--graph` or `--left-right` that don't yet support NUL-delimited output.

Key technical details include:
- New `nul_delim_stdin` flag in `setup_revision_opt` for consistent stdin handling
- Modified `show_object()` to handle both traditional and NUL-delimited formats
- Comprehensive error checking for incompatible option combinations
- Tests in t6000 and t6017 verifying basic NUL-delimited output and stdin parsing
- Documentation updates explaining the new format's structure and limitations

The patch builds on previous refactoring work in the series and maintains all existing validation while adding the new output mode. It represents a significant step toward the series' goal of comprehensive NUL-delimited I/O support in `rev-list`, with subsequent patches planned to extend `-z` to other options like `--missing` and `--boundary`.
