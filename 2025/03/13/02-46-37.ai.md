Feature/bugfix hybrid for merge-ort's rename detection behavior. This patch from Elijah Newren enables disabling rename detection in merge-ort, addressing both a behavioral request and completing feature parity with merge-recursive.

The change adds support for the `no-renames` option and `merge.renames` config in merge-ort, which was previously ignored despite being documented. The implementation adds a simple early return in `detect_and_process_renames()` when `opt->detect_renames` is false, skipping rename detection while maintaining other merge processing. Documentation updates clarify that merge-ort now handles the same rename-related options as merge-recursive, though still ignoring some recursive-specific options like `patience` and `diff-algorithm`.

A new test case in t4301 verifies the behavior by repeating a merge scenario with rename detection disabled via `-c diff.renames=false`, expecting the appropriate modify/delete conflict when files are moved without detection. The test demonstrates both the functionality and the different conflict output when rename detection is off.

This change is part of Newren's larger effort to make merge-ort a complete replacement for merge-recursive, addressing one of the last behavioral differences between the two merge strategies. The patch follows up on a specific user request from 2021 where someone needed to disable renames for behavioral rather than performance reasons. The implementation is straightforward, adding only 5 lines of core logic while maintaining the existing rename detection flow when enabled.
