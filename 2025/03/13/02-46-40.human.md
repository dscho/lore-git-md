Bugfix for merge-ort's directory rename handling when merge.directoryRenames=false. This patch addresses two issues in the ongoing merge-ort conversion effort:

First, it fixes a case where directory rename detection logic was still running even when explicitly disabled via merge.directoryRenames=false. While this wasn't causing functional problems (due to other checks preventing the results from being used), the code now properly skips this path when directory renames are disabled.

Second and more significantly, it resolves an assertion failure that could occur when replaying commits with cached renames while directory renames are disabled. The issue arises when a cached rename from a previous commit references a directory that isn't relevant to the current merge. The fix takes a conservative approach by disabling rename caching entirely when directory renames are turned off, similar to how the code already handles rename/rename(1to1) cases.

The patch includes a test that was previously marked as expect_failure and now passes, demonstrating the fix works. This is part of Elijah Newren's larger series to replace merge-recursive with merge-ort, and specifically addresses a behavioral divergence between the two merge strategies in the directory-renames-disabled case. The changes are focused and well-explained, with clear reasoning for the conservative solution chosen.
