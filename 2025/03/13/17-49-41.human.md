Feature proposal for configurable recursive submodule cloning during `git clone`.

Tor Nichols suggests adding a configuration option to make `git clone` automatically recurse into submodules, similar to the existing `--recurse-submodules` flag. The motivation comes from working with nested submodules where recursive cloning is always desired, particularly when switching between IDEs (which often handle this automatically) and the command line.

The proposal notes that while there are existing submodule recursion controls, they don't apply to `git clone` specifically. The suggested syntax would mirror other Git config patterns with either `clone.recursive` or `clone.recurse-submodules` boolean options. The author emphasizes this should be clone-specific to avoid affecting other operations like checkout where recursive behavior might not always be wanted.

This appears to be a well-motivated quality-of-life improvement for developers working with complex submodule hierarchies. The request is clearly explained with practical workflow examples, though it doesn't include a patch implementation. The suggestion aligns with Git's existing configuration patterns and would provide parity with IDE behaviors.
