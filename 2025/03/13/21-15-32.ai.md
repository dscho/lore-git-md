Documentation fix for git-diff word-diff formatting.

Han Jiang reports a formatting error in the git-diff documentation where the word-diff=plain example incorrectly shows `{added}` when it should be `{+added+}`. The issue appears in the online documentation at git-scm.com. The reporter notes they attempted to file this as an issue on the git-scm.com GitHub but were redirected to the community page instead, suggesting the issue reporting process may not be straightforward.

This is a straightforward documentation correction for the word-diff format examples. The current documentation shows the wrong syntax for word-diff plain mode output, which could mislead users about the actual output they should expect. The fix would align the example with Git's actual behavior where changed words are wrapped in `{+ +}` and `[- -]` markers rather than simple `{ }` brackets.

The patch appears to be a simple but valid correction, though it's worth noting that the reporter didn't follow through with creating a proper issue or patch submission through the normal channels. The documentation error itself seems clearly wrong when compared to Git's actual output format for word-diff.
