This thread addresses a Windows-specific race condition in Git's lockfile handling where file creation fails with EACCESS when a file is marked for deletion. The discussion initially considered three approaches but has now reached consensus on using the Windows NT API's `RtlGetLastNtStatus()` to precisely detect `STATUS_DELETE_PENDING` cases while properly distinguishing them from genuine permission errors.

The solution, proposed by Patrick Steinhardt and reviewed by Windows expert Johannes Schindelin, will be implemented as a 2-patch series. The first patch is a straightforward Meson build fix for MSVC compatibility, while the second implements the NTSTATUS-based solution. Johannes initially had concerns about using an undocumented API but ultimately approved the approach after verifying its technical soundness and initialization safety.

The fix applies to Git's general lockfile subsystem rather than being reftable-specific. As a fallback option, the series will document SQLite's polling approach (25ms delays with 10 attempts) should the NTSTATUS solution prove problematic in practice. With Windows experts now in agreement, the series is ready for final implementation and expected to be merged by maintainer Junio Hamano.
