This thread addresses a Windows-specific race condition in Git's file handling that was causing flaky test failures in t0610. The issue occurs when `_wopen()` with `O_CREAT|O_EXCL` incorrectly returns `EACCESS` on Windows when another process has marked a file for deletion via `DeleteFileW()`. 

Patrick Steinhardt has submitted a v2 series with two patches: the first fixes a Meson build issue to ensure proper compatibility file inclusion for MSVC, while the second (the current focus) introduces more precise error code translation by checking for `STATUS_DELETE_PENDING` via the Windows NT API. This maps the error to `EEXIST` instead, allowing proper retry behavior in the lockfile subsystem. The changes specifically affect reftable's lockfile handling during compaction.

The series has evolved from v1 by dropping previously approved `O_CLOEXEC` changes to focus on the core issue. Patrick confirms the new approach resolves the test flakiness, with t0610 now passing consistently where it previously failed 20-30% of the time. The solution requires careful review from Windows experts like Johannes Schindelin to ensure it doesn't mask legitimate permission errors while properly handling the deletion race condition. 

Open questions remain about the impact of additional system calls in error paths and whether to document the Windows-specific behavior. The Meson build fix is straightforward and uncontroversial, while the NtStatus checking represents a more substantive change that needs expert validation. Next steps include confirmation from Johannes on the error handling precision and potential performance measurements.
