This is the third patch in a series implementing NUL-delimited I/O for `git rev-list`, specifically adding stdin handling. The patch introduces a `nul_delim_stdin` flag in `setup_revision_opt` to control whether stdin arguments should be NUL-delimited rather than newline-delimited.

The implementation modifies two key functions - `read_pathspec_from_stdin()` and `read_revisions_from_stdin()` - to use `strbuf_getdelim_strip_crlf()` with a configurable terminator (NUL or newline) instead of hardcoded newline handling. The terminator is determined by checking the new `nul_delim_stdin` flag when processing the `--stdin` option in `setup_revisions()`.

This change enables reliable parsing of revision arguments and pathspecs containing newlines when `-z` mode is active. The patch maintains all existing functionality while adding the new delimiter behavior, with careful handling of the transition between revision arguments and pathspecs (after `--`).

The implementation builds on the preparatory refactoring in earlier patches and demonstrates good attention to detail in preserving the existing control flow while adding the new feature. The changes are focused and well-contained to the stdin handling logic, with corresponding updates to the revision.h header to expose the new flag.
