Bugfix and refactoring patch in the protocol v2 fetch series, addressing refspec prefix handling. This is patch 5/9 in Jeff King's architectural improvement series for protocol v2 fetch behavior, which has already received Taylor Blau's comprehensive review and approval.

The patch focuses on cleaning up the `refspec_ref_prefixes()` function in `refspec.c`, which generates prefix strings for server communication. Key changes include:
1. Separating the negative refspec check from exact-SHA1 handling (which was moved to a different patch)
2. Restructuring the fetch/push logic with clearer conditional blocks
3. Fixing a latent bug discovered during the refactoring

Taylor Blau suggested two potential improvements in the review:
1. Renaming the function to `refspecs_to_ref_prefixes()` for clarity
2. Using a switch/case structure for the fetch/push operation type

Jeff King acknowledges these suggestions but notes deeper naming issues with the `fetch` field (which confusingly uses enum values REFSPEC_FETCH/REFSPEC_PUSH despite being a boolean). He indicates the current patch represents a minimal fix to preserve the bugfix while leaving more opinionated cleanups for potential follow-up work.

This patch builds on the series' broader goals of improving protocol v2's ref-prefix handling while maintaining all existing functionality. The changes are focused on internal implementation details rather than user-visible behavior, with test coverage provided by the series' other patches.
