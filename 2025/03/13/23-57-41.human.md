This is a feature proposal for NUL-delimited output in `git rev-list`, now at version 3 of the patch series. Justin Tobler builds on previous discussion to implement comprehensive machine-readable output formatting.

The series introduces a `-z` option that replaces newline-delimited output with NUL-delimited records, using a consistent `<token>=<value>` format for all object metadata (paths, boundary markers, missing objects). This makes parsing safer for paths containing special characters. The implementation now handles `--stdin` input with NUL delimiters when in this mode.

Changes since v2 include earlier documentation of the `--stdin` behavior change and minor code/doc refinements. The series has evolved from initial discussions about double-NUL delimiters to the current single-NUL key-value approach, with all technical concerns addressed. One remaining philosophical question about standardizing -z behavior across Git commands doesn't block merging.

The implementation looks thorough, with good test coverage and careful attention to edge cases. The commit messages clearly explain the motivation and design choices. This appears ready for final review, representing a well-executed solution to a real parsing problem in machine consumption of rev-list output.
