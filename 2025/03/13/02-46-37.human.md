This is a patch in Elijah Newren's series to migrate from merge-recursive to merge-ort, specifically addressing rename detection behavior. The patch allows merge-ort to honor the `--no-renames` flag and `merge.renames` configuration, which previously only worked with merge-recursive.

The change comes after years of merge-ort development where rename detection was always enabled, as the author initially suspected performance was the main reason people disabled it. With merge-ort's improved performance and a specific behavioral use case now documented (linked in the commit message), the patch adds proper support for disabling renames.

The implementation adds a simple check in merge-ort.c to skip rename detection when requested, updates documentation to show the option is now supported by both strategies, and includes a test case verifying the behavior. This is part of making merge-ort a complete replacement for merge-recursive by matching all its configuration options.

The patch appears straightforward and well-justified, with clear documentation updates and test coverage. It's one of several compatibility-focused changes in this series to ease the transition from merge-recursive to merge-ort.
