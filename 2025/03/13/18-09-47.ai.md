This is a bugfix patch in the cruft pack series, specifically addressing an issue with freshening objects that exist in multiple cruft packs. The patch is being split from the larger policy discussion to allow quicker merging of the critical fix.

The core issue occurs when trying to freshen objects that exist in cruft packs larger than the size threshold. Previously, these objects couldn't be freshened because the code would skip over them entirely. The patch introduces a new `ignore_packed_keep_in_core_has_cruft` flag and `want_cruft_object_mtime()` helper to properly handle these cases by:
1. Tracking whether we have any cruft packs in our kept list
2. Only rejecting objects when they exist in non-cruft packs or in cruft packs with equally/more recent mtimes
3. Allowing freshening when the existing cruft copy is older

The implementation modifies key functions in `builtin/pack-objects.c` including `want_found_object()` and adds comprehensive tests in `t7704-repack-cruft.sh` to verify the new behavior. The changes ensure objects can be properly freshened even when spread across multiple cruft packs of varying sizes.

This is a well-motivated fix with thorough test coverage that addresses a clear limitation in the existing cruft pack implementation. The strategic split from the policy discussion allows this important fix to progress independently while other aspects of the feature continue to be refined.
