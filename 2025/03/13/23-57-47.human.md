Feature implementation completing NUL-delimited output support in `git rev-list`. This is the final patch (6/6) in Justin Tobler's series, adding `-z` support for the `--missing` option to provide machine-readable output of missing objects.

The patch modifies the output format when `-z` is used with `--missing=print-info` to use NUL-delimited key-value pairs instead of the human-readable format. Missing objects are now printed as `<OID> NUL missing=yes NUL` followed by optional metadata like path and type, all NUL-delimited. This matches the consistent format established in earlier patches of the series.

Key changes include:
- Updating the documentation to include the new `--missing` compatibility with `-z`
- Modifying `print_missing_object()` to handle both NUL-delimited and traditional output
- Adding comprehensive tests for the new format, including handling of paths with spaces
- Relaxing some option compatibility checks to allow `-z` with `--missing`

The implementation looks thorough, with careful attention to maintaining consistency with the NUL-delimited formats introduced in previous patches. The test coverage appears robust, including edge cases like paths with spaces. This completes the series' goal of providing comprehensive NUL-delimited I/O support in `rev-list`.
