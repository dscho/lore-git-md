This is a bugfix patch series addressing a Windows-specific race condition in file handling, with a secondary refactoring patch.

Patrick Steinhardt investigates a flaky test (t0610) on MinGW that occurs when trying to create lock files for reftable stacks. The root cause is Windows' behavior when opening files with O_CREAT|O_EXCL while another process has marked the same file for deletion - Windows returns ERROR_ACCESS_DENIED where Linux would return EEXIST. The main patch changes this error code translation to match Linux behavior, fixing the test flakiness.

The second patch is a minor refactoring that handles O_CLOEXEC in mingw_open_existing(), which the author noticed while debugging but acknowledges isn't strictly necessary. The changes are focused in compat/mingw.c with straightforward modifications to error handling logic.

The patch appears well-motivated by a concrete test failure and targets a Windows-specific edge case in file handling that affects Git's locking mechanism. The author appropriately seeks Windows experts' review given the platform-specific nature of the changes. The secondary refactoring seems like a reasonable cleanup but is clearly marked as optional.
