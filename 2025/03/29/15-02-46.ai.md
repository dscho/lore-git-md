This is a GSoC proposal draft for consolidating ref-related functionality into `git-refs`, representing the next step in the technical refinement phase. Zheng Yuting's updated proposal now incorporates prior feedback from Shejialuo and others, focusing on implementing 8 new subcommands (`list`, `exists`, `show`, `resolve`, `pack`, `update`, `delete`, `check-format`) to replace existing scattered reference management commands while maintaining backward compatibility.

The implementation strategy emphasizes code reuse through shared backend logic (particularly from `refs/files-backend.c`) and strict parameter compatibility with legacy commands. A detailed example shows how `git-refs pack` would replace `git-pack-refs`, including option parsing, testing plans leveraging existing test cases, and documentation updates. The proposal includes a comprehensive timeline allocating 3-4 weeks per subcommand implementation, with `git-refs pack` scheduled as the initial target.

Key technical constraints from earlier discussions are now explicitly addressed: no modification of original commands, guaranteed backward compatibility through preserved test suites, and avoidance of subprocess-based approaches. The proposal also introduces one enhancement - recursion depth control for symbolic reference resolution via `--max-depth` in `git-refs resolve`. Testing strategy remains an open question, with the current draft leaning toward creating parallel test suites while reusing scenarios from legacy command tests.

The background section establishes the author's relevant experience with C programming and prior Git contribution (a send-email optimization patch), though the bulk of their experience appears in networking and web development rather than version control systems. The proposal directly connects to Patrick Steinhardt's ref backend abstraction vision and GitLab issue #330's consolidation goals.
