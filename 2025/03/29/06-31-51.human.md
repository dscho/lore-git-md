This is a follow-up in an ongoing bug report about `git push --mirror` hanging with Azure DevOps repositories. The original issue involves Git processes freezing during push operation after the "Storing index (done)" message, with stack traces showing blocked read operations in transport-helper.c.

Akash S reports that Microsoft Azure DevOps has responded to their ticket by suggesting the issue is related to rate-limiting, though attempts to configure timeout settings (GIT_CURL_TIMEOUT, http.lowSpeedLimit/Time) have not resolved the hanging behavior. The email asks two key questions: whether there are other config options to force Git to timeout when hung, and whether Azure DevOps might be sending rate-limit headers that Git isn't properly handling.

The thread suggests this appears to be a server-specific issue, with Brian m. carlson previously noting that the process seems stuck waiting for server responses during push finalization. The new information about Azure DevOps' rate-limiting claim adds a potential explanation, though the ineffectiveness of timeout configurations raises questions about whether this is the true root cause. The issue remains unresolved, with the reporter seeking ways to either work around the hanging behavior or better understand the server-side behavior that might be causing it.
