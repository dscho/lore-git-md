Platform compatibility fix for gitk and git-gui on Cygwin, addressing a regression from Windows-specific security changes.

Mark Levedahl follows up on the Cygwin regression discussion, confirming that the `exec` and `open` function overrides were never intentionally applied to non-Windows platforms. He traces the issue back to historical git-gui code that was later removed (commit 7145c654), suggesting the current behavior in gitk is an oversight rather than a deliberate security measure. 

The email proposes to restrict the function overrides to Windows-only operation, which would resolve the Cygwin stack exhaustion while maintaining the intended Windows protections. Levedahl indicates he'll submit patches for both gitk and git-gui to implement this platform-specific behavior, treating Cygwin like other non-Windows systems by restoring native path handling functions.

Key technical points include the distinction between Windows security needs and Cygwin's POSIX-like behavior, the historical context from git-gui's codebase, and the planned approach of reverting non-Windows platforms to native functions. This aligns with Johannes Sixt's earlier suggestion and awaits confirmation from Johannes Schindelin about any overlooked security implications before implementation.
