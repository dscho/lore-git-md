Bugfix investigation for `git push --mirror` hangs with Azure DevOps. Brian M. Carlsen confirms the likely root cause is Azure DevOps failing to send the required protocol-mandated flush packet ("0000") during unsuccessful pushes, leaving Git waiting indefinitely. This matches the packet-level evidence provided by Akash S showing the missing packet in failed push attempts.

The analysis suggests two possible server-side failure modes: either Azure DevOps is omitting the flush packet entirely, or it's failing earlier in the sequence (missing "ok" responses for ref updates) which would prevent reaching the flush stage. Either way, the result is a protocol violation that Git currently handles poorly by hanging rather than timing out.

Carlsen recommends providing complete trace outputs of both successful and failed pushes to Azure DevOps engineers for further diagnosis. The issue appears specific to Azure DevOps's implementation of the Git protocol over HTTPS (using stateless-RPC), particularly affecting large repositories. While the immediate cause seems clear, the deeper question remains whether this represents an Azure-specific protocol deviation or a more general gap in Git's timeout handling for incomplete protocol sequences.
