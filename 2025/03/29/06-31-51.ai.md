This is a follow-up in the ongoing investigation of `git push --mirror` hanging with Azure DevOps repositories. The reporter has engaged with Microsoft support who attribute the issue to rate limiting, though the provided timeout configurations (GIT_CURL_TIMEOUT, http.lowSpeedLimit/Time) failed to make Git exit when hung. The email seeks clarification on two fronts: whether additional timeout mechanisms exist in Git to handle indefinite hangs, and whether Azure DevOps might be sending rate-limit headers that Git isn't properly handling. 

Key technical details include the process getting stuck in pkt-line operations waiting for server responses during push finalization, with the issue being intermittent but reproducible with large repos like elasticsearch/node. The reporter provides concrete reproduction steps using PAT authentication. 

The thread context shows this is likely server-specific behavior, with previous analysis suggesting either Azure DevOps peculiarities or local interception tools might be causing the transport layer to wait indefinitely for expected server responses that never arrive. The new questions focus on potential missing timeout handling in Git's HTTP transport when facing Azure's rate limiting, though the core issue remains that Git appears to wait forever rather than timing out when server responses stop arriving during the final push phase.
