Documentation patch for git-update-ref synopsis formatting.

This email from Junio C Hamano responds to Jean-Noël Avila's feedback about the proper formatting of alternative command invocations in the git-update-ref manpage. The key issue is that each distinct command form should be prefixed with "git update-ref" rather than continuing options from the previous line. The proposed diff shows the corrected formatting with each invocation on its own line, properly indicating these are separate usage patterns rather than continuations of a single command.

The change affects the SYNOPSIS section of git-update-ref.adoc, splitting what was previously three continuation lines into three separate command forms, each starting with "git update-ref". This follows standard manpage conventions for showing alternative invocation patterns. The patch is minimal and focused solely on documentation formatting, with no code changes.

This is part of the final polish for the batched reference updates series (v5 8/8) that has already received technical approval, addressing a documentation style point raised during review. The change maintains all functionality while making the usage patterns clearer in the documentation.
