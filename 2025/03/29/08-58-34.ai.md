This is a follow-up discussion in the SHA implementation reporting thread, focusing on naming and warning improvements. Christian Couder responds to Justin Tobler's patch series that adds SHA implementation details to `git version --build-options`, suggesting several refinements to the terminology and safety warnings.

Christian proposes alternative naming schemes for the SHA-1 variants, suggesting either using "SHA-1" alone when only one variant exists, or distinguishing between "SHA-1 for crypto" and "SHA-1 for non-crypto" when multiple are present. He also raises the important point about collision detection warnings, proposing that implementations without collision detection (like OpenSSL's SHA-1) should be clearly marked with a warning like "(No collision detection!!!)" in the output.

The email contains several typo corrections for Justin's original message (build→built, git-verison→git-version, currectly→currently), though these appear to be side comments rather than the main focus. The core discussion advances the naming debate from the original thread, moving beyond just "unsafe-SHA-1" vs "fast-SHA-1" to consider more nuanced labeling that could better communicate cryptographic safety properties to users. This suggests the naming discussion may be heading toward a solution that distinguishes cryptographic vs non-cryptographic use cases rather than just speed vs safety.
