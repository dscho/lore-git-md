This is a follow-up in the Cygwin regression thread, proposing a concrete fix for the gitk and git-gui path handling issue.

Mark Levedahl responds to Johannes Sixt's question about whether the Windows-specific exec/open overrides need to apply to all platforms. After examining git-gui's history, he finds no evidence these overrides were intentionally made platform-agnostic - they appear to have been carried over to non-Windows platforms by default rather than by design. He notes he previously removed similar problematic Cygwin code from git-gui in 2023.

Levedahl announces his intention to submit a fix that would restore native path search functions for non-Windows platforms in both gitk and git-gui. This aligns with the thread's emerging consensus to restrict the security measures to Windows-only operation. The proposed solution appears straightforward and builds on prior cleanup work in git-gui, suggesting it's likely to be uncontroversial. The patch should resolve the Cygwin stack exhaustion while maintaining Windows security protections.
