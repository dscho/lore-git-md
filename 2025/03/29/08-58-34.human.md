This is a follow-up discussion on the SHA implementation reporting feature, focusing on naming and warning improvements.

Christian Couder responds to Justin Tobler's patch series that adds SHA implementation details to `git version --build-options`. While acknowledging the usefulness of the feature, Christian suggests several refinements to the output format and warnings.

He first corrects some typos in Justin's cover letter (build→built, git-verison→git-version, currectly→currently). Then he proposes alternative naming schemes for the non-cryptographic SHA-1 variants, suggesting either:
1. Using just "SHA-1" if a single algorithm handles everything
2. Distinguishing between "SHA-1 for crypto" and "SHA-1 for non-crypto" when different implementations are used

Christian also raises an important safety consideration - whether Git should more prominently warn users when a non-collision-detection algorithm is being used for cryptographic purposes. He suggests output like "SHA-1: OpenSSL (No collision detection!!!)" with corresponding documentation.

The discussion continues to refine both the terminology (balancing accuracy with user experience) and safety warnings around SHA-1 usage, building on the technical foundation from Justin's patches. The thread shows active consideration of how to best present potentially concerning security information to end users.
