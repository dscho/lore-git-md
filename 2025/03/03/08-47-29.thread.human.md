Patrick Steinhardt continues his systematic effort to eliminate `the_repository` global variable usage across Git's object APIs with patch 8/12 in the series. This installment focuses on `object-file-convert.c`, which handles hash algorithm translations for commits, trees, and tags when repositories with different hash algorithms interact.

The patch adds explicit `struct repository*` parameters to `convert_object_file()` and its internal helpers, removing their dependency on global state. All callers in builtin/tag.c, commit.c, and object-file.c are updated to pass the repository context through. The changes follow the established pattern from earlier patches in the series - straightforward mechanical conversions that maintain existing behavior while making dependencies explicit.

With this patch, the series has now converted:
1. Core object file operations
2. Pack writing and verification
3. Revindex handling  
4. Bitmap generation
5. Object conversion between hash algorithms

Review participation remains strong, with Justin Tobler, Karthik Nayak, and Eric Sunshine providing substantive feedback on previous patches. The work continues to demonstrate careful, incremental progress toward the long-term goal of removing implicit repository state, while strengthening the foundation for future work like pluggable object database backends. Four patches remain in the series, covering object verification APIs, delta-islands, and final conversions in object-file.c.
