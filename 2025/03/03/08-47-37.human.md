This is part 8/12 of the ongoing `the_repository` removal effort, focusing on `object-file-convert.c`. Patrick Steinhardt continues the series by eliminating global repository usage from object file conversion functions.

The patch modifies `convert_object_file()` and its internal helpers to accept a `struct repository` parameter instead of relying on `the_repository`. This affects tree, tag, and commit object conversions, which now use the passed repository for hash algorithm lookups. The changes ripple through several callers in `builtin/tag.c`, `commit.c`, and `object-file.c`, all of which now explicitly pass `the_repository` (though this maintains the same behavior for now).

The conversion follows the established pattern seen in earlier parts of the series - methodically removing implicit dependencies while maintaining functionality. The changes are straightforward and well-contained, touching only the necessary call sites. This continues the broader effort to make repository dependencies explicit, though as with previous patches, it doesn't yet address the deeper question of when repository-specific vs process-wide behavior is appropriate.
