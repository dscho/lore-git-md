This is part 2/12 of the `the_repository` removal series, focusing on object-related APIs. The patch refactors several functions in `object.c` and their callers to explicitly take a `struct repository*` parameter instead of implicitly using the global `the_repository`. Key changes include:

- Converting `get_max_object_index()` and `get_indexed_object()` to take repository parameters (now `repo_get_*` variants)
- Adding repository parameter to `parse_object_or_die()`
- Making `clear_object_flags()` repository-aware
- Updating 15 call sites across various commands (fsck, grep, pack-objects, etc.) to pass `the_repository` explicitly

The changes are mechanical but widespread, touching object lookup, parsing, and flag management. The patch maintains existing behavior while making repository dependencies explicit - a key goal of the larger series. Call sites that were already repository-aware now use their context's repository rather than falling back to `the_repository`.

This continues the pattern seen in part 1 (csum-file refactoring), applying similar treatment to core object infrastructure. The changes are straightforward with no expected behavior differences, though the volume of call site updates (48 insertions, 44 deletions across 15 files) suggests careful review of the mechanical transformations would be prudent.
