This is a technical clarification in the ongoing incremental MIDX bitmap discussion, specifically addressing documentation questions about pseudo-pack ordering.

Patrick Steinhardt seeks clarification on how object ordering works in the incremental MIDX design, particularly regarding duplicate objects case. Taylor Blau explains that the pseudo-pack order determines bitmap bit positions but emphasizes that duplicates are already been filtered out by the MIDX layer design - each MIDX stores only one copy of an object, and the incremental design prevents objects from appearing in multiple layers of the chain.

The exchange highlights an important implementation detail that wasn't immediately obvious from the documentation: the deduplication happens before the pseudo-pack ordering is applied, meaning the comparison between o1 and o2 in the documentation will always be between distinct objects. This clarification helps prevent potential misunderstandings about how object selection works across MIDX layers.
