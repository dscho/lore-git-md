[PATCH v2 0/12] object: reduce use of `the_repository` in object APIs

Series by Patrick Steinhardt systematically eliminates global `the_repository` usage in object-related APIs, now covering patches 1-8/12 (csum-file.c, object.c, pack-write.c, pack-check.c, core.bigFileThreshold conversion, pack-revindex.c, pack-bitmap-write.c, and object-file-convert.c). The work builds on previous efforts to remove implicit repository state while maintaining behavior.

Key technical progress:
1/12: csum-file.c conversion complete - all hashfile operations now take explicit `struct git_hash_algo*`
2/12: object.c conversion - core object functions now take `struct repository*`
3/12: pack-write.c conversion - all pack-writing functions converted
4/12: core.bigFileThreshold moved to `struct repo_settings`:
- New accessors: `repo_settings_get/set_big_file_threshold()`
- 15 files updated (archive, diff, pack operations, object streaming)
- Maintains 512MB default when unconfigured
- Test adjustments in t1050-large.sh for new config loading behavior
5/12: pack-check.c conversion:
- All pack checksum verification and index validation now uses explicit `struct repository*`
- Removes `USE_THE_REPOSITORY_VARIABLE` define
- Updates big file threshold checks to use repo-specific settings
6/12: pack-revindex.c conversion:
- Removes `USE_THE_REPOSITORY_VARIABLE` define
- Replaces `the_hash_algo` with `p->repo->hash_algo`
- Introduces `ridx_min_size()` helper for hash-algorithm-aware calculations
- Updates revindex loading/verification to take explicit hash algorithm
- Modifies trace2 calls to use repository context
7/12: pack-bitmap-write.c conversion:
- Adds `repo` field to `struct bitmap_writer`
- Updates all bitmap writing operations to use explicit repository context
- Converts tree lookups, progress reporting, and hash operations
- Modifies bitmap header writing to use repository-specific hash algorithms
- Maintains existing bitmap generation behavior while removing global state
8/12: object-file-convert.c conversion:
- Adds `struct repository*` parameter to `convert_object_file()`
- Propagates repository context through all internal conversion functions
- Updates callers in builtin/tag.c, commit.c, and object-file.c
- Removes `USE_THE_REPOSITORY_VARIABLE` define
- Maintains hash algorithm translation behavior for commits, trees/tags
