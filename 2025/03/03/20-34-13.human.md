This is the final patch in a series implementing partial reference transactions, adding the user-facing `--allow-partial` flag to `git update-ref`. The flag allows stdin-mode transactions to continue processing even if individual reference updates fail, with rejected updates reported in a structured format.

The patch has undergone significant review, with Phillip Wood suggesting two improvements: (1) moving the partial-failure control from a global flag to a per-transaction setting (similar to how "no-deref" works), and (2) removing unnecessary output flushing and `-z` mode handling for rejection messages. Karthik acknowledges these as good ideas but notes the current implementation serves mainly to demonstrate viability before extending the feature to `git-fetch` and `git-receive-pack`.

The implementation is now complete after addressing all major design questions raised during review, including error message translation policy (settled on untranslated) and output format consistency. The series represents a significant refactoring of Git's reference transaction system while maintaining atomicity guarantees where needed.
