This RFC patch series introduces a new `--subject-extra-prefix` option for `git format-patch`, designed to help participants in mentoring programs like GSoC and Outreachy clearly mark their contributions in email subjects. The series currently stands at 4 of 6 planned patches, with the implementation following a careful, incremental approach.

The first three patches established the command-line interface, added constraints to prevent incompatible combinations (like `--keep-subject`), and introduced a new `subject_extra_prefix` field in `struct rev_info`. The latest patch (4/6) completes the plumbing by copying the parsed extra prefix value into this new field, following the same pattern used for the standard subject prefix. This sets up the infrastructure needed for the actual subject generation changes coming in subsequent patches.

So far the series appears technically sound, with each change logically building on the last while keeping the scope focused. The remaining work will modify the subject construction logic in `log-tree.c` to handle three components (extra prefix + standard prefix + subject) and add comprehensive tests. The discussion is just beginning, and key questions remain about whether this functionality belongs in core Git versus wrapper scripts, and whether the proposed option name (`--subject-extra-prefix`) is optimal.
