Here's the updated human-readable thread summary:

This thread tracks a Windows-specific regression investigation following a Git 2.48.1 upgrade, originally reported by Jörg Hohwiller with involvement from Johannes Schindelin (Git for Windows maintainer). The core issue involves persistent phantom lock file errors during `git pull` operations, where Git reports non-existent `.lock` files (e.g., `refs/remotes/origin/bugfix/XY-74488.lock`). Testing with the latest Git for Windows snapshot (2.49.0) has definitively ruled out the initial hypothesis that this was related to a known ReFS drive regression.

The problem affects both command-line usage and GUI clients (IntelliJ, git-fork), with git-fork frequently freezing and requiring process termination. Johannes Schindelin's workaround of manually removing the non-existent lock files remains the only known mitigation, though Hohwiller finds this impractical for daily use. A secondary issue of missing status output with exit code 1 (previously fixed in 2.47.1) appears less critical given the workflow-blocking nature of the lock file errors.

The investigation has progressed from initial reporting through hypothesis testing to confirming this is a distinct issue, but root cause analysis remains stalled. Key missing diagnostic information includes complete GIT_TRACE output, FSCache configuration details, and exact Windows version specifics. The GUI client freezing behavior adds a new symptom that may help pinpoint the underlying issue.
