Testing with the latest Git for Windows snapshot (2.49.0) confirmed this is distinct from the known ReFS drive regression. The lock file issue affects both command-line Git and GUI clients (IntelliJ, git-fork), with git-fork exhibiting new freezing behavior requiring process termination. The only known workaround is manually deleting the reported `.lock` files, though this is impractical for regular use.

A secondary issue involves missing status output with exit code 1, previously fixed in 2.47.1 but possibly resurfacing. Now a third symptom has emerged: "fatal: failed to run reflog" errors during pull operations, accompanied by "error: task 'gc' failed" messages. While pulls still complete, these new errors suggest problems with Git's garbage collection mechanism during routine operations. All issues persist across versions from 2.48.1 through the latest 2.49.0 snapshot.
