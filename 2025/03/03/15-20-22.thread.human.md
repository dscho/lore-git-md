This thread tracks multiple serious Windows-specific regressions that appeared between Git 2.46.0 (working) and 2.48.1+ (broken), reported by Jörg Hohwiller and investigated with help from Johannes Schindelin (Git for Windows maintainer). The issues include spurious lock file errors during `git pull`, "failed to run reflog" errors, ref lock failures showing SHA mismatches during fetch, and random "connection reset by peer" failures during clone operations. The problems affect both CLI and GUI clients (IntelliJ, git-fork) and persist in Git 2.50.0.

Debugging efforts have been challenging - while downgrading to 2.46.0 reliably resolves the issues, attempts to build a debug-enabled version of newer Git to investigate further hit a snag when the initial instructions missed a crucial `sdk cd git` step. Johannes has now provided corrected build instructions to unblock this, specifying how to properly set up the Git source tree in the Git for Windows SDK environment and switch to the v2.50.0.windows.2 commit. The immediate goal is to obtain useful backtraces when the ref lock errors occur, which should help pinpoint whether the root cause lies in filesystem interaction, ref handling, or possibly bundled OpenSSL changes between the working and broken versions. The version-boundary reproducibility strongly suggests a regression, but the exact mechanism remains unclear without these debugging traces.
