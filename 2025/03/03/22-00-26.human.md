This is part 3 of a 6-patch RFC series introducing a `--subject-extra-prefix` flag for `git format-patch` to help mentoring program participants clearly identify their contributions in email subjects.

The patch adds infrastructure support for the new feature by extending `struct rev_info` with a `subject_extra_prefix` field, initialized to NULL. This follows the pattern of the existing `subject_prefix` field and will be used in subsequent patches to construct three-part email subjects (extra prefix + standard prefix + subject) when the new flag is used.

The change is straightforward and well-contained, touching only `revision.h` to add the new field. It maintains consistency with Git's existing code structure where subject prefix handling lives in `rev_info`. The patch keeps the series' incremental approach by first establishing the data structure before implementing the behavior in later patches.

This appears to be a technically sound addition that properly prepares for the subject construction changes coming in patch 4. The implementation choice to store this in `rev_info` rather than passing it through function parameters makes sense given how subject prefixes are already handled in the codebase.
