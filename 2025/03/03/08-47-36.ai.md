This is part 7/12 of the ongoing `the_repository` removal series, focusing on the pack-bitmap-write subsystem. The patch converts `pack-bitmap-write.c` to stop using the global `the_repository` variable by storing the repository context in the `bitmap_writer` struct instead.

Key changes include:
- Adding a `repo` field to `struct bitmap_writer` to carry repository context
- Removing the `USE_THE_REPOSITORY_VARIABLE` define
- Converting all `the_repository`/`the_hash_algo` references to use `writer->repo` and its hash algorithm
- Updating trace2 calls, progress reporting, and hash calculations to use the repository from the writer context
- Modifying tree and commit lookups to use the repository parameter

The changes follow the established pattern seen in previous patches of the series, making repository dependencies explicit while maintaining existing behavior. The patch touches core bitmap writing functionality including commit selection, bitmap building, and final bitmap file writing. All conversions leverage the repository context already available at call sites through the writer initialization.

This continues the systematic elimination of global state from Git's object handling code, with the bitmap writing subsystem now properly tracking its repository context. The changes are mechanical but important for the larger effort to make repository handling more explicit and support pluggable object storage backends.
