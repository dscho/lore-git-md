This is part 4/12 of the `the_repository` removal series, focusing on moving the "core.bigFileThreshold" config setting from a global variable into `struct repo_settings`. The patch converts the big file threshold handling to be repository-specific, addressing potential issues when working with multiple repositories that have different threshold values in a single process.

The change removes the global `big_file_threshold` variable and replaces it with repository-specific storage in `repo_settings`. The threshold value is now lazily computed and cached when first accessed via the new `repo_settings_get_big_file_threshold()` function. A corresponding setter function `repo_settings_set_big_file_threshold()` is added for cases like `fast-import` that need to modify the value.

The patch updates 15 files that previously referenced the global variable, mostly replacing direct `big_file_threshold` access with calls to the new repository-aware getter. The changes are mechanical but widespread, affecting blob handling in archive, diff, pack, and streaming operations. The test suite is updated to verify the config validation still works, though the test modified is somewhat tangential to the main change.

This follows the series' pattern of making repository dependencies explicit while maintaining existing behavior. The change is independently useful for multi-repo scenarios even outside the larger pluggable ODB effort. The implementation is straightforward with clear mechanical conversions, though some reviewers might question whether all these call sites truly need repository-specific behavior versus keeping a process-wide threshold.
