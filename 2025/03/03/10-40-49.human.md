This is a follow-up in the `git cat-file` filtering enhancement series, specifically addressing the naming convention debate for the new `--filter` option.

Patrick Steinhardt confirms he will adopt Junio Hamano's authoritative recommendation to use `--filter=` for consistency with other Git commands (`rev-list`, `pack-objects`, `repack`, `clone`), rather than the proposed `--objects-filter`. Junio provided historical context showing that `--filters` (for smudge/clean operations) and `--filter=` (for object filtering) have always been distinct namespaces in Git, and that maintaining this established pattern is more important than avoiding similar-looking option names.

This resolves the last major interface design question in the series, clearing the way for implementation work to proceed. The decision maintains consistency with Git's existing CLI conventions while acknowledging that a more explicit name like `--object-filter=` might have been preferable if designing the feature from scratch today. With this naming settled, the series can now focus on the remaining technical challenges of bitmap integration and performance validation.
