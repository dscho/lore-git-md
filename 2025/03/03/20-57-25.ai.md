Test modernization feedback on path checking helpers. Eric Sunshine provides review comments on Prachit Ingle's patch converting shell path tests to Git test helpers, identifying several issues with the current approach.

The key technical problems identified are:
1. The test helpers (`test_path_exists`, `test_path_is_file`, etc.) are designed for assertions within `test_expect_success` blocks, not for general control flow. Their error reporting behavior makes them inappropriate for conditional logic where a path might legitimately not exist.
2. The patch incorrectly includes changes to chainlint test files, which test a separate tool's syntax rather than Git's behavior and should not be modified.
3. The only valid change in the current patch is in t/perf/p5302-pack-index.sh where `test -f` is correctly replaced with `test_path_is_file` within a proper test assertion context.

The review suggests the patch needs significant restructuring to:
- Remove all chainlint test modifications
- Revert most other conversions except those in proper assertion contexts
- Focus only on valid use cases where test helpers replace shell tests within `test_expect_success` blocks

This feedback follows up on Mahendra Dani's earlier review about proper test helper usage, reinforcing that the project's test conventions require these helpers to be used only for assertions, not control flow. The patch will need to be substantially revised to address these concerns.
