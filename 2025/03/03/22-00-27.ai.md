This is part 4 of a 6-patch series introducing a `--subject-extra-prefix` flag for `git format-patch`, aimed at helping mentoring program participants clearly identify their contributions in email subjects.

The patch focuses on plumbing the new `--subject-extra-prefix` value into the `rev_info` structure. It's a straightforward change that copies the `extra_prefix` string (parsed from the command line in earlier patches) into the `subject_extra_prefix` field of `struct rev_info` that was added in patch 3. This happens right before the existing subject prefix handling in `cmd_format_patch()`.

The implementation is minimal - just a single line addition that follows the same pattern used for the standard `subject_prefix`. This maintains consistency with how other subject-related options are handled in the format-patch machinery. The placement ensures the extra prefix will be available when the actual email subject generation happens (which will be handled in a subsequent patch).

Key technical details for future reference:
- Modifies `builtin/log.c` to populate the `subject_extra_prefix` field
- Field was added to `struct rev_info` in patch 3/6
- Value comes from `extra_prefix` variable set by option parsing
- Positioned alongside existing `subject_prefix` assignment
- Part of the logical sequence to implement three-component subject lines (extra prefix + standard prefix + subject)

This continues the series' incremental approach, with each patch building on the previous ones while keeping changes focused and reviewable. The change is straightforward plumbing with no apparent complications or edge cases to handle at this stage.
