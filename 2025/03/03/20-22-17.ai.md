This is the final patch in the 7-part series implementing partial reference transactions, focusing on the user-facing `--allow-partial` flag for `git update-ref`'s stdin mode. The patch adds documentation and implementation for the flag that enables partial success in reference updates, where user-input errors (invalid refs, bad OIDs) don't abort the entire transaction while system errors (I/O failures) still do.

Key technical details include:
- The `--allow-partial` flag is added to the command-line interface and documented in git-update-ref.adoc
- Error reporting distinguishes between user errors (skippable) and system errors (fatal)
- Current implementation treats F/D conflicts as fatal, though Patrick Steinhardt notes this may need revisiting for integration with fetch/receive-pack
- Error messages are kept untranslated as per Git's plumbing conventions
- The patch includes a `print_rejected_refs()` helper that categorizes different transaction failure modes
