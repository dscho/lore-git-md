This is a performance discussion in the ongoing thread about fixing bash completion for remote names containing slashes. SZEDER Gábor weighs in with important Windows-specific performance concerns about the current implementation that calls `git for-each-ref` for each remote.

The key points are:
- On Git for Windows, each fork/exec operation is about 10x slower than Linux, making the current approach problematic even with just 4-5 remotes (could exceed 1 second per TAB completion)
- SZEDER strongly advises against parallelizing the forks as proposed, warning this could "forkbomb" the system
- Instead suggests exploring whether `git for-each-ref` itself could be enhanced to strip remote prefixes natively via a new format specifier like `%(refname:strip=remote)`

This moves the performance discussion forward by:
1. Providing concrete Windows timing data showing the current approach is untenable there
2. Vetoing parallelization as too dangerous
3. Proposing a potentially cleaner solution that would move the work into Git proper rather than shell scripting

The thread continues to balance correctness (already demonstrated in the patches) with performance considerations, now with platform-specific realities in view. SZEDER's input suggests the current patches may need significant rework to be viable on Windows.
