This is the final patch in a 7-part series implementing partial reference transactions, adding the user-facing `--allow-partial` flag to `git update-ref`. The patch concludes the implementation with command-line interface and documentation.

The patch adds a `--allow-partial` flag to `git update-ref --stdin` mode, allowing transactions to continue even when individual reference updates fail. The implementation builds on the refactored reference transaction backend from earlier patches. Rejected updates are reported in a structured format (human-readable with LF or machine-readable with -z), while successful completion is signaled by "commit: ok". 

Key implementation details include:
- The `print_rejected_refs()` helper categorizes different failure modes (name conflicts, invalid values, etc.)
- Error messages are untranslated per thread consensus
- Output flushing is optimized to avoid per-line flushes
- The flag is transaction-level rather than per-update, though Phillip Wood suggests considering per-transaction control via stdin commands

The discussion reveals two potential follow-up areas:
1. Whether to support per-transaction control via stdin commands (like "start allow-partial") rather than a global flag
2. Future integration with `git-fetch` and `git-receive-pack` to leverage partial transactions

The patch incorporates review feedback from Phillip Wood regarding output formatting and flushing behavior. With this final piece, the series achieves its goal of enabling controlled partial reference updates while maintaining clear error reporting. The implementation demonstrates careful attention to both plumbing conventions and practical use cases.
