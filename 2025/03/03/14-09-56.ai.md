This is a discussion about cross-compilation support in Git's Meson build system, specifically regarding the distinction between build-time and target-host binaries. The thread context shows Patrick Steinhardt's initial patch that introduced explicit `native: true/false` parameters to `find_program()` calls to properly handle cross-compilation scenarios.

Peter Seiderer responds with a counter-proposal, arguing that using Meson's cross-file mechanism for specifying target-host binaries (like `sh`, `python`, and `perl`) is conceptually wrong. His key points are:

1. The cross-file's `[binaries]` section is meant for tools needed during compilation (like compilers and linkers), not for target system binaries whose paths will be embedded in Git.

2. At compile/configure time, the target system's layout is typically unknown, making `find_program()` for target binaries problematic.

3. He suggests an alternative approach using a dedicated configure option for cross-compilation with sensible defaults for native builds.

The technical context involves:
- Key binaries affected: `sh`, `python`, `perl`
- Build system files modified: `meson.build`, `Documentation/meson.build`, `gitweb/meson.build`, `templates/meson.build`
- New variables introduced: `target_shell`, `target_python`, `target_perl`

1) Continue with the current approach of using `native: false` with cross-file`[binaries]` overrides
2) Adopt Peter's proposal for a separate cross-compile configuration option
