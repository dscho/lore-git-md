This is part 4/12 of the ongoing series to reduce `the_repository` usage, focusing on moving the "core.bigFileThreshold" config setting from a global variable into per-repository settings. The patch converts the big file threshold handling to use `struct repo_settings` instead of a global variable, addressing potential issues when working with multiple repositories that have different threshold values. The change affects 15 files across various subsystems that check blob sizes, including archive, diff, pack operations, and streaming. 

The conversion follows the established pattern of the series by making repository dependencies explicit while maintaining existing behavior. The threshold is now lazily loaded and cached per-repository via new `repo_settings_get/set_big_file_threshold()` functions. The patch includes mechanical updates to all callers that previously accessed the global variable directly.

This is a straightforward refactoring that removes another piece of global state while being a clear improvement over the previous implementation. The changes are focused and well-contained, with test coverage confirming the config validation still works. As with other patches in this series, it moves Git incrementally closer to better libification by reducing implicit dependencies.
