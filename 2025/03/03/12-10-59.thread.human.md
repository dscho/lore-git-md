This thread discusses improvements to Git's Meson build system to better support cross-compilation scenarios, specifically around how to properly distinguish between build-time tools (needed during compilation) and target-host binaries (that get embedded in the final Git executable). 

The discussion began with Patrick Steinhardt's patch introducing explicit `native: true/false` parameters in `find_program()` calls, creating separate variables for target system binaries (`target_shell`, `target_python`, `target_perl`), and updating configuration templates accordingly. This approach aimed to maintain backward compatibility while enabling proper cross-compilation support.

Peter Seiderer has raised significant concerns about this approach, arguing that Meson's cross-file mechanism is being misused. He contends that the `[binaries]` section should only specify compilation tools (like compilers), not target system binaries whose paths will be embedded in Git. He points out that the target system's layout is typically unknown at configure time, making `find_program()` problematic for target binaries. Instead, he proposes a dedicated configure option for cross-compilation with sensible defaults for native builds.

The technical debate centers on key binaries (`sh`, `python`, `perl`) and affects several build system files. The discussion has reached a fundamental design question about the proper Meson idioms for cross-compilation, with two distinct approaches now on the table. The thread awaits further technical discussion to determine whether to proceed with the original approach, adopt Peter's alternative, or find some middle ground.
