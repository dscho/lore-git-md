This thread addressed how to document build-time breaking changes for deprecated repository layout features (specifically `.git/branches` and `.git/remotes` directories) when building with `WITH_BREAKING_CHANGES`. The discussion reached consensus on using conditional documentation sections controlled by a build configuration attribute, with Phillip Wood implementing the agreed solution.

The final patch implements this by introducing a new AsciiDoc attribute `with-breaking-changes` that controls the visibility of deprecated feature documentation. It modifies the Makefile and Meson build systems to set this attribute when configured, and updates `gitrepository-layout.adoc` with conditional blocks. The implementation avoids a double negative by using positive formulation (`ifndef::with-breaking-changes[]`), matching the approach favored by Patrick Steinhardt and confirmed by Junio Hamano.

Phillip notes that a future series will rename the test prerequisite from `WITHOUT_BREAKING_CHANGES` to match this new scheme. With all technical and naming issues resolved and the implementation now complete in Phillip's patch, this thread has effectively concluded its work, establishing a reusable pattern for documenting build-time deprecated features.
