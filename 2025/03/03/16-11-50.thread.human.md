This thread addressed how to document build-time breaking changes for deprecated repository layout features (specifically `.git/branches` and `.git/remotes` directories). The discussion centered on the documentation approach and naming convention for a new build configuration attribute that would control whether these deprecated features appear in the docs.

Phillip Wood initially proposed the change but raised concerns about the double-negative formulation (`without-breaking-changes`). Junio Hamano suggested using a positive formulation instead (`with-breaking-changes`), which Patrick Steinhardt supported. After discussion, Phillip agreed to this approach and will implement it in his pending patch series (#1863), updating both the test prerequisite name and documentation attribute to use `WITH_BREAKING_CHANGES`.

The solution involves conditional documentation sections wrapped in `ifdef::with-breaking-changes[]` blocks, with parallel support added in both the Makefile and Meson build systems. Junio has now confirmed the consensus and acknowledged Phillip's implementation plan, effectively closing the discussion. This establishes a clear pattern for how to document future build-time feature deprecations in Git's documentation.
