This thread has been discussing how to document build-time breaking changes for deprecated repository layout features (specifically `.git/branches` and `.git/remotes` directories) when building with `WITH_BREAKING_CHANGES`. The technical approach of using conditional documentation blocks controlled by build configuration was quickly agreed upon, but the discussion focused on naming conventions for the conditional attribute.

Phillip Wood initially raised concerns about the awkward double-negative formulation (`without-breaking-changes` leading to `ifdef::!without-breaking-changes[]`). Junio Hamano and Patrick Steinhardt both favored a positive formulation (`with-breaking-changes`), which Phillip has now confirmed he will implement in his pending patch series (pull request #1863). 

The thread has reached consensus on all technical and naming aspects, with Phillip planning to:
1. Use the positive `WITH_BREAKING_CHANGES` formulation
2. Update both the test prerequisite name and documentation attribute accordingly
3. Implement these changes in his upcoming patch series

With all participants raising no further objections and the technical approach remaining uncontested, this discussion appears resolved and ready for implementation. The changes will affect the build system (both Makefile and Meson) and documentation, maintaining consistency with prior test infrastructure while improving readability through clearer naming.
