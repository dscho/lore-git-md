Refactoring patch for the `git-diff-pairs` plumbing command infrastructure.

This is the foundational patch in the final v5 iteration of the `git-diff-pairs` series, which refactors core diff queue operations to enable subsequent functionality. The change splits `diff_addremove()` and `diff_change()` into two layers: low-level queue operations that return the created `diff_filepair`, and existing wrapper functions that maintain current behavior. This prepares for later patches that need to modify filepairs after queueing.

The patch maintains backward compatibility while enabling the status preservation mechanism needed for batch processing. Junio confirms the change is a safe no-op for existing code paths and approves the approach of keeping the original functions as wrappers. The separation also properly handles cases where diff options perform pruning operations that don't use the queue at all.

Key technical details:
- Introduces new `diff_queue_addremove()` and `diff_queue_change()` functions that return `diff_filepair*`
- Preserves existing `add_remove_fn_t` and `change_fn_t` callback signatures
- Documents the new functions in diff.h
- Maintains current memory management patterns
- Follows Git's established pattern of exposing low-level operations while keeping compatibility wrappers

This mechanical refactoring completes the first of four planned implementation components for the series, with all architectural decisions now finalized and no outstanding objections from reviewers. The change enables the subsequent patches to implement the core command functionality, flush control, and status resolution features while maintaining pipeline safety and backward compatibility.
