Refactoring patch in the `the_repository` removal series, focusing on hash algorithm implementation separation.

This is patch 10/12 in Patrick Steinhardt's series to reduce `the_repository` usage in object APIs. The patch moves all hash algorithm implementation code from `object-file.c` to a new `hash.c` file, keeping the exact same functionality but improving code organization. The change is purely structural - 283 lines moved to the new file with 277 lines removed from `object-file.c`, plus build system updates.

Key technical details:
- Preserves all existing hash algorithm implementations (SHA-1 and SHA-256)
- Maintains identical behavior for all hash operations
- Keeps the same static oid constants (empty_tree_oid, empty_blob_oid, null_oid)
- Retains all hash algorithm lookup functions (by name, by format_id, by length)
- Continues supporting "unsafe" variants of hash operations

The patch follows the series' pattern of mechanical but careful changes, though this one focuses on code organization rather than direct `the_repository` elimination. The separation makes the hash subsystem more self-contained and easier to locate, which may help future work on the ODB abstraction. The change is low-risk since it doesn't modify behavior, only file organization.
