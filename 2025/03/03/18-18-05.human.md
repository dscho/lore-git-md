This is a follow-up discussion in the documentation patch thread about conditionally including deprecated repository layout features. Junio Hamano responds to Phillip Wood's concerns about the double-negative naming scheme (`without-breaking-changes`) used for the new Asciidoc attribute.

The core issue revolves around the awkwardness of the current naming, which requires using `ifdef::!without-breaking-changes[]` syntax - a double negative that could confuse readers. Junio suggests exploring an alternative naming approach using `with-breaking-changes` instead, which would make the conditionals more straightforward (`ifdef::with-breaking-changes[]`).

The discussion remains focused on documentation build configuration, with both participants agreeing the current implementation works technically while acknowledging the suboptimal naming. This appears to be a minor but important polish point before finalizing the patch series about phasing out legacy repository layout features. The actual content being conditionally included (documentation for `.git/branches` and `.git/remotes`) remains uncontroversial.
