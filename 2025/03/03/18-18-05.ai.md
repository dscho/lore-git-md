This is a follow-up discussion in the documentation patch thread about conditional build-time documentation for deprecated repository layout features. Junio Hamano responds to Phillip Wood's concerns about the double-negative naming scheme (`without-breaking-changes`) used for the new Asciidoc attribute that controls whether documentation for legacy features appears.

Hamano agrees with Wood's reservations about the awkward double-negative formulation (`ifdef::!without-breaking-changes[]`), noting it could become confusing as future breaking changes may not all be removals. He suggests exploring an alternative positive formulation (`!with-breaking-changes`) that would avoid the double negative while maintaining consistency with the build configuration.

The technical implementation remains unchanged in this email - it still shows the conditional blocks wrapping the documentation for `.git/branches` and `.git/remotes` directories in `gitrepository-layout.adoc`. The core issue being discussed is purely about the naming convention for the build-time flag, with both parties acknowledging the current formulation is suboptimal but needing to balance clarity with consistency to the test prerequisite naming.

This continues the thread's focus on documentation presentation for deprecated features while shifting the discussion toward improving the conditional syntax's readability. The underlying build system changes (Makefile and meson.build modifications) are not contested, only the naming scheme for the new attribute.
