This is a performance optimization discussion for the bash completion remote-ref handling patch series. SZEDER Gábor weighs in on David Mandelberg and Phillip Wood's earlier discussion about scaling concerns with the current implementation that calls `git for-each-ref` per remote.

Key technical points raised:
- On Windows (where fork/exec is expensive), the current approach becomes noticeably slow with just 4-5 remotes (~1 second delay per TAB completion)
- Strongly advises against parallelizing the `for-each-ref` calls due to forkbomb risk
- Proposes a more fundamental solution: adding a `%(refname:strip=remote)` format specifier to `git for-each-ref` itself
  - Would be faster than any shell/sed filtering
  - Avoids metacharacter escaping complexity
  - Would benefit all completion scenarios, not just this specific case

The email reinforces Phillip Wood's earlier concerns about process overhead while offering a novel direction that could solve both the performance and scaling issues at the plumbing level rather than in bash. This suggests the completion script fixes may need to wait on core Git changes, though the discussion remains active about finding an acceptable interim solution.
