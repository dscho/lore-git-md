This is a follow-up in the reftable decoupling effort (ps/reftable-sans-compat-util series), specifically addressing the Windows-specific memory allocator issue that was blocking the series.

Patrick Steinhardt confirms the series is now ready to merge as-is, noting that the final MinGW-specific memory allocator mismatch (which caused SIGTRAP failures in Windows unit tests) has been resolved by moving mimalloc override declarations to `compat/posix.h`. The fix was verified through successful CI runs on Git for Windows' `shears/seen` branch, as reported by Johannes Schindelin in the parent email.

The key technical detail is that the mimalloc-related code causing the Windows build issues exists only in Git for Windows' downstream codebase, meaning no further changes are needed in the upstream patch series. This clears the last known technical issue with the reftable decoupling work, which removes Git-specific dependencies from the reftable code for better portability. The series represents a significant step in the long-term ref backend abstraction work and is prerequisite for other reftable-related patches.
