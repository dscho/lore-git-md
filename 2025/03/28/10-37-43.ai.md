This is a bug report describing a `git push --mirror` operation hanging indefinitely when pushing large repositories to Azure DevOps. The issue occurs after the "Storing index (done)" message appears, with the process becoming unresponsive despite various attempted workarounds.

The reporter provides detailed technical information including Git version (2.48.1), reproduction steps using large open-source repositories (elasticsearch/node), and multiple failed mitigation attempts involving HTTP configuration tweaks (http.postBuffer, GIT_CURL_TIMEOUT, http.maxRequests). Process stack traces show the hang occurs in transport-helper.c during push_refs_with_push, with multiple processes stuck in read() operations.

Key technical details for future reference:
- The issue appears Azure DevOps-specific and intermittent
- Processes involved: git, git-remote-https, git send-pack
- Stack traces point to transport-helper.c and pkt-line.c
- All attempted HTTP/timeout configurations failed to resolve
- TLS connections appear active but unresponsive (TLSv1.3 traffic visible)

The report is thorough with process dumps and strace outputs, suggesting a potential protocol-level hang during the finalization phase of mirror pushes to Azure DevOps. The issue appears to be server-side or protocol-specific rather than a general Git bug, given the Azure-specific context and that standard HTTP configuration tweaks don't help.
