This thread investigates a persistent `git push --mirror` hang when pushing large repositories to Azure DevOps, first reported in Git 2.48.1. The core issue occurs after "Storing index (done)" where the process freezes indefinitely, with stack traces showing blocked reads in transport-helper.c. Packet-level analysis by Akash S revealed the hang happens when Azure DevOps fails to send the protocol-mandated final "git flush message 0000" packet during unsuccessful pushes, leaving Git waiting indefinitely.

Brian M. Carlson has now confirmed these findings, noting the missing flush packet violates Git protocol requirements. The discussion has narrowed to two scenarios: either Azure DevOps omits the flush packet entirely, or fails earlier by not sending all required 'ok' responses before the flush. The consensus is this represents a server-side protocol compliance issue rather than a client timeout problem, as all attempted HTTP/timeout configurations failed to resolve the hang.

Next steps focus on providing full trace outputs to Azure DevOps engineers to pinpoint where their implementation diverges from Git's protocol expectations. The investigation remains technical, with emphasis on the use of `--stateless-rpc` mode in HTTPS operations and the precise protocol sequence during push finalization. While Microsoft previously suggested rate limiting as a cause, the new evidence points more strongly to protocol-level incompatibilities in Azure DevOps's handling of unsuccessful pushes.
