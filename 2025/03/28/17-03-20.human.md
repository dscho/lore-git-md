This is the second patch in a series improving rebase status reporting, focusing on output formatting. The change makes `git status` during a rebase consistently abbreviate commit hashes in 'merge -C' and 'fixup -C' lines, matching the existing behavior for other rebase commands like 'pick' and 'squash'.

The patch modifies `wt-status.c` to properly parse these less common command formats, where the hash appears in the third field rather than the second. The implementation adds special handling for these cases while maintaining the existing behavior for other commands. The change is well-contained and includes updated comments showing the before/after behavior.

This is a straightforward usability improvement that reduces visual noise in rebase status output, particularly helpful during complex rebases involving merge commits. The patch follows the established pattern of hash abbreviation in rebase status messages and appears to be a clean implementation with no obvious drawbacks.
