Documentation patch fixing a pre-commit hook issue with conflict markers.

Phillip Wood noticed that after committing a merge resolution involving the AsciiDoc conversion of documentation files, a pre-commit hook was failing. The hook's `git diff --check` was incorrectly flagging example conflict markers in `merge-file.adoc` as unresolved conflicts. This patch adds the `conflict-marker-size=32` attribute for this file in `.gitattributes`, matching how other documentation files with example conflict markers are already configured.

The change is straightforward and follows existing patterns - the commit message notes that a grep didn't find any other files missing this attribute. This appears to be a simple but necessary fix to prevent false positives in the pre-commit checks, particularly as more documentation files are converted to AsciiDoc format. The patch is minimal (just one line added to `.gitattributes`) and clearly motivated by a concrete issue encountered in development workflow.
