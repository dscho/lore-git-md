Platform compatibility follow-up in gitk/Cygwin thread.

Johannes Sixt responds to Mark Levedahl's report about gitk's regression on Cygwin caused by commit 4cbe9e0e2. The issue involves a recursive loop between `_which` and wrapped `exec` functions when running under Cygwin. Sixt acknowledges the problem and questions whether the Windows-specific protections (which override `exec` and `open` system-wide) are actually needed on non-Windows platforms including Cygwin.

The email specifically asks Johannes Schindelin (referred to as "Dscho") to confirm if there's any hidden rationale for the current platform-agnostic implementation. This moves the discussion toward potentially restricting the security measures to Windows-only, which would resolve the Cygwin regression while maintaining the intended protections where needed. The thread remains focused on finding the right platform-specific boundaries for these security measures in gitk's TCL implementation.
