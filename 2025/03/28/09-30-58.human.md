Platform-specific test debugging for backfill batch size issue.

Patrick Steinhardt continues investigating the failing "backfill --min-batch-size" test on s390x and sparc64 architectures. The test fails when checking trace2 event data for expected fetch counts during a partial clone operation. Steinhardt proposes modifying the test infrastructure to provide more debugging information by replacing `grep` with `test_grep` in the `test_trace2_data` helper function, which would show the actual file contents when the match fails.

The suggested change would help determine whether the trace2 data contains unexpected values or if the issue lies elsewhere. Steinhardt also recommends running the test with `-ix` flags for verbose output. This debugging approach follows up on earlier reports from Todd Zullinger and John Paul Adrian Glaubitz about the same test failure during the release candidate period, which went unaddressed at the time.

The patch appears to be a straightforward test infrastructure modification aimed at gathering more diagnostic information. While the root cause remains unclear, this change could help determine whether the issue stems from trace2 data collection or deeper batch size handling problems on big-endian systems. The feature author Derrick Stolee remains CC'd but has not yet engaged with the debugging effort.
