Bugfix investigation for platform-specific test failures in `backfill --min-batch-size`.

Patrick Steinhardt follows up on the ongoing issue where the `backfill --min-batch-size` test fails consistently on s390x and sparc64 architectures. The thread already has two independent reports of this failure (from Debian builds and Todd Zullinger during the RC period), but remains unresolved with no response from the feature author Derrick Stolee.

Steinhardt provides a concrete debugging suggestion: modifying the test infrastructure to show the actual output when the trace2 data check fails, rather than just reporting a mismatch. He proposes changing `test_trace2_data` to use `test_grep` (which shows mismatches) instead of plain `grep`, and suggests running the test with `-ix` for more verbose output. This would help identify what value is actually being recorded in the trace2 log versus the expected "20".

This moves the investigation forward by providing a way to gather more diagnostic information about the failure, which could reveal whether this is an endianness issue in the batch size handling or some other platform-specific behavior. The patch itself is a simple one-line change to test infrastructure that could be applied locally by anyone trying to debug the issue.
