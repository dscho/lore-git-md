Build system fix for meson's curl detection logic. This is the first patch in a series collecting build system improvements, addressing a regression in how Git's meson build handles `-Dcurl=auto` configuration.

The patch corrects a subtle bug where curl-dependent features (like HTTP remote helpers) wouldn't be built even when curl was successfully auto-detected. The issue stemmed from checking `get_option('curl').enabled()` which returns false for "auto" mode, rather than checking `curl.found()` which properly reflects detection status. Since curl is essential for many Git workflows (enabled by default), this could silently produce incomplete builds when users explicitly requested auto-detection.

Technical details show the fix is minimal (one-line change in meson.build) but important, affecting how HTTP-related sources are included in the build. The commit message provides clear context about curl's importance and the difference between feature options vs. dependency states in meson. This appears to be a straightforward correction of an oversight from the meson conversion work.
