Bugfix for `rebase -r` merge commit creation. This patch fixes a confusing edge case in interactive rebase with merge commits where an empty conflict resolution (resolving to the same content as HEAD) would skip creating the merge commit entirely, leaving the side branch's commits out of the rebased history. The fix ensures we properly create merge commits when MERGE_HEAD is present, even with empty resolutions, and cleans up merge state correctly.

The issue occurs in `sequencer.c` where the code was prematurely exiting before commit creation when the working tree was clean, without checking for ongoing merges. The patch adds this check and also ensures MERGE_HEAD is cleaned up when merges fail to start, matching existing behavior for MERGE_MSG.

Philippe Blain includes a thorough test case in `t3418-rebase-continue.sh` that verifies merge commits are now properly created after empty resolutions, with the expected merge message preserved. The change is well-contained, touching only the sequencer logic and adding test coverage, and appears to cleanly fix the described behavior without introducing new edge cases.
