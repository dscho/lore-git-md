This is a follow-up in the resolution of the reftable library decoupling effort, specifically addressing a Windows-specific build issue. 

Patrick Steinhardt confirms that the reftable decoupling series (`ps/reftable-sans-compat-util`) is now ready to merge as-is. The final blocker was a MinGW-specific memory allocator mismatch between reftable (using mscrt.dll) and Git core (using mimalloc) that caused SIGTRAP failures in Windows unit tests. Johannes Schindelin had verified that moving the mimalloc override declarations to `compat/posix.h` resolved the CI failures in Git for Windows' testing infrastructure.

Steinhardt notes that since the mimalloc code only exists downstream in Git for Windows, no further changes to the main Git series are needed. This clears the way for merging this important ref backend abstraction work, which removes Git-specific dependencies from the reftable code for better portability. The change represents a key step in the long-term effort to make the reftable backend more independent of Git's core infrastructure.
