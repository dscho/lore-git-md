This is a feature patch adding SHA implementation details to Git's version reporting. It's the first of a 2-part series aimed at improving diagnostic information about Git's cryptographic backends.

The patch modifies `help.c` to show which SHA-1 and SHA-256 implementations Git was built with when using `git version --build-options`. Currently this information is only known at build time. The new output will distinguish between various implementations (OpenSSL, Apple CommonCrypto, collision-detection variants for SHA-1; OpenSSL, Nettle, gcrypt for SHA-256) which could be useful for debugging or compatibility checking.

The implementation adds a new `get_sha_impl()` function that checks compile-time defines and formats the appropriate strings, then calls this from the existing version info printer. The changes are straightforward and contained to help.c with no expected runtime impact. 

As noted in the thread context, the main open question is around terminology for non-standard SHA-1 implementations (currently labeled "Collision Detection" in the code) - whether to call them "unsafe-sha1" (more accurate but potentially alarming) or something like "fast-sha1" (more user-friendly). This patch uses neutral technical names but that discussion will likely continue in the thread.
