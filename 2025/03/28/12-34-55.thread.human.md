This thread addresses a Cygwin-specific regression in gitk and git-gui introduced in Git v2.49.0, where Windows-specific security changes caused stack exhaustion due to recursive function calls between `_which` and wrapped `exec` functions on Cygwin. The issue stems from commit 4cbe9e0e2, which implemented protections against executing worktree files but inadvertently affected Cygwin's path handling.

Mark Levedahl initially reported the regression and proposed solutions, with Johannes Sixt (Hannes) later questioning why these Windows protections were applied platform-agnostically. Levedahl has now followed up with historical analysis, confirming the overrides were never meant for non-Windows platforms - tracing this back to removed git-gui code (commit 7145c654). The consensus is forming around restricting the function overrides to Windows-only operation, which would resolve the Cygwin issue while maintaining intended security where needed.

Levedahl plans to submit patches implementing this change for both gitk and git-gui, treating Cygwin like other non-Windows systems. The thread now awaits confirmation from Johannes Schindelin (Dscho) about any overlooked security implications before proceeding, though the historical evidence suggests the current behavior was an oversight rather than deliberate. Key technical considerations remain the interaction between `_which` and `real_exec` functions, and maintaining proper PATH handling differences between Windows and Cygwin environments.
