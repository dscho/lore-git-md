This thread addresses a Cygwin-specific regression in gitk and git-gui introduced in Git v2.49.0, where changes to Windows security protections inadvertently caused stack exhaustion on Cygwin due to recursive interactions between path-handling functions. Mark Levedahl identified the root cause - the security measures were never intended for non-Windows platforms - and proposed restricting them to Windows only, which Johannes Sixt (Hannes) agreed with.

The latest patch implements this solution for gitk, removing Cygwin-specific PATH handling and wrapping all security-related overrides in Windows-only conditionals. This preserves the intended protections against CVEs on Windows while restoring Cygwin's previous behavior. The change is clean and well-justified, following through on the thread's technical consensus. Johannes Schindelin (Dscho) hasn't raised any objections to the approach, so this appears ready for inclusion once the corresponding git-gui patch is submitted. The fix maintains security where needed while resolving the regression cleanly.
