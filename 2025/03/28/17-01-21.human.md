This is the second patch in a series enhancing `git version --build-options` to report SHA implementation details. It specifically adds reporting for "unsafe-SHA-1" variants used for non-cryptographic purposes, following up on the Makefile changes from last September that introduced these faster but cryptographically insecure SHA-1 implementations.

The patch adds three conditional output lines to detect and report unsafe SHA-1 backends (OpenSSL, blk, and Apple CommonCrypto), mirroring the structure from the first patch that handled standard SHA implementations. The documentation is also updated to explain this new output line. The implementation is straightforward, adding the new cases to the existing `get_sha_impl()` function in help.c.

The author maintains the "unsafe-SHA-1" terminology from the original Makefile change, though the cover letter had questioned whether "fast-SHA-1" might be a less alarming alternative. This naming choice may prompt discussion, as the thread summary noted this was likely to be the primary point of feedback. The patch itself is cleanly implemented and completes the series' goal of making Git's cryptographic backend choices more transparent to users.
