Bug report about `git push --mirror` hanging with Azure DevOps. Akash S reports that when pushing large bare repositories (1.5GB) to Azure DevOps using PAT authentication, the process hangs indefinitely after showing "Storing index (done)" in the output. The issue occurs intermittently with large open-source repos like elasticsearch and node.

Several troubleshooting attempts were made without success:
- Setting `http.postBuffer` to 50MB
- Configuring timeout-related settings (`GIT_CURL_TIMEOUT`, `http.lowSpeedLimit`)
- Disabling concurrent requests with `http.maxRequests=1`
- Using `--no-thin` option

Debug output shows the process gets stuck after TLS communication completes successfully. Process stack traces indicate the hang occurs in various read operations during the push operation. The reporter provides detailed process listings and stack traces showing the processes blocked on read operations, suggesting a potential deadlock or communication issue between Git and Azure DevOps's server implementation.

This appears to be a real issue affecting users pushing large repositories to Azure DevOps, though the root cause isn't immediately clear from the provided information. The thorough debugging information makes this a well-documented report that should be actionable for Git developers familiar with the push protocol implementation.
