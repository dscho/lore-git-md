Bugfix follow-up discussion for `git blame` porcelain output markers. Patrick Steinhardt provides minor code review feedback on Karthik Nayak's v2 patch implementing the unblamable/ignored line markers in porcelain mode. The feedback consists of two small suggestions: (1) potentially renaming `emit_per_line_details()` to `emit_porcelain_per_line_details()` for better consistency with other porcelain-related functions, and (2) considering `puts()` instead of `printf()` for the simple string writes. 

Patrick also confirms the test approach makes sense, noting that the per-line emission is necessary since the unblamable/ignored status depends on line-specific history rather than being commit-level properties. This aligns with the thread's established technical consensus that these markers must appear in `--line-porcelain` output while maintaining backward compatibility with existing porcelain parsers.

The discussion represents final polish on an otherwise settled implementation, with all major design questions (SHA-1 line format preservation, porcelain extensibility via metadata lines, per-line versus per-commit emission) having been resolved in earlier thread exchanges. The patch remains focused on its core goal of properly showing ignored/unblamable markers in porcelain output while respecting the porcelain format rules established in blame-format.txt.
