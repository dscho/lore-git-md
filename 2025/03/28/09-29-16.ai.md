Bugfix investigation for platform-specific test failures in `backfill --min-batch-size` feature.

Patrick Steinhardt provides debugging assistance for the ongoing issue where the "do partial clone 2, backfill min batch size" test fails on s390x and sparc64 architectures. The problem was previously reported during the RC period but remains unresolved. Steinhardt suggests modifying the test infrastructure to provide more detailed output when the test fails, proposing a patch that replaces `grep` with `test_grep` in the `test_trace2_data` helper function. This change would make the test output show the actual file contents when the expected trace2 data isn't found, potentially revealing why the batch size check fails on big-endian systems. The suggestion comes with instructions to run the test with `-ix` flags to get verbose output. This moves the investigation forward by providing a concrete way to gather more diagnostic information, though the root cause of the platform-specific behavior remains unknown. The thread continues waiting for either the feature author's input or for someone to collect the suggested debug output from an affected system.
