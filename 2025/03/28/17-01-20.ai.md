Feature enhancement to `git version --build-options` reporting SHA implementations.

This first patch in a 2-part series adds SHA implementation details to Git's version output when using `--build-options`. The change introduces a new `get_sha_impl()` function in help.c that detects and reports which cryptographic backends are compiled in for both SHA-1 and SHA-256 operations. The implementation checks various compile-time defines (like SHA1_OPENSSL, SHA256_GCRYPT) and produces human-readable labels for each detected backend.

For SHA-1, it distinguishes between standard implementations (OpenSSL, Apple CommonCrypto) and collision-detection variants (both external and submodule versions). For SHA-256, it reports OpenSSL, Nettle, gcrypt, and blk backends. The output format uses clear labels like "SHA-1: OpenSSL" and "SHA-256: gcrypt" on separate lines.

The patch is cleanly focused on the reporting mechanism itself, leaving the naming discussion around "unsafe-sha1" vs "fast-sha1" (mentioned in the cover letter) for the second patch. The implementation is straightforward, adding the new function and calling it from `get_version_info()` while maintaining the existing output structure. No behavioral changes or user-visible effects occur unless `--build-options` is explicitly requested.
