This is a documentation review comment on the final patch of Karthik Nayak's batched reference updates series, which has already received technical approval from Patrick Steinhardt. Jean-Noël Avila points out a formatting issue in the manpage synopsis section of `git-update-ref.adoc`.

The reviewer notes that when showing alternative command line invocations (as opposed to options for a single invocation), each alternative should begin with the full command name "git update-ref" rather than continuing from the previous line. The current formatting could mislead readers into thinking the alternatives are part of a single command's options rather than distinct invocation patterns.

This is a minor documentation polish for the already-approved feature that adds `--batch-updates` support to `git update-ref --stdin`. The series implements partial failure handling for batched reference updates while maintaining atomicity for critical errors, with comprehensive backend support across files, packed, and reftable storage. The technical implementation has been thoroughly reviewed and benchmarked, with all major questions resolved in previous iterations.

The documentation fix doesn't affect the functionality but improves clarity in showing the different ways to invoke `update-ref`. Since this is the final patch in a technically complete series, the change would likely be incorporated as a trivial follow-up before merging.
