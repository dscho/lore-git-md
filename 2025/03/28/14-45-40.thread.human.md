This thread documents a small but useful fix for Git's documentation build process. The issue arose when a contributor's pre-commit hook flagged what appeared to be conflict markers in `git-merge-file.adoc`, though these were actually intentional examples in the documentation. 

The solution follows an established pattern seen elsewhere in Git's docs - adding `conflict-marker-size=32` to `.gitattributes` for this file, which prevents false positives from diff checks. This matches how similar documentation files like `git-merge.adoc` and `gitk.adoc` are already configured. The change is straightforward and maintains consistency in how Git's documentation handles example conflict markers.

The patch appears ready for merging, addressing a minor but legitimate edge case in the pre-commit validation of documentation files. No objections or additional discussion have been raised about this change.
