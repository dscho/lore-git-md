This thread has been discussing a 2-patch series to enhance `git version --build-options` to report which SHA implementations Git was built with. The first patch, already reviewed, implemented reporting for standard SHA-1 and SHA-256 backends using a symbol-based approach that Junio Hamano approved. 

The second patch, just received, completes the series by adding reporting for non-cryptographic (formerly called "unsafe") SHA-1 variants. It follows the same pattern as the first patch, defining `SHA1_UNSAFE_BACKEND` symbols in hash.h for each implementation (Apple, OpenSSL, and block-sha1) and exposing them in the version output. The documentation has been updated to explain this new output line.

The series has evolved through discussion, with terminology shifting from "unsafe-SHA-1" to "non-crypto-SHA-1" in the output, and includes explicit warnings about collision detection. All major technical questions were resolved in earlier rounds, with Patrick Steinhardt proposing the symbol-based architecture, Christian Couder suggesting terminology improvements, and Justin Tobler contributing to the warning presentation. Junio Hamano has already endorsed the core approach.

With this final patch addressing the remaining presentation details for non-crypto variants, the series appears complete and ready for merging. The changes are narrowly scoped to version reporting with no runtime overhead, maintaining compile-time safety through preprocessor symbols. The output format uses raw symbol names (like "SHA1_OPENSSL") as agreed in the thread.
