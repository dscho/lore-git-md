This thread documents the evolution of a 2-patch series that enhances `git version --build-options` to report which SHA implementations are in use. The technical implementation, now at version 2, has been approved by maintainer Junio Hamano and uses a symbol-based approach (SHA1_BACKEND, SHA1_UNSAFE_BACKEND, SHA256_BACKEND) defined in hash.h. The first patch implemented core functionality while the second added reporting for non-crypto SHA-1 variants.

The discussion has progressed from architectural decisions to final documentation polish. Patrick Steinhardt originally proposed the symbol-based architecture and has been reviewing for technical precision, while Christian Couder has been advocating for clearer user-facing documentation. The latest email from Christian proposes expanding the warning text about non-crypto SHA-1 variants to better explain the security implications, including a Wikipedia reference for further reading. This builds on earlier consensus to use "non-crypto-SHA-1" terminology rather than "unsafe-SHA-1."

All technical aspects are settled, with the final discussion focusing on optimal documentation phrasing. Christian's proposal represents a middle ground between minimal warnings and extensive explanations, addressing Patrick's concern about the original note being too terse while maintaining the maintainer-approved approach. The series appears ready for merging once this last documentation refinement is resolved.
