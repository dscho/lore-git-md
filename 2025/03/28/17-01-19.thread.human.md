This thread has progressed from technical architecture to final user-facing polish for enhancing `git version --build-options` to report SHA implementations. The series started with an if/elif cascade approach in help.c, evolved through architectural feedback from Junio Hamano, and settled on Patrick Steinhardt's symbol-based implementation where each SHA backend defines its own `SHA1_BACKEND` symbol in hash.h.

With the technical approach now agreed upon, the discussion has shifted to presentation details. Justin Tobler and Christian Couder are refining how to name and warn about non-cryptographic SHA-1 variants. Christian suggested "SHA-1 for non-crypto" as less alarming than "unsafe-SHA-1", while Justin proposes "non-crypto-SHA-1" as a middle ground. They've also agreed to add explicit "No collision detection!!!" warnings when non-collision-detecting SHA-1 is used in cryptographic contexts.

The next version (v3) will implement both the symbol-based technical solution and these presentation refinements, maintaining the original diagnostic goals while improving both code robustness and user clarity. The only remaining open item is finalizing the exact warning message format for DC_SHA1 variants.
