This thread discusses Justin Tobler's patch series to report SHA implementations in `git version --build-options`. The discussion has evolved from initial implementation details to broader architectural considerations, with input from key contributors.

The series originally proposed using an if/elif cascade to detect SHA implementations, but Junio Hamano raised concerns about maintainability and potential misalignment with hash.h assumptions. Patrick Steinhardt later suggested a more architectural approach using backend-defined symbols. Justin has now responded to Junio's feedback, agreeing to use independent #if defined() blocks instead of the if/elif cascade, which will improve maintainability and help catch build misconfigurations.

There's ongoing discussion about how to handle special cases like the collision-detection SHA-1 variants (DC_SHA1_*), with Justin proposing either listing them alongside other implementations or creating a dedicated section. The output format will use raw symbol names (e.g., "SHA1_OPENSSL") as suggested, making it easier to map to build configurations.

The thread shows good progress toward resolving the architectural concerns while maintaining the diagnostic utility of the feature. Justin plans to incorporate these changes in v3 of the patch series, which will need to address both the implementation approach and naming scheme based on the accumulated feedback from Junio, Patrick, and Christian Couder. The impact remains contained to help.c and documentation, with no wider codebase changes needed.
