This thread introduces a 2-patch series that enhances `git version --build-options` to report which SHA implementations Git was built with, helping users diagnose SHA-1 vs SHA-256 usage and identify non-standard SHA-1 variants. The first patch implemented core functionality in help.c to detect and report SHA backends (OpenSSL, Nettle, gcrypt, etc.) with clear output labels like "SHA-1: OpenSSL". 

The second patch, now received, specifically addresses reporting of non-cryptographic SHA-1 implementations (used for performance where collision resistance isn't critical). These are currently labeled "unsafe-SHA-1" in the output, though the author acknowledges this terminology might alarm users unnecessarily. The implementation is clean and consistent with the first patch's approach, adding detection of unsafe variants via their compile-time defines while maintaining the existing output structure.

The primary open question is whether "unsafe-SHA-1" is the right label - the thread suggests "fast-SHA-1" as a less alarming alternative that still conveys the tradeoff (faster performance without cryptographic guarantees). This naming discussion appears to be the key remaining issue before the series can proceed. The changes are well-contained to help.c and documentation, with no wider impact on Git's functionality.
