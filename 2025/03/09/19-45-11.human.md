This is a documentation patch addressing formatting consistency in Git's AsciiDoc files. Jean-Noël Avila points out that block delimiters (like `----`) can be visually confused with section titles in translations when they happen to be the same length as the preceding line. The patch adds blank lines around these delimiters in 17 documentation files to prevent this ambiguity.

The change is mechanical but thorough, touching tutorial guides (`MyFirstContribution.adoc`), command references (`git-bisect.adoc`), and protocol documentation (`gitprotocol-common.adoc`). The author notes this issue surfaced in a Chinese translation where the line lengths matched the delimiter length exactly. While the immediate fix is straightforward, the commit message also raises an interesting question about potentially modernizing all documentation to use ATX-style headers (with leading `=` characters) instead of the current setext-style format.

The patch appears well-scoped and non-controversial, focusing purely on presentation rather than content changes. It follows Git's documentation conventions while making the source more robust for translators. The diff shows consistent application of the blank-line rule, with special handling for nested blocks (marked with `+` lines).
