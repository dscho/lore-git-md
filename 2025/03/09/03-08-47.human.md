This is part 6 of Jeff King's 9-patch series improving ref-prefix handling in fetches, building on earlier fixes for tag fetching regressions. The patch optimizes a specific case where Git fetches without any refspecs (either from command line or config) - instead of requesting all refs from the server, it now explicitly asks only for HEAD.

The change makes fetches more efficient by reducing unnecessary ref advertisements, demonstrated by a new test showing we no longer receive unrelated branch refs. It also simplifies the code's mental model by ensuring an empty ref_prefixes list truly means "no refs wanted" rather than being a special case for "fetch everything". 

The patch touches `builtin/fetch.c` to add the HEAD prefix when no refspecs exist, and adds a test in `t/t5702-protocol-v2.sh` verifying the behavior. While there's a possible edge case where HEAD could be added twice (once here and once for remote HEAD updates), Jeff notes this is harmless and not worth extra complexity to prevent.

This continues the series' pattern of careful, incremental improvements - each patch makes the code both more correct and easier to reason about while maintaining backward compatibility. The change is particularly valuable for large repositories where avoiding unnecessary ref advertisements can significantly reduce fetch overhead.
