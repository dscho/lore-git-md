Performance optimization in the ref-prefix handling for protocol v2 fetches. This is part 7/9 of Jeff King's series addressing architectural improvements to Git's fetch behavior.

The patch simplifies the ref-prefix handling logic in `builtin/fetch.c` by removing conditional checks that were previously needed when the ref-prefix list was empty. Now that earlier patches have ensured an empty list truly means "fetch nothing," the code can unconditionally add prefixes for tags and HEAD updates. This both cleans up the code and enables new optimizations - fetches of exact OIDs can now avoid enumerating all remote refs when following tags.

A new test case demonstrates fetching a specific commit by OID while still following tags, showing the optimization in action. The change maintains all existing behavior while making the code more straightforward and efficient. This continues the series' progression from bugfixes through to performance improvements, with each patch building on the last to refine Git's fetch protocol handling.
