Performance optimization in the ongoing ref-prefix handling series. This is patch 8/9 in Jeff King's series addressing fetch behavior and protocol v2 optimizations.

The patch eliminates an unnecessary `ls-refs` call when fetching an exact OID (like `git fetch origin $exact_oid:refs/heads/foo`) where updating the remote's HEAD symref would be impossible. The current code always asks for HEAD advertisement in these cases, but the patch demonstrates this is pointless since the fetch operation's constraints prevent HEAD from being processed anyway.

The change builds on previous architectural improvements in the series, particularly the ref-prefix handling simplifications. It includes a new test that verifies the optimization by checking packet traces to confirm the `ls-refs` command is skipped when appropriate. The patch maintains all existing functionality while removing a redundant network round-trip.

Jeff notes some open questions about whether the optimization could be taken further by being more aggressive about HEAD updates, but acknowledges this might conflict with other performance goals. The patch represents a clear win in its current form, avoiding work that can't possibly produce useful results.
