This is a performance optimization patch in Jeff King's ongoing series improving ref-prefix handling in protocol v2 fetches. The change builds on previous fixes for tag-following behavior and removes now-unnecessary protections around adding to the ref-prefix list.

The key change simplifies `builtin/fetch.c` by unconditionally adding "refs/tags/" and "HEAD" to the ref-prefix list when needed, rather than checking if the list is non-empty first. This works because an earlier patch ensured an empty list now truly means "fetch nothing" rather than being a special case for "fetch everything". The simplification allows more efficient fetches in cases like exact-OID fetches with tag following, where we can now avoid enumerating all remote refs.

A new test in `t/t5702-protocol-v2.sh` demonstrates the optimization by verifying that fetching a specific commit by OID while following tags no longer downloads unrelated branch references. The test uses packet tracing to confirm the optimization works as expected. The patch maintains all existing functionality while improving performance in these edge cases.

This represents a logical next step in the series' progression from bugfixes through architectural improvements to targeted optimizations. The change is relatively small but meaningful, removing special-case handling that had accumulated over time.
