This thread concerns a refactoring to move the "core.attributesfile" configuration handling from global state to per-repository storage, as part of the ongoing `the_repository` removal effort. The changes affect attribute file path resolution, touching attr.c, environment.c, and builtin/var.c to introduce repository-scoped access while preserving behavior.

Patrick Steinhardt provided initial review feedback, which Ayush Chandekar has now fully addressed in a revised two-patch series. The first patch moves the config lookup into `struct repo_settings` with a new accessor function, while the second updates all callers to use this repository-aware approach instead of the old global variable. The changes follow established patterns for this type of refactoring and include all requested improvements like better commit splitting and style fixes.

With the review feedback implemented and no outstanding technical concerns, this appears ready for final consideration. The work is a mechanical but important step in the project's long-term effort to eliminate global state and improve multi-repository handling.
