This thread focuses on refactoring the "core.attributesfile" configuration handling as part of Git's ongoing effort to remove the `the_repository` global variable. The initial patch by René Scharfe moves attribute file path resolution from global state into per-repository settings, introducing a new `repo_settings_get_attributesfile_path()` function and updating all callers to pass repository context. The changes affect several key functions in attr.c while maintaining existing behavior.

Patrick Steinhardt has reviewed the patch and suggested several improvements. He recommends restructuring the commit message to better highlight the problem being solved, splitting the changes into two commits (one for the config movement and another for caller updates), and addressing some style issues. While he questions whether keeping `git_attr_global_file()` as a thin wrapper adds value, he doesn't object to the overall approach. The review also notes some missing cleanup code and opportunities to simplify certain changes.

The discussion remains technical and constructive, with no fundamental disagreements about the direction. The patch appears to be progressing well through the review process, with Steinhardt's feedback focusing on implementation details and organization rather than core design. This work continues Git's multi-year effort to improve repository isolation by eliminating global state, a pattern that has been successfully applied to many other subsystems.
