Performance optimization patch in the ref-prefix handling series, specifically addressing unnecessary HEAD symref updates during exact-OID fetches. This is patch 8/9 in Jeff King's follow-up series building on the earlier tag-fetching regression fixes.

The patch eliminates a redundant `ls-refs` call when fetching exact OIDs where HEAD updates would be impossible. The key insight is that when fetching a specific object ID (like `git fetch origin $exact_oid:refs/heads/foo`), the remote's HEAD symref cannot possibly update our local remote-tracking HEAD because we never fetch the ref that HEAD points to. The change moves the HEAD prefix addition inside the `must_list_refs` conditional, avoiding the round-trip when it's provably unnecessary.

The patch includes a new test in `t/t5702-protocol-v2.sh` that verifies the optimization using packet tracing, confirming the `ls-refs` command is skipped. Jeff notes some open questions about whether the optimization could be more aggressive by sometimes updating HEAD when we do fetch matching refs, but recognizes this might conflict with earlier performance work in commit e70a3030e7. He also questions whether the `uses_remote_tracking()` check from 6c915c3f85 could be tightened further.

This builds directly on the architectural changes in earlier patches (particularly patch 6's ref-prefix simplification) and demonstrates the series' progression from bugfixes through to targeted optimizations. The change touches `builtin/fetch.c` and adds test coverage while maintaining all existing functionality.
