This is a performance optimization patch in the ongoing ref-prefix handling series, specifically addressing config-less fetches. Jeff King builds on the earlier regression fixes and refactoring to improve fetch behavior when no refspecs are specified.

The patch modifies `builtin/fetch.c` to explicitly request only HEAD when no refspecs are given (either via command line or config), rather than receiving the full ref advertisement. This optimization reduces unnecessary network traffic by telling the server we only care about HEAD in this case. The change comes with a new test in `t/t5702-protocol-v2.sh` that verifies this filtering behavior.

A key architectural benefit is that this eliminates the special case where an empty ref_prefixes list meant "fetch everything" - now it truly means "not interested in any refs". This simplifies future maintenance as code adding to ref_prefixes no longer needs to handle the empty-list case specially. The patch notes there's a theoretical overlap with remote HEAD updates, but explains why this can't occur in practice.

This change is part of a larger effort to clean up and optimize ref-prefix handling in the fetch protocol, following earlier fixes for tag decoration regressions. It demonstrates the series' progression from bugfixes to architectural improvements while maintaining careful attention to edge cases and test coverage. The patch maintains protocol v2 semantics while making the implementation more efficient and maintainable.
