This is a documentation patch addressing formatting issues in Git's AsciiDoc files. The patch adds blank lines around block delimiters (----) to prevent them from being misinterpreted as section headers in translations where the preceding text length might exactly match the delimiter length.

The change affects 17 documentation files, mostly adding blank lines before and after code blocks and examples. The motivation comes from a specific case where a Chinese translation caused such a misinterpretation due to text length matching the delimiter. The patch is mechanical in nature, systematically applying the blank line rule throughout the documentation.

Key files modified include various command manuals (git-bisect.adoc, git-cat-file.adoc, etc.), protocol documentation (gitprotocol-common.adoc), and contributor guides (MyFirstContribution.adoc). The changes are straightforward and maintain the existing content while improving formatting consistency.

The commit message also briefly mentions a potential future direction of converting all AsciiDoc files to the modern ATX-style headers (using = characters) but does not propose this change directly. The patch appears well-scoped and non-controversial, focusing solely on the immediate formatting issue.
