Refactoring and bugfix for ref-prefix handling in fetch/push logic. This patch is part of Jeff King's 9-part series improving ref-prefix architecture following a regression in tag fetching behavior.

The patch focuses on `refspec_ref_prefixes()` in refspec.c, which generates prefix strings for server communication. It clarifies the interaction between exact-SHA1 fetches and push operations, fixing a subtle logic issue introduced in 6c301adb0a. The key changes:

1. Separates fetch vs push logic into distinct blocks rather than interleaving them
2. Moves the exact_sha1 check inside the fetch block where it belongs (pushes should still consider destinations even for exact SHA1s)
3. Maintains the same behavior for fetches while better preparing for potential v2 push protocol
4. Keeps negative refspec handling at the top level since it applies to both operations

The changes are technically a no-op for current behavior since v2 push isn't implemented, but they prevent future bugs and make the code's intent clearer. The patch touches only refspec.c, restructuring the logic without changing functionality. It builds on prior work from commits 6c301adb0a and 6373cb598e while being careful to maintain protocol v2 fetch semantics.

This is a preparatory cleanup that could stand alone but fits into the larger series' goal of robust ref-prefix handling. The author notes it could be dropped if deemed too churn-y, but the improved clarity and future-proofing seem worthwhile.
