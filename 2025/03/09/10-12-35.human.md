Bugfix for `git archive` command preventing a segfault when using an empty remote parameter.

This patch addresses a crash that occurs when running `git archive --remote=""` by adding validation to reject empty remote strings. Currently, passing an empty string as the remote parameter leads to a segmentation fault. The fix adds a simple check that displays a usage error message instead.

The change is minimal (4 lines added) and focused on the immediate issue in `builtin/archive.c`. While the patch doesn't include tests, the problem is straightforward and the solution appears correct - it matches how Git typically handles invalid empty parameters in other commands. This seems like a clear improvement over the current crashing behavior.

The fix would be particularly valuable for scripts or tools that might accidentally pass empty remote parameters to `git archive`.
