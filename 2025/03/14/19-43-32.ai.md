This is a follow-up to the Git v2.49.0 release announcement regarding Rust integration issues. Josh Steadmon reports problems publishing the Rust crates to crates.io due to build system incompatibilities. 

The core issue is that `cargo publish` operates differently from `cargo build` - it doesn't include the repository root, preventing the build scripts from accessing the top-level Makefile and Git sources outside the `contrib/libgit-*` directories. This breaks the publishing process for the Rust foreign language interface that was just added in v2.49.0.

As a temporary measure, Steadmon has published placeholder crates on crates.io to prevent name squatting of the libgit* crate names. The actual publishing of the functional crates is blocked until the build system issues can be resolved. This appears to be an unanticipated consequence of the Rust integration work that wasn't caught during development and testing.

The email doesn't propose specific solutions but serves to document the current roadblock in making the Rust crates properly available following the v2.49.0 release. The problem appears to be technical rather than conceptual, relating to build system integration details between Git's Makefile-based build and Cargo's publishing workflow.
