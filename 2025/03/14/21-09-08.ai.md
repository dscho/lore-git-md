Build system improvement patch addressing platform-specific compiler warnings.

This is the second patch in a 3-part series to handle unreachable code warnings from `- Wunreachable-code`. It specifically addresses a macOS-specific issue where clang considers the error handling for `sigfillset()` unreachable since the platform's implementation always succeeds. The patch replaces the direct return value check with an `errno`-based check, which works around the compiler optimization while maintaining POSIX compliance on other platforms.

The change modifies `run-command.c` to first clear `errno`, call `sigfillset()`, then check `errno` rather than the return value. This preserves error checking where needed while avoiding the compiler warning on macOS. The commit message explains the rationale clearly, noting this is a pragmatic solution that maintains correctness while working around platform-specific compiler behavior.

This patch follows Jeff King's initial warning-enabling patch and precedes Junio Hamano's more comprehensive `NOT_A_CONST` macro solution in the series. It represents an intermediate solution focused on a specific platform issue while the broader architectural approach is being developed. The change is minimal (10 lines) and well-contained to the `atfork_prepare()` function.
