This is a technical patch in Taylor Blau's incremental MIDX bitmap series (v4 12/13), focusing on integrating the new type-level bitmap infrastructure from the previous patch. The change systematically replaces direct `ewah_iterator` usage with the new `ewah_or_iterator` across all type bitmap operations in pack-bitmap.c, enabling proper handling of multi-layered bitmaps.

Key technical changes:
- Updates `init_type_iterator()` to use `ewah_or_iterator_init()` with the new `*_all` arrays (commits_all, trees_all, etc.) and layer count
- Modifies all iteration sites to use `ewah_or_iterator_next()` instead of `ewah_iterator_next()`
- Adds proper cleanup with `ewah_or_iterator_free()` in all modified functions
- Affects core bitmap operations including object display, counting, filtering, and disk usage calculation
- The patch touches several critical paths:
  * `show_objects_for_type()` (bitmap object traversal)
  * `filter_bitmap_exclude_type()` and `filter_bitmap_blob_limit()` (bitmap filtering)
  * `count_object_type()` (object counting)
  * `get_disk_usage_for_type()` (size calculations)

The changes maintain consistency with the series' architectural approach while enabling the cross-layer bitmap operations that the type-level arrays were designed to support. All modifications follow the established pattern of handling layer counts via `bitmap_git->base_nr + 1` and maintain the series' careful memory management practices. This represents a straightforward but important integration step in the larger MIDX bitmap effort.
