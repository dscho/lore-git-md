This is part 11/13 of Taylor Blau's incremental MIDX bitmap series, focusing on type-level bitmap tracking across MIDX layers. The patch introduces infrastructure to maintain arrays of type bitmaps (commits, trees, blobs, tags) for each layer in a MIDX chain, preparing for the efficient bitmap combination work introduced in patch 10/13.

Key technical changes:
- Adds four new arrays to `struct bitmap_index`: `commits_all`, `trees_all`, `blobs_all`, `tags_all` to store type bitmaps from all layers
- Implements `load_all_type_bitmaps()` to populate these arrays by walking the MIDX chain
- Modifies `load_bitmap()` to handle recursive loading with a new `recursing` parameter
- Updates `free_bitmap_index()` to clean up the new arrays
- Maintains backward compatibility for non-incremental MIDX cases (single-element arrays)

The change builds directly on the base layer infrastructure from earlier patches (particularly 03/13) and enables the `ewah_or_iterator` functionality from patch 10/13. The implementation follows the series' established pattern of careful memory management and error checking, including a BUG() check for invalid layer counts.

This is a focused technical patch that completes the groundwork needed for cross-layer type bitmap operations, with no apparent loose ends or unresolved questions. The changes are well-contained to pack-bitmap.c and maintain consistency with the series' architectural approach.
