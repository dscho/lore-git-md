This is a follow-up discussion in the promisor-remote bugfix thread, where Christian Couder responds to Junio Hamano's architectural concerns about the v3 patch. The exchange focuses on two key design questions: whether remote names should fall back to URLs in promisor configurations, and how to handle empty URLs.

Christian concedes to Junio's points by agreeing to simplify the implementation in v4 by:
1. Completely removing remote name entries without URLs from consideration (rather than filtering them later)
2. Treating empty URLs the same as missing URLs (dropping them early rather than issuing warnings)
3. Fixing case sensitivity in remote name comparisons to match Git's config handling

The discussion reveals an interesting edge case where filesystem paths can serve as remote names without explicit URLs, though both agree this is rare. Christian demonstrates this works in practice with relative paths, but ultimately accepts that requiring configured URLs is a reasonable simplification.

This email marks a turning point where Christian aligns the patch with Junio's architectural preferences, moving from defending certain design choices to accepting simpler alternatives. The changes will result in a more straightforward implementation that avoids special cases for empty/missing URLs while still fixing the original NULL dereference issue. The thread shows healthy technical debate yielding to maintainer guidance on Git's design principles.
