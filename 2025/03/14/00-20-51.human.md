This is the second patch in a 3-part series addressing potentially dangerous assertions with side effects in Git's codebase. It introduces a CI check to detect problematic assert() calls that might have side effects, which could lead to different behavior when assertions are compiled out in production builds.

The patch adds a new CI script `check-unsafe-assertions.sh` that uses a clever compiler trick - redefining assert() to reference an undefined symbol - to catch assertions that might have side effects. The script identifies 9 existing assertions that are too complex for the compiler to verify as side-effect-free, though manual inspection suggests they're actually safe. When found, the script outputs the file locations and code snippets of these assertions, recommending they be converted to the new BUG_IF_NOT() macro introduced in the first patch.

The implementation is thorough, adding the check to the static analysis CI job and including clear error messages to guide developers. The approach is iterative - since the compiler may not show all problematic assertions at once, developers can fix the reported ones and rerun to find others. This automated detection complements the manual conversions being done in the series, providing ongoing protection against dangerous assertions being introduced in the future.
