Final patch in promisor-remote bugfix series: case sensitivity alignment.

Junio Hamano confirms Christian Couder's patch to make promisor-remote name comparisons case-sensitive, bringing them in line with Git's standard remote configuration behavior. The change replaces `strcasecmp()` with `strcmp()` in `remote_nick_find()` and updates the documentation in `promisor.adoc` to explicitly state that name and URL comparisons are case-sensitive.

This resolves a potential security issue where case-insensitive matching could have allowed a malicious promisor remote to confuse the system by advertising a differently-cased remote name than what's actually configured. The patch ensures consistent behavior when matching advertised remotes against local configuration, preventing any mismatch between the lookup phase and actual remote operations.

With this final patch, the three-part series is now complete, having addressed:
1. NULL pointer dereference safety
2. URL validation hardening
3. Case sensitivity alignment

Junio's review confirms the implementation matches Git's existing behavior in `remote.c` and gives final approval. The series demonstrates careful attention to both security implications and consistency with Git's conventions.
