Bugfix addressing integer overflow in xdiff's hunk calculation on Windows. This patch from René Scharfe fixes the issue reported by Jason Cho where `git diff --unified=2147483647` would incorrectly repeat context lines due to arithmetic overflow in `xdl_get_hunk()`. The problem specifically manifests on Windows where `long` and `int` have the same size, allowing the overflow when summing context lengths.

The solution introduces a `saturating_add()` helper that caps sums at LONG_MAX, preventing overflow while still allowing extremely large context values to work as expected (producing a single hunk for the entire file). The patch includes a test case verifying the fix works with the problematic value of 2147483647 lines of context.

Key technical details: The fix modifies `xdiff/xemit.c` to use safe addition when calculating `max_common`, which determines hunk boundaries. The test in `t4055-diff-context.sh` confirms the diff output contains all expected lines without repetition. The change maintains compatibility with GNU diff's behavior for extreme values while fixing the Windows-specific overflow case.

This is a focused fix for a narrow edge case that only affects Windows users specifying context values near INT_MAX. The solution is conservative, choosing to saturate rather than fail or document limits, keeping behavior consistent with other platforms and GNU diff. The test provides regression protection going forward.
