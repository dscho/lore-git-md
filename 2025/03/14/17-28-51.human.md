This is a discussion thread about the promisor-remote bugfix series, specifically addressing the architectural justification for handling missing remote URLs. Junio Hamano is pushing back on Christian Couder's defense of supporting relative path fallbacks in rare cases.

The exchange focuses on whether it makes practical sense to support remote configurations where:
1. A relative path is used without a configured URL (via r->name fallback)
2. The setup relies on symlinks or mounts to make the path work across machines

Junio argues that while such configurations might technically work, they represent poor system design - any admin capable of setting up symlinks/mounts could just as easily configure proper URLs. He distinguishes between "technically possible but useless" (first "rare") and "configuration that serves no purpose" (second "rare").

The discussion shows Junio maintaining his position from earlier in the thread that special-case handling for missing URLs should be removed entirely rather than accommodated, as the series has now done in its final form. This appears to be closing commentary on the architectural decisions rather than proposing further changes, as the case sensitivity resolution in Patch 3 has already been approved.
