Feature implementation for incremental MIDX bitmaps, part of Taylor Blau's ongoing series (v4 03/13). This patch lays groundwork for handling layered bitmap indexes by adding base tracking to the bitmap_index struct and related infrastructure.

The key technical additions are:
- New `base` pointer in `struct bitmap_index` to chain MIDX bitmap layers
- `base_nr` counter tracking total layer depth
- Modified `midx_bitmap_filename()` to handle split MIDX paths
- Updates to `open_midx_bitmap_1()` and `load_reverse_index()` to traverse MIDX chains
- Proper cleanup of base bitmaps in `free_bitmap_index()`

The changes are primarily plumbing - preparing the bitmap machinery to work with layered MIDXs while maintaining existing single-layer functionality. The patch handles core requirements like:
- Correct pack and revindex loading across MIDX layers
- Proper bitmap file path resolution for split MIDXs
- Memory management of chained bitmap indexes
- Safety checks for non-MIDX cases

This appears to be for future commits that will implement the actual multi-layer bitmap operations. The implementation follows the established pattern from earlier patches in the series, maintaining consistency in how MIDX chains are handled across the codebase. The changes are focused and well-contained to the pack-bitmap.c file.
