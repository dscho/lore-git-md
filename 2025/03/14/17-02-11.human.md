This is a design discussion about NUL-delimited I/O behavior in `git rev-list`, part of the ongoing feature implementation series.

Junio Hamano weighs in on the thread discussing whether `-z` should affect both input and output in `git rev-list`. He notes that while developers might expect consistency between `rev-list` and `log` (which share infrastructure), end users don't necessarily need this. He points out that `git log` already accepts `-z` while `rev-list` currently doesn't, and this discrepancy hasn't caused problems.

Hamano suggests a more flexible approach: having separate `--nul-delimited-output` and `--nul-delimited-input` options for precise control. He's open to starting with `-z` as a shorthand that could either control both (despite inconsistency with `git log`) or just output (for consistency). The key point is keeping the design flexible enough to allow independent control of input and output delimiters in the future.
