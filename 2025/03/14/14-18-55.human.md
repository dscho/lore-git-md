This is a follow-up to the Windows reftable bugfix discussion, providing additional context about alternative solutions. Christian Reich notes that while Patrick Steinhardt's v2 patch hasn't been merged yet, Git for Windows has implemented a separate change (commit dba1473162) that reduces the prompt spam by preventing multiple retry questions. He also mentions the existing `GIT_ASK_YESNO` workaround, though notes it slows down operations.

The email serves as a status update rather than proposing new changes, confirming that the underlying Windows prompt behavior is being addressed through multiple channels. The original patch from Patrick proposed a targeted solution using a `MINGW_DONT_HANDLE_IN_USE_ERROR` flag for reftable operations, while this follow-up shows parallel progress in Git for Windows itself. Both approaches aim to solve the same user experience issue where Windows would repeatedly ask about failed unlink operations during reftable maintenance.
