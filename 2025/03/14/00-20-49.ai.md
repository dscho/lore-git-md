CI / build system patch series aimed at preventing assertions with side effects. This is a cover letter introducing a 3-patch series that adds static analysis to catch potentially dangerous uses of assert() in the Git codebase.

The series proposes a new BUG_IF_NOT() macro as a safer alternative to assert() for cases where the assertion might contain side effects. The key motivation is that while CodingGuidelines could warn against problematic assertions, an automated CI check would be more effective at preventing these hard-to-debug issues. The author notes that while most existing assertions are safe, 9 cases are converted to the new macro as a precaution.

The implementation includes:
1. A new BUG_IF_NOT() macro in git-compat-util.h that won't be compiled out when NDEBUG is defined
2. A new check-unsafe-assertions.sh CI script that uses compiler/linker tricks to detect potentially problematic assertions
3. Conversion of the 9 identified special cases to use the new macro

The changes touch several subsystems including merge machinery, object storage, and parallel checkout. The author provides a link to example CI output showing the detection in action. This appears to be a well-motivated change with thorough implementation, addressing a subtle but potentially serious class of bugs through both tooling and code changes.
