Performance enhancement for incremental MIDX bitmap implementation (v4 06/13).

This patch extends pack-reuse capabilities to work across MIDX layers in Taylor Blau's incremental MIDX bitmap series. The changes focus on two key areas:

1. **Multi-pack reuse expansion**: Modifies the pack enumeration logic in `reuse_partial_packfile_from_bitmap()` to consider packs from all MIDX layers (current + base) rather than just the current layer. The loop now uses `m->num_packs + m->num_packs_in_base` as its upper bound when checking packs for reuse candidates.

2. **Preferred pack selection**: When reusing from a single pack, the patch now traverses to the oldest MIDX layer (via `while (m->base_midx) m = m->base_midx`) to select the preferred pack, as older layers are likely to contain more reusable sections. This maintains the existing preferred pack behavior but applies it across the MIDX chain.

The implementation builds on the base infrastructure established in earlier patches (particularly 03/13's MIDX chain traversal support) while introducing specific optimizations for the pack-reuse case. The changes are relatively contained (11 lines modified) but important for performance when dealing with incremental MIDXs.

Key technical details include:
- Modified `reuse_partial_packfile_from_bitmap()` function in pack-bitmap.c
- New traversal of MIDX base layers via `m->base_midx` chain
- Continued use of existing `nth_midxed_pack()` helper for pack lookups
- Maintains warning messages for error cases (preferred pack lookup failure)

This patch represents a natural progression in the series, addressing pack-reuse behavior that would become relevant once the full MIDX bitmap functionality is in place. The approach aligns with the established pattern of considering the full MIDX chain rather than individual layers.
