This is the first patch in a 3-part series addressing potentially dangerous uses of assert() in Git's codebase. It introduces a new BUG_IF_NOT() macro as a safer alternative to assert() that remains active even in production builds (when NDEBUG is defined). The macro is designed to catch assertion failures that might otherwise be silently dropped if they contain side effects.

The patch adds the macro definition in git-compat-util.h alongside Git's existing BUG() functionality. The implementation is straightforward - it checks a condition and triggers a BUG() call if the condition fails, with an automatically generated error message showing the failed assertion. The commit message notes this will be used to convert several existing assert() calls in subsequent patches.

This appears to be a well-motivated change addressing a subtle but potentially serious class of bugs. The implementation looks clean and focused, introducing just the core macro that the rest of the series will build upon. The commit message clearly explains the change and its purpose within the larger series.
