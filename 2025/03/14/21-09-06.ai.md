This is a cover letter for a 3-patch series addressing the `-Wunreachable-code` build warning discussion. The series combines work from Jeff King and Junio Hamano to handle compiler warnings about unreachable code in a cross-platform way.

The first patch (Jeff King) enables `-Wunreachable-code` in developer builds, which had previously identified a real issue in the packed refs backend. The second patch (Jeff King) uses `errno` checking as an interim solution to handle `sigfillset()` errors in `run-command.c`, addressing a false positive from the warning.

The key addition is Junio Hamano's third patch introducing a `NOT_A_CONST` macro with a global `false_but_the_compiler_does_not_know_it_` variable. This provides a systematic way to prevent compiler optimization of expressions we want to keep for defensive programming. The macro is demonstrated in `atfork_prepare()` and represents the maintainer's preferred architectural solution over platform-specific workarounds.

The series shows the evolution from initial warning detection through multiple solution iterations (platform exclusions, errno checks) to this final robust approach. It maintains cross-build-system consistency by incorporating Patrick Steinhardt's Meson build change. The solution preserves important defensive checks while eliminating false positives, with the macro approach being more general than case-by-case fixes.
