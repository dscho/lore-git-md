Bugfix and platform compatibility patch for `sigfillset()` error handling.

This is the second patch in a 3-part series addressing unreachable code warnings in the build system. The patch modifies how Git checks for `sigfillset()` failures to work around a compiler warning while maintaining POSIX compliance. 

The issue arises because macOS's `sigfillset()` always returns success (as documented), making the error-checking code appear unreachable to clang. Jeff King's solution switches from checking the return value to checking `errno`, which preserves error detection on platforms where `sigfillset()` can fail while avoiding the compiler warning. The patch includes a clear comment explaining the workaround's rationale.

This change is part of a broader effort to enable `-Wunreachable-code` warnings in Git's build system while handling platform-specific behaviors. The approach shows careful consideration of both technical correctness (maintaining error checking where needed) and build system cleanliness (avoiding false positives). The patch builds on the first patch in the series that enabled the warnings, and precedes Junio Hamano's more comprehensive `NOT_A_CONST` macro solution in patch 3.
