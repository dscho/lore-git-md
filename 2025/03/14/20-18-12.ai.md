This is a cover letter for a patch series implementing incremental MIDX bitmap support, part of Taylor Blau's ongoing work to enable efficient bitmap operations across multi-pack index layers. The series builds on previous work (parts 1 and pseudo-merge fixes) and represents the second of three planned series.

The core architectural approach remains unchanged from previous iterations: each MIDX layer maintains its own bitmap file, with the topmost layer driving reachability traversals while consulting lower layers for commit/pseudo-merge data. The key innovation is the `ewah_or_iterator` which combines type-level bitmaps across layers via logical OR operations, treating them as a unified bitmap.

The v4 iteration incorporates Patrick Steinhardt's feedback, focusing on documentation clarity, coding style alignment, and some technical refinements like the base layer indexing convention (now 0-based). The changes are mostly cosmetic - the functionality remains the same as v3.

The series touches multiple subsystems:
- Documentation updates explaining the bitmap layering
- Pack-revindex adjustments for MIDX chains
- Bitmap internals modifications to handle layered operations
- New EWAH iterator implementation
- MIDX writing capabilities for incremental bitmaps
- Test infrastructure

Notable technical details:
- Each commit/pseudo-merge exists in exactly one layer's bitmap
- Type-level bitmaps are combined via `ewah_or_iterator`
- Base layer indexing changed from 1-based to 0-based
- Pack-reuse optimization preserves layer invariants
- Comprehensive test coverage in t5334

The work represents significant progress toward efficient bitmap operations in large repositories, with the remaining goal being layer compaction support. The changes are well-motivated and carefully implemented, maintaining Git's architectural principles while extending functionality.
