Bugfix addressing integer overflow in diff hunk calculation on Windows. This is a follow-up to René Scharfe's patch that fixes an edge case where extremely large context values (like `--unified=2147483647`) could cause incorrect hunk splitting and line repetition in `git diff` output on Windows platforms.

Junio C Hamano reviews and approves the fix, praising its careful bounds-checking approach rather than simply switching to size_t. The solution introduces a `saturating_add()` helper that caps sums at LONG_MAX, preventing overflow while still allowing users to request all lines in a changed file as a single hunk when desired. The fix specifically targets Windows where `long` and `int` have the same size, making this platform uniquely vulnerable to the overflow.

The patch maintains compatibility with GNU diffutils' behavior and takes a conservative approach by saturating rather than failing or imposing artificial limits. Junio notes the patch is "well thought out" and queues it for inclusion, suggesting it will likely land in an upcoming release. This resolves the issue originally reported by Jason Cho where Windows users could observe incorrect diff output with unrealistic but technically valid context values.
