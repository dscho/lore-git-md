Incremental MIDX bitmap implementation (part 3/13). This patch adds core infrastructure for handling layered bitmap indexes in the pack-bitmap machinery. It introduces a new `base` pointer in `struct bitmap_index` to track the previous MIDX layer's bitmap, along with a `base_nr` counter to track the depth of the bitmap chain.

The changes are primarily plumbing work to:
1. Open and store bitmap layers correctly when working with MIDX chains
2. Ensure proper pack and revindex loading across MIDX layers
3. Handle cleanup of the base bitmap when freeing the structure
4. Adjust filename generation for split MIDX files

This is a foundational patch in the series that enables subsequent commits to implement the actual bitmap operations across layers. The implementation appears thorough, with careful attention to memory management and error cases. As noted in the commit message, the real bitmap operations will come in later patches - this one focuses on setting up the necessary scaffolding.

The patch maintains the series' high quality standards, with clear commit message explanations and comprehensive changes to the core bitmap handling code. It builds directly on the documentation and pack-revindex adaptations from the first two patches in v4.
