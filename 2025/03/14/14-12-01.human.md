This is the first patch in a bugfix series addressing NULL pointer dereferences in the promisor-remote subsystem. The patch fixes a segfault that occurs when a promisor remote has no URL configured by skipping such remotes entirely rather than attempting to push NULL into a strvec. The change also handles empty URLs consistently with missing ones, aligning with Git's standard remote behavior.

The fix is minimal and focused, modifying just the promisor-remote.c file to use git_config_get_string_tmp() for safer memory management while checking URLs. The patch includes extensive test coverage (59 new test lines) that verifies the behavior with both missing and empty URLs across different promisor remote scenarios.

This is part of a v5 series that has evolved through several iterations based on feedback, particularly from Junio Hamano, to remove special-case handling and align with Git's standard remote conventions. The current version cleanly separates concerns - this first patch handles just the core safety fix while subsequent patches address related architectural improvements.

The patch demonstrates good attention to detail with thorough test coverage and clear commit message explaining both the technical fix and the rare edge case (same-filesystem configurations) that might be affected. The changes appear well-considered and maintainable.
