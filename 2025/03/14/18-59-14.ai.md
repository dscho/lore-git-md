This is a design discussion follow-up in the NUL-delimited output format thread, primarily between Jeff King and Junio Hamano about the command interface philosophy for the `-z` option in `git rev-list`.

The email continues the debate about whether `-z` should control both input and output (as currently implemented) or just output (for consistency with `git log`). Jeff King acknowledges Junio's preference for separate `--nul-delimited-{output,input}` options as the ideal plumbing interface, but suggests the current combined `-z` behavior could serve as a convenient shorthand while preserving the ability to control input/output independently via the longer options.

Key technical points raised:
- Notes the current `rev-list` technically accepts `-z` but has no effect (since it doesn't produce diffs)
- Proposes keeping the implementation flexible enough to support both combined and separate control
- Suggests the combined `-z` behavior might be more user-friendly despite the inconsistency with `git log`

The discussion represents final interface design considerations after the technical implementation has been settled in previous patches. Both participants appear to view this as a forward-looking discussion rather than a blocking issue, with Jeff King emphasizing the importance of getting the initial `- z` behavior right since it would be hard to change later.
