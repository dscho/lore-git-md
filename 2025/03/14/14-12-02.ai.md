Bugfix patch hardening promisor-remote URL validation, part 2/3 in a series addressing promisor-remote safety issues. This patch specifically handles cases where a remote server advertises no URL or an empty URL, preventing potential NULL pointer dereferences while maintaining consistent warning messages.

The change modifies `should_accept_remote()` in `promisor-remote.c` to explicitly check for NULL or empty remote URLs before comparison. When such cases are detected, the function now rejects the remote and emits a standardized warning message (with "URL" consistently capitalized). The warning helps diagnose configuration issues while the early rejection prevents crashes.

This builds on the series' progression from initial NULL dereference fixes to more comprehensive validation. The patch aligns with the thread's direction of removing special cases while maintaining safety, as seen in the consolidated warning messages and explicit handling of edge cases. Test coverage for these scenarios was added in earlier patches of the series.

Key technical details:
- Adds NULL/empty check before `strcmp()` in `should_accept_remote()`
- Standardizes warning message capitalization ("URL" vs "url")
- Maintains consistent rejection behavior for invalid configurations
- Part of broader effort to remove special-case handling
- Follows through on architectural simplification suggested in thread discussion

The patch represents the middle step in a three-part series that has evolved through multiple iterations based on mailing list feedback, now focused on discrete, well-tested safety improvements to the promisor-remote subsystem.
