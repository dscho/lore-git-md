Bugfix addressing integer overflow in diff hunk calculation on Windows.

Junio C Hamano reviews and approves René Scharfe's patch fixing an arithmetic issue in `xdl_get_hunk()` that caused incorrect diff output with extremely large context values on Windows. The maintainer praises the careful bounds-checking approach using a new `saturating_add()` helper rather than simply switching to size_t, noting this preserves the ability to request all-file context while preventing overflow. The solution caps sums at LONG_MAX when calculating `max_common` for hunk boundaries, specifically addressing the Windows case where `long` and `int` share the same range.

The patch modifies `xdiff/xemit.c` to use safe addition when combining context lengths, with Junio confirming the implementation looks correct. This follows up on Jason Cho's original report showing `git diff --unified=2147483647` produced incorrect repeated context lines compared to GNU diff. The fix maintains compatibility with GNU diffutils' behavior while handling the overflow case properly.

Technical details show the solution involves wrapping the arithmetic in `xdl_get_hunk()` with saturation logic rather than introducing artificial limits. The accompanying test in `t4055-diff-context.sh` verifies correct handling of the problematic edge case value. The approval indicates this will be queued for inclusion, resolving the Windows-specific overflow while preserving cross-platform consistency in diff output formatting.
