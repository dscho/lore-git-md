This is a final discussion in the bugfix series addressing promisor-remote subsystem issues, specifically focusing on the architectural justification for handling missing remote URLs. The email captures Junio Hamano's response to Christian Couder's defense of supporting relative path fallbacks in rare cases.

Junio makes a key distinction between two interpretations of "rare" cases in the previous discussion: one being technically possible but practically dubious configurations (like symlink/mount setups), versus deliberately incomplete configurations that serve no useful purpose. He argues that even if relative path fallbacks are technically possible via filesystem tricks, they represent poor system design that would confuse users and maintainers. The core objection remains that using the remote name as a fallback URL creates more problems than it solves, regardless of implementation feasibility.

The exchange demonstrates the architectural principle being enforced - that Git should not accommodate configurations that work accidentally rather than by design. This finalizes the thread's direction toward explicitly rejecting invalid configurations rather than trying to handle edge cases, as reflected in the v5 series' hardened validation. The discussion confirms the series' approach of removing special cases aligns with Git's maintainability goals, with Junio's latest comments serving as final validation of the architectural decisions made in the patches.
