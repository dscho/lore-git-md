Bugfix improving error messaging in `git reflog expire` when given invalid references. This is part of a larger series introducing a `drop` subcommand to `git reflog`, but stands alone as a straightforward improvement to existing functionality.

The patch changes the error message from the vague "points nowhere!" to the more precise "reflog could not be found" when `git reflog expire` is given a non-existent reference or reflog entry. The new message directly states the problem is a missing reflog rather than implying some ambiguous reference state. The change affects both the core implementation in builtin/reflog.c and updates corresponding test expectations in t/t1410-reflog.sh to verify the new error text appears correctly. Test cases cover both invalid reflog entries (main@{123}) and non-existent references (does-not-exist).

This is a minor but clear improvement to user experience, making the error case more understandable. The change is uncontroversial - it doesn't modify behavior beyond the error message wording, maintains existing test coverage while updating assertions, and fits cleanly with the surrounding reflog management work. The patch follows the project's style and includes sign-off. As part of the v3 series, it has already undergone review with no outstanding issues noted.
