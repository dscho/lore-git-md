Bugfix improving error messaging in `git reflog expire`. This is the first patch in a two-part series introducing new reflog management capabilities, though it stands alone as a straightforward improvement to existing functionality.

The patch changes the error message when `git reflog expire` is given a non-existent reference from the vague "points nowhere!" to the clearer "reflog could not be found: '<ref>'". This makes the error more actionable by directly stating what went wrong (missing reflog rather than some other issue) and clearly showing the problematic input. The change is minimal - just a one-line modification to the error string in builtin/reflog.c plus corresponding test updates in t1410-reflog.sh to expect the new message format.

While small, this is a nice quality-of-life improvement that makes Git's error reporting more precise. The patch is cleanly focused, with no behavioral changes beyond the error message wording. It's part of Karthik Nayak's larger reflog management work, but stands well on its own as a simple, uncontroversial fix that could be applied independently of the more substantial 'reflog drop' functionality coming in the next patch.
