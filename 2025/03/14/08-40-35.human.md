Feature enhancement for `git reflog` adding a 'drop' subcommand to delete entire reflogs. This is the second and final patch in a series addressing the limitation where users could previously only remove individual reflog entries (via `expire` or `delete`) but not entire reflog structures.

The new `git reflog drop` command provides two key flags:
- `--all` to remove reflogs from all references across all worktrees
- `--single-worktree` to limit the scope to the current worktree when using `--all`

The implementation handles reference resolution via `repo_dwim_log` and uses `refs_delete_reflog` for the actual deletion. It includes comprehensive error handling and clear usage messages. The patch comes with extensive test coverage in t1410-reflog.sh, verifying behavior for single/multiple references, worktree handling, error conditions, and the mutual exclusion between `--all` and explicit references.

Documentation clearly distinguishes the new 'drop' subcommand from existing 'expire' and 'delete' functionality, noting that 'drop' removes the entire reflog structure rather than individual entries. The patch appears well-polished, having addressed all feedback from previous reviews, and provides a clean solution for users needing to manage reflog accumulation in repositories with `core.logAllRefUpdates=false`.
