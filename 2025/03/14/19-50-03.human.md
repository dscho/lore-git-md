Build system improvement for unreachable code detection. This is a follow-up in the ongoing discussion about handling compiler warnings for unreachable code, specifically addressing false positives from overzealous compiler optimizations.

Junio Hamano responds to Jeff King's suggestion about implementing a `CAN_BE_TAKEN` macro by proposing a more general solution called `NOT_A_CONST`. The patch introduces a new compilation unit and macro that prevents compilers from optimizing away expressions that may appear constant but could actually fail at runtime (like POSIX system calls). The implementation replaces the previous `errno`-based solution in `run-command.c` with this new approach.

The change affects multiple build systems (Makefile and Meson) and adds the new infrastructure in `git-compat-util.h`. The solution is more architectural than the previous platform-specific workarounds, though Junio notes the macro name may need refinement to be more generally applicable beyond just `if`/`while` statements. This appears to be a well-considered technical solution to the problem, moving the thread forward from temporary fixes toward a more maintainable approach.
