This is the first patch in a bugfix series addressing NULL pointer dereferences in the promisor-remote subsystem. The patch specifically prevents a segfault that occurs when a promisor remote has no configured URL by skipping such remotes entirely rather than attempting to push NULL into a strvec. The fix is minimal and focused, avoiding any broader architectural changes while maintaining safety.

The patch modifies `promisor-remote.c` to use `git_config_get_string_tmp()` for cleaner memory handling and explicitly skips remotes with missing or empty URLs. This matches Git's standard behavior of treating missing and empty URLs equivalently. The change is accompanied by 59 new test lines in `t/t5710-promisor-remote-capability.sh` that verify the fix handles both missing and empty URL cases correctly.

Technical details show the patch removes the problematic `xstrdup(NULL)` case while maintaining functionality for filesystem-sharing configurations where remote names alone might suffice. The implementation cleanly separates the safety fix from later patches that will standardize URL handling behavior. The tests demonstrate both the crash prevention and expected failure modes when URLs are missing or empty.

This represents the first of three focused patches in the v5 series, following Junio's feedback to split the original fix into distinct components. The thread history shows this version has converged on a solution that addresses the immediate safety issue while leaving broader architectural improvements for subsequent patches.
