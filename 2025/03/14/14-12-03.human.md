Bugfix patch finalizing case sensitivity alignment in promisor-remote handling. This is the third and final patch in Christian Couder's v5 series addressing promisor-remote issues.

The patch makes remote name comparisons case-sensitive in the promisor-remote subsystem, bringing it in line with Git's standard remote configuration behavior. The commit explains that while Git treats configuration section names case-insensitively (like "remote.origin.fetch" vs "Remote.origin.FETCH"), the actual remote nickname portion ("origin" in this example) is case-sensitive. The change modifies both the implementation code and documentation to reflect this.

The implementation is straightforward - replacing a `strcasecmp()` with `strcmp()` in the nickname comparison function, plus updating the documentation to explicitly state that name and URL comparisons are case sensitive. This matches how Git handles remote names elsewhere in the codebase.

As the final patch in a well-discussed series, this appears ready for inclusion. It completes the architectural alignment with Git's remote handling conventions that Junio Hamano requested in earlier reviews.
