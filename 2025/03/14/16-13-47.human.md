This is a follow-up in the ongoing discussion about enabling `-Wunreachable-code` warnings in developer builds. Jeff King proposes an alternative solution to the macOS-specific false positives from `sigfillset()` that doesn't require disabling the warning entirely on Darwin systems.

The patch changes the error checking in `run-command.c` to use `errno` rather than the return value of `sigfillset()`, cleverly working around the compiler's ability to detect the unreachable code path on macOS (where the function always succeeds). This preserves the warning's usefulness on all platforms while silencing the false positive.

The approach demonstrates deeper consideration of the tradeoffs than the earlier platform-specific disablement - it maintains warning coverage for platform-specific code paths while being more correct according to POSIX (which specifies `errno` should be set on error). The solution is elegant in that it uses the standard's own mechanisms to outsmart overzealous compiler optimizations.

This continues the thread's evolution from initial implementation through platform-specific issues to increasingly refined solutions. The patch shows good attention to both technical correctness and practical developer experience concerns.
