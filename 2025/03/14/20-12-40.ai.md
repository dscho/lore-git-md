This is a follow-up in the ongoing Rust crates publishing discussion, part of the Git v2.49.0 release thread's Rust integration work. Brian M. Carlson responds to Josh Steadmon's report about difficulties publishing Git's Rust crates to crates.io due to build system incompatibilities between Cargo and Git's Makefile-based workflow.

The email acknowledges the temporary solution of publishing placeholder crates to prevent name squatting, while noting that Git repositories could technically serve as an alternative distribution mechanism to crates.io. Carlson suggests using `cargo package` as a test case to explore build solutions, mentioning it could be integrated into CI to catch similar issues earlier. The tone is collaborative, focusing on practical next steps rather than immediate resolution.

Key technical points for future reference: the issue stems from `cargo publish` not including the repository root, breaking Makefile dependencies; `libgit*` crate names are at stake; and `cargo package` is proposed as a diagnostic tool. The discussion remains open-ended regarding the final publishing strategy (crates.io vs Git repos).
