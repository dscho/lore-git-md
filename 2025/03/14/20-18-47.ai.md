Feature implementation for incremental MIDX bitmaps with pseudo-merges.

This patch extends the pseudo-merge functionality to work across MIDX bitmap layers, marking the ninth installment in Taylor Blau's 13-part series on incremental MIDX bitmaps. The change modifies `apply_pseudo_merges_for_commit_1()` to traverse the MIDX chain when applying pseudo-merges, checking each layer's bitmap index in sequence.

The key technical change replaces a single pseudo-merge application with a while-loop that walks through the MIDX chain via the `base` pointer (introduced in patch 03/13). For each layer, it applies that layer's pseudo-merges to the result bitmap, accumulating the count of satisfied pseudo-merges. The return value now sums successful applications across all layers rather than just the topmost one.

This builds directly on the layered MIDX infrastructure established in earlier patches, particularly the recursive traversal pattern seen in 04/13's commit lookup and 07/13's test infrastructure. The change maintains the existing pseudo-merge counting mechanism (`pseudo_merges_satisfied_nr`) but now accounts for matches found in any layer.

The implementation appears straightforward and consistent with the series' architectural direction. It handles the NULL-terminated MIDX chain properly and preserves the existing error handling behavior. As with previous patches in the series, this extends functionality while maintaining compatibility with single-layer MIDX cases.

This moves the series closer to complete MIDX bitmap functionality by addressing one of the remaining open items from the thread summary - proper handling of pseudo-merges in the layered context. The change is focused and builds logically on the established MIDX chain traversal patterns from earlier patches.
