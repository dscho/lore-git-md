This is a cover letter for a 13-patch series implementing incremental MIDX bitmap support, part of Taylor Blau's ongoing work to improve multi-pack index functionality. The series builds on previous work to enable reachability bitmaps that can be updated incrementally rather than requiring full rewrites.

The key technical approach involves:
- Each MIDX layer having its own bitmap file tracking only its objects
- A new `ewah_or_iterator` to efficiently OR together type-level bitmaps across layers
- Reachability traversals using only the topmost bitmap while consulting lower layers for commit/pseudo-merge data

The cover letter notes this is the second of three planned series, with future work focusing on compaction of MIDX layers. The current changes are mostly refinements from v3 based on Patrick Steinhardt's review - clarifying documentation, aligning with coding guidelines, and fixing some indexing conventions (notably changing `base_nr` from 1-based to 0-based).

The implementation appears thorough, with tests added in t5334. The changes touch core bitmap handling, MIDX writing, and introduce new EWAH bitmap operations. While the architectural approach remains unchanged from previous iterations, the implementation details have been polished based on review feedback. This looks like a solid step toward more efficient bitmap maintenance in large repositories.
