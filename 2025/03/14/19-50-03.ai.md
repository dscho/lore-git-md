Build system improvement for unreachable code detection.

This email from Junio Hamano responds to Jeff King's suggestion about implementing a `CAN_BE_TAKEN` macro to handle compiler warnings about unreachable code. Junio proposes a more general solution called `NOT_A_CONST` that would work across different control structures (if/while/switch) by introducing a global variable `false_but_the_compiler_does_not_know_it_` that's defined in a separate compilation unit. This prevents compilers from optimizing away expressions that might appear constant but could actually fail at runtime.

The patch implements this approach with several key changes:
1. Adds a new compilation unit `fbtcdnki.c` (presumably containing the global variable)
2. Introduces the `NOT_A_CONST` macro in `git-compat-util.h`
3. Updates both Makefile` and `meson.build` to include the new source file
4. Modifies `run-command.c` to use the new macro for the `sigfillset()` check that was previously using an `errno` workaround

Junio notes that while the `CAN_BE_TAKEN` name might work for if/while statements, it wouldn't be appropriate for switch cases, hence the more general `NOT_A_CONST` name. The solution maintains the warning's usefulness while avoiding platform-specific workarounds, aligning with the maintainer's preference for systematic solutions over one-off fixes.

The approach represents a more architectural solution to the problem of compiler false positives for unreachable code warnings, though Junio indicates he may still improve the macro name. This continues the thread's evolution from platform-specific exclusions to errno checks to this more general mechanism.
