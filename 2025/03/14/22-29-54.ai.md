This is the final patch in a 3-part series addressing build system improvements for unreachable code detection, specifically focusing on a systematic solution for false positives with `-Wunreachable-code`.

The patch introduces a new `NOT_A_CONST` macro and supporting infrastructure to handle cases where compilers incorrectly optimize away code paths that should remain reachable. The key technical components are:

1. A new compilation unit `fbtcdnki.c` containing a global variable `false_but_the_compiler_does_not_know_it_` (initialized to 0 but never modified)
2. The `NOT_A_CONST(expr)` macro that ORs any expression with this variable, preventing compiler optimization while maintaining semantics
3. Application of this macro to replace the previous `errno`-based workaround in `run-command.c`'s `atfork_prepare()` function for `sigfillset()` checking
4. Build system integration (both Makefile and Meson) for the new compilation unit

The solution is more general than previous approaches (like the `errno` workaround or proposed `CAN_BE_TAKEN` macro) and better documents developer intent. It maintains POSIX compliance while preventing false positives from `-Wunreachable-code` warnings, particularly for cases like `sigfillset()` where platform headers may incorrectly indicate certain calls cannot fail.

This patch represents the final architectural solution in the series, following an evolution from initial warning enablement (patch 1) to platform-specific workaround (patch 2) to this systematic approach. The implementation is cross-build-system compatible and preserves warning detection on supported platforms while handling edge cases.
