This is the final patch in a 3-part series addressing build system improvements for unreachable code detection, specifically focusing on the `-Wunreachable-code` compiler warning. Junio Hamano introduces a systematic solution to replace the earlier platform-specific workarounds.

The patch adds a new `NOT_A_CONST` macro that prevents compilers from optimizing out expressions that might trigger false positives with `-Wunreachable-code`. The implementation includes a new compilation unit (`fbtcdnki.c`) containing a variable that the compiler cannot prove is constant, allowing the macro to work across control structures. The solution is applied to `sigfillset()` checks in `run-command.c`, replacing Jeff King's earlier `errno`-based workaround.

The approach is more maintainable than per-case workarounds and preserves warning detection on supported platforms while working across both Makefile and Meson build systems. The commit message thoughtfully discusses the tradeoffs, noting this should be used sparingly - if the warning triggers too often, it may indicate `-Wunreachable-code` isn't useful for Git's codebase.

This appears to be a well-considered architectural solution to the problem, completing the series that started with warning enablement and progressed through intermediate fixes. The patch is cleanly implemented with thorough documentation of the macro's purpose.
