Bugfix patch hardening promisor-remote URL handling. This is the second patch in Christian Couder's v5 series addressing issues in the promisor-remote subsystem.

The patch focuses on error handling when a remote server doesn't advertise any URL. It adds explicit NULL and empty string checks for `remote_url` in `should_accept_remote()`, rejecting such cases with a warning message. The warning text is also standardized to use uppercase "URL" consistently.

This change prevents potential crashes if a server stops advertising URLs in the future, while maintaining the same diagnostic warnings seen in the rejection path. The implementation follows the series' architectural direction of removing special cases and aligning with Git's standard remote conventions.

The patch builds on the first patch's NULL dereference fix (which used `git_config_get_string_tmp()` for memory safety) and precedes the third patch addressing case sensitivity. Together, these three patches provide comprehensive solution to the promisor-remote issues while significantly expanding test coverage (59 new test lines in the series).

The changes are minimal and focused, with clear commit message explaining both the technical fix and the diagnostic improvements. The patch appears ready for inclusion, having incorporated feedback from Junio and others through five iterations of refinement.
