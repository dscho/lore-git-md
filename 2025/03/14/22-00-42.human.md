This is a bugfix addressing an integer overflow in Git's diff machinery on Windows. The patch fixes an issue where extremely large context values (approaching INT_MAX) with `--unified` could cause incorrect hunk splitting and line repetition, as originally reported by Jason Cho.

The core problem occurs in `xdl_get_hunk()` where arithmetic operations on context lengths could overflow on Windows (where `long` and `int` are the same size). René Scharfe's solution introduces a `saturating_add` helper to prevent overflow by capping at LONG_MAX, while maintaining the expected behavior of showing all lines in a single hunk when requested.

The fix comes with a new test case that verifies `-U2147483647` works correctly, checking both the output line count and specific expected content. While this edge case has limited practical impact (requiring unrealistically large context values), the fix ensures correctness matches GNU diff's behavior and prevents potential issues on Windows platforms.

The patch appears well-constructed with a clear commit message explaining both the problem and solution, plus a regression test. It directly addresses the reported issue without introducing new complexity beyond the necessary overflow protection.
