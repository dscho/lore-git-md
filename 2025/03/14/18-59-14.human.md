This is a design discussion about the NUL-delimited output format for `git rev-list`, part of an ongoing thread about Justin Tobler's patch series.

Jeff King (Peff) responds to Junio Hamano's thoughts about command interface consistency between `git rev-list` and `git log`. While acknowledging that end users may not care about the discrepancy, Peff notes that `rev-list` technically already accepts `-z` (though it's currently a no-op for diffs). 

The key discussion point is whether the new `-z` option should handle both input and output (as currently implemented) or just output (for consistency with `git log`). Peff suggests that while longer option names (`--nul-delimited-{output,input}`) would be ideal plumbing, the team should carefully consider `-z`'s behavior now since it will be hard to change later. He proposes keeping the current "both input and output" implementation while allowing the longer names as escape hatches for finer control.

This email represents the final design discussion before the series (now at v3) is likely to be merged, with all technical implementation already agreed upon. The remaining question is purely about interface philosophy - whether to balance plumbing purity with practical usability.
