This is the ongoing discussion about the NUL-delimited output format interface design for `git rev-list`, specifically addressing the option syntax. Junio Hamano responds to Justin Tobler's proposal for a combined `--nul-delimited={all,input,output}` option format.

Junio argues against the combined option approach, preferring separate `--nul-delimited-input` and `--nul-delimited-output` flags. His key objections are that the combined syntax requires more planning (needing to change from "output" to "all" when adding input support) and introduces potential confusion between "all" vs "both" terminology. He emphasizes that plumbing-level commands should maintain orthogonal, independent options even if it makes the interface slightly more verbose.

This represents the final point of discussion in an otherwise technically complete series. The implementation already supports both approaches - the decision now centers purely on user interface design philosophy between Junio's preference for explicit control and the proposed combined syntax. The thread shows the Git maintainer's typical attention to long-term usability and scriptability considerations in plumbing commands.
