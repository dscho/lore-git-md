Feature implementation for incremental MIDX bitmaps.

This patch (04/13 in the series) extends the `bitmap_for_commit()` function to support layered MIDX bitmaps by adding recursive lookup capability. When a commit isn't found in the current bitmap layer, the function now automatically checks the base layer (via the new `base` pointer added in 03/13). The changes include:

1. Moving the `hash_pos` declaration to avoid initialization issues with recursive calls
2. Adding NULL checks for the bitmap_index parameter
3. Implementing the recursive fallback to base layers when commits aren't found in the current layer
4. Maintaining the existing lazy-loading behavior for table_lookup cases

The implementation preserves all existing behavior while adding the new layer traversal capability. This is a key piece of the incremental MIDX bitmap architecture, enabling the system to combine bitmap data across multiple MIDX layers. The patch follows the established pattern from earlier in the series, building on the base infrastructure from 03/13 and pack-revindex adaptations from 02/13.

The changes are focused and mechanical, with no apparent edge cases left unhandled. The recursive approach matches the layered MIDX design philosophy while keeping the diff small (just 11 lines changed). This appears ready for review as part of the ongoing series, though test coverage of the recursive behavior would be valuable to confirm in later patches.
