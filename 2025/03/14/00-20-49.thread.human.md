This thread introduces safer alternatives to Git's assert() macro to prevent potentially dangerous assertions with side effects. The 3-patch series adds a new BUG_IF_NOT() macro that remains active even in production builds, implements CI detection of risky assertions, and converts all identified cases. The clever CI technique - which forces compilation failures when assertions contain function calls - was contributed by Bruno De Fraine and has now been confirmed as public domain, resolving the last licensing concern.

The technical approach has already received positive reviews from Junio Hamano (who suggested shell script improvements) and brian m. carlson (who confirmed C99 compliance). Elijah Newren, responding to the licensing discussion, notes he'll send a final version updating the commit message and addressing Junio's style feedback. With all concerns now addressed and the core technique cleared for use, this series appears ready for merging once those final tweaks are made. The changes affect several key subsystems including merge machinery and object storage, but are mechanical conversions that maintain existing behavior while adding production-build safety.
