This is a follow-up discussion in the ongoing thread about NUL-delimited output in `git rev-list`, now focusing on the command-line interface design.

Justin Tobler responds to Jeff King and Junio Hamano's discussion about whether to use a single `-z` flag or separate options for controlling NUL-delimited input and output. He proposes a compromise approach using a `--nul-delimited` option that could take values like `all`, `input`, or `output` to specify which parts should use NUL delimiters. This would provide more explicit control than a simple `-z` flag while maintaining flexibility.

The suggestion comes after the technical implementation of NUL-delimited I/O has already been completed in the patch series (now at v3), with all participants agreeing on the underlying functionality. This email focuses purely on the user interface question of how to expose that functionality through command-line options. Justin indicates willingness to send another version of the series implementing this alternative interface if there's consensus to move in this direction.

The discussion represents the final design decision needed before this feature can be merged, with the technical implementation already being in good shape. The key question now is whether to proceed with the current `-z` approach or switch to a more explicit interface as proposed here.
