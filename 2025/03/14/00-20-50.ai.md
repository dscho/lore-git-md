This is the first patch in a 3-part series introducing safer alternatives to assert() in Git's codebase. The patch adds a new `BUG_IF_NOT()` macro to git-compat-util.h that serves as a side-effect-safe replacement for assert(). Unlike regular assert() which gets compiled out in production builds (when NDEBUG is defined), BUG_IF_NOT() remains active at all times while maintaining the same assertion-checking behavior. The macro uses Git's existing BUG() infrastructure to report failures, making it consistent with the project's error handling patterns.

The implementation is minimal - just a single line addition that wraps the condition check and formats a failure message using the existing BUG_fl() machinery. The commit message explains this will be used to replace problematic assert() calls that may have side effects, though the actual conversions come in later patches. The change touches a core header file (git-compat-util.h) that affects all compilation units, but the addition is straightforward and unlikely to cause conflicts.

This foundational change enables the subsequent patches to safely convert existing assertions while maintaining runtime checking. The macro's design ensures it can be used anywhere assert() would be, but with guaranteed execution of the condition check. The patch appears well-scoped and properly motivated as part of the larger series goal to catch dangerous assertions through automated tooling rather than just documentation warnings.
