Build system improvement for unreachable code detection (final patch in series). This is the third and concluding patch in a series addressing `-Wunreachable-code` warnings, implementing Junio Hamano's architectural solution after Jeff King's initial warning enablement and platform-specific workarounds.

The patch introduces a new `NOT_A_CONST` macro that prevents compilers from optimizing out code paths they incorrectly deem unreachable. The macro works by OR'ing expressions with a global variable (`false_but_the_compiler_does_not_know_it_`) defined in a new compilation unit, making the compiler-visible value non-constant. This replaces the previous `errno`-based workaround for `sigfillset()` in `run-command.c` with a more general solution that better documents developer intent.

The implementation adds a new source file (`fbtcdnki.c`) to hold the dummy variable and updates both Makefile and Meson build systems. The change is minimal (16 lines added, 7 removed) but provides a systematic way to handle similar cases that might appear elsewhere. The commit message thoughtfully explains the tradeoffs between case-by-case workarounds and compiler warning utility, suggesting this approach is preferable if more such cases emerge.

This appears to be a well-considered solution to a tricky compiler interaction problem, completing the thread's progression from warning enablement through platform workarounds to a maintainer-approved architectural approach. The patch maintains cross-platform compatibility while improving code clarity compared to the previous `errno`-checking version.
