Performance enhancement for incremental MIDX bitmaps (part 11/13 of series)

This patch extends Taylor Blau's incremental MIDX bitmap work by adding infrastructure to track type-level bitmaps (commits, trees, blobs, tags) across all layers of a multi-pack index chain. It's a preparatory step for efficiently combining these bitmaps using the new `ewah_or_iterator` introduced in patch 10/13.

The change adds four new arrays to `struct bitmap_index` to store each layer's type information, with careful handling of both incremental and non-incremental cases. The `load_all_type_bitmaps()` function populates these arrays by walking the MIDX chain, while maintaining the existing single-pack behavior. The patch includes proper memory management with additions to `free_bitmap_index()`.

This is a well-contained technical piece that follows the series' established patterns. The commit message clearly explains the purpose and the diff shows careful attention to edge cases (like the BUG check for unexpected layer counts). As with previous patches in this series, it builds incrementally toward the goal of efficient cross-layer bitmap operations while maintaining backward compatibility.
