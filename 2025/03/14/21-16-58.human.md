This is a design discussion in the ongoing thread about adding NUL-delimited I/O support to `git rev-list`. Junio Hamano responds to Justin Tobler's proposal for a new `--nul-delimited={all,input,output}` option syntax, arguing against it in favor of keeping separate `--nul-delimited-input` and `--nul-delimited-output` flags.

Junio makes a pragmatic case for maintaining independent options, pointing out that the proposed combined form would require more cognitive overhead when modifying scripts over time. He notes that with separate flags, script authors can independently toggle input and output handling without needing to remember special "all" syntax or rewrite existing option selections. The response reinforces Junio's previously stated preference for explicit control at the plumbing level, even if it results in slightly more verbose command lines.

This email represents the final outstanding discussion point before the series can be merged - all technical implementation aspects are settled, and the debate has narrowed to just the command-line interface design. Junio's position contrasts with Jeff King's preference for a combined `-z` shorthand, with Justin having proposed this middle-ground syntax as a potential compromise. The exchange shows the careful consideration Git maintainers give to plumbing command interfaces, even for what might seem like minor syntactic differences.
