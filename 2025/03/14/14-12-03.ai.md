Bugfix patch finalizing case sensitivity behavior in promisor-remote subsystem. This is the third and final patch in Christian Couder's v5 series addressing promisor-remote issues, now making remote name comparisons consistently case-sensitive to match Git's standard behavior for remote configuration.

The change modifies both the implementation in `promisor-remote.c` and updates the documentation in `Documentation/config/promisor.adoc`. The patch switches from `strcasecmp()` to `strcmp()` in the `remote_nick_find()` function, ensuring remote nicknames are compared case-sensitively. This aligns with how Git handles remote configuration sections, where "remote.Origin.fetch" is distinct from "remote.origin.fetch" despite the case-insensitive handling of other configuration components.

The documentation update explicitly states that both name and URL comparisons are case sensitive, clarifying expectations for users configuring promisor remotes. This change completes the series' goal of bringing promisor-remote behavior into alignment with Git's standard remote conventions while maintaining safety, following Junio's earlier architectural feedback.

The patch is narrowly focused and well-justified, with the commit message clearly explaining the rationale by referencing how remote nicknames work in Git's configuration system. The changes are minimal (4 lines total) but important for consistency, and the series as a whole has undergone significant refinement through multiple iterations based on mailing list discussion.
