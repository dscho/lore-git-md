This is the final patch (13/13) in Taylor Blau's v4 series implementing incremental MIDX bitmaps, completing the writing side of the functionality after previous patches established the reading infrastructure. The patch teaches Git to write multi-layer bitmap indexes by:

1. Modifying `find_object_pos()` to locate objects in previous MIDX layers when they don't exist in the current layer's pack_order, using a new MIDX parameter to track base layers. The pack_order field is moved into `write_midx_context` to simplify callers.

2. Updating `bitmap_writer_build_type_index()` to offset type-level bitmap positions by the number of objects in base layers, enabling proper OR-ing of bitmaps across layers. The writer initialization now accepts a MIDX parameter to track the base layer context.

Key technical changes include:
- New `ewah_or_iterator_release()` function (renamed from `free`)
- MIDX writing now handles incremental bitmap cases that were previously forbidden
- Pack-reuse testing across different `pack.allowPackReuse` modes
- Verification of multi-layer bitmap reading through rev-list tests
- Proper handling of MIDX chain relinking when converting between incremental and non-incremental modes

The implementation maintains consistency with the series' architectural patterns, particularly in handling layer traversal and bitmap operations. Test coverage in t5334 exercises the new writing functionality through layer creation, bitmap verification, and object access scenarios.

This completes the core MIDX bitmap layering work, with all infrastructure now in place for both reading and writing incremental bitmaps. The changes are focused and well-contained, building logically on the prior patches in the series.
