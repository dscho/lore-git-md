Christian Couder responds to Junio Hamano's architectural concerns about the promisor-remote NULL dereference fix, proposing simplifications to address the feedback. This is part of an ongoing discussion about how promisor remotes should handle missing or empty URLs, with implications for both implementation details and broader design principles.

Couder agrees with Junio's suggestion to simplify promisor_info_vecs() by excluding remotes without URLs entirely, rather than handling them as special cases. He acknowledges the filesystem-sharing use case without URLs is rare and can be worked around by specifying explicit URLs. The response also clarifies that empty URLs behave similarly to missing URLs in Git's remote handling, justifying treating them identically in the promisor context.

Regarding case sensitivity, Couder notes an inconsistency in Junio's explanation (correcting that remote nicknames are actually case-sensitive in config) and indicates this will be addressed in a separate patch. The exchange reveals Couder's willingness to streamline the solution by removing edge case handling that Junio considered over-engineering, while still preserving the core functionality needed to prevent the NULL dereference.

Key technical points in this response:
- Accepts removing r->name entries for remotes without URLs at the source
- Will treat empty URLs same as missing URLs (excluding both from consideration)
- Notes filesystem paths can work as remote names despite validation rules
- Corrects misunderstanding about remote nickname case sensitivity
- Indicates case sensitivity fix will come in separate patch

The discussion continues to balance immediate safety fixes against broader questions about promisor remote design, with Couder now favoring a more minimal approach that defers some architectural questions while still solving the crash bug. Junio's persistent concerns about design coherence appear to be steering the solution toward greater simplicity, though some fundamental questions about promisor remote behavior remain open.
