This is a feature patch series (2/2) implementing a new 'drop' subcommand for `git reflog` to completely remove reflogs, addressing a gap where users could only expire individual records but not delete entire reflogs. The series has evolved through three versions with all review feedback addressed.

The current patch (v3) introduces the 'drop' subcommand with two key flags: '--all' to remove reflogs across all worktrees and '--single-worktree' to limit deletion to the current worktree. The implementation handles reference resolution via `repo_dwim_log` and uses `refs_delete_reflog` for the actual deletion. Error handling has been strengthened with clearer messages using `usage()`, and the code structure was improved by moving the reference-processing logic into an else block.

Test coverage in t1410-reflog.sh is comprehensive, verifying:
- Single and multiple reference deletion
- Mixed success/failure scenarios
- Worktree handling (both all worktrees and single-worktree cases)
- Error conditions (nonexistent refs, invalid combinations)
- Command-line constraints (mutual exclusion of --all and explicit refs)

Documentation has been reorganized to clearly distinguish between 'drop' (removing reflog structure), 'expire' (pruning entries), and 'delete' (removing refs). The patch also includes a preparatory commit improving error messages for nonexistent reflogs in the 'expire' subcommand.

All substantive review requests from Patrick Steinhardt have been implemented, including documentation reorganization, error handling improvements, and the addition of the '--single-worktree' flag. The only remaining discussion point was a minor code structure preference regarding loop placement, which doesn't affect functionality. Junio Hamano has acknowledged the utility of this feature for workflows needing selective reflog management between different core.logAllRefUpdates modes.

The series appears ready for inclusion after the current feature freeze period, with architectural questions cleanly separated from the user-facing functionality. The implementation is thorough, with comprehensive test coverage addressing all edge cases mentioned in reviews.
