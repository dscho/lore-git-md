Maintainer documentation update regarding third-party project issue reporting. This is Junio Hamano's follow-up to his earlier proposal about documenting where to report issues for Git-related projects like git-scm.com, Git for Windows, and ProGit.

The email marks a reversal of the maintainer's previous position - where he had indicated he would withdraw the documentation change due to lack of community feedback. Instead, the latest MaintNotes now includes the proposed "Other places" section listing GitHub issue trackers for these projects. The section provides direct links to issue trackers (git-scm.com/issues, git-for-windows/git/issues, progit/progit2/issues) and contribution guidelines.

Key technical details remain unchanged from the original proposal: the documentation lives in the maintainer-facing MaintNotes rather than user docs, and the same three fundamental questions about maintenance approach, inclusion criteria, and documentation placement remain unresolved. The maintainer is now soliciting corrections to the contact information as well as suggestions for additions or removals from the list.

This appears to be a "ship first, refine later" approach to the documentation, putting the initial version in place while keeping the discussion open about the long-term maintenance strategy. The thread continues to highlight the tension between providing useful contributor guidance and the overhead of maintaining accurate external project references.
