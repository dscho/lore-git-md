Build system improvement for unreachable code detection (follow-up). This is a follow-up to Jeff King's earlier patch enabling `-Wunreachable-code` in developer builds, now addressing platform-specific issues that emerged.

The patch disables the warning specifically on macOS due to false positives around `sigfillset()` calls. On macOS, `sigfillset()` always returns success (despite POSIX allowing errors), making compiler-visible error paths unreachable only on that platform. The change preserves the warning for Linux/Clang CI jobs where it has proven useful in catching real issues (like the packed backend problem found earlier).

Jeff notes this is still exploratory - while the macOS workaround is straightforward, it's unclear how many other false positives might emerge. The patch maintains the warning's availability in most CI environments while avoiding known-bad cases, striking a balance between detection capability and developer experience. The implementation uses a simple platform check in `config.mak.dev` to exclude Darwin systems.

Key technical details preserved for future reference:
- Specific affected function: `sigfillset()` in `run-command.c`
- Platform behavior difference: macOS vs POSIX spec
- Implementation mechanism: `$(uname_S)` check in build config
- Warning remains active in linux-sha256 CI job
- Maintainer (Junio Hamano) had previously approved limited evaluation approach
- Open question about FreeBSD behavior (manpages differ from macOS)
