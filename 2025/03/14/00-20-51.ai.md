This is the second patch in a 3-part series introducing safer alternatives to assertions with side effects. The patch adds CI infrastructure to detect potentially dangerous assert() calls that might have side effects.

The core of the patch is a new script `ci/check-unsafe-assertions.sh` that uses a clever compiler trick to identify assertions: it redefines assert() to reference an undefined symbol, causing the build to fail if the compiler can't prove the assertion has no side effects. The script then extracts and displays the problematic assertions from the error output, suggesting they be converted to BUG_IF_NOT() (introduced in patch 1).

The patch shows 9 existing assertions that trigger the check, spread across merge machinery (merge-ort.c, merge-recursive.c), object storage (object-file.c), parallel checkout, and other areas. While the author notes these appear side-effect-free to human inspection, they involve function calls that confuse the compiler. The CI check will run as part of static analysis.

The implementation adds a new build flag CHECK_ASSERTION_SIDE_EFFECTS and integrates the check into run-static-analysis.sh. The assert() redefinition in git-compat-util.h is carefully scoped to only activate during CI checks, avoiding impact on normal builds. The approach allows iterative cleanup - fixing some assertions will reveal others in subsequent runs.

This continues the series' proactive approach to catching a subtle class of bugs where assertions with side effects could cause different behavior between debug and production builds. The CI integration ensures the check runs automatically rather than relying on developer vigilance.
