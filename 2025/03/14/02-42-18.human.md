Jeff King provides technical refinements to Simon Josefsson's reproducible bundle approach, addressing edge cases and offering lower-level alternatives.

This follow-up in the reproducible bundles thread offers practical improvements to Simon's successful experiment with `pack.threads=1`. Jeff notes that while Simon's method works for identical repository states, the repack operation considers all repository objects - meaning bundle hashes would change if new tags or branches are added later. He suggests creating minimal clone repositories first to isolate the desired refs.

Jeff then presents two alternative approaches for advanced users: a manual bundle creation method that bypasses `git-bundle` to directly control pack-objects parameters, and a content verification method that operates on the bundle's unpacked objects. Both methods are more involved but offer different tradeoffs in terms of Git version compatibility and trust requirements.

The email maintains the thread's technical depth while acknowledging the inherent tradeoffs between simplicity and robustness in bundle verification. Jeff's suggestions don't invalidate Simon's working solution but rather expand the toolkit for different use cases, particularly where repository state might change between bundle generations.
