This is a build system improvement series addressing unreachable code detection, now incorporating feedback from the ongoing thread. The 3-patch series combines work from Jeff King and Junio Hamano to handle compiler warnings about unreachable-code in a cross-platform way.

The first patch (Jeff King) enables `-Wunreachable-code` in developer builds, which had previously identified a real issue in the packed refs backend. Patrick Steinhardt's Meson build system change is now squashed into this patch for consistency across build systems.

The second patch (Jeff King) takes the simpler approach of using `errno` checks to prevent the compiler from optimizing out a `sigfillset()` error check in `run-command.c`. This was the immediate solution that prompted Junio to think about a more systematic approach.

The third patch (Junio Hamano) introduces a new `NOT_A_CONST` macro that provides a general way to mark expressions the compiler shouldn't optimize away. This architectural solution is demonstrated by applying it to the `atfork_prepare()` function. The approach uses a global variable to fool the compiler while maintaining clean code semantics.

The series shows the discussion progressing from problem identification through platform-specific workarounds to a robust cross-platform solution. While the `errno` check provides an immediate fix, the `NOT_A_CONST` macro offers a more maintainable long-term approach for similar cases. The changes are well-contained and demonstrate careful consideration of the tradeoffs between warning utility and code maintainability.
