Junio Hamano responds to Karthik Nayak's bugfix for `git blame` porcelain output regarding ignored/unblamable lines. While agreeing there's a documentation/implementation mismatch, he raises concerns about the proposed solution's backward compatibility. The current patch would prefix markers to the commit hash line, which Hamano argues would break existing parsers that expect a strict 40-character SHA-1 format. He suggests the porcelain format should instead find a less disruptive way to convey this information, perhaps using the info lines that already exist in the format. This appears to be a design discussion about how to properly extend the porcelain output format without breaking existing consumers. The core issue remains valid, but the implementation approach needs reconsideration to maintain backward compatibility.
