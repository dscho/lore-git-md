[GSoC 2025 proposal] Consolidate ref-related functionality into git-refs - technical refinement phase. Zheng Yuting's updated proposal implements 8 new subcommands (`list`, `exists`, `show`, `resolve`, `optimize`, `update`, `delete`, `check-format`) to unify reference management while maintaining backward compatibility through existing commands and test suites. The implementation strategy focuses on `refs.c` for backend-agnostic access, initially prioritizing `list` and `update` subcommands as foundational elements.

Patrick Steinhardt's technical review shaped key refinements: accepted `optimize` naming over `pack` for packing functionality, confirmed `resolve` should dereference to objects (`rev-parse --verify` semantics), and emphasized working through `refs.c` without backend modifications. Zheng maintains separate `delete` command despite Patrick's preference for unified `update` functionality. Error corrections include proper placement of `--exclude-existing` option in `list` and removal of premature implementation details.

Technical constraints remain: no command modifications, backward-compatible tests, no subprocesses, with added `--max-depth` for `resolve`. The discussion connects to Patrick's ref backend abstraction vision and GitLab issue #330, with next steps focusing on proposal revision before implementation.
