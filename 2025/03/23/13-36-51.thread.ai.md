[GSoC 2025 proposal] Consolidate ref-related functionality into git-refs - technical refinement phase. Zheng Yuting's updated proposal specifies implementation of 8 new subcommands (`list`, `exists`, `show`, `resolve`, `pack`, `update`, `delete`, `check-format`) to replace scattered reference management commands while maintaining backward compatibility through unmodified commands and preserved test suites. The implementation strategy focuses on code reuse from `refs/files-backend.c` with strict parameter compatibility, initially targeting `git-refs pack` as a migration demonstration.

Patrick Steinhardt's technical review provides critical feedback on subcommand design: questioning the need for separate `delete` when `update` handles deletions, suggesting `optimize` as clearer than `pack` for packing functionality, and clarifying that `resolve` should dereference to objects (like `rev-parse --verify` rather than `symbolic-ref`). He emphasizes working through `refs.c` without backend modifications and sees this as a chance to improve legacy design warts rather than strictly preserving all semantics. The review advises focusing on quality implementations of a subset of subcommands rather than rushing to complete all proposed functionality, while maintaining the project's core goals of consolidation and compatibility.

Key technical constraints remain unchanged (no command modifications, backward-compatible tests, no subprocesses) with the addition of recursion depth control via `--max-depth` in `resolve`. Implementation questions center on test suite strategy (parallel vs. integrated) and interface specifications, with Patrick's feedback now guiding naming conventions and semantic refinements. The proposal connects to Patrick's ref backend abstraction vision and GitLab issue #330, with next steps focused on incorporating this technical feedback before coding begins. Zheng Yuting's background in networking/web development and prior Git contribution (send-email optimization) remains relevant as the project transitions from specification to implementation planning.
