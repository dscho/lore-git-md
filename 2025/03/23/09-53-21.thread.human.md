This thread discusses a refactoring of commit mark clearing functions in commit.c, originally proposed by René Scharfe. The patch reorganizes the relationship between `clear_commit_marks_many()` and `clear_commit_marks()`, moving the single-commit handling logic into `clear_commit_marks()` and making `clear_commit_marks_many()` simply iterate over commits. This consolidation removes duplicate code while maintaining identical behavior.

Junio C Hamano, the Git maintainer, has reviewed the change and endorsed the simplification. He speculates that the original code organization might have anticipated batch processing optimizations that never materialized, and agrees the new version makes the control flow clearer. The change remains purely internal - it improves code organization without affecting functionality or performance. With the maintainer's approval, this refactoring appears likely to be accepted, though no other reviewers have commented yet. The patch continues Git's ongoing effort to improve maintainability of core commit graph functionality through clean, focused refactorings.
