This is a refactoring patch that simplifies the commit marking logic in Git's core code. René Scharfe restructures how commit marks are cleared by moving the single-commit handling code from `clear_commit_marks_many()` into `clear_commit_marks()` and then calling the simpler function from the more complex one, rather than the previous reverse arrangement.

The change flips the relationship between these two functions - where previously `clear_commit_marks()` was just a thin wrapper around `clear_commit_marks_many()`, now the many-commit version becomes the single-commit version's caller. This makes the code more straightforward by eliminating redundant list handling in the loop and centralizing the mark-clearing logic in one place.

The patch is small (16 lines changed) and focused, touching only commit.c. It maintains all existing functionality while making the control flow more intuitive - a textbook example of good refactoring.
