Security hardening patch for git-shell command override functionality.

This v3 patch from Ayman Bagabas finalizes the implementation to allow overriding git-shell built-in commands via scripts in the git-shell-commands directory. The key change from v2 is replacing the `F_OK` (file existence) check with `X_OK` (executable permission) check, implementing the security consensus reached in the discussion.

The patch maintains the core functionality where users can place executable scripts matching built-in command names (like `git-receive-pack`) in git-shell-commands to intercept and potentially modify behavior. The security model remains constrained to git-shell's existing trust boundaries, with the executable permission check serving as the primary safeguard.

The implementation appears clean and focused, addressing all previously raised concerns about the security model. The change is minimal (just 9 lines modified) and maintains consistency with git-shell's existing patterns. With the security review complete and no outstanding technical objections, this looks ready for maintainer consideration.
