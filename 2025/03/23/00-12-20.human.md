Security feature for git-shell command overrides

This is version 2 of Ayman Bagabas's proposal to allow overriding git-shell's built-in commands via scripts in the git-shell-commands directory. The patch has evolved from its RFC state with clarified commit message wording and removal of some CC'd maintainers.

The core functionality remains: administrators can now place scripts in git-shell-commands that intercept and potentially modify behavior of built-in commands like `git-receive-pack`. The example use case shows this could enable user access control by wrapping commands with permission checks.

The thread has narrowed to focus on security implications specific to git-shell, having moved past broader architectural concerns. The key question now is whether intercepting built-ins (versus just adding new commands) introduces new attack vectors. The patch's security model argues this is no riskier than git-shell-commands' existing ability to run arbitrary scripts.

Implementation-wise, the changes are minimal - just 9 lines modifying shell.c to check for override scripts before executing built-ins. The diff shows careful handling of command dispatch and argument passing. The patch appears technically sound for its stated purpose, though the security debate may continue.
