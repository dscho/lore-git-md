Security-focused technical review of git-shell command patch.

Chris Torek provides a focused code review of Ayman Bagabas's v2 patch proposing built-in command overrides in git-shell. The email doesn't engage with the broader security discussion happening in the thread, instead zeroing in on a specific implementation detail in shell.c where the patch checks for command existence.

The key observation is that the current patch uses `F_OK` (file exists) when it should likely use `X_OK` (executable permission) in the `access()` check for override commands. This is a security-sensitive detail since the check determines whether a script can override a built-in git-shell command. Using `X_OK` would properly verify execute permissions rather than just file existence.

This suggestion aligns with the thread's ongoing security focus but comes from a different angle - not about the architectural security implications being debated, but about hardening the implementation itself. The change would make the behavior more consistent with Unix security practices where executable checks should verify both existence and execute permissions.
