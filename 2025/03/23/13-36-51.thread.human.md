This thread documents the evolution of Zheng Yuting's GSoC 2025 proposal to consolidate Git's reference-related commands into a unified `git-refs` tool, mentored by Patrick Steinhardt with technical review from Karthik Nayak. The proposal has matured through detailed discussion, with key architectural decisions now in place: a unified approach combining filtering, sorting and formatting in `git-refs list`, using `git-show-ref`'s lightweight format by default for performance, and proceeding with direct implementation rather than a phased migration.

The latest version (v2) adds concrete implementation plans, breaking the work into three subcommands with clear timelines: `show` (replacing `git-show-ref --verify`) will come first in May/June, followed by the more complex `list` (merging `git-show-ref` and `git-for-each-ref` functionality) in June/July, and finally `update` (replacing `git-update-ref`) in July/August. Testing will verify output consistency with the legacy commands while adding new coverage for integrated functionality, and documentation will explicitly map new options to their predecessors.

Open questions remain about handling some legacy format options (`--tcl`, `--shell`, `--perl`) and finalizing UX details, but the core architecture is settled. Zheng has incorporated feedback about performance testing methodology and option categorization from prior reviews, showing the proposal transitioning from design discussion to implementation planning. With Patrick's endorsement and Karthik's technical guidance shaping the concrete next steps, this appears to be on track as a well-scoped GSoC project that could meaningfully simplify Git's ref-related tooling.
