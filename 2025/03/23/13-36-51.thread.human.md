The core architecture has solidified around a unified approach that combines filtering, sorting, and formatting capabilities in `git-refs list`, with three key decisions now confirmed: using `git-show-ref`'s lightweight output format by default (avoiding object database access), implementing integrated filtering/formatting rather than separate options, and proceeding with direct implementation rather than a phased migration.

Implementation will start with the simpler `git-refs show` (replacing `git-show-ref --verify`) before tackling the more complex `list` functionality. Zheng has addressed review feedback by committing to clear option categorization, rigorous performance testing of each new feature against benchmarks, and an incremental development approach. While concerns remain about potential performance impacts from option iteration overhead, this is accepted as a tradeoff for the unified model's benefits.

Open questions still under discussion include how to handle legacy format options (`--tcl`, `--shell`, `--perl`), the detailed user experience of option structures, and specific performance testing methodologies.
