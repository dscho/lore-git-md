Performance optimization in refs subsystem (patch 8/16) eliminating redundant prefix checks during reference verification.

This patch from Patrick Steinhardt continues the refs optimization series by addressing a specific inefficiency in `refs_verify_refnames_available()`. The function was needlessly re-verifying common reference prefixes (like "refs/heads/") multiple times when processing batches of references. The solution introduces a `strset` to track already-checked prefixes, yielding significant speedups particularly for the reftable backend (1.58x faster when creating many refs) and more modest gains for the files backend (1.03x). The change also improves reference migration between backends by about 10%.

The implementation is straightforward - it adds a `strset` to cache checked prefixes and skips re-checking them. The patch includes comprehensive benchmarks showing the improvements across different scenarios. This appears to be a well-justified optimization that builds cleanly on the series' earlier infrastructure changes.
