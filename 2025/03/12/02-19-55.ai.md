Security hardening for remote-object-info format string validation.

This is a follow-up discussion about a security vulnerability in the remote-object-info functionality, specifically around format string validation. Jeff King (Peff) identified that the current implementation using `strstr()` for format validation is insufficient, as it doesn't properly reject format strings containing unsupported placeholders. The vulnerability could lead to segfaults when users provide format strings with placeholders like `%(objecttype)` that aren't actually supported by the remote-object-info command.

Peijian Ju acknowledges the issue and outlines the planned fixes for v12:
1. Implementing proper format string validation that iterates through the format to detect any unsupported placeholders
2. Expanding test coverage to verify handling of various format string cases, including:
   - Valid single placeholder (`%(objectsize)`)
   - Valid single placeholder (`%(objectname)`)
   - Mixed valid and invalid placeholders
   - Edge cases around format string parsing

This exchange represents the final security hardening for the remote-object-info feature, addressing the last identified vulnerability before the series was merged. The fix ensures proper input validation for all format strings passed to the remote object query functionality, preventing potential crashes from malformed input. This was the last outstanding issue in the 12-iteration development of this feature.
