Bugfix addressing NULL pointer dereference in promisor-remote URL handling, now incorporating standard remote behavior patterns. This v3 patch from Christian Couder builds on previous iterations by changing the fallback behavior when no URL is configured - instead of pushing NULL (which caused crashes) or empty strings (v2 approach), it now follows the convention seen in `git fetch` and `git remote get-url` by using the remote name as a fallback URL.

The patch makes several related improvements:
1. Replaces `git_config_get_string()` with `git_config_get_string_tmp()` for safer memory management
2. Adds comprehensive warnings for various URL-related edge cases in 'KnownUrl' mode (missing URLs, empty URLs, name/URL mismatches)
3. Includes new test cases covering missing and empty URL scenarios
4. Standardizes "URL" capitalization in warning messages

Key technical details for future reference:
- Modified files: `promisor-remote.c` and `t/t5710-promisor-remote-capability.sh`
- Behavior change: NULL URLs now fall back to remote name rather than empty string
- New warnings cover:
  - Missing server-advertised URLs
  - Empty server-advertised URLs
  - Empty client-configured URLs
  - Name/URL equality cases (potential misconfigurations)
- Test coverage expanded to verify:
  - 'KnownName' with missing client URL
  - 'KnownUrl' with unset server URL
  - 'KnownUrl' with empty server URL

The patch maintains the thread's separation between immediate safety fixes (NULL dereference) and longer-term API design questions, while now aligning more closely with Git's standard remote handling conventions. The implementation appears thorough, with clear commit message explanations and comprehensive test coverage for the new edge cases.
