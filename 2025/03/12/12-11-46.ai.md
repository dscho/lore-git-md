This is a bugfix series for the reftable subsystem, part of Meet Soni's GSoC project, addressing error handling improvements in block writing operations. The v3 iteration splits the changes from v2 into two distinct patches following Patrick Steinhardt's review feedback.

The first patch standardizes error code propagation in `block_writer_add()` and related functions, replacing generic -1 returns with specific error codes. This allows callers to distinguish between different failure modes rather than assuming all errors indicate a full block. The changes affect core reftable files (block.c, record.c) with careful attention to documentation formatting and error semantics.

The second patch modifies writer.c to properly handle these distinct error conditions. Rather than always treating failures as block-full conditions requiring retry, it now propagates specific errors directly while only retrying for REFTABLE_ENTRY_TOO_BIG_ERROR cases. This addresses the key review concern about incorrect error assumptions in the writer logic.

The series shows good responsiveness to prior feedback, with clear commit message explanations and careful attention to Git's code style conventions. The split into two patches makes the logical separation between error code plumbing and caller adaptation more visible. The changes maintain backward compatibility while improving debuggability through precise error reporting - a solid step forward in the reftable error handling improvements.
