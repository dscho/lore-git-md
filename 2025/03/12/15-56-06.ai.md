Performance optimization for refname availability checks across ref backends (v6 series).

This is the sixth iteration of Patrick Steinhardt's series optimizing refname availability checks during operations like ref updates, particularly addressing performance bottlenecks in the reftable and files backends. The series builds on previous work and now includes all requested documentation fixes and implementation confirmations, with final approval from Karthik Nayak.

The key optimizations in this version remain:
1. Skipping redundant ambiguity checks in `git-update-ref` via new `GET_OID_SKIP_AMBIGUITY_CHECK` flag
2. Batching refname checks using a `strset` to avoid re-checking common prefixes
3. Implementing iterator reuse across all ref backends to avoid recreation costs

Notable changes in v6:
- Switched to `for_each_string_list()` for cleaner iteration
- Removed unnecessary refname sorting in `refs_verify_refnames_available()`
- Restored important documentation about termination behavior in prefix iterators
- Confirmed prefix optimization works as intended for both backends

Performance impact remains substantial:
- Files backend: 1.19-1.27x speedup in edge cases, 1.23x in realistic scenarios
- Reftable backend: 2.32-7.56x speedup in edge cases, 4.78x in realistic scenarios

The series touches core refs infrastructure across multiple backends (files, packed, reftable) and introduces new iterator capabilities while maintaining backward compatibility. All technical concerns from previous reviews have been addressed, making this ready for inclusion. The changes are well-documented and tested, with clear performance benefits for both synthetic and realistic workloads.
