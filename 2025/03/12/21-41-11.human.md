This is a follow-up discussion in the ongoing feature series adding NUL-delimited output support to `git rev-list`. The exchange focuses on implementation details of the `-z` option's compatibility checks.

Justin Tobler responds to Patrick Steinhardt's suggestion about adding a clarifying comment to the code that enforces which options can be used with `-z`. The current implementation rejects combinations with several other rev-list options (like graph output, verbose headers, and bitmap indexes), but Patrick notes this is an implementation choice rather than a fundamental limitation.

Justin agrees to add a comment indicating these restrictions could be lifted in future work, keeping the door open for extending NUL-delimited support to more rev-list modes. This is a minor refinement to the already well-developed v2 implementation, showing the series is in its final polishing stages with attention to both code clarity and future extensibility.
