This is a bug report concerning an overflow issue in Git's diff output when using extremely large context values with `--unified`. The reporter, Jason Cho, demonstrates that when running `git diff --unified=2147483647` on Windows with Git 2.47, the output incorrectly repeats the context of the second hunk, while GNU diff handles the same large value correctly. 

The issue appears to stem from an integer overflow in `xdiff/xemit.c` where the context length calculation (`2 * ctxlen + interhunkctxlen`) could exceed valid bounds when given extremely large input values. The reporter has identified the specific line where this calculation occurs but notes that Git's documentation doesn't specify any limits for the `--unified` parameter.

This is clearly a bugfix candidate for the diff machinery, though the practical impact is limited since such extreme context values are rarely used. The report is well-documented with clear reproduction steps and version information, including comparisons with GNU diff's behavior. The reporter requests either clarification on the supported range for `--unified` or a fix to properly handle large values.

Key technical details for future reference: the issue manifests in `xdiff/xemit.c`'s `xdl_get_hunk()` function, involves integer overflow with context length parameters, and produces incorrect output when `--unified` approaches INT_MAX (2147483647). The behavior differs from GNU diffutils 3.10 which handles the same input correctly.
