Performance optimization for reftable backend (patch 12/16 in series). This patch implements seeking capability for reftable reference iterators, building on the iterator reseek functionality introduced in earlier patches. The change is straightforward since the low-level reftable iterators already support seeking.

Key aspects:
- Adds `reftable_ref_iterator_seek()` to handle seeking operations
- Properly manages memory for prefix strings during seeks
- Explicitly checks for initialization success of reftable stack iterators
- Intentionally omits seeking support for reflog iterators (no current use case)
- Maintains consistency with the series' iterator API changes

The patch continues the series' pattern of incremental improvements to ref iteration performance, with this change specifically enabling more efficient seeking operations in the reftable backend. The implementation looks clean and focused, with clear handling of edge cases and proper memory management.
