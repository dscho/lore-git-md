This is a bug report about an overflow issue in Git's diff output when using extremely large context values.

Jason Cho reports that when running `git diff --unified=2147483647` (the maximum 32-bit signed integer value), Git incorrectly repeats the second hunk's context in the output, while GNU diff handles the same input correctly. The issue appears to stem from an integer overflow in `xdiff/xemit.c` where the context length is calculated as `2 * ctxlen + interhunkctxlen`.

The report is well-documented, showing:
1. Reproducible test case with two simple text files
2. Comparison between Git's incorrect output and GNU diff's correct output
3. Identification of the likely problematic code location
4. Reference to documentation that doesn't specify limits for the `--unified` parameter

While this edge case (using the maximum possible context lines) is unlikely to affect normal usage, the report makes a valid point about either needing to document the limit or fix the overflow. The issue appears to be platform-independent, though discovered on Windows. This seems like a legitimate bug worth addressing, though probably low priority given the extreme parameter value required to trigger it.
