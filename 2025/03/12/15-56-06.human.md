Performance optimization for refname availability checks in refs subsystem (v6 series)

This is the sixth version of Patrick Steinhardt's series optimizing refname availability checks across Git's ref backends. The work originated from performance issues with reftable tombstones but has expanded to address broader inefficiencies in how Git verifies refnames during operations like `git update-ref`.

The series implements three key optimizations:
1. Skips unnecessary ambiguity checks in `git update-ref` since it's plumbing that expects object IDs
2. Uses a `strset` to cache and avoid re-checking common refname prefixes
3. Reuses ref iterators rather than recreating them for nested ref checks

Benchmarks show significant improvements - up to 7.56x faster for reftable in edge cases and 4.78x faster in more common scenarios with many preexisting refs. The files backend also sees modest gains of 1.23-1.27x.

Version 6 includes minor refinements:
- Uses `for_each_string_list()` instead of manual iteration
- Stops sorting refs before verification
- Restores a previously deleted comment about iterator termination
- Maintains all prior optimizations and fixes

The series has received thorough review, with Karthik Nayak giving final approval in v5 after all technical concerns were addressed. This v6 appears ready for inclusion, building on the foundational API changes from earlier patches to deliver measurable performance wins while maintaining correctness.
