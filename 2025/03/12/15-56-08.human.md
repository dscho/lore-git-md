This is the second patch in a 16-part performance optimization series for the refs subsystem, focusing on refname availability checks. The patch introduces a new flag `GET_OID_SKIP_AMBIGUITY_CHECK` that allows skipping the expensive ambiguity check in `get_oid()` functions when a reference name matches an object ID.

The change is straightforward - it lays groundwork for later optimizations in the series by adding a flag to bypass the ambiguity check that normally verifies whether a given string could refer to both an object ID and a refname. The patch modifies both the flag definitions in `hash.h` and the check logic in `object-name.c`.

This is a foundational change that enables subsequent performance improvements, particularly for operations like ref updates where these checks can be safely skipped. The commit message notes this will be used in a follow-up commit, positioning it as part of the larger optimization effort rather than a standalone change. The implementation appears clean and focused, with minimal changes needed to achieve the desired functionality.
