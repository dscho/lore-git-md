Performance optimization for refs/files backend in initial transactions. This is patch 7/16 in a series addressing refname availability checks across Git's ref storage backends.

The patch, Patrick Steinhardt modifies the files-backend.c to batch refname availability checks during initial transactions (like those occurring during clone or format migration). Rather than checking each refname individually via `refs_verify_refname_available()`, it now collects all refnames into a string list first and verifies them together. 

The change doesn't yet show performance benefits - that comes in subsequent patches that will optimize the batched verification itself. But it lays important groundwork by restructuring the transaction flow to first collect all refnames, then lock packed refs, then perform verification, before finally committing. The patch maintains all existing behavior and error handling, just reorganizing when checks occur.

This is part of a larger effort to optimize ref operations, particularly benefiting cases with many references. The series has already received thorough review and this patch follows the established pattern seen in earlier parts of the series.
