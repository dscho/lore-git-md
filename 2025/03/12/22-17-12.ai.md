This is a follow-up discussion in the documentation standardization thread about boolean value syntax in Git. Taylor Blau, the original author of some of the documentation being modified, responds to Junio Hamano's patch that centralizes boolean syntax documentation in git-config.txt.

Taylor confirms the general approach of listing all valid boolean variants but questions the wording about canonicalization behavior. He provides a test case showing that while "yes" is accepted as equivalent to "true", the output still shows "true" rather than preserving the original "yes" spelling. This suggests the documentation should clarify that while multiple spellings are accepted, the output will always be normalized to "true"/"false".

The exchange highlights an important technical nuance in how Git actually handles boolean values versus how the documentation describes it. Taylor's response comes from both historical context (as the author of the original pretty-formats.txt boolean documentation) and practical verification of current behavior. This is likely to lead to a documentation refinement in the next version of the patch to more precisely describe the normalization behavior.

Key technical details for future reference:
- The discussion centers on git-config's `--type=bool` behavior
- Current implementation normalizes all true variants to "true" (not preserving input spelling)
- Original patch proposed wording about "canonicalize" may need adjustment
- Test case provided: `git -c foo.bar=yes config --type=bool foo.bar` outputs "true"
