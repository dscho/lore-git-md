This thread addresses a bug in Git's diff output when using extremely large context values with `--unified`. Jason Cho originally reported that `git diff --unified=2147483647` on Windows with Git 2.47 incorrectly repeated context from the second hunk, differing from GNU diff's correct behavior. The issue stems from an integer overflow in `xdiff/xemit.c`'s `xdl_get_hunk()` function, specifically affecting Windows where `long` and `int` have the same size.

René Scharfe provided a fix introducing a `saturating_add()` helper that caps sums at LONG_MAX, preventing overflow while maintaining the ability to show a single hunk for the entire file. The solution modifies the hunk boundary calculation to use safe addition and includes a new test case in `t4055-diff-context.sh` to verify correct behavior with extreme context values.

Junio C Hamano has now reviewed and approved the patch, praising its careful bounds-checking approach. He confirmed the implementation looks correct and will queue it for inclusion. The fix maintains compatibility with GNU diffutils' behavior while properly handling the overflow case on Windows, resolving the issue without introducing artificial limits.
