This thread addressed a Windows-specific integer overflow in Git's diff output when using extremely large context values with `--unified`. Jason Cho originally reported that `git diff --unified=2147483647` incorrectly repeated context from the second hunk on Windows, where `long` and `int` have the same size. René Scharfe provided an elegant fix using saturating addition to prevent overflow while maintaining GNU diffutils compatibility, which Junio Hamano reviewed and approved. The solution avoids more invasive changes like switching to `size_t`, especially since René's follow-up research showed the upstream xdiff library has been stable since 2008 with no active development. A new test case verifies the fix handles the extreme context value correctly. The thread has reached clear resolution, with the maintainer satisfied by the minimal, platform-aware approach and the original reporter confirming the fix works. No outstanding issues remain - the solution preserves expected behavior for normal usage while safely handling edge cases.
