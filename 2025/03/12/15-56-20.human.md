Performance optimization for packed-refs iterator. This is patch 14/16 in Patrick Steinhardt's series optimizing refname availability checks across Git's ref backends. Following the ref-cache iterator changes in patch 13/16, this implements seek capability for packed-ref iterators, completing the seek functionality across core ref storage backends.

The change modifies the packed-ref iterator to support seeking by prefix, similar to the reftable iterator changes in patch 12/16. The implementation had to open-code the prefix matching in `advance()` rather than using the prefix iterator helper, since the latter would prevent reseeking (a capability added in patch 10/16). The patch adds a `prefix` field to track the current search scope and implements the new `seek` vtable function.

This continues the series' pattern of adding consistent seek/reseek capabilities across all ref backends, enabling future optimizations that can take advantage of targeted iteration. The changes maintain compatibility with prior performance improvements while handling edge cases like empty prefixes correctly. With this patch, the iterator seek implementation now covers both reftable and files backends with matching behavior.
