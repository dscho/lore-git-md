This is a follow-up discussion in the documentation standardization thread about boolean value syntax in Git. Taylor Blau, the original author of some of the documentation being modified, responds to Junio Hamano's patch that aims to centralize boolean syntax documentation in git-config.txt.

Taylor agrees with most of the changes but questions one specific claim about canonicalization behavior. He provides a test case showing that while Git accepts "yes"/"no" as boolean values (converting them to "true"/"false" internally), the documentation might be slightly misleading about the exact canonicalization process. His example demonstrates that `git config --type=bool` does convert "yes" to "true" in practice, contrary to his initial suspicion.

The exchange is collegial, with Taylor noting this was one of his first contributions to Git (from 2018) and apologizing for the delayed response. The core documentation improvement remains uncontested - this is just a minor clarification about the wording around canonicalization behavior. Given the thread's history and Junio's maintainer role, this will likely be resolved with a small documentation tweak in the next version.
