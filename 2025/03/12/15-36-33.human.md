Performance optimization series for refs subsystem (v5, patch 4/16). This is a foundational patch in a larger series addressing refname availability checks, introducing batched verification of refnames for efficiency gains.

The patch adds `refs_verify_refnames_available()` as a batch counterpart to the existing single-refname verification function. While the implementation shows the batch processing via a raw for-loop, shejialuo suggests using `for_each_string_list_item` for better readability, which Patrick Steinhardt agrees to change.

There's brief discussion about whether the function's documentation should explain why batch processing is more efficient. Patrick argues this is an internal optimization detail that callers don't need to understand, maintaining the focus on functional equivalence with the single-refname version.

This patch serves as preparatory refactoring enabling later optimizations in the series, particularly the iterator reuse improvements that ultimately deliver the performance gains (1.19-1.27x speedup for files backend, 2.32-7.56x for reftable). The series has received final approval from Karthik Nayak, with shejialuo providing ongoing documentation-focused review.
