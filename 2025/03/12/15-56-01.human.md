Junio Hamano weighs in on the ongoing discussion about NUL-delimited output in `git rev-list`. This is part of the v2 design phase for a feature that will make machine parsing of rev-list output more reliable by using NUL delimiters instead of newlines.

The specific point being addressed here is whether the `-z` option should affect both input and output formats (as it does in most other Git commands) or just the output. Patrick Steinhardt had previously advocated for making `-z` affect both, citing consistency with other commands and past regrets when this wasn't done (like in `git cat-file`).

Junio agrees with this approach, noting that while some commands use `-Z` to differentiate between input and output formats, making `-z` affect both sides is the more intuitive choice if they're not going to use separate flags. This comment helps solidify the design direction for this aspect of the feature, moving the discussion toward implementation.

The thread has largely reached consensus on the major design points, with this being one of the final details being worked out before the feature can be finalized. The exchange demonstrates the careful consideration being given to interface design and consistency with existing Git conventions.
