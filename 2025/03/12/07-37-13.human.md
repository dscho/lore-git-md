Feature proposal discussion about NUL-delimited output format in `git rev-list`.

Patrick Steinhardt weighs in on the ongoing discussion about attribute naming in the proposed NUL`-delimited output format for `git rev-list`. The thread has previously settled on a key-value format with single NUL delimiters, but there's debate about whether to use abbreviated attribute names (like "m=yes" for missing objects) or full names ("missing=yes").

Steinhardt argues for keeping the longer, more descriptive names for three reasons: better readability for developers working with the code, avoidance of potential naming conflicts if multiple attributes start with the same letter, and minimal performance impact since the extra characters won't significantly affect processing time compared to object decompression.

This is part of a larger effort to make `rev-list` output more reliably machine-parseable, particularly for paths containing special characters. The discussion has progressed through multiple refinements and now focuses on finalizing the output format details before the v2 implementation. The patch appears well-considered, with Steinhardt providing clear technical rationale for his preference in this specific aspect of the design.
