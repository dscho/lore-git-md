Performance optimization series for refs subsystem (patch 14/16) implementing seek capability for packed-ref iterators. This continues Patrick Steinhardt's work to optimize refname availability checks across Git's ref backends, following the reftable iterator seek implementation in patch 12/16 and ref-cache iterator in patch 13/16.

The patch modifies the packed-ref iterator to support seeking by:
1. Adding a `prefix` field to `struct packed_ref_iterator` to track the current seek position
2. Implementing `packed_ref_iterator_seek()` using `find_reference_location()`
3. Removing the prefix iterator wrapper in favor of direct prefix handling in `advance()`
4. Converting the iterator initialization to use the new seek method
5. Adding proper cleanup of the prefix string in `release()`

Key technical changes include:
- 65 lines modified in `refs/packed-backend.c` (43 insertions, 22 deletions)
- New `seek` vtable method implementation matching the API introduced in patch 10/16
- Removal of `empty_ref_iterator_begin()` optimization to maintain seek capability
- Direct prefix comparison in `advance()` replacing the prefix iterator wrapper
- Memory management for the owned `prefix` string

The implementation follows the same pattern as previous iterator seek implementations in this series, maintaining consistency across backends while addressing packed-refs' specific needs. This completes the seek capability implementation for all major ref backends (files, reftable, and now packed), enabling the performance optimizations planned in later patches of the series. The changes appear well-contained and build logically on the established iterator API changes from earlier in the series.
