This is a feature inquiry about Git bundle reproducibility. Simon Josefsson reports that creating Git bundles of the same repository content results in different checksums, even when the source repository hasn't changed. He's specifically working with Gnulib bundles and finds that the current `git-bundle` behavior makes it impossible to verify bundle integrity through checksum comparison.

The email describes a concrete problem where bundle checksums vary between creation attempts, which impacts users who need verifiable source distributions. Simon asks three key things: (1) whether there's an existing way to create bit-identical bundles, (2) what causes the current irreproducibility, and (3) whether changes to Git could address this.

The issue appears genuine and well-motivated, touching on software supply chain integrity - a growing concern in open source distribution. The email is clear and provides enough context (including Git version and a real-world use case) for others to investigate. This seems like a reasonable feature request that might interest maintainers working on bundle internals or deterministic build tooling.
