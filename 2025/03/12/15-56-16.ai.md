Performance optimization series for refs subsystem (patch 10/16) introducing iterator reseek capability.

This patch adds infrastructure to allow ref iterators to be reseeked to new prefixes without requiring full reinitialization, enabling potential performance optimizations by reusing internal iterator state. The change introduces a new `.seek` vtable function that backends can implement to support this capability, with initial implementations provided for the debug and prefix iterators.

Key technical changes:
- New `ref_iterator_seek()` API that takes a new prefix and resets iteration
- Vtable extension with `seek_fn` callback
- Implementations for:
  - Empty iterator (no-op)
  - Debug iterator (proxies to underlying iterator)
  - Prefix iterator (updates prefix and reseeks underlying iterator)
- Documentation of behavior expectations in `refs-internal.h`

The change maintains all prior optimizations from the series while enabling future backend-specific optimizations, particularly for reftable where internal iterator reuse is already possible but wasn't exposed. The implementation currently only allows changing the seek prefix while keeping other iterator parameters (flags, trim patterns) constant, though the design leaves room to expand this later if needed.

This builds directly on patch 9/16's iterator lifecycle changes and is part of the core optimization phase of the foundational API work done in earlier patches. The change affects 3 files with 59 net new lines, primarily adding the new capability while maintaining existing behavior for non-reseek cases.
