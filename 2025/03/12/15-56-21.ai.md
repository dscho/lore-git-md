Performance optimization series for refs subsystem (v6 patch 15/16), implementing files backend iterator seek capability. This patch completes the seek implementation across all three ref backends (files, reftable, and packed) in the performance optimization series. It adds seek support to the files backend by leveraging the existing ref-cache iterator implementation (from patch 13/16), while explicitly marking reflog iterator seeking as unsupported (via BUG() call) to maintain consistency with other backends.

The changes are minimal (16 lines added) and focused, implementing the seek operation by forwarding to the underlying ref-cache iterator. The patch follows the same pattern seen in previous backend implementations (reftable in 12/16, packed in 14/16), completing the series' goal of uniform seek capability across all ref storage backends. Key technical points include:
- New `files_ref_iterator_seek()` function that delegates to `ref_iterator_seek()`
- Explicit `files_reflog_iterator_seek()` that triggers BUG() if called
- Updates to both iterator vtables to include seek operations
- Maintains the series' pattern of not implementing reflog seeking (consistent with reftable backend)

This patch builds directly on the ref-cache iterator seek capability from patch 13/16 and follows the same API patterns established in earlier patches (10/16's reseek API and 9/16's iterator lifecycle management). With this change, all three major ref backends now support the same seek optimization pattern, enabling the performance improvements for ref operations that the series aims to deliver. The implementation is straightforward given the prior work in the series, with no new technical challenges or open questions introduced.
