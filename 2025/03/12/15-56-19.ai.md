Performance optimization series for refs subsystem (v6, 13/16) - ref-cache iterator seek implementation.

This patch implements seek functionality for ref-cache iterators, continuing the performance optimization series for ref operations. The change splits most of the seeking logic out of `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function for reuse. Key technical changes include:

- Adds `seek` method to ref-cache iterator vtable
- Converts `prefix` from `const char*` to owned `char*` to support reseeking
- Removes empty iterator optimization to allow reseeking to different prefixes
- Adds early bailout in `advance()` when no more directories remain
- Introduces new `cache` and `prime_dir` fields to iterator struct
- Modifies initialization flow to use the new seek function

The implementation maintains compatibility with the series' earlier changes while enabling more flexible iteration patterns. The removal of the empty iterator optimization is noted as a minor performance tradeoff that shouldn't significantly impact real-world usage. This builds directly on the iterator infrastructure established in previous patches (particularly 11/16's merged iterator seek) and follows the same pattern of separating concerns to enable future optimizations.

The patch touches 79 lines in `refs/ref-cache.c`, with 51 additions and 28 deletions. It continues the series' focus on making ref operations more efficient across different backends, though this particular change is files-backend specific (the reftable equivalent was handled in patch 12/16).
