Performance optimization patch extending batched refname availability checks to initial transactions in the files backend, part of a larger series addressing ref operations performance.

This patch modifies `files_transaction_finish_initial()` in `files-backend.c` to collect refnames into a string list (`refnames_to_check`) during transaction preparation rather than verifying them individually. The actual verification is then performed in a single batch via `refs_verify_refnames_available()`. While this doesn't yet improve performance (that comes in later patches), it lays the groundwork for optimizing operations like cloning or format migration where many refs are created simultaneously.

The changes maintain all existing behavior including packed-refs locking semantics and error handling, just restructuring the verification flow. Key technical points:
- Adds new `refnames_to_check` string list parameter
- Moves verification after packed-refs locking but before transaction commit
- Preserves all error conditions (name conflicts via TRANSACTION_NAME_CONFLICT, other errors via TRANSACTION_GENERIC_ERROR)
- Properly cleans up resources with `string_list_clear()`

This is patch 7/16 in the performance optimization effort, following the reftable backend batching in patch 5/16 and files backend core changes in patch 6/16. The series has received final approval from Karthik Nayak with all documentation feedback resolved. Performance gains (1.19-1.27x for files backend, 2.32-7.56x for reftable) will materialize once the full batching infrastructure is in place.
