This is the second patch in a 16-part performance optimization series for the refs subsystem, introducing a foundational API change to enable subsequent optimizations.

The patch adds a new `GET_OID_SKIP_AMBIGUITY_CHECK` flag to the `get_oid()` family of functions, allowing callers to bypass expensive ambiguity checks when they know such checks are unnecessary. The ambiguity check normally verifies whether a given object ID string could also refer to a refname, which adds overhead even when the caller knows the input is definitely an object ID. The implementation modifies `get_oid_basic()` in object-name.c to respect this new bit in the flags parameter, while maintaining all existing behavior when the flag isn't set.

Key technical details include:
- New flag value `040000` added to hash.h's flag definitions
- Modified check in object-name.c that now respects the new flag
- No behavior change by default - existing callers continue working as before
- Part of preparing for patch 3/16 which will use this to optimize `git-update-ref`

The change is cleanly implemented with minimal diff impact (15 lines changed total) and serves as infrastructure for the series' later performance improvements. As noted in the thread context, this foundational change enables measurable speedups in subsequent patches (1.19x for files backend, 2.32x for reftable). The patch has already been reviewed and approved as part of the complete v6 series.
