This is a small bugfix patch in the merge-ort series, addressing verbosity control for merge operations. The change allows callers like `git am` and `git checkout` to completely suppress conflict messages by setting verbosity to 0, matching behavior that was previously only possible by bypassing the wrapper functions.

The patch itself is minimal - just a two-line addition to `merge-ort.c` that adds an early return when verbosity is 0. Taylor Blau confirms the technical correctness but raises a good point about adding regression tests, which would help ensure this behavior isn't accidentally broken in future changes.

This is part of the larger effort to establish merge-ort as a complete replacement for merge-recursive, with particular attention to maintaining compatibility with existing caller expectations. The thread context shows this is one of several small but important details being worked out in the transition.
