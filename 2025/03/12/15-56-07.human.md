This is the foundational patch in a performance optimization series for the refs subsystem. It introduces a new function `repo_get_oid_with_flags()` that extends the existing `repo_get_oid()` by adding a flags parameter to pass through to the lower-level `get_oid_with_context()`. The change is straightforward - it enables future patches in the series to control ambiguity checking behavior during refname lookups.

The patch is part of a larger effort to optimize refname availability checks, particularly around tombstone references in the reftable backend. While this first patch doesn't yet implement any optimizations itself, it provides the necessary API groundwork that subsequent patches will build upon to achieve significant performance improvements (1.19-1.27x speedup for files backend, 2.32-7.56x for reftable).

The change is cleanly implemented with minimal churn - just adding the new function while keeping the existing `repo_get_oid()` as a wrapper for backward compatibility. The series has already gone through multiple rounds of review and this v6 version has received final approval from Karthik Nayak, indicating it's ready for inclusion.
