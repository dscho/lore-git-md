Performance optimization patch for the reftable backend, part of a larger series addressing refname availability checks. This is patch 5/16 in v6 of the series, focusing specifically on batching refname availability checks in the reftable backend.

The patch modifies `reftable_be_transaction_prepare()` to collect refnames into a string list (`refnames_to_check`) rather than checking each one individually with `refs_verify_refname_available()`. The actual batched verification is then performed later via `refs_verify_refnames_available()`. This is a preparatory change that doesn't yet improve performance - the optimization comes in later patches that will take advantage of this batching capability.

Key technical changes:
- Adds new `refnames_to_check` string list to collect refnames
- Removes individual `refs_verify_refname_available()` calls for each refname
- Adds single batched call to `refs_verify_refnames_available()` after collecting all refnames
- Properly cleans up the new string list in the `done` section

The patch builds on the batched verification API introduced in patch 4/16 and is part of the series' broader goal to optimize refname availability checks across all ref backends. As noted in the commit message, the performance benefits will be realized in subsequent patches that optimize the batched verification logic. The changes are focused entirely on the reftable backend implementation in `refs/reftable-backend.c`.
