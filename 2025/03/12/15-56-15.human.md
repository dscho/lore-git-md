Refactoring of Git's ref iterator lifecycle management. This is patch 9/16 in Patrick Steinhardt's performance optimization series for the refs subsystem.

The patch decouples iterator lifecycle management from iteration itself. Previously, iterators were automatically freed when exhausted, which created awkward calling patterns and prevented iterator reuse. Now callers must explicitly free iterators using a new `ref_iterator_free()` function, while `ref_iterator_abort()` is simplified to just signal early termination.

Key changes:
- Introduces `ref_iterator_free()` for explicit cleanup
- Simplifies `ref_iterator_abort()` to return void
- Updates all iterator implementations (files, packed, reftable backends) to match new interface
- Modifies callers to handle the new lifecycle rules
- Includes a special case for `dir_iterator` which doesn't use the ref iterator interface

The change enables potential future optimizations like iterator reuse while making the code more consistent with Git's typical resource management patterns. As part of a larger performance series, this foundational change helps enable subsequent optimizations while being a clean refactoring on its own.
