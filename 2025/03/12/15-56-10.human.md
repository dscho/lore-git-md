Performance optimization patch introducing batched refname verification.

This is part 4/16 of Patrick Steinhardt's series optimizing refname availability checks across Git's ref backends. The patch introduces a new `refs_verify_refnames_available()` function that checks for refname conflicts in bulk rather than one at a time. While functionally equivalent to the existing single-ref check, this lays groundwork for future optimizations by centralizing the verification logic.

The implementation wraps the existing verification code in a loop over the input refnames, with the original `refs_verify_refname_available()` now becoming a thin wrapper around this new batch version. The diff is large (170 lines) but mostly structural - moving the existing logic into a loop while maintaining all the same checks for directory conflicts, extras, and skip lists.

This is a foundational change in the series, enabling the more significant performance improvements that come in later patches by allowing optimizations to be applied once across multiple refnames rather than per-refname. The patch appears well-constructed with thorough handling of all existing edge cases, though the real performance benefits will come in subsequent commits that build on this infrastructure.
