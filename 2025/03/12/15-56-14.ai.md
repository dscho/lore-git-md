Performance optimization in the refs subsystem, part of Patrick Steinhardt's v6 series (8/16) addressing refname availability checks. This patch specifically targets redundant verification of common reference prefixes during batch operations.

The change introduces a `strset` to track already-checked directory prefixes in `refs_verify_refnames_available()`, avoiding repeated checks for common paths like "refs/heads/". This yields significant speedups in the reftable backend (1.58x faster for creating 10k refs) and smaller but measurable improvements in the files backend (1.03x). The optimization also benefits reference migration between backends (1.09-1.10x faster for 1m refs).

Key technical details:
- Adds `struct strset dirnames` to track checked prefixes
- Skips re-verification if prefix exists in strset
- Maintains all existing error conditions and cleanup paths
- Preserves packed-refs locking semantics
- Modifies `refs.c` with 12-line addition

The patch builds on previous infrastructure changes (patches 1-7) and shows the expected performance characteristics from the series' design. Benchmarks demonstrate the optimization works best for reftable where prefix checks were more expensive, while files backend sees modest gains due to different performance characteristics. This is one of the core optimization patches in the series following the foundational API changes.
