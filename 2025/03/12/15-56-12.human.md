Performance optimization for the files backend's refname availability checks. This is patch 6/16 in a series addressing performance bottlenecks in ref operations, specifically focusing on batching refname checks to reduce redundant work.

The patch modifies the files backend to batch refname availability checks during transactions, similar to the reftable backend changes in the previous patch. The author identifies five call sites for refname checks in the files backend, but focuses on optimizing the two most performance-sensitive paths: (1) during normal reference updates and (2) when initializing new repositories.

Key changes include:
- Adding a `refnames_to_check` string list to collect refnames for batched verification
- Modifying `lock_raw_ref()` to defer availability checks
- Performing a single batched check via `refs_verify_refnames_available()` before locking packed-refs
- Maintaining the existing error semantics while reducing overhead

The author acknowledges a race condition where packed-refs could change between the batched check and actual locking, but considers this an acceptable tradeoff to avoid changing locking semantics that users might depend on. The patch shows careful consideration of edge cases and maintains backward compatibility while delivering performance improvements.

This continues the series' pattern of measured optimizations with clear explanations of tradeoffs. The changes are well-contained and build logically on the foundation established by earlier patches in the series.
