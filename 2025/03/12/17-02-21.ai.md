Junio Hamano's review of the promisor-remote NULL URL fix. This is a detailed technical review addressing edge cases in the v3 patch that fixed the NULL pointer dereference in promisor-remote configuration handling.

The review focuses on several key concerns about the current implementation:
1. Questions whether the r->name fallback (matching git fetch behavior) is appropriate for promisor remotes since the name may be meaningless to the remote server
2. Suggests the empty URL warnings may be overzealous since malformed URLs would fail similarly
3. Points out potential inconsistencies in string comparison methods between remote_nick_find() (strcasecmp) and other comparisons (strcmp)
4. Notes that some warning conditions may trigger too late after the acceptance decision is already made
5. Raises the architectural question of whether promisor_info_vecs() should be pushing local names as fallback URLs at all

The review maintains the core safety fix from v3 but suggests reconsidering some of the warning logic and the fundamental approach to URL fallbacks in the promisor context. Junio appears to be leaning toward either:
- Removing the name fallback entirely from promisor_info_vecs() if the URLs are only used for remote communication
- Or implementing stricter filtering at the capability response layer if the vectors have other local uses

This represents a potential post-release refinement to the solution, though the immediate NULL dereference fix remains sound. The thread shows careful consideration of how promisor remote behavior should align with (or differ from) standard Git remote conventions.
