Performance optimization for reftable backend (part 5/16 in series). This patch refactors the reftable backend to batch refname availability checks during transaction preparation, though the actual performance gains will come in later patches. 

The change modifies `reftable_be_transaction_prepare()` to collect all refnames needing verification into a string list first, then perform a single batched check via `refs_verify_refnames_available()`. This replaces the previous per-refname checks with `refs_verify_refname_available()`. The patch is part of a larger effort to optimize refname availability checks across Git's ref backends, with particular focus on improving reftable performance when handling tombstone references.

The implementation appears clean and well-contained, modifying only the reftable backend code while maintaining the same error checking behavior. As noted in the commit message, the performance impact will be realized in subsequent patches that optimize the batched verification logic. This is one of the core optimization patches in the series that has already received thorough review in previous iterations.
