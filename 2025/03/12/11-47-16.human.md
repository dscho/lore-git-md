This is a follow-up discussion in the promisor-remote NULL dereference bugfix thread, where Christian Couder responds to Jeff King's review of v2 and outlines changes coming in v3.

Christian acknowledges Jeff's suggestion to make promisor-remote behavior consistent with standard Git remakes by falling back to the remote name when no URL is configured (rather than using an empty string as in v2). He also agrees to switch to `git_config_get_string_tmp()` for cleaner memory management.

The email reveals two additional refinements coming in v3:
1. A warning system to help users when remotes are rejected due to URL mismatches
2. A plan to make `strvec_push()` NULL-tolerant by using `xstrdup_or_null()`, though this will be deferred until after the release

The discussion shows the patch evolving from a simple crash fix to a more polished solution that aligns with Git's conventions while maintaining debuggability. Christian demonstrates responsiveness to review feedback while keeping the immediate focus on the urgent NULL dereference fix. The technical exchange suggests this will be ready for inclusion soon, with some API design questions about strvec handling left for future consideration.
