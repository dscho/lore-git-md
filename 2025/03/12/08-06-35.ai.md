This is a follow-up review comment on a patch in Elijah Newren's merge-ort API compatibility series. Patrick Steinhardt is providing feedback on the rename detection disablement patch (2/3 in the series).

The patch adds `no-renames` support to merge-ort by:
1. Documenting the option in merge-strategies.adoc (removing it from the "ignored by ort" list)
2. Adding early exit logic in `detect_and_process_renames()` when `opt->detect_renames` is 0

Patrick suggests two improvements:
1. Linking to the behavioral-request motivation mentioned in the commit message
2. Adding a test case to verify the disable functionality works as expected

The changes are straightforward - the doc update is clean and the implementation properly resets the `redo_after_renames` and `cached_pairs_valid_side` flags when skipping rename processing. This continues the series' work of bringing merge-ort to parity with merge-recursive's feature set while maintaining the same configuration interface.
