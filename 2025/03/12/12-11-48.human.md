Bugfix for reftable writer error handling, completing a two-part series from Meet Soni's GSoC project. This second patch refines how the reftable writer responds to errors from block_writer_add(), addressing a key concern from earlier reviews.

The writer now properly distinguishes between different error conditions rather than treating all failures as block-full situations. It only retries writing when encountering REFTABLE_ENTRY_TOO_BIG_ERROR (indicating a full block), while immediately propagating other errors like memory allocation or I/O failures. This fixes an incorrect assumption in the previous implementation that could mask serious errors.

The changes focus on writer.c, modifying writer_add_record() and write_object_record() to inspect error codes before deciding whether to retry. The patch follows through on the error code standardization from the first patch in the series, demonstrating good attention to review feedback from Patrick Steinhardt about proper error semantics.
