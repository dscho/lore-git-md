Performance optimization in the refs subsystem (patch 3/16 of v6 series). This patch modifies `git-update-ref` to skip expensive ambiguity checks when parsing object IDs, building on the new `repo_get_oid_with_flags()` API introduced in patch 1/16 and the `GET_OID_SKIP_AMBIGUITY_CHECK` flag from patch 2/16.

The change eliminates redundant ambiguity warnings in this plumbing command where they provide little value (users should use fully-qualified refnames anyway) while delivering measurable speedups: 1.19x faster for files backend and 2.32x for reftable in benchmarks creating 10,000 refs against 100,000 existing refs. The implementation replaces all `repo_get_oid()` calls with `repo_get_oid_with_flags()` using the new skip flag, maintaining identical behavior except for the removed warnings.

Key technical details:
- Modifies 5 call sites in builtin/update-ref.c to use new flag
- Follows precedent from git-cat-file's similar optimization (25fba78d36b)
- Performance gains come from avoiding ref lookups during DWIM resolution
- Reftable backend sees larger relative improvement due to faster baseline
- Part of broader optimization series now approved for inclusion

The patch is well-justified with benchmark data and maintains all existing functionality while removing an expensive check that provided minimal user benefit in this context. It cleanly integrates with the series' incremental API changes.
