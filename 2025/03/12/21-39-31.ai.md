This is a refactoring patch in Elijah Newren's series to establish API compatibility layers for merge-ort as preparation for merge-recursive removal. The patch focuses on the new `merge_ort_generic()` wrapper function and related changes.

The key technical components are:
1. The new `merge_ort_generic()` function handles OID-to-commit conversion and index locking while delegating to `merge_ort_recursive()`. It copies the `get_ref()` helper from merge-recursive.c verbatim except for using standard `error()` reporting instead of merge-recursive's custom `err()`.
2. The patch relaxes an assertion in `merge_incore_recursive()` to allow builtin/am's fake ancestor case through, which relates to the missing `num_merge_bases == 1` check that Patrick Steinhardt noted in his review.
3. Elijah acknowledges he should have included more explanation about the merge base handling differences in this commit message rather than splitting it to a later test-related commit.

The changes maintain behavioral parity with merge-recursive while using more standard Git conventions (like `error()`).
