Performance optimization series follow-up regarding batch refname checking in files backend.

This is a review comment from shejialuo on patch 7/16 of Patrick Steinhardt's refs performance optimization series. The patch implements batched refname availability checks for initial transactions in the files backend, building on earlier work to optimize refname verification.

The reviewer notes two issues: (1) some redundant text in the commit message that could be trimmed, and (2) a repeated question about why the files backend doesn't sort the `refnames_to_check` list like the reftable backend does in patch 5/16. This sorting inconsistency between backends was previously discussed, with the files backend deliberately avoiding sorting to maintain lock-free behavior at the cost of potential race conditions.

The patch itself is straightforward - it replaces individual `refs_verify_refname_available()` calls with batched verification via a string list, though the actual performance benefits will come in later patches when iterator reuse is implemented. The change is part of a larger effort to optimize refname availability checks that has already received final approval from Karthik Nayak, with this being a minor documentation clarification request.
