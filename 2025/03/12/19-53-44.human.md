Security hardening refinement for remote-object-info command. This is part of the ongoing remote object-info functionality series, now in its 12th iteration.

Peijian Ju responds to Jeff King's feedback about input validation in the `remote-object-info` command. The discussion clarifies that this is purely client-side operation, making some of the earlier security checks unnecessary since Git traditionally trusts its local clients. The key change is simplifying the command parsing from using `split_cmdline()` to direct space-based splitting, as URLs should be properly encoded and object IDs cannot contain spaces.

The patch will:
1. Remove the MAX_REMOTE_OBJ_INFO_LINE length check that was added in v11
2. Replace the complex command splitting with simple space-based parsing
3. Update documentation to clarify URL encoding requirements
4. Adjust tests to match the new simpler input format

This appears to be a well-considered refinement based on deeper understanding of the security model. The changes in v11 were based on a misunderstanding of the threat model, and this revision brings the implementation back to its appropriate level of simplicity while maintaining security through proper URL encoding requirements. The exchange shows good technical discussion about Git's security boundaries between client and server operations.
