Bugfix for reftable error handling standardization. This is the first patch in Meet Soni's v3 series addressing error propagation in the reftable backend, part of their GSoC project.

The patch replaces generic -1 returns with specific REFTABLE_*_ERROR codes throughout the reftable codebase, particularly introducing REFTABLE_ENTRY_TOO_BIG_ERROR for size-related failures. This change affects several key functions in block.c and record.c that handle writing reftable records, including block_writer_add() and various encoding functions.

The motivation is to enable callers to distinguish between different types of failures rather than treating all errors as "entry too big" conditions. The changes maintain backward compatibility while improving debuggability. Documentation is updated to clarify the new error return behavior.

This appears to be a well-crafted change that addresses prior review feedback, with clean separation of concerns from the follow-up patch that will handle the caller-side adaptations. The diff shows careful attention to error propagation through multiple layers of the reftable implementation.
