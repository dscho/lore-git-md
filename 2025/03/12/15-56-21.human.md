Performance optimization series for refs subsystem (patch 15/16). This patch implements seek capability for the files backend's ref iterator, completing the seek functionality across all three major ref backends (files, reftable, and packed) in this performance-focused series.

The change is straightforward since the files backend uses a ref-cache iterator internally - the implementation just delegates the seek operation to the underlying iterator. The patch follows the same pattern as previous iterator seek implementations in the series, adding a `seek` method to the iterator vtable. Notably, like with the reftable backend, seeking is not implemented for reflog iterators (attempts to seek will trigger a BUG).

This is part of a larger effort to optimize refname availability checks, particularly around tombstone references. The series has progressed through foundational API changes, batched verification infrastructure, and now core optimizations. With this patch, all major backends support consistent iterator seeking patterns, enabling future performance improvements. The changes are relatively small (16 lines added) and build on well-established patterns from earlier in the series.
