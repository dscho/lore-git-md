Performance optimization in the refs subsystem (part 10/16 of a series). This patch introduces infrastructure to re-seek ref iterators, allowing them to be reused rather than discarded after exhaustion. The change is particularly relevant for reftable iterators which currently must be scrapped after use, despite having reusable internal state.

The core addition is a new `.seek` function in the ref iterator vtable that lets callers reset an iterator to start from a new (or same) prefix. This maintains the same behavior as creating a fresh iterator but enables potential optimizations through state reuse. The implementation currently only provided for trivial cases (empty and prefix iterators), with backend-specific implementations to follow in later patches.

This builds on the iterator lifecycle refactoring from patch 9/16 and is part of a larger effort to optimize refname availability checks. The change is well-motivated by the reftable backend's needs and appears carefully implemented, touching 3 files with 59 lines added. The commit message clearly explains both the immediate utility and future extensibility (noting that other iterator parameters remain fixed for now).
