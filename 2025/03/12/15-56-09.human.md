Performance optimization patch in a series addressing refname checks. This is the third of 16 patches in v6 of a performance optimization series for the refs subsystem, now with final approval from reviewers.

The patch modifies `git-update-ref` to skip expensive ambiguity checks when parsing object IDs, similar to a previous optimization made to `git-cat-file`. The change uses the new `GET_OID_SKIP_AMBIGUITY_CHECK` flag (introduced in patch 2/16) with `repo_get_oid_with_flags()`. The optimization is particularly valuable for `--stdin` operations with many refs.

Benchmarks show significant speedups: 1.19x faster for the files backend and 2.32x faster for reftable when creating 10,000 refs against a repository with 100,000 existing refs. The patch maintains all existing behavior except for removing the ambiguity warning, which the commit argues is appropriate since `update-ref` is plumbing that should use unambiguous refnames anyway.

The change touches multiple call sites in `builtin/update-ref.c`, consistently applying the new flag when parsing object IDs. The series as a whole appears well-vetted, with all documentation feedback resolved and technical concerns addressed by reviewers.
