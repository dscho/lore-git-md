Performance optimization completing ref iterator improvements in refs subsystem.

This is the final patch in Patrick Steinhardt's 16-part series optimizing refname availability checks across Git's ref backends. Building on the iterator seek capabilities added in previous patches (including the files backend seek support in patch 15/16), this change modifies `refs_verify_refnames_available()` to reuse iterators rather than recreating them for each check. The key improvement comes from reseeking existing iterators when checking nested refnames, avoiding repeated allocation and initialization overhead.

Benchmarks show a 25% speedup for the reftable backend when creating many refs (39.8ms → 31.9ms), though the files backend sees minimal improvement (392.3ms → 387.7ms) due to its inherent filesystem overhead. The change is small (12 lines modified in refs.c) but completes the series' goal of optimizing ref operations by making iterator usage more efficient across all backends.

The patch maintains the series' pattern of focused, measurable improvements while keeping the changes contained - it doesn't introduce new concepts but effectively applies the iterator reseek capability established earlier in the series. With this change, the performance optimization series appears complete, having systematically addressed refname checking bottlenecks through API improvements and backend-specific implementations.
