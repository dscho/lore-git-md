Performance optimization patch for reftable backend iterators, part 12/16 in a series addressing refname availability checks. This patch implements seeking capability for reftable reference iterators while explicitly excluding reflog iterators from this functionality.

The changes center around:
- Adding `reftable_ref_iterator_seek()` function that handles prefix-based seeking by duplicating the prefix string and delegating to low-level reftable iterator
- Modifying iterator initialization to properly check `reftable_stack_init_ref_iterator()` success before proceeding
- Converting the `prefix` field from `const char*` to owned `char*` to support dynamic updates during seeks
- Explicitly implementing (but rejecting) seek operations for reflog iterators via `BUG()` since the use case isn't clear
- Updating the iterator vtable to include the new seek operation alongside existing advance/peel/release methods

Key technical details:
- 35 lines changed in `refs/reftable-backend.c`
- Seeks are implemented for regular ref iterators but not reflog iterators
- Iterator ownership model updated to handle dynamic prefix strings
- Error checking strengthened during iterator initialization
- Maintains compatibility with prior iterator API changes from patches 8-11

The patch builds directly on the iterator reseek capability added in patch 11/16, applying it specifically to the reftable backend. It follows the series pattern of adding orthogonal capabilities that together enable performance improvements, in this case by allowing more efficient navigation of reftable references during operations like ref updates. The explicit exclusion of reflog iterator seeking leaves room for future implementation if use cases emerge.
