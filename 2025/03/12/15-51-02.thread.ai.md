Bug report and fix for integer overflow in Git's diff output when using extremely large context values with `--unified`. Original reporter Jason Cho demonstrated that `git diff --unified=2147483647` on Windows with Git 2.47 incorrectly repeats context from the second hunk, unlike GNU diff which handles this case correctly. The issue stems from an overflow in `xdiff/xemit.c`'s `xdl_get_hunk()` function where `2 * ctxlen + interhunkctxlen` exceeds valid bounds, specifically affecting Windows where `long` and `int` have the same size.

René Scharfe provided a fix introducing a `saturating_add()` helper that caps sums at LONG_MAX, preventing overflow while maintaining the ability to produce a single hunk for the entire file with extreme context values. The solution modifies `xdiff/xemit.c` to use safe addition when calculating `max_common` for hunk boundaries. Junio C Hamano reviewed and approved the patch, praising the careful bounds-checking approach that preserves compatibility with GNU diffutils' behavior rather than introducing artificial limits, while critiquing broader trends in patch submissions that prioritize warning suppression over thoughtful correctness improvements.
