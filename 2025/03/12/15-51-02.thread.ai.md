Thread summary:

Bug report regarding integer overflow in Git's diff output when using extremely large context values with `--unified`. Reporter Jason Cho demonstrates that `git diff --unified=2147483647` on Windows with Git 2.47 incorrectly repeats context from the second hunk, unlike GNU diff which handles this case correctly. The issue stems from an overflow in `xdiff/xemit.c`'s `xdl_get_hunk()` function where `2 * ctxlen + interhunkctxlen` exceeds valid bounds. Current documentation doesn't specify limits for `--unified` parameter values. The bug has limited practical impact due to the extreme values required to trigger it, but represents a correctness issue in the diff machinery. Technical details show the problem occurs specifically with values approaching INT_MAX (2147483647) and manifests as incorrect hunk context repetition. GNU diffutils 3.10 serves as reference implementation for correct behavior. Open questions include whether to document limits or fix the overflow handling.
