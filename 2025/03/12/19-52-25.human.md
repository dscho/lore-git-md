This is a follow-up discussion in the cruft pack size limit thread, focusing on potential mechanisms to mark packs that have reached their size limit.

Taylor Blau responds to Junio Hamano's suggestion about using a .keep-like mechanism to mark packs that have hit the `--max-cruft-size` limit. While acknowledging the idea has merit, Taylor points out practical limitations: the existing .keep mechanism doesn't distinguish between user-requested keeps and system-generated ones, and creating a new .frozen mechanism would add complexity to an already "ugly" system.

The discussion touches on longer-term possibilities like extending pack headers to record size limit information, but Taylor maintains that the current v3 implementation (with its strict size enforcement) is sufficient for now. This aligns with the thread's earlier conclusion that the core implementation is settled, though the exchange keeps open the door for future metadata-based solutions.

The email reinforces the thread's status quo - the v3 behavior remains the accepted approach, with potential future improvements noted but not pursued at this time. For readers following the cruft pack work, this is a minor postscript to the main discussion rather than a new direction.
