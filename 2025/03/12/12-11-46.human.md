Bugfix series for reftable error handling, part of Meet Soni's GSoC project. This v3 iteration splits the previous patch into two parts and refines error code propagation in the reftable subsystem.

The first patch replaces generic -1 error returns in `block_writer_add()` and related functions with specific error codes, allowing callers to distinguish between different failure modes rather than assuming all errors mean "entry too big". The second patch adapts the writer code to properly handle these distinct error cases - now it only retries writes when encountering specific block-full conditions, while propagating other errors immediately.

The changes address Patrick Steinhardt's review feedback from v2, including splitting the work into logical units and improving comment formatting to match Git conventions. The implementation now cleanly separates the error code plumbing changes from the writer's error handling adaptations. This continues the series' goal of improving debuggability through precise error reporting in the reftable backend.
