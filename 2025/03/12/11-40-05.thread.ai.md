Git thread summary:

Simon Josefsson initiated investigation into non-reproducible Git bundle generation where identical source repositories produce bundles with different checksums, observed in Git 2.48.1 when creating bundles for Gnulib. Technical analysis by Kyle Lippincott and Jeff King (peff) identified threading as the root cause, with `pack.threads=1` providing deterministic output at performance cost. The discussion has expanded to consider security implications and practical constraints of reproducibility.

Simon's latest contribution confirms the non-determinism occurs during `git clone` operations, not within a single repository, and persists even with alternative clone methods (dumb protocol, rsync). This reinforces the threading/pack-generation origin of the issue. The email significantly advances the security discussion by drawing parallels to established reproducible build practices, arguing that environment-specific reproducibility (same Git version, zlib implementation) would provide meaningful security benefits despite not achieving universal bit-for-bit matching.

Technical scope now encompasses:
- Bundle and clone reproducibility mechanisms
- Pack file generation threading models
- Object ordering variations between clones
- Alternative clone protocols (smart/dumb HTTP, rsync)
- Security verification models for content-addressable systems
- Performance/reproducibility tradeoffs
- Environment constraints for verification

Key findings:
1. `pack.threads=1` enables deterministic bundles but with performance impact
2. Clone operations intrinsically introduce non-determinism through threading
3. Dumb/rsync clones don't resolve object ordering variations
4. Environment-specific reproducibility may suffice for security use cases

Open questions:
* Feasibility of clone-time synchronization for deterministic ordering
* Documentation requirements for reproducible environments
* Security value proposition of partial reproducibility
* Whether to treat this as a bug or document as expected behavior
* Potential changes to bundle format to support verification
