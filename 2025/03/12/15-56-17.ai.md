Performance optimization patch extending the refs iterator API to support seeking in merged iterators, part of a larger series addressing refname availability checks. This is the 11th patch in a 16-part v6 series focused on optimizing ref operations across different backends.

The patch implements the `seek` operation for merged reference iterators, building on the iterator reseek capability introduced in patch 10/16. Key technical changes include:
- Splitting iterator ownership tracking from active iteration state (new `iter0_owned`/`iter1_owned` fields)
- Preserving underlying iterators after exhaustion to allow reseeking
- Implementing the new `merge_ref_iterator_seek()` vtable function
- Maintaining all existing iterator behavior while adding seek capability

The implementation is straightforward but requires careful handling of iterator lifecycle - underlying iterators must not be freed when exhausted since they may be needed for reseeking. The patch modifies 38 lines in `refs/iterator.c`, primarily adding the seek implementation while adjusting the advance and release logic to maintain the new ownership model.

This continues the series' pattern of foundational changes enabling future optimizations, particularly for reftable performance. The change maintains compatibility with all prior work in the series while providing another building block for efficient ref lookups. No new documentation is added as the behavior aligns with the iterator API established in previous patches.
