This is a bugfix patch in the reftable subsystem, part of a series standardizing error handling. It replaces generic -1 error returns with specific REFTABLE_*_ERROR codes throughout the reftable codebase, with particular focus on block_writer_add() and related functions.

The patch systematically converts all error paths in reftable/block.c and reftable/block.c to use proper error codes, with REFTABLE_ENTRY_TOO_BIG_ERROR being the most common replacement for size-related failures. The changes affect core encoding functions like reftable_record_encode() and various record-specific encoders (ref, obj, log). Function documentation is updated to reflect that callers should now expect specific error codes rather than just -1.

Key technical changes include:
- Block writer operations now distinguish between "entry too big" (REFTABLE_ENTRY_TOO_BIG_ERROR) and other error conditions
- Error propagation is now direct rather than being normalized to -1 at each level
- The block_writer_add() header comment is updated to clarify it returns "appropriate error codes"
- All size checks that previously returned -1 now use REFTABLE_ENTRY_TOO_BIG_ERROR

This builds on prior review feedback to properly separate error code standardization (this patch) from caller adaptation (handled in patch 2/2). The changes are mechanical but thorough, touching multiple subsystems within reftable while maintaining backward compatibility. The patch appears well-tested and follows Git's coding standards, with clean commit message explaining the motivation for finer-grained error handling.
