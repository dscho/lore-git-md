This is a final review discussion in the promisor-remote NULL dereference bugfix thread. Junio Hamano raises several thoughtful points about the v3 patch's design choices, particularly around how empty/missing URLs should be handled in the promisor-remote subsystem.

The key discussion points are:
1. Questioning whether the fallback to using the remote name (matching `git fetch` behavior) makes sense in this context, since promisor remotes communicate with external servers where local path conventions may not be meaningful
2. Suggesting the warnings about empty/mismatched URLs may be overzealous, since malformed URLs would fail anyway during actual use
3. Noting potential inconsistencies in string comparison methods between different parts of the code
4. Raising the architectural question of whether URL fallbacks should be filtered earlier rather than handled with warnings later

The tone is constructive but probing - Hamano isn't rejecting the patch (which has already been approved for inclusion), but is encouraging deeper consideration of whether the current approach aligns with Git's conventions and the promisor-remote's specific needs. This represents the kind of high-level design discussion that often happens after the immediate bugfix is settled, as maintainers consider longer-term implications.

The patch author Christian Couder will need to decide whether to address these points in a follow-up or leave them for future consideration, given that the critical NULL dereference is already properly fixed in v3.
