Bugfix completing the reftable error handling series by refining writer behavior. This second patch in the v3 series focuses on error propagation in writer.c, following the first patch's standardization of error codes.

The change makes writer_add_record() and write_object_record() properly distinguish between different error conditions from block_writer_add(). Previously, any non-zero return would trigger a block flush and retry, incorrectly assuming all errors indicated a full block. Now, only REFTABLE_ENTRY_TOO_BIG_ERROR triggers retry behavior, while other errors (like memory allocation failures) propagate immediately.

Key technical changes include:
- Error code inspection before deciding to flush blocks
- Removal of forced error code conversion to REFTABLE_ENTRY_TOO_BIG_ERROR
- Parallel updates to both writer_add_record() and write_object_record()
- Added comments clarifying the retry logic flow

This implements Patrick Steinhardt's key review feedback from v2 about properly handling distinct error conditions. The patch maintains the same error code standardization introduced in patch 1 while fixing the writer's response to those codes. The changes are focused and well-contained to writer.c, with clear documentation of the new behavior in both code and commit message.

The series appears ready for merging, having addressed all substantive feedback through careful iteration. This final patch completes the error handling improvements by ensuring proper error propagation matches the newly standardized error codes from the first patch.
