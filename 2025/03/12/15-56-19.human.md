Performance optimization for ref-cache iterators (patch 13/16 in a series)

This patch implements seeking capability for ref-cache iterators, continuing Patrick Steinhardt's performance optimization series for the refs subsystem. The change splits iterator seeking logic out of `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function for reuse, while removing an optimization that returned empty iterators when no references existed (since reseeking to different prefixes would otherwise be impossible).

The implementation shows careful attention to iterator state management, with notable changes including:
- Converting the prefix` from `const char*` to owned `char*`
- Adding explicit cache and repository references to the iterator struct
- Properly handling directory priming and prefix matching states
- Maintaining the iterator stack levels during seeks

This builds directly on the merged iterator seek capability added in patch 11/16, and like other patches in the series, focuses on optimizing refname availability checks. The change appears well-contained and properly motivated within the series' context, though it does trade one small optimization (empty iterator returns) for more flexible seeking behavior. The patch follows the series' pattern of methodical, incremental improvements to the refs subsystem's performance characteristics.
