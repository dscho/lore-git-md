Joschua Kesper has proposed making `.gitignore` patterns more intuitive by allowing negated exact paths to override parent directory exclusions. Currently, if you want to ignore a directory `foo` but track a specific deep file `foo/bar/baz`, you need four patterns to work around Git's exclusion rules. The proposal would let you accomplish this with just two patterns (`foo` and `!foo/bar/baz`), as long as the paths are exact matches without wildcards.

The key insight is that literal path matches don't require the directory scanning that makes wildcard exclusions expensive, so relaxing the rules for exact paths wouldn't hurt performance. This would make a common use case simpler while preserving the current behavior for wildcard patterns. The change would affect core ignore pattern handling, so careful implementation would be needed to avoid regressions in more complex scenarios. The proposal seems well-motivated for workflows where users need to track specific files deep in ignored directory trees.
