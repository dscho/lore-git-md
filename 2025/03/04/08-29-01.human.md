This is a discussion about a build system regression affecting test suite variable propagation. Jeff King responds to Taylor Blau's report about GIT-BUILD-OPTIONS silently overriding test environment variables like NO_EXPAT when using the performance test suite.

Jeff questions whether the reported usage pattern (setting variables via make -C) is the intended way to run these tests, suggesting the proper approach might be to set variables during the initial build. He acknowledges the regression exists but notes the behavior was already somewhat fragile before the change, with undocumented conventions around test variable handling.

The core issue remains that the new template-based GIT-BUILD-OPTIONS writes empty variable assignments that clobber environment settings, but Jeff suggests the underlying problem may be broader - the test infrastructure lacks clear documentation about how to properly pass build variables. While agreeing the regression should be fixed, he implies the solution might need to consider both the immediate issue and the larger question of how these variables should work.
