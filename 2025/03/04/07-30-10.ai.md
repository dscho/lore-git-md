This is a test infrastructure discussion about environment isolation in Git's unit tests, continuing the thread about how to handle external configuration influences.

Jeff King (Peff) responds to Junio Hamano's suggestion that functions affected by environment might be too high-level for unit testing. He raises practical concerns about environment-dependent breakage that could surface unpredictably in different user setups. The key examples given are: 1) commit creation falling back to system info when ident is missing (potentially failing on systems with blank GECOS fields), and 2) potential issues with programs like gpg/ssh that read their own config files based on environment variables.

The email reinforces the need for robust environment control in unit tests, suggesting that simply suppressing Git config may not be sufficient. Peff's examples highlight subtle ways tests could break in production systems, supporting the case for either comprehensive environment control (Junio's preference) or at least thorough environment sanitization (Patrick's approach). The response doesn't propose a specific solution but strengthens the argument against relying on "good enough" environment states that might work for some developers but fail for others.
