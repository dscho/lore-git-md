Feature request to modify `.gitignore` pattern handling for negated non-wildcard paths. Joschua Kesper proposes allowing simpler syntax to exclude directories while including specific subpaths, where current behavior requires verbose patterns (e.g. tracking `foo/bar/baz` while ignoring `foo` currently needs 4 patterns vs proposed 2). The change would relax parent directory exclusion rules for exact path matches only, maintaining current wildcard behavior. Performance impact claimed neutral/positive since literal paths avoid directory scanning. Technical considerations: requires modifying pattern matching logic in `dir.c` while preserving wildcard optimizations, with potential documentation updates to `gitignore(5)`. Core challenge is implementing without regressing existing wildcard cases while adding the literal path capability.
