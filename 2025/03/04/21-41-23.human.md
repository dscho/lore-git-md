This is a feature patch adding a "prompt-yes" mode to Git's `help.autocorrect` configuration. Chris Howlett's patch introduces a new option that makes the interactive confirmation prompt default to "Yes" when Git suggests a corrected command, as opposed to the existing "prompt" mode which defaults to "No". The change is motivated by the observation that Git's autocorrections are usually correct, so accepting them by default would be more convenient.

The implementation adds a new `AUTOCORRECT_PROMPT_YES` constant (-5) in help.c, with corresponding handling in the prompt logic to show "[Y/n]" instead of "[y/N]". Like the existing prompt mode, it falls back to different behavior when not in a terminal - in this case executing immediately rather than doing nothing. The patch updates the help.adoc documentation to describe the new mode.

This is version 2 of the patch, rebased against master to account for some intervening changes. The author notes this is their first contribution to Git and acknowledges the difficulty of testing interactive prompts as the reason for not adding new tests. The patch appears clean and focused, though it may need to coordinate with Scott Chacon's parallel work on boolean values for `help.autocorrect` that was noted earlier in the thread.
