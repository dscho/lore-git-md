This is a design discussion in the ongoing thread about marking mentoring program patches (like GSoC) in `git format-patch` subjects. Junio Hamano responds to Patrick Steinhardt's compromise proposal of a `--patch-prefix` flag, arguing against introducing new flags entirely.

Junio makes several key points: First, he clarifies the existing `--subject-prefix` (configurable via `format.subjectPrefix`) is meant for project-specific prefixes like "[PATCH rcu]", while `--rfc` is deliberately unconfigurable for occasional use. He suggests students could simply use `--subject-prefix="GSoC PATCH"` for their entire project, optionally adding `--rfc` when unsure ("[GSoC PATCH WIP]").

The core argument is that GSoC markers shouldn't be treated as "extra" prefixes requiring new mechanisms, but rather incorporated into the existing subject prefix system. Junio sees this as more natural than either the original `--subject-extra-prefix` proposal or Patrick's `--patch-prefix` compromise, avoiding flag proliferation while maintaining email subject compactness.

This moves the discussion toward potentially simpler solutions, though it remains to be seen whether other participants will agree this approach satisfies the discoverability needs for mentoring program participants. The thread continues to balance interface design, email presentation, and workflow considerations.
