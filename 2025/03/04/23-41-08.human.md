Refactoring patch in the reflog-expire maintenance task effort, addressing global state removal.

Justin Tobler responds to Patrick Steinhardt's patch that moves reflog expiry configuration from global variables into the `reflog_expire_options` struct. The patch is part of a larger series (3/6) to refactor reflog expiration for Git's maintenance system.

The key technical change here replaces the global `reflog_expire_cfg` linked list with per-options-storage via new `entries` and `entries_tail` fields in `reflog_expire_options`. This eliminates global state while maintaining the same functionality. Justin notes the patch successfully moves all configuration into the options struct but questions whether the `expire_total` and `expire_unreachable` fields still belong there, suggesting they might be better handled during the actual expiration process rather than as configuration.

This appears to be a clean, focused refactoring that advances the series' goal of removing global state. Justin's observation about the struct fields seems like a reasonable design consideration that could be addressed in future iterations. The discussion remains technical and constructive, with both contributors clearly engaged in refining the implementation details.
