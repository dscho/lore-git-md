This is a discussion about the future of Git's `--literally` flag and unknown object type handling, part of Jeff King's ongoing zlib inflation series. The thread has been considering deprecating the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` feature and `--literally` flag in Git 3.0, with Junio Hamano suggesting complete removal and Taylor Blau proposing to move it to test-only helpers.

Jeff King pushes back against removing `--literally` entirely, arguing it's valuable for debugging and recovery from corruption cases where objects fail fsck but remain usable. However, he agrees unknown type handling (via `OBJECT_INFO_ALLOW_UNKNOWN_TYPE`) has never been practically useful and should be removed. This maintains the ability to work with slightly broken but functional objects while eliminating support for truly unknown types that can't be packed or transferred.

The discussion reveals differing perspectives on the utility of these debugging tools - while all agree unknown types serve no purpose, there's debate about whether `--literally` should remain public or become test-only. Jeff's position preserves more flexibility for real-world recovery scenarios, while Taylor's test-helper approach would clean up the public interface while keeping the functionality available for development purposes. The thread shows the series is nearing completion with only this higher-level design question remaining open.
