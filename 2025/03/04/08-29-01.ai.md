This is a discussion about build system behavior affecting test suite variable propagation, specifically around the GIT-BUILD-OPTIONS file generation. Jeff King responds to Taylor Blau's report about how commit 4638e8806e changed the Makefile's handling of test-related variables like GIT_PERF_MAKE_OPTS and NO_EXPAT, causing empty assignments to override environment variables.

Jeff questions the original use case, noting that the typical workflow for performance tests involves building via `make` first before running tests, rather than passing build options through the test invocation. He suggests the intended behavior is to set these variables during the initial build rather than at test time, though acknowledges this is undocumented convention.

The email identifies two key issues: 1) the regression where empty values now override environment variables, and 2) the lack of clear documentation around the expected workflow for test configuration. While agreeing that Taylor's proposed fix (only writing non-empty values to GIT-BUILD-OPTIONS) would address the regression, Jeff raises concerns that the underlying usage pattern may itself be problematic. The discussion highlights tension between maintaining backward compatibility with existing workflows versus enforcing clearer (but potentially breaking) conventions.
