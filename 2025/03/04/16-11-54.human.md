Memory leak fix for reftable reader initialization. This is the second version of a patch addressing a production code memory leak in `reftable_reader_new()` where the 'name' field allocation would be lost if initialization failed partway through. The issue was originally reported by H Z and has been through review by Jeff King, who identified a potential NULL dereference in the error path.

The fix adds cleanup for the 'name' field when errors occur during reader initialization, while also guarding against the NULL dereference case Jeff spotted. The change is minimal - just two lines added to the error handling path - and maintains the existing allocation timing. This follows the thread's earlier resolution of a similar test-only leak.

The patch appears well-considered, with clear attribution to both the original reporter and the reviewer who caught the edge case. The v2 changelog notes the improvement over v1 (the NULL check addition) in response to Jeff's feedback. This looks like a straightforward, uncontroversial fix that properly closes out the memory management issue while maintaining safety.
