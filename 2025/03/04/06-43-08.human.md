This is a discussion about the future of Git's `--literally` flag and unknown object type handling, part of Jeff King's ongoing zlib inflation series.

Jeff King responds to Taylor Blau and Junio Hamano's earlier discussion about potentially deprecating `--literally` and `OBJECT_INFO_ALLOW_UNKNOWN_TYPE`. While agreeing that unknown type handling should be removed (calling it "never usable"), Jeff argues for keeping `--literally` as a valuable tool for working with slightly broken but still functional objects, particularly for recovery from corruption. He distinguishes between truly invalid objects (which `--literally` helps with) and objects with unknown types (which serve no practical purpose).

The exchange reveals differing perspectives on `--literally`'s utility - while Junio sees it primarily as a debugging tool that could be removed, and Taylor suggests moving it to test infrastructure, Jeff advocates keeping it in the mainline for its recovery use cases. This appears to be the last open discussion point in the otherwise technically settled zlib series, with the unknown type handling now clearly marked for removal while `--literally`'s fate remains under discussion.
