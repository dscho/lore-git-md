This is a performance and refactoring patch that simplifies cruft pack aggregation in `git repack`. It's the first of a two-patch series addressing object freshening behavior in multi-cruft pack scenarios.

The patch removes complex size-based aggregation logic for cruft packs when using `--max-cruft-size`, replacing it with a simpler approach that combines all small packs below the threshold size. The old implementation would carefully track cumulative sizes to stay under the limit, while the new version lets `pack-objects` handle any necessary splitting of the combined result. This yields equivalent functionality with significantly less code - the diff shows 80 lines removed versus 2 added.

The behavioral change is minor: previously, smaller packs would be combined first to maximize packing efficiency, while now all eligible packs are combined opportunistically. The patch removes a now-irrelevant test that specifically verified the old ordering behavior. The commit message clearly explains the rationale and acknowledges the subtle behavior change.

This appears to be a well-considered simplification that has already gone through review, with Elijah Newren approving the technical approach. The only outstanding discussion point (raised by Patrick Steinhardt in the thread) concerns whether this might lead to perpetual repacking cycles, but that doesn't affect the immediate correctness of the change.
