This is the first patch in a two-part series addressing cruft pack handling during repacks, specifically focusing on simplifying the logic for aggregating small cruft packs when using `--max-cruft-size`.

The patch removes complex size-based aggregation logic from `builtin/repack.c` that previously tried to combine cruft packs in size order until reaching the maximum size threshold. Instead, it now simply combines all cruft packs smaller than the threshold in one operation, letting `pack-objects` handle any necessary splitting. This results in a simpler implementation that changes the behavior slightly - packs are now be combined more opportunistically rather than in strict size order.

The changes include:
- Removal of the `existing_cruft_pack_cmp` comparison function and related size-tracking variables
- Simplification of the main aggregation loop to directly check pack sizes against the threshold
- Deletion of a now-irrelevant test case that verified the old size-ordering behavior
- Updated commit message explaining the simpler approach and behavioral change

The patch maintains all core functionality while reducing code complexity. The commit message notes this was reviewed by Elijah Newren and incorporates his suggested wording improvements. The only outstanding discussion point (raised by Patrick Steinhardt in the thread) concerns whether this simplification might lead to perpetual repacking cycles, though this doesn't affect the immediate correctness of the change.
