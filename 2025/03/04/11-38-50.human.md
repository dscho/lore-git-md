Reftable backend bugfix for `transfer.hideRefs` consistency. Patrick Steinhardt responds to Jeff King's investigation of inconsistent ref-hiding behavior between packed and loose refs, confirming the reftable backend has the same bug and proposing a fix.

The thread has established that commit 59c35fac54 introduced incorrect prefix matching behavior in packed refs, where they would hide all refs starting with a prefix rather than requiring a directory separator (like loose refs do). Patrick now confirms the reftable backend shares this bug, as shown by existing tests in t1419.

Patrick proposes a fix for the reftable backend that mirrors the correct loose ref behavior: a prefix pattern will only hide refs when either (1) it's an exact match, or (2) the pattern ends with '/' (indicating a directory) and the ref continues with '/'. The patch adds these checks to `should_exclude_current_ref()` in reftable-backend.c.

This moves the discussion forward by addressing the third backend (reftable) that needs alignment, following the packed/loose ref inconsistency already identified. The solution maintains the principle that prefix matching should respect directory boundaries, which appears to be the intended behavior for `transfer.hideRefs`. The patch looks straightforward and aligns with the established direction of fixing the packed backend.
