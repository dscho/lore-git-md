This is a platform compatibility fix for the ongoing reftable library decoupling effort (`ps/reftable-sans-compat-util` series). Patrick Steinhardt identifies and fixes a MinGW-specific issue where mismatched memory allocators between the reftable library and Git core were causing SIGTRAP failures in Windows unit tests.

The problem occurs specifically in MinGW builds (not MSVC) when Git's custom mimalloc allocator gets used by default. The reftable library was using standard mscrt.dll allocators while the rest of Git used mimalloc, leading to memory being freed with the wrong allocator. The fix moves the mimalloc override declarations from `git-compat-util.h` to `compat/posix.h`, ensuring consistent allocator usage across the codebase.

This represents the last technical blocker for the reftable decoupling series, which aims to remove Git-specific dependencies from the reftable code for better portability. The issue was discovered during integration testing on Windows, highlighting the complex interactions between platform-specific build configurations and the reftable backend work. The patch is narrowly focused on the allocator mismatch without introducing broader changes to the mimalloc integration.
