Bugfix for inconsistent `transfer.hideRefs` behavior across ref backends.

Taylor Blau confirms Patrick Steinhardt's analysis that the reftable backend exhibits the same incorrect behavior as packed refs when handling prefix matching in `transfer.hideRefs`. The issue, originally identified by Jeff King, stems from commit 59c35fac54 which made packed refs incorrectly hide all refs starting with a prefix, rather than requiring a directory separator ('/') for proper prefix matching (as loose refs correctly do).

Patrick has provided the specific fix for the reftable backend, which needs to mirror the same logic being proposed for packed refs - requiring either an exact match or proper directory containment for prefix exclusions. The proposed change to `should_exclude_current_ref()` in reftable-backend.c would make it properly handle edge cases while maintaining consistency with the intended behavior.

Taylor indicates he'll work on implementing this fix, which will bring all three ref backends (loose, packed, and reftable) into alignment. This thread has now clearly identified both the problem and solution path, with the remaining work being the actual implementation of the fixes.
