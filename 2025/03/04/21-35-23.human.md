Bugfix for cruft pack object freshening with size thresholds. This is the second and final patch in a series addressing object freshening behavior in multi-cruft pack scenarios.

The patch fixes an issue where objects in large cruft packs (those exceeding the `--max-cruft-size` threshold) couldn't be freshened during repacks. Previously, these objects would be skipped entirely because they were marked as "kept in-core". The solution introduces a new `ignore_packed_keep_in_core_has_cruft` flag and mtime-based comparison logic to ensure objects can still be freshened when needed.

Key changes:
- Objects in non-cruft packs are always preserved (unchanged behavior)
- For cruft packs, objects are only preserved if their mtime is at least as recent as the candidate copy
- New test cases verify the mtime comparison logic works correctly
- The implementation spans `pack-objects.c`, `packfile.c`, and `packfile.h`

The patch appears well-tested and addresses a real limitation in the current implementation. The commit message clearly explains both the problem and solution, including detailed analysis of the previous behavior's shortcomings. The only remaining discussion point (from Patrick Steinhardt) concerns potential long-term repacking behavior, but that relates more to the first patch in the series.
