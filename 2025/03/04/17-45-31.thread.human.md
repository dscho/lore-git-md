The Git 2.49.0-rc1 release thread continues with discussion of a platform-specific test failure affecting the new `git backfill` command. Todd Zullinger initially reported that test 5620.4 ('do partial clone 2, backfill min batch size') fails on s390x architecture during release testing, specifically when verifying promisor fetch count metrics in the batch fetching logic. 

Maintainer Junio Hamano has now responded, acknowledging the report and agreeing that while s390x is a niche platform, the issue deserves attention. Junio appears cautiously optimistic that this may not block the release, but leaves the door open for further investigation. Todd has offered to provide additional debugging information and complete test logs to help diagnose whether this represents a genuine bug in the backfill command or merely a test timing issue specific to s390x. 

The release otherwise appears stable, with no other platform-specific issues reported for the 367 non-merge commits that introduce major features like the backfill command, shallow clone improvements, and atomic push fixes. The maintainers will need to decide whether this s390x-specific behavior requires a fix before finalizing 2.49.0 or can be documented as a known platform limitation.
