Feature request for negated non-wildcard patterns in `.gitignore`.

Joschua Kesper proposes modifying Git's handling of negated patterns in `.gitignore` files to allow simpler syntax for excluding directories while including specific subpaths. The current behavior requires verbose patterns when wanting to track a specific file deep in an otherwise-ignored directory tree (like `foo/bar/baz` while ignoring all of `foo`). The proposal suggests relaxing the restriction that prevents re-including files when a parent directory is excluded, at least for exact (non-wildcard) path matches.

The email notes this wouldn't impact performance (and might even improve it) since exact path matches are unambiguous. The current limitation exists to avoid performance penalties from directory scanning when handling wildcard patterns, but the author argues this optimization isn't needed for literal paths. The change would make `.gitignore` patterns more intuitive for cases where users want to track specific deep paths while ignoring surrounding directories.

Key technical points for future reference:
- Current behavior requires 4 patterns to track `foo/bar/baz` while ignoring `foo`
- Proposed behavior would allow just 2 patterns (`foo` + `!foo/bar/baz`)
- Performance impact claimed neutral/positive since exact paths don't require directory scanning
- Related to `gitignore(5)` documentation about parent directory exclusion
- Implementation would need to modify pattern matching logic while maintaining wildcard behavior

This touches core ignore pattern handling and would require careful implementation to avoid regressions in wildcard cases while adding the new literal path capability. The change seems well-motivated for specific workflows but would need validation that it doesn't introduce edge cases in more complex ignore patterns.
