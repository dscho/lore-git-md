This is a technical follow-up in the ongoing discussion about inconsistent `transfer.hideRefs` behavior between packed and loose refs. Jeff King notes that while loose refs correctly handle prefix matching (requiring a '/' suffix to hide sub-refs), packed refs incorrectly hide all similarly-prefixed refs since commit 59c35fac54. He also raises an important new consideration: how the newer reftable backend handles these exclusions, suggesting this should be examined as part of the solution.

The email doesn't propose new code but advances the technical discussion by identifying another backend that needs to be checked for consistency. This shows the issue may have broader implications across Git's ref storage systems. The thread has now moved from problem identification to solution design, with Jeff King's input helping ensure any fix will consider all major ref backends.
