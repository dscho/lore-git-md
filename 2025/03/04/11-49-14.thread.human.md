This RFC thread explores whether and how Git should support language-specific `.gitignore` files during repository initialization. The discussion began with proposals to bake common language patterns directly into `git init`, but maintainer Junio Hamano firmly rejected this approach, emphasizing Git's neutrality principle and recommending the existing `--template` mechanism instead. 

A new middle-ground proposal from Oleg Taranenko suggests adding a `--only-gitignores` flag to `git init --template` that would selectively copy just the `.gitignore` files from templates while ignoring other components. This aims to simplify the common case of language-specific ignores without requiring users to manage full templates or risk unintended side effects. The proposal includes safeguards against overwriting existing files. While this stays within the template framework Junio endorsed, it still requires core changes to treat `.gitignore` files specially - which may face similar neutrality objections.

The thread currently has two competing technical approaches (predefined templates and Randall Becker's regex-based system) that now appear unlikely to be accepted in their current forms due to maintainer reservations. Key open questions remain about whether any solution can satisfy Git's neutrality principle while meeting user needs, whether `--template` could be enhanced appropriately, or if this functionality belongs in contrib/ instead of core. The discussion suggests this feature faces significant philosophical hurdles in core Git unless proponents can substantially redesign their proposals to externalize all ecosystem-specific logic.
