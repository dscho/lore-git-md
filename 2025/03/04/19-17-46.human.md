This is a feature request proposing changes to how `.gitignore` handles negated patterns in excluded paths. Joschua Kesper identifies a usability pain point where users must write multiple exclusion rules when they want to track specific files in otherwise ignored directories. The current behavior requires verbose patterns to re-include nested files when parent directories are excluded.

The proposal suggests modifying Git to allow simpler negated patterns (like `!foo/bar/baz`) to work even when parent directories are excluded, as long as the patterns match exactly (not using wildcards). The author argues this wouldn't impact performance and might even improve it in some cases by avoiding directory scans.

The change would make `.gitignore` rules more intuitive for cases where users want to track specific files in ignored directories. The email thoughtfully references the current documentation and considers implementation implications, though it doesn't provide a concrete implementation. This seems like a well-motivated quality-of-life improvement that could simplify common ignore patterns while maintaining backward compatibility.
