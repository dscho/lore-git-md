This is a refactoring patch in a series about reflog expiration and maintenance tasks, specifically addressing global state removal in the reflog expiry code. The patch moves default reflog expiry dates from global variables into the `reflog_expire_options` struct, adding new fields (`default_expire_total` and `default_expire_unreachable`) and an initialization macro (`REFLOG_EXPIRE_OPTIONS_INIT`).

Key technical changes:
- Removes `default_reflog_expire` and `default_reflog_expire_unreachable` globals from builtin/reflog.c
- Adds corresponding fields to `struct reflog_expire_options` in reflog.h
- Introduces `REFLOG_EXPIRE_OPTIONS_INIT` macro with default 30/90 day expiry periods
- Updates config callback to store defaults in options struct rather than globals
- Modifies fallback logic to use struct fields instead of global variables

The changes appear clean and focused, with straightforward mechanical transformations that maintain the same behavior while eliminating global state. This aligns with the series' broader goal of making reflog expiration more maintainable and suitable for integration with the maintenance subsystem. The patch follows the pattern established in the thread of incrementally removing global state dependencies.
