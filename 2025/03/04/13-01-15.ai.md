This is a bugfix patch for gitk's external diff functionality regarding file renames. The patch addresses an issue where gitk would fail to properly handle renamed files when launching an external diff tool, whether the user selected the original or renamed file in the interface.

The core problem was that gitk would try to fetch files using their original paths even when they had been renamed between commits. The solution introduces a new `check_for_renames_in_diff` procedure that examines the diff output for "rename from"/"rename to" markers, then uses this information to properly locate both versions of the file. The implementation handles both directions - detecting renames whether the user selects the original or renamed file.

Key technical details:
- Adds regex-based detection of rename markers in the diff output
- Uses Tcl/Tk's text widget search capabilities to locate the rename markers
- Handles both forward ("rename from" first) and backward ("rename to" first) cases
- Maintains the same external diff interface but now with correct file paths
- Removes the GUI toggle option that was present in earlier versions (v1/v2)

The patch appears well-considered, with clear evolution through three versions based on feedback (removing the experimental toggle, improving variable names, and fixing handling for renamed file selection). The change is focused specifically on the external diff functionality and doesn't appear to introduce broader architectural changes.
