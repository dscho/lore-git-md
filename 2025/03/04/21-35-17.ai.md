This is a cover letter for a two-patch bugfix series addressing object freshening behavior in multi-cruft pack scenarios. The series is now in its second iteration with only textual commit message updates since v1.

The first patch simplifies cruft pack aggregation logic in `builtin/repack.c`, replacing complex size-based sorting with direct combination of all small packs when using `--max-cruft-size`. This behavioral change was noticed while working on the main bugfix.

The core fix in the second modifies `want_found_object()` in `builtin/pack-objects.c` to properly handle object freshening when multiple cruft packs exist. The key changes:
- Introduces `ignore_packed_keep_in_core_has_cruft` flag to control mtime comparison behavior
- Preserves objects from non-cruft packs unconditionally
- For cruft pack objects, keeps them only if their mtime is older than the version being packed
- Adds comprehensive test coverage in `t/t7704-repack-cruft.sh`

The series has undergone thorough review with all technical feedback incorporated, including corrected mtime comparison descriptions in commit messages (originally reversed). A new operational question from Patrick Steinhardt raises potential long-term concerns about perpetual repacking cycles from Patch 1's simplification, though this doesn't affect the technical correctness of either patch.

Implementation spans `builtin/repack.c`, `builtin/pack-objects.c`, `packfile.c`, and `packfile.h`, with extensive test coverage. The series appears ready for maintainer consideration pending resolution of the operational concern about long-term repack behavior patterns.
