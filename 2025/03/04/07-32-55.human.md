This is a design discussion in the ongoing thread about adding subject prefix marking for mentoring program participants in `git format-patch`. Patrick Steinhardt weighs in on Junio Hamano's suggestion to use `--rfc=GSoC` rather than the originally proposed `--subject-extra-prefix` flag.

Patrick acknowledges Junio's point about avoiding flag proliferation but notes that `--rfc=GSoC` might not be intuitive for newcomers. He proposes a compromise solution: introducing a more discoverable alias called `--patch-prefix` that would mirror the existing `--subject-prefix` option while maintaining backward compatibility with `--rfc`.

The suggested `--patch-prefix` would allow flexible prefix positioning (before or after "PATCH") and could serve as a more user-friendly frontend to the `--rfc` functionality. Patrick's proposal includes detailed documentation showing how it would work with examples for common cases like WIP patches.

This email moves the discussion forward by offering a concrete alternative that attempts to balance discoverability with interface simplicity. It doesn't resolve the core design question but provides a potential middle path between the original proposal and Junio's suggestion. The technical implementation would likely require less rework than switching to pure `--rfc` parameterization while addressing the discoverability concern.
