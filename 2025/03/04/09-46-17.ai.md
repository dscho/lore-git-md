This is an update in the ongoing reftable library decoupling effort, specifically addressing Windows build and test issues. Patrick Steinhardt responds to Johannes Schindelin's report of Windows-specific problems with the `ps/reftable-sans-compat-util` series, which removes Git-specific dependencies from reftable code for better portability.

Schindelin had noted two key issues: CMake-related breakages (unrelated to the reftable changes) and Windows unit test failures with exit code 127 in MinGW builds (specifically affecting reftable tests). Steinhardt confirms he can reproduce the MinGW-specific reftable test failures, though they don't appear in MSVC builds using Meson. He commits to investigating these MinGW issues further.

The exchange highlights the final integration challenges for this series, particularly around Windows compatibility, which remains the last blocker before promotion. The thread context shows this work is prerequisite for the dependent `ps/reftable-windows-unlink-fix` patch. Technical details mentioned include the `CLAR_TEST_OBJS` and `lib-oid` CMake changes (unrelated to the core issue) and the specific MinGW vs MSVC build behavior divergence.
