Follow-up in meson build system thread confirming resolution of template directory issue.

This email from Steffen Nurpmeso acknowledges Patrick Steinhardt's diagnosis that the missing template directory issue was caused by the distro's use of `-Druntime_prefix=true` in their meson build configuration, not by datadir settings as originally suspected. The thread summary had already noted this root cause and the existence of fix commit bd262d07b65 ("meson: fix exec path with enabled runtime prefix").

Steffen confirms they will pass along the information about either backporting the fix or disabling runtime prefix as solutions. The email includes some additional context about the maintainer's unfamiliarity with meson build system changes and expresses appreciation for the investigation. No new technical information is added about the still-open chroot execution problem mentioned in the thread summary.

Key points maintained from thread context:
- Runtime prefix configuration was the actual cause of template path issue
- Fix exists upstream in commit bd262d07b65
- Two resolution paths available: backport or disable runtime prefix
- Testing limitations for installation-context issues acknowledged
- Chroot execution problem remains unaddressed in this email

The exchange demonstrates successful diagnosis of one of the two originally reported issues, with the distro maintainer now equipped to resolve it in their packaging. The thread's remaining open question about chroot execution failures is not advanced by this message.
