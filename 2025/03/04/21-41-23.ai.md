This is a feature patch proposing a new "prompt-yes" mode for Git's `help.autocorrect` configuration, following up on a previous version that was rebased against master. The change introduces a variant of the existing prompt behavior where the default selection is "Yes" rather than "No" when confirming suggested commands, with non-terminal fallback to immediate execution (unlike the "prompt" mode which falls back to doing nothing).

The technical implementation adds a new `AUTOCORRECT_PROMPT_YES` constant (-5) in help.c, updates config parsing in `parse_autocorrect()`, and modifies prompt handling in `help_unknown_cmd()`. The prompt text changes from "[y/N]" to "[Y/n]" for the new mode. Documentation is updated in help.adoc to describe the new option. The patch acknowledges testing limitations for interactive prompts, noting the test suite currently lacks such tests.

This is the second version of the patch, rebased to account for commits e21bf2c and e4542d8. The thread previously discussed coordination with Scott Chacon's parallel work on boolean values for `help.autocorrect`, but there's been no recent activity - the author is checking if the patch was overlooked or if there's lack of interest. The implementation remains contained to the help subsystem with clear boundaries from other concurrent changes.
