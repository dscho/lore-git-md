This is a follow-up in the libgit-sys build system thread, specifically addressing the symlink and cleanup approach from patch 2/4 in the series. The original patch introduced a `git-src` symlink solution for `cargo package` compatibility but required post-build cleanup that affected the worktree. The author now proposes an alternative approach that would build object files in Cargo's working directory instead of the source tree, which would eliminate most of the cleanup requirements.

Key technical details include the recognition that the current symlink solution forces cleanup on all builds (not just packaging) due to Cargo's build script sandboxing constraints. The proposed alternative would use Cargo's working directory for build artifacts, avoiding worktree pollution at the cost of potentially duplicating source files (though hardlinks might mitigate this). This change would maintain the series' goals of crates.io packaging compatibility while reducing the impact on developer workflows.

The thread context shows this is part of a broader effort to properly package the Rust bindings, with previous discussion around symlink approach and cleanup requirements. This follow-up suggests the author is reconsidering the implementation based on the tradeoffs revealed in the initial solution, indicating the technical approach is still evolving before the v2 submission.
