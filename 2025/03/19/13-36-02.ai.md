Build system patch in a meson optimization series, discussing DEFAULT_* variable handling. Patrick Steinhardt questions the current approach in patch 3/12, which conditionally sets build variables only when meson options differ from hardcoded defaults ('vi', 'man', 'less'). He notes this doesn't change runtime behavior and actually increases hardcoded assumptions. Instead, he proposes eliminating default values from meson_options.txt entirely, which would allow checking for empty strings rather than comparing against hardcoded defaults. This would avoid duplicating default values between meson configuration and source code (editor.c). The discussion suggests the current patch may be an intermediate step toward a cleaner solution that removes redundancy in default value specification. The thread context shows this is part of a larger effort to optimize meson build configuration by eliminating unnecessary compiler definitions.
