This is a bugfix patch in Meet Soni's GSoC series improving reftable error handling. It's the first of three patches in v5 of the series, which has undergone several rounds of review under Patrick Steinhardt's mentorship.

The patch replaces generic -1 error returns in the reftable writer implementation with specific error codes, particularly introducing REFTABLE_ENTRY_TOO_BIG_ERROR for cases where records don't fit in a block. This allows callers to distinguish between temporary block-full conditions (which may be retryable) and other permanent errors. The changes touch core reftable writing functions in block.c, record.c, and their headers.

The implementation looks clean and focused, with thorough updates to both implementation and documentation. The commit message clearly explains the motivation and benefit of the change. This appears to be a well-considered improvement to the reftable subsystem's error handling, building on previous review iterations. The patch maintains backward compatibility while adding more precise error reporting.
