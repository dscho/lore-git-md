This is a refactoring patch series that finalizes the Boolean conversion of the `fetch` field in the refspec API, part of the larger protocol v2 fetch behavior improvements thread.

Elijah Newren provides a positive review of Taylor Blau's 4-patch series that completes the refspec API modernization. The series converts the `fetch` field from using macros (REFSPEC_FETCH/REFSPEC_PUSH) to a simple Boolean, then introduces type-safe initialization functions (`refspec_init_fetch()`/`refspec_init_push()`) and removes transitional wrapper functions. 

Newren notes that while he might have initially chosen an enum approach for the final API design with typed initialization functions makes the Boolean conversion work well. He confirms the series looks good overall, marking another step toward consensus in this long-running thread about refspec handling.

The changes touch several key areas of the codebase including `builtin/fetch.c`, `remote.c`, and `transport-helper.c`, but are purely internal API improvements with no user-visible behavior changes. This appears to be the final piece of the refspec API cleanup that has been discussed and reviewed extensively throughout the thread.
