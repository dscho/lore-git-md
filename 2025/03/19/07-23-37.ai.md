This is a bugfix patch in Martin Ågren's ongoing series refactoring Git's format parsing code. The patch addresses an edge case in padding placeholder parsing where partially valid formats like "%<(10,bad)" could incorrectly apply some formatting parameters while failing to parse others. The fix ensures padding directives only modify the output struct after successful full parsing, preventing partial application of parameters.

The technical change introduces a temporary `struct padding_args` that's only copied to the output on success, initialized with safe defaults. This prevents lingering state from previous valid parses (like "trunc") from affecting subsequent invalid ones. The patch adds a test demonstrating how previously a valid "%<(4,trunc)" could leak its truncation behavior into a following invalid "%<(10,bad)" parse.

Key implementation details: the `parse_padding_placeholder()` function now uses a local `ans` struct to accumulate parsed values before committing them, with all three fields (`flush_type`, `truncate`, `padding`) being written atomically. The test in t4205-log-pretty-formats.sh verifies the fix by checking that invalid placeholders appear verbatim rather than partially applying formatting. This change maintains the series' focus on making the pretty-format parsing more robust while keeping behavior identical for valid inputs.
