Build system patch addressing CSPRNG backend selection in Meson.

Patrick Steinhardt follows up on the established technical consensus about Linux's glibc arc4random implementation being just a getrandom() wrapper, proposing to adjust the Meson build system's detection order to prefer getrandom() over arc4random. The patch modifies meson.build to check for getrandom() first when auto-detecting cryptographic random number generation backends, reflecting the preference established in the thread's technical discussion.

The change aligns Meson's behavior with the Makefile approach where getrandom() is now the recommended choice for Linux. This addresses one of the open items from the thread regarding Meson's suboptimal configuration. The patch maintains all existing functionality while simply reordering the detection sequence to match the project's security and performance preferences.

Key technical details:
- Changes detection order in meson.build's csprng_backend selection
- Keeps all existing backend options (arc4random, arc4random_bsd, getentropy)
- Preserves the same compilation flags (-DHAVE_GETRANDOM etc.)
- Maintains the same auto-detection fallback behavior

This appears to be a straightforward implementation of the thread's conclusions, cleanly applying the agreed-upon preference for getrandom() on Linux systems to the Meson build system. The change is well-contained and follows the established pattern while resolving a known discrepancy between build systems.
