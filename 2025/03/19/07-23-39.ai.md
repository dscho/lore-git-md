This is a refactoring patch in Martin Ågren's series cleaning up Git's pretty-format parsing code. It focuses on the line-wrapping "%w" placeholder handling in pretty.c.

The patch extracts the parsing logic for "%w(width,indent1,indent2)" placeholders into a new `parse_rewrap()` helper function and introduces a `struct rewrap_args` to hold the parsed values (width, indent1, indent2). Previously this parsing was done inline within the large switch statement in `format_commit_one()`. The values are now stored in a dedicated field in `struct format_commit_context` rather than as individual members.

Key technical details:
- Maintains identical behavior for valid inputs while making the code more maintainable
- Uses `size_t` consistently for the wrapping parameters (previously mixed `unsigned long` and `size_t`)
- Adds a zero-initialized `rewrap_reset` constant for clearing state
- The refactoring doesn't fix any bugs but makes the code more readable and separates parsing from application logic
- Part of a larger effort to modularize the pretty-format state machine

This continues the series' pattern of breaking down complex formatting logic into smaller, more focused components. The changes are purely internal - no user-visible behavior is modified. The patch fits well with the preceding padding-related refactors and sets up for future work on the pretty-format system.
