This is a bugfix series for the reftable backend, part of Meet Soni's GSoC project, focusing on proper error code propagation in the block writer. The v4 iteration splits the previous v3 changes into three more focused patches, each targeting specific functions while maintaining the same core improvements.

The series standardizes error handling in the reftable writer to properly distinguish between different failure modes rather than treating all errors as block-full conditions. Key changes include:
- Patch 1 updates `block_writer_add()` to propagate specific error codes rather than converting everything to -1
- Patch 2 modifies `writer_add_record()` to only retry on REFTABLE_ENTRY_TOO_BIG_ERROR while propagating other errors immediately
- Patch 3 (new in v4) applies the same logic to `write_object_record()`

The changes show good attention to review feedback from Patrick Steinhardt, with the v4 splitting the changes into more logical units and restoring an explanatory comment that was accidentally removed.
