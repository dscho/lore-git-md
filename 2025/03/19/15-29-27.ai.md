This is the final patch in Meet Soni's reftable error handling bugfix series (GSoC project under Patrick Steinhardt's mentorship), focusing on refining error propagation in `write_object_record()`. The patch specifically addresses how object record writing handles different error types from `block_writer_add()`.

The key change makes `write_object_record()` properly distinguish between temporary block-full conditions (REFTABLE_ENTRY_TOO_BIG_ERROR) and permanent errors. Previously, it would unconditionally flush and retry on any error, which could mask serious issues like memory allocation failures. Now it only performs the flush/reinit cycle for block-full conditions, immediately propagating other errors. As a last resort for persistent block-full errors, it attempts to write the record with zero offset length.

The implementation adds careful error code checking at each stage of the write attempt sequence, with clear inline documentation explaining the retry logic. This completes the series' goal of robust error handling throughout the reftable writer stack while maintaining all existing functionality for valid inputs. The changes are localized to `writer.c` and build on the standardized error codes introduced in earlier patches.
