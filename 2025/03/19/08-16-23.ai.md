Documentation patch standardizing git-branch formatting (v2)

This is the second patch in a 2-part series updating git-branch documentation and completion scripts. The series builds on Jean-Noël Avila's documentation standardization work, with this patch focusing exclusively on manpage formatting improvements.

The changes convert the git-branch documentation to use consistent formatting conventions:
- Synopses now use proper synopsis blocks with automatic formatting
- Placeholders are marked with _<placeholder>_ instead of <placeholder>
- Keywords and options use `backticks` consistently
- Value enumerations are converted to definition lists for better readability
- Branch naming standardized to _<branch-name>_ pattern

The patch makes no functional changes - it's purely about documentation presentation. The changes affect both git-branch.adoc and branch.adoc config documentation, with 196 lines changed overall (insertions balancing deletions).

- Files modified: Documentation/git-branch.adoc, Documentation/config/branch.adoc
- Builds on existing documentation standards work
- Maintains all existing content while improving formatting
- Follows conventions established in other Git documentation
- No impact on functionality or compatibility
