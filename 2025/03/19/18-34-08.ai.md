This is the core implementation patch in a series adding NUL-delimited output support to `git rev-list`. The patch introduces the `-z` option which changes the command's output format to use NUL bytes as delimiters instead of newlines and spaces, making it more robust for machine parsing of paths containing special characters.

The implementation:
- Adds `-z` option to rev-list that uses NUL delimiters (`\0`) between objects and metadata
- Formats output as `<OID> NUL [path=<path> NUL]` where path information is optional and preserved exactly (no newline truncation)
- Currently only works with `--objects` (other options will extend this)
- Rejects incompatible options like `--graph`, `--left-right`, etc. when used with `-z`
- Includes comprehensive tests verifying basic NUL-delimited output and path handling
- Updates documentation with format specification and examples

Key technical details:
- Introduces `line_term` and `info_term` variables to control delimiters (set to NUL with `-z`)
- Maintains backward compatibility by defaulting to newline/space delimiters
- Uses `path=<path>` token-value syntax for metadata to allow future expansion
- OIDs serve as record markers (they never contain '=' characters)
- Test cases verify both simple OID output and path-included output

This is part of the v4 series which has simplified from earlier versions by focusing solely on output formatting (removing stdin handling) to align with `git log` behavior. The implementation appears clean and thorough, with good test coverage and documentation. The patch follows the preparatory refactoring in earlier patches and sets up the foundation for extending NUL support to other rev-list options in subsequent patches.
