This is a behavior change patch in the cruft pack handling series, modifying how `--max-cruft-size` interacts with pack combination. The patch redefines `--max-cruft-size` to act as a strict override for `--max-pack-size` specifically for cruft packs, rather than its previous behavior of trying to combine packs up to the given size threshold. The key technical changes are:

1. The `collapse_small_cruft_packs()` function is temporarily repurposed to simply list all cruft packs for repacking, ignoring size thresholds (this will be properly reworked in the next patch)
2. Documentation is updated to clarify that `--max-cruft-size` now directly overrides `--max-pack-size` for cruft packs
3. Tests are added/modified to:
   - Mark the old combining behavior test as expected-to-fail
   - Add a new test verifying the strict size limiting behavior
   - Update mtime verification tests to match new expectations

The change is framed as fixing an unintuitive behavior where the original implementation would create packs just under the threshold, leading to repeated repacking of the same objects. This is a breaking change, but justified as correcting a flawed initial design. The patch maintains all existing test coverage while adapting it to the new semantics, with careful attention to transitional states between the old and new behaviors.
