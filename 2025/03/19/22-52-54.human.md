This is a patch in the cruft pack handling series that changes the behavior of `--max-cruft-size` to be a strict override of `--max-pack-size` rather than its previous problematic implementation.

The patch fixes an unintuitive behavior where `--max-cruft-size` would create packs slightly smaller than the specified size, leading to repeated repacking of the same objects. The new approach makes `--max-cruft-size` act as a hard limit on cruft pack sizes, matching user expectations and avoiding wasted I/O from repeated repacking.

Key changes include:
- Rewriting `collapse_small_cruft_packs()` to treat `--max-cruft-size` as a strict size limit
- Updating documentation to clarify the relationship between `--max-cruft-size` and `--max-pack-size`
- Adding a new test case that verifies proper splitting behavior when the size limit is hit
- Marking an existing test that relied on the old behavior as failing (to be fixed in a follow-up)

This is a breaking change to the `--max-cruft-size` behavior, but the author justifies it as correcting an implementation that didn't match its intended purpose. The patch maintains the series' careful approach with thorough test coverage and documentation updates.
