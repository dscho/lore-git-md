This is the final patch in a series implementing NUL-delimited output for `git rev-list`, specifically adding support for the `--missing` option. The patch completes the feature implementation by extending the NUL-delimited format to missing object reporting, maintaining consistency with the structured key-value approach used elsewhere in the series.

The implementation modifies `print_missing_object()` to handle both traditional newline-delimited and new NUL-delimited output formats. In NUL mode, it replaces the '?' prefix with a `missing=yes` token and properly handles path quoting - using raw paths in NUL mode while maintaining quoted paths in traditional mode. The patch includes comprehensive test coverage that verifies correct handling of paths with spaces and special characters.

Key technical details:
- Adds NUL-delimited output support for `--missing=print` and `--missing=print-info`
- Uses same `<OID> NUL [key=value NUL]...` format established in earlier patches
- Maintains backward compatibility with existing newline-delimited output
- Properly handles path quoting differences between output modes
- Includes test case verifying handling of paths with spaces
- Updates documentation to include `--missing` in supported NUL-delimited options
- Maintains option incompatibility checks (disallowing `-z` with certain other options)

The patch follows the series' design principles by:
- Using structured key-value pairs (`missing=yes`, `path=`, `type=`) for metadata
- Making NUL` the sole record delimiter in `-z` mode
- Preserving special characters in paths without escaping
- Maintaining strict separation between input and output handling

This completes the v4 series' goal of providing comprehensive NUL-delimited output support across all `rev-list` output modes while maintaining consistency with `git log`'s output-only `-z` behavior.
