This is a bugfix patch in Meet Soni's reftable error handling series, part of their GSoC project under Patrick Steinhardt's mentorship. It's the first of three patches in v4 of the series, focusing on propagating specific error codes in the reftable block writer implementation.

The patch replaces generic -1 error returns with specific REFTABLE_*_ERROR codes throughout the reftable implementation, particularly in block.c, record.c, and their headers. Key changes include:
- Introducing REFTABLE_ENTRY_TOO_BIG_ERROR for size-related failures
- Properly propagating error codes from encoding functions rather than converting to -1
- Updating function documentation to clarify expected return values
- Maintaining consistent error handling patterns across the codebase

The changes affect core reftable operations like block writing, record encoding, and string handling. The patch preserves all existing functionality while enabling callers to distinguish between different types of failures (like block-full conditions vs other errors). This builds on prior feedback in the thread to standardize error handling in the reftable backend.

Technical details important for future summarization:
- Modified files: reftable/block.c, reftable/block.h, reftable/record.c
- Key error codes: REFTABLE_ENTRY_TOO_BIG_ERROR, preserved original error codes
- Affected functions: block_writer_add(), reftable_encode_key(), various record encoding functions
- Behavior change: Callers can now distinguish block-full conditions from other errors
- Related to ongoing reftable error handling improvements in the series
