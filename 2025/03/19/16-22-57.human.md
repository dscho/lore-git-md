This is the second patch in a 3-part series introducing safer assertion infrastructure in Git. The patch adds CI detection for potentially dangerous assertions with side effects.

The patch introduces a new CI check that scans the codebase for `assert()` calls that might have side effects - a dangerous practice since assertions may be compiled out in production builds. It uses a clever redefinition of `assert()` that causes compilation to fail if side effects are detected, with the error output showing the problematic locations. The check flags 9 existing assertions (shown in the commit message) that involve function calls, though the author notes these appear safe upon inspection.

The implementation adds a `CHECK_ASSERTION_SIDE_EFFECTS` build flag and a new `ci/check-unsafe-assertions.sh` script that runs as part of static analysis. The script parses compiler errors to identify and report problematic assertions, suggesting they be replaced with the new `ASSERT()` macro introduced in patch 1.

This is a well-motivated change that addresses a subtle but important code quality issue. The implementation looks thorough, with clear error reporting and integration into existing CI infrastructure. The patch builds on the foundation from part 1 and has already incorporated feedback from earlier versions of the series.
