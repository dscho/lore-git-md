Bugfix in the reftable writer error handling series. This is the second patch in Meet Soni's v5 series (under Patrick Steinhardt's mentorship) to improve error propagation in the reftable backend.

The patch specifically addresses `writer_add_record()`'s handling of errors from `block_writer_add()`. Previously, the function would treat any non-zero return as a block-full condition, forcing a flush and retry. The new version properly distinguishes between REFTABLE_ENTRY_TOO_BIG_ERROR (which indicates a full block and warrants retry) and other error conditions (like memory or I/O failures) that should propagate immediately.

The change is clean and focused, removing the TODO comment about error code improvements since that work is now completed in earlier patches. The diff shows the logic becoming more precise while actually reducing line count. This continues the series' theme of making reftable error handling more robust and specific, building on the standardized error codes introduced earlier.
