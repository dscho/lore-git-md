Refactoring patch completing the safer assertion infrastructure series.

This is the final patch in Elijah Newren's 3-part series introducing the new `ASSERT()` macro (previously called `BUG_IF_NOT()` in earlier versions) for safer assertions in Git's codebase. The series establishes infrastructure to catch assertions with potential side effects in CI, with this patch converting existing problematic assertions across 7 files to use the new macro.

The changes replace `assert()` calls with `ASSERT()` in cases where the compiler cannot verify the assertion is side-effect free, typically when the assertion contains function calls. Affected areas include merge machinery (merge-ort.c, merge-recursive.c), object storage (object-file.c), parallel checkout, and scalar operations. Each conversion maintains the same logical checks but uses the new safer assertion primitive.

The series has already addressed all prior feedback in v3, including renaming the macro per Taylor Blau's suggestion and fixing script formatting issues noted by Junio Hamano. With consensus reached on the approach and all technical concerns resolved, this final patch completes the mechanical conversion work to make the safer assertion system operational across Git's codebase.
