This is the third version of a series introducing safer assertion infrastructure in Git. The patches add a new `ASSERT()` macro (previously called `BUG_IF_NOT()` in earlier versions) that remains active in production builds, along with CI detection for potentially dangerous assertions that might have side effects.

The series addresses a subtle issue where some of Git's `assert()` calls could contain function calls that might have side effects - a problem that would only surface when assertions are disabled in production builds. The solution involves:

1. Introducing the new `ASSERT()` macro that works like `assert()` but stays active always
2. Adding CI detection that flags assertions containing function calls
3. Converting the 9 problematic assertions found across merge, object storage, and parallel checkout code

The v3 changes respond to feedback by:
- Renaming the macro from `BUG_IF_NOT()` to `ASSERT()`
- Fixing shell script style issues in the CI detection
- Keeping the documentation question open (whether to document this in CodingGuidelines or SubmittingPatches)

The series has received positive technical reviews and appears ready for merging pending final naming confirmation from Junio Hamano. The changes are focused on making Git codebase more robust against subtle assertion-related bugs while maintaining backward compatibility.
