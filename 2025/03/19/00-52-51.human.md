This is a thread wrap-up email in a discussion about changing `git format-patch`'s handling of commit notes. 

Junio C Hamano responds to Tuomas Ahola's acknowledgment that the proposed change to use raw formatting would break critical functionality in patch emails. Hamano notes with some amusement that he had rejected an identical proposal in 2017 for the same reasons, pointing to the historical discussion where he made the same arguments about preserving leading whitespace to prevent patch boundary detection errors.

The email serves as a gentle closing to the thread, with Hamano observing that no new compelling arguments have emerged in 7.5 years to change the current behavior. While he remains open to considering an optional feature if someone presents a strong use case, the discussion appears settled for now. The exchange highlights how Git's email patch infrastructure has specific formatting requirements that constrain how notes can be displayed while maintaining compatibility and safety.
