This is a feature implementation (v4) from Justin Tobler adding NUL-delimited output support to `git rev-list`, now focused solely on output formatting after dropping the stdin handling changes from v3. The series has evolved through multiple rounds of review with input from Patrick Steinhardt, Junio Hamano, Jeff King, and others.

The core change introduces a `-z` option that formats `rev-list` output with NUL delimiters and a consistent key-value syntax for metadata (paths, boundary markers, and missing object info). This replaces the current LF-delimited output that can break when paths contain newlines. The implementation now handles three main cases: basic object listing (`<oid> NUL`), paths with `--objects` (`<oid> NUL path=<path> NUL`), and boundary objects (`<oid> NUL boundary=yes NUL`).

Key technical details include:
- Unified output format using `<token>=<value>` pairs for all metadata
- Careful handling of special characters in paths (no truncation or quoting)
- Rejection of `-z` with incompatible options (though future expansion is possible)
- Test coverage in t6000-rev-list-misc.sh and t6022-rev-list-missing.sh
- Documentation updates in rev-list-options.adoc

The v4 changes drop the stdin handling from v3 to align with other log-family commands, leaving potential future work for explicit `--nul-delimited-input`/`--nul-delimited-output` options. The implementation appears solid with thorough test coverage and has addressed all prior review feedback, including test case ordering fixes noted by Christian Couder. The design consensus favors the current approach of having `-z` control only output formatting while maintaining compatibility with `git log` behavior.
