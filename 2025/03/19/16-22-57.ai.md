This is the second patch in a 3-part series introducing safer assertion infrastructure, focusing on CI detection of problematic assertions with side effects. The patch adds a build-time check that identifies assert() calls that may have side effects, which could lead to different behavior between debug and production builds.

The implementation introduces a CHECK_ASSERTION_SIDE_EFFECTS flag that redefines assert() to trigger linker errors when side effects are present. A new CI script (check-unsafe-assertions.sh) parses these errors and reports the locations of potentially dangerous assertions, suggesting they be replaced with the new ASSERT() macro from patch 1. The script handles the compiler output to present readable error messages showing the file locations and surrounding code of flagged assertions.

Key technical components:
- Makefile addition for CHECK_ASSERTION_SIDE_EFFECTS flag)
- New check-unsafe-assertions.sh script with error parsing logic
- Assertion redefinition technique in git-compat-util.h
- Integration into run-static-analysis.sh CI workflow

The patch identifies 9 existing assertions (across merge-ort.c, merge-recursive.c, object-file.c, and other files) that involve function calls too complex for the compiler to verify as side-effect-free. The error reporting is designed to work iteratively - fixing some assertions may reveal others in subsequent runs.

This builds on the foundation from patch 1 (the ASSERT() macro) and addresses the CI aspect of the overall safety improvement. The implementation appears thorough, with clear error reporting and integration into existing CI infrastructure. The technique used comes from Stack Overflow contributor Bruno De Fraine, who has placed it in the public domain.
