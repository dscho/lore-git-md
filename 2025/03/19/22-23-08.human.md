Build system refinement for libgit-sys Rust crate. This is a follow-up to the second patch in a series addressing packaging challenges for Git's Rust integration.

Josh Steadmon provides an update on the symlink-based solution for building libgit-sys with `cargo package`. The original approach created a `git-src` symlink and required cleaning the worktree after builds, which had drawbacks. He's now working on an improved version that would build object files in Cargo's working directory instead of the source tree, avoiding the cleanup requirement.

The new approach would maintain the same goal - enabling proper packaging while respecting crates.io constraints - but with better performance characteristics by eliminating the need to clean the worktree after each build. This responds to the inherent limitations of the initial solution where builds always triggered cleanup, regardless of whether they were for development (`cargo build`) or packaging (`cargo package`).

The message suggests this is still in progress, with a v2 series expected soon. The change appears focused on build system ergonomics rather than altering the fundamental packaging strategy or Rust/C integration approach established in the initial series.
