This is the second patch in Zheng Yuting's GSoC project to improve SMTP error handling in `git-send-email.perl`, implementing the promised status code parsing after the first patch established the error capture framework.

The patch adds RFC 5321-compliant SMTP status code parsing to distinguish between temporary (4xx) and permanent (5xx) errors, with different handling for each. Temporary errors will allow retries (returning 1) while permanent errors fail immediately (returning 0). The implementation uses regex pattern matching to extract 3-digit status codes from error messages, with appropriate warning messages for each case. Unrecognized codes are treated as permanent errors.

The changes are focused on the `smtp_auth_maybe` function, adding 24 lines while removing 3. The implementation maintains the existing return value convention (1 for success/retry, 0 for failure) while adding the new status-aware logic. Error messages now include the specific status code when available, improving debugging visibility.

This completes the two-patch series that restructures SMTP authentication error handling in `git-send-email.perl`, with all review feedback from previous iterations addressed. The changes are backward-compatible and properly documented with RFC references. The series is now ready for merging after a thorough review process spanning five versions.
