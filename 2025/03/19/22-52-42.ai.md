This is a cover letter for a patch series introducing a new `--combine-cruft-below-size` option for `git repack`, part of the ongoing cruft pack handling improvements. The series replaces the problematic `--max-cruft-size` behavior with clearer semantics for combining small cruft packs while leaving larger ones untouched.

The v2 reroll contains no functional changes from v1, only documentation and commit message tweaks in response to review feedback. Key changes include:
- More precise wording about large cruft pack handling ("leaves alone" instead of "prohibits")
- Explicit documentation that size parameters accept k/m/g suffixes (though implementation remains unchanged)
- Clarification that `--max-cruft-size` can still be used alongside the new option for size limiting

The series follows a careful structure with test cleanups first (moving repack tests to t7704, clarifying test wording, consolidating test helpers), then modifies `--max-cruft-size` behavior in patch 4 before introducing the new `--combine-cruft-below-size` in patch 5. This staged approach makes the transition easier to review.

Technical details:
- New option combines cruft packs below given size while preserving larger ones
- Resulting combined packs may exceed threshold size (intentional design)
- Maintains compatibility with `--max-cruft-size` for output size limiting
- Documentation now explicitly notes size parameter units (bytes with k/m/g suffixes)

The series appears well-considered with thorough test coverage and documentation. The v2 changes address previous review feedback while maintaining the core technical approach. The staged implementation and clear commit messages make the behavior change easier to evaluate.
