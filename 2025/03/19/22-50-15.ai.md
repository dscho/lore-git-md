This is the final patch in a series improving cruft pack handling in `git repack`, transitioning from the problematic `--max-cruft-size` behavior to clearer semantics via the new `--combine-cruft-below-size` option. The patch implements the core behavior change while responding to documentation feedback from Elijah Newren and Junio C Hamano.

The key technical change replaces `collapse_small_cruft_packs()` with `combine_small_cruft_packs()` in builtin/repack.c, modifying `write_cruft_pack()` to accept the new size parameter. The new behavior aggregates all cruft packs smaller than the specified threshold (potentially creating packs larger than the threshold) while leaving larger packs untouched. This differs from the old `--max-cruft-size` behavior which would build up packs until hitting the threshold.

Taylor Blau addresses Elijah Newren's documentation feedback by:
- Changing "prohibits repacking" to "leaves alone" for large packs
- Clarifying that `--max-cruft-size` can be used together with the new option (not instead of it)
- Opting not to document specific size ratios between the options, wanting to discourage overuse of size-limiting flags

The implementation remains unchanged from previous reviews, with only documentation tweaks in response to feedback. The patch maintains test coverage while updating test names and comments to reflect the new behavior. This completes the series' transition to more intuitive cruft pack handling while preserving the original goal of avoiding expensive repacks of large cruft packs.
