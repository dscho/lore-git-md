This is a build system patch addressing the ongoing CSPRNG backend selection discussion. Patrick Steinhardt proposes adjusting the Meson build system's detection order to prioritize `getrandom` over `arc4random` on Linux, following the technical consensus that glibc's `arc4random` is just a wrapper for `getrandom` with no benefits.

The change would make Meson's behavior match the Makefile's documented preference, though as noted in the thread, the current suboptimal Meson configuration isn't critical since both methods ultimately use the same Linux kernel CSPRNG. The patch cleanly swaps the detection order of these two methods while maintaining all other fallback logic.

This appears to be a straightforward technical follow-up to the earlier discussion, implementing one of the remaining open items (Meson build system correction) that emerged from the CSPRNG analysis. The change is well-motivated by the established technical understanding of Linux's `arc4random` implementation.
