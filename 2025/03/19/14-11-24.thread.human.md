This thread explores potential enhancements to `git bisect`, starting with an RFC proposing two features: worktree support for side-by-side debugging of "good" and "bad" states, and a manual "try" command for testing hunches. The original suggestion envisioned built-in worktree management with a specific two-worktree syntax.

Junio Hamano has responded with a more conservative approach, noting that `git bisect --no-checkout` already provides the necessary foundation for this workflow. He suggests users could manage their own worktrees while letting bisect handle commit selection, potentially making new core features unnecessary. The response questions whether limiting to two worktrees is ideal when the existing approach could support any number, and notes that third-party tools could implement this today.

The discussion now centers on whether the original proposal's tighter integration would provide enough added value to justify new core functionality, or if the existing `--no-checkout` method sufficiently enables the debugging workflows described. No patches have been submitted yet as the design direction remains under discussion.
