This thread investigates a regression where Git's "Using 'master' as name for initial branch" hint message appears during bundle clone operations despite suppression flags (GIT_ADVICE=0 and --quiet). The reporter initially narrowed the regression to between Git 2.44.1 and 2.45.1, with Elijah Newren identifying the exact problematic commit (199f44cb2ead) that modified clone's remote helper interaction.

Justin Tobler has now provided a detailed technical analysis of the root cause. The issue stems from when the default branch name is first computed during clone operations. The regression changed this timing so that the computation now happens in `guess_remote_head()` (without suppression) rather than earlier in `create_reference_database()` (with suppression). Since the result is cached after first computation, this timing difference determines whether advice appears. For bundle clones specifically, the transport falls back to `guess_remote_head()` which computes the default branch name without respecting the quiet flags.

Tobler proposes modifying `guess_remote_head()` to support quiet operation by configuring the underlying `repo_default_branch_name()` call. This targeted fix would restore the pre-regression behavior while maintaining the functionality added in the problematic commit.
