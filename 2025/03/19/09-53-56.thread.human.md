This thread addresses a regression where Git would show unwanted advice about the default branch name ("hint: Using 'master' as the name for the initial branch") during bundle clone operations, even when suppression flags like GIT_ADVICE=0 or --quiet were used. The issue stemmed from changes in how clone interacts with remote helpers.

Justin Tobler has led the fix through multiple iterations, now at version 3, with input from Phillip Wood and Junio Hamano. The solution has two main parts: immediate fixes for clone operations and architectural improvements to advice handling.

For clone operations, the patches introduce new flags (REMOTE_GUESS_HEAD_QUIET) to properly suppress the advice across all clone code paths, including special cases like --single-branch clones and bundle operations. The implementation includes comprehensive test coverage to catch these edge cases.

The architectural improvement, which just received its v3 update, makes the default branch name advice respect Git's standard advice control mechanisms. It adds ADVICE_DEFAULT_BRANCH_NAME to the advice system, allowing suppression via config (advice.defaultBranchName=false) or command line (--no-advice) while maintaining existing behavior when enabled. This addresses a long-standing limitation where previously only setting init.defaultBranch could silence the hint.

The series appears complete with all known edge cases addressed, including newly discovered interactions with --single-branch. The design discussion has converged on maintaining explicit flags for clone operations while using standard advice mechanisms elsewhere. With Junio's technical approval of the core approach, the patches seem ready for final review and potential merging.
