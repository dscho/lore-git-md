This thread addresses a regression where Git's default branch name advice ("Using 'master' as the initial branch") appeared during bundle operations despite suppression flags (GIT_ADVICE=0/--quiet). Justin Tobler has led the fix with input from Junio Hamano, Patrick Steinhardt, and Phillip Wood.

The solution has evolved into three parts: immediate clone-specific fixes, architectural improvements to the advice system, and comprehensive test coverage. The latest patch (v2 3/3) completes the architectural work by introducing ADVICE_DEFAULT_BRANCH_NAME and making repo_default_branch_name() respect suppression through advise_if_enabled(). This ensures consistent behavior across all code paths, particularly important for scripts and automation.

Key technical changes include converting parameters to bitmask flags (following Git conventions), adding specific test cases for bundle clones, and addressing timing issues in refdb initialization. The solution maintains backward compatibility while fixing both the immediate regression and underlying inconsistency in advice handling.

The thread shows consensus that default branch name advice should never appear in clone scenarios regardless of config, and that this three-pronged approach properly restores pre-regression behavior. Remaining work includes auditing other advise() calls that might need conversion and verifying all affected call sites in the fetch/remote code.
