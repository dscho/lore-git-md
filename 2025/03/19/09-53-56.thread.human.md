This thread addresses a regression where Git shows unwanted advice about default branch names ("hint: Using 'master' as the name for the initial branch") during clone operations, even when suppression flags like GIT_ADVICE=0 or --quiet are used. The issue stems from changes in remote helper interactions introduced by commit 199f44cb2ead.

Justin Tobler has been leading the fix with input from Phillip Wood and Junio Hamano. The solution has evolved through multiple versions to handle both the immediate regression and broader architectural improvements to advice handling. The current approach:

1. Fixes the clone-specific behavior by modifying guess_remote_head() to support advice suppression through explicit flags, with test coverage added for bundle clone cases. There's ongoing discussion about whether to make this behavior implicit when all=false.

2. Improves the architecture by introducing ADVICE_DEFAULT_BRANCH_NAME as a proper advice type that respects standard suppression mechanisms (both --no-advice flag and config settings), while ensuring clone operations never show this advice regardless of configuration.

In the latest exchange, Phillip Wood identified another case where the advice appears during --single-branch clones, including a scenario where bundle clones show the message twice. Justin has confirmed this and plans to extend the suppression to wanted_peer_refs() in an upcoming version. The thread demonstrates careful attention to edge cases as the solution evolves, with all participants aligned on the goal of completely eliminating this advice during clones while maintaining proper advice handling architecture.
