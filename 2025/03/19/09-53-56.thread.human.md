This thread addresses a regression where Git's advice messages (specifically the "hint: Using 'master' as the name for the initial branch" notice) were appearing during bundle clone operations despite users explicitly suppressing advice through GIT_ADVICE=0 or --quiet flags. The issue was introduced in Git 2.45.1 by changes to the clone's remote helper interaction logic.

Justin Tobler identified the root cause and proposed a two-patch solution: first modifying the underlying `guess_remote_head()` function to support advice suppression, then updating clone.c to properly pass the suppression flag. Patrick Steinhardt reviewed the series and suggested improving the API design by converting boolean parameters to a flags field - a change that would require a preparatory refactoring commit but follows Git's established patterns.

In the latest exchange, Patrick has reviewed the second patch (which specifically fixes the bundle clone case) and confirmed the technical approach is sound. He notes that since users can't control the branch name during clone operations, the advice message serves no purpose in this context anyway. While generally approving the patch, Patrick suggests two non-critical follow-ups: potentially using `advise_if_enabled()` and considering additional test coverage. These appear to be optional improvements rather than blockers.

The thread shows consensus on both the problem and solution, with only minor API design considerations remaining. The changes maintain all existing functionality while properly respecting user requests for suppressed output. With Patrick's review feedback addressed, the patches appear ready for maintainer consideration, particularly from those familiar with clone behavior and remote helper interactions.
