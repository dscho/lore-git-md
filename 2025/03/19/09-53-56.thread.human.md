This thread addresses a regression where Git incorrectly shows default branch name advice ("hint: Using 'master' as the name for the initial branch") during bundle clone operations, even when suppression flags like GIT_ADVICE=0 or --quiet are used. The issue stems from commit 199f44cb2ead which changed when the default branch name is computed during cloning.

Justin Tobler has developed a comprehensive fix with three components: immediate clone fixes, architectural improvements to advice suppression, and specific handling of the bundle case. The solution introduces new flag-based controls (REMOTE_GUESS_HEAD_QUIET) to properly suppress advice messages and makes the default branch name advice globally suppressible via --no-advice.

The latest patch specifically handles the bundle clone scenario, adding test coverage and using the new flag system. Reviewers including Phillip Wood and Junio Hamano have confirmed the technical direction - that default branch advice should never appear during clones regardless of configuration. The solution maintains backward compatibility while fixing both the immediate regression and underlying architectural inconsistencies in Git's advice system.

The thread shows strong consensus on the approach, with the v3 series incorporating naming feedback to follow Git conventions. Remaining work includes auditing other advice calls that might need similar treatment and verifying all affected call sites in the fetch/remote code.
