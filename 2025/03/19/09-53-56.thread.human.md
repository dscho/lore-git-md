This thread began as a bug report about unexpected advice messages persisting during clone operations despite suppression flags (GIT_ADVICE=0 and --quiet), specifically the "hint: Using 'master'..." message when cloning bundle files. The regression was traced to changes in Git 2.45.1 that modified clone's remote helper interaction.

Justin Tobler proposed a two-patch solution to fix the clone-specific issue, which has evolved through review feedback from Patrick Steinhardt and others. The current approach involves modifying guess_remote_head() to properly handle advice suppression and updating clone.c to pass the correct flags. Justin has committed to additional refinements including converting direct advise() calls to advise_if_enabled() and adding test coverage.

The discussion has now expanded to address Phillip Wood's observation about a deeper architectural issue - that direct advise() calls bypass Git's global advice suppression mechanisms entirely, contrary to what the documentation suggests. Justin acknowledges this inconsistency and indicates he will expand his fix to make the default branch name advice respect --no-advice in all cases, not just during clone operations. This represents a shift from merely patching the immediate regression to addressing the underlying design flaw in Git's advice system.

The thread now has two parallel tracks: the nearly-complete clone-specific fix (awaiting final test coverage and implementation refinements) and the newly-identified broader work to make all advice calls properly respect suppression mechanisms. Justin appears to be taking ownership of both aspects, with the solution evolving from a targeted bugfix into a more comprehensive improvement of Git's advice handling behavior.
