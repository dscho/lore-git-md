This is the second and final patch in Zheng Yuting's GSoC project to improve SMTP error handling in `git send-email`. The patch implements RFC 5321-compliant status code parsing for SMTP authentication errors, building on the error capture infrastructure from the first patch.

The change introduces fine-grained handling of SMTP status codes, distinguishing between temporary errors (4xx codes, which allow retries), permanent errors (5xx codes, which fail immediately), and unrecognized codes (also treated as permanent). The implementation uses regex to extract status codes from error messages and adds appropriate warning messages for each case. The patch maintains backward compatibility while adding this new functionality.

The changes are well-contained to the `smtp_auth_maybe` function and include clear documentation references to RFC 5321. This completes the project's goal of making SMTP error handling more robust and standards-compliant. The patch series has gone through five iterations of review with all feedback addressed, and is now ready for merging.
