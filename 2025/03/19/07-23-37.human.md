Bugfix in Martin Ågren's pretty-format refactoring series. This fourth patch addresses a subtle issue where partially parsed padding directives ("%<" and "%>") could leave the formatting state in an inconsistent state. The fix ensures padding parameters are only applied after successful parsing, preventing lingering state from previous valid placeholders from affecting subsequent invalid ones.

The change introduces a temporary `struct padding_args` to collect parsed values, only copying them to the output struct after all parsing succeeds. This makes the code more robust against partial parsing failures while maintaining the same behavior for valid inputs. A new case in t4205 demonstrates how previously a valid "%<(4,trunc)" could incorrectly influence the handling of a following invalid "%<(10,bad)" placeholder.
