Feature: New userdiff driver for gitconfig files.

This patch (1/2 in a series) adds syntax highlighting support for gitconfig files in `git diff` and `git log -p` output. The implementation introduces a builtin userdiff driver that recognizes gitconfig section headers like `[section]` and `[section "subsection"]` as function names, making config file diffs more readable - particularly useful for dotfiles repositories where config files are frequently versioned.

The regex patterns follow Git's documented config file syntax rules: section names allow alphanumerics, hyphens and dots, while subsections can contain any characters except newlines. The word regex is kept simple to match any non-whitespace sequence. The implementation follows Git's existing userdiff driver conventions and appears complete for the main syntax cases.

The accompanying test patch (not shown here) reportedly covers basic cases including indented and unindented sections. This looks like a well-scoped, clearly motivated addition that should improve diff readability for a common file type without introducing complexity. The commit message thoroughly documents the syntax rules being implemented.
