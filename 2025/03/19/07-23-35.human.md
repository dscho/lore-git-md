This is the second patch in Martin Ågren's 8-part refactoring series for Git's pretty-format parsing code. It focuses on reducing code duplication in the color parsing logic within `pretty.c`.

The patch simplifies an if-else chain that handles color formatting options ("auto," and "always,") by restructuring the control flow. The original code had nearly identical blocks for the "auto," case and the default case. The new version makes the default case handle both scenarios more cleanly by opportunistically consuming the "auto," prefix when present.

The change is small (4 lines removed, 2 added) but improves code clarity by eliminating the duplicated logic while maintaining the same behavior. The commit message explains the tradeoffs considered (like not going for the most minimal "golfed" version) and how the change makes the code easier to verify as correct at a glance.

This continues the series' theme of cleaning up the pretty-format code with straightforward, non-controversial improvements that don't change functionality. The patch touches the same test file as the rest of the series but doesn't require test modifications since it's purely a code organization change.
