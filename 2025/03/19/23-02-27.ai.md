Performance optimization discussion in MIDX bitmap series.

This email from Taylor Blau responds to Jeff King's concern about using `ewah_or_iterator` unconditionally for type bitmap operations in patch 12/13 of the MIDX bitmap series. The change introduces an extra allocation and function call per iteration, which Jeff wondered might impact performance in tight loops.

Taylor provides benchmark results comparing the current release against a build with this change, showing no statistically significant difference in performance when running `git pack-objects` with bitmap indexing. The measurements show nearly identical timing (1.715s vs 1.712s mean), well within the margin of error, confirming the change doesn't introduce measurable overhead.

Key technical details:
- Maintains the switch to `ewah_or_iterator` for type bitmap operations
- Benchmarks use `git pack-objects --use-bitmap-index` as a real-world test case
- Comparison between stock Git and patched version shows no regression
- Confirms the implementation choice is safe from a performance perspective

This concludes the performance discussion for this patch, with no changes needed to the implementation. The series remains on track with all technical concerns addressed.
