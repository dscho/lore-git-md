This is a documentation and shell completion fix series (v2) that standardizes git-branch documentation formatting while addressing a completion script regression. The two-patch series builds on previous discussion about portability and testing improvements.

The first patch updates `generate-configlist.sh` to handle backtick-wrapped option names in documentation, now using a more portable ERE-based solution (addressing Junio's feedback from v1). The changes simplify the script into a single `sed` command while maintaining the same functionality. This fixes completion breakage that was caught by `t9902` tests when working with git-branch documentation.

The second patch applies Git's newer documentation standards to the git-branch man pages, including:
- Converting synopsis to use `[` blocks
- Standardizing placeholder notation
- Reorganizing option value lists into definition lists
- Normalizing branch naming conventions
- Removing redundant information while preserving content

Junio has already approved the documentation changes as "nicely done" in previous discussion. The completion script fix has been simplified and made more portable since v1, though testing coverage for config list generation remains an identified gap that may need follow-up work. The series shows careful attention to both documentation standards and practical tooling concerns.
