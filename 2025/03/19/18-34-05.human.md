This is a feature implementation for `git rev-list` that introduces NUL-delimited output format, now at v4 with some design refinements from previous iterations.

Justin Tobler's series adds machine-friendly NUL-delimited output to `git rev-list`, addressing the longstanding issue of parsing output containing special characters. The key change in v4 is that the `-z` option now only affects output delimiters (not input), aligning with other Git commands' behavior. The implementation provides a consistent `<OID> NUL [<token>=<value> NUL]...` format that handles object paths, boundary markers, and missing objects without truncation or encoding issues.

The series has evolved through review feedback, with v4 specifically:
- Dropping the stdin NUL-delimiting feature to match `git log` behavior
- Clarifying test variable names and commit chronology in assertions
- Maintaining the unified key-value format for all metadata

The patches are well-structured, with preparatory refactors first (patches 1-2), core NUL output (patch 3), then boundary (patch 4) and missing object (patch 5) support. Test coverage appears thorough, checking edge cases with special characters. The design discussion has reached consensus on keeping input/output delimiter control separate, with potential future options (`--nul-delimited-input/output`) to be added later.

This looks ready for inclusion - it solves a real parsing pain point with a clean implementation that follows Git's existing patterns. The v4 changes show responsiveness to review feedback while maintaining the core functionality.
