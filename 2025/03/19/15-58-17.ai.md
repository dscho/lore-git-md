This is a design discussion follow-up in the NUL-delimited output format series for `git rev-list`. Justin Tobler responds to Junio Hamano's preference for separate `--nul-delimited-input` and `--nul-delimited-output` options rather than a combined `--nul-delimited={all,input,output}` syntax.

Justin concedes that separate options are indeed clearer for plumbing commands, agreeing with Junio's design principle about keeping independent features orthogonal. He plans to modify the next version to make `-z` affect only output (matching `git log` behavior) and proposes adding NUL-delimited input support later via explicit `--nul-delimited-input`/`--nul-delimited-output` options.

The email also notes an inconsistency in Git's existing delimiter control options, observing that `git commit` uses `--null` as an alias for `-z`. Justin suggests standardizing on `--nul-delimited-{input,output}` as a more consistent naming scheme moving forward, though this would be a separate effort from the current series.

Key technical points for future reference:
- Current implementation supports both combined and separate input/output modes
- `-z` will now only control output delimiters (matching `git log`)
- Proposed future options: `--nul-delimited-input` and `--nul-delimited-output`
- Related command inconsistency noted: `git commit --null` vs `-z`
- Design decision settled: separate orthogonal options preferred over combined syntax

This represents the resolution of the last major design question in the series, with Justin accepting Junio's maintainer guidance on the interface design while noting an opportunity for broader consistency in Git's delimiter control options.
