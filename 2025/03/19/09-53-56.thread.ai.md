Bug report and regression investigation about unexpected hint messages persisting despite suppression flags (GIT_ADVICE=0 and --quiet) during clone operations, specifically the "hint: Using 'master' as the name for the initial branch" message when cloning bundle files. The regression was introduced between Git 2.44.1 and 2.45.1 by commit 199f44cb2ead ("builtin/clone: allow remote helpers to detect repo"), which modified clone's remote helper interaction logic and inadvertently bypassed advice suppression.

Justin Tobler's analysis identified the precise mechanism: the regression occurs when `repo_default_branch_name()` caches its result during clone operations, with the computation moving from `create_reference_database()` (with suppressed advice) to `guess_remote_head()` (without suppression). For bundle clones where HEAD can't be determined automatically, this causes unwanted hint messages despite suppression flags.

The complete solution comes in a two-patch series:

   - Function signature change in remote.h adding the `quiet` parameter

   - Quiet flag propagation to `repo_default_branch_name()` in remote.c
   - Unchanged default behavior (quiet=0) for existing callers

2. The second patch completes the fix by updating `builtin/clone.c` to pass the quiet flag (1) to `guess_remote_head()` when advice suppression is active. This specifically targets the bundle clone case where HEAD can't be determined automatically, ensuring the "hint: Using 'master'..." message is properly suppressed when requested via GIT_ADVICE=0 or --quiet flags. The change is minimal (a single parameter change) but effectively restores pre-regression behavior while maintaining all other clone functionality.
