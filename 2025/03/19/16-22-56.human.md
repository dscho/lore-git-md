This is the first patch in a series introducing safer assertion infrastructure to Git's codebase. The patch adds a new `ASSERT()` macro that remains active even in production builds (unlike the standard `assert()` which gets compiled out with `NDEBUG`), making it safe to use with expressions that have side effects.

The implementation is straightforward - it's a simple wrapper that calls `BUG()` when the assertion fails, with the same file/line reporting as other Git error mechanisms. The commit message notes this will be used to convert existing `assert()` calls that can't be proven side-effect-free, though those conversions come in later patches.

This foundational change has already gone through several rounds of review (v3), with all feedback addressed (including renaming from the original `BUG_IF_NOT()` proposal to the now-finalized `ASSERT()` name). The technical approach appears sound, with reviewers having confirmed it works under C99 and the licensing concerns resolved. The patch is small and focused, doing just one thing well - introducing the macro that the rest of the series will build upon.
