Error handling refinement in reftable writer implementation. This is the second patch in Meet Soni's v4 series to standardize error propagation in the reftable writer, part of their GSoC project under Patrick Steinhardt's mentorship.

The patch modifies `writer_add_record()` in reftable/writer.c to properly distinguish between different types of errors from `block_writer_add()`. Previously, the function treated all non-zero returns as block-full conditions, forcing a flush and retry. The new version specifically checks for `REFTABLE_ENTRY_TOO_BIG_ERROR` (introduced in patch 1/3) to trigger the block-full handling path, while propagating other errors immediately. This change removes the previous assumption that all failures indicate a full block, allowing proper handling of memory allocation or I/O errors. The diff shows the simplified logic flow and removal of an outdated TODO comment about error code improvements (now addressed by the series). The patch maintains the existing block-full retry behavior while making the error handling more precise and transparent.
