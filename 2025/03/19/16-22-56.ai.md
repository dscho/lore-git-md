Refactoring introducing a safer assertion macro for Git's codebase. This is the first patch in a 3-part series that has already undergone significant review and iteration (now at v3).

The patch introduces a new `ASSERT()` macro in git-compat-util.h that maintains assertion checking even in production builds (unlike standard `assert()` which gets compiled out with NDEBUG). The macro triggers a `BUG()` call when assertions fail, ensuring side effects in assertion expressions remain safe. The implementation is minimal - just 2 lines added to the header file.

Key technical details for future reference:
- Macro name settled as `ASSERT()` after earlier `BUG_IF_NOT()` proposal
- Behavior matches standard assert() but always active
- Fails via existing BUG() infrastructure
- First of several conversions planned (merge and object storage subsystems mentioned in thread)

This foundational change enables the safer assertion conversions in subsequent patches. The thread context shows this version has addressed all prior feedback (naming, formatting, licensing) and has received positive reviews from multiple core contributors. The macro definition itself appears straightforward with no obvious technical concerns.
