Documentation patch standardizing git-branch manpage formatting (v2)

This is the second patch in a series addressing shell completion issues while standardizing Git documentation. It focuses exclusively on formatting improvements to the git-branch manpage, building on Jean-Noël Avila's ongoing documentation standardization work.

The changes are purely presentational, converting the git-branch documentation to use consistent formatting:
- Switches synopsis to use the new synopsis block format that automatically styles placeholders and keywords
- Standardizes on _<placeholder>_ notation instead of <placeholder>
- Uses backticks consistently for commands, options, and config keys
- Converts enumerated values into definition lists for better readability
- Updates branch naming to use _<branch-name>_ consistently

The patch makes no functional changes - it's all about making the documentation more consistent and machine-parseable. The changes are substantial (196 insertions/deletions across two files) but focused entirely on formatting. 

This appears to be a well-executed documentation improvement that follows the project's documentation standards. The patch has already received maintainer approval in previous iterations, with this version adding further refinements to the formatting approach. It's part of a coordinated effort to make Git's documentation more consistent and maintainable.
