Feature: new builtin userdiff driver for gitconfig files.

This patch implements a userdiff driver for gitconfig files to improve syntax highlighting in diffs. The driver matches section headers (like `[section]`) and subsection headers (like `[section "subsection"]`) as function names, using regex patterns that follow Git's config file syntax rules exactly. The word regex is kept simple to match any non-whitespace sequence.

The implementation is straightforward - just 4 lines added to userdiff.c to define the patterns. The commit message clearly explains the syntax being matched and references the config file format documentation. This appears to be a well-scoped, self-contained addition that follows Git's existing userdiff driver patterns. The accompanying test patch (2/2) will verify the behavior.

Key technical details for future reference: The funcname regex handles both basic sections (`^\[[a-zA-Z0-9]+\]`) and subsections (`^\[[a-zA-Z0-9]+[ \t]+\".+\"\]$`), while word_regex is the simple `[^ \t]+`. The change is minimal and focused, touching only userdiff.c with no config or command changes needed. This should be particularly when diffing dotfiles repositories containing gitconfigs.
