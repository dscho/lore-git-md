This is the final patch in a series improving cruft pack handling in `git repack`, introducing a new `--combine-cruft-below-size` option to replace the problematic behavior of `--max-cruft-size`. The change provides clearer semantics for managing cruft packs in repositories with many unreachable objects.

The patch introduces explicit control over cruft pack combination - the new flag aggregates all cruft packs smaller than a specified threshold while leaving larger packs untouched. This differs from the old `--max-cruft-size` behavior which would build up packs until hitting a size threshold. The implementation includes thorough test updates and careful handling of edge cases.

Key technical aspects include:
- New `combine_small_cruft_packs()` function implementing the selective combination logic
- Updated `write_cruft_pack()` to accept the new size parameter
- Clear documentation of byte-based sizing (with k/m/g suffixes)
- Test cases verifying the new combination behavior while maintaining mtime preservation

The change appears well-considered, with Taylor Blau having incorporated feedback from Elijah Newren and Junio C Hamano about documentation clarity. The staged approach from earlier preparatory patches pays off here with clean test integration. This completes the series' goal of separating the concerns of pack size limiting from selective combination.
