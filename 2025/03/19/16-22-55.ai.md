This is the v3 cover letter for a series introducing safer assertion infrastructure in Git. The series adds a new `ASSERT()` macro (previously called `BUG_IF_NOT()` in earlier versions) that remains active in production builds, along with CI detection for potentially dangerous assertions containing side effects.

The key changes in v3:
1. Renamed the macro from `BUG_IF_NOT()` to `ASSERT()` following Taylor Blau's preference
2. Fixed shell script formatting issues (indentation, multi-line pipes) in the CI detection script
3. Updated all references to the new macro name across the series

The series now has:
- Core assertion macro in git-compat-util.h
- CI detection via check-unsafe-assertions.sh that identifies assertions with potential side effects
- Conversion of 9 problematic assertions across merge machinery, object storage, and parallel checkout subsystems

Technical approach uses a compiler/linker hack to detect assertions with function calls by redefining `assert()` to include an undefined symbol. The CI job flags these cases and suggests converting them to the new `ASSERT()` macro.

The cover letter indicates the naming discussion may be settled (favoring `ASSERT()`), with only minor script formatting feedback from Junio Hamano potentially remaining. The series appears ready for merging pending final review, with technical soundness confirmed by brian m. carlson and Reviewed-by from Taylor Blau. The merge and object storage subsystems are most affected by the changes.
