This is a bugfix patch in Meet Soni's reftable error handling series (part of their GSoC project). The patch focuses on improving error propagation in the reftable block writer implementation.

The key change replaces generic -1 error returns with specific REFTABLE_* error codes throughout the reftable writer stack (block.c, record.c). The main new error code introduced is REFTABLE_ENTRY_TOO_BIG_ERROR for cases where records don't fit in blocks, while preserving other error codes that may originate from lower-level functions. The changes affect core encoding routines like block_writer_add(), reftable_record_encode(), and various helper functions that handle string and varint encoding.

The patch maintains all existing functionality while making error handling more precise. Callers can now distinguish between temporary block-full conditions (which may be retryable) and other error conditions. Documentation comments are updated to clarify the new error return behavior. The changes are mechanical but thorough, touching multiple encoding paths while maintaining consistent behavior for valid inputs.

This is the first of three patches in v5 of the series, building on previous iterations that established the core error handling framework. The implementation appears clean and well-tested, with comprehensive coverage of error paths across different record types (refs, objects, logs). The changes align with the series' goal of robust error handling in the reftable writer while preserving backward compatibility.
