Refactoring patch in Martin Ågren's pretty-format parsing series. This is patch 7/8 in the ongoing effort to modularize Git's pretty-format parsing code in pretty.c. The patch extracts magic character parsing (for modifiers like '-', '+', and ' ') from `format_commit_item()` into a new `parse_magic()` helper function. 

The change introduces an `enum magic` type to represent the parsing results and handles the special case where '%+w' combinations are invalid (returning an error via the new 2-value return code convention). The refactoring maintains identical behavior while making the control flow clearer and continuing the series' pattern of breaking down complex formatting logic into smaller, more maintainable pieces.

Key technical details include:
- New `enum magic` type with `NO_MAGIC`, `ADD_LF_BEFORE_NON_EMPTY`, `DEL_LF_BEFORE_EMPTY`, and `ADD_SP_BEFORE_NON_EMPTY` values
- `parse_magic()` returns 0/1 for valid magic characters or 2 for invalid combinations
- The '%+w' special case handling is preserved but now clearly separated
- All changes are internal to pretty.c with no user-visible effects
- Follows the series' established pattern of incremental, behavior-preserving refactoring

The patch continues the series' high quality with clean separation of concerns and thorough preservation of existing behavior. It appears to be preparing the codebase for potential future pretty-format enhancements by making the parsing logic more modular and maintainable.
