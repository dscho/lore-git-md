Windows config file race condition follow-up

Allen Li confirms they were referring to Git v2.48.0 in the previous discussion about Windows config file race conditions. The email serves as an acknowledgment of Patrick Steinhardt's technical explanation about the remaining gaps in Windows file handling, particularly around `FILE_SHARE_DELETE` support in file opening operations. 

The key technical points reiterated are: (1) the need for both POSIX-style rename support and proper file handle sharing flags, (2) current `_wfopen()` and `_wfsopen()` implementations lacking full delete sharing capabilities, and (3) the ultimate requirement to use `CreateFileW()` for complete control over file sharing modes. 

Allen notes their team has implemented a workaround that avoids this specific issue, but leaves the door open for future work to properly fix the underlying Windows implementation. The email doesn't propose new solutions but serves to document the current understanding of the limitations for future reference.
