Build system optimization discussion about meson defaults. This is part 3 of a 12-part series aimed at reducing redundant compiler definitions in the meson build configuration.

Patrick Steinhardt questions the value of the current patch, which conditionally sets DEFAULT_* variables only when they differ from built-in defaults ('vi', 'man', 'less'). He notes the behavior remains identical before and after the change, while actually increasing the number of hard-coded assumptions in the build system.

Instead, Patrick suggests a more substantial improvement: completely removing default values from meson_options.txt and checking for empty strings instead. This would eliminate the duplication of default values between meson configuration and source code (like editor.c). The discussion highlights an opportunity for cleaner build system design beyond the current incremental approach.

The exchange shows the series is receiving thoughtful review, with contributors looking for ways to maximize the benefits of the build system cleanup while minimizing technical debt.
