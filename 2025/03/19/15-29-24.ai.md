This is the v5 iteration of Meet Soni's reftable error handling bugfix series, completing their GSoC project under Patrick Steinhardt's mentorship. The series standardizes error propagation in the reftable writer implementation, with this version focusing on final refinements to the error handling logic.

The key changes in v5 are documentation improvements and commit message clarifications, building on the substantial work from previous versions that:
1. Introduced specific REFTABLE_* error codes to replace generic -1 returns
2. Distinguished between block-full conditions (REFTABLE_ENTRY_TOO_BIG_ERROR) and other errors
3. Systematically propagated errors through block_writer_add(), writer_add_record(), and write_object_record()

The most notable technical change in this version is the enhanced handling in write_object_record() where it now:
- Explicitly checks for REFTABLE_ENTRY_TOO_BIG_ERROR at both retry points
- Attempts to reduce the record's offset length to zero if the block remains too full after flush/reinit
- Maintains clear separation between temporary block-full conditions and permanent errors

The series touches core reftable writer components (block.c, record.c, writer.c) and represents the culmination of multiple review iterations. The implementation now provides robust error handling throughout the reftable writer stack while maintaining backward compatibility with existing behavior. The changes are well-contained and focused specifically on error propagation improvements, with clear documentation of the expected error codes and retry logic.
