Bugfix in the reftable writer's error handling, specifically addressing object record writing edge cases. This is a follow-up to Meet Soni's v3 patch series standardizing error propagation in the reftable implementation.

Patrick Steinhardt identifies a remaining issue in `write_object_record()` where error handling needs to be consistent with the rest of the series. The function currently retries writes after both flushing the block and resetting the record's offset length, but doesn't properly check for REFTABLE_ENTRY_TOO_BIG_ERROR in the second retry case. This could lead to incorrect retry behavior for non-block-full errors.

The proposed change adds explicit error code checks at both retry points in `write_object_record()`, ensuring the function only retries for REFTABLE_ENTRY_TOO_BIG_ERROR conditions while properly failing for other error types. The diff shows the straightforward addition of error code validation at both retry points, maintaining the existing retry logic but making it more precise.

This appears to be the final refinement needed for the error handling improvements in the reftable writer, completing the work started in the earlier patches. The change is focused and clearly motivated by the same principles established in the rest of the series - proper error propagation and discrimination between temporary (block-full) and permanent error conditions.
