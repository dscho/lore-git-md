Bugfix in Git's pretty-format padding handling. This is patch 5/8 in Martin Ågren's series refactoring pretty.c's format parsing code.

The patch addresses a subtle issue where padding state could leak between placeholders in pretty-format strings. After applying padding directives like `%<` or `%>`, some internal state in the `struct padding_args` wasn't being fully reset, potentially affecting subsequent placeholders. While the previous patch fixed one manifestation of this issue, this change ensures all padding-related fields are properly cleared after use.

Martin notes this is a defensive change - he couldn't find a way to trigger a bug with the current behavior, but it makes the code more robust by preventing any potential state leakage. The included test verifies that truncation only affects the immediately following placeholder, not subsequent ones.

This continues the series' theme of tightening up pretty-format parsing while maintaining backward compatibility. The change is small but meaningful, showing careful attention to edge cases in Git's formatting engine.
