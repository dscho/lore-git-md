This is the third and final patch in Meet Soni's v4 reftable error handling bugfix series, focusing on precise error propagation in the writer implementation. The patch specifically targets `write_object_record()` in reftable/writer.c, which previously treated all errors from `block_writer_add()` as indicating a full block, forcing unnecessary flushes for non-block-full errors like memory allocation or I/O failures.

The change makes `write_object_record()` properly discriminate between error types by:
- Only triggering block flush/reinit when receiving `REFTABLE_ENTRY_TOO_BIG_ERROR`
- Immediately propagating all other error codes (memory, I/O) to callers
- Adding clear comments explaining the retry logic
- Maintaining the existing block-full handling behavior while making it more precise

This completes the series' goal of improving error handling granularity in the reftable writer, following Patrick Steinhardt's mentorship. The implementation now properly distinguishes between temporary block-full conditions (which should trigger retry) and permanent errors (which should abort immediately). The patch builds on the error code standardization from earlier in the series and demonstrates careful attention to edge cases in the object record writing path.
