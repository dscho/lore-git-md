This is a contributor housekeeping patch that extends the `.editorconfig` file to include `.bash` files in the same formatting rules as other shell scripts (`.sh`). The change ensures consistent tab-based indentation for Git's Bash completion script and CI helper script, aligning them with the project's existing shell script style.

The patch is straightforward - it simply adds `bash` to the list of extensions in the EditorConfig pattern that already handles shell scripts. The commit message notes that both existing `.bash` files in the tree (git-completion.bash and check-directional-formatting.bash) currently use tabs, making this a logical consistency improvement.

The change is minimal (one line modified) and low-risk, affecting only editor behavior rather than actual code. It follows the same pattern already established for other file types in a section that explicitly notes the need to keep formatting rules in sync with `.clang-format` for C files. No tests or additional documentation are needed for this purely mechanical change.
