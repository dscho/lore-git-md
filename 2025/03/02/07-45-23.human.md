This is a preparatory patch in a series fixing bash completion issues with remote names containing slashes. It introduces a new helper function `__git_escape_fnmatch()` that properly escapes special characters (?, *, [, and \) in strings before they're used with fnmatch patterns. The function will be used in the series' later patches to handle ref names correctly during completion.

The patch includes both the implementation in git-completion.bash and a test case verifying the escaping behavior works as expected. The test confirms that special characters are properly prefixed with backslashes in the output. This foundational change enables the subsequent fixes for slash-containing remote names by ensuring pattern matching will work correctly with escaped special characters.

The patch appears clean and focused, with a clear single responsibility and accompanying test coverage. As the first in a three-part series, it sets up infrastructure needed for the actual bugfixes to follow.
