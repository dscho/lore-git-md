Bugfix for bash completion with slashed remote names, with performance concerns raised.

This is a review comment on the final patch of a series fixing bash completion issues with remote names containing slashes. Phillip Wood raises a performance concern about the current approach of running `git for-each-ref` once per remote, suggesting it won't scale well for users with many remotes. He proposes an alternative using `sed` to strip remote prefixes outside the `for-each-ref` call, which would only fork three processes regardless of remote count.

The proposed solution involves:
1. Building a `sed` command that escapes special characters (., $, /) in remote names
2. Sorting remotes in reverse order to handle nested remote names (e.g. "github" vs "github/alice")
3. Applying the transformations in a single pipeline

The comment notes uncertainty about whether this affects output order when `GIT_COMPLETION_IGNORE_CASE` is set. The original patch being discussed modified `__git_dwim_remote_heads()` and `__git_refs()` to use new utilities `__git_escape_fnmatch()` and `__git_count_path_components()` for proper slash handling in remote names.

This feedback suggests the solution may need revision before merging, with the key tradeoff being correctness of slash handling versus performance with many remotes. The extensive test coverage (180 lines added in t9902-completion.sh) should help verify any alternative implementation.
