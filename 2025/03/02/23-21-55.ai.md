This is a bug report about PKCS#11 authentication failing due to URI escaping issues. The reporter describes how Git 2.48.1 on Fedora 41 incorrectly escapes special characters in PKCS#11 URIs when they're specified in the gitconfig for smart card authentication, causing OpenSSL to fail to recognize the credentials. The escaped characters include equals signs, colons and semicolons that are part of the PKCS#11 URI format.

The bug report provides a clear reproduction case showing the unescaped URI in the gitconfig versus how Git transforms it before passing to OpenSSL. The reporter notes this worked correctly in Git 4.35.5 on Rocky Linux 9, suggesting this is a regression in newer versions. The issue manifests when trying to clone a repository using a YubiKey 5 smart card for authentication.

Key technical details include the specific OpenSSL version (3.2.2) and the configuration showing the PKCS#11 URI format being used. The reporter has sanitized sensitive information like the actual YubiKey serial number and repository URL. The error occurs in the authentication phase where Git tries to use ksshaskpass for password prompting before ultimately failing with an authentication error.

This appears to be a legitimate bug in Git's URI handling for PKCS#11 authentication paths, with clear before/after behavior and version information that could help pinpoint when the regression was introduced. The report is thorough and well-formatted, though it doesn't include any proposed fix or analysis of where in Git's code the problematic escaping occurs.
