This is a technical response to ZheNing Hu's proposal for inline code commenting in Git. Randall Becker offers implementation thoughts while raising important considerations about the feature's feasibility.

Randall suggests storing comments as an ancillary data structure tied to commits and line ranges, with content blobs that could be signed. He notes this would need merge/squash handling similar to other Git objects and proposes using a `--notes`-like mechanism for synchronization between repositories. However, he identifies several challenges: the need for non-core server support (like JGit), potential conflicts with proprietary features from GitHub/GitLab, and the fact that some useful features (like GitLab's Merge Squash) haven't been adopted into core Git.

The response advances the technical discussion by proposing a concrete storage model while highlighting real-world adoption barriers. It doesn't reject the proposal outright but provides a reality check about the ecosystem considerations that would affect implementation. The mention of signature requirements suggests security is a key concern, and the reference to existing platform features implies the proposal would need clear differentiation from centralized solutions.
