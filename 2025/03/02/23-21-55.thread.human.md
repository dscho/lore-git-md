A bug report has been filed regarding PKCS#11 smart card authentication failures in Git 2.48.1 on Fedora 41. The issue occurs when Git incorrectly escapes special characters (like equals signs, colons and semicolons) in PKCS#11 URIs specified in gitconfig for smart card authentication. This malformed URI then causes OpenSSL 3.2.2 to fail to recognize the credentials during repository operations like cloning.

The reporter provides a clear reproduction case showing the correct unescaped URI format that worked in Git 4.35.5 on Rocky Linux 9 versus the incorrectly escaped version in newer Git versions. The problem specifically affects YubiKey 5 authentication workflows, though the report carefully sanitized sensitive details. The error manifests during authentication when Git attempts to use ksshaskpass for password prompting before ultimately failing.

This appears to be a regression in Git's URI handling for PKCS#11 paths, with clear version information that could help trace when the problematic escaping behavior was introduced. The report is thorough in documenting the failure mode but doesn't yet include analysis of the root cause or proposed fixes.
