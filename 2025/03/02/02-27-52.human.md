This is a feature and bugfix patch series for git-p4, the Git-P4 bridge tool. Nikolay Shustov proposes several enhancements to improve the git-p4 workflow, along with one important fix for file handling after revert operations.

The patch introduces several new configuration options and command-line flags to give users more control over git-p4's behavior. Key additions include encoding configuration for Perforce error messages (P4CommandErrorEncoding), options to control changelist creation and shelving behavior (--new-changelist, --keep-p4opened), and templating support for changelist descriptions (--p4-description-file and --p4-description). There are also complementary options to control when the changelist editor appears (--no-edit-p4spec and --edit-p4spec).

The bugfix addresses a problematic edge case where git-p4 would leave writable files in the workspace after a revert operation, which could interfere with subsequent syncs. The fix adds the -w' flag to p4 revert` to properly clean up added files.

The changes appear well-motivated by real-world usage scenarios and are clearly explained. The patch doesn't include tests, which might be worth requesting given the behavioral changes. The modifications seem focused on practical workflow improvements rather than fundamental architectural changes, making them likely candidates for inclusion if the implementation proves sound.
