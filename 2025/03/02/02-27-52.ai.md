This is a feature and bugfix patch series for git-p4, the Git-P4 bridge tool. The author Nikolay Shustov proposes several new configuration options and command-line flags to improve the git-p4 workflow, along with one bugfix for file handling after revert operations.

The patch introduces several new user-configurable features for git-p4:
1. A `P4CommandErrorEncoding` setting to handle non-UTF-8 Perforce error messages
2. Options to control changelist creation (`--disable-p4refresh`, `--new-changelist`)
3. Shelving workflow improvements (`--keep-p4opened`, description templating via `--p4-description-file` and `--p4-description`)
4. Editor control flags (`--no-edit-p4spec`, `--edit-p4spec`)

The bugfix addresses an issue where git-p4 would leave writable files in the Perforce workspace after revert operations, now fixed by using `p4 revert -w` to properly clean up added files. The changes appear well-motivated by real-world usage scenarios, particularly around shelving operations and workspace management.

Key technical details for future reference:
- New config settings: `git-p4.P4CommandErrorEncoding`, `git-p4.disableP4Refresh`, `git-p4.makeNewChangelist`, `git-p4.keepShelvedFilesOpened`, `git-p4.descriptionTemplateFile`, `git-p4.descriptionTemplate`
- New command-line flags mirror these config options with `--` prefixes
- Template syntax supports `{message}`, `{hash}`, and `\n` substitutions
- The fix modifies revert behavior to use `-w` flag when cleaning up added files

The changes are focused on the git-p4 Python implementation and its interaction with Perforce workspaces, with no changes to core Git functionality. The patch appears to be a standalone contribution rather than part of a larger series.
