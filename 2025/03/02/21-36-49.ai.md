Feature proposal discussion on inline code commenting in Git.

This email from Randall Becker responds to ZheNing Hu's proposal for adding GitHub/GitLab-style inline code comments to Git while maintaining its distributed nature. Randall suggests implementing this as an ancillary data structure tied to commits and line ranges, with content blobs that could be signed or have SHA signatures. He notes the system would need to handle merges similarly to how notes are processed, with squashing combining comments.

Key technical considerations raised include:
- The need for push/fetch mechanisms to transfer comments between repositories (similar to `--notes`)
- Challenges with non-core Git server support (e.g., JGit compatibility)
- Potential conflicts with existing concepts in GitLab/GitHub
- The example of GitLab's Merge Squash feature not being adopted into core Git

The response continues the thread's focus on implementation feasibility, particularly around distributed synchronization and compatibility with existing Git infrastructure. Randall's concerns highlight the non-trivial integration challenges this feature would face, especially regarding cross-platform support and potential overlap with proprietary features from major Git hosting platforms. The email doesn't propose concrete solutions but rather identifies additional technical hurdles to consider in the proposal's evolution.
