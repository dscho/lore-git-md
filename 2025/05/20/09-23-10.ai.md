This is the third and final patch in a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch adds test coverage for the fixes introduced in the previous two patches, specifically targeting corruption scenarios that trigger the leaks.

The test case deliberately corrupts the XOR offset field of the first entry in a bitmap file to verify the validation checks and cleanup paths work correctly. It implements a helper function `skip_ewah_bitmap()` to navigate the bitmap file structure, skipping past the header and four EWAH bitmaps (commits, trees, blobs, tags) to reach the entries section where the corruption is injected. The test creates a repository with a bitmap, then modifies the XOR offset field to be invalid (0xa1) while ensuring the bitmap loading still completes without leaks.

This completes the series by providing regression protection for both the validation-order leak fix (first patch) and the partial-load leak fix (second patch). The test demonstrates the robustness of the new error handling approach that relies on centralized cleanup via `free_bitmap_index()` rather than per-error-path handling. The test implementation shows careful attention to the bitmap file format details, with comments explaining the structure and the precise location being corrupted.
