Feature implementation for GitLab's specialized receive-pack optimization. This is the second patch in a series that adds a `--skip-connectivity-check` option to `git receive-pack`, allowing server-side systems like GitLab's Gitaly to bypass Git's built-in object graph validation when they can provide stronger guarantees about repository connectivity.

The patch implements the core functionality after the first patch established test infrastructure. The new option is marked as OPT_HIDDEN_BOOL to prevent casual use, with thorough documentation warning about the corruption risks if used without external validation. The implementation cleanly integrates with receive-pack's existing connectivity check logic, skipping both the `check_connected()` call and associated sideband messaging when the flag is active.

Test coverage demonstrates both the default failure case (rejecting packs with missing objects) and the new bypass mode (accepting such packs when the flag is set). The tests use clever pipe-and-tee patterns to validate both protocol messages and repository state. The implementation appears well-considered, with clear motivation tied to GitLab's specific needs and appropriate safeguards against misuse.

This looks ready for final security review, particularly around the implications of bypassing a critical safety check. The hidden flag and explicit warnings suggest the maintainers have found a reasonable balance between GitLab's optimization needs and general repository safety.
