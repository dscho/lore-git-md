This is the final patch (6/6) in a documentation series addressing `--stdin` behavior in git-notes commands. The patch equalizes the documentation treatment of `--stdin` between the `copy` and `remove` subcommands, which previously had inconsistent descriptions despite both supporting the option.

The changes make two key improvements: (1) adding `--stdin` documentation to the `remove` subcommand section (mirroring what already existed for `copy`), and (2) updating the general `--stdin` option documentation to clarify the behavioral differences between subcommands - specifically noting that `remove --stdin` can combine with command-line object names while `copy --stdin` cannot.

Junio Hamano approves the patch but suggests simplifying the option documentation further by removing the detailed behavioral notes and just pointing readers to the subcommand sections. This would defer the behavioral specifics to where they naturally belong with each subcommand's documentation. The patch currently maintains these details in the option section while adding cross-references.

The changes complete the series' goal of making implicit behaviors explicit and standardizing documentation across related commands. With this patch, the entire stdin behavior for git-notes operations is now fully and consistently documented, addressing an oversight from the original 2010/2011 implementations. The patch follows the same documentation conventions established in earlier parts of the series.
