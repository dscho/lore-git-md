Bugfix patch in a series addressing memory leaks in pack-bitmap.c's bitmap loading paths. This is the second of three patches in v2 of the series, following up on earlier discussion about proper error handling and cleanup.

The patch simplifies error handling in `load_bitmap()` by removing redundant cleanup code that was causing memory leaks. Previously, when `load_bitmap()` failed partway through loading bitmap entries, it would perform partial cleanup (destroying the oid map but not freeing individual bitmaps) before returning -1. The caller would then call `free_bitmap_index()`, but the bitmap entries were already lost due to the intermediate cleanup.

The solution replaces all `goto failed` jumps with direct `return -1` statements, letting the caller's `free_bitmap_index()` handle all cleanup uniformly. This removes 17 lines of duplicate cleanup code while fixing the leak scenario. The change affects several failure paths in `load_bitmap()` including reverse index loading, bitmap reading, and base bitmap handling.

This builds on the thread's established approach of centralizing cleanup in `free_bitmap_index()` rather than having per-error-path handling. The patch follows the first patch's similar fix for validation-order leaks in `load_bitmap_entries_v1()`, with both now having test coverage added in v2 of the series. The changeset is minimal (4 insertions, 17 deletions) and maintains the performance-critical nature of the bitmap loading code while improving its robustness.
