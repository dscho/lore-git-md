**Thread Update: Git Exec-Path Security and Compatibility**

This thread addresses security concerns around how Git exposes its internal binaries in child process environments, particularly the PATH variable. The core tension is between security (preventing unintended execution of Git's internal tools by editors and other programs) and compatibility (ensuring Git's own subprocesses like hooks can still access the correct versions of Git commands). The discussion has evolved through multiple patch versions, with D. Ben Knoble as the primary author.

The latest exchange reinforces that GIT_EXEC_PATH serves a critical role in version consistency for Git's subprocesses, beyond just supporting deprecated dashed commands. Junio Hamano clarified that setup_path() in git.c remains necessary for proper subcommand execution, suggesting the solution must preserve consistent execution environments for hooks and subcommands. This positions the discussion toward keeping PATH modification for Git's own processes while removing it for external ones.

Key participants have staked out positions: Junio prefers a narrower approach focused on editor invocations, while Patrick Steinhardt and Phillip Wood have raised important considerations about Windows Unicode handling and hook execution environments. The author is now preparing two versions for comparison - one maintaining the original broad approach and another implementing Junio's suggested narrower focus. Windows-specific requirements and the ongoing deprecation of dashed commands remain complicating factors that any solution must address.
