This thread addresses security and compatibility issues around how Git exposes its internal binaries in the PATH environment variable for child processes. The current behavior can cause problems, particularly on Windows where editors like Vim may unintentionally execute Git's internal commands. D. Ben Knoble has proposed a 4-patch series (v1) that would prevent Git's exec-path from being added to PATH for non-Git child processes.

The series begins with preparatory cleanups, including Patrick Steinhardt's reviewed patch that modernizes editor environment handling to use Git's strvec API consistently. While technically sound, Patrick noted the commit message could better explain the motivation beyond just API consistency. The main security change would modify PATH handling in run-command.c to exclude Git's exec-path when spawning non-Git processes.

Junio C Hamano has raised concerns that the current approach might be too broad, potentially breaking legitimate cases where child processes need access to Git binaries. He suggests an alternative design using a more surgical drop_git_exec_path flag in the child_process struct. Johannes Schindelen has provided input on Windows-specific considerations, and the author acknowledges needing Windows testing verification. A memory leak from earlier patches also needs addressing before the series can progress.

The discussion continues with participants weighing the tradeoffs between security and compatibility, particularly for Windows users, while the author considers how to incorporate Junio's feedback about making the PATH modifications more targeted.
