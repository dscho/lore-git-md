This thread continues the discussion about securing Git's process spawning while maintaining version consistency across child processes. The original series from D. Ben Knoble proposed changes to prevent Git's internal binaries from being exposed in PATH for non-Git child processes, with particular attention to Windows compatibility.

The discussion has evolved to consider two approaches: a broad version affecting all non-Git commands (v2) and a narrower editor-focused version (v3) as suggested by Junio Hamano. Key participants including Patrick Steinhardt, Phillip Wood, and Johannes Schindelen have weighed in on technical considerations, PATH vs GIT_EXEC_PATH requirements, and Windows Unicode handling.

Justin Tobler's latest contribution adds an important technical clarification: when GIT_EXEC_PATH is explicitly set in the parent process, it should propagate to child Git processes to maintain version consistency. This suggests GIT_EXEC_PATH handling may need separate consideration from the broader PATH modifications, adding nuance to the security/compatibility tradeoffs. The thread remains active with the author planning to send updated versions for comparison, while participants continue to balance security improvements against the need to maintain existing workflows, particularly around hooks and subprocess execution.
