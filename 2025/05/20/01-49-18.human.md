This is a 2-patch series introducing a new hidden option for `git receive-pack` to skip connectivity checks, specifically for GitLab's internal use case. The cover letter explains that GitLab's Gitaly service already performs rigorous transaction-based connectivity validation, making `receive-pack`'s general-purpose checks redundant in their environment.

The first patch reorganizes test infrastructure, moving existing alternates tests into a more general `t5410-receive-pack.sh` file and adding explicit checks for connectivity error messages. The second patch implements the actual `--skip-connectivity-check` option as a hidden flag (OPT_HIDDEN_BOOL) to prevent casual misuse, while allowing GitLab to bypass the redundant checks.

The series has already gone through one round of review, with Patrick Steinhardt providing feedback that led to test consolidation and improved error message verification. Junio Hamano has endorsed the approach while emphasizing documentation needs. The current version includes updated commit messages and documentation explaining the option's purpose and GitLab's specific use case.

This appears to be a well-considered change with clear motivation and thorough test coverage. The hidden flag approach seems designed to prevent abuse while solving GitLab's specific performance optimization need. The discussion suggests this will be merged once documentation is finalized and any remaining security concerns are addressed.
