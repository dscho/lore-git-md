Security-focused patch removing Git's exec-path from PATH for non-Git child processes. This is the final patch in a series addressing potential security and compatibility issues when Git's internal binaries are exposed to external programs.

The change modifies `run-command.c` to selectively remove Git's exec-path from the PATH environment variable when spawning non-Git commands (determined by the `git_cmd` flag). This prevents editors and other external programs from accidentally executing Git's internal binaries. The implementation carefully handles PATH manipulation to avoid false positives when matching the exec-path string.

A new test in `t7005-editor.sh` verifies that editors no longer see Git's exec-path in their environment. The patch builds on earlier refactoring in the series that standardized environment handling with `strvec` and improved test isolation.

Key technical details:
- Adds `remove_git_exec_path()` helper to safely modify PATH entries
- Updates `prep_childenv()` to conditionally filter PATH based on `git_cmd`
- Maintains existing PATH behavior for Git subprocesses
- Includes test case validating editor environment
- Handles edge cases around PATH separators and partial matches
- Acknowledges remaining leak of environment memory (from earlier patches)

The change addresses a real-world issue reported by Git-for-Windows users where Vim integration was affected by Git's exec-path in PATH. Johannes Schindelen suggested the approach, which the author refined with additional safety checks for PATH parsing. The patch appears well-considered but would benefit from Windows-specific verification given its security implications.
