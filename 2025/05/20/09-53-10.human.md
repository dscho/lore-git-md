Performance optimization for multi-pack-index handling, implementing a negative lookup cache for missing packfiles. This is the second patch in a v2 series that has already seen productive discussion and consensus on the approach.

The patch addresses a performance issue where Git would repeatedly attempt to look up packfiles that no longer exist (due to a stale multi-pack-index), resulting in unnecessary syscalls. The solution introduces a cache that remembers failed lookups by storing a sentinel value (-1 cast to a pointer) in the midx->packs[] array. This avoids repeated stat() and access() calls for the same missing pack.

The impact is demonstrated with clear benchmarks showing a 4x speedup for `git log --patch` in repositories with stale multi-pack-indexes, reducing syscalls from ~24,000 to just 83 in the test case. The implementation is careful to maintain all existing safety constraints around packfile handling and includes proper cleanup of the cache entries.

This builds on Jeff King's suggested approach from earlier in the thread and represents the culmination of discussion that identified the original optimization attempt (reordering auxiliary file checks) as unsafe. The patch is well-contained and maintains Git's packfile integrity invariants while delivering measurable performance improvements.
