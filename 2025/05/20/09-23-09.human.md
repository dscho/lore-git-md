Bugfix for a memory leak in the pack-bitmap loading code. This is the second patch in a 3-part series addressing bitmap-related leaks, following up on Lidong Yan's initial report.

The patch fixes a case where partially-loaded bitmap entries would leak if `load_bitmap()` failed midway through. The issue stems from redundant cleanup: the function had its own error-handling path that freed some (but not all) resources, while callers would also call `free_bitmap_index()` to clean up. The solution is simple and elegant - remove the partial cleanup in `load_bitmap()` entirely and let the caller's `free_bitmap_index()` handle everything uniformly.

Taylor Blau's change removes 17 lines of error-handling code while adding just 4 lines of direct returns, demonstrating how the fix actually simplifies the codebase. The patch builds on Jeff King's earlier review confirming this approach, and is now accompanied by new test coverage added in v2 of the series. This appears to be merged soon given the clear problem and straightforward solution that has already garnered reviewer approval.
