This is a feature proposal for Git 3.0's breaking changes, specifically targeting `git stash` behavior. The series aims to make `stash apply/pop` default to restoring the index (equivalent to current `--index`) when breaking changes are enabled, addressing a long-standing "footgun" where staged changes are lost during stash application.

The email is the cover letter for a 9-patch series that:
1. Starts with preparatory test cleanups (patches 1-2)
2. Documents the proposed change in BreakingChanges.adoc (patch 3)
3. Implements the core behavior change in builtin/stash.c (patch 4)
4. Updates affected tests across multiple test files (patches 5-9)

Key technical aspects include:
- Behavior change gated behind GIT_BREAKING_CHANGES flag
- Replaces `--index` flag with `--no-index` as the opt-out mechanism
- Updates documentation to reflect dual behavior
- Comprehensive test updates showing:
  - Basic stash operations (t3903)
  - Interactive mode (t3904)
  - Untracked files handling (t3905)
  - Submodule improvements (t3906)
  - Documentation consistency (t0450)

The author notes the test strategy splits tests into separate versions for old/new behavior rather than using `test_has_prereq`, inviting feedback on this approach. The change is motivated by historical context (original stash implementation considered this behavior) and real-world confusion cases.

The thread context shows Junio C Hamano has raised significant ergonomic concerns about the change, particularly around workflow friction from needing to type `--no-index` more frequently than `--index`. This positions the series at a critical decision point where the technical merits (fixing a known pitfall) conflict with practical usability considerations.
