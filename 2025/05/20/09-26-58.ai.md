This is a cover letter for a two-patch bugfix series addressing `git stash` option parsing, specifically around the `-p/--patch` flag with pathspecs. The series splits the changes from v1 into two logical parts following maintainer feedback.

The first patch fixes a regression introduced in 8c3713cede7 (2020) where "git stash -p <pathspec>" stopped working due to incorrect argv handling during the push assumption. The fix checks argv[1] instead of argv[0] for the "-p" flag and adds regression tests. This restores the pre-2020 behavior where "-p" implies "push".

The second patch (new in v2) extends this to support more flexible option ordering, allowing combinations like "-m <message> -p <pathspec>" to work. It uses PARSE_OPT_STOP_AT_NON_OPTION when push is assumed, maintaining rejection of malformed commands while enabling valid use cases. The test suite from t3903-stash.sh verifies both the regression fix and new parsing rules.

The changes maintain backward compatibility while addressing both the immediate regression and longer-term option parsing flexibility. The implementation follows the maintainer's suggested approach of splitting the fixes while preserving the technical solution using PARSE_OPT_STOP_AT_NON_OPTION. The series shows good responsiveness to review feedback with clear commit message updates and focused test coverage.
