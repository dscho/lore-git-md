Refactoring patch in a series addressing exec-path security issues, specifically modernizing editor environment handling to use strvec API consistently.

This second patch in the 4-part series updates Git's editor launching code to use the modern strvec API for environment variable handling, replacing the older const char** approach. The change affects three editor-related functions in editor.c/h and their single caller in builtin/commit.c. The motivation stems from the code not having been updated when surrounding APIs evolved to use strvecs, despite the environment parameter being introduced in 2007 (commit 8babab95af).

The patch makes mechanical changes to function signatures and implementations to accept struct strvec pointers instead of char** arrays. The only caller that passes a non-NULL environment (in builtin/commit.c) already has a strvec available, making this a straightforward conversion. Johannes Schindelin is credited as a helper, suggesting Windows compatibility was considered.

Key technical changes:
- Modifies launch_specified_editor() and related functions in editor.c to take const struct strvec*
- Updates function prototypes in editor.h accordingly
- Adjusts the single caller in builtin/commit.c to pass &env instead of env.v
- Maintains identical functionality while using more modern Git internal APIs

This appears to be a preparatory refactoring for the series' main change (patch 4/4) which will modify PATH handling for child processes. The change is low-risk as it doesn't alter behavior and affects code with only one non-NULL environment caller. The patch follows the series' pattern of cleaning up related infrastructure before making functional changes.
