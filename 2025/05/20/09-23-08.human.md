Bugfix addressing a memory leak in bitmap loading validation. This is the first patch in a v2 series fixing memory leaks in pack-bitmap.c, following up on earlier discussion.

Lidong Yan's patch reorders validation checks in `load_bitmap_entries_v1()` to prevent memory leaks when bitmap validation fails. The original code would allocate a bitmap via `read_bitmap_1()` before performing XOR offset and commit index validation, meaning failed validation would leak the allocated bitmap. The fix moves these checks before the allocation, ensuring we only allocate after confirming the data is valid.

This change is part of a broader effort to simplify and robustify bitmap error handling by centralizing cleanup in `free_bitmap_index()` rather than having scattered cleanup paths. The patch follows the thread's established approach of removing redundant error handling while ensuring proper resource cleanup. Reviewers Jeff King and Junio C Hamano had already approved the technical direction in previous iterations, and this version adds test coverage (in subsequent patches) to verify the fix.

The change is minimal (4 line rearrangement) but important for preventing leaks in error paths, particularly when dealing with corrupt bitmap files. The series as a whole shows careful attention to both the memory management fixes and adding regression tests for the scenarios being fixed.
