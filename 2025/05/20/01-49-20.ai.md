Feature implementation for GitLab's Gitaly integration, adding a `--skip-connectivity-check` option to `git receive-pack`. This is the second patch in a 2-part series that follows up on mailing list feedback, with patch 1 having established comprehensive test coverage for the default connectivity check behavior.

The patch introduces a hidden boolean option that allows bypassing `receive-pack`'s expensive object graph validation when server-side systems (like GitLab's Gitaly) can guarantee connectivity through other means. The implementation wraps the existing `check_connected()` call in a conditional block and adds corresponding documentation warning about the corruption risks if used without proper external validation.

Key technical changes include:
- New `skip_connectivity_check` global flag in `builtin/receive-pack.c`
- Modified `execute_commands()` to conditionally skip the connectivity check and sideband setup
- Added test case in `t/t5410-receive-pack.sh` verifying the bypass works while maintaining object integrity
- Documentation in `git-receive-pack.adoc` explaining the specialized use case and risks

The implementation carefully preserves all existing error handling paths and sideband communication when the check is enabled. The test demonstrates the bypass scenario by capturing `send-pack` output and replaying it with the new flag, verifying the repository remains valid despite skipping the check.

Security considerations are prominent in both code and documentation, with the option marked as OPT_HIDDEN_BOOL to prevent casual use. The commit message provides detailed rationale about GitLab's specific use case where repository invariants allow safer optimization.
