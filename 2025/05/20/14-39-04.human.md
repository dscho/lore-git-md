This is a follow-up in the ongoing discussion about changing `git stash`'s default behavior to restore the index when applying stashes under breaking changes mode. The original author, D. Ben Knoble, is checking for feedback on their 9-patch series that implements this change.

The series proposes making `stash apply/pop` imply `--index` by default when GIT_BREAKING_CHANGES is enabled, addressing what the author describes as a long-standing "footgun" where users lose carefully staged changes. The implementation includes test updates across multiple test files, documentation changes, and core functionality modifications in builtin/stash.c.

Key points in this email:
- The author is soliciting feedback, particularly on their test strategy which splits tests into separate versions for old/new behavior rather than using conditional tests
- They acknowledge an alternative approach using `test_has_prereq` might make diffs smaller but potentially harder to follow
- The series remains structured as originally proposed, with infrastructure improvements first, then the behavior change, followed by test updates

The thread has seen significant discussion, including reservations from Junio C Hamano about the ergonomic impact of requiring `--no-index` for the (in his experience) more common case of not wanting to restore the index. This email appears to be checking whether others share these concerns or have additional feedback before proceeding.

The patch series looks thorough and well-structured, with the main open question being whether the community consensus will support changing this default behavior, given the tradeoffs between safety and workflow ergonomics.
