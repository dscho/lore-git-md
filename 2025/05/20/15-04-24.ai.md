This is the first patch in a bugfix series addressing integer overflow issues in Git's multi-pack-index repack functionality, specifically targeting 32-bit systems. The patch fixes two concrete overflow scenarios that can occur during midx repack operations.

The core issue stems from size calculations that can overflow on 32-bit systems when handling large packfiles. The first fix replaces 32-bit arithmetic with 64-bit operations when estimating object sizes, using new `u64_mult()` and `u64_add()` helper functions added to git-compat-util.h. The second fix addresses potential overflow when summing sizes by implementing saturating arithmetic that caps at SIZE_MAX.

Key technical changes include:
- New overflow-safe arithmetic helpers in git-compat-util.h
- Modified size calculations in midx-write.c's `fill_included_packs_batch()`
- Conversion from `st_mult()` to `uint64_mult()` for pack size estimation
- Careful handling of size additions with overflow checks

The patch appears well-constructed with clear commit message explanations of both the problem and solution. It includes specific reproduction steps (failing case with --batch-size=120M) and handles edge cases like SIZE_MAX/2 boundaries. The changes are focused on the immediate 32-bit overflow issues while laying groundwork for potential 64-bit overflow protection that will be discussed in later patches.
