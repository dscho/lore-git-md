This is a feature proposal for MPTCP support in Git, continuing the ongoing thread about Multipath TCP integration. Muhammad Nuzaihan responds to Junio Hamano's RFC 6897 transparency argument by presenting a concrete use case: uninterrupted Git operations when switching between WiFi and Ethernet connections on laptops. The email also reports progress in simplifying the implementation after consulting with Linux MPTCP developer Matthieu Baerts.

Key technical updates include: a new configuration approach using `core.mptcp` (defaulting to false for clients, true for servers), removal of environment variable control, and server-side default enablement based on MPTCP project recommendations. The attached WIP implementation shows these changes while maintaining the Linux-specific focus.

The email cites production use by Apple (12 years), Intel, and Red Hat as evidence of MPTCP's maturity, and positions the feature as particularly valuable for large repository operations. This directly addresses Junio's skepticism about whether Git needs explicit MPTCP support by demonstrating a scenario where application-layer awareness provides user-visible benefits beyond what transparent MPTCP can offer.

The thread's central question remains unresolved - whether Git should incorporate MPTCP awareness despite RFC 6897's transparency goals - but this response strengthens the pro-MPTCP case with specific engineering improvements and real-world deployment evidence. The implementation now uses more Git-idiomatic configuration while still requiring platform-specific checks and maintaining the original port 9418 limitation.
