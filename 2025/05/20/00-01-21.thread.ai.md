[PATCH v3 0/7] git diff --no-index with pathspec filtering

Series adds pathspec support to `git diff --no-index` for comparing directories/files outside Git repos, completing the implementation in the final patch. Key changes from previous versions: refined NO_REPO pathspec handling, improved prefix_path() behavior (now including proper slash handling in prefix_path_gently()), and expanded test coverage. Current version includes API exposure of match_pathspec_with_flags() with selected flags (DO_MATCH_DIRECTORY and DO_MATCH_LEADING_PATHSPEC) while keeping DO_MATCH_EXCLUDE private.

Core problem: Currently `git diff --no-index` cannot filter compared files/dirs with pathspecs like repository-based diffs can. This series enables that while maintaining consistent behavior between repo and non-repo contexts.

Technical implementation:
- Introduces PATHSPEC_NO_REPOSITORY flag for pathspec matching without repository context
- Final patch implements core directory comparison filtering by:
  - Modifying fixup_paths() to detect directory inputs
  - Using parse_pathspec() with PATHSPEC_NO_REPOSITORY flag
  - Disabling repository-dependent pathspec features (PATHSPEC_ATTR and PATHSPEC_FROMTOP)
  - Processing pathspecs separately per input path with proper prefixing
  - Special handling in read_directory_contents() using DO_MATCH_LEADING_PATHSPEC and DO_MATCH_DIRECTORY flags
- Enforces that repository-dependent pathspec magics cannot be used with PATHSPEC_NO_REPOSITORY
- Adds BUG check for invalid combinations of attribute pathspecs without an index
- Modifies "outside directory tree" warning to respect no-repository case
- Maintains previous improvements to prefix_path() and prefix_path_gently() slash handling
- Includes 110 lines of tests covering edge cases (basic patterns, nested dirs, globs, negatives)

Current limitations (intentional design choices):
1. Pathspec argument position fixed after input paths (no reordering)
2. Pathspec interpretation relative to each input path
3. Negative pathspecs require full qualification
4. Only directory-vs-directory comparisons support pathspec filtering

Design discussion:
- Junio Hamano reviews Jacob Keller's changes to `match_pathspec_with_flags()` exposure, approving the functional changes while noting two minor style issues: a casual comment about `diff.orderfile` usage and use of `//` comments (not standard in native Git code)
- Earlier discussion with Junio about `prefix_path_gently()` regarding slash handling - whether the function should be lenient about non-slash-terminated prefixes (Jacob's approach) or enforce strict input requirements (Junio's preference)
- Junio argues that since Git-computed prefixes always end in slashes, leniency might mask bugs
- Suggests input validation (including slash checks) should happen before calling `prefix_path_gently()` if handling user-provided prefixes
- Security implications noted regarding proper sanitization of "./", "//", "../" in user input
