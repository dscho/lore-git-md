Bugfix and enhancement for git stash's option parsing, completing the two-patch series addressing -p/--patch behavior.

This second patch extends the earlier fix to allow more flexible option ordering when using --patch` with `git stash`. The assumption that -p implies "push" (introduced in 9e140909f61) was previously too restrictive, rejecting valid commands like `git stash -m <message> -p <pathspec>`. The solution uses PARSE_OPT_STOP_AT_NON_OPTION when push is assumed, then sets force_assume if --patch was present. This maintains safety against subcommand typos (still rejecting `git stash <pathspec> -p`) while accepting more reasonable option orderings.

The change modifies builtin/stash.c's option parsing logic, adding flags to handle dashdash and stop-at-non-option cases differently when push is assumed. A test in t3903-stash.sh is updated to verify the new behavior works with --patch after other options. The patch maintains backward compatibility while expanding valid syntax, completing the series' goal of fixing the -p regression while making the command more flexible. The implementation follows the thread's agreed approach of separating the regression fix (patch 1) from this syntax enhancement (patch 2).
