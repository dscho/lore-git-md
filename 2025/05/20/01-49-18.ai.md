This is a cover letter for a 2-patch series implementing a `--skip-connectivity-check` option for `git receive-pack`, part of GitLab's transaction management system optimization. The series represents a refined version of a previously proposed change, now incorporating feedback from the mailing list discussion.

The first patch reorganizes test infrastructure, consolidating connectivity check tests into an expanded `t5410-receive-pack.sh` while removing the now-redundant `t5410-receive-pack-alternates.sh`. The tests now include more explicit verification of error messages when connectivity checks fail. The second patch implements the actual `--skip-connectivity-check` option as a hidden flag (OPT_HIDDEN_BOOL) in `builtin/receive-pack.c`, modifying `execute_commands()` to conditionally bypass `check_connected()` when the flag is active.

The motivation stems from GitLab's Gitaly service architecture, which already performs rigorous transaction-based connectivity checking at a higher level, making `receive-pack`'s built-in checks redundant in their environment. The cover letter provides detailed technical background about GitLab's transaction system and its object validation approach. Changes since v1 reflect Patrick Steinhardt's feedback about test organization and error message verification, while Junio Hamano's emphasis on documentation is addressed through updates to `git-receive-pack.adoc`.

Key technical points include the hidden flag implementation strategy (preventing casual misuse while allowing GitLab's internal use), the modified test infrastructure showing both successful bypass and proper failure modes, and the careful documentation of this as a GitLab-specific optimization case. The series appears well-constructed with thorough test coverage and clear commit messages, though security implications of bypassing connectivity checks may still need review from experts like Jeff King.
