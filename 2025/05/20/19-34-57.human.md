This is the third patch in a series addressing security and compatibility issues around Git's exec-path handling. The change refactors process spawning to consistently use `prep_childenv()` across all platforms, including Windows, where it was previously skipped. 

The patch moves the environment preparation step earlier in the process and ensures cleanup happens in one place for both Windows and non-Windows code paths. While the immediate effect is just code reorganization, it sets up for the series' main change in the next patch that will modify the environment to prevent Git's internal binaries from being exposed in PATH for non-Git child processes.

The change looks mechanical and well-contained, touching only `run-command.c` with straightforward modifications. The commit message clearly explains the motivation as preparing for future environment modifications. Since this is part of a security-sensitive series that affects process spawning across platforms, Windows users and maintainers will want to pay particular attention to verify the behavior remains correct.
