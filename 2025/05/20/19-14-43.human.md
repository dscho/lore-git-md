This is a documentation patch in a series improving comment character handling in Git's documentation. Junio Hamano provides feedback on patch 4/6, which updates `git-notes` documentation to reference `core.commentChar` for comment character configuration.

The patch adds a cross-reference to `core.commentChar` in the `--stripspace` documentation and changes phrasing from hardcoded `#` to "comment character (default `#`)". Junio suggests this might be too indirect, proposing alternative wording that makes the configuration precedence more explicit by directly stating the fallback to `#` when `core.commentChar` isn't set.

This follows the pattern seen earlier in the series where Junio has been pushing for clearer documentation of configuration hierarchies. The feedback is consistent with his previous comments on patch 1/6, maintaining focus on making implicit behaviors explicit in the text. The author will need to decide whether to adjust the phrasing to show the config/default relationship more directly.
