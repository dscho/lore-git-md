This is the first patch in a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch specifically fixes a leak that occurs when validation checks in `load_bitmap_entries_v1()` fail after a bitmap has been allocated but before it's stored. The fix reorders the validation checks (for XOR offset and commit index) to happen before calling `read_bitmap_1()`, preventing the allocation when these checks would fail. This maintains the same validation logic while eliminating the leak path. The change is minimal (4 line move) and follows the thread's established pattern of centralizing cleanup in `free_bitmap_index()` rather than handling it at each error site. This version includes new test coverage (added in patch 3/3) that verifies the fix by deliberately corrupting bitmap files to trigger the validation failures. The patch has already received positive review from Jeff King in previous iterations, with the technical approach being to simplify error handling while ensuring proper cleanup.
