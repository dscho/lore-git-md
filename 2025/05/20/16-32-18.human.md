This is the second patch in a 2-part series implementing a hidden `--skip-connectivity-check` option for `git receive-pack`, specifically for GitLab's Gitaly service. The patch adds the actual implementation after the test infrastructure was established in patch 1.

The change introduces a new `skip_connectivity_check` flag that bypasses `receive-pack`'s expensive object graph validation when set. This is safe for GitLab's use case because Gitaly maintains its own guarantees about repository connectivity. The option is marked as hidden (OPT_HIDDEN_BOOL) to prevent casual use, as bypassing these checks without proper safeguards could corrupt repositories.

The implementation carefully preserves all error paths and sideband communication when the check is enabled. A new test case verifies that with the flag set, the repository remains intentionally unconnected after receiving objects, while still maintaining basic object existence. The documentation clearly warns about the corruption risks of using this option without proper external validation.

The patch appears well-constructed with thorough test coverage and clear documentation. It addresses the specific GitLab optimization case while protecting general users from accidental misuse. The changes follow the feedback received in the RFC discussion, particularly around test consolidation and error verification.
