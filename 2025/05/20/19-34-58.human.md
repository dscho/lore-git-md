Security-focused patch removing Git's exec-path from PATH for non-Git child processes. This is the final patch in a series addressing potential security and compatibility issues when Git's internal binaries are exposed to external programs like editors.

The change modifies `run-command.c` to only include Git's exec-path in the PATH environment variable when spawning Git subcommands, not for other child processes. This prevents situations where editors or other programs might accidentally execute Git's internal binaries when searching PATH. The patch includes a new test in `t7005-editor.sh` to verify editors don't see Git's exec-path.

The implementation carefully handles PATH modification by:
1. Locating and removing the exec-path segment while preserving other PATH components
2. Only applying the change when `git_cmd` is false
3. Maintaining proper handling of path separators

The author notes a known leak in the modified PATH string that needs addressing, and credits Johannes Schindelen for the original suggestion. The change builds on prior work that stopped prepending argv[0] to PATH, and follows a similar security-conscious approach.

This appears to be a well-considered change to a subtle but potentially problematic behavior, particularly relevant for Windows users where PATH handling can cause integration issues. The test coverage and careful path manipulation suggest it's production-ready aside from the noted memory leak.
