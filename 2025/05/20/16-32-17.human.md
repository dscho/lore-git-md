This is the first patch in a 2-part series implementing a `--skip-connectivity-check` option for `git receive-pack`, specifically for GitLab's Gitaly service. The patch focuses on test infrastructure.

The test file `t5410-receive-pack-alternates.sh` is being renamed and expanded to `t5410-receive-pack.sh` to become a more general test suite for receive-pack functionality. The new test case verifies that `git receive-pack` properly fails when receiving a packfile that would leave the repository with missing objects, which is the default behavior that the subsequent patch will allow bypassing.

The test uses an interesting technique of capturing the output of `git send-pack` via `tee` and then replaying it to verify the connectivity check behavior. It checks both the sideband output ("missing necessary objects") and stderr output, and confirms the repository remains in a valid state after the failed push.

This appears to be a well-constructed test case that will serve as the foundation for verifying the new `--skip-connectivity-check` functionality in the next patch. The test consolidation approach was reviewed and approved by Karthik Nayak in the thread discussion.
