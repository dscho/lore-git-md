This is the final test patch in a bugfix series addressing memory leaks in pack-bitmap loading paths. The patch adds a test case that deliberately corrupts a bitmap file to verify the fixes from earlier patches handle malformed data correctly.

The test specifically targets the XOR offset field of the first bitmap entry, which was one of the leak scenarios fixed in the series. It includes a helper function `skip_ewah_bitmap()` to navigate the bitmap file structure and precisely corrupt the target field. The test verifies that Git can still complete operations (like `rev-list --count`) when encountering this corruption, rather than leaking memory or crashing.

This completes the series by providing concrete verification of the fixes. The test is thorough - it understands the bitmap file format well enough to surgically corrupt just the targeted field, and it checks both the expected behavior and the memory safety. With this addition, the series now has both the code fixes and regression tests needed to prevent these leaks from recurring.
