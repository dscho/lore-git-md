Bugfix and enhancement for `git stash` option parsing. This is the second version of a two-patch series addressing issues with how `git stash` handles the `-p/--patch` option in combination with pathspecs. 

The first patch fixes a regression introduced in 2020 where `git stash -p <pathspec>` stopped working due to incorrect argument handling during a code reorganization. The fix restores the behavior where `-p` implies the "push" subcommand, matching historical expectations. Phillip Wood has simplified this fix from v1 based on Junio Hamano's feedback, now just checking argv[1] rather than adding more complex parse options logic.

The second patch (new in v2) extends this to make `--patch` also imply "push", and allows more flexible option ordering like `-m <message> -p <pathspec>`. The implementation carefully maintains rejection of malformed commands like `stash <pathspec> -p` while enabling valid use cases. Both patches include test cases from t3903-stash.sh to verify the behavior.

The changes are well-motivated by real user-facing regressions and limitations, with clean separation between the immediate fix and the enhancement. The test coverage looks thorough, exercising both the restored functionality and new capabilities. This appears ready for inclusion after the v1 feedback was addressed.
