This is a technical discussion about MPTCP (Multipath TCP) support in Git, with input from a Linux kernel MPTCP maintainer. Matthieu Baerts weighs in on the ongoing debate about whether Git should explicitly support MPTCP, clarifying key implementation details and addressing Junio Hamano's concerns about protocol transparency.

The email makes several important technical points: MPTCP in Linux requires explicitly creating sockets with IPPROTO_MPTCP (rather than IPPROTO_TCP), but otherwise uses the same socket API. Baerts notes that while RFC 6897 envisioned transparent MPTCP support, real-world Linux adoption required making it opt-in for performance and compatibility reasons. He suggests the minimal code change needed (similar to Muhammad Nuzaihan's WIP patch) would be preferable to workarounds like LD_PRELOAD or eBPF hooks.

The discussion reveals a tension between protocol philosophy (MPTCP was designed to be transparent) and practical deployment realities (Linux requires explicit opt-in).
