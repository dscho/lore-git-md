This is a finalized 2-patch series implementing a hidden `--skip-connectivity-check` option for `git receive-pack`, primarily for GitLab's Gitaly service. The series has evolved through mailing list feedback and now includes comprehensive test coverage and documentation.

The first patch establishes test infrastructure in `t5410-receive-pack.sh`, consolidating previous test files and introducing verification methods using `tee` pipes to capture pack data. The second patch implements the actual `skip_connectivity_check` flag in `builtin/receive-pack.c`, guarded by OPT_HIDDEN_BOOL to prevent casual misuse. The implementation preserves all error paths while allowing the bypass when explicitly requested.

Key technical aspects include: conditional bypass of `check_connected()` in `execute_commands()`, sideband message verification, and repository state checks via `cat-file -e`. The documentation explicitly warns about corruption risks and frames this as a GitLab-specific optimization case where Gitaly's transaction system provides equivalent validation guarantees. Test coverage now verifies both that the repository remains intentionally unconnected post-bypass and that the normal connectivity failure path works as expected.

The series has incorporated feedback from Patrick Steinhardt and Karthik Nayak, with final refinements including strengthened test verification of post-bypass repository state and clarified documentation scope regarding bypassed reference connectivity checks. The implementation appears technically sound with appropriate safeguards, though final security review from connectivity experts remains pending.
