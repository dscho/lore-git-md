Performance optimization documentation patch for packfile handling. This is the first of two patches in Patrick Steinhardt's v2 series addressing syscall reduction in multi-pack-index scenarios.

The patch adds crucial documentation to `add_packed_git()` explaining the current ordering of auxiliary file checks (`.keep`, `.promisor`, `.mtimes`) before checking for the packfile itself. While this ordering appears inefficient (wasting syscalls when the packfile is missing), it's actually required to maintain race safety during packfile operations. The comment documents two key invariants: (1) auxiliary files must be installed before their `.idx` file during creation, and (2) auxiliary files must be deleted after their `.pack` file during removal.

This documentation provides important context for the performance optimization in the series' second patch, which implements a negative lookup cache in midx.c to avoid repeated failed packfile lookups. The comment serves as a safeguard against future optimizations that might inadvertently violate these ordering constraints, as nearly happened with an earlier proposed optimization that was correctly identified as unsafe in thread discussion.

The patch touches packfile.c's core packfile handling logic but makes no functional changes - it purely documents existing behavior that's critical to the thread's performance optimization work. The thorough explanation aligns with the thread's focus on maintaining Git's packfile integrity invariants while reducing syscalls.
