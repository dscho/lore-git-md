Feature implementation for GitLab's Gitaly service, adding a `--skip-connectivity-check` option to `git receive-pack`. This is the second patch in a finalized 2-part series, following test infrastructure established in patch 1.

The implementation adds a hidden boolean flag that bypasses `receive-pack`'s object graph connectivity validation when set. The change is carefully scoped to:
- Add `skip_connectivity_check` global flag in `builtin/receive-pack.c`
- Conditionally skip `check_connected()` in `execute_commands()`
- Preserve sideband communication when checks are enabled
- Document the option with strong warnings about corruption risks
- Include comprehensive test coverage in the consolidated `t5410-receive-pack.sh`

Key technical details:
- Uses `OPT_HIDDEN_BOOL` to prevent casual misuse
- Maintains all existing error paths and sideband handling
- Tests verify both successful bypass and intentional repository corruption
- Documentation explicitly states the bypassed checks (transitive closure validation) and GitLab's specific use case
- Test methodology uses `tee` pipe to capture and replay pack data

The patch addresses final review comments by:
- Strengthening documentation to clarify bypassed reference connectivity checks
- Adding test verification that repository remains intentionally unconnected post-bypass
- Maintaining test isolation via `git send-pack -C repo` pattern

Security considerations remain prominent, with the implementation designed for GitLab's Gitaly service which maintains its own transaction-level validation. The hidden flag and explicit warnings aim to prevent misuse while enabling the specialized optimization.
