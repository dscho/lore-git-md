Bugfix for git stash's patch mode option parsing. This is the first patch in a two-part series addressing option handling regressions in `git stash -p`.

The patch fixes a regression introduced in 2020 where `git stash -p <pathspec>` stopped working due to incorrect argv index checking. The bug occurred when the code was moved to `push_stash()` but kept checking argv[0] for "-p" flag after "push" had been prepended to argv. The fix changes the index to argv[1] and adds test coverage.

Key technical details:
- Changes one line in builtin/stash.c to check argv[1] instead of argv[0] for "-p" flag
- Adds two new test cases in t3903-stash.sh:
  - Verifies `stash -p <pathspec>` works as expected (regression test)
  - Confirms `stash <pathspec> -p` is still rejected (backward compatibility)
- Maintains the existing behavior where "-p" implies "push" subcommand
- Preserves the parse_opt behavior that rejects malformed command orderings

The patch is well-motivated with clear commit message tracing the regression history through three prior commits (1ada5020b38, 9e140909f61, 8c3713cede7). The test coverage appears thorough, checking both the fixed case and ensuring invalid syntax remains rejected. This is a focused fix that addresses a specific regression while maintaining existing behavior constraints.
