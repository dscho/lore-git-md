This is the first patch in a 2-part series implementing a `--skip-connectivity-check` option for `git receive-pack`, specifically for GitLab's Gitaly service. The patch focuses on establishing test infrastructure to verify the connectivity check behavior that will be modified in the second patch.

The test infrastructure moves existing alternate refs tests from `t5410-receive-pack-alternates.sh` to a more general `t5410-receive-pack.sh` file, then adds a new test case that verifies `receive-pack` fails when receiving a pack that would leave the repository with missing objects. The test uses a clever `tee` pipe technique to capture and replay pack data, checking for the expected "missing necessary objects" sideband message and verifying the repository remains unconnected after the failed push.

Key technical details include:
- File rename from `t5410-receive-pack-alternates.sh` to `t5410-receive-pack.sh` with updated test description
- New test case demonstrating connectivity check failure scenario
- Verification of both sideband messages (`actual`) and stderr output (`err`)
- Repository state validation using `cat-file -e`
- Test isolation through temporary repository creation and cleanup
- Maintained existing alternate refs test cases in the consolidated file

This test groundwork will support the actual implementation in patch 2, where the connectivity check can be conditionally bypassed while still verifying the safety mechanisms work as intended. The test methodology aligns with existing Git test patterns and has been reviewed by multiple contributors including Patrick Steinhardt and Karthik Nayak.
