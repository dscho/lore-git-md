This is the final patch in a 6-part documentation series improving `--stdin` usage documentation in git-notes and standardizing references to comment characters. The series has focused on making implicit behaviors explicit across several Git commands.

The patch equalizes how `--stdin` is documented between the `copy` and `remove` subcommands of `git-notes`. While both subcommands have supported `--stdin` for years (since 2010 and 2011 respectively), their documentation has been inconsistent. The patch adds the `--stdin` mention to the `remove` subcommand's description (matching `copy`) and consolidates the option documentation to clearly explain the behavior for both subcommands in one place.

A key clarification is that `--stdin` can be combined with command-line object names for `remove`, but not for `copy` - a distinction that wasn't previously documented. The changes follow the series' pattern of using consistent terminology and cross-references, in this case linking back to `core.commentChar` where appropriate.

This completes the series' goal of documenting stdin behavior in git-notes, building on the previous patches that standardized terminology around comment characters and improved option documentation formatting. The changes are focused and well-explained, continuing the series' high standard of documentation improvements.
