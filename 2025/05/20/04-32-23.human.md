This is a feature proposal for MPTCP (Multipath TCP) support in Git, continuing an ongoing discussion about whether and how to implement it. Muhammad Nuzaihan responds to Junio Hamano's skepticism about whether Git needs explicit MPTCP awareness by presenting a concrete use case: uninterrupted cloning/pulling when switching between Ethernet and WiFi connections on a laptop. He argues this is particularly valuable for large repositories.

The email notes several developments since earlier discussion: consultation with Linux MPTCP developers has led to a simplified implementation, removal of environment variable configuration in favor of a `core.mptcp` config setting (defaulting to false for clients), and enabling MPTCP by default for the server side. References to Apple's long-term MPTCP usage and Red Hat's involvement aim to establish production readiness.

While still marked as WIP pending Linux MPTCP developer review, this iteration shows progress in addressing prior technical concerns about implementation complexity. The core philosophical question remains open - whether Git should handle MPTCP explicitly given RFC 6897's transparency principles - but the email grounds the discussion in practical user benefits rather than just technical feasibility.
