Test infrastructure patch consolidating receive-pack connectivity validation tests. This is the first of two patches in a series implementing a GitLab-specific optimization to bypass receive-pack's connectivity checks when Gitaly's transaction system has already validated object connectivity.

The patch renames `t5410-receive-pack-alternates.sh` to `t5410-receive-pack.sh` and expands it with a new test case that verifies receive-pack's default behavior of rejecting packs with missing objects. The test creates a repository with two commits, captures the pack data from `git send-pack`, then attempts to apply it to a new empty repository to trigger the connectivity check failure. The verification includes checking both the sideband error message ("missing necessary objects") and stderr output ("Failed to traverse parents"), plus confirming the target repository remains empty.

This test reorganization follows mailing list feedback to consolidate receive-pack testing into a single file rather than maintaining separate test scripts. The implementation demonstrates careful test construction with proper cleanup (`test_when_finished`), output verification (`test_grep`), and state validation (`cat-file -e`). The test methodology uses `git send-pack` with a tee'd receive-pack to capture pack data, then replays it to isolate the connectivity check behavior.
