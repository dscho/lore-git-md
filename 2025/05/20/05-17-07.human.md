This is the second patch in a finalized series adding a `--skip-connectivity-check` option to `git receive-pack`, primarily for GitLab's Gitaly service. The patch implements the actual feature after the test infrastructure was established in patch 1.

The option allows bypassing `receive-pack`'s expensive object graph validation when the server (like GitLab) can guarantee object connectivity through other means. The implementation includes:
- A hidden `--skip-connectivity-check` flag in `receive-pack`
- Careful preservation of error paths and sideband communication
- Documentation clearly warning about corruption risks
- Test verification that the bypass works while maintaining repository integrity

Patrick Steinhardt's review suggests the documentation could be more precise about what connectivity checks are being skipped (not just ref connectivity but the full transitive closure of objects). He also proposes an additional test to verify the repository isn't accidentally fully connected, ensuring the test properly exercises the bypass scenario.

The patch appears well-constructed with thorough test coverage and clear documentation of the specialized use case. The discussion shows careful attention to edge cases and safety considerations, though some minor documentation and test improvements may still be needed. This is a targeted optimization for GitLab's infrastructure that maintains safety for general Git usage.
