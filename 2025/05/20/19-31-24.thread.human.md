This thread proposed adding Windows-specific update instructions to Git's built-in help output, aiming to guide users of Git for Windows to the correct update mechanism. The initial patch used simple `_WIN32` detection, which would have shown the message for all Windows builds regardless of origin.

The discussion quickly moved beyond technical implementation to fundamental questions about Git's platform neutrality. brian m. carlson strongly opposed the change on principle, arguing that update mechanisms are distribution responsibilities (similar to how Debian handles updates) and that upstream Git should avoid platform-specific messaging. These concerns proved decisive - even exploring more accurate detection methods for Git for Windows specifically was deemed inappropriate.

After considering the feedback, author Aditya Garg has withdrawn the proposal, accepting that such functionality belongs in Git for Windows rather than upstream Git. The thread demonstrates how the project maintains clear boundaries between core functionality and distribution-specific concerns, even when it means passing up seemingly simple user experience improvements. For Windows users, the takeaway is that any future update notifications will need to come through Git for Windows itself rather than the upstream project.
