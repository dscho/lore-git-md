This thread discusses whether to include Windows-specific update instructions in Git's core help output, specifically mentioning `git update-git-for-windows`. The original patch proposed adding this tip for all Windows builds, but brian m. carlson objected, arguing that update mechanisms should be handled by downstream distributions like Git for Windows rather than upstream Git. 

Junio C Hamano sought clarification on whether a more targeted approach might resolve the concerns, but brian m. carlson has now firmly restated their opposition to any form of platform-specific messaging in upstream Git. Their reasoning centers on three points: the lack of a reliable detection mechanism for Git for Windows specifically, the principle that distributions should handle their own update messaging, and concerns about upstream inheriting responsibility for update-related issues in corporate environments.

The discussion has moved beyond implementation details to a fundamental question about Git's design philosophy regarding platform-specific features. With brian m. carlson maintaining a hard line against inclusion and Junio appearing open to exploring solutions, the next likely step is hearing from Johannes Schindelin, the Git for Windows maintainer, whose perspective could help determine whether this feature belongs upstream or should remain downstream. Until then, the thread remains at an impasse.
