This is the first patch in a 2-part series implementing a `--skip-connectivity-check` option for `git receive-pack`, primarily for GitLab's Gitaly service. The patch focuses on test infrastructure consolidation.

The patch renames `t5410-receive-pack-alternates.sh` to `t5410-receive-pack.sh` and expands it to test the existing connectivity check behavior in `receive-pack`. It adds a new test case that verifies `receive-pack` correctly rejects packs that would leave the repository with missing objects, checking both the expected error messages and the repository state.

The test setup creates a repository with two commits, captures the pack data from `git send-pack`, then attempts to apply it to a new empty repository to trigger the connectivity check failure. The test explicitly verifies the "missing necessary objects" message appears in the output and that the target repository remains unchanged.

This test reorganization was requested during the RFC discussion to consolidate receive-pack testing into a single file. The implementation patch (2/2) will introduce the new `--connectivity-check` option that allows bypassing these checks when GitLab's Gitaly service can guarantee connectivity through other means.
