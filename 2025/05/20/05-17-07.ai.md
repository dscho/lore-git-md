This is the second patch in a finalized 2-part series implementing a `--skip-connectivity-check` option for `git receive-pack`, primarily for GitLab's Gitaly service use case. The patch adds the actual implementation after the test infrastructure was established in patch 1.

The implementation introduces a hidden `--skip-connectivity-check` flag that bypasses `receive-pack`'s object graph validation when the server (like GitLab) can guarantee connectivity through other means. The changes include:
- Documentation warning about corruption risks if used without proper external validation
- OPT_HIDDEN_BOOL protection to prevent casual use
- Modified `execute_commands()` to conditionally skip `check_connected()`
- Test case verifying the bypass works while maintaining repository integrity

Patrick Steinhardt's review suggests two minor improvements:
1. Clarifying in documentation that the check verifies both reference connectivity and existence of all reachable objects
2. Adding a test verification that the repository isn't fully connected, ensuring the test properly validates the bypass scenario

The patch appears technically sound with thorough test coverage (building on the infrastructure from patch 1) and clear documentation of the specialized use case. The hidden flag and strong warnings mitigate misuse risks. This completes the series after incorporating earlier feedback, with only minor documentation and test verification refinements suggested.
