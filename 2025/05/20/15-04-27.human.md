Documentation patch clarifying midx tie-breaking behavior, completing a 4-part series fixing integer overflow issues in multi-pack-index repacks.

This final patch in the series addresses documentation rather than code, specifically the rules for how Git selects which pack to use when an object appears in multiple packs. The current docs incorrectly suggest that all ties are broken in favor of the oldest pack (lowest mtime), but Phillip Wood points out that `git multi-pack-index repack` actually depends on the opposite behavior for non-preferred packs - it uses the newest pack (highest mtime) in those cases.

The change makes the behavior explicit in the docs, noting that while the preferred pack is still the oldest by default, objects not in the preferred pack will use the newest available copy. This matches the actual implementation and ensures the multi-pack-index will properly reference objects in newly repacked packs. The patch is straightforward with a clear commit message explaining both the current behavior and why the documentation needs updating. As the final piece of the series, it provides important context for the overflow fixes in the earlier patches by documenting the tie-breaking rules those changes rely on.
