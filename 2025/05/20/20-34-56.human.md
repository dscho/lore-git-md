This is a technical discussion about MPTCP configuration design in Git, continuing the ongoing thread about Linux kernel MPTCP support. Matthieu Baerts (a Linux kernel MPTCP maintainer) responds to Junio Hamano's questions about performance implications and configuration granularity.

The email clarifies that MPTCP in Linux was designed to not impact regular TCP performance, with automatic fallback to TCP when MPTCP isn't available or fails. Baerts explains that servers can safely enable MPTCP by default since they'll only use it when clients request it, while clients may want more selective control. He compares the potential configuration to other Git features like protocol v2 or GPG signing, suggesting both global and per-repository settings might be useful.

Key technical details confirmed include: MPTCP's resilience against middlebox interference, the protocol's minimal overhead (12 bytes per connection request), and Linux's behavior of returning plain TCP sockets when clients don't request MPTCP. The discussion is moving toward practical configuration questions - whether to make MPTCP opt-in or opt-out, and at what granularity (global vs per-repository).

This response provides important implementation assurances while acknowledging the need for user control, keeping the conversation grounded in real-world deployment experience (noting Apple's long-term MPTCP use since 2013). The tone remains collaborative, with Baerts appreciating Git maintainers' careful consideration of the feature's integration.
