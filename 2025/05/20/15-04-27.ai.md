Documentation patch completing a series about multi-pack-index repack behavior and integer overflow fixes. This final patch clarifies the tie-breaking rules for objects that exist in multiple packs but not in the preferred pack, correcting the documentation to match actual behavior.

The patch updates the man page to explain that when no preferred pack is specified, the pack with the lowest mtime becomes the preferred pack, while objects not in that pack use the pack with the newest mtime. This behavior is important for `git multi-pack-index repack` to function correctly, as the current documentation's suggestion of always preferring older packs would prevent the repack from working as intended.

Key technical details include:
- File modified: Documentation/git-multi-pack-index.adoc
- Clarifies behavior when multiple packs contain the same object
- Documents the dual mtime-based selection criteria (oldest for preferred pack, newest for other objects)
- Explains the relationship to `git multi-pack-index repack` functionality
