This is a patch series addressing platform compatibility and potential security issues related to how Git's exec-path is exposed to child processes. The series aims to prevent Git's internal binaries from being accidentally invoked by non-Git programs, which has caused problems particularly on Windows.

The root issue stems from Git's exec-path being added to PATH for child processes, which can lead to unintended execution of Git's internal binaries by editors and other programs. The author cites two prior incidents where this caused problems, including one specifically affecting Git-for-Windows users with Vim. The solution was previously implemented downstream but is being proposed for upstream adoption to benefit all platforms.

The series consists of 4 patches: two preparatory cleanups (with the first being essential for testing), a refactoring to make the fix work uniformly across platforms, and finally the main change that removes git_exec_path() from PATH for non-Git commands. The author notes they haven't tested on Windows and would appreciate help with that, as well as suggestions for fixing a memory leak.

Key technical points include changes to editor.c/h to use strvec for environment handling, modifications to run-command.c to apply prep_childenv consistently, and test updates in t7005-editor.sh. The changes touch core process-spawning behavior and environment handling, which could have wide-ranging implications for editor integrations and subprocess execution.

This appears to be a well-motivated change addressing a real-world compatibility issue, with careful staging of preparatory refactors.
