Performance optimization for MIDX packfile handling, implementing a negative lookup cache for missing packs. This is the second patch in Patrick Steinhardt's v2 series addressing syscall reduction in multi-pack-index scenarios.

The patch introduces a caching mechanism where failed packfile lookups are stored as -1 in the midx->packs[] array, preventing repeated syscalls for the same missing pack. The implementation carefully maintains Git's packfile handling invariants while providing significant performance benefits. Key technical aspects include:

- The prepare_midx_pack() function now checks for and respects the -1 sentinel value before attempting pack lookups
- nth_midxed_pack() properly handles the negative cache by returning NULL for cached misses
- close_midx() is updated to skip the -1 entries during cleanup
- The change uses type-punned pointers (void*)(intptr_t)-1 following Git conventions

Performance measurements show dramatic improvements:
- Syscall reduction from 24,083 to just 83 in the test case
- 4x speedup for `git log --patch` operations
- Maintains all safety constraints identified in previous discussion

The patch builds on Jeff King's suggested approach and represents the consensus solution from the thread discussion. While theoretically the MIDX should always be up-to-date, the practical benefits of this defensive optimization are clear from the benchmarks. The change is well-isolated to midx.c and comes with clear performance data demonstrating its value.
