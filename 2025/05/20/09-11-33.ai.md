This is a test infrastructure patch that's part of a 2-patch series implementing a `--skip-connectivity-check` option for `git receive-pack`. The patch generalizes the existing `t5410-receive-pack-alternates.sh` test file to become a more comprehensive `t5410-receive-pack.sh` that will house all receive-pack related tests.

The main addition is a new test case that verifies receive-pack's connectivity check behavior by:
1. Creating a test repository with two commits
2. Capturing the pack data sent by `git send-pack`
3. Attempting to apply that pack to a new empty repository
4. Verifying the expected error messages about missing objects appear
5. Confirming the repository remains in an unconnected state

Karthik Nayak reviews the changes and notes the test file consolidation is preferable to creating a new file given the current test count. He also points out that while the test_when_finished cleanup doesn't explicitly remove the 'out' file, this is acceptable since tee will overwrite it.

The test methodology uses a tee pipe to capture pack data and verify both sideband messages and stderr output, establishing a pattern that will be used in the series' second patch to test the new skip-connectivity-check functionality. The test verifies the baseline behavior that receive-pack must maintain even with the new option.
