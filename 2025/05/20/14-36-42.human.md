This is a feature proposal to change `git stash`'s default behavior when breaking changes are enabled (GIT_BREAKING_CHANGES). The series, now at version 9 patches, aims to make `stash apply/pop` restore the index by default, addressing a long-standing "footgun" where users lose staged changes. The change would flip the current behavior, requiring `--no-index` to opt out rather than `--index` to opt in.

The author, D. Ben Knoble, notes this aligns with the original design discussion for `git stash` and cites personal experience with the issue. The series includes preparatory test cleanups (patches 1-2), documentation updates (patch 3), the implementation change (patch 4), and extensive test updates across multiple test suites (patches 5-9). The test strategy splits tests into separate versions for old/new behavior rather than using conditional checks, which the author acknowledges might not be optimal for review.

Junio C Hamano has raised significant ergonomic concerns about the change, noting that while the rationale is sound, the longer `--no-index` opt-out might frustrate users more frequently than the current behavior. The proposal remains under discussion, with open questions about whether this warrants being a breaking change and how it might impact existing workflows. The submodule test improvements (t3906) reveal unexpected benefits to submodule handling that may strengthen the case for the change.
