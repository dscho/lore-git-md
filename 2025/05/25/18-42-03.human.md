This is a refactoring patch in the ongoing MIDX (multi-pack-index) improvements series by Taylor Blau. It changes the `prepare_midx_pack()` function to directly return a `packed_git` pointer rather than requiring callers to manually look it up in the MIDX's packs array.

The patch simplifies a common but error-prone pattern where callers had to:
1. Call `prepare_midx_pack()`
2. Handle errors
3. Manually compute the correct pack array index (which gets complicated with incremental MIDX chains)
4. Access the pack through the MIDX's packs array

Now callers get the pack pointer directly from `prepare_midx_pack()`, which internally handles all the MIDX chain traversal logic. The change makes the API both safer (less chance of incorrect array indexing) and more convenient (fewer steps for callers).

The patch updates all callers across midx-write.c, midx.c, and pack-bitmap.c to use the new interface. The changes are mechanical but widespread, touching about 60 lines of code. The core logic remains the same - this is purely an API improvement that better encapsulates the MIDX pack lookup details.

This continues the thread's theme of making MIDX code more maintainable by improving interfaces and reducing direct manipulation of internal MIDX structures. The change was suggested by Jeff King and fits well with the series' focus on correctness and code quality.
