This is the second patch in a two-part bugfix series addressing memory leaks when loading corrupt bitmaps. It adds test coverage for the leak scenarios fixed in the first patch.

The patch introduces a new test helper `test-tool bitmap list-commits-offset` that precisely reports the file positions of bitmap entries (commit OID, XOR offset, flags, and EWAH bitmap data). This enables targeted corruption of specific fields in bitmap files for testing. The main test case uses this to corrupt the XOR offset field of the first bitmap entry, which would previously trigger memory leaks that are now fixed.

The implementation tracks bitmap entry positions by extending the stored_bitmap struct to include file offsets when in test mode. The test helper then outputs these positions in a parseable format. The test case verifies the bitmap loading code properly handles corruption without leaking memory.

This completes the series by providing robust test coverage for the memory leak fixes. The approach of structured corruption testing via a dedicated helper is more maintainable than the direct file manipulation used in earlier versions, as noted in the thread discussion. The patch has already been reviewed and approved by Jeff King and Junio Hamano in previous iterations.
