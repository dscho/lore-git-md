This is the second patch in a bugfix series addressing memory leaks in pack-bitmap.c, focused on improving test coverage for corrupt bitmap scenarios. The patch introduces a new test helper `test-tool bitmap list-commits-offset` that provides structured access to bitmap entry metadata (commit OID, field offsets) to enable precise corruption testing.

The key technical additions are:
1. A new `stored_bitmap_tag_pos` struct that extends `stored_bitmap` with position tracking
2. The `test_bitmap_commits_offset()` function that outputs bitmap entry field positions
3. A test case in t5310 that uses the helper to corrupt the XOR offset field and verify proper handling

The test infrastructure allows targeted corruption of specific bitmap fields (like XOR offsets) that trigger memory leak paths, replacing the fragile direct file manipulation approach from v2. The implementation tracks file positions during bitmap loading via the new `map_pos` parameter in `store_bitmap()`, enabled by the `tag_pos_on_bitmap` flag.

This complements the first patch's leak fixes by providing maintainable test coverage for the error paths. The approach has been reviewed and approved by Jeff King and Junio C Hamano, with the thread showing consensus on both the technical solution and testing methodology. The series appears complete with no outstanding technical objections.
