Bugfix addressing a memory leak in the pack-bitmap loading code. This is the first patch in a two-part series fixing memory leaks when loading corrupt bitmaps.

The patch simplifies error handling in `load_bitmap()` by removing redundant cleanup code. Currently, if bitmap loading fails partway through, the function's `failed` label would clean up some resources but leave EWAH bitmaps allocated, causing a leak. The fix replaces all `goto failed` with direct `return -1`, letting the caller's `free_bitmap_index()` handle cleanup uniformly. This removes 17 lines of error-handling code while maintaining safety.

The change is well-motivated by the leak scenario and has been reviewed across multiple iterations, with Jeff King confirming the approach. The patch stands alone as one of two independent fixes in the series - this one handles the general `load_bitmap()` case while the second patch adds test coverage. The solution follows Git's convention of centralized cleanup rather than per-error-path handling.
