This is a feature patch introducing a new `git last-modified` command, part of an ongoing series that has evolved through mailing list discussion. The command shows which commit last modified each file or directory in the repository, similar to `git blame` but operating at the tree level rather than line-by-line.

The patch establishes the core functionality with thorough test coverage, including handling of recursive directory traversal (`-r` flag), subdirectory scoping, revision ranges, and merge cases. The implementation uses a hashmap to track paths and their final states, then walks history backwards to find modification points. Documentation marks the command as experimental.

Justin Tobler raises several documentation and implementation questions in his review:
- Clarification needed about default behavior with trees (whether they're shown without `-r` or `-t`)
- A minor documentation typo ("are include in the")
- Suggests moving builtin-specific code out of the shared `last-modified.[ch]` files
- Requests more documentation comments in the header file
- Questions whether argument parsing belongs in the shared initialization function

The patch appears well-structured with comprehensive tests, though the review identifies some areas where the interface and implementation boundaries could be clarified. This is patch 1 of a series that has already incorporated significant feedback from other contributors regarding naming, architecture, and performance optimizations.
