This is the second patch in a bugfix series addressing memory leaks in pack-bitmap.c, specifically adding test coverage for corrupt bitmap handling. The patch introduces a new test helper and test case to verify proper cleanup when loading corrupted bitmaps.

The patch adds `test_bitmap_commits_offset()` to pack-bitmap.c, which extends the existing test infrastructure with position tracking for bitmap entries. A new `test-tool bitmap list-commits-offset` command outputs structured data including commit OID and field positions (commit index, xor_offset, flags, and EWAH bitmap positions) for each bitmap entry. This enables targeted corruption testing by knowing exactly where to modify the bitmap file.

The test case in t5310 uses this helper to corrupt the xor_offset field of the first bitmap entry, then verifies Git can safely handle this corruption during bitmap loading. The test checks that `git rev-list --use-bitmap-index` still produces correct results despite the corruption, demonstrating proper cleanup of partially-loaded bitmaps.

Key technical components include:
1. The new `stored_bitmap_tag_pos` struct that extends `stored_bitmap` with position tracking
2. Modified `store_bitmap()` to optionally track positions when `tag_pos_on_bitmap` is set
3. The test helper that outputs field positions in a parseable format
4. The test case that uses `dd` to precisely corrupt the bitmap file at the xor_offset position

This complements the first patch's leak fixes by providing verifiable test coverage for corruption scenarios. The approach maintains the series' theme of centralized cleanup while adding instrumentation for testing edge cases. The test infrastructure could be reused for future bitmap corruption testing.
