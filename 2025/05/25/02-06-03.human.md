Bugfix addressing a memory leak in pack-bitmap.c when loading corrupt bitmaps. This is the first patch in a two-part series that has already gone through several rounds of review.

Taylor Blau fixes a case where partially-loaded bitmap entries would leak memory if `load_bitmap_entries_v1()` failed. The issue occurred because the error handling path in `load_bitmap()` was prematurely cleaning up data structures that the caller's `free_bitmap_index()` would normally handle. The solution is straightforward - remove the redundant cleanup code and let the caller handle all error cases consistently.

The patch simplifies the code by replacing all `goto failed` jumps with direct `return -1` statements, reducing the function by 17 lines while making the error handling more robust. Reviewers Jeff King and Junio C Hamano have already approved this approach in previous iterations, noting it's a rare case where fixing a bug actually removes code rather than adding it.

This change is part of a coordinated effort with Lidong Yan's follow-up patch that adds comprehensive test coverage using a new test helper tool. The series appears well-vetted and ready for inclusion, having addressed all technical concerns from reviewers.
