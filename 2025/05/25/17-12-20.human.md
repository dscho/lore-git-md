This is the second patch in a two-part series improving `git send-email` behavior, focusing on logging improvements when Outlook modifies Message-IDs. The first patch (already submitted) fixed threading issues when editing the first patch in a series.

The current patch addresses a specific logging quirk: when Outlook rewrites a Message-ID (which it sometimes does), the final header log would display the original ID rather than the modified one. The fix updates the `$header` variable to show the new Message-ID consistently. It also makes the "Message-ID changed" notice debug-only, since the final header log will show the correct ID anyway.

The changes are minimal (4 lines in `git-send-email.perl`) and well-contained, touching only the Outlook-specific Message-ID handling in the `send_message` subroutine. This appears to be a straightforward quality-of-life improvement that makes the logs more accurate when interacting with Outlook servers. The patch builds logically on the threading fixes from part 1 of the series, though it addresses a separate concern.
