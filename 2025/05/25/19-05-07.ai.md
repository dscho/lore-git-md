Bugfix for `git send-email` threading behavior when editing messages. This is part 1 of a 2-patch series (no cover letter seen).

The patch addresses an issue where editing a message in `git send-email` causes the message number in the Message-ID to increment incorrectly. The core problem occurs in the `process_file` subroutine, which increments `$message_num` each time it runs - this happens both when sending subsequent messages in a thread (correct) and when re-processing an edited message (incorrect). The bug particularly affects shallow threading logic which expects the first message to have `$message_num = 1`.

Kristoffer Haugsbakk's testing shows the issue manifests when using `--confirm=always` and editing messages, where the Message-ID's sequence number (like the "6" in `<20250525181003.40129-6-...>`) increments unnecessarily. While simple cases may still thread correctly, the patch author demonstrates this can break threading when the first message in a series is edited.

The reproduction steps involve sending a series with `--in-reply-to` and editing the first patch, observing the Message-ID's sequence number increment from 1 to 2. The fix (in the follow-up patch) would presumably add logic to preserve the original message number when re-processing an edited message rather than treating it as a new message in the sequence.
