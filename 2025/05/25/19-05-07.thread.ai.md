Thread summary:

Bugfix series for `git send-email` threading behavior when editing messages. The thread originates from Kristoffer Haugsbakk reporting an issue where editing messages in `git send-email` causes incorrect Message-ID sequence numbering, particularly affecting shallow threading logic. The problem occurs in `process_file` which increments `$message_num` both for new messages (correct) and when re-processing edited messages (incorrect). This manifests when using `--confirm=always` and editing messages, where the Message-ID's sequence number (e.g. the "6" in `<20250525181003.40129-6-...>`) increments unnecessarily. The bug can break threading when the first message in a series is edited, as demonstrated by reproduction steps showing sequence numbers incrementing from 1 to 2 after editing. The fix (coming in part 2) will need to preserve original message numbers when re-processing edited messages rather than treating them as new messages in the sequence. The thread currently consists of part 1 describing the problem; part 2 with the actual fix is expected to follow.
