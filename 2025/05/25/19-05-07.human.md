Bugfix for `git send-email` threading behavior when editing messages.

This patch addresses an issue where editing a message in `git send-email` causes the message number to incorrectly increment, which can break email threading. The problem occurs because the `process_file` subroutine increments the message counter each time it runs, even when processing the same message during an edit session rather than moving to a new message in a thread.

The author explains that this particularly affects "shallow thread" mode where the first message should have number 1, but gets bumped to 2 if edited. While the issue might seem minor in simple cases (as noted by Kristoffer Haugsbakk in the thread), it can cause threading problems in more complex scenarios. The patch includes clear reproduction steps showing how to trigger the bug.

The discussion reveals some confusion about the exact impact, with the initial reviewer struggling to understand the problem from the commit message. This suggests the explanation could be clearer about the specific threading scenarios affected. The patch appears to be a straightforward fix for a real but somewhat subtle issue in email message numbering.
