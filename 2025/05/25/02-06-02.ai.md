This is the v3 cover letter for a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The series has evolved through three versions with input from multiple contributors (Lidong Yan and Taylor Blau) and reviewers (Jeff King, Junio C Hamano).

The key technical change in this version is the introduction of a new test helper (`test-tool bitmap list-commits-offset`) to precisely locate bitmap entry fields for targeted corruption testing, replacing the more fragile direct file manipulation approach from v2. The helper outputs structured data (commit OID, offsets for commit index, XOR offset, flags, and EWAH bitmap) to enable reliable corruption of specific fields that trigger the memory leak paths being fixed.

The series now consists of two patches:
1. Taylor Blau's fix for EWAH bitmap leaks in `load_bitmap()`, simplifying error handling by removing redundant cleanup code
2. Lidong Yan's test addition using the new helper to validate the leak fixes by corrupting XOR offsets

The thread context shows consensus has been reached on both the technical approach (centralized cleanup via `free_bitmap_index()`) and test methodology. The v3 changes focus on improving test robustness while maintaining the leak detection capability. The cover letter notes the patches have been reordered for logical progression and commit messages revised for clarity.

This appears to be the final iteration of a well-reviewed series that addresses real memory safety issues while demonstrating careful attention to test design principles. The addition of the structured test helper in v3 resolves earlier concerns about test fragility and provides a maintainable way to validate the bitmap loading paths.
