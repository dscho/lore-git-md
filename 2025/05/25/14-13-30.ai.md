This is a bug report about a regression in Git's locking behavior during maintenance operations. The reporter describes a sequence of Git commands that worked in previous versions but fails in Git 2.47.2 with a lock conflict when checking out a branch after `git fetch`. 

The key observation is that `git fetch` now triggers an auto-maintenance process with a `--detach` flag, which appears to run in parallel with the main script. This creates a `HEAD.lock` file that prevents the subsequent `git checkout` from succeeding. The reporter provides trace logs showing the maintenance process running concurrently with the checkout attempt.

The issue appears to be a regression introduced in Git 2.47.2 where the new detached maintenance mode doesn't properly coordinate its locking with other Git operations. The reporter's script had worked reliably before this version. The bug affects the interaction between maintenance and core repository operations, specifically around reference updates and locking.

The report is well-documented with a clear reproduction sequence and evidence of the maintenance process interference. This looks like a legitimate regression that would affect any automated scripts running similar command sequences. The maintenance subsystem's locking behavior when run in detached mode will need to be examined to resolve the conflict with concurrent operations.
