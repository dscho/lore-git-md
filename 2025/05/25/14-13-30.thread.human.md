This thread reports a regression in Git 2.47.2 where background maintenance operations running in detached mode (`--detach`) create lock conflicts with concurrent Git commands. The specific case involves `git fetch` (which now runs auto-maintenance in detached mode) followed by `git checkout`, where the maintenance process holds a `HEAD.lock` that blocks the checkout. Trace logs confirm the interference, showing this represents a clear regression from previous versions.

Patrick Steinhardt has acknowledged the report, confirming it matches a known issue with detached maintenance operations. He indicates this is part of a broader problem with the maintenance subsystem's locking behavior and has stated he will be sending a patch series in the coming days to address it. While the exact solution isn't detailed yet, the response suggests this is actively being worked on by a core contributor familiar with the maintenance subsystem. The issue remains open but appears to be on track for a fix.
