This thread reports a regression in Git 2.47.2 where automated maintenance operations interfere with normal repository workflows. The reporter demonstrates that `git fetch` now triggers a background maintenance process with `--detach`, which creates a `HEAD.lock` file that conflicts with subsequent operations like `git checkout`. Trace logs confirm the maintenance process runs concurrently with the checkout attempt, causing the failure.

The issue appears specific to the new detached maintenance mode's locking behavior, which doesn't properly coordinate with other Git operations. This regression affects any automated scripts that perform sequences like fetch-then-checkout, which had worked reliably before 2.47.2. The report provides clear reproduction steps and evidence of the maintenance interference, making this a high-priority issue for the maintenance subsystem maintainers to address the locking coordination in detached mode.
