Classification: Discussion response regarding Microsoft Graph API support for `git send-email`

Brian m. carlson responds to Aditya Garg's RFC proposing Microsoft Graph API integration for `git send-email`, expressing strong opposition to adding proprietary email transport methods to Git. The response argues that Git should only support standard, well-specified email protocols (SMTP and sendmail binary), citing Microsoft's history of proprietary formats like TNEF and MAPI as examples of what to avoid.

The reply acknowledges the performance and Message-ID preservation benefits Aditya described, but positions these as Microsoft-specific problems that should be solved by improving their SMTP implementation rather than adding new API support in Git. The author shares their own positive experience with alternative SMTP providers (Postfix, Dovecot, and Google's SMTP) to counter the performance claims.

The response leaves a narrow path forward, suggesting that if the Graph API were standardized through an RFC or similar process with multiple implementations, it might be reconsidered. This appears to be the first substantive technical discussion of the RFC, setting up a potential debate about Git's stance on proprietary integrations versus solving real-world usability problems for Microsoft-hosted email users.
