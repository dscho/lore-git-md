This is a correctness patch for the MIDX (multi-pack-index) subsystem, adding assertions to guard against potential issues with incremental MIDX chains. Taylor Blau identifies a theoretical vulnerability in practice that's currently safe due to an existing guard in `midx_repack()`, but wants to make the safety guarantees more explicit.

The patch adds `ASSERT()` statements to three functions in midx-write.c that handle pack selection for repacking operations. These assertions make it clear these functions should never be called with an incremental MIDX (one with a base_midx pointer), since the calling function `midx_repack()` already rejects such cases. While the current code is technically correct, the assertions serve as documentation of the expected invariants and would catch any future misuse.

This is part of Taylor's ongoing series to improve MIDX correctness and follows earlier discussions about MIDX chain management. The change is low-risk since it only adds assertions to codify existing behavior rather than changing any logic. The patch demonstrates careful attention to edge cases in MIDX handling and follows the thread's theme of strengthening MIDX invariants.
