Feature patch extending `git send-email` with Microsoft Graph API support, following up on the initial RFC with additional implementation details.

This email provides a credential helper implementation for testing purposes, supplementing the core Graph API integration described in the original RFC. The helper (hosted on GitHub) handles OAuth2 token generation, which is a key requirement for the Graph API authentication flow. This appears to be a companion piece to the main patch series rather than a new version - the credential helper would presumably be used alongside the `sendemail.useMSGraph` configuration option introduced in the RFC.

The implementation maintains focus on solving the two core problems identified in the RFC: slow SMTP handshake times (8-10s reduced to ~1s for multiple patches) and Message-ID preservation. The credential helper approach aligns with Git's existing patterns for sensitive data handling, though its security model would need review like the rest of the OAuth2 integration.

Technical details worth noting for future reference include:
- Separate credential helper repository suggests this may be intended as optional/companion tooling
- Maintains the three new configs from RFC (`useMSGraph`, `MSGraphUser`, `MSGraphToken`)
- Implicitly confirms REST API approach over SMTP for Microsoft-hosted mail
- Testing instructions now available via external helper

This appears to be a well-considered extension to the email submission system, though its Microsoft-specific nature and additional Perl dependencies may prompt discussion about mainline suitability. The credential helper availability should facilitate testing while the core patch undergoes review.
