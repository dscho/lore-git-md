Thread identity: RFC patch series from Aditya Garg proposing Microsoft Graph API support for `git send-email`, addressing performance and Message-ID preservation issues with Microsoft SMTP servers, now with credential helper implementation, facing first substantive objections.

Core problem/goal: Replace SMTP transport for Microsoft-hosted email with direct Graph API integration to solve slow connection times (8-10s handshake reduced to ~1s) and forced Message-ID replacement, while maintaining all existing `git send-email` functionality. New credential helper provides OAuth2 token generation capability required for Graph API authentication. Now contested on standards-compliance grounds.

Current status: Initial RFC version demonstrating working implementation with three new configs (`sendemail.useMSGraph`, `sendemail.MSGraphUser`, `sendemail.MSGraphToken`) and external credential helper for OAuth2 token handling. Performance measurements show ~1s send times versus 8-10s via SMTP. brian m. carlson has raised fundamental objections to the approach based on protocol standardization principles.

Key technical details:
- Core implementation:
  - New Perl dependencies: MIME::Base64, HTTP::Tiny
  - Message processing: Base64 encoding, CRLF conversion
  - Fallback: Maintains SMTP compatibility when Graph disabled
  - API requirements: MIME message encoding, REST error handling
- Credential helper:
  - Separate GitHub-hosted tool for OAuth2 token generation
  - Follows Git credential helper patterns
  - Enables complete authentication flow testing

Open questions:
- Fundamental appropriateness of proprietary API integration vs Git's standards-based approach
- Acceptability of new Perl dependencies (MIME::Base64, HTTP::Tiny)
- Security review of OAuth token handling in both core and helper
- Core vs helper tool placement (mainline vs external)
- Documentation completeness for both components
- Microsoft-specific feature appropriateness for mainline Git
- Long-term maintenance of credential helper

Participant positions:
- brian m. carlson: Strong opposition based on protocol standardization and vendor neutrality principles, citing historical avoidance of proprietary formats like TNEF/MAPI. Suggests Microsoft should fix their SMTP implementation rather than Git adopting proprietary workarounds. Leaves open possibility if Graph API becomes an open standard.

Related work: Aditya's prior work on `git send-email` SMTP/IMAP improvements. Microsoft's email API documentation. Git's existing helper tool patterns. Historical context of Git's avoidance of proprietary email formats.
