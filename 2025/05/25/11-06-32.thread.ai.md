Thread identity: RFC patch series from Aditya Garg proposing Microsoft Graph API support for `git send-email`, now pivoting to standards-compliant alternatives after substantive objections from multiple contributors.

Core problem/goal: Originally aimed to replace SMTP transport for Microsoft-hosted email with direct Graph API integration for performance (1s vs 8-10s handshake) and Message-ID preservation. Now shifting focus to external solutions that maintain Git's standards-based approach while still addressing the performance issues with Microsoft SMTP implementation.

Current status: Author concedes to objections about proprietary protocol integration. Proposal now considers either an external SMTP-to-Graph bridge (keeping proprietary component outside Git core) or leveraging existing sendmail command capabilities. Performance measurements showing 8-10s SMTP handshake remain valid but no longer justify violating Git's protocol standardization principles.

Key technical details:
- Original implementation (now abandoned):
  - Required new Perl dependencies (MIME::Base64, HTTP::Tiny)
  - Included credential helper for OAuth2 token generation
  - Maintained SMTP fallback
- New direction considerations:
  - External SMTP-to-Graph proxy service
  - Existing sendmail command integration
  - No new core dependencies
- Preserved knowledge:
  - Base64 encoding requirements
  - CRLF conversion needs
  - REST error handling patterns

Open questions:
- Whether Microsoft will improve their SMTP implementation
- Potential for Microsoft to standardize Graph API
- Relative merits of SMTP bridge vs sendmail command approaches
- Maintenance expectations for any external bridge component
- Documentation needs for alternative solutions

Participant positions:
- brian m. carlson: Maintains strong opposition to proprietary protocol integration, position now accepted by author.
- Drew DeVault: Continues advocating standards-based approach, suggested external bridge alternative.
- Aditya Garg: Concedes to objections, pivots to standards-compliant solutions while preserving performance goals.
