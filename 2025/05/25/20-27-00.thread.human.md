This thread documents a patch series converting Git's manpages to a new synopsis-style format, part of Jean-Noël Avila's ongoing documentation standardization effort. The series, submitted via GitGitGadget as PR #1927, now includes six of its planned nine patches, with the latest focusing on merge-related configuration documentation.

The first five patches standardized the formatting for `git-checkout`, `git-merge`, and their related options and strategies, while maintaining all technical content. Patch 4 notably improved the explanation of the `--allow-unrelated-histories` option, and patch 5 comprehensively converted the merge strategy documentation. The newest addition, patch 6/9, applies the same mechanical conversion to merge configuration options in `merge.adoc` and `fmt-merge-msg.adoc`, standardizing how options like `merge.conflictStyle` and `merge.directoryRenames` are presented.

So far, the series has touched five documentation files across six patches, with a minimal net line count impact (-3 lines in the first four patches, +4 in patch 6) while significantly improving consistency. The changes follow the project's established documentation conventions, wrapping option names in backticks, using `_<placeholder>_` syntax for variables, and formatting conflict markers with `+` signs. The remaining patches will complete the conversion for `git-switch`, `git-mergetool`, and checkout config references.
