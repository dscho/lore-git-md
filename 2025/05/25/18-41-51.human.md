This is a bugfix patch addressing an out-of-bounds array access in the MIDX bitmap handling code. The issue occurs when loading incremental MIDX layers where a pack file is missing - the warning message would incorrectly index into the pack_names array, potentially causing a segfault.

The patch fixes a regression introduced in commit f31a17cea5 that updated the MIDX bitmap code to handle incremental layers but didn't properly adjust the pack_names array indexing when looking up missing packs. The fix is straightforward - subtracting the number of base packs from the index when accessing pack_names.

This is part of Taylor Blau's ongoing series (1/5) improving MIDX and bitmap handling, building on previous discussions about performance optimizations and correctness in the multi-pack-index subsystem. The patch demonstrates careful attention to edge cases in the incremental MIDX implementation and maintains compatibility with the queued performance improvements.

The change is small but important for correctness, particularly as the MIDX subsystem evolves to handle more complex incremental cases. It shows the kind of subtle bug that can emerge when layering new functionality on existing systems, and the fix follows the established pattern of the surrounding code.
