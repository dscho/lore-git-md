This is a bugfix patch addressing an out-of-bounds array access in the MIDX bitmap handling code. The patch corrects a warning message that could trigger a SIGSEGV when trying to report a missing pack file in incremental MIDX bitmaps.

The issue stems from a mismatch in array indexing when handling MIDX layers - the warning message was using the wrong offset into the `pack_names` array when reporting missing packs in non-base MIDX layers. The fix adjusts the index calculation to properly account for packs in base layers.

Key technical details:
- The bug was introduced when incremental MIDX bitmap support was added in commit f31a17cea5
- The problematic code path occurs when loading a MIDX bitmap and encountering a missing pack file
- The fix modifies the warning message in `open_midx_bitmap_1()` to properly index into `pack_names`
- The correction subtracts `num_packs_in_base` from the index when accessing pack names

This patch is part of Taylor Blau's ongoing work to improve MIDX and bitmap handling, building on previous performance optimizations and correctness fixes in this area. The change is narrowly focused but important for stability, as it prevents a potential crash when reporting warning messages about missing pack files.
