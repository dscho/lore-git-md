This is a refactoring and API improvement series for the MIDX (multi-pack-index) subsystem, building on earlier performance optimizations. The series focuses on making `prepare_midx_pack()` safer and more ergonomic by having it directly return a `packed_git` pointer rather than requiring callers to handle pack ID translation themselves.

The series begins with four preparatory cleanups that fix minor issues and simplify MIDX-related code:
1. Fixes a broken warning message in pack-bitmap.c when a MIDX'd pack is missing
2. Adds guards against incremental MIDXs in `want_included_pack()`
3-4. Simplify and refactor `fill_packs_from_midx()` by extracting its inner loop

The main change comes in patch 5, which modifies `prepare_midx_pack()` to return a `packed_git` pointer directly. This makes the API less error-prone when dealing with incremental MIDXs by handling pack ID translation internally. The change affects several MIDX-related functions and their callers.

Taylor Blau suggests this could be the first step toward further encapsulation of MIDX internals, potentially making the entire structure opaque to external callers in the future. The series maintains compatibility with the queued performance optimizations while improving the API's safety and usability.

Key technical details:
- Changes span midx-write.c, midx.c, midx.h, and pack-bitmap.c
- Introduces more direct handling of `packed_git` pointers
- Preserves all existing functionality while making error cases harder to misuse
- Sets up potential future work to further encapsulate MIDX internals
