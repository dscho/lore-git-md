This is a feature patch in the ongoing `imap-send` authentication improvements series, adding PLAIN authentication support for the OpenSSL backend. The patch implements RFC 4616-compliant PLAIN authentication, which is commonly used with app passwords by email providers.

The implementation introduces a new `plain_base64()` helper that properly formats and encodes the username/password combination according to the RFC, along with an `auth_plain()` function to handle the IMAP protocol exchange. The documentation is updated to reflect that PLAIN is now available for OpenSSL users alongside the existing CRAM-MD5, OAUTHBEARER and XOAUTH2 methods.

Key technical details include:
- New `AUTH_PLAIN` capability flag in the IMAP protocol handling
- `plain_base64()` helper implementing the RFC 4616 encoding scheme
- Proper error handling for both base64 encoding and socket write failures
- Integration with the existing authentication method selection logic
- Documentation update showing PLAIN as available for OpenSSL users

This completes the authentication method parity between curl and OpenSSL backends, addressing a gap where PLAIN was previously only available. The implementation follows the same pattern as the recently added OAuth2.0 support, with proper memory management and error handling. The patch fits cleanly into the v5 series which has already addressed critical configuration parsing bugs and memory leaks in other authentication methods.
