This is a bugfix patch for `git send-email` that addresses a threading issue when editing messages. It's part of a v3 series (1/2) that builds on prior discussion about fixing incorrect threading behavior.

The core issue occurs when editing the first message in a series - the message numbering gets incremented, breaking the shallow thread logic that expects $message_num to remain 1 for the first message. The patch fixes this by decrementing both $message_num and $message_id_serial when either skipping or editing a message, ensuring proper numbering when the process restarts.

The solution is straightforward - it adds counter decrements in two key places in send_message(): when choosing not to send a message ('n') and when editing a message ('e'). The commit message clearly explains the problem and solution, including the interaction between these variables and the threading logic.
