Feature addition to `imap-send` providing a command-line override for the target IMAP folder. This is part 5/6 of a series that has already addressed critical configuration parsing bugs, added OAuth2.0 support, and fixed memory leaks in authentication paths.

The patch introduces a new `--folder` (`-f`) option that overrides the `imap.folder` configuration setting, allowing users to specify the destination folder at runtime. The implementation follows the established pattern for command-line options in `imap-send.c`, with proper memory management (freeing the old folder string before assigning the new one). Documentation updates clearly explain the precedence (command-line over config) and provide example usage.

This builds on the series' earlier fix for folder handling (where `cfg->folder` was incorrectly NULLed during config parsing) by giving users direct control. The change is straightforward with clear documentation, though it doesn't include new tests - likely because the existing IMAP test infrastructure doesn't easily support folder-specific testing. The patch maintains consistency with the series' focus on usability improvements while preserving the architectural changes from prior iterations.
