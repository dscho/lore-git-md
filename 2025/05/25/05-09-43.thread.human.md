Lidong Yan's patch series addressing memory leaks in pack-bitmap.c's boundary traversal logic has reached its final approved version (v5) and is ready for merging. The core fix ensures proper cleanup of the `roots_bitmap` in `find_boundary_objects()` by making `bitmap_free()` unconditional, correcting what appears to have been an oversight in the original implementation. This prevents memory leaks whether the `cascade_pseudo_merges_1()` operation succeeds or fails.

The solution includes a new test case in t5333 that demonstrates the leak scenario while maintaining shell portability and using ASAN for detection. The test creates a simple repository with commits A and B, configures pseudo-merges, and verifies boundary traversal behavior through direct commit counting. Reviewers including Junio Hamano, Patrick Steinhardt, and Taylor Blau have validated both the technical approach and test methodology, with Eric Sunshine ensuring shell script portability.

All open questions have been resolved, and the series has achieved consensus approval. The patch not only fixes the immediate issue but also establishes a useful pattern for ASAN-based leak detection in future bitmap-related tests. With maintainer approval confirmed, this work is now positioned for integration into Git's main development branch.
