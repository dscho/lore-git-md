This is a bugfix patch in the `imap-send` series, addressing a memory leak in the CRAM-MD5 authentication path. The patch ensures that the `response` buffer is properly freed when socket writes fail during authentication. This was identified as part of a comprehensive review of memory management in the authentication code paths.

The change is straightforward - it plugs a leak that could occur if `socket_write()` failed to send the full response. The fix wraps the error return with a `free(response)` call, matching the existing cleanup that happens on the success path. This completes the memory leak fixes for CRAM-MD5 that were identified earlier in the thread's review process.

This patch is part of a larger v5 series that adds OAuth2.0 support and other improvements to `imap-send`. The series has undergone thorough review, with this particular issue being caught by Ben Knoble during validation of the CRAM-MD5 implementation. The change is small but important for correctness, and fits into the series' broader goal of robust authentication handling.
