Bugfix for `imap-send` configuration parser regression that NULLs out `cfg->folder` incorrectly. This is the first patch in a v5 series that adds OAuth2.0 support and other `imap-send` improvements.

The bug was introduced in commit 6d1f198f34 ("imap-send: fix leaking memory in `imap_server_conf`") where the configuration parser would incorrectly free and NULL the `folder` field when processing other IMAP settings (`user`, `pass`, `tunnel`, `authmethod`). This has rendered `git-imap-send` unusable since Git 2.46.0. The patch fixes this by properly freeing and NULLing the correct struct fields for each configuration option.

The thread context shows this is part of a larger effort to modernize `imap-send` with OAuth2.0 support and other authentication methods, but this particular patch focuses on fixing a critical regression. The bug appears to have gone unnoticed due to `git-send-email` being more commonly used. The fix is straightforward - changing the incorrect `FREE_AND_NULL(cfg->folder)` calls to target the correct struct fields instead.

This is a well-justified bugfix with a clear explanation of the regression and its impact. The patch is minimal (4 line changes) and directly addresses the issue. As the first patch in the series, it establishes a solid foundation for the subsequent authentication improvements by fixing this configuration parsing bug.
