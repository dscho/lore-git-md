This is the second patch in a bugfix series addressing memory leaks in pack-bitmap handling. It adds test coverage for corrupt bitmap loading scenarios, complementing the first patch's code fixes.

The patch introduces a new test helper `test-tool bitmap list-commits-offset` that reveals the internal structure of bitmap files by reporting field positions (commit OID, xor_offset, flags, and EWAH bitmap data). This enables targeted corruption testing by precisely modifying specific fields in bitmap files. The main test case intentionally corrupts the xor_offset field of the first entry and verifies Git handles it gracefully.

The implementation extends the bitmap storage with position tracking (via `stored_bitmap_tag_pos`) and adds the new test command that outputs these positions. The test infrastructure will help catch regressions in bitmap error handling, particularly for the memory leak fixes in the first patch of the series.

This appears to be a well-constructed test addition that directly supports the series' goal of robust bitmap error handling. The test helper is narrowly focused on enabling corruption testing without adding unnecessary complexity, and the test case verifies both the specific leak scenario and general bitmap loading resilience. The patch has already gone through several review iterations (now at v4) with no outstanding technical concerns.
