Bugfix series addressing memory leaks in pack-bitmap.c's error paths, now in its fourth version. This iteration follows up on previous rounds that established consensus around using centralized cleanup via `free_bitmap_index()` rather than per-error-path handling.

The series contains two patches:
1. Taylor Blau's fix that prevents `load_bitmap()` from nulling `bitmap_git->bitmap` on failure, eliminating a memory leak scenario. This simplifies error handling by removing redundant cleanup code.
2. Lidong Yan's test case that uses clang's leak sanitizer to verify proper handling when loading corrupt bitmaps.

The v4 changes are minor - the first patch's commit message was updated for clarity (changing the function name reference from `load_bitmap_entries_v1` to `load_bitmap`), while the test patch remains unchanged from v3. The test infrastructure introduced in v3 remains, providing robust validation through targeted corruption scenarios rather than fragile file manipulation.

The series appears technically sound, having addressed all review feedback from Jeff King and Junio C Hamano in previous rounds. The changes are focused and well-explained, with the test coverage providing confidence in the fix.
