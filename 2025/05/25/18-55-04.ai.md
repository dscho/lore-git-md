Feature patch completing the `imap-send` backend selection series by adding config-based control over curl/OpenSSL choice. This final patch in the v5 series introduces `imap.usecurl` configuration to set the default backend preference, complementing the existing `--[no]-curl` command-line flags. The implementation follows the established pattern of CLI options overriding config settings, with proper handling of build-time constraints (`USE_CURL_FOR_IMAP_SEND` and `NO_OPENSSL`). Documentation updates clarify the precedence rules and conditional behavior. The change integrates cleanly with the existing configuration parser in `imap-send.c`, adding just two lines of implementation code while maintaining the series' focus on robust memory management and user control. This completes the architectural work started in earlier patches, providing both runtime (`--curl`) and persistent (`imap.usecurl`) ways to select between curl's native OAuth2.0 support and OpenSSL's authentication methods. The patch maintains backward compatibility and properly documents the interaction between build options, configuration, and command-line overrides.
