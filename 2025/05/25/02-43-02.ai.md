This is a bugfix patch addressing memory leaks in pack-bitmap.c's bitmap loading paths, specifically when `load_bitmap()` fails mid-operation. The patch is part of a v4 series (1/2) that has already undergone significant review and refinement.

The key change removes redundant cleanup code in `load_bitmap()` by replacing all `goto failed` jumps with direct `return -1` statements. This simplification works because callers (`prepare_bitmap_walk()` and `prepare_bitmap_git()`) already handle cleanup via `free_bitmap_index()`. The patch eliminates ~17 lines of error-handling code while maintaining safety, as the centralized cleanup path properly handles EWAH bitmap deallocation.

The change fixes a specific leak scenario where partial bitmap loading (followed by failure) would previously orphan successfully-loaded entries due to premature destruction of the bitmap map. The solution aligns with the thread's technical consensus to rely on caller-side cleanup rather than per-error-path handling.

This version generalizes the commit message from v3 to explicitly cover the broader `load_bitmap()` case rather than just `load_bitmap_entries_v1()`. The patch has been reviewed by Jeff King and Junio C Hamano, with no outstanding technical objections remaining in v4. The change demonstrates the rare case where a fix actually removes code while improving correctness.
