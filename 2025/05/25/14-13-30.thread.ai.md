Bug report identifies a regression in Git 2.47.2 where maintenance operations running in detached mode (`--detach`) create lock conflicts with concurrent Git commands, specifically `HEAD.lock` conflicts during sequences like `git fetch` followed by `git checkout`. Patrick Steinhardt confirms this matches a known issue with detached maintenance operations interfering with regular repository operations through improper locking coordination. He indicates a patch series is forthcoming to address the problem, referencing prior discussion of the same underlying issue. The regression affects automated workflows using these command sequences, and while the exact technical solution remains unspecified, the problem is actively being worked on by a core contributor. The maintenance subsystem's detached mode locking behavior needs revision to prevent conflicts while preserving background operation capability.
