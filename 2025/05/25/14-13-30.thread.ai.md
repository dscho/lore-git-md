New thread summary:

Bug report identifies a regression in Git 2.47.2 where maintenance operations running in detached mode (`--detach`) create lock conflicts with concurrent Git commands. The specific sequence triggering the issue involves `git fetch` (which now auto-maintenance runs in detached mode) followed by `git checkout`, where the maintenance process holds a `HEAD.lock` that blocks the checkout. Trace logs confirm the maintenance process runs concurrently with the attempted checkout. This represents a regression from previous versions where the same sequence worked reliably. The core problem appears to be insufficient locking coordination between detached maintenance operations and regular repository operations, particularly around reference updates. The report provides clear reproduction steps and evidence of the interference, indicating this would affect any automated scripts using similar command sequences. The maintenance subsystem's detached mode locking behavior will need review to prevent such conflicts while preserving the intended background operation capability.
