This is a bugfix patch in the `imap-send` series, specifically addressing a memory leak in the CRAM-MD5 authentication path. The patch is part of a larger v5 series that has been through extensive review and iteration to improve IMAP functionality.

The fix ensures proper cleanup of the `response` buffer when socket writes fail during CRAM-MD5 authentication. Previously, if `socket_write()` didn't send the full response length, the function would return an error without freeing the allocated memory. The patch adds the missing `free(response)` call in the error path, matching the existing cleanup that happens on success.

This completes the comprehensive memory management for CRAM-MD5 that was identified as a key requirement in the series. The change is small but important, as it prevents resource leaks during authentication failures. The fix aligns with the series' broader goal of robust error handling across all authentication methods (OAuth2.0, PLAIN, and now fully fixed CRAM-MD5).

Technical details show this affects the `auth_cram_md5()` function in `imap-send.c`, specifically the error path when `socket_write()` fails. The patch maintains the existing behavior of returning an error message while now properly cleaning up. This was the last identified memory management issue in the authentication paths, following earlier fixes for configuration parsing and OAuth2.0/PLAIN implementations.

The change is straightforward and unlikely to be controversial, as it follows the pattern established by other fixes in the series. With this patch, all authentication methods in `imap-send` now have complete memory cleanup, fulfilling one of the series' major technical requirements.
