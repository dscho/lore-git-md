Feature proposal for `git send-email` with Microsoft Graph API integration, following up on the initial RFC.

This is a follow-up to Aditya Garg's RFC proposing Microsoft Graph API support for `git send-email`, now providing a companion credential helper for easier testing. The original proposal aims to replace slow SMTP connections to Microsoft servers (8-10s handshake) with a faster Graph API alternative (~1s for 5 patches) while preserving user-specified Message-IDs.

The email points testers to a new credential helper implementation hosted on GitHub that handles the OAuth2 authentication required by the Graph API. This appears to be a practical addition to the initial proposal, addressing one of the open questions about token handling from the RFC. The helper would complement the three new configs already proposed (`sendemail.useMSGraph`, `sendemail.MSGraphUser`, `sendemail.MSGraphToken`).

The implementation remains focused on Microsoft ecosystem users experiencing SMTP performance issues, maintaining the original benefits of speed and Message-ID preservation. This follow-up suggests the author is actively developing the tooling around the core proposal, though the thread has not yet seen other participants weigh in on the broader questions of dependency impact and mainline suitability.
