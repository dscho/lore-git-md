This is the third version of a bugfix series addressing memory leaks in Git's pack-bitmap handling. The series has two patches:

1. Taylor Blau's patch fixes a memory leak that occurs when `load_bitmap_entries_v1()` fails after allocating a bitmap but before validation checks. The solution moves validation before allocation to prevent leaks.

2. Lidong Yan adds a test case that deliberately corrupts bitmap files to verify the fix works. The test uses a new helper (`test-tool bitmap list-commits-offset`) to precisely locate and modify the XOR offset field, triggering the leak path in a controlled way.

The series has evolved through careful review, with v3 representing consensus on the test approach. Instead of fragile direct file manipulation, it now uses a structured helper to identify corruption points. This builds on earlier discussion where reviewers (including Jeff King and Junio C Hamano) approved the technical approach while refining the testing strategy.

The changes are focused and well-justified, addressing real memory leaks with proper test coverage. The test helper addition in particular shows thoughtful design - it enables targeted corruption while making the test more maintainable. This appears ready for merging.
