Feature proposal adding Microsoft Graph API support to `git send-email`. This RFC patch introduces an alternative to SMTP for sending emails through Microsoft's REST API, addressing two specific pain points with Microsoft's SMTP servers: slow connection times (8-10 seconds initial handshake) and forced Message-ID replacement. The Graph API implementation shows significantly better performance (~1 second for 5 patches) and preserves user-specified Message-IDs.

The patch adds three new configuration options: `sendemail.useMSGraph` boolean to enable the feature, `sendemail.MSGraphUser` for the account email, and `sendemail.MSGraphToken` for OAuth2 authentication. The implementation handles credential management through Git's credential helper system and performs MIME message encoding as required by the API. The author notes documentation is still pending but demonstrates the feature by sending the patch itself via Graph API.

Key technical details for future reference: new Perl dependencies on MIME::Base64 and HTTP::Tiny, base64 encoding of messages, CRLF line ending conversion, and error handling for the REST API responses. The implementation maintains backward compatibility, falling back to SMTP when Graph is not enabled. Likely discussion points may include the new dependencies, security implications of OAuth token handling, and whether this belongs in core Git versus a separate helper tool.
