This is a feature and bugfix series for `imap-send`, now in its fifth iteration, that aims to restore functionality and modernize authentication support. The series builds on the v4 version that had already addressed critical configuration parsing bugs, memory leaks, and added OAuth2.0 support, now adding new command-line and configuration options.

The v5 series introduces two new user-facing features: (1) command-line specification of the destination folder via new `--folder` option, and (2) configurable default choice between curl and OpenSSL backends via new `imap.preferredbackend` setting. These complement the earlier authentication improvements (OAuth2.0 via curl's native API and new RFC 4616-compliant PLAIN method for OpenSSL) and memory management fixes (particularly for CRAM-MD5).

Key technical additions in v5:
- New `--folder` CLI option overrides `imap.folder` configuration
- New `imap.preferredbackend` configuration (values "curl" or "openssl") with fallback logic
- Maintains all prior fixes: configuration parser robustness, OAuth2.0 via curl's `CURLOPT_XOAUTH2_BEARER`, PLAIN auth via OpenSSL's `plain_base64()`, and comprehensive CRAM-MD5 memory management
- Documentation updates cover new options and clarify authentication methods

The series appears well-tested through multiple rounds of review, with v5 representing incremental usability improvements rather than fundamental changes. The author has consistently incorporated feedback from Jeff King, Eric Sunshine, Brian Carlson, and Ben Knoble across previous versions. With the configuration parsing and memory management issues fully resolved in v4, these new conveniences make the feature more practical for end users while maintaining the architectural improvements.
