Bugfix for memory leak in sequencer's `update_squash_messages()` during interactive rebase, now proposing `BUG()` assertion approach.

This v2 patch from Lidong Yan switches from their original memory leak fix to Phillip Wood's suggested approach of using `BUG()` for invalid command types in `update_squash_messages()`. The function should only receive TODO_SQUASH or TODO_FIXUP commands from its callers, making any other input a programming error rather than a runtime condition. The change replaces the error return with a `BUG()` call, which will terminate the program if hit.

The patch is minimal - a single line change in sequencer.c replacing `error()` with `BUG()`. This follows Git's convention of using assertions for impossible conditions rather than trying to recover from them. Yan's static analysis confirms this path would be unreachable in practice, addressing Junio C Hamano's earlier concern about whether static analysis tools could verify this.

This version drops the original leak-fix approach (which added `repo_unuse_commit_buffer()` in the error path) in favor of Wood's more assertive solution. The discussion has narrowed to choosing between these two valid approaches based on Git's error handling philosophy - whether to treat unknown command types as recoverable errors or programming bugs. The technical merits of both solutions have been established, with this patch now advocating for the `BUG()` approach.
