This is part 2/6 of a feature series adding OAuth2.0 authentication support to `imap-send`. The patch implements both RFC-standard OAUTHBEARER and Google's XOAUTH2 mechanisms, with OpenSSL-based implementations for when curl is not available. The changes include new helper functions `oauthbearer_base64()` and `xoauth2_base64()` that construct the proper authentication strings according to their respective specifications (RFCs 5801/7628 for OAUTHBEARER, Google's protocol for XOAUTH2).

The documentation updates explain the new authentication methods, with specific guidance for Gmail and Outlook users. Gmail users are advised to use app-specific passwords or OAuth2.0 tokens, while Outlook users must use XOAUTH2. The curl integration is handled via `CURLOPT_XOAUTH2_BEARER` which automatically selects the appropriate mechanism. Error handling covers both OpenSSL encoding failures and socket write failures.

Key technical points for future reference:
- New capabilities `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` added to IMAP protocol handling
- OpenSSL fallback paths via `oauthbearer_base64()`/`xoauth2_base64()` when curl unavailable
- Curl's native OAuth2.0 support used when available (detects best mechanism automatically)
- Documentation covers both standard and provider-specific (Gmail/Outlook) usage patterns
- Maintains backward compatibility with existing `imap.authMethod` configuration

The implementation appears thorough, with clear attention to protocol specifications and error cases. This was a key part of the series' goal to modernize `imap-send` authentication methods, and follows extensive review iteration from multiple contributors.
