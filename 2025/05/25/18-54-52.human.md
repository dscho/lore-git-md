This is a feature and bugfix series for `imap-send`, now in its fifth iteration, that aims to make the command usable again while adding modern authentication methods. The series has evolved through thorough review, addressing configuration parsing bugs, memory leaks, and adding OAuth2.0 support.

The v5 version introduces two new user-facing features: command-line specification of the destination folder (patch 5) and configurable preference between curl and OpenSSL backends (patch 6). These join the previously added OAuth2.0 authentication (via curl) and PLAIN authentication (for OpenSSL users) from earlier versions.

The series appears well-tested and merge-ready, having addressed all identified issues from previous rounds of review. The configuration parsing fix (patch 1) remains critical as it corrects a severe usability issue where `cfg->folder` was incorrectly NULLed out. The memory management is now comprehensive, with all authentication methods (including CRAM-MD5) properly handling error paths.

For users needing IMAP functionality, this series provides modernized authentication support while maintaining compatibility with existing configurations. The added flexibility in choosing backends and specifying folders directly should make `imap-send` more practical for real-world use. The documentation updates help users navigate provider-specific requirements for the various authentication methods.
