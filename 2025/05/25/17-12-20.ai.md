This is the second patch in a two-part series addressing `git send-email` behavior, specifically focusing on logging improvements when Outlook modifies Message-IDs. The first patch (v3 1/2) fixed threading issues when editing the first patch in a series, while this follow-up enhances logging clarity.

The patch modifies how `git send-email` handles Message-ID changes by Outlook servers. Currently, when it modifies a Message-ID, two things happen: (1) a log message shows the new ID, and (2) a final log shows all headers (with the original ID). This creates confusion as the logs show conflicting information. The change makes the final log display the correct Message-ID by updating the $header variable, and moves the change notification behind the smtp-debug flag since the final log now shows the accurate ID.

Key technical changes are in send_message subroutine, where it now modifies $header to reflect Outlook's Message-ID change and gates the change notification behind debug mode. The diff shows the specific regex substitution that updates the Message-ID in $header and the conditional debug print. This appears to be a straightforward quality-of-life improvement that doesn't introduce new complexity while making the logs more consistent.

The patch builds on the threading fixes from part 1 but stands independently as a logging refinement. It addresses a minor but noticeable inconsistency in the output when using Outlook servers, though the impact is limited to debugging scenarios. The change is well-contained (4 lines modified) and maintains backward compatibility while improving the debugging experience.
