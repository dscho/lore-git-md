This is a bugfix patch addressing memory leaks in the pack-bitmap loading code. It's the first of two patches in v3 of a series, following up on Lidong Yan's report of bitmap-related leaks.

The patch simplifies error handling in `load_bitmap()` by removing redundant cleanup code that was causing memory leaks when loading corrupt bitmaps. Instead of having each error path`goto failed` to perform cleanup, it now returns -1 directly and relies on the caller's `free_bitmap_index()` to handle cleanup uniformly. This fixes a case where partially-loaded bitmap entries would leak when subsequent loading failed.

The change removes ~17 lines of error-handling code while maintaining the same safety guarantees, as Jeff King confirmed in review. The patch demonstrates the rare case where a fix actually reduces code complexity while solving the problem. The commit message clearly explains the leak scenario and why the new cleanup approach is correct.

This is a focused, well-explained change that addresses a real issue with minimal churn. It sets up the foundation for the second patch in the series which introduces more robust testing for these cases. The technical approach has already been reviewed and approved by Jeff King and Junio C Hamano in previous iterations.
