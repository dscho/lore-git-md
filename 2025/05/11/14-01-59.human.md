This is the final patch in a performance optimization series for the packed-refs backend, specifically addressing memory usage during fsck operations. The patch replaces a strbuf-based file reading approach with mmap for large packed-refs files, aligning with the rest of the codebase's memory-efficient practices.

The change is relatively small (19 lines modified) but impactful, leveraging the new `allocate_snapshot_buffer()` helper introduced in patch 2 of the series. The implementation follows the direct mmap/verify/unmap pattern confirmed correct by Jeff King, while maintaining all existing error handling and platform-specific considerations (including Windows compatibility). The patch removes 12 lines of strbuf handling code while adding 7 lines using the new mmap-based approach.

This completes the series' goal of reducing memory pressure during packed-refs verification. The thread history shows thorough review from Jeff King and Junio Hamano, with all technical considerations addressed. The changes appear well-tested and ready for integration, with the only noted future work being potential unification of parsing paths - a separate effort from this optimization.
