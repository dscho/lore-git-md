This is the first patch in Raymond Pasco's bugfix series addressing issues with `git apply --intent-to-add`. The patch focuses on error handling for invalid usage outside a repository.

The change makes `--intent-to-add` properly error out when used outside a git repository, rather than silently disabling the flag. This matches the behavior of other index-modifying flags like `--cached`. The implementation modifies `check_apply_state()` in `apply.c` to explicitly check `is_not_gitdir` before proceeding with intent-to-add operations.

Key technical details:
- Returns an error message "`--intent-to-add` outside a repository" when used in non-git directories
- Maintains the existing behavior of disabling `ita_only` when combined with `--check-index`
- Builds on Johannes Altmanninger's earlier work while taking a different approach
- Part of a larger fix for index corruption issues with `--intent-to-add`

The patch is straightforward and uncontroversial, providing clear error handling for an invalid usage case. It serves as a foundation for the subsequent patches in the series which address more complex index handling issues. The change is small (6 insertions, 2 deletions) and focused, with the test coverage presumably coming in later patches of the series.
