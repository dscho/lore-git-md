Bugfix for `git apply --intent-to-add` index handling. This is the second patch in Raymond Pasco's series addressing a longstanding issue where `--intent-to-add` incorrectly clobbers the index. 

The patch fixes a fundamental flaw in how `git apply` reads the index when using `--intent-to-add`. Currently, the command only reads the index in `--index` mode, but `--intent-to-add` also needs to modify the index (to mark new files) while operating primarily on the worktree. The change makes the index reading depend on `update_index` rather than `check_index`, ensuring the index is properly loaded before any modifications.

This is a key step toward fixing the destructive behavior where `--intent-to-add` was wiping out existing index entries. The fix is minimal (just a one-line change in `apply.c`) but addresses a core architectural issue. The patch builds on prior reports from Ryan Hodges and Johannes Altmanninger, with the solution taking a different approach from Altmanninger's original proposal.

The patch maintains the original intent of `--intent-to-add` as a worktree-focused operation while properly handling the necessary index interactions. Subsequent patches in the series will address related edge cases and documentation.
