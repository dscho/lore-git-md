This is a bugfix patch series addressing longstanding issues with `git apply --intent-to-add` (`-N`). The series builds on prior work from Johannes Altmanninger but takes a different approach to fix both the original index corruption issue and newly discovered edge cases.

The core problem is that `--intent-to-add` currently clobbers the entire index when it should only mark new files as intent-to-add. The series makes several key changes: properly initializing the index, restricting writes to only new files, and adding error handling for invalid usage outside a gitdir. It also documents the behavior more clearly states the flag's limitations.

The technical implementation involves modifying `apply.c` to respect the `ita_only` flag and properly handle partial diffs, while new tests in `t4140` verify correct interactions with other index-modifying operations. The documentation updates clarify that `--intent-to-add` is mutually exclusive with `--index` and `--cached`.
