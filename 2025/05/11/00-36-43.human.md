This is a bugfix series addressing long-standing issues with `git apply --intent-to-add` (-N). Raymond Pasco presents a 5-part solution to fix the command's incorrect behavior that has persisted since Git 2.19, where it would improperly clobber the entire index contents rather than just adding new files as intended.

The series builds on but corrects Johannes Altmanninger's 2021 attempt, with key improvements including proper index initialization, stricter handling of new-file-only changes, and better error handling. The patches add safeguards against running outside a gitdir and introduce comprehensive tests to verify correct interactions with other apply modes. Documentation updates clarify the intended behavior and limitations.

The changes appear well-considered, addressing both the original index corruption issue and edge cases discovered during recent discussion. The test coverage expansion (31 new lines across a dedicated test file) suggests the author has thoroughly validated the fixes against real-world failure scenarios that prompted this renewed attention to the feature. This looks like a serious, production-quality fix for a problematic behavior that has caused actual workflow breakage for years.
