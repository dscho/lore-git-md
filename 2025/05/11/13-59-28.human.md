This is a completed 3-patch series optimizing memory usage in the packed-refs backend, specifically focusing on mmap usage during fsck operations. The series builds on previous discussions with Jeff King and Patrick Steinhardt, incorporating feedback from Junio Hamano.

The first patch fixes an edge case where fsck would incorrectly report errors for empty packed-refs files, aligning the behavior with runtime expectations. The second patch refactors buffer allocation logic by extracting `allocate_snapshot_buffer()` from `load_contents()`, enabling reuse for fsck operations. The final patch implements mmap-based verification for large packed-refs files during fsck, significantly reducing memory pressure.

Key improvements in v3 include removing an unnecessary munmap helper function (as direct mmap/verify/unmap is sufficient), using stack allocation for the snapshot struct, and cleaning up redundant file size checks. The changes maintain all existing behavior while optimizing memory usage, particularly for large repositories. The series is now fully reviewed and ready for integration.
