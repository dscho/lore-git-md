Bugfix addressing memory leaks in reftable writer error paths, now expanded to cover two cases. This is version 2 of the patch, building on the initial submission that only handled the padded_write() case.

The patch now fixes two distinct memory leak scenarios in reftable/writer.c:
1. In padded_write(), when the underlying writer fails during padding operations, a zeroed buffer allocated via reftable_calloc would leak. This matches the original report.
2. A new fix for writer_index_hash() where a malloc'd key would leak if reftable_buf_add() fails before the key is inserted into obj_index_tree.

Changes from v1 to v2:
- Added the second fix for writer_index_hash()
- Kept the original padded_write() fix unchanged
- Updated commit message to describe both fixes
- Maintained the same simple approach of adding reftable_free() calls in error paths

The patch continues to focus on the reftable subsystem's low-level writing infrastructure, specifically the writer.c component that handles table formatting and indexing.
