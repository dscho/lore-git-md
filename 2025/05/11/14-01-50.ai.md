This is a refactoring patch in the packed-refs memory optimization series. It extracts the buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()`, enabling reuse of this logic in fsck operations while maintaining all existing behavior. The change is straightforward - it moves 54 lines of code with a net +10/-0 change, keeping the same mmap/read selection behavior based on file size and mmap strategy.

The key technical details are:
- New function `allocate_snapshot_buffer()` handles both mmap and read-based approaches with the same thresholds (MMAP_NONE or files <=32KB use read)
- Maintains all existing error handling and platform-specific considerations
- Preserves the MMAP_TEMPORARY handling for Windows compatibility
- Keeps the same buffer initialization pattern (start/eof pointers)
- `load_contents()` becomes simpler wrapper that handles file opening/closing while delegating to the helper

This refactoring enables the fsck optimization in patch 3 of the series to reuse the same buffer allocation logic. The implementation follows suggestions from Jeff King and Patrick Steinhardt, and maintains all the defensive conditions from the original code. The change is purely structural with no behavior modification, just better code organization to support the upcoming fsck optimization.
