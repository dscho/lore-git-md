This is the final patch in a 3-part series optimizing memory usage in the packed-refs backend, specifically focusing on enabling mmap for large packed-refs files during fsck operations. The patch implements the mmap-based verification approach that was discussed and refined through multiple review iterations.

The change replaces the previous `strbuf_read()` approach with the new `allocate_snapshot_buffer()` helper introduced in patch 2, which handles both mmap and read-based approaches using the same thresholds (files <=32KB use read). The implementation maintains all existing behavior and platform-specific considerations, including Windows compatibility through MMAP_TEMPORARY handling.

Key technical details:
- Uses stack allocation for the snapshot struct (not heap) as suggested by Jeff King
- Maintains the current buffer loading approach rather than direct xmmap()
- Properly cleans up with `clear_snapshot_buffer()`
- Preserves the direct mmap/verify/unmap pattern confirmed correct in reviews
- Removes the now-unneeded `munmap_temporary_snapshot()` helper
- No longer needs mmap strategy infrastructure for the fsck-only path

The patch achieves the series' goal of reducing memory pressure during packed-refs verification while maintaining all existing behavior and safety checks. The thread has reached consensus on the implementation after addressing all technical considerations, with Jeff King and Junio Hamano confirming the approach is correct. Future work may unify fsck verification with other packed-refs parsing logic.
