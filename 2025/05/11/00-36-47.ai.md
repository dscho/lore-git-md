This is a test patch in the series fixing `git apply --intent-to-add` index corruption issues. It adds test coverage for two important scenarios that weren't previously tested: applying a new file creation patch when other files exist in the index, and handling patches that contain both modifications to tracked files and new file creations.

The patch extends `t/t4140-apply-ita.sh` with two new test cases:
1. `apply creation patch to existing index with -N` verifies that applying a new file patch with `-N` doesn't interfere with other index entries
2. `apply complex patch with -N` checks behavior when a patch contains both modifications to a committed file and new file creations

Key technical details:
- Adds a committed file (`committed-file`) to the test setup for interaction testing
- Creates a new `complex-patch` containing both modifications and new files
- Verifies index state after applying patches using `git ls-files` and `git diff`
- Maintains the test's existing structure while expanding coverage

This patch builds on the earlier fixes by validating that the corrected behavior works in more complex scenarios. The tests specifically check that the index remains intact for tracked files while properly handling intent-to-add operations for new files. The test cases appear well-designed to catch regressions the series aims to prevent.
