This is the third patch in Raymond Pasco's series fixing the `--intent-to-add` index corruption bug. It tightens the conditions under which index entries are written, ensuring they only happen for truly new files when in intent-to-add mode.

The change modifies `create_file()` in `apply.c` to be more precise about when it writes to the index. Instead of just checking `state->update_index`, it now also verifies we're either in normal index-updating mode (`check_index`) or specifically adding a new file in intent-to-add mode (`ita_only && patch->is_new`). This prevents the command from incorrectly marking existing tracked files as deleted.

The patch represents an important refinement to the core fix from patch 2/5, ensuring the index is only modified for its intended purpose - recording new file additions - while maintaining the worktree-only behavior for all other cases. The change is small but surgically precise, directly addressing one of the key failure modes in the original implementation.
