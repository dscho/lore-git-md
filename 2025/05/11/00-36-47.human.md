This is a test patch in Raymond Pasco's series fixing `git apply --intent-to-add` index corruption issues. It adds test coverage for two important scenarios that weren't previously tested: applying a new file creation patch when other files exist in the index, and handling patches that mix modifications to tracked files with new file creations.

The new tests verify that:
1. `git apply -N` correctly handles new file creation alongside existing index entries (without clobbering them)
2. Complex patches containing both modifications to tracked files and new file additions work as expected

The test setup now includes a committed file alongside the intent-to-add test file, allowing more realistic interaction testing. The new test cases specifically check that index state remains correct after applying patches in these mixed scenarios.

This patch builds on the previous fixes in the series by validating their behavior in more complex cases. The tests are thorough and directly target the edge cases that could reveal regressions in the index handling improvements made earlier in the series.
