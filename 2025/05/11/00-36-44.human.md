Bugfix patch for `git apply --intent-to-add` behavior outside repositories.

This is the first patch in Raymond Pasco's series addressing issues with `git apply --intent-to-add` (`-N`). The patch fixes a logical inconsistency where Git would silently ignore the `--intent-to-add` flag when run outside a repository, rather than erroring out as it does with similar flags like `--cached`. The change makes the behavior more predictable by explicitly failing when `--intent-to-add` is used outside a Git directory.

The implementation modifies `check_apply_state()` in `apply.c` to return an error in this case, while maintaining the existing behavior of silently disabling `ita_only` when combined with `--index` (which will be addressed in later patches). The patch is based on earlier work by Johannes Altmanninger and includes a clear error message matching Git's style for similar cases.

This appears to be a straightforward improvement that makes the command's behavior more consistent and predictable. The change is small (6 lines added, 2 removed) and well-contained, with the error case clearly documented in the code. As the first patch in a series addressing longstanding issues with `--intent-to-add`, it sets up the foundation for more substantial fixes to come.
