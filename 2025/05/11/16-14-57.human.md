Bugfix addressing memory leaks in `mailinfo.c`'s email header decoding functions. This is version 2 of Lidong Yan's patch, which now implements the more substantial architectural change suggested by Junio Hamano in the thread discussion.

The patch refactors the `decode_q_segment()` and `decode_b_segment()` functions to take caller-allocated strbufs rather than returning heap-allocated ones, eliminating several potential memory leak points. This includes fixing the original issue where a `convert_to_utf8()` failure could leak a strbuf, but goes further to clean up the interface more generally. The changes affect both header decoding and transfer encoding handling, with corresponding updates to error handling.

The implementation appears thorough, converting all call sites to the new interface and properly handling error cases. This represents a more maintainable solution than the v1 approach of just patching the specific leak, though it's a more invasive change. The commit message could still be improved by explaining the architectural benefits beyond just fixing the leak.
