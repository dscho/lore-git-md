This is a 3-patch series completing the optimization work for memory usage in the packed-refs backend, specifically focusing on aligning fsck behavior with the mmap strategy used elsewhere in the_repository. The series builds on prior discussions with Jeff King and Patrick Steinhardt, incorporating feedback from Junio Hamano.

Key changes in v3:
1. The first patch fixes fsck behavior to properly handle empty packed-refs files, matching runtime behavior by skipping consistency checks for zero-length files (3+13 line change with test coverage).
2. The second patch refactors buffer allocation logic by extracting `allocate_snapshot_buffer()` from `load_contents()` (54 lines moved, net +10/-0 change), enabling reuse for fsck operations while maintaining existing behavior (MMAP_NONE fallback, 32KB threshold, error handling).
3. The final patch implements mmap-based fsck verification (18 lines) with several refinements from v2: stack allocation for snapshot struct, removal of redundant file size check, proper cleanup sequence, and dropping the now-unneeded `munmap_temporary_snapshot()` helper.

The series modifies packed-backend.c (~70 lines changed) and adds test coverage in t0602-reffiles-fsck.sh. It maintains all platform-specific handling (Windows MMAP_TEMPORARY, NO_MMAP cases) while optimizing the fsck path to use direct mmap/verify/unmap. The changes are well-motivated by prior memory optimization work and have gone through multiple rounds of review with all technical concerns addressed. The implementation now matches the agreed-upon approach confirmed by Jeff King and Junio Hamano.
