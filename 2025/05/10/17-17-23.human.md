This is a bugfix for gitk's compatibility with older Tcl/Tk versions. The patch addresses an unintentional requirement for Tk 8.5+ that crept in when text wrapping preferences were added last December. 

The issue stems from gitk's dual support for both themed (ttk) and non-themed widgets, controlled by a global variable. While gitk normally works with older Tk versions by avoiding ttk widgets, commit 904b36b815 accidentally introduced two ttk::combobox widgets that only exist in Tk 8.5+. 

Mark Levedahl fixes this by replacing the ttk comboboxes with calls to makedroplist, an existing helper that creates combobox-like widgets using basic Tk components. This restores compatibility with pre-8.5 Tk installations while maintaining the same user interface functionality for text wrapping preferences.

The change is straightforward - just two line changes swapping the widget type - and clearly motivated by the compatibility regression. The patch appears well-targeted, touching only the problematic widget instantiations while leaving the surrounding preference page layout unchanged. This should be a safe change for the gitk maintainer to consider.
