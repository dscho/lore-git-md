This thread introduces a new `--mergeability-only` option for `git merge-tree` that allows checking whether branches can be merged without computing the full merge result. The two-patch series is designed to optimize merge checks in Git hosting platforms like GitHub and GitLab, which often only need to know if a merge is possible rather than generating the complete merged content.

The first patch added internal optimizations to the merge-ort machinery, introducing a `mergeability_only` flag that makes the merge process exit early upon detecting conflicts while avoiding writing intermediate objects. The second patch, now submitted, exposes this functionality through a new `--mergeability-only` command-line option. When used, `git merge-tree` will simply exit with status 0 (clean merge possible) or 1 (conflicts exist) without producing any merge results or writing objects to the repository. The implementation includes thorough tests verifying the early exit behavior and confirming no objects are written to the object store.

The changes maintain backward compatibility while providing significant optimization for server-side use cases. The patch series appears well-constructed with careful consideration of edge cases and thorough test coverage, though it hasn't yet received review feedback as it's the initial submission.
