Elijah Newren's patch series to add a fast mergeability check to `git merge-tree` continues to be discussed, with the focus now squarely on naming the new flag. The core functionality—which performs a lightweight merge check while still creating some objects in specific cases—is uncontested. 

Junio Hamano has weighed in more firmly on the naming question, proposing `--dry-run` despite the command's partial object creation. He points to existing Git commands like `git fetch --dry-run` that similarly write some objects internally while remaining effectively non-observable to users. This addresses Elijah's earlier concern that `--dry-run` might mislead users into expecting no object writes at all. Junio explicitly rejects using `--check` (despite the parallel with `git apply`) and frames `--dry-run` as consistent with Git's existing conventions where the term implies no user-visible changes rather than absolute immutability.

With the maintainer now clearly favoring `--dry-run` and having provided precedent to justify it, the discussion appears to be converging—though Elijah may still respond to Junio's latest arguments. The series otherwise seems ready to proceed once this final naming question is resolved.
