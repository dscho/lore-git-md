Elijah Newren has proposed adding a `--dry-run` option to `git merge-tree` to enable efficient mergeability checking, particularly useful for Git hosting platforms. The two-patch series introduces internal optimizations in the first patch and exposes them through a user-facing interface in this second patch.

The implementation carefully handles edge cases - it skips writing merged blobs and trees in most cases while still properly detecting conflicts, with specific accommodations for rename/rename+modify scenarios. The option includes safety checks to prevent incompatible combinations with other flags like `--messages` or `--stdin`.

Junio Hamano provided key guidance on naming, steering the interface toward Git's established `--dry-run` convention rather than the initial `--mergeability-only` proposal. The series now stands complete with comprehensive tests verifying both the optimization's core promise (avoiding unnecessary object writes) and its correct interaction with existing merge-tree behavior.

With consensus reached on both the technical approach and interface design, this optimization for hosting platforms is ready for finalization. The changes will allow forking services to check mergeability more efficiently while maintaining all the necessary correctness guarantees.
