Feature addition to `git merge-tree` exposing the mergeability check optimization from patch 1.

This is the second patch in the series, implementing the user-facing `--mergeability-only` flag for `git merge-tree` that leverages the internal merge-ort optimizations added in patch 1. The flag suppresses all output and makes the command exit early upon detecting any conflict, while avoiding writing merge result objects to the object store. This is targeted at Git forges that only need to check branch mergeability without computing full merge results.

The implementation:
- Adds the `--mergeability-only` option to `git merge-tree` with appropriate documentation
- Makes the option incompatible with other output-affecting flags (`--messages`, `--name-only`, `-z`, `--stdin`)
- Includes tests verifying:
  - Successful clean merges exit with status 0 and write no objects
  - Conflicted merges exit with status 1 and write no objects
  - Output is always empty in mergeability-only mode
- Maintains existing exit codes (0=clean, 1=conflict)

The tests carefully validate both the early exit behavior and the avoidance of object creation by checking `git count-objects` before and after operations. The commit message clearly links this to the internal changes from patch 1 and the Git forge use case. This appears to be a well-constructed patch with thorough test coverage that cleanly exposes the optimization while maintaining backward compatibility.
