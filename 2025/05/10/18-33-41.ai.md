Test update for stash's --[no-]index behavior with breaking changes.

This patch updates t3903-stash.sh to account for the proposed behavior change where `git stash apply/pop` will default to restoring the index when GIT_BREAKING_CHANGES is enabled. The changes systematically duplicate many existing tests to handle both old and new behaviors, using the WITH_BREAKING_CHANGES conditional.

Key technical details:
- Tests now have parallel versions for both old (!WITH_BREAKING_CHANGES) and new (WITH_BREAKING_CHANGES) behaviors
- Pathspec-related tests now use --no-index when applying stashes under breaking changes to avoid conflicts
- Tests cover basic operations, stash dropping, quiet mode, and pathspec handling
- The patch notes an open question about whether pathspec filtering should apply to the stashed index

The test strategy is comprehensive but results in significant duplication - each affected test is effectively copied and modified rather than using conditionals within tests. This makes the test changes very explicit but at the cost of increased file size (158 line diff). The patch maintains all existing test coverage while adding the new behavior checks.
