Performance optimization patch in the sparse-index integration series, addressing edge cases in `git add -p/-i` behavior. This email from Elijah Newren provides a detailed review of patch 2/3 in Derrick Stolee's series optimizing `git add -p/-i` for sparse checkouts. The review focuses on two key issues: clarifying ambiguous commit message wording about index expansion behavior, and correcting test case assumptions about index state between operations.

The main technical points are:
1) The test cases incorrectly assume `git reset` will re-sparsify the index between `add -p` and `add -i` operations, when in reality a `reset --hard` plus `sparse-checkout reapply` is needed to properly test the sparse index behavior.
2) The commit message's description of the `-p` vs `-i` expansion behavior is unclear about whether it describes current or desired state, particularly around the handling of sparse directories on disk.

Elijah provides specific reproduction steps showing the test flaw and recommends adding `git sparse-checkout reapply` between test steps to properly validate the sparse index behavior. This builds on his earlier review of patch 1/3 where he identified a similar test issue with `git apply --cached`.

The review doesn't challenge the core optimization (moving the `command_requires_full_index=0` setting earlier in `cmd_add()`) but ensures the test coverage accurately reflects real sparse index behavior. This maintains the thread's focus on rigorous validation of sparse index edge cases while preserving the demonstrated performance improvements.
