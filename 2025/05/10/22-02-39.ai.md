This is a cover letter for a 2-patch series introducing a new feature to `git merge-tree`. The series adds a `--mergeability-only` option that makes the command exit early with just a success/failure status when checking if two branches can be merged, without computing full merge result.

The primary motivation is optimization for Git forges (like GitHub/GitLab) that often need to check mergeability without requiring the actual merge output. The first patch adds internal plumbing in merge-ort to support early termination on conflicts and avoid writing intermediate objects. The second patch exposes this via the new `--mergeability-only` flag in `git merge-tree`.

Key technical points:
- When the flag is set, merge-ort stops at first conflict and skips writing blobs/trees
- The command returns 0 for clean merge, 1 for conflicts (matching merge-tree's existing behavior)
- Tests verify the early exit behavior and that no objects are written in mergeability-only mode
- Documentation updates explain the new flag's purpose and behavior

The changes touch merge-ort internals (adding a mergeability_only flag to struct merge_options) and the merge-tree CLI interface. Test coverage appears thorough, verifying both the early exit behavior and that no objects are written to the ODB in this mode. The commit messages provide clear rationale for the optimization benefits, particularly for server-side use cases.
