This is a bugfix for gitk's compatibility with older Tcl/Tk versions. The patch addresses a regression introduced in commit 904b36b815 ("gitk: add text wrapping preferences") where the use of `ttk::combobox` widgets inadvertently made gitk require Tk 8.5+ with themed widgets enabled. The fix replaces these combobox instances with `makedroplist`, a homegrown alternative that works with base Tk widgets.

The change affects two UI elements in gitk's preferences page - the text wrapping options for comments and other text. The patch maintains identical functionality (same dropdown values and readonly behavior) while restoring compatibility with older Tcl/Tk installations. This is a straightforward replacement that doesn't modify any behavior beyond the widget implementation details.

The fix is minimal (just 2 lines changed) and clearly motivated by the compatibility breakage. The commit message provides good context about the `makedroplist` proc's purpose and the regression's origin. This appears to be a well-scoped fix for a real issue, though it might be worth noting that gitk codebase still contains other `ttk::` widget usages that could potentially cause similar issues.
