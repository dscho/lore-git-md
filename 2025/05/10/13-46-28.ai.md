This is the core implementation patch in a series adding diff context configuration support to interactive patch commands. It follows two test modernization patches that were already reviewed.

The patch makes `add-patch` infrastructure respect `diff.context` and `diff.interHunkContext` configurations across all interactive commands (`add -p`, `commit -p`, `checkout -p`, `restore -p`, `stash -p`). Key changes include:
- Adds `context` and `interhunkcontext` fields to `struct add_i_state`
- Reads config values during state initialization with validation for negative values
- Passes the values through to the diff machinery via `--unified` and `--inter-hunk-context` flags
- Includes comprehensive tests verifying behavior for each command

The implementation builds on prior work that made builtins respect these configs (commit 8b91eef812) and follows the thread's established patterns for config handling. Error messages for negative values are consistent with the codebase's style, though there's a minor inconsistency in the error text between commands (some say "cannot be negative" while others use "bad config variable").

Test coverage is thorough, with new cases for each interactive command verifying both positive config application and negative value rejection. The tests use the now-standard `test_config` pattern established in earlier patches of this series. This completes the thread's goal of config support, leaving only the command-line override functionality for the final patch.
