Thread identity: Feature proposal regarding sparse-checkout and symlink interaction, originating from Gabriel Scherer. Thread type is design discussion with potential implementation impact on sparse-checkout behavior.

Core problem: Symlinks in sparse-checkout become dangling when their targets are outside the checked-out area, particularly problematic in large repositories like typst/packages where symlinks are used for file deduplication. Specific case: b/file symlinks to a/file while only b/ is in sparse-checkout, causing CI workflow failures.

Proposed solutions:
1. Content copying - duplicate target file content when symlink is accessed
2. Automatic sparse-checkout expansion - include symlink targets in checkout scope

Key technical considerations:
- Content copying maintains current sparse boundaries but may cause duplication and silently convert symlinks to regular files
- Automatic expansion conflicts with cone mode and violates user expectations about sparse-checkout boundaries
- The problem extends beyond symlinks to other file dependencies (script calls, includes/imports)
- Configuration needed to choose between behaviors if implemented

Current status: Discussion at impasse between feature proposal and core maintainer preferences. Elijah Newren (sparse-checkout expert) strongly opposes both solutions, arguing they create more problems than they solve and violate Git's philosophy that sparse-checkout users must manually specify all needed paths.

Open questions:
- Whether to pursue any automatic handling of symlinks/dependencies given maintainer objections
- Alternative approaches like explicit dependency handling in CI scripts
- Revisiting abandoned 2020 `.gitdeps` proposal for explicit dependency declarations

Participant positions:
- Gabriel Scherer proposing the feature with detailed analysis of alternatives
- Elijah Newren opposing both solutions as problematic and philosophically misaligned with Git's sparse-checkout design

Related work: Connects to broader sparse-checkout/sparse-index efforts in Git, though this addresses a specific interaction not previously handled. References abandoned 2020 dependency tracking proposal that faced similar philosophical objections.
