This is a cover letter for a proposed feature change to `git stash` behavior, targeting Git 3.0. The series aims to make `git stash apply` and `git stash pop` default to restoring the index (equivalent to current `--index` behavior) when breaking changes are enabled, addressing long-standing user confusion.

The proposal stems from historical context - the original stash implementation considered but didn't implement this default behavior. Patch 3 documents the planned change in BreakingChanges.adoc, while patch 4 implements the actual behavior change in builtin/stash.c. The remaining patches (5-9) update affected tests across multiple test files (t3903, t3904, t3905, t3906) to handle both old and new behaviors.

Key technical details include:
- New behavior gated behind breaking changes flag (GIT_BREAKING_CHANGES)
- Tests modified to verify both legacy and new behaviors
- Documentation updates in git-stash.adoc and BreakingChanges.adoc
- Changes touch stash core functionality and submodule handling
- Test strategy splits cases rather than using test_has_prereq for clarity

The author acknowledges the test approach could alternatively use conditional checks but chose explicit test splits for reviewer clarity. The change appears well-motivated by historical precedent and user confusion reports, with thorough test coverage across stash's various modes (basic, patch, untracked files, submodules). The breaking change nature suggests this may spark discussion about timing and migration impact.
