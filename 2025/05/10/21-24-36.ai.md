This is a bugfix note for the `git stash export` series, pointing out a potential NULL dereference in the commit parsing logic. Jeff King (peff) identifies a code ordering issue in `write_commit_with_parents()` where error checks for NULL author/committer fields happen after those fields are already used in `split_ident_line()`. The fix would involve reordering the checks to validate the pointers before attempting to parse them.

The issue was caught by Coverity static analysis and affects patch v5/3 of the stash export/import series. While not a runtime bug (since the later NULL check would catch the error case), this is a logical flaw that could confuse static analyzers and make the code harder to maintain. The thread context shows this series is otherwise in good shape with all major technical points resolved, so this appears to be one of the final polish items before merge.
