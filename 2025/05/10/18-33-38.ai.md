This is a documentation patch in a series proposing to make `--index` the default for `git stash apply/pop` when breaking changes are enabled. The patch updates BreakingChanges.adoc to announce the planned behavior change, explaining that the current default creates a "footgun" where carefully staged changes are lost during stash application. The new behavior will make `stash apply` properly reverse `stash push` by default, with `--no-index` available to opt out.

The commit message references historical discussion where this behavior was suggested but not implemented, and includes links to relevant mailing list threads. The documentation change clearly states both the motivation (fixing a long-standing user confusion) and the new behavior, while noting this will be a breaking change for workflows that rely on the current non-index behavior.

This appears to be a well-justified change with clear documentation, though as noted in the thread summary, questions remain about whether this warrants being a breaking change and what the migration impact might be. The patch cleanly separates the documentation update from the implementation changes in other patches of the series.
