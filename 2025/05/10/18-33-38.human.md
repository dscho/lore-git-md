This is a documentation patch in a series proposing to change `git stash` behavior. It updates the planned breaking change where `git stash apply/pop` will default to `--index` mode when the GIT_BREAKING_CHANGES flag is enabled.

The patch adds an entry to BreakingChanges.adoc explaining that the new default behavior will make `stash apply/pop` properly restore the index by default, fixing what has been a long-standing "footgun" where these commands didn't fully reverse a `stash push`. Users who need the old behavior can use `--no-index`.

The commit message notes this change was originally suggested in 2007 but not implemented at the time. The documentation cites mailing list discussions showing this has been a persistent pain point for users who lose carefully staged changes. The change is framed as fixing an inconsistency rather than introducing new functionality.

This is part of a larger 9-patch series that implements the behavior change along with test updates. The documentation here serves to formally announce the change in behavior for Git 3.0 when breaking changes are enabled. The patch itself is straightforward and well-justified, with clear references to prior discussions about the issue.
