Performance optimization follow-up in sparse index series. Elijah Newren responds to Derrick Stolee's patch integrating `git apply` with the sparse index, which is part of a performance improvement series for `git add -p/-i`. While generally approving the approach, Newren identifies a subtle testing issue where the sparse index state wasn't properly reset between test cases.

The key observation is that `git apply --cached` actually does expand the index when operating on paths outside the sparse definition, contrary to what the current test asserts. This happens because the test's `git reset --hard` doesn't fully reset the sparse state - a `git sparse-checkout reapply` is needed first. Newren provides detailed reproduction steps showing the index expansion occurring, and suggests fixing the test to properly reset state and expect expansion in this case.

The discussion remains technical and constructive, focusing on ensuring test coverage accurately reflects real behavior. This is a late-stage review of a performance series that's otherwise ready for merging, addressing one final testing detail before integration.
