This thread introduces a 2-patch series adding a mergeability check optimization to `git merge-tree`, authored by Elijah Newren. The series consists of:

1. Internal merge-ort plumbing changes introducing a `mergeability_only` flag in `struct merge_options` that enables early termination on conflicts while carefully avoiding most object creation, with modifications to conflict handling and directory processing.

2. A user-facing flag (initially named `--mergeability-only`, with Junio C Hamano suggesting `--dry-run` as an alternative) that provides fast mergeability checking without full merge computation. The implementation includes comprehensive tests for exit codes, object creation verification, and empty output validation, plus clear documentation of the feature's limitations.

Elijah Newren has responded to Junio's naming suggestion by explaining the initial choice of --mergeability-only, clarifying that while the flag avoids writing objects for the main merge result, it still performs object writes in two specific cases: (1) when computing merge bases, and (2) when handling rename/rename conflicts where both sides modified the same file. This subtle behavior means `--dry-run` could be misleading since it doesn't match the conventional "no changes at all" expectation, while `--mergeability-only` more accurately reflects the partial-object-creation reality.

The technical discussion has shifted to weighing naming tradeoffs between clarity (`--dry-run` being more conventional but potentially misleading about object creation) versus precision (`--mergeability-only` being technically accurate but less familiar). The core functionality remains uncontested, with the naming convention being the primary open question. Future discussion may explore whether to:
- Document the caveats of using `--dry-run`
- Keep `--mergeability-only` for accuracy
- Find a third name that better captures the partial-object-creation behavior

The series remains in active discussion with no other loose ends identified beyond this naming consideration. The thread currently involves Elijah Newren (author) and Junio C Hamano (maintainer).
