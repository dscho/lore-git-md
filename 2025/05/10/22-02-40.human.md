Performance optimization for merge-ort internals. This first patch in a 2-part series adds a `mergeability_only` flag to `struct merge_options` that allows the merge machinery to exit early when it detects conflicts, avoiding unnecessary object writes. The change is motivated by Git forges (like GitHub/GitLab) that often only need to check mergeability without computing full merge results.

The patch modifies several functions in merge-ort.c to respect the new flag, particularly around content merging and tree writing operations. It carefully preserves the existing behavior for recursive merges (call_depth > 0) which still need to complete fully. The implementation shows thoughtful consideration of edge cases like rename/rename conflicts, though the author notes they chose not to optimize those rare cases further.

This appears to be a well-considered internal plumbing change that lays groundwork for the user-facing `--mergeability-only` option coming in patch 2. The commit message clearly explains the tradeoffs and limitations, and the diff shows thorough attention to all the necessary touch points in the merge machinery.
