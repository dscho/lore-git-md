This thread addresses a regression in gitk's compatibility with older Tcl/Tk versions, caused by a recent change that introduced `ttk::combobox` widgets. Mark Levedahl initially proposed replacing these with gitk's existing `makedroplist` alternative to restore compatibility, but Johannes Sixt pointed out this wasn't sufficient due to parameter passing differences between the widgets. 

Johannes referenced a more complete solution from YOKOTA Hiroshi that properly handles both the widget interface differences and maintains backward compatibility. The fix targets the same two UI elements (text wrapping preferences) but implements the widget substitution correctly by following `makedroplist`'s calling convention. While this appears to resolve the immediate issue, the discussion highlights that gitk still contains other `ttk::` widget usages that may need similar attention for full backward compatibility. The thread shows active collaboration to address a real regression while maintaining gitk's support for older Tcl/Tk installations.
