Feature addition to `git merge-tree` for Git forges. This is the second patch in a 2-part series that adds a `--mergeability-only` flag to optimize merge checks in server-side Git operations.

The patch exposes the internal merge-ort plumbing from the first patch via a new CLI option. When `--mergeability-only` is used, `git merge-tree` will exit immediately upon detecting any merge conflict and avoid writing intermediate objects to the object store. This is particularly useful for Git forges like GitHub and GitLab that often need only to check mergeability without computing full merge results.

The implementation includes:
- Documentation of the new flag
- Command-line option handling with validation against incompatible flags
- Tests verifying both successful and conflicted merge cases
- Object store validation to ensure no unnecessary objects are written

The tests are thorough, checking both the exit code behavior and object store impact. The commit message clearly explains the server-side optimization use case. This appears to be a well-considered addition that maintains backward compatibility while providing meaningful performance benefits for large-scale Git hosting platforms.
