This thread introduced a new `stash.index` configuration option that makes `git stash apply/pop` restore staged changes by default, addressing a long-standing inconsistency where `stash push` would save staged changes but not restore them. The feature was implemented by D. Ben Knoble as a backward-compatible addition, preserving the `--no-index` opt-out flag and explicitly documenting how the config affects `--autostash` operations during merge/pull/rebase.

After thorough review, the series has been approved by maintainer Junio Hamano with all feedback addressed, including test isolation improvements from Phillip Wood and documentation refinements suggested by Kristoffer Haugsbakk. The final version incorporates preparatory refactoring, comprehensive test coverage, and maintainer-approved documentation phrasing that omits merge commit references. A brief follow-up email from Haugsbakk confirmed the patches are already in `next` and resolved the last minor misunderstanding about their status. With all participants now aligned and no outstanding issues, this feature is cleared for final integration into Git 3.0.
