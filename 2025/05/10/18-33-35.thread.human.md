This thread has completed the implementation of configurable index restoration for `git stash`, a feature that addresses the long-standing inconsistency where `stash push` saves staged changes but `apply/pop` doesn't restore them by default. The series, authored by D. Ben Knoble, introduces a new `stash.index` configuration (defaulting to false) that controls whether staged changes are restored, while preserving the `--no-index` opt-out for backward compatibility.

The feature received thorough review from Phillip Wood, who helped refine the test strategy and documentation, particularly around the interaction with `--autostash` operations in commands like merge, rebase, and pull. Maintainer Junio C Hamano has approved the series for integration, noting that the default behavior may evolve based on user feedback. The final patch adds explicit documentation clarifying that the `stash.index` setting affects both explicit stash operations and implicit `--autostash` usage, completing the series with no outstanding technical concerns. The implementation includes comprehensive test coverage, code organization improvements, and maintains all existing safety checks while adding this configurable behavior.
