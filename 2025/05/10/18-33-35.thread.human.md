The implementation is carefully structured to:
- Gate the behavior change behind the breaking changes flag
- Document the change in both the stash manpage and BreakingChanges documentation
- Maintain separate test paths for old and new behavior rather than using conditionals
- Cover all stash scenarios including submodules, untracked files, and patch mode

So far the discussion is just getting started, with the core questions being whether this change warrants being a breaking change and how it might affect existing workflows. The test infrastructure improvements are being made first to ensure solid coverage before the behavior change lands.
