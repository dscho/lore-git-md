This thread introduces a new `stash.index` configuration option that lets users control whether `git stash apply/pop` restores the index by default, addressing a long-standing inconsistency where staged changes were saved but not automatically restored. The series, authored by D. Ben Knoble, has gone through several iterations with feedback from Phillip Wood and maintainer Junio Hamano.

The implementation is now fully baked, with comprehensive test coverage including isolated test cases and proper handling of edge conditions. The config defaults to false for backward compatibility but can be set to true for those who prefer automatic index restoration. All code paths respect this setting, including the `--autostash` operations used during merge/pull/rebase. The `--no-index` flag remains available as an opt-out when the config is enabled.

In the final exchange, Phillip Wood noted that the documentation should explicitly mention the `--autostash` interaction, which wasn't previously highlighted. The author agrees this is worthwhile and appears ready to make that final documentation tweak. With all technical concerns addressed and maintainer approval secured, this feature is poised for inclusion in Git 3.0, giving users more control over stash behavior while maintaining backward compatibility.
