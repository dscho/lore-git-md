This is a bugfix discussion about gitk's Tcl/Tk widget compatibility. Johannes Sixt responds to Mark Levedahl's patch that attempted to fix a regression where gitk unintentionally required Tk 8.5+ by replacing `ttk::combobox` widgets with `makedroplist`. 

Sixt points out that the fix isn't as simple as a direct substitution - `makedroplist` has a different interface and behavior than `ttk::combobox`. Instead, he references an alternative solution from YOKOTA Hiroshi that properly handles both themed and legacy widget modes by having `makedroplist` intelligently select the appropriate underlying widget type (ttk::combobox for themed mode, tk_optionMenu for legacy mode).

The discussion highlights an important nuance in maintaining cross-version compatibility for gitk's UI elements. While both approaches aim to solve the same regression, Sixt's reference to Hiroshi's patch suggests it provides a more complete solution that properly preserves functionality across all supported Tk versions. This exchange demonstrates the careful consideration needed when modifying cross-platform GUI code with version-dependent behavior.
