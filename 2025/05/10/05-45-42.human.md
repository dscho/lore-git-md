This is a bugfix patch for the submodule system that prevents accidental configuration overwrites when reusing paths for different submodules.

The patch addresses a subtle issue where Git would silently overwrite `.gitmodules` entries when adding a new submodule at a path that previously hosted another submodule. For example, if you had a submodule 'child' that you moved to 'child_old' and then tried to add a new submodule at the original 'child' path, Git would reuse the name and overwrite the old configuration without warning.

The solution adds safety checks in `module_add()` to detect when a submodule name is being reused for a different path. In such cases, Git will error out unless the user explicitly provides `--force` or specifies a new name with `--name`. The patch includes tests that verify this new protection works as intended.

The implementation looks thorough, with careful handling of the config checking and clear error messages. The test case demonstrates the exact scenario the patch aims to prevent, showing good attention to real-world use cases. This seems like a sensible safety measure that could prevent subtle configuration bugs when managing submodules.
