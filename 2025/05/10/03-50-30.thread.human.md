This thread addresses memory leaks in the reftable writer's error paths. The initial patch (v1) fixed a leak in `padded_write()` where a zeroed buffer wasn't freed when underlying write operations failed. In v2, the author expanded the scope to also fix a similar leak in `writer_index_hash()` where a malloc'd key could be lost if `reftable_buf_add()` failed.

The changes are minimal but important - adding proper cleanup in error paths while maintaining the existing error handling flow. Both fixes follow the same pattern of ensuring allocated resources are freed when operations fail. The patch remains focused on the reftable subsystem's low-level writing infrastructure, specifically the table formatting and indexing components in `writer.c`.

While the fixes appear straightforward, the patch hasn't yet received review feedback. A potential area for follow-up would be adding regression tests for these error paths, though the current changes are unlikely to introduce new issues since they only add cleanup code. The work fits into the broader reftable backend development effort led by Patrick Steinhardt and Karthik Nayak.
