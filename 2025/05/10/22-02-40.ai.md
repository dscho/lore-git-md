This is the first patch in a 2-part series adding mergeability checking optimization to merge-ort. It introduces internal plumbing for early termination of merges when only checking for conflicts, without computing full merge results.

The patch adds a `mergeability_only` flag to `struct merge_options` that, when set, makes the merge machinery exit immediately upon detecting any conflict and avoid writing intermediate blobs/trees to the object store. The changes touch core merge-ort logic across multiple functions, carefully preserving existing behavior for recursive merges (call_depth > 0) while optimizing the final merge case. The implementation handles edge cases like rename/rename conflicts where some intermediate processing is still needed, though the commit message notes a potential micro-optimization opportunity that was deemed not worth the complexity given the rarity of such cases.

Key technical details include:
- New `record_object` parameter added to `handle_content_merge()` to control blob writing
- Conditional tree writing in `write_completed_directory()` based on mergeability mode
- Early exit path in `process_entries()` when conflicts are found in mergeability-only mode
- BUG() assertions added to prevent invalid combinations of merge options
- The changes are focused on merge-ort internals, with no user-facing interface yet

The patch appears well-constructed with thorough consideration of edge cases. The commit message provides clear rationale for the design decisions and explicitly calls out the tradeoffs considered. The changes are focused and surgical, touching only the necessary parts of merge-ort while maintaining all existing behavior for normal merge operations.
