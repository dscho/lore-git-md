This is the implementation patch in a series proposing to change `git stash` behavior under breaking changes. It modifies `git stash apply/pop` to restore the index by default when the GIT_BREAKING_CHANGES flag is enabled, flipping the current behavior where `--index` must be explicitly requested.

The patch makes several coordinated changes to implement this behavior flip. It updates the command-line interface to show `--no-index` as the opt-out flag in the help text when breaking changes are enabled, rather than showing `--index` as the opt-in. The implementation in `builtin/stash.c` is modified to handle both the old and new behaviors, with the new default being to restore the index unless `--no-index` is specified. Error messages are also updated to point users to the correct flag (`--no-index` instead of `--index`) when conflicts occur.

The changes are cleanly gated behind the WITH_BREAKING_CHANGES compile-time flag, maintaining backward compatibility. Documentation updates in git-stash.adoc show both variants of the command syntax depending on whether breaking changes are enabled. The patch appears well-structured and focused, though the accompanying changes to tests (mentioned as coming in later patches) will be important for verifying the behavior.

This is part of a larger effort to fix what the author describes as a "footgun" in stash behavior where carefully staged changes can be lost during application. The change makes `stash apply` properly reverse `stash push` by default when breaking changes are enabled.
