This is a response in the ongoing discussion about sparse-checkout and symlink behavior, with Elijah Newren providing counterpoints to Gabriel Scherer's proposed solutions.

Newren argues against automatically handling symlinks in sparse-checkout, stating that both proposed solutions (content copying and automatic expansion) have significant drawbacks. He notes that content copying would show files as modified, potentially leading to accidental conversions, while automatic expansion conflicts with cone mode and user expectations of control. 

The response broadens the discussion beyond symlinks, pointing out that many file dependencies (scripts calling other scripts, includes/imports) would face similar issues. Newren suggests that dependency analysis belongs at the repository level rather than in Git core, recommending that CI scripts should explicitly handle dependencies rather than expecting Git to infer them.

The email references a prior proposal for declaring dependencies (from 2020) but notes it was abandoned due to technical issues. Newren maintains that explicit user control over sparse-checkout boundaries is preferable to automatic dependency handling, even if it requires more upfront work for repository maintainers.

This moves the discussion forward by challenging the premise that Git should handle this automatically, while acknowledging the real-world pain points that motivated the original proposal. The response maintains Git's current philosophy of explicit configuration over magic behavior.
