Feature discussion response regarding sparse-checkout and symlink handling, from a core Git contributor. This is a substantive technical reply to Gabriel Scherer's proposal about making sparse-checkout automatically handle symlink targets.

Elijah Newren pushes back on the proposed solutions (content copying and automatic sparse-checkout expansion), arguing they would create more problems than they solve. Key objections include:
- Content copying would show files as modified and could silently convert symlinks to regular files
- Automatic expansion conflicts with cone mode and violates user expectations about sparse-checkout boundaries
- The problem extends beyond symlinks to other file dependencies (script calls, includes/imports)

Newren advocates for keeping dependency analysis outside Git, suggesting CI scripts should explicitly handle symlink dependencies when setting up checkouts. He references an abandoned 2020 proposal for explicit dependency declarations (via a `.gitdeps` file) but notes it had unresolved issues and wouldn't solve the immediate symlink case.

The response maintains Git's current philosophy that sparse-checkout users must manually specify all needed paths, rather than having Git infer dependencies. This positions the thread at an impasse between the original feature request and core maintainer preferences, with no clear path forward beyond custom tooling.
