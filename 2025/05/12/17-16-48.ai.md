This is a follow-up patch in the ongoing `git send-email` FQDN detection improvement series, now at version 4. It proposes a platform-specific approach to getting the fully qualified domain name (FQDN) by using the `hostname` command directly rather than relying on Perl modules.

The patch introduces a new `maildomain_hostname_command` function that:
- Uses `hostname --fqdn` on Linux for explicit FQDN request
- Uses `hostname -f` on macOS (Darwin) where `--fqdn` isn't supported
- Validates results through the existing `valid_fqdn()` function
- Maintains the existing fallback chain to Perl modules and MTA methods

Key technical points:
- Justifies the change by noting Perl's Net::Domain module is unreliable
- References implementation details in Perl's own modules that use `hostname`
- Includes error handling (checking `$?` exit status) and proper chomping
- Preserves the final fallback to 'localhost.localdomain'

This version (v4) represents a compromise position from earlier discussions, differentiating between Linux (`--fqdn`) and macOS (`-f`) after maintainer feedback about semantic clarity. The patch shows careful attention to cross-platform behavior while trying to maximize reliability of FQDN detection before falling back to less ideal methods.

The implementation appears technically sound with proper error checking, though the thread context shows ongoing discussion about platform-specific behaviors and flag choices. This patch seems ready for consideration as part of the larger series, with the platform-specific approach addressing previous maintainer concerns about semantic ambiguity.
