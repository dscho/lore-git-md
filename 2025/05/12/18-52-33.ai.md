This is the third and final patch in a refactoring series for Git's oidmap implementation, specifically focusing on the replace-object subsystem. The change removes an unnecessary pointer indirection by embedding the `replace_map` oidmap directly within the `raw_object_store` struct rather than having it as a separately allocated pointer.

The patch demonstrates that the map is always initialized with the containing struct and never checked for NULL, making the extra pointer unnecessary. The change simplifies memory management by eliminating one allocation/free cycle and reduces pointer chasing. It affects several files that interact with the replace-map functionality, including commit-graph handling, object store management, and the replace-object implementation itself.

The implementation is straightforward, converting all access from `r->objects->replace_map` to `&r->objects->replace_map` and removing the separate allocation in `prepare_replace_object()`. The change maintains all existing behavior while making the code slightly more efficient and simpler to reason about. This concludes the series' goal of improving oidmap API clarity and encapsulation.
