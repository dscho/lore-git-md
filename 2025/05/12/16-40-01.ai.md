Bugfix for `git stash` branch name corruption in submodule contexts. This patch addresses the reported issue where stash entries in superprojects incorrectly display submodule branch names instead of the superproject's branch. The root cause is identified as a buffer reuse problem in `builtin/stash.c` - `refs_resolve_ref_unsafe()` returns a pointer to a static buffer that gets overwritten during submodule operations before the stash message is finalized.

The fix introduces a new `branch_name_buf` variable to preserve the superproject's branch name by making a copy when resolving HEAD. This ensures the correct branch name persists through subsequent submodule operations. The change is localized to the stash creation logic and maintains all existing behavior when not in a branch (falling back to "(no branch)").

Key technical details include:
- Adds heap allocation via `xstrdup()` for the resolved branch name
- Preserves the existing "(no branch)" fallback behavior
- Modifies only the message generation path in `do_create_stash()`
- Maintains the same buffer reuse pattern for other ref resolutions

The patch appears well-scoped to the reported issue with clear commit message explanation and minimal code changes. It directly addresses the thread's focus on metadata presentation without introducing functional changes to stash behavior. The solution aligns with Git's typical patterns for handling similar ref resolution cases elsewhere in the codebase.
