Bug report about incorrect branch display in `git stash` when working with submodules.

Stuart MacDonald reports a bug where `git stash list` incorrectly shows the submodule's branch name instead of the superproject branch when stashing changes. The issue occurs when working in a superproject with submodules - after stashing changes in the superproject's `bugfix_bar` branch, the stash entry incorrectly references the submodule's `feature_sdk_foo` branch in its "On <branch>" display.

The reporter provides clear reproduction steps involving a superproject with submodules, where they stash changes in the superproject while the stash entry shows the submodule's branch. This makes it difficult to track which stashes belong to which superproject branches, especially when working with multiple branches. The bug appears in Git for Windows 2.49.0 on Windows 10, and the reporter notes this behavior differs from their experience several years ago.

Key technical details:
- Affects the stash entry metadata display, not the actual stashed content
- Only occurs when working with submodules
- Windows-specific version reported, but likely not platform-specific
- No prior reports found in mailing list archives or web searches
- Documentation doesn't mention this edge case

The report is well-structured with clear reproduction steps, expected vs actual behavior, and system information. The issue appears legitimate and could affect others working with submodules, though the impact is limited to stash metadata display rather than core functionality.
