Bugfix for memory leak in reftable writer's error path. This is the first of two patches in v3 of the series, addressing a buffer leak in `padded_write()` when write operations fail.

The patch fixes a specific memory leak where a `zeroed` buffer allocated via `reftable_calloc` would not be freed if the subsequent `w->write()` operation fails. The buffer is properly freed in the success path, but was missing from the error path. The fix adds the missing `reftable_free(zeroed)` call before returning the error.

This change is part of a series addressing error-path resource leaks in the reftable writer, now properly split into two atomic commits per maintainer feedback. The technical approach remains unchanged from v2, which received positive review from Patrick Steinhardt. The patch is narrowly focused on the `padded_write()` function in `reftable/writer.c`, adding just 2 lines (one for the buffer free, one for the error path brace) while maintaining the existing error handling flow.

The commit message clearly explains the failure scenario (write errors from `reftable_write_data` in `reftable/stack.c`) and the straightforward solution. While the fix appears correct and minimal, the thread context notes that test coverage for these error paths remains an open question. The patch follows the maintainer's requested structure and seems ready for merging from a technical standpoint.
