This is the second patch in a 2-part series adding a `--dry-run` option to `git merge-tree`, focused on the user-facing interface. The change enables efficient mergeability checking for Git forges by leveraging the internal `mergeability_only` flag added in patch 1.

The implementation exposes the optimization through a new `--dry-run` flag that suppresses all output and avoids writing most merge objects to the object store. The patch includes thorough documentation of the option and comprehensive tests verifying both clean and conflicted merge scenarios. The tests specifically confirm that no loose objects are written during dry-run operations, which is the key performance benefit for hosting platforms.

This completes the series after naming guidance from Junio Hamano, settling on `--dry-run` to match Git's established semantics (indicating no user-visible changes rather than guaranteeing zero object writes). The implementation is clean, with proper handling of option conflicts and edge cases, making it ready for integration. The change addresses a clear use case for hosting platforms that need merge checks without the overhead of full merge computation.
