This is the final step in the deprecation process for `git whatchanged`, making the command optional via a `WITH_BREAKING_CHANGES` compile-time flag. Junio Hamano proposes removing the command entirely when this flag is set, following the pattern established by earlier deprecations.

The patch updates documentation across multiple files to conditionally reference `whatchanged` only when built without breaking changes. It also guards the command's implementation in `builtin/log.c` and `git.c` behind the same flag. Test updates ensure the command is only tested when available, maintaining existing coverage while allowing for its removal.

This comes after the previous step that required users to opt-in with `--i-still-use-this`, and represents the logical next phase where the command can be compiled out entirely. The implementation is thorough, touching all relevant documentation and tests while maintaining backward compatibility when the breaking changes flag isn't set. The changes are minimal and focused, showing the command can be cleanly removed when the time comes.
