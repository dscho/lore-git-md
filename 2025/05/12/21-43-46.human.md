This is a technical discussion about implementing stable Change-IDs in Git, specifically addressing how Jujutsu's approach could be adapted for Git workflows. Martin von Zweigbergk responds to Nico Williams' suggestion about using content similarity to track changes rather than explicit IDs.

The key points center around practical workflow needs versus theoretical approaches. Martin explains why content similarity checking wouldn't work for Jujutsu's `jj describe`/`jj new` workflow, where users need to refer to changes by stable identifiers even after modifying commit messages. He clarifies that Jujutsu currently uses randomly generated IDs (16-32 bytes) which have proven effective in practice.

The discussion reveals an important tension between Git's content-based model and the needs of change-based workflows. While Nico suggests Git-like content tracking could work, Martin points out concrete cases where this would break existing Jujutsu commands. The exchange helps clarify implementation requirements as the Change-ID standardization effort continues, particularly around how tools would generate and maintain these identifiers across distributed operations.
