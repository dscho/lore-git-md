This thread addresses a bug in `git stash list` where stashing changes in a superproject would incorrectly display the submodule's branch name instead of the superproject's branch in the stash entry metadata. Stuart MacDonald initially reported the issue, with K Jayatheerth confirming it occurs across platforms (Windows/Linux) while noting it only affects display, not functionality.

After technical analysis identified the root cause - a buffer reuse problem in `builtin/stash.c` where submodule operations overwrite the superproject's branch name - a fix has now been proposed. The solution introduces a dedicated buffer to preserve the superproject's branch name during stash creation, using `xstrdup()` to maintain the correct name through submodule operations. The patch maintains all existing behavior (including the "(no branch)" fallback) while fixing the display issue.

The fix is narrowly scoped to the message generation path in `do_create_stash()` and follows Git's established patterns for similar ref resolution cases. While the discussion initially included questions about when this behavior was introduced (with Stuart noting it may date back to 2016), the current consensus is that the display is incorrect regardless of its history, and the proposed patch cleanly addresses the technical issue without introducing new side effects.
