When stashing changes in a superproject branch (like `bugfix_bar`), the stash entry incorrectly shows the submodule's branch name (such as `feature_sdk_foo`) in its "On <branch>" display. This makes it difficult to track which stashes belong to which superproject branches, particularly when working with multiple branches.

The reporter provides clear reproduction steps demonstrating the problem on Git for Windows 2.49.0, though the issue likely isn't Windows-specific. While the actual stashed content remains correct, the misleading metadata display could cause confusion in workflows involving submodules.
