This thread addresses a bug in `git stash list` where stashing changes in a superproject would incorrectly display the submodule's branch name rather than the superproject's branch in the stash entry metadata. Stuart MacDonald initially reported the issue, and K Jayatheerth provided a minimal reproduction showing the problem occurred across platforms (Windows/Linux).

The root cause was traced to buffer reuse in `builtin/stash.c` - the static buffer holding the branch name was being overwritten during submodule operations. The proposed fix introduces a dedicated buffer to preserve the superproject's branch name via `xstrdup()`, maintaining correct display while keeping all other stash behaviors intact. K Jayatheerth has now verified the fix works as intended, confirming through additional testing that stash entries properly show the superproject branch name (`bugfix_bar`) rather than the submodule's branch (`feature_sdk_foo`). The reproduction recipe now demonstrates the expected behavior, serving as both verification and documentation of the corrected functionality.

The fix appears well-scoped and effective, with no regressions in basic stash operations or the "(no branch)" fallback behavior. While the historical context of when this bug was introduced remains an open question, the technical solution directly addresses the immediate issue and has been independently validated. The patch seems ready for maintainer consideration.
