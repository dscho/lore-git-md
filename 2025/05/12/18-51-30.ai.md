Refactoring patch adding size query functionality to oidmap.

This second patch in the series introduces `oidmap_get_size()` as a type-safe wrapper around the underlying hashmap implementation's size query. The change addresses an implementation detail leak where callers previously had to access the hashmap internals directly. The patch updates two call sites - in commit-graph compatibility checking and replace-object lookup - to use the new interface.

Notably, the replace-object case reveals a subtle behavior change: the code was previously checking the hashmap's allocated table size rather than its actual entry count. While functionally equivalent in this context (since the map only grows), the new version more accurately expresses the intent to check for non-empty maps. The change is minimal, touching just three files with straightforward mechanical updates.

The implementation follows the pattern established in patch 1 of the series, maintaining type safety while hiding hashmap implementation details. This continues the theme of improving the oidmap API's clarity and encapsulation. The change appears well-scoped and unlikely to introduce regressions, with all modifications limited to querying rather than modifying map state.
