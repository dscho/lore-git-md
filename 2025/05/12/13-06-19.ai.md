This is a refactoring patch in the ongoing packed-refs optimization series, specifically addressing buffer allocation logic. Jeff King (peff) is reviewing the v3 patch from shejialuo that extracts snapshot buffer allocation into a new helper function.

The patch moves the buffer allocation logic from `load_contents()` into a new `allocate_snapshot_buffer()` helper, maintaining all existing behavior around mmap/read thresholds and Windows MMAP_TEMPORARY handling. This enables cleaner code patterns, particularly for fsck verification where direct file access needs to be avoided.

Jeff King's review confirms the technical soundness of the refactoring but notes a minor readability concern about the `ret` variable usage in `load_contents()`. He suggests a clearer alternative (directly returning the helper's result) but considers this not worth a re-roll. The review indicates this part of the series is functionally complete and ready for inclusion, with the buffer allocation helper now established as stable infrastructure.

Key technical details preserved in the refactoring include: the mmap vs read decision logic, Windows-specific handling, and all size/performance tradeoffs. The changes affect packed-backend.c with about 54 lines moved/refactored. This patch follows earlier optimizations suggested by both Jeff King and Patrick Steinhardt, with the current implementation having received positive feedback on its technical merits.
