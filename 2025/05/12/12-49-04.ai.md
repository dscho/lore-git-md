Bugfix for a memory leak in the reftable writer's index hash handling during error conditions. This is the second patch in a v3 series addressing error-path resource leaks in `reftable/writer.c`, following maintainer feedback to split the fixes into atomic commits.

The patch specifically fixes a case where the `key` buffer allocated by `reftable_malloc()` would leak if `reftable_buf_add()` fails. The solution is straightforward - adding `reftable_free(key)` in the error path before returning. The change is minimal (4 lines added, 1 removed) and maintains the existing error handling flow while properly cleaning up resources.

This follows the same pattern as the first patch in the series (which fixed a `zeroed` buffer leak in `padded_write()`), and both have been technically approved by Patrick Steinhardt in previous iterations. The v3 series splits these fixes into separate commits as requested for better commit granularity.

The patch remains focused on the specific leak without introducing behavioral changes to successful paths. Like the first patch, it currently lacks specific test coverage for the error case being fixed, which remains an open question in the thread. The changes appear ready for merging pending final maintainer decision.
