This is a response in the ongoing discussion about changing `git stash`'s default behavior to restore stashed index changes by default when breaking changes are enabled.

Junio C Hamano expresses strong reservations about the proposed change to make `git stash apply/pop` default to `--index` behavior. He shares personal experience from trying this workflow via an alias, finding that it frequently failed when the index restoration wasn't actually needed. While acknowledging the escape hatch of `--no-index`, he argues this creates worse ergonomics since users would need to type the longer opt-out flag more often than the current opt-in `--index`.

The response suggests this change might not provide the improved user experience its proponents expect, based on real-world testing. This introduces a key consideration for the thread - whether the theoretical benefits of index restoration by default outweigh the practical friction it may cause in common workflows. The comment doesn't reject the idea outright but provides important experiential data that wasn't previously discussed in the thread.
