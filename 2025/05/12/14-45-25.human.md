Maintenance discussion about Thunderbird patch submission script. This is part of an ongoing thread about cleaning up unmaintained contrib scripts, specifically focusing on whether to keep or remove the "thunderbird-patch-inline" tool.

Patrick Steinhardt responds to Phillip Wood's proposal to update rather than remove the script. While acknowledging Phillip's technically sound patch that adapts the script to work with the maintained External Editor Revived extension, Patrick questions whether there's sufficient justification to keep it in Git's contrib directory. His skepticism stems from the script's long period without maintenance and apparent lack of current users.

The exchange highlights two perspectives: Phillip's position that the script could still provide value to Thunderbird users with minimal maintenance, versus Patrick's view that unmaintained contrib scripts should be pruned unless there's clear evidence of active use. Patrick suggests the patch might be more valuable as a historical reference than as living code in the repository.

This represents a common tension in open source maintenance - balancing the potential utility of niche tools against the burden of carrying unmaintained code. The technical viability question appears settled (the script can work with the revived extension), but the more philosophical question about Git's responsibility to host such tools remains open.
