This is the first patch in a 2-part series adding a `--dry-run` option to `git merge-tree` for fast mergeability checking, primarily targeting Git forges. The patch introduces internal plumbing changes in merge-ort to support early conflict detection while minimizing object creation.

The key technical changes add a `mergeability_only` flag to `struct merge_options` that, when set:
1. Skips writing merged blobs/trees to the object store in the outer merge layer (call_depth == 0), except for rename/rename+modify cases which still require object writes
2. Exits early from `process_entries()` upon first detected conflict in the outer merge
3. Preserves object writing for inner merges (call_depth > 0) which are needed for merge base computation

The patch includes detailed documentation of the optimization scope and edge cases in the commit message, noting that:
- Early exit doesn't cover all possible first conflicts (rare rename cases still process fully)
- Some object writes still occur in rename/rename+modify scenarios
- The implementation prioritizes simplicity over micro-optimizing rare cases

The changes touch core merge-ort functionality across multiple files:
- Adds the new flag to merge-ort.h
- Modifies `handle_content_merge()` to conditionally skip blob writes
- Updates tree writing logic in `write_completed_directory()` and `process_entries()`
- Adds early exit path in `process_entries()` for conflicts
- Adds safety checks preventing incompatible option combinations

This foundational change enables the subsequent patch to expose the functionality via a user-facing `--dry-run` option while maintaining Git's established dry-run semantics of no user-visible changes rather than guaranteeing zero object writes.
