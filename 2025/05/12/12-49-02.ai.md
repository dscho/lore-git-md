This is a bugfix series addressing memory leaks in the reftable writer during error conditions, now properly split into two patches per maintainer feedback. The first patch fixes a leak of the `zeroed` buffer in `padded_write()` when the underlying writer fails. The second patch addresses a leak of the `key` buffer in `writer_index_hash()` when `reftable_buf_add()` fails. Both changes are minimal (6 lines added, 2 removed total) and maintain the error handling flow while properly cleaning up resources.

The series has evolved through three versions: v1 initially fixed only the padded_write leak, v2 added the writer_index_hash fix, and now v3 splits them into separate commits as requested by Patrick Steinhardt. The technical correctness of both fixes was already confirmed in v2 review. The changes remain limited to `reftable/writer.c` with no behavioral impact on successful paths.

Notable is what's still missing - there's no test coverage added for these error paths, which might be worth considering given these were real leaks that went unnoticed. The thread shows productive collaboration between the author and maintainer, with the series now in good shape for potential merging. The split into atomic commits makes the changes easier to review and bisect.
