Feature patch in the stash import/export series, adding validation for exported stashes. Phillip Wood suggests two improvements to the v5 implementation:

1. The commit message could better emphasize the need for handling chains of stashes (the current workaround with push/pull only handles single stashes). While agreeing the new commands are useful, Phillip notes single-stash transfer is already possible with existing commands.

2. The patch adds stricter validation of stash topology during export, rejecting commits that don't match the expected stash structure (2-3 parents with specific relationships). This addresses Phillip's observation that the current code accepts non-stash commits like HEAD. The new `check_stash_topology()` function enforces the proper commit structure.

The changes are proposed as a fixup commit to the existing patch, adding 42 lines to `builtin/stash.c` for the validation logic. This tightens the export safety checks without affecting the core functionality, addressing a gap where the existing `assert_stash_like()` was too permissive. The series is otherwise in good shape, having addressed prior technical feedback and static analysis findings.
