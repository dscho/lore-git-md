This is the second patch in a refactoring series improving Git's oidmap implementation. It adds a new `oidmap_get_size()` function to query the number of entries in an oidmap, replacing direct access to the underlying hashmap implementation details.

The patch addresses a subtle inconsistency where callers were previously examining internal hashmap fields to determine size. One caller in `lookup_replace_object()` was even checking the wrong metric (allocated table size rather than actual entry count), though the author notes this was functionally equivalent in practice since the map only grows. The new wrapper provides proper encapsulation while maintaining the same behavior.

Changes are minimal and focused - just adding the new function declaration and updating two call sites (commit-graph.c and replace-object.h). This continues the series' theme of mechanical, non-disruptive improvements to the oidmap API. The implementation looks straightforward and maintains compatibility with existing code.
