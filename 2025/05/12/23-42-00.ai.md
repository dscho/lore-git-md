This is a cover letter for a 2-patch series introducing a new `--dry-run` option to `git merge-tree`, following up on naming feedback from Junio Hamano. The series provides a fast-path for Git forges to check mergeability without computing full merge results.

The first patch adds internal merge-ort plumbing with a `mergeability_only` option that enables early exit on conflicts and avoids most object-store writes during the merge's outer layer (though some writes still occur for merge base computation and rename/rename conflicts). The commit message provides detailed rationale about the tradeoffs in optimization scope.

The second patch exposes this as a `--dry-run` user-facing option after the naming discussion settled on this term (originally proposed as `--mergeability-only`). The option suppresses all output, making it suitable for scripting. Tests verify both successful and conflicted merge cases while checking object store impact.

The thread context shows this concludes the discussion, with consensus reached about using `--dry-run` terminology while documenting the edge cases where objects may still be written. The implementation appears solid with thorough test coverage of the optimization behavior. This provides a useful performance optimization for Git hosting platforms that only need mergeability checks.
