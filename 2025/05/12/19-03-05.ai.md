This is the final cover letter for the `git whatchanged` deprecation series, now in its 4th iteration. The series implements a complete deprecation lifecycle for the obsolete `whatchanged` command, building on the shared infrastructure previously developed for `pack-redundant`.

The 6-patch series follows a systematic deprecation approach:
1. First refactors the warning infrastructure into a reusable `you_still_use_that()` helper
2. Removes `whatchanged` references from documentation and tests
3. Implements the `--i-still-use-this` opt-in requirement
4. Adds conditional removal when built with `WITH_BREAKING_CHANGES`
5. Documents the deprecation in BreakingChanges.adoc

Key technical elements include:
- New helper function in usage.c for deprecation warnings
- Documentation updates across 8 files (MyFirstObjectWalk.adoc, user-manual.adoc, etc.)
- Test updates in t9300/t9301 replacing `whatchanged` with `log --raw`
- Build-time control via `WITH_BREAKING_CHANGES`
- BreakingChanges.adoc entry with removal rationale

The series incorporates feedback from Elijah Newren and Patrick Steinhardt, including commit message refinements and a missing period in the documentation. The implementation demonstrates the now-mature deprecation infrastructure, with `whatchanged` following the same pattern as `pack-redundant` but progressing further through the full removal pipeline. The cover letter notes this is the most complete iteration yet, with all documentation and test updates in place for the eventual removal.
