Refactoring patch concluding an oidmap cleanup series. This third patch in the series simplifies the replace-object storage by embedding the oidmap directly in the raw_object_store struct rather than using a pointer to a separately allocated map. The change removes unnecessary indirection since the map is always initialized with its parent struct and never NULL-checked.

The patch updates five files to handle the structural change, with straightforward mechanical conversions at each call site. The author notes this is somewhat subjective but argues it's generally good to avoid extra pointers when possible. The change maintains all existing functionality while making the code slightly simpler and more efficient by removing one level of pointer chasing.

This concludes a focused series that improves the oidmap API's clarity and encapsulation, with each patch carefully maintaining behavior while cleaning up implementation details. The changes touch several subsystems but remain purely internal refactoring with no user-visible effects.
