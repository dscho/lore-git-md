This is a bugfix patch addressing a memory leak in the pack-bitmap code. The issue occurs in `load_bitmap_entries_v1()` where validation checks were being done after allocating a bitmap via `read_bitmap_1()`, meaning the allocated bitmap wouldn't be freed if those checks failed.

The patch is straightforward - it simply reorders the operations to perform all validation checks before the bitmap allocation. This prevents the leak by ensuring we only allocate memory after we're certain the operation will succeed. The change is small (4 lines moved) and the commit message clearly explains both the problem and solution.

The fix appears well-targeted and correct - it doesn't introduce any new allocations or complexity, just moves existing validation logic to a safer position. This seems like a low-risk change that properly addresses the memory management issue.
