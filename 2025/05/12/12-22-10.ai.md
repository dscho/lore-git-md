Bugfix for a memory leak in the pack-bitmap code. The patch addresses a case where validation checks in `load_bitmap_entries_v1()` would fail after allocating a bitmap via `read_bitmap_1()`, causing the allocated memory to leak. The fix reorders operations to perform checks before allocation.

The change is straightforward - moving the `read_bitmap_1()` call after all validation checks (for XOR offset and commit index bounds) in the bitmap loading logic. This ensures no bitmap is allocated if the input data fails validation. The patch touches only pack-bitmap.c with minimal changeset (4 line moves, no additions/removals).

This appears to be a clean, focused fix for a real issue. The commit message clearly explains the problem and solution. The change is small and low-risk, affecting only error paths in bitmap loading. The validation checks being moved are all related to corrupt input handling, so the reordering makes logical sense for both correctness and resource management.
