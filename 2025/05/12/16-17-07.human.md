Bugfix and refactoring in mailinfo's decoding functions. This v3 patch from Lidong Yan addresses a memory leak in `decode_header()` when `convert_to_utf8()` fails, while also implementing the architectural refinements requested by Junio Hamano in the v2 review. The changes:

1. Fix the memory leak by properly releasing the `strbuf` when conversion fails
2. Remove redundant `strbuf_init()` calls from decoder functions
3. Consolidate cleanup paths to use a common `release_return` label
4. Simplify control flow by removing unnecessary braces around single statements
5. Apply the same strbuf ownership pattern to `decode_transfer_encoding()`

The patch shows good attention to the review feedback while maintaining the core architectural improvement from v2 - moving to caller-allocated strbufs in the decoding functions. The changes are focused and well-contained to the mailinfo header decoding subsystem. While the decoders still silently ignore malformed input (a potential future improvement area noted in the thread), this version appears ready for inclusion.
