This is a refactoring patch that extracts the deprecation warning logic for `git pack-redundant` into a reusable helper function as part of the ongoing deprecation infrastructure work. The patch moves the warning message and enforcement logic from `builtin/pack-redundant.c` to a new `you_still_use_that()` function in `usage.c`, making it available for other commands facing deprecation. The warning text remains identical but is now centralized.

The patch adds the function declaration to `git-compat-util.h` and includes a new test in `t5323-pack-redundant.sh` to verify the enforcement behavior. The implementation follows the same pattern established in the `git whatchanged` deprecation work, where commands require an explicit `--i-still-use-this` opt-in to run when marked for removal. This is part of a systematic approach to deprecation that includes usage measurement via forced opt-in, consistent warning messages, and test coverage for deprecation paths.

The changes are straightforward - extracting existing code into a helper function while maintaining identical behavior. The patch has already incorporated feedback from Elijah Newren on commit message phrasing and is part of a larger effort that has seen extensive review regarding documentation handling and deprecation methodology. This particular change focuses on the mechanical refactoring aspect to make the warning infrastructure reusable across multiple commands.
