Performance fix for reftable backend addressing regression from fd888311fbc ("reftable/table: move reading block into block reader"). The regression caused full decoding of blocks before type checking, significantly slowing `update-ref` operations (1.62x slower than pre-regression state). Patch modifies `reftable_block_init()` to accept `want_type` parameter and return early for mismatched types, avoiding unnecessary decoding. Benchmarks show 1.62x speedup over regressed state and 1.57x improvement over original performance. Changes affect core block reading logic in `table.c`, updating all callers and tests while maintaining backward compatibility via `REFTABLE_BLOCK_TYPE_ANY`. Performance impact verified through Bencher monitoring. The fix follows established reftable optimization patterns and includes comprehensive test updates.
