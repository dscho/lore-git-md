**Documentation update for `git whatchanged` removal**

This is the final patch in the `git whatchanged` deprecation series, adding formal documentation about its removal to the BreakingChanges.adoc file while also updating the command's man page with a clear deprecation warning. The patch comes from Junio Hamano with input from Elijah Newren.

The BreakingChanges entry notes that `git whatchanged` has been obsolete for over a decade, provides the rationale for removal (it's just a synonym for `git log --raw` but longer to type), and documents the deprecation process that found no users objecting to its removal. The man page update adds a prominent WARNING section explaining the deprecation and recommending `git log --raw` instead.

Junio suggests this as a logically separate patch from the actual code removal to allow projects time to test the deprecation before finalizing the decision, though he notes it could have been squashed with the previous removal patch following the `pack-redundant` precedent. The patch also modernizes the man page's SYNOPSIS section formatting using Git's newer [synopsis] markup.

This completes the documentation side of `git whatchanged`'s deprecation journey, which has served as a model for Git's new deprecation infrastructure alongside the ongoing `pack-redundant` work. The changes are straightforward and well-justified, with no signs of controversy remaining.
