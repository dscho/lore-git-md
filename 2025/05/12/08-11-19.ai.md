This is a follow-up patch in the `git send-email` improvement series, specifically addressing FQDN (Fully Qualified Domain Name) detection reliability. The patch introduces a new `maildomain_hostname_command` function that attempts to get the system's FQDN by running `hostname -f` on Linux and macOS systems, falling back to existing methods if unsuccessful.

Key technical details:
- Adds a new `maildomain_hostname_command` function that executes `hostname -f` (changed from `--fqdn` in v2 for better compatibility)
- Only runs on Linux (`$^O eq 'linux'`) and macOS (`$^O eq 'darwin`)
- Checks command exit status (`$?`) before processing output
- Validates results with existing `valid_fqdn()` function
- Maintains the existing fallback chain: Net::Domain -> MTA -> hostname command -> 'localhost.localdomain'
- The patch responds to Julian Swagemakers' feedback about `--fqdn` portability issues by switching to `-f` flag
- References Perl module internals that use similar hostname detection methods
- Includes proper error handling (silent operation on failure via `2>/dev/null`)

This is the third version of this particular follow-up patch, showing iterative improvement based on review feedback. The change is now properly integrated with the series' broader domain validation work and maintains compatibility with the recently-approved RFC1035 validation checks. The implementation appears technically sound and addresses the portability concerns raised in previous reviews.
