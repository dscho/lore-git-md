This is a cover letter for Patrick Steinhardt's v3 patch series cleaning up Git's `contrib/` directory, part of the ongoing contributor housekeeping effort. The series removes 11 unmaintained components from `contrib/` while establishing clearer maintenance policies for the directory's future.

The cover letter explains the three criteria used for removal: broken functionality, clear alternatives, or obsolete stubs. It positions `contrib/` as a staging area (similar to Linux's staging drivers) where tools should either graduate to core Git, spin out as independent projects, or be removed. The v3 changes refine the justification language to avoid using age as a removal reason and retain `packinfo.pl` (from the stats directory) since it has no replacement.

Key technical removals in this series include:
- `remotes2config.sh` and remote helper stubs (broken/unused)
- `thunderbird-patch-inline` (depends on obsolete Thunderbird extension)
- `mw-to-git` and `persistent-https` (unmaintained remote helpers)
- `git-resurrect.sh` and `git-new-workdir` (superseded by core commands)
- The series follows Junio Hamano's guidance that `contrib/` should not be a dumping ground
- Policy discussions from earlier versions have clarified that technical factors (not age) justify removals
- One script (`packinfo.pl`) was kept pending potential core integration
- The cover letter hints at future reorganization into `tools/` and documentation examples

The patch appears well-considered with clear justifications for each removal. The v3 changes show responsiveness to feedback about avoiding time-based arguments and preserving useful functionality. The series builds on established thread consensus about `contrib/`'s purpose while leaving open the question of where development tools should ultimately live.
