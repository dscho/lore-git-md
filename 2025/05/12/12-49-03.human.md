This is a bugfix patch for the reftable backend, specifically addressing a memory leak in the writer component. It's the first of two patches in this series, following maintainer feedback to split the fixes into separate commits.

The patch fixes a memory leak that occurs when `padded_write()` fails during reftable operations. When writing fails (for example due to disk I/O errors), a `zeroed` buffer allocated via `reftable_calloc()` wasn't being freed. The fix is straightforward - adding a `reftable_free()` call in the error path before returning.

This is part of a v3 series where the author has responded to maintainer feedback by separating what was originally a combined fix into two atomic commits. The change is small (just 4 lines modified) and focused specifically on the error path, with no impact on successful operations. While the fix appears correct, the thread summary notes that test coverage for these error cases is still lacking.

The patch maintains the existing error handling flow while properly cleaning up resources. Given that this is the third iteration and has received positive feedback from the reftable maintainer Patrick Steinhardt, it appears to be in good shape for potential merging.
