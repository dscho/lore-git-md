This is a review comment on the stash export/import feature series, specifically addressing patch v5 3/4. Phillip Wood provides feedback points and a proposed fixup patch to strengthen validation of stash commits during export.

The key technical points raised are:
1. The commit message could better emphasize the need for chain preservation rather than single-stash transfers (which can already be done manually via push/pull of reflog entries).
2. The `--to-ref` option's implementation using OPT_CMDMODE is confusing - it would be clearer as an OPT_STRING with manual validation.
3. Current implementation allows exporting non-stash commits (like HEAD) without validation.
4. The fixup patch adds a new `check_stash_topology()` function that enforces strict stash commit structure (2-3 parents with specific relationships between them) rather than relying on the more permissive `assert_stash_like()`.

The proposed validation would:
- Require exactly 2 or 3 parents
- Verify parent commit relationships match stash structure
- Reject commits where p2 has multiple parents or p3 has any parents
- Ensure p2's parent matches p1

This addresses a gap where the original patch could potentially export malformed or non-stash commits. The feedback comes late in the review cycle (v5) but focuses on tightening edge cases rather than challenging core functionality. The series has otherwise reached technical consensus, making this likely one of the final refinements before merge.
