This is a bugfix investigation for `git stash`'s incorrect branch display in submodule contexts. K Jayatheerth confirms Stuart MacDonald's report that when stashing changes in a superproject branch, the stash entry incorrectly shows the submodule's branch name instead. The reporter provides a clean reproduction recipe showing this occurs when working with nested branches in a superproject/submodule setup.

Jayatheerth verifies the issue is not Windows-specific (reproducible on Fedora too) and confirms the core functionality remains intact - branches and submodule states are preserved correctly, only the stash metadata is mislabeled. The bug appears to be in how `git stash` gathers HEAD information, incorrectly pulling from submodule context when it should use the superproject's branch name.

The investigation notes this may be a regression from circa 2021 behavior, suggesting a promising angle for tracking down the root cause. While the impact is limited to display rather than functionality, the mislabeling could cause confusion in workflows involving frequent branch switching with submodules. The response is thorough and methodical, clearly demonstrating the problem while ruling out platform-specific factors.
