This is the second patch in a bugfix series addressing memory leaks in the reftable writer during error conditions. It specifically fixes a leak of the `key` buffer in `writer_index_hash()` when `reftable_buf_add()` fails, complementing the first patch's fix for the `zeroed` buffer leak in `padded_write()`.

The patch is straightforward - it adds a `reftable_free(key)` call in the error path before returning, matching the maintainer-approved approach from v2. The change is minimal (4 lines modified) and focused solely on the leak fix without altering successful code paths. This follows the maintainer's request to split the original combined fixes into atomic patches.

As with the first patch, this appears technically sound but lacks specific test coverage for the error case. The series as a whole seems ready for merging, having addressed Patrick Steinhardt's review feedback in v3 by properly separating the fixes while maintaining their correctness. This concludes the two-part fix for known memory leaks in the reftable writer's error handling paths.
