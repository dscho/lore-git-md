Bugfix for `git stash` branch name display in submodule contexts. This patch addresses the issue where stashing changes in a superproject would incorrectly show the submodule's branch name in the stash message rather than the superproject's branch.

The problem occurs because `git stash` uses a static buffer to store the branch name, which gets overwritten when resolving submodule references. K Jayatheerth's solution duplicates the branch name string before it can be clobbered, ensuring the correct superproject branch appears in the stash message. The fix is straightforward - allocate a new buffer for the branch name when resolving HEAD.

This builds on Stuart MacDonald's original bug report, confirming the issue affects both Windows and Linux systems. While purely a cosmetic issue (the stash functionality itself works fine), the incorrect branch display could confuse users working with submodules. The patch appears well-contained, touching only the relevant code paths in `builtin/stash.c` with clear commit message explaining both the problem and solution.

The change maintains the existing behavior when not on a branch (still showing "(no branch)") while fixing the submodule case. No test updates are included in this initial patch, though the reproduction recipe from the thread could likely be adapted to prevent regression.
