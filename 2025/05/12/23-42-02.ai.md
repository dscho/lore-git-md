This is the second patch in a 2-part series adding a `--dry-run` option to `git merge-tree` for efficient mergeability checking, primarily targeting Git forges. The patch implements the user-facing interface for the mergeability optimization introduced in the first patch.

The key changes in this patch:
- Adds `--dry-run` flag to `git merge-tree` that sets the internal `mergeability_only` flag from patch 1
- Documents the flag's behavior (suppresses output, allows early exit on conflicts, avoids most objects)
- Adds safety checks preventing `--dry-run` from being combined with incompatible options (`--messages`, `--name-only`, `--stdin`, `-z`)
- Includes comprehensive tests verifying:
  - No output and no object writes on clean merges
  - Correct exit code (1) and no object writes on conflicted merges
  - Interaction with existing merge-tree behavior

The implementation is clean and well-tested, with clear documentation of the intended use case (Git forges needing mergeability checks without full merge computation). The tests specifically verify the optimization's core promise - avoiding object writes in the outer merge layer while maintaining correct mergeability detection.

This completes the series after Junio Hamano's naming guidance to use `--dry-run` (established Git terminology) rather than the initial `--mergeability-only` proposal. The thread shows consensus on both the technical approach and interface design, making this ready for finalization.
