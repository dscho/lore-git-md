Maintainer feedback on merge-tree's --mergeability-only naming. Junio C Hamano weighs in on the naming debate for the new merge-tree flag, suggesting `--dry-run` could still be appropriate despite some object creation, citing `git fetch --dry-run` as precedent where temporary objects are created but not made reachable. He also notes `git apply --check` as a conceptually similar operation that checks applicability without applying changes, though he considers that name suboptimal and wouldn't recommend it for merge-tree.

The email reinforces the core tradeoff in naming: while `--mergeability-only` is technically precise about partial object creation, `--dry-run` has existing precedent for operations that create temporary objects. Hamano's perspective as maintainer suggests leaning toward the more conventional `--dry-run` name, with any object-creation caveats documented, rather than introducing a new specialized flag name. This moves the discussion forward by providing historical context from similar Git commands while acknowledging the author's valid concerns about potential user confusion.
