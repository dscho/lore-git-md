This is a bug report about incorrect branch display in `git stash` when working with submodules. 

Stuart MacDonald reports that when stashing changes in a superproject branch while a submodule is checked out to a different branch, `git stash list` incorrectly shows the submodule's branch name rather than the superproject branch. The reporter provides clear reproduction steps where they stash changes on a superproject branch 'bugfix_bar' while the stash entry incorrectly references the submodule's 'feature_sdk_foo' branch.

The issue affects workflow visibility since users rely on stash entries to identify which branch the stashed changes belong to. The reporter notes this appears to be a regression from behavior they observed in 2021, though they couldn't find prior reports of this issue. The bug occurs on Git for Windows 2.49.0.windows.1.

The report is well-structured with clear reproduction steps, expected vs actual behavior, and system information. The issue appears legitimate and specific to submodule interactions with stash. While not a functionality breakage, it impacts usability for developers working with submodules who rely on stash branch information. The report seems ready for maintainer attention, though it may need verification on other platforms beyond Windows.
