This is a technical review comment in the ongoing discussion about the thunderbird-patch-inline contrib script. Junio C Hamano points out an issue with Phillip Wood's patch that updates the script to work with External Editor Revived rather than removing it.

The key technical observation is that the patch introduces a new separator pattern (SEP) for message headers but doesn't clean up the old separator assignment that follows later in the file. Junio notes that while the change to HEADERS extraction is correct for the new extension, the patch should also remove the now-unused SEP assignment that was specific to the old ExternalEditor extension.

This is a code quality nit in an otherwise functional patch - the script would still work as the new separator logic doesn't depend on the old SEP variable, but leaving the unused assignment is sloppy. The exchange shows Junio's careful review of the technical details even in contrib scripts, maintaining Git's high code quality standards.

The comment doesn't take a position on the broader remove-vs-update debate between Patrick and Phillip, focusing purely on this implementation detail in Phillip's proposed update path. It's a typical maintainer-level review pointing out a small but non-critical improvement opportunity in the patch.
