This is a follow-up discussion about naming the new mergeability check feature in `git merge-tree`. Elijah Newren responds to Junio C Hamano's suggestion to use `--dry-run` instead of the proposed `--mergeability-only` flag.

Elijah explains his hesitation about using `--dry-run`, noting that while the flag avoids writing objects for the main merge result, it still may create objects during merge base computations and rename conflict handling. He's concerned `--dry-run` might imply no object creation at all, which isn't strictly true in this case.

The exchange represents a typical early-stage naming discussion for a new feature that otherwise appears technically sound. The functionality itself isn't in question - just the most accurate and intuitive way to expose it to users. This kind of naming debate is common in Git development when introducing new flags that might have subtle behavioral implications.

The thread shows the careful consideration given to command-line interface design, where the maintainers weigh technical accuracy against user expectations and existing conventions. The discussion is likely to continue until reaching consensus on the most appropriate flag name.
