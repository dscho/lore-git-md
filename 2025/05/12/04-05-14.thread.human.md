This thread discusses the fate of the `thunderbird-patch-inline` script in Git's contrib directory, which provides Thunderbird integration for editing patches. Patrick Steinhardt initially proposed removing the script due to its dependency on an unmaintained extension, sparking a broader discussion about when to keep or remove niche contrib tools.

Phillip Wood stepped in with a technically sound v2 patch that updates the script to work with current Thunderbird extensions and fixes CR/LF handling issues, though he notes he doesn't personally use it. While this addressed the technical concerns, the debate shifted to policy questions about maintaining scripts with few known users. Junio Hamano introduced the possibility of "silent users" who might be using the script without reporting issues, complicating what seemed like a straightforward removal decision.

The discussion is now at an impasse. Phillip has indicated he's ready to drop his patch if there's no further interest, while Junio maintains a neutral stance, suggesting documentation updates about Thunderbird integration should be handled by actual Thunderbird users. The thread has also uncovered outdated documentation in `git format-patch`'s manpage that needs updating regardless of the script's fate. With no clear maintainer stepping forward for the functionality and no consensus on the broader policy question, the script's future is uncertain.
