This is a discussion about finalizing the fsck warning implementation for empty packed-refs files, part of the ongoing optimization work for the packed-refs backend.

Junio Hamano concurs with Jeff King's earlier proposal regarding how to handle fsck warnings for empty packed-refs files. The key points are that while Git should maintain runtime leniency for compatibility (especially with older repositories that legitimately created empty files), it would be useful to have fsck detect these cases with a configurable severity level. This provides a path forward that addresses both Patrick Steinhardt's safety concerns and the need for backward compatibility.

The proposal suggests starting with a non-fatal warning level (like "info" or "ignore") that could be increased by users who know they're working with modern Git repositories. This would be particularly useful for code hosting platforms that run automated fsck checks. The discussion indicates this approach could serve as a stepping stone toward potentially making the check stricter in a future Git 3.0 release.

This email doesn't introduce new technical changes but rather confirms alignment on the maintainer side regarding the warning implementation strategy. The thread appears to be nearing consensus on this final piece of the optimization series, with the main remaining on finalizing the fsck warning details before integration.
