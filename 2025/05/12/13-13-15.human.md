Bugfix for a memory leak in corrupt bitmap handling, with review feedback. This is a follow-up to Lidong Yan's patch that reordered validation checks in `load_bitmap_entries_v1()` to prevent leaks when reading invalid bitmaps. Jeff King confirms the fix is correct but notes an additional consideration - since the code runs in a loop, we need to ensure we don't leak the bitmap from the current iteration if validation fails on the next one. However, this isn't a practical concern because by that point the bitmap would have been stored via `store_bitmap()`. The discussion remains technical and focused, with no objections to the proposed change. The patch appears ready to proceed, addressing a real (though edge-case) issue in the bitmap handling code that could matter for repositories with corrupt bitmap data.
