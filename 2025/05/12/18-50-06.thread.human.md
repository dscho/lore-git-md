This thread presents a refactoring series improving Git's oidmap implementation, focusing on API clarity and encapsulation. The series begins by renaming `oidmap_free()` to `oidmap_clear()` to better reflect its behavior of clearing entries without freeing the map structure itself, updating callers across several subsystems including commit-graph handling, object filtering, and the sequencer. 

The second patch introduces `oidmap_get_size()` as a type-safe wrapper for querying map size, replacing direct access to hashmap internals in commit-graph and replace-object code. The final patch, just submitted, simplifies the replace-object subsystem by embedding the `replace_map` directly within the `raw_object_store` struct rather than using a separate pointer. This eliminates unnecessary allocation while maintaining identical behavior.

The changes are mechanical improvements that don't alter functionality but make the code more maintainable by reducing implementation leakage and pointer indirection. The series touches multiple areas of Git's object handling infrastructure while carefully maintaining backward compatibility. With all three patches now submitted, the oidmap API emerges cleaner and better encapsulated.
