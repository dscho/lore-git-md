This thread has been discussing a series of three patches refactoring Git's oidmap implementation to improve API clarity and encapsulation. The changes rename `oidmap_free()` to `oidmap_clear()` for accuracy, add a type-safe `oidmap_get_size()` wrapper, and eliminate unnecessary pointer indirection in the replace-object subsystem by embedding the map directly in its containing struct.

Patrick Steinhardt has now reviewed and acked the entire series, agreeing with Jeff King's earlier assessment that removing the extra pointer indirection is a sensible change since the map is always allocated with its parent struct. With no outstanding objections from other contributors, this cleanup work appears ready to be picked up by the maintainer. The changes affect several subsystems including commit-graph handling, object store management, and replace-object implementation, but maintain identical behavior while improving code structure.
