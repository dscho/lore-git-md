This is a refactoring patch in the ongoing packed-refs memory optimization series. The patch extracts buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()`, making the code more reusable while maintaining all existing mmap/read thresholds and Windows compatibility. 

The change was prompted by Jeff King and Patrick Steinhardt's earlier suggestions about handling packed-refs more efficiently. While Steinhardt questions whether he directly suggested this specific refactoring, he confirms the change looks technically sound. The extracted helper will be useful for fsck verification where direct file opening isn't desired.

This is the second of three patches in the series, with the refactoring now confirmed as valid while discussion continues on filesystem safety concerns in the first patch. The changes are focused in packed-backend.c and maintain all existing behavior, just with cleaner organization.
