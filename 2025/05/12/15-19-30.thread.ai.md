Bug report and fix for `git stash list` branch display corruption in submodule contexts. Stuart MacDonald initially reported that stashing changes in a superproject's `bugfix_bar` branch incorrectly shows the submodule's `feature_sdk_foo` branch in stash entries' "On <branch>" display. K Jayatheerth confirmed the issue with a minimal test case and provided the fix - modifying `builtin/stash.c` to use `xstrdup()` for preserving the superproject branch name through submodule operations, preventing buffer reuse corruption.

The solution introduces a `branch_name_buf` variable to maintain the correct branch name while keeping the existing "(no branch)" fallback behavior. Junio C Hamano reviewed the patch, confirming the core approach is sound but noting two code quality issues needing correction: inconsistent indentation around the `if (branch_name_buf)` block and a memory leak from not freeing the allocation. Eric Sunshine subsequently noted the patch lacks test coverage for the fixed behavior, which is a standard expectation for bugfixes.

Key technical details:
- Localized change to `do_create_stash()` message generation path
- Heap allocation via `xstrdup()` preserves branch name through submodule ops
- Must add corresponding `free()` for `branch_name_buf` to prevent leak
- Indentation fixes needed in control flow around branch name handling
- Test case required to verify superproject branch name preservation
- Maintains existing buffer reuse pattern for other ref resolutions
- Verified working in multiple independent test environments
