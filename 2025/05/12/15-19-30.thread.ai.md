Bug report and fix for `git stash list` branch display corruption in submodule contexts. Stuart MacDonald initially reported that stashing changes in a superproject's `bugfix_bar` branch incorrectly shows the submodule's `feature_sdk_foo` branch in stash entries' "On <branch>" display. K Jayatheerth confirmed the issue with a minimal reproduction recipe, verifying cross-platform occurrence (Windows/Linux) with impact limited to metadata presentation.

The root cause is identified as a buffer reuse problem in `builtin/stash.c` - `refs_resolve_ref_unsafe()` returns a pointer to a static buffer that gets overwritten during submodule operations before the stash message is finalized. The fix introduces a new `branch_name_buf` variable to preserve the superproject's branch name via `xstrdup()`, ensuring correct display while maintaining the existing "(no branch)" fallback behavior.

K Jayatheerth provides additional verification that the patch correctly preserves the superproject's branch name (`bugfix_bar`) in stash entries when working with submodules, showing the fix works as intended in their test environment. The complete reproduction recipe now demonstrates the corrected behavior, where stash entries properly reflect the superproject branch rather than the submodule's branch name (`feature_sdk_foo`). The solution maintains all expected behaviors: correct branch name preservation through submodule operations, proper "(no branch)" fallback when applicable, and no regression in basic stash functionality.

Key technical details:
- Localized change to `do_create_stash()` message generation path
- Heap allocation preserves branch name through submodule operations
- Maintains existing buffer reuse pattern for other ref resolutions
- No functional changes to stash behavior - purely metadata correction
- Verified working in independent test environment with full reproduction case

The test case serves as both verification and documentation of the fixed behavior, strengthening confidence in the patch's effectiveness.
