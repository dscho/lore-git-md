Bugfix addressing memory leak in mailinfo header decoding, with interface improvements. This is Junio Hamano's review of Lidong Yan's v2 patch that reworks the `decode_q_segment()` and `decode_b_segment()` functions in `mailinfo.c` to use caller-allocated strbufs rather than returning allocated buffers.

Hamano approves the overall approach but suggests several refinements: (1) callers should initialize strbufs before passing them to decoder functions rather than having the functions initialize them, (2) braces around single-statement blocks should be removed for consistency, (3) strbuf cleanup should be consolidated at the `release_return` label in `decode_header()`, and (4) the error handling in `decode_transfer_encoding()` should release the strbuf unconditionally. 

The review also notes (without requesting changes) that the decoders currently ignore malformed input rather than reporting errors, suggesting this might be worth addressing separately with a strict mode. The patch appears technically sound but needs minor cleanup before finalization. This continues the thread's progression from a simple leak fix to a more robust interface redesign.
