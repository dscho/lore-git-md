This is the first patch in a 2-part series adding a `--dry-run` option to `git merge-tree` for fast mergeability testing, primarily targeting Git hosting platforms. The patch introduces internal plumbing changes to optimize merge conflict detection while minimizing object creation.

The core addition is a `mergeability_only` flag that modifies merge-ort's behavior to:
- Exit early upon detecting conflicts in the outer merge layer (though some rare rename/rename cases may be processed first)
- Avoid writing most merged blobs/trees to the object store, with exceptions for inner merges and certain rename conflicts

The commit message provides detailed rationale for the implementation choices, acknowledging tradeoffs between optimization scope and code complexity. The changes are focused on the merge-ort internals, with thorough documentation of edge cases where objects may still be written. The patch appears well-considered, with clear explanations of its limitations and deliberate design decisions.

This is part of an already-discussed series where the naming and approach have reached consensus, so the technical content here is unlikely to be controversial. The changes lay groundwork for the user-facing `--dry-run` option that will follow in patch 2.
