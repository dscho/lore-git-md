Performance fix for the reftable backend, addressing a regression introduced in fd888311fbc.

This patch fixes a significant performance regression in the reftable code that occurred when reading blocks of an uninteresting type. The regression was introduced in fd888311fbc ("reftable/table: move reading block into block reader") which refactored block reading logic but inadvertently caused full decoding of blocks before checking their type. The patch modifies `reftable_block_init()` to accept a `want_type` parameter and return early if the block type doesn't match, avoiding unnecessary decoding work.

The performance impact is substantial: benchmarks show the fix makes `update-ref` operations 1.62x faster compared to the regressed state, and actually improves on the original pre-regression performance (1.57x faster than the initial regression). The changes affect the block reading core of reftable, modifying the `reftable_block_init()` interface and its callers in `table.c`, plus updates to unit tests. The author notes the regression was detected via Bencher's performance monitoring.

Key technical details:
- Adds `want_type` parameter to `reftable_block_init()`
- Returns early if block type doesn't match `want_type`
- Updates all callers in `table.c` and test files
- Maintains backward compatibility via `REFTABLE_BLOCK_TYPE_ANY`
- Performance improvement confirmed via `update-ref` benchmark

The change is well-motivated with clear before/after benchmarks and follows the pattern of previous reftable optimizations. The patch appears complete with corresponding test updates and maintains the existing behavior while fixing the performance issue.
