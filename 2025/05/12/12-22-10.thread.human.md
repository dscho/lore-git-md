This thread addresses memory leaks in Git's pack-bitmap handling, specifically in the bitmap loading paths when processing corrupt bitmaps. The series originated from a report by Lidong Yan and has progressed through four versions, with the latest iteration refining commit messages while maintaining the technical approach.

Taylor Blau contributed the first patch, which fixes EWAH bitmap leaks by simplifying error handling in `load_bitmap()`. The solution replaces multiple cleanup paths with a single centralized approach using `free_bitmap_index()`, removing redundant code while ensuring proper cleanup. Jeff King reviewed and confirmed this approach, noting it both fixes the leak and improves code structure.

Lidong Yan's second patch adds comprehensive test coverage through a new `test-tool bitmap list-commits-offset` helper. This infrastructure enables targeted corruption testing by tracking positions of bitmap entries, with a specific test case verifying proper handling of corrupt xor_offset fields. While technically sound, Junio C Hamano suggested improving the commit message to better explain why this test code belongs in pack-bitmap.c rather than being separate.

The series has reached consensus on both the leak fixes and testing approach, with all review feedback addressed in v4. The patches demonstrate the rare case where fixes actually remove code while improving correctness, and provide reusable test infrastructure for future bitmap validation work. With no outstanding technical objections, the series appears ready for merging.
