This thread addresses memory leaks in pack-bitmap.c's bitmap loading paths, originally reported by Lidong Yan. The series has gone through several iterations, with the current version fixing two distinct leak scenarios when loading corrupt bitmaps. The first patch reorders validation checks to prevent leaks on XOR offset validation failures, while the second removes redundant cleanup code to ensure consistent handling via `free_bitmap_index()`.

Taylor Blau and Jeff King have reviewed the technical approach, confirming the fixes address the issues while simplifying the code. There was some discussion about whether a dedicated test patch was necessary, given Git's existing corruption fallback behavior, but Lidong Yan argued it provides specific leak detection under corruption scenarios. 

In the latest exchange, Lidong and Taylor agreed to restructure the series for clarity in v3, moving the standalone leak fix patch first and the validation reordering second. They also noted the first patch's benefit is now clearer as a performance optimization (avoiding unnecessary bitmap reads) rather than just leak prevention. The technical content of the fixes remains uncontested, with only organizational improvements needed before the series is ready for merging. Junio C Hamano has already indicated approval of the code reduction approach, so the thread appears to be nearing resolution pending final agreement on the test coverage question.
