This thread addresses memory leak fixes in Git's pack-bitmap loading code, originally reported by Lidong Yan. The series has gone through several iterations, with version 3 adding comprehensive test coverage. The fixes handle two distinct leak scenarios when loading corrupt bitmaps: one by reordering validation checks to fail before allocation, and another by removing redundant cleanup code in favor of centralized error handling.

Taylor Blau, who contributed one of the fixes, has now provided feedback on how to best organize the patch series. He suggests reordering the patches so his cleanup change (which removes duplicate error handling paths) would come first, making Lidong's validation reordering patch build on top as a performance improvement rather than a leak fix. This would make the commit history clearer, as Taylor's patch independently fixes the leaks while Lidong's would then primarily provide the benefit of failing faster on invalid input. The technical consensus around using centralized cleanup remains unchanged, and the fixes themselves have already been reviewed positively by Jeff King and Junio Hamano.

The discussion now focuses on presentation rather than technical concerns, with Taylor offering to discuss alternatives if the current organization is preferred. The series appears ready for merging once this final organizational question is resolved. The comprehensive test coverage added in v3 ensures these fixes will be protected against regression.
