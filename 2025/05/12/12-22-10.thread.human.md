This thread addresses memory leaks in Git's pack-bitmap subsystem, specifically during bitmap loading failures. The issue was originally reported by Lidong Yan, who identified a leak when validation checks for XOR offsets and commit indexes failed. His initial patch reordered these checks to prevent the leak, which Jeff King reviewed and confirmed as correct.

Taylor Blau then discovered a second leak scenario where partially loaded bitmap entries were being orphaned when error handling destroyed the bitmap hashmap prematurely. He proposed a more comprehensive solution that simplifies the code by removing redundant cleanup paths in `load_bitmap()` and relying on callers' `free_bitmap_index()` for uniform cleanup. This approach would address both leak cases while making the error handling more robust.

Junio C Hamano has now weighed in on Taylor's proposal, noting approvingly that the fix actually removes code (about 10 lines) rather than adding it - a rare and welcome outcome. The changes maintain Git's performance-critical bitmap loading patterns while ensuring proper memory management during failures. With both fixes combined, the subsystem will handle errors consistently without leaking memory in either validation failures or partial-load scenarios. The thread shows clear technical consensus forming around this solution.
