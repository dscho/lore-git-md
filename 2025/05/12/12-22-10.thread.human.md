This thread addresses memory leaks in Git's pack-bitmap handling, originally reported by Lidong Yan. The series has gone through four iterations, with the latest version refining commit messages while keeping the technical approach unchanged.

The first patch, from Taylor Blau, simplifies error handling in `load_bitmap()` by removing redundant cleanup code and relying on callers' `free_bitmap_index()` for uniform cleanup. This removes about 17 lines of code while maintaining safety. The second patch, from Lidong Yan, adds comprehensive test coverage using new test infrastructure that allows targeted corruption of bitmap entries.

The technical approach has received positive reviews from Jeff King and Junio Hamano, with consensus that the changes properly address the memory leaks while simplifying the code. A procedural question about sign-off ordering was resolved with Junio clarifying that secondary sign-offs (like Lidong's on Taylor's patch) are encouraged but not strictly required for public patch sharing.

The series is now in its final form, with only minor refinements to the test infrastructure implementation still pending before merging. These include simplifying position tracking and improving test output verification. Junio has suggested some final commit message improvements to better explain the test infrastructure's placement.
