This thread addresses memory leaks in Git's pack-bitmap loading code, originally reported by Lidong Yan. The series has progressed through two versions, with version 2 adding crucial test coverage. The fixes target two distinct leak scenarios when loading corrupt bitmaps.

The first patch, from Lidong Yan, reorders validation checks in `load_bitmap_entries_v1()` to prevent leaks by validating before making allocations. The second patch, from Taylor Blau, simplifies error handling in `load_bitmap()` by removing redundant cleanup code that were causing partial leaks, instead relying on the caller's `free_bitmap_index()` for uniform cleanup. Jeff King reviewed both fixes, confirming they address the issues while actually reducing code complexity - a rare case where fixes remove rather than add code.

Version 2 of the series includes new test cases in t5310-pack-bitmaps.sh that verify the fixes by deliberately corrupting bitmap files to trigger specific error paths. These tests, added by Lidong Yan, provide LSan-verifiable coverage of both validation failures and partial-load scenarios. The changes remain minimal (29 lines modified in pack-bitmap.c) while significantly improving robustness in these performance-critical paths.

With both key reviewers (Jeff King and Junio C Hamano) having approved the technical approach and the addition of comprehensive test coverage, this series appears ready for merging.
