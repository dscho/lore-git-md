This thread addresses memory leaks in pack-bitmap.c's bitmap loading paths, originally reported by Lidong Yan. The series has gone through three versions, with the first two patches fixing distinct leak scenarios during corrupt bitmap handling: one reordering validation checks to prevent pre-allocation failures, and another removing redundant cleanup code in favor of centralized resource freeing. Jeff King reviewed and approved both fixes, while Junio C Hamano noted the rare case where a fix actually reduces code size.

The third patch added targeted test coverage by corrupting bitmap XOR offsets to verify the fixes, but Taylor Blau has now questioned its necessity. He points out that Git's existing test infrastructure already catches these leaks through universal leak checking, making the custom corruption test potentially redundant. Taylor suggests the test's manual bitmap parsing is fragile and proposes an alternative approach using object-ID-based position tracking if testing is still needed. This may lead to dropping the test patch entirely, simplifying the series to just the two core fixes that have already received positive reviews from key contributors. The thread shows careful attention to both technical correctness and test suite maintainability.
