This thread addresses memory leaks in Git's pack-bitmap loading code, originally reported by Lidong Yan. The core issue involved two scenarios where corrupt bitmaps could cause memory leaks: during validation checks and when loading failed mid-operation. Lidong's initial patch reordered validation checks to prevent the first leak, while Taylor Blau later identified and fixed the second scenario by removing redundant cleanup paths in favor of centralized error handling via `free_bitmap_index()`. Both fixes were small, focused changes to `pack-bitmap.c` that received positive reviews from Jeff King and Junio Hamano.

With the technical solution now agreed upon, the discussion has shifted to testing. Lidong has volunteered to attempt creating test cases that trigger these error paths by crafting specifically corrupted bitmap files. While Jeff King expressed some skepticism about the practicality of this approach, successful test cases would provide valuable regression protection for these edge cases in the performance-critical bitmap code. The thread demonstrates how even small memory leak fixes in core functionality can benefit from both careful code review and, where possible, targeted testing of error scenarios.
