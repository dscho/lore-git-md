Bugfix follow-up in reftable memory leak series. Patrick Steinhardt reviews Lidong Yan's v2 patch that fixes two distinct memory leaks in the reftable writer's error paths. The patch addresses leaks in both the padded write operation and the index hash handling, adding proper `reftable_free()` calls when write operations fail.

Steinhardt agrees with both fixes but suggests splitting them into separate commits since they touch different code areas - one in the padded write function and another in the index hash handling. The changes themselves are minimal (just adding free calls in error paths) and maintain the existing error handling flow.

This continues the thread started by Yan's initial v1 patch that only addressed the padded write case. The v2 expansion to cover both identified leaks appears technically sound based on Steinhardt's review, though there remains an open question about whether regression tests should be added for these error cases. The changes are focused on `reftable/writer.c` and don't affect successful code paths.
