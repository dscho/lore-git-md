This is a continuation of the discussion about empty packed-refs file handling in the optimization series for the packed-refs backend. Jeff King (peff) provides historical context showing that older Git versions (pre-1.8.4) did indeed write empty packed-refs files, which supports maintaining lenient runtime behavior for compatibility. He demonstrates this with reproduction steps using Git v1.8.4 and v1.4.4.

The email suggests a middle path for fsck verification: while continuing to accept empty files at runtime for compatibility, fsck could detect and report them (perhaps at a low severity level by default). This would allow sites that know they're using modern Git to configure stricter checking while maintaining backward compatibility for older repositories. The eventual Git 3.0 transition could then simply adjust the default severity rather than introducing new behavior.
