Bugfix and refactoring in mailinfo header decoding. This v3 patch from Lidong Yan addresses memory leaks in `mailinfo.c`'s header decoding functions, implementing the changes requested in Junio Hamano's review of v2. The patch completes the architectural shift to caller-allocated strbufs by:

1. Removing `strbuf_init()` from `decode_q_segment()` and `decode_b_segment()`, making initialization the caller's responsibility
2. Consolidating cleanup paths by moving `strbuf_release(&dec)` to the common `release_return` label in `decode_header()`
3. Simplifying control flow by removing unnecessary braces around single-statement blocks
4. Fixing the `decode_transfer_encoding()` function to use stack-allocated strbufs consistently

The changes maintain the same functionality while eliminating potential leaks when `convert_to_utf8()` fails or when decoding operations encounter errors. The patch affects the core email header parsing logic in Git's mailinfo subsystem, particularly around quoted-printable and base64 decoding. While the decoders still silently ignore malformed input (a potential future enhancement area), this version properly handles resource cleanup in all error paths.
