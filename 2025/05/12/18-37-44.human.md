This is a follow-up in the merge-tree optimization thread, where Elijah Newren agrees to change the flag name from `--mergeability-only` to `--dry-run` based on Junio Hamano's arguments about Git's established conventions. 

Elijah acknowledges Junio's point about `git fetch --dry-run` creating objects internally while still being considered a "no changes" operation from the user's perspective. He accepts this as precedent for the merge-tree flag's behavior where some internal objects may be created during merge base computation and rename/rename conflict detection. While agreeing to the name change, Elijah notes that unlike `git fetch`, the primary users of this merge-tree feature may care about object creation, so he plans to document this implementation detail clearly.

The discussion resolves the secondary question about using `--check` (as `git apply` does) with Junio arguing convincingly that `--dry-run` is the more consistent choice across Git commands. With this naming decision settled, the patch series appears ready for finalization and inclusion. The technical implementation was never in dispute - this was purely about interface design and terminology alignment with Git's existing conventions.
