This is a refactoring patch that renames `oidmap_free()` to `oidmap_clear()` to better reflect its actual behavior. It's the first in a three-part series improving Git's oidmap implementation.

The change addresses a naming mismatch - while the function was called `oidmap_free`, it doesn't actually free the oidmap struct itself, just clears its entries (using `hashmap_clear_()` internally). The new name `oidmap_clear()` better matches Git's CodingGuidelines and makes the behavior more obvious to callers.

The patch updates all callers across several subsystems including commit-graph handling, object filtering, and the sequencer. The changes are mechanical but thorough, touching 7 files with simple renaming. The commit message clearly explains the change and its rationale. This appears to be a straightforward, well-motivated improvement to internal API clarity.
