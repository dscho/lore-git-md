This is a cover letter for a 2-patch series introducing a new `--dry-run` option to `git merge-tree`. The series, now in its second version, has been through naming discussion and is ready for final review.

Elijah Newren's series adds a fast mergeability check mode to `git merge-tree`, primarily targeting Git Forges that need to test branch mergeability without computing full merge results. The key optimization is early exit on conflict detection and avoiding most object store writes during the outer merge layer. The implementation builds on merge-ort internals to provide this lightweight check while maintaining correctness.

The naming discussion from v1 has been resolved by adopting Junio Hamano's suggestion to use `--dry-run` instead of the original `--mergeability-only` proposal. The commit messages now explicitly document the edge cases where objects may still be written (merge base computation and rename/rename conflicts), while maintaining the dry-run guarantee from the user's perspective.

The series appears well-considered, with thorough documentation of implementation tradeoffs in the first patch's commit message. The tests demonstrate both successful and conflicted merge scenarios while verifying the object store impact. With the naming question settled and technical implementation uncontested, this looks ready for inclusion.
