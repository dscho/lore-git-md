This is the 10th patch in Jeff King's series removing support for non-standard object types in Git. The patch focuses on the `hash-object` command, specifically removing its ability to create objects with arbitrary types when using the `--literally` flag.

The change drops the `hash_literally()` helper function and modifies the code to reject unknown types while still keeping the `--literally` flag for bypassing other format checks. The patch argues this isn't a practical compatibility break since such objects were never properly functional. Test cases are updated to verify the new rejection behavior.

The change is part of the broader effort to simplify Git's object handling code by removing support for experimental features that never matured. This patch builds on earlier infrastructure changes (like the new test helpers introduced in patch 9) to maintain test coverage while removing the non-standard type support. The implementation appears straightforward, replacing the custom literal hashing path with a modified call to the standard `index_fd()` function.

While this is a behavior change, the patch makes a reasonable case that the impact will be minimal since the feature was only useful for testing/debugging. The change helps pave the way for further simplifications in the object writing code in subsequent patches.
