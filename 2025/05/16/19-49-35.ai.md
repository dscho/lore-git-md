Performance optimization series (final patch discussion). This email from Karthik Nayak responds to Jeff King's review of the batched reference updates series, specifically addressing memory management in the error handling paths. The discussion focuses on patch 4/4 which implements batched updates in `git-receive-pack`.

The key technical development is agreement to modify `ref_transaction_error_msg()` to return string literals (`const char *`) rather than allocated strings, eliminating the need for callers to free the results. This change:
- Fixes a memory leak in receive-pack's error string handling
- Simplifies memory management across all callers
- Maintains identical error messages while reducing allocations
- Requires const-casting when storing literals in strmap
- Adjusts strmap cleanup to not free values (since they're literals)

Karthik confirms this approach aligns with Junio Hamano's earlier suggestion and Jeff King's proposed implementation. The change affects multiple files (`builtin/fetch.c`, `builtin/receive-pack.c`, `builtin/update-ref.c`, `refs.[ch]`) but preserves all performance improvements from the batched updates.
