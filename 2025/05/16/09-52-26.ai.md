This is patch 6/13 in Jeff King's series removing support for non-standard object types from Git's core. The patch focuses on simplifying fsck's handling of unknown object types by removing the type_name strbuf infrastructure.

The key change moves error reporting for unknown types from fsck.c to read_loose_object(), where we now bail immediately when encountering an unparsable type rather than trying to proceed with the check. This eliminates the last uses of the type_name strbuf while making the error output slightly more verbose but potentially more debuggable (showing the full malformed header). The patch removes 40 lines while adding 14, with most changes in fsck.c and its tests.

Patrick Steinhardt reviews the patch positively, agreeing with the approach and noting the error reporting relocation makes sense since read_loose_object() now handles the failure case directly. The changes align with the series' broader goal of removing non-standard type handling while maintaining equivalent safety - unknown types are still detected, just with different (and arguably better) error messages.

This patch follows the series' established pattern of systematically removing read-side support for non-standard types after earlier patches eliminated the OBJECT_INFO_ALLOW_UNKNOWN_TYPE flag and converted type handling to enum-only. The fsck changes here are a natural progression of that work, cleaning up one of the last places that still tried to handle unknown types rather than rejecting them outright.
