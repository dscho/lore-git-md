This is the final patch in Elijah Newren's series adding mergeability checking to `git merge-tree`, implementing the user-facing `--quiet` flag that leverages the `mergeability_only` optimization from the previous patch. The flag provides hosting platforms with efficient merge conflict detection while avoiding unnecessary object writes and output generation.

The patch adds the `--quiet` option to `git merge-tree` which:
1. Suppresses all output (including conflict messages)
2. Enables early exit on conflict detection
3. Prevents writing most merge result objects to the object store
4. Includes safety checks to prevent incompatible combinations with other options like `--messages` and `--stdin`

Key implementation details:
- Adds the flag to `struct merge_tree_options` and propagates it to the underlying merge machinery
- Modifies `real_merge()` to skip output generation when `mergeability_only` is set
- Includes comprehensive tests verifying:
  - Empty output on both clean and conflicted merges
  - No object store pollution in either case
  - Correct exit codes (0 for clean, 1 for conflicts)
  - Incompatibility with other output-affecting options

The implementation builds on the merge-ort plumbing changes from the previous patch, completing the optimization pipeline for hosting platform use cases. The tests specifically validate the object-write avoidance behavior that was the primary motivation for the series. The final naming (`--quiet`) follows Git's conventional terminology for silent operation modes after discussion on the mailing list.
