Performance optimization follow-up discussing packfile access ordering. Junio Hamano responds to Patrick Steinhardt's patch that reordered checks in `add_packed_git()` to reduce syscalls for missing packs. While acknowledging the optimization's merit, Hamano raises historical context about the original ordering being deliberate for correctness - ensuring .idx files are checked before .pack files to prevent using incomplete packs. He questions whether the current ordering still serves this safety purpose, noting the pack naming scheme has changed since those early concerns.

Hamano identifies the multi-pack-index edge case as a real but somewhat self-inflicted problem (stale indexes should be regenerated), and while the 75% reduction is good, he wonders if even the remaining 25% of syscalls could be avoided. The response suggests the optimization might be treating symptoms rather than root causes, while leaving open whether the original safety constraints still apply to the current codebase. The discussion hints at deeper questions about packfile integrity checking that may need revisiting.
