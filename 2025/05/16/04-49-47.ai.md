This is part 4 of Jeff King's series removing support for non-standard object types in Git's core. The patch continues the refactoring by simplifying type handling in `git cat-file -t`, converting from a strbuf-based approach to using the object_type enum directly.

The change builds on patch 3's removal of the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag. Since we now only handle standard object types, we can use the simpler enum-based type reporting rather than passing a strbuf to capture type names. The patch removes the strbuf handling code in `cat_one_file()` and replaces it with direct use of the `type` field and `type_name()` helper.

Key technical changes:
- Drops the `sb` strbuf variable and related cleanup code
- Uses `oi.typep = &type` instead of `oi.type_name = &sb`
- Outputs the type name via `type_name(type)` rather than the strbuf contents
- Simplifies the control flow by removing the conditional strbuf check

This is a straightforward mechanical change that follows logically from the earlier patches in the series. It touches only `builtin/cat-file.c`, focusing on the type-reporting path for the `-t` option. The change reduces code complexity while maintaining identical behavior for standard object types.

The patch appears well-contained and low-risk, with no obvious edge cases or complications. It continues the series' trend of removing now-unnecessary infrastructure for handling non-standard object types.
