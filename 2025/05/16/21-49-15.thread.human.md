Here's a human-readable thread summary:

Chris Conti reports a regression in Git 2.49.0 on Windows where symlink functionality breaks during directory diff operations. Their custom `diffdirsym` alias, which temporarily enables symlinks via `-c core.symlinks=true` when using `difftool --dir-diff`, now fails with a "Function not implemented" error. This worked correctly in Git 2.48.1.

The issue occurs when Git attempts to create symlinks for changed files in temporary directories during the directory diff operation. Chris provides detailed environment information (Windows 10, PowerShell 5.1, OpenSSL 3.2.4) and confirms their Beyond Compare difftool setup remains unchanged between versions. The error suggests a regression in symlink handling specifically for Windows builds of Git between versions 2.48.1 and 2.49.0.
