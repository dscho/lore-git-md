This thread reports a Windows-specific regression in Git 2.49.0 where symlinks fail during directory diff operations (`git difftool --dir-diff`). Chris Conti originally described how a custom difftool alias that temporarily enables `core.symlinks` now fails with "Function not implemented" errors, despite working in Git 2.48.1. 

Johannes Schindelin (Git for Windows maintainer) has responded, identifying commit 8241ae63d821 ("difftool: eliminate use of global variables") as the likely cause. This refactoring, while not Windows-specific, appears to have inadvertently broken symlink handling during the temporary file setup phase of directory diffs. Schindelin notes this matches behavior reported in GitHub issue #5517, though he hasn't yet proposed a fix due to time constraints.

The issue specifically affects Windows users who rely on symlink functionality in difftool operations, particularly those using custom configurations that temporarily enable symlinks for directory comparisons. The regression appears limited to the dir-diff workflow where Git creates symlinks in temporary directories. No other maintainers have weighed in yet, but Schindelin's analysis provides a clear starting point for further investigation.
