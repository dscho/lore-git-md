This is a bug report about symlink functionality breaking in Git for Windows 2.49.0. Chris Conti reports that an alias that enables symlinks for directory diffs stopped working after upgrading from version 2.48.1. The error occurs when trying to use `git difftool --dir-diff` with Beyond Compare, failing with a "Function not implemented" error when attempting to create symlinks.

The issue appears specific to Windows environments where `core.symlinks=false` is set in the system config, but temporarily enabled via command-line flag. The alias worked in 2.48.1 but fails in 2.49.0, suggesting a regression in the symlink handling code for Windows builds. The reporter provides clear reproduction steps including their config settings and environment details.

This looks like a legitimate regression that affects Windows users who rely on temporary symlink creation for difftool operations. The report is well-documented with all necessary technical details, though it doesn't include any analysis of what might have changed between versions. Windows maintainers would likely want to investigate whether this relates to recent changes in symlink handling or the difftool implementation.
