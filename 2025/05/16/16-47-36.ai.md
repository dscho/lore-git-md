This is patch 2/13 in Jeff King's series removing support for non-standard object types in Git's core. The patch makes `--allow-unknown-type` in `git cat-file` a no-op while retaining the option for backward compatibility. 

The key insight is that while the option no longer serves its original purpose (allowing unknown object types), removing it entirely could break scripts that pass the flag even when working with normal objects. The patch keeps the option's presence but removes its functionality, maintaining compatibility while simplifying the code. 

Junio Hamano notes he initially questioned why the option was being retained until reading the explanation in the commit message, and now fully supports the approach. The patch appears technically sound with no outstanding issues, though Patrick Steinhardt had earlier suggested adding a test for option acceptance and documenting the deprecation path more explicitly. 

This change is part of the broader effort to remove non-standard object type support that was never properly usable beyond testing purposes. The series has received positive reviews from both Patrick Steinhardt and Junio Hamano, with all technical aspects now complete.
