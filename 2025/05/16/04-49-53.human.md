This is part 6 of Jeff King's series removing support for non-standard object types from Git's core. The patch focuses on simplifying fsck's handling of unknown object types by eliminating its use of the type_name strbuf.

The change makes fsck bail immediately when encountering an unknown object type rather than trying to proceed with hash verification. This results in slightly more verbose error messages (now showing both the header parsing failure and the subsequent corruption error) but provides better debugging information. The patch removes a now-redundant test case that previously checked behavior with both type and hash mismatches.

This continues the series' trend of removing special cases for non-standard types while maintaining the ability to detect corruption. The changes are mechanical and well-explained, with clear rationale for the user-visible effects. The error message changes are unlikely to impact real usage since such malformed objects are already unusable in practice.

The patch builds on earlier work in the series that removed other uses of the type_name strbuf, further simplifying the object handling code. It's a logical next step in the overall goal of removing support for non-standard object types that were never been properly usable.
