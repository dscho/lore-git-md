Test infrastructure patch in Jeff King's series removing non-standard object type support. This is patch 9/13, introducing a new shell library `t/lib-loose.sh` for creating raw loose objects in tests without relying on `git hash-object --literally`. The library provides a `loose_obj` helper that writes objects directly to the object database, bypassing Git's normal validation.

The patch converts three test scripts to use this new approach instead of `hash-object --literally` when creating invalid objects. This is part of the larger effort to remove support for non-standard object types entirely - the new helper will allow tests to continue creating invalid objects even after `hash-object --literally` is removed in a later patch.

The implementation handles the low-level details of object formatting (header, compression) and storage (directory structure) that `hash-object` normally manages. The changes to the test scripts are mechanical replacements of one invocation with another, showing the helper works as a drop-in replacement for the existing test cases.

This appears to be a well-constructed piece of test infrastructure that cleanly separates the testing needs from the production code being modified. The commit message clearly explains the motivation and how this fits into the larger series. The patch follows the established pattern of the series by making incremental, focused changes that move toward the end goal.
