This is a performance optimization patch in Derrick Stolee's series making interactive Git commands sparse-index aware. The patch specifically focuses on `git add -p` and `git add -i`, preventing unnecessary index expansion when operating within the sparse checkout area.

The key change moves the sparse-index integration point earlier in `cmd_add()` so the optimization applies before the interactive control flow begins. This builds on previous work optimizing `git apply` (which `add -p` uses internally). The patch includes comprehensive test cases verifying:
- No index expansion occurs when editing files within the sparse checkout
- Proper expansion still happens when editing files outside the sparse area
- Both `-p` and `-i` modes are covered

Performance tests show a 96.7% runtime reduction (2.09s to 0.07s) for `git add -p` with sparse index. The implementation follows established sparse-index patterns while carefully handling edge cases through rigorous testing in both compatibility (`t1092`) and performance (`p2000`) test suites.
