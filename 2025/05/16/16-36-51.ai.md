This is the final discussion in Jeff King's series removing support for non-standard object types. Junio Hamano, the Git maintainer, weighs in with historical context and approval for the removal.

Junio clarifies that the original purpose of non-standard object types was never experimental feature development, but rather testing how Git handled unknown types - making their removal even more justified. He expresses surprise at how widely the support was scattered through the codebase (requiring 13 patches to clean up), but fully endorses the removal effort.

The email confirms the maintainer's position that this change doesn't need to wait for Git 3.0, as the functionality was never intended for production use. This aligns with Jeff King's original argument and Patrick Steinhardt's positive reviews throughout the series. With both the technical reviewers and now the maintainer in agreement, the path appears clear for merging this simplification of Git's object handling code.

Key technical points from the thread remain relevant: the series removes parallel implementations, improves code unification (particularly benefiting ODB work), and introduces useful test helpers (`test-zlib` and `lib-loose.sh`) that may have value beyond this specific cleanup. The only remaining loose end is whether to incorporate Patrick's suggestions about documenting deprecation in patch 2/13, but the core technical work appears complete and approved.
