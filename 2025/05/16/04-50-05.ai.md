This is the 10th patch in Jeff King's series removing support for non-standard object types from Git's core. The patch focuses on the `hash-object` command, specifically removing its ability to create objects with arbitrary types when using the `--literally` flag.

The key technical changes are:
- Removes the `hash_literally()` helper function that previously handled non-standard types
- Modifies the main `hash_fd()` function to use `index_fd()` for all cases, just disabling format checks when `--literally` is used
- Updates tests to show rejection of non-standard types rather than accepting them
- Retains the `--literally` flag itself for bypassing other format checks

The patch continues the series' pattern of simplifying object handling code by removing special cases for non-standard types. It builds on earlier infrastructure changes (like the new test helpers in patch 9) to maintain test coverage while removing the actual support code. The commit message argues this backwards-incompatible change is acceptable since the feature was never properly functional beyond testing/debugging.

This patch touches `builtin/hash-object.c` and its tests, removing about 30 lines of specialized handling code. The changes are straightforward but do represent a behavior change in rejecting rather than accepting bogus types with `--literally`. The patch leaves room for further cleanup in subsequent patches, particularly around the remaining `--literally` functionality.
