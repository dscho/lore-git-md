Refactoring patch in the non-standard object type removal series. This is patch 11/13 in Jeff King's effort to simplify Git's object handling by eliminating support for non-standard types.

The patch removes an unnecessary indirection layer in `builtin/hash-object.c` where the command was maintaining its own set of flag bits (HASH_OBJECT_*) that simply mirrored the underlying INDEX_* flags used by `index_fd()`. With the removal of `hash_literally()` in the previous patch, this indirection no longer serves any purpose. The change:
- Eliminates the HASH_OBJECT_CHECK and HASH_OBJECT_WRITE flag definitions
- Directly uses INDEX_FORMAT_CHECK and INDEX_WRITE_OBJECT flags throughout
- Updates the flag initialization and condition checks accordingly
- Maintains the same behavior while simplifying the code

This is a straightforward cleanup that follows naturally from the series' earlier work. The patch touches only `builtin/hash-object.c`, modifying 23 lines with a net reduction of 17 lines. The changes are mechanical and unlikely to be controversial, though reviewers may want to verify that the flag handling remains correct for all code paths. The patch builds on the test infrastructure established in patches 8-10, though it doesn't require any test changes itself since it's purely an internal refactoring.
