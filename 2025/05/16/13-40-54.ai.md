This is a follow-up discussion on the bundle-uri patch from the static analysis cleanup series, focusing on Windows compatibility for 64-bit value parsing. Phillip Wood proposes replacing the previously approved `sscanf()` solution with a new `strtoul_u64()` helper function to better support Windows platforms.

The patch introduces a new utility function in `git-compat-util.h` that uses `strtoumax()` for parsing 64-bit unsigned integers, addressing potential portability issues with `sscanf()` on Windows. The implementation includes explicit error checking for negative values and invalid characters, similar to Git's existing `strtoul_ui()` helper. The function is then used in two places in `bundle-uri.c` where creation tokens are parsed.

Phillip notes this maintains consistency with Git's existing string-to-number conversion patterns while raising questions about whether to strictly require digits-only input (like `isdigit(*s)`) rather than the current whitespace-tolerant approach that matches `strtoul_ui()`. The change comes after the series was already approved, suggesting it as a potential follow-up improvement rather than a blocker for the current series.

This builds on earlier discussion where Jeff King had suggested moving away from `sscanf()` and Phillip had raised Windows-specific concerns about 64-bit value handling. The implementation demonstrates how static analysis findings can lead to broader code quality improvements beyond the original scope.
