This thread continues the discussion about adding Multipath TCP (MPT CP) support to Git, focusing on how it would work across different Git transports. The original proposal from Muhammad Nuzaihan suggested automatic MPTCP usage when available, with fallback to regular TCP. Linux kernel MPTCP maintainer Matthieu Baerts has been providing key technical guidance throughout.

The conversation has now expanded beyond the initial git:// protocol focus to consider HTTPS and SSH transports. Matthieu's latest email clarifies that inetd-managed git-daemon instances would need MPTCP configured at the inetd level, not within Git. He also explains technical approaches for HTTPS (via libcurl's socket callback mechanism) and notes OpenSSH's historical resistance to MPTCP due to lack of BSD support. 

Key open questions remain about final configuration design (global vs per-repository), performance documentation needs, and practical deployment guidance - particularly for server administrators using inetd. While the technical foundations are solid, with Linux's production-proven fallback behavior, the discussion continues to surface real-world integration challenges across Git's transport stack. Junio Hamano has been ensuring the proposal aligns with Git's configuration philosophy while accounting for operational realities like declining git:// protocol usage.
