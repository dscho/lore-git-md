This thread explores adding Multipath TCP (MPTCP) support to Git, focusing on Linux systems. The original proposal by Muhammad Nuzaihan suggested automatically using MPTCP when available, with fallback to regular TCP. The discussion has evolved through technical implementation details, with key input from Matthieu Baerts (Linux kernel MPTCP maintainer) confirming that Linux implementation requires explicit opt-in via `IPPROTO_MPTCP` but provides robust fallback to TCP when unavailable. The current proposal uses a `core.mptcp` configuration (defaulting to false for clients, true for servers) following Git's existing configuration patterns.

Junio Hamano, as maintainer, has been ensuring the design aligns with Git's philosophy while raising important concerns. His latest email highlights a practical deployment consideration: when `git-daemon` runs via `inetd` (still common for server setups), MPTCP support depends on `inetd`'s socket configuration rather than Git's settings. This surfaces an important nuance - while the technical implementation is sound, the actual benefits for server administrators may be limited unless their entire hosting environment is properly configured. The discussion remains productive, with open questions now focusing on configuration granularity and documentation needs, particularly around server deployment scenarios and performance tradeoffs. The thread demonstrates effective collaboration between Git contributors and MPTCP experts, with the technical foundations now well-established and policy decisions being the remaining focus.
