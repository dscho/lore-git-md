The thread discusses adding Multipath TCP (MPTCP) support to Git on Linux systems, which would allow bandwidth aggregation across multiple network paths and seamless failover during disruptions. The initial patch proposed automatically using MPTCP when available on the host system, falling back to regular TCP otherwise, with no new configuration needed.

Brian has raised important compatibility concerns about this automatic approach, identifying edge cases where it might fail: binaries built on MPTCP-capable systems running on stripped-down kernels, IPv6-only connections on systems with IPv4-only MPTCP support (like FreeBSD), and potential issues similar to Go 1.24's problematic MPTCP rollout. He suggests making MPTCP usage configurable while keeping it as the default.

The discussion reveals this primarily affects the legacy unauthenticated Git protocol (port 9418), which sees little modern use - though the remaining users may be precisely those running unusual configurations where automatic MPTCP could cause problems. The technical details include the distinction between IPPROTO_MPTCP v1 vs v0 and layer 4 networking behavior. The core question now is whether to proceed with the original automatic approach or add configuration options to control MPTCP usage.
