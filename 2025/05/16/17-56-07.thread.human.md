This thread explores adding Multipath TCP (MPTCP) support to Git, with Muhammad Nuzaihan proposing Linux-specific implementation details and Junio Hamano serving as the architectural gatekeeper. The discussion has evolved from initial technical feasibility to deeper questions about Git's role in transport-layer decisions.

Matthieu Baerts, the Linux kernel MPTCP maintainer, provided key technical clarifications explaining why Linux requires explicit application support through IPPROTO_MPTCP socket creation, validating Muhammad's approach. The current proposal uses a `core.mptcp` configuration (defaulting to false for clients) with platform-specific checks in `connect.c`.

Junio's latest email shifts focus to user experience concerns, questioning whether unconditionally passing IPPROTO_MPTCP could harm functionality when MPTCP is unavailable, and suggesting the kernel should handle this transparently if truly safe. He also probes whether MPTCP configuration needs finer granularity (per-repository or per-host) rather than a global switch, indicating the discussion is moving from technical implementation to integration design.

Key open questions include: fallback behavior when MPTCP is unavailable, performance tradeoffs between MPTCP and TCP in real-world usage, and the appropriate scope for MPTCP configuration. While technical objections have been addressed, the thread now focuses on ensuring the feature integrates cleanly with Git's configuration model and provides clear user benefits.
