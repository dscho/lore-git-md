Refactoring patch in a series removing non-standard object type support. This is patch 3/13 in Jeff King's series to simplify Git's object handling by eliminating support for non-standard object types that were never properly usable beyond test cases.

The patch removes the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag and related code, following the previous patch that made `git cat-file --allow-unknown-type` a no-op. The removal allows simplifying several functions, particularly `unpack_loose_header()`, which no longer needs to handle the strbuf parameter for unknown types. The patch touches object-file.c, object-file.h, object-store.h, and streaming.c, removing about 50 lines of code while maintaining the same core functionality.

This is part of the logical progression of the series - having removed the user-facing option in patch 2, this cleans up the internal implementation details. The changes are straightforward and mechanical, with no expected behavior change for normal Git operations. The patch maintains the same careful approach seen earlier in the series, keeping the ULHR_TOO_LONG distinction for slightly better error messages while removing all the now-unused code paths.
