This thread documents Jeff King's (Peff) effort to remove Git's long-dormant support for non-standard object types - a 10-year-old feature that was only ever intended for testing unknown type handling. The 13-patch series has progressed smoothly, with Junio Hamano approving each technical implementation. The latest patch (10/13) removes `git hash-object`'s ability to create objects with non-standard types while preserving the `--literally` flag for other validation bypasses, which Junio confirmed with a quick "Yup."

The series has systematically eliminated both read-side and write-side support, with patches already merged to simplify `git cat-file` type handling, remove strbuf-based type infrastructure, and clean up fsck's unknown type processing. New test infrastructure was added in patches 8/13 and 9/13 to support future object format testing without relying on the deprecated functionality. The only remaining discussion point is how to document the deprecation of `cat-file --allow-unknown-type` - Jeff prefers minimal changes while Patrick Steinhardt suggests more explicit deprecation notes in the manpage. With all technical implementations approved and only this minor documentation question open, the series appears ready for merging.
