Jeff King's series to remove support for non-standard object types in Git is nearing completion, with all 13 patches technically reviewed and approved. The changes simplify Git's object handling by eliminating code paths that were only ever used for testing unknown type handling, not for actual feature development. Junio Hamano has confirmed this cleanup doesn't need to wait for Git 3.0 since the functionality was never intended for production use.

The most substantive discussion centered on patch 2/13, which makes `--allow-unknown-type` a no-op in `git cat-file` while retaining the option for backward compatibility. After some back-and-forth, Junio endorsed the approach, though there's still a minor open question about whether to use `OPT_NOOP_NOARG` to make the no-op status clearer. The series has already removed the write-side support for non-standard types and simplified related code in `git cat-file` and fsck.

In a recent follow-up, Patrick Steinhardt suggested a more descriptive name for a test helper function (`write_loose_obj` instead of `loose_obj`), but Jeff noted this is consistent with existing test helper naming patterns. This minor stylistic point doesn't affect the series' readiness, which appears complete pending any documentation tweaks for patch 2/13. The changes are particularly helpful for Patrick's ongoing ODB abstraction work by removing parallel implementations of object writing code.
