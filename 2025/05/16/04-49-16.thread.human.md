Jeff King (Peff) continues his series to remove support for non-standard Git object types, now at version 1 with four patches. The thread focuses on simplifying Git's core object handling by eliminating a decade-old experiment with non-standard types that never matured beyond test cases.

The first three patches established the technical foundation: fixing a typo, making `--allow-unknown-type` a no-op in `git cat-file`, and removing the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag while simplifying loose object header parsing. The new fourth patch builds on this by converting type handling in `git cat-file -t` from a strbuf-based approach to using the object_type enum directly, removing now-unnecessary string buffer management.

So far the series appears uncontroversial, with only Peff contributing. The changes are mechanical and well-contained, touching `builtin/cat-file.c` and object-file.* while maintaining behavior for standard types. The main open question is whether this needs to wait for Git 3.0, though Peff argues the functionality was never properly usable. The series continues to progress logically through the codebase, with nine more patches expected to complete the removal.
