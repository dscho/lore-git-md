This thread documents Jeff King's (Peff) completed 13-patch series removing support for non-standard object types in Git's core object handling. The series simplifies Git's internals by eliminating a decade-old experimental feature that never matured beyond testing purposes, reducing maintenance burden. 

Junio Hamano has reviewed and approved all technical aspects of the series, which is now complete at version 1. The changes span read-side removal, cleanup, write-side removal, and final cleanups - including removing the ability to create non-standard types with `hash-object --literally` and eliminating the parallel `write_object_file_literally()` implementation. New test infrastructure (`test-tool zlib` and `t/lib-loose.sh`) was added to support future object format testing.

The only remaining discussion point is documentation approach for making `--allow-unknown-type` a no-op in `git cat-file`, where Jeff prefers minimal documentation while Patrick Steinhardt suggests a more explicit deprecated section in the manpage. Both agree on the technical implementation using `OPT_NOOP_NOARG`. A minor style discussion about the zlib test tool's loop structure was resolved with both maintainer and author agreeing the current implementation is sound.

With all patches technically approved, this series appears ready for merging once the minor documentation question is settled, marking the end of Git's decade-long experiment with non-standard object types.
