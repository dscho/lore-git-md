Performance test patch for the path-walk delta compression feature. This is part 4/13 of the series introducing the `--path-walk` option for pack-objects and repack.

The patch adds performance tests comparing the new path-walk delta compression against the existing name-hash versions (v1 and v2) across three scenarios: thin packs (small pushes), big packs (full repacks), and shallow fetch packs. The tests measure both time and resulting pack size.

Key findings from the test data:
- For the Git repo itself, path-walk shows comparable performance to name-hash v2, with slightly smaller pack sizes (16.3M vs 16.4M for big packs)
- More dramatic improvements show up in the microsoft/fluentui repo where path-walk reduces thin pack size from 1.2M to 18.4K and speeds up from 0.36s to 0.08s
- Linux kernel tests show path-walk producing smaller packs (158.5M vs 159.1M for name-hash v2) but with slightly slower times (13.92s vs 12.32s) due to lack of threading in current implementation

The test infrastructure is refactored to use a new `test_all_with_args` helper function that runs the same battery of tests against either name-hash versions or the new path-walk option. The repack tests remain separate since path-walk repack support comes in a later patch.

This test suite will be important for monitoring performance as the path-walk implementation evolves, particularly when threading optimizations are added. The results already validate the core premise that path-based delta selection can outperform name-hashing in repositories with certain file organization patterns.
