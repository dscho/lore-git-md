This thread addresses improvements to `git stash`'s option parsing, particularly around the `-p/--patch` flag. The discussion produced a two-patch series following Junio Hamano's suggestion to separate concerns. 

The first patch fixed a regression from 2020 where `git stash -p <pathspec>` broke due to incorrect argv handling, specifically checking the wrong argument index after "push" was prepended. Phillip Wood implemented the fix with test coverage verifying both the corrected behavior and continued rejection of malformed syntax.

The just-received second patch extends this by allowing more flexible option ordering, such as `git stash -m <message> -p <pathspec>`. It uses PARSE_OPT_STOP_AT_NON_OPTION to maintain safety against subcommand typos while accepting reasonable option variations. The implementation preserves the assumption that `-p` implies "push" but handles pathspecs and messages in more combinations.

The series demonstrates consensus on this split approach, with the first patch addressing the immediate regression and the second carefully expanding valid syntax without compromising safety. Both patches include comprehensive test coverage in t3903-stash.sh and maintain backward compatibility.
