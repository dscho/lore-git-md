This thread explores performance optimizations for packfile handling, particularly when dealing with missing packs referenced by stale multi-pack-index (midx) entries. The original patch by Patrick Steinhardt reduced syscalls in `add_packed_git()` by reordering checks for auxiliary files (.keep, .promisor, .cruft) when the main packfile doesn't exist, showing a 75% reduction in syscalls for pathological cases. 

The discussion revealed important historical context from Junio Hamano about the original safety constraints requiring .idx checks to precede .pack checks to prevent using incomplete packs. Jeff King (peff) agreed with these safety requirements but proposed a separate optimization: adding a "failed lookup" state (-1) to midx->packs[] to cache negative results and avoid repeated syscalls for missing packs. 

In the latest development, Hamano has approved King's approach. The new patch implements this cache by modifying `midx.c` to handle the new state, skip already-failed lookups, and maintain the state during cleanup. The implementation uses a type-punned pointer (casting -1 to void*) - a common Git pattern - while preserving the critical safety invariants around pack verification order. 

The thread has productively narrowed from broader architectural questions to this focused optimization that addresses the core performance issue while maintaining packfile integrity. With Hamano's approval, this solution appears likely to be adopted, though follow-ups may still explore lazy-loading auxiliary files as a future optimization.
