This thread discusses a performance issue in Git's packfile handling when dealing with missing packfiles. The current implementation makes unnecessary system calls by checking auxiliary files (like `.keep` or `.promisor`) before verifying if the packfile itself exists, which becomes problematic when the pack is missing.

The patch from the author reorders these checks in `add_packed_git()` (in `packfile.c`) to first verify the packfile's existence before checking auxiliary files, then restoring the packfile name afterward. This simple change reduces redundant system calls by 75% in edge cases where a stale multi-pack-index references nonexistent packs, as seen in a production environment. While the optimization won't affect most repositories, it provides a meaningful improvement for this specific scenario with minimal code changes and no functional impact. The author considered but decided against implementing a more complex negative lookup cache solution.
