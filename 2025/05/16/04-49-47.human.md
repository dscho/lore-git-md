This is the fourth patch in Jeff King's series removing support for non-standard object types from Git's core. The patch simplifies the `git cat-file -t` implementation by switching from using a strbuf to store the type name to using the standard object_type enum, now that we no longer need to handle unknown types.

The change removes the temporary strbuf that was previously used to store type names and replaces it with direct use of the type field in the object_info struct. This makes the code both simpler (removing 5 lines) and more type-safe, while maintaining the same external behavior for valid objects. The patch is a straightforward mechanical change that follows naturally from the earlier removal of the unknown-type support in patch 3/13.

This continues the series' trend of cleaning up now-unnecessary code paths while keeping the core functionality intact. The change appears well-contained and low-risk, touching only the cat-file command's type-display logic. Since this builds on the earlier removal of unknown type support, it should not introduce any new compatibility concerns.
