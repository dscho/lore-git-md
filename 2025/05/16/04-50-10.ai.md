This is the 12/13 patch in Jeff King's series removing support for non-standard object types, focusing on the `git hash-object` command's `--literally` flag handling.

The patch simplifies the internal implementation of `--literally` by using `OPT_NEGBIT` to directly modify the `INDEX_FORMAT_CHECK` flag during option parsing, rather than passing around a separate boolean. This eliminates the need for the `literally` parameter in several helper functions (`hash_fd`, `hash_object`, `hash_stdin_paths`), making the code more straightforward. The change removes 16 lines while adding 11, for a net reduction of 5 lines.

The modification maintains the same behavior where `--literally` bypasses format checking, but now implements it through direct flag manipulation rather than parameter passing. This builds on previous patches that removed the specialized `hash_literally()` function (patch 10/13) and simplified flag handling (patch 11/13).

Key technical details:
- Replaces boolean `literally` parameter with `OPT_NEGBIT` flag clearing
- Updates all callers to drop the now-unused parameter
- Maintains `INDEX_FORMAT_CHECK` flag clearing behavior
- Touches only `builtin/hash-object.c`
- Part of broader effort to remove non-standard object type support

The change appears mechanical and low-risk, following the established pattern of simplifying the codebase while maintaining functionality. It continues the series' trend of removing indirection and special cases from the object handling code.
