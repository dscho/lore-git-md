Performance optimization integrating `git add -p/-i` with sparse index, part of the interactive commands optimization series. This patch specifically moves the sparse index integration point earlier in `cmd_add()` to prevent unnecessary index expansion during interactive operations (`-p` and `-i` modes). The change enables sparse index awareness for these commands, maintaining performance benefits when editing files within the sparse checkout cone while still expanding for out-of-cone edits.

Key technical details include:
- Moves `command_requires_full_index=0` setting before interactive control flow in `builtin/add.c`
- Adds comprehensive test coverage in `t1092-sparse-checkout-compatibility.sh` verifying:
  * No expansion for in-cone edits via -p/-i
  * Required expansion for out-of-cone edits
  * Correct behavior with user input sequences (y/n responses)
  * Status/reset validation
- Maintains existing behavior where out-of-cone edits still expand the index
- Follows established sparse-index integration pattern seen in other commands

The patch builds on Elijah Newren's prior review feedback, particularly around test accuracy for index expansion behavior. Performance improvements were previously measured at 96.7% reduction for `git add -p` operations with sparse index. This change completes the integration while maintaining all edge case handling through rigorous test coverage, including both in-cone and out-of-cone scenarios. The implementation aligns with the broader sparse-index optimization effort's goal of minimizing tree parsing overhead.
