This is patch 2/13 in Jeff King's series removing support for non-standard object types from Git's core. The patch focuses on `git cat-file`'s `--allow-unknown-type` option, which previously provided limited access to objects with non-standard types (not blob/tree/commit/tag).

The patch makes `--allow-unknown-type` a no-op while keeping the option available for backward compatibility. This is the first user-visible change in the series, though the impact is minimal since the functionality was severely limited (could only show type/size, not contents; didn't work with packed objects or transfers). The commit message thoroughly explains why this feature wasn't useful in practice while still being careful to avoid breaking any existing scripts that might use the option harmlessly.

Key technical details:
- Removes `--allow-unknown-type` from documentation while keeping it as a hidden option
- Drops `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag usage in `cat_one_file()`
- Simplifies test suite by removing all `--allow-unknown-type` test cases while keeping tests that verify rejection of broken objects
- Maintains backward compatibility by making the option a no-op rather than removing it entirely

The changes touch `builtin/cat-file.c`, its documentation, and the extensive test file `t/t1006-cat-file.sh`. The test changes are particularly significant, removing about 2/3 of the test cases since they were specifically testing the now-removed functionality.

This patch sets up for later patches that will remove the underlying support for unknown types from Git's object handling code. The careful handling of backward compatibility here suggests the author is being particularly cautious about not breaking any existing (if unlikely) use cases during this major refactoring.
