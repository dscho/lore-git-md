This is the final patch in Jeff King's series removing support for non-standard object types from Git's core. The patch completes the cleanup by removing the now-unused `write_object_file_literally()` function and its supporting infrastructure after the previous patches eliminated all callers.

The removal eliminates a parallel implementation path in `write_object_file_literally()` that had grown increasingly divergent from the main `write_object_file()` path, including tricky duplicated code around loose object map handling. The patch removes several helper functions (`format_object_header_literally`, `write_object_file_prepare_literally`, `hash_object_file_literally`) that were only used by this code path.

Key technical changes include:
- Deletes 80 lines of code while adding only 6 (net -74)
- Removes the last remaining string-based type handling in object-file.c
- Simplifies `hash_object_file()` to use the standard `write_object_file_prepare()` path
- Updates documentation comments to remove references to the deleted functionality
- Maintains all standard object type handling while removing the non-standard path

This completes the series' goal of removing all support for non-standard object types from Git's core. The changes are mechanical and unlikely to be controversial given the thorough preparation in earlier patches. The series appears ready for merging, having addressed all technical aspects of the removal while maintaining test coverage through the new test helpers introduced earlier in the series.
