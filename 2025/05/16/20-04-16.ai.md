This is the final version of Elijah Newren's feature series adding mergeability checking to `git merge-tree`, now with the interface renamed from `--dry-run` to `--quiet` based on mailing list feedback. The series provides hosting platforms with an efficient way to check if branches can be merged without computing full merge results.

The core implementation introduces a `mergeability_only` flag in merge-ort that skips writing merged blobs/trees in outer merges (except for rename/rename+modify cases) while preserving object writes for inner merges. The user-facing interface now uses `--quiet` to better match Git's convention for silent operation (where `--dry-run` typically shows diagnostics). The change follows Phillip Wood's observation about output behavior consistency across Git commands.

The patch maintains all safety checks against incompatible options (`--messages`, `--stdin`, etc.) and includes comprehensive tests in t4301 verifying empty stdout, no object writes, and correct exit codes. The series has been approved for merging with this final naming adjustment, addressing the last minor inconsistency in interface conventions while keeping the core optimization intact.

Key technical components:
- merge-ort plumbing changes with `mergeability_only` flag
- builtin/merge-tree.c validation for `--quiet`
- Documentation/git-merge-tree.adoc updates
- t/t4301-merge-tree-write-tree.sh test coverage

The optimization allows early conflict detection and avoids unnecessary object writes, particularly useful for Git forges that only need mergeability status. All edge cases are documented and tested, with the implementation now aligned with Git's command-line interface conventions.
