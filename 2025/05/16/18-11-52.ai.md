This is the second patch in a 13-part series introducing path-based delta compression to pack-objects. The patch adds the core `--path-walk` option that enables the new compression strategy, which organizes objects by path before delta compression to improve locality and avoid name-hash collisions.

The implementation replaces the standard object walk with a path-based traversal using the path-walk API. Objects sharing the same path are batched together for delta testing, with a fallback to traditional name-hash delta finding. The patch notes current limitations: incompatible with filters, delta islands, shallow packs, and bitmap indexes, with plans to address some of these in future work. Performance impact is acknowledged as suboptimal due to lack of threading during path-scoped delta calculations, though still sometimes faster than name-hash approach.

Key technical details include:
- New `add_objects_by_path()` callback for path-walk API that handles object entry creation and delta testing
- `get_object_list_path_walk()` as alternative to standard revision walk
- Incompatibility handling for conflicting options like `--filter` and `--shallow`
- Basic test cases verifying path-walk functionality
- Documentation updates for new option and its constraints

The patch builds on the path-walk API introduced earlier in the series, with subsequent patches expected to add threading optimizations and deeper integration. Performance testing will follow in later patches, though the commit message hints at observed speedups even in this unoptimized state.
