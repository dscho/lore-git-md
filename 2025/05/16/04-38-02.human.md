This is a naming discussion in the ongoing `git-blame-tree`/`git-last-modified` feature proposal thread. Patrick Steinhardt responds to Jeff King's suggestion of integrating the functionality into `git log` as a `--last-modified` option, while also weighing in on the naming debate.

Patrick expresses support for the "git last-modified" name, finding it clear and descriptive. However, he pushes back against Jeff's `git log` integration proposal, arguing that the different traversal behavior would make many existing `git log` options incompatible or confusing. He notes Git already has too many commands with hidden "modes" that are hard to discover and maintain.

The exchange highlights the tension between reusing existing command infrastructure versus creating a new purpose-built tool. Patrick seems to favor a separate `git-last-modified` command that could grow formatting options organically as needed, rather than trying to fit the `git log` model. The discussion remains focused on finding both a technically accurate and user-friendly name while working through the best command structure for this path-modification-tracking functionality.
