Performance optimization for packfile handling focusing on syscall reduction in multi-pack-index scenarios, originally proposed by Patrick Steinhardt. The thread has converged on a robust approach that maintains Git's packfile integrity invariants while reducing unnecessary syscalls for missing packs.

Core problem: Stale MIDX entries were causing repeated failed lookups of missing packfiles via multiple syscalls (access() and stat()). While impact is small in well-maintained repos, the optimization is worthwhile performance improvement.

Current solution (v2 series from Patrick Steinhardt):
1. First patch adds documentation to `add_packed_git()` explaining required ordering of auxiliary file checks (`.keep`, `.promisor`, `.mtimes`) before packfile existence checks, with two key invariants: (a) auxiliary files must be installed before their `.idx` file during creation, and (b) must be deleted after their `.pack` file during removal
2. Second patch implements negative lookup cache in midx.c (Jeff King's suggestion) by storing -1 in midx->packs[] for missing entries, with detailed performance measurements showing 4x speedup for `git log --patch` and syscall reduction from 24,083 to 83 in test case
3. Maintains all safety constraints identified in discussion
4. Uses type-punned pointers following Git conventions
5. Preserves correct cleanup in close_midx()

Key technical constraints clarified through discussion:
- Original optimization of reordering auxiliary file checks was unsafe due to potential race conditions
- Auxiliary files must exist before their .idx file (creation order)
- Auxiliary files must be deleted after their .pack file (deletion order)
- unlink_pack_path() already maintains correct deletion order

Implementation details:
- prepare_midx_pack() now caches failed lookups by storing -1 and checks for sentinel value
- nth_midxed_pack() returns NULL for cached misses
- close_midx() skips -1 entries during cleanup
- New comments document the packfile handling invariants

Consensus reached:
- Junio Hamano and Patrick Steinhardt agree on Jeff King's caching approach
- Original auxiliary file reordering optimization was correctly identified as unsafe
- Current solution provides syscall reduction without compromising safety
- Performance data confirms significant improvements (4x speedup, 99.6% syscall reduction)

Open considerations:
- Midx cache invalidation during repacking remains handled by existing mechanisms
- Lazy-loading auxiliary files (earlier Jeff King proposal) deemed too risky
- Performance gains modest but worthwhile given implementation simplicity

The discussion has produced a robust solution that addresses the original performance concern while respecting Git's packfile handling requirements, with clear documentation of the underlying invariants for future work. The documentation patch provides crucial context for the optimization and serves as a safeguard against future unsafe changes.
