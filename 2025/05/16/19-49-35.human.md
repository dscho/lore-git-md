Performance optimization follow-up addressing memory management in batched reference updates. This email from Karthik Nayak responds to Jeff King's observation about a memory leak in the error handling path of `git-receive-pack` when processing batched reference updates. The issue arises from duplicating error strings that were already owned by the strmap, creating leaks when those strings weren't properly freed.

Karthik agrees with Jeff's proposed solution to modify `ref_transaction_error_msg()` to return string literals (`const char*`) rather than allocated strings, which would eliminate the need for callers to manage memory for these error messages. This approach aligns with Junio Hamano's earlier suggestion and would simplify the code by removing the leak while maintaining the same error reporting behavior. The patch shows the necessary changes across several files to implement this, including const-casting when storing literals in the strmap and adjusting cleanup to not free the values.

This appears to be a clean solution to the memory management issue, building on prior discussion in the thread about error handling unification. The change doesn't affect the performance improvements from batched updates but does make the implementation more robust. With this last issue addressed, the series seems ready to move forward.
