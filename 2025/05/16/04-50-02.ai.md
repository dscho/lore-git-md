This is part 9/13 of Jeff King's series removing support for non-standard object types from Git's core. The patch introduces a new test helper library `t/lib-loose.sh` that provides a `loose_obj` function for manually creating loose objects in the object database, bypassing `git hash-object`.

The key technical addition is the `loose_obj` shell function which:
- Takes an object directory path and type as arguments
- Reads object content from stdin
- Handles the low-level object formatting (header + content)
- Uses `test-tool` for hashing and zlib compression
- Creates the proper loose object directory structure
- Returns the object ID

The patch converts three test scripts (`t1006-cat-file.sh`, `t1450-fsck.sh`, and `t1512-rev-parse-disambiguation.sh`) to use this new helper instead of `git hash-object --literally` for creating invalid/unknown object types. This is preparation for completely removing the `--literally` option in later patches.

The helper provides more direct access to the object storage layer than `hash-object`, allowing tests to create objects that would be rejected by Git's normal object creation path. This maintains test coverage while removing the need to support non-standard types in the main codebase.

The implementation handles platform-specific whitespace issues from `wc -c` and integrates cleanly with both the Makefile and meson build systems. The changes to the test scripts are mechanical replacements that don't alter the test behavior, just the mechanism for creating test objects.
