This is a performance optimization patch for Git's merge machinery, specifically adding a `mergeability_only` option to skip unnecessary object writes during merge checks. It's part of an approved series to help Git hosting platforms efficiently verify branch mergeability without computing full merges.

The patch introduces a new flag that modifies merge-ort's behavior in two key ways for the "outer layer" (final merge): it exits upon first detected conflict and avoids writing most merged blobs/trees to the object store. The commit message carefully explains edge cases where objects may still be written (during inner merges or rename/rename+modify conflicts) and justifies the implementation choices with detailed technical reasoning.

The changes touch core merge-ort logic, adding conditional checks around object writing operations and early exit paths. While the optimization doesn't guarantee absolute minimal object writes in all cases, it covers the common scenarios that matter most for hosting platforms. The patch appears well-considered, with thorough documentation of limitations and clear test coverage indicated in the series context.

This is the first of two patches in v4 of the series, following previous iterations that refined the interface naming (from `--dry-run` to `--quiet` per mailing list feedback). The changes are focused and surgical, modifying only merge-ort.c and merge-ort.h with the core logic changes needed to support the new optimization mode.
