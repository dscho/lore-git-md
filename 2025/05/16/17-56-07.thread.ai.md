MPTCP support thread summary:

This thread discusses Multipath TCP (MPT CP) support for Git on Linux systems, initially proposing automatic use of MPTCP v1 when available with fallback to regular TCP. The discussion has evolved from implementation details to questioning whether Git should be MPTCP-aware at all, given RFC 6897's transparency guarantees, with Junio Hamano raising this fundamental architectural concern.

Muhammad Nuzaihan has proposed technical improvements including Linux-specific checks and error handling, while Brian Carlson and Phillip Wood raised compatibility concerns. The latest email from Muhammad strengthened the case for MPTCP with: (1) a concrete use case of uninterrupted operations when switching between WiFi/Ethernet, (2) production deployment evidence from Apple/Intel/Red Hat, and (3) implementation improvements using `core.mptcp` configuration (default false for clients, true for servers) after consulting MPTCP developer Matthieu Baerts.

Matthieu Baerts (Linux kernel MPTCP maintainer) has now provided key technical clarifications addressing Junio's RFC 6897 concerns. He explains why Linux's MPTCP implementation requires explicit application support through socket creation with `IPPROTO_MPTCP` rather than operating transparently, validating Muhammad's technical approach. The email details the minimal code change needed (single protocol parameter modification in socket() call) and contrasts this with alternative enforcement methods like `mptcpize` and LD_PRELOAD, arguing native support is preferable for controlled deployment.

Key technical details include: MPTCP's dual IPv4/IPv6 support, the v1/v0 distinction, current limitation to port 9418 connections, Linux-specific implementation in `connect.c` requiring IPPROTO_MPTCP socket parameter, and platform-specific checks. The proposal now uses Git-idiomatic configuration (`core.mptcp`) while maintaining platform-specific checks.

Open questions remain: (1) configuration approach (`core.mptcp` vs Makefile knob), (2) platform limitations (Linux-only), and (3) documentation needs. Junio's initial skepticism about application-layer awareness has been addressed by Matthieu's explanation of Linux implementation realities, moving the discussion toward implementation details rather than architectural objections. The thread now focuses on refining the technical approach with input from both Git contributors and MPTCP maintainers.
