MPTCP support thread summary:

This thread introduces Multipath TCP (MPTCP) support for Git on Linux systems, initially proposing automatic use of MPTCP when available (IPPROTO_MPTCP v1) with fallback to regular TCP. The implementation modifies socket creation without requiring configuration changes, specifically targeting the legacy unauthenticated Git protocol (port 9418). 

Brian's follow-up raises compatibility concerns about the automatic approach, identifying three failure scenarios: binaries built with MPTCP support running on stripped-down kernels, IPv6-only connections on IPv4-only MPTCP systems (like FreeBSD), and parallels to Go 1.24's problematic MPTCP rollout. He argues for making MPTCP configurable while keeping it default, noting that remaining users of the legacy protocol may be precisely those with unusual configurations where automatic behavior could fail. The discussion reveals the current implementation affects only the legacy protocol, which sees little modern use. Technical details include MPTCP v1's improvements over v0 in handling middlebox limitations, layer 4 networking behavior, and the automatic detection mechanism's limitations. The thread now has an open question about whether and how to add configuration options for MPTCP usage, with Brian advocating for user control while maintaining the current behavior as default. No specific configuration mechanism has been proposed yet.
