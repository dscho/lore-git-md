MPTCP support thread summary:

This thread discusses Multipath TCP (MPT CP) support for Git on Linux systems, initially proposing automatic use of MPTCP v1 when available with fallback to regular TCP. The discussion has evolved through architectural concerns, technical implementation details, and now focuses on configuration design and performance implications.

Muhammad Nuzaihan's original proposal has been strengthened with production deployment evidence and implementation improvements using `core.mptcp` configuration (default false for clients, true for servers). Matthieu Baerts (Linux kernel MPTCP maintainer) provided key technical clarifications explaining why Linux's MPTCP requires explicit application support through `IPPROTO_MPTCP` socket creation, validating the technical approach while addressing Junio Hamano's initial RFC 6897 transparency concerns.

Junio's latest email shifts focus to practical implications, questioning: (1) whether unconditionally passing IPPROTO_MPTCP could harm functionality when MPTCP is unavailable, (2) performance tradeoffs between MPTCP and TCP (latency vs throughput), and (3) configuration granularity (suggesting per-repository or per-host settings may be preferable to a global `core.mptcp` switch). His questions indicate the discussion is moving from technical feasibility to user experience design, with particular attention to how this feature integrates with Git's existing configuration model.

Key technical details established so far include: MPTCP's dual IPv4/IPv6 support, Linux-specific implementation requiring IPPROTO_MPTCP socket parameter, current limitation to port 9418 connections, and platform-specific checks in `connect.c`. The proposal maintains Git-idiomatic configuration while addressing platform constraints.

Open questions now center on: (1) final configuration approach (`core.mptcp` scope and granularity), (2) performance impact validation (particularly fallback behavior), (3) documentation needs, and (4) whether additional use case justification is required beyond the demonstrated WiFi/Ethernet handoff scenario. The thread shows productive collaboration between Git contributors and MPTCP maintainers, with Junio serving as architectural gatekeeper ensuring the feature's design aligns with Git's configuration philosophy.
