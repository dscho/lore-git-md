MPTCP support thread summary:

This thread discusses Multipath TCP (MPT CP) support for Git on Linux systems, initially proposing automatic use of MPTCP v1 when available with fallback to regular TCP. The discussion has evolved from implementation details to questioning whether Git should be MPTCP-aware at all, given RFC 6897's transparency guarantees, with Junio Hamano raising this fundamental architectural concern.

Muhammad Nuzaihan has proposed technical improvements including Linux-specific checks and error handling, while Brian Carlson and Phillip Wood raised compatibility concerns. The latest email from Muhammad strengthens the case for MPTCP with: (1) a concrete use case of uninterrupted operations when switching between WiFi/Ethernet, (2) production deployment evidence from Apple/Intel/Red Hat, and (3) implementation improvements using `core.mptcp` configuration (default false for clients, true for servers) after consulting MPTCP developer Matthieu Baerts.

Key technical details include: MPTCP's dual IPv4/IPv6 support, the v1/v0 distinction, current limitation to port 9418 connections, and Linux-specific implementation in `connect.c`. The proposal now uses Git-idiomatic configuration while maintaining platform-specific checks.

Open questions remain: (1) whether to proceed given RFC 6897's transparency principle, (2) configuration approach (`core.mptcp` vs Makefile knob), (3) platform limitations (Linux-only), and (4) documentation needs. Junio's skepticism about application-layer awareness contrasts with Muhammad's demonstrated user-visible benefits for large repository operations. The thread now balances philosophical protocol design considerations against concrete use cases and implementation refinements.
