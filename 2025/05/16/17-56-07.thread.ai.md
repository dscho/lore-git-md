MPTCP support thread summary:

This thread discusses Multipath TCP (MPT CP) support for Git on Linux systems, initially proposing automatic use of MPTCP v1 when available with fallback to regular TCP. The discussion has evolved through architectural concerns, technical implementation details, configuration design, and now spans server deployment considerations across multiple transports.

Muhammad Nuzaihan's original proposal has been strengthened with production deployment evidence and implementation improvements using `core.mptcp` configuration (default false for clients, true for servers). Matthieu Baerts (Linux kernel MPTCP maintainer) provided key technical clarifications explaining Linux's MPTCP requirements through `IPPROTO_MPTCP` socket creation, validating the approach while addressing Junio Hamano's initial RFC 6897 transparency concerns. Matthieu confirmed Linux's robust fallback to TCP when MPTCP is unavailable, with production-proven behavior since Apple's 2013 deployment.

Junio's earlier email on server-side deployment raised `git-daemon` usage patterns and `inetd` integration challenges. Matthieu's latest response confirms `inetd`-managed `git-daemon` requires MPTCP configuration at the `inetd` level, with modern Linux distributions already including MPTCP protocol definitions in `/etc/protocols`. The discussion now extends beyond git:// protocol, with Matthieu detailing technical pathways for MPTCP integration with HTTPS (via libcurl's `CURLOPT_OPENSOCKETFUNCTION`) and SSH transports, though noting OpenSSH maintainers have historically rejected MPTCP patches due to lack of BSD support.

Key technical details established include: MPTCP's mandatory opt-in nature on Linux, dual IPv4/IPv6 support, Linux-specific socket requirements, current port 9418 limitation, platform-specific checks in `connect.c`, header overhead implications, `inetd` integration requirements, libcurl socket callback mechanism for HTTPS transport, and OpenSSH platform limitations. External references include curl PR #13278 and MPTCP project FAQ documenting OpenSSH workarounds.

Open questions now include: (1) final configuration approach (global vs per-repository/host settings), (2) performance impact documentation needs, (3) use case justification beyond WiFi/Ethernet handoff, (4) latency/throughput tradeoff guidance in documentation, (5) `inetd` deployment documentation requirements, and (6) feasibility of MPTCP support in Git's HTTPS/SSH transports given third-party component constraints. The thread continues productive collaboration between Git contributors and MPTCP maintainers, with technical pathways now identified for broader transport integration despite OpenSSH's platform limitations. Matthieu's technical clarifications and Junio's operational insights have strengthened the proposal's foundation while surfacing real-world deployment considerations across Git's transport stack.
