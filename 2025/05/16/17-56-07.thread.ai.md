MPTCP support thread summary:

This thread discusses Multipath TCP (MPTCP) support for Git on Linux systems, initially proposing automatic use of MPTCP v1 when available with fallback to regular TCP, specifically for the legacy unauthenticated Git protocol (port 9418). The implementation modifies socket creation without configuration changes.

Brian raised compatibility concerns about the automatic approach, identifying three failure scenarios: stripped-down kernels, IPv6-only connections on IPv4-only MPTCP systems, and parallels to Go 1.24's problematic MPTCP rollout. He advocated for making MPTCP configurable while keeping it default.

Muhammad Nuzaihan responded by pushing back on these concerns, noting the patch specifically uses MPTCP v1 (not problematic v0) with improved middlebox support and proper fallback. He questioned whether stripped-down kernels would realistically lack both MPTCP and IPv4 support, and challenged the Go 1.24 comparison by requesting evidence those issues occurred with v1. Nuzaihan defended testing with the legacy protocol first but conceded to potentially making it configurable via `.gitconfig` with default-off behavior.

In a follow-up, Nuzaihan provided a Wireshark screenshot demonstrating successful MPTCP operation with the legacy Git protocol (port 9418), reinforcing his position that this basic protocol is the right starting point. He continues to distinguish MPTCP v1's reliable fallback behavior from v0's issues, while challenging critics to provide concrete evidence of v1 problems. The discussion remains unresolved regarding configuration - Nuzaihan appears willing to implement a `.gitconfig` option defaulting to off, though maintains skepticism about the need given v1's improved behavior. The empirical validation shows current implementation works as intended for the Git protocol, while broader protocol support (SSH/HTTP) remains a future consideration.

Key technical details include: MPTCP's dual IPv4/IPv6 support, the v1/v0 distinction with v1's proper fallback mechanisms, current limitation to port 9418 connections, and the existing `#ifdef` check. The thread shows tension between automatic modern adoption versus conservative compatibility, with Nuzaihan providing implementation evidence while acknowledging possible user control. No specific configuration implementation has been proposed yet, and the question of expanding beyond the Git protocol remains open.
