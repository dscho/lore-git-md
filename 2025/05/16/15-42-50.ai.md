This is a follow-up discussion in the static analysis fixes thread, specifically addressing the bundle-uri creation token parsing issue. Jeff King (Peff) responds to Phillip Wood's proposal for a new `strtoul_u64()` helper function to replace the previously approved `sscanf()` solution for 64-bit value parsing.

Key technical points:
- Jeff confirms the need for proper 64-bit parsing on Windows, agreeing with Phillip's approach of using `strtoumax()`-based solution
- Notes most existing large-value configs in Git use `unsigned long` rather than 64-bit values
- Suggests a broader solution might involve adding `repo_config_get_u64()` infrastructure
- Strongly advocates against using `*scanf()` with `%s` due to security concerns, though notes numeric placeholders are less dangerous
- Points to `builtin/gc.c` as an example of careful-but-ugly `fscanf()` usage with size-limited strings
- Recommends Git's standard pattern of reading into buffers first then parsing

The discussion shows consensus forming around Phillip's `strtoul_u64()` implementation while opening the door for future work on Git's numeric parsing utilities. Jeff's response reinforces the thread's pattern of using static analysis findings to drive deeper architectural improvements. The exchange also highlights ongoing concerns about input validation strictness and scanf-family function usage in the codebase.
