Refactoring patch in Jeff King's series removing non-standard object type support. This is patch 7/13, continuing the systematic elimination of string-based type handling from Git's object storage internals.

The patch removes the `type_name` strbuf field from `struct object_info` and all related code that populated it. This was originally meant to support returning arbitrary type strings for non-standard object types, but as the series establishes, such types are now considered errors rather than valid cases to handle. The change simplifies several object-info related functions by removing now-unnecessary string copying and conditionals.

The diff shows straightforward mechanical changes across object-file.c, object-store.c, object-store.h, and packfile.c. Each removal follows the same pattern: deleting code that previously handled the strbuf case while preserving the enum-based type handling that remains. The patch builds on earlier work in the series that already migrated callers away from string-based type queries.

This continues the series' trend of making the codebase both simpler and more type-safe by removing legacy support for experimental features that never gained real-world usage. The changes appear well-contained and unlikely to introduce new bugs, as they're removing dead code paths rather than modifying live behavior.
