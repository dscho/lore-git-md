Performance optimization for packfile handling when dealing with missing packs.

This patch reorders the checks in `add_packed_git()` to avoid unnecessary `access(3p)` syscalls when a packfile doesn't exist. The current implementation first checks for auxiliary files (`.keep`, `.promisor`, `.cruft`) before verifying the packfile itself, which wastes syscalls when the pack is missing. The change moves the packfile existence check first, then restores the packfile name after checking the auxiliary files.

The motivation comes from a production issue where a stale multi-pack-index referenced nonexistent packs, causing hundreds of thousands of redundant syscalls. While this is an edge case, the fix reduces syscalls by 75% for missing packs with minimal code changes. The author considered but rejected adding a negative lookup cache as too complex for the benefit.

The patch touches only `packfile.c`, modifying the order of operations in `add_packed_git()` while maintaining the same functionality. Key changes include moving the `stat()` check earlier and restoring the packfile name after auxiliary file checks. The author acknowledges this won't affect most repositories but considers it a worthwhile low-risk optimization.
