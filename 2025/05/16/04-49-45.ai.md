This is the third patch in Jeff King's series removing support for non-standard object types from Git's core. Following the removal of the `--allow-unknown-type` option from `git cat-file` in patch 2/13, this change eliminates the now-unused `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag and its associated infrastructure.

The patch removes the flag definition from `object-store.h` and cleans up related code in `object-file.c` that handled oversized headers for unknown types. The `unpack_loose_header()` function is simplified to no longer take a `strbuf` parameter, as it was only used for unknown type handling. The function now always returns `ULHR_TOO_LONG` for oversized headers rather than attempting to inflate them into a buffer.

Key technical changes include:
- Removal of `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag and all its uses
- Simplification of `unpack_loose_header()` signature and implementation
- Removal of `hdrbuf` handling in `loose_object_info()`
- Updates to callers including `read_loose_object()` and streaming.c
- The patch retains the `ULHR_TOO_LONG` distinction from `ULHR_BAD` for slightly better error messages, though this could have been removed as well.

This is a straightforward cleanup that builds on the previous patch's removal of unknown type support. The changes are mechanical and focused, with no apparent loose ends or controversial aspects. The patch maintains consistency with the series' goal of simplifying object handling by removing unused complexity.
