Thread identity: Technical discussion about optimizing Git's index file structure, initiated by Jon Forrest with a "two-file index" proposal to avoid full resorting during `git add` operations.

Core problem: Current index implementation requires full resorting when adding files, which becomes expensive for large repositories. Proposal suggests separating sorted filename lookup from unsorted entry storage to reduce data movement.

Key technical details:
- Proposed "index index" would store sorted (filename, offset, length) tuples pointing to unsorted entries in main index
- Main index would grow by appending new entries without resorting
- Deleted entries would remain in place with a deletion marker until periodic cleanup
- Still requires sorting but operates on smaller "index index" structure

Current status: Initial proposal stage with no implementation or performance data yet. No prior art or related work referenced in this opening email.

Open questions:
- Impact on other index operations (fast-import, concurrent access)
- Performance characteristics (memory vs disk tradeoffs)
- Cleanup strategy details
- Compatibility with existing index consumers

Participant positions: Only Jon Forrest has contributed so far, proposing the design without implementation. No reviewers or maintainers have weighed in yet.
