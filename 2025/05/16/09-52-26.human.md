This is patch 6/13 in Jeff King's series removing support for non-standard object types from Git's core. The patch focuses on simplifying fsck's handling of unknown object types by removing the type_name strbuf infrastructure.

The change makes fsck bail immediately when encountering an unknown object type rather than trying to proceed with limited validation. This results in slightly more verbose error messages (now showing the unparseable header) but provides better debugging information. The patch removes now-unnecessary test cases that were specifically checking the old behavior with corrupted unknown-type objects.

Patrick Steinhardt reviews the changes and agrees with the approach, noting that the error reporting is now more straightforward. The patch continues the series' trend of removing string-based type handling in favor of enum-based checks, eliminating maintenance burden for code paths that were never properly usable in practice. This is a straightforward cleanup that aligns with the series' overall goal.
