This is the seventh patch in Jeff King's series removing support for non-standard object types from Git's core. The patch eliminates the `type_name` strbuf field from `struct object_info` and all related code paths, as this was the last remaining mechanism for handling object types as strings rather than enums.

The changes remove the string-based type reporting infrastructure that was previously used for non-standard object types, which the series has established are now considered errors. The patch modifies four files:
- `object-file.c`: Removes strbuf handling from loose object parsing
- `object-store.c`: Drops type string handling in cached object info
- `object-store.h`: Removes the `type_name` field declaration
- `packfile.c`: Eliminates string-based type reporting for packed objects

This is a straightforward mechanical change that builds on the previous patches' conversion to enum-only type handling. The removal is safe because earlier patches already migrated all callers away from the string-based interface. The patch continues the series' trend of simplifying the codebase by removing now-unused functionality, with no expected behavior changes for normal Git operations.

This patch appears uncontroversial as it's a natural follow-on to the earlier conversions and removes code that is now unused. It touches core object-handling code but makes focused, well-isolated changes that maintain the same behavior for standard object types while dropping support for the non-standard ones that were the series' target.
