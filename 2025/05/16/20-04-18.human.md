This is the final patch in a series adding mergeability checking to `git merge-tree`, implementing the new `--quiet` flag for efficient merge conflict detection without full merge computation. The patch adds the user-facing `--quiet` option that leverages the internal `mergeability_only` optimization from the previous commit. When enabled, it suppresses all output and avoids writing most merge objects to the object store, while still detecting conflicts. This is particularly useful for Git hosting platforms that only need to know if a merge would succeed, not the full results.

The implementation includes thorough validation to prevent incompatible option combinations (like `--quiet` with `--messages` or `--stdin`) and adds comprehensive tests verifying both successful and conflicted merge scenarios. The tests confirm that no objects are written to the object store and no output is produced when using `--quiet`, while maintaining correct exit codes.

This completes the series' goal of providing an efficient mergeability check for Git hosting platforms, with the final interface refined based on earlier feedback to use `--quiet` (rather than `--dry-run`) to align with Git's conventions for silent operation. The patch appears well-tested and ready for inclusion.
