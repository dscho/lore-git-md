This is a performance optimization patch integrating `git apply` with the sparse index, part of Derrick Stolee's series to make interactive commands sparse-index aware. The patch focuses on preventing unnecessary index expansion when `git apply` is used as a child process by commands like `git add -p`.

The key change is setting `command_requires_full_index=0` in `builtin/apply.c`, allowing the sparse index to remain unexpanded during operations. The implementation leverages existing sparse index support in the underlying index manipulation code, requiring only this configuration change for the builtin.

The patch includes comprehensive test coverage in `t1092-sparse-checkout-compatibility.sh` verifying:
1. Basic `git apply` functionality with patches inside/outside sparse definitions
2. Index expansion behavior when applying patches to out-of-cone files
3. Edge cases around partially expanded indexes and cached operations

Notable test assertions confirm:
- Applying patches to in-cone files preserves sparse index
- Out-of-cone patches fail without `--index/--cached` (matching filesystem constraints)
- Index expansion occurs when necessary (for `--index` operations)
- Cached operations behave differently with partially vs fully collapsed indexes

This foundational change enables the performance improvements seen in the series' later patches (96.7% speedup for `git add -p`), while maintaining correct sparse-checkout behavior. The tests model both current behavior and edge cases that might affect dependent commands. Elijah Newren's prior feedback on test accuracy appears incorporated, with clear distinctions between in-cone and out-of-cone file handling.
