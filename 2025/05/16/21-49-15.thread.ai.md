Bug report about symlink regression in Git 2.49.0 on Windows affecting `git difftool --dir-diff` operations. Original reporter Chris Conti described a custom difftool alias `diffdirsym` that temporarily enables symlinks via `-c core.symlinks=true` failing with "Function not implemented" errors during directory diff operations with Beyond Compare, despite working in Git 2.48.1. Environment: Windows 10, PowerShell 5.1, Git built with OpenSSL 3.2.4.

Johannes Schindelin (Dscho) responded, identifying this as similar to GitHub issue #5517 and pinpointing commit 8241ae63d821 ("difftool: eliminate use of global variables") as the likely culprit. This commit was part of the ongoing `the_repository` removal/refactoring effort and appears to have inadvertently changed symlink behavior defaults on Windows during the temporary file setup phase of directory diffs. The regression affects Windows users relying on symlink functionality in difftool operations, particularly those using custom aliases that temporarily enable symlinks.

Key technical details: The issue manifests when `difftool --dir-diff` creates symlinks in temporary directories for comparing changed files. The Windows implementation broke when global variables were removed from difftool.c, though the commit wasn't Windows-specific. Current status: Schindelin noted time constraints preventing immediate fix but provided the key reference point (commit 8241ae63d821) for further debugging. This remains an open regression affecting a specific but legitimate Windows use case.
