Performance test addition for the path-walk delta compression feature. This is part of a larger series introducing `--path-walk` as an alternative delta compression strategy that groups objects by path rather than name hash.

The patch adds performance tests comparing `--path-walk` against the existing name-hash versions (v1 and v2) across three scenarios: thin packs (small pushes), big packs (full repacks), and shallow fetch packs. Results show path-walk is competitive with name-hash v2 in most cases, with notable improvements in specific repositories like microsoft/fluentui where it reduces thin pack size from 1.2MB to 18.4KB and speeds up packing from 0.36s to 0.08s.

The test refactors existing name-hash performance tests into a helper function to avoid duplication when testing the new path-walk option. While current timings show path-walk is sometimes slightly slower due to lack of threading (which will be added later), the size improvements demonstrate the potential benefits, particularly for repositories with many similarly-named files. The Linux kernel results show path-walk matching name-hash v2's space savings (158.5MB vs 159.1MB) while being slightly faster than v1 (13.92s vs 15.29s).

This appears to be a well-constructed performance test that validates the real-world benefits promised by the path-walk feature, with clear before/after comparisons across multiple repository types. The results support the series' claims about improved delta compression for certain workloads.
