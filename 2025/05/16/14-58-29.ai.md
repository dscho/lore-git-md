This is a bugfix patch for the stash command's option parsing behavior. The patch addresses a regression where "git stash -p <pathspec>" stopped working as intended after a 2020 refactoring, and expands the cases where the command will assume "push" when given patch mode options.

The key technical details:
- Fixes a regression from commit 8c3713cede7 where "-p" parsing broke due to incorrect argv handling
- Relaxes the strictness of 9e140909f61's "push" assumption to work with more option combinations like "-m <message> -p <pathspec>"
- Uses PARSE_OPT_STOP_AT_NON_OPTION when push is assumed to properly handle option ordering
- Adds new tests/t3903-stash.sh cases to verify both the fixed behavior and maintain the rejection of malformed commands like "stash <pathspec> -p"

The patch touches builtin/stash.c's option handling logic and adds test coverage. It maintains backward compatibility while making the command more flexible in its interpretation of ambiguous invocations. The changes are well-motivated by the commit history and include tests to prevent future regressions.
