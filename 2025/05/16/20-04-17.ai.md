Performance optimization for merge-ort plumbing with new mergeability_only flag.

This patch introduces a `mergeability_only` option to the merge-ort machinery, enabling hosting platforms to efficiently check mergeability without computing full merges. The key optimization is skipping object writes in outer merges (call_depth=0) while still performing them for inner merges (call_depth>0) and rename/rename+modify cases. The implementation:

1. Adds the new flag to `struct merge_options` in merge-ort.h
2. Modifies object-writing functions (handle_content_merge, write_tree) to check the flag and call_depth before writing
3. Adds early exit from process_entries() on first conflict detection in outer merges
4. Includes safety checks to prevent incompatible combinations with other options

The patch carefully documents edge cases where objects may still be written despite the optimization, particularly:
- Inner merges (recursive base merges) always write objects
- Rename/rename+modify conflicts in outer merges still trigger object writes
- The "first conflict" detection is limited to process_entries() for implementation simplicity

The changes touch core merge-ort.c logic around blob/tree writing and conflict processing, with corresponding updates to handle_content_merge() and process_entries(). This builds on the approved series goal of providing efficient mergeability checks for Git hosting platforms while maintaining correctness in edge cases.
