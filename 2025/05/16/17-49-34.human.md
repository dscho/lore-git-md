This is a bugfix patch addressing submodule configuration safety, now in its fourth iteration. The patch prevents `.gitmodules` entries from being silently overwritten when reusing paths for submodules, building on previous discussion in the thread.

The key change modifies `module_add()` to detect when a submodule name is being reused for a different path, which could lead to incorrect configuration overwrites. When such a conflict is found, Git now either errors out (default behavior) or, when using `--force`, generates unique names by appending incrementing numbers (e.g., foo, foo1, foo2). The implementation handles memory ownership cleanly using Git's standard `to_free` pointer idiom.

The patch also includes a secondary improvement to avoid writing redundant `submodule.<name>.active` entries when the submodule path is already covered by a pattern in `submodule.active`, addressing a separate configuration bloat issue reported by Moritz. This uses `wildmatch()` to check path patterns.

Test coverage in t7400 verifies both the error behavior and the numbering scheme through sequences of add/move/re-add operations. The implementation appears well-considered, incorporating feedback from previous reviews to remove unnecessary helper functions and standardize memory management. This version seems ready for consideration after the productive iteration shown in the thread.
