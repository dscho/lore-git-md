Performance optimization integrating `git apply` with the sparse index, part of Derrick Stolee's series to make interactive commands sparse-index aware. This patch enables sparse index support for `git apply`, which is particularly important since it's used as a child process by `git add -p` and other interactive commands. The main change is setting `command_requires_full_index=0` in `builtin/apply.c`, allowing the command to operate without expanding the sparse index unnecessarily.

The patch includes comprehensive tests in `t1092-sparse-checkout-compatibility.sh` that verify:
- Applying patches to files inside the sparse checkout works normally
- Applying patches to files outside fails without `--index` or `--cached`
- Index expansion behavior when applying patches to out-of-cone files
- That the sparse index isn't expanded unnecessarily in most cases

This builds on previous sparse index work and follows the established pattern of incrementally enabling sparse index support command by command. The performance impact is significant - earlier in the thread we see a 96.7% runtime reduction for `git add -p` when combined with this optimization. The tests carefully validate both functionality and performance characteristics, including edge cases around partially expanded indexes.
