Performance optimization integrating sparse index with `git reset --patch` and `git checkout --patch`, part of the ongoing sparse-index/sparse-checkout effort. This patch follows the same pattern as previous optimizations for `git add -p` by moving the `command_requires_full_index=0` setting earlier in `cmd_reset()` to prevent unnecessary index expansion when using `--patch` mode.

Key technical changes include:
- The sparse index optimization is moved before the patch mode logic in `builtin/reset.c`
- Comprehensive test coverage in `t1092-sparse-checkout-compatibility.sh` verifying:
  - No index expansion for in-cone edits
  - Required expansion for out-of-cone edits
  - Behavior parity with full index operations
- New test cases specifically for `checkout --patch` and `reset --patch` scenarios
- Maintains the established pattern where interactive commands expand only for out-of-cone edits

The patch builds on Elijah Newren's prior review feedback and shows 95.6% speedup for `git reset --patch` and 91.6% for `git checkout --patch` in sparse checkouts. Test coverage now includes edge cases with partially expanded indexes and verifies the optimization doesn't break existing functionality. The changes align with the broader sparse-index integration strategy where `git apply` optimizations enable command-specific improvements.
