Performance optimization series (part 5/5) finalizing the batched reference updates implementation with standardized error reporting. This email specifically addresses Junio Hamano's suggestion to simplify the `ref_transaction_error_msg()` helper function by returning string literals (`const char*`) rather than allocated strings.

Karthik Nayak agrees with Junio's proposal, noting that string literals are safe to pass around and that this change would simplify the implementation. The function currently handles 7 distinct error cases (refname conflicts, existence checks, value validation, etc.) with a default "unknown failure" case (which Karthik notes contains a typo "unkown" that will be fixed). 

This change would:
- Eliminate the need for callers to free error messages
- Reduce allocations in error paths
- Maintain identical error message content
- Affect fetch, receive-pack, and update-ref callers
- Preserve all performance improvements from the series
- The implementation will need to adjust strmap cleanup to not free values
- Some const-casting will be required when storing literals in strmap

This follows earlier discussion where Jeff King also supported the string literal approach. The change represents the final polish to the error reporting API in this performance optimization series, which has already addressed memory leaks, error handling unification, and static analysis warnings across fetch, send-pack and receive-pack operations.
