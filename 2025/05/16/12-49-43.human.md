Performance optimization in the sparse index integration series. This is a follow-up to Elijah Newren's review of the test cases for `git apply` with sparse index support. 

Derrick Stolee acknowledges Newren's discovery that the test was incorrectly asserting that `git apply --cached` wouldn't expand the sparse index when in fact it does need to expand for out-of-cone file modifications. The issue stemmed from the test not properly resetting the sparse state after previous operations.

Stolee plans to update the test to include both scenarios: verifying expansion when needed (for `--cached` operations that modify out-of-cone files) while maintaining the non-expansion cases where appropriate. This addresses the edge case Newren identified while preserving the test's original intent to validate sparse index behavior.

The exchange demonstrates the careful review process for this performance optimization work, with reviewers catching subtle test inaccuracies that could mislead future readers. The series remains on track for inclusion with these test improvements.
