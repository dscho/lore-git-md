Refactoring patch in Jeff King's series removing non-standard object type support. This fifth patch in the 13-part series continues simplifying type handling by converting `oid_object_info_convert()` from string-based to enum-based type processing.

The patch removes the `type_name` strbuf from `oid_object_info_convert()` and replaces it with direct enum usage, eliminating string-to-enum conversion and associated memory management. The change builds on earlier patches that removed support for unknown object types, making the string representation unnecessary. Jeff notes the error checking for invalid types was redundant since `oid_object_info_extended()` already validates types before this function is called.

Key technical changes:
- Replaces `struct strbuf type_name` with `enum object_type type`
- Uses `new_oi.typep = &type` instead of string-based approach
- Removes `type_from_string_gently()` conversion and error check
- Simplifies content handling path by assuming valid enum types
- Maintains same behavior for delta base and content conversion

The change affects object-file.c's inter-hash-algorithm conversion logic but doesn't modify external behavior. It's a straightforward cleanup following the series' earlier removal of `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` in patch 3/13. The patch continues the series' pattern of mechanical simplifications enabled by dropping non-standard type support.
