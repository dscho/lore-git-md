This is the final patch in Jeff King's series removing support for non-standard object types, completing the write-side cleanup after earlier patches removed read-side support. The patch removes `write_object_file_literally()` and its helper functions, which had become redundant after `hash-object --literally` stopped supporting unknown types in previous patches. 

The removal eliminates a parallel implementation of `write_object_file()` that had accumulated tricky duplicated code, particularly around loose object map updates. Patrick Steinhardt confirms this solves a problem he was encountering while working on pluggable object databases, where attempts to unify the code paths had proven messy. The patch appears uncontroversial, with Patrick expressing clear approval and no outstanding technical concerns raised in the series.

This concludes the technical implementation of the series' goal to remove non-standard object type support. The only remaining open questions are whether to document a deprecation path (as suggested for patch 2/13) and whether the removal timing needs to wait for Git 3.0 - though Jeff has argued this isn't necessary since the functionality was never properly usable. The series now appears ready for merging pending any final documentation updates.
