This is the fifth patch in Jeff King's series removing support for non-standard object types in Git's core. The patch simplifies the `oid_object_info_convert()` function by switching from string-based to enum-based type handling.

The function converts objects between SHA-1 and SHA-256 formats, and previously used a string buffer to pass around object types. The change eliminates this string handling in favor of direct enum usage, since the function no longer needs to support unknown types. This makes the code both simpler (removing string allocation/cleanup) and more type-safe.

Jeff notes this was likely always safe - the string-to-enum conversion was redundant since invalid types would already have been caught earlier in the call chain. The patch removes 11 lines while adding 4, with the bulk of the changes being removal of string buffer management code.

This continues the series' pattern of mechanical simplifications enabled by dropping support for non-standard types. Like previous patches, it appears straightforward and unlikely to be controversial. The change is focused and well-explained, with the commit message clearly justifying both the change and why the removed error checking wasn't needed.
