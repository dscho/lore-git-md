Refactoring patch in the series removing non-standard object types. This is patch 6/13 in Jeff King's effort to simplify Git's object handling by eliminating support for non-standard object types that were never properly usable beyond test cases.

The patch focuses on `fsck`'s handling of unknown object types, removing its use of the `type_name` strbuf in `object_info` - the last remaining user of this field. Key changes include:

1. Early bailout in `read_loose_object()` when encountering unknown types, before attempting hash verification
2. Removal of the `for_each_loose_cb.obj_type` strbuf and related cleanup code
3. Updated error reporting that now shows two messages (parsing failure + corruption) instead of one combined message
4. Test updates to match the new error output and removal of a now-irrelevant test case

The changes trade slightly more verbose error output (when extremely rare unknown-type objects are encountered) for significant code simplification. The patch continues the series' pattern of methodically removing support for non-standard types while maintaining core functionality. Technical details include updates to `builtin/fsck.c`, `object-file.c`, and `t/t1450-fsck.sh`, with the most notable behavior change being that unknown-type objects will now be reported as corrupt without attempting a hash check.
