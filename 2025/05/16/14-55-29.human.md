Performance optimization for `git reset --patch` with sparse index support.

This is the third patch in a 4-part series integrating sparse index support with interactive commands (`git add -p/-i`, `git checkout -p`, `git reset --patch`). The change follows the same pattern as the earlier `git add -p` optimization - moving the sparse index check earlier in `cmd_reset()` to avoid unnecessary index expansion when using `--patch` mode.

The patch demonstrates a 95.6% speedup for `git reset --patch` when working with a sparse index, similar to the performance gains seen with `git add -p`. The implementation maintains the existing behavior where the index expands when editing files outside the sparse checkout cone, while keeping the index for in-cone edits.

New tests verify both the performance improvement and correct behavior:
- Confirms sparse index isn't expanded unnecessarily for in-cone edits
- Validates index expansion does occur for out-of-cone edits
- Tests integration with other interactive commands like `git checkout -p`
- Maintains compatibility with existing `git reset` functionality

The changes build on Elijah Newren's prior review feedback and follow the sparse-index integration patterns established in earlier parts of the series. With this patch, all major interactive commands (`add`, `checkout`, `reset`) now benefit from sparse index optimizations when used with `-p/--patch` flags.
