This is a performance optimization patch in the path-based delta compression series, introducing threading to the path-walk compression phase in `git pack-objects`. The patch builds on the earlier refactoring in patch 10/13 that separated the path-walk compression into distinct phases.

The key technical change adds a threaded implementation of the path-based delta compression by:
1. Adding a `regions` member to `thread_params` to track path-based work units
2. Creating `threaded_find_deltas_by_path()` worker function that processes path regions
3. Implementing work-stealing logic to balance load between threads
4. Maintaining the existing two-phase compression approach (intra-path then cross-path)

Performance impact is significant, showing:
- 16.7% speedup for big packs in Git repo tests
- 57.7% faster repack operations
- Makes path-walk competitive with name-hash-v2 in runtime while maintaining its space savings
-0.2% to -0.0% size improvements in tested repos (Git, nodejs/node, Linux kernel)
- Particularly benefits repositories with path-similar data (e.g. microsoft/fluentui sees path-walk time drop from 81.29s to 28.16s while maintaining 142.5M pack size)

The implementation reuses the existing thread pool infrastructure from `ll_find_deltas()` but adapts it for path-based work units rather than object batches. The patch includes careful synchronization around progress reporting and work distribution, with each thread processing path regions until work can be stolen from slower peers.

This completes the performance optimization arc of the path-walk feature, addressing the main remaining drawback (single-threaded compression time) while preserving all space savings. The changes are contained to `builtin/pack-objects.c` and maintain compatibility with all existing path-walk features and configurations.
