This is a follow-up discussion about the proposed MPTCP support patch for Git on Linux systems. Brian m. carlson raises several important considerations about the implementation's robustness across different system configurations.

The email focuses on potential edge cases and backward compatibility concerns with the automatic MPTCP detection approach. Key questions include: what happens when binaries compiled on MPTCP-capable systems run on stripped-down kernels without MPTCP, how IPv6-only scenarios would be handled given FreeBSD's IPv4-only MPTCP support, and whether the feature should be configurable rather than automatic.

The author cites real-world concerns from Go 1.24's MPTCP implementation causing problems in some environments, suggesting Git should learn from this experience. They note this primarily affects the unauthenticated Git protocol (port 9418), which sees little use, but argue the users who do use it may be precisely those with unusual configurations that need special handling.

The tone is constructive concern rather than opposition, with clear technical reasoning behind each question. This appears to be valuable feedback that would help harden the patch before merging, particularly around fallback behavior and configuration options. The discussion seems likely to prompt either documentation improvements or implementation changes to address these edge cases.
