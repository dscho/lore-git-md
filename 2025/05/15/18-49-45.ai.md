Git-gui bugfix addressing trailing newline issue in commit messages. This is a follow-up refinement to the previously discussed solution that replaces multiple regex substitutions with a single `string trim` operation in `lib/commit.tcl`.

The patch now incorporates Oswald Buddenhagen's review feedback, updating the comment to clarify that `puts` will re-add a trailing newline and using the more precise phrasing "did not consider" rather than "forgot". The technical approach remains unchanged - using Tcl's `string trim` to handle both leading and trailing newlines while maintaining the existing behavior of compressing multiple internal newlines down to two.

Key implementation details: the solution removes 4 lines of regex substitutions while adding 2 lines with the `string trim` operation and updated comment. The patch maintains the edge case handling for completely empty commit messages that triggers an error popup. All participants in the thread (Gareth Fenn, Johannes Sixt, Oswald Buddenhagen) have agreed on this solution, with Junio C Hamano having previously validated the approach.

The change is localized to git-gui's commit message processing logic and doesn't affect other subsystems. The historical context about previous attempts using `git stripspace` (and its compatibility issues) remains relevant background but doesn't impact this specific solution. The patch is ready for inclusion with no outstanding technical concerns.
