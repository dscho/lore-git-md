This is a naming debate continuation in the `git-blame-tree` RFC thread. Marc Branchaud responds to Junio Hamano's argument that line-by-line blame and tree modification tracking serve different user mental models, while Patrick Steinhardt sees them as technically similar operations.

Marc offers a compromise position - he acknowledges both perspectives are valid but suggests that if the operation isn't considered a "blame" variant, then the name should reflect that distinction. He proposes "last-touch" as an alternative name that better captures the directory modification tracking semantics without implying line-by-line attribution.

The email highlights the core tension in the naming debate: whether to emphasize the technical implementation similarities (both track object modifications) or the different user intents (who changed this code vs. when was this file last modified). Marc's "last-touch" suggestion attempts to bridge this gap with a name that's both technically descriptive and matches the user's query about modification timing.

This continues the thread's unresolved naming question while showing willingness to move away from "blame" terminology if that better serves user expectations. The discussion remains focused on conceptual clarity rather than implementation details.
