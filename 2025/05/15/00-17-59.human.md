This is a response in the ongoing discussion about adding a `commit.signoff` configuration option, which would make the `--signoff` behavior persistent for commits.

Junio Hamano pushes back against the argument that the precedent of `format.signoff` justifies adding this new config option. While acknowledging that `format.signoff` was added in 2009 despite earlier objections, he argues that past decisions shouldn't automatically validate similar new additions - "an old mistake is never an excuse that we can pile more mistakes of the same kind on top."

The comment suggests the maintainer may have concerns about the principle of adding this configuration, though it doesn't directly address the technical implementation. This appears to reopen the discussion that had seemed settled after Chris Down's earlier response addressing historical concerns. The thread now seems to be moving from technical implementation details back to the philosophical question of whether such signoff configuration options should exist at all.
