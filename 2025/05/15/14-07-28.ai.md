Performance optimization patch completing a series that introduces batched reference updates to `git-receive-pack`. This is the fourth and final patch in v2 of the series, building on the batched update infrastructure introduced in commit 23fc8e4f61.

The patch modifies `receive-pack` to use batched reference updates via a single transaction with failure tolerance, replacing the previous one-ref-per-transaction approach. Key technical changes include:
- Introduces a `ref_transaction_rejection_handler` callback using `struct strset` to track failed refs
- Moves error handling to after transaction commit while maintaining accurate error attribution
- Fixes a confusing edge case where duplicate ref updates would produce misleading status messages
- Changes hook behavior so `reference-transaction` now operates all-or-nothing with batched updates

Performance benchmarks show significant improvements: 18x faster for reftable backend (235ms vs 4.3s for 10k refs) and 1.21x for files backend. The patch also resolves test inconsistencies in t5408 and t1416 that were affected by the behavioral changes.

The implementation addresses feedback from Patrick Steinhardt and Junio C Hamano by:
- Properly initializing the `reported_error` string pointer
- Using the new `ref_transaction_error_msg()` helper from patch 5/4
- Maintaining clear error reporting while gaining performance benefits

This completes the series' goal of error handling unification while delivering the promised performance gains, particularly for reftable users. The changes touch core reference transaction handling in `builtin/receive-pack.c` with corresponding test updates.
