This is a user-facing documentation improvement patch targeting the sequencer's interactive rebase interface. The change aims to clarify that commit descriptions in the rebase todo list are merely comments and not directives that affect the rebase operation.

The patch prepends a '#' character to commit messages in the todo list to visually distinguish them from actual rebase commands. This addresses user confusion where edits to these descriptions were mistakenly thought to affect the rebase outcome. The author justifies hardcoding '#' rather than using comment_line_str by explaining that (1) no disambiguation is needed here, (2) the exact character doesn't matter functionally, (3) merge directives already hardcode '#', and (4) making it configurable would work against the goal of discouraging edits.

The change affects sequencer.c to modify the output format and updates several test files (t3404, t3415, t3430, t5520, t7512) to match the new output format. The author notes this is intentionally not using comment_line_str since the goal is specifically to discourage editing these lines, unlike other cases where comment_line_str enables flexible editing.

Key technical points for future reference:
- Changes rebase todo list output to prefix commit messages with '#'
- Affects both regular pick lines and merge directives
- Updates multiple test suites to expect the new format
- Justifies not using comment_line_str configuration
- References existing hardcoded '#' usage in merge directive handling
