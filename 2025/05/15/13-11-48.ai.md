This is a bugfix patch addressing potential undefined behavior in the bundle-uri subsystem, part of a larger series addressing CodeQL static analysis findings.

The patch modifies `bundle-uri.c` to properly handle the case where `sscanf()` fails to parse the `fetch.bundlecreationtoken` config value. The original code assumed `sscanf()` would leave the output variable unchanged on failure, but POSIX makes no such guarantee. The fix ensures `maxCreationToken` is always initialized (to 0 if parsing fails) before being used in the comparison with `bundles.items[0]->creationToken`.

This change follows the series' pattern of making memory safety properties more explicit while maintaining identical behavior. The modification is small (7 lines added, 5 removed) but important for correctness, as it prevents potential use of an uninitialized value. The commit message clearly cites both the original commit (c429bed102) and the relevant POSIX documentation to justify the change.

The patch maintains the existing logic flow while making it more robust - if parsing fails, it treats it as if the token was 0 (the most conservative value for the comparison).
