This is a performance optimization series (v2) that introduces batched reference updates to `git-fetch` and `git-receive-pack`, building on the batched reference update support added in commit 23fc8e4f61. The series shows significant speedups, particularly for the reftable backend (22x faster for fetch, 18x for receive-pack).

The cover letter explains the motivation: current per-reference transactions are slow, especially for repositories with many refs, and batched updates provide a middle ground between all-or-nothing transactions and individual updates. The series includes 4 patches:

1. Adds a helper to translate ref transaction errors to human-readable strings
2. Modifies `git-fetch` to use batched updates (with a noted TODO about handling pruning/creation conflicts)
3. Fixes a memory leak in `git-send-pack` when handling duplicate refs
4. Updates `git-receive-pack` to use batched updates with improved error handling

The author suggests targeting this for Git 2.51 to allow more bake time, as any bugs here would be high-impact. Review feedback from Patrick Steinhardt and Junio Hamano has been incorporated, including better error reporting and documentation of known limitations. The changes touch core ref handling code and require updates to several test scripts.

Performance numbers show the improvements are substantial, making this an important optimization, especially for reftable users. The implementation appears thorough, with clear commit messages and addressed review feedback, though some edge cases around error handling and conflict resolution remain as noted TODOs.
