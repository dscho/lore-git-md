This is a memory safety patch in the ongoing CodeQL static analysis series, specifically addressing potential use of stale stack addresses in the commit-graph writing code. The change modifies `commit-graph.c` to explicitly null out the `topo_levels` pointer in the commit graph structure after writing completes, ensuring no code can accidentally access the now-invalid stack-allocated `topo_levels` variable that was used during the write operation.

The patch adds a cleanup block that walks the commit graph chain (including base graphs) to clear all `topo_levels` pointers. This makes the code's behavior more obviously correct by preventing any possibility of dangling references to the now-defunct stack variable. The change follows the series' pattern of making memory safety properties more visible to both static analyzers and human readers, though the commit message notes the actual risk was unclear ("hard to reason about") rather than demonstrating a concrete bug.

This is the second instance in the series addressing stack address safety (following a similar change in `fetch.c`), showing a consistent approach to eliminating this class of potential issues. The modification is localized to commit-graph writing internals and doesn't affect user-visible behavior.
