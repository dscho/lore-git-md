This is a bugfix patch addressing a memory leak in `git send-pack` when handling duplicate reference updates, part of a performance optimization effort to use batched reference updates.

Karthik Nayak fixes a memory leak that occurs when pushing duplicate refspecs (like `A:foo B:foo`) where the remote status messages would overwrite each other without freeing the previous message. The patch adds a `free()` call before overwriting `remote_status` in `struct ref`.

Junio C Hamano raises an interesting design question about edge cases where one update succeeds and another fails - should we keep the first error, last error, or most severe error? Karthik responds that the whole duplicate refspec situation is problematic and will be addressed more fundamentally in the next patch, which will fail all updates when duplicates are detected. He demonstrates how the current behavior can misleadingly report both updates as failed even when one succeeds.

The patch is straightforward and correct, but the discussion reveals deeper issues with how duplicate refspecs are handled that will be tackled in the series' next installment. This fix is a necessary stepping stone toward that more comprehensive solution.
