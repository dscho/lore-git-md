Feature proposal for `git diff --no-index` to support pathspec filtering. This RFC patch from Jacob Keller adds pathspec support to `git diff --no-index` when comparing directories, allowing users to limit which files are compared using the same pathspec syntax available in repository-based diffs. The implementation handles both paths being directories by creating separate pathspec objects for each input path, with new flags (PATHSPEC_NO_REPOSITORY) and functions (match_leading_pathspec) to support repository-less operation.

Key technical aspects:
- Only activates pathspec processing when both inputs are directories
- Adds PATHSPEC_NO_REPOSITORY flag to disable repository-specific checks
- Implements match_leading_pathspec() to handle directory recursion cases
- Modifies prefix_path_gently() to properly handle non-/ terminated prefixes
- Disables PATHSPEC_ATTR and PATHSPEC_FROMTOP features which require a repo
- Pathspecs must come after the two directory arguments and are relative to each directory root

The author notes several limitations and open questions around negative pathspec behavior, argument ordering requirements, and whether the dual-pathspec approach is optimal. The patch touches core pathspec handling in pathspec.[ch], directory traversal in dir.c, and the diff-no-index implementation, with changes to setup.c for path prefix handling. No tests are included yet in this RFC version.
