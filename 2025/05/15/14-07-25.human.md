Performance optimization series (part 1/4) introducing standardized error reporting for ref transactions. This patch extracts error message generation from `builtin/update-ref.c` into a new `ref_transaction_error_msg()` helper function in `refs.c`, making it available to all ref transaction users. The change is part of a larger series optimizing reference updates in fetch/receive operations, where consistent error handling was requested by reviewers.

The patch cleanly moves the existing error message mapping logic with minimal changes, just adding proper memory management (the new function returns an allocated string that callers must free). It handles all existing ref transaction error cases including name conflicts, existence checks, and value validation.

This appears to be a straightforward refactoring with no behavior change, addressing a specific piece of feedback from the ongoing batched reference updates discussion. The implementation looks solid, though reviewers may want to verify the memory management pattern matches Git's conventions. As the first patch in a performance-focused series, it sets up infrastructure needed by later optimizations rather than delivering speedups itself.
