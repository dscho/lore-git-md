This is the fourth and final patch in a performance optimization series introducing batched reference updates. It modifies `git-receive-pack` to use batched updates rather than processing references one at a time, completing the series' goal of improving performance for fetch and receive operations.

The patch shows impressive benchmark results - an 18x speedup for the reftable backend and 1.21x for the files backend when handling 10,000 references. The implementation uses a new `ref_transaction_rejection_handler` callback with a `struct strset` to properly track failed references after batched updates.

An interesting side effect is that batched transactions now properly handle (and reject) cases where clients try to push multiple updates to the same reference, fixing what was previously misleading error reporting. The patch also clarifies behavior around reference-transaction hooks, which now operate in an all-or-nothing fashion with batched updates.

The changes required updates to tests in t5408 and t1416 to account for the new behavior. Karthik Nayak notes this actually fixes what was arguably buggy behavior in the old implementation. Patrick Steinhardt provided helpful feedback during development.

This completes the series' technical work after addressing review feedback about error handling consistency. The performance improvements are substantial, particularly for repositories using the reftable backend. While some architectural questions remain open (noted in earlier patches), this appears ready to merge pending any last-minute review comments.
