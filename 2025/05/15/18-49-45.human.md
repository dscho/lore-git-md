Bugfix for git-gui's commit message formatting, addressing a reported issue where messages ended with two newlines instead of one. This was caused by an interaction between the Tk text widget (which ensures one trailing newline) and Tcl's `puts` command (which adds another). Johannes Sixt's patch simplifies the code by replacing three regex substitutions with a single `string trim` operation that handles both leading and trailing newlines while maintaining the existing behavior of compressing multiple internal newlines down to two.

The solution has been reviewed by Oswald Buddenhagen, who suggested minor comment improvements and noted this prevents newline creation rather than stripping existing ones. The patch maintains compatibility with existing behavior while being more concise (2 lines added vs 4 removed). This follows previous attempts to use `git stripspace` that were reverted due to compatibility issues, with the current approach being validated as the correct solution given current constraints.

All technical concerns appear resolved, with the patch ready for inclusion. The change is localized to `lib/commit.tcl` and improves both correctness and code simplicity.
