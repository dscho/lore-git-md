Bugfix for a memory leak in `git-send-pack` when handling duplicate reference updates, part of the performance optimization series introducing batched reference updates. This patch addresses a specific issue where duplicate refspec inputs (like `A:foo B:foo`) would cause a memory leak when overwriting error messages in `ref->remote_status` without freeing the previous value. Karthik Nayak provides the straightforward fix by adding a `free()` call before overwriting.

The discussion reveals deeper concerns about the behavior when one duplicate update succeeds and another fails. While the current implementation uses a "last-one-wins" approach for error messages, Junio C Hamano questions whether this is the best semantic, suggesting alternatives like keeping the first error or the most severe one. Karthik indicates this edge case will be properly handled in the next patch of the series, which will make duplicate refspecs fail all updates deterministically.

The current behavior produces misleading output when one update succeeds and another fails, as both are reported as failures to the user despite the ref actually being updated once. This highlights the need for the more comprehensive solution coming in the next patch. The fix itself is simple and correct, but the discussion surfaces important questions about edge case handling that will be addressed in the broader context of the batched reference updates series.
