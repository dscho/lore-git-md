This is a follow-up in the ongoing discussion about the proposed `git-blame-tree` command, focusing on naming and conceptual alignment with `git blame`. Marc Branchaud responds to Junio Hamano and Patrick Steinhardt's debate about whether tree attribution shares enough semantics with line blame to justify the "blame" terminology.

Marc takes a middle position, acknowledging both perspectives: while he sees Patrick's point about the output format similarity (commit IDs prefixing lines of output), he also understands Junio's view that users may perceive file history differently from line history. He suggests "last-touch" as an alternative name that avoids the "blame" connotation while still describing the operation's purpose.

The email reinforces the core naming debate that's blocking progress on this feature - whether to position it as a variant of blame (emphasizing technical implementation similarities) or as a distinct operation (emphasizing user mental models). Marc's proposal of "last-touch" attempts to bridge this gap with neutral terminology, though it doesn't resolve the underlying architectural question of whether to integrate with `git blame` or keep a separate command.

This continues the thread's pattern where technical implementation is largely settled but naming and command structure remain contentious, with contributors divided between integration advocates (Marc), separate-command proponents (Toon Claes), and those emphasizing user experience constraints (Junio Hamano). The "last-touch" suggestion represents another naming option in a discussion that has already seen several proposals ("ascribe-tree" being retracted earlier due to accessibility concerns).
