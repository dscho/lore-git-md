Performance optimization patch modifying `git-fetch` to use batched reference updates. This is part of a series introducing batched updates to improve performance in fetch and receive operations (v2, patch 2/4).

The patch replaces `git-fetch`'s per-reference transactions with the new batched update mechanism from commit 23fc8e4f61. This provides significant performance improvements: 22x faster for reftable backends and 1.25x for files backends when handling 10,000 refs. The implementation maintains the ability for individual updates to fail while using a single transaction under the hood.

Key changes include:
- Removing custom error handling in favor of standardized ref-transaction errors
- Adding a rejection handler to maintain error reporting behavior
- Cleaning up now-unnecessary transaction management code
- Documenting remaining limitations around file/directory conflicts

The patch appears well-constructed with thorough benchmarking and maintains existing behavior while improving performance. It builds on previous discussion about handling edge cases, though some architectural questions about conflict resolution remain open for future work. This is a clear win for performance with no apparent downsides.
