This is a follow-up in the ongoing bugfix thread addressing memory leaks in pack-bitmap.c's bitmap loading paths. Lidong Yan responds to Jeff King's observation about the difficulty of testing the leak scenarios by volunteering to attempt creating test cases.

The thread has already established consensus on the technical solution - Taylor Blau's patch that removes redundant cleanup paths in favor of centralized `free_bitmap_index()` handling. Now the discussion shifts to test coverage. Lidong proposes to craft corrupted bitmap files that would trigger the error paths where leaks were previously possible (validation failures and partial loads). This would allow LSan to verify the fixes work as intended.

The challenge lies in creating bitmap files with specific corruption patterns that fail at the right points in the loading process. While Jeff King expressed doubts about whether this effort would be worthwhile, Lidong appears willing to explore it. This would be a valuable addition if successful, as the thread has focused on robust error handling in performance-critical bitmap code. The test cases would help prevent regression of these leak scenarios.
