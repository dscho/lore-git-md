Performance optimization patch modifying `git-fetch` to use batched reference updates, part 2/4 in a series. This builds on the batched reference transaction infrastructure introduced in commit 23fc8e4f61 to significantly improve fetch performance, particularly for repositories with many refs.

The patch replaces `git-fetch`'s per-reference transaction model with batched updates while maintaining the ability for individual updates to fail independently. Key technical changes include:
- Removing custom error codes (`STORE_REF_ERROR_OTHER` and `STORE_REF_ERROR_DF_CONFLICT`) in favor of the standardized ref transaction error types
- Introducing a `ref_transaction_rejection_handler` callback to process failed updates after transaction commit
- Maintaining the same error messages and behavior for D/F conflicts, just with different timing
- Cleaning up now-unnecessary transaction management code

Performance benchmarks show dramatic improvements: 22x faster for reftable backend (154ms vs 3.4s for 10k refs) and 1.25x for files backend. The implementation handles both atomic and non-atomic fetch modes, with a TODO noting future potential to resolve F/D conflicts within a single transaction if the ref-transaction layer gains that capability.

This patch follows through on the series' goal of unifying error handling while preserving performance gains from v1. It touches core fetch functionality in `builtin/fetch.c`, removing about 50 lines while adding more structured error processing. The changes align with Junio Hamano's earlier feedback about standardizing error reporting, though his request for clearer batch/non-batch distinction in the transaction code remains open.
