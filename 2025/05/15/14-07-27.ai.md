This is a bugfix patch in the performance optimization series for batched reference updates, specifically addressing a memory leak in `git-send-pack`.

The patch fixes a memory leak that occurs when pushing duplicate references that fail to update. Currently, if a user pushes the same reference multiple times (e.g., `git send-pack remote.git A:foo B:foo`) and the updates fail, the error messages overwrite each other without freeing the previous message. The fix adds proper cleanup before overwriting the `remote_status` field.

Key technical details:
- Modifies `send-pack.c` to free the previous `remote_status` before overwriting it
- Adds a new test case in `t5408-send-pack-stdin.sh` that specifically triggers this leak scenario with multiple duplicate refs
- Maintains the existing behavior where the last error message is preserved (now just does so cleanly)
- Part of the larger batched reference updates series but addresses a standalone issue

The patch is straightforward and well-contained, adding both the fix and a test case to verify it. It follows the pattern established in the series of cleaning up edge cases while maintaining the performance improvements. The change is minimal and focused, with no apparent impact on the broader batched reference update functionality.
