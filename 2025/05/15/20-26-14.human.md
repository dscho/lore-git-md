Bugfix and API improvement in the batched reference updates series. Junio C Hamano questions why the new `ref_transaction_error_msg()` helper duplicates string literals when returning error messages, suggesting it could simply return the literals directly as `const char*` rather than allocating copies. This comes in the fifth patch of the performance optimization series that standardizes error reporting across fetch, receive-pack, and update-ref.

The current implementation in Karthik Nayak's patch uses `xstrdup()` to return allocated strings, requiring callers like `update-ref.c` to free the result. Junio points out this is unnecessary since the messages are static strings, and eliminating the allocations would simplify memory management without changing functionality. This follows earlier refinements by Jeff King to the error handling approach in this series.

The observation doesn't affect the core performance improvements (which show 18-22x speedups for reftable operations), but would clean up the API surface. The thread history shows this is part of ongoing polish for a high-impact change that's nearing readiness, with previous rounds having addressed memory leaks, error handling unification, and static analysis warnings.
