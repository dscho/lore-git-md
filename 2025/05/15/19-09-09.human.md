This is a performance optimization follow-up in the batched reference updates series. Jeff King (peff) identifies a memory management issue in the error handling path of `git-receive-pack` when processing batched reference updates. The current implementation duplicates error strings unnecessarily, creating potential memory leaks since the strings are sometimes allocated and sometimes not.

The proposed solution changes `ref_transaction_error_msg()` to return string literals rather than allocated strings, avoiding the need for callers to free them. This requires adjusting the strmap handling in receive-pack to work with const strings and updating several callers (fetch.c, update-ref.c) to stop freeing the returned strings. The change simplifies memory management while maintaining the same error reporting behavior.

This appears to be a clean optimization that builds on the series' earlier work standardizing error reporting. It doesn't affect the core batched update functionality or performance improvements, but rather cleans up an implementation detail in the error path. The change is well-motivated and the patch looks straightforward, though as Jeff notes, it's surprising the existing code didn't trigger leak detection.
