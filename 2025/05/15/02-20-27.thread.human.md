This thread discusses a proposed change to make it clearer that commit descriptions in interactive rebase todo lists are comments rather than editable directives. The original patch (likely from Elijah Newren) adds '#' prefixes to these lines to prevent users from mistakenly editing them, as some were confusing these comments with editable parts of the rebase instructions.

Reto raised concerns that syntax highlighting in editors might make these prefixed messages harder to read during rebase navigation. Phillip Wood has strongly defended the approach, pointing out that Git already uses '#' consistently in similar contexts (merge command lines and empty commit markers) and arguing that editors should properly handle lines starting with '#' as comments. He maintains that editor behavior shouldn't dictate Git's output format.

The discussion has evolved into a broader question about whether Git should adapt to current editor behaviors or expect editors to correctly interpret its standard output. While the original goal was to reduce user errors, the readability concerns remain unresolved. Phillip's technical arguments about existing Git behavior and proper editor handling have shifted the focus, but there's no clear consensus yet on how to balance these competing priorities. The patch currently uses a hardcoded '#' rather than the configurable comment_line_str, affecting several test files that verify rebase behavior.
