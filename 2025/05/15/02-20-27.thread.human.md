This thread discusses a documentation and UX improvement to make it clearer that commit descriptions in interactive rebase todo lists are comments rather than directives that affect the rebase operation. The original patch from Elijah Newren proposed prefixing these messages with '#' to visually distinguish them, similar to Git's existing use of '#' in merge command lines and other contexts.

Reto initially raised concerns that syntax highlighting might make these prefixed messages harder to read during rebase navigation. However, Phillip Wood has now weighed in strongly in favor of the change, calling it "a very good idea" and confirming the technical implementation looks correct. He provided a minor test improvement suggestion (using a cleaner `sed` command in t5520-pull.sh) and reinforced that the approach aligns with Git's existing output patterns. Phillip's position is that editor implementations should adapt to Git's conventions rather than the other way around.

The discussion has largely converged on accepting the change, with Phillip's maintainer perspective carrying significant weight. The remaining open question is whether any additional documentation or guidance might help users understand the new format, though the consensus seems to be that the visual distinction provided by the '#' prefix will sufficiently prevent the original confusion that motivated the patch.
