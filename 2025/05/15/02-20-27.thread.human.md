This thread addresses a user experience improvement for Git's interactive rebase functionality. The core change makes it visually obvious that commit descriptions in rebase todo lists are comments rather than commands, by prefixing them with '#'. This prevents users from mistakenly editing these descriptions when modifying their todo lists.

The discussion began with Elijah Newren proposing the change, which received initial pushback from Reto about readability impact but strong support from Phillip Wood and maintainer Junio Hamano. The technical approach - modifying sequencer.c to output commit descriptions as comments - was quickly validated. The remaining discussion focused on test refinements in t5520, with various patterns proposed for filtering commented lines in test comparisons.

In the latest update, Elijah confirms he's implementing the minimal test change - switching from `grep -v -e \#` to `grep -v -e ^\#` in his GitHub PR #1923. This aligns with Junio's earlier suggestions while keeping the diff small. The thread appears to be wrapping up, with all technical aspects approved and only this final test implementation detail being settled.
