This is a refactoring patch in the ongoing CodeQL static analysis series, specifically addressing memory safety in the commit-graph writing code. The change converts a heap-allocated `write_commit_graph_context` struct to stack allocation, eliminating a malloc/free cycle for a structure that only exists within the function's scope.

The patch moves initialization of the context struct to the function's declaration point, with Jeff King noting this changes the timing of `get_configured_generation_version()` call. While technically correct, he flags this as a potential maintenance hazard if that function's implementation changes to depend on repo settings initialized later. He suggests an alternative approach using memset() and direct field assignment that would preserve the original initialization timing.

Key technical details:
- Affects `commit-graph.c`'s `write_commit_graph()` function
- Changes allocation strategy for the `write_commit_graph_context` struct
- Preserves all existing struct fields and their values
- Subtly alters when `get_configured_generation_version()` is called
- Maintains identical runtime characteristics

This continues the series' theme of making memory safety properties more robust while maintaining behavior. The discussion highlights how even simple allocation changes can have subtle implications for initialization order and future maintenance.
