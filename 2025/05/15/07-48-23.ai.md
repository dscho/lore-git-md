This is a CI/build system follow-up discussing TAP protocol integration in Meson. Karthik Nayak confirms the core functionality of enabling TAP parsing in Meson 1.8+ works correctly for normal test runs, showing proper subtest counting as demonstrated in Patrick Steinhardt's original patch. However, Nayak identifies an inconsistency when using the `--interactive` flag with Meson 1.8.99, where tests that pass in normal mode show as "IGNORED" rather than "OK" in interactive mode. The test output itself (47 passing subtests) appears correct, but the final status classification differs between modes.

The issue appears specific to interactive test execution and doesn't affect the core TAP parsing capability, which works as intended for regular test invocations. Nayak notes the behavior differs from master branch, suggesting it may be related to the series' changes rather than a pre-existing condition. The observation comes while testing Steinhardt's patch series that introduced TAP protocol support via a `protocol: 'tap'` addition to `test_kwargs` in meson.build when Meson >=1.8.0 is detected.

This follow-up highlights a remaining edge case in interactive test execution that wasn't caught by the initial implementation or review. The thread had previously established consensus on the technical approach to TAP output handling, with this being the first reported issue with the actual usage of the feature. The discrepancy between interactive and non-interactive modes warrants investigation, though it doesn't invalidate the series' core functionality.
