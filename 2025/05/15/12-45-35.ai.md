Defensive programming patch for `git describe` error handling. This is the 10th patch in a 14-part series adding systematic error checking across Git's codebase based on static analyzer findings.

The change modifies `builtin/describe.c` to add a NULL check after `lookup_commit_reference()`, which CodeQL flagged as potentially returning NULL. When this occurs, the code now dies with an error message showing the problematic commit hash rather than risking a NULL dereference when accessing `cmit->object.oid.

This follows the series' established pattern of hardening specific subsystems - in this case the describe command's commit lookup path. The change is minimal (just 2 lines added) and maintains the existing behavior while adding safety for theoretical edge cases. Like previous patches in the series, it addresses a static analyzer warning without introducing functional changes for normal operation.
