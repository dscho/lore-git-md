This is a bugfix patch in a performance optimization series about batched reference updates. It addresses a memory leak in `git-send-pack` when handling duplicate reference updates.

The patch fixes a case where pushing the same reference multiple times (like `A:foo B:foo`) could leak memory when updates fail. Currently, if multiple updates to the same reference fail, the error messages overwrite each other without freeing the previous message. The fix adds proper cleanup before overwriting the error message.

The patch includes a new test case that specifically triggers this scenario with multiple duplicate references. This complements existing tests that didn't catch the leak because they only had one failing update per reference. The change is straightforward - just freeing the old message before storing a new one - and fits into the larger series' goal of improving reference update performance and reliability.
