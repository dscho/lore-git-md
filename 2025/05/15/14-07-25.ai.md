This is a refactoring patch that standardizes error message handling in the ref transaction system, part of a larger performance optimization series for batched reference updates.

The patch introduces a new helper function `ref_transaction_error_msg()` in refs.c that centralizes the translation of ref transaction error codes to human-readable strings. This addresses previous feedback about inconsistent error reporting across commands. The function handles all enum values from `REF_TRANSACTION_ERROR_* with appropriate string messages, including cases like name conflicts, incorrect old values, and invalid new references.

The implementation moves existing error message logic from `builtin/update-ref.c` into this new shared function, cleaning up the update-ref code while maintaining identical behavior. The function returns a newly allocated string that callers must free, as shown in the updated `print_rejected_refs()` function which now uses this helper.

This change is part of the broader review feedback requesting unified error handling across the reference transaction system. The patch appears well-contained, with clean diffs that show the straightforward movement of code from a command-specific location to a shared library function. The implementation maintains all existing error cases while making them available to other parts of the codebase that need to report transaction failures.

Key technical details:
- New public API function `ref_transaction_error_msg()` in refs.h
- Handles all 7 defined ref transaction error types plus a catch-all
- Returns allocated string that must be freed by caller
- First consumer is `builtin/update-ref.c`'s rejection printing
- Part of addressing Junio Hamano and Patrick Steinhardt's feedback about error handling consistency

The patch appears ready with no obvious issues, completing one of the requested improvements in the batched reference updates series. It doesn't introduce new functionality but provides better infrastructure for error reporting that will be used by subsequent patches in the series.
