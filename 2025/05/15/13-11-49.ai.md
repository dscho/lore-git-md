Refactoring patch in the CodeQL static analysis series, focusing on sequencer.c's control flow clarity.

This is the final patch in a 16-part series addressing CodeQL findings, specifically targeting the sequencer subsystem's `is_command()` function. The change transforms a confusing return statement that mixed conditions with pointer assignment into a clearer if-block structure. The original code from 2019 combined three checks with `&&`, where the last "condition" was actually assigning to `*bol` while still being evaluated as part of the logical expression. 

The new version separates the assignment from the conditional logic, making it more obvious that we're both modifying state and returning a value. While functionally identical, this makes the code more readable and avoids triggering static analyzer warnings about assignments in conditional contexts. The change affects how Git parses todo commands during interactive rebases, though the actual behavior remains unchanged.

This follows the series' pattern of small, focused improvements that enhance code clarity and static analysis friendliness without altering functionality. The patch is straightforward and unlikely to be controversial, though reviewers may want to verify that the control flow transformation doesn't introduce any subtle edge cases in command parsing.
