This is a CI/build system discussion confirming resolution of the final open question in Patrick Steinhardt's Meson TAP output parsing patch series. The exchange clarifies the expected behavior of interactive test mode (`--interactive`) versus verbose mode (`-v`) when using Meson's TAP protocol support.

Karthik Nayak had observed that interactive mode showed tests as "Ignored" rather than "OK" and questioned if this was correct. Steinhardt explains this is intentional due to two technical constraints: 1) direct console connection prevents Meson from parsing the output stream, and 2) user interaction during tests (like with `test_pause`) would break TAP format compliance. The proper workflow for those wanting test output visibility without interaction is to use `meson test -v` instead.

This confirmation resolves the last identified question about the series' behavior, with Nayak indicating approval of the approach. The discussion reinforces that the interactive mode limitations are inherent to the nature of TAP parsing rather than an implementation flaw, and that the series' core functionality for non-interactive test runs works as designed.
