Platform compatibility fix for NetBSD's errno behavior with O_NOFOLLOW.

This patch addresses a test failure on NetBSD where the system's `open()` with `O_NOFOLLOW` returns `EFTYPE` for symlinks instead of the POSIX-standard `ELOOP`. The discrepancy was exposed by test t0602-reffiles-fsck.sh, which checks packed-refs filetype validation. The failure appeared after commit cfea2f2da8 added stricter filetype checking.

The solution adds NetBSD-specific handling in `open_nofollow()` to translate `EFTYPE` to `ELOOP` when opening fails on a symlink. The patch includes a comment explaining the rationale and noting that this avoids an extra `lstat()` call since NetBSD's `EFTYPE` only occurs in this specific circumstances. The change is localized to wrapper.c and only affects NetBSD builds.

The patch appears well-targeted and correctly handles the platform quirk while maintaining the expected behavior. The commit message clearly explains both the problem and solution, including the specific test case that failed. The implementation choice to special-case NetBSD rather than add a more general solution seems reasonable given the narrow scope of the issue.
