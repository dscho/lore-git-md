This thread began as a discussion about handling platform-specific errno values (NetBSD's EFTYPE and FreeBSD's EMLINK) when checking for symlinks in packed-refs operations. The group reached consensus on Jeff King's proposal to use lstat() for portable symlink detection, with Collin Funk preparing a patch to handle the BSD errno cases with proper style compliance.

The conversation then naturally progressed to optimizing packed-refs file handling, particularly for large repositories. Shejialuo is working on an mmap-based implementation after GitLab.com metrics showed that while 99% of packed-refs files are under 50MB, there are rare 2GB outliers that could benefit from more efficient handling.

In the latest development, Junio Hamano has raised broader questions about atomicity guarantees in filesystem operations. While agreeing that fsck doesn't need the atomicity provided by open_nofollow(), he's questioning whether Git should be more explicit about where atomic operations are truly required versus where they're merely convenient. This touches on deeper design questions about how Git should abstract platform differences - whether to treat certain behaviors as mandatory requirements or implementation details that can have fallbacks.

The thread now spans three connected but distinct technical areas: BSD errno handling (nearing resolution), packed-refs performance optimization (in progress), and platform abstraction design philosophy (newly opened). Key participants include Jeff King (who proposed both the lstat solution and mmap optimization), Collin Funk (handling BSD errnos), shejialuo (implementing mmap), and Junio Hamano (raising the atomicity design questions). Patrick Steinhardt and brian m. carlson have also contributed important perspectives and data points along the way.
