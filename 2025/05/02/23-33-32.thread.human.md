This thread began as a platform compatibility discussion about handling BSD variants' errno behavior when checking packed-refs files, particularly around symlink operations. The core issue - differing errno values (EFTYPE on NetBSD, EMLINK on FreeBSD) for symlink operations - was resolved with Jeff King's lstat()-based approach in packed-backend.c, while maintaining BSD-specific errno translation for completeness.

The discussion has now shifted to performance optimization after observations during the BSD work revealed that the current implementation reads entire packed-refs files into memory. While most repositories have small packed-refs files (under 5MB, with 99% under 50MB according to GitLab.com metrics), outliers like GitLab's 2GB case exist. Jeff King and Patrick Steinhardt noted that using mmap would be more efficient, avoiding memory copying and enabling process sharing.

Shejialuo has confirmed understanding of these performance considerations and plans to submit a patch converting the packed-refs reading to use mmap. This optimization builds naturally on the platform compatibility work and follows established Git patterns for handling large files. Given the uncontroversial nature of the change and clear real-world motivation from repository scaling data, this appears to be a logical next step for the thread.
