This thread began as a discussion about platform compatibility issues in `git fsck` when checking packed-refs files, specifically how different BSD variants handle errno values for symlink operations. The core problem was whether to handle BSD-specific errno codes (like NetBSD's EFTYPE and FreeBSD's EMLINK) through platform-specific translation or to restructure the code to avoid the issue entirely by using lstat() for symlink detection.

After initial patches from Collin Funk to handle BSD errno translation, Jeff King proposed a more portable lstat()-based solution that gained consensus, making the BSD-specific approach obsolete. While brian m. carlson later approved the BSD translation method, he acknowledged the technical direction had already moved to Jeff's solution.

The discussion has since shifted to performance considerations for very large packed-refs files, particularly relevant for massive repositories like GitHub's fork networks where these files can reach 1.5GB. Jeff King notes that while the current strbuf-based approach works, mmap could offer better performance for these extreme cases, though it would require careful implementation to handle platform-specific behaviors like Windows file locking. This remains a secondary discussion point, as the main thread resolution about symlink detection has already been settled in favor of the lstat() solution.
