Collin Funk's original patch addressed NetBSD's use of EFTYPE instead of the POSIX-standard ELOOP, fixing test failures in t0602-reffiles-fsck.sh that appeared after stricter filetype checking was added for packed-refs.

Brian m. carlson has confirmed the NetBSD fix works correctly but points out FreeBSD has a similar issue, returning EMLINK instead of ELOOP. This reveals a broader pattern of BSD systems not fully complying with POSIX standards for this operation, even when _POSIX_SOURCE is defined - a point carlson finds particularly frustrating.

While the NetBSD solution (translating EFTYPE to ELOOP in wrapper.c's open_nofollow()) has consensus, the thread now recognizes this may need to expand into a more comprehensive BSD compatibility effort. The technical focus remains on proper errno handling for symlink operations across different platforms, with the current discussion suggesting FreeBSD will need similar treatment in a follow-up patch.
