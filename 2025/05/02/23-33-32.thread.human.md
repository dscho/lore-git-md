This thread addresses a platform compatibility issue where BSD variants (NetBSD and FreeBSD) return different errno values (EFTYPE and EMLINK respectively) than the POSIX-standard ELOOP when O_NOFOLLOW encounters a symlink. This divergence caused test failures in t0602-reffiles-fsck.sh after stricter filetype checking was introduced for packed-refs.

Collin Funk has now completed the issue with a follow-up patch that extends his initial NetBSD fix to also handle FreeBSD's EMLINK case. The solution uses conditional compilation in wrapper.c's open_nofollow() function to translate these platform-specific errno values to ELOOP while maintaining the expected behavior on POSIX-compliant systems. The implementation remains narrowly focused on symlink cases to avoid masking legitimate errors.

Both brian m. carlson and Junio C Hamano had previously reviewed and approved the technical approach, with Junio anticipating this follow-up to complete the BSD errno translation work. The patch fixes all known test failures while leaving OpenBSD unaffected - though Collin notes any future issues there would be similarly straightforward to address. This concludes the specific BSD compatibility issue, though broader platform errno divergence remains a systemic consideration for future cases.
