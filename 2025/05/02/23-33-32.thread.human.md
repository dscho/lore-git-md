This thread addresses platform-specific errno behavior when Git encounters symlinks during filesystem operations. The core issue stems from BSD variants (NetBSD and FreeBSD) returning non-POSIX error codes (EFTYPE and EMLINK respectively) when O_NOFOLLOW encounters a symlink, where POSIX specifies ELOOP should be used. This caused test failures after stricter packed-refs validation was introduced.

Collin Funk submitted a patch to handle NetBSD's EFTYPE by translating it to ELOOP in wrapper.c's open_nofollow() function. brian m. carlson reviewed and confirmed this approach, noting it avoids unnecessary lstat() calls since NetBSD's EFTYPE in this context reliably indicates a symlink. Junio C Hamano has indicated the NetBSD fix will be merged after minor log message cleanup.

The discussion revealed FreeBSD has a related but distinct issue (returning EMLINK) that will need separate handling. Participants expressed frustration about BSD systems not consistently following POSIX errno specifications, though recognized this as a systemic issue beyond Git project's control. The thread remains open for FreeBSD-specific follow-ups, but these won't block the NetBSD fix. This case highlights Git's ongoing need to accommodate platform variations in filesystem behavior, particularly around symlink handling in ref operations.
