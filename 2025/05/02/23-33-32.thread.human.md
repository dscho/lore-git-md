Here's a human-readable summary of the thread's current state:

This thread began as a platform compatibility discussion about how different BSD variants handle errno values when detecting symlinks during packed-refs operations. The core issue was resolved with Jeff King's lstat()-based approach, but BSD systems needed additional errno handling since NetBSD returns EFTYPE and FreeBSD returns EMLINK where POSIX specifies ELOOP.

Collin Funk has now submitted the third version of his BSD errno translation patch, which has been refined to meet Git's strict coding style guidelines after feedback from Patrick Steinhardt and Junio Hamano. The technical solution remains sound - it translates the BSD-specific error codes to ELOOP in wrapper.c - but now properly formats the preprocessor directives with correct indentation and spacing. This appears to be the final form needed before merging.

Meanwhile, shejialuo continues working on a parallel effort to optimize packed-refs reading by using mmap instead of strbuf operations. The two efforts are related but independent - the BSD errno handling improves portability while the mmap work focuses on performance. Measurements show most packed-refs files are small (<5MB), though some outliers reach 2GB.

The thread has reached consensus on the BSD errno solution, with the style compliance being the last remaining item. With that now addressed in v3, the patch seems ready for final review and merging. The mmap optimization work will continue as a separate but complementary improvement to the packed-refs handling.
