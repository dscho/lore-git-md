The thread discusses a platform-specific fix for NetBSD's non-standard behavior when opening files with O_NOFOLLOW. The POSIX standard specifies that open() should return ELOOP when encountering a symlink with O_NOFOLLOW, but NetBSD instead returns EFTYPE. This discrepancy caused test failures in t0602-reffiles-fsck.sh after commit cfea2f2da8 introduced stricter filetype checking for packed-refs.

The proposed solution adds NetBSD-specific handling in open_nofollow() to translate EFTYPE to ELOOP when the failure occurs on a symlink. The patch avoids the need for an additional lstat() call by leveraging NetBSD's consistent behavior where EFTYPE only occurs in this specific circumstance. The change is cleanly contained to wrapper.c and only affects NetBSD builds, maintaining expected behavior across all platforms while addressing the test failure.
