This thread began as a platform compatibility fix for BSD variants' errno behavior when handling symlinks in refs validation. Collin Funk's patches addressed test failures where NetBSD and FreeBSD return EFTYPE and EMLINK respectively (instead of POSIX-standard ELOOP) for symlink operations. His v2 patch completed the BSD errno translation work in wrapper.c, which Junio C Hamano and brian m. carlson had reviewed and approved.

Jeff King (Peff) has now proposed an alternative approach that could simplify the solution. Rather than handling platform-specific errno values, he suggests using lstat() directly in packed-backend.c to check file types - a more universal solution that would eliminate the need for BSD-specific code. His key points are that this would work consistently across platforms, avoid errno translation complexity, and maintain functionality while slightly changing error messages. He notes the atomicity tradeoff is acceptable for fsck operations.

The thread now presents two viable solutions: Collin's BSD-specific errno translation (already implemented and working) versus Peff's proposed lstat()-based approach (which would restructure the file checking logic). Both maintainers had signed off on the current direction, but Peff's suggestion introduces new technical considerations about whether to handle platform differences at the errno level or restructure the validation logic itself. The discussion may now shift to evaluating which approach better aligns with Git's long-term maintenance and portability goals.
