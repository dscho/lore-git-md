Feature patch series completing the `git gc` replacement by implementing the last two missing maintenance tasks (worktree pruning and rerere garbage collection). This v3 iteration from Patrick Steinhardt simplifies the rerere GC approach in response to performance concerns raised by Junio Hamano.

The series now counts rr-cache directory entries rather than checking staleness, making the auto-execution condition much lighter weight. The default threshold is set to 1 entry (down from 20 stale entries in v2). This change addresses the main outstanding concern from the v2 review while maintaining the core functionality.

Other improvements since v1 include new config options (`maintenance.worktree-prune.auto` and `maintenance.rerere-gc.auto`) for controlling when these tasks run automatically, plus test infrastructure improvements to avoid fragile subprocess checking. The series has already received approval from Derrick Stolee, with this v3 addressing the final performance optimization question.

With these changes, Git now has all the technical pieces needed to fully replace `git gc` with granular maintenance tasks, though the actual deprecation of `git gc` remains future work. The implementation follows the established pattern of the maintenance command while providing finer user control over what operations run.
