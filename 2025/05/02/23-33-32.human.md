This is a platform compatibility fix targeting NetBSD. The patch addresses a discrepancy where NetBSD's `open()` with `O_NOFOLLOW` returns `EFTYPE` for symlinks instead of the POSIX-standard `ELOOP`. This caused a test failure in `t0602-reffiles-fsck.sh` where the error message for symlinked packed-refs files showed the wrong errno value.

The fix modifies `open_nofollow()` in wrapper.c to translate NetBSD`'s `EFTYPE` to `ELOOP` when opening files. This maintains consistent behavior across platforms while avoiding the overhead of an additional `lstat()` call. The issue was introduced in commit cfea2f2da8 which added packed-refs filetype checking.

The patch is small and focused, with a clear explanation of both the problem and solution. It includes a test case demonstrating the fix and properly documents the NetBSD-specific behavior in the code. This appears to be a straightforward, well-justified platform compatibility improvement.
