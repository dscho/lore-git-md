This is part 2 of a 2-patch series introducing standardized deprecation infrastructure, specifically targeting `git whatchanged`. The patch adds the opt-in requirement (`--i-still-use-this`) to `git whatchanged` using the new deprecation helper from part 1.

Junio Hamano responds to Patrick Steinhardt's suggestion about showing replacement commands in deprecation warnings. Hamano argues that the deprecation process should be driven by actual usage metrics (via forced opt-in) rather than education about alternatives. He maintains that if users still need education about replacements, it's too early to deprecate the command. The exchange clarifies that this is currently a measurement phase before formal deprecation.

The technical implementation places the `i_still_use_this` flag in the log configuration struct since it's needed during the parsing phase. The patch follows the established pattern from `pack-redundant` deprecation, treating this as a transitional phase to gauge real-world usage before making breaking changes.
