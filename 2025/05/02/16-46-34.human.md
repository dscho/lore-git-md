This is a discussion about the deprecation process for `git whatchanged`, part of the ongoing standardization of Git's deprecation infrastructure. Junio Hamano clarifies the intent behind the current patches, explaining they are meant to gauge usage of `git whatchanged` by introducing warnings (with an escape hatch) before any formal deprecation announcement.

The exchange reveals two key points: First, the current work parallels the earlier `pack-redundant` deprecation process, combining the initial warning phase and subsequent escalation into one step. Second, Hamano confirms the intent is indeed to measure real-world usage before deciding on full deprecation, which would then be documented in BreakingChanges.adoc in a future step.

The discussion shows careful consideration of how to balance user impact with maintenance burden, following established patterns while being transparent about the phased approach. This maintains Git's conservative stance on breaking changes while still making progress on cleaning up the command set.
