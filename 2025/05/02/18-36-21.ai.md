This is a technical follow-up in the diff context unification thread, where Junio Hamano responds to Leon Michalak's concern about edge case handling of `--unified=-1` values. 

Junio acknowledges the theoretical edge case where a user could explicitly pass `--unified=-1` (which the code treats identically to not passing any value), but dismisses it as a non-issue in practice. He suggests two approaches: either the command line/config parsers could validate the input to reject `-1`, or more pragmatically, the project could simply consider this user error (PEBKAC) that doesn't warrant special handling. His position is clearly in favor of the latter approach, stating users who pass invalid values have no grounds to complain when they're ignored.

The email reinforces the thread's consensus to use `-1` as an internal sentinel value while treating the edge case as unimportant. This moves the discussion forward by resolving one of the remaining minor questions, leaving only the validation layer placement and `GIT_DIFF_OPTS` behavior as open issues. Junio's response carries significant weight as the Git maintainer, effectively settling this aspect of the design.
