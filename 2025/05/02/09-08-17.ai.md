This is a follow-up discussion on the deprecation infrastructure series, specifically addressing the implementation details of the `git whatchanged` deprecation patch. Patrick Steinhardt suggests enhancing the deprecation warning to include the recommended alternative command.

The email focuses on two technical aspects:
1. Explains why the `i_still_use_this` flag is placed in `struct log_config` rather than being local to `cmd_whatchanged()` (due to parsing happening in `cmd_log_init_finish()`)
2. Proposes extending the `you_still_use_that()` helper to accept an explanation parameter that would tell users the replacement command (`git log --raw` in this case)

This is a refinement suggestion to the deprecation infrastructure rather than a challenge to the overall approach. The change would make the deprecation warnings more actionable by explicitly stating the modern alternative. The implementation would require modifying both the helper function in usage.c and its call sites, while maintaining the same warning/die behavior.

The suggestion aligns with the series' goal of creating a complete deprecation template, adding an explicit "migration path" component to the warning messages. This would be particularly useful for commands like `git whatchanged` where the alternative (`git log --raw`) isn't immediately obvious to all users.
