This is a feature patch series (v3) that completes the implementation of standalone maintenance tasks to fully replace `git gc` functionality, specifically adding worktree pruning and rerere garbage collection as configurable maintenance operations.

The series builds on prior work to decompose `git gc` into granular tasks, with this version simplifying the rerere GC implementation in response to performance concerns raised in v2. The key changes in v3 are: replacing the three-phase rerere GC approach (collect/prune/cleanup) with a simpler directory entry count check, and adjusting the default threshold from 20 stale entries to just 1 directory entry. This addresses Junio Hamano's concerns about unnecessary overhead while maintaining the core functionality.

Technical details include new config options (`maintenance.worktree-prune.auto` and `maintenance.rerere-gc.auto`), optimized worktree name retrieval via `get_worktree_names()`, and comprehensive test coverage of the auto-execution threshold logic. The implementation avoids process spawning where possible and maintains compatibility with existing rerere-related config options.

The series appears well-polished, with thorough documentation updates and test cases that replace fragile subprocess checking with more robust verification methods. With Derrick Stolee's prior approval of v2 and this simplification addressing the last open question, the series seems ready for inclusion as the final piece in the multi-year effort to replace `git gc` with granular maintenance tasks.
