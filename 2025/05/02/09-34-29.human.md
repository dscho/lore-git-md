This is a follow-up clarification to a completed 3-patch series enhancing the promisor-remote protocol. The series adds configurable validation of remote attributes (partialCloneFilter and token) during clone/fetch operations, with both server advertisement and client verification.

The author, Christian Couder, notes that an earlier comment about case sensitivity in field name comparisons is now outdated - the v2 series already implements case-insensitive comparison for field names (while maintaining case-sensitive comparison for values). This was one of several refinements made between v1 and v2 based on feedback from Junio C Hamano and Patrick Steinhardt.

The clarification serves as a minor correction to the discussion record, confirming that this particular issue was properly addressed in the final version of the series. The patch set appears ready for maintainer review, having incorporated all substantive feedback and established clear protocol constraints around field handling.
