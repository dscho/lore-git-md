This is a follow-up in the Scalar feature series addressing implementation issues with the `--no-maintenance` flag. Derrick Stolee acknowledges Patrick Steinhardt's findings about two problems in the current implementation: (1) the `toggle_maintenance(0)` call actually performs an active unregistration (via `git maintenance unregister --force`) rather than just skipping maintenance setup as documented, and (2) the test suite lacks verification that existing maintenance configurations remain untouched.

Stolee confirms the behavior discrepancy using `test_subcommand` tracing and commits to fixing it by properly plumbing the ability to skip `toggle_maintenance()` when `--no-maintenance` is specified. He also accepts Steinhardt's suggested wording improvement from "if" to "whether" in the option help text.

For testing, Stolee provides a concrete example of how the current test would look when verifying the (incorrect) unregister behavior, noting the importance of properly validating this baseline before flipping it to a negative test. He plans to add additional test coverage to ensure maintenance configurations aren't disturbed when they shouldn't be.

This response focuses narrowly on fixing the implementation-level issues Steinhardt identified, separate from the ongoing architectural debate about maintenance control placement. The fixes appear straightforward and uncontroversial, addressing clear documentation/behavior mismatches while maintaining the flag's core purpose of avoiding maintenance.lock conflicts during setup.
