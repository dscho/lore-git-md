Maintenance control discussion continues in Scalar patch series. Patrick Steinhardt raises two technical concerns about Derrick Stolee's proposed `--no-maintenance` flag implementation. First, he points out that passing `0` to `toggle_maintenance()` would actually deregister existing maintenance (via `git maintenance unregister --force`), which contradicts the documentation's claim that it merely skips configuration without affecting existing setups. Second, he suggests a wording improvement for the option help text ("whether" instead of "if") and notes the test suite should verify the flag doesn't deregister pre-existing maintenance.

This follows Junio Hamano's earlier architectural concerns about maintenance control placement, adding implementation-specific issues to resolve. The exchange highlights how subtle behavior differences in maintenance registration could affect users, especially around the distinction between skipping new maintenance setup versus preserving existing configurations. The test coverage discussion suggests both documentation and implementation may need adjustment to properly reflect the intended behavior.
