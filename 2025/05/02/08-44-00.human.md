This is a refactoring patch in Patrick Steinhardt's series to decompose `git gc` functionality into standalone maintenance tasks. It extracts worktree pruning from `cmd_gc()` into a new `maintenance_task_worktree_prune()` function, maintaining the same behavior but preparing for the upcoming introduction of this as a standalone maintenance task.

The change is straightforward - it moves the existing worktree pruning logic that calls `git worktree prune --expire` into a dedicated function with the same signature as other maintenance tasks. The implementation remains identical, still using a child process to perform the actual pruning. This is part of the larger effort to make each `git gc` operation available independently through `git maintenance`.

The patch appears clean and focused, with no behavior changes. It follows the pattern seen in previous maintenance task decompositions, suggesting it will integrate smoothly with the rest of the series.
