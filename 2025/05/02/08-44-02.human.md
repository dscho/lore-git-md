This is a feature patch (5/7 in a series) that introduces worktree pruning as a standalone maintenance task, completing the decomposition of `git gc` functionality. Patrick Steinhardt adds a new "worktree-prune" task to `git-maintenance` that handles stale worktree cleanup, matching what `git gc` currently does.

The patch adds configurable auto-execution via `maintenance.worktree-prune.auto` (defaulting to 1 prunable worktree) and maintains compatibility with the existing `gc.worktreePruneExpire` setting. The implementation reuses the existing worktree pruning logic but wraps it in the maintenance framework, including proper condition checking before auto-execution.

Test coverage is thorough, verifying:
- Basic pruning behavior
- Auto-execution thresholds
- Config option handling
- Expiration date propagation
- Edge cases around empty/nonexistent worktrees

This continues the series' pattern of cleanly extracting `git gc` components into standalone maintenance tasks with configurable auto-execution. The implementation looks solid, building on existing worktree infrastructure while adding the necessary integration points for the task scheduler.
