This is a bug report about Git's safe.directory behavior interfering with SSH cloning of repositories owned by other users. Matthias vom Bruch describes a scenario where they cannot clone a bare repository over SSH when it's owned by a different user, even after adding the suggested safe.directory exception.

The issue occurs when:
1. A bare repo is created with group ownership (a:a_and_b) and 770
2. User b (part of a_and_b group) tries to clone it via SSH
3. Git rejects the operation with a "dubious ownership" error
4. Adding the suggested safe.directory config doesn't resolve the issue

The reporter expected this to work since multi-user repository access is a common workflow, and notes that rsync works fine with the same permissions. They're particularly surprised that the suggested fix doesn't actually fix the problem. The behavior was reproduced on NixOS with Git 2.47.2.

This appears to be either a bug in how safe.directory exceptions are applied during SSH operations or possibly a documentation issue if this is intended behavior that needs better explanation. The report is well-documented with clear steps to reproduce, though it lacks information about whether this works with non-bare repositories or other permission configurations.
