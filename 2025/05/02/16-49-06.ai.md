This is a follow-up discussion in the ongoing deprecation infrastructure thread, specifically addressing technical details of the `git whatchanged` deprecation implementation.

Junio Hamano responds to Patrick Steinhardt's suggestions about the deprecation warning implementation. Steinhardt had questioned the placement of the `i_still_use_this` flag in `struct log_config` rather than being local to `cmd_whatchanged()`, and proposed extending the warning to suggest `git log --raw` as the replacement.

Hamano clarifies two key points:
1. The flag placement is intentional - it needs to persist beyond the command function due to the parsing flow in `cmd_log_init_finish()`
2. He pushes back against including replacement suggestions in warnings, arguing that deprecation should only proceed when adoption has already shifted naturally, making such explanations unnecessary

The exchange reveals differing philosophies about deprecation messaging - Steinhardt favors proactive guidance while Hamano prefers measuring actual usage patterns first. This touches on core aspects of the deprecation infrastructure being established, particularly around when and how to communicate transitions to users.

Technical details discussed include:
- The `struct log_config` modification adding `i_still_use_this`
- The warning insertion point in `cmd_whatchanged()`
- The relationship between `cmd_log_init_finish()` and command execution flow
- The existing `you_still_use_that()` helper's capabilities

This discussion occurs after the core deprecation approach has been settled (opt-in warnings first, documentation updates later) but before any potential implementation refinements would be incorporated.
