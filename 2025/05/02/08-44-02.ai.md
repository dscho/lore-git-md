This is a feature patch (5/7 in v3 series) implementing the worktree-prune maintenance task, completing the decomposition of `git gc` functionality. The patch introduces a new standalone task for pruning stale worktrees, matching `git gc`'s behavior while making it configurable via `maintenance.worktree-prune.auto`.

Key technical details:
- Adds `maintenance_task_worktree_prune()` function calling `git worktree prune`
- Implements `worktree_prune_condition()` checking for prunable worktrees against configurable threshold (default 1)
- Preserves existing `gc.worktreePruneExpire` config compatibility
- Uses new `get_worktree_names()` helper from previous patch
- Includes comprehensive test suite verifying auto-execution thresholds and expiration handling
- Follows established pattern of direct implementation in maintenance builtin

The implementation maintains child process spawning for compatibility while adding the configurable auto-execution threshold typical of maintenance tasks. Test coverage includes edge cases for threshold values and verification of expiration date handling. This completes one of the two final missing pieces (along with rerere GC) for full `git gc` replacement capability.
