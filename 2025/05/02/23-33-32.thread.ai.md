Thread identity: Platform compatibility fix for NetBSD's errno behavior with O_NOFOLLOW, addressing test failures in t0602-reffiles-fsck.sh where BSD variants return non-POSIX errno values (EFTYPE on NetBSD, EMLINK on FreeBSD) for symlink operations instead of standard ELOOP. Originated from Collin Funk's patch after commit cfea2f2da8 added stricter filetype checking for packed-refs.

Core problem: POSIX specifies ELOOP should be returned when O_NOFOLLOW encounters a symlink, but BSD variants diverge - NetBSD returns EFTYPE and FreeBSD returns EMLINK. This causes test failures in refs/files-backend.c's validation logic.

Current status: Collin Funk's initial patch added NetBSD-specific handling in wrapper.c's open_nofollow() to translate EFTYPE to ELOOP, avoiding extra lstat() calls since NetBSD's EFTYPE only occurs for symlinks in this case. brian m. carlson confirmed the NetBSD solution but identified FreeBSD's EMLINK behavior as needing similar treatment.

Key technical details: The fix centers on wrapper.c's open_nofollow() implementation, which wraps open(O_NOFOLLOW). The function must handle platform-specific errno values while maintaining POSIX-expected behavior. NetBSD's EFTYPE translation is safe because it only occurs for symlinks in this context, avoiding the need for additional stat calls to disambiguate error cases.

Open questions: FreeBSD's EMLINK behavior needs equivalent handling in open_nofollow(). brian m. carlson notes broader frustration with BSD variants not providing POSIX-compliant errno values even when _POSIX_SOURCE is defined, suggesting this may require a more comprehensive BSD compatibility patch series.

Participant positions: Collin Funk authored the initial NetBSD fix. brian m. carlson reviewed and confirmed the NetBSD solution while identifying the FreeBSD issue, expressing concern about broader POSIX compliance problems across BSD systems.

Related work: The issue surfaced after commit cfea2f2da8 (refs: verify packed-refs using filetype in dirent) added stricter validation. The discussion may lead to expanded BSD compatibility handling in wrapper.c.
