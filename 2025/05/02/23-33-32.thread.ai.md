Thread identity: Platform compatibility fix for NetBSD's errno behavior with O_NOFOLLOW, addressing test failures in t0602-reffiles-fsck.sh where BSD variants return non-POSIX errno values (EFTYPE on NetBSD, EMLINK on FreeBSD) for symlink operations instead of standard ELOOP. Current status: Collin Funk's patch adding NetBSD-specific errno translation (EFTYPE->ELOOP) in wrapper.c's open_nofollow() has been reviewed by brian m. carlson and approved by Junio C Hamano for merging after minor log message formatting fixes. The FreeBSD case (EMLINK) remains outstanding but won't block the NetBSD fix.

NetBSD's EFTYPE translation is safe because it only occurs for symlinks in this context. The discussion confirmed this approach avoids extra lstat() calls while correctly handling the test case failures. FreeBSD's EMLINK will require similar but separate handling.
