Platform compatibility fix for NetBSD's errno behavior with O_NOFOLLOW, addressing a test failure in t0602-reffiles-fsck.sh where NetBSD's open() with O_NOFOLLOW returns EFTYPE for symlinks instead of POSIX-standard ELOOP. The issue surfaced after commit cfea2f2da8 added stricter filetype checking for packed-refs. The solution adds NetBSD-specific handling in open_nofollow() (wrapper.c) to translate EFTYPE to ELOOP when opening fails on a symlink, avoiding an extra lstat() call since NetBSD's EFTYPE only occurs in this specific case. The patch maintains expected behavior while working around the platform quirk, with a clear commit message explaining both problem and solution.
