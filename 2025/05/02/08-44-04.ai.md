This is the final patch in Patrick Steinhardt's v3 series completing the `git gc` decomposition by adding rerere garbage collection as a standalone maintenance task. The patch introduces a new `rerere-gc` task that mirrors the functionality from `git gc`, with configurable auto-execution thresholds via `maintenance.rerere-gc.auto`.

The implementation follows the rr-cache directory entry count approach that was simplified in response to Junio Hamano's performance concerns about the v2 three-phase design. The task checks for stale entries by counting directory entries in `.git/rr-cache`, running garbage collection when the count exceeds the configured threshold (defaulting to 1). Like other tasks in the series, it maintains child process spawning for compatibility while moving the logic into the maintenance builtin.

Key technical details include:
- New `rerere_gc_condition()` helper that checks rr-cache directory entries against the threshold
- Preserved error handling and reporting through existing rerere infrastructure
- Comprehensive test coverage verifying auto-execution behavior with various config values
- Documentation updates for both config and command references
- Follows the established pattern from earlier patches in the series

The patch appears well-tested with cases covering:
- Forced execution without --auto
- Auto-execution only when entries exist
- Threshold configuration (negative, zero, positive values)
- Directory existence edge cases

This completes the technical prerequisites for replacing `git gc` functionality, with all major concerns from previous iterations addressed. The implementation is now simpler and more performant than the v2 approach while maintaining the same functionality.
