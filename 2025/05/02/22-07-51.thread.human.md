This thread discusses a bug in Git's safe.directory ownership checking that affects SSH clones of bare repositories when local and remote users differ. The original issue occurs when cloning a remote bare repo with group permissions (770) where the user has SSH access but lacks matching local ownership. The safe.directory configuration suggestion fails to resolve the problem, indicating a gap in how Git handles SSH-based access patterns.

Brian M. Carlson has now responded, suggesting that Git 2.48 or newer on the server side may already contain a fix for this issue from untrusted repositories. The solution requires using the `--no-local` flag for local clones, though this isn't needed for pure network operations. While this provides a potential path forward, it leaves open the question of whether safe.directory should still work in these cases, which was a key concern in the original report. The thread remains active as participants verify whether the newer Git release fully addresses the reported behavior.
