A user has reported a problem with Git's safe.directory feature when cloning bare repositories over SSH in multi-user environments. The issue occurs when trying to clone a repository owned by a shared group (with 770 permissions) where the local user has SSH access but isn't the owner. Despite adding the directory to safe.directory as Git's error message suggests, the clone operation still fails with a "dubious ownership" error, while rsync works fine for the same path.

The reporter notes this is a common scenario for shared repositories and argues Git should handle it better by default. The current behavior appears to have a gap in how ownership checks interact with SSH-based operations, where the suggested configuration fix doesn't actually resolve the problem. The report provides clear reproduction steps across NixOS systems, indicating this isn't an isolated case. This seems like a legitimate usability issue that may need either a bug fix or enhancement to properly support multi-user SSH access patterns.
