Bug report about `git svn clone` failures on Windows with unhelpful error messages. BERENDSEN Arnoud reports two distinct but possibly related issues when migrating an SVN repository to Git on Windows. The first error occurs when trying to strip paths from commits, failing on a `.gitignore` file with an unclear message about path stripping. The second and more serious issue shows Perl warnings about uninitialized values in Git.pm followed by a fatal error about invalid object names when processing branch initialization.

The report notes the errors appear in Git for Windows version 2.49.0.windows.1, with OpenSSL 3.2.4 and Perl 5. The user observes that restarting the clone command sometimes allows progress past these errors, suggesting the process could potentially continue rather than aborting. The error messages are criticized for being unhelpful - they don't explain what went wrong or how to fix it, particularly the Perl warnings which point to internal implementation details rather than user-actionable information.

Key technical details include the SVN repository layout (using --stdlayout), the Windows-specific paths involved, and the specific line numbers in Git.pm where the Perl warnings originate (lines 1655 and 1681). The report doesn't include repository-specific details that would help reproduce the issue, but does show the general structure of the failing operations. The issues appear related to branch mapping and path handling during the SVN-to-Git conversion process.
