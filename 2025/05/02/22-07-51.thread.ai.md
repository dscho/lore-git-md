[Thread summary]

This thread reports and analyzes a bug in Git's safe.directory ownership checking during SSH clones of bare repositories, where the current implementation fails to properly handle multi-user access scenarios. The original report demonstrated that when cloning a remote bare repo owned by a different user group (group a_and_b with 770 permissions) where the user has SSH access but lacks matching local ownership, Git's error about safe.directory configuration doesn't resolve the issue despite functional SSH access. The problem is reproducible across NixOS systems and affects any multi-user Git environment not using centralized hosting platforms.

Brian M. Carlson has now responded suggesting the issue may already be fixed in Git 2.48 or newer on the server side, where a patch addresses similar problems from untrusted repositories. He notes that local clones would still require the `--no-local` flag as documented, while network operations wouldn't need this workaround. This moves the discussion forward with a potential solution path, though it leaves unresolved whether the safe.directory configuration suggestion should work in these cases. The technical distinction between local and network operations helps clarify the scope of the fix, but the core question about safe.directory's behavior in SSH-based multi-user scenarios remains open for further investigation. The thread now awaits confirmation whether the Git 2.48 server-side change fully resolves the reported case or if additional changes are needed to properly support this access pattern.
