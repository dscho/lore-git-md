This thread reports a bug in Git's safe.directory ownership checking during SSH clones of bare repositories. The core issue occurs when cloning a remote bare repo owned by a different user group (group a_and_b with 770 permissions) where the user has SSH access but lacks matching local ownership. Git's error suggesting safe.directory configuration fails to resolve the issue, despite SSH access being otherwise functional (verified via rsync). The reporter demonstrates this is reproducible across NixOS systems and argues the current behavior is incorrect for multi-user repository access scenarios. The key technical problem appears to be that safe.directory checks don't properly account for SSH-based access patterns where local and remote users differ, making the suggested configuration workaround ineffective. This represents either an implementation bug in safe.directory or a missing feature for SSH use cases, with impact on any multi-user Git environment not using centralized hosting platforms. The report provides clear reproduction case showing the configuration suggestion doesn't solve the problem, indicating deeper investigation needed into ownership check interactions with remote operations.
