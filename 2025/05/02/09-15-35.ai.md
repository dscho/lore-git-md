Feature patch in ongoing Scalar maintenance control discussion. Patrick Steinhardt raises two specific technical concerns about Derrick Stolee's implementation of the `--no-maintenance` flag for `scalar register`. First, he points out that passing `0` to `toggle_maintenance()` (as done when `--no-maintenance` is used) actually invokes `git maintenance unregister --force`, which actively deregisters maintenance rather than just skipping its setup - directly contradicting the documentation's claim that it "does not disable any maintenance that may already be enabled". Second, he suggests a minor wording improvement for the option help text ("whether" instead of "if").

Steinhardt also notes a testing gap: while the patch includes a test for `--no-maintenance`, it doesn't verify that existing maintenance configurations remain untouched (a key documented behavior). This feedback comes amid Junio Hamano's broader architectural critique about maintenance control placement, though Steinhardt focuses narrowly on these implementation-level issues rather than engaging with the higher-level design debate.

The concerns center around scalar.c's `register_dir()` and `toggle_maintenance()` functions, with implications for how maintenance state transitions are represented in both code and documentation. The test file t9210-scalar.sh would need expansion to properly validate the maintenance preservation guarantee. This appears to be a straightforward fix requiring either documentation adjustment or behavior change to align with stated intentions, separate from the ongoing architectural discussion about where maintenance control should live.
