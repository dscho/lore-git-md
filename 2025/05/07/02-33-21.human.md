Bugfix for memory leaks in parse-options short option handling.

This is the first patch in a series addressing memory leaks and type safety in Git's option parsing code. Lidong Yan fixes a specific case where `xstrdup()` was used to handle unknown short options (`-c` style) without proper cleanup. The patch introduces a new `strdup_fn` callback mechanism that allows callers to control memory allocation for unknown options.

The change adds a new `OPT_UNKNOWN` macro and modifies the parse-options machinery to optionally use a caller-provided allocation function. A new helper program (`test-free-unknown-options`) demonstrates the fix by collecting unknown options in a strvec for proper cleanup. Test coverage in t0040 verifies the new behavior.

The patch appears well-contained and focused, with clear test coverage. The approach of adding a callback mechanism rather than hardcoding cleanup behavior seems sensible for flexibility. This looks like a solid fix for a long-standing leak in a core component.
