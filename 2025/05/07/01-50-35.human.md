This is part 2 of a 4-patch series implementing a tri-state maintenance configuration model for Scalar commands. The series builds on previous work to replace a boolean flag with explicit "enable"/"disable"/"keep" options for background maintenance control.

The current patch adds a `--no-maintenance` option to `scalar register`, allowing users to skip automatic background maintenance setup when registering a repository. This is particularly useful for automation scenarios where background maintenance might interfere with foreground operations. The implementation:
- Adds the new flag to the command-line interface
- Updates the documentation to explain the option
- Includes tests verifying the new behavior
- Maintains backward compatibility by defaulting to enabled maintenance

The patch is well-contained, with clear documentation and test coverage. It follows the established pattern from the series by modifying the `register_dir()` infrastructure while preserving existing behavior. This change aligns with the overall goal of giving users more precise control over maintenance configuration.
