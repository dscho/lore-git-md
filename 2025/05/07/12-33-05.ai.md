This is a bugfix patch for `git send-email`'s domain name validation, part of a v4 series improving email sending functionality. The patch tightens the RFC1035-compliant validation of Fully Qualified Domain Names (FQDNs) in the Perl script.

The current implementation had overly lax checks, only verifying the presence of a dot and a macOS-specific `.local` exclusion. This caused problems when invalid domains like "MacBook.." were passed to SMTP servers, triggering errors. The new regex enforces proper label structure (1-63 alphanumeric/hyphen characters per component) while maintaining special handling for macOS `.local` domains.

Key technical changes:
- Adds RFC1035-compliant regex enforcing label rules (no leading/trailing hyphens, proper character sets)
- Preserves existing macOS `.local` special case
- Explicitly handles valid domain structure while rejecting malformed inputs
- "example-.com" (trailing hyphen)
- "-example.com" (leading hyphen)
- "example..com" (double dots)
- Overly long labels (>63 chars)

The patch demonstrates practical impact by showing before/after SMTP handshake behavior, where invalid "MacBook.." now properly falls back to "localhost.localdomain". This builds on prior discussion about `Net::Domain` limitations and server behavior differences.

The change is narrowly scoped (3-line diff) but addresses a concrete interoperability issue with email servers. It maintains backward compatibility while bringing validation in line with standards. The commit message provides clear examples of valid/invalid cases and references the relevant RFC.
