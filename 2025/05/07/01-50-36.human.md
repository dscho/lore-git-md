This is part of the Scalar maintenance configuration series, implementing the tri-state model for maintenance control. The patch adds a `--no-maintenance` option to `scalar clone`, completing the implementation of the three possible states (enable, disable, keep) across all Scalar commands.

The change allows users to skip background maintenance setup when cloning, which is particularly useful for automation scenarios like VM image preparation where concurrent maintenance could interfere with manual steps. The implementation follows the established pattern from earlier patches in the series, using a boolean flag that gets passed to the unified `register_dir()` function.

Documentation is updated to explain the new option, and tests verify both the successful disable case and that maintenance isn't attempted when `--no-maintenance` is used. The patch maintains consistency with the rest of the series, including trace2 verification and error message updates to reflect the tri-state model.
