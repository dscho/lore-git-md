This is a cover letter for a performance-focused patch series integrating the sparse index with `git add -p/-i` and `git apply`. The series is part of the ongoing effort to make more Git commands sparse-index aware to improve performance when working with large repositories using sparse-checkout.

The cover letter explains that while the sparse index improves performance for some commands, others still need to expand the sparse index to a full index, which is slow. This series specifically targets `git add -p` which suffers from two issues: (1) its use of `git apply` which wasn't sparse-index aware, and (2) the interactive add modes exiting too early before sparse index settings are applied. The patches address both issues with corresponding test coverage.

The performance impact is significant - the sparse index case shows a 96.7% reduction in runtime after both patches are applied (from 2.09s to 0.07s). The series includes a new performance test in p2000-sparse-operations.sh to track this improvement. The changes touch builtin/add.c and builtin/apply.c to properly handle sparse index cases, plus test files to verify behavior and measure performance. The patches appear well-motivated with clear performance data and thorough test coverage.
