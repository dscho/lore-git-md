This is a feature patch introducing worktree pruning as a standalone maintenance task, part of Patrick Steinhardt's v5 series to complete the decomposition of `git gc` functionality. The patch adds a new "worktree-prune" task to `git maintenance` that handles stale worktree cleanup, matching what `git gc` currently does.

The implementation includes a new `maintenance.worktree-prune.auto` config option that controls when the task runs automatically, with behavior similar to other maintenance tasks (zero to disable, negative to always run, positive to require N prunable worktrees). The patch preserves compatibility with the existing `gc.worktreePruneExpire` config while adding the new maintenance-specific control.

The code uses direct directory operations to check for prunable worktrees, replacing a helper function from earlier versions. It includes thorough test coverage of the auto-execution conditions and config handling, including edge cases. The implementation follows the established pattern for maintenance tasks, with a condition-check function and task execution function.

This appears to be a well-crafted addition to the maintenance command, completing one of the last remaining gaps in the `git gc` decomposition effort. The patch builds on previous discussion and review feedback, with all known issues from earlier versions addressed.
