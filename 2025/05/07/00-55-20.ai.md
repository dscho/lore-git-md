Performance test addition for the sparse-index `git add -p` optimization series.

This is the final patch in a 3-part series optimizing `git add -p/-i` and `git apply` for sparse checkouts. It adds a performance test case to `p2000-sparse-operations.sh` that measures the interactive add operation (`git add -p`) with both full and sparse index scenarios. The test writes to a file and then runs `git add -p` with simulated user input (accepting all changes with 'y').

The commit message includes performance data showing dramatic improvements from the series - sparse index cases improve by 33% after the first optimization and then 96.7% after the second, reducing runtime from 2.09s to 0.07s. The test is designed to validate these gains and monitor future performance. The author notes they didn't add a separate test for `git add -i` since its optimization is identical to `git add -p`.

Key technical details: The test uses the existing `test_perf_on_all` framework to run against both full and sparse checkouts. It modifies file 'a' (in the sparse cone) and measures the add-patch operation. The test complements earlier patches that made `git apply` and `git add -p` sparse-index aware by setting `command_requires_full_index=0`. This completes the performance validation for the series while maintaining the established sparse-index testing patterns.
