Performance optimization patch for `git add -p/-i` with sparse index. This is the second in a 3-part series integrating sparse index support with interactive add operations.

The patch moves the sparse index configuration earlier in `cmd_add()` to prevent unnecessary index expansions during interactive sessions. It reveals an interesting asymmetry: `-i` avoids expansion when sparse directories exist on disk, while `-p` still hits `ensure_full_index()`. The author notes this leaves room for future optimization but considers it an edge case since users should typically stay within their sparse-checkout.

The changes are well-tested with new cases in t1092 that verify both `-p` and `-i` behavior with sparse index, including scenarios where edits are inside and outside the sparse checkout. The implementation follows established sparse-index patterns while maintaining all existing functionality. This continues the series' goal of significant performance improvements for interactive workflows with large sparse checkouts.
