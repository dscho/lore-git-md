This is an RFC proposal for a new feature to skip connectivity checks in `git receive-pack`, motivated by GitLab's internal transaction management system. The series consists of 2 patches: a test suite addition and the implementation of a `--skip-connectivity-check` option.

The proposal explains that GitLab's RPC service already performs its own connectivity validation through a transaction system that stages changes and verifies object connectivity before applying them to the canonical repository. The built-in `receive-pack` checks are therefore redundant in their workflow. The author raises security concerns about exposing this as a command-line flag that could potentially be abused via `git push --receive-pack`, suggesting a config option or environment variable might be safer.

The implementation touches `builtin/receive-pack.c` to add the new option and modify the connectivity check logic, plus adds a new test script `t/t5412-receive-pack.sh` to verify the behavior. The changes appear well-scoped and the commit message provides clear context about the GitLab use case. The security consideration about command-line flag exposure shows thoughtful design awareness, though the RFC explicitly seeks feedback on this aspect before proceeding further.

Key technical details for future reference: the new `--skip-connectivity-check` flag (or potential config alternative), the modified connectivity check logic in `receive-pack`, and the new test file `t5412` that verifies the skip behavior. The discussion will likely focus on the security implications of the skip mechanism and whether GitLab's specialized use case justifies adding this to core Git.
