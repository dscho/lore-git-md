This is a follow-up discussion about the `remotes2config.sh` removal from Patrick Steinhardt's `contrib/` cleanup series. The email clarifies the script's removal timeline and rationale after Junio Hamano suggested waiting until Git 3.0.

Key technical points:
- The script was meant to migrate old-style remote configurations (`.git/remotes/`) to config-based ones, but Git now provides a built-in migration path via `git remote rename`
- The deprecation notice explicitly directs users to `git remote rename` rather than this script
- The script is incomplete (only handles `remotes/` not `branches/`) and broken (requires `git-sh-setup` in PATH)
- No references to the script exist in Git's codebase

Patrick argues for immediate removal rather than waiting for Git 3.0 since:
1. The script isn't the canonical migration path
2. It's effectively non-functional in its current state
3. There's no evidence of real-world usage
4. The deprecation process already directs users to the proper method

The discussion reinforces the established criteria for `contrib/` removal (unmaintained, broken, superseded) while addressing timing question raised by Junio. This aligns with the thread's systematic approach to cleaning up technical debt in `contrib/`.
