This is a technical discussion about the implementation approach for worktree pruning in Patrick Steinhardt's maintenance task decomposition series (v4). The email responds to Eric Sunshine's critique of patch 4/7 from v3, which had introduced a `get_worktree_names()` helper function in worktree.[hc].

Eric argued the helper function didn't provide meaningful abstraction over direct directory operations and questioned its value in the public API. Patrick agrees with this assessment and provides a diff showing how to directly use `opendir()`/`readdir()` in the worktree pruning condition check instead. The new implementation:
- Eliminates the need for the `get_worktree_names()` helper
- Uses direct directory operations with `repo_git_path_replace()`
- Maintains the same functionality for worktree pruning
- Simplifies the control flow by removing the intermediate string list

This change addresses one of the open questions in the thread about whether `get_worktree_names()` should be part of the public API. Patrick's response indicates he will drop the original patch from the series, resolving that design question. The discussion continues to focus on the remaining memory leak issue in the worktree pruning path and other minor documentation fixes needed before the series can be merged.
