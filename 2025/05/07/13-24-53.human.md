This is a bugfix patch addressing a memory leak in Git's option parsing code. The patch fixes an issue where unknown short options would cause memory leaks when parsed via `parse_options()`. The leak occurred because the code would `xstrdup()` the option string but never free it.

The solution introduces a way for callers to provide a custom allocation function for unknown options via a new `OPT_UNKNOWN` macro and associated infrastructure. The patch includes a test helper (`test-free-unknown-options.c) demonstrating how to use this with `strvec` to properly track and clean up unknown options.

This is the second version of the patch, which has been consolidated from three separate patches into one based on review feedback from Patrick Steinhardt. The changes include improved commit message clarity, code style fixes, and maintaining the test helper as a standalone documentation example. The implementation looks clean and well-tested, with the test case showing proper handling of both known (-a, -b) and unknown (-c, -d) options.

The patch touches parse-options.[ch] and adds new test infrastructure, with all changes contained to the option parsing subsystem. It maintains backward compatibility while fixing the memory leak issue.
