This is an RFC proposal for a new feature to optionally bypass connectivity checks in `receive-pack`. Justin Tobler from GitLab is exploring adding a `--skip-connectivity-check` option to `git-receive-pack` for cases where their transaction management system already performs equivalent checks.

The proposal explains that GitLab's RPC service handles connectivity validation through a separate transaction system that stages changes and verifies object connectivity before applying them to the canonical repository. This makes the built-in `receive-pack` checks redundant in their environment. The patch series includes both the implementation and new tests to verify the behavior.

The author raises a security consideration about whether this should be exposed as a command-line option (which could potentially be abused via `git push --receive-pack`) versus a config setting or environment variable. This appears to be the main open question they're seeking feedback on before proceeding.

The changes touch `builtin/receive-pack.c` to add the new option and modify the connectivity check logic, plus adds a new test script `t/t5412-receive-pack.sh`. The implementation looks thorough, with clear motivation tied to a real-world use case at GitLab. The RFC suggests the author is being appropriately cautious about potential security implications before finalizing the design.
