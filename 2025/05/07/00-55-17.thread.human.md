This thread focuses on optimizing `git add -p` and `git add -i` to work efficiently with sparse checkouts by avoiding unnecessary index expansions. The series is part of the broader sparse-index effort to improve performance in large repositories where only a subset of files is checked out.

The initial patch made `git apply` sparse-index aware, since it's used internally by `git add -p`. It showed dramatic performance improvements, reducing runtime by 96.7% in some cases while maintaining all existing functionality. The latest patch moves the sparse-index awareness check earlier in `cmd_add()` to prevent premature index expansions during interactive adds. 

An interesting asymmetry was discovered: `git add -p` still expands the index for edits outside the sparse checkout cone, while `git add -i` does not. The maintainers consider this an edge case since users typically work within their sparse checkout. The patch includes comprehensive tests verifying both commands' behavior with files inside and outside the sparse cone.

The changes touch `builtin/add.c` and `builtin/apply.c`, following established sparse-index patterns. All patches include thorough test coverage in `t1092-sparse-checkout-compatibility.sh` and performance tracking in `p2000-sparse-operations.sh`. While the current implementation maintains correctness and optimizes the common case, there remains room for future improvement in handling out-of-cone files with `git add -p`.
