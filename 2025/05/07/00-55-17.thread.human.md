This thread discusses Derrick Stolee's performance optimization series that integrates the sparse index with interactive commands like `git add -p/-i` and `git apply`. The changes prevent unnecessary index expansion in sparse checkouts, showing impressive results - a 96.7% runtime reduction (from 2.09s to 0.07s) for `git add -p`. 

After thorough review from Elijah Newren (who initially flagged some test case corrections) and approval from Junio Hamano, the series is considered merge-ready. The implementation handles edge cases well, with comprehensive test coverage in both compatibility and performance test suites.

Phillip Wood has now raised a follow-up question about whether similar optimizations should be applied to other patch-oriented commands like `git checkout --patch` and `git reset --patch`. While this expands the discussion's horizon, it doesn't affect the readiness of the current series, which remains focused and validated for its specific commands. The technical foundation established here could serve as a basis for future optimizations in related commands if needed.
