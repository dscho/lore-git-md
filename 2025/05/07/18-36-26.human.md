This is a follow-up discussion in the ongoing `contrib/` cleanup series, specifically about the removal of `git-resurrect.sh`. Kristoffer Haugsbakk provides additional evidence supporting the script's removal by analyzing StackOverflow data, showing that users overwhelmingly prefer manual reflog inspection (with 3029 votes) over using the contrib script (only 16 votes). The data suggests that even when users need to recover lost branches, they don't seek out or rely on this contrib script.

The email reinforces Junio Hamano's earlier point that the script's lack of maintenance and low usage make it a good candidate for removal, especially since core Git's reflog functionality provides a more transparent alternative. The StackOverflow analysis shows this isn't just a theoretical concern - actual user behavior aligns with removing the script. The discussion continues the thread's pattern of removing unmaintained contrib scripts when core Git offers equivalent or better functionality.
