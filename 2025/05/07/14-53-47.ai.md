Refactoring patch in the packed-refs memory optimization series. This is the second of four patches aimed at reducing memory pressure during packed-refs operations, particularly during fsck.

The patch extracts the buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()`. This enables reuse of the allocation logic in future fsck operations where direct file opening isn't desired. The change is purely structural - no behavior modifications are introduced in this patch.

Key technical details:
- Moves 54 lines of buffer allocation code (mmap vs read decisions) into new function
- Maintains all existing behavior including:
  - MMAP_NONE fallback handling
  - Small file threshold (32KB) for read vs mmap decision
  - Error handling for read/mmap operations
- Returns boolean success/failure consistently
- Updates `load_contents()` to use the new helper while preserving its interface
- Follows suggestions from Jeff King and Patrick Steinhardt to enable future fsck optimizations

The change prepares for patch 4 in the series which will use this extracted logic for mmap-based fsck operations. The code organization improvement allows sharing allocation strategy between runtime and verification code paths while keeping the fsck-specific changes focused.
