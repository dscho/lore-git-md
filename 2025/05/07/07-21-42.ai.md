This is the final patch in Patrick Steinhardt's v5 series completing the decomposition of `git gc` functionality into standalone maintenance tasks, specifically implementing rerere garbage collection.

The patch introduces a new `rerere-gc` maintenance task that handles garbage collection of the rerere cache, matching the functionality previously only available through `git gc`. The implementation follows the established pattern for maintenance tasks with:
- A new `maintenance_task_rerere_gc()` function that invokes `git rerere gc`
- A condition check (`rerere_gc_condition()`) that uses a simple existence-based heuristic (any positive `maintenance.rerere-gc.auto` value triggers GC if rr-cache exists with at least one entry)
- Configuration via `maintenance.rerere-gc.auto` with the standard integer-based threshold pattern used by other tasks
- Comprehensive test coverage verifying both manual and auto-triggered behavior

The implementation is clean and consistent with the rest of the maintenance framework, using direct directory operations (replacing the removed `get_worktree_names()` helper) and proper memory management. The tests cover all config scenarios (negative, zero, positive values) and verify the auto-condition behavior matches the documented semantics.

This completes the series' goal of fully decomposing `git gc` functionality into granular maintenance tasks, with rerere GC being the final missing piece. The patch appears technically sound with thorough test coverage and follows the established patterns seen in previous maintenance task implementations.
