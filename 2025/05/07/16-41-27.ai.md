This is a discussion thread about Git commit message conventions, specifically comparing bracketed annotation lines versus formal trailers for attributing contributions. The thread revisits a 2024 conversation between Kristoffer Haugsbakk and Jeff King about how to properly credit non-code contributions like commit message authorship.

The key technical discussion centers on whether bracketed annotations (e.g., `[kh: Added tests]`) provide any advantage over formal trailers (e.g., `Comment: Added tests`) when combined with Signed-off-by lines. Haugsbakk argues the signoff order already provides attribution, making brackets redundant. Jeff King had previously noted practical concerns about not wanting to forge others' signoffs when adding commit messages.

The thread references Junio Hamano's 2023 email about trailer parsing behavior, where bracketed lines become "non-trailer values" discarded by `git interpret-trailers`. This technical detail about trailer block parsing is relevant to the discussion about which format better preserves attribution information.

The email serves as a gentle bump of this stylistic discussion, inviting further input on whether the Git project should standardize on one approach over the other for auxiliary contributor annotations. The underlying question touches on both technical parsing behavior and project conventions for giving proper credit in commit histories.
