This is a discussion about command naming and integration in the ongoing `git-blame-tree` RFC thread. Kristoffer Haugsbakk responds to Marc Branchaud's concerns about having two separate blame commands (`git blame` and `git blame-tree`), arguing that Git already has many specialized commands (144 builtins, 6 with `-tree` suffix) and that causing significant user confusion.

Key points in this email:
- Counters Marc's concern about command proliferation by noting Git already has many niche commands (like `git-commit-tree`) that don't cause major issues
- Observes that `-tree` commands are typically discovered through curiosity rather than causing confusion
- Suggests `-tree` commands are seen as more advanced/less user-friendly tools
- Asks Marc for concrete examples where a new command would cause actual user confusion

The email continues the naming debate but shifts focus from technical integration concerns to user experience arguments, with Kristoffer taking a more permissive stance toward command proliferation compared to Marc's unification preference. No new technical implementation details are introduced - this is purely about the command structure debate that Junio Hamano had previously weighed in on.
