Performance optimization completing the packed-refs mmap series.

This is the final patch in a 4-part series optimizing memory usage in the packed-refs backend, specifically targeting fsck operations. Building on the refactoring work in patches 2-3 (which extracted buffer allocation and cleanup logic), this patch replaces the `strbuf_read()` approach in `packed_fsck()` with mmap-based file reading for large packed-refs files. The change aligns fsck operations with the rest of the packed-refs codebase's memory-efficient practices.

The patch modifies `packed_fsck()` to use the new `allocate_snapshot_buffer()` helper (introduced in patch 2) and properly handle cleanup via `munmap_temporary_snapshot()` (from patch 3). Key changes include replacing the `strbuf` with a `snapshot` struct, using the buffer allocation helper, and updating the content verification calls to work with the mmapped buffer. The implementation maintains all existing behavior while reducing memory pressure during verification.

This completes the series' goal of optimizing memory usage during packed-refs verification, particularly for large repositories. The changes have been guided by feedback from Jeff King and Patrick Steinhardt throughout the thread, with the final implementation following the planned approach outlined in earlier patches. The patch is a straightforward application of the infrastructure prepared in previous steps, with no new edge cases or behavioral changes beyond the intended memory optimization.
