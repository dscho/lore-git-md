This is a design discussion about the interactive context control feature in patch 3/3 of the series. Phillip Wood proposes an alternative approach to Junio C Hamano's suggestion for adjusting diff context during interactive sessions.

Phillip argues that modifying the "What now>" prompt (as Junio suggested) would be less optimal than enhancing `git add -p` specifically to allow re-displaying hunks with more context. His key points are:
1. The proposed change would let users get more context for the current hunk without restarting the entire selection process
2. Users who know their desired context upfront can already use the `-U` option added in patch 2/3
3. The current workaround (quitting and restarting) has limitations, especially for `git stash -p` where you can't amend stashes or pop multiple stashes on dirty worktrees

This suggests the interactive adjustment feature (patch 3) may need reconsideration or could potentially be dropped in favor of Phillip's proposed `add -p` enhancement. The discussion continues to refine the UI approach while maintaining the core functionality of runtime context control. Phillip's feedback represents an experienced contributor's perspective on workflow ergonomics, particularly around the stash use case which has special constraints.
