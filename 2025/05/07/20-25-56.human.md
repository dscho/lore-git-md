This is a documentation clarification in the ongoing interactive diff context controls patch series.

Junio C Hamano responds to Leon Michalak's explanation about the intended meaning of "implies" in the documentation for command-line diff context overrides. The thread had previously established that these overrides (-U/--unified and --inter-hunk-context) should require explicit -i/-p flags rather than implicitly enabling interactive mode.

Hamano explains that in Git's documentation conventions, "implies" has a specific technical meaning - it indicates that an option automatically enables another option (like `--short` implying `--dry-run` in `git commit`). What Michalak intended was to say these options only work in interactive mode, which should be phrased as "only effective for --interactive or --patch mode" instead.

This exchange helps finalize the documentation wording for patch 2/3 in the series, which implements command-line interface for diff context controls. The technical implementation is already settled - the remaining work is getting the documentation precisely right to match Git's established conventions. The clarification ensures the final wording will accurately reflect that these options require (rather than imply) interactive mode flags.
