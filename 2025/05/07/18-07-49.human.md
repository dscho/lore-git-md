This is a review discussion about command-line options for diff context in interactive Git commands, specifically addressing patch 2/3 in the series. Junio C Hamano responds to Phillip Wood's suggestion about documentation organization and raises concerns about option implications.

The key point of contention is whether `-U<n>` and `--inter-hunk-context=<n>` should automatically imply `--interactive/--patch` mode. While Phillip had suggested consolidating the documentation (which Junio agrees with), Junio strongly objects to the implication behavior, arguing it unnecessarily restricts future use cases. He proposes instead making it an error to use these context options without explicitly specifying interactive mode via `-i` or `-p`.

Junio's position is that while these options currently only make sense in interactive mode, future Git development might find non-interactive uses for configurable diff contexts. His suggestion would force users to be explicit about their intent while keeping the design more flexible for future extensions. This represents a significant design decision that will need resolution before the patch can proceed.
