This is a discussion about the naming and integration approach for the proposed `git-blame-tree` functionality. Junio Hamano responds to Marc Branchaud's push for integrating the tree-blame capability into the existing `git blame` command rather than creating a new standalone command.

Junio suggests two possible integration strategies:
1. A `--mode=file` option (with `--mode=line` as default) to switch between line-based and tree-based blaming
2. Automatic mode selection based on whether the target path is a file or directory, which he finds more elegant

He notes the need for input validation to catch nonsensical combinations (like line ranges with directory targets) but sees this as manageable. The email reinforces Marc's position in the ongoing debate while providing concrete technical pathways for implementation.

Key technical considerations mentioned:
- The distinction between "blaming lines in a file" vs "blaming a tree"
- Pathspec-based automatic mode detection
- Input validation requirements for mixed-mode options
- Avoiding confusing terminology like "blaming a file" when line movement across files is possible

This moves the naming debate forward by providing Junio's authoritative perspective on viable integration approaches while maintaining focus on the core technical requirements. The discussion remains centered on user experience and command structure rather than the underlying algorithm implementation.
