Performance patch integrating `git apply` with the sparse index system, part of a series to optimize sparse-checkout workflows. This first patch focuses on making `git apply` sparse-index aware, which is particularly important since it's used as a child process by `git add -p`. The core change is straightforward - removing the `UNUSED` attribute from the `repo` parameter and setting `command_requires_full_index=0` to prevent index inflation. The bulk of the patch consists of new test cases in `t1092-sparse-checkout-compatibility.sh` that verify behavior when applying patches both inside and outside the sparse checkout definition. Tests confirm the index remains sparse when applying to in-cone files, expands when needed for --index operations on out-of-cone files, but stays sparse for --cached operations. The patch maintains existing functionality while enabling sparse index benefits, with no behavior changes for non-sparse cases. This is a well-tested, focused change that directly addresses a performance bottleneck in the sparse-checkout workflow.
