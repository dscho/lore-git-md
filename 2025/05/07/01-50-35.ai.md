Feature implementation in the Scalar maintenance configuration series. This patch introduces a `--no-maintenance` option to `scalar register`, allowing users to skip automatic background maintenance setup during repository registration. The change is part of the broader tri-state maintenance control model (enable/disable/keep) being implemented across Scalar commands.

The patch modifies the `register_dir()` function to accept a maintenance parameter while maintaining backward compatibility (default remains enabled). Documentation is updated to explain the new option, and tests verify that `--no-maintenance` properly skips maintenance setup. The implementation includes trace2 verification to confirm the expected behavior.

This change specifically addresses automation scenarios where background maintenance might interfere with foreground operations. The test case demonstrates that maintenance remains disabled when requested, with no error output expected in this case. The error message for maintenance operations is also updated to use "toggle" instead of "turn on" to better reflect the new tri-state model.

The patch builds on the infrastructure established in the first patch of the series while implementing one of the three maintenance states (disable via `--no-maintenance`). It maintains consistency with the overall design approach while providing immediate utility for automation use cases. Test coverage is expanded to verify the new option works as intended without affecting other maintenance states.
