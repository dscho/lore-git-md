This is a discussion about removing the `git-resurrect.sh` script from `contrib/` as part of Patrick Steinhardt's ongoing cleanup series. The thread has already reached consensus on removing other obsolete scripts, with this being one of the final cases under consideration.

Junio Hamano notes that while the script hasn't seen updates since 2009, that alone isn't sufficient justification for removal since stable scripts don't necessarily need changes. However, he observes that the script is likely unused - users either don't know about it or prefer manual `git reflog` inspection when recovering lost branches. He supports removal but asks if there's a better supported alternative.

Patrick responds that no direct alternative exists, but suggests a more fundamental solution: modifying the reftable backend to preserve reflogs for deleted branches. This would make branch resurrection trivial via existing `git reflog` commands without needing a special script. He argues this better aligns with reflogs' purpose of tracking reference history, noting the file/directory conflict concerns that motivated current behavior don't apply to reftable.

The discussion reveals two paths forward: simple removal of the unmaintained script (the immediate action) versus a potential deeper change to reflog retention policy (a separate future consideration). The preservation of deleted branch reflogs in reftable would effectively obsolete the need for resurrection scripts while providing more comprehensive history tracking. This ties into broader questions about how Git handles reference lifecycle and data retention.
