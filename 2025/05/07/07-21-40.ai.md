This is a feature patch implementing worktree pruning as a standalone maintenance task, part of Patrick Steinhardt's v5 series to complete the decomposition of `git gc` functionality. The patch introduces a new "worktree-prune" task that handles stale worktree cleanup, matching `git gc`'s behavior while making it configurable via `maintenance`.

Key technical details:
- Adds `maintenance.worktree-prune.auto` config to control auto-execution frequency (default 1, meaning prune if any worktrees are stale)
- Implements `worktree_prune_condition()` to check worktree staleness against configured thresholds
- Preserves compatibility with existing `gc.worktreePruneExpire` setting
- Uses direct directory operations via `opendir()`/`readdir()` rather than the removed `get_worktree_names()` helper
- Includes comprehensive test coverage verifying auto-execution conditions and config handling
- Fixes a memory leak in the worktree pruning path that was identified in earlier review

The implementation follows the established pattern for maintenance tasks, with the pruning logic extracted to a standalone function and integrated into the maintenance framework. This completes one of the two final pieces needed to fully decompose `git gc` functionality (the other being rerere GC). The patch appears technically sound with thorough test coverage and documentation updates.
