Bugfix for memory leaks in parse-options short option handling. This is the first patch in a series addressing issues in Git's option parsing machinery.

The patch fixes a memory leak in `parse_short_opt()` where unknown short options were being duplicated with `xstrdup()` but never freed. The solution introduces a new `strdup_fn` callback mechanism in the parse-options API, allowing callers to control how unknown options are duplicated. The key changes include:

1. Adding a `strdup_fn` field to `struct option` and `parse_opt_ctx_t`
2. Introducing a new `OPT_UNKNOWN` macro to specify the callback
3. Modifying `parse_short_opt()` to use the callback when available
4. Adding a test helper (`test-free-unknown-options.c`) that demonstrates the fix by collecting unknown options in a strvec
5. Extending t0040-parse-options.sh with a test case

The implementation maintains backward compatibility by falling back to `xstrdup()` when no callback is provided. The test case verifies that unknown options (-c, -d) are properly captured and can be freed by the caller. This change primarily affects parse-options.[ch] but requires updates to test infrastructure to verify the fix.

The patch appears well-contained and focused changes, with clear test coverage for the new functionality. The memory leak being fixed was previously noted in a comment as "leaky, too bad", indicating this addresses a known issue. The callback approach provides flexibility while maintaining the existing behavior as a fallback.
