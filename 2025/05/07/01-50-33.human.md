This is a feature patch series for Scalar, introducing more flexible maintenance control options. The series has evolved through discussion to adopt a tri-state model (`enable`, `disable`, `keep`) for background maintenance configuration across Scalar commands.

The key change is converting the original boolean `--no-maintenance` flag to a more versatile `--maintenance=<mode>` option, particularly for the `scalar reconfigure` command. This addresses use cases where automated environments need to prevent background maintenance from interfering with setup steps, while maintaining the default "best practice" behavior for typical users.

The series now includes:
1. Refactoring of `register_dir()` to be more explicit about maintenance behavior
2. Adding `--no-maintenance` to `scalar register`
3. Adding `--no-maintenance` to `scalar clone`
4. Converting `scalar reconfigure` to use the new tri-state model

The implementation appears thorough, with comprehensive test coverage in t9210/t9211 and clear documentation updates. The design has reached consensus among maintainers, with Junio Hamano providing input on the tri-state approach. This looks like a well-considered change that provides needed flexibility while preserving Scalar's opinionated defaults.
