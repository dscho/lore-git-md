This is the first patch in a 4 series implementing a tri-state maintenance control model for Scalar commands. The patch refactors the `register_dir()` function to accept a `maintenance` parameter that determines whether to enable/disable maintenance or leave it unchanged, preparing for the new `--maintenance` option being added in later patches.

The changes are straightforward plumbing work - the patch modifies the function signature and updates all callers to pass `1` (enable maintenance) to maintain current behavior. It also adds clear doc comments explaining the maintenance behavior. The implementation follows Junio Hamano's suggested approach from earlier discussion, using an integer parameter that will later be replaced with string values ("enable"/"disable"/"keep") in subsequent patches.

This is a clean preparatory change that doesn't alter functionality yet but sets up the infrastructure needed for the tri-state model. The patch maintains all existing behavior while making the code more flexible for the upcoming changes. As part of a well-discussed series that has reached design consensus, this looks like solid incremental work.
