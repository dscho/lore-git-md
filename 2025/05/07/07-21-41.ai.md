This is a refactoring patch in Patrick Steinhardt's v5 series to decompose `git gc` functionality into standalone maintenance tasks. The patch extracts rerere garbage collection from `cmd_gc()` into a new `maintenance_task_rerere_gc()` function, following the established pattern for maintenance task decomposition.

The change moves the rerere GC implementation into a standalone function with the standard maintenance task signature, taking `maintenance_run_opts` and `gc_config` parameters (though neither is currently used). The actual functionality remains identical - it still spawns a child process running `git rerere gc` - but the code is now properly encapsulated for use by the maintenance framework.

This is one of the final preparatory steps before introducing the new `rerere-gc` maintenance task in the next patch. The series has already addressed all known issues from previous rounds, including a memory leak fix and simplification of the rerere GC condition check. The patch maintains the existing error handling where failures result in `die()` with the "rerere" task name.

The change is straightforward with no behavioral impact, just moving code into the expected structure for maintenance tasks. It follows the same pattern seen earlier in the series for worktree pruning extraction and aligns with the project's multi-year effort to decompose `git gc` into granular, configurable maintenance operations.
