This is a technical follow-up in the `git send-email` validation series, specifically addressing RFC-compliant domain name checking. The patch tightens the regex for valid FQDNs (fully qualified domain names) in `git-send-email.perl` to strictly enforce RFC1035 rules, rejecting malformed domains like those with leading/trailing hyphens or consecutive dots.

The author provides a test script demonstrating the new regex correctly identifies both valid domains ("example.com", "good-domain.org") and invalid ones ("-bad.com", "too..many.dots"). They also float the idea of using `hostname -f` as an alternative to `Net::Domain` on Linux/macOS, though this isn't implemented in the current version.

This continues the series' focus on robust email infrastructure, building on previous validation improvements while maintaining special handling for macOS `.local` domains. The change is small but meaningful, preventing potential SMTP issues from malformed sender domains. The test script shows practical verification of the new rules.
