This is the first patch in a 4-part series implementing the tri-state maintenance control model for Scalar commands. The patch refactors the `register_dir()` function to accept a `maintenance` parameter that determines whether to enable maintenance (1), leave it unchanged (0), or later in the series, disable it (via the tri-state enum).

Key technical changes:
- Adds documentation comment explaining `toggle_maintenance()` behavior
- Modifies `register_dir()` to conditionally enable maintenance based on new parameter
- Updates all callers to pass `1` (enable) to maintain current behavior
- Preserves existing error handling and warning messages
- Maintains all other functionality (FSMonitor, config setup)

The changes are preparatory for the tri-state model being fully implemented in subsequent patches. This establishes the parameterized infrastructure while keeping backward compatibility. The patch shows careful attention to documentation and maintains existing behavior, with all callers still requesting maintenance enablement at this stage.

This is part of the completed design consensus mentioned in the thread summary, where the tri-state model will provide clearer semantics across `scalar register`, `clone`, and `reconfigure` commands. The implementation follows Junio Hamano's suggested OPT_STRING approach, though that appears in later patches.
