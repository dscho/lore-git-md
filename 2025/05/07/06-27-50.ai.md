This is a policy discussion about Git's `contrib/` directory cleanup, specifically regarding the removal of `git-new-workdir` and the broader implications for how `contrib/` should function.

Patrick distinguishes these as testing interactions rather than validating the script itself. The discussion reveals differing views on `contrib/`'s purpose - whether it carries implicit stability expectations or should be explicitly experimental.

The email proposes rewriting `contrib/README` to formalize a new policy where `contrib/` serves as a temporary home for experimental features that either graduate to core Git or get removed if unmaintained. This would resolve ambiguity around removal criteria and deprecation expectations. The thread shows consensus on removing `git-new-workdir` but needs agreement on whether to establish this as precedent for future `contrib/` maintenance.
