Performance optimization completing a 4-part series to reduce memory usage in packed-refs operations. This final patch replaces `strbuf_read()` with mmap-based file access during `git fsck` operations on large packed-refs files, aligning fsck behavior with the rest of the codebase's memory-efficient approach.

The change builds on two helper functions introduced in earlier patches (`allocate_snapshot_buffer` and `munmap_temporary_snapshot`) to handle buffer allocation and cleanup. The implementation maintains the same mmap strategy selection (including fallback for small files) used elsewhere in packed-backend.c, while eliminating the memory overhead of reading the entire file into a strbuf.

The patch appears well-integrated with the series' architectural changes, completing the transition to consistent mmap usage across all packed-refs operations. It addresses suggestions from Jeff King and Patrick Steinhardt about memory optimization while preserving the existing error handling and cleanup paths. The change is relatively small (20 lines modified) but impactful for repositories with large packed-refs files.
