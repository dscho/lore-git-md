Memory leak fix in parse-options machinery with new OPT_UNKNOWN macro.

This is the consolidated version of a patch series that addresses a memory leak in Git's option parsing when encountering unknown short options. The leak occurs in parse-options.c where memory is allocated for unknown options but never freed. The solution introduces:

1. A new strdup_fn field in struct option that allows callers to provide a custom allocation function for unknown options
2. An OPT_UNKNOWN macro that behaves like OPT_END but includes this allocation function
3. A test helper (test-free-unknown-options.c) demonstrating usage with strvec_push_wrapper

Key technical changes:
- Added parse_opt_strdup_fn callback type and strdup_fn field to struct option
- Modified parse_options_step to use the custom allocator when available
- Implemented set_strdup_fn to extract the callback from the options array
- Added test coverage in t0040-parse-options.sh showing handling of both known (-a, -b) and unknown (-c, -d) options

The implementation maintains backward compatibility while providing a way to properly manage memory for unknown options. The test helper serves both as validation and documentation of the intended usage pattern. This version incorporates feedback from Patrick Steinhardt, including code style improvements and consolidation of earlier patches into a single commit.
