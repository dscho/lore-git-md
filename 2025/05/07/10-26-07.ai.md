This is a follow-up in the discussion about adding trailer-related functionality to `git rebase` and `git am`. Phillip Wood responds to Li Chen's justification for a dedicated `--reviewby` flag by arguing against specialized trailer options, suggesting the general `--trailer` interface should suffice instead.

Phillip makes two key points: First, he views `--signoff` (which `--reviewby` was modeled after) as a historical artifact that might not be added today, implying we shouldn't repeat that pattern. Second, he suggests enhancing the `--trailer` option itself by having it use the committer identity when no value is specified, which would address the convenience need without project-specific flags.

This email moves the discussion toward potentially simplifying the proposal by focusing solely on the flexible `--trailer` approach rather than maintaining parallel code paths. Phillip indicates he'll review the `--trailer` implementation separately, suggesting the technical review will continue but likely with a narrower scope than the original RFC proposed. The thread now has clear disagreement about whether specialized trailer flags provide value versus creating maintenance burden.
