This is the final patch in a series implementing a tri-state maintenance control model for Scalar commands. The patch adds the `--maintenance=<mode>` option to `scalar reconfigure`, completing the consistent implementation across all Scalar repository setup commands.

The patch introduces three maintenance states for `reconfigure`: "enable" (default), "disable", and "keep" (preserve current state). This matches the behavior already implemented for `scalar register` and `scalar clone` in earlier patches. The implementation uses OPT_STRING parsing as suggested by Junio Hamano, with clear error handling for invalid mode values.

Key technical details include:
- Defaults to enabling maintenance (maintenance=1) when no option given
- Uses `toggle_maintenance()` helper with -1 indicating "keep" state
- Updates documentation in scalar.adoc explaining all three modes
- Adds comprehensive test coverage in t9210-scalar.sh verifying:
  - Default enable behavior
  - Explicit disable via --maintenance=disable
  - State preservation via --maintenance=keep
  - Correct subcommand execution via trace2 verification

The patch maintains backward compatibility while providing the new flexibility. It completes the series' goal of giving users and automation precise control over maintenance configuration during repository setup and reconfiguration. The implementation is cleanly integrated with existing Scalar infrastructure and follows the established pattern from the earlier patches in the series.
