Feature patch completing the tri-state maintenance configuration for Scalar commands. This final patch in the v3 series adds the `--maintenance=<mode>` option to `scalar reconfigure`, bringing it in line with the behavior already implemented for `register` and `clone`.

The patch allows users to explicitly control background maintenance when reconfiguring Scalar enlistments, with three options: "enable" (default), "disable", and "keep" (preserve current state). This addresses a limitation where `scalar reconfigure --all` previously forced maintenance to be enabled, which wasn't always desirable in certain environments.

Implementation follows the same OPT_STRING pattern used elsewhere in the series, with thorough test coverage added to verify all three states work correctly. Documentation is updated to explain the new option. The change maintains backward compatibility while providing more flexibility, particularly useful for automation scenarios where maintenance behavior needs to be explicitly controlled.

This completes the series' goal of providing consistent maintenance control across all Scalar repository setup commands, with Junio Hamano's suggested design fully implemented. The patch appears well-tested and follows the established pattern from earlier in the series.
