This is the second patch in a 4-part series optimizing memory usage in the packed-refs backend, focusing on enabling mmap for large packed-refs files during fsck operations. The patch refactors buffer allocation logic by extracting it from `load_contents()` into a new helper function `allocate_snapshot_buffer()`.

The change moves 54-line allocation logic into a reusable function while maintaining the same behavior - it still handles both mmap and read-based approaches depending on file size and mmap strategy. The extraction enables this logic to be reused for fsck operations in later patches, avoiding code repetition. The patch itself is a pure refactoring with no behavior changes.

The implementation follows suggestions from Jeff King and Patrick Steinhardt to improve code organization for the mmap optimization work. The changes are straightforward - the patch simply moves existing well-tested logic into a new function while keeping all the same conditions and error handling. This sets up the foundation for the next patch which will introduce the mmap-based fsck verification.
