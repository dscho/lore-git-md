Thread identity: RFC proposal for `--skip-connectivity-check` option in `git receive-pack`, originating from GitLab's internal transaction management system. 2-patch series now complete with test infrastructure (patch 1) and implementation (patch 2).

Core problem: GitLab's RPC service performs its own connectivity validation through a staging system, making `receive-pack`'s built-in checks redundant. The RFC seeks to optimize this workflow while addressing security concerns about exposing the skip mechanism. The implementation introduces a hidden flag to bypass connectivity validation for specialized cases.

Current status: Complete RFC patches submitted. First patch added comprehensive test coverage for existing connectivity check behavior in `t/t5412-receive-pack.sh`. Second patch implements the `--skip-connectivity-check` option as a hidden flag (OPT_HIDDEN_BOOL) that skips `check_connected()` in `execute_commands()`. Test demonstrates successful push of incomplete pack when check is disabled.

Key technical details:
- New test file t5412-receive-pack.sh with detailed push scenarios (both failure and success cases)
- Global `skip_connectivity_check` flag in `builtin/receive-pack.c`
- Modified `execute_commands()` to conditionally skip connectivity validation
- Option deliberately hidden from normal usage via OPT_HIDDEN_BOOL
- Test positioned between t5411 and t5500 in meson.build
