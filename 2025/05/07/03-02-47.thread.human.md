This RFC thread explores adding a `--skip-connectivity-check` option to `git receive-pack` for GitLab's Gitaly service, which maintains stronger connectivity guarantees than standard Git repositories. The initial proposal included two patches - one for test infrastructure and another for the implementation - with Patrick Steinhardt providing detailed feedback on test organization and error handling.

Justin Tobler has now responded to Patrick's review, agreeing to consolidate the new tests into the existing `t5410-receive-pack-alternates.sh` file rather than creating a separate test file. He also clarifies technical details about how `git-receive-pack` reports connectivity failures (via stdout with a specific "missing necessary objects" message) and plans to update the tests to explicitly verify this output pattern. These changes address Patrick's concerns while maintaining the thread's focus on validating this specialized optimization for GitLab's use case.

Junio Hamano has endorsed the technical approach but emphasized the need for clear documentation about when this optimization is safe to use. The discussion remains focused on ensuring robust test coverage and proper error handling before this GitLab-specific optimization moves forward. Security implications are still being considered, with Jeff King or other security-focused contributors likely to weigh in next.
