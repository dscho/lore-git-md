This thread concerns a finalized 2-patch series adding a `--skip-connectivity-check` option to `git receive-pack` for GitLab's Gitaly service. The implementation itself is approved and ready, but testing has uncovered a Windows+Meson-specific hang in the CI environment when piping output through `tee`. 

Patrick Steinhardt reports the issue occurs consistently in both GitHub and GitLab CI but remains unreproducible locally, suggesting an environment-specific interaction between Windows process handling and Meson builds. The proposed workaround replaces the problematic `tee | git-receive-pack` pipe with wrapper scripts, which resolves the hang though the root cause remains unclear. Johannes Schindelin had previously confirmed the tests pass in Git for Windows' VS-based test environment, indicating this is specific to Meson builds in CI.

The core functionality remains sound, with the hidden flag and corruption warnings intact. Justin Tobler continues investigating why the pipe approach fails only in CI environments, while the team moves forward with the wrapper script solution to unblock the series. Junio Hamano maintains general approval pending resolution of this test infrastructure issue.
