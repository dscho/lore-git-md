This RFC thread proposes a hidden `--skip-connectivity-check` option for `git receive-pack`, primarily for GitLab's Gitaly service which can provide stronger connectivity guarantees than Git's general checks. The discussion has produced a finalized 2-patch series, with Justin Tobler implementing changes based on feedback from Patrick Steinhardt, Karthik Nayak, and Junio Hamano.

The first patch established test infrastructure using a `git send-pack --receive-pack="tee | git-receive-pack"` pattern to verify behavior, while consolidating test files. The second patch (now under discussion) implements the actual connectivity check bypass with safeguards: it's hidden from casual use via OPT_HIDDEN_BOOL, preserves all error paths, and includes thorough test coverage. Recent refinements clarify that the option bypasses both reference connectivity and object existence validation, and the tests now explicitly verify the repository remains unconnected after bypass.

The series has received positive technical review from Karthik Nayak confirming the implementation soundness, with Patrick Steinhardt and Junio Hamano contributing to documentation improvements. While the changes appear technically ready, a final security review from connectivity experts (potentially Jeff King) would be valuable given the sensitive nature of bypassing these checks. The implementation remains tightly scoped to GitLab's specific use case where their transaction system can guarantee connectivity.
