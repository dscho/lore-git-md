This thread concerns a finalized 2-patch series adding a `--skip-connectivity-check` flag to `git receive-pack` for GitLab's Gitaly service. The implementation itself is sound and approved, with a hidden flag that properly documents the corruption risks of bypassing connectivity checks. However, a test case in `t5410-receive-pack.sh` is hanging specifically in GitHub's Windows+Meson CI environment, though it works fine in Git for Windows' VS tests and other platforms.

The test uses a `tee` pipe to verify the connectivity check bypass, and the hang appears to be an environment-specific interaction with process management or pipe handling. Johannes Schindelin confirmed the test passes normally in Git for Windows, while Justin Tobler is investigating the CI-specific issue. The core functionality remains unaffected - this is purely a test infrastructure problem that's holding up finalization of an otherwise approved series. The patch authors and reviewers agree the implementation meets GitLab's needs while maintaining proper safeguards, with the only remaining question being how to handle this Windows+Meson CI quirk.
