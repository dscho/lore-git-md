This RFC thread proposes adding a `--skip-connectivity-check` option to `git receive-pack` to support GitLab's Gitaly service, which maintains stronger connectivity invariants than standard Git repositories. The two-patch series includes test infrastructure and implementation, with the option hidden (OPT_HIDDEN_BOOL) to prevent misuse.

Patrick Steinhardt provided key context about GitLab's architecture, explaining how Gitaly's optimized validation makes the general connectivity checks redundant in their environment. The test case (in a new t5412-receive-pack.sh file) verifies the connectivity check behavior by pushing between repositories with different commit histories. Patrick has since offered constructive feedback on the test methodology, suggesting refinements like error message placement and test organization, though he confirms the test's fundamental validity.

Open questions remain about security implications, test coverage for Gitaly-specific cases, and whether alternative approaches (like environment variables) might be preferable. The discussion is now focused on polishing the test suite before finalizing the implementation. Security-focused contributors like Jeff King may still need to weigh in on the bypass mechanism's safety.
