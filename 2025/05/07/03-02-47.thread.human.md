This RFC thread proposes adding a `--skip-connectivity-check` option to `git receive-pack` to support GitLab's Gitaly service, which can guarantee object connectivity through its transaction system. The two-patch series has evolved through mailing list feedback, with Patrick Steinhardt and Junio Hamano shaping the direction.

The first patch consolidated test infrastructure into `t5410-receive-pack.sh` with enhanced error verification, while this second patch implements the actual connectivity check bypass. The implementation adds a hidden flag that conditionally skips `check_connected()` when external validation exists, as in GitLab's case. Security is a key concern - the option is hidden to prevent misuse, and documentation clearly warns about corruption risks without proper validation.

Justin Tobler has implemented the changes with technical precision, addressing Junio's documentation concerns and maintaining all existing error handling paths. The test suite now verifies both the default behavior and the bypass scenario, using `git send-pack` patterns to validate repository integrity. While the approach has general approval, final security review from connectivity experts like Jeff King remains pending. The solution is specifically framed as a GitLab optimization case, with careful consideration given to long-term maintenance implications of both the feature and test reorganization.
