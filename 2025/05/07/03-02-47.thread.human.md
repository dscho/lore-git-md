This RFC thread proposes adding a `--skip-connectivity-check` option to `git receive-pack`, motivated by GitLab's internal workflow where connectivity validation happens through an external staging system. The two-patch series begins with comprehensive test infrastructure (added in patch 1) that verifies the existing connectivity check behavior, followed by the implementation (patch 2) that introduces the new flag.

The implementation adds a hidden `--skip-connectivity-check` option that skips the critical object graph validation when receiving pushes. While technically sound, the proposal raises significant security questions - the commit message acknowledges the check is normally critical, and the hidden flag suggests this is meant for controlled use rather than direct user invocation. The test demonstrates the expected behavior but doesn't address potential abuse scenarios.

Key open questions center on whether GitLab's specialized use case justifies a core Git change, whether the hidden flag provides sufficient protection, and if alternative configuration approaches (like environment variables) might be preferable. The thread is likely to draw scrutiny from security-conscious reviewers and GitLab-affiliated contributors familiar with their transaction system. The proposal currently lacks any Reviewed-by or Acked-by tags, indicating this is still in early discussion stages.
