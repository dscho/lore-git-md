This is a bugfix patch in the packed-refs backend, addressing fsck behavior for empty packed-refs files. The patch aligns fsck's treatment of empty files with runtime behavior by skipping consistency checks when the file size is zero.

The change modifies packed-backend.c to return an empty snapshot rather than reporting an error when encountering an empty packed-refs file during fsck operations. This matches how the runtime code path already handles such cases. The patch includes test coverage in t0602-reffiles-fsck.sh.

Junio Hamano provided feedback suggesting improvements to both the commit message and title to better highlight the fsck-specific nature of the fix. The author acknowledges this feedback and plans to incorporate it in the next version. The technical implementation itself is confirmed correct by Junio, who notes the change is "trivially correct" and well-found.

This is patch 1/4 in a series focused on optimizing memory usage in the packed-refs backend, particularly around mmap operations during fsck. The series has received thorough review from multiple maintainers (Jeff King, Patrick Steinhardt, and Junio Hamano) with all feedback being addressed. This particular patch appears ready for integration with the suggested documentation improvements.
