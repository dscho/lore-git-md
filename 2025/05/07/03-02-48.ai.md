This is the first patch in a 2-part RFC series proposing a `--skip-connectivity-check` option for `git receive-pack`. The patch adds test coverage for the existing connectivity check behavior that the subsequent patch will make optional.

The new test `t5412-receive-pack.sh` verifies that `receive-pack` correctly fails when receiving a packfile that would leave the repository with missing objects. The test creates a scenario where a client sends commits to a server that lacks the parent objects, then confirms the server rejects the push with an appropriate error message ("Failed to traverse parents") and leaves the repository in a clean state.

The test setup is thorough, using three repositories to simulate the push scenario: a source repo with commits, a bare clone that captures the pack data, and a target repo that attempts to receive the incomplete pack. The test checks both the error output and the repository state to ensure the connectivity check works as expected.

This test will serve as the baseline for verifying the behavior of the subsequent patch that introduces the skip-connectivity-check functionality. The test file is added to the meson build system alongside other receive-pack related tests (t5410, t5411).

Key technical details:
- New test file `t/t5412-receive-pack.sh` with single test case
- Verifies error message "Failed to traverse parents"
- Confirms repository state remains clean after failed push
- Added to meson.build test list between t5411 and t5500

The patch appears well-constructed with a clear test case that exercises the exact behavior the series aims to modify. The test follows Git's standard patterns and includes proper cleanup. This provides a solid foundation for the RFC discussion about whether and how to make this check optional.
