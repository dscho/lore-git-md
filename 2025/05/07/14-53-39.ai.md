This is the first patch in a 4-part series optimizing memory usage in the packed-refs backend, specifically addressing fsck operations. The patch focuses on fixing fsck behavior for empty packed-refs files.

The change modifies `packed-backend.c` to skip consistency checks when encountering a zero-length packed-refs file during fsck, aligning with how runtime code paths already handle this case. The patch adds a simple 3-line check in the verification logic and includes a 13-line test case that creates an empty packed-refs file and verifies fsck doesn't report errors.

Key technical details:
- File modified: `refs/packed-backend.c` (3 lines added to skip empty file checks)
- Test file: `t/t0602-reffiles-fsck.sh` (new test creates empty packed-refs file directly rather than using `touch`)
- Behavior change: fsck now matches runtime behavior by allowing empty packed-refs files

The patch has already gone through review iterations with Junio Hamano, who suggested improvements to the commit message clarity and test implementation. The final version uses direct file creation via `.git/packed-refs` instead of `touch` to avoid misleading timestamp implications. This is part of a larger effort to optimize memory usage during packed-refs operations, with subsequent patches introducing mmap-based approaches for large files.
