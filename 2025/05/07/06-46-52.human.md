Feature discussion response regarding `--reviewby` and `--trailer` options for rebase. Li Chen addresses Junio Hamano's concerns about code duplication and proliferation of trailer-specific flags in their RFC patch series.

The response clarifies two key points: First, that `git-interpret-trailers` currently operates on files/stdin rather than in-memory commits during rebase, making direct reuse difficult for the `--reviewby` implementation which mirrors `--signoff`'s approach. Second, Li argues for keeping `--reviewby` as a dedicated flag (like `--signoff`) for projects that mandate Reviewed-by trailers, noting the convenience over requiring users to create aliases for the generic `--trailer` interface.

The email seeks guidance on whether to proceed with both approaches (keeping `--reviewby` while also implementing `--trailer`) or focus solely on the generic solution. The technical discussion remains open, with the core question being whether Git's CLI should grow specialized trailer flags or push users toward the more flexible but verbose `--trailer` option. The response is thoughtful and addresses the architectural concerns directly while making a practical case for the specialized flag.
