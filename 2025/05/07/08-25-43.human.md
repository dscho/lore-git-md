This is a review response in the ongoing promisor-remote protocol enhancement series, focusing on documentation and implementation details. Patrick Steinhardt raises several thoughtful points about the v2 patch series that aims to make promisor-remote attributes configurable during clone/fetch operations.

Patrick suggests improving the documentation by converting the field list into a more extensible format and making the configuration per-remote rather than global. He questions whether the current single `sendFields` config is too inflexible given that different remotes may need different filters and tokens. The review also requests clarification on field semantics - particularly how partial clone filters and tokens should be interpreted and used by clients.

Several specific documentation nits are noted: abbreviating "field" as "fld" is unnecessarily terse, and the protocol should more clearly define client behavior regarding unknown fields (mandating rather than suggesting they be ignored). The implementation's `allowed_fields` naming is also questioned as potentially misleading since the protocol actually recommends ignoring unknown fields rather than enforcing a strict allowlist.

These comments come after the series has already addressed major protocol design concerns from Junio C Hamano and incorporated Patrick's earlier feedback about field handling strategy. The current focus is on refining documentation clarity and considering future extensibility, suggesting the technical approach is largely settled but some presentation details could be improved.
