This is a discussion about removing the `git-resurrect.sh` script from Git's `contrib/` directory, part of Patrick Steinhardt's ongoing cleanup effort. The script, which helps recover lost branches by searching reflogs, hasn't been touched since its introduction in 2009. While Junio Hamano notes it might still work correctly, he agrees to its removal since few users likely depend on it and manual reflog inspection provides more control.

Patrick suggests a more fundamental solution: keeping reflogs for deleted branches in the reftable backend, which would make branch recovery simpler without needing a special script. This would let users directly query `git reflog show` for deleted branches. The discussion reveals an interesting tension between maintaining niche contrib scripts versus improving core functionality to make them unnecessary. The patch appears uncontroversial, with both parties agreeing the script can go, though Patrick's reflog preservation idea might spark separate discussion about reftable behavior.
