Junio C Hamano provides precise explanation of Git's conventional use of "implies" in documentation, correcting Leon Michalak's interpretation. The maintainer explains that "implies" in Git's documentation specifically means the command behaves as if the implied option was given, not merely that the option requires another to function. He contrasts this with the phrasing "only works with" for cases where an option depends on another being present but doesn't automatically enable it.

The email reinforces the earlier consensus that command-line context overrides (-U/--unified and --inter-hunk-context) must explicitly require -i/-p flags, rather than implicitly enabling interactive mode. This maintains consistency with Git's established documentation patterns and prevents surprising behavior.
