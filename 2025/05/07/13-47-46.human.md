This is a technical discussion about delta chain handling in `git index-pack`, following up on Patrick Steinhardt's recently approved bugfix series. Derrick Stolee clarifies some edge cases around REF_DELTA processing that Taylor Blau raised regarding compatibility with older clients.

The key points are:
1. The original bug occurred when servers sent REF_DELTA chains (A->B->C) where the client unexpectedly already had intermediate object B, causing `index-pack` to incorrectly detect a cycle.
2. Taylor is concerned this might interact poorly with his earlier work converting OFS_DELTAs to REF_DELTAs for pack reuse, particularly for servers supporting older clients.
3. Derrick confirms the risk exists but notes it's mitigated by several factors: cross-pack deltas are rare, bitmap walks reduce negotiation gaps, and very old clients would need to lack OFS_DELTA capability entirely to trigger the worst cases.

The discussion doesn't require any changes to the merged series but surfaces important considerations for future delta optimization work. Derrick provides helpful context about when these edge cases might realistically occur in practice.
