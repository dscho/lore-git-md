This is a feature patch series for Scalar's maintenance configuration, now implementing the tri-state model that was reached as consensus in the thread discussion. The series adds `--maintenance=<mode>` options to `scalar register`, `clone`, and `reconfigure` commands, with modes "enable" (default for register/clone), "disable", and "keep" (default for reconfigure).

The implementation follows Junio Hamano's suggestion to use an OPT_STRING parameter with explicit values rather than the original boolean approach, maintaining backward compatibility while allowing future extensions. The series builds on previous versions that established the basic behavior, with v3 specifically converting the reconfigure option to the new tri-state model.

Key technical changes include:
- Unified `register_dir()` function handling all maintenance states
- Updated documentation in scalar.adoc explaining the new modes
- Expanded test coverage in t9210/t9211 verifying all state transitions
- Maintenance lock file handling preserved across all modes
- Trace2 verification maintained

The patch appears well-constructed with thorough test coverage and clear documentation updates. It resolves the semantic inconsistency in `reconfigure` behavior while meeting all original requirements.
