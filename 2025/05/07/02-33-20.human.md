This is a bugfix series addressing memory leaks and type safety issues in the parse-options code. Lidong Yan proposes three patches to fix:

1. A memory leak in `parse_short_opt()` where `xstrdup()` allocations weren't being freed
2. A case where an `int` was incorrectly used as a boolean
3. A UBSan (undefined behavior sanitizer) failure that's prevented by using a strvec wrapper

The changes are accompanied by a new test helper (`test-free-unknown-options`) and additions to the parse-options test suite. The series appears well-scoped, with each commit addressing a distinct issue in the option parsing code. The inclusion of new test coverage suggests the author has taken care to verify the fixes.

The changes touch core option parsing infrastructure, so they'll need careful review, but the problems being fixed are clear-cut and the solutions straightforward. This looks like a solid maintenance series that should improve code hygiene without introducing new complexity.
