This is a naming discussion in the ongoing `git-blame-tree` RFC thread. Toon Claes responds to Marc Branchaud's concerns about the command name, defending the "blame-tree" choice while remaining open to alternatives.

The exchange reveals two main perspectives: Marc argues the command should either be folded into `git blame` (as a new mode like `--latest`) or given a completely different name to avoid command proliferation. Toon counters that the implementation is too distinct from `git blame` to merge, and that "blame" is an established Git concept users will understand. He cites Jeff King's original rationale for the name, which drew parallels between the tree-level attribution and file-level blame.

While Toon maintains that "blame-tree" works well, he ultimately expresses flexibility, listing several whimsical alternatives (`git last-for-each`, `git when-modified`, etc.) to show he's not wedded to the name. The discussion remains unresolved but good-natured, with both sides acknowledging the importance of naming for usability without letting it block progress on the feature itself.

This email doesn't advance the technical implementation but keeps the naming debate active, suggesting the RFC may need more community input before finalizing this aspect. The core functionality (now performance-optimized and mostly production-ready) appears unaffected by the naming discussion.
