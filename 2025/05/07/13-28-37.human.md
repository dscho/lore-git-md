This is a follow-up discussion in the RFC thread about adding a `--skip-connectivity-check` option to `git receive-pack`. Patrick Steinhardt from GitLab responds to Justin Tobler's initial patch, providing more context about GitLab's specific use case that motivates the change.

The key point is that GitLab's internal architecture (via Gitaly) already performs rigorous connectivity validation through its staging system, making the built-in Git check redundant in their environment. Steinhardt explains that GitLab can safely skip Git's connectivity check because they enforce stronger invariants - all objects in their repositories are guaranteed to be fully connected, and their custom validation process is more efficient for their specific workflow.

The response clarifies the original motivation that was somewhat vague in the patch, addressing why a server-side system might want to bypass Git's built-in safety check. Steinhardt references a previous proposal (linked) that was rejected for general Git usage but makes sense in GitLab's controlled environment. This provides important context for reviewers evaluating whether the proposed hidden flag is justified.

The email doesn't introduce new technical changes to the patch but strengthens the case for it by detailing GitLab's specific requirements and constraints. This information will likely be valuable as the discussion progresses, particularly for reviewers concerned about the implications of bypassing a core safety mechanism.
