This is the fifth version of a feature patch series completing the decomposition of `git gc` functionality into granular maintenance tasks. The series now implements the final two missing operations - worktree pruning and rerere garbage collection - as standalone tasks with configurable auto-execution thresholds.

The v5 iteration makes several refinements:
- Drops the `get_worktree_names()` helper in favor of direct directory operations
- Fixes a memory leak in `worktree_prune_condition()`
- Further simplifies the worktree pruning logic
- Corrects a typo in test documentation ("man" -> "many")

The series maintains six patches:
1. Indentation cleanup in `cmd_gc()`
2. Removal of trivial global variables
3. Refactoring worktree pruning into a standalone function
4. Implementation of the new "worktree-prune" maintenance task
5. Refactoring rerere GC into a standalone function  
6. Implementation of the new "rerere-gc" maintenance task

With all known issues addressed (including the memory leak fix confirmed here), this appears to be the final technical iteration of this long-running effort to fully replace `git gc` with more configurable maintenance tasks. The changes are well-tested and documented, with comprehensive test coverage for both new tasks.

The series represents the culmination of a multi-year decomposition effort, giving users finer control over maintenance operations while maintaining backward compatibility. While not yet switching the default maintenance strategy to use these new tasks, this provides all the plumbing needed for that eventual transition.
