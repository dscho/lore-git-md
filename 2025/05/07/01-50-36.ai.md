Feature patch extending the Scalar clone command with maintenance control options, part of the completed tri-state maintenance configuration series.

This patch adds a `--no-maintenance` option to `scalar clone`, completing the implementation of the tri-state maintenance model across all Scalar commands. The change follows the same pattern established in earlier patches, where maintenance can be explicitly enabled (default for clone), disabled via `--no-maintenance`, or preserved via the "keep" state (used in reconfigure). The implementation modifies the clone command's option parsing to accept the new maintenance flag, passes it through to the shared `register_dir()` function, and updates documentation and tests accordingly.

Key technical details include: the new OPT_BOOL flag for maintenance control in scalar.c; the modified usage string showing the new option; the test case verifying `--no-maintenance` skips maintenance registration; and the updated error message using "toggle" terminology consistent with the tri-state model. The patch maintains backward compatibility while adding the explicit disable path, particularly useful for automation scenarios like VM image preparation where concurrent maintenance could interfere.

The change is well-integrated with the series' existing infrastructure, building on the refactored `register_dir()` from earlier patches. Test coverage is expanded to verify the new state transition, including trace2 verification that maintenance registration is skipped when requested. Documentation updates clearly explain the new option's purpose and default behavior.

This represents the final implementation piece for the agreed-upon design, with all three maintenance states now available across register, clone, and reconfigure commands. The patch maintains the series' careful approach to backward compatibility and consistent user experience while addressing the specific automation use case that motivated the tri-state model.
