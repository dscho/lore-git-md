Refactoring patch in the packed-refs memory optimization series.

This is the third patch in a 4-part series optimizing memory usage in the packed-refs backend, specifically focusing on mmap operations during fsck. The patch extracts munmap logic into a new helper function `munmap_temporary_snapshot()`, addressing feedback from Junio Hamano about making the mmap strategy checks more explicit at call sites rather than embedding them in the helper.

The key changes in this revision:
- Renames the helper from `munmap_snapshot_if_temporary` to `munmap_temporary_snapshot` to better reflect its specific purpose
- Moves the `mmap_strategy == MMAP_TEMPORARY` check to callers rather than the helper itself
- Adds explicit NULL check in the helper function
- Maintains the same core functionality while improving code organization

Junio had raised concerns about the original implementation being an "antipattern" that could cause maintenance issues if new mmap strategies were added. The revised version addresses these by making the strategy check explicit at call sites while keeping the munmap operation itself encapsulated. The patch follows the series' overall goal of improving memory pressure during packed-refs operations while making the code more maintainable.

Technical details:
- File modified: packed-backend.c
- New function: `munmap_temporary_snapshot()`
- Callers now explicitly check `mmap_strategy == MMAP_TEMPORARY` before invoking
- Maintains compatibility with existing MMAP_OK/MMAP_TEMPORARY/MMAP_NONE strategies
- Part of broader effort to optimize fsck operations on large packed-refs files

The patch appears technically sound and incorporates all requested changes from the maintainer. It represents a clear improvement over the initial submission while maintaining the series' optimization goals.
