This is a test patch in a bugfix series addressing file mode handling in `git apply --reverse`. It adds missing test coverage for warning behavior when file modes don't match expectations during patch application.

The patch focuses specifically on testing the warning behavior that was fixed in commit 01aff0a (2023-12-26). It verifies that `git apply` properly warns when applying patches (both forward and reverse) to files whose modes don't match what the patch expects. The test infrastructure is enhanced with new helper functions `test_file_mode_staged()` and `test_file_mode_HEAD()` to consistently check file modes in both the index and HEAD.

Key technical details:
- Tests cover both forward and reverse patch directions
- Verifies warning behavior when executable bit mismatches occur (100644 vs 100755)
- Uses `core.fileMode=false` to ensure tests work on all platforms
- Implements robust test isolation using tags and resets
- Tests both working tree and index states
- The test matrix validates the warning behavior that was previously missing coverage

This is the first of two patches in v3 of the series, building the test infrastructure before applying the actual fix in the next patch. The test design follows feedback from previous iterations, using standardized six-digit modes and improved isolation. The test cases specifically target the warning behavior that would indicate improper mode handling during patch application.
