Bugfix for submodule configuration safety. This is the first patch in a two-part series addressing submodule configuration issues, specifically preventing accidental overwrites when reusing paths.

The patch fixes a case where adding a new submodule at a path that previously hosted another submodule (which was moved but not renamed) could silently overwrite the original submodule's configuration in .gitmodules. The author notes this causes lost configuration and confusion when the original submodule is still expected to exist elsewhere.

The solution adds validation in `module_add()` to check if the computed submodule name already exists in the config. If found, it either errors out (default) or auto-increments the name when `--force` is used. The implementation includes a new test case that verifies the protection works by simulating the problematic scenario.

This appears to be a focused, well-justified change with clear test coverage. The patch touches core submodule management code but keeps the changes contained to the specific issue. Reviewers will likely want to verify the force-mode behavior and edge cases around path handling, but the approach seems sound.
