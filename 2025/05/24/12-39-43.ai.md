Bugfix for git-send-email threading behavior when editing or skipping messages. This patch addresses a specific edge case in the email threading logic where editing or skipping a message (particularly the first one in a series) causes incorrect message numbering and breaks the shallow thread structure.

The core issue stems from how `process_file` increments `$message_num` and `$message_id_serial` on each run, without accounting for message edits or skips. When a user edits a message, the function restarts but continues incrementing these counters, causing the edited message to appear as a new message in the thread rather than a replacement. The patch fixes this by decrementing both counters when either skipping (`n`) or editing (`e`) a message, ensuring the numbering remains consistent.

Key technical details:
- Modifies the `send_message` subroutine in `git-send-email.perl`
- Adjusts both `$message_num` (thread position tracking) and `$message_id_serial` (Message-ID generation)
- Handles both edit and skip cases with counter decrements
- Maintains existing behavior for all other cases (continue sending, quit)

This builds on the ongoing thread discussion about threading behavior but takes a different approach than the previously proposed `$num_sent` solution. The current implementation avoids the batch processing complications raised by Junio C Hamano but may still face scrutiny regarding code clarity and maintainability concerns raised by Jacob Keller, as it introduces new state management logic in the message sending flow.
