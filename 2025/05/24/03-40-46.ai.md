Bugfix for file mode handling in `git apply --reverse` when reversing deletions, now in its third iteration. This patch completes the test coverage for the fix introduced in v1, specifically focusing on mode preservation when reversing file deletions that become creations.

The core change remains a one-line modification in apply.c to include deletion cases (`p->is_delete`) in the mode bit swapping logic. The bulk of this patch adds comprehensive test coverage through two main scenarios:
1. `change_x_to_notx`: Tests executable->non-executable transitions and deletion
2. `change_notx_to_x`: Tests non-executable->executable transitions and deletion

Key test infrastructure improvements include:
- New `test_file_mode_common()` helper that properly handles absent files (000000 mode)
- Consistent use of six-digit octal modes throughout
- Isolated test execution via `git tag` and `git reset --hard`
- Both forward and reverse application testing
- Verification of warning behavior for mode mismatches

The tests validate that `git apply --reverse` correctly preserves file modes when:
- Recreating deleted files (both executable and non-executable)
- Handling mode transitions in both directions
- Operating with `core.fileMode=false`
- This represents the final test coverage expansion for the v1 bugfix, complementing the earlier test improvements in v2. The tests follow the same pattern for both scenarios, verifying mode preservation through the full lifecycle of file creation, mode change, and deletion, then testing both forward reapplication and reverse application of each patch.
