This thread centers on Patrick Steinhardt's ongoing refactoring of Git's object storage layer, an 18-patch series that's part of the larger effort to eliminate the `the_repository` global variable. The work involves significant architectural changes, including renaming core structures like `object_directory` to `odb_alternate` and `raw_object_store` to `object_database`.

The key discussion point has been naming the components in this new model, with debate between `odb_alternate` and `odb_source`. Justin Tobler raised concerns that calling everything an "alternate" could be confusing when the primary storage would technically become an alternate under that naming. Patrick acknowledged the dilemma, noting that while `odb_backend` was considered, it might incorrectly imply a one-to-one relationship.

Junio Hamano has now provided definitive guidance, analyzing the glossary definitions and concluding that while neither term is perfect, `odb_source` is the least problematic option. He notes the current "alternate object database" definition doesn't align well with the new granular storage model, where components like loose and packed objects are treated as separate sources rather than complete databases inheriting from each other. This appears to resolve the last open question blocking the series.

The discussion exemplifies the careful balance required when evolving core architecture while maintaining compatibility with existing documentation and terminology. With Junio's input, the naming question seems settled in favor of `odb_source`, clearing the path for this substantial refactoring to progress.
