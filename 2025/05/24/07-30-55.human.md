This is a bugfix patch for submodule path safety, part of a series that has already seen extensive review (now at v7). The patch prevents `.gitmodules` entries from being silently overwritten when reusing paths from moved submodules.

The core issue occurs when adding a submodule at a path that previously hosted another submodule (e.g., adding a new "child" where an old "child" was moved to "child_old"). Currently Git reuses the path-derived name without checking if it's still in use elsewhere, which can overwrite configuration. The patch adds protection by:
1. Checking for name/path conflicts via `submodule_from_name()`
2. Either erroring out (default) or auto-incrementing names (with `--force`)
3. Adding test coverage in t7400 that verifies the failure case and proper path movement

This is the second and final patch in the series that has already addressed maintainer feedback about test coverage and implementation clarity. The first part (active flag optimization) was merged earlier. The changes are now documented in Git 2.50.0's release notes under "Fixes".

The implementation looks solid with proper memory management (`strbuf` usage, cleanup handlers) and maintains the existing behavior when no conflicts exist. The test case clearly demonstrates the problematic scenario and verifies the new safety check works as intended. Since this is the final version after multiple iterations, it appears ready for inclusion.
