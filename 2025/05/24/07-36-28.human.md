Bugfix for submodule configuration management. This is the second patch in a 2-part series addressing issues with submodule config handling. The first patch prevented config overwrites when moving submodules, while this one tackles redundant active entries.

The patch modifies `configure_added_submodule()` to avoid writing unnecessary `submodule.<name>.active` entries when the submodule's path is already covered by existing `submodule.active` patterns. It introduces a new helper function `submodule_active_matches_path()` that checks for path coverage using wildmatch patterns. The change reduces config file clutter while maintaining the same effective activation state.

Test coverage in `t7413-submodule-is-active.sh` demonstrates the new optimization, showing that a submodule added under a path matching an existing pattern no longer gets an explicit active entry. The implementation appears clean and focused, with clear commit message explaining the motivation and approach. This is a straightforward quality-of-life improvement for submodule users who use path patterns extensively.
