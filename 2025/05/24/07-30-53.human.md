This is a bugfix patch series addressing two submodule configuration safety issues, now in its 7th iteration. The patches build on previous work that was already partially accepted, with this version making minor formatting adjustments to test cases (converting 4-space indents to tabs) as the final step before merging.

The series tackles two distinct but related problems in submodule handling: First, it prevents accidental overwrites when adding a new submodule at a path previously used by a moved submodule, now requiring explicit `--force` to allow such cases (which then auto-increments names like foo2, foo3). Second, it optimizes submodule configuration by skipping redundant `submodule.<name>.active=true` entries when the path already matches existing `submodule.active` patterns.

The implementation has undergone thorough review, with maintainer Junio Hamano guiding the separation of concerns and test coverage expansion. The current version appears ready for merging, with only minor documentation updates remaining as non-blocking follow-up work. The changes are well-tested in t7400-submodule-basic.sh and demonstrate Git's careful approach to configuration safety and optimization.
