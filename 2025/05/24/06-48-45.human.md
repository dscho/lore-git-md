This is a bugfix and optimization patch series for submodule handling, now in its 6th iteration. The two patches address distinct but related issues in submodule configuration:

1. The first patch fixes a bug where moving a submodule and then adding a new one at the same path could silently overwrite the original submodule's configuration. It adds protection by detecting path/name mismatches and requiring `--force` with sequential naming (foo, foo2, foo3) for such cases.

2. The second patch optimizes submodule activation by avoiding redundant `submodule.<name>.active=true` writes when the path already matches existing `submodule.active` patterns.

The series has already received technical approval through several rounds of review, with maintainer Junio Hamano now focusing on final polish items: clearer separation of concerns between the two changes, additional test coverage for the optimization behavior, and better documentation of what constitutes "redundant" config entries. The author maintains that the current implementation structure is sound and that existing tests already cover the key behaviors.

This represents the final stretch of review for functionality that improves both safety (preventing accidental configuration overwrites) and efficiency (reducing unnecessary config bloat) in submodule handling. The patches touch core submodule helper code and add tests in t7400 and t7413.
