Bugfix for `git apply --reverse` file mode handling, part of a v3 series addressing executable bit preservation when reversing deletions. This second patch focuses on test coverage expansion.

The core fix (in patch 1/2) was a one-line change to ensure mode bits are preserved when reversing a deletion (which becomes a creation). This follow-up patch adds comprehensive tests covering all combinations of file mode transitions (executable<->non-executable) in both forward and reverse application, with special attention to the deletion->creation case that was previously broken.

The test infrastructure is notably robust, with:
- New helpers to verify file modes in various states (working tree, index, HEAD)
- Complete coverage of mode transitions (100644<->100755)
- Both forward and reverse patch application scenarios
- Core.fileMode=true/false testing
- Proper handling of absent files (000000 mode)
- Clear "undo"/"redo" labeling for test cases

The tests demonstrate the fix works while also serving as regression protection. The series has gone through multiple rounds of review with all feedback addressed, and appears ready for merging with this final test coverage expansion.
