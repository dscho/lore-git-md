This thread explores two approaches to handling whitespace in Git's notes editor templates. The original issue identified trailing whitespace on indented commit message lines, which Kristoffer Haugsbakk addressed with a focused fix in `builtin/notes.c` using `strbuf_stripspace()`. The solution was thoroughly reviewed, with Eric Sunshine validating the POSIX-compliant test patterns and Phillip Wood suggesting structural improvements.

While the technical implementation reached consensus, Junio Hamano raised philosophical questions about whether removing the whitespace was actually desirable, suggesting it might serve as useful visual markers. He has now followed up with a more architectural alternative that would modify the pretty-printing subsystem (`pretty.c`) to handle empty line indentation generically through new `--[no-]indent-empty-lines` options. This proof-of-concept touches 7 files but remains incomplete, lacking tests and documentation.

Junio acknowledges this broader approach may not be worth the complexity, particularly for commands like `git log` where there's no user demand for such control. The discussion has clarified that while the pretty-print solution is technically feasible, the original focused fix in `notes.c` remains the more practical path forward. All technical concerns about the current implementation have been resolved, and the thread appears to be concluding with the understanding that the simpler solution will proceed while keeping the architectural alternative as a possible future direction.
