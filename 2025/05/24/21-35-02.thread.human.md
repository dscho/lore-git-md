This thread addresses a bugfix for Git's notes functionality where editor templates contained trailing whitespace on indented commit message lines. Kristoffer Haugsbakk initially proposed modifying `write_commented_object()` in `builtin/notes.c` to use `strbuf_stripspace()` on the raw message buffer, with Phillip Wood reviewing and suggesting structural improvements to operate on the raw buffer rather than the commented one.

Junio Hamano has now weighed in, confirming the technical soundness of the approach and the POSIX compliance of the test patterns. However, he raises broader questions about whether the change is actually desirable, suggesting the indented whitespace might serve as useful visual markers in editor templates. He proposes alternative solutions that would address the root cause differently - either by fixing editors that complain about trailing whitespace or modifying `git show`'s output formatting to avoid indenting empty lines.

While the technical implementation is now fully resolved with consensus on the approach, Junio's comments introduce philosophical considerations about the change's purpose. The patch remains technically ready for merging, but the discussion has expanded to consider whether this is the right solution to the underlying issue. No concrete objections to the current implementation have been raised, but the maintainer's perspective suggests there may be more fundamental questions worth exploring about how Git handles whitespace in these contexts.
