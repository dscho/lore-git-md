Bugfix for file mode handling in `git apply --reverse` when reversing deletions of executable files, now in its third version. This series addresses the issue where reversing a deletion (which becomes a creation) wasn't properly transferring mode bits from patch metadata to the new file. The core fix remains a one-line change in apply.c to include deletion cases in mode preservation, but the test infrastructure has seen significant refinement.

Key changes in v3:
- Test helper `test_file_mode_common()` now properly handles absent files (000000 mode) and uses full 6-digit modes consistently
- Test setup now uses `git tag` and `git reset --hard` for better isolation between test segments
- File creation uses `>f` instead of `touch f` for consistency
- Test cases are more clearly labeled with "undo"/"redo" in commit messages
- Added tags at key checkpoints (`mode_test_forward_initial`, `change_x_to_notx_initial`, etc.) to make test execution order-independent

The test matrix remains comprehensive, covering:
- Both executable->non-executable and non-executable->executable transitions
- Forward and reverse patch application
- Core.fileMode=true/false scenarios
- Working tree vs index states
- Warning behavior for mode mismatches

All feedback from v2 has been addressed, including Junio Hamano's suggestions about test isolation and Mark Mentovai's input on mode representation. The series appears technically sound with robust test coverage and is likely ready for merging. The changes since v2 are primarily test infrastructure improvements rather than modifications to the core fix.
