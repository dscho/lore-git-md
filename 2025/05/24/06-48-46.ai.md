This is the first patch in a 2-part series addressing submodule configuration safety, specifically focusing on preventing silent overwrites when reusing paths for submodules. The patch introduces path reuse protection in `module_add()` to avoid losing existing submodule configurations.

The core change adds a check in `builtin/submodule--helper.c` that verifies if a submodule name derived from the path is already in use elsewhere in the repository. When a conflict is detected, it either:
1. Fails with an error message (default behavior)
2. Auto-increments the name (foo, foo2, foo3) when `--force` is used

The implementation uses `submodule_from_name()` to detect name/path mismatches and employs `strbuf` management for handling path collisions. A new test case in t7400-submodule-basic.sh verifies the behavior by:
- Creating a submodule
- Moving it to a new path
- Attempting to add a different submodule at the original path
- Confirming the operation fails without `--force`

This addresses a real pain point where Git would silently overwrite `.gitmodules` entries when reusing paths, potentially losing user configuration. The patch is well-structured with proper memory management (freeing allocated resources) and includes clear test coverage for the new behavior.
