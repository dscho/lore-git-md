This is a bugfix patch series targeting submodule handling, specifically addressing two distinct but related issues in submodule configuration management.

The first patch fixes a case where moving a submodule and then adding a new one at the same path could incorrectly overwrite the moved submodule's configuration. The issue occurs because the code only checks path matches without considering the submodule's origin. The fix adds validation to prevent this overwrite scenario while maintaining the moved submodule's configuration.

The second patch optimizes submodule activation by avoiding redundant `submodule.<name>.active` entries when the submodule's path is already covered by existing `submodule.active` patterns. This prevents configuration bloat while maintaining the same effective activation state.

The changes are focused in `builtin/submodule--helper.c` with supporting test cases added to verify both fixes. The test coverage appears thorough, with new cases in both basic submodule tests and the active-submodule-specific test suite. The commit messages clearly explain the problems and solutions, though they could benefit from more detailed examples of the problematic scenarios.

Key technical details for future reference:
- Adds `is_submodule_active_in_path()` helper function to centralize active-path checking
- Modifies `configure_added_submodule()` to skip redundant active entries
- Introduces path validation in submodule movement handling
- Test cases cover both path collision and redundant activation scenarios
- Touches core submodule configuration management logic

The changes seem well-contained and address clear bugs, though reviewers might want to verify the interaction between these fixes and other submodule operations like recursive submodule handling.
