This is a bugfix patch series (v3) addressing file mode handling in `git apply --reverse` when reversing deletions of executable files. The issue stems from commit 01aff0a which missed preserving mode bits when reversing deletions (which become creations).

The series consists of two well-tested patches:
1. A test verifying `git apply` warns for unexpected mode changes, now with improved coverage for core.fileMode=false cases and better test isolation
2. The main fix plus comprehensive tests for mode handling during file creation/modification/deletion

Key improvements in v3:
- Fixed test helper to properly handle absent files (000000 mode)
- Added tags and `git reset --hard` between tests for better isolation
- Standardized on 6-digit mode representations (000755/000644)
- Minor style cleanups

The tests now cover all combinations of:
- File creation, modification, and deletion
- Executable<->non-executable transitions
- Both forward and reverse patch application
- Core.fileMode=true/false scenarios
- Working tree vs index states
