This is the second patch in a 2-part series addressing submodule configuration safety, specifically preventing silent overwrites when reusing paths for new submodules. The series has gone through 7 iterations and is now being included in Git 2.50.0.

The patch modifies `module_add()` in `builtin/submodule--helper.c` to detect when a submodule name derived from the path (like 'child') is already in use elsewhere in the repository (e.g. if the original was moved to 'child_old'). Without this check, adding a new submodule at the original path would silently overwrite the old submodule configuration. The new behavior either fails with an error (default) or auto-increments the name (foo, foo2, foo3) when `--force` is used.

Key implementation details:
- Uses `submodule_from_name()` to check for existing submodule names
- Implements auto-increment naming via `strbuf` when `--force` is specified
- Adds test coverage in t7400-submodule-basic.sh that verifies:
  - Basic submodule creation and movement
  - Path conflict detection
  - Proper failure when attempting to reuse names
  - Does not test the `--force` auto-increment behavior (covered in other tests)

This completes the path safety portion of the series, which has already been merged. The companion patch (1/2) handled active flag optimization. Both changes are now documented in the Git 2.50.0 release notes under "Fixes". The implementation addresses all maintainer feedback from previous iterations regarding test coverage and conceptual separation of concerns.
