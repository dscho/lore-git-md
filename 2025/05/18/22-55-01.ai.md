Feature proposal for `git diff` command flags. This email proposes introducing a new `--index` flag to `git diff` as an alternative to the existing `--cached` flag, with the intent to eventually deprecate `--cached`. The author argues that `--index` would be more intuitive since it directly references the index/staging area that the flag operates on, rather than the more obscure "cached" terminology. 

The patch modifies the diff.c file to add the new flag while maintaining backward compatibility with `--cached`. Key technical details include: adding the `--index` option to the diff_options struct, updating documentation in Documentation/diff-options.txt, and adjusting the builtin/diff.c logic to handle both flags equivalently. The change is relatively small (about 20 lines of code) and comes with corresponding test updates in t/t4013-diff-various.sh.

This appears to be a well-motivated change that follows Git's pattern of providing more intuitive aliases for historical terminology (like `git restore` vs `git checkout`). The implementation looks clean and maintains backward compatibility. However, the proposal may spark discussion about whether this change is worth the churn given that `--cached` is widely used in existing documentation and scripts. The patch doesn't address potential impacts on scripts/tutorials that use `--cached`, which could be a point of contention in the review.
