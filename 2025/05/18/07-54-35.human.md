Bugfix for submodule configuration handling, addressing two related issues in the `git submodule add` command. This is version 5 of a patch that has seen extensive review and refinement.

The first part of the patch prevents redundant configuration entries by avoiding writing `submodule.<name>.active = true` when the submodule path is already covered by a pattern in `submodule.active`. This cleans up unnecessary config clutter when using pattern-based activation.

The second and more significant change prevents dangerous path reuse scenarios where adding a submodule at a path that previously hosted another submodule could silently overwrite `.gitmodules` entries. The new behavior:
- Errors out by default when detecting a name/path mismatch
- When `--force` is specified, generates unique numbered names (foo, foo1, foo2) to avoid conflicts
- Includes comprehensive tests verifying the error behavior and forced naming scheme

This builds on previous versions of the patch that were refined based on maintainer feedback, now properly handling submodule activation states and following Git's memory management patterns. The implementation is focused in `builtin/submodule--helper.c` with new test cases in t7400.
