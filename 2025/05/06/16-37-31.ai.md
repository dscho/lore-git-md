This is a follow-up discussion about the interactive "context" subcommand patch in the diff context control series. The conversation focuses on UI design considerations for the interactive menu layout and command entry methods.

Junio C Hamano responds to Eric Sunshine's review of the patch, which proposed moving the new "context" command to the end of the menu to preserve muscle memory for existing users. Junio notes that the colored first-letter shortcuts (like 's' for status) are already the preferred input method, suggesting the documentation example should show letter input rather than numbers. He also shares Eric's concern about cluttering the main menu with configuration commands.

The discussion explores alternative UI approaches: either grouping settings under a "settings" submenu (though noting 's' is already taken by "status"), or allowing command-specific parameters in the prompt (e.g., "r -U7" to set context during revert). These alternatives aim to maintain the clean action-oriented main menu while providing flexible context control.

The exchange reveals ongoing tension between preserving established UI patterns and adding new functionality, with both reviewers favoring solutions that minimize disruption to existing workflows. The technical implementation of context control (established in earlier patches) isn't questioned - the focus is purely on user interaction design.
