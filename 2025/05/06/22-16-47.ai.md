This is a design discussion email in the Scalar maintenance configuration series, specifically about the proposed tri-state model for maintenance control.

Junio Hamano responds to Derrick Stolee's suggestion of replacing the current `--no-maintenance` boolean flag with a more expressive `--maintenance=<option>` interface. Hamano strongly agrees that the tri-state model ("enable", "disable", "keep") makes sense and would resolve ambiguity, particularly for the `reconfigure` command where the current boolean approach is less clear.

Hamano notes that while the tri-state approach is clearly better for `reconfigure`, a simple boolean would suffice if not for that command. He also suggests an alternative implementation approach using OPT_BOOL with a -1 sentinel value to represent the "keep" state, which would maintain backward compatibility while allowing different defaults per command (enable for `clone`/`register`, leave-as-is for `reconfigure`). He acknowledges this might make future changes harder but would be simpler for users.

The email indicates general agreement with Stolee's proposal while offering implementation alternatives. This moves the thread closer to consensus on adopting the tri-state model, with remaining questions being primarily about implementation details rather than the fundamental design. The discussion remains focused on maintaining all existing technical requirements while improving the semantic clarity of the interface.
