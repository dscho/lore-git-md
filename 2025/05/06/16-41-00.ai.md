This is the first patch in a 4-part series addressing memory usage and behavior in the packed-refs backend. It's a bugfix that aligns error reporting with runtime behavior for empty packed-refs files.

The patch fixes an inconsistency where Git would correctly handle empty packed-refs files at runtime (returning an empty snapshot) but incorrectly report an error when checking consistency during fsck operations. The change modifies packed-backend.c to skip consistency checks for zero-length files, matching the runtime behavior in load_contents().

The implementation adds a simple size check before reading the file contents, plus a new test case in t0602-reffiles-fsck.sh that verifies no error is reported for empty packed-refs file. The test creates a repository, touches an empty packed-refs file, and confirms `git refs verify` produces no error output.

This appears to be a straightforward, well-contained fix that addresses a clear inconsistency. The patch is small (3 lines of code + 13 lines of test) and focused, with test coverage demonstrating the changed behavior. As the first step in a larger series about packed-refs handling, it cleanly separates this behavioral fix from the subsequent refactoring and mmap-related changes.
