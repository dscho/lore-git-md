This is a follow-up discussion about removing the `remotes2config.sh` contrib script, part of Patrick Steinhardt's completed series to clean up Git's `contrib/` directory. Junio Hamano agrees with the removal but notes timing considerations.

The script in question was created in 2007 to migrate remote configurations from the old `.git/branches/` and `.git/remotes/` format to config-based remotes. However, as Patrick points out, Git's `remote rename` command now handles this migration natively, making the script obsolete. The script hasn't been modified since 2007, further supporting its removal.

Junio concurs with the removal but suggests waiting until Git 3.0 when the related breaking changes (removal of the old directory-based remote configuration) will be implemented. He also notes that a script's age alone doesn't necessarily indicate it should be removed - what matters more is whether its functionality has been properly superseded, which in this case it has.

This exchange confirms the script's removal is appropriate but coordinates the timing of Git's broader compatibility changes. The discussion is brief and technical, with both parties in agreement about the eventual outcome.
