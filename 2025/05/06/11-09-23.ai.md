This is part 10/17 of Patrick Steinhardt's series refactoring the object database subsystem to remove `the_repository` dependencies, continuing the broader `the_repository` removal effort.

The patch focuses on two functions that manage temporary primary object database backends: `set_temporary_primary_odb()` and `restore_primary_odb()`. These functions previously relied on the global `the_repository` variable. The changes:

1. Rename the functions to follow the established naming pattern:
   - `set_temporary_primary_odb()` -> `odb_set_temporary_primary_backend()`
   - `restore_primary_odb()` -> `odb_restore_primary_backend()`

2. Modify both functions to take an explicit `struct object_database*` parameter instead of implicitly using `the_repository->objects`.

3. Update all callers in `tmp-objdir.c` to pass the repository's ODB explicitly through `t->repo->objects`.

The changes are mechanical but important for establishing proper ODB boundaries. The temporary ODB handling is used in scenarios like:
- Object quarantine during fetches/pushes
- Temporary object storage during operations like `git commit-graph write`
- Migration of temporary object directories

Key technical details for future reference:
- The `tmp_objdir` struct now stores the repository's ODB explicitly
- The `will_destroy` flag behavior is preserved (used to mark temporary ODBs for cleanup)
- BUG() checks remain for safety (mismatched paths, invalid state transitions)
- All temporary ODB operations now flow through the explicit ODB` parameter

This continues the series' pattern of methodically eliminating `the_repository` dependencies while maintaining existing behavior. The changes appear straightforward but reviewers should verify the temporary ODB handling remains correct in all scenarios, particularly during error cases and repository teardown.
