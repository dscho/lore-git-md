This thread investigates a long-standing bug where `git pull --rebase` unexpectedly drops commits after changing a repository's remote URL. The issue was first reported by Bill, who demonstrated a reproducible case where commits F-G disappeared when rebasing after switching remotes. D. Ben Knoble's bisect revealed this behavior has existed since Git 2.0.

Tuomas Ahola later discovered related anomalies in `git merge-base --fork-point` when changing remote URLs, showing inconsistent results between identically-configured remotes. This is significant because fork-point calculations are used internally by `git pull --rebase`. The thread now has two confirmed technical manifestations of remote URL change problems: the original commit-dropping behavior and fork-point inconsistencies.

While the core investigation continues, a tangential build system issue regarding macOS compilation (related to commit 1ee85f0e21) has been resolved. Torsten Bögershausen provided a fix in branch `tb/macos-false-but-the-compiler-does-not-know-it-fix`, which D. Ben Knoble confirms works correctly. This side discussion doesn't affect the main investigation into the rebase and fork-point behaviors.

The key open question remains whether these are two symptoms of the same root cause in remote tracking logic or separate bugs. Both the original reporter and new contributors remain engaged in testing and analysis.
