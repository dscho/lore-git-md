This is a follow-up discussion in the reftable test modernization thread, specifically about Git diff configuration for reviewing test conversions.

The email clarifies the interpretation of Git's `-M` (rename detection) threshold values after some initial confusion between Patrick Steinhardt and Junio Hamano. Junio confirms that `-M<number>` without a percent sign is interpreted as a fraction where the number` is divided by 10^digits (so `-M90` = 90/100 = 90%, same as `-M90%`, while `-M5` = 5/10 = 50%). 

The key takeaways are:
1. For reviewing test conversions, lower similarity thresholds (like `-M90%`) are actually more useful than higher ones, as they help reject marginal rename detections that might obscure real changes.
2. The documentation could be clearer about the numeric interpretation rules.
3. This discussion emerged from the practical need to review test file conversions in the reftable modernization series.

The thread has now resolved all technical questions about both the test conversions and the review methodology, with Junio providing authoritative clarification on Git diff behavior that may inform future project documentation or review guidelines.
