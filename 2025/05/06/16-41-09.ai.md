This is the second patch in a refactoring series preparing for mmap usage in packed-refs fsck operations. The patch extracts the buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()`, making the code more modular and reusable.

The change moves 32 lines of buffer allocation logic (handling both mmap and read-based approaches) into a standalone function while maintaining identical behavior. This refactoring enables future patches to reuse this allocation logic without file opening operations, which is needed for fsck consistency checks. The patch touches only packed-backend.c, modifying 54 lines with a net +10/-0 change after the refactoring.

Key technical details include:
- New `allocate_snapshot_buffer()` takes fd and stat struct rather than opening files itself
- Preserves all existing behavior around mmap strategy selection (MMAP_NONE fallback, small file threshold)
- Maintains error handling for read/mmap operations
- Returns boolean indicating whether allocation occurred (matching original `load_contents()` semantics)

The change is cleanly separated from behavior modifications, focusing solely on code organization. It follows suggestions from Jeff King and Patrick Steinhardt to enable the mmap optimization work while keeping the change reviewable. The extracted function will be used in patch 4/4 to implement mmap-based fsck operations.
