This is a review comment on an RFC patch proposing a new `--reviewby` option for `git rebase` and `git am`. Junio C. Hamano raises two main concerns about the proposed feature:

First, he questions whether the implementation should leverage Git's existing trailer machinery (from `interpret-trailers`) rather than creating new dedicated logic, noting this would handle edge cases like duplicate trailers more robustly. This suggests the current patch may be reinventing functionality that already exists elsewhere in the codebase.

Second, he expresses skepticism about the approach of adding dedicated flags for specific trailer types (like `--reviewby`), pointing out this could lead to proliferation of similar options (`--helped-by`, `--acked-by`, etc.). This critique may impact the design direction of the entire series, as the second patch proposes a more general `--trailer` option.

The feedback indicates the maintainer sees potential architectural issues with the current approach, particularly around code reuse and scalability of the interface. These comments will likely shape the next revision of the series, possibly pushing toward either greater integration with `interpret-trailers` or consolidation around the more flexible `--trailer` approach.
