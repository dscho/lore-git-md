Feature addition for `git rebase`'s merge backend, implementing a `--trailer` option to append custom trailers to rebased commits. This is the second patch in Li Chen's RFC series, complementing the earlier `--reviewby` proposal.

The implementation adds a new `--trailer` option that accepts arbitrary trailer lines (like `Reviewed-by: Dev <dev@example.com>`) and appends them to each rebased commit message using the existing trailer infrastructure. The patch explicitly rejects use with the apply backend (`git am`) due to its lack of message filtering support, forcing users to the merge/interactive backends. When trailers are specified, rebase automatically enables `--force-rebase` to ensure trailers are added even to fast-forwardable commits.

Key technical details include: new state tracking for trailers in the rebase-merge directory, integration with the sequencer's replay_opts struct, and modifications to builtin/rebase.c to handle the new option. The 108-line test script t3440-rebase-trailer.sh verifies behavior across various scenarios including conflict resolution, --exec, and --root cases, while ensuring the apply backend fails cleanly.

The patch appears thorough with comprehensive test coverage, though the implementation duplicates some trailer-handling logic between rebase.c and sequencer.c. This builds on the thread's earlier discussion about whether dedicated flags like `--reviewby` are preferable to the more flexible `--trailer` approach. The apply backend limitation may be a design tradeoff worth discussing further.
