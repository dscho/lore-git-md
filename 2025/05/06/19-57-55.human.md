This is the final patch in Patrick Steinhardt's series cleaning up Git's `contrib/` directory, removing the obsolete `git-new-workdir` script. The script, which predates `git worktree`, creates separate working directories but has been functionally replaced by core Git's worktree support.

Junio Hamano confirms he still uses one legacy workdir created with this script but doesn't object to its removal, noting even he no longer creates new ones this way. However, he raises a new concern upon seeing the patch's test deletions - several test scripts appear to depend on `contrib/` functionality. This wasn't previously discussed in the series.

Hamano suggests this might warrant the same `WITH_BREAKING_CHANGES` transition approach used for other removals in the series, where breaking changes are deferred until Git 3.0. This introduces a new consideration for the removal that wasn't part of the original series discussion, potentially requiring adjustments to the patch's timing or implementation.

The exchange highlights how even seemingly straightforward cleanups can uncover unexpected dependencies, especially in test infrastructure. While the technical justification for removal remains sound (core Git provides better alternatives), the discovery of test dependencies may require revisiting the implementation approach.
