This is patch 4/17 in Patrick Steinhardt's series refactoring the object database subsystem as part of the `the_repository` removal effort. The patch introduces parent pointers between object databases and their owning repositories, as well as between ODB backends and their owning object databases.

The change enables future patches to access repository configuration when needed while removing direct dependencies on `the_repository`. The implementation requires modifying how alternate ODB entries are linked, passing through the object database explicitly rather than getting it from `the_repository`. The patch updates several functions in odb.c to handle the new parent pointer relationships while maintaining existing behavior.

The changes are mechanical but touch core ODB operations like alternate handling and temporary ODB setup. The patch follows the series' pattern of structural changes that enable future pluggable backends while maintaining current functionality. Reviewers should pay particular attention to the alternate ODB handling changes, which could impact submodule and alternate repository cases.
