This is a technical follow-up in the `git send-email` validation improvement series, specifically addressing domain name validation issues. Aditya Garg clarifies that the double-dot issue stems from `Net::Domain` behavior on systems without configured domain names (not macOS-specific as previously speculated), where it outputs malformed "hostname.." strings. He notes this was previously masked by Gmail's leniency but is now exposed by Outlook's stricter validation.

The discussion reveals the current regex already handles consecutive dots per RFC standards, though there's an open question about whether it should also reject domain segments starting/ending with dashes (like "someone.-example.com"). Garg suggests holding off on that refinement until the broader validation approach is settled. The exchange shows good technical depth in understanding both the RFC requirements and real-world system behaviors, with maintainer Junio Hamano previously advocating for clear, explainable validation rules. This patch appears well-grounded in standards compliance while remaining pragmatic about actual deployment scenarios.
