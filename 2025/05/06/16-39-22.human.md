This is a patch series addressing memory usage and behavior consistency in the packed-refs backend. The series follows up on a previous discussion about using mmap for large packed-refs files to reduce memory consumption.

The first patch fixes an inconsistency where Git would report an error for empty packed-refs files despite them being valid. The next three patches refactor the code to extract helper functions for snapshot allocation and mmap operations, then apply these to make the fsck code use mmap when appropriate.

The changes touch core refs handling code and include test updates. The series appears well-motivated by prior discussion and addresses both a bug (the empty file handling) and a performance optimization (mmap usage). The author credits Peff and Patrick for suggestions on the approach.

The patches modify `refs/packed-backend.c` and add tests in `t/t0602-reffiles-fsck.sh`, showing good test coverage for the changes. The refactoring looks like a solid step toward more consistent and memory-efficient packed-refs handling.
