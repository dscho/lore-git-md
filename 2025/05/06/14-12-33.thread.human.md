This thread documents Patrick Steinhardt's systematic effort to clean up Git's `contrib/` directory, transitioning from a "batteries included" approach to focused maintenance. The discussion has progressed through several phases: first removing specific unmaintained scripts like `mw-to-git` (with author confirmation), `remotes2config.sh` (as obsolete), and `git-resurrect.sh` (replaced by native `git reflog` functionality), then moving toward establishing formal policy.

Maintainer Junio Hamano has consistently supported this effort, approving each removal and now encouraging Patrick to draft a new `contrib/README` policy document. Kristoffer Haugsbakk contributed valuable empirical data showing StackOverflow users overwhelmingly prefer core Git tools (3029 votes) over contrib scripts like `git-resurrect.sh` (16 votes), strengthening the case for removal when better alternatives exist.

The latest update confirms Patrick will proceed with drafting the policy document, using the concrete examples from previous removals as a foundation. This shifts the thread's focus from evaluating individual scripts to establishing guidelines for future maintenance decisions. The policy will likely codify patterns already demonstrated: requiring author confirmation for abandoned scripts, preferring core Git functionality when available, and considering user preference data. The `git-new-workdir` removal serves as another data point informing this emerging policy framework.
