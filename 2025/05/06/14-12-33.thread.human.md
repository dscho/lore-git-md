Patrick Steinhardt continues his systematic cleanup of Git's `contrib/` directory, now turning to the "hooks" subdirectory in the fifth patch of an 11-part series. This latest removal targets several example hook scripts that have either fallen into disuse or been superseded by better alternatives. The deleted hooks include the long-unmaintained `post-receive-email` (last updated in 2007, with git-multimail now being the recommended replacement), `pre-auto-gc-battery`, `setgitperms.perl`, and the complex `update-paranoid` ACL system - totaling 1443 lines removed across five files.

The thread has evolved from individual component removals to establishing clear patterns for when and how to remove contrib content. This hooks cleanup follows the established criteria: scripts are removed if they're broken, haven't been updated in over five years, or have clear alternatives. Patrick notes that if Git wants to provide hook examples, they should be properly documented (like in githooks(5)) rather than left as unmaintained scripts. 

Junio Hamano has previously validated this approach, and Kristoffer Haugsbakk contributed empirical data about user preferences. The series is building toward formal policy documentation in `contrib/README`, with open questions remaining about whether to create a separate `tools/` directory for development utilities and how to best handle historical preservation versus maintenance burden. The hooks removal represents another category of contrib content - example scripts that have either bitrotted or been superseded by better approaches - adding to the growing set of patterns being established for the directory's future.
