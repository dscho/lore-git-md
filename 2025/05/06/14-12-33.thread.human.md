This thread continues Patrick Steinhardt's effort to systematically clean up Git's `contrib/` directory by removing obsolete or unmaintained components. The series began by removing a 17-year-old migration script (`remotes2config.sh`) and some Mercurial/Bazaar remote helper stubs that had been redirecting users to external implementations for a decade.

The latest patch targets the "thunderbird-patch-inline" directory, which contained a script and README for integrating patch sending with Thunderbird via the ExternalEditor extension. This setup appears effectively abandoned - the script hasn't seen meaningful maintenance, and its required extension hasn't been updated since 2008 (with a fork last updated in 2020). The 55-line shell script handled patch metadata extraction and reformatting, depending on the zenity GUI toolkit. Like the previous removals, this doesn't change core Git functionality but continues the pattern of removing clearly obsolete components.

So far, the series has removed three categories of content: a deprecated migration tool, documentation redirects for external VCS helpers, and now an abandoned Thunderbird integration script. The removals follow consistent criteria - targeting components that are broken, unmaintained, or obsolete. No objections have been raised to the specific removals yet, though broader questions about `contrib/` maintenance standards may emerge as the series progresses through the remaining seven components. The work draws inspiration from the Linux kernel's staging drivers model for managing such semi-official contributions.
