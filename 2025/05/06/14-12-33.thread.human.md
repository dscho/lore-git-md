This thread continues Patrick Steinhardt's systematic cleanup of Git's `contrib/` directory, now focusing on `git-contacts` as the latest candidate for removal. The tool meets all three established criteria - it's effectively unmaintained, has a better alternative (`git-related`), and isn't core Git functionality. 

Eric Sunshine provides important historical context, revealing he originally ported `git-related` from Ruby for inclusion in contrib before it became a standalone project. His research shows minimal real-world usage of `git-contacts` beyond Git's own documentation references. The discussion has surfaced one practical consideration: the tool appears in `MyFirstContribution.adoc` and `SubmittingPatches`, though recent updates already clarify it's not part of core Git. 

With no new objections raised and Junio Hamano's prior approval of the cleanup approach, the thread appears to be converging on removing `git-contacts` after addressing the documentation updates. This follows the same pattern as previous `contrib/` removals where better-maintained alternatives exist outside the Git tree. The only remaining work appears to be coordinating the documentation changes to avoid confusion for new contributors.
