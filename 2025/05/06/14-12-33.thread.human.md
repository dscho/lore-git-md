This thread documents Patrick Steinhardt's systematic cleanup of Git's `contrib/` directory, removing broken, unmaintained, or obsolete components. The series has already identified ten such items for removal, including outdated scripts like `git-resurrect.sh`, the bitrotted persistent-https helper, and the MediaWiki integration tools. Junio Hamano has approved the overall approach, distinguishing between components that can be removed immediately versus those needing Git 3.0 coordination (like `remotes2config.sh`).

In the latest discussion, Eric Sunshine suggests adding `git-contacts` to the removal list, noting that while it still has some users, there's a better-maintained alternative (`git-related`) available. This follows the established pattern of externalizing specialized tools when superior alternatives exist. The thread shows consensus on the removal criteria, with no technical objections raised - the focus now is on identifying additional candidates that fit the pattern rather than debating the approach itself.

Junio has endorsed using the Linux kernel's staging drivers model as future policy for `contrib/`, suggesting further reorganization into `tools/` and documentation examples directories. With the core questions resolved, the remaining work involves timing considerations for a few specific removals and potentially identifying any other components that meet the criteria.
