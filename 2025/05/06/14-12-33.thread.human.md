This thread continues Patrick Stehtardt's systematic cleanup of Git's `contrib/` directory, transitioning from individual component removals to establishing formal policy. The discussion has covered several scripts (`mw-to-git`, `remotes2config.sh`, `git-new-workdir`, `git-contacts`, and now `git-resurrect.sh`), with each removal following established patterns based on whether the functionality exists in core Git or requires author confirmation.

Junio Hamano has now weighed in on the proposed removal of `git-resurrect.sh`, agreeing with Patrick's assessment that its branch recovery functionality is fully covered by Git's native reflog capabilities. Junio notes that `git reflog show refs/heads/branch` provides equivalent functionality, and extends this by pointing out users don't even need to remember exact branch names to recover deleted branches. This maintains the pattern seen throughout the thread where obsolete contrib components are removed in favor of core Git features.

The thread has reached clear maintainer consensus on both the technical removals and the need for policy documentation. Junio has explicitly endorsed Patrick's approach, and the discussion is shifting toward formalizing these patterns in `contrib/README`. The remaining open questions center on how precisely to document the removal criteria and balance historical preservation with maintenance burden. With no new objections raised, the cleanup appears to be proceeding smoothly toward completion.
