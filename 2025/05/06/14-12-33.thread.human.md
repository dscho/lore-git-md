Patrick Steinhardt continues his systematic cleanup of Git's `contrib/` directory, now transitioning from individual component removals to establishing formal policy. The thread has reached consensus on removing several unmaintained scripts, including `git-resurrect.sh` (obsoleted by native `git reflog`), `mw-to-git` (confirmed abandoned by its author), and `remotes2config.sh` (broken migration path). Kristoffer Haugsbakk provided supporting data from StackOverflow showing users overwhelmingly prefer the native `git reflog` over `git-resurrect.sh` by a 3000:16 margin.

The new patch series removes 11 more components based on three clear criteria: broken state, 5+ years without updates, or existence of better alternatives. Each removal includes detailed justification, like `remotes2config.sh`'s inability to handle modern Git configurations. Junio Hamano has endorsed the approach, suggesting `contrib/` components should either "move up" to core, "move out" to separate projects, or "disappear" if unmaintained.

Patrick now plans to draft formal policy documentation in `contrib/README`, using these concrete removals as examples. The thread shows how empirical data and clear criteria can guide maintenance decisions while preserving Git's focus on supported functionality.
