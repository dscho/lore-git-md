This thread documents Patrick Steinhardt's systematic cleanup of Git's `contrib/` directory, transitioning from a "batteries included" approach to focused maintenance. The discussion has established patterns for removing unmaintained components like `mw-to-git` (with author confirmation) and `remotes2config.sh` (as obsolete), with maintainer Junio Hamano endorsing the overall direction.

The latest development focuses on `git-resurrect.sh`, where Kristoffer Haugsbakk provided compelling StackOverflow data showing users overwhelmingly prefer core Git's reflog functionality (3029 votes) over the contrib script (16 votes) for branch recovery. This empirical evidence strengthens the case for removal, showing even infrequently used core commands are trusted more than contrib scripts. Junio had previously noted this preference, observing users avoid rarely-used contrib scripts in favor of transparent core functionality.

The thread is now shifting from individual removals to policy formulation, with work underway on `contrib/README` documentation. Key open questions remain about how to formally categorize different removal types and balance historical preservation with maintenance burden, but there's clear consensus on moving forward with both the technical cleanup and accompanying policy updates.
