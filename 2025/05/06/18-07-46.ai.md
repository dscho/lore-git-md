This is a review comment on the `--reviewby` feature proposal from the rebase trailer series. Junio C Hamano raises two key technical concerns about the implementation approach:

1. The current patch implements trailer handling directly in sequencer.c rather than reusing the existing interpret-trailers machinery, which already handles duplicate prevention and placement logic. This appears to be a missed opportunity for code reuse.

2. The design of adding dedicated flags for specific trailer types (like `--reviewby`) may not scale well, as it could lead to proliferation of similar flags for other common trailers (Helped-by, Acked-by, etc.). This reinforces the case for the more general `--trailer` approach proposed in patch 2/2 of the series.

The feedback suggests the implementation should either:
- Modify the existing interpret-trailers code to support this use case, or
- Reconsider whether the specialized `--reviewby` flag is needed given the more flexible `--trailer` option

This moves the discussion toward architectural decisions about trailer handling infrastructure and API design, with implications for both the current series and future extensions. The comment doesn't reject the feature outright but pushes for a more maintainable implementation approach.
