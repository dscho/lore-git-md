This is a follow-up in the ongoing discussion about Git's `contrib/` directory and legacy code management. Patrick Steinhardt responds to Junio Hamano's proposed triage approach (promote/spin-off/remove) by drawing a parallel to Linux kernel staging drivers, noting the lack of movement on many stale components. He proposes concrete action: a patch series to remove some clearly unmaintained parts of `contrib/`, plus updating the README to reflect current expectations for the directory.

Steinhardt also identifies several actively maintained `contrib/` components (CMake, Coccinelle rules, credential helpers, etc.) that may deserve promotion to core. The email reinforces the distinction between truly unmaintained code and useful-but-peripheral tools that simply lack a proper home. While acknowledging his earlier misclassification of `git svn` (which is already a core command), Steinhardt focuses the discussion on `contrib/` specifically, moving toward actionable next steps while the broader legacy code policy framework takes shape.
