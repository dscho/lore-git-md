Refactoring patch in Patrick Steinhardt's worktree maintenance series. This is part of the larger effort to decompose `git gc` functionality into standalone maintenance tasks.

Christian Couder provides a code review of patch 4/7, which introduces a new helper function `get_worktree_names()` to centralize worktree directory listing. The function is used to simplify the worktree pruning logic by moving directory handling out of the main pruning function. While the implementation is functionally sound, Christian suggests a stylistic improvement to reduce the use of `goto` statements in favor of a more straightforward control flow.

The suggested alternative implementation maintains the same behavior but structures the error handling without early exits, which some developers find easier to follow. This is a minor nit in an otherwise straightforward refactoring that helps clean up the worktree pruning code path. The patch appears ready to go with this small adjustment, though the decision to accept the suggestion would be up to the original author.
