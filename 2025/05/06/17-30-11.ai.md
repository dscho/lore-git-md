Submodule name/path collision fix proposal. K Jayatheerth responds to Moritz Lell's bug report about `.gitmodules` entries being overwritten when submodules with the same name but different paths are added. The proposed solution modifies `module_add()` to detect when a submodule name is already associated with a different path, then either:

1. Fails with an error message suggesting `--name` or `--force` options
2. When forced, auto-disambiguates by appending the basename (e.g. "child" becomes "child.child")

The patch would add validation before the existing `check_submodule_name()` call, querying the submodule cache to compare paths. The error case preserves the original configuration rather than silently overwriting, addressing the data loss scenario. Jayatheerth notes this is a starting point and is open to alternative approaches, planning to include tests in existing files rather than adding new ones. The solution focuses on preventing the problematic case while maintaining backward compatibility through the `--force` escape hatch.
