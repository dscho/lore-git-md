This is a follow-up in the incremental Git backup discussion, focusing on implementation details for using `git bundle`. Abhishek Dalmia from Commvault seeks verification of their proposed backup/restore workflow after Justin Tobler's initial bundle examples.

The email outlines a concrete plan: starting with a full `--all` bundle, then creating time-based incremental bundles with `--since`, and restoring via `git clone -bare` for the initial state followed by `git fetch` with a wildcard refspec for incrementals. The key question is whether this approach reliably captures all repository data, particularly concerned about missing tags or references when using `refs/*:refs/*` during restore.

The proposal appears technically sound for basic cases but doesn't address edge cases like packed refs or special ref namespaces. The thread continues to focus on practical implementation of bundle-based backups while implicitly highlighting the need to verify complete reference restoration - a common pain point in Git backup strategies. This represents a natural next step from Justin's conceptual examples toward a production-ready solution.
