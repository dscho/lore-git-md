This is part 4/17 of Patrick Steinhardt's series refactoring the object database (ODB) subsystem as part of the `the_repository` removal effort. The patch introduces parent pointers between ODB components to enable repository access without relying on globals.

The key change adds `repo` and `odb` pointer fields to `struct object_database` and `struct odb_backend` respectively. This allows components to traverse from an ODB backend up to its owning repository when needed (e.g. for config values), while maintaining the architectural goal of removing direct `the_repository` access. The patch updates several functions in `odb.c` to pass through the object database rather than repository pointer, particularly in the alternate ODB handling code paths.

Technical impacts include:
- New `repo` field in `object_database` struct
- New `odb` field in `odb_backend` struct
- Modified call chains for `link_alt_odb_entry()` and related functions to pass ODB instead of repo
- Updates to `prepare_alt_odb()`, `add_to_alternates_file()`, and other alternate-handling code
- Initialization of parent pointers in `odb_new()` and temporary ODB creation

The changes are mechanical but touch sensitive alternate ODB handling code. Reviewers should verify the pointer propagation logic, particularly in edge cases around submodules and nested alternates. This builds on the previous structural renaming work while enabling future patches to remove `the_repository` dependencies from the ODB layer.
