This is a refactoring discussion in the packed-refs backend optimization series. Junio Hamano responds to patch 3/4, which extracted mmap cleanup logic into a helper function. He raises concerns about the maintainability of naming the helper `munmap_snapshot_if_temporary()` when it actually checks `mmap_strategy != MMAP_OK`, arguing this could cause confusion if future mmap strategies are added.

Junio suggests a more explicit approach where the caller checks the specific MMAP_TEMPORARY condition directly, and the helper (renamed to `munmap_temporary_snapshot()`) would only the null check and actual unmapping. This would make the intention clearer at call sites and better accommodate potential future strategy additions. The feedback focuses on code organization and long-term maintainability rather than functionality, as the series already addresses its core optimization goals through earlier review iterations.
