This is the third patch in a series refactoring the packed-refs backend to enable mmap usage during fsck operations. The patch extracts the munmap operation for `MMAP_TEMPORARY` cases into a new helper function `munmap_snapshot_if_temporary()`, which will be reused in the upcoming fsck changes.

The change moves the temporary mmap cleanup logic from `create_snapshot()` into a dedicated function, following the same pattern as patch 2/4's buffer allocation extraction. The new function handles the case where we need to copy mmapped content to a regular buffer when using `MMAP_TEMPORARY` strategy, maintaining the existing behavior while making the code more modular.

Key technical details:
- New function `munmap_snapshot_if_temporary()` encapsulates the mmap cleanup logic
- Preserves the existing behavior of copying mmapped content when needed
- Modifies `create_snapshot()` to use the new helper
- Part of the preparation for enabling mmap in fsck operations (patch 4/4)
- Follows suggestions from Jeff King and Patrick Steinhardt

The patch continues the series' pattern of careful refactoring with no behavior changes, keeping each step reviewable. The extracted function will be used in the final patch to handle mmap cleanup during fsck operations on large packed-refs files.
