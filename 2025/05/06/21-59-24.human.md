Maintainer feedback on FQDN validation rules for `git send-email`

This is part of the ongoing discussion about improving domain name validation in `git send-email`, specifically addressing RFC compliance while considering real-world email server behavior. Junio Hamano responds to Aditya Garg's technical analysis of the current validation shortcomings.

The maintainer agrees that the script's current checks are both too strict (requiring a period when local settings may not need one) and too lenient (allowing malformed domain names). He confirms that consecutive periods are clearly invalid, while noting that trailing periods can be valid in DNS contexts. 

Hamano highlights the tension between strict RFC compliance and practical interoperability, pointing out that some servers (like Outlook in Garg's testing) accept non-compliant domain names. He suggests a balanced approach: validating domain components as alphanumeric runs (up to 63 characters) separated by single dots, with no leading/trailing hyphens in each component.

This feedback helps refine the validation rules while acknowledging that real-world email systems may not perfectly follow standards. The discussion shows the maintainer weighing technical correctness against user experience, with the goal of catching clear errors while not breaking valid local configurations.
