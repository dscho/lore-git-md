This is a follow-up discussion in the reftable test modernization thread, specifically addressing Git's rename detection thresholds during test conversion reviews. Patrick Steinhardt and Junio Hamano clarify the behavior of `-M<number>` in Git's diff/rename detection.

The key points:
1. Junio confirms that `-M<number>` without % is interpreted as a fraction where the number is divided by 10^digits (so -M90 means 90/100 = 90%, same as -M90%, while -M5 means 5/10 = 50%).
2. Both agree that lower similarity thresholds (like -M50) are actually more useful for reviewing test conversions, as they help avoid Git mistakenly marking modified tests as renames.
3. Patrick acknowledges his initial confusion about the numeric interpretation, noting the documentation could be clearer on this point.

This discussion doesn't introduce new changes to the patch series, but provides important context for reviewers about optimal diff settings when examining the test conversions. The clarification about rename detection thresholds may influence future project guidelines for patch review.
