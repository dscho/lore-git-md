This is patch 15/17 in Patrick Steinhardt's series refactoring the object database (ODB) subsystem as part of the `the_repository` removal effort. The patch renames the `has_object()` function to `odb_has_object()` to align with modern coding guidelines and the naming pattern established in previous patches for ODB-related functions.

The change follows the same approach as earlier patches in the series:
1. Renames the core function while maintaining backward compatibility through a wrapper
2. Updates all 30 call sites across the codebase to use the new name
3. Shifts the parameter from taking a `struct repository*` to taking a `struct object_database*` (via `the_repository->objects` at call sites)

Key technical details:
- The function checks for object existence in the ODB
- Flags parameter remains unchanged (HAS_OBJECT_RECHECK_PACKED, HAS_OBJECT_FETCH_PROMISOR)
- Wrapper preserves compatibility for in-flight topics
- Changes span various components including builtins (cat-file, fsck, fetch), bulk operations, and network code

The patch continues the series' pattern of mechanical updates that:
1. Standardize ODB function naming
2. Move toward explicit ODB parameterization
3. Maintain existing behavior while preparing for `the_repository` removal

Review considerations:
- Mechanical nature similar to previous patches (13/17, 14/17)
- Need to verify all flag handling remains correct
- Particularly in alternate ODB and promisor remote cases
- Compatibility wrapper ensures no disruption to ongoing work

This is another incremental step in establishing proper ODB boundaries while maintaining functionality, with the changes appearing straightforward but requiring verification of object existence checks in all scenarios.
