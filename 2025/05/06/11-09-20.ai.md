This is part 7/17 in Patrick Steinhardt's series refactoring the object database (ODB) subsystem to remove `the_repository` dependencies, continuing the `the_repository` removal effort.

The patch focuses on `odb_mkstemp()`, which creates temporary files in the object database. Previously this function implicitly used `the_repository` internally. The changes:
1. Modify `odb_mkstemp()` to take an explicit `struct object_database*` parameter
2. Update all callers to pass `the_repository->objects` (or equivalent)
3. Update the function's header comment to clarify it operates on the primary ODB
4. Adjust internal calls to `repo_git_path_replace()` and `safe_create_leading_directories()` to use the ODB's repository pointer

The changes are mechanical but touch several components that create temporary pack files and related objects: fast-import, index-pack, bundle-uri, pack-bitmap-write, and pack-write. The patch follows the established pattern of the series by maintaining identical behavior while removing global state dependencies.

This continues the series' progression toward proper ODB encapsulation, with each patch removing another `the_repository` dependency while preserving functionality. The changes appear straightforward with no obvious edge cases, though reviewers will want to verify the temporary file handling remains correct in all scenarios (particularly error paths).
