This thread has completed a series of optimizations to reduce memory usage when verifying large packed-refs files during `git fsck` operations. The work originated from suggestions by Jeff King (Peff) and Patrick Steinhardt, with Junio Hamano providing guidance throughout the review process.

The final patch implements mmap-based verification for large packed-refs files (over 32KB), while maintaining the existing read-based approach for smaller files. The implementation carefully preserves all platform-specific considerations, including Windows compatibility through MMAP_TEMPORARY handling. Key improvements include using stack-allocated snapshot structs (as suggested by Jeff King) and proper cleanup sequences.

The series went through three iterations (v1-v3) with all technical concerns addressed. The changes are now ready for integration, having achieved the goal of reducing memory pressure during packed-refs verification while maintaining all existing behavior and safety checks. Future work may unify this verification logic with other packed-refs parsing paths.
