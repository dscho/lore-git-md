This is part 14/17 of Patrick Steinhardt's series refactoring the object database (ODB) subsystem as part of the `the_repository` removal effort. The patch renames `repo_read_object_file()` to `odb_read_object()` to align with the naming conventions established in earlier patches of the series, where ODB-related functions are being standardized to use the `odb_` prefix.

The change is mechanical but widespread, touching 47 files across the codebase. The function signature remains the same - it still takes an object database pointer, OID, and returns the object content along with type and size information. A compatibility wrapper is provided to avoid breaking in-flight topics that may still use the old function name.

Key technical details:
- The function now takes an explicit `struct object_database*` parameter rather than implicitly using `the_repository->objects`
- All callers are updated to pass `the_repository->objects` where they previously passed `the_repository`
- The change continues the pattern seen in patch 13/17 where object info functions were similarly renamed
- The implementation remains in odb.c but now has a more consistent naming scheme with other ODB operations

This patch follows the established pattern of the series, making incremental progress toward removing `the_repository` dependencies while maintaining backward compatibility.
