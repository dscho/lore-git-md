This is a design discussion in the ongoing Scalar maintenance configuration series, specifically about the `--maintenance` option's interface.

Junio Hamano responds to Derrick Stolee's proposal for a three-state `--maintenance=<option>` parameter (enable/disable/keep) instead of the current boolean `--[no-]maintenance` flag. Hamano agrees the tri-state approach makes more sense for the `reconfigure` command, though he notes a boolean would suffice for just `clone` and `register`.

He suggests an alternative implementation using OPT_BOOL with a -1 sentinel value to represent "keep current state", which would maintain simpler user-facing syntax while handling the three cases internally. However, he acknowledges this might be less flexible if defaults need to change later. Hamano explicitly states no strong preference between the approaches.

The discussion shows consensus on moving away from the current boolean flag due to semantic ambiguity in `reconfigure`, with two technically viable paths forward. This refinement would improve the interface while maintaining all existing functionality and test coverage from the already-complete series.
