This is a review response in the ongoing series to complete the `git gc` decomposition into granular maintenance tasks. Christian Couder provides final feedback on Patrick Steinhardt's v4 patch series, which implements the last two missing tasks (worktree pruning and rerere garbage collection) as standalone maintenance operations.

Christian notes that the series looks good overall, with just a few minor nits addressed in his replies to individual patches. He points out that one issue from Eric Sunshine's earlier review - a memory leak in the worktree pruning path - appears to have been overlooked in this revision. The leak occurs when `wtpath` isn't freed during early exit conditions.

The v4 series simplified the rerere GC auto-condition check from counting directory entries to just checking for any positive config value when the rr-cache exists with at least one entry. This addresses Junio Hamano's concerns about the heuristic value while maintaining integer config consistency. The series is otherwise technically complete with comprehensive test coverage and documentation updates.

With the memory leak fix being the main outstanding issue, this appears to be the final round of review before the series could be ready for merging, completing the multi-year effort to decompose `git gc` functionality.
