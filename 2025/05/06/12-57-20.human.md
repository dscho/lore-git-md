This is a feature proposal introducing new `git rebase` and `git am` options for managing commit metadata. The RFC patch series from Li Chen adds two related capabilities:

First, it proposes a `--trailer` option for `git rebase`'s merge backend, allowing arbitrary trailer lines (like Reviewed-by or Tested-by) to be appended to each rebased commit. The author notes this is particularly useful for adding reviewer acknowledgments during rebase operations. The apply backend (`git am`) explicitly rejects this option since it lacks trailer support.

Second, it introduces a `--reviewby` convenience flag (analogous to `--signoff`) that automatically adds a "Reviewed-by" trailer using the committer's identity. This works with both rebase backends and automatically disables fast-forwarding to ensure commit rewriting. The same flag is also added to `git am` for consistency.

The implementation appears thorough, adding about 550 lines of code across 10 files with corresponding test coverage in two new test files. The author notes some CI failures around leak checks that are still being investigated. The use case for adding review metadata during rebase operations seems reasonable, though the interaction between `--trailer` and `--reviewby` (and whether both are needed) may warrant discussion. The patch appears well-structured with documentation updates included.
