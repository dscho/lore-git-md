This is a follow-up discussion about the final removal timing for the `remotes2config.sh` script, which was part of Patrick Steinhardt's completed `contrib/` cleanup series. Junio Hamano agrees with the script's removal but notes it should wait until after the related `branches/` and `remotes/` directory removal lands in Git 3.0, when the `WITH_BREAKING_CHANGES` code paths can be cleaned up together.

The script in question (last updated in 2007) migrated remote configurations from the obsolete `.git/branches/` and `.git/remotes/` formats to config-based remotes. While the script still works, Git's built-in `git remote rename` now handles this migration directly, making the script redundant. Hamano questions whether the script's age alone justifies removal, but agrees the existence of a core Git migration path makes the script obsolete.

This email doesn't introduce new technical details but clarifies the removal timeline - it should happen alongside other breaking changes in Git 3.0 rather than immediately. The discussion confirms the script meets all criteria for removal (obsolete functionality with direct core replacement) but coordinates timing with related changes.
