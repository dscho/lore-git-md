This is a feature proposal for Git's rebase and am commands, introducing new trailer-related functionality. The RFC patch series from Li Chen adds two main capabilities:

First, it proposes a `--trailer` option for `git rebase`'s merge backend, allowing arbitrary trailer lines (like Reviewed-by or Tested-by) to be appended to each rebased commit. The implementation explicitly prevents using trailers with the apply backend (`git am`) since it lacks message filtering support. The commit message provides a clear example of adding multiple trailers during a rebase operation.

Second, it introduces a `--reviewby` convenience flag that automatically adds a Reviewed-by trailer using the committer's identity, similar to how `--signoff` works. This works with both rebase backends and automatically disables fast-forwarding. The patch also extends this to `git am` for consistency. The changes touch several core components including the sequencer, rebase, and am implementations, with extensive new test coverage (over 300 lines across two new test files).

The implementation appears thorough, adding proper documentation and tests, though the author notes some CI failures around leak checks that are still being investigated. The changes would be particularly useful for workflows involving code review tracking through commit trailers. The proposal seems well-motivated for teams using trailer-based review tracking, though some discussion may be needed about the apply backend limitations and whether the `--reviewby` shortcut warrants a dedicated flag versus just using the more flexible `--trailer` option.
