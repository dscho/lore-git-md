This is a bugfix patch that aligns error reporting behavior with runtime handling of empty packed-refs files. It's the first in a series addressing memory usage and consistency in the packed-refs backend.

Currently, Git correctly handles empty packed-refs files at runtime by returning early, but still reports them as errors during consistency checking. This patch makes the fsck operation skip consistency checks for empty files, matching the runtime behavior. The change is straightforward - it adds a zero-size check before reading the file contents.

The patch includes a new test case that verifies no error is reported when checking an empty packed-refs file. This appears to be a well-scoped fix that addresses a clear inconsistency, with proper test coverage. The change is small (3 lines of code plus tests) and focused on the stated issue.

As the first patch in a series about packed-refs optimization, this establishes baseline behavior before subsequent refactoring. The thread context indicates this work responds to prior discussions about memory efficiency, though this particular patch is more about correctness than performance.
