This is the second patch in a CI/build system series improving TAP output parsing for Meson integration. It addresses how shell traces from test verbosity flags (`--verbose`, `-x`) are handled to prevent them from breaking TAP output format.

The patch modifies `test-lib.sh` to redirect test stdout to stderr when verbose mode is active, rather than keeping it on stdout. This ensures TAP parsers (like Meson's) only see clean TAP-formatted output on stdout. The change sacrifices the ability to distinguish between stdout and stderr in verbose mode, but the author notes this distinction hasn't been needed in practice. The patch updates test expectations in `t0000-basic.sh` to match the new output routing, splitting checks between stdout (TAP) and stderr (diagnostics).

This is a mechanical change that builds on the series' goal of proper TAP parsing support. It touches core test infrastructure files but doesn't affect test behavior - only output routing. The implementation appears straightforward, with test updates demonstrating the new output separation clearly. Since this depends on redirecting stdout to stderr, future discussion might examine whether any tests actually rely on the old stdout/stderr separation in verbose mode.
