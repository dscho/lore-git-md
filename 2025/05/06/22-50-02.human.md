This is a performance optimization patch for xdiff's `--minimal` mode that has now received final approval. The change from Niels Glodny modifies the `cleanup_records` heuristic to skip marking lines as changed when they're surrounded by many changes, but only when `--minimal` is explicitly requested. This produces shorter diffs in about 1.3% of cases while maintaining the same performance characteristics.

The patch has gone through three iterations with feedback from Phillip Wood and Junio C Hamano. Benchmarking showed no statistically significant runtime impact (2.363s vs 2.362s for `git log -p -3000 --minimal`), while achieving the desired diff size reduction. Phillip Wood gave the final approval after Niels incorporated the performance data into the commit message as suggested.

With all technical feedback addressed and consensus reached, this narrowly-scoped optimization to xdiff's minimal diff output appears ready for merging. The change only affects `--minimal` output where shortest-possible diffs are the expected behavior, with no runtime penalty.
