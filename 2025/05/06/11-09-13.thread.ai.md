Patrick Steinhardt's 17-patch v3 series refactoring Git's object database (ODB) subsystem is in final form, with the first two patches establishing core naming conventions. Patch 1/17 renamed `raw_object_store` to `object_database` (ODB) across 8 files (~24+19 lines), introducing new APIs like `odb_new()` and `odb_clear()`. Patch 2/17 continues this by renaming `object_directory` to `odb_alternate` across 28 files (~270 lines), preparing for future non-directory-based storage backends while maintaining current behavior.

The series systematically removes `the_repository` usage across 333 files (139 changed, ~1200 lines) to enable pluggable ODB backends, with key architectural elements now settled:
- Core APIs: `odb_read_object()`, `odb_has_object()`, `odb_read_object_peeled()`, `odb_pretend_object()`
- Structure names: `object_database` (was `raw_object_store`), `odb_alternate` (was `object_directory`)
- File organization: root-level `odb.h` with `odb/` subdirectory (mirroring refs/ pattern)
- Alternate handling via `odb_for_each_alternate_ref()` iterators

All technical aspects have Junio Hamano's confirmation for integration and Derrick Stolee's Reviewed-by on both foundational patches. The v3 changes are purely cosmetic (comment/commit message polish, documentation clarifications) with no substantive modifications from the approved v2 state. The series completes the architectural foundation for future ODB work while maintaining current behavior, with performance validation and non-code follow-ups remaining as separate items.
