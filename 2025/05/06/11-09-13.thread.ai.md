Patrick Steinhardt's v6 series (17 patches) continues the architectural refactoring of Git's object database (ODB) subsystem to eliminate `the_repository` global state and enable pluggable ODB backends. The series begins with patch 1/17 renaming the core `raw_object_store` structure to `object_database` (ODB), affecting 8 files with mechanical updates to type names and function signatures (`raw_object_store_new()` -> `odb_new()`, etc.). Patch 2/17 renames `struct object_directory` to `struct odb_source` (affecting 28 files) to better reflect its role as an access point for object storage that may not always be directory-based.

Patch 4/17 (the focus of the latest email) introduces parent pointers between ODB components to enable repository access without global state: `struct object_database` gains a `repo` field pointing to its owning repository, and `struct odb_source` gains an `odb` field pointing to its owning object database. These changes (35 lines added, 21 removed across 3 files) update functions like `link_alt_odb_entry()` to pass ODB explicitly rather than using `the_repository`, maintaining correct relationships while eliminating global state. The patch builds on earlier structural renames while preserving backward compatibility.
