Final patch in a series optimizing packed-refs memory usage. This completes the work by switching the fsck operation to use mmap for large packed-refs files, following the preparatory refactoring in earlier patches.

The patch replaces the direct `strbuf_read()` call in `packed_fsck()` with the new `allocate_snapshot_buffer()` helper introduced earlier in the series. This change means that when verifying packed-refs integrity, Git will now use memory-mapped files for large packed-refs files rather than reading the entire contents into memory. The implementation maintains the same error handling and cleanup paths while using the more memory-efficient approach.

The change is relatively straightforward (9 lines added, 9 removed) and builds on the infrastructure established in the previous patches. It addresses the original motivation of reducing memory pressure when multiple processes need to examine large packed-refs files. The patch carries suggestions from both Jeff King and Patrick Steinhardt, indicating it follows their earlier feedback on the approach.

This completes the series' goal of enabling mmap usage for packed-refs operations, with all preparatory refactoring now being put to use in the fsck operation. The change appears well-contained and consistent with the series' incremental approach.
