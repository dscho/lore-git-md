Patrick Steinhardt's ongoing refactoring of Git's object database subsystem has reached a key naming decision point in its third iteration. The 17-patch series systematically removes the `the_repository` global state while laying groundwork for pluggable ODB backends, with core structural changes already reviewed positively by Junio Hamano and Derrick Stolee.

The current focus is whether to rename `odb_alternate` - a structure that handles both primary and alternate object stores - to something like `object_source` for clarity. Justin Tobler has advocated strongly for the change, while Patrick maintains that "alternate" conceptually works since even primary stores can be viewed as alternates from another repository's perspective. Toon Claes has now joined the discussion, supporting Patrick's position while acknowledging Justin's concerns. As a non-native English speaker, Toon finds "alternate" acceptable if not ideal, but strongly cautions against using "backend" which would conflate instances with implementations.

The technical implementation is otherwise complete, with all ODB-related functions converted to use explicit repository parameters and follow the new `odb_` naming convention. The series has already updated over 100 call sites and established a clear directory structure mirroring Git's refs subsystem. While the naming discussion continues, the underlying work is functionally ready - a testament to the careful, incremental approach Patrick has taken in this foundational refactoring.
