This thread centers on Patrick Steinhardt's major refactoring of Git's object database (ODB) subsystem to eliminate the `the_repository` global variable and enable pluggable backends. The 17-patch v3 series introduces a new `struct object_database` (formerly `raw_object_store`) and systematically converts all ODB-related functions to take explicit repository parameters. 

The current discussion focuses on naming of the `struct odb_alternate`, which represents object storage instances. Justin Tobler initially suggested `object_source` as more accurate since the structure applies to primary stores too, while Toon Claes supports keeping "alternate" despite its ambiguity but strongly rejects using "backend" terminology. Patrick Steinhardt has clarified key distinctions: "local" objects come from the primary object directory while "non-local" objects come from alternates, and backend implementations are per-alternate rather than per-database. 

While Patrick defends "alternate" as the clearest term, he remains open to `odb_source` if consensus favors it. The exchange exemplifies Git's careful approach to API design, where naming decisions balance technical precision against long-term usability. The series has already received Reviewed-by from Derrick Stolee on foundational patches and confirmation from Junio Hamano about the integration path, with the remaining discussion focused on finalizing these naming details before merging.
