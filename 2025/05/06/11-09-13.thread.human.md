Patrick Steinhardt's ongoing refactoring of Git's object database (ODB) subsystem continues with part 9/17 of his series, which systematically removes dependencies on the global `the_repository` variable. The series has already renamed core structures (`raw_object_store` to `object_database`) and relocated files while establishing explicit parameter passing for ODB operations.

The latest patch focuses on iterator-style functions that work with alternate object databases. It renames three key iteration functions to use the new `odb_` prefix convention (`foreach_alt_odb` becomes `odb_for_each_alternate`, etc.) and modifies them to take an ODB parameter rather than implicitly using the repository. The changes affect 8 call sites across commands like fetch-pack, receive-pack, and revision walking, though the actual behavior remains unchanged - this is purely about making dependencies explicit.

The series has now converted about 184 files (up from ~170 in previous patches) as it methodically works through the codebase. Core ODB operations are fully converted to explicit parameter passing, and the infrastructure is in place to eventually store alternate paths directly in the object database structure. Remaining work includes performance validation, regression testing for operations using alternates, and final documentation of the new interfaces. The changes maintain build stability while progressing toward the larger goal of enabling mixed backend support by eliminating global state.
