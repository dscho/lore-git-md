Patrick Steinhardt's large-scale refactoring of Git's object database (ODB) subsystem continues with version 2 of his 17-patch series. The work aims to decouple object storage from `the_repository` global variable, a key step toward enabling pluggable storage backends. The series has already renamed core structures (`raw_object_store` to `object_database`, `object_directory` to `odb_alternate`) and relocated implementation files, with these changes reviewed and validated by Junio Hamano and Derrick Stolee.

The latest patch (4/17) introduces parent pointers between ODB structures to maintain repository relationships without relying on global state. It adds a `repo` pointer to `object_database` and an `odb` pointer to `odb_alternate`, carefully managing these relationships during ODB initialization. While mechanical in nature, this change is foundational for the series' goal of proper ODB/repository separation, updating key functions like `link_alt_odb_entry()` and `read_info_alternates()`.

The thread shows steady progress on this architectural shift, with core design decisions already settled regarding structure naming, function prefixes, and file organization. Reviewers are now focused on implementation details, with several open considerations remaining around edge cases, promisor remote integration, and documentation updates. Patrick has outlined a future vision where different alternates could use distinct storage implementations, with an RFC planned for the Git 2.51 cycle.
