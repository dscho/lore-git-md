Patrick Steinhardt's ongoing refactoring of Git's object database subsystem has reached patch 16/17 in the series. The work continues the project-wide effort to eliminate reliance on the global `the_repository` variable by making object database operations work through explicit parameters. 

The latest patch focuses on renaming `pretend_object_file()` to `odb_pretend_object()` and updating its interface to take an object database parameter directly. This change follows the naming pattern established in previous patches (13-15/17) and affects a rarely-used function that temporarily registers objects in memory without writing to disk - primarily used by the blame machinery. Since the function has only one caller in `blame.c`, the change is straightforward with minimal risk.

The series as a whole has systematically renamed structures and functions across the codebase, with patches 1-15 already converting core object database operations to use explicit parameters. This foundational work enables future pluggable backends while maintaining current behavior. Reviewers have been focusing on mechanical updates, edge cases in alternate object handling, and promisor remote scenarios. With only two patches remaining, the series appears on track to complete its goal of establishing proper ODB boundaries in preparation for fully removing `the_repository` dependencies from this subsystem.
