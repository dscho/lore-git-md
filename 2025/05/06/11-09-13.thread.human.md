Patrick Steinhardt's ongoing series to refactor Git's object database (ODB) subsystem has reached an important milestone with the v4 patches. The work systematically removes reliance on the `the_repository` global variable while establishing a clear naming convention (`odb_` prefix) and structure for future pluggable backends. 

The latest patch completes this mechanical conversion by renaming `read_object_with_reference()` to `odb_read_object_peeled()`, updating its 8 call sites across builtins like `cat-file` and `grep`. This follows the established pattern: adding an explicit `object_database` parameter, using the ODB's repository pointer, and maintaining behavior through direct updates rather than compatibility wrappers. The new name better reflects the function's purpose of recursively peeling commit/tag objects.

The series has seen thorough review, with Junio Hamano confirming the integration path and Derrick Stolee providing Reviewed-by tags on foundational patches. Key technical decisions included standardizing on `odb_source` for alternate storage naming and organizing files similarly to the refs subsystem. With this final patch, all major ODB-related functions have been converted, clearing the way for Patrick's planned pluggable backend work while completing the removal of `the_repository` from this subsystem.
