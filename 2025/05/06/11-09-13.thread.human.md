Patrick Steinhardt continues his major refactoring of Git's object database (ODB) subsystem, now at patch 11/17 in his series to eliminate `the_repository` global dependencies. The work is part of René Scharfe's broader initiative to remove implicit repository access throughout the codebase.

The series has systematically renamed core ODB structures and functions while maintaining behavior - converting `raw_object_store` to `object_database`, moving functions like `find_odb()` to `odb_find_backend()`, and updating callers across dozens of files. Recent patches (5-10) focused on alternate ODB handling and temporary file management, ensuring proper parent pointer relationships between repositories and their object stores.

Patch 11 specifically tackles submodule integration, moving submodule ODB tracking from global state in `submodule.c` to being properly scoped within each repository's `object_database` struct. This changes how alternate object stores are registered during operations like recursive grep, but preserves the same functionality. The patch removes several submodule-specific helpers in favor of the new ODB-centric API.

Reviewers have been focusing on edge cases in alternate handling, particularly around submodules, temporary object storage, and iterator safety. The changes appear methodical and maintain existing behavior while making the architecture more explicit. The series remains foundational work enabling future pluggable ODB backends, with several patches still to come in this substantial refactoring effort.
