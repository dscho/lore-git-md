Patrick Steinhardt's ongoing refactoring of Git's object database subsystem has reached patch 12/17 in its fifth iteration. The series systematically removes reliance on the `the_repository` global variable while preparing for pluggable ODB backends. The latest patch focuses on odb.c internals, eliminating remaining uses of repository globals by plumbing through explicit parameters.

The work builds on substantial infrastructure established in earlier patches, including renaming core structures (`raw_object_store` to `object_database`), standardizing API names with `odb_` prefixes, and converting over 150 files to use the new patterns. Patch 12 completes this conversion for odb.c by removing the `USE_THE_REPOSITORY_VARIABLE` define entirely and updating internal functions like `read_alternate_refs()` to use repository-specific configurations and hash algorithms. These are mechanical but important changes that maintain consistency with the series' architectural goals.

The series has benefited from multiple review cycles, with Derrick Stolee providing Reviewed-by tags on foundational patches. With core naming questions resolved and the conversion pattern well-established, the work now focuses on completing the remaining mechanical changes. The final patches will continue this file-by-file approach, with the last planned change being the renaming of `read_object_with_reference()` to `odb_read_object_peeled()`. The changes are currently under review by Junio Hamano for potential inclusion.
