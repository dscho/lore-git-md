This is a patch series addressing memory usage and behavior consistency in the packed-refs backend, following up on prior discussion about using mmap for large packed-refs files.

The series has two main goals: fixing an inconsistency in error reporting for empty packed-refs files, and refactoring the code to enable mmap usage in fsck operations. The first patch fixes a minor bug where Git would incorrectly report an error for empty packed-refs files, despite handling them correctly at runtime. The next three patches are refactoring steps that extract helper functions from existing code (snapshot allocation and munmap operations) to prepare for the final change that enables mmap usage for large packed-refs files during fsck operations.

The changes touch the packed-backend.c file extensively (106 lines modified) and add new test cases in t0602-reffiles-fsck.sh. The work appears motivated by memory optimization concerns raised in a previous thread referenced in the cover letter, where Peff and Patrick suggested these changes. The series seems well-structured, with each patch building logically toward the final mmap implementation, and includes test coverage for the new behavior.
