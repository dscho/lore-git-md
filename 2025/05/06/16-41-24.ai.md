This is the final patch in a 4/4 series optimizing memory usage in the packed-refs backend, specifically enabling mmap for large packed-refs files during fsck operations. The patch builds on the refactoring work from earlier patches (which introduced helper functions for buffer allocation and cleanup) to replace the memory-intensive `strbuf_read()` approach with mmap when verifying packed-refs.

The key changes:
- Replaces `strbuf_read()` with the new `allocate_snapshot_buffer()` helper
- Uses the existing `packed_fsck_ref_content()` and `packed_fsck_ref_sorted()` functions but now passes mmap'd buffer pointers instead of strbuf contents
- Maintains the same error handling and cleanup flow but with mmap-aware operations
- Adds proper snapshot buffer cleanup via `clear_snapshot_buffer()` and `munmap_snapshot_if_temporary()`

The patch completes the series' goal of reducing memory pressure when working with large packed-refs files, particularly benefiting multi-process scenarios. It follows the suggested approach from Jeff King and Patrick Steinhardt, using the infrastructure built in previous patches. The change is relatively straightforward (18 lines modified) and maintains all existing functionality while improving efficiency.
