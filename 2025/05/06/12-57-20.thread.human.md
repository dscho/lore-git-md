This RFC thread explores adding trailer-related functionality to `git rebase` and `git am`, proposed by Li Chen. The series introduces two complementary features: a `--reviewby` flag that automatically appends Reviewed-by trailers (similar to `--signoff`), and a more flexible `--trailer` option for arbitrary trailer additions during rebase.

The current patch focuses on implementing `--trailer` for the merge backend, allowing users to append custom trailers (like Reviewed-by or Tested-by) to each rebased commit. The implementation is thorough, with new state tracking in the rebase-merge directory and 108 lines of test coverage across various scenarios. Notably, it excludes the apply backend (`git am`) due to technical limitations in message filtering, automatically enabling `--force-rebase` when trailers are specified to ensure they're added even to fast-forwardable commits.

Open questions remain about whether the apply backend limitation is acceptable, and whether dedicated flags like `--reviewby` are preferable to the more flexible `--trailer` approach. The implementation currently duplicates some trailer-handling logic between rebase.c and sequencer.c, which may warrant refactoring. The series appears well-tested but is still marked RFC as the author investigates some CI leak check failures. These changes would particularly benefit workflows that use commit trailers for review tracking.
