This RFC thread explores adding new trailer-related features to `git rebase` and `git am`. Li Chen's proposal introduces two main capabilities: a `--reviewby` flag that automatically adds Reviewed-by trailers (similar to `--signoff`), and a more general `--trailer` option for appending arbitrary trailers during rebasing. The implementation currently handles both rebase backends (though not `git am`) with extensive test coverage, but Junio Hamano has raised concerns about code duplication and long-term maintainability - particularly whether the features should reuse existing trailer infrastructure rather than implementing parallel code paths.

In the latest response, Li Chen defends the current approach, noting technical constraints that make reusing interpret-trailers machinery difficult for in-memory operations during rebase. They argue for keeping the dedicated `--reviewby` flag by analogy to `--signoff`, citing projects that require Reviewed-by trailers, while acknowledging the tradeoffs between convenience and code scalability. The discussion remains open on whether to refactor the implementation, keep both features, or focus solely on the more general `--trailer` approach. The thread shows active design debate about how to extend Git's trailer functionality while maintaining clean architecture.
