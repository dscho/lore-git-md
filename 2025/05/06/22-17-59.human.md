This is a review comment on a refactoring patch in the packed-refs memory optimization series. Junio Hamano provides feedback on patch 3/4, which extracts mmap cleanup logic into a helper function.

Junio suggests renaming the proposed `munmap_snapshot_if_temporary()` helper to `munmap_temporary_snapshot()` and restructuring the control flow to make the mmap strategy check more explicit at the call site. His key concern is maintainability - the current naming could cause confusion if future mmap strategies are added, as the "if_temporary" name doesn't clearly indicate it's specifically checking for MMAP_TEMPORARY.

The suggested approach would:
1. Move the NULL check into the helper function
2. Have callers explicitly check `mmap_strategy == MMAP_TEMPORARY` before invoking
3. Rename the helper to better reflect its specific purpose

This continues the thread's pattern of Junio providing precise technical feedback to improve the series' code organization and long-term maintainability. The change appears straightforward to implement while making the code's intent clearer.
