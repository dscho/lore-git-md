This is part 5/10 of Patrick Steinhardt's series to clean up Git's `contrib/` directory by removing obsolete/unmaintained components. The patch removes the `contrib/hooks/` directory containing example hooks.

The hooks being removed are:
- `post-receive-email`: A legacy email notification script that was superseded by `git-multimail` (removed in 2021)
- `pre-auto-gc-battery`: A battery check script for `git gc --auto`
- `setgitperms.perl`: A permissions/ownership tracking script
- `update-paranoid`: An access control hook

The rationale is that these hooks are either highly specific, unmaintained (last updates 2008-2020), or have better alternatives. The commit suggests that if example hooks are needed, they should be documented in `githooks(5)` rather than shipped in `contrib/`.

This follows the same pattern as previous patches in the series - removing clearly obsolete functionality. The removal is straightforward with no impact on core Git behavior. The patch deletes 5 files totaling 1443 lines of code.

Key technical details:
- The multimail hook was already deprecated in favor of an external project
- `post-receive-email` was 759 lines of shell script with complex email formatting logic
- `update-paranoid` was 421 lines of Perl implementing fine-grained ACLs
- No behavior changes or migrations needed - these were just examples

The patch continues the systematic cleanup of `contrib/` with another low-risk removal of unmaintained code. Like previous patches, this appears non-controversial and aligns with the series goal of reducing technical debt.
