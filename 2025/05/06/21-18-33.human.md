This is a follow-up discussion about a test fix for t6011-rev-list-with-bad-commit.sh. Junio C Hamano confirms Torsten Bögershausen's observation that the test needs `mv -f` to reliably overwrite read-only files during packfile corruption simulation. 

Junio notes that the original test used Perl's in-place editing which handled read-only files properly, and that the current issue stems from a recent refactoring commit (cdbdc6bf) that switched to using `sed` and `mv` without the force flag. He raises a more fundamental concern about using `sed` on binary packfiles, pointing out this was likely why Perl was originally used for this operation.

The discussion suggests the test change may need a more thorough solution than just adding `-f` to `mv`, since the underlying approach of using text tools on binary files could be problematic. This appears to be a minor but legitimate test infrastructure issue that warrants attention from the test maintainers.
