This is a bugfix proposal for Git's submodule handling, addressing the name/path collision issue reported earlier in the thread. K Jayatheerth confirms the reported behavior where adding a new submodule with the same name as a moved submodule silently overwrites the original configuration in `.gitmodules`.

The proposed solution would make `git submodule add` detect and reject name collisions by default, requiring explicit `--force` to overwrite or `--name` to specify a different name. The patch would modify `module_add()` to check for existing submodules with the same name but different paths, and suggests auto-disambiguation by appending the basename when forced (e.g., turning "child" into "child.child" when the path differs.

The approach seems technically sound - it prevents data loss while maintaining backward compatibility through the `--force` option.
