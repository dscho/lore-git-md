This is part 11/17 of Patrick Steinhardt's series to remove `the_repository` dependencies from the object database (ODB) subsystem, continuing the broader `the_repository` removal effort. The patch focuses on submodule backend handling, specifically addressing how submodule object databases are registered as alternates during operations like `git grep --recursive`.

The key technical changes move submodule ODB tracking from a global string list in `submodule.c` to being stored directly in the `object_database` struct. The patch:
- Adds a `submodule_backend_paths` string list field to `struct object_database`
- Introduces `odb_add_submodule_backend_by_path()` to register paths (replacing `add_submodule_odb_by_path()`)
- Implements `register_all_submodule_backends()` in odb.c (replacing `register_all_submodule_odb_as_alternates()`)
- Removes the `the_repository` check when registering submodule backends since they're now tracked per-ODB
- Updates callers in `builtin/grep.c` and `submodule-config.c` to use the new API
- Deletes the now-unused submodule ODB functions from `submodule.c` and `submodule.h`

The changes maintain the same behavior while eliminating global state - submodule backends are still registered as alternates when needed for object lookups, but now the tracking is properly scoped to the repository's ODB rather than being process-wide. The patch follows the series' established pattern of methodically moving ODB-related state and functionality into proper ODB structures while preserving existing behavior.

Reviewers should verify the submodule alternate registration still works correctly in all scenarios, particularly edge cases where submodule ODBs might be registered across multiple repositories or during error conditions. The changes appear straightforward but touch sensitive submodule object lookup paths.
