This is patch 2/5 in a completed v3 series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series has already been through extensive review with all major design decisions settled.

The patch introduces server-side support for advertising additional remote attributes (currently just `partialCloneFilter` and `token`) via a new `promisor.sendFields` config option. When configured, the server will include these fields in its promisor-remote capability advertisement after the mandatory name/URL fields. The implementation:
- Defines allowed field names in a static array
- Validates configured fields against this allowlist
- Preserves URL encoding of field values
- Maintains backward compatibility
- Includes comprehensive documentation updates
- Adds test coverage for field transmission scenarios

Justin Tobler's review notes two minor implementation details that could be improved (using `repo_config_get_string()` and `test_config`), but these don't block the series. The patch appears well-tested and integrates cleanly with the existing promisor-remote infrastructure.

This is part of a security-focused enhancement that will be completed by the next patch, which adds client-side validation of the advertised fields. The series represents a thoughtful extension of the promisor-remote protocol that maintains backward compatibility while adding useful new capabilities.
