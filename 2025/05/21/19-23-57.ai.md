Feature proposal for a new `git imap-get-recipients` helper command. This would be a Perl script that extracts To/Cc recipients from a given message ID, intended to streamline sending patch revisions via `git send-email`.

The author, Aditya Garg, proposes this as a quality-of-life improvement when sending patch revisions, where recipients from the original email could be automatically populated rather than manually re-entered. The motivation comes from observing how GUI email clients simplify replies by auto-filling recipients. Currently, the author uses a basic version with `git send-email --to-cmd`, but wants to polish it for inclusion in Git proper.

Key technical details:
- Would be implemented as a Perl script (likely in `contrib/`)
- Takes a message ID as input
- Outputs To/Cc headers for that message
- Designed to integrate with `git send-email --to-cmd`

The proposal appears well-motivated by a concrete workflow pain point, though it raises some open questions about implementation details (IMAP server authentication, error handling) that would need to be addressed in a formal patch submission. The use case seems narrowly focused on patch email workflows rather than general IMAP functionality.
