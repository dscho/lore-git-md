The exchange highlights careful consideration of the API boundaries between pathspec parsing and matching components. While the flag is checked during parsing (parse_pathspec), the matching layer (match_pathspec_item) relies on the BUG() check as a secondary defense against invalid state. This maintains the series' goal of preventing incompatible pathspec features (like attributes) from being used in no-repository contexts.

The technical nuance here involves understanding that pathspec validation is split across two layers: parse_pathspec handles flag validation up front while match_pathspec_item contains runtime assertions about preconditions.
