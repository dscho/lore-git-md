This is a refactoring patch in a series addressing exec-path security and compatibility issues, specifically converting editor environment handling to use the strvec API consistently.

The patch updates editor.c/h to use strvec for passing editor environments, bringing it in line with surrounding APIs that evolved to use this standard interface. The change is primarily a cleanup, though it was originally considered preparatory work for the larger series. The only caller that passes a non-NULL environment (added in commit 8babab95af) already has a strvec available.

Patrick Steinhardt reviewed the change as sensible but noted the commit message could better explain the motivation. The author acknowledges this will be expanded in a reroll. A trailer ordering issue was also identified (Helped-by before Signed-off-by) which will be corrected.

The change is relatively straightforward but part of a larger effort with significant platform-specific considerations (particularly Windows Unicode handling) and open design questions about PATH modification approaches. This particular patch appears uncontroversial as it's a mechanical API update with no behavior changes.
