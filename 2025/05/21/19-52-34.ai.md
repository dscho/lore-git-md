Junio Hamano responds to Aditya Garg's proposal for a `git imap-get-recipients` helper script with several key concerns. This is a discussion about potential new tooling for email-based patch workflows.

The response questions the fundamental approach of simply copying To/Cc lists from previous messages, arguing this could lead to suboptimal recipient selection for patch revisions. Hamano emphasizes that v2 emails should consider both original recipients and commenters from the v1 thread, suggesting the proposed tool might encourage lazy practices if it only replicates previous recipients without context.

The email highlights significant gaps in the proposal's technical details - particularly around the IMAP data source (personal mailbox vs public archive), authentication methods, and whether the tool would analyze just the original message or also its replies. Hamano notes these missing details make it impossible to properly evaluate the tool's usefulness.

A broader philosophical point is directed at the mailing list audience: contributors should focus first on creating genuinely useful work based on their own needs and interests, rather than seeking pre-commitment from maintainers. The "make us come to you begging" principle suggests tools should prove their value through implementation rather than theoretical discussion.

This response effectively puts the proposal on hold until more concrete implementation details and use cases can be demonstrated, while also serving as a general reminder about Git's contribution philosophy. The thread remains open for Aditya to address these concerns with a revised proposal or prototype.
