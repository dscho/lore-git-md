This is a follow-up discussion in the thread about type consistency in the git graph display code. Junio Hamano responds to Octavio Carneiro's patch that changed `graph_line->width` from `size_t` to `int` to match `git_graph->width` and eliminate a sign-compare warning.

Second, he notes that while the change is technically safe (since neither type prevents potential overflow from string length additions), some developers might prefer using `size_t` consistently.

The email also contains an interesting aside suggesting that the graph display code's assumption of single-byte column width could be modernized to handle Unicode graphics, potentially as a project for new contributors. This isn't directly related to the current patch but shows broader thinking about the code's limitations.

The discussion remains focused on the original type mismatch issue while opening the door for other developers to weigh in on the `int` vs `size_t` question before proceeding.
