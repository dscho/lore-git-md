This is a feature patch targeting Windows users, implementing the previously proposed addition of a tip about `git update-git-for-windows` in the help output. The patch follows through on the earlier discussion by providing concrete code changes.

The implementation adds a single line about the update command to the output of `git help`, gated behind a `_WIN32` compiler flag check. The message appears at the end of the categorized command listing, maintaining the existing format while adding the Windows-specific tip. The change is minimal - just 3 lines added to help.c with no other modifications.

Key technical details:
- Modifies `list_common_cmds_help()` in help.c
- Uses `#ifdef _WIN32` for platform-specific behavior
- Adds a simple printf statement with the tip message
- Maintains existing help output structure
- No configuration options or suppression mechanism

The patch addresses the core proposal directly but leaves open some questions from the initial discussion thread - there's no mention of whether this should appear in `git version --help` output, nor any configurability for users who prefer other update methods. The implementation is straightforward and appears to achieve the stated goal of making Windows users more aware of the update command through Git's built-in help system.
