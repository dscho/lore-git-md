This is a review comment on a patch in the exec-path security series, specifically addressing platform consistency in child process environment preparation.

Patrick Steinhardt is reviewing patch 3/4 of the series, which makes `prep_childenv()` work consistently across all platforms (previously Windows was excluded). While he doesn't object to the technical change itself, he requests better justification in the commit message - specifically asking the author to explain why it's safe to add this call on Windows now when it wasn't used there before.

The patch is part of a larger effort to make Git's child process spawning more secure by preventing Git's internal binaries from being exposed in PATH for non-Git processes. This particular change is focused on the infrastructure work needed before the main security fix can be implemented. The review is generally positive but highlights the importance of thorough commit messages, especially when changing platform-specific behavior.
