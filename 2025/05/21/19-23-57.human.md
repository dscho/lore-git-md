This is a feature proposal for a new Git command to help with email workflows. Aditya Garg suggests adding `git imap-get-recipients`, a Perl script that would extract To/Cc recipients from a given message ID. The primary use case is simplifying the process of patch revisions - when sending a v2 patch, it would automatically populate recipients rather than requiring manual re-entry.

The motivation comes from GUI email clients' convenience in auto-filling reply recipients, which Garg wants to replicate for Git's email-based workflow. They note already using a basic version of this with `git send-email --to-cmd`, but propose polishing it for inclusion in mainline Git.

The implementation would be a standalone Perl script, suggesting it might be relatively simple to review and maintain. While the proposal is brief, it addresses a clear pain point for contributors using Git's email workflow, particularly those sending multiple patch revisions. The idea appears focused and potentially useful, though its adoption would depend on demonstrating robust handling of various email header formats and IMAP edge cases.
