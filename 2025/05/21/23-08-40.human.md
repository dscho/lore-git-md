This is a follow-up discussion on a small refactoring patch that addresses a compiler warning about type mismatches in the graph display code. Junio Hamano raises two thoughtful points about the patch that was previously submitted by Octavio Carneiro.

First, he questions why the patch chose to change `graph_line->width` from `size_t` to `int` rather than the reverse (making `git_graph->width` a `size_t`). While he personally prefers using `int` for display widths (which shouldn't need the full range of `size_t`), he notes the commit message should explain this design choice when there are multiple valid approaches.

Second, he observes that the code still has potential integer overflow issues when accumulating line widths, regardless of whether `int` or `size_t` is used. While the current patch doesn't make this worse, he suggests this might be worth addressing separately. He also notes this could be an opportunity for someone to modernize the ASCII-art graph rendering to support Unicode characters.

The discussion remains constructive but suggests the original patch may need a bit more justification in its commit message before being accepted. The technical change itself remains small and uncontroversial, but the thread shows maintainers thinking carefully about type consistency patterns in the codebase.
