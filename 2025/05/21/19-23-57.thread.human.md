Aditya Garg proposed a new `git imap-get-recipients` helper to automate populating email recipients when sending patch revisions, using IMAP to look up previous messages. The discussion quickly revealed deeper questions about both implementation and philosophy. Junio Hamano raised concerns about technical details (Perl dependencies, IMAP authentication) and whether simply copying previous To/Cc lists leads to poor recipient selection, suggesting b4's thread-aware analysis might be better. Emily Shaffer clarified this wasn't a rejection but guidance to develop the tool independently first to demonstrate value.

Garg has now acknowledged this feedback, particularly agreeing with Hamano's point that recipient selection needs more context than just previous addresses. While the technical approach using IMAP remains specified, the discussion has shifted to whether such functionality belongs in core Git at all. The thread appears to be concluding with Garg reconsidering the design approach, though no immediate next steps are indicated. The core questions about dependencies, contribution model, and recipient selection philosophy remain open if someone chooses to revisit this later.
