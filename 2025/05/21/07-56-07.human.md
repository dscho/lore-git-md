This is a refactoring patch in a series addressing exec-path security issues, specifically part 2 of 4 that modernizes editor environment handling.

Patrick Steinhardt provides a brief review of D. Ben Knoble's patch that converts the editor API to use the strvec interface consistently. The change updates editor.c/h to accept const struct strvec* parameters instead of the older string array format, bringing it in line with surrounding APIs that already use strvecs. 

The reviewer notes the change itself looks technically sound, though the commit message could better explain the motivation beyond just API alignment. Steinhardt also points out a minor documentation issue - the Signed-off-by and Helped-by trailers are in the wrong order and should be reversed.

This patch appears to be preparatory work for the larger series' security fixes, cleaning up infrastructure before the functional changes in later parts. While the change is straightforward, the reviewer's note about trailer ordering suggests the author should pay closer attention to Git contribution conventions in future revisions. The patch doesn't introduce new functionality but helps maintain consistency across Git's codebase.
