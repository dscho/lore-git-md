This thread concerns a critical buffer overflow discovered in the recently merged `git diff --no-index` pathspec support feature. Originally authored by Jacob Keller and approved by Junio Hamano, the feature allows pathspec filtering for non-repository diffs. However, Johannes Schindelin identified a security-sensitive buffer overflow when processing directory paths with trailing slashes (GitHub issue #5836).

Keller has now responded with a technical analysis of the bug, which occurs in `diff-no-index.c` during path length calculations. The current implementation incorrectly increments path lengths when checking for trailing slashes at NUL terminator positions. Keller proposes fixing the conditional logic to properly account for existing slashes, while acknowledging deeper questions about the path-matching architecture may need revisiting later. The immediate priority is correcting the buffer overflow, with additional test cases needed to cover trailing slash scenarios.

Key participants are actively engaged: Schindelin surfaced the critical issue, Keller is working on the fix, and Junio will need to evaluate the correction. This represents a significant post-merge regression that escaped earlier review, requiring prompt attention to address both the security vulnerability and test coverage gaps. The discussion suggests this may spawn a v5 patch series to properly resolve all concerns.
