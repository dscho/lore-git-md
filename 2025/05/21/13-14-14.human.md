Documentation patch in a series fixing multi-pack-index integer overflow issues. This is the final patch in a 4-part series, clarifying tie-breaking behavior for objects in multiple packs.

The patch updates the documentation for `git multi-pack-index write` to better explain how pack selection works when an object exists in multiple packs. The key clarification is that when no preferred pack is specified, the pack with the lowest mtime becomes the preferred pack, but for objects not in that preferred pack, the pack with the newest mtime is used. This behavior is important for `git multi-pack-index repack` to work correctly.
