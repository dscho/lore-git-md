Error reporting improvement follow-up in index operations thread.

This is a reply from Han Young in the ongoing thread about improving index file error reporting. The email points out a minor UX issue with Patrick Steinhardt's original patch that adds detailed lock failure reporting through `repo_hold_locked_index()`. While the patch correctly shows lock errors when they occur, it still shows the generic "could not write index" message afterward, which could be confusing since the actual failure was the lock acquisition rather than the write operation itself.

The observation suggests the current implementation doesn't properly distinguish between lock failures (now reported via `LOCK_REPORT_ON_ERROR`) and actual write failures, potentially leaving users to wonder whether two separate errors occurred. This doesn't affect the functionality but could be a polish issue in the error reporting flow. The thread so far has established the value of detailed lock error reporting and message standardization, and this email identifies one remaining rough edge in how those errors are presented to users. No solution is proposed in this email - it's purely an observation about the current patch's behavior. The comment doesn't reject the approach but notes an area where the error reporting could be made even clearer.
