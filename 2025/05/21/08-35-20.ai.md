This is a bugfix patch improving error reporting for index lock failures, part of a two-patch series that was originally started by Patrick Steinhardt. The patch modifies `repo_refresh_and_write_index()` in read-cache.c to propagate more detailed error messages when index locking fails.

The key change makes `repo_hold_locked_index()` report specific lock errors by passing the `LOCK_REPORT_ON_ERROR` flag when not in gentle mode, rather than silently returning -1. This addresses the current situation where commands like `git stash` would only print a generic "could not write index" message without indicating the root cause of the failure.

The implementation is straightforward - a one-line change that conditionally adds the error reporting flag based on the existing `gentle` parameter. This maintains backward compatibility while improving diagnostics in the non-gentle case. The patch appears well-scoped and focused, directly addressing the error reporting gap identified in the thread's original goal.

For future reference in this thread, the technical details include:
- Modified function: `repo_refresh_and_write_index()` in read-cache.c
- New flag usage: `LOCK_REPORT_ON_ERROR` passed to `repo_hold_locked_index()`
- Behavior change: Failed locks in non-gentle mode will now show detailed error messages
- Related commands affected: Any caller of `repo_refresh_and_write_index()` in non-gentle mode (like `git stash`)

The patch cleanly implements part of the series' goal to improve index operation error reporting, though it's worth noting this appears to be a new submission building on Patrick's original work rather than a direct continuation.
