This is a response to a proposal for a new Git helper tool. Junio C Hamano pushes back on Aditya Garg's suggestion for a `git imap-get-recipients` command that would extract email recipients from IMAP messages. The core concern is that the proposal lacks critical details about the data source and scope - it's unclear whether the tool would just copy recipients from the original message (which Junio considers insufficient) or also incorporate commenters from the discussion thread.

Junio emphasizes that for patch revisions, the recipient list should evolve based on who engaged with previous versions, not just replicate the initial To/Cc fields. He notes the current description is too vague to assess the tool's potential usefulness. The response concludes with Junio's general philosophy on contributions: developers should create tools they genuinely find valuable rather than seeking pre-approval, aiming to produce work compelling enough that the project would actively want to include it.

The exchange highlights the importance of considering thread participation in patch workflows and the Git project's preference for well-motivated, clearly-specified contributions.
