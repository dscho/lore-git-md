This is patch 2/5 in a completed v3 series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series has already been through extensive review with all major design decisions settled.

The patch introduces server-side support for advertising additional promisor remote fields beyond just name/url. A new `promisor.sendFields` config option lets servers specify which extra fields to send (currently supporting `partialCloneFilter` and `token`). The implementation:

- Defines allowed field names in a static array (`known_fields`)
- Adds `filter` and `token` fields to `struct promisor_info`
- Introduces field validation and config parsing helpers
- Updates protocol documentation with BNF notation and field rules
- Includes test coverage for field transmission scenarios

Key protocol behaviors:
- Servers MUST send name/url first, in that order
- Unknown fields are ignored (with warning) to allow future extensions
- Field values are URL-encoded
- Case-insensitive field name comparison

The test demonstrates proper transmission of configured fields while maintaining existing functionality. One minor note in the review points out that the test's `promisor.sendFields` config contains a space after the comma, triggering the unsupported field warning - this is harmless but could be cleaned up.

This patch provides the server-side foundation for the client-side validation that follows in later patches. The implementation aligns with the series' goal of enabling dynamic attribute verification while maintaining backward compatibility.
