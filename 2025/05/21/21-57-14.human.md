This is a discussion about a proposed Windows-specific feature patch. Brian m. carlson raises concerns about the patch that adds a tip about `git update-git-for-windows` to the help output.

The core objection is that this change shouldn't be in the main Git codebase since the update command is specific to Git for Windows, and other Windows builds (like Cygwin or MINGW) wouldn't have this command available. The argument is that this could mislead users of other Windows Git distributions into trying a command that won't work for them.

The response suggests this functionality should instead be maintained as a downstream patch in the Git for Windows project rather than upstream. This maintains a clean separation where platform-specific features stay with their respective distributions. The concern is particularly relevant since some users and organizations compile their own Windows binaries outside the Git for Windows ecosystem.

This appears to be a well-reasoned technical objection to the patch's approach, suggesting an alternative implementation path rather than rejecting the feature entirely. The discussion highlights the challenges of platform-specific features in a cross-platform codebase.
