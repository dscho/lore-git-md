Thread summary:

[Proposal] git imap-get-recipients helper for patch email workflows. Aditya Garg proposed a Perl script to extract To/Cc recipients from IMAP messages by message ID for use with `git send-email --to-cmd`, aiming to automate recipient population in patch revisions. Junio Hamano raised significant concerns about technical implementation (Perl dependency, unspecified authentication/mailbox selection) and philosophical alignment (whether copying To/Cc lists leads to suboptimal recipient selection), suggesting b4's thread-aware analysis might better serve the need.

Emily Shaffer clarified that Hamano's feedback should not be interpreted as outright rejection but rather as suggesting independent development first to demonstrate concrete value. Garg acknowledged this interpretation and agreed with Hamano's philosophical point about recipient selection needing more context than just previous round's addresses. While reconsidering the tool's design approach, Garg shows no immediate plans to continue development.

In the concluding message, Hamano acknowledges Shaffer's clarification and notes that even without full implementation, a clear design description could help evaluate the proposal's merits, while recognizing the chicken-and-egg problem of needing to show value before getting design attention. The thread leaves unresolved key questions about IMAP-based recipient lookup's alignment with Git's philosophy, technical implementation challenges (Perl dependencies, authentication handling), and whether this belongs in core Git versus external tools like b4. The discussion reaches a natural pause point, with no immediate path forward unless someone develops a more context-aware approach to recipient selection. No patches were submitted during this discussion.
