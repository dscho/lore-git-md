Thread summary:

Proposal] git imap-get-recipients helper for patch email workflows. Aditya Garg suggests adding a Perl script to extract To/Cc recipients from an IMAP message by message ID, intended for use with `git send-email --to-cmd` when sending patch revisions. The tool would automate recipient population currently done manually, mimicking GUI email client behavior. Junio Hamano raises significant concerns about the approach, questioning whether simply copying To/Cc lists from previous messages would lead to suboptimal recipient selection for patch revisions. He emphasizes v2 emails should consider both original recipients and commenters from the v1 thread, suggesting the tool might encourage lazy practices if it only replicates previous recipients without context.

Key technical gaps are identified: IMAP data source (personal mailbox vs public archive), authentication methods, and whether the tool would analyze just the original message or also its replies. Hamano notes these missing details make proper evaluation impossible. The response also includes a broader philosophical point about Git's contribution approach - tools should prove their value through implementation rather than theoretical discussion, following the "make us come to you begging" principle.

The current status is that the proposal is effectively on hold until more concrete implementation details and use cases can be demonstrated. The thread remains open for Aditya to address these concerns with a revised proposal or prototype. No patches have been submitted yet; this remains a discussion of the concept's fit with Git's email-based workflow.
