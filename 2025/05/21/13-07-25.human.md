This is a technical discussion about PATH handling in Git's child process execution, specifically addressing concerns about Windows Unicode compatibility and broader design questions.

Phillip Wood responds to Patrick Steinhardt's feedback on the patch series that removes git_exec_path() from non-Git commands' PATH. While agreeing with some concerns, Phillip raises two key counterpoints: First, he questions the reliability of using git's executable location to find related tools like git-jump, noting their installation locations vary by distribution. Second, he argues PATH modification may still be necessary for certain Git operations (hooks, aliases, rebase --exec) to ensure child processes use the same Git executable as the parent.

The discussion reveals deeper questions about the patch series' approach - whether PATH modification should be opt-in rather than opt-out, and whether it's needed at all given modern Git's execution model. Phillip's comments add weight to the need for careful consideration of edge cases, particularly around hooks and aliases, while maintaining Windows Unicode compatibility.
