This is a follow-up in the name-hash sparse directory bugfix thread, where Alex Mironov responds to Derrick Stolee's review comments. The original patch prevents sparse directories from being added to the name_hash table during multithreaded initialization, mirroring existing single-threaded behavior.

Alex confirms this is primarily a performance fix, but reveals additional context about their organization's custom sparse checkout implementation that keeps files outside sparse cones on disk. This setup causes Git to frequently expand the full index despite `sparse.expectFilesOutsideOfPatterns=true`, particularly problematic with the multithreaded lazy load path that activates only for large indexes.

The email hints at future work to improve `sparse.expectFilesOutsideOfPatterns` handling across other expansion cases, asking whether to use the existing config option or introduce a new one. This suggests the current patch may be the first in a series addressing sparse index behavior in non-standard sparse checkout scenarios.

Key technical details carried forward:
- The fix modifies `name-hash.c`'s threaded initialization path
- Involves `S_ISSPARSEDIR` checks similar to commit 5f116695864
- Relates to `sparse.expectFilesOutsideOfPatterns` configuration
- Performance impact could be measured via `p2000-sparse-operations.sh`
