This is a follow-up discussion on patch 3/6 of a documentation series about git-notes options. Junio Hamano acknowledges the patch's changes to split combined `--[no-]option` forms into separate entries, which he approves as "OK". However, he notes an existing documentation gap regarding the default behavior of `--stripspace` that isn't addressed in this series.

Junio observes that while the patch correctly separates the `--stripspace` and `--no-stripspace` options, the surrounding documentation doesn't clearly explain their default behavior. He recalls from memory that the default is to strip whitespace unless the message comes from an existing note, but suggests this verification and documentation could be handled separately by another contributor.

The exchange shows this minor documentation gap was identified during review but deliberately left for future work, as the current series focuses on restructuring option documentation rather than exhaustively documenting all behaviors. Junio's tone is constructive, treating this as a known limitation rather than a blocker for the current changes.
