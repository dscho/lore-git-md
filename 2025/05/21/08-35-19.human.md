This is a two-patch series improving error reporting for index file operations, primarily focused on making lock failures more visible and standardizing error messages.

The first patch addresses a case where index write failures (particularly lock failures) are silently swallowed in `repo_refresh_and_write_index()`. Currently callers just see a generic "could not write index" message. The patch makes `repo_hold_locked_index()` report the actual lock error when one occurs, which should help diagnose filesystem permission issues or other locking problems.

The second patch standardizes the various error messages shown when index writing fails across different commands. Currently there are three different phrasings in use ("could not write index", "unable to write index file", and "Unable to write index."). The patch makes them all use the most common variant ("could not write index") for consistency.

The changes are straightforward and mechanical, touching only a handful of files. The motivation is clear - better error reporting and message consistency - though the impact is modest since this doesn't change any actual behavior, just how failures are communicated. The patches appear cleanly implemented with appropriate test coverage implied by the existing error cases they modify.
