Thread summary:

This thread introduces a two-patch series improving error reporting for index file operations, particularly lock failures. The series originates from Patrick Steinhardt and targets the read-cache.c and related command implementations.

The core goal is to enhance diagnostic clarity when index operations fail by:
1. Making `repo_hold_locked_index` report specific lock errors rather than silently returning -1
2. Standardizing the error message phrasing across commands to consistently use "could not write index"

Key technical details:
- Modifies `repo_refresh_and_write_index` in read-cache.c to propagate lock errors
- Touches error paths in builtin/am.c, builtin/commit.c, builtin/merge.c, and merge-ort.c
- Unifies three existing message variants ("could not write index", "unable to write index file", "Unable to write index.") to one standard form

The changes are focused quality-of-life improvements with no behavioral changes beyond error reporting. The series is at v1 with no reviews or feedback recorded yet. All modifications are straightforward string changes and error handling additions in the index writing paths of several core commands.
