Bugfix completing the sparse directory handling in Git's threaded name-hash initialization. This is the third version of a patch that ensures sparse directories (those outside the sparse-checkout definition) are excluded from the name_hash table in multithreaded operations, matching the behavior already implemented for single-threaded cases.

The change is small but important - it adds a condition in `lazy_name_thread_proc()` to skip hash table insertion for sparse directory entries (marked with S_ISSPARSEDIR). This prevents filling the table with unnecessary entries that would never be queried, while maintaining correct behavior for case-insensitive lookups via the directory hashtable.

The patch follows the pattern established in commit 5f11669586 for the single-threaded path. Discussion in previous versions established technical consensus, with this version addressing feedback about improving the commit message structure. The change has negligible performance impact in normal cases but ensures correctness, particularly for edge cases involving sparse.expectFilesOutsideOfPatterns.
