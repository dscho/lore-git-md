This is a two-patch series addressing error reporting in index file operations, primarily focused on lock failures and message consistency.

The first patch modifies `repo_refresh_and_write_index` in read-cache.c to have `repo_hold_locked_index` report lock errors when they occur, rather than silently returning -1. Currently, commands like `git stash` just print a generic "could not write index" message when index operations fail, which doesn't help diagnose locking issues specifically.

The second patch standardizes the error messages across various commands when index writing fails. There are currently three different phrasings in the codebase ("could not write index", "unable to write index file", and "Unable to write index.") which the patch unifies to the most commonly used "could not write index" variant.

The changes touch several key commands (am, commit, merge) and the merge-ort infrastructure. The modifications are straightforward string changes and error handling additions, with no behavioral changes beyond the improved error reporting. The series appears to be a focused quality-of-life improvement for debugging index-related issues.
