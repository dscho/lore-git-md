Bugfix completing the sparse directory name-hash correction for threaded initialization. This v3 patch from Alex Mironov finalizes the fix to prevent sparse directories from being incorrectly added to the name_hash table during multithreaded initialization, mirroring the behavior already established for single-threaded cases in commit 5f11669586.

The change modifies lazy_name_thread_proc() in name-hash.c to skip hash table insertion when encountering directory entries marked with S_ISSPARSEDIR. This matches the existing single-threaded behavior and maintains consistency between both initialization paths. The patch avoids filling the name_hash with entries that would never be queried, though performance impact in normal cases is negligible.

Key technical points:
- Adds a condition check for S_ISSPARSEDIR before hashmap operations
- Maintains the CE_HASHED flag setting for all entries
- Follows the pattern established by the single-threaded fix
- Only affects the threaded initialization path in name-hash.c

The v3 revision addresses Junio Hamano's request for a more specific commit message, now clearly explaining why sparse directories should be excluded (they represent paths outside sparse-checkout definitions and aren't blob paths) and where they should go instead (the directory hashtable for ignore_case scenarios).
