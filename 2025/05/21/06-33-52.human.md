This is a discussion about naming and potential optimizations for the promisor-remote protocol series, specifically addressing patch 1/5 which refactors the code to use `struct promisor_info` instead of `struct strvec`.

Christian Couder responds to Junio Hamano's naming suggestions for a helper function, agreeing to use either `promisor_info_find()` or `promisor_info_find_by_name()` in the next version of the patch. The discussion clarifies that promisor_info instances are not primarily found by name, but are iterated over in various ways (for generating advertisements and checking field matches).

Junio had raised the possibility of using strmap or string_list for optimization, but Christian argues this isn't currently worthwhile since the number of promisor remotes is typically small. This is a minor refinement discussion in an otherwise finalized series - the core functionality and improvements from v2 (better structure, documentation, tests) remain unchanged. The exchange shows the project's attention to naming consistency even in late-stage reviews.
