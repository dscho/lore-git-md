This is a bugfix patch addressing an issue with sparse directories in the threaded name-hash initialization. 

The patch ensures sparse directory entries (which represent directories outside the sparse-checkout definition) are not added to the name_hash table during multithreaded initialization, mirroring the behavior already implemented for single-threaded cases in commit 5f11669586. 

The change is straightforward - it adds a check to skip S_ISSPARSEDIR entries in the threaded initialization path, just before adding entries to the name_hash. This prevents unnecessary additions since these directory entries should never be queried through the name_hash mechanism.
