This is a follow-up in the sparse directory name-hash thread, clarifying the performance impact of the proposed fix. Alex Mironov responds to Derrick Stolee's review, confirming this is indeed a performance optimization and sharing additional context about their organization's specific sparse-checkout setup that makes the fix particularly valuable.

The key new information is that the patch helps address performance issues in a custom sparse-checkout implementation where files outside sparse cones remain on disk. This causes Git to frequently expand the full index despite `sparse.expectFilesOutsideOfPatterns` being set. Mironov notes the problem was hard to detect because the multithreaded lazy load only triggers above a certain index size threshold.

Mironov also signals intent to submit more patches to improve handling of `sparse.expectFilesOutsideOfPatterns` across other expansion cases, asking whether these should use the existing config option or a new one. The discussion remains focused on optimization rather than correctness, with the original technical solution (excluding sparse directories from name-hash) already agreed upon by all parties.

The exchange suggests this is part of ongoing work to refine sparse-checkout behavior, particularly in edge cases where files outside sparse definitions remain present. The patch itself appears ready to merge pending commit message refinements, with future related improvements likely to follow.
