This is a response to a newcomer's patch attempting to fix -Wsign-compare warnings in log-tree.c. Junio Hamano explains why both proposed changes are problematic and argues against blindly silencing these compiler warnings.

For the first change (changing a loop counter to unsigned long), Junio notes the array size is small and the compiler warning is effectively a false positive. He maintains the existing int type is correct and safe in this context.

The second change (adding a cast in fmt_output_subject) is called out as actively wrong, potentially hiding real overflow issues. Junio suggests the proper fix would involve using size_t consistently throughout the length calculations in that function.

The response includes broader critique of -Wsign-compare warnings in general, calling them "mostly garbage" and suggesting the microproject task encouraging these fixes should be removed. Despite rejecting the technical approach, Junio makes a point to welcome the new contributor and separate the critique of the code from the person submitting it.

This email effectively closes the discussion on this particular warning fixes while opening a side discussion about whether such warning-cleanup tasks should be offered to newcomers at all. The tone is firm on technical merits but intentionally encouraging to the contributor.
