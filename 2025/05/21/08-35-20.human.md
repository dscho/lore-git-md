Bugfix improving index lock error reporting. This is the first patch in a two-part series (previously introduced by Patrick Steinhardt) that aims to provide better diagnostics when index operations fail.

The patch modifies `repo_refresh_and_write_index()` in read-cache.c to make it report specific lock errors via `repo_hold_locked_index()` rather than silently returning -1. The key addition is passing `LOCK_REPORT_ON_ERROR` when not in gentle mode, which will cause the underlying lock function to emit error messages explaining why locking failed.

Currently, commands like `git stash` just print a generic "could not write index" message when index operations fail, which makes troubleshooting difficult. This change ensures the actual locking error gets reported to users while maintaining the same behavior when operating in "gentle" mode.

The change is small (just one line modified) but targeted at a real pain point - understanding why index operations fail. It fits cleanly into the broader series goal of improving error reporting consistency across Git commands. The patch appears well-scoped and follows the established pattern of the surrounding code.
