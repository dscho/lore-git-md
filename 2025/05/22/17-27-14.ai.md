This is a feature and bugfix series targeting the `imap-send` command, which appears to have been largely unmaintained. The cover letter outlines two main goals: fixing a configuration parsing bug that made the command unusable, and adding OAuth2.0 authentication support.

The first patch fixes a specific bug where the IMAP folder configuration was incorrectly being set to NULL during config parsing. This appears to be a straightforward bugfix for functionality that was previously broken.

The second patch is more substantial, adding OAuth2.0 authentication support to `imap-send`. The implementation touches documentation (adding new config options in `imap.adoc` and command usage in `git-imap-send.adoc`) and makes significant changes to `imap-send.c` (adding ~150 lines of new code). The OAuth2.0 appears to be implemented with new config options for client ID, client secret, and refresh token.

Key technical details for future reference:
- Configuration changes include new `imap.oauth2ClientId`, `imap.oauth2ClientSecret`, and `imap.oauth2RefreshToken` options
- The implementation appears to use the standard OAuth2.0 refresh token flow
- Documentation updates explain both the fixed configuration syntax and new OAuth2.0 usage
- The changes are self-contained to the IMAP subsystem with no apparent cross-component impacts

The series seems well-structured with clear separation between the bugfix and feature addition. The author notes surprise at the command's existence, suggesting it may not be widely used, which could affect review priority. The OAuth2.0 implementation in particular may warrant security scrutiny given its authentication handling.
