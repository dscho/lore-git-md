Bugfix discussion in the imap-send memory safety thread. This email corrects an earlier suggestion by Eric Sunshine regarding the CRAM-MD5 authentication path in `imap-send.c`, where he had recommended unconditionally freeing the `response` buffer after socket write but before checking the return value. Jeff King points out this would create a use-after-free when comparing the return value against the response length. The correct approach requires storing `strlen(response)` in a local variable before freeing the buffer.

This exchange demonstrates the careful attention being paid to memory management in the authentication paths of this legacy code. The thread has seen multiple iterations of fixes for the IMAP subsystem, with particular focus on resource management corner cases. The current state leaves the CRAM-MD5 fix needing to store the length before free, while other potential leaks in `cfg->host` and `server_fill_credential()` remain unaddressed in this series.
