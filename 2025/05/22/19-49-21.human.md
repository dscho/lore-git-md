This is a follow-up in the ongoing `imap-send` OAuth2.0 support thread, addressing concerns about OpenSSL dependencies. The original patch added OAuth2.0 authentication using OpenSSL for base64 encoding, but Brian Carlson raised legal distribution concerns for Git when linked with OpenSSL.

Aditya Garg responds that version 2 of the patch will instead use curl's dedicated OAuth2.0 API, avoiding the OpenSSL dependency entirely. This appears to be a clean solution to the licensing concern while maintaining the same functionality. The approach aligns with Carlson's earlier suggestion to either implement a custom base64 encoder or delegate to credential helpers, though it takes a third path by leveraging curl's existing capabilities.

The thread shows good responsiveness to technical and legal constraints, with the author quickly pivoting to a more maintainable solution. This follow-up suggests the OAuth2.0 feature is progressing well through the review process, with major architectural concerns being addressed.
