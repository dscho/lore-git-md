This is a bugfix addressing file mode handling in `git apply --reverse`. 

Mark Mentovai fixes a case where reversing a patch that deletes an executable file would fail to restore the executable permission when recreating the file. The issue stems from commit 01aff0a (2023) which correctly handled most mode bit reversals but missed this specific deletion-then-recreation case. The fix is straightforward - modifying `reverse_patches()` in apply.c to properly swap mode bits when reversing deletions.

The patch includes extensive new test coverage that verifies `git apply` handles file modes correctly in both forward and reverse operations. The tests systematically check mode preservation through file creation, modification, deletion, and their reversals. The change is small (a one-line logic modification) but important for maintaining correct file permissions when using `--reverse`.
