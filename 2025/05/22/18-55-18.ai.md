Build system improvement addressing a developer workflow issue with compilation databases. This patch from Brian Carlson fixes unnecessary rebuilds when `GENERATE_COMPILATION_DATABASE=yes` is set, which currently causes the entire codebase to recompile on subsequent `make` runs due to timestamp updates in the `compile_commands` directory.

The change applies the same pattern used for `.depend` directory handling - filtering out the compilation database directory from rebuild targets if it already exists. This prevents the directory's modification from triggering full rebuilds while maintaining the LSP/clangd functionality that many developers rely on for code navigation features.

The one-line Makefile modification is straightforward and follows established patterns in the build system. Philippe Blain is credited for helping with the solution. While this doesn't affect runtime behavior or end-user functionality, it significantly improves the contributor experience for those using language server tooling.

This appears completely separate from the ongoing stash import/export thread mentioned in the context - it's a self-contained build system tweak with clear motivation and a simple, focused implementation. The patch seems ready for inclusion with no apparent controversy or technical concerns.
