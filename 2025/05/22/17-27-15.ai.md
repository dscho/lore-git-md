Bugfix for the `imap-send` command, correcting a long-standing configuration parsing error. The patch fixes a case where setting common IMAP configuration options (`imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`) would incorrectly NULL out the `cfg->folder` field instead of the intended target field. This caused the command to fail with a "no imap store specified" error, effectively rendering it unusable when these options were set.

The bug appears to have gone unnoticed due to `imap-send` being rarely used compared to alternatives like `git send-email`. The fix is straightforward - changing four instances where `cfg->folder` was incorrectly freed to instead free the corresponding field being set (`user`, `pass`, `tunnel`, `auth_method`). The changes are confined to `imap-send.c` with no behavioral changes beyond fixing the configuration parsing.

This is the first patch in a two-part series that also adds OAuth2.0 support to `imap-send`. While this particular fix is simple and clearly correct, the overall series may warrant attention given the security implications of authentication changes to the IMAP subsystem. The author notes the command's low usage, which may affect review priority despite the clear bug being fixed here.
