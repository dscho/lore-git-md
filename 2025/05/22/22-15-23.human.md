Bugfix proposal for smudge/clean filter handling of empty files. Jeff King responds to Joey Hess's report about inconsistent behavior when using content filters with empty files, where `git diff` shows false changes despite a clean working tree.

The issue stems from `ce_match_stat_basic()` incorrectly handling empty files when smudge/clean filters are involved. The current code checks if the repository blob is empty, but this doesn't account for cases where filters transform empty files to/from non-empty content. Jeff identifies the problematic check from 2008's f49c2c22fe that was designed to handle racy conditions but doesn't consider filter transformations.

Jeff proposes a tentative fix that would check the expected working tree content by running the smudge filter on the repository blob, though he notes this approach feels "very dirty" and may have performance implications. The patch demonstrates the concept but lacks proper error handling. Jeff expresses uncertainty about the best solution, hoping for input from others more familiar with the index or filter systems, as there are edge cases where files should have content in the worktree but are cleaned to empty in the repository.

This appears to be a genuine edge case in Git's filter processing that could affect any smudge/clean filter scenario involving empty files. The proposed solution would be invasive to the index handling code, suggesting this may need careful review from core Git maintainers.
