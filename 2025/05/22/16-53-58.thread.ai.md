Summary of thread: HEAD.lock contention between user operations and maintenance

Thread identity: Bug report about HEAD.lock contention between Git operations and maintenance processes, originating from a user experiencing failures after upgrading from Git 2.39.5 to 2.47.2.

Core problem: User's automated system intermittently fails during `git checkout b2` due to HEAD.lock contention, traced via GIT_TRACE_PERFORMANCE to Git's auto-maintenance running in detached mode. The maintenance process appears to acquire HEAD.lock, conflicting with concurrent checkout operations. The version change (2.39.5->2.47.2) suggests this behavior may be related to maintenance changes in recent Git versions.

Current status: Open question whether this is expected behavior (maintenance legitimately taking locks) or a bug in lock contention handling. No maintainer response yet.

Key technical details: 
- Reproduction involves concurrent checkout and maintenance operations
- Maintenance runs in detached mode during fetch-triggered auto-maintenance
- HEAD.lock contention observed between these operations
- Workaround proposed: setting maintenance.autoDetach=false

Open questions:
