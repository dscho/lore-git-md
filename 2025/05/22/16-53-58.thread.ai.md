Summary of thread: HEAD.lock contention between user operations and maintenance

Thread identity: Bug report and now proposed fix for HEAD.lock contention between Git operations and maintenance processes, originating from a user experiencing failures after upgrading from Git 2.39.5 to 2.47.2, with Patrick Steinhardt now engaged.

Core problem: Race condition where maintenance in detached mode (`--auto --detach`) spawns git-gc which locks packed-refs, conflicting with concurrent ref-modifying operations like checkout. The version change (2.39.5->2.47.2) suggests this behavior relates to maintenance changes in recent Git versions.

Current status: Patrick Steinhardt confirms this is a known race condition and proposes a proper fix. The thread has moved from diagnosis to solution proposal stage, with a patch series expected.

Key technical details:
- Reproduction involves concurrent checkout and maintenance operations
- Maintenance runs in detached mode during fetch-triggered auto-maintenance
- HEAD.lock contention occurs between git-gc's packed-refs locking and user operations
- Current workaround: adjust `core.packedRefsTimeout` (masks but doesn't fix)
- Proposed solution: modify git-maintenance to run ref-packing tasks pre-daemonization
- Expected behavior change: maintenance caller will wait for ref packing completion
