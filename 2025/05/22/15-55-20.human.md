This is the first patch in a bugfix series addressing integer overflow issues in Git's multi-pack-index repack functionality, particularly affecting 32-bit systems like Raspberry Pi. The patch fixes a specific crash that occurs when running `git multi-pack-index --repack --batch-size=120M` on 32-bit systems, where size calculations would overflow.

The core issue involves two overflow scenarios in the midx repack calculations. First, multiplying pack size by referenced objects could overflow 32-bit size_t values. Second, adding estimated sizes could overflow when batch sizes approach SIZE_MAX/2. The solution introduces 64-bit arithmetic operations (u64_mult and u64_add) in git-compat-util.h and uses them in midx-write.c, with saturating arithmetic for the addition case to prevent overflow.

This is version 2 of the patch, incorporating feedback from the initial submission. The commit message now explicitly addresses safety concerns about size_t casting and includes a more thorough explanation of the overflow scenarios. The changes are focused and well-explained, with clear motivation from real-world failure cases. The patch appears technically sound and addresses a concrete problem that affects users on 32-bit systems.
