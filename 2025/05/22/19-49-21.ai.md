This is a follow-up in the ongoing `imap-send` OAuth2.0 support thread, specifically addressing Brian Carlson's concerns about OpenSSL dependencies in the base64 encoding implementation for OAuth2.0 authentication. Aditya Garg proposes an alternative approach using curl's dedicated OAuth2.0 API for the v2 patch series, which would avoid the OpenSSL licensing issues entirely.

The key technical pivot here is moving from an OpenSSL-based implementation (using `EVP_EncodeBlock` for base64 encoding of OAuth tokens) to leveraging curl's native OAuth support. This addresses Carlson's legal concerns about OpenSSL distribution while maintaining the same functionality. The original implementation had shown the base64 encoding was the only OpenSSL dependency in the OAuth2.0.

This response indicates the v2 series will take one of two paths Carlson suggested - either implementing a custom base64 encoder (like the one in mailinfo.c) or delegating to credential helpers - by instead using curl's built-in capabilities. The thread continues to focus on finding the most maintainable, legally sound approach to OAuth2.0 support while preserving the authentication functionality.

The discussion remains focused on architectural decisions rather than implementation details at this point, with the author signaling a significant implementation change in response to review feedback about OpenSSL dependencies. This keeps the OAuth2.0 feature moving forward while addressing distribution concerns.
