Thread identity: Performance regression report about `git status` being slow with hard-linked large files (1GB+) in working directories, even when files are in `.gitignore`. Reporter provides reproduction showing 16s vs 2ms difference between hard links and regular copies.

Core problem: Git appears to perform full index refreshes when encountering hard links to large files (even ignored ones), while skipping this for regular copies. This creates significant performance penalty for workflows using hard links for space efficiency with large files.

Current status: Initial bug report with clear reproduction on Git 2.49.0. No maintainer response or analysis yet. Test case demonstrates the issue doesn't require git-lfs and shows exact timing difference (16s vs 2ms).
