This is the first patch in a bugfix series addressing integer overflow issues in multi-pack-index repack functionality, particularly affecting 32-bit systems. The patch specifically fixes an overflow that occurs when calculating estimated object sizes during repacking with large batch sizes on 32-bit platforms.

The core issue manifests when running `git multi-pack-index --repack --batch-size=120M` on 32-bit systems, where size_t arithmetic overflows during pack size calculations. The solution introduces 64-bit arithmetic operations (u64_mult and u64_add) in git-compat-util.h and updates midx-write.c to use these safe operations. The patch also handles potential overflow in the total_size accumulation by using saturating arithmetic that caps at SIZE_MAX.

Key technical details include:
- New utility functions u64_mult() and u64_add() for overflow-safe arithmetic
- Conversion of pack size calculations from st_mult() to uint64_t operations
- Careful handling of size_t casting safety in the commit message
- Protection against overflow when summing estimated sizes that could exceed SIZE_MAX/2
