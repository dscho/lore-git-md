Feature and bugfix series for the largely unmaintained `imap-send` command, addressing configuration parsing bugs, memory leaks, and adding OAuth2.0 authentication support. The first patch fixed incorrect NULL assignments in `git_imap_config()` where `imap.folder` was mistakenly cleared when appearing before other IMAP options (`imap.user`, `imap.pass`, etc.) in a subtle order-dependent bug that Jeff King precisely characterized. Aditya Garg confirms in this follow-up that v2 will document the bug's origin in commit 6d1f198f34 ("imap-send: fix leaking memory in `imap_server_conf`", 2024-06-07) and the order-dependent behavior, addressing Junio Hamano and Eric Sunshine's emphasis on proper documentation. Hamano's observation about the lack of user reports suggests either minimal `imap-send` usage since mid-2024 or that affected users didn't notice the issue.

The second patch implemented OAuth2.0 support with OAUTHBEARER and XOAUTH2 mechanisms, adding three new config options and credential helper integration in ~150 lines of new `imap-send.c` code. Garg notes progress testing OAuth2.0 with curl's API, though this remains separate from the immediate patch updates. Documentation updates cover both the configuration syntax fix and new OAuth2.0 support.

Memory leak fixes progressed through multiple iterations: the CRAM-MD5 authentication path fix saw detailed discussion between Garg, Sunshine, and Peff. Garg initially proposed adding a `free(response)` in the error path, Sunshine suggested unconditionally freeing after socket write, but Peff identified this would create a use-after-free when checking the return value against response length. The correct approach requires storing `strlen(response)` before freeing.

Open items: the configuration fix's v2 commit message is pending with the 6d1f198f34 regression documentation, the OAuth2.0 implementation awaits security-focused review (possibly benefiting from curl's authentication APIs), and potential leaks in `cfg->host` and `server_fill_credential()` remain unaddressed. Key technical details include the OAUTHBEARER/XOAUTH2 credential helper integration, precise CRAM-MD5 response buffer management (now requiring storage of length before free), and configuration parsing behavior where option order affects `imap.folder` clearing. The thread shows incremental hardening of the IMAP subsystem through review-fix cycles between Garg, Sunshine, King, and Hamano, with particular attention to memory safety corner cases in authentication paths and proper documentation of bug origins.
