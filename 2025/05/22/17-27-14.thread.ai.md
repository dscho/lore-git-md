Feature and bugfix series for the largely unmaintained `imap-send` command, addressing two main goals: fixing a configuration parsing bug and adding OAuth2.0 authentication support. The first patch fixes a bug where common IMAP configuration options (`imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`) incorrectly NULLed out `cfg->folder` instead of their intended target fields, causing "no imap store specified" errors. The fix changes four instances in `imap-send.c` to free the correct fields.

The second patch completes the series by implementing OAuth2.0 support with both RFC-standard OAUTHBEARER and Google's XOAUTH2 mechanisms. It adds three new authentication-related capabilities to the IMAP protocol handler (AUTH_OAUTHBEARER, AUTH_XOAUTH2) with corresponding base64 encoding functions (`oauthbearer_base64()`, `xoauth2_base64()`). The ~150 lines of new functionality in `imap-send.c` include full token flow implementation, new config options (`imap.oauth2ClientId`, `imap.oauth2ClientSecret`, `imap.oauth2RefreshToken`), and credential helper integration. Documentation updates in `imap.adoc` and `git-imap-send.adoc` cover both the fixed configuration syntax and new OAuth2.0 usage for Gmail/Outlook, with warnings about OpenSSL requirements and noted libcurl bugs (recommending `--no-curl` fallback).

The series remains self-contained to the IMAP subsystem but touches sensitive authentication paths. The author acknowledges the command's low usage may affect review priority and that the OAuth2.0 implementation may require security scrutiny. No reviews or acks yet for either patch. The work presents a clear bugfix alongside substantial modernizing feature work, with the authentication changes likely to generate more discussion around token handling and dependency requirements.
