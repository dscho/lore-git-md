Feature and bugfix series for `imap-send` now complete in v3, addressing configuration parsing bugs, memory leaks across all authentication methods (CRAM-MD5, OAuth2.0), and OAuth2.0 support via curl's native API (OAUTHBEARER/XOAUTH2). The architectural shift from OpenSSL-dependent approach (v1) to curl-native implementation (v2-v3) was driven by Brian Carlson's licensing concerns. Series contains three patches: (1) fixing order-dependent NULL assignments in config parsing (technically approved by Junio Hamano), (2) RFC-compliant OAuth2.0 with provider-specific handling (Gmail/Outlook), and (3) complete CRAM-MD5 memory leak fixes including error path cleanup, now adding final `response` buffer cleanup when `socket_write()` fails.

Key technical details:
- Configuration parsing robustly handles all IMAP settings (`imap.folder`, `imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`) regardless of option order, fixing regression from commit 6d1f198f34 where setting certain fields would incorrectly NULL out `cfg->folder`
- Fix replaces incorrect `FREE_AND_NULL(cfg->folder)` calls with proper field-specific cleanup for each configuration option (`user`, `pass`, `tunnel`, `auth_method`), maintaining intended memory management while preventing accidental clearing of unrelated fields
- OAuth2.0 implementation now complete with `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` capability flags and handlers (`auth_oauthbearer()`, `auth_xoauth2()`), using curl's `CURLOPT_XOAUTH2_BEARER` with proper RFC 5801/7628 compliance and OpenSSL fallback paths via `oauthbearer_base64`/`xoauth2_base64` helpers
- CRAM-MD5 fixes now fully comprehensive with brace standardization to avoid `-Wunreachable-code` warnings and complete `response` buffer cleanup in all paths (including new `socket_write()` failure case)
- Documentation covers both configuration behavior and OAuth2.0 requirements (app-specific passwords, provider quirks like Gmail's localized folder names and Outlook's XOAUTH2 requirement)
