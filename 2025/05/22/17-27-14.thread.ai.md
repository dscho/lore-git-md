Feature and bugfix series for `imap-send` now in v4, completing configuration parsing fixes and authentication support expansion. The series addresses: (1) critical configuration parser bug where `cfg->folder` was incorrectly NULLed out when other IMAP settings were modified (regression from 6d1f198f34), (2) OAuth2.0 support via curl's native API (OAUTHBEARER/XOAUTH2) as architectural shift from OpenSSL, (3) new PLAIN authentication method for OpenSSL users (RFC 4616 compliant via `plain_base64()` helper and `auth_plain()` handler), (4) comprehensive CRAM-MD5 memory leak fixes including all error paths, and (5) provider-specific documentation for Gmail/Outlook quirks.

Key regression fix corrects configuration parsing where modifying any IMAP setting would incorrectly NULL out `cfg->folder` due to copy-paste errors in the parser. This standalone fix (first patch in series) addresses severe usability issues that made `git-imap-send` completely unusable when changing settings.

Key technical details:
- Configuration parsing robustly handles all IMAP settings (`imap.folder`, `imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`) with proper field-specific cleanup
- OAuth2.0 implementation maintains RFC 5801/7628 compliance via curl's `CURLOPT_XOAUTH2_BEARER` with OpenSSL fallback paths (`oauthbearer_base64`/`xoauth2_base64` helpers)
- New PLAIN authentication (`auth_plain()`) implements RFC 4616 via `plain_base64()` helper, adding `AUTH_PLAIN` capability for OpenSSL users
- CRAM-MD5 fixes now fully comprehensive with complete `response` buffer cleanup in all paths
- Documentation covers all authentication methods (PLAIN, CRAM-MD5, OAUTHBEARER, XOAUTH2) and provider-specific requirements
- New capabilities `AUTH_OAUTHBEARER`, `AUTH_XOAUTH2`, and `AUTH_PLAIN` added to IMAP protocol handling
- Authentication logic split between curl-native path (preferred) and OpenSSL-compatible base64 encoding
