Feature and bugfix series for the largely unmaintained `imap-send` command, addressing configuration parsing bugs, memory leaks, and adding OAuth2.0 authentication support. The first patch fixed incorrect NULL assignments in `git_imap_config()` where `imap.folder` was mistakenly cleared when appearing before other IMAP options (`imap.user`, `imap.pass`, etc.) in a subtle order-dependent bug that Jeff King precisely characterized. Aditya Garg acknowledged the need for commit message refinement to accurately describe this behavior, with Eric Sunshine confirming the fix while identifying related memory leaks.

The second patch implemented OAuth2.0 support with OAUTHBEARER and XOAUTH2 mechanisms, adding three new config options and credential helper integration in ~150 lines of new `imap-send.c` code. Documentation updates covered both the configuration syntax fix and new OAuth2.0 support.

Memory leak fixes progressed through multiple iterations: the CRAM-MD5 authentication path fix saw detailed discussion between Garg, Sunshine, and Peff. Garg initially proposed adding a `free(response)` in the error path, Sunshine suggested unconditionally freeing after socket write, but Peff identified this would create a use-after-free when checking the return value against response length. The correct approach requires storing `strlen(response)` before freeing. This exchange demonstrates the thread's technical rigor around resource management in legacy code.

Open items remain: the configuration fix's commit message needs updating to reflect the order-dependent `imap.folder` bug, the OAuth2.0 implementation awaits security-focused review, and potential leaks in `cfg->host` and `server_fill_credential()` remain unaddressed. Key technical details include the OAUTHBEARER/XOAUTH2 credential helper integration, precise CRAM-MD5 response buffer management (now requiring length storage before free), and configuration parsing behavior where option order affects `imap.folder` clearing. The thread shows incremental hardening of the IMAP subsystem through review-fix cycles between Garg, Sunshine, and King, with particular attention to memory safety corner cases in authentication paths.
