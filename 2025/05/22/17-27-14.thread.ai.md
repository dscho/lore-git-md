Feature and bugfix series for the largely unmaintained `imap-send` command, addressing configuration parsing bugs, memory leaks, and adding OAuth2.0 authentication support. The first patch fixed incorrect NULL assignments in `git_imap_config()` where four IMAP options were mistakenly clearing `cfg->folder` instead of their target fields. Eric Sunshine's review confirmed the fix but identified related memory leak issues, suggesting referencing commit 6d1f198f34 as the source of these copy/paste bugs, flagging a possible `cfg->host` leak, and raising questions about `server_fill_credential()` leaks. Aditya Garg responded by agreeing to reference the commit and acknowledging the additional leaks as potential follow-up work.

The second patch implemented OAuth2.0 support with OAUTHBEARER and XOAUTH2 mechanisms, adding three new config options and credential helper integration in ~150 lines of new `imap-send.c` code. Documentation updates covered both the configuration syntax fix and new OAuth2.0 support.

A follow-up bugfix addresses memory leaks in the CRAM-MD5 authentication path, where the `auth_cram_md5()` function was leaking the 'response' buffer when `socket_write()` failed. The fix adds the missing `free()` call before returning the error. This continues the thread's focus on memory safety in the historically neglected `imap-send` component, revealing deeper questions about memory management patterns in this codebase.

Open items remain: the configuration fix awaits commit message updates referencing 6d1f198f34, the OAuth2.0 implementation needs security-focused review, and potential leaks in `cfg->host` and `server_fill_credential()` identified by Sunshine remain unaddressed. The thread demonstrates careful attention to memory safety in legacy code, with Eric Sunshine providing detailed review and Aditya Garg responding to feedback while incrementally hardening the subsystem.
