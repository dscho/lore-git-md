Bugfix for file mode handling in `git apply --reverse`. This patch addresses an edge case where reversing a patch that deletes an executable file would fail to restore the executable permission when recreating the file.

The issue stems from commit 01aff0a (2023-12-26) which correctly handled mode bit preservation in most cases but missed the special case of file deletions. When reversing a deletion (which becomes a creation), the mode bits were not being properly transferred from the patch metadata to the newly created file. The fix modifies `reverse_patches()` in apply.c to also swap mode bits when processing deletions.

The patch includes extensive new test coverage in t/t4129-apply-samemode.sh that verifies correct mode handling in both forward and reverse operations. Tests cover:
- Normal file creation with modes
- Mode changes to existing files
- File deletions and their reversal
- Interaction with core.fileMode configuration
- All operations in both working tree and index

The tests follow a careful progression that first establishes baseline behavior for forward operations before testing the reverse cases. Each test validates both the working tree state and index state after operations. The test names clearly indicate their purpose ("git apply restores file modes" and "git apply --reverse restores file modes").

This appears to be a well-constructed fix for a subtle edge case, with thorough test coverage that should prevent regression. The commit message clearly explains the problem and solution, referencing the prior commit that introduced the partial handling. The change itself is minimal (a one-line logic modification) but important for correct behavior when reversing patches that delete executable files.
