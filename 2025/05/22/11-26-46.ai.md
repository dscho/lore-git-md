This is a platform compatibility fix for the cvsserver Perl script, now in its final iteration. The patch addresses test failures (t9402 tests 30-32 and 34) that occur with Perl 5.41.4+ due to a new warning about operator precedence between `!` and `=~` in the `escapeRefName` function.

The solution has evolved from adding parentheses (v2) to now using Perl's idiomatic `!~` operator for negative pattern matching (v3), as suggested by Brian Carlson. This change resolves the warning while being more conventional Perl style. The patch maintains backward compatibility and fixes the immediate test failures in Fedora builds with newer Perl versions.

The commit message clearly identifies the specific tests affected and references the Perl 5.41.4 delta documentation explaining the new warning. Attribution is properly given to Jitka Plesnikova who originally reported and suggested the fix. The diff shows the straightforward replacement of the negated match pattern with the `!~` operator in `git-cvsserver.perl`.

While this specific fix is now complete, the thread has noted broader questions about whether `escapeRefName` is actually used and the maintenance status of cvsserver itself, but those remain separate from this technical correction.
