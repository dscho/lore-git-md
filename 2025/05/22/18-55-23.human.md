Feature implementation for stash portability. This is patch 4/5 in the v6 series introducing `git stash export` and `import` commands, now with all major technical concerns resolved and ready for final review.

The patch adds the `git stash export` subcommand, which converts stash entries into a chain of commits under a ref (or prints the hash with `--print`). This solves the longstanding problem of stashes being stuck in reflogs and untransferable between repositories. The implementation carefully preserves stash metadata while creating a predictable commit structure with proper validation.

Key technical points:
- Creates an empty base commit as the chain's root
- Validates stash topology (2-3 parents, proper relationships)
- Preserves original author/committer info while adding "git stash: " prefix
- Handles both specific stash references and full reflog iteration
- Offers both ref-based storage (`--to-ref`) and hash output (`--print`)

The patch builds on earlier refactoring work in the series and incorporates extensive review feedback, particularly around validation and memory safety. Documentation is updated to explain the new subcommand's behavior and options. With Phillip Wood's sign-off now included, this appears to be the final form of the export functionality before merging.
