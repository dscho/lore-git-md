This is a follow-up in the documentation patch series updating references from .txt to .adoc extensions. Jouke Witteveen responds to Junio C Hamano's review of the initial patch, acknowledging two issues:

1. For gitprotocol-v2.adoc, Witteveen agrees the reference should have been updated to use proper `linkgit:` syntax (like `linkgit:git[1]`) rather than just changing the extension, and notes Junio has already made this correction.

2. For build-systems.adoc, Witteveen explains the xref: syntax replacement was incorrect - this AsciiDoc feature doesn't work with Git's current documentation toolchain (legacy asciidoc processor and asciidoctor in compat mode). This creates a dilemma since the original Markdown-style link was also incorrect, but the proper AsciiDoc solution isn't currently viable.

The email reveals an undocumented constraint in Git's documentation build system regarding xref: syntax support, which affects how inter-document links should be formatted during this transition period. Witteveen expresses regret for introducing additional complexity rather than solving the original problem cleanly.

Key technical details: The thread now has uncovered that Git's documentation processing doesn't support AsciiDoc's xref: feature due to compatibility requirements, which impacts how links between documentation files should be formatted during the .txt->.adoc transition. This may require either maintaining broken links temporarily or finding an alternative linking syntax that works across both old and new toolchains.
