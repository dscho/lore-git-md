This is a technical discussion about const-correctness in the strmap API, arising from the final review of the batched reference updates performance series. Karthik Nayak and Jeff King debate whether strmap_put() should accept const void* pointers to avoid casting away constness in the caller. 

Jeff argues against changing the API, noting that C's type system can't properly represent the desired semantics - callers would still need to cast in some cases, and silently dropping constness could be dangerous. He sketches a runtime-checked alternative but acknowledges it would be cumbersome. Karthik initially suggests the const change would be cleaner but ultimately agrees with Jeff's assessment.

The discussion is purely theoretical at this point - the performance series is already approved for merging in Git 2.51, with the current casting approach deemed acceptable. The #leftoverbits tag remains for potential future consideration of strmap API improvements, but there's consensus that no changes are needed now. This represents the final polish on a major optimization that has already undergone extensive review.
