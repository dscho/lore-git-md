Bugfix for gitk's Tcl/Tk compatibility when themed widgets are disabled, addressing a regression from commit 904b36b that breaks the preferences dialog when `want_ttk=0`. The issue prevents dialog opening due to unconditional `::combobox` widget usage in non-themed mode (Tcl/Tk 8.6 on macOS), showing an error then empty window (reproducible with git-gui 2.49.0 and master at 9f1818). Workarounds exist (enable `want_ttk` or delete config), but the proper fix would resolve gitk issue #18.

The regression stems from 904b36b adding text wrapping preferences without fallback for non-themed mode. The email provides the full commit message and diff showing the problematic combobox introduction in the exact error message ("invalid command name ::combobox"), and call stack. Reverting to 904b36b's parent works correctly. These technical details aid verification and fixing. The issue remains open with the same workarounds while awaiting a proper fix that handles both themed and non-themed Tk modes.
