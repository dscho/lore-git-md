Bugfix for gitk's Tcl/Tk compatibility when themed widgets are disabled, addressing a regression from commit 904b36b that breaks the preferences dialog when `want_ttk=0`. The issue prevents dialog opening due to unconditional `::combobox` widget usage in non-themed mode (Tcl/Tk 8.6 on macOS), showing an error then empty window (reproducible with git-gui 2.49.0 and master at 9f1818). Workarounds exist (enable `want_ttk` or delete config), but the proper fix would resolve gitk issue #18.

Johannes Sixt (gitk maintainer) has proposed a fix in his personal branch `yh/fix-non-themed-combobox` on GitHub, though not yet submitted as a formal patch. The branch presumably implements proper fallback behavior for non-themed environments while maintaining the text wrapping preferences functionality added in 904b36b. The technical context remains: Tcl/Tk 8.6 on macOS fails with "invalid command name ::combobox" when trying to use combobox widgets without themed support. The original regression stemmed from 904b36b adding text wrapping preferences without fallback for non-themed mode. Reverting to 904b36b's parent works correctly. The issue remains open awaiting a proper fix that handles both themed and non-themed Tk modes, with Johannes' branch representing the current proposed solution direction.
