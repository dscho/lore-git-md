This is a feature and bugfix series for `imap-send`, addressing both usability issues and adding modern authentication support. The v2 series follows up on previous discussion by pivoting to use curl's native OAuth2.0 API rather than OpenSSL-based encoding, resolving licensing concerns raised in earlier reviews.

The first patch fixes a configuration parsing bug where `imap.folder` could be incorrectly cleared when appearing before other IMAP options - a regression from commit 6d1f198f34 that needs proper documentation. The second patch now implements OAuth2.0 authentication (OAUTHBEARER/XOAUTH2) through curl's built-in support rather than the original OpenSSL approach. The third patch addresses a memory leak in CRAM-MD5 authentication that required careful handling of response buffers and control flow to avoid compiler warnings.

The series shows good responsiveness to review feedback, with the architectural change to curl's OAuth2.0 API being the most significant evolution from v1. The fixes demonstrate attention to both immediate bugs (configuration parsing, memory leaks) and longer-term concerns (modern authentication, legal/technical constraints). While some memory management details around port-related leaks remain for future work, this appears to be a well-considered iteration that makes meaningful progress on making `imap-send` more robust and feature-complete.
