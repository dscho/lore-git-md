MPTCP support technical follow-up from Linux kernel maintainer.

Matthieu Baerts (Linux kernel MPTCP maintainer) responds to Junio Hamano's questions about server-side deployment specifics. He confirms that `inetd`-managed `git-daemon` instances would need MPTCP support configured at the `inetd` level rather than within Git itself, noting that modern Linux distributions already include MPTCP protocol definitions in `/etc/protocols`. The email shifts focus to broader protocol support, with Matthieu identifying technical pathways for MPTCP integration with Git's HTTPS (via libcurl's `CURLOPT_OPENSOCKETFUNCTION`) and SSH transports, though noting OpenSSH maintainers have historically rejected MPTCP patches due to lack of BSD support. 

Key technical details surfaced include: `inetd` configuration requirements for MPTCP server support, libcurl socket callback mechanism for HTTPS transport integration, and OpenSSH's platform support limitations. The email also references external resources including a curl PR (#13278) and MPTCP project FAQ documenting OpenSSH workarounds. This moves the discussion beyond the original git:// protocol focus to address practical deployment across Git's transport stack while highlighting remaining integration challenges with third-party components.
