This is a bug report about inconsistent behavior in Git's smudge/clean filter processing for empty files. Joey Hess demonstrates that when using a simple filter pair (which adds/removes a "hi" line), Git shows a false diff for empty files after staging. The issue appears when:

1. A smudge/clean filter is configured to modify file content
2. An empty file is staged (which gets "hi" added by the clean filter)
3. `git diff` shows the file as changed (removing "hi") even though `git status` reports a clean working tree

The core of the bug seems to be that `git diff` runs the clean filter but ignores its output for empty files, using an empty file as the current content instead. This creates a mismatch between the staged content (which contains the filter's output) and what `git diff` displays. The report includes a reproduction script (setup_smudge_clean.sh) that demonstrates the issue with minimal setup.

This appears to be a genuine inconsistency in Git's filter processing that could affect any use of smudge/clean filters with empty files. The report is well-documented with clear reproduction steps and analysis of the underlying behavior. The bug affects the diff machinery's interaction with the clean filter subsystem.
