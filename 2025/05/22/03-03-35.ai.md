Bugfix for gitk's Tcl/Tk compatibility when themed widgets are disabled. This email provides additional technical details about the regression introduced by commit 904b36b, which added text wrapping preferences to gitk's settings dialog. The key issue is that the commit introduced `::combobox` widget usage without proper fallback for non-themed Tk mode (`want_ttk=0`), causing the preferences dialog to fail completely on macOS systems with Tcl/Tk 8.6.

The email helpfully includes both the full commit message of 904b36b and the specific diff section that introduced the problematic combobox widgets in the preferences dialog. This makes it easier to verify the issue and potential fixes. The reporter confirms the problem occurs with both released versions (git-gui 2.49.0) and current master (commit 9f27318), and notes that reverting to the parent of 904b36b works correctly.

The technical details provided - including the exact error message about the missing `::combobox` command and the call stack leading to the failure - should help developers reproduce and fix the issue. The workarounds mentioned (enabling themed widgets or deleting config) remain valid temporary solutions while awaiting a proper fix. This email serves as both a confirmation of the original bug report and a helpful technical reference for anyone working on the solution.
