Bugfix proposal for smudge/clean filter handling of empty files. This is a follow-up to Joey Hess's report about inconsistent behavior when using content filters with empty files, where `git diff` shows false changes for empty files that have passed through clean/smudge filters.

Jeff King identifies the root cause in `ce_match_stat_basic()` where the code checks for empty blobs without considering smudge filter transformations. The current logic from 2008's f49c2c22fe uses `is_empty_blob_oid()` to detect racy conditions, but this doesn't account for cases where clean/smudge filters modify content. The proposed patch attempts to fix this by reading the object content and running it through `convert_to_working_tree()` to get the expected worktree content before comparing lengths.

Key technical points:
- The fix targets `read-cache.c`'s `ce_match_stat_basic()` function
- Introduces a more complex check that considers smudged content via `convert_to_working_tree()`
- Acknowledges the solution is suboptimal (calls it "very dirty") due to:
  - Lack of direct API to check if conversion would occur
  - Performance impact of reading and converting content during stat checks
  - Edge cases where clean produces empty content but smudge would produce data

The email leaves the door open for better solutions, specifically hoping for input from those more experienced with index handling or filter conversions. The core issue remains reconciling the index's view of content (post-clean) with the worktree's view (post-smudge) when dealing with empty files.
