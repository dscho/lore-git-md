This thread documents a regression in gitk's preferences dialog that occurs when themed Tk widgets are disabled (`want_ttk=0`). The issue stems from commit 904b36b, which added text wrapping preferences but introduced `::combobox` widget usage without proper fallback for non-themed mode. On macOS systems with Tcl/Tk 8.6, this causes the preferences dialog to fail completely with an error about the missing `::combobox` command, leaving users with an empty window.

The problem affects both released versions (git-gui 2.49.0) and current master (commit 9f27318). While workarounds exist (enabling themed widgets or deleting config), the proper fix would resolve gitk issue #18. The thread includes detailed technical information to aid debugging: the full commit message of 904b36b, the specific diff section introducing the problematic combobox widgets, and the exact error conditions. Reverting to the parent of 904b36b has been confirmed to work correctly, suggesting the fix will need to either provide a non-themed fallback or restructure the dialog to avoid combobox dependency in classic Tk mode.
