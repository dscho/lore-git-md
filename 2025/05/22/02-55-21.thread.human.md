This thread addresses a regression in gitk (Git's Tcl/Tk-based repository browser) where the preferences dialog fails when themed widgets are disabled (`want_ttk=0`). The issue stems from commit 904b36b, which introduced combobox widgets without a fallback for non-themed Tk environments, causing the dialog to show an "invalid command name ::combobox" error on macOS with Tcl/Tk 8.6. Current workarounds involve enabling themed widgets or modifying configuration.

Johannes Sixt, gitk's maintainer, has now proposed a fix in his personal GitHub branch (`yh/fix-non-themed-combobox`), moving from problem identification to solution. While not yet submitted as a formal patch, this indicates progress toward resolving the issue while preserving the text wrapping preferences functionality added in the original commit. The fix would properly handle both themed and non-themed Tk modes, closing gitk issue #18.
