This is a technical discussion about const-correctness in the strmap API, part of the performance optimization series for batched reference updates that's now merge-ready for Git 2.51.

Jeff King (peff) responds to Karthik Nayak's concerns about const handling in the strmap API, which came up during the review of the batched reference updates series. The core issue is how to properly handle const pointers in an API that fundamentally deals with non-const void pointers. Jeff argues that explicit casting at the call site is preferable to silently dropping const-ness in the API implementation, as it makes the type system tradeoffs more visible to developers.

The discussion is largely academic at this point, as the series has already been approved with the current approach. Jeff acknowledges there's no perfect solution within C's type system, and that adding separate const/non-const variants of the API functions would introduce complexity without clear benefits. The thread serves to document the rationale behind the current implementation choice rather than propose any changes.

This email doesn't introduce new technical concerns or require any action - it's a post-approval clarification of design decisions that were already settled during the review process. The batched reference updates optimization remains on track for inclusion in Git 2.51 with its current implementation.
