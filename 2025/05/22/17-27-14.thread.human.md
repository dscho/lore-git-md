This thread focuses on improvements to `imap-send`, addressing both immediate bugs and adding modern OAuth2.0 support. The discussion began with reports of configuration parsing issues and memory leaks in the CRAM-MD5 authentication path. Jeff King and Eric Sunshine provided detailed reviews that helped identify the root causes, while Brian Carlson raised licensing concerns about OpenSSL dependencies that led to a significant architectural shift.

The v2 series represents a complete rework, now using curl's native OAuth2.0 API instead of OpenSSL. The first patch fixed configuration parsing to properly handle option order for all IMAP settings, while the second (this latest addition) implements OAuth2.0 support through both standard OAUTHBEARER and Google's XOAUTH2 mechanisms. The implementation includes proper error handling, maintains backward compatibility, and adds comprehensive documentation covering various email provider configurations.

All major review feedback from v1 has been addressed, resulting in a more maintainable solution that avoids OpenSSL licensing concerns while providing equivalent functionality. The remaining work (port-related leaks) has been deferred for separate attention. Junio Hamano has been following the discussion but hasn't yet indicated whether he plans to merge the series. The collaborative review process between Aditya Garg (author), Jeff King, Eric Sunshine, and Brian Carlson has significantly improved both the code quality and architecture of these changes.
