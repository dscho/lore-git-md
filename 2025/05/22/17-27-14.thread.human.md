This thread covers a v8 patch series improving Git's `imap-send` functionality with both technical fixes and new features. The series originated to address a critical configuration parser bug that made `imap-send` unusable in Git 2.46.0 when certain IMAP options were set. That issue has now been fully resolved with proper field-specific cleanup.

The latest iteration (v8) introduces several key improvements:
- A new `--list` command line option for discovering available IMAP folders, replacing the removed `imap.usecurl` configuration option from v7
- Comprehensive fixes for CRAM-MD5 authentication memory handling
- OAuth2.0 support via both OAUTHBEARER and XOAUTH2 methods, working across OpenSSL and libcurl backends
- Standardized message formatting and improved user experience with clearer progress output

The most recent patch specifically adds modern OAuth2.0 authentication methods, implementing RFC-compliant OAUTHBEARER and Google's XOAUTH2 protocol. This addresses real-world needs as providers increasingly deprecate basic authentication. The implementation supports both OpenSSL (with direct base64 encoding) and libcurl (using its native OAuth2.0 API), with detailed documentation covering Gmail and Outlook configurations.

The series has seen thorough review from Jeff King, Eric Sunshine, Brian Carlson, Junio Hamano, and Ben Knoble. While most technical issues appear resolved, Phillip Wood's concerns about maintaining dual backends remain an open question. The current focus has shifted from configuration options to practical utility, with the new folder listing feature providing immediate value for users dealing with different IMAP server conventions.
