Aditya Garg's series to improve the largely unmaintained `imap-send` command continues to receive thorough review, with the latest discussion focusing on memory management in the CRAM-MD5 authentication path. Jeff King (Peff) weighed in on Eric Sunshine's earlier suggestion about buffer cleanup, pointing out that unconditionally freeing the response buffer immediately after socket write - while simpler - would create a use-after-free scenario when checking the write result. The correct approach requires storing the response length before freeing.

This exchange continues the thread's pattern of meticulous attention to memory safety in this legacy code.
