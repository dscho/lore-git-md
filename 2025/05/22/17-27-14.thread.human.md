Aditya Garg's `imap-send` series has reached v8 with comprehensive improvements to IMAP functionality, including new OAuth2.0 authentication support and folder listing capabilities. The technical work is largely complete, with critical bugs fixed and both OpenSSL and libcurl backends fully functional. However, the final design question concerns whether maintaining both backends is worth the complexity.

Junio Hamano and Phillip Wood have raised concerns about the maintenance burden of dual-backend support. In response, Garg acknowledges that dropping OpenSSL would mainly affect rarely-used CRAM-MD5 support, and notes that much OpenSSL code would remain for tunnel functionality regardless. He has already removed the configurable backend switching option in v8, replacing it with the new folder listing feature instead.

The series now stands at a crossroads: while technically sound, it faces a maintainability tradeoff. The folder listing addition (with separate implementations for both backends) improves user experience by making IMAP folder names discoverable, but the architectural question remains whether OpenSSL support provides enough value to justify its ongoing maintenance cost. This is the last open issue before potential merging.
