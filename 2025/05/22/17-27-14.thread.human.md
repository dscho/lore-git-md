This thread covers a major update to `imap-send` adding OAuth2.0 authentication support (both RFC-standard OAUTHBEARER and Google's XOAUTH2), along with new folder management features and critical bug fixes. The series, now at v13, originated from Aditya Garg and has undergone extensive review from Jeff King, Eric Sunshine, and Junio Hamano.

The most critical fix addressed a regression since Git 2.46.0 where configuration parsing incorrectly NULLed out folder fields. The OAuth implementation saw particularly close scrutiny - a Coverity scan by Jeff King caught a security-sensitive logic error in libcurl setup where passwords could incorrectly be set for OAuth methods (fixed by changing `||` to `&&`). Junio has approved the technical correctness but raised design questions about making the authentication method handling more maintainable long-term, suggesting potential follow-up work to consolidate OpenSSL checks and improve the method selection architecture.

New user-facing features include a `--list` option showing available IMAP folders with proper flag handling, runtime folder selection via `--folder`, and improved credential prompts showing port numbers. The series also standardizes error messages and adds progress output showing destination folders during sending. All authentication methods (PLAIN, CRAM-MD5, OAuth2.0) now have consistent implementations across both OpenSSL and libcurl backends with proper compile-time guards.

While functionally complete and security-reviewed, Junio has indicated the code organization around authentication methods may see minor refinements before final merge. The discussion shows the project's careful balance between adding features and maintaining long-term code quality, particularly for security-sensitive components like authentication handlers.
