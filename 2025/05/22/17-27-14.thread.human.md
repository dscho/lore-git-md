This thread covers an extensive patch series (now at v18) adding OAuth2.0 authentication and folder management features to `git imap-send`. The series has been through multiple rounds of review from key contributors like Jeff King, Eric Sunshine, and Junio Hamano, addressing critical issues including a configuration parser regression that broke `imap-send` in Git 2.46.0.

The latest version implements RFC-compliant OAuth2.0 (both OAUTHBEARER and Google's XOAUTH2), adds folder listing support, and improves authentication methods across both OpenSSL and libcurl backends. Most technical issues appear resolved, with the newest feedback coming from Phillip Wood on patch 4/10. He points out two final polish items: the OAuth string construction could be made more robust by using Git's standard string utilities rather than manual buffer handling, and there's a minor mismatch between the RFC-specified host/port inclusion and the current implementation.

Given the thorough prior review and the focused nature of these final comments, the series seems ready for integration after addressing these last points. The changes would make the string handling more maintainable and bring the OAuth implementation fully in line with the RFCs. With these tweaks, this substantial improvement to `imap-send` should be complete.
