This thread covers a feature and bugfix series for `imap-send`, now at version 7, which adds comprehensive IMAP functionality with both technical fixes and user experience improvements. The series resolves several issues including a configuration parser regression, adds OAuth2.0 support via curl with OpenSSL fallback, implements RFC-compliant authentication methods, and introduces new configuration options like `--folder` and `imap.usecurl`. Version 7 polishes the user experience with standardized message formatting and better credential helper output.

The discussion has involved thorough review from Jeff King, Eric Sunshine, and others, with the implementation now technically sound. However, Phillip Wood raised concerns about the long-term maintainability of supporting both OpenSSL and libcurl backends. The latest response defends keeping both backends, citing CRAM-MD5 authentication (which curl doesn't support), implementation advantages in OpenSSL for certain features, and performance benefits. The author argues this maintains flexibility for users who compile Git themselves, though the question of whether this complexity is justified remains open.

The series appears ready for merging from a technical standpoint, having addressed all identified issues and incorporated extensive review. The backend strategy discussion may continue as a separate consideration, but doesn't block the current improvements. The implementation provides clear value with its fixes and new features while leaving room for future optimization of the underlying architecture.
