Aditya Garg's `imap-send` patch series (now at v13) has reached an advanced stage of review, with the OAuth2.0 authentication implementation being the primary focus of recent discussion. The series introduces comprehensive IMAP functionality including OAuth2.0 support, folder management via a new `--list` option, and fixes for critical configuration parsing bugs that had broken `imap-send` since Git 2.46.0.

The most recent exchange between Aditya and maintainer Junio Hamano centers on refining the libcurl password handling logic for OAuth methods. While the v13 series already fixed a critical security issue (incorrectly setting passwords for OAuth flows), Junio is pushing for clearer code organization around authentication method handling. He suggests making unsupported method cases more explicit through BUG/die() calls or warnings, and proposes using `NOT_CONSTANT()` to better handle OpenSSL compiler warnings. Aditya has provided detailed technical context about the constraints, including the need to maintain backward compatibility with PLAIN/LOGIN methods and limitations in testing CRAM-MD5 due to unavailable test servers.

The discussion confirms the OAuth2.0 implementation is technically sound after the v13 fixes, with all identified security concerns addressed. What remains are relatively minor structural refinements to improve long-term maintainability. The series has already incorporated extensive feedback from multiple reviewers including Jeff King (who identified the critical OAuth logic error via Coverity) and Eric Sunshine. With these final polishing discussions underway, the series appears close to being ready for merge consideration by Junio.
