This thread covers a substantial series of improvements to `git imap-send`, now at version 17, which adds OAuth2.0 authentication, fixes critical configuration parsing bugs, and introduces comprehensive folder management features. The series was rebased on master to resolve a merge conflict, with no functional changes from v16.

The most critical fix addresses a regression since Git 2.46.0 where configuration fields were incorrectly NULLed out, making `imap-send` unusable in some cases. The series also adds RFC-compliant support for multiple authentication methods (OAUTHBEARER, XOAUTH2, and now PLAIN for both OpenSSL and libcurl backends), with proper error handling and memory management throughout. The latest patch specifically completes PLAIN authentication support for the OpenSSL backend, implementing the RFC 4616 standard with a new `plain_base64()` helper function.

The series has undergone thorough review from key contributors including Jeff King, Eric Sunshine, and Junio Hamano. Junio has approved the core changes while noting minor formatting issues that were promptly addressed. The remaining items needing final review are the folder listing and destination display features. With all substantive feedback incorporated and only organizational considerations remaining, the series appears to be in its final stages before potential merging.

These improvements make `imap-send` more robust and feature-complete, particularly for users who need OAuth2.0 support or who were affected by the configuration parsing regression. While `git send-email` remains the more commonly used alternative, this work ensures `imap-send` is a viable option with modern authentication methods and better error handling.
