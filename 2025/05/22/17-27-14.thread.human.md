This thread focuses on improving the largely unmaintained `imap-send` command, addressing both bugs and new features. The discussion began with two key patches: one fixing a subtle configuration parsing bug where `imap.folder` was incorrectly cleared when appearing before other IMAP options, and another adding OAuth2.0 authentication support.

The configuration bug, introduced by commit 6d1f198f34 in June 2024, has seen detailed analysis from Jeff King, Eric Sunshine, and Junio Hamano. Aditya Garg, the primary contributor, has acknowledged the need to better document both the regression and the order-dependent behavior in the commit message, which he'll address in a v2 submission. Junio noted the lack of user reports suggests either minimal usage of `imap-send` since mid-2024 or that affected users didn't notice the issue.

The OAuth2.0 implementation remains a separate effort, with Garg reporting successful testing using curl's authentication APIs. This 150-line addition introduces OAUTHBEARER and XOAUTH2 support through three new config options and credential helper integration. While the thread has thoroughly addressed memory leaks in the CRAM-MD5 authentication path through careful review from Sunshine and Peff, some potential leaks in `cfg->host` and `server_fill_credential()` remain open for future work. The discussion demonstrates the project's meticulous approach to maintaining even its less-used components, with particular attention to documenting bug origins and ensuring memory safety in authentication paths.
