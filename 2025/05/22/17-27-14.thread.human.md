This thread covers a substantial update to `imap-send` that has gone through 12 iterations, adding OAuth2.0 support and fixing several long-standing issues. The series, now in v12, introduces key features like folder listing and proper OAuth authentication while addressing critical bugs - notably a configuration parsing regression that made `imap-send` unusable since Git 2.46.0.

The latest email from Jeff King (Peff) catches a subtle logic error in the libcurl OAuth2.0 setup where passwords were incorrectly be set for OAuth methods (which use bearer tokens instead). This was due to an incorrect `strcmp()` condition that always evaluated to true. While the issue is straightforward to fix, it's important for correct OAuth operation. The series has otherwise received thorough review from multiple core contributors (Eric Sunshine, brian m. carlson, Junio Hamano) and appears ready for merging after this final polish.

The changes span authentication methods (OAuth2.0, PLAIN, CRAM-MD5), configuration handling, and user experience improvements like folder listing and better progress output. The work maintains compatibility with OpenSSL and libcurl backends while adding modern authentication support that many email providers now require. With this late-stage bugfix identified via Coverity static analysis, the series seems to have addressed all substantive technical concerns through its 12 iterations.
