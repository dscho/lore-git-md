This thread introduces improvements to Git's largely unmaintained `imap-send` command, addressing both immediate bugs and modern authentication needs. The series begins with a fix for a configuration parsing issue where IMAP options like `imap.user` and `imap.pass` were incorrectly clearing the wrong fields, causing store specification errors. The second and final patch adds OAuth2.0 support, implementing both standard OAUTHBEARER and Google's XOAUTH2 mechanisms to accommodate providers that have deprecated basic authentication.

The OAuth2.0 implementation is substantial, adding about 150 lines of new code with protocol-specific base64 encoding helpers, expanded configuration options, and documentation for major providers like Gmail and Outlook. It includes fallback recommendations when libcurl encounters OAuth2.0 issues. While the changes are contained to the IMAP subsystem, they touch sensitive authentication paths and may benefit from security scrutiny, particularly around token handling and OpenSSL dependencies. The author notes the command's low usage may affect review priority, and as of this email, neither patch in the series has received formal review feedback. Together, these patches modernize `imap-send` while fixing a clear bug, though the authentication additions may generate further discussion about maintenance and security implications.
