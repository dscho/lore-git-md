The `imap-send` patch series has reached its fourth iteration (v4) with comprehensive improvements to configuration handling, authentication methods, and memory management. The series fixes a critical configuration parser bug affecting IMAP folder settings, adds OAuth2.0 support via curl's native API, implements RFC-compliant PLAIN authentication for OpenSSL users, and thoroughly addresses memory leaks in CRAM-MD5 authentication. Multiple reviewers—including Jeff King, Eric Sunshine, and Junio Hamano—have vetted the changes, with Ben Knoble recently confirming that a use-after-free issue in CRAM-MD5 error handling has been properly fixed in v4. The series now supports all major authentication methods (PLAIN, CRAM-MD5, OAUTHBEARER, XOAUTH2) with complete memory safety and provider-specific documentation. With all identified issues resolved and no outstanding concerns, the series appears merge-ready.
