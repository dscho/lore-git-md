This thread covers a v13 patch series that significantly enhances `git imap-send` with OAuth2.0 authentication support and fixes several long-standing issues. The series originated to address a critical regression introduced in Git 2.46.0 that made `imap-send` unusable by incorrectly clearing the IMAP folder configuration when processing unrelated settings. The first patch in the series fixes this by properly isolating the cleanup of each configuration field.

Beyond fixing the regression, the series adds substantial new functionality: OAuth2.0 support (both standard OAUTHBEARER and Google's XOAUTH2), comprehensive folder management via a new `--list` option, and fixes for various authentication methods including PLAIN and CRAM-MD5. The implementation spans both OpenSSL and libcurl backends with consistent behavior. Reviewers including Jeff King, Eric Sunshine, and Junio Hamano have thoroughly vetted the changes, with v13 addressing all remaining concerns through careful fixes to OAuth2.0 logic, memory management, and documentation.

The series appears ready for merging, representing both an important bugfix and meaningful feature additions that bring `imap-send` up to modern standards. The regression fix alone would justify inclusion, but the OAuth2.0 support and folder management improvements make this a particularly valuable update for users who rely on IMAP integration.
