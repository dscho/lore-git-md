This is the final patch in a bugfix series for `imap-send`, addressing a memory leak in the CRAM-MD5 authentication path. The patch fixes a case where the `response` buffer wasn't freed if the socket write operation failed, which could occur during network issues or IMAP server problems.

The change is straightforward - it wraps the error return with a `free(response)` call to match the successful path's cleanup. This completes the series' memory management improvements, which also included configuration parsing fixes and OAuth2.0 support via curl's native APIs. The patch is small (just 3 lines changed) but important for correctness, and follows naturally from earlier review feedback about memory handling in the IMAP code. With this change, all three patches in the series now properly manage resources whether operations succeed or fail.
