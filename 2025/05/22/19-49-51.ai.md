This is a feature and bugfix series for `imap-send`, addressing both usability issues and adding OAuth2.0 authentication support. The v2 series represents a significant architectural shift from the initial approach, now using curl's native OAuth2.0 instead of OpenSSL-based base64 encoding to avoid licensing concerns raised in previous reviews.

The series contains three patches: First fixes a configuration parsing bug where `imap.folder` could be incorrectly cleared when appearing before other IMAP options. Second implements OAuth2.0 support via OAUTHBEARER/XOAUTH2 mechanisms through curl's API, replacing the OpenSSL-dependent approach from v1. Third addresses memory leaks in CRAM-MD5 authentication paths, specifically fixing control flow and buffer management in error cases.

Key technical details include:
- Configuration parsing now properly handles option order for `imap.folder`
- OAuth2.0 implementation uses curl's native support rather than OpenSSL for base64
- CRAM-MD5 authentication path ensures proper memory management with:
  - Correct brace usage to avoid compiler warnings
  - Length storage before buffer freeing
  - Prevention of use-after-free scenarios

The changes respond directly to feedback from Brian Carlson (OpenSSL concerns), Eric Sunshine (memory management), and Jeff King (bug characterization). Documentation updates cover both the configuration fix and new OAuth2.0 options. The series appears well-considered, with each patch addressing specific review feedback while maintaining focus on the dual goals of fixing existing issues and adding modern authentication support.
