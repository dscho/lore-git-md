Feature patch adding OAuth2.0 authentication support for `imap-send`, part of a v2 series that pivoted from OpenSSL to curl's native OAuth2.0 API after licensing concerns. This patch implements both OAUTHBEARER (RFC-standard) and XOAUTH2 (Google-proprietary) mechanisms for modern authentication with email providers like Gmail and Outlook.

The implementation adds new authentication methods to the IMAP capability list and introduces two new helper functions (`oauthbearer_base64` and `xoauth2_base64`) that construct the appropriate authentication strings. The patch handles both direct OpenSSL-based encoding (using `EVP_EncodeBlock`) and provides clear error messages when built without OpenSSL support. The curl integration is updated to properly handle OAuth2.0 tokens via `CURLOPT_XOAUTH2_BEARER`, which automatically selects between OAUTHBEARER and XOAUTH2.

Documentation is expanded to cover OAuth2.0 configuration, including Gmail app-specific passwords and Outlook's exclusive use of XOAUTH2. The patch maintains backward compatibility while adding the new authentication paths, with clear separation between traditional password-based auth and the new token-based methods. The implementation follows RFCs 5801 and 7628 for OAUTHBEARER while accommodating Google's XOAUTH2 protocol for compatibility.
