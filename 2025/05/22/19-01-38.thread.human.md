This thread reports a bug in Git's smudge/clean filter processing that causes inconsistent behavior with empty files. Joey Hess demonstrates that when a clean filter modifies empty files (in this case by adding a "hi" line), `git diff` incorrectly shows the file as changed after staging, even though `git status` correctly reports a clean working tree. The issue stems from `git diff` running the clean filter but ignoring its output for empty files, creating a mismatch between the staged content and what gets displayed. The report includes a clear reproduction script and analysis pinpointing the diff machinery's interaction with the clean filter subsystem as the source of the inconsistency. This appears to be a genuine bug that could impact any use of smudge/clean filters with empty files.
