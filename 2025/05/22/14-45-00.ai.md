Bug report about performance regression when hard-linking large files in Git working directories. The reporter demonstrates that `git status` takes 16 seconds to complete after creating a hard link to a committed 1GB file (listed in `.gitignore`), versus 2ms for a regular copy of the same file. The issue occurs with Git 2.49.0 and doesn't require git-lfs. The reporter provides a clear reproduction script showing the timing difference between `cp` and `ln` operations, noting that hard links are preferred for their space efficiency with large files. The unexpected behavior appears to be that Git performs a full index refresh when encountering hard links, even for ignored files, while skipping this for regular copies. The report is well-documented with system info and clear test cases, suggesting this is a genuine performance bug in Git's index handling of hard links.
