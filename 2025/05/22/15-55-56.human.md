Platform compatibility fix for the cvsserver Perl script, now in its final iteration. This addresses test failures in Fedora builds caused by a new warning in Perl 5.41.4+ related to operator precedence in the `escapeRefName` function.

The immediate issue is that Perl's test suite fails (specifically tests 30-32 and 34 in t9402-git-cvsserver-refs.sh) due to warnings from the `!` operator having higher precedence than `=~` in pattern matching. The solution has evolved from adding parentheses to now using the more idiomatic `!~` operator for negative pattern matching, which both fixes the warning and aligns with Perl best practices.

Junio Hamano raises broader questions about whether this code is actually be used - the function appears to be dead code that's only caught by the test suite. He suggests the better fix might be to remove the unused function entirely, and wonders about cvsserver's active usage in general. However, since the immediate problem is breaking Fedora builds, the operator fix is being accepted regardless.

The patch submitter, Ondřej Pohořelský, clarifies they encountered this through test failures rather than actual usage, and will update the commit message to better explain the observable symptoms and use the imperative style requested by Junio.

This appears to be a straightforward technical fix that's ready to go in, though it surfaces interesting questions about maintaining legacy components like cvsserver that may no longer be in active use but remain in the test suite.
