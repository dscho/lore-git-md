This is a follow-up discussion in the bugfix thread for `git apply --reverse` file mode handling. Junio Hamano responds to Kristoffer Haugsbakk's review of Mark Mentovai's commit message style, defending the project's conventional phrasing approach while acknowledging the value of consistency.

The exchange clarifies Git's documentation standards: commit messages should describe the current problematic state in present tense ("the code does X which causes Y") followed by the proposed fix ("change Z to address this"). While Hamano notes other tense conventions could work logically, the project has standardized on this approach for clarity. The discussion remains focused on message style rather than the technical content of the original patch, which both parties agree is correct.

Key points mentioned:
- Standard commit reference format uses commas (e.g. "Commit 01aff0a, 2023-12-26")
- Active voice and present tense preferred when describing current behavior
- Passive constructions ("tests are added") discouraged in favor of direct phrasing ("Add tests")
- The project prioritizes consistent style over debating alternative phrasing approaches

This email doesn't introduce new technical changes but reinforces documentation norms that will affect future patch submissions in this thread and others. The core bugfix for executable bit preservation in reversed deletions remains uncontested, with attention now on polishing the presentation.
