This is a bug report about Git's handling of empty files with smudge/clean filters. Joey Hess demonstrates that when using a simple filter pair (which adds/removes a "hi" line), Git's diff output incorrectly shows a change for empty files even when the working tree is clean. The issue appears to be that `git diff` runs the clean filter but ignores its output for empty files, causing a mismatch between the staged content (which contains the filtered "hi" line) and the diff output (which shows an empty file).

The report includes a reproducible test case showing that while `git status` correctly reports a clean working tree, `git diff` displays a spurious removal of the "hi" line for empty files. This suggests a discrepancy in how different Git commands handle filtered empty files. The bug appears to be in the diff machinery's interaction with the clean filter output for empty files. The test case is clear and minimal, making this a well-documented bug report that should be straightforward to investigate.
