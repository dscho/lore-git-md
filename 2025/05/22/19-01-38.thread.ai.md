Git thread summary:

Bug report from Joey Hess about inconsistent behavior in Git's smudge/clean filter processing for empty files, where `git diff` shows false changes for empty files that have passed through clean/smudge filters. The issue occurs when: 1) a smudge/clean filter modifies content, 2) an empty file is staged (getting transformed by the clean filter), and 3) `git diff` incorrectly shows the file as changed by removing the filter output while `git status` reports a clean working tree.

Jeff King analyzed the root cause in `read-cache.c`'s `ce_match_stat_basic()` function, where the current logic (from f49c2c22fe, 2008) checks for empty blobs using `is_empty_blob_oid()` without considering smudge filter transformations. His proposed fix involves reading object content and running it through `convert_to_working_tree()` to properly compare lengths when filters are involved. The solution acknowledges performance tradeoffs and edge cases where clean produces empty content but smudge would generate data.

Junio C Hamano has now weighed in with a more conservative perspective, suggesting the current behavior might reflect an intentional design choice to assume empty files remain empty through filter cycles. While not rejecting the fix outright, he expresses skepticism about changing this longstanding behavior and hopes for a cleaner solution from index/filter experts. His comment raises the bar for what would constitute an acceptable fix, particularly regarding the invasiveness of changes to `ce_match_stat_basic()`.

Technical details:
- Core issue in `ce_match_stat_basic()`'s empty blob handling
- Current fix approach requires content conversion during stat checks
- Performance impact remains a concern
- Edge cases with empty-clean-but-nonempty-smudge scenarios
- Historical behavior may reflect intentional design constraints

Open questions:
- Whether this inconsistency warrants changing longstanding behavior
- Alternative approaches that don't require invasive changes to stat checking
- Performance implications of content conversion in common cases
- Whether filter contracts should guarantee empty-file preservation
