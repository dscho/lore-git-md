Git thread summary:

Bug report from Joey Hess about inconsistent behavior in Git's smudge/clean filter processing for empty files. When using a simple filter pair that adds/removes a "hi" line, Git shows a false diff for empty files after staging. The issue manifests when: 1) a smudge/clean filter is configured to modify file content, 2) an empty file is staged (getting "hi" added by the clean filter), and 3) `git diff` shows the file as changed (removing "hi") despite `git status` reporting a clean working tree. The root cause appears to be `git diff` running the clean filter but ignoring its output for empty files, using an empty file as current content instead, creating a mismatch between staged content (containing filter output) and diff display. The report includes a minimal reproduction script (setup_smudge_clean.sh) demonstrating the issue. This is a genuine inconsistency in Git's filter processing affecting diff machinery's interaction with clean filters for empty files. The bug impacts any smudge/clean filter usage with empty files.
