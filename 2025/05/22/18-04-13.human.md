Bugfix for `imap-send` configuration parsing, addressing a long-standing issue where several IMAP options were incorrectly clearing the wrong field. This is the first patch in a two-part series that also adds OAuth2.0 support to the second patch).

The patch fixes a copy/paste error introduced in commit 6d1f198f34, where four configuration options (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`) were mistakenly clearing `cfg->folder` instead of their intended target fields. This made `imap-send` essentially unusable as it would always complain about "no imap store specified".

Eric Sunshine's review confirms the fix but notes two additional potential memory leak issues: one in `cfg->host` handling and another in `server_fill_credential()`. The author acknowledges these as separate issues that could be addressed in future patches. The commit message will be updated to reference the original problematic commit (6d1f198f34) that introduced these copy/paste errors.

While this is a straightforward bugfix, it highlights the fragile state of the largely unmaintained `imap-send` command. The patch appears well-targeted and uncontroversial, though reviewers may want to consider the additional memory safety issues flagged by Sunshine in future work.
