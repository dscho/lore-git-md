This thread addresses a bug in `git apply --reverse` where file mode bits (particularly executable permissions) were not properly preserved when reversing deletions. The issue stems from commit 01aff0a in December 2023, which handled mode preservation cases but missed the deletion scenario.

The series has evolved through two versions, with v2 now consisting of two patches. The first patch adds comprehensive test coverage for mode change warnings in `git apply`, verifying both forward and reverse application across different file states (staged vs committed) and mode transitions (executable ↔ non-executable). The second patch contains the actual fix - a one-line change to `reverse_patches()` in apply.c that properly transfers mode bits during deletion processing.

Reviewers including Junio Hamano, Kristoffer Haugsbakk, and Mark Mentovai have provided feedback that's been fully incorporated. The test structure was refined to create patch files once at setup and test both directions of mode changes, while commit messages were rewritten for clarity. The expanded test matrix now covers all relevant scenarios including core.fileMode interaction and working tree vs index states.

With all feedback addressed and technical consensus reached on both the test coverage and the minimal fix, this series appears ready for merging. The thorough test suite ensures the fix works as intended while guarding against regressions in mode handling behavior.
