Bugfix for gitk's Tcl/Tk compatibility when themed widgets are disabled. 

This patch reports a regression in gitk's preferences dialog that occurs when running with `want_ttk=0` (disabling themed widgets). The error manifests when trying to open settings, showing an error about missing `::combobox` commands before displaying an empty dialog. The issue was introduced in commit 904b36b which added combobox widgets without proper fallback handling for non-themed Tk.

The reporter, Ilya, has verified the problem occurs on macOS with Tcl/Tk 8.6 using both packaged and master branch versions of gitk. They provide a simple workaround - either enabling themed widgets (`want_ttk=1`) or deleting the gitk config file. The bug appears specific to the combobox additions in 904b36b, as the parent commit works correctly.

This seems like a straightforward compatibility issue that needs addressing for users who prefer the classic Tk widgets. The report is clear with reproduction steps and references the original GitHub issue, making it easy to verify. The impact appears limited to the preferences dialog functionality when using non-themed widgets.
