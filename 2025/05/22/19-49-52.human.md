Bugfix for `imap-send` configuration parsing that corrects a long-standing issue where the IMAP folder setting was being incorrectly cleared. This is the first patch in a v2 series that overhauls `imap-send`'s authentication handling.

The patch fixes a bug where `cfg->folder` was being set to NULL when other IMAP configuration options (`imap.user`, `imap.pass`, etc.) were defined, causing the "no imap store specified" error. The incorrect behavior dates back to at least June 2024 (6d1f198f34) but went unnoticed due to most users preferring `git send-email`.

The fix is straightforward - it properly clears the correct configuration field for each option rather than always clearing `cfg->folder`. This makes `imap-send` actually usable when configured with these options. The patch is well-contained (just 4 line changes) and comes with a clear commit message documenting both the bug and its impact.

This is part of a larger series that addresses multiple `imap-send` issues including memory leaks and OAuth2.0 support, but this particular patch stands alone as a simple correctness fix that should be uncontroversial.
