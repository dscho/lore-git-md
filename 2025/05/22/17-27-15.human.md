Bugfix for `imap-send` configuration parsing. This is the first patch in a two-part series that fixes a long-standing bug and adds OAuth2 support to the largely unmaintained IMAP sending functionality.

The patch corrects a configuration parsing error where `cfg->folder` was being incorrectly set to NULL when processing other IMAP settings (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). This bug made the command effectively unusable, showing a "no imap store specified" error. The fix is straightforward - each config option now correctly NULLs and sets its own field rather than incorrectly clearing the folder field.

The author notes this bug has likely gone unnoticed because most users prefer `git send-email` over the IMAP functionality. The patch is small (4-line change) and focused, though it does highlight how little attention this subsystem receives. The change appears correct and uncontroversial, though reviewers may want to verify there are no other similar bugs in the configuration parsing logic.

This sets the stage for the second patch which will add OAuth2 authentication support to `imap-send`.
