This is the second patch in a 3-part series adding OAuth2.0 support to `imap-send`. The patch implements OAuth2.0 authentication using both the standard OAUTHBEARER mechanism (RFC 5801/7628) and Google's proprietary XOAUTH2 protocol.

The implementation handles the OAuth2.0 handshake by constructing properly formatted authentication strings and base64-encoding them. The patch includes documentation updates showing how to configure OAuth methods for both Gmail and Outlook, noting that Outlook only supports XOAUTH2. It also mentions credential helper integration for token generation.

Notably, this version of the patch represents an architectural shift from the v1 series - it now uses curl's native OAuth2.0 API instead of OpenSSL for base64 encoding, addressing licensing concerns raised in earlier reviews. The implementation appears thorough, with clear documentation of both the protocols and configuration examples.

This is a significant addition to `imap-send`'s capabilities, particularly for users who need to work with email providers that require OAuth2.0 authentication. The patch builds on the configuration parsing fixes from patch 1/3 in the series.
