Bugfix for gitk's Tcl/Tk compatibility when themed widgets are disabled. This patch addresses a regression introduced in commit 904b36b that prevents the preferences dialog from opening when `want_ttk=0` (themed widgets disabled). The error occurs because the code tries to use `::combobox` widgets which aren't available in non-themed mode.

The issue manifests as an error dialog followed by an empty preferences window, specifically when trying to create combobox widgets for configuration options. The reporter verified the problem occurs on macOS with Tcl/Tk 8.6 using both Homebrew-installed gitk (from git-gui 2.49.0) and current master branch builds. The regression is clearly tied to commit 904b36b as its parent commit works correctly.

A simple workaround exists - either enabling themed widgets (setting `want_ttk=1`) or deleting the gitk config file - but this patch would provide a proper fix. The issue is documented in the gitk issue tracker as #18, suggesting it's a known problem affecting real users. The technical details provided (specific error message, reproduction steps, version information) make this a well-documented bug report that should be straightforward to verify and fix.
