This is a bugfix patch in a series addressing `imap-send` configuration and authentication issues. The patch corrects a long-standing bug where `cfg->folder` was incorrectly being set to NULL when parsing other IMAP configuration options (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). This caused the "no imap store specified" error and made `imap-send` unusable in affected configurations.

The fix is straightforward - each configuration option now correctly clears its own field rather than incorrectly clearing `cfg->folder`. The bug was introduced in commit 6d1f198f34 and went unnoticed likely because most users prefer `git send-email`. The patch demonstrates careful attention to the configuration parsing logic, with each option now properly managing its own memory cleanup.

This is the first of three patches in v2 of the series, which represents a significant architectural improvement over v1 by moving to curl's native OAuth2.0 API. While this particular patch doesn't deal with the OAuth2.0 changes, it fixes a fundamental configuration parsing issue that would affect all authentication methods. The changes are minimal (4 lines modified) but critical for correct operation.
