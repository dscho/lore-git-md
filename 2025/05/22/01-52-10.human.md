This is a follow-up discussion about the proposed `git imap-get-recipients` helper tool for patch email workflows. Junio Hamano raises several practical concerns about the proposal, building on his earlier critique that the tool's design was too vague to properly evaluate.

He notes four additional issues: the Git project's current avoidance of Perl dependencies, reluctance to add new contrib/ scripts, uncertainty about where such a tool would fit in the project structure, and whether the existing b4 tool already provides similar functionality. Hamano suggests that extending b4 might be more appropriate than creating a new tool, since b4 already understands email threading and could potentially identify appropriate reviewers for patch revisions.

The email reinforces the earlier conclusion that the proposal needs more concrete details before it can move forward, while also highlighting broader project constraints that would affect any implementation. The reference to b4 as a possible alternative suggests the discussion may shift toward whether existing tools can solve the problem rather than creating new ones.
