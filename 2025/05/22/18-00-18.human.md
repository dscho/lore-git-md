Bugfix for a configuration parsing issue in `imap-send`. This is the first patch in a two-part series that addresses both a bug and adds OAuth2.0 support to the IMAP functionality.

Eric Sunshine reviews Aditya Garg's fix for a long-standing bug where `imap-send` incorrectly NULLed out the `cfg->folder` field when processing other configuration options (`imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`). The patch correctly updates the code to free and set the intended fields instead. 

Sunshine suggests the commit message could note these were copy/paste bugs introduced by commit 6d1f198f34. He also points out a potential remaining leak of `cfg->host` in the "imap.host" conditional and questions whether `server_fill_credential()` might have similar issues, though these would be separate from the current fix.

The review is positive but highlights some additional cleanup opportunities that could be addressed in future work. The patch appears straightforward and corrects a clear bug that was making `imap-send` unusable for basic configuration.
