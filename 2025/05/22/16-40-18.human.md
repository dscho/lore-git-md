Performance workaround for hard-link slowdown in `git status`. Justin Tobler responds to a reported issue where creating hard links to large files (even ignored ones) causes `git status` to perform a full index refresh, taking 16 seconds versus 2ms for regular copies. He explains this occurs because hard links update metadata (link count and ctime) on the original file, triggering Git's index refresh mechanism. 

The response provides a practical workaround - setting `core.trustCTime=false` to bypass ctime checks - while implicitly confirming the reported behavior is expected given Git's current design. This moves the thread forward by offering immediate relief while leaving open whether the underlying behavior should be changed for ignored files. The explanation is technically sound but doesn't address whether the performance impact is justified for ignored files.
