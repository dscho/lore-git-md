This is a technical discussion about MPTCP support in Git, focusing on server-side deployment considerations and protocol integration challenges.

Matthieu Baerts (Linux kernel MPTCP maintainer) responds to Junio Hamano's questions about `git-daemon` and `inetd` integration. He confirms that `inetd` should already support MPTCP through `/etc/protocols` on major Linux distributions, though this needs verification from the original patch author Muhammad Nuzaihan. The discussion reveals a practical challenge - MPTCP support in server deployments depends on the socket configuration of the hosting service (`inetd` in this case), not just Git's settings.

The email also highlights broader protocol integration issues beyond the `git://` protocol. For HTTPS connections, Matthieu suggests using libcurl's `CURLOPT_OPENSOCKETFUNCTION` to enable MPTCP. The situation with SSH is more complicated - OpenSSH maintainers have rejected MPTCP patches due to lack of BSD support, despite availability on Linux, macOS, and Windows WSL.

This exchange shows the proposal maturing from technical feasibility to practical deployment considerations. While the core MPTCP implementation appears sound, the discussion now focuses on real-world integration challenges across different protocols and deployment scenarios.
