This thread reports a performance regression in Git 2.49.0 where `git status` becomes extremely slow (16 seconds) when working directories contain hard links to large files, even when those files are properly ignored via `.gitignore`. The reporter provides a clear reproduction case showing that creating a hard link to a 1GB file (rather than copying it) triggers a full index refresh that doesn't occur with regular copies, despite both being ignored. The issue appears to stem from Git treating hard links differently than regular files during index operations, causing unnecessary work for ignored content. The reporter notes that hard links are often preferred for space efficiency with large files, making this regression particularly impactful for workflows dealing with large assets. The report includes detailed system information and test scripts demonstrating the timing difference between `cp` and `ln` operations.
