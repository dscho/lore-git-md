Bugfix for gitk's Tcl/Tk compatibility when themed widgets are disabled. This email provides additional context about commit 904b36b, which introduced a regression that breaks gitk's preferences dialog when running with `want_ttk=0` (Themed widgets disabled). The commit added text wrapping preferences but used `::combobox` widgets that aren't available in non-themed mode.

The email helpfully includes both the full commit message and the problematic diff section showing where the comboboxes were added to the preferences dialog. This makes it easier to verify the issue, which manifests as an error about the missing `::combobox` command followed by an empty preferences window. The reporter confirms the bug occurs on macOS with Tcl/Tk 8.6 using both released and master versions of gitk.

While workarounds exist (enabling themed widgets or deleting the config file), this appears to be a genuine regression that needs fixing. The email serves as a) confirmation of the issue first reported in gitk issue #18, and b) additional technical details to help diagnose the problem. The patch author or maintainers will need to either find an alternative widget type for non-themed mode or implement a fallback mechanism.
