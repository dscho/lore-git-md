This is a bugfix patch for `git send-email` that tightens validation of fully-qualified domain names (FQDNs) to comply with RFC1035 standards. The current implementation only checks for a dot in the domain name (and excludes `.local` domains on macOS), which allowed malformed domains like "MacBook.." to pass validation, causing SMTP failures.

Aditya Garg encountered this issue when `git send-email` failed on Ubuntu because it was using an invalid domain format. The patch adds proper RFC1035 checks requiring: at least one dot, 1-63 character labels between dots, alphanumeric start/end for labels, and no consecutive/hyphen-prefixed/suffixed labels. The commit includes before/after SMTP session logs showing the fix working.

The change is minimal (3 lines modified) but addresses a real-world problem where overly permissive validation caused email sending to fail. This appears to be a straightforward improvement with clear benefits and no obvious downsides. As the first patch in a 3-part series, it focuses on the technical FQDN validation while subsequent patches will handle documentation updates.
