Here's a human-readable summary of the thread so far:

The thread began with Junio Hamano reporting an issue where `git show -s` unnecessarily warns about rename detection being skipped due to hitting `diff.renameLimit`, even though the `-s` flag explicitly suppresses diff output. This happens because Git still performs rename detection checks by default even when no diff will be shown, which is wasteful and confusing.

Jeff King has now proposed a solution, digging up an old patch he had been working on locally. His change would skip diff computation entirely in `git show -s` cases by adding an early return when both the output format is set to suppress diffs and the command is one that always shows commit headers (like `git show`). The patch is small and focused, avoiding both the unnecessary rename detection work and its associated warnings when they wouldn't affect the output anyway.

Jeff mentions he had previously held back this change due to concerns about edge cases like `--exit-code` behavior, but given Junio's report of the concrete issue, he believes it may be worth reconsidering. The proposed fix directly addresses the reported problem while maintaining all other expected behaviors.
