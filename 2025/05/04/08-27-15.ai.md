Bugfix proposal for unnecessary diff computation in `git show -s`. Jeff King responds to Junio Hamano's observation about wasteful rename detection warnings by digging up an old patch he had been carrying locally. The patch would skip diff computation entirely when both: (1) the output format is DIFF_FORMAT_NO_OUTPUT (as with `-s`), and (2) the rev_info.always_show_header flag is set (true for `git show`). 

The patch modifies log-tree.c to add this early return condition before parse_commit happens. Jeff notes he had previously hesitated to submit this due to uncertainty about --exit-code behavior and other corner cases, but the current discussion suggests it may be worth revisiting. The change is small (4 lines) and focused, touching only the diff-skipping logic while preserving all other behavior. This directly addresses the reported issue by avoiding both the rename detection and its associated warnings when they can't affect the output.
