This is a bugfix discussion regarding platform compatibility on macOS, specifically around commit 82e79c63642c which introduced NOT_CONSTANT with sigfillset(). Torsten Bögershausen reports compilation failures on older macOS systems where the compiler encounters an undefined symbol "_false_but_the_compiler_does_not_know_it_" from libgit.a's run-command.o.

The issue stems from macOS's signal.h having both a proper sigfillset prototype and a macro definition that can never fail, making the NOT_CONSTANT error checking unnecessary on this platform. Torsten proposes three potential solutions: (a) create a platform-specific sigfillset_or_die_if_needed macro that skips error checking on macOS, (b) revert the original commit (though this would require resolving merge conflicts), or (c) find some better alternative.

The email seeks input from the community before proceeding, noting that while a revert patch exists, the commit message would need careful crafting. This appears to be a genuine platform-specific edge case that wasn't caught during initial development, and the proposed solutions suggest reasonable approaches to maintain compatibility while preserving the original intent of the change.
