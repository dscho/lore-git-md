Bugfix for `git send-email` FQDN validation, part 1/3 in a series combining technical improvements and documentation updates.

This patch tightens the validation of fully-qualified domain names in `git-send-email.perl` to comply with RFC1035 standards. The current implementation only checks for a dot and macOS-specific `.local` suffix, which allowed malformed domains like "MacBook.." to pass validation, causing SMTP failures. The new validation enforces: minimum one dot, 1-63 character labels, alphanumeric start/end for labels, and no consecutive/hyphen-prefixed/suffixed labels.

The patch includes detailed examples of valid/invalid domains and shows before/after SMTP logs demonstrating the fix in action - where previously a malformed "MacBook.." domain caused SMTP rejection, the patched version properly uses "localhost.localdomain". The change is minimal (3-line diff) but addresses a real-world issue the author encountered on Ubuntu.

Key technical details for future reference:
- Modified function: `valid_fqdn` in `git-send-email.perl`
- New regex pattern enforces RFC1035 label rules
- Maintains macOS `.local` special case
- Fixes SMTP handshake failures from malformed EHLO/HELO
