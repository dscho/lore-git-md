This is a bugfix addressing unnecessary diff computation in `git show -s`. Jeff King responds to Junio Hamano's observation that Git still performs rename detection checks (and emits warnings about rename limits) even when using `-s` to suppress diff output, despite no diff being shown.

King notes this issue was previously discussed in a 2022 thread where he had proposed a similar fix. His patch skips diff computation entirely when both conditions are met: the output format is set to NO_OUTPUT (as with `-s`) and the commit header will be shown regardless (which `git show` always does). The change is minimal - just a few lines added to log-tree.c to short-circuit the diff logic.

The patch appears well-considered, though King mentions some lingering uncertainty about edge cases, particularly around `--exit-code` behavior. This seems like a straightforward optimization that would eliminate wasted computation while maintaining correct behavior for the common `git show -s` case. The fix directly addresses the warning issue Hamano reported while also improving performance by avoiding unnecessary diff work.
