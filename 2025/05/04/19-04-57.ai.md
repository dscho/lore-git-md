Platform compatibility issue regarding `NOT_CONSTANT` and `sigfillset()` on older macOS systems.

This email reports a compilation failure on older macOS systems related to commit 82e79c63642c, which introduced `NOT_CONSTANT` with `sigfillset()`. The error occurs because macOS's `signal.h` has a proper prototype for `sigfillset` followed by a macro definition that can never fail, causing the `false_but_the_compiler_does_not_know_it` symbol to be undefined.

Torsten Bögershausen proposes three potential solutions: (a) create a `sigfillset_or_die_if_needed` macro that skips error checking on affected macOS versions, (b) revert the problematic commit, or (c) find a better alternative. He mentions having a draft patch for option (b) but is seeking input on better solutions before proceeding.

The issue appears to be specific to certain macOS versions where the system's `signal.h` implementation makes the error-checking wrapper unnecessary. This follows Git's pattern of needing platform-specific workarounds, particularly around signal handling functions. The email doesn't specify which macOS versions are affected, but the problem stems from an interaction between Git's safety checks and macOS's header implementation.
