Bugfix discussion about unnecessary rename detection warnings in `git show -s`.

Junio Hamano points out that `git show -s` (which suppresses diff output) still triggers warnings about rename detection being skipped due to too many files, even though no rename detection is needed in this mode. The warning appears when there are many file changes in the commit, suggesting users increase `diff.renameLimit`.

The observation is that since `-s` explicitly avoids showing diffs, Git shouldn't bother checking rename limits at all in this case. The warning is particularly confusing because it suggests adjusting a configuration that wouldn't actually help (since no rename detection is being attempted).

This appears to be a minor but legitimate UX issue where Git is doing unnecessary work and giving misleading advice. The fix would presumably involve modifying the warning logic to account for the `-s` flag. No patch is provided in this email - it's raising the issue for discussion first. The change would affect the diff machinery's interaction with the `git show` command.
