This is a cover letter for a patch series that combines a feature update and documentation improvements for `git send-email`. The series aims to tighten FQDN validation in the email sending component while expanding OAuth-related documentation.

The first patch modifies `git-send-email.perl` to enforce stricter RFC1035 compliance when validating fully-qualified domain names, which could prevent malformed email addresses from being accepted. The implementation appears focused and technically sound, though the cover letter doesn't detail what specific validation gaps are being addressed.

The remaining patches focus on documentation, with two complementary changes: updating `git-send-email.adoc` with more comprehensive examples of OAuth2.0 configuration for major email providers, and adding references to relevant credential helpers in `gitcredentials.adoc`. The documentation updates look practical and well-scoped, addressing a real user need for clearer OAuth setup instructions.

The series touches both technical plumbing (FQDN validation) and user-facing documentation (OAuth examples), with cleanly separated patches. The changes appear non-controversial and focused on improving existing functionality rather than introducing new features. The documentation additions in particular be valuable for users struggling with modern email authentication requirements.
