Bugfix for `git send-email` logging behavior when Outlook modifies Message-IDs. This is the second and final patch in a v6 series addressing email threading and logging issues.

The patch fixes a specific case where Outlook modifies the Message-ID header during email transmission. Currently, while `git send-email` detects and logs the new Message-ID separately, the final header dump shown to users still displays the original ID. The change updates the `$header` variable to reflect the modified Message-ID in the final log output, while making the "Message-ID reassigned" notice conditional on `smtp-debug` being enabled (since the main log will now show the correct ID).

Key technical details:
- Modifies the `send_message` subroutine in `git-send-email.perl`
- Updates the `$header` variable to replace the original Message-ID with Outlook's modified version
- Makes the reassignment notice debug-only via `$smtp->debug` check
- Maintains the warning when Message-ID extraction fails
- Small change (4 lines modified) with clear behavioral impact

This patch completes the v6 series after incorporating all of Junio C Hamano's feedback from v5. The solution is now stable with no remaining open questions, focusing solely on improving logging accuracy when email clients modify headers. The change is particularly useful for debugging email delivery issues when using Outlook as the SMTP server.
