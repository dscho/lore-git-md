Bugfix for a regression in `imap-send` configuration handling that made the command unusable since Git 2.46.0. This is the first patch in a 9-part series improving IMAP functionality.

The patch fixes a critical bug introduced in commit 6d1f198f34 where the configuration parser incorrectly NULLed out `cfg->folder` when processing unrelated IMAP settings (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). The fix properly clears each configuration field's corresponding struct member rather than incorrectly clearing the folder field in all cases.

The bug had gone unnoticed for nearly a year, which the commit message speculates may be due to users preferring alternatives like `git send-email`. The regression made `git-imap-send` completely non-functional when these common configuration options were set.

The change is minimal (4 lines modified) but critical, correcting the field-specific cleanup in the configuration parser. This forms the foundation for the subsequent patches in the series which add new IMAP features and improvements while ensuring proper configuration handling. The fix maintains compatibility with both OpenSSL and libcurl backends that the series supports.
