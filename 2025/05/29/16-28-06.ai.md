This is a discussion about the ongoing dual-backend support in the `imap-send` series, specifically addressing whether to maintain both OpenSSL and libcurl implementations. The email comes from Aditya Garg in response to concerns raised by Junio Hamano and Phillip Wood about the maintenance burden of supporting both backends.

The key points are:
1. Garg acknowledges the main downside of dropping OpenSSL would be losing CRAM-MD5 authentication support, but notes this is rarely used anyway.
2. He points out that much of the OpenSSL code would still be needed for the tunnel option, limiting the potential code reduction.
3. In response to these concerns, Garg has already removed the config-switching patch (from v7) in the upcoming v8 series, replacing it with folder listing functionality instead.

The email highlights the ongoing tension between feature completeness (supporting multiple authentication methods) and code maintainability (reducing dual-implementation complexity). While the technical capability exists to support both backends, the maintainers are questioning whether the OpenSSL implementation provides enough value to justify its maintenance cost. Garg's response suggests the impact of removing OpenSSL would be minimal in practice, particularly since the tunnel functionality would still require much of the OpenSSL-related code.

This discussion represents the final unresolved question in the otherwise mature imap-send series, with v8 removing the configurable backend option while keeping both implementations functional for now. The folder listing feature mentioned as the replacement addition in v8 continues the series' focus on improving user experience and discoverability.
