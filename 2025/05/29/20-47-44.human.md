Performance and correctness patch for MIDX pack name access in incremental chains.

This is part of Taylor Blau's ongoing work to improve MIDX (multi-pack-index) handling, specifically addressing potential issues when MIDX files are chained together incrementally. The patch introduces a new helper function `nth_midxed_pack_name()` to safely access pack names across MIDX layers, replacing direct array accesses that could be error-prone in incremental MIDX chains.

The key insight is that in incremental MIDX chains, a pack's global ID may not match its index in a particular layer's `pack_names` array. The new helper properly handles this translation. While presented as a code cleanup, Junio Hamano's review suggests it may actually fix real bugs in pack-bitmap.c where direct array accesses could go out of bounds when processing chained MIDXs.

The changes affect several areas:
- Adds the new helper function in midx.c/h
- Updates pack-bitmap.c to use it in bitmap handling
- Modifies test helper code to demonstrate proper usage

This appears to be a well-considered change that improves both safety and maintainability of MIDX handling code. It's part of a larger series that has seen thorough review from multiple Git maintainers, suggesting it's a high-quality contribution addressing real technical debt in the MIDX subsystem.
