This is a bugfix patch in a series addressing memory leaks in pack-bitmap.c, specifically focusing on test infrastructure for corrupt bitmap handling. Taylor Blau provides a detailed review of Lidong Yan's patch that adds test coverage for bitmap corruption scenarios.

The patch introduces a new `test-tool bitmap list-commits-offset` helper that outputs bitmap entry positions, allowing targeted corruption of specific bitmap fields (commit OID, offsets, flags). Taylor identifies several concerns with the current approach:

1. The memory allocation strategy using `tag_pos_on_bitmap` is fragile and potentially dangerous, suggesting instead to always include the position field in the main `stored_bitmap` struct.

2. The test helper's output format is somewhat brittle as it hardcodes knowledge of the bitmap format's internal layout.

3. The test case could be improved to better validate bitmap correctness beyond just counting objects.

Taylor provides concrete suggestions for improvement, including safer memory handling, clearer comments, and more robust test verification. The review is thorough and constructive, focusing on making the test infrastructure both safer and more maintainable while still serving its purpose of validating bitmap corruption handling.

This patch represents the second half of a two-part solution to bitmap leak issues, with the first part having already addressed the core leak fixes. The test infrastructure here will help prevent regression of those fixes while also providing a foundation for future bitmap corruption testing.
