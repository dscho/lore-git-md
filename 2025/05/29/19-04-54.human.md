Documentation formatting follow-up in git-send-email docs.

This is a response to Junio Hamano's review of Aditya Garg's documentation formatting improvements for git-send-email. The original patch series standardized quoting styles (using backticks for commands and single quotes for email fields), fixed broken links, and added CPAN module references. 

In this exchange, Junio provides detailed feedback on the markup choices, suggesting that mail header names like 'To' and 'Cc' might be better marked with backticks rather than single quotes for consistency. He also notes that placeholder variables like `<num>` should follow Documentation/CodingGuidelines by using underscores (e.g., _<num>_). 

Aditya responds that keeping mail headers in single quotes avoids rendering issues on the website, and acknowledges the placeholder formatting suggestion. The discussion reveals that some changes in the original patch (like link removals) weren't immediately obvious in the diff, highlighting the value of separating different types of changes into distinct commits.

This is part of an ongoing effort to improve Git's email-related documentation, with Junio maintaining rigorous attention to both technical accuracy and presentation quality. The exchange demonstrates the careful review process these documentation changes undergo before being accepted.
