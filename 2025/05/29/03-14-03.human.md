Maintainer rationale clarification on fast-export signature handling

Junio Hamano responds to Elijah Newren's questioning about the default behavior change for signed commits in fast-export/import. This is part of an ongoing discussion about how to handle signatures in these experimental features, where the default recently changed from 'abort' to 'strip'.

Hamano explains his reversal from earlier positions, stating the signature representation design is less mature than he initially thought. He now believes the feature was premature for inclusion in a release and should remain clearly marked as such. The current "strip" default maintains backward compatibility while the feature remains experimental.

Key points in this response:
- Acknowledges the feature's design is still under discussion and unstable
- Justifies keeping the conservative default (strip) for experimental status
- Suggests future maturity might warrant different default (possibly abort)
- Notes the option to revert the feature entirely was considered

This email provides important context for the thread by clarifying the maintainer's current thinking, though it doesn't resolve the underlying technical questions about signature representation. The discussion remains open about when and how these experimental features should evolve.
