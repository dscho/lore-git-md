This is a discussion about backend selection in the `imap-send` series, specifically regarding the proposed `imap.usecurl` config option. Phillip Wood questions the need for runtime backend switching between libcurl and OpenSSL, suggesting that standardizing on libcurl might be preferable for code simplification and security reasons. He references past discussions about removing the OpenSSL backend entirely.

The email is part of a larger v7 series that has already added IMAP functionality improvements including OAuth2.0 support, authentication fixes, and user experience polish. This particular patch would add persistent configuration for backend selection via `imap.usecurl`, complementing the existing `--curl`/`--no-curl` command-line options.

Phillip raises valid architectural concerns about maintaining dual backends long-term, pointing to previous maintainer discussions about eventually removing the OpenSSL implementation. His comments suggest this config option might make such a future simplification harder, though he acknowledges the current patch series doesn't need to address that question. The discussion highlights an ongoing tension between user configurability and codebase maintainability.
