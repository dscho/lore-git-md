This is a feature and bugfix series for `imap-send`, now in its 8th iteration, that aims to make the command usable again while adding new functionality. The series has evolved significantly through previous rounds of review, with v8 dropping a previously proposed config option for backend selection (`imap.usecurl`) in favor of adding a new `--list` option to show available IMAP folders.

The key changes in this version include:
1. A new regression fix for config parsing where `cfg->folder` was incorrectly set to NULL
2. OAuth2.0 authentication support via curl with OpenSSL fallback
3. PLAIN authentication method for OpenSSL users
4. Memory leak fixes in CRAM-MD5 authentication
5. New `--folder` command-line option to override config settings
6. User experience improvements including standardized message formatting and showing port information in credential prompts
7. Display of destination mailbox during message transmission
8. The new `--list` option to show available IMAP folders (the major addition in v8)

The `--list` functionality is particularly useful as it helps users navigate different IMAP server naming conventions (e.g., Gmail's "[Gmail]/Trash" vs Outlook's "Deleted"). The implementation works with both OpenSSL and libcurl backends, following respective RFC standards and library examples.

This appears to be a well-considered series that has incorporated extensive feedback from reviewers. The author has demonstrated responsiveness to suggestions while maintaining focus on both technical correctness and user experience. The removal of the backend selection config option in favor of the more universally useful folder listing suggests good judgment about what functionality will actually help users.
