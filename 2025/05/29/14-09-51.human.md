This is a response in the ongoing `imap-send` feature/bugfix series, addressing concerns about maintaining dual backends (OpenSSL and libcurl). Aditya Garg defends the need for both implementations, countering Phillip Wood's suggestion to standardize on libcurl.

The response provides three technical justifications for keeping OpenSSL support: (1) CRAM-MD5 authentication (still used by some servers like rediffmail) is only available via OpenSSL, (2) OpenSSL offers more flexible feature implementation compared to curl's limitations, and (3) performance benchmarks show OpenSSL outperforms curl for mail operations. The tone is factual but firm, suggesting the OpenSSL backend remains valuable for specific use cases despite the maintenance burden.

This keeps open the discussion about backend strategy while providing concrete reasons why the current dual-backend approach (with its new `imap.usecurl` config option) may still be justified. The response doesn't propose any code changes but offers important context for evaluating the long-term direction of the IMAP implementation.
