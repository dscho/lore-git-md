This is a bugfix patch in a series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch adds test coverage for corrupt bitmap handling, building on the first patch's leak fixes.

Taylor Blau provides a detailed review of the test infrastructure changes, focusing on the new `test_bitmap_commits_offset()` function and its supporting code. Key technical points raised:

1. The current implementation uses a fragile approach with `stored_bitmap_tag_pos` and conditional allocation based on `tag_pos_on_bitmap`. Taylor suggests simplifying by always including the position field in `stored_bitmap` rather than using a separate structure.

2. The test helper outputs positions of key bitmap fields (commit OID, XOR offset, flags, EWAH data) to enable targeted corruption testing. Taylor notes this makes assumptions about the bitmap format but accepts it as reasonable for testing purposes.

3. Several improvements are suggested for the test script:
   - More robust output parsing from the test helper
   - Better verification of bitmap correctness beyond just object counts
   - Clearer comments about bypassing the lookup table

4. The review identifies potential memory safety issues in the current conditional allocation approach and suggests a simpler alternative that would be more maintainable.

The patch appears technically sound for its testing purpose but could benefit from incorporating Taylor's suggested simplifications to the bitmap position tracking implementation. The review maintains the thread's focus on thorough validation of the bitmap leak fixes while improving code quality.
