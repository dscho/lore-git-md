This is a feature patch adding OAuth2.0 authentication support to `imap-send`, part of a larger v8 series improving IMAP functionality. The patch introduces two OAuth2.0 authentication methods (OAUTHBEARER and XOAUTH2) for both OpenSSL and libcurl backends, with comprehensive documentation updates.

The implementation adds new authentication handlers (`auth_oauthbearer` and `auth_xoauth2`) that construct properly formatted authentication strings per RFC 5801/7628 (OAUTHBEARER) and Google's XOAUTH2 protocol. The OpenSSL path implements base64 encoding directly while the libcurl path leverages curl's native OAuth2.0 support via `CURLOPT_XOAUTH2_BEARER`. Documentation covers both Gmail and Outlook use cases, noting Gmail's requirement for app passwords or OAuth2.0 and Outlook's exclusive OAuth2.0 support.

Key technical changes include:
- New `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` capability flags
- Base64 encoding utilities for both protocols (`oauthbearer_base64`, `xoauth2_base64`)
- Conditional password handling in curl setup to avoid double-authentication
- Updated config documentation showing new authmethod options
- Detailed examples for Gmail and Outlook configurations

The patch maintains backward compatibility while adding modern authentication methods, addressing a real-world need as more providers deprecate basic auth. It follows the series' pattern of thorough documentation and cross-backend support, though reviewers may want to verify the curl/OpenSSL behavior parity claims.
