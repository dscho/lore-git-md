This is a feature and bugfix series for `imap-send`, now in its 8th iteration. The series continues the work to make the IMAP functionality fully usable, with v8 introducing a significant new feature while rolling back a previous configuration option.

The key change in v8 is the replacement of the `imap.usecurl` config option (from v7) with a new `--list` command line option that shows available IMAP folders. This helps users navigate server-specific folder naming conventions (like Gmail's "[Gmail]/Drafts" vs Outlook's "Drafts"). The implementation works across both OpenSSL and libcurl backends, following respective RFC and libcurl documentation.

Other changes from previous versions remain intact:
- Fixes for config parsing bugs and memory leaks
- OAuth2.0 and PLAIN authentication support
- Command line folder specification (`--folder`)
- User experience improvements (message formatting, port display in credentials, folder visibility during sending)

The series touches documentation, configuration, and core IMAP handling code, with 431 lines added/changed across 3 files. The removal of `imap.usecurl` simplifies the configuration space while the new `--list` feature provides practical utility for users dealing with different IMAP server conventions.

Technical details for future reference:
- New `list_folders` static variable controls `--list` behavior
- Both OpenSSL and libcurl paths implement folder listing
- OpenSSL uses IMAP LIST command per RFC6154
- Libcurl follows example from curl documentation
- Output shows server-specific folder hierarchies and flags
- Documentation updated to recommend `--list` for troubleshooting folder names
- Changes span command line options, config handling, and both backend implementations
