This is the final patch in a feature series enhancing `imap-send` with new capabilities, adding a `--list` option to show available IMAP folders. The patch implements folder listing for both OpenSSL and libcurl backends, addressing the common issue where different IMAP servers (like Gmail vs Outlook) use different naming conventions for standard folders.

The implementation uses RFC6154's LIST command for OpenSSL and follows libcurl's example code for its backend. The output shows folder metadata like `\HasNoChildren` flags alongside names, helping users identify the correct folders to use with `--folder`. The documentation is updated to mention this new option, particularly useful for troubleshooting folder naming issues.

Technical changes include:
- New `list_folders` flag and `--list` option in `imap-send.c`
- Separate `list_imap_folders()` and `curl_list_imap_folders()` implementations
- Modified curl setup to handle folder-less operations
- Verbose output tweaks to show LIST responses
- Documentation updates in `git-imap-send.adoc`

This completes the series' user-facing improvements by solving the discoverability problem for IMAP folder names, complementing earlier additions like OAuth2 support and credential handling enhancements. The dual-backend implementation maintains consistency with the series' approach while handling each protocol stack's specifics.
