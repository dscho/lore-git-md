This is a refactoring and safety improvement patch in the ongoing MIDX (multi-pack-index) optimization series. Taylor Blau introduces a new helper function `nth_midxed_pack_name()` to safely access pack names in MIDX chains, where pack IDs can differ between global and local indices. The change replaces direct array accesses with this helper in four call sites across the codebase.

The patch appears well-motivated by the error-prone nature of direct `pack_names` array access in chained MIDX scenarios. Junio Hamano raises a good question about whether we should expect no remaining direct accesses to `pack_names` outside the new helper's implementation - this suggests the change might need to be more comprehensive to fully achieve its safety goals.

This continues the thread's pattern of incrementally improving MIDX safety through better encapsulation. The change is particularly important for bitmap handling code where direct array accesses could be incorrect in chained MIDX scenarios. The implementation maintains existing behavior where safe while adding a layer of protection against potential array access issues.
