This is a sixth iteration of a two-patch bugfix series for `git send-email`, addressing threading and logging issues. The series remains technically stable from v5, with only minor documentation and variable handling refinements.

The first patch fixes a subtle threading bug where editing the first message in a thread with `--in-reply-to` and shallow threading could break the thread structure. The core fix involves decrementing the `$message_num` counter when editing messages, while notably now omitting the `$message_id_serial` adjustment that was present in earlier versions. The commit message has been further refined per Junio's feedback, with clearer wording ("increment" vs "increase") and a more focused explanation of the threading mechanics.

The second patch (unchanged from v5) improves logging by showing the actual Message-IDs assigned by email clients like Outlook when they modify messages during delivery. This makes debugging email delivery issues more straightforward.

Key technical changes in v6:
- First patch now only decrements `$message_num` (not `$message_id_serial`) during message operations
- Commit message wording improvements throughout
- Subject line change for the first patch to better reflect the threading impact
- Maintains all prior fixes for the Outlook Message-ID logging case

The series appears ready for final review, with all substantive feedback from Junio addressed. The remaining changes are primarily documentation polish, suggesting this iteration may be the final one before potential inclusion. The patches remain small (14 lines total) and focused on their specific edge cases.
