This is the second patch in a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch adds test infrastructure and a specific test case for corrupt bitmap handling, complementing the first patch's direct leak fixes.

The patch introduces a new `test-tool bitmap list-commits-offset` helper that outputs structured data about bitmap entries, including their positions in the bitmap file. This enables targeted corruption testing by revealing where key fields (commit OID, xor_offset, flags, and EWAH bitmap data) are located. The core addition is a `stored_bitmap_tag_pos` struct that extends the existing `stored_bitmap` with position tracking when enabled by the new `tag_pos_on_bitmap` flag.

The test case in t5310 uses this helper to corrupt the xor_offset field of the first bitmap entry, then verifies proper handling via `git rev-list --use-bitmap-index`. The test infrastructure is designed to be reusable for future bitmap corruption testing scenarios. Junio C Hamano notes the commit message could better explain why this test-only code belongs in pack-bitmap.c rather than being separate, and suggests following the project's standard log message structure (problem -> solution -> implementation).

The patch appears technically sound, building on the v3 approach that received positive reviews from Jeff King. The test coverage is thorough, using both the new position-tracking infrastructure and direct bitmap corruption. This completes the series' validation of the bitmap leak fixes, though the commit message could be strengthened to better motivate the implementation choices.
