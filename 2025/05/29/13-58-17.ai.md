This is a discussion about backend selection in the `imap-send` series, specifically regarding patch 6/9 which adds a config option (`imap.usecurl`) to choose between libcurl and OpenSSL backends. Phillip Wood raises concerns about the long-term maintainability of having dual backends, suggesting that standardizing on libcurl would simplify the codebase and avoid potential OpenSSL correctness issues. He references prior discussions about removing the OpenSSL backend entirely.

The technical details center around:
- New `imap.usecurl` boolean config option
- Documentation updates in `imap.adoc` and `git-imap-send.adoc`
- Implementation in `imap-send.c` via `git_config_bool()` for the new setting
- The config can be overridden by existing `--[no]-curl` CLI flags

Phillip's comment introduces a new consideration for the series - whether maintaining both backends is worth the complexity given that libcurl could potentially handle all cases. This suggests the patch might need reevaluation of its long-term implications, though the immediate technical implementation appears sound. The discussion references two prior threads about OpenSSL removal that would be relevant for future decisions about backend strategy.
