This is a discussion about the ongoing `imap-send` backend architecture, specifically addressing whether to maintain both OpenSSL and libcurl implementations. The email comes from Aditya Garg in response to concerns raised by Junio Hamano and Phillip Wood about the maintenance burden of supporting dual backends.

The key point is that Garg acknowledges the primary downside of dropping OpenSSL support would be losing CRAM-MD5 authentication, but notes this is rarely used. They also observe that much of the OpenSSL code would still be needed for tunnel support, limiting the potential code reduction. In practice, Garg has already removed the runtime backend selection patch from v8 series and replaced it with folder listing functionality instead.

This continues the thread's central architectural debate about whether maintaining both backends is worth the complexity. While all technical features currently work in both implementations, the discussion now focuses on whether OpenSSL support provides enough value to justify its maintenance cost, with Garg leaning toward simplification but noting some remaining dependencies. The exchange shows the series is nearing finalization but still needs resolution on this design question.
