This is a platform compatibility follow-up discussing the NetBSD errno handling patch for O_NOFOLLOW behavior. Junio C Hamano acknowledges brian m. carlson's review of Collin Funk's patch that fixes test failures on NetBSD by translating EFTYPE to ELOOP in wrapper.c's open_nofollow(). The maintainer notes the patch will be queued after minor log message formatting fixes.

The email highlights two key points about the broader context: First, FreeBSD exhibits a similar but distinct issue (returning EMLINK instead of ELOOP) that will need separate handling. Second, there's frustration about BSD systems not providing POSIX-compliant errno values even when _POSIX_SOURCE is defined, though this is recognized as a systemic issue beyond Git's scope to fix.

The discussion confirms the NetBSD-specific solution is technically sound, with brian m. carlson verifying the approach despite not being a NetBSD user. The thread remains open for FreeBSD-specific follow-up patches, with Junio explicitly stating this doesn't need to block the current NetBSD fix. The exchange underscores Git's ongoing need to handle platform-specific errno variations in filesystem operations, particularly around symlink handling in the refs backend.
