Bugfix addressing wildcard pathspec handling in `git add` and `git commit`. This is a follow-up revision incorporating maintainer feedback on test formatting and commit message structure from the previous round.

The patch fixes an edge case where Git commands would incorrectly stop matching files if a literal file matching the wildcard pattern existed (e.g., having a file named `f*` would prevent matching `foo` when using `git add f*`). The one-line change in `dir.c` modifies the exact-match detection logic to properly handle escaped wildcards (like `f\*` for literal matching).

The revision includes comprehensive test coverage in a new file `t6137-pathspec-wildcards-literal.sh` that verifies all major wildcard types (`*`, `?`, `**`) and their escaped variants. The tests follow Git conventions with proper tab indentation and HERE-DOC formatting, and include Windows-specific skips where needed.

The patch has been reviewed by Jeff King and Junio Hamano, with no fundamental objections remaining. The author notes a formatting quirk in the patch email where line alignment appears correct locally but shifts when sent - this appears to be a mail client issue rather than a substantive problem with the patch itself.
