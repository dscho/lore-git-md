Platform compatibility follow-up regarding BSD errno behavior in symlink operations.

This is a brief exchange between Collin Funk and Jeff King about the ongoing discussion around handling BSD variants' errno returns for symlink operations. The thread had previously settled on using lstat() for portable symlink detection in packed-refs validation, moving away from errno-based approaches.

Collin responds to Jeff's concern about making errno handling too exotic by pointing out that the specific BSD cases (FreeBSD's EMLINK and NetBSD's EFTYPE) are actually quite constrained. He notes that FreeBSD only uses EMLINK in this particular case, and while NetBSD's EFTYPE could theoretically appear with O_REGULAR, Git doesn't use that flag (a NetBSD extension) anywhere in its codebase.

The exchange reinforces that while the lstat() solution remains the primary approach, the BSD errno cases being discussed are not as exotic as they might have initially appeared. This helps justify why documenting these BSD-specific behaviors in Gnulib (as Collin has done) remains valuable for cross-platform compatibility, even if Git itself won't rely on them directly.
