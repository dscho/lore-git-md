This is a platform compatibility discussion thread that questions the approach of the BSD errno translation patches. Jeff King suggests an alternative solution might be better than handling platform-specific errno values - using `lstat()` directly in `packed-backend.c` to check file types rather than relying on `open_nofollow()`'s errno behavior. He notes this would work universally without platform-specific code and would be more direct since the code already needs to `stat()` the file for other checks.

The key technical points are: 1) The proposed change would replace the `open_nofollow()` call with an `lstat()` check that handles symlinks and other non-regular files in one operation, 2) This avoids the need for BSD-specific errno translation, 3) The atomicity loss isn't critical for fsck operations, and 4) The patch shows this approach would simplify the test expectations by removing the symlink-specific error message.

Jeff also notes two unrelated observations: 1) Git generally tries not to be too particular about errno values, and 2) The packed-refs fsck implementation reads the whole file into a strbuf rather than mmap-ing it, which could be problematic for very large repositories.

This email represents a potential alternative direction to the BSD errno translation work, suggesting the root issue in `packed-backend.c` might be better solved by restructuring the file checking logic rather than accommodating platform errno differences in the wrapper layer. The proposal maintains the same functionality while being more portable, though it does change the error message wording slightly.
