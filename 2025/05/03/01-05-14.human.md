This is a platform compatibility fix for NetBSD's errno behavior with symlinks, continuing a thread about BSD variants diverging from POSIX standards. The patch from Collin Funk addresses test failures in t0602-reffiles-fsck.sh by translating NetBSD's EFTYPE error to the POSIX-standard ELOOP when O_NOFOLLOW encounters a symlink.

Junio C Hamano confirms the patch is ready to be queued after minor log message formatting fixes, while noting that FreeBSD has a similar issue (returning EMLINK instead of ELOOP) that will need separate attention. brian m. carlson expresses frustration with BSD systems not providing POSIX-compliant errno values even when _POSIX_SOURCE is defined, though this broader issue is beyond the scope of this specific fix.

The discussion highlights an ongoing challenge in maintaining cross-platform compatibility, particularly with BSD variants that don't fully conform to POSIX errno specifications for symlink operations. The immediate fix is narrowly scoped to NetBSD's behavior, leaving the FreeBSD case for future work by someone with access to that platform.
