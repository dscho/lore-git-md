This is a feature request proposing to add character escape support in `.gitignore` patterns, specifically to handle non-printable and non-ASCII characters in filenames. The author encountered a real-world problem trying to exclude macOS Icon files (which end with a carriage return character) and found current workarounds inadequate.

The proposal suggests extending Git's escape sequence syntax (like `\r` for carriage return) to `.gitignore`, similar to Python's string escape sequences. This would solve the immediate problem of matching control characters without requiring them to appear literally in the ignore file. The author thoughtfully considers backward compatibility, noting the documentation doesn't specify current behavior for backslashes before non-special characters, and suggests potentially limiting escapes to character classes as a safer implementation path.

Key technical details include:
- Current workaround using `Icon?` with `!Icon[ -~]` has limitations (matches other control chars and non-ASCII)
- References Python's escape sequences as a model
- Potential implementation constraint around character classes
- Specific problematic filename pattern: `Icon\r`

The proposal is well-motivated by a concrete use case and demonstrates awareness of potential pitfalls. The suggested solution would affect pattern matching in `.gitignore` files, particularly for filenames containing control characters or needing non-ASCII matching. The thread may need to discuss backward compatibility implications and whether character class limitation is necessary.
