Bugfix addressing wildcard pathspec handling in `git add` and `git commit`. This is a revised version of the patch following maintainer feedback, now with improved test structure and commit message clarity.

The core issue fixes incorrect behavior when literal files exist with names containing wildcard characters (like `f*`). Previously, commands like `git add f*` would stop after matching the literal `f*` file rather than continuing to match other files (like `foo`). The fix modifies `do_match_pathspec()` in `dir.c` to properly handle escaped wildcards by checking `nowildcard_len` against the full pathspec length.

The patch introduces comprehensive test coverage in new file `t6137-pathspec-wildcards-literal.sh` that verifies both wildcard patterns (`*`, `?`, `**`) and their escaped variants. Tests follow Git's standard structure with `test_cmp` verification and cover both `git add` and `git commit` scenarios. The test file is added to meson.build and uses subshell style for isolation.

Key technical details include:
- The one-line change in `dir.c` adds a condition checking if `nowildcard_len` equals the full pathspec length
- Tests verify all major wildcard types and their escaped forms
- Windows-specific tests are skipped via `FUNNYNAMES` prerequisite
- Each test case uses isolated repositories via subshells
- Both positive (wildcard matching) and negative (literal matching via escapes) cases are covered

The patch builds on previous discussion where Jeff King mentored the solution and Junio Hamano reviewed the implementation. While the core logic was confirmed sound, this version addresses feedback about test formatting and commit message structure. The tests now better follow Git conventions with proper indentation and HERE-DOC formatting.
