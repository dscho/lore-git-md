This is a documentation patch series continuing the standardization of option presentation in Git man pages. The 3-patch series builds on Jean-Noël Avila's earlier work to convert documentation from [verse] to [synopsis] format and apply consistent markup rules.

The changes focus on three key documentation improvements: consistently backquoting option names, splitting negatable options (--[no-]opt) into separate entries, and removing non-option text from OPTIONS sections. The first two patches (verify-verify-*/var/write-tree) remain unchanged from the previous iteration, while the git-daemon patch incorporates additional backquoting of command names (`git daemon`) and literal paths (`/srv/git`) based on Eric Sunshine's review feedback.

Notable changes in the git-daemon documentation include converting `--base-path` examples to use backticks and updating the command references from 'git daemon' to `git daemon`. The patch maintains the original mixed formatting for example URLs like `git://host/{tilde}alice/foo` where the variation was intentional. The series drops a previously included WIP patch for worktree documentation.

The changes are purely presentational, improving documentation consistency without altering behavior. The thread has established clear guidelines for when to apply strict backquoting (commands, options, paths users must reproduce) versus allowing stylistic variation in illustrative examples. This series represents uncontroversial documentation standardization building on existing consensus.
