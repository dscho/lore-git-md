This is a follow-up platform compatibility patch completing the BSD errno translation work for symlink operations. Collin Funk confirms FreeBSD returns EMLINK instead of ELOOP when O_NOFOLLOW encounters a symlink, similar to NetBSD's EFTYPE behavior addressed in the previous patch. The v2 patch extends the solution to handle both BSD variants using the same conditional compilation approach in wrapper.c's open_nofollow() function.

The implementation maintains the pattern established in the NetBSD fix - translating platform-specific errno values (EMLINK for FreeBSD) to POSIX-standard ELOOP while avoiding broader errno handling that might mask legitimate errors. The change fixes test failures in t0602-reffiles-fsck.sh on FreeBSD systems while preserving expected behavior on POSIX-compliant platforms.

Collin notes OpenBSD appears unaffected but indicates any future issues would be similarly straightforward to address. The patch follows Junio C Hamano's earlier approval of the technical approach and completes the errno translation work anticipated in the thread. No open questions remain regarding this specific BSD compatibility issue.
