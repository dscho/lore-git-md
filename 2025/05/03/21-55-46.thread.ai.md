Britton Kerin proposes adding 3-pane Meld-style visualization for reviewing merge commits, noting current Git tools only support 2-pane views. The feature would show base+left+right versions simultaneously for 2-parent merges, with Kerin providing a shell script prototype. Johannes Sixt raises a key design challenge regarding the proposal's limitation to 2-parent merges, pointing out that merge commits can have arbitrary numbers of parents. Sixt questions whether 2-parent merges deserve special treatment when the general case could involve more parents, and whether merge tools could scale to N-pane views. This introduces an important consideration for any implementation - the tension between optimizing for common 2-parent cases versus handling the general N-parent scenario. The discussion now needs to address whether to proceed with a 2-parent-specific solution (acknowledging the limitation) or explore more general approaches that could handle higher-order merges.
