Britton Kerin proposes adding 3-pane Meld-style visualization for reviewing merge commits, noting current Git tools only support 2-pane views. The feature would show base+left+right versions simultaneously for 2-parent merges, with Kerin providing a shell script prototype. Johannes Sixt raises a key design challenge regarding the proposal's limitation to 2-parent merges, pointing out that merge commits can have arbitrary numbers of parents. D. Ben Knoble provides a practical demonstration that vimdiff can technically handle comparing an arbitrary number of files (demonstrated with 5 files), though notes the interface becomes more difficult to understand with many panes. This shows that while the technical capability exists in at least one tool (vimdiff), usability degrades with more panes, which may inform the design decision between optimizing for the common 2-parent case versus handling all possible cases. The core tension remains unresolved - whether to proceed with a 2-parent-specific solution (acknowledging the limitation) or explore more general approaches that could handle higher-order merges. No Reviewed-by or Acked-by tags have appeared yet, indicating the discussion is still in the technical exploration phase.
