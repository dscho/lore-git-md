This is a feature patch introducing a new subcommand for remote group management. The patch comes from a first-time contributor seeking feedback on their approach.

The main addition is a `git remote group` subcommand that provides both bash completion and listing functionality for remote groups. The implementation touches documentation, the remote.c builtin, bash completion scripts, and adds new tests. The author notes that while bash completion could be implemented via config parsing, they believe a dedicated subcommand is the more proper solution if remote groups are meant to be a supported feature.

The patch also surfaces an interesting edge case regarding remote renames not updating group memberships in local config files. The author observed this behavior but decided not to address it in this initial patch, instead soliciting discussion about whether this is the intended behavior (particularly when groups are defined in local vs global config). They're open to follow up with additional patches once the expected behavior is clarified.

Key technical details for future reference:
- New subcommand: `git remote group` for listing groups
- Files modified: builtin/remote.c, git-completion.bash, git-remote.adoc
- New test file: t/t5506-remote-groups.sh
- Open question: Should renames update group members in local config?
- Current behavior preserves original names in groups after rename

The patch appears well-structured with documentation and tests included, though the remote rename behavior question may need resolution before the feature can be considered complete. The author is explicitly seeking maintainer guidance on both their implementation approach and the rename behavior question.
