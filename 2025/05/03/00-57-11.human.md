This is a platform compatibility discussion about NetBSD's non-POSIX errno behavior for symlinks. Brian Carlson responds to Collin Funk's patch that fixed a test failure in t0602-reffiles-fsck.sh by adding NetBSD-specific errno translation in open_nofollow().

Carlson confirms the patch looks correct and notes they're surprised this NetBSD quirk (returning EFTYPE instead of ELOOP for symlinks) hadn't surfaced earlier. They also flag a related issue on FreeBSD which returns EMLINK in the same scenario, suggesting both BSD variants should ideally provide POSIX-compliant behavior when _POSIX_SOURCE is set.

The response serves as an informal ACK for the NetBSD fix while raising awareness of the broader BSD compatibility landscape. No changes to the patch are suggested, but the FreeBSD case is noted as a likely future consideration. The tone is collegial, recognizing both the immediate fix and the underlying platform divergence.
