This is a cover letter for a 6-patch series that formalizes the deprecation process for `git whatchanged` and establishes infrastructure for future command deprecations. The series builds on previous discussions about standardizing Git's deprecation approach.

The first patch refactors deprecation warning infrastructure from `git pack-redundant` into a reusable `you_still_use_that()` helper in usage.c. The next two patches clean up documentation and tests to reduce future removal work. Patch 4 makes `--i-still-use-this` mandatory for `git whatchanged`, forcing users to explicitly opt-in. The final two patches prepare for eventual removal by adding conditional compilation with `WITH_BREAKING_CHANGES` and updating BreakingChanges.adoc.

The series represents a more complete approach than previous iterations, addressing both the technical infrastructure and policy aspects of deprecation. It follows a clear progression: first measuring usage via forced opt-in, then cleaning up references, and finally preparing for removal. The implementation touches core files (usage.c, git-compat-util.h), command plumbing (builtin/log.c), and updates documentation and tests across multiple files.

While the technical approach is now well-established, the cover letter notes this continues the philosophical discussion about when and how to guide users during deprecations. The series appears thorough, with comprehensive test coverage and documentation updates, suggesting it's likely to move forward as Git's standard deprecation template.
