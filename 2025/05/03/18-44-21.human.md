This is a follow-up in the ongoing platform compatibility discussion about BSD variants' errno behavior with O_NOFOLLOW in packed-refs operations.

Collin Funk notes that the FreeBSD EMLINK and NetBSD EFTYPE behavior with O_NOFOLLOW on symlinks (which differs from POSIX's ELOOP) is documented in Gnulib, though previously only for older versions. He has now updated the Gnulib documentation to reflect that this behavior patterns still exists in current systems, confirmed through Git's test suite.

The email serves as a cross-reference between the Git discussion and broader Unix portability documentation efforts, with Collin linking to his Gnulib documentation update. This doesn't change the technical direction of the Git patches (which have settled on using lstat() for portable symlink detection), but provides useful context for future portability work. The message also highlights brian m. carlson's FreeBSD man page reference as another resource for handling similar compatibility issues.
