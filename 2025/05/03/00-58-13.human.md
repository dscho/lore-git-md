This is part of the ongoing `git whatchanged` deprecation effort, specifically implementing the final removal when built with `WITH_BREAKING_CHANGES`. The patch completes the deprecation lifecycle by making the command optional at compile time, following the earlier introduction of the `--i-still-use-this` opt-in requirement.

The changes systematically remove all references to `whatchanged` from documentation and tests when the breaking changes flag is set. Documentation updates span multiple files (format.adoc, log.adoc, etc.) to either conditionally include `whatchanged` references or remove them entirely. The implementation uses `#ifndef WITH_BREAKING_CHANGES` guards in the code to completely remove the command's implementation when enabled.

The patch maintains backward compatibility by keeping the command available by default, with removal only happening when explicitly built with the breaking changes flag. Test coverage is updated to handle both scenarios, with tests for `whatchanged` functionality now requiring the `WITHOUT_BREAKING_CHANGES` prerequisite. This represents the most intrusive change in the deprecation series so far, while still following the gradual, measured approach established earlier in the thread.
