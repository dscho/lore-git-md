Platform compatibility follow-up regarding BSD errno handling in symlink operations.

This email continues the discussion about handling BSD-specific errno values (EMLINK on FreeBSD and EFTYPE on NetBSD) during symlink detection in Git's packed-refs operations. Collin Funk responds to Jeff King's concern about over-reliance on errno checking for edge cases, arguing that these particular BSD errno values are not truly "exotic" in this context.

The key technical point is that FreeBSD's EMLINK and NetBSD's EFTYPE only occur in very specific circumstances that don't overlap with Git's current usage patterns. Collin notes that searching the codebase confirms Git never uses NetBSD's O_REGULAR flag (the other case where EFTYPE would appear), making these errno values reliable indicators of symlink conditions on BSD systems.

This exchange maintains the thread's consensus around using lstat() for portable symlink detection while providing additional justification for why BSD errno handling remains relevant as a secondary check. The discussion remains focused on the narrow technical question of errno reliability rather than reopening the broader solution approach.
