Bugfix for `git apply --intent-to-add` index corruption issue. Raymond Pasco provides technical analysis of the longstanding bug where `apply -N` incorrectly clobbers the index, confirming Ryan Hodges' reproduction of the destructive behavior. Pasco explains the three apply modes (worktree-only, index+worktree, index-only) and how `--intent-to-add` was meant to work only with worktree changes, but currently replaces the entire index contents. 

The analysis notes that Johannes Altmanninger's v3 patch from 2021 had correct code despite its confused commit message, and that `--intent-to-add` should be documented as mutually exclusive with both `--index` and `--cached`. Pasco offers to clean up and resubmit the patch if the original author is unavailable. This moves the thread forward by validating the technical approach while identifying needed documentation updates, though the core index-clobbering behavior remains unfixed in mainline Git. The email provides important clarification about the original patch's viability despite its misleading message.
