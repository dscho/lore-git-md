CI / build system patch addressing Windows Meson builds in GitHub Actions. This is version 2 of a change to force Release mode rather than Debug mode builds, originally motivated by hangs in t7001-mv tests but now positioned as a general CI improvement.

The patch modifies `.github/workflows/main.yml` to add `-Dbuildtype=release` to the Meson configuration. Johannes Schindelin explains that Debug mode builds on Windows trigger modal assertion failures that hang CI jobs, while Release mode avoids this. The immediate trigger was a t7001-mv test case that exposed this behavior, though that specific case is being fixed separately via Patrick Steinhardt's `git mv` improvements.

The commit message details the rationale: Debug mode's interactive assertion behavior is useful for developers but harmful in CI. While some proposed replacing all `assert()` calls with `BUG()`, Schindelin argues this patch remains necessary since dependencies may still use `assert()` and new `assert()` calls could be introduced. The v2 revision expands the explanation to clarify this isn't just about t7001-mv but about general CI robustness.

This change aligns the Meson-based Windows CI with the existing Visual Studio-based Windows CI which already uses Release mode. The one-line change is straightforward and uncontroversial, building on prior discussion where the core issue was recognized but the solution path debated. The patch now stands independently of the `git mv` fixes, addressing a systemic CI concern rather than just working around one test case.
