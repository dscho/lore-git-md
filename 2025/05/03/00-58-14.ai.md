This is a documentation patch completing the `git whatchanged` deprecation series by formally listing it in the BreakingChanges document. It follows the same pattern as the earlier `pack-redundant` deprecation, though Junio notes it could theoretically have been squashed with the previous patch to maintain consistency with that approach.

The patch adds two documentation updates: a new entry in BreakingChanges.adoc explaining the rationale for `whatchanged`'s removal (it's been obsolete for over 10 years, offers no advantage over `git log --raw`, and has seen zero complaints during the opt-in warning phase), and a warning banner in git-whatchanged.adoc itself. The BreakingChanges entry specifically notes the command will be removed, while the man page warning softens this to "scheduled for removal."

This represents the final documentation step in the deprecation lifecycle for `whatchanged`, complementing the code changes in previous patches. The patch maintains the series' careful approach to deprecation - providing clear warnings, documenting the timeline, and giving users visibility into the removal process through official channels. The dual documentation updates ensure users will encounter the deprecation notice both when checking the general breaking changes list and when specifically consulting the `whatchanged` man page.
