This is a cover letter for a 6-patch series that formalizes the deprecation process for `git whatchanged` and establishes infrastructure for future command deprecations. The series builds on previous discussions about standardizing Git's deprecation approach, now moving beyond just warning messages to actual removal preparation.

The series progresses through several logical phases: First, it generalizes the deprecation warning infrastructure from `git pack-redundant` into reusable components (patch 1). Then it systematically removes `whatchanged` references from documentation and tests (patches 2-3), requiring explicit `--i-still-use-this` opt-in (patch 4). Finally, it prepares for actual removal by adding conditional compilation (patch 5) and documenting the planned deprecation (patch 6).

Key technical aspects include the new `you_still_use_that()` helper in usage.c, updates to 8 documentation files, test modifications across 5 test suites, and the introduction of `WITH_BREAKING_CHANGES` build-time control. The series maintains the measured approach discussed earlier - first gathering usage data via forced opt-in before full removal - while now taking concrete steps needed for eventual removal.

The cover letter clarifies this is a more complete iteration than previous attempts, with each patch serving a distinct phase in the deprecation lifecycle. The approach suggests this may become Git's standard template for command removal, with `git whatchanged` serving as the pilot case. The persistent `i_still_use_this` flag in `struct log_config` remains necessary due to command initialization flow, as established in earlier discussion.
