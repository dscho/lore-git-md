Bugfix addressing wildcard pathspec handling in `git add` and `git commit`. This is a revised version of a patch that fixes an issue where Git would incorrectly stop matching files when encountering a literal filename that looks like a wildcard pattern (e.g., having a file named `f*` would prevent matching other files like `foo` when using `git add f*`).

The core change is a one-line modification in `dir.c` that tweaks the `do_match_pathspec` logic to properly handle escaped wildcards. The patch comes with extensive test suite (429 lines across 24 test cases) that verifies correct behavior for various wildcard patterns (`*`, `?`, `**`) and their escaped variants, covering both `git add` and `git commit` scenarios.

The tests are thorough but follow-up feedback from Junio Hamano suggests the commit message could better explain the current behavior before diving into the solution, and that some test formatting could be improved. The core logic itself has been confirmed correct by maintainers. This appears to be a well-motivated fix for a real edge case in pathspec handling, with Windows-specific cases noted but deferred due to platform limitations.
