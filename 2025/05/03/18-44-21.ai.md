This is a platform compatibility follow-up in the ongoing BSD errno behavior discussion. Collin Funk provides additional context about the BSD errno behavior being documented in Gnulib, noting they've updated the Gnulib documentation to reflect that FreeBSD's EMLINK and NetBSD's EFTYPE behavior with O_NOFOLLOW persists in current versions (contrary to some older documentation). The email references brian m. carlson's earlier FreeBSD man page resource while contributing this cross-project documentation update.

The message serves as both a confirmation of the BSD behavior being discussed in the thread and a record of the quirk being documented in the broader GNU ecosystem. It doesn't propose any changes to Git's code - the technical solution using lstat() remains the agreed approach - but provides useful context for future portability work by linking the Git discussion to the Gnulib documentation updates. The Gnulib commit referenced shows this errno behavior is now properly documented for other projects that may encounter similar platform compatibility issues.
