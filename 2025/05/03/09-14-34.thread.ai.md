Proposed feature to add character escape sequence support in `.gitignore` patterns, motivated by inability to properly exclude macOS Icon files containing carriage returns (`Icon\r`). Current workarounds using `Icon?` with `!Icon[ -~]` are insufficient as they match other control characters and non-ASCII. Suggests adopting Python-style escapes (e.g. `\r`) with consideration for backward compatibility, noting documentation doesn't specify behavior for backslashes before non-special characters. Potential implementation path could limit escapes to character classes. Core problem involves pattern matching for filenames containing control characters or non-ASCII, with specific need to handle `\r` in macOS Icon files. Open questions include exact escape syntax scope and backward compatibility impact on existing ignore patterns.
