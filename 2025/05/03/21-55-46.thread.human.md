Britton Kerin proposed adding 3-pane Meld-style visualization for reviewing merge commits, noting current Git tools only support 2-pane views. His prototype shell script demonstrates the concept for 2-parent merges, suggesting this might warrant a dedicated `git-meld3` command.

Johannes Sixt has raised an important consideration about the proposal's scope - while 3-pane views work well for conflict resolution (with clear base/ours/theirs versions), merge commits can have arbitrary numbers of parents. He questions whether special-casing 2-parent merges makes sense when higher-order merges would require different visualization approaches. 

The discussion now centers on whether the common case of 2-parent merges justifies dedicated tooling despite not covering the general case, and whether merge visualization tools could reasonably scale to N-pane views. This thoughtful critique moves the conversation forward by identifying a key design challenge that would need addressing in any implementation.
