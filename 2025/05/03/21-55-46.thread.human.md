Here's a human-readable summary of the thread so far:

Britton Kerin has proposed adding better visualization for merge commits, specifically a 3-pane "Meld view" that would show the base, left, and right versions simultaneously when reviewing already-committed merges. Currently, Git's standard tools like `git diff` and `git show` only offer 2-pane diff views, even though 3-pane visualization is available during active conflict resolution via `git mergetool`.

Kerin has already prototyped this functionality as a shell script shared on Stack Overflow, but suggests it might be worth creating a dedicated `git-meld3` command rather than trying to modify existing diff tools. The proposal highlights a gap in Git's tooling - while developers can see all three versions during conflict resolution, they lose this capability once the merge is committed. The implementation would require either a new subcommand or significant changes to how Git interfaces with diff tools.
