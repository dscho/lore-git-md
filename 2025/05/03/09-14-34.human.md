Feature request proposing character escape support in .gitignore files. Jordan Macdonald identifies a real-world pain point when trying to exclude macOS Icon files (which end with a carriage return character) from version control. The current workaround using wildcards is imperfect and can unintentionally match other files.

The proposal suggests extending Git's existing backslash escaping in .gitignore to support standard character escapes (like `\r` for carriage return), similar to Python's escape sequences. This would allow matching special characters without requiring them to appear literally in the .gitignore file, avoiding editor and tooling issues with control characters.

The email thoughtfully considers backward compatibility, noting the documentation doesn't specify behavior for backslashes before non-special characters. A suggested mitigation would be to character classes (`[]`) to minimize accidental impact. The proposal appears well-motivated by a concrete use case and considers implementation tradeoffs.
