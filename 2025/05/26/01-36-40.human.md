This is a reply in the ongoing discussion about Microsoft Graph API support for `git send-email`. Drew DeVault weighs in on the debate, siding with brian m. carlson's earlier objections to integrating a proprietary API into Git's email subsystem.

The email concisely reinforces the standardization concerns raised earlier, suggesting that first-class support for Microsoft's proprietary protocol would be inappropriate for Git. DeVault proposes an alternative approach: creating a local SMTP-to-Graph-API bridge as an external solution, which would keep the proprietary integration outside Git's core while still providing the desired functionality for Microsoft-hosted email users.

The reply doesn't introduce new technical arguments but strengthens the position against direct Graph API integration in Git. It acknowledges the practical reality that Microsoft may not improve their SMTP implementation while still maintaining that Git shouldn't accommodate proprietary workarounds. The suggestion of an external bridge implies this could be a compromise solution, though no implementation details are provided.

This moves the discussion forward by solidifying opposition to the current approach while hinting at potential alternative solutions that might satisfy both standardization purists and users needing Microsoft email integration.
