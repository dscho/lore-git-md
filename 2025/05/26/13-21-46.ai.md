Bugfix proposal for HEAD.lock contention between maintenance and user operations.

Patrick Steinhardt responds to a bug about HEAD.lock contention during concurrent checkout and maintenance operations, confirming this is a known race condition. The issue occurs when maintenance in detached mode (`--auto --detach`) spawns git-gc which locks packed-refs, conflicting with subsequent ref-modifying operations like checkout. While users can work around this by increasing `core.packedRefsTimeout`, Patrick acknowledges this only masks the underlying problem.

He proposes a proper fix involving modifying git-maintenance to handle tasks that should run before daemonizing, similar to git-gc's historical behavior. This would ensure ref packing completes before the auto-maintenance caller continues, eliminating the race condition. The planned patch series will implement this solution.

Key technical details:
- Root cause: maintenance's detached mode races with user operations over packed-refs lock
- Current workaround: adjust `core.packedRefsTimeout`
- Proposed solution: make maintenance run ref-packing tasks pre-daemonization
- Expected behavior change: maintenance caller will wait for ref packing completion
