This is a technical review response in the ongoing discussion about bitmap cleanup in pack-bitmap.c. Patrick Steinhardt provides a detailed analysis of Lidong Yan's patch that proposed unconditionally freeing the `roots_bitmap` in `find_boundary_objects()`.

The review identifies several gaps in the original patch submission. First, it notes the commit message lacks sufficient justification for both the correctness and benefits of the change. Second, it performs a thorough code analysis showing that the current conditional free could actually cause a memory leak when `cascade_pseudo_merges_1()` fails, since none of the called functions take ownership of the bitmap. This suggests the patch may be fixing a real issue, though the original submission didn't frame it that way.

Key technical points raised include: the bitmap is always newly allocated and never escapes local scope; the call chain through `cascade_pseudo_merges_1()`, `cascade_pseudo_merges()`, and `apply_pseudo_merge()` only reads/modifies the bitmap without freeing it; and there may be testable scenarios where the current code leaks memory. The review serves as a model for what a thorough analysis of such changes should include - tracking ownership through the call graph and considering edge cases.

This moves the thread forward by confirming the technical soundness of the change while providing concrete feedback about how to improve future submissions. The analysis suggests the patch may need to be resubmitted with a stronger commit message and possibly test coverage for the failure case. No new technical objections to the change itself are raised, but the review highlights the importance of proper justification in commit messages.
