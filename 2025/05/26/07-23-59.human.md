Refactoring discussion in the MIDX (multi-pack-index) subsystem. This email from Patrick Steinhardt questions a proposed change by Taylor Blau that would set the `MIDX_WRITE_REV_INDEX` flag as a workaround to ensure packfiles are loaded when a preferred pack is specified.

Patrick finds the approach confusing, noting it creates an indirect dependency between functions where one sets an unrelated flag that another function interprets specially. He suggests instead introducing a dedicated flag to explicitly control pack preparation behavior.

This is part of an ongoing thread focused on improving MIDX code organization and API design, following earlier work on performance optimizations and correctness fixes. The discussion reflects the careful attention being paid to making the MIDX implementation both correct and maintainable. Patrick's comment shows the kind of thoughtful API design scrutiny that characterizes high-quality open source development.
