This is a follow-up discussion in the ongoing signature handling improvements thread, specifically addressing the representation of signature algorithm names in fast-import/fast-export. Christian Couder responds to brian m. carlson's earlier critique about conflating signature protocols (OpenPGP/X.509/SSH) with hash algorithms (SHA-1/SHA-256) in the documentation.

The key technical issue is that the current approach doesn't properly represent signatures that combine different protocols with different hash algorithms. brian m. carlson points out valid cases like SHA-256 commits signed with SSH keys, which the current scheme can't express. He suggests either separating the fields (hash algorithm vs protocol) or keeping just the hash algorithm field and deriving the protocol from signature inspection.

Christian acknowledges the limitations of the current approach and mentions that his v2 series attempts a different solution by actually checking signatures to extract both pieces of information. This aligns with the thread's broader shift toward verification-first improvements, though the fast-import/export compatibility issues remain outstanding.

The exchange highlights the tension between clean technical design (proper separation of concerns between protocol and hash algorithm) and practical implementation constraints (the difficulty of extracting protocol information without signature verification). This discussion feeds into the larger thread questions about how to handle unknown signatures versus verifying known ones, and how to maintain backward compatibility while improving the system.
