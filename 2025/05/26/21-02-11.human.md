Bug report about `git fetch` hanging indefinitely after connection loss during prune operations.

Parker Killion reports that `git fetch --prune --tags --prune-tags` can hang indefinitely if network connectivity is lost and then restored during the operation. The issue appears specific to prune operations - a normal `git fetch` without these flags recovers properly when connectivity returns. The reporter provides video evidence showing both the problematic case and expected behavior.

The bug occurs with Git 2.43.0 on Linux (Ubuntu 24.04) and can be reproduced by running the fetch command while disabling network connectivity (demonstrated via `nmcli` in the provided videos). Unlike normal fetch operations that resume after reconnection, the prune-enabled fetch appears to get stuck in an unrecoverable state.

This looks like a legitimate bug in Git's network recovery logic during tag/prune operations. The report is well-documented with clear reproduction steps and visual evidence, making it easy to verify. The behavior difference between regular fetch and prune-enabled fetch suggests the issue lies in the interaction between network recovery and the pruning logic rather than the core fetch machinery.
