Bug report about `git fetch` hanging indefinitely when connection is lost during prune operations. The reporter demonstrates that while a normal `git fetch` recovers when internet connection is restored, `git fetch --prune --tags --prune-tags` can hang forever in the same scenario. The issue was observed with Git 2.43.0 on Linux (Ubuntu 24.04).

The key difference in behavior appears when combining prune operations with tag fetching. The reporter provides two video attachments showing the contrasting behaviors - one where a basic fetch recovers and one where the prune+tags variant hangs. System details include x86_64 architecture, glibc 2.39, and GCC 13.3.

This looks like a legitimate bug in the interaction between network recovery and the pruning logic. The report is well-documented with clear reproduction steps and evidence, though it doesn't include any analysis of the underlying cause. The hanging behavior suggests either a missing timeout or a deadlock condition in the prune-tags codepath when network connectivity is interrupted.
