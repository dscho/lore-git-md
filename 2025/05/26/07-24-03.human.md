This is a follow-up discussion in the ongoing MIDX (multi-pack-index) refactoring thread, specifically about API improvements for packfile handling. Patrick Steinhardt responds to Taylor Blau's patch that changes `prepare_midx_pack()` to return a `packed_git` pointer directly rather than an integer status code. The change aims to simplify the API by having callers work with pack objects directly rather than translating IDs.

Patrick notes that the change builds on his earlier work introducing a negative lookup cache (using `(void *)(intptr_t)-1` as a sentinel value), but expresses mild frustration that this dependency wasn't made explicit in the series. He suggests including his cache patch in the same series to make iteration easier. Despite this organizational concern, he agrees the API simplification is sensible and appreciates how it hides complexity from callers.

The exchange continues the thread's progression from performance optimizations to API cleanliness, with both contributors aligned on the technical direction but discussing how to best manage the patch series dependencies. The change appears non-controversial but highlights the coordination challenges in multi-author refactoring work.
