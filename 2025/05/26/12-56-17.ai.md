This is a technical discussion about the final build system integration challenge in the reftable test modernization series. Patrick Steinhardt responds to Seyi Chamber's report of linker errors when trying to combine Clar-dependent and framework-agnostic test helpers in lib-reftable.{c,h}.

The core issue is that Clar-based helper functions (prefixed with cl_) require Clar framework assertions (clar_assert, clar_assert_equal) which aren't available to non-Clar tests. Current attempts to keep both helper variants in the same compilation unit cause linker failures when non-Clar tests reference Clar-dependent functions. Additional problems include Makefile warnings about duplicate targets and header pollution.

Patrick proposes an alternative approach: introduce the new Clar-based helpers in separate files (lib-reftable-clar.{c,h}) early in the series, then in the final patch delete the original lib-reftable.{c,h} and rename the Clar-specific versions to take their place. This physical separation avoids the linker issues while maintaining a clean end state where all helpers live in lib-reftable.{c,h} as originally intended.

This represents the last major technical hurdle before the series can be merged, following successful conversion of all test files and resolution of other build system issues. The solution maintains the series' goal of standardizing on Clar while avoiding technical debt from mixed-framework helper implementations. The rename operation in the final patch preserves the intended code organization while working around the immediate build constraints.
