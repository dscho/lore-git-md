Thread summary:

Bug report about `git fetch` hanging indefinitely during prune operations when network connection is lost. Original reporter demonstrates that while normal `git fetch` recovers when connection is restored, `git fetch --prune --tags --prune-tags` hangs forever in same scenario. Observed with Git 2.43.0 on Linux (Ubuntu 24.04, x86_64, glibc 2.39, GCC 13.3). Key difference appears when combining prune operations with tag fetching. Reporter provided video attachments showing contrasting behaviors - basic fetch recovers while prune+tags variant hangs. Behavior suggests either missing timeout or deadlock condition in prune-tags codepath during network interruptions. Well-documented report with clear reproduction steps but no analysis of root cause.
