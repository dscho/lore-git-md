This is a feature proposal for improving signature handling in Git, building on the ongoing discussion about signature formats in `fast-export`/`fast-import`. Christian Couder presents a new approach after feedback from brian m. carlson suggested separating hash algorithm and protocol information.

The series introduces a `--summary` option for `verify-commit` that outputs signature verification results in a standardized format (STATUS FORMAT ALGORITHM), which could later be adopted by `fast-export`. The key insight is that checking signatures during export provides more reliable information about hash algorithms (for OpenPGP/X.509) and key types (for SSH), though this comes with a performance tradeoff.

The patch series includes improvements to signature parsing, documentation updates, and new test coverage. It represents a pivot from the previous approach that conflated protocol and hash information into a single string. The implementation appears thorough, with all CI tests passing, though the thread context notes there are still unresolved test failures in related functionality that may need to be addressed first.

This proposal seems well-considered, addressing both technical concerns about signature representation and practical considerations about user needs. The discussion will likely focus on whether the new summary format meets the project's needs and whether the performance impact of signature checking during export is acceptable.
