This is part of the string-list test modernization and implementation improvement series, specifically addressing a historical quirk in the string-list insertion logic. Patch 3/8 simplifies the code by having `add_entry()` return direct positive indices rather than using negative values to indicate existing elements, since the negative-index pattern was never actually needed for this function's use cases.

Jeff King confirms this is a safe change, noting the negative-index pattern was a historical artifact that made sense for other functions like `string_list_find_insert_index()` but wasn't necessary for `add_entry()`. The author shejialuo traces this back to the original 2006 introduction of path-list.c (string-list's predecessor).

The change is straightforward and improves code clarity while maintaining behavior. This patch has already been reviewed positively, with the only discussion point being whether to inline a helper function (which the author has decided against to maintain readability). The patch represents one of several cleanups in this series that modernize the string-list implementation alongside converting its tests from shell to C.
