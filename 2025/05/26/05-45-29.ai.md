This is a naming discussion within Patrick Steinhardt's object database refactoring series, specifically about patch 2/17 which renames `object_directory` to `odb_alternate`. 

Justin Tobler raises concerns that `odb_alternate` might be confusing since the structure applies to both primary and alternate object stores, suggesting `object_source` as an alternative. Patrick responds that while he understands the concern, he finds `odb_alternate` acceptable since the primary object directory can conceptually be seen as another repo's alternate. He notes they previously rejected more generic names like `odb_backend`, and while open to `odb_source` if others prefer it, he'd keep `odb_alternate` for now.

The discussion reflects careful consideration of API naming for long-term clarity in the ODB refactoring effort. The technical implementation remains sound regardless of the naming choice, and this appears to be the last open question in an otherwise well-reviewed series. The exchange maintains a constructive tone typical of Git's technical discussions, with Patrick showing willingness to adapt if consensus emerges for an alternative name.
