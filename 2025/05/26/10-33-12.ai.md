This is a technical patch in the signature verification improvement series, specifically focusing on hash algorithm extraction from GPG/GPGSM signatures. It adds support for capturing the hash algorithm used in OpenPGP/X.509 signatures (like SHA-1, SHA-256) from GPG's machine-readable status output.

The patch introduces a new `sig_algo` field in `struct signature_check` to store the hash algorithm name. It implements parsing logic that extracts the algorithm ID from GPG's `VALIDSIG` (8th field) and `ERRSIG` (3rd field) status lines, then maps these numeric IDs to human-readable names using RFC 4880's OpenPGP hash algorithm registry. The implementation includes a lookup table for common algorithms (MD5, SHA-1, RIPEMD-160, SHA-2 variants) with proper memory management.

This change is part of the broader effort to improve signature handling in Git, particularly around the gpg-interface internals. While not directly addressing the test failures in t9350 mentioned in the thread context, it provides foundational infrastructure that could help with signature verification workflows and future fast-export/import improvements. The patch follows the thread's technical direction by adding more detailed signature metadata without breaking backward compatibility.

Key technical details for future reference:
- New field: `sig_algo` in `struct signature_check`
- Parses GPG status lines: `VALIDSIG` (field 8) and `ERRSIG` (field 3)
- Algorithm mapping based on RFC 4880 section 9.4
- Memory management integrated with existing `signature_check_clear()`
- No behavior change for existing successful verifications
- Could enable future features like algorithm warnings or verification UIs
