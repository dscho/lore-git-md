This is a documentation and behavior change patch for Git's experimental signature handling in `fast-export`/`fast-import`. Junio Hamano proposes marking the signed commits feature as explicitly experimental in the upcoming 2.50.0 release while deferring more substantial changes to a future cycle.

The patch makes three key changes: First, it adds prominent warnings in the documentation (fast-export, fast-import, and release notes) that the signature format is experimental and may change incompatibly. Second, it changes the default behavior for signed commits from 'abort' to 'strip' to maintain compatibility with existing workflows that didn't specify `--signed-commits`. Third, it removes the obscure `FAST_EXPORT_SIGNED_COMMITS_NOABORT` environment variable escape hatch since it's no longer needed with the more conservative default.

The changes reflect a pragmatic compromise in the ongoing signature handling discussion - acknowledging the experimental nature of the design is still evolving while minimizing disruption for users. The patch simplifies the test suite by removing redundant tests for the old environment variable and adding a test confirming the new default matches explicit `--signed-commits=strip` behavior.

This appears to be a well-considered interim step that addresses immediate compatibility concerns while the community works toward a more comprehensive solution in future releases. The documentation updates are thorough and the behavior changes are minimal and justified.
