This is a feature patch adding persistent configuration support for IMAP backend selection in `git imap-send`. It introduces a new `imap.usecurl` config option that lets users set their preferred backend (libcurl or OpenSSL) as a default, while still allowing runtime override via the existing `--curl`/`--no-curl` command-line flags.

The patch is part of a larger v7 series that comprehensively improves IMAP functionality, with this being the sixth of nine patches. The series has undergone extensive review and iteration, addressing authentication methods, memory management, and user experience. This particular addition provides the missing persistent configuration piece to complement the existing runtime CLI backend selection.

The implementation is straightforward - it adds the config option documentation and hooks it into the existing configuration parser. The behavior follows Git's standard precedence rules where command-line flags override config settings. The patch maintains consistency with the build system constraints (`USE_CURL_FOR_IMAP_SEND`/`NO_OPENSSL`) that were in place for the CLI options.

As with the rest of the series, this appears well-considered and properly implemented. The documentation clearly explains the interaction between config and command-line options, and the change is minimal and focused. This completes one of the key goals of the series - giving users comprehensive control over IMAP backend selection through both temporary and persistent means.
