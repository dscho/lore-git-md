Performance optimization for MIDX packfile lookups. This is the second patch in Patrick Steinhardt's v3 series addressing redundant system calls when handling missing packfiles in multi-pack indexes.

The patch introduces a negative lookup cache (MIDX_PACK_ERROR) to avoid repeatedly checking for missing packfiles that were indexed but later removed. When prepare_midx_pack() fails to find a pack, it now caches this failure, preventing subsequent redundant access() and stat() calls. The change is well-motivated with clear benchmark results showing a 4x speedup for `git log --patch` in repositories with stale MIDX files.

The implementation is clean and focused, touching only midx.c with minimal changes. It builds on Jeff King's earlier work while maintaining the existing MIDX behavior - the cache simply optimizes the failure case. The patch includes thorough testing data showing both reduced system calls (from 24,000 to 83) and improved performance. While ideally the MIDX should stay in sync with packfiles, this optimization provides real benefits for the common case of stale indexes.
