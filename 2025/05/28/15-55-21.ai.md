This is a test infrastructure patch in Patrick Steinhardt's ongoing series to improve TAP compliance between Make and Meson test runners. The specific issue here addresses shell trace output handling when using verbose flags (`-x`, `--verbose`).

The patch originally proposed redirecting both stdout and stderr to stderr to avoid breaking TAP output parsers, but Junio Hamano raises concerns about potential buffering issues causing interleaved output. The discussion reveals an important distinction: TAP-formatted output (test results) must go to stdout for parsers, while all other output (including shell traces) should go to stderr.

Key technical points:
- Current behavior splits output between fd3 (stdout) and fd4 (stderr)
- TAP parsers expect clean stdout with only test results
- Shell traces currently risk corrupting TAP output when verbose
- Buffering behavior remains unchanged by the redirects
- t0000-basic.sh tests verify stdout/stderr separation

The thread shows this is part of a larger effort to standardize test output handling across build systems, with particular attention to maintaining TAP compliance while preserving useful debugging output. The discussion highlights an unresolved question about output ordering guarantees when merging streams, which may need further investigation before finalizing the approach.
