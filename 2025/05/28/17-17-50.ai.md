This is a bugfix patch in the `imap-send` series, specifically addressing memory management in the CRAM-MD5 authentication flow. The patch fixes a memory leak that could occur when socket writes fail during authentication - the `response` buffer would not be freed in the error path. The fix is straightforward, adding a `free(response)` call before returning the error when `socket_write()` fails to write the full response.

The change is part of the comprehensive memory management improvements in the larger IMAP series, which has seen multiple rounds of review (now at v7). This particular leak was likely identified during the thorough error path testing that has been a focus of the series. The patch follows the established pattern of the series by ensuring all allocated resources are properly cleaned up in both success and error cases.

Key technical details:
- Fixes a leak in `auth_cram_md5()` when `socket_write()` fails
- Maintains consistency with the series' focus on robust memory management
- Touches the same authentication code that was previously fixed for other error cases
- Follows the pattern of the series by adding proper cleanup in error paths

This appears to be one of the final memory management fixes in the series, which has comprehensive coverage of all authentication methods (OAuth2.0, PLAIN, and now fully fixed CRAM-MD5). The change is small but important for correctness of the authentication flow.
