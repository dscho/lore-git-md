This is a documentation and behavior change patch addressing the experimental status of signature handling in `git fast-export`/`fast-import`. The patch comes from Junio Hamano as a follow-up to ongoing discussion about signature verification workflows.

The key changes mark the `--signed-commits` feature as experimental in multiple documentation files (RelNotes, fast-export, fast-import) and change the default behavior from 'abort' to 'strip' for signed commits. This matches the behavior of older Git that didn't have the `--signed-commits` option at all. The patch removes the `FAST_EXPORT_SIGNED_COMMITS_NOABORT` environment variable escape hatch since it's no longer needed with the more conservative default behavior.

The test changes reflect this new default, simplifying the test cases to verify that the default 'strip' behavior matches explicit `--signed-commits=strip`. This represents a pragmatic step forward while the community continues discussing more comprehensive signature handling improvements, deferring those larger changes to a future release. The patch acknowledges that the current signature format may change incompatibly in future versions.
