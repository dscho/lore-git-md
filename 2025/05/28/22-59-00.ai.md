This is a refactoring patch in the ongoing MIDX (multi-pack-index) improvements series, introducing a new helper function to safely access pack names across MIDX layers. The patch adds `nth_midxed_pack_name()` to provide a safer interface for accessing pack names in MIDX chains, where the global pack ID may not match the local index due to incremental MIDX layers. It replaces direct array accesses to `pack_names` with this new helper in several key locations: pack-bitmap.c (for bitmap operations) and test-read-midx.c (for test infrastructure).

The change addresses a subtle correctness issue where direct array access could be error-prone when dealing with MIDX chains, particularly around the boundary between base and incremental layers. The helper properly handles the translation between global and local pack IDs via the existing `midx_for_pack()` function. This builds on previous work in the thread to improve MIDX safety and encapsulation, following Taylor Blau's pattern of introducing dedicated accessors for MIDX internals.

The patch is part of a 4-patch series (this being v2 of the first patch) and follows established patterns from earlier MIDX refactoring. It touches core MIDX functionality but appears focused and well-contained, updating all necessary callers while maintaining the existing behavior. The changes align with the thread's broader goals of improving MIDX code safety and maintainability through better encapsulation.
