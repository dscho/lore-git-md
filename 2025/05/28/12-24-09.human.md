This is a performance optimization patch series addressing MIDX packfile lookups when packs are missing. Patrick Steinhardt follows up on earlier discussions about MIDX performance and correctness, now focusing on reducing unnecessary syscalls when MIDX entries reference nonexistent packfiles.

The series introduces two changes:
1. Adds documentation explaining the current ordering of auxiliary packfile lookups (which was previously implicit knowledge)
2. Implements a negative lookup cache using a macro `MIDX_PACK_ERROR` to avoid repeated syscalls for missing packs

The motivation comes from production issues where stale MIDX files caused Git to repeatedly check for missing packs via multiple syscalls (three `access()` calls and one `stat()` per missing pack). While the author notes this is likely a rare edge case, the solution is straightforward - cache negative lookups to avoid redundant filesystem checks.

The patch builds on prior work in this thread (including Patrick's own performance optimizations and Taylor Blau's safety assertions) while keeping the changes minimal. The v3 revision introduces a macro to clean up the `(void *)(intptr_t)-1` magic number used in earlier versions. The changes are well-contained to MIDX handling code and maintain backward compatibility.
