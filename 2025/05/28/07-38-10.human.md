This is part 2 of a 6-patch series adding OAuth2.0 authentication support to `git imap-send`. The patch implements both the standard OAUTHBEARER (RFC 5801/7628) and Google's XOAUTH2 authentication mechanisms, completing the feature work described in the cover letter.

The implementation handles both curl's native OAuth2.0 API (using `CURLOPT_XOAUTH2_BEARER`) and an OpenSSL fallback path. For OpenSSL builds, new helper functions `oauthbearer_base64()` and `xoauth2_base64()` construct and encode the authentication strings according to the respective specifications. The patch also documents provider-specific guidance for Gmail (which supports both mechanisms) and Outlook (which only supports XOAUTH2).

The changes are thorough - adding new capability flags (`AUTH_OAUTHBEARER` and `AUTH_XOAUTH2`), updating documentation with clear examples, and implementing proper error handling for both authentication paths. The implementation follows the established pattern of the existing CRAM-MD5 support while accounting for OAuth2.0's different requirements (like using access tokens instead of passwords).

This appears to be a well-constructed patch that cleanly integrates with the existing IMAP authentication framework. The documentation updates are particularly helpful, explaining both the technical requirements and practical setup for major email providers. As part of the larger series that has undergone multiple rounds of review, this looks ready for inclusion.
