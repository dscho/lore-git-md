This is a refactoring and API improvement series for MIDX (multi-pack-index) handling, building on Patrick Steinhardt's performance optimization work. The series focuses on making the prepare_midx_pack() interface more ergonomic and safer to use across MIDX chain layers.

The key changes include:

1. Introducing nth_midxed_pack_name() to safely access pack names in MIDX chains, preventing direct array access that could be error-prone with incremental MIDXs. This affects midx.c, pack-bitmap.c, and test helpers.

2. Adding assertions in midx-write.c to guard against incremental MIDX cases that shouldn't occur during repacking, making the code's assumptions more explicit.

3. Extracting the inner loop of fill_packs_from_midx() into a helper function (fill_packs_from_midx_1()) to simplify the logic and prepare for future changes.

4. Changing prepare_midx_pack() to return a packed_git pointer directly rather than using pack IDs, making the API more straightforward. This affects all MIDX subsystems and includes updates to handle the new MIDX_PACK_ERROR macro from Patrick's v3 series.

The series is based on Patrick's v3 performance patches and maintains the separation of concerns between performance optimizations and API improvements. Taylor Blau has addressed previous feedback by using the new MIDX_PACK_ERROR macro consistently and improving the safety of pack name access across MIDX layers. The changes are focused on code organization and maintainability while preserving the performance gains from the underlying work.
