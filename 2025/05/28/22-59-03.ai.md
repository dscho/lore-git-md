This is a correctness patch in the MIDX (multi-pack-index) subsystem, adding assertions to guard against invalid incremental MIDX chains in repacking operations. The patch builds on the ongoing thread about MIDX performance optimizations and safety improvements.

The key insight is that while the `want_included_pack()` function and its callers (`fill_included_packs_all()` and `fill_included_packs_batch()`) appear vulnerable to incorrect pack lookups in incremental MIDX chains, they are actually protected by an earlier check in `midx_repack()` that rejects incremental MIDXs entirely. Taylor Blau adds explicit assertions to make this invariant clear and prevent future breakage if the code structure changes.

The patch adds three identical assertions checking that the MIDX pointer is non-NULL and has no base MIDX (i.e., isn't part of an incremental chain). These assertions document and enforce the existing assumption that these functions only operate on single-layer MIDXs. The changes are minimal but important for long-term maintainability, making implicit assumptions explicit and preventing subtle bugs if the surrounding code evolves.
