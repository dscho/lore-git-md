This is a documentation and behavior change patch for Git's fast-export/import signature handling, marking the feature as experimental while adjusting defaults for better backward compatibility.

Elijah Newren responds to Junio Hamano's patch that documents the experimental nature of signature handling in fast-export/import and changes the default behavior from 'abort' to 'strip' for signed commits. The change aligns with how older versions behaved before the feature was introduced, avoiding potential breakage for tools like git-filter-repo that call fast-export internally.

Newren approves the change overall, noting it will save him from having to modify filter-repo. He raises an interesting question about Git's typical deprecation process - usually involving warnings period before changing defaults - but doesn't oppose the immediate change. The patch review also catches a minor typo ("discourge" -> "discourage").

The technical changes include:
- Adding "experimental" warnings to documentation (RelNotes, fast-export, fast-import)
- Changing the default signed commit handling to 'strip'
- Removing the FAST_EXPORT_SIGNED_COMMITS_NOABORT environment variable
- Updating tests to verify the new default matches explicit --signed-commits=strip behavior

This represents a pragmatic resolution to immediate compatibility concerns while the signature handling design continues to evolve, with the experimental status clearly communicated to users. The patch appears well-considered and maintains Git's stability while allowing future improvements to the signature system.
