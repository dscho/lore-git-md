Bugfix for `imap-send` configuration parser regression that NULLed out the wrong field. This is the first patch in a v7 series that has already seen extensive review and iteration.

The patch fixes a regression introduced in 6d1f198f34 where the configuration parser would incorrectly free and NULL `cfg->folder` when processing other IMAP settings (`imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`). The fix properly frees the correct field for each configuration option. This bug made `git-imap-send` completely unusable since Git 2.46.0, though it went unnoticed for some time likely due to alternatives like `git-send-email` being more commonly used.

The changes are straightforward - each configuration case now frees its own field rather than incorrectly freeing `cfg->folder`. This matches the thread context indicating this was a critical configuration bug that has now been fully fixed with proper field-specific cleanup. The patch is part of a larger series that provides comprehensive IMAP functionality improvements, with this being the foundational fix that enables the rest of the features.
