This is a refactoring patch in the ongoing MIDX (multi-pack-index) improvements series. It introduces a new helper function `nth_midxed_pack_name()` to safely access pack names in MIDX chains, where pack IDs can differ between layers.

The patch replaces direct accesses to the `pack_names` array with calls to this new helper, which properly handles the translation between global and local pack IDs. This is particularly important for incremental MIDX chains where the same pack may have different IDs in different layers. The change fixes two locations in pack-bitmap.c and one in test-read-midx.c that were previously accessing the array directly.

This appears to be a well-motivated change that improves code safety by centralizing pack name access logic. It's part of a broader effort to make MIDX handling more robust, following earlier discussions about array bounds safety and API improvements. The patch is cleanly implemented with appropriate header updates and test coverage.
