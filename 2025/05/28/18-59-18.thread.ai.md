Thread identity: Build failure report and fix for Git 2.50.0-rc0 on NonStop platform involving reftable subsystem's `REFTABLE_UNUSED` macro.

Core problem: Compilation error in `blocksource.c` where NonStop's C99 compiler fails to parse GNU-specific `__attribute__((__unused__))` in `REFTABLE_UNUSED` macro, used for marking unused function parameters in reftable code.

Current status: Carlo Marcelo Arenas Belón's fix making the GNU attribute conditional has been acknowledged by Junio C Hamano, who indicates it will be queued. Brian M. Carlson's follow-up confirms the simpler solution is sufficient given modern GCC version requirements, settling any remaining questions about the approach. The solution follows Git's historical approach to such compatibility issues, though Hamano notes the main codebase uses a more complex version in `compat/posix.h` with deprecation warnings.

Key technical details:
- Failing component: `REFTABLE_UNUSED` macro in `reftable/basics.h`
- Problematic syntax: GNU `__attribute__((__unused__))` not supported on NonStop
- Solution: Conditional compilation with `#ifdef __GNUC__` (empty definition otherwise)
- Introduced in: commit f93b2a0424 (reftable internal UNUSED annotations)
- Historical context: RHEL 7 (GCC 4.8) and Debian 7 (GCC 4.7) are EOL, making complex version checks unnecessary
- Alternative implementation exists in `compat/posix.h` with deprecation attributes
- Minimal change focused only on reported issue

Open questions: None remaining - discussion confirms the simpler solution is adequate and no further standardization needed for this case.
