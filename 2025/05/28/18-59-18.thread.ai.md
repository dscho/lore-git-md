Thread identity: Build failure report and fix for Git 2.50.0-rc0 on NonStop platform involving reftable subsystem's `REFTABLE_UNUSED` macro, with follow-up discussion about consistency with core Git's attribute handling.

Core problem: Compilation error in `blocksource.c` where NonStop's C99 compiler fails to parse GNU-specific `__attribute__((__unused__))` in `REFTABLE_UNUSED` macro, used for marking unused function parameters in reftable code. Follow-up discussion revealed deeper inconsistency between reftable's attribute handling and core Git's compatibility layer, where `MAYBE_UNUSED` works on NonStop due to platform-specific preprocessing.

Current status: Carlo Marcelo Arenas Belón's fix making the GNU attribute conditional has been acknowledged by Junio C Hamano and will be queued, though Randall S. Becker reports the issue remains present in Git 2.50.0-rc0. Patrick Steinhardt has confirmed understanding Jeff King's technical explanation about why core Git's `MAYBE_UNUSED` works on NonStop (platform-specific handling in `git-compat-util.h` makes `__attribute__()` a no-op before macro definition), resolving the earlier inconsistency question. The thread has reached consensus with no further changes needed to the queued fix.

Key technical details:
- Failing component: `REFTABLE_UNUSED` macro in `reftable/basics.h`
- Problematic syntax: GNU `__attribute__((__unused__))` not supported on NonStop
- Solution: Conditional compilation with `#ifdef __GNUC__` (empty definition otherwise)
- Key difference from core Git: `git-compat-util.h` has platform-specific preprocessing that makes `__attribute__()` a no-op before `MAYBE_UNUSED` definition
- Historical context: Older GCC versions (pre-4.5) no longer relevant due to EOL distros
- Introduced in: commit f93b2a0424 (reftable internal UNUSED annotations)
- Alternative implementations exist in `compat/posix.h` and `git-compat-util.h`

Open questions: None remaining - all technical questions resolved. Discussion has identified potential future work to standardize attribute macros across codebase, though immediate fix remains adequate.
