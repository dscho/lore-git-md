Feature patch adding GPG signing support to `git subtree` commands. This is the first of two patches in a series from a first-time contributor, implementing the core functionality for signing subtree operations.

The patch adds standard `-S/--gpg-sign` options to all commit-creating `git subtree` commands (add, merge, split, pull, push), following Git's conventional signing interface. The implementation forwards the signing option to the underlying `git commit-tree` and `git merge` calls. Documentation updates in `git-subtree.adoc` explain the new options with the same phrasing used elsewhere in Git's docs.

Key technical details include:
- New `gpg_sign_opt()` helper function that formats the signing option correctly
- Option parsing that handles both `-S` (default key) and `-S<keyid>` forms
- Signing support for all commit creation paths (regular commits, squash merges, etc.)
- No behavior change when signing is not used

The implementation appears thorough, matching Git's existing signing patterns. The patch follows standard practices for option handling and documentation. As noted in the thread context, this addresses a real-world need for signed commits in subtree-based dependency management workflows. The second patch in the series will add test coverage.
