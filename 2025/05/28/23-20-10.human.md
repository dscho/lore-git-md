Performance optimization series (part 1/9) - standardizing option handling in pack-objects.

This is kicking off a 9-part series to optimize MIDX and cruft pack interactions during repacking. The first patch is a straightforward refactoring that replaces custom option conflict checks in `pack-objects` with the standard `die_for_incompatible_opt2()` function. This brings consistency to error messages when incompatible options like `--stdin-packs` and `--filter` are used together.

The change is mechanical but meaningful - it unifies the error message format across Git while maintaining the same validation logic. A test had to be updated to expect the new standardized message format. This cleanup precedes more substantive changes in later patches that will introduce new pack-objects behaviors and configuration options for cruft pack handling.

As the first in a well-structured series, this patch sets the stage for the performance optimizations to come while standing on its own as a minor code quality improvement. The rest of the series (as noted in the thread context) has already received positive feedback during review.
