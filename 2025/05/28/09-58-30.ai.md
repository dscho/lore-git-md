Performance optimization in the promisor-remote subsystem. This patch removes an unnecessary object verification check that was causing significant slowdowns in large repositories.

The change targets `promisor_remote_get_direct()`, which handles fetching objects from promisor remotes. The original code performed a redundant check using `is_promisor_object()` on each remaining object after a failed fetch, which involved scanning local packfiles. The patch argues this check is unnecessary because callers already filter out local objects, meaning all objects passed to this function are guaranteed to be promisor objects.

The key technical change replaces the per-object verification loop with a simple check for any remaining objects, immediately failing on the first one. This eliminates what the commit message describes as an "agonizingly slow" process in large repositories. The diff shows removal of the iteration variable and simplification of the error handling path.

This appears to be a well-motivated optimization with a clear performance rationale. The commit message effectively explains why the check was redundant and the performance impact of removing it. The change is focused and maintains the same error semantics while being more efficient.
