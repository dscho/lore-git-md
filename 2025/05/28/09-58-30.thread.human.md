This thread discusses a performance optimization in Git's promisor-remote subsystem, which handles fetching objects from remote partial clone repositories. The patch removes an unnecessary object verification check in `promisor_remote_get_direct()` that was causing significant slowdowns in large repositories.

The original implementation performed redundant `is_promisor_object()` checks on each remaining object after a failed fetch, requiring expensive scans of local packfiles. The author argues this check is unnecessary because callers already filter out local objects, meaning all objects passed to this function are guaranteed to be promisor objects. The patch simplifies the verification to just check for any remaining objects and fail immediately on the first one, eliminating what was described as an "agonizingly slow" process in large repositories.

The change appears well-motivated and focused, maintaining the same error semantics while improving performance. The commit message clearly explains the optimization rationale and the technical details of the change. This should provide noticeable speed improvements for operations involving promisor remotes in large repositories.
