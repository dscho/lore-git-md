This thread discusses optimizing performance in Git's promisor-remote subsystem by removing redundant object verification checks. The original patch from Han Young proposed eliminating slow `is_promisor_object()` checks in `promisor_remote_get_direct()`, arguing these were unnecessary since callers already filter out local objects. The change would significantly speed up operations in large repositories by replacing per-object verification with a simple check for any remaining objects.

Junio C Hamano has raised important concerns about this approach. While acknowledging the performance benefits, he questions whether all objects passed to this function are truly guaranteed to be promisor objects, as the commit message claims. He notes the current callers appear to simply pass objects not found locally, rather than explicitly filtering for promisor objects. Junio also points out the behavior change - the function would now fail on any fetch error, not just for objects that were actually promised. This could have unintended consequences for error handling.

The discussion has now shifted to whether there might be a better solution, such as optimizing `is_promisor_object()` itself by caching results. Key reviewers Christian Couder and Jonathan Tan have been CC'd to weigh in on these technical concerns. The thread remains open while awaiting their input on how to balance performance improvements with maintaining correct object verification semantics.
