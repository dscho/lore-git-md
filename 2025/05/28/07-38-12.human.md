This is a bugfix patch in the `imap-send` series, addressing a memory leak in the CRAM-MD5 authentication path. The patch ensures the `response` buffer is freed when `socket_write()` fails during authentication, closing a case that was missed in earlier versions of the series.

The change is small but important - it adds a `free(response)` call in the error path where sending the authentication response fails. This completes the comprehensive memory leak fixes for CRAM-MD5 that have been iterated on throughout the series (v4 fixed a use-after-free, and now v6 catches this final leak case).

The patch is straightforward and clearly motivated - it plugs a real memory leak that could occur during IMAP authentication.
