Feature patch adding GPG signing support to `git subtree` commands. This is the first of a 2-patch series from first-time contributor Patrik Weiskircher, introducing the ability to sign commits created by subtree operations.

The patch adds the standard `-S/--gpg-sign` option to all commit-creating `git subtree` commands (add, merge, split, pull, push), matching the pattern used in other Git commands. The implementation forwards the signing option to the underlying `commit-tree` and `merge` operations. Documentation is updated to reflect the new option, which supports both key specification (`-Skeyid`) and default signing behavior (`-S`).

The changes appear well-contained, modifying only the subtree implementation files (`git-subtree.sh` and `git-subtree.adoc`) without touching core Git code. The implementation follows established patterns for GPG signing in Git, suggesting it should integrate cleanly with existing workflows. As noted in the thread context, this addresses a real-world need for signed commits in subtree-based dependency management.

The patch looks technically sound at first glance, though reviewers will likely want to verify the test coverage (coming in the second patch) exercises all the new signing scenarios. This is a straightforward but useful addition that brings subtree operations in line with Git's standard signing capabilities.
