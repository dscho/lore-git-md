Performance optimization patch for MIDX packfile lookup, part of an ongoing series to improve multi-pack-index handling. This v3 patch from Patrick Steinhardt builds on Jeff King's earlier work to address repeated system calls when looking up missing packfiles in a stale MIDX.

The core change introduces a negative lookup cache using a new `MIDX_PACK_ERROR` macro (defined as `(void *)(intptr_t)-1`) to mark packs that have been confirmed missing. When `prepare_midx_pack()` fails to find a pack, it now caches this failure state, preventing repeated system calls for the same missing pack. The patch modifies several MIDX functions to handle this new state:
- `close_midx()` skips MIDX_PACK_ERROR entries when clearing pack references
- `prepare_midx_pack()` checks the cache before attempting lookups
- `nth_midxed_pack()` returns NULL for cached misses

The patch demonstrates significant performance improvements - reducing system calls from ~24,000 to ~80 in the test case, and speeding up `git log --patch` by nearly 4x. While ideally the MIDX should stay in sync with packfiles, this change provides robust handling of the stale case with minimal overhead.

This is the second patch in a v3 series focused on eliminating redundant system calls. It follows the thread's progression from performance optimizations to correctness fixes, now incorporating the `MIDX_PACK_ERROR` macro discussed earlier in the thread. The changes are well-contained to MIDX pack lookup logic while maintaining compatibility with the broader MIDX chain management work being done in parallel by Taylor Blau.
