This is a discussion about the historical context and potential evolution of `git commit -a` behavior, specifically regarding its handling of untracked files.

Junio C Hamano responds to Kristoffer Haugsbakk's historical analysis of why `git commit -a` only stages modified tracked files. He notes that early Git lacked robust `.gitignore` functionality, making it risky to automatically stage untracked files. The original implementation (using `git-diff-files` piped to `git-update-cache`) was likely designed conservatively to avoid accidentally staging unwanted files like build artifacts.

Hamano observes that while the historical context explains the current behavior, modern Git has better ignore-file support. He suggests that experienced users are more likely to be careful about including new files than forgetting to add necessary ones, implying the original safety concerns may be less relevant today.

The email doesn't take a direct position on Jon Forrest's proposal for a new `-A` flag, but provides important historical and practical context that would inform any decision about changing this behavior. The discussion remains at the conceptual level, with no implementation details yet proposed.
