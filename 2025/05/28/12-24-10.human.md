This is a documentation patch that clarifies an important ordering constraint in packfile handling. Patrick Steinhardt explains why Git checks auxiliary packfile data (like .keep files) before verifying the packfile itself, even though this seems inefficient at first glance.

The patch adds a detailed comment to `add_packed_git()` explaining that the current order of system calls is necessary to avoid race conditions with concurrent packfile operations. When installing packs, auxiliary files are moved first, and when deleting, the .idx/.pack files are removed first. Checking auxiliary files first ensures we either get a consistent view of all files or fail cleanly if the pack is being deleted.

This is part of Patrick's v3 series optimizing packfile system calls, but stands alone as a useful documentation improvement. The explanation is clear and well-motivated, addressing a subtle but important detail in Git's packfile handling that could easily trip up future developers. The patch is small and focused, adding just the explanatory comment without changing behavior.
