This is a documentation patch that clarifies Gmail authentication requirements for `git send-email`. It's the final patch in a 4-part series that consolidated email provider documentation.

The patch updates the Gmail section in git-send-email.adoc to explicitly state that regular account passwords no longer work with Gmail, regardless of multi-factor authentication status. It maintains the existing guidance about app passwords for MFA users while adding new text explaining that OAuth2.0 is an alternative for users who don't want to enable MFA.

The change reflects modern Gmail security practices, as the previous documentation was written when Google still allowed regular password usage. The patch completes the series' goal of providing clear, up-to-date email configuration instructions by addressing this subtle but important authentication detail.

Key technical points:
- Modifies only git-send-email.adoc
- Documents Gmail's current password policy (no regular passwords allowed)
- Preserves existing app password instructions for MFA users
- Adds OAuth2.0 as an option for non-MFA users
- References the subsequent OAuth section ("as described below")
- Maintains the series' focus on centralized email documentation

This patch represents the final refinement in the documentation series, addressing a specific authentication clarification that wasn't covered in the earlier structural reorganization. It demonstrates attention to detail in ensuring the email configuration instructions accurately reflect current provider requirements.
