This is a follow-up discussion on the signature handling improvements in `git fast-export`/`fast-import`, specifically addressing Junio Hamano's patch to mark the feature as experimental and change the default behavior.

Elijah Newren generally agrees with the changes but raises a question about the process for changing defaults, noting that Git typically follows a deprecation period before changing defaults, whereas this change appears more immediate. He provides concrete evidence from git-filter-repo's perspective that the change would be helpful, but seeks clarification on why this case differs from past practices. The technical changes in Junio's patch include:
- Marking `--signed-commits` as experimental in RelNotes and documentation
- Changing default behavior from 'abort' to 'strip'
- Removing the `FAST_EXPORT_SIGNED_COMMITS_NOABORT` environment variable
- Updating tests to verify the new default matches explicit `--signed-commits=strip`

The discussion highlights the ongoing tension between feature development and stability guarantees, with this patch representing a pragmatic solution to prevent compatibility issues while the signature handling design continues to evolve. The thread shows consensus on marking the feature experimental but leaves open questions about Git's standard deprecation processes for future consideration.
