This is the final patch in a feature series adding configuration options to `imap-send`. It introduces a new `imap.usecurl` config option to persistently set the preferred backend (curl vs OpenSSL) for IMAP operations, complementing the existing `--[no]-curl` command-line flags. The implementation follows the established pattern of the series, with proper build-time constraint handling (`USE_CURL_FOR_IMAP_SEND`/`NO_OPENSSL`) and clear documentation of precedence (CLI overrides config).

The patch adds the config option to `imap-send.c`'s configuration parser alongside other IMAP settings, using the standard `git_config_bool()` helper. Documentation updates explain the new option in both the `imap.adoc` config reference and `git-imap-send.adoc` man page, with consistent formatting of build-time option names in backticks. The change is minimal and focused, touching only the necessary files to add this final piece of user control.

This completes the series' goal of providing comprehensive backend selection options, now offering both runtime (`--curl`/`--no-curl`) and persistent (`imap.usecurl`) configuration methods. The implementation maintains all prior fixes from the series (configuration parser correctness, memory management, authentication parity) while adding this user-facing convenience. With this patch, the series achieves full feature parity between command-line and config-based control of IMAP backend selection.
