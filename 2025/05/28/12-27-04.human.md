This is a test infrastructure update addressing inconsistent handling of unexpected test successes between Meson and Make-based CI systems. Patrick Steinhardt proposes a solution to make the Make-based test runner fail when TODO tests unexpectedly pass, aligning it with Meson's stricter behavior.

The patch modifies `t/test-lib.sh` and `t0000-basic.sh` to:
1. Make the test suite exit with failure when fixed tests (unexpected passes) are detected
2. Use `write_and_run_sub_test_lib_test_err` for TODO test cases to properly capture their output
3. Maintain the existing behavior for inverted exit codes

The change addresses an inconsistency Junio Hamano noted where the osx-meson CI job fails on unexpected passes while osx-gcc (Make-based) treats them as successes. While the solution makes prove report these as "dubious" rather than clean failures, it does surface the unexpected passes clearly in the output.

This is a focused technical change that advances the thread's goal of consistent test behavior across build systems, though it trades some output cleanliness for stricter validation. The patch appears straightforward and maintains compatibility with existing test infrastructure while closing the specific gap identified in CI behavior.
