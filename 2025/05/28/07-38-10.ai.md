Feature patch adding OAuth2.0 authentication support to `imap-send`, part of a larger v6 series addressing IMAP improvements. This specific patch implements both OAUTHBEARER (RFC 5801/7628) and XOAUTH2 (Google's proprietary variant) authentication methods, with OpenSSL fallback paths when curl is unavailable.

The implementation adds new capability flags `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` to the IMAP protocol handling, with corresponding base64 encoding helpers (`oauthbearer_base64()` and `xoauth2_base64()`) for OpenSSL compatibility. The curl integration uses `CURLOPT_XOAUTH2_BEARER` for automatic mechanism selection. Documentation updates include provider-specific guidance for Gmail (app passwords/OAuth2.0 tokens) and Outlook (XOAUTH2-only support).

Key technical details:
- New authentication methods integrate with existing `imap.authmethod` configuration
- OpenSSL fallback paths maintain functionality when curl is unavailable
- Error handling covers OpenSSL encoding failures and socket write errors
- Documentation explains OAuth2.0 requirements for major providers (Gmail, Outlook)
- Maintains backward compatibility with existing authentication methods
- Follows RFC standards for OAUTHBEARER while supporting Google's XOAUTH2 variant

The patch builds on prior work in the series that fixed configuration parsing and memory management issues, now adding comprehensive OAuth2.0 support as a major feature enhancement. Review history shows thorough iteration with input from multiple contributors, addressing technical constraints and edge cases.
