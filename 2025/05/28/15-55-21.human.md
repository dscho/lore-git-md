This is a test infrastructure patch in Patrick Steinhardt's ongoing series to improve TAP compliance between Make and Meson test runs. The specific issue addresses how shell traces (-x output) interact with TAP parsing when tests run in verbose mode.

The patch originally proposed redirecting both stdout and stderr to stderr to avoid breaking TAP output, but Junio Hamano raises valid concerns about potential buffering issues causing interleaved output. Patrick acknowledges this could happen but isn't sure how to solve it while maintaining the TAP compatibility goals. 

The discussion reveals an important distinction in the output streams: TAP-formatted results (like "ok 1") must go to stdout for parsers, while all other output (including shell traces) should go to stderr. This clarification helps explain why the current approach in t0000 tests checks the streams separately.

The patch appears technically sound for its immediate goal of TAP compliance, but the buffering question suggests there may be deeper stream handling considerations that need resolution before finalizing this change. This is part of a larger, carefully reviewed effort to align test behavior across build systems.
