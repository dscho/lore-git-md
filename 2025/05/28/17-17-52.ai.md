This is part of the ongoing `imap-send` feature and bugfix series, specifically adding persistent configuration for backend selection between libcurl and OpenSSL. The patch introduces a new `imap.usecurl` config option that allows users to set their preferred backend (curl vs OpenSSL) as a default, while still allowing runtime override via the existing `--curl`/`--no-curl` command-line options. The implementation follows the series' pattern of proper memory management and build-time constraint handling.

The change adds documentation for the new config option in both the `imap.adoc` config documentation and updates the `git-imap-send.adoc` man page to clarify the relationship between CLI flags and config settings. The implementation is minimal - just adding the config parser for `imap.usecurl` that sets the existing `use_curl` global variable, maintaining consistency with the rest of the codebase.

This completes one of the series' major goals by providing both runtime (`--curl`/`--no-curl`) and persistent (`imap.usecurl`) control over backend selection. The patch follows the established pattern of the series by properly documenting the precedence (CLI overrides config) and build constraints (`USE_CURL_FOR_IMAP_SEND`/`NO_OPENSSL`). As with other patches in the series, this maintains backward compatibility while adding new functionality.

Key technical details:
