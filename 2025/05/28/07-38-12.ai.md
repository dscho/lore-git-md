This Bugfix for CRAM-MD5 memory leak in imap-send

This patch completes the comprehensive memory leak fixes for CRAM-MD5 authentication in `imap-send` by addressing the final error path where socket writes fail. The change ensures the `response` buffer is freed when `socket_write()` returns an error, matching the existing cleanup that happens on success.

The fix is straightforward - wrapping the error return with a `free(response)` call before propagating the error. This was the last remaining leak path identified in the CRAM-MD5 implementation, following earlier fixes in the series for other error cases. The patch maintains the same error message and behavior while properly cleaning up allocated memory.

This is part of a larger v6 series that has already addressed multiple authentication-related issues in `imap-send`, including configuration parsing bugs, OAuth2.0 support, and other memory management problems. The series has undergone thorough review with multiple iterations incorporating feedback, and this patch represents the final piece of the CRAM-MD5 leak fixes that were identified during that process.
