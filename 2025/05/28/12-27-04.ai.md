This is a test infrastructure patch addressing the handling of unexpected test passes in the Git test suite, part of Patrick Steinhardt's ongoing Meson build system series. The email responds to Junio Hamano's observation about inconsistent behavior between Meson and Make-based CI jobs when tests marked as TODO unexpectedly pass.

The key technical changes:
- Modifies `t0000-basic.sh` to use `write_and_run_sub_test_lib_test_err` for TODO tests that might pass
- Updates `test-lib.sh` to exit with status 1 when fixed tests (`test_fixed != 0`) are detected
- Preserves the existing `--invert-exit-code` behavior while adding the new failure mode

The patch causes prove to report unexpected passes as failures" (with "Dubious" status) while still showing the passing subtest count. This aligns the Make-based test runner behavior with Meson's stricter validation approach discussed earlier in the thread, though Patrick notes the prove output formatting isn't ideal.

This change directly addresses the CI inconsistency Junio identified while maintaining the thread's principle that unexpected passes should be treated as errors. The implementation builds on previous test infrastructure modifications in the series, particularly around TAP output handling and test result validation.
