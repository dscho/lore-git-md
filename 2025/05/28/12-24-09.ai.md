Performance optimization patch series addressing MIDX packfile lookup inefficiencies. This is the third version of a patch that reduces unnecessary system calls when MIDX files reference non-existent packfiles.

The series builds on previous discussions about MIDX optimizations and correctness, now focusing specifically on eliminating redundant access(3p) calls when looking up missing packfiles. The key technical changes are:

1. A new macro `MIDX_PACK_ERROR` is introduced to represent failed pack lookups, replacing the direct use of (void *)(intptr_t)-1 for better readability. This was a suggestion from previous discussion.

2. The patch modifies `prepare_midx_pack()` and `nth_midxed_pack()` to cache and check for failed lookups using this macro, avoiding repeated system calls when a packfile is known to be missing. The changes affect midx.c and packfile.c.

3. The series maintains the existing behavior where the first lookup attempt still performs all system calls (including the three auxiliary access(3p) calls), but subsequent lookups for the same missing pack will be served from cache.

The motivation comes from production issues where stale MIDX files referenced non-existent packs, causing performance degradation. While the author notes the impact is likely minimal for most repositories, the change is considered worthwhile due to its simplicity. The patch explicitly avoids implementing a more complex negative lookup cache solution, keeping the scope focused.

This version addresses feedback from v2 by introducing the macro for the special error value. The changes are relatively contained but touch sensitive MIDX lookup paths, so careful review of the caching behavior would be warranted. The patch appears to be a straightforward improvement that aligns with the ongoing MIDX optimization work in the thread.
