This is a refactoring patch that simplifies the MIDX pack lookup API by having `prepare_midx_pack()` return a `packed_git` pointer directly rather than requiring callers to perform additional array indexing. The change makes the API more straightforward and less error-prone, particularly when dealing with incremental MIDX chains where pack IDs span multiple layers.

The patch converts the existing pattern where callers would:
1. Call `prepare_midx_pack()` to load the pack
2. Manually index into the MIDX's packs array
3. Handle complex cases where packs might be in base MIDX files

Instead, callers now get the `packed_git` pointer directly from `prepare_midx_pack()`, with NULL indicating failure. This encapsulates the MIDX chain traversal logic within midx.c rather than exposing it to callers. The change affects several MIDX-related operations including pack expiration, bitmap handling, and verification.

Key technical details:
- The `midx_for_pack()` helper remains but is now purely internal
- All MIDX subsystems (midx-write.c, midx.c, pack-bitmap.c) are updated to use the new API
- Error handling becomes more consistent as callers don't need to handle MIDX_PACK_ERROR separately
- The change builds on earlier work introducing the MIDX_PACK_ERROR macro
- Performance impact should be neutral since the same underlying operations occur

The patch is part of an ongoing series to improve MIDX handling, following earlier performance optimizations and safety fixes. It represents a logical next step in making the MIDX API more maintainable by reducing the cognitive overhead for callers dealing with pack lookups across MIDX chains. The implementation appears thorough, updating all relevant call sites while maintaining existing behavior.
