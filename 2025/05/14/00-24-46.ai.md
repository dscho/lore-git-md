This is the first patch in a two-part series implementing a `--dry-run` option for `git merge-tree` to enable efficient mergeability checking for Git forges. The patch introduces core plumbing changes in merge-ort to support this functionality.

The key technical changes add a `mergeability_only` flag that modifies merge-ort's operation in two main ways when enabled:
1. It avoids writing merged blobs/trees to the object store in the outer merge (call_depth == 0), except for rename/rename+modify cases which still require object writes
2. It enables early exit upon first conflict detection in process_entries() (though not from detect_and_process_renames() due to implementation complexity vs. marginal benefit)

The patch carefully documents edge cases where object writes still occur (inner merges and rename/rename+modify conflicts) and justifies the design tradeoffs. The implementation touches several key merge-ort functions:
- Adds `record_object` parameter to `handle_content_merge()`
- Modifies tree writing logic in `write_completed_directory()` and `process_entries()`
- Adds early exit path in `process_entries()`
- Updates result handling in `merge_ort_internal()`

The changes are well-motivated for Git forge use cases that need merge conflict checking without full merge computation or object writing overhead. The patch shows thorough consideration of edge cases and maintains existing behavior where needed (like still writing objects for inner merges). This appears ready for integration as part of the larger `--dry-run` feature.
