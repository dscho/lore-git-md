This is a follow-up discussion on the git-gui commit message formatting bugfix. Junio C Hamano confirms Johannes Sixt's reasoning about the double-newline issue caused by Tk text widget and `puts` interaction. The patch simplifies the newline handling by replacing multiple regex substitutions with a single `string trim` operation that handles both leading and trailing newlines.

Junio notes that since git-gui uses the plumbing command `commit-tree` directly (rather than the porcelain `git commit` which has built-in stripspace handling), it needs to be more careful about extra blank lines in the commit message. The discussion confirms the technical approach taken in the patch, with no new concerns raised. The change remains straightforward, touching only `lib/commit.tcl` with a clear reduction in code complexity (4 lines removed, 2 added).

Key technical details for future reference: the fix modifies how commit messages are processed before being passed to `commit-tree`, specifically around handling of comment strings (via `comment_string` variable) and newline compression. The `string trim` operation now handles both ends of the message while maintaining the existing behavior of compressing multiple internal newlines down to two.
