This is the final patch in a performance optimization series introducing batched reference updates to Git's receive operations. The patch modifies `git-receive-pack` to use batched reference updates (building on commit 23fc8e4f61) instead of per-reference transactions, providing significant performance improvements - an 18x speedup with the reftable backend and 1.21x with the files backend when handling 10,000 references.

The change also fixes a subtle behavioral issue where multiple updates to the same reference (like `A:foo B:foo`) would produce misleading error messages while partially applying updates. The new batched approach properly detects and rejects such conflicts before any updates occur. This requires updates to test cases in t5408 that previously relied on the old behavior.

The patch includes careful error handling through a new `ref_transaction_rejection_handler` that properly attributes errors to specific failed references. It also adjusts the behavior of the reference-transaction hook to be all-or-nothing in the prepared stage when used with batched updates, which affects t1416 test expectations.

This completes the series' goal of bringing batched reference performance improvements to both fetch and receive operations, with the reftable backend seeing particularly dramatic gains. The implementation appears thorough, with clear benchmark results and attention to edge cases revealed by the conversion.
