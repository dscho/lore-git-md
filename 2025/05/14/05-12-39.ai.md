Refactoring patch in Patrick Steinhardt's object database (ODB) modernization series, specifically targeting the `the_repository` removal effort. This is patch 16/17 in v3 of the series, continuing the mechanical conversion of ODB-related functions to use explicit `object_database` parameters instead of relying on the global `the_repository`.

The patch renames `pretend_object_file()` to `odb_pretend_object()` to align with the established naming convention (`odb_` prefix) for ODB functions. The function is used to temporarily cache an in-memory object before writing it to persistent storage, primarily called from `blame.c` for fake working tree commits. The implementation now takes a direct `object_database` parameter rather than a full `repository` struct, though it still accesses the repository's hash algorithm internally.

Key technical changes:
- Function signature updated to take `struct object_database *odb` instead of `struct repository *repo`
- Internal calls to `odb_has_object()` and `find_cached_object()` now use the passed ODB directly
- Memory allocation for cached objects now uses the ODB's fields rather than repository indirection
- Only one caller in `blame.c` needed updating, so no compatibility wrapper was deemed necessary

The change follows the same pattern as previous patches in the series - a straightforward mechanical conversion that maintains all existing behavior while removing implicit `the_repository` usage. The patch is narrowly focused and appears uncontroversial, continuing the systematic elimination of global state from the ODB subsystem.
