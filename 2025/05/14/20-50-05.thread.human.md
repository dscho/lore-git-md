This thread addresses a bug in git-gui where commit message processing was leaving two trailing newlines instead of one due to an interaction between Tk's text widget and the `puts` command. The issue was reported by Gareth Fenn.

The proposed fix simplifies the message cleanup in `lib/commit.tcl` by replacing three separate regex substitutions with a single `string trim` operation that handles both leading and trailing newlines. The change maintains all existing functionality while fixing the double-newline issue and making the code more straightforward. The patch appears well-justified, with clear technical details showing the modification and its benefits.
