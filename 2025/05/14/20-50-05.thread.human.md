This thread addresses a bug in git-gui where commit messages were incorrectly formatted with two trailing newlines due to an interaction between Tk's text widget and Tcl's `puts` command. The original patch proposed by Gareth Fenn simplified the solution by replacing multiple regex substitutions with a single `string trim` operation in `lib/commit.tcl`, which handles both leading and trailing newlines while maintaining the existing behavior of compressing multiple internal newlines down to two.

The solution was reviewed and validated by Johannes Sixt and Junio C Hamano, with Oswald Buddenhagen providing additional feedback that has now been incorporated into the latest version. The updated patch clarifies the comment to more precisely describe the behavior (using "did not consider" rather than "forgot") and explicitly notes that `puts` will re-add a trailing newline. The technical approach remains sound, reducing complexity by removing 4 lines of regex substitutions while adding just 2 lines with the improved solution.

All participants agree this is the correct solution given current constraints, though there's historical context about a previous attempt using `git stripspace` that was reverted due to compatibility issues. The change is localized to git-gui's commit message handling and doesn't affect other subsystems. With no outstanding technical concerns, the patch is ready for inclusion.
