This thread addresses a bug in git-gui where the commit message text widget was incorrectly leaving two trailing newlines due to interactions between Tk and Tcl's `puts` command. Gareth Fenn proposed a fix that simplifies the code by replacing multiple regex substitutions with a single `string trim` operation in `lib/commit.tcl`, maintaining proper newline handling while reducing complexity.

The discussion revealed important context about git-gui's direct use of the plumbing command `commit-tree` (rather than the porcelain `git commit`), which requires careful blank line handling. Johannes Sixt and Junio Hamano validated the technical approach, noting it correctly preserves the existing behavior of compressing multiple internal newlines to two while trimming leading/trailing ones. 

Johannes later provided historical background about a previous attempt to use `git stripspace` (in commit b9a4386) that was reverted (c0698df) due to compatibility issues with older Tcl versions and macOS. While the current solution using Tcl's native `string trim` is preferred, this context explains why certain approaches were rejected in the past and might be reconsidered if version requirements change.

All participants agree the current patch is correct and ready for inclusion. The change remains localized to commit message handling with clear improvements in code simplicity while maintaining compatibility with existing behavior.
