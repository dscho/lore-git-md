This is a bugfix for git-gui addressing an issue with commit message formatting. The patch fixes a case where the GUI was unintentionally adding an extra newline at the end of commit messages due to how the Tk text widget and `puts` command interact.

The problem occurs when processing commit messages - while the code already handled multiple internal newlines and leading whitespace, it wasn't properly accounting for the additional newline that `puts` adds when writing the file. This resulted in commit messages ending with two newlines instead of one.

The solution cleanly replaces several regex-based trimming operations with a single `string trim` call that handles both leading and trailing newlines. The change is straightforward and comes with a Reported-by credit, indicating it addresses a real user-reported issue. The patch appears well-contained, touching only the commit message processing logic in `lib/commit.tcl` with no obvious side effects.
