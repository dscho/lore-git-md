Bugfix addressing memory leaks in the bitmap loading code, following up on Taylor Blau's analysis of a second leak scenario. This is part of an ongoing thread about fixing memory management issues when loading corrupt bitmaps.

Junio Hamano responds to Taylor's proposed solution, which eliminates duplicate cleanup code by removing the `failed` label in `load_bitmap()` and having all error paths return directly. The key insight is that callers already handle cleanup via `free_bitmap_index()`, making the intermediate cleanup in `load_bitmap()` both redundant and problematic - it was prematurely destroying data structures before the caller could properly free their contents.

The patch simplifies the code significantly by removing about 15 lines of error-handling boilerplate while actually making the error paths more robust. Junio notes the rarity of fixes that remove this much code while improving correctness, suggesting this is likely to be well-received. The change builds on Lidong Yan's initial fix for validation-order leaks and Taylor's identification of the partial-load leak scenario, completing the thread's goal of comprehensive bitmap error handling.
