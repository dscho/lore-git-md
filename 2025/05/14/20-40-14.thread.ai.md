RFC proposal for `git diff --no-index` pathspec support, evolving from initial `--exclude` approach. Authored by Jacob Keller, this thread has established consensus on implementing full pathspec support with arguments following comparison targets, mirroring `git diff-tree -r` behavior.

Core problem:
- Need to filter files during directory comparisons in `--no-index` mode
- Original `--exclude=<pattern>` proposal replaced by pathspec approach
- Junio C Hamano's consistency concerns with repository diff syntax (`:!exclude`) drove design shift

Current implementation status:
- First two arguments are comparison targets (files or directories)
- Subsequent arguments treated as pathspecs when comparing directories
- Supports both inclusion and exclusion patterns like repository diffs
- Documentation will recommend `--` separator for clarity (not required)
- Argument structure intentionally parallels `git diff-tree -r`
- Jacob Keller has working v2 patch needing cleanup of temporary hacks

Technical challenges addressed:
- Distinguishing comparison targets from pathspecs via strict argument ordering
- Applying pathspecs during directory traversal without repository context
- Documentation examples will show recommended `--` separator usage
- Behavior now fully aligned with `git diff-tree -r`'s treeish-then-pathspec structure

- Junio C Hamano confirmed pathspec-after-targets syntax as solution
- Consensus remains strong on this direction with no new objections
