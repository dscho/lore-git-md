RFC proposal for `git diff --no-index` pathspec support, evolving from initial `--exclude` approach. Authored by Jacob Keller, this thread explores mechanisms to filter directory comparisons outside repositories. Current discussion favors implementing full pathspec support rather than a separate `--exclude` mechanism.

Core problem:
- Need to filter files during directory comparisons in `--no-index` mode
- Original proposal added `--exclude=<pattern>` using wildmatch
- Junio C Hamano identified inconsistency with repository diff's pathspec syntax (`:!exclude`)

Current technical direction:
- Treat first two arguments as comparison targets (files or directories)
- Interpret subsequent arguments as pathspecs when comparing directories
- Supports both inclusion and exclusion patterns like repository diffs
- Maintains backward compatibility for simple file comparisons
- Argument structure parallels `git diff-tree -r`

Implementation challenges:
- Distinguishing comparison targets from pathspecs in argument parsing
- Applying pathspecs during directory traversal without repository context
- Potential edge cases in mixed file/directory target scenarios

Key participant positions:
- Jacob Keller now advocates pathspec approach after initial `--exclude` proposal
- Junio C Hamano's consistency concerns drove the design shift
- Discussion indicates consensus forming around pathspec solution

Open questions:
- Exact argument parsing semantics for mixed cases
- Whether to support all pathspec` features (e.g. magic signatures)
- Performance impact of pathspec processing in `--no-index` mode
- Documentation updates needed for new behavior

Status: Design discussion active, implementation not yet attempted. Thread shows clear momentum toward pathspec solution but awaits concrete patches demonstrating the approach. Next steps likely involve a v2 series implementing this direction with corresponding tests.
