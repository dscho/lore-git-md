RFC proposal for `git diff --no-index` pathspec support, evolving from initial `--exclude` approach. Authored by Jacob Keller, this thread explores mechanisms to filter directory comparisons outside repositories. Current discussion has converged on implementing full pathspec support with arguments after comparison targets, mirroring `git diff-tree -r` behavior.

Core problem:
- Need to filter files during directory comparisons in `--no-index` mode
- Original `--exclude=<pattern>` proposal replaced by pathspec approach
- Junio C Hamano's consistency concerns with repository diff syntax (`:!exclude`) drove design shift

Technical direction now confirmed:
- First two arguments are comparison targets (files or directories)
- Subsequent arguments treated as pathspecs when comparing directories
- Supports both inclusion and exclusion patterns like repository diffs
- Documentation will recommend `--` separator for clarity (though not required)
- Argument structure intentionally parallels `git diff-tree -r`

Implementation challenges remain:
- Distinguishing comparison targets from pathspecs in argument parsing
- Applying pathspecs during directory traversal without repository context
- Edge cases in mixed file/directory target scenarios
- Performance impact of pathspec processing in `--no-index` mode

Key participant positions:
- Jacob Keller now implementing pathspec approach after initial `--exclude` proposal
- Junio C Hamano confirmed pathspec-after-targets syntax as preferred solution
- Consensus clearly established on this direction

Open questions:
- Whether to support all pathspec magic signatures
- Documentation updates needed for new behavior
- Testing strategy for various argument combinations
