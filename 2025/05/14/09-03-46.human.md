This is a performance optimization series that modifies `git-fetch` and `git-receive-pack` to use batched reference updates instead of individual transactions for each reference change. The change builds on recent work that introduced batched updates (commit 23fc8e4f61) which allows partial success/failure within a batch rather than all-or-nothing transactions.

The key motivation is performance, especially for the reftable backend where individual transactions trigger auto-compaction. Benchmarks show dramatic improvements - up to 22x faster for fetches with reftable and more modest but still significant gains (1.2x) for the files backend. The series also fixes a memory leak discovered during development.

Patch 1 handles the fetch side changes, patch 2 fixes the memory leak in send-pack, and patch 3 updates receive-pack. The changes are substantial but focused, touching core reference update logic while maintaining the existing partial update behavior that's important for these commands. The commit messages are clear and the performance claims are backed by concrete numbers, making this a well-presented optimization proposal.
