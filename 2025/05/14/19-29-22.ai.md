This is a continuation of the `git-blame-tree` command discussion, focusing on UI design and command structure. Junio Hamano responds to Toon Claes' arguments about multi-file handling, clarifying the distinction between traditional line-by-line blame and the proposed tree-wide operation.

Junio outlines a potential hybrid approach where `git blame` could detect tree-mode based on arguments (directory paths or multiple files) while maintaining backward compatibility for single-file blame. He proposes explicit `--tree` flag support alongside the heuristic detection. However, he strongly expresses that the operation is conceptually distinct from blame and would prefer a separate command with no "blame" naming, likening it more to a parallelized `git log -1` across multiple paths.

Key technical points raised:
- Single-file case must remain traditional line blame
- Multiple files/directories could trigger tree mode
- Explicit `--tree` flag would override heuristics
- Fundamental disagreement on whether the operation constitutes "blaming"
- Suggests the functionality is closer to batch `git log -1` than true blame

This moves the discussion forward by:
1. Providing concrete UI syntax proposals for integration
2. Reinforcing backward compatibility constraints
3. Introducing stronger conceptual arguments against the "blame" naming
4. Keeping separate command option alive with clearer rationale

The response maintains Junio's earlier position on UI constraints while acknowledging Toon's multi-file use case, but introduces new philosophical objection to the operation being called "blame" at all. This may shift the debate toward either stronger naming justification or reconsideration of the separate command approach.
