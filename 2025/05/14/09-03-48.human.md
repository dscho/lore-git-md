This is a bugfix patch that addresses a memory leak in `git-send-pack` when handling duplicate reference updates. It's part 2 of a 3-patch series primarily focused on performance optimizations for batched reference updates, though this particular patch fixes an unrelated issue discovered during that work.

The patch fixes a case where pushing the same reference multiple times in a single command (like `git send-pack remote.git A:foo B:foo`) could leak memory when the updates fail. The `remote_status` field storing error messages was being overwritten without freeing the previous value. The fix adds proper cleanup before overwriting the status message.

The patch includes both the code fix and a new test case that specifically triggers the leak scenario (multiple duplicate refs where updates fail). While existing tests covered duplicate refs, they didn't expose the leak because they only had one failing case. The author notes this was discovered while working on the larger batched reference update series, showing good attention to detail in catching side issues during development.

The change is straightforward and low-risk, touching only the error handling path in `send-pack.c` and adding a targeted test. It doesn't affect the main functionality of the series but cleans up a real issue that could accumulate memory leaks in edge cases.
