Jacob Keller has revised his proposal for excluding files in `git diff --no-index` directory comparisons, shifting from a simple `--exclude` option to full pathspec support in response to Junio C Hamano's feedback. The original approach used wildmatch patterns to skip files like `.git/`, but Junio pointed out this would create an unnecessary inconsistency with repository diffs that already use pathspecs.

The new design would treat the first two arguments as comparison targets (maintaining backward compatibility) while interpreting any additional arguments as pathspecs when comparing directories. This mirrors how `git diff-tree -r` works and would support both inclusion and exclusion patterns (via Git's existing `:!` syntax). The main implementation challenges involve parsing the mixed argument types and applying pathspecs during directory traversal.

The thread is converging on this more comprehensive solution, which would provide feature parity between repository and non-repository diff modes. While the pathspec approach is more complex to implement than the original `--exclude` proposal, it addresses the core design concern about having two different exclusion mechanisms. Jacob appears willing to pursue this direction, though the actual implementation work remains to be done.
