This is the final version of a 2-patch series introducing a `--dry-run` option to `git merge-tree`, primarily targeting Git forges that need efficient mergeability checking. The series is now fully resolved with all feedback addressed.

The implementation provides two key optimizations when checking if branches can merge: (1) early exit on first conflict detection rather than computing full merge results, and (2) avoiding unnecessary object writes for most cases while preserving them for inner merges and rename/rename+modify cases. The documentation has been updated to consistently use the `--dry-run` terminology throughout, addressing the last remaining inconsistency caught in review.

The changes since v2 are minimal - just fixing a few missed locations in the rename from `--mergeability-only` to `--dry-run` (per Junio Hamano's earlier naming suggestion). The series appears ready for finalization with comprehensive test coverage and clear documentation of edge cases where object writes still occur. This should provide meaningful performance benefits for hosting platforms that frequently check mergeability without needing merge results.
