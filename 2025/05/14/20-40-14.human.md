This is a feature proposal for `git diff --no-index` that adds a new `--exclude` option to filter files by pattern when comparing directories outside a repository. The `--no-index` mode currently doesn't ignore VCS directories like `.git`, which can lead to unwanted comparisons of repository internals when diffing folders that happen to contain them.

The patch implements pattern exclusion using Git's existing `wildmatch()` functionality, similar to GNU diff's `-x` option. The author notes this is simpler than trying to support Git's full negative pathspec syntax in `--no-index` mode, though they float that as a possible future direction. The implementation modifies the directory traversal logic to skip any filenames matching the patterns.

As an RFC, this lacks tests and documentation, but the author provides clear motivation for the feature - they wanted to use `git diff`'s colorization and options when comparing folders, but found the lack of exclusion problematic when one folder was a repository. The 32-line change is focused and appears well-structured, modifying just the `diff-no-index.c` file to add the new option and filtering logic.

The proposal seems reasonable for a common use case, though reviewers may want to discuss whether pattern exclusion belongs in Git's diff machinery or if users should use other tools when needing such features outside a repository context. The author is explicitly seeking feedback on both the approach and whether the feature is worth having.
