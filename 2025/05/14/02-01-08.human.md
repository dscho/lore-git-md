This is a bugfix patch addressing submodule configuration safety, now in its third iteration. The patch prevents Git from silently overwriting `.gitmodules` entries when adding a new submodule at a path that previously hosted a different submodule. The core issue occurs when a submodule is moved (e.g., from 'child' to 'child_old') but its name isn't updated, and then another submodule is added at the original path.

K Jayatheerth's implementation now detects name/path mismatches in `module_add()`, either erroring out (default) or generating unique numbered names (like 'child1', 'child2') when `--force` is used. The patch includes a new helper function `submodule_active_matches_path()` to handle submodule activation checks more efficiently. Test cases verify both the error behavior and the numbering scheme.

The v3 iteration addresses Junio Hamano's feedback from the previous review round, particularly around memory management for auto-generated names and code style fixes. The solution maintains compatibility with existing `submodule.active` handling while adding safety checks. The patch appears well-tested with new cases in t7400, though reviewers may want to verify edge cases around nested submodules. This represents a thoughtful solution to a real configuration hazard that could silently corrupt setups.
