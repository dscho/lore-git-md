Feature addition to `git merge-tree` implementing the user-facing `--dry-run` flag for mergeability checking.

This final patch in the series adds the `--dry-run` option to `git merge-tree`, building on the `mergeability_only` plumbing from the previous patch. The flag provides a fast mergeability check for Git forges by suppressing output and avoiding unnecessary object writes in the outer merge layer. Key implementation details include:

1. The option is implemented with `OPT_BOOL_F` to prevent negation and includes safety checks preventing combination with incompatible flags like `--messages` or `--stdin`. The merge machinery exits early via a new `cleanup` label when conflicts are detected.

2. Tests verify both successful and conflicted cases, confirming that:
   - No output is produced (empty stdout)
   - No objects are written to the object store
   - Exit codes properly indicate merge success (0) or conflict (1)

The changes touch documentation, option parsing in builtin/merge-tree.c, and add new test cases in t4301. The implementation follows Junio Hamano's naming guidance to use `--dry-run` rather than the original `--mergeability-only` proposal. With this patch, the series achieves its goal of providing hosting platforms an efficient way to check mergeability without computing full merge results, completing the functionality introduced in the plumbing changes from patch 1/2.
