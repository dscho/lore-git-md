Performance refactoring for packed-refs memory handling. This is the second patch in a 3-part series optimizing memory usage in the packed-refs backend, following review feedback from Jeff King and Patrick Steinhardt.

The patch extracts the buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()`. This enables reuse of the same memory allocation strategy (mmap vs read) in other contexts, particularly for fsck verification where we want the same behavior but don't want to open the file. The refactoring preserves all existing functionality including:
- The 32KB threshold for choosing between mmap and read
- Windows-specific MMAP_TEMPORARY handling
- Empty file detection
- Error handling patterns

The changes are mechanical with no behavior modifications - 31 lines added for the new helper function and 22 lines removed from `load_contents()`, which now delegates to the helper. The patch follows the suggestions from previous reviewers to standardize memory handling across different code paths that work with packed-refs files.

This is part of a mature series that has gone through 5 iterations (v1-v5) with thorough review from Jeff King, Patrick Steinhardt, and Junio Hamano. The technical approach is settled and this version only contains minor style adjustments from earlier feedback. The series is now ready for merging.
