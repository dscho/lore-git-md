This is a final version of a performance optimization series for the packed-refs backend, addressing memory usage and filesystem safety. The series has gone through multiple rounds of review (now at v5) with input from Jeff King, Patrick Steinhardt, and Junio Hamano.

The three patches standardize how Git handles packed-refs files, particularly focusing on memory-mapped I/O for large files during fsck operations. The key changes include:

1. Fixing an inconsistency where fsck would error on empty packed-refs files while runtime code accepted them, now issuing an INFO-level warning instead. The commit message has been significantly improved in v5 to better explain the historical context and rationale.

2. Refactoring buffer allocation code into a helper function (`allocate_snapshot_buffer`) that preserves mmap/read thresholds and Windows compatibility.

3. Using the new helper to implement mmap-based verification during fsck, completing the memory optimization effort while maintaining all existing behavior and platform support.

The series is now fully reviewed and approved, with all technical concerns addressed across five iterations. The v5 changes are minor refinements to commit messages and grammar.
