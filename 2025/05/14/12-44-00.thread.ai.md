Thread identity: Bugfix for memory leak in sequencer's `update_squash_messages()` during interactive rebase operations.

Core problem: The function `update_squash_messages()` in sequencer.c leaks memory when encountering unknown command types because it fails to call `repo_unuse_commit_buffer()` on the error path, while `repo_logmsg_reencode()` may return either a newly allocated string or a pointer to the commit buffer.

Current status: Single patch addressing the issue by adding proper cleanup call before returning from error case. No version iterations yet. Affects interactive rebase's message handling during squash operations.

Key technical details: Modifies 4 lines in sequencer.c to add buffer release via `repo_unuse_commit_buffer()` in error path. Does not change successful code path behavior. Fix follows established pattern seen in non-error case. Leak only occurs with unknown commands (error case).
