This is a bugfix for git-gui addressing commit message formatting. The patch fixes an issue where the message processing would leave two trailing newlines instead of one due to the interaction between Tk's text widget behavior and the `puts` command used to write the file.

The change simplifies the message cleanup by using Tcl's `string trim` to handle both leading and trailing newlines in one operation, replacing three separate regex substitutions. This addresses a specific report from Gareth Fenn about the double-newline issue while also cleaning up the implementation.

The technical details show the modification to `lib/commit.tcl` where the message processing occurs, removing the separate leading/trailing newline handling in favor of the unified `string trim` approach.
