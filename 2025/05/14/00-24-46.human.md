This is the first patch in a two-part series adding a `--dry-run` option to `git merge-tree` for efficient mergeability checking, primarily targeting Git forges. The patch introduces core plumbing changes in merge-ort to support this functionality.

The key technical changes add a `mergeability_only` flag that modifies merge behavior in two main ways: it enables early exit upon detecting conflicts (though with some carefully documented limitations), and it avoids writing merged blobs/trees to the object store for the outer merge layer. The patch includes detailed explanations about edge cases where object writes still occur (particularly for inner merges and rename/rename+modify conflicts) and the rationale for the current implementation boundaries.

The changes touch merge-ort.c extensively, modifying blob/tree writing logic and adding early exit paths, while keeping the core merge algorithm intact. The implementation appears thorough, with careful consideration given to performance tradeoffs and clear documentation of limitations in the commit message. This is clearly part of a well-considered series that has already gone through multiple iterations based on mailing list feedback.
