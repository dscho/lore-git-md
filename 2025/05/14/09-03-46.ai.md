Performance optimization series introducing batched reference updates to fetch and receive operations.

This 3-patch series modifies `git-fetch` and `git-receive-pack` to use the recently introduced batched reference update mechanism (from commit 23fc8e4f61) rather than processing each reference update as a separate transaction. The key motivation is performance - particularly for the reftable backend where individual transactions trigger auto-compaction, but also for the files backend where transaction setup/teardown overhead adds up with many refs.

The series shows dramatic speedups, especially for reftable (22x faster fetches, 18x faster receives). The changes maintain partial update semantics while batching - individual ref updates can still fail independently. Patch 1 handles fetch, patch 3 handles receive-pack, with patch 2 fixing an unrelated memory leak discovered during development.

Files modified span the fetch/receive code paths and related tests. The implementation appears thorough with clear performance measurements provided. This builds on prior work introducing the batching infrastructure and seems ready for review, though the reftable speedup magnitude may warrant closer scrutiny of the measurement methodology.
