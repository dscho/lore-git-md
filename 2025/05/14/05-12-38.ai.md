This is patch 15/17 in Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to remove `the_repository` global state. The patch focuses on renaming the `has_object()` function to `odb_has_object()` to align with the established naming conventions in the ODB refactoring effort.

The change is mechanical but widespread, updating 30 files to use the repository's object store explicitly via `the_repository->objects` rather than implicitly through `the_repository`. A compatibility wrapper is provided to maintain compilation for in-flight topics, following the pattern seen in earlier patches of this series.

Key technical details:
- The function signature changes from `has_object(repository, oid, flags)` to `odb_has_object(object_database*, oid, flags)`
- All callers are updated to pass `the_repository->objects` explicitly
- The flags parameter behavior remains unchanged (HAS_OBJECT_RECHECK_PACKED, HAS_OBJECT_FETCH_PROMISOR)
- A static inline wrapper preserves the old interface for compatibility
- The implementation moves from repository.c to odb.c while maintaining identical behavior

This continues the systematic approach seen in previous patches, completing the function renaming portion of the ODB API standardization. The changes are purely mechanical with no functional impact, keeping with the series' goal of maintaining behavior while enabling future pluggable ODB backends.
