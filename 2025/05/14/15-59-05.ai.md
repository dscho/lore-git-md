This is a platform compatibility follow-up in the ongoing msgfmt argument ordering discussion. Johannes Sixt responds to Nathan Royce's reproduction steps for the POSIXLY_CORRECT-sensitive msgfmt behavior that breaks Git's Tcl translation builds. The key development is Johannes marking the issue as "fixed" (presumably in the build system), though the email doesn't specify the exact solution implemented. The thread had previously established that argument order matters for msgfmt when POSIXLY_CORRECT is set, particularly affecting gitk's translation files, with the command failing when source files appear before options. The fix appears to address this build system quirk without requiring changes to core Git code. No details are provided about whether the solution involves reordering arguments in the Makefile, adding POSIXLY_CORRECT handling, or another approach. The resolution comes after Nathan demonstrated the issue could be reproduced simply by setting POSIXLY_CORRECT=1 before building.
