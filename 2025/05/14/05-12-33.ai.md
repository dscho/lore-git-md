This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global from Git's object database (ODB) subsystem, specifically focusing on alternate object database functionality.

The patch converts two key functions that manage temporary primary alternates to use an explicit `object_database*` parameter instead of relying on `the_repository`:
- `set_temporary_primary_odb()` becomes `odb_set_temporary_primary_alternate()`
- `restore_primary_odb()` becomes `odb_restore_primary_alternate()`

The changes propagate through the ODB interface, updating:
1. Function signatures in `odb.h` with new names and explicit ODB parameters
2. Implementation in `odb.c` to use the passed ODB instead of `the_repository->objects`
3. Call sites in `tmp-objdir.c` that handle temporary object directories

The patch maintains all existing functionality while completing another piece of the systematic conversion to explicit ODB parameters. It follows the established pattern of prefixing functions with `odb_` and properly documents the new interfaces in `odb.h`. The changes are mechanical but important for the architectural goal of removing global state and enabling pluggable ODB backends.

Key technical details:
- The temporary alternate management now tracks ownership through explicit ODB pointers
- BUG() checks verify expected state during restoration
- The `tmp_objdir` subsystem's interactions with alternates are updated to pass the repository's ODB
- Documentation clarifies the functions' purposes and ownership semantics

This continues the series' pattern of methodical, non-disruptive changes that have been receiving positive feedback from maintainers.
