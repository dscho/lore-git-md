Bugfix for a memory leak in `git-send-pack` when handling duplicate reference updates. This is the second patch in a performance optimization series introducing batched reference updates.

The patch addresses a specific leak that occurs when pushing duplicate refspecs (e.g., `A:foo B:foo`) where the updates fail. Currently, the second error message overwrites the first without freeing the original, leaking memory. The fix adds a `free()` call before overwriting `ref->remote_status`.

Junio C Hamano's response notes the fix is correct but raises an interesting design question about what should happen in edge cases where one update succeeds and another fails (either order). He suggests several possible behaviors (last-one-wins, first-one-retained, keep-most-severe-error) but doesn't insist on any particular approach, indicating the current solution is acceptable.

This is a straightforward fix with clear test coverage, though it touches on some subtle refspec handling behaviors that could be explored further. The patch fits cleanly into the larger series about batched reference updates, though this particular issue is independent of that optimization.
