This is the first patch in a v5 series addressing memory optimization in the packed-refs backend, specifically focusing on filesystem safety for empty packed-refs files. The patch adds an INFO-level fsck warning when encountering an empty packed-refs file, which is technically valid but unusual since Git has written headers in these files since version 1.8.4.

The change handles a subtle inconsistency where fsck would previously report an error for empty files (due to missing line terminators), while runtime code silently accept them. The solution introduces a new "EMPTY_PACKED_REFS_FILE" warning to surface this anomaly without breaking compatibility with very old Git versions that might have created such files.

The patch includes thorough documentation of the new fsck message, implementation in packed-backend.c, and a new test case. Review history shows this approach was refined through multiple rounds with input from Jeff King and Junio Hamano, with the v5 version representing consensus on the technical solution. The change is relatively small (33 lines across 4 files) but addresses an important edge case in refs verification.
