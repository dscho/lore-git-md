This is part 13/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to remove `the_repository` global state. The patch renames `oid_object_info()` to `oid_read_object_info()` and its `_extended` variant to match modern naming conventions, introducing compatibility wrappers to avoid breaking in-flight topics.

The changes are mechanical but widespread, touching 48 files across the codebase to update callers. The new names better reflect that these functions operate on the object database (`odb_` prefix) and follow the pattern established by other ODB functions in the series. The compatibility wrappers ensure existing code continues to work while allowing gradual migration to the new names.

Key technical details:
- Old names: `oid_object_info()`, `oid_object_info_extended()`
- New names: `odb_read_object_info()`, `odb_read_object_info_extended()`
- Location: `odb.h` and `odb.c` with compatibility wrappers in `repository.h`
- Behavior remains unchanged - these are pure renames
- Part of broader effort to make ODB operations repository-aware rather than using globals

The patch continues the systematic approach seen in previous parts of the series, maintaining functionality while updating naming and organization to support future ODB work. It follows established patterns from earlier patches (1-12) that renamed core ODB functions and structures.
