This is the final patch in a performance optimization series for the packed-refs backend, specifically focusing on memory usage during fsck operations. The patch replaces `strbuf_read()` with the newly introduced `allocate_snapshot_buffer()` helper to use mmap for large packed-refs files during verification, aligning fsck with the rest of the codebase's memory handling strategy.

The changes are relatively straightforward (19 lines modified) and build on the refactoring work from previous patches in the series. Key technical points:
- Swaps `strbuf_read` for the standardized buffer allocation helper
- Maintains the same verification logic through `packed_fsck_ref_content()` and `packed_fsck_ref_sorted()`
- Preserves empty file detection (now using the helper's return value)
- Updates cleanup to use `clear_snapshot_buffer()`

The patch has already gone through multiple review rounds (v1-v5) with approvals from Jeff King, Patrick Steinhardt, and Junio Hamano. All technical aspects appear resolved, with only minor commit message polish remaining. This completes the series' goal of standardizing memory handling while maintaining compatibility with historical behavior and Windows-specific considerations.
