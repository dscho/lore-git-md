This positions Change-IDs as a higher-level convention rather than a core Git feature, distinguishing them from more fundamental concepts like predecessor pointers that might benefit from Git-level support. The response suggests the standardization effort should focus on trailer syntax and propagation rules rather than deeper Git modifications, while acknowledging the value of tools agreeing on common semantics.
