This is part of Patrick Steinhardt's ongoing `the_repository` removal series (v3 04/17), introducing parent pointers between object database structures to enable repository access when needed while eliminating global state.

The patch adds bidirectional ownership links between repository and ODB structures:
- `struct object_database` gains a `repo` pointer to its owning repository
- `struct odb_alternate` gains an `odb` pointer to its parent object database
- `odb_new()` now requires the repository parameter to establish the link
- Key changes propagate through alternate handling:
  - `link_alt_odb_entry()` and related functions now take `struct object_database*` instead of `struct repository*`
  - Alternate initialization in `repository.c` sets up the new pointers
  - Temporary ODBs maintain the parent relationship

The changes are mechanical but touch core ODB handling paths, with 35 lines added and 21 removed across `odb.c`, `odb.h`, and `repository.c`. This enables future patches to access repository context when needed (e.g. for config lookups) while continuing the architectural shift away from `the_repository` global. The patch follows the established pattern from earlier series iterations, with all technical aspects previously reviewed and approved.
