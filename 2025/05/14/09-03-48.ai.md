Bugfix patch addressing a memory leak in `git-send-pack` when handling duplicate reference updates. This is the second patch in a 3-part series primarily focused on performance optimizations for batched reference updates, though this particular fix is an orthogonal issue discovered during development.

The patch fixes a memory leak that occurs when pushing duplicate refspecs (e.g., `A:foo B:foo`) where the same reference is updated multiple times in a single push. Currently, when such duplicate updates fail, the error message for the first failure is overwritten without freeing the previous allocation. The fix adds a `free()` call before overwriting the `remote_status` field in the `struct ref`.

The change is minimal (7 lines added) and comes with a new test case that specifically triggers the leak scenario by having multiple failing updates to the same reference. The existing tests already covered duplicate refspec cases but didn't expose the leak because they only had one failing update per reference.

This appears to be a straightforward and well-contained fix, though it's worth noting it's somewhat tangential to the main thrust of the series (batched reference updates). The patch maintains the existing behavior while just fixing the memory management aspect. The test addition follows the existing test pattern and provides good coverage for the edge case.
