Performance optimization completing a 3-patch series introducing batched reference updates, now covering `git-receive-pack`. This final patch modifies receive-pack to use the batched reference update mechanism introduced in commit 23fc8e4f61, replacing its previous per-reference transaction model. The change provides significant performance improvements: 18x faster with reftable backend and 1.21x with files backend when handling 10,000 refs, as shown in detailed benchmarks.

The patch introduces a `ref_transaction_rejection_handler` to properly track and report failures in batched updates, using a `struct strset` to manage failed refs. It also fixes a subtle behavioral issue where multiple updates to the same reference (like `A:foo B:foo`) previously produced misleading error messages and partial updates, while the new batched approach properly rejects such conflicting updates entirely.

The change affects hook behavior - the reference-transaction hook now operates in an all-or-nothing manner during the 'prepared' stage when using batched updates, which modifies test expectations in t1416. Several tests in t5408 are updated to reflect the new stricter handling of duplicate reference updates. The implementation touches core receive-pack functionality in `builtin/receive-pack.c` while maintaining the existing atomic/non-atomic operation modes.

This completes the series' goal of bringing batched reference updates to both fetch and receive operations, with the reftable backend seeing particularly dramatic improvements. The patch is well-documented with performance measurements and clear explanations of behavior changes, though the hook behavior modification may warrant discussion from hook users.
