This is the final patch in a performance optimization series introducing batched reference updates to `git-receive-pack`. The change completes the work started in earlier patches by applying the same batching approach used in `git-fetch` to receive operations, showing significant speedups - 18x faster with reftable and 1.21x with files backend for 10,000 refs.

The patch replaces per-reference transactions with a single batched transaction in `execute_commands_non_atomic()`, using a new `ref_transaction_rejection_handler` to track failed updates via `struct strset`. Patrick Steinhardt raises several technical questions in review: whether the error string handling is correct (particularly around empty vs NULL strings), whether the transaction fails atomically or partially, and if the `strmap_empty()` check is the right way to detect transaction-wide failures. He also suggests the error messages from the rejection handler could be reused in `git-fetch`.

The change affects hook behavior by making reference-transaction hooks operate in an all-or-nothing manner during the 'prepared' stage, which required updates to tests t1416 and t5408. While the performance improvements are clear, the patch introduces some subtle behavior changes around error handling that warrant careful review, particularly regarding how failures are reported back to individual commands when some references succeed while others fail in a batched update.
