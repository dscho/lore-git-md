This is part of Patrick Steinhardt's ongoing series to refactor Git's object database (ODB) subsystem, specifically targeting the removal of the_repository global state. Patch 11/17 focuses on submodule alternate handling.

The patch moves submodule alternate tracking from a global string list to being stored directly in the object database structure. This eliminates the need to check `r == the_repository` when registering submodule alternates, since they are now properly scoped to their owning repository. The change affects `git grep --recursive` functionality and submodule config reading, which need to access submodule objects.

Key changes include:
- Adding a `submodule_alternate_paths` string list to `struct object_database`
- Renaming functions to follow the new `odb_` prefix convention (`add_submodule_odb_by_path` becomes `odb_add_submodule_alternate_by_path`)
- Moving implementation from submodule.c to odb.c
- Updating callers in builtin/grep.c and submodule-config.c

The patch maintains existing behavior while making the code more repository-aware, continuing the series' systematic approach to removing global state. It's a straightforward conversion that follows the patterns established in earlier patches, with clear documentation of the new API.
