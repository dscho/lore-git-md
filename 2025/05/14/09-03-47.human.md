Performance optimization patch modifying `git fetch` to use batched reference updates. This is the first in a 3-part series aiming to speed up operations that modify many references, particularly benefiting the reftable backend where individual updates trigger expensive auto-compaction.

The patch replaces `git fetch`'s per-reference transaction model with the new batched update mechanism introduced in commit 23fc8e4f61. This maintains the ability for individual updates to fail independently (unlike `--atomic` mode) while significantly reducing overhead. Benchmarks show a 22x speedup for reftable with 10,000 refs (154ms vs 3.4s) and a more modest 1.25x improvement for the files backend.

Key changes include removing custom error handling in favor of the new transaction error system, consolidating transaction management, and moving conflict messages to a post-commit handler. The implementation appears thorough, with careful attention to maintaining existing semantics while cleaning up now-redundant code paths. The dramatic reftable performance claims may warrant verification, but the approach looks promising for high-refcount repositories.
