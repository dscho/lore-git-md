This patch introduces more precise control over fork-point behavior in `git pull --rebase`. Currently, the command always uses the fork-point algorithm to determine where to start the rebase, which isn't always what users want. The change adds both command-line flags (`--fork-point`/`--no-fork-point`) and a config setting (`rebase.forkpoint`) to let users explicitly choose whether to use this behavior.

The implementation carefully maintains backward compatibility while adding the new options. When unspecified, it defaults to using fork-point (the current behavior), but users can now disable it either temporarily via command line or persistently through config. The patch includes clear messaging about the fork-point decision, helping users understand what's happening during the rebase operation. The changes are well-contained to the pull machinery's rebase integration, primarily modifying `cmd_pull()` to check the new preferences before determining the rebase starting point.
