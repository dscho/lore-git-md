Performance optimization patch modifying `git-fetch` to use batched reference updates. This is the first in a 3-part series aiming to speed up operations that modify many references by leveraging the batched update mechanism introduced in commit 23fc8e4f61. The patch replaces `git-fetch`'s per-reference transaction model with batched updates while maintaining the same partial-update semantics where individual refs can fail independently. Key changes include removing custom error handling in favor of the new ref-transaction error types, consolidating transaction management, and adding a rejection handler for conflict messages. Performance measurements show dramatic improvements with reftable (22x faster for 10k refs) and modest gains with files backend (1.25x). The implementation appears thorough, though reviewers may want to verify the benchmark methodology given the large speedup magnitude. Changes are confined to `builtin/fetch.c` with significant code reorganization but no new test cases added.
