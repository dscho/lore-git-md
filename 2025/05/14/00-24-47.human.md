This is the final patch in a series adding a `--dry-run` option to `git merge-tree` for efficient mergeability checking, primarily targeting Git forges. The feature allows platforms to test whether branches can be merged without computing or storing the full merge result.

The patch introduces the user-facing `--dry-run` flag that leverages the underlying `mergeability_only` plumbing from the previous commit. When enabled, it suppresses all output and avoids writing most merge results to the object store while still detecting conflicts. The implementation includes:
- Option validation preventing incompatible combinations (like `--messages` or `--stdin`)
- Tests verifying both successful and conflicted merge scenarios
- Documentation explaining the flag's purpose and behavior

The changes show careful attention to edge cases and maintain compatibility with existing merge-tree functionality. This appears to be a well-considered addition that meets its stated goal of optimizing mergeability checks for hosting platforms, completing the series that has already addressed all prior review feedback.
