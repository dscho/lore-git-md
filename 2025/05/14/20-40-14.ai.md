Feature proposal for `git diff --no-index` to add file exclusion patterns.

This RFC patch from Jacob Keller proposes adding a `--exclude` option to `git diff --no-index` that would allow excluding files by wildmatch pattern when comparing directories. The motivation comes from cases where one wants to compare directories that might contain Git repositories, as currently `--no-index` will recurse into `.git` directories rather than ignoring them like many other diff tools do.

The implementation adds a `--exclude` option that builds a string list of patterns, which are then checked against each filename using `wildmatch()` in `read_directory_contents()`. The patch modifies the directory traversal logic to skip files matching any exclusion pattern. The author notes this is simpler than trying to support negative pathspecs in `--no-index` mode, though they acknowledge that would be more powerful.

Key technical details:
- New `--exclude` option takes patterns via `OPT_STRING_LIST`
- Patterns are stored in a `string_list` and passed through the diff queue
- `wildmatch()` handles pattern matching against filenames
- Only affects `--no-index` mode (regular diff operations would use pathspecs)
- Modifies `read_directory_contents()` and `queue_diff()` functions

The author flags this as an RFC since it currently lacks tests and documentation. They're seeking feedback on whether this approach is worthwhile compared to either using standard diff tools or attempting to implement negative pathspec support. The implementation appears straightforward but would need those missing components before being production-ready.
