This is part 11/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to remove `the_repository` global state. The patch focuses on submodule alternate handling, moving it from global state to repository-specific.

The change moves submodule alternate tracking from a global string list in `submodule.c` to being stored directly in the `object_database` struct. Key changes include:
- Adds `submodule_alternate_paths` string list to `struct object_database`
- Renames functions with new `odb_` prefix: `add_submodule_odb_by_path()` becomes `odb_add_submodule_alternate_by_path()`
- Removes `the_repository` check when registering alternates since they're now repository-specific
- Updates callers in `builtin/grep.c` and `submodule-config.c` to use new API
- Adds trace2 logging for debugging
- Maintains same behavior while removing global state

The patch continues the series' pattern of mechanical conversions that preserve functionality while enabling future work. It completes another piece of the ODB API surface conversion, specifically around submodule alternates used by `git grep --recursive`. The changes are straightforward and maintain existing behavior while properly integrating submodule alternates into the explicit ODB parameterization scheme.
