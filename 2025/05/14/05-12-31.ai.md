This is part 8/17 of Patrick Steinhardt's series to remove `the_repository` global from Git's object database (ODB) subsystem, continuing the refactoring work to enable pluggable ODB backends.

The patch focuses on alternate object database functionality, converting functions that previously relied on `the_repository` to instead take an `object_database*` parameter. Key changes include:
- Renaming functions with new `odb_` prefix: `prepare_alt_odb()` becomes `odb_prepare_alternates()`, `add_to_alternates_file()` becomes `odb_add_to_alternates_file()`, etc.
- Updating all callers across 14 files to pass the repository's ODB instance explicitly
- Maintaining the same behavior while removing implicit global state access
- Documenting the new APIs in `odb.h` with clear ownership semantics

The changes propagate through core operations like clone, fsck, repack, and submodule handling, as well as infrastructure like commit-graphs and multi-pack indexes. While the alternates system still internally uses repository paths (a temporary state noted in the commit message), this patch completes the mechanical conversion of the API surface.

This continues the systematic approach seen in earlier patches, with thorough updates to both implementation and documentation. The changes are mechanical but wide-ranging, touching many components that interact with alternate object stores. As with previous patches in the series, this maintains existing functionality while enabling future ODB work.
