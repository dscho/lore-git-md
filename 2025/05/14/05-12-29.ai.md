This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global from Git's object database (ODB) subsystem. Patch 6/17 focuses on `assert_oid_type()`, converting it to work with explicit ODB instances rather than relying on the global repository state.

The patch renames the function to `odb_assert_oid_type()` and modifies it to take a `struct object_database*` parameter instead of implicitly using `the_repository`. The implementation now accesses the repository through the passed ODB's `repo` pointer (established in earlier patches). Callers in `commit-tree.c` and `commit.c` are updated to pass `the_repository->objects` explicitly.

This change follows the series' pattern of making ODB operations repository-aware while maintaining functionality. The modification is straightforward - the function's core behavior (type checking with error reporting) remains unchanged, just the repository access mechanism is updated. The patch affects commit creation paths where object type validation occurs, but doesn't introduce new test coverage as the existing tests presumably still exercise these code paths.

This continues the architectural shift where ODB operations carry their repository context explicitly rather than relying on global state, which is important for enabling future pluggable ODB backends. The change is mechanical but meaningful in the context of the larger refactoring effort.
