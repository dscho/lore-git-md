This is the final patch in a series optimizing memory usage in the packed-refs backend. The patch replaces direct file reading with mmap-based verification during `git fsck`, aligning it with the rest of the codebase's memory handling patterns.

The change uses the `allocate_snapshot_buffer` helper introduced in earlier patches, reducing code duplication while maintaining the same behavior for empty files. Junio Hamano noted the line count reduction as a positive outcome and suggested a commit message fix (addressed by the author). There was some discussion about whether empty file handling should be the helper's responsibility, but the author explains this design choice helps maintain consistency between runtime and fsck behavior.

The patch series has gone through multiple iterations with input from Jeff King and Patrick Steinhardt, and appears ready for merging. The changes are focused on packed-backend.c, affecting about 90 lines total across the series. This final patch specifically touches 19 lines, simplifying the fsck path while preserving Windows compatibility and memory thresholds.
