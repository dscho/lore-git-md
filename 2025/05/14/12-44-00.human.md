This is a bugfix patch addressing a memory leak in the sequencer code. The issue occurs in `update_squash_messages()` when handling unknown commands - the function would return without properly releasing memory allocated by `repo_logmsg_reencode()`. The patch adds the missing `repo_unuse_commit_buffer()` call in the error path.

The change is straightforward and appears correct - it matches the memory management pattern used elsewhere in the function. The commit message clearly explains the technical details of the fix. While this is a small change, memory leaks in core commands like the sequencer are worth fixing, especially when they occur in error paths that might not be exercised in normal operation.

The patch touches only 4 lines in sequencer.c, adding proper cleanup in one error case. It's part of a pull request on GitHub (#1964) but appears to be a standalone fix rather than part of a larger series.
