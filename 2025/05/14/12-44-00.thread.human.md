This thread documents the completion of a project-wide standardization effort for BUG() messages in Git's codebase. Lidong Yan's series addresses two related aspects: fixing a memory leak in the sequencer's interactive rebase handling and converting all remaining translated BUG() messages to untranslated form.

The first patch fixed a memory leak in `update_squash_messages()` by replacing error() calls with BUG() when encountering unexpected command types during interactive rebase. This change was refined through several iterations, with Junio C Hamano suggesting improved wording for the BUG() messages to clearly document the expected command types (FIXUP/SQUASH). Phillip Wood, as the sequencer expert, reviewed and approved the technical approach.

The second patch, which just arrived, completes the standardization effort by mechanically converting the last few translated BUG() messages in builtin/mktag.c, builtin/worktree.c, and pack-bitmap-write.c to use untranslated strings. This establishes the clear convention that BUG() messages - meant for developers debugging issues - should not be translated, while maintaining proper translation for end-user facing error messages.

The series is now merge-ready with all feedback addressed and consensus achieved. It provides both immediate technical benefits (fixing the sequencer leak) and long-term maintainability improvements through consistent error handling across the codebase. The discussion also yielded useful guidance for future API boundary decisions, particularly around validation tradeoffs.
