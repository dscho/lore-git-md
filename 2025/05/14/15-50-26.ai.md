This is the first patch in a v5 series addressing filesystem safety in the packed-refs backend, specifically handling empty packed-refs files. The patch introduces an INFO-level fsck warning when encountering an empty packed-refs file, while maintaining runtime compatibility with such files for historical reasons (pre-1.8.4 Git versions could create them).

The technical changes add a new FSCK_INFO message "EMPTY_PACKED_REFS_FILE" that gets triggered when fsck detects an empty packed-refs file. The implementation checks file size before content validation in `packed_fsck()`, skipping further checks if empty. Documentation updates explain this is an INFO-level warning that may become stricter in future versions. A new test case verifies the warning appears when manually creating an empty packed-refs file.

Key technical details:
- New fsck.h entry: `FUNC(EMPTY_PACKED_REFS_FILE, INFO)`
- Documentation in fsck-msgids.adoc with mailing list reporting suggestion
- Size check in packed-backend.c before content validation
- Test case in t0602-reffiles-fsck.sh creating/verifying empty file
- Maintains compatibility with runtime code paths like `create_snapshot`

The patch follows through on the thread's established consensus to handle empty files as a warning rather than an error, with Junio Hamano having approved this approach after commit message refinements clarified the fsck vs runtime behavior differences. The implementation preserves historical behavior while adding appropriate detection and reporting.
