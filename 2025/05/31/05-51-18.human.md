This is a follow-up in the ongoing discussion about modifying `git add -p` to handle merge conflicts. Jarrad Whitaker proposes a potential implementation approach: having `git add -p` automatically resolve the conflict by discarding the staged versions (stages 1-3) when first invoked on a conflicted file. 

The suggestion comes with a recognition that this might be too aggressive - it would immediately mark the file as no longer conflicted, which could be surprising behavior. Whitaker acknowledges this might be "too footgunny" (prone to accidental misuse). 

This email continues the technical exploration started in earlier messages, where Chris Torek explained the fundamental constraints of Git's index model. The current proposal attempts to work within those constraints by suggesting a behavioral change rather than an index format change, though it raises new questions about user expectations and safety. 

The thread remains in exploratory mode, with no clear consensus yet on whether to pursue any implementation or what form it should take. Phillip Wood, as the maintainer of the interactive add machinery, has not yet weighed in on these latest suggestions.
