Bugfix for `git refs verify` compatibility with older worktrees. This is a follow-up to the ongoing thread about `git refs verify` failing on worktrees created with Git v2.43.0 or older.

Kristoffer Haugsbakk provides additional context and minor suggestions for shejialuo's proposed fix. The core issue is that the fsck code assumes all worktrees have a "refs" directory, which wasn't automatically created in older Git versions. The patch modifies `files_fsck_refs_dir()` to ignore ENOENT errors specifically for linked worktrees.

Haugsbakk notes two important commits in the timeline: 8f4c00de95 (2024) which changed worktree refdb creation, and 7c78d819e6a (2024) which introduced the regression in v2.48.0. He also points out that the issue was discovered through `git-fsck` stderr output changes in v2.48.0-rc1.

The email includes minor nits about the commit message wording and test case formatting, suggesting using `git rev-parse --git-dir` instead of hardcoding `.git` path. The discussion indicates the fix is ready for review, with the remaining questions being about test implementation details and whether the regression warrants inclusion in the current release cycle.
