Bugfix targeting worktree refs verification compatibility. This patch addresses the issue where `git refs verify` fails on older-format worktrees that lack a `refs` directory, a regression introduced in Git v2.47.0.

The fix modifies `files_fsck_refs_dir()` in `refs/files-backend.c` to specifically ignore ENOENT (no such directory) errors for linked worktrees, while maintaining the error reporting for other cases. This preserves backward compatibility with worktrees created before v2.43.0 while keeping the verification behavior for newer worktrees that have the expected directory structure.

The patch includes a new test case in `t/t0602-reffiles-fsck.sh` that verifies the fix by creating a worktree, manually removing its `refs` directory (to simulate the old layout), and confirming `git refs verify` no longer fails. The test follows the pattern established in previous test cases in this file while addressing Eric Sunshine's earlier feedback about test implementation.

This appears to be a straightforward solution to the compatibility issue identified in the thread, though maintainers may want to consider whether this approach should be documented as a known behavior change in the release notes. The patch is minimal and focused, with clear test coverage for the specific case reported by Kristoffer Haugsbakk.
