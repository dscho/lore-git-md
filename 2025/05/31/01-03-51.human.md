Bugfix for `git refs verify` compatibility with older worktrees. This is a follow-up to Kristoffer Haugsbakk's report about `git refs verify` failing on worktrees created with Git v2.43.0 or older.

Shejialuo confirms the issue and identifies the commit (8f4c00de95) that changed when worktree refs directories are created - they're now made automatically during worktree creation, whereas older versions only created them when needed. The author plans to submit a fix soon, hoping it can make the upcoming release.

The thread has established this is a real compatibility problem where newer Git versions expect refs directories that older-format worktrees don't have. While Eric Sunshine previously focused on improving the test cases, this email moves toward an actual fix by pinpointing when the behavior changed. The proposed solution isn't shown yet, but the author appears confident they can address the issue.
