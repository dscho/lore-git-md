Bugfix for `git refs verify` compatibility with older worktrees. This patch addresses an issue where the command would fail when checking worktrees created with Git v2.43.0 or older, which didn't automatically create a "refs" directory in worktree metadata.

The fix modifies the files backend to gracefully handle missing refs directories in linked worktrees by checking for ENOENT (no such file/directory) errors. This maintains backward compatibility while preserving the stricter verification behavior for newer worktrees that should have this directory. The change is minimal - just a few lines adding the error check before reporting directory access failures.

A new test case demonstrates the fix by simulating an old-format worktree (by manually removing its refs directory) and verifying `git refs verify` now succeeds rather than failing. The patch appears well-targeted, with the test directly exercising the problematic scenario reported by Kristoffer Haugsbakk.

This is part of the ongoing effort to handle the behavior change introduced in Git v2.47.0 (commit 8f4c00de95) that started automatically creating refs directories. The solution takes a pragmatic approach of making the verification more lenient for older worktrees rather than forcing migration or complex detection logic.
