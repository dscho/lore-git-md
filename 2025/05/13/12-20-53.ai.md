This is a feature patch adding a new configuration option for commit signing. It introduces `commit.signoff` as a configuration counterpart to the existing `--signoff` command-line flag, similar to how `format.signoff` works for `git format-patch`.

The patch adds the new config option to `builtin/commit.c`, documents it in the signoff documentation, and includes a test case verifying that setting `commit.signoff` automatically adds signoffs to commits. The implementation follows the established pattern seen with other boolean commit options in the codebase.

The motivation is to provide a persistent way for users who regularly need signoffs to avoid having to specify `--signoff` on every commit or create shell aliases. This matches Git's general pattern of making frequently used command-line options available as config settings. The change is straightforward and well-contained, touching only the commit command's configuration handling while maintaining the existing `--signoff` behavior.

Key technical details for future reference:
- New config key: `commit.signoff` (boolean)
- Implementation in `git_commit_config()` alongside similar options
- Documentation added to `signoff-option.adoc`
- Test case in `t7500-commit-template-squash-signoff.sh` verifies config-based signoff works
- Maintains existing `--signoff`/`--no-signoff` command-line behavior
- Follows precedent of `format.signoff` for patch-based workflows
