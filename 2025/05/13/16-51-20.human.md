This is the final patch in a performance optimization series for the packed-refs backend, switching the fsck verification path to use mmap rather than reading the file contents into memory. The change aligns fsck with the rest of the codebase's memory-efficient approach and completes the refactoring work started in earlier patches.

The patch replaces direct file reading via `strbuf_read()` with the new `allocate_snapshot_buffer()` helper introduced in patch 2, maintaining the same verification logic through `packed_fsck_ref_content()` and `packed_fsck_ref_sorted()`. Junio Hamano notes the implementation is clean though slightly quirky in how it handles empty files, and approves the change while suggesting a theoretical alternative design.

With this patch, the series achieves its goals of memory optimization and code consistency across all packed-refs operations. The work has received thorough review from Jeff King and Patrick Steinhardt, with only minor documentation polish noted as future work. The thread shows consensus among all involved maintainers, making this ready for inclusion.
