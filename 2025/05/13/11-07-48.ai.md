This is a refactoring patch in the packed-refs optimization series, specifically addressing buffer allocation logic. The patch extracts the buffer allocation code from `load_contents()` into a new helper function `allocate_snapshot_buffer()`. This enables the same allocation logic to be reused for fsck verification while maintaining the existing behavior around mmap thresholds (32KB cutoff) and Windows compatibility (MMAP_TEMPORARY handling). The change preserves all existing functionality while making the code more modular - the helper now handles both mmap and read-based loading paths, returning whether allocation succeeded (1) or the file was empty (0).

Key technical details:
- Core change moves 22 lines into new helper while adding 9 lines of function scaffolding
- Maintains identical mmap_strategy behavior (MMAP_NONE vs threshold-based selection)
- Preserves Windows-specific mmap handling through xmmap()
- Keeps same error handling (die_errno on failures)
- Updates `load_contents()` to use the helper while maintaining its interface
- Follows suggestions from Jeff King and Patrick Steinhardt in earlier thread discussion

The refactoring has already been reviewed and approved by Jeff King in previous iterations, with only minor style notes about variable handling that were addressed in v4. This is the middle patch in a 3-part series that has reached consensus among all participants (Jeff King, Patrick Steinhardt, and Junio Hamano). The change enables the subsequent fsck verification patch while standing as a clean refactoring on its own merits.
