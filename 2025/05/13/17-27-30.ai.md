This is a follow-up in the platform compatibility thread about msgfmt argument ordering under POSIXLY_CORRECT. Johannes Sixt asks Nathan Royce for more details about the environment where the build failure was observed, specifically requesting the OS and version. The thread previously identified that argument order matters for msgfmt when building gitk's translations with POSIXLY_CORRECT set, where `msgfmt --statistics --tcl -l bg -d po/ po/bg.po` works but the reverse order fails. This email doesn't propose solutions but seeks to better understand the reproduction environment, suggesting the issue may be platform-dependent. The core question remains whether Git's build system should be made more robust against argument ordering variations in msgfmt invocations.
