This is a technical discussion about Change-ID generation methods in the ongoing standardization effort, with a focus on comparing deterministic versus random approaches.

D. Ben Knoble responds to Martin von Zweigbergk's defense of Jujutsu's random Change-ID generation by suggesting an alternative similarity-based approach inspired by Git's rename detection. The key technical point is that commit contents (trees) rather than messages could be compared to track changes, analogous to how Git detects file renames based on content similarity. Knoble references Git's range-diff functionality as a potential model for this approach.

The email highlights an important tension in the thread - while Jujutsu's random IDs work operationally, Knoble suggests content-based tracking might better align with Git's existing mechanisms. This introduces another technical dimension to the discussion beyond the security-focused deterministic approaches (SHA-256/HMAC-SHA-256) proposed earlier by brian m. carlson.

The exchange surfaces two competing philosophies: Jujutsu's pragmatic random IDs versus Git-style content-derived identifiers. Knoble's suggestion of tree-based comparison offers a potential middle ground that leverages Git's native capabilities while still providing stable change tracking. This keeps open the question of whether the standardization should prioritize operational simplicity (random IDs), security (deterministic hashes), or Git compatibility (content-based tracking).
