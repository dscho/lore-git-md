This is a refactoring patch in the packed-refs optimization series, specifically addressing buffer allocation. The patch extracts snapshot buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()` to enable code reuse, particularly for fsck verification paths that need the allocation logic without file opening.

The change has already been technically approved by Jeff King, who noted one minor readability improvement opportunity (simplifying the `ret` variable handling) but considers it not worth a re-roll. The helper function preserves all existing behavior including mmap/read thresholds and Windows MMAP_TEMPORARY handling.

This patch (2/3) is part of a series that has reached consensus on its technical approach, with the buffer allocation refactoring enabling subsequent mmap-based fsck verification (patch 3/3). The thread shows active collaboration between shejialuo, Jeff King, and Patrick Steinhardt, with clear technical alignment on the implementation. The only outstanding item is a trivial code style note that the author plans to address in a future version.
