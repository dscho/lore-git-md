Bugfix and fsck enhancement for packed-refs handling. This is the first patch in a v4 series addressing memory optimization and safety in the packed-refs backend, now implementing the agreed-upon solution for empty file detection.

The patch introduces a new INFO-level fsck warning "EMPTY_PACKED_REFS_FILE" when encountering empty packed-refs files, rather than treating them as errors. This maintains runtime compatibility (since empty files were legitimately created by pre-1.8.4 Git versions) while warning users about the deprecated state. The warning includes documentation explaining that only very old Git versions create such files and that future versions may enforce stricter validation.

Implementation adds the warning check in `packed_fsck()` after verifying the file exists but before reading contents. The warning uses the existing fsck reporting infrastructure with a new message ID. Test coverage in t0602-reffiles-fsck.sh verifies the warning appears for empty files but doesn't fail verification. Documentation updates in fsck-msgids.adoc explain the warning's purpose and potential future tightening.

This completes the filesystem safety aspect of the series, implementing the middle path Jeff King proposed and all reviewers agreed upon - warning about empty files while maintaining runtime leniency. The patch follows historical context established in the thread discussion, where Jeff confirmed pre-1.8.4 behavior and Patrick Steinhardt raised valid filesystem safety concerns. The INFO-level severity was chosen to avoid breaking compatibility while still surfacing the issue.
