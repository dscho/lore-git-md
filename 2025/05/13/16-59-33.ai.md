This is a continuation of the discussion about cleaning up Git's `contrib/` directory, specifically focusing on credential helpers. Junio C Hamano responds to Patrick Steinhardt's proposal about moving certain credential helpers from `contrib/` to core.

The email addresses two key points from the ongoing thread: First, Hamano agrees with moving security-focused credential helpers (`libsecret` and `osxkeychain`) into core Git, suggesting a straightforward path via removing their `contrib/` prefix. Second, he pushes back on labeling the `netrc` helper as "known-unsafe", arguing that when used with GPG-encrypted files on properly secured single-user systems, it can be a reasonable solution despite its plaintext storage nature.

This response moves the credential helper discussion forward by providing maintainer approval for the core integration of security-sensitive helpers while introducing nuance to the safety evaluation of `netrc`. The exchange demonstrates progress toward operationalizing the earlier-proposed framework for handling legacy components, with credential helpers now having clear promotion paths differentiated by their security characteristics. The technical implementation appears straightforward (simple file moves), though the policy discussion around safety thresholds for core components continues.
