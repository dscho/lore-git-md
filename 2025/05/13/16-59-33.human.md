This is a discussion about credential helper security and maintenance in the ongoing "contrib/" cleanup thread.

Junio Hamano responds to Patrick Steinhardt's proposal about moving credential helpers from contrib/ to core. He agrees that secure helpers like libsecret and osxkeychain should be moved to core with a simple directory change, but pushes back on labeling the netrc helper as "known-unsafe". 

Hamano argues the netrc helper's safety depends on context - while it stores credentials in plaintext by default, it can be reasonably secure when used with GPG-encrypted files on properly secured single-user systems. This nuanced view suggests the netrc helper might still have a place in core despite its different security model compared to other credential helpers.

The exchange shows the discussion moving from broad cleanup principles to specific implementation questions about security tradeoffs. While there's agreement on promoting secure credential helpers, the netrc case highlights how even "unsafe" tools may have valid use cases that complicate simple removal decisions. This continues the thread's progression toward concrete action while surfacing important security considerations.
