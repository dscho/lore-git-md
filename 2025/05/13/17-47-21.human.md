Bugfix follow-up addressing additional memory leaks in pack-bitmap error handling. Taylor Blau builds on Lidong Yan's initial fix for `load_bitmap_entries_v1()` by identifying a broader issue: when `load_bitmap()` fails partway through loading entries, it destroys the bitmap hashmap without freeing already-loaded entries, leaking their memory. The proposed solution removes the error-handling code from `load_bitmap()` entirely, as its callers will invoke `free_bitmap_index()` to properly clean up regardless of success or failure. This maintains the same error behavior while ensuring complete cleanup.

The patch appears technically sound, addressing a real issue in the bitmap loading path. It complements the earlier fix by handling the case where some bitmaps load successfully before a failure occurs. The change is focused and well-explained, though it hasn't yet received review feedback. Given the performance-critical nature of the bitmap subsystem and the straightforward nature of the fix, this seems like a low-risk improvement to error handling.
