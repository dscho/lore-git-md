This is the final patch in a build system series, specifically addressing an autoconf configuration issue for sysinfo detection. The patch upgrades the `HAVE_SYSINFO` check in configure.ac from a simple function existence test to a full compilation check that verifies both the function and its expected struct fields (`totalram` and `mem_unit`).

The change mirrors a similar fix already implemented in Meson (commit f5e3c6c57d) and corrects a Solaris/Cygwin compatibility issue where the existing check could incorrectly report sysinfo availability. The problem stems from Solaris having a sysinfo() function with different semantics than Linux's version, despite sharing the same header name. The new check ensures the function behaves as needed by `git gc`'s RAM calculation.

The patch completes the series' goal of aligning build system behaviors across Make, Meson and Autoconf. It specifically affects the autoconf build's handling of sysinfo detection while maintaining compatibility with existing configurations. The implementation carefully validates both the function signature and the struct field access patterns actually used by Git's memory calculation code.

Key technical details include:
- Replacement of `GIT_CHECK_FUNC` with `AC_COMPILE_IFELSE`
- New `HAVE_SYSINFO_SRC` macro containing the test program
- Verification of both `si.totalram` and `si.mem_unit` usage
- Maintained `HAVE_SYSINFO` variable and substitution behavior

This appears to be a well-justified change that closes a platform-specific edge case while keeping the build system's behavior consistent. The patch follows the pattern established by the earlier Meson fix and has already received positive feedback in the thread.
