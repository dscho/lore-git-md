This thread documents two parallel efforts to improve Git's email-related functionality: a now-completed documentation update and an ongoing technical implementation of OAuth2.0 support for git-imap-send.

The documentation work, which reached its seventh and final version, focused on clarifying email authentication methods. It standardized terminology (using "mechanism" consistently for OAuth), reorganized credential helper references to include Yahoo alongside Gmail and Outlook options, and explicitly noted Gmail's shift away from regular passwords toward OAuth2.0 as the preferred authentication method. Junio Hamano approved the final wording with a "Much nicer" review, particularly praising the clear distinction between app passwords and OAuth2.0. The series also addressed numerous formatting details like strict backtick consistency for configuration options and standardized placeholder formats.

A minor outstanding point about improving OpenSSL `verify(1)` documentation was acknowledged by Aditya Garg but deliberately left for a future patch, with Junio agreeing this wouldn't detract from the current series' completeness. This exchange effectively closed the documentation effort, with all substantive feedback addressed.

Meanwhile, the technical implementation of OAuth2.0 for git-imap-send remains in progress at version 5. It builds on the documentation work's approach, implementing OAUTHBEARER and XOAUTH2 authentication while maintaining backward compatibility with CRAM-MD5. The implementation handles both OpenSSL and non-OpenSSL builds and includes updated IMAP capability handling.

The thread demonstrates Git's meticulous documentation standards in action, with Junio Hamano and Ben Knoble ensuring rigorous review of both content and formatting. While the documentation work is now complete, the related technical implementation continues its review process, benefiting from the now-standardized documentation approach.
