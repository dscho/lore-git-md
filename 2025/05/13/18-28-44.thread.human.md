This thread documents two parallel efforts to improve Git's email-related functionality and documentation. The first is a documentation series (now at v6) that reorganizes and clarifies email-related documentation, particularly around credential helpers and authentication methods. The second is a technical implementation adding OAuth2.0 support to git-imap-send (currently at v5).

The documentation work has evolved through multiple iterations, with recent changes including better organization of credential helper references, standardized formatting, and clearer authentication guidance. A notable discussion point has been Junio Hamano's insistence on strict documentation consistency standards, particularly around formatting choices like using backticks versus single quotes for email header names. Aditya Garg, the series author, has conceded some points (like keeping a reference to `verify(1)` that he initially thought was broken) while advocating for readability in other cases. The documentation is nearing its final form, with the latest version incorporating feedback from both Junio and an external git-scm.com PR that helped surface organization issues.

Meanwhile, the technical implementation for git-imap-send OAuth2.0 support continues under review. This work builds on concepts from the documentation effort while adding new authentication methods and maintaining backward compatibility. Both efforts demonstrate Git's careful approach to email-related improvements, with Junio ensuring rigorous review standards across documentation and implementation. The thread shows how initial documentation work can inform technical changes while maintaining high standards for clarity and consistency.
