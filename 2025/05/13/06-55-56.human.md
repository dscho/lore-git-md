This is a refactoring patch in a series optimizing memory usage in the packed-refs backend. It extracts buffer allocation logic from `load_contents()` into a new helper function `allocate_snapshot_buffer()` to enable code reuse, particularly for fsck verification which needs similar logic but without opening files.

The patch has already been reviewed and approved by Jeff King, who noted one minor readability improvement (simplifying the return value handling) that the author agrees with but considers too small to warrant a re-roll. The change preserves all existing behavior including mmap/read thresholds and Windows compatibility, while making the code more maintainable.

This is patch 2/3 in a technically complete series that has reached consensus among key reviewers (Jeff King, Patrick Steinhardt, and Junio Hamano). The remaining discussion focuses on finalizing fsck warning implementation details rather than this refactoring, which is considered sound and ready for inclusion.
