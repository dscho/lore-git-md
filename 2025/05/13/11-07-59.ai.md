This is the final patch in a series optimizing memory usage in the packed-refs backend, specifically focusing on the fsck verification path. The patch completes the refactoring work by replacing direct file reading with mmap`-based verification in `packed_fsck()`, aligning it with the rest of the codebase's memory-efficient practices.

The change builds on the `allocate_snapshot_buffer()` helper introduced in patch 2, using it to mmap large packed-refs files during verification rather than reading them into a strbuf. This maintains the same 32KB mmap threshold and Windows compatibility while reducing memory overhead. The patch removes 12 lines of direct file reading code and replaces it with 7 lines using the new helper, keeping the same error handling and verification logic.

Key technical points:
- Switches from `strbuf_read()` to mmap-based verification in `packed_fsck()`
- Uses the new `allocate_snapshot_buffer()` helper (from patch 2)
- Maintains identical verification behavior through `packed_fsck_ref_content()` and `packed_fsck_ref_sorted()`
- Preserves the empty file detection path (now using the helper's return value)
- Updates cleanup to use `clear_snapshot_buffer()` instead of `strbuf_release()`
