This is a bugfix patch in the ongoing diff context configuration series, specifically addressing validation in the stash command.

Phillip Wood identifies an issue where `git stash` fails to properly validate the `--unified` and `--inter-hunk-context` options when used with `--patch`. Currently, the command checks for stashable changes before validating these options, which means invalid values (like negative numbers) might be silently ignored if there's nothing to stash. The proposed fix would move the validation earlier in the execution flow to ensure consistent behavior with other interactive commands.

The patch builds on the series' established validation patterns, where negative values for diff context settings are rejected. This maintains consistency with the thread's earlier work on config validation and command-line overrides. The issue specifically affects the stash command's handling of the `add_p_opt` struct fields that were added in previous patches of this series.

This appears to be the final refinement to the series' edge case handling, following Phillip Wood's earlier test reorganization and coverage improvements.
