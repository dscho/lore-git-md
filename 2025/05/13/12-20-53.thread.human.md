This thread introduces a new `commit.signoff` configuration option that provides persistent signoff behavior for commits, similar to the existing `--signoff` command-line flag. The initial patch added the config option in `builtin/commit.c`, documented it, and included test cases, following Git's pattern of making frequently used command-line options available as config settings.

D. Ben Knoble has reviewed the implementation and suggested two test improvements: using `test_config` for better cleanup and potentially refactoring to use the `commit_msg_is` helper function. He also referenced prior discussion about similar functionality, though this doesn't reopen the core design question. The suggestions are focused on test quality rather than the feature itself, which remains uncontroversial. The change is straightforward and follows established patterns for boolean options in the codebase.
