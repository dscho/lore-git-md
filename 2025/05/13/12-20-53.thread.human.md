This thread centers on a proposal to add a `commit.signoff` configuration option that would automatically add Signed-off-by lines to commits, mirroring the existing `format.signoff` option for patches. The technical implementation is straightforward and uncontroversial, with clean code in `builtin/commit.c`, proper documentation, and tests.

The debate has evolved into a philosophical discussion about whether historical precedent justifies expanding automatic signoffs. Chris Down, the patch author, argues that the long-standing `format.signoff` option (in use since 2009 without issues) sets a valid precedent. Initial reviewer D. Ben Knoble was satisfied with this justification after some back-and-forth about test implementation details.

Maintainer Junio Hamano objects on principle, viewing automatic signoffs as problematic regardless of precedent. In the latest exchange, Junio contends that the very existence of this debate proves the original `format.signoff` feature was ill-advised, even if no concrete harm has been demonstrated. This leaves the discussion at an impasse between precedent-based justification and maintainer philosophy.

The patch remains technically sound but stalled on policy grounds. Unless Junio can point to specific problems caused by `format.signoff` or Chris can find a way to address the philosophical concerns, this proposal may not move forward despite its technical readiness. The core disagreement now centers on Git's approach to automating legal attestations rather than any implementation details.
