This thread proposed adding a `commit.signoff` configuration option to automatically add Signed-off-by lines to commits, similar to the existing `format.signoff` option for patches. The implementation was technically sound, with reviews from D. Ben Knoble and Chris Down confirming the code in `builtin/commit.c`, tests, and documentation were properly structured.

However, Junio C Hamano ultimately rejected the feature on philosophical grounds, arguing that Git shouldn't lower the barrier to automatic signoffs as this could dilute their legal meaning. Collin Funk reinforced this by drawing parallels to FSF copyright processes, highlighting potential legal risks. The discussion concluded that while user-created aliases for signoff are acceptable, project-provided automation crosses a line. Chris Down's final email politely accepted this decision, marking the definitive end of the proposal. The existing `format.signoff` mechanism remains as the only project-provided signoff automation, with no expansion to commit-time signoffs planned.
