This is a platform compatibility report regarding argument ordering in the msgfmt command when building Git's translations.

Nathan Royce reports that the POSIXLY_CORRECT environment variable affects how msgfmt processes arguments when building translations, specifically for the Tcl format. The issue manifests when building gitk's translations, where the command fails if the locale specification (`-l bg`) comes after the input file (`po/bg.po`), but succeeds when arguments are ordered with options first.

The error occurs in the build process when running `make all`, specifically failing at the gitk translation step in the Makefile. The report includes concrete examples of both failing and successful command invocations, showing that `msgfmt --statistics --tcl -l bg -d po/ po/bg.po` works while the reverse order fails.

This appears to be a build system quirk rather than a Git code issue, but it could affect developers building Git from source on systems where POSIXLY_CORRECT is set. The report doesn't propose a solution but clearly demonstrates the problematic behavior, which could help maintainers decide whether to adjust the build process to be more robust against argument ordering.
