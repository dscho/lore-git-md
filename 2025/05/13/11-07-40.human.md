This is the first patch in a v4 series addressing memory optimizations for the packed-refs backend, specifically focusing on filesystem safety and fsck behavior. The patch introduces a new INFO-level fsck warning when encountering an empty packed-refs file.

The change recognizes that while Git's runtime code has historically accepted empty packed-refs files (for compatibility with very old Git versions), such files have not been created since Git 1.8.4 (commit 694b7a1999). The patch adds a gentle warning to alert users about these legacy empty files, as future Git versions may enforce stricter validation. The warning is implemented at INFO level rather than ERROR to maintain backward compatibility.

The implementation includes documentation updates, test coverage, and the actual fsck check in packed-backend.c. This represents the consensus solution from the thread discussion, where Jeff King, Patrick Steinhardt, and Junio Hamano agreed on this graduated warning approach rather than immediate strict enforcement. The patch appears well-considered, with clear commit message explaining the historical context and future direction, and thorough test coverage demonstrating the new behavior.
