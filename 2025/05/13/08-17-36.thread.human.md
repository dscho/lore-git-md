This thread addresses a platform compatibility issue in Git's build process, specifically to the translation handling for gitk (the Tcl/Tk GUI). Nathan Royce initially reported that `msgfmt` command argument ordering fails when `POSIXLY_CORRECT` is set, breaking the build of non-English translations. Johannes Sixt (gitk maintainer) investigated and requested more platform details to understand the scope. 

The discussion confirmed this is a build system quirk rather than a core Git issue, where `msgfmt --statistics --tcl -l bg -d po/ po/bg.po` works but the reverse argument order fails under `POSIXLY_CORRECT`. Johannes has now marked the issue as fixed in the build system, though the exact solution isn't detailed in this email. The fix likely involves argument reordering or `POSIXLY_CORRECT` handling in the Makefile, resolving the problem without requiring changes to Git's core code. The resolution came after Nathan demonstrated reproducible failure by simply setting `POSIXLY_CORRECT=1` during build. This appears to close the issue unless new platform-specific cases emerge.
