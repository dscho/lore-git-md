This thread reports a build system quirk affecting Git's translation files, specifically when building gitk's translations. Nathan Royce found that the order of arguments passed to `msgfmt` matters when the POSIXLY_CORRECT environment variable is set - the command fails if the locale specification comes after the input file, but succeeds when options appear first. The issue manifests during `make all` when processing Tcl-formatted translations like `po/bg.po`.

While this doesn't affect Git's core functionality, it could trip up developers building from source on systems where POSIXLY_CORRECT is enabled. The report provides clear reproduction steps showing both failing and working command invocations, giving maintainers enough information to consider whether to make the build process more robust against argument ordering variations.
