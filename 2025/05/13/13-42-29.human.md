This is the final version of a bugfix and refactoring patch for email header decoding in `mailinfo.c`. The patch series started as a fix for a memory leak when `convert_to_utf8()` fails, and evolved into a comprehensive architectural improvement under Junio C Hamano's guidance. 

The v4 patch completes the transition to caller-allocated strbufs in the decoding functions, removing the last remaining `strbuf_init()` calls in favor of `strbuf_grow()`. While this slightly over-allocates memory for Q and B-encoded segments (since decoded output is always smaller than encoded input), Hamano has accepted this as a harmless inefficiency. The patch also cleans up error handling in `convert_to_utf8()` and ensures consistent use of stack-allocated strbufs throughout the header decoding subsystem.

The iterative review process has resulted in robust solution that properly manages strbuf ownership while fixing the original memory leak. With all technical issues resolved and Hamano's approval, this patch is now ready for merging. The collaboration demonstrates how Git's review process can transform a bugfix into a meaningful architectural improvement.
