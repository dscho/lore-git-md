This is a follow-up in the platform compatibility thread about `msgfmt` argument ordering issues when building Git's translations.

Johannes Sixt asks Nathan Royce for more details about the environment where the `msgfmt` argument ordering problem was observed. The original report showed that with `POSIXLY_CORRECT` set, `msgfmt` fails when the `.po` file appears before the `-l` locale flag, but succeeds with the reverse order. This affects Git's translation build process, specifically for gitk's Tcl message catalogs.

The response seeks to better understand the context by asking about the operating system and version where the issue was seen, suggesting the next step is to gather more concrete reproduction details before considering any build system changes. The thread remains focused on diagnosing rather than solving the issue at this stage.
