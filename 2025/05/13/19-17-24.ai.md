This is a build system patch fixing system-wide config path handling in Meson. It's part 3 of a 5-part series addressing various build system issues, with this specific patch focusing on correcting how Git's system configuration and attributes files are located during Meson builds.

The patch changes Meson's handling of `gitconfig` and `gitattributes` paths to properly respect the `sysconfdir` convention, where paths should be relative to the installation prefix rather than always assuming `/etc`. The key changes are:
1. Removing hardcoded `/etc` defaults from meson_options.txt
2. Implementing logic in meson.build to use `sysconfdir` when paths aren't explicitly overridden
3. Maintaining backward compatibility by still allowing explicit path overrides

The implementation follows standard Unix filesystem hierarchy conventions, where `/usr` gets `/etc` but other prefixes (like `/usr/local`) get their own `etc` subdirectory. This matches behavior in Git's Makefile-based build system. The patch includes careful handling of both absolute and relative path specifications.

This change is technically sound and addresses a real inconsistency in the Meson build configuration. It's part of the broader effort to align Meson's behavior with Git's existing build system while properly handling cross-platform installation scenarios. The patch has already incorporated feedback from Patrick Steinhardt regarding Meson path handling conventions.
