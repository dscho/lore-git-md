Bugfix for potential divide-by-zero in parallel fetch operations. This patch addresses a safety issue in `builtin/fetch.c` where the `max_children` parameter (used to control parallel operations) could be zero, leading to a division by zero in `pp_collect_finished`. The fix changes the validation check from `max_children < 0` to `max_children <= 0` in two locations - for both regular fetch operations and submodule fetches. When zero is detected, it falls back to the configured parallel jobs value (`config.parallel` or `config.submodule_fetch_jobs`).

The change is straightforward and clearly motivated by preventing a real (though likely rare) crash scenario. The patch touches only the validation logic, not the actual parallel processing code, suggesting the fix is well-contained. The commit message could be slightly more detailed about the exact failure scenario (mentioning `pp_collect_finished` explicitly), but the technical content appears correct. This seems like a low-risk defensive programming improvement that should be uncontroversial to merge.
