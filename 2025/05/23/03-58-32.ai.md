Bugfix for `imap-send` configuration parsing that corrects a regression introduced in commit 6d1f198f34. The patch fixes a critical issue where setting any of `imap.user`, `imap.pass`, `imap.tunnel`, or `imap.authmethod` would incorrectly NULL out the `cfg->folder` field, effectively breaking `git imap-send` functionality. The regression had gone unnoticed likely due to `git send-email` being the more commonly used alternative.

The fix is straightforward - replacing incorrect `FREE_AND_NULL(cfg->folder)` calls with the proper field-specific cleanup for each configuration option (`user`, `pass`, `tunnel`, `auth_method`). This maintains the intended memory management while preventing the accidental clearing of unrelated fields. The change affects the core configuration parsing logic in `imap-send.c`.

This is the first patch in a v3 series that has already undergone significant review, with Junio Hamano having previously confirmed the technical correctness of this specific fix while suggesting commit message improvements. The bug's impact is severe (making `imap-send` unusable when certain configs are set) but the solution is clean and focused, with minimal changes (4 lines modified) to correct the behavior. The patch shows good attention to detail by specifically referencing the problematic commit and explaining the real-world impact.
