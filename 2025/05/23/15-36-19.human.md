Bugfix for `git send-email` threading behavior when editing the first patch in a series. This patch addresses a subtle issue where shallow threading breaks if (1) `--in-reply-to` is specified and (2) the user edits the first patch before sending. In this case, subsequent patches incorrectly thread to the original `--in-reply-to` target rather than the first patch in the series.

The root cause lies in how threading conditions are evaluated. The script was checking `$message_num == 1` (which increments when editing) rather than `$num_sent == 1` (which tracks actual sends). The fix switches to using `$num_sent`, making the behavior consistent regardless of edits.

The patch maintains existing behavior in all cases except the specific bug scenario, and the author notes this won't affect users who don't use `--in-reply-to`.
