Performance optimization for the proposed `git last-modified` command. This patch adds Bloom filter support to skip unnecessary diff computations during the revision walk, yielding dramatic speed improvements - from ~5 seconds to under 1 second in kernel repository tests. The implementation builds on Taylor Blau's prior Bloom filter work, checking path changes probabilistically before computing full diffs.

The patch extends the `last_modified_entry` struct to store Bloom keys for each tracked path and adds new logic to consult the commit-graph's Bloom filters. When filters indicate no possible changes to relevant paths, the expensive diff computation is skipped entirely. Benchmark results show a 5-6x speedup even in unoptimized builds, with further gains under `-O3`.

This appears to be a well-integrated optimization that follows the established Bloom filter patterns in Git's codebase. The implementation handles edge cases like missing generation numbers or filters gracefully. As part of the v2 series, this addresses one of the key performance concerns raised in earlier discussion while maintaining the command's correctness guarantees.
