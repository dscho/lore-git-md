This is a follow-up discussion about the partial clone optimization gap in `git show` identified in Bob Bell's bug report. Junio Hamano confirms the core issue: `git show -s` (without diff-affecting options) unnecessarily accesses parent tree objects in partial clones, though he notes the immediate error occurs because the test deliberately corrupts the repository by removing the promisor remote.

The discussion connects this to prior work by Jeff King (Peff) on similar object-access optimizations, linking two relevant threads. Hamano clarifies that while `-s` suppresses diff output, certain options like `--diff-filter` or pathspecs may still require tree access to evaluate changes. This suggests any fix would need to carefully consider which `git show` modes truly need tree objects versus those that can work with commit metadata alone.

The exchange indicates this is a legitimate optimization opportunity to align `git show`'s `git log`'s more efficient behavior in partial clones, though the solution will need to account for edge cases where tree access remains necessary. The tone is constructive, with Hamano validating the underlying issue while providing technical context about when tree access is actually required.
