This is a feature and bugfix series for `imap-send`, now in its fourth iteration. The series aims to restore functionality of the largely neglected IMAP email sending capability in Git while adding modern OAuth2.0 authentication support.

The v4 series expands on previous versions by adding PLAIN authentication for OpenSSL and further refining the fixes for configuration parsing and memory leaks. The core improvements remain: fixing a critical config parsing bug that made `imap-send` unusable (where certain config settings would incorrectly NULL out the folder field), and adding OAuth2.0 support via curl's native API. The new PLAIN authentication method provides another fallback option when OpenSSL is used instead of curl.

The series has seen thorough review from key Git maintainers, with Jeff King, Eric Sunshine, and Junio Hamano all contributing feedback that's been incorporated. The architectural shift from OpenSSL to curl for OAuth2.0 was driven by licensing concerns raised by Brian Carlson. With the memory leak fixes now comprehensive (covering CRAM-MD5 failure paths) and config parsing robust, this appears to be a mature series ready for inclusion.

While `imap-send` isn't widely used compared to `git send-email`, these fixes make it properly functional again while bringing it up to modern authentication standards. The documentation updates help users navigate the configuration and OAuth2.0 setup, including provider-specific quirks for services like Gmail and Outlook.
