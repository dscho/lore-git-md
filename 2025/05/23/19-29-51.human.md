This is part 5 of a 9-part documentation patch series focused on improving `--stdin` and whitespace handling documentation in git-notes. The patch removes redundant discussion of whitespace stripping behavior from options where it doesn't belong, following the principle that porcelain commands typically clean whitespace by default without needing explicit documentation.

The key changes are:
1. Removes mentions of comment line stripping and whitespace cleaning from `-m` and `-F` options, since these behaviors are already covered by the general `--stripspace` documentation
2. Clarifies that `-C/--reuse-message` implies `--no-stripspace` by default since it aims to copy messages verbatim
3. Eliminates misleading references to comment character handling that were incorrectly mixed with whitespace discussion

The patch continues the series' trend of separating concerns (whitespace vs comment handling) and documenting actual behavior rather than incorrect assumptions. It follows git-commit(1)'s example of only noting whitespace behavior where it differs from the default. The changes are clean and focused, with the commit message clearly explaining the rationale for each removal.
