Feature patch adding OAuth2.0 authentication support for `imap-send`, part of a v3 series addressing IMAP authentication improvements. This patch introduces RFC-compliant OAUTHBEARER and Google's proprietary XOAUTH2 mechanisms, completing the architectural shift from OpenSSL to curl-native authentication that began in v2.

Key technical details:
- Adds `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` capability flags and implements corresponding authentication handlers (`auth_oauthbearer()`, `auth_xoauth2()`)
- Introduces helper functions `oauthbearer_base64()` and `xoauth2_base64()` for proper RFC 5801/7628 compliant token encoding, with OpenSSL fallback paths
- Documents provider-specific requirements: Gmail needs app-specific passwords or OAuth tokens, Outlook only supports XOAUTH2
- Updates curl integration to use `CURLOPT_XOAUTH2_BEARER` which automatically handles both mechanisms
- Maintains backward compatibility by only applying OAuth2.0 curl options when explicitly configured

The implementation handles edge cases like:
- Proper base64 encoding/decoding of OAuth tokens
- Server capability checking before attempting OAuth methods
- Clear error messages about unsupported authentication methods
- Documentation of provider-specific quirks (Gmail's localized folder names, Outlook's XOAUTH2 requirement)

This builds on the series' earlier config parser fixes and represents the main feature addition, enabling modern authentication flows while maintaining compatibility with existing IMAP setups. The documentation updates provide clear guidance for users needing to configure OAuth2.0 with major providers.
