This is a documentation patch addressing a gap in the submodule configuration documentation. Chris Wilson reports encountering an issue where trying to use a relative URL in `git config submodule.<name>.url` didn't work as expected - the system treated it as a filesystem path rather than resolving it like relative URLs in `.gitmodules` files do. Their workaround was to directly modify the `.gitmodules` file with `sed`.

The patch proposes updating the `git-config` documentation to explicitly state that `submodule.<name>.url` only accepts absolute URLs, unlike the `.gitmodules` file which handles relative URLs. As an alternative suggestion, they float the idea of adding a new configuration option to make the config setting behave like `.gitmodules` does with relative URLs.

The issue appears to be a real-world pain point encountered in CI/CD systems where relative URLs would be useful. While the email doesn't include an actual patch, it clearly identifies a documentation gap and suggests two potential solutions - one immediate (documenting the limitation) and one future-looking (adding new functionality). The proposal seems well-motivated by a concrete use case.
