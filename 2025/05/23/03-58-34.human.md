This is the final patch in a bugfix series for `imap-send`, addressing a memory leak in the CRAM-MD5 authentication path. The patch ensures the `response` buffer is properly freed when socket writing fails during authentication, closing a resource leak that could occur in error conditions.

The change is straightforward - wrapping the error return with a `free(response)` call to match the existing cleanup that happens on the success path. This completes the memory management fixes in the authentication subsystem that were started in earlier patches of the series.

As part of a v3 series that has already received thorough review from multiple maintainers (including Junio Hamano, Jeff King, and Eric Sunshine), this patch represents the last piece of the puzzle for stabilizing `imap-send`'s authentication handling. The series as a whole has evolved from addressing configuration parsing bugs to implementing OAuth2.0 support while fixing various memory management issues.

The patch follows the same careful approach seen in the rest of the series, with a clear one-line commit message and minimal diff that precisely targets the leak. Given the prior review attention and the non-controversial nature of this fix, it appears ready for inclusion.
