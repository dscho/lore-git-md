This is a bug report about `git show` unnecessarily requiring parent tree access in partial clones. Bob Bell reports that when using a tree-less partial clone (`--filter=tree:0`) and requesting only commit metadata (like author email via `--format=%ae`), `git show` fails by trying to read the parent's tree object when it shouldn't need to. The commit metadata is actually available (as shown by `git log` and `git cat-file` working fine), but `git show` appears to be doing extra work it doesn't need to.

The report is clear and well-documented, showing the exact reproduction steps and demonstrating the inconsistency between commands. This looks like a legitimate optimization opportunity where `git show` could be made to work in more partial clone scenarios. The bug affects users who want to examine commit metadata without downloading full history, particularly in CI/CD or automation pipelines where partial clones are common.
