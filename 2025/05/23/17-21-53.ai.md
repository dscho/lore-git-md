Test patch adding coverage for `git apply` mode change warnings, part of the bugfix series for file mode handling in reverse patches. This first of two patches focuses on testing the warning behavior that commit 01aff0a fixed, where `git apply` should warn when a file's mode doesn't match what the patch expects.

The test creates a file with changing modes (executable/non-executable) and verifies that both forward and reverse application of patches properly warn about mode mismatches. It introduces helper functions `test_file_mode_staged` and `test_file_mode_HEAD` to check modes in the index and HEAD respectively. The test matrix covers:
- Core functionality with `core.fileMode=false`
- Both staged and committed file states
- Forward and reverse patch application
- Mode transitions between 0644 and 0755

This test explicitly verifies the behavior that the subsequent patch will fix regarding mode preservation during reverse application. The test structure follows Junio Hamano's earlier feedback by creating patch files once at setup and testing both directions of mode changes. The commit message clearly links this to the 01aff0a fix it's meant to validate.
