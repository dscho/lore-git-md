This is a bugfix patch in the `imap-send` authentication series, specifically addressing a memory leak in the CRAM-MD5 authentication path. It's the final patch in a v4 series that has seen extensive review and iteration.

The patch fixes a case where the `response` buffer allocated during CRAM-MD5 authentication wasn't being freed if the socket write operation failed. The fix is straightforward - adding a `free(response)` call in the error path before returning. This completes the comprehensive memory management work for CRAM-MD5 that was identified as needing attention earlier in the thread.

The change is small (just 3 lines added) but important for correctness, and fits into the larger context of the series which has been stabilizing `imap-send`'s authentication code. Given the thorough review history and the technical soundness of previous iterations, this final fix appears ready for inclusion.
