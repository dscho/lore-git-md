This is a documentation patch in a 9-part series improving `--stdin` usage documentation, specifically focusing on git-notes and `core.commentChar` behavior. This first patch updates `git-stripspace.adoc` to clarify where the default comment character comes from.

The change makes two key improvements: it explicitly states that the comment character is configurable via `core.commentChar` (while maintaining `#` as the default), and it updates the formatting to use backticks around the config variable and default value in line with modern documentation conventions. The patch removes an unnecessary link to git-config(1) that was present in v1, following feedback from Junio Hamano.

This is a straightforward documentation clarification that builds on prior work by Jean-Noël Avila and others in standardizing Git's documentation style. The change is small but meaningful, properly documenting behavior that was previously only implied. The patch maintains consistency with the series' broader goal of accurately documenting comment character behavior across related commands.
