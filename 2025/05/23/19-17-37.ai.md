Documentation patch addressing submodule URL configuration behavior. Chris Wilson reports encountering an issue where attempting to use a relative URL in `git config submodule.<name>.url` failed, requiring direct modification of the `.gitmodules` file instead. The current documentation does not explicitly state this limitation.

The patch proposes clarifying in the git-config documentation that `submodule.<name>.url` only accepts absolute URLs, treating any input as a filesystem path if not absolute. This would help others avoid similar confusion when trying to override submodule URLs without modifying the original `.gitmodules` file.

As an alternative solution, Wilson suggests potentially adding a new configuration option that would allow relative URLs to be handled consistently with how they work in `.gitmodules`. This appears to be a genuine documentation gap rather than a bug, as the current behavior seems intentional but undocumented. The email provides clear reproduction context from a real-world CI/CD use case where this limitation caused problems.
