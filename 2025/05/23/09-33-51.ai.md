This is a performance optimization patch for the `git last-modified` command, part of the v2 series implementing path modification tracking. The patch introduces a priority queue-based traversal algorithm that dramatically speeds up the operation, particularly for paths that haven't been modified in a long time.

The key technical changes include:
- New priority queue traversal using generation numbers (Derrick Stolee's approach)
- Bloom filter integration for first-parent diff optimization (Taylor Blau's contribution)
- Active path tracking via `commit_active_paths` slab and `active_paths` struct
- New `process_parent()` helper that handles diff computation and path propagation
- Special handling for boundary commits and `--not` revisions

Performance improvements are substantial:
- 2.78-9.81x faster with Bloom filters (github/git and torvalds/linux)
- 1.58-4.81x faster without Bloom filters
- The new implementation without filters matches/exceeds original performance with filters

The implementation maintains all existing functionality while adding:
- Proper memory management for Bloom keys and active paths
- Correct handling of merge commits
- Preservation of the revision walk semantics

This represents the core optimization work for the series, building on prior feedback about performance concerns. The patch appears technically sound with thorough test coverage (including new merge case tests) and maintains backward compatibility when commit-graph Bloom filters are unavailable. The co-authorship reflects the collaborative nature of the solution, combining Stolee's traversal approach with Blau's Bloom filter optimizations.
