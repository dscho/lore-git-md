Patch review feedback on documentation series. Junio Hamano responds to Kristoffer Haugsbakk's documentation patch about `--stripspace` defaults in git-notes, pointing out that while the current documentation accurately describes the implementation, that implementation may itself be buggy. 

Hamano analyzes the code history from v8 to v11 of the original implementation series, noting that the current behavior where option order affects stripping behavior (with `-m` overriding `-C`) appears to be a design flaw rather than intentional. He suggests the documentation should perhaps frame this as a known bug rather than expected behavior, and outlines what a proper fix might look like - having each message source (`-m`, `-C` etc.) apply its own stripping before concatenation, rather than applying stripping only at the final concatenated result.

This feedback comes as part of a larger 9-part documentation series that has otherwise been well-received, with Hamano having previously reviewed and approved earlier versions. The current exchange highlights how documentation improvements can sometimes uncover deeper implementation issues worth revisiting.
