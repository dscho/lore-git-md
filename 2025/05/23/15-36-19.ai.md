Bugfix for `git send-email` threading behavior when editing the first patch in a series. The patch addresses a specific edge case where shallow threading breaks if (1) `--in-reply-to` is specified and (2) the user edits the first patch before sending. In this scenario, subsequent patches incorrectly thread to the original `--in-reply-to` target rather than the first patch in the series.

The root cause lies in the threading logic checking `$message_num == 1` as one condition to enable threading. When a user edits the first patch, `$message_num` increments, causing this condition to fail. The fix replaces this with a check against `$num_sent == 1`, which properly tracks the first patch sent regardless of edits. The patch also moves the `$num_sent++` increment to before the threading check to ensure proper sequencing.

The change is minimal (2-line diff) and well-explained, with clear analysis of both the bug and solution. The commit message thoroughly documents the edge case conditions and why the new approach works. This appears to be a straightforward improvement to a subtle but real usability issue in email-based patch submission.
