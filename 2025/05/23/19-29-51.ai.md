This is part 5/9 of a documentation patch series improving `--stdin` usage and comment character handling in git-notes. The patch specifically cleans up misleading documentation around whitespace stripping behavior in git-notes options.

The key changes remove redundant mentions of comment line stripping and whitespace cleaning from the `-m`, `-F`, and `-C` option descriptions in git-notes.adoc. The patch correctly notes that whitespace cleaning is the default porcelain behavior and only needs to be mentioned when the default is not used (as with `-C` which implies `--no-stripspace`). It also removes incorrect implications that these options directly handle comment lines, which was a conceptual error from v1 series.

The changes align with the series' goal of accurately documenting implementation behavior, focusing the discussion of whitespace cleaning where it belongs (with the `--[no-]stripspace` options) rather than redundantly repeating it elsewhere. The patch maintains all prior improvements from v1 while further refining the documentation structure.

- Removes 10 lines of redundant/misleading text about comment line stripping
- Documents `-C`'s implicit `--no-stripspace` behavior
- Standardizes on only mentioning stripping behavior where it differs from default
- Follows git-commit(1)'s precedent of keeping cleanup discussion focused
- Maintains cross-references to actual stripping behavior documentation
- Continues the series' pattern of matching docs to implementation
