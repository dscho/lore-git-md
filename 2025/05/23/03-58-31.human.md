This is a feature and bugfix series for `imap-send`, now in its third iteration. The series makes two main improvements: fixing configuration parsing issues that had broken the command, and adding OAuth2.0 authentication support.

The first patch fixes a bug where `cfg->folder` could incorrectly be set to NULL during config parsing, addressing a regression from commit 6d1f198f34. The second patch implements OAuth2.0 support using curl's native API (both standard OAUTHBEARER and Google's XOAUTH2), which represents an architectural shift from the OpenSSL-dependent approach in earlier versions. The third patch cleans up a memory leak in the CRAM-MD5 authentication error path.

The series has evolved through review feedback, with v3 specifically improving commit message wording and fixing a misleading error message about OAuth2.0/OpenSSL requirements. The changes touch configuration parsing, authentication mechanisms, and memory management across three files, with significant documentation updates explaining the new OAuth2.0 support and configuration options.

This appears to be a well-considered series that has incorporated multiple rounds of feedback. The OAuth2.0 implementation in particular looks thorough, supporting both standards-compliant and provider-specific variants while avoiding OpenSSL licensing concerns raised in earlier versions. The fixes to configuration parsing and memory leaks make this a solid maintenance improvement even before considering the new feature.
