Bugfix for potential divide-by-zero in parallel submodule fetching.

This patch fixes a potential divide-by-zero issue in the parallel fetching code for both regular remotes and submodules. The `max_children` parameter (which controls parallel job count) was only checked for negative values, but could also be zero to trigger the same fallback to configured defaults. The fix changes the checks from `max_children < 0` to `max_children <= 0` in two locations within `builtin/fetch.c`.

The issue was discovered by Alex Guo, who notes that zero values could propagate to `opt.process` and later cause division by zero in `pp_collect_finished`. The change is straightforward and appears correct, though the commit message could be more detailed about the exact failure scenario. The patch touches core fetching logic but is a simple bounds check that shouldn't introduce new issues.
