This thread documents a gap in Git's configuration behavior for submodule URLs. Chris Wilson encountered an issue where trying to set a relative URL via `git config submodule.<name>.url` didn't work as expected - the configuration only accepts absolute URLs, treating anything else as a filesystem path. The current documentation doesn't mention this limitation, forcing users to directly modify the `.gitmodules` file when they need relative URLs.

Wilson's patch proposes clarifying this behavior in the git-config documentation to help others avoid similar confusion. He also suggests the possibility of introducing a new configuration option that would properly handle relative URLs, matching the behavior in `.gitmodules`. The issue came up in a real-world CI/CD scenario where this undocumented limitation caused problems, though the current behavior appears intentional rather than buggy.
