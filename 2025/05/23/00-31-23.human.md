**Bugfix discussion regarding test coverage for memory leak fixes**

This email continues the discussion about whether to include a test case specifically targeting memory leak detection in corrupt bitmap loading scenarios. Taylor Blau responds to Lidong Yan's defense of the test patch, acknowledging that while the test's approach is reasonable, there are concerns about its fragility and necessity.

Taylor clarifies that the test helper approach Lidong proposed would need to live in pack-bitmap.c due to struct visibility, suggesting a model similar to existing test-bitmap.c helpers. He distinguishes between the fragile parsing code (which could be improved) and the actual corruption injection (which is fine to keep in shell).

The key point is that while the test serves a valid purpose - verifying leak detection under corruption scenarios when SANITIZE_LEAK is enabled - there's debate about whether this adds meaningful coverage beyond Git's existing universal leak checking infrastructure. Taylor seems open to keeping the test if it's made less fragile, but notes the decision ultimately rests with reviewers. The discussion remains technical and constructive, focused on balancing test value against maintenance cost.
