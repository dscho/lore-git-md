This is a follow-up discussion in the bug report thread about `git show` unnecessarily accessing parent trees in partial clones. Junio C Hamano confirms Bob Bell's observation that `git show -s` (without diff-affecting options) shouldn't need to examine commit trees, even while noting the test case technically corrupts the repository by removing the promisor remote.

The email connects this to prior optimization work by Jeff King (peff) around object access patterns, referencing two past threads about similar issues. Hamano provides additional technical context about how `-s` interacts with diff filtering options, explaining that while `-s` suppresses diff output, it doesn't bypass diff machinery that might still need tree access for certain operations like path filtering.

Key technical details for future reference:
- The problematic behavior occurs with `git show -s --format=%ae` in tree-less clones
- Diff filtering options (`--diff-filter`, pathspecs) may legitimately require tree access
- Related prior work exists in peff's optimizations for similar cases
- The test methodology (removing promisor config) creates an artificial but effective demonstration case

The discussion appears headed toward consensus that this represents a real optimization opportunity, with Hamano's technical analysis suggesting the fix would involve modifying `git show`'s object access patterns to match `git log`'s behavior for metadata-only operations.
