This is the first patch in a v2 series introducing a new `git last-modified` command, which tracks when paths in the repository were last changed. The command works similarly to `git blame` but operates at the tree level rather than line-by-line.

The implementation introduces core functionality in `last-modified.[ch]` with a `builtin/last-modified.c` frontend. Key features include:
- Non-recursive operation by default (`-r` flag for recursion)
- Support for pathspecs and revision ranges
- Proper handling of merge commits and conflict resolutions
- Comprehensive test coverage in `t/t8020-last-modified.sh`

The patch builds on prior work from Jeff King and Ævar Arnfjörð Bjarmason, incorporating feedback from the RFC discussion. The command is marked as experimental in its documentation, allowing for future behavioral refinements. The implementation appears solid with thorough test cases covering basic usage, subdirectory operation, merge scenarios, and edge cases.

This is part of a larger effort that has already addressed naming concerns (settling on "last-modified") and architectural questions through mailing list discussion. The series appears ready for final review, with remaining open items limited to minor documentation polish and potential future enhancements like caching.
