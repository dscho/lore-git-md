Bugfix for `git apply --reverse` mode handling when reversing file deletions. This is the second patch in a v2 series addressing an edge case where executable bits weren't preserved when reversing a patch that deletes an executable file.

The fix modifies `reverse_patches()` in apply.c to properly handle mode bits when reversing deletions (which become creations). The key change is adding `|| p->is_delete` to the mode bit swapping condition, ensuring the executable bit is preserved when recreating deleted files. This builds on commit 01aff0a (2023-12-26) which fixed mode preservation in most cases but missed this deletion scenario.

The patch includes extensive test coverage in t/t4129-apply-samemode.sh, with new test cases that:
- Verify both forward and reverse application of patches that create/modify/delete files
- Cover both executable->non-executable and non-executable->executable transitions
- Test behavior with core.fileMode=false
- Check both working tree and index states
- Validate warning behavior for mode mismatches

Test infrastructure is improved with helper functions `test_file_mode_common()` and refactored checks for staged/HEAD modes. The tests create and verify patch files with specific mode transitions (100644<->100755) and deletion cases.

This version incorporates all feedback from v1, including improved commit messages and test structure. The series appears technically sound with comprehensive test coverage and no outstanding objections from reviewers. The fix is minimal (one-line change) but well-validated, addressing a real gap in mode preservation behavior.
