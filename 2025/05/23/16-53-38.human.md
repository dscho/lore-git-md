This is a platform compatibility discussion about test behavior differences between macOS and Cygwin, emerging from Patrick Steinhardt's Meson test integration series.

Ramsay Jones provides concrete examples showing how the traditional test runner (`prove`) silently accepts unexpected test passes (exit code 0) while Meson's stricter TAP parser surfaces them. He demonstrates this with test 868/1023 (`t7815-grep-binary.sh`), which unexpectedly passes on Cygwin due to BSD-derived regex behavior where '.' matches NUL bytes - behavior now found to also exist on macOS. 

The email reveals this has been happening unnoticed for about a decade in Cygwin builds, masked by the test infrastructure's leniency toward unexpected passes. Jones initially considered deleting the test entirely but opted for a more conservative approach. He raises a philosophical question about whether test runners should fail on unexpected passes, contrasting Meson's behavior with `prove`'s permissiveness.

This discussion goes beyond the immediate technical fix (already handled in the series) to examine deeper test infrastructure design questions. The thread shows the Meson migration is uncovering long-standing platform-specific behaviors that were previously hidden, with all technical aspects now resolved and awaiting integration by Junio Hamano. The exchange highlights how infrastructure changes can surface dormant issues in ways that may influence future test design.
