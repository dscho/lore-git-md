Feature patch adding OAuth2.0 authentication support to `imap-send`, part of a v4 series addressing IMAP configuration and authentication improvements. This patch introduces support for both OAUTHBEARER (RFC 5801/7628) and XOAUTH2 (Google proprietary) authentication mechanisms, completing the series' goal of expanding authentication options beyond CRAM-MD5.

The implementation handles OAuth2.0 via curl's native API when available (using `CURLOPT_XOAUTH2_BEARER`), with fallback paths for OpenSSL users through new helper functions `oauthbearer_base64()` and `xoauth2_base64()`. The patch documents provider-specific requirements, including Gmail's app password workaround and Outlook's XOAUTH2-only restriction. Configuration is updated to reflect the new authmethod options, and credential helper integration is noted.

Key technical details:
- New capabilities `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` added to IMAP protocol handling
- Authentication logic split between curl-native path (preferred) and OpenSSL-compatible base64 encoding
- Documentation covers both protocol standards and major provider quirks (Gmail/Outlook)
- Maintains backward compatibility while adding new methods
- Follows RFC 5801/7628 for OAUTHBEARER's GS2 header and key-value pairs

The patch appears well-integrated with the series' other improvements (configuration fixes, CRAM-MD5 leaks) and addresses prior feedback about architectural approach. No technical objections remain from the review thread.
