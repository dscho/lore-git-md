Git thread summary:

RFC proposal for a new `git-ghost` tool to track context around deleted code lines. The tool would preserve the "why" behind deletions by storing metadata in per-file `.ghost` files, prompting users for explanations during commits. Key features include optional per-repo configuration, integration with the commit flow, and a `git ghost view` command to access the metadata later. The author argues this would aid code reviews and historical understanding, mentioning potential benefits for both human maintainers and AI tools analyzing history. The proposal contrasts with `git notes`, suggesting it wouldn't address the use case as effectively. Currently an RFC with no implementation, seeking feedback on concept and implementation approaches before proceeding. The tool would be implemented as a userland extension requiring no core Git changes.
