[PATCH] git show unnecessarily accesses parent tree in partial clones

Bug report from Bob Bell identifying an optimization gap in `git show --no-patch --format=%ae` when run in tree-less partial clones (`--filter=tree:0`). The command incorrectly attempts to access the parent commit's tree object despite only needing commit metadata (author email), causing a "fatal: unable to read tree" error when the remote is a promisor. This differs from `git log` and `git cat-file` which correctly avoid loading unnecessary objects for metadata-only operations. Reproducible in Git 2.47.2. The issue presents an opportunity to optimize object access patterns in `git show` to match other commands' behavior with partial clones. No proposed fix yet, but clear reproduction steps provided showing the inconsistency between commands. Relevant for users extracting commit metadata from partial clones without fetching full history.
