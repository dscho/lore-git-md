[PATCH] git show unnecessarily accesses parent tree in partial clones

Bug report from Bob Bell identifying an optimization gap in `git show --no-patch --format=%ae` when run in tree-less partial clones (`--filter=tree:0`). The command incorrectly attempts to access the parent commit's tree object despite only needing commit metadata (author email), causing a "fatal: unable to read tree" error when the remote is a promisor. This differs from `git log` and `git cat-file` which correctly avoid loading unnecessary objects for metadata-only operations.

Junio C Hamano confirms the observation while noting the test case technically corrupts the repository by removing the promisor remote. He provides technical context about how `-s` interacts with diff filtering options - while `-s` suppresses diff output, it doesn't bypass diff machinery that might still need tree access for operations like path filtering. The discussion references prior optimization work by Jeff King (peff) around similar object access patterns.

Key technical details:
- Reproducible with `git show -s --format=%ae` in tree-less clones
- Diff filtering options (`--diff-filter`, pathspecs) may legitimately require tree access
- Test methodology (removing promisor config) creates artificial but effective demonstration
- Related to peff's past optimizations for metadata-only operations

Current status: Consensus emerging that this represents a real optimization opportunity, with the fix likely involving modifying `git show`'s object access patterns to match `git log`'s behavior for metadata-only cases. No patch proposed yet but clear technical direction established.
