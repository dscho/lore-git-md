[PATCH] git show unnecessarily accesses parent tree in partial clones

Bug report and discussion about optimization gap in `git show --no-patch --format=%ae` behavior in tree-less partial clones (`--filter=tree:0`). The command incorrectly attempts to access parent commit's tree object when only needing commit metadata (author email), causing "fatal: unable to read tree" errors with promisor repos. Differs from `git log`/`git cat-file` which correctly avoid unnecessary object loads.

Technical consensus confirms this as real optimization opportunity. Key details:
- Reproducible with `git show -s --format=%ae` in tree-less clones
- `-s` suppresses diff output but doesn't bypass diff machinery that may need trees
- Test case deliberately removes promisor config to make unnecessary access fail visibly
- Part of reporter's broader effort to minimize object retrieval at scale
- Related to Jeff King's past optimizations for metadata-only operations

Current status: Reporter Bob Bell agrees with Junio C Hamano's analysis that `git show -s` shouldn't need trees for metadata-only operations without diff options. Discussion winding down with reporter willing to monitor for future fixes rather than push for action. Clear technical direction established to align `git show` behavior with `git log` for these cases. Reporter's corporate context (Outlook constraints, large-scale ops) provided but not blocking resolution.
