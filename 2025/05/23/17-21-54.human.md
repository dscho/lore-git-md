This is a bugfix patch addressing file mode handling in `git apply --reverse` when dealing with executable files. It's the second patch in a v2 series that has already incorporated feedback from reviewers.

The core issue fixes a case where reversing a patch that deletes an executable file would not properly restore the executable bit when recreating the file. The fix is minimal - just a one-line change in `apply.c` that adds `|| p->is_delete` to the mode bit swapping logic. This ensures the mode bits are properly transferred when reversing deletions.

The bulk of the patch consists of comprehensive new test coverage that verifies:
- Both forward and reverse application of patches
- Both executable-to-non-executable and non-executable-to-executable transitions
- Behavior with core.fileMode=false
- Mode preservation across both working tree and index states
- Warning behavior for mode mismatches

The tests are well-structured with helper functions and cover all the edge cases reviewers had requested in the v1 discussion. The commit message clearly explains the problem and solution, referencing the prior commit (01aff0a) that fixed similar mode handling issues but missed this case.

This appears ready for merging - it has thorough test coverage, a clear minimal fix, and has already incorporated all reviewer feedback from the previous version. The patch demonstrates careful attention to both the technical correctness and test completeness.
