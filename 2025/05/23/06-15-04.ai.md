This is a bug report about unnecessary object access in `git show` during partial clones. Bob Bell reports that when using `git show --no-patch --format=%ae` on a commit in a tree-less partial clone (created with `--filter=tree:0`), Git unnecessarily tries to access the parent commit's tree object even though the requested operation (displaying author email) doesn't require it. The command fails with "fatal: unable to read tree" when the remote is configured as a promisor, preventing object fetching.

The report notes this is inconsistent with other commands like `git log` and `git cat-file` which can display the same metadata without requiring the parent tree. The behavior appears in Git 2.47.2 and seems to be an optimization opportunity where `git show` could avoid loading unnecessary objects when only commit metadata is requested. The bug report is well-structured with clear reproduction steps and expected/actual behavior comparison, though it doesn't propose a specific fix. This could be relevant for users working with partial clones who need to extract commit metadata without fetching full history.
