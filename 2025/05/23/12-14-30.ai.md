Bugfix patch completing the `imap-send` authentication series by addressing a memory leak in CRAM-MD5 error handling. This final patch in the v4 series ensures proper cleanup of the `response` buffer when socket writes fail during CRAM-MD5 authentication, closing the last known memory management gap in the authentication subsystem.

The change wraps the error return path with a `free(response)` call when `socket_write()` fails to transmit the full CRAM-MD5 response. This matches the existing cleanup that already freed the buffer on success paths. The fix is minimal (3 lines changed) but critical for preventing memory leaks during authentication failures, particularly important given the security-sensitive nature of authentication code.

This patch follows through on Eric Sunshine's earlier identification of memory management issues in the series. With this change, all authentication methods (CRAM-MD5, PLAIN, and OAuth2 variants) now have comprehensive memory cleanup. The implementation maintains the existing error reporting via `error()` while adding the missing resource cleanup.

- Maintains identical error message when socket writes fail
- Follows pattern established in other auth methods' cleanup
