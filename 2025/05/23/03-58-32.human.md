Bugfix for `imap-send` configuration parsing, part of a larger series adding OAuth2.0 support and fixing memory leaks. This first patch corrects a regression from commit 6d1f198f34 where the wrong variable (`cfg->folder`) was being cleared when processing other IMAP configuration options like `imap.user` and `imap.pass`. The bug made `imap-send` unusable when these settings were defined, though it went unnoticed due to most users preferring `git send-email`.

The fix is straightforward - each configuration option now correctly clears its own field rather than incorrectly clearing the folder field. This was technically approved by Junio Hamano in earlier iterations, with minor commit message improvements suggested. The patch is well-contained, touching only the configuration parsing logic in `imap-send.c` with clear before/after behavior.

This is the foundational fix in a three-part series that goes on to add OAuth2.0 authentication support and fix CRAM-MD5 memory leaks. The thread history shows thorough review from multiple contributors, with this particular patch being technically sound and ready for inclusion.
