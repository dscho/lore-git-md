This thread discusses how to handle path resolution in Git's test suite, particularly when tests are run from directories containing symlinks. The issue originally surfaced in macOS maintenance tests (t7900-maintenance.sh), where `strbuf_realpath()` would resolve paths differently than test expectations.

Mark Mentovai initially proposed fixing this by modifying specific test cases to use `pwd -P` for consistent path resolution. Junio Hamano then suggested a more comprehensive approach - handling path normalization at the test infrastructure level in `test-lib.sh` rather than in individual tests. While Mark expressed concern this might mask some edge cases in Git's path handling, Junio argued infrastructure-level consistency is more important for reliable testing.

The latest patch implements Junio's approach, modifying `test-lib.sh` to normalize both the test directory (`$TRASH_DIRECTORY`) and home directory (`$HOME`) paths after resolving any symlinks via `cd -P`. This change affects all tests that compare paths, not just the original macOS maintenance tests. The implementation is minimal (just two lines) but provides consistent path handling across the entire suite while still allowing dedicated path resolution tests when needed.

The discussion remains technical but productive, with participants converging on an infrastructure solution that maintains test reliability while preserving the ability to test edge cases through other means. The patch appears ready for inclusion, having addressed both the immediate test failures and the broader architectural question of where path normalization should occur.
