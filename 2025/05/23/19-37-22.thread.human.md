This thread examines how Git's test suite should handle path resolution, particularly when tests are run from directories containing symlinks - an issue that surfaced in the macOS and Windows maintenance tests (t7900-maintenance.sh). The discussion has evolved through several technical approaches, revealing a deeper architectural question about test infrastructure design.

Eric Sunshine suggested alternative approaches using `sed` and placeholder paths. Junio Hamano then advocated for handling this at the infrastructure level by canonicalizing paths in test-lib.sh using `cd -P`.

In the latest exchange, Junio defends his infrastructure approach, arguing it provides more consistent test environments across different developer setups. He distinguishes between three concerns: fixing test script bugs, testing Git's path resolution behavior, and maintaining reliable test infrastructure. Mark maintains that Junio's approach might mask real issues in Git's path resolution logic that only appear with non-canonical working directories. The discussion remains collegial but highlights an important tension between test consistency and edge case coverage. Junio's latest response introduces the possibility of specialized path resolution tests as a way to preserve both goals.

The thread shows experienced contributors thoughtfully working through a subtle technical tradeoff that affects both immediate test reliability and long-term maintenance of the test suite.
