This thread addressed test failures caused by path resolution differences when running Git's test suite from directories containing symlinks, particularly affecting macOS and Windows. The core issue was that `strbuf_realpath()` resolved paths differently than the test infrastructure expected, leading to failures in the maintenance tests (t7900-maintenance.sh).

Mark Mentovai proposed a solution to normalize test working directories by using `cd -P` behavior in `t/test-lib.sh`, ensuring consistent path resolution across platforms. The discussion evolved into a nuanced debate about terminology, with proposals like "absolute pathname" being rejected since the paths were already absolute - the key change was symlink resolution. After considering alternatives like "physical path" and "symlink-resolved file path", the thread converged on keeping the original "normalized working directory" commit subject as the least misleading option, while using "physical path" terminology in the documentation.

Junio Hamano has now merged the patch, which makes a minimal (2-line) change with broad impact across the test suite. The solution resolves the immediate test failures while preserving the ability to test Git's internal path resolution behavior. The thread demonstrates the project's careful attention to both technical correctness and precise documentation, even for infrastructure changes.
