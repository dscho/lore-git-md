This thread explored how to handle path resolution in Git's test suite, particularly when tests are invoked from directories containing symlinks. The discussion began with Mark Mentovai identifying macOS test failures in t7900-maintenance.sh due to inconsistent path resolution between `pwd -P` and Git's internal `strbuf_realpath()`. 

After considering several approaches - including Eric Sunshine's path sanitization suggestions - the group converged on Junio Hamano's solution to normalize paths in test-lib.sh using `cd -P`. The technical implementation was straightforward (just 2 lines changed), but the terminology debate proved more nuanced. Torsten Bögershausen advocated for "physical path" to describe symlink-resolved paths, which Junio accepted while noting Git's codebase typically uses "absolute path" elsewhere.

In the final email, Mark provided thoughtful analysis of path terminology, observing that while "physical path" was the agreed term, no single word perfectly captures the symlink-resolution concept without additional explanation. He noted POSIX avoids the term in favor of descriptive language, and that multiple forms of path canonicalization exist beyond symlink handling. The thread concluded with consensus on both the technical solution and documentation approach, resolving the immediate test failures while establishing clearer standards for future path-related test infrastructure work.
