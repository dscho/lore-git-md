This is the first patch in a v2 series implementing the new `git last-modified` command, a feature that tracks when files were last modified in the repository history. The patch introduces the core functionality with:

- New files `last-modified.[ch]` containing the core implementation
- `builtin/last-modified.c` for the command interface
- Documentation in `Documentation/git-last-modified.adoc`
- Comprehensive test coverage in `t/t8020-last-modified.sh`

The command works similarly to `git blame` but tracks modifications at the tree level rather than line-by-line. Key characteristics from this initial implementation:

- Uses a hashmap to track paths of interest
- Walks history backwards to find when each path last changed
- Handles basic cases including:
  - Non-recursive vs recursive (`-r`) operation
  - Subdirectory scoping
  - Revision range limiting
  - Merge commit behavior

The implementation builds on prior work from Jeff King and Ævar Arnfjörð Bjarmason, with this version incorporating feedback from the RFC discussion. The command is marked as EXPERIMENTAL in the documentation, allowing for future behavioral refinements.

Notable technical details for future reference:
- Uses `hashmap` to track paths with `last_modified_entry` structs
- Implements diff callbacks for both initial setup (`add_from_diff`) and traversal (`last_modified_diff`)
- Handles merge cases explicitly in tests
- Output format shows commit hash followed by path (tab-separated)
- Core logic in `last_modified_run()` drives the revision walk

The patch appears technically sound with thorough test coverage, representing the consensus reached in the RFC discussion about command structure and basic behavior. Remaining work (like caching layer integration) is deferred to future patches in the series.
