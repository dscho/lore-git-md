Bob Bell found that running `git show --no-patch --format=%ae` in a tree-less partial clone fails with "fatal: unable to read tree" because it tries to load the parent's tree object, even though displaying the author information doesn't require it. 

This behavior differs from similar commands like `git log` and `git cat-file` which can show the same metadata without fetching unnecessary objects. The issue affects Git 2.47.2 and appears to be a missed optimization opportunity in `git show`'s object access pattern. While the report doesn't propose a specific fix, it clearly demonstrates the problem with reproduction steps and expected/actual behavior comparisons, making it actionable for maintainers. The bug impacts users working with partial clones who need to extract commit metadata without fetching full history.
