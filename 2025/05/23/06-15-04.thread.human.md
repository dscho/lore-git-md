Bob Bell reported that `git show --no-patch --format=%ae` incorrectly tries to access parent tree objects in tree-less partial clones, unlike similar commands like `git log`. Junio C Hamano confirmed this is indeed an unnecessary object access when using `-s` (suppress diff output) without diff-affecting options. He noted that while the test case technically corrupts the repository by removing the promisor remote, it effectively demonstrates the issue.

The discussion connects this to Jeff King's prior optimizations around object access patterns. Hamano clarified that while `-s` suppresses diff output, some diff machinery (like path filtering) may still legitimately need tree access. The core issue appears to be that `git show` doesn't optimize its object access as well as `git log` does for metadata-only operations. This presents a clear optimization opportunity to align `git show`'s behavior with other commands in partial clone scenarios.
