This is part 4 of a 9-patch documentation series improving `--stdin` and comment character handling in git-notes and related commands. The patch focuses specifically on rewriting the `--[no-]stripspace` option documentation in git-notes.adoc to be more accurate and consistent with git-stripspace(1) behavior.

Key changes include:
1. Replacing the original paragraph with a bullet list copied from git-stripspace(1) for clearer presentation of the whitespace cleaning rules
2. Removing incorrect claims about comment line handling (which was mistakenly attributed to this option)
3. Documenting the actual whitespace behaviors: trailing whitespace removal, empty line collapsing, and boundary empty line removal
4. Adding a cross-reference to git-stripspace(1) for detailed behavior
5. Dropping misleading statements about `#` lines being stripped in non-editor cases

The patch corrects a conceptual error from v1 series where comment character handling was incorrectly tied to the stripspace option. The author notes this was misleading since comment line processing is actually controlled by interactivity, not this option. The changes focus purely on documenting the whitespace manipulation behaviors while deferring comment character discussion to a later patch.

Technical details:
- Updates Documentation/git-notes.adoc
- Standardizes on git-stripspace(1) terminology ("multiple consecutive empty lines" vs previous "empty lines other than a single line")
- Documents actual whitespace behaviors without incorrect comment line implications
- Maintains backtick formatting for consistency
- Follows the series' pattern of splitting combined option forms into separate entries

This continues the series' goal of precise documentation by fixing an area where the docs didn't match implementation behavior, while improving readability through bulleted lists. The change is purely documentation with no code impact.
