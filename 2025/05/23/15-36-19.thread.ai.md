Root cause: threading logic uses $message_num == 1 check which fails after editing (increments $message_num). Key technical details: affects perl/git-send-email.pl threading logic when both --in-reply-to is set AND first patch is edited. Batch processing interaction requires solution to handle counter resets mid-series while maintaining clear, maintainable code. Open questions: how to robustly track first-message status across batch boundaries without introducing confusing state management, whether deeper refactoring of message numbering is needed.
