This is a discussion response in the `git-ghost` RFC thread, questioning the need for the proposed tool. Lucas Seiki Oshiro challenges the core premise of Max Rhodin's `git-ghost` proposal by suggesting existing Git functionality (`git log` with appropriate flags) could serve the same purpose of tracking deleted code history. The response argues that commit messages on empty-line changes could already capture the "why" behind deletions, and that `git log` with proper filtering might provide equivalent functionality to the proposed `git ghost view` command.

The email continues the thread's central debate about whether specialized tooling is needed for deleted code context versus leveraging existing Git capabilities. It specifically counters two aspects of the RFC: 1) the claimed uniqueness of capturing deletion rationale, and 2) the proposed viewing functionality. The response implies the solution may be over-engineering for problems that could be addressed through better use of current tools, though it acknowledges `git blame`'s limitations for deleted code analysis.

Key technical pushback includes:
- Equivalence between `git ghost view` and `git log -- <file>`
- Alternative approach using empty-line commits with messages
- Implicit questioning of whether the tool solves a problem not already has adequate solutions

The discussion remains at the conceptual level without addressing implementation details, focusing instead on whether the tool's value proposition justifies its creation. This response represents a skeptical perspective in the ongoing evaluation of whether `git-ghost` offers sufficient differentiation from Git's native capabilities.
