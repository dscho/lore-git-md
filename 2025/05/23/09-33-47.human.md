This is a feature patch series introducing the new `git last-modified` command, which tracks when files were last modified in a repository's history. The series represents a rebranded version of the previously proposed `git blame-tree` command, now using the more accurate "last-modified" terminology that better reflects its functionality.

The 5-patch series implements core functionality in `last-modified.[ch]` and `builtin/last-modified.c` with test coverage in `t/t8020-last-modified.sh` and performance benchmarks in `t/perf/p8020-last-modified.sh`. Key technical components include:

1. A new `last_modified_entry` struct to track paths and their modification commits
2. Bloom filter integration to skip unchanged paths efficiently
3. A priority queue-based algorithm for optimized history traversal
4. Non-recursive behavior by default (requires `-r` flag for recursion)

The implementation appears production-ready with thorough test coverage, including edge cases around merges and pathspec handling. Performance optimizations using Bloom filters and the priority queue algorithm show significant speed improvements, particularly for deep histories with many unchanged paths.

Notable changes from previous iterations:
- Renamed from `blame-tree` to `last-modified` based on mailing list consensus
- Removed `--max-depth` feature for separate consideration
- Excluded caching layer implementation for future work
- Made non-recursive the default behavior
- Fixed memory leaks and removed `the_repository` usage

The series builds on prior work from multiple contributors while maintaining a clean commit history. It represents a mature implementation of path modification tracking that could be useful for various Git analysis tasks. The main open question appears to be finalizing the command name and structure, though "last-modified" seems to have consensus.
