This is a maintainer response in the ongoing Meson test integration thread, addressing philosophical questions about test runner behavior that emerged from the technical implementation work.

Junio Hamano responds to Ramsay Jones' question about whether test runners should fail on unexpected passes (where a test marked as known-broken unexpectedly succeeds). He expresses openness to the idea that both Meson and traditional runners (make/prove) should treat unexpected passes as failures, noting that the current divergence in behavior between build systems is problematic. This moves the discussion beyond the immediate technical fixes (which are now ready for integration) to consider broader test infrastructure design principles.

The exchange highlights how Meson's stricter TAP parsing has revealed long-standing inconsistencies in test handling that were previously masked by the traditional test runners. While the technical aspects of Patrick Steinhardt's series have been fully reviewed and resolved (including platform-specific test output handling and TAP protocol support), this follow-up discussion may influence future test infrastructure decisions regarding how to handle test expectations across different platforms and build systems.
