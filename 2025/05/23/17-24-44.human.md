Junio Hamano responds to Max Rhodin's RFC for `git-ghost` with a practical alternative approach. He suggests that `git blame` run in reverse might serve a similar purpose for understanding deleted code, though acknowledges the inherent difficulty in tracing removed content since you can't directly reference what's no longer present. 

Hamano shares his personal workflow for such cases: checking out old revisions to find when code still existed (potentially using `git bisect`), then working forward from there. This isn't a direct critique of the `git-ghost` proposal, but rather offers an existing technique that addresses part of the same problem space. The response maintains an open tone while questioning whether the proposed tool would meaningfully better than current methods.
