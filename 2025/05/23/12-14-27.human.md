Bugfix for `imap-send` configuration handling that corrects a regression introduced in Git 2.46.0. This is the first patch in a v4 series that expands authentication support while fixing several issues in the IMAP subsystem.

The patch fixes a critical bug where setting any of `imap.user`, `imap.pass`, `imap.tunnel`, or `imap.authmethod` would incorrectly NULL out the `cfg->folder` field. This made `git-imap-send` completely unusable since the 2.46.0 release. The regression originated from commit 6d1f198f34 which introduced memory leak fixes but accidentally cleared the wrong field in several configuration handlers.

The fix is straightforward - each configuration handler now correctly clears its own field rather than incorrectly clearing `cfg->folder`. The change demonstrates good attention to detail by matching each `FREE_AND_NULL` operation with the corresponding struct field being configured.

This appears to be a well-justified fix for a clear regression. The commit message explains both the impact (complete breakage of `imap-send`) and the likely reason it went unnoticed (preference for `git send-email`). As the first patch in a larger series that has seen thorough review, this foundational fix looks solid and merge-worthy.
