This is a performance optimization patch for the new `git last-modified` command, part of the v2 series implementing path modification tracking. The patch simplifies the revision walk initialization by setting `no_walk=1` since the command no longer needs the full revision walk preparation that was previously required.

The key change is moving away from using `rev.pending` to directly processing `rev.commits`, which avoids unnecessary initialization work. This builds on Taylor Blau's earlier work and maintains all the Bloom filter optimizations added in previous patches. The patch also fixes a subtle issue where non-commit inputs would be silently ignored rather than rejected.
