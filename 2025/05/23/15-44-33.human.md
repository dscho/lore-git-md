This is a bugfix for `git send-email`'s threading behavior when editing the first patch in a series. The patch addresses a specific edge case where shallow threading breaks if: (1) `--in-reply-to` is specified, and (2) the user edits the first patch before sending. In this scenario, subsequent patches incorrectly thread to the original `--in-reply-to` target rather than the first patch in the series.

The root cause lies in the threading logic checking `$message_num == 1`, which fails after editing (as editing increments `$message_num`). The fix replaces this with a check for `$num_sent == 1`, which more reliably tracks the first patch being sent, and moves the `$num_sent++` increment before the check. This ensures threading works correctly regardless of whether the first patch was edited.
