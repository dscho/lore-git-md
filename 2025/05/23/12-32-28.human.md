This is an RFC proposal for a new userland tool called `git-ghost` that would preserve the "why" behind deleted lines in code. The tool would hook into commits to stash deleted lines in a `.ghost` file and prompt maintainers for a brief explanation when lines are removed. Users could later view these annotations with `git ghost view <file>` to understand what was deleted and why.

The proposal comes from Max Rhodin, who argues this would help with code review comprehension and make `git blame` more informative. The tool would be optional (repos could opt in or out) and implemented purely in userland without requiring core Git changes. Rhodin mentions this could also benefit AI tools trying to understand code history, though the primary audience appears to be human maintainers.

The email presents this as an early idea seeking feedback, noting that while there are many possible implementations, storing the deleted lines as file-bound information would make the data more accessible than alternatives like `git notes`. The proposal is light on technical details about the actual implementation mechanics but presents a clear problem statement around preserving context for deleted code.
