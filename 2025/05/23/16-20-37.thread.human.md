This thread addresses a potential divide-by-zero bug in Git's parallel fetch operations. The issue occurs when the `max_children` parameter (which controls how many parallel fetches can run) is set to zero, causing a crash in `pp_collect_finished`. The patch fixes this by changing the validation check from `max_children < 0` to `max_children <= 0` in both regular fetch and submodule fetch code paths. When zero is detected, it falls back to the configured parallel jobs value.

The fix is small and focused, touching only the validation logic without modifying the core parallel processing code. While the commit message could be slightly more detailed about the exact failure scenario, the technical content appears correct and the change seems uncontroversial. This appears to be a straightforward, low-risk defensive programming improvement that prevents a real (though likely rare) crash scenario.
