Feature patch adding OAuth2.0 authentication support to `git imap-send`. This is part 2 of a 3-patch series that modernizes IMAP authentication, following earlier fixes for configuration parsing and memory leaks.

The patch implements RFC-compliant OAUTHBEARER and Google's XOAUTH2 authentication methods, with proper handling for major providers like Gmail and Outlook. The implementation uses curl's native OAuth support when available (via `CURLOPT_XOAUTH2_BEARER`), falling back to OpenSSL-based encoding when needed. Documentation is updated with clear examples for both Gmail (which requires app-specific passwords or OAuth) and Outlook (which mandates OAuth).

The technical implementation appears solid, with proper RFC 5801/7628 compliance and careful error handling. The patch includes thorough documentation updates explaining the new authentication methods and provider-specific requirements. This addresses a real need as more email providers move away from password-based authentication.

The series has seen multiple rounds of review addressing licensing concerns (moving from OpenSSL to curl-native implementation) and this version incorporates all prior feedback. No outstanding technical objections remain in the thread.
