This is a feature proposal for a new `git-ghost` tool that would preserve context around deleted code lines. The RFC suggests a system that would:

The proposal introduces a new `git-ghost` command that would track deleted lines in a special `.ghost` file, storing the "why" behind deletions. The tool would hook into the commit process to prompt for explanations when lines are removed, then allow viewing this metadata later via `git ghost view <file>`. The author positions this as particularly useful for code reviews and historical understanding, mentioning potential benefits for both human maintainers and AI tools analyzing code history.

Key technical aspects include:
- Stores deletion metadata in `.ghost` files (per-file tracking)
- Integrates with commit flow to prompt for explanations
- Designed as a userland tool requiring no core Git changes
- Optional per-repo opt-in via configuration
- Mentions `git notes` as an alternative approach but argues it wouldn't solve the problem as effectively

The proposal is currently at RFC stage with no implementation provided. The author appears to be soliciting feedback on both the concept and potential implementation approaches before proceeding further. The suggestion touches on areas of version control metadata, developer workflow, and historical code understanding - areas that have seen various approaches in the past but no standardized solution in Git itself.
