Bugfix patch series addressing file mode handling in `git apply --reverse` when reversing deletions of executable files. This is version 2 of the series, incorporating feedback from the initial review round.

The core issue stems from commit 01aff0a (2023-12-26) which preserved mode bits in most cases but missed the deletion case. When reversing a deletion (which becomes a creation), mode bits were not properly transferred from patch metadata to the new file. The fix modifies `reverse_patches()` in apply.c to swap mode bits during deletion processing by adding `|| p->is_delete` to the mode bit swapping logic.

Key changes in v2:
- Reworded commit messages per Kristoffer Haugsbakk's feedback to use present tense and active voice
- Refactored test structure based on Junio Hamano's suggestions:
  - Split tests into more focused scenarios
  - Added coverage for both executable->non-executable and non-executable->executable transitions
  - Created patch files once at test start rather than regenerating them
- Added a new test specifically verifying the case that commit 01aff0a fixed

The series now contains two patches:
1. A new test verifying `git apply` warns for unexpected mode changes
2. The main fix plus comprehensive test coverage for mode handling in both forward and reverse operations

Test coverage now includes:
- Normal file creation with modes
- Mode changes to existing files
- File deletions and their reversal
- Core.fileMode interaction
- Working tree vs index states
- Both executable and non-executable file cases

The thread shows consensus on the technical approach, with all prior feedback addressed. The test structure improvements make the verification more maintainable while maintaining thorough coverage of the mode bit preservation behavior.
