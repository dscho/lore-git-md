This is a feature patch series introducing the new `git last-modified` command, which tracks path modification history. The series represents a rebased and renamed version of the previously proposed `git blame-tree` functionality, now incorporating feedback and implementation from GitHub's version.

Key changes in v2:
- Renamed from `blame-tree` to `last-modified` following mailing list consensus
- Added comprehensive documentation marking the command as experimental
- Included new test cases and merge behavior tests
- Removed recursive behavior by default (now requires `-r` flag)
- Fixed memory leaks and removed `USE_THE_REPOSITORY_VARIABLE`
- Excluded caching layer and `--max-depth` features for future consideration

Technical implementation:
- Core functionality in `last-modified.[ch]` and `builtin/last-modified.c`
- Uses Bloom filters for performance optimization when available
- Implements priority queue algorithm for efficient traversal
- Handles merge cases and pathspecs carefully
- Includes both functional tests (`t/t8020-last-modified.sh`) and performance benchmarks (`t/perf/p8020-last-modified.sh`)

The series builds on work from multiple contributors including Jeff King (performance), Taylor Blau (Bloom filters), and Derrick Stolee (priority queue). The implementation appears production-ready pending final decisions on command structure and integration approach, with the mailing list discussion currently favoring a standalone command over `git log` integration due to UI complexity concerns.
