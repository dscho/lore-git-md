Bugfix patch series addressing file mode handling in `git apply --reverse` when reversing deletions of executable files. This is version 2 of the series, incorporating feedback from the initial review.

The core issue stems from commit 01aff0a (2023-12-26) which preserved mode bits in most cases but missed handling deletions properly. When reversing a deletion (which becomes a creation), mode bits weren't being transferred from patch metadata to the new file. The fix modifies `reverse_patches()` in apply.c to properly handle mode bits during deletion processing with a one-line change adding `|| p->is_delete` to the mode bit swapping logic.

The series now includes two patches:
1. A new test verifying `git apply` warns about unexpected mode changes
2. The main fix plus expanded test coverage for both forward and reverse operations

Mark Mentovai has addressed all review feedback from Junio Hamano and Kristoffer Haugsbakk, including:
- Rewriting commit messages to use present tense/active voice
- Restructuring tests to be more maintainable
- Adding comprehensive test coverage for both executable and non-executable files
- Isolating test cases rather than chaining scenarios

The tests now verify correct mode handling in both directions (forward apply and reverse apply) through two parallel test sequences (change_x_to_notx and change_notx_to_x) that cover all combinations of mode changes and file operations. The test infrastructure was improved with helper functions to reduce duplication.

This appears to be a well-tested, focused fix for a real bug in a non-trivial edge case of patch application. The thorough test coverage and responsiveness to review feedback suggest this is ready for inclusion.
