Bugfix for `imap-send` configuration parsing that corrects a regression introduced in Git 2.46.0. The patch fixes a critical issue where modifying any of the IMAP settings (`imap.user`, `imap.pass`, `imap.tunnel`, or `imap.authmethod`) would incorrectly NULL out the `cfg->folder` field due to copy-paste errors in the configuration parser. This made `git-imap-send` completely unusable since the folder setting is essential for operation.

The bug originated in commit 6d1f198f34 which attempted to address memory leaks in `imap_server_conf` but introduced this side effect. The patch simply corrects the field being cleared in each case to match the variable being set (e.g. clearing `cfg->user` when processing `imap.user` rather than incorrectly clearing `cfg->folder`).

This is the first patch in a v4 series that expands IMAP authentication support, but stands alone as an urgent fix for the configuration parser regression. The commit message notes the bug went unnoticed likely because most users prefer `git send-email`, but the impact is severe for those relying on `imap-send`. The fix is straightforward and has already been reviewed by Junio Hamano in previous iterations, with no outstanding technical concerns.
