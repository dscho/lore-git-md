This is a documentation patch in a 9-part series improving `--stdin` usage documentation in git-notes and clarifying `core.commentChar` references. It specifically focuses on reworking the `--[no-]stripspace` option documentation.

The patch makes several key improvements to the git-notes documentation:
1. Replaces the original description with a cleaner bullet list format copied from git-stripspace(1), standardizing the description of whitespace handling behavior
2. Removes incorrect information about comment line handling that was misleading (comment lines are actually controlled by interactivity, not this option)
3. Documents the actual whitespace cleaning behavior more precisely, including trailing whitespace removal, empty line collapsing, and newline handling

The changes follow up on feedback from the v1 series, where the author realized the comment character handling documentation was misplaced. This patch is part of a broader effort to improve technical accuracy in the documentation, particularly around how git-notes handles input formatting. The patch maintains all prior improvements while fixing the documentation to match actual behavior.
