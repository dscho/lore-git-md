This is a performance optimization patch for the `git last-modified` command series, specifically addressing revision walk initialization. The change builds on prior work from Taylor Blau and others in the path modification tracking functionality.

The patch removes unnecessary initialization work from `prepare_revision_walk()` by setting the `no_walk` flag, since the command no longer relies on `log_tree_commit()`. This optimization comes with a tradeoff - the revision machinery will now silently ignore non-commit inputs rather than erroring out, as the validation check is skipped. The implementation carefully maintains all other functionality while simplifying the commit processing logic to work directly with `rev.commits` list.

Key technical changes include:
- Added `no_walk = 1` flag to revision setup
- Modified commit processing to use `rev.commits` directly instead of `rev.pending`
- Kept Bloom filter checks and priority queue traversal intact
- Maintained all existing diff callback functionality
- Preserved boundary commit handling via BOTTOM flag checks

The change appears well-contained and builds logically on the series' evolution, though reviewers may want to verify the silent handling of non-commit inputs is acceptable behavior. This completes the performance optimization arc that included Bloom filters and priority queue traversal in earlier patches.
