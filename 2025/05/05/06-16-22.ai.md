This is a bugfix patch for `git send-email` that tightens domain name validation to comply with RFC1035 standards. It's the first in a three-part series that improves `send-email` functionality, with documentation updates following in subsequent patches.

The patch modifies the `valid_fqdn` function in `git-send-email.perl` to enforce stricter domain name validation rules. The current implementation only checks for a dot and excludes `.local` domains on macOS, while the new version adds several RFC1035 requirements: exactly one dot, 1-63 character labels, alphanumeric start/end for each label, and no consecutive dots or hyphens at label edges. The author encountered this when their Ubuntu system generated an invalid "MacBook.." domain that passed Git's validation but caused SMTP failures.

Key technical changes include:
- New regex pattern `^(?!-)[A-Za-z0-9-]{1,63}(?<!-)(\.[A-Za-z0-9-]{1,63})+$`
- Maintains special macOS `.local` handling
- Includes before/after SMTP log output showing the fix working
- Preserves the existing function signature and return behavior

The patch appears well-motivated by a concrete failure case and follows the RFC specification closely. While it lacks automated tests (a noted limitation), the manual testing evidence is thorough, showing both the failure case and successful authentication after the fix. This is the second revision (v2) of the patch, with only minor formatting changes from v1 based on Kristoffer Haugsbakk's feedback. The core technical solution remains unchanged from the initial proposal.
