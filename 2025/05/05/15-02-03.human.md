Bugfix for wildcard pathspec handling in `git add` and `git commit`. This final version of the patch addresses an edge case where Git would incorrectly stop matching files when encountering a literal filename that looks like a wildcard pattern (e.g., a file named `f*`). The fix ensures escaped wildcards (like `f\*`) properly match only the literal filename while unescaped wildcards (like `f*`) continue to glob as expected.

The one-line change in `dir.c` modifies the matching logic to consider whether the pathspec contains actual wildcards before stopping the search. The patch includes extensive test coverage in a new test script `t6137-pathspec-wildcards-literal.sh` that verifies behavior for all major wildcard types (`*`, `?`, `**`) and their escaped variants across both `git add` and `git commit` operations.

Jeff King mentored the solution, and Junio Hamano reviewed the implementation. All technical feedback has been addressed, and the only remaining discussion concerned email formatting (tab spacing was a display issue in some mail clients, not a problem with the patch itself). The changes are self-contained and appear ready for merging.
