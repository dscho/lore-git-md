Technical implementation patch in the Scalar maintenance control series. This first patch of v2 refactors the `register_dir()` function to make maintenance behavior configurable, adding a `maintenance` parameter that controls whether background maintenance is enabled during registration. The change is preparatory for adding `--no-maintenance` flags to several Scalar commands in subsequent patches.

Key technical changes:
- Adds documentation comment clarifying `toggle_maintenance()` behavior (enable/unregister based on boolean input)
- Modifies `register_dir()` to accept a `maintenance` parameter (1=enable, 0=leave unchanged)
- Updates all callers to pass `1` (maintaining current behavior)
- Preserves existing warning/error handling but adjusts messages for new conditional logic

The patch maintains the series' focus on preventing maintenance.lock conflicts while making the maintenance control more flexible.
