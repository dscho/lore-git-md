This is a bugfix patch for `git send-email` that enforces RFC1035-compliant domain name validation. It's the first in a three-part series (v3) that improves `send-email` functionality, with this technical fix followed by documentation enhancements in subsequent patches.

The patch modifies the `valid_fqdn` function in `git-send-email.perl` to properly validate Fully Qualified Domain Names according to RFC1035 standards. The new implementation enforces several key rules that were previously missing: domain labels must be 1-63 characters, start/end with alphanumerics, and not contain consecutive dots. The author encountered this when their system generated an invalid "MacBook.." domain that passed Git's validation but caused SMTP failures, providing concrete debug logs showing both the failure case and successful operation after the fix.

The technical changes are minimal (a regex replacement) but well-motivated by real-world breakage. The patch maintains the existing macOS `.local` special case while adding comprehensive validation. The commit message thoroughly documents the RFC requirements with clear valid/invalid examples and includes before/after SMTP session logs demonstrating the fix in action. While the patch lacks test coverage, the detailed problem description and verification approach make the impact clear. This appears ready for inclusion as part of the larger series.
