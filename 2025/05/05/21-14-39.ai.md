This is a clarification email in the reftable test modernization thread, specifically addressing Git's rename detection behavior.

Junio Hamano responds to Patrick Steinhardt's explanation of Git's --find-renames option, correcting a potential misunderstanding about the numeric interpretation. The discussion stems from earlier build system cleanup work where rename detection thresholds were being considered for reviewing test changes.

Key technical clarification: -M<number> without % is interpreted as a fraction where the number is divided by 10^digits (so -M90 and -M90% are equivalent, both meaning 90% similarity). Junio agrees with Patrick that for reviewing test conversions, one would typically want to *lower* the threshold from the default -M50% to catch more potential renames, not raise it.
