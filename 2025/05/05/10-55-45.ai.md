This is a CI/build system fix addressing test result aggregation in Meson builds. The patch ensures test output files are correctly located by both GitHub Workflows and other CI systems when using Meson as the build system.

The issue stems from differing expectations about test output locations between Make and Meson builds. While some CI jobs explicitly set `TEST_OUTPUT_DIRECTORY`, GitHub Workflows assume tests write to "t/" in the source directory by default. Meson instead writes to the build directory, breaking this assumption. The fix explicitly sets the test output directory during Meson configuration, defaulting to "t/" when not otherwise specified.

The change modifies `ci/run-build-and-tests.sh` to pass `-Dtest_output_directory` to Meson configuration, using the existing environment variable if set or falling back to the source directory's "t/" subdirectory. This matches the behavior expected by GitHub's test result aggregation while maintaining compatibility with other CI systems that set the variable explicitly.

The patch was prompted by a report from Johannes Schindelin about test result aggregation failures in GitHub Actions. Patrick Steinhardt confirms the fix works in his testing and notes the issue wasn't caught earlier because GitLab CI always sets the environment variable. The change is minimal (one line added) and focused specifically on the CI integration issue.
