Thread identity: CI/build system fix addressing test result aggregation in Meson builds, prompted by Johannes Schindelin's report of GitHub Actions failures.

Core problem: Test output files are written to different locations in Make vs Meson builds, breaking GitHub Workflows' assumption that tests write to "t/" in the source directory by default. Meson writes to the build directory instead.

Current status: Patch v1 proposed, with confirmation from Patrick Steinhardt that it resolves the issue in testing. The fix is minimal (one line change to `ci/run-build-and-tests.sh`).

Key technical details: Modifies Meson configuration to pass `-Dtest_output_directory`, using existing `TEST_OUTPUT_DIRECTORY` env var if set, otherwise defaulting to source directory's "t/". Maintains compatibility with CI systems that set the variable while fixing GitHub Workflows integration.

Participant positions: Johannes Schindelin reported the issue. Patrick Steinhardt confirmed the fix works and noted GitLab CI wasn't affected as it always sets the environment variable.

Related work: Part of ongoing Meson build system integration efforts. Build system differences between Make and Meson continue to surface subtle incompatibilities like this one.
