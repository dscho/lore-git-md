Thread identity: CI/build system fix addressing test result aggregation in Meson builds, prompted by Johannes Schindelin's report of GitHub Actions failures.

Core problem: Test output files are written to different locations in Make vs Meson builds, breaking GitHub Workflows' assumption that tests write to "t/" in the source directory by default. Meson writes to the build directory instead.

Current status: Patch v1 confirmed working by both Patrick Steinhardt and Johannes Schindelin, resolving the issue. The one-line change in `ci/run-build-and-tests.sh` modifies Meson configuration to use `TEST_OUTPUT_DIRECTORY` if set, otherwise defaulting to source directory's "t/".

Key technical details: Fix ensures Meson builds match Make behavior for test output location. Maintains compatibility with CI systems that set the environment variable while fixing GitHub Workflows integration where the variable isn't set. No changes needed to the actual test output generation - only the directory specification.

Participant positions: Johannes Schindelin originally reported the issue and now confirms the fix works for their GitHub Actions use case. Patrick Steinhardt had previously verified the solution works in testing. Both agree the minimal change resolves the problem without introducing new issues.

Related work: Part of ongoing Meson build system integration efforts where subtle differences from Make continue to surface. This particular issue specifically addresses test result aggregation in CI systems, particularly GitHub Workflows which made assumptions based on Make build behavior.
