This is a feature patch series for Scalar, adding a `--no-maintenance` option to several commands. The series addresses both implementation fixes and architectural feedback from the previous round.

Derrick Stolee's v2 iteration makes several key improvements:
1. Fixes the `toggle_maintenance()` behavior to properly skip maintenance setup rather than forcibly unregistering it (patch 1)
2. Adds thorough test coverage using `test_subcommand` to verify maintenance behavior (patches 2-3)
3. Extends the feature to `scalar reconfigure` (new patch 4)

The motivation remains unchanged - preventing maintenance.lock conflicts in automated environments where Scalar repositories are pre-configured. The implementation now better matches the documented behavior while maintaining the original goal of making maintenance opt-out rather than opt-in.

The series appears well-tested, with each patch adding corresponding test cases. Stolee has addressed all concrete implementation feedback from Patrick Steinhardt while still considering Junio Hamano's architectural concerns about maintenance control placement. The v2 changes suggest Stolee is leaning toward keeping the centralized `register_dir()` approach but making its behavior more precise.

This remains part of Scalar's ongoing evolution toward being a "batteries included but removable" tool for large repositories. The careful attention to test coverage and edge cases suggests this is production-ready code, though the architectural discussion may continue.
