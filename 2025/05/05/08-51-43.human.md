Refactoring patch in Patrick Steinhardt's series to decompose `git gc` functionality. This is patch 3/7 in v4 of the series that moves worktree pruning logic from `cmd_gc()` into a new standalone `maintenance_task_worktree_prune()` function.

The change extracts the worktree pruning code that was previously inline in `cmd_gc()` into a separate function with the same behavior. This prepares for the introduction of a new "worktree-prune" maintenance task in a subsequent patch. The function maintains the same child process spawning approach used in `git gc` for compatibility.

This is a straightforward mechanical refactoring that follows the pattern used elsewhere in the series to break up `git gc` functionality. The patch keeps the existing config handling for `gc.worktreePruneExpire` and preserves the error handling behavior where failures cause `git gc` to die. The change is part of the final push to fully decompose `git gc` into granular maintenance tasks.
