This is a discussion about the maintenance status of Git's `contrib/` directory and related legacy commands, sparked by earlier reports of `git svn` failures on Windows. Johannes Schindelin responds to Patrick Steinhardt's suggestion about cleaning up unmaintained scripts in `contrib/` by pointing out that `git svn` isn't actually in `contrib/` at all - it's part of the main Git distribution alongside other legacy import tools like `git-cvsserver` and `git-archimport`. 

Schindelin agrees with the general sentiment about cleaning up `contrib/`, noting it contains a mix of well-supported scripts (like Bash completion) and completely unmaintained ones (like `contrib/workdir/`). However, he classifies `git svn` differently - as part of a group of transitional tools from when Git was newer, most of which are now effectively "dust collectors" in the codebase. While he acknowledges `git svn` may be slightly less obsolete than others, the implication is that it shares their general maintenance challenges.

The email continues an important conversation about how Git should handle aging components that were once important for migration but now see little maintenance attention, though it doesn't propose specific solutions beyond acknowledging the problem exists both in `contrib/` and the main codebase.
