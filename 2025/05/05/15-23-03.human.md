Bugfix for `git send-email` domain validation. This is the first patch in a three-part series that improves `git send-email` functionality, now in its third revision.

The patch fixes a real-world issue where `git send-email` was accepting invalid domain names that would later cause SMTP failures. The current validation was too lenient, only checking for a dot and a macOS-specific exception for `.local` domains. The new implementation enforces RFC1035 compliance with stricter checks that:
- Require at least one dot
- Limit labels to 1-63 characters
- Enforce alphanumeric start/end for each label
- Allow only alphanumerics and hyphens within labels

Aditya Garg provides concrete examples of both valid and invalid domains, showing how the old validation would incorrectly accept malformed domains like "MacBook.." (with consecutive dots) that would later fail during SMTP handshake. The patch includes before-and-after SMTP debug logs demonstrating the fix in action - where previously the SMTP server rejected the malformed domain, it now properly accepts a valid `localhost.localdomain`.

The change is minimal (just 3 lines modified in `git-send-email.perl`) but addresses a clear pain point for users. While test coverage would be welcome, the patch appears well-researched with proper RFC reference and real-world validation of the fix. This is a straightforward improvement that makes `git send-email` more robust when validating domain names.
