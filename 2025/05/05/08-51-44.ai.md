Refactoring patch in the `git gc` decomposition series, extracting worktree name retrieval into a reusable helper function. This is patch 4/7 in v4 of Patrick Steinhardt's series to complete the maintenance task decomposition by implementing standalone worktree pruning and rerere GC functionality.

The patch introduces a new public API function `get_worktree_names()` in worktree.h that retrieves the names of all worktree directories from the ".git/worktrees" directory. The implementation replaces direct directory traversal in `prune_worktrees()` with calls to this new helper, maintaining identical behavior while making the code more modular. The function returns 0 on success (including when no worktrees exist) or a negative error code on failure.

Key technical details:
- New `get_worktree_names()` function in worktree.c with corresponding declaration in worktree.h
- Takes a repository pointer and strvec output parameter
- Handles ENOENT case (no worktrees) as non-error
- Replaces manual directory operations in builtin/worktree.c's `prune_worktrees()`
- Preserves existing behavior including error handling
- Follows pattern of extracting reusable components during refactoring

This change is part of the broader effort to extract worktree pruning logic from `git gc` into a maintenance task. The helper function's design remains a discussion point in the thread, with Eric Sunshine questioning whether it warrants being a public API versus using direct directory operations or a more generic helper. The patch itself is a straightforward refactoring that doesn't change behavior but enables the subsequent extraction of the worktree pruning maintenance task.
