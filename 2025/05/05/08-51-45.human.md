Feature patch implementing worktree pruning as a standalone maintenance task, part of the ongoing `git gc` decomposition effort.

This patch introduces a new "worktree-prune" task to `git maintenance`, completing the functionality previously only available through `git gc`. The task prunes stale or broken worktrees, with behavior matching the existing `git worktree prune` command. The implementation includes:

- A new `maintenance_task_worktree_prune()` function that runs the pruning operation
- Configurable auto-execution via `maintenance.worktree-prune.auto`, which can be set to:
  - 0 to disable auto-pruning
  - A positive number to prune when that many stale worktrees exist
  - A negative number to always prune
- Compatibility with the existing `gc.worktreePruneExpire` config for expiration timing
- Comprehensive test coverage verifying the auto-pruning conditions and config handling

The patch is well-structured with thorough documentation and tests. It follows the established pattern of other maintenance tasks and represents the fifth in a series of seven patches to fully decompose `git gc` functionality. The only remaining open question in the thread concerns the design of a helper function introduced in an earlier patch, but that doesn't affect this specific implementation.
