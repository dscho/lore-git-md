This is a contributor housekeeping discussion about the future of unmaintained scripts in Git's `contrib/` directory, sparked by the ongoing `git svn` Windows issues.

Patrick Steinhardt responds to Johannes Schindelin's suggestion to deprecate Windows support for `git svn` by broadening the discussion to question the purpose of `contrib/` more generally. He argues that keeping unmaintained scripts in the official Git repository creates a false impression that they are supported solutions when in reality they often languish without attention.

The email suggests two possible paths forward: either reevaluating whether `contrib/` should exist as part of Git at all, or at least a cleanup to remove scripts that haven't been maintained in years. This comes across as a thoughtful proposal rather than a direct critique, though it clearly stems from frustration with the maintenance burden of features like `git svn`.

The discussion represents a shift from the original bug report about specific Windows issues to a higher-level conversation about Git's maintenance philosophy. While not offering concrete solution for the immediate `git svn` problems, it raises important questions about how the project handles aging or niche functionality.
