This is a feature patch extending the `scalar clone` command with maintenance control, part of an ongoing series about configurable background maintenance in Scalar operations.

The patch adds a `--no-maintenance` flag to `scalar clone`, mirroring the functionality recently added to `scalar register`. The default behavior remains unchanged (enabling maintenance), but users can now opt out, which is particularly useful for VM image preparation where concurrent maintenance could interfere with manual operations. The implementation follows the established pattern from previous patches, passing the maintenance flag through to `register_dir()`.

Technical changes include:
- New `--[no-]maintenance` documentation in scalar.adoc
- Addition of `maintenance` parameter to `cmd_clone()` with default `1`
- Updated usage string showing new flag
- Explicit test case verifying maintenance registration is skipped when `--no-maintenance` is used
- Trace2 verification that `git maintenance unregister` is not called in this case
- Error message standardization ("toggle maintenance" vs previous "turn on")

The patch maintains consistency with the series' architectural approach while expanding scope to cover clone operations. Test coverage appears thorough, checking both the positive case (default behavior) and negative case (--no-maintenance). The implementation cleanly integrates with the refactored `register_dir()` interface from earlier in the series.

This continues the pattern seen in previous patches of the series' core idea (configurable maintenance) being systematically applied across Scalar commands. The clone-specific justification (VM image prep) provides clear motivation for this particular application of the feature.
