This is a bugfix patch for `git send-email` that tightens up domain name validation to match RFC1035 standards. It's the first in a three-part series that improves email sending functionality.

Aditya Garg encountered a real-world issue where `git send-email` would accept invalid domain names like "MacBook.." (with consecutive dots), causing SMTP failures. The current validation only checked for a single dot and had special handling for macOS `.local` domains. The patch introduces proper RFC1035 validation that enforces:
- Exactly one dot between labels
- 1-63 character labels
- Alphanumeric start/end for each label
- No consecutive hyphens or dots

The commit includes clear before/after SMTP logs showing the fix in action - where previously the invalid "MacBook.." domain caused SMTP rejection, the patched version properly falls back to "localhost.localdomain". The implementation maintains the macOS `.local` special case while adding comprehensive validation.

This appears to be a well-motivated change with a clear problem statement and solution. The patch is focused (just 3 lines changed) and includes real-world debugging evidence. While it could potentially benefit from test coverage, the direct SMTP log comparisons provide strong validation of the fix.
