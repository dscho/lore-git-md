Feature patch completing the `git gc` decomposition by adding rerere garbage collection to `git maintenance`.

This is the final patch in Patrick Steinhardt's series to fully replace `git gc` functionality with granular maintenance tasks. It introduces a new "rerere-gc" task that handles garbage collection of the rerere cache (used for recording conflict resolutions), matching the behavior previously only available via `git gc`.

The implementation includes:
- A new `maintenance_task_rerere_gc()` function that runs `git rerere gc`
- Auto-execution logic that triggers when the rr-cache directory exists and has at least one entry (configurable via `maintenance.rerere-gc.auto`)
- Comprehensive test coverage verifying both manual and auto-execution behavior
- Documentation updates explaining the new task and config option

The design represents a simplification from v3's directory entry count heuristic to a basic existence check, addressing prior feedback from Junio Hamano. The patch maintains compatibility with existing rerere functionality while making it available through the maintenance framework.

With this addition, the series now provides complete coverage of all `git gc` functionality through individual maintenance tasks, marking a significant milestone in the multi-year effort to decompose the monolithic gc command. The implementation appears solid with thorough testing, though one open question about a helper function design remains from earlier in the series.
