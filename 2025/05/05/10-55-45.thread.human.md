This thread addresses a CI/build system issue where test results weren't being properly aggregated in GitHub Actions when using Meson builds. The core problem stems from differing assumptions about test output locations between Make (which writes to "t/" in the source directory) and Meson (which writes to the build directory). 

The proposed fix modifies `ci/run-build-and-tests.sh` to explicitly set the test output directory during Meson configuration, defaulting to the source "t/" directory when no other location is specified. This ensures GitHub's test result aggregation continues working while maintaining compatibility with other CI systems that explicitly set the output directory. Johannes Schindelin reported the original issue, and Patrick Steinhardt confirmed the fix works, noting the problem wasn't caught earlier because GitLab CI always sets the environment variable. The change is minimal and focused specifically on resolving the CI integration mismatch.
