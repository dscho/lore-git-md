This is a follow-up discussion in the Windows CI build system thread, now centered on the broader implications of using Release mode in CI builds.

Patrick Steinhardt and Johannes Schindelin are aligning on the v2 patch that changes Meson-based GitHub Actions workflows to build in Release mode on Windows. While the original motivation was to work around test hangs in t7001-mv, the discussion has evolved to recognize this as a systemic improvement that also protects against assertion failures in Git's external dependencies.

Schindelin makes two key points: (1) even if Git removes all its own asserts, external libraries might still trigger them, making Release mode builds necessary, and (2) converting asserts to BUG() calls remains valuable for better error reporting, but is a separate concern from the immediate CI fix. Steinhardt concurs with both points, acknowledging he hadn't considered the external dependency angle.

The exchange shows consensus forming around the CI change as a robust solution that addresses both immediate test stability and broader build reliability concerns on Windows. The discussion remains technical and productive, with both contributors focused on practical improvements while recognizing longer-term goals for error handling.
