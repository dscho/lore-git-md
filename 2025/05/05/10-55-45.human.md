This is a CI/build system fix addressing test result aggregation in Meson-based builds. Patrick Steinhardt reports that some GitHub Workflow jobs fail to collect test results because they expect output in the source directory's "t/" subdirectory, while Meson defaults to writing results in the build directory. The patch ensures consistent behavior by explicitly setting the test output directory in the Meson configuration, defaulting to "t/" when TEST_OUTPUT_DIRECTORY isn't set.

The issue was discovered by Johannes Schindelin in Git for Windows' CI runs, though Patrick notes it didn't surface in GitLab CI where the environment variable is always set. The fix is minimal - a single line addition to ci/run-build-and-tests.sh that passes the output directory to Meson's configuration. The accompanying CI run [2] demonstrates the successful resolution.

This appears to be a straightforward and well-justified fix for a real-world CI problem, with clear evidence of both the issue and the solution's effectiveness. The change is appropriately scoped and maintains compatibility with existing workflows while fixing the Meson case.
