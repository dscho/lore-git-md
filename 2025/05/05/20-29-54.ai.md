This is a review comment on a test improvement in the ongoing patch series about diff context configuration in interactive commands. Eric Sunshine points out a potential cleanup issue in the test cases added by Leon Michalak's patch 1/3. The tests for `diff.context` handling in `git add -p` and other commands currently use `git config` followed by manual `--unset`, which could leave configuration polluted if earlier test steps fail. The suggested fix is to use `test_config` instead, which automatically cleans up after itself regardless of test success or failure. This is a standard testing best practice in Git's test suite. The comment applies to all similar test patterns in the patch, though the quoted excerpt only includes the `git add -p` example. This is a minor but important technical refinement to ensure robust test hygiene.
