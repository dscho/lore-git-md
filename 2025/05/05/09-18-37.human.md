This is a feature patch that makes interactive patch commands respect the `diff.context` and `diff.interHunkContext` configuration settings. It's the first in a 3-part series.

Leon Michalak's patch addresses an inconsistency where commands like `git add -p`, `git commit -p`, and other interactive patch modes weren't honoring the user's configured diff context settings, while regular `diff` and `log` commands did. The changes modify the interactive add/commit infrastructure to read these config values and pass them through to the underlying diff machinery.

The implementation adds new fields to store the context values in the interactive state struct and modifies the diff generation in both `add-interactive.c` and `add-patch.c` to include the context parameters when configured. The patch includes comprehensive tests that verify the behavior across all major interactive commands (`add`, `commit`, `checkout`, `stash`, `restore`).

The change appears well-considered and complete, with clear motivation stated in the commit message and thorough test coverage. This seems like a straightforward quality-of-life improvement that makes Git's behavior more consistent across commands. The patch is small and focused, touching only the necessary parts of the interactive code paths.
