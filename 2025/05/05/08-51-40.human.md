This is the v4 cover letter for a feature patch series completing the decomposition of `git gc` functionality into granular maintenance tasks. Patrick Steinhardt's series implements the final two missing operations - worktree pruning and rerere garbage collection - as standalone tasks with configurable auto-execution thresholds.

The key change in v4 further simplifies the rerere GC auto-condition check. Instead of counting directory entries (v3), it now simply checks for the existence of any entry in the rr-cache directory when the config value is positive. This maintains config consistency while addressing earlier concerns about the value of counting entries. The series has already been approved by Derrick Stolee for merging, with only minor API design questions remaining from Eric Sunshine regarding the `get_worktree_names()` helper.

With these patches, Git now has all technical prerequisites to fully replace `git gc` with finer-grained maintenance tasks, giving users more control over what maintenance operations are performed. The series follows the established pattern of earlier maintenance task decompositions, preserving existing config options while adding new `maintenance.worktree-prune.auto` and `maintenance.rerere-gc.auto` knobs. Test coverage is comprehensive, including edge cases for both tasks.
