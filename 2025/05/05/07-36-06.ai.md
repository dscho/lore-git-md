This is a discussion about the maintenance status of `git svn` and other legacy import tools, expanding the ongoing thread about `contrib/` cleanup. Johannes Schindelin responds to Patrick Steinhardt's suggestion about moving unmaintained scripts out of the repository, clarifying that `git svn` (the original subject of the bug report) is not actually in `contrib/` but rather lives alongside other legacy import commands like `git-cvsserver` and `git-archimport`. 

Schindelin agrees with the general sentiment about cleaning up `contrib/` but notes it contains a mix of well-supported scripts (like Bash completion) and truly unmaintained code (like `contrib/workdir/`). He classifies `git svn` and similar import commands as "dust collectors" - transitional tools from when Git was less dominant, now largely obsolete but still part of core Git rather than `contrib/`. 

The email reinforces the thread's two parallel discussions: (1) the immediate technical issues with `git svn` on Windows, and (2) the broader question of how Git should handle legacy code, whether in `contrib/` or main commands. Schindelin's contribution is to clarify the distinction between `contrib/` scripts (which have varied maintenance levels) and core commands (which include similarly unmaintained import tools), suggesting both areas may need review but as separate concerns.
