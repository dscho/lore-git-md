This is a discussion thread about Git's rename detection thresholds, emerging from a larger thread about reftable test modernization.

Junio Hamano and Patrick Steinhardt are clarifying how Git interprets the `-M`/`--find-renames` option's numeric thresholds. Patrick had previously noted that without a percent sign, the number is interpreted as a fraction (e.g., -M5 becomes 0.5). Junio initially thought -M90 and -M90% would be equivalent, but confirms Patrick's explanation that they are indeed the same (both meaning 90% similarity).

The more interesting point is about the practical use of these thresholds. Junio notes that higher thresholds (like -M90) are actually more restrictive - they require files to be more similar to be considered renames. This means using -M90 would help filter out marginal rename candidates that might be false positives at the default threshold of 50%.

This is a side discussion in what is otherwise a completed series about test modernization. The core technical work appears settled, with this being more of a clarification about Git's diff behavior that came up during review. The exchange serves as a good reminder about how Git's rename detection thresholds work in practice.
