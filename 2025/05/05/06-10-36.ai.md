This is a brief discussion about the `git whatchanged` deprecation implementation, specifically regarding whether to include alternative command suggestions in the deprecation warning.

Patrick Steinhardt initially suggested enhancing the `you_still_use_that()` helper to accept an explanation parameter that would tell users what replacement command to use. Junio Hamano pushed back on this idea, arguing that if users still need education about alternatives, then the deprecation/removal timeline is premature. The deprecation should only proceed when most users have already naturally migrated to the alternative (`git log` in this case).

The exchange demonstrates the careful philosophy behind Git's deprecation process - removal is justified by actual usage patterns rather than just the existence of better alternatives. This aligns with the thread's established principles of usage measurement via forced opt-in and minimal guidance about alternatives. The discussion doesn't propose any code changes, but reinforces the conceptual approach being taken across both the `whatchanged` and `pack-redundant` deprecation tracks.
