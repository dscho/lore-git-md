This thread discusses a bug in Git's handling of `.gitmodules` when submodules are moved and their original paths are reused with the same name. Moritz Lell originally reported that Git silently overwrites the configuration of the moved submodule when a new one is added at the original path, causing data loss during repository reorganizations.

K Jayatheerth has now proposed a fix that would make Git detect such name/path collisions. The solution would either error out (suggesting explicit disambiguation via `--name` or `--force` options) or, when forced, automatically disambiguate by appending the basename (turning "child" into "child.child"). This preserves the original configuration rather than silently overwriting it, addressing the data loss scenario while maintaining backward compatibility through the `--force` option. Jayatheerth notes this is an initial proposal and is open to alternative approaches, with plans to add tests within existing test files. The discussion is now open for feedback on this approach to resolving the submodule collision issue.
