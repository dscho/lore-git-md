This is a refactoring patch in Patrick Steinhardt's series to decompose `git gc` functionality, specifically drawing attention to the new `get_worktree_names()` helper function. Eric Sunshine raises several concerns about its design and necessity.

The function in question provides a simple directory listing of entries in `.git/worktrees/` without any validation of whether they are actually valid worktree directories. Eric argues this offers little value over direct `opendir()`/`readdir()` usage, suggesting either:
1. Callers should implement their own directory reading logic
2. A more generic directory-listing helper should be created if needed

Key technical points in the critique:
- The function makes no guarantees about entry validity (could be files, special files, etc.)
- The "names" terminology in the API is potentially misleading
- The `goto`-based cleanup adds unnecessary cognitive overhead
- The functionality seems too trivial to warrant a dedicated public API

Eric does acknowledge the documentation correctly warns about non-functional worktrees, but sees this as further evidence the function may not belong in the public API. The discussion represents a design review of a helper function in the larger worktree pruning effort, with Eric advocating for either removal or a more generic solution.
