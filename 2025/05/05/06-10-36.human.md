This is a brief discussion in the ongoing `git whatchanged` deprecation thread. Patrick Steinhardt had suggested enhancing the deprecation warning to include information about alternatives, but Junio Hamano pushes back, arguing that if users still need education about alternatives, the command isn't ready for removal yet. The exchange reinforces Junio's principle that deprecation should only happen after widespread migration has already occurred naturally, not as a way to force migration. This aligns with the thread's established approach of measuring actual usage via the `--i-still-use-this` opt-in rather than trying to direct users to alternatives. The discussion doesn't propose any code changes, just clarifies the philosophical approach to deprecation.
