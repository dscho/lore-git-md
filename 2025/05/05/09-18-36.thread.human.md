This thread continues the discussion of a patch series that aims to give users more control over diff context settings in interactive patch commands like `add -p`. The series builds on earlier work that made these commands respect diff.context and diff.interHunkContext configurations.

The latest exchange focuses on design decisions for the interactive UI portion of the work (patch 3/3). Junio Hamano has weighed in on Phillip Wood's proposal for hunk redisplay in `add -p`, explaining technical limitations that make this approach impractical. The discussion clarifies that while `add -i` could support context changes through subcommands, `add -p` lacks the necessary state tracking to dynamically redisplay hunks with modified context settings. This effectively narrows the design options for the final patch.

Earlier in the series, consensus was reached on the command-line interface (patch 2/3), where context overrides (-U/--unified and --inter-hunk-context) will require explicit -i/-p flags rather than implying interactive mode. Leon Michalak is implementing documentation updates to reflect this "opt-in" behavior more clearly.

Key participants include Junio Hamano (maintainer), Phillip Wood (interactive patch expert), and Leon Michalak (implementing contributor). The remaining work involves finalizing the interactive UI approach for `add -i`, completing documentation updates, and ensuring comprehensive test coverage for the new behaviors. The thread demonstrates careful consideration of both user experience and implementation constraints as the feature takes shape.
