This is a feature patch in the ongoing Scalar maintenance control series, specifically adding a `--no-maintenance` flag to `scalar register`. The patch follows up on previous architectural discussions about how to handle maintenance configuration in Scalar commands.

The change modifies `register_dir()` to accept an explicit maintenance parameter (1=enable, 0=leave unchanged) rather than always enabling maintenance. The default behavior remains unchanged (maintenance enabled) for backward compatibility. Documentation is updated to explain the new flag, and tests verify that `--no-maintenance` properly skips maintenance setup without triggering the unregister path.

Key technical details:
- Adds `OPT_BOOL` for `--[no-]maintenance` in `cmd_register()`
- Updates `register_dir()` call to pass through the maintenance flag
- Modifies error message from "turn on" to "toggle" maintenance
- Adds test case verifying no maintenance setup occurs with `--no-maintenance`
- Uses `test_subcommand` to verify absence of maintenance unregister calls

The implementation appears clean and well-tested, with clear documentation of the new behavior. This patch builds on the refactoring from earlier in the series while leaving the higher-level architectural questions (centralized vs per-command control) unresolved but not blocking this specific change.
