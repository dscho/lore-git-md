This is a follow-up discussion about performance optimization in the ongoing platform compatibility thread regarding packed-refs handling.

The email continues the conversation about whether to use `mmap()` instead of reading the entire packed-refs file into memory during fsck operations. Patrick Steinhardt and Jeff King provide concrete data showing that while most packed-refs files are small (<5MB), there are significant outliers (up to 2GB at GitLab.com). Jeff King explains the GitHub fork network case where packed-refs can reach ~1.5GB due to storing refs from thousands of forks.

The discussion confirms that using `mmap()` would be more efficient than the current strbuf approach, especially for these large edge cases. Shejialuo acknowledges the information and indicates they will send a patch to implement this optimization. This represents a separate but related performance improvement to the main BSD errno compatibility fixes being discussed in the thread.
