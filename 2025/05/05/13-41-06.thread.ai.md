Git submodule name/path collision bug report and proposed fix. Original report from Moritz Lell demonstrates data loss when moving a submodule and reusing its original name at the original path, as Git's `.gitmodules` handling uses submodule name as primary key, silently overwriting the original configuration. K Jayatheerth proposes modifying `module_add()` to detect when a submodule name is already associated with a different path, then either failing with an error (suggesting `--name` or `--force` options) or, when forced, auto-disambiguating by appending the basename (e.g. "child" becomes "child.child"). The solution would add validation before `check_submodule_name()`, querying the submodule cache to compare paths, preserving original configurations rather than silently overwriting. Jayatheerth notes this is a starting point and is open to alternatives, planning to use existing test files rather than adding new ones. The proposal focuses on preventing the problematic case while maintaining backward compatibility through a `--force` escape hatch. Open questions include whether the disambiguation strategy (appending basename) is optimal and whether additional UI options would be helpful.
