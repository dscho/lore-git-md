This is the second patch in a 3-part series removing obsolete Visual Studio build system components (CI/build system cleanup). The patch removes support for generating `.vcproj` and `.vcxproj` project files, deleting 7 Perl modules and scripts from `contrib/buildsystems` that were used to generate these project files. The commit message explains this was a "hacky script" that predated CMake support and is no longer needed since CMake is now the preferred way to build Git in Visual Studio.

Key technical details:
- Deletes 1864 lines across 7 files: `Generators.pm`, `Generators/QMake.pm`, `Generators/Vcproj.pm`, `Generators/Vcxproj.pm`, `engine.pl`, `generate`, and `parse.pl`
- The removed code handled generating Visual Studio project files for both older VC++ project formats (vcproj) and newer formats (vcxproj)
- The generator scripts parsed Makefile output to create Visual Studio solutions and projects
- Each deleted file contained logic for different aspects of the build system generation:
  - `Generators/` modules contained the core project generation logic
  - `engine.pl` was the main driver script
  - `generate` was the entry point wrapper
  - `parse.pl` handled Makefile output parsing

The removal is part of a broader cleanup of obsolete build infrastructure, following the first patch which removed CI script symlinks. The changes appear straightforward and non-controversial, focused on removing clearly obsolete code now that CMake provides better Visual Studio integration. The commit message provides clear rationale for the removal, noting the maintenance burden versus limited benefit of keeping the old generator scripts.
