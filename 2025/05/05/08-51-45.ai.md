Feature patch implementing worktree pruning as a standalone maintenance task, part of the ongoing `git gc` decomposition effort.

This patch introduces a new "worktree-prune" maintenance task that handles stale worktree cleanup, functionality previously only available via `git gc`. The implementation follows the established pattern for maintenance tasks, with both manual execution (`git maintenance run --task=worktree-prune`) and auto-execution modes. The auto mode is controlled by a new `maintenance.worktree-prune.auto` config that accepts integer values (negative for always run, zero for never, positive for threshold-based execution).

Key technical components include:
- New `worktree_prune_condition()` function that checks for prunable worktrees using the existing `should_prune_worktree()` logic
- Integration with the existing `gc.worktreePruneExpire` config for expiration threshold compatibility
- Comprehensive test coverage verifying auto-execution behavior with various config values
- Preservation of the child process spawning pattern seen in other maintenance tasks

The implementation builds on the `get_worktree_names()` helper introduced in patch 4/7, though the API design question around that helper remains open per Eric Sunshine's feedback. The patch maintains behavioral parity with `git gc`'s worktree pruning while making it available as a granular maintenance operation.
