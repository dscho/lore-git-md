Scalar feature patch series introducing `--no-maintenance` flag across multiple commands, addressing both implementation fixes and architectural feedback from v1 discussion.

Derrick Stolee's v2 series expands the initial `--no-maintenance` implementation to cover `scalar reconfigure` in addition to `register` and `clone`, while addressing specific technical concerns raised in review. The key changes include:

1. A new patch (1/4) that explicitly separates maintenance behavior in `register_dir()`, fixing the v1 issue where `toggle_maintenance(0)` incorrectly performed active unregistration rather than simply skipping setup. This is verified via new `test_subcommand` checks in t9210/t9211.

2. Extended test coverage validating that existing maintenance configurations remain untouched when using `--no-maintenance`, addressing Patrick Steinhardt's observation from v1 review.

3. The new patch 4/4 adds `--[no-]maintenance` to `scalar reconfigure`, though this appears to sidestep Junio Hamano's architectural concern about `cmd_reconfigure()`'s unconditional maintenance behavior. The cover letter doesn't explicitly acknowledge this tension.

The implementation now properly tracks maintenance state through the call chain while maintaining the original goal of preventing maintenance.lock conflicts in automated environments. Test coverage has been significantly strengthened with trace2 event verification of subcommand behavior.

Notably absent is resolution of the architectural debate about maintenance control placement - the series continues using `register_dir()` for central handling rather than moving to explicit command-level calls as Hamano suggested. The `reconfigure` addition may reignite this discussion, as it represents another case where maintenance toggling happens deeper in the call stack.
