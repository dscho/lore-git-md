This is a v4 feature patch series completing the `git gc` decomposition effort by implementing the final two maintenance tasks (worktree pruning and rerere garbage collection) as standalone operations with configurable auto-execution thresholds.

The series simplifies the rerere GC auto-condition check from v3's directory entry count to a simpler existence check - any positive value for `maintenance.rerere-gc.auto` now triggers GC if the rr-cache directory exists and has at least one entry, while preserving the integer config pattern for consistency. The worktree pruning task maintains compatibility with `gc.worktreePruneExpire` while adding a new `maintenance.worktree-prune.auto` threshold.

Key technical details remain unchanged from v3: both tasks maintain child process spawning for compatibility, include comprehensive test coverage, and follow the established pattern from earlier maintenance task implementations. The series has received explicit approval from Derrick Stolee, with the rerere GC simplification addressing Junio Hamano's concerns about the previous heuristic's value. Eric Sunshine's feedback about the `get_worktree_names()` helper API remains the only open design question.

With these final tasks implemented, the series provides all technical prerequisites for fully replacing `git gc` with granular maintenance operations, though the actual deprecation timeline remains future work. The implementation is now focused on the simplest possible conditions that maintain behavioral parity while enabling configurable auto-execution.
