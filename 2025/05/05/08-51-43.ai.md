Refactoring patch in the `git gc` decomposition series. This is the third patch in v4 of Patrick Steinhardt's series to complete the replacement of `git gc` functionality by moving worktree pruning into a standalone maintenance task.

The patch extracts the worktree pruning logic from `cmd_gc()` into a new `maintenance_task_worktree_prune()` function, following the pattern established for other maintenance tasks. The new function takes the existing `gc_config` struct to access the `prune_worktrees_expire` setting and spawns the same `git worktree prune --expire` child process as before. The behavior remains identical - the change is purely structural to prepare for the subsequent introduction of the worktree-prune maintenance task.

This continues the series' approach of incrementally refactoring `gc.c` to extract functionality while maintaining compatibility. The patch preserves the existing error handling where failures in worktree pruning will terminate the gc operation with an error message. The diff shows the straightforward movement of code with minimal changes beyond the function extraction.

The change is part of the larger effort to make all `git gc` operations available as configurable maintenance tasks, with this patch specifically enabling worktree pruning to be run independently through the maintenance framework while keeping the same behavior when invoked via `git gc`.
