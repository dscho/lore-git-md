Bugfix addressing the confirmed heap-use-after-free in rebase's reflog handling. Jeff King (Peff) responds to Kristoffer Haugsbakk's successful reproduction of the issue using address and undefined behavior sanitizers, which showed the problem occurs when `ctx->reflog_message` holds a stale pointer to freed memory from a strbuf reallocation during complex rebase operations.

Peff provides a reliable way to trigger the bug by forcing strbuf reallocation in `reflog_message()`, confirming it appears in existing tests. He proposes two potential fixes: a minimal solution where `ctx->reflog_message` owns its memory (shown in the patch), or a broader refactoring of `reflog_message()`'s memory ownership pattern which he considers an anti-pattern. The provided patch implements the smaller approach, making `reflog_message` a char* that must be freed and updating all callers to duplicate the string.

The patch appears thorough, covering all code paths that set `reflog_message` in sequencer.c, including `pick_one_commit()`, `pick_commits()`, `sequencer_continue()`, and `single_pick()`. It adds proper cleanup in `replay_ctx_release()` and handles memory management at each assignment point. While untested beyond basic verification with t3430, the approach looks sound and addresses the root cause identified in the thread.
