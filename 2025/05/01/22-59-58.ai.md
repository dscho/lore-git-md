This is the second patch in a 2-part series introducing a standardized deprecation mechanism for Git commands, demonstrated by deprecating `git whatchanged`. The patch applies the new deprecation infrastructure (introduced in patch 1/2) to mark `git whatchanged` as deprecated, requiring users to pass `--i-still-use-this` to continue using it.

The changes include:
- Adding the deprecation warning and flag handling in builtin/log.c using the shared `you_still_use_that()` helper
- Updating git-whatchanged.adoc with a WARNING section and new `[synopsis]` markup
- Modifying tests in t4013-diff-various.sh to use the flag and verify the warning appears without it
- Updating t4202-log.sh to consistently use the flag
- Replacing `whatchanged` with `log --raw` in t9300-fast-import.sh and t9301-fast-import-notes.sh where output wasn't being checked

The patch maintains the historical rationale that `whatchanged` is kept for users who haven't transitioned to `git log --raw`, while establishing a clear deprecation path. The test changes demonstrate both enforcement of the deprecation warning and migration to the preferred alternative. The approach follows the series' template of warning + documentation + test updates before eventual removal.
