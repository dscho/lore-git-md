Bugfix proposal for reflog corruption during rebase merges. Phillip Wood responds to Jeff King's proposed fix for the heap-use-after-free issue in `git rebase --rebase-merges` that was causing uninitialized memory to appear in reflog entries. While agreeing with Jeff's diagnosis, Phillip suggests an alternative approach that would eliminate the problematic static buffer entirely by converting `ctx->reflog_message` to an `strbuf` and modifying `reflog_message()` to write directly into it.

The key difference is architectural: Phillip's approach would remove the need for callers to manage string duplication by having the reflog message buffer owned directly by the context structure. This would prevent similar issues in the future by making the memory management more straightforward. Phillip notes he'll work on a proper patch implementing this approach, which would require updating all call sites to use the strbuf's buffer rather than the function's return value.
