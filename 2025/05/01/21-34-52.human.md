This is the second patch in a series introducing a standardized deprecation mechanism for Git commands, now applying it to `git whatchanged`. The patch marks `whatchanged` as deprecated, requiring users to pass `--i-still-use-this` to continue using it, following the pattern established in the first patch for `git pack-redundant`.

The changes include:
- Adding a prominent warning to the `git-whatchanged` documentation noting its deprecation and equivalence to `git log --raw`
- Implementing the deprecation check in `builtin/log.c` using the new `you_still_use_that()` helper
- Updating tests in t4013-diff-various.sh to handle the new requirement
- Preserving the command's functionality when the opt-in flag is provided

The commit message notes this is being done to test whether users still rely on this historical command (which has long been documented as equivalent to `git log --raw`). The patch appears well-executed, with thorough test coverage and clear documentation updates. This completes the series' goal of establishing a reusable deprecation pattern in Git's infrastructure.
