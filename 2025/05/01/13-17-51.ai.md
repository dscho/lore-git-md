Bugfix addressing the confirmed heap-use-after-free in `git rebase --rebase-merges` reflog handling. Jeff King builds on Kristoffer Haugsbakk's sanitizer-confirmed diagnosis of the issue, where `ctx->reflog_message` holds a stale pointer to freed memory after strbuf reallocation during merge operations.

The proposed fix changes the `reflog_message` field in `struct replay_ctx` from `const char*` to `char*` to properly track ownership, adding explicit memory management with `xstrdup()` and `free()`. Key changes include: modifying `reflog_message()` to allow ownership transfer, updating all call sites to duplicate strings before storage, and ensuring proper cleanup in `replay_ctx_release()`. A test case in t3430 demonstrates the issue reliably when forcing strbuf reallocation.

The solution addresses the root cause while maintaining the existing behavior - the sequencer now properly manages the lifetime of reflog message strings through rebase operations involving merges. Jeff suggests this as a minimal fix but notes the broader anti-pattern of returning static strbuf contents, leaving the door open for more comprehensive refactoring. The patch appears complete with all necessary call site updates and memory management, though it awaits testing confirmation from Kristoffer or Phillip Wood.
