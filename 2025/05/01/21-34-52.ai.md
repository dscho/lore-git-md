This is the second patch in a series introducing a standardized deprecation mechanism for Git commands, applying it to `git whatchanged`. The patch follows the pattern established in the first patch (which refactored the `pack-redundant` deprecation into reusable infrastructure).

The patch marks `git whatchanged` as deprecated, requiring users to pass `--i-still-use-this` to invoke it. Key technical changes include:
- Adding the deprecation warning and opt-in flag handling to `builtin/log.c`
- Updating the documentation with a WARNING section explaining the deprecation
- Modifying `t/t4013-diff-various.sh` tests to use the new flag and adding a new test verifying the deprecation warning appears
- Using the new `[synopsis]` markup in docs

The commit message notes this command has been kept historically for users who couldn't retrain from `whatchanged` to `git log --raw`, and the deprecation serves to gauge current usage. The implementation reuses the `you_still_use_that()` helper from the first patch, maintaining consistency with the `pack-redundant` deprecation approach.

This completes the series' goal of establishing a standard deprecation path where:
1. Commands show warnings and require explicit opt-in
2. Documentation clearly states deprecation status
3. Tests verify the warning behavior
4. Users are implicitly encouraged to notify the list if they still need the command

The changeset touches documentation, command plumbing, and test files, with careful attention to maintain existing behavior while adding the deprecation layer. The approach suggests this may become Git's standard template for future command deprecations.
