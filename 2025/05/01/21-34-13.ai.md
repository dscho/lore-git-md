Documentation patch continuing the standardization of option formatting in Git man pages. This is the third in Junio C Hamano's 4-part series, applying the same transformations to `git-daemon` documentation that were previously applied to verification commands and `git var`/`git write-tree`.

The patch makes three mechanical changes to `git-daemon.adoc`: converting the SYNOPSIS section from [verse] to [synopsis] format, backquoting all option names (like `--base-path=<path>`), and splitting the `--[no-]informative-errors` option into separate `--informative-errors` and `--no-informative-errors` entries for better grepability. The changes are purely presentational, following the pattern established in Jean-Noël Avila's earlier work on standardizing documentation formatting.

The diff shows extensive but straightforward changes throughout the OPTIONS section, with every option name now properly backquoted and cross-option references updated to match (e.g. changing "--base-path is enabled" to "`--base-path` is enabled"). The `--[no-]informative-errors` split is the only semantic-adjacent change, but it maintains the same functionality while improving documentation usability.

This continues the series' consistent application of documentation conventions with no surprises. The changes are mechanical and unlikely to be controversial, following the same uncontested pattern as the previous patches in the series.
