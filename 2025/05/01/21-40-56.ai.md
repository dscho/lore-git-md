This is part 2 of Junio Hamano's 3-part series introducing a general mechanism for optional file specifications in Git configuration. The patch focuses on implementing support for `:(optional)` prefixes in pathname-type config variables.

The core change modifies `config.c` to recognize the `:(optional)` prefix when processing pathname configurations. When this prefix is present and the specified file is missing or empty, Git will silently treat the configuration as if it wasn't set, rather than erroring out. The implementation includes proper memory management (freeing paths when they're optional and missing) and maintains existing error behavior for non-optional paths.

Documentation is updated to explain the new syntax in `Documentation/config.txt`, and a new test case in `t7500-commit-template-squash-signoff.sh` verifies the behavior with an optional commit template file. The test shows that `git commit` proceeds normally when an optional template file is missing, unlike the current behavior which would error out.

This builds on the preparatory test changes from part 1 and provides the config-file-specific implementation of the general optional-files mechanism. The solution is designed to be reusable across various Git commands that accept file paths in their configuration, with the immediate motivation coming from the `.git-blame-ignore-revs` use case discussed in the thread. The implementation is careful to maintain backward compatibility while adding the new optional-file functionality.
