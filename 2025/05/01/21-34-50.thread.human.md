This thread introduces a standardized mechanism for deprecating Git commands, demonstrated through a 2-patch series that first refactors the existing `pack-redundant` deprecation into reusable infrastructure, then applies it to `git whatchanged`. The approach requires users of deprecated commands to pass `--i-still-use-this` to invoke them, while showing warnings that encourage mailing list feedback from active users.

The first patch moved the deprecation logic from `pack-redundant.c` into a new `you_still_use_that()` helper in `usage.c`, establishing the pattern. The just-received second patch applies this to `git whatchanged`, updating its implementation in `builtin/log.c`, adding documentation warnings, and modifying tests in `t4013-diff-various.sh`. The changes maintain existing behavior while adding the deprecation layer, with careful attention to consistent messaging and test coverage.

The series frames these deprecations as a way to gauge real-world usage rather than immediate removals, noting `whatchanged` has been kept historically for users who hadn't transitioned to `git log --raw`. The work suggests this may become Git's standard template for future command deprecations, with its reusable infrastructure, documentation updates, and test verification of warning behavior. No reviewers have commented on the approach yet, but the careful separation of infrastructure from specific deprecations and the reuse of an established pattern (from `pack-redundant`) suggests a well-considered proposal.
