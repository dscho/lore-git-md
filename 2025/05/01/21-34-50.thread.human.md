This thread documents Git's systematic approach to command deprecation through two case studies: `git whatchanged` (now an 11-patch series) and `git pack-redundant` (1 patch). The work establishes reusable deprecation infrastructure while maintaining distinct implementation paths for each command.

The `whatchanged` track has progressed through its full deprecation lifecycle - from initial warnings to opt-in requirements (`--i-still-use-this` flag), build-time controls (`WITH_BREAKING_CHANGES`), and now final documentation including a BreakingChanges.adoc entry. The `pack-redundant` track remains in the warning phase but shares the core infrastructure. Key contributors have debated whether to include alternative command suggestions in warnings, with Junio Hamano maintaining that deprecation should only proceed when most users have already naturally migrated (to `git log` in this case), rather than needing explicit guidance. This exchange reinforces the project's philosophy of measuring actual usage patterns before removal.

The implementation spans core infrastructure in usage.c, command-specific changes in builtin/log.c, documentation updates across 9 files, and test modifications in 6 test suites. Both tracks demonstrate the infrastructure's flexibility while following Junio's principles of usage measurement, minimal alternative guidance, and cautious removal with compilation guardrails.
