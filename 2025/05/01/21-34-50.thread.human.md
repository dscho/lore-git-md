This thread has documented the systematic deprecation and removal of `git whatchanged`, establishing a reusable pattern for handling obsolete Git commands. The effort was led by Patrick Steinhardt with reviews from Elijah Newren and Junio Hamano, demonstrating the project's approach to managing breaking changes.

The work proceeded through several phases: first modernizing tests to use `git log --raw` instead of `whatchanged`, then requiring an explicit `--i-still-use-this` opt-in flag, and finally removing the command entirely (behind a `WITH_BREAKING_CHANGES` compile-time guard). The just-added documentation update completes this process by officially listing `whatchanged` in the BreakingChanges document and updating its man page with a clear deprecation notice. The rationale notes the command had been effectively obsolete for over a decade, with no user pushback during the opt-in phase.

A parallel effort applied the same deprecation infrastructure to `git pack-redundant`, which remains in the warning phase. Both cases share core components like the centralized warning helper in usage.c, while demonstrating the framework's flexibility to handle different deprecation timelines. The work touched 19 documentation files and 10 test suites, with careful attention to maintaining functionality throughout the transition.
