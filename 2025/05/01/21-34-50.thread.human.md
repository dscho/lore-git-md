This thread discusses a new standardized approach to deprecating Git commands, demonstrated by deprecating `git whatchanged`. The initial two-part series establishes core infrastructure for deprecation warnings, moving shared logic into a `you_still_use_that()` helper function and applying it to `git whatchanged` with appropriate documentation and test updates.

Patrick Steinhardt raised an important process question about whether deprecation warnings should be accompanied by immediate breaking change notices, highlighting two possible interpretations of the approach. In a follow-up discussion, Steinhardt suggested enhancing the deprecation warnings to explicitly mention the replacement command (`git log --raw` in this case), making the warnings more actionable for users. He also clarified why the implementation places the `i_still_use_this` flag in `struct log_config` rather than locally.

The discussion is refining the deprecation template to include both warning infrastructure and clear migration guidance. While the technical implementation is progressing, the broader question about when to document breaking changes remains open. The series appears to be establishing a pattern where commands first show warnings before potential removal, with the current focus being on making those warnings as helpful as possible by including alternative commands.
