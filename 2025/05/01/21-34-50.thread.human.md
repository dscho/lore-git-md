This thread documents Git's systematic approach to command deprecation through two parallel efforts: the now-completed removal of `git whatchanged` and the ongoing deprecation of `git pack-redundant`. The work establishes reusable infrastructure for measuring usage and phasing out commands while maintaining backward compatibility.

The `whatchanged` deprecation is fully implemented, with all documentation updated (including BreakingChanges.adoc and man pages), tests converted to use `git log --raw` instead, and build system integration complete. The final iteration incorporated feedback from Elijah Newren on commit message phrasing and Junio Hamano's confirmation of documentation formatting.

The `pack-redundant` work is now sharing this infrastructure, with a new patch that extracts the warning logic into a reusable `you_still_use_that()` helper function. This maintains identical warning behavior while centralizing the deprecation mechanism. The change follows the established pattern of requiring `--i-still-use-this` opt-in and includes new test coverage.

Key participants Patrick Steinhardt, Junio Hamano, and Elijah Newren have aligned on the deprecation methodology throughout the thread, focusing on usage measurement via forced opt-in, consistent warning messages, and thorough test coverage. The work demonstrates how commands can be systematically deprecated while giving users clear migration paths.
