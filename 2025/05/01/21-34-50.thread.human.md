This thread introduces a standardized mechanism for deprecating Git commands, demonstrated by applying it to `git whatchanged`. The work builds on the existing deprecation pattern used for `pack-redundant`, generalizing it into reusable infrastructure.

The first patch refactors the deprecation logic into a shared `you_still_use_that()` helper in usage.c, moving warning/die behavior from individual commands to core code. It establishes the pattern of requiring `--i-still-use-this` for deprecated commands and includes thorough test verification.

The second patch applies this to `git whatchanged`, adding the warning in builtin/log.c and updating documentation with clear deprecation notices. Tests are updated to either use the new flag or migrate to the preferred alternative (`git log --raw`). The changes maintain backward compatibility while signaling the deprecation path.

The series establishes a complete template for future command deprecations, covering warning behavior, documentation, test updates, and gradual migration. While no reviewers have commented yet, the work appears well-structured as maintenance preparation rather than immediate removal. The approach suggests this may become Git's standard deprecation path going forward.
