Documentation patch continuing the standardization of Git man page formatting. This is the second in Junio C Hamano's 4-part series to align documentation with newer conventions established by Jean-Noël Avila's earlier work.

The patch updates the man pages for `git var` and `git write-tree` with two consistent changes: converting SYNOPSIS sections from [verse] to [synopsis] format, and wrapping all option names in backticks for uniform presentation. The changes are purely presentational, with no behavioral impact.

For `git var`, this means the -l option now appears as `-l` in the OPTIONS section. The `git write-tree` update is more extensive, converting both its options (`--missing-ok` and `--prefix=<prefix>/`) to backtick format while also updating several command references in the DESCRIPTION section to use consistent backtick-wrapping.

The patch follows the same pattern demonstrated in the first patch of the series (which covered verification commands) and appears mechanically sound. As with the rest of the series, these changes are non-controversial documentation improvements that make the man pages more consistent and grep-friendly. The only outstanding work noted in the thread is for git-worktree changes, which Junio flagged as needing more attention in a later patch.
