This is the first patch in a 2-part series introducing a general deprecation mechanism for Git commands. The patch refactors the existing deprecation warning from `git pack-redundant` into a reusable helper function in usage.c.

The key changes are:
1. Moves the deprecation warning and die() logic from pack-redundant.c to a new `you_still_use_that()` function in usage.c
2. Adds the function declaration to git-compat-util.h
3. Includes a new test in t5323-pack-redundant.sh to verify the deprecation warning appears when running without the required `--i-still-use-this` flag

The patch maintains the same behavior as before - commands marked for deprecation will show a warning and refuse to run unless the opt-in flag is provided. The message encourages users to notify the mailing list if they still use the command. This establishes a standardized pattern that can be applied to other commands in future, starting with `git whatchanged` in the next patch.

The changes touch core infrastructure (usage.c), command plumbing (pack-redundant.c), and test files. The implementation looks clean and follows the established pattern from pack-redundant, suggesting this will become Git's standard deprecation path for commands. The test addition helps ensure the deprecation mechanism works as intended.
