This is the second patch in a series introducing a standardized deprecation mechanism for Git commands, here applied to `git whatchanged`. The patch marks `whatchanged` as deprecated, requiring users to pass `--i-still-use-this` to continue using it, while updating documentation and tests accordingly.

Junio notes two additional test adjustments needed beyond what's in the patch: t4202-log needs the new flag since it actually checks `whatchanged` output, while t9300-fast-import could just switch to `log --raw` since it discards the output anyway. He also clarifies this isn't yet ready for the 3.0 breaking changes document since the deprecation mechanism is still new.

The patch follows the pattern established in the first patch of the series, moving Git toward a consistent deprecation workflow where commands first warn users before eventual removal. For `whatchanged`, this serves as both a deprecation notice and a way to survey remaining users who haven't switched to `git log --raw`. The implementation looks thorough, updating docs, tests, and command behavior while maintaining backward compatibility through the opt-in flag.
