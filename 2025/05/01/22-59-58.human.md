This is the second patch in a 2-part series introducing a standardized deprecation mechanism for Git commands, demonstrated by deprecating `git whatchanged`. The patch applies the new deprecation infrastructure (introduced in patch 1/2) to mark `git whatchanged` as obsolete, requiring users to pass `--i-still-use-this` to continue using it.

The changes include:
- Adding a warning section to git-whatchanged.adoc explaining the deprecation
- Modifying builtin/log.c to require the opt-in flag and show the warning
- Updating test scripts to either use the new flag or replace `whatchanged` with `log --raw` where the output wasn't being checked
- Adding a new test to verify the warning appears when the flag is omitted

The patch maintains `whatchanged` functionality for existing users while encouraging migration to `git log --raw`. The author notes that some test script changes merely replace `whatchanged` with `log --raw` in places where the output wasn't being verified, suggesting these calls could potentially be removed entirely in future cleanup.

This appears to be a well-executed application of the new deprecation framework, with thorough test coverage and documentation updates. The approach follows Git's conservative deprecation policy while providing a migration path for users. The series as a whole establishes a clear pattern for future command deprecations.
