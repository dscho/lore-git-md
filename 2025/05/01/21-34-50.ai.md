This is a cover letter for a 2-patch series proposing the deprecation of `git whatchanged`. The series is part of long-term maintenance work, potentially leading to future removal of the command.

The first patch extracts the deprecation warning infrastructure from `git pack-redundant` into a reusable helper that can be used to mark other commands for removal. This creates a standardized way to warn users about deprecated commands while requiring an explicit `--i-still-use-this` flag to proceed. The implementation moves code from pack-redundant.c to usage.c and adds tests.

The second patch applies this new deprecation mechanism to `git whatchanged`, adding the warning message and requiring the opt-in flag. The documentation is updated to reflect this deprecation status. The change is tested in t4013-diff-various.sh to verify the warning appears and the command fails without the opt-in flag.

The series is positioned as preparatory work that doesn't yet commit to removing `whatchanged` from Git 3.0, but makes it easier to do so in the future if desired. The approach follows the pattern already established with `pack-redundant`, suggesting this may become a standard deprecation path for other commands. The changes touch core command plumbing, documentation, and test infrastructure.
