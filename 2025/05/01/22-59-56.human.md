This is a cover letter for a 2-patch series that continues the work to establish a standardized deprecation mechanism for Git commands, now applying it to `git whatchanged`. The series builds on previous work that created a reusable helper for command deprecation, originally demonstrated with `git pack-redundant`.

The first patch refactors the deprecation warning infrastructure into a shared `you_still_use_that()` helper function, moving the logic from `pack-redundant.c` to `usage.c` where it can be reused. The second patch then applies this mechanism to `git whatchanged`, adding the deprecation warning and requiring the `--i-still-use-this` flag, while also updating documentation and tests.

Junio notes this is preparatory work and not yet targeting Git 3.0's breaking changes list. The v2 iteration includes test adjustments identified after the first version - tests that validate `whatchanged` output now use the required flag, while tests that incidentally used `whatchanged` have been updated to use `git log --raw` instead. The changes appear mechanical and focused, with the author noting some test cleanups that could be done separately.

The series represents a thoughtful approach to command deprecation, establishing clear patterns for warnings, documentation, and test updates. While focused on `whatchanged`, the infrastructure changes suggest this may become Git's standard deprecation path.
