This is a preparatory patch series for potential future removal of the `git whatchanged` command, part of ongoing deprecation efforts. Junio Hamano proposes two changes that don't immediately remove anything, but lay groundwork for future deprecations.

The first patch extracts the deprecation warning mechanism from `git pack-redundant` into a shared helper function. This creates reusable infrastructure for marking commands as deprecated, requiring users to explicitly opt-in with `--i-still-use-this` if they want to continue using them. The second patch then applies this mechanism to `git whatchanged`, though it's worth noting this doesn't yet add it to Git 3.0's official removal list.

The changes touch several areas including command implementations, documentation, and tests. The approach appears well-considered, building on prior work with `pack-redundant`'s deprecation while making the mechanism more maintainable. The patch series seems uncontroversial as it doesn't actually remove functionality yet, just makes the deprecation process more systematic. Busy readers can probably skip this unless they have strong opinions about `whatchanged`'s future.
