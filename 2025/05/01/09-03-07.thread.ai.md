Thread summary:

This thread addresses a serious bug in `git apply --intent-to-add` (`-N`) where the command incorrectly clobbers the entire index contents, marking tracked files as deleted. The issue was originally reported by Johannes Altmanninger in 2021 with a v3 patch series proposing to make `--intent-to-add` imply `--index`, though this approach was questioned by Junio Hamano due to potential conflicts with other index-modifying options like `--cached` and `--3way`. Recent discussion was reignited by Jason Cho's inquiry and Ryan Hodges' concrete demonstration of the destructive behavior.

Raymond Pasco's analysis has progressed in two phases: first confirming the technical details of the original bug (where `--intent-to-add` incorrectly replaces the full index despite being designed for worktree-only changes), and now identifying a new edge case where the command incorrectly processes non-new-file changes even when `ita_only` is enabled. This means the fix requires both documentation updates about mutual exclusivity with `--index`/`--cached` and logic adjustments to properly handle partial diffs.

Key technical points:
- Three apply modes exist (worktree-only, index+worktree, index-only)
- Current implementation violates the principle that `--intent-to-add` should only affect new files
- The bug causes real workflow breakage between apply/diff/commit operations
- New discovery: even with the original fix, the command incorrectly processes non-new-file changes

Participants:
- Altmanninger: Original 2021 patch author
- Hamano: Maintainer who raised concerns about interaction with other index options
- Cho/Hodges: Recent reporters demonstrating actual breakage
- Pasco: Current technical analysis, identifying both original issue and new edge case

Open questions:
- How to properly handle partial diffs in `--intent-to-add` mode
- Final resolution of interaction with other index-modifying flags
- Need for mode exclusivity and edge case behavior in documentation

The thread now has clear reproduction cases and increasingly precise technical understanding, but requires an updated patch addressing both the original index corruption and the newly discovered partial-diff issue. The solution must carefully balance the original intent of `--intent-to-add` with the various apply modes while preventing any index corruption scenarios.
