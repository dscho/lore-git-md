Thread summary:

This thread concerns a bug in `git apply --intent-to-add` behavior where tracked files are incorrectly marked as deleted in the index. Johannes Altmanninger originally proposed a v3 patch series in 2021 to make `--intent-to-add` imply `--index` as a fix. Jason Cho recently inquired about the patch status, prompting Kristoffer Haugsbakk to investigate and find no record of the patches being merged. Junio Hamano has now responded with technical concerns about the proposed solution, pointing to documentation showing `--index` is not the only way to affect the index (other options like `--cached` and `--3way` also modify it). Hamano questions whether automatically forcing `--index` would create incorrect behavior in some cases, suggesting the solution may need reconsideration. The core issue remains unresolved, with two paths forward: 1) accept the documented behavior as correct despite the edge case, or 2) develop a more comprehensive solution that properly handles all index-modifying scenarios when `--intent-to-add` is used. Key participants are Altmanninger (original author), Cho (current inquiry), Haugsbakk (status check), and Hamano (maintainer feedback). No formal Reviewed-by or Acked-by tags exist on the original patch series, which now appears insufficient due to the newly raised concerns about interaction with other index-affecting options. The thread awaits either a revised technical proposal or confirmation that the current behavior is working as intended.
