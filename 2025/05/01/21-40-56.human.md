This is part 2 of Junio Hamano's 3-part series introducing a general mechanism for optional file specifications in Git configuration. The patch adds support for marking pathname-type config values as optional by prefixing them with `:(optional)`, causing Git to silently ignore missing or empty files rather than erroring out.

The change directly addresses the motivating use case from the thread - making `.git-blame-ignore-revs` files optional - but implements it as a general solution applicable to any pathname config. The implementation modifies `config.c` to handle the new prefix and adds test coverage using the commit template feature as a concrete example.

The patch builds on part 1's test improvements and introduces the core functionality, with part 3 expected to extend this to command-line options. The approach reuses Git's existing pathspec prefix notation for consistency. While the change is relatively small, it provides a clean solution to a long-standing pain point where users want to specify files that may legitimately not exist in some contexts.

The implementation looks solid with proper error handling and tests, though as noted in the thread, documentation for the parse-options integration (coming in part 3) will need attention. This is shaping up to be a well-considered solution to the original problem while providing useful general functionality.
