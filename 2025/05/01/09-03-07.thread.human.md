This thread examines a serious bug in `git apply --intent-to-add` (`-N`) where the command incorrectly clobbers index contents, marking tracked files as deleted. Originally reported by Johannes Altmanninger in 2021, the issue was recently rediscovered through reports from Jason Cho and Ryan Hodges demonstrating real workflow breakage.

Raymond Pasco's technical analysis confirms the core problem: `--intent-to-add` was designed to work only with worktree changes but currently replaces the full index. While Altmanninger's original patch had correct code, Pasco has now uncovered an additional edge case where the command still misprocesses partial diffs even after the initial fix. The solution will need to both document the option's exclusivity with `--index`/`--cached` and adjust logic to properly handle new-file portions of patches.

The thread has progressed from initial bug reports to a precise technical understanding, with Pasco emerging as the primary investigator. While the path forward is clearer - preserving Altmanninger's approach while addressing the new edge case - no updated patch has been submitted yet. Maintainer Junio Hamano had previously raised concerns about interaction with other index-modifying options, so any solution will need to carefully balance these constraints. The next step likely depends on either Pasco or another contributor preparing a revised patch that handles both the index corruption and partial-diff cases.
