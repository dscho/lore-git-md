This thread addresses a serious bug in `git apply --intent-to-add` (`-N`) where the command was incorrectly clobbering index contents. Raymond Pasco has led a comprehensive fix that includes both technical corrections and now, with the latest patch, documentation updates.

The solution involved four key technical patches that:
1. Fixed error handling for repository detection
2. Corrected index loading behavior
3. Tightened index write conditions
4. Added extensive test coverage

The new documentation patch completes the series by clarifying the man page to accurately reflect the command's behavior. It removes confusing double negatives and makes explicit that `--intent-to-add` cannot be combined with index-writing modes like `--index` or `--cached` - a key design point that the technical changes enforced.

The fix addresses a bug first reported in 2021 by Johannes Altmanninger and later demonstrated by Ryan Hodges. Junio Hamano provided maintainer guidance about flag interactions, while Raymond Pasco developed the comprehensive solution. With both the implementation fixes and now the documentation updates in place, this long-standing issue appears fully resolved. The series maintains `--intent-to-add`'s original purpose as a worktree-only operation while eliminating the dangerous index corruption behavior.
