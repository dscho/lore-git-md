This thread revisits a long-standing bug in `git apply --intent-to-add` where tracked files are incorrectly marked as deleted in the index. Johannes Altmanninger originally proposed a fix in 2021 (v3 series) to make `--intent-to-add` imply `--index`, but the patches were never merged. Jason Cho recently inquired about the status, prompting Kristoffer Haugsbakk to confirm the fix remains unmerged.

Maintainer Junio Hamano has now weighed in, pointing out that the proposed approach may be too simplistic. The documentation indicates `--index` isn't the only way to modify the index (options like `--cached` also affect it), so automatically forcing `--index` could create new edge cases. While the original bug persists, Hamano's response suggests the solution needs to account for these interactions rather than just coupling `--intent-to-add` to `--index`.

The thread now faces a choice: either accept the current documented behavior as intentional (despite the edge case), or develop a more comprehensive fix that properly handles all index-modifying scenarios when `--intent-to-add` is used. With the maintainer raising these concerns, the original patch series likely needs significant revision before reconsideration.
