This thread concerns a long-standing bug in `git apply --intent-to-add` where the command incorrectly marks tracked files as deleted in the index. Johannes Altmanninger proposed a fix in 2021 (v3 patch series) that would make `--intent-to-add` imply `--index` to prevent this behavior, but the patch was never merged. Jason Cho recently inquired about the status of this fix, prompting Kristoffer Haugsbakk to investigate. After searching the commit history, Haugsbakk found no record of the patch being merged or any alternative fix addressing the issue. The thread now awaits input from maintainers to clarify why the fix wasn't merged or to restart discussion about implementing it. The core technical solution remains clear - `--intent-to-add` should automatically set `--index` to avoid the deletion marking behavior - but the path forward depends on whether the original patch can be revived or if a new approach is needed.
