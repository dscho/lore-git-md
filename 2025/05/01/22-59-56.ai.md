This is a cover letter for a 2-patch series that continues the work to establish a standardized deprecation mechanism for Git commands, specifically targeting `git whatchanged`. The series builds on the previous iteration by refining test adjustments needed for the deprecation.

The first patch remains unchanged from v1, extracting the deprecation warning pattern from `git pack-redundant` into a reusable `you_still_use_that()` helper in usage.c. The second patch now includes additional test updates beyond what was in v1, particularly in t9300-fast-import.sh where `git whatchanged` calls are replaced with `git log --raw` since they weren't actually checking the output. The cover letter notes these test changes were the only updates from v1.

Key technical changes in the second patch include:
- Adding `--i-still-use-this` flag handling to builtin/log.c
- Updating git-whatchanged.adoc with WARNING section and new synopsis markup
- Modifying t4013-diff-various.sh tests to use the flag
- Adding new test verification for warning behavior
- Adjusting t4202-log.sh to consistently use the flag
- Replacing `whatchanged` with `log --raw` in t9300-fast-import.sh and t9301-fast-import-notes.sh

The series continues to position this as preparatory work rather than immediate removal, explicitly noting it doesn't yet touch the Git 3.0 breaking changes list. The author suggests some test cleanups (removing unnecessary git operations) could be done separately. The standardized deprecation approach being established patterns around warnings, documentation, test updates, and user feedback collection remains the primary focus.
