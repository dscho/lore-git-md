This is a test infrastructure patch in Patrick Steinhardt's ongoing series to improve TAP output consistency between Make and Meson builds. The patch specifically addresses shell trace output handling in verbose test modes.

The issue stems from how test output is redirected when using verbose flags (--verbose, --verbose-only, -x). Currently, stdout (fd3) and stderr (fd4) are separately redirected to the console, which breaks TAP parsing. The patch changes this by redirecting both stdout and stderr to the same destination (stderr) in verbose modes, sacrificing the ability to distinguish between them but ensuring valid TAP output.

Key technical changes:
- Modifies file descriptor handling in t/test-lib.sh to redirect fd3 to stderr instead of stdout
- Updates t/t0000-basic.sh tests to use new check_sub_test_lib_test_err helper that verifies both stdout and stderr streams
- Maintains existing test functionality while changing only the output routing
- The change affects test output parsing in verbose modes but doesn't impact test execution logic
- Follows the series' pattern of mechanical conversions for TAP compliance
- Builds on previous work standardizing test output handling across the suite

The patch continues the series' uncontroversial technical improvements to test infrastructure, with the tradeoff being loss of stdout/stderr separation in exchange for reliable TAP parsing. It's a focused change that aligns with the thread's established direction of standardizing test output formats.
