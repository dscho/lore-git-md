This is a discussion thread continuation in the ongoing `the_repository` removal effort, specifically focusing on naming choices in Patrick Steinhardt's object store refactoring series.

The email captures Junio Hamano weighing in on the naming debate between `odb_alternate` and `odb_source` for components in Git's new object storage model. Junio acknowledges Patrick's concerns about potential confusion but ultimately sides with `odb_source` as the least problematic option, noting it better fits the vision where loose objects, packed objects, and future storage types are all treated as equal "sources" rather than some being "alternates" to a primary.

Junio provides useful perspective by referencing Git's existing glossary definitions, highlighting how "alternate object database" currently implies inheriting from another complete database - a concept that doesn't cleanly map to the new model where storage components are more granular. While admitting "source" isn't perfect, he considers it the best available choice given the architectural direction.

The exchange shows this naming question - the last remaining blocker for Patrick's 18-patch series - moving toward resolution, with both main contributors now leaning toward `odb_source`.
