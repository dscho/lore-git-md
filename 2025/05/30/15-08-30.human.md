This is a bugfix patch in Patrick Steinhardt's series addressing race conditions in Git's maintenance operations. The patch makes `--task` and `--schedule` mutually exclusive options for `git maintenance run`, similar to how `--auto` and `--schedule` already were.

The change makes logical sense - `--task` lets users specify exactly which maintenance tasks to run, while `--schedule` relies on the repository's configured maintenance strategy. Using both together would create ambiguity about which should take precedence. The patch enforces this by using Git's standard `die_for_incompatible_opt2()` helper for both cases, making the error handling more maintainable.

The implementation is straightforward, adding the new validation check alongside the existing one for `--auto` and updating the tests to verify the new and old cases. This appears to be a clean, focused improvement that fits well with the series' broader goal of making maintenance operations more robust. The change is small but meaningful, and the test coverage is thorough.
