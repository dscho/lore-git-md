This is a naming discussion within Patrick Steinhardt's ongoing series to refactor Git's object database subsystem. The thread focuses on the terminology for structures that handle alternate object directories (previously called `object_directory`, now proposed as `odb_alternate`).

Patrick responds to Toon Claes' concerns about the "alternate" terminology by explaining the backend relationship - each alternate is backed by a specific backend implementation, but "alternate" was chosen over "backend" to avoid implying a 1:1 relationship between the main object database and its backends. While Patrick acknowledges `odb_source` as a viable alternative name, he argues that mixing "alternate" and "source" terminology in the interfaces could create confusion.

The discussion exemplifies the careful consideration going into API design decisions in this refactoring effort, with multiple contributors weighing in on naming choices that will affect long-term code clarity. The technical implementation itself is ready with positive reviews, but this naming debate shows the project's attention to getting the conceptual model right.
