This is a review comment in the ongoing test infrastructure series focusing on Python version detection in the Git test suite.

Todd Zullinger responds to Patrick Steinhardt's patch that converted Python version detection for git-p4 tests to use test prerequisites (P4_PYTHON2/P4_PYTHON3) rather than wrapper scripts. While agreeing with the technical approach, Zullinger notes two issues:

1. A typo in the commit message where "git-b4" should be "git-p4" (a reference to the Perforce integration tool being tested)
2. A broader question about whether Python 2 support should still be maintained given its EOL status in 2022, noting that major distributions like Debian and RHEL now include Python 3 by default

The comment doesn't propose immediate changes to the patch but raises the Python 2 sunsetting question as a potential future cleanup opportunity. This fits into the series' broader theme of test modernization while highlighting an area where test infrastructure could potentially be simplified if backward compatibility requirements evolve.
