This is a test infrastructure patch that changes how Git's test suite handles unexpectedly passing tests marked with `test_expect_failure`. Currently, when a test marked as expected to fail actually passes, the suite still reports success while noting the unexpected pass. Patrick Steinhardt proposes making such cases cause the test suite to fail instead, bringing Git's behavior in line with Meson's TAP parser and making unexpected passes more visible.

The change addresses two problems: (1) it makes unexpected passes harder to miss, especially in CI environments where developers might not scrutinize every test output, and (2) it unifies behavior between Git's current test runner (prove) and Meson's upcoming TAP parser, which already treats unexpected passes as failures. The TAP specification allows either interpretation, but having both tools behave differently would be problematic.

The implementation modifies `test-lib.sh` to exit with status 1 when `test_fixed` is non-zero (indicating unexpected passes) and updates test cases in t0000-basic.sh to use the new error-checking helper. The patch is part of a larger series standardizing test output for Meson compatibility, and this particular change represents a deliberate choice to prioritize consistency with Meson's stricter interpretation of the TAP spec over prove's more lenient handling. The patch is cleanly implemented with clear test coverage and follows the pattern of the series' other mechanical TAP-compliance improvements.
