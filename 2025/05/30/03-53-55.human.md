This is the second patch in a bugfix series addressing memory leaks in pack-bitmap.c when loading corrupt bitmaps. The patch adds test infrastructure to validate the fixes from the first patch and catch future regressions.

The test suite now includes a new `test-tool bitmap list-commits-offset` helper that outputs the positions of key fields in bitmap entries (commit OID, xor_offset, flags, and EWAH bitmap data). This allows targeted corruption of specific fields - in this case, the test corrupts the xor_offset field of the first entry. The test_bitmap_commits_offset() function tracks these positions by extending the stored_bitmap struct when in test mode.

While the technical approach has consensus from reviewers, Junio Hamano notes the commit message could better explain why the test infrastructure lives in pack-bitmap.c rather than being separate. The patch appears well-crafted with thorough test coverage, though Taylor Blau has suggested some implementation refinements around position tracking simplification and output verification that may be addressed in future iterations.

This completes the series' goal of fixing memory leaks while corrupt bitmaps are loaded, with the test infrastructure serving as both validation for these fixes and a foundation for future bitmap corruption testing.
