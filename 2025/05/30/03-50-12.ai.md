Bugfix patch in a series addressing bitmap memory leaks, now including sign-off clarification.

This is a procedural follow-up to the first patch in the v4 series fixing memory leaks in pack-bitmap.c. The patch itself (authored by Taylor Blau) simplifies error handling by removing redundant cleanup code in `load_bitmap()`, letting callers handle cleanup via `free_bitmap_index()`. The technical content remains unchanged from previous versions, with Junio Hamano now confirming the proper sign-off ordering when relaying patches.

The thread context shows this is part of a two-patch series where:
1. This first patch removes duplicate cleanup paths for EWAH bitmaps
2. A second patch adds test infrastructure for bitmap corruption scenarios

The only change here is Lidong Yan adding their sign-off below Taylor Blau's, resolving a procedural question about relayed patch attribution. Junio references documentation (commit c11c3b5681) that secondary sign-offs are encouraged but not strictly required for public patch sharing. This distinction between public relay (where Taylor's original sign-off suffices) versus private forwarding (which would need Lidong's sign-off) may warrant future documentation updates but doesn't affect the current series.

Key technical points from the patch remain:
- Removes ~17 lines of error-handling code in `load_bitmap()`
- Replaces all `goto failed` with direct `return -1`
- Relies on callers' `free_bitmap_index()` for uniform cleanup
- Maintains safety while simplifying the code

The patch has already received positive reviews from Jeff King and Junio Hamano, with consensus on both the technical approach and now the sign-off procedure. No further changes are expected to this particular patch as the series moves toward merging.
