This is a naming discussion in Patrick Steinhardt's ongoing series to refactor Git's object database subsystem. The exchange clarifies terminology around object storage locations.

Patrick responds to Justin Tobler's question about distinguishing "local" vs "non-local" objects in the context of alternate object directories. He confirms that "local" refers to objects in the primary object directory while "non-local" means objects from alternate directories. This comes as part of the broader discussion about whether to name the related structure `odb_alternate` (Patrick's preference) or alternatives like `object_source`.

The thread shows careful attention to API naming that will affect future maintenance, with multiple contributors weighing in. While the technical implementation is ready (with positive reviews from Junio Hamano and Derrick Stolee), this particular naming question remains open. The exchange exemplifies Git's collaborative approach to API design decisions that balance technical accuracy with long-term clarity.
