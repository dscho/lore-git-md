This is a refactoring patch in a series about maintenance task execution timing. It's part of an ongoing effort to fix locking issues with `packed-refs` during background maintenance.

The patch restructures how maintenance tasks are run before and after detaching (going into the background). Currently all tasks run after detach, which can cause reference locking problems. The change splits the task execution into two phases by introducing `before_detach` and `after_detach` function pointers in the task structure.

While this patch doesn't yet move any tasks to run before detach (they all still run after), it lays the groundwork for future changes by:
1. Adding the infrastructure to distinguish pre- and post-detach tasks
2. Modifying the task runner to handle both phases
3. Adding proper trace2 regions to track execution timing

The implementation looks clean and focused, with clear separation of concerns. The commit message provides good historical context about why this change is needed, tracing the issue back to when maintenance moved from `git gc` to `git maintenance`. This appears to be a well-considered preparatory change for fixing known locking issues.
