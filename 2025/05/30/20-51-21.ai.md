Maintenance patch in the `imap-send` OAuth2.0 series, addressing code style issues in multi-line comments. Eric Sunshine points out that the project's standard formatting for multi-line comments uses `/*` on its own line followed by asterisk-prefixed lines, rather than the inline `/*` style used in the OAuth2.0 authentication code. This appears in the `oauthbearer_base64()` function documentation and other parts of the patch.

The comment itself provides useful technical context about the OAUTHBEARER string composition, explaining the gs2 header from RFC5801 and the key-value pairs from RFC7628. The actual authentication functionality remains unchanged - this is purely about aligning with Git's code style conventions.

This follows the extensive v9 series that added OAuth2.0 support via both OAUTHBEARER and XOAUTH2 protocols, implemented across OpenSSL and libcurl backends. The series has seen thorough review and iteration, with this being one of the final polish items before potential inclusion. The style fix doesn't affect functionality but helps maintain code consistency in the newly added authentication handlers.
