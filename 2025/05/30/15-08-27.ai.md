This is a refactoring patch that converts the array of maintenance tasks in `builtin/gc.c` to use designated field initializers. As the first patch in Patrick Steinhardt's 12-part series addressing race conditions in Git's maintenance operations, it serves as preparatory cleanup work.

The change makes the task definitions more explicit by naming each struct field (`.name`, `.fn`, `.auto_condition`, etc.) rather than relying on positional initialization. This improves maintainability by making the code more self-documenting and reducing the risk of errors when adding new fields to the `maintenance_task` struct in future changes. The diff shows a straightforward mechanical conversion of all task definitions in the array, with no behavioral changes.

Key technical details for future reference:
- The patch touches only `builtin/gc.c`, modifying the static `tasks[]` array
- All maintenance tasks are updated: prefetch, loose-objects, incremental-repack, gc, commit-graph, pack-refs, reflog-expire, worktree-prune, and rerere-gc
- Fields converted include task name strings, function pointers, and condition checkers
- The `TASK_GC` entry shows the additional `.enabled` field that was previously positionally initialized

This change supports the series' broader goal by making the task definitions more maintainable before subsequent patches add complexity to the maintenance framework. The clean diff and focused scope suggest this is a well-executed preparatory change.
