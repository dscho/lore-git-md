Refactoring patch in Patrick Steinhardt's maintenance race condition series. This is the second patch in a 12-part v2 series addressing race conditions during auto-maintenance operations.

The patch simplifies the quiet flag handling in `builtin/gc.c` by eliminating a redundant local `quiet` variable that duplicated functionality already provided by the `quiet` field in `struct maintenance_run_opts`. The change makes the code more maintainable by removing confusion about which variable controls quiet behavior, consistently using the struct field throughout. All references to the local variable are updated to use `opts.quiet` instead, including in progress reporting for repacking, pruning, and commit graph writing.

This is a straightforward cleanup that doesn't affect functionality but improves code clarity. It follows the series' pattern of preparatory refactoring before introducing more complex changes. The patch touches the same maintenance task execution paths that will later be modified to handle ref locking safely, making this a useful simplification of the control flow.
