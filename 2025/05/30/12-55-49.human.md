This is a bugfix patch in a series addressing locking races in Git's maintenance tasks. It follows previous fixes for "pack-refs" and "reflog-expire" by applying similar treatment to the "gc" task.

The patch splits the garbage collection task into two phases: `gc_before_detach` (which handles pre-detach operations like repacking refs) and `gc_after_detach` (which runs the actual GC). A new hidden flag `--skip-maintenance-before-detach` is introduced to prevent duplicate work when GC is run non-detached.

Ben Knoble raises a question about the implementation: if `--no-detach` is specified, why do we need to skip the before-detach steps? This suggests there may be some logical inconsistency in how the flag is being used, though the core race condition solution appears sound.

The changes are well-tested with updates to t7900-maintenance.sh that verify the new flag's behavior. This appears to be a thoughtful fix to a subtle concurrency issue, though Ben's question indicates there may be room for clarification in the implementation details.
