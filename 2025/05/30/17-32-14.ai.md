Bugfix for a critical regression in `imap-send` configuration parsing that has made the command unusable since Git 2.46.0. The patch corrects a memory management error introduced in commit 6d1f198f34 where the wrong field (`cfg->folder`) was being freed and NULLed when processing unrelated configuration variables (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). This led to the folder setting being lost, breaking basic functionality.

The fix changes each case to free and NULL the correct corresponding field instead of incorrectly targeting the folder field. The regression appears to have gone unnoticed for some time, likely because most users prefer `git send-email` over `imap-send`. This is the first patch in a 9-part series that significantly improves `imap-send` with OAuth2.0 support and other features, but this particular change is a straightforward bugfix with no new functionality.

The patch is minimal (4 line changes) and clearly corrects the specific regression. It touches only the configuration parsing logic in `imap-send.c`, fixing the field-specific cleanup that was broken in the original memory leak fix. This is a prerequisite for the rest of the series which builds on working configuration handling.
