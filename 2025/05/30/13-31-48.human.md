This is a build system patch that completes Patrick Steinhardt's series integrating Git's test suite with Meson's TAP output parsing. The change enables Meson to properly interpret the TAP-formatted output from Git's test scripts when using Meson 1.8 or newer.

The patch makes Meson aware of individual test results (pass/fail/skip counts) rather than just the final exit code. This provides more detailed reporting, as shown in the example output where we can now see that t0027-auto-crlf contains 2600 subtests. The change comes with a workaround for interactive test runs, which are marked as "ignored" since TAP parsing isn't reliable when tests might pause for user input.

This is the final patch in a well-reviewed series that has been evolving through multiple versions. The implementation is straightforward - it conditionally adds the TAP protocol parameter when Meson 1.8+ is detected. The patch builds on earlier work to make Git's test output strictly TAP-compliant, and the upstream Meson fix Patrick contributed ensures the interactive mode case is handled gracefully.
