This is a feature patch adding OAuth2.0 authentication support to `imap-send`, part of a larger series that has been through multiple iterations (now at v9). The patch implements both RFC-standard OAUTHBEARER and Google's XOAUTH2 protocols for secure authentication with IMAP servers, particularly targeting Gmail and Outlook services.

The implementation spans both OpenSSL and libcurl backends, with new authentication handlers (`auth_oauthbearer` and `auth_xoauth2`) that construct properly formatted authentication strings and handle the protocol exchange. The patch includes detailed documentation updates explaining the new authentication methods, their security benefits over app-specific passwords, and configuration examples for both Gmail and Outlook. Notably, it warns that Gmail requires either app-specific passwords or OAuth2.0 tokens, while Outlook only supports OAuth2.0 via XOAUTH2.

Technical changes include new capability flags (AUTH_OAUTHBEARER, AUTH_XOAUTH2), base64 encoding utilities for constructing authentication strings, and curl-specific handling that uses CURLOPT_XOAUTH2_BEARER for both protocols. The documentation emphasizes OAuth2.0 as the more secure choice and mentions credential helper integration for token management. This appears to be a well-considered implementation that addresses modern authentication needs while maintaining compatibility with existing IMAP functionality.
