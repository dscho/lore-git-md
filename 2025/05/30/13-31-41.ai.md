This is a test infrastructure improvement patch in Patrick Steinhardt's ongoing series to standardize TAP output across Git's test suite. The patch converts an ad-hoc filesystem capability check in t9822-git-p4-path-encoding.sh into a proper test prerequisite using test_lazy_prereq.

The test script previously used direct filesystem operations to check for ISO-8859-1 filename support, printing a skip message directly to stderr when unsupported. This broke TAP output formatting. The new version wraps the check in test_lazy_prereq, which properly handles output redirection for TAP compliance while maintaining the same functionality.

Key technical changes:
- Replaces raw filesystem test block with test_lazy_prereq FS_ACCEPTS_ISO_8859_1
- Keeps same test logic (create/delete ISO-8859-1 encoded filename)
- Moves skip_all message into standard test prerequisite handling
- Preserves all existing test behavior while fixing TAP output format

This continues the series' pattern of mechanical conversions to improve TAP compliance without altering test semantics. The change is straightforward and aligns with the broader effort to standardize test output handling between Make and Meson builds. No behavioral changes to the actual p4 path encoding tests are introduced - only the prerequisite checking infrastructure is modified.
