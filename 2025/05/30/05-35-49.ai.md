Platform compatibility follow-up regarding `REFTABLE_UNUSED` vs `MAYBE_UNUSED` macros.

Patrick Steinhardt questions why the `REFTABLE_UNUSED` macro (recently patched by Carlo Marcelo Arenas Belón to be C99-compatible) causes build failures on NonStop when the similarly-defined `MAYBE_UNUSED` macro in `git-compat-util.h` does not. This appears to be probing for deeper consistency in how unused parameter attributes are handled across Git's codebase.

The thread had previously settled on Carlo's solution of making `REFTABLE_UNUSED` conditionally use the GNU attribute, with Junio Hamano noting this simpler approach is sufficient given modern GCC requirements. Patrick's question suggests there may be an inconsistency between how the reftable subsystem and core Git handle these attributes, though the email doesn't propose any specific changes to the already-approved fix.

Key technical points raised:
- `MAYBE_UNUSED` in `git-compat-util.h` has same basic structure (GNU attribute or empty)
- Question implies NonStop builds must be including `git-compat-util.h` without issue
- Potential inconsistency between core and reftable's attribute handling approaches

This appears to be seeking clarification rather than proposing action, as the immediate build fix is already queued. The question may prompt discussion about whether the reftable code should align more closely with core Git's attribute macros, though that would be separate from the NonStop compatibility fix.
