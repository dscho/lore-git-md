This is a platform compatibility fix for the reftable subsystem, concluding the discussion about NonStop build failures. Junio C Hamano confirms the solution is ready to be fast-tracked into the codebase before the next release candidate.

The thread had previously identified a compilation error where NonStop platform's C99 compiler couldn't handle the GNU-specific `__attribute__((__unused__))` syntax in the `REFTABLE_UNUSED` macro. The fix makes this attribute conditional on `__GNUC__` being defined, with an empty fallback for other compilers.

Patrick Steinhardt, the reftable maintainer, has reviewed and approved the solution after Jeff King's technical explanation clarified why core Git's `MAYBE_UNUSED` macro works on NonStop (due to platform-specific preprocessing in `git-compat-util.h`). This resolved earlier questions about consistency between reftable's attribute handling and core Git's compatibility layer.

The email shows consensus has been reached with no further changes needed to Carlo Marcelo Arenas Belón's proposed fix. Junio indicates the patch will be expedited into the codebase before the next release candidate, addressing Randall S. Becker's original report of the issue persisting in Git 2.50.0-rc0.

Key technical points settled in this thread include: the difference between reftable's direct attribute usage versus core Git's compatibility layer approach, the irrelevance of older GCC version constraints, and the adequacy of the conditional compilation solution. While the discussion identified potential future work to standardize attribute macros across the codebase, the immediate fix is considered complete.
