Refactoring patch in Patrick Steinhardt's maintenance race condition series. This is patch 6/12 in the v2 series, focusing on restructuring the task execution code in preparation for splitting maintenance tasks between pre- and post-daemon phases.

The patch extracts the task execution logic from `maintenance_run_tasks()` into a new helper function `maybe_run_task()`. The new function encapsulates the auto-condition checking, trace2 instrumentation, and error handling that was previously duplicated in the loop. The core behavior remains unchanged - tasks are still selected based on the `opts->tasks` array and run with the same conditions and error reporting.

Key technical details:
- The new `maybe_run_task()` takes a `const struct maintenance_task *` parameter rather than using array indexing
- Maintains identical trace2 regions (`maintenance` category with task name)
- Preserves the auto-condition check and error message format
- Returns 0/1 success status like the original code

This is a preparatory change for the upcoming patch that will split task execution across daemonization boundaries. The extraction makes that future change cleaner by isolating the per-task execution logic. The patch follows the series' pattern of incremental refactoring to support the eventual race condition fixes, with no functional changes at this stage.
