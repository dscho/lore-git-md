This patch is part of Patrick Steinhardt's ongoing series to fix race conditions in Git's maintenance operations, specifically addressing locking issues around packed-refs and reflogs. It moves the "pack-refs" and "reflog-expire" tasks to execute before daemonization in the maintenance process, matching the behavior already present in `git gc`.

The change is straightforward - it simply updates the task definitions to use `before_detach` function pointers instead of `after_detach` for these two reference-related operations. This prevents potential race conditions around their lockfiles that could occur if they ran after detaching. The patch notes that fixing the "gc" task requires more involved changes that will come in a subsequent commit.

This builds directly on the phase-split execution framework introduced in the previous patch (08/12), now putting it to use for concrete case of reference operations. The change maintains backward compatibility while resolving a specific race condition scenario. The implementation is minimal (just 2 lines changed) but effectively leverages the infrastructure work done in earlier patches of the series.

Key technical points:
- Updates `TASK_PACK_REFS` and `TASK_REFLOG_EXPIRE` in the `tasks[]` array
- Preserves existing auto-condition checks
- Leaves `gc` task for future work (as noted in commit message)
- Maintains same function pointers, just moves when they execute

The patch continues the series' methodical approach to making maintenance operations more robust, with this being the first practical application of the phase-split execution model to solve a concrete locking issue.
