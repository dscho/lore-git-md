Bugfix for `git refs verify` failing on older worktrees without refs. This patch addresses an issue where `git refs verify` (introduced in v2.47.0) fails with error messages when encountering worktrees created by Git v2.43.0 or older that don't have any worktree-specific refs. The command incorrectly tries to check a non-existent `refs` directory in these worktrees, resulting in error messages and a 255 exit code.

The problem occurs because older Git versions didn't create the `refs` directory in worktrees unless there were actual worktree refs present. The patch includes test cases demonstrating both the failing scenario (worktree without refs) and a working scenario (worktree with bisect refs).

While the bug is clear and well-documented, the email only includes test cases rather than the actual fix. The author provides detailed reproduction steps and confirms the issue exists in both `seen` and `next` branches. This appears to be a genuine edge case that would affect users with mixed-version worktree environments, though the impact is limited to the verification output rather than core functionality.
