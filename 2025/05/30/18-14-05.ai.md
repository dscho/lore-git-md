Bugfix for memory leak in pack-bitmap.c's boundary object handling. This is the first patch in a v2 series addressing a memory leak scenario in the bitmap cascade logic, following up on Patrick Steinhardt's review.

The patch modifies `find_boundary_objects()` to unconditionally free the `roots_bitmap` after cascade operations, rather than only freeing it when `cascade_pseudo_merges_1()` fails. The key insight is that `cascade_pseudo_merges_1()` only uses the bitmap as a mutable reference without taking ownership, so the caller must always clean it up. This matches the ownership pattern seen in similar functions like `find_objects()`.

The change is minimal (4 lines modified) but important for correctness - the previous conditional free could leak memory when the cascade operation succeeded. The second patch in the series adds test coverage to verify this fix. The commit message clearly explains the ownership semantics and leak scenario, showing good responsiveness to prior review feedback.

This appears to be a well-contained fix for a real issue, with the v2 series now including both the implementation change and test coverage to verify it. The patch follows established patterns in the codebase and doesn't introduce any new complexity while fixing the memory management issue.
