This is a test infrastructure patch series (10 parts) focused on improving TAP output parsing in the Meson build system, building on extensive prior discussion. The series has evolved through three versions with input from multiple reviewers, now addressing shell trace output handling and unexpected test pass detection.

The key technical changes in v3 include:
- Splitting the output silencing patch into multiple focused commits (1-4)
- Properly handling shell traces by redirecting them from stdout to stderr (5)
- Formatting BASH_XTRACEFD warnings in TAP-compliant format (6)
- Fixing a macOS-specific test that was passing unexpectedly (7)
- Making the test suite fail on unexpectedly passing tests (8)
- Consolidating test kwargs in meson.build (9)
- Enabling TAP output parsing for Meson 1.8+ (10)

The series now properly separates TAP-formatted output (stdout) from other diagnostic output (stderr), which is critical for TAP parsers. It also introduces stricter validation where tests that unexpectedly pass (e.g. when marked as failing but actually passing) will now be reported as failures, matching prove(1)'s behavior.

Review discussion has centered on balancing quick fixes versus structural improvements, with Eric Sunshine advocating for proper test_expect_success wrapping over /dev/null redirection. The v3 series represents a compromise, splitting changes into more focused commits while maintaining the core functionality. Outstanding questions remain about stream buffering behavior during redirection, but the technical implementation appears sound across 19 modified files.

This continues the broader effort to align Meson's test handling with Make's while adding TAP parsing capabilities, with the series now technically ready pending resolution of the remaining stream handling questions. The changes affect test output formatting, prerequisite handling, and build system integration while maintaining backward compatibility.
