This is the second patch in a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch adds test infrastructure and a test case for corrupt bitmap handling, building on the first patch's leak fixes.

The patch introduces a new `test-tool bitmap list-commits-offset` helper that outputs structured data about bitmap entries (commit OID, offsets for commit index, XOR offset, flags, and EWAH bitmap positions). This enables targeted corruption testing by revealing the internal layout of bitmap files. The test case uses this to corrupt the XOR offset field of the first entry while verifying the bitmap still functions correctly.

Key technical components include:
- New `stored_bitmap_tag_pos` struct to track positions alongside bitmap data
- Modified `store_bitmap()` to optionally store position data when `tag_pos_on_bitmap` is set
- Test helper that outputs field positions for corruption testing
- Test case in t5310 that uses `dd` to corrupt specific bitmap fields

Junio Hamano notes the commit message should better explain why the test infrastructure is placed in pack-bitmap.c rather than being separate, and should follow the standard problem-solution-command structure. The author acknowledges this feedback for future iterations.

The patch builds on the thread's consensus around centralized cleanup via `free_bitmap_index()` while adding validation that the fixes properly handle corrupt bitmaps. Outstanding review feedback from Taylor Blau requests simplifying the position tracking implementation and making test output parsing more robust.
