This is a refactoring patch in Patrick Steinhardt's series addressing race conditions in Git's maintenance operations. The patch focuses on improving the configuration of explicit maintenance tasks when users specify them via `--task` options.

The key change moves task selection logic from modifying global state in `task_option_parse()` to collecting tasks in a string list first, then applying the configuration in `initialize_task_config()`. This addresses two issues: (1) eliminating direct global state modification during option parsing, and (2) centralizing task configuration logic that was scattered across multiple functions.

Technical details: The patch introduces a `selected_tasks` string list passed through the option parsing machinery. Each selected task is stored with its name and a pointer to the corresponding `maintenance_task` struct. The actual task ordering is now applied in `initialize_task_config()` by iterating this list. The change touches only `builtin/gc.c`, modifying how the `--task` option interacts with the maintenance task array while maintaining the same external behavior.

This is part of the series' broader effort to clean up maintenance task execution before implementing the core race condition fixes. The change follows logically from patch 2's quiet flag cleanup and precedes the planned global state elimination mentioned in the commit message. The implementation appears clean and well-contained, with proper memory management via `string_list_clear()`.
