This is version 9 of a feature and bugfix series for `git imap-send`, now focused on OAuth2.0 support and usability improvements. The series has evolved through multiple rounds of review, with v9 dropping the config-based backend selection from v8 and adding documentation encouraging OAuth2.0 for Gmail users.

The key changes in this version include:
1. A new note in the documentation recommending OAuth2.0 over app-specific passwords for Gmail, emphasizing its security benefits and lack of multi-factor authentication requirement
2. Cleaned up wording around OAuth2.0 configuration options (OAUTHBEARER/XOAUTH2)
3. The series maintains all previous improvements: fixed config parsing, OAuth2.0/PLAIN authentication support, command-line folder specification, folder listing capability, and various user experience tweaks

The thread context shows this has been thoroughly reviewed, with the main outstanding question being whether to maintain both OpenSSL and libcurl backends long-term. The author argues the OpenSSL code is still needed for tunnel functionality even if CRAM-MD5 usage is rare. This version appears technically complete, with the documentation polish in v9 being the final refinement.

For users, this makes `imap-send` fully functional with modern authentication methods and better visibility into folder structures - particularly useful for Gmail users who can now use OAuth2.0 without app passwords. The implementation handles both major backends (OpenSSL and libcurl) with protocol-specific adaptations where needed.
