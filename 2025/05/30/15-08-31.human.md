This is a refactoring patch in Patrick Steinhardt's series addressing race conditions in Git's maintenance operations. It focuses on eliminating global state manipulation in the task selection logic.

The patch removes direct modifications to the global `tasks` array, which previously used multiple fields (`enabled`, `selected_order`, `schedule`) to track task execution conditions in a distributed way. Instead, it introduces a cleaner approach where task selection is computed once in `initialize_task_config()` and stored in the options structure. This makes the logic more self-contained and easier to follow.

Key changes include:
- Moving task selection state from global variables to the `maintenance_run_opts` struct
- Introducing a `maintenance_strategy` struct to better organize configuration
- Simplifying the task execution loop to iterate through pre-selected tasks
- Adding proper cleanup of allocated memory

The patch continues the series' trend of making the maintenance code more maintainable while working toward the larger goal of safe reference operations during auto-maintenance. The changes are mechanical but important for the overall architecture, and the thorough diff suggests careful attention to correctness.
