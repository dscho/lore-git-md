Bugfix for a critical regression in `imap-send` that has made the command unusable since Git 2.46.0. The patch corrects a memory management error introduced in commit 6d1f198f34 where the wrong struct field (`cfg->folder`) was being cleared when processing unrelated IMAP configuration options like `imap.user` and `imap.pass`. This caused the folder setting to be incorrectly NULLed out, breaking basic functionality.

The fix is straightforward - it addresses four cases where the wrong field was being freed, replacing each with the correct corresponding field (`user`, `pass`, `tunnel`, and `auth_method`). The commit message notes this bug went unnoticed for some time, likely because most users prefer `git send-email` over `imap-send`.

This is the first patch in a larger v9 series that adds OAuth2.0 support and other IMAP improvements, but stands alone as an important bugfix that restores basic functionality. The change is minimal and focused, touching only the configuration parsing logic in `imap-send.c`. Given that this fixes a regression that has been present for nearly a year, it seems like a high-priority fix that should be straightforward to merge.
