This is the second patch in a two-part series addressing a memory leak in the pack-bitmap code. It adds test coverage for the fix implemented in the first patch.

The test creates a scenario where `find_boundary_objects()` would previously leak memory by not properly cleaning up the `roots_bitmap` when using pseudo-merges. The test sets up a simple repository with two commits (A and B), configures pseudo-merges, and performs a boundary bitmap traversal between them. This exercises the code path where the bitmap would have leaked before the series' fixes.

The test is well-constructed - it clearly demonstrates the problematic case while being self-contained and readable. Together with the first patch's implementation change, this provides a complete solution to the memory leak issue. The series shows good attention to detail by not just fixing the bug but also adding regression protection.

This appears ready for inclusion - it addresses the original issue thoroughly, has already incorporated review feedback from Patrick Steinhardt, and maintains the established testing patterns for the bitmap code. The changes are focused and unlikely to introduce new problems.
