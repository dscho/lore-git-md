This is a bugfix patch addressing a memory leak in the pack-bitmap code. It's part of a 2-patch series (1/2) that follows up on earlier review discussion.

The patch modifies `find_boundary_objects()` in pack-bitmap.c to unconditionally free the `roots_bitmap` after use, rather than only freeing it when `cascade_pseudo_merges_1()` fails. The change fixes a memory leak scenario where the bitmap would be lost when the cascade operation succeeds. The commit message explains that since `cascade_pseudo_merges_1()` only uses the bitmap as a mutable reference without taking ownership, we should always free it in the calling function.

This appears to be a straightforward, well-motivated change that follows the pattern seen in similar functions. The patch is small (just 2 lines changed) and focused on the exact issue identified in previous review. The second patch in the series adds test coverage for this case, making this a complete fix. The change demonstrates good responsiveness to review feedback from Patrick Steinhardt.
