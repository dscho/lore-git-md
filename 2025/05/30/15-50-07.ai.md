Documentation patch finalizing Gmail authentication details in git-send-email docs. This is the last patch in the v7 documentation series that has been through extensive review.

The patch clarifies that Gmail no longer accepts regular passwords at all (not just for MFA accounts) and that app passwords are required for basic authentication. It promotes OAuth2.0 as a more secure alternative that works regardless of MFA status, aligning with the parallel OAuth2.0 implementation work for git-imap-send. The changes standardize on "mechanism" instead of "method" when referring to OAUTHBEARER/XOAUTH2, matching official documentation terminology.

Key technical details:
- Updates `Documentation/git-send-email.adoc` with clearer Gmail password requirements
- Explicitly states regular passwords don't work (not just MFA limitation)
- Positions OAuth2.0 as preferred over app passwords
- Changes "method" to "mechanism" for OAuth terminology (3 instances)
- Maintains consistency with Outlook OAuth2.0 documentation
- Keeps backtick formatting for config options (`smtpAuth`, `OAUTHBEARER` etc.)

This concludes the documentation series after addressing all feedback, with Junio Hamano and Ben Knoble having previously settled the formatting debates. The patch ties into the broader email authentication improvements by providing clear guidance that complements the technical OAuth2.0 work still under review for git-imap-send.
