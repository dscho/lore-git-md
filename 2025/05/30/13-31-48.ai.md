This is a build system patch that enables TAP output parsing in Meson for Git's test suite. It's the 10th patch in Patrick Steinhardt's 18-part series improving Meson build system support, specifically focusing on test infrastructure standardization.

The patch enables Meson's TAP protocol support when using Meson 1.8+, which allows the build system to properly parse the test output format Git's test suite already generates. This provides better test reporting by showing subtest counts and skipped tests, as demonstrated in the example output showing 2600 subtests passing in t0027-auto-crlf. The change comes after an upstream fix in Meson resolved an incompatibility with interactive test mode.

The implementation is straightforward - it conditionally sets the 'protocol': 'tap' parameter in test_kwargs when Meson 1.8+ is detected. Interactive mode tests are marked as "ignored" since their output can't be reliably parsed when connected to a terminal. This builds on previous work in the series that standardized test output to be TAP-compliant.

The patch appears well-justified and low-risk, being gated behind a version check and building on established TAP output work. It represents the culmination of the series' efforts to properly integrate Git's test suite with Meson's test reporting capabilities. The change is purely about improving test output interpretation without modifying test behavior.
