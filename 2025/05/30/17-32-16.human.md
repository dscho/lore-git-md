This is a feature patch for the `imap-send` tool, adding PLAIN authentication support for the OpenSSL backend. It's part of a larger v9 series that introduces OAuth2.0 support and fixes several IMAP-related issues.

The patch implements RFC 4616-compliant PLAIN authentication for OpenSSL, which was previously only available when using libcurl. This allows users with app passwords or providers requiring PLAIN auth to use the OpenSSL backend. The implementation follows the standard format of a null-terminated username and password string, base64-encoded as specified in the RFC.

The changes include:
1. Adding AUTH_PLAIN capability detection
2. Implementing the base64 encoding logic for PLAIN credentials
3. Adding the authentication handler that sends the encoded credentials
4. Updating documentation to list PLAIN as a supported method

This appears to be a well-contained addition that matches the existing authentication framework in `imap-send.c`. The commit message clearly explains the change and its motivation (supporting providers that use app passwords with PLAIN auth). The implementation includes proper error handling and follows the pattern of other auth methods in the codebase.

As part of the larger series, this helps provide feature parity between the OpenSSL and libcurl backends, though the thread context shows there's ongoing discussion about whether maintaining both backends is worthwhile long-term.
