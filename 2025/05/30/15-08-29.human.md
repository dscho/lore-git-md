Refactoring patch in Patrick Steinhardt's maintenance race condition series (3/12). This change reorganizes how explicit maintenance tasks are configured when users pass `--task` options to `git maintenance run`.

The patch addresses two issues with the current implementation: (1) modifying global state during option parsing makes the code harder to follow, and (2) task configuration logic is scattered across multiple functions. The solution moves task selection into a string list during parsing, then centralizes the final configuration in `initialize_task_config()`. This is a preparatory change that makes the code more maintainable without altering behavior.

This is part of a larger effort to fix race conditions in maintenance operations, with this particular patch focusing on cleaning up the task selection infrastructure. The change is mechanical but well-explained, with clear separation between collecting user input and applying the configuration. The patch maintains the existing functionality while making the code more amenable to the ref locking changes coming later in the series.
