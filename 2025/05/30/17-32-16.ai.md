This is a feature patch in the ongoing `imap-send` series, adding PLAIN authentication support for the OpenSSL backend. The patch implements RFC 4616-compliant PLAIN authentication, which was previously only available when using libcurl. The implementation includes a new `plain_base64()` helper function that properly formats credentials according to the RFC, plus the necessary capability flag (`AUTH_PLAIN`) and authentication handler (`auth_plain`).

The documentation is updated to list PLAIN alongside other supported methods when using OpenSSL. The implementation handles the base64 encoding of credentials in the format `\0user\0pass` and properly integrates with the existing IMAP command flow. Error paths are covered, including base64 encoding failures and socket write errors.

This addresses a gap where email providers offering app passwords via PLAIN authentication couldn't be used with Git's OpenSSL backend. The change is part of broader improvements to `imap-send`'s authentication options, though the thread context shows ongoing discussion about whether maintaining dual backend support (OpenSSL + libcurl) is worthwhile long-term. The patch appears technically sound with proper error handling and RFC compliance.
