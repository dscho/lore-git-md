This is the final patch in Patrick Steinhardt's v2 series addressing locking races in Git's maintenance operations, specifically focusing on the "gc" task. The patch completes the parallel execution framework work by applying the same phase-split approach used earlier for ref-related tasks to garbage collection.

The key technical change splits the gc task into pre- and post-daemonization phases, mirroring the pattern established in patches 9/12 for pack-refs and reflog-expire. The pre-detach phase (now called `gc_before_detach()`) handles reference maintenance that requires locking, while the post-detach phase runs the actual gc with a new `--skip-maintenance-before-detach` flag to avoid duplicate work. This prevents the same packed-refs.lock/reflog lockfile races that were fixed for other maintenance tasks.

Implementation details include:
- Renaming `gc_before_repack` to `gc_before_detach` for clarity
- Adding the hidden `--skip-maintenance-before-detach` flag to `cmd_gc()`
- Splitting the maintenance task into `maintenance_task_gc_before_detach` and `maintenance_task_gc_after_detach` functions
- Updating test expectations to account for the new flag

The changes maintain backward compatibility while eliminating the race condition. Test coverage is updated to verify the new behavior, though the patch introduces no fundamentally new test cases - it extends the existing framework to cover the gc task's new execution model. This completes the series' architectural work on phase-split execution while leaving the door open for future maintenance task refactoring.
