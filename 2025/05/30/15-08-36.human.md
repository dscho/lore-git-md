This is a refactoring patch in Patrick Steinhardt's maintenance operations series (v2 10/12). It introduces a cleaner way to handle fatal errors when an error message has already been printed.

The patch adds support for `die(NULL)` to avoid hardcoding `exit(128)` in cases where we want to terminate with an error status but have already printed the error message. This eliminates magic numbers and makes the intent clearer. The change is demonstrated by converting several existing `exit(128)` calls in builtins like `am`, `checkout`, `fetch`, and `submodule--helper` to use the new pattern.

The implementation is minimal - just a NULL check in `die_message_builtin()` that skips printing when no message is provided. This maintains all existing behavior while providing a more maintainable alternative to direct exit calls. The patch fits well with the series' focus on systematic improvements to Git's internals.
