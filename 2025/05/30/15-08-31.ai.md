This is a refactoring patch in Patrick Steinhardt's series to fix race conditions in Git's maintenance operations. It specifically addresses the problematic use of global state in task configuration.

The patch eliminates direct modification of the global `tasks[]` array, which previously tracked task state through multiple overlapping fields (`enabled`, `selected_order`, `schedule`). Instead, it introduces a `maintenance_strategy` struct to cleanly represent task configuration and moves the computed task list into the `maintenance_run_opts` structure. The key changes are:

1. Makes the `tasks[]` array `const` since it now only contains immutable task definitions
2. Adds task selection tracking via `opts->tasks` array populated by `initialize_task_config()`
3. Introduces strategy structs (`none_strategy`, `default_strategy`, `incremental_strategy`) to cleanly represent configuration presets
4. Simplifies task execution logic in `maintenance_run_tasks()` to just iterate the pre-computed task list

The patch maintains all existing behavior while making the code more maintainable by:
- Removing implicit state modifications
- Centralizing task selection logic
- Making configuration dependencies explicit
- Adding proper cleanup of allocated memory via `maintenance_run_opts_release()`

This is a foundational change that enables the later race condition fixes in the series by establishing cleaner task management infrastructure. The implementation is thorough, with careful attention to memory management and configuration edge cases.
