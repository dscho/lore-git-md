This is a test infrastructure patch in Patrick Steinhardt's ongoing series to improve TAP output consistency between Make and Meson builds. The patch addresses how the test suite handles unexpectedly passing tests marked with `test_expect_failure`.

Currently, when a test marked as expected-to-fail passes, Git reports it as a "known breakage vanished" but still considers the overall test suite successful. This patch changes that behavior to fail the test suite when such unexpected passes occur, bringing Git's behavior in line with Meson's TAP parser which treats these as failures. The change helps catch regressions that might otherwise go unnoticed, especially in platform-specific cases where tests may pass on some systems but not others.

The implementation modifies `test-lib.sh` to exit with status 1 when `test_fixed` is non-zero, and updates two test cases in `t0000-basic.sh` to use the new `write_and_run_sub_test_lib_test_err` helper that properly captures this behavior. The patch includes rationale about TAP specification interpretation differences between tools and why consistent failure behavior is important for cross-tool compatibility.

This change is part of the broader effort to standardize test output handling across build systems while maintaining test functionality. It follows established patterns from earlier patches in the series and addresses a specific inconsistency that could affect CI results when using Meson. The modification is straightforward and focused, with clear test coverage of the new behavior.
