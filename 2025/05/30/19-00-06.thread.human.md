Kristoffer Haugsbakk reported a bug where `git refs verify` fails (with exit code 255) when checking worktrees created with Git v2.43.0 or older, due to a behavior change in v2.47.0 that expects worktree-specific refs directories to exist. The initial report included test cases demonstrating the issue - one showing the failure when refs directories are missing (as in older worktrees), and another verifying correct behavior when refs exist.

Eric Sunshine reviewed the test cases and confirmed the bug is genuine, but suggested several improvements to make the tests clearer and more maintainable. He noted the first test correctly demonstrates the failure case but includes unnecessary branch creation, while the second test contains some dead code and unclear intent. Sunshine recommended using `git rev-parse --git-dir` instead of hardcoded paths. The discussion remains focused on improving the test quality rather than proposing a solution to the underlying compatibility issue, which remains open.
