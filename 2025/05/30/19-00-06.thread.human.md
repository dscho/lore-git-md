This thread documents a bug in `git refs verify` that affects older-format worktrees (created with Git v2.43.0 or earlier) when checked with Git v2.48.0+. The issue occurs because v2.48.0's ref backend changes made the command check worktree refs, causing it to fail when encountering missing refs directories in these older worktrees - even though core functionality like `git fsck` still works fine.

Kristoffer Haugsbakk originally reported the issue, and Shejialuo developed the fix through several iterations. The solution modifies `files_fsck_refs_dir()` to specifically ignore ENOENT errors for linked worktrees while maintaining strict error checking elsewhere. Eric Sunshine provided key improvements to the test case, ensuring proper isolation with subshells and correct path resolution via `git rev-parse --git-dir` rather than hardcoded paths.

The patch has gone through thorough review, with Patrick Steinhardt emphasizing safety considerations (keeping the ENOENT check before the worktree check) and Phillip Wood proposing alternative approaches before agreeing on the final implementation. Junio C Hamano has approved the technical direction. All feedback has been incorporated, and the commit message properly references both the commit that introduced the behavior change (7c78d819e6a) and the original worktree refs commit (8f4c00de95).
