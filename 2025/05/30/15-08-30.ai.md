This is a patch in Patrick Steinhardt's series fixing race conditions in Git's maintenance operations, specifically addressing command-line option validation. The patch makes `--task=` and `--schedule=` mutually exclusive options for `git maintenance run`, since they represent fundamentally different ways to select tasks (explicit selection vs. strategy-based scheduling). It also modernizes the existing `--auto`/`--schedule` conflict check to use Git's standard `die_for_incompatible_opt2()` helper.

The changes are straightforward: the option validation moves from a direct `die()` call to the more maintainable helper function, and a new validation is added for the task/schedule conflict. The test suite is extended to verify both cases, with error message expectations updated to match the new helper's standard phrasing ("cannot be used together" rather than "at most one").

This patch continues the series' theme of cleaning up maintenance task configuration logic, though it's more about user interface consistency than the core race condition fixes that come later in the series. The changes are mechanical and unlikely to be controversial, with clear test coverage showing the intended behavior. As with earlier patches in the series, the focus remains on eliminating potential confusion points in the maintenance command's operation.
