This is a refactoring patch in Patrick Steinhardt's maintenance operations series, introducing a new way to handle error exits without duplicate error messages.

The patch adds support for `die(NULL)` as a way to exit with error code 128 without printing an additional error message, replacing direct `exit(128)` calls in several builtins. This addresses cases where the code has already printed an error but needs to use Git's standard error exit code. The change is minimal but touches multiple commands (`am`, `checkout`, `fetch`, and `submodule--helper`) that had been using the raw exit code.

Key technical details:
- Modifies `die_message_builtin()` in `usage.c` to no-op when passed NULL
- Updates 5 files with 11 line changes (mostly replacing `exit(128)` with `die(NULL)`)
- Preserves existing error reporting while eliminating magic numbers
- Maintains identical behavior to previous `exit(128)` calls

This fits into the series' broader goal of cleaning up maintenance operations by standardizing error handling patterns. While not directly related to the locking race conditions addressed in other patches, it demonstrates the same careful attention to code quality and consistency seen throughout the series. The change is straightforward and unlikely to be controversial, though reviewers might want to verify the NULL case doesn't mask any important error contexts.
