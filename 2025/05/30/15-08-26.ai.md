This is the cover letter for v2 of Patrick Steinhardt's 12-patch series addressing ref lock races in Git's maintenance operations. The series builds on the previous 11-patch version with some refinements and additions.

The core issue remains fixing race conditions around packed-refs locking during auto-maintenance, particularly when maintenance tasks detach to run in the background. The series restructures task execution into "before detach" and "after detach" phases to safely handle reference operations.

Key changes in v2 include:
- Commit message improvements throughout
- Introduction of `die(NULL)` to exit cleanly without error messages
- Addition of an enum to clearly distinguish task phases (before/after detach)
- Patch 10 is new, adding the `die(NULL)` capability
- Patches 11-12 now use `die(NULL)` instead of `exit(127)`
- Several typo fixes from v1 have been incorporated

The series maintains its logical progression from refactoring (patches 1-2) through configuration improvements (3-5) to execution logic changes (6-8) and finally the concrete race fixes (9-12). The split-phase model introduced in patch 8 remains the architectural centerpiece, now with cleaner phase tracking via the new enum.

Technical scope remains focused on `builtin/gc.c` with supporting changes. The implementation continues to eliminate global state while maintaining behavior, bringing git-maintenance's locking safety in line with git-gc. Test coverage appears thorough, with the range-diff showing only expected adjustments to the implementation details.

This version appears ready for review, with all known issues from v1 addressed. The changes are focused and maintain the series' clear technical direction while improving code quality and documentation.
