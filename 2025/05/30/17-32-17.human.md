Bugfix for a memory leak in `imap-send`'s CRAM-MD5 authentication. This is part of Aditya Garg's v9 series improving IMAP functionality, which has already addressed several critical issues in the subsystem.

The patch fixes a case where the `response` buffer allocated during CRAM-MD5 authentication would leak if the socket write operation failed. The fix is straightforward - adding a `free(response)` call in the error path before returning. This matches the existing cleanup that happens on the success path.

While small (just 4 lines changed), this completes the memory leak fixes for CRAM-MD5 that were part of the series' goals. The change is low-risk since it only affects an error path and maintains the existing behavior when authentication succeeds. This appears to be one of the final polish items in what has been a thorough and well-reviewed series.
