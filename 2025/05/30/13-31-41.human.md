This is a test infrastructure patch in Patrick Steinhardt's ongoing series to improve TAP compliance in Git's test suite. The patch focuses on t9822-git-p4-path-encoding.sh, which tests handling of non-ASCII paths in git-p4.

The change converts an ad-hoc filesystem capability check for ISO-8859-1 filename support into a proper test prerequisite using test_lazy_prereq. This ensures the test's TAP output remains clean when the prerequisite fails, rather than printing directly to stderr. The functionality remains the same - tests will be skipped if the filesystem can't handle ISO-8859-1 encoded filenames - but now handles the output in a TAP-compliant way.

This is a straightforward mechanical conversion that follows the pattern established in earlier patches of the series. It's a small but meaningful improvement that helps standardize test output formatting, particularly important for the Meson build system integration work. The change is well-contained and unlikely to be controversial, continuing the series' focus on TAP output purity without affecting test behavior.
