This is a refactoring patch in Patrick Steinhardt's series addressing maintenance operation race conditions. It introduces a split between maintenance tasks that should run before and after daemonization to prevent reference locking issues.

The patch modifies the `maintenance_task` struct to track separate function pointers for pre- and post-detach phases, replacing the single `fn` member with `before_detach` and `after_detach` variants. All existing tasks are initially assigned to run only after detach (maintaining current behavior), with the infrastructure now in place to add pre-detach tasks later. The `maybe_run_task()` helper is updated to accept a `task_phase` enum parameter and select the appropriate function pointer.

Key technical changes include:
- New `task_phase` enum distinguishing `TASK_PHASE_BEFORE_DETACH` and `TASK_PHASE_AFTER_DETACH`
- Updated trace2` region labels to reflect execution phase
- Split task execution loop in `maintenance_run_tasks()` to run pre-detach tasks first
- Preserved behavior by keeping all tasks in post-detach phase for now

This prepares for future patches that will move reference-related tasks (like `pack-refs` and `reflog-expire`) to run before detach, addressing the "packed-refs" locking issue mentioned in the commit message. The change is part of a larger effort to make maintenance operations safer when run automatically in the background.
