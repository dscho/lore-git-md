This is a follow-up discussion in Patrick Steinhardt's ongoing test infrastructure series, specifically addressing Python version detection in the test suite. The exchange focuses on patch 4/10 which standardizes Python version checking for git-p4 tests using the test prerequisite system.

Todd Zullinger points out a typo in the commit message where "git-b4" was written instead of "git-p4", which Patrick acknowledges was due to his frequent use of the b4 tool. More significantly, Todd raises the question of whether Git should still maintain Python 2 support given its EOL status in 2022, noting that major distributions like Debian Bullseye and RHEL 8 now include Python 3.9.

Patrick agrees there's likely no need to keep Python 2 support, mentioning that while it's still tested in Ubuntu 20.04 CI jobs, that alone isn't sufficient justification to maintain it. He indicates he'll wait for more feedback before sending an updated version of the patch series. The discussion suggests this may lead to future simplification of Python-related test infrastructure, though that would be handled separately from the current TAP compliance improvements.
