Feature addition to `imap-send` in v9/9 of the series, introducing folder listing capability. This final patch adds a `--list` option that shows available IMAP folders with their server-specific names, addressing the common issue where users struggle to identify the correct folder names (like Gmail's "[Gmail]/Drafts" vs Outlook's "Drafts"). 

The patch implements RFC6154-compliant LIST command handling for both OpenSSL and libcurl backends, with consistent output formatting showing folder flags and hierarchy. The implementation includes documentation updates suggesting `--list` as a troubleshooting aid when folder names aren't obvious. The verbose output shows raw IMAP responses including system flags like `\HasNoChildren` and `\Sent`.

Technical changes span `imap-send.c` with 98 lines added/modified, introducing a new `list_folders` flag, separate execution paths for listing vs sending, and backend-specific implementations. The OpenSSL path reuses existing IMAP command infrastructure while the libcurl version adapts documented examples. Error handling maintains consistency with the rest of the series.

This concludes the v9 series that has evolved through extensive review, now providing comprehensive IMAP functionality including OAuth2.0 auth, configuration fixes, and this user-facing discovery tool. The only outstanding architectural question remains the long-term maintenance of dual backends.
