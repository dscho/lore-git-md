This is a refactoring patch in Patrick Steinhardt's series addressing maintenance task race conditions. It introduces a split between maintenance tasks that should run before and after daemonization (detaching to run in the background), though no actual task behavior is changed yet.

The patch restructures the `maintenance_task` struct to separate function pointers for pre-detach and post-detach phases, with all existing tasks currently assigned to run after detach. A new `task_phase` enum and modified `maybe_run_task()` helper implement the phase distinction, while maintaining identical runtime behavior for now.

This prepares for fixing reported issues where background maintenance tasks could lock the packed-refs file too long, blocking other Git operations. The change follows the split that already existed in `git gc` but was lost when maintenance tasks moved to `git maintenance`. The commit message clearly explains the motivation and notes this is purely preparatory - actual task reassignment will come in later patches.

The changes are methodical and well-contained, touching only `builtin/gc.c` with clear trace2 region labeling for the new phases. This continues the series' pattern of careful infrastructure improvements before behavioral changes.
