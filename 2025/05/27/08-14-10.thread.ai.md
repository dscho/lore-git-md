Bug report: pathspec handling regression in empty repositories with `git add --update` and exclude patterns. Regression introduced in Git 2.45.0, persisting through 2.49.0.1266. Original report from Piotr Siupa demonstrated duplicate error messages for commands like `git add --update -- ':(exclude)foo'` in empty repositories, while working correctly in pre-2.45.0 versions. Phillip Wood initially responded, agreeing the behavior is inconsistent but suggesting the deeper issue may be that Git should error when exclude patterns match nothing, even in non-empty repos. He contrasted current behavior where `git add -u does-not-exist` errors versus `git add -u ':(exclude)*'` silently succeeding when excluding all files.

Junio Hamano now weighs in, disagreeing with Phillip's proposal for consistent error behavior. He argues exclude patterns should remain silent when they match nothing, distinguishing them from positive pathspecs where no matches likely indicate user error. Junio cites the common case of `git add -- \*.c ':!auto-generated.c'` where silent non-matching excludes are desirable - if there's no auto-generated.c, that's the expected outcome. He draws parallels to .gitignore behavior where non-matching patterns are silently accepted. The empty repository case that started the thread remains unaddressed in this response, but the principles discussed would apply there.

Open questions now include: whether to treat this as a bugfix (restoring pre-2.45.0 behavior) or behavior improvement, how to handle the implicit pathspec interaction in empty repositories, and whether to maintain the distinction between positive and negative pathspec matching semantics. The discussion has shifted from a technical regression to a philosophical debate about pathspec design, with Phillip Wood advocating for consistency and Junio Hamano for practical distinction between pattern types. No resolution yet on how to handle the original empty-repo case while respecting these differing perspectives.
