Bug report: pathspec handling regression in empty repositories with `git add --update` and exclude patterns. Regression introduced in Git 2.45.0, persisting through 2.49.0.1266. Original report from Piotr Siupa demonstrated duplicate error messages for commands like `git add --update -- ':(exclude)foo'` in empty repositories, while working correctly in pre-2.45.0 versions. Phillip Wood responds, agreeing the behavior is inconsistent but suggesting the deeper issue may be that Git should error when exclude patterns match nothing, even in non-empty repos. He contrasts current behavior where `git add -u does-not-exist` errors versus `git add -u ':(exclude)*'` silently succeeding when excluding all files. Discussion now reframed from fixing a regression to potentially changing expected behavior - proposing pathspec matching should consistently error when no files remain after exclusions, regardless of repository state. The empty-repo case remains uniquely problematic due to its interaction with the implicit '.' pathspec. Open questions: whether to treat this as a bugfix (restoring pre-2.45.0 behavior) or behavior improvement (making exclude patterns consistently strict), and how to handle the implicit pathspec interaction in empty repositories. Phillip Wood is the primary participant so far; no other contributors have weighed in yet on his proposed direction.
