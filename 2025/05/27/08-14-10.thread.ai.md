Bug report: pathspec handling regression in empty repositories with `git add --update` and exclude patterns, introduced in Git 2.45.0 and persisting through 2.49.0.1266. Original report from Piotr Siupa demonstrated duplicate error messages for commands like `git add --update -- ':(exclude)foo'` in empty repositories, while working correctly in pre-2.45.0 versions. 

Discussion has evolved from technical regression to design philosophy debate around pathspec vs. exclude pattern semantics. Phillip Wood initially suggested making exclude patterns error when matching nothing, similar to positive pathspecs, but Junio Hamano strongly disagreed, arguing exclude patterns should remain silent when they match nothing - citing common workflows like `git add -- \*.c ':!auto-generated.c'` and parallels to .gitignore behavior. Piotr Siupa reinforced Junio's position with practical scripting examples, noting erroring on unmatched excludes would break existing scripts and require workarounds.

Emerging consensus favors maintaining current behavior for exclude patterns (silent when no matches) while keeping error behavior for positive pathspecs. Key technical points: exclude patterns serve different purpose than positive pathspecs, silent non-matches are expected in scripting contexts, and changing this would break existing workflows. The original empty-repo regression case remains technically unresolved but appears likely to be fixed in a way that preserves these semantics. Next steps may involve documenting the intended behavior more clearly while addressing the empty-repo edge case that triggered the report. Participants: Piotr Siupa (reporter), Phillip Wood (initial responder advocating consistency), Junio Hamano (maintainer position favoring practical distinction).
