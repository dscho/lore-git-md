This is a follow-up discussion in the `git last-modified` feature series, focusing on input validation in the revision walk initialization.

Patrick Steinhardt responds to Toon Claes's patch that modified the revision walk initialization for the `git last-modified` command. The change removed the need for full `prepare_revision_walk()` initialization by using the `no_walk` flag, but this had the side effect of silently accepting non-commit inputs that would previously have been rejected.

Patrick questions whether this silent acceptance is the right behavior, suggesting that explicitly validating inputs to ensure they're commits would be better than silently ignoring invalid ones. This comes as part of the ongoing polish phase for the series, where core functionality is established but implementation details are being refined.

The thread context shows this is one of several remaining code quality improvements being discussed before the experimental feature can be finalized. Other open items include documentation fixes, performance optimizations, and naming improvements from multiple reviewers. The discussion remains focused and technical, with all major architectural questions already resolved in prior rounds.
