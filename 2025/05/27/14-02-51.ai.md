This is a test infrastructure patch in Patrick Steinhardt's ongoing series to improve TAP output compliance. The patch specifically addresses a TAP formatting issue in the test suite's Bash trace handling.

The change modifies a warning message about unsupported BASH_XTRACEFD functionality to be TAP-compliant by adding a "#" prefix, which marks it as a diagnostic comment in the TAP protocol. The warning appears when running tests with `-x` tracing on older Bash versions that don't support the BASH_XTRACEFD feature. Without this prefix, the warning would corrupt the TAP output stream that test harnesses parse.

This is a mechanical fix that maintains the same functionality while making the output properly structured. It's part of a larger effort (now 6 patches in v2) to standardize test output for better compatibility with TAP parsers, particularly in the Meson build system context. The change is straightforward and uncontroversial, following the same pattern as other TAP formatting fixes in the series.

Key technical details:
- Modifies t/test-lib.sh
- Changes warning message format but not behavior
- Maintains backward compatibility
- Follows established TAP v14 spec for diagnostic comments
- Part of broader test infrastructure improvements

The patch fits cleanly into the series' goal of strict TAP validation while preserving existing functionality. It addresses one of the remaining edge cases where non-TAP output could appear in the test stream.
