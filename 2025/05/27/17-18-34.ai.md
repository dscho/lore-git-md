This is a follow-up discussion in the notes editor whitespace bugfix thread, where Junio Hamano weighs in on the technical approach and broader implications.

The email contains two key technical points. First, Junio agrees with Phillip Wood's earlier suggestion that whitespace stripping should happen on the raw commit message buffer (`buf`) rather than the commented buffer (`cbuf`), as this provides better separation of concerns. Second, he confirms the POSIX compliance of using a lone `$` in test patterns, validating the test methodology.

Junio expresses reservations about the patch's motivation, suggesting the indented whitespace in editor templates might actually be useful visual markers for commit message boundaries. He proposes two alternative solutions: either fixing the editors that complain about trailing whitespace, or modifying `git show`'s output formatting to avoid indenting empty lines - suggesting this could be implemented similarly to the existing `expand_tabs_in_log` handling in `pretty.c`.

The discussion shows the patch is technically sound but reveals deeper questions about whether the change is desirable at all. While the immediate technical questions about implementation approach and test portability are resolved, Junio's comments introduce new considerations about the patch's fundamental purpose and potential alternatives. This shifts the thread from implementation details to design philosophy, though no concrete objections to merging the current approach are raised.
