This is a follow-up in the thread about HEAD.lock contention between user operations and maintenance processes. Emily Shaffer from Google confirms they've encountered similar issues in the past with maintenance processes causing lock contention, corroborating Patrick Steinhardt's diagnosis of the race condition. The discussion centers around maintenance running in detached mode (`--auto --detach`) spawning git-gc which locks packed-refs, conflicting with concurrent ref operations like checkout.

Key technical points from this email:
- Google had experienced similar problems about a year prior, though it's unclear if there was public discussion about it
- The issue manifests when maintenance tasks (particularly ref packing) run concurrently with user operations that need to modify locks
- Patrick has proposed a solution involving modifying git-maintenance to handle ref-packing tasks before daemonization
- Emily expresses interest in Patrick's upcoming patch series to address this

The email doesn't introduce new technical details but provides important validation from a major Git user (Google) that this is a real-world problem affecting production systems. This lends additional weight to the need for Patrick's proposed fix. The thread remains focused on the technical solution rather than debating the problem's existence or severity.
