This is the 10th patch in Patrick Steinhardt's series fixing race conditions in Git's maintenance operations, specifically addressing the `git gc` command's handling of ref locking. The patch refactors `gc_before_repack()` to eliminate its use of a static flag for preventing duplicate execution, instead making the duplicate call prevention explicit through the `opts.detach` flag.

The key changes are:
1. Removing the static `done` flag from `gc_before_repack()`
2. Converting the function to return an error code instead of calling `die()`
3. Making the second call conditional on `opts.detach <= 0` in `cmd_gc()`
4. Updating error handling to exit with status 127 on failure

This continues the series' pattern of making maintenance operations more robust by properly sequencing operations between foreground and background processes. The change is focused entirely within `builtin/gc.c` and doesn't require test updates. The patch demonstrates good attention to detail by maintaining the same error semantics while making the control flow more explicit and removing global state.
