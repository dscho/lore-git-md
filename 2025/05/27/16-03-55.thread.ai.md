Thread identity: Feature proposal from Jon Forrest about `git commit` behavior, suggesting adding a `-A` option to stage new files automatically alongside `-a`'s behavior.

Core problem: `git commit -a` only stages modifications to tracked files, not new untracked files, which can surprise users expecting more comprehensive staging. The proposal suggests `git commit -A` would behave like `git add -A` vs `git add -u` - staging both modified tracked files and new untracked files.

Current status: Initial proposal stage, no implementation or discussion yet. Backward compatible as it adds rather than changes behavior.

Key technical details: Would modify `builtin/commit.c` to add new flag handling parallel to `-a` but with `ALL` semantics. Behavior would mirror `git add -A` vs `-u` distinction.

Open questions: How to handle ignored files (should they be included like `git add -A` does?), whether to maintain exact `git add -A` parity, potential edge cases around partial staging.

Participant positions: Only Jon Forrest so far, proposing the change as a UX improvement particularly for users coming from other VCS systems.
