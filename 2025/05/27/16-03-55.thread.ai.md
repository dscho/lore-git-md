Core problem: `git commit -a` only stages modifications to tracked files, not new untracked files, which can surprise users expecting more comprehensive staging. The proposal suggests `git commit -A` would behave like `git add -A` vs `git add -u` - staging both modified tracked files and new untracked files. Historical analysis reveals this behavior dates to Git's 2005 implementation and was influenced by early lack of `.gitignore` functionality, with Junio C Hamano now clarifying additional constraints around `git add -N` marked files and introducing new considerations about conflict marker handling.
