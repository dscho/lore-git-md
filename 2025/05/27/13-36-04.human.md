This is a philosophical discussion about test runner behavior in the ongoing Meson integration series. Junio Hamano and Patrick Steinhardt are examining how different test runners handle "unexpected passes" (tests marked TODO that unexpectedly succeed) and whether this divergence should be standardized.

The key point centers on interpretation of the TAP specification, which states that harnesses "may" report unexpected passes but doesn't mandate how. Steinhardt notes this creates undefined behavior, with Meson choosing to fail on unexpected passes while make/prove silently accepts them. The discussion has evolved from technical implementation to broader test infrastructure philosophy, with multiple contributors (including Phillip Wood and Eli Schwartz) advocating for stricter validation.

This email doesn't introduce new code changes but deepens the standards discussion, highlighting that the TAP spec leaves TODO test success handling deliberately open. The thread shows consensus forming around failing on unexpected passes, though the final decision remains with Junio Hamano as maintainer. The exchange demonstrates how the Meson transition is prompting reevaluation of long-standing test infrastructure assumptions.
