Junio C Hamano has weighed in further on the discussion about `git commit -a` behavior and the proposed `-A` option. While not directly addressing the `-A` proposal, he defends the current `-a` behavior as useful for focused workflows like merging, where it works well with pre-commit hooks to catch conflict markers. He introduces a new technical consideration - the potential value of a `pre-add` hook to prevent accidental staging of conflicted files, which current `git add -u` allows. This highlights another dimension where staging behavior matters, though it doesn't resolve the core question about adding `-A`.

The discussion remains at an impasse regarding whether to add the `-A` option. Jon Forrest's proposal maintains that it would be a strictly additive UX improvement, while others question its necessity given users can already achieve similar results with `git add -A && git commit`. Junio appears open to the change if it remains purely additive, but his latest email suggests alternative approaches (like improved hooks) might address some of the underlying concerns without modifying commit behavior. The technical constraints around `git add -N` and ignored files are now well-documented, leaving the decision to hinge on whether the project sees sufficient value in the new option.
