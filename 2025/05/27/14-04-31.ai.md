This is a refactoring patch in the ongoing series addressing race conditions in Git's maintenance operations. It's the fifth in an 11-part series that restructures how maintenance tasks handle ref locking during auto-maintenance.

The patch eliminates direct modification of the global `tasks` array in `builtin/gc.c`, which previously used three separate fields (`enabled`, `selected_order`, and `schedule`) to track task execution state. Instead, it introduces a new approach where task configuration is computed once in `initialize_task_config()` and stored in the options structure as an array of tasks to run. This makes the logic more self-contained and easier to follow.

Key technical changes include:
- Moving task state from global `tasks` array to `maintenance_run_opts` structure
- Introducing `maintenance_strategy` struct to encapsulate task configuration
- Adding `maintenance_run_opts_release()` to clean up allocated memory
- Simplifying task execution logic in `maintenance_run_tasks()` to just iterate the pre-computed task list
- Maintaining the same behavior for task selection via config, command line, and schedules

The changes are focused on `builtin/gc.c` and don't require test updates since the behavior remains the same - this is purely an internal restructuring. The patch follows logically from the previous ones in the series, continuing the pattern of centralizing and simplifying maintenance task configuration before the later patches implement the core race condition fixes.
