This is a feature request proposing an enhancement to `git add -p`'s behavior with conflicted files. 

Currently, Git excludes files with merge conflicts from `git add` operations by default, which makes sense for most workflows. However, the author points out that this behavior may be unnecessarily restrictive when using the interactive patch mode (`-p`), where users review changes chunk-by-chunk. The current behavior forces users to add conflicted files manually without benefiting from patch mode's granular control.

The proposal suggests making `git add -p` work with conflicted files, allowing users to selectively stage conflict resolutions while still getting the interactive review experience. The author notes this would eliminate the current workaround of manually copying filenames for staging, while maintaining safety since patch mode already provides careful review of each change.

This appears to be a well-motivated quality-of-life improvement for users who frequently resolve conflicts. The suggestion is focused and doesn't seem controversial, though it would need implementation that preserves the safety of conflict resolution workflows. The email is concise and clearly explains both the current pain point and proposed solution.
