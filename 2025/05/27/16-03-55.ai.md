This is a feature proposal questioning Git's current behavior and suggesting an enhancement. The email comes from Jon Forrest, who notes that `git commit -a` doesn't add new files despite what some users might expect, and proposes adding a `-A` variant that would include new files in the commit.

The core observation is that `git commit -a` only stages modifications to tracked files, not new untracked files, which can be surprising to some users. The proposal suggests introducing `git commit -A` as a parallel option that would behave like `-a` but also automatically stage new files, similar to how `git add -A` works compared to `git add -u`.

This appears to be a well-motivated suggestion that could improve user experience, particularly helping those transitioning from other VCS systems where similar commands might have different semantics. The change would be backward compatible since it introduces a new flag rather than modifying existing behavior. The proposal is straightforward but doesn't include implementation details or discuss potential edge cases like ignored files.
