This is part 3 of an 11-patch series fixing race conditions in Git's maintenance operations around ref locking. The series is restructuring how maintenance tasks are executed to properly handle reference locking during auto-maintenance.

This patch centralizes the configuration of explicitly requested maintenance tasks (via `--task=` options) by moving the task selection logic from `task_option_parse()` to `initialize_task_config()`. Previously, each `--task` option would immediately modify global state by setting task selection order. Now, the options are collected in a string list first, with the actual configuration happening later in a single place.

The change makes the code easier to follow by:
1. Removing global state modifications during option parsing
2. Consolidating task configuration logic in one function rather than spreading it across multiple locations

This is a preparatory refactoring that doesn't change behavior - it sets up for subsequent patches that will implement the core race condition fixes. The patch is cleanly focused and well-explained, with clear motivation for the immediate change and how it fits into the larger series.
