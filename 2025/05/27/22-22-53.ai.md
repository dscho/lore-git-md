This is a conceptual follow-up to the notes editor whitespace discussion, proposing an alternative architectural approach via the pretty-printing subsystem. 1. Add new `--[no-]indent-empty-lines` options
2. Introduce `indent_empty_lines` flags in `rev_info` and `pretty_print_context`
3. Modify `pp_remainder()` in `pretty.c` to respect the new setting
4. Update `builtin/notes.c` to use `--no-indent-empty-lines`

The implementation touches 7 files but is incomplete - lacking tests, documentation, and configuration support. This represents a more invasive but potentially more maintainable solution than the current `notes.c`-specific fix, though the author had previously rejected similar `pretty.c` changes as "scary". The patch serves primarily to illustrate the technical feasibility rather than as a serious proposal - Junio states he won't be pursuing this direction immediately.

Key technical elements:
- New `indent_empty_lines` flags propagate through revision/pretty stack
- `pp_remainder()` gains conditional logic for blank lines
- Changes would affect all pretty-printed output, not just notes
- Would require new config/CLI controls to be fully usable

The discussion remains at an architectural exploration stage, with the simpler `notes.c` solution still favored by the immediate issue's author.
