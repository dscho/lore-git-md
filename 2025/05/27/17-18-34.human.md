This is a follow-up discussion in the notes editor whitespace bugfix thread. Junio Hamano weighs in on Phillip Wood's suggestion to strip whitespace from commit messages before commenting them out, rather than after. 

Junio expresses reservations about the original patch's approach, suggesting that the consistent indentation in commit message output serves a useful purpose by clearly delineating message boundaries. He proposes two alternative solutions: either fixing the editors that complain about trailing whitespace, or modifying the indentation logic in `git show` to skip indenting empty lines (similar to how tab expansion is handled in `pretty.c`).

The discussion also confirms that the test pattern using a lone `$` is POSIX-compliant, resolving a previous question about shell interpretation. This thread shows the patch is still under consideration, with maintainers exploring alternative approaches that might better preserve the visual structure of commit messages while addressing the whitespace issue. The technical merits of each approach are being carefully weighed.
