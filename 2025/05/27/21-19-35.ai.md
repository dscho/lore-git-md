This is a documentation patch in a series improving `--stdin` usage documentation in git-notes, now at v3. The patch specifically clarifies the default behavior of `--stripspace` and documents a subtle interaction between options.

The patch makes two key documentation improvements: First, it explicitly states that `--stripspace` is the default behavior for most git-notes operations except when using `-C/--reuse-message`. Second, it documents a known limitation where option ordering affects behavior - for example, using `-C` followed by `-m` will apply `--stripspace` because `-m`'s default overrides `-C`'s implicit `--no-stripspace`. The commit message notes this may be fixed in future.

The change follows Junio Hamano's earlier feedback to clearly document which option variants (regular or negated) are defaults. The patch adds a new section to git-notes.adoc with a bulleted list of whitespace cleaning behaviors (matching git-stripspace(1)) and the new default behavior explanation. The "known limitation" wording addresses Junio's concern about the option ordering being potentially problematic implementation behavior.

This is part of a comprehensive documentation effort that has gone through multiple rounds of review, with all feedback incorporated. The series appears ready for merging, with this patch completing the documentation of default behaviors and edge cases around `--stripspace` in git-notes operations.
