This thread began with Piotr Siupa reporting a regression in `git add --update` behavior when using exclude patterns in empty repositories, where Git 2.45.0+ shows duplicate error messages compared to pre-2.45.0 versions. Phillip Wood agreed the behavior was inconsistent but suggested a deeper change: making Git error when exclude patterns match nothing, even in non-empty repos, for consistency with how positive pathspecs work.

Junio Hamano has now weighed in, opposing Phillip's proposal. He argues that exclude patterns should remain silent when they match nothing, drawing a distinction between positive pathspecs (where no matches likely indicate a user error) and exclude patterns (where empty matches are often intentional). Junio points to `.gitignore` behavior as precedent and gives the example of `:!auto-generated.c` - if no such file exists, that's fine since the user didn't want to add those files anyway.

The discussion has shifted from fixing a specific regression to debating broader pathspec semantics. While the original issue in empty repositories remains unresolved, Junio's response suggests he favors keeping the current exclude pattern behavior rather than making it stricter. The key open question is whether to treat this as a bug to fix (restoring pre-2.45.0) or as an opportunity to improve pathspec consistency - with Phillip and Junio representing different perspectives on what "improvement" would mean.
