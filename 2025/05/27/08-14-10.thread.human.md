This thread began with Piotr Siupa reporting a regression in Git 2.45.0 where `git add --update` with exclude patterns in empty repositories produced duplicate error messages, a behavior that didn't occur in earlier versions. The discussion quickly expanded beyond the technical bug to examine the fundamental design of pathspec handling, particularly how exclude patterns should behave when they match nothing.

Phillip Wood initially suggested making exclude patterns error on no matches, similar to positive pathspecs, for consistency. However, Junio Hamano strongly opposed this, arguing that exclude patterns serve a different purpose and should remain silent when they match nothing—just as .gitignore does. Piotr Siupa later reinforced this position with practical examples showing how erroring on unmatched excludes would break existing scripts. The most recent email was a technical resend with no new content, indicating the discussion has stabilized.

The emerging consensus is to maintain the historical behavior where exclude patterns stay silent on no matches, as this aligns with common workflows and .gitignore semantics. While the original empty-repository regression still needs to be fixed, the broader design question appears settled in favor of Junio's practical approach. The next steps will likely involve documenting this intended behavior clearly while addressing the specific edge case that triggered the report.
