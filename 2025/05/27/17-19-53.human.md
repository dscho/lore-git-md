This is a discussion about test infrastructure and path resolution in Git's test suite, specifically around the handling of symlinks and canonical paths.

Junio Hamano responds to Mark Mentovai's concerns about forcing canonical paths in the test suite. Junio argues that ensuring tests run from canonical paths is an effective way to prevent mysterious failures that depend on where the repository is checked out. He points out that the current test-lib.sh already tries to align `$PWD` with the physical world via `cd -P`, but does so inconsistently with `$HOME` setting - a bug his proposed fix would address.

Junio makes a key distinction between test infrastructure bugs (like the current issue) and actual Git bugs in path resolution. He suggests that if Git itself handles non-canonical paths correctly should be tested explicitly through dedicated tests, not by leaving the test infrastructure in a state that might expose such edge cases incidentally. This would allow systematic testing of path resolution while keeping the general test environment more predictable.

The exchange highlights the ongoing tension between test consistency and edge case coverage. Junio's position favors infrastructure-level solutions that reduce variability, while Mark seems to prefer targeted fixes that preserve the ability to catch path-related bugs organically. The technical discussion remains focused on how to best serve both goals without compromising either test reliability or coverage.
