Refactoring patch in a series addressing maintenance task race conditions.

This second patch in the 11-part series simplifies the quiet mode handling in `git gc` by removing a redundant local variable. The code previously maintained two separate `quiet` flags - a local variable and a field in `struct maintenance_run_opts` - which could lead to confusion about which one controlled which behavior. The patch consolidates this by using only the struct field, updating all references to the local variable to instead use `opts.quiet`.

The changeset is mechanical but meaningful, touching 6 locations in `builtin/gc.c` where the quiet flag affects behavior: progress reporting for repacking, background operation notifications, prune operations, and commit graph writing. The patch maintains all existing functionality while making the code more straightforward by having a single source of truth for the quiet setting.

This change fits into the series' broader goal of cleaning up maintenance task execution logic before introducing the core fixes for ref locking races. It follows the initial modernization of task array initialization (patch 1) and precedes more substantial restructuring of task configuration and execution. The commit message clearly explains the motivation and effect without needing to reference the larger series context.
