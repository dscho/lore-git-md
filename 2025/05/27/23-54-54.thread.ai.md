Thread identity: Feature request to modify `git add -p` behavior regarding merge conflicts, from Jarrad Whitaker, with technical analysis from Chris Torek.

Core problem: Proposal to allow `git add -p` on files with merge conflicts, which currently fails. Torek's analysis reveals this requires fundamental changes to Git's index model where conflicted files exist in stages 1-3 (base/ours/theirs) while `git add -p` assumes stage 0 (unconflicted) state.

Current status: Initial proposal met with detailed technical constraints. No implementation exists yet. The challenge is architectural rather than just UI - would require changing how the index represents partially resolved conflicts.

Key technical details: Current index cannot simultaneously represent conflict state (stages 1-3) and partial resolution (stage 0). Supporting the feature would need either:
1. Parallel representation of conflict markers and partial resolution (breaking current mutual exclusivity of stages)
2. New index representation for conflicts
Also impacts `git restore` and other commands expecting atomic conflict resolution via `git add`.

Open questions: Whether to pursue index modifications given architectural impact. How to handle edge cases where partial resolution interacts with remaining conflicts. Phillip Wood's input needed on interactive add implications.
