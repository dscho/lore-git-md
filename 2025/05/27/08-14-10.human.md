Bugfix for `git add --update` with exclude pathspecs in empty repos. 

Piotr Siupa reports a regression introduced in Git 2.45.0 where using `git add --update` with an exclude pathspec (like `:(exclude)foo`) in a completely empty repository fails with confusing error messages. The command works fine once the repo contains any files (even untracked ones via `git add -N`) or has commits, regardless of whether those files match the exclude pattern.

The error manifests as two messages: first complaining about the exclude pathspec not matching, then about the implicit '.' pathspec failing. This appears to be a regression from earlier Git versions where this combination worked correctly. The bug seems to be triggered by the empty repository state rather than the pathspec itself, suggesting an edge case in how `--update` handles the empty working tree scenario.

The report includes clear reproduction recipe and version information (affects 2.45.0 through current next). This looks like a legitimate bug that could trip up users scripting around empty repos, though the workaround (adding any file) is simple. The patch would likely need to adjust how `--update` validates pathspecs in the empty-repo case.
