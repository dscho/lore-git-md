Feature proposal discussion about `git commit -A` behavior. Nico Williams responds to Jon Forrest's suggestion for a new `-A` flag that would stage new and modified files, similar to `git add -A` vs `-u`.

Nico expresses strong opposition to changing the existing `-a` behavior, stating it would be "exceedingly annoying" if `git commit -a` started staging new files in their typical workflow of committing in dirty workspaces. This reinforces the need for a new flag rather than modifying existing behavior.

While Nico isn't opposed to adding `-A` as a new option, they indicate they would "almost never use it" themselves. This suggests the feature might have niche appeal rather than broad utility. The response doesn't address any of the technical implementation questions raised in the original proposal about ignored files or edge cases.

The exchange highlights that any implementation would need to maintain clear behavioral separation between `-a` (current modified-files-only behavior) and the proposed `-A` (all-files behavior), as changing the existing `-a` semantics would disrupt established workflows. The discussion remains at the UX level with no new technical details added.
