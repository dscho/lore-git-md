Patrick Steinhardt continues refining his series to fix race conditions in Git's maintenance operations. The latest patch (v2) improves how explicit maintenance tasks are configured when users specify them via `--task` options. Instead of modifying global state during option parsing, the patch now collects tasks in a string list first, then applies the configuration in a centralized location. This cleanup is part of the series' broader effort to restructure maintenance task execution before implementing the core race condition fixes.

The series has evolved through two versions, with v2 incorporating feedback and adding documentation improvements. The architectural approach remains focused on establishing a clean framework for task execution, with the split-phase model being a key component. The changes so far - including this latest refactoring - are preparatory work that improves code quality without altering external behavior, setting the stage for the subsequent race condition fixes that will make reference operations safe during auto-maintenance.
