Patrick Steinhardt's maintenance task refactoring series has reached its final form in v4, systematically addressing race conditions while improving code quality. The 12-patch series takes a three-pronged approach: fixing core race conditions, improving terminology around task execution phases, and refactoring internals for better type safety and error handling.

The series culminates with the "gc" task being split into foreground and background phases, mirroring earlier work on "pack-refs" and "reflog-expire". The foreground phase now handles ref packing and reflog expiration (critical for lock safety), while background runs the actual GC with a new `--skip-foreground-tasks` flag. This completes the elimination of lockfile races across all maintenance operations.

Key technical improvements include converting global state patterns to explicit control flow (notably in `gc_before_repack()`), standardizing error handling via `die(NULL)`, and introducing type-safe function pointers. The implementation maintains backward compatibility while making execution flow more modular through helpers like `maybe_run_task()`. Kristoffer Haugsbakk and Karthik Nayak provided collaborative review throughout the series.

With all maintenance tasks now properly split between phases and all known races addressed, this represents a significant improvement to Git's maintenance infrastructure. The changes touch `builtin/gc.c` and test files, with careful attention to preserving behavior while making the code more maintainable. The series is now complete and ready for integration.
