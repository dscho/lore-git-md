This thread presents an 11-patch series addressing race conditions in Git's maintenance operations, particularly around ref locking during auto-maintenance. The core issue is that `git-maintenance` could race with other processes when repacking references, unlike `git-gc` which handles this safely. The series restructures maintenance task execution to properly sequence operations into "before detach" and "after detach" phases.

The series has progressed through several refactoring steps to prepare for the core fixes. Early patches modernized initialization patterns, simplified quiet mode handling, and centralized task configuration logic. The latest patch (v1 5/11) eliminates direct modification of the global `tasks` array in favor of a more encapsulated approach, moving task state into the `maintenance_run_opts` structure and introducing a `maintenance_strategy` struct to better organize the configuration. This internal restructuring maintains the same behavior while making the code more maintainable.

So far, the changes have focused on `builtin/gc.c`, with test updates in `t/t7900-maintenance.sh` for the option validation improvements. The series is following a clear progression: first refactoring the code to be more robust, then (in upcoming patches) implementing the actual race condition fixes around "pack-refs", "reflog-expire", and "gc" tasks. The foundational work done in these early patches will make the subsequent behavioral changes safer and easier to reason about.
