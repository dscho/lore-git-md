This is the 8/11 patch in Patrick Steinhardt's series fixing race conditions in Git's maintenance operations around ref locking. The patch introduces a split between maintenance tasks that should run before detaching (foreground) and after detaching) (background) to prevent reference locking issues.

The key change restructures the `maintenance_task` struct to have separate function pointers `before_detach` and `after_detach` instead of a single `fn` pointer. All existing tasks are initially assigned to `after_detach` (maintaining current behavior), with `before_detach` left NULL. The `maybe_run_task()` helper is updated to take a `before` parameter and select the appropriate function pointer, with separate trace2 regions for "maintenance before" and "maintenance" phases.

The patch adds a new task execution loop before detaching, while keeping the existing post-detach loop. This prepares for future patches that will move ref-related tasks (pack-refs, reflog-expire) to run before detaching, matching git-gc's behavior. The changes are purely structural at this point - no tasks are actually moved to run before detaching yet.

Technical details: The patch modifies `builtin/gc.c`, introducing the split execution phases while maintaining all existing functionality. Trace2 logging is updated to distinguish between phases. The `maintenance_task` typedefs from patch 7/11 are now used with their proper pointer semantics. This continues the series' pattern of preparatory refactoring before implementing the core race condition fixes.
