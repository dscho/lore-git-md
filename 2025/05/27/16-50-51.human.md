This is a discussion thread about naming choices in the ongoing `the_repository` removal effort, specifically around object store terminology.

Junio C Hamano responds to Patrick Steinhardt's follow-up about two patch series mentioned in the "What's cooking" status update. The first (midx-negative-packfile-cache) is essentially settled, with Junio noting it's fine to clean up the `(void *)(intptr_t)-1` syntax even though Taylor Blau has built on it.

The main discussion focuses on naming for the object store components in Patrick's larger ps/object-store series. The open question is whether to use `odb_alternate` or `odb_source` for the components that make up the object store. Junio provides thoughtful analysis of the naming options, noting that "alternate" made sense when there was a primary store plus alternates, but may not fit the new unified model where all components are equals. He considers alternatives like "source" but isn't fully satisfied, and muses about parallels to pathspec terminology.

The exchange shows careful consideration of naming semantics in this significant refactoring work, with Junio providing historical context while acknowledging the need to evolve terminology to match the new architecture. No firm conclusion is reached, leaving room for further discussion about the most appropriate naming scheme.
