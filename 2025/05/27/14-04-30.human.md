This is a refactoring patch in a series addressing race conditions in Git's maintenance operations. It's the fourth of eleven patches that restructure how maintenance tasks handle ref locking.

The patch makes two related changes to option validation in `git maintenance run`:
1. Explicitly marks `--task=` and `--schedule=` as incompatible options, since they represent conflicting ways to specify which tasks to run (explicit selection vs repository-configured schedule)
2. Modernizes the existing `--auto`/`--schedule` incompatibility check to use the standard `die_for_incompatible_opt2()` helper function

The changes are straightforward - the patch updates the option validation logic in `builtin/gc.c` and adds a corresponding test case. This continues the series' pattern of cleaning up the maintenance command's internals before implementing the core race condition fixes in later patches.

The patch appears well-constructed with a focused scope, though the commit message could better explain why these particular options are conceptually incompatible (beyond just "it's sensible"). The test coverage is adequate for the change being made.
