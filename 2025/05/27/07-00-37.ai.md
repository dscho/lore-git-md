Bug report about `git branch --show-current` behavior in detached HEAD state.

This is a bug report from Ulrich Wittenberg describing unexpected behavior with `git branch --show-current` when in a detached HEAD state. The reporter is using this in a Jenkins job context where the repository is frequently in detached HEAD state. They expect the command to show which branch the script is working on, but instead it returns nothing (empty output) without any error message.

The report notes that other Git commands that typically show branch information also fail to work in this state, though it doesn't specify which commands were tried. The system information shows this is occurring with Git 2.39.5 on a Linux system with glibc 2.36.

The core issue appears to be a mismatch between user expectations and actual behavior - the reporter seems to want branch information even in detached HEAD state, while Git's current behavior is to return nothing in this case. The report doesn't specify whether they want the command to show the detached HEAD state explicitly or perhaps show the branch that was previously checked out before detaching.

This could potentially be classified as either a bug (if the behavior violates documented expectations) or a feature request (to make the command more informative in detached HEAD state). The report would benefit from more specific details about which other commands were tried and what output was expected from them.
