This is a documentation patch series (v3) from Kristoffer Haugsbakk that improves the documentation around `--stdin` behavior in git-notes and related `core.commentChar` references. The 9-part series builds on previous work and has been refined based on feedback from Junio Hamano and others.

The key improvements in this version include:
1. Clearer documentation of when `--stripspace` is the default behavior, including a note about a known limitation when mixing options like `-C` and `-m` (which may be fixed in the future)
2. Standardized phrasing for `--stdin` documentation ("Only valid for" instead of "For") as suggested by Junio
3. Consistent use of the "stuck form" (`--option=value`) throughout the documentation

The series has already received positive feedback on its technical accuracy, with Junio approving part 8 with minor wording suggestions. The remaining open question is whether to document the message concatenation behavior as a known issue or fix the implementation. The patches touch documentation files for git-notes, git-stripspace, and commit configuration.

This appears to be a well-crafted documentation cleanup that addresses subtle but important behavioral details in git-notes handling. The author has been responsive to feedback and the changes look ready for merging pending resolution of the implementation question.
