This is a refactoring patch in a series addressing race conditions in Git's maintenance operations. It's the fifth in an 11-part series that restructures how maintenance tasks handle ref locking during auto-maintenance.

The patch eliminates global state manipulation in the task configuration system, which previously used three different fields (`enabled`, `selected_order`, and `schedule`) to track whether and when tasks should run. The new approach computes the task list once during initialization and stores it in the options structure, making the logic more self-contained and easier to follow.

Key changes include:
- Task configuration now happens entirely in `initialize_task_config()`
- The global `tasks` array becomes `const` since it's no longer modified
- A new `maintenance_strategy` struct helps organize the different configuration states
- The patch maintains all existing behavior while making the code more maintainable
- It's part of a larger effort to fix race conditions in maintenance operations, with this refactoring laying groundwork for subsequent patches that will implement the actual locking fixes
