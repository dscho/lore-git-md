Kristoffer Haugsbakk responds to Jon Forrest's inquiry about `git commit -a` not adding new files by tracing the behavior back to its 2005 implementation. The original code used `git-diff-files --name-only` piped to `git-update-cache`, which only processed tracked files. Haugsbakk suggests this design may have been intentional to avoid accidentally staging unwanted files like build artifacts, noting the original commit message didn't strongly endorse the feature.
