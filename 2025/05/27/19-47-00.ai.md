This is a test infrastructure patch addressing TAP output handling in Git's test suite. The change redirects shell trace output from stdout to stderr to maintain clean TAP protocol compliance when using verbose test modes. The patch modifies both the test harness (t/test-lib.sh) and verification tests (t0000-basic.sh) to ensure mixed stdout/stderr streams don't break TAP parsers.

The technical changes involve:
- Redirecting fd3 (previously stdout) to stderr in verbose modes
- Updating check_sub_test_lib_test_err to handle merged streams
- Preserving test expectations while changing output locations
- Maintaining all existing test assertions with adjusted stream handling

Junio Hamano raises two concerns in his response: potential buffering issues when merging streams, and apparent inconsistency with the test's continued checking of separate output streams. The patch appears well-tested with comprehensive updates to t0000-basic.sh, but these questions about stream ordering and verification methodology may need clarification before final acceptance.
