This is a cover letter for a bugfix series addressing race conditions in Git's maintenance operations, specifically around ref locking during auto-maintenance. The series aims to fix issues where `git-maintenance` could race with other processes when repacking references, similar to how `git-gc` already handles this safely.

The root problem stems from `git-maintenance` not properly sequencing operations - it would detach before repacking references, unlike `git-gc` which does these operations in the correct order. The series restructures the maintenance task execution to properly split operations into "before detach" and "after detach" phases.

The 11 patches follow a logical progression: initial refactoring (patches 1-2), centralizing task configuration (3-5), extracting task running logic (6-7), then implementing the core fix by adding before/after detach phases (8-11). The changes touch mainly `builtin/gc.c` with some test updates.

Key technical points for future reference:
- Introduces `maintenance_task_fn` typedef for task functions
- Adds `run_tasks()` helper to execute maintenance operations
- Splits tasks into `before_detach` and `after_detach` phases
- Specifically fixes races for "pack-refs", "reflog-expire", and "gc" tasks
- Removes reliance on global state in task configuration
- The changes are motivated by real-world race reports (links [1] and [2] in cover letter)
- Test coverage appears in `t/t7900-maintenance.sh`

This looks like a well-structured series addressing a concrete problem with careful attention to maintaining existing behavior while fixing the races. The commit messages and cover letter provide clear rationale and the changes appear focused on the stated issue.
