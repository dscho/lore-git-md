This is a conceptual follow-up to the notes editor whitespace discussion, where Junio Hamano proposes an alternative approach to handling indented empty lines in Git's output formatting. While not a complete patch submission, it demonstrates how the issue could be addressed more broadly in the pretty-printing machinery rather than just in the notes-specific solution currently under discussion.

Junio suggests adding a new `--no-indent-empty-lines` option and corresponding infrastructure that would control whether empty lines receive indentation in formatted output. The proof-of-concept patch modifies several core files (`pretty.c`, `revision.c`, etc.) to add this capability, though it's explicitly marked as incomplete - lacking tests, documentation, and configuration options. The approach would affect not just notes editing but other commands like `git log` and `git show`.

The email makes clear this is just an illustrative example rather than a serious proposal at this stage. Junio notes several missing pieces that would be needed for a complete solution, while expressing skepticism about whether the broader feature is actually needed beyond the immediate notes-editor use case. The patch serves more to demonstrate that alternative architectural approaches exist, while the current thread's focused `notes.c` solution remains the more immediately practical fix.
