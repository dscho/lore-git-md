This is the 8th patch in Patrick Steinhardt's series addressing race conditions in Git's maintenance operations, specifically around ref locking during auto-maintenance. The patch introduces a key structural change to split maintenance tasks into those that should run before detaching (in the foreground) and those that can run after (in the background).

The change addresses a known issue where `git-maintenance` could hold locks on the "packed-refs" file for extended periods, potentially blocking other Git commands. While `git-gc` already handled this by splitting tasks, `git-maintenance` lacked this distinction. The patch modifies the task execution framework to support this split by adding `before_detach` and `after_detach` function pointers in the task struct, though it doesn't yet change any task behaviors - that comes in later patches.

The implementation is clean and focused, touching only `builtin/gc.c` to:
1. Split the task function pointer into two variants
2. Update all task definitions to use `after_detach` (maintaining current behavior)
3. Modify `maybe_run_task()` to handle both phases
4. Add a new foreground task execution phase before detaching

This continues the series' pattern of careful preparation before implementing the actual behavior changes. The commit message clearly explains the motivation and maintains the separation between structural changes (this patch) and behavioral changes (coming next). The change is well-contained and appears to be a solid foundation for the actual fixes to follow.
