Maintainer feedback on submodule active pattern optimization. Junio C Hamano raises two key concerns about K Jayatheerth's patch to skip redundant `submodule.<name>.active` entries when paths match existing patterns:

First, he questions whether the behavior change is actually desirable - the current behavior ensures a submodule stays active even if the pattern later changes, while the patch would make activation dependent on the current pattern. This could surprise users who rely on the existing behavior.

Second, he suggests a simpler approach that wouldn't require a new helper function: just check `is_submodule_active()` before writing the explicit active flag, since that function already handles all the activation logic (including both pattern matching and URL presence). This would avoid duplicating logic and reduce maintenance burden.

The feedback indicates the patch needs revision to either:
1) Keep the current behavior's guarantees while still reducing config clutter, or
2) More clearly document the behavior change as intentional, and implement it in a way that shares logic with existing code rather than adding new helpers.

This is the second patch in a series where the first patch (handling submodule path conflicts) has already received maintainer approval. The discussion here focuses specifically on the pattern-matching optimization aspect.
