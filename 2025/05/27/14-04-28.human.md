This is a refactoring patch in a series addressing race conditions in Git's maintenance operations. It's the quiet-mode handling logic in `git gc` that currently uses two separate variables to track quiet mode - a local `quiet` variable and a field in the `maintenance_run_opts` struct.

The patch simplifies this by eliminating the redundant local `quiet` variable in favor of consistently using the `opts.quiet` field throughout the command. This makes the code clearer by removing the confusion about which variable controls quiet mode behavior. The change is mechanical but improves maintainability as part of the larger series.

The patch touches only `builtin/gc.c`, updating all references to the local `quiet` variable to use `opts.quiet` instead. This is a straightforward cleanup that doesn't change behavior, just makes the code's intent more obvious. It follows logically from the first patch in the series which modernized the maintenance task initialization.
