This is a refactoring patch in the maintenance task race condition series. It centralizes the configuration logic for explicitly requested maintenance tasks (`--task` option) in `builtin/gc.c`.

The patch moves task selection state management from `task_option_parse()` to `initialize_task_config()`. Previously, `task_option_parse()` would directly modify the global `tasks[]` array's `selected_order` field when processing `--task` arguments. Now it collects selections in a temporary `string_list` which is later processed by `initialize_task_config()`. This makes the configuration flow more linear and easier to follow.

Key technical details: The change introduces a `selected_tasks` string list in `maintenance_run()` that gets passed through the option parsing. Each selected task is stored with its name as the string and a pointer to the task struct as the util field. The patch maintains all existing behavior while eliminating direct global state modification during option parsing. This is part of the larger effort to make maintenance task execution more robust by properly sequencing operations.

The change is mechanical and well-contained, touching only task selection logic while preserving all functionality. It follows the codebase's style and includes appropriate error handling for duplicate task selection. This prepares for subsequent patches that will further restructure task execution to prevent races.
