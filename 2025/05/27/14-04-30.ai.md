This is a patch in the maintenance ref-locking race condition series that enforces option compatibility rules in `git maintenance run`.

The patch makes `--task` and `--schedule` mutually exclusive options, similar to how `--auto` and `--schedule` already were. The rationale is that `--task` specifies exact tasks to run while `--schedule` uses the repository's configured strategy, making them conceptually incompatible. The implementation consolidates the option validation by using the standard `die_for_incompatible_opt2()` helper for both cases, replacing a custom error message for the `--auto` case.

The changes touch `builtin/gc.c` to add the new validation and update the existing one, plus a test in `t/t7900-maintenance.sh` to verify the new restriction. The test updates show the error message changed from "at most one" to the more standard "cannot be used together" phrasing when validating `--auto`/`--schedule`.

This is a straightforward validation improvement that fits with the series' goal of making maintenance operations more robust. The patch maintains the series' pattern of small, focused changes with corresponding test coverage. The use of `die_for_incompatible_opt2()` follows Git's convention for option validation.
