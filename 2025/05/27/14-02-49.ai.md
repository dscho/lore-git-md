This is the first patch in Patrick Steinhardt's 6-part series to improve TAP format compliance in Git's test suite, building on the ongoing Meson test integration work. The patch fixes cases where test scripts generate output that breaks strict TAP parsing by either removing non-essential diagnostic messages or properly redirecting them to /dev/null.

The changes affect 12 test scripts that were producing unmarked output outside test cases, which violates TAP specifications. Key modifications include:
- Removing filesystem capability announcements (case sensitivity, Unicode handling)
- Silencing repository creation output with >/dev/null
- Converting some say() calls to skip_all when they indicate test prerequisites
- Using test_lazy_prereq for more robust prerequisite checking
- Fixing Python version detection in git-p4 tests to be quieter

The patch maintains all test functionality while making the output properly parseable by TAP consumers like Meson's test runner. This is part of the broader effort to align Git's test infrastructure with stricter TAP validation standards, as discussed in the thread where participants have reached consensus on treating unexpected passes as failures. The changes are mechanical and focused on output formatting rather than test behavior, with all technical aspects already reviewed by Karthik Nayak and Phillip Wood.
