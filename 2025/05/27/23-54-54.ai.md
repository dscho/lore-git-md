This is a feature request proposing an enhancement to `git add -p` behavior regarding merge conflicts.

The author, Jarrad Whitaker, observes that while Git currently excludes files with merge conflicts from `git add` operations (which is generally sensible), this behavior may be unnecessarily restrictive for the interactive patch mode (`git add -p`). The key argument is that since patch mode already allows granular review of changes chunk-by-chunk, there's no fundamental reason to block it from operating on conflicted files.

The current behavior forces users to add conflicted files manually without the benefit of patch mode's interactive review capabilities. Whitaker suggests this creates unnecessary friction in the conflict resolution workflow, requiring manual filename copying and losing the ability to review changes incrementally.

The proposal appears technically sound and focused on improving a specific workflow pain point. It targets the interactive add functionality (`add-interactive.c`) and would likely involve modifying the conflict file detection logic when in patch mode. The change would maintain all existing safety checks while removing what the author sees as an artificial limitation in this particular mode.

No implementation details or potential edge cases are discussed in this initial proposal, which is typical for a feature request email. The tone is appropriately lighthearted while making a clear case for the change.
