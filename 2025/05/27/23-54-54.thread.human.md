Jarrad Whitaker has raised an interesting proposal to improve `git add -p`'s handling of merge conflicts. Currently, Git prevents any `git add` operation on files with merge conflicts - a sensible default that prevents accidentally adding unresolved conflicts. However, Whitaker points out this blanket restriction may be unnecessarily limiting for the interactive patch mode, since `git add -p` already provides careful, chunk-by-chunk review capabilities.

The core argument is that forcing users to add conflicted files manually (without patch mode's interactive review) creates workflow friction. Users lose the ability to incrementally review changes and must instead copy filenames manually. The proposal suggests modifying `add-interactive.c` to allow patch mode operations on conflicted files while maintaining all other safety checks.

This appears to be a fresh take on improving the conflict resolution workflow, with no fundamental technical barriers mentioned. The change would specifically target the interactive add functionality while leaving the default `git add` behavior unchanged. As this is an initial proposal, implementation details and edge cases haven't been explored yet, but the core idea seems well-reasoned and focused on a real pain point.
