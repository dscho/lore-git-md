This is a patch series addressing race conditions in Git's maintenance operations, specifically around locking the "packed-refs" file during auto-maintenance. The series comes from Patrick Steinhardt and targets a known issue that has been reported by multiple users.

The core problem stems from how `git-maintenance` handles reference repacking compared to `git-gc`. While `git-gc` properly sequences operations to avoid lock races by detaching only after repacking references, `git-maintenance` currently lacks this careful sequencing. The series restructures the maintenance task execution to properly separate pre-detach and post-detach operations.

The 11 patches follow a logical progression: initial refactoring to clean up the codebase (patches 1-2), restructuring task configuration to eliminate global state (patches 3-5), and finally implementing the actual fix by introducing the before/after detach split for key maintenance operations (patches 6-11). The changes specifically address races during "pack-refs", "reflog-expire", and "gc" tasks.

The series appears well-structured and addresses a concrete problem with clear user reports. The changes are focused and the commit messages provide good context. The modifications touch core maintenance operations, so they'll likely need careful review from maintenance/gc experts, but the approach seems sound and the problem worth fixing.
