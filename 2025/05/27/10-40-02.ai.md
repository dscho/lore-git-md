Performance optimization patch for the `git last-modified` command, specifically adding Bloom filter support to skip unnecessary diff computations. This is part of the ongoing v2 series implementing path modification tracking.

The patch adds Bloom filter checks before computing diffs during the revision walk, which can substantially reduce runtime when filters are available (kernel repo benchmarks show ~5x speedup). Key implementation points:

- New `maybe_changed_path()` function checks Bloom filters for path changes
- Uses existing commit-graph infrastructure for filter lookups
- Maintains backward compatibility when filters aren't available
- Includes memory management for Bloom filter keys

Patrick Steinhardt's review identifies several technical concerns:
1. Questionable `generation_numbers_enabled()` call with void cast (potential commit-graph subsystem issue)
2. Unnecessary braces in hashmap iteration
3. Unclear generation number requirement in filter check
4. Overall design appears sound but needs cleanup

The performance gains are significant (0.75s vs 5.13s in optimized builds), making this a valuable optimization despite the implementation polish needed. The patch builds on prior resolved discussions about Bloom filter usage in this feature.
