This is a follow-up in the ongoing `merge-tree` feature discussion, specifically about the new dry-run functionality. Elijah Newren reports that version 4 of the patch series has been submitted, incorporating feedback from Phillip Wood to rename the `--dry-run` flag to `--quiet` for better consistency with Git's existing conventions. The change reflects the command's behavior of suppressing output when checking mergeability rather than performing an actual dry-run operation.

The thread context shows this is part of Junio Hamano's "What's cooking" report where the original `merge-tree --dry-run` feature was noted as ready to merge to 'next'. The new naming aligns better with Git's established patterns where `--quiet` typically means suppressing output rather than simulating operations.

The technical detail for future reference: the change affects `builtin/merge-tree.c` and `merge-ort.c`, introducing a `mergeability_only` option in the ORT backend that gets triggered by the frontend's `--quiet` flag. This maintains the same functionality of checking merge conflicts without writing results, just with more idiomatic naming. The discussion suggests the Git community values consistency in CLI interface design, even for new features.
