This thread explores adding test infrastructure to verify Git's handling of corrupt bitmap indexes, specifically targeting memory leaks during loading. The initial patch introduced test cases for invalid commit positions and XOR offsets, implemented directly in pack-bitmap.c. Patrick Steinhardt raised concerns about mixing test code with production logic, suggesting relocation to test-specific files.

In response, the author clarifies their primary goal is testing memory leaks when corruption occurs immediately after the index header - a scenario that depends on hash algorithm details. They propose a compromise: keeping the low-level corruption functionality in pack-bitmap.c while moving test cases to the unit test framework. This addresses the technical need for precise header manipulation while improving code organization.

The discussion remains constructive, with no objections to the test approach itself. The key open question is implementation location, with both parties showing flexibility - Patrick advocating for cleaner separation of concerns, and the author acknowledging this while explaining their technical constraints. The thread demonstrates Git's typical review dynamic where technical merit and codebase hygiene receive equal consideration.
