This thread discusses a new test infrastructure for detecting corruption in Git's bitmap loading functionality. The initial patch by the author introduces controlled corruption scenarios (invalid commit positions and XOR offsets) to verify proper error handling, implemented via a new `test_bitmap_load_corrupt()` function in pack-bitmap.c with corresponding test-tool commands and t5310 test cases.

Patrick Steinhardt has raised an organizational question in his response, suggesting the test logic might better belong in test-specific files (either test-bitmap.c or as a unit test) rather than the main pack-bitmap.c implementation. While not challenging the test's technical merit, he emphasizes Git's principle of keeping production code separate from test infrastructure where possible. The author now needs to either justify the current placement or consider restructuring the code according to these suggestions. The core functionality - deliberately corrupting in-memory bitmap structures to verify detection - remains uncontested and appears ready to proceed once the code organization question is resolved.
