**Feature patch adding MPTCP support for Git on Linux**

This patch introduces Multi-Path TCP (MPTCP) support to Git, specifically targeting Linux systems. MPTCP allows aggregating multiple network paths (like WiFi and 5G simultaneously) for increased bandwidth and failover capabilities. The implementation is gated behind both compile-time checks (for `IPPROTO_MPTCP` availability) and runtime configuration (via `GIT_ENABLE_MPTCP` environment variable for clients and `--mptcp` flag for the git-daemon).

The patch mechanics involve careful fallback handling: it checks for MPTCP support in both the kernel (via socket creation attempts) and glibc's `getaddrinfo()`, falling back to regular TCP if either check fails. The author notes this is particularly important for older glibc versions that may lack MPTCP support despite kernel availability. Server-side support is opt-in via the daemon flag.

The motivation comes from the author's personal use case handling large (50GB+) repositories across multiple WAN links, where MPTCP provides both aggregation and failover benefits. They reference Apple's long-standing MPTCP usage in cloud services as precedent, though acknowledge potential fallback-induced delays as a theoretical concern.

Implementation-wise, the patch touches socket initialization in network-facing code, adding Linux-specific branches guarded by `__linux__` checks. The author explicitly avoids enabling MPTCP on non-Linux systems. A question remains about whether Makefile configuration would be preferable to environment variables for enabling the feature.

This appears to be a serious, well-motivated contribution with clear fallback paths, though its utility depends on both client and server supporting MPTCP. The patch doesn't include performance measurements or tests demonstrating the benefits under multi-path conditions, which might help reviewers evaluate the real-world impact.
