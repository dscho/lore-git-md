Feature patch advocating for MPTCP support in Git, responding to maintainer concerns.

Muhammad Nuzaihan responds to Junio Hamano's skepticism about the necessity of application-level MPTCP support by providing historical context and adoption evidence. The email argues that MPTCP is now mature technology (IETF standardized since 2020, Linux mainline since kernel 5.6) with production use at Apple for over 12 years. The author draws parallels to IPv6 adoption, suggesting Git should lead rather than follow in supporting emerging network protocols.

The personal motivation comes from poor hotel WiFi experiences where bandwidth aggregation would help, though the author acknowledges server-side benefits may be greater. Notable ecosystem support is cited with Go 1.24 enabling MPTCP by default this year. The response addresses security concerns by noting a 2022 CVE is now outdated, while conceding the Linux implementation's stability remains to be proven over time.

This email doesn't introduce technical changes but attempts to address the maintainer's fundamental objection about whether Git should support MPTCP at all. The argument leans on growing ecosystem support and protocol maturity rather than presenting new Git-specific performance data. The tone suggests the author sees this as inevitable protocol evolution, similar to IPv6, though the maintainer's skepticism about application-level implementation remains the key hurdle.
