Maintainer feedback on MPTCP support proposal (v2)

Junio Hamano responds to Muhammad Nuzaihan's MPTCP patch series with skepticism about the approach's viability. The core concern questions whether application-level MPTCP support is the right architectural direction, given what appears to be limited adoption across the software ecosystem. The response suggests the author may need to better familiarize themselves with Git contribution guidelines before proceeding.

The feedback implies the proposal lacks sufficient justification for why Git specifically needs native MPTCP support rather than relying on lower-level system configuration. No technical flaws in the implementation are mentioned, but the fundamental premise is challenged. The maintainer's rhetorical question about adoption rates in other applications suggests this may face an uphill battle for acceptance without stronger evidence of either broad ecosystem support or unique Git-specific benefits.

This exchange occurs after the author's v2 patch which introduced the feature with environment variable controls and careful compatibility checks, and before the v3 patch that fixed a protocol selection bug. The thread context shows the technical implementation has been refined, but this high-level concern about the feature's necessity remains unaddressed. Future discussion would need to either demonstrate wider MPTCP adoption patterns or articulate why Git should lead in this space despite that.
