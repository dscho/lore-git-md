This is a test patch adding corruption detection for bitmap loading functionality. The patch introduces a new test infrastructure to verify Git's handling of corrupt bitmap indexes, specifically targeting the bitmap table lookup feature.

The core addition is a new test function `test_bitmap_load_corrupt()` in pack-bitmap.c that provides a framework for corrupting bitmap indexes and verifying the loading behavior. It implements two specific corruption scenarios: invalid commit positions and invalid XOR offsets. The test works by first preparing a bitmap index, then deliberately corrupting it in memory before attempting to load it, verifying that the corruption is properly detected.

The patch adds a new `load-corrupt` subcommand to the test-tool bitmap helper and a corresponding test case in t5310-pack-bitmaps.sh. The test creates a simple repository with a bitmap index (using the lookup table feature) and verifies the corruption detection works as expected.

Key technical details include:
- New `bitmap_corrupt_then_load()` helper that handles the corruption/loading sequence
- Two corruption functions: `do_corrupt_commit_pos()` and `do_corrupt_xor_offset()`
- Requires bitmap table lookup feature to be enabled (as it prevents early loading)
- Carefully handles memory management around the bitmap index's mmap'd data

The test infrastructure appears well-designed for its purpose, with clear comments explaining the approach. This should help catch bitmap corruption handling issues, particularly around the relatively new bitmap lookup table feature. The patch follows Git's testing conventions and integrates cleanly with existing bitmap test infrastructure.
