This is a technical response in the ongoing MPTCP support discussion, with Muhammad Nuzaihan addressing Brian Carlson's concerns about cross-platform compatibility and kernel support variations.

The email focuses on refining the Linux-specific MPTCP implementation with additional safety checks. Muhammad proposes three specific technical improvements: (1) adding a `__linux__` compile-time check to explicitly limit the feature to Linux, (2) handling `EAI_SOCKTYPE` errors (a POSIX-standard error for unsupported socket types) to fall back to regular TCP, and (3) maintaining the existing `IPPROTO_MPTCP` availability check. These changes aim to address Brian's scenario where binaries compiled on MPTCP-capable systems might run on stripped-down kernels.

Muhammad provides context about MPTCP's maturity (15 years of development, v1 improvements since 2020) and his personal use case involving large repositories (50GB) with multiple WAN links where MPTCP provides bandwidth aggregation and failover benefits. He contrasts this with MultiPath QUIC's immaturity and notes Apple's long-term MPTCP usage (since 2013 with v0).

The response clarifies that the patch only affects client-side code (`connect.c`) not server components (`daemon.c`), addressing Brian's reference to Go 1.24's server-side MPTCP issues (CVE-2022-49198). However, Muhammad does propose adding a `--mptcp` flag for `git-daemon` as a server-side opt-in.

Key technical specifics include: the POSIX `EAI_SOCKTYPE` fallback mechanism, Linux-specific implementation boundaries, and the distinction between client/server impacts. The discussion remains unresolved on broader cross-platform support, with Muhammad maintaining a Linux-first approach while acknowledging macOS as future work and excluding FreeBSD due to its experimental status. Documentation gaps about platform limitations remain a point Brian has emphasized.
