This is a bugfix revision (v3) of the ongoing MPTCP support feature patch for Git on Linux. The change corrects a fallback logic error in the socket protocol selection where the previous version would incorrectly use MPTCP protocol even when the mptcp flag was disabled. The fix ensures proper fallback to regular TCP (IPPROTO_TCP) when MPTCP is either unsupported or explicitly disabled via the GIT_ENABLE_MPTCP environment variable (client) or --mptcp flag (server).

The patch maintains all previously introduced MPTCP functionality from v2, including comprehensive compatibility checks for Linux kernel version (5.6+), glibc support in getaddrinfo(), and proper error handling for various socket creation scenarios. The implementation remains guarded by __linux__ and IPPROTO_MPTCP availability checks to prevent issues on non-Linux systems.

Key technical details unchanged from v2 include the dual client/server control mechanisms (environment variable and daemon flag), the careful version checking for both kernel and glibc support, and the robust fallback paths when MPTCP is unavailable. The patch continues to target large-repo transfer scenarios where multi-path aggregation and failover could provide benefits, though actual performance impact remains unmeasured.

This revision appears to be a straightforward correction of an implementation oversight rather than a conceptual change to the MPTCP approach. The author discovered the issue through practical testing with Wireshark packet inspection, suggesting active validation of the feature's network behavior.
