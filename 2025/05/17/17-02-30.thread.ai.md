**Thread summary: Feature patch adding MPTCP support for Git on Linux (v4)**

Initial patch series introduces Multi-Path TCP (MPTCP) support for Linux systems, enabling bandwidth aggregation across multiple network paths (WiFi + 5G). Implementation requires kernel (IPPROTO_MPTCP) and glibc support, with fallback to TCP. Client-side uses GIT_ENABLE_MPTCP environment variable, server-side via git-daemon --mptcp flag. Carefully handles __linux__ guards and checks for kernel 5.6+ and glibc getaddrinfo() support. Author motivation cites large-repo transfers (50GB+) benefiting from aggregation/failover, with Apple's cloud usage as precedent. Technical implementation modifies socket initialization in network code.

Version 3 fixed fallback logic error where MPTCP protocol was incorrectly used when disabled, ensuring proper fallback to IPPROTO_TCP when unsupported. Issue discovered through Wireshark packet inspection during testing. Maintainer Junio Hamano expressed skepticism about the approach's viability, questioning whether application-level MPTCP support is the right direction given limited ecosystem adoption. Feedback challenges the fundamental premise rather than technical implementation, suggesting author needs to better justify why Git specifically needs native MPTCP support versus system configuration.

Open questions remain regarding Makefile vs env var configuration, still lacks performance measurements. Technical approach appears sound with compatibility handling, but maintainer concerns about feature necessity create significant adoption barrier unless either broader ecosystem support is demonstrated or unique Git-specific benefits are articulated. The protocol selection fix in v3 addressed an implementation issue, but high-level architectural concerns from maintainer remain the primary obstacle.
