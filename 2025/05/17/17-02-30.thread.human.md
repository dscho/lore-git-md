This thread introduces a patch adding Multi-Path TCP (MPTCP) support to Git on Linux systems, allowing aggregation of multiple network paths (like WiFi and 5G) for increased bandwidth and failover capabilities. The implementation is carefully designed with fallback mechanisms - it checks for both kernel and glibc support at runtime, defaulting to regular TCP if either check fails. The feature is gated behind both compile-time checks and runtime configuration (via `GIT_ENABLE_MPTCP` for clients and a `--mptcp` flag for git-daemon).

The author's motivation comes from handling large repositories (50GB+) across multiple WAN links, citing Apple's production use of MPTCP as precedent. The patch touches socket initialization code with Linux-specific branches, explicitly avoiding enabling MPTCP on other platforms. While the implementation appears robust with clear fallback paths, the patch currently lacks performance measurements demonstrating the benefits under multi-path conditions, which would help reviewers evaluate the real-world impact. One open question remains about whether Makefile configuration might be preferable to environment variables for enabling the feature.
