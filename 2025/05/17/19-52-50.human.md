This is a follow-up discussion about the recently merged `--quiet` flag for `git merge-tree`. Kristoffer Haugsbakk shares their experience using `--stdin` mode for scripting conflict detection and suggests a potential enhancement to combine `--quiet` with `--stdin` for batch processing.

The email describes a current workaround using `tee` and text processing to correlate merge pairs with conflict status when using `--stdin`. Haugsbakk proposes either a new `--format` option or relaxing the current restriction that prevents `--quiet` from being used with `--stdin`. The key observation is that while the current implementation intentionally prevents these flags from being combined (to maintain output format consistency), there might be value in allowing a new mode that sacrifices some information for batch efficiency.

This appears to be a thoughtful suggestion from someone with practical experience using the feature, though it would require careful consideration of the tradeoffs between output consistency and scripting convenience. The proposal doesn't include a concrete implementation, but raises an interesting design question about whether the current restrictions could be relaxed for users who explicitly opt into a different behavior.
