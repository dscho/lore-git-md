This is the first patch in a v7 series improving `git send-email`'s domain validation and OAuth2.0 authentication. The patch tightens the RFC1035-compliant domain name validation in `valid_fqdn()` to properly reject malformed domains that were previously accepted.

The key technical changes:
- Replaces the simple dot-check with a regex enforcing RFC1035 rules: labels must be 1-63 alphanumeric/hyphen characters, cannot start/end with hyphens, and must be dot-separated
- Maintains the macOS `.local` domain special case
- Includes test evidence showing the fix prevents SMTP failures when invalid domains like `MacBook..` are rejected by servers

The patch demonstrates the previous validation was insufficient by showing real SMTP session logs where Outlook rejected malformed domains, and how the new validation properly falls back to `localhost.localdomain`. The implementation uses lookaheads/lookbehinds to enforce label constraints while keeping the macOS special case.

This is the technical core of the series that was approved in v5, with subsequent iterations focusing on documentation polish. The regex solution addresses the original problem where invalid domains caused SMTP failures, while maintaining backward compatibility with the macOS `.local` special case.
