This is a continuation of the discussion about integrating the `git-blame-tree` functionality into `git blame` rather than creating a new command. Junio Hamano responds to Marc Branchaud's proposal about UI behavior for directory handling.

Key points in this email:
- Clarifies that `git blame path/to/file` must maintain its current line-by-line annotation behavior and cannot be changed to show only the last commit
- Agrees that `git log -1 path/to/file` already provides the "last commit" information, making a new way redundant
- Notes that while he initially assumed recursive directory behavior (like `git ls-files`), he's open to non-recursive as the default (like `git ls-tree`) with a recursion option

The exchange continues to refine the UI implications of integrating the directory-level blame functionality, with Junio providing maintainer perspective on backward compatibility and existing command expectations. This helps narrow the discussion toward concrete decisions about default behaviors if the integration path is chosen.
