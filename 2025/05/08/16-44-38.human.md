This is part 4 of a 5-part build system patch series focused on path handling consistency across Git's build systems. The patch corrects how Meson sets `GIT_EXEC_PATH`, aligning it more closely with Make's behavior while maintaining configurability.

The change makes Meson default to a relative `libexec/git-core` path for `GIT_EXEC_PATH` (matching Make's behavior) rather than an absolute path. It preserves the ability to override this via `-Dlibexecdir` while adding a new check to error out if an absolute path is used with `runtime_prefix` enabled, since these are incompatible. The implementation is straightforward logic in `meson.build` that checks the libexecdir option value and applies appropriate path handling.

This continues the series' theme of standardizing path handling between build systems, with this patch specifically addressing executable path configuration. The change appears well-motivated by the discrepancy between Make's behavior and Meson's previous absolute path approach. The patch is narrowly focused and maintains backward compatibility with existing configuration methods while adding new safety checks.
