This is a performance optimization patch for `git repack` that improves how it handles promisor packs when `--keep-pack` or `.keep` files are involved. The patch builds on an earlier version by Tomáš Trnka, with Han Young providing a more efficient implementation.

The core issue is that when repacking promisor objects, Git was still enumerating objects from kept packs (those marked with `--keep-pack` or `.keep` files) even though they wouldn't be repacked. The original fix passed `--keep-pack` to `pack-objects`, but this still required enumerating all objects. The new approach skips kept packs entirely during enumeration in `repack_promisor_objects()`, using the `SKIP_IN_CORE_KEPT_PACKS` and `SKIP_ON_DISK_KEPT_PACKS` flags.

The patch includes compelling performance data showing the improvement: from 67.6 seconds to 18.8 seconds in a test case with a 2.7GB promisor pack, with the new version also producing a smaller pack file (1.6MB vs 4.5MB). The speedup comes from avoiding unnecessary object enumeration - the new version processes 20,952 objects versus 19,091,575 in the original.

The changes are focused in `builtin/repack.c`, modifying `collect_pack_filenames()` to mark `--keep-pack` packs as kept in-core, and updating `repack_promisor_objects()` to skip both in-core and on-disk kept packs during enumeration. The commit message thoroughly explains the problem, solution, and benefits, including concrete performance measurements. This appears to be a well-justified optimization that maintains the same behavior while being more efficient.
