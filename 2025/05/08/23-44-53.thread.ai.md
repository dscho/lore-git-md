Stash import/export as refs (v5) - a complete feature series introducing new `git stash export` and `git stash import` subcommands to enable bidirectional stash transfer between repositories via commit chains stored under `refs/stash-export/`. Maintainer Junio Hamano has responded positively to the v5 iteration, positioning it as the first step toward potential future evolution of the stash storage format.

Core implementation spans `builtin/stash.c` (command logic), `object-name.c` (OID lookup modifications with new `GET_OID_GENTLY` flag for reflog history handling), and `git-stash.adoc` documentation. The v5 series resolves all prior issues (memory leaks, rebase segfaults, test robustness) and adds:
1. Final `import` functionality reconstructing original stashes via `do_import_stash()`
2. Non-destructive appending through `do_store_stash()`
3. Commit structure validation with `get_oidf()`
4. 78 new test lines in `t/t3903-stash.sh` covering round-trip scenarios

Technical foundations remain:
- Dual-parent commit structure (sequence pointer + stash data)
- `oid_array` memory management
- `GET_OID_GENTLY` error handling
- Comprehensive test coverage

Maintainer feedback indicates this export/import functionality is ready for merging as a foundation, with the suggestion that future work could migrate core stash operations (`create`, `push`) to use this commit-chain format instead of reflogs. The current priority is stabilizing the import/export feature before considering deeper integration. No outstanding technical objections remain from the maintainer or other contributors.
