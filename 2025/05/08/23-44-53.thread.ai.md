**Stash import/export as refs (v6)**
Final iteration of the feature series introducing `git stash export` and `git stash import` subcommands for bidirectional stash transfer via commit chains under `refs/stash-export/`. The v6 version incorporates all prior review feedback and focuses on final polish. Core implementation spans `builtin/stash.c` (with new `parse_revision` helper), `object-name.c` (extended `get_oid` behavior), and `reflog-walk` components.

Key technical refinements from v5:
1. Enhanced import validation:
   - Stricter commit message parsing enforcing "git stash: " prefix
   - Robust parent count verification
   - Phillip Wood's topology checks now fully integrated:
     * Direct commit object validation via `repo_get_commit_tree()`
     * Strict 2-parent requirement for chain entries
     * Second parent stash commit verification
   * `read_complete_reflog` for safer reflog walking
2. Memory management fixes:
   * Resolved leaks and uninitialized variables
   * Safer OID handling without string conversions
3. Expanded test coverage:
   * 94 new lines in t3903 (vs 78 in v5)
   * Additional edge cases: empty stashes, malformed imports
4. Documentation clarifications:
   * Subcommand behavior and safety guarantees
   * Ref namespace rules confirmed safe under Jeff King's upcoming restrictions
5. New `GET_OID_GENTLY` flag in `object-name.c`:
   * Enables graceful error handling for reflog exhaustion cases
   * Required for robust stash import/export error recovery
   * Maintains backward compatibility with existing callers

Current status:
- All major technical concerns resolved (topology, memory safety, ref safety)
- Phillip Wood's sign-off pending for one patch
- Test suite fully covers round-trip scenarios including new error cases
- No outstanding objections from maintainers
- Ready for final review and merge

The series includes two refactoring patches:
1. Moves the `complete_reflogs` struct and related functions (`read_complete_reflog`, `free_complete_reflog`) from reflog-walk.c to reflog-walk.h to expose reflog reading machinery needed for stash import validation.
2. Extracts stash revision parsing logic into a reusable helper function (`parse_stash_revision`) while maintaining identical behavior, preparing for future reuse in other parts of the stash implementation. This change:
   - Preserves all existing error cases and messages
   - Adds a `quiet` parameter to suppress "No stash entries" output
   - Initializes the strbuf in `get_stash_info` before passing it
   - Maintains the same three parsing cases: empty input, numeric index, direct reference

**Core export implementation details**:
- Creates empty base commit with fixed timestamp for reproducibility
- Processes stashes from command-line arguments or `refs/stash` reflog walk
- Validates topology via `check_stash_topology()` helper
- Reconstructs commits with new parent chains pointing to previous exports
- Offers `--to-ref` (writes to specified ref) and `--print` (outputs hash) modes
- Uses `GET_OID_QUIETLY | GET_OID_GENTLY` for graceful error handling
- Preserves original commit metadata with "git stash: " prefix
- Handles both bulk export (all stashes) and selective export (specific references)
- Leverages reflog-walk infrastructure via `read_complete_reflog()`
- Uses new `parse_stash_revision()` helper from earlier refactoring
- Maintains existing stash commit structure in second parents

The series represents the culmination of a multi-year effort (referencing 2022 discussions) to solve stash portability while maintaining security. Junio Hamano and Phillip Wood have confirmed the dedicated commands provide value over manual push/pull+ref updates. The implementation has undergone six iterations with extensive review from key contributors including Phillip Wood (topology), Jeff King (ref safety and object handling), and Brian Carlson (use cases). The final plumbing changes to `get_oid` error handling, reflog infrastructure modifications, and stash parsing refactoring demonstrate the series' careful attention to edge cases, recovery paths, and future maintainability.
