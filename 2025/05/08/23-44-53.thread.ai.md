**Stash import/export as refs (v6)**
Final iteration of the feature series introducing `git stash export` and `git stash import` subcommands for bidirectional stash transfer via commit chains under `refs/stash-export/`. The v6 version completes the implementation with the new `import` subcommand and incorporates all prior review feedback. Core implementation spans `builtin/stash.c` (with new `parse_revision` helper), `object-name.c` (extended `get_oid` behavior), and `reflog-walk` components.

**Key technical refinements from v5**:
1. Enhanced import validation matching export rigor:
   - Enforces "git stash: " message prefix on all imported commits
   - Verifies parent topology via shared `check_stash_topology()`
   - Validates empty root commit structure with fixed format
2. Complete round-trip functionality:
   - `import` reconstructs stashes from exported chains
   - Appends to rather than replaces existing stashes
   - Uses same strict validation as export
3. Expanded test coverage:
   - 94 new lines in t3903 (268 total for feature)
   - Tests round-trip fidelity, edge cases, append behavior
4. Builds on prior series infrastructure:
   - Reflog walking via `read_complete_reflog()`
   - Stash parsing via `parse_stash_revision()`
   - Topology validation from earlier patches
5. Memory and error handling:
   - Uses `GET_OID_GENTLY` for robust error recovery
   - Maintains test OID consistency across hash algorithms

**Implementation details**:
- Export creates commit chains under `refs/stash-export/` with:
  - Empty base commit for reproducibility
  - Stash commits as second parents
  - Strict topology validation
- Import walks chains, strips chain commits, stores stash commits via `do_store_stash()`
- Preserves original metadata while validating structure
- Offers `--to-ref` and `--print` modes for export
- Uses shared validation helpers across both commands
