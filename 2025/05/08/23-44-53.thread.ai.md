Stash import/export as refs (v5) - a complete feature series introducing new `git stash export` and `git stash import` subcommands to enable bidirectional stash transfer between repositories via standard Git operations. The implementation represents stashes as commit chains with two parents per commit (sequence and data) stored under `refs/stash-export/`. 

Core changes span `builtin/stash.c` (command implementations), `object-name.c` (OID lookup modifications), and `git-stash.adoc` documentation. The v5 iteration includes:
1. A bugfix patch adding `GET_OID_GENTLY` flag (0100000) to make `get_oid_basic()` return -1 for reflog history limits instead of terminating)
2. The final patch implementing `import` functionality that:
   - Reconstructs original stash entries from exported commits using `do_import_stash()`
   - Appends imported stashes non-destructively via `do_store_stash()`
   - Validates commit structure with `get_oidf()`
   - Includes 78 new test lines in `t/t3903-stash.sh` covering round-trip scenarios

Technical foundations:
- Memory management using `oid_array`
- Error handling via `GET_OID_GENTLY` flag in `hash.h`/`object-name.c`
- Robust test coverage (78+ new test cases across series)
- Documentation updates in `git-stash.adoc`

The series has evolved through five versions addressing:
- Memory leaks
- Rebase segfaults
- Test robustness
- Ident validation
- Complete import/export symmetry

No outstanding technical objections remain. The implementation provides full workflow support for stash transfer while maintaining the existing stash stack behavior and validation rigor established in prior iterations.
