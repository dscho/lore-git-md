This is a discussion contribution to the ongoing debate about whether to add a new `git-blame-tree` command or integrate directory-blame functionality into the existing `git blame`. The email comes from D. Ben Knoble, who weighs in on Marc Branchaud's proposal to have `git blame` automatically handle directories differently from files.

Knoble expresses support for Branchaud's idea of making `git blame` smart enough to distinguish between files and directories, noting that this would turn current error cases (like `git blame t` failing when 't' is a directory) into useful functionality. He suggests this could be an "expansion of capabilities" rather than a new command.

The email also proposes a third way forward: keeping `git-blame-tree` as plumbing (similar to `diff-tree`) while having the porcelain `git blame` command use it internally when given a directory. This would maintain separation of concerns while providing a unified user interface.

This continues the thread's central tension between command proliferation concerns and implementation complexity. Knoble's suggestion offers a potential middle ground that addresses both usability and code organization considerations. The discussion remains unresolved but is moving toward concrete technical pathways for integration.
