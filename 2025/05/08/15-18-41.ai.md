This is the first patch in the final v6 series improving `git send-email`'s domain validation and OAuth2.0 documentation. The patch tightens the RFC1035-compliant domain name validation in `valid_fqdn()` to properly reject malformed domains that were previously accepted.

The key changes are:
- Replaces the simple dot-check with a full RFC1035 regex pattern that enforces:
  - 1-63 character labels between dots
  - Alphanumeric start/end for each label
  - No consecutive dots
  - Maintains the special macOS `.local` exclusion
- Introduces a `$subdomain` variable for the repeated label pattern
- Fixes a real-world issue where invalid domains like "MacBook.." were being passed to SMTP servers, causing failures

The patch demonstrates the problem with actual SMTP session logs showing the invalid domain being rejected by Outlook's SMTP servers, and the fixed behavior falling back to "localhost.localdomain" properly. The implementation follows Junio's earlier suggestion to extract the repeated regex pattern into a variable for readability.

This is the technically approved implementation from v5, now with final documentation formatting. The change is well-motivated by actual SMTP failures and provides proper validation that matches email infrastructure expectations. The test coverage mentioned in the thread context verifies edge cases including hyphen placement and length limits.
