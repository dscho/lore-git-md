This thread addresses a memory leak in Git's commit-graph handling code. The issue occurs when processing packfiles - if opening a pack's index fails, the code wasn't properly cleaning up the allocated `packed_git` struct. The fix is straightforward, adding proper cleanup in the error path by calling `close_pack()` and freeing the struct when `open_pack_index()` fails. The patch modifies just two lines in `commit-graph.c` to plug this leak, which could otherwise cause memory loss during commit-graph operations involving problematic packfiles. The change is small, focused, and uncontroversial - a clear bugfix with no expected side effects.
