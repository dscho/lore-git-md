This thread addresses a memory leak in Git's commit-graph subsystem, specifically in the `fill_oids_from_packs()` function where a `packed_git` struct would leak when `open_pack_index()` fails. Lidong Yan submitted the initial fix, which adds proper cleanup with `close_pack()` and `free(p)` calls in the error path - a minimal but important 2-line change.

The patch went through two rounds of review focused on documentation improvements. Patrick Steinhardt first suggested referencing the function name rather than line numbers in the commit message, which Lidong incorporated in v2. In this final round, Patrick noted the commit subject should use the standard "commit-graph:" prefix rather than the specific function name, following project conventions.

All technical aspects of the fix itself were agreed upon from the start, with the discussion focusing solely on commit message formatting. With these documentation suggestions now addressed, the patch appears ready for merging. The change is narrowly scoped to the error path when pack index opening fails and has no impact on normal commit-graph operation. This was a clean, focused thread with clear consensus on both the problem and solution.
