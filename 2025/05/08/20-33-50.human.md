This is a follow-up discussion in the completed series optimizing packed-refs memory usage, focusing on mmap strategy details. Jeff King (peff) responds to Junio Hamano's observation that the temporary snapshot approach may be unnecessary for fsck operations.

The key points are:
1. They agree the preliminary refactoring for temporary snapshots can likely be removed since direct mmap/verify/unmap would be more efficient for fsck operations.
2. Jeff analyzes the mmap strategy handling, noting MMAP_NONE only occurs when NO_MMAP is set, since there's no config mechanism to set mmap_strategy directly.
3. He considers but dismisses simplifying away MMAP_NONE entirely due to edge cases with MMAP_PREVENTS_DELETE and NO_MMAP combinations that could cause redundant copies.
4. The discussion suggests the original code's mmap strategy handling has some historical quirks that aren't worth revisiting now, given the small file size optimization already in place.

This email wraps up the technical discussion after Junio's final ack, confirming the series is ready for integration with the understanding that fsck operations will use direct mmap rather than the temporary snapshot approach.
