Feature patch adding stash export capability, part 3/4 in a series. This introduces a new `git stash export` subcommand that converts stashes into regular commit chains that can be pushed/pulled between repositories. The patch solves a common workflow problem where users want to transfer stashed work between machines but currently can't because stashes live only in reflogs. The implementation creates a chain of commits where each exported stash commit has two parents - one linking to the previous stash (or an empty base commit) and one preserving the original stash content. Users can either print the resulting commit hash or store it to a specified ref.

Key technical details:
- New `export` subcommand with `--print` and `--to-ref` options
- Creates predictable empty base commit using fixed timestamp (2001-09-17)
- Preserves original stash metadata (author/committer/message) in exported commits
- Handles both specific stash references and iterating through all stashes
- Uses quiet OID lookup to gracefully handle missing stashes
- Modifies documentation to include new subcommand and options

The implementation appears thorough, with careful handling of commit metadata and parent linkage. The commit message clearly explains the motivation and approach. This builds on previous patches in the series (not shown here) that presumably laid groundwork for stash manipulation.
