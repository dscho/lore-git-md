This is a bugfix patch addressing a memory leak in the email header decoding logic. 

The patch fixes a case in `mailinfo.c` where a failed character set conversion could leak memory. When `convert_to_utf8()` fails during header decoding, the function would exit without properly freeing the allocated `strbuf` and its contents. The fix adds cleanup calls to `strbuf_release()` and `free()` in the error path.

The change is straightforward and appears correct - it plugs a clear memory leak in an error-handling path. The patch is small (just 4 lines changed) and focused on the specific issue. While the commit message is brief, it accurately describes both the problem and solution.

This affects the email parsing code path in Git, which is used when applying patches received via email. The memory leak would only occur when processing malformed or unsupported character encodings in email headers.
