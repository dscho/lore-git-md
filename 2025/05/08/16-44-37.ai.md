This is patch 3/5 in a build system series fixing configuration path handling across Git's build systems. The patch corrects how Meson handles system-wide gitconfig and gitattributes file locations, addressing an issue where paths were incorrectly defaulting to absolute `/etc` paths regardless of the installation prefix.

The change removes hardcoded `/etc` defaults from meson_options.txt and implements proper sysconfdir handling. When users don't specify custom paths, the build now uses `<sysconfdir>/gitconfig` and `<sysconfdir>/gitattributes`, where sysconfdir follows standard conventions (e.g. `/usr/local/etc` for `/usr/local` prefix). The implementation preserves the ability to override paths via command-line options while ensuring correct relative path handling.

Key technical changes:
- Removes default `/etc` values from meson_options.txt
- Adds logic in meson.build to use sysconfdir when no override is provided
- Maintains backward compatibility with explicit path overrides
- Updates ETC_GITCONFIG/ETC_GITATTRIBUTES compiler definitions accordingly

This continues the series' theme of standardizing path handling across build systems, following patch 2's Perl module path correction. The change is well-contained (meson.build and meson_options.txt only) and maintains the series' focus on build system consistency. The patch appears technically sound with clear motivation and implementation.
