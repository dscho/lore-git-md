This is a discussion about UI design for the proposed `git-blame-tree` command, specifically around integration with `git blame` and recursion behavior.

Marc Branchaud responds to Junio Hamano's feedback about the command's behavior when given file vs. directory paths. Junio had clarified that `git blame path/to/file` must maintain its current line-by-line annotation behavior and shouldn't be repurposed to show file-level blame. Marc agrees with this constraint, noting that `git log -1` already provides the "last commit" information for a file.

The discussion then turns to whether directory blame should recurse by default. While Junio had no strong preference, Marc suggests making non-recursive the default with an option to enable recursion, arguing this would be more user-friendly by avoiding potentially overwhelming output. However, Marc acknowledges this isn't a strong position and leaves the final decision open.

This email continues the thread's central debate about how to best integrate the new functionality - whether as a separate command, integrated into `git blame`, or split between plumbing and porcelain. The exchange shows progress in narrowing the design space, with clear constraints emerging around maintaining backward compatibility for existing `git blame` behavior.
