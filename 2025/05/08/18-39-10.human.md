This is a technical response in the ongoing discussion about Git bundle-based backup strategies, addressing a critical edge case in timestamp-based incremental backups.

Jeff King responds to Abhishek Dalmia's discovery that `--since`-based bundle creation can miss commits with backdated timestamps, which poses a serious problem for reliable incremental backups. He proposes two alternative approaches that avoid timestamp dependence entirely.

The first solution involves maintaining a snapshot file of previous bundle contents and using it to exclude already-backed-up objects in subsequent runs. Jeff provides a concrete shell script example that creates bundles while tracking object IDs from previous backup, though he notes this relies on parsing bundle internals.

The second, more fundamental suggestion is to bypass `git bundle` entirely in favor of directly managing ref snapshots (via `for-each-ref`) and thin packs (via `pack-objects`), which would provide more control over the backup process. This approach essentially reimplements bundle functionality at a lower level.

The response significantly advances the thread by moving past the problematic timestamp-based approach while maintaining the core goal of efficient incremental backups. Jeff's solutions appear technically sound but introduce new implementation complexity that backup system designers would need to weigh against the benefits. The discussion continues to evolve toward more robust backup strategies that can meet enterprise reliability requirements.
