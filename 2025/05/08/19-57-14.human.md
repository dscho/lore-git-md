This is a review comment on patch 3/4 of the packed-refs memory optimization series, which has already been acked and is ready for integration. Jeff King (Peff) points out a subtle behavior change in the refactored mmap cleanup code.

The patch extracted munmap operations into a new `munmap_temporary_snapshot()` function, but in doing so changed when the cleanup happens - the original code ran for any non-MMAP_OK strategy, while the new version only runs for MMAP_TEMPORARY. Peff notes this could be correct if MMAP_NONE never sets the mmapped flag, but suggests either documenting this assumption or keeping the original behavior.

This is a minor technical point in an otherwise complete series, showing the careful attention these memory optimizations are receiving. The thread context shows the series has already been approved with all feedback incorporated, so this observation likely serves as a final sanity check rather than requiring changes.
