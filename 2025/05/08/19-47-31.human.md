This is a technical discussion about storage efficiency in Git backup strategies, specifically responding to Michal Suchánek's filesystem-level deduplication proposal.

Jeff King (peff) analyzes the storage implications of using filesystem deduplication with unpacked Git objects, as suggested in the thread about incremental backups. He provides concrete measurements showing that storing objects unpacked would dramatically increase storage requirements compared to packed objects - in linux.git, packed objects take 2.4GB while unpacked would require ~135GB (a 56x difference). Even with zlib compression, the storage would still be 14x larger than packed objects.

The email includes useful commands for measuring object storage efficiency and explains why filesystem deduplication alone isn't sufficient. Jeff suggests an alternative approach using `.keep` files to preserve important packs permanently while still benefiting from Git's delta compression. This continues the thread's exploration of reliable backup strategies while maintaining storage efficiency, though it doesn't directly address the timestamp vulnerability concerns raised earlier in the bundle-based approaches.
