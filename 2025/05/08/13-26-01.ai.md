This is a discussion about integrating directory-blame functionality into `git blame` rather than creating a new `git-blame-tree` command. Marc Branchaud responds to Junio Hamano's clarification about distinguishing between line-level and file-level blame, proposing concrete UI behaviors for different use cases.

The email introduces several key technical suggestions for the command's behavior:
1. A `--latest` option to show only the last commit that changed a file (equivalent to `git log -1`), with the default `git blame` showing annotated blame lines
2. Implicit directory handling where `git blame path/to/directory` would show last commits for each file (non-recursive by default)
3. Explicit recursion control for directory operations

The discussion builds on the thread's ongoing debate about whether to integrate this functionality into `git blame` (Marc's position) versus maintaining a distinct `git-blame-tree` command. Marc's proposal attempts to address Junio's concern about the conceptual distinction between line-level and file-level blame by making the behaviors explicit through different invocation patterns.

This email moves the discussion toward concrete UI design questions that would need resolution if the integration approach is chosen, particularly around default behaviors and option naming. The suggestions aim to maintain intuitive usage while accommodating both the traditional line-oriented blame and new directory-oriented functionality.
