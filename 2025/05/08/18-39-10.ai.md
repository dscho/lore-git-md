This is a technical response in the ongoing discussion about Git bundle-based backup strategies, addressing the timestamp vulnerability issue raised earlier.

Jeff King (peff) responds to Abhishek Dalmia's discovery that `--since`-based bundle creation can miss commits with backdated timestamps. He proposes two alternative approaches that avoid timestamp dependence entirely. The first method involves maintaining a snapshot file of previous bundle contents and using it to exclude already-backed-up objects in subsequent bundles. The solution includes shell script snippets showing how to generate the snapshot file by parsing bundle headers and use it with `git bundle create`.

The second, more fundamental suggestion bypasses bundles entirely in favor of directly storing ref snapshots (via `for-each-ref`) and thin packs (via `pack-objects`), noting that this essentially replicates bundle functionality at a lower level. This approach would give more control over the backup process but require custom tooling to manage the components.

Key technical points include:
- The vulnerability stems from conflating commit timestamps with backup timing
- Bundle headers contain the necessary ref state information for delta calculation
- The proposed solutions shift from time-based to state-based incremental backups
- Both methods require maintaining some form of previous state tracking

This moves the discussion toward implementation alternatives that address the core reliability concern while maintaining the incremental backup capability. The response provides concrete technical pathways while acknowledging the tradeoffs between using existing bundle tools versus building custom solutions.
