This is a technical discussion about storage efficiency in Git backup strategies, specifically responding to Michal Suchánek's filesystem-level deduplication proposal. Jeff King (peff) analyzes the storage implications of storing objects unpacked versus packed, providing concrete measurements from linux.git.

Key technical points:
- Demonstrates that packed objects in linux.git occupy 56x less space than unpacked (2.4GB vs 135GB)
- Notes that even with zlib compression, unpacked storage would still be 14x larger than packed
- Provides concrete commands to measure object storage ratios (`git cat-file` pipelines)
- Points out additional inode overhead for loose objects
- Suggests `.keep` files as a better alternative for long-term pack retention

The analysis focuses on the storage efficiency tradeoffs, showing that while filesystem deduplication might work at the block level, the fundamental pack compression provides orders of magnitude better space savings. This counters Michal's suggestion by showing the storage overhead would be prohibitive for large repositories, even with deduplication.

The email advances the thread by moving from theoretical discussion to concrete measurements, providing data that favors pack-based backup strategies over filesystem-level approaches for space efficiency. It doesn't directly address the timestamp vulnerability concerns from earlier in the thread, but reinforces the value of pack-based solutions.
