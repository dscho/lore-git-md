This is a discussion about integrating directory-level blame functionality into Git, specifically debating whether it should be part of the existing `git blame` command or a separate tool. Marc Branchaud responds to Junio Hamano's clarification about terminology, agreeing that "blaming lines in a file" is more accurate than "blaming a file."

The key proposal is to enhance `git blame` with new behaviors:
- Default behavior would show annotated line-by-line blame for files (`git blame path/to/file`)
- A new `--latest` option would show just the last commit that changed a file (equivalent to `git log -1`)
- Directory targets would implicitly use `--latest` behavior, showing last commits per file
- Directory traversal would be non-recursive by default, with potential for a recursion option

This builds on earlier discussions about integrating the `git-blame-tree` functionality directly into `git blame` rather than creating a separate command. The email suggests concrete UX decisions about default behaviors while acknowledging the need for flexibility in handling different use cases. The tone is collaborative, with Marc offering specific suggestions while remaining open to alternative approaches.
