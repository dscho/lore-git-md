This thread introduces a new `git stash export`/`import` feature that enables bidirectional transfer of stashes between repositories via commit chains under `refs/stash-export/`. The series has gone through seven iterations of review and is now in its final form, ready for merging.

The core functionality was established in earlier patches, with `git stash export` creating portable stash representations. This final email adds the complementary `import` command, completing the round-trip capability. The import process carefully validates commit chains match the expected stash topology (2-3 parents per commit) and appends imported stashes to the existing stack rather than replacing them. The implementation reuses topology validation and commit-walking logic from earlier patches while adding new test coverage.

Key contributors include brian m. carlson (the primary author), Phillip Wood (who designed the topology validation), and Junio Hamano (who guided the API design). The series has achieved consensus with no remaining objections, representing a significant enhancement to stash portability. With 268 lines of test coverage and thorough documentation, this work not only solves the immediate need but also provides reusable components like the new `parse_stash_revision()` helper that may benefit future stash-related features.
