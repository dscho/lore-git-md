This is a bugfix patch for the reftable subsystem, addressing a potential memory leak in the `REFTABLE_REALLOC_ARRAY` macro when reallocation fails. The patch comes from Lidong Yan and is currently at version 1.

The issue occurs when `reftable_realloc` fails - the original pointer would be set to NULL without being freed first, leaking memory. The fix restructures the macro to properly free the original pointer in the failure case before setting it to NULL. The changes introduce a `cleanup` label and explicit error handling path that ensures cleanup occurs in both allocation size calculation failures and reallocation failures.

The patch modifies `reftable/basics.h` with a significant rewrite of the macro (20 lines added, 8 removed) to implement this safer behavior. The new version maintains the same functionality when successful but properly handles error cases. The change appears straightforward and focused, though it might benefit from including a test case demonstrating the fixed behavior.

Key technical details for future reference:
- The macro now uses a `new_p` temporary variable to hold realloc result
- Two failure cases are handled: allocation size calculation and actual reallocation
- Both cases jump to a `cleanup` label that frees the original pointer
- The macro still sets errno to ENOMEM and x to NULL on failure
- The change affects reftable's internal memory management utilities
