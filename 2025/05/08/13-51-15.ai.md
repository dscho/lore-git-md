Bugfix for a leak in the commit-graph pack handling code. This patch addresses a memory leak that occurs in `fill_oids_from_packs()` when `open_pack_index()` fails. The leak happens because the `packed_git` struct allocated by `add_packed_git()` isn't properly freed in the error path.

The fix is straightforward - adding calls to `close_pack()` and `free(p)` when the index opening fails. The patch modifies just 2 lines in `commit-graph.c`, adding the cleanup before jumping to the error handler. This appears to be a clear-cut resource management issue rather than anything controversial.

The commit message directly points to the problematic lines (1925 and 1930) and explains the solution concisely. While small, this fix plugs a real leak in error handling that could accumulate memory loss during commit-graph operations involving problematic packfiles. The change is well-contained and unlikely to have any side effects beyond fixing the leak.
