This thread explores an edge case in Git's force-push safety mechanisms when working in detached HEAD state. A contributor describes their workflow of cleaning up colleagues' branches by making changes in detached HEAD mode, then force-pushing back to the original branch. Despite no actual remote changes occurring, their push fails with a "remote ref updated since checkout" error when using both `--force-with-lease` and `--force-if-includes` together.

The core issue appears to be an interaction between these safety checks and detached HEAD state - the reflog-based verification that `--force-if-includes` performs may not work as expected without an attached branch. The thread starter has found that explicitly specifying the expected remote SHA (via `--force-with-lease=branch:SHA`) works as a workaround, but seeks confirmation on whether this behavior is intentional and if there are more ergonomic solutions. The discussion may reveal either a documentation gap or a subtle edge case in Git's force-push safety mechanisms.
