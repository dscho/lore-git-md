Performance optimization for `git repack` when handling promisor packs with kept packs (either via `--keep-pack` or `.keep` files). Original issue identified by Tomáš Trnka, with implementation by Han Young. The problem was that Git unnecessarily enumerated objects from kept packs during promisor repacking, even though these objects wouldn't be repacked. Previous fix passed `--keep-pack` to `pack-objects` but still required full enumeration. New solution skips kept packs entirely during object enumeration in `repack_promisor_objects()` using `SKIP_IN_CORE_KEPT_PACKS` and `SKIP_ON_DISK_KEPT_PACKS` flags. Changes are in `builtin/repack.c`: `collect_pack_filenames()` now marks `--keep-pack` packs as kept in-core, and `repack_promisor_objects()` skips both types of kept packs. Performance improvement is significant: test case with 2.7GB promisor pack shows time reduction from 67.6s to 18.8s, with output pack size also smaller (1.6MB vs 4.5MB). New version processes only 20,952 objects versus 19,091,575 in original, demonstrating the enumeration optimization.
