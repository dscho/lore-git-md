This is a bugfix patch for the reftable subsystem, addressing a potential memory leak in the `REFTABLE_REALLOC_ARRAY` macro. The issue occurs when memory reallocation fails - the original pointer would be set to NULL without being freed first, leaking memory.

The patch modifies the macro to properly clean up by:
1. Introducing a `cleanup` label to handle error cases
2. Freeing the original pointer before setting it to NULL when reallocation fails
3. Maintaining the same error behavior (setting errno to ENOMEM)

The change is focused and well-contained, touching only the basics.h header file in the reftable directory. The commit message clearly explains both the problem and solution, though it might benefit from mentioning that this is a defensive change (the leak would only occur in out-of-memory situations).

The patch appears technically sound and addresses a real issue, though one might wonder about test coverage for this error path since memory allocation failures can be tricky to test. The change follows the existing code style and doesn't introduce any new dependencies or side effects.
