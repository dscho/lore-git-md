This is the second patch in a series adding SHA-256 support to gitk, specifically addressing the auto-select length preference for SHA-256 repositories. The patch introduces separate storage for SHA-256 length preferences in gitk's config (as `autosellensha256`) with a default of 64 characters, while maintaining the existing SHA-1 behavior.

Johannes Sixt raises two key points in review: First, the commit message could better explain the user-facing impact rather than just implementation details. Second, he questions whether the hash algorithm should affect the preferred length at all - if a user sets a short length (like 12 characters) for example, they might want that to apply consistently across repositories regardless of hash algorithm.

The implementation itself looks thorough, with a new `get_autosellen` proc to dynamically select the length based on repository settings, and updates to all relevant UI elements (commit selection, reference copying, and preference dialogs). The changes maintain backward compatibility while properly handling both algorithms.

This appears to be the final piece needed for full SHA-256 support in gitk, though the review suggests the user experience around length preferences may need more discussion before merging. The patch hasn't yet received other feedback beyond Sixt's comments.
