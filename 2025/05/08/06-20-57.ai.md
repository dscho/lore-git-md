This is the second patch in a series adding SHA-256 support to gitk, specifically addressing hash length preferences. Johannes Sixt provides a review of Takashi Iwai's implementation that introduces algorithm-specific auto-select lengths for commit IDs.

The patch adds a new `get_autosellen` proc that dynamically returns either the SHA-1 length (40 chars) or SHA-256 length (64 chars) based on repository settings, storing the SHA-256 preference separately as `autosellensha256` in gitk's config. The changes affect several UI interactions including commit selection, reference copying, and preference dialogs.

Sixt questions the fundamental design choice of having different length preferences per algorithm, suggesting users might want consistent behavior across repositories regardless of hash type. He also notes the commit message focuses too much on implementation details rather than explaining the user-facing impact. The review doesn't identify technical flaws in the implementation itself, which appears to correctly handle the preference switching and maintains backward compatibility.
