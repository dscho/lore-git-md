This is a refactoring patch in a series about stash command internals. It's part 2 of 4 in v5 of the series from brian m. carlson.

The patch extracts stash revision parsing into a new `parse_revision()` function, moving logic that handles special stash reference formats (like numeric indices and default "@{0}" behavior) out of `get_stash_info()`. The motivation is to make this parsing reusable for future changes, though the commit doesn't specify what those changes will be.

The code change is straightforward - it preserves all existing behavior while making the logic more modular. The patch appears well-constructed with proper error handling and memory management (note the `strbuf_init`/`free_stash_info` pairing). This seems like a clean preparatory change for whatever larger stash improvements are coming in the rest of the series.
