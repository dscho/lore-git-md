Refactoring patch in the stash command series. This is part 2 of 4 in a series (no cover letter seen) that appears to be cleaning up stash implementation details.

The patch extracts stash revision parsing logic into a new `parse_revision()` function, handling three cases: when no commit is specified (defaulting to `stash@{0}`), when given a numeric index (`stash@{n}`), and when given an arbitrary revision string. The function returns -1 if no stash exists (with optional quiet mode) and 0 on success. The main change moves this logic out of `get_stash_info()` while maintaining identical behavior.

Key technical details for future reference: the function operates on a `strbuf *revision` output parameter, takes a `const char *commit` input and `quiet` flag, and preserves all existing stash reference formats (`ref_stash` symbol). The error message for missing stash remains unchanged. The patch touches only `builtin/stash.c`, modifying how revision strings are constructed but not their final form or usage.
