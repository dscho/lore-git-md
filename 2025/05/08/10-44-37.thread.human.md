This thread discusses a performance optimization for `git repack` when working with promisor packs (used in partial clone scenarios) that are marked to be kept (via `--keep-pack` or `.keep` files). The original implementation would still scan all objects in kept packs even though they wouldn't be repacked, causing unnecessary overhead.

Tomáš Trnka initially identified the issue and proposed a solution, with Han Young following up with a more efficient implementation. The key improvement skips object enumeration entirely for kept packs during promisor repacking, using new flags to avoid both in-memory and on-disk kept packs. Performance measurements show dramatic improvements - a test case with a 2.7GB promisor pack went from 67.6 seconds to 18.8 seconds, while also producing a smaller output pack (1.6MB vs 4.5MB).

The changes are focused in `builtin/repack.c` and maintain all existing behavior while being more efficient. The patch includes thorough benchmarking data showing the optimization works as intended, processing far fewer objects (20,952 vs 19 million) to achieve the same result. This appears to be a clean, well-justified optimization that should benefit users working with large promisor packs.
