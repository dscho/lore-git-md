This is a follow-up patch to the already-approved `git send-email` domain validation series, proposing an additional FQDN detection method. The patch adds a new `maildomain_hostname_command` function that attempts to get the fully qualified domain name by running `hostname --fqdn` on Linux and macOS systems, inserting this check between the existing Net::Domain module check and the final fallback to 'localhost.localdomain'.

The implementation currently:
- Only runs on Linux/macOS (`$^O` check)
- Silently ignores stderr and processes stdout regardless of command exit status
- Validates results with the existing `valid_fqdn()` function
- Maintains the same fallback chain structure

Junio Hamano acknowledges the merit of adding `hostname` as another source but raises concerns about error handling:
- Some `hostname` implementations might output garbage to stdout on error
- Current code processes output even if command fails
- Suggests checking command exit status before processing output
- Notes this is acceptable despite fork/exec cost since `maildomain()` is called at most once

The patch builds on the robust domain validation work from the main series but needs minor refinement to handle edge cases in `hostname` command behavior across different platforms. The core concept of adding this detection method appears sound and aligns with the series' goal of improving FQDN reliability.
