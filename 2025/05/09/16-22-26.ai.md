Refactoring patch in a bugfix series addressing sequencer memory safety.

This is the first of two patches fixing a use-after-free issue in the sequencer's reflog message handling. The patch moves two functions - `sequencer_reflog_action()` and `reflog_message()` - earlier in sequencer.c to avoid needing forward declarations when they are called from `pick_one_commit()` in the next patch. The changes are purely code reorganization with no functional changes - the diff shows the exact same functions being moved from near the bottom of the file to above `do_pick_commit()`.

The functions handle generating reflog messages, with `reflog_message()` using a static strbuf that will be the source of the use-after-free issue addressed in the next patch. The movement is a preparatory step to enable the actual fix while keeping the patch series cleanly separated. The commit message is straightforward and correctly describes the mechanical nature of the change.
