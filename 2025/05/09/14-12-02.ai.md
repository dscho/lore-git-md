This is part 2/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to decouple it from `the_repository`. The patch renames the `object_directory` structure to `odb_alternate` to better reflect its role and future direction.

The change addresses naming issues where "object directory" would become misleading as Git moves toward pluggable object storage backends (like databases) that may not use filesystem directories. The new name `odb_alternate` is storage-agnostic while still indicating this represents an alternate object database. The commit explains this prepares for future variants like `odb_files_alternate`.

The patch updates 28 files with 273 insertions and 270 deletions, primarily mechanical replacements of `object_directory` with `odb_alternate` and related variable renames (`odb` -> `alternate`). Key impacted areas include commit-graph handling, loose object management, and alternate ODB traversal. The change is foundational for the series but doesn't yet implement pluggable backends - it just establishes the naming convention that will enable that future work.

This follows the first patch's renaming of `raw_object_store` to `object_database` and like that change, has been validated through discussion with Junio Hamano and Derrick Stolee. The series is now in final implementation phase with core architectural decisions settled.
