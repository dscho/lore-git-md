Platform compatibility fix for BSD systems, following up on Brad Smith's patch to improve CPU detection in `thread-utils.c`. Patrick Steinhardt reviews and approves the change, which modifies the `online_cpus()` function to properly handle OpenBSD/NetBSD systems where SMT (Simultaneous Multithreading) is disabled. The patch adds support for the `HW_NCPUONLINE` sysctl parameter while maintaining the existing fallback behavior through `HW_AVAILCPU` and `HW_NCPU`.

The review confirms the change aligns with OpenBSD documentation and correctly implements the intended behavior of returning the number of active CPUs rather than physical cores when SMT is disabled. The approval suggests this is a straightforward improvement with no outstanding technical concerns. The change remains localized to the thread-utils subsystem and doesn't affect other platforms' behavior.

Key technical details for future reference: the modified function checks `HW_AVAILCPU` first, then the BSD-specific `HW_NCPUONLINE` where available, falling back to `HW_NCPU` otherwise. The sysctl interface remains unchanged for non-BSD systems. The review references OpenBSD man pages as authoritative source for the sysctl parameter behavior.
