This is part 3/17 of Patrick Steinhardt's refactoring series to decouple Git's object database from `the_repository`. Following the structural renames in patches 1-2 (renaming `raw_object_store` to `object_database` and `object_directory` to `odb_alternate`), this patch renames the implementation files from `object-store.{c,h}` to `odb.{c,h}` to match the new terminology.

The change is mechanical, updating 126 files to use the new header name. The diff shows the Makefile and meson.build updates to reference the new filenames, followed by the header include changes across the codebase. The actual content of the files remains unchanged - this is purely a file rename to align with the new naming scheme established in earlier patches.

This continues the series' systematic approach to renaming, having already settled on core structure names (`object_database` for the main store, `odb_alternate` for storage units) and the `odb_` function prefix convention. The patch maintains consistency with the architectural decisions validated by Junio Hamano and Derrick Stolee in previous discussion.

Key technical points:
- File rename preserves all existing functionality
- Updates both build systems (Makefile and meson)
- Touches a wide range of files due to the object store's central role
- Follows the established `odb_` naming prefix convention
- Part of the broader `the_repository` decoupling effort

The change is straightforward and unlikely to be controversial given it follows the already-approved naming scheme from earlier patches in the series.
