This is the second patch in a bugfix series addressing a use-after-free in the sequencer's reflog message handling. The patch reworks how reflog messages are managed during rebase operations to prevent corruption when merge commits are created.

The core issue stems from storing pointers to a static strbuf buffer that could be reallocated, leading to stale references in `ctx->reflog_message`. The fix eliminates this field from `struct replay_ctx` entirely and instead generates reflog messages locally right before commit creation, passing them directly to `run_git_commit()` and related functions. This approach maintains the same user-visible behavior while preventing any possibility of dangling pointers.

Key technical changes include:
- Removing the `reflog_message` field from `struct replay_ctx`
- Adding a `reflog_action` parameter to `run_git_commit()`, `try_to_commit()`, and `do_commit()`
- Generating reflog messages at call sites rather than storing them in the context
- Updating test t3430-rebase-merges.sh to verify correct reflog entries for merge commits

The patch demonstrates good engineering practices - it solves the memory safety issue while actually reducing code size (60 fewer lines overall) and includes a test to verify the fix works as intended.
