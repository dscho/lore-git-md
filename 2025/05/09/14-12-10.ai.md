Part of Patrick Steinhardt's ongoing series to remove `the_repository` from the object database subsystem, this patch refactors temporary primary alternate handling. The changes focus on two functions that manage temporary object directories during operations like `tmp_objdir` usage.

The patch converts `set_temporary_primary_odb()` and `restore_primary_odb()` to take explicit `struct object_database*` parameters, renaming them to `odb_set_temporary_primary_alternate()` and `odb_restore_primary_alternate()` respectively. This continues the series' pattern of making ODB operations repository-agnostic by removing implicit `the_repository` access.

Key technical changes include:
- Updated function signatures in `odb.h` with new `odb_` prefix convention
- Modified implementations in `odb.c` to use passed `odb` instead of `the_repository->objects`
- Adjusted all callers in `tmp-objdir.c` to pass the repository's ODB explicitly
- Maintained existing behavior for temporary directory swapping during object creation/migration

The changes affect temporary object directory handling during:
- Object directory migration (`tmp_objdir_migrate`)
- Primary ODB replacement (`tmp_objdir_replace_primary_odb`)
- Primary ODB restoration (`tmp_objdir_unapply_primary_odb`)

This patch builds on previous infrastructure changes in the series while maintaining the same careful approach to preserving functionality during the refactor. The modifications are mechanical but important for the overall goal of removing global state dependencies in the object storage layer.
