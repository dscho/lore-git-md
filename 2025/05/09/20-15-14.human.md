This is a discussion in the ongoing "Importing and exporting stashes to refs" feature series. Brian Carlson responds to questions from D. Ben Knoble about the motivation and technical details of the proposed stash import/export functionality.

The email clarifies the primary use case: enabling developers to synchronize their stash collections across multiple machines or ephemeral development environments like GitHub Codespaces. Carlson notes that current workarounds (like cloud syncing) can corrupt repositories, while manual stash transfer is cumbersome, especially for chains of stashes. The proposed solution would provide a safer, more convenient way to preserve this workflow state.

On the technical side, Carlson confirms that imported stashes must maintain a specific commit structure (with a fixed number of parents to track index and working tree states) and that the implementation includes validation to reject malformed imports. The response includes an example error message that would appear if someone tried to import an arbitrary commit as a stash.
