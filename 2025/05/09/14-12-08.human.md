This is part 8/17 of Patrick Steinhardt's series to refactor Git's object database subsystem, continuing the effort to remove dependencies on `the_repository` global. The patch focuses on alternate object database handling, converting functions that manage alternates to explicitly take an object database parameter instead of implicitly using `the_repository`.

The changes rename several key functions to use an `odb_` prefix and accept `struct object_database*` parameters:
- `prepare_alt_odb()` -> `odb_prepare_alternates()`
- `has_alt_odb()` -> `odb_has_alternates()`
- `add_to_alternates_file()` -> `odb_add_to_alternates_file()`
- `add_to_alternates_memory()` -> `odb_add_to_alternates_memory()`

The patch updates callers across 14 files including clone, fsck, repack, and commit-graph operations. While the changes are mechanical, they represent an important step in decoupling the ODB subsystem from global state. The commit message notes this is still transitional - the path handling will be further refined in future patches to store paths directly in the object database rather than relying on the_repository.

This continues the series' systematic approach to making object database operations repository-agnostic, with careful attention to maintaining existing behavior while changing the plumbing. The changes are wide-ranging but focused, touching core object storage operations while keeping the build stable.
