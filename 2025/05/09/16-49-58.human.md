This is a bugfix patch for `git send-email` that improves the reliability of determining the system's fully qualified domain name (FQDN). It's part of the ongoing work to improve email sending reliability, following up on the recently approved RFC1035 domain validation changes.

The patch adds a new fallback method to try getting the FQDN by running the `hostname --fqdn` command on Linux and macOS systems before falling back to 'localhost.localdomain'. The author notes that while the current Net::Domain Perl module is unreliable, the `hostname` command (which these modules themselves use internally) tends to be more reliable in practice. The patch includes references to both the Linux man page and Perl module implementations to support this claim.

The implementation adds a new `maildomain_hostname_command` function that runs the system command and validates its output using the recently improved `valid_fqdn()` function. This becomes the third fallback option in the chain, after the existing Net::Domain and MTA-based methods. The change is relatively small (14 lines added) and focused, touching only the domain resolution logic in `git-send-email.perl`.

This appears to be a well-motivated improvement that builds on the recent domain validation work. The patch is cleanly implemented with proper error handling (discarding stderr) and maintains the existing fallback behavior. It should help reduce cases where `git send-email` falls back to 'localhost.localdomain' unnecessarily while being careful to only use the command on platforms where it's known to be available (Linux and macOS).
