This is part 15/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem, continuing the effort to eliminate global state dependencies. The patch renames `has_object()` to `odb_has_object()` to align with modern coding guidelines and the ODB abstraction work.

The change follows the pattern established in previous patches, making object access operations explicitly ODB-centric rather than repository-centric. The new function takes a `struct object_database*` parameter instead of implicitly using `the_repository`. A compatibility wrapper maintains the old `has_object()` interface for in-flight topics.

The mechanical change updates 30 files across the codebase, with callers now passing `repo->objects` where needed. Behavior remains identical - the patch only changes the function signature and name, not the underlying logic. The update includes core commands like `fetch`, `clone`, and `fsck`, as well as lower-level components like the bulk-checkin and walker infrastructure.

This continues the systematic conversion of object database operations to use explicit ODB parameters, with consistent naming that reflects their ODB focus rather than repository context. The series has now converted all major object database operations, with remaining work focusing on validation and documentation.
