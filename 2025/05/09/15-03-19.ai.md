This is a follow-up discussion in the completed packed-refs memory optimization series, specifically addressing patch 3's mmap state management. The author (shejialuo) acknowledges a mistake in their earlier refactoring of the munmap operation for temporary mmap snapshots. 

The key issue revolves around the condition change from checking `mmap_strategy != MMAP_OK` to `mmap_strategy == MMAP_TEMPORARY`. While the author initially thought this simplification would work (reasoning that `MMAP_NONE` would never set `snapshot->mmapped`), they now agree with Jeff King and Junio Hamano that this change should either be reverted or properly documented. 

Junio emphasizes that refactoring patches should maintain existing behavior unless changes are explicitly justified. The author confirms they will revert this change in the next version, preserving the original defensive condition that handles both `MMAP_TEMPORARY` and `MMAP_NONE` cases. This discussion provides final clarification on the series' mmap strategy handling before integration.
