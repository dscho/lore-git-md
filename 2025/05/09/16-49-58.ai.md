This is a follow-up patch to the recently approved `git send-email` series, adding an additional fallback mechanism for determining the mail domain. The patch introduces a new `maildomain_hostname_command` function that attempts to get the fully qualified domain name (FQDN) using the system's `hostname --fqdn` command on Linux and macOS before falling back to 'localhost.localdomain'.

The technical implementation adds a new check between the existing Net::Domain module check and the final fallback. The key aspects are:
- Uses `hostname --fqdn` command which is noted to be more reliable than the current Net::Domain perl module
- Only attempts this on Linux and macOS (`$^O` checks for 'linux' and 'darwin')
- Still validates the result with the existing `valid_fqdn()` function from the previous patch
- Maintains the same fallback chain: Net::Domain -> MTA check -> new hostname command -> 'localhost.localdomain'

The commit message provides rationale by noting that:
- The `hostname` command is already used internally by the perl modules being replaced
- While the new `valid_fqdn` check prevents invalid domains, this provides better FQDN detection before falling back
- Includes references to man pages and perl module sources showing the command's reliability

This appears to be a straightforward improvement that builds on the recently approved domain validation work, adding another layer of robustness to FQDN detection. The implementation is clean and maintains all existing validation checks while adding the new fallback path.
