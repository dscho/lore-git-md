Bug investigation for `git pull --rebase` commit-dropping behavior. D. Ben Knoble follows up on Bill's report about `git pull --rebase` unexpectedly dropping commits after changing a repository's remote URL. They've created a bisect script to track when the issue first appeared, finding that the behavior dates back to at least Git 2.0 (the test stopped at this version without finding a "good" state). The bisect points to commit d717282532 ("t5537: re-drop http tests") as the first bad commit, though this may just indicate the bug's longstanding presence rather than its origin. 

Knoble notes some troubleshooting challenges, including build issues with Git master and unexpected environment variable behavior during bisect runs (GIT_DIR being set). The core issue remains unresolved, but this provides useful historical context for the bug's longevity. The thorough bisect work suggests this is a genuine issue worth deeper investigation rather than just undocumented behavior.
