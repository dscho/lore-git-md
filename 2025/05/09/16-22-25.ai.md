Bugfix patch series addressing a use-after-free issue in the sequencer's reflog message handling. This is a two-part series from Phillip Wood that fixes a reported memory safety issue while maintaining the convenience of automatic buffer management.

The core issue stems from storing a pointer to a static strbuf's buffer that could be reallocated, leading to use-after-free scenarios. The series takes a middle path between two possible solutions - rather than removing the buffer entirely (which would shift memory management burden to callers), it restructures the code to avoid keeping long-lived pointers to the potentially reallocated buffer.

The first patch is a preparatory refactoring that moves reflog message functions within sequencer.c, while the second patch implements the actual fix by reworking how reflog messages are handled. The changes touch both the sequencer implementation and its test suite, with a net reduction of 60 lines despite adding new functionality.

The bug was originally reported by Kristoffer Haugsbakk with a detailed backtrace. The changes maintain the same user-facing behavior while making the internal implementation more robust against memory corruption. The patch series appears well-structured with clear commit messages and includes test updates to verify the fixes.
