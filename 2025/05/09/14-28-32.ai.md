This is a bugfix patch addressing memory leaks in Git's parse-options machinery, specifically handling unknown bundled short options (like "-abc") when PARSE_OPT_KEEP_UNKNOWN is used. The patch represents Lidong Yan's third iteration on this issue, now proposing a marker-based solution after previous discussions explored alternative approaches.

The key technical change introduces a magic byte (0xee) prefix before heap-allocated unknown options, allowing subsequent parse_options_step() calls to detect and free previously allocated memory. The implementation:
1. Adds OPT_MAGIC constant (0xee) in parse-options.h
2. Modifies parse_options_step() to check for and free magic-prefixed strings
3. Allocates new unknown options with the magic prefix +1 byte
4. Preserves the original "-" prefix behavior while preventing leaks

This approach differs from the in-place modification solution discussed in the thread, instead maintaining the earlier marker-based strategy but with refined implementation. The patch touches both parse-options.c (core logic) and parse-options.h (new constant definition).

The thread history shows this competes with Phillip Wood's simpler in-place modification approach, with Patrick Steinhardt having previously raised concerns about solution complexity. This version appears to be a refinement of Lidong's earlier proposals rather than adopting the in-place method, suggesting ongoing evaluation of tradeoffs between allocation tracking and direct buffer modification.
