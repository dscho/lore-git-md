This patch continues Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to remove dependencies on `the_repository`. The focus here is on submodule alternate handling, specifically for `git grep --recursive` which needs to search across submodule boundaries.

The key changes move submodule alternate tracking from a global string list to being stored directly in the object database structure. The patch:
1. Adds a `submodule_alternate_paths` string list to `struct object_database`
2. Renames `add_submodule_odb_by_path()` to `odb_add_submodule_alternate_by_path()`
3. Replaces `register_all_submodule_odb_as_alternates()` with `register_all_submodule_alternates()` that operates on a specific ODB
4. Removes the `r == the_repository` check since alternates are now tracked per-ODB
5. Updates callers in `builtin/grep.c` and `submodule-config.c` to use the new API

The changes maintain existing behavior while making the submodule alternate handling repository-agnostic. This is part of the larger effort to support multiple repository backends by removing global state dependencies. The patch follows the established pattern in the series of moving functionality into the ODB structure with `odb_`-prefixed names.

Technical details to note for future reference:
- New `submodule_alternate_paths` field in `object_database` struct
- `odb_add_submodule_alternate_by_path()` API for registering paths
- `register_all_submodule_alternates()` now takes an ODB parameter
- Trace2 events maintained for debugging
- `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB` test knob preserved
- All submodule alternate handling code moved from `submodule.[ch]` to `odb.[ch]`
