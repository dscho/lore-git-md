This is a refactoring patch in the stash import/export series, specifically addressing code organization in `builtin/stash.c`. Maintainer Junio Hamano provides two technical review comments on patch v5/4.

The patch extracts stash revision parsing logic into a new `parse_revision()` function to enable future reuse, handling three input forms: empty (defaulting to `stash@{0}`), numeric (converting to `stash@{n}`), and direct references. While the refactoring itself is sound, Hamano notes two concerns:

1. The function's name `parse_revision()` is too generic for its stash-specific purpose, suggesting it could be confused with revision.c's more widely-used parsing. Since it's static, this is a minor naming clarity issue rather than a technical problem.

2. More critically, the patch introduces a premature `free_stash_info()` call in the error path of `get_stash_info()`, breaking the established pattern where callers handle cleanup. This could lead to double-free issues if the cleanup pattern changes, even if currently safe due to idempotency.

These appear to be the final polish items needed before the series can be merged, as they don't affect the core functionality but address code organization and robustness concerns. The feedback continues the maintainer's pattern of thorough review on this otherwise well-received series.
