Part of Patrick Steinhardt's ongoing refactoring series to remove `the_repository` dependency from the object database subsystem. This patch focuses on alternate object database handling, converting functions to explicitly take a `struct object_database*` parameter rather than implicitly using the global `the_repository`.

Key changes:
- Renames `add_to_alternates_file()` to `odb_add_to_alternates_file()` and adds ODB parameter
- Renames `add_to_alternates_memory()` to `odb_add_to_alternates_memory()` with ODB parameter
- Renames `prepare_alt_odb()` to `odb_prepare_alternates()` with ODB parameter
- Renames `has_alt_odb()` to `odb_has_alternates()` with ODB parameter
- Updates all callers across 14 files to use the new functions
- Documents the new functions in odb.h with their explicit ODB requirements

The patch maintains the current behavior where alternates still reference paths through the repository, but sets up the infrastructure to eventually store paths directly in the object database structure. This is part of the larger architectural shift where ODB operations are being decoupled from repository state.

The changes are mechanical but widespread, touching core operations like clone, fsck, repack, and commit-graph handling. The patch follows the established pattern of the series by systematically converting implicit global state usage to explicit parameter passing.
