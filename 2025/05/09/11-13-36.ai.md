Platform compatibility and backup strategy discussion.

Michal Suchánek responds to Akash S's inquiry about incremental Git backups with a focus on filesystem-level approaches, though this follows previous discussion establishing pack-based solutions as superior. The email provides practical steps for optimizing full backups and speculates about incremental approaches using shared object stores.

Key technical details include:
- Recommends `--bare --mirror` for initial clones
- Suggests `repack -adk` to consolidate packs and preserve unreachable objects
- Notes `-k/--cruft` is required to avoid corruption
- Proposes untested incremental approach using shared clones with `fetch -p`
- Mentions need for `--local` flag when repacking shared clones

The proposal differs from earlier state-tracking and bundle approaches by leveraging filesystem sharing between clones. However, this comes after quantitative analysis showed filesystem approaches are 14x less space-efficient than pack-based solutions. The email maintains technical correctness of the approach while acknowledging it hasn't been tested, effectively positioning it as a possible but suboptimal alternative to the pack-based methods already discussed in the thread.

The response doesn't challenge the established consensus favoring pack-based solutions but provides additional options for those who might prefer filesystem-level approaches despite their space inefficiency. It notably doesn't address the timestamp vulnerability concerns raised against earlier bundle proposals.
