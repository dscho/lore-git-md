This is the second patch in a bugfix series addressing a use-after-free issue in Git's sequencer during rebase operations. The problem caused corrupted reflog entries when running `git rebase --rebase-merges`, where stale pointers to freed memory would produce garbage output.

Phillip Wood's solution restructures the reflog message handling to eliminate the unsafe pattern of storing pointers to a static strbuf. The patch moves message generation closer to commit creation and passes it through function parameters rather than storing it in the replay context. This narrower scope prevents the use-after-free while maintaining the same user-visible behavior.

The changes touch core sequencer operations but are focused on memory safety rather than functionality - all rebase operations should continue working exactly as before, just without the memory corruption risk. The patch includes an updated test that verifies both the correct reflog message content and proper merge commit creation.

This appears to be a well-considered fix for a real memory safety issue, with clear commit messages and appropriate test coverage. The changes are surgical and maintain the existing behavior while eliminating the problematic memory management pattern.
