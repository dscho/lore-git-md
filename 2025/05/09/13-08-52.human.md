This is a bugfix proposal for Git's parse-options machinery, offering a simpler solution to the memory leak discussed in the ongoing thread. Phillip Wood agrees with Patrick Steinhardt's earlier concerns about complexity and suggests an alternative approach that avoids string duplication entirely.

The patch modifies how unknown options are handled in `parse-options.c`, replacing the current leaky `xstrdup` with a direct array move operation. Phillip argues this is safe because bundled options preceding unknown ones can't have values that would interfere. The change is minimal - just a few lines touching the same code path as previous proposals.

This comes as the thread has been debating whether the leak (now understood to occur only in specific multi-call scenarios with `PARSE_OPT_KEEP_UNKNOWN`) justifies any architectural changes. Phillip's solution appears simpler than both the original `strdup_fn` approach and Lidongyan's marker-based proposal, though it does involve modifying input strings which some might consider risky.

The patch maintains the thread's focus on fixing the leak while significantly reducing implementation complexity. It may help break the deadlock between "fix is too complex" and "leak should be fixed" positions, though reviewers will need to evaluate whether the string modification is truly safe in all cases.
