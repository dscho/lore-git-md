This is part of Patrick Steinhardt's ongoing refactoring series to decouple the object database (ODB) subsystem from `the_repository`. Patch 4/17 introduces parent pointers between ODB structures to maintain repository relationships without global state.

The change adds two key parent pointers:
1. `struct object_database` gains a `repo` field pointing to its owning repository
2. `struct odb_alternate` gains an `odb` field pointing to its parent object database

These pointers enable future patches to access repository-specific configuration while maintaining the architectural goal of removing `the_repository` dependencies. The implementation requires modifying ODB initialization in `odb_new()` and adjusting the alternates linking chain (`link_alt_odb_entry()`, `read_info_alternates()`, etc.) to propagate the parent relationships.

The patch demonstrates careful consideration of the object lifetime management - alternates inherit their parent ODB pointer during creation, and the main repository's ODB is properly initialized with its repo pointer. The changes are mechanical but foundational for the series' goal of proper ODB/repository separation.

Technical details important for future reference:
- New fields: `object_database->repo`, `odb_alternate->odb`
- Modified initialization: `odb_new()` now takes `repo` parameter
- Key functions updated: `link_alt_odb_entry()`, `read_info_alternates()`, `link_alt_odb_entries()`
- Maintains existing behavior while enabling future `the_repository` removal
- Touches core ODB operations but doesn't yet remove any global state uses

This represents a stepping stone in the larger architectural shift, with the parent pointers providing the necessary scaffolding for subsequent patches to properly handle repository-specific configuration access.
