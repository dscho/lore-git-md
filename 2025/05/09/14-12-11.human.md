This is part 11 of Patrick Steinhardt's ongoing series to refactor Git's object database (ODB) subsystem, continuing the effort to remove dependencies on `the_repository` global. The patch focuses on submodule alternate handling during operations like `git grep --recursive`.

The change moves submodule alternate tracking from a global string list into the object_database structure itself. Previously, submodule paths were stored in a global list and only registered as alternates when needed (via `add_submodule_odb_by_path()`), with the assumption they'd be used with `the_repository`. The new approach stores these paths directly in the ODB structure and removes the `the_repository` check when registering them.

Key changes:
- Adds `submodule_alternate_paths` string list to `struct object_database`
- Renames functions to use `odb_` prefix (`odb_add_submodule_alternate_by_path`)
- Updates callers in `builtin/grep.c` and `submodule-config.c`
- Removes now-unused submodule ODB functions from `submodule.[ch]`

The patch appears mechanically sound, following the established pattern of the series. It maintains existing behavior while making the code more repository-agnostic. The change is particularly important for `git grep --recursive` functionality that needs to access submodule objects.
