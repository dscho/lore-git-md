This is part 4/17 of Patrick Steinhardt's series refactoring Git's object database subsystem to remove dependencies on `the_repository` global. The patch introduces parent pointers between object databases and their owning repositories, a key piece of infrastructure for the larger decoupling effort.

The change adds `repo` and `odb` pointer fields to `struct object_database` and `struct odb_alternate` respectively, allowing code to navigate from an object store back to its repository when needed (such as for config lookups). The patch updates all relevant initialization and alternate-handling code to maintain these pointers, including modifications to `odb_new()`, `link_alt_odb_entry()`, and repository setup functions.

The implementation appears thorough, with careful attention to maintaining the pointer relationships when creating new object databases and alternates. The changes are mechanical but necessary for the larger architectural goal of making object storage independent of the repository singleton. This continues the series' pattern of well-contained, incremental steps toward the final decoupled design.
