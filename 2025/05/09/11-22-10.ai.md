This is a follow-up in the incremental Git backup discussion, where Michal Suchánek provides additional details about filesystem-level approaches using shared clones. Michal clarifies that the initial clone should use `--bare --mirror` for easier updates, and recommends `repack -adk` (with `--cruft`) to reduce repository size while avoiding corruption. His incremental backup approach involves creating shared clones of the full backup, updating their origin URLs, and using `-p` flag with fetch operations.

The key technical detail added here is the requirement for `--local` flag when repacking shared clones, which maintains object sharing between incremental backups and the full backup. Michal acknowledges this approach remains untested and reiterates that these repositories can be inspected with standard Git commands.
