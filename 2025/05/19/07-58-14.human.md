This is a test patch in the ongoing series about detecting memory leaks when loading corrupt bitmap indexes. The author (lidongyan) is responding to Jeff King's suggestion to simplify the test implementation by using shell commands (`dd`) to corrupt bitmap files rather than C code. 

The thread has settled on integrating these tests with the original memory leak fixes rather than keeping them as a separate series. Jeff's proposed approach would corrupt specific offsets in the bitmap file (120 bytes plus the hash size) to trigger error conditions, then verify Git handles them properly by comparing `rev-list` outputs. 

The author agrees with this direction, noting the shell-based approach is simpler and more realistic for simulating on-disk corruption. The tests will eventually need to be marked with `!SANITIZE_LEAK` until the underlying leaks are fixed, or sequenced after those fixes in the final patch series. This represents a clean technical compromise - keeping the core corruption detection in C where needed for hash algorithm handling, while moving the test cases to more maintainable shell scripts.
