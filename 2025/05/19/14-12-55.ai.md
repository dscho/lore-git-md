This is a refactoring patch that's part of a 5-patch series enhancing the promisor-remote protocol. It's the first patch in v3 of the series, which has already undergone extensive review with all major design decisions settled.

The patch replaces the existing `strvec`-based storage of promisor remote information with a new `struct promisor_info` linked list. This change provides better type safety and clearer field handling as the protocol expands to support additional remote attributes beyond just name and URL. The new structure explicitly names each field (currently just `name` and `url`) rather than using generic string vectors, making the code more self-documenting and easier to extend.

Key technical changes include:
- Introduces `struct promisor_info` with `next`, `name`, and `url` members
- Replaces `promisor_info_vecs()` with `promisor_config_info_list()`
- Updates all related functions to use the new structure
- Adds proper memory management via `promisor_info_list_free()`
- Maintains identical external behavior while improving internal structure

The refactoring enables the series' subsequent patches to cleanly add support for new promisor-remote fields (partialCloneFilter and token) while maintaining protocol backward compatibility. The change was specifically suggested by Patrick Steinhardt during v2 review to improve type safety and code clarity.

This foundational change has already been reviewed and agreed upon by the thread participants, with the only remaining feedback being Junio C Hamano's final review of the complete series. The patch includes comprehensive updates to all affected code paths while preserving existing functionality.
