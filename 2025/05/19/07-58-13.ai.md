This is a follow-up discussion in the string-list test modernization thread, specifically about patch 3/8 which simplifies string-list insertion logic. Jeff King provides historical context about the "-1-index" pattern used when inserting existing elements, confirming it dates back to the original implementation but was never actually needed for `add_entry()`'s behavior.

Key technical details:
- The patch changes `add_entry()` to directly return positive indices rather than using negative values to indicate existing elements
- Jeff confirms this is safe since callers always get a valid index pointing to the matching entry
- The negative-index pattern originated from other string-list functions like `string_list_find_insert_index()`
- No functional change results from this simplification
- Patrick Steinhardt had previously suggested optional inlining of `get_entry_index()` in this patch

The email reinforces that this change is correct while satisfying historical curiosity about the original implementation pattern.
