Performance optimization patch modifying `git-fetch` to use batched reference updates, part of a v3 series introducing this capability across multiple commands. This is patch 2/4 in the series.

The change replaces `git-fetch`'s per-reference transaction model with batched updates using the new infrastructure from commit 23fc8e4f61. The key technical aspects are:

1. Removes custom error codes `STORE_REF_ERROR_OTHER` and `STORE_REF_ERROR_DF_CONFLICT` in favor of the new enum-based transaction error types
2. Introduces `ref_transaction_rejection_handler` callback to process failed updates after transaction commit
3. Maintains existing error reporting behavior while changing the timing (errors now reported post-commit rather than per-update)
4. Shows significant performance gains: 22x faster for reftable backend with 10k refs, 1.25x for files backend

The patch touches core fetch functionality in `builtin/fetch.c`, with changes to:
- `s_update_ref()` (simplified transaction handling)
- `store_updated_refs()` (removed error reporting now handled by callback)
- `do_fetch()` (added batched transaction setup and error handling)

Error handling now uses the thread's agreed-upon `ref_transaction_error_msg()` API (returning string literals) and properly tracks F/D conflicts via the new callback mechanism. The implementation appears thorough, with all custom error handling migrated to the new system and test coverage maintained.

This continues the series' pattern of maintaining backward compatibility while delivering substantial performance improvements, particularly for the reftable backend. The changes align with the thread's resolved design decisions around error handling and memory management.
