This thread introduces a refactoring to improve ref transaction error handling by making error message generation available to all ref transaction code. The patch moves the error message generation logic from `builtin/update-ref.c` to a new public function `ref_transaction_error_msg()` in `refs.c`, handling all error types introduced in commit 76e760b999. 

The change is part of a 4-patch series and represents a clean architectural improvement - taking existing error message generation that was previously buried in update-ref and elevating it to a proper public API. The implementation maintains identical error strings while making the functionality available to all ref transaction clients. Junio C Hamano provided input on the approach (helped-by). The patch stands well on its own as the first step in the series, with subsequent patches likely building on this foundation.
