Bugfix patch in the batched reference updates performance optimization series (v3 3/4), addressing a memory leak in `git-send-pack` when handling duplicate reference updates. This follows up on earlier feedback from Junio Hamano and Jeff King about memory management in the series.

The patch fixes a specific leak that occurs when pushing duplicate ref updates that fail - the `remote_status` field would be overwritten without freeing the previous value. The fix adds a `free()` call before overwriting the status message. A new test case is added to `t5408-send-pack-stdin.sh` that explicitly tests multiple duplicate ref updates to catch this case.

The change is narrowly focused on the memory leak issue while maintaining the existing behavior of the command. The test demonstrates the scenario where multiple updates to the same ref (A:foo, B:foo, C:foo) are pushed and fail, which would previously leak memory. The fix ensures proper cleanup in this case.

This patch builds on the series' broader work to optimize reference updates by batching them, where earlier patches established the infrastructure for batched updates and error handling. The memory management here aligns with the series' overall approach to error handling via the `ref_transaction_error_msg()` API that was finalized in earlier rounds of review.
