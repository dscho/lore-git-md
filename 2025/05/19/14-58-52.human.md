This is part 7 of Jeff King's 13-patch series removing support for non-standard object types in Git. The series has already received maintainer approval for its technical approach, with this patch awaiting Junio Hamano's review.

The patch removes the `type_name` strbuf mechanism from `oid_object_info()`, which previously allowed callers to get object types as raw strings rather than enum values. This functionality was originally intended to support non-standard object types, but since the series treats such types as errors and there are no remaining callers using this feature, the code can be simplified.

Junio Hamano confirms the change is sound, noting that with standardized type handling now in place, we can simply pass around the enum values and convert to strings when needed. The patch continues the series' trend of cleaning up now-unnecessary infrastructure after removing non-standard type support.

The changeset is small (12 lines removed, 2 added across 4 files) and straightforward, touching object-file handling code. Since this is a later patch in an already-approved series and Junio has explicitly endorsed the approach, it appears ready to merge once the documentation question from patch 2/13 is resolved.
