Feature request for `git reset --hard` to preserve work via reflog

Josh Bleecher Snyder proposes making `git reset --hard` automatically stash changes in the reflog before executing the reset. The motivation comes from occasional painful experiences where resetting discards uncommitted work that could have been recovered if it had been stashed first. The suggested behavior would be equivalent to manually running stash commands before the reset, but done automatically to prevent accidental data loss. 

This appears to be a well-motivated quality-of-life improvement for users who frequently use `reset --hard`. The proposal is straightforward and addresses a real pain point, though it would represent a behavior change for a fundamental Git command. The implementation would need to carefully consider edge cases and whether this should be opt-in via configuration.

The change would affect the reset command's interaction with the reflog, potentially making it safer at the cost of some automatic background operations. No implementation details or patches are provided yet - this is purely a feature request to gauge interest from the community.
