Feature enhancement to the promisor-remote protocol, part 2/5 of a series extending remote attribute validation. This patch introduces server-side configuration for advertising additional remote fields ("partialCloneFilter" and "token") through the promisor-remote capability.

The core addition is the `promisor.sendFields` config option, which specifies which remote attributes to advertise. The implementation:
- Defines allowed field names in a static array (`known_fields`)
- Adds config parsing to collect requested fields
- Extends `struct promisor_info` to store filter and token values
- Modifies the protocol advertisement to include configured fields after mandatory name/url
- Documents the new capability in config/promisor.adoc and protocol-v2.adoc
- Includes comprehensive tests verifying field transmission

Key protocol changes:
- Server must still send name/url first
- Optional fields follow in any order
- Field values must be URL-encoded
- Unknown fields must be ignored by clients (forward compatibility)
- Currently only supports partialCloneFilter and token fields

The test case verifies proper transmission of configured fields while maintaining existing functionality. Documentation updates include BNF notation for the protocol format and explanations of field purposes. This builds on patch 1/5's structural changes to `promisor_info` and sets up for client-side validation in subsequent patches.

Implementation appears thorough with good test coverage and clear documentation. The approach maintains backward compatibility while adding the new functionality in a constrained way (only two predefined fields allowed). This matches the series goal of enabling secure attribute validation without breaking existing clients.
