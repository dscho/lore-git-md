Performance test infrastructure for bitmap corruption detection. This is a response to Lidong Yan's initial patch that added test infrastructure for detecting corrupt bitmap indexes during loading. Patrick Steinhardt raises two main points about the implementation approach.

First, he notes the patch lacks motivation - while it demonstrates we *can* test corruption scenarios, it doesn't explain why we *should*. Second, he questions whether the test logic belongs in pack-bitmap.c rather than being moved to either test-bitmap.c or a new unit test. He suggests unit tests might be particularly appropriate since the expected behavior is graceful failure handling.

The technical discussion focuses on code organization rather than the corruption detection approach itself. The original implementation introduced a framework with two specific corruption scenarios (invalid commit positions and XOR offsets) that carefully handles mmap'd data during testing. Patrick's feedback doesn't challenge the technical merits of these tests, but rather their placement in the codebase.

This appears to be early-stage review feedback on a test infrastructure patch, with the reviewer pushing for better separation of test vs production code and clearer justification for the testing approach. The core functionality seems sound but may need restructuring based on project conventions.
