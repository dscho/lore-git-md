Performance optimization for packfile handling, specifically addressing repeated failed lookups of missing packs in the multi-pack-index (midx) cache.

Jeff King proposes a concrete implementation to cache failed pack lookups in the midx->packs array by introducing a third state (-1) to represent "lookup failed", alongside the existing NULL (not yet looked up) and valid pointer states. This directly addresses the syscall overhead issue from the original patch while maintaining the safety constraints Junio Hamano emphasized about pack verification order.

The patch shows the code changes needed in midx.c to implement this caching, with careful handling of the new state in both prepare_midx_pack() (where lookups occur) and close_midx() (where cleanup happens). Junio expresses approval for this direction, having previously questioned whether repeated failures were actually occurring in practice.

This appears to be a well-considered solution that preserves correctness while optimizing the pathological case where stale midx entries reference missing packs. The changes are focused and maintainable, though as with any cache invalidation scheme, there may be subtle edge cases to consider around repacking operations. The discussion seems to be converging on this approach as it cleanly separates the performance optimization from the safety-critical pack ordering constraints.
