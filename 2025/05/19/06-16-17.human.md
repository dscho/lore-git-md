This is a follow-up discussion on patch 2/13 in Jeff King's series removing support for non-standard object types. The patch makes `--allow-unknown-type` a no-op in `git cat-file` while retaining the option for backward compatibility.

Patrick Steinhardt suggests two potential improvements: (1) adding a test to verify the option is accepted (even though it does nothing), and (2) explicitly documenting the deprecation path in the manpage. Jeff King is ambivalent about both suggestions - he notes the no-op behavior is obvious from the code, and questions whether deprecation documentation would just add clutter. However, he provides a sample patch showing how the option could be marked more clearly as a no-op using `OPT_NOOP_NOARG`.

The discussion remains open-ended, with Jeff acknowledging Patrick's points but not strongly advocating for either change. This appears to be a minor polish question on an otherwise technically complete patch that has maintainer approval. The core functionality (making the option a no-op) is uncontroversial and already implemented.
