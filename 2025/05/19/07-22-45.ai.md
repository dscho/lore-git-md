This is a follow-up discussion on patch 2/13 in Jeff King's series removing non-standard object type support, focusing on the deprecation approach for the `--allow-unknown-type` option in `git cat-file`.

The email continues the conversation about how to handle the now-no-op `--allow-unknown-type` flag. Jeff King proposes using `OPT_NOOP_NOARG` to make the no-op status unambiguous in the code, while Patrick Steinhardt raises concerns about documentation for users who might encounter the option in existing scripts. 

Key technical points:
- The option is being retained for backward compatibility but does nothing
- Current implementation uses `OPT_HIDDEN_BOOL` with an internal flag
- Proposed change would use `OPT_NOOP_NOARG` for clearer signaling
- Help text would show "no-op (backward compatibility)" when using `--help-all`

The discussion reveals differing perspectives on documentation:
- Jeff leans toward minimal documentation, relying on release notes
- Patrick suggests a deprecated section in the manpage to help users understand why the option exists but does nothing
- Both agree the technical implementation is sound regardless of documentation approach

This represents the last open question in the otherwise complete series, with maintainer Junio Hamano having already approved the technical approach. The decision now centers on user-facing communication rather than code changes.
