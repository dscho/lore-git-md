This is a follow-up discussion on patch 2/13 in Jeff King's series removing non-standard object type support, focusing on the `--allow-unknown-type` option deprecation path.

The email addresses Patrick Steinhardt's review feedback about whether to add tests verifying the now-no-op `--allow-unknown-type` option is still accepted, and whether to document its deprecation more explicitly. Jeff considers both suggestions but leans toward minimalism - he notes the code change makes the option's no-op status obvious, and questions the value of adding explicit deprecation documentation when the release notes could cover this.

Jeff proposes an alternative implementation using `OPT_NOOP_NOARG` that would make the no-op nature completely unambiguous in the code while still keeping the option available for backward compatibility. He also notes this could be paired with a deprecation warning in the future if desired. The discussion remains open-ended, with Jeff acknowledging Patrick's points but expressing preference for keeping the documentation changes minimal unless there's clear value.

This exchange represents the last remaining open question in the otherwise technically complete series, with both reviewers and maintainer having approved the core approach. The decision point is whether to add explicit deprecation signaling (tests/docs) for this historical option or rely on the code changes and release notes to communicate the change.
