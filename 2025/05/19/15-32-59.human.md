This is the final patch in Jeff King's series removing support for non-standard object types in Git's core. The patch eliminates `write_object_file_literally()` and its helper functions, which were previously used to create objects with unknown types via `hash-object --literally`. With that functionality now removed in earlier patches, these functions are unused and can be safely deleted.

The removal cleans up a parallel implementation of `write_object_file()` that had grown increasingly divergent over time, particularly with tricky code around loose object map updates. As Junio notes in his response, the original testing use case for creating broken loose objects has been reimplemented in the test suite using new shell script helpers introduced earlier in the series.

This marks the completion of the technical work to remove non-standard type support from Git's object handling code. The change is uncontroversial, with Junio explicitly approving it as a safe and welcome cleanup. The series appears ready to merge once any remaining documentation questions from patch 2/13 are resolved.
