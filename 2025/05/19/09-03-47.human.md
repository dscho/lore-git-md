This is a follow-up discussion in the bundle-uri parsing thread, focusing on numeric input handling and Windows compatibility. Phillip Wood responds to Jeff King's comments about 64-bit value parsing, noting that most existing config values use `unsigned long` rather than needing full 64-bit support. 

The exchange reveals two key points: First, there's agreement that `*scanf()` should generally be avoided, especially with `%s` placeholders due to security concerns (though numeric placeholders are less dangerous). Second, while Jeff suggests a future `repo_config_get_u64()` helper would be ideal, Phillip points out that the current bundle-uri case expects bare integers without multiplier suffixes, unlike other config values like `packSizeLimit`.

The discussion shows the project's careful approach to parsing - preferring strict validation of input formats and avoiding `scanf` in favor of buffer-first parsing patterns seen elsewhere in the codebase (like `builtin/gc.c`). While the immediate patch is about bundle-uri, the conversation is shaping broader conventions for numeric input handling across Git.
