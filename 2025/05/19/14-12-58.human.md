This is the 4th patch in a 5-part series enhancing the promisor-remote protocol with configurable validation. The series adds support for dynamic advertisement and verification of remote attributes like `partialCloneFilter` and `token` during clone/fetch operations.

This particular patch introduces client-side validation of these additional fields through a new `promisor.checkFields` config option. When set, the client will verify that any advertised fields match its local configuration before accepting a promisor remote. The validation ensures three conditions: the field must be configured locally, advertised by the server, and have matching values. The implementation handles both the filter and token fields, with case-sensitive value comparisons.

The patch includes thorough documentation explaining the validation rules and adds test coverage verifying the field matching behavior. This builds on the server-side field advertisement capability added in earlier patches, completing the bidirectional protocol extension. The changes maintain backward compatibility while providing stricter validation when desired.

The implementation looks solid, with careful attention to edge cases and clear documentation. As the 4th patch in a well-reviewed series, it appears ready for final consideration pending Junio Hamano's review. The only remaining patch in the series appears to be a documentation update.
