This is a refactoring patch in the v3 series enhancing promisor-remote protocol validation. It prepares for upcoming additions by restructuring how advertised remote fields are parsed and validated.

The patch introduces a new `parse_one_advertised_remote()` function that centralizes parsing of server-advertised promisor remote information into a `struct promisor_info`. This replaces the previous ad-hoc parsing scattered through `filter_promisor_remote()`. The refactored version properly handles URL decoding and field validation in one place, while maintaining the same warning messages for invalid input.

Key technical changes:
- Moves field parsing logic from `filter_promisor_remote()` to new `parse_one_advertised_remote()`
- Updates `should_accept_remote()` to take a `struct promisor_info` instead of separate name/url strings
- Maintains identical warning behavior for malformed input
- Preserves all existing functionality while making the code more maintainable
- Keeps the same memory management patterns (caller frees allocated `promisor_info`)

The changes support the series' goal of cleanly handling additional fields (filter and token) in subsequent patches. This intermediate refactoring step shows good attention to incremental development - separating mechanical restructuring from functional additions. The patch appears well-contained, touching only promisor-remote.c with straightforward changes that don't affect behavior.
