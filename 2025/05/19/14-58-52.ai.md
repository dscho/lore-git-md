This is patch 7/13 in Jeff King's series removing support for non-standard object types, focusing on code simplification through the removal of now-unneeded infrastructure.

The patch removes the `type_name` strbuf parameter from `oid_object_info()` and related functions, which previously allowed callers to get object types as raw strings rather than the standard `object_type` enum. The commit message notes this was theoretically useful for non-enumerated types, but since the series treats such types as errors and there are no remaining callers using this feature, the code can be simplified by removing it.

Junio Hamano approves the change, noting that with standardized type handling now in place, the code can simply pass around the enum and convert to strings when needed. The implementation removes the strbuf parameter from several object-file handling functions, deleting 12 lines while adding only 2, demonstrating the simplification benefit. This continues the series' trend of removing now-unnecessary code paths after establishing that non-standard object types won't be supported.

The change affects several core object-handling files (`object-file.c`, `object-store.c`, `packfile.c`) but is straightforward since it builds on earlier patches that already removed all practical uses of this functionality. This appears to be a clean, uncontroversial removal of dead code that was made possible by the series' earlier changes.
