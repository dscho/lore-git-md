This is a refactoring patch in the v3 series enhancing promisor-remote protocol validation. It responds to Patrick Steinhardt's feedback by replacing the generic string_list-based field storage in `struct promisor_info` with direct struct members for each known field (name, url, filter, token). 

The change simplifies field access by eliminating index-based lookups and string comparisons in favor of direct member access, while maintaining the same protocol behavior. The author notes this makes some code paths more straightforward (like `remote_nick_find()`) though generic field handling still requires case-sensitive/insensitive string comparisons in other places. 

This implementation choice reflects the series' decision to strictly limit supported fields rather than maintain open-ended field handling. The patch preserves all existing functionality while making the code more type-safe and slightly more efficient by avoiding dynamic field lookups. It's a direct response to Patrick's v2 review suggesting this structural improvement, though some of his broader concerns about future validation needs remain as open questions for potential protocol evolution.
