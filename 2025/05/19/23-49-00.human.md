Junio Hamano weighs in on the MPTCP discussion, reinforcing the concerns about compatibility while questioning the need for Git to explicitly support MPTCP at all. He cites RFC 6897's claim that MPTCP is designed to be backward compatible, suggesting that system-level MPTCP policies could handle optimization transparently without requiring application changes. 

The Git maintainer expresses skepticism about Git needing to be "MPTCP-aware," noting that as a relatively simple network application, Git may not benefit enough from the protocol's advanced features to justify the added complexity. His comments imply that the current implementation effort might be premature or unnecessary if MPTCP truly works transparently as advertised.

This intervention from the project lead suggests the discussion may need to pivot from implementation details to a more fundamental question: whether Git should explicitly support MPTCP at all, or instead rely on system-level configuration. The email doesn't reject the idea outright but challenges the proponents to better justify why Git needs this capability rather than letting the OS handle it.
