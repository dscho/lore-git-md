Performance optimization patch completing the batched reference updates series for `git-receive-pack`. This is the final patch in v3 of the series, building on the earlier infrastructure from commit 23fc8e4f61. The change replaces per-reference transactions with batched updates in receive-pack, yielding an 18x speedup for reftable backends and 1.21x for files backends when handling 10,000 refs.

Key technical changes include:
- Introduces `ref_transaction_rejection_handler` using `struct strset` to track failed refs after batched commit
- Moves error handling to post-commit while maintaining accurate error attribution
- Fixes misleading status messages from duplicate ref updates (now treated as errors)
- Changes hook behavior to all-or-nothing for batched transactions
- Updates tests in t1416 (hook behavior) and t5408 (duplicate ref handling)
- Uses the finalized `ref_transaction_error_msg()` helper from earlier patches

The patch also fixes a subtle bug where multiple updates to the same ref (e.g. `A:foo B:foo`) would produce confusing output and partial updates. The batched approach properly rejects such cases entirely. Test changes reflect this corrected behavior.

Jeff King and Patrick Steinhardt provided key reviews, with all major technical concerns addressed in previous iterations. The series appears ready for integration with no outstanding objections from reviewers. Performance improvements are substantial, especially for reftable users, while maintaining backward compatibility.
