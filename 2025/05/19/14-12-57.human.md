This is part 3 of a 5-patch series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now in its third iteration with all major design decisions settled.

This patch refactors the code that parses advertised fields from promisor remotes. It introduces a new `parse_one_advertised_remote()` function that populates a `struct promisor_info` with parsed name and URL fields, replacing the previous direct parsing approach. The refactoring also modifies `should_accept_remote()` to take the full `promisor_info` struct rather than individual name/url parameters.

The changes are preparatory work for upcoming patches that will add support for parsing additional fields (filter and token) from server advertisements. The code is well-structured and maintains existing functionality while making the codebase more maintainable for future extensions. The patch follows the series' established pattern of careful protocol handling and maintains backward compatibility.
