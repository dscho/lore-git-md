This is the second patch in a 5-patch series enhancing the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now at v3 with all major design decisions settled through extensive review.

The patch introduces server-side support for advertising additional remote attributes (currently just `partialCloneFilter` and `token`) via a new `promisor.sendFields` config option. When set, the server will include these fields in its promisor-remote capability advertisement if they are configured for the remote. The implementation carefully handles URL encoding and maintains backward compatibility.

Key technical aspects:
- Defines allowed fields in a static array
- Adds comprehensive documentation of the field format and rules
- Includes tests verifying field transmission and encoding
- Maintains the existing protocol requirement that unknown fields must be ignored

The patch builds on the structural changes from patch 1/5 and sets up for client-side validation that will come in later patches. It's a well-constructed piece of work with thorough documentation and testing, addressing all feedback from previous rounds. The only remaining step is Junio's final review before potential inclusion.
