This is the 4th patch in a 5-part v3 series enhancing the promisor-remote protocol with configurable field validation. The patch introduces client-side verification of advertised remote attributes (partialCloneFilter and token) through a new `promisor.checkFields` config option.

The implementation adds:
- Configuration parsing for `promisor.checkFields` (comma/space separated list of fields to verify)
- Core validation logic in `all_fields_match()` that checks three conditions for each field: local config must be set, server must advertise the field, and values must match exactly
- Integration with existing remote acceptance logic in `should_accept_remote()`
- Comprehensive documentation of the new config option and its validation rules
- Test cases verifying field matching behavior and rejection scenarios

Key technical details:
- Field names are case-insensitive in config but values are compared exactly
- Validation occurs after basic name/URL checks from `promisor.acceptFromServer`
- The `match_field_against_config()` helper handles individual field comparisons
- Tests demonstrate proper transmission and validation of filter and token fields
- Maintains backward compatibility when new fields are not configured for checking

This completes the client-side counterpart to the server-side field advertisement added earlier in the series, providing a mechanism for clients to enforce consistency in partial clone filters and authentication tokens. The implementation follows the protocol constraints established in previous patches regarding field handling and unknown field behavior.
