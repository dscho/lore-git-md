This is part of Jeff King's completed series removing support for non-standard object types in Git's core. Patch 6/13 simplifies fsck's handling of unknown object types by moving error reporting to read_loose_object() rather than using the type_name strbuf.

The discussion here clarifies a minor implementation detail about error message formatting. When encountering an unknown object type, the patch now shows the full malformed header (e.g. "bogus 4") rather than just the type name ("bogus"). Jeff explains this is simpler to implement and potentially more informative, though either approach would work. The key point is that the change makes the code cleaner by removing the type_name strbuf handling while maintaining equivalent error detection.

This patch was already technically approved as part of the series, with the current exchange just providing additional implementation rationale. The series as a whole is now complete and awaiting merge pending only minor documentation decisions on earlier patches.
