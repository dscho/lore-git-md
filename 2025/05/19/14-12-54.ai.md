This is a completed 5-patch v3 series enhancing the promisor-remote protocol with configurable validation of remote attributes (partialCloneFilter and token) during clone/fetch operations. The series builds on the thread's established context where all major design decisions have been settled through previous rounds of review.

The key technical changes in this version include:

1. Replacing the string_list with direct struct members in promisor_info for better type safety and clarity. The struct now explicitly contains name, url, filter, and token fields rather than using a generic key-value store.

2. Adding comprehensive documentation in config/promisor.adoc and protocol-v2.adoc that clearly spells out:
   - Required field ordering (name and url must come first)
   - Case sensitivity rules (case-insensitive field names, case-sensitive values)
   - Strict handling of unknown fields (clients MUST ignore them)
   - Purpose of each supported field (filter for clone specs, token for auth)

3. Implementing server-side field advertisement via promisor.sendFields config and client-side validation via promisor.checkFields config. The validation performs exact matching of field values between server-advertised and client-configured remotes.

4. Adding test coverage in t5710 that verifies:
   - Field transmission in protocol messages
   - Client acceptance/rejection based on field matching
   - Proper handling of unknown fields
   - URL encoding behavior

The series has undergone significant refinement from v2 based on feedback, particularly around implementation structure and documentation clarity. All open questions from previous rounds appear resolved, with the only remaining loose end being Junio's final review. The changes align well with Git's protocol evolution philosophy while maintaining backward compatibility.
