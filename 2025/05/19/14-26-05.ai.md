This is patch 6/13 in Jeff King's series removing non-standard object type support from Git's core. The patch simplifies fsck's handling of unknown object types by moving error reporting from fsck.c to read_loose_object() and eliminating the type_name strbuf infrastructure.

The key technical change is that fsck now bails immediately when encountering an unknown type in read_loose_object(), rather than continuing to process the object. This results in two visible effects: error messages become slightly more verbose (showing both the unparseable header and the corruption error), and hash checks are skipped for unknown types since they're already unusable. The patch updates fsck tests to match the new behavior and removes a now-irrelevant test case.

Junio Hamano reviews the changes positively, noting the error message format change is acceptable and the overall approach is sound. He specifically confirms that the difference between showing 'bogus' vs 'bogus 4' in error messages isn't significant, and agrees with the rationale for skipping hash checks on unknown types. The patch appears technically complete and ready for inclusion in the series.

This continues the series' trend of simplifying object handling code by removing special cases for non-standard types, with maintainer approval indicating the approach is on the right track. The changes here are focused on internal error handling paths and test updates, with no expected impact on normal Git operations.
