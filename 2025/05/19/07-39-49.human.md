This is a test patch in the ongoing series about detecting memory leaks when loading corrupt bitmap indexes. Jeff King (peff) responds to the discussion about where to place the test infrastructure, suggesting a simpler approach using `dd` to corrupt the bitmap file directly in the shell test script rather than adding C code.

The key points are:
1. Jeff proposes marking the test with `!SANITIZE_LEAK` until the memory leaks are fixed, or better yet, stacking it after the leak fixes in a 3-patch series.
2. He prefers using shell commands (`dd`) to corrupt the bitmap file rather than C code, as it more accurately simulates real disk corruption and avoids test infrastructure code.
3. The suggested approach would modify the bitmap file at a calculated offset (based on hash algorithm size) to trigger the corruption case being tested.

This moves the discussion forward by offering a concrete alternative implementation that would simplify the test infrastructure while still achieving the same verification goals. The suggestion aligns with Git's preference for simple, shell-based tests when possible.
