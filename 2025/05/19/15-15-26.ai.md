This is patch 10/13 in Jeff King's series removing support for non-standard object types in Git. The patch focuses on `git hash-object`, removing its ability to create objects with non-standard types while retaining the `--literally` flag for other bypasses of format validation.

The key change is making `hash-object` reject non-standard types even when `--literally` is used, as evidenced by the new test case. The commit message notes this aligns with the series' goal of eliminating support for these experimental types while keeping `--literally` for its other validation-skipping purposes. Junio Hamano confirms this is the desired behavior with his "Yup" response to the test case.

The patch builds on earlier work to standardize type handling across Git's object code. It follows logically from patches that removed read-side support for non-standard types (like patch 6/13's fsck changes) and prepares for the final removal of write-side support in patch 13/13. The implementation appears straightforward - the test failure demonstrates the new restriction works as intended.

No new discussion points are raised here - this seems to be a clean application of the series' principles to `hash-object`. The maintainer's quick approval suggests this is uncontroversial and likely to proceed as-is. The only remaining open question in the series appears to be the documentation approach for the `cat-file --allow-unknown-type` deprecation from patch 2/13.
