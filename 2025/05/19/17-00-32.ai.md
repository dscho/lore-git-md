This is patch 6/13 in Jeff King's series removing support for non-standard object types, focusing on fsck's handling of unknown types. The patch moves error reporting for unknown types from fsck to read_loose_object(), simplifying the code by removing the type_name strbuf parameter from oid_object_info() and related functions.

The key technical change is that fsck now sees unknown types as corrupt/missing objects rather than getting a type name to report. This produces slightly different error output - instead of one line showing the unknown type, there are now two lines: one showing the raw header parse failure and another about the corrupt/missing object. 

Jeff explains the implementation details in response to Junio's question about the error message format. The new output includes the full malformed header (like "bogus 4") rather than just the type name, which provides more debugging context with minimal code changes. He notes this is safe because unpack_loose_header() guarantees proper NUL termination of the header buffer.

This patch is part of the broader simplification of Git's object handling by removing support for non-standard types that was only ever used for testing. The change is technically sound and has been approved by Junio, with the series now complete except for minor documentation questions on earlier parts.
