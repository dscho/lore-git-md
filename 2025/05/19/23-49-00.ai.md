Junio Hamano weighs in on the MPTCP discussion, reinforcing the compatibility concerns raised by Brian Carlson and Phillip Wood while questioning the need for Git-specific MPTCP awareness. He cites RFC 6897's backward compatibility guarantees, noting that MPTCP is designed to work transparently for applications. 

The key technical point is that MPTCP-capable systems should handle subflow management automatically without requiring application-level changes, making Git's socket-level modifications potentially unnecessary. Junio expresses skepticism about Git needing to explicitly enable MPTCP features, given its simple network requirements compared to applications that might need fine-grained control over subflows.

This moves the discussion beyond implementation details (Makefile knobs, error handling) to question the fundamental premise of the patch - whether Git should be MPTCP-aware at all when the protocol is designed for transparent operation. Junio's position suggests the feature might be better handled at the system/network level rather than in Git itself, though he stops short of outright rejecting the proposal. The RFC reference provides new technical grounding for the compatibility concerns while maintaining a neutral tone about MPTCP's value in principle.
