This is a discussion about implementation details for patch 2/13 in Jeff King's series removing support for non-standard object types. The patch makes `--allow-unknown-type` a no-op in `git cat-file` while retaining the option for backward compatibility.

Patrick Steinhardt raises two remaining questions about the patch's presentation: whether to explicitly test that the option is still accepted (even though it does nothing), and whether to document its deprecation status more clearly in the manpage. Jeff King is open to using `OPT_NOOP_NOARG` to make the no-op behavior unambiguous in the code, but is less convinced about adding explicit documentation, suggesting release notes may suffice.

The discussion reveals differing perspectives on how to handle deprecated features - Patrick leans toward explicit signaling to help future users understand legacy options, while Jeff prefers minimal documentation changes for what is effectively dead code. Both agree the technical implementation is sound, leaving these as minor presentation choices before the series can be merged.
