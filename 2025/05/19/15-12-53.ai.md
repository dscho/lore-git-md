This is a test infrastructure patch in Jeff King's series removing non-standard object type support. Junio Hamano reviews the new `lib-loose.sh` helper library introduced in patch 9/13, which provides low-level loose object creation for test scripts.

The helper function `loose_obj()` writes objects directly to the object database without going through `git hash-object`, taking an object type and content from stdin while outputting the resulting OID. Junio approves the implementation while noting some stylistic alternatives - the careful use of temporary files is appreciated though not strictly necessary for test code. The patch also updates `t1006-cat-file.sh` to use this new helper instead of `git hash-object --literally` for creating test objects with bogus types.

Key technical details include the helper's implementation which:
- Constructs raw object headers with type/size
- Uses `test-tool $test_hash_algo` for hashing
- Handles object storage path creation
- Leverages the new `test-tool zlib deflate` from patch 8/13
- Cleans up temporary files

This fits into the series' broader goal by providing test infrastructure that doesn't rely on the `--literally` flag being removed in later patches. The review confirms the technical approach while suggesting the `printf` format could use `%d` for size, though the current explicit whitespace handling is clearer. No outstanding issues remain for this patch.
