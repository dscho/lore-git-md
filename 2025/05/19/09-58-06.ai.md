This is a refactoring patch that's part of a series to improve ref transaction error handling. It moves error message generation for ref transaction errors from `builtin/update-ref.c` to a new public function `ref_transaction_error_msg()` in `refs.c`, making the functionality available to all ref transaction clients.

The patch takes the existing switch statement that maps `enum ref_transaction_error` values to human-readable strings and elevates it to a public API. The function handles all error types introduced in commit 76e760b999, including name conflicts, existence checks, value validation errors, and symref mismatches. The implementation in `update-ref.c` is updated to use this new shared function.

Key technical details:
- New public function `ref_transaction_error_msg()` added to refs.h
- Error strings remain identical to previous implementation
- Handles 6 specific error cases plus a default "unknown failure" case
- Part of ongoing work around ref transaction error handling (referencing prior commit 76e760b999)
- Maintains same behavior while making functionality more widely available

This appears to be a straightforward and well-contained refactoring with clear motivation (making error messages available to all ref transaction clients) and proper attribution (helped-by Junio C Hamano). The patch is part of a larger series (1/4) but stands on its own as a logical unit of work.
