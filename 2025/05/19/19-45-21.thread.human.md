This thread explores making `git reset --hard` less destructive by automatically preserving the pre-reset state, either via the stash or reflog. Josh Bleecher Snyder originally proposed the feature, with brian m. carlson and Junio C Hamano engaging in the technical discussion. There's consensus that the feature is valuable, but Junio has raised concerns about defaulting to the stash mechanism due to potential script breakage.

The latest email from brian m. carlson addresses these concerns, agreeing that using the regular stash stack by default is problematic. He suggests an alternative approach: using the same underlying stash machinery but storing the state in a separate ref to avoid interfering with users' existing stashes. The email also clarifies that while `reset --hard` does record HEAD changes in the reflog, it doesn't currently preserve the discarded local modifications—precisely the gap this feature aims to fill.

The discussion is now focused on implementation details, weighing modified stash machinery against potential reflog extensions. Junio's earlier input suggests the final solution will likely be configurable rather than changing defaults outright. The next steps involve deciding between these technical paths while ensuring the solution works reliably for both interactive use and scripts.
