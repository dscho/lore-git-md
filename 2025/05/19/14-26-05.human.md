This is patch 6/13 in Jeff King's series removing support for non-standard object types in Git. The patch simplifies fsck's handling of unknown object types by moving error reporting from fsck.c to read_loose_object() and eliminating the type_name strbuf infrastructure.

The key change makes fsck bail immediately when encountering an unknown type rather than proceeding to check the object hash. This produces slightly more verbose error messages (now showing the full broken header) but makes the code simpler. Junio Hamano reviews the patch and agrees with the approach, noting the error message format change is acceptable and the simplification is worthwhile.

The patch removes some now-unnecessary fsck tests since the behavior they were checking (hash verification of unknown types) is no longer performed. This is part of the broader effort to remove support for non-standard object types that were only ever used for testing Git's unknown type handling. The series has maintainer approval and appears ready to proceed.
