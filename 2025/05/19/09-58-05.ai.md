This is a performance optimization series (v3) introducing batched reference updates to `git-fetch` and `git-receive-pack`, building on the batched reference update support added in commit 23fc8e4f61. The series shows significant speedups, particularly for the reftable backend (22x faster fetches, 18x faster receive-pack operations).

The key technical changes in this version:
1. Modified `ref_transaction_error_msg()` to return string literals instead of allocated strings, simplifying memory management (addressing Junio Hamano's feedback)
2. Fixed memory leaks in send-pack when handling duplicate references
3. Added proper error handling for batched updates in receive-pack using a `ref_transaction_rejection_handler`
4. Cleaned up type casts and fixed typos from previous versions

The implementation touches core refs infrastructure (`refs.c`, `refs.h`) and modifies several commands (`fetch.c`, `receive-pack.c`, `send-pack.c`). Test coverage is updated in `t1416` and `t5408`. Performance improvements are most dramatic for reftable but still noticeable (1.25x) for the files backend.

All major technical concerns from previous reviews have been addressed:
- Memory management refined per Jeff King's suggestions
- Error reporting API finalized with string literals
- Static analysis warnings fixed
- Patrick Steinhardt validated the error handling model
- Junio Hamano approved core design decisions

The series appears ready for integration with all reviewers satisfied. Karthik suggests targeting Git 2.51 to allow additional baking time given the high-impact nature of these changes. The only remaining open items are non-blocking requests for future improvements (clearer batch/non-batch distinction and prepare-phase error handling).
