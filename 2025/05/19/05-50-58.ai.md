This is a policy discussion about maintaining niche contrib scripts, specifically the thunderbird-patch-inline tool. Collin Funk weighs in supporting Patrick Steinhardt's position that the script should be removed rather than updated, arguing that the functionality is simple enough to replicate manually and expressing skepticism about the longevity of the ExternalEditorRevived dependency.

The email reinforces Patrick's earlier argument that contrib scripts should have clear maintainers or demonstrated user demand, noting that the years-long broken state without complaints suggests minimal need. Collin provides a concrete example of how the script's core functionality (patching via Thunderbird) can be easily achieved with basic command-line tools, questioning the script's value proposition.

A key new point is the concern about dependency churn - Collin jokingly references a potential "ExternalEditorRevivedRevived" scenario, highlighting the maintenance burden of tracking third-party extension ecosystems. This aligns with Patrick's "dead weight" characterization but frames it in terms of future maintenance risk rather than just current usage patterns.

The response doesn't address any technical aspects of Phillip Wood's v2 patch (which had resolved all code quality issues), instead focusing entirely on the policy question. It represents a second voice favoring removal on grounds of minimal demonstrated need and maintainability concerns, though like Patrick, leaves the door open if Phillip can assert personal usage.
