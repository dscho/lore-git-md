Performance optimization patch completing the batched reference updates series for `git-receive-pack`. This is the final patch in v3 of the series, building on the earlier work to use batched transactions for reference updates across Git commands.

The patch modifies `receive-pack` to use batched reference updates via a single transaction, providing significant performance improvements - 18x faster for reftable backends and 1.21x for files backends when handling 10,000 refs. The implementation introduces a `ref_transaction_rejection_handler` to track failed refs and properly attribute errors after the batch commit.

Notably, this change fixes a confusing edge case where multiple updates to the same ref would produce misleading status messages and partial updates. The batched approach properly rejects such invalid requests up front. The patch also adjusts the behavior of the `reference-transaction` hook to be all-or-nothing when used with batched updates, which required updates to test expectations.

The patch has been reviewed by Jeff King and Patrick Steinhardt, addressing all previous feedback in the thread. It represents the culmination of a well-executed performance optimization effort that maintains backward compatibility while significantly improving reference update efficiency, particularly for large repositories using reftable.
