Performance optimization patch modifying `git-fetch` to use batched reference updates. This is part 2 of a 4-part series introducing batched updates across several Git commands, now in its third revision.

The patch replaces `git-fetch`'s per-reference transaction model with batched updates, which can process multiple references in a single transaction while still allowing individual updates to fail. This provides significant performance improvements, especially for the reftable backend (22x faster with 10,000 refs) and a modest 1.25x speedup for the files backend.

Key changes include:
- Removing custom error codes in favor of the new transaction error types
- Adding a rejection handler to process failed updates after transaction commit
- Cleaning up now-unnecessary transaction management code
- Maintaining the same error reporting behavior despite the changed execution order

The implementation appears solid, building on the batched update infrastructure introduced in an earlier commit (23fc8e4f61). The patch includes clear benchmark data showing the performance benefits and maintains backward compatibility with both atomic and non-atomic fetch modes. This is a well-motivated change that has undergone thorough review in previous iterations of the series.
