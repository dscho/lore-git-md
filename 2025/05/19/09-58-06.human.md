This is a refactoring patch that's part of a larger series (1/4) about updating git-fetch to use partial transactions. The patch moves error message handling for ref transactions from being a local implementation in `builtin/update-ref.c` to a shared function in `refs.c`.

The change makes sense architecturally - it centralizes the error message strings that correspond to the `ref_transaction_error` enum values that were recently introduced. This provides a consistent way for all parts of Git to get human-readable error messages for ref transaction failures, rather than having each caller implement their own mapping.

The implementation looks straightforward - it extracts the existing switch statement from update-ref.c verbatim into a new `ref_transaction_error_msg()` function in refs.c, adds the appropriate header declaration, and updates update-ref.c to use the new shared function. The patch is cleanly split between the three files it touches.

Since this is part of a series, readers may want to look at the cover letter (if available) to understand the broader context of the partial transaction work. But this particular patch stands well on its own as a simple code organization improvement.
