This is a performance optimization series that introduces batched reference updates to `git-fetch` and `git-receive-pack`, building on previous work to improve transaction handling in the refs subsystem. The series is now in its third version and appears ready for integration.

The key improvement comes from replacing individual reference transactions with batched updates, which is particularly beneficial for the reftable backend (showing 22x speedup for fetch and 18x for receive-pack) while also providing modest gains for the files backend (1.25x and 1.21x respectively). The series maintains partial update semantics while eliminating the overhead of per-reference transaction setup/teardown.

Version 3 incorporates several refinements based on reviewer feedback, most notably changing the error message helper to use string literals instead of allocated strings, simplifying memory management. The series also fixes memory leaks around duplicate reference handling in `send-pack` and improves error reporting in `receive-pack`.

Karthik Nayak suggests targeting this for Git 2.51 to allow additional baking time in 'next', given the high-impact nature of these changes. The series has received thorough review from core contributors including Jeff King, Junio Hamano, and Patrick Steinhardt, with all major technical concerns addressed. The implementation touches core refs functionality across multiple commands while maintaining backward compatibility.
