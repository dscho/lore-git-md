This thread presents a 4-part series refactoring Git's hash algorithm infrastructure to improve type safety and maintainability. The work converts the hash context from a union to a proper structure and introduces generic wrapper functions, building on master (3b0d05c) and incorporating tb/unsafe-hashtcleanup changes.

The first two patches restructured the hash context implementation, first converting `git_hash_ctx` from a typedef'd union to a structure with a nested union, then removing the typedef entirely. The third patch added algorithm tracking and introduced inline wrapper functions (`git_hash_update`, `git_hash_final`, etc.) that delegate via the new `algop` field while preventing algorithm mixing.

The newly received final patch completes the series by updating all callers across 19 files to use the new wrappers instead of directly accessing `the_hash_algo` function pointers. This mechanical change affects core hashing operations throughout Git (object-file.c, diff machinery, pack operations) while maintaining identical behavior. The changes enforce type safety and reduce direct dependencies on the global `the_hash_algo`, achieving the series' goal of making hash algorithm usage more explicit without impacting performance.

With all four patches now submitted, the series appears ready for maintainer consideration. The changes represent internal plumbing improvements with no user-facing impact, but significantly modernize how Git handles hash algorithm operations throughout the codebase.
