This is a follow-up discussion on the final patch in Patrick Steinhardt's series fixing repository reinitialization issues with different formats. The patch (3/3) addresses the same problem for `GIT_DEFAULT_HASH` that the previous patch fixed for `GIT_DEFAULT_REF_FORMAT` - preventing environment variables from overriding existing repository configurations during reinitialization.

Junio agrees with the conservative approach of preserving the existing object hash format (SHA-1/SHA-256) rather than allowing environment overrides, noting this prevents repository corruption. He observes that while the same "silent ignore" behavior applies here as in the ref format case, automatic conversion of object hashes would be significantly more expensive than ref formats. This implies the current solution is particularly appropriate for the hash case, though he doesn't explicitly suggest adding a warning like he did for the ref format patch.

The discussion confirms consensus on this final piece of the series, which completes the protection against incompatible reinitialization for both ref formats and object hashes in `setup.c`. The solution maintains safety in CI workflows where cached repositories might otherwise be corrupted by environment variable overrides.
