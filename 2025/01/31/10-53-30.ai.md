This is the sixth patch in an 8-part series addressing atomic push exit code propagation, introducing a new error code to handle ref status failures consistently across transport protocols.

The patch adds ERROR_SEND_PACK_BAD_REF_STATUS (value 1) to distinguish ref status errors from other failures in send-pack operations. The core issue being addressed is that git-transport-push for the Git protocol (smart HTTP) was returning -1 for bad ref statuses while the HTTP protocol handler returned 0, creating inconsistent behavior. The solution maintains the HTTP protocol's behavior by having git-transport-push ignore ERROR_SEND_PACK_BAD_REF_STATUS while still allowing send-pack to report ref status failures when called directly (e.g. from builtin/send-pack.c).

Key changes include:
1. Modifying send-pack.c to use the new error code instead of -1 for ref status failures
2. Adding documentation in send-pack.h explaining the error code and improving the send_pack() function's docstring
3. Updating transport.c to explicitly handle ERROR_SEND_PACK_BAD_REF_STATUS by converting it to 0 to match HTTP protocol behavior

The patch maintains the series' focus on atomic push reliability while addressing protocol consistency. It builds on the extensive test infrastructure updates from earlier patches in the series, particularly the porcelain output verification in t5548. The changes are well-contained to transport.c and send-pack.{c,h}, with careful attention to maintaining backward compatibility while fixing the inconsistency.
