CI/build system fix for GitLab CI whitespace and style checks.

Justin Tobler addresses an edge case in GitLab CI where the check-whitespace and check-style jobs could fail when certain environment variables are null rather than unset. The patch modifies the shell parameter expansion syntax in `.gitlab-ci.yml` to properly handle null values by using `:-` instead of `-` for variable substitution.

The issue stems from two related commits from July 2024 that added fallback behavior for determining the base commit in these CI jobs. While the original implementation worked when variables were unset, it would incorrectly select an empty value when variables were null, causing the jobs to fail. The fix is straightforward - a two-character change in each job's script section - and comes with successful CI run links demonstrating the corrected behavior.

This appears to be a well-motivated and narrowly scoped fix for a real-world CI pipeline issue. The commit message clearly explains both the problem and solution, and the change follows the established pattern used elsewhere in Git's CI configuration.
