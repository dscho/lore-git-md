This is a bugfix series addressing an edge case in atomic push behavior where Git fails to properly report errors from `git-receive-pack` on the remote side. The patches come from both Jiang Xin and Patrick Steinhardt, with Patrick adopting and refining Jiang's earlier work.

The core issue occurs when an atomic push partially succeeds (ref updates work) but `git-receive-pack` exits with a non-zero status - currently Git silently treats this as success. The series fixes this by:
1. Adding proper error handling that respects the exit code
2. Introducing a specific error code (`ERROR_SEND_PACK_BAD_REF_STATUS`) for ref status failures
3. Ensuring graceful connection closure during atomic push failures
4. Adding extensive test coverage, including porcelain output verification

The series has gone through 4 iterations with improvements to test organization, Windows compatibility, and documentation. The changes look well-considered, with careful attention to maintaining backward compatibility while fixing the edge case. The test coverage is particularly thorough, including new cases for dry-run mode and porcelain output.

This addresses a real-world issue encountered at GitLab and provides a robust solution that maintains atomic push semantics while properly reporting failures. The patch quality appears high, with clear commit messages and careful handling of edge cases.
