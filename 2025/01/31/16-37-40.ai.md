Junio Hamano's response in the ongoing os-version capability discussion reinforces his position that OS version information should be merged with the existing agent string rather than being a separate capability. This is a protocol design debate in a technically complete feature series.

Hamano argues strongly against parsing the agent string to extract OS information, stating it should be treated as an opaque string for statistical purposes only. He provides concrete examples showing how different agent strings (Linux git/2.48.0, macOS libgit2/1.9.0, Windows git/2.47.1) should not be parsed to infer feature availability, but could be used for aggregate statistics about client distributions.

The email counters Christian Couder's concerns about parsing difficulties by asserting that the inherent variability in agent strings (including custom GIT_USER_AGENT values and the ability to hide OS information) is actually a privacy feature, not a bug. Hamano emphasizes that the documentation's use of "typically" for the package/version format intentionally leaves the string flexible and unparseable.

This response doesn't introduce new technical arguments but solidifies the philosophical stance that protocol simplicity and privacy protection should take precedence over making the data easily parseable for statistical purposes. The thread remains at an impasse between Hamano's protocol-minimalism view and Couder's parsing-practicality concerns, with the implementation itself not in question.
