Final patch in the atomic push exit code propagation series, implementing the core fix for graceful connection closure on atomic push failures. This addresses the root cause where git-receive-pack errors weren't properly reported back to the pusher due to missing flush packets during early termination of atomic pushes.

The patch makes two key changes: First, it adds a `packet_flush(out)` call in send-pack.c when atomic push fails, ensuring git-receive-pack properly terminates. Second, it simplifies transport.c by removing special-case handling for atomic pushes during connection cleanup, now always calling `finish_connect()`. The test cases from patch 7/8 are upgraded from `test_expect_failure` to `test_expect_success`, verifying the fix works for both regular and porcelain output formats.

The solution maintains backward compatibility while fixing the silent failure case that originated from commit 7dcbeaa0df.
