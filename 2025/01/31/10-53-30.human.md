This is the sixth patch in an 8-part series fixing atomic push exit code propagation, now introducing the core protocol change after test infrastructure updates. The patch addresses an inconsistency between how different transport protocols handle rejected ref statuses during push operations.

Currently, the smart protocol (used by `git_transport_push`) treats rejected refs as a hard error (-1 return), while the HTTP protocol silently ignores them (returning 0). The patch introduces a new error code `ERROR_SEND_PACK_BAD_REF_STATUS` (value 1) to distinguish ref status failures from other errors. The smart protocol handler in transport.c is modified to ignore this specific error code, bringing its behavior in line with HTTP while still allowing other callers (like `builtin/send-pack.c`) to detect ref rejections.

The change maintains atomic push semantics while fixing the silent failure case - when ref updates succeed but receive-pack fails with a non-zero exit, the client will now properly detect this. The patch includes thorough documentation of the new error code and updates the `send_pack()` function's docstring to clarify its return values. This appears to be a well-considered change that completes the test infrastructure work from earlier patches in the series.
