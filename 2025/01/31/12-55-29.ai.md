Refactoring patch in a hash algorithm infrastructure series.

This is the second patch in a 4-part series to improve Git's hash algorithm plumbing. Following the first patch's conversion of `git_hash_ctx` from a union to a struct-with-union, this change removes the `typedef` for `git_hash_ctx` entirely, making it a direct `struct git_hash_ctx` throughout the codebase. The patch updates all 22 affected files to use the explicit struct syntax, touching core areas like object-file handling, diff machinery, and pack operations.

The change aligns with Git's general preference against typedefs for structs, as noted in the commit message. While purely mechanical (73 insertions, 74 deletions), it affects widespread hash-related code paths. The patch maintains all existing behavior, just changing the type syntax. Subsequent patches will build on this to introduce generic hash wrappers.

Key technical details for future reference:
- Updates function pointer typedefs in hash.h (`git_hash_init_fn` etc) to use `struct git_hash_ctx*`
- Touches hash algorithm implementations in object-file.c (SHA1/SHA256 init/update/final functions)
- Affects hash contexts in pack operations, bulk-checkin, diff patch IDs, and HTTP HMAC code
- Preserves all existing hash state handling through the now-explicit struct access
