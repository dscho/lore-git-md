This is a feature patch series introducing a new `--revision` option to `git clone`. The series consists of 6 patches, with the first 5 being preparatory refactoring commits to improve the code structure of `builtin/clone.c` before adding the new functionality.

The main feature allows cloning a single specific revision (either a ref or raw commit hash) without creating any remote-tracking branches or local branches, detaching HEAD at the requested revision. This is particularly useful for CI systems that need minimal clones of specific versions. The implementation ensures compatibility with `--depth` for shallow clones and handles various edge cases (tags, raw hashes, bare repos).

Key technical details:
- New `--revision` option conflicts with `--branch` and `--mirror`
- Creates no tracking branches or fetch refspecs
- Works with both refs (branches/tags) and raw commit hashes
- Detaches HEAD for non-branch refs
- Includes comprehensive tests in new file `t5621-clone-revision.sh`
- Prep work includes reducing globals, refactoring `wanted_peer_refs()`, and introducing `struct clone_opts`

The series has gone through 4 revisions, with v4 adding significant preparatory refactoring to make the code more maintainable before introducing the new feature. The implementation appears thorough with good test coverage and clear documentation updates.
