Feature addition to `git clone`: new `--revision` option for minimal clones. This is the final patch in a 6-part series that has been through 4 iterations of refactoring to prepare the clone internals for this feature.

The new `--revision` option lets users clone a single specific ref or commit hash without creating remote-tracking branches or local branches, detaching HEAD at the requested revision. Unlike `--branch` (which only works with branches and tags), this works with any ref (like `refs/pull/123` from Git forges) or raw commit hashes. It's particularly useful for CI systems that need minimal clones containing just one revision's objects.

The implementation ensures `--revision` conflicts with `--branch` and `--mirror`, creates no tracking branches or fetch refspecs, and includes comprehensive tests covering various ref types and edge cases. The patch builds on significant preparatory refactoring done in earlier patches to clean up clone's internals.
