CI / build system fix addressing a GitLab CI edge case in the whitespace and style check jobs. The patch corrects how base commits are determined when running these checks in GitLab pipelines. 

The check-whitespace and check-style CI jobs need a base commit for comparison, which can come from either CI_MERGE_REQUEST_TARGET_BRANCH_SHA or (as fallback) CI_MERGE_REQUEST_DIFF_BASE_SHA. The current implementation uses shell parameter expansion that fails to properly handle null values - it would accept an empty first variable rather than falling back to the second one when the first is null. This causes CI failures when the variables exist but are null.

The fix changes the parameter expansion syntax from `${var-default}` to `${var:-default}` which properly handles both unset and null cases. The change is made in two places in .gitlab-ci.yml - once for each of the affected jobs. The commit includes links to successful CI runs demonstrating the fix works.
