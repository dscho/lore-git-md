This is a response in the ongoing discussion about warning users when credentials will be stored unencrypted via git-credential-store. Junio C Hamano raises several technical considerations about the current RFC implementation:

1. **Helper detection concerns**: Notes the current check for "store" as first helper may be insufficient since (a) insecure helpers could appear later in a cascading configuration, (b) the store helper might be installed in non-standard locations with absolute paths, and (c) third-party helpers could have "store" as a substring in their names (like "store-securely").

2. **Warning timing**: Agrees with the pre-password-entry warning placement as proposed, acknowledging the layering violation is necessary since post-storage warnings would be too late to prevent insecure storage.

3. **Message delivery mechanism**: Suggests considering the advice mechanism instead of warning() to allow users who intentionally use credential-store to suppress repeated notifications, while still informing new/unaware users.

The response maintains the security focus of the original RFC while identifying practical implementation challenges around helper detection that would need resolution before finalizing the patch. No strong objections to the fundamental approach, but proposes refinements to both the technical implementation and user experience aspects. The thread continues to explore how best to balance security warnings with usability for legitimate use of credential-store.
