This thread addresses a subtle bug in GitLab's CI infrastructure for Git's whitespace and style check jobs. The issue stemmed from how shell parameter expansion handled null values in the CI_MERGE_REQUEST_* environment variables used to determine base commits. Justin Tobler identified that the existing `${var-default}` syntax failed when variables were null (as opposed to unset), causing CI failures. His fix changed this to `${var:-default}` syntax in two places in .gitlab-ci.yml to properly handle both cases.

Toon Claes, reviewing the fix, confirmed its correctness by referencing the Bash manual's distinction between unset and null variables. He approved the change, noting it cleanly resolves the edge case where variables might be set but null. The patch is minimal (just adding colons to the parameter expansion) but important for reliable CI operation, with Justin having already shown successful test runs demonstrating the fix works.
