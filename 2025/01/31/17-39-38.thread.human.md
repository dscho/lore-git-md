This thread addresses a CI build system fix for GitLab pipelines, specifically targeting the whitespace and style check jobs. The issue stems from how base commits are determined for comparison in these checks. Currently, the implementation fails to properly handle null values in the CI environment variables (CI_MERGE_REQUEST_TARGET_BRANCH_SHA and CI_MERGE_REQUEST_DIFF_BASE_SHA), causing CI failures when these variables exist but are empty.

The proposed solution changes the shell parameter expansion syntax from `${var-default}` to `${var:-default}` in two places in .gitlab-ci.yml. This small but important tweak ensures proper fallback behavior when variables are null, not just when they're unset. The patch includes successful CI run links demonstrating the fix works as intended. The change is minimal (adding just two colons) and well-justified, with the commit message providing clear context about the problem and referencing prior related commits. This appears to be a straightforward, targeted fix for a specific edge case.
