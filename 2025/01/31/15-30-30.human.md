This is a preparatory refactoring patch in a series introducing a new `--revision` option for `git clone`. The change inverts the internal handling of tag cloning from a `--no-tags` flag to a positive `--tags` flag (which remains enabled by default). 

The patch makes no functional change - `--tags` is simply added as a no-op option that maintains the current default behavior, while `--no-tags` continues to work as before. The documentation is updated to clarify that tags are cloned by default and `--tags` doesn't change this. 

This appears to be groundwork for later patches in the series that will introduce more sophisticated tag handling. The change is straightforward, touching only the flag variable, its documentation, and a few conditionals that check it. Since this is purely an internal refactoring with no behavior change, no new tests are added. The patch follows the series' theme of cleaning up `builtin/clone.c` in preparation for the new `--revision` feature.
