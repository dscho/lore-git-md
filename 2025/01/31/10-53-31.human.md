This is the 7/8 patch in a bugfix series addressing atomic push exit code propagation. The patch adds test coverage for an edge case where `git-receive-pack` fails after successfully updating refs during an atomic push, which currently gets incorrectly reported as success.

The new tests in t5543-atomic-push.sh verify two scenarios:
1. A basic case where the receive-pack wrapper exits with code 1 after ref updates
2. A porcelain output variant of the same failure case

Both tests are currently marked as `test_expect_failure` since the underlying bug hasn't been fixed yet - this appears to be preparatory work for the final patch in the series. The tests check that the error message and exit code properly reflect the receive-pack failure, even when ref updates technically succeeded.

This continues the series' pattern of thorough test coverage before implementation, building on earlier test modernization and refactoring. The test cases specifically target the porcelain output behavior that will be critical for validating the eventual fix.
