This is the third patch in a 4-part refactoring series improving Git's hash algorithm infrastructure. The patch introduces generic wrapper functions for hash operations that automatically use the correct algorithm based on the context's stored algorithm pointer, rather than requiring callers to track and specify the algorithm themselves.

The change adds a new `algop` field to `struct git_hash_ctx` that remembers which algorithm was used, then provides four new inline functions (`git_hash_clone`, `git_hash_update`, `git_hash_final`, and `git_hash_final_oid`) that use this stored algorithm pointer. This prevents potential mismatches where code might accidentally use the wrong algorithm's functions on a context, which could lead to crashes. The patch updates the initialization functions for SHA-1 (both safe and unsafe variants) and SHA-256 to set this new field.

The changes are internal plumbing improvements with no user-facing effects, but they make the code more robust by centralizing algorithm tracking in the hash context itself. The patch is part of a larger effort to clean up and future-proof Git's hash infrastructure, following earlier work to separate safe and unsafe hash variants. The next patch will update callers to use these new wrapper functions.
