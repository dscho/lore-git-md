This is the third patch in a 4-part refactoring series improving Git's hash algorithm infrastructure. The patch introduces generic wrapper functions for hash operations that automatically use the correct algorithm based on the context's stored algorithm pointer.

The key changes are:
1. Adds an `algop` field to `struct git_hash_ctx` to track which algorithm initialized the context
2. Introduces four new inline wrapper functions in hash.h (`git_hash_clone`, `git_hash_update`, `git_hash_final`, `git_hash_final_oid`) that delegate to the appropriate algorithm-specific functions via the stored `algop`
3. Updates the initialization and clone functions for SHA1, SHA1-unsafe, and SHA256 to set the `algop` field

The motivation is to prevent potential segfaults from mixing hash algorithms by making the need for callers to track algorithms explicit. The patch builds on previous work that eliminated mixing of safe/unsafe variants of the same algorithm. The wrappers maintain identical behavior while centralizing algorithm selection logic.

This is a plumbing change with no user-facing impact. The actual migration of callers to use these new wrappers will happen in the next patch (4/4). Reviewers should verify the indirection doesn't introduce performance overhead in critical paths like object-file.c operations. The changes are relatively straightforward but touch fundamental hashing infrastructure.
