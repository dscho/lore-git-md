This is a protocol design discussion in the ongoing thread about adding OS version capability to Git. Junio Hamano responds to Christian Couder's concerns about parsing OS information when combined with the existing agent string" capability.

Junio strongly advocates treating the combined agent+OS string as an opaque identifier, arguing this approach better aligns with Git's privacy philosophy. He emphasizes that any parsing of version numbers for feature detection would violate the intended use of this information, even if technically possible. The suggested use case is limited to offline statistical analysis (e.g., counting how many connections come from Windows vs Linux systems).

The response reinforces Junio's position that protocol simplicity trumps parsing convenience, noting that the existing agent string format is intentionally loose ("typically package/version" but not strictly required). He sees the configurable nature and potential for obfuscation (via GIT_USER_AGENT) as privacy features rather than problems.

This continues the core architectural debate in the thread - whether OS information should be a separate capability (Christian's preference for clean parsing) or merged with the agent string (Junio's preference for simplicity and privacy). The exchange highlights differing views on how strictly the protocol should constrain versus enable potential use cases.
