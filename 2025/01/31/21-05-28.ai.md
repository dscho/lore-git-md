This is a review comment on the final patch in a 6-patch series introducing a new `--revision` option for `git clone`. The series has undergone significant refactoring in previous patches to prepare for this feature.

Junio C. Hamano points out several technical concerns about the implementation details. First, he questions whether the string-based `--revision` option will be properly parsed into a commit later in the process. He then notes the style issue with a commented-out `// TODO` line (Git prefers `/* TODO */` style comments).

The main substantive feedback focuses on the handling of incompatible options. While the patch correctly marks `--revision` as incompatible with `--branch` and `--mirror`, Hamano questions why the code explicitly clears `option_branch` to 0 when `option_rev` is set, since the earlier check should have prevented them being used together. He notes this assignment triggers a Sparse warning due to type mismatch (assigning integer 0 to a char pointer), and wonders why similar clearing isn't done for other incompatible options like `option_mirror`.

The review doesn't challenge the overall approach but focuses on implementation cleanliness and consistency. It suggests the author (Toon Claes) should either justify the special handling of `option_branch` or make the clearing of incompatible options more uniform. The tone is technical and constructive, typical of Git's code review culture.
