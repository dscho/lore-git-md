This thread discusses a proposed security warning when users are about to store credentials unencrypted via `git-credential-store`. The original RFC patch suggests showing a warning before password entry when the first configured credential helper is "store", directing users to `gitcredentials(7)` for secure alternatives. The implementation modifies credential.c and includes test updates, though some tests currently fail.

Junio Hamano has now weighed in with technical feedback. While agreeing with the pre-password warning timing, he notes the current helper detection may be too simplistic - it could miss insecure helpers later in the chain, fail to recognize store helpers with absolute paths, or incorrectly flag third-party helpers containing "store" in their names. He also suggests using Git's advice mechanism rather than warnings to allow experienced users to suppress the messages. 

The discussion continues to balance security awareness with usability, with open questions around the precise detection logic and messaging approach. While there's consensus on warning users about credential-store's limitations, the implementation details need refinement to handle edge cases and configuration variations properly. The thread remains in RFC phase as these technical considerations are worked through.
