This thread explores how Git should handle the security implications of the `git-credential-store` helper, which stores credentials in plaintext. The original RFC patch proposed showing a warning when users enter credentials that will be stored unencrypted, triggered when "store" is the first credential helper. Junio Hamano provided initial technical feedback, noting limitations in helper detection and suggesting using Git's advice system instead of direct warnings.

The discussion has now deepened with Jeff King's (Peff) contribution, which questions whether warnings are the right approach at all. He argues that since credential-store is already opt-in and documented as insecure, more radical solutions might be appropriate—like renaming the helper to make its insecurity obvious ("git-credential-plaintext") or planning for its eventual deprecation. Peff raises additional technical concerns about the patch's implementation, particularly around reliably detecting insecure usage patterns.

The thread has shifted from discussing how to implement warnings to whether they're needed, with participants weighing security benefits against potential usability impacts. While there's consensus that plaintext credential storage is undesirable, opinions differ on how forcefully Git should intervene—from gentle warnings to eventual removal of the feature. The discussion remains technical and constructive, with Junio and Peff's feedback shaping the direction while keeping the original security motivation in focus.
