This thread began as an RFC proposing security warnings for users of `git-credential-store`, but has evolved into a deeper discussion about the helper's fundamental role in Git's ecosystem. The original patch suggested warning users before password entry when the first credential helper is "store", but maintainers have raised significant concerns about this approach.

Key participants Junio Hamano and Jeff King (Peff) now argue that since `git-credential-store` is already opt-in and clearly documented as insecure, additional warnings may be unnecessary friction - particularly in constrained corporate environments where it might be the only viable option (a point emphasized by Brian Carlson). The discussion has shifted from implementation details to broader design questions: whether the helper should exist at all, be deprecated, or remain as a documented last-resort option.

While all agree the credential-store poses security risks, maintainers are converging on the view that the current documentation may be sufficient warning for knowledgeable users who deliberately choose this helper. The thread shows no clear consensus yet on next steps, but the focus has moved away from warning mechanisms toward either accepting the status quo with clearer documentation or considering more radical changes like deprecation. This reflects Git's philosophy of trusting informed users while minimizing unnecessary friction, even when security tradeoffs are involved.
