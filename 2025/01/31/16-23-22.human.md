Junio Hamano responds to shejialuo's patch about checking sortedness in packed-refs files. This is part of the ongoing bugfix series introducing comprehensive validation for packed-refs.

The key clarification here is about when sortedness verification should occur. Junio insists it should only happen when the packed-refs file explicitly declares a "sorted" trait in its header, maintaining compatibility with Git's runtime behavior that doesn't require sorting for files without this trait. He points out that shejialuo's original patch description inaccurately suggested always checking sortedness, which would be stricter than necessary.

This exchange highlights an important design principle being maintained in the series: validation checks should match Git's actual behavior rather than impose new requirements. The discussion continues to refine the balance between safety checks and backward compatibility.
