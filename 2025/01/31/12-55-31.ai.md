Final patch in a refactoring series converting Git's hash algorithm infrastructure to use generic wrapper functions. This patch updates all callers across 19 files to use the new `git_hash_*` wrappers (`git_hash_update`, `git_hash_final`, `git_hash_final_oid`, `git_hash_clone`) instead of directly accessing hash algorithm function pointers through `the_hash_algo`.

Key technical changes:
- Replaces direct calls like `the_hash_algo->update_fn(&ctx, data, len)` with `git_hash_update(&ctx, data, len)`
- Maintains identical behavior while enforcing type safety through the wrapper functions
- Removes many direct dependencies on `the_hash_algo` global
- Touches core hashing operations in object-file.c, diff machinery, pack operations, bulk-checkin, HTTP HMAC, and test helpers
- The changes are mechanical replacements with no functional impact
- Completes the transition started in earlier patches to make hash algorithm usage more explicit and type-checked
- Follows through on the series' goal to simplify caller code while preventing algorithm mixing

The patch demonstrates thorough coverage of Git's codebase, updating all significant hash operation sites. As the final piece of the series, it achieves the architectural goal of decoupling callers from direct hash algorithm knowledge while maintaining performance (via inline wrappers) and correctness.
