Thread summary:

CI infrastructure fix addressing edge case in GitLab CI whitespace/style check jobs. The thread concerns a bug in how base commits are determined for these checks in GitLab pipelines, where the shell parameter expansion syntax fails to properly handle null values of CI_MERGE_REQUEST_TARGET_BRANCH_SHA/CI_MERGE_REQUEST_DIFF_BASE_SHA variables. The current implementation uses `${var-default}` which doesn't fall back when the first variable is null, causing CI failures. The fix changes this to `${var:-default}` syntax in two places in .gitlab-ci.yml to properly handle both unset and null cases. The commit demonstrates successful CI runs with the fix and provides context linking to prior related commits that introduced the current behavior. The change is minimal (adding two colons) and well-validated with clear evidence it resolves the issue.
