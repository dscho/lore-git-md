This is the final patch in a 4-part refactoring series that converts Git's algorithm-specific hash context handling to use generic wrapper functions. The series has been progressively restructuring the hash infrastructure to make it more explicit and type-safe.

This patch updates all remaining callers across 19 files to use the new wrapper functions (`git_hash_update`, `git_hash_final`, etc.) instead of directly accessing algorithm-specific function pointers. The changes are mechanical but widespread, touching core areas like object handling, diff machinery, pack operations, and HTTP authentication. 

The conversion eliminates direct uses of `the_hash_algo` in these callers, which was one of the series' goals. The patch maintains identical behavior while making the code more maintainable and less prone to algorithm-mixing errors. Since this is the culmination of work established in earlier patches, it carries forward the same careful approach with thorough file coverage.

The changes are straightforward replacements with no functional impact, though the diff is large due to the number of call sites. The patch appears well-executed, completing the series' goal of centralizing hash algorithm selection while preserving performance through inline wrappers.
