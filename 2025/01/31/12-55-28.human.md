Refactoring patch converting Git's hash context from a union to a structure. This is the first of a 4-part series to improve hash algorithm handling in Git's internals. The patch changes `git_hash_ctx` from being a direct union of SHA-1 and SHA-256 contexts to a structure containing that union as a member. 

The change is motivated by the need to later add hash algorithm tracking to the context - something that wasn't possible with the pure union approach. The conversion is straightforward, mostly involving adding a `state.` prefix to access the hash-specific contexts. The patch updates both the type definition in hash.h and all the hash function implementations in object-file.c.

While this is purely an implementation detail change with no user-facing impact, it's a foundational step for the series' goal of simplifying hash operations across Git's codebase. The changes appear carefully done with thorough updates to all affected functions. Reviewers will want to verify the mechanical nature of the changes and confirm no performance impact given how frequently these hash operations are used.
