This is the final patch in a 6-part series introducing a new `--revision` option to `git clone`. The feature allows cloning a single specific ref or commit hash without creating remote-tracking branches or local branches, detaching HEAD at the requested revision.

The patch implements the core functionality after the preparatory refactoring in previous patches. Key aspects:
- Accepts both ref names (like `refs/pull/123`) and raw commit hashes
- Detaches HEAD for all cases (unlike `--branch` which only detaches for tags)
- Creates no tracking branches or fetch refspecs
- Works with `--depth` for minimal clones (useful in CI)
- Incompatible with `--branch` and `--mirror`
- Includes comprehensive tests in new file `t5621-clone-revision.sh`

Implementation details:
- Adds `option_rev` and `detach` flag to `struct clone_opts`
- Modifies `update_head()` to handle detached HEAD case
- Skips branch/tracking setup when `--revision` is used
- Adds validation for incompatible options
- Handles both refspec and raw hash cases in transport setup

The tests verify:
- Cloning with branch/tag/HEAD refs and raw hashes
- Behavior with `--depth` and `--bare`
- Error cases (short hashes, trees, parent refs)
- Incompatibility with other options

This completes the series that began with major refactoring of `builtin/clone.c` to enable this feature. The implementation appears thorough with good test coverage for the new functionality.
