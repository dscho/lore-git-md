This thread presents a 4-part refactoring series by Patrick Steinhardt improving Git's hash algorithm infrastructure by converting the hash context from a union to a proper structure with algorithm-tracking wrappers. The work builds on master (3b0d05c) and incorporates tb/unsafe-hashtcleanup changes.

The series progresses through architectural changes to:
1. Convert `git_hash_ctx` from typedef'd union to structure containing union
2. Remove `git_hash_ctx` typedef in favor of explicit `struct git_hash_ctx`
3. Add algorithm-tracking via `algop` field and implement four inline wrapper functions
4. Update all callers across 19 files to use new wrappers instead of direct `the_hash_algo` access

Key technical details:
- Wrappers centralize algorithm selection while preserving performance (inline)
- Maintains compatibility with existing hash implementations (SHA1/SHA1-unsafe/SHA256)
- Touches core hashing operations in object-file.c, diff machinery, pack operations
- Removes many direct dependencies on `the_hash_algo` global
- Changes are mechanical with no functional impact

Maintainer Junio Hamano acknowledges the series appears sensible and notes it will need coordination with Karthik Nayak's parallel work on passing hash algorithm instances through pack-write.c's callchain. Hamano anticipates being able to resolve any textual conflicts between these efforts, suggesting architectural compatibility despite related areas being touched.

The series represents a significant internal plumbing improvement that:
- Makes hash algorithm usage explicit and type-checked
- Simplifies caller code while maintaining identical behavior
- Reduces direct global variable usage
- Preserves performance through inline wrappers
- Positions Git better for future hash algorithm evolution
