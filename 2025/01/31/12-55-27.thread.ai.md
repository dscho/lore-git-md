This thread presents a 4-part refactoring series improving Git's hash algorithm infrastructure by converting the hash context from a union to a proper structure and adding generic wrapper functions. The work builds on master (3b0d05c) and incorporates tb/unsafe-hashtcleanup changes.

The series progresses through these architectural changes:
1. Converted `git_hash_ctx` from typedef'd union to structure containing union (23+/-21 lines)
2. Removed `git_hash_ctx` typedef in favor of explicit `struct git_hash_ctx` (73+/-74 lines across 22 files)
3. Added algorithm-tracking via `algop` field and implemented four inline wrapper functions (`git_hash_clone`, `git_hash_update`, `git_hash_final`, `git_hash_final_oid`)
4. Updated all callers across 19 files to use the new wrappers instead of direct `the_hash_algo` access

Key technical details:
- Wrappers centralize algorithm selection while preserving performance (inline)
- Maintains compatibility with existing hash implementations (SHA1/SHA1-unsafe/SHA256)
- Touches core hashing operations in object-file.c, diff machinery, pack operations, bulk-checkin, HTTP HMAC
- Removes many direct dependencies on `the_hash_algo` global
- Changes are mechanical with no functional impact
- Achieves goal of making hash algorithm usage explicit and type-checked

The series represents a significant internal plumbing improvement that:
- Prevents algorithm mixing
- Simplifies caller code
- Maintains identical behavior
- Reduces direct global variable usage
- Preserves performance through inline wrappers

With the final patch applied, the transition to structured hash contexts with type-safe wrappers is complete. The changes affect fundamental hashing infrastructure but produce no user-facing behavior changes. The work positions Git better for future hash algorithm evolution while maintaining strict backwards compatibility.
