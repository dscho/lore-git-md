Refactoring patch in the `--revision` clone series, moving global state into a new struct.

This is patch 5/6 in v4 of a series introducing a new `--revision` option for `git clone`. The patch creates a new `struct clone_opts` to hold clone configuration, starting with a `wants_head` field that tracks whether the remote HEAD should be fetched. This replaces some ad-hoc logic around `option_single_branch` and `option_branch` with a more structured approach.

The change affects core clone behavior by:
1. Moving HEAD-fetching logic into the new struct
2. Modifying `wanted_peer_refs()` to use the struct
3. Exporting `tail_link_ref()` from remote.c since it's now needed by clone.c

The patch appears well-contained, with clean separation between the new infrastructure and existing behavior. It's part of a larger effort to clean up clone.c's many global variables in preparation for the `--revision` feature. The changes maintain all existing functionality while making the code more maintainable - a typical preparatory refactoring in a feature series.
