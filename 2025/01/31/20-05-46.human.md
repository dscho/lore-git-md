Junio C Hamano responds to the RFC patch proposing warnings for git-credential-store usage, offering several technical considerations for improving the implementation. This is part of the ongoing discussion about how to best warn users about insecure credential storage.

The response raises multiple implementation concerns: the current check only looks at the first credential helper, but users may have insecure helpers configured later in the chain. There are also edge cases around path resolution (absolute paths, unusual install locations) and potential false positives with third-party helpers that happen to start with "store" in their names. 

Hamano agrees with the fundamental approach of warning before password entry rather than after storage, acknowledging the security rationale. However, he suggests considering the advice mechanism instead of warnings, which would allow users who intentionally use the store backend to silence repeated notifications. 

The response doesn't reject the concept but provides concrete technical feedback that would need to be addressed in a revised version. The discussion continues to focus on finding the right balance between security warnings and user experience, particularly for those who knowingly accept the risks of credential-store.
