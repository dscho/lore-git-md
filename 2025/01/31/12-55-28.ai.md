Refactoring patch converting Git's hash context from a union to a structure.

This is the first of a 4-part series refactoring Git's hash algorithm infrastructure. The patch converts the `git_hash_ctx` from a typedef'd union into a structure containing a union, with all hash-specific states (SHA1, SHA1-unsafe, SHA256) moved into a nested `state` field. The change is motivated by the need to later extend the context to track the hash algorithm used, which isn't possible with the current union structure.

The mechanical changes update all hash function implementations in `object-file.c` to access the state through the new `state` member. The diff shows 23 lines added and 21 removed across `hash.h` and `object-file.c`, with straightforward updates to function calls like `git_SHA1_Update(&ctx->state.sha1)` instead of direct union access.

This foundational change enables the subsequent patches in the series to add algorithm tracking while maintaining type safety. The conversion touches core hashing operations but doesn't change behavior - all existing hash operations continue working as before, just with an additional level of indirection. Reviewers should verify the mechanical nature of the changes and confirm no performance impact from the added structure layer.
