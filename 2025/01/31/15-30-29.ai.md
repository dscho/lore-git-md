This is a refactoring patch that's part of a larger series introducing a new `--revision` option for `git clone`. As the first of six patches in its fourth iteration, it focuses on cleaning up `builtin/clone.c` by reducing global variables in preparation for the new feature.

The patch moves numerous global variables that were only used within `cmd_clone()` into local scope, including the entire `builtin_clone_options` array and its associated variables. This affects over 20 different configuration and option variables related to cloning behavior, from verbosity and progress reporting to submodule handling and shallow cloning options. The diff shows a significant reorganization - 195 lines changed with 101 insertions and 94 deletions - but the actual behavior remains identical.

Key technical details for future reference: the patch relocates variables like `option_reject_shallow`, `deepen`, various string options (`option_template`, `option_depth`), the `option_config` string list, transport-related settings, and the `server_options` list. It also fixes some minor issues like properly initializing variables and cleaning up string lists. The `builtin_clone_usage` array is also made local, though it was already effectively used only within `cmd_clone()`.

This groundwork appears well-executed, with careful attention to maintaining all existing functionality while improving code structure. The changes are purely internal - no user-facing behavior is modified. The patch follows the series' strategy of separating refactoring from feature addition, making the subsequent `--revision` implementation easier to review and maintain.
