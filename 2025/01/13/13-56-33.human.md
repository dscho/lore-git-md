Bug report for reftable migration in Git 2.48. Brian Carlson reports encountering a "corrupt reftable file" error when attempting to migrate a repository with multiple ref updates to the reftable format. The issue appears when performing ref updates across multiple transactions (where max_update_index increments beyond 1), causing a mismatch between header and trailer values in the reftable file.

The report includes a clear reproduction script that creates a test case with thousands of refs across two update blocks. The error only manifests when the second update block is present, suggesting the bug relates to how transaction indices are handled during migration. Carlson notes they've observed this in real-world repositories with thousands of refs, though they can't share those directly.

This appears to be a legitimate bug in the newly introduced reftable migration feature from Git 2.48. The report is well-documented with a minimal reproduction case and some initial analysis of the root cause (header/trailer index mismatch). While not yet investigated deeply, the problem seems credible given the detailed reproduction steps and the reporter's familiarity with Git internals.
