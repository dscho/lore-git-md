This is a follow-up discussion in the ongoing ref-filter memory management thread, focusing on edge cases in `git ls-remote` when using sorting atoms that require object access. Jeff King notes that while the current patch (either approach) would work for `ls-remote`, there are deeper issues with how sorting atoms interact with remote references.

Key technical points:
- The `ls-remote` command currently lacks a `ref_format` struct, which would need to be added under either solution
- Some sorting atoms (like `authordate`) fail gracefully when outside a repo, but others (like ahead-behind calculations) produce inconsistent results depending on local object availability
- Remote references may or may not have corresponding local objects, leading to potential sorting inconsistencies
- The discussion reveals a broader design question about which sorting atoms should be allowed for remote operations

The email doesn't propose a solution but highlights an orthogonal issue that would affect both proposed approaches to the memory management problem. It suggests the current error handling may be insufficient for some object-dependent sorting cases in `ls-remote`.
