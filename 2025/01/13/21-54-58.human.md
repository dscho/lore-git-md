Security documentation clarification for credential URL warnings. Brian Carlson responds to Junio Hamano's query about the scope of `transfer.credentialsInUrl` warnings, confirming the current implementation only flags passwords in URLs (not usernames alone) by examining the code. He agrees with the need for clearer documentation to help users understand exactly what triggers warnings, and promises to submit a documentation patch. This follows ongoing discussion about making the "warn" default more comprehensive by covering both `.URL` and `.pushURL` patterns, where consensus has formed around the security benefits while ensuring proper user guidance exists for disabling warnings when needed. The exchange shows the careful attention to detail typical of Git's security-related discussions, with multiple contributors vetting both implementation scope and user-facing communication.
