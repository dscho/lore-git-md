Bugfix for object name resolution with curly braces in branch names.

This patch fixes a regression where Git would fail to resolve object names containing curly braces in branch names (like `foo{bar:README.md`), introduced by cce91a2caef9 which assumed braces would only appear after `@` or `^` characters. The fix modifies the parsing logic in `object-name.c` to only treat braces specially when they immediately follow `@` or `^`, allowing other uses of braces in names to work normally.

The changes are well-tested with new cases in `t/t1006-cat-file.sh` covering:
- Basic curly brace resolution (`foo{bar:hello`)
- Edge cases with multiple `@` signs (`foo@@{0}:hello`)
- Commit text searches containing colons (`other^{/testing:}:hello`)

The implementation consciously avoids refactoring the broader brace-handling logic, as the commit message notes this would require coordinating changes across multiple functions (`get_oid_basic`, `interpret_nth_prior_checkout`, etc.). While not ideal architecturally, this targeted fix addresses the immediate issue while leaving room for future generalization if needed.

This appears to be a robust solution to a real-world problem reported by Gabriel Amaral, with clear test coverage for both the fixed behavior and related edge cases. The patch is part of a v3 series that has already incorporated review feedback, suggesting it's in good shape for inclusion.
