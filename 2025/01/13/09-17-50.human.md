Bugfix discussion for cruft pack expiration in `git gc`. 

Jeff King (Peff) responds to ZheNing Hu's patch that aims to fix an interaction between `--prune=now` and `--expire-to` in `git gc`. The core issue is that the current logic incorrectly disables the `-a` repack option when both `--expire-to` and `--cruft` are used together with `--prune=now`. 

Peff analyzes that the `--expire-to` option should only be considered when used with `--cruft`, as the manpage indicates. He references Taylor Blau's earlier work on expanding `--expire-to` usage during pruning, suggesting the current patch's logic is correct but might belong in the first patch of the series to avoid introducing a buggy intermediate state.

The discussion highlights some subtle interactions between garbage collection flags and suggests the patch author may want to coordinate with Taylor Blau about future directions for the `--expire-to` functionality. The technical focus remains on how `git gc` passes options to `git repack` when managing cruft pack expiration.
