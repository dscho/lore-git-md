This is a follow-up in the thread about `git fetch` tag behavior in shallow clones, confirming the regression's origin point. Danila Manturov reports their CI has identified commit 5f212684abb6 ("fetch: do not ask for HEAD unnecessarily", 2024-12-06) as the first commit where the bug occurs, where tags pointing to the shallow boundary commit stopped being fetched with `--depth=1`. This confirms the earlier suspicion about the regression's source, though Bence Ferdinandy had noted this was already addressed by commit 6c915c3f85 in the final 2.48 release. The email highlights that the issue specifically manifests when fetching without an explicit refspec, suggesting the regression may involve how default refspecs interact with shallow clone tag fetching. The thread shows progress in pinpointing the regression's origin, though it remains unclear whether the fix fully addresses the shallow clone edge case demonstrated in the original report.
