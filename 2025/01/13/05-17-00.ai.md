This is a discussion about refactoring the ref-filter code to better handle memory management and consistency between formatting and sorting operations. The thread has established that the current approach using separate string lists for committish references in formatting vs sorting leads to leaks and incorrect behavior depending on operation order.

Jeff King responds to René Scharfe's proposed solution (making the string lists static variables) with an alternative approach that would require callers to explicitly pass a ref_format struct to sorting operations. His patch modifies ref_sorting_options() to take a ref_format parameter and updates all callers accordingly. This maintains the connection between formatting and sorting while avoiding static variables, at the cost of slightly more boilerplate in calling code.

Key technical details:
- Changes affect multiple commands (branch, for-each-ref, tag, ls-remote)
- Introduces new parameter to ref_sorting_options() API
- Updates parse_sorting_atom() to use provided format struct
- Maintains same behavior but with explicit rather than implicit state
- Still resolves the original memory management issues

The discussion highlights a tension between immediate cleanup (Scharfe's simpler static variable approach) and longer-term lib-ification goals (King's more explicit context passing). King notes both solutions work but expresses mild preference for the more explicit approach as better aligning with future direction, while acknowledging the appeal of Scharfe's code deletion.
