Platform compatibility and security patch in Patrick Steinhardt's Meson build system transition series (7/9). This patch makes the cryptographically secure pseudo-random number generator (CSPRNG) backend configurable in the Meson build, matching functionality already present in the Makefile build system.

The changes introduce a new `csprng_backend` meson option with possible values: 'auto' (default), 'arc4random', 'arc4random_bsd', 'getrandom', 'getentropy', 'rtlgenrandom', 'openssl', and 'urandom'. The implementation systematically checks for each backend's availability when 'auto' is selected, falling back to /dev/urandom if no other options are available. The selected backend is now included in the build summary output alongside other configured backends.

The patch maintains the same detection logic as the Makefile version, supporting platform-specific implementations (arc4random on BSD, RtlGenRandom on Windows) and OpenSSL when available. It properly handles the dependency chain by adding CSPRNG to the list of features that might require OpenSSL. The error handling is explicit - the build will fail if an explicitly requested backend is unavailable.

This continues the series' pattern of methodically porting build system functionality to Meson while maintaining feature parity. The change is particularly relevant for security-conscious deployments that may need to enforce specific cryptographic implementations. The patch appears well-tested and follows the established patterns from earlier backend configuration work in the series.
