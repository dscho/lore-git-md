The discussion began with an RFC proposing to add Vim modelines to Git's AsciiDoc documentation files (starting with git-add.txt) to improve editor support, since these files are often mistaken for Markdown. The original proposal presented three options: adding modelines at file bottoms (implemented), moving them to tops, or renaming files with .adoc extensions.

Brian M. Carlson has now responded with substantive objections to the modeline approach. He argues against including editor-specific configuration in project files, drawing a comparison to how Git avoids editor-specific patterns in .gitignore. He questions the modelines' necessity, noting proficient Vim users can set filetypes manually. Instead, he advocates for the .adoc extension change as a more editor-agnostic solution, potentially combined with .editorconfig settings.

The thread now has two clear positions: the original proposal favoring modelines (with questions about placement), and Brian's counterproposal rejecting modelines in favor of file extension changes. The core questions remain open: whether to use modelines at all, and if not, whether to pursue the .adoc extension approach. No other participants have weighed in yet on these alternatives.
