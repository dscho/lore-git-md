Feature addition to `git gc` with a new `--expire-to` option for cruft pack management.

This patch from ZheNing Hu adds a `--expire-to` option to `git gc`, mirroring existing functionality in `git repack`. The option lets users specify a directory where unreachable objects (that would normally be pruned) are instead stored in cruft packs. This provides a way to keep a backup of pruned objects while still cleaning up the main repository.

The change is straightforward - it pipes the new option through to the underlying `git repack` call that `gc` makes. Documentation and tests are included, showing the patch follows Git's usual standards. The commit message clearly explains the change and its motivation (avoiding the need to run separate `repack` and `prune` commands).

This appears to be a well-considered quality-of-life improvement, though it's been waiting for review since December. The patch is part of a 2-part series, but this first part stands on its own as a complete feature addition.
