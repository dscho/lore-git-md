This is a follow-up in the ongoing discussion about `git fetch` tag behavior regression in shallow clones. Bence Ferdinandy acknowledges Danila Manturov's CI analysis confirming that commit 5f212684abb6 introduced the regression where tags pointing to shallow boundary commits weren't fetched with `--depth=1`. While a fix (6c915c3f85) exists in Git 2.48 that addressed similar HEAD request issues, Bence notes it's unclear why this fix doesn't resolve the specific edge case Danila demonstrated. The key open question remains why the existing solution doesn't cover this particular scenario where tags reference the boundary of a shallow clone. The discussion has moved from identifying the regression source to understanding the limitations of the current fix, suggesting this may require additional investigation or a separate solution for the boundary tag case.
