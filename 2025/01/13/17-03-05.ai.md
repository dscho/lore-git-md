Development environment setup for Git debugging.

Jon Forrest shares an alternative approach to debugging Git in VS Code that doesn't require CMake or Meson integration. On Fedora 41, they build Git from source using the standard Makefile approach, then use VS Code's native capabilities to debug the resulting binary by setting breakpoints directly in common-main.c. This method has worked for basic execution tracing, though they note limitations around process/thread handling and mention the debugged executable doesn't retain the 'git' name.

This represents a third viable path alongside the previously discussed CMake and Meson approaches, though it may have more limited functionality for complex debugging scenarios. The approach is currently working for the author's needs of basic execution tracing, but they're seeking feedback on potential gaps, particularly around multi-process/thread debugging. The executable naming issue appears to be a minor inconvenience rather than a functional blocker.

Key technical details:
- Works with standard Makefile build
- Uses VS Code's native debugger integration
- Breakpoints set starting from common-main.c
- Known limitations: process/thread handling, executable naming
- Platform: Fedora 41 Workstation

This adds to the growing set of options for Git development environments, providing a simpler alternative that may suffice for basic debugging needs while the more comprehensive Meson/CMake solutions are being refined. The thread remains open for others to share experiences with any of these approaches.
