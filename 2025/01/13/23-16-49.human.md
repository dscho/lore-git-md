This is a follow-up to a reported performance issue with `git bisect old` on large repositories like the Linux kernel. The original report showed the operation taking 21 minutes with CPU-bound behavior in the single-threaded bisect setup phase.

The reporter confirms the issue persists in Git 2.47.1, noting that the bisect implementation appears largely unchanged from the previously tested version (2.39.5). They've observed no meaningful performance improvement in newer releases and question whether further version testing would be productive, though they remain willing to conduct additional tests if requested.

This reinforces the core issue - the revision walking during bisect old/new operations remains a serial bottleneck even in current Git versions. The reporter's willingness to provide more data suggests they're engaged in helping diagnose and potentially improve this performance pain point for large repository workflows.
