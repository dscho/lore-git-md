Feature addition to `git gc` with cruft pack management.

This is the first patch in a 2-part series (though the second patch isn't shown here) that adds a new `--expire-to` option to `git gc`. The option mirrors existing `git repack --expire-to` functionality (added in commit 91badeb), allowing users to specify a directory where expired cruft packs should be stored during garbage collection. Currently, achieving this requires running `git repack` and `git prune` separately - this change streamlines the workflow by plumbing the option through `git gc`.

The implementation adds:
- Documentation for the `git-gc.txt` manpage
- A new `repack_expire_to` field in `gc_config`
- Plumbing to pass the option through to `git repack`
- A test case in t6500-gc.sh verifying the option is properly forwarded

The patch appears well-structured with clear documentation and test coverage. The commit message provides adequate context about the motivation (workflow simplification) and prior art (the existing repack option). The implementation is straightforward, just passing the parameter through to the underlying repack command. The thread context shows this has been waiting for review since December 2024, suggesting it may need a maintainer's attention to move forward.
