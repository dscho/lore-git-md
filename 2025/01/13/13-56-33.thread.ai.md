Bug report and resolution for reftable migration corruption in Git 2.48, involving header/trailer max_update_index mismatch during multi-batch operations. The issue affected repositories with many refs and reflog updates during format migration (`git refs migrate --ref-format=reftable`), where reflog handling caused header/trailer inconsistency. The thread has now concluded with final verification, merge approval, and confirmation that the fix will proceed to integration branches.

- Reftable writer initialization uses this max_index upfront before writing blocks
- Removed redundant max_update_index tracking in reflog writing path
- Added test case creating 5000 refs with 3000 updates to verify multi-batch handling
- Uses uint64_t for max_index to handle extremely large repositories
