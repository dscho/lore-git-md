Bug report and resolution for reftable migration corruption in Git 2.48, involving header/trailer max_update_index mismatch during multi-batch operations. Originally reported by Brian Carlson with technical analysis from Patrick Steinhardt, now addressed by Karthik Nayak with a solution that has received both maintainer and reporter feedback. The issue affects repositories with many refs and reflog updates during format migration (`git refs migrate --ref-format=reftable`), where reflog handling caused header/trailer inconsistency.

Technical resolution:
- Karthik Nayak's fix introduces transaction->max_index in ref_transaction to track highest update_index across all operations
- Reftable writer initialization uses this max_index upfront before writing blocks
- Removes redundant max_update_index tracking in reflog writing path
- Includes test case creating 5000 refs with 3000 updates to verify multi-batch handling
- Fix ensures consistent max_update_index between header and trailer regardless of batch count
- Brian Carlson suggests using uint64_t instead of unsigned int for max_index to future-proof against extremely large repositories
