Bug report regarding GPG key selection behavior when signing tags.

Carlos Maiolino follows up on a thread about Git seemingly bypassing the specified signing key. After further investigation prompted by Jeff King's questions, Carlos now agrees this appears to be a GPG issue rather than a Git problem. 

The key observations: When attempting to sign a tag with a specific subkey while the smartcard containing another key is disconnected, GPG still prompts for the smartcard passphrase and seems to ignore the explicitly specified key. The GIT_TRACE output confirms Git is correctly passing the requested key to GPG's command line, but GPG's behavior is unexpected - it first requests the smartcard passphrase, then considers a different key when that's cancelled, ultimately failing the operation.

This appears to be a case where GPG is overriding the key selection despite being given explicit instructions, though the exact GPG configuration causing this isn't clear yet. The thread has shifted from being a potential Git bug report to investigating GPG's key selection behavior when multiple keys are available. Carlos plans to investigate further on the GPG side.
