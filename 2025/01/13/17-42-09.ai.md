This is a follow-up discussion in Patrick Steinhardt's Meson build system transition series, specifically addressing patch that moved Git's version generation from GIT-VERSION-GEN to a separate GIT-VERSION file. Junio Hamano raises concerns about the approach, questioning whether modifying the established version generation system to accommodate Meson is justified.

The core disagreement centers on whether extracting the default version (DEF_VER) into a separate file is truly necessary versus simply having Meson grep for "^DEF_VER=" in the existing GIT-VERSION-GEN file. Junio characterizes the proposed change as "bending an established workflow" to satisfy Meson's requirements, which he views as undesirable. His preference would be for Meson to adapt to Git's existing version management rather than vice versa.

This exchange occurs in the context of a larger, now-completed series that has systematically converted Git's build infrastructure to Meson while maintaining cross-platform functionality. The version generation optimization was one of the early technical achievements in the series, showing measurable performance improvements (1.43x faster on Unix, 2x on Windows). The current discussion represents a rare point of contention in what has otherwise been a methodical and well-received transition effort.
