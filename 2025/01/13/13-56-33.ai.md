Bug report for reftable migration in Git 2.48. Brian Carlson reports encountering a "corrupt reftable file" error when attempting to migrate refs to reftable format, particularly when dealing with repositories containing many refs and reflog updates.

The issue manifests when running `git refs migrate --ref-format=reftable` on repositories with multiple ref updates, where the max_update_index in the reftable header/trailer becomes mismatched (header shows 1 while trailer shows the correct higher value). Carlson provides a detailed reproduction script that creates a test repo with thousands of refs across two update blocks - the error only occurs when both blocks are present, suggesting the problem relates to handling multiple update batches.

The report notes this was encountered in real-world scenarios with repositories containing thousands of refs (2983 and 44832 refs respectively), though those specific repositories can't be shared. Carlson offers to test potential fixes against these real-world cases and provides technical details about the observed header/trailer mismatch that triggers the corruption error.

Key technical details for future reference:
- Error occurs during reftable migration with `--format=reftable`
- Reproduction involves creating many refs (`refs/heads/ref-*`) across multiple update batches
- Problem appears related to max_update_index tracking between header and trailer
- Fails when max_update_index differs from 1, works when it remains 1
- Real-world impact shown with repositories containing thousands of refs

The report is well-documented with a clear reproduction case and technical analysis of the likely cause, though Carlson notes they haven't done deeper investigation yet. This appears to be a legitimate bug in the reftable migration path that could affect users with large numbers of refs.
