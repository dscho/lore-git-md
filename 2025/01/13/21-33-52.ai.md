This is a response in the ongoing discussion about adding editor support for Git's AsciiDoc documentation files. The thread began with an RFC proposing Vim modelines, and this email from Brian M. Carlson opposes that approach while suggesting an alternative.

The response makes three key points against the original proposal: 1) It objects to adding editor-specific configuration (Vim modelines) to project files, drawing a comparison to how Git doesn't include editor-specific patterns in `.gitignore`. 2) It questions the need for modelines, arguing that proficient Vim users can manually set filetype. 3) It suggests the alternative of renaming files with `.adoc` extensions would be more editor-agnostic and useful, especially when combined with `.editorconfig` settings.

The email introduces new considerations for the thread: the principle of avoiding editor-specific configuration in project files, and the potential of `.editorconfig` as a complementary solution. It also represents the first substantive response to the RFC, establishing a position against modelines while being open to the file extension change approach. The response doesn't address the original proposal's question about modeline positioning (top vs bottom), focusing instead on rejecting the concept entirely.
