This is a documentation patch discussion about classifying `git-cherry` as porcelain versus plumbing. Junio Hamano responds to Kristoffer Haugsbakk's argument that `git-cherry` should be considered porcelain due to its user-facing workflow purpose, despite its stable output format (a plumbing characteristic).

Hamano pushes back on the reasoning, arguing that output stability is the key factor in plumbing classification, not just usage patterns. He points out that users can still interactively use plumbing commands (like `git cat-file`), and that the plumbing label primarily signals output stability for script writers. This challenges the premise that workflow purpose should override output stability in classification decisions.

The exchange highlights a fundamental tension in Git's command taxonomy - whether classification should prioritize a command's intended usage context or its technical output characteristics. Hamano's position suggests the project's established practice favors the latter. The discussion remains unresolved, with no clear consensus yet on how to handle commands that straddle both categories.
