This thread reports a bug in Git 2.48's reftable migration feature. Brian Carlson encountered a "corrupt reftable file" error when converting repositories with many refs to the new reftable format. The issue specifically occurs when there are multiple batches of ref updates, causing a mismatch between the max_update_index values in the reftable header and trailer. 

Carlson provided a detailed reproduction script that creates a test repository with thousands of refs across two update blocks - the error only appears when both blocks are present. While he can't share the exact real-world repositories where this was discovered (containing 2983 and 44832 refs respectively), he confirmed the same behavior occurs in production environments. The problem seems to be in how the migration process tracks update indices across multiple batches of changes.

The report includes technical specifics about the header/trailer mismatch and offers to help test potential fixes against real-world cases. This appears to be a legitimate issue that could affect users migrating large repositories to the reftable format, though the core functionality works fine for simpler cases. The bug report is thorough, with clear reproduction steps and analysis of the likely cause.
