This thread documented a bug report about inconsistent behavior of `git diff --merge-base` with annotated tags between Apple Git (version 2.39.5) on macOS and standard Git on Windows. The original reporter found that Apple Git incorrectly rejected annotated tags with a "fatal: --merge-base only works with commits" error, while the same command worked on Windows. 

Kristoffer Haugsbakk identified this as a known bug that was fixed in Git 2.43.0 (commit 4adceb5a299), which corrected the handling of annotated tags while still properly rejecting non-commit objects. Torsten Bögershausen clarified that the Git project doesn't support third-party distributions like Apple's outdated builds, recommending users compile from source or use current versions.

In a follow-up, André de Castro confirmed that the fix works as expected in Homebrew's Git 2.48.0, validating the earlier analysis. The thread serves as a clear case study showing this was purely a version-specific issue (not platform-specific) that was resolved in upstream Git. The recommended solution is to use current Git versions through Homebrew or source compilation rather than vendor-packaged versions. With this confirmation, the discussion is now fully resolved with no outstanding questions.
