Security enhancement follow-up regarding credential URL warnings, specifically addressing coverage of pushURLs in the proposed default change for `transfer.credentialsInUrl`. Johannes Schindelin strongly supports changing the default to "warn" as originally intended, noting this was the long-term plan of the Git Fundamentals team. He explains the historical rationale for initially excluding `.pushURL` from credential checks: clone operations with embedded credentials were a more pressing concern since they silently stored plaintext passwords in configs, whereas push URLs require explicit configuration making credential exposure more obvious to users. However, Schindelin now agrees with Junio Hamano that the warning system should treat both URL types consistently, suggesting equal handling of `remote.*.pushURL` and `remote.*.url` under the credential checking mechanism. This moves the discussion forward by resolving one of the two key implementation concerns (URL coverage) raised earlier, while maintaining consensus on the security benefits of warning users about credentials in URLs. The email provides important historical context about the original implementation decisions while aligning with the thread's trajectory toward more comprehensive credential protection.
