This is a follow-up discussion about the OS version capability feature that has already been accepted into the codebase. Randall Becker (from NonStop systems) is sharing additional thoughts about potential future extensions to the version reporting format, though he acknowledges Junio's position that the current implementation (`osVersion.command`) is sufficient for now.

The key points:
- The core functionality (letting users specify a command to generate version strings) has been accepted as-is without additional formatting options
- Becker suggests there might be value in future format bindings for non-standard `uname` outputs (like mapping `-r` and `-v` flags differently across platforms)
- He explicitly defers to Junio's judgment that such extensions should wait until the community gains experience with the basic feature

This email doesn't propose any code changes - it's more of a "for future consideration" note from someone working on a less common platform (NonStop). The thread shows how Git's design discipline (starting minimal) accommodates both mainstream and niche platform needs while avoiding premature complexity.
