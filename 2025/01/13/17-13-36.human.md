Bugfix for object name resolution with curly braces. This is the first patch in a v3 series addressing edge cases in object name parsing, originally started by Junio C Hamano and now being carried forward by Elijah Newren.

The patch fixes a regression where Git would fail to parse object names containing curly braces (like `foo{bar:README.md`) unless they followed an @ or ^ character. The issue dates back to a 2006 change that assumed braces would always be paired and come after these special characters. The fix modifies the parsing logic to only apply brace-handling rules when braces actually follow @ or ^, while allowing unpaired braces elsewhere in the name.

The commit includes several test cases covering the fixed behavior as well as related edge cases: references containing multiple @ signs (`foo@@{0}`), path components with colons after brace patterns, and commit message searches with colons. The changes are focused in `object-name.c` with test additions in `t1006-cat-file.sh`.
