This is a bug report thread investigating an issue with GPG key selection during tag signing. The discussion reveals that while Git correctly passes the specified signing key to GPG via the command line, GPG appears to ignore it in favor of a smartcard key, even when that smartcard isn't connected.

Key technical details:
- The issue manifests when using `git tag -s` with `user.signingkey` specified
- Git's trace shows the correct key being passed to GPG (`gpg --status-fd=2 -bsau A6...`)
- GPG unexpectedly prompts for a smartcard passphrase and considers a different key (`KEY_CONSIDERED` message shows different key ID)
- The failure occurs with GPG error "Operation cancelled" after password prompt is aborted

The thread suggests this is likely a GPG configuration/behavior issue rather than a Git bug, as Git properly forwards the signing key but GPG appears to override it. The reporter plans to investigate further on the GPG side. No Git code changes are proposed in this email - it's primarily diagnostic information sharing about an interaction quirk between Git's signing interface and GPG's key selection behavior.
