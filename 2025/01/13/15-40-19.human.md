Refactoring patch in the combine-diff memory management series. This is patch 2/14 in Jeff King's ongoing effort to clean up the `combine_diff_path` implementation, which has been receiving positive reviews from Junio Hamano and now Patrick Steinhardt.

The patch introduces a new constructor function `combine_diff_path_new()` to centralize initialization of the tricky-to-allocate `combine_diff_path` struct. This struct has variable size components (both path storage and a parent array) that previously required careful handling at each allocation site. The new constructor:
- Encapsulates the memory calculation and pointer arithmetic
- Ensures consistent zero-initialization of parent arrays
- Converts some `int` parameters to `size_t` for better type usage
- Maintains identical behavior while making the calling code simpler

Patrick Steinhardt's review is positive, noting the code faithfully transplants the existing logic while suggesting `xcalloc()` might be slightly cleaner than explicit `memset()`. This is part of a larger effort to eliminate memory management bugs and simplify the diff machinery's internals. The series has been well-received so far, with Junio having already approved several earlier patches.
