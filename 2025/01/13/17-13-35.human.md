This is a bugfix series addressing two object name resolution issues in Git. Elijah Newren's third iteration improves upon previous versions with better readability and additional test coverage.

The first patch fixes object name resolution when refs contain curly braces (like `foo@{...}` or `get_oid_with_context_1()` was incorrectly handling these cases). The commit message explains why a more comprehensive refactoring would be ideal but isn't straightforward.

The second patch tightens parsing of describe-like output (format `${REFNAME}-${INTEGER}-g${HASH}`) to prevent ambiguous cases where invalid ref names could be misinterpreted as object hashes. This is a slight backward-incompatibility (previously Git would accept garbage before the `-gHASH`), but the change is justified to prevent future ambiguity. The patch includes real-world examples where the old behavior caused problems (like `git cat-file -t master:path/to/who-gabbed` incorrectly resolving to object `abbed`).

The series includes thorough test coverage in `t1006-cat-file.sh` and `t6120-describe.sh`, with the v3 changes adding specific test cases for edge cases like `OBJ-COUNT-gHASH~13` and describe output with revision modifiers. The changes appear well-considered, with clear explanations of the tradeoffs and potential future implications.
