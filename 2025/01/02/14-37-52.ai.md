This is a follow-up in the ongoing meson build system portability discussion, specifically addressing the shell syntax issue in test execution. Junio C Hamano points to what appears to be the relevant patch series that introduced the problematic `check-meson` target in t/Makefile. The issue involves process substitution syntax (`<(...)`) failing on shells like dash that don't support this bashism, despite being used in a critical test comparison operation.

The email doesn't propose a solution but rather connects the reported issue (previously confirmed by both Andy Koppe and Jonathan Nieder) to the specific patch series that likely introduced this behavior. This helps establish the technical context for further discussion, showing the problem stems from meson integration work by Patrick Steinhardt (pks) in late December 2024. The core conflict remains between modern build system adoption and maintaining portability across different shell environments, with the current workaround being explicit bash invocation.
