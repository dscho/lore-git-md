This thread discusses a build system portability issue affecting the new `meson-test` rule in Git's test suite. The problem occurs when running tests with shells that don't support process substitution syntax (like dash), causing a syntax error on the `diff -u <(...)` line in `t/Makefile`. Andy Koppe reports this affects default shell configurations, though it can be worked around by explicitly using bash. The core issue appears to be a portability oversight in the build system, where the test comparison relies on bash-specific process substitution syntax. The thread is currently exploring whether this behavior was intentional or if the Makefile should be modified to use more portable shell constructs. The immediate workaround is to run tests with `SHELL=/bin/bash`, but a proper fix would likely involve either shell feature detection or rewriting the comparison logic.
