This thread has uncovered a portability issue in Git's meson build system test infrastructure, where bash-specific process substitution syntax (`<(...)`) in t/Makefile breaks when run with dash or other minimal shells. The problem was initially missed because many development systems link /bin/sh to bash, and because make's SHELL variable propagation behavior is more complex than expected - it requires explicit passing through the hierarchy rather than just being set in the environment.

Junio Hamano and others have thoroughly diagnosed the issue, confirming that the failure requires specific conditions (SHELL=/bin/dash passed directly to make) and documenting make's variable propagation quirks. The discussion has identified several potential solutions, including rewriting with portable shell constructs, documenting a bash requirement, or fixing the makefile variable handling.

Original series author Patrick Steinhardt has now acknowledged the issue and thanked the diagnostic work, though hasn't yet proposed a fix. The thread remains in a holding pattern awaiting his next steps, with the technical understanding solid but the resolution approach still open. This case has highlighted gaps in portability testing that will need addressing as the build system modernization continues.
