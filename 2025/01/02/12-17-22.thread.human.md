This thread has uncovered a portability issue in Git's meson build system infrastructure, specifically the `check-meson` test target in t/Makefile contains bash-specific process substitution syntax (`<(...)`). The problem was introduced in Patrick Steinhardt's December 2024 meson integration series and affects systems using dash or other minimal shells.

Junio Hamano has been actively involved in diagnosing the issue, confirming it was an oversight in the review process. The failure only manifests when explicitly testing with SHELL=/bin/dash, which explains why it wasn't caught earlier - most development environments either use bash by default or don't test with alternate shells. Recent emails have further clarified that the SHELL variable must be passed directly to the `make check-meson` invocation rather than just set in the environment, and that the top-level `make test` doesn't properly propagate SHELL settings to sub-makes.

The thread has identified three potential resolution paths: rewriting the test comparison logic with portable shell constructs, documenting an explicit bash requirement, or implementing a SHELL=/bin/bash workaround. While the technical disagreements appear minimal, the discussion awaits input from the original author (Patrick Steinhardt) regarding intent and preferred solution. The conversation has also highlighted broader implications for the project's portability testing practices, particularly as the build system modernization continues.
