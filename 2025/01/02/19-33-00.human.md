This is a brief follow-up in the LSan race condition thread, focusing on Git's revert mechanics rather than the original performance issue.

Junio C Hamano responds to Jeff King's suggestion about improving Git's revert commit message format. Jeff had proposed a more structured approach that would automatically list all reverted commits with their hashes and subjects, similar to merge commit messages. While appreciating the idea, Junio notes that auto-generating the subject line (like `Revert jk/lsan-race-with-barrier~3..jk/lsan-race-with-barrier`) would be less readable than the current manual approach.

The exchange highlights an interesting workflow consideration - while merge messages benefit from automated branch naming, reverts are better served by clear manual descriptions paired with detailed commit listings in the message body. This is particularly true when reverting ranges that might use uninformative references like `HEAD~3..HEAD`.

This discussion doesn't propose any code changes but documents an area where Git's tooling could potentially be improved for complex reverts, building on earlier conversations in the thread about maintainer workflows. The tone is collegial, with both maintainers agreeing on the current pragmatic approach while acknowledging room for future enhancement.
