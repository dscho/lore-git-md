Build system issue affecting meson test execution. The new `meson-test` rule in `t/Makefile` fails when run with shells that don't support process substitution syntax (like dash), producing a syntax error on the `diff -u <(...)` line. Andy Koppe reports the error occurs with default shell configurations, though it can be worked around by explicitly using bash. The email questions whether this behavior is intentional or if the Makefile should be made more portable.

Key technical details:
- Failing command: `diff -u <(echo "$$meson_tests") <(echo "$$actual_tests")`
- Error occurs in `t/Makefile` line 119 (check-meson target)
- Shell feature in question is process substitution (`<(...)` syntax)
- Current workaround: `make test SHELL=/bin/bash`

This appears to be a portability oversight in the build system, likely needing either shell feature detection or rewriting the comparison to use more portable constructs. The question implies this may not have been caught in testing environments that default to bash.
