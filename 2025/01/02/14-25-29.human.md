This is a follow-up in the ongoing meson build system portability discussion. Jonathan Nieder confirms Andy Koppe's report about the `check-meson` test target failing on shells without process substitution support (like dash). The issue stems from using bash-specific `<(...)` syntax in t/Makefile line 119 for test comparisons. While the immediate workaround is to explicitly set `SHELL=/bin/bash`, the email points to a broader review thread about meson CI integration where this should be properly addressed. The exchange highlights a real portability concern in Git's build system modernization efforts, though the tone suggests this will be straightforward to resolve in the established discussion channel.
