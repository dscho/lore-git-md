This is a question about worktree relocation in container environments, specifically about safely modifying the `.git` file and related worktree metadata when moving the common directory.

Jörg Sommer asks about relocating Git's common directory (where shared objects live) when repositories are mounted in Docker containers. The core issue is that worktrees reference this common directory via absolute paths in `.git` files, which breaks when the container mounts paths differently from the host. Their proposed solution involves bind-mounting the common dir at a fixed container path and rewriting the `.git` file's path references.

The email notes this works for simple cases but questions whether additional files like `.git/worktrees/*/commondir` and `gitdir` also need adjustment. It's essentially asking whether path rewriting is sufficient or if there are other internal mechanisms that track these locations.

This appears to be a real-world problem for containerized Git users, particularly those using worktrees. The question is well-framed but leaves open whether Git has hidden assumptions about path stability that could cause problems. Responses will likely need input from Git worktree experts about internal invariants.
