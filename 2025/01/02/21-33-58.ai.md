This is a follow-up in the ongoing discussion about unsigned integer literals in bit operations. Junio Hamano responds to Seija Kijin's patch that added 'U' suffixes to integer literals to prevent potential undefined behavior from overflow. While agreeing with the general principle that bit operations should use unsigned types by default, Hamano points out specific flaws in the patch's justification - notably that the examples shown (shifting by stage numbers which are always small) cannot actually overflow. He suggests the real motivation should be code hygiene rather than UB prevention in these cases, and notes that for shifts approaching 31 bits, the unsigned suffix would indeed be important. The response maintains Git's characteristic thorough review culture while being open to the changes if properly justified, continuing the thread's focus on requiring clear rationale for technical changes. Key technical details mentioned include the specific files/lines modified (builtin/checkout.c and merge-tree.c) and the maximum stage number (3) that makes overflow impossible in these cases.
