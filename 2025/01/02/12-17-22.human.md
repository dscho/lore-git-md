CI/build system issue regarding shell compatibility in meson test rules.

Andy Koppe reports that the new `meson-test` rule in `t/Makefile` fails with a syntax error when the default shell doesn't support process substitution (the `<(command)` syntax). The error occurs during a `diff` command that compares test lists, and while it can be worked around by explicitly using bash (`make test SHELL=/bin/bash`), the question is raised whether this is the expected behavior or if the Makefile should be more portable.

This appears to be a legitimate compatibility issue that affects users with non-bash default shells. The patch doesn't propose a solution but rather surfaces the problem for discussion - whether the Makefile should be modified to use more portable shell constructs or whether requiring bash is acceptable. The issue seems straightforward but touches on Git's cross-platform compatibility goals.
