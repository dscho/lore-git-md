Platform compatibility issue in meson test execution, continuing discussion of shell portability problems.

Jonathan Nieder confirms encountering the same issue as Andy Koppe with the `check-meson` target failing on shells without process substitution support. The problem manifests when running tests with default shell configurations (like dash) that don't support the `<(command)` syntax used in t/Makefile line 119 for test comparison. 

This appears to be a follow-up to an earlier review thread (linked) about meson CI integration, suggesting the portability oversight may have been introduced during those changes. The current workaround of explicitly setting SHELL=/bin/bash remains the immediate solution, but the thread indicates this needs discussion about whether to require bash or rewrite the test comparison more portably.

Key technical details remain the process substitution syntax (`diff -u <(...) <(...)`) and its incompatibility with POSIX shells. The thread now has multiple independent confirmations of the issue occurring in default environments, strengthening the case for addressing it either through documentation or code changes.
