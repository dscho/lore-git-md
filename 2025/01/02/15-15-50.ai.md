Bug report for `git log` date filtering behavior. The reporter (Sarah Gastner) identifies an inconsistency where commits with dates clearly within a specified range are sometimes omitted from `git log --after=DATE1 --before=DATE2` output. The specific test case shows commit 501976cc34 (dated 2023-03-13) failing to appear when filtering between 2023-03-10 and 2024-01-24, though it does appear in a narrower window (2023-03-07 to 2023-03-14). The issue reproduces across multiple repositories and platforms (Windows and WSL/Ubuntu), suggesting a core date-parsing or filtering bug rather than environment-specific behavior.

Key technical details: The affected Git version is 2.47.1.windows build), and the reporter provides precise minimal reproduction case with exact date boundaries where the behavior changes (commit disappears when --after changes from 2023-03-07 to 2023-03-08). The report includes full system info but no proposed fix - this appears to be an initial bug report rather than a patch submission. The narrow date window where the commit becomes visible suggests the date comparison may be incorrectly handling timezone offsets or performing an exclusive rather than inclusive range check.
