Bug report about `git log` date filtering inconsistency.

Sarah Gastner reports unexpected behavior with `git log` date filtering where commits with dates clearly within the specified range are being excluded. The specific case shows a commit from March 13, 2023 not appearing when using `--after=2023-03-10 --before=2024-01-24`, despite both its author and commit dates falling within that range. The commit only appears when using a much narrower window (March 7-14, 2023).

The issue appears reproducible across different repositories and platforms (Windows and WSL/Ubuntu), suggesting this isn't an environment-specific problem. The report includes detailed version information showing Git 2.47.1 on Windows with OpenSSL 3.2.3.

This looks like a legitimate bug in Git's date filtering logic, though the report doesn't speculate about the underlying cause. The reporter has done thorough investigation, providing exact date boundaries where the behavior changes and confirming the issue isn't repository-specific. The bug affects a core `git log` feature that many users rely on for commit history inspection.
