This is patch 13/14 in a refactoring series improving Git's combine-diff implementation, focusing on list management in the `emit_path()` function. The patch simplifies how diff paths are temporarily added to and potentially removed from a linked list.

The change modifies the previous approach where paths were immediately added to the list before checking if they should be kept (via the `pathchange` callback). Now, paths are only linked into the list after the callback confirms they should be kept. This eliminates the need to "roll back" additions when paths are rejected, removing some temporary state tracking (`pprev`) and making the code flow more straightforward.

The patch maintains all existing functionality while reducing complexity - a continuation of the series' theme of methodical simplification. As with previous patches, this comes from Jeff King (the original author of much of this code) reviewing and refining his own work, lending credibility to the changes. The diff shows a clean 11-line reduction with no behavior change, just clearer logic.
