This is a bugfix for the credential-cache helper's handling of capability negotiation, now at version 5 in the patch series. The change makes the cache daemon properly respect the authtype capability by only sending authentication type and credential data when explicitly requested via CREDENTIAL_OP_RESPONSE, rather than unconditionally including it via CREDENTIAL_OP_HELPER.

The patch modifies two condition checks in builtin/credential-cache--daemon.c and adds a new test case in t/lib-credential.sh that verifies the helper only includes authtype/credential data when the capability is present. The test demonstrates how without this fix, "credential fill" would print incomplete credentials (missing username/password) when encountering unexpected authtype attributes.

The commit message has been improved since v4 to better explain the change's rationale and impact, addressing feedback from Junio Hamano. This appears to be a well-tested, focused change that brings the credential-cache helper into compliance with documented behavior in git-credential.txt. The series is part of PR #1842 and seems ready for final review.
