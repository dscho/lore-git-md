This is a bugfix follow-up in Patrick Steinhardt's series addressing signed/unsigned comparison warnings in Git's codebase. The thread has uncovered a memory safety regression in the blame command's object ID output when using very large abbreviation values.

Patrick acknowledges Johannes Schindelin's discovery that the v4 patch's switch from `printf()` to `fwrite()` for object ID output in `builtin/blame.c` introduced a security issue. While the original code would safely stop at NUL bytes, the new version could read out-of-bounds memory when given extreme values like `--abbrev=99999`.

The author indicates he'll be sending a fix shortly, though this email doesn't yet include the correction. This highlights the subtle but important behavioral differences between string and binary output functions, even when addressing what initially appeared to be a straightforward type conversion warning. The issue serves as a good reminder of how compiler warning fixes can sometimes introduce more serious problems if not carefully reviewed.
