Performance refactoring in the combine-diff infrastructure, part 7/14 in the series. This patch removes an optimization in `path_appendnew()` that attempted to reuse allocated `combine_diff_path` structs when possible. The optimization dates back to 2014 and was originally meant to avoid performance regressions when unifying single-parent and multi-parent diff code paths.

Jeff King provides detailed benchmarks showing the optimization provides only a 1% speedup in the best case, which is within measurement noise. The optimization complicates the code by storing allocation metadata in the `next` pointer and prevents using the cleaner `combine_diff_path_new()` constructor introduced earlier in the series. The patch simplifies the implementation by always allocating fresh structs and properly freeing unused ones, while maintaining the same external behavior.

Key technical changes:
- Removes the allocation reuse logic from `path_appendnew()`
- Simplifies struct initialization by always setting `next` to NULL
- Updates `emit_path()` to properly free filtered-out paths
- Removes cleanup of pre-allocated elements from `diff_tree_paths()`
- Deletes now-unneeded documentation about the optimization scheme

The change affects `tree-diff.c` exclusively, modifying the path list management while keeping the same diff output. This continues the series' pattern of methodically simplifying the combine-diff implementation while maintaining performance characteristics. The patch represents a tradeoff of minor potential performance impact for significantly cleaner code structure.
