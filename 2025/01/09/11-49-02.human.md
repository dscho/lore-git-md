Behavior change in shallow fetch affecting tags. 

Danila Manturov reports that Git 2.48's shallow fetch behavior changed in a way that breaks tag visibility in TeamCity's test environment. The issue appears related to commit 5f212684ab which modified shallow fetch behavior. 

A minimal reproduction shows that with Git 2.47.1, a shallow fetch (`--depth=1`) would include tags pointing to the fetched commit, but in 2.48.0-rc0 these tags are no longer included. The test repository shows tags `tag1` and `tag2` pointing to commits in the shallow history, but only the older version makes them visible after fetch.

This appears to be an unintentional regression rather than a deliberate change, given that it broke existing test workflows. The report includes clear reproduction steps and version comparisons, making it easy to verify. The impact appears limited to shallow fetches where tags reference commits within the shallow history.

The change affects CI systems like TeamCity that rely on shallow clones and tag visibility. While the regression seems clear, the thread may need input from the original author of 5f212684ab to determine whether this was an intended behavior change or a bug.
