Patch 8/14 in the combine-diff refactoring series, continuing the work to simplify path handling in tree diffs. This patch changes how path strings are constructed when building combined diff paths, moving the string concatenation work from `path_appendnew()` to its caller `emit_path()`.

The key change is having `emit_path()` handle the full path construction by appending the current path component to the base strbuf before calling `path_appendnew()`, then rolling back the strbuf afterward. This removes the need for `path_appendnew()` to handle separate base and path components, simplifying its interface and implementation. The patch notes this doesn't actually increase allocations since the strbuf is reused, and the same concatenation would happen anyway during recursive diffs.

Technical changes include:
- Modified `path_appendnew()` signature to take a single pre-constructed path string rather than separate base/path components
- Updated `emit_path()` to handle the strbuf manipulation around the call
- Maintained the same memory allocation patterns while simplifying the code flow
- Preserved all existing functionality while enabling future refactoring

This continues the series' trend of trading minor implementation details for clearer code structure, with Jeff King's analysis showing no meaningful performance impact from the change. The patch builds on previous work that removed an optimization in `path_appendnew()`, further simplifying that function's responsibilities.
