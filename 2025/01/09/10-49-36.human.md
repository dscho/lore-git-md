Bugfix and behavior clarification for `help.autocorrect` configuration. This v2 patch from Scott Chacon expands on the previous version by fully implementing Junio Hamano's suggestion to support all boolean values (`true`, `false`, `yes`, `no`, etc.) for the `help.autocorrect` setting, while maintaining backward compatibility.

The key changes are:
1. `help.autocorrect=1` now means immediate execution (like "immediate"), not a 0.1 second delay
2. Boolean `false` values (like "off"/"no") are treated as 0 (shows guesses but doesn't execute)
3. Boolean `true` values (like "on"/"yes") are treated as "immediate"
4. Numbers ≥2 still work as decisecond delays
5. The documentation is updated to clarify these behaviors

The implementation uses `git_config_bool_or_int()` to handle both boolean and numeric cases, with special treatment for the 0/1 cases. This addresses the original confusion where users expected `1` to mean "on" rather than a tiny delay, while preserving all existing functionality. The patch has already received technical approval from Johannes Schindelin in the thread, with this version incorporating feedback about boolean handling.
