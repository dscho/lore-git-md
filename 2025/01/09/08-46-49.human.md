Refactoring patch in the combine-diff series, removing an optimization that's no longer worth its complexity.

This is patch 7/14 in Jeff King's series to clean up Git's combine-diff implementation. It removes a memory reuse optimization in `path_appendnew()` that was originally added in 2014 to avoid allocations when diffing trees. The optimization made the code more complex by storing allocation sizes in pointer fields and prevented using the cleaner `combine_diff_path_new()` constructor.

Jeff provides detailed benchmarks showing the optimization only provides about a 1% speedup, which is within the margin of error. The patch simplifies the code significantly (removing 61 lines while adding just 6) by always allocating fresh structs. The change makes the code more straightforward and enables future refactoring, at a negligible performance cost.

The patch continues the series' pattern of carefully measuring tradeoffs between performance and maintainability, here deciding in favor of simplicity. The change is well-motivated and comes with thorough performance analysis showing the optimization's minimal impact on modern Git.
