This is a bugfix patch from Junio Hamano reviewing Jeff King's combine-diff refactoring series. The patch addresses a memory leak in `run_diff_files()` where a `combine_diff_path` struct could be allocated but then leaked if `check_removed()` returned an error. 

The fix is straightforward - it simply moves the allocation after the error-prone `check_removed()` call. This both prevents the leak and has the side benefit of making the code more amenable to future refactoring (as noted in the commit message, this helps pave the way for a constructor function).

The change is small (12 lines moved) and clearly correct. As part of a larger refactoring series that's already been well-reviewed, this patch appears to be a clean improvement that fixes a real (if likely rare) issue while making the code slightly more maintainable.
