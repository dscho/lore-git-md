Refactoring patch in the combine-diff series, focusing on code clarity in list management. This is patch 12/14 in Jeff King's ongoing series to improve Git's combine-diff implementation.

The patch renames a confusing variable name in the tree-diff code. The `p` parameter in several functions was doing double duty as both the list tail pointer and sometimes as a newly allocated entry, which made the code harder to follow. Jeff changes this to consistently use `tail` when referring to the list tail, while keeping `p` for new entries in `emit_path()`. This makes the code's intent clearer without changing any behavior.

The change is straightforward and mechanical, touching only variable names in `tree-diff.c`. It builds on the previous patches' work to simplify the combine-diff implementation, particularly the list management aspects that were addressed in patch 11. As with the rest of the series, this change improves maintainability while preserving all existing functionality.
