Bugfix for `git blame`'s object ID output handling. This patch addresses an out-of-bounds read that could occur when using an excessively large `--abbrev` value with `git blame`.

The issue stems from a recent change (6411a0a896) that switched from `printf` to `fwrite` for emitting object IDs to avoid a type-casting issue. While that fixed the type safety, it introduced a new problem: `fwrite` doesn't stop at NUL bytes like `printf` does, which could lead to reading beyond the OID array bounds when the requested abbreviation length exceeds the actual hash length.

The fix reverts back to using `printf` but adds a safeguard to cap the length at `GIT_MAX_HEXSZ` before the cast to `int`. This maintains the type safety while preventing buffer overreads. The patch includes a new test case that verifies the fix by attempting to use an absurdly large abbreviation value (9000 characters).

The change affects `builtin/blame.c`'s OID output logic and adds a regression test in `t/t8002-blame.sh`. The bug was identified by Johannes Schindelin and the fix comes from Patrick Steinhardt. This appears to be a straightforward and well-tested correction of a subtle but potentially dangerous edge case in the blame output formatting code.
