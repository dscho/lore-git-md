This is a bugfix and interface improvement patch for the `help.autocorrect` configuration, implementing Junio Hamano's suggestion from the thread to handle boolean values more comprehensively. The patch builds on the previously approved technical approach (treating `1` as immediate correction) while expanding it to accept all boolean string values ("true"/"false", "yes"/"no", etc.) for more intuitive configuration.

The key changes in v2:
1. Now accepts boolean strings where "true" values map to immediate correction (AUTOCORRECT_IMMEDIATELY) and "false" maps to 0 (show suggestion but don't execute)
2. Maintains backward compatibility with numeric delays (values ≥2 still interpreted as deciseconds)
3. Documents the new boolean string support in help.txt
4. Clarifies the subtle difference between "false" (show guesses) vs "never" (don't show guesses)

The implementation uses git_config_bool_or_int() to handle the boolean cases while preserving the existing numeric delay behavior. The documentation updates explicitly call out the boolean string support and the distinction between 0/false and "never".

This addresses the core user experience issue (confusion around `help.autocorrect=1`) while incorporating Junio's interface design suggestion. The thread shows technical consensus on the approach, with this version addressing prior documentation feedback (commit message style and typos). The remaining open question from Junio about potentially treating the config as an extended boolean isn't blocking this change but could be a future enhancement.
