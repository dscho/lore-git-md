This is a bugfix for `git blame`'s an out-of-bounds read issue when using large `--abbrev` values, part of an ongoing thread about OID output handling.

The patch addresses a regression introduced in commit 6411a0a896 where switching from `printf` to `fwrite` for OID emission could read past buffer bounds with excessive `--abbrev` values. The v2 version makes two key improvements over the initial fix: it moves the `GIT_MAX_HEXSZ` length check after handling prefix characters (^, *, ?) to maintain proper spacing, and adds a test case that verifies truncation of absurdly large abbrev values (9000) to the hash algorithm's actual hex size.

The changes affect `builtin/blame.c`'s OID emission logic and add test coverage in `t/t8002-blame.sh`. The solution reverts to using `printf` with length truncation rather than `fwrite`, which prevents buffer overreads while preserving the expected formatting behavior for boundary/unblamable/ignored commits. The test explicitly checks that the truncation occurs rather than just verifying the output length.

This iteration addresses Johannes Schindelin's feedback about both the buffer safety issue and the test coverage, making it a more complete fix. The thread history shows careful attention to edge cases in OID formatting while maintaining security against buffer overreads. The changes are focused and well-tested, with the test case designed to fail without the fix.
