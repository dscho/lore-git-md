This thread discusses improving documentation for `git-credential-cache` to better address the limitations when storing personal access tokens (PATs). The original patch from M Hickford identified that the cache's ephemeral nature makes it unsuitable for long-lived credentials, leading developers to use insecure workarounds. Junio C Hamano agreed with the need for better documentation but suggested being more explicit about recommending persistent alternatives like libsecret and osxkeychain.

Randall Becker has now contributed practical experience report, describing how he implemented a custom credential manager specifically for PAT handling that bypasses both the standard cache and OAuth flows. His solution, which includes Microsoft Authenticator integration, demonstrates real-world developer pain points and reinforces the need for clearer official guidance. While not proposing specific documentation changes, Becker's input provides valuable context about enterprise Windows environments that could help shape the final documentation wording.

The discussion is now focused on how to best present this information - whether to modify existing credential backend documentation or add new warnings, and finding the right phrasing to steer users toward secure persistent storage options without creating redundancy. The core agreement remains that the documentation should better warn about cache limitations while pointing to proper solutions.
