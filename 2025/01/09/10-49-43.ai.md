Follow-up to the `git blame` OID output fix addressing edge cases in the truncation behavior. Johannes Schindelin points out two issues with Patrick Steinhardt's fix for the out-of-bounds read when using large `--abbrev` values. First, the regression test incorrectly uses `--abbrev=$hexsz` rather than testing an actually excessive value. Second, the fix's hard truncation at `GIT_MAX_HEXSZ` disrupts alignment behavior for boundary/unblamable/ignored commits, where the original code would use the full `abbrev` value for spacing even when displaying full OIDs. The proposed fixup adjusts the truncation threshold to `GIT_MAX_HEXSZ + 3` to preserve this spacing behavior while still preventing buffer overreads, and corrects the test to use an absurdly large value (9000) that will trigger truncation. The change is subtle and only observable in SHA-256 mode due to the size difference from SHA-1. This refinement maintains the original safety fix while better preserving the expected output formatting edge cases.
