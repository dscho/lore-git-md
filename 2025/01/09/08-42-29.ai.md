This is the fourth patch in a 14-part refactoring series improving Git's combine-diff implementation, focusing on memory management and code clarity. The patch converts a `strbuf` field in `combine_diff_parent` to a simple string pointer, fixing an initialization inconsistency while simplifying the code.

The change addresses a subtle issue where parent path storage was using `strbuf` unnecessarily - the field only ever stored a single string without modification. The patch notes this was technically an API violation since the strbuf wasn't properly initialized for non-0th parents, though the implementation happened to handle it. By switching to a plain `char*`, the code becomes simpler and the initialization more straightforward (just NULL or a string pointer).

Key technical changes include replacing `strbuf` operations with direct string allocation/free, updating access patterns to check for NULL pointers rather than the `combined_all_paths` flag, and modifying the struct definition in diff.h. The patch touches several combine-diff.c functions that handle path display and memory management, consistently applying the new simpler pattern.

This change fits into the series' broader goal of cleaning up memory management in combine-diff, though it stands out as fixing an actual minor bug (the strbuf initialization gap) rather than just refactoring. The simplification makes the code easier to reason about and maintain going forward, while reducing the memory overhead of the strbuf structure.
