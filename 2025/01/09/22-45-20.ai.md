This is a bugfix patch (v5) in a series addressing credential-cache helper behavior regarding authtype capabilities. The change modifies the credential-cache daemon to only include authtype and credential data in responses when explicitly requested via CREDENTIAL_OP_RESPONSE capability, rather than the previous unconditional inclusion via CREDENTIAL_OP_HELPER.

The patch makes two key changes in builtin/credential-cache--daemon.c, replacing CREDENTIAL_OP_HELPER checks with CREDENTIAL_OP_RESPONSE for authtype and credential field output. It also adds a new test case in t/lib-credential.sh that verifies the helper only returns authtype/credential data when the request includes the capability. The test demonstrates the failure case where without this fix, "credential fill" would print incomplete credentials due to unexpected authtype attributes being discarded.

This version improves the message from v4 by better explaining the behavioral change and its impact, addressing Junio Hamano's earlier feedback. The change aligns the credential-cache helper with documented behavior in git-credential.txt, which states authtype should only be sent when the appropriate capability is provided. The test addition helps prevent regression of this capability-aware behavior.
