Bugfix refinement for `git blame`'s object ID formatting. This is a follow-up to Patrick Steinhardt's v2 patch that fixed an out-of-bounds read when using large `--abbrev` values in `git blame`. The original issue occurred when switching from `printf` to `fwrite` for OID emission, which could read past buffer bounds.

Junio C Hamano reviews the current solution, which reverts to using `printf` while capping the length at `GIT_MAX_HEXSZ`. He notes this is technically correct since it prevents buffer overreads, though it does leave the theoretical question of what happens if the hash function produces output shorter than `GIT_MAX_HEXSZ` (in practice this isn't a concern with current hash algorithms). 

The review highlights two key improvements in this version: moving the length check after prefix character handling (for ^, *, ? markers) maintains proper spacing, and the `printf` approach is more robust than alternatives like using `fwrite` with `strlen`. While Hamano mentions an alternative approach using `strlen` could work, he explicitly states this isn't a suggestion to change the current solution, which he considers a "very good improvement" over the v1 iteration.

This concludes the technical discussion about the buffer safety fix, with the maintainer's approval suggesting this solution is likely to be merged. The thread has thoroughly examined edge cases around OID formatting, particularly for boundary/unblamable commits, and arrived at a robust solution.
