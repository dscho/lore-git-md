Bugfix: `git grep` incorrectly matches empty lines at end of file

Olly Betts reports that `git grep '^$'` produces a false positive match at the end of files, showing a line number one greater than the file's actual line count. This differs from GNU grep's behavior, which correctly doesn't match in this case. The bug is reproducible with both current Debian stable (2.47.1) and experimental (2.48.0-rc1) Git versions.

The report includes clear reproduction steps: creating a single-line test file and showing how `git grep` reports a match on line 2 while GNU grep shows no match. The behavior occurs regardless of whether the `-n` option is used.

This appears to be a straightforward bug in Git's grep implementation where it's incorrectly handling the EOF condition when looking for empty lines. The report is well-documented with specific version information and clear steps to reproduce, making it easy to verify and likely straightforward to fix. The discrepancy with GNU grep's behavior suggests this wasn't an intentional design choice.
