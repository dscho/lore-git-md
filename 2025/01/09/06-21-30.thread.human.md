This thread addresses a bug in `git blame`'s handling of object ID output when using large `--abbrev` values, which could cause buffer overreads. The issue was introduced by a change from `printf` to `fwrite` for OID emission. Patrick Steinhardt provided the initial fix, which Johannes Schindelin reviewed, identifying both the original problem and some issues with the solution - particularly around test coverage and formatting of special commit markers (those prefixed with ^, *, or ?).

Steinhardt's v2 patch improved the fix by properly handling prefix characters while capping lengths, and added better test cases. Shejialuo has now reviewed v2, agreeing with the technical implementation but questioning whether `git blame` should allow `--abbrev` values larger than `GIT_MAX_HEXSZ` at all, suggesting this might warrant a separate discussion about input validation. The current solution is considered complete from a technical standpoint, safely handling buffer overreads while maintaining proper formatting, but may lead to future interface refinements regarding what `--abbrev` values should be permitted.
