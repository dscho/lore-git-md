This thread addresses a series of security fixes for `git blame`'s object ID handling, focusing on three distinct vulnerabilities. The core issue involves out-of-bounds reads when using large `--abbrev` values, with additional fixes for a pre-existing buffer overflow and boundary commit handling problems. Patrick Steinhardt's v3 patch series provides comprehensive solutions across `builtin/blame.c` with expanded test coverage.

The latest patch specifically fixes a boundary condition that could cause out-of-bounds writes when combining `-b` (blank boundary commits) with excessive `--abbrev` values. The solution replaces an unsafe `memset()` call with `strlen(hex)` to ensure proper blank spacing while respecting hash length limits. The fix maintains compatibility with both SHA-1 and SHA-256 repositories and adds test cases verifying correct behavior with both normal and extreme values.

Key participants include Patrick Steinhardt (author), who implemented all three fixes in v3 series; Johannes Schindelin, who originally identified the primary issue and discovered the buffer overflow; and Junio Hamano, who approved the technical direction. The series now comprehensively addresses the security vulnerabilities while preserving expected blame output formatting, with extensive test coverage for both current and edge cases.
