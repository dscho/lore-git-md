This thread addresses three security vulnerabilities in `git blame`'s object ID handling. The main issue involved an out-of-bounds read from large `--abbrev` values, with two additional problems found during review: a pre-existing buffer overflow in OID formatting and unsafe boundary commit handling with the `-b` flag. Patrick Steinhardt led the fixes across three versions of the patch series, with Johannes Schindelin providing key review and identifying some of the vulnerabilities.

The solutions maintain compatibility with both SHA-1 and SHA-256 repositories while fixing all three issues. The boundary commit handling was the last piece to be approved, with Schindelin calling the `strlen(hex)` approach a "neat trick" that preserves formatting while eliminating risks. Junio Hamano has now given final approval for inclusion in the next release.

While the security fixes are complete, there remains an open discussion about whether to reject `--abbrev` values exceeding `GIT_MAX_HEXSZ` entirely - this is a philosophical question about input validation policy rather than a security concern. The series has extensive test coverage and addresses all identified vulnerabilities, making it ready for merging.
