This thread discusses a documentation reorganization patch that moves the detailed explanation of `trailer.*` configuration variables from `git-interpret-trailers.txt` to a new centralized location in `config/trailer.txt`. The change improves discoverability while maintaining all existing content through include directives.

The patch affects three files: it creates the new `config/trailer.txt` with all trailer configuration details, adds an include reference in `config.txt`, and replaces inline documentation in `git-interpret-trailers.txt` with includes pointing to the new file. This makes sense since trailer configuration affects multiple commands (`git-commit`, `git-tag`, and `git-interpret-trailers` itself).

The documentation covers key trailer configuration options including separator characters, placement rules, handling of duplicate/missing keys, and per-key overrides. The patch maintains the distinction between deprecated and preferred syntax for key-specific commands. The change is purely organizational with no content modifications, following Git's standard documentation practices for centralized configuration documentation.
