This thread reports a regression in `git fetch` behavior with shallow clones between Git versions 2.47.1 and 2.48.rc0. Danila Manturov discovered that while Git 2.47.1 would fetch tags pointing to the most recent commit (the shallow boundary) during a `--depth=1` fetch, version 2.48.rc0 no longer retrieves any tags in this scenario. 

The reporter provides a clear test case using a GitHub repository with two tags (tag1 on the latest commit and tag2 on the initial commit), demonstrating the changed behavior isn't just about tags in deeper history. The regression appears linked to commit 5f212684abb66c9604e745a2296af8c4bb99961c, though the exact connection hasn't been analyzed yet. This change could impact CI systems and other automation that rely on shallow fetches including boundary tags.
