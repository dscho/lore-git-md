Here's the updated human-readable summary:

This thread investigates a regression in `git fetch` behavior for tags in shallow clones. Danila Manturov originally reported that tags pointing to the shallow boundary commit stopped being retrieved with `--depth=1` between Git 2.47.1 and 2.48.rc0, tracing it to commit 5f212684abb6. Bence Ferdinandy identified that commit 6c915c3f85 ("fetch: do not ask for HEAD unnecessarily") had already addressed part of this issue by fixing unnecessary HEAD requests in `ls-remote`.

New testing reveals the fix works in some scenarios but shows transport-specific behavior. While the issue appears resolved when using the JSch (Java SSH) transport, it still fails with native SSH/HTTPS transports. This suggests the solution may need protocol-specific adjustments or that different transport implementations handle shallow clone tag resolution differently. The discussion has evolved from identifying the regression to understanding why the current fix doesn't cover all cases, particularly for tags at shallow boundaries, and now to uncovering transport-layer variations in the behavior. The original reproduction case (a test repo with tags on distinct commits) remains the reference scenario, but the investigation has grown more complex with these new findings about transport protocol differences.
