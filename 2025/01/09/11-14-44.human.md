This is a bugfix refinement for `git blame`'s object ID output handling, continuing the discussion from earlier in the thread. Patrick Steinhardt responds to Johannes Schindelin's review of the initial fix for an out-of-bounds read when using large `--abbrev` values.

The key points in this follow-up:
1. Patrick proposes moving the length truncation check (`GIT_MAX_HEXSZ`) to after the special character indicators (^, *, ?) are handled, which would simplify the logic by eliminating the need for the `+3` buffer adjustment.
2. He also notes the test case should verify the actual truncation behavior by checking that an absurdly large `--abbrev=9000` gets reduced to `$hexsz` (the full hash length) rather than testing with `--abbrev=$hexsz`.

The discussion shows careful attention to both safety (preventing buffer overreads) and maintaining expected formatting behavior for boundary/unblamable/ignored commits. The proposed changes would make the code more straightforward while still addressing the original issue. This appears to be a thoughtful refinement of the solution, though it hasn't been finalized yet.
