This is a refactoring patch in the combine-diff improvement series, specifically addressing initialization consistency in the path allocation code.

The patch focuses on `path_appendnew()`, which creates new `combine_diff_path` structs but was the only allocation function not zeroing out the parent array. While this wasn't causing bugs (since callers populate the relevant fields), the inconsistency made the code more error-prone. The change adds a `memset()` to zero the parent array, matching the behavior of the new `combine_diff_path_new()` constructor introduced in patch 02/14.

Key technical details include:
- Modifies `tree-diff.c`'s `path_appendnew()` function
- Initializes `p->parent` array for `nparent` entries
- Updates the function's documentation comment to remove the note about uninitialized parents
- Maintains the function's memory-reuse optimization (reusing `last->next`) while adding the initialization

This change improves code consistency and safety without affecting functionality, continuing the series' theme of cleaning up combine-diff's memory management. The patch is small (4 lines changed) and straightforward, building on the foundation laid by previous patches while keeping the optimization path intact for later treatment in patches 07-10.
