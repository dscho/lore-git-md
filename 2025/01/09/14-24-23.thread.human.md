This thread addresses a build system race condition that emerged when Git's version generation script (`GIT-VERSION-GEN`) was recently modified to also produce version strings for documentation files. The change introduced a concurrency issue during parallel builds (`make -j2 html man`), particularly problematic on Windows where the script runs through slow POSIX emulation. The original implementation used a static `+` suffix for temporary files, allowing one build process to interfere with another's operations.

The fix, a minimal 4-line change, replaces the static suffix with process-specific temporary filenames (using `.$$`), solving both the race condition and an incidental Windows compatibility issue (where `+` isn't a valid filename character). The author notes that while a more comprehensive build system redesign would be preferable, this targeted fix addresses the immediate problem without disrupting the current release cycle. The patch is well-grounded in evidence from failed CI runs and maintains the existing build architecture while unblocking Git for Windows v2.48.0-rc2.
