This thread addresses a build system race condition that occurs during parallel builds, particularly affecting Windows, where version generation in `GIT-VERSION-GEN` can collide when creating temporary files. The original patch proposed using process-specific temporary filenames (`.$$` suffix) to resolve both parallel build conflicts and Windows filename constraints. The issue became more noticeable when version strings were extended to documentation files (`asciidoctor-extensions.rb` and `asciidoc.conf`), causing problems with concurrent `make -j2 html man` runs.

Martin Ågren later pointed out an interaction with `.gitignore` patterns (which currently match `*+` to clean up temporary files) and suggested an alternative format (`"$OUTPUT"."$$"+`) to maintain `.gitignore` coverage while ensuring uniqueness. However, this wouldn't fully address the Windows filename limitation. 

Junio C Hamano has now weighed in, confirming that the `.$$` suffix approach is reasonable for a short-term fix, though alternatives like `~` could also work. He notes that a previous attempt (216.git) failed due to inconsistent application and unupdated `.gitignore` patterns—issues the current patch properly handles. The discussion remains focused on implementation details, with consensus forming around the `.$$` solution as a pragmatic fix. No fundamental objections remain, and the thread is now refining edge cases without challenging the core approach. The broader build system redesign remains deferred for future work.
