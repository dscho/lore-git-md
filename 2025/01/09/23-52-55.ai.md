This patch reports an inconsistency where `git grep '^$'` incorrectly matches at the end of a file (reporting a line number one past the last line), while standard `grep` does not. The issue is reproducible with both current and development versions in Debian.

The core problem appears in the interaction between `git grep`'s line matching logic and file boundaries. The reporter provides clear reproduction steps: creating a single-line file and showing the differing behavior between `git grep` and GNU grep. The mismatch suggests either an off-by-one error in line counting or incorrect handling of empty line matching at EOF.

This seems like a legitimate bug that would affect any user trying to match empty lines consistently between Git and standard grep tools.
