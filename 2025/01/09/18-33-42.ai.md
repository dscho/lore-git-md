This is a follow-up discussion on the build system race condition fix for parallel version generation. Martin Ågren responds to Johannes Schindelin's explanation of the race condition in parallel documentation builds, agreeing with the analysis while noting the broader issue of recursive make's problems. 

Martin points out an additional consideration: the current `.gitignore` includes a pattern (`*+`) that catches temporary files with `+` suffixes, which could be useful for interrupted builds or GUI tools monitoring untracked files. He suggests an alternative approach of using `"$OUTPUT"."$$"+` as the temporary filename, which would maintain the `+` suffix pattern while still including the process ID for uniqueness. This would preserve the `.gitignore` coverage while still solving the parallel build issue, though it would no longer address the Windows filename character limitation that Johannes mentioned as a secondary benefit.

The email doesn't propose changing the patch but raises a potential trade-off between maintaining existing `.gitignore` patterns and the Windows filename compatibility improvement. The discussion remains technical and constructive, focused on edge cases and secondary effects of the proposed solution.
