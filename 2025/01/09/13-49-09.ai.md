This is a refinement in the ongoing discussion about `git blame`'s OID formatting and `--abbrev` handling. Johannes Schindelin responds to Shejialuo's question about why Git allows `--abbrev` values exceeding `GIT_MAX_HEXSZ` by explaining the alignment behavior for prefixed OIDs (marked with ^, *, ?). The key technical detail is that when blaming a range (HEAD..) in SHA-1 repos, Git prefixes the OID with ^ and truncates the last hex digit to maintain alignment, but shows the full OID when `--abbrev=41` is used. This interaction between prefix characters and length truncation is the core issue being addressed in the thread. The discussion remains focused on edge case behavior in OID formatting, with Schindelin referencing his earlier explanation of why the alignment requirements make the current behavior necessary despite the apparent oddity of accepting values beyond the hash length. The exchange shows the careful consideration being given to both the security implications (preventing buffer overreads) and user-visible formatting behavior in this bugfix series.
