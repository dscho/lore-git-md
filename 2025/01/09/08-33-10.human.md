Refactoring patch in the combine-diff memory management series. This is patch 3/14 in Jeff King's series cleaning up Git's combine-diff implementation.

The patch focuses on `path_appendnew()`, a helper function that allocates and initializes `combine_diff_path` structs. While other allocation paths zero out the parent array in these structs, this particular code path was leaving it uninitialized. The change makes the behavior consistent by adding a `memset()` to clear the parent array.

The commit message explains this isn't fixing an actual bug (since callers fill in the fields they need), but makes the code more maintainable by eliminating potential confusion of uninitialized values. This aligns with the series' broader goal of improving memory management consistency in the combine-diff code.

The change is small (just 2 lines modified) and straightforward, removing a minor inconsistency while maintaining the existing optimization where this function reuses memory from the previous allocation. It continues the pattern seen in earlier patches of making initialization behavior more predictable across the codebase.
