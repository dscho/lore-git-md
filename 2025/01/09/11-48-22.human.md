Bugfix for `git blame`'s object ID formatting, addressing an edge case with large `--abbrev` values. This is version 2 of a patch that fixes an out-of-bounds read introduced when switching from `printf` to `fwrite` for OID emission. The original change (6411a0a896) avoided a type cast but inadvertently allowed reading past buffer bounds when `--abbrev` exceeded the hash length.

Patrick Steinhardt's revised solution reverts to `printf` while capping the length at `GIT_MAX_HEXSZ`, but now properly handles prefix characters (^, *, ?) that indicate boundary/unblamable/ignored commits. The patch also includes a corrected test case that verifies absurdly large abbrev values (like 9000) get truncated to the hash algorithm's actual size. The changes affect `builtin/blame.c`'s OID emission logic and add test coverage in `t/t8002-blame.sh`.

This iteration addresses feedback from Johannes Schindelin, who identified both the original buffer overread issue and problems with the initial fix's test case and prefix handling. The solution maintains safety while preserving expected formatting behavior in edge cases.
