This is a continuation of the Windows reftable backend compatibility discussion, specifically addressing file deletion behavior. Patrick Steinhardt responds to Johannes Sixt's proposal to remove the interactive prompt from mingw_unlink() in favor of a cooperative deletion strategy between Git processes.

The key points in this email:
1. Steinhardt acknowledges Sixt's distinction between inter-process (where cooperative deletion is desired) and intra-process (where files shouldn't be deleted while open) scenarios
2. He expresses hesitation about Sixt's broader proposal to modify mingw_unlink() behavior system-wide, citing limited Windows expertise
3. Steinhardt prefers maintaining his original narrower scope-limited solution for the reftable library specifically
4. He conditionally defers to Dscho's (Johannes Schindelin's) judgment on the wider change

The email reveals an important tension in the discussion - while Sixt advocates for a systematic solution addressing the root cause, Steinhardt prefers a targeted fix for the immediate reftable issue. This reflects the ongoing architectural debate about whether to handle this at the platform layer (mingw_unlink) or library layer (reftable-specific handling).

The discussion remains unresolved but is moving toward needing input from Windows maintainers (Dscho) to break the deadlock between these approaches. Steinhardt's position maintains the status quo of his original patch while leaving room for the broader change if Windows experts approve it.
