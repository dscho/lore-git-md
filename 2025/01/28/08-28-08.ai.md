Refactoring patch in the reftable decoupling effort, specifically addressing error handling conversion from BUG() to proper error returns.

This patch continues the systematic replacement of Git's BUG() macro with proper error returns in the reftable library, now targeting several remaining trivial cases. The changes affect three key areas:

1. The indexed table iterator's seek operation now returns REFTABLE_API_ERROR instead of aborting, as seeking isn't supported for this iterator type. This matches the pattern established in earlier patches for other unsupported operations.

2. Reference counting functions in the reader implementation drop their BUG() checks entirely, as the author notes these would only trigger after the structure was already freed (making the checks redundant since we'd be in undefined behavior territory anyway).

3. The writer gains two error returns: one for invalid block size configuration and another for type mismatches when adding records. These replace what were previously hard aborts.

The changes are straightforward mechanical conversions, maintaining the library's error handling consistency while removing the last Git-specific BUG() dependencies in these components. This continues the thread's overall goal of making reftable fully portable by eliminating Git-specific behaviors, with particular attention to error propagation patterns that will work in standalone library contexts. The patch follows the established pattern of previous conversions in the series, showing careful consideration of edge cases while simplifying the code where possible (as with the removed refcount checks).
