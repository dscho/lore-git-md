This is a refactoring patch that splits Git's initialization and exit code into separate files to make `libgit.a` more self-contained. It's part of the ongoing Rust bindings effort (v7 1/4) where external users need to link against Git's core functionality without pulling in unnecessary dependencies.

The patch moves `common_exit()` and `check_bug_if_BUG()` into new `common-exit.c` and extracts initialization code from `main()` into `common-init.c` with a new `init_git()` function. Both new files are added to `LIB_OBJS` in the Makefile and meson.build to ensure they're included in `libgit.a`. The changes allow external consumers to use Git's setup/teardown routines without linking against the full Git binary's dependencies.

Key technical details:
- Creates new files `common-exit.c` (exit handling) and `common-init.c` (startup routines)
- Adds corresponding `common-init.h` for the new `init_git()` API
- Strips `common-main.c` down to just the main() wrapper
- Maintains all existing functionality including SIGPIPE handling, trace2 initialization, and working directory tracking
- References prior discussions about similar splits for fuzz/unit test support
