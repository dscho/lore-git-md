This is a CI/build system issue regarding documentation file extensions during a transitional period.

Jeff King reports a CI failure where `difftool.adoc` tries to include `mergetools-diff.txt`, which fails because the file extension situation is in flux between two concurrent changes. The `bc/doc-adoc-not-txt` branch (by Jean-Noël Avila) has renamed all documentation files from `.txt` to `.adoc`, while the `aj/difftool-config-doc-fix` branch (by Adam Johnson) introduces a new include reference still using the old `.txt` extension. 

The problem manifests as a missing include file during documentation build, specifically when processing `difftool.adoc` which references the not-yet-renamed `mergetools-diff.txt`. Jeff notes this can't be fixed independently on either branch - it requires either an "evil merge" (a manual merge resolution) or for the adoc conversion branch to be rebased on top of the now-merged doc-fix changes.

This highlights a transitional challenge in the ongoing AsciiDoc conversion effort, where file extension changes need to be coordinated with any new documentation references being added in parallel development. The issue is specific to the build process and doesn't affect runtime behavior.
