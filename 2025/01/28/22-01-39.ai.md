This is part 3/4 of the final v8 series implementing Rust bindings for Git's C library, focusing on expanding the configset API exposure in `libgit-sys`. The patch adds FFI bindings for core config management functions, wrapping them with `libgit_`-prefixed names to prevent symbol collisions. Key additions include:

The C layer now exposes `libgit_configset_alloc()`/`libgit_configset_free()` for heap management of config sets, plus functions for adding config files (`libgit_configset_add_file`) and retrieving values (`libgit_configset_get_int`/`libgit_configset_get_string`). These are implemented via a new `libgit_config_set` wrapper struct that maintains type safety boundary while allowing external consumers to treat config sets as opaque objects. The Rust FFI layer in `lib.rs` mirrors these additions with corresponding type definitions and extern declarations.

This builds on the series' established pattern of careful FFI design, here applied to Git's config subsystem. The changes are preparatory work for the higher-level Rust API coming in the next patch, so no direct tests are included here - testing will happen through that higher layer. The implementation follows the project's safety practices by using proper wrapper structs rather than direct casting, continuing the approach seen earlier with user agent functions. This maintains the series' focus on providing safe, idiomatic Rust interfaces to Git's core functionality while keeping the FFI boundary cleanly defined.
