This is a refactoring patch that's part of a larger performance optimization series introducing zlib-ng support (v4, patch 2/10). The patch removes the `z_const` define from git-compat-util.h, which was previously used to suppress the `const` qualifier in zlib function parameters.

The commit explains that this define was likely carried over from an old compatibility shim for `uncompress2()` (removed in the previous patch) without clear justification. The author argues that removing `const` qualifiers doesn't actually make parameters less constant, and there appears to be no good reason to maintain this define. The change is straightforward - a single line deletion from git-compat-util.h.

This is a minor cleanup in the context of the larger zlib-ng integration effort, which aims to provide significant performance improvements (~25% speedup in object reading operations). The patch follows logically from the removal of the `uncompress2()` compatibility shim in the previous patch, cleaning up related cruft. The change is uncontroversial and aligns with the series' goal of modernizing Git's zlib integration.
