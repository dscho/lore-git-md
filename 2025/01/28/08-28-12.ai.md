Platform compatibility patch in the reftable decoupling series, introducing a portable random number generator interface.

This patch adds a new `reftable_rand()` function to the reftable system layer, replacing direct calls to Git's `git_rand()`. The implementation currently wraps Git's CSPRNG for compatibility during transition, but the interface is designed to allow the calling codebase to provide its own seeded RNG implementation. Two call sites in the reftable stack code are updated to use the new interface - one for backoff delays during retries and another for generating unique filenames.

The change follows the series' pattern of replacing Git-specific functionality with reftable-owned abstractions. While the current implementation still depends on Git's RNG, the interface separation prepares for complete independence. The patch is straightforward with clear documentation of the expected behavior (returning pre-seeded data) in the header. This appears to be a low-risk change in the series' systematic decoupling effort, though reviewers may want to confirm the random number quality requirements for the two use cases.
