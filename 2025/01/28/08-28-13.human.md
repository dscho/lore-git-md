This is a refactoring patch in Patrick Steinhardt's ongoing series to decouple the reftable library from Git's core infrastructure. The change replaces a call to Git's `sleep_millisec()` function with a direct use of `poll()` in the reftable stack implementation.

The patch is straightforward - it modifies the retry logic when reloading reftable stacks to use POSIX's `poll()` function directly rather than going through Git's compatibility wrapper. This continues the series' pattern of removing dependencies on Git-specific functions. The commit message notes there isn't a perfect POSIX millisecond sleep function, so `poll()` is used as the closest available alternative.

This appears to be a clean, mechanical change that maintains the same behavior while furthering the architectural goal of making reftable independent. The change is minimal (just one line modified) and focused, consistent with the careful, incremental approach seen throughout this series. Since it's part of a well-reviewed effort to improve reftable's portability, it seems likely to be uncontroversial.
