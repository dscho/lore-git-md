This is a cleanup patch in the zlib-ng performance optimization series, removing an unnecessary compatibility define. 

The patch drops the `z_const` macro that was being defined before including zlib.h. This macro was originally added as part of compatibility code for `uncompress2()` (which was removed in the previous patch), but the commit message notes there's no clear reason why this define was kept or made public. The author argues that not marking parameters as `const` doesn't actually make them any less constant, so the define serves no useful purpose.

This is a straightforward removal of legacy code that's part of the larger effort to clean up zlib compatibility code while introducing zlib-ng support. The change is small and focused, removing just one line from git-compat-util.h. Since this is part of a well-reviewed series that's already gone through multiple iterations (v4), and the change aligns with the overall goal of removing obsolete zlib compatibility code, it appears to be a safe and justified cleanup.
