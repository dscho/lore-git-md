This is a refactoring patch that's part of the larger reftable decoupling effort, specifically targeting the removal of Git-specific I/O utilities. The patch replaces the single remaining `read_in_full()` call in the reftable library with a direct implementation using POSIX `read()`, moving the code closer to being fully independent of Git's core infrastructure.

The key technical changes involve:
- Replacing `read_in_full()` with a manual read loop in `fd_read_lines()`
- Preserving the same error semantics but omitting `EWOULDBLOCK` handling since reftable doesn't use non-blocking I/O
- Maintaining the existing error reporting through `REFTABLE_IO_ERROR`
- Adding explicit size tracking with `total_read` to match the original behavior

The implementation carefully considers edge cases:
- Handles `EAGAIN` and `EINTR` by continuing the read loop
- Validates each read operation's return value
- Maintains the null-termination of the buffer
- Preserves the existing error paths

This change is part of a systematic effort to eliminate Git dependencies, with the commit message clearly explaining the rationale for not porting over the full `read_in_full()` functionality (specifically the `EWOULDBLOCK` handling). The patch appears well-contained and focused, with no apparent impact on functionality while making progress toward the series' goal of complete decoupling.
