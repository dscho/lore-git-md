Refactoring patch for Rust bindings infrastructure. This is the first of four patches in v8 of the series implementing Rust bindings for Git's C library.

The patch splits initialization and exit code from `common-main.c` into two new files (`common-exit.c` and `common-init.c`) to make `libgit.a` more self-contained. Currently, external users linking against `libgit.a` must include many extra objects because `common-main.o` contains both the shared exit handler and the Git command entry point. The split allows external users to access Git's initialization and exit handling without pulling in the entire command infrastructure.

The change moves `common_exit()` and `check_bug_if_BUG()` to `common-exit.c` and extracts initialization code into a new `init_git()` function in `common-init.c`. Both new files are added to `LIB_OBJS` so they're included in `libgit.a`. The patch follows up on two previous attempts to solve similar problems for fuzz tests and unit tests, though those were addressed differently at the time.

The implementation looks clean and well-motivated, with all the expected build system updates (both Makefile and meson). The commit message provides good historical context and rationale. This foundational change enables the subsequent patches in the series to build Rust bindings against a more modular `libgit.a`.
