This is part of the ongoing reftable library decoupling effort, specifically addressing error handling strategy in record initialization. The patch converts a `BUG()` call in `reftable_record_init()` to return an error code (REFTABLE_API_ERROR) when encountering unknown record types, rather than aborting. This change removes another Git-specific dependency while making the error handling more library-appropriate.

The modification affects several key reftable components that initialize records - block iteration, merged table operations, and reader functionality. Each caller is updated to check the new return value. The test suite is also adjusted to verify successful initialization via the new error-checking pattern.

This continues the series' pattern of replacing Git-specific behaviors with portable alternatives, here addressing the architectural concern that library code shouldn't terminate the host process. The change is straightforward but important for reftable's standalone viability, particularly since record initialization is a fundamental operation. All modifications follow the established pattern of propagating errors rather than aborting, maintaining consistency with the series' earlier I/O and memory handling changes.
