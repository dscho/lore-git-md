Performance optimization enabling zlib-ng as an alternative zlib backend, part of the 10-patch series introducing zlib-ng support. This patch (8/10) implements the core build system integration for linking against zlib-ng's optimized implementations while maintaining compatibility with standard zlib.

The patch adds a new build option (`ZLIB_NG=1` for Makefile, `zlib_backend=zlib-ng` for meson) that redefines zlib symbols to use zlib-ng's `zng_`-prefixed versions when available. This allows using zlib-ng's optimized implementations (SSE2/AVX2 etc.) without requiring system-wide zlib replacement. The implementation shows significant performance gains - a 25% speedup in `git cat-file --batch --batch-all-objects` benchmarks (52.085s → 40.324s).

Key technical changes:
- Adds `HAVE_ZLIB_NG` define and conditional compilation paths in `compat/zlib-compat.h`
- Implements symbol remapping for all major zlib functions (deflate/inflate family)
- Maintains fallback to standard zlib when zlib-ng is unavailable
- Updates both Makefile and meson build systems with new configuration options
- Preserves existing compatibility shims for older zlib versions
- Adds zlib backend selection to meson summary output

The patch follows the series' established pattern of handling zlib-ng differences through the compatibility layer, now completing the build system integration after previous patches reorganized headers and consolidated shims. It maintains backward compatibility while providing a clean path to opt into the performance benefits.
