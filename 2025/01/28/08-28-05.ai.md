This is a refactoring patch in the ongoing reftable decoupling series, specifically replacing Git's `COPY_ARRAY()` helper with direct `memcpy()` calls. The change is part of the larger effort to make the reftable library fully independent from Git's core infrastructure.

The patch modifies a single location in `reftable/record.c` where object record offsets are copied. The key changes are:
1. Replaces `COPY_ARRAY()` with an equivalent `memcpy()` operation
2. Adds an explicit check for zero-length arrays before copying
3. Maintains the same memory safety by using `sizeof(*src->offsets)` for the element size calculation

The commit message is minimal but clear about the motivation - reducing Git library dependencies. The change appears straightforward and mechanically correct, though it's worth noting this introduces a small amount of code duplication (the array copy pattern) that was previously handled by the shared `COPY_ARRAY()` utility. This tradeoff is consistent with the series' overall goal of eliminating Git dependencies even at the cost of some localized duplication.

The patch fits cleanly into the broader context of the reftable decoupling work, following the pattern seen in earlier patches of systematically replacing Git-specific utilities with direct system calls or reimplementations.
