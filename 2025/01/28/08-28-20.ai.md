This is patch 19/20 in Patrick Steinhardt's series to decouple the reftable library from Git's core infrastructure. The patch completes the transition from using Git's git-compat-util.h to the new standalone compat/posix.h header for POSIX emulation functionality.

The key change is replacing the inclusion of git-compat-util.h with compat/posix.h in reftable/system.h, while keeping git-compat-util.h in system.c where Git-specific functionality remains. This finalizes the architectural separation between reftable's portable core and Git-specific glue code, with only system.h/system.c now containing Git-specific dependencies that external users would need to provide.

The patch maintains the series' pattern of careful, incremental changes - it's a small diff (4 lines changed) that builds on the extensive preparatory work in previous patches to ensure no behavioral regressions. The commit message clearly explains the motivation (enabling standalone use by projects like libgit2) and current limitations (system.h/system.c still being Git-specific).

This represents a major milestone in the reftable portability effort, as it leaves the library with a clean separation between its portable core and Git integration layer. The changes are straightforward and unlikely to be controversial given the thorough preparation and testing throughout the series.
