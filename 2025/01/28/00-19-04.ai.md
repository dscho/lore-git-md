Feature implementation for the Rust bindings infrastructure, specifically extending the `libgit-sys` crate with config API bindings. This patch (v7 3/4) builds on the established FFI infrastructure to expose Git's config handling capabilities to Rust callers through the `libgit-sys` crate.

The changes introduce FFI wrappers for core config operations: allocation/destruction of config sets (`libgit_configset_alloc/free`), file loading (`libgit_configset_add_file`), and value retrieval (`libgit_configset_get_int/string`). The implementation follows the established pattern of prefixing symbols with `libgit_` to avoid collisions with libgit2. The patch maintains type safety by treating the config_set` struct as opaque in Rust (via a zero-sized type with phantom data) while providing proper memory management through the exported alloc/free functions.

This work directly supports the planned higher-level Rust config interface mentioned as coming in the next patch (4/4). The commit message notes this is preparatory work, with testing deferred to the higher-level API that will exercise these bindings. The changes touch the same three files as previous `libgit-sys` work: the public symbol export C/H files and the Rust `lib.rs` binding definitions.

The implementation appears technically sound, building on the already-reviewed FFI patterns established earlier in the series. The patch carries co-authorship from Calvin Wan, suggesting collaborative development. As part of the v7 series that has already received maintainer approval for the overall approach, this incremental addition seems unlikely to raise new concerns, though reviewers may scrutinize the specific choice of which config functions to expose at this stage.
