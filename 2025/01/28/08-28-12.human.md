This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git's core infrastructure. Patch 11/20 introduces a new `reftable_rand()` function to replace direct calls to Git's `git_rand()`, continuing the pattern of creating reftable-specific implementations of system functions.

The change is straightforward: it wraps Git's random number generator in a new reftable-specific interface, with the intention that callers could eventually provide their own implementation. The patch updates two existing callsites in the reftable stack code - one for retry delays during stack reloading, and another for generating unique filenames.

This appears to be a clean, mechanical change that fits well with the series' goal of making reftable portable. The implementation currently still relies on Git's random number generator internally, but the new abstraction layer makes it clear where future work could plug in alternative implementations. The change is small and focused, with no obvious issues in the implementation.
