Refactoring patch in the reftable decoupling series, replacing Git's `st_mult()` with portable overflow-checked allocation helpers.

This patch (8/20 in v2) continues the systematic removal of Git-specific dependencies from the reftable library. It replaces three macros (`REFTABLE_ALLOC_ARRAY`, `REFTABLE_REALLOC_ARRAY`, and the inline `reftable_alloc_grow`) that previously used Git's `st_mult()` for safe multiplication with overflow checking. The new implementation introduces a `reftable_alloc_size()` helper that performs manual overflow checking and returns an error rather than dying on overflow, while maintaining the same safety guarantees.

Key technical changes:
- New `reftable_alloc_size()` function checks for overflow in `nelem * elsize` calculations
- Allocation macros now set `errno = ENOMEM` and return NULL on overflow
- `reftable_alloc_grow()` preserves existing pointer on allocation failure
- All changes maintain the same overflow safety as `st_mult()` but with error returns
- Changes affect array allocation patterns throughout reftable (though this patch only modifies the interface)

The patch cleanly separates the allocation logic from Git's infrastructure while preserving the safety properties. This is part of the broader effort to make reftable usable as a standalone library, with each patch systematically removing another Git-specific dependency. The implementation appears thorough and maintains the expected error handling behavior.
