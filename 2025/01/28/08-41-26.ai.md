Performance optimization series introducing zlib-ng support as an alternative zlib backend. This is the cover letter for the complete 10-patch series that has now gone through multiple review iterations (v4).

The series enables Git to use zlib-ng's optimized implementations (with SSE2/AVX2 optimizations) while maintaining compatibility with standard zlib. Benchmarks show a ~25% speedup in object reading operations (52.085s → 40.324s in `git cat-file --batch --batch-all-objects`). The implementation handles zlib-ng's `zng_`-prefixed symbols and constness differences via a new "compat/zlib.h" header that abstracts the differences between the two backends.

Key technical aspects include:
- Header reorganization moving zlib includes from git-compat-util.h to git-zlib.h
- Special handling for reftable via reftable/system.h to maintain library independence
- Compatibility shims for zlib-ng's symbol prefixes and constness differences
- Removal of obsolete compatibility shims (uncompress2, z_const)
- Build system integration via ZLIB_NG=1 (Makefile) or zlib_backend=zlib-ng (meson)
- CI testing via Alpine Linux (chosen for zlib-ng-dev package availability)

The series has been thoroughly reviewed with all feedback incorporated, including:
- Justin Tobler's suggestions about no-op behavior documentation and const-cast explanation
- Final verification of CI configuration by Karthik Nayak
- Confirmation that the changes maintain backward compatibility while providing significant performance benefits

The implementation is now complete with all technical and administrative issues resolved, ready for inclusion in the next release cycle.
