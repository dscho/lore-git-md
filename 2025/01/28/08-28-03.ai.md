This is part of the ongoing reftable library refactoring effort to achieve full portability and independence from Git's core infrastructure. The patch replaces Git's `write_in_full()` utility with a reftable-specific implementation `reftable_write_data()` in the stack module, continuing the systematic removal of Git dependencies.

The new implementation handles partial writes and retries on EAGAIN/EINTR errors, similar to Git's version but now living in the reftable namespace. It maintains the same error semantics (returning REFTABLE_IO_ERROR on failure) while eliminating the Git dependency. The change affects three key write operations in the stack implementation: writing table data, committing additions, and compacting ranges.

This is a straightforward mechanical conversion that follows the pattern established in earlier patches of the series. The implementation appears correct, with careful attention to maintaining the existing error handling behavior. As with other I/O utility replacements in this series, the change is motivated by the goal of making reftable usable as a library outside of Git's ecosystem, particularly for projects like libgit2. The patch fits cleanly into the larger architectural effort to decouple reftable from Git's infrastructure while preserving functionality.
