This is part of the foundational Rust bindings for Git's C library, specifically introducing the `libgit-sys` crate as part of the v8 series that has now concluded. The patch establishes the build system integration and initial FFI bindings for Git's user agent string functions, serving as a proof of concept for the Rust-C interop approach.

The key technical elements include:
- Makefile integration with `INCLUDE_LIBGIT_RS` flag to conditionally build Rust components
- Symbol visibility management via `public_symbol_export.[ch]` with `libgit_` prefix to prevent collisions
- Build process that combines Git's static libraries (`libgit.a`, `libreftable.a`, `xdiff/lib.a`) into `libgitpub.a`
- Initial FFI bindings for `git_user_agent()` and `git_user_agent_sanitized()`
- Rust test cases verifying the user agent string format
- Cargo build system configuration with dependencies on `libz-sys` and build tools

The implementation demonstrates the core FFI safety approach that will be used throughout the bindings, including proper symbol visibility control and type-safe wrappers. The build system changes are designed to maintain compatibility with both Makefile and meson builds while keeping Rust components optional. This patch represents the low-level foundation that subsequent patches will build upon to expose more Git functionality to Rust.
