Refactoring patch in the reftable decoupling series. This is patch 5/20 in Patrick Steinhardt's effort to make the reftable library fully independent from Git's core infrastructure.

The patch removes a dependency on Git's `BUG()` macro from `reftable_record_init()`, which previously would abort the program when encountering an unknown record type. Instead, the function now returns an error code (REFTABLE_API_ERROR) in such cases. This change better fits library code that shouldn't terminate the calling program, and furthers the goal of making reftable usable as a standalone library.

The modification is straightforward - the function signature changes from void to int, and all callers are updated to check the return value. The patch includes updates to several reftable implementation files and corresponding test adjustments. This continues the pattern seen in earlier patches of systematically replacing Git-specific functionality with reftable-native equivalents while maintaining the same error semantics.

The change appears well-contained and properly tested, with no obvious issues in the implementation. It's a logical step in the broader effort to decouple reftable from Git's internals.
