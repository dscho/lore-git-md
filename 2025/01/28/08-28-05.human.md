This is a refactoring patch as part of the larger reftable decoupling effort. It's the 4th patch in a 20-part series aimed at making the reftable library fully independent from Git's core infrastructure.

The change is straightforward: it replaces a single use of Git's `COPY_ARRAY()` macro with direct `memcpy()` in the reftable record handling code. The motivation is to reduce dependency on Git-specific utilities, aligning with the series' broader goal of making reftable usable as a standalone library.

The implementation appears correct - it maintains the same behavior while adding a safety check for zero-length copies. This is a small but logical step in the systematic removal of Git dependencies that the series is undertaking. The patch follows the established pattern seen in previous conversions, though it's worth noting this particular change is quite localized and mechanical compared to some of the more complex I/O handling changes elsewhere in the series.
