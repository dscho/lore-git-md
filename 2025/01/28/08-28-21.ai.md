This is the final patch (20/20) in Patrick Steinhardt's series to decouple the reftable library from Git's core infrastructure, focusing on build system integration. The patch excludes reftable sources from Coccinelle checks since the library doesn't use Git's common helpers and the semantic patches could generate false positives. The change is minimal one-line Makefile modification that adds `reftable/%` to the filtered-out paths for Coccinelle processing.

The patch completes the series' goal of making reftable standalone by removing the last vestige of Git-specific tooling. This follows logically from the architectural separation achieved in previous patches, where reftable was already using its own POSIX compatibility layer rather than Git's helpers. The change is low-risk as it only affects static analysis tooling, not runtime behavior.

Key technical details for future reference:
- Modified file: `Makefile`
- Filter pattern added: `reftable/%` alongside existing `$(THIRD_PARTY_SOURCES)`
- Justification: Avoid false positives from Coccinelle rules targeting Git-specific patterns
- Build system impact: Coccinelle will now skip all `.c` files under `reftable/`

This patch represents the culmination of the series' careful, incremental approach - each change small and focused, with this final touch ensuring the standalone reftable library won't trigger irrelevant tooling checks meant for Git's core code.
