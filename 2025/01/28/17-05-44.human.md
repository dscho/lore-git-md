This is a technical discussion in Patrick Steinhardt's reftable decoupling series, specifically about patch 01/19 which replaces `read_in_full()` with direct `read()` calls. Junio Hamano raises two concerns about the implementation: the `off_t` to `size_t` conversion safety and the handling of `EAGAIN` errors. Patrick confirms both are safe in this context - the size conversion is guarded by a negative check, and `O_NONBLOCK` isn't used in reftable so simplified error handling suffices. The exchange shows careful attention to portability details as the reftable library is separated from Git's core infrastructure. This is part of the larger effort to make reftable truly standalone while maintaining correctness.
