This is the final patch in the Rust bindings series (v8 4/4), introducing the higher-level `libgit` crate that provides idiomatic Rust wrappers around the FFI bindings from `libgit-sys`. The patch completes the Rust infrastructure by adding safe, RAII-style interfaces for working with Git's configset API.

Key technical details for future reference:
- The `ConfigSet` struct wraps the C `libgit_config_set` pointer with Rust's ownership model, implementing `Drop` to automatically free resources
- Methods like `get_int()` and `get_string()` handle C-to-Rust type conversion and error cases properly (returning `Option` types)
- The implementation demonstrates proper FFI safety practices:
  - Uses `CString` for string conversions
  - Manages memory ownership (freeing xstrdup'd strings from C side)
  - Provides RAII guarantees
- Test coverage verifies config precedence rules and basic functionality
- Build system integration adds `libgit-rs` alongside `libgit-sys` when `INCLUDE_LIBGIT_RS` is set
- The crate follows Rust packaging conventions with proper `Cargo.toml` and dependency specifications

The patch builds on the configset API exposed in v8 3/4, showing how the lower-level FFI bindings can be wrapped safely. It completes the series' goal of providing both direct C bindings (`libgit-sys`) and idiomatic Rust interfaces (`libgit`). With this addition, the Rust infrastructure is now fully functional while maintaining safety through careful FFI design.
