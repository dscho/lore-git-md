This is part 18/20 of Patrick Steinhardt's series to refactor the reftable library for portability, specifically splitting out POSIX-emulation functionality from Git-specific code.

The patch extracts all POSIX-compatibility definitions and implementations from `git-compat-util.h` into a new `compat/posix.h` header. This includes:
- POSIX feature test macros (_XOPEN_SOURCE etc.)
- Platform-specific header includes and definitions
- POSIX function replacements (time, mkdir, setitimer etc.)
- File system operations (stat, fstat, lstat)
- Network/socket APIs
- Memory mapping functions
- String and memory utilities
- Sorting functions
- Various compatibility macros

The motivation is to separate the two concerns mixed in `git-compat-util.h`: providing a POSIX-like interface on non-POSIX platforms versus providing Git-specific low-level functionality. This separation is key for the reftable library which needs the POSIX emulation but wants to avoid Git dependencies.

The patch is mechanically sound - it moves 541 lines to the new header while removing 529 lines from the original, maintaining all functionality. This continues the architectural pattern seen in earlier patches of the series to create clean boundaries between portable interfaces and Git internals. The change is well-contained with no behavioral impact, just reorganization of existing code.
