Refactoring patch in the reftable decoupling series, replacing Git-specific sleep function with direct poll() call.

This patch continues Patrick Steinhardt's systematic removal of Git dependencies from the reftable codebase. It replaces the `sleep_millisec()` helper function with a direct call to `poll()` in the reftable stack implementation. The change appears in the retry logic when reloading reftable stacks, where the code needs to sleep with millisecond precision between attempts.

The commit explains this is necessary because while poll() isn't the most semantically clear way to sleep (it's normally used for I/O multiplexing), it's the most portable POSIX-compliant way to achieve millisecond sleeps. The patch maintains identical behavior - the sleep duration calculation using `reftable_rand()` remains unchanged, only the underlying implementation differs.

This change follows the series' pattern of removing dependencies on Git's utility functions in favor of direct POSIX calls. The simple one-line change is well-contained and unlikely to introduce regressions, though it does highlight the ongoing tension between code clarity and portability in the decoupling effort. The patch builds on previous work abstracting random number generation (now using `reftable_rand()`) and continues moving toward a fully self-contained reftable implementation.
