Refactoring patch for better library isolation in Git's Rust bindings effort. This is part of the ongoing work to create Rust bindings for Git's C library, specifically addressing how initialization and exit code is organized.

Josh Steadmon splits Git's common initialization and exit code into separate files (`common-exit.c` and `common-init.c`) to make `libgit.a` more self-contained. Currently, external users linking against `libgit.a` must pull in many extra objects due to tangled dependencies between `common-main.o` (containing both main() and common_exit()) and other parts of Git. The change allows Rust bindings and other external users to access Git's initialization and exit routines without needing the full command-line interface machinery.

The patch moves `common_exit()` and `check_bug_if_BUG()` to `common-exit.c`, and extracts initialization code into `init_git()` in `common-init.c`. Both new files are added to `LIB_OBJS` so they're included in `libgit.a`. The changes maintain all existing behavior while making the code more modular.

The commit message notes this approach was previously considered for fuzz/unit tests but solved differently, and now serves the Rust bindings effort. Junio Hamano helped with the changes, suggesting this is a well-vetted approach. The patch is part of v7 of the Rust bindings series, which has already addressed major technical concerns and is in final refinement stages.
