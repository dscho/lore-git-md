Bugfix for filter-repo's config parsing. This patch addresses a crash that occurs when processing multi-line configuration values in filter-repo. The root cause is that the tool uses `git config --list` output without proper handling of newlines in values, which can occur in certain config entries.

The fix switches to using `git config --list --null` which properly handles multi-line values by using NUL delimiters. This matches Git's recommended approach for programmatic parsing of config values. The patch includes a simple test case that reproduces the crash before the fix.

The email notes this is a known issue with multiple GitHub PRs proposing alternative solutions, suggesting the problem affects real users. The change appears straightforward and well-motivated, though the test coverage could potentially be expanded to verify more complex multi-line scenarios. This seems like a clear improvement to filter-repo's robustness when dealing with real-world git config files.
