This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git's core infrastructure (patch 9/20 in v2). The patch standardizes big-endian conversion functions within the reftable codebase by:

1. Removing Git-specific `put_be*`/`get_be*` functions from reftable/basics.c
2. Introducing a new set of reftable-specific inline functions in basics.h for 16/24/32/64-bit conversions with consistent `reftable_` prefix
3. Updating all callers across the reftable codebase to use the new functions
4. Expanding test coverage to include 32-bit and 64-bit variants

The changes are mechanical but thorough, touching core reftable components like block handling, reader/writer logic, and record encoding. The new functions maintain the same behavior but use `void*` parameters rather than `uint8_t*` for slightly more flexible typing. Test coverage is expanded to verify all bit-width conversions work correctly.

This continues the series' pattern of systematically replacing Git-specific functionality with reftable-owned implementations, moving toward full portability. The changes are straightforward with no apparent behavioral impact, just consistent naming and complete test coverage for the conversion utilities.
