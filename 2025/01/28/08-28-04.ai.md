This is part of the ongoing reftable library decoupling effort, specifically addressing memory mapping functionality. The patch replaces Git's `xmmap()` with direct `mmap()` calls in the reftable blocksource implementation, continuing the series' work to remove Git-specific dependencies.

The key changes in this patch are:
1. Replacing the fatal `xmmap()` wrapper with direct `mmap()` calls that properly handle errors by returning REFTABLE_IO_ERROR when mapping fails
2. Fixing error propagation in `reftable_block_source_from_file()` to properly bubble up the mmap failure rather than always returning success
3. Maintaining the same memory mapping semantics (private, file-backed) while removing the Git-specific implementation

The implementation carefully preserves the existing behavior while making it more robust by:
- Still using the system's mmap (or Git's emulated version on platforms without mmap)
- Properly cleaning up resources (file descriptor and allocated memory) on error
- Keeping the same protection flags (PROT_READ) and mapping type (MAP_PRIVATE)

This change is part of the systematic replacement of Git I/O utilities discussed in the thread, following the earlier conversion of read/write operations.
