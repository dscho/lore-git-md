This is part of Patrick Steinhardt's ongoing refactoring effort to make the reftable library portable and independent from Git's core infrastructure (patch 18/20 in the series). The change splits the POSIX-emulation functionality out of `git-compat-util.h` into a new `compat/posix.h` header, separating it from Git-specific code.

The patch moves 541 lines of POSIX-related definitions and compatibility wrappers (file operations, time functions, socket handling, etc.) to the new header while keeping Git-specific utilities in the original file. This is a key step in the reftable decoupling effort since the library needs POSIX emulation but shouldn't depend on Git internals.

The implementation looks thorough - it preserves all the existing platform-specific handling (Windows, Solaris, glibc quirks) while creating a cleaner boundary between portable system interfaces and Git's own utilities. The change is mechanical but well-contained, with test coverage presumably handled at the series level. This continues the pattern seen in earlier patches of systematically untangling dependencies to make the reftable library more self-contained.
