This is patch 3/10 in the zlib-ng performance optimization series, focusing on header reorganization to prepare for zlib-ng integration. The patch introduces a new `compat/zlib-compat.h` header that serves as an indirection layer for zlib includes, replacing direct `<zlib.h>` inclusions in `git-compat-util.h` and reftable code. This is a foundational change that enables the subsequent zlib-ng support by creating a single point where zlib implementation differences can be abstracted.

The implementation is straightforward - the new header simply includes the system's `<zlib.h>` while providing a namespaced include guard. The patch carefully avoids naming it `zlib.h` to prevent include path precedence issues. Changes are minimal but strategic, touching core infrastructure (`git-compat-util.h`) and reftable code that needs to maintain library independence.

This is part of the larger effort to enable zlib-ng's optimized implementations while maintaining standard zlib compatibility, with the series showing ~25% speedup in object reading operations. The patch follows good practices by keeping the change focused and mechanical, making it a clean preparatory step for the more substantial zlib-ng integration that follows in later patches.
