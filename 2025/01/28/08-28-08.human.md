This is part of the ongoing reftable library refactoring effort to make it fully portable and independent from Git's core infrastructure. The patch continues the systematic replacement of Git-specific error handling (via `BUG()`) with library-appropriate error returns (using `REFTABLE_API_ERROR`).

The changes focus on three areas:
1. Removing `BUG()` calls in reference counting functions (`reftable_reader_{inc,dec}ref()`), where invalid usage would already lead to undefined behavior
2. Converting `BUG()` in the indexed table iterator's seek operation to return an error code
3. Replacing `BUG()` with error returns for invalid block sizes and record types in the writer

This follows the pattern established in earlier patches of the series, where Git-specific behaviors are being systematically replaced with portable alternatives. The changes are straightforward and maintain the same safety properties while making the library more suitable for standalone use. The patch appears well-contained and consistent with the series' overall goal of decoupling reftable from Git's internals.
