This is a refactoring patch in the ongoing reftable library decoupling effort, specifically addressing error handling in record comparison.

The patch modifies `reftable_record_cmp()` to return an error code when comparing records of differing types, rather than aborting with `BUG()`. This change makes the behavior more appropriate for library code by allowing callers to handle errors gracefully. The comparison result is now passed back through an out-parameter.

The change ripples through several call sites:
- `pq_less()` and `merged_iter_pqueue_remove()` in the priority queue implementation now handle potential errors
- The merged iterator's queue operations propagate errors up the call chain
- All unit tests are updated to check error returns and use the new comparison pattern

Key technical details:
- The function signature changes from `int cmp(a,b)` to `int err(a,b,&cmp)`
- Error case: returns -1 (REFTABLE_API_ERROR) for type mismatches
- Success case: returns 0 and sets `*cmp` to the comparison result
- Affects record types: refs, logs, objects, and index entries
- Tests verify both error cases and comparison ordering

This continues the series' pattern of replacing Git-specific behaviors (here `BUG()`) with library-appropriate error handling, maintaining the architectural goal of making reftable usable outside Git while preserving functionality. The changes are thorough, with corresponding test updates showing careful attention to maintaining correctness during the transition.
