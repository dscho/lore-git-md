Platform compatibility patch in Patrick Steinhardt's reftable decoupling series.

This patch standardizes header inclusion paths across Git's compatibility layer, addressing inconsistent approaches that made it difficult to trace include origins. The changes:

1. Remove the Windows-specific `-Icompat` compiler flag and update all `#include` directives in compat/ files to use project-root-relative paths (e.g., `#include "git-compat-util.h"` instead of `#include "../git-compat-util.h"`)

2. Update 39 files across the compatibility layer, primarily changing:
   - Core utility includes (git-compat-util.h)
   - Windows-specific headers (win32.h, lazyload.h)
   - Subsystem headers (fsmonitor, pthread, win32mmap)
   - Utility function headers (strbuf, strlcpy, nonblock)

3. Modify config.mak.uname to remove the redundant include path, completing the standardization.

The change serves both immediate goal of clarity (making include origins obvious) and future work (preparing for splitting mingw.h/msvc.h). As part of the larger reftable decoupling effort, this continues replacing Git-specific assumptions with portable interfaces, though focused here on build system rather than runtime behavior. The mechanical nature of the changes and comprehensive file coverage suggest low risk of functional impact.
