Initial refactoring for Rust bindings infrastructure.

This is the first patch in the final v8 series implementing Rust bindings for Git's C library. It splits initialization and exit code from `common-main.c` into new files `common-exit.c` and `common-init.c`, making these components available in `libgit.a` without requiring the full Git executable's dependencies. The change enables external users to link against Git's core functionality while avoiding symbol conflicts and unnecessary dependencies.

The patch moves two key components:
1. `common_exit()` and `check_bug_if_BUG()` to `common-exit.c`
2. Main initialization logic into new `init_git()` function in `common-init.c`

This refactoring was previously considered for fuzz testing but is now motivated by the need to make `libgit.a` more self-contained for Rust bindings. The commit references prior discussions about similar splits for testing purposes, though those were resolved differently. Build system integration updates ensure the new files are included in both Makefile and meson builds.

The changeset is cleanly separated with minimal impact on existing code - `common-main.c` is reduced to just the main entry point that calls the new initialization function. All moved functionality remains behaviorally identical, just organizationally separated for better library usability. This foundational change enables the subsequent Rust binding work in the series while maintaining build system compatibility.
