Refactoring patch in the reftable decoupling series. This is patch 14/20 in Patrick Steinhardt's ongoing effort to make the reftable library fully independent from Git's core infrastructure.

The change replaces Git's `UNUSED` macro with a new `REFTABLE_UNUSED` macro throughout the reftable codebase. The new macro provides a weaker guarantee - it suppresses unused parameter warnings but doesn't error if a marked parameter is actually used. This simplification avoids needing compiler-specific logic while still serving the primary purpose of silencing warnings.

The patch touches several key reftable components (blocksource, iterator, record handling, writer) but is purely mechanical - each instance of `UNUSED` is replaced with `REFTABLE_UNUSED(x)` where x is the parameter name. The implementation is straightforward and maintains the existing behavior while removing another Git-specific dependency.

This continues the series' pattern of systematically replacing Git infrastructure with reftable-specific equivalents. The change is well-contained and unlikely to be controversial, though reviewers may want to verify the weaker guarantee doesn't mask any real issues in practice.
