This is a build system patch that makes the CSPRNG (cryptographically secure pseudo-random number generator) backend configurable in the Meson build system, continuing Patrick Steinhardt's series converting Git's build with Meson (now at patch 8/11).

The patch adds a new `csprng_backend` configuration option to `meson_options.txt` with several possible values ('auto', 'arc4random', 'arc4random_bsd', 'getrandom', 'getentropy', 'rtlgenrandom', 'openssl', 'urandom'). The implementation follows the same pattern as other backend configurations in the series, with detection logic that checks for each backend in order of preference (from most secure/fastest to least) when set to 'auto'. The selected backend is then added to the build summary output alongside other configured backends.

Key technical details include:
- Backend detection now properly handles explicit backend selection (not just auto-detection)
- The openssl dependency check now includes CSPRNG needs
- Windows' RtlGenRandom is properly detected via ntsecapi.h
- The implementation maintains the same security hierarchy as the original (arc4random variants first, falling back to getrandom/getentropy, then platform-specific options, with openssl and urandom as last resorts)
- All existing functionality is preserved while making the backend properly configurable

This continues the series' pattern of methodically converting build components while maintaining feature parity with the Makefile system. The change is straightforward and well-contained, following the established approach for backend configuration seen in earlier patches for HTTPS and SHA backends.
