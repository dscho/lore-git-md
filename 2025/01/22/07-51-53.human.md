This is the second patch in a refactoring series to centralize refspec handling logic. The patch moves three query-related functions (`query_refspecs`, `query_refspecs_multiple`, and `query_matches_negative_refspec`) from `remote.c` to `refspec.c`, continuing the effort to consolidate refspec operations in one place.

The changes are purely organizational - no behavior is modified. The functions handle core refspec operations like checking if a ref matches negative refspecs and querying refspec mappings. The patch follows the same mechanical approach as the first in the series, with straightforward code relocation (123 lines added to refspec.c, 122 removed from remote.c) and corresponding header updates.

This continues the clean separation between refspec logic (now in refspec.[ch]) and remote-specific operations (remaining in remote.[ch]). The implementation looks solid, maintaining all existing functionality while improving code organization. The patch appears ready for review, though as an RFC it may still see adjustments based on maintainer feedback about the overall refactoring approach.
