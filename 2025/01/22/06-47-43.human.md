Bugfix for reflog regression in `git update-ref` affecting symbolic ref updates. Karthik Nayak confirms Jeff King's proposed one-line fix to remove an early return in `lock_ref_for_update()` when `REF_LOG_ONLY` is set. The regression, introduced in Git 2.48.1, caused incorrect `old_oid` recording in derived reflogs (like HEAD's) when updating branches referenced symbolically.

Nayak explains the original assumption behind the problematic code - that reflog-only updates only needed to capture the lock - was incorrect, as it skipped the crucial step of populating the `old_oid`. King's fix restores this behavior while maintaining the locking functionality. The change has been tested and doesn't break existing tests.

This appears to be a straightforward resolution to a significant regression affecting reflog integrity for symbolic reference operations. With the original author's confirmation of the fix's correctness, it seems ready for inclusion, likely warranting a fix release given the impact on fundamental reflog functionality.
