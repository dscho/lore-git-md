Brian Carlson reported a bug where stash reflog entries become inaccessible after converting from files-based ref storage to reftable format, though the underlying data appears intact. Karthik Nayak has confirmed the issue, noting that while `git for-each-ref` shows the stash commit exists in reftable storage, commands like `git stash show` fail to access it. This suggests the problem lies in the display layer rather than the migration itself. Nayak is investigating further, treating this as a high-priority follow-up. Both contributors emphasize this is valuable real-world feedback for the reftable migration effort, not a fundamental flaw in the design. The immediate focus is understanding why standard Git commands can't access properly migrated stash entries.
