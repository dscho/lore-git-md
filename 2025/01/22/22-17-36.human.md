Feature enhancement for pack-objects delta compression with performance implications. This is part 2/8 in a series introducing alternative name hash algorithms to improve delta compression when files with similar names but different parent directories would collide under the current hashing scheme.

Taylor Blau provides a review of Derrick Stolee's patch adding a `--name-hash-version` option to `git pack-objects`. The patch introduces two hash versions: version 1 (current behavior focusing on path endings) and version 2 (a more sophisticated component-based hash that considers directory structure). Blau confirms the technical implementation looks sound, noting particularly good test coverage and documentation.

The review highlights dramatic real-world performance improvements from version 2 - in one public repository (fluentui), pack size dropped from 440MB to 161MB while repack time improved from 728s to 142s. The patch includes appropriate safeguards, like forcing version 1 when writing bitmaps (since the bitmap format doesn't yet support version 2).

Blau offers only minor style nitpicks (brace placement) and one suggestion about consolidating validation logic, but overall approves the approach. The thread indicates this series is nearing readiness for merging, with version 2 clearly established as the preferred implementation. The remaining work appears to be bitmap format compatibility, noted as a future TODO.
