This is the first patch in a 3-patch series addressing reftable migration issues, specifically focusing on API cleanup. The patch marks `ref_transaction_update_reflog()` as static since it's only used within refs.c, addressing Junio C Hamano's observation about unnecessary API exposure. The function's documentation is preserved but moved to the implementation file.

Key technical details:
- Removes the declaration from refs.h while keeping the function in refs.c
- Moves the detailed function comment about reflog update ordering and committer info from header to implementation
- Maintains all existing functionality while reducing API surface area
- Part of a larger effort to harden reftable handling after corruption issues were found in large repositories

The change is straightforward and uncontroversial, having already been merged in previous iterations of the series. It serves as preliminary cleanup before the more substantive changes in subsequent patches that address integer overflow and writer state validation.
