Performance-focused follow-up in the batch remote removal discussion.

Jeff King (Peff) builds on Brian Carlson's performance analysis of batch remote removal, noting that config file updates also suffer from quadratic scaling when removing multiple remotes sequentially. He suggests that any implementation of multi-remote removal should process all operations in a single pass through both the config and refs, rather than internally looping through individual removals.

The email highlights two key points: first, that the config rewrite overhead compounds the performance problems already identified with packed-refs updates, and second, that the solution should address both aspects simultaneously. King also observes that `git config` itself could benefit from similar batching optimizations for section removal, though currently lacks this capability.

This moves the technical discussion forward by emphasizing the need for atomic, single-pass handling of both configuration and ref updates in any batch removal implementation. The note about `git config`'s limitations suggests the scope of the optimization opportunity may extend beyond just the remote removal command.
