This is a bugfix for a reflog regression in the refs backend. Karthik Nayak confirms Jeff King's proposed one-line fix to remove an early `REF_LOG_ONLY` return in `lock_ref_for_update()`, explaining that the original assumption about reflog-only updates only needing the lock was incorrect. The change properly populates the `old_oid` field in derived reflogs (like HEAD's) when updating symbolic references, fixing the issue Nika Layzell reported in Git 2.48.1.

The fix targets the files backend's reflog handling in `refs/files-backend.c`, specifically the interaction between symbolic reference updates and reflog entries. Karthik links to prior discussion showing the mistaken assumption that led to the problematic early return`. While the change appears straightforward, it affects core refs behavior during symbolic reference operations, so careful review is warranted given the regression's impact on reflog integrity.

The thread shows consensus that this fixes the immediate issue without test failures, though the original author of commit 297c09eabb (which introduced the regression) should verify the change doesn't break any intended behavior. The fix would likely be a candidate for a maintenance release once properly vetted by the refs subsystem maintainers.
