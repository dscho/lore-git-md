This is the final patch in a 3-part series addressing reftable corruption issues, specifically focusing on preventing invalid updates to index limits after records are written. The patch modifies `reftable_writer_set_limits()` to enforce that update index ranges can only be set before any records are written, preventing header/footer mismatches that could corrupt the reftable.

Key technical details:
- The function now returns REFTABLE_API_ERROR if called after writing begins, detected by checking the writer's `last_key` and `next` fields
- All callers in refs/reftable-backend.c, reftable/stack.c, and test files are updated to handle the new return value
- A new unit test (t_reftable_invalid_limit_updates) explicitly verifies the error case
- The reftable-error.h documentation is updated to clarify this new error condition

The change implements Patrick Steinhardt's suggestion for strict state validation while maintaining backward compatibility. This completes the series' goal of hardening the reftable migration path against corruption, particularly for repositories with large reflogs. The patch appears well-tested with comprehensive unit test coverage and careful handling of all call sites.
