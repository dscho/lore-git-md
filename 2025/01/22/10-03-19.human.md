Bugfix for reflog corruption in symbolic reference updates. This patch addresses a regression introduced in Git 2.48.1 where reflog entries for symrefs (like HEAD) were being created without the proper `old_oid` value. The issue stemmed from an overzealous performance optimization that skipped necessary processing for reflog-only updates.

Karthik Nayak's patch removes the problematic early return in `lock_ref_for_update()` that was causing the issue, restoring correct behavior for symref reflogs. The change is simple (just 3 lines removed) but important for maintaining reflog integrity. A new test case is added to prevent future regressions.

The fix has already been vetted by Jeff King, who originally identified the root cause. While the optimization being removed was intended to speed up reflog operations, the patch notes it wasn't essential to the original changes. This appears to be a straightforward and low-risk fix for a concrete bug affecting fundamental Git functionality.
