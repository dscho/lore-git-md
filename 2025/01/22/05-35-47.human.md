Refactoring patch in a completed series addressing reftable migration issues. This is the first of three patches that have already been reviewed and merged.

The patch marks `ref_transaction_update_reflog()` as static since it's only used within refs.c, addressing Junio C Hamano's observation about unnecessary API exposure. The function's important documentation about index field behavior is preserved by moving it to the public `ref_transaction_update()` API.

This is a straightforward cleanup that tightens the API surface while maintaining all functionality. The change is part of a larger effort to improve reftable reliability, particularly for repositories with large reflogs. Since this is part of a completed series where all technical concerns have been addressed, readers can safely focus on the later patches if they're interested in the substantive reftable improvements.
