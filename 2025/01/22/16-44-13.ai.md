This is a bug report regarding a regression in the reftable backend. Karthik Nayak reports that the `kn/reflog-migration-fix` commit (which was merged to 'next') is causing test failures in reftable mode, though the issue wasn't caught by CI initially. The problem was discovered when Derrick Stolee's macOS reftable builds started failing.

The commit in question fixed an issue with `git refs migrate` writing incorrect max_update_index values in reftable headers. While the fix worked for the files backend, it's now causing test failures in the reftable backend, specifically in t1400-update-ref when run with GIT_TEST_DEFAULT_REF_FORMAT=reftable.

Karthik notes that the CI didn't catch this issue, which they plan to investigate. For now, they recommend removing the commit from 'next' until the reftable-specific problem can be properly diagnosed and fixed. The email includes a link to the failing CI run that helped identify the regression.

This appears to be a case where a fix that worked for one ref backend (files) introduced problems in another (reftable), highlighting the challenges of maintaining multiple backend implementations. The immediate action is to revert from 'next' while the root cause is investigated.
