This is the final patch in a series implementing the removal of legacy remote configuration mechanisms via the `WITH_BREAKING_CHANGES` build flag. It specifically targets the deprecation of the `branches/` and `remotes/` directory-based remote configuration methods, which were superseded by config-based remotes nearly 20 years ago.

The patch:
1. Documents the removal in BreakingChanges.txt with historical context and rationale
2. Updates repository-layout documentation to mark these as deprecated
3. Implements the actual removal behind the breaking changes flag by:
   - Adding warning messages when these legacy paths are accessed
   - Conditionally compiling out the legacy code paths
   - Updating test suite to skip legacy tests when flag is set

Key technical details:
- Adds `warn_about_deprecated_remote_type()` function to notify users
- Uses `#ifndef WITH_BREAKING_CHANGES` guards around legacy code
- Updates multiple test scripts (t5505, t5510, t5515, t5516) to handle both legacy and new behavior
- Documents the 20-year deprecation timeline in BreakingChanges.txt

The patch follows the established pattern from earlier in the series, maintaining backward compatibility by default while providing a clean removal path when the breaking changes flag is enabled. It completes the infrastructure work started in earlier patches by applying it to these specific legacy features.
