This is a refactoring patch series aiming to centralize refspec-related logic. The series responds to a previous observation that refspec code is currently scattered across multiple header files, particularly split between remote.[ch] and refspec.[ch].

The proposal moves several functions dealing with refspecs from remote.c to refspec.c, creating a more logical organization. The author notes there are some borderline cases (like `get_fetch_map()` and `match_push_refs()`) that contain both refspec and remote logic, and is explicitly seeking feedback on whether these should be moved as well.

The changes are mechanical relocations with no intended behavior changes - 203 lines added to refspec.c offset by 201 removed from remote.c. The series appears well-scoped and focused on code organization, though the RFC nature suggests the author is particularly interested in discussion about those borderline functions before finalizing the changes.
