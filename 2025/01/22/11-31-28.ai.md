This is the final patch series in the effort to remove legacy "branches/" and "remotes/" reference naming, marking their deprecation for Git 3.0. The series builds on extensive prior discussion and implementation work, now adding migration instructions to the warning messages and final documentation updates.

The v4 changes focus on improving user communication about the deprecation:
- Added clear migration instructions to the warning messages, suggesting `git remote rename` as the path forward
- Refactored warning messages into a shared function to ensure consistency
- Further clarified the deprecation rationale in BreakingChanges.txt
- Maintained all prior infrastructure work including CI job repurposing and conditional compilation

The technical implementation remains focused on remote.c and builtin/remote.c, with warning messages now triggered when accessing either deprecated path. Test coverage in t5505 verifies the migration path behavior, while other tests are updated to handle the new warnings. The series demonstrates Git's careful approach to breaking changes, providing clear migration paths and ample warning before removal.

Key files modified:
- Documentation updates in BreakingChanges.txt and gitrepository-layout.txt
- Warning infrastructure in remote.c with new warn_about_deprecated_remote_type()
- CI configuration in .github/workflows and .gitlab-ci.yml
- Build system support across Makefile, CMake and Meson
- Test updates in t55* test scripts

The series appears ready for merging, having addressed all prior feedback and demonstrating comprehensive test coverage. It represents the culmination of a long-planned deprecation process for these 20-year-old legacy features.
