This is a bugfix for Git's trace2 analytics system, addressing a segmentation fault that occurs when processing empty/valueless config values. The patch is part of an already-reviewed v2 series that has received positive feedback from core maintainers.

The fix modifies multiple trace2 targets (event, normal, perf) to properly handle NULL config values by:
1. Adding NULL checks before processing values in trace2.c
2. Updating output formats to conditionally include values only when non-NULL
3. Adding test coverage in t0210-trace2-normal.sh

Key technical changes include:
- Modified redact_arg() handling in trace2.c to skip NULL values
- JSON output format in tr2_tgt_event.c now omits "value" field when NULL
- Normal and perf targets adjusted to format output differently for NULL values
- New test case verifies empty config value handling

The thread shows consensus on the approach, with Johannes Schindelin giving explicit approval in this email. The remaining open items from earlier discussion (perf target review and documentation updates) appear to be progressing separately. This particular patch appears ready for inclusion, representing the core fix for the NULL handling issue across all trace2 output formats.
