This is a follow-up on the reftable regression issue identified in Karthik Nayak's earlier `kn/reflog-migration-fix` commit. The patch, which fixed max_update_index values for the files backend, is now confirmed to cause test failures in the reftable backend (specifically t1400-update-ref) when tested with GIT_TEST_DEFAULT_REF_FORMAT=reftable.

Karthik reports being able to reproduce the issue when building with address and undefined sanitizers (using clang) and testing against the reftable backend. The failure wasn't caught by CI initially, which remains under investigation. The immediate action is to remove the commit from the 'next' branch pending diagnosis.

The email provides specific reproduction steps using meson builds with sanitizers enabled, though Karthik notes they haven't yet identified the root cause. This highlights ongoing challenges in maintaining compatibility between Git's multiple ref backends, particularly when changes affect one backend but have unintended consequences in another. The thread shows active investigation into both the technical issue and the CI gap that allowed the regression to slip through.
