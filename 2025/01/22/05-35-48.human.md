This is the second patch in a 3-part series addressing reftable migration issues, specifically a bugfix for potential integer overflow in large repositories. The patch changes the `index` field type from `unsigned int` to `uint64_t` across the refs subsystem to safely handle repositories with millions of references.

The change affects several key data structures and functions that track reference update ordering, including `ref_update` and `ref_transaction` in refs-internal.h, the reflog migration code in refs.c, and the reftable backend implementation. The motivation comes from Brian M. Carlson's report about 32-bit system limitations with large repositories.

This is a straightforward but important change that prevents potential corruption when dealing with very large numbers of reference updates. The patch is cleanly implemented with minimal churn - just 5 lines changed across 3 files. As part of a reviewed series where the first two patches have already been merged, this appears to be a well-justified and uncontroversial fix.
