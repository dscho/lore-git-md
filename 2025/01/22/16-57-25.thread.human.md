Here's a human-readable summary of the thread so far:

Michael Cheel noticed a discrepancy between the version numbers shown on Git's main website (v2.48.1, released January 13) and the Windows download page (v2.47.1(2), released January 14). He asked whether this reflected a coordination issue between the main Git releases and the Windows packaging.

Junio Hamano, Git's maintainer, responded to clarify that this is normal - the Windows port (maintained separately by Johannes Schindelin) typically lags slightly behind upstream releases as it requires additional platform-specific packaging work. He suggested checking the mailing list for announcements from the Windows maintainer to track when the Windows version catches up. The response confirms this is simply a matter of release timing rather than any website error or coordination problem. Users can expect some delay between upstream releases and Windows binary availability.
