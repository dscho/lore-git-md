This is part 4/5 of a series implementing breaking changes for Git 3.0, specifically removing the deprecated `git-pack-redundant` subcommand. The patch conditionally excludes the subcommand from compilation when the `WITH_BREAKING_CHANGES` flag is set, matching the deprecation announcement made in September 2024.

The changes touch three key areas: the Makefile to skip building the command, git.c to remove its command table entry, and the test script to skip tests when built with breaking changes. The implementation is straightforward and follows the pattern established earlier in the series for handling deprecated functionality.

The patch appears well-considered - it maintains backward compatibility for users not opting into breaking changes while cleanly removing the command for those who are. The test modification ensures the test script won't fail when the command isn't available, which is a thoughtful touch for CI environments. This continues the series' careful approach to managing breaking changes through build-time configuration.
