Refactoring patch moving refspec matching functions to their logical home. This is the first of three patches in a series aiming to centralize refspec handling code currently split between remote.[ch] and refspec.[ch].

The patch relocates three key refspec-related functions from remote.c to refspec.c: `omit_name_by_refspec()` (which checks if a ref matches any negative refspec), `refspec_match()`, and `match_name_with_pattern()` (the core pattern matching logic). The changes are purely mechanical code movement with no behavioral modifications, as evidenced by the symmetric +56/-54 line changes across files.

The author's goal is better code organization by keeping refspec-specific logic in refspec.c while reserving remote.c for remote-specific functionality. This initial patch handles the most straightforward cases where the separation is clear. The series will need to address more complex functions with mixed responsibilities in subsequent patches.

The changes affect core refspec operations used by both fetch and push, though this first patch focuses on the matching infrastructure rather than the higher-level operations. The implementation looks clean and well-contained, with proper header file updates to maintain the API.
