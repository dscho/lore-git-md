Build system patch introducing infrastructure for upcoming breaking changes. This is the first of five patches in a series preparing for Git 3.0's removal of legacy "branches/" and "remotes/" reference naming conventions.

The patch adds a new `WITH_BREAKING_CHANGES` compile-time flag across all supported build systems (Makefile, Meson, CMake) to control whether deprecated features should be enabled. This implements a policy established in earlier documentation that breaking changes must be gated behind such a switch. The changes are purely infrastructural at this point - no actual deprecations are wired up yet.

The implementation touches build configuration files across the project and adds a new test prerequisite `WITHOUT_BREAKING_CHANGES` for future test suite use. The patch appears straightforward and well-contained, following established patterns for build system modifications. It's part of a larger, carefully planned effort to modernize Git's reference handling while maintaining backward compatibility through compile-time options.
