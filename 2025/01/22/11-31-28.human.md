This is the final patch series in the long-running effort to remove the deprecated "branches/" and "remotes/" reference naming conventions, targeting Git 3.0. The series builds on previous iterations that established warning messages and CI infrastructure for breaking changes.

Patrick Steinhardt presents version 4 of the series, which now includes improved migration instructions in the warning messages and clearer deprecation documentation. The key changes in this version are the addition of specific `git remote rename` commands to help users migrate away from the old formats, and refinements to the warning text clarity.

The series systematically removes these legacy features that have been deprecated for nearly 20 years ("branches/") and 14 years ("remotes/"). It includes all the supporting infrastructure needed for such breaking changes: build system support, CI job repurposing, and comprehensive test coverage. The implementation spans multiple areas including remote handling code, build systems (Makefile, CMake, Meson), and CI configurations.

This appears to be the culmination of careful planning and community feedback, with all major technical questions resolved in previous iterations. The patch series is well-documented and thorough, with clear migration path for any remaining users of these ancient features. It represents a significant step in Git's modernization efforts while maintaining proper deprecation practices.
