Bugfix for reflog corruption in symref updates, addressing a regression introduced in Git 2.48.1. This patch removes an early return in `lock_ref_for_update()` that was incorrectly skipping `old_oid` population for symbolic reference reflogs, while still working correctly for direct branch updates. The issue was introduced as a premature optimization in commit 297c09eabb ("refs: allow multiple reflog entries for the same refname") which assumed reflog-only updates didn't need full processing.

The fix simply removes the problematic early return when `REF_LOG_ONLY` is set, allowing the symref handling code to properly populate the `old_oid` field. Karthik Nayak adds a new test case in `t/t1400-update-ref.sh` that verifies correct reflog behavior when updating HEAD via `git update-ref`, catching this class of error. The change affects the files backend's reflog handling in `refs/files-backend.c`, specifically around line 2615 where the early return was removed.

While the patch appears straightforward and correct, it's worth noting this modifies behavior that was intentionally added as a performance optimization. The commit message explains this optimization wasn't actually necessary for the original changes. The fix has been tested and confirmed by both the original bug reporter (Nika Layzell) and Jeff King, who initially diagnosed the issue. This seems ready for inclusion in a maintenance release once reviewed by refs subsystem maintainers.
