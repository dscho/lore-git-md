This is the final patch in a 3-part series hardening the reftable backend against corruption during repository migrations. The patch prevents invalid updates to the reftable writer's index limits after records have been written, which could previously cause header/footer mismatches.

Karthik Nayak modifies `reftable_writer_set_limits()` to return an error if called after any records are written, using both `last_key` and `next` fields for robust state detection. The change affects several call sites that now must handle the new error return value. A new unit test explicitly verifies the error case.

The solution addresses Patrick Steinhardt's concerns from earlier discussion by providing strict validation and comprehensive testing. With all three patches now technically ready and addressing previous review feedback, this completes the series' goal of preventing corruption when migrating large repositories to reftable.
