This is a refactoring RFC patch series aiming to centralize refspec-related logic in the Git codebase. The series responds to a previous observation that refspec handling is currently scattered across multiple header files, particularly split between remote.[ch] and refspec.[ch].

The proposed changes would move 200+ lines of refspec-related code from remote.c to refspec.c, creating a more logical organization where all refspec operations live together. The author identifies four borderline functions (get_fetch_map, count_refspec_match, check_push_refs, match_push_refs) that contain mixed refspec/remote logic and explicitly calls out their uncertain status - these may become discussion points in the review.

The series consists of three mechanical moves: first relocating omit_name_by_refspec and related functions, then query-related functions, and finally apply_refspecs and its dependencies. The changes appear to be straightforward code motion without behavioral modifications, as evidenced by the symmetric +226/-216 line count changes across the four affected files.

For future thread tracking: key functions being moved include omit_name_by_refspec and apply_refspecs, with the four borderline functions (get_fetch_map, count_refspec_match, check_push_refs, match_push_refs) flagged as potentially needing special handling. The changes touch core refspec handling that affects both fetch and push operations.
