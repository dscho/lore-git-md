Feature proposal for batch remote removal with performance considerations.

Jeff King (Peff) builds on Brian M. Carlson's performance analysis of batch remote removal, focusing on the quadratic time complexity issues in both config file updates and packed-refs handling. He confirms that current `git remote remove` operations rewrite the entire config file for each remote, making sequential deletions inefficient at scale. The email suggests that a proper implementation should process multiple removals in a single pass through both the configuration and ref storage systems, rather than just wrapping the existing single-remote removal in a loop.

Key technical points raised include:
- The config file rewrite penalty mirrors the packed-refs quadratic behavior already discussed
- Any implementation should refactor `builtin/remote.c:rm()` to handle multiple operations atomically
- Similar optimizations could benefit `git-config --remove-section` for multiple sections

This moves the discussion toward implementation specifics, emphasizing the need for atomic multi-operation handling across both configuration and reference subsystems. The email reinforces Carlson's performance arguments while expanding the scope to include config file operations, suggesting coordinated improvements across related commands. The maintainer's focus on avoiding naive looping indicates this will require non-trivial refactoring to achieve the desired performance characteristics.
