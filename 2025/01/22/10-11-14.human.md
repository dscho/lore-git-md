Bugfix for trace2 segfault when handling empty config values. This is the second version of Adam Murray's patch addressing a crash that occurs when Git's trace2 analytics system encounters a config option with no value (like `-c foo.empty`). The fix adds NULL checks across all three trace2 output targets (event, normal, perf) and includes a test case.

The patch has received positive feedback, with Johannes Schindelin approving it as looking good. The changes from v1 include more comprehensive handling of NULL values across all trace2 subsystems rather than just the initial null check, and output format adjustments to properly represent empty values. The thread context shows this is part of a series that's nearly ready, with only perf target changes needing final review from a subsystem expert.

This appears to be a well-constructed fix for a clear bug, with thorough coverage across all trace2 output formats and a new test case.
