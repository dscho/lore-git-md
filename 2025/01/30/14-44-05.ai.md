CI / build system patch completing Patrick Steinhardt's Meson refactoring series (v2 13/13), addressing Windows-specific resource constraints in GitLab CI.

This final patch in the series tackles a practical CI limitation on Windows runners, where the default parallel linking behavior causes memory exhaustion with GitLab's 7.5GB RAM allocation. The solution restricts linker parallelism to one job at a time (-Dbackend_max_links=1) specifically for the msvc-meson build job, while noting GitHub Actions' 16GB runners don't exhibit the same constraint.

The change is narrowly scoped to the GitLab CI configuration, modifying only the meson setup command in .gitlab-ci.yml. It builds upon the series' broader Meson build system improvements but stands apart as a CI-specific optimization rather than a core build system change. The patch follows the series' pattern of platform-aware optimizations, though this one targets infrastructure constraints rather than build architecture.

Key technical points for future reference:
- Windows-specific: Only affects MSVC builds on GitLab CI
- Memory constraint: Addresses 7.5GB RAM limit causing OOMs during parallel linking
- Solution: Disables parallel linking via meson's backend_max_links parameter
- Scope: Does not modify core build logic, only CI job configuration
- Contrast: Notes GitHub Actions' higher RAM (16GB) avoids this issue

The patch appears well-justified and narrowly targeted, completing the series that has systematically improved build system reliability and efficiency across multiple dimensions.
