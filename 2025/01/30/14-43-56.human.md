Build system refactoring in Patrick Steinhardt's Meson series (patch 4/13) simplifies how executables link against common code. The patch eliminates a static library (`common-main`) that was previously used to share initialization code between Git executables, instead compiling that code directly into each executable that needs it. This removes some build system indirection while maintaining the same functionality.

The change required fixing a subtle issue with Git's HTTP aliases (like `git-remote-https`). These aliases reuse object files from `git-remote-http`, which already contain a `main()` function. The new approach would have caused duplicate `main()` definitions, so the patch adjusts the aliases to link only against `libgit.a` instead of the common code.

This is a straightforward structural improvement that makes the build configuration more direct. The patch touches multiple build files but doesn't change runtime behavior. It continues the series' trend of simplifying the Meson build system while maintaining compatibility with the existing Makefile-based build.
