Bugfix report about tag fetching behavior when fetching specific commits.

Igor Todorov reports a regression where tags are no longer being fetched when using `git fetch` with a specific commit hash, bisecting the issue to commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist"). The report includes clear reproduction steps showing the difference in behavior - with Git 2.48.1, fetching a specific commit from the golang/go repository no longer includes associated tags in the output (like "tag: go1.24rc1") that were present before.

The problematic commit was meant to automatically set remote/HEAD during fetch operations, but appears to have unintentionally affected tag fetching behavior. The reporter questions whether this change was intentional and notes the issue was first reported through the zOpen community's Git port project. The patch looks like a genuine regression rather than an intentional change, given the clear before/after behavior and bisect result.
