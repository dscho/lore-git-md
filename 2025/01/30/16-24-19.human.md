This is the third and final patch in Patrick Steinhardt's series fixing repository reinitialization issues with different formats. It addresses a parallel problem to the previous patch, but for object hashes rather than ref formats.

The patch fixes a case where `GIT_DEFAULT_HASH` could incorrectly override an existing repository's object format during reinitialization, which would lead to repository corruption since existing objects wouldn't be converted. The fix mirrors the approach from patch 2/3 - the environment variable is now only respected when initializing a new repository or when no format is specified. The commit includes a clear reproduction case showing how the bug manifests (resulting in a "broken branch" error) and adds tests verifying the fix works for both SHA-1 and SHA-256 repositories.

This completes the series' goal of preventing environment variables from corrupting repositories during reinitialization, which was particularly problematic for CI systems using cached repositories. The changes are straightforward and well-tested, though as with the previous patches, they touch sensitive initialization code paths that would benefit from careful review.
