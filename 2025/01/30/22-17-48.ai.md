Maintainer ack for integer overflow fix in `git apply`.

Junio Hamano acknowledges Phillip Wood's patch fixing an integer overflow vulnerability in `git apply`'s hunk header parsing. The patch properly initializes and checks `errno` after `strtoul()` calls to detect numeric overflows when processing line numbers in patch files. While noting the error message remains generic ("corrupt patch"), Hamano agrees this is sufficient for now given the unlikelihood of users encountering this in normal operation.

The maintainer praises the narrow scope of the change (just one line in `parse_num()` in `apply.c`) and the accompanying test case that demonstrates overflow detection with extreme line numbers. Hamano highlights this as a defensive fix against potential malicious input, though the original code's design limited the exposure surface. The patch is accepted and will be queued for inclusion.

Key technical details for future reference: The fix modifies `parse_num()` in `apply.c` to properly handle `strtoul()` overflow cases, with test coverage in `t4100-apply-stat.sh` using intentionally extreme line numbers (98765432109876543210). The error reporting remains unchanged from the existing "corrupt patch" message. This addresses the specific overflow case while leaving similar parsing in `git add -p` for future fix.
