Build system refactoring (part of Patrick Steinhardt's Meson improvements series v2 4/13). This patch simplifies the handling of the common-main library in the Meson build system by eliminating an intermediate static library and compiling common sources directly into each executable.

The change removes the `common_main_library` static library and replaces it with a direct `libgit_commonmain` dependency that combines the common sources with `libgit.a`. This reduces build system complexity by removing an unnecessary layer of indirection. The patch affects multiple executables including `git`, `git-shell`, test helpers, and HTTP-related programs.

A notable technical detail is the fix for git-remote-http aliases (like git-remote-https), which previously would have caused linker errors due to duplicate `main()` definitions. The solution is to only link these aliases against `libgit.a` rather than the full common-main` sources. The changes touch build files across the project (`meson.build`, `oss-fuzz/meson.build`, `t/helper/meson.build`, `t/meson.build`) but maintain identical functionality while making the build configuration more straightforward.

This continues the series' theme of structural improvements to the Meson build system, following earlier patches that addressed GIT_EXEC_PATH resolution and OpenSSL fallback handling. The change is purely internal - no runtime behavior is affected - but contributes to the overall goal of making the build system more maintainable and easier to understand.
