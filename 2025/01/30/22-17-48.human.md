Maintainer ack for integer overflow fix in `git apply`

Junio Hamano has reviewed and accepted Phillip Wood's patch that fixes an integer overflow vulnerability in `git apply`'s hunk header parsing. The patch properly initializes and checks `errno` when using `strtoul()` to parse line numbers in patch files, preventing silent overflow errors that could lead to incorrect patch application.

Hamano notes the fix is narrowly scoped (requiring only one line change) and commends the original code's design while acknowledging the need for this defensive check against malicious input. The patch includes a test case demonstrating overflow detection with extreme line numbers. While the error message remains generic ("corrupt patch"), Hamano indicates this can be improved later if needed.

This appears to be a straightforward, well-contained security hardening measure that will be queued for inclusion. The same issue exists in `git add -p` but is being handled separately. The change has clear test coverage and maintainer approval.
