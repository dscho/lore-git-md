Bugfix patch adding NUL character detection in packed-refs refnames.

This is patch 5/8 in a series improving packed-refs validation, now focused specifically on file format checks. The patch addresses a reported issue where embedded NUL characters in refnames could go undetected during packed-refs parsing. Currently, the code checks refname validity but could be fooled by NULs that truncate the name to something valid.

The solution introduces a new `refname_contains_nul()` helper that scans for embedded NULs using memchr() (as previously agreed in the thread). When found, parsing fails with a descriptive error. The implementation is straightforward and well-explained in both commit message and code comments, building on existing validation infrastructure.

The patch appears technically sound with clear motivation from the referenced report. It fits well with the series' goal of hardening packed-refs parsing while avoiding broader object validation (deferred to future work per Patrick Steinhardt's architectural direction). Test coverage isn't shown in this patch but would presumably be covered by the series' test infrastructure changes.
