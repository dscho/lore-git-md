Thread summary:

Bugfix addressing integer overflow vulnerability in `git apply`'s hunk header parsing. Phillip Wood identified that `strtoul()` could silently ignore numeric overflows when processing line numbers in patch files, potentially leading to incorrect patch application. The fix properly initializes and checks `errno` after `strtoul()` calls in `apply.c`, though error messages remain generic ("corrupt patch") for now. Includes test case in `t4100-apply-stat.sh` demonstrating overflow detection with extreme line numbers. 

While the same issue exists in `git add -p`'s similar parsing logic, that remains unaddressed pending resolution of another related patch series. The change is narrowly scoped to `apply.c` with clear test coverage, though error messaging could be more specific (a noted but deferred). This appears to be a defensive fix for an edge case unlikely to affect normal usage, but important for correctness. Phillip Wood is the primary contributor on this fix, which touches number parsing logic in the apply machinery. The patch stands alone and isn't part of any larger series.
