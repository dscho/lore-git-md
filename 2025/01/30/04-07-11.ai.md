Bugfix in the packed-refs validation series, addressing an edge case where HEAD parsing could trigger premature validation failures. This is patch 2/8 in v2 of the series, which focuses on packed-refs file format validation while deferring object validation to future work.

The patch introduces `get_worktrees_without_reading_head()` to avoid triggering packed-refs validation when checking worktrees during `git refs verify`. Currently, `get_worktrees()` parses HEAD references, and if they point to packed refs, it triggers the packed-backend's snapshot validation which may abort the program on format errors. The new function uses existing infrastructure from commit 465a22b338 to skip HEAD parsing, allowing `git refs verify` to report all validation issues rather than dying on the first problem.

Changes are minimal - just exposing the existing skip-HEAD functionality from `get_worktrees_internal()` via a new public API and using it in `builtin/refs.c`. The patch maintains the series' goal of comprehensive validation reporting while avoiding premature termination. It touches worktree.c/h for the new API and updates the single call site in builtin/refs.c.

Key technical points for future reference:
- New API `get_worktrees_without_reading_head()` mirrors `get_worktrees()` but skips HEAD parsing
- Avoids triggering packed-refs validation during worktree enumeration
- Builds on prior worktree.c infrastructure from 465a22b338
- Part of making `git refs verify` more robust by collecting all errors rather than dying early
