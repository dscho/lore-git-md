This is the final patch in Patrick Steinhardt's Meson build system refactoring series, focusing on CI system reliability for Windows builds. The patch addresses a practical issue where GitLab's Windows CI jobs were failing due to memory exhaustion during linking. The root cause is that Microsoft's link.exe is memory-hungry when running multithreaded, and GitLab's Windows runners only have 7.5GB RAM (versus GitHub Actions' more generous 16GB).

The solution is straightforward: limit concurrent linker jobs to 1 via Meson's `-Dbackend_max_links=1` flag. This completes the series' Windows reliability improvements, which previously covered tool path handling and documentation tool resolution. The change is minimal (a one-line modification to .gitlab-ci.yml) but important for stable CI operation.

As the series conclusion, this patch follows through on the earlier architectural improvements with a concrete fix for real-world build problems. The series as a whole has systematically modernized Git's build system while addressing platform-specific concerns, with this final patch ensuring the changes work reliably in constrained CI environments.
