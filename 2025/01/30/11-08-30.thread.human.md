Phillip Wood identified and fixed an integer overflow vulnerability in `git apply`'s hunk header parsing, where `strtoul()` could silently ignore numeric overflows when processing line numbers in patch files. The fix properly initializes and checks `errno` in `parse_num()` within `apply.c` to detect these cases, though it continues using the generic "corrupt patch" error message for now. A test case in `t4100-apply-stat.sh` demonstrates overflow detection with extreme line numbers.

Junio Hamano has reviewed and accepted the patch, praising its narrow scope and defensive nature against potential malicious input. While noting the same issue exists in `git add -p`'s similar parsing logic, that remains unaddressed for now. The change is queued for inclusion, providing an important correctness fix for an edge case that's unlikely to affect normal usage but strengthens the code's robustness.
