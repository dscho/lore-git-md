This is a cover letter for a 2-patch bugfix series addressing memory leaks detected by Meson builds. The series follows up on previous discussion where Jeff King and Patrick Steinhardt analyzed why these leaks were caught by Meson but not Makefile builds.

The first patch fixes a Unix socket memory leak in `unix-socket.c` where `ctx->orig_dir` wasn't freed when `chdir()` fails, particularly noticeable with long pathnames exceeding socket length limits (~108 bytes). The second patch addresses a scalar.c leak where `remote_default_branch()` results weren't freed in `cmd_clone()`.

Key updates in v2:
- Added explanation that the Unix socket leak only triggers with long pathnames that exceed socket name length limits
- Corrected Meson configuration references to use the proper `-Db_sanitize=leak` syntax (with "b_" prefix)
- Maintains the same minimal code changes (6 lines added, 2 deleted total)

The thread context shows the first patch was already approved by Junio Hamano after technical validation from Jeff King, while the second remains pending review. The discussion has also served as a reference for Meson build configuration details, particularly around leak detection setup and test execution workflows. The series demonstrates Meson's value in catching resource leaks that Makefile builds miss, though the exact reason for the Makefile/Meson discrepancy in detecting these leaks remains partially unexplained.
