Final patch in a bugfix series adding packed-refs validation checks, now integrating them into `git fsck` via a new `git refs verify` subcommand. This wraps up the v2 series that has been shaped by Patrick Steinhardt's architectural guidance to separate file format validation from object validation.

The patch adds a `fsck_refs()` function that runs `git refs verify` as a child process during `git fsck` execution, with progress reporting and support for existing `--verbose` and `--strict` flags. The implementation is intentionally minimal - it runs early in `git fsck` to avoid interference with existing ref checks, and uses a simple progress meter (just 1 step) since counting loose refs upfront would be difficult.

This represents the first step toward backend-agnostic ref validation, though the series has focused specifically on packed-refs checks. The patch maintains the series' careful approach to test reliability (using subshells) and error reporting that was developed through earlier review feedback. With this integration point now in place, future work can build on it for more comprehensive ref validation.
