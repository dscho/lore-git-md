Bugfix report regarding tag fetching behavior regression. Igor Todorov reports that commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist") introduced an unintended side effect where tags are no longer fetched when fetching specific commits. The issue manifests when using protocol version 2 with a depth limit, where previously fetched commits would include their associated tags in the output of `git log --decorate`, but now show only the commit hash.

The regression was bisected to Bence Ferdinandy's November 2024 commit that modified fetch handles remote/HEAD references. While that commit's primary purpose was to ensure remote/HEAD gets set during fetch operations, it appears to have inadvertently affected tag fetching behavior. The reporter provides a clear reproduction case using the golang/go source repository and shows the difference in output between expected (tag included) and actual (tag missing) behavior.

The issue was originally reported through the zopencommunity/gitport project's issue tracker. The email questions whether this behavior change was intentional, suggesting it may be an unintended regression rather than a deliberate modification of fetch semantics. The technical details focus on the interaction between commit-specific fetches and tag decoration output, with the key observation being that tags that were previously included in the fetch operation are now missing from the log output.
