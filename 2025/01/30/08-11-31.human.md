Bugfix for promisor pack handling in `git repack`. This patch addresses an oversight where `--keep-pack` and `.keep` files were not being respected when repacking promisor objects (used in partial clones). Currently this means settings like `gc.bigPackThreshold` don't work for promisor packs.

The fix straightforwardly copies the existing keep-pack logic into `repack_promisor_objects()`, though the author notes it might be cleaner to handle this in `prepare_pack_objects()` instead. The patch is marked RFC as the author is seeking input on test implementation - whether to add tests in t7700-repack.sh or t0410-partial-clone.sh.

The change is small (12 lines) and focused, touching only builtin/repack.c. While the impact is limited to partial clone users, it fixes a clear inconsistency in pack handling behavior. The author demonstrates good awareness of the testing implications but is appropriately seeking community input before finalizing.
