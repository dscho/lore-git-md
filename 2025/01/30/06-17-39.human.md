This is the second patch in a 2-part bugfix series addressing memory leaks found via Meson's leak detection. The patch fixes a missing free of the remote default branch result in scalar.c's `cmd_clone()` function, where `remote_default_branch()` allocates memory that wasn't being freed.

The leak shows up in test t9211 when run under Meson with leak sanitization enabled, though interestingly not under Makefile builds. The fix introduces a new `branch_to_free` variable to safely handle cases where the branch name might come from either command-line arguments (which shouldn't be freed) or from `remote_default_branch()` (which should). The change is minimal - just 3 lines added to properly track and free the allocated string.

While the first patch in this series (fixing a Unix socket leak) has already been approved, this scalar.c fix remains pending review. The thread has included detailed discussion about Meson's leak detection capabilities and how they're exposing issues that Makefile builds miss. This particular leak is small (5 bytes) but demonstrates the value of the more rigorous checking Meson provides.
