Bugfix in the packed-refs validation series, addressing premature termination during verification. This patch modifies `git refs verify` to avoid reading HEAD information from worktrees when checking ref consistency, preventing potential die() calls from packed-refs parsing that would short-circuit the verification process.

The issue arises because existing worktree handling would parse packed-refs when checking HEAD references, triggering validation that could terminate the program before completing all checks. The solution builds on a recent addition (465a22b338) that introduced infrastructure to skip HEAD reading, exposing it via a new `get_worktrees_without_reading_head()` function.

This change aligns with the series' goal of comprehensive validation without early termination, allowing `git refs verify` to report all issues rather than dying on the first problem. The implementation is straightforward - just a function wrapper and call site update - and comes with mentoring from both Patrick Steinhardt and Karthik Nayak, suggesting it fits well with the broader ref verification architecture being developed.

The patch appears technically sound and focused, though it's worth noting this is part of a larger series (currently at v2 2/8) restructuring packed-refs validation. The change makes sense in context but reviewers will want to consider it alongside the full series' direction.
