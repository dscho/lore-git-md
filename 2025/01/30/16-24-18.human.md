This is a bugfix patch in Patrick Steinhardt's series addressing repository reinitialization issues. The patch corrects behavior when `GIT_DEFAULT_REF_FORMAT` is set during repository reinitialization, ensuring the existing repository's ref format is preserved rather than being overwritten by the environment variable.

Currently, when reinitializing a repository with a different `GIT_DEFAULT_REF_FORMAT` than its existing format, Git incorrectly tries to change the format, leading to errors. The patch modifies `setup.c` to only respect the environment variable for new repositories, not existing ones. A test case is added to verify this behavior works correctly across both files and reftable ref storage formats.

The change is technically sound with clear test coverage, though it touches core repository initialization paths that may warrant careful review. The fix addresses real-world problems seen in CI systems where cached repositories with one format configuration fail when reinitialized with different settings. This is the second of three patches in the series, building on the initial test cleanup from patch 1/3.
