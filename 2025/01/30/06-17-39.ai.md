Bugfix for a memory leak in scalar.c detected by Meson's leak sanitizer. This is the second patch in a 2-part series addressing leaks found via Meson builds that weren't caught by traditional Makefile builds.

The patch fixes a missing free of the result from `remote_default_branch()` in scalar.c's `cmd_clone()`. The leak occurs when the remote's default branch name is allocated (5 bytes in the test case) but never freed. The fix introduces a new `branch_to_free` variable to safely handle cases where `branch` might point to either a command-line argument string (which shouldn't be freed) or the allocated default branch name (which should be freed).

Key technical details:
- Leak occurs in `cmd_clone()` when falling back to `remote_default_branch()`
- Fix uses a separate `branch_to_free` variable to avoid freeing string constants from command-line arguments
- Leak is detected by Meson with `-Db_sanitize=leak` but not by Makefile builds
- Test t9211 exposes the leak under Meson
- Patch adds 3 lines (variable declaration and assignment) and 1 free call
- Similar in spirit to the first patch in the series (Unix socket leak fix) but focuses on scalar component
- Maintainer status: First patch was approved by Junio Hamano; this one remains pending review
- Build system implications continue the thread's theme of Meson catching leaks Makefile misses

The thread has established that both patches demonstrate Meson's value in leak detection, though this second patch's review is still in progress while the first has been approved. The technical approach here follows the pattern of the first fix - identifying and plugging a clear resource leak - though the scalar.c context requires slightly more care due to mixed string sources.
