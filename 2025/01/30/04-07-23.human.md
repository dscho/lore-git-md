This is a bugfix patch in a series improving packed-refs validation. It adds a check to ensure the "packed-refs" file is a regular file (not a symlink) when verifying refs.

The patch introduces a race-condition-safe way to verify the file type by opening it with `open_nofollow()` rather than just using `lstat()`. This prevents a potential security issue where the file could be changed to a symlink between checking and reading. The implementation reuses the existing `FSCK_MSG_BAD_REF_FILETYPE` error message when reporting non-regular files.

The change includes test coverage that creates a symlink for packed-refs and verifies the error is correctly reported. The approach follows the series' direction of strengthening packed-refs validation while keeping the changes focused and incremental. The patch has been reviewed by Patrick Steinhardt and Karthik Nayak, suggesting it aligns with the broader refs verification architecture being developed.
