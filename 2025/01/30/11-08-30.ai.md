Bugfix for `git apply` hunk header parsing to detect integer overflows. Phillip Wood addresses a subtle issue where `strtoul()` could silently ignore numeric overflows when parsing hunk line numbers in patch files. The fix properly initializes `errno` before the call and checks it afterward, though the error message remains generic ("corrupt patch") for now. A test case demonstrates the overflow detection by using absurdly large line numbers that would exceed `unsigned long` capacity.

The patch touches `apply.c`'s number parsing logic and adds a test in `t4100-apply-stat.sh`. While the commit notes this same issue exists in `git add -p`, that's left for future work pending resolution of another related patch series. The change is straightforward with clear test coverage, though the error messaging could be more descriptive (a noted but deferred improvement). This appears to be a defensive fix for an edge case that's unlikely to affect normal usage.
