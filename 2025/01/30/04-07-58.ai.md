This is patch 6/8 in a bugfix series improving packed-refs validation, focusing on entry-level consistency checks. The patch adds detailed verification of individual packed-refs entries, splitting the validation logic between main ref lines (containing refname and target OID) and peeled lines (for annotated tags). It introduces a new fsck error type "badPackedRefEntry" and implements checks for: invalid OIDs, missing/trailing spaces after OIDs, malformed refnames (including NUL detection via the existing `refname_contains_nul()` helper), and invalid peeled references. The validation is integrated into the existing `packed_fsck_ref_content()` function and exercised through new test cases that deliberately create malformed packed-refs entries.

Key technical details include: the new `packed_fsck_ref_main_line()` and `packed_fsck_ref_peeled_line()` helper functions, use of `parse_oid_hex_algop()` for OID validation, and careful error reporting through the fsck infrastructure. The test additions in t0602-reffiles-fsck.sh verify detection of various malformed cases including short OIDs, missing spaces, trailing garbage, and invalid refnames. This builds on the series' earlier work (header validation in previous patches) while maintaining the architectural separation from object validation that was a key point in Patrick Steinhardt's review of v1. The implementation appears thorough, with clear error messages and comprehensive test coverage for the new validation cases.
