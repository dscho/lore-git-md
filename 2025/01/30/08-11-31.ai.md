This is a bugfix patch addressing an inconsistency in how `git repack` handles promisor packs with respect to keep-pack settings. The patch ensures that `--keep-pack` and `.keep` file settings are properly honored when repacking promisor objects, fixing a case where configurations like `gc.bigPackThreshold` were being ignored for these packs.

The change modifies `repack_promisor_objects()` in builtin/repack.c to pass through the same keep-pack logic used elsewhere in repacking. The author notes this could potentially be improved by centralizing the logic in `prepare_pack_objects()`, but opts for the simpler direct fix. The patch adds proper handling of both `--honor-pack-keep` and `--keep-pack` options when invoking pack-objects for promisor packs.

Key technical details include:
- Modified function signature of `repack_promisor_objects()` to accept `keep_pack_list`
- Added logic to pass keep-pack options to pack-objects subprocess
- Maintains existing behavior when `pack_kept_objects` is true
- Affects promisor pack handling during `ALL_INTO_ONE` repacks

The author raises an RFC question about test implementation, considering either t7700-repack.sh or t0410-partial-clone.sh as potential locations, suggesting adapting existing keep-pack tests with promisor file modifications. The patch appears straightforward and well-motivated, addressing a clear inconsistency in behavior, though test coverage would strengthen it.
