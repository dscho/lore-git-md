This is part 7/8 of a bugfix series improving packed-refs validation. The patch adds sorting verification to ensure packed-refs entries are properly ordered by refname, which is a requirement for correct operation.

The implementation introduces a new `packedRefUnsorted` error type that gets reported when entries are out of order. Rather than storing all refnames for comparison (which would be memory-intensive), the patch cleverly reuses existing snapshot record comparison logic by extracting the refname comparison into a new `cmp_packed_refname()` helper. The validation happens during the existing packed-refs parsing pass, with detailed error messages showing the problematic line numbers and refnames.

The patch includes thorough test coverage demonstrating detection of both regular ref and annotated tag sorting violations. It builds on previous work in the series by Patrick Steinhardt and Karthik Nayak, with clean integration into the existing validation framework. The implementation looks solid, with careful attention to memory management and error reporting consistency with other validation checks in the series.

This is a focused addition to the packed-refs validation suite that addresses a real consistency requirement while maintaining the series' goal of comprehensive file format checking. The approach is efficient and well-integrated with the codebase's existing ref handling infrastructure.
