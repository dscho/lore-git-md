This is a build system optimization patch in Patrick Steinhardt's ongoing Meson refactoring series (v2 10/13). The change eliminates redundant searches for the `sed` program during the build process by storing its location in a variable at the top level and reusing it, rather than looking it up repeatedly in a loop. 

The patch is straightforward - it moves the `sed` program lookup to the main `meson.build` file where other tool declarations live, then updates the documentation build to reference this variable. This follows the pattern already established for other tools like `git` and `diff`. The change also removes `sed` from the list of tools being sanity-tested in a loop, as it's now handled separately.

This appears to be a clean, logical optimization that reduces unnecessary work during the build. It builds on previous changes in the series that improved tool path handling, particularly for Windows builds. The change is small and focused, with no apparent downsides or compatibility concerns. 

As part of the larger Meson modernization effort, this patch continues the theme of making the build system more efficient and maintainable while preserving all existing functionality. It's the kind of incremental improvement that makes sense in a refactoring series like this.
