This is a bugfix patch addressing a memory leak in Unix socket handling, specifically in the credential-cache operations path. The patch is part of a v2 series where the first patch has already been maintainer-approved, with this version adding explicit notes about the path length dependency.

The leak occurs in `unix_sockaddr_init()` when `chdir()` fails after allocating memory for `ctx->orig_dir` - the original directory path is not freed in the error path. The issue manifests when creating Unix sockets with pathnames exceeding system limits (~108 bytes), causing `chdir()` to fail while leaving the allocated path string dangling. The fix adds proper cleanup with `FREE_AND_NULL(ctx->orig_dir)` in the error path.

Key technical details for future reference:
- Trigger condition: Path length exceeding `sockaddr_un.sun_path` limits (around 108 bytes)
- Leak source: `strbuf_getcwd()` allocation in `unix_sockaddr_init()`
- Fix pattern: Standard `FREE_AND_NULL` cleanup
- Test coverage: Detected by t0301 when run in sufficiently deep directory hierarchy
- Build system context: Meson's leak detection caught this while Makefile builds missed it due to path length variations
- Maintainer status: Junio Hamano has already approved this fix after technical validation from Jeff King

The patch is minimal (3 lines added, 1 deleted) and follows established patterns for error handling cleanup. The thread discussion has confirmed this addresses a real edge case while deciding against adding specific tests for the path length scenario.
