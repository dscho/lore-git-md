Bugfix patch adding packed-refs header validation as part of the larger packed-refs fsck series (v2 4/8). This implements strict checking of the packed-refs file header format while maintaining backward compatibility for existing repositories.

The patch introduces three new fsck checks for packed-refs headers: (1) ERROR-level "badPackedRefHeader" when the header doesn't start with "# pack-refs with:", (2) INFO-level "unknownPackedRefHeader" when the header content differs from Git's standard format, and (3) INFO-level "packedRefMissingHeader" when no header exists. It also adds ERROR-level "packedRefEntryNotTerminated" check for malformed entries without newlines.

The implementation reads the packed-refs file via strbuf_read and parses line-by-line, reusing the existing fsck reporting infrastructure. The validation logic is ported from create_snapshot() but enhanced with the new compatibility-aware checks. Extensive test cases verify all scenarios including missing headers, malformed headers, and non-standard but acceptable headers.

This is a focused piece of the larger packed-refs validation effort, specifically handling header format verification while deferring object validation to future work. The patch maintains the series' separation of concerns by only validating file format, not object contents. Test infrastructure uses subshells as established in earlier patches for reliable cleanup.
