Bugfix patch adding packed-refs filetype validation to prevent symlink attacks, part of the v2 packed-refs validation series (3/8).

This patch introduces a security check to ensure the packed-refs file is a regular file, not a symlink, when being verified. The author explains two potential implementation approaches (lstat vs open_nofollow) and chooses the more secure open_nofollow method to avoid TOCTOU race conditions where a file could be replaced with a symlink between checking and reading. The implementation reuses the existing FSCK_MSG_BAD_REF_FILETYPE message for consistency.

The change affects packed-backend.c by adding filetype validation in the packed_fsck function, with proper error handling for ELOOP (symlink) and ENOENT (missing file) cases. A new test case in t0602-reffiles-fsck.sh verifies the behavior by creating a symlink and checking that git refs verify correctly detects and reports the invalid filetype. The test follows the subshell pattern established earlier in the series for reliable cleanup.

This appears to be a well-justified security hardening measure, with clear motivation about preventing symlink attacks and careful consideration of implementation tradeoffs. The patch maintains the series' focus on packed-refs validation while avoiding scope creep into object validation. Test coverage is thorough for the new functionality. The implementation follows Patrick Steinhardt's architectural guidance from earlier in the thread by keeping this as a file format validation check within the packed-backend.
