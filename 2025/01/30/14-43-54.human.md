This is a build system fix targeting Windows compatibility in Patrick Steinhardt's Meson refactoring series (patch 2/13). It corrects an issue with OpenSSL fallback behavior when the HTTPS backend is set to 'auto' - a case that was previously broken because the fallback to the subproject wrapper was implicitly disabled. The patch ensures proper fallback behavior when OpenSSL is either required or when the backend is auto-detected, which is particularly important for Windows systems where OpenSSL typically isn't available system-wide.

The change is small but important, touching just the OpenSSL dependency declaration in meson.build. It adds an explicit `allow_fallback` condition and fixes the backend reporting when no HTTPS backend is selected. This builds on the series' broader goal of improving Windows support and build system reliability, following up on feedback from the v1 review.

The patch appears well-contained and focused, with a clear explanation of both the problem and solution. As part of a larger refactoring effort, it contributes to making the Meson build more robust, especially for Windows users who rely on the OpenSSL fallback mechanism.
