This is a bugfix patch in a series addressing packed-refs validation (currently v2, patch 7/8). It introduces sortedness verification for packed-refs files, ensuring refnames are in increasing order as required by the format.

The patch adds a new "packedRefUnsorted" error type (ERROR severity) to report when packed-refs entries are out-of-order. It implements this by:
1. Extracting the refname comparison logic from `cmp_packed_ref_records()` into a new `cmp_packed_refname()` helper
2. Creating a `fsck_packed_ref_entry` structure to track line numbers and record positions during validation
3. Adding `packed_fsck_ref_sorted()` to verify ordering across all entries, reporting the first out-of-order pair found
4. Including comprehensive test cases in t0602-reffiles-fsck.sh that verify detection of unsorted refs in both branch and tag entries

The implementation avoids excessive memory usage by not storing all refnames, instead comparing entries as they're parsed. It reuses existing comparison infrastructure where possible while adding the new validation pass. The error reporting follows the series' established pattern of including line numbers and specific refnames in messages.

This continues the series' focus on packed-refs file format validation while deferring object validation to future work, as noted in the thread context. The patch builds on prior feedback about implementation robustness and test reliability, maintaining the architectural direction established in earlier reviews.
