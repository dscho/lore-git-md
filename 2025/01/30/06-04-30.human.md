Build system discussion follow-up. Patrick Steinhardt responds to Jeff King's analysis of why the Unix socket memory leak (from the first patch in the series) only appears in Meson builds. King had explained that the leak occurs with long socket paths that exceed `sockaddr_un.sun_path` limits (~108 bytes), and provided a concrete test case demonstrating the failure at 109+ byte paths versus working cases at 93 bytes.

Steinhardt agrees with King's analysis and confirms he'll add this explanation to the commit message, but declines to include King's proposed test case for the error path, judging it too specific to be worthwhile. The exchange serves to document the edge case while keeping the patch minimal. 

This email doesn't introduce new technical changes but provides useful context about the leak's reproduction conditions and a maintainer's perspective on test coverage tradeoffs. The thread continues to serve as both a bugfix record and a reference for Meson-based development workflows.
