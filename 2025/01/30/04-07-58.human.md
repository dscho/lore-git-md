Bugfix patch adding packed-refs entry validation as part of a larger series to improve refs verification. This is patch 6/8 in v2 of a series that has evolved significantly from its initial version, now focusing specifically on packed-refs file format validation after separating out object validation concerns.

The patch, mentored by Patrick Steinhardt and Karthik Nayak, introduces detailed consistency checking for individual entries in packed-refs files. It adds two new helper functions (`packed_fsck_ref_main_line` and `packed_fsck_ref_peeled_line`) that validate:
- Proper OID formatting and spacing in main ref entries
- Valid refname formatting (including NUL character detection)
- Correct peeled reference syntax and OIDs
- Presence of required whitespace

A new fsck message ID (`badPackedRefEntry`) is added to report these issues, and the test suite is expanded with a comprehensive test case that exercises various malformed packed-refs entries. The implementation builds on previous work in the series to provide thorough validation while maintaining the architectural separation between file format checks (handled here) and object validation (deferred to future work).

The changes appear well-considered, with clear test coverage for the new validation cases. As part of the broader effort to improve refs verification, this patch represents an important step in catching malformed packed-refs entries that could lead to subtle repository corruption.
