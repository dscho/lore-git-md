This is a bugfix patch addressing a memory leak in Unix socket handling, now approved for inclusion in the main Git tree. The patch fixes a case where `unix_sockaddr_init()` would leak memory allocated for `ctx->orig_dir` when `chdir()` fails during credential-cache operations with long socket paths. 

The issue only manifests when creating Unix sockets with pathnames exceeding ~108 bytes (the typical `sockaddr_un.sun_path` limit), where Git attempts to `chdir()` into the parent directory to shorten the path. The leak was caught by Meson's leak detection but missed by Makefile builds, highlighting Meson's value in catching such edge cases.

Patrick Steinhardt's v2 patch adds a simple `FREE_AND_NULL(ctx->orig_dir)` cleanup when the `chdir()` fails, maintaining the existing error return behavior. The fix has been technically validated by Jeff King, who demonstrated precise reproduction conditions, and approved by Junio Hamano. While the thread included discussion about adding a test for the long-path edge case, maintainers ultimately decided the existing t0301 test coverage was sufficient.

This is a straightforward, well-validated fix for a real (though edge-case) memory leak, demonstrating how Meson's stricter build configuration can surface issues that traditional builds miss. The patch is minimal (just 3 lines added) and ready for inclusion.
