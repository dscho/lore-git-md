This thread addresses a regression in Git's tag-following behavior during fetches, originally reported by Igor Todorovski. The issue emerged from an interaction between three recent changes to the fetch protocol, particularly affecting shallow fetches of specific commits where tags weren't being decorated properly. The root cause was commit 3f763ddf28 unconditionally adding "HEAD" to ref_prefixes, which conflicted with protocol v2's optimization logic.

After technical analysis from multiple contributors - including Bence Ferdinandy (original commit author), Taylor Blau, and Junio Hamano - Jeff King (Peff) proposed several solutions. The discussion evolved from a specific bugfix to broader questions about protocol v2's design, particularly around how multiple prefix components should interact.

The latest development is a concrete fix co-authored by Jeff King that makes the HEAD prefix conditional (mirroring existing tag-following logic) and adds a test case. This conservative solution resolves the immediate regression while being safe enough to potentially backport to the upcoming 2.49 release. The patch preserves protocol v2's advertisement semantics but leaves open larger architectural questions about prefix coordination for future work. While the immediate issue is now addressed, the thread has surfaced deeper design considerations that may need revisiting in future protocol iterations.
