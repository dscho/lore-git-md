This thread addresses a regression in Git's tag fetching behavior that occurs when fetching specific commits with depth limits under protocol v2. The issue was introduced by commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist"), which inadvertently broke tag decoration in `git log --decorate` output by preventing servers from returning tags unless explicitly requested.

Taylor Blau analyzed the interaction between three commits and proposed modifying `builtin/fetch.c` to unconditionally include "refs/tags/" when tag following is enabled. Bence Ferdinandy, the original author of the problematic commit, has now confirmed the issue and noted that similar problems have appeared before but remain unresolved. He tried two experimental fixes in his own repository—one that broke many things and another that worked but felt like a temporary solution—but the underlying behavior remains unclear. The discussion is waiting for input from protocol v2 experts to determine a proper fix that preserves both the intended optimizations and expected tag-fetching behavior. Key participants include Igor Todorovski (who reported the issue), Taylor Blau, and Bence Ferdinandy. The regression particularly affects shallow fetches where tag decoration is expected but missing.
