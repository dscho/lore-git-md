This thread concerns a regression in Git's tag fetching behavior when using protocol v2 with depth-limited fetches. The issue was introduced by Bence Ferdinandy's commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist"), which inadvertently broke tag decoration in `git log --decorate` output for shallow-fetched commits. Igor Todorovski originally reported the problem, demonstrating that tags previously visible in commit histories were now missing.

Taylor Blau has analyzed the issue and identified the root cause: the interaction between three commits affecting protocol v2 fetch behavior. The regression occurs because the problematic commit added "HEAD" to ref_prefixes, which now prevents the server from returning tags unless explicitly requested. Taylor has proposed a fix that would modify builtin/fetch.c to always include the tags prefix when tag following is enabled, but he's seeking confirmation from the original authors of the related commits (Bence Ferdinandy and others) since this touches subtle protocol v2 behavior.

The discussion has established this as a genuine regression with a plausible solution, though the fix requires careful review given its impact on fetch semantics. The thread is now awaiting input from the protocol experts involved in the original changes to confirm whether Taylor's proposed solution aligns with the intended behavior.
