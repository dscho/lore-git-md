Here's a human-readable summary of the thread:

A regression in Git's tag behavior was reported by Igor Todorov, where tags are no longer being fetched properly when fetching specific commits under certain conditions. The issue appears to have been introduced by commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist") from Bence Ferdinandy in November 2024. While that commit's main purpose was to properly set remote/HEAD references during fetch operations, it inadvertently changed how tags are handled when fetching specific commits with protocol version 2 and a depth limit.

The problem manifests when examining fetched commits with `git log --decorate` - where previously associated tags would be shown, now only the commit hash appears. Igor provided a clear reproduction case using the golang/go repository, demonstrating the difference between expected (tags included) and current (tags missing) behavior. The issue was first noted in the zopencommunity/gitport project's tracker, raising the question of whether this change was intentional or an accidental regression. The core of the problem seems to be in how commit-specific fetches now interact with tag decoration output.
