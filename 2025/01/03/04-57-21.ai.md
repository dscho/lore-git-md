This is a feature patch adding a new `--expire-to` option to `git gc`, part of a 2-patch series (this being the first part). The patch builds on existing functionality in `git repack` (added in commit 91badeb) that allows storing expired cruft packs in a specified directory.

The change adds the option to pass through the `--expire-to` parameter from `git gc` to the underlying `git repack` call, eliminating the need for users to manually chain `git repack --cruft --expire-to` with `git prune`. The implementation includes:
- Documentation updates in git-gc.txt
- Addition of `repack_expire_to` field to `gc_config` struct
- Passing the option through in `add_repack_all_option()`
- A new test case in t6500-gc.sh

The patch appears well-structured with clear commit message explaining the motivation and proper test coverage. This seems like a straightforward quality-of-life improvement for users managing cruft pack storage locations during garbage collection. The change is minimal and focused, just plumbing the existing repack option through the gc interface.
