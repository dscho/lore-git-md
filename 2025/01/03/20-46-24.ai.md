Bugfix for trace_printf-induced crash in combined diff machinery. Jeff King responds to Wink Saville's report of a segmentation fault when adding trace statements to `diff_tree_combined()`. The crash occurs because the debugging code attempts to access uninitialized `path.buf fields in the parent array when printing trace output. 

The root cause is that these strbufs are only initialized in `intersect_paths()` when `combined_all_paths` is set and there's an actual path change (copy/rename). Jeff provides a fix that checks these conditions before attempting to print the path contents, using NULL for uninitialized paths. The solution demonstrates careful understanding of the combined diff internals while maintaining the debugging intent of the original trace statements.

Key technical details for future reference: the crash occurs in `combine-diff.c` when tracing parent path information, specifically around the `path.buf` field of `struct combine_diff_parent`. The fix involves checking `rev->combine_all_paths` and `filename_changed(p->parent[i].status)` before accessing path contents. This is a good example of how debugging instrumentation can expose latent assumptions in code paths.
