CI modernization patch converting GitHub Actions Linux jobs to containerized execution. This is the fourth in Patrick Steinhardt's 10-part series improving Git's CI infrastructure.

The patch moves all remaining direct-execution Linux jobs in GitHub Actions to containerized runs, completing a transition started earlier in the series. The key motivation is increased flexibility in choosing execution environments - containerized runs allow selecting any container image rather than being limited to GitHub's preconfigured machine pools. The change affects 9 job configurations (linux-sha256, linux-reftable, linux-gcc, etc.) that previously ran directly on Ubuntu machines.

Technical changes include:
- Removes direct-execution job definitions from the first matrix
- Adds equivalent containerized versions in the existing container jobs matrix
- Preserves all existing job characteristics (compiler selection, test configurations)
- Uses Ubuntu images matching the previous machine pool versions (latest/20.04)
- Maintains the same environment variables and execution flow

This builds on the series' earlier security improvements (non-root execution in patch 3) while addressing the last remaining architectural difference between containerized and direct-execution jobs. The change is presented as a straightforward modernization with no expected performance impact, though it does significantly restructure the workflow file (68 lines modified). The patch maintains consistency with the series' broader goals of CI reliability and cross-platform testing while eliminating a legacy execution mode.
