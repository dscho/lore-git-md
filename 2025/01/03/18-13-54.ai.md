Maintenance feature adding automated remote ref pruning. This is the third iteration of Shubham Kanodia's patch to introduce a `prune-remote-refs` maintenance task that runs `git remote prune` across all configured remotes. The implementation now includes Junio Hamano's sign-off and several key refinements from earlier review feedback.

The patch adds a new maintenance task that addresses the problem scenarios where users want to prune stale remote-tracking branches without fetching new content (unlike `fetch.prune=true`) and without manual intervention (unlike direct `git remote prune` usage). The task is explicitly disabled by default due to its destructive potential, with documentation clearly warning about the opt-in nature and recommending `fetch.prune=true` for most users.

Technical changes since v2 include:
- Improved error handling that now reports failed remotes individually while continuing to process others, modeled after the existing prefetch task's behavior
- Documentation fixes including proper linkgit syntax and clearer scenario explanations
- Additional test coverage verifying the task's behavior with failing remotes
- Shared infrastructure for remote iteration error reporting between prune and prefetch tasks

The implementation now lives in Junio's integration branch "sk/maintenance-remote-prune", indicating maintainer approval pending final technical considerations around remote processing semantics. The patch appears ready for inclusion, having addressed all previously raised concerns while maintaining the careful opt-in safety model.
