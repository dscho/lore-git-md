This is a bugfix for Zsh shell completion that was broken by a previous change. The issue stems from commit 1e0ee4087e which introduced Bash-specific indirect variable expansion syntax (`${!var}`) that doesn't work in Zsh's ksh emulation mode. The patch replaces this with a portable `__git_indirect` helper function that uses `printf` and `eval` to safely expand variables in both shells.

The bug manifested when completing Git config variables, showing incorrect completions like "__git_first_level_config_vars_for_section_remote" instead of proper config options. The fix involves modifying several functions in git-completion.bash that handle config variable completion, replacing all instances of Bash's indirect expansion with calls to the new helper.

Philippe Blain confirms the fix works on their test systems (Bash 3.2.57 and Zsh 5.0.8) and suggests adding Zsh testing to CI to catch similar issues in the future, though notes the current completion test suite is Bash-specific. The patch appears well-tested with a demonstration program showing the indirect expansion works correctly across shells.

Key technical details for future reference: The new `__git_indirect` function uses `eval printf '%s' "\"\$$1\""` to safely expand variables without word splitting or globbing. The changes affect config completion for sections like branch.*, remote.*, and submodule.* where first and second level variables are completed. The fix maintains the same behavior while working across shells.
