CI modernization patch focusing on container security.

This is the third patch in Patrick Steinhardt's 10-part series modernizing Git's CI infrastructure. It modifies GitHub Actions container jobs to run tests as a non-root user rather than with elevated privileges. The change addresses test failures that occur when tests expecting restricted file permissions run under root, where those restrictions don't apply.

The patch makes two key changes: First, it adds a 'builder' user that executes the test suite via sudo, mirroring GitLab CI's existing approach. Second, it installs shadow-utils and sudo packages in Fedora/AlmaLinux containers to support this workflow. The changes affect both test execution and post-failure artifact collection in .github/workflows/main.yml.

This continues the series' theme of improving CI reliability across platforms while modernizing infrastructure. Running tests without root privileges better matches real-world usage scenarios and prevents permission-related test flakiness. The implementation appears straightforward, building on existing patterns from GitLab CI. No obvious technical concerns are present in the changes, which are focused and well-contained to the CI configuration files.
