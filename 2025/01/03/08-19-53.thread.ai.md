This thread addresses race condition hardening in Git's object file handling, building on commit 0ad3d65652. The series focuses on collision detection during object writing, with two patches now discussed. The second patch (newly summarized) implements Jeff King's suggested retry mechanism for a subtle race where destination files vanish between collision check and linking operations. It introduces a `CHECK_COLLISION_DEST_VANISHED` return code (-2) and corresponding retry logic in `finalize_object_file_flags()`, while removing special `ENOENT` handling for source files (which should never vanish). The changes modify about 60 lines in `object-file.c` with a +11 net addition, focused on `check_collision()` and `finalize_object_file_flags()`. This continues the project's documented effort to harden object storage reliability, with Jeff King's involvement signaling the importance of these race condition fixes.
