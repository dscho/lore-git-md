Documentation formatting fix for pathname rendering in gitcli.txt. This is the second patch in Martin Ågren's series addressing minor documentation rendering issues, following up on the git.txt heading fix in patch 1/2.

The patch corrects a formatting issue where pathnames containing tildes (like `~/directory/file`) were being misinterpreted by AsciiDoc processors as subscript markers, causing incorrect output in the rendered manpages. The fix wraps these pathnames in backticks to mark them as literal/verbatim text, which both prevents the subscript interpretation and aligns with Git's documentation style guidelines for literal values.

The change is minimal (a single line modified) but addresses a real rendering bug introduced in commit 1bc1e94091 from November 2024.
