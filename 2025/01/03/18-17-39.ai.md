This is a technical discussion about fixing a flaky SIGPIPE test in the submodule test suite, part of Patrick Steinhardt's CI modernization series.

Jeff King identifies a deeper issue with the SIGPIPE test in t7422 that wasn't fully addressed by Patrick's initial fix (which used `stdbuf` to make streams unbuffered). The core problem is that the test relies on timing - the submodule process might finish writing before grep exits, making SIGPIPE unreliable regardless of buffering. Jeff demonstrates this with a sleep-based reproduction case and proposes a more robust solution: filling the pipe buffer with dummy data to force blocking writes, ensuring SIGPIPE will occur when the reader exits early.

The suggested fix involves:
1. Pre-filling the pipe with 128KB of dummy data using Perl (test_seq can't be used due to shell function limitations)
2. Using `head -n 1` instead of grep since pattern matching isn't actually needed
3. Keeping the submodule status check as the second writer that will block
4. Removing the sleep once the approach is validated
