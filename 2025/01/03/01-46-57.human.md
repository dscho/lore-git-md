Refactoring patch in the commit-reach subsystem to improve type safety.

This is part of a series (4/9) addressing signed/unsigned integer comparisons in the commit-reach code. The patch changes `remove_redundant()` and related functions to use `size_t` for array indices instead of `int`, eliminating compiler warnings about signed/unsigned comparisons. The change is cleanly implemented by splitting the previous dual-purpose return value (which could indicate either an error code or a count) into separate error code and out-parameter for the count.

The patch appears well-considered, maintaining the same functionality while improving type safety. Justin Tobler's response indicates agreement with Patrick Steinhardt's approach, noting the sensible separation of concerns in the new design. The change is localized to internal implementation details and shouldn't affect callers, though the series notes that related functions in `get_merge_bases_many()` will need similar treatment in a later patch.
