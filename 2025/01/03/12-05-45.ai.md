Performance optimization follow-up discussing test infrastructure changes for LSan leak detection. Patrick Steinhardt suggests a potential simplification to Jeff King's patch that filters false positive leak reports from LSan's thread stack traces. The current implementation uses `xargs` to chain `grep` calls, which Patrick questions could be replaced with `find -exec` for better readability around the negation operator (`!`).

This is part of the ongoing series addressing LSan race conditions in threaded test execution (patch 4/6). The specific change being discussed modifies `test-lib.sh` to consolidate leak checking logic and filter out known false positives from LSan's output. Patrick's suggestion focuses on the implementation detail of how the filtering is performed, proposing an alternative that might make the negation behavior clearer.

Key technical details:
- The code filters LSan output files matching `$TEST_RESULTS_SAN_FILE_PFX.*`
- Current implementation pipes `find` output through `xargs grep`
- Proposed alternative would use `find`'s `-exec` with `+` terminator
- Both approaches aim to exclude "Unable to get registers from thread" stack traces
- Discussion centers on portability and readability tradeoffs

This is a minor implementation detail in the larger context of the series, which has already been merged with maintainer approval. The exchange demonstrates the project's attention to code clarity even in test infrastructure changes.
