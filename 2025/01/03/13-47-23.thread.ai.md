Standardizing git-commit man page documentation (3-part series) - Jean-Noël Avila's ongoing effort to convert Git's man pages to consistent AsciiDoc synopsis format. The series standardizes formatting of git-commit documentation with no functional changes.

First patch converted git-commit.txt to new guidelines: introduced synopsis blocks for automatic formatting, standardized _<placeholder>_ notation, used backticks for command/option references, and updated cross-references (276 lines changed). Second patch reformatted Documentation/config/commit.txt with mechanical changes: wrapping config keys (`commit.cleanup`, `commit.gpgSign`) and boolean values in backticks, standardizing cross-references using new `see-git-commit` variable to avoid self-referential links, and introducing conditional AsciiDoc directives (`ifdef::git-commit[]`). Third and final patch completes the series by applying identical mechanical formatting to supporting documentation files (`i18n.txt` and `signoff-option.txt`), converting single-quoted references to backtick-wrapped format (e.g., `'git commit'` → `` `git commit` ``) and standardizing option flag presentation (e.g., `--signoff` → `` `--signoff` ``) while maintaining conditional AsciiDoc directives from patch 2. Total changes across all three patches are purely presentational (297 lines modified) with no content modifications or functional impact.

This series represents a continuation of Git's documentation modernization effort, following established patterns from prior accepted documentation work. All changes were mechanical updates conforming to project's evolving AsciiDoc standards, with no technical objections raised during review. The work is now complete, having standardized the git-commit documentation ecosystem (main command, configuration, and supporting files) to current presentation guidelines as part of Jean-Noël Avila's broader initiative to bring consistency to Git's documentation.
