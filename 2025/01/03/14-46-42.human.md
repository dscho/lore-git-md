CI infrastructure cleanup in Patrick Steinhardt's modernization series. This patch (5/10) simplifies how Linux job distributions are specified in GitHub Actions workflows by eliminating redundant distro name declarations. Instead of maintaining separate `distro` and `image` fields that were nearly identical (differing only in colon-to-dash conversion), the patch standardizes on using the container image name directly.

The change affects 3 files, primarily removing duplicate distro specifications from 9 job definitions in `.github/workflows/main.yml`. Two special cases are handled: the "linux32" job gets renamed to match its image path (`i386/ubuntu`), while Alpine and Fedora jobs now explicitly use the "latest" tag. The actual distro name is now derived from the image name in `ci/lib.sh` using a simple string substitution.

This is a logical cleanup that follows the pattern already established in GitLab CI, reducing maintenance overhead by having a single source of truth for container specifications. The patch appears straightforward with no obvious technical issues, though reviewers might want to verify the "linux32" job rename doesn't break any assumptions in the test infrastructure.
