Documentation formatting fix for pathname rendering in gitcli.txt. This is the second patch in Martin Ågren's series addressing minor documentation display issues for Git 2.48.0.

The patch fixes how pathnames containing tildes (like `~/directory/file`) are rendered in the manpage. The current formatting causes AsciiDoc tools to incorrectly interpret the tildes as subscript markers, resulting in broken display. The solution is to wrap these pathnames in backticks, which both prevents the subscript interpretation and follows Git's documentation guidelines for literal values.

This is a straightforward one-line change that corrects a visual artifact without altering the actual content. The fix maintains consistency with Git's documentation style while ensuring proper rendering across different AsciiDoc processors. Like the first patch in the series, this is a clean, focused improvement to documentation presentation.
