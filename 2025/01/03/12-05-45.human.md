This is a technical follow-up in the performance optimization series addressing LSan race conditions in test execution. Patrick Steinhardt suggests a minor improvement to patch 4/6's leak detection logic in `test-lib.sh`, proposing to replace the `xargs` pipeline with `find -exec` for better readability and possibly portability.

The suggestion focuses on the command that filters out false positive leak reports from LSan, specifically those containing "Unable to get registers from thread". The current implementation uses `find | xargs grep`, while Patrick questions whether `find -exec grep` would be clearer, especially regarding how the negation (`!`) interacts with the pipe.

This is a small but thoughtful refinement to an already merged solution (the series was completed with a shift from thread synchronization to output filtering). The exchange shows ongoing attention to code quality even after the main technical direction was settled, with Patrick offering a potential cleanup to make the leak detection logic more straightforward.
