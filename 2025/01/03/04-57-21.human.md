Feature addition to `git gc` with new `--expire-to` option for cruft pack management.

This is the first patch in a two-part series (though the second patch isn't shown here) that adds a new `--expire-to` option to `git gc`. The option mirrors existing functionality in `git repack`, allowing users to specify a directory where expired cruft packs should be stored during garbage collection. Currently, achieving this requires running `git repack` and `git prune` separately - this change streamlines the workflow by letting `gc` handle it in one step.

The implementation is straightforward, passing the option through to the underlying `repack` command. The patch includes documentation updates and a new test case to verify the behavior. The change appears well-contained, touching only the expected files (gc.c, its docs, and tests). The commit message clearly explains the motivation and connects it to prior work (commit 91badeb which added similar functionality to `repack`).

This seems like a logical quality-of-life improvement for users who want to maintain backup locations for their cruft packs.
