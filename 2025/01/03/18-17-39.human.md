**Bugfix follow-up in CI modernization series**

Jeff King responds to Patrick Steinhardt's patch that attempted to fix a flaky SIGPIPE test in t7422 (submodule output). While Patrick's solution used `stdbuf` to make streams unbuffered, Jeff demonstrates this isn't sufficient - the test can still fail if the submodule process completes before the pipe is closed.

Jeff provides a more robust solution that forces the pipe buffer to fill by:
1. First stuffing the pipe with dummy data using Perl
2. Then running the actual submodule command
3. Using `head` (rather than `grep`) to immediately close the pipe after first line

The response includes detailed test modifications and explains why certain approaches (like using shell functions) don't work due to SIGPIPE behavior. This is a technical refinement to an earlier patch in Patrick's CI modernization series, showing careful attention to test reliability.
