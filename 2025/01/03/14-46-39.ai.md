This is a test fix addressing flakiness in the submodule SIGPIPE propagation test, part of Patrick Steinhardt's larger CI modernization series.

The patch fixes an intermittent failure in t7422 where a test checking SIGPIPE propagation in `git submodule status --recursive` would sometimes pass when it should fail. The root cause is buffered I/O - the test uses grep to terminate the pipe early (triggering SIGPIPE), but buffering means the submodule process might complete before the signal is delivered. The fix makes both the Git command and grep use unbuffered I/O via `stdbuf -oL` and `stdbuf -i0` respectively, and adds a new STDBUF prerequisite.

The change is minimal (7+/3- lines) but addresses a subtle race condition. The author notes the flakiness was hard to reproduce (only seen once under stress testing), so the fix's effectiveness isn't fully proven. The test remains skipped on MINGW (Windows) where signal handling differs. This appears to be a well-reasoned fix for a real but rare CI flakiness issue, though reviewers might want to verify the stdbuf approach is portable across all target platforms.
