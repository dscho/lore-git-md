Feature: Automated remote ref pruning via maintenance task

Shubham Kanodia's patch adds a new `prune-remote-refs` maintenance task that automatically runs `git remote prune` on all configured remotes. This addresses the problem of stale remote-tracking branches accumulating when users don't perform full updates, which can degrade performance. The task is disabled by default due to its potentially destructive nature.

The implementation builds on the existing maintenance infrastructure, running daily when enabled. It includes improved error handling that continues processing other remotes if one fails, reporting all failures at the end. The documentation clearly explains the opt-in nature and when this might be preferable to `fetch.prune=true` (primarily for selective fetching workflows).

This is the third iteration of the patch, now with maintainer sign-off from Junio Hamano. The changes since v2 include better commit message formatting, documentation improvements, and shared error handling infrastructure with the prefetch task. The patch appears well-tested with new scenarios verifying partial failure cases.
