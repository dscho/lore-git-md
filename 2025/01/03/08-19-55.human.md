**Bugfix addressing a race condition in Git's object file handling**

This is the second patch in a series hardening Git's object storage against race conditions, following up on Jeff King's earlier suggestions. It specifically handles the case where a destination file vanishes between the collision check and linking operations - a subtle timing window that could previously cause failures.

The patch modifies `object-file.c` to retry the linking operation when the destination file disappears during the collision check (detected via a new `CHECK_COLLISION_DEST_VANISHED` return code). This makes the operation more robust against concurrent processes. It also tightens error handling by no longer silently ignoring missing source files (which should never happen with temporary files) - now treating this as a real error.

The changes are relatively small (17 lines added, 6 removed) but address an important edge case in the object storage system. The patch builds logically on the first in the series (which was purely refactoring) and shows careful attention to the race condition scenarios that can occur in concurrent Git operations. Given Jeff King's prior involvement and the clear technical rationale, this appears to be a well-considered improvement to Git's object storage reliability.
