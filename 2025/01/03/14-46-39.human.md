This is a test fix addressing flakiness in the submodule SIGPIPE test. The patch is part of Patrick Steinhardt's 10-part CI modernization series, though it stands alone as a specific test improvement.

The test in t7422 checks whether `git submodule status --recursive` properly handles SIGPIPE when its output pipe is closed early. The test was flaky because it relied on grep terminating the pipe at exactly the right moment - if the submodule process finished before grep closed the pipe, no SIGPIPE would occur. The fix makes both the Git command and grep use unbuffered I/O via `stdbuf` to ensure the pipe closes at the intended moment.

The change is minimal (7 lines added, 3 removed) but addresses a subtle race condition. The author notes the flakiness was hard to reproduce, only occurring once during extended stress testing, so the fix's effectiveness isn't fully proven. The test remains skipped on MINGW (Windows) platforms and now requires the `stdbuf` utility as a new prerequisite.

This appears to be a well-reasoned fix for an intermittent test failure, though rare, could cause confusion in CI runs. The solution follows the pattern of making test timing more deterministic while maintaining the original test's intent.
