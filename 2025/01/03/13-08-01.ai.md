This is a bugfix patch addressing a segfault in `git fast-import`, part of an ongoing discussion about hash function safety. The thread involves Patrick Steinhardt and Taylor Blau working through the proper way to handle hash initialization in the fast-import code.

The immediate fix changes `init_fn` to `unsafe_init_fn` in `stream_blob()` to match what the hashfile API uses, preventing the segfault. However, both authors acknowledge this is still brittle - the hash function implementation needs to stay in sync between components. The discussion then shifts to a more robust long-term solution where the hash function type would be stored in `struct git_hash_ctx` itself, eliminating the need for callers to track which variant to use.

Key technical details: the patch touches `builtin/fast-import.c`, specifically the hash initialization in `stream_blob()`. The proposed architectural change would modify `struct git_hash_ctx` to remember its initialization method, with new APIs like `git_hash_sha1_init()` that set this state internally. This builds on prior work around `unsafe_hash_algo()` and relates to broader hash function safety concerns in the codebase. The discussion suggests this may be coordinated with Meson build system changes.
