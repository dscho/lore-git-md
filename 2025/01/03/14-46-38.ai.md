This is a test fix addressing MinGW-specific CI flakiness, part of Patrick Steinhardt's larger CI modernization series. The patch resolves an intermittent EBUSY error in t0060 that occurs when copying the Git executable during runtime prefix tests on Windows. The error suggests the binary remains locked by some process (possibly MinGW or Windows itself) between test cases, though the exact cause remains unclear.

The solution refactors the test setup by extracting the common binary-copying operation into a dedicated setup` test case, avoiding the need to overwrite the file in subsequent tests. The change is minimal (6 lines added, 4 removed) and focused solely on the test file t/t0060-path-utils.sh. While the workaround is pragmatic, the commit message notes the underlying cause remains mysterious, leaving room for future investigation into why Windows holds the file open between test executions.

Key technical details for future reference: the fix affects two test cases (`RUNTIME_PREFIX works` and `%(prefix)/ works`) that verify Git's ability to locate its installation prefix at runtime. The tests now rely on a new shared `setup runtime prefix` prerequisite that copies the git binary once rather than redundantly in each test. The prereqs (!VALGRIND,RUNTIME_PREFIX,CAN_EXEC_IN_PWD) remain unchanged, indicating this is specifically testing runtime prefix behavior under normal execution conditions.
