This is a discussion about improving hash function handling in Git's internals, building on a recent bugfix for `git fast-import`.

Junio Hamano agrees with Patrick Steinhardt's proposal to restructure how hash functions are managed in Git's core. The current approach requires callers to track which hash variant (SHA-1 or SHA-256) they're using, which led to a segfault in `fast-import` that was recently patched with a temporary fix.

The proposed solution would embed the hash function information directly in `struct git_hash_ctx`, making the API more robust by eliminating the need for callers to track this state. The example shows how this would work: initialization would set the hash type once (e.g. `git_hash_sha1_init`), and subsequent operations would automatically use the correct variant.

This discussion represents the next step after the immediate bugfix, moving toward a more maintainable architecture for hash handling. The change would affect multiple parts of Git's codebase and appears to be gaining consensus among core maintainers.
