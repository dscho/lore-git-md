This is part 4/5 of a refactoring series in the `the_repository` removal effort, converting the `write_rev_file()` family of functions to take explicit `hash_algo` parameters instead of using the global `the_hash_algo`. The patch modifies `write_rev_file()`, `write_rev_file_order()`, and `write_rev_header()` to accept a `const struct git_hash_algo*` parameter, propagating this change through their callers in `index-pack.c`, `midx-write.c`, and `pack-write.c`.

Key technical changes include:
- Updated function signatures in `pack.h` to include the new `hash_algo` parameter
- Modified `write_rev_header()` to use the passed algorithm's version rather than the global
- Converted callers in `index-pack.c` and `pack-write.c` to pass `the_hash_algo` temporarily for compatibility
- Special handling in `midx-write.c` where repository context is already available, avoiding reintroduction of globals

The implementation follows the series' established pattern of mechanical refactoring without behavior change, pushing global variable usage up to callers while noting this is a temporary measure. The commit message acknowledges this intermediate state, explaining the compatibility-preserving approach of passing `the_hash_algo` from upper layers while fully converting the lower-level functions. This continues the thread's theme of precise parameter flow documentation, with the midx case demonstrating how repository-aware contexts can avoid global usage entirely.
