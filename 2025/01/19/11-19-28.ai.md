This is part 3/5 of a refactoring series in the `the_repository` removal effort, converting pack-writing functions to explicitly take hash algorithm parameters rather than using the global `the_hash_algo`. The patch focuses on `write_idx_file()` and its caller `stage_tmp_packfiles()` in `pack-write.c`.

The changes propagate a `const struct git_hash_algo*` parameter through these functions, replacing direct usage of `the_hash_algo`. While the upper layers still pass `the_hash_algo` for now (maintaining compatibility), this pushes the global variable usage up the call stack where it can be addressed later. The implementation follows the series' established pattern of mechanical refactoring without behavior change.

Key technical details:
- Updates function signatures in `pack.h` to include the new `hash_algo` parameter
- Modifies `write_idx_file()` to use the passed algorithm's `rawsz` rather than the global
- Converts `stage_tmp_packfiles()` to take and forward the hash algorithm
- Updates callers in `fast-import.c`, `index-pack.c`, `pack-objects.c`, and `bulk-checkin.c` to pass `the_hash_algo` temporarily

This continues the thread's pattern of precise technical implementation with careful documentation, following earlier feedback about accurately describing the passing of full algorithm structs rather than just hash functions. The changes are straightforward and maintain compatibility while making progress toward the series' goal of eliminating global variable usage in pack-writing code.
