Refactoring patch in a series addressing sparc64 SIGBUS crashes in pack handling. This is the second of five patches in v2 of the series.

The patch factors out duplicate `--pack_header` argument parsing code from `index-pack` and `unpack-objects` into a new shared function `parse_pack_header_option()` in `packfile.c`. This prepares for the alignment fixes coming in later patches by centralizing the pack header handling. The function maintains the same behavior as the original code - parsing version and entry count from a string like "2,42" and writing the corresponding packed header bytes to a buffer.

Key technical details:
- New function `parse_pack_header_option()` takes input string, output buffer, and length pointer
- Still uses direct struct cast (alignment issues to be fixed in later patches)
- Returns -1 on parse errors, 0 on success
- Callers remain responsible for option detection and error reporting
- `unpack-objects` error messages now marked for translation to match `index-pack`
- Touches `builtin/index-pack.c`, `builtin/unpack-objects.c`, `packfile.[ch]`

This is a preparatory refactoring that makes the actual alignment fixes easier to implement consistently. The patch maintains all existing behavior while reducing duplication. The thread context shows this is part of a well-reviewed series addressing a real platform-specific crash bug.
