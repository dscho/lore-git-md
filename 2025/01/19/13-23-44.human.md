This is a bugfix patch addressing alignment issues in Git's pack handling on sparc64 systems. It's part of Jeff King's v2 series (3/5) that comprehensively fixes SIGBUS crashes when reading/writing pack headers on architectures with strict alignment requirements.

The patch modifies `parse_pack_header_option()` in packfile.c to avoid direct struct writes that could trigger unaligned memory access. Instead of casting the buffer to a `struct pack_header` and assigning fields directly, it now uses the alignment-safe `put_be32()` function to write individual bytes. This change maintains the same functionality while preventing crashes on sparc64.

The patch builds on earlier work in the series that introduced this helper function to consolidate pack header parsing logic. It's a focused change that completes the alignment protection for both read and write operations across Git's pack handling code. The solution has evolved through maintainer review and appears technically sound, with careful attention to platform compatibility and code safety.
