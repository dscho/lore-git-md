Refactoring patch in the `the_repository` removal effort, converting `index_pack_lockfile()` to take an explicit repository parameter. This is patch 2/5 in a series eliminating global variable usage in pack-writing functionality.

The patch modifies `index_pack_lockfile()` to accept a `struct repository*` parameter instead of implicitly using `the_repository`. The function now uses the repository's hash algorithm rather than the global `the_hash_algo`. Callers in `builtin/receive-pack.c` and `fetch-pack.c` are updated to pass `the_repository` for now, maintaining compatibility while pushing the global variable usage up to higher layers where it can be addressed later.

The implementation follows the series' established pattern of mechanical refactoring without behavior change. The commit message notes this is an intermediate step that still relies on `the_repository` at the caller level, consistent with the incremental approach seen in previous patches. The changes touch core pack-writing functionality but are straightforward - replacing global variable access with parameter passing while preserving all existing behavior.
