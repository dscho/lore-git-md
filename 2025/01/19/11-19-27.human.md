This is part 2/5 of a series in the `the_repository` removal effort, converting `index_pack_lockfile()` to take an explicit repository parameter instead of relying on the global `the_repository`. The patch follows the series' established pattern of pushing global variable usage up to callers while maintaining compatibility - here by having callers pass `the_repository` for now.

The change is straightforward: the function now takes a `struct repository*` parameter and uses it to access the hash algorithm and object directory rather than using the globals directly. The patch updates three callers in `builtin/receive-pack.c`, `fetch-pack.c`, and the function's own implementation in `pack-write.c`, plus the declaration in `pack.h`.

As with other patches in this series, the implementation appears technically sound, though the commit message notes this is an intermediate step that still relies on `the_repository` being passed from callers. The changes are mechanical and well-contained, touching only pack-related functionality. This continues the incremental approach seen throughout the series of converting lower-level functions first while maintaining compatibility in upper layers.
