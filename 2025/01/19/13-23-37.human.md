This is a refactoring patch in Jeff King's series addressing sparc64 alignment issues in Git's pack handling. It factors out the duplicated `--pack_header` argument handling from both `index-pack` and `unpack-objects` into a new shared function in `packfile.c`.

The patch moves the logic for parsing the pack header format (signature, version, and entry count) into a new `parse_pack_header_option()` function, which both commands now call. While this doesn't directly fix the alignment bug, it's a preparatory step that makes the subsequent fixes cleaner by centralizing the pack header manipulation code.

Notable changes include:
- Both commands now use the same error handling (including marking errors for translation)
- The core parsing logic is now in one place rather than duplicated
- The new function is properly documented in `packfile.h`

This is part 2 of 5 in the series, following an initial patch that addressed static analyzer warnings in byte-swapping utilities. The refactoring here sets up for the actual alignment fixes that will come in later patches. The changes are straightforward and maintain the same behavior while improving code organization.
