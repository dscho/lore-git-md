This is the third and final part of René Scharfe's series refactoring memory management in Git's ref-filter subsystem, completing the migration to storing commit references directly in atom structs. The patch removes the now-obsolete `bases` string list and its associated cleanup code, since ahead-behind calculations now use the same atom-struct storage pattern that was previously implemented for is-base functionality.

The changes are purely mechanical cleanup - all behavior remains the same. The key technical changes include:
- Removing the global `bases` string list
- Storing commit references directly in the `base` struct within each atom
- Updating the ahead-behind calculation logic to count bases from atom structs
- Removing now-unused initialization and cleanup functions
- Adjusting the iterative format check to look at atom types rather than the removed global list

This completes the architectural shift to atom-based state management that was started in parts 1 and 2 of the series. With all three parts now posted and the maintainer having signaled approval of the technical direction, this appears ready for final review and merging. The series as a whole provides cleaner memory management while maintaining all existing functionality.
