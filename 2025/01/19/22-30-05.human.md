Bugfix for worktree detection in bare repositories with worktree-specific configs. This patch addresses a specific issue where secondary worktrees incorrectly report the main worktree as non-bare when the main repository has `core.bare=true` in its worktree config.

The problem manifests when trying to perform operations like checking out the main branch from a secondary worktree - the incorrect bare status detection prevents these operations. The fix introduces a new `is_bare_git_dir()` helper that properly checks both the main config and worktree-specific config for the `core.bare` setting.

Eric Sunshine's review confirms this is a real problem that was previously noted in a NEEDSWORK comment. He suggests some minor improvements to the commit message clarity and test naming, but agrees the technical approach is sound. The patch maintains existing behavior where possible while fixing the specific bare-repo case, and includes test coverage demonstrating the fixed behavior.

This appears to be a well-motivated fix for a concrete issue, with careful consideration given to maintaining backward compatibility. The changes are focused on the specific problem area in worktree.c without attempting broader architectural changes to repository handling.
