This is part of Jeff King's bugfix series addressing sparc64 alignment issues in Git's pack handling. The patch focuses on `parse_pack_header_option()` in packfile.c, which was identified as another location where unaligned memory writes could cause SIGBUS crashes on sparc64 when compiled with clang.

The change replaces direct struct writes with byte-by-byte operations using `put_be32()`, similar to the approach taken in earlier patches of the series. The function now:
- Uses an unsigned char pointer instead of casting to struct pack_header
- Writes each 32-bit field individually with `put_be32()`
- Manually tracks buffer position with pointer arithmetic
- Updates the length calculation to match the new approach

This maintains the same functionality while avoiding alignment issues. The patch is part of a comprehensive solution that has evolved through maintainer feedback, now covering both read and write operations across multiple pack-handling components. The changes are focused on packfile.c but relate to the series' broader goal of making pack operations safe on strict-alignment architectures.
