Refactoring patch completing the ref-filter memory management transition.

This is the third and final patch in René Scharfe's series to migrate ahead-behind and is-base calculations from global state to per-atom storage. Building on the previous patches that moved is-base functionality, this one completes the transition by:

1. Removing the global `bases` string list and moving ahead-behind commit references into the `used_atom` struct's new `base` field, matching the pattern established for is-base
2. Updating `ahead_behind_atom_parser()` to store commits directly in the atom struct
3. Modifying `filter_ahead_behind()` to iterate through atoms rather than the removed global list
4. Adjusting the iterative format check to look for ahead-behind atoms instead of the global state
5. Removing now-unused `bases` cleanup from `ref_array_clear()`

The changes are mechanical and maintain the same behavior while eliminating the last remaining global state management in this subsystem. The patch follows through on the architectural direction previously approved by Junio Hamano, completing the transition to atom-based state storage that was partially implemented in the first two patches of the series.

Key technical details preserved for future reference:
- New `base` struct field in `used_atom` storing commit pointers
- Modified ahead-behind calculation now counts active atoms instead of global list items
- All memory management now handled through `ref_array_clear()`
- No behavior changes - purely internal API cleanup
- Completes removal of `ref_format`-based memory management

With this patch, the series achieves its goal of eliminating shared state while maintaining all existing functionality, resolving the memory management issues that prompted the original discussion. The implementation appears clean and consistent with the established pattern.
