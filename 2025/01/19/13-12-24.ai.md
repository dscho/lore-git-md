Bugfix series addressing sparc64 SIGBUS crashes in pack handling (v2)

This is the second version of Jeff King's series fixing alignment-related crashes on sparc64 when using `unpack-objects` and `index-pack`. The patches now comprehensively address both read and write sides of the pack header operations that were causing SIGBUS due to misaligned memory access.

The series consists of 5 patches building on previous discussion:
1. Silences sparse analyzer warnings about potential truncation in `put_be32()`
2. Factors out pack header argument parsing into a shared function
3. Fixes unaligned writes by using `put_be32()` for pack header operations
4. Applies similar alignment-safe `get_be32()` approach to reading pack headers
5. Cleans up magic numbers using `skip_prefix()`

Key technical improvements in v2:
- Completes the alignment fixes by covering read operations (previously only writes were fixed)
- Incorporates Junio Hamano's suggestion for handling sparse warnings
- Maintains the union-based approach for alignment safety
- Touches multiple components: builtins, packfile handling, and compatibility layers

The changes span several files but focus on making pack header operations alignment-safe while improving code organization. The series appears ready for final review, having addressed both the core issue and ancillary concerns raised in the thread.
