This is a documentation patch that follows up on a resolved reftable migration bug. Karthik Nayak proposes adding guidelines to `SubmittingPatches` about how to handle fixes for bugs discovered in topics already merged to `next`.

The patch comes after the final refinement of a reftable migration fix that was flaky on macOS with leak sanitizer enabled. Junio Hamano suggested documenting such fixes since they represent valuable learning opportunities - bugs that slipped through thorough review. Karthik agrees and submits this documentation addition while also preparing the macOS-specific refinement as a separate patch.

The proposed documentation explains that fixes for `next`-merged topics should be relative patches (not replacements) that describe: the original unnoticed issue, who reported it, and the fix details. This contrasts with `seen` branch patches which can be more freely revised. The patch is straightforward and uncontroversial, simply codifying existing practice that emerged during this reftable fix process. It's a small but useful addition to contributor guidelines that could help prevent similar review oversights in the future.
