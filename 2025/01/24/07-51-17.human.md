This is a technical discussion in the ongoing bugfix series for packed-refs validation (currently at v1, patch 4/10). Patrick Steinhardt responds to shejialuo's concerns about race condition handling in the packed-refs header check.

The exchange focuses on whether to add more robust race condition protection when reading the packed-refs file. Patrick had previously suggested using `open(O_NOFOLLOW)` and `fstat` to prevent symlink attacks between the existence check and file read. Shejialuo expressed concern this would complicate the code without fully eliminating races.

Patrick clarifies that his proposed solution would only add two function calls, keeping complexity minimal, and that they only need to ensure correctness at check time - not guard against changes that might occur during the check itself. He agrees they shouldn't need to handle post-read modifications.

This is a focused technical discussion about the tradeoffs between robustness and complexity in file handling, with Patrick maintaining that the additional safety measures are worth their modest implementation cost. The conversation shows careful consideration of edge cases while keeping the focus on practical needs of the validation system.
