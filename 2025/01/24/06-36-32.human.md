Bugfix for Windows reftable file locking behavior. Patrick Steinhardt responds to Christian Reich's report about interactive prompts appearing when Git fails to unlink locked reftable files on Windows. The issue stems from `mingw_unlink()`'s aggressive retry behavior when files are locked (typically by JGit), which contradicts the reftable specification's expectation that failed unlinks should be silently skipped.

Steinhardt identifies the problem occurs in multiple locations - during `reftable_stack_clean()` and stack reloading - but notes these failed unlinks should be harmless. The core issue is that Windows-specific error handling in `mingw_unlink()` prompts the user unnecessarily when it encounters locked files, rather than silently failing as expected.

The response indicates a forthcoming patch will address this by modifying the Windows-specific unlink behavior to better align with the reftable specification's expectations. This appears to be a focused fix targeting a clear platform-specific divergence between documented and actual behavior.
