This is a bug report about parallel fetch operations repeatedly prompting for SSH key passwords when they should only ask once. The issue occurs when running `git fetch --all --tags --prune --jobs=10` - instead of using the SSH agent's cached credentials after the first unlock, each parallel fetch process appears to independently prompt for the key password. The reporter confirms the expected behavior works with a single-threaded `git fetch`, where the key is properly cached in the SSH session.

The problem manifests on a modern Linux system (Arch Linux with kernel 6.12.10) using Git 2.48.1 with OpenSSL 3.4.0. The core issue seems to be that the SSH credential caching mechanism isn't being properly shared across the parallel fetch worker processes, leading to repeated password prompts that prevent the operation from completing successfully. This would be particularly problematic for users with many remotes configured who rely on parallel fetches for performance. The report provides clear reproduction steps and system details but doesn't include any proposed solution or analysis of the underlying cause.
