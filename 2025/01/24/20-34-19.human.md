Clarification on SSH credential handling in parallel fetches.

Brian M. Carlson responds to a bug report about repeated SSH key prompts during parallel fetch operations, explaining Git's limited role in SSH authentication. The key point is that Git itself doesn't handle SSH passphrases - it merely passes file descriptors to the SSH client, which manages all authentication. This means Git has no visibility into whether credentials are cached or when prompts occur.

The response emphasizes that solutions must come from the SSH layer rather than Git. Carlson notes that even querying an SSH agent wouldn't reliably prevent prompts, as some may require re-authentication per use. They suggest two practical workarounds: explicitly adding keys to ssh-agent before fetching, or using a password manager that handles SSH authentication with single-prompt behavior.

This email reinforces the technical boundary between Git and SSH credential management that was discussed earlier in the thread, while providing concrete recommendations for users experiencing the issue. The explanation makes clear why Git project is unlikely to implement changes to address this behavior, as the prompting occurs outside Git's control.
