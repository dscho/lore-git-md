This is a feature patch adding `--expire-to` support to `git gc`, mirroring existing `git repack` functionality for cruft pack management. The patch is now in its fourth iteration, having incorporated all substantive review feedback from previous versions.

The change allows specifying a directory where expired cruft packs should be stored during garbage collection, particularly useful for server-side maintenance workflows. Key technical aspects include:
- New `repack_expire_to` field in `gc_config` structure
- Modified `add_repack_all_option()` to handle the new parameter while maintaining backward compatibility
- Special handling of `-a` flag skipping when both `--cruft` and `--expire-to` are specified
- Documentation updates in `git-gc.txt` explicitly stating the cruft pack requirement
- Comprehensive test coverage in t6500-gc.sh verifying various option combinations

The v4 changes focus on documentation improvements and additional test cases:
