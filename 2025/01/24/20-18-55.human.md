Maintainer response to parallel fetch SSH prompt issue.

Junio Hamano responds to the bug report about repeated SSH key prompts during parallel fetch operations. He questions some assumptions in the original report, noting that without knowing how many repositories are involved or their credential requirements, it's hard to diagnose the exact issue. 

Hamano suggests two possible explanations for the reported behavior: either the SSH passphrase was entered incorrectly (causing repeated failures), or the user isn't using ssh-agent at all. He shares his own workflow where he explicitly adds keys to ssh-agent before operations, contrasting with the reported scenario where keys might be added on-demand via AddKeysToAgent.

The response casts doubt on whether the proposed "wait for first connection" solution would work universally, since Git can't know if subsequent connections would use the same credentials. Hamano leaves the door open for others with more AddKeysToAgent experience to weigh in, while maintaining a skeptical stance about whether this represents a Git bug versus an SSH configuration matter. The footnote raises an additional question about what exactly "does not succeed" means when fetching from multiple remotes.
