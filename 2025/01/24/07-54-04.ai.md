This is a discussion about ref validation architecture in the ongoing bugfix series for packed-refs handling. Patrick Steinhardt responds to shejialuo's implementation approach in patch 1/10, which currently validates regular refs by parsing objects directly after file format checks. 

Patrick reiterates his vision for backend-agnostic validation through `git refs verify`, arguing that object existence and type checks (currently implemented files-backend specifically) should be handled generically since they apply to all ref backends like reftable. While acknowledging shejialuo's efficiency argument for reusing already-parsed hex data, Patrick emphasizes the long-term maintainability benefits of separating format validation from semantic checks.

The exchange reveals architectural tension between immediate optimization (leveraging parsed data) and design purity (strict backend separation). Shejialuo has accepted postponing these checks for later restructuring, indicating the series will likely see significant reorganization in v2 to accommodate Patrick's backend-agnostic vision. This discussion sets the stage for subsequent patches to implement validation in a way that could be lifted into shared infrastructure later.
