This is a v3 patch series introducing a new `os-version` capability for Git's protocol v2, addressing both feature implementation and ongoing architectural discussions from previous rounds.

The series proposes adding OS version reporting to help with debugging, statistics, and security by letting clients and clients exchange sanitized OS information (just the OS name like "Linux" or "Windows"). The implementation uses `uname(2)` and follows similar sanitization rules as Git's existing `agent` capability.

Key changes in v3:
- Dropped the controversial `osversion.command` config that would execute arbitrary commands (rejected in previous reviews)
- Improved string sanitization using `isprint()`
- Better test formatting and documentation
- Simplified API by combining version retrieval and sanitization
- Added rationale for keeping OS version separate from the agent capability

The series still faces open questions about the feature's fundamental value (raised by Junio Hamano) and whether extending the existing user-agent capability might be preferable. Platform-specific handling for Windows and NonStop is now unified under a `compat/` layer approach.

The implementation looks clean and well-tested, though the core debate about whether this capability is needed at all remains unresolved. The author has addressed many technical concerns from previous rounds while maintaining the feature's original goals.
