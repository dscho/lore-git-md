This is a follow-up bugfix in the reftable migration series, addressing a macOS-specific edge case found during CI testing. The patch corrects uninitialized memory access in the reftable backend that could occur when migrating repositories with multiple worktrees.

The issue stems from how max_update_index values were being propagated when writing reftable transactions. While the original fix in Git 2.48.1 properly handled the core case, it only initialized the max_index for the first element in an array of transaction arguments. Karthik Nayak's patch now ensures all array elements are properly initialized by:
1. Adding zero initialization when preparing transaction updates
2. Moving the max_index assignment inside the transaction finish loop

The change is minimal (6 lines modified) but important for correctness, particularly on macOS where the uninitialized values were causing test flakiness under leak sanitizer. Johannes Schindelin identified the issue during CI testing, and this patch represents the final technical refinement in what has been a thorough debugging and fixing process for the reftable migration feature.
