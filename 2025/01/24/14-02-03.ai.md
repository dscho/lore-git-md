This is a follow-up bugfix in the reftable migration series, addressing a macOS-specific edge case identified during CI testing. The patch corrects uninitialized memory access in the reftable backend's transaction handling that could lead to undefined behavior when writing multiple worktree references.

The issue stems from how max_update_index values were propagated in the reftable writer. While the core fix (bc67b4ab5f) properly tracked the maximum index at the transaction level, it only initialized this value for the first element in the write_transaction_table_arg array. The patch makes two key changes: (1) adds explicit zero initialization of max_index in prepare_transaction_update(), and (2) moves the max_index assignment inside the worktree processing in reftable_be_transaction_finish() to ensure all array elements are properly set.

The changes maintain all core improvements from the original fix while addressing the platform-specific issue found under macOS's leak sanitizer. The zero initialization, while not strictly necessary with the new assignment logic, is included as a defensive measure against future code changes. This represents the final technical refinement in the reftable migration fix series, following earlier core fixes and edge case resolutions. The patch builds on the already-merged 'kn/reflog-migration-fix' and has been reviewed through the thread's established validation process.
