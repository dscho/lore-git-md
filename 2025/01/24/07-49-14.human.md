This is a feature patch adding `--expire-to` support to `git gc`, mirroring existing functionality in `git repack`. The change allows specifying a directory to store expired cruft packs during garbage collection, which is particularly useful for server-side maintenance workflows.

The patch has gone through four iterations with thorough review feedback incorporated. Key changes in v4 include improved documentation clarifying that `--expire-to` requires `--cruft`, better commit message explanation of the `-a` flag behavior change, and expanded test coverage for various option combinations (`--no-cruft`, `--prune=now`).

The implementation modifies `gc_config` to track the expire-to directory and updates `add_repack_all_option()` to handle the new parameter. When both `--cruft` and `--expire-to` are used, it skips the `-a` flag to `repack` and instead passes `--cruft`, `--expire-to`, and `--cruft-expiration=now` to properly handle the expired objects.

The patch appears well-tested and documented, with all substantive feedback from previous rounds addressed. It provides a useful quality-of-life improvement for users who want to manage cruft pack expiration more conveniently through `git gc`.
