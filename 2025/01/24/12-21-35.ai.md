This is a v3 resubmission of a feature series introducing OS version reporting capability to Git's protocol, following significant design changes from previous iterations. The series has evolved substantially based on feedback, most notably:

1. The controversial `osversion.command` config option (which allowed arbitrary command execution) has been completely removed in response to security concerns raised by Junio Hamano.

2. The implementation now uses a simplified sanitized-only API approach, with platform-specific handling unified under the `compat/` system (confirmed for both Windows and NonStop platforms).

Key technical aspects of the current proposal:
- Introduces `os-version` protocol field separate from `agent` capability
- Uses `uname(2)` syscall (or platform equivalents) to get OS name
- Implements sanitization via `isprint()` (resolving previous debate about manual checks)
- Adds `transfer.advertiseOSVersion` config (default true) for privacy control
- Disables Windows testing due to `uname` discrepancies
- Includes preparatory refactoring of version.c utilities

The cover letter provides expanded justification for having a separate OS version capability rather than extending the existing agent field, citing benefits for modularity, script compatibility, future extensibility, and security control. The series appears to have addressed most technical concerns from previous rounds while maintaining the core functionality, though Junio's fundamental question about the feature's value proposition remains open.
