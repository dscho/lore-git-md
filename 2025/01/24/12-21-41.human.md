Feature implementation adding OS version exchange to Git's protocol. This is the final patch in Usman Akinyemi's v3 series, introducing the `os-version` capability that allows Git clients and servers to exchange operating system information via the `uname(2)` system call. The patch adds:

1. A new `transfer.advertiseOSVersion` config option (defaulting to true) to control privacy
2. Protocol documentation specifying ASCII-printable-only sanitization
3. Server and client-side capability advertisement
4. Test updates, with special handling for Windows where `uname(2)` differs from the command-line version

The implementation follows the series' established patterns: platform-specific code lives in `compat/`, uses `isprint()` sanitization, and maintains the security model of no runtime command execution. While the technical implementation appears solid (with Christian Couder's mentorship), the thread's open question remains whether this feature's benefits justify its inclusion - the patch notes it could help with OS-specific debugging but doesn't provide concrete use cases. Windows testing is explicitly disabled due to output discrepancies between `uname(1)` and `uname(2)`.
