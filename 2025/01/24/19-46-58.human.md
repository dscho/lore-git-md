This is a bug report about parallel fetch operations repeatedly prompting for SSH key passwords. Perez-Lopez Áron Ricardo describes a scenario where running `git fetch --all --tags --prune --jobs=10` results in multiple password prompts for the same SSH key, rather than properly sharing the unlocked key across parallel fetch jobs as expected. The issue doesn't occur with a non-parallel fetch, which correctly caches the unlocked key in the SSH agent for subsequent operations.

The report includes clear reproduction steps and system information showing this occurs with Git 2.48.1 on an Arch Linux system. The behavior suggests a synchronization issue in how parallel fetch operations handle SSH key authentication - while the fetch jobs should coordinate to use a single unlocked key, they instead each attempt to unlock the key independently. This makes parallel fetch operations effectively unusable with password-protected SSH keys.

The report is well-structured with clear expectations versus actual behavior, though it doesn't propose a solution. This appears to be a legitimate usability issue that would affect anyone using parallel fetches with password-protected SSH keys.
