Feature proposal for credential helper authtype support across multiple platforms.

This email from M Hickford proposes extending the authtype capability, currently only implemented in `git-credential-cache`, to three other credential helpers: `git-credential-osxkeychain` (macOS), `git-credential-libsecret` (Linux), and `git-credential-wincred` (Windows). The authtype field would store non-confidential authentication type information alongside confidential credentials, with the primary use case being support for bearer tokens that might be generated by another helper.

The proposal references existing test infrastructure in t0303-credential-external.sh that could verify the new functionality, though it notes the test would need to be extended with a helper_test_authtype component. Implementation would involve modifying the platform-specific credential helper codebases, with links provided to all relevant source files. The author suggests this might be suitable as a #leftoverbits microproject, indicating they view it as a modest but useful enhancement rather than a major undertaking.

Key technical points for future reference: the change would involve adding authtype storage/retrieval to the credential helper protocol implementation in each platform's helper (wincred.c, osxkeychain.c, libsecret.c), maintaining the current security model where authtype is non-confidential while credentials remain protected. The proposal doesn't specify implementation details but implies following the pattern already established in credential-cache.c.
