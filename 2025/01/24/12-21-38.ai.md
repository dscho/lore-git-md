Refactoring patch in the OS version capability series.

This is the third patch in Usman Akinyemi's v3 series adding OS version reporting to Git's protocol. It extracts the uname(2) system call handling from builtin/bugreport.c into a new get_uname_info() function in version.c, making it reusable for the OS version feature. The change is straightforward - moving the existing uname handling code while maintaining identical behavior, with proper error handling preserved through the strbuf interface.

The patch is part of the larger effort to implement configurable OS version reporting while consolidating platform handling under Git's `compat/` system. This particular refactoring prepares for reusing the uname functionality when reporting OS versions in the protocol, following the series' architectural decision to handle all platform-specific code through the `compat/` system rather than runtime configuration.

Key technical details:
- New get_uname_info() function added to version.[ch]
- Function signature takes a strbuf for output
- Maintains existing error handling and message formatting
- Includes gettext wrappers for localization
- Preserves all current bugreport.c behavior
- Christian Couder reviewed and mentored the change (Mentored-by tag)
- Follows the series' pattern of preparatory refactoring before new functionality

The change is cleanly separated from the controversial aspects of the series, focusing purely on code organization. It maintains the security model established in v3 by keeping platform-specific handling in version.c rather than adding new configuration points. The patch appears well-contained and properly tested through existing bugreport usage.
