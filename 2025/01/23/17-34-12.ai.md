This is the final version of Taylor Blau's 8-part series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations, introducing a unified `unsafe_hash_algo()` mechanism. The series builds on brian m. carlson's earlier work on hash algorithm abstraction.

Key changes in this version:
- `hash_algo_by_ptr()` now returns `GIT_HASH_UNKNOWN` for NULL and unsafe variants, improving safety over both v3 and current master
- Maintains all previous architectural improvements from the series:
  - Unified algorithm access via `unsafe_hash_algo()`
  - Removal of all `unsafe_` prefixed function variants
  - `struct hashfile` now carries its own `algop`
  - Checkpoint API ensures algorithm consistency
  - Test infrastructure verifies safe/unsafe behavior parity

The series has seen extensive review from Jeff King, Patrick Steinhardt, and Junio C Hamano, with all identified edge cases addressed. The changes:
- Reduce API surface by removing duplicate unsafe functions
- Prevent accidental mixing of safe/unsafe operations
- Simplify future hash algorithm additions
- Maintain backward compatibility while enabling future work

Notable technical details:
- New `unsafe` pointer field in `struct git_hash_algo`
- `hashfile_checkpoint_init()` ensures algorithm matching
- `sha1-unsafe` test helper verifies identical output
- csum-file.c fully converted to use unsafe variants through unified `algop`
- Test helper `cmd_hash_impl()` simplified to single code path

The series represents the completion of architectural changes in hash algorithm handling, removing all scaffolding for old unsafe variants after converting all callers. The test infrastructure ensures behavioral parity while demonstrating the benefits of the unified approach.
