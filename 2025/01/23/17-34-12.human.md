This is the final version of Taylor Blau's 8-part series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations. The series introduces a unified `unsafe_hash_algo()` mechanism that wraps unsafe variants within the main algorithm structure, preventing accidental mixing of safe and unsafe operations.

The key change in this version is that `hash_algo_by_ptr()` now returns `GIT_HASH_UNKNOWN` for both NULL and unsafe algorithm pointers, which improves safety by making incorrect usage fail visibly rather than silently. This addresses concerns raised in earlier reviews while maintaining the series' core goal of reducing API surface area and preventing unsafe operation mixing.

The series has seen extensive review from Jeff King, Patrick Steinhardt, and Junio C Hamano, with all major concerns addressed. The implementation now:
- Stores hash algorithms directly in `hashfile` structs
- Uses a single code path for both safe and unsafe operations via `unsafe_hash_algo()`
- Includes test infrastructure to verify behavioral parity
- Removes all scaffolding for the old unsafe variants

This represents the completion of architectural changes to Git's hash algorithm handling that began in v2.47.0. The changes maintain backward compatibility while simplifying future hash algorithm additions and continuing the project's move toward more explicit algorithm selection. The series is well-tested and ready for inclusion, with only minor pre-existing NULL pointer handling issue noted for future work.
