Final patch in Taylor Blau's hash algorithm refactoring series, removing the now-unused unsafe function variants from the hash API. This completes the transition to using `unsafe_hash_algo()` throughout the codebase, eliminating the separate unsafe function pointers that were previously part of `struct git_hash_algo`.

The patch removes 15 lines from hash.h and 15 from object-file.c, deleting all `unsafe_*_fn` function pointer declarations and their implementations. This cleanup was made possible by the earlier patches in the series that converted all callers to use the new `unsafe_hash_algo()` mechanism instead of directly accessing the unsafe function variants.

Key technical details:
- Removes `unsafe_init_fn`, `unsafe_clone_fn`, `unsafe_update_fn`, `unsafe_final_fn`, and `unsafe_final_oid_fn` from `struct git_hash_algo`
- Eliminates the corresponding implementations from `hash_algos[]` array in object-file.c
- Maintains the `unsafe` pointer field that links safe/unsafe algorithm variants
- Preserves all the standard hash function pointers that remain in use
- Follows through on the architectural goal of handling safe/unsafe variants through algorithm pointers rather than separate function calls

The removal is safe because all callers have been converted in previous patches to use the new `unsafe_hash_algo()` accessor, which provides the same functionality through the algorithm's standard function pointers. This final cleanup reduces API surface area and prevents future confusion between safe and unsafe variants.

The series has been through multiple iterations with review from Jeff King, Patrick Steinhardt, and Junio C Hamano, and this final removal was anticipated as the logical conclusion of the refactoring work. It represents a significant simplification of Git's hash algorithm handling while maintaining all the safety guarantees introduced earlier in the series.
