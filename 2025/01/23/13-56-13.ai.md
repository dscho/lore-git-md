This is a bugfix patch for the reftable backend, addressing a corruption issue that was discovered after the initial fix was merged. The patch is a follow-up to the recently resolved reftable migration corruption issue (where header/trailer max_update_index mismatches occurred during multi-batch operations).

The key technical changes in this v2 patch:
1. Adds missing zero initialization for `write_transaction_table_arg.max_index` to fix a flaky test on macOS when leak sanitizer is enabled.
2. Ensures `max_index` is properly set for all elements of `reftable_transaction_data`.
3. Maintains the core fix from v1 which tracks the maximum update index at the transaction level and propagates it to the reftable backend before writing begins.

The patch includes a test that creates 5000 refs with 3000 updates to verify multi-batch handling. The changes are based on Git 2.48.1 (Maint f93ff170b9) and address feedback from the initial merge where test flakiness was discovered.

The author notes they removed Junio's Signed-off-by line from the previous version since it's typically added by the maintainer during merge. The patch demonstrates careful attention to edge cases (like the macOS test failure) while maintaining the core solution to the reftable corruption issue.
