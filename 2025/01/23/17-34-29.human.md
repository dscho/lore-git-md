This is part of Taylor Blau's ongoing series to refactor Git's hash algorithm handling, specifically introducing a new `unsafe_hash_algo()` helper function to simplify unsafe hash variant usage.

The patch eliminates the need for callers to manually choose between safe and unsafe hash function pairs (like `init_fn` vs `unsafe_init_fn`) by introducing a unified access pattern. Now callers can simply get an algorithm pointer once (optionally converting it to its unsafe variant via the new helper) and use standard function names throughout. This prevents accidental mixing of safe/unsafe variants and reduces boilerplate code.

The implementation adds an `unsafe` pointer field to `struct git_hash_algo` that points to the unsafe variant of each algorithm (currently only SHA-1 has one). The new `unsafe_hash_algo()` function returns either this variant or the original algorithm if no unsafe version exists. The change also modifies `hash_algo_by_ptr()` to handle unsafe algorithm pointers properly.
