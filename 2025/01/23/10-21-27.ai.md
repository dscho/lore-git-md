This is a bugfix patch addressing a reflog corruption issue in the files backend, following up on review feedback from Patrick Steinhardt. The patch corrects a regression introduced in Git 2.48.1 where symbolic reference updates (like HEAD) would create corrupted reflog entries due to missing old_oid values, while direct branch updates worked correctly.

Karthik Nayak responds to Steinhardt's review comments, agreeing to several improvements: fixing "reflog only" to "reflog-only" in the commit message, restructuring the message for better flow (currently describes the fix twice), and explicitly noting this is a files-backend-specific issue. He also confirms the test case will be updated to use `git symbolic-ref HEAD` rather than hardcoding "main" and setting GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME.

The technical discussion confirms that despite removing the REF_LOG_ONLY optimization, the check_old_oid() call remains efficient since REF_HAVE_OLD is unset for these cases. The core fix remains removing an early return in files-backend.c that skipped populating old_oid for symref reflogs. The patch includes a test in t1400-update-ref.sh to prevent regression.
