This is a feature patch adding `--expire-to` support to `git gc`, mirroring existing `git repack` functionality for cruft pack management. It's the third iteration of a change that's already been through substantial review.

The patch makes it easier to manage cruft packs by letting users specify a destination for expired objects directly in `git gc`, rather than needing to chain `git repack` and `git prune` commands. The implementation passes the expire-to parameter through to the underlying repack operation while carefully handling the interaction with `--cruft` and `--prune=now` options.

Junio Hamano's review identified several documentation and testing improvements needed:
- The commit message needs to better explain the `-a` flag behavior change
- Documentation should clarify that `--expire-to` requires `--cruft` to take effect
- Test coverage should verify behavior with `--no-cruft`

The author (ZheNing Hu) acknowledges these points and indicates they'll be addressed in the next revision. The core technical approach appears sound, with the change building on established cruft pack infrastructure. This looks like a useful quality-of-life improvement for repository maintenance workflows, particularly for server-side operations where preserving expired cruft packs is valuable.
