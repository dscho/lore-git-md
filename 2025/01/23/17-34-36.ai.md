This is a refactoring patch in Taylor Blau's series converting Git's hash algorithm handling to use the new `unsafe_hash_algo()` mechanism. The patch simplifies the test helper `cmd_hash_impl()` that powers both the 'sha1' and 'sha1-unsafe' test commands by removing duplicate code paths for safe/unsafe variants.

The key change moves the unsafe/safe decision point to the start of the function, where it transforms the algorithm pointer to its unsafe variant if requested. This allows all subsequent hash operations (init, update, final) to use the standard function names through the algorithm pointer, eliminating 12 lines of conditional logic. The patch maintains identical behavior while making the code more maintainable and consistent with the series' architectural goal of handling safe/unsafe variants through algorithm pointers rather than separate functions.

This change builds on the thread's established pattern seen in previous patches, where unsafe operations are accessed through the `unsafe_hash_algo()` function rather than direct calls to `unsafe_*_fn` variants. The test helper simplification demonstrates the series' benefits in reducing code duplication while maintaining the same functionality. This is the sixth patch in an 8-part series that has already received extensive review, with the architectural approach approved by Junio C Hamano and safety validated by Jeff King.
