Bugfix follow-up for reftable migration edge cases, addressing macOS test flakiness under leak sanitizer.

This is a follow-up to the recently merged reftable corruption fix, now addressing test flakiness that surfaced in the CI pipeline on macOS when running with leak sanitizer enabled. The issue was discovered by Dscho (Johannes Schindelin) and traced to missing zero initialization of `write_transaction_table_arg.max_index`. While the core functionality was correct, this edge case caused intermittent test failures.

The patch builds on the existing solution in Git 2.48.1 (commit f93ff170b9) rather than replacing it, maintaining all the key improvements from the original fix: proper max_update_index tracking at the transaction level, removal of redundant reflog path tracking, and the large-scale test case validation. Junio Hamano suggests presenting this as an incremental patch to properly document the post-merge discovery process, including credit to the reporter and a description of how the issue was diagnosed.

This exemplifies Git's quality process where even reviewed-and-merged changes get refined based on real-world testing. The fix is minimal (just adding the missing initialization) but important for ensuring consistent behavior across all platforms and test configurations. With this follow-up, the reftable migration path should now be fully robust, having addressed both the original corruption issue and these edge case test failures.
