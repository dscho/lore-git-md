This is the final patch in Taylor Blau's series refactoring Git's hash algorithm handling, introducing a new `hashfile_checkpoint_init()` function to prevent crashes from hash algorithm mismatches between hashfiles and their checkpoints. The patch builds on previous fixes for segfaults in fast-import and bulk-checkin when using unsafe SHA-1 backends.

The key change is the new `hashfile_checkpoint_init()` function which ensures hashfile checkpoints use the same algorithm as their parent hashfile, eliminating the need for manual initialization with potentially mismatched algorithms. The patch updates both fast-import.c and bulk-checkin.c to use this new API, with careful handling of the bulk-checkin case where initialization must wait until the hashfile is prepared.

Notable implementation details include:
- New `hashfile_checkpoint_init()` function in csum-file.c that properly initializes the checkpoint context
- Removal of direct `unsafe_init_fn` calls in favor of the new API
- Special handling in bulk-checkin.c to defer initialization until the hashfile is ready
- Maintained safety through proper NULL checks and flag verification
- The patch demonstrates the series' architectural benefits by eliminating manual algorithm selection in favor of the hashfile's stored algorithm pointer
- Patrick Steinhardt provided assistance with the changes
- The implementation maintains all existing functionality while being more robust against future changes

This completes the series' goal of unifying hash algorithm handling through pointer-based access rather than direct function calls, with the checkpoint API being the final piece to prevent algorithm mismatches. The changes are well-contained and maintain backward compatibility while improving safety.
