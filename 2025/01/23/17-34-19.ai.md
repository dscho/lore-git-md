This is the first patch in an 8-part series refactoring Git's hash algorithm handling, introducing test infrastructure for the new "unsafe" SHA-1 variants. The patch adds a new `sha1-unsafe` test helper that exercises Git's unsafe SHA-1 implementation through the existing `cmd_hash_impl()` framework. The implementation conditionally calls either safe or unsafe variants of the hash functions (init, update, final) based on a new `unsafe` parameter. The test script is updated to verify both safe and unsafe variants produce identical output.

Key technical details:
- New `cmd__sha1_unsafe()` entry point added to test-tool
- `cmd_hash_impl()` modified to take `unsafe` parameter and select appropriate function variants
- Test script extended to run all checks against both safe and unsafe implementations
- SHA-256 test remains safe-only (no unsafe variant needed)
- Helper maintains same interface as existing `sha1` test tool

The patch serves as foundational test infrastructure for the larger series, allowing verification that the unsafe variants behave identically to their safe counterparts. This will be important for validating the architectural changes in subsequent patches that eliminate the unsafe function variants in favor of the unified `unsafe_hash_algo()` mechanism.
