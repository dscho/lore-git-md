Bugfix for reftable corruption during multi-batch migrations. This is a follow-up to the recently merged fix for reftable header/trailer mismatches during ref migrations with many reflog updates. Karthik Nayak addresses two issues found after initial merge: missing zero-initialization of a max_index field that caused flaky tests under leak sanitizers, and ensuring the max_index is properly set across all transaction data elements.

The core fix remains the same - properly tracking the maximum update index across reflog operations to prevent header/footer corruption during multi-block writes. The new test creates 5000 refs with 3000 updates to verify the fix under heavy load. This version also cleans up some commit message formatting and removes an extraneous sign-off that had been added during integration.

The patch has already been verified to resolve the original corruption issue in real-world large repositories, and these additional fixes address the test stability and initialization completeness. It's now ready for final inclusion in the maintenance track (based on Git 2.48.1).
