This is part of Taylor Blau's series refactoring Git's hash algorithm handling, specifically focusing on unifying the safe and unsafe variants of hash functions. The patch converts csum-file.c to use the new `unsafe_hash_algo()` function rather than calling unsafe hash variants directly. This change builds on the series' architectural work to eliminate separate unsafe function variants by instead using a unified `algop` pointer that can point to either safe or unsafe implementations.

The key change here is initializing the hashfile's `algop` pointer with `unsafe_hash_algo(the_hash_algo)`, which automatically routes all subsequent hash operations through the unsafe variants. The patch updates all hash operations in csum-file.c to use the standard function names (`update_fn`, `final_fn`, etc.) rather than their `unsafe_`-prefixed counterparts. This includes operations in `hashflush()`, `finalize_hashfile()`, `hashwrite()`, and the checkpointing/truncation functions.

The changes maintain the same behavior while reducing API surface area and preventing accidental mixing of safe/unsafe variants. The patch appears well-integrated with the series' broader goals and follows the established pattern seen in earlier patches. Since this is the fifth patch in an eight-part series that has already undergone significant review, it represents a focused, incremental change that builds on the architectural foundation laid by previous patches.
