This is a feature patch adding `--expire-to` support to `git gc`, mirroring existing `git repack` functionality for cruft pack management. The patch is in its third iteration and addresses feedback from Junio Hamano regarding documentation clarity and test coverage.

Key technical aspects:
- The implementation adds a `repack_expire_to` field to `gc_config` and modifies `add_repack_all_option()` to handle the new parameter
- When both `--cruft` and `--expire-to` are specified, `git gc` skips the automatic `-a` flag to preserve cruft objects
- Documentation updates in `git-gc.txt` explain the cruft pack requirement
- Test coverage in t6500-gc.sh verifies the basic behavior

The author acknowledges several improvements needed based on review:
- Using `git show --format=reference` for commit references
- More prominent explanation of the `-a` flag skipping behavior
- Documentation clarification that `--expire-to` requires `--cruft` to take effect
- Changing "for more" to "for more information" in docs
- Adding test coverage for the `--no-cruft` case

The patch appears technically sound and well-considered, with the remaining work being primarily documentation polish and additional test cases. The functionality provides a useful simplification for server-side maintenance workflows that want to preserve expired cruft packs in a specific location.
