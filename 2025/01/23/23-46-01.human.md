This is a discussion about naming and interface design for Git's name hash implementation variants.

Junio Hamano responds to Taylor Blau's suggestion about simplifying the name hash interface. The thread has three proposed versions (v1, v2, v3) of the name hashing algorithm, where v2 is generally superior to both v1 and v3 in most cases. Taylor had suggested unifying behind a single approach rather than exposing multiple versions simultaneously.

Junio agrees that v2 is superior in most cases and that keeping v3 makes "version" an awkward term, since it implies progression when in reality v3 is just a specialized alternative. He proposes dropping v3 from the current series (keeping just v1 and v2) and reintroducing a new v3 later if a genuinely better algorithm emerges. This would allow them to use clearer "version" terminology while still leaving room for future improvements.

The discussion shows the maintainers converging on an interface design that balances technical needs with user experience considerations, while leaving the core algorithm (which was technically sound) unchanged. This appears to be one of the final interface decisions needed before the name hash changes can be finalized.
