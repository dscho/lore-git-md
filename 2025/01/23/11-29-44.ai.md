Bugfix for reflog corruption in symref updates, files backend specific.

This final version of the patch addresses a regression introduced in commit 297c09eabb that caused corrupted reflog entries when updating symbolic references (like HEAD) via `git update-ref`. The issue stemmed from an incorrect early return in `lock_ref_for_update()` when `REF_LOG_ONLY` was set, which skipped the population of `old_oid` for symref reflog entries.

The fix removes this premature optimization in `refs/files-backend.c` around line 2615, allowing proper `old_oid` population for symref reflogs. The patch includes a test case in `t/t1400-update-ref.sh` that verifies correct reflog behavior when updating HEAD, using `git symbolic-ref HEAD` as suggested in review feedback rounds. The test creates a commit, records its hash, rewinds HEAD via `update-ref`, and verifies the reflog contains the expected previous value.

The commit message has been refined through review to better explain the files-backend-specific nature of the issue and clarify that the removed optimization was non-essential. The patch carries sign-offs from both Karthik Nayak and Jeff King, indicating consensus on the solution. All suggested test improvements from the review process have been incorporated, including removal of unnecessary repository setup and using proper symbolic reference resolution. This fixes a concrete regression affecting reflog integrity that was reported against Git 2.48.1, with the solution now ready for merging.
