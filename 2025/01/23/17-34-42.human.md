This is the final patch in Taylor Blau's series refactoring Git's hash algorithm handling, completing the transition to using `unsafe_hash_algo()` throughout the codebase. The patch removes the now-obsolete scaffolding for unsafe hash function variants, as all callers have been converted to use the new `unsafe_hash_algo()` mechanism instead.

The changes delete 15 lines from both `hash.h` and `object-file.c`, removing the separate `unsafe_*_fn` function pointers that were previously used to access non-cryptographic hash operations. This cleanup was made possible by the series' earlier work to unify safe and unsafe variants through algorithm pointers.

The patch represents the culmination of a significant architectural improvement that:
- Reduces API surface area
- Prevents accidental mixing of safe/unsafe operations
- Simplifies future hash algorithm additions
- Maintains backward compatibility while enabling future work

With this change, the series achieves its goal of handling safe/unsafe variants through algorithm pointers rather than separate function calls, completing the safety guarantees established in earlier patches. The changes have been thoroughly reviewed and tested, with all feedback incorporated from Jeff King, Patrick Steinhardt, and Junio C Hamano.
