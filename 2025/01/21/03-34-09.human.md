This is a 3-patch series addressing followups to a reftable migration corruption fix. The series makes targeted improvements to the refs and reftable subsystems after issues were discovered when converting repositories with large reflogs.

The first patch marks `ref_transaction_update_reflog()` as static while preserving its important documentation about index field ordering behavior. The second patch converts index fields from unsigned int to uint64_t to better support large repositories and prevent overflow on 32-bit systems. Both of these appear uncontroversial and ready for inclusion.

The third patch introduces safeguards to prevent 'update_index' changes after records are added to a reftable, addressing the root cause of the original corruption issue. This version modifies the approach from v1 to be more robust - now preventing index changes after *any* record write rather than just the first block write. The patch uses REFTABLE_API_ERROR instead of BUG() and handles all callers appropriately.

The series shows careful attention to the technical discussion, with v2 incorporating feedback about documentation preservation, error handling, and tightening the safety checks. The changes are well-motivated by real-world corruption scenarios and appear thoughtfully implemented with proper test coverage. This looks like a solid incremental improvement to the reftable migration path.
