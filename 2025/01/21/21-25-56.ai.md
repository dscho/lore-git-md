This is the final patch in a series removing legacy "branches/" and "remotes/" reference naming conventions, now at version 3. Junio Hamano provides final review feedback before merging. While approving the removal overall, he notes one remaining use case where the file-based mechanism could be preferable for managing many remotes with changing branch names, though no users have actively advocated for keeping it.

The patch implements the actual removal with warning messages and documentation updates marking these paths as deprecated for Git 3.0. Key technical changes include conditional compilation with WITH_BREAKING_CHANGES, warning messages when accessing legacy paths, and documentation updates across multiple files. The implementation spans remote.c, builtin/remote.c, and documentation.

Junio suggests improving the warning messages to include specific migration instructions - either `git remote mv foo foo` to convert to config-based remotes or `git remote rm foo` for obsolete entries. He also clarifies that feedback should focus on why users can't migrate rather than just notification of usage. The patch maintains backward compatibility through conditional compilation while preparing for final removal in Git 3.0, with robust test coverage via CI adaptations. This concludes the systematic deprecation process that began with infrastructure preparation and example removal (git-pack-redundant).
