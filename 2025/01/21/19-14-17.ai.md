This is Junio Hamano's response in the ongoing discussion about the OS version reporting feature, specifically addressing the proposed `osversion.command` config option in patch 6/6 of the series. The email focuses on platform-specific implementation concerns and security implications of the configurable command approach.

Junio firmly rejects the `osversion.command` mechanism due to security risks of arbitrary command execution, proposing instead a compile-time solution in the `compat/` layer similar to how Windows handles version reporting via `GetVersion()`. He argues that NonStop's platform needs (raised by Randall Becker) could be addressed through platform-specific code in `compat/` rather than a runtime-configurable command, maintaining Git's security model.

The response highlights two key technical considerations: 1) the precedent set by Windows' compile-time solution, and 2) the principle that platform-specific details should be abstracted through Git's `compat/` system rather than exposed via user-configurable commands. Junio suggests modifying `get_uname_info()` to call into NonStop-specific code, keeping the implementation details internal while still meeting the platform's reporting needs.

This email reinforces Junio's earlier architectural objections to the configurable command approach while offering a concrete alternative path forward for NonStop compatibility. The discussion remains unresolved regarding whether the entire OS version feature will proceed in some form or be replaced by extending the user-agent capability as previously suggested.
