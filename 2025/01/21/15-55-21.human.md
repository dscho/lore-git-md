This is a bug report about `git stash pop` failing silently when using the reference syntax `'stash@{0}'` in a specific repository, while working fine with simpler references like `0` or no reference at all. The reporter, Martin, provides detailed reproduction steps showing the issue occurs in one particular clone but not in fresh repositories.

The key observations are:
1. The command fails silently (exit code 1 with no output) unless stderr is explicitly redirected
2. When stderr is captured, it shows "error: stash@{0} is not a valid reference"
3. The same reference format appears in `git stash list` output
4. The issue persists across Git versions (2.34.1 and 2.48.1) and shells (zsh/bash)

This appears to be a repository-specific parsing issue where Git fails to recognize the standard stash reference syntax in this particular clone. The reporter is looking for debugging suggestions since they can't share the private repository. The fact that it works with simpler references suggests some repository metadata might be interfering with reference parsing.
