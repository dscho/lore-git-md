This is a follow-up in the ongoing discussion about `git fetch` behavior with tags in shallow clones. Danila Manturov reports new experimental findings showing the issue behaves differently depending on the transport protocol implementation - working correctly with JSch (Java SSH) but failing with native SSH/HTTPS transports. This suggests the problem may be protocol-specific rather than purely a fetch logic issue.

The email builds on previous analysis that identified commit 5f212684abb6 as introducing a regression where tags pointing to shallow boundary commits weren't fetched with `--depth=1`. While a fix exists in Git 2.48, it appears incomplete as it doesn't resolve Danila's test case. Bence Ferdinandy had previously noted this discrepancy but hadn't investigated further.

The new transport-specific behavior adds another layer of complexity to diagnosing the issue, indicating the problem may involve interaction between shallow clone logic and protocol implementations. The thread remains open with no clear resolution yet for why the existing fix doesn't cover this edge case or why different transports behave differently.
