This thread documents the discovery and resolution of a reflog corruption bug affecting symbolic reference updates in Git 2.48.1. Nika Layzell originally reported that `git update-ref` was recording incorrect `old_oid` values in derived reflogs (like HEAD's) while direct branch reflogs remained correct. Jeff King traced the regression to commit 297c09eabb, which introduced an optimization in `lock_ref_for_update()` that incorrectly skipped necessary work for symref updates when the `REF_LOG_ONLY` flag was set.

Karthik Nayak developed the fix by removing this problematic early return, ensuring proper `old_oid` population in derived reflogs. The solution went through multiple rounds of review, with Jeff King providing detailed test case improvements and Patrick Steinhardt verifying the files-backend-specific nature of the fix. The final patch includes a comprehensive test in `t/t1400-update-ref.sh` using `git symbolic-ref HEAD` and carries Signed-off-by tags from both Nayak and King.

Junio Hamano has now provided final maintainer feedback, suggesting minor wording improvements to the commit message while approving the technical solution. The patch is in its final form with all substantive issues resolved, making it a strong candidate for inclusion in an upcoming maintenance release. This collaborative effort between Layzell, King, Nayak, and Steinhardt has produced a robust fix for a concrete regression affecting symbolic reference handling.
