This thread addresses a regression in Git 2.48.1 where symbolic reference updates (like HEAD) were incorrectly recording `old_oid` in derived reflogs, while direct branch reflogs remained correct. Nika Layzell originally reported the issue, and Jeff King traced it to a problematic early return in `lock_ref_for_update()` introduced in commit 297c09eabb. Karthik Nayak submitted the core patch to fix this by removing the incorrect early return, ensuring proper `old_oid` recording in all reflogs.

The fix has undergone thorough review: Jeff King improved the test case by replacing hardcoded "main" with `git symbolic-ref HEAD` and added his Signed-off-by. Patrick Steinhardt then reviewed the changes, confirming the fix while suggesting commit message clarifications about the files-backend scope. Now Junio Hamano has weighed in, agreeing with all proposed improvements and calling for a clearer commit message structure that avoids repeating the fix description. 

With the original reporter verifying the solution and all reviewers aligned on the final tweaks, this important fix for reflog integrity is ready for merging. The changes specifically target the reflog handling in `refs/files-backend.c` and are verified by the enhanced test in `t/t1400-update-ref.sh`. Given the regression's impact on fundamental functionality, this is a strong candidate for inclusion in a maintenance release.
