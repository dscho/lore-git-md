This thread reports a regression in Git 2.48.1 affecting reflog behavior when updating symbolic references through `git update-ref`. The core problem is that the `old_oid` field in derived reflogs (like HEAD's) shows all zeroes when a branch is updated via a symbolic reference, though the direct branch reflog remains correct. This impacts commands that rely on these fields, such as `HEAD@{1}` queries.

The reporter provides clear reproduction steps demonstrating the difference between expected behavior (where the old_oid should be recorded) and the current broken state. The issue appears specific to cases where a symbolic ref like HEAD points to the branch being modified, suggesting the bug lies in how update-ref handles indirect references during reflog updates. While the exact commit introducing the regression isn't yet identified, the problem is well-documented with concrete examples showing both correct and incorrect outputs. This affects core refs/reflog functionality and could impact any use of symbolic references with reflog queries.
