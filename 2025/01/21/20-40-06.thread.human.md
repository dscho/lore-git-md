This thread documents a regression in Git 2.48.1 where `git update-ref` incorrectly recorded `old_oid` in derived reflogs (like HEAD) during symbolic reference updates, while direct branch reflogs remained correct. Nika Layzell originally reported the issue, and Jeff King traced it to a problematic early return in `lock_ref_for_update()` introduced in commit 297c09eabb.

Karthik Nayak submitted the fix, removing this early return after determining the original assumption about reflog-only updates was incorrect. The patch includes a test case in `t/t1400-update-ref.sh` verifying correct reflog behavior. Jeff King and Patrick Steinhardt both reviewed the fix, suggesting improvements to the test case and commit message while confirming the technical correctness. The final version incorporates all feedback, with both Karthik and Jeff signing off.

In the latest exchange, Jeff King acknowledges the collaborative work, humorously downplaying his own contribution while confirming consensus on the fix. With all technical issues resolved and reviewers in agreement, the patch is now ready for maintainer consideration. Given this affects fundamental reflog integrity for symbolic refs, it's likely to be prioritized for inclusion in a maintenance release.
