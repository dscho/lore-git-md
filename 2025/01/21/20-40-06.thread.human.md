This thread addressed a regression in Git 2.48.1 where symbolic reference updates (like HEAD) via `git update-ref` were incorrectly recording `old_oid` in derived reflogs, while direct branch updates worked fine. Nika Layzell originally reported the issue, and Jeff King traced it to a problematic early return in `lock_ref_for_update()` introduced in commit 297c09eabb.

Karthik Nayak submitted the fix, removing this early return to properly handle symref cases while maintaining optimizations for regular refs. The patch included a comprehensive test case in `t/t1400-update-ref.sh`. Jeff King provided multiple rounds of test improvements, ultimately signing off on the solution. Patrick Steinhardt reviewed the changes, confirming the fix while noting it was specific to the files backend.

After some final editorial polishing from Junio Hamano (removing potentially misleading "corrupted" language from the commit message and improving explanations), the patch has now been merged to 'next'. This resolves a concrete files-backend regression affecting reflog integrity during symbolic reference updates. All participants - including the original reporter, fix author, reviewers, and maintainer - are satisfied with the solution.
