Bug report: `git add` silently fails when given case-mismatched pathspec on case-insensitive filesystems.

Lê Duy Quang reports unexpected behavior when using `git add` on Windows (with its case-insensitive filesystem). When attempting to add a file with incorrect case (e.g., `sourcefile.c` when the actual filename is `SourceFile.c`), Git neither stages the file nor produces an error message - it silently appears to succeed while doing nothing. The reporter expected either the file to be staged despite the case mismatch or an explicit error message.

This appears to be a genuine bug in path handling on case-insensitive systems, where Git's behavior diverges from user expectations in a potentially dangerous way (users may commit without realizing files were missed). The report is clearly written with a concrete reproduction case and states the expected behaviors, making it lacks only a test case or proposed fix to be a complete bug report. The silent failure aspect suggests this could be worth prompt attention from Windows Git maintainers.
