This is a bugfix report for a regression in `git update-ref`'s reflog handling introduced in Git 2.48.1. Nika Layzell identifies a case where updating a branch referenced by a symbolic ref (like HEAD) fails to properly set the `old_oid` field in the reflog, though the direct ref's reflog remains correct. The issue manifests when using commands like `HEAD@{1}` which rely on this field.

The report includes clear reproduction steps showing the difference between expected behavior (where the reflog entry shows the previous commit hash) and the current broken behavior (where the old_oid shows all zeroes). The problem appears limited to derived reflogs while direct ref updates work correctly.

This looks like a genuine regression with a well-documented test case. The impact is moderate - while basic reflog functionality works, certain reflog-based references will return incorrect values. The report is thorough, showing both command output and file contents to demonstrate the issue, making it easy to verify.
