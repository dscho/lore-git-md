Project documentation proposal in the GSoC 2025 thread. Junio Hamano responds to Patrick Steinhardt's suggestion to move the list of microprojects into the Git repository as Documentation/Projects.txt.

Hamano agrees with the general idea but adds an important condition: each listed project should have a clear expiration date to prevent the file from becoming an uncurated collection of stale ideas. He draws a parallel to the maintenance burden of stale topic branches that never graduate to 'next'. This suggests he wants the projects list to remain actively maintained and relevant, not just accumulate indefinitely.

The response keeps the discussion moving forward on how to best document GSoC project ideas while maintaining project hygiene. Hamano's condition implies he sees value in having the list in-tree (supporting discoverability and easier updates as Patrick noted), but wants guardrails to prevent documentation rot. This positions the proposal as likely to move forward if the expiration mechanism can be worked out.
