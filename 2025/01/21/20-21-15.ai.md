This is a feature patch series (v3) focused on improving delta compression in pack-objects by introducing alternative name hash algorithms. The series was previously closed and is being resubmitted after force-pushing made GitHub unable to reopen the original PR.

The core motivation comes from observing repositories where delta compression fails to connect different versions of the same file due to suboptimal name hashing. The series introduces a new `--name-hash-version` option with three implementations: 
1. Version 1 (default) maintains current behavior focusing on path endings
2. Version 2 implements Jonathan Tan's suggested path-component hash with modifications to reduce collisions while preserving some delta locality
3. Version 3 (marked as likely to be dropped) retains the earlier full-name-hash approach that minimizes collisions at the cost of locality

The author considers this the most promising direction for improving delta compression and notes the only remaining decision is whether to include the experimental Version 3 implementation in the final merge. The series has been stable at this version for some time, suggesting it's ready for final review.

Key technical details for future reference:
- Affects pack-objects delta selection algorithm
- Introduces new command-line option `--name-hash-version`
- Version 2 appears to be the preferred approach, overlaying component hashes with parent directory weighting
- Version 3 exists mainly for comparison with its pseudorandom full-path hashing
- Builds on previous discussion with Jonathan Tan about hash collision issues
