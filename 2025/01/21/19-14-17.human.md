Junio Hamano responds to the discussion about the `osversion.command` config option in the OS version reporting series. This is part of the ongoing debate about how to handle platform-specific version information, particularly for NonStop systems.

Hamano firmly rejects the configurable command approach due to security concerns, arguing it's unnecessary to spawn external processes when platform-specific code in `compat/` can handle the version reporting directly. He points out that Windows already follows this pattern by using `GetVersion()` rather than executing external commands, and suggests NonStop platform should do the same.

The response highlights a key architectural disagreement in the series: whether to allow runtime configuration (as requested by Randall Becker for NonStop compatibility) or enforce compile-time solutions through the `compat/` system. Hamano clearly favors the latter approach for both security and design cleanliness reasons. This email reinforces his earlier position that the configurable command mechanism should be removed from the series entirely.
