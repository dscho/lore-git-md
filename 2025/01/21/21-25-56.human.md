This is the final patch in a series removing the legacy "branches/" and "remotes/" reference naming conventions in Git 3.0. Junio Hamano provides a review of Patrick Steinhardt's implementation, acknowledging one remaining use case for the old mechanism (convenient pattern matching and URL storage) but supporting removal due to lack of community demand.

The patch adds clear deprecation warnings when these legacy paths are accessed, with documentation updates marking them as deprecated and noting their removal in Git 3.0. The implementation uses conditional compilation (WITH_BREAKING_CHANGES) to maintain backward compatibility while preparing for removal.

Junio suggests improving the warning messages to include specific migration instructions (like using `git remote mv` or `git remote rm`) and clarifies that the project would be more interested in understanding why users can't migrate rather than just knowing they still use the old paths. The review indicates the patch is otherwise well-crafted and ready for inclusion, completing this long-planned deprecation process that began 20 years ago.
