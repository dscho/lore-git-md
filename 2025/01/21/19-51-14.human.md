This is a response in the ongoing discussion about OS version reporting in Git, specifically addressing the security concerns around the proposed `osversion.command` config option. Randall Becker (from NonStop platform) weighs in after Junio Hamano firmly rejected the approach of running arbitrary commands to get OS version info.

Randall agrees with Junio's position that platform-specific version info should be handled via the `compat/` layer (following the Windows `GetVersion()` precedent) rather than through a configurable command. He expresses willingness to implement NonStop-specific version detection in `compat/` once the series is finalized, though he personally questions the utility of the feature since `uname -a` provides similar information.

The email reveals some tension between the feature's supporters and skeptics - Randall notes he's implementing it because "others want this" despite his own reservations. This suggests the feature may continue to face scrutiny about its fundamental value even after the security concerns are addressed through the `compat/` approach.

The thread appears to be converging on a solution that avoids the security risks of command execution while still providing platform-specific version info, though questions remain about whether the feature is truly needed.
