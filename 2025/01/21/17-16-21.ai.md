Bug report follow-up regarding case-insensitive `git add` behavior. Torsten Bögershausen confirms the core issue: Windows filesystems report a match for incorrect case variants, which explains why Git neither stages the file nor errors out. The response clarifies this is neither clearly a bug nor intended behavior, but rather an unimplemented edge case in Git's handling of case-insensitive systems. The practical advice given is to use `git status` as a verification step before committing to catch such cases.

Key technical details for future reference:
- The issue manifests when attempting to stage files with incorrect case on case-insensitive filesystems (Windows/macOS)
- Current behavior: silent non-staging when case doesn't match exactly
- Filesystem reports existence of file regardless of case, preventing the "no match" error case
- No proposed solution yet, but establishes this as a known behavioral gap
- Workaround suggested: manual verification via `git status`

This moves the discussion from initial bug report to acknowledged platform-specific behavior quirk, setting up potential future discussion about whether and how to modify this behavior (either through case-insensitive matching or explicit warnings).
