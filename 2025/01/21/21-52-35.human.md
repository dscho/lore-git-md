Bugfix investigation for reflog regression in `git update-ref`. Jeff King responds to Nika Layzell's report of incorrect `old_oid` recording in derived reflogs (like HEAD's) when updating branches referenced symbolically. The issue was introduced in Git 2.48 by commit 297c09eabb ("refs: allow multiple reflog entries for the same refname").

King provides a simple one-line diff that appears to fix the issue by removing an early return for `REF_LOG_ONLY` cases in `lock_ref_for_update()`. While this makes the problem disappear and passes tests, he notes this is just initial exploration without understanding the original rationale for those lines. The fix seems promising but requires deeper review of why the early return existed in the first place.

This is a significant regression affecting core reflog functionality for symbolic references, so the investigation and potential fix warrant attention from refs subsystem maintainers. The straightforward reproduction case and bisect result make this a well-documented bug report with promising initial debugging.
