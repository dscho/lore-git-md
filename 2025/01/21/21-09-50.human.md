This is a patch in the final stages of removing deprecated functionality as part of Git's breaking changes preparation for 3.0. The patch removes the `git-pack-redundant` subcommand, which was already marked for removal in September 2024 and had its deprecation warnings escalated to errors in Git 2.41 (March 2023).

Junio Hamano approves the removal, noting that the actual deprecation timeline (when the command stopped working without an explicit opt-in) is more important to users than when it was first announced in documentation. He expresses general support for reducing Git's command surface area, quipping "The fewer the subcommands, the happier the users."

This patch represents the second-to-last step in a carefully planned deprecation process that included infrastructure preparation, warning escalation, and now removal behind a breaking changes flag. The change is straightforward - simply stopping compilation of the subcommand when `WITH_BREAKING_CHANGES` is set - and comes after ample warning to users. The positive reception suggests this uncontroversial removal will likely proceed as part of the Git 3.0 changes.
