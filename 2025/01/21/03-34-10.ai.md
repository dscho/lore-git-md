This is a refactoring patch that's part of a series improving the reftable migration path. It marks `ref_transaction_update_reflog()` as static since the function is only used within refs.c, while preserving its documentation by moving it to the public `ref_transaction_update()` API.

The change involves:
- Removing the declaration from refs.h
- Making the function static in refs.c
- Keeping the detailed comment about index field ordering behavior
- No functional changes to the implementation

The patch was prompted by Junio C Hamano's observation that the function didn't need to be public. This is the first of three patches in the series, and according to the thread summary, this change is uncontested and ready for merging. The series as a whole addresses corruption issues discovered during reftable conversion of repositories with large reflogs.
