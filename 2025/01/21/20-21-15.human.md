This is a feature proposal for improving Git's delta compression by introducing alternative name hashing algorithms in `pack-objects`. The patch series (now at v3) offers three hash versions: the existing default (v1), a new component-based hash (v2) that better preserves path relationships, and a full-path hash (v3) included mainly for comparison.

The motivation comes from observing poor delta compression in large repositories where files moving across paths should theoretically compress well but currently don't. The new v2 hash, suggested in previous discussion, appears to be the most promising approach by balancing collision resistance with path locality.

The author notes this has been baking for a while and considers it ready for consideration, with the only open question being whether to include the experimental v3 hash in the final version. The patch looks well-motivated and addresses a known pain point in large repositories, though its effectiveness would need real-world testing.
