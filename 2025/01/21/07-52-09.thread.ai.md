Thread summary:

Bug report regarding silent failure in `git add` on case-insensitive filesystems (Windows/macOS). When attempting to stage a file with incorrect case (e.g. `sourcefile.c` for actual `SourceFile.c`), the command exits successfully without staging the file or providing any warning. This creates potential for silent workflow failures where users may commit without realizing files were missed. The behavior is inconsistent with case-insensitive filesystem expectations - either successful staging (matching filesystem behavior) or an error message would be more intuitive. No proposed solution yet, but the report provides clear reproduction steps. Affects core file staging behavior on case-insensitive platforms.
