Feature proposal discussion about batch remote removal. Emily Shaffer questions whether direct config file editing might be a better solution for power users than extending `git remote remove` to handle multiple remotes.

This is a reply to Christian Fredrik Johnsen's proposal to add batch removal capability to `git remote remove`, similar to `git branch -d`. Emily raises a practical counterpoint: since power users (the likely audience for this feature) already know how to edit `.git/config` directly, they could remove multiple remotes in one editor session rather than needing a new command-line interface. The implication is that the proposed feature might not justify its implementation cost when existing workflows already cover the use case.

The exchange highlights an important consideration for feature proposals - whether the new functionality offers enough advantage over existing methods to warrant the maintenance burden. Emily's question doesn't reject the idea outright but invites the proposer to articulate why the config-editing approach falls short for this use case. The thread now awaits either a defense of the original proposal's necessity or perhaps a reconsideration in light of this alternative solution.
