This is a discussion about the proposed OS version reporting feature in Git's protocol capabilities, specifically addressing fundamental design questions.

Junio Hamano continues to question the value of adding OS version reporting as a separate capability, suggesting the information could instead be included in the existing "agent" capability string. He remains unconvinced by the current justification that OS version helps diagnose client/server issues, pointing out that Git version differences are likely more relevant and that other Git-compatible software (like Gerrit) wouldn't benefit from this feature.

The email proposes simplifying the implementation by having `os_version()` always return sanitized strings, eliminating the need for separate raw and sanitized versions. This would involve immediately sanitizing the system-provided version string (from `uname` or similar) and caching the result. Junio sees no concrete use cases requiring access to the raw, unsanitized version string.

The discussion represents a critical juncture for the feature - while implementation details like string sanitization are being worked out, the more fundamental question of whether this capability belongs in Git at all remains unresolved. Junio's preference leans toward either dropping the feature entirely or incorporating OS information into the existing agent string rather than creating a new capability.
