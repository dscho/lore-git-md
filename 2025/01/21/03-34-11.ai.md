This is the second patch in a 3-part series addressing reftable migration issues, specifically focusing on preventing integer overflow in large repositories by converting index fields from unsigned int to uint64_t.

The patch changes the data type of several index-related fields across the refs subsystem to handle very large repositories safely. The key changes are:
- `ref_update.index` in refs-internal.h (used for ordering reference updates)
- `ref_transaction.max_index` tracking the highest index in a transaction
- Related parameters in refs.c and reftable-backend.c functions

The motivation comes from Brian M. Carlson's report about potential issues in repositories with millions of references, where 32-bit unsigned integers could overflow. The changes are mechanical type updates with no functional changes to the logic, just expanding the numeric range. The patch touches core refs infrastructure (refs.c, refs-internal.h) and the reftable backend implementation.

This appears technically sound and uncontroversial, aligning with the series' goal of hardening the reftable migration path. The changes are focused and well-contained, with straightforward type updates that don't introduce new logic or behavior. As part of the series, this patch has already been reviewed with no outstanding concerns noted in the thread.
