This is the third and final patch in a series addressing reftable corruption issues, specifically focusing on preventing invalid state changes during reftable writing. The patch enforces that `reftable_writer_set_limits()` can only be called before any records are written to the writer's header/footer mismatch issue that could occur when update indices were modified mid-write.

The key changes are:
1. Modifying `reftable_writer_set_limits()` to return an error (REFTABLE_API_ERROR) if called after any records are written (detected via the `last_key` field)
2. Updating all callers to handle the new return value
3. Adding documentation clarifying the API contract
4. Extending test coverage to verify the new behavior

The solution takes a pragmatic approach that maintains API stability while preventing misuse, satisfying Patrick Steinhardt's earlier concerns about corruption prevention. The changes touch the reftable writer implementation, its callers in the reftable backend, and unit tests, with careful attention to error handling and documentation.
