Bugfix targeting reflog behavior in `git update-ref`. This report identifies a regression in Git 2.48.1 where `git update-ref` fails to properly set the `old_oid` field in derived reflogs (like HEAD's reflog) when updating a branch that is symbolically referenced. The issue manifests when using commands like `HEAD@{1}` which rely on this field, though the direct branch reflog remains correct.

The email provides clear reproduction steps showing the difference between expected behavior (where the old_oid is properly recorded) and the current broken state (where it shows all zeroes). The problem appears specific to cases where a symbolic ref like HEAD points to the branch being modified, suggesting the bug lies in how update-ref handles indirect references during reflog updates.

This is a core refs/reflog functionality issue that could affect any workflow using symbolic references and reflog queries. The report is well-documented with concrete examples showing both correct and incorrect outputs, making it easy to verify and debug. The regression appears to have been introduced in Git 2.48, though the exact commit causing it isn't identified yet.
