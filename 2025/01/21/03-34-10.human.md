Refactoring patch in a series improving reftable migration path. This is the first of three patches addressing corruption issues discovered during large reflog conversions.

Karthik Nayak marks `ref_transaction_update_reflog()` as static since it's only used within refs.c. The function's documentation is preserved but moved to the implementation file from the header. This straightforward change was suggested by Junio Hamano and appears uncontroversial - the thread summary indicates this patch is already considered finalized.

The modification is clean: the function signature remains identical, just moved to internal visibility, while its explanatory comment about index field usage stays intact. This is part of a coordinated effort to harden the reftable backend against corruption, though this particular change is more about code organization than direct bug prevention.

The patch in the series will handle the more substantive changes to support large repositories and prevent integer overflow. This first step seems ready to go as a simple cleanup.
