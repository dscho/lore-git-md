Bugfix investigation for reflog regression in `git update-ref`. Jeff King responds to Nika Layzell's report of incorrect `old_oid` recording in derived reflogs (like HEAD) when updating branches referenced symbolically. The issue was introduced in commit 297c09eabb ("refs: allow multiple reflog entries for the same refname") from December 2024.

King identifies a suspicious early return in `lock_ref_for_update()` when `REF_LOG_ONLY` is set, which appears to be the root cause. He provides a simple one-line diff removing this early return that fixes the issue without breaking any tests, though notes he doesn't fully understand why those lines existed originally. The fix targets the files refs backend's handling of reflog updates during symbolic reference operations.

This is a core refs subsystem issue affecting reflog integrity for any workflow using symbolic references (like HEAD) with reflog queries. The proposed change is minimal but needs validation from the original author of 297c09eabb to ensure the removed check wasn't serving some important purpose. The regression is serious enough that it would likely warrant a fix release once properly vetted.
