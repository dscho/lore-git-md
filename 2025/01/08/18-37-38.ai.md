This is part 7/8 of a feature series implementing client-side support for remote object-info functionality, building on server-side support added earlier. The patch adds core client implementation for requesting object information (currently just sizes) from a v2 server via the new object-info capability.

The key technical additions are:
- New `fetch-object-info.[ch]` files implementing the request/response flow, with `fetch_object_info()` as the main entry point
- Integration with the transport layer to handle protocol version checking (v2-only) and capability verification
- Request construction via `send_object_info_request()` which writes the full request buffer before sending, following `send_fetch_request()`'s pattern
- Response parsing that validates server capabilities, protocol version, and response structure
- Memory management using `xcalloc` for result allocation
- Transport layer updates to support the new functionality across methods

The implementation enforces strict v2-only support (rejecting v0/v1 with clear errors) and requires explicit server capability advertisement. Error handling includes validation of server responses and proper cleanup. The patch builds on earlier transport refactoring work (generalizing packet writing) and integrates with the existing fetch-pack state machine.
