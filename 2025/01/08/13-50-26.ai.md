This is a platform compatibility discussion regarding random number generation failures on ia64 systems with OpenSSL 3.0.11/PRNGD, expanding from the original reftable-specific issue to broader CSPRNG concerns.

Randall Becker reports that their ia64 systems experience widespread test failures due to OpenSSL's PRNGD implementation failing when the pool is exhausted, while x86 systems work fine due to hardware RNG support. The issue appears to have emerged suddenly after a maintenance window, suggesting an environmental change rather than a Git regression. With ia64 support ending in 2025, Randall seeks a stopgap solution that could work with PRNGD while warning about reduced randomness quality.

Patrick Steinhardt had initially proposed reftable-specific fixes but now recognizes the problem affects all `git_rand()` callsites. He suggests completely removing OpenSSL CSPRNG support since NonStop is the only platform still using it, but Randall confirms ia64 has no alternative RNG backends available (`arc4random_buf`, `getrandom`, etc.). The discussion reveals a tension between security requirements for cryptographic randomness and practical needs on legacy platforms with limited entropy sources.

Key technical points include:
- OpenSSL 3.0.11's PRNGD fails on ia64 when entropy is exhausted
- No fallback RNG mechanisms available on ia64
- x86 systems work due to hardware RNG support
- Issue affects all `git_rand()` calls, not just reftable code
- NonStop platform's OpenSSL dependency complicates removal

The thread has shifted from fixing specific test failures to considering broader architectural changes to Git's RNG system, with platform support timelines (ia64 EOL 2025) now factoring into the decision. The sudden onset of failures suggests either an environmental configuration issue or previously latent OpenSSL behavior on ia64's limited entropy sources.
