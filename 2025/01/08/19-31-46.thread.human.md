This thread addresses user confusion around the `help.autocorrect` configuration by improving both its behavior and interface. The original patch proposed treating `help.autocorrect=1` as triggering immediate command correction (rather than a 0.1 second delay), which Johannes Schindelin approved as fixing a design mistake. Documentation issues were identified by Kristoffer Haugsbakk (style improvements) and Yongmin Hong (a typo fix).

In response to Junio Hamano's suggestion about making the configuration more intuitive, the v2 patch now additionally accepts boolean string values ("true"/"false", "yes"/"no" etc.) while maintaining backward compatibility with numeric delays. True values trigger immediate correction, false values show suggestions without executing (equivalent to 0), and numbers ≥2 still work as decisecond delays. The documentation clearly explains these behaviors and the subtle difference between "false" (show guesses) versus "never" (don't show guesses).

The implementation uses git_config_bool_or_int() to handle both boolean and numeric cases cleanly. With Johannes' approval of the core approach and the documentation issues addressed, this appears ready for merging. Junio's broader question about extended boolean handling remains an interesting design consideration for future work, but doesn't block this improvement.
