This thread has refined the behavior and interface of `help.autocorrect` through multiple iterations, with the latest patch adding a small finishing touch. The series began by addressing user confusion around the `help.autocorrect=1` behavior (which previously introduced an unnecessary 0.1 second delay) and evolved to create a clearer distinction between showing versus running corrections. Key contributors including Johannes Schindelin, Jeff King, and Junio Hamano helped shape the final design, which now groups equivalent values consistently: "false"/"off"/"no"/0 all show corrections without running them, "never" does nothing, and positive numbers specify a delay (with 1 meaning immediate execution).

The most recent patch, from Kristoffer Haugsbakk, adds "show" as another accepted value for the AUTOCORRECT_SHOW behavior, bringing this option in line with Git's convention of supporting multiple synonymous forms for boolean-like settings. This is a documentation and test completeness change rather than a functional one, following the substantive work in earlier versions to resolve the false/0 vs never distinction. With all core design questions settled and this final polish applied, the series appears ready for merging. The thread demonstrates Git's careful attention to configuration interface design, with each iteration incorporating feedback to arrive at a robust solution.
