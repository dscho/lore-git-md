This thread discusses a bugfix to make the `help.autocorrect` configuration behave more intuitively. The original patch from Scott Chacon changes the interpretation of `help.autocorrect=1` to trigger immediate command correction, rather than the previous 0.1 second delay that users found confusingly fast. The implementation in `help.c` now treats both "immediate" and "1" as equivalent values for instant correction while maintaining backward compatibility with other settings.

Kristoffer Haugsbakk has followed up with suggestions to improve the patch's documentation aspects, noting the commit message should use imperative mood per Git's style guidelines and that the `git-config` man page should be updated to reflect the new behavior. These are presentation refinements rather than objections to the technical change itself. The core behavior modification - making "1" mean immediate correction - remains uncontroversial and appears ready for merging once these documentation updates are addressed. No other reviewers have weighed in yet, and there don't seem to be any outstanding technical concerns about the change.
