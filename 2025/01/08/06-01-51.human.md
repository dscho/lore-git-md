Bugfix addressing a segfault in `git diff` when processing corrupted repository state. This patch adds validation to detect and handle an uninitialized `diff_filepair` status field, preventing a crash that occurs when object files are manually removed from the repository. The fix mirrors `git log`'s behavior of failing with an error message rather than crashing.

The issue occurs when the diff machinery encounters a filepair with a zero (invalid) status value, which can happen when repository objects go missing. While the commit message doesn't specify exact reproduction steps, the problem appears to stem from repository corruption rather than normal operation.

The change is minimal - just a 4-line validation in `diff.c` that checks the status field before use. The patch follows Git's existing error handling patterns by using `die()` for fatal errors. However, it currently lacks test coverage and doesn't explore whether similar validation might be needed elsewhere in the diff code.
