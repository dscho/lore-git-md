Test infrastructure patch adding unsafe SHA-1 testing capability. This is the first patch in an 8-part series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations.

The patch introduces a new `sha1-unsafe` test-tool helper that exercises Git's unsafe SHA-1 wrappers, mirroring the existing `sha1` test helper but using the unsafe variants of the hash operations. The implementation modifies the generic `cmd_hash_impl()` function to accept an `unsafe` parameter that determines whether to use the safe or unsafe variants of the hash functions (init, update, final). The test script `test-sha1.sh` is updated to run all tests against both the safe and unsafe variants.

Key technical details include:
- New `cmd__sha1_unsafe()` function added to `test-sha1.c`
- Modified `cmd_hash_impl()` signature and implementation to handle unsafe variants
- Updated test script to run all cases against both implementations
- Maintains existing SHA-256 test functionality (only SHA-1 gets unsafe variant)

This provides testing infrastructure needed for the subsequent patches in the series that will refactor the unsafe SHA-1 handling. The changes are focused on test helpers and don't affect production code paths. The patch appears well-structured with clear separation between the safe and unsafe testing paths.
