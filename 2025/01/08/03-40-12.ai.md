Feature addition to `git rev-list`'s `--missing` option, introducing a new `print-type` action that shows object types alongside missing object hashes.

The patch adds a `--missing=print-type` option to `git rev-list` that extends the existing `print` functionality by including object type information (commit, tree, blob, tag) when available. The output format is `?<oid> [type]`. The implementation replaces the previous `oidset` with an `oidmap` to store type information, and includes tests verifying the new behavior works for different object types (commits, trees, blobs).

Key technical details:
- New `MA_PRINT_TYPE` enum value and corresponding `print-type` string option
- Uses `oidmap` instead of `oidset` to store type information via `missing_objects_map_entry` struct
- Special handling for missing tips which lack type context
- Test coverage in t6022-rev-list-missing.sh verifies type output for different object types
- Alternative approaches considered (separate formatting option) but rejected in favor of dedicated action

The implementation appears thorough, with clear documentation updates and test coverage. The commit message explains the design choice between adding a new action versus a formatting option, suggesting thoughtful consideration of the interface. The change is relatively self-contained, primarily modifying `builtin/rev-list.c` while maintaining backward compatibility with existing `--missing` behaviors.
