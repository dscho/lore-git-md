This is a discussion about the missing object reporting feature in `git rev-list`, specifically focusing on output format and attribute handling. Junio Hamano responds to Justin Tobler's proposal for a `--missing-attr` option, arguing it may be over-engineered and suggesting instead to simply output all known attributes for missing objects, letting the consumer filter what they need.

Key technical points in this exchange:
- The discussion builds on the existing `--missing=print` functionality that shows unique missing object IDs
- Junio notes the path multiplicity issue (where an object may be referenced by multiple trees) already has precedent in `--objects` output - it shows the path only on first encounter
- The proposed solution is to record attributes (type, path) when first inserting into the missing object table (`oidmap`), then skip subsequent occurrences
- Output format considerations include future extensibility while maintaining backward compatibility with `--missing=print`

Junio's position favors simplicity - dumping all available attributes rather than implementing a filtering mechanism via `--missing-attr`. This suggests the implementation should focus first on robust attribute collection and output formatting, deferring selective display to post-processing. The exchange continues refining how to handle multiple paths per object while maintaining clean output semantics.
