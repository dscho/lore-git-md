Junio Hamano responds to Justin Tobler's proposal for extensible missing object reporting in `git rev-list`. This is part of the ongoing discussion about improving how Git reports missing objects during traversal.

Hamano pushes back against Justin's suggestion of a `--missing-attr` option to select which attributes to print, calling it potentially "over-engineered." Instead, he advocates for dumping all known information about missing objects and letting the user filter it as needed. This aligns with Git's general philosophy of providing rich output that tools can parse rather than adding numerous filtering options.

The discussion also touches on handling path information for missing objects. Hamano clarifies that the current `--objects` behavior (showing each object only once, with its first-seen path) provides a good model for missing objects too. The implementation should record attributes like path and type when first encountering an object, then skip duplicates.

This email moves the technical discussion forward by simplifying the proposed interface while maintaining the core goal of richer missing-object reporting. Hamano's position suggests favoring a more straightforward implementation that could be extended later if needed, rather than designing for every possible future case upfront. The thread continues to focus on balancing flexibility with simplicity in this new feature.
