This is a follow-up in the ongoing discussion about extending `git rev-list --missing` to report object types and other attributes. The thread has evolved from simply adding a `--missing=print-type` option to considering a more extensible `--missing-attr` system that could handle multiple attributes like type and path information.

Justin Tobler responds to Christian Couder's review suggestions by agreeing to:
1. Refactor the code to extract common operations into helper functions (`add_missing_object_entry` and `print_missing_objects`)
2. Move toward a more generic `--missing-attr` approach rather than adding specific `print-type` action
3. Maintain cleaner output formatting by omitting spaces when type information isn't available

The technical discussion now centers around:
- Using `oidmap` to track missing objects with their attributes
- Proper handling of cases where type information isn't available (like missing commit tips)
- Future extensibility for additional attributes while maintaining backward compatibility

The implementation remains focused in `builtin/rev-list.c` with test coverage in `t6022-rev-list-missing.sh`. The changes represent a shift from a single-purpose solution to a more flexible attribute reporting system, with path information likely being the next addition.
