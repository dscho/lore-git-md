Maintainer fast-tracking of reftable test allocator fix.

Junio Hamano acknowledges Johannes Schindelin's patch that changes reftable test initialization to pass NULL allocators instead of explicit malloc/free pointers. This follows up on the thread about Windows-specific heap corruption issues caused by allocator switching in the reftable test suite. 

The key technical point is that passing NULL to `reftable_set_alloc()` makes the code use whatever malloc implementation is currently active (like Windows' mimalloc) rather than trying to explicitly capture function pointers. This avoids the STATUS_HEAP_CORRUPTION errors seen in Windows builds while being semantically cleaner - the reftable infrastructure already handles NULL parameters by maintaining the current allocator.

Junio notes an additional subtle benefit: the NULL approach doesn't require taking the address of malloc (which could be problematic if malloc were a macro). He indicates this will be fast-tracked to master, suggesting the fix is both correct and urgent. The message implies consensus from previous discussion (including René Scharfe's review) that this is the right solution.

This appears to be the final step in resolving the Windows-specific test failures, with the maintainer's approval clearing the path for inclusion in Git for Windows v2.48.0-rc2 and potentially the main Git codebase. The change remains confined to test infrastructure rather than production reftable code.
