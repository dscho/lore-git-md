Platform-specific random number generation issue on ia64 systems. Randall Becker reports that OpenSSL 3.0.11 on ia64 systems (using PRNGD) fails entropy-related tests, while x86 systems (using hardware RNG) work fine. This appears to be a systemic issue affecting multiple Git tests, not just the original reftable case.

The discussion has shifted from Patrick Steinhardt's initial reftable-specific fix to considering whether to deprecate OpenSSL's CSPRNG backend entirely, since it's now only used on NonStop platforms. Randall notes that ia64 has no alternative RNG sources available, and the platform will reach end-of-life in 2025 anyway. He suggests a stopgap solution might be possible with PRNGD if Git can reduce randomness requirements.

Key points:
1. The problem is specific to ia64's OpenSSL/PRNGD configuration and appeared suddenly after a maintenance window
2. No alternative RNG sources exist on ia64
3. The platform will be discontinued soon, limiting the impact window
4. A warning about reduced randomness might be acceptable as a temporary measure

This appears to be a time-limited platform compatibility issue rather than a fundamental design problem in Git's RNG system. The discussion is converging toward either accepting reduced security on these legacy systems or waiting for their retirement.
