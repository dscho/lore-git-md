This is a bugfix and usability improvement for the `help.autocorrect` configuration. The patch addresses a common misunderstanding where users set `help.autocorrect=1` expecting it to enable immediate command correction, when in fact it was being interpreted as a 0.1 second delay (1 decisecond). The author notes this is too fast for human reaction time, making the current behavior confusing.

The change makes `help.autocorrect=1` behave the same as `help.autocorrect=immediate`, skipping the delay and just showing the corrected command. This matches what most users likely intend when setting the value to 1. The implementation is straightforward - just adding "1" as another condition that triggers the immediate behavior.

The patch is small (a single line change) and well-justified, fixing a clear usability issue without introducing any complexity. It maintains backward compatibility while making the configuration more intuitive. The change is unlikely to be controversial as it doesn't affect any existing documented behavior (the docs already describe "immediate" as the intended way to skip the delay).
