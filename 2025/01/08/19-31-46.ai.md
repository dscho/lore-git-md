This is a bugfix patch addressing user confusion around the `help.autocorrect` configuration. The patch changes the interpretation of setting `help.autocorrect=1` to mean "immediate" autocorrection rather than waiting 0.1 seconds, which was the previous behavior.

The author notes that many users mistakenly set this value to 1 thinking it's a boolean flag to enable/disable the feature, when in fact it was being interpreted as a decisecond delay value. Since 0.1 seconds is too fast for human reaction time anyway, the patch makes this common case behave as users likely intend - executing the corrected command immediately without delay.

The change is minimal, modifying just one line in `help.c` to treat both "immediate" and "1" as equivalent values that trigger immediate autocorrection. The patch maintains all other behaviors (never, prompt, and numeric delay values) unchanged. This appears to be a well-motivated change that fixes a clear UX issue without introducing any backward compatibility concerns, as the old numeric delay behavior remains available for any users who actually wanted sub-second delays.
