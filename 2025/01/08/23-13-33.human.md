This is a follow-up in the ongoing discussion about extensible missing object reporting in `git rev-list`. Justin Tobler responds to Junio Hamano's suggestion to simplify the approach by having Git output all known attributes about missing objects rather than implementing a complex filtering mechanism.

The key points in this response:
1. Justin agrees with Junio's simpler approach of dumping all available attributes rather than implementing selective attribute printing via options like `--missing-attr`.
2. He suggests two possible implementations: either adding a new `--missing=print-attr` action type or modifying the existing `--missing=print` output to include all attributes.
3. Justin confirms understanding Junio's explanation about handling multiple paths for the same missing object (taking the first encountered path, similar to how `--objects` works).

This email represents consensus-building in the thread, with Justin aligning his implementation approach with Junio's preference for simplicity while maintaining the ability to extend attribute reporting in the future. The discussion appears to be converging on a solution that will output all known attributes in a format like `?<oid> [<token>=<value>...]`.
