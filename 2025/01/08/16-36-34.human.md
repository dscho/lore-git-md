This is a bugfix for the reftable test suite that addresses an allocator inconsistency issue affecting Windows builds. René Scharfe is responding to Johannes Schindelin's patch that fixes heap corruption occurring when the reftable tests switch between custom allocators (like Windows' mimalloc) and the default allocator.

The core issue stems from recent reftable test changes that explicitly passed malloc/free pointers, overriding the custom allocator after it had already been used for initial allocations. This caused STATUS_HEAP_CORRUPTION errors on Windows. Scharfe agrees with Schindelin's solution to pass NULL instead, which properly maintains allocator consistency by falling back to the initial allocator.

The fix is straightforward - changing four reftable_set_alloc() calls to use NULL parameters. Scharfe notes this better captures the intent to use default allocators. While the patch specifically addresses Windows issues, the underlying problem could affect any platform using custom allocators. The change appears well-justified and narrowly targeted at fixing the test behavior without broader implications.
