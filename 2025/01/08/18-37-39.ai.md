Feature addition to `git cat-file --batch-command` for remote object info queries. This is the final patch in a 9-part series implementing client-side support for remote object-info functionality.

The patch adds a new `remote-object-info` command to `git cat-file --batch-command` that allows querying object metadata (currently just sizes) from a remote server without downloading the objects themselves. The implementation handles both buffered and non-buffered modes, with the key optimization being that multiple object IDs can be specified in a single command to avoid per-object network overhead.

Key technical details:
- New command syntax: `remote-object-info <remote> <oid>...`
- Currently only supports `%(objectname)` and `%(objectsize)` format options
- Explicitly rejects unsupported format options like `%(objecttype)` and `%(deltabase)`
- Requires protocol v2 and server-side object-info capability (enabled via `transfer.advertiseobjectinfo`)
- Includes comprehensive tests covering:
  - Multiple transport protocols (git://, file://, http://)
  - Error cases (invalid OIDs, missing objects, unsupported protocols)
  - Buffer and non-buffer modes
  - Null-delimited input (-Z) mode
- Adds new `free_object_info_contents()` helper in object-store-ll.h
- Modifies default format for remote queries to `%(objectname) %(objectsize)` (with warning this may change when more fields are supported)

The implementation builds on the infrastructure from earlier patches in the series, completing the client-side functionality by integrating with `git cat-file`. The extensive test suite verifies both successful operation and proper error handling across all supported transports.
