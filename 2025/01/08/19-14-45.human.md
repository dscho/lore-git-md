This is part 5 of an 8-part series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations. The patch converts `csum-file.c` to use the new `unsafe_hash_algo()` infrastructure introduced in earlier patches, rather than calling the unsafe hash function variants directly.

Taylor Blau updates the file to initialize the hashfile's algorithm pointer with `unsafe_hash_algo(the_hash_algo)`, which automatically routes all subsequent hash operations through the unsafe variants. This removes explicit calls to `unsafe_update_fn`, `unsafe_final_fn`, etc., replacing them with the standard `update_fn`, `final_fn` names that now point to the unsafe implementations via the algorithm pointer.

The changes are mechanical but thorough, touching all hash operations in the file including hash flushing, finalization, writing, checkpointing, and checksum validation. This continues the series' pattern of making the unsafe operations opt-in at the algorithm selection level rather than requiring explicit unsafe calls throughout the codebase. The patch appears to be a straightforward application of the new infrastructure with no obvious issues.
