This is part 4 of an 8-part series refactoring Git's hash algorithm handling to eliminate separate variants of hash operations. The patch introduces a new `unsafe_hash_algo()` function that provides access to a wrapped version of a hash algorithm struct, replacing the previous pattern of having separate `unsafe_` prefixed functions for each operation.

The key improvement here is moving from a pattern where callers must remember to use matching `unsafe_` variants of hash functions (init, update, final) to a model where they simply get an algorithm pointer that already has the unsafe behavior baked in. This reduces the risk of mixing safe and unsafe operations accidentally. The patch adds the new function and implements it for SHA-1, with the unsafe variant now accessible via the `unsafe` field in the main algorithm struct.

This continues the series' clean approach to hash algorithm abstraction, with each patch making focused, testable changes. The implementation looks straightforward and maintains backward compatibility while moving toward the cleaner API. The change was suggested by Jeff King and appears well-considered, with the commit message clearly explaining both the problem and solution.
