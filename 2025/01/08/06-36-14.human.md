**Feature deprecation notice with user control**

This is a follow-up in a thread about deprecating the legacy "branches/" and "remotes/" directory structures in Git's remote configuration. The patch author, Patrick Steinhardt, is responding to feedback about warning messages for these deprecated paths.

The key development here is a proposed solution to control the deprecation warnings. In response to a suggestion about allowing users to suppress warnings once they're aware of the issue, Steinhardt proposes using an environment variable `GIT_ALLOW_DEPRECATED_REMOTES=true` to silence the messages, along with accompanying hints about how to enable it.

This appears to be part of a careful deprecation process where the team is balancing the need to notify users about upcoming changes while providing mechanisms to reduce warning fatigue. The discussion shows responsiveness to user experience concerns, though we don't see the actual warning implementation being discussed in this particular message.

The thread context suggests this is the final patch in a series (v2 5/5), but without seeing the cover letter, we can't be certain of the full scope of changes. The focus here is specifically on the warning mechanism rather than the underlying deprecation itself.
