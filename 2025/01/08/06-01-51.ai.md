Bugfix addressing a segfault in `git diff` when processing invalid diff status. This patch adds validation for the `status` field in `diff_filepair` structures, which can become zero (invalid) when certain object files are missing. The change mirrors `git log`'s behavior of failing with an error message rather than crashing.

The patch modifies `diff.c` to check for zero status values during diff queue processing, adding a `die()` call with a generic "invalid diff status" message. The fix is minimal (4 lines) and targets the specific crash scenario where uninitialized status values lead to undefined behavior. The commit message notes this makes `git diff` behave more like `git log` when encountering corrupt/missing objects, though it doesn't specify exact reproduction steps.

Key technical details include: the validation occurs in `diff_queued_diff_prefetch()`, the affected struct field is `diff_filepair->status`, and the error handling uses Git's standard `die()` mechanism. The change appears technically sound but leaves open questions about whether this indicates deeper issues in diff machinery initialization, and whether similar validation might be needed elsewhere. The patch currently lacks test coverage, which could verify both the crash prevention and error message behavior.
