This is part 7 of an 8-part series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations. The patch introduces a new `hashfile_checkpoint_init()` function that ensures hashfile checkpoints use the same hash algorithm as their parent hashfile, preventing crashes when the algorithms mismatch.

The change addresses crashes that occurred in `fast-import` and `bulk-checkin` when checkpoint initialization used a different hash implementation than the main hashfile. The new function centralizes the initialization logic and removes explicit unsafe hash function calls, making the code more robust against future hash algorithm changes. The patch updates both `fast-import.c` and `bulk-checkin.c` to use the new helper function.

Notable improvements include removing the need for explicit zero-initialization of checkpoints and properly handling cases where the hashfile isn't immediately available in `bulk-checkin`. The change demonstrates good attention to edge cases while simplifying the interface - a solid incremental improvement to the ongoing hash algorithm refactoring work.
