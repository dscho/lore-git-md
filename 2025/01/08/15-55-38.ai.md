This is part 5 of a 6-part series implementing client-side support for object-info functionality, building on server-side support added in a2ba162cda. The patch adds client functions to request object information (currently just sizes) from a v2 server via the object-info capability.

The core implementation is in the new fetch-object-info.[ch] files, which handle sending object-info requests and processing responses. The client will error out if the server doesn't advertise the object-info capability (controlled by transfer.advertiseobjectinfo). The transport layer is updated to support this new capability across different transport methods.

Calvin Wan suggests two improvements in the error message wording ("unsupported" instead of "wrong" protocol version) and flattening some conditional logic in the response parsing. Eric Ju acknowledges these and indicates they'll be fixed in v9 revision.

Key technical details:
- New files: fetch-object-info.[ch] with core request/response handling
- Protocol: Only v2 supported, rejects v0/v1 explicitly
- Current feature: "size" requests for object sizes
- Memory management: Allocates space for results via xcalloc
- Error handling: Checks server capability, protocol version, response validity

The patch appears to be in good shape with clear direction from the original author on suggested improvements. The functionality builds logically on prior work and has received review input from multiple contributors (Jonathan Tan, Christian Couder).
