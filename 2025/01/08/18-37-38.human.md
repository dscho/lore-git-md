This is part 7/8 of a feature series adding client-side support for remote object-info functionality, building on server-side support added earlier. The patch implements the core client logic for requesting object information (currently just sizes) from a v2 server.

The patch introduces new files `fetch-object-info.[ch]` containing the main implementation, which handles constructing the protocol request and parsing responses. The client will error out if the server doesn't advertise the object-info capability (controlled by `transfer.advertiseobjectinfo`). The implementation follows the same buffered request pattern used elsewhere in fetch-pack.c.

Key technical aspects include:
- Strict protocol version checking (v2 only)
- Support for the 'size' feature
- Memory allocation for results using xcalloc
- Integration with the transport layer and fetch-pack state machine
- Error handling for unsupported protocols and malformed responses

The patch appears well-structured with thorough error handling, though it's worth noting this is only the client-side piece - server support must be enabled separately. The implementation looks solid, building carefully on existing protocol infrastructure while adding the specific object-info functionality. This continues the series' pattern of careful, incremental development with good test coverage.
