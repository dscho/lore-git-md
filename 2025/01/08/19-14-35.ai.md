Refactoring patch in a series eliminating unsafe hash variants. This is the second of eight patches in brian m. carlson's series to consolidate Git's hash algorithm handling by removing separate "unsafe" function variants. The patch modifies the `hashfile` struct to store its own hash algorithm pointer (`algop`) rather than relying on the global `the_hash_algo`, preparing for future changes where different hashfiles might use different algorithms.

The changes touch `csum-file.[ch]`, adding the new field` and updating all hash operations (`init_fn`, `update_fn`, `final_fn`, `clone_fn`) to use the stored algorithm pointer rather than the global. The diff shows mechanical conversions of all unsafe hash operations in the hashfile API to use the new field, maintaining identical behavior but with more explicit algorithm tracking. This is a straightforward structural change that enables the broader series' goal of eliminating unsafe variants while keeping the same functionality.

Key technical details include:
- New `algop` field added to `struct hashfile` in `csum-file.h`
- All unsafe hash operations (`unsafe_init_fn`, `unsafe_update_fn`, etc.) updated to use `f->algop` instead of `the_hash_algo`
- Initialization of `algop` set to `the_hash_algo` for backward compatibility
- Changes to `hashflush()`, `finalize_hashfile()`, `hashwrite()`, and checkpointing functions to use the stored algorithm

The patch follows the series' pattern of first establishing test infrastructure (in patch 1) before making core changes. It maintains the existing behavior while setting up for the elimination of unsafe variants in later patches. The changes are focused and mechanical, with no behavior modifications beyond the internal pointer indirection.
