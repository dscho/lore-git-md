This is a feature addition to `git rev-list` that extends the `--missing` option with a new `print-type` mode. The patch, originally from Justin Tobler, adds the ability to show not just object IDs but also their types (commit, tree, blob, tag) when reporting missing objects, formatted as `?<oid> [type]`.

Junio Hamano's review raises important considerations about the design. He notes the documentation should clarify that these types are inferred from context (like parent pointers or tree entries) rather than from the missing objects themselves. He suggests a more extensible output format (`?<oid> [key=value]...`) that could accommodate future additions like path information, with proper escaping for special characters. While not requesting immediate implementation of these extensions, he emphasizes keeping the design open for them.

The review maintains the patch's core functionality while thoughtfully considering its future evolution. This appears to be a well-reasoned enhancement to Git's missing object reporting, with room to grow based on user needs. The discussion is now at the design refinement stage before finalizing the implementation details.
