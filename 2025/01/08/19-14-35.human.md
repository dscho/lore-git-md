Refactoring patch in a series about hash algorithm handling. This is the second of eight patches that aim to clean up Git's hash algorithm API by eliminating separate "unsafe" variants of hash operations.

Taylor Blau modifies the hashfile API to store the hash algorithm as a field in the `hashfile` struct rather than relying on the global `the_hash_algo`. The patch updates all hash operations in `csum-file.c` to use this new field (`f->algop`) instead of the global variable, while maintaining identical behavior. A new `algop` field is added to `struct hashfile` in `csum-file.h`.

This change prepares for future work where different hash algorithms might be used within the same process, though for now it still initializes the field with `the_hash_algo`. The patch is mechanical but thorough, updating all hash operations including init, update, final, and clone functions. It's part of a larger effort by brian m. carlson to improve Git's hash algorithm abstraction, building on previous work to make Git's internals more flexible around hash algorithms.
