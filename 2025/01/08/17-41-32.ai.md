This is a follow-up acknowledgment in the reftable test suite allocator fix thread. Junio Hamano confirms René Scharfe's agreement with the NULL allocator solution that Johannes Schindelin proposed to fix Windows-specific test failures. The issue stemmed from explicit malloc/free pointers in the reftable test code conflicting with Windows' mimalloc implementation, causing heap corruption. The NULL approach allows reftable to maintain allocator consistency naturally.

The thread has reached consensus that passing NULL to `reftable_set_alloc()` is both technically correct (avoiding issues with taking addresses of potentially-macro'd malloc implementations) and semantically cleaner than explicit allocator switching. This solution has already been merged to master and will be included in Git for Windows v2.48.0-rc2. No further action appears needed as all parties agree this resolves the immediate problem while being a general improvement to the test infrastructure.
