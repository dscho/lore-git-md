Feature implementation for remote object-info protocol support (part 6/8 of series).

This patch adds server-side advertisement of supported object-info features, currently just "size" capability, allowing clients to check server support before making requests. The change modifies `object_info_advertise()` in serve.c to populate a strbuf with the supported features when advertising is enabled, while maintaining the existing config-based enable/disable logic (`transfer.advertiseobjectinfo`).

Key technical details:
- Server now advertises "size" as the supported object-info feature when enabled
- Maintains backward-compatible boolean advertisement via return value
- Uses existing `advertise_object_info` config/static variable control
- Follows protocol pattern of feature advertisement via strbuf population
- Part of broader object-info capability work building on a2ba162cda server support

The change is straightforward but important for protocol completeness, letting clients make informed decisions about whether to use object-info or fall back to full fetches. It builds on the series' established patterns for capability advertisement while keeping the door open for future feature additions (though currently only "size" is implemented). The patch shows clean integration with existing serve.c infrastructure and maintains the series' high standard of configurable behavior.
