This is a cover letter for a patch series that refactors Git's hash algorithm handling to better support unsafe/non-cryptographic variants. The series introduces a new `unsafe_hash_algo()` function to access unsafe hash variants through a wrapped struct, eliminating the need for separate `unsafe_*` function variants.

The series builds on previous work to support unsafe SHA-1 implementations (for testing and performance) and addresses a deficiency in the original approach where callers had to manually switch between safe and unsafe variants. The new approach makes it impossible to accidentally mix safe and unsafe operations.

Key changes include:
1. Adding infrastructure to store hash algorithms in struct fields
2. Introducing `unsafe_hash_algo()` as the central mechanism
3. Converting existing callers to use the new pattern
4. Finally removing the now-unneeded `unsafe_*` function variants

A new patch (7/8) was added in v2 to further harden hashfile checkpoint initialization, preventing potential crashes when mixing hash variants. The series touches core hash functionality, test helpers, and several subsystems that use hashing (fast-import, bulk-checkin).

The changes appear well-motivated and carefully implemented, with good test coverage. The series follows up on previous discussions and builds on recent work by Patrick Steinhardt. It represents a significant cleanup of Git's hash algorithm handling that should make the code more maintainable while preventing subtle bugs.
