This is part 5 of an 8-part series refactoring Git's hash algorithm handling to eliminate separate function variants for "unsafe" operations. The patch converts `csum-file.c` to use the new `unsafe_hash_algo()` infrastructure introduced in patch 4, removing direct calls to the `unsafe_` prefixed functions.

The changes are mechanical but wide-ranging across `csum-file.c`, updating all hash operations to use the standard function names (`init_fn`, `update_fn`, `final_fn`, `clone_fn`) through the algorithm pointer that now points to the unsafe variant. Key modifications include:
- Initializing the hashfile's `algop` to `unsafe_hash_algo(the_hash_algo)` in `hashfd_internal()`
- Converting all hash operations (`hashflush()`, `finalize_hashfile()`, `hashwrite()`, checkpoint handling) to use the standard function names
- Updating `hashfile_checksum_valid()` to use the unsafe algorithm variant while maintaining the same validation logic

The patch follows the series' pattern of maintaining backward compatibility while cleaning up the API, with all unsafe operations now accessed through the algorithm pointer indirection rather than separate function names. This continues the effort to prevent accidental mixing of safe/unsafe operations while making the codebase more maintainable for future hash algorithm work.
