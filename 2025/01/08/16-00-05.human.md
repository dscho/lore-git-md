**Bugfix for reftable tests with custom allocators on Windows**

This patch fixes a heap corruption issue in the reftable unit tests that occurs when using custom memory allocators (like `mimalloc` in Git for Windows). The problem stems from recent changes that introduced explicit allocator function pointer calls, which inadvertently override custom `#define`d allocators after they've already been used to initialize memory.

The fix is straightforward: instead of passing the default `malloc`/`realloc`/`free` functions to `reftable_set_alloc()`, the patch passes NULL to maintain the existing custom allocator behavior. This prevents the dangerous mixing of allocators that was causing `STATUS_HEAP_CORRUPTION` errors on Windows.

The patch appears well-motivated and addresses a real issue that's blocking the Git for Windows release. The change is minimal (just 4 lines modified) and focused on the test code, though the commit message suggests this was discovered through broader testing of the reftable changes. The author notes the patch is based on an existing branch that has its own CI failures, but those appear unrelated to this specific fix.
