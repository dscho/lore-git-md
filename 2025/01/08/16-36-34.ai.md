Bugfix for reftable test suite allocator handling, addressing Windows-specific heap corruption issues. This is a follow-up to Johannes Schindelin's patch that identified problems when custom allocators (like Windows' mimalloc) interact with recent reftable test changes.

René Scharfe concurs with the analysis and solution, noting that passing NULL to `reftable_set_alloc()` better expresses the intent to use default allocators. The patch modifies four calls in `t/unit-tests/t-reftable-basics.c` to avoid allocator switching during array operations, which was causing STATUS_HEAP_CORRUPTION on Windows (manifesting as exit code 127 in test runs).

Key technical points:
- Changes replace explicit `malloc/free` pointers with NULL in `reftable_set_alloc()` calls
- Reftable internally maintains allocator consistency when NULL is passed
- Fixes interaction between initial mimalloc usage and subsequent libc allocator calls
- Builds on rs/reftable-realloc-errors branch work (commits 8db127d43f5b and 2cca185e8517)
- Affects test infrastructure rather than production reftable code

The thread context shows this was blocking Git for Windows v2.48.0-rc2, though the issue appears present in the base branch too. René's response indicates consensus on the NULL approach being more semantically correct while solving the immediate problem. No new technical concerns are raised in this follow-up.
