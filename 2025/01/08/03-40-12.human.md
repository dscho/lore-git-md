Feature enhancement for `git rev-list`'s missing object handling. Justin Tobler proposes adding a new `--missing=print-type` option that extends the existing `print` action to include object type information when available. The patch modifies the internal storage to track types alongside object IDs and updates documentation and tests accordingly.

The change allows users to see not just which objects are missing (prefixed with "?") but also their types (commit, tree, blob, etc.) when known. This could be useful for debugging or understanding the nature of missing objects in a repository. The implementation switches from using an oidset to an oidmap to store the additional type information.

The author considered alternative approaches like a separate formatting option but opted for this direct solution since type information was the primary goal. The patch appears well-constructed with thorough test coverage and clear documentation updates. This seems like a straightforward quality-of-life improvement for users who need to diagnose missing objects.
