This thread introduces a new `--missing-info` option for `git rev-list` that provides detailed reporting about missing objects, evolving from the simpler `--missing=print` functionality. Justin Tobler's implementation tracks both the path and type of missing objects using an `oidmap` with `missing_objects_map_entry` struct, with comprehensive tests in `t6022-rev-list-missing.sh`.

The design emerged through discussion with Christian Couder and Junio Hamano, following Unix philosophy principles by outputting all known attributes (path and type) and letting consumers filter what they need. The two-part series first added path reporting, now completed with type information in this second patch. The output format uses C-style quoting (e.g. `?<oid> path=<path> type=<type>`) and maintains backward compatibility.

Key implementation details include new helper functions (`add_missing_object_entry`, `print_missing_object`), careful handling of path resolution to match `--objects` behavior, and thorough test coverage. The series achieves consensus on recording attributes upfront while avoiding in-Git filtering. With both path and type reporting now implemented, this completes the thread's goal of extensible missing object reporting.
