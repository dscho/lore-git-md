This thread discusses extending `git rev-list`'s missing object reporting to include additional attributes like object type and path, moving beyond the current simple `--missing=print-type` functionality. The initial proposal from Justin Tobler suggested a filtering mechanism (`--missing-attr`), but after review from Christian Couder and input from Junio Hamano, the approach has shifted toward a simpler Unix-style design where Git outputs all available attributes and lets consumers filter as needed.

The current consensus is to:
- Record attributes (type and path) when an object is first noted as missing
- Use an output format like `?<oid> [<token>=<value>...]` with proper quoting
- Maintain backward compatibility with existing `--missing=print` behavior
- Let external tools handle any attribute filtering rather than building it into Git

In the latest email, Justin confirms agreement with Junio's simplified approach and is considering implementation details - whether to introduce a new `--missing=print-attr` option or extend the existing `--missing=print`. The path handling will follow `--objects` behavior where only the first encountered path is recorded.
