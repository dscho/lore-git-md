This thread discusses improvements to Git's missing object reporting in `git rev-list`, evolving from a simple type-printing feature to a more flexible system that can report multiple attributes like object types and paths. The initial proposal by Justin Tobler introduced a `--missing-attr` option with extensible design, storing attributes in an `oidmap` with helper functions for clean output formatting.

Christian Couder provided key review feedback advocating for this extensible approach, while Junio Hamano has now weighed in with a simpler vision - suggesting we output all available attributes by default rather than implementing filtering through `--missing-attr`. Junio notes the path multiplicity problem (where an object may be referenced by multiple paths) already has precedent in Git's `--objects` output, which shows the path only on first encounter.

The current technical focus has shifted toward:
1. Robust attribute collection (recording type and first-seen path)
2. Clean output formatting that maintains backward compatibility
3. Handling special characters with proper quoting
4. Deferring attribute filtering to post-processing tools

The implementation remains in `builtin/rev-list.c` with tests in `t6022-rev-list-missing.sh`. While the core design has consensus, the team is still working through output format details and how best to handle multiple path references while keeping the output clean and machine-parseable. Junio's latest input suggests simplifying the approach by outputting all known attributes rather than implementing complex filtering in Git itself.
