This is a bugfix patch addressing a memory allocation issue in the reftable test code. The problem occurs when custom allocators (like Windows' mimalloc) are used, as recent changes to the reftable test suite inadvertently forced a switch back to default allocators mid-operation, causing heap corruption.

The patch modifies `t/unit-tests/t-reftable-basics.c` to pass NULL instead of explicit `malloc`/`free` pointers to `reftable_set_alloc()`, allowing the reftable code to maintain consistency with whatever custom allocator was initially set up. This fixes a `STATUS_HEAP_CORRUPTION` error on Windows that manifested as exit code 127 in test runs.

The issue was introduced by two recent commits (8db127d43f5b and 2cca185e8517) that added explicit allocator` function pointer parameters. The patch author notes this is blocking Git for Windows v2.48.0-rc2 release, though the PR build failures appear to be present in the base branch as well.

Key technical details for future reference:
- The fix involves 4 changes to `reftable_set_alloc()` calls in the test file
- The problematic behavior occurs when mixing allocators during array initialization and resizing
- The reftable code already has fallback behavior when NULL parameters are passed
- Windows-specific symptoms include `STATUS_HEAP_CORRUPTION` (C0000374)
- Related to rs/reftable-realloc-errors branch
