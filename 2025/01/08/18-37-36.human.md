This is a refactoring patch in the ongoing series implementing client-side remote object-info support. It moves initialization code for fetch-pack's v2 protocol handling out of the state machine's initial state and before the state machine itself, in preparation for supporting multiple initial states.

The change is straightforward - it relocates three variable initializations (`allow_unadvertised_object_request`, `use_sideband`, and `args->deepen`) that were previously inside the `FETCH_CHECK_LOCAL` case to just before the state machine loop begins. The commit message clearly explains this is a future-proofing change that maintains identical behavior while allowing for more flexible state machine initialization in upcoming patches.

The patch has been reviewed by Jonathan Tan and Christian Couder, and carries their "Helped-by" tags along with Calvin Wan's sign-off. This appears to be a clean, well-justified preparatory change as part of the larger series.
