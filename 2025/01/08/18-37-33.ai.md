This is a refactoring patch in the ongoing series implementing client-side remote object-info support. It's a minor code style improvement that moves loop counter variable declarations inside their respective for loops where they are only used within the loop scope.

The patch modifies two files - `builtin/cat-file.c` and `fetch-pack.c` - changing four instances where loop counters were declared at function scope but only used within a single loop. Each change moves the declaration into the loop header and updates the type to `size_t` where appropriate (notably in cases dealing with array sizes or counts). The changes are purely stylistic with no functional impact, improving code readability by limiting variable visibility to their actual usage scope.

This follows standard C best practices for loop variable scoping and was reviewed by Christian Couder. The changes are straightforward and uncontroversial, aligning with the series' overall polish and attention to code quality details. The patch fits naturally with the series' broader focus on clean, maintainable code for the new remote object-info functionality.
