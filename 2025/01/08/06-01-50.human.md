Bugfix patch addressing a segfault in `git diff` when encountering invalid diff status. 

Jake Roggenbuck reports encountering a segmentation fault when running `git diff` after manually removing some object files. The issue stems from the `status` field of `diff_filepair` remaining uninitialized (zero value) in certain cases. The patch adds a check for this invalid status and makes `git diff` exit gracefully with an error message, mirroring the behavior of `git log` in similar situations.

The patch is minimal (4 lines added to diff.c) and appears to address a real crash scenario, though the exact reproduction steps aren't fully specified beyond manual object file removal. The author notes this was discovered while working on a school assignment and expresses enthusiasm for fixing the issue. 

While the fix seems reasonable, reviewers might want to understand more about the specific conditions that lead to the uninitialized status field, and whether there are other code paths that could benefit from similar validation. The patch doesn't include tests, which would help verify the fix and prevent regression.
