Here's the updated human-readable thread summary:

Johannes Schindelin (Dscho) identified and fixed a Windows-specific issue in the reftable test suite where explicit malloc/free pointers were causing heap corruption (STATUS_HEAP_CORRUPTION) during test execution. The problem stemmed from recent changes to the reftable test initialization that didn't play well with Windows' mimalloc allocator. The solution changes four `reftable_set_alloc()` calls to pass NULL instead, letting reftable maintain allocator consistency automatically.

René Scharfe reviewed and agreed this approach is both correct and semantically cleaner, as reftable already handles NULL parameters appropriately. Junio Hamano has now fast-tracked the fix to master, noting an additional benefit - avoiding taking malloc's address prevents potential issues if malloc were a macro. This resolves the immediate Windows test failures blocking Git for Windows v2.48.0-rc2, while being a general improvement to the test infrastructure. The change remains confined to test code and doesn't affect production reftable usage. With the maintainer's approval, this appears to be the final step in addressing the issue.
