The problem emerged when recent changes to the reftable test code (commits 8db127d43f5b and 2cca185e8517) inadvertently forced a switch back to default allocators during test execution, leading to STATUS_HEAP_CORRUPTION errors that manifested as test failures with exit code 127.

The fix modifies the test file t/unit-tests/t-reftable-basics.c to pass NULL instead of explicit malloc/free pointers to reftable_set_alloc(), allowing the reftable code to maintain consistent allocator usage throughout the test. This issue is particularly urgent as it's currently blocking the Git for Windows v2.48.0-rc2 release, though the problem appears to exist in the base branch as well. The solution leverages the reftable code's existing fallback behavior when NULL parameters are provided.
