Bugfix discussion regarding entropy pool exhaustion in reftable and broader Git usage. This email from Patrick Steinhardt responds to Randall Becker's report of test failures when OpenSSL's entropy pool is exhausted, particularly on ia64 systems using PRNGD.

The conversation reveals the issue is more widespread than initially thought - affecting multiple callsites beyond just reftable. Patrick now agrees with Brian Carlson's position that insecure fallbacks aren't the right solution, as this would require patching numerous callsites. Instead, he suggests potentially removing the OpenSSL CSPRNG backend entirely since NonStop (the only platform using it) might support alternative methods like arc4random or /dev/urandom.

Patrick notes the timing suggests a system configuration change during a maintenance window may be the root cause, as the failures appeared suddenly between release candidates without Git changes to the random number generation. The discussion highlights the tension between robustness (handling entropy exhaustion) and security (avoiding weak random number generation) in Git's cryptographic operations.
