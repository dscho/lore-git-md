This is a follow-up to the reftable test suite allocator fix, now being fast-tracked to master. Junio Hamano acknowledges Johannes Schindelin's patch that changes test initialization to use NULL allocators rather than explicit malloc/free pointers, which avoids issues with custom allocators like Windows' mimalloc. 

The key insight is that passing NULL to `reftable_set_alloc()` lets the reftable code maintain allocator consistency by using whatever malloc implementation is currently active, rather than forcing a specific one. This solves the Windows-specific heap corruption issues while being semantically cleaner - as Junio notes, it doesn't even require taking malloc's address.

The patch has already received positive review from René Scharfe and is considered ready for immediate inclusion. This was identified as blocking the Git for Windows v2.48.0-rc2 release, though the underlying issue appears present in the base branch as well. The change affects only test infrastructure, not production reftable code.

Junio's response indicates this straightforward fix has achieved consensus and will be merged promptly, resolving the Windows build issues while improving the code's robustness against custom allocators in general.
