This is a performance-oriented patch series introducing support for zlib-ng as an alternative zlib backend. The series refactors Git's zlib integration to allow switching between standard zlib and zlib-ng, which provides optimized implementations using modern CPU features like SSE2 and AVX2.

The cover letter presents compelling results showing a 25% speedup in `git cat-file --batch --batch-all-objects` when using zlib-ng, though notes this is an extreme case. The motivation is clear: while zlib-ng provides a compatibility layer, most distributions don't enable it to avoid replacing system zlib globally, requiring these changes to use zlib-ng's prefixed symbols (`zng_*`).

The technical approach involves:
1. Introducing a new `compat/zlib.h` header to abstract backend differences
2. Removing now-unnecessary compatibility shims (`uncompress2`, `z_const`)
3. Adding meson build options to select the zlib backend
4. Providing necessary shims for zlib-ng's API differences

The changes touch core compression infrastructure across multiple files but appear focused and well-motivated. The series builds on previous zlib refactoring work and maintains compatibility with existing systems while adding the new backend option. The performance gains shown, particularly for hosting providers and other heavy users of object access, make this a potentially valuable addition.
