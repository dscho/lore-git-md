Security discussion regarding GitHub PATs in Git URLs, with platform-specific implementation perspective.

Randall Becker provides additional context from the NonStop platform perspective, explaining why GitHub PAT-based authentication is necessary in their environment (particularly for automated PR creation). He confirms that PATs don't require passwords, making them inherently insecure when persisted. His solution was to implement a custom credential manager to handle PATs securely in memory, though he notes this is proprietary and can't be shared.

The email reinforces two key points from earlier discussion:
1. The security risks of PATs in URLs (no password requirement makes them particularly vulnerable)
2. The real-world need for PAT-based authentication in certain environments (like NonStop's CLI/scripting workflows)

Randall's implementation approach (custom credential manager) represents an alternative to both the pattern-based detection originally proposed and Junio's suggested credential-flow detection mechanism. His experience suggests that:
- Platform-specific solutions can work when core Git doesn't handle the use case
- Memory management of PATs requires special care in any solution
