Security-focused bugfix series for `git blame`'s object ID handling, addressing both the originally reported out-of-bounds read and a pre-existing buffer overflow.

This v3 series from Patrick Steinhardt builds on previous discussion to comprehensively fix two distinct security vulnerabilities in `git blame`'s OID formatting code. The first patch (now refined from v2) prevents out-of-bounds reads when processing extremely large `--abbrev` values by using a ternary operator to safely truncate output via `printf`. The second patch is new in v3 and fixes a separate buffer overflow in boundary commit handling that was discovered by Coverity.

Key technical improvements in v3 include:
- Added test case for boundary commits (`^HEAD`) to verify the `--abbrev` truncation works with prefix characters
- Simplified the `printf` implementation using a ternary operator while maintaining safety
- Fixed the pre-existing buffer overflow where `memset(hex, ' ', length)` could write beyond buffer bounds
- Maintained test coverage for both SHA-1 and SHA-256 cases through the `check_abbrev` helper

The changes affect `builtin/blame.c`'s OID emission logic and expand test coverage in `t/t8002-blame.sh`. The thread history shows this solution emerged after careful evaluation of alternatives, with Johannes Schindelin having identified critical flaws in earlier approaches and Junio Hamano endorsing the current direction. The series now addresses both the immediate security issue from the `printf`-to-`fwrite` conversion and a deeper, pre-existing vulnerability in the boundary commit handling path.
