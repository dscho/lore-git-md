This thread presents a performance optimization series introducing zlib-ng support as an alternative zlib backend for Git. The author has systematically refactored Git's zlib integration to allow runtime switching between standard zlib and the optimized zlib-ng implementation, which provides SSE2/AVX2 acceleration. The series achieves substantial performance improvements - benchmarks show ~25% speedup in operations like `git cat-file --batch-all-objects` - while maintaining full compatibility with system zlib and reftable's independent usage.

The work encompasses core infrastructure changes (including a new abstraction layer and header reorganization), build system support for both meson and Makefile, and comprehensive CI testing. The latest patch completes the CI strategy by modifying the Alpine Linux job to test with zlib-ng, chosen because it's the only distribution in Git's CI that both packages zlib-ng and runs the full test suite. All technical requirements have been addressed, including earlier concerns from Taylor Blau about meson support, and the series now appears ready for maintainer consideration. The implementation is distribution-friendly, maintaining backward compatibility while providing significant performance gains through a lightweight compile-time remapping approach.
