This thread introduces a performance optimization patch series that adds support for zlib-ng as an alternative zlib backend in Git. The author demonstrates significant speed improvements - up to 25% faster in `git cat-file --batch --batch-all-objects` operations when using zlib-ng's optimized implementations that leverage modern CPU features like SSE2 and AVX2.

The series takes a careful approach to integration, refactoring Git's zlib handling to maintain compatibility while adding the new backend option. Key technical changes include creating a compatibility layer in `compat/zlib.h`, cleaning up old shims, and adding build system support via meson. The changes are focused on core compression infrastructure but avoid breaking existing systems, instead using zlib-ng's prefixed symbols to coexist with system zlib installations.

The motivation is particularly compelling for hosting providers and other heavy users where object access performance matters. While the 25% improvement represents an extreme case, even modest gains in this area could provide meaningful benefits at scale. The patch series appears well-structured and builds on prior zlib refactoring work in the codebase.
