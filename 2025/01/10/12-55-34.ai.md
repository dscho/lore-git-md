This is a technical compatibility patch in the zlib-ng integration series, addressing a constness issue between zlib and zlib-ng APIs.

The patch fixes a compiler error that occurs when assigning between `git_zstream::next_in` and `z_stream::next_in` fields. While zlib's `next_in` is not const-qualified, zlib-ng marks it as const, causing type mismatches during compilation. The solution adds an explicit cast to remove the const qualifier when copying the pointer value.

The change is minimal (a single line modification in `git-zlib.c`) and follows the established pattern of the series - adapting Git's zlib abstraction layer to handle differences between standard zlib and zlib-ng implementations. This maintains the series' goal of transparent compatibility while enabling future performance optimizations through zlib-ng.
