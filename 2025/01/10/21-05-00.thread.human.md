This thread discusses potential security enhancements to Git's credential warning system, specifically targeting GitHub personal access tokens (PATs) appearing in URLs. The original proposal suggested extending Git's existing `transfer.credentialsInUrl` warning to detect GitHub PAT prefixes ("ghp_" and "github_pat_") when used as usernames - a common but insecure practice.

Junio Hamano raised fundamental architectural concerns, questioning whether this belongs in Git core at all. He noted the credential system is password-focused while PATs don't require passwords, and suggested credential helpers might be a better solution. Brian m. carlson's follow-up provided important technical context: GitHub has accepted tokens in the username field via Basic auth (not Bearer tokens) since at least 2019, though the exact reasons for this design choice remain unclear. He highlighted legitimate cases where usernames appear in URLs without being tokens, and warned against hardcoding token patterns that might change or produce false positives.

The discussion has revealed deeper tensions between security warnings and avoiding service-specific heuristics in core Git. While GitHub's approach creates security risks (since many tools log usernames but not passwords), the current consensus seems to be moving against implementing the proposed warning due to maintenance burdens and the difficulty of reliable detection. The thread remains open with no clear resolution yet, awaiting further technical rationale about alternative approaches.
