This thread addresses a bug in `git-instaweb.sh` where the Python server binding behavior was inverted from what the documentation specified. The default binding was incorrectly set to localhost (127.0.0.1) while the `-l` flag for local binding was exposing the server to all interfaces (0.0.0.0), contrary to both security best practices and the documented behavior.

Alecs King submitted a minimal 2-line patch that corrects this inversion, making the default bind to all interfaces while properly restricting to localhost when `-l` is specified. Junio C Hamano reviewed and accepted the patch, noting it fixes a long-standing issue dating back to 2019 when Python server support was introduced. While the discussion briefly surfaced a separate issue about some backends ignoring the `--local` option entirely, this was acknowledged as being outside the scope of the current fix. The patch is now queued for inclusion, resolving this straightforward but important security/usability mismatch.
