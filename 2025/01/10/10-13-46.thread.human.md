This thread addresses a bug in `git instaweb`'s Python server binding behavior, where the implementation was incorrectly inverting the IP address binding logic - defaulting to localhost when it should have bound to all interfaces, and vice versa when the `-l` flag was used. Alecs King's simple 2-line fix swaps this behavior to match both the documented expectations and typical security conventions for server binding. Junio Hamano has already accepted the patch, noting it correctly resolves this long-standing issue.

A follow-up from Arti Zirk points out a separate future concern: Python 3.13 will deprecate the CGIHTTPRequestHandler that `git instaweb` relies on for its Python backend. While this doesn't affect the current binding fix, it signals that broader maintenance work will be needed to keep the Python backend functional in future Python releases. The core binding issue remains resolved with Alecs' patch, which is now queued for inclusion.
