Security-focused bugfix for `git blame`'s object ID handling, specifically addressing an out-of-bounds read vulnerability when using large `--abbrev` values. This is the first patch in Patrick Steinhardt's v3 series, building on previous discussion where Johannes Schindelin identified the core issue.

The problem stems from commit 6411a0a896 which switched from `printf` to `fwrite` for OID output to avoid type casting, but inadvertently introduced a buffer overread since `fwrite` doesn't stop at NUL bytes. The fix reverts to `printf` while safely capping the length at `GIT_MAX_HEXSZ` using a ternary operator, ensuring both security and correct output formatting.

Key technical details:
- Modifies `builtin/blame.c` to reintroduce `printf` with length validation
- Adds two new test cases in `t/t8002-blame.sh` verifying behavior with:
  - Extremely large abbrev values (9000 chars)
  - Boundary commit handling (^HEAD) with large abbrev
- Maintains compatibility with both SHA-1 and SHA-256 repositories
- Preserves prefix character handling (^, *, ?) while fixing the security issue

The patch demonstrates careful attention to edge cases, with test coverage that would catch similar issues in the future. It represents the culmination of iterative improvements from the thread's earlier versions, now properly addressing the core vulnerability while maintaining all expected functionality.
