Feature enhancement for `git rev-list`'s missing object reporting. This is the second patch in Justin Tobler's series extending `--missing-info` functionality, following the first patch that added path reporting for missing objects. The patch adds type information to the missing object reports, showing the expected object type (commit, tree, blob, etc.) when an object is missing but its type can be inferred from context.

The implementation builds on the existing `oidmap` infrastructure from part 1, adding a `type` field to the `missing_objects_map_entry` struct. The output format now includes `type=<type>` alongside the existing path information, with proper C-style quoting for special characters. Test coverage is extended to verify the type reporting works as expected.

The change maintains the thread's established design principles - recording all available attributes upfront and letting consumers filter as needed. This completes the core functionality envisioned in the thread's technical consensus, with path and type reporting now both implemented. The patch appears well-integrated with the existing code and follows through on the design discussed in the thread.
