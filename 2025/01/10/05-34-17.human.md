This is a feature patch introducing enhanced missing object reporting for `git rev-list`. It's part of a v2 series (1/2) that builds on previous discussion about making missing object information more extensible.

The patch adds a new `--missing-info` option that works with `--missing=print` to show additional context about missing objects, starting with their paths. The output format is designed to be extensible, using `?<oid> [<token>=<value>]...` syntax with C-style quoting for special characters. Currently it only implements path reporting, but the commit message notes type information will be added in a follow-up patch.

The implementation changes include:
- Switching from an oidset to an oidmap to store path information
- Adding proper string quoting for paths containing spaces/special chars
- Comprehensive tests covering various path edge cases (spaces, quotes)

The patch appears well-constructed with:
- Clear documentation of the new option
- Careful handling of edge cases in path formatting
- Thorough test coverage for the new functionality
- Clean separation between the core functionality and output formatting

This continues the thread's technical consensus about letting consumers filter the output rather than building filtering into Git itself. The implementation looks solid and ready for review, with the second patch in the series presumably adding the promised type information.
