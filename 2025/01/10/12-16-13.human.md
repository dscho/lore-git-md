This is a follow-up discussion in the security-focused `git blame` bugfix thread regarding the handling of large `--abbrev` values. Shejialuo questions the design decision to allow `--abbrev` values exceeding `GIT_MAX_HEXSZ`, noting it feels unintuitive from a user perspective. Johannes Schindelin points to his earlier explanation that this behavior exists to maintain alignment in blame output when OIDs are prefixed (like with `^` in range specifications).

The exchange is brief and doesn't introduce new technical changes - it's primarily clarifying the rationale behind the existing behavior that the security fixes preserve. The thread has already settled on an implementation approach (using `printf` truncation) that maintains this alignment behavior while fixing the out-of-bounds read vulnerability. This appears to be a minor design discussion point rather than a blocker for the security fixes.
