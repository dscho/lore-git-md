Performance optimization patch introducing a new zlib compatibility layer as part of the zlib-ng integration effort. This is the third patch in an 8-part series to enable runtime switching between standard zlib and the optimized zlib-ng backend.

The patch creates a new `compat/zlib-compat.h` header that serves as an indirection layer for zlib includes, replacing direct `#include <zlib.h>` statements. This abstraction is necessary to support the upcoming zlib-ng integration while maintaining compatibility with system zlib. The header is deliberately named `zlib-compat.h` rather than `zlib.h` to avoid potential include path issues.

Changes include:
1. Creation of the new header file with basic zlib include
2. Updates to `git-compat-util.h` to use the new header
3. Corresponding update in `reftable/block.c`

The patch is a straightforward infrastructure change that enables the more substantial zlib-ng integration work to follow. It maintains identical functionality while establishing the necessary abstraction layer. The changes are minimal and focused, touching only the zlib include paths without modifying any compression logic. This appears to be a well-scoped preparatory change in the larger performance optimization effort.
