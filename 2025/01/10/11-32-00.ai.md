CI/build system patch converting GitHub Actions Linux jobs to containerized execution. This is part 4/10 in Patrick Steinhardt's series modernizing Git's CI infrastructure, following the rootless execution changes in the previous patch.

The patch moves all Linux CI jobs from direct machine pool execution to containerized runs, maintaining the same test coverage while gaining more control over the execution environment. Key technical details include:
- Job definitions moved from the direct-execution matrix to the containerized matrix in `.github/workflows/main.yml`
- Each job now specifies its container image (mostly `ubuntu:latest` or `ubuntu:20.04`)
- Maintains all existing job configurations (compiler choices, test variants) while changing only the execution method
- Preserves environment variables including `CC` and `CC_PACKAGE`

The commit message provides rationale through:
- Performance comparison showing negligible timing differences between old/new approaches
- Resolution of previous root execution issue via prior `setpriv(1)` changes
- Note about resolved Node.js binary injection issue affecting 32-bit jobs
- The change appears well-justified and low-risk, with timing data showing no significant performance impact
- Follows logically from the rootless execution changes in the previous patch
- Maintains exact test coverage while providing more environment control
- Part of broader CI modernization including containerization, obsolete CI removal, and platform updates
