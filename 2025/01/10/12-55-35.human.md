Performance optimization patch introducing zlib-ng support as an optional compression backend. This is the final patch in an 8-part series that refactors Git's zlib integration to allow runtime switching between standard zlib and the optimized zlib-ng fork.

The patch adds build system support for linking against zlib-ng's prefixed symbols (using `zng_` prefixes) when available, while maintaining compatibility with standard zlib. This allows distributions to package both libraries without conflicts. Benchmarks show a 25% speedup in `git cat-file --batch-all-objects` when using zlib-ng, which leverages SSE2/AVX2 optimizations.

The implementation adds a new meson build option (`zlib_backend`) to select between auto-detection, standard zlib, or zlib-ng. The core change is in `compat/zlib-compat.h` which now conditionally redefines zlib symbols to their zlib-ng equivalents when enabled. The series has been methodically structured, with previous patches establishing the abstraction layer needed for this final integration step.

This appears to be a well-considered optimization that maintains compatibility while offering measurable performance gains for object-heavy operations. The approach is particularly thoughtful in handling distribution packaging constraints where global zlib replacement isn't feasible.
