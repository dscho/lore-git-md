Bug investigation into Git grep's EOF matching inconsistency. Jeff King responds to Olly Betts' bug report about `git grep '^$'` incorrectly matching at end-of-file, tracing the issue back to a 2010 merge commit (34349bea60) that introduced the behavior. 

Through bisection and diff analysis, King identifies the likely culprit: a change that removed an empty-file check and added a null terminator to file buffers, which interacts poorly with lookahead code from another branch. He notes this may have been reading uninitialized memory before, making the current behavior a more visible symptom of an older issue.

The email provides technical details of the problematic changes in builtin-grep.c, particularly around buffer handling and empty file checks. King suggests the root cause may lie in Junio Hamano's 2010 optimization commit (a26345b608) but stops short of proposing a fix, instead inviting further input from the original author.

This appears to be a genuine bug with clear reproduction steps and historical analysis, though the exact fix path remains open for discussion. The issue affects compatibility with standard grep behavior and has apparently existed unnoticed for over a decade.
