Technical discussion on hash algorithm pointer safety in brian m. carlson's refactoring series.

Taylor Blau responds to Jeff King's suggestion about implementing `hash_algo_by_ptr()` in patch 3 of the hash algorithm refactoring series. While agreeing with the general approach of using a loop to check algorithm pointers, Taylor points out a subtle edge case: the original proposal would incorrectly return SHA-256 when passed NULL, rather than GIT_HASH_UNKNOWN as expected. 

He provides a corrected version of the loop that properly handles NULL values by first checking the main algorithm pointer before dereferencing the unsafe variant. The discussion remains focused on implementation details rather than architectural concerns, with both participants appearing to agree on the core approach while fine-tuning the pointer comparison logic. This represents the final open technical question in the otherwise well-received series.
