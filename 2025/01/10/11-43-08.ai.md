Bugfix for long-standing `git grep` EOF matching inconsistency. Jeff King investigates a reported issue where `git grep '^$'` incorrectly matches at end-of-file, showing it stems from a 2010 merge commit (34349bea60) that introduced lookahead code. The root cause appears to be removal of an empty-file check and addition of a null terminator in `builtin-grep.c`, combined with changes from a26345b608 that optimized line skipping. The bug manifests as uninitialized memory access that coincidentally worked until the merge. The analysis suggests the lookahead code was always subtly wrong but masked by memory layout. King identifies the problematic diff but stops short of proposing a fix, instead CC'ing the original author (Junio) for further input. This appears to be a genuine compatibility bug with standard grep behavior that has existed for over a decade.
