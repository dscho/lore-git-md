Bugfix refinement for `git blame`'s OID output handling. This email from Johannes Schindelin points out a potential buffer overrun in Patrick Steinhardt's proposed v2 fix for the `--abbrev` out-of-bounds read issue. While the thread had been discussing various approaches to handle length truncation after prefix character processing, Schindelin notes that moving the `GIT_MAX_HEXSZ` guard could introduce a new security risk if placed after the `memset()` call that writes to the `hex` buffer.

The discussion remains focused on ensuring both correct formatting (particularly for prefixed OIDs marked with ^, *, ?) and memory safety. Schindelin's observation highlights the delicate balance required in this fix - the solution must handle alignment for special commit markers while preventing any buffer overruns. This comes after Junio Hamano had already approved the technical approach of using `printf` with length truncation in the v2 patch.

The email serves as a cautionary note about subtle interactions in the code, reminding contributors that even well-intentioned rearrangements of safety checks can introduce new vulnerabilities. The thread demonstrates Git maintainers' meticulous attention to security-sensitive formatting code, where both functionality and safety must be preserved.
