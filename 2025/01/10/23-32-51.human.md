This is a bugfix for the Python backend of `git instaweb`, addressing an inverted IP binding behavior that has existed since the feature was introduced in 2019. The patch flips the default binding behavior to match both documentation and security best practices: now `git instaweb -d python` binds to all interfaces (0.0.0.0) while `-l` properly binds to localhost only (127.0.0.1). 

Junio C Hamano has reviewed and accepted the patch, noting that the current implementation had the behavior backwards since inception. He confirms this is a correct fix for the Python backend, though raises a separate question about other backends that ignore the `--local` flag entirely - suggesting this might warrant future attention but is outside the scope of this focused fix.

The change is minimal (just two lines modified in `git-instaweb.sh`) and low-risk, with the commit message clearly explaining both the incorrect current behavior and the corrected state. This appears to be a straightforward improvement that aligns the Python server's behavior with both user expectations and security conventions for local development servers.
