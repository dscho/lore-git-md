This is a bugfix targeting CIFS/NTFS filesystem compatibility issues with Git's permission handling.

Konrad Bucheli investigates two problematic scenarios when running `git init` on NetApp-backed CIFS shares. First, he shows how a seemingly no-op `chmod` can create restrictive "User Deny" rules that override broader permissions. Second, he demonstrates that modifying permissions on an already-open file can cause subsequent writes to fail until the file is reopened. Both cases cause `git init` to fail in environments where local UNIX filesystems would work fine.

The email continues a thread where Junio Hamano suggested checking file modes with `stat` before attempting `chmod`, only performing the permission change when necessary. Bucheli agrees this approach would work better than his initial proposal, as it minimizes system calls for the common case while handling the CIFS edge cases. He argues the minor performance cost of an extra `stat` is justified by improved reliability across diverse filesystems.

The patch appears well-motivated by real-world problems and follows Git's usual pattern of optimizing for the happy path while properly handling error cases. The investigation is thorough, with detailed reproduction steps and system configuration details provided. This looks like a solid improvement for users working with CIFS/NTFS-backed repositories.
