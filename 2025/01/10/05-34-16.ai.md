This is a feature patch series extending `git rev-list`'s missing object reporting capabilities, building on the ongoing thread about extensible object attribute reporting.

The series introduces a new `--missing-info` option that augments the existing `--missing=print` output with additional object attributes. Patch 1 adds path information (recording the first encountered path for each missing object, matching `--objects` behavior), while Patch 2 extends this to include object types. The implementation uses an `oidmap` to track missing objects and their attributes, with output format following the established `?<oid> [<token>=<value>...]` pattern.

The v2 redesign moves from a specific `--missing=print-type` approach to a more general attribute reporting system, addressing earlier thread feedback about extensibility. Key implementation details include recording attributes on first insertion (avoiding path multiplicity) and leaving filtering to consumers rather than building it into Git. The patches touch `builtin/rev-list.c` core logic, documentation, and add tests in `t6022-rev-list-missing.sh`.

This appears to be a well-considered implementation of the consensus reached in the thread, though it introduces `--missing-info` as a new option rather than extending `--missing=print` as some participants suggested. The commit messages clearly explain the design choices and changes from v1. Test coverage looks thorough, including cases for both path and type reporting. One open question from the thread - whether to include object size as an attribute - remains unaddressed in this series.
