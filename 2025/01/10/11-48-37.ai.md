Build system race condition fix for parallel documentation generation, particularly affecting Windows builds. This is version 2 of a patch that modifies `GIT-VERSION-GEN` to use process-specific temporary filenames (`.$$+` suffix) instead of static `+` suffix, addressing both parallel build collisions and Windows filename constraints.

The patch explains how recent changes to use `GIT-VERSION-GEN` for documentation files (`asciidoctor-extensions.rb` and `asciidoc.conf`) created race conditions during concurrent `make -j2 html man` invocations. The issue is particularly acute on Windows where the POSIX emulation layer makes the races more likely to occur, as evidenced by several failed GitHub workflow runs linked in the commit message.

The solution appends the process ID (`.$$`) to temporary filenames while preserving the final `+` character to maintain compatibility with the existing `.gitignore` pattern (`*+`). This addresses Martin Ågren's concern from the thread about maintaining `.gitignore` coverage while solving the race condition. The 4-line change is minimal and focused, preserving the current build architecture while fixing the immediate problem.

Key technical details include: the race condition mechanism in parallel documentation generation, Windows filename constraints, `.gitignore` pattern implications (`*+`), and the specific temporary filename format chosen (`.$$+`). The patch acknowledges this is a short-term solution rather than a full build system redesign, which would be preferable but is deferred beyond the current release cycle.
