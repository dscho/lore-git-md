Bugfix for the trace2 analytics system that prevents a segfault when collecting config values. 

Adam Murray reports that when TRACE2 is enabled and a config option with no value is requested (like `-c status.relativePaths` with no `=`), Git crashes with a segmentation fault. The patch adds null checks across three trace2 target implementations (event, normal, and perf) to handle empty config values gracefully by either omitting the value field or treating it as empty.

The fix is straightforward - it checks for NULL values before processing them in each trace2 backend. A new test case verifies the behavior with an empty config value. This is version 2 of the patch, which appears to have simplified the approach from the first version by just returning an empty value rather than an error.

The change touches multiple trace2 backend implementations but follows a consistent pattern, suggesting the issue was systemic in how trace2 handled config collection. The patch looks well-contained and addresses a clear crash scenario.
