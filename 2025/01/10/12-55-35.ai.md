Performance optimization introducing zlib-ng support as an optional zlib backend. This is the final patch in an 8-part series that refactors Git's zlib integration to enable runtime switching between standard zlib and zlib-ng (an optimized fork with SSE2/AVX2 implementations). The patch adds build system support for linking against zlib-ng's prefixed symbols (zng_*) when available, while maintaining compatibility with standard zlib.

Key technical details include:
- New meson build option `zlib_backend` with choices: auto/zlib/zlib-ng
- Symbol remapping in `compat/zlib-compat.h` to handle zlib-ng's prefixed API
- Benchmark shows ~25% speedup in `git cat-file --batch --batch-all-objects`
- Designed to work with distro packages that install zlib-ng without replacing system zlib
- Maintains all previous compatibility shims (deflateBound, deflateSetHeader)
- Adds `HAVE_ZLIB_NG` compile-time define when using zlib-ng backend

The implementation carefully handles the distribution constraint where zlib-ng cannot globally replace zlib by providing symbol remapping rather than requiring the compatibility layer. The changes are focused in the build system and compatibility header, with minimal impact on the rest of the codebase. This completes the series' goal of establishing a clean abstraction layer for zlib backends while delivering measurable performance improvements.
