This is the second patch in a security-focused bugfix series addressing object ID handling in `git blame`. It specifically fixes an out-of-bounds write vulnerability that occurs when using the `-b` flag (which shows blank spaces for boundary commits) with an excessively large `--abbrev` value.

The patch replaces a dangerous `memset()` call that could write past buffer bounds with a safer `strlen()`-based approach. This ensures we only write as many spaces as needed to match the actual hash length, regardless of the user-provided `--abbrev` value. The fix maintains proper alignment for both SHA-1 and SHA-256 repositories.

Two new test cases verify the fix: one checks that normal abbreviation works with `-b`, while another confirms extreme abbreviation values are properly truncated to the hash length. The solution builds on the series' earlier work to make `git blame`'s object ID handling robust against edge cases while preserving expected formatting behavior.
