This is a CI/build system patch series addressing flaky tests and modernizing the CI infrastructure. Patrick Steinhardt's v4 series builds on previous iterations that focused on fixing a particularly tricky SIGPIPE race condition in the submodule tests (t7422). The current version now includes broader CI improvements while maintaining the robust solution for the SIGPIPE test.

The series has evolved through several rounds of review, with Jeff King ("Peff") providing key technical input on the SIGPIPE test fix. The solution involves generating thousands of nested submodules to reliably trigger the pipe buffer condition, which Junio Hamano has now approved. The current version improves the commit message to better explain the race condition mechanics.

Beyond the SIGPIPE fix, this series:
- Modernizes GitHub Actions to use containerized Linux jobs consistently
- Removes outdated CI code (Azure Pipelines, Ubuntu 16.04 special cases)
- Adds a new 32-bit Linux test job
- Simplifies distro handling in CI
- Fixes a MinGW-specific EBUSY issue in t0060

The changes appear well-considered, with clear explanations of both the problems and solutions. The series demonstrates careful attention to CI reliability while cleaning up technical debt in the test infrastructure. The SIGPIPE test in particular shows thoughtful engineering to verify subtle system behavior without becoming overly fragile.
