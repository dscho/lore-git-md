Feature proposal for `git rev-list` to print additional missing object attributes.

This cover letter introduces a two-patch series that enhances `git rev-list --missing=print` with a new `--missing-info` option to show more context about missing objects. The current implementation only shows OIDs of missing objects, but often we can infer additional attributes like the object's path (from a containing tree) and type.

The series takes a flexible approach by introducing a general `--missing-info` option rather than specific per-attribute flags. The first patch adds path information support, while the second extends this to include object types. The implementation builds on the existing missing object tracking infrastructure in `builtin/rev-list.c` and adds thorough tests in `t6022-rev-list-missing.sh`.

This version (v2) represents a significant redesign from the initial approach, moving from a specific `--missing=print-type` to the more general `--missing-info` mechanism. The thread discussion has converged on a comprehensive approach where Git provides all available attributes (currently path and type) while leaving filtering to consumers, following the Unix philosophy.

The implementation appears well-considered, with attention to backward compatibility and alignment with existing behavior (like how paths are recorded from the first encounter). The cover letter clearly explains the motivation and evolution of the approach, though some open questions remain about final naming and whether to include object size as an attribute.
