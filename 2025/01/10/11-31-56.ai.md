This is a CI/build system patch series addressing flaky tests and modernizing the CI infrastructure. The v4 series from Patrick Steinhardt builds on previous iterations that focused on fixing a particularly tricky SIGPIPE race condition in t7422 (submodule status output testing). 

The series has evolved through four versions with input from Jeff King (Peff), who helped diagnose and fix the SIGPIPE test race. The key technical challenge was ensuring reliable test behavior when verifying SIGPIPE propagation in submodule output - the solution involves generating thousands of submodules to force buffer filling and make the pipe behavior deterministic. The v4 iteration improves the commit message to better explain the race mechanics between git-submodule and grep.

Beyond the SIGPIPE fix, the series includes several CI improvements: converting all GitHub Linux jobs to containerized execution, removing obsolete CI code (including Azure Pipelines remnants and Ubuntu 16.04 special cases), adding an i386 test job, and updating to use the latest Ubuntu release. The changes show careful attention to both test reliability and CI maintenance, with particular focus on the containerization transition which required rootless operation support.

The thread shows consensus on the SIGPIPE solution after thorough review, and the broader CI changes appear straightforward modernizations. The series touches multiple CI configuration files (.github/workflows/main.yml, .gitlab-ci.yml) and test scripts, with the most complex changes in t7422's test logic and the GitHub Actions containerization setup.
