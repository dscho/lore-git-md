This is a bugfix patch series addressing security-sensitive buffer handling issues in `git blame`'s object ID formatting. The series builds on previous discussion and fixes two distinct problems: an out-of-bounds read when using very large `--abbrev` values (first patch) and a pre-existing buffer overflow when formatting boundary commit markers (second patch). The v3 iteration adds test coverage for boundary cases and simplifies the implementation with a ternary operator.

Patrick Steinhardt's solution now properly handles both the primary security issue (truncating over-long abbrev values after accounting for commit marker prefixes) and a secondary buffer overflow discovered during review. The changes affect `builtin/blame.c` and are verified by new tests in `t/t8002-blame.sh`. The thread history shows thorough technical review from Johannes Schindelin and approval from Junio Hamano, with all proposed alternatives carefully evaluated.

The series appears ready for inclusion, with comprehensive test coverage for edge cases including 9000-character abbrev values and boundary commit markers. The fixes maintain compatibility with both SHA-1 and SHA-256 hashes while preventing memory safety violations. This represents a significant hardening of security-sensitive formatting code in the blame machinery.
