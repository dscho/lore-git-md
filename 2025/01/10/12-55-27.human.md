This is a performance-focused patch series that enables Git to use zlib-ng as an alternative zlib backend, showing promising speed improvements.

Patrick Steinhardt proposes adding support for zlib-ng, a zlib fork optimized with modern CPU instructions (SSE2, AVX2). Benchmarking `git cat-file --batch-all-objects` shows zlib-ng running ~25% faster than standard zlib when decompressing repository objects. While this is an extreme case, the speedup should benefit any commands accessing the object database.

The series refactors Git's zlib integration through a new "compat/zlib.h" header that abstracts differences between zlib and zlib-ng (primarily the latter's `zng_`-prefixed symbols). A Meson build option lets users choose their preferred backend. The change is motivated by distros typically shipping zlib-ng without its zlib-compatibility layer to avoid system-wide replacement.

The 8 patches clean up existing zlib compatibility code, introduce the new abstraction layer, and add zlib-ng support. The changes touch core compression code across multiple files but appear focused and well-motivated. This seems like a worthwhile optimization, particularly for hosting providers and performance-sensitive users who can benefit from zlib-ng's optimizations without system-wide changes.
