Bugfix for trace2 config collection that prevents segfault when empty config values are encountered. This is v2 of the patch, addressing a specific crash scenario in Git's trace2 analytics system.

The patch fixes a segmentation fault that occurs when TRACE2 is enabled and a git config option with no value is encountered (e.g., `git -c status.relativePaths version` with `GIT_TRACE2_CONFIG_PARAMS=status.*`). The crash happens because the trace2 system tries to handle the NULL value without proper checks. The fix adds NULL checks across three trace2 target implementations (event, normal, and perf) to safely handle empty config values.

Key technical details:
- Modifies `trace2.c` to pass NULL through when value is NULL
- Updates all three trace2 target formats (event, normal, perf) to conditionally include the value only when non-NULL
- Adds a test case in t0210-trace2-normal.sh that verifies empty config values don't crash
- Changes output format slightly in normal and perf targets to handle NULL values gracefully

The changes are straightforward defensive programming - adding NULL checks before processing config values. The v2 changes from v1 appear to simplify the handling by returning an empty value rather than an error message, and the implementation is now more complete with all three trace2 formats properly handled.
