This is the second patch in a 2-part series extending Git's missing object reporting capabilities in `git rev-list`. It builds on the path reporting functionality introduced in the first patch by adding type information to the `--missing-info` output.

The patch adds a `type=<type>` attribute to the missing object report, showing the expected object type (commit, tree, blob, tag) as inferred from the containing object. The implementation stores the type in the `missing_objects_map_entry` struct and extends the `add_missing_object_entry` function to accept this parameter. The output format remains consistent with the C-style quoting established in the first patch, now showing both path and type when available (e.g. `?<oid> path=<path> type=<type>`).

Key technical changes include:
- Adding a `type` field to `missing_objects_map_entry`
- Modifying `add_missing_object_entry` to accept and store the type
- Updating `print_missing_object` to include type information in output
- Extending test cases in `t6022-rev-list-missing.sh` to verify type reporting
- Maintaining backward compatibility with existing `--missing=print` behavior

The implementation follows the thread's established design principles - recording all available information upfront and letting consumers filter what they need. The patch completes the series' goal of extensible missing object reporting by adding this second attribute type after the path reporting in patch 1. Test coverage remains thorough, verifying the new type reporting works alongside the existing path reporting functionality.
