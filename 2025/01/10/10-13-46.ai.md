This is a bugfix for the `git instaweb` Python server binding behavior. The patch corrects an inversion in the IP address binding logic when using Python's built-in HTTP server.

The current implementation incorrectly binds to 127.0.0.1 (localhost) by default and switches to 0.0.0.0 (all interfaces) when the `-l` (local) flag is used. The patch flips this behavior to match the expected and documented functionality: binding to all interfaces by default and restricting to localhost only when `-l` is specified.

The change is minimal (just 2 lines modified in git-instaweb.sh) but important for security and usability. The current behavior could be problematic as it exposes the server more widely when the user explicitly requests local-only access with -l, while being too restrictive by default. The fix aligns with typical server binding conventions where wider access requires explicit opt-in rather than opt-out.
