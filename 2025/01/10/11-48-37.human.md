Build system fix addressing a race condition in parallel documentation builds, particularly affecting Windows. This is version 2 of a patch that modifies `GIT-VERSION-GEN` to use process-specific temporary filenames (`.$$+` suffix) instead of static `+` suffix.

The issue emerged when `GIT-VERSION-GEN` was extended to generate version strings for documentation files (`asciidoctor-extensions.rb` and `asciidoc.conf`), creating race conditions during concurrent `make -j2 html man` invocations. The problem is particularly acute on Windows where the POSIX emulation layer makes the races more likely to occur, as evidenced by several failed CI runs.

The solution appends the process ID (`.$$`) to temporary filenames while preserving the final `+` character to maintain compatibility with existing `.gitignore` patterns (`*+`). This addresses both the parallel build collisions and Windows filename constraints without requiring a larger build system redesign. The patch has evolved from v1 based on feedback from Martin Ågren regarding the `.gitignore` implications.

The change is minimal (4 lines) and focused, with consensus in the thread that this is a reasonable short-term solution. While a more comprehensive build system redesign might be preferable, this pragmatic fix unblocks the immediate release cycle issues.
