This is part 4/8 of a performance optimization series introducing zlib-ng support. The patch refactors zlib header handling to be more targeted, moving the include of "compat/zlib.h" from the broad "git-compat-util.h" to the more specific "git-zlib.h" wrapper. This change affects several files that use zlib functionality, requiring them to include "git-zlib.h" explicitly.

The reftable library is treated as a special case - it gets its zlib includes through "reftable/system.h" instead, maintaining independence from Git's zlib wrapper. This preserves the reftable library's ability to be used outside of the Git project.

This is a preparatory change that helps clean up header dependencies before the main zlib-ng integration work. The patch appears well-scoped and mechanical, updating all the necessary files that use zlib functionality. It follows logically from the previous patch that introduced the zlib-compat.h abstraction layer.
