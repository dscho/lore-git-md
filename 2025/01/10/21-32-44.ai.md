Git maintainer response to GitHub PAT security proposal

Junio C Hamano responds to the initial proposal about warning for GitHub personal access tokens (PATs) in URLs, raising important architectural questions about the approach. The thread concerns extending Git's credential URL warnings to detect when GitHub PATs are used as usernames, a common but insecure practice.

The maintainer questions the fundamental assumption that PATs need special handling, noting Git currently treats them as regular usernames. Key concerns raised: (1) whether we can avoid host-specific heuristics since users already make this work without them, (2) how the system would know these tokens don't require passwords (the current credential warning system is password-focused), and (3) whether credential helpers should be handling this via mechanisms like Bearer token authentication rather than core Git.

This moves the discussion from implementation details to first principles - whether the proposed warning belongs in Git core at all versus being handled by helpers or other parts of the stack. The response suggests skepticism about baking GitHub-specific knowledge into Git but leaves the door for the original author to provide more context about why core Git needs to be involved. No position is taken yet on whether to accept or reject the feature - the focus is on understanding the problem space better.
