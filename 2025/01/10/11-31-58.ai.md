This is a test fix addressing a flaky SIGPIPE test in the submodule output verification. The patch is part of Patrick Steinhardt's v4 CI/build system series, specifically focusing on the SIGPIPE test verification component mentioned in the thread summary.

The test in t7422 was intermittently failing because it relied on a race condition between `git submodule status --recursive` writing output and `grep` exiting. The original test would sometimes complete before SIGPIPE could be triggered due to buffered stdout. The fix creates 2000 nested submodules to ensure the submodule process fills its output buffer completely, making the SIGPIPE behavior deterministic. This approach was developed with input from Jeff King, who previously confirmed the ~160k output threshold needed to reliably trigger the condition.

The patch demonstrates careful attention to test reliability, maintaining the same verification goals while eliminating flakiness. It uses Git plumbing commands (`git hash-object`, `git mktree`) to efficiently create the test structure rather than running thousands of submodule commands. The commit includes a helpful demonstration of how the previous version could be modified to reliably reproduce the race condition, showing the problem's nature and the solution's effectiveness.

This change aligns with the series' broader theme of improving test reliability across platforms, though it specifically targets a Unix-specific issue (SIGPIPE handling).
