Security bugfix for `git blame`'s object ID handling. This is the first of two patches in v3 of a series addressing memory safety issues in `git blame`'s output formatting.

The patch fixes an out-of-bounds read that could occur when using very large values with `--abbrev`. The issue stems from a previous change that switched from `printf` to `fwrite` for outputting object IDs - while this avoided a type cast, `fwrite` doesn't stop at NUL bytes like `printf` does. The fix reverts to using `printf` while properly capping the length at `GIT_MAX_HEXSZ` to prevent buffer overreads.

The change is well-motivated by a security report from Johannes Schindelin and includes new test cases that verify the fix works even with absurdly large abbrev values (9000 characters) and with boundary commits (^HEAD). The implementation maintains compatibility with both SHA-1 and SHA-256 repositories.

This appears to be a carefully considered fix for a subtle but important security issue, with thorough test coverage. It's part of a larger effort that addresses multiple related vulnerabilities in `git blame`'s object ID handling.
