Performance optimization (zlib backend refactoring): This is the second patch in an 8-part series introducing zlib-ng support as an alternative compression backend. The patch removes an apparently unnecessary `z_const` macro definition from `git-compat-util.h` that was originally added as part of zlib compatibility code.

The macro, which prevented zlib's `const` qualifiers from being applied to parameters, seems to have been carried over from older compatibility code without clear justification. The author notes that omitting `const` doesn't actually make parameters less constant, and since the related `uncompress2()` compatibility shim was removed in the previous patch, this definition no longer serves any purpose.

This change is a straightforward cleanup that removes dead code while preparing for the main zlib-ng integration work. The patch appears uncontroversial - it doesn't affect functionality and simply removes code that was likely overlooked during previous refactoring. The commit message provides clear historical context tracing the macro's origin back to commit 07564773c2, though no rationale for its continued existence could be found.

As part of the larger performance optimization effort, this patch helps streamline the codebase before introducing the new zlib-ng backend functionality in subsequent patches. The change is minimal (just one line removed) and focused entirely on the zlib compatibility layer.
