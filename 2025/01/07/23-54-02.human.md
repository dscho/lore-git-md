This is a technical discussion about entropy handling in the reftable backend, specifically addressing OpenSSL's behavior when the system entropy pool is exhausted. Randall Becker reports that on ia64 systems running OpenSSL 3.0.11 with PRNGD (where hardware entropy isn't available), the system fails when writing to reftable stacks - a problem not seen on x86 systems with hardware entropy support.

The thread reveals a fundamental disagreement about how Git should handle this case. Brian Carlson argues that systems should provide proper entropy sources (noting that modern OpenSSL versions use CTR-DRBG with large reseed intervals) and that Git shouldn't compromise security by using weaker RAND_pseudo_bytes(). He questions whether supporting such edge cases falls within Git's support policy, especially since TLS would also fail in these conditions.

Randall's response provides concrete details about the failing configuration (OpenSSL 3.0.11 on ia64 using PRNGD), validating the original problem report while highlighting the platform-specific nature of the issue. The discussion remains at an impasse between those wanting to handle the edge case (Patrick Steinhardt's original patch) and those believing the system should be properly configured (Carlson's position). The technical specifics are well-articulated by both sides, but no resolution path has yet gained consensus.
