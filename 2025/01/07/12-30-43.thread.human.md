This thread addresses a Windows/MinGW-specific test failure in Git's runtime prefix tests, where intermittent EBUSY errors occur when copying the Git binary during test setup. The issue manifests in t0060-path-utils.sh when two tests attempt to copy git.exe to the same directory, with Windows apparently keeping the file locked between operations.

The proposed solution cleanly factors out the problematic setup into a dedicated test case that runs once, avoiding the duplicate file operations that trigger the EBUSY errors. The patch maintains all existing test requirements while removing redundant setup steps from the individual test cases. This appears to be a straightforward fix for an observed CI issue, though it would be useful to confirm whether the EBUSY behavior reproduces consistently outside of GitLab CI environments.
