Feature proposal for submodule symlink validation override.

Vadim Zeitlin proposes adding an option to disable Git's validation of submodule paths being directories rather than symlinks. This validation was introduced in commit e8d0608944 to improve security, but Zeitlin describes a legitimate use case where symlinked submodules provided significant workflow benefits - saving disk space and initialization time when the same submodule is used across multiple projects.

The email makes a well-reasoned case for an escape hatch, noting that while the security check is generally useful, there are trusted repository scenarios where symlinks are preferable to alternatives like bind mounts. The request is framed as an inquiry about whether such an option would be acceptable before submitting a formal patch.

Key technical details include:
- Current behavior fails any Git command (even `git status`) when detecting symlinked submodules
- The proposed change would introduce a configuration option to bypass this check
- Use case involves a large submodule shared across multiple projects/worktrees
- Linux-specific workaround (bind mounts) exists but is less convenient

This touches the submodule subsystem's path validation logic, specifically the checks added in e8d0608944. The proposal seems likely to spark discussion about security tradeoffs versus workflow flexibility, with Zeitlin positioning it as an opt-in feature for trusted environments rather than weakening the default security posture.
