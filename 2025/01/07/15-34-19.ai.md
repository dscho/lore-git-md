Bugfix follow-up confirming resolution in newer Git versions. Kristoffer Haugsbakk responds to Keith Mendoza's crash report in `git restore --staged -p` during merge conflicts, identifying this as a known issue fixed in v2.41.0 (commit 28d1122f9ca). The bug was introduced when the interactive patch interface became the default in v2.37.0 and specifically failed to handle "Unmerged path" lines in the diff output.

The response includes a clean reproduction recipe that demonstrates the fix works in v2.48.0-rc2, contrasting with the original reporter's experience on v2.39.5. The thread context shows this was a real user-impacting bug where Git would abort with a core dump when trying to selectively stage portions of conflicted files, though the fix has been available since mid-2023.

Key technical details for future reference: the crash occurred in add-patch.c when processing diffs starting with unmerged path markers, fixed by properly handling these conflict indicators. The discussion references Jeff King's original fix email and confirms the affected version range (v2.37.0 through v2.40.x). This appears to be a straightforward case of a known fix that hasn't reached all users via maintenance releases.
