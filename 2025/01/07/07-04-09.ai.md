This is a follow-up documentation and refactoring patch series to the recently merged LSan race condition fixes. Jeff King is submitting three small improvements based on Patrick Steinhardt's review of the original six-patch series that addressed LeakSanitizer false positives in threaded test execution.

The changes focus on improving readability and maintainability of the test infrastructure code:
1. Inverts the return value logic of `check_test_results_san_file_empty` to make the function's behavior more intuitive (true when files are empty)
2. Simplifies the LSan results checking code by removing redundant operations
3. Adds explanatory comments to document the LSan log checking logic, particularly around the handling of false positives from sanitizer internals

These changes build on the technical foundation established in the main series, which implemented a DEDUP_TOKEN-based approach to filter false positives while preserving real leak detection. The patches are purely cosmetic and documentation-focused, applying cleanly to the already-merged solution. The email notes these are based on review feedback, showing the Git project's attention to code quality even after technical implementation is complete.
