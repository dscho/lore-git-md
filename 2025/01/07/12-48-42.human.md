This is a follow-up in the thread about removing deprecated remote configuration mechanisms, specifically addressing the addition of warning messages for users still relying on the old `branches/` and `remotes/` directory-based configurations.

Patrick Steinhardt responds to Junio Hamano's enthusiastic endorsement of Christian Couder's suggestion to add explicit warnings (similar to those used for `pack-redundant` removal) before fully removing these long-deprecated features. The patch shows the proposed implementation - adding warning messages that will appear when Git encounters these legacy configurations, nudging users to migrate to modern config-based remotes while also providing a way for them to report if they still need the old functionality.

The warnings follow the same pattern for both `remotes/` and `branches/` directories, suggesting migration to config-based remotes and inviting users to email the Git mailing list if they still depend on these mechanisms. This implements the agreed-upon "prudent" approach to breaking changes that Junio supported, giving users clear advance notice before the eventual removal.

The implementation is straightforward, adding the warning calls in `remote.c` where these legacy configurations are read. This keeps with the thread's theme of careful, well-communicated deprecation while maintaining the technical work to eventually remove these features in Git 3.0. The patch appears ready for inclusion in the next version of the series.
