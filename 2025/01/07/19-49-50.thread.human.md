This thread addresses an authentication issue in `git send-email` when using SMTP bearer authentication (XOAUTH2/OAUTHBEARER) with long credentials. The original patch implementing this feature was sent by Julian, but M Hickford has now reported a specific failure case when using Gmail's SMTP server with access tokens exceeding ~220 characters. Debug output shows the SMTP command gets corrupted by an inserted space in the base64-encoded string around column 241, resulting in a 535 authentication error. 

The problem appears to stem from how Perl's Net::SMTP module handles long authentication strings, though the exact location of the bug remains unclear. Hickford has provided detailed reproduction steps using git-credential-oauth and Gmail configuration, confirming the issue affects both XOAUTH2 and OAUTHBEARER mechanisms when credentials are sufficiently long. This is a real-world concern since services like Gmail issue long-lived OAuth tokens that would trigger this edge case. The thread is currently awaiting input from the original patch author to confirm reproducibility and help diagnose the Net::SMTP interaction.
