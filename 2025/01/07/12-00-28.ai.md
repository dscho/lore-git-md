This is the final patch in a 10-part series adding comprehensive ref consistency checks to Git, now being hooked into `git fsck` via a child process. The patch adds a `fsck_refs()` function that runs `git refs verify` as a subprocess, with progress reporting and flag passthrough from the parent fsck process. The implementation uses `CHILD_PROCESS_INIT` for clean process setup and integrates the ref verification errors into fsck's overall error reporting via `errors_found |= ERROR_REFS`.

The patch represents the culmination of the series' systematic validation work, now making the ref checks available to end users through Git's standard fsck infrastructure. The child process approach provides clean separation while leveraging fsck's existing reporting capabilities. With this integration, Git gains comprehensive verification of ref storage covering file types, headers, refname validity, entry syntax, object existence, and sort order - all validated through the new `git refs verify` subcommand called from fsck.
