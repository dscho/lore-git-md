Junio Hamano responds to Patrick Steinhardt's implementation of deprecation warnings for the legacy `branches/` and `remotes/` directory configurations. While agreeing with the general direction, Junio suggests making the warnings less intrusive by only showing them when the deprecated configurations are actually used, not just when the files are read.

He provides a concrete code sketch showing how to implement this by adding a new `remote_stale_warning()` function that checks the remote's origin type (whether it came from the legacy directories) and emits warnings only when those remotes are actually used in transport operations. The patch modifies three files - remote.c to add the warning function, remote.h to expose it, and transport.c to call it when setting up a transport.

This continues the thread's careful approach to deprecation, balancing the need to warn users about upcoming removal with minimizing disruption to workflows. The implementation would make warnings more targeted and actionable by only appearing when problematic configurations are actively in use.
