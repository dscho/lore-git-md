This is a bugfix patch series addressing an issue in the reftable backend's handling of exhausted entropy pools. The series consists of two patches that modify how random bytes are generated for reftable operations.

The core issue stems from OpenSSL's `RAND_bytes()` failing when the system entropy pool is exhausted, causing Git to die during reftable operations. The author notes this appears unique to OpenSSL among the various CSPRNG backends Git supports. The solution introduces a new `CSRNG_INSECURE` flag to allow falling back to less secure random bytes when cryptographic strength isn't required.

Key technical details:
- Adds new `CSRNG_INSECURE` flag to `csprng_bytes()` interface
- Modifies reftable stack code to use insecure random bytes for temporary filenames
- Updates tests and other callers to maintain existing behavior
- Avoids using OpenSSL's `RAND_pseudo_bytes()` due to its weaker security guarantees

The patch appears well-considered, with the author explicitly weighing security tradeoffs. The changes are focused and the commit message provides clear rationale for the chosen approach. This seems like a reasonable solution to a real-world problem while maintaining security where it matters.
