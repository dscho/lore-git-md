# Feature proposal: git-request-get for converting pull requests to email

Matěj Cepl proposes a new `git-request-get` script that converts `git-request-pull` output into email submissions via `git-send-email`. The tool aims to bridge the gap between pull request workflows and email-based code review, addressing a 2016 GitLab feature request.

The script can either parse `git-request-pull` output from stdin or accept URL/branch arguments directly. It handles remote repository setup, branch creation, and email generation. The implementation includes logic for detecting common hosting platforms (GitHub, GitLab, sr.ht) to generate appropriate remote names.

This is an RFC seeking feedback on the concept, code quality, and testing approach before formal submission. The author specifically asks about alternatives to debug conditionals in the test harness. The current test setup uses a Makefile with expected output matching.

The patch appears to be a complete working implementation, though the author acknowledges it may need refinement before becoming official Git tooling. The concept seems useful for projects that use email workflows but receive pull requests from contributors more familiar with web-based platforms.
