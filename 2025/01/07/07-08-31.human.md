Documentation patch adding explanatory comments to the LSan leak detection code. This is part of a post-merge refinement series (3/3) that follows up on the earlier performance optimization work for LSan race conditions in threaded tests.

The patch adds clarifying comments to the somewhat cryptic `DEDUP_TOKEN` grep pipeline in `test-lib.sh`. Jeff King explains that while the code looks for unique leaks marked by DEDUP_TOKEN, it also needs to filter out false positives originating from the sanitizer's own internal thread stack handling (`sanitizer::GetThreadStackTopAndBottom`). The comment serves as a quick orientation for future maintainers, with commit references available for deeper context.

This is a straightforward documentation improvement that follows through on the series' goal of making the LSan solution more maintainable. The change is minimal (just 5 lines of comments) but adds valuable context to code that might otherwise be puzzling to readers. The patch maintains all existing functionality while improving code comprehension.
