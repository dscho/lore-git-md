This is a bugfix follow-up confirming that a known crash in `git restore --staged -p` during merge conflicts has already been addressed. Kristoffer Haugsbakk responds to Keith Mendoza's bug report by identifying that the issue was fixed in Git v2.41.0 (commit 28d1122f9ca) and provides reproduction steps that now work correctly in Git 2.48.0-rc2.

The email explains this was a regression introduced in v2.37.0 when the interactive patch interface was switched from Perl to C by default, affecting users until the fix landed. The original bug caused Git to crash when encountering "Unmerged path" lines during interactive staging of conflicted files.

This appears to be a straightforward case of a user hitting a known issue on an older Git version. The response is helpful and conclusive - it both confirms the bug's legitimacy and provides the version information needed to resolve it (upgrade to v2.41.0 or later). No further action appears needed since the fix is already in mainline Git.
