Bug report about test failure in reftable backend on ia64 architecture.

Randall Becker reports that test t0610.47 ("ref transaction: many concurrent writers") fails on ia64 systems in Git 2.48.0-rc2, though it worked in rc1 on x86. The test creates 100 concurrent ref updates using `git update-ref` and verifies they all complete successfully, but on ia64 it fails with "fatal: unable to get random bytes" errors. The test output shows several refs (like branch-40, branch-47, branch-62, etc.) are missing from the final result, suggesting the concurrent updates failed for those branches.

The key difference appears to be in random number generation - ia64 uses PRNGD while x86 uses hardware RNG. The test sets a very high `reftable.lockTimeout` (300000ms) to avoid flakiness, but this doesn't prevent the random number generation failures. The error suggests a platform-specific issue in the reftable backend's locking mechanism when generating unique identifiers for concurrent transactions.

This looks like a legitimate platform-specific bug that could affect real-world usage on ia64 systems, though the test case is intentionally stress-testing edge conditions. The failure mode (missing ref updates) could potentially cause data loss in concurrent scenarios. The report provides complete test output showing exactly which ref updates failed, which should help diagnose the root cause in the reftable/PRNG interaction.
