Performance optimization in the LSan test infrastructure. This is the second patch in a 3-part series refining the leak detection code that was recently merged into Git's test suite.

Jeff King simplifies the LSan results checking logic by replacing a `find | xargs grep` pipeline with direct shell globbing. The new approach is more efficient (one fewer process), handles paths with spaces correctly, and matches the pattern used elsewhere in the test infrastructure. It also naturally handles edge cases like missing directories without special comments.

The change uses `grep -s` (silent mode) which is POSIX-compliant and already used elsewhere in the test suite. While this introduces a theoretical command-line length limit, the same limit already applies to other parts of the test infrastructure without issues in practice.

This continues the series' focus on maintainability improvements after the core LSan race condition fixes were merged. The patch demonstrates careful attention to edge cases and consistency with existing test patterns.
