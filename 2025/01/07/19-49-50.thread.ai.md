Summary of SMTP bearer authentication thread:

This thread concerns the implementation of SMTP bearer authentication (XOAUTH2/OAUTHBEARER) in `git send-email`, originally proposed by Julian. The feature enables OAuth-based authentication with email providers like Gmail. A bug report from M Hickford identifies an authentication failure when using long credentials (>220 characters) with Gmail's SMTP server, where the SMTP command becomes corrupted by an inserted space at column 241 in the base64-encoded auth string. The issue affects both XOAUTH2 and OAUTHBEARER mechanisms and is reproducible when using git-credential-oauth with sufficiently long access tokens. The root cause appears to be in how Net::SMTP handles long authentication strings, though the exact location of the bug remains unconfirmed. The reporter has provided detailed test methodology using Gmail SMTP configuration and asks the original author to verify the behavior. This represents a real-world edge case that would affect users relying on long-lived OAuth tokens from services like Gmail. The thread currently lacks a proposed fix but contains sufficient debugging information to investigate the Net::SMTP interaction further.
