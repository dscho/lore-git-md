This is a response to an RFC proposal for a new `git-request-get` script that would complement `git-request-pull` by automating patch fetching and emailing for review. Junio Hamano provides initial feedback on the proposal.

The response notes several issues with the current submission approach: the motivation isn't clearly explained in the email itself (requiring readers to visit an external 8-year-old GitLab issue), the patch creates a new Makefile rather than integrating with Git's existing build system, and the testing approach needs work. Hamano suggests studying Git's existing Perl scripts for style guidance and verifying the patch applies cleanly by emailing it to oneself first.

The feedback is constructive but highlights that the proposal needs more self-contained explanation and better alignment with Git's development practices before it can be properly evaluated. The core idea of automating patch fetching/emailing isn't rejected, but the implementation needs refinement in presentation and technical approach. This appears to be early-stage feedback aimed at helping the author improve their submission rather than a substantive review of the concept.
