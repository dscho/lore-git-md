This is a brief follow-up in the ongoing thread about removing deprecated remote configuration mechanisms.

Patrick Steinhardt responds to Junio Hamano's historical note about the evolution of Git's remote configuration systems. While Junio had pointed out that the old `.git/branches/` mechanism wasn't strictly "replaced" since it offered unique advantages for users managing frequently-changing remotes through direct file manipulation, Patrick counters that the widespread unfamiliarity with these old mechanisms today indicates `git remote` has effectively superseded them. He offers to reword the phrasing in documentation but notes this discussion may not affect the actual commit messages.

The exchange highlights differing perspectives on terminology around feature deprecation - whether newer mechanisms fully replaced older ones or merely provided alternative approaches. Patrick maintains the practical position that current usage patterns demonstrate the old methods' obsolescence, while acknowledging Junio's historical accuracy point. This doesn't appear to require any technical changes to the patch series but may influence how the removal is documented or justified in future iterations.
