This is a technical discussion about test reliability in the context of Patrick Steinhardt's CI modernization series, specifically addressing the SIGPIPE test fragility in t7422.

Jeff King provides a refined approach for reliably triggering SIGPIPE in test scenarios, though notes it doesn't solve the immediate submodule test issue. The key insight is using `{ yes || true; }` piped to `true` as a more robust pattern than the previous Perl-based solution, as it:
1. Avoids buffer size guessing by continuously writing until pipe closure
2. Eliminates read-side buffering uncertainty by using `true` which reads nothing
3. Works regardless of timing/speed variations (demonstrated with `sleep 1`)

The solution is presented as general-purpose technique for future test cases needing reliable SIGPIPE triggering, though it doesn't address the specific timing-dependent interaction between Perl's buffering and git-submodule's output that makes the t7422 test inherently fragile.
