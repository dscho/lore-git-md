This is a follow-up discussion in the ongoing thread about removing deprecated remote configuration mechanisms. Junio Hamano responds to Patrick Steinhardt's claim that `git remote` has completely replaced the old `.git/branches/` and `.git/remotes/` directory mechanisms. While acknowledging Patrick's point about current usage patterns, Junio expresses concern about potential breakage of ancient scripts that may still rely on these long-deprecated features.

The key new point here is Junio's strong recommendation to add warning checks in remote.c when these legacy mechanisms are used, similar to the approach taken with `pack-redundant` removal. This would serve as both a migration aid and a way to detect any remaining real-world usage before the final removal in Git 3.0. The exchange shows the project's careful balancing act - recognizing that modern practices have moved on while still being cautious about breaking obscure but possibly important legacy use cases.
