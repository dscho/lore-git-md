This is a follow-up in the breaking changes thread, specifically addressing the implementation of warning messages for deprecated remote configuration methods. Patrick Steinhardt responds to Junio Hamano and Christian Couder's discussion about adding more visible warnings for the soon-to-be-removed `branches/` and `remotes/` directory-based configuration.

The email includes a proposed diff that would add warning messages when Git encounters these deprecated configuration methods. The warnings follow the pattern established by the `pack-redundant` removal, informing users about the planned removal and suggesting migration to config-based remotes. The messages also invite users who still rely on these methods to notify the Git mailing list.

The changes would be implemented in remote.c, modifying the `read_remotes_file()` and `read_branches_file()` functions to emit warnings when these legacy configuration files are accessed. The warning text is localized (using `_()`) and includes clear instructions for migration and a request for feedback from affected users.

This response shows consensus forming around Christian's suggestion for more aggressive deprecation warnings, with Patrick providing immediate implementation that Junio had earlier endorsed as "excellent" and "prudent". The warning text maintains a helpful tone while clearly communicating the impending removal, following the established pattern from the `pack-redundant` removal process.
