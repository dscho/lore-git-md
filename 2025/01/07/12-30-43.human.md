This is a platform compatibility fix for MinGW/Windows, addressing flaky test failures in GitLab CI. The patch is part of a larger series (v3 01/10) focused on CI fixes.

The issue occurs in t0060 tests that verify Git's runtime prefix functionality by copying the Git executable to a test directory. On Windows, these tests intermittently fail with EBUSY errors when trying to overwrite git.exe, suggesting the file remains locked by some process (possibly MinGW or Windows itself) even after the test completes.

Patrick Steinhardt's solution is straightforward: factor out the common setup (creating the directory and copying git.exe) into a separate test case that runs once, rather than repeating it in each test. This avoids the race condition by ensuring the file is only written once.

The patch is clean and well-explained, with a clear commit message documenting both the symptom and solution. The change is minimal and focused, just moving setup code to a more appropriate location while maintaining all test functionality. This appears to be a solid fix for an annoying CI flakiness issue.
