This is a post-merge refinement patch in the LSan test optimization series, focusing on improving code readability. The patch inverts the return value logic of the leak detection function to make the control flow more intuitive.

The function `check_test_results_san_file_empty_` is renamed to `check_test_results_san_file_has_entries_` and now returns success (0) when leaks are found, rather than when the file is empty. This change eliminates the need for awkward shell negation in the pipeline and makes the calling code more straightforward. The patch updates both the function implementation and its callers in `test-lib-functions.sh` and `test-lib.sh`.

Key technical details:
- The function now returns 1 (false) when no leaks are found, rather than 0 (true)
- The pipeline no longer requires negation with `!` at the start
- Callers now use `! check_test_results_san_file_has_entries_` which reads more naturally
- The change preserves all existing functionality while improving readability

This is part of a 3-patch series refining the already-merged LSan optimization work, showing the project's attention to code quality even after technical consensus has been reached.
