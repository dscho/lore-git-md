This thread reports a platform-specific test failure in Git 2.48.0-rc2's reftable backend on ia64 systems. Randall Becker found that test t0610.47 ("ref transaction: many concurrent writers") fails when running on ia64 architecture, though it passes on x86. The test creates 100 concurrent ref updates, but on ia64 several updates fail with "fatal: unable to get random bytes" errors, leaving some branches (like branch-40, branch-47, and branch-62) missing from the final result.

The issue appears related to differences in random number generation between platforms - ia64 uses PRNGD while x86 uses hardware RNG. Despite setting a high `reftable.lockTimeout` (300000ms) to prevent flakiness, the test still encounters failures in generating unique identifiers needed for concurrent transactions. This suggests a genuine platform-specific bug in the reftable backend's locking mechanism that could potentially lead to data loss in real-world concurrent usage scenarios on ia64 systems. The detailed test output provided in the report should help diagnose the root cause of the PRNG interaction issue.
