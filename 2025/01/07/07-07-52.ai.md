Performance optimization and code simplification in the ongoing LSan test infrastructure series.

This is the second of three post-merge refinement patches from Jeff King, continuing the work to improve Git's LeakSanitizer test infrastructure. The change replaces a `find | xargs grep` pipeline with direct shell globbing in the leak detection function, now named `check_test_results_san_file_has_entries_` (following the earlier inversion of its return value semantics).

The patch makes several concrete improvements: eliminating a process fork, properly handling paths with spaces (which previously caused grep errors), and removing redundant error handling for removed directories (now handled naturally by `grep -s`). The solution uses POSIX`-compliant `grep -s` which has existing precedent in the test suite. While this approach is theoretically subject to command-line length limits, Jeff notes this hasn't been an issue in practice and matches the existing behavior of log display code.

The change maintains all existing functionality including the DEDUP_TOKEN-based parsing and sanitizer internal stack trace filtering established in the original series. This continues the pattern seen throughout this thread of preserving the core technical approach while finding opportunities to simplify implementation details. The patch demonstrates particular attention to edge cases (spaces in paths, missing directories) while making the code more straightforward.
