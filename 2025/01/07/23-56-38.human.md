This is part 2 of a bugfix series addressing entropy-related failures in the reftable backend, specifically on ia64 systems using OpenSSL with PRNGD. Randall Becker provides additional test data showing the scope of impacted tests, which fail consistently on ia64 but pass on x86.

The patch modifies two reftable operations that use randomness - delaying retries when reading and generating unique table names when writing - to use insecure random bytes when the entropy pool is exhausted. This follows part 1's changes to allow insecure fallback in the OpenSSL backend.

The key new information here is the comprehensive list of 15 tests that fail on ia64 due to entropy exhaustion, demonstrating the real-world impact. The patch appears well-scoped, changing only two calls to use the new insecure flag while maintaining the same basic behavior. The test failures confirm Patrick Steinhardt's original report and validate the solution approach.

The discussion remains at an impasse regarding whether this architectural change is justified, but the empirical evidence continues to mount that this is a real problem affecting multiple test scenarios on certain platforms. The patch itself is straightforward and seems technically sound for its stated purpose.
