Thread summary:

Vadim Zeitlin proposes adding a configuration option to disable Git's validation that submodule paths must be directories rather than symlinks, which currently fails Git operations when violated. The security check was introduced in e8d0608944 but Zeitlin presents a legitimate use case where symlinked submodules provide workflow advantages in trusted environments - particularly for large submodules shared across multiple projects/worktrees where symlinks save disk space and initialization time compared to alternatives like bind mounts.

brian m. carlson responds favorably to the proposal, acknowledging the workflow benefits and suggesting this aligns with recent discussions about balancing security hardening with practical needs. They outline implementation details: a new config-controlled global variable or repository struct field to toggle validation behavior, with changes needed in `validate_submodule_path`. While not committing to implement it themselves, they provide technical guidance for contributors and note documentation requirements for the new option.

The discussion has progressed from initial inquiry to core team validation of the concept, with clear technical direction for implementation. Open items include actual patch submission and final documentation wording. The security-usability tradeoff is framed as part of Git's ongoing hardening conversation, with this representing a case where workflow needs may justify an opt-in relaxation of security checks in trusted environments.
