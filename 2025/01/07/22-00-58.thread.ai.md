Thread summary:

Vadim Zeitlin proposes adding a configuration option to disable Git's validation that submodule paths must be directories rather than symlinks, which currently fails all Git operations when violated. The security check was introduced in e8d0608944 but Zeitlin presents a legitimate use case where symlinked submodules provide workflow advantages in trusted environments - particularly for large submodules shared across multiple projects/worktrees where symlinks save disk space and initialization time compared to alternatives like bind mounts. The proposal would maintain the secure default while adding an opt-in override, touching the submodule subsystem's path validation logic. No patch yet submitted; this is an initial inquiry about acceptability before implementation. Key open question is whether the core team would accept such a security relaxation even as an optional feature, given Git's general hardening direction.
