This is a bugfix patch addressing inconsistent behavior in fsck.skipList configuration handling. 

The patch makes Git more strict when parsing `fsck.skipList` and related configurations (`fetch.fsck.skipList`, `receive.fsck.skipList`). Currently, if these options are specified without a path value, Git prints an error but continues execution as if the option wasn't set. The change makes these configurations properly fail when misconfigured.

The fix is straightforward - changing the return value from 1 to -1 in the configuration parsers to trigger a proper error. The patch includes tests verifying the new strict behavior for all three configuration variants, ensuring they now fail when given empty values.

This appears to be a well-justified change that follows up on previous discussion (referenced in the commit message). The implementation is clean, touching only the necessary configuration parsers, and includes comprehensive test coverage for the new behavior. The change makes Git's behavior more consistent and predictable when these configurations are misused.
