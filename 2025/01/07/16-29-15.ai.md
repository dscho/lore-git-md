This is a bugfix patch addressing inconsistent handling of misconfigured fsck.skipList settings. The patch makes Git's configuration parsing more strict by properly rejecting empty or invalid fsck.skipList values rather than silently continuing with the operation.

The change affects three related configuration options: `fsck.skipList`, `fetch.fsck.skipList`, and `receive.fsck.skipList`. Previously, when these were configured without a valid path value, Git would print an error but continue processing as if the option wasn't set. The patch updates the configuration parsers in fsck.c, fetch-pack.c, and builtin/receive-pack.c to return -1 (indicating error) rather than 1 (indicating the option was handled) when the path parsing fails.

The patch includes comprehensive test coverage in t/t5504-fetch-receive-strict.sh, adding new test cases that verify the stricter behavior for all three configuration variants. The tests check that Git now fails with appropriate error messages when:
- fsck.skipList is specified without a value
- receive.fsck.skipList is missing a path
- fetch.fsck.skipList is empty

The change appears well-motivated by prior discussion (referenced in the commit message) and maintains consistency across the related fsck skipList configurations. The implementation is straightforward, changing the return value in three similar configuration callbacks, and the test coverage is thorough, verifying both the new behavior and that valid configurations continue to work.
