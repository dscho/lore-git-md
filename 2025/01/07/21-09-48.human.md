This is a design discussion in the ongoing reftable entropy handling series, specifically about whether reftable should use Git's cryptographic random number generator (CSPRNG) for non-security purposes.

Junio Hamano clarifies his earlier position in response to Randall Becker, acknowledging he misread which random number generator was being discussed in the patch. The discussion has moved beyond just fixing the OpenSSL PRNGD failures on NonStop systems (which Randall confirmed are real) to a broader architectural question: should subsystems like reftable that need only basic randomness (for things like temporary filenames and retry delays) use simpler, non-cryptographic sources like standard `rand()`, or even constant values in some cases?

Junio's stance suggests he sees this as setting an important precedent about dependency boundaries between Git's core cryptographic code and other subsystems. While the technical merits of the fix are validated, the conversation is now about finding the right balance between platform compatibility and clean architectural separation.
