This is a bugfix patch addressing inconsistent handling of invalid fsck.skipList configurations. Junio Hamano is reviewing Justin Tobler's proposed change to make Git's configuration more strict when fsck.skipList and related options are misconfigured with empty or invalid paths.

The patch modifies the configuration parsers to properly reject invalid cases where skipList is specified without a path value (like `skipList` with no `=` and value). Currently, Git prints an error but continues processing as if the option wasn't set, which could lead to unexpected behavior. Hamano agrees with the change, noting that when a path is specified but invalid (like referencing a non-existent user's home directory), Git already dies with an error, so being strict about empty values is consistent.

The review confirms this is a sensible change that aligns with Git's existing behavior for other invalid cases. The patch appears well-motivated and maintains consistency across the three related fsck skipList configurations (fsck.*, fetch.fsck.*, and receive.fsck.*). This is part of an ongoing effort to make Git's configuration handling more robust and predictable.
