Feature proposal for submodule symlink validation override.

Vadim Zeitlin proposes adding an option to disable Git's relatively new validation that prevents submodule paths from being symlinks. This check was introduced in March 2024 (commit e8d0608944) for security reasons, but the author explains it breaks their established workflow where they symlink to a single shared submodule instance across multiple projects to save disk space and initialization time.

The request comes from a practical need - the author maintains a large submodule used across many projects and finds symlinking more efficient than proper submodule initialization or workarounds like mount points. They're asking if there's already an undocumented way to bypass this check, and if not, whether the Git project would accept a patch adding such an option.

This appears to be a well-motivated request from an experienced user (they reference the workflow working "for many years" before the recent change). The security implications of allowing symlinks would need consideration, but the author seems aware this would be an opt-in relaxation of the rules for trusted environments. The proposal is framed politely as an inquiry about feasibility before investing in implementation work.
