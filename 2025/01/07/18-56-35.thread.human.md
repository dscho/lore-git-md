This thread discusses Matěj Cepl's proposal for a new `git-request-get` Perl script to complement `git-request-pull`, automating patch fetching and emailing for review. The initial RFC described functionality for parsing pull requests, remote management, and review branch creation, but Junio Hamano raised several implementation concerns about packaging and integration with Git's build system.

Junio has now clarified two key points about the submission requirements: while Perl scripts must follow specific conventions, shell scripts remain valid when properly implemented, and RFC submissions are acceptable as long as they are technically complete enough to apply cleanly. The core issue remains ensuring the implementation meets Git's standards for script packaging and test integration before technical evaluation can proceed.

The proposal's conceptual approach - including its remote management and branch naming strategies - remains under consideration, but the thread is effectively on hold until Matěj submits a revised implementation that addresses both the original technical feedback and these clarified packaging expectations. So far, only the original author and maintainer have participated in the discussion.
