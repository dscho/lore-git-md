CI modernization: Finalizing containerized GitHub Actions jobs

This patch (4/10 in Patrick Steinhardt's v3 series) completes the migration of GitHub CI jobs to containerized execution. The change moves all remaining Linux jobs from direct machine-pool execution to container-based runs, following the pattern already established for other jobs in the series.

The key motivation is increased flexibility in choosing container images while maintaining performance parity - benchmark data from Peff shows negligible timing differences between old and new approaches. The patch addresses two potential concerns: root execution (solved by the preceding patch's `setpriv` approach) and historical Node.js binary issues (now resolved for 32-bit jobs).

The diff reorganizes the job matrix, moving all Linux jobs under the containerized section while preserving their existing configurations. Notable is the preservation of Ubuntu 20.04 for gcc-8 compatibility jobs, while most others use `ubuntu:latest`. This change completes the standardization of Git's CI infrastructure across GitHub and GitLab platforms.

As part of a well-tested series that has undergone multiple iterations, this patch appears straightforward and low-risk, representing the final piece in eliminating direct machine-pool execution from Git's CI workflow.
