This is a bug report and investigation regarding SMTP bearer authentication in `git send-email`. The email follows up on a patch implementing SMTP bearer auth (XOAUTH2/OAUTHBEARER) and identifies a specific authentication failure when using long credentials with Gmail's SMTP server.

The reporter (M Hickford) has tested the patch with Gmail configuration and git-credential-oauth, but encounters a 535 authentication error when the access token exceeds ~220 characters. Debug output reveals the SMTP command appears to be corrupted by an inserted space at column 241 in the base64-encoded auth string. The issue is reproducible with both XOAUTH2 and OAUTHBEARER mechanisms when using sufficiently long credentials.

The problem appears to stem from how Net::SMTP handles long authentication strings, though the exact location of the bug isn't yet pinpointed. The reporter asks the original patch author (Julian) to confirm whether they can reproduce the issue and for any insights into the problem. The test methodology is clearly described, including configuration details for Gmail SMTP and credential storage.

This appears to be a legitimate edge case in the SMTP authentication handling that would affect real-world OAuth token usage, particularly with services like Gmail that issue long-lived tokens. The report provides enough detail to investigate the Net::SMTP interaction, though it doesn't yet propose a specific fix.
