Reftable backend thread: discussion about random number generation implementation choices for temporary filenames and backoff delays in the reftable stack. Originated by Patrick Steinhardt as part of ongoing work to reduce Git dependencies in reftable while maintaining platform compatibility. Current status shows disagreement between Patrick and Junio Hamano about necessity of randomization.

Core technical details: reftable code has two random number generation callsites - one for temporary filename generation (format_name()) and one for backoff delays to reduce contention. Both currently use different implementations. Patrick proposes unifying on git_rand() via a shim in "reftable/system.h" as part of dependency reduction effort. Junio questions whether randomization is needed at all, suggesting constant values might suffice since filenames are already distinguished by update indices.

Key positions: Patrick maintains randomization helps reduce contention in high-concurrency scenarios, though acknowledges it's not required for correctness. Junio expresses skepticism about the value of randomization versus added complexity, noting filenames are already unique via update indices. Technical clarification reveals randomization is only performance-related (contention reduction) not correctness-critical.

Open questions: whether to keep randomization for performance benefits or simplify with constants, and whether to use git_rand() or system rand() if keeping randomization. Related to larger effort to reduce Git dependencies in reftable code while maintaining cross-platform compatibility.
