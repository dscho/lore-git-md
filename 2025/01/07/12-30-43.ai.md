This is a platform compatibility bugfix targeting MinGW/Windows test failures in the runtime prefix tests. The patch addresses intermittent EBUSY errors when copying the Git executable during test setup, where Windows appears to keep the file locked even after test completion.

The issue occurs in t0060-path-utils.sh where two tests (testing runtime prefix functionality) both try to copy git.exe to the same test directory. While the root cause of the file lock isn't fully understood (possibly a MinGW or Windows quirk), the solution cleanly factors out the setup into a dedicated test case that runs once, avoiding the duplicate file operations that trigger the EBUSY.

Key changes:
- Extracts the common `mkdir` and `cp` operations from tests 218 and 219 into a new `setup runtime prefix` test
- Leaves the actual test assertions in their original test cases but without the redundant setup
- Maintains all existing test prerequisites (!VALGRIND, RUNTIME_PREFIX, CAN_EXEC_IN_PWD)

The patch is part of a larger series (v3 01/10) of CI fixes, though the context doesn't reveal the series' broader scope. The change is straightforward and appears well-justified given the observed CI failures, though it would be helpful to see if the EBUSY issue reproduces consistently in local Windows environments or is specific to GitLab CI.
