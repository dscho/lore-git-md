This is a documentation patch in the performance optimization series addressing LSan race conditions in threaded test execution. It's the final patch in the post-merge refinements (3/3), adding explanatory comments to the LSan log checking code.

The patch adds clarifying comments to the `check_test_results_san_file_has_entries_` function in `t/test-lib.sh`, which handles leak detection in test output. The comments explain two key aspects: that the function looks for unique leaks marked with DEDUP_TOKEN lines, and that it specifically filters out false positives from the sanitizer's internal `sanitizer::GetThreadStackTopAndBottom` function. This builds on commit b119a687d4 which originally implemented the false positive suppression.

Patrick Steinhardt acknowledges Jeff King's addition of these comments, which help future maintainers understand the somewhat obscure grep pipeline that checks for leaks while filtering known false positives. The comment serves as a breadcrumb trail back to the original implementation commit for those needing more context. This patch represents the documentation polish phase of the series after the technical implementation was already merged.

The function being documented was previously renamed and had its logic inverted in earlier patches of this refinement series (now returns 1 when leaks are found). The comment helps explain why the function needs to look for both DEDUP_TOKEN lines and filter specific sanitizer internals, preserving the technical rationale while making the code more maintainable. This completes the series' focus on long-term maintainability improvements after the core performance optimizations were established.
