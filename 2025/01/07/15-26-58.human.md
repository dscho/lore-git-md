This is a bugfix patch series addressing an issue with the reftable backend's handling of random number generation when the system entropy pool is exhausted. The problem was reported by Randall and appears to specifically affect the OpenSSL backend of Git's cryptographic random number generation.

The series introduces a new flag to allow generating "insecure" random bytes when cryptographic-strength randomness isn't strictly necessary, which is the case for reftable's internal operations. The first commit modifies the wrapper infrastructure to support this, while the second applies it to the reftable stack code. Patrick notes that other platforms' random number generators (like arc4random_buf and getrandom) don't have this issue, making this primarily an OpenSSL-specific fix.

The patch appears carefully considered - Patrick explicitly discusses the alternative of using RAND_pseudo_bytes() unconditionally but rejects it due to potential security implications if the function were accidentally used for cryptographic purposes elsewhere. The changes are relatively contained, touching just a few files with straightforward modifications.

This seems like a solid fix for a real (if somewhat edge-case) problem, though it might be worth watching the thread for any security-conscious reviewers' opinions on the new "insecure" random byte generation API. The changes are well-explained and the commit messages provide good context about why this approach was chosen over alternatives.
