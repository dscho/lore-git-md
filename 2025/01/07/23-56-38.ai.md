This is a bugfix patch addressing reftable entropy handling on ia64 systems with PRNGD, building on the earlier cryptographic random number changes. Randall Becker provides crucial test impact data showing which specific Git tests fail on ia64 platforms when using OpenSSL's PRNGD for entropy, while working fine on x86 systems with hardware RNG.

The patch modifies two reftable call paths that use randomness - for delaying retries when reading stacks and for generating table names - to use the new `CSPRNG_BYTES_INSECURE` flag introduced in the previous patch. This allows operation to continue when the entropy pool is exhausted, which was causing test failures in high-concurrency scenarios.

Key technical details include:
- Specific test cases affected (t0610-reftable-basics through t2400-worktree-add)
- Platform-specific behavior confirmed (fails on ia64/PRNGD, works on x86/hardware RNG)
- Two modified locations in reftable/stack.c:
  - Retry delay calculation now uses insecure random
  - Table name generation uses insecure random

The empirical data strengthens the case for the solution by precisely identifying which tests fail under what conditions, though the underlying architectural debate about whether reftable should depend on cryptographic randomness at all remains unresolved. The patch appears well-scoped to the demonstrated problem while maintaining the thread's high technical precision around platform-specific OpenSSL behavior.
