Platform compatibility bug affecting reftable tests on ia64. Randall reports that test t0610.26 ("ref transaction: many concurrent writers") fails on ia64 systems using OpenSSL's PRNGD random generator, while working correctly on x86 systems with hardware RNG. The test creates 100 concurrent ref updates and verifies they all complete successfully, but on ia64 several updates fail with "unable to get random bytes" errors, causing missing branches in the final output.

The issue appears between Git 2.48.0-rc1 and rc2, suggesting a regression in the release candidate cycle. The test sets an unusually high `reftable.lockTimeout` (300000ms) to avoid flakiness under ASAN, but this doesn't prevent the random number generation failures. The error output shows about 20% of the branch updates failing, with the missing branches appearing randomly in the 40-100 range.

This looks like a potentially serious issue for ia64 users, as it suggests basic ref operations may fail when the system's entropy pool is exhausted. The test failure provides a clear reproduction case that should help diagnose whether this is a Git issue or an OpenSSL/PRNGD configuration problem on ia64.
