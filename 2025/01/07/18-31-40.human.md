This is a feature patch adding client-side support for the object-info capability, part of a series (patch 5/6) that enables retrieving object metadata without full downloads. The patch builds on server-side support added in 2021, allowing clients to request object sizes from v2 protocol servers when the feature is advertised.

The implementation introduces new files `fetch-object-info.{c,h}` with core functionality for sending object-info requests and processing responses. The client currently only supports the 'size' feature, returning an error if the server doesn't advertise object-info capability (controlled by `transfer.advertiseobjectinfo`). The patch includes thorough error handling for protocol versions and malformed responses.

Eric Ju, who picked up the series, suggests two minor improvements: changing an error message from "wrong" to "unsupported" protocol version, and flattening some conditional logic for better readability. The patch appears well-structured with clear helper functions and proper memory allocation, though the suggested simplifications might make the control flow even clearer.

This continues work from Calvin Wan with help from Jonathan Tan and Christian Couder, now being shepherded by Eric Ju. The feature looks ready for review, with only minor stylistic feedback offered so far in the thread.
