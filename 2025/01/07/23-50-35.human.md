This is a follow-up in the discussion about allowing symlinked submodules via a new configuration option. Vadim Zeitlin responds to technical suggestions from brian m. carlson and Junio Hamano about implementing the feature.

The email focuses on two main points: First, Zeitlin agrees that no special clone support is needed for the symlink use case, considering the minor workflow inconvenience acceptable. Second, they raise an open question about naming the new configuration option, suggesting "safe.submodules" or "submodule.validate" as possibilities but seeking input on what would be most consistent with Git's existing configuration patterns.

The discussion has moved from conceptual approval to practical implementation details, with this email addressing the remaining loose ends before a patch can be submitted. The naming question appears to be the last significant blocker, as the technical approach (config-controlled validation in `validate_submodule_path`) and workflow implications (manual configuration after clone) seem settled.
