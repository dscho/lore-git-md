This is a technical discussion about improving test reliability for SIGPIPE handling in Git's test suite. Jeff King responds to Patrick Steinhardt's earlier suggestion about using Perl for test data generation by proposing a simpler and more robust approach to trigger SIGPIPE signals in tests.

Jeff explains why the current Perl-based solution (with its 128KB buffer guess) and the use of `head` are suboptimal. Instead, he suggests using `yes` piped to `true` as a more reliable way to ensure the pipe is closed before the test command runs. This approach eliminates timing races and buffer size guessing while working regardless of command execution speed.

While noting this solution doesn't directly solve the immediate submodule test issue (which requires mid-command SIGPIPE), Jeff shares it as a general technique worth documenting for future test cases. The exchange shows careful consideration of test reliability mechanics, though the core submodule test challenge remains unresolved by this particular approach.
