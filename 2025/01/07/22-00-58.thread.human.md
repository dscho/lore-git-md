This thread discusses whether to add an option to disable Git's validation that prevents submodule paths from being symlinks, prompted by a regression where previously working symlink-based submodule setups broke after commit e8d06089 introduced stricter path checks.

Junio Hamano raises important concerns about how such a configuration option would interact with Git's bootstrapping process, particularly during `git clone` operations. Vadim Zeitlin argues the use case is niche enough that the current workflow—cloning without `--recurse-submodules` and initializing them later—may be sufficient, though Junio notes this represents a regression from behavior that previously worked.

The discussion explores naming the potential option, with "submodule.validate=no" suggested as a placeholder, though participants acknowledge this name might need refinement if future validation checks are added beyond just symlink detection. The thread highlights the tension between maintaining security/safety checks and supporting real-world workflows, with the maintainer seeking input from submodule users about their actual needs while being cautious about configuration design implications.
