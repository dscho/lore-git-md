This thread explores a proposal to allow symlinked submodule paths via an optional configuration override, relaxing Git's current security validation that requires submodules to be directories. Vadim Zeitlin initiated the discussion by presenting a legitimate use case where symlinks would save disk space and initialization time for large submodules shared across multiple projects, particularly in trusted development environments.

Brian m. carlson has responded favorably to the concept, acknowledging the practical workflow benefits while recognizing this represents a tradeoff between security hardening and usability. He suggests the change aligns with recent discussions about balancing these concerns, noting that strict security measures can sometimes disrupt established workflows unnecessarily. From a technical perspective, Brian outlines how the feature could be implemented—likely through a config-controlled toggle that would modify the behavior of `validate_submodule_path()`—though he leaves the actual implementation open for someone else to contribute.

The discussion appears to be moving toward consensus that such an option would be reasonable to add, provided it remains opt-in rather than the default. The next steps would be for someone (potentially Vadim or another interested contributor) to submit a patch implementing the proposed configuration option along with appropriate documentation.
