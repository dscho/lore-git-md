This thread discusses a proposal to allow symlinked submodules in Git. Vadim Zeitlin makes the case for adding an option to bypass Git's current validation that requires submodule paths to be directories rather than symlinks. While this validation was introduced for security reasons (commit e8d0608944), Zeitlin describes a legitimate workflow where symlinked submodules provide significant benefits - particularly for large submodules shared across multiple projects, where symlinks save both disk space and initialization time compared to alternatives like bind mounts.

The proposal suggests making this an opt-in configuration option rather than changing the default behavior, maintaining security for most users while accommodating specialized use cases. The change would affect the submodule subsystem's path validation logic. This seems likely to prompt discussion about the right balance between security and workflow flexibility, particularly in trusted repository scenarios where the symlink behavior is desirable. No patches have been submitted yet; the email is framed as an inquiry about whether such a change would be acceptable before proceeding with implementation.
