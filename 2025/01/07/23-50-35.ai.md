This is a follow-up in the ongoing discussion about adding a configuration option to allow symlinked submodules. Vadim Zeitlin responds to technical implementation suggestions from brian m. carlson and Junio Hamano regarding the proposed feature to relax submodule path validation.

The email focuses on two key points: First, Zeitlin agrees with Hamano's assessment that no special clone support is needed for the feature, acknowledging that the minor workflow inconvenience of cloning without submodules first is acceptable for this niche use case. Second, they raise an important naming question for the new configuration option, suggesting either `safe.submodules` (while noting inconsistency with existing safe.* options) or `submodule.validate` as possibilities, and soliciting feedback on the naming convention.

The discussion has progressed from conceptual approval to practical details, with this email addressing the remaining open questions about option naming and confirming the bootstrapping approach. The technical implementation path (modifying `validate_submodule_path` with config-controlled behavior) remains unchanged from previous messages. Zeitlin indicates intent to prepare a patch soon, pending resolution of these final design questions.

Key elements for future reference: potential config names `safe.submodules` and `submodule.validate`, confirmation that no clone changes are needed, and the continued focus on modifying `validate_submodule_path` behavior. The security-workflow tradeoff remains framed as an opt-in relaxation for trusted environments.
