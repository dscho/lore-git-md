This is a bugfix addressing Git's handling of unpaired curly braces in object names, part of a two-patch series. The patch corrects a longstanding issue where Git would incorrectly parse branch names containing unpaired curly braces (like `foo{bar:README.md`), failing to recognize the path separator. The problem dates back to a 2006 change that assumed curly braces would only appear paired following '@' or '^' symbols.

The fix modifies `get_oid_with_context_1()` in object-name.c to only treat braces as special when they follow '@' or '^', while preserving existing functionality for valid cases like `@{...}` and `^{...}` syntax. The patch includes thorough test coverage for several edge cases, including:
- Basic unpaired brace resolution (`foo{bar:hello`)
- Nested at-sign cases (`foo@@{0}:hello`)
- Commit text searches containing colons (`other^{/testing:}:hello`)

The change maintains backward compatibility while fixing real-world cases that previously failed.
