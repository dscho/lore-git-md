Bugfix discussion with API design considerations in combine-diff.c.

Jeff King responds to concerns about strbuf invariants in Git's combined diff machinery, following up on a previous segmentation fault issue. While the immediate crash was fixed by guarding trace output, the discussion has revealed deeper questions about the `combine_diff_path` struct's handling of strbufs.

King clarifies that the strbuf invariants only apply to initialized strbufs, and in this case, the parent path strbufs are intentionally left uninitialized when not needed (to avoid duplicating path strings). He acknowledges the interface is fragile but argues this doesn't constitute a bug since it's an internal implementation detail without user-facing impact.

The email includes a proposed patch that would initialize all parent path strbufs (not just the changed ones), making the API more robust at minimal cost. However, King notes this doesn't solve the fundamental design issue - that these strbufs are only sometimes populated - and suggests a more thorough solution might involve encapsulating the path access logic.

The discussion also touches on Git's bug tracking practices, with King confirming the project primarily uses the mailing list rather than a formal bug tracker, though he mentions an unofficial issue tracker that sees some activity. The technical focus remains on balancing API robustness with performance in the combined diff implementation.
