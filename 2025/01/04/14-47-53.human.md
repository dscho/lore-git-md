Bugfix for Zsh completion broken by Bash-specific variable expansion. This is version 2 of a patch that fixes config variable completion in Zsh when using Git's completion script.

The issue stems from commit 1e0ee4087e which introduced Bash-specific `${!var}` indirect variable expansion syntax that doesn't work in Zsh's ksh emulation mode. This caused Zsh to show incorrect completions like "__git_first_level_config_vars_for_section_remote" when trying to complete config variables.

D. Ben Knoble's solution replaces the Bash-specific expansion with a portable `__git_indirect` helper function that uses `eval printf` to safely expand variables across shells. The patch includes a thorough demonstration showing the helper works correctly in both Bash and Zsh, handling globals, locals, and values with spaces.

The changes affect multiple functions in git-completion.bash that handle config variable completion (branch.*, remote.*, submodule.* etc.). The technical fix appears sound, building on Philippe Blain's initial work confirming it resolves the Zsh issues while maintaining Bash compatibility.

While the immediate technical issue is addressed, the broader question of cross-shell testing remains open, as noted in the thread context. The current test suite is Bash-specific, making it difficult to automatically catch similar portability issues in the future.
