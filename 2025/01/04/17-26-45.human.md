Maintainer response addressing edge case in object name parsing fix.

Junio Hamano responds to Elijah Newren's patch fixing object name resolution with curly braces, pointing out a potential buffer overflow issue in the current implementation. The patch attempts to handle special cases where braces follow '@' or '^' characters, but Hamano notes the code could read past the string boundary when checking the next character.

He suggests an alternative formulation using `strchr()` that would be both safer and more maintainable, while acknowledging the deeper issue that the solution still relies too much on special-casing specific characters. Hamano expresses some frustration at not having found a more principled solution himself, indicating this remains an area needing further thought.

This is a careful technical review of a subtle edge case in a bugfix series that's already seen significant discussion about how Git should handle ambiguous object names. The maintainer's feedback suggests the implementation needs refinement before merging, though the core approach appears sound.
