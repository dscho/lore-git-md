This is a follow-up bugfix in the ongoing discussion about `git diff-tree --cc`'s handling of path strings in the combined diff machinery. Jeff King builds on the previous consensus that initializing strbufs was the right approach, but now proposes a more fundamental change: replacing the strbuf fields in `struct combine_diff_parent` with simple `char*` pointers.

The key technical changes are:
- Replaces `struct strbuf path` with `char *path` in `struct combine_diff_parent`
- Uses `xstrdup()` when storing paths (only when they differ from the main path)
- Explicitly NULL-initializes path pointers in all creation sites
- Simplifies cleanup to just `free()` calls
- Updates all access sites to handle NULL paths by falling back to the main path

Jeff notes this is both more correct (properly handling all initialization) and more efficient (avoiding strbuf overhead for what is essentially a simple string copy). He also explores but rejects the idea of directly pointing to diff_queue strings due to potential lifetime issues. The patch touches core diff machinery in combine-diff.c, diff-lib.c, and tree-diff.c, plus the diff.h header.

This represents a significant simplification of the earlier approach while maintaining the same optimization (only storing paths when they differ from the main path). It addresses the thread's original concerns about strbuf invariants by eliminating them entirely from this code path. The change appears thorough, with all creation and access sites updated consistently.
