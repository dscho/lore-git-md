Maintainer feedback on object name resolution fixes. Junio C Hamano responds to Elijah Newren's v2 patch series addressing edge cases in Git's object name parsing, particularly around unpaired curly braces and branch:path ambiguities.

The maintainer raises concerns about backward compatibility in the second patch, which tightens validation for describe-like output (e.g., `garbage-gaffed` strings). He argues against requiring strict refname validation since validity rules can change over time, and users may need to copy-paste such strings from old text. The core issue is how to handle strings that could be interpreted multiple ways - Hamano suggests treating them as ambiguous (like other ambiguous object names) rather than imposing new validation rules.

This continues the architectural discussion from earlier in the thread about how strictly Git should validate object names versus maintaining flexibility for historical usage patterns. The maintainer seems to prefer a more permissive approach that preserves existing behavior over stricter validation, even if it means accepting some ambiguity in parsing.
