This is a bug report and technical inquiry about absolute Windows paths in Git repositories. The reporter, Youtian Wang, encountered a commit containing a file with a full Windows absolute path (C:\erg4eye_3\xiangxun23080202) in a public repository, which causes checkout to fail with an "invalid path" error. The email raises two key questions about Git's handling of absolute paths: whether they are intentionally prohibited by design (since they could reference locations outside the repository), and whether the current behavior where such paths can exist in repository history but fail on client-side checkout is expected/desired.

The reporter speculates the path may have been introduced by a third-party tool (possibly referencing a similar issue with a VS Code Git extension) and notes that while hosting services might not detect the issue (since they don't perform checkouts), it surfaces when clients attempt to check out the problematic commit. The email includes links to both the problematic commit and a related GitHub issue for context. This appears to be a genuine platform-specific edge case that could affect Windows users, particularly when working with repositories modified by certain tools.
