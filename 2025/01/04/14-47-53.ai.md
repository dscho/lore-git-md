Bugfix for Zsh shell completion broken by Bash-specific variable expansion. This is version 2 of a patch that addresses config variable completion issues in Zsh when using Git's completion scripts.

The core issue stems from commit 1e0ee4087e which introduced Bash-specific `${!var}` indirect variable expansion syntax that doesn't work in Zsh's ksh emulation mode. This caused Zsh to incorrectly complete config variables, showing raw variable names like "__git_first_level_config_vars_for_section_remote" instead of actual config options.

D. Ben Knoble's patch introduces a portable `__git_indirect` helper function that uses `eval printf '%s' "\"\$$1\""` to safely expand variables across shells. The implementation carefully avoids echo-related portability issues and properly quotes the expansion to prevent word splitting or globbing. The change affects multiple functions in git-completion.bash that handle config variable completion, particularly for first/second level variables in config sections.

The patch includes a demonstration program showing the technique works correctly in both Bash and Zsh (even in ksh emulation mode), properly handling variables containing spaces and working for both local and global variables. Changes are limited to git-completion.bash, modifying 6 existing indirect expansions to use the new helper while adding the helper function definition.

This version (v2) removes some verbose explanation from the commit message while maintaining the key technical details. The fix appears technically sound, having been tested on both Bash 3.2.57 and Zsh 5.0.8. The thread context shows the immediate technical issue is resolved, though broader questions about cross-shell testing infrastructure remain open.
