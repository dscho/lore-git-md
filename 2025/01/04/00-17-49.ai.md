Bugfix addressing object name resolution with unpaired curly braces in branch names, part of a two-patch series. This first patch specifically fixes a long-standing issue where Git incorrectly assumed curly braces only appear paired after '@' or '^' symbols, dating back to a 2006 change.

The core fix modifies `get_oid_with_context_1()` in object-name.c to only treat braces as special when they follow '@' or '^', while properly handling unpaired braces elsewhere. This maintains backward compatibility with existing revision syntax while allowing valid object references like `foo{bar:README.md` to work correctly. The patch includes comprehensive test coverage in t1006-cat-file.sh, verifying several edge cases:
- Basic unpaired brace resolution (`foo{bar:hello`)
- At-sign handling (`foo@@{0}:hello`)
- Commit text containing colons (`other^{/testing:}:hello`)

The change resolves a real-world issue reported by Gabriel Amaral, with input from Michael Haggerty. The implementation carefully preserves existing functionality for @{...} and ^{...} syntax while fixing the original bug. Test cases demonstrate the fix works across various scenarios including branch names with braces, at-signs, and commit message searches containing colons.

This represents the first part of a series addressing related object name resolution issues, with the second patch tackling branch:path syntax edge cases. The current changeset appears well-tested and focused, maintaining backward compatibility while fixing a clear bug in revision parsing.
