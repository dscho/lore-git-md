This is a bugfix series addressing edge cases in object name resolution, particularly involving curly braces and describe-like output parsing. The patches fix longstanding issues dating back to 2006.

The first patch improves handling of unpaired curly braces in object names, ensuring Git only treats braces as special when they follow '@' or '^' characters. This fixes cases like `foo{bar:README.md` that previously failed incorrectly. The patch includes thorough test coverage for various edge cases including `foo@@{...}` syntax and colon handling in commit searches.

The second patch tightens parsing of describe-like output (e.g., `git describe` results) to be more strict about valid refname formats. This addresses cases where malformed input like `major-gaffed` was being misinterpreted as a commit reference. The patch raises backward compatibility questions about how lenient the parser should remain, with examples from real-world repositories showing both strict and loose parsing in use.

The series appears well-tested and carefully considers edge cases, though the second patch's backward compatibility implications may warrant discussion. The maintainer note confirms these aren't regressions but longstanding bugs. The changes demonstrate careful attention to parsing interactions while maintaining existing functionality where needed.
