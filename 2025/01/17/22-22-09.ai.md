This is a protocol feature patch adding OS version capability advertisement, part of Usman Akinyemi's v2 series that's now in final review stages. Junio Hamano provides detailed feedback on the implementation, focusing on several key aspects:

The patch introduces `transfer.advertiseOSVersion` config (default true) to control OS info exchange via new `os-version` protocol capability. Junio questions the fundamental utility of OS version info compared to Git version data, though this appears more as philosophical pushback than blocking feedback.

Technical review highlights include:
- Clarification needed around Windows platform behavior where Git fakes uname(2)
- Suggestion to append "or equivalent" to uname(2) documentation since Windows lacks native uname
- Observation that the config description could better explain the 4 possible advertisement states (client/server combinations)
- Deeper architectural question about whether sanitized versions should be the only form, eliminating separate _sanitized() functions
- Note that http.c's unsanitized git_user_agent() usage might need future fixing

The feedback doesn't raise showstopper issues but suggests several documentation and API design improvements. Junio's questions about the sanitization approach indicate this may need minor rework before final acceptance, though the core functionality appears sound.
