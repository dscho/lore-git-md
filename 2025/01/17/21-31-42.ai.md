This is the final cover letter for a series standardizing help text output behavior across Git commands, converting `git cmd -h` from stderr to stdout. The series originated from Jonas Konrad's observation of inconsistent behavior between parse-options API (stdout) versus manual usage() implementations (stderr).

The implementation introduces three key helpers - `show_usage_if_asked()`, `show_usage_with_options_if_asked()`, and `usage_with_options_internal()` - to centralize stdout behavior while maintaining exit code 129 for compatibility. These helpers use `vfdreportf()` and `vfreportf()` for explicit flush control, with FILE* parameterization for flexibility. The v5 changes replace the earlier `vfdreportf()` helper (taking a file descriptor) with `vfreportf()` (taking a FILE*) as suggested by Jeff King.

The series converts usage_with_options() calls in 14 builtin commands and handles special cases in subcommands like credential and fetch-pack. A test infrastructure in t0012-help.sh with `GIT_TEST_HELP_MUST_BE_STDOUT` validates stdout-only help output. While the exit code question (changing from 129 to 0) is noted as a potential future change, it's deliberately left out of this series.

Technical discussion established that unconditional stdout flushing via write() syscalls is reasonable since the process exits immediately after help output. The implementation refactors reporting to use `vfreportf()` instead of stderr-hardcoded `vreportf()`, while maintaining flushing behavior via `fflush()` followed by `write_in_full()`. The test strategy maintains strict verification of both stdout content and empty stderr, despite recognizing this could produce false positives if warnings appear on stderr, as this will surface concrete cases needing adjustment.

The series has received final approval from Jeff King, confirming it properly implements the goals while addressing all prior concerns. With all technical issues resolved and test verification strategy confirmed, the implementation is complete and ready for integration.
