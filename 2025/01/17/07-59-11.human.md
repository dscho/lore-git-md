This is a follow-up bugfix series addressing edge cases in the reftable migration corruption fix. The original issue involved `git refs migrate` failing for repositories with large reflogs due to a mismatch in reftable header/footer metadata.

Karthik Nayak's 3-patch series makes several technical improvements to prevent similar issues:
1. Makes an internal reflog update function static since it's not used outside refs.c
2. Changes a counter type from unsigned int to uint64_t to better support large repositories and 32-bit systems
3. Adds a safeguard to prevent metadata changes after the reftable header is written

The changes appear focused and well-motivated, building on the previous fix (which was already merged). The patches touch core refs infrastructure and reftable backend code, with clean separation between internal API changes and the new safety check. This looks like solid preventative maintenance work following up on a tricky edge case.
