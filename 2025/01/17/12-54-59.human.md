This is the first patch in a 3-part series fixing a sparc64-specific SIGBUS crash in Git's pack handling. Jeff King factors out the duplicate `--pack_header` argument parsing code from `index-pack` and `unpack-objects` into a new shared function in `packfile.c`. 

The change is a refactoring that centralizes the logic for parsing pack header information, which is passed internally between Git commands like `receive-pack` and `fetch`. While the immediate motivation is to prepare for fixing an alignment issue on sparc64, the change also improves maintainability by eliminating duplicate code and makes the error messages consistent between the two commands.

The patch introduces a new `parse_pack_header_option()` function that handles the parsing of version and entry count from the header string, while leaving the error reporting to the calling functions. This keeps the interface flexible for potential changes in how the options are processed in the future. The implementation remains functionally identical to the code it replaces, just better organized.

This appears to be a well-considered change that follows Git's established patterns for code sharing. The commit message clearly explains the rationale and the tradeoffs made in the design. As the first step in a series addressing a real bug, it sets up the foundation for the subsequent fixes while improving the codebase independently.
