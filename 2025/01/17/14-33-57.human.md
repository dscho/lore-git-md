Bugfix addressing NULL character detection in packed refnames. This is patch 5/10 in a series improving packed-refs validation, responding to a report that `git fsck` fails to detect embedded NULL bytes in refnames. The patch adds a check in `next_record()` to catch refnames containing NUL characters before they can cause issues, since the existing `check_refname_format()` may miss these if the truncated name remains valid.

The implementation currently uses `strlen()` to detect NULs, which Patrick Steinhardt suggests optimizing to `memchr()` in the next version. While the placement of this check in the packed-refs reading code rather than fsck was initially questioned, the author explains this is necessary to catch cases that bypass higher-level validation. The patch appears well-motivated by a concrete bug report and has received constructive technical feedback that will be incorporated in v2.
