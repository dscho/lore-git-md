Thread summary:

Bug report and comprehensive fix for sparc64-specific SIGBUS crash in Git's pack handling (affecting both `unpack-objects` and `index-pack` commands) when compiled with clang. The crash occurs during operations like `git pull` due to misaligned memory access when writing to/reading from a `struct pack_header` through unaligned `unsigned char` buffers. Original report identified the issue in `builtin/unpack-objects.c:653` on sparc64 (clang 19.1.4, glibc 2.40).

Jeff King has provided a completed 3-patch series that:
1. [PATCH 1/3] Refactors pack header parsing into new `parse_pack_header_option()` in packfile.c, centralizing logic from both commands while maintaining identical behavior and adding proper error handling
2. [PATCH 2/3] Replaces direct struct-based memory writes with alignment-safe `put_be32()` operations in the newly introduced function, fixing the immediate SIGBUS issue while preserving identical behavior
3. [PATCH 3/3] Cleans up magic numbers by replacing hardcoded string offsets with `skip_prefix()` in both commands when handling the `--pack_header` option, improving maintainability and updating error messages to include full prefix

Koakuma has verified:
