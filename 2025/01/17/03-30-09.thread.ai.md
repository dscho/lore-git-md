Thread summary:

Bug report and fix for sparc64-specific SIGBUS crash in `git unpack-objects` (triggered during `git pull` operations) when compiled with clang (version 2.48.1.262). The crash occurs at `builtin/unpack-objects.c:653` due to misaligned memory access when writing to a `struct pack_header` through a cast from an unaligned `unsigned char` buffer. Original reporter provided system details (sparc64, clang 19.1.4, glibc 2.40) and identified an overalignment workaround.

Jeff King analyzed the root cause and provided a minimal reproduction case, proposing a fix that replaces struct-based writes with direct buffer manipulation using `put_be32()`. The patch modifies `builtin/unpack-objects.c` to write header fields sequentially into the buffer rather than through potentially misaligned struct access. King notes the same issue likely exists in `index-pack` but addresses only `unpack-objects` in this initial fix.

The solution cleanly resolves the platform-specific issue (sparc64 with clang) by eliminating alignment assumptions that have been present in the code for years. The fix represents a more robust approach than the reporter's workaround, as it removes the problematic pattern entirely rather than compensating for it. The patch demonstrates understanding of both the immediate alignment issue and the broader principle of avoiding type-punning through potentially unaligned pointers.
