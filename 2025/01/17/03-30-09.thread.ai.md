Thread summary:

Bug report and comprehensive fix for sparc64-specific SIGBUS crash in Git's pack handling (affecting both `unpack-objects` and `index-pack` commands) when compiled with clang. The crash occurs during operations like `git pull` due to misaligned memory access when writing to a `struct pack_header` through unaligned `unsigned char` buffers. Original report identified the issue in `builtin/unpack-objects.c:653` on sparc64 (clang 19.1.4, glibc 2.40).

Jeff King has provided a complete solution through a 3-patch series that:
1. Factors out pack header parsing into new `parse_pack_header_option()` in packfile.c
2. Replaces all struct-based writes with alignment-safe `put_be32()` operations
3. Cleans up magic numbers using `skip_prefix()` in both commands

The changes span `builtin/index-pack.c`, `builtin/unpack-objects.c`, and introduce shared functionality in `packfile.[ch]`. While the immediate SIGBUS is fixed by eliminating alignment-sensitive writes, King notes an open question about whether the platform might still have issues with unaligned reads from the same buffers. The solution represents a thorough architectural improvement over the initial workaround by:
- Centralizing header parsing logic
- Removing all type-punning through potentially unaligned pointers
- Improving code clarity by replacing magic numbers
- Applying consistent fixes to both affected commands

Technical details for future reference:
- Core fix uses `put_be32()` for alignment-safe writes
- New `parse_pack_header_option()` handles common header parsing
- `skip_prefix()` replaces hardcoded "pack-" checks
- Both `index-pack` and `unpack-objects` receive identical treatment
- Functionality remains unchanged while becoming platform-safe

The series addresses the immediate crash, improves code quality, and provides a maintainable solution, though the unaligned read question remains pending verification on sparc64. The changes demonstrate deep understanding of both the alignment issue and broader codebase patterns, representing a significant improvement over the original workaround approach.
