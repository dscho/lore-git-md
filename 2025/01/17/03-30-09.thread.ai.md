Thread summary:

Bug report and comprehensive fix for sparc64-specific SIGBUS crash in Git's pack handling (affecting both `unpack-objects` and `index-pack` commands) when compiled with clang. The crash occurs during operations like `git pull` due to misaligned memory access when writing to a `struct pack_header` through unaligned `unsigned char` buffers. Original report identified the issue in `builtin/unpack-objects.c:653` on sparc64 (clang 19.1.4, glibc 2.40).

Jeff King has provided a completed 3-patch series that:
1. [PATCH 1/3] Refactors pack header parsing into new `parse_pack_header_option()` in packfile.c, centralizing logic from both commands while maintaining identical behavior and adding proper error handling
2. [PATCH 2/3] Replaces direct struct-based memory writes with alignment-safe `put_be32()` operations in the newly introduced function, fixing the immediate SIGBUS issue while preserving identical behavior
3. [PATCH 3/3] Cleans up magic numbers by replacing hardcoded string offsets with `skip_prefix()` in both commands when handling the `--pack_header` option, improving maintainability and updating error messages to include full prefix

Technical implementation details:
- PATCH 1 established foundation by moving shared header parsing to packfile.[ch] with:
  - New `parse_pack_header_option()` handling signature, version, and entry count parsing
  - Translated error handling
  - Strict input validation (comma-separated version,entry format)
  - Buffer/length through to helper function
- PATCH 2 specifically addressed the alignment issue by:
  - Replacing 3 struct field assignments with `put_be32()` calls in packfile.c
  - Manual buffer position tracking with `hdr` pointer arithmetic
  - Updated length calculation matching new write pattern
  - Maintaining all existing input validation
- PATCH 3 completed the series with quality improvements:
  - Eliminated magic number `+14` offset for `--pack_header=`
  - Updated error messages to show full option prefix
  - Applied consistent changes to both `index-pack` and `unpack-objects`
  - Used Git's `skip_prefix()` utility for cleaner string handling

The series demonstrates thorough architectural improvements that:
- Centralize header parsing logic in packfile.c
- Fix platform-specific crashes on sparc64
- Improve code clarity and maintainability
- Apply consistent fixes to both affected commands
- Preserve functionality while making it platform-safe
- Remove magic numbers in favor of utility functions

Changes span `builtin/index-pack.c`, `builtin/unpack-objects.c`, and `packfile.[ch]`, with all three patches now complete. The solution shows deep understanding of both the immediate alignment issue and broader codebase patterns, providing a robust fix that benefits all platforms while specifically solving the sparc64 SIGBUS problem.
