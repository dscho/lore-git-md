Refactoring patch in the OS version capability series, extending system information gathering.

This patch modifies the recently introduced `get_uname_info()` function to optionally return just the OS name (`sysname`) rather than full system details. The change prepares for upcoming use in the protocol capability where only the OS name is needed, while maintaining the existing full-detail behavior for bug reports via a new `full` parameter.

Key technical changes:
- Adds boolean `full` parameter to `get_uname_info()` function signature
- Splits output formatting into two paths: full details (unchanged) vs. just `sysname`
- Updates all three call sites (header, implementation, bugreport.c caller)
- Preserves error handling and documentation behavior

The patch maintains backward compatibility by defaulting bugreport.c to request full details (passing `1`). This is part of the larger effort to centralize and reuse system information gathering while accommodating different feature needs - here distinguishing between debug/help contexts needing full details versus protocol efficiency preferring minimal data.

The change is straightforward but foundational, enabling the subsequent protocol capability patch while demonstrating the value of the earlier refactoring that moved uname handling to version.c. The commit message notes this may need further evolution if structured format options are added later.
