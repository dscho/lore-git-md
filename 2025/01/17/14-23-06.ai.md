This is patch 4/10 in a bugfix series addressing packed-refs validation issues, focusing specifically on-disk format consistency checks. The patch adds header validation for packed-refs files, ensuring they start with the correct "# pack-refs with:" line and handling malformed cases.

Key technical aspects in this iteration:
1. Introduces `packed_fsck_ref_header()` to validate the packed-refs header format, with Patrick suggesting more future-proof error messaging ("unknown" vs "official" header)
2. Implements `packed_fsck_ref_next_line()` for line parsing, currently handling missing newlines in a way Patrick questions (treating EOF as EOL) - the author acknowledges this needs refinement
3. Maintains the `safe_object_check` flag approach (to skip object validation if format is invalid) despite Patrick's earlier architectural suggestion to separate format checks from object validation
4. Handles race conditions between file existence check and reading, though Patrick notes remaining TOCTOU risks with symlinks that the author argues would overcomplicate the fix

The discussion reveals two main points of ongoing refinement:
- Line parsing logic needs clearer separation between validation and parsing roles
- Header validation messaging should avoid implying there's one "official" format

The author indicates these will be addressed in v2 while keeping the current race condition handling as-is due to complexity concerns. This patch remains architecturally transitional - while it implements specific format checks, Patrick's broader vision (expressed in earlier reviews) would restructure this validation to happen before generic object checks rather than using the current `safe_object_check` flag approach.
