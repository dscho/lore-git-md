This is a test infrastructure patch that's part of a larger effort to standardize help text output behavior across Git commands. The patch modifies t0012-help.sh to optionally enforce that "-h" help output goes to stdout rather than stderr, which is the eventual goal of the series. Currently, some commands output help to stderr via usage_with_options(), while parse-options.c sends it to stdout.

The key change here is making the test suite more useful during the migration period. By default, tests remain permissive (allowing help output on stdout or stderr), but developers can set GIT_TEST_HELP_MUST_BE_STDOUT=1 to see which commands still need conversion. The patch comes from Jeff King (peff) with Junio Hamano's sign-off, indicating it's a well-considered part of the broader standardization effort.

This is a transitional step - the flag will eventually be removed when all commands are converted. The test changes are straightforward, splitting output capture into separate files for stdout and stderr, then applying different assertions based on whether strict mode is enabled. This maintains test coverage while allowing incremental conversion of commands.
