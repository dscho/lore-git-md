This is part 2/8 of brian m. carlson's series refactoring Git's hash algorithm handling, with Taylor Blau contributing this specific patch. The change modifies the hashfile API to store its own `git_hash_algo` pointer rather than relying on the global `the_hash_algo`.

The patch adds an `algop` field to `struct hashfile` and updates all hash operations in `csum-file.c` to use this local reference instead of the global one. This includes changes to `hashflush()`, `finalize_hashfile()`, `hashwrite()`, and checkpoint-related functions to consistently use `f->algop` for all unsafe hash operations (init, update, final, clone).

The technical changes are straightforward mechanical conversions from `the_hash_algo` to the new field, maintaining identical behavior while preparing for future flexibility in hash algorithm selection. This aligns with the series' broader goal of eliminating separate unsafe hash variants by making the algorithm choice explicit at the hashfile level rather than relying on global state.

The patch builds on the test infrastructure introduced in part 1 (the `sha1-unsafe` test helper) and sets up for subsequent patches that will introduce the unified `unsafe_hash_algo()` mechanism. It touches core hashing operations but doesn't change any user-visible behavior, focusing purely on internal API restructuring.
