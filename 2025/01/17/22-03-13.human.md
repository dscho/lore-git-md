This is part 2 of an 8-part series refactoring Git's hash algorithm handling, specifically focusing on storing the hash algorithm within the hashfile structure rather than relying on the global `the_hash_algo`.

The patch modifies the hashfile API to store its own `algop` pointer (to a `git_hash_algo` struct) rather than using the global `the_hash_algo`. This is a preparatory change for future work that may need to use different hash algorithms within the same process. The changes are mechanical - replacing direct `the_hash_algo` references with `f->algop` throughout `csum-file.c`, while maintaining identical behavior since the field is initialized to `the_hash_algo`.

This is a clean, focused change that follows the series' architectural direction of moving away from global hash algorithm state. The patch appears well-crafted with thorough updates to all relevant hash operations in the file. As part of a larger effort to abstract hash algorithm handling, this change helps enable future work while being relatively low-risk since it doesn't change any observable behavior.
