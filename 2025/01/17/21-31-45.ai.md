This is part of the ongoing series to standardize help text output behavior across Git commands, specifically converting `git cmd -h` from stderr to stdout. The patch introduces a new helper function `show_usage_if_asked()` that encapsulates the common pattern of checking for "-h" and showing usage text, similar to the earlier `usage_with_options_internal()` helper but for simpler commands that don't use the parse-options API.

The implementation builds on the series' established pattern by using the new `vfreportf()` function (which takes a FILE* parameter) to ensure help text goes to stdout while maintaining the existing status code 129 for backward compatibility. The commit message notes this exit code may be worth reconsidering in the future since showing help is a successful operation. The change is mechanical and relies on the test coverage from t0012-help.sh established earlier in the series.

Jeff King (peff) provided input on the approach, and Junio Hamano has signed off on this patch. This is one of the key plumbing pieces needed before converting individual commands, following the same pattern as previous patches in the series. The helper will be used to standardize direct `usage()` calls in commands that don't use the parse-options infrastructure.
