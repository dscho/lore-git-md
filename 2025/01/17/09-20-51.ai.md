This is part 4 of a 5-patch series continuing the `the_repository` removal effort, specifically targeting the `write_rev_file()` family of functions in `pack-write.c`. The patch converts `write_rev_file()`, `write_rev_file_order()`, and `write_rev_header()` to take an explicit `hash_algo` parameter instead of using the global `the_hash_algo`. 

The changes follow the series' established pattern of bubbling up global usage to callers while maintaining compatibility. Most callers (in `index-pack.c` and `pack-write.c`) temporarily pass `the_hash_algo`, but `midx-write.c` uses its available repository context to avoid reintroducing globals. The patch updates function prototypes in `pack.h` and modifies all internal hash algorithm references to use the passed parameter rather than the global.

Key technical details include:
- New `const struct git_hash_algo*` parameters added to all three functions
- `write_rev_header()` now writes the passed algorithm's OID version
- Call sites updated in `builtin/index-pack.c`, `midx-write.c`, and `pack-write.c`
- Function prototypes in `pack.h` expanded to include the new parameter
- The change maintains existing behavior while removing direct global dependencies

This continues the incremental strategy of converting lower-level functions while temporarily preserving global usage in upper layers, with special handling for contexts (like midx) where repository information is already available. The patch is mechanically similar to prior conversions in the series, focusing on the `write_rev_*` functions while leaving remaining globals for later patches.
