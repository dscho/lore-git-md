This is the final patch in Jeff King's 3-part series fixing a sparc64-specific SIGBUS crash in Git's pack handling. The series previously refactored pack header parsing into a shared function and fixed alignment issues in the implementation.

Patch 3/3 is a cleanup that replaces magic number string offsets with `skip_prefix()` in both `index-pack` and `unpack-objects` when handling the `--pack_header` option. The change:
- Eliminates the hardcoded `+14` offset for skipping past `"--pack_header="`
- Updates error messages to include the full `--pack_header` prefix for better context
- Maintains identical functionality while making the code more maintainable

The patch touches both command implementations similarly, showing the refactoring benefits from the earlier centralization of the parsing logic. While noting this might be "just churn", the author demonstrates good practice by removing manual string length calculations in favor of Git's string utilities.

This completes the series that:
1. Centralized pack header parsing
2. Fixed sparc64 alignment issues
3. Now cleans up the interface with proper string utilities

The changes span `builtin/index-pack.c` and `builtin/unpack-objects.c`, with the error message updates being the most visible behavior change (though functionally equivalent). The series as a whole improves code quality while solving a real platform-specific bug.
