This is part 5/6 of the series standardizing help text output behavior across Git commands, focusing on "oddball" cases that don't follow the typical `-h` pattern. The patch converts several special-case commands (`credential`, `fetch-pack`, `unpack-file`, `upload-archive`, and `var`) to use the new `show_usage_if_asked()` helper, ensuring their help text goes to stdout rather than stderr when explicitly requested.

The changes handle three distinct patterns: commands that combined argument validation with `-h` checking in a single condition, commands that didn't specially handle `-h` at all (like `git var`), and commands that had their own usage patterns. Each is updated to first check for help requests via the new helper before proceeding with their normal argument validation. The patch maintains all existing error handling and exit codes while just changing the output stream for help text.

The implementation has been reviewed and acked by Jeff King, with Junio Hamano signing off. This continues the series' careful approach of preserving backward compatibility while systematically converting all command help output to stdout. The changes are mechanical but necessary to cover edge cases that didn't fit the standard `-argc == 2 && !strcmp(argv[1], "-h")` pattern.
