This is the 5/6 patch in Usman Akinyemi's series adding OS version capability to Git's protocol. The patch implements the core functionality for exchanging OS information between clients and servers via a new `os-version` capability.

The feature is enabled by default but can be disabled via `transfer.advertiseOSVersion` config for privacy. The OS name comes from `uname(2)`'s `sysname` field (like "Linux" or "Windows"), sanitized to printable ASCII. Windows testing is skipped due to Git's fake `uname(2)` implementation differing from the command-line tool.

The patch adds:
- New config option and protocol documentation
- Capability advertisement in both client (connect.c) and server (serve.c)
- Core version string handling in version.c with caching and sanitization
- Test updates to verify the behavior (skipping Windows)

This appears to be a well-considered implementation that balances functionality with privacy concerns, building on earlier refactoring work in the series. The Windows test limitation is clearly documented as a known constraint rather than a bug. With maintainer approval already secured in earlier discussion, this looks ready for inclusion.
