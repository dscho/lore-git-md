Refactoring of hash algorithm handling with new checkpoint API. This patch introduces `hashfile_checkpoint_init()` to ensure consistent hash function usage between hashfiles and their checkpoints, addressing crashes that could happen when mismatched algorithms were used. The change affects `csum-file.c`, `bulk-checkin.c`, and `fast-import.c`.

The new API eliminates manual initialization of checkpoints with unsafe variants, instead using the hashfile's algorithm pointer (`f->algop`) to ensure matching implementations. Key changes include:
- New `hashfile_checkpoint_init()` function that initializes a checkpoint's context using the hashfile's algorithm
- Removal of explicit unsafe hash function calls in `fast-import.c` and `bulk-checkin.c`
- Additional `prepare_to_stream()` call in bulk-checkin to ensure proper initialization before checkpoint creation
- Zero-initialization of checkpoints now handled internally by the new function

The patch builds on earlier fixes for segfaults (106140a99f, 9218c0bfe1) and represents a more robust solution than the previous workarounds. It continues the series' theme of unifying hash algorithm access while making the checkpoint API more foolproof against future changes to hashfile implementations.
