This is the final version of a series standardizing help text output behavior across Git commands. The patch series converts `git cmd -h` output from stderr to stdout, addressing an inconsistency where some commands (using parse-options API) showed help on stdout while others (using manual usage() calls) showed it on stderr.

The series introduces three key helper functions to centralize stdout behavior while maintaining backward compatibility with exit code 129. The implementation now uses FILE* parameterization for flexibility, with explicit flush control via `vfreportf()` and `vfreportf()`. The technical discussion has settled on using unconditional flushing via write() syscalls since the process exits immediately after help output.

Test coverage includes t0012-help.sh with `GIT_TEST_HELP_MUST_BE_STDOUT` to validate stdout-only help behavior. The maintainers have agreed to keep strict verification of both stdout content and empty stderr in tests, despite recognizing this could produce false positives - the strict check will help surface any cases needing adjustment.

The series converts usage_with_options() calls in 14 builtin commands and handles special cases in subcommands like credential and fetch-pack. While the exit code question (changing from 129 to 0) remains open for future discussion, the core output stream handling is now fully resolved and ready for integration. Jeff King has approved the final implementation, confirming it properly addresses all prior concerns.
