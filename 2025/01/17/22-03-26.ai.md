This is part 6 of an 8-part series refactoring Git's hash algorithm handling, specifically converting test infrastructure to use the new `unsafe_hash_algo()` mechanism. The patch comes from Taylor Blau and builds on earlier work in the series by brian m. carlson.

The change simplifies the test helper `cmd_hash_impl()` that powers both the 'sha1' and 'sha1-unsafe' test commands. Previously it contained conditional logic to choose between safe and unsafe variants of hash operations (init, update, final). Now it uses `unsafe_hash_algo()` at the start to potentially convert the algorithm pointer to its unsafe variant, then proceeds with direct calls to the standard function names. This eliminates 12 lines of conditional code while maintaining the same behavior.

The modification demonstrates the series' core goal of eliminating separate unsafe function variants in favor of unified access through algorithm pointers. The test helper continues to support both safe and unsafe operations, but now does so through the new `unsafe_hash_algo()` indirection rather than direct function pointer selection. This matches the architectural direction seen in the series' other conversions of core components like csum-file.c.

The change is straightforward and appears well-contained, affecting only test infrastructure while maintaining the same test coverage. It follows naturally from the series' earlier introduction of `unsafe_hash_algo()` and completes the test helper's adaptation to the new approach. Reviewers have already engaged with the core concepts in previous patches, so this appears to be a clean application of the established pattern to the test component.
