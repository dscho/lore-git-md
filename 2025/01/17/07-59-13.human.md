Technical improvement to reftable migration path (part 2/3). This patch changes the type of reference update indices from `unsigned int` to `uint64_t` throughout the refs subsystem, addressing potential limitations when handling repositories with millions of references. The change affects several key data structures including `ref_update.index` and `ref_transaction.max_index`.

The modification stems from the reftable migration context where reference ordering is important, particularly for large repositories. While the current alphabetical ordering works for most cases, the index provides an alternative ordering mechanism that needs to accommodate very large repositories. The change is straightforward but touches multiple files (refs.c, refs-internal.h, and reftable-backend.c) to maintain consistency across the codebase.

This appears to be a proactive change rather than fixing an immediate bug, though it was prompted by earlier corruption issues during reftable conversion. The patch maintains the same behavior while future-proofing the code against potential overflow issues on large repositories. The change is cleanly implemented with minimal churn, just updating type declarations in a handful of locations.
