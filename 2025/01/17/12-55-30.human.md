Bugfix addressing a sparc64-specific SIGBUS crash in Git's pack handling when compiled with clang. This is the second patch in Jeff King's 3-part series to fix alignment issues in pack header parsing.

The patch replaces unsafe struct-based memory writes with alignment-safe `put_be32()` operations when reconstructing pack headers in memory. The original code cast an unaligned buffer to a `struct pack_header`, which caused crashes on sparc64 due to strict alignment requirements. The new version writes each 32-bit value individually using byte operations that don't require alignment.

This change affects the newly centralized `parse_pack_header_option()` function introduced in patch 1/3, which handles pack header parsing for both `unpack-objects` and `index-pack`. While this should resolve the immediate SIGBUS issue, King notes there's still an open question about potential alignment problems with memory reads that may need addressing in future work.

The patch demonstrates careful attention to platform-specific behavior while maintaining the same logical operation of the code. It's a focused change that builds on the refactoring from the first patch to provide a robust solution to the reported issue.
