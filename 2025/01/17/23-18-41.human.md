This is a follow-up discussion in the OS version capability series, specifically addressing concerns about platform compatibility and the need for custom version string generation.

Randall Becker confirms that the non-standard `uname` output format from his NonStop platform ("NONSTOP_KERNEL L24 08 NSV-D") would be acceptable for the protocol's purposes. This directly responds to Junio Hamano's earlier question about whether the proposed `osversion.command` config is actually necessary if platforms can work with their native `uname` output.

The exchange suggests that the custom command execution feature (introduced in patch 6/6) may indeed be solving a non-problem, at least for some platforms. This aligns with Junio's security concerns about arbitrary command execution and strengthens the case for simplifying or removing this configuration option. The discussion continues to cast doubt on the current design's necessity while providing concrete data points about real-world platform behavior.
