This thread addresses a sparc64-specific SIGBUS issue in Git's pack handling that occurs when compiled with clang, affecting both `unpack-objects` and `index-pack` during operations like `git pull`. The root cause is misaligned memory access when reading/writing `struct pack_header` through unaligned buffers.

Jeff King has provided a thorough 3-patch series that centralizes pack header parsing logic, fixes write-side alignment issues using `put_be32()`, and cleans up magic numbers. Junio C Hamano has validated the architectural approach, while Koakuma confirmed the fixes resolve write-side crashes but identified remaining read-side alignment issues in `unpack_all()`.

The discussion has now turned to compiler warnings from sparse about bit truncation in the `put_be32()` implementation. Jeff notes these warnings are inconsistent (only appearing for large constants) and confirms Junio's proposed fix generates identical assembly despite feeling less clean aesthetically. This highlights broader considerations about balancing code clarity with static analysis requirements, particularly important given the low-level memory handling involved in these alignment fixes.

The series demonstrates excellent cross-platform thinking - fixing immediate sparc64 crashes while improving code structure through centralized parsing logic and elimination of magic numbers. Remaining work includes finalizing the read-side alignment solution (either via `get_be32()` or union restructuring) and verifying similar issues in `index-pack`. The patches have already received maintainer validation and represent a significant improvement in both correctness and maintainability of Git's pack handling.
