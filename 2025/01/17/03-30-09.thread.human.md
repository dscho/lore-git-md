This thread addresses a sparc64-specific crash in Git's pack handling that occurs during operations like `git pull` when compiled with clang. The issue stems from misaligned memory access when working with `struct pack_header` through unaligned buffers, causing SIGBUS errors. Jeff King (Peff) has provided a comprehensive 3-patch series that refactors the pack header parsing logic, fixes the immediate write-side alignment issues using `put_be32()`, and cleans up magic numbers in the code.

Junio Hamano, the Git maintainer, has now weighed in with an insightful observation about why the crash was intermittent - it depended on which of two static buffers in `unpack-objects.c` was being used, as one happened to be properly aligned while the other wasn't. He confirms that Peff's approach using `put_be32()` is the right solution for handling alignment properly. This maintainer validation gives the series additional weight.

While the write-side issues are now addressed, testing by Koakuma has revealed that the read path in `unpack_all()` still crashes due to unaligned access, suggesting a need for similar treatment using `get_be32()`. The same may apply to `index-pack`. The series demonstrates excellent architectural improvements by centralizing logic and making the code more maintainable while fixing platform-specific issues, but some work remains to fully resolve all alignment problems.
