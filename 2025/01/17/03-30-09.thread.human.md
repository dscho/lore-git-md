This thread reports a platform-specific compilation bug affecting sparc64 systems when Git is built with clang. The issue manifests as a SIGBUS crash during `git pull` operations, specifically when unpacking objects and handling the packfile signature. The crash occurs reliably at a specific line in `builtin/unpack-objects.c` where the code attempts to access `hdr->hdr_signature`.

The reporter has provided detailed system information (sparc64, clang 19.1.4, glibc 2.40) and identified that the issue doesn't occur with GCC builds. They've found that overaligning the buffer prevents the crash, suggesting an alignment sensitivity in clang's code generation for this architecture. While the workaround appears effective, the reporter is unsure whether this constitutes a proper fix or merely masks a deeper issue. The report is thorough in describing the failure mode but lacks historical context about when the problem was introduced. Platform experts and compiler specialists will likely need to weigh in on whether this requires a Git-side fix or should be addressed in clang's sparc64 backend.
