This thread addresses a sparc64-specific SIGBUS issue in Git's pack handling that occurs when compiled with clang, affecting both `unpack-objects` and `index-pack` commands. Jeff King provided a comprehensive 3-patch series that refactors pack header parsing, fixes alignment issues using `put_be32()`, and cleans up magic numbers. The solution was verified by Koakuma on sparc64 hardware and reviewed by Junio C Hamano, who confirmed the architectural approach.

Junio has now followed up with a refinement to address static analysis warnings from sparse about constant truncation in the `put_be32()` implementation. While the original fix worked correctly, sparse flagged the implicit truncation of the PACK_SIGNATURE constant (0x5041434b). The proposed solution adds explicit masking with `& 0xff` in `compat/bswap.h` to silence these warnings without changing the generated code. Junio notes this is somewhat unsatisfying since the masking is redundant for actual compilers, but necessary to keep static analysis happy.

The core fix for the sparc64 alignment issue remains unchanged and effective.
