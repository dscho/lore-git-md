This thread reports and fixes a sparc64-specific crash in `git pull` operations when Git is compiled with clang. The issue manifests as a SIGBUS signal during object unpacking, specifically when accessing pack header data through a struct pointer that may be misaligned on this architecture. The original reporter provided detailed system specifications and confirmed the crash could be worked around by forcing buffer alignment, though the proper solution wasn't immediately clear.

Jeff King has now analyzed the root cause and proposed a fix. The problem stems from code that writes to a `struct pack_header` through a cast from an unaligned buffer - a pattern that works on most architectures but fails on strict-alignment platforms like sparc64 when using clang. His solution replaces the struct-based writes with direct buffer manipulation using `put_be32()`, cleanly avoiding the alignment assumptions. While the same issue might exist in `index-pack`, this initial patch focuses on fixing `unpack-objects.c` where the crash was observed.

The fix addresses a long-standing but previously unnoticed issue that only surfaced with this specific platform/compiler combination, showing how subtle architecture-dependent behaviors can lurk in code that works fine on more common configurations.
