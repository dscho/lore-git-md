This thread addresses a sparc64-specific SIGBUS crash in `git unpack-objects` (triggered during `git pull`) when compiled with clang. The crash occurs due to misaligned memory access when writing to a pack header structure. The original reporter provided detailed system information and a workaround.

Jeff King analyzed the root cause and initially proposed a fix for `unpack-objects` that replaces problematic struct-based writes with safer `put_be32()` buffer manipulation. He has now expanded this into a more comprehensive 3-patch series that also fixes the same issue in `index-pack`. The solution centralizes pack header parsing logic into a new `parse_pack_header_option()` function, eliminates magic numbers in favor of `skip_prefix()`, and makes both commands alignment-safe by removing all direct struct access to potentially unaligned buffers.

While the immediate write-side crash is resolved, King notes an open question about whether the platform might still have issues with unaligned reads from these buffers. The patches represent a significant improvement in both robustness and code quality, addressing a long-standing alignment assumption that only manifested on this particular platform/toolchain combination. The changes affect `packfile.[ch]`, `index-pack.c`, and `unpack-objects.c`, with identical fixes applied to both commands for consistency.
