This is a documentation patch that formalizes Git's long-standing but previously unwritten convention about command-line option precedence. Junio C Hamano proposes adding a new section to `gitcli.txt` that explicitly states command-line options override both configuration variables and environment variables, with concrete examples like `git commit --author` taking precedence over `user.name` config and `GIT_AUTHOR_NAME` environment variable.

The patch builds on an earlier discussion about `git grep` options, where it became clear this general principle needed documentation. The new section is placed near existing documentation about negated options (`--no-option` syntax) since it relates to the same theme of option behavior. The patch maintains Git's documentation style and provides clear examples to illustrate the precedence rules.

This change doesn't introduce any behavior modifications - it simply documents existing behavior that was previously only implicit. The maintainer sees value in making these rules explicit for both end users and command authors, even if it might seem obvious to experienced Git contributors. The patch is well-formed and addresses a clear documentation gap surfaced by recent discussions.
