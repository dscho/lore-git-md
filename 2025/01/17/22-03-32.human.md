This is the final patch in a series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations. Authored by Taylor Blau, it removes the now-unused scaffolding for the unsafe function variants after all callers have been converted to use the new `unsafe_hash_algo()` mechanism introduced earlier in the series.

The patch deletes 15 lines from `hash.h` and 15 lines from `object-file.c`, removing the now-obsolete `unsafe_*_fn` function pointers from the `git_hash_algo` struct and their implementations. This cleanup was made possible by the series' earlier work to unify hash algorithm access through the `unsafe_hash_algo()` indirection.

The changes are straightforward mechanical removals with no behavior changes, as all call sites were already updated in previous patches. This represents the completion of the series' goal to simplify the hash algorithm API by eliminating duplicate unsafe variants while maintaining the same functionality through a more maintainable indirection mechanism.

The patch builds on substantial prior review from Jeff King, Patrick Steinhardt, and others in the thread, and demonstrates the benefits of the new approach by showing the codebase can now operate without the separate unsafe function variants. This is a clean-up patch that finalizes the architectural improvements made throughout the series.
