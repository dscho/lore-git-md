This is a discussion about the OS version advertisement feature in Git's protocol, specifically addressing concerns raised by Junio Hamano about the design approach.

Randall Becker weighs in on the ongoing debate about the OS version capability implementation. He raises concerns about the portability of both `uname(2)` and `uname(1)`, noting that neither is guaranteed to be available on all systems. His main point is that the current approach could cause build problems, particularly during release candidate cycles when such issues would be most disruptive.

The email continues the thread's central tension between runtime command execution (as currently implemented) versus compile-time solutions. Becker suggests an alternative approach where the version string could be queried by specific named elements rather than relying on uname's output format. This aligns with Junio's earlier concerns about the security and portability of the current design.

The discussion remains unresolved, with core questions about:
- Whether the feature's value justifies its complexity
- How to handle platform-specific behavior more robustly
- Whether to maintain both sanitized and unsanitized version strings
