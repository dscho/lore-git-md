Feature implementation with configurable OS version reporting in Git protocol v2.

This is the cover letter for v2 of Usman Akinyemi's patch series adding OS version capability to Git's protocol. The series builds on previous work by Christian Couder and incorporates feedback from the mailing list discussion, particularly addressing enterprise use cases raised by Randall S. Becker.

The implementation introduces a new `os-version` capability that lets clients and servers exchange operating system information, similar to the existing `agent` capability. Key aspects include:
- Default behavior uses `uname(2)` to report just the OS name (e.g. "Linux")
- Privacy-sensitive users can disable via `transfer.advertiseOSVersion=false`
- Enterprise customization via `osversion.command` to run arbitrary commands for version reporting
- Windows compatibility handled by disabling tests due to Git's fake `uname` implementation

The v2 changes show thoughtful refinements: better test organization, improved documentation clarity, and proper handling of carriage returns in the string sanitization. The series appears well-tested with comprehensive changes to protocol documentation, config options, and test suites.

This represents a balanced solution between the maintainer's preference for simplicity and real-world needs for customizable version reporting. With Junio Hamano having approved the core approach in previous discussion, this iteration seems ready for serious consideration.
