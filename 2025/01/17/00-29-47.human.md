Git CLI documentation patch clarifying option precedence rules.

Junio Hamano proposes adding a section to `gitcli.txt` that explicitly states Git's long-standing convention: command-line options override configuration variables. This comes from a thread about documenting negatable options in `git grep`, where it became clear this fundamental behavior wasn't formally documented. The patch uses `user.signingKey` and `git tag -u` as the example, showing how command-line flags take precedence over config settings.

This is a behavior change - it's codifying existing practice that was previously only mentioned in passing near the `--no-track` documentation. The patch is clean and focused, though Junio notes he couldn't find existing documentation of this rule despite it being a 20-year-old convention. The change would help newcomers understand Git's configuration hierarchy without having to infer it from scattered examples.
