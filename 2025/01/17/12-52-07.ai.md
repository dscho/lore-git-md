This is a follow-up in the sparc64 SIGBUS crash thread, providing a more complete fix for the alignment issue in `unpack-objects` and `index-pack`. Jeff King expands on his earlier analysis with a 3-patch series that:

1. Factors out pack header parsing logic into a new `parse_pack_header_option()` function in packfile.c
2. Replaces the problematic struct-based writes with direct buffer manipulation using `put_be32()` to avoid alignment issues
3. Cleans up magic number usage with `skip_prefix()` in both commands

The changes affect `builtin/index-pack.c`, `builtin/unpack-objects.c`, and introduce new shared functions in `packfile.[ch]`. While the immediate fix addresses the write-side alignment problem that caused the SIGBUS, King notes potential concerns about subsequent reads from the same buffer, speculating the platform might allow unaligned reads where writes fail. The series represents a more thorough solution than the initial workaround, eliminating the alignment-sensitive pattern entirely rather than just compensating for it.

Key technical points for future reference:
- The core fix replaces direct struct access with `put_be32()` writes
- New `parse_pack_header_option()` centralizes header parsing logic
- Magic numbers like "pack-" are replaced with `skip_prefix()` calls
- Both `index-pack` and `unpack-objects` receive identical fixes
- The solution maintains the same functionality while being alignment-safe

The patch appears well-considered, addressing both the immediate crash and related code quality issues, though the unaligned read question remains open pending testing on the affected platform.
