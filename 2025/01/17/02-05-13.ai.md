Documentation patch formalizing Git's CLI precedence rules.

This patch adds a new section to `gitcli.txt` explicitly stating that command-line options override both config variables and environment variables, with `git commit --author` given as a concrete example. The change builds on the earlier discussion about `git grep`'s documentation by generalizing the principle of command-line precedence that was previously only implied in Git's behavior.

The patch maintains Git's documentation style while filling an important gap in the official documentation. It specifically addresses the precedence chain: command-line > environment > config, using `user.name`, `GIT_AUTHOR_NAME`, and `--author` as the canonical example. The addition is placed near existing documentation about negated options (`--no-option`), creating a more complete picture of Git's CLI behavior patterns.

This serves as a reference point for both users and contributors, making explicit what was previously implicit knowledge. The patch doesn't introduce new behavior but documents existing conventions that affect many Git commands. The maintainer's sign-off and the placement in `gitcli.txt` (Git's central CLI documentation) indicate this is intended as authoritative guidance.
