This is a discussion about the final patch in Usman Akinyemi's series adding OS version capability to Git's protocol. Junio Hamano raises fundamental concerns about the proposed `osversion.command` config option, which would allow arbitrary command output to be used as the OS version string.

Junio questions whether this runtime customization is the right approach, suggesting instead that platform-specific uname(2) emulation or compile-time customization would be preferable. He cites security concerns about arbitrary command execution and worries about the feature being abused to send useless data. The critique extends to the test case using "uname -srvm", which Junio notes may not be portable and suggests using a more controlled test string instead.

The exchange highlights a philosophical difference - while Usman's patch provides maximum flexibility, Junio favors a more constrained approach that would avoid runtime command execution. This comes after the series has already addressed most technical concerns, with only this high-level design question remaining unresolved. The discussion may lead to either a revision of this final patch or its removal from the series.
