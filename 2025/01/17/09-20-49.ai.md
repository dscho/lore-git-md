This is part 2 of a 5-patch series continuing the `the_repository` removal effort, specifically targeting `pack-write.c` functionality. The patch converts `index_pack_lockfile()` to take an explicit `struct repository*` parameter instead of using the `the_repository` global.

The change is mechanical - the function signature and all callers are updated to pass `the_repository` explicitly. The function now uses `r->hash_algo` instead of `the_hash_algo` and `repo_get_object_directory(r)` instead of the repository-global version. Callers in `builtin/receive-pack.c` and `fetch-pack.c` are updated to pass through `the_repository`, maintaining current behavior while bubbling up the global usage to higher layers.

This follows the series' established pattern of incremental conversion, where lower-level functions are made repository-aware first, with the understanding that callers will be converted later. The commit message acknowledges this as a temporary solution that preserves compatibility while moving toward the long-term goal of eliminating global repository access.

The patch-specific discussion from earlier in the thread noted that the original commit message incorrectly mentioned hash algorithm considerations when this change was purely about repository context passing. This version appears to have corrected that documentation issue while maintaining the technical changes.
