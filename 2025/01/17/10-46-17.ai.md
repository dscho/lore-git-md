This is the 5th patch in a 6-part series introducing OS version capability to Git's protocol. It implements the core functionality for advertising OS versions between clients and servers, building on the refactoring work from earlier patches.

The patch adds:
- A new `transfer.advertiseOSVersion` config (default true) to control whether OS version information is shared
- Protocol documentation specifying ASCII-only constraints for the `os-version` capability
- Implementation in `connect.c` and `serve.c` to advertise the capability when enabled
- Windows-specific test handling due to Git's fake `uname(2)` implementation
- New `os_version()` and `os_version_sanitized()` functions in version.c that reuse the refactored `get_uname_info()`
- Test updates in `t/t5555-http-smart-common.sh` and `t/t5701-git-serve.sh` to verify the capability

Key technical details:
- Uses the `sysname` field from `uname(2)` (e.g. "Linux", "Windows")
- Applies the same ASCII sanitization as user-agent strings via `redact_non_printables()`
- Windows tests are disabled rather than adding test-tool complexity
- The implementation reuses the series' earlier refactoring of system info gathering
- Follows the same pattern as existing capabilities like `agent`

The patch demonstrates the series' value by showing how the foundational refactorings enable clean addition of new protocol capabilities while maintaining security and cross-platform compatibility.
