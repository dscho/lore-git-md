This is a bugfix addressing a sparc64-specific SIGBUS crash in `git unpack-objects`. The issue occurs when writing to a pack header through a cast struct pointer, which fails due to alignment constraints on sparc64 when compiled with clang. Jeff King provides a minimal reproduction recipe and analyzes the root cause: the code assumes alignment when writing to a `struct pack_header` via a cast from an unaligned `unsigned char` buffer.

The proposed fix replaces the struct-based writes with direct buffer manipulation using `put_be32()`, avoiding alignment assumptions. The patch touches `builtin/unpack-objects.c`, modifying the `--pack_header` parsing logic to write header fields sequentially into the buffer rather than through a struct. King notes the same fix may be needed in `index-pack` as well, though that's not included in this initial patch.

The thread context shows this is a platform-specific issue (sparc64 with clang) that manifests during `git pull` operations. While the reporter found an overalignment workaround, King's solution addresses the root cause more cleanly by avoiding struct-based access entirely. The patch appears well-reasoned, replacing a potentially problematic pattern that has existed for years but only recently surfaced on this particular platform.
