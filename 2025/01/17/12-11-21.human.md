Bugfix addressing a sparc64-specific SIGBUS crash during `git pull` when compiled with clang. Jeff King responds to a bug report about alignment issues in `unpack-objects.c` where writing to a pack header through a cast struct triggers crashes on sparc64 systems.

The email provides a minimal reproduction recipe involving `git repack` and manual pack header manipulation. King analyzes the root cause: the code writes to a static buffer through a struct pointer without proper alignment guarantees, which has worked historically but fails on sparc64 with clang. He proposes switching from direct struct access to using byte-by-byte `put_be32()` writes, which avoids alignment assumptions.

The fix would need to be mirrored in `index-pack.c` as well. While this appears to be a legitimate platform-specific bug, it's notable that the issue has existed for years without surfacing until now, suggesting the sparc64/clang combination exposes a latent alignment sensitivity in Git's pack handling code.
