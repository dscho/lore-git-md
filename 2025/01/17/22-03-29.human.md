Refactoring patch in the hash algorithm unification series, focusing on checkpoint initialization safety.

This is the 7th patch in an 8-part series by Taylor Blau that improves how Git handles hash algorithm checkpoints during file operations. The change introduces a new `hashfile_checkpoint_init()` function to ensure hashfiles and their checkpoints always use matching hash implementations, preventing crashes that could occur when they got out of sync.

The patch modifies three key areas:
1. Adds the new initialization function in csum-file.c that properly sets up the checkpoint's hash context
2. Updates fast-import.c to use the safer initialization method
3. Adjusts bulk-checkin.c to properly sequence its checkpoint setup

The changes are particularly careful about the bulk-checkin case, where initialization needs to happen after the stream is prepared but before writing begins. The patch builds on earlier fixes for segfaults and incorporates feedback from Patrick Steinhardt. It's a focused, well-explained change that continues the series' trend of making hash operations more robust while reducing direct access to unsafe hash variants.
