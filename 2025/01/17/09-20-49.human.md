This is part 2 of a 5-patch series continuing the `the_repository` removal effort, focusing on pack-writing functionality. The patch converts `index_pack_lockfile()` to take an explicit `struct repository*` parameter instead of relying on the global `the_repository` variable.

The change is mechanical but important - it bubbles up the repository context requirement to callers in `receive-pack` and `fetch-pack`, which currently just use `the_repository` as a temporary measure. The commit message acknowledges this as an incremental step that maintains compatibility while moving toward the long-term goal of eliminating global state.

The patch follows the series' established pattern of focused, file-by-file refactoring. While simple in implementation (just adding a repository parameter and updating callers), it's part of a larger architectural improvement to make Git's internals more explicit about their dependencies. The changes touch core pack-writing infrastructure but shouldn't affect behavior or performance.

This version incorporates feedback from the initial submission, where Junio Hamano noted the commit message incorrectly mentioned hash algorithm considerations when the change was purely about repository context. The current version keeps the scope clean and well-defined.
