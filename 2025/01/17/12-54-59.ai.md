This is the first patch in a 3-part series addressing a sparc64-specific SIGBUS crash in Git's pack handling. The patch refactors duplicated pack header parsing code from `index-pack` and `unpack-objects` into a new shared function `parse_pack_header_option()` in packfile.c.

The change centralizes the logic for handling the internal `--pack_header` option used by receive-pack and fetch. While not fixing the alignment issue directly (that comes in later parts), this refactoring prepares for the solution by:
- Moving the header parsing into a single location
- Maintaining identical behavior between the two commands
- Adding proper error handling (including marking errors for translation)
- Keeping the option identification in the callers for flexibility

The patch touches four files, with the new function declared in packfile.h and implemented in packfile.c, while removing duplicate code from both builtin commands. The implementation still uses the problematic struct-based writes (to be fixed in subsequent patches), but the refactoring makes those fixes easier to apply consistently.

Technical details for future reference:
- New `parse_pack_header_option()` handles signature, version, and entry count parsing
- Callers remain responsible for option detection and error reporting
- Both commands now use identical error handling (translated messages)
- Input validation remains strict (comma-separated version,entry format)
- Output buffer and length are passed through to the helper function

This represents the first step in a comprehensive solution that will ultimately replace the alignment-sensitive struct writes with safer byte operations.
