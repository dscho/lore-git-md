Test infrastructure patch for hash algorithm refactoring series.

This is the first patch in brian m. carlson's 8-part series refactoring Git's hash algorithm handling to eliminate separate "unsafe" variants of hash operations. Taylor Blau contributes this test helper implementation that will be used to verify the unsafe SHA-1 operations during the transition.

The patch adds a new `sha1-unsafe` test helper that exercises the unsafe variants of SHA-1 operations (init, update, final) through the existing `cmd_hash_impl()` infrastructure. The implementation:
- Modifies `cmd_hash_impl()` to take an `unsafe` parameter controlling which variant to use
- Adds the new `cmd__sha1_unsafe()` entry point
- Updates test scripts to run both safe and unsafe variants of the tests
- Maintains existing SHA-256 test infrastructure unchanged

Key technical details:
- New function `cmd__sha1_unsafe()` added to test-tool
- Modified `cmd_hash_impl()` signature and implementation to handle unsafe variants
- Test script `test-sha1.sh` updated to run all tests in both safe and unsafe modes
- SHA-256 tests remain unchanged (no unsafe variant needed)

The patch provides essential test coverage for the unsafe algorithm variants that will be unified in later patches of the series. It demonstrates the parallel operation of safe and unsafe variants while maintaining identical output expectations. The test infrastructure will be used to verify the correctness of the core algorithm refactoring in subsequent patches.
