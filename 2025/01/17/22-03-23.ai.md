This is part of the ongoing hash algorithm refactoring series, specifically implementing the unsafe algorithm linking mechanism in csum-file.c. The patch converts direct calls to unsafe hash function variants to use the new `unsafe_hash_algo()` wrapper, which provides access to unsafe implementations through the main algorithm structure.

The changes touch core hashfile operations including initialization, updates, finalization, cloning contexts, and checksum validation. Each unsafe function variant (`unsafe_init_fn`, `unsafe_update_fn`, etc.) is replaced with its standard counterpart, with the unsafe algorithm selected via `f->algop = unsafe_hash_algo(the_hash_algo)`. This maintains the unsafe behavior while eliminating the separate unsafe function pointers.

Key technical details include:
- `hashfile` struct now uses unsafe algorithm variants through the unified `algop` pointer
- All hashfile operations (write, flush, finalize) use the standard function names
- Checksum validation in `hashfile_checksum_valid()` also switches to unsafe variants
- The changes affect low-level file hashing operations while maintaining identical behavior

This patch builds on Taylor Blau's earlier work in the series and implements Jeff King's suggested approach for unsafe algorithm linking. It represents a mechanical conversion of csum-file.c to the new unsafe algorithm access pattern, with no functional changes intended. The patch continues the series' goal of eliminating separate unsafe function variants while maintaining backward compatibility.
