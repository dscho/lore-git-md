This is a feature patch series introducing OS version capability to Git's protocol, building on previous discussion and iteration. The series has reached technical resolution with maintainer approval, representing a compromise between minimal system-provided strings and configurable version reporting.

The 6-patch series (v2) from Usman Akinyemi adds an `os-version` capability to Git's v2 protocol, allowing clients and servers to exchange operating system information. Key components include:

1. A new `transfer.advertiseOSVersion` config (default true) to disable the feature for privacy
2. A sanitization function (redact_non_printables()) that strips non-ASCII characters
3. The `osversion.command` config option (suggested by Randall S. Becker) allowing custom command output for version strings
4. Windows-specific handling where tests are disabled due to Git's fake uname(2) implementation

The implementation uses `uname(2)` by default (just the sysname field), with the command option providing flexibility for platforms like NonStop. The sanitization handles ASCII range 33-126, stripping CR/LF consistently. Tests cover both default and custom command scenarios, with careful file naming and setup to avoid side effects.

This version incorporates feedback from v1, including documentation clarity improvements, test restructuring, and commit message fixes. The thread history shows Junio Hamano accepted this as sufficient, explicitly rejecting additional format options while leaving room for future evolution based on real-world use.
