This is a test infrastructure patch that's part of the series standardizing help text output behavior across Git commands. The patch introduces an optional strict mode for t0012-help.sh to verify that `-h` help output goes to stdout rather than stderr.

The test script previously accepted help output on either stdout or stderr, but the long-term goal is to enforce stdout-only output. This patch adds a `GIT_TEST_HELP_MUST_BE_STDOUT` flag that, when set, makes the test verify two things: that the help text appears on stdout (via `test_grep usage output) and that stderr is empty (via `test_must_be_empty err`). When unset, it maintains the old permissive behavior of checking either stream.

The change affects how builtin commands are tested in a subdirectory context, using `git -C sub` to ensure the test works regardless of where it's run from. The exit code 129 check remains unchanged, maintaining backward compatibility. This transitional approach allows gradual conversion of commands while providing a tool for developers working on the standardization effort to identify commands still outputting to stderr.

The patch is signed off by both Jeff King (original author) and Junio Hamano (who appears to be forwarding it), indicating it's been reviewed and is part of the final v5 series. The implementation matches the thread's established direction of standardizing on stdout while maintaining compatibility during transition.
