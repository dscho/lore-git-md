This is part 4 of an 8-part refactoring series to unify Git's hash algorithm handling by eliminating separate "unsafe" variants of hash operations. The patch introduces a core infrastructure change with a new `unsafe_hash_algo()` function.

The key problem being solved is the current cumbersome approach where callers must manually choose between safe and unsafe hash variants (like `init_fn` vs `unsafe_init_fn`), which is error-prone. The new mechanism allows a hash algorithm to reference its unsafe variant via a pointer in `struct git_hash_algo`, letting callers simply switch algorithms once rather than remembering to use unsafe variants at each call site.

The implementation adds:
- An `unsafe` pointer field to `struct git_hash_algo`
- The new `unsafe_hash_algo()` lookup function
- A concrete `sha1_unsafe_algo` instance
- Updates to `hash_algo_by_ptr()` to handle unsafe variants

This is a well-motivated change that simplifies the API while making it harder to accidentally mix safe and unsafe operations. The patch builds on prior discussion (with credit to Jeff King for the suggestion) and fits cleanly into the broader series' goal of hash algorithm unification. The changes are focused and the commit message clearly explains both the problem and solution.
