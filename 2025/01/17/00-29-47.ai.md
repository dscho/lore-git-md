This is a documentation patch that expands Git's CLI conventions guide to explicitly state that command-line options override configuration variables. Junio C Hamano proposes adding a new section to `gitcli.txt` while acknowledging this might already be common knowledge among experienced contributors.

The patch adds clear examples showing how command-line flags like `-u` for `git tag` override corresponding configs like `user.signingKey`. This formalizes what has been an unwritten convention in Git's behavior for 20 years. The change emerges from a thread about documenting negatable `git grep` options, where the maintainer recognized a broader documentation gap about option precedence rules.

The patch follows Git's established documentation style, placing the new section near existing content about negated options. While functionally trivial (as it only documents existing behavior), it serves as an important reference point for both new contributors and command authors. The maintainer expresses some uncertainty about whether this might duplicate existing documentation, suggesting this could be seen as either filling a gap or making implicit knowledge more accessible.
