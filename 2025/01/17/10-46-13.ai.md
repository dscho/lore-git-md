Refactoring patch for string sanitization in preparation for OS version capability.

This is the first patch in a 6-part series introducing OS version reporting to Git's protocol. It extracts the non-printable character sanitization logic from `git_user_agent_sanitized()` into a new `redact_non_printables()` function. The refactoring serves two purposes: making the sanitization reusable for the upcoming OS version feature, and improving the existing code by using `strbuf_detach()` to properly handle memory management.

The new function replaces ASCII characters outside the printable range (33-126) with dots, while also trimming whitespace. The implementation remains static for now since it's only used locally in version.c. The patch includes a TODO comment noting a potential optimization for handling consecutive non-printable characters, though this doesn't affect current functionality.

This change is purely internal refactoring with no user-visible behavior changes. It's part of the larger effort to add OS version reporting capability to Git's protocol, with subsequent patches building on this foundation. The thread context shows this technical approach has already received maintainer approval, with the sanitization behavior being one of the settled aspects of the series.
