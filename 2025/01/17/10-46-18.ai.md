This is the final patch in Usman Akinyemi's series adding OS version capability to Git's protocol, implementing the configurable command execution feature that was a key point of discussion throughout the thread.

The patch introduces `osversion.command` configuration to override the default uname(2)-based OS version string with custom command output, addressing Randall S. Becker's NonStop platform use case. When set, Git will execute the specified command and use its output (after sanitization) as the `os-version` capability value. The implementation includes:

1. New `osversion.command` config documented in transfer.txt, with clear relationship to `transfer.advertiseOSVersion`
2. Protocol documentation updates clarifying ASCII constraints and command output handling
3. Test cases in t5555 and t5701 verifying command-based version string behavior
4. Core implementation in version.c with:
   - `fill_os_version_command()` for config and argument parsing
   - `capture_os_version()` to execute and capture command output
   - Fallback to uname(2) if command fails or isn't configured
   - Proper memory management via strbuf_detach()

The patch maintains Windows compatibility by keeping test exclusions for that platform. It represents the resolution of earlier maintainer concerns about command execution, now accepted as necessary for uncommon platforms while defaulting to simpler uname(2) output for most systems. The implementation follows Git's pattern of configurable behavior with secure defaults, while the test coverage ensures both the new feature and fallback paths work as intended.
