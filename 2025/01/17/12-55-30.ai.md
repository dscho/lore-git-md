Bugfix patch addressing sparc64 alignment issues in pack header handling. This is the second patch in Jeff King's series fixing SIGBUS crashes during pack operations on sparc64 when compiled with clang.

The patch replaces direct struct-based memory writes with alignment-safe `put_be32()` operations in the newly introduced `parse_pack_header_option()` function. Instead of casting the buffer to a `struct pack_header` and assigning fields directly (which caused unaligned access crashes), it now writes each 32-bit value byte-by-byte using the endian-safe helper. The function maintains identical behavior while being portable.

Key technical details:
- Changes are confined to `packfile.c`
- Replaces 3 struct field assignments with `put_be32()` calls
- Manually tracks buffer position with `hdr` pointer arithmetic
- Updates length calculation to match new write pattern
- Preserves all existing validation of input format (comma-separated version,entry count)

The patch builds on the foundation from PATCH 1/3 which centralized the header parsing logic. While this should resolve the immediate SIGBUS from writes, King notes uncertainty about potential remaining issues with unaligned reads in the same code paths. The change demonstrates careful attention to platform-specific memory access requirements while maintaining clean cross-platform behavior.
