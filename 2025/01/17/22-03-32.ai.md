This is the final patch in a refactoring series that eliminates separate "unsafe" hash algorithm variants in favor of a unified `unsafe_hash_algo()` mechanism. The patch removes the now-unused scaffolding for the old unsafe function variants from both `hash.h` and `object-file.c`, completing the transition where all callers now use the new indirection pattern.

The changes delete 15-line blocks of function pointer declarations from `struct git_hash_algo` in hash.h, and remove corresponding initialization of those pointers in `hash_algos[]` for the unknown, SHA-1, and SHA-256 algorithms. The removal is safe because all callers have been converted to use `unsafe_hash_algo(the_hash_algo)->init_fn()` style access instead of directly calling the unsafe variants.

This cleanup represents the culmination of the series' architectural goal to reduce API surface area while preventing accidental mixing of safe/unsafe operations. The changes maintain backward compatibility while simplifying future addition of new hash algorithms. The test infrastructure from earlier patches ensures behavioral parity between the old and new approaches.

Key technical details:
- Removes all `unsafe_*_fn` function pointer fields from `struct git_hash_algo`
- Deletes initialization of unsafe variants in `hash_algos[]` array
- Preserves the `unsafe` pointer field that links to alternate implementations
- Follows through on Jeff King's suggested approach for algorithm linking
- Builds on Taylor Blau's earlier work in the series
- Completes the transition to unified unsafe algorithm access pattern

The patch demonstrates the series' success in eliminating conditional code paths while maintaining the same functionality, as evidenced by the straightforward removal of now-unused infrastructure.
