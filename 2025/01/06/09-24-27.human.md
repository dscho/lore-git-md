This is the final patch in a series hardening Git's object file handling against race conditions, specifically addressing a corruption scenario where destination files vanish between collision checks and linking operations.

The patch implements a retry mechanism with a 5-attempt limit when a destination file disappears during the collision check process. It introduces a new `CHECK_COLLISION_DEST_VANISHED` return code (-2) to distinguish this case from other errors. The solution carefully balances between being too pessimistic (which would hurt performance) and too optimistic (which could allow corruption in hash collision cases).

The implementation modifies `object-file.c` to retry the linking operation when the destination file vanishes, while maintaining all existing safety checks. The 5-retry limit prevents infinite loops while still handling the common case where the file disappearance is transient. This builds on previous discussion and refinements from Jeff King and Junio Hamano, with the commit message clearly explaining both the problem and solution.
