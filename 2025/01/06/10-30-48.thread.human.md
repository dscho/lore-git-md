This thread documents the implementation of OS version reporting in Git's protocol, now merged after several iterations. The feature extends the existing `agent` capability string to include OS information (like "package/version os") rather than introducing a separate capability. The implementation handles platform differences (notably Windows) and includes comprehensive test coverage in t5701-git-serve.sh.

Junio Hamano approved the final v5 series after refinements that removed a proposed `transfer.advertiseOSVersion` config in favor of using `GIT_USER_AGENT` for privacy control. The series also improved test isolation and added string sanitization utilities. Post-merge, Usman Akinyemi raised concerns about privacy control ergonomics, particularly the inability to fully suppress the agent capability by setting an empty string.

In the latest exchange, Junio flags a protocol safety issue regarding whitespace in the capability string format. While praising the overall implementation quality, he suggests using dashes or dots instead of spaces to avoid potential parsing issues in the whitespace-separated protocol v1 capability list. He also questions relaxing the documentation's restrictions on spaces in the agent string, preferring to maintain existing security constraints. This represents final polishing of an accepted feature, showing the project's attention to backward compatibility and security details.
