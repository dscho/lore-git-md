This thread discusses a proposal to add OS version reporting capability to Git's protocol v2, similar to the existing 'agent' capability for Git version reporting. The series, contributed by an Outreachy participant mentored by Christian Couder, consists of four patches that refactor version string handling, add OS info utilities, implement protocol capability plumbing, and add configuration options.

Junio Hamano has been providing detailed feedback on the implementation. After earlier suggestions about better organizing the patch series (particularly separating refactoring from new functionality in patch 2/4), his latest review focuses on patch 3/4's documentation and implementation details. He questions some placeholder variables in the capability description and suggests more precise wording about ASCII character handling. Junio also raises an interesting consideration about whether there should be guidelines or a registry for canonical OS version names to ensure consistent reporting across systems.

The implementation currently has Windows support disabled pending resolution of uname behavior questions, and there are ongoing discussions about privacy implications of the default-enabled reporting. The series includes comprehensive test coverage and builds on prior work by Christian Couder, with the mentoring relationship helping guide both technical and organizational aspects of the contribution. Junio's feedback continues to shape the patches toward a form that could be suitable for inclusion, focusing now on refining documentation clarity after earlier structural suggestions.
