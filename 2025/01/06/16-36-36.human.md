This is a feature proposal in the ongoing discussion about Git protocol enhancements for remote repository queries. Theodore Ts'o builds on Junio Hamano's suggestion about custom capabilities by proposing a specific use case from kernel testing infrastructure.

The core need is for a lightweight way to check if a specific commit exists in a remote repository and which branches/tags reference it, without requiring a full fetch. This would help Theodore's kernel testing tool (`gce-xfstests`) provide immediate feedback about invalid commit IDs before launching expensive cloud VMs, particularly useful in low-bandwidth scenarios (airplanes, cruise ships).

The proposal highlights a real-world pain point where current solutions (full fetches) are too heavyweight for quick validation. While the email doesn't propose a concrete implementation, it suggests extending remote query capabilities could benefit more than just the original triangular workflow use case. The request comes from an experienced maintainer (Theodore maintains ext4 filesystem) with clear operational requirements, making it a serious proposal worth considering alongside Junio's protocol ideas.
