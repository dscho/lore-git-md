This is a feature proposal introducing OS version reporting capabilities to Git's protocol, part of an Outreachy internship project. It's a series of 4 patches that would allow Git clients to optionally share their operating system information with servers during protocol exchanges.

The proposal adds a new 'os-version' capability to Git's v2 protocol, similar to the existing 'agent' capability that shares Git version info. The default behavior sends just the basic OS name (like "Linux"), sanitized for safety. The series includes privacy-conscious design with a `transfer.advertiseOSVersion` config option (enabled by default but can be disabled) and flexibility through an `osversion.command` option for custom output. A future `osversion.format` option is also planned for more structured output.

The motivation centers on debugging, security warnings, and performance optimization scenarios where servers could tailor responses based on client OS information. The implementation builds on existing version-reporting infrastructure, with careful consideration for Windows platform differences and privacy implications.
