This is a bugfix for the credential-cache helper, addressing an issue with capability handling. 

The patch corrects the credential-cache daemon to only respond with the 'authtype' capability if it was actually requested by the client. Previously, it would always include this capability in responses regardless of whether the client asked for it, which violated the protocol where response capabilities should be a subset of request capabilities.

The change is straightforward - it adds a check for the CREDENTIAL_OP_RESPONSE flag before including the authtype capability in responses. The patch also updates related credential fields (authtype and credential) to use the same capability check for consistency.

A new test case is added to verify this behavior, checking that the helper only provides authtype information when the request includes the capability. The patch appears well-contained and focused changes, with clear test coverage for the fixed behavior. This is version 2 of the patch, with some test description improvements from the initial version.
