This is a cover letter for a series of patches announcing the removal of long-deprecated remote configuration mechanisms, part of Git's ongoing cleanup of legacy features.

Patrick Steinhardt proposes removing two obsolete ways to configure remotes: the `.git/branches/` directory (deprecated since 2005) and `.git/remotes/` directory (deprecated since 2011). Both were replaced by config-based remotes long ago and are unlikely to be in use today. The series announces these for removal in Git 3.0 and establishes infrastructure to test such breaking changes.

The series includes 5 patches:
1. Adds build infrastructure flag for deprecated features
2-3. Adjust CI jobs to test deprecation builds
4. Removes the `pack-redundant` subcommand (another breaking change)
5. Announces the removal of the legacy remote configuration directories

The changes since v1 are minor tweaks to deprecation notices and commit messages. The series appears well-motivated and carefully prepared, with thorough documentation updates and test coverage. This is part of Git's broader effort to clean up technical debt while providing clear migration paths for users.
