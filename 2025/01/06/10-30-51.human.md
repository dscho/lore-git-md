This is part 3 of a 4-patch series introducing a new protocol v2 capability for exchanging OS version information between Git clients and servers, similar to the existing 'agent' capability.

The patch implements the core functionality for advertising OS versions in protocol v2 communications. It adds a new `transfer.advertiseOSVersion` config option (defaulting to true) that controls whether clients and servers will exchange OS information derived from the `uname(2)` system call's 'sysname' field (e.g., "Linux" or "Windows"). The implementation includes proper string sanitization to remove non-printable characters.

Notable technical aspects include:
- New functions in `version.c` for getting and sanitizing OS version strings
- Protocol plumbing in `connect.c` and `serve.c` to handle the capability
- Test updates to verify the capability advertisement
- Special handling for Windows where `uname` behavior differs between command-line and system calls

The patch appears well-structured with thorough test coverage, though Windows support is temporarily disabled in tests due to platform-specific quirks. This is part of an Outreachy project mentored by Christian Couder, building on prior version-related work in Git. The implementation seems ready for review, with the main open question being whether the default-enabled configuration is appropriate from a privacy perspective.
