This is the fourth and final patch in the series implementing the OS version capability for Git's protocol v2, adding configurable command-based version string generation.

The patch introduces a new `osversion.command` configuration option that allows users to specify a custom command whose output will be used as the OS version string exchanged between clients and servers, rather than just the basic system name from `uname`. The implementation:
- Adds the new config option documentation in `transfer.txt` and updates protocol documentation
- Implements command execution via `capture_command()` with proper error handling
- Falls back to the original `uname` behavior if the command fails or isn't set
- Includes comprehensive tests for both HTTP and git:// protocols
- Maintains the existing privacy safeguards (non-printable character redaction)

Key technical details:
- New `fill_os_version_command()` parses and validates the config
- `capture_os_version()` executes the command and captures output
- Tests verify behavior with `uname -srvm` as a sample command
- Windows tests remain disabled pending uname resolution
- Builds on prior refactoring of version utilities

The patch completes the series' functionality while maintaining all prior constraints. It provides server operators more flexibility in what version information they exchange while preserving the privacy-focused design (default sanitization, explicit opt-in). The implementation appears thorough with good test coverage and proper memory management.

This concludes the initial implementation of the OS version capability, though as noted in earlier patches, Windows support and some design questions around default enablement remain open for discussion.
