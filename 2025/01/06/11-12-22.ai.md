Test fix addressing SIGPIPE propagation in submodule status tests. This email from Patrick Steinhardt responds to Jeff King's analysis of a flaky test in t7422 that verifies SIGPIPE handling in `git submodule status --recursive`. The test intermittently fails because buffered output can prevent the SIGPIPE signal from being properly detected.

Jeff demonstrated the issue can be reliably reproduced by forcing a delay before the pipe consumer (grep) runs, and proposed a solution using a Perl script to pre-fill the pipe buffer with 128KB of data before running the submodule command. Patrick agrees with the approach but notes the grep for "X/S" is important to verify SIGPIPE occurs during subprocess execution rather than the parent process. They discuss implementation details around using Perl vs test_seq and whether to keep the grep verification.

Key technical points:
- The fix involves pre-filling the pipe buffer to force blocking writes
- Uses Perl to generate filler data (33000 "foo" lines)
- Retains grep for "X/S" to verify subprocess SIGPIPE specifically
- Avoids test_seq due to shell function limitations with SIGPIPE
- Removes the debug sleep once the solution is verified
