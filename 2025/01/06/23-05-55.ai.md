This is a bugfix patch for the credential-cache helper's capability handling, addressing protocol compliance issues identified in previous discussion. The patch is version 3 of a series that has been through technical review.

The key changes in v3:
- Corrects the credential-cache daemon to only output authtype and credential fields when the request includes the authtype capability (using CREDENTIAL_OP_RESPONSE flag)
- Adds a new test case in t/lib-credential.sh that verifies this conditional output behavior
- Reverts the incorrect capability advertisement change from v2 while maintaining proper field output logic

The patch aligns with brian m. carlson's protocol clarification that capability advertisement should be unconditional while field output must be conditional. The test addition helps verify both aspects of protocol compliance, addressing the coverage gap noted in previous discussion.

Technical changes are focused in:
- builtin/credential-cache--daemon.c (modified condition checks)
- t/lib-credential.sh (new test case)

The patch appears to fully resolve the protocol compliance issue while maintaining backward compatibility. The test coverage now includes both capability advertisement and conditional field output scenarios.
