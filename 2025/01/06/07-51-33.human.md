Build system patch establishing infrastructure for breaking changes. This is the first of five patches in a series removing long-obsolete remote configuration mechanisms (deprecated since 2005-2011) in preparation for Git 3.0.

The patch introduces a new `WITH_BREAKING_CHANGES` compile-time option that will control whether upcoming breaking changes are enabled. This implements the pattern established in the project's `BreakingChanges.txt` document, which requires such switches for any backward-incompatible modifications. The change wires up the option across all build systems (Makefile, CMake, Meson) and adds a test prerequisite to check its status.

The implementation looks thorough, touching all relevant build system files consistently. As the first patch in the series, it lays groundwork for the actual feature removals that follow. The commit message clearly connects this to the broader breaking changes policy and the specific deprecations being removed in this series.
