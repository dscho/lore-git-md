This is a CI/build system patch that repurposes an existing test job to verify breaking changes infrastructure. It's part of the ongoing series removing long-deprecated features while establishing patterns for handling breaking changes.

The patch renames the "linux-gcc" CI job to "linux-breaking-changes" and enhances it to test the new `WITH_BREAKING_CHANGES` compile-time flag. This job was already testing the future default branch name ("main" instead of "master"), making it a natural fit for additional forward-looking tests. The changes are mechanical updates to both GitHub Actions and GitLab CI configurations, plus the shared `ci/run-build-and-tests.sh` script that sets up the test environment.

Key technical details include the addition of `WITH_BREAKING_CHANGES=YesPlease` environment variable and maintaining the existing `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME=main` setting. The changes affect three files: `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`.

This follows the series' pattern of gating breaking changes behind build options while ensuring they're properly tested. The job renaming makes its purpose clearer while maintaining the same basic configuration (GCC compiler, Ubuntu 20.04 image). The patch appears straightforward with no obvious technical issues, cleanly integrating with the broader deprecation effort.
