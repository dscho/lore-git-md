This is a code review comment on patch 1/4 of the "Protocol v2 OS version capability" series. Eric Sunshine points out a discrepancy between the commit message and the actual code changes in Usman Akinyemi's patch.

The patch refactors string sanitization code from `git_user_agent_sanitized()` into a new `redact_non_printables()` function, with some claimed improvements. However, Eric notes that two of the stated improvements (using `size_t` for the loop counter and moving its declaration inside the `for` statement) were already present in the original code, making the commit message inaccurate.

The actual changes in the patch are:
1. Extracting the sanitization logic into a separate function
2. Replacing direct buffer access with `strbuf_detach()`

This appears to be a minor documentation issue in an otherwise straightforward refactoring patch that's part of a larger effort to add OS version reporting to Git's protocol. The series has been getting active review from both the maintainer (Junio Hamano) and mentor (Christian Couder), with this particular comment coming from another experienced contributor. The feedback suggests the patch may need a minor revision to align the commit message with the actual changes.
