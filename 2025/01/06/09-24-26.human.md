Bugfix patch refining Git's object collision detection. This is the second in a 3-part series hardening Git against filesystem race conditions during object writing.

The patch narrows the scope of a previous fix (0ad3d65652) that broadly ignored "file not found" errors during collision checks. Patrick Steinhardt points out that while vanishing destination files can legitimately occur due to races, source files (temporary objects Git just created) should never disappear - if they do, it indicates a real problem. The change makes Git properly report ENOENT errors for source files while maintaining the race-tolerant handling for destinations.

This is a focused correction to the collision detection logic in `object-file.c`, modifying just 3 lines to remove the special ENOENT case for source files. The change aligns with the series' overall goal of making object writing more robust against filesystem races while avoiding over-broad error suppression. The patch follows thorough review discussion and appears well-justified, with the maintainers having already approved the general approach in prior thread discussion.
