This is a feature proposal and implementation for a new 'os-version' capability in Git's protocol v2, part of an Outreachy project. The patch series introduces configurable OS version reporting between Git clients and servers, with privacy controls.

The proposal adds a new capability that lets clients and servers exchange operating system information, similar to the existing 'agent' capability for Git versions. The default behavior sends just the OS name (like "Linux") sanitized similarly to version strings. Two config options are implemented: `transfer.advertiseOSVersion` (default true) to disable the feature entirely, and `osversion.command` to customize what's sent. A future `osversion.format` option is also planned for more structured output.

The implementation involves refactoring existing version-handling code (patches 1-2), adding the capability plumbing (patch 3), and implementing the config options (patch 4). Windows support is currently disabled due to differences between `uname` implementations. The series builds on prior work by Christian Couder, with thorough test coverage across multiple protocol tests.

Key technical details include:
- New functions in version.c for OS info handling (get_uname_info, redact_non_printables)
- Protocol v2 capability advertisement in connect.c and serve.c
- Multiple test additions in t5555 (HTTP) and t5701 (git://)
- Documentation updates for both config and protocol specs
- Windows-specific handling noted in patch 3's message

Potential discussion points include:
- The privacy implications of OS reporting (though opt-out is provided)
- Whether the %() syntax is best for the planned format option
- Windows compatibility questions around uname behavior
- Whether this capability warrants being enabled by default
