Bugfix for fetch's set-head advice message. Junio C Hamano is queuing Bence Ferdinandy's patch that corrects the format of a configuration suggestion in Git's fetch warning message. The fix addresses an issue where the advice text incorrectly showed how to configure `remote.<name>.followRemoteHEAD` - it previously suggested using the branch name directly rather than the proper `warn-if-not-branch-%s` syntax.

This is a straightforward documentation correction that ensures users following the advice will enter valid configuration. The change is minimal (just two lines in `builtin/fetch.c`) and maintains all existing functionality while fixing the misleading message. Teng Long originally reported the incorrect format, and the patch has now been reviewed and accepted for inclusion.

The fix is part of ongoing work around the `followRemoteHEAD` configuration, though this particular change is narrowly focused on making the advice text technically accurate rather than modifying any underlying behavior. Users who see warnings about remote HEAD changes will now get correct instructions for configuring the warning behavior.
