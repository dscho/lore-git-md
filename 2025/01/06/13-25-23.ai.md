CI/build system patch refining the test matrix consolidation for breaking changes infrastructure.

This email from Christian Couder provides feedback on Patrick Steinhardt's patch that merges the "linux-gcc-default" CI job into "linux-gcc". While agreeing with the overall goal of simplifying the test matrix, Christian points out two clarifications needed in the commit message: first, that the change makes "linux-gcc" use the distribution's default GCC version (rather than gcc-8), and second, that it removes the "linux-gcc-default" job entirely.

Christian also notes an unmentioned difference between the jobs - "linux-gcc" uses ubuntu-20.04 while "linux-gcc-default" used ubuntu-latest - suggesting this platform distinction should be documented in the commit message. The changes affect three files: `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/lib.sh`, with the diff showing the removal of the `cc_package: gcc-8` line and the entire "linux-gcc-default" job definition.

This feedback comes as part of the broader breaking changes infrastructure work, where the CI matrix is being reorganized to eventually include a dedicated "linux-breaking-changes" job. The exchange demonstrates careful attention to detail in documenting CI configuration changes, even when the functional impact is minor.
