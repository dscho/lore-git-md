This is a discussion about deprecation warning strategy in the ongoing breaking changes series.

Junio Hamano responds to Christian Couder's suggestion about improving the deprecation warnings for the soon-to-be-removed `branches/` and `remotes/` directory-based remote configuration methods. Christian had noted that the `pack-redundant` removal (from the previous patch) used a more aggressive warning strategy (requiring an explicit `--i-still-use-this` flag) and suggested applying similar visibility to these directory-based methods.

Junio strongly agrees with this approach, calling it "excellent" and "prudent" to prepare users despite the long deprecation period (14-20 years). He confirms the implementation would be contained within remote.c and playfully invites patches ("Patches welcome ;-)") to implement the suggested warning system.

The exchange shows consensus forming around making the transition more user-friendly through visible warnings, following the successful pattern established with `pack-redundant`. This would represent an enhancement to the current series' approach of just documenting the changes. The implementation would need to modify remote.c to add warning messages, potentially with configuration to disable them, though the exact mechanism isn't specified here.
