Bugfix discussion for credential-cache capability handling. Brian Carlson responds to M Hickford's patch that aimed to make the credential-cache helper only respond with authtype capability when requested. Carlson disagrees with the core premise, stating that helpers should always advertise their capabilities regardless of the request, as this is necessary for Git to properly handle credential storage. 

The response notes that while the first part of the patch (changing capability advertisement behavior) is incorrect, the second part (conditionally outputting authtype and credential fields based on CREDENTIAL_OP_RESPONSE) may be valid. The discussion centers on protocol compliance and backward compatibility in the credential helper system.

This is a technical discussion about the proper implementation of credential helper capabilities, with Carlson providing authoritative feedback on the protocol requirements. The exchange suggests the original patch needs revision to maintain the correct capability advertisement behavior while potentially keeping some of the field output changes.
