This is part of Patrick Steinhardt's CI modernization series (v2), specifically focusing on GitHub Actions job configuration cleanup. The patch simplifies how Linux job names are derived from container image names in the GitHub CI workflow.

The key change replaces explicit `distro` field declarations with automatic derivation from the container image name (with colons converted to dashes), matching GitLab CI's approach. Special cases are handled for:
- The "linux32" job which uses a different naming convention (now using `i386/ubuntu-*`)
- Untagged "alpine" and "fedora" images which now explicitly use ":latest"

The changes touch GitHub workflow definitions, dependency installation scripts, and CI library code, standardizing on `CI_JOB_IMAGE` as the source of truth. This continues the series' theme of removing redundant configuration while maintaining all existing functionality, with the distro name now being computed consistently across the CI system.

The patch appears well-contained and follows the established pattern of the series, with clear commit message explanation of the rationale and special cases. It builds on the prior containerization work in the series while further simplifying the CI configuration.
