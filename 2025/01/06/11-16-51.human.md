This is a bugfix patch in Patrick Steinhardt's CI modernization series (v2), specifically addressing a flaky test in the submodule subsystem. The test `t7422.18` checks whether `git submodule status --recursive` properly handles SIGPIPE signals, but was failing intermittently due to buffering issues in the pipe between the submodule command and grep.

The root cause is that grep might terminate the pipe after git-submodule has already exited, due to standard stream buffering. The solution, suggested by Jeff King, uses Perl to pre-fill the pipe buffer with over 128KB of data before running the submodule command, ensuring the pipe blocks on write and reliably triggers SIGPIPE. The patch includes a test modification that previously reproduced the flakiness reliably (using a sleep) to verify the fix works.

This is a well-constructed fix that preserves the test's original intent while making it reliable. It's part of a larger effort to modernize Git's CI infrastructure by eliminating flaky tests, with this being one of the final technical issues resolved in the series before integration.
