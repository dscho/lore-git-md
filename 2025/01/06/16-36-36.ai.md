This is a feature proposal expanding on the triangular workflow discussion, suggesting additional protocol capabilities for commit reachability checking. Theodore Ts'o builds on Junio Hamano's suggestion about custom capabilities by proposing a specific use case from kernel testing infrastructure.

The email introduces a concrete scenario where the current protocol limitations cause real-world pain: the `gce-xfstests` kernel testing framework needs to verify commit reachability before launching expensive cloud VMs, but doing a full fetch is impractical on slow networks. Ts'o describes how users currently get delayed feedback about invalid commit IDs only after VM launch, wasting time and resources.

The proposed enhancement would allow querying two key pieces of information from the server without fetching: (1) whether a specific commit exists in the remote repository, and (2) which ref(s) contain that commit. This goes beyond the original thread's branch existence checks, addressing a related but more general problem of commit reachability verification.

The use case highlights important constraints: the checking needs to happen before VM launch, potentially from a client with limited bandwidth, and the repository in question may not be local. This suggests any solution would need to work through the existing remote protocol rather than requiring local repository access.

This proposal connects to the thread's broader theme of protocol extensions for better remote repository introspection, but introduces new technical requirements around commit-level queries rather than branch existence. It represents a natural evolution of the discussion from branch detection to more general remote repository state interrogation capabilities.
