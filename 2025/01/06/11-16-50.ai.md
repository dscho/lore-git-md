This is a bugfix patch in Patrick Steinhardt's CI modernization series, addressing a MinGW-specific test flakiness. The patch fixes intermittent EBUSY errors in t0060 when tests try to overwrite the git.exe binary in Windows CI environments. The root cause remains unclear (possibly Windows/MinGW file handle retention), but the solution cleanly factors out the binary copying into a shared setup step to avoid the race condition.

The change modifies t0060-path-utils.sh to create a new 'setup runtime prefix' test that handles the binary copy operation once, before the two dependent tests that previously each did their own copy. This eliminates the EBUSY scenario while maintaining test coverage of the runtime prefix functionality. The patch preserves all existing test prerequisites (!VALGRIND,RUNTIME_PREFIX,CAN_EXEC_IN_PWD) and adds them to the new setup step.

This appears to be a well-justified change with a clear problem statement (reproducible CI failures) and minimal surgical fix. The commit message documents both the observed failure mode and the pragmatic solution, though it notes the underlying Windows behavior remains mysterious. As part of the broader CI modernization series that's nearing completion, this patch helps stabilize Windows testing infrastructure.
