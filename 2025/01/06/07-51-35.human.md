This is a CI/build system patch that repurposes an existing test job to also verify breaking changes. It's part of a series removing long-deprecated Git features, where earlier patches introduced a `WITH_BREAKING_CHANGES` compile-time flag.

The patch renames the "linux-gcc" CI job to "linux-breaking-changes" and enhances it to test both the default branch name change (from "master" to "main") and the new breaking changes flag. The changes are mechanical updates to GitHub Actions, GitLab CI, and the shared test runner configuration.

The rationale is that this job was already testing forward-looking changes (the branch name) and wasn't providing unique coverage otherwise, making it a good candidate for also verifying the breaking changes infrastructure. The implementation looks straightforward, simply adding the new flag while preserving the existing branch name test.

This continues the series' pattern of carefully managing backward compatibility while preparing for Git 3.0's removal of long-deprecated features, now with corresponding test coverage for the transition mechanism.
