This is a technical suggestion for improving remote branch detection in CI scripts, continuing the thread about triangular workflows.

Theodore Ts'o responds to Chris Packham's question about checking remote branch existence by sharing a solution from the gce-xfstests project. The approach uses `git ls-remote` with the `--heads` and `--exit-code` flags to cleanly verify branch existence without the output format issues of `rev-parse`. The function first validates the repository URL (appending .git if needed) before checking for the specific branch.

The solution is presented as production-ready, coming from Ts'o's xfstests project, though he notes a limitation in the related commit validation function which doesn't fetch full history to verify SHA hashes. This appears more robust than the current `rev-parse` approach being discussed, though it may have different tradeoffs in terms of network operations versus local reference checks.

The email provides concrete code examples and links to the full implementation, making it easy for the original poster to evaluate whether this approach would work for their triangular workflow needs. It doesn't directly address the '_incoming' branch pattern specifically, but offers a general-purpose branch validation technique that could be adapted.
