This is the final patch in a series hardening Git's object file handling against race conditions, specifically addressing vanishing destination files during collision checks. The patch implements a retry mechanism with a 5-attempt limit when a destination file disappears between the collision check and linking operations. It builds on prior work (commit 0ad3d65652) that fixed races in object collision detection, with refinements from Jeff King's review.

Key changes include:
- Treating missing source files as hard errors (now split into a separate patch per Jeff's suggestion)
- Introducing a `CHECK_COLLISION_DEST_VANISHED` return code (-2)
- Adding retry logic in `finalize_object_file_flags()` with safety limit
- Maintaining careful TOCTOU race mitigation throughout

The solution addresses a serious but rare corruption scenario where destination files vanish mid-operation. The implementation preserves performance optimizations from earlier work while adding necessary safety measures. Reviewers have thoroughly vetted the control flow and error handling, and all parties now agree on the approach. The patch demonstrates Git's meticulous attention to filesystem atomicity in the object storage layer.
