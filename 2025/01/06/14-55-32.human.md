This is a bug report about unexpected behavior in Git's tag signing functionality when using smartcards.

Carlos Maiolino reports that Git appears to bypass the configured `user.signingkey` when the specified GPG key (stored on a smartcard) is unavailable, silently falling back to a different key instead. This contradicts both the documented behavior in `git-tag` manpage and user expectations - Carlos reasonably expects Git should either fail or warn when unable to use the explicitly configured signing key.

The issue was discovered when Carlos had two smartcards connected, causing Git to sign with an unexpected key. Further testing showed the problem also occurs when the smartcard containing the configured key is disconnected entirely. While Jeff King initially suggested checking for config overrides and tracing the command execution (which worked when explicitly passing the key via CLI), the core issue appears to be Git's silent fallback behavior when the configured key is unavailable.

The behavior raises questions about security implications, as silent fallback to a different signing key could lead to unintentional signatures. The thread suggests this may warrant either a behavior change to fail when the specified key is unavailable, or at minimum clearer warnings about the fallback.
