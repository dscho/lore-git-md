This is a bugfix follow-up in the ongoing thread about object name resolution with curly braces. Junio C Hamano reports that the proposed changes break a long-standing `git rev-parse` usage pattern in Git's own release scripts, where `^0` is used to peel tags to commits. The maintainer provides a concrete example showing the regression: where previously `v2.48.0-rc2-161-g6c2274cdbc^0` correctly resolved to a commit hash, the patch now fails with "Needed a single revision". This appears to be an unintended side effect of the changes meant to handle unpaired curly braces in object names.

The report is significant because it shows the patches are breaking real-world usage that has worked since 2006, despite the changes being meant to fix other long-standing issues. The maintainer's tone suggests this regression needs to be addressed before the patches can proceed, though the overall approach to fixing the curly brace issues still seems acceptable in principle. This appears to be a case where fixing one edge case (unpaired braces) accidentally broke another established behavior (peeling tags with caret syntax).
