This is a follow-up discussion about the final patch in a series removing long-deprecated remote configuration methods, specifically the `branches/` and `remotes/` directories. Christian Couder suggests improving the deprecation process by adding user-visible warnings for these directory-based configurations, similar to what was done for `pack-redundant` in the previous patch.

The suggestion notes that while the documentation changes and compile-time flag approach are solid, adding runtime warnings would make the deprecation more visible to users who might still be using these ancient configuration methods. Christian points to the `pack-redundant` removal as a good model, where users had to explicitly opt-in with an `--i-still-use-this` flag before the command was fully removed.

This is a refinement suggestion rather than a criticism of the core approach - the thread shows consensus on removing these features (deprecated since 2005 and 2011) in Git 3.0. The discussion highlights an opportunity to make the transition even smoother by giving users more proactive notice through runtime warnings before the final removal. The patch series already establishes solid infrastructure for breaking changes, and this suggestion would build on that foundation.
