Bugfix for Zsh shell completion broken by Bash-specific variable expansion. This is version 3 of a patch that fixes config variable completion (for branch.*, remote.*, etc.) in Zsh, which had been showing raw variable names instead of proper completions since commit 1e0ee4087e introduced Bash-specific `${!var}` syntax.

D. Ben Knoble's solution replaces the problematic Bash syntax with a portable `__git_indirect` helper function that uses `eval printf` to safely expand variables across shells. The patch includes a test program demonstrating correct handling of variables containing spaces in both Bash and Zsh. The implementation modifies 6 existing indirect expansions in git-completion.bash while adding the new helper function.

The patch has been reviewed and acked by Philippe Blain, who originally identified the issue. The changes are focused and well-explained, with careful attention to portability concerns and edge cases. The commit message provides clear evidence of testing across shell versions (Bash 3.2.57 and Zsh 5.0.8) and includes references to relevant shell portability discussions.

This appears to be a solid technical solution to a real usability problem, though the broader question of how to test shell completion portability in Git's test suite remains open from earlier discussion. The patch is ready for inclusion pending any final review comments.
