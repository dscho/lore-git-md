This is part 4 of a 5-part series removing long-deprecated Git features in preparation for Git 3.0, specifically targeting the `pack-redundant` subcommand. The patch implements the actual removal of `git-pack-redundant` when built with the `WITH_BREAKING_CHANGES` flag, following its deprecation announcement in September 2024.

The changes are straightforward: the Makefile and git.c are modified to conditionally exclude the subcommand's compilation, while the test script is updated to skip tests when built with breaking changes. This follows the same pattern established earlier in the series for handling deprecated features.

The implementation appears clean and well-contained, with appropriate test coverage. Since this removal was pre-announced and the subcommand has been deprecated for years, the change is unlikely to be controversial. The patch maintains backward compatibility for those not using the breaking changes flag, allowing for a gradual transition period.
