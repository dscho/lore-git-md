Bugfix follow-up addressing a regression in tag-peeling syntax (`^0` suffix) that was introduced by earlier patches fixing object name resolution with curly braces.

Elijah Newren responds to Junio C Hamano's report that the changes broke Git's release process, where version strings like `v2.48.0-rc2-161-g6c2274cdbc^0` were failing to resolve. The issue stemmed from operating on the full string rather than the buffered portion when validating refnames. 

The proposed fix modifies `object-name.c` to properly use the string buffer for refname validation while preserving the tag-peeling functionality. Newren notes this will be included in a reroll of the patch series after the Git 2.48 release to avoid disruption.

This exchange highlights the delicate balance between fixing long-standing issues (dating back to 2006) and maintaining backward compatibility with critical workflows. The maintainer's real-world use case revealed a test coverage gap in the original patches. The core safety improvements from the series remain valid but need this adjustment to handle legacy tag-peeling syntax correctly.
