This is the second patch in a v2 series addressing race conditions in Git's object file collision detection. The patch focuses on tightening error handling for source files in the collision check logic.

The change modifies `object-file.c` to stop special-casing ENOENT (file not found) errors when opening the source file during collision checks. While the previous version treated missing source files as non-errors (to handle races where files vanish), this patch asserts that source files - being temporary objects we just created - should never disappear. If they do, it indicates a real problem that should be reported rather than silently ignored.

The technical change is small (3 lines modified) but meaningful, removing the ENOENT check while keeping the error reporting. This aligns with the series' overall goal of hardening Git against filesystem races while maintaining clear failure modes. The patch builds on the thread's established consensus about when vanishing files indicate races (destination) versus actual errors (source).

This refinement came from Jeff King's review of v1, where he noted the original ENOENT handling was too broad. The change demonstrates the careful progression from initial security fix to more precise error handling as the discussion evolved. The patch maintains all the series' existing safety mechanisms while making the error reporting more accurate.
