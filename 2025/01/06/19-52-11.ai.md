This is a bugfix patch for the credential-cache helper, addressing an issue with capability handling. The patch ensures the credential-cache daemon only responds with the `authtype` capability when the request actually includes that capability, rather than always sending it unconditionally.

The main changes modify the credential-cache daemon's response logic in `builtin/credential-cache--daemon.c` to check `CREDENTIAL_OP_RESPONSE` before including the authtype capability or related fields. The patch also adds a new test case in `t/lib-credential.sh` that verifies the helper only provides authtype information when requested.

Key technical details:
- The fix centers around the `credential_has_capability()` check for `CREDENTIAL_OP_RESPONSE`
- Affects both the capability announcement and the conditional output of `authtype` and `credential` fields
- Test case demonstrates the new behavior by showing a fill request without authtype capability gets basic username/password only
- This is v2 of the patch, with the test description clarified from "does not get" to "get authtype only if"

The change appears well-contained and properly tested, fixing what seems like an oversight in capability handling. The patch maintains backward compatibility while making the behavior more correct according to the credential helper protocol.
