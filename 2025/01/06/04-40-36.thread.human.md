This thread explores how to reliably detect the existence of remote '_incoming' branches in CI scripts, particularly for triangular workflows where CI fetches from one branch (e.g., 'foo') but pushes to another ('foo_incoming'). Chris Packham initiated the discussion by noting that `git rev-parse --symbolic-full-name` produces awkward output (appending '--' when the branch exists), making script parsing difficult.

Torsten Bögershausen has now suggested an alternative approach using `git fetch -p` followed by `git branch -r` to list all remote branches after pruning stale references. While this avoids the specific `rev-parse` output issue, it doesn't directly address the core need to distinguish between regular and '_incoming' branches in triangular workflows. The thread remains open for better solutions that combine reliable branch detection with clear handling of the triangular workflow pattern.
