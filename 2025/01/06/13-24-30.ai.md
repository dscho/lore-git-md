This is a follow-up discussion about the final patch in a series removing deprecated remote configuration mechanisms, focusing on improving the deprecation warning strategy for the `branches/` and `remotes/` directory removal.

Christian Couder suggests enhancing the deprecation process for the directory-based remote configuration (targeted in patch 5/5) to mirror the more aggressive warning approach used for `pack-redundant` removal in patch 4/5. He notes that while the current patch simply announces removal, the `pack-redundant` approach included visible runtime warnings since 2020 and required an explicit `--i-still-use-this` opt-in, making deprecation harder to ignore. 

The suggestion implies modifying the implementation to add warning messages when these legacy directories are detected, potentially with configuration to silence them. This would affect the remote handling code in `remote.[ch]` and `builtin/remote.c`, requiring updates to both the implementation and tests. The thread has shown consensus on the removal itself, with this being a refinement suggestion about the transition strategy rather than opposition to the change.

This email continues the pattern seen throughout the thread of carefully considering user experience during breaking changes, though it introduces a new implementation consideration not previously discussed for this specific patch. The suggestion would make the deprecation more visible than just documentation updates, aligning with Git's gradual removal practices for other features.
