This is a technical suggestion for improving remote branch detection in CI scripts, continuing the thread about triangular workflow branch management.

Theodore Ts'o proposes using `git ls-remote` as an alternative to the previously discussed `rev-parse` and `fetch+branch` approaches for checking remote branch existence. His solution comes from the gce-xfstests project, where they validate both repository accessibility and branch names before operations. The key advantages are that `ls-remote` doesn't require a local repository clone and provides cleaner exit codes than `rev-parse`'s output parsing challenges.

The implementation shows two validation functions: one for checking basic repository accessibility (adding .git suffix if needed) and another specifically for branch validation using `ls-remote --heads --exit-code`. This approach avoids the output parsing issues of `rev-parse` by relying on exit codes, though it does require knowing the remote repository URL rather than working with configured remotes.

Ts'o notes this may not be ideal for SHA validation (where full fetches would be more reliable) but works well for branch name checking. The solution is presented as production-tested code from their CI system, suggesting it handles real-world robustness requirements discussed earlier in the thread. This adds a third technical approach to the growing set of options for the original triangular workflow detection problem.
