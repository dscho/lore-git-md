CI modernization patch converting GitHub Actions Linux jobs to containerized execution. This is part 4/10 of Patrick Steinhardt's series that has already addressed key technical concerns through prior review iterations.

The patch moves all Linux CI jobs from direct machine-pool execution to containerized runs, completing the standardization effort. Key technical points:
- Containerized jobs provide more control over execution environments while showing negligible performance impact (timing data shows variations within ±1 minute across jobs)
- Root execution concerns were resolved in the preceding patch via setpriv(1)
- The change affects 9 Linux job configurations (sha256, reftable, gcc variants, leaks, asan-ubsan, meson) while preserving their existing parameters (compiler choices, distro versions)
- Job definitions are reorganized into the containerized section with new `distro` field mapping while maintaining all test coverage
- The solution builds on resolved issues including the Node.js binary injection problem that previously affected 32-bit jobs

The implementation demonstrates careful migration by:
- Keeping identical job names and test matrices
- Preserving compiler toolchain selections (gcc-8 for specific jobs)
- Maintaining Ubuntu version alignment (20.04 for jobs requiring it)
- Adding explicit `CC` environment variable to container contexts

This represents the final piece of the containerization strategy after addressing all identified technical hurdles in prior patches.
