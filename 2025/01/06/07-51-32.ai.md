This is a cover letter for a patch series announcing the removal of long-deprecated remote configuration mechanisms. The series is part of Git's ongoing effort to clean up legacy features and prepare for breaking changes in Git 3.0.

The series focuses on removing two obsolete ways to configure remotes: the `branches/` directory (deprecated since 2005) and `remotes/` directory (deprecated since 2011), both long since replaced by config-based remotes. The patches establish infrastructure for handling breaking changes, including a new build option to enable deprecated features, CI job updates for testing breaking changes, and documentation updates.

Key technical components include:
- New `GIT_DEPRECATED_FEATURES` build option
- CI job restructuring to test with deprecations enabled
- Removal of the `pack-redundant` subcommand (another breaking change)
- Documentation updates in `BreakingChanges.txt` and `gitrepository-layout.txt`
- Test updates to handle the deprecated feature removal

The series builds on previous work to establish patterns for handling breaking changes, with v2 containing minor fixes to deprecation notices and commit messages. The changes appear well-considered, targeting features that have been deprecated for 14-20 years and are unlikely to be in active use. The infrastructure changes suggest this may serve as a template for future breaking change removals.
