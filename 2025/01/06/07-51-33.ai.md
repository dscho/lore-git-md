Build system patch introducing infrastructure for upcoming breaking changes. This is the first of five patches in v2 of a series removing long-deprecated features (branches/ and remotes/ directories, pack-redundant command).

The patch adds a new `WITH_BREAKING_CHANGES` compile-time flag across all build systems (Makefile, CMake, Meson) to control whether deprecated features should be removed. This implements the policy established in earlier commits to BreakingChanges.txt that breaking changes must be gated behind a build option. The changes include:
- New preprocessor macro `WITH_BREAKING_CHANGES`
- Build system wiring in Makefile, CMakeLists.txt, and meson.build
- Meson configuration option `breaking_changes`
- Test infrastructure support via `WITHOUT_BREAKING_CHANGES` prereq
- Updates to GIT-BUILD-OPTIONS generation

The patch is mechanical infrastructure work that enables the actual feature removals in subsequent patches. It follows the pattern established for handling deprecations, with no functional changes yet - just the plumbing needed to make the breaking changes optional during the transition period. The implementation is thorough, touching all major build systems and test infrastructure.
