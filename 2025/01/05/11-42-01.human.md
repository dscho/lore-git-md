This is a bugfix patch addressing an issue with the fetch set-head warning message. The patch corrects an advice message that was incorrectly suggesting users could set a configuration value with a dynamic branch name, which isn't actually supported by Git's configuration system.

The change comes in response to Bence Ferdinandy's observation that the suggested `git config` command in the warning would try to use the branch name as a literal config key, rather than the intended behavior of setting a static value. The patch updates the advice message to be more accurate about how to configure the `followRemoteHEAD` setting.

This is a small but important correction to prevent users from being misled by incorrect configuration advice. The change is straightforward and clearly motivated by the kind of subtle documentation bug that can cause real user confusion. As part of a 3-patch series (position 2/3), it appears focused on improving the user experience around remote HEAD tracking warnings.
