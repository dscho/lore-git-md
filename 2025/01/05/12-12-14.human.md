Feature proposal for `git describe` to consider untracked files in dirty state detection.

Ross Goldberg proposes adding a `--untracked-is-dirty` option to `git describe` that would make untracked (but not ignored) files trigger the dirty marker when used with `--dirty`. Currently, `--dirty` only marks the repository as dirty for modified/deleted tracked files (staged or unstaged) and newly staged files, but ignores untracked files.

The proposal suggests two possible implementations: a new `--untracked-is-dirty` flag that would work alongside `--dirty`, or an alternative syntax using a colon (`--dirty:<mark>`) instead of equals sign to activate the behavior. The author is open to naming suggestions and asks whether other file status categories should also be considered for dirty state detection.

This appears to be a well-motivated proposal that would make `git describe`'s dirty detection more comprehensive. The author demonstrates good understanding of the current behavior and provides clear implementation alternatives. The change would be particularly valuable for users who want their version strings to reflect the presence of any uncommitted changes, including new files.
