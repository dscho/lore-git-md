This is part of a ref consistency checking series, specifically addressing worktree handling during verification.

The patch introduces `get_worktrees_without_reading_head()` to avoid premature program termination during ref verification. Currently, when checking packed refs via `git refs verify` or `git fsck`, reading worktree HEAD information could trigger packed-refs parsing that dies on errors - exactly what the verification process is meant to detect and report. The new function builds on existing infrastructure (465a22b338) that can skip HEAD reading, allowing verification to continue and report all issues rather than failing fast.

Key technical points:
- Adds new public API in `worktree.h/c` mirroring `get_worktrees()` but with HEAD reading disabled
- Modifies `builtin/refs.c` to use this when verifying refs
- Preserves all existing functionality while avoiding packed-refs parsing during verification
- Follows the series' pattern of separating verification from normal operation paths

The change is narrowly scoped (12 lines net) and builds logically on prior work, though it might be worth noting this creates a parallel API surface to `get_worktrees()`. The patch appears well-motivated within the context of the larger verification effort, preventing false negatives during system-wide checks.
