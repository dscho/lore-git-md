This is patch 7/10 in a series adding comprehensive ref consistency checks, specifically introducing a helper struct to store parsing information during packed-refs validation.

The patch creates a new `fsck_packed_ref_entry` struct to track validation state while parsing packed-refs entries, rather than immediately checking object existence. This avoids potential program termination that could occur if validation directly called `parse_object()`, which might trigger dangerous operations during the verification phase. The struct stores line numbers, OIDs, and peeled tag information for later validation.

Key changes include:
- New `fsck_packed_ref_entry` struct with fields for line numbers, OIDs, and peeled tag status
- Allocation and cleanup functions for these entries
- Modifications to the validation functions to use the struct rather than immediate checking
- Maintaining the existing error reporting while deferring object existence checks

This is part of the series' logical progression from basic file checks to detailed content validation. The approach follows the pattern of earlier patches by focusing validation on syntax first, deferring more expensive checks until the structure is verified. The patch maintains thorough error reporting while making the validation process more robust against crashes.
