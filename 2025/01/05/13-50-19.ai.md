This is patch 8/10 in a series adding comprehensive ref consistency checks, focusing on object existence validation in packed-refs entries.

The patch adds object consistency checking for packed refs after the file format validation from previous patches. It introduces `packed_fsck_ref_oid()` which verifies that both main ref entries and their peeled tag references point to valid objects via `parse_object()`. The function handles promisor objects specially by skipping their validation. Error reporting includes the line number from the packed-refs file for debugging.

Key technical details:
- New function `packed_fsck_ref_oid()` checks object existence for both main refs and peeled tags
- Uses `parse_object()` to validate OIDs
- Skips promisor objects with `is_promisor_object()`
- Reports errors via existing `fsck_report_ref()` infrastructure
- Maintains line number context from patch 7's `fsck_packed_ref_entry` struct
- Adds comprehensive tests covering:
  - Invalid main ref OIDs
  - Invalid peeled tag OIDs
  - Both cases with test OIDs 001 and 002
  - Proper error message formatting
- Integrates with the existing validation flow, only running after successful format checks

The patch builds logically on the series' progression from format validation to content validation, with thorough test coverage matching earlier patches. It handles both regular refs and peeled tags while respecting the repository's promisor configuration. The error reporting maintains consistency with the series' approach of including file location context.
