Bug report thread: `git branch --format` sorting behavior with `ahead-behind:HEAD`

Ross Goldberg reports unexpected behavior in `git branch` when combining `--format` with `--sort=ahead-behind:HEAD`. The core issue is that when sorting by ahead-behind counts relative to HEAD, the field values disappear from output and sorting falls back to alphabetical by branch name rather than the requested ahead/behind counts. The detached HEAD appears first regardless of sort order, suggesting a priority inversion.

Technical specifics:
- Bug manifests specifically with `ahead-behind:HEAD` field - other fields like `objectsize` work correctly
- Issue occurs both when field is displayed and when used only for sorting
- Reproduction shows consistent behavior on macOS with Git 2.47.1 (clang 14.0.0)
- Implementation likely involves branch formatting/sorting logic parsing these fields differently

The report provides clear reproduction steps showing the discrepancy between expected (sort by commit counts) and actual (alphabetical) behavior. The field-specific nature suggests this is a general sorting bug rather than a configuration issue. No workarounds or patches are proposed yet - this appears to be a newly identified edge case in the branch formatting machinery.
