Thread summary:

This thread addresses memory leaks and inconsistent behavior in Git's ref-filter code when handling ahead-behind and is-base calculations across commands (branch, for-each-ref, tag, verify-tag). The core issue stems from committish references being stored in separate string lists for formatting versus sorting operations, causing leaks when sorting preceded formatting and incorrect results in the reverse case. The solution makes the bases and is_base_tips string lists static variables shared between operations rather than per-ref_format instance, eliminating the need for ref_format_init() and ref_format_clear() functions which are removed. All callers are updated accordingly. New tests verify correct behavior with sorting operations using these atom types. While this makes ref-filter more stateful via static variables, it resolves the memory management issues and ordering-dependent behavior. The changes affect multiple commands but are most visible in sorting operations using ahead-behind or is-base calculations.
