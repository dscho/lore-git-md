This is the final patch in a 10-part series adding comprehensive ref consistency checks to Git's files and packed ref backends, now integrating them into `git fsck`. The series has been systematically building validation for various aspects of ref storage, with this patch focusing on the user-facing integration.

The patch adds a new `fsck_refs()` function that runs `git refs verify` as a child process during `git fsck` execution. It includes progress reporting (though currently simplified since loose ref counts aren't known upfront) and respects existing `--verbose` and `--strict` flags. The checks run early in `git fsck` to avoid interference from the command's implicit ref validation.

This appears to be a well-considered conclusion to the series, providing the promised integration point while being careful about user experience (progress reporting) and backward compatibility (running before existing checks). The implementation follows Git's patterns for child process handling and progress reporting. As the final piece of a GSoC project, it delivers on the thread's goal of comprehensive ref validation now accessible via Git's standard repository verification tool.
