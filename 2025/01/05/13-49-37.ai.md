This is part 4 of a 10-patch series adding comprehensive ref consistency checks, focusing on validating the "packed-refs" file header format. The patch introduces three new validation rules for the header line in packed-refs files, with corresponding fsck messages at different severity levels.

The patch adds checks for: missing headers (warning), malformed headers that don't start with "# pack-refs with:" (error), and non-standard headers that deviate from Git's canonical format (warning). It implements these by reading the packed-refs file and parsing the first line, with careful handling of newline termination. The validation rules mirror those used in `create_snapshot()` but are adapted for fsck reporting.

A key technical change is the addition of a `safe_object_check` flag to `fsck_options` that gets disabled if header parsing fails, preventing potentially dangerous object checks later in the process. The patch also reorders the verification sequence to check packed-refs before loose refs to avoid crashes from malformed packed-refs files.

Test coverage includes cases for all three header scenarios plus edge cases like missing newlines. The new fsck messages are documented in fsck-msgids.txt with clear explanations. The implementation builds on existing packed-refs parsing logic while adding about 100 lines of new validation code, with careful attention to backward compatibility for repositories with non-standard headers.

This continues the series' pattern of methodically adding validation while maintaining safety - each check is narrowly focused, well-tested, and integrated with the existing fsck framework. The header validation is particularly important as malformed headers could indicate corruption or malicious tampering with the ref storage.
