This is a bugfix patch in a series improving ref consistency checks, specifically addressing NULL byte detection in packed refnames.

Patch 5/10 in the series adds validation to catch embedded NULL bytes in refnames stored in packed-refs files. The author explains that while Git already checks refname format, it could miss NULL bytes in the middle of a refname if the portion before the NULL is valid. This builds on a reported issue where `git fsck` failed to detect such corruption.

The solution introduces a new `refname_contains_null()` helper that compares a refname's length against its string length (which stops at the first NULL). When found during packed-refs iteration, this triggers a fatal error. The patch includes clear documentation of the edge case being fixed and references the original bug report.

This appears to be a well-motivated change that plugs a real hole in ref validation. The implementation is straightforward and the commit message provides good technical context. As part of a larger ref validation effort, this patch specifically targets an edge case that could allow corrupted refnames to slip through existing checks.
