This is a bugfix patch correcting an error in Git's fetch advice message. It's part of an ongoing series addressing issues with the warning shown when a remote's HEAD changes during fetch.

The patch fixes an incorrect configuration syntax suggestion in the advice message. The previous version mistakenly told users to set `remote.%s.followRemoteHEAD %s` when they should actually use `warn-if-not-branch-%s`. This was caught by Teng Long and acknowledged by the author Bence Ferdinandy.

The change is minimal - just two lines in `builtin/fetch.c` updating the format string in `set_head_advice_msg()`. The fix ensures users following the advice will enter valid configuration syntax rather than something that wouldn't work as intended.

This appears to be a straightforward correction with no behavioral changes beyond making the documentation accurate. The patch follows the standard format with a clear commit message explaining both the problem and solution, plus proper attribution to the reporter. It's a small but important fix since incorrect advice messages can frustrate users trying to follow Git's guidance.
