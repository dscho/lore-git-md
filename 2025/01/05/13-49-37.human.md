This is patch 4/10 in a series adding comprehensive ref consistency checks, focusing on validating the header format of packed-refs files. The patch introduces three specific checks:

1. A warning when the packed-refs file lacks any header (though this is technically allowed)
2. An error when the header doesn't start with the required "# pack-refs with:" prefix
3. A warning when the header content differs from Git's standard format (though still allowing such variations)

The patch also fixes a subtle issue where verification would die prematurely when encountering malformed packed-refs, by adding a `safe_object_check` flag to skip object validation after detecting backend problems. This ensures all validation errors are reported rather than stopping at the first issue.

The changes include thorough test coverage in t0602-reffiles-fsck.sh, exercising all the new validation scenarios. The implementation follows the same patterns used elsewhere in the packed-refs backend, and adds appropriate documentation for the new fsck message IDs.

This continues the series' pattern of methodically adding validation checks before the final fsck integration in patch 10. The changes are well-motivated and carefully implemented, with clear commit message explanations of both the technical changes and the compatibility considerations.
