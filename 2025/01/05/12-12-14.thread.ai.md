Thread summary:

Ross Goldberg proposes extending `git describe --dirty` to consider untracked files when determining repository dirtiness. Current behavior only marks dirty state for modified/deleted tracked files (staged or unstaged) and newly staged files, ignoring untracked files. Two implementation approaches are suggested: 1) adding a new `--untracked-is-dirty` option, or 2) changing the syntax from `--dirty=<mark>` to `--dirty:<mark>` to allow future extensibility for other file status categories. The proposal seeks feedback on whether this functionality would be useful and which implementation approach would be preferred. No specific use cases or implementation details are provided yet - this is an initial discussion starter about potentially making dirty state detection more comprehensive or configurable.
