Bug report about `git branch --format` sorting behavior with `ahead-behind:HEAD`.

This is a bug report documenting unexpected behavior in `git branch` when using the `--format` option with the `ahead-behind:HEAD` field. Ross Goldberg reports that when sorting branches by `ahead-behind:HEAD`, the field values disappear from the output and the sorting appears to fall back to alphabetical by branch name rather than the requested ahead/behind counts. The report includes clear reproduction steps showing the difference between expected and actual behavior, with the detached HEAD case appearing first regardless of sort order.

The issue appears specific to the `ahead-behind:HEAD` field - other fields like `objectsize` work as expected. The bug persists even when `ahead-behind:HEAD` is only used for sorting but not displayed in the output format. System information shows this was observed on macOS with Git 2.47.1 built with clang 14.0.0.

Key technical details for future reference:
- The bug manifests when combining `--format` with `--sort=ahead-behind:HEAD`
- Field values disappear from output when used for sorting
- Sorting falls back to refname rather than ahead/behind counts
- Detached HEAD appears first regardless of sort criteria
- Contrasting behavior with `objectsize` field shows this is field-specific

The report is well-structured with clear reproduction steps and system details, suggesting this is a genuine bug rather than user error. The behavior difference between fields indicates this may be a parsing/implementation issue in the branch formatting and sorting logic.
