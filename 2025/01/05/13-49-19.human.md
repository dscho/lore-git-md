This is part 2 of a 10-patch series adding comprehensive consistency checks for Git's ref storage backends, eventually to be integrated with `git fsck`. The series is part of the author's GSoC project but developed independently.

The current submission addresses a subtle interaction between worktree handling and ref verification. When `git refs verify` or `git fsck` checks refs, it currently calls `get_worktrees()`, which reads HEAD information. If HEAD points to a ref in packed-refs, this triggers packed-refs parsing that could die on errors - exactly the behavior the verification tools aim to avoid by collecting all issues rather than failing fast.

The patch introduces `get_worktrees_without_reading_head()` as a variant of the existing function, using infrastructure added in commit 465a22b338. This prevents the packed-refs parsing during verification while still allowing access to worktree information. The change is minimal (12 lines net) and well-contained, touching only the verification path in `builtin/refs.c` while adding the new API to worktree.{c,h}.

This appears to be a thoughtful improvement that maintains the series' goal of comprehensive verification without early termination. The change is small but meaningful, with clear motivation explained in the commit message. The patch follows established patterns and has appropriate mentor sign-offs.
