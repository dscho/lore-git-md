This thread has progressed from design discussion to implementation of memory management improvements in Git's ref-filter subsystem, focusing on how commit references for ahead-behind and is-base calculations are stored. The key participants—René Scharfe, Jeff King, and Junio Hamano—have converged on a hybrid approach that stores commit references directly in atom structs rather than in format-wide string list.

René Scharfe is now leading the implementation with a v2 patch series. The first patch, just submitted, moves ahead-behind base commit storage from the `ref_format` struct into individual `used_atom` entries. This fixes several practical issues including memory leaks when sort options are parsed before format strings (a common case in `git branch`), inconsistent behavior with excluded sort keys, and the inability to share committish references between operations. The changes maintain the same external behavior while improving internal consistency.

The implementation follows through on the architectural direction endorsed by Junio Hamano, building on Jeff King's earlier work to make state management more explicit. With the design questions settled, the focus has shifted to the concrete application of these improvements. René's upcoming patches will complete the transition for both ahead-behind and is-base functionality, representing the culmination of this extended discussion about ref-filter's internal organization.
