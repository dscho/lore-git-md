This thread has completed a significant refactoring of Git's ref-filter subsystem to eliminate global state management for ahead-behind and is-base calculations. René Scharfe led the implementation through a carefully structured three-part patch series that transitions these operations to store commit references directly in atom structs rather than using shared global variables.

The work addresses long-standing concerns about memory management and inconsistent behavior when sorting references. Jeff King initially pushed for explicit state management, and Junio Hamano signaled approval of the technical direction. The final patch, just submitted, removes the last remaining global state (the `is_base_tips` string list) by applying the same atom-struct pattern used earlier for ahead-behind calculations.

The implementation maintains all existing functionality while achieving the architectural goal of eliminating shared state between formatting and sorting operations. With all three parts now implementing this consistent approach and comprehensive test coverage in place, the series appears ready for merging. This represents a significant cleanup of the ref-filter internals that should improve reliability and maintainability of several Git commands including branch, for-each-ref, tag, and verify-tag.
