This is patch 8/10 in a series adding comprehensive ref consistency checks, focusing on object existence validation in packed refs. The patch adds verification that all object IDs referenced in packed-refs actually exist in the object database, catching cases where refs point to missing or corrupted objects.

The patch introduces a new `packed_fsck_ref_oid()` function that iterates through packed ref entries after the file format checks pass. It verifies both main ref objects and peeled tag objects using `parse_object()`, skipping promisor objects. The function reports errors with detailed line numbers when invalid objects are found. 

Test cases demonstrate the validation by creating packed-refs files with intentionally invalid object IDs (both for regular refs and peeled tags) and verifying the appropriate error messages are produced. The tests cover both the main ref line and peeled tag line cases.

This continues the series' pattern of thorough validation with clear error reporting, building on the refactoring in patch 7 that enabled this deferred object checking. The implementation appears clean and well-tested, with proper handling of error cases and memory management. As with previous patches in the series, this moves Git closer to having comprehensive packed-refs validation as part of `git fsck`.
