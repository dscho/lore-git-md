This is a discussion about a documentation patch that proposes standardizing Git's headers to reflect its purpose as a DVCS, replacing Linus Torvalds' original humorous descriptions.

The email is a response to Bartosz Pracz's patch that changes various file headers from "The information manager from hell" to "Distributed version control system". David Aguilar raises two main points: First, he notes that Linus's original comments were intentionally humorous and self-deprecating, and questions whether removing them is necessary. Second, he points out a technical inconsistency - the patch changes documentation text that describes the output of `git walken`, but the actual commit history (including the initial commit's message) remains unchanged, making the documentation incorrect.

Aguilar also suggests a minor wording tweak ("Distribute version control" without "system") but acknowledges this may not be worth changing. The discussion touches on both the cultural/historical aspects of Git's documentation and technical accuracy concerns. The original patch was purely cosmetic with no functional changes, but this response highlights how even documentation changes can have implications for accuracy and project culture.
