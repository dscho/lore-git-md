Bug report about `git branch` sorting and field display issues with `ahead-behind:HEAD`.

Ross Goldberg reports unexpected behavior when trying to sort `git branch` output by the `ahead-behind:HEAD` field. The bug manifests in two ways: (1) when sorting by this field, the field values disappear from the output, and (2) the sorting appears to fall back to alphabetical by branch name rather than using the ahead/behind counts.

The report includes clear reproduction steps showing that while the field displays correctly without sorting, it vanishes when `--sort` is added. Interestingly, sorting by other fields like `objectsize` works as expected. The issue appears specific to `ahead-behind:HEAD` handling.

This looks like a legitimate bug in the branch formatting/sorting logic. The report is well-structured with clear before/after examples and system information. The behavior difference between `ahead-behind:HEAD` and other sortable fields suggests this might be a straightforward fix in the field display logic when combined with sorting.
