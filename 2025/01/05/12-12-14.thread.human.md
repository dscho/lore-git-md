Here's a human-readable summary of the thread so far:

Ross Goldberg has proposed enhancing `git describe`'s dirty state detection to include untracked files. Currently, when using `--dirty`, Git only considers modified or deleted tracked files (whether staged or unstaged) as making the repository dirty, completely ignoring untracked files. The proposal suggests either adding a new `--untracked-is-dirty` option or modifying the syntax from `--dirty=<mark>` to `--dirty:<mark>` to accommodate this change.

The suggestion recognizes that there might be other file status categories users would want to include in dirty state detection in the future, so any solution should be designed with extensibility in mind. While no specific use cases are provided, the implication is that the current behavior can be surprising when untracked files are present in the working directory. The proposal is currently at the discussion stage, with no implementation yet provided, seeking feedback on both the concept and the preferred approach to achieve it.
