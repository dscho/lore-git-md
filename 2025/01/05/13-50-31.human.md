This is patch 9/10 in a series adding comprehensive validation checks for Git's packed-refs file, focusing on verifying the file's sort order. The series is part of a larger effort to improve ref consistency checking, eventually integrating with `git fsck`.

The patch adds a check that packed-refs entries are properly sorted by refname, which is a requirement for the file format. Rather than storing each refname for comparison (which would be memory-intensive), the author cleverly reuses the existing `snapshot_record` structure and comparison functions from the packed-refs backend. The implementation introduces a new fsck error type `packedRefUnsorted` and includes thorough test cases demonstrating detection of out-of-order refs.

The change builds logically on previous patches in the series, particularly leveraging the line-number tracking added in patch 7. The implementation looks solid, with careful approach to memory management and error reporting. Test coverage is comprehensive, checking both simple refs and peeled tags. This continues the series' pattern of focused, well-explained changes to harden Git's ref storage validation.
