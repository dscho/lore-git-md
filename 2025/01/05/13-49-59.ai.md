This is patch 6/10 in a series adding comprehensive ref consistency checks, focusing on packed-refs entry validation. The patch introduces detailed parsing and error reporting for individual packed-refs entries, building on the earlier header validation work.

The patch adds two new validation functions: `packed_fsck_ref_main_line()` checks the main ref entry line (oid + refname format), while `packed_fsck_ref_peeled_line()` validates the optional peeled tag lines. Both integrate with the existing fsck framework, using a new `FSCK_MSG_BAD_PACKED_REF_ENTRY` error type. The validation catches:
- Invalid OID formats
- Missing/incorrect whitespace after OIDs
- Malformed peeled tag entries
- Trailing garbage in entries
- Bad refname formats (reusing existing checks)

The implementation carefully tracks line numbers for error reporting and handles the packed-refs file format's two-line-per-tag case. Test coverage is thorough, including:
- Short/invalid OIDs
- Missing whitespace
- Malformed peeled tags
- Trailing garbage
- Bad refnames
Each test verifies the exact error message output matches expectations.
