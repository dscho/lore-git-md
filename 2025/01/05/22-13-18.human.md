A follow-up refinement to the `git diff-tree --cc` path handling refactoring. This is part of the ongoing thread addressing a segfault caused by uninitialized path buffers in the combined diff code.

Wink Saville suggests a small but meaningful improvement to Jeff King's final solution - renaming the `path` field in `struct combine_diff_parent` to `changed_path` and adding a clarifying comment. This better reflects the field's purpose (it's only populated when the parent's path differs from the main path) and makes the NULL-means-no-change semantics more self-documenting.

The change is minimal - just a field rename and comment addition - but improves code clarity while maintaining all the benefits of the earlier refactoring that replaced strbufs with simpler char* pointers. This appears to be a straightforward improvement to an already-solid solution, though whether it's worth changing the field name at this stage is ultimately up to the maintainers.
