This is the final patch in a 10-part series adding comprehensive ref consistency checks, integrating them into `git fsck`. The series has systematically built up checks for both files and packed ref backends, with this patch completing the user-facing integration.

The patch adds a new `fsck_refs()` function that runs `git refs verify` as a child process during `git fsck` execution. It handles progress reporting (initialized to 1 task since loose ref counts aren't known upfront) and passes through relevant flags like `--verbose` and `--strict`. The check runs early in `git fsck` to avoid interference from its existing implicit ref checks.

Key technical details:
- Uses `CHILD_PROCESS_INIT` and `strvec` for process setup
- Progress reporting via `start_progress()`/`stop_progress()`
- Error reporting through `errors_found |= ERROR_REFS`
- Positioned before existing connectivity checks in `cmd_fsck()`
- Maintains flag parity between `git fsck` and `git refs verify`

The patch completes the series' goal of exposing the new validation infrastructure to users while being careful not to disrupt existing fsck behavior. The child process approach provides clean separation while ensuring the new checks benefit from fsck's progress reporting and error handling. The implementation appears straightforward and well-integrated with Git's existing process spawning patterns.

This represents the culmination of the series' work to systematically validate ref storage integrity, now making those checks available as part of Git's standard repository verification toolkit.
