This is a bugfix patch correcting an error in the fetch command's advice message. It's part of an ongoing series addressing issues with the fetch set-head warning (though we haven't seen the full series context).

The patch fixes an incorrect configuration syntax suggestion in the advice message shown when a remote's HEAD changes during fetch. The previous version mistakenly suggested using the branch name directly (`%s`) rather than the proper `warn-if-not-%s` syntax for the `remote.<name>.followRemoteHEAD` configuration. The change affects `set_head_advice_msg()` in builtin/fetch.c, which generates this message when `ADVICE_FETCH_SET_HEAD_WARN` is enabled.

The fix was prompted by Teng Long's report identifying the incorrect format. The patch maintains the same message structure but now provides accurate configuration syntax that would actually work if followed by users. The underlying behavior of the remote set-head and followRemoteHEAD interaction remains unchanged - this is purely about correcting misleading documentation in the advice text.

The change is minimal (2-line diff) and clearly targeted, with the commit message properly crediting the reporter. This appears to be a straightforward correction of a documentation error that could have led users to enter invalid configuration syntax if they followed the previous incorrect advice.
