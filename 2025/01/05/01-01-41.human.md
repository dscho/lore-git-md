This is a discussion about a documentation patch that proposes standardizing Git's headers to reflect its purpose as a DVCS, removing Linus Torvalds' original humorous descriptions.

David Aguilar responds to Bartosz Pracz's patch that aimed to replace informal descriptions like "the information manager from hell" with more professional language. David notes that the original comments were intentionally lighthearted and self-deprecating, and points out a technical issue where the documentation change would become inaccurate - Git's immutable history means the initial commit will always contain the original phrase.

The discussion touches on both cultural and technical aspects. Culturally, there's a question about preserving Git's historical character versus modernizing its documentation. Technically, the patch creates a mismatch between the documentation and actual commit history. David suggests a minor wording tweak ("Distribute version control" instead of "Distributed version control system") but acknowledges this may not be worth changing if there's no broader interest.

The exchange highlights how even seemingly simple documentation changes can involve considerations of project history, technical accuracy, and community preferences. The patch appears well-intentioned but may need refinement to address these concerns.
