This thread documents the evolution of a patch series (currently at v2) that introduces comprehensive validation checks for Git's packed-refs file format. The discussion has focused on striking the right balance between strict validation and backward compatibility, particularly regarding how to handle repository formats from different Git versions.

The series originally aimed to validate both the file format and referenced objects, but has since been narrowed to focus solely on format validation after Patrick Steinhardt suggested separating these concerns architecturally. The current implementation includes checks for malformed headers, invalid refnames, NUL characters in refs, and symlink attacks (using platform-appropriate methods like `open_nofollow()` where available).

A key recent discussion with Junio Hamano clarified several subtle points about header validation. The maintainer noted that the validator must accept headerless files to maintain compatibility with pre-v1.5.0 repositories, while still catching truly malformed headers. He also emphasized that the format was designed to be extensible, so unknown optional traits shouldn't trigger errors. These insights led to removing some proposed validation messages and adjusting others to better match Git's actual runtime behavior.

The series is nearing completion, with Junio having verified the test infrastructure and worktree handling approach. The validation now runs early in `git fsck` via a new `git refs verify` child process, maintaining the existing error reporting system while adding these new checks. Test coverage in t0602-reffiles-fsck.sh has been expanded to verify the various validation scenarios, including symlink detection and combined corruption cases.

Looking ahead, this work lays the foundation for future validation improvements while keeping the door open for backend-agnostic checking. The careful attention to historical behavior and forward compatibility in these discussions reflects Git's commitment to maintaining stability across repository versions.
