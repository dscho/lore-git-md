This thread covers a bugfix series (now at v3) implementing comprehensive validation for packed-refs files, with the latest patch focusing on verifying refname sorting when the "sorted" capability is present in the header. The series originated from shejialuo and has undergone extensive review, particularly from Patrick Steinhardt, who has provided detailed feedback on implementation details.

The core work establishes a new `git fsck --references` option that performs end-to-end validation of packed-refs files, checking file format, header capabilities, content structure, and now sortedness. The latest patch adds sortedness verification that only activates when the header declares the file is sorted, maintaining backward compatibility with older files. Error reporting includes specific line numbers and refnames when violations are found.

Patrick has suggested optimizations throughout the review process, including changing the sortedness verification from storing all entries to pairwise comparison (to save memory) and modernizing test construction with HERE documents. shejialuo has incorporated most suggestions and acknowledges the remaining ones will be addressed in the next version. The series is nearly complete, with just a few loose ends around HEAD corruption reporting and root ref validation still to be resolved.
