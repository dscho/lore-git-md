This thread covers a bugfix series (currently at v2) addressing validation issues in Git's packed-refs file format. The series has been restructured from its original 10 patches to focus specifically on file format validation, deferring object validation to future work as recommended by Patrick Steinhardt. The current iteration implements strict checks for packed-refs headers, NUL characters in refnames, entry consistency, and sortedness, while introducing scaffolding for a new `git refs verify` command.

The latest patch (2/8 in v2) fixes an edge case where HEAD parsing during worktree checks could trigger premature validation failures. It introduces `get_worktrees_without_reading_head()` to avoid this, allowing `git refs verify` to report all validation issues rather than dying on the first problem. The change is minimal but important for robustness, building on existing worktree infrastructure.

Patrick Steinhardt has been guiding the architectural direction, with the series now cleanly separating file format validation from object validation. Eric Sunshine and Karthik Nayak have contributed test infrastructure improvements, particularly around reliable subshell usage for test cleanup. The series touches core refs handling code and adds extensive test coverage, with all v2 changes focused on restructuring rather than scope expansion to ease review burden. While some questions remain about long-term backend-agnostic design, the current work represents solid progress on immediate packed-refs validation goals.
