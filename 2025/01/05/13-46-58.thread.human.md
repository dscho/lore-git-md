This thread documents a bugfix series (currently at v2) that introduces comprehensive validation checks for Git's packed-refs file format. The series was originally 10 patches but has been streamlined to 8 based on feedback, focusing specifically on file format validation while deferring object validation to future work.

The core work adds strict validation of packed-refs files, including checks for malformed headers, invalid ref entries, NUL characters in refnames, and now in v2, verification that refs are properly sorted. The implementation introduces new error types and validation functions in refs/packed-backend.c, with extensive test coverage in t0602-reffiles-fsck.sh. The series follows Patrick Steinhardt's architectural vision of separating file format validation from object validation, with the latter planned for a future `git refs verify` command.

The final patch (8/8) integrates this validation with `git fsck` by spawning a `git refs verify` child process early in fsck's execution. While this creates some redundancy with fsck checks, it's intentional to maintain backward compatibility. The implementation includes progress reporting and proper flag passing between processes.

Patrick Steinhardt has been the primary architectural guide throughout the series, with Eric Sunshine and Karthik Nayak providing key feedback on test infrastructure improvements. The author has incorporated this guidance, particularly around using subshells for reliable test cleanup on Windows. The series represents significant progress in packed-refs validation while leaving the door open for future work on backend-agnostic validation architecture.
