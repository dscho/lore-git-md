This is patch 9/10 in a series adding comprehensive ref consistency checks, specifically focusing on verifying the sort order of packed-refs entries. The patch builds on the validation infrastructure established in previous patches, particularly leveraging the `fsck_packed_ref_entry` struct introduced in patch 7.

The key technical addition is a new check that ensures packed-refs entries are sorted by refname, which is a requirement for correct operation. Rather than storing refnames in memory-intensive strbufs, the implementation cleverly reuses the existing `snapshot_record` structure and `cmp_packed_ref_records` comparison function. A new `packed_fsck_ref_sorted()` function performs the validation, reporting errors through the established fsck infrastructure with a new `FSCK_MSG_PACKED_REF_UNSORTED` message type.

The patch includes thorough test coverage demonstrating detection of unsorted refs in both regular and peeled tag cases. Error messages clearly indicate the problematic line numbers and refnames. The implementation maintains the series' pattern of building validation incrementally while reusing existing comparison logic where possible.
