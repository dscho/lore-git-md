This is part 3 of a 10-patch series adding comprehensive ref consistency checks, focusing on verifying that the "packed-refs" file is a regular file. The series builds on the author's GSoC work to strengthen Git's validation of ref storage.

The patch adds a check in the packed backend to ensure "packed-refs" is a regular file (not a symlink or special file) using `lstat()` and reporting issues via the existing `FSCK_MSG_BAD_REF_FILETYPE` message. The change is straightforward but important - while Git expects "packed-refs" to be a regular file created by its own commands, it previously didn't enforce this. The patch includes a test that verifies the check catches symlinks.

This continues the series' pattern of methodically adding validation checks before the final fsck integration. The change is well-contained (33 lines added/modified) with clear test coverage. As with earlier patches, it follows established patterns by reusing existing fsck infrastructure rather than inventing new mechanisms.
