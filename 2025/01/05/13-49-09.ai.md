This is the first patch in a 10-part series adding comprehensive ref consistency checks, focusing on object existence verification for regular refs in the files backend.

The patch introduces a new `files_fsck_refs_oid()` function that performs two key validations when checking ref contents: (1) it verifies the referenced object exists via `parse_object()`, and (2) for branch refs specifically, confirms the object is a commit. Both failures report using the existing `FSCK_MSG_BAD_REF_CONTENT` message ID. The validation skips promisor objects to avoid unnecessary network fetches.

The changes touch core ref verification logic in `refs/files-backend.c`, adding 50 lines while restructuring the error handling flow. Tests in `t0602-reffiles-fsck.sh` expand significantly (30 new lines) to cover:
- Missing object cases using test OIDs 001 and 002
- Branch refs pointing to tree objects
- The new checks' interaction with existing content validation

The implementation appears careful, with clear error messages and thorough test coverage. It follows the pattern of the series' stated goal to mirror parsing logic in verification, here ensuring ref contents point to valid objects of the correct type. The patch lays groundwork for subsequent validations while being independently useful for catching corrupt or invalid refs.
