Maintainer response on object name parsing strategy

Junio Hamano responds to Elijah Newren's patch fixing curly brace handling in object names, while also discussing broader parsing strategy. The immediate patch (which fixes a 2006-era bug where Git incorrectly assumed braces only appear paired after '@' or '^') is queued for consideration post-2.48 release.

Hamano outlines a more comprehensive left-to-right parsing approach that could handle ambiguous cases by trying interpretations in sequence, noting this would be a larger architectural change than the current targeted fix. He describes how this strategy would work for cases like `foo@{some:thing}` (trying reflog interpretation after treeish fails) and `foo:path-gaffed` (trying describe output after path resolution fails).

While acknowledging the current patch's approach is more surgical, Hamano's comments suggest this may be just the first step toward a more systematic handling of ambiguous object names. The discussion continues to balance immediate fixes against long-term parsing architecture, with the maintainer signaling openness to both approaches at different timescales.
