Feature proposal for `git describe` to consider untracked files in dirty state detection.

Ross Goldberg proposes adding a new `--untracked-is-dirty` option to `git describe` that would make untracked (but not ignored) files trigger the dirty marker when used with `--dirty`. Currently, `--dirty` only marks the repository as dirty for modified/deleted tracked files (staged or unstaged) and newly staged files, but ignores untracked files. The author suggests this could alternatively be implemented via a syntax change (replacing `--dirty=<mark>` with `--dirty:<mark>`) if adding a new option is undesirable.

The proposal acknowledges there may be other file status categories users might want to consider as well, suggesting any solution should be extensible. The email does not provide specific use cases but implies the current behavior may be surprising when untracked files are present. The change would affect the behavior of `git describe`'s dirty state detection, potentially making it more comprehensive by default or configurable via the new option. No implementation is provided - this is purely a feature request to gauge interest and discuss design options.
