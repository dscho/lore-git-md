This is a follow-up refinement to Jeff King's bugfix for the `git diff-tree --cc` segfault issue. Wink Saville proposes a small but meaningful improvement to the recently merged solution that replaced strbuf paths with char pointers in the combine-diff implementation.

The suggestion focuses on making the code's intent clearer by renaming the `path` field in `struct combine_diff_parent` to `changed_path` and adding an explanatory comment. This better reflects the field's purpose - it only stores paths when they differ from the main path (otherwise it remains NULL). The attached patch shows the straightforward changes needed across diff.h and combine-diff.c.

This comes after the core technical solution (switching from strbuf to char* with proper initialization) was already validated to fix both the immediate segfault and underlying design concerns. The naming tweak doesn't affect functionality but improves code clarity, building on the thread's earlier work to make the combine-diff path handling more robust while preserving its deduplication optimization.
