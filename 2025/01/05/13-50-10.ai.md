Bugfix and refactoring patch in the packed-refs validation series.

This is patch 7/10 in a series adding comprehensive validation checks for packed-refs files, ultimately to be integrated into `git fsck`. The patch introduces a new `fsck_packed_ref_entry` struct to store parsing information during validation, avoiding premature termination when checking object existence.

The key technical change is the introduction of this new struct which tracks:
- Line numbers for error reporting
- Whether each entry has a peeled line (for tags)
- The parsed OIDs (both main and peeled)

The patch modifies the validation functions to:
- Store parsed information rather than checking objects immediately
- Handle memory allocation/cleanup for the entry tracking
- Maintain the same validation logic but defer object existence checks
- Preserve all existing error reporting capabilities

This solves a specific problem where direct object checking during parsing could trigger fatal errors via `create_snapshot()` calls. The change allows the validation to complete fully before any potentially dangerous checks are performed, controlled by the `safe_object_check` flag.

The implementation follows the series' pattern of thorough validation while maintaining the existing packed-refs parsing logic. It builds on previous patches' line-by-line validation while adding this new layer of state tracking. The memory management appears careful with proper allocation growth patterns and cleanup.

This is a foundational change enabling the subsequent object existence validation in patch 8, while itself being a pure refactoring that doesn't change the validation behavior - it just changes when and how the validation state is stored. The patch maintains the series' high standard of test coverage, though no new tests are added here as the behavior change is internal.
