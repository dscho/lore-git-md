This is a technical discussion about Windows reftable backend compatibility, specifically addressing file unlinking behavior. Patrick Steinhardt responds to Johannes Sixt's alternative proposals for handling file-in-use errors on Windows systems.

The exchange clarifies a key misunderstanding: while the reftable library itself doesn't require POSIX unlink semantics (and can tolerate failed deletions), it currently inherits Git's POSIX-emulating behavior through the `unlink()` implementation. Steinhardt confirms the original patch's goal was to disable this emulation specifically for reftable use cases.

The discussion reveals two distinct approaches on the table:
1. Sixt's suggestion to use Windows-specific `CreateFileW` with `FILE_FLAG_DELETE_ON_CLOSE`
2. The original approach of selectively disabling POSIX emulation for reftable

Steinhardt expresses caution about modifying Git's core `unlink()` behavior due to its widespread use, while acknowledging the reftable library's unique tolerance for failed deletions. The email highlights the ongoing challenge of balancing Windows platform constraints with Git's cross-platform expectations, with both participants working to clarify their technical positions.
