This is a discussion thread continuation about the reftable library refactoring series that aims to achieve full independence from Git's core infrastructure. Junio Hamano acknowledges Patrick Steinhardt's work to replace Git-specific helpers with POSIX implementations and open-coding, but raises an important maintenance question about keeping these reftable-specific implementations in sync with future improvements to Git's original helpers.

The key new consideration is the long-term maintenance burden of having parallel implementations - if Git improves its I/O utilities or error handling, those improvements won't automatically propagate to reftable's now-independent versions. Junio suggests (while expressing uncertainty) that a shared library might be needed, but recognizes this could recreate the original dependency situation the series aimed to eliminate.

This email doesn't propose concrete solutions but rather opens the floor for discussion among the "libification" contributors about how to handle this architectural tradeoff between independence and maintainability. The thread context shows this comes after extensive technical work to achieve the separation (19 patches replacing Git helpers with POSIX equivalents) and some review discussion about specific implementation choices, but now raises higher-level design questions about the project's long-term direction.
