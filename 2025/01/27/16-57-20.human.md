This is a refactoring patch in a series decoupling reftable from Git's core utilities. Justin Tobler raises two technical questions about Patrick Steinhardt's initial patch that replaced `read_in_full()` with direct POSIX operations:

1. The patch casts `off_t` to `size_t` when reading file contents, which matches current behavior but may not be safe on all platforms. Justin suggests considering a reftable-specific equivalent to Git's `xsize_t()` for safer conversions.

2. The new error handling for `EAGAIN` and `EINTR` doesn't match Git's more comprehensive `xread()` behavior. Justin questions whether this simplified approach is sufficient for reftable's needs.

The discussion focuses on implementation details of the transition away from Git-specific I/O functions, with Justin probing edge cases that might need attention as the library becomes more standalone. These are thoughtful technical follow-ups to the first patch in a major refactoring series.
