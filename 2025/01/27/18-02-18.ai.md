Junio Hamano responds to Christian Couder's Large Object Promisor (LOP) design document with technical concerns about implementation specifics. This is part of the ongoing discussion around the promisor-remote/LOP series (currently at v4).

Key points raised:
1. Objects that the document's description of blob handling lacks concrete implementation details, making it appear to rely on "magical object storage" rather than explaining practical optimization strategies for using services like S3/GCP.

2. Questions the completeness of the design regarding client-side blob management, particularly around versioned large objects (like media files) where clients might want to offload older versions. Notes the document doesn't clarify whether such objects should first go through main remote validation.

3. Acknowledges Couder's response about existing storage services but maintains the critique that the document still doesn't address how Git would practically interface with these services for efficient large blob handling.

The exchange highlights two unresolved aspects of the LOP design:
- Missing technical specifics about blob storage optimization strategies
- Unclear policies around versioned object offloading and remote validation

This continues the thread's pattern of Junio pushing for more concrete implementation details and clearer user-facing behavior specifications in the LOP system design.
