Review feedback on promisor-remote security controls in Christian Couder's LOP series. Junio Hamano provides detailed technical review of patch 5/6, which adds "KnownName" and "KnownUrl" options to the `promisor.acceptFromServer` configuration. The patch allows more granular control over which promisor remotes a client will accept from a server's advertisements.

Key technical points addressed:
- Questions the security model assumptions behind case-insensitive name/URL matching
- Suggests renaming `strvec_find_index()` to be more specific (`remote_nick_find`) or making it a proper public API
- Recommends against case-insensitive URL comparison (schema://host should be case-insensitive but paths generally case-sensitive)
- Notes potential config API edge cases with uninitialized strings
- Praises the comprehensive test coverage while pointing out missing test cases for case sensitivity

The review maintains the ongoing thread's focus on security mechanisms while introducing new implementation concerns about string comparison semantics and API design. Junio's feedback indicates the patch is functionally sound but could benefit from tighter string handling and clearer public/private API boundaries. The discussion continues to balance security controls with practical deployment scenarios in corporate environments.
