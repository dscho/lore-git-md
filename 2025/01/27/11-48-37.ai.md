This is a follow-up in the ongoing bugfix thread about `git fetch` tag behavior in shallow clones. Danila Manturov confirms that Bence Ferdinandy's proposed patch (which reorders tag/HEAD prefix additions in `do_fetch()`) will help maintain backward compatibility for their use case where Git commands are programmatically generated. The email doesn't introduce new technical content but serves as positive feedback on the proposed solution from an affected user.

Key points from context: The patch moves the `HEAD` prefix addition before tags in the ref prefixes list, which appears to resolve the shallow clone tag fetching regression that was protocol-dependent (working with JSch but failing with native SSH/HTTPS). While the fix works empirically, the underlying reason why prefix ordering affects behavior remains unclear, suggesting this may be addressing symptoms rather than root causes. The thread has progressed from initial bug report through protocol-specific behavior analysis to this proposed code change.
