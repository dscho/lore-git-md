This is part 4/6 of Christian Couder's v4 series introducing protocol v2 support for promisor remotes (Large Object Promisors/LOPs). The patch adds a new "promisor-remote" capability to protocol v2, allowing servers to advertise promisor remotes they use so clients can optionally fetch objects directly from those remotes.

The key additions are:
- Server-side `promisor.advertise` config to control capability advertisement
- Client-side `promisor.acceptFromServer` config to control which advertised remotes to use
- Protocol format for exchanging promisor remote names and URLs
- Infrastructure to parse and handle these capabilities during protocol negotiation

The implementation is thorough, with new documentation, protocol specs, and extensive tests in t5710 that verify the config options and protocol behavior. The patch builds on previous work standardizing string handling and memory management in the series. It's a well-motivated addition that could help optimize large object fetches by allowing clients to bypass intermediate servers when possible.
