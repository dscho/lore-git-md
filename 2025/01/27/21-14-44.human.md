Junio Hamano responds to Christian Couder's v4 promisor-remote/Large Object Promisor (LOP) series, focusing on patch management concerns. This is part of the ongoing discussion about introducing a "promisor-remote" capability for better large file handling in client-server scenarios.

The key issue raised is about shared foundational patches between this series and another unrelated work by Usman Akinyemi. Junio notes that having multiple in-flight series sharing early patches creates maintenance headaches, as any changes to those shared patches would require coordinated rebases across all dependent series. He suggests the typical Git project approach would be to pause both efforts and solidify the shared foundation first.

While Junio acknowledges the improvements in this version (better commit messages, code changes, and test adjustments in patch 4/6), his primary concern is about the project management implications of the shared patch situation. He queues the series but flags this as something that needs a better long-term solution.

The email doesn't address the MIDX compatibility questions from earlier in the thread, keeping the focus on the patch organization concerns. This suggests those technical discussions may be happening in parallel or awaiting input from Taylor Blau.
