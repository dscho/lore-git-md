This is a refactoring patch in the ongoing reftable independence series, specifically addressing error handling in record initialization. The patch changes `reftable_record_init()` to return an error code (`REFTABLE_API_ERROR`) when encountering an unknown record type, rather than calling Git's `BUG()` which would abort the program. This is part of the broader effort to remove Git-specific dependencies from the reftable library.

Justin Tobler reviews the change and agrees with using `REFTABLE_API_ERROR` for this case, as it matches the documented use case for API misuse. He considers but dismisses the alternative of adding a more specific error type for unsupported record types as unnecessary. The change maintains the series' goal of making reftable a standalone library while preserving functionality through careful error handling conversion.

The patch (05/19) follows earlier conversions of Git-specific utilities and precedes further replacements of Git helpers in the series. It demonstrates the systematic approach being taken to eliminate Git dependencies while maintaining robust error handling semantics. The review suggests the technical approach is sound, with no outstanding concerns raised about this particular conversion.
