This is part 11 of a 19-patch series decoupling the reftable library from Git's core infrastructure. The patch introduces a new `reftable_rand()` function to replace direct calls to Git's `git_rand()` for random number generation.

The change creates a reftable-specific wrapper around `git_rand()` that returns a single unsigned integer, with the implementation meant to be provided by the calling codebase. This allows better integration with pre-seeded RNGs in other projects using reftable. The patch updates two call sites in reftable/stack.c that previously used `git_rand()` directly - one for retry delay calculation and another for generating unique filenames.

This continues the series' pattern of systematically replacing Git-specific functionality with reftable-specific interfaces while maintaining the same behavior. The change is straightforward and mechanical like previous patches in the series, with clear testable behavior preserved. The commit message could benefit from mentioning why this particular change is valuable for reftable's independence, though the technical implementation appears sound.
