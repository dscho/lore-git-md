Performance optimization patch series introducing configurable name hashing for pack-objects delta compression. This is the fourth version of a series that originally proposed a `--full-name-hash` option but has evolved into a more flexible `--name-hash-version` approach after extensive review.

The series addresses suboptimal delta compression in repositories where files at the same path across versions fail to connect due to limitations in Git's current name hashing (which focuses narrowly on path endings). The key technical changes:

1. Introduces `--name-hash-version` with two implementations:
   - Version 1 preserves existing behavior
   - Version 2 implements Jonathan Tan's improved path-component hash with:
     - Better non-ASCII handling
     - Directory hierarchy awareness via XOR operations with downshifted parent hashes
2. Removes the previously proposed Version 3 (full-name-hash) after review determined its benefits didn't outweigh maintenance costs
3. Adds comprehensive testing including:
   - New performance tests (p5313, p5314)
   - Test helper for hash value verification
   - Bitmap compatibility safeguards
4. Integrates with `git repack` via option passthrough

Performance data from JavaScript repositories shows Version 2 achieving dramatic size reductions (e.g., 37GB → 7GB in one case) while maintaining compatibility with existing workflows. The series is now in final form with all substantive concerns addressed, having undergone rigorous review rounds from Taylor Blau and others. Only minor style nits remain for v4.
