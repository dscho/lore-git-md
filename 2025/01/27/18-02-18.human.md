Junio Hamano responds to Christian Couder's Large Object Promisor (LOP) design document with concerns about the practical implementation details. While acknowledging existing storage solutions like S3 and GCP Bucket, Hamano argues the document handwaves the critical "how" of efficiently using these high-latency services for Git objects. He specifically questions the offloading behavior - whether clients can directly send object versions to LOPs without main remote validation, noting this ambiguity could hinder real-world usage. The exchange reveals important unresolved questions about LOP's operational boundaries and validation requirements that need clarification before the design can be considered complete. This is part of an ongoing technical discussion about making large blob handling practical while maintaining Git's integrity guarantees.
