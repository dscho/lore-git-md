Refactoring patch in the reftable library's independence effort, specifically addressing error handling.

This seventh patch in the 19-part series continues the systematic removal of Git-specific dependencies from the reftable library by eliminating remaining uses of `BUG()`. The changes replace hard program aborts with proper error returns using the reftable-specific `REFTABLE_API_ERROR` code, maintaining the library's goal of being a portable, standalone component.

The patch modifies three key areas:
1. The indexed table iterator's seek operation now returns an error code rather than aborting when called (a documented unsupported operation)
2. Reader reference counting removes `BUG()` checks entirely, as the zero-count case would already indicate undefined behavior from a freed structure
3. Writer operations now return errors for invalid block sizes and type mismatches rather than aborting

These changes align with the series' pattern of replacing Git-specific behaviors while preserving functionality. The commit message notes the careful consideration given to cases where `BUG()` was previously used for impossible conditions, opting for either error returns or complete removal of the checks where appropriate. The changes are behavior-preserving for valid usage while providing better error handling for API misuse.

This continues the mechanical but important work of making reftable independent of Git's core infrastructure, with each patch focusing on a specific dependency to remove. The changes here touch core reader/writer operations but maintain all existing functionality through the new error handling approach.
