Patrick Steinhardt's v5 series (18 patches) marks the final stage of separating the reftable library from Git's core infrastructure, making it usable by external projects like libgit2. The series has undergone extensive review across multiple versions, with all major technical concerns addressed by v5 - including build system integration, memory safety, and I/O independence. 

The first patch in v5 removes one of the last Git-specific dependencies by open-coding `read_in_full()` in reftable/stack.c rather than using Git's version. This maintains the same read loop but omits Git-specific error handling for `O_NONBLOCK` (unneeded by reftable) while keeping error reporting within the reftable system. The change follows the series' pattern of carefully replacing Git helpers with equivalent standalone functionality.

Key reviewers like Junio Hamano (I/O/build concerns), Justin Tobler (memory safety), and Toon Claes (attribute usage) have signed off on earlier versions, with only a minor header inclusion style question remaining open from earlier discussions. The series is now technically complete, representing a significant architectural milestone that cleanly separates reftable while preserving all functionality through the designed system.h interface.
