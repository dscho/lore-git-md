This thread documents Patrick Steinhardt's substantial effort to decouple the reftable library from Git's core infrastructure, making it portable for standalone use by projects like libgit2. The series has grown to 20 patches (from 19 in v1) and has addressed feedback from both Junio Hamano (maintenance concerns) and Justin Tobler (type safety/I/O handling).

The latest patch continues the systematic replacement of Git-specific utilities, this time on memory mapping functionality. It replaces Git's `xmmap()` wrapper with direct `mmap()` calls in the reftable blocksource implementation, while carefully preserving error semantics and resource cleanup. This follows earlier conversions of read/write operations and completes the I/O utility overhaul.

Key architectural changes so far include replacing Git's I/O utilities with reftable-specific POSIX equivalents, introducing proper error handling (REFTABLE_API_ERROR), and reorganizing platform compatibility layers. The implementation maintains careful attention to error propagation and type safety, particularly around `off_t` to `size_t` conversions. Junio and Justin have both engaged with the technical details, and Patrick has been responsive to their feedback about code duplication and maintenance tradeoffs.

The series demonstrates steady progress toward complete decoupling, with each iteration showing both technical rigor and responsiveness to review. The reftable library is now very close to full independence from Git's core infrastructure while maintaining its functionality across platforms.
