This thread documents a 19-patch series refactoring Git's reftable library to become fully portable and independent from Git's core infrastructure. The goal is to enable standalone use by projects like libgit2 by systematically replacing Git-specific helpers with direct POSIX calls or reftable-specific implementations. The series has progressed through fourteen patches so far, each carefully replacing dependencies like `read_in_full()`, `write_in_full()`, `xmmap()`, and various Git macros while maintaining identical behavior and error semantics.

The latest patch (15/19) focuses on Windows compatibility, reorganizing the mingw.h header into two separate files: mingw/posix.h for POSIX emulation and mingw/compat-util.h for Git-specific Windows utilities. This change cleanly separates concerns while maintaining all existing functionality, including UTF-8/UTF-16 conversion and SSL wrappers. The patch updates all build systems (Makefile, CMake, meson) to reflect the new organization and ensures MSVC compatibility remains intact.

Patrick Steinhardt is the primary author driving this architectural effort, with each patch following a consistent pattern of focused, behavior-preserving changes. The series represents the final stages of making reftable a truly standalone library, with only four patches remaining after this Windows compatibility reorganization. Review feedback has been minimal so far, suggesting the approach is sound and the changes are well-contained.
