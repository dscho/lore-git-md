The reftable library separation effort continues to make steady progress in Patrick Steinhardt's v6 series. The latest patch replaces Git's `xmmap()` with direct `mmap()` usage in the blocksource implementation, following the established pattern of removing Git-specific dependencies while maintaining functionality. This change improves error handling by properly returning REFTABLE_IO_ERROR instead of fatal errors when memory mapping fails.

The 18-patch series has already addressed all major technical concerns, with core maintainers approving the architectural approach. The changes systematically replace Git helpers with reftable-native or POSIX-compatible alternatives across 25 files, with only final confirmation from Johannes Schindelin remaining before merge. This work is the final step in enabling reftable's use by external projects like libgit2, while maintaining compatibility through a new compat/posix.h layer. The series has been carefully reviewed for Windows support, memory safety, and coding style by multiple domain experts.
