Patrick Steinhardt's v5 series (18 patches) is nearing completion of its goal to fully decouple the reftable library from Git's core infrastructure. The series has systematically replaced Git-specific dependencies with self-contained implementations, addressing all major technical feedback from reviewers like Junio Hamano, Justin Tobler, and Johannes Sixt.

The latest patch (11/18) introduces a new `reftable_rand()` function to abstract random number generation, completing the isolation of reftable's system dependencies. While it currently wraps Git's `git_rand()` internally as a transitional step, the interface is designed to eventually allow external callers to provide their own RNGs. This change affects two specific uses in stack.c: calculating retry delays during stack reloading and generating random filename suffixes.

This follows the series' established pattern of utility replacements, which has now completed the conversion of I/O operations, memory operations, error handling, comparison operations, endian conversion, and array utilities (with the final `ARRAY_SIZE` usage recently removed). The only remaining open question is about header inclusion style from earlier discussions, but no new technical concerns have been raised. With all major feedback addressed, the series appears technically complete and ready for merging, representing a significant architectural milestone in making reftable usable by external projects while preserving Git's internal behavior.
