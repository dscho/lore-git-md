Patrick Steinhardt continues his work to fully decouple the reftable library from Git's core infrastructure with a new patch in his v3 series. The latest change introduces a reftable-specific random number generation interface, replacing direct calls to Git's RNG while maintaining the same behavior. This affects two non-critical uses in stack.c for generating temporary filenames and retry delays.

The architectural separation is now nearly complete, with all major Git dependencies removed except for final verification of I/O implementations. The series has addressed all substantive feedback from reviewers including Junio Hamano's concerns about low-level I/O and Justin Tobler's memory safety points. What remains is essentially polishing - this latest patch follows the established pattern of mechanical replacements that maintain identical functionality while providing cleaner abstraction boundaries for external consumers. The changes are well-contained and low-risk, primarily affecting debug and retry functionality rather than core reftable operations.
