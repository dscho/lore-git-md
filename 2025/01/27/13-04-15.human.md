This is part 7 of a 19-patch series refactoring the reftable library to remove Git-specific dependencies. The patch continues the systematic replacement of Git's `BUG()` macro with proper error handling in the reftable codebase.

The changes convert several cases where `BUG()` was previously used for invalid API usage into proper error returns of `REFTABLE_API_ERROR`. Notable changes include removing `BUG()` checks in reference counting functions (where hitting zero would indicate already-freed memory anyway), replacing a block size validation `BUG()` with an error return, and converting an unsupported seek operation's `BUG()` to an error. The writer's record type validation also returns an error rather than aborting.

The patch maintains the series' consistent approach of preserving behavior while removing Git-specific constructs. The commit message explains the rationale clearly, particularly noting that the refcount changes are safe since zero counts would already indicate undefined behavior. This continues the thread's goal of making reftable a standalone library with proper error handling rather than Git-specific assertions.
