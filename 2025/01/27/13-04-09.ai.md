Refactoring patch in the reftable independence series. This is the first of 19 patches decoupling reftable from Git's core utilities, specifically targeting `read_in_full()` usage.

The patch replaces the single remaining `read_in_full()` call in reftable/stack.c with direct POSIX read operations. The new implementation handles partial reads and EAGAIN/EINTR retries explicitly, maintaining the same error semantics but without Git's helper function. The change affects the `fd_read_lines()` function which reads file contents into a buffer for processing reftable stack files.

Key technical details: The replacement uses a loop with `read()` calls tracking total bytes read, with explicit error handling for partial/interrupted reads. The buffer management and error paths remain otherwise unchanged. This is a mechanical but important step in removing Git-specific dependencies from the reftable library.

The patch follows the series' pattern of replacing Git utilities with direct POSIX equivalents while preserving functionality. It touches core file I/O operations but maintains backward compatibility in behavior. The change is straightforward with clear error handling, though it does increase code complexity slightly by open-coding what was previously a library function.
