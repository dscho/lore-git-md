This is part 4/6 of Christian Couder's v4 series introducing protocol v2 support for promisor remotes (Large Object Promisor/LOP functionality). The patch adds a new "promisor-remote" capability to protocol v2, allowing servers to advertise promisor remotes to clients.

Key technical elements:
- New server config `promisor.advertise` (default false) controls whether to advertise promisor remotes
- New client config `promisor.acceptFromServer` (default "None") controls which advertised remotes to accept
- Capability format includes urlencoded remote names and optional URLs
- Server-side implementation in `promisor-remote.c` with new functions for capability handling
- Client-side response handling in `connect.c`
- Comprehensive test suite in t5710 covering various config combinations

The capability enables servers to suggest alternative object sources (like better-connected remotes) while maintaining security boundaries - proxy configs and other Git-external details remain the client's responsibility. The series appears well-considered with thorough documentation and testing, building on prior feedback to reach a stable design.
