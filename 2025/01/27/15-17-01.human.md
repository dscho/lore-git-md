This is a documentation patch adding a technical design document for the Large Object Promisors (LOP) feature, which is part of Christian Couder's ongoing series to improve handling of large blobs in Git. The document serves as the capstone to the v4 series, providing comprehensive background and design rationale.

The 640-line technical document outlines a server-side solution for storing large binary blobs on dedicated promisor remotes (LOPs) as an alternative to Git LFS. It describes seven key features including protocol negotiation between clients and servers, configurable offloading thresholds, and integration with object storage backends like S3. The document carefully delineates scope (focusing on server-side improvements while acknowledging client-side needs as out of scope) and includes an FAQ addressing security, backward compatibility, and deployment considerations.

The design positions LOPs as complementary to existing solutions, with particular attention to corporate environments where client upgrades can be coordinated. It's a thorough piece of technical writing that should help reviewers and future maintainers understand the architectural decisions behind the code changes in the series. The document shows careful consideration of edge cases and migration paths while maintaining clear boundaries with related efforts like pluggable ODBs.
