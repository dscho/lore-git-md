Patrick Steinhardt's 18-patch v6 series to architecturally separate the reftable library from Git core continues progressing, with the latest patch replacing Git's `xmmap()` with direct `mmap()` usage in the blocksource implementation. This change systematically removes Git dependencies by handling memory mapping through either system `mmap(3p)` or Git's `git_mmap()` wrapper, while propagating reftable-specific error codes (REFTABLE_IO_ERROR) instead of fatal errors. The modification affects `reftable_block_source_from_file()` with proper resource cleanup on failure, following the established pattern of replacing Git helpers with reftable-native or POSIX-compatible alternatives.

The series has already addressed all major technical concerns through previous patches, including the replacement of `write_in_full()` with `reftable_write_data()` in stack.c, Windows build system conflicts via 541 lines of POSIX compatibility code, and removal of BUG() calls. Core maintainers have approved the architectural approach (Junio Hamano for I/O/build, Justin Tobler for memory safety, Johannes Sixt for include style, Toon Claes for macro usage), with only final confirmation from Johannes Schindelin remaining before merge. The changes span 25 files (+1405/-1155 lines), systematically decoupling reftable from Git internals while preserving functionality through the new compat/posix.h layer. This latest mmap refactoring represents another incremental step toward enabling reftable's external use by projects like libgit2, maintaining all existing behavior while removing another core Git dependency.
