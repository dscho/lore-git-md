This 19-patch series refactors the reftable library to achieve full portability and independence from Git's core infrastructure, systematically decoupling reftable from git-compat-util.h and Git-specific helpers to enable standalone use by projects like libgit2. The series demonstrates architectural separation through replacing Git I/O utilities with POSIX operations, eliminating Git-specific error handling, introducing reftable-specific utilities, and reorganizing platform compatibility layers.

Key technical changes include:
- Replacing Git's `read_in_full()`, `write_in_full()`, and `xmmap()` with direct POSIX equivalents while maintaining error semantics (with Justin Tobler raising concerns about type safety and I/O error handling adequacy)
- Converting Git's `BUG()` and assertions to reftable-specific error returns (REFTABLE_API_ERROR)
- Introducing reftable-specific versions of utilities like `reftable_alloc_size()`, `reftable_rand()`, and endian conversion functions
- Splitting MinGW/MSVC headers and extracting POSIX functionality into a new compat/posix.h
- Excluding reftable from Coccinelle processing in the final patch

Junio Hamano has now raised a maintenance concern about the long-term viability of maintaining parallel implementations - if Git improves its I/O utilities or error handling, those improvements won't automatically propagate to reftable's now-independent versions. While acknowledging the technical achievement of the separation, he questions whether a shared library approach might eventually be needed, though this could recreate the original dependency situation the series aimed to eliminate. This opens a higher-level design discussion about the tradeoff between independence and maintainability, coming after extensive technical work and review discussion about specific implementation choices. Justin Tobler's earlier technical questions about type safety and I/O error handling in the initial conversion remain open alongside this new architectural consideration.
