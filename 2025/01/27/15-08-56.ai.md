This is a protocol feature patch in Christian Couder's promisor-remote series, addressing Junio Hamano's feedback about the v3 submission. The patch introduces a "promisor-remote" capability for protocol v2 to coordinate object fetching between server (S) and client (C), allowing S to omit objects available from alternate promisor remotes (X) when C can fetch them directly.

Key changes in response to Junio's feedback:
- Replaced vague "should" directives with clearer rationale about the protocol benefits
- Added explicit statement that clients must handle their own network configuration (including proxy setup) rather than relying on the protocol
- Clarified that the immediate use case is for servers advertising their own promisor remotes, while leaving future extension possibilities open

The technical mechanism remains unchanged: server-side `promisor.advertise` and client-side `promisor.acceptFromServer` configs control the capability. Christian notes this is particularly useful for enterprise environments where repos share infrastructure, but carefully avoids protocol creep into network configuration details.

This iteration shows the design tightening in response to maintainer concerns about protocol scope and documentation clarity. The exchange reveals ongoing tension between enabling efficient object sharing and maintaining Git's traditional boundaries around network configuration. Christian positions this as a focused solution for the promisor-remote use case while explicitly ruling out broader network configuration distribution.
