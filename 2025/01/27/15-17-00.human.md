This is part 5/6 of Christian Couder's promisor-remote/Large Object Promisor (LOP) series, adding more granular control over which promisor remotes clients will accept from servers.

The patch introduces two new values for the `promisor.acceptFromServer` config option:
- `KnownName`: Accepts remotes that match existing client-side remote names (useful in trusted corporate environments)
- `KnownUrl`: More secure option requiring both name and URL to match existing client configuration

The implementation includes:
- New enum values and logic in `promisor-remote.c` to handle the additional validation cases
- String comparison helpers to match remote names/URLs case-insensitively
- Comprehensive test coverage in t5710 that verifies both successful and rejected cases
- Updated documentation explaining the new options and their security implications

This builds on the series' goal of giving clients fine-grained control over promisor remote acceptance while maintaining security boundaries. The tests demonstrate how the new options behave with mismatched names/URLs, showing the stricter validation of `KnownUrl` compared to `KnownName`. The implementation looks thorough, with careful handling of string comparisons and memory management.
