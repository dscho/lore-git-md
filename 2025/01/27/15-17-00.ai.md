This is part 5/6 of Christian Couder's promisor-remote/Large Object Promisor (LOP) series, introducing finer-grained client-side control over which promisor remotes to accept from servers. The patch adds two new values ("KnownName" and "KnownUrl") to the existing "promisor.acceptFromServer" configuration option, which previously only supported "None" or "All". "KnownName" allows accepting remotes that match locally configured names, while "KnownUrl" requires both name and URL to match - the latter being the more secure option. 

Implementation includes:
- New enum values ACCEPT_KNOWN_NAME and ACCEPT_KNOWN_URL in promisor-remote.c
- A strvec_find_index() helper for case-insensitive string matching
- Enhanced should_accept_remote() logic to check name/URL matches against local config
- Updated filter_promisor_remote() to handle the new modes
- Comprehensive test cases in t5710 verifying the new acceptance behaviors
- Documentation updates explaining the security tradeoffs

The changes maintain the series' focus on security boundaries while providing more flexible deployment options, particularly for corporate environments where some trust exists between servers and clients. Test coverage is thorough, verifying both successful acceptance cases and rejection scenarios where names or URLs don't match.

This continues the series' pattern of incremental improvements to the promisor remote capability handling, building on the protocol v2 foundation established in earlier patches. The implementation appears clean and well-tested, with clear documentation of the new options' security implications.
