Bugfix in the reftable library's record comparison logic, part of the larger reftable independence effort. This patch (6/19 in the series) addresses a specific issue where `reftable_record_cmp()` would call `BUG()` when comparing records of different types - an undesirable behavior for library code that should gracefully handle errors. Patrick Steinhardt's change converts this to return an error code (REFTABLE_API_ERROR) while maintaining the comparison result in a separate output parameter, requiring adjustments to callers up the stack.

The change exemplifies the series' broader goal of removing Git-specific behaviors (like `BUG()`) from reftable. Justin Tobler notes a typo in the commit message ("refatble") but doesn't raise substantive concerns about the technical approach. The patch appears to be a straightforward conversion with no obvious complications, though it does require coordinated changes to multiple call sites to handle the new error return convention.
