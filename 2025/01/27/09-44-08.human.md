Bugfix for uninitialized memory in reftable backend affecting multi-worktree operations.

Patrick Steinhardt is submitting this patch on behalf of Karthik Nayak, who is currently unavailable. This is version 4 of the patch, with only commit message refinements from the previous version.

The patch fixes an issue in the reftable backend where the `max_index` field was only being set for the first transaction argument when writing to multiple worktrees simultaneously. This could lead to uninitialized memory access for subsequent worktrees. The fix moves the assignment inside the processing loop and adds defensive initialization of the field to zero.

The problem was originally reported by Johannes Schindelin and relates to maintaining proper ordering of reflog entries during backend migrations. The reftable backend uses update indices to preserve this ordering, and the uninitialized values could potentially corrupt this process.

The changes are minimal and focused - just 3 lines modified in `refs/reftable-backend.c`. The patch appears well-considered, with clear explanations of both the technical issue and the solution. The additional initialization, while not strictly necessary, shows good defensive programming practices.
