Maintainer feedback on refspec function naming and documentation

This is Junio Hamano providing detailed review feedback on the first patch of Meet Soni's refspec reorganization series. While the patch itself (moving refspec matching functions from remote.c to refspec.c) is sound, Junio focuses on improving the API design now that these functions are becoming more public.

Key points raised:
1. Function names like `omit_name_by_refspec` were acceptable as internal helpers but need reconsideration as public API - suggesting `refname_matches_negative_refspec_item` as more descriptive
2. Parameter naming could be more precise (e.g., "name" → "refname") to better convey expected inputs
3. Documentation should explain the function's purpose and caller use cases rather than just restating implementation behavior
4. Suggests a two-step process for such changes: first improve naming/docs in place, then move the improved version
5. Provides specific examples of how to better document `match_name_with_pattern`, explaining the refspec globbing behavior

The feedback doesn't block the current series but offers concrete suggestions for follow-up improvements to the API design. Junio acknowledges these naming/documentation issues existed before the move and could be addressed separately. The tone is constructive, focusing on making the codebase more maintainable long-term rather than criticizing the current work.
