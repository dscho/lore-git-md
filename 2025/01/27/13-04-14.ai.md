This is patch 06/19 in a series refactoring the reftable library to remove Git-specific dependencies. The patch focuses on error handling in record comparison operations.

The key change replaces a `BUG()` call in `reftable_record_cmp()` with proper error handling when comparing records of different types. Previously, this would abort the program, which is undesirable for library code. The new implementation returns an error code while maintaining the comparison result through an output parameter.

The patch affects several components:
- Modifies `reftable_record_cmp()` to return REFTABLE_API_ERROR for type mismatches
- Updates the priority queue implementation (`pq.c`) to handle the new error returns
- Adjusts callers in `merged.c` to properly propagate comparison errors
- Updates all unit tests to check for and handle the new error conditions

The changes are systematic and maintain backward compatibility while removing another Git-specific behavior (the `BUG()` macro). This continues the series' pattern of making reftable more suitable as a standalone library by replacing Git-specific constructs with portable error handling.

The patch touches core record comparison logic but appears to be a straightforward mechanical conversion with comprehensive test coverage. It follows the same careful approach as previous patches in the series, maintaining behavior while removing Git dependencies.
