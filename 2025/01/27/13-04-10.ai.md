This is the second patch in a 19-part series refactoring the reftable library to remove Git dependencies. It follows the same pattern as the first patch by replacing Git's `write_in_full()` helper with a reftable-specific implementation called `reftable_write_data()`.

The new function handles partial writes and EAGAIN/EINTR retries explicitly while maintaining the same error semantics as the original. The implementation uses a write loop with byte tracking, similar to the read loop introduced in patch 01. The changes affect three call sites in stack.c where table data and lock files are written.

Key technical details include:
- New `reftable_write_data()` function in stack.c that implements the write loop
- Return value maintains compatibility with existing error handling (returns REFTABLE_IO_ERROR on failure)
- All call sites updated to use the new function instead of `write_in_full()`
- Part of systematic replacement of Git utilities across the reftable codebase

This is a straightforward mechanical change that continues the series' goal of removing Git dependencies while preserving behavior. The patch demonstrates the consistent approach being taken across the series - replacing each Git helper with a reftable-specific implementation that provides the same functionality.
