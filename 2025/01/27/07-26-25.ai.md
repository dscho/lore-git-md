This is a follow-up question in a thread about type safety improvements in Git's commit parsing code, specifically addressing MSVC compiler warnings. The thread has been systematically converting integer types in commit.c to more appropriate size types (size_t for lengths, ssize_t for positions).

Patrick Steinhardt points out that while Sören Krecker's patch (v3 4/4) changes the `len` parameter of `find_invalid_utf8()` from `int` to `size_t`, the local `offset` variable remains as `int`. This appears inconsistent with the series' goal of proper type safety, as `offset` is used to track positions within the buffer and could theoretically exceed INT_MAX on large inputs.

The observation suggests the patch may need one more adjustment to fully align with the series' type safety goals. This is a pattern seen throughout the thread where both buffer lengths and position trackers are being updated to size-appropriate types. No response from the original author is shown yet.
