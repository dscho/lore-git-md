This is a discussion about the final design decision for the OS version capability in Git's protocol.

Christian Couder weighs in on Junio Hamano's suggestion to merge the new OS version information into the existing "agent" capability rather than keeping it separate. Christian argues strongly against this approach, pointing to the web browser User-Agent header as a cautionary tale of what happens when too much information gets crammed into a single field. He notes that browser User-Agent strings have become difficult to parse and prone to spoofing, while also leaking privacy information.

Christian highlights that Git's capabilities system was specifically designed to avoid this problem by having separate capabilities for different features, as documented in the protocol specification. He quotes the existing documentation that state the "agent" capability "MUST NOT be used to programmatically assume the presence or absence of particular features," suggesting that adding OS version information would violate this principle.

This email represents the final substantive discussion point before the series can be merged, with Christian providing a clear rationale for maintaining the current design of a separate capability. The argument is well-reasoned and grounded in both Git's existing design philosophy and real-world examples of what happens when this approach isn't followed.
