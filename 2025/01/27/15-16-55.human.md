This is a feature patch series introducing a "promisor-remote" capability for Git's protocol v2, part of the ongoing Large Object Promisor (LOP) effort to better handle large files in client-server contexts. The series has reached its fourth iteration with significant documentation refinements and some code changes based on maintainer feedback.

The core addition is a new protocol capability that allows servers to advertise promisor remotes (like LOPs) to clients during clone/fetch operations. This enables more efficient large-blob handling by letting clients fetch directly from specialized storage rather than through the main server. The design document (patch 6/6) provides comprehensive technical details about the LOP approach and its benefits over alternatives like Git LFS.

Key changes in v4 include:
- Reusing string sanitization utilities from Usman Akinyemi's parallel work instead of implementing new ones
- Improved documentation language that's more assertive about the protocol direction
- Additional security considerations about proxy configurations
- Expanded future work section in the design doc
- Disabled problematic multi-pack-index tests that were causing issues

The series appears well-considered with thorough test coverage and has addressed previous maintainer concerns. The documentation improvements suggest the design is stabilizing, though some implementation refinements around lazy fetch security and client-side behavior remain open. This represents a significant step forward in Git's large object handling capabilities, particularly for enterprise environments.
