This is part 6 of a 19-patch series refactoring the reftable library to remove Git-specific dependencies. The patch focuses on error handling in record comparison.

The change modifies `reftable_record_cmp()` to return an error code when comparing records of different types, rather than calling Git's `BUG()` function. This makes the behavior more appropriate for library code where callers should handle errors gracefully. The patch updates all callers to check the new error return value, including priority queue operations in merged.c and pq.c, and updates corresponding unit tests.

The change is consistent with the series' goal of removing Git-specific code from reftable. The implementation looks thorough, touching all necessary call sites while maintaining the same comparison semantics when types match. The test updates demonstrate the new error handling works as expected.

This is a mechanical but important step in making reftable more self-contained. The patch appears well-executed with proper test coverage, though reviewers may want to verify the error propagation through the priority queue operations is handled correctly in all cases.
