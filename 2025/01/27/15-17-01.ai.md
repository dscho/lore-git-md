This is a documentation patch adding a design document for the Large Object Promisors (LOP) feature, which is part of Christian Couder's ongoing promisor-remote/LOP series (v4). The document provides comprehensive technical details about the proposed system for handling large blobs in Git.

The 640-line design doc outlines:
- The motivation (issues with current large blob handling in Git)
- Non-goals (what's explicitly out of scope)
- Seven main features of the LOP solution
- Benefits of using LOPs
- FAQ section addressing common concerns
- Future improvement areas

Key technical aspects covered include:
- Server-side blob offloading to dedicated promisor remotes
- Protocol v2 capability for LOP negotiation
- Integration with existing remote helpers like git-remote-s3
- Security considerations around LOP trust models
- Client/server interaction patterns
- The document positions LOPs as a Git-LFS alternative while acknowledging complementary client-side improvements would still be needed.

The design shows careful consideration of real-world deployment scenarios (corporate vs open source), backward compatibility, and incremental adoption paths. It builds on existing Git infrastructure like partial clones and promisor remotes while proposing new protocol extensions.

This appears to be the capstone documentation for the v4 series, providing the architectural context for the code changes in previous patches. The level of detail suggests it's intended both for reviewers evaluating the series and future maintainers needing to understand the system's design rationale.
