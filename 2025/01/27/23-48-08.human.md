This is a review response from Junio Hamano on Christian Couder's promisor-remote/LOP series, focusing on patch 5/6 which adds "KnownName" and "KnownUrl" options to the promisor remote acceptance configuration.

Junio generally approves of the technical approach but raises several thoughtful concerns. He questions whether the case-insensitive string comparisons used for remote names and URLs are appropriate, suggesting URLs in particular should likely be compared case-sensitively. He also proposes renaming the helper function to be more specific rather than using the generic "strvec_" prefix, and suggests a more extensible callback-based design if it were to become a public API.

The review highlights security considerations around the "KnownName" option, speculating about potential attack vectors where a malicious server could redirect fetches by matching remote names. Junio acknowledges the corporate use case where this might be acceptable, but wants the security implications to be more clearly documented.

While praising the test coverage, Junio notes one missing test case that would verify the case-sensitivity behavior. The feedback maintains the constructive but rigorous tone typical of Junio's reviews, focusing on making the implementation more robust and maintainable while preserving the core functionality.
