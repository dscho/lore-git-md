This is a performance test patch in Derrick Stolee's series introducing configurable name hashing for pack-objects delta compression. The patch adds a new performance test script (p5313) that measures both execution time and resulting pack sizes when using different name hash versions across various pack scenarios (thin packs, big packs, shallow packs, and full repacks).

The test demonstrates concrete performance characteristics of the new name hash version 2 compared to the existing version 1 across multiple repositories. Key findings from the test data show:

1. Significant improvements in the FluentUI repository case, where version 2 reduces repack size from 439MB to 160MB and time from 95s to 33s, while also dramatically improving thin pack performance (1.2MB → 22KB).

2. Mixed results in other repositories:
   - Git repo shows minimal differences (slight bloat in some cases)
   - Node.js repo shows time improvements despite some size bloat
   - Linux kernel shows time improvements in most cases with modest size gains
   - Internal JavaScript repo shows dramatic repack improvements (6.2GB → 855MB)

The test script itself creates three input scenarios (thin, big, shallow) and runs pack-objects/repack operations with both hash versions, measuring both time and output size. It uses Git's existing performance test infrastructure and adds new test_size helper functionality.

This patch provides the empirical validation for the performance claims made in the series, showing that while version 2 doesn't universally improve all metrics, it provides significant benefits in repositories with certain naming patterns (many similarly-named files in different directories). The test will help maintainers evaluate the tradeoffs and monitor for regressions in future versions.
