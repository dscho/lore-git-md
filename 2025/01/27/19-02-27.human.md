Performance optimization for pack-objects delta compression with new name hashing algorithm.

This is the fourth version of Derrick Stolee's patch series introducing configurable name hash algorithms for pack-objects delta compression. The key change is replacing the original `--full-name-hash` option with a more flexible `--name-hash-version` approach after feedback from Jonathan Tan and Taylor Blau.

The series now focuses on two hash versions:
1. Version 1 (default) maintains existing behavior focusing on path endings
2. Version 2 implements Tan's improved path-component hash with better handling of non-ASCII characters and directory hierarchy awareness

Version 3 (a full-name hash alternative from earlier versions) has been definitively removed from the series after review determined its benefits didn't clearly outweigh maintenance costs. The patch organization makes it easy to add future versions if better algorithms emerge.

Performance results show Version 2 provides dramatic improvements over Version 1 in repositories with many name hash collisions (e.g., reducing a 37GB pack to 6.9GB), coming close to Version 3's compression while avoiding its downsides. The implementation includes comprehensive testing, documentation updates, and safety checks to prevent mid-operation version changes.

This appears ready for merging with all substantive review concerns addressed. The only remaining changes since v3 are minor style fixes and moving version validation logic to better handle feature interactions (like temporarily requiring Version 1 with bitmaps). The series represents a significant optimization for repositories suffering from suboptimal delta compression due to path naming patterns.
