This is a discussion thread about the ongoing reftable library refactoring effort to achieve full independence from Git's core infrastructure. Junio Hamano acknowledges Patrick Steinhardt's 19-patch series that successfully removes all dependencies on git-compat-util.h, replacing Git-specific helpers with direct POSIX operations and reftable-specific utilities.

The key question raised is about maintaining synchronization between reftable's newly implemented standalone helpers and any future improvements made to Git's original versions of those utilities. Hamano wonders aloud whether a shared library implementation might be needed, though he recognizes this could potentially recreate the very dependency the series aims to eliminate.

This appears to be a high-level architectural consideration rather than a technical issue with the patches themselves, which have already been reviewed and are nearing completion. The thread seems to be soliciting broader input from the "libification" effort participants about long-term maintenance strategies for these now-duplicated utilities. The core technical work appears sound, but there's an open question about whether the current approach of complete code duplication is sustainable versus some middle-ground solution.
