Refactoring patch in the reftable library independence series. This is patch 5/19 in the ongoing effort to remove Git-specific dependencies from the reftable codebase.

The change modifies `reftable_record_init()` to return error codes instead of calling `BUG()` when encountering unknown record types. This eliminates a dependency on Git's error handling infrastructure while maintaining the same safety checks. The function now returns REFTABLE_API_ERROR for invalid types rather than aborting the program.

The patch updates all callers to handle the new error return, including block iteration, merged table operations, and reader functionality. Test cases are also adjusted to verify the successful initialization path. The changes are mechanical but thorough, touching core record initialization logic across multiple components while preserving the existing behavior for valid cases.

This continues the series' pattern of replacing Git-specific constructs with portable alternatives, in this case moving from fatal errors to returnable error codes. The modification is behavior-preserving for all valid inputs while making the library more robust and self-contained.
