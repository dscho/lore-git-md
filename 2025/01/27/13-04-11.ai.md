This is the third patch in a 19-part series refactoring the reftable library to remove Git-specific dependencies. It focuses on replacing `xmmap()` with direct `mmap()` calls in the blocksource implementation.

The patch removes the Git-specific `xmmap()` wrapper which would die on failure, replacing it with direct `mmap()` calls that properly handle errors. The change affects `reftable_block_source_from_file()`, which now returns an error code (REFTABLE_IO_ERROR) when mmap fails rather than terminating. The implementation still works with Git's `git_mmap()` wrapper on systems lacking native mmap support.

The changes are mechanical but important for the series' goal of making reftable independent from Git's core infrastructure. The patch follows the same pattern seen in previous patches of replacing Git helpers with direct POSIX equivalents while maintaining error semantics. The diff shows careful handling of the error path, including proper cleanup of allocated resources when mmap fails.

This continues the systematic removal of Git dependencies in the reftable codebase, with this particular change affecting how reftable files are memory-mapped. The error handling change makes the code more robust while maintaining the same functionality.
