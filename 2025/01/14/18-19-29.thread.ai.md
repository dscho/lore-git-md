[Security] ANSI escape sequence injection in sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin and Junio Hamano's implementation provides configurable sanitization via `sideband.allowControlCharacters` with per-URL configuration through `sideband_apply_url_config()`. Core sanitization in `strbuf_add_sanitized()` validates without allocations, replacing control characters with caret notation (e.g., `^[` for escape sequences) to prevent terminal state corruption and input buffer injection attacks.

The mature v5 series (rebased to v2.53.0 in v4) had production validation in Git for Windows (1+ year) and Red Hat (6+ months). Latest patches introduce nuanced control with URL-scoped configuration via `sideband.<url>.allowControlCharacters` mirroring Git's `http.<url>.*` pattern, default behavior allowing ANSI color sequences (`\033[31m` etc) via `ALLOW_ANSI_COLOR_SEQUENCES`, and new bitmask flags for cursor movements (`ALLOW_ANSI_CURSOR_MOVEMENTS`), erase sequences (`ALLOW_ANSI_ERASE`), and full passthrough (`ALLOW_ALL_CONTROL_CHARACTERS`). The configuration now accepts comma-separated lists (`color,cursor,erase`) alongside boolean values.

Junio Hamano removes the ambiguous 'default' keyword from `sideband.allowControlCharacters` configuration, requiring explicit preference specification (like 'color' or 'cursor') or implicit default behavior by not setting the option. This eliminates behavior changes at the Git 3.0 boundary for users who had explicitly set 'default'. The change maintains all other configuration options while simplifying the interface.

Patch 5/7 adds URL-specific configuration handling through `sideband_apply_url_config()`, integrating with Git's existing `urlmatch` infrastructure. This allows per-server policies while maintaining the global `sideband.allowControlCharacters` default. The implementation preserves backward compatibility and has been production-validated in Git for Windows and Red Hat environments. Test coverage in `t/t5409-colorize-remote-messages.sh` verifies URL-specific behaviors.

The final patch (7/7) delays the secure-by-default behavior of sanitizing control characters until Git 3.0, maintaining backward compatibility while committing to future hardening. It introduces conditional compilation (`WITH_BREAKING_CHANGES`) to manage the transition - currently defaulting to permissive behavior (allowing all control characters) while documenting the planned change to only allow ANSI color sequences by default in Git 3.0. The implementation preserves URL-specific configuration while adjusting test expectations via a `TURN_ON_SANITIZING` test prerequisite to account for version-dependent defaults.

Junio Hamano proposes merging patches 1-7 to 'next' for extended testing, implementing the allowlist approach while using conditional compilation to manage the transition path. The series represents a compromise between immediate security needs and backward compatibility, with secure-by-default behavior (only ANSI colors) planned for Git 3.0.
