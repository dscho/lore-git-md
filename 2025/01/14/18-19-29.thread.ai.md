[Security] ANSI escape sequence injection in sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin's implementation provides configurable sanitization via `sideband.allowControlCharacters` with evolving granularity (boolean/string/comma-separated values for color/cursor/erase sequences) and per-URL configuration via `sideband_apply_url_config()`. Core sanitization in `strbuf_add_sanitized()` validates without allocations.

The mature v5 series had production validation in Git for Windows (1+ year) and Red Hat (6+ months) with secure defaults permitting colors while requiring opt-in for higher-risk sequences. Junio C Hamano's maintainer override reverts to unfiltered behavior by default, removing the `default` keyword that enabled basic color filtering. Documentation and tests (`t/t5409-colorize-remote-messages.sh`) are updated to reflect opt-in security, requiring explicit `sideband.allowControlCharacters=color` for previous behavior. URL-specific overrides (`sideband.<url>.allowControlCharacters`) remain technically supported but Junio rejects middle-ground positions.

Technical implementation is uncontested; debate centers on policy defaults. Schindelin and security team advocated safe-by-default for terminal injection risks, while Junio prioritizes backward compatibility citing GitHub/Red Hat deployment concerns and legacy encodings (IEC/ISO 2022:1994). brian m. carlson supports opt-in model citing SSH precedents. D. Ben Knoble's "swiss cheese" security model and Patrick Steinhardt's URL whitelisting proposals remain technically valid but overridden by maintainer decision. Implementation allows future policy changes while shifting security responsibility to end users.
