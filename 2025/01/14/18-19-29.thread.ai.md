[Security] ANSI escape sequence injection in sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin's implementation provides configurable sanitization via `sideband.allowControlCharacters` with per-URL configuration through `sideband_apply_url_config()`. Core sanitization in `strbuf_add_sanitized()` validates without allocations, replacing control characters with caret notation (e.g., `^[` for escape sequences) to prevent terminal state corruption and input buffer injection attacks.

The mature v5 series (rebased to v2.53.0 in v4) had production validation in Git for Windows (1+ year) and Red Hat (6+ months). Latest patches introduce nuanced control with URL-scoped configuration via `sideband.<url>.allowControlCharacters` mirroring Git's `http.<url>.*` pattern, default behavior allowing ANSI color sequences (`\033[31m` etc) via `ALLOW_ANSI_COLOR_SEQUENCES`, and new bitmask flags for cursor movements (`ALLOW_ANSI_CURSOR_MOVEMENTS`), erase sequences (`ALLOW_ANSI_ERASE`), and full passthrough (`ALLOW_ALL_CONTROL_CHARACTERS`).

The final patch in v4 series delays secure-by-default behavior to Git 3.0 while maintaining backward compatibility in current versions. This addresses concerns about breaking existing workflows that rely on unfiltered sideband output, particularly for colored pre-receive hooks. Implementation introduces conditional compilation via `WITH_BREAKING_CHANGES` to toggle between permissive (current) and secure (future) defaults, with current versions maintaining unfiltered output (`ALLOW_ALL_CONTROL_CHARACTERS`) while Git 3.0 will default to allowing only color sequences (`ALLOW_ANSI_COLOR_SEQUENCES`). URL-specific overrides (`sideband.<url>.allowControlCharacters`) remain functional.

Test coverage in `t/t5409-colorize-remote-messages.sh` verifies both current and future behaviors through a new `TURN_ON_SANITIZING` test prerequisite, checking:
- Color sequences pass through by default
- Non-color control characters (e.g., bell `\a`) remain sanitized
- Cursor/erase sequence handling when explicitly enabled
- URL-specific configuration overrides
- Both compilation modes (current vs Git 3.0)

The debate continues between Schindelin advocating secure-by-default (terminal emulators cannot distinguish malicious sequences) and brian m. carlson supporting opt-in model, with the current compromise delaying stricter defaults to Git 3.0. Documentation clearly warns about the behavior change in Git 3.0 while maintaining technical foundation for future policy changes. Production validation in Git for Windows and Red Hat systems confirms stability of the URL-scoped configuration approach. The architecture supports both immediate needs and potential Git 3.0 behavior changes while minimizing disruption to existing deployments.
