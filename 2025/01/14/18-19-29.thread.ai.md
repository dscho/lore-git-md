[Security] ANSI escape sequence injection in sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin's implementation provides configurable sanitization via `sideband.allowControlCharacters` with per-URL configuration through `sideband_apply_url_config()`. Core sanitization in `strbuf_add_sanitized()` validates without allocations, replacing control characters with caret notation (e.g., `^[` for escape sequences) to prevent terminal state corruption and input buffer injection attacks.

The mature v5 series (rebased to v2.53.0 in v4) had production validation in Git for Windows (1+ year) and Red Hat (6+ months). Latest patches introduce nuanced control with URL-scoped configuration via `sideband.<url>.allowControlCharacters` mirroring Git's `http.<url>.*` pattern, default behavior allowing ANSI color sequences (`\033[31m` etc) via `ALLOW_ANSI_COLOR_SEQUENCES`, and new bitmask flags for cursor movements (`ALLOW_ANSI_CURSOR_MOVEMENTS`), erase sequences (`ALLOW_ANSI_ERASE`), and full passthrough (`ALLOW_ALL_CONTROL_CHARACTERS`).

Junio Hamano's review initially raised fundamental concerns: (1) version-dependent defaults as poor UX; (2) suggested testing opt-in mechanisms first; (3) challenged the whitelist security model in favor of blacklisting known-dangerous sequences. His terminal title update example (ESC ] 0; <string> BEL sequence) demonstrated legitimate functionality broken by current design. However, in his latest email, Junio has shifted position on rollout strategy, now acknowledging Schindelin's default-on approach may be more practical for real-world testing when deployed in `next`, accepting that some breakage may be necessary to properly evaluate impact.

The review follows Junio's earlier technical input about ISO/IEC 2022 encoding collisions, which can switch back to ASCII despite "remote: " prefix. Current implementation in v4 introduces conditional compilation via `WITH_BREAKING_CHANGES` to toggle between permissive (current) and secure (future) defaults, with URL-specific overrides (`sideband.<url>.allowControlCharacters`). Test coverage in `t/t5409-colorize-remote-messages.sh` verifies behaviors through `TURN_ON_SANITIZING` prerequisite.

The debate continues between Schindelin's secure-by-default approach (emphasizing terminal emulator vulnerabilities) and accommodating legitimate control sequences, but Junio's latest position signals acceptance of the default-on strategy for testing purposes. Production validation in Git for Windows and Red Hat confirms URL-scoped configuration stability, while the maintainer's evolving stance suggests the architecture may proceed with current design while monitoring real-world impact from `next` branch deployment.
