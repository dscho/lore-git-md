[Security] ANSI escape sequence injection in sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin's implementation provides configurable sanitization via `sideband.allowControlCharacters` with evolving granularity (boolean/string/comma-separated values for color/cursor/erase sequences) and per-URL configuration via `sideband_apply_url_config()`. Core sanitization in `strbuf_add_sanitized()` validates without allocations.

The mature v5 series had production validation in Git for Windows (1+ year) and Red Hat (6+ months) with secure defaults permitting colors while requiring opt-in for higher-risk sequences. Junio C Hamano's maintainer override reverts to unfiltered behavior by default, removing the `default` keyword that enabled basic color filtering. Documentation and tests (`t/t5409-colorize-remote-messages.sh`) are updated to reflect opt-in security, requiring explicit `sideband.allowControlCharacters=color` for previous behavior.

Schindelin strongly opposes the opt-in approach, arguing terminal emulators cannot distinguish legitimate from malicious sequences and that sideband messages' ASCII prefixes make encoding concerns theoretical. He proposes a phased approach: keep sanitization opt-in for Git 2.x but make it default in Git 3.0. The technical implementation remains uncontested - debate centers on security philosophy (secure-by-default vs backward compatibility). Schindelin seeks security expert input on sanitizing untrusted input before interpreter exposure.

URL-specific overrides (`sideband.<url>.allowControlCharacters`) remain supported but discouraged.
