Feature proposal for `git diff` shorthand, with historical context.

Kristoffer Haugsbakk responds to tao lv's request to extend the `-` shorthand (equivalent to `@{-1}`) to `git diff`, noting that a similar proposal for `git branch` was rejected in 2022. The thread shows interest in consistent shorthand behavior across Git commands but now surfaces a precedent where this was previously deemed undesirable for at least one command.

The response doesn't take a position on the current proposal but provides important context that reviewers will need to consider: whether the rejection of `git branch -` sets a precedent that would apply to `git diff` as well, or if diff's use case is meaningfully different. The lack of implementation details in the original request remains unaddressed, leaving open questions about scope and compatibility.
