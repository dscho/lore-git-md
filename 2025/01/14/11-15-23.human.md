Build system patch addressing version header handling in Meson builds. This v2 revision from Toon Claes, co-authored with Patrick Steinhardt, proposes a solution to prevent Meson builds from accidentally including stale `version-def.h` files left by previous Make builds.

The patch takes a different approach from v1's file-copying solution, now using a compiler define (`-DGIT_VERSION_H`) to explicitly specify which `version-def.h` to include. This addresses the core issue where some preprocessors would prefer Make-generated headers due to include path behavior with double-quoted includes. The solution maintains compatibility with other build systems through a fallback to the traditional include.

This appears to be converging toward Patrick Steinhardt's preferred solution from the ongoing thread discussion, addressing concerns about build system transition periods and compiler variability. The implementation is clean - just two small changes to `meson.build` and `version.c` - and the commit message clearly explains both the problem and solution. The patch seems ready for consideration unless new technical objections emerge about the compiler define approach.
