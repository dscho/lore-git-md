Performance optimization series adding zlib-ng support (part 6/10). This patch centralizes compatibility handling for `deflateSetHeader()`, which was introduced in zlib 1.2.2.1. The change moves the version-specific logic from `archive-tar.c` into the new `zlib-compat.h` abstraction layer, where it joins the existing `deflateBound()` compatibility shim.

The patch removes direct version checks (`ZLIB_VERNUM`) from the tar archive code, instead providing a stub implementation in the compatibility layer when building against older zlib versions. This maintains the same behavior while preparing for the zlib-ng integration where version checks would be inappropriate. The implementation includes a dummy `gz_header_s` struct and a no-op `deflateSetHeader()` that returns success, matching the behavior of newer zlib versions when the header is set late (which already triggers a BUG).

This is part of the systematic refactoring to enable runtime switching between zlib backends. The change is straightforward and maintains backward compatibility while removing version-specific code from individual callers. The patch follows the established pattern seen earlier in the series for `deflateBound()`, further consolidating zlib compatibility handling.
