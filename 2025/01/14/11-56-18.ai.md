This is a build system patch that makes the CSPRNG (cryptographically secure pseudo-random number generator) backend configurable in the Meson build system, continuing Patrick Steinhardt's comprehensive Meson migration series.

The patch adds a new `csprng_backend` option to `meson_options.txt` with choices for all supported backends (arc4random variants, getrandom, getentropy, RtlGenRandom, OpenSSL, and urandom), defaulting to 'auto' detection. The implementation in `meson.build` now explicitly checks for each backend in order of preference (most secure/fastest first) when either auto-detecting or when a specific backend is requested. The selected backend is then added to the build summary output alongside other configured backends.

The changes maintain security properties by preserving the existing preference order for backends while making the selection more transparent and configurable. This follows the pattern seen in other backend configurations (HTTPS, SHA1, etc. that were previously converted in this series. The patch also fixes an oversight where OpenSSL's CSPRNG capability wasn't properly considered in the OpenSSL dependency detection logic.

This appears to be a straightforward and well-contained addition to the Meson build system that completes the CSPRNG configuration story while maintaining all security properties. It follows the established patterns from other backend configurations in the series and includes the backend selection in the build summary for visibility. The implementation handles both auto-detection and explicit selection cases cleanly.
