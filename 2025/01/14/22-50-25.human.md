This is a security-related discussion about the recently merged ANSI escape sequence sanitization for the sideband channel. Brian Carlson raises substantive objections to the approach, arguing that:

1) The vulnerability classification is overstated - terminal emulators already disable the most dangerous features (like input buffer manipulation), and other common tools (SSH, curl) expose users to similar risks without mitigation.

2) The solution breaks legitimate use cases beyond just color codes, including progress bars from tools like Cargo and potential future uses like QR code display via sixel sequences.

3) The burden of incompatible changes outweighs the security benefits, especially since the issue exists more broadly across terminal-using programs and would be better addressed at the terminal emulator level.

The email provides concrete examples of real-world breakage (Cargo output) and potential lost functionality (QR codes), while acknowledging the security team's position but disagreeing with their risk assessment. This represents a significant critique of the recently merged security fix from someone with apparent terminal protocol expertise.
