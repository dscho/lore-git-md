Refactoring patch in the zlib-ng optimization series, focusing on header reorganization. This patch moves the zlib compatibility header inclusion from `git-compat-util.h` to the more specific `git-zlib.h`, where it logically belongs since only zlib-using files need these definitions. The change affects several core files (`archive.c`, `config.c`, etc.) that now explicitly include `git-zlib.h`. 

A special case is made for reftable, which maintains its independent zlib usage by including `compat/zlib-compat.h` through `reftable/system.h` instead. This preserves reftable's ability to be built outside Git while keeping the zlib abstraction consistent. The patch is part of a larger effort to clean up zlib dependencies in preparation for zlib-ng support, and follows logically from previous patches that established the `zlib-compat.h` abstraction layer. The changes are mechanical and low-risk, simply moving includes to more appropriate locations without altering functionality.
