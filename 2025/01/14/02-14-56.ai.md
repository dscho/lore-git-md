This is a refactoring patch in the v10 series implementing remote object-info functionality. It generalizes the packet-writing code from fetch-pack.c to make it reusable for other protocol v2 commands.

The patch moves and renames `write_fetch_command_and_capabilities()` to `write_command_and_capabilities()` in connect.c, making it available for any protocol v2 command (not just fetch). The function handles writing the command name, agent/session IDs, server options, and hash algorithm negotiation. The key changes are:

1. The function now takes an explicit `command` parameter rather than hardcoding "fetch"
2. The `advertise_sid` config is now read directly in connect.c rather than being managed in fetch-pack.c
3. The move is safe because the original fetch-pack-specific logic (checking protocol v1 support) isn't needed for protocol v2 usage

The patch includes careful analysis showing why the config handling change is safe, noting that the original v1-specific checks can be dropped since this is now v2-only code. The new location in connect.c makes this functionality available to future protocol v2 commands while maintaining all existing behavior for fetch operations.

This refactoring directly supports the series' goal by enabling the new remote-object-info command to reuse this packet-writing infrastructure. The implementation follows Git's established patterns, with clear documentation of the changes and their rationale. All review feedback from Jonathan Tan and Christian Couder has been incorporated.
