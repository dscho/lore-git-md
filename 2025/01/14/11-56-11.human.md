Build system refactoring with performance benefits. This is the first patch in an 11-part series (though no cover letter was provided for context).

Patrick Steinhardt simplifies how Git detects dirty worktrees during version generation. The current code uses a manual `git diff-index` check for dirtiness, a holdover from 2008 when `git describe` didn't support `--dirty`. The patch switches to using `git describe --dirty` directly, which is both cleaner and faster - about 1.4x on Unix systems and roughly 2x faster on Windows (400ms vs 800ms).

The change is straightforward, removing 5 lines of manual dirtiness checking while keeping the same functionality. The commit includes clear benchmarking data showing the improvement across platforms. While the speedup might be negligible for most Unix developers, Windows users will notice the difference in build times.

This appears to be a well-justified cleanup with measurable benefits. The commit message provides good historical context and performance data, making the case for the change compelling. As the first in a series, it's likely setting up for more substantial build system changes to come.
