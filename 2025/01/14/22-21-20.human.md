Performance discussion about `git bisect` initialization on large repositories. This is a follow-up to Askar Safin's report about `git bisect old` taking 21 minutes to initialize on the Linux kernel repository (spanning 535k revisions). D. Ben Knoble provides additional context and observations.

Key points:
- Confirms the massive scale of the problem (1.07 million revisions between v3.0 and v6.13-rc7)
- Notes that even basic operations like `git rev-list --count` take ~15 seconds for this range
- Observes that checkout operations are also slow (~27 seconds) on this repository
- Suggests using pathspecs or smaller commit ranges as potential workarounds
- Notes the bisect helper has been removed in recent Git versions, making the current bottleneck location unclear

The email maintains a constructive tone while acknowledging the performance challenges inherent in operating on such a large history. It doesn't propose solutions but provides useful benchmarking context that could help diagnose where time is being spent in the bisect initialization process. The thread continues to highlight a real performance pain point for large repositories.
