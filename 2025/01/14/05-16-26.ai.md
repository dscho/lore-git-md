This is a feature inquiry about `git replace` behavior with namespaces. Josh Bleecher Snyder reports that `git replace` does not appear to respect `GIT_NAMESPACE`, meaning replacements created in one namespace are visible in others. He demonstrates this by showing that a replacement created normally is still visible when operating under a different namespace, and that attempts to access the namespace-qualified replacement ref directly fail.

The email presents a clear reproduction case showing that:
1. Regular replacements work outside namespaces
2. The same replacement remains visible when operating under `GIT_NAMESPACE=foo`
3. Direct access to the namespace-qualified replacement ref path fails
4. `git log` shows the replacement applies regardless of namespace

The core question is whether this is a bug (where replacements should be namespace-isolated) or working as intended (where replacements are global). This touches on Git's namespace isolation behavior and whether replacements should be treated like other refs in this regard. The email doesn't propose a solution but seeks clarification on current expectations, which could lead to either a bug report or documentation update depending on the answer.
