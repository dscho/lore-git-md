This thread addresses a build system issue in Git's meson configuration where technical documentation articles could fail to build due to a missing dependency declaration. The problem specifically manifests in parallel builds when documentation targets attempt to build before their dependencies (notably asciidoc.conf) are ready.

The fix is minimal and well-scoped - a single line change in Documentation/technical/meson.build that properly declares the dependency. This follows up on feedback from Patrick Steinhardt in v2 where an incorrect dependency was removed. The patch cleanly resolves the race condition without affecting other documentation targets that already had correct dependencies. The change appears straightforward and uncontroversial, focused specifically on fixing this build system edge case.
