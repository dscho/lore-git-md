This is part 3/10 of a performance optimization series introducing zlib-ng support as an alternative zlib backend. The patch establishes the core infrastructure change needed for the zlib abstraction layer by introducing a new `compat/zlib-compat.h` header that replaces direct `#include <zlib.h>` statements throughout the codebase.

The key technical change is the creation of this new header file that simply includes the system zlib header, along with updates to three locations that previously included zlib.h directly: `git-compat-util.h`, `reftable/block.c`, and the new header file itself. The header is deliberately named `zlib-compat.h` rather than `zlib.h` to avoid potential include path conflicts with the actual system zlib header.

This change is foundational for the series' goal of enabling runtime switching between standard zlib and zlib-ng backends. The patch maintains backward compatibility while creating the abstraction point where future patches will insert the zlib-ng support. The reftable subsystem's zlib usage is also updated to use the new header, maintaining consistency across the codebase while preserving reftable's independent zlib usage as noted in the thread context.

The change is minimal and low-risk, touching only include directives while keeping all actual zlib functionality intact. It follows the series' established pattern of maintaining compatibility with system zlib while preparing for the zlib-ng integration.
