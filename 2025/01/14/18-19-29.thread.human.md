This security thread addresses ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005/GHSA-7jjc-gg6m-3329). Johannes Schindelin's implementation, which has been production-tested in Git for Windows and Red Hat systems for 6-12 months, provides configurable sanitization with strict defaults that only allow color sequences while blocking riskier cursor/erase commands. The technical implementation is sound, with thorough test coverage and URL-specific configuration options.

The debate has centered on whether to maintain these security-conscious defaults (Schindelin's position) or revert to unfiltered behavior for backward compatibility (brian m. carlson's view). Junio Hamano has now weighed in decisively, siding with carlson and advocating for completely opt-in sanitization with no filtering by default. He rejects the middle ground of allowing only color sequences, calling it arbitrary, and expresses concern about breaking legacy systems. This represents a significant shift, as the maintainer is overriding the security team's preferred approach despite its proven stability in production. The discussion now turns to how to implement Junio's direction while minimizing security risks, with Schindelin continuing to push for concrete examples of breakage under the current defaults.
