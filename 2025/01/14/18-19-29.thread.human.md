This thread addresses security concerns around ANSI escape sequence injection in Git's sideband channel (CVE-2024-32002, CVE-2024-52005). Johannes Schindelin (Dscho) implemented configurable sanitization with secure defaults that permit color sequences while blocking more dangerous control codes like cursor movement. This approach was validated in production for over a year in Git for Windows and six months in Red Hat's deployment.

The debate centers on whether sanitization should be enabled by default. Junio Hamano, as maintainer, has overridden the secure defaults, reverting to unfiltered behavior to preserve backward compatibility, particularly citing concerns from GitHub and Red Hat about legacy encodings. Documentation and tests have been updated to reflect that users must now explicitly opt in to even basic color filtering.

In the latest email, Schindelin strongly disagrees with this decision, arguing that terminal emulators cannot distinguish between safe and malicious sequences, making Git-level sanitization critical. He dismisses concerns about Japanese ISO encodings as theoretical since sideband messages use ASCII prefixes. While the technical implementation itself is uncontested, Schindelin advocates for a security-first approach, proposing a compromise where sanitization remains opt-in for Git 2.x but becomes the default in Git 3.0 to give users time to adapt while committing to stronger long-term security. The thread reflects a philosophical divide between security-by-default principles and backward compatibility priorities.
