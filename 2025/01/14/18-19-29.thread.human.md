This thread addresses a security vulnerability in Git's sideband channel where ANSI escape sequences could be injected (CVE-2024-32002, CVE-2024-52005). Johannes Schindelin (Dscho) has proposed a v2 patch series that introduces controlled sanitization through a new `sideband.allowControlCharacters` configuration option (defaulting to `color`). The core sanitization happens in `handle_ansi_color_sequence()` and a new `strbuf_add_sanitized()` function, with test coverage in `t5409-colorize-remote-messages.sh`.

The series has evolved since v1 with contributions from Phillip Wood (expanding the whitelist of allowed control sequences) and includes documentation enhancements and test fixes. There's an ongoing technical discussion about the security model - Schindelin advocates for layered security focusing on Windows/HTTPS channels, while brian m. carlson argues that terminal emulators should bear more responsibility, particularly for SSH which has inherent limitations. Both sides acknowledge legitimate uses for control characters (like QR codes) but differ on risk prioritization.

The implementation currently provides solid protection for HTTPS connections while acknowledging SSH's limitations. Junio Hamano is mediating the discussion as it balances technical evidence from both perspectives. Open questions remain about transport-specific boundaries, downstream impact, and whether these mitigations might create false security expectations. The conversation has at times become heated, with Schindelin using strong language ("gas-lit") that carlson has rebutted, though the technical merits of the patches themselves appear sound for their stated HTTPS-focused scope.
