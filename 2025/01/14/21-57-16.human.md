This is a follow-up in a resolved bug thread about `git diff --merge-base` behavior with annotated tags. The original issue involved Apple Git 2.39.5 incorrectly rejecting annotated tags with a "fatal: --merge-base only works with commits" error, which was fixed in upstream Git 2.43.0. The email provides a more concise workaround than previously discussed: using `<tag>^{commit}` syntax to "peel" the tag to its underlying commit before passing it to `git diff --merge-base`. This is functionally equivalent to the earlier `git rev-list -n 1` suggestion but more direct. The thread serves as a good reference for users encountering similar version-specific issues with vendor-packaged Git binaries, demonstrating both the proper fix (upgrading) and temporary workarounds.
