This is a technical clarification in Jeff King's ongoing combine-diff refactoring series (now at 15 patches). The email responds to Patrick Steinhardt's observation about an unmentioned type change in `path_appendnew()`'s parameters.

Jeff explains that the `int`→`size_t` change for the length parameter wasn't an independent decision, but rather a consequence of restructuring how path strings are handled. The original code took both a `strbuf` (with size_t length) and a separate path string (with int length), while the new version consolidates this into a single string operation before calling the function. The remaining `int` type in the caller's code is preserved for now to avoid wider tree-wide changes, though Jeff notes this could eventually be updated to `size_t`.
