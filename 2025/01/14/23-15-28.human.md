This is a follow-up in the security release thread regarding version metadata issues in Git v2.47.2. Randall Becker from NonStop explains they cannot package v2.47.2 due to strict compliance requirements in their customer base - they cannot modify files (like the `version` workaround suggested) or use unofficial commits. Since v2.47.2's `GIT-VERSION-GEN` incorrectly shows v2.47.1 in tarball builds, they'll have to skip this version entirely and direct users to v2.48.1 instead, despite potential user dissatisfaction. The exchange highlights real-world packaging constraints where even minor metadata issues can block adoption in regulated environments, though the core security fixes remain unaffected. Johannes Schindelin had earlier clarified this was purely a cosmetic issue for tarball builds, with the security content fully present.
