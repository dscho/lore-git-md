Security patch addressing ANSI escape sequence injection in sideband channel. This is the first of three patches in a series to mitigate CWE-150 by sanitizing remote server output while preserving ANSI color support.

The patch introduces a new `strbuf_add_sanitized()` function that replaces control characters (except tab and newline) with caret notation (e.g., ESC becomes ^[). This affects all sideband output, including error messages from remote operations like `git clone`. The implementation modifies `sideband.c` to use this sanitization in `maybe_colorize_sideband()`, while maintaining existing colorization behavior for whitelisted ANSI sequences.

A new test case in `t5409-colorize-remote-messages.sh` verifies that color control sequences from a malicious remote (simulated via `uploadPack.packObjectshook`) are properly sanitized. The commit message notes this is a broad initial approach, with more fine-grained controls to follow in subsequent patches.

Key technical details for future reference:
- New function: `strbuf_add_sanitized()`
- Modified function: `maybe_colorize_sideband()`
- Test file: `t5409-colorize-remote-messages.sh`
- Whitelisted characters: tab (\t), newline (\n)
- Caret notation format: ^ followed by @ + ASCII value (e.g., 0x1b becomes ^[)
