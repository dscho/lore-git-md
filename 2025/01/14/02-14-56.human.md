Refactoring patch for protocol v2 command handling. This is part 4/8 of a series adding remote object-info support, focusing on generalizing the packet-writing infrastructure.

The patch moves and generalizes the packet-writing logic from `fetch-pack.c` to `connect.c`, transforming the fetch-specific `write_fetch_command_and_capabilities()` into a reusable `write_command_and_capabilities()` function. This prepares the codebase to support additional protocol v2 commands (like the new object-info feature) while maintaining all existing fetch functionality.

Key changes include:
- Moving the function to `connect.c` where it can be shared by multiple commands
- Making the command name parameterized rather than hardcoded to "fetch"
- Simplifying the session ID (`advertise_sid`) handling since it's only relevant for protocol v2
- Preserving all existing capability negotiation (agent, server-options, object-format)

The refactoring is well-justified in the commit message, with clear analysis of the session ID handling changes. The patch follows the series' pattern of careful, incremental changes with thorough consideration of edge cases. It builds on review feedback from Jonathan Tan and Christian Couder, showing the typical Git project attention to code organization and future extensibility.
