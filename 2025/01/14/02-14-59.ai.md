This is part 7/8 of a feature series implementing remote object-info functionality, focusing on the client-side implementation. The patch adds client support for querying object information (currently just sizes) from protocol v2 servers without full object downloads, building on server-side capability advertisement added in earlier patches.

Key technical details:
- New `fetch_object_info()` function handles the client-side protocol interaction, validating server capability and protocol version (strictly v2-only)
- Uses generalized packet-writing infrastructure from connect.c (`write_command_and_capabilities()`) to send requests
- Supports requesting object sizes via the 'size' feature, with error handling for unsupported servers
- Integrates with transport layer through new `object_info` flag in `git_transport_options`
- Follows fetch-pack's pattern of buffering entire request before sending
- Adds new `fetch-object-info.[ch]` files to the build system

The implementation handles both stateless and stateful RPC modes, with proper packet reading state machine. Error cases are explicit about protocol version requirements and server capability support. The transport layer changes ensure the feature works across git://, file:// and http:// protocols when properly configured.

This completes the client-side piece of the end-to-end functionality, matching the server-side capability added earlier in the series. All review feedback from v9 appears incorporated, with clean separation of concerns between the new object-info logic and existing fetch-pack machinery.
