This is a dissenting opinion in the ongoing security discussion about ANSI escape sequence handling in Git's sideband channel. Brian M. Carlson challenges the characterization of the issue as a vulnerability and argues against the proposed solution of sanitizing control characters while allowing ANSI colors.

The email makes several key technical points: (1) The input buffer manipulation capability is limited to terminal report features that are already disabled in major emulators, (2) Common developer tools like Cargo legitimately use various control sequences (including `\e[K` for progress bars and hyperlinks) that would be broken by the sanitization, (3) Other useful sequences like sixel codes for QR images could be blocked, and (4) The problem exists more broadly in terminal usage (SSH, curl, cat) and should be solved at the terminal emulator level rather than in Git.

Carlson emphasizes the practical impact on users, particularly those relying on pre-receive hooks running tools that produce terminal output. While acknowledging the security team's perspective, they argue the costs of breaking existing workflows outweigh the benefits, especially since the vulnerability can manifest through many other common terminal interactions. The position is that terminal emulators should handle these security concerns universally rather than having individual applications implement partial solutions.
