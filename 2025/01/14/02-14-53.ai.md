Utility function addition for the remote object-info series.

This patch introduces `strtoul_ul()`, a new utility function in git-compat-util.h that provides error-checked conversion to unsigned long values. It follows the pattern of existing functions like `strtoul_ui()` but handles the larger unsigned long type. The implementation includes standard error checking: rejecting negative values (which strtoul would otherwise accept), checking for conversion errors via errno, and validating the entire string was consumed.

The function appears well-crafted with clear documentation and follows Git's existing patterns for similar numeric conversion utilities. It will be used in later patches of this series for handling object size values in the remote object-info protocol implementation. The error handling matches Git's typical robustness standards, including explicit negative number rejection that strtoul() itself doesn't provide.

Key technical details:
- Returns -1 on any error (invalid format, negative numbers, overflow)
- Uses standard strtoul() internally but adds Git's stricter validation
- Follows same pattern as strtoul_ui() but for unsigned long instead of unsigned int
- Will be used to parse object sizes in the remote object-info protocol responses

This is a straightforward utility addition with no apparent controversy - it fills a clear gap in Git's numeric conversion helpers and follows established patterns. The implementation looks correct and the documentation is clear.
