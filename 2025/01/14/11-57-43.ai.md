This is a refactoring patch in the zlib-ng optimization series, specifically removing an unnecessary `z_const` macro definition from `git-compat-util.h`. The patch builds on the thread's context of modernizing Git's zlib compatibility layer.

The change removes a seemingly vestigial `#define z_const` that was originally introduced with zlib compatibility code but no longer serves any clear purpose. The macro was preventing zlib's own `z_const` from expanding to `const` in parameter declarations, which the author argues is unnecessary since the parameters are effectively constant regardless of the qualifier. The commit notes this was likely carried over from older compatibility code without clear justification.

This is a straightforward cleanup that:
- Removes one line from `git-compat-util.h`
- Follows logically from the previous patch's removal of `uncompress2()` compatibility code
- Maintains all existing functionality while simplifying the codebase
- Is part of the broader effort to streamline zlib integration in preparation for zlib-ng support

The change is low-risk as it doesn't affect behavior, just removes an apparently superfluous definition. It fits well with the series' goal of cleaning up zlib-related compatibility code while maintaining all necessary functionality.
