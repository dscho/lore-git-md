Performance optimization discussion in the combine-diff refactoring series.

Jeff King responds to Patrick Steinhardt's question about the performance impact of dropping the `path_appendnew()` allocation optimization. While the optimization provided a 1-3% speedup in some cases by reusing freed memory blocks, Jeff argues this small gain isn't worth the added code complexity. He provides detailed measurements showing the optimization triggers about half the time in real-world cases like `git log --raw`.

The discussion expands to consider allocator performance more broadly. Jeff tests with jemalloc and finds it provides 10-15% speedups in pathological cases, dwarfing the gains from the dropped optimization. This suggests that while micro-optimizations can help, the choice of memory allocator has a larger impact. The exchange demonstrates the series' careful balance between performance and maintainability, with both reviewers agreeing the simpler code is preferable to marginal speed improvements.
