This is part 3 of a 10-patch series introducing zlib-ng support as an alternative zlib backend for performance improvements. The patch creates a new compatibility header `zlib-compat.h` that serves as an indirection layer for zlib includes, replacing direct `#include <zlib.h>` statements throughout the codebase.

The change is straightforward - it's a foundational piece for the larger zlib-ng integration work. The new header currently just includes the system zlib header, but will later be expanded to handle the zlib-ng backend switching. The patch updates includes in `git-compat-util.h` and `reftable/block.c` to use this new indirection.

This is a clean, mechanical change that maintains exact functionality while setting up for the more substantial backend switching work to come. The series has been through multiple iterations and appears well-considered, with this particular patch being a low-risk prerequisite for the performance improvements promised by zlib-ng.
