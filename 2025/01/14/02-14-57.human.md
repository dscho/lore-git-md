Refactoring patch in the remote object-info series (5/8). This patch moves initialization code for the fetch-pack state machine out of the first state (FETCH_CHECK_LOCAL) to just before the state machine begins. The change prepares for future work where the state machine might start in a different initial state while still needing these same variables initialized.

The patch is straightforward - it relocates three variable initializations (allow_unadvertised_object_request, use_sideband, and args->deepen) that were previously set at the start of FETCH_CHECK_LOCAL. The commit message clearly explains this is a pure refactoring with no behavior change, and the change has been reviewed by both Jonathan Tan and Christian Couder.

This is part of the larger effort to implement client-side remote object-info functionality, where these initialization changes help support the protocol v2 infrastructure. The patch appears well-justified and follows the series' pattern of careful refactoring to support the new functionality.
