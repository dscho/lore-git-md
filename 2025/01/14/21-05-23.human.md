This is a follow-up discussion about the Git security release version metadata issue, specifically regarding v2.47.2's incorrect `GIT-VERSION-GEN` file. Johannes Schindelin responds to Randall Becker's concerns about packaging the release for NonStop systems.

Schindelin clarifies that the version metadata issue only affects tarball builds, not Git checkouts, and suggests workarounds like manually creating a `version` file. He strongly discourages any attempt to re-tag the release, noting the security fixes themselves are complete and correct in all releases. The discussion reveals some tension between the need for precise version metadata in downstream packaging workflows and the immutability of security release tags.

The email provides important context for packagers: while v2.47.2 contains all security fixes, those building from tarballs will need to use workarounds to get correct version reporting until a future release corrects the metadata. The exchange highlights real-world challenges in coordinating security releases across diverse distribution channels.
