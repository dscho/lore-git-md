[Security] This is the second patch in a series addressing ANSI escape sequence injection, introducing an opt-out mechanism for the security protections added in the first patch.

The patch adds a new configuration option `sideband.allowControlCharacters` that lets users disable the control character sanitization when they specifically want to allow remote servers to send ANSI color sequences. The implementation checks this config setting in `use_sideband_colors()` and bypasses the `strbuf_add_sanitized()` function when enabled. Documentation is added in a new `config/sideband.txt` file explaining the security implications.

The test case is extended to verify both the default sanitization behavior and the opt-out path, showing that color sequences are blocked by default but allowed when the config is set. The implementation maintains the existing color handling infrastructure while adding this new control point.

Key technical elements include:
- New config variable `sideband.allowControlCharacters`
- Modified `sideband.c` to check the setting before sanitizing
- Extended test coverage in `t5409-colorize-remote-messages.sh`
- New config documentation file

This patch builds on the security foundation from patch 1 while addressing use cases where remote color output is desired. The implementation appears straightforward and maintains the security-by-default approach while providing an escape hatch. The test coverage verifies both security and configurability aspects.
