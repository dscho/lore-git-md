Behavior question about `git replace` and namespaces. Josh Bleecher Snyder observes that `git replace` doesn't seem to respect `GIT_NAMESPACE` - replacements created in one namespace appear to affect all namespaces. He demonstrates this with commands showing that a replacement object is visible even when querying through a different namespace, which seems counterintuitive given how other Git operations handle namespaces.

The email poses this as a question rather than proposing a fix - asking whether this is a bug (and thus might be fixed) or working as intended. The behavior appears to contradict the expected isolation between namespaces, but the email doesn't dig into technical details about why this might be happening or what the implications of changing it would be. This seems like it could be either a bug report or a request for design clarification, depending on maintainer perspective.
