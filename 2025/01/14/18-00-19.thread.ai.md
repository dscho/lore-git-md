Security release announcement for Git maintenance versions v2.48.1, v2.47.2, v2.46.5, v2.45.3, v2.44.3, v2.43.5, v2.42.3, v2.41.2, and v2.40.4, addressing two critical CVEs: CVE-2024-50349 (credential phishing via malicious URLs containing control sequences during recursive clones) and CVE-2024-52006 (credential protocol handling vulnerabilities from carriage return misinterpretation). Johannes Schindelin (Dscho) led the security response, coordinating fixes that make Git reject URLs with control sequences. Tarballs are available at kernel.org and other sources, with tags pushed to multiple repositories. 

The thread details a version metadata inconsistency in v2.47.2 where `GIT-VERSION-GEN` incorrectly shows v2.47.1 in tarball builds due to an unupdated `DEF_VER` variable, though the security fixes are fully present. Schindelin provides technical clarification that this only affects tarball builds (not Git checkouts where the tag is correct) and offers two workarounds for Randall Becker's NonStop packaging needs: building from Git checkouts or manually creating a `version` file. He firmly states retagging is not possible due to release coordination constraints, maintaining the security content is unaffected while acknowledging packaging workflow impacts. The thread captures the tension between urgent security fixes and downstream packaging concerns, with Schindelin as the authoritative voice on both the security implementation and build system behaviors. All releases contain the complete credential phishing protection (CVE-2024-50349) and credential protocol fixes (CVE-2024-52006), with v2.47.2's metadata inconsistency being a non-security packaging issue that has documented workarounds.
