Security release thread for Git maintenance versions v2.48.1, v2.47.2, v2.46.5, v2.45.3, v2.44.3, v2.43.5, v2.42.3, v2.41.2, and v2.40.4, addressing CVEs CVE-2024-50349 (credential phishing via malicious URLs with control sequences during recursive clones) and CVE-2024-52006 (credential protocol handling vulnerabilities from carriage return misinterpretation). Johannes Schindelin (Dscho) led the security response, implementing fixes that reject URLs with control sequences. The thread reveals a version metadata inconsistency in v2.47.2 where tarball builds incorrectly show v2.47.1 due to an unupdated DEF_VER variable in GIT-VERSION-GEN, though all security fixes are present. Schindelin clarified this only affects tarball builds (not Git checkouts) and provided workarounds including a `version` file method. Junio C Hamano reassured Schindelin about the oversight while confirming v2.48.1 was correctly processed. Randall Becker now reports NonStop's packaging constraints prevent using v2.47.2 entirely due to their environment's strict unmodified-commit requirements, forcing them to skip this version and direct users to v2.48.1 despite potential upgrade friction. This demonstrates how build system details can have outsized impact in regulated environments, with the thread capturing both the security implementation (complete across all versions) and downstream consequences of the v2.47.2 metadata issue (isolated to tarball builds but blocking NonStop adoption). Schindelin remains the technical authority on the fixes while Becker's response highlights real-world packaging constraints that make version metadata accuracy critical for some distributions.
