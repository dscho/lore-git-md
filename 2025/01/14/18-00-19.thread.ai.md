Security release thread for Git maintenance versions v2.48.1, v2.47.2, v2.46.5, v2.45.3, v2.44.3, v2.43.5, v2.42.3, v2.41.2, and v2.40.4, addressing CVEs CVE-2024-50349 (credential phishing via malicious URLs with control sequences during recursive clones) and CVE-2024-52006 (credential protocol handling vulnerabilities from carriage return misinterpretation). Johannes Schindelin (Dscho) led the security fixes that reject URLs with control sequences. The thread revealed a version metadata inconsistency in v2.47.2 where tarball builds incorrectly show v2.47.1 due to an unupdated DEF_VER variable in GIT-VERSION-GEN, though all security fixes are present. Randall Becker (NonStop maintainer) explained their certification process requires unmodified commit-based builds, making the tarball version discrepancy irrelevant but forcing them to skip v2.47.2 entirely due to other compliance requirements. Junio Hamano clarified that repository builds (NonStop's method) correctly report "2.47.2" via `git describe` regardless of the DEF_VER issue, expressing puzzlement why this remains a blocking concern given NonStop's build-from-repo approach would naturally produce accurate version strings. This suggests either unstated additional certification constraints or a misunderstanding of NonStop's exact requirements. The discussion continues to document both the security implementation (complete across all versions) and real-world deployment constraints, with Schindelin as technical authority on the fixes while Hamano and Becker provide maintainer and downstream packaging perspectives. The situation highlights potential need for more rigorous version metadata handling in security releases to accommodate environments with strict certification requirements, though the core security fixes are verified as properly backported regardless of version reporting method.
