This is a follow-up in the security release thread, focusing on packaging constraints for the NonStop platform. Randall Becker explains they cannot package v2.47.2 due to its version metadata inconsistency (DEF_VER still showing v2.47.1 in tarball builds), as their highly regulated environment prohibits any modifications - even workarounds like the `version` file method suggested by Johannes Schindelin. The issue stems from strict requirements that only unmodified official commits are acceptable for their customer base. 

The email reveals a real-world impact of the version metadata issue: Becker's organization will skip v2.47.2 entirely and direct users to v2.48.1 instead, despite potential user dissatisfaction with forced upgrades. This highlights how packaging constraints in regulated environments can amplify the consequences of what might otherwise be a minor build system oversight. 

Key technical details for future reference: the problem specifically affects tarball builds (not Git checkouts) due to the unupdated DEF_VER variable in GIT-VERSION-GEN, and the suggested workaround (creating a `version` file) is unusable in this constrained environment. The exchange demonstrates the tension between security urgency and downstream packaging realities, with Becker's response showing how release artifacts' exact contents can be critical for some distributions.
