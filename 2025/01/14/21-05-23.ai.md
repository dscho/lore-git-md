This is a follow-up in the security release thread regarding a version metadata inconsistency in Git v2.47.2. Johannes Schindelin clarifies the technical details around the `GIT-VERSION-GEN` oversight where the `DEF_VER` variable still shows v2.47.1, explaining this only affects tarball builds and not Git checkouts (where the tag name correctly shows v2.47.2). He provides two workarounds for Randall Becker's NonStop packaging needs: either building from a Git checkout where the version is correct, or manually creating a `version` file to hard-code v2.47.2 during tarball builds.

Schindelin firmly states that retagging v2.47.2 is not an option due to the coordinated release process, emphasizing the security fixes are properly included regardless of this metadata issue. The email maintains that the security content is unaffected while acknowledging the packaging inconvenience, offering practical solutions that don't require reissuing the release. This continues the thread's theme of balancing urgent security fixes with downstream packaging concerns, with Schindelin providing technical specifics about version detection mechanisms in Git's build system.
