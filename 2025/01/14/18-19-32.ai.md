This is the third and final patch in a security-focused series addressing ANSI escape sequence injection in Git's sideband channel. It modifies the previous approach to specifically allow ANSI color sequences by default while still blocking other potentially dangerous control characters.

The patch introduces a three-state configuration for `sideband.allowControlCharacters` (defaulting to `color` mode) where:
1. `color` (default) permits ANSI color sequences while blocking other control chars
2. `false` blocks all control chars except basic whitespace
3. `true` allows all control characters (original unsafe behavior)

Key technical elements include:
- New `handle_ansi_color_sequence()` function that validates and passes through only proper ANSI color codes
- Enhanced `strbuf_add_sanitized()` that now distinguishes between color sequences and other control chars
- Expanded test coverage verifying color preservation while still blocking non-color control chars like BEL (\a)
- Updated documentation explaining the three configuration modes and their security implications

The change is motivated by real-world use cases where `pre-receive` hooks rely on color output, while maintaining security against malicious sequences. The implementation carefully preserves the colorization infrastructure from earlier patches while making the safe-by-default behavior more practical for common workflows.

This concludes the series that began with CVE-2024-32002 fixes, now providing both security and usability with configurable escape sequence handling in the sideband channel.
