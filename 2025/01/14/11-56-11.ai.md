Performance optimization in version generation script, part of a larger meson build system series.

This patch simplifies how Git detects and marks "dirty" versions in the GIT-VERSION-GEN script. Currently it uses a manual `git diff-index` check for dirty state, but switches to using `git describe --dirty` which provides the same functionality. The change is both cleaner (removing several lines of custom logic) and faster, particularly on Windows where the improvement is most noticeable (from ~800ms to ~400ms per run).

The commit explains this was originally split into separate operations because `git describe` didn't support `--dirty` when the version marking was first implemented in 2008. The patch includes benchmark results showing a 1.43x speedup on Unix systems, though the real win is for Windows where filesystem operations are slower.

The change touches the core version generation script but is low-risk since it's just consolidating functionality that already exists in Git's plumbing. It's the first in an 11-part series (as indicated by [PATCH v2 01/11]) focused on meson build system additions, though this particular change is build-system agnostic. The clean, focused implementation with clear benchmarks suggests this is production-ready.
