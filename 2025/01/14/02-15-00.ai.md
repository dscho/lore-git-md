This is the final patch (8/8) in a v10 series implementing remote object-info functionality. It adds a `remote-object-info` command to `git cat-file --batch-command` that queries object sizes from remote repositories without downloading the full content.

The patch introduces a new command that accepts multiple OIDs in a single request to minimize round-trips when querying remote servers. It works across git://, file://, and http:// transports when the remote has the object-info` capability enabled (via `transfer.advertiseobjectinfo`). The implementation handles both buffered and non-buffered modes, with special logic to batch remote requests efficiently.

Key technical details:
- New `remote-object-info` command in `builtin/cat-file.c` with custom parsing logic
- Uses existing transport` infrastructure with new `object_info` flag
- Default format is `%(objectname) %(objectsize)` (object type not yet supported)
- Comprehensive tests in `t1017` covering all transports and failure modes
- New `free_object_info_contents()` helper in `object-file.c`
- Error handling for unsupported formats (`objecttype`, `deltabase`, etc.)
- Protocol v2 required - clear error messages for v0/v1 attempts

The implementation is thorough with extensive test coverage across all major protocols. It completes the end-to-end functionality started in earlier patches, with documentation noting current limitations (like unsupported format options) that may change in future. The patch follows the series' pattern of careful error handling and clear user feedback when capabilities are missing.
