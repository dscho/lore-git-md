Performance optimization adding zlib-ng support as an alternative zlib backend. This is patch 8/10 in a series that has systematically built up infrastructure for runtime switching between standard zlib and the optimized zlib-ng fork.

The patch implements build system support for linking against zlib-ng's prefixed API (`zng_*` symbols) when configured via `ZLIB_NG=1` in Make or `zlib_backend=zlib-ng` in meson. This addresses distribution packaging constraints where zlib-ng cannot globally replace zlib. The compatibility layer remaps all zlib symbols to their zlib-ng equivalents via macros in `compat/zlib-compat.h`.

Benchmarks show a ~25% speedup in `git cat-file --batch-all-objects` when using zlib-ng's vectorized implementations (SSE2/AVX2). The changes maintain full compatibility with both build systems and preserve the ability to use standard zlib. The implementation handles symbol remapping at compile time rather than requiring runtime detection, keeping the compatibility layer lightweight.
