This security release thread began with Johannes Schindelin (Dscho) announcing patches for two critical CVEs affecting credential handling, with fixes backported across multiple Git versions. A version metadata inconsistency in v2.47.2's tarball builds (showing v2.47.1 due to an unupdated DEF_VER variable) emerged as a secondary issue, though Junio Hamano confirmed the security fixes themselves were complete. 

The discussion has now revealed real-world consequences of this packaging issue. Randall Becker explains that their NonStop platform's strict compliance requirements prevent them from using v2.47.2 or applying Schindelin's suggested workarounds, forcing them to skip this version entirely and direct users to v2.48.1 instead. This illustrates how even minor build system inconsistencies can create significant downstream challenges in regulated environments where unmodified official releases are mandatory. 

The core security fixes for CVE-2024-50349 (credential phishing via malicious URLs) and CVE-2024-52006 (credential protocol vulnerabilities) remain unaffected and are fully present in all released versions. The thread has evolved from technical implementation details to highlighting the practical constraints faced by specialized distributions, with Schindelin providing technical clarifications and Becker representing the needs of strictly regulated deployment environments.
