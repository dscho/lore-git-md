Performance optimization patch in the LSan test infrastructure series. This is the fourth of six patches addressing LeakSanitizer race conditions in Git's test suite.

The patch simplifies the leak detection logic in `test-lib.sh` by removing the now-unused `nr_san_dir_leaks_` counting function and folding its functionality directly into `check_test_results_san_file_empty_`. The change reflects that since commit 95c679ad86, the test infrastructure only needs to know whether any leaks were found (a boolean result) rather than counting them. The implementation now directly checks for non-empty results by inverting the grep output with `!` and `-qv` flags.

Key technical details:
- Removes 13 lines of counting infrastructure while maintaining the same functionality
- Modifies the leak check to return true when no leaks are found (matching existing expectations)
- Touches only `t/test-lib.sh` with no behavioral changes to other files
- Follows from earlier work in the series that isolated test outputs and removed synchronization barriers

The author notes some potential confusion around the inverted logic and suggests an alternative naming approach (`check_test_results_has_leaks`) that might be clearer, though this would require updating two callers. This appears to be a preparatory refactoring for upcoming changes in the series related to log-based false positive filtering.
