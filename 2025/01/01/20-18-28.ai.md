Performance optimization for LSan leak detection in tests. This is patch 5/6 in Jeff King's series addressing LeakSanitizer race conditions in threaded test execution.

The patch changes how the test infrastructure checks for memory leaks by looking specifically for `DEDUP_TOKEN` lines in LSan output rather than scanning for any non-empty log while ignoring uninteresting lines. This builds on previous work (370ef7e40d) that filtered out noisy output but was limited to single-line patterns. The new approach leverages the fact that LSan always includes `DEDUP_TOKEN` markers for actual leaks when `dedup_token_length` is enabled.

The key change is a one-line modification to `test-lib.sh` that replaces a grep pattern ignoring thread register messages with a positive match for `DEDUP_TOKEN`. This inversion of strategy makes the leak detection more robust by focusing on definitive leak markers rather than trying to exclude noise. It also sets the stage for future false positive filtering improvements mentioned in the commit message.

This patch follows logically from the series' earlier simplification of leak checking infrastructure (patch 4) and maintains the same functional behavior while improving the implementation approach. The change is minimal (just 1 line modified) but strategically important for the overall goal of threaded test execution with LSan. The patch appears well-considered, with clear explanation of both the technical approach and its benefits for future development.
