Performance optimization addressing LSan (LeakSanitizer) race conditions in stress test execution. This is the first of six patches in Jeff King's series tackling false positive leak reports in threaded test runs.

The patch fixes a long-standing but rarely noticed issue where multiple concurrent `--stress` test runs would all write to the same LSan output directory (`$TEST_NAME.leak`), causing log corruption and misattribution. The solution is straightforward: use the existing `$TEST_RESULTS_BASE` variable (which includes the stress job suffix) to create per-run leak directories, matching how other test results are already handled.

The change is minimal (a one-line modification to `t/test-lib.sh`) but important for reliable LSan diagnostics during stress testing. While the race condition was previously harmless in practice (since stress testing with LSan is uncommon), it becomes relevant when debugging the LSan stack unwinding race that's the series' main focus. The patch lays groundwork for subsequent changes by ensuring clean separation of LSan outputs across parallel test invocations.

Key technical details include the use of `TEST_RESULTS_BASE` (already containing `$TEST_STRESS_JOB_SFX`) and maintaining consistency with the existing `TEST_RESULTS_SAN_DIR_SFX=leak` convention. The solution avoids introducing new mechanisms by leveraging the test infrastructure's existing stress-test support.
