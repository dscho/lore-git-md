Bugfix addressing a long-standing edge case in object name resolution with curly braces in branch names. This fixes a 2006-era issue where Git would incorrectly reject branch names containing unpaired curly braces (like 'foo{bar') when used with path specifications (e.g., `git cat-file -p foo{bar:README.md`). The patch modifies the parsing logic in object-name.c to only treat braces as special when they follow an '@' symbol, preserving the existing @{...} functionality while allowing unpaired braces elsewhere.

The change is well-motivated with clear examples of both the broken behavior and the fixed case. Test coverage is thorough, verifying both the new handling of brace-containing names and backward compatibility with existing @{...} syntax. Junio C Hamano's response suggests the patch looks good, though he raises an interesting historical question about whether the original restriction was meant to prevent confusion with colons in commit searches. The patch appears ready for inclusion, addressing a real (if somewhat obscure) issue that could affect users with brace-containing branch names.
