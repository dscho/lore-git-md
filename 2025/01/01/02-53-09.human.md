This is a bugfix addressing a long-standing issue in Git's object name resolution when dealing with curly braces in branch names.

The patch fixes a case where Git incorrectly fails to resolve object names containing unpaired curly braces in branch names (like `foo{bar:README.md`). The issue stems from a 2006 change that assumed curly braces would only appear after '@' symbols and always be paired. The fix modifies the parsing logic to only enforce brace pairing when they immediately follow an '@' character.

Elijah Newren provides clear reproduction steps and test cases demonstrating both the original failure and the fixed behavior. The patch includes tests for both the curly brace case and a related case with '@@' in branch names. The commit message notes this is not a regression but a long-standing bug, and credits both the reporter and a helper from GitHub.

The changes are minimal (8 lines modified in object-name.c) but well-targeted, with 17 lines of new test coverage. This appears to be a straightforward fix for a niche but legitimate edge case in Git's object naming syntax.
