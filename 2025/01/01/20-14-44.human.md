Performance optimization in the LSan (LeakSanitizer) test infrastructure. This is patch 3/6 in a series addressing false positive leak reports in threaded test execution.

Jeff King proposes changing how the test suite handles LSan reports by making the sanitizer exit normally (exitcode=0) rather than aborting on leaks. The key insight is that the test suite already reliably detects leaks through log parsing (added in recent commits), making the abort behavior redundant. This change prepares for future work to better filter false positives.

The patch is a straightforward one-liner adding the exitcode option to LSAN_OPTIONS in test-lib.sh. It builds on several previous improvements to leak detection via logs, which now check results after every test snippet. The change is well-motivated by the series' goal of making leak detection more robust while reducing false positives from thread races.

This appears to be a solid incremental improvement that simplifies the test infrastructure while maintaining detection capabilities. The series as a whole shows careful attention to both the technical details of sanitizer behavior and the practical needs of Git's test suite.
