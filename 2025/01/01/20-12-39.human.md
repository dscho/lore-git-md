This is a performance and test infrastructure patch that fixes a race condition in LSan (LeakSanitizer) output handling during stress test runs. It's the first in a 6-part series addressing LSan false positives in threaded test execution.

The patch corrects an issue where multiple concurrent stress test runs would all try to the same LSan output directory, causing log corruption and spurious failures. Jeff King notes this wasn't previously noticed because stress tests (which run code repeatedly to find races) are rarely combined with LSan (which slows execution). The fix uses an existing `$TEST_RESULTS_BASE` variable that already includes stress job identifiers to give each run its own output directory.

The change is minimal - just one line modifying `t/test-lib.sh` to append the stress job identifier to the LSan output directory path. This appears to be a straightforward, well-motivated fix that properly isolates test artifacts. As the first patch in a series, it sets up the infrastructure needed by later patches that will implement more complex LSan handling logic. The commit message clearly explains both the problem exists and why the solution works.
