This is a clarification response in an ongoing thread about Git branch behavior. Junio C Hamano responds to Prasad Pandit's question about whether committed changes are visible across local branches.

The response clearly states that branches maintain independent development lines - changes committed on one branch do not automatically appear in another. Hamano emphasizes this is fundamental to version control systems, noting that changes only propagate between branches through explicit merge operations.

The email serves as a basic educational explanation of Git's branching model, correcting a common misconception. It's no-nonsense technical accuracy from the Git maintainer, though the thread appears to be addressing a very fundamental Git concept rather than discussing new development or changes to the system.
