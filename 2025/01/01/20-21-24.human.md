This is the final patch in a performance optimization series addressing LSan (LeakSanitizer) false positives in threaded test execution. Jeff King identifies and works around a specific race condition where LSan's own thread stack setup code can appear as a false leak when threads exit during test runs.

The patch modifies the leak detection logic in `test-lib.sh` to ignore these particular false positives by filtering out stack traces containing `sanitizer::GetThreadStackTopAndBottom` while still catching real leaks via the `DEDUP_TOKEN` markers. The change is minimal (just 3 lines modified) but effectively solves the intermittent test failures seen in threaded operations like `git-grep` and `index-pack` under stress testing.

Jeff notes this isn't a complete solution - if a real leak and this race condition occur simultaneously, the false positive would still mask the real issue. However, he considers this an acceptable tradeoff given the rarity of both conditions occurring together. The patch completes the series' goal of making LSan testing more reliable for threaded operations.
