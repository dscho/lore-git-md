Performance optimization completing a series addressing LSan false positives in threaded tests. This final patch (6/6) handles a specific race condition where LSan's own thread stack setup code appears to leak memory during concurrent test execution. The issue manifests when one thread calls exit() while another is in LSan's stack unwinding code, producing false leak reports mentioning `sanitizer::GetThreadStackTopAndBottom`.

The solution modifies the leak detection logic in `test-lib.sh` to filter out these known false positives by extending the `DEDUP_TOKEN` matching approach introduced in patch 5. The change adds a negative grep pattern to exclude stack traces containing the sanitizer's internal thread stack functions while preserving detection of real leaks. The patch acknowledges a minor tradeoff: if both a real leak and this race occur in the same test run, the false positive would mask the real issue, though this is considered unlikely in practice.

This completes the series' transition from earlier approaches involving thread synchronization barriers (removed in patch 3) to a more robust output-based filtering strategy. The change is minimal (3-line modification) but effectively addresses the remaining CI noise from stress tests like `t0003` and `t5309`. The solution demonstrates pragmatic handling of toolchain limitations while maintaining test reliability.
