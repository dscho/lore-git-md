This is part of the performance optimization series addressing LSan (LeakSanitizer) race conditions in threaded test execution. The patch modifies test infrastructure to improve leak detection reliability by changing how LSan reports errors.

The patch removes LSan's abort-on-error behavior (previously set via `abort_on_error=1`) in favor of relying solely on log parsing to detect memory leaks. This is now possible because recent test infrastructure changes (faececa53f, 8c1d6691bc, cf1464331b) have made leak log checking comprehensive and mandatory. The key change is adding `exitcode=0` to LSAN_OPTIONS, which suppresses process termination on leaks while still generating diagnostic logs.

This change serves two purposes: 1) eliminates redundant error detection mechanisms (since logs are now thoroughly checked) and 2) prepares for future false positive filtering by giving the test framework full control over leak assessment. The patch notes that while ASan/UBSan benefit from immediate abort behavior, LSan's post-execution leak checking makes this unnecessary.
