Bugfix for object name resolution with curly braces in branch names.

This patch fixes a long-standing issue (dating back to 2006) where Git would fail to resolve object names containing unpaired curly braces in branch names. The problem stems from an assumption in the parsing logic that curly braces would only appear after an '@' symbol and would always be paired. This caused commands like `git cat-file -p foo{bar:README.md` to fail when they should succeed.

The fix modifies the parsing logic in object-name.c to only consider curly braces as special when they immediately follow an '@' character. The patch includes test cases verifying both the fixed behavior (handling branch names with unpaired curly braces) and ensuring existing functionality (handling '@{...}' syntax) remains intact.

Key technical details:
- Changes parsing logic in get_oid_with_context_1() to be more precise about when to count curly braces
- Adds tests in t1006-cat-file.sh for both the fixed case (foo{bar:hello) and the existing case (foo@@{0}:hello)
- Maintains backward compatibility with the @{...} syntax while fixing the unpaired brace case

The patch appears well-constructed with clear commit message explaining both the problem and solution, and includes appropriate test coverage. The fix addresses a real edge case that could affect users with branch names containing curly braces.
