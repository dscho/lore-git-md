This thread addresses a bug in Git's object name resolution that has existed since 2006, where commands would fail when encountering branch names containing unpaired curly braces. The issue stems from overly strict parsing assumptions in object-name.c that didn't properly handle this edge case.

The proposed fix modifies the parsing logic in get_oid_with_context_1() to only treat curly braces as special when they immediately follow an '@' character, which preserves the existing @{...} syntax while correctly handling branch names containing unpaired braces. The patch includes comprehensive test cases in t1006-cat-file.sh that verify both the new behavior (allowing commands like `git cat-file -p foo{bar:README.md`) and ensure existing functionality remains intact.

The solution appears well-considered, with a clear commit message explaining the problem's history and the chosen approach.
