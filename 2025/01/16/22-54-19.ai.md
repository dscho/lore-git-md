This is a documentation patch discussion about standardizing how boolean options are presented in Git's man pages.

Junio C Hamano responds to D. Ben Knoble's patch that added explicit documentation for negated `--no-line-number` and `--no-column` options in `git-grep`. While acknowledging the usefulness of negating these options, Junio argues against documenting each negated form separately. He points out two key issues: (1) it's redundant to repeatedly state that command-line options override config settings, as this is a universal Git behavior, and (2) Git already has a standard convention for documenting boolean options using the `--[no-]option` syntax (as seen in other commands like `git blame`).

The response suggests modifying the original patch to use this bracketed `[no-]` notation instead of adding separate entries for negated options. Junio notes this approach is already understood by users (with `git help cli` explaining the convention) and maintains consistency across Git's documentation. The thread continues the theme of documenting `git grep`'s negatable options but shifts focus to following existing documentation patterns rather than introducing new ones.
