Maintainer response to `git grep` negatable options documentation.

Junio Hamano responds to D. Ben Knoble's patch proposing explicit documentation of `--no-line-number` and `--no-column` options in `git-grep.txt`. While acknowledging the use case, Hamano suggests a more maintainable approach: using the existing `--[no-]` syntax convention seen elsewhere in Git's documentation (like `--[no-]progress` in blame) rather than adding separate entries for negated options.

The response makes two key points: (1) Git already has a pattern where command-line options override config settings, and we shouldn't redundantly document this for each option, and (2) the `--[no-]` syntax both indicates an option is boolean and implicitly documents its negated form. Hamano notes this convention is explained centrally in `git help cli`.

This appears to be a documentation style discussion rather than a technical disagreement - the underlying functionality isn't in question, just how best to document it. The response suggests the original patch could be simplified to just use the bracketed syntax while maintaining the same clarity for users. The tone is constructive, offering a documented precedent from `git blame` as an example of the preferred approach.
