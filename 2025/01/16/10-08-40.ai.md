Refactoring patch in the reftable type-cleanup series, converting block length from `int` to `size_t`.

This patch continues the systematic conversion of signed types to unsigned variants where negative values are impossible, focusing on the block length field in the reftable block structure. The change affects `reftable_block.len`, which tracks byte counts and thus should never be negative. The modification is straightforward - just updating the type declaration in `reftable-blocksource.h` from `int` to `size_t`.

This change aligns with the series' goal of eliminating signed/unsigned comparison warnings while improving type correctness. The block length modification follows similar conversions already made to other size-related fields in the reftable codebase. Since this is a core structure used throughout the reftable implementation, the change will propagate to all block handling code, though the diff shows only the header modification. The patch maintains consistency with the series' approach of using unsigned types for size/count fields while preserving the existing 32-bit integer usage pattern seen elsewhere in the codebase.
