This is a feature addition to `git gc`, adding `--expire-to=<dir>` support to mirror existing `git repack` functionality for cruft pack management. The patch is now in its final form after incorporating review feedback, with Junio Hamano providing some last-minute documentation and testing suggestions.

The change allows specifying a directory where expired cruft packs should be stored during garbage collection, simplifying server-side maintenance workflows. The implementation carefully handles the `-a` flag when both `--cruft` and `--expire-to` are specified, avoiding premature deletion of unreachable objects.

Junio's review notes some minor documentation clarifications needed around when the option applies (it requires `--cruft`, which is on by default) and suggests expanding test coverage to verify behavior with `--no-cruft`. These appear to be straightforward follow-ups rather than fundamental issues with the patch.

The change builds on established cruft pack infrastructure and follows the same patterns used in `git repack`, with proper test coverage already in place. It's a focused, well-motivated addition that completes the integration of cruft pack management into the higher-level `git gc` command.
