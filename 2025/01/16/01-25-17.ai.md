This is a cover letter for a patch series addressing consistency in help text output behavior across Git commands. The series aims to standardize how `git cmd -h` displays help text by ensuring it always goes to stdout rather than stderr, fixing an inconsistency between commands using parse-options API and older manual implementations.

The series stems from Jonas Konrad's observation that `git branch -h` unexpectedly outputs help to stderr. Investigation revealed this inconsistency affects many commands - those using parse-options API correctly output to stdout, while older commands using manual `usage()` or `usage_with_options()` calls send help to stderr. The patches systematically update these cases.

Key technical details:
- Adds new helper functions `show_usage_help_and_exit_if_asked()` (parse-options) and `show_usage_and_exit_if_asked()` (usage.c) to centralize the stdout behavior
- Updates 38 builtin commands across 41 files to use these helpers
- Includes test updates in t0012-help.sh to verify stdout behavior
- Maintains existing stderr output for error cases while reserving stdout for explicit `-h` requests

The changes are mechanical but widespread, touching many commands' help output plumbing. The series appears well-structured with Jeff King contributing test infrastructure and Junio handling the bulk of the command updates. The commit messages clearly explain the rationale and implementation approach. This looks like a straightforward quality-of-life improvement that should be uncontroversial.
