This is part 3 of a 6-part series standardizing help text output behavior across Git commands. The patch introduces a new helper function `show_usage_if_asked()` that encapsulates the common pattern of checking for `-h` and showing usage text, similar to the `show_usage_with_options_if_asked()` helper introduced in patch 2.

The new helper replaces manual `-h` checks that would previously call `usage()` directly, ensuring consistent stdout output (rather than stderr) while maintaining the existing exit code 129 for compatibility. The implementation uses a new `vfdreportf()` function that allows directing output to either stdout or stderr as needed, with the helper specifically routing help text to stdout (fd 1).

The patch includes careful handling of error cases - while help text goes to stdout, actual error messages still go to stderr. The exit code remains 129 for now, though the commit message notes this could be revisited later since help requests are successful operations that might warrant exit code 0.

This is an infrastructure change that enables converting individual commands in subsequent patches. The implementation builds on the series' earlier work while maintaining strict backward compatibility, as verified by the test infrastructure from patch 1. The helper's name was refined through review discussion to be concise yet clear about its conditional nature ("if_asked").
