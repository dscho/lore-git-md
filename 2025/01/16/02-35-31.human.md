This is a feature patch adding cruft pack management to `git gc`, consolidating the previous two-patch series into one. It introduces a `--expire-to` option for `git gc` that mirrors the existing `git repack --expire-to` functionality, allowing users to specify a directory where expired cruft packs should be stored during garbage collection.

The patch simplifies the workflow for users who want to safely manage repository cleanup, particularly on servers where concurrent pushes might cause issues. Previously they had to run separate `git repack` and `git prune` commands to achieve this. The implementation forwards the `--expire-to` parameter to `git repack` and includes appropriate documentation and test coverage.

Notably, when both `--cruft` and `--expire-to` are used together, `git gc` no longer passes `-a` to `git repack` to delete all unreachable objects (as it would with `--prune=now`), instead generating a cruft pack in the specified directory. The patch has been reviewed by Jeff King and incorporates feedback to avoid introducing intermediate buggy states.

This appears to be a well-considered addition that follows established patterns from the repack implementation, with clear documentation and tests. It addresses a specific use case for server maintenance while maintaining backward compatibility.
