Feature addition to `git gc` for cruft pack management, consolidating the v2 series into a single patch. This patch adds `--expire-to=<dir>` support to `git gc`, mirroring the existing `git repack --expire-to` functionality (from commit 91badeb). The key change allows specifying a directory where expired cruft packs are stored during garbage collection, simplifying the workflow compared to manually running `git repack` followed by `git prune`.

The implementation:
- Adds `repack_expire_to` field to `gc_config`
- Updates `add_repack_all_option()` to handle the new parameter
- Includes documentation updates in `git-gc.txt`
- Adds test coverage in t6500-gc.sh
- Preserves backward compatibility while adjusting behavior when both `--cruft` and `--expire-to` are used (skipping `-a` in this case)

The patch follows prior discussion where Jeff King reviewed the logic and suggested consolidation to avoid intermediate buggy states. The current version correctly safeguards against invalid combinations and maintains expected behavior. The change aligns with Taylor Blau's ongoing cruft pack work while providing immediate utility for server-side repository maintenance.
