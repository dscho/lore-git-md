This is part 2/5 in a series continuing the `the_repository` removal effort, specifically targeting pack-writing functionality. The patch converts `index_pack_lockfile()` to take an explicit `struct repository*` parameter instead of relying on the `the_repository` global. The function is used during pack operations to generate lockfile paths, and this change affects callers in receive-pack and fetch-pack.

The modification follows the established pattern of bubbling up repository context to callers. While the patch still passes `the_hash_algo` (acknowledged as a temporary measure), it properly uses the repository->hash_algo internally. The changes are mechanical but thorough, updating both the function definition and all call sites across builtin/receive-pack.c, fetch-pack.c, and the pack-write.c/pack.h interface.

The patch maintains compatibility while removing one more dependency on global state. It's a straightforward conversion that fits cleanly into the larger series' goal of eliminating `the_repository` usage in pack operations. The changes span multiple subsystems (receive-pack, fetch-pack) but are focused on a single well-defined function conversion, following Git's incremental refactoring approach.
