Refactoring patch in the help text standardization series, focusing on output stream handling.

This patch introduces `show_usage_if_asked()` as a helper to consolidate the common pattern where commands check for `-h` and call `usage()`. The new helper follows the same approach as earlier patches in the series, ensuring help text goes to stdout rather than stderr while maintaining the exit code 129 for now (though the commit message notes this may change later).

The implementation refactors the underlying reporting mechanism to use `vfreportf()` which takes a FILE* parameter, replacing the previous `vreportf()` that was hardcoded to stderr. This change supports writing to either stdout or stderr while maintaining the same flushing behavior. The patch includes both the new helper function and the infrastructure changes needed to support it.

Key technical details:
- Adds `show_usage_if_asked()` declaration to git-compat-util.h
- Introduces `vfreportf()` as the new base function that takes a FILE* parameter
- Keeps `vreportf()` as a wrapper that calls `vfreportf()` with stderr
- Maintains the same flushing behavior via `fflush()` followed by `write_in_full()`
- Preserves exit code 129 for compatibility, though the commit message questions whether this should change to 0 in the future

This is part of the ongoing effort to standardize help text behavior across Git commands, building on previous work to convert `usage_with_options()` calls. The patch appears ready for inclusion, having addressed earlier feedback about stream handling and flushing behavior.
