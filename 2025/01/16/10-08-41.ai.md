This is part 9/10 of a refactoring series addressing type safety and compiler warnings in the reftable codebase, specifically focusing on the blocksource subsystem. The patch changes the return type of `block_source_read_block()` and related functions from `int` to `ssize_t` to better indicate that these functions return either a byte count (like read(3p)) or a negative error value. This makes the interface more self-documenting and helps avoid signed/unsigned comparison warnings.

Key changes include:
- Updating the function signatures in blocksource.c, reader.c, and their headers
- Modifying `reader_get_block()` to only return success/failure rather than propagating the byte count
- Adjusting error checking in `reftable_reader_new()` to properly handle the new return type
- Updating documentation comments to reflect the change

The patch follows the series' pattern of careful type adjustments while maintaining existing functionality. It touches core reftable reading infrastructure but doesn't change behavior - just makes the interfaces more precise. The changes are straightforward and well-contained, with corresponding updates to all callers. This continues the series' goal of improving type safety as reftable moves toward being a standalone library.
