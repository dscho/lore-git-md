Test infrastructure patch for the help output consistency effort.

This is the second patch in a 6-part series standardizing where Git commands send their "-h" help output. Currently, some commands print to stdout while others use stderr, depending on whether they use the parse-options API. The series aims to make stdout the consistent destination.

This particular patch modifies the test suite to optionally enforce stdout-only output when the environment variable GIT_TEST_HELP_MUST_BE_STDOUT is set. This allows developers working on converting commands to check for compliance while keeping the default test behavior permissive during the transition period. The change affects t0012-help.sh, making it check either output or error streams based on the flag.

The patch comes from Jeff King (with Junio Hamano signing off) and shows good forward-thinking design - it provides a migration path rather than an abrupt change. The test modification is clean and maintains existing functionality while adding the new checking capability. This is a well-executed step in the broader effort to standardize help output behavior across Git commands.
