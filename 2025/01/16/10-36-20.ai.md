This is a code review discussion about naming and implementation details in the ongoing help text standardization series.

Jeff King (Peff) responds to Junio's patch introducing `show_usage_and_exit_if_asked()`, which centralizes help text handling for commands not using parse-options. The main discussion points are:
1. Naming confusion between this new helper and the earlier `show_usage_help_and_exit_if_asked()` from parse-options.c. Peff suggests shorter alternatives like `show_usage_if_asked()` and `show_usage_with_options_if_asked()` that drop the "and_exit" as redundant.
2. Concerns about the implementation of `vfdreportf()` which handles output to arbitrary file descriptors. Peff finds the fd-based approach "gross" and suggests using FILE* instead to maintain proper flushing behavior and avoid potential output ordering bugs.

The discussion remains constructive despite the "bikeshed" nature of naming debates, with Peff acknowledging the patch's value while suggesting refinements. This email doesn't propose concrete changes but rather explores alternatives that might be addressed in a v4 of the patch series. The thread context shows this is part of a well-structured effort to standardize help output behavior across Git commands.
