Performance optimization series (zlib-ng support) - removing obsolete zlib compatibility define.

This patch removes the `z_const` define from git-compat-util.h, which was previously used to override zlib's const-correctness behavior. The change is part of the ongoing zlib-ng optimization series and follows the removal of the `uncompress2()` compatibility shim in the previous patch.

The `z_const` define was originally introduced in commit 07564773c2 as part of zlib compatibility work, but the commit message didn't explain its purpose. The author argues there's no good reason to maintain this define since it doesn't actually change the const-ness of parameters - it just suppresses the const qualifier in zlib API declarations. The change is safe because it doesn't affect functionality, only potentially making the API declarations more accurate by allowing zlib's natural const annotations to appear.

This is a straightforward cleanup that removes legacy code now that the zlib-ng integration has made the compatibility shims unnecessary. The patch is small (just one line removed) and well-justified, with no apparent downsides. It continues the series' theme of removing obsolete zlib compatibility code while preparing for the zlib-ng backend support.
