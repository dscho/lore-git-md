This is a technical discussion about the implementation details of the Git usage message standardization effort, specifically around how to handle file descriptor flushing when printing help text.

Jeff King (Peff) responds to Junio Hamano's concerns about the current approach to flushing stderr before writing usage messages. The core debate centers on whether to:
1. Keep the current direct file descriptor approach with manual flush checks (as in the original patch)
2. Switch to using FILE* streams which would automatically handle flushing via fileno()

Peff argues for the FILE* approach, noting it's conceptually cleaner and matches the original intent of flushing any buffered stdio output before writing. He provides a concrete patch showing how this would simplify the code by removing explicit fd==2 checks and using fflush() consistently.

The discussion is highly technical but shows careful attention to edge cases - Peff acknowledges the unlikely scenario of stdout being written before "-h" processing but suggests the safer approach should be taken as a general principle.
