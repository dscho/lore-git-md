This is a refactoring patch in a series addressing compiler warnings and type safety in the reftable codebase. It changes the `hash_size()` function to return `uint32_t` instead of `int`, since hash sizes are inherently non-negative values. The change propagates through multiple files that use this function, including block handling, record processing, and test code.

The patch removes now-unnecessary assertions that previously verified the hash size was positive, since the type system now enforces this. The changes are mechanical but widespread, touching basics.c/h, block.c/h, reader.c, record.c/h, and test files. This is part of a larger effort to make the reftable implementation more type-correct and suitable for standalone library use.

Key technical details for future reference:
- Function signature changes in basics.c/h (hash_size return type)
- Updated parameter types in block writer/reader interfaces
- Modified record handling functions to use uint32_t for hash_size parameters
- Test updates to match new types
- Removed redundant assertions about positive hash sizes
- Changes propagate through record comparison and encoding/decoding logic

The patch appears straightforward and well-contained within the series' goal of type safety improvements. It follows the pattern established in earlier patches of the series by converting signed types to unsigned where appropriate.
