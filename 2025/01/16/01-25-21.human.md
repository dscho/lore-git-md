This is part 4/6 of Junio Hamano's series to standardize help text output behavior across Git commands. The patch introduces a new helper function `show_usage_and_exit_if_asked()` that provides a standardized way for commands to handle `-h` help requests, similar to the parse-options helper introduced earlier in the series.

The new helper replaces the common pattern where commands manually check for `-h` and call `usage()`, which previously sent output to stderr. Like the parse-options helper, this new version ensures help text goes to stdout while maintaining the existing exit code 129 for compatibility. The implementation includes some refactoring of the underlying `vreportf()` function to support output to arbitrary file descriptors.

The patch notes that while the exit code 129 is preserved for now (as required by existing tests), this may be revisited later since a help request is technically a user asking for information rather than an error condition. This continues the series' careful approach of first establishing consistent behavior before potentially optimizing further.

As with previous patches, this change is infrastructure-focused, setting up the helper that will be used by subsequent command conversions. The implementation appears clean and well-contained, with the diff showing both the new helper and the necessary plumbing changes to support it.
