This is a discussion about ref validation checks in Git's ref backend systems, part of an ongoing bugfix series addressing packed-refs validation issues.

Patrick Steinhardt responds to shejialuo's initial patch that added object existence and type checking for regular refs in the files backend. While agreeing with the need for such validation, Patrick questions whether this check belongs specifically in the files backend implementation. He suggests the validation might be better placed in the more generic `git refs verify` command, since these checks (verifying object existence and type correctness) would apply equally to other backends like reftable.

The comment indicates a potential architectural mismatch in the original patch's approach, proposing to move the validation logic up a level to make it backend-agnostic. This aligns with the thread's broader theme of improving ref validation while maintaining consistency across different storage backends. The discussion of specific implementation details suggests this is still an open question rather than settled design.
