git grep documentation update discussing negatable options presentation.

The thread documents that `git grep`'s `--line-number` and `--column` options can be negated (as `--no-line-number` and `--no-column` respectively), overriding grep.lineNumber and grep.column config settings. D. Ben Knoble's initial patch added these as separate documented options, while Junio C Hamano suggests following Git's standard `--[no-]option` bracketed notation instead, citing consistency with other commands like `git blame` and the universal understanding that command-line options override configs. The discussion now centers on documentation style rather than functionality, with Junio advocating for the established pattern that avoids redundant explanations of config override behavior. No behavior change is proposed - this remains purely a documentation clarification, now considering how best to present boolean options following Git's existing conventions. The thread shows maintainer preference for standardized documentation patterns over command-specific explanations of common behaviors.
