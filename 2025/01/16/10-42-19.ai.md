This is a review comment in the ongoing series standardizing help text output behavior. Jeff King (Peff) responds to Junio Hamano's patch converting "oddball" usage() callers to the new stdout-based help system.

Peff notes that while some commands use clever/obscure argc/argv checks for help requests, builtin/var.c represents a different case - it doesn't explicitly check for "-h" at all, instead treating it as an invalid variable name. He confirms Junio's approach of adding show_usage_and_exit_if_asked() is correct here, though this case differs from the other "oddballs" being converted.

The exchange highlights an edge case in the standardization effort - commands where help requests get caught by other validation logic rather than explicit "-h" checks. Peff's observation suggests the series is handling these cases appropriately while maintaining the goal of consistent stdout output for help text. This appears to be a minor implementation detail in an otherwise well-progressing series that's nearing completion (patch 5/6).
