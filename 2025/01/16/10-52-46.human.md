Performance analysis of `git bisect` initialization bottleneck. Jeff King responds to Ben Knoble's timing data with a technical deep dive into why bisect` initialization scales poorly on large repositories like Linux (1M+ commits). He identifies quadratic behavior in `do_find_bisection()` where the algorithm repeatedly traverses commit lists to set and clear distance flags. While acknowledging the fundamental scaling issue, King suggests a potential optimization: instead of clearing flags across the entire list for each commit, the code could target only reachable commits from the current tip. He notes this wouldn't eliminate the quadratic worst case but might yield practical improvements. The analysis confirms this as a known architectural limitation requiring deeper changes to the bisect machinery for proper scaling.
