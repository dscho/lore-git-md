This is a cover letter for a patch series standardizing help text output behavior across Git commands. The series addresses an inconsistency where some commands output help text to stderr when using `-h`, while others use stdout. The core change ensures all built-in commands send help text to stdout for `-h` requests, while maintaining the existing exit code (129) for compatibility.

The series has evolved through several rounds of review, with key refinements to function names (`show_usage_if_asked()` and `show_usage_with_options_if_asked()`) and careful handling of edge cases like `builtin/var.c` and `fetch-pack.c`. The implementation follows a structured approach: first introducing helper functions (patches 1-3), then converting commands in two waves - those using `usage_with_options()` (patch 4) and those using direct `usage()` calls (patches 5-6).

Reviewers have validated the approach, including proper handling of error cases and edge conditions. While the series focuses on stdout behavior, the cover letter notes that exit code standardization (potentially changing from 129 to 0) could be a future improvement. The changes are well-tested with comprehensive coverage in t0012-help.sh.

This appears to be a well-executed cleanup that improves consistency without breaking existing behavior. The careful staging and thorough review process suggest it's ready for inclusion, with potential follow-ups identified but deliberately separated from this core standardization effort.
