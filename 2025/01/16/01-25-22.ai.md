This is part 5/6 of the series standardizing help text output behavior across Git commands, specifically handling "oddball" commands that don't follow the typical pattern for checking help requests. The patch converts four commands (`credential`, `unpack-file`, `upload-archive`, and `var`) to use the new `show_usage_and_exit_if_asked()` helper from patch 4/6, ensuring their help text goes to stdout rather than stderr.

The key challenge addressed here is that these commands had non-standard help request detection - some used inverted logic (`argc != 2 || !strcmp(argv[1], "-h")`), while others didn't specially handle "-h" at all. The patch refactors them to first check for help requests using the new helper, then proceed with their normal error handling. Each command now has consistent behavior where "-h" prints help to stdout and exits with status 0, while invalid usage still exits with an error.

The changes are mechanical but require careful attention to maintain existing error handling semantics. The patch follows the series' established pattern of infrastructure-first development, with the helper function already introduced in patch 4/6. No test changes are needed here since the test framework from patch 2/6 already verifies the stdout behavior system-wide.
