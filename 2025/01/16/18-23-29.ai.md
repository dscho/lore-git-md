This is a feature addition to `git gc` that mirrors existing `git repack` functionality for cruft pack management. The patch adds `--expire-to=<dir>` support to `git gc`, allowing users to specify a directory for expired cruft packs during garbage collection, similar to the existing `git repack --expire-to` option (from commit 91badeb).

The implementation adds a `repack_expire_to` field to the `gc_config` structure and modifies `add_repack_all_option()` to handle the new parameter. The change includes documentation updates in `git-gc.txt` and test coverage in t6500-gc.sh. A key design aspect is that when both `--cruft` and `--expire-to` are specified, `git gc` automatically skips the `-a` flag to `repack` to avoid prematurely deleting unreachable objects.

Junio Hamano's review questions highlight several important considerations:
- Whether the documentation implies `--expire-to` only works with `--cruft` (it does, since cruft packs are required for this functionality)
- The phrasing of the documentation could be clearer ("for more" → "for more information")
- Whether test coverage should include the `--no-cruft` case (currently only tests with explicit `--cruft`)

The patch builds on prior review feedback from Jeff King and aligns with Taylor Blau's cruft pack work. The technical implementation appears sound, with proper handling of option combinations and preservation of existing behavior. The remaining questions from Junio are about documentation clarity and test coverage rather than fundamental design issues.
