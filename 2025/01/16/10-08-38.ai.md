Refactoring patch in the reftable type-cleanup series, focusing on block header/footer size functions. This is part 6 of 10 in Patrick Steinhardt's series to address compiler warnings and type correctness in the reftable codebase.

The patch changes the return type of `header_size()` and `footer_size()` from `int` to `size_t`, since these functions can only return positive values representing format-dependent sizes. This matches the pattern established in earlier patches of the series where signed return types are replaced with unsigned ones where negative values are impossible. The changes propagate through block.c, block.h, and a test file where the assertion is updated to use `check_uint()` instead of `check_int()`.

This continues the mechanical but thorough type cleanup needed for making reftable a standalone library, with each commit systematically addressing specific subsystems. The changes are straightforward and maintain consistency with the series' approach to eliminating sign comparison warnings while preserving the existing behavior. The test update demonstrates the type change doesn't affect the actual size calculations.
