Performance optimization patch enabling zlib-ng as an alternative zlib backend, part of a series that has already seen thorough review. This patch specifically adds build system support for linking against zlib-ng's non-compatibility mode (where symbols are prefixed with `zng_`), which is how most distributions package zlib-ng to avoid conflicts with system zlib.

The patch introduces a new `ZLIB_NG` build option for Makefile users and a `zlib_backend` meson option, allowing users to opt into zlib-ng's optimized implementations. Benchmarks show a ~25% speedup in object reading operations when using zlib-ng, with the example given being a `git cat-file --batch --batch-all-objects` run going from 52s to 40s.

The implementation handles the symbol renaming through a new `compat/zlib-compat.h` header that remaps standard zlib calls to their `zng_` prefixed equivalents when zlib-ng is enabled. The changes are cleanly contained to build system configuration and compatibility layers, maintaining the series' goal of being a transparent optimization that doesn't require changes to core Git code.

This is the 8th patch in a 10-part series that has already addressed all technical concerns in previous iterations, with Karthik Nayak having reviewed and acked the implementation. The performance gains are significant and the approach is now well-vetted, making this ready for inclusion.
