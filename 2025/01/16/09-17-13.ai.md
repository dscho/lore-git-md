Performance optimization series introducing zlib-ng support as an alternative zlib backend, now in its third iteration. This cover letter summarizes the changes and provides benchmark results showing ~25% speedup in object reading operations when using zlib-ng compared to standard zlib.

The series refactors Git's zlib integration to support both standard zlib and zlib-ng via a new "compat/zlib.h" header that handles the differences between the two implementations (primarily zlib-ng's `zng_`-prefixed symbols). While zlib-ng provides a compatibility layer, most distros don't install it globally to avoid system-wide impacts, making this direct integration necessary.

Changes in v3 are minor refinements: fixing commit message typos, clarifying the removal of redundant `CC=gcc` in Meson builds, and rebasing on current master. The series has already received thorough review from Karthik Nayak and all technical aspects appear resolved, including build system integration (Makefile and Meson), CI testing via a modified linux-musl job, and platform compatibility considerations.

Key technical components include:
- New "zlib-compat.h" header to abstract backend differences
- Build system support via `ZLIB_NG=1` (Make) or `zlib_backend=zlib-ng` (Meson)
- Removal of obsolete compatibility shims like `uncompress2()`
- CI coverage through an adapted linux-musl job that exercises zlib-ng
- Benchmark shows 25% speedup in `git cat-file --batch --batch-all-objects`
- All platform-specific build issues resolved (MinGW/Windows header handling)
- No remaining technical blockers - series appears ready for merging
