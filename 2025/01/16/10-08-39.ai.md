This is part 7 of a 10-part refactoring series addressing type safety in the reftable codebase. The patch focuses on the restart length type in block writing operations.

The change converts the restart length tracking from `int` to `uint32_t` in both the block writer implementation and writer statistics. The commit explains that while the value could technically fit in a smaller unsigned type (`uint16_t`), it maintains consistency with other parts of the code that already use 32-bit integers for restart counts. The patch removes redundant negative-value handling since the type now guarantees non-negativity, and simplifies some conditional logic in `block_writer_register_restart()` by eliminating unnecessary braces.

Key technical details:
- Updates `restart_len` field in `block_writer` operations
- Modifies `restarts` counter in `reftable_block_stats` struct
- Removes redundant bounds enforcement since `MAX_RESTARTS` already caps the value
- Changes loop variable in `block_writer_finish()` to match the new type
- Maintains the same 3-byte storage format for restart offsets despite the type change

This continues the series' pattern of making type choices more precise while preserving existing behavior, with the changes being mechanical but carefully reasoned to maintain consistency across the reftable implementation.
