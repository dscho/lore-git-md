Performance optimization introducing zlib-ng support infrastructure. This is patch 3/10 in the third iteration of the series, focusing on the core abstraction layer needed to support zlib-ng as an alternative backend.

The patch introduces a new `compat/zlib-compat.h` header that serves as an indirection layer for zlib includes. This header will later be expanded to handle the differences between standard zlib and zlib-ng implementations. The change replaces direct `#include <zlib.h>` with `#include "compat/zlib-compat.h"` in three locations: `git-compat-util.h`, `reftable/block.c`, and the newly created header itself.

The commit explains the naming choice - using "zlib-compat.h" rather than "zlib.h" to avoid potential include path conflicts with the system zlib headers. This is a preparatory step for the actual zlib-ng integration that will follow in subsequent patches.

The patch is straightforward and mechanical, changing only include directives while maintaining identical functionality at this stage. It follows the series' established pattern of careful, incremental changes to the zlib infrastructure. The reftable subsystem is included in the changes since it directly uses zlib compression, showing the author's attention to cross-cutting concerns.

This change is part of the larger effort that has already demonstrated ~25% speed improvements in object reading operations when using zlib-ng. The series has undergone thorough review rounds with all technical concerns addressed, and this particular patch represents a non-controversial infrastructure piece that enables the more substantial changes to come.
