Refactoring patch in the `the_repository` removal effort. This is the first of five patches converting pack-writing code to avoid global hash algorithm access.

The patch modifies `fixup_pack_header_footer()` to take a `hash_algo` parameter instead of using the global `the_hash_algo`. This affects pack operations in fast-import, index-pack, pack-objects, and bulk-checkin. The change is mechanical - callers simply pass through `the_hash_algo` for now, pushing the global variable dependency up the call stack where it can be addressed later. The patch updates both the function implementation and its declaration in pack.h, along with all call sites.

Key technical details: The function now takes a `const struct git_hash_algo*` as its first parameter. All hash algorithm operations within the function (init, update, final) now use this parameter rather than the global. The patch maintains existing behavior while removing one layer of global variable usage. This follows the established pattern of the `the_repository` removal effort by making dependencies explicit at function boundaries.

The changes are straightforward and touch only pack-writing infrastructure. No behavior changes are introduced, and the patch appears to be a clean conversion with proper updates to all callers. This looks like a solid incremental step in the ongoing effort to eliminate global state from Git's codebase.
