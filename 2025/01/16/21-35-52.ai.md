This is part 5/6 of the series standardizing help text output to stdout across Git commands, focusing on "oddball" cases that don't follow the typical `-h` check pattern. The patch converts several commands that had unconventional help request handling to use the new `show_usage_if_asked()` helper.

The changes affect `git` subcommands including `credential`, `fetch-pack`, `unpack-file`, `upload-archive`, and `var`. These were special cases because they either: (1) combined the `-h` check with argument validation in a single conditional, (2) didn't treat `-h` specially at all (like `git var` which let it fall to error paths), or (3) had help checks after parameter parsing loop (like `fetch-pack`). The patch separates these concerns by first checking for `-h` requests via the new helper, then handling argument validation separately.

The implementation maintains all existing functionality while ensuring help text goes to stdout. Notable cases preserved include `git var`'s error paths and `fetch-pack`'s parameter parsing order. The changes are mechanical but careful, as seen in the test updates that verify both stdout output and exit code 129 behavior. This completes the conversion of all builtin commands to consistent help output behavior, with only non-builtin commands left as future work (as mentioned in the series cover letter).
