Refactoring patch in the reftable type-cleanup series. This is the sixth in a 10-part series addressing compiler warnings and type correctness in the reftable codebase.

The patch changes the return type of `header_size()` and `footer_size()` functions from `int` to `size_t`, since these functions can only return positive values representing block header/footer sizes in the reftable format. This matches the pattern seen in earlier patches of the series, converting signed types to unsigned where negative values are impossible.

The change propagates through three files - block.c, block.h, and a test file - with straightforward updates to function signatures and a corresponding switch from `check_int` to `check_uint` in the test assertions. Like the rest of the series, this appears to be a mechanical but careful change that improves type safety while maintaining existing behavior.

The patch continues the thread's theme of preparing reftable to become a standalone library by eliminating questionable type choices that trigger compiler warnings. It's a small but logical piece of the larger type-cleanup effort.
