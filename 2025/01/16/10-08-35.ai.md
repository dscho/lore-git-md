This is a refactoring patch in the reftable warning-cleanup series, addressing potential integer overflows in varint decoding and simplifying the encoding implementation.

The patch focuses on two varint handling functions in reftable/record.c. The key change is making `get_var_int()` properly detect integer overflows during varint decoding, which could previously return invalid results when processing malformed input. The new implementation is modeled after Git's existing `decode_varint()` which already handles this case correctly. The function now checks for buffer overruns and integer overflow conditions explicitly.

For consistency, the patch also rewrites `put_var_int()` to match Git's `encode_varint()` implementation, which is simpler, avoids -Wsign-compare warnings, and is already well-tested in the codebase. Both functions now return negative values on encoding/decoding failures, with updated documentation in record.h clarifying this behavior.

The changes include new unit tests verifying overflow detection, with `t_varint_overflow()` specifically testing that malformed varints triggering overflow conditions are properly rejected. The test uses a crafted buffer that would cause the old implementation to overflow a uint64_t.

This is part of the larger effort to clean up compiler warnings in preparation for making reftable a standalone library. The changes are mechanical but important for correctness, particularly the overflow detection which could prevent potential security issues from malformed input. The patch follows the series' pattern of aligning reftable code with Git's core implementations where appropriate.
