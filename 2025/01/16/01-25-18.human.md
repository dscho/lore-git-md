This is a refactoring patch that's part of a series standardizing help text output behavior across Git commands. It introduces a new helper function `show_usage_help_and_exit_if_asked()` to centralize the common pattern where commands check for "-h" and show help text. 

The key change is that this helper will eventually ensure help text goes to stdout rather than stderr when users explicitly ask for it with "-h", though this first patch just establishes the infrastructure while maintaining the existing stderr behavior. The patch notes that the current exit code 129 (indicating error) may need revisiting later since showing help when requested shouldn't be considered an error condition.

Junio Hamano implements Jeff King's suggestion to create this helper, which will be used to update ~40 command implementations in subsequent patches. The change is mechanical but important for consistency - it's part of a well-organized effort to clean up long-standing inconsistencies in how Git commands output help text. The patch includes thorough documentation of both the current behavior and potential future improvements.
