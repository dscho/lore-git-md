This is part of a refactoring series cleaning up compiler warnings and type correctness in the reftable codebase. The patch changes the return type of block reading functions from `int` to `ssize_t` to better match the POSIX `read()` convention where negative values indicate errors and positive values indicate bytes read.

The change affects several key functions in the reftable block I/O subsystem, including the core `block_source_read_block()` interface and its implementations. The patch also updates callers to properly handle the new return type, with special attention to `reader_get_block()` which now simplifies its return to just indicate success/failure rather than propagating the count.

This continues the series' pattern of making type choices more explicit and compiler-friendly while maintaining the existing behavior. The changes are mechanical but important for the long-term goal of making reftable a standalone library with clean interfaces. The patch follows the established style of the series, with thorough updates to both implementation and header files, plus adjustments to error handling paths.
