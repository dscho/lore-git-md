Bugfix investigation for Windows packfile handling. Brian M. Carlsen responds to Ginger Luo's report of 4GB clone failures on Windows, distinguishing it from a previously fixed large-blob issue. The response systematically explores potential causes: suggesting it's unlikely to be a fundamental packfile size limitation (given widespread large repository usage), considering whether a single >4GB blob might be involved (though noting compression should mitigate this), and raising the possibility of antivirus/proxy interference. Carlsen provides technical background on Windows' LLP64 integer model differing from Unix's LP64, explaining why `long` vs `size_t` issues persist in Windows porting. The email requests a reproducible test case (suggesting trying the Linux kernel repo) and asks about environmental factors that might corrupt transfers. The technical depth and methodical troubleshooting approach suggest this is a serious investigation of a potentially significant Windows-specific data transfer bug, with Carlsen involving the Git for Windows maintainer (Dscho) for further insight. The discussion highlights ongoing challenges in Windows portability due to fundamental ABI differences.
