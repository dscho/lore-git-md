**Cover letter for a consistency fix series addressing help text output streams**

This is a 6-patch series from Junio C Hamano (with one test addition from Jeff King) that standardizes where Git commands send their "-h" help text. Currently there's an inconsistency - some builtins send help to stdout when "-h" is used (the parse-options API default), while others send it to stderr (via direct usage() calls or usage_with_options()). The series makes all builtins consistently send help text to stdout when explicitly requested with "-h", while keeping error case help on stderr.

The change was prompted by Jonas Konrad noticing that "git branch -h" unexpectedly sent output to stderr. The series introduces new helper functions (show_usage_help_and_exit_if_asked() and show_usage_and_exit_if_asked()) to handle this distinction cleanly, then updates numerous builtins to use them. The changes are mechanical but widespread, touching 41 files across various commands. Jeff King contributes a test to verify the stdout behavior.

This appears to be a well-motivated cleanup of a long-standing inconsistency. The changes are straightforward and the series maintains the important distinction between requested help (-h) and error-case help. The scope is large but the individual changes are simple and consistent.
