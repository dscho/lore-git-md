This is a cover letter for a patch series standardizing help text output behavior across Git commands. The series converts `git cmd -h` output from stderr to stdout consistently for all built-in commands, addressing an inconsistency where parse-options API users got stdout behavior while manual usage() implementations used stderr.

The series introduces two key helper functions - `show_usage_if_asked()` in parse-options.c and `show_usage_with_options_if_asked()` in usage.c - to centralize stdout behavior while maintaining exit code 129 for compatibility. The implementation follows careful staging: first adding infrastructure (patches 1-3), then converting commands (patches 4-6). Patch 5/6 handles "oddball" usage() callers, while patch 6/6 converts remaining commands across 21 files.

Notable changes in v4 include renaming the helper functions (dropping redundant "and_exit"), reorganizing patches to group infrastructure first, and fixing fetch-pack.c to follow the same pattern as var.c where `-h` was previously treated as an unrecognized option. The series leaves exit code unification (changing from 129 to 0) as future work, focusing solely on stdout behavior standardization.

The implementation demonstrates thorough edge case handling, with reviewers identifying subtle organizational improvements like moving the help check before parameter parsing in fetch-pack.c. Test coverage in t0012-help.sh verifies the new behavior. The series now appears complete with all built-in commands converted and all reviewer feedback addressed, making it ready for final consideration.
