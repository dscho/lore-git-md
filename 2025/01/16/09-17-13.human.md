Performance optimization series introducing zlib-ng support as an alternative zlib backend. This is the third version of a technically complete series that has already been reviewed and acked by Karthik Nayak, with all substantive technical discussions resolved.

The series refactors Git's zlib integration to support zlib-ng, a zlib fork with optimized implementations using modern CPU features like SSE2 and AVX2. Benchmarks show a ~25% speedup in object reading operations (52s → 40s in a `git cat-file --batch-all-objects` test). The changes create a compatibility layer that handles zlib-ng's `zng_`-prefixed symbols while maintaining support for standard zlib.

Key technical aspects:
- Introduces a new "compat/zlib.h" header to abstract differences between backends
- Adds build system support via `ZLIB_NG=1` (Make) and `zlib_backend=zlib-ng` (meson)
- Includes CI testing via an adapted linux-musl job
- Resolves platform-specific header inclusion challenges
- The v3 changes are minor: fixed commit message typos, clarified why `CC=gcc` can be dropped in Meson builds, and updated the base commit.

The series is now in final polish phase with no technical blockers, ready for merging. The performance gains make this particularly interesting for hosting providers and users who frequently access Git's object database.
