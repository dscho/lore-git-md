This thread addresses a series of patches standardizing how Git commands handle `-h` help requests, moving the output from stderr to stdout consistently across all built-in commands. The effort originated from Jonas Konrad's observation of inconsistent behavior between commands using the parse-options API (which sent help to stdout) versus those with manual usage() implementations (which used stderr).

The implementation introduced two key helper functions - `show_usage_if_asked()` and `show_usage_with_options_if_asked()` - to centralize the stdout behavior while maintaining backward compatibility. Jeff King (Peff) provided thorough reviews, questioning implementation details like function naming and the file descriptor-based approach, while confirming the solution correctly handles edge cases like error messages during formatting.

Junio Hamano has been closely involved in handling special cases, particularly in commands like `builtin/var.c` and `fetch-pack.c` where `-h` previously fell through to parameter error paths. The final patch adjusts `fetch-pack.c` to move the help check before the parameter parsing loop for cleaner code organization while preserving functionality - a refinement caught during final review.

The series follows a careful infrastructure-first approach, with foundational helpers introduced first, followed by systematic command conversions. All built-in commands now exhibit uniform stdout behavior for help requests, with errors remaining on stderr. While the exit code (129 for help requests) could be standardized to 0 in a future series, the core goal of output consistency has been achieved through this comprehensive effort. The boundary between converted built-ins and remaining non-builtin commands (explicitly left for future work) makes any remaining inconsistencies clear and addressable.
