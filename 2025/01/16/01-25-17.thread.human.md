This thread has successfully completed the standardization effort to make `git cmd -h` output consistently go to stdout rather than stderr. The work originated from Jonas Konrad's observation of inconsistent behavior between commands using the parse-options API (stdout) versus manual usage() implementations (stderr). 

The implementation introduced core helper functions (`show_usage_if_asked()`, `show_usage_with_options_if_asked()`, and `usage_with_options_internal()`) to centralize the stdout behavior while preserving the expected exit code 129. After technical discussion between Jeff King (peff) and Junio Hamano, the final version adopted Jeff's suggestion to use `vfreportf()` (taking a FILE* parameter) for better flush control rather than the earlier vfdreportf() approach.

The series went through several phases: establishing the core plumbing helpers, converting standard builtins, handling special-case commands, and finally applying mechanical replacements across the remaining files. The test infrastructure was updated to strictly verify stdout-only output, removing the transitional `GIT_TEST_HELP_MUST_BE_STDOUT` flag.
