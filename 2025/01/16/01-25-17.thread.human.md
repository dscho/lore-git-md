This thread has been working to standardize how Git commands handle `-`h` help output, moving it from stderr to stdout for consistency. The effort started with Jonas Konrad noticing that commands using the parse-options API (stdout) behaved differently from those with manual `usage()` implementations (stderr). 

The series took a careful, infrastructure-first approach - first introducing helper functions `show_usage_if_asked()` and `show_usage_with_options_if_asked()` to centralize the behavior, then systematically converting commands. Jeff King (Peff) provided thorough review, particularly around naming and implementation details. The naming was simplified from earlier verbose versions, and the team preserved the fd-based approach for explicit flush control. 

The final patch completes the conversion of all builtin commands, with special attention to edge cases like `builtin/fetch-pack.c` where Junio suggested moving the help check outside a parameter loop for cleaner code. While the core work is now done - all commands consistently use stdout for help - the thread notes potential follow-ups like changing the help exit code from 129 to 0, which would be handled separately. The implementation includes comprehensive test coverage in t0012-help.sh to verify the new behavior.
