This thread focuses on standardizing how Git commands handle `-h` help requests, moving the output from stderr to stdout while maintaining backward compatibility. The effort originated from Jonas Konrad's observation of inconsistent behavior between commands. The series introduces new helper functions in parse-options.c to centralize this behavior - `show_usage_if_asked()` and `show_usage_with_options_if_asked()` - which handle the common pattern of checking for `-h` and displaying usage text.

Jeff King (Peff) has been actively reviewing the implementation, providing feedback on naming (resulting in the current concise yet clear function names) and implementation details. The series carefully maintains the existing exit code 129 for now, though there's agreement this could be changed to 0 in a future refinement since help requests are successful operations. The implementation uses `vfdreportf()` for explicit control over output destination, ensuring help text goes to stdout while error messages remain on stderr.

The conversion is being done incrementally, with infrastructure changes first (patches 1-3) followed by command conversions (patches 4-6). The test infrastructure in t0012-help.sh verifies both output location and exit code behavior, supporting both permissive (current) and strict (future) modes. The series is now complete with all built-in commands converted and all reviewer feedback addressed, making it ready for final consideration. Exit code unification remains as a documented follow-up task that wouldn't affect the core standardization achievement.
