This thread addresses the standardization of help text output behavior across Git commands, ensuring `git cmd -h` consistently uses stdout rather than stderr. The effort originated from Jonas Konrad's observation of inconsistencies between parse-options API (stdout) and manual `usage()` implementations (stderr). The series introduces centralized helpers—`show_usage_help_and_exit_if_asked()` and `show_usage_and_exit_if_asked()`—to enforce this while preserving exit code 129 for compatibility.

Jeff King (Peff) has been closely reviewing the implementation, initially raising concerns about naming and the file descriptor-based approach. His latest feedback confirms the patch correctly handles edge cases, such as error messages still going to stderr when formatting fails. The series follows a structured approach: infrastructure changes first (patches 1-2), followed by command conversions (patches 3-6), including handling "oddball" cases like `builtin/var.c`.

In the most recent exchange, Junio Hamano and Peff refined the API names, settling on shorter alternatives like `show_usage_if_asked()` and `show_usage_with_options_if_asked()`. They also discussed the low-level implementation of `vfdreportf()`, with Peff suggesting a `FILE*`-based approach for cleaner code, though Junio noted the current fd-based method provides clearer control over flushing behavior for stderr cases.

The series is now in its final polishing phase, with consensus on the core approach and only minor naming and implementation details remaining. Peff has also floated the idea of changing the help request exit code from 129 to 0, though this would require additional handling for non-builtin commands. The systematic, test-backed approach has effectively resolved this long-standing inconsistency, ensuring uniform behavior across all Git commands.
