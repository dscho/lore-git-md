This thread standardizes how Git commands output help text, moving from inconsistent behavior (some commands using stderr, others stdout) to consistently using stdout for `git cmd -h` output. The effort originated with Jonas Konrad's observation of this discrepancy between parse-options API and manual usage() implementations.

The technical solution introduces three helper functions to centralize stdout behavior while maintaining backward compatibility, including the traditional exit code 129. After discussion between Jeff King (Peff) and Junio Hamano, the implementation settled on using `vfreportf()` with explicit flushing, replacing an earlier approach. The series converts 14 builtin commands and handles special cases in subcommands like credential and fetch-pack.

A new test infrastructure patch adds strict verification via `GIT_TEST_HELP_MUST_BE_STDOUT`, which checks both that help text appears on stdout and that stderr remains empty. This transitional approach allows gradual conversion while identifying remaining stderr outputs. Both Jeff King and Junio have signed off on the final version, confirming it meets the series' goals. While changing the exit code from 129 to 0 was discussed as a future possibility, it's deliberately excluded from this already-complete effort. The thread is now resolved and ready for integration.
