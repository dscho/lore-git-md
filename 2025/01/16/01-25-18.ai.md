This is a refactoring patch that's part of a series standardizing help text output behavior across Git commands. It introduces a new helper function `show_usage_help_and_exit_if_asked()` in the parse-options API to centralize the common pattern where commands check for "-h" and show usage help. The key change is that this helper will eventually ensure help text goes to stdout rather than stderr when explicitly requested with "-h", though this first patch maintains the existing exit code 129) behavior for compatibility.

The patch adds the new function to both parse-options.c and parse-options.h, implementing it as a wrapper around the internal `usage_with_options_internal()` function. The commit message notes this is the first step in converting approximately 40 call sites that currently use `usage_with_options()` directly. The exit code behavior is preserved for now to match test expectations in t0012-help.sh, though the message suggests this may be revisited later since a successful help request shouldn't need a non-zero exit code.

This is a mechanical but important plumbing change that will affect many builtin commands. The implementation looks straightforward and maintains backward compatibility while setting up for the behavioral change in subsequent patches. The commit message clearly explains both the immediate change and the longer-term direction, with proper attribution to Jeff King for the original idea.
