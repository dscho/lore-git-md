Test infrastructure enhancement for help output standardization.

This patch modifies t0012-help.sh to optionally enforce stricter checking of where help output (`-h`) goes, as part of the ongoing effort to standardize help text output behavior across Git commands. Currently, the test is permissive and accepts help output on either stdout or stderr, but the eventual goal is to require stdout for all commands (matching parse-options.c behavior).

The change introduces a new environment variable `GIT_TEST_HELP_MUST_BE_STDOUT` that, when set, makes the test verify that help output appears only on stdout. This allows for a transition period where commands can be incrementally converted while still catching regressions. The test continues to check for the expected exit code 129) and verifies the usage message appears in the correct output location based on the strictness setting.

The patch is part of a larger series (1/6) that standardizes help output behavior, with this first step focusing on test infrastructure to support the conversion work. It maintains backward compatibility during the transition while providing a clear path to eventual strict enforcement. The implementation handles both the permissive and strict modes cleanly, with clear conditional logic in the test script.
