This is part of a refactoring series cleaning up type safety in the reftable codebase. Patch 7/10 focuses on the restart length variable used in block writing, changing it from `int` to `uint32_t` since the value can never be negative and is bounded by `MAX_RESTARTS`. The change brings consistency with other parts of the code that already use 32-bit integers for restart counts.

The patch makes straightforward mechanical changes to the block writer implementation and updates the corresponding struct field in the writer header. While the commit notes that `uint16_t` would technically suffice for the value range, the choice of `uint32_t` maintains uniformity with existing code. This continues the series' pattern of tightening type safety while preserving the existing tests and behavior.

The changes are clean and focused, with clear justification in the commit message. As with previous patches in this series, this appears to be a well-considered step toward making the reftable implementation more robust as it moves toward becoming a standalone library.
