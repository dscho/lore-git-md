Bugfix follow-up in the packed-refs validation series. Patrick Steinhardt responds to patch 5/10, which aims to detect NULL (NUL) characters in packed refnames. The original patch adds a check that would die if a refname contains embedded NULs, since the current parsing approach could miss them when calculating lengths via pointer arithmetic.

Steinhardt suggests a more efficient implementation using `memchr()` rather than comparing string length to buffer length. He also notes some surprise that this validation is being added to the packed-refs reading code rather than the fsck infrastructure, but agrees the check itself makes sense.

This continues the thread's theme of hardening packed-refs validation, though it takes a different approach from earlier patches by focusing on refname content rather than file format headers. The discussion shows careful attention to both correctness and performance in the validation code.
