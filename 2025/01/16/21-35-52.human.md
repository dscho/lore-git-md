This is part 5 of a 6-part series standardizing help text output to stdout across Git commands. The patch focuses on "oddball" cases where commands had unconventional `-h` handling - either clever-but-unnecessary conditionals (like `credential` and `unpack-file`) or commands that previously didn't treat `-h` specially at all (like `var`).

The changes introduce `show_usage_if_asked()` calls before the existing error handling, ensuring help text goes to stdout while maintaining the original error behavior. Notable cases include `fetch-pack.c` where the help check is moved before parameter parsing, and `var.c` which now properly recognizes `-h` as a help request rather than an error.

The implementation is mechanical but careful - the commit message explains the different patterns being unified and how each case is handled. This continues the series' thorough approach to standardizing help output while preserving edge case behaviors. With this patch, nearly all builtins now consistently send help text to stdout when explicitly requested with `-h`.
