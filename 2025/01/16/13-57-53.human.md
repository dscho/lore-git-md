Bugfix review in packed-refs validation series (9/10). Patrick Steinhardt responds to a patch that adds sorting validation for packed-refs entries, noting this addresses a known class of bugs that can silently produce incorrect results. The patch introduces a new `packed_fsck_ref_sorted()` function that compares adjacent refnames in the packed-refs file using the existing `cmp_packed_refname()` helper.

Patrick's brief but substantive review endorses the change as sensible, recalling past issues caused by unsorted packed-refs files. This comes as part of an ongoing series (now at v1) that's receiving thorough technical review, particularly around validation architecture and performance considerations. The patch appears uncontroversial and well-aligned with the series' goal of hardening packed-refs validation.
