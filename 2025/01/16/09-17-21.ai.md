Performance optimization introducing zlib-ng support as an alternative zlib backend (patch 8/10 in v3 series). This patch enables direct linking against zlib-ng's optimized implementation when configured via `ZLIB_NG=1` (Makefile) or `zlib_backend=zlib-ng` (meson), while maintaining compatibility with standard zlib.

The implementation handles zlib-ng's `zng_`-prefixed symbols through macro redefinitions in compat/zlib-compat.h, allowing both libraries to coexist on systems where zlib-ng is installed without its compatibility layer. Benchmark results show a ~25% speedup in object reading operations (52.085s → 40.324s in `git cat-file --batch --batch-all-objects` tests).

Build system changes include:
- Makefile support via ZLIB_NG flag
- Meson integration with new zlib_backend option (auto/zlib/zlib-ng)
- Header adjustments to map standard zlib calls to zng_ prefixed equivalents
- Maintained fallback to standard zlib when zlib-ng is not available

The patch builds on previous infrastructure work (compat/zlib-compat.h in patch 3/10) and addresses the key technical challenge of symbol naming differences between the libraries. Performance gains are significant while maintaining backward compatibility, with all platform-specific considerations (including earlier MinGW/Windows issues) now resolved.
