This is a discussion about the behavior of help.autocorrect configuration, specifically how boolean values should be interpreted for command autocorrection.

David Aguilar responds to Junio's "What's Cooking" report about the `help.autocorrect` changes, which currently make "1" mean "immediate" autocorrection. David argues this is unsafe and proposes making "1" mean "prompt" instead (showing the correction but not running it), while keeping "0" as "never". His rationale is that immediate execution of potentially unintended commands is dangerous, and the current interpretation of "1" as immediate doesn't improve on the original behavior where it meant a 0.1 second delay.

The email suggests this would be a better user experience while not being concerned about backwards compatibility since it's making the behavior safer rather than more risky. David offers to prepare a patch implementing this change if others agree with the assessment. The discussion appears to be about fine-tuning the behavior of an already-accepted change rather than proposing something entirely new.
