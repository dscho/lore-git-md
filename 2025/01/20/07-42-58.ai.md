This is a build system patch introducing infrastructure for upcoming breaking changes in Git. It's the first of a 5-part series (v3) focused on deprecation handling.

The patch adds a new `WITH_BREAKING_CHANGES` compile-time flag that will control whether upcoming breaking changes are enabled. This implements the policy established in commit 2454970930 which requires breaking changes to be gated behind a build-time option. The change touches multiple build systems (Makefile, CMake, Meson) and adds the necessary plumbing to expose the flag through `GIT-BUILD-OPTIONS` and test infrastructure.

Key technical details:
- Adds `WITH_BREAKING_CHANGES` preprocessor macro
- Wires it into Makefile (via `BASIC_CFLAGS`), CMake (string replacement), and Meson (as a boolean build option)
- Adds a test prerequisite `WITHOUT_BREAKING_CHANGES`
- Does not yet activate any actual breaking changes - this is just the infrastructure
- Follows up on two prior commits (57ec9254eb and 2454970930) that established the breaking changes policy

The patch appears well-scoped and mechanically sound, implementing the agreed-upon policy for handling breaking changes. It touches multiple build systems consistently and includes test infrastructure, suggesting thorough consideration of the change's impact.
