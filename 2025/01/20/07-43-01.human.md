This is the fourth patch in a 5-part series implementing breaking changes for Git 3.0, specifically removing the deprecated `git-pack-redundant` subcommand. The patch follows through on a previously announced deprecation (from September 2024) by making the command unavailable when Git is built with the `WITH_BREAKING_CHANGES` flag.

The changes modify the build system (Makefile and git.c) to conditionally exclude the subcommand, and update the test suite to skip pack-redundant tests when built with breaking changes. This serves as a concrete example of how the project is handling breaking changes in the lead-up to Git 3.0.

The implementation appears straightforward and well-contained, with proper test coverage. As part of the broader deprecation effort discussed earlier in the thread, this change demonstrates the project's commitment to cleaning up legacy functionality while giving users clear migration paths (in this case, the deprecation was announced months in advance). The patch maintains consistency with the series' approach of using the `WITH_BREAKING_CHANGES` flag to gate breaking changes.
