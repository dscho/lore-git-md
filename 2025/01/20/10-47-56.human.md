This is a test portability fix addressing printf formatting in Git's blame test suite. The patch modifies t8002-blame.sh and t8003-blame-corner-cases.sh to replace non-portable `printf "%0.s"` sequences with equivalent `printf "%Ns"` syntax (where N is either 11 or hexsz) for padding spaces.

The issue stems from mksh's printf implementation (which comes from coreutils) not supporting the `%0.s` format specifier. Jan Palus explains that mksh doesn't have a built-in printf and instead uses the system's printf from coreutils, which rejects this particular format. The change maintains identical test expectations while improving portability.

The thread shows this is a straightforward improvement that has already received technical approval, with the only remaining work being commit message refinements to clarify whether this is a general portability concern or specific to mksh. Jan indicates they'll be posting a v2 shortly to address these final wording suggestions from Junio Hamano.
