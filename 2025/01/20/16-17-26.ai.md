This is a type-safety refactoring patch in the reftable codebase, part of a larger series to eliminate compiler warnings and improve type correctness. The change converts the `len` field in `struct reftable_block` from `int` to `size_t`, since block lengths are inherently non-negative values. This aligns with the series' broader goal of using appropriate unsigned types for size-related fields throughout the reftable implementation.

The patch is mechanical and straightforward, affecting only the block source header file. It follows the same pattern as previous changes in the series that updated other size-related fields (like `common_prefix_size()`, `hash_size()`, and restart length tracking) to use unsigned types. The modification maintains existing functionality while improving type safety and eliminating potential signed/unsigned comparison warnings.

This change is part of Patrick Steinhardt and Karthik Nayak's effort to make the reftable codebase more robust as it moves toward being a standalone library. The series has already addressed similar issues across multiple reftable components (basics.c, block.c, reader.c, etc.), with this patch completing the type safety conversion for block length tracking. No test updates are needed since the change is purely type-related with no behavioral impact.
