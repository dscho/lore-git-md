This is a documentation patch series that converts all AsciiDoc-formatted documentation files in Git from the `.txt` extension to `.adoc`. The change is motivated by the fact that most editors don't automatically recognize `.txt` files as AsciiDoc, which means contributors miss out on syntax highlighting and other editor features unless they manually configure their editors.

The series consists of 5 patches that:
1. Update `.gitignore` to recognize `.adoc` files
2. Add `.adoc` to `.editorconfig`
3. Mark AsciiDoc files as LF-only in `.gitattributes`
4. Perform the bulk rename of all documentation files (923 files total)
5. Clean up obsolete `.txt` extensions

The author notes that while they could have made the build system handle both extensions simultaneously, this would have created more diff noise. Instead, they opted for a clean switch, with most changes being simple renames (though some files required minor path adjustments). The commit message suggests using `git log -p --word-diff --word-diff-regex=.` for easier review of the large rename patch.

This is a mechanical but impactful change that will improve the contributor experience when working with Git's documentation. The patch appears well-structured and thoughtfully explained, with the author clearly considering reviewer experience in their approach. The change is low-risk since it doesn't modify content, only file extensions and build system references.
