This is a refactoring patch in the reftable type safety series, converting the return types of `header_size()` and `footer_size()` functions from `int` to `size_t`. 

The change is straightforward - these functions return positive integers representing header/footer sizes in the reftable format, so using `size_t` is more semantically correct than `int` since sizes cannot be negative. The patch updates the function declarations in block.h, their implementations in block.c, and one test case that checks the total size calculation. 

This continues the thread's broader effort to eliminate signed/unsigned comparison warnings and improve type safety throughout the reftable codebase. The changes are mechanical with no logic alterations, similar to previous patches in the series that updated other size-related functions. The test update shows this maintains compatibility with existing behavior while using more appropriate types.

The patch affects core reftable files (block.c/h) and their unit tests, completing another piece of the type safety work needed for making reftable a standalone library. It follows the same pattern as earlier patches in the series that updated return types for related functions like `common_prefix_size()` and `hash_size()`.
