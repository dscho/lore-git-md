Documentation modernization with concerns about backward compatibility.

Jean-Noël Avila raises important concerns about the AsciiDoc file extension conversion's impact on existing workflows, particularly for documentation consumers like git-scm.com and manpage translation projects. While acknowledging the benefits of standard `.adoc` extensions for editor support, they argue the change breaks backward compatibility for users who have already configured their environments to handle `.txt` files as AsciiDoc.

The email suggests two alternative approaches: (1) using directory-local editor configurations (demonstrated with an Emacs `.dir-locals.el` example) to achieve syntax highlighting without renaming files, or (2) implementing a transitional period with symlinks between `.txt` and `.adoc` versions. This represents the first substantive pushback in the thread against the mechanical conversion approach.

Key technical details mentioned include:
- Specific impact on git-scm.com website and manpage translation workflows
- Emacs configuration workaround using `adoc-mode` with `.txt` files
- Symlink-based transition strategy as potential compromise
- Implicit assumption that documentation writers can configure editors regardless of extension

This introduces a new dimension to the discussion around the purely mechanical changes proposed in the series, shifting focus to real-world impact on documentation maintainers. The concerns center on workflow disruption rather than technical implementation, suggesting the change's benefits might not outweigh its costs for certain user groups.
