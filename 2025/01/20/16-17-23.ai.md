This is a refactoring patch in the reftable type safety series, converting `hash_size()` to return `int` to `uint32_t` since hash sizes cannot be negative. The change propagates through the codebase, updating function signatures and removing now-redundant assertions that previously guarded against negative sizes. The patch affects core reftable files including basics.c, block.c, reader.c, and record.c, plus their headers and test code. This continues the thread's broader effort to eliminate signed/unsigned mismatches and strengthen type safety in the reftable code, with all changes being mechanical signature updates rather than logic alterations. The series has already been reviewed by Karthik Nayak, with this patch representing a straightforward completion of the hash size type cleanup.
