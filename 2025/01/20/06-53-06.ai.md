This is a discussion about the behavior of `help.autocorrect` configuration, specifically how boolean values should be interpreted. The thread follows up on Junio C Hamano's "What's Cooking" report which noted the pending change to make "1" mean immediate execution of corrected commands.

David Aguilar argues against interpreting "1" as "immediate", considering it potentially dangerous since it could accidentally run unintended commands. He proposes instead that "1" should map to "prompt" (requiring user confirmation) while "0" maps to "never". His rationale focuses on safety principle - making the most dangerous behavior ("immediate") require explicit configuration rather than being accessible through a simple "1" value. He acknowledges this differs from the current direction but argues backwards compatibility is less important when moving to safer defaults.

The discussion touches on several key configuration values and their proposed mappings:
- true/yes/on/1 → immediate (current proposal) vs prompt (David's suggestion)
- false/no/off/0 → never
- "immediate", "never", "prompt", and numeric delays retain their current meanings

David offers to prepare a patch implementing his suggested behavior if there's agreement. The core question is whether to prioritize strict boolean interpretation (where "1"=true maps to the most aggressive correction) versus safety-conscious interpretation (where "1" maps to the interactive "prompt" mode). This continues the thread's examination of how Git should handle potentially disruptive automatic behaviors.
