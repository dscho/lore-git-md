This is a feature patch proposing changes to the `help.autocorrect` configuration behavior. David Aguilar follows up on the ongoing thread about making the autocorrect feature safer by changing the boolean "true" value (1/yes/on/true) to mean "prompt for confirmation" rather than the current "immediate execution". The patch also clarifies documentation and ensures "0" and other false values consistently mean "never".

The changes include:
- Updating the config documentation to clearly show the new mapping of values to behaviors
- Modifying the parsing logic in `help.c` to implement the new behavior
- Adjusting tests to reflect the changes while maintaining backward compatibility with existing string values like "immediate"

The motivation is to prevent potentially dangerous automatic execution of commands when users might have intended just to see suggestions. The patch maintains all existing functionality while making the default boolean case safer. This appears to be a well-considered change with thorough test coverage, directly addressing concerns raised in the thread about command safety versus strict boolean interpretation.
