This thread begins a series of documentation housekeeping patches to transition Git's documentation from `.txt` to `.adoc` file extensions for AsciiDoc files. The first patch updates `.gitignore` files in Documentation directories to include the new `.adoc` extension, preventing accidental commits of build artifacts once the transition occurs. 

The change is motivated by better editor support - while `.txt` is technically correct for AsciiDoc files, most editors don't associate it with AsciiDoc syntax highlighting and tooling, whereas `.adoc` is widely recognized. The patch modifies `Documentation/.gitignore` and `Documentation/technical/.gitignore` to add matching ignore patterns for files like `howto-index`, `cmds-*`, `mergetools-*`, `SubmittingPatches`, and `api-index` that will have `.adoc` counterparts in upcoming patches. 

This appears to be a straightforward preparatory change before the actual file renaming occurs later in the series. The implementation is clean, adding parallel ignore rules for each existing `.txt` pattern that will need an `.adoc` equivalent.
