This thread is about a series of patches transitioning Git's documentation files to AsciiDoc format. The current patch (3/5 in the series) focuses on ensuring proper line endings for the new .adoc files in the Documentation/ directory. The change marks these files as LF-only in .gitattributes, mirroring the existing rule for .txt files.

The technical motivation is clear: generate-cmdlist.sh reads these files using shell builtins, and CRLF line endings would cause problems by treating the CR as part of the content rather than a line ending. This would lead to malformed C strings that fail compilation, particularly important for Windows compatibility where CRLF is the default line ending style.

The patch appears straightforward and technically sound, adding a single line to .gitattributes that parallels existing patterns. While this is part of a larger documentation format transition effort, this particular change is narrowly focused on preventing a specific build issue that would arise from the format change. The patch seems uncontroversial and well-justified for its specific purpose.
