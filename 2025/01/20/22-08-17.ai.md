This is a discussion about the ongoing documentation conversion from .txt to .adoc extensions, specifically addressing backward compatibility concerns raised by Jean-Noël Avila.

brian m. carlson responds to Avila's concerns about workflow disruption for documentation consumers like git-scm.com and manpage translation projects. While acknowledging the impact, carlson argues that such breaking changes are sometimes necessary and downstreams will need to adapt. The response focuses on technical limitations of editor-specific solutions - noting that while Emacs can handle directory-local configurations, Vim lacks a secure way to achieve similar functionality without project-specific hacks in user dotfiles.

The email explores Avila's symlink transition proposal but expresses reservations about implementation complexity (patch size concerns) and the temporary nature of such a solution. A key question emerges about whether Avila's opposition is to the change itself or just the timing - carlson probes whether a grace period would address the concerns or if the conversion is fundamentally objectionable. The exchange highlights the tension between modernizing tooling support and maintaining existing documentation workflows, with particular focus on editor compatibility and transition strategies.
