This is the fifth patch in a 6-part series adding OS version capability to Git's protocol, now focusing on the actual protocol advertisement and configuration. The patch implements the `os-version` capability controlled by a new `transfer.advertiseOSVersion` config option (defaulting to true), which exchanges sanitized OS names between clients and servers using the `uname(2)` system call's `sysname` field.

The discussion reveals several key points: Junio questions the fundamental value of OS version information compared to Git version data, noting servers might not even run Git. He also flags documentation imprecision around the 4 possible advertisement combinations (client/server true/false states) and raises architectural concerns about maintaining both raw and sanitized version strings when only sanitized may be needed.

Windows compatibility remains tricky - the patch acknowledges test complications from differences between Git's faked `uname(2)` and the `uname(1)` utility output, opting to disable Windows tests rather than build test infrastructure workaround. The thread shows the author responsive to feedback on documentation clarity and Windows handling, though core design questions about the feature's utility and string handling remain unresolved.

This patch moves the feature forward technically but occurs alongside ongoing debate about whether the capability should exist at all in its current form, with maintainers suggesting tighter integration with Git's version reporting or removal of the raw/sanitized string distinction. The Windows test exclusions appear pragmatic but may need revisiting if the design evolves.
