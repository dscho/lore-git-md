This is the second patch in a 2-part series adjusting Perl version requirements in Git's Meson build configuration. The patch fixes an issue with how Meson interprets Perl version strings when checking the minimum required version (5.26.0 established in patch 1/2). The author notes that while `perl --version` outputs version strings like "v5.26.0", Meson interprets this as simply "26", requiring the version check to be adjusted accordingly.

The patch includes a comment noting that a more robust solution using `version_argument: '-eprint "$^V"'` would be preferable but requires Meson 1.5.0, which is too new to require at this time. The change is minimal, affecting only the version string format in the `find_program()` call in meson.build while maintaining the same semantic version requirement.

Key technical details for future reference:
- The version check changes from `'>=5.26.0'` to `'>=26'` to match Meson's interpretation
- The underlying required Perl version remains 5.26.0 despite the syntax change
- The patch acknowledges but defers a more robust solution due to Meson version constraints
- Only the meson.build file is modified, with no changes to actual functionality or Perl version requirements
