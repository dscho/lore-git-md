Junio Hamano weighs in on the ongoing discussion about converting Git's documentation from `.txt` to `.adoc` extensions. As the Git maintainer, he acknowledges that the change would break his own private tooling for processing release notes, but frames this as an expected part of upstream evolution that documentation producers (as opposed to end users) should be prepared to handle.

Hamano suggests a practical compromise: keeping the change in the 'next' branch for an extended period (longer than the usual one week) to give documentation tooling maintainers time to adapt. He notes this requires those maintainers to actively monitor 'next' and make necessary adjustments, like making file extension handling more flexible in their scripts.

The email reinforces brian m. carlson's position that breaking changes are sometimes necessary for progress, while showing more sympathy for Jean-Noël Avila's concerns about disruption. Hamano explicitly rejects the symlink transition approach as adding unnecessary complexity, agreeing with carlson that it would just delay rather than avoid the eventual need for tooling updates.

This moves the discussion forward by proposing a concrete timeline adjustment as a middle path between immediate change and indefinite postponement, while maintaining the technical direction of the conversion. The maintainer's perspective carries significant weight in assessing what constitutes reasonable expectations for downstream tooling adaptation.
