This is the fourth patch in a 5-part series about deprecating legacy Git features, specifically removing the `git-pack-redundant` subcommand when built with breaking changes enabled. The patch implements the actual removal that was previously announced in BreakingChanges.txt, making the subcommand unavailable when compiled with the `WITH_BREAKING_CHANGES` flag.

The changes touch three key areas: the Makefile removes compilation of pack-redundant.c when the flag is set, git.c excludes the command from the commands table, and the test script skips pack-redundant tests in this configuration. The test modification uses a new `WITHOUT_BREAKING_CHANGES` prerequisite to skip tests when the subcommand isn't available.

This patch serves as a concrete example of how the breaking changes infrastructure (introduced earlier in the series) works in practice. It demonstrates the project's approach to removing deprecated functionality - first announcing the change, then implementing removal behind a build-time flag before eventual full removal. The changes are straightforward and follow the pattern established by previous breaking changes in Git.
