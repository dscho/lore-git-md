This is a cover letter for version 3 of a 5-patch series about deprecating legacy "branches/" and "remotes/" reference naming conventions, part of Git's broader effort to modernize reference namespace handling. The series introduces infrastructure for handling breaking changes and adds warning messages about these soon-to-be-removed features.

The key changes in this version include the addition of warning messages when reading from the deprecated "remotes/" and "branches/" directories, encouraging users to migrate to config-based remotes. The warnings include instructions for users who still depend on these features to notify the Git community. The series also establishes build system support for deprecated features via a new WITH_BREAKING_CHANGES flag and reorganizes CI jobs to test these deprecations.

The technical changes span multiple areas: build system modifications (Makefile, meson), CI configuration updates, documentation additions to BreakingChanges.txt, and the core warning implementation in remote.c. The series removes the pack-redundant subcommand as an example of handling breaking changes, though this appears to be a preparatory change rather than directly related to the remote deprecation work.

This version follows up on previous discussion about warning mechanisms, now implementing the actual warning messages that were previously discussed in abstract terms. The cover letter notes this is building toward removal in Git 3.0, though the thread context reveals ongoing debate about warning suppression mechanisms between Patrick Steinhardt and Junio Hamano. The implementation here appears to show warnings unconditionally without suppression options, suggesting Patrick may be deferring to Junio's preference for persistent warnings despite earlier proposals for configurable suppression.
