Bug analysis of `git diff --name-only --ignore-space-at-eol` behavior.

Shejialuo confirms Bob Ruiken's bug report about `--name-only` not properly respecting `--ignore-space-at-eol` filtering. They provide a clean reproduction recipe showing that files with only end-of-line whitespace changes still appear in the output when both flags are used. 

The analysis points to `diff.c::diff_flush` as the problematic area, where the `DIFF_FORMAT_NAME` bit causes early exit without applying whitespace filtering. Shejialuo notes the code appears to only compare tree metadata rather than file contents when `--name-only` is active, bypassing the whitespace checks entirely.

The email suggests two potential solutions: either better documentation clarifying this limitation, or making the flags mutually exclusive. Shejialuo acknowledges they're not deeply familiar with the diff code and doesn't propose a specific fix, but their technical analysis helps pinpoint where the logic diverges from expected behavior.

This appears to be a genuine inconsistency in Git's diff filtering behavior that could affect users relying on `--name-only` output while trying to ignore trivial whitespace changes. The analysis seems technically sound though stops short of proposing concrete changes.
