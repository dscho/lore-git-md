Bug report: `--ignore-space-at-eol` doesn't filter filenames when combined with `--name-only`

Bob Ruiken reports an unexpected interaction between two `git diff` flags. When using `--name-only` to show just filenames of changed files, the `--ignore-space-at-eol` flag fails to filter out files that only contain whitespace changes at line endings. The expected behavior would be for such files to be excluded from the output when both flags are used together.

The report is clear and provides straightforward reproduction steps: run `git diff --name-only --ignore-space-at-eol` between two branches where some files only have end-of-line whitespace changes. The current behavior shows these files in the output when they should be filtered out.

This appears to be a legitimate bug in how these two diff options interact. The report comes with system information showing the issue was observed on macOS with Git 2.39.5. As this is Bob's first bug report to the list, the tone is appropriately cautious while still clearly describing the problem. The issue seems well-isolated and should be straightforward for a Git maintainer to verify and address.
