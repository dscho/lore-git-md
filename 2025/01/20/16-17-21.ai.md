This is a refactoring patch in the reftable cleanup series, specifically addressing varint encoding/decoding safety. The patch fixes an integer overflow vulnerability in `get_var_int()` by adopting Git's battle-tested `decode_varint()` implementation, while also updating `put_var_int()` to match `encode_varint()`'s simpler and warning-free approach.

The key technical changes are:
- `get_var_int()` now properly detects overflows during varint decoding by checking for value wrapping and using proper bounds checking
- Both functions now handle the micro-optimization where the 0x80 bit indicates non-zero values (requiring +1/-1 adjustments)
- The implementations are aligned with Git's packfile varint encoding scheme as documented in reftable specs
- New unit test `t_varint_overflow()` verifies overflow detection
- Documentation comments clarify the return value semantics

This change is part of a larger effort to make reftable a standalone library by addressing type safety issues and compiler warnings. The patch demonstrates careful attention to edge cases while maintaining compatibility with existing varint formats. The implementation borrows from Git's proven code while adding necessary bounds checking for the reftable context.
