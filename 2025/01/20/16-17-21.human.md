This is a refactoring patch in a series cleaning up the reftable codebase. It focuses on improving varint (variable-length integer) handling in the reftable implementation.

The patch addresses an overflow vulnerability in `get_var_int()` where malformed input could cause an integer overflow. The new implementation is copied from Git's battle-tested `decode_varint()` while adding bounds checking against the string view length. The patch also simplifies `put_var_int()` by adopting Git's `encode_varint()` implementation, which avoids sign-compare warnings and is more straightforward.

The changes come with new unit tests that verify the overflow detection works correctly. This is part of a larger effort to make the reftable code more robust as it moves toward becoming a standalone library. The patch follows the reftable specification's note that its varint encoding should match Git's packfile encoding scheme.

The implementation appears careful and well-tested, with clear explanations of the optimization choices (like the `val += 1` micro-optimization). This is a solid technical improvement that closes a potential correctness issue while simplifying the code.
