Configuration change proposal for `help.autocorrect` behavior.

David Aguilar follows up on the ongoing discussion about `help.autocorrect` configuration with a concrete patch implementing his proposed safer behavior. The patch makes three key changes to the configuration interpretation:

1. Changes boolean "true" (1/yes/on) to mean "prompt for confirmation" rather than "execute immediately"
2. Makes boolean "false" (0/no/off/never) consistently mean "never show or execute suggestions"
3. Adds explicit "show" as a documented option that matches the current default behavior

The implementation touches documentation, core logic in help.c, and test updates. The help.c changes introduce a new `AUTOCORRECT_SHOW` constant and adjust the parsing logic to map values to the new behavior. Tests are updated to reflect the new semantics while maintaining coverage of all configuration variants.

This directly addresses the safety concerns raised in the thread about accidental command runs, though it represents a behavior change from the current implementation where "1" means immediate execution. The patch maintains backward compatibility for explicit string values ("immediate", numeric delays) while changing the interpretation of boolean values to prioritize safety over strict boolean interpretation.

The changes are self-contained and focused on the configuration parsing behavior, with thorough test coverage showing the new behavior works as intended. This appears ready for consideration as an alternative to the current direction, though it would need to be weighed against backward compatibility concerns for users relying on the current "1" behavior.
