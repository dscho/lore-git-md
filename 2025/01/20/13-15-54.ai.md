This is a bug report about unexpected interaction between `--name-only` and `--ignore-space-at-eol` flags in `git diff`. The reporter, Bob Ruiken, describes a case where combining these flags fails to filter out files that only contain whitespace changes at end-of-line, despite the `--ignore-space-at-eol` flag being specified.

The issue occurs when running `git diff --name-only --ignore-space-at-eol` - files that should be ignored due to only having EOL whitespace changes still appear in the output. The expected behavior would be for these files to be excluded from the name list, similar to how they would be excluded from a full diff output.

The bug appears in Git version 2.39.5 on macOS (arm64). The report includes detailed system information but doesn't specify whether this behavior differs from other Git versions or platforms. The reporter is new to submitting Git bugs but provides clear reproduction steps and a straightforward description of the discrepancy between expected and actual behavior.

This seems like a legitimate bug in the interaction between diff filtering and formatting options, where the name-only` output isn't properly respecting the whitespace ignore rules. The issue would primarily affect users trying to generate clean lists of meaningfully changed files while ignoring trivial whitespace differences.
