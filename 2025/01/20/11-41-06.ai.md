This is a test fix addressing an ambiguous printf specification in the blame test suite. The patch changes two test cases in t8002-blame.sh that were using the potentially ambiguous "%0.s" printf format to generate padding spaces. The new version uses the more explicit "%${N}s" format which is already used elsewhere in the test suite and is unambiguous across different printf implementations.

The issue stems from commit e7fb2ca945 which introduced these test cases. The original format could be interpreted differently by shells (as field width) versus coreutils (as 0-padding for numeric fields). The fix ensures consistent behavior by using the more standard format string that clearly specifies the field width.

The changes affect two test cases:
1. One testing blame's --abbrev -b option with a fixed width of 11 spaces
2. Another testing blame with excessive --abbrev using the full hexsz (object ID length) for padding

The patch is small (just 2 lines changed) and focused, with a clear explanation of the problem and solution. It's been reviewed by Patrick Steinhardt as indicated by the Helped-by tag. The fix aligns with existing test patterns seen in t5300 and t0450.
