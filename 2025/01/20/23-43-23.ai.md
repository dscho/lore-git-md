This is a documentation modernization discussion with input from the Git maintainer. Junio C Hamano weighs in on the ongoing debate about converting Git's documentation from `.txt` to `.adoc` extensions, acknowledging the disruption to downstream workflows but framing it as an inevitable evolution.

Hamano confirms the change would break his own tooling for processing RelNotes files, but argues that documentation producers (unlike end users) are expected to adapt to upstream changes. He suggests a longer-than-usual baking period in 'next' to allow affected parties time to adjust their tooling, proposing that maintainers could make their scripts more flexible by detecting the actual file extension rather than hardcoding ".txt".

The email reinforces brian m. carlson's position that breaking changes are sometimes necessary for progress, while showing more sympathy for transition concerns than carlson's initial response. Hamano explicitly rejects the symlink transition approach suggested by Jean-Noël Avila, agreeing with carlson that it would complicate the patch without solving the fundamental need for downstreams to eventually adapt.

Key technical points mentioned include:
- RelNotes files being affected despite not using full AsciiDoc processing
- Suggested adaptation pattern: checking for Documentation/git.adoc to determine the active extension
- The distinction between end-user compatibility promises and contributor-side adaptability expectations

This moves the discussion forward by providing the maintainer's perspective on balancing progress with ecosystem impact, while keeping open the question of whether Avila's concerns can be addressed through extended transition timing rather than technical compromises.
