This is a platform compatibility patch that's part of a series moving documentation to AsciiDoc format. The change marks AsciiDoc files (with .adoc extension) as LF-only in .gitattributes, preventing CRLF line endings that would cause compilation failures on Windows.

The patch explains that when generate-cmdlist.sh reads these files, CRLF line endings would cause the CR to be treated as part of the command synopsis text. This leads to invalid C strings that make the compiler fail. The issue specifically affects Windows systems where CRLF line endings are common.

The change is straightforward - adding a single line to .gitattributes to ensure consistent LF line endings for AsciiDoc files, matching the existing handling of .txt files in the Documentation directory. This appears to be a well-justified preparatory change for the larger AsciiDoc migration mentioned in the commit message.

The patch is part of a 5-part series (position 3/5), though the context about the broader migration goals isn't fully clear from this individual patch. The technical explanation is clear and the solution seems appropriate for the described problem.
