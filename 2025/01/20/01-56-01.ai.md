This is a platform compatibility patch that's part of a series transitioning documentation files to AsciiDoc format. The change marks AsciiDoc files (with .adoc extension) in Documentation/ as LF-only in .gitattributes, mirroring the existing rule for .txt files in that directory.

The technical motivation is that generate-cmdlist.sh reads these files using shell builtins, and CRLF line endings would cause problems - the CR would be treated as part of the content rather than line ending, leading to malformed C strings that fail compilation. This is particularly important for Windows compatibility where CRLF is the default line ending style.

The patch is straightforward and clearly motivated, adding a single line to .gitattributes that parallels existing patterns. It's part of a larger effort (3/5 in the series) to transition documentation to AsciiDoc format, though the specific motivation for that broader change isn't explained in this commit. The change appears technically sound and narrowly focused on preventing a specific build issue that would arise from the format transition.
