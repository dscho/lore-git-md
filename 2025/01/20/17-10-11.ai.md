Refactoring patch in the OS version capability series, addressing code review comments.

This is the first patch in Usman Akinyemi's v2 series to add OS version reporting to Git's protocol. It extracts string sanitization logic from `git_user_agent_sanitized()` into a new `redact_non_printables()` function for reuse in later patches that will handle OS version strings. The refactoring includes switching to `strbuf_detach()` for cleaner memory management.

Junio Hamano provides several review suggestions:
1. Clarifies the function's comment about ASCII character ranges
2. Questions the need for a TODO about consecutive dot replacement
3. Points out formatting issues in the comment block
4. Suggests using `isprint()` from <sane-ctype.h> (though Usman proposes handling this in a separate commit)
5. Confirms the caller should handle empty/dot-only string cases

The patch appears mechanically sound - it's a straightforward extraction of existing logic with minor improvements. The discussion focuses on code style and documentation rather than functional concerns. This refactoring is preparatory work for the more controversial OS version reporting feature that follows in later patches, where the fundamental design approach is now being questioned by core contributors.
