Bugfix analysis for `git diff` whitespace filtering behavior.

This email from Jialuo responds to Bob Ruiken's bug report about `git diff --name-only --ignore-space-at-eol` showing files that only contain end-of-line whitespace changes. The response confirms the bug is reproducible in Git's master branch and provides a minimal test case. 

The technical analysis points to `diff.c::diff_flush` as the problematic area, where the `DIFF_FORMAT_NAME` bit causes the function to exit early without applying whitespace filtering. The code path for name-only output appears to work at the tree comparison level rather than examining file contents, which explains why whitespace options are ignored. 

Jialuo suggests two potential solutions: either better documentation clarifying this limitation, or making the options mutually exclusive. The analysis stops short of proposing a code fix, noting unfamiliarity with the diff internals. The issue appears to be a genuine inconsistency in how diff filtering options interact, with the current behavior potentially surprising users who expect whitespace rules to apply uniformly across all diff output formats.
