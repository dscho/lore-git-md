Type safety improvement in the reftable codebase.

This patch is part of Patrick Steinhardt's ongoing series to clean up compiler warnings and improve type safety in the reftable implementation. It changes the `hash_size()` function to return `uint32_t` instead of `int`, since hash sizes are inherently non-negative values. The change propagates through the codebase, updating all related functions and call sites to use unsigned types consistently.

The patch removes several now-unnecessary assertions that previously guarded against negative hash sizes, since the type system now enforces this invariant. The changes affect core reftable operations including block writing/reading, record encoding/decoding, and equality comparisons. Test code is also updated to match.

This is a straightforward improvement that aligns with the series' goal of making the reftable code more type-safe and warning-free. The changes are mechanical but thorough, touching multiple files while maintaining the existing behavior. As part of a larger, well-reviewed effort to prepare reftable for standalone use, this patch appears uncontroversial and ready for inclusion.
