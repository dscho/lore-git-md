Christian Fredrik Johnsen proposed extending `git remote remove` to accept multiple remote names, similar to how `git branch -d` works, to make bulk operations more efficient. Initial pushback came from Emily Shaffer and D. Ben Knoble, who argued that power users could edit `.git/config` directly or use shell scripting as workarounds.

The discussion took a significant turn when Junio Hamano weighed in. As maintainer, he acknowledged the real inefficiency of sequential operations when dealing with many remotes (like 1000), noting that shell workarounds still require multiple Git invocations. More importantly, he highlighted technical limitations of the config-editing approach - it's error-prone for bulk operations and doesn't properly clean up remote-tracking branches. Hamano's comparison to `git branch --delete`'s behavior suggests he's open to the multiple-argument approach as a reasonable middle ground, though questions remain about error handling semantics and atomicity of the operation.

The thread now represents a nuanced debate about Git's interface philosophy - balancing power user needs against interface complexity, with the maintainer signaling that the current limitations may warrant addressing despite existing workarounds. The discussion remains focused on design principles rather than implementation details at this stage.
