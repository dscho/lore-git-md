This is a feature request proposing batch removal of remotes in Git. Christian Fredrik Johnsen suggests enhancing `git remote remove` to accept multiple remote names at once, similar to how `git branch -d` handles multiple branches. The proposal notes this would be particularly useful for cleaning up repositories with many remotes, aligning with existing batch operations in Git.

The request is clearly motivated by practical workflow needs, though the author acknowledges this might be a niche use case. They provide a concrete example of the desired syntax (`git remote remove myfork myrepo origin`) and note they couldn't find prior discussion of this feature in GitHub issues. An attached screenshot presumably illustrates a real-world scenario where this would be helpful.

The proposal is straightforward and well-presented, though it doesn't include implementation details or discuss potential edge cases (like handling non-existent remotes in the batch). The suggestion seems reasonable given Git's existing patterns for batch operations, but its utility would depend on how common the multi-remote cleanup scenario actually is in practice.
