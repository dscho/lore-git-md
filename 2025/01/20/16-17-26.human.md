This is a type-safety refactoring patch in the reftable codebase, part of a larger series to eliminate compiler warnings and improve type correctness. The change converts the `len` field in `struct reftable_block` from `int` to `size_t`, since block lengths can never be negative. This is a mechanical change that maintains consistency with other size-related fields in the reftable code that were already updated in earlier patches.

The patch is straightforward - a one-line change to a header file with no functional impact. It's part of Patrick Steinhardt and Karthik Nayak's ongoing effort to make the reftable backend more robust as they work toward making it a standalone library. The series as a whole has already been thoroughly reviewed, with this being one of the final cleanups.

This is the 8th of 10 patches in v2 of the series, which has already addressed more complex type safety issues like varint handling and other size-related fields. The change here is simple enough that it doesn't require test updates or deeper analysis - it's just completing the type consistency work for one remaining field.
