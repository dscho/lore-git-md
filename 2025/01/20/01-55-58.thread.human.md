This thread discusses a proposed conversion of Git's documentation from `.txt` to `.adoc` file extensions to improve editor support and forge rendering. The 5-patch series handles the mechanical changes across build systems, scripts, and documentation files while maintaining identical output. Initial responses from M Hickford were positive, highlighting benefits for new contributors.

Jean-Noël Avila, the documentation modernization lead, has now raised concerns about backward compatibility, particularly for git-scm.com and translation workflows. While acknowledging the technical merits, he suggests alternatives like editor configuration files or a transitional symlink approach to avoid breaking existing setups. This introduces new considerations about the real-world impact on documentation maintainers.

A brief off-topic discussion emerged between D. Ben Knoble and brian m. carlson about diff viewing preferences, though this doesn't affect the main proposal. The core question now is whether to proceed with the clean break (as originally proposed) or adopt a more gradual transition to accommodate existing workflows. The thread awaits further discussion on how to balance modernization with compatibility concerns.
