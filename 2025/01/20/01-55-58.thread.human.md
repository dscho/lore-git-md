This thread discusses the proposal to convert Git's documentation from `.txt` to `.adoc` file extensions, a change that would affect nearly 1,000 files across the Documentation/ directory. The series from M Hickford aims to improve editor support for contributors but has raised concerns about downstream impacts.

Jean-Noël Avila, Git's documentation maintainer, highlighted real-world disruption risks to the git-scm.com website, translation workflows, and existing editor configurations. brian m. carlson countered that some breaking changes are necessary for progress, noting technical limitations of editor-specific solutions. Now, maintainer Junio C Hamano has weighed in, acknowledging the disruption but framing it as an inevitable evolution. While confirming the change would break his own RelNotes processing tools, he argues documentation producers should adapt to upstream changes, suggesting an extended period in the 'next' branch to ease the transition.

The discussion now centers on balancing modernization benefits against ecosystem impact. Hamano rejects transitional measures like symlinks, agreeing with carlson that downstream tools should eventually adapt. However, he shows more sympathy for transition concerns than carlson's initial response, proposing practical detection patterns for the new extension. The key open question remains whether Avila's objections can be addressed through timing adjustments or represent fundamental opposition to the change.
