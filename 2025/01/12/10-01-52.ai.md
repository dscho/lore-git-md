This is a refactoring patch that fixes memory leaks and inconsistent behavior in the ref-filter code when handling ahead-behind and is-base calculations. The core issue stems from how committish references were being stored in separate string lists for formatting versus sorting operations, leading to leaks when sorting was done first and incorrect results when formatting was done first.

The key changes are:
1. Makes the `bases` and `is_base_tips` string lists static variables shared between formatting and sorting operations, rather than per-`ref_format` instance
2. Removes now-unnecessary `ref_format_init()` and `ref_format_clear()` functions since the format struct no longer owns allocated memory
3. Updates all callers to stop calling the removed functions
4. Adds new tests verifying the fixed behavior works correctly with sorting operations

The patch affects several commands (`branch`, `for-each-ref`, `tag`, `verify-tag`) that use ref-filter functionality, though the behavioral changes are most visible in sorting operations that use ahead-behind or is-base calculations. The test additions specifically verify the sorting functionality now works as expected with these atom types.

The change is a clear improvement over the previous state where memory was leaked and behavior depended on operation ordering, though it does make the ref-filter code slightly more stateful by introducing static variables. The commit message and tests do a good job explaining and verifying the changes.
