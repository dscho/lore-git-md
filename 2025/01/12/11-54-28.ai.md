This is a documentation patch that reverts a previous change that moved `git-cherry` from porcelain to plumbing classification. The patch argues that `git-cherry` should remain classified as a porcelain command (specifically under "ancillary interrogators") because it serves a high-level workflow purpose - checking which commits have or haven't been applied to another branch - despite being used less frequently than other commands. The author contends that while `git-cherry`'s output is stable (a plumbing characteristic), its primary value is as a user-facing tool rather than a building block for scripts. The patch also fixes a regression in Bash completion that occurred when the command was moved to plumbing, restoring the completion functionality. The change affects two files: `command-list.txt` (changing the command classification) and `git-completion.bash` (restoring completion support). The discussion appears to center around whether command frequency of use should determine its porcelain/plumbing status, with the author arguing that even rarely-used commands can rightfully belong in porcelain if they serve user-facing workflows.
