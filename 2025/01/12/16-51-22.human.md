Bugfix for HEAD handling in bare repositories with mixed mirror/non-mirror remotes. This patch addresses a regression introduced in Git 2.48.0 where fetching from non-mirror remotes in bare repositories could incorrectly overwrite HEAD, causing it to point to non-existent references. The issue was particularly problematic in multi-remote setups where one remote is a mirror and others are regular remotes.

The fix modifies the `set_head` function in `builtin/fetch.c` to distinguish between mirror and non-mirror remotes in bare repositories. Now it will only overwrite HEAD when fetching from a true mirror remote, while properly setting remote-specific HEAD symrefs (like `refs/remotes/<remote>/HEAD`) for non-mirror remotes. This preserves the expected behavior where HEAD in bare repos remains stable when interacting with non-mirror remotes.

The patch includes two new test cases that verify the correct behavior: one ensuring non-mirror fetches don't interfere with mirror operations, and another specifically testing HEAD handling in bare repositories with regular remotes. The changes are relatively focused, touching only the fetch logic and test files, with clear test coverage for the regression scenario. This appears to be a well-targeted fix for the identified issue.
