Bugfix for ref-filter's ahead-behind and is-base calculations. This patch addresses an issue where the committish references used in `%(ahead-behind:<committish>)` and `%(is-base:<committish>)` format specifiers were being handled inconsistently between formatting and sorting operations, leading to memory leaks and incorrect results.

The core problem stems from how these references were stored in separate string lists - one in the format parsing path and another in the sorting path. René Scharfe's solution makes these lists static and shared between both operations, eliminating the duplication and ensuring consistent behavior. The change also allows removing some now-unnecessary initialization and cleanup functions.

The fix is well-motivated by a real bug report and includes test cases demonstrating both the incorrect behavior and the corrected functionality. The implementation appears clean and focused, touching only the necessary parts of the ref-filter machinery while maintaining the existing API contracts.
