Bugfix proposal for mirrored bare repository HEAD handling regression in Git 2.48.0. This is a follow-up to Christian Hesse's report about `git describe` failing in mirrored bare repos after adding a second remote.

Bence Ferdinandy identifies the specific commit (b1b713f722) that changed the behavior: previously, HEAD remained pointing to the original branch (refs/heads/4.x) after adding a second remote, but now gets overwritten to point to a non-existent branch (refs/heads/mariadb-4.x). The issue appears when fetching from the second remote in a bare mirror repository.

The proposed fix would distinguish between mirror and non-mirror remotes in bare repositories - overwriting HEAD for true mirrors while setting up remote tracking (refs/remotes/remote/HEAD) for non-mirror cases. Bence notes the behavior might differ between bare and non-bare repositories with mirror remotes, and plans to submit a patch the following week.

This appears to be a well-analyzed regression affecting a specific but legitimate use case (multi-remote mirrored bare repositories). The proposed solution direction seems reasonable, though the actual patch will need careful review regarding edge cases around mirror/non-mirror remote configurations.
