This is a test infrastructure patch in the ongoing effort to standardize Git's help output behavior. Jeff King proposes an enhancement to `t0012-help.sh` that allows optional strict checking of help output destination during the transition period.

The patch adds a `GIT_TEST_HELP_MUST_BE_STDOUT` flag that, when set, enforces that `-h` output must go to stdout (the new standard) rather than being permissive about stderr output (the legacy behavior). This creates a tool for contributors working on conversions to identify remaining commands needing updates, without breaking regular test runs during the transition.

Key technical details:
- Modifies the builtin command test loop to conditionally check output destination
- Preserves backward compatibility by default (accepting either stdout or stderr)
- Prepares for eventual strict enforcement once all conversions are complete
- Maintains the 129 exit code check (for now) while focusing on output destination

The patch builds on Junio Hamano's v2 `show_usage_help_and_exit_if_asked()` helper and the existing test infrastructure, providing a practical tool for the community to complete the standardization work. It represents a transitional step in the broader effort to unify Git's help output behavior.
