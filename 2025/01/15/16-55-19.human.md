This is a technical follow-up in the ongoing discussion about Git command help output behavior. Kristoffer Haugsbakk provides a concrete script to audit which built-in Git commands currently output their help text to stderr rather than stdout when using the `-h` flag. The script lists 35 commands (including `git branch`, `git commit`, `git status` and others) that exhibit the inconsistent behavior under Git 2.48.0. This data directly responds to Junio Hamano's suggestion to systematically identify all affected commands, providing a clear starting point for any standardization effort.

The contribution is timely and practical, offering an automated way to verify the scope of the inconsistency that was previously discussed in abstract terms. The script handles edge cases (like the "EXPERIMENTAL!" marker in usage strings) and produces clean output showing just the command names. This will be valuable whether the project ultimately decides to standardize on stdout (as Junio suggested) or maintain the current stderr behavior for some commands. The email doesn't take a position on the debate but provides the technical groundwork needed to move forward with implementation.
