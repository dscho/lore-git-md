Documentation patch (part 4/5) in Jean-Noël Avila's series standardizing Git's man page format. This installment focuses on converting the commit-related configuration documentation to the new AsciiDoc style.

The patch updates Documentation/config/commit.txt with several mechanical but important changes: wrapping config variable names in backticks for monospace formatting, introducing a conditional variable (`see-git-commit`) to avoid self-referential links, and standardizing boolean value formatting (now `true` instead of just true). The changes maintain all existing technical content while making the presentation more consistent with the new documentation guidelines established in earlier patches.

Notably, the patch introduces a subtle but clever improvement by using AsciiDoc conditionals to handle the "see git-commit[1]" reference - it will either show the full link when viewed standalone or omit redundant self-references when included from the main git-commit man page. This follows through on the series' goal of making the documentation more modular and avoiding duplication.

The rest of the changes are straightforward conversions to the new style - passive to active voice, consistent formatting of option values, and maintaining all existing cross-references while presenting them more cleanly. As with previous patches in the series, these are purely presentational changes with no impact on Git's functionality.
