Matěj Cepl responds to Jonas Konrad's bug report about `git branch -h` writing to stderr by arguing this is actually correct UNIX behavior. Cepl asserts that help messages and diagnostics should go to stderr while only "substantial material" for processing should go to stdout, and suggests using `|&` to capture both streams. This directly contradicts the original reporter's expectation that help output should be consistent with `git -h` behavior (stdout) and usable in pipelines. The response doesn't address why Git's behavior differs between commands, nor does it engage with the core question of whether this inconsistency should be standardized. The reply takes a firm stance that the current behavior is correct by UNIX convention, though it doesn't reference any specific Git design principles or documentation to support this position.
