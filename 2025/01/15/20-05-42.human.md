This is part of the ongoing Rust bindings effort for Git's C library, specifically expanding the low-level `libgit-sys` FFI crate to support configuration access. The patch exports several `config_set` functions through the public symbol shim layer, enabling Rust code to read Git config values (both integers and strings) and manage config set lifetimes. 

The changes introduce new FFI wrappers for `git_configset_*` functions, following the established pattern of prefixing with "libgit_" for symbol visibility management. Notably, it adds heap allocation support via new `libgit_configset_alloc()` and `libgit_configset_free()` functions, allowing external consumers to treat config sets as opaque objects. The Rust bindings mirror these additions with appropriate type definitions and unsafe extern declarations.

As the third patch in a 5-part series, this builds on previous infrastructure work to make `libgit.a` more self-contained. The commit message indicates this is groundwork for a higher-level Rust config API coming in the next patch, so no standalone tests are included here. The changes are focused and well-contained within the `contrib/libgit-sys` directory, maintaining the project's careful approach to symbol visibility and FFI safety.
