This is a follow-up in the ongoing standardization of Git's output behavior for `-h` help messages. Kristoffer Haugsbakk adds a `Reported-by` trailer to Junio Hamano's patch implementing the new `show_usage_help()` helper function in parse-options.c, properly crediting Jonas Konrad as the original reporter of the inconsistent help output behavior.

The patch being referenced (from Junio) introduces a systematic solution to standardize help output to stdout rather than stderr when explicitly requested with `-h`, addressing the inconsistency where 40 builtin commands currently output help to stderr. The implementation includes safety checks for argc/argv and maintains the distinction between help output (exit code 0) and error cases (stderr, exit 129).

This email doesn't introduce new technical discussion but serves to ensure proper attribution in the commit history. The thread has already progressed through technical analysis, implementation design, and maintainer approval, with Junio's patch representing the finalized API approach that will be used to update the affected commands. The added trailer helps maintain the project's practice of tracking issue origins through commit metadata.
