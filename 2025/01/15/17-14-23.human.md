Bugfix proposal for Git's help output consistency, focusing on the `git branch` command. Jeff King (Peff) responds to Kristoffer Haugsbakk's audit of builtins that output help to stderr by proposing a concrete solution for one problematic case.

The email contains two key technical contributions:
1. A test case modification that would catch stderr output from help commands
2. A specific fix for `git branch -h` that reorders initialization code to avoid repository checks before handling the -h` flag

Peff identifies the root cause in `git branch` - early repository access that triggers a BUG() outside a repo, leading to the current stderr usage. His solution moves the `-h` handling after `parse_options()` while verifying this is safe since none of the early setup affects option parsing.

The email also suggests a more scalable solution - introducing a new `usage_with_options()` variant that writes to stdout by default, which could be applied across all 35 problematic commands identified in the audit. This would provide a consistent solution without requiring case-by-case analysis of each command's initialization sequence.

This moves the thread from problem identification toward concrete implementation, offering both an immediate fix for one command and a pattern for addressing the broader issue. The proposed changes align with Junio Hamano's earlier stated preference for stdout consistency.
