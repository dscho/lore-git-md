This is part of the ongoing Rust bindings effort, specifically expanding the `libgit-sys` FFI layer to expose Git's config API. The patch adds several config-related functions to the public symbol exports, enabling Rust code to allocate/free config sets and read config values (both integers and strings). 

The changes follow the established pattern of wrapping Git's internal functions with `libgit_`-prefixed names in the public interface. New additions include `libgit_configset_alloc()`/`free()` for heap management of config sets, plus `add_file()`, `get_int()`, and `get_string()` for basic config operations. The Rust FFI bindings mirror these additions with appropriate type mappings.

Notably, this patch doesn't include direct tests for the new FFI functions, as they'll be exercised through higher-level Rust APIs in subsequent commits. The implementation maintains the project's approach of treating config sets as opaque structs when crossing the FFI boundary, with proper memory management via the new alloc/free functions.

This continues the incremental expansion of `libgit-sys`'s capabilities, building on previous work that established the user agent API. The changes are contained to the `contrib/libgit-sys` directory and maintain compatibility with the project's symbol visibility strategy. The patch appears production-ready, with the temporary lack of direct FFI tests being a deliberate tradeoff given the planned higher-level testing.
