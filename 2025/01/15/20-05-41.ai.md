This is part of the Rust bindings feature series introducing FFI wrappers for Git's C library. The patch establishes the low-level `libgit-sys` crate that provides Rust bindings to `libgit.a`, starting with user agent string functions as an initial proof of concept.

The implementation handles symbol visibility carefully to avoid conflicts with other libraries like libgit2. It uses `public_symbol_export.[ch]` shims that prepend "libgit_" to exposed symbols and control visibility via pragmas. The build system creates `libgitpub.a` containing both the original `libgit.a` and these exported symbols, compiled with `-fvisibility=hidden` to hide non-exported symbols. The Rust integration includes tests verifying the user agent string functionality and requires Rust 1.63+.

Key technical details include:
- New Makefile rules for building the Rust artifacts (`partial_symbol_export.o`, `hidden_symbol_export.o`, `libgitpub.a`)
- Cargo configuration establishing `libgit-sys` as a Rust crate with `libz-sys` dependency
- Initial FFI bindings for `git_user_agent()` and `git_user_agent_sanitized()`
- Rust tests validating the user agent string format
- `.gitignore` updates for Rust build artifacts

The patch appears production-ready with thorough build integration and testing, though it's just the first step toward a complete Rust API. The careful symbol handling suggests attention to potential integration challenges with other Git library consumers.
