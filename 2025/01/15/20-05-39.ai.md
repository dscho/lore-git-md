This is a cover letter for a feature series introducing Rust bindings for Git's C library. The series provides two Rust crates: `libgit-sys` (low-level FFI bindings to `libgit.a`) and `libgit` (higher-level Rust-friendly API). The work has been tested with the JJ project as a proof-of-concept replacement for `libgit2-rs`.

Key technical details:
- The series splits `common-main.c` to isolate initialization/exit code
- `libgit-sys` handles symbol visibility/renaming via `public_symbol_export.c` shims
- The build system integrates with `make` through custom targets (`libgit-sys`, `libgit-rs`)
- Config handling functions are exposed via FFI
- Minimum Rust version is 1.63 with fallbacks for older type definitions

Notable changes in v6:
- Separated `libgit-sys` from nested structure to match Git project layout
- Standardized Makefile target naming (`-rs`/`-sys` suffixes)
- Prepared crates for eventual `crates.io` publication
- Rebased onto current master after several months' hiatus

The cover letter notes two outstanding issues (symbol visibility management and versioning) that may need follow-up work. The series appears production-ready for initial integration, with thorough test coverage and real-world validation via JJ. The changes are contained to `contrib/` and shouldn't impact core Git functionality.
