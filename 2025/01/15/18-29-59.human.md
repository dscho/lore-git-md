This is an implementation patch for the ongoing standardization of Git's `-h` help output behavior. Junio Hamano proposes a new helper function `show_usage_help()` in the parse-options API to systematically address the inconsistency where some commands output help to stderr while others use stdout.

The patch introduces a function that encapsulates both the `-h` flag check and the help output, making it harder for developers to incorrectly convert existing `usage_with_options()` calls. The helper will output to stdout (via `usage_with_options_internal`) when `-h` is detected, then exit with code 0. This matches the behavior Jeff King suggested earlier in the thread.

Junio notes this design prevents careless mass conversions, as each call site still needs individual inspection to ensure it's only handling user-requested help cases. The implementation follows the thread's consensus to standardize on stdout for help output while maintaining stderr for actual error messages.

This appears to be a well-considered solution to the 40+ builtin commands needing conversion, with careful attention to preventing regression during the transition. The patch builds on previous discussion and testing infrastructure (`t0012-help.sh`) established earlier in the thread.
