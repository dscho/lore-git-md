This is a refactoring patch that splits Git's common initialization code into separate files as part of the Rust bindings infrastructure work. The patch moves initialization logic from `common-main.c` into new `common-init.c` and `common-exit.c` files, making the code more modular and reusable by external consumers like the new Rust bindings.

The changes allow `libgit.a` to be more self-contained by providing standalone `init_git()` and `common_exit()` functions that can be called without requiring the full `main()` entry point. This builds on previous discussions about testability (where symbol conflicts were resolved differently) and now serves the Rust binding effort's need for clean library boundaries.

Key technical details:
- Splits `common-main.c` into three parts: `common-main.c` (minimal main wrapper), `common-init.c` (`init_git()`), and `common-exit.c` (exit handling)
- New `common-init.h` header exposes the initialization API
- Maintains identical behavior through the code movement
- Part of making Git's core functionality available as a library for Rust bindings
- Follows up on earlier proposals from 2021/2022 about testability

The maintainer (Junio Hamano) expresses approval of the approach while noting he didn't verify every line of the code motion. The change appears uncontroversial and well-aligned with the ongoing Rust binding work's architectural needs. This is patch 1/5 in a series that has already received positive maintainer feedback on its overall direction.
