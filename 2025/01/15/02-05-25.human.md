This is a follow-up in the security release thread regarding packaging constraints for NonStop environments. Randall Becker explains why they cannot package Git v2.47.2 despite Junio Hamano's clarification about the version metadata issue. 

The key issue is that NonStop's strict certification requirements demand builds to be directly traceable to unmodified Git repository commits - tarballs are unacceptable as they can't be verified by the community. Becker serves as a trusted build manager for this platform, and the community won't accept builds that can't be directly correlated to official Git commits. 

While the version reporting issue doesn't affect functionality (as previously clarified), the packaging constraints are more fundamental build requirements than just version number accuracy. Becker must therefore skip v2.47.2 and direct users to v2.48.1 instead, despite the inconvenience this causes. The email emphasizes these are non-negotiable constraints imposed by the NonStop community's certification process.
