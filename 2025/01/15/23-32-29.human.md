This is a test infrastructure patch in the ongoing effort to standardize Git's help output behavior. Jeff King (Peff) proposes adding a transitional flag `GIT_TEST_HELP_MUST_BE_STDOUT` to the test suite that will help identify commands still sending help output to stderr rather than stdout. The flag allows most test runs to remain permissive during the transition period while enabling contributors to easily find commands still needing conversion.

Junio Hamano approves the change, noting it's a practical approach to managing the transition. He raises an interesting side question about whether all 40 commands currently doing manual "-h" checks actually need to - suggesting some may be able to switch to the standard parse-options path instead. The patch itself modifies `t/t0012-help.sh` to check either output stream based on the flag's presence, with strict stdout-only checking when enabled.

This is a small but important piece of the larger standardization effort, providing tooling to track progress as commands are converted. Junio indicates the patch will be queued, showing maintainer approval for this incremental approach. The discussion hints at future work needed to audit which commands truly require special help handling versus those that can use the standard path.
