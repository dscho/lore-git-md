This is part of the performance optimization series introducing zlib-ng support as an alternative zlib backend. The patch focuses on infrastructure changes needed for runtime switching between standard zlib and zlib-ng.

The patch introduces a new "compat/zlib-compat.h" header that serves as an abstraction layer for zlib functionality, replacing direct includes of <zlib.h> in three key locations: git-compat-util.h, reftable/block.c, and the newly created header file itself. The header is deliberately named zlib-compat.h rather than zlib.h to avoid potential include path conflicts with the system zlib headers.

Karthik Nayak raises a question about whether adding "compat/" to the compiler's header search path could cause issues, though notes they couldn't find evidence of this being done in the Makefile. This appears to be a clarification rather than a substantive concern about the patch's approach.

The changes are straightforward mechanical replacements that maintain the foundation for subsequent patches to implement the zlib-ng backend switching. The reftable subsystem's independent zlib usage is properly handled through this new abstraction layer, maintaining the separation noted in earlier patches. This is part of the comprehensive header reorganization work that has been completed in the series.
