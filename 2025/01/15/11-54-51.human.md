Bugfix for reftable migration corruption in multi-batch scenarios. Karthik Nayak responds to Brian Carlson's report of "corrupt reftable file" errors during ref migration when processing repositories with many refs and reflog updates.

The issue occurs when multiple batches of ref updates are written, causing a mismatch between the max_update_index in the reftable header (stuck at 1) and the correct higher value in the trailer. Karthik confirms this stems from how reflog migration handles update indices differently than regular ref migrations, particularly when writes span multiple blocks.

The proposed fix introduces a max_index field in the ref transaction to track the highest update index across all operations. This value is then used to properly set max_update_index before the first block is written, preventing header/trailer mismatches. The patch includes a test that reproduces the issue by creating thousands of ref updates with multiple reflog entries.

Karthik's response is thorough - he confirms the reproduction case, clearly explains the root cause, and provides a well-structured fix with test coverage. The patch appears to directly address the reported issue while maintaining the intended reflog functionality.
