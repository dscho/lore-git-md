Feature: Rust bindings for Git's C library (part 2/5 of series)

This patch introduces `libgit-sys`, the low-level Rust FFI wrapper for Git's C library (`libgit.a`). It's the second in a 5-part series to enable Rust programs to use Git's core functionality directly rather than relying on `libgit2`. The implementation focuses on symbol visibility management to avoid conflicts with other libraries (notably `libgit2`) by using `public_symbol_export.[ch]` shims that prefix exposed symbols with "libgit_" and control visibility via compiler pragmas.

The initial version exposes Git's user agent string functions (`git_user_agent` and `git_user_agent_sanitized`) as a proof of concept, with tests verifying the strings start with "git/". The build system integration includes new Makefile rules and Rust/Cargo configuration, with all changes contained to the `contrib/` directory to avoid impacting core Git functionality. The approach appears well-considered, with clear attention to symbol isolation and build system integration.

This foundational work enables subsequent patches to build higher-level Rust abstractions while maintaining careful control over which Git internals become part of the public interface. The implementation has been tested with the JJ project as a real-world validation.
