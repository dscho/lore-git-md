Feature patch adding a new configuration option for command autocorrection behavior.

Chris Howlett proposes adding a "prompt-yes" option to `help.autocorrect` that works like the existing "prompt" mode but defaults to "Yes" when confirming whether to run a corrected command. Currently, the "prompt" mode defaults to "No", requiring explicit confirmation. The patch argues this new default would better match the typical case where Git's autocorrection is correct.

The change adds the new config value alongside documentation updates and implements the behavior in `help.c`, including proper handling for non-interactive terminals (falling back to immediate execution). The author notes this is their first Git contribution and acknowledges the lack due to testing difficulties with interactive prompts.

This appears to be a well-scoped, clearly motivated quality-of-life improvement. The implementation follows existing patterns and includes documentation. While test coverage would be ideal, the author's explanation for omitting tests seems reasonable given the interactive nature of the feature. The change seems unlikely to be controversial and could benefit users who frequently rely on command autocorrection.
