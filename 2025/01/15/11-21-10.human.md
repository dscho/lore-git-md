This is a bug report about unexpected behavior in `git branch`'s help output. Jonas Konrad reports that `git branch -h` sends its usage message to stderr rather than stdout, which breaks standard shell piping patterns (like `| grep`). The behavior differs from `git -h` which correctly uses stdout, and the command also exits with a non-zero status, suggesting this might be intentional but inconsistent.

The report is well-documented with clear reproduction steps, expected vs actual behavior, and system information. The issue appears to be a long-standing inconsistency in Git's command-line interface behavior rather than a recent regression. While not a critical bug, it affects shell scripting use cases and creates inconsistency between commands. The reporter suggests standardizing on stdout output for help text, which would align with common Unix conventions and other Git commands' behavior.

This seems like a straightforward quality-of-life improvement that could be addressed with a small patch to redirect the output stream. The report provides all necessary technical details for someone to propose a fix, though it may require some discussion about whether changing the behavior would break existing scripts that might rely on the current stderr output.
