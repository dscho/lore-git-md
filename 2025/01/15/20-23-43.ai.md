Documentation standardization series (v2) for git-commit. This is the second iteration of Jean-Noël Avila's effort to bring git-commit documentation into alignment with Git's new AsciiDoc formatting guidelines. The 5-patch series refines the git-commit man page and related files with purely presentational changes, splitting some improvements from v1 into separate commits for better reviewability.

Key changes in this revision include separating the original monolithic v1 patch into distinct commits for different aspects: core man page formatting (patch 1), optional parameter clarification for `-u` mode (patch 2), more direct option explanations (patch 3), config file conversion (patch 4), and supporting file updates (patch 5). The changes maintain the same scope as v1 - standardizing synopsis blocks, placeholder notation (_<file>_), backtick-wrapped commands/options, and cross-references - but now with clearer commit separation.

Notable technical adjustments from v1 feedback include reverting the `-u[<mode>]` bracket syntax in builtin/commit.c (kept as `-u<mode>`) since the test-related justification didn't hold, and maintaining original descriptive text in some option explanations rather than converting to imperative mood. The series continues using the `see-git-commit` variable to avoid self-referential links in config documentation.

The changes touch Documentation/git-commit.txt (281 lines), Documentation/config/commit.txt (25 lines), and supporting files i18n.txt and signoff-option.txt (12 lines total), plus a minor builtin/commit.c tweak. All modifications are mechanical formatting improvements with no functional impact, continuing the broader initiative to standardize Git's documentation presentation.
