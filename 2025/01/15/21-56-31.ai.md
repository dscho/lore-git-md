This is a patch implementing the parse-options API helper function to standardize Git command help output behavior, part of the ongoing effort to make `-h` output consistently go to stdout rather than stderr.

Junio Hamano presents v2 of the `show_usage_help_and_exit_if_asked()` helper function for the parse-options API, which encapsulates the common pattern of checking for `-h` and showing help. The implementation follows Jeff King's suggestion to properly check argc/argv before showing help, preventing blind string replacement conversions. The helper still exits with status 129 (matching current parse-options behavior) though the commit message notes this may change later.

The patch introduces the new function that will be used to convert approximately 40 builtin commands that currently send help to stderr. The implementation uses `usage_with_options_internal()` with parameters to force stdout output while maintaining the existing error-case behavior. The exit code behavior remains under discussion due to PARSE_OPT_HELP's dual use for both explicit help requests and ambiguous options.

This is the infrastructure patch that will precede the series of conversions for individual commands. The maintainer indicates the final patch in the series may modify the exit code behavior and test expectations once all conversions are complete. The implementation includes proper attribution to Jeff King for the technical suggestion while reserving Jonas Konrad's Reported-by credit for the eventual conversion patches.
