This is a follow-up in the security release thread regarding version metadata issues in Git v2.47.2. Junio Hamano responds to Randall Becker's concerns about NonStop platform certification requirements, clarifying the build process for users who must build from Git repository clones rather than tarballs.

Hamano explains that when building directly from a Git checkout (either the v2.47.2 tag or maint-2.47 branch), the GIT-VERSION-GEN script will correctly identify the version as "2.47.2" by using `git describe`, regardless of the outdated DEF_VER variable in the source. This addresses Becker's concern about version reporting accuracy for NonStop's certification process, where tarball builds are unacceptable due to security policies.

The email highlights a disconnect between Git's release engineering practices and the strict compliance requirements of enterprise environments like NonStop. While the security fixes are properly included in all release formats, this thread reveals how version metadata handling in security releases can create real-world deployment challenges for some platforms. Hamano seems genuinely puzzled why this remains an issue after his technical explanation, suggesting the conversation may continue as packaging requirements collide with Git's development practices.
