Bug report and implementation audit for Git help output behavior inconsistency, progressing toward standardization. The thread began with Jonas Konrad's report of divergent behaviors in Git 2.48.1: `git -h` (stdout, exit 0) vs `git branch -h` (stderr) vs `git reflog -h` (stdout, non-zero). After debate between Jonas (arguing for stdout consistency) and Matěj Cepl (defending stderr as UNIX convention), maintainer Junio Hamano sided with stdout standardization, suggesting an audit of current behavior.

Kristoffer Haugsbakk provided a comprehensive audit identifying 35 builtins (including high-use commands like `branch`, `commit`, and `status`) that output help to stderr. The audit methodically enumerated builtins and tested their -h behavior, revealing surprising cases like the `git diff` family and potential duplicates.

Jeff King (Peff) has now advanced the technical discussion by:
1. Proposing a test case (`t/t0012-help.sh`) to verify help output goes to stdout with empty stderr
2. Analyzing `git branch -h`'s stderr output, tracing it to commit 1dacfbcf13 which bypasses parse-options
3. Providing a concrete fix for `branch.c` that reorders initialization to safely use parse-options
4. Suggesting a systematic solution: introducing a stdout variant of `usage_with_options()`

Technical considerations now in play:
