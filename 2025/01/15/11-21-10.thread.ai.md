Thread summary:

Bug report regarding inconsistent help message behavior in `git branch -h`. Jonas Konrad observed that while `git -h` writes its usage message to stdout (allowing piping to tools like `grep`), `git branch -h` unexpectedly writes to stderr and exits with non-zero status. The reporter argues this behavior is inconsistent and unintuitive for a simple help request, suggesting stdout would be more appropriate while reserving stderr for actual errors. The issue was reproduced on Git 2.48.1 on Arch Linux with bash. No patch or proposed solution was provided - this is an initial report documenting the discrepancy. The core question raised is whether this behavior is intentional (and if so, why) or an oversight that should be corrected for consistency with other Git commands' help output behavior.
