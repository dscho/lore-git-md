Bug report and implementation audit for Git help output behavior inconsistency, now with maintainer-endorsed systematic solution and API design refinement, including exit code semantics finalization. The thread began with Jonas Konrad's report of divergent behaviors in Git 2.48.1: `git -h` (stdout, exit 0) vs `git branch -h` (stderr) vs `git reflog -h` (stdout, non-zero). After initial debate between Jonas (stdout consistency) and Matěj Cepl (stderr as UNIX convention), maintainer Junio Hamano sided with stdout standardization, prompting implementation analysis.

Kristoffer Haugsbakk's expanded audits provided definitive numbers: 40 builtins output help to stderr versus 102 using stdout, plus examination of auxiliary tools showing even more varied patterns. Core commands like `add`, `commit`, `fetch` use stdout while `branch`, `checkout`, `merge` use stderr. Non-builtin tools exhibit special cases: `git-http-backend` rejects `-h` with HTTP 500, `git-filter-branch` shows warning/delay behavior. Junio validated that `git-upload-pack` correctly maintains the stderr/stdout distinction between errors and help.

Jeff King (Peff) advanced technical discussion with test infrastructure (`t/t0012-help.sh`), code analysis tracing `git branch -h` stderr to commit 1dacfbcf13, and a concrete `branch.c` fix demonstrating safe parse_options() reordering. His systematic solution proposal - a stdout variant of `usage_with_options()` - has maintainer endorsement. Junio Hamano confirms this architectural approach as the preferred path, having independently concluded that modifying parse-options machinery is superior to patching individual commands.
