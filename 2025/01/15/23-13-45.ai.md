This is a build system patch in the ongoing Rust bindings effort, specifically addressing symbol visibility and linking concerns for the `libgit-sys` FFI layer. Junio Hamano provides maintainer feedback on the technical implementation details.

The patch introduces several Makefile changes to support building Rust-compatible versions of Git's symbols, including new targets for symbol export handling (`partial_symbol_export.o`, `hidden_symbol_export.o`, `libgitpub.a`). The implementation uses GNU binutils tools (`ld`, `objcopy`) for symbol manipulation, which Hamano notes may need platform-specific consideration for non-GNU toolchains.

Key technical aspects include:
- New public symbol shims (`libgit_user_agent()`) with GCC visibility attributes
- Makefile rules for symbol processing chain
- Clean targets for Rust build artifacts
- Platform compatibility considerations (GNU toolchain assumed but with opt-out paths)

Hamano identifies several areas needing attention:
1. The unconditional inclusion of `public_symbol_export.o` in `OBJECTS` may need to be made optional
2. Unnecessary `-r` flags in clean targets for non-directory files
3. Platform portability of the `-r` linker flag and `--localize-hidden` objcopy feature
4. Whether the GCC visibility pragmas will work on non-GCC/clang compilers

The feedback maintains the overall positive trajectory of the Rust bindings work while flagging specific technical details that would benefit from either broader platform support or clearer opt-out mechanisms. The implementation remains contained to `contrib/` with core Git functionality unaffected.
