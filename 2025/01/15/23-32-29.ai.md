This is a test infrastructure patch in the ongoing effort to standardize Git's help output behavior. Jeff King proposes adding a transitional flag `GIT_TEST_HELP_MUST_BE_STDOUT` to the test suite that will allow developers to selectively enforce the new stdout standard for help output while maintaining permissive behavior by default during the conversion period.

The patch modifies `t/t0012-help.sh` to check help output location conditionally - either allowing output on stdout or stderr normally, but enforcing stdout-only when the test flag is set. Junio Hamano approves the approach while noting some implementation details: the check may be stricter than strictly necessary (as it requires stderr to be completely empty) but considers this acceptable for now, and raises a broader question about whether all 40 commands currently doing manual `-h` checks actually need that special handling.

The change represents a practical step in the multi-track standardization effort, providing developers with a tool to identify remaining conversion work while not breaking existing test runs. It follows earlier discussions about the scope of the problem (40 vs 102 builtins) and maintains the temporary exit code 129 convention until output behavior is fully standardized. The test infrastructure will eventually transition to always enforcing stdout output once all conversions are complete.
