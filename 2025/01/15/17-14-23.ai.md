This is a technical follow-up in the ongoing discussion about standardizing Git's output streams for help text. Jeff King (Peff) builds on Kristoffer Haugsbakk's audit of builtins that output help to stderr by:

1. Proposing a test case (`t/t0012-help.sh`) to verify help output goes to stdout with empty stderr, which would catch the current inconsistency
2. Analyzing the specific case of `git branch -h`, tracing its stderr output to commit 1dacfbcf13 which bypasses parse-options to avoid repository checks
3. Providing a concrete fix for `branch.c` that reorders initialization to safely use parse-options
4. Suggesting a broader solution: introducing a stdout variant of `usage_with_options()` to handle this systematically across all commands

Key technical points:
- The `branch.c` fix involves moving `parse_options()` before repository-dependent setup
- Peff notes the safety of this depends on no option parsing depending on the moved initialization
- The proposed solution would affect all 35 identified commands rather than requiring individual fixes

This moves the thread from documentation/analysis to concrete implementation options, with Peff favoring a targeted helper function over command-by-command fixes. The email provides enough technical detail for future discussion about whether to adopt the systematic approach or handle commands individually.
