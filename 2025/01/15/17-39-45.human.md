This is a bugfix/consistency patch in the ongoing effort to standardize Git's help output behavior. Kristoffer Haugsbakk provides concrete data showing that 40 out of 142 Git builtins currently output help text to stderr when using the `-h` flag, while the majority (102) use stdout. This confirms Junio Hamano's earlier suspicion that stderr usage is the minority case.

The email includes a comprehensive list of all builtins and their current behavior, showing some duplicates (like `git add` and `git log` appearing multiple times) that may need verification. The data strengthens the case for standardizing on stdout for help output, which has been the direction favored by the maintainer. The thread has already seen technical proposals from Jeff King for implementing this change, including test infrastructure and specific fixes.

This email serves as important validation of the audit work, providing the concrete numbers needed to make an informed decision about the standardization effort. The next steps will likely involve evaluating Jeff King's proposed systematic approach against this complete dataset.
