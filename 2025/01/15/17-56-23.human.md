This is a technical follow-up in the ongoing thread about standardizing Git's help output behavior. Junio Hamano responds to Jeff King's proposal for a systematic solution to make `-h` help output go to stdout consistently across all commands.

The email shows a concrete implementation of Jeff's suggested `show_usage_help()` helper function that would handle the `-h` check and help output in one step. Junio provides a sample patch demonstrating how it would work in `builtin/am.c`, while expressing some reservation about the "show help and exit if requested, otherwise no-op" semantics.

The proposed change would:
1. Add a new `show_usage_help()` function to parse-options.c that centralizes the `-h` handling
2. Modify commands to use this helper instead of manual `-h` checks
3. Maintain the existing behavior where help goes to stdout with exit code 0

This represents progress toward the maintainer-endorsed solution of standardizing help output behavior through parse-options infrastructure changes rather than patching individual commands. The thread has moved from philosophical debate through implementation analysis to concrete code proposals, with this email showing what the systematic solution might look like in practice.
