Bug report about `git branch -h` output behavior. Jonas Konrad reports that `git branch -h` unexpectedly writes its usage message to stderr rather than stdout, which breaks piping to tools like `grep`. The behavior differs from `git -h` which uses stdout as expected. The report notes this is accompanied by a non-zero exit status, suggesting it might be intentional but arguing this makes little sense for a simple help request. The issue was observed on Git 2.48.1 running on Arch Linux with bash shell. The reporter provides full system info and suggests stdout would be more appropriate for this case, especially since invalid options could justify stderr while still allowing zero exit status for `-h`. No patch is included - this is purely an issue report.
