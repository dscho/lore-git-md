Refactoring patch for Rust bindings infrastructure, part 1/5 in the series. This initial patch splits Git's initialization and exit code out of `common-main.c` into separate files (`common-exit.c` and `common-init.c`) to make `libgit.a` more self-contained for external users. The change allows linking against Git's core library without pulling in unnecessary dependencies from builtin commands.

The patch moves `common_exit()` and `check_bug_if_BUG()` to their own file, and extracts initialization logic into a new `init_git()` function. This follows up on previous attempts to solve symbol conflicts for fuzz tests and unit tests, though those were addressed differently. The new organization better supports the project's Rust bindings effort by providing cleaner boundaries for FFI integration.

The changes are mechanical and well-contained, touching only the build system and core initialization paths. The commit message provides clear rationale and references prior discussions about similar splits. As the first step in a larger series to enable Rust bindings, this appears to be a solid foundation that doesn't introduce new functionality but improves code organization for the work to come.
