Chris Howlett has proposed adding a "prompt-yes" mode to Git's `help.autocorrect` configuration, which would make the interactive prompt for suggested commands default to "Yes" (changing from "[y/N]" to "[Y/n]"). The second version of the patch has been rebased against recent changes in master (commits e21bf2c and e4542d8) and introduces a new constant value (-5) in the help subsystem.

Kristoffer Haugsbakk initially noted this change might interact with Scott Chacon's parallel work to make `help.autocorrect` accept boolean values, but that work appears stalled in the `seen` branch. The current implementation remains cleanly separated from those changes, focusing only on the help subsystem with updates to config parsing and prompt handling. Documentation has been included to explain the new mode.

The patch is technically sound but appears to be waiting for feedback - Howlett is checking if it was overlooked or if there's waning interest. The change would provide a useful middle ground between the current prompt behavior (defaulting to No) and immediate execution, particularly for users who frequently accept suggested commands but still want the safety of a prompt. Testing remains limited by the test suite's inability to easily verify interactive prompts.
