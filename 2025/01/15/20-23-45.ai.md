Documentation patch in a series standardizing git-commit man page formatting.

This is the second patch in Jean-Noël Avila's 5-part series converting Git documentation to consistent AsciiDoc format. It specifically addresses the optionality of the mode parameter for the `-u` option in `git commit`. The change makes the synopsis match the actual behavior by wrapping `<mode>` in square brackets in both the man page (Documentation/git-commit.txt) and the command usage message (builtin/commit.c).

The modification is straightforward - adding square brackets around `<mode>` in the `-u` option syntax to indicate it's optional, which aligns with how the option is described elsewhere in the documentation. This follows from feedback on the first version of the series regarding accurate representation of optional parameters.

The patch maintains the series' focus on mechanical formatting improvements without altering functionality, keeping with the goal of documentation standardization. Both changes are minimal (2 lines modified in each file) and clearly focused on the stated purpose of reflecting the option's optional parameter correctly.
