This thread documents Git's ongoing effort to standardize help output behavior across all commands to consistently use stdout rather than the current mix of stdout and stderr. The effort began with Jonas Konrad's bug report about inconsistent behavior between commands like `git -h` (stdout) versus `git branch -h` (stderr). After debate, maintainer Junio Hamano mandated stdout standardization, with Jeff King (Peff) providing test infrastructure and Kristoffer Haugsbakk auditing the scope (40 builtins using stderr versus 102 using stdout).

Junio is actively converting commands through two parallel tracks: those using parse-options (via a new helper function) and those with direct `usage()` calls (via an upcoming 6-patch series). The latest discussion between Junio and Peff shows them converging on pragmatic solutions, agreeing to use a transitional test flag (`GIT_TEST_HELP_MUST_BE_STDOUT`) rather than maintaining a conversion checklist, and accepting that auditing all 40 manual `-h` cases may not be worth the effort. They're prioritizing progress on the core standardization while deferring edge cases like deprecation notices.

The implementation is now showing concrete progress, with test updates (like `t7600-merge.sh`) and infrastructure in place, though some architectural questions remain about `vreportf()`'s stderr assumption and eventual exit code standardization. The maintainers appear aligned on direction, with Junio driving the conversions and Peff providing testing support, suggesting this standardization will likely land in an upcoming release.
