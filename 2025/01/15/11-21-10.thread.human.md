This thread documents Git's ongoing effort to standardize how builtin commands handle `-h` help output, moving from inconsistent behavior (some commands printing to stdout, others to stderr) to a maintainer-mandated stdout standard. The work has progressed along three technical tracks: parse-options API changes, direct usage() callers, and test infrastructure improvements.

Jonas Konrad originally reported the divergent behaviors, sparking discussion between stdout consistency advocates and those favoring stderr as UNIX convention. Maintainer Junio Hamano ultimately mandated stdout standardization, with Jeff King (Peff) providing key technical analysis and test infrastructure. Kristoffer Haugsbakk's audit found 40 builtins using stderr versus 102 using stdout for help output.

The latest patch from Junio converts 13 more builtin commands (including frequently used ones like branch, commit, and rebase) to use the new helper function that ensures stdout output. While this makes concrete progress on the parse-options conversion track, the thread notes deeper architectural challenges remain - particularly around direct usage() callers and vreportf()'s stderr assumption. The test infrastructure now supports both transitional and strict validation modes, with exit code standardization deferred until after output behavior is fixed.

Key contributors include Junio driving implementation, Jeff King expanding the technical solution, Jonas as original reporter, and Kristoffer providing the initial audit. The work continues to balance immediate progress with addressing Git's underlying output handling mechanisms.
