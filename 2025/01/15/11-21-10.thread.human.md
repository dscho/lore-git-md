This thread began with Jonas Konrad reporting inconsistent behavior in Git 2.48.1 where different commands handled `-h` help output differently - some printing to stdout (like `git -h`), others to stderr (like `git branch -h`), with varying exit codes. After initial discussion between Jonas (advocating stdout consistency) and Matěj Cepl (defending stderr as UNIX convention), maintainer Junio Hamano settled the debate by endorsing stdout standardization.

Kristoffer Haugsbakk conducted a comprehensive audit revealing 40 builtins output help to stderr versus 102 using stdout, with non-builtin tools showing even more variation. Jeff King (Peff) contributed technical analysis, test infrastructure, and a concrete fix for `branch.c`, proposing a systematic solution through a new stdout variant of `usage_with_options()`. Junio has now implemented this as `show_usage_help()` in parse-options.c, incorporating Jeff's safety checks and maintaining the important distinction between help output (stdout, exit 0) and errors (stderr, exit 129).

The latest email sees Kristoffer adding a `Reported-by` trailer to Junio's patch, ensuring Jonas receives proper credit as the original reporter. With the API design finalized and test infrastructure in place, the remaining work involves updating the 40 affected builtin commands to use the new helper. The thread demonstrates Git's typical progression from bug report through analysis to maintainer-approved solution, with careful attention given to both technical correctness and proper attribution.
