This thread documents Git's ongoing effort to standardize where help messages are printed (`-h` output), moving from the current inconsistent behavior (some builtins to stdout, others to stderr) to a maintainer-mandated stdout standard. What began as Jonas Konrad's bug report has evolved into a multi-faceted implementation effort touching parse-options infrastructure, test tooling, and now deeper refactoring of Git's help system.

Junio Hamano and Jeff King (Peff) are driving the technical work, with Junio establishing the stdout standard and Peff building test infrastructure (`t/t0012-help.sh` with a new `GIT_TEST_HELP_MUST_BE_STDOUT` flag) to enforce it. The latest discussion reveals another layer of complexity: commands that bypass parse-options entirely, manually checking for `-h` before calling `usage()`, which currently writes to stderr via `vreportf()`. This will require refactoring the low-level reporting machinery itself.

The team has identified two parallel conversion tracks: one for parse-options users (addressed via Junio's new `show_usage_help_and_exit_if_asked()` helper) and another for direct `usage()` callers, which may need a new helper. Exit code behavior (currently 129 for parse-options help) remains temporarily unchanged pending future cleanup. While test infrastructure exists to validate conversions, the work continues to uncover subtle edge cases, demonstrating how deep this standardization cuts into Git's plumbing.
