This is part 4/5 in a series introducing Rust bindings for Git's C library, building on the low-level FFI bindings established in previous patches. The patch adds a higher-level `libgit` crate that provides idiomatic Rust wrappers around the C functions exposed by `libgit-sys`.

The new crate implements Rust-native interfaces for Git's config API, including:
- Memory-safe wrapper types (`ConfigSet`) with proper RAII semantics
- Rust-style methods for config operations (`add_files()`, `get_int()`, `get_string()`)
- Automatic conversion between C and Rust string types
- Test cases demonstrating config file loading and value retrieval

Key technical details:
- Follows Rust's common `$X`/`$X-sys` crate pattern for FFI
- Maintains Rust 1.63+ compatibility
- Includes build system integration (Cargo.toml, Makefile updates)
- Adds test data files for config API validation
- The implementation builds on the config API functions exposed in earlier patches (`libgit_configset_*`)
- Uses Rust's ownership system to ensure proper memory management of C allocations
- Provides a more ergonomic interface than raw FFI calls while maintaining safety

The patch appears well-structured with thorough test coverage and follows established Rust FFI patterns. It represents a logical next step in the Rust bindings effort after the foundational `libgit-sys` work. The implementation looks production-ready for incremental integration while remaining contained to `contrib/`.
