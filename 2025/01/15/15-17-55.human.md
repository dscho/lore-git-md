Bugfix follow-up addressing a technical implementation detail in the ANSI escape sequence security series.

Andreas Schwab points out a specific issue with the `iscntrl()` call in the newly introduced `strbuf_add_sanitized()` function from the sideband control character sanitization patch. The function needs to cast its character argument to `unsigned char` when calling `iscntrl()`, as is standard practice for character classification functions to avoid potential undefined behavior with negative `char` values on platforms where `char` is signed.

This is a focused technical correction to an already-reviewed security patch, not challenging the overall approach. The fix aligns with established C programming practices for character handling. While minor, it's the sort of precise observation that helps harden security-sensitive code. The thread's broader discussion about terminal security models and whitelisted sequences continues unaffected by this implementation-level note.
