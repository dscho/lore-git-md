This is a follow-up in the ongoing discussion about inconsistent help message behavior in Git commands. Jonas Konrad expands on his original bug report by surveying more subcommands, finding that `git -h` writes to stdout (as he prefers), `git reflog -h` writes to stdout but exits non-zero, and `git branch -h` writes to stderr - three distinct behaviors for what seems like the same operation. He argues this inconsistency is confusing, and counters Matěj Cepl's UNIX convention argument by noting most Git subcommands already use stdout for help text. The email highlights the scope of the issue - if stderr is the "correct" place for help text, many subcommands would need changing. No technical resolution is proposed, but the message effectively demonstrates the current behavior is inconsistent even within Git itself. The thread remains at an impasse between UNIX convention arguments and practical usability concerns, awaiting maintainer input.
