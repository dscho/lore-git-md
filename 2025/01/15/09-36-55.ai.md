This is a feature patch adding a new configuration option for Git's command autocorrection behavior. The patch introduces a "prompt-yes" mode for `help.autocorrect` that works like the existing "prompt" mode but defaults to "Yes" when confirming whether to run the suggested command. The "prompt" mode currently defaults to "No", which the author argues is less optimal since Git's autocorrection is usually correct.

The implementation adds a new `AUTOCORRECT_PROMPT_YES` constant (-4) alongside the existing AUTOCORRECT_PROMPT (-3), with corresponding handling in both the config parsing and the interactive prompt logic. When not in a terminal environment, "prompt-yes" falls back to immediate execution (like "immediate" mode) rather than doing nothing (like "prompt" falls back to "never").

The patch touches two files: `Documentation/config/help.txt` to document the new option, and `help.c` to implement the behavior. The author notes this is their first Git contribution and acknowledges the lack of tests due to the difficulty of testing interactive prompts, though they observe the existing "prompt" behavior also lacks tests. The change appears well-contained and focused on a specific user experience improvement.
