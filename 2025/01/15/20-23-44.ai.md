Documentation standardization patch converting git-commit man page to AsciiDoc format. This is the first of five patches in Jean-Noël Avila's v2 series, focusing on mechanical formatting changes to the git-commit.txt documentation without altering content.

The patch systematically applies new documentation guidelines to the git-commit man page, introducing several consistent formatting elements: converting the synopsis to a dedicated synopsis block (which handles automatic italics/monospace formatting), standardizing placeholder notation as _<placeholder>>_, and wrapping commands/options in backticks (`git commit`, `-a`). The changes affect 256 lines (128 insertions, 128 deletions) in Documentation/git-commit.txt, touching nearly every section of the man page.

Key technical changes include updating the SYNOPSIS section to use [synopsis] block syntax instead of [verse], converting all option descriptions to use backtick-wrapped monospace formatting, and standardizing placeholder markup throughout. The patch maintains all existing functionality while making the documentation more consistent with Git's evolving style guidelines. This is part of a broader effort to standardize Git's man page formatting, with subsequent patches in the series handling more specialized aspects of the git-commit documentation.
