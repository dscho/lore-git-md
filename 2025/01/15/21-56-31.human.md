Implementation patch for Git help output standardization, finalizing the API design for consistent stdout behavior. This is the second version of Junio Hamano's patch introducing `show_usage_help_and_exit_if_asked()`, a helper function to correct the 40+ builtin commands that currently send help text to stderr when invoked with `-h`.

The patch provides a systematic solution to the inconsistency first reported by Jonas Konrad, where different Git commands handle help output differently (`git -h` vs `git branch -h`). The new helper function encapsulates the common pattern of checking for `-h` and displaying help via stdout while maintaining the existing exit code behavior (129) for now. The implementation includes safety checks for argc/argv to prevent misuse.

Notably, the patch preserves the current exit code behavior despite theoretical arguments for using 0 when displaying help, due to PARSE_OPT_HELP's dual use for both help requests and ambiguous options. Junio indicates this may be addressed in a future patch after all commands are converted. The implementation follows Jeff King's suggested approach and credits him for the technical suggestion, while maintaining proper attribution sequencing for the original bug report.

This represents the infrastructure piece of the solution, with the actual command conversions to follow in subsequent patches. The design intentionally makes careless conversions difficult by requiring proper callsite inspection, ensuring each conversion is done thoughtfully.
