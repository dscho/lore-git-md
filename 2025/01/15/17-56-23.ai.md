This is a technical implementation discussion in the ongoing thread about standardizing help output behavior across Git commands. Junio Hamano responds to Jeff King's proposal for a systematic solution to the help output inconsistency issue.

The email presents a concrete implementation of Jeff's suggested `show_usage_help()` function that would handle the "-h" help case uniformly. The proposed function would:
1. Check for the "-h" flag
2. If found, display help via `usage_with_options_internal()` (which outputs to stdout)
3. Exit with status 0
4. Otherwise do nothing

The patch shows the function's implementation in parse-options.c, its declaration in parse-options.h, and a sample conversion of `builtin/am.c` to use the new helper. Junio expresses some reservation about the semantic design ("I am not sure if I like..."), particularly around the function's dual nature as both a potential exit point and a no-op.

This continues the thread's progression from problem identification through audit to implementation, now focusing on the specific mechanics of the parse-options API changes needed to support the stdout standardization effort. The discussion remains technical, with Junio providing concrete code while still questioning aspects of the design approach.
