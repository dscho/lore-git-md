Follow-up investigation of non-builtin Git commands' help output behavior. Kristoffer Haugsbakk completes the audit by examining auxiliary tools not covered in the main builtin analysis, confirming several edge cases:

- `git-http-backend` (a builtin) rejects `-h` with a fatal error on stderr and HTTP 500 status
- `git-filter-branch` shows special behavior: warning message followed by 10-second delay before stdout help output
- Confirms Jonas's findings about `git-scalar` (stderr), `git-lfs` (no `-h` support), and `git-p4` (stdout without `-h` flag)

This email provides the missing pieces of the implementation audit, showing that while the core standardization effort focuses on builtins, auxiliary tools exhibit even more varied behavior patterns. The findings suggest that any future standardization beyond core commands would need to account for these special cases, particularly the delayed output of `git-filter-branch` and the web-specific response format of `git-http-backend`.

Key technical details:
- `git-http-backend` implements CGI protocol requirements (REQUEST_METHOD check)
- `git-filter-branch` maintains its legacy warning/delay behavior
- Non-builtin tools show no consistent pattern for help output handling

The email reinforces that the current stdout standardization effort for builtins (40 commands) is appropriately scoped, as extending it to auxiliary tools would require addressing fundamentally different implementation constraints.
