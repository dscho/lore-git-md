Bugfix/consistency patch for Git help output behavior.

Kristoffer Haugsbakk provides a concrete implementation of Junio Hamano's suggestion to audit which Git builtins output their usage help to stderr rather than stdout. The script enumerates all builtin commands (via `git --list-cmds=builtins`), runs each with `-h` while redirecting stdout to /dev/null, and filters for usage messages appearing on stderr. The output shows 35 commands that currently exhibit this behavior, including commonly used ones like `git branch`, `git commit`, and `git status`.

The technical implementation is notable for its careful handling of the output - it strips the "usage: " prefix and experimental markers while preserving just the command names. The script was tested against Git 2.48.0, showing this is a current issue rather than something fixed in later versions. This provides a concrete starting point for any standardization effort, as it precisely identifies which commands would need modification if the project decides to normalize help output to stdout.

The email advances the thread from theoretical discussion to actionable data, though it doesn't propose specific code changes. The list includes some surprises (like `git diff` and its variants) and duplicates (`git upload-archive` appears twice), which may warrant investigation. This inventory will be crucial for any systematic fix, as it shows the scope of commands affected by the stdout/stderr inconsistency.
