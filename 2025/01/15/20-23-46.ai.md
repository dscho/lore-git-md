Documentation patch (part 3/5 of standardization series) focusing on direct option explanations in git-commit.txt. This patch continues Jean-Noël Avila's effort to modernize Git's documentation format, specifically targeting the OPTIONS section of git-commit.txt.

The changes convert passive explanations to active voice and consistently apply the placeholder format (_<file>_, _<msg>_, etc.) throughout the options documentation. Notable transformations include simplifying hook bypass descriptions (-n/--no-verify), restructuring the --allow-empty-message explanation, and making path specification language more direct (--pathspec-from-file). The patch touches 29 lines with 13 insertions and 16 deletions, maintaining the same semantic meaning while improving clarity and consistency.

This follows the pattern established in patches 1-2 of the series, applying the same documentation principles to option descriptions. The changes are mechanical in nature, focusing on presentation rather than content changes. The patch maintains all existing cross-references (linkgit) and configuration variable mentions while updating their surrounding text to the new style.

Key technical details for future reference: the patch standardizes on imperative mood for all option descriptions, uses _<placeholder>_ notation for variables, and tightens phrasing while preserving all technical accuracy. The changes affect core commit options like -a, -F, -m, --cleanup, and --pathspec-from-file, with particular attention drawn to the rewritten --allow-empty-message explanation that now leads with its primary purpose before mentioning the SCM interface use case.
