This is a technical discussion about the ongoing standardization of Git's help output behavior. Jeff King (Peff) responds to Junio Hamano's observation about another class of commands that handle `-h` help requests manually rather than through the parse-options API. These commands directly call `usage()` with a manual `-h` check, and since `usage()` writes to stderr via `vreportf()`, they'll need similar refactoring to match the new stdout standard.

The exchange highlights an additional layer of complexity in the standardization effort - beyond the parse-options API changes already underway, there's now a recognition that manual help handlers will need parallel treatment. This suggests the project will need to develop equivalent helpers for these cases, similar to the `show_usage_help_and_exit_if_asked()` helper already created for parse-options users.

The tone is one of recognizing necessary but somewhat tedious work - Peff's "Oof" and Junio's "Sigh" suggest this is a non-trivial expansion of scope, though one they clearly intend to address as part of the comprehensive fix for the help output inconsistency issue.
