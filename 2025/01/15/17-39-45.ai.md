Implementation audit follow-up confirming stdout/stderr distribution for Git help output. Kristoffer Haugsbakk provides concrete numbers from their expanded analysis: 40 builtins output help to stderr versus 102 using stdout, confirming Junio Hamano's observation that stderr usage is the minority case. The email includes a comprehensive list of all builtins and their current behavior, with some duplicates noted (like `git log` appearing multiple times).

The message also demonstrates the expected behavior for usage-on-error cases (like `git-upload-pack` without arguments), which correctly uses stderr, distinguishing this from the `-h` help case under discussion. This data reinforces the technical basis for standardizing on stdout for `-h` output, as previously endorsed by the maintainer.

Key technical details:
- Full list of 102 stdout-using commands (including core ones like `add`, `commit`, `fetch`)
- List of 40 stderr-using commands (including `branch`, `checkout`, `merge`)
- Demonstration of proper stderr behavior for error cases
- Some duplicate entries in the audit data needing verification

This provides the concrete implementation landscape needed to proceed with the standardization effort, showing both the scope of changes needed (40 commands to modify) and confirming the maintainer's position that stdout is the dominant existing pattern. The data supports Jeff King's proposed systematic approach using parse_options() reordering where possible.
