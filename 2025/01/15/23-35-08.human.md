This is a patch in the ongoing effort to standardize Git's help output behavior, specifically addressing builtin commands that use `usage_with_options()`. 

Junio Hamano's patch converts several builtin commands to use the new `show_usage_help_and_exit_if_asked()` helper function, ensuring their help text goes to stdout rather than stderr when explicitly requested with `-h`. The changes affect commands like `git branch`, `git commit`, `git merge`, and others - 13 files in total. 

The patch is part of a larger effort that has identified three distinct code paths needing conversion (parse-options API, direct usage() callers, and test infrastructure). This particular patch handles the first category. The changes are mechanical but important for consistency, following maintainer direction to standardize on stdout output for help text.

The patch includes a test update in t7600-merge.sh to account for the new stdout behavior. While the exit code remains 129 for now (a separate issue being tracked), this moves forward the primary goal of output stream consistency. The changes appear straightforward and well-contained, focusing only on the help text output path without altering other functionality.

This represents concrete progress on an issue originally reported by Jonas Konrad, with technical contributions from Jeff King and Kristoffer Haugsbakk. The patch follows the established pattern seen in earlier conversions and should integrate cleanly with the new test infrastructure (`GIT_TEST_HELP_MUST_BE_STDOUT`) that's been developed to verify these changes.
