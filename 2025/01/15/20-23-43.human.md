Documentation standardization series for git-commit (v2). This is the second iteration of Jean-Noël Avila's effort to bring git-commit's documentation in line with Git's new man page formatting guidelines. The 5-part series expands on the previous 3-part version with more granular changes and refinements based on feedback.

The series starts with converting git-commit.txt to use the new synopsis block format, standardizing placeholder notation (_<file>_), and wrapping commands/options in backticks. It then makes several focused improvements: clarifying that the -u option's mode parameter is optional, rewriting some option descriptions to be more direct, converting the config documentation format, and updating supporting files (i18n.txt and signoff-option.txt).

Notable changes from v1 include splitting the original first patch into three more focused commits (1-3) for better reviewability, keeping the config and secondary file updates as separate commits (4-5), and incorporating feedback about commit message style and placeholder consistency. The changes remain purely presentational - 297 lines modified across 5 files with no functional impact. This continues Avila's broader initiative to standardize Git's documentation format.
