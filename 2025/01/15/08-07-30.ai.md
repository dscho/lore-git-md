This is a bug report about large repository cloning failures on Windows. The reporter, Ginger Luo, describes encountering a "fatal: pack has bad object" error when attempting to clone a 30GB+ repository using Git for Windows (versions including 2.47.1). The failure consistently occurs around the 4GB mark during object transfer, suggesting a 32-bit integer overflow issue similar to one previously fixed in git-for-windows/git#2179.

The key technical details are the error message ("inflate returned 1") and the 4GB threshold, which strongly indicate a size_t vs long integer handling problem in the packfile processing code. The reporter notes they're using 64-bit Git on 64-bit Windows Server, implying this isn't simply a 32-bit platform limitation. They express confusion about why this issue persists despite what appears to be a prior fix.

This appears to be a serious data transfer issue affecting large repositories on Windows. The reporter provides enough technical detail (specific error, size threshold, platform info) to suggest this is a legitimate bug rather than user error. The reference to PR 2179 gives maintainers a starting point for investigation, though the reporter doesn't specify whether they've tried any workarounds or newer Git versions beyond 2.47.1. The bug's impact is clear - it prevents cloning repositories over 4GB on Windows - but the exact conditions triggering it (network protocol, server configuration, etc.) aren't fully specified.
