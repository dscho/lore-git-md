This is part of the foundational Rust bindings for Git's C library (v9 2/4), building on the initialization refactoring from patch 1/9. The patch introduces `libgit-sys`, a low-level Rust crate that provides FFI bindings to `libgit.a` with careful symbol visibility management to avoid collisions (prefixing with `libgit_` and using `-fvisibility=hidden`).

Key technical elements:
- Build system integration via new Makefile rules and `build.rs` that compiles `libgitpub.a` containing Git's static libraries
- Symbol visibility controlled through `public_symbol_export.[ch]` shim layer
- Initial proof-of-concept exposing user agent string functions (`libgit_user_agent()`, `libgit_user_agent_sanitized()`)
- Includes test cases verifying the Rust bindings work correctly
- Uses Rust 1.63+ compatibility with `autocfg` feature detection
- Builds as part of main Git build when `INCLUDE_LIBGIT_RS` is set

The implementation demonstrates the pattern that will be used for future API exposure - all C functions must go through the symbol export layer before being callable from Rust. This is part of the larger effort to provide both direct C bindings (`libgit-sys`) and idiomatic Rust interfaces (`libgit`), with all build system and symbol visibility issues now resolved through the v9 iterations.
