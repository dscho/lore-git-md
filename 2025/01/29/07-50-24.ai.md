Build system refinement discussion regarding header inclusion styles in the reftable separation series.

Johannes Sixt provides a stylistic critique of Patrick Steinhardt's header path changes in the fsmonitor compatibility code. The key observation is that the patch changes a local `"fsm-health.h"` include to a project-root-relative `"compat/fsmonitor/fsm-health.h"` when both resolve to the same file. Sixt argues this violates the conventional meaning of double-quote includes (which imply same-directory location) versus angle-bracket includes (which imply system/search-path location). 

This is a nuanced point about coding style rather than functionality, coming late in the already-accepted reftable separation series. Sixt suggests considering more liberal use of angle brackets if the goal is to enforce project-root-relative paths, though the thread context shows this particular build system change (patch 15/20) had already been approved by Junio Hamano after earlier revisions. The comment doesn't challenge the series' technical merits but offers a refinement to its stylistic consistency regarding include directives.
