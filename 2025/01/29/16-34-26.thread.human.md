This thread explores a reported issue with Git's handling of the `PREFIX` environment variable for configuration file locations. Randall S. Becker initially observed that Git wasn't respecting `PREFIX` at runtime when looking for system config files, expecting it to use `${PREFIX}/etc/gitconfig` but finding it used build-time paths instead. Junio C Hamano clarified that this is intentional - `PREFIX` is strictly a build-time setting in Git's architecture, not meant for runtime configuration.

In a follow-up, Randall points to documentation that appears to contradict this behavior while explaining his practical constraint: lacking permissions to create system directories where Git expects its config files. He proposes `GIT_CONFIG_SYSTEM=path` as a potential runtime solution and seeks guidance on implementation. The discussion has revealed both a documentation question (clarifying `PREFIX`'s role) and a potential feature gap (runtime control of config paths), with Randall's latest email providing concrete use cases and solution ideas. The thread remains open on whether to address this through documentation updates, reviving the possibly unmaintained `RUNTIME_PREFIX` mechanism, or implementing new runtime override capabilities.
