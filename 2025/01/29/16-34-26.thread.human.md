This thread examines a discrepancy between Git's documented and actual behavior regarding the `PREFIX` environment variable's role in configuration path resolution. The discussion began when Randall S. Becker reported that Git wasn't respecting `PREFIX` for runtime to locate configuration files, particularly on NonStop systems where system directory writes are restricted.

Junio Hamano initially clarified that `PREFIX` is build-time only, but in the latest email corrects this to specify he was referring to the Makefile's `$(prefix)` macro, not the environment variable. The thread has uncovered that while Git's source code contains no runtime handling of `PREFIX`, the progit2 documentation (Git Internals - Environment Variables) describes it as a runtime mechanism. This documentation originates from a 2014 progit2 repository commit, separate from Git's main project docs.

Testing has shown that `RUNTIME_PREFIX` doesn't solve the underlying need for runtime configuration path control, leaving `GIT_CONFIG_SYSTEM` as the most promising alternative. The discussion now centers on whether to implement runtime `PREFIX` support to match the external documentation or declare that documentation inaccurate. Randall maintains the need for a runtime solution to accommodate restricted environments, while Junio has focused on clarifying the current implementation's behavior and documentation provenance. The path forward will require either code changes or documentation updates, potentially involving coordination with progit2 maintainers.
