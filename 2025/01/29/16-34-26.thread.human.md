This thread discusses a configuration path issue where Git currently lacks runtime control over system configuration file locations. Randall S. Becker (NonStop port maintainer) initially reported that Git wasn't respecting the `PREFIX` environment variable for runtime config paths, expecting it to look in `${PREFIX}/etc/gitconfig`. Junio C Hamano clarified that `PREFIX` is strictly a build-time setting, not runtime-configurable.

The discussion has revealed a documentation discrepancy and highlighted real-world constraints where system administrators need runtime control over config paths due to filesystem permission restrictions. Randall tested Junio's suggestion to use `RUNTIME_PREFIX` but found it ineffective, reinforcing the need for a solution. The main proposal on the table is implementing a `GIT_CONFIG_SYSTEM` environment variable as a runtime override mechanism.

Key outstanding questions include whether to update documentation to better reflect the build-time nature of `PREFIX`, whether to revive/improve the `RUNTIME_PREFIX` mechanism, or implement a new solution like `GIT_CONFIG_SYSTEM`. The discussion remains active with no resolution yet, focused on finding a solution that maintains Git's current architecture while addressing real-world deployment constraints, particularly for environments like NonStop with strict permission requirements.
