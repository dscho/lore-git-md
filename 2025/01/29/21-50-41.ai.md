This is the first patch of the final v9 series implementing Rust bindings for Git's C library, focusing on refactoring initialization and exit code. The patch splits Git's common initialization and exit handling into separate files (`common-exit.c` and `common-init.c`) to make `libgit.a` more self-contained for external users.

The key changes move `common_exit()` and `check_bug_if_BUG()` into `common-exit.c` and extract initialization code from `main()` into a new `init_git()` function in `common-init.c`. This allows external programs to use Git's setup/teardown code without pulling in all builtin commands. The patch references prior attempts to solve similar problems for fuzz tests and unit tests, but now positions this as a general solution for making `libgit.a` more modular.

The implementation touches core initialization paths including signal handling, locale setup, repository initialization, and trace2 instrumentation. Both new files are added to `LIB_OBJS` in the Makefile and `libgit_sources` in meson.build to ensure they're included in the static library. The changes maintain all existing behavior while improving code organization.

This foundational refactoring enables the subsequent patches in the series to build Rust bindings that can properly initialize and interact with Git's core functionality. The clean separation of concerns here is particularly important for the FFI boundary between C and Rust. The patch appears well-tested and complete, with all build system integrations properly handled.
