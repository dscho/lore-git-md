This is a feature proposal for a new Git hook. Mike Weltevrede suggests adding a `pre-checkout` hook to complement the existing `post-checkout` hook, specifically to validate branch names before a checkout occurs rather than after.

The key motivation is branch name validation - currently, while `post-checkout` can validate names, the checkout has already occurred by that point. The author wants to prevent users from even starting work on improperly named branches, rather than detecting the issue after the fact (which requires manual cleanup). They mention currently combining `post-checkout` and `pre-push` as a workaround, but find this suboptimal since it allows work to begin on invalid branches.

The email raises an interesting design question about why Git doesn't already have a `pre-checkout` hook given it has both pre/post variants for other operations. The proposal is straightforward but lacks implementation details - it's purely a conceptual pitch at this stage, without any patch or technical design for how the hook would integrate with Git's checkout machinery. The use case seems legitimate for branch name validation workflows, though the thread may explore whether there are technical or design reasons this hook was omitted originally.
