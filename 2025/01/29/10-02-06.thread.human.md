This RFC thread addresses a subtle bug in `git repack` where promisor objects were bypassing `--keep-pack` and `.keep` file checks, potentially causing large promisor packs to be unnecessarily repacked despite `gc.bigPackThreshold` settings. The discussion has progressed through several technical phases.

Tomáš Trnka originally identified the issue and proposed a fix that has now been empirically validated in production environments, successfully preventing repacking of 80GB promisor packs on btrfs filesystems. While Han Young initially raised theoretical concerns about the implementation approach, they've since confirmed the patch works as intended in practice, though they note a remaining optimization opportunity: the current solution still iterates over kept objects before discarding them, suggesting moving the keep-pack filtering earlier in the process.

The thread has reached consensus on test placement (favoring `t0410-partial-clone.sh` over `t7700-repair.sh`) and the core functionality appears sound. Two main items remain before this could graduate from RFC status: (1) addressing the performance optimization around object iteration, and (2) resolving earlier formatting issues that prevented clean patch application. The discussion has benefited from both theoretical analysis and production validation, with brian m. carlson providing process guidance along the way. With the core correctness now established, the focus shifts to refining the implementation before potential inclusion.
