This thread addresses a bug in `git repack` where promisor packs were not properly respecting keep-pack protections (both `.keep` files and explicit `--keep-pack` arguments). The issue means large promisor packs that should be preserved (e.g., based on `gc.bigPackThreshold`) could be repacked unnecessarily.

The proposed fix modifies `repack_promisor_objects()` to apply the same keep-pack logic used for regular packs, ensuring consistent behavior. The patch is small but touches core repacking behavior. The author has marked it as RFC while seeking input on test placement - whether to add coverage in the existing repack tests (t7700) or partial clone tests (t0410). 

While the technical change appears straightforward, the test location question may prompt feedback from repack and partial clone experts like Patrick Steinhardt or Taylor Blau, who have worked extensively on these subsystems. The patch seems likely to proceed after resolving the testing approach.
