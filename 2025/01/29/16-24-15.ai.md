This is the second patch in a 2-patch series fixing memory leaks detected by Meson builds. It addresses a leak in scalar.c where the result of `remote_default_branch()` wasn't being freed, as revealed by test t9211 under leak sanitization.

The patch introduces a new `branch_to_free` variable to properly track and free the allocated string from `remote_default_branch()`, while preserving the existing `branch` variable that may contain string constants from command-line arguments. The fix follows the same pattern as the first patch in the series, using proper memory management while maintaining existing behavior.

Key technical details:
- Leak occurs in `cmd_clone()` when fetching remote default branch
- Fix adds 3 lines (including new variable declaration) and removes 1
- Uses standard `free(branch_to_free)` pattern in cleanup section
- Leak was detected via Meson's leak sanitizer but not Makefile builds
- Test t9211 exposes the issue under leak detection

The change is minimal and focused, similar in scope to the first patch in the series. It demonstrates another case where Meson's build configuration catches resource management issues that traditional builds miss. The patch appears ready for review, completing the series' goal of fixing these specific leak cases.
