Build system refactoring in Patrick Steinhardt's Meson improvement series, patch 3/11. This change simplifies how executables link against the common-main functionality by eliminating an intermediate static library.

The patch removes the separate `common-main` static library and instead compiles its sources directly into each executable that needs them. This reduces build complexity by avoiding the need to specify both `libgit` and `common-main` dependencies everywhere. The change introduces a new `libgit_commonmain` dependency that combines both requirements.

A subtle issue surfaces with git-remote-http aliases (https, ftp, ftps) where the object extraction approach causes duplicate `main()` definitions when common-main is compiled in. The fix is to only link against `libgit` for these aliases rather than the combined dependency. The changes affect meson.build and related test build files, with straightforward mechanical updates to dependency specifications.

This continues the series' theme of simplifying Meson build configuration while maintaining identical functionality. The patch appears carefully implemented with attention to edge cases, though it may warrant review from those familiar with Git's build system internals, particularly the alias handling mechanism.
