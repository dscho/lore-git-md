Bugfix for a memory leak in Unix socket handling when directory changes fail. This is the first patch in a 2-part series addressing memory leaks caught by Meson's leak sanitizer.

Patrick Steinhardt fixes a case where `unix_sockaddr_init()` fails to free the original directory path when a subsequent `chdir()` operation fails. The leak occurs during Unix socket creation when trying to handle long path names by changing into the parent directory first. The issue was detected by test t0301 under Meson builds with leak sanitization enabled, though the commit message notes this wasn't caught by traditional Makefile builds.

The fix is straightforward - adding a `FREE_AND_NULL` call to clean up the allocated path when the directory change fails. The patch modifies just 4 lines in unix-socket.c, adding proper cleanup while maintaining the same error return behavior. This appears to be a well-contained fix for a clear resource management issue.
