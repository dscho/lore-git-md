This is a build system cleanup patch in Patrick Steinhardt's ongoing Meson refactoring series (patch 7/11). It simplifies the pattern of program detection in the Meson build configuration by reducing redundant checks for coreutils binaries.

The change removes several tools (`cut`, `sort`, `tr`, `uname`) from the list of required programs that get their paths prepended to PATH during build. The rationale is that since these all come from coreutils, checking for just one (in this case `cat`) is sufficient to ensure the suite is available. The modification maintains the same Windows build-time path resolution behavior while eliminating unnecessary individual program checks.

The patch continues the series' theme of mechanical but meaningful build system simplifications, this time focusing on the program detection logic. It touches only meson.build, changing the list of tools in the PATH preparation loop while keeping the same underlying mechanism. The change appears low-risk since it doesn't modify any actual build behavior - just reduces redundant checks for tools that would all be present together as part of coreutils.

Key technical details:
- Maintains Windows-specific PATH prepending behavior
- Reduces checked tools from 7 to 3 (`cat`, `grep`, `sed`)
- Keeps same script_environment modification pattern
- Preserves all functionality while simplifying configuration
- Follows series' pattern of focused meson.build optimizations
