This is the third patch in Patrick Steinhardt's series improving Git's Meson build system, focusing on simplifying library dependencies. The change streamlines how executables link against the shared "common-main.c" functionality by eliminating an intermediate static library and instead compiling the common code directly into each executable.

The patch reveals and fixes an interesting edge case: when creating aliases for git-remote-http, the existing approach would cause duplicate `main()` definitions since both the original objects and the newly compiled common code would include one. The solution is to only link against `libgit.a` for these aliases.

The changes touch meson.build and test-related build files, replacing the `common_main` dependency with a new `libgit_commonmain` that combines both common code and libgit linkage. This appears to be a well-considered optimization that maintains functionality while simplifying the build configuration, though it may warrant verification that all platform-specific builds continue to work as expected.
