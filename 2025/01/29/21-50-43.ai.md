Feature implementation for Rust bindings to Git's config API. This is patch 3/4 in the v9 series completing the Rust/C FFI bridge for Git's configuration system.

The patch exposes Git's configset API through the `libgit-sys` FFI layer, adding several key functions:
- `libgit_configset_alloc()`/`libgit_configset_free()` for heap-allocated config sets
- File operations via `libgit_configset_add_file()`
- Value retrieval with `libgit_configset_get_int()` and `libgit_configset_get_string()`

The implementation wraps Git's internal `config_set` struct in an opaque `libgit_config_set` type to maintain proper abstraction boundaries. Memory management follows RAII principles, where allocation and cleanup are explicitly paired. The Rust-side bindings use proper FFI types (`c_int`, `*const c_char`) and include null pointer safety markers.

This builds on the foundation established in earlier patches, particularly the symbol visibility management and initialization refactoring. The changes are focused on `contrib/libgit-sys/` with corresponding updates to `public_symbol_export.[ch]` and Rust bindings in `src/lib.rs`. No tests are added here since the functionality will be exercised through higher-level Rust APIs in subsequent patches.

The patch with Calvin Wan addresses Phillip Wood's earlier feedback about memory management patterns, using conventional pointer-freeing semantics in `libgit_configset_free()`. This completes the config API exposure needed for building idiomatic Rust wrappers while maintaining proper FFI safety boundaries.
