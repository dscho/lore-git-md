Memory leak fix in Scalar's clone command. This is the second patch in a series addressing memory leaks found via Meson's leak detection that were missed by Makefile builds. Patrick Steinhardt fixes a case where `remote_default_branch()`'s weren't being freed in Scalar's clone operation, with the leak showing up in test t9211 under leak sanitization.

The fix introduces a new `branch_to_free` variable to properly track and free the allocated branch name, since the existing `branch` variable might point to either allocated memory or a string constant. The change is minimal (4 lines modified) and follows the established pattern of using `FREE_AND_NULL` for cleanup.

This appears to be a straightforward correctness fix for resource management in Scalar's clone operation. The patch builds on the thread's theme of Meson catching leaks that Makefile builds miss, though this particular case was found via test t9211 rather than the Unix socket case from patch 1. The change is small, well-explained, and unlikely to be controversial.
