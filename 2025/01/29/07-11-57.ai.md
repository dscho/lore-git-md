Build system optimization patch in Patrick Steinhardt's Meson refactoring series. This fourth patch addresses unnecessary libcurl linking in the build configuration.

The change removes libcurl from the global `libgit_dependencies` variable where it was being linked into all executables, and instead adds it only to the specific executables that need it: the HTTP/HTTPS/FTP remote helpers, HTTP fetch/push utilities, and IMAP send (when configured to use curl). The patch introduces a new `imap_send_dependencies` variable to handle the conditional curl linking for IMAP send.

This continues the series' theme of build system simplifications by eliminating unnecessary library linkages. The change is mechanical but meaningful - it reduces the dependency graph for most Git executables while maintaining all required functionality. The patch follows the same careful approach seen in earlier parts of the series, with clear scope and no behavior changes beyond the intended build optimization.

Key technical details:
- Removes `libgit_dependencies += curl` line
- Adds explicit `curl` to HTTP/FTP/IMAP-related executables
- Introduces `imap_send_dependencies` for conditional curl linking
- Affects `git-remote-http`, `git-http-fetch`, `git-http-push`, and their aliases
- Maintains same functionality while reducing unnecessary linkages

The change is straightforward and unlikely to be controversial, though reviewers may want to verify no edge cases were missed in the executable dependency declarations. This patch appears to be a clear improvement that aligns with the series' goals of build system cleanup.
