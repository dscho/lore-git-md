This is a refactoring patch in Patrick Steinhardt's Meson build system cleanup series (patch 10/11). It addresses a variable naming collision where the `git` variable was being overwritten in multiple contexts - first to store the external Git executable path, then to store the built Git executable, and again in the documentation build configuration. The patch renames the built executable variable to `git_builtin` to avoid this collision, allowing removal of a redundant `find_program('git')` call in the documentation build configuration.

The change is mechanical but meaningful, eliminating a subtle naming conflict that could cause confusion in the build system. It touches two files: the main meson.build where the executable declaration is modified, and Documentation/meson.build where the now-unnecessary Git program resolution is removed. The patch maintains all existing functionality while making the build configuration more robust by clearly distinguishing between the external Git tool and the built executable.

This continues the series' pattern of focused, independent build system improvements. The change is low-risk as it doesn't modify any actual build behavior, just variable naming and organization. It follows logically from earlier patches that similarly simplified variable usage and program resolution in the Meson configuration. The patch appears well-scoped and correctly implemented, with no obvious edge cases introduced by the rename.
