This is the final patch in the v9 series implementing Rust bindings for Git's C library, completing the higher-level `libgit` crate that provides idiomatic Rust wrappers around the FFI bindings from `libgit-sys`. The patch establishes the idiomatic Rust interface pattern for the configset API, implementing RAII via `Drop` for automatic resource management and safe FFI encapsulation.

Key technical elements:
- Introduces `ConfigSet` struct wrapping the FFI `libgit_config_set` pointer with proper Rust ownership semantics
- Implements RAII pattern via `Drop` trait to automatically call `libgit_configset_free()`
- Provides safe Rust methods for config operations (`new()`, `add_files()`, `get_int()`, `get_string()`)
- Handles C string conversion and memory management safely (converting `xstrdup()` results to owned Rust strings)
- Includes test coverage for config precedence rules and basic operations
- Updates build system to handle both crates (`libgit-sys` and `libgit-rs`)
- Maintains Rust 1.63+ compatibility with `autocfg` feature detection

The implementation follows Rust FFI best practices by:
- Using opaque types to prevent direct struct access
- Properly converting between C and Rust string types
- Managing memory ownership correctly across FFI boundaries
- Providing panic-safe interfaces that can't leak resources

This completes the series' goal of providing both direct C bindings (`libgit-sys`) and higher-level Rust interfaces (`libgit`), with all technical and stylistic issues resolved through the v9 iterations. The work has maintainer approval and has been validated through real-world use in the JJ VCS.
