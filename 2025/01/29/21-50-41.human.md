This is the first patch of a 4-part series that refactors Git's initialization and exit code to make `libgit.a` more self-contained. The patch splits functionality from `common-main.c` into two new files: `common-exit.c` (containing exit handling and BUG checking) and `common-init.c` (containing initialization code). This allows external users to link against `libgit.a` without pulling in unnecessary dependencies from the main Git executable.

The change is part of the larger effort to create Rust bindings for Git's C library, where having a more modular `libgit.a` is beneficial. The split was previously considered for fuzz testing but is now motivated by the Rust integration needs. The patch appears well-constructed, with clean separation of concerns and proper updates to both Makefile and meson build systems.

This foundational change has already gone through multiple review iterations (now at v9) and has maintainer approval, indicating it's ready for integration. The rest of the series will build on this to expose Git functionality to Rust code.
