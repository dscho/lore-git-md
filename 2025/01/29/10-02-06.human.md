This is a bugfix patch addressing an inconsistency in how `git repack` handles promisor packs (used in partial clones) with respect to keep-pack settings.

Tomáš Trnka points out that `git repack` currently doesn't honor `--keep-pack` or pack `.keep` files when repacking promisor objects, which means settings like `gc.bigPackThreshold` are effectively ignored for these packs. The patch fixes this by modifying `repack_promisor_objects()` to properly pass through the keep-pack logic that exists elsewhere in the repack code.

The change is relatively straightforward - it adds the same keep-pack handling that exists in the main repack path to the promisor-specific path. The author notes this could potentially be improved by centralizing the logic in `prepare_pack_objects()`, but takes the simpler approach for now.

The patch is marked as RFC (Request For Comments) as the author is seeking input on test implementation - specifically whether to add tests in t7700-repack.sh (which already has keep-pack tests) or t0410-partial-clone.sh (which focuses on partial clone behavior). The change looks technically sound but would benefit from test coverage before finalizing.
