This is a bugfix patch addressing an inconsistency in how `git repack` handles promisor packs with respect to keep-pack options. The patch fixes `git repack` to properly honor `--keep-pack` and `.keep` files when repacking promisor objects, which currently bypass these protections. The issue means settings like `gc.bigPackThreshold` are effectively ignored for promisor packs, potentially leading to unwanted repacking of large packs that should be preserved.

The technical change modifies `repack_promisor_objects()` in builtin/repack.c to pass through the same keep-pack logic used elsewhere in repacking. The author adds the `--honor-pack-keep` flag and `--keep-pack` arguments to the pack-objects command when processing promisor packs, mirroring the behavior for regular packs. The change is relatively small (10 lines added, 2 changed) but touches core repacking logic.

The author notes this is an RFC patch and raises questions about test implementation - whether to add tests in t7700-repack.sh (which already has keep-pack tests) or t0410-partial-clone.sh (which focuses on partial clone behavior). The patch appears technically sound but the test coverage question suggests it may need some iteration before being ready to merge. The change seems uncontroversial in principle but the test location discussion may prompt feedback from partial clone/repack experts.
