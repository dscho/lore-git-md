This is a bugfix patch addressing a memory leak in the Unix socket handling code, part of a 2-patch series fixing leaks detected via Meson builds. The patch specifically handles a case in `unix_sockaddr_init()` where a failed `chdir()` operation would leak memory allocated for storing the original directory path. The leak occurs when creating Unix sockets with long pathnames, where Git first tries to `chdir()` to a parent directory to shorten the path.

The leak was detected by Meson builds with leak sanitizer enabled, though the commit notes this wasn't caught by traditional Makefile builds. The fix adds proper cleanup by freeing `ctx->orig_dir` when `chdir()` fails, using the standard `FREE_AND_NULL` pattern. The test case t0301 exposes this issue under leak detection.

The patch is minimal (3 lines added, 1 removed) and well-contained, fixing a clear resource management issue. The commit message provides detailed context including the leak trace and affected codepaths (`credential-cache` operations via `unix_stream_connect`). This appears to be a straightforward correctness fix with no obvious downsides or controversy.
