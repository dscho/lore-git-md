This is a technical follow-up in the reftable decoupling series, specifically addressing a refactoring patch that removes Git-specific helpers. Justin Tobler raises a safety concern about Patrick Steinhardt's patch that replaces `COPY_ARRAY()` with direct `memcpy()` in the reftable record handling code.

The original patch (v2 04/20) was part of the larger effort to make reftable independent of Git's core infrastructure by removing dependencies on Git-specific utilities. Justin points out that while the change achieves the goal of reducing Git dependencies, it might lose the overflow protection that `COPY_ARRAY()` provides through its use of `st_mult()`.

This is a focused technical question about whether the direct `memcpy()` approach needs additional safeguards for the size calculation, particularly regarding potential integer overflow when multiplying the array element size by the element count. The thread context shows this series has otherwise reached consensus, so this appears to be one of the final safety checks before full integration.
