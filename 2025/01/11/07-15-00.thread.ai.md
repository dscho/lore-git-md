Security enhancement proposal for credential handling in URLs, building on commit 6dcbdc0d66 which originally added the `transfer.credentialsInUrl` configuration with "allow" default. Proposal suggests changing default to "warn" to emit redacted warnings when credentials appear in plaintext (e.g., "https://user:<redacted>@host"), nudging users toward credential helpers while maintaining backward compatibility via explicit `fetch.credentialsInUrl=ignore` override. Warning message format already implemented to show URL patterns without exposing actual secrets. Change framed as security hardening measure that was anticipated in original implementation, with potential for whether "warn" provides sufficient value to justify default change being open for discussion.
