Feature patch adding OAuth bearer authentication support to `git send-email`. 

This patch implements SMTP bearer authentication (OAUTHBEARER and XOAUTH2) in `git-send-email.perl`, working around limitations of Perl's Authen::SASL module which doesn't support these authentication types. The implementation follows RFC standards (5801 and 7628) for the authentication protocol and includes proper error handling.

The change enables `git send-email` to work with OAuth2-protected email services like Gmail and Office 365 when configured with the appropriate credentials and settings. The patch includes example configurations for both services, showing how to set up the SMTP connection with TLS encryption and OAuth authentication.

The implementation appears thorough, with careful attention to the protocol specifications and security requirements (enforcing TLS for bearer auth). The code includes new helper functions to generate the proper authentication strings and handles both success and failure cases according to the RFCs. One minor issue noted is an uninitialized variable warning that should be addressed.

This would be particularly useful for developers who need to send patches from corporate or Google accounts that require OAuth authentication, filling a gap in Git's email functionality. The patch references an external credential helper (git-credential-oauth) that would need to be installed separately to provide the OAuth tokens.
