This is a feature patch adding SMTP bearer authentication support to `git send-email`. The patch implements direct handling of OAUTHBEARER and XOAUTH2 authentication mechanisms since they aren't supported by Perl's Authen::SASL module. The implementation includes new helper functions to generate the proper authentication strings following RFCs 5801 and 7628, with specific handling for Gmail and Office 365 configurations.

The patch adds two new string generation functions (`generate_oauthbearer_string` and `generate_xoauth2_string`) that format the authentication payloads according to the respective protocols. A new `smtp_bearer_auth` function handles the actual SMTP AUTH command transmission, including TLS requirement enforcement and proper error handling with dummy requests on failure as specified in RFC 7628.

The commit message provides clear configuration examples for both Gmail and Office 365, showing how to use this with the git-credential-oauth helper. The implementation appears thorough, with proper attention to protocol requirements and error cases. The diff shows one minor issue with uninitialized variable warnings that should be addressed, but the core functionality looks solid.

This patch would enable Git users to use modern OAuth-based authentication with major email providers when sending patches via `git send-email`, filling a current gap in the Perl implementation's SASL support. The RFC references and protocol-specific handling suggest careful attention to standards compliance.
