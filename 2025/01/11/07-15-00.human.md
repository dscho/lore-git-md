Security enhancement proposal for credential handling in URLs.

This email proposes changing the default behavior of `transfer.credentialsInUrl` from "allow" to "warn", which would make Git issue warnings when it detects credentials embedded in remote URLs. The author cites security concerns with plaintext credentials in URLs, which can be accidentally exposed through logs or other mechanisms. The warning would help nudge users toward more secure alternatives like credential helpers.

The patch references a prior commit (6dcbdc0d661) that originally introduced this configuration option with an "allow" default, while leaving open the possibility of changing to "warn" later. The current proposal follows up on that suggestion, noting that users who still need this pattern could explicitly set `fetch.credentialsInUrl=ignore` to suppress warnings.

This appears to be a well-motivated security improvement that aligns with Git's general direction toward better credential handling. The change is relatively low-risk since it only adds warnings rather than changing behavior, and the commit message clearly documents the rationale and alternatives. The proposal is framed as a question to the list to gauge community support before implementation.
