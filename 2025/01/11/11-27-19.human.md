Feature/bugfix for `help.autocorrect` config handling. This v3 patch implements the consensus from the technical discussion, restructuring the config parsing to properly handle boolean values while maintaining backward compatibility.

The patch addresses user confusion where `help.autocorrect=1` was previously interpreted as a 0.1 second delay rather than immediate execution. It now treats `1`, `true`, `on`, and `yes` as immediate execution, while `false`, `off`, `no`, and `never` suppress suggestions entirely. Numeric values ≥2 still specify delay times in deciseconds.

Key changes from v2 include splitting the parsing logic into a dedicated `parse_autocorrect()` function and adjusting false boolean values to map to `AUTOCORRECT_NEVER` rather than 0 (meaning they now suppress suggestions rather than just preventing execution). The documentation has been updated to clearly show all valid values and their effects.

The implementation follows Junio Hamano's suggested approach and incorporates feedback about bare boolean handling from Jeff King. This appears to be the final iteration addressing all technical concerns raised in the thread, with clean separation of parsing logic and comprehensive documentation updates.
