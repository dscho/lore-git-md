Regression in bare repository mirror behavior introduced in Git 2.48.0 (commit b1f713f722) affecting multi-remote setups, where HEAD symref handling breaks when cloning with `--mirror` and adding/fetching secondary remotes. Core symptoms: (1) HEAD incorrectly overwritten to point to non-existent branches, and (2) failure to properly set refs/remotes/mariadb/HEAD, causing `git describe` failures. Analysis confirmed this only affects bare repositories with mixed mirror/non-mirror remotes.

Bence Ferdinandy's proposed fix modifies `set_head()` logic in builtin/fetch.c with these technical changes:
- Adds `mirror` parameter to `set_head()`
- Introduces `baremirror` condition checking both repo type and remote status
- Only overwrites HEAD for true mirrors while properly setting remote-specific HEAD symrefs otherwise
- Includes two new test cases in t5505-remote.sh and t5510-fetch.sh verifying:
  1. Non-mirror fetches don't interfere with existing HEAD in bare repos
  2. Proper remote HEAD handling in bare repositories with mixed remotes

Junio Hamano has reviewed and queued the solution, confirming the technical approach while correcting the commit message attribution ordering (placing Reported-by before Signed-off-by) as noted by Eric Sunshine. The 7-line change in `builtin/fetch.c` maintains architectural boundaries with conditionals preserving existing mirror cases while fixing non-mirror behavior in bare repositories. The test coverage in t5505-remote.sh and t5510-fetch.sh verifies the specific failure modes (HEAD overwrite prevention and proper remote HEAD creation).
