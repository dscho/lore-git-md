Regression in bare repository mirror behavior introduced in Git 2.48.0 (commit b1f713f722) affecting multi-remote setups, where HEAD symref handling breaks when cloning with `--mirror` and adding/fetching secondary remotes. Core symptoms: (1) HEAD incorrectly overwritten to point to non-existent branches (e.g., mariadb-4.x instead of preserving original 4.x), and (2) failure to properly set refs/remotes/mariadb/HEAD, causing `git describe` failures. Analysis confirmed this only affects bare repositories with mixed mirror/non-mirror remotes.

Bence Ferdinandy's proposed fix modifies `set_head()` logic in builtin/fetch.c with these technical changes:
- Adds `mirror` parameter to `set_head()`
- Introduces `baremirror` condition checking both repo type and remote status
- Only overwrites HEAD for true mirrors while properly setting remote-specific HEAD symrefs otherwise
- Includes two new test cases in t5505-remote.sh and t5510-fetch.sh verifying:
  1. Non-mirror fetches don't interfere with existing HEAD in bare repos
  2. Proper remote HEAD handling in bare repositories with mixed remotes

Junio Hamano has reviewed the solution, confirming the technical approach looks sensible while requesting:
1. Commit message attribution ordering correction (Reported-by before Signed-off-by)
2. Verification from original reporter Christian Hesse that the fix resolves the issue

The maintainer's input reinforces the architectural boundaries, noting non-bare mirror setups would only work in limited scenarios (static checkouts/detached HEADs) where HEAD overwrites during fetch would be problematic regardless. The 7-line focused change maintains existing mirror behavior while fixing the non-mirror case, with test coverage demonstrating proper HEAD management in multi-remote bare repositories.
