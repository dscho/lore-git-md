Security enhancement proposal for credential handling in URLs.

This email proposes changing the default behavior of `transfer.credentialsInUrl` from "allow" to "warn", which would make Git emit warnings when credentials appear in plaintext in remote URLs. The motivation is security hardening - nudging users toward safer credential storage methods like credential helpers rather than embedding secrets in URLs where they might be accidentally. The warning would redact the actual credentials while still showing the problematic URL pattern.

The change builds on commit 6dcbdc0d66 which originally introduced the configuration option with an "allow" default, explicitly leaving open the possibility of switching to "warn" later. The warning message format is already implemented and would show as in the example, replacing actual credentials with "<redacted>". The proposal acknowledges some users may still need to use URL credentials and suggests they could explicitly set `fetch.credentialsInUrl=ignore` to suppress warnings.

Key technical details include:
- Configuration option: `transfer.credentialsInUrl` (current default "allow", proposed default "warn")
- Warning message format shows URL with credentials redacted
- Related setting `fetch.credentialsInUrl` mentioned as escape hatch
- Original implementation commit referenced (6dcbdc0d66)

This appears to be a well-motivated security hardening measure that maintains backward compatibility while encouraging better practices. The change seems non-controversial as it was anticipated in the original implementation, though some discussion may arise around whether "warn" provides enough value to justify changing defaults.
