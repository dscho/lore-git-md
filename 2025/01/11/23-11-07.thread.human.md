Jan Palus has provided additional technical context about the printf formatting issue in Git's blame test suite, clarifying that the problem stems from coreutils' printf implementation (which mksh uses) explicitly rejecting "0" as a flag for string conversions. This isn't just a shell limitation but a deliberate restriction in a widely-used printf implementation. The explanation distinguishes between the ambiguous `%0.s` syntax and the clearer `%.0s` form, justifying why the fixed-width `%${N}s` solution is more portable.

The technical solution itself - replacing non-portable `%0.s` with `%11s` or similar in t8002-blame.sh and t8003-blame-cases.sh - remains unchanged and has consensus. Patrick Steinhardt had already confirmed the approach matches portable usage in other tests, and Junio Hamano's only remaining request was for commit message refinements to accurately describe whether this was a general portability concern or mksh-specific.
