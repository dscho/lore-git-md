This thread addresses a portability fix for Git's blame test suite, specifically modifying t8002-blame.sh and t8003-blame-cases.sh to replace non-portable `printf "%0.s"` sequences with equivalent `printf "%Ns"` syntax (where N is 11 or hexsz) for padding spaces. The changes target test cases verifying blame output formatting with blank boundary commits when using `--abbrev` and `-b` flags.

Jan Palus initially proposed the fix, with Patrick Steinhardt reviewing and confirming the technical approach matches portable usage elsewhere in Git's tests. Junio Hamano raised questions about whether the issue was specific to mksh or a general portability concern, leading to valuable technical clarification: the problem stems from coreutils' printf implementation (which mksh uses) explicitly rejecting "0" as a flag for string conversions, rather than being an mksh limitation. This distinction between `%0.s` (ambiguous) and `%.0s` (clear precision) helped justify the `%${N}s` solution.

The technical solution has consensus and requires no further code changes. Junio has acknowledged this clarification and confirmed the approach is sound.
