This thread discusses a straightforward portability fix for Git's blame test suite to improve compatibility with the mksh shell. The original patch, from Jan Palus, modified two test cases in t8003-blame-corner-cases.sh that verify blame output formatting with blank boundary commits. The key change replaces non-portable `printf "%0.s "` sequences with equivalent `printf "%Ns"` syntax (where N is the desired padding length) to generate spaces for test expectations, matching existing portable usage seen elsewhere in the test suite.

Patrick Steinhardt provided review feedback focusing on improving the commit message format and subject line, but raised no technical objections to the change itself. The modification is minimal (just 2 lines changed) and specifically targets shell portability without altering the test's verification of blame's --abbrev and -b flag behavior. The discussion shows consensus that this is a clean solution, as similar printf usage already exists in t5300. With the minor documentation suggestions addressed, this appears ready to be picked up as a simple but worthwhile portability improvement to tests originally added in commit e7fb2ca945.
