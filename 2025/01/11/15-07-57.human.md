This is a question about Git's configuration file handling and potential security implications.

Randall Becker reports that Git fails when system-wide (`/usr/local/etc/gitconfig`) or user (`~/.gitconfig`) configuration files don't exist, rather than creating them automatically. They've been advising their team to manually create these files with proper permissions, suspecting that auto-creation might introduce security vulnerabilities (CVEs).

The email raises two key points: whether this failure behavior is intentional in Git, and whether the security concerns about auto-creation are valid. The author comes from a background of long-term UNIX and NonStop system development, suggesting they're considering this from both a usability and security perspective.

This appears to be a genuine question rather than a bug report, seeking clarification from the Git community about the design decisions around config file handling. The security angle makes it potentially interesting for maintainers who think about safe defaults and attack surfaces.
