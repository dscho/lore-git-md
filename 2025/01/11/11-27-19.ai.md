This is a v3 patch in the `help.autocorrect` configuration improvement thread, implementing boolean string value handling as discussed in previous rounds. The patch refactors the parsing logic into a new `parse_autocorrect()` function and changes how false boolean values are interpreted.

Key technical changes from v2:
- Extracted core parsing logic into `parse_autocorrect()` helper function
- Now maps false boolean values ("false", "off", "no") to AUTOCORRECT_NEVER instead of 0 (meaning they won't show guesses at all)
- Maintains backward compatibility for numeric values (1 = immediate, ≥2 = decisecond delay)
- Updates documentation to clearly show all accepted string values and their equivalents

The implementation follows the technical consensus reached in the thread regarding boolean handling, using `git_parse_maybe_bool_text()` for string parsing while preserving the numeric delay behavior. The documentation now groups equivalent values together ("true"/"on"/"yes" with "immediate", "false"/"off"/"no" with "never") for clarity.

This version addresses all previous feedback:
- Junio Hamano's suggestion to properly handle boolean strings
- Jeff King's clarification about bare boolean syntax (handled via `git_parse_maybe_bool_text())
- Documentation improvements from Kristoffer Haugsbakk and Yongmin Hong

The patch appears ready for final review, having incorporated all technical feedback while maintaining backward compatibility with existing configurations. The only remaining question might be whether the change in false boolean behavior (from showing guesses to hiding them) warrants additional discussion, though this aligns with the "never" semantics.
