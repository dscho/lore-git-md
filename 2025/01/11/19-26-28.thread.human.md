This thread addresses a regression in Git 2.48.0 that caused incorrect HEAD handling in bare repositories with mixed mirror/non-mirror remotes. The issue manifests when cloning with `--mirror` and then adding secondary remotes, leading to HEAD pointing to non-existent branches and failing to properly set remote-specific HEAD symrefs.

Bence Ferdinandy proposed a fix modifying `set_head()` in builtin/fetch.c to properly distinguish between mirror and non-mirror cases in bare repositories. The 7-line change adds mirror/bare checks while preserving existing behavior for true mirrors. Two new test cases verify the fix prevents HEAD corruption and ensures proper remote HEAD creation.

Junio Hamano reviewed the technical approach positively but noted a commit message formatting issue (attribution ordering) which he has since corrected when queuing the patch. Eric Sunshine's follow-up confirms the project's attention to proper attribution practices, while noting the technical solution remains sound. The only remaining item is confirmation from the original reporter Christian Hesse that the fix resolves their real-world case, though the included tests already verify the specific failure modes. This appears to be a small but important fix that will likely be included in an upcoming release.
