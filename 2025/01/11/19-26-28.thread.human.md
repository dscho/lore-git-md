This thread reports a regression in Git 2.48.0 affecting bare repositories with multiple remotes. The issue occurs when cloning with `--mirror`, adding a second remote, and then trying to use `git describe` on a branch from that remote - the command fails with "fatal: Not a valid object name HEAD". The reporter provides clear reproduction steps using galera.git and mariadb repositories and suspects commit 5f212684abb6 (from the 2.48.0) may be the culprit. While the exact mechanism isn't yet understood, this appears to be a legitimate regression affecting users maintaining mirrored repositories with multiple remotes. The report contains sufficient detail for maintainers to investigate whether this stems from the referenced commit or another issue in bare repository handling.
