This thread discusses a security enhancement to Git's credential handling in URLs. The `transfer.credentialsInUrl` setting currently defaults to "allow," letting users embed credentials in URLs (like `https://user:pass@host`). The proposal suggests changing this to "warn" by default, which would show redacted warnings (e.g., `https://user:<redacted>@host`) to nudge users toward more secure credential helpers while maintaining backward compatibility via an explicit `fetch.credentialsInUrl=ignore` override.

Junio Hamano has no objection to the change but points out an inconsistency: the current implementation only checks `.URL` and not `.pushURL`, which would need to be addressed first. He also agrees with Derrick Stolee that clear instructions should be provided for users who need to disable the warnings. The discussion now centers on these two technical details—expanding the check to push URLs and ensuring proper user guidance—before the default can be changed. There appears to be general support for the security goal, with these implementation gaps being the remaining hurdles.
