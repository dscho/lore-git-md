Bugfix addressing file descriptor double-close in bundle transport, with Junio C Hamano reviewing and queuing Johannes Schindelin's patch. The fix modifies bundle handling to prevent closing the file descriptor both in `unbundle()` and `close_bundle()`, which could cause failures on Windows i686 due to rapid file descriptor reuse.

The patch makes three key changes: (1) adds documentation in `bundle.h` clarifying that `unbundle()` closes the file descriptor, (2) ensures descriptor closure even on bundle verification failure in `bundle.c`, and (3) invalidates the file descriptor in transport data after `unbundle()` to prevent double-closing. The change trades potential rare file descriptor leaks during error cases (which would occur anyway during failures) for preventing hard failures in normal operation.

Junio notes he was able to backport the fix to maint-2.44 with trivial conflicts, though expresses some concern about the file descriptor leak tradeoff mentioned in the commit message. The patch is acknowledged as addressing a long-standing issue dating back to the original 2007 bundle implementation (c7a8a16239), though the problem has rarely manifested until now. The review confirms the patch will be queued for inclusion.
