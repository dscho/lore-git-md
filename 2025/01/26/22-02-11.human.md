Bugfix for HEAD handling in bare repositories with mixed mirror/non-mirror remotes. This is the second patch in a v2 series addressing a regression introduced in Git 2.48.0 that caused incorrect symref behavior when cloning with `--mirror` and adding secondary non-mirror remotes.

The patch modifies `set_head()` in builtin/fetch.c to properly distinguish between mirror and non-mirror remotes in bare repos. The key change is introducing a `baremirror` condition that checks both repository type and remote status before overwriting HEAD. This prevents HEAD from incorrectly pointing to non-existent branches when fetching from regular remotes in a bare repo.

The patch includes two new test cases in t5505-remote.sh and t5510-fetch.sh that verify the fix works as intended. The tests create bare repositories with mixed remote configurations and confirm HEAD remains correct after fetches. The implementation has been refined from v1 based on reviewer feedback, now passing the full remote` struct rather than individual parameters.

This appears to be a well-tested solution to a real regression reported by Christian Hesse, with the fix following Git's typical review process - first validating behavior, then test coverage, and finally code structure. The patch maintains backward compatibility while preventing the problematic HEAD overwrites in mixed remote scenarios.
