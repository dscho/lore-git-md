This thread reports a security vulnerability in Git's worktree handling where ownership validation is incomplete. Antonio Russo discovered that when a worktree's `.git` file points to another repository, Git only verifies ownership of the `.git` file itself, not the target repository. This creates an inconsistency in Git's security model: while User A would be blocked from accessing their own repository if proper ownership checks were enforced, User B can currently access User A's repository through a worktree link, bypassing Git's usual cross-user access protections.

The issue affects Git 2.48.1 and likely earlier versions. Russo suggests two potential solutions - either introducing explicit trust declarations in the `.git` file (with proposed `trust-other-user` syntax) or at minimum documenting this behavior more clearly. The report highlights a significant gap in Git's security model for multi-user systems, where worktree links could potentially be exploited to bypass repository access controls.
