This is a security report about a missing ownership validation in Git's worktree handling. Antonio Russo reports that when a worktree's `.git` file points to another repository, Git only checks ownership of the `.git` file itself, not the referenced repository. This could allow User B to access User A's repository through a worktree link, bypassing Git's usual security checks that prevent cross-user repository access.

The report demonstrates the inconsistency: while User B can access User A's repository this way, User A would be blocked from accessing their own repository if the ownership check were properly enforced. Russo suggests two potential solutions: either require explicit trust declarations in the `.git` file (proposing a `trust-other-user` syntax), or at minimum improve documentation of this behavior.

The issue appears to affect Git 2.48.1 and likely other versions. This is a security-sensitive area of Git's design, as the ownership checks exist precisely to prevent unauthorized access between users on multi-user systems. The report doesn't propose a specific implementation but raises awareness of what appears to be an oversight in the security model for linked worktrees.
