Bugfix for HEAD handling in bare repositories with mixed mirror/non-mirror remotes, addressing a regression introduced in Git 2.48.0. This is the second patch in a v2 series that has already undergone significant review and refinement.

The patch specifically fixes the case where fetching from a non-mirror remote in a bare repository could incorrectly overwrite HEAD to point to non-existent references. The solution introduces a `baremirror` condition that checks both repository type and remote mirror status before modifying HEAD. The key technical change is in `builtin/fetch.c` where the logic now properly handles the combination of bare repositories and non-mirror remotes.

Two new test cases verify the fix:
1. In t5505-remote.sh: Confirms non-mirror fetches don't interfere with existing HEAD in bare repos
2. In t5510-fetch.sh: Validates proper HEAD/remote-HEAD behavior in bare repos with upstream remotes

The implementation has evolved from v1 to v2 with cleaner parameter passing (now using full remote struct) and improved test hygiene (using `test_when_finished` and subshell isolation). The patch maintains the same core behavior while improving code structure, as requested in earlier reviews.

This appears to be a well-tested and carefully considered fix for a real regression affecting users with multi-remote bare repository setups. The changes are focused and the test coverage is thorough, including both the regression scenario and related edge cases. The patch builds on previous community feedback and appears ready for inclusion.
