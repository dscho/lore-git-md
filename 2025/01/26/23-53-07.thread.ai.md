Security vulnerability report regarding worktree ownership validation in Git. Antonio Russo identifies that when a worktree's `.git` file points to another repository, Git only verifies ownership of the `.git` file itself without checking the referenced repository's ownership. This creates a security bypass where User B could access User A's repository through a worktree link, circumventing Git's standard cross-user access protections. The report notes the inconsistency that while this allows unauthorized access, proper enforcement would block legitimate access by the repository owner. Two potential solutions: introducing a `trust-other-user` declaration in `.git` files to explicitly allow cross-user links, or at minimum documenting this behavior more clearly. Affects Git 2.48.1 and likely earlier versions. The issue touches core security mechanisms designed to prevent unauthorized repository access on multi-user systems, representing a significant oversight in worktree security validation. No patch proposed yet, but the report highlights an important gap in the worktree security model that requires addressing either through technical changes or improved documentation.
