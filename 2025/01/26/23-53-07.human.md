Security issue with worktree ownership checks. Antonio Russo reports that Git's "dubious owner" security check (which prevents accessing repositories owned by other users) is only applied to the `.git` file in linked worktrees, not the actual repository. This creates a potential security hole where User B could access User A's repository via a worktree link, bypassing the intended protection.

The current behavior is particularly odd because User A would be blocked from their own repository while User B gets access. Russo suggests either making the trust relationship explicit (with a `trust-other-user` marker) or at least documenting this behavior more clearly.

This appears to be a genuine security oversight in Git's worktree handling. The report is well-articulated and demonstrates a clear understanding of both the technical issue and security implications. The suggested solutions are reasonable starting points for discussion, though the core team may want to consider stricter default behavior given the security context.
