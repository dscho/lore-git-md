This is a bugfix addressing a long-standing file descriptor double-close issue in the bundle transport code, originally introduced in 2007. The patch comes from Johannes Schindelin and is being queued by Junio Hamano after some backporting discussion.

The core issue is that the file descriptor for bundle files was being closed both by `index-pack` (via `start_command()`) and explicitly in `close_bundle()`, which could cause problems on i686 Windows where file descriptors are quickly reused. The fix modifies the behavior to ensure the descriptor is properly closed exactly once, even on verification failures, and documents that `unbundle()` takes ownership of closing the descriptor.

Junio notes this is a relatively straightforward fix that trades potential file descriptor leaks during error cases (which would occur anyway during failures) for preventing hard failures in normal operation. The patch touches `bundle.c`, `bundle.h`, and `transport.c` to implement and document the change. While the bug has existed for nearly two decades without major issues, it was recently observed causing problems specifically on i686 Windows builds.
