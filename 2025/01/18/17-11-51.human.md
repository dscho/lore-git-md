This is part 2 of a 3-part refactoring series that improves memory management in Git's ref-filter subsystem, specifically focusing on the "is-base" functionality used by commands like `for-each-ref`. The patch continues the work from part 1 (which handled ahead-behind calculations) by applying the same architectural pattern to is-base calculations.

The key change moves the storage of commit references from a global string_list in the ref_format struct to per-atom storage in the used_atom struct. This eliminates memory leaks and inconsistencies that could occur when sorting references before formatting them. The patch includes thorough test coverage, adding new tests for is-base behavior when used with `--sort`.

The implementation follows the hybrid model discussed earlier in the thread, where commit references are stored directly in the atom structs rather than being managed separately. This is part of a broader effort to make the ref-filter code more maintainable by reducing cross-component dependencies while maintaining identical external behavior.

The changes are well-contained and follow the pattern established in part 1, suggesting this is a straightforward continuation of the approved approach. The patch has already received positive feedback from Jeff King (who is credited as a helper) and appears ready for review.
