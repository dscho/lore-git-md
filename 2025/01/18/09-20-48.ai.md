Bugfix follow-up addressing read-side alignment issues in sparc64 pack handling. This email continues the discussion of the 3-patch series that fixed SIGBUS crashes during pack operations on sparc64 when compiled with clang.

Jeff King responds to Koakuma's confirmation that while the write-side fixes worked, the read path in `unpack_all()` still crashes due to unaligned access to `hdr->hdr_entries`. He proposes two potential solutions: using `get_be32()` for safe unaligned reads (similar to the `put_be32()` approach used for writes) or ensuring proper buffer alignment through either compiler attributes or a union.

The email includes a concrete diff showing the union approach, which would align the static `buffer` by wrapping it with a `struct pack_header`. This changes all buffer accesses to go through `buffer.bytes` instead of direct `buffer` references, requiring updates throughout `unpack-objects.c` to maintain functionality. The changes affect hash computation, memory movement, I/O operations, and pack header handling while preserving the existing behavior.

Key technical points include the need to update all `sizeof(buffer)` references to `sizeof(buffer.bytes)`, careful handling of the hash context updates, and maintaining the existing pack header parsing logic while working through the new union structure. The solution demonstrates awareness of both the immediate alignment issue and the broader implications for the codebase's memory access patterns.

This follow-up highlights that while the initial series fixed the write-side issues, the read path requires similar attention, with multiple valid technical approaches available. The discussion continues to focus on sparc64-specific alignment requirements while maintaining cross-platform compatibility.
