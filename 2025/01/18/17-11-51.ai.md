This is part 2 of a 3-part refactoring series moving state management in ref-filter from format-wide storage to per-atom structs, specifically targeting the "is-base" functionality. The patch follows the same pattern as part 1 (which handled ahead-behind calculations), completing the transition to the hybrid model discussed in the thread.

Key technical changes:
- Removes the `is_base_tips` string list from `struct ref_format`
- Adds `name` and `commit` fields to the `base` struct in `used_atom`
- Updates `is_base_atom_parser()` to store references directly in the atom
- Modifies `filter_is_base()` to scan the `used_atom` array rather than the removed string list
- Adjusts `can_do_iterative_format()` to check for `ATOM_ISBASE` in used atoms
- Adds new tests for `--sort=is-base` behavior
- Includes memory management for the new atom fields in `ref_array_clear()`

The changes maintain identical external behavior while improving memory management and reducing cross-component dependencies. The implementation follows the same pattern as the earlier ahead-behind changes, demonstrating the consistent application of the hybrid model across ref-filter's stateful operations.

This continues the thread's progression toward explicit state management, with part 3 expected to complete the series. The patch includes thorough coverage of the changes with new test cases verifying the sorting behavior with is-base atoms.
