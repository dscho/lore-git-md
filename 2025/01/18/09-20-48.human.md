Bugfix follow-up for sparc64 SIGBUS crash in `unpack-objects`. This is a continuation of the thread addressing alignment issues in Git's pack handling on sparc64 systems.

Jeff King responds to Koakuma's confirmation that the read path in `unpack_all()` still crashes due to unaligned access to `hdr->hdr_entries`. While the previous patches fixed the write-side alignment issues using `put_be32()`, this email explores two potential solutions for the read path: using `get_be32()` or ensuring proper buffer alignment from the start.

The proposed solution uses a union to guarantee alignment of the static buffer while maintaining the existing buffer interface. The diff shows how this would work in `builtin/unpack-objects.c`, replacing the raw `unsigned char` buffer with a union containing both a `pack_header` and byte array. This approach would prevent both read and write alignment issues while requiring careful handling of buffer access throughout the file.

The email highlights the trade-offs between different solutions and shows awareness of the broader implications (like sizeof() usage and pointer arithmetic). This continues the thread's pattern of thorough, platform-aware fixes for a tricky memory alignment issue.
