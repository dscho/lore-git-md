Bugfix follow-up addressing static analysis warning in the sparc64 alignment fix series.

Junio C Hamano points out that while Jeff King's patch series correctly uses `put_be32()` to fix sparc64 alignment issues, it triggers sparse warnings about constant truncation when writing the PACK_SIGNATURE (0x5041434b). The warnings occur because sparse flags the implicit truncation of the original `put_be32()` implementation, even though compilers would generate identical code. 

The email includes a proposed fix that adds explicit masking with `& 0xff` in `compat/bswap.h` for both `put_be32()` and `put_be64()`, which silences the warnings while maintaining the same functionality. Hamano notes this is somewhat unsatisfying since the masking is redundant for actual compilers, and points out the inconsistency that similar usage in fsmonitor.c doesn't trigger warnings only because it uses a smaller constant value.

This is a refinement to the earlier alignment fixes, addressing a code quality issue (static analysis warnings) rather than changing the core solution. The change affects the low-level byte swapping utilities used throughout Git, though the behavioral impact is identical to the previous version. The discussion highlights an interesting edge case in sparse's constant propagation analysis versus real compiler behavior.
