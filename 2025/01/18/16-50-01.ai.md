Bugfix follow-up discussing alignment solutions for sparc64 pack handling. This email from Koakuma responds to Jeff King's proposed union-based solution for the SIGBUS crash in `unpack-objects` by confirming it works and suggesting an alternative approach using alignment attributes.

The discussion focuses on two technical approaches to ensure proper memory alignment when accessing `struct pack_header`:
1. Jeff's union-based solution that combines the header struct with a byte array
2. Koakuma's attribute-based approach that explicitly aligns the buffer

Key technical details:
- Both solutions address the same core issue of unaligned memory access on sparc64
- The union approach requires widespread changes to replace `buffer` references with `buffer.bytes`
- The attribute approach uses `__attribute__((aligned(16)))` but hardcodes alignment
- Koakuma notes the attribute solution could be improved by querying the actual alignment needs of `struct pack_header`

The email confirms Jeff's union solution works while suggesting the attribute approach might be simpler, though both would require careful implementation. This continues the ongoing discussion about the best way to handle alignment-sensitive memory operations in Git's packfile handling code, particularly for platforms like sparc64 with strict alignment requirements.
