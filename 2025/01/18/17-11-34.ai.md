This is a refactoring patch in the ongoing ref-filter memory management series, specifically addressing ahead-behind calculations. It's part 1 of 3 in René Scharfe's v2 series implementing the hybrid model where commit references are stored directly in atom structs rather than in a format-wide string list.

The patch moves ahead-behind base commit storage from the `ref_format` struct's string list into individual `used_atom` entries. This fixes several issues:
- Memory leaks when sorting options are parsed before format strings (as in `git branch`)
- Inconsistent behavior when sort keys aren't included in format strings
- The inability to share committish references between format and sorting operations

Key technical details:
- Adds new `base` struct field to `used_atom` union for commit storage
- Removes `bases` string list from `ref_format` struct
- Updates `filter_ahead_behind()` to scan `used_atom` array for bases
- Modifies `can_do_iterative_format()` to check for ahead-behind atoms
- Includes new tests for `--sort=ahead-behind` behavior

The changes maintain identical external behavior while improving internal consistency and fixing edge cases. This represents concrete progress on the thread's goal of moving state management into atom structs, following the hybrid approach that gained consensus in earlier discussion. The patch builds on Jeff King's earlier work and addresses Ross Goldberg's reported issues.
