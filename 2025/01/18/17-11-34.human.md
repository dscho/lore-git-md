This is a refactoring patch that improves memory management in Git's ref-filter subsystem, specifically addressing ahead-behind calculations. It's part of an ongoing effort to clean up state sharing between ref-filter commands (branch, for-each-ref, etc.).

The patch moves the storage of commit references for ahead-behind calculations from a format-wide string_list to per-atom structs in used_atom. This fixes several issues:
1. Memory leaks when sorting options are parsed before format strings
2. Inconsistent behavior between commands that parse format strings in different orders
3. Missing commit references when sort keys aren't included in format strings

The changes are focused in ref-filter.c and affect how ahead-behind data flows through the system. The implementation maintains all existing functionality while making the code more robust. Test cases are added to verify the new sorting behavior works correctly.
