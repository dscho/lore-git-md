This thread discusses a proposal for a new plugin system called GpluginLoader that would enable loading C/C++ plugins into Git in a platform-independent way. The initial email introduces API files (git-plugin-api.[ch]) that provide functions for plugins to interact with Git repositories, including accessing metadata like README files and profiles. However, the proposal is at an early stage - it's currently hosted as an external GitHub project rather than being submitted as a patch series for Git itself.

The suggestion raises several open questions that would need to be addressed before such a system could be considered for inclusion in Git. The proposal lacks details about key aspects like security implications, version compatibility, performance overhead, and how it would integrate with Git's existing codebase and build system. While the motivation mentions addressing "differences between community members and developers," it doesn't specify what problems this would solve that can't already be handled through Git's existing extension mechanisms like hooks or subcommands. Given the early stage of the proposal and the significant architectural questions it raises, this would likely need substantial design discussion and refinement before being seriously considered for the core Git project.
