This thread examines how to handle file unlinking behavior differences between POSIX and Windows systems for the reftable backend, with architectural tensions between platform-layer changes versus reftable-specific solutions. Patrick Steinhardt initially proposed modifying `mingw_unlink()` with a new flag to handle Windows' restrictions on unlinking open files, but Johannes Sixt questioned whether this belonged in the platform layer. Christian Reich later confirmed the approach works but noted merge conflicts with Git for Windows' current implementation.

Johannes Sixt has now proposed two technical alternatives: using Windows' `CreateFileW()` with delete-on-close flags for more POSIX-like behavior, or accepting that Git doesn't strictly need POSIX unlink semantics since reftable can tolerate failed deletions. These suggestions aim to address both the technical requirements and architectural concerns while maintaining compatibility with JGit. The discussion remains open, with the core tension being whether to modify platform behavior or adapt the reftable implementation to Windows' constraints. No new patches have been submitted yet to implement these alternatives, leaving the path forward still under consideration.
