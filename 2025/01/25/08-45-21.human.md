This is a follow-up in the Windows reftable compatibility thread, where Christian Reich reports successful testing of Patrick Steinhardt's patch to modify Windows file unlinking behavior for reftable operations. The patch aims to prevent annoying user prompts when reftable tries to delete files that are still open (a Windows limitation that differs from POSIX behavior).

Christian confirms the patch works as intended in his testing, but notes two merge conflicts that would need resolution before it could land in git-for-windows: (1) the current `mingw_unlink()` implementation in git-for-windows differs from the patched version, and (2) there's another call to `mingw_unlink()` in `mingw_rename()` that would need consideration. These observations suggest the patch may need some adaptation to integrate cleanly with the git-for-windows codebase.

The email doesn't propose any technical changes - it's providing valuable real-world testing feedback and pointing out integration challenges. The core solution (using a `MINGW_DONT_HANDLE_IN_USE_ERROR` flag to suppress retry prompts for reftable operations) appears sound, but the path to mainline inclusion may require additional work to handle these Windows-specific codebase differences.
