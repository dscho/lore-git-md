Platform compatibility patch addressing Windows-specific behavior in the reftable backend. The issue stems from Windows' non-POSIX behavior where files cannot be unlinked while open, unlike on Unix systems. Git's current Windows compatibility layer (`mingw_unlink()`) handles this by retrying with delays and prompting the user, which becomes problematic in the reftable context where failed unlinks are expected and handled gracefully by the reftable stack cleanup mechanism.

The patch introduces a preprocessor flag `MINGW_DONT_HANDLE_IN_USE_ERROR` that disables the interactive retry behavior specifically for the reftable library. This is done by modifying the `unlink` macro in mingw.h to pass through a flag to `mingw_unlink()`, and setting the flag in reftable's system.h. The change prevents annoying user prompts during reftable operations while maintaining the existing retry logic for other parts of Git.

Key technical details:
- Modifies `mingw_unlink()` to accept a `handle_in_use_error` parameter
- Adds conditional macro definition in mingw.h based on the new flag
- Sets `MINGW_DONT_HANDLE_IN_USE_ERROR` in reftable/system.h
- Affects only reftable operations while preserving behavior elsewhere

The patch cleanly addresses a specific Windows usability issue without broader impacts, and includes a clear explanation of the problem scenario and solution rationale. The change appears well-scoped and maintains the existing safety mechanisms for non-reftable code paths.
