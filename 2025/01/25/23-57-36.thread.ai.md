Bugfix addressing file descriptor double-close issue in bundle transport code, present since original 2007 implementation (c7a8a16239). Problem occurs when file descriptor is closed both by `index-pack` (via `start_command()`) and explicitly in `close_bundle()`, potentially causing failures on i686 Windows with rapid file descriptor reuse. Patch by Johannes Schindelin modifies `bundle.c`, `bundle.h`, and `transport.c` to: (1) document in `bundle.h` that `unbundle()` closes the file descriptor, (2) ensure descriptor closure even on bundle verification failure in `bundle.c`, and (3) invalidate file descriptor in transport data post-`unbundle()` to prevent double-closing. Change trades potential file descriptor leaks during error cases (which would occur anyway during failures) for preventing hard failures in normal operation, particularly on Windows i686. Junio C Hamano reviewed and queued the patch, noting successful backport to maint-2.44 with trivial conflicts while expressing minor concern about the leak tradeoff. Patch acknowledged as addressing a long-standing but rarely manifested issue, with maintainer approval for inclusion. The fix is targeted and does not fully resolve file descriptor ownership in command execution plumbing.
