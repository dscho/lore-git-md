Bugfix targeting Windows platform compatibility in the reftable backend. Patrick Steinhardt addresses an issue where Git's Windows-specific unlink() wrapper causes unnecessary user prompts when deleting stale reftable files. On Windows, unlike POSIX systems, files cannot be deleted while open by another process, so Git normally retries with delays and asks the user what to do. However, the reftable library already handles this case gracefully - it expects unlink() to sometimes fail and has its own cleanup mechanism via `reftable_stack_clean()`.

The patch adds a preprocessor flag `MINGW_DONT_HANDLE_IN_USE_ERROR` that disables the retry-and-prompt behavior specifically for the reftable code. This prevents confusing multiple prompts when Git tries to delete the same file at different stages of reftable operations. The change is contained to the reftable subsystem by setting the flag in reftable/system.h, which only affects internal reftable code. The fix is well-motivated by a real user report and cleanly solves the problem without broader impacts.
