Platform compatibility discussion in the reftable/Windows thread, with Johannes Sixt proposing an alternative approach to handling file-in-use errors during unlink operations. This email responds to Patrick Steinhardt's justification for the current approach (JGit compatibility requirements) while suggesting two alternative solutions.

The first technical alternative involves using Windows' `CreateFileW()` with `DELETE` access and `FILE_FLAG_DELETE_ON_CLOSE` flags instead of direct `_wunlink()` calls, which would provide similar-but-not-identical semantics to POSIX behavior for files Git itself opens. The second, more architectural suggestion questions whether Git should depend on POSIX unlink behavior at all, noting that the reftable library can tolerate failed deletions and that such failures are rare in current Git usage.

Key technical points raised:
- Direct reference to Windows API functions (`CreateFileW`, `FILE_FLAG_DELETE_ON_CLOSE`)
- Distinction between POSIX-like behavior and actual POSIX compliance
- Observation about current Git's limited dependence on POSIX unlink semantics
- Reftable's ability to function with failed deletions

This moves the discussion forward by offering concrete alternatives to the platform-layer modification approach while acknowledging the JGit compatibility constraints Patrick raised earlier. The suggestions appear aimed at finding a solution that satisfies both the technical requirements and architectural preferences, though they would require implementation and testing to verify their effectiveness.
