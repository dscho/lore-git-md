Bugfix for a long-standing file descriptor double-close issue in bundle handling.

This patch addresses a subtle bug in Git's bundle transport that has existed since its introduction in 2007. The issue occurs when fetching from a bundle file - the file descriptor gets closed twice: first by the `index-pack` process and then again by `close_bundle()`. While this hasn't caused widespread problems, Johannes Schindelin encountered a failure case on i686 Git for Windows where the reused file descriptor leads to mmap failures during subsequent operations.

The fix is straightforward: invalidate the file descriptor after `unbundle()` closes it, preventing the second close attempt. The patch also improves documentation to clarify that `unbundle()` takes ownership of closing the file descriptor. While there's a theoretical file descriptor leak in rare error cases, this is deemed an acceptable tradeoff compared to the current hard failure scenario.

The change touches three files with minimal modifications, focusing just on the double-close issue without attempting a broader redesign of file descriptor handling. This appears to be a well-scoped fix for a real problem, though the commit message notes it deviates slightly from Git's usual practice of applying fixes on top of the original buggy commit.
