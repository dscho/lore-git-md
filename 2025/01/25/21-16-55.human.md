Response from a Git contributor regarding the GitPanel proposal. Brian m. carlson acknowledges the project's potential usefulness but explains why it wouldn't be a good fit for the core Git project. The main concern is that Git aims to be forge-agnostic, while GitPanel's features (profile pictures, pull requests) are GitHub-specific. They suggest the project could be more success as a standalone tool supporting multiple forges, mentioning tig as an existing Git-related TUI example. The response is constructive, offering specific advice about making the tool more generally useful by supporting multiple forge types, including self-hosted instances. While not rejecting the idea outright, the email makes clear that Git's architecture and philosophy prioritize neutrality across code hosting platforms.
