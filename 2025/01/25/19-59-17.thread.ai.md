Thread summary: Initial proposal for "GitPanel" - a new terminal user interface for Git/GitHub account management, from devtracer following prior GitHub discussion (PR #1877) with Johannes Schindelin. The concept includes three components: (1) ASCII-styled GitHub profile display (Neofetch-style), (2) credential management, and (3) GitHub project access via TUI. Proposed as a new `gitpanel` command that would complement existing tooling without replacing current commands. brian m. carlson has responded with architectural concerns, arguing against inclusion in core Git due to its GitHub-specific nature conflicting with Git's forge-agnostic philosophy. They note profile pictures and pull requests are GitHub concepts rather than Git concepts, suggesting the project might be more appropriate as a standalone tool supporting multiple forges. The response points to tig as an example of a related TUI project while maintaining Git's architectural boundaries regarding forge integration. Key technical distinctions include Git's core functionality versus forge-specific features, with a suggestion to abstract forge interactions for multi-platform support. This effectively closes consideration for GitPanel as a core feature while leaving room for external development. The thread now has clear architectural guidance against GitHub-specific tooling in core Git, with the remaining open question being whether devtracer will pivot to a multi-forge approach or develop externally.
