This is a bugfix addressing a long-standing file descriptor double-close issue in the bundle transport code. The problem dates back to the original bundle implementation in 2007, where a file descriptor would be closed both by `index-pack` (via `start_command()`) and then again explicitly in `close_bundle()`. While this hasn't caused widespread issues, it can lead to failures on i686 Windows when file descriptors are quickly reused.

The patch makes three key changes: (1) documents that `unbundle()` closes the file descriptor, (2) ensures the descriptor is closed even when bundle verification fails, and (3) invalidates the file descriptor in the transport data after `unbundle()` to prevent double-closing. The author notes this doesn't completely resolve file descriptor ownership issues in the command execution plumbing, but provides a targeted fix for the immediate problem.

The changes affect `bundle.c`, `bundle.h`, and `transport.c`, adding documentation and explicit cleanup. The author acknowledges this is a rare edge case that primarily manifests in specific Windows environments, and the fix trades potential file descriptor leaks in error cases (which would occur during failure scenarios anyway) for preventing hard failures during normal operation.
