This thread continues the long-running effort to modernize Git's test infrastructure, focusing on error handling in test helpers like `test_must_fail` and `test_might_fail`. The discussion originated with SZEDER Gábor's 2021 patches to standardize file descriptor usage and integrate BUG() reporting, which has recently gained relevance by demonstrating it would have caught a real test failure scenario.

Jeff King (Peff) has been the primary reviewer, contributing sub-test framework improvements that automatically insert `test_done` calls, reducing boilerplate. Junio Hamano has now engaged more deeply, questioning whether `test_might_fail` should be kept at all given its limited use cases (primarily for cleanup operations where failure is expected). He suggests simpler alternatives like `|| :` might suffice for these cases, while acknowledging the helpers' value in detecting crashes.

Technical consensus has been reached on the core changes: standardized file descriptor usage (fd 6 for stderr), BUG() integration in test helpers, and Peff's sub-test improvements (pending one minor commit message fix). The only remaining item is documentation of the fd conventions from SZEDER Gábor. Junio's latest comments suggest potential future simplification of the test helper API, though this would be separate from the current modernization effort. The thread demonstrates how these infrastructure improvements, while technical, have concrete value in making tests more robust and maintainable.
