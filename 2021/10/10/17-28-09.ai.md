This is a test fix for `t3420-rebase-autostash.sh`. The patch corrects a fragile test that was using `! grep dirty file3` to verify that a file no longer contained dirty content after `git rebase --quit`. The problem: the file *shouldn’t exist at all* in the conflicted state, so `grep` was failing not because the content was missing, but because the file itself was missing. The fix replaces the `grep` check with `test_path_is_missing file3`, which is the proper way to assert that a file does not exist. The change affects one test case, but that case is run with three different rebase strategies (`--apply`, `--merge`, and `--interactive`), so the fix propagates to all three scenarios. The commit message cites prior art (2745817028) and the commit that introduced the bug (9b2df3e8d0).
