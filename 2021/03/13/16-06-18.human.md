Bug report about recursive stack overflow in `git subtree`. Arun Sharma reports hitting a maximum recursion depth (1000) when trying to push a subtree from the PostgreSQL repository (52k commits) containing a subtree with 1,685 commits. The error occurs between `process_split_commit()` and `check_parents()` functions in the shell-script implementation of `git-subtree`.

The reporter has tried increasing stack limits (`ulimit -s` and `FUNCNEST`) without success and asks about non-recursive implementations or alternative language versions of `git-subtree`. This appears to be a known limitation of the shell script implementation when handling repositories with deep commit histories. The report was originally sent to git-users@ but received no responses, prompting this follow-up to the main development list.

The issue affects users working with large repositories who need to split and merge subtrees. While the report doesn't propose a specific fix, it highlights a real-world scalability problem in a core contrib script. The shell implementation's recursive approach clearly struggles with deep histories, suggesting a rewrite in a more suitable language (like the C versions of other Git commands) might be needed for robust handling of large repositories.
