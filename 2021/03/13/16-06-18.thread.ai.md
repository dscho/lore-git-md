Thread identity: Bug report about recursion depth limitation in `git subtree` shell script implementation, originally reported by Arun Sharma, with follow-up from brian m. carlson, Johannes Schindelin, and now Colin Stagner.

Core problem: The shell script implementation of `git subtree` hits maximum recursion depth (1000) when `process_split_commit()` and `check_parents()` mutually call each other, particularly with large histories (original reproduction: 1685 subtree commits from parent repo with 52k commits). Shell recursion limits prevent operation despite `ulimit -s` and `FUNCNEST` workarounds. Reproduction confirmed on Ubuntu 20.04 with Git 2.25.1 and Bash 5.0.16 using PostgreSQL's `src/interfaces/libpq` subtree.

Current status: Two potential solutions now exist:
1. Johannes Schindelin's reference to PR #493 (October 2020 v2 series) - a shell-to-C conversion that would inherently avoid shell recursion limits
2. Colin Stagner's new v2 patch series that directly addresses the mutual recursion in the shell implementation
