Thread identity: Bug report about recursion depth limitation in `git subtree` shell script implementation, reported by Arun Sharma.

Core problem: The shell script implementation of `git subtree` hits a maximum recursion depth (1000) when processing commits with `process_split_commit()` and `check_parents()` mutually calling each other, particularly when handling large histories (1685 subtree commits from a parent repo with 52k commits). Shell recursion limits prevent successful operation even with `ulimit -s` and `FUNCNEST` workarounds.

Current status: Unresolved bug report with no proposed fix yet. The reporter asks about non-recursive implementations or alternative language versions.

Key technical details:
- Affects `contrib/subtree/git-subtree.sh`
- Specific functions involved: `process_split_commit()`, `check_parents()`
- Fails with deep commit histories (1685+ commits)
- Shell-specific limitation (wouldn't affect C implementation)

Open questions:
- Are there existing non-recursive implementations?
- Would a C or other language port avoid this?
- How to reproduce without PostgreSQL repo access?
- Is this a common failure mode for large repos?

Participant positions:
