This thread reports a recursion depth limitation in `git subtree`, a shell script in Git's contrib directory. Arun Sharma encountered the issue when trying to a PostgreSQL repository subtree, where `process_split_commit()` and `check_parents()` mutually recurse beyond the 1000-call limit. The subtree contained 1685 commits from a parent repo with 52k commits.

Shell-level workarounds like `ulimit -s` and `FUNCNEST=10000` failed to resolve the issue, suggesting this is a fundamental limitation of the shell script implementation. The reporter asks whether non-recursive approaches exist, or if alternative implementations (like a C version) might avoid this problem. While the report lacks specific reproduction steps, it highlights a real-world limitation when processing deep commit histories in large repositories. The question of alternative implementations is particularly pertinent since `git subtree` remains one of the few major Git components still implemented as a shell script.
