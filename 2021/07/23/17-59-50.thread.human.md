This thread documents an incremental improvement to Git's bug report template formatting, originally proposed by Felipe Contreras and now carried forward by Kristoffer Haugsbakk. The goal is to make bug reports more readable by better structuring the template that users fill out when running `git bugreport`.

The discussion began with a v2 patch that added `>` prefixes to instructional lines in the template. Junio Hamano then suggested considering additional formatting improvements, particularly around how questions and answers should be separated. In response, Kristoffer has now submitted a v3 patch that makes two key changes: it removes the `>` prefixes from non-question introductory text (reverting part of v2) while adding explicit spacing guidance - increasing the blank lines between questions to three and including instructions about response formatting (answer on the second line with blank lines around it).

The patch maintains the `>` prefixes for actual questions from v2 while addressing Junio's feedback about question/answer separation. Test coverage in t0091-bugreport.sh has been updated to verify the new template format. The changes appear well-considered, with Kristoffer combining both adjustments into a single patch to minimize test churn. This iteration seems likely to satisfy the original goal of improving template readability while incorporating the maintainer's suggestions about structural clarity.
