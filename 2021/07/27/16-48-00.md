> > My gut feeling is that "-m" without "--merge" in the context of

> >
> > As "git pull" is a "git fetch" followed by a "git merge" (or "git

> Thanks for the explanation. I forgot that "-m" usually means

> "merge".


It means --merge plenty of times:

 * git restore -m
 * git checkout -m
 * git rebase -m
 * git diff -m
 * git read-tree -m
 * git diff-tree -m
