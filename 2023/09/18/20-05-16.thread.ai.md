[PATCH] git subtree split regression with squashed subtree merges

Regression report from Colin Stagner identifying incorrect behavior in `git subtree split` when processing repositories containing squashed subtree merges (those created via `git subtree add --squash`). The issue manifests in Git v2.44+ where commits with squashed subtree merges are incorrectly filtered by `should_ignore_subtree_split_commit()`, causing nested subtree content (demonstrated via missing `deeper/` directory) to be omitted from split output. Verified regression window between v2.43 (correct) and v2.44 (broken), with commit 98ba49ccc247 identified as the likely culprit. The filtering logic fails to properly handle squashed merges lacking the "git-subtree-mainline:" marker. Impact limited to users performing splits on repositories with squashed subtree history, but results in incomplete split output for affected cases. Clear reproduction provided showing the commit filtering incorrectly drops valid history that should be preserved.
