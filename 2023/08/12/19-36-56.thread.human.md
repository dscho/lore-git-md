This thread addresses a long-standing issue with `git describe`'s commit traversal order, where it currently follows commit-date ordering rather than the correct topological/ancestry order. The problem can lead to incorrect tag descriptions in some cases, particularly when multiple tags are involved.

The proposed fix would make `git describe` traverse commits in proper ancestry order, which would resolve the known test case in t6120-describe.sh that was previously marked as expect-failure. However, this comes with a significant performance tradeoff - without a commit-graph available, the operation could take minutes rather than being nearly instantaneous. The change might also alter existing tag descriptions (e.g., changing from "tag-release-7-g<hash>" to "tag-release-5-g<hash>").

The discussion explores two potential solutions: making the accurate traversal the default (with possible warnings about commit-graph usage) or adding an `--accurate` flag to opt into the new behavior. The patch builds on previous work (commit 7379046221) that addressed a different aspect of `git describe`'s tag search, and includes an updated reproduction script that works with current Git versions. Performance concerns remain a key consideration, particularly around potential O(n*m) behavior characteristics.
