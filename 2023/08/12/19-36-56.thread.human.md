This thread addresses a bug in `git describe` where it follows commit-date ordering rather than proper topological/ancestry ordering, causing incorrect tag descriptions in repositories with complex merge histories. The core issue is now well-understood, with consensus that the behavior needs correction despite potential backward compatibility concerns for existing scripts.

Jeff King (Peff) identified serious performance problems with the initial proposed solution using `repo_is_descendant_of()`, which showed O(n²) characteristics. The discussion has since shifted to evaluating more efficient approaches. Ben Boeckel is now considering two main strategies: leveraging generation numbers (either from commit-graphs or computed during traversal) for optimized ancestor checks, or potentially rewriting `git describe` to use Git's existing revision machinery which already handles topological ordering via `init_topo_walk()`.

The key open questions now center on implementation tradeoffs: whether to adapt `git describe`'s custom traversal or migrate to the standard revision walker, how commit-graph availability should influence the default behavior, and how to balance correctness with performance. The performance impact is particularly significant without commit-graphs, where the current approach could slow from instantaneous to minutes-long operations. While the correct semantic behavior is now agreed upon, the path to an optimized implementation remains under active discussion.
