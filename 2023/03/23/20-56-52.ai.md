This is a follow-up in the thread about optimizing `git branch --contains` performance, suggesting an alternative approach to the exclusion pattern idea.

Felipe Contreras shares a custom tool (`git-smartlist`) he developed to address a similar need - efficiently listing only the commits unique to local branches (excluding upstream content). His solution works by comparing each branch to its upstream counterpart (using `@{u}..` syntax) rather than doing full revision walks.

The tool demonstrates an alternative implementation strategy to Oswald's original exclusion pattern proposal, though it requires external tooling rather than modifying core Git. This suggests the problem space has multiple potential solutions, from syntax additions to algorithmic changes to external helpers.

The email doesn't directly engage with the concurrent walking optimization direction that emerged in later discussion, instead offering a practical workaround that solves the immediate use case through existing Git primitives. It reinforces that the core issue (avoiding expensive full-history walks when only recent branch differences are needed) is a real pain point with multiple possible solutions.
