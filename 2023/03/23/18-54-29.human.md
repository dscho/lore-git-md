This is a feature request for `git branch --contains` to support exclusion patterns, similar to how other Git revision walks work. Oswald Buddenhagen notes that `git branch --contains` can be expensive in large repositories, and proposes adding the ability to exclude certain branches (like `^origin/master`) from the search to improve performance when only checking local work-in-progress branches.

The request is straightforward and well-motivated by a real performance pain point. The proposed syntax would align with Git's existing revision walk exclusion patterns, making it intuitive for experienced users. No implementation is provided - this is purely a suggestion to spark discussion about whether such a feature would be useful and how it might be implemented.

The email is friendly and open to alternative solutions ("suggestions how this is actually already achievable efficiently are of course welcome"). This looks like a reasonable quality-of-life improvement that could benefit users with large repositories, though the actual implementation would need to consider edge cases around branch naming and the performance characteristics of the revision walk.
