This thread explores performance optimizations for `git branch --contains` and related operations. Jeff King (Peff) initially diagnosed that replace refs were disabling commit-graph optimizations, causing severe slowdowns (1m40s vs 30ms with the workaround `-c core.useReplaceRefs=false`). While this resolved the immediate issue, Oswald Buddenhagen raised questions about improving Git's handling of such optimization-disabled cases from a user experience perspective.

Now Kristofer Karlsson from Spotify has revived the discussion with compelling benchmark data showing that enabling the cached DFS algorithm (`contains_tag_algo`) for branch operations can yield dramatic speedups when generation numbers are available via commit-graph. In large repositories, this optimization provides 15-16x faster queries in monorepos and 3.7x improvements for deep tags in git.git itself. The data demonstrates clear real-world impact at Spotify's scale (millions of commits, thousands of refs), validating the optimization's value for large repository workflows.

While Peff's technical analysis remains authoritative on the replace refs interaction, Kristofer's benchmarks move the discussion forward by showing how existing infrastructure could be safely applied to improve performance in the common case where generation numbers are available. The thread has progressed from problem diagnosis to concrete optimization proposals with measurable benefits.
