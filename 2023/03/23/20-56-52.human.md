This is a follow-up in the ongoing discussion about optimizing `git branch --contains` performance. Felipe Contreras shares a practical workaround he developed - a custom tool called `git-smartlist` that implements branch exclusion by comparing each local branch against its upstream (using `@{u}..` syntax) to identify unique commits.

The contribution provides a concrete example of how users are working around the current limitations, though it doesn't directly address the core performance issues with revision walking that the thread has uncovered. The tool demonstrates one way to implement branch exclusion without modifying Git itself, though likely still involves multiple revision walks.

This email reinforces that the performance pain point is real enough that users are creating their own solutions. The thread continues to explore whether the right fix is (1) adding exclusion patterns to the command, (2) deeper optimization of the revision walking logic, or (3) both.
