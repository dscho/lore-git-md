This is a feature request for `git branch --contains` to support exclusion patterns, similar to how other Git commands accept `^ref` syntax to limit revision walks.

Oswald Buddenhagen notes that `git branch --contains` can be expensive in large repositories, and proposes adding the ability to exclude certain branches (like `^origin/master`) from the search. Their specific use case is searching for commits in local work-in-progress branches while avoiding the overhead of scanning all branches.

The email doesn't propose a specific implementation but rather floats the idea and invites suggestions for alternative solutions if they already exist. This appears to be an initial exploration of the problem space rather than a fully-formed patch proposal.

The request touches on performance optimization in the branch listing machinery, specifically around revision walking with containment checks. It could be implemented by plumbing through the revision walk exclusion mechanism that already exists in other Git commands.
