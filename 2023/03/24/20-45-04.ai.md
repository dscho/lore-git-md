This is a follow-up in the ongoing investigation of `git branch --contains` performance issues related to commit-graph loading. Jeff King (Peff) identifies the root cause in Oswald Buddenhagen's Linux kernel repository setup: the presence of a replace ref is disabling commit-graph optimizations entirely.

The key technical insight is that replace refs invalidate commit-graph invariants about commit generations and ancestry, causing Git to conservatively disable the optimization. Peff provides a workaround (`-c core.useReplaceRefs=false`) to temporarily bypass this restriction and confirms this should restore the expected performance benefits. He also suggests this could be set permanently if the replace ref isn't needed for daily work.

The email moves the discussion from diagnosis to solution while leaving open whether Peff's earlier proposed optimization (from 1m40s to 30ms in his tests) would provide additional gains in this specific case. The resolution highlights an important edge case in Git's performance optimization heuristics - how replace refs interact with commit-graph loading - that could inform future improvements to the commit-graph subsystem's handling of repository modifications.
