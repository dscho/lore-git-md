This is a bugfix patch for `git describe` that addresses an inconsistency when combining `--contains` with `--all` and pattern matching options.

The patch fixes a case where `git describe --contains --all` would ignore any `--match` or `--exclude` patterns provided by the user, rather than failing with an error. The author (Jacob Keller) discovered this while trying to use these options together and finding the patterns weren't being applied as expected.

The change adds an explicit check that causes the command to die with an error message when `--contains --all` is used with pattern matching options. The implementation is straightforward - it adds the check in `builtin/describe.c` where the other pattern handling occurs.

The patch is marked as "quick/dirty" by the author, who notes they haven't had time to write tests. The change itself is small (3 lines added) and focused, touching only the behavior it aims to fix. While untested, the logic appears correct - it catches the invalid combination before the patterns would be silently ignored.

This seems like a reasonable quality-of-life improvement that prevents user confusion when these options are combined. The error message clearly explains the limitation. The change is low-risk since it only adds validation rather than modifying existing working behavior.
