This thread addresses a bug in `git describe` where the `--match` and `--exclude` pattern matching options are silently ignored when used with `--contains --all`, rather than being rejected as invalid. Jacob Keller originally identified the issue and submitted a patch to make this combination fail with an error, but it was never merged. 

Tuomas Ahola independently encountered the same problem in current Git versions, demonstrating that both `--match=bogus` and `--exclude="*"` have no effect when combined with `--contains --all`. His real-world confirmation underscores the need for the fix. Eric Sunshine reviewed Jacob's initial patch, suggesting only minor wording improvements in the commit message and an optional code style tweak (converting nested if/else to else-if), indicating technical approval of the approach.

The solution remains straightforward - explicitly reject this invalid option combination with a clear error message. The patch appears ready for revival, needing only minor updates: fixing a commit message typo ("bail of" to "bail if") and potentially adding regression tests. There's clear consensus that failing with an explanation is better than silently ignoring the patterns, and the independent confirmation suggests this should be prioritized for inclusion.
