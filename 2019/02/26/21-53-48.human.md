Bugfix for `git describe` command behavior.

Jacob Keller noticed that when using `git describe --contains --all`, any `--match` or `--exclude` patterns are silently ignored rather than affecting the results. This can lead to unexpected behavior where users provide patterns expecting them to filter the output, but they have no effect.

The patch adds an explicit check that causes the command to die with an error message when these incompatible options are used together, rather than silently ignoring the patterns. The change is minimal - just 3 lines added to `builtin/describe.c` to detect and reject this invalid combination.

The author notes this is a quick fix and hasn't yet added tests, but the change is straightforward and clearly addresses the issue. This prevents users from unknowingly getting incorrect results when combining these options. The fix is targeted and unlikely to have wider impacts since it only affects this specific invalid option combination.
